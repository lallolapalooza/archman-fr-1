DESCRIPTIO

N

Les transferts atomiques sont utilisés pour lire et mettre à jour des données situées dans des régions de mémoire distantes de manière atomique. Conceptuellement, ils sont similaires aux opérations atomiques locales de nature similaire (par ex. incrément atomique, comparaison et échange, etc.). Les mises à jour des données distantes impliquent l'une de plusieurs opérations sur les données, et agissent sur des types spécifiques de données, comme listés ci-dessous. En tant que tels, les transferts atomiques ont connaissance du format des données étant accédées. Une fonction atomique unique peut opérer sur un tableau de données en appliquant une opération atomique à chaque entrée, mais l'atomicité d'une opération est limitée à un seul type de données ou

entrée.

Opérations atomiques

Les opérations atomiques suivantes sont définies. Une opération atomique agit souvent sur une valeur cible dans le tampon de mémoire distant et une valeur source fournie avec la fonction atomique. Elle peut également transporter des données source pour remplacer la valeur cible dans les opérations de comparaison et d'échange (compare and swap). Une description conceptuelle de chaque opération est fournie.

FI_MIN
Minimum
if (buf[i] < addr[i])
    addr[i] = buf[i]
FI_MAX
Maximum
if (buf[i] > addr[i])
    addr[i] = buf[i]
FI_SUM
Somme
addr[i] = addr[i] + buf[i]
FI_PROD
Produit
addr[i] = addr[i] * buf[i]
FI_LOR
OU logique
addr[i] = (addr[i] || buf[i])
FI_LAND
ET logique
addr[i] = (addr[i] && buf[i])
FI_BOR
OU bit à bit
addr[i] = addr[i] | buf[i]
FI_BAND
ET bit à bit
addr[i] = addr[i] & buf[i]
FI_LXOR
OU exclusif logique (XOR)
addr[i] = ((addr[i] && !buf[i]) || (!addr[i] && buf[i]))
FI_BXOR
OU exclusif bit à bit (XOR)
addr[i] = addr[i] ^ buf[i]
FI_ATOMIC_READ
Lire des données de manière atomique
result[i] = addr[i]
FI_ATOMIC_WRITE
Écrire des données de manière atomique
addr[i] = buf[i]
FI_CSWAP
Comparer les valeurs et, si elles sont égales, échanger avec les données
if (compare[i] == addr[i])
    addr[i] = buf[i]
FI_CSWAP_NE
Comparer les valeurs et, si elles sont différentes, échanger avec les données
if (compare[i] != addr[i])
    addr[i] = buf[i]
FI_CSWAP_LE
Comparer les valeurs et, si l'une est inférieure ou égale, échanger avec les données
if (compare[i] <= addr[i])
    addr[i] = buf[i]
FI_CSWAP_LT
Comparer les valeurs et, si l'une est inférieure, échanger avec les données
if (compare[i] < addr[i])
    addr[i] = buf[i]
FI_CSWAP_GE
Comparer les valeurs et, si l'une est supérieure ou égale, échanger avec les données
if (compare[i] >= addr[i])
    addr[i] = buf[i]
FI_CSWAP_GT
Comparer les valeurs et, si l'une est supérieure, échanger avec les données
if (compare[i] > addr[i])
    addr[i] = buf[i]
FI_MSWAP
Échanger les bits masqués avec les données
addr[i] = (buf[i] & compare[i]) | (addr[i] & ~compare[i])
FI_DIFF
Calculer la différence
addr[i] = addr[i] - buf[i]

Fonctions atomiques de base

Les fonctions atomiques de base – fi_atomic, fi_atomicv, fi_atomicmsg – sont utilisées pour transmettre des données à un nœud distant, où l'opération atomique spécifiée est effectuée sur les données cibles. Le résultat d'une fonction atomique de base est stocké dans la région de mémoire distante. La principale différence entre les fonctions atomiques réside dans le nombre et le type de paramètres qu'elles acceptent en entrée. Sinon, elles effectuent la même fonction générale.

L'appel fi_atomic transfère les données contenues dans le tampon de données spécifié par l'utilisateur vers un nœud distant. Pour les points de terminaison sans connexion, le point de terminaison de destination est spécifié via le paramètre dest_addr. Sauf si le point de terminaison a été configuré différemment, le tampon de données passé à fi_atomic ne doit pas être touché par l'application jusqu'à ce que l'appel fi_atomic se termine de manière asynchrone. Le tampon cible d'une opération atomique de base doit permettre l'accès en lecture et/ou en écriture à distance, selon le cas.

L'appel fi_atomicv ajoute la prise en charge d'une liste scatter-gather à fi_atomic. fi_atomicv transfère l'ensemble des tampons de données référencés par le paramètre ioc vers le nœud distant pour traitement.

L'appel fi_inject_atomic est une version optimisée de fi_atomic. La fonction fi_inject_atomic se comporte comme si le drapeau de transfert FI_INJECT était défini et que FI_COMPLETION ne l'était pas. C'est-à-dire que le tampon de données est disponible pour être réutilisé immédiatement après le retour de fi_inject_atomic, et aucun événement de complétion ne sera généré pour cette opération atomique. L'événement de complétion sera supprimé même si le point de terminaison n'a pas été configuré avec FI_SELECTIVE_COMPLETION. Voir la discussion sur les drapeaux ci-dessous pour plus de détails. La taille de message demandée qui peut être utilisée avec fi_inject_atomic est limitée par inject_size.

L'appel fi_atomicmsg prend en charge les fonctions atomiques sur les points de terminaison connectés et sans connexion, avec la possibilité de contrôler l'opération atomique pour chaque appel à l'aide de drapeaux. La fonction fi_atomicmsg prend une struct fi_msg_atomic en entrée.

struct fi_msg_atomic {
    const struct fi_ioc *msg_iov; /* tableau scatter-gather local */
    void                **desc;   /* descripteurs d'accès locaux */
    size_t              iov_count;/* # éléments dans ioc */
    const void          *addr;    /* adresse de point de terminaison facultative */
    const struct fi_rma_ioc *rma_iov; /* SGL distant */
    size_t              rma_iov_count;/* # éléments dans le SGL distant */
    enum fi_datatype    datatype; /* type de données de l'opérande */
    enum fi_op          op;       /* opération atomique */
    void                *context; /* contexte défini par l'utilisateur */
    uint64_t            data;     /* données facultatives */
};
struct fi_ioc {
    void        *addr;    /* adresse locale */
    size_t      count;    /* # opérandes cibles */
};
struct fi_rma_ioc {
    uint64_t    addr;     /* adresse cible */
    size_t      count;    /* # opérandes cibles */
    uint64_t    key;      /* clé d'accès */
};

La liste suivante d'opérations atomiques est utilisable avec les opérations atomiques de base : FI_MIN, FI_MAX, FI_SUM, FI_PROD, FI_LOR, FI_LAND, FI_BOR, FI_BAND, FI_LXOR, FI_BXOR et FI_ATOMIC_WRITE.

Fonctions atomiques avec récupération (Fetch-Atomic)

Les fonctions atomiques avec récupération – fi_fetch_atomic, fi_fetch_atomicv et fi_fetch_atomicmsg – se comportent de manière similaire à la fonction atomique de base équivalente. La différence entre les appels atomiques avec récupération et les appels atomiques de base est que les routines atomiques avec récupération renvoient la valeur initiale stockée à la cible à l'utilisateur. La valeur initiale est lue dans le tampon de résultat fourni par l'utilisateur. Le tampon cible des opérations atomiques avec récupération doit être autorisé à l'accès en lecture à distance.

La liste suivante d'opérations atomiques est utilisable avec les opérations atomiques avec récupération : FI_MIN, FI_MAX, FI_SUM, FI_PROD, FI_LOR, FI_LAND, FI_BOR, FI_BAND, FI_LXOR, FI_BXOR, FI_ATOMIC_READ et FI_ATOMIC_WRITE.

Pour les opérations FI_ATOMIC_READ, l'opérande du tampon source (par exemple, le paramètre buf de fi_fetch_atomic) est ignoré et peut être NULL. Les résultats sont écrits dans le tampon de résultat.

Fonctions atomiques valides

Les fonctions atomiques valides – fi_atomicvalid, fi_fetch_atomicvalid, et fi_compare_atomicvalid – indiquent quelles opérations le fournisseur local prend en charge. Les opérations nécessaires non prises en charge par le fournisseur doivent être émulées par l'application. Chaque appel valide correspond à un ensemble de fonctions atomiques. fi_atomicvalid vérifie si un fournisseur prend en charge une opération atomique de base spécifique pour un type de données et une opération donnés. fi_fetch_atomicvalid indique si un fournisseur prend en charge une opération atomique de récupération spécifique pour un type de données et une opération donnés. Et fi_compare_atomicvalid vérifie si un fournisseur prend en charge une opération atomique de comparaison spécifiée pour un type de données et une opération donnés.

Si une opération est prise en charge, un appel atomique valide retournera 0, ainsi qu'un décompte des unités de données atomiques sur lesquelles un seul appel de fonction opérera.

Interroger les attributs atomiques

L'appel fi_query_atomic agit comme une opération atomique valide améliorée (voir les définitions des fonctions atomiques valides ci-dessus). Il est fourni, en partie, pour une extensibilité future. L'opération de requête signale quelles opérations atomiques sont prises en charge par le domaine, pour les points d'extrémité correctement configurés.

Le comportement de fi_query_atomic est ajusté en fonction du paramètre flags. Si flags est 0, l'opération signale les attributs atomiques pris en charge pour les opérations atomiques de base, similaire à fi_atomicvalid pour les points d'extrémité. Si flags a le bit FI_FETCH_ATOMIC défini, l'opération se comporte de manière similaire à fi_fetch_atomicvalid. De même, le bit de drapeau FI_COMPARE_ATOMIC entraîne un comportement de requête similaire à fi_compare_atomicvalid. Les bits FI_FETCH_ATOMIC et FI_COMPARE_ATOMIC ne peuvent pas être définis simultanément.

Si le bit FI_TAGGED est défini, le fournisseur indiquera s'il prend en charge les opérations atomiques sur les tampons de réception étiquetés. Le bit FI_TAGGED peut être utilisé seul, ou en conjonction avec les drapeaux FI_FETCH_ATOMIC et FI_COMPARE_ATOMIC.

La sortie de fi_query_atomic est la structure fi_atomic_attr:

struct fi_atomic_attr {
    size_t count;
    size_t size;
};

Le champ d'attribut count est tel que défini pour les appels atomiques valides. Le champ size indique la taille en octets du type de données atomique. Le champ size est utile pour les types de données dont la taille peut varier en fonction de la plateforme ou du compilateur, comme FI_LONG_DOUBLE.

Accomplissements

Les opérations atomiques terminées sont signalées à l'initiateur de la requête via une file d'attente d'accomplissement ou un compteur associé. Tout contexte fourni par l'utilisateur spécifié avec la requête sera retourné dans le cadre de tout événement d'accomplissement écrit dans une CQ. Voir fi_cq pour les détails des événements d'accomplissement.

Tous les résultats retournés à l'initiateur dans le cadre d'une opération atomique seront disponibles avant la génération d'un événement d'accomplissement. Ce sera vrai même si la sémantique d'accomplissement demandée fournit une garantie plus faible. C'est-à-dire que les opérations atomiques de récupération ont une sémantique FI_DELIVERY_COMPLETE. Les accomplissements générés pour d'autres types d'opérations atomiques indiquent qu'il est sûr de réutiliser les tampons de données source.

Toute mise à jour des données à la cible d'une opération atomique sera visible par les agents (processus CPU, cartes réseau et autres périphériques) sur le nœud cible avant que l'un des événements suivants ne se produise. Si l'opération atomique génère un événement d'accomplissement ou met à jour un compteur d'accomplissement au point d'extrémité cible, les résultats seront disponibles avant la notification d'accomplissement. Après le traitement d'un accomplissement pour l'opération atomique, si l'initiateur soumet un transfert entre les mêmes points d'extrémité qui génère un accomplissement à la cible, les résultats seront disponibles avant l'événement du transfert suivant. Ou, si un transfert de données groupé depuis l'initiateur suit la requête atomique, les résultats seront disponibles avant un accomplissement à la cible pour le transfert groupé.

La correction des opérations atomiques sur une région mémoire cible n'est garantie que lorsqu'elle est effectuée par un seul acteur pendant une période donnée. Un acteur est défini comme un seul domaine libfabric sur la cible (identifié par le nom du domaine, et non une instance ouverte de ce domaine), un complexe CPU cohérent, ou un autre périphérique (par exemple, GPU) capable d'effectuer des opérations atomiques sur la mémoire cible. Les résultats des opérations atomiques effectuées par plusieurs acteurs simultanément sont indéfinis. Par exemple, émettre des opérations atomiques basées sur le CPU vers une région cible en cours de mise à jour par des opérations atomiques basées sur la carte réseau peut laisser les données de la région dans un état inconnu. Les résultats des opérations atomiques du premier acteur doivent être visibles par le second acteur avant que le second acteur n'émette ses propres opérations atomiques.

DRAPEAUX

Les appels fi_atomicmsg, fi_fetch_atomicmsg, et fi_compare_atomicmsg permettent à l'utilisateur de spécifier des drapeaux qui peuvent modifier l'opération de transfert de données par défaut. Les drapeaux spécifiés avec les opérations de message atomique remplacent la plupart des drapeaux précédemment configurés avec le point d'extrémité, sauf indication contraire (voir fi_control). La liste suivante de drapeaux est utilisable avec les appels de message atomique.

FI_COMPLETION
Indique qu'une entrée d'accomplissement doit être générée pour l'opération spécifiée. Le point d'extrémité doit être lié à une file d'attente d'accomplissement avec FI_SELECTIVE_COMPLETION qui correspond à l'opération spécifiée, sinon ce drapeau est ignoré.
FI_MORE
Indique que l'utilisateur a des requêtes supplémentaires qui seront immédiatement publiées après le retour de l'appel actuel. L'utilisation de ce drapeau peut améliorer les performances en permettant au fournisseur d'optimiser son accès au matériel de la fabric.
FI_INJECT
Indique que le contrôle des tampons de données constants doit être rendu à l'utilisateur immédiatement après le retour de l'appel, même si l'opération est gérée de manière asynchrone. Cela peut nécessiter que l'implémentation du fournisseur sous-jacent copie les données dans un tampon local et transfère à partir de ce tampon. Les tampons de données constants font référence à tout tampon de données ou iovec utilisé par les API atomiques qui sont marqués comme `const'. Les tampons non constants ou de sortie ne sont pas affectés par ce drapeau et peuvent être accédés par le fournisseur à tout moment jusqu'à ce que l'opération soit terminée. Ce drapeau ne peut être utilisé qu'avec des messages plus petits que inject_size.
FI_FENCE
S'applique aux transmissions. Indique que l'opération demandée, également connue sous le nom d'opération groupée, et toute opération publiée après l'opération groupée seront différées jusqu'à ce que toutes les opérations précédentes ciblant le même point d'extrémité pair soient terminées. Les opérations publiées après le groupage verront et/ou remplaceront les résultats de toute opération initiée avant l'opération groupée.

L'ordre des opérations commençant à la publication de l'opération groupée (inclusive) jusqu'à la publication d'une opération groupée subséquente (exclusive) est contrôlé par les sémantiques d'ordre du point d'extrémité.

FI_TAGGED
Spécifie que la cible de l'opération atomique est un tampon de réception étiqueté au lieu d'un tampon RMA. Lorsqu'un tampon étiqueté est la région mémoire cible, le paramètre addr est utilisé comme un décalage en octets basé sur 0 dans le tampon étiqueté, le paramètre key spécifiant l'étiquette.

VALEUR DE RETOUR

Retourne 0 en cas de succès. En cas d'erreur, une valeur négative correspondant à errno de fabric est retournée. Les valeurs errno de fabric sont définies dans rdma/fi_errno.h.

ERREURS

-FI_EAGAIN
Voir fi_msg(3) pour une description détaillée de la gestion de FI_EAGAIN.
-FI_EOPNOTSUPP
L'opération atomique demandée n'est pas prise en charge sur ce point d'extrémité.
-FI_EMSGSIZE
Le nombre d'opérations atomiques dans une seule requête dépasse celui pris en charge par le fournisseur sous-jacent.

NOTES

Les opérations atomiques opèrent sur un tableau de valeurs d'un type de données spécifique. L'atomicité n'est garantie que pour chaque opération de type de données, et non pour l'ensemble du tableau. Le pseudocode suivant démontre cette opération pour une écriture atomique non signée de 64 bits. ATOMIC_WRITE_U64 est une macro dépendant de la plateforme qui écrit atomiquement 8 octets dans un emplacement mémoire aligné.

fi_atomic(ep, buf, count, NULL, dest_addr, addr, key,
      FI_UINT64, FI_ATOMIC_WRITE, context)
{
    for (i = 1; i < count; i ++)
        ATOMIC_WRITE_U64(((uint64_t *) addr)[i],
                 ((uint64_t *) buf)[i]);
}

Le nombre d'éléments du tableau sur lesquels opérer est spécifié par un paramètre count. Il doit être compris entre 1 et le maximum retourné par l'opération valide pertinente, inclus. L'opération et le type de données demandés doivent également être valides pour le fournisseur donné.

L'ordre des opérations atomiques effectuées dans le cadre de différents messages de requête est soumis aux définitions d'ordre des messages et des données attribuées aux points d'extrémité d'émission et de réception. L'ordre des messages et des données est requis si les résultats de deux opérations atomiques sur les mêmes tampons mémoire doivent refléter la deuxième opération agissant sur les résultats de la première. Voir fi_endpoint(3) pour plus de détails et les restrictions de taille de message.

NOM

fi_compare_atomicv - Compare et échange des valeurs atomiques sur un transfert d'E/S.

SYNOPSIS


#include <rdma/fi_atomic.h>

int fi_compare_atomicv(
    fi_atomic_handle_t atomic_handle,
    const uint64_t *local_addr,
    const uint64_t *remote_addr,
    const uint64_t *values,
    size_t count,
    uint64_t flags
);

ARGUMENTS

atomic_handle
Un handle d'opération atomique créé par fi_atomic_open.
local_addr
L'adresse locale où le résultat de l'opération sera stocké.
remote_addr
L'adresse distante où l'opération atomique sera effectuée.
values
Un pointeur vers un tableau de valeurs à comparer et échanger.
count
Le nombre d'éléments dans le tableau values.
flags
Les drapeaux d'opération.

DESCRIPTION

La fonction fi_compare_atomicv effectue une opération atomique de comparaison et échange sur des valeurs sur une cible distante. Cette opération est une primitive de synchronisation qui permet de comparer atomiquement une valeur à une adresse distante avec une ou plusieurs valeurs fournies localement, et si elles correspondent, de stocker une nouvelle valeur à l'adresse distante.

Le comportement exact de fi_compare_atomicv dépend des capacités du fournisseur de Fabric Interface (FI) sous-jacent et des drapeaux spécifiés.

L'opération est effectuée de manière atomique, ce qui signifie qu'elle est garantie d'être indivisible et de ne pas être interrompue par d'autres opérations concurrentes sur la même adresse distante.

FLAGS

FI_COMPARE_AND_SWAP
Spécifie l'opération de comparaison et échange.
FI_COMPARE_AND_ADD
Spécifie l'opération de comparaison et ajout.
FI_COMPARE_AND_FETCH_ADD
Spécifie l'opération de comparaison et ajout avec retour de la valeur d'origine.
FI_ATOMIC_OK
Indique que l'opération atomique est prise en charge.
FI_REMOTE_CQ
Indique que le cq_remote spécifié lors de la création du handle d'opération atomique doit être utilisé pour le transfert.

VALEUR DE RETOUR

En cas de succès, fi_compare_atomicv renvoie 0. En cas d'erreur, un numéro d'erreur est renvoyé.

ERREURS

Des erreurs spécifiques peuvent inclure:

  • -FI_ENOMSG: Message trop long.
  • -FI_EHOSTUNREACH: Hôte distant inaccessible.
  • -FI_ETIMEDOUT: Délai d'attente dépassé.
  • -FI_ENOSPC: Espace insuffisant.
  • -FI_EINVAL: Argument invalide.
  • -FI_EAGAIN: Ressource temporairement indisponible.

NOTES

L'utilisation de fi_compare_atomicv nécessite que le nœud distant soit configuré pour prendre en charge les opérations atomiques. La taille des données transférées est déterminée par la taille de uint64_t.
