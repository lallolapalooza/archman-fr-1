File::Basename(3perl) Guide de référence des programmeurs Perl File::Basename(3perl)

NOM

File::Basename - Analyse les chemins de fichiers en répertoire, nom de fichier et suffixe.

SYNOPSIS

use File::Basename;
my ($name, $path, $suffix) = fileparse($fullname, @suffixlist);
my $name = fileparse($fullname, @suffixlist);
my $basename = basename($fullname, @suffixlist);
my $dirname  = dirname($fullname);

DESCRIPTION

Ces routines vous permettent d'analyser les chemins de fichiers en leur répertoire, nom de fichier et suffixe.

NOTE: dirname() et basename() émulent les comportements, et les particularités, des fonctions du shell et de C du même nom. Voir la documentation de chaque fonction pour les détails. Si votre préoccupation est simplement l'analyse de chemins, il est plus sûr d'utiliser les méthodes splitpath() et splitdir() de File::Spec.

Il est garanti que

# Où $path_separator est / pour Unix, \ pour Windows, etc...
dirname($path) . $path_separator . basename($path);

est équivalent au chemin original pour tous les systèmes sauf VMS.

"fileparse"
my($filename, $dirs, $suffix) = fileparse($path);
my($filename, $dirs, $suffix) = fileparse($path, @suffixes);
my $filename                  = fileparse($path, @suffixes);

La routine fileparse() divise un chemin de fichier en ses parties $dirs, $filename et (optionnellement) le suffixe du nom de fichier $suffix.

$dirs contient tout jusqu'à et y compris le dernier séparateur de répertoire dans le $path y compris le volume (si applicable). Le reste du $path est le $filename.

# Sur Unix retourne ("baz", "/foo/bar/", "")
fileparse("/foo/bar/baz");
# Sur Windows retourne ("baz", 'C:\foo\bar\', "")
fileparse('C:\foo\bar\baz');
# Sur Unix retourne ("", "/foo/bar/baz/", "")
fileparse("/foo/bar/baz/");

Si @suffixes sont donnés, chaque élément est un motif (soit une chaîne soit un "qr//") comparé à la fin du $filename. La partie correspondante est retirée et devient le $suffix.

# Sur Unix retourne ("baz", "/foo/bar/", ".txt")
fileparse("/foo/bar/baz.txt", qr/\.[^.]*/);

Si le type n'est pas Unix (voir "fileparse_set_fstype") alors la correspondance de motif pour le retrait du suffixe est effectuée sans tenir compte de la casse, puisque ces systèmes ne font pas de distinction de casse lors de l'ouverture de fichiers existants.

Il est garanti que "$dirs . $filename . $suffix" désignera le même emplacement que le chemin $pathoriginal.

"basename"
my $filename = basename($path);
my $filename = basename($path, @suffixes);

Cette fonction est fournie pour la compatibilité avec la commande shell Unix basename(1). Elle ne retourne pas TOUJOURS la partie nom de fichier d'un chemin comme vous pourriez l'attendre. Pour être sûr, si vous voulez la partie nom de fichier d'un chemin, utilisez fileparse().

basename() retourne le dernier niveau d'un chemin de fichier même si le dernier niveau est clairement un répertoire. En effet, elle agit comme pop() pour les chemins. Cela diffère du comportement de fileparse().

# Les deux retournent "bar"
basename("/foo/bar");
basename("/foo/bar/");

@suffixes fonctionnent comme dans fileparse() sauf que tous les métacaractères regex sont échappés.

# Ces deux appels de fonction sont équivalents.
my $filename = basename("/foo/bar/baz.txt",  ".txt");
my $filename = fileparse("/foo/bar/baz.txt", qr/\Q.txt\E/);

Notez également que pour être compatible avec la commande shell, basename() ne retire pas un suffixe s'il est identique aux caractères restants du nom de fichier.

"dirname"
Cette fonction est fournie pour la compatibilité avec la commande shell Unix dirname(1) et a hérité de certaines de ses particularités. Malgré son nom, elle ne retourne PAS toujours le nom du répertoire comme vous pourriez l'attendre. Pour être sûr, si vous voulez le nom du répertoire d'un chemin, utilisez fileparse().

Seulement sur VMS (où il n'y a pas d'ambiguïté entre les parties fichier et répertoire d'un chemin) et AmigaOS (possiblement dû à une particularité d'implémentation dans ce module) que dirname() fonctionne comme fileparse($path), retournant simplement les $dirs.

# Sur VMS et AmigaOS
my $dirs = dirname($path);

Lorsqu'on utilise la syntaxe Unix ou MSDOS, cela émule la fonction shell dirname(1) qui est subtilement différente de la façon dont fileparse() fonctionne. Elle retourne tout sauf le dernier niveau d'un chemin de fichier même si le dernier niveau est clairement un répertoire. En effet, elle ne retourne pas la partie répertoire mais simplement le chemin un niveau au-dessus, agissant comme chop() pour les chemins de fichiers.

Aussi, contrairement à fileparse(), dirname() n'inclut pas de barre oblique finale sur son chemin retourné.

# retourne /foo/bar.  fileparse() retournerait /foo/bar/
dirname("/foo/bar/baz");
# retourne aussi /foo/bar malgré le fait que baz est clairement un 
# répertoire.  fileparse() retournerait /foo/bar/baz/
dirname("/foo/bar/baz/");
# retourne '.'.  fileparse() retournerait 'foo/'
dirname("foo/");

Sous VMS, s'il n'y a pas d'information de répertoire dans le $path, alors le périphérique et répertoire par défaut courant est utilisé.

"fileparse_set_fstype"
my $type = fileparse_set_fstype();
my $previous_type = fileparse_set_fstype($type);

Normalement File::Basename supposera un type de chemin de fichier natif à votre système d'exploitation courant (c.-à-d. style /foo/bar sur Unix, \foo\bar sur Windows, etc...). Avec cette fonction vous pouvez annuler cette hypothèse.

Les $types valides sont "MacOS", "VMS", "AmigaOS", "OS2", "RISCOS", "MSWin32", "DOS" (aussi "MSDOS" pour la compatibilité de bug rétroactive), "Epoc" et "Unix" (tous sans distinction de casse). Si un $type non reconnu est donné, "Unix" sera supposé.

Si vous avez sélectionné la syntaxe VMS, et que la spécification de fichier que vous passez à l'une de ces routines contient un "/", elles supposeront que vous utilisez l'émulation Unix et appliqueront les règles de syntaxe Unix à la place, pour cet appel de fonction uniquement.

VOIR AUSSI
