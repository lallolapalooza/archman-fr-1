DESCRIPTION

Une assertion FIDO2 est une collection d'énoncés, chaque énoncé étant une correspondance entre un défi, un identifiant d'accès, une signature et des attributs auxiliaires. Dans libfido2, une assertion FIDO2 est abstraite par le type fido_assert_t . Les fonctions décrites dans cette page permettent d'allouer, de désallouer et d'inspecter un type fido_assert_t . Pour d'autres opérations sur fido_assert_t, veuillez consulter fido_assert_set_authdata(3), fido_assert_allow_cred(3), fido_assert_verify(3), et fido_dev_get_assert(3).

La fido_assert_new() fonction renvoie un pointeur vers un type fido_assert_t nouvellement alloué et vide. Si la mémoire ne peut pas être allouée, NULL est renvoyé.

DESCRIPTION

The fido_assert_free() function libère la mémoire allouée pour *assert_p, où *assert_p doit avoir été préalablement alloué par fido_assert_new(). Au retour, *assert_p est mis à NULL. Soit assert_p, soit *assert_p peut être NULL, auquel cas fido_assert_free() ne fait rien.

La fonction fido_assert_count() retourne le nombre d'instructions dans assert.

La fonction fido_assert_rp_id() retourne un pointeur vers une chaîne de caractères terminée par NULL contenant l'ID de la partie utilisatrice de assert.

Les fonctions fido_assert_user_display_name(), fido_assert_user_icon() et fido_assert_user_name() retournent des pointeurs vers les attributs de nom d'affichage de l'utilisateur, d'icône et de nom de l'instruction idx dans assert. Si non NULL, les valeurs retournées par ces fonctions pointent vers des chaînes UTF-8 terminées par NULL. Les attributs de nom d'affichage de l'utilisateur, d'icône et de nom ne seront généralement retournés par l'authentificateur que si la vérification de l'utilisateur a été effectuée par l'authentificateur et que plusieurs identifiants résidents/découvrables étaient impliqués dans l'assertion.

Les fonctions fido_assert_authdata_ptr(), fido_assert_authdata_raw_ptr(), fido_assert_clientdata_hash_ptr(), fido_assert_id_ptr(), fido_assert_user_id_ptr(), fido_assert_sig_ptr(), fido_assert_sigcount() et fido_assert_flags() retournent des pointeurs vers les données de l'authentificateur et la signature encodées en CBOR, le hachage des données client, l'ID de l'identifiant, l'ID de l'utilisateur, la signature, le nombre de signatures et les indicateurs des données de l'authentificateur de l'instruction idx dans assert.

La fonction fido_assert_hmac_secret_ptr() retourne un pointeur vers l'attribut hmac-secret de l'instruction idx dans assert. L'extension HMAC Secret (hmac-secret) est une extension CTAP 2.0. Notez que le hmac-secret résultant varie selon que la vérification de l'utilisateur a été effectuée par l'authentificateur.

Les fonctions fido_assert_blob_ptr() et fido_assert_largeblob_key_ptr() retournent des pointeurs vers les attributs "credBlob" et "largeBlobKey" de l'instruction idx dans assert. Credential Blob (credBlob) et Large Blob Key (largeBlobKey) sont des extensions CTAP 2.1.

Les fonctions fido_assert_authdata_len(), fido_assert_authdata_raw_len(), fido_assert_clientdata_hash_len(), fido_assert_id_len(), fido_assert_user_id_len(), fido_assert_sig_len(), fido_assert_hmac_secret_len(), fido_assert_blob_len() et fido_assert_largeblob_key_len() retournent la longueur d'un attribut donné.

Veuillez noter que la première instruction dans assert a une valeur d'index (idx) de 0.

Les données de l'authentificateur et les parties de signature d'une instruction d'assertion sont généralement transmises à un serveur FIDO2 pour vérification.

VALEURS DE RETOUR

Les données de l'authentificateur retournées par fido_assert_authdata_ptr() sont une chaîne d'octets encodée en CBOR, telle qu'obtenue de l'authentificateur.

Les fonctions fido_assert_rp_id(), fido_assert_user_display_name(), fido_assert_user_icon(), fido_assert_user_name(), fido_assert_authdata_ptr(), fido_assert_clientdata_hash_ptr(), fido_assert_id_ptr(), fido_assert_user_id_ptr(), fido_assert_sig_ptr(), fido_assert_hmac_secret_ptr(), fido_assert_blob_ptr() et fido_assert_largeblob_key_ptr() peuvent retourner NULL si le champ respectif dans assert n'est pas défini. Si non NULL, les pointeurs retournés sont garantis d'exister jusqu'à ce que toute fonction API qui prend assert sans le qualificateur const soit invoquée.
