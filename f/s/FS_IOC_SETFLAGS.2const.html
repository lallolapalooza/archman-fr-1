FS_IOC_SETFLAGS(2const) FS_IOC_SETFLAGS(2const)

NOM

FS_IOC_GETFLAGS, FS_IOC_SETFLAGS - opérations ioctl() pour les drapeaux d'inode

SYNTAXE

#include <linux/fs.h>  /* Définition des constantes FS_* */
#include <sys/ioctl.h>
int ioctl(int fd, FS_IOC_GETFLAGS, int *attr);
int ioctl(int fd, FS_IOC_SETFLAGS, const int *attr);

DESCRIPTION

Divers systèmes de fichiers Linux supportent la notion de drapeaux d'inode — attributs qui modifient la sémantique des fichiers et des répertoires. Ces drapeaux peuvent être récupérés et modifiés à l'aide de deux opérations ioctl(2) :


int attr;
fd = open("chemin", ...);
ioctl(fd, FS_IOC_GETFLAGS, &attr);  /* Place les drapeaux actuels
                                       dans 'attr' */
attr |= FS_NOATIME_FL;              /* Modifie le masque de bits retourné */
ioctl(fd, FS_IOC_SETFLAGS, &attr);  /* Met à jour les drapeaux pour l'inode
                                       référencé par 'fd' */

Les commandes shell lsattr(1) et chattr(1) fournissent des interfaces à ces deux opérations, permettant à un utilisateur de visualiser et de modifier les drapeaux d'inode associés à un fichier.

Les drapeaux suivants sont supportés (affichés avec la lettre correspondante utilisée pour indiquer le drapeau par lsattr(1) et chattr(1)) :

FS_APPEND_FL 'a'
Le fichier ne peut être ouvert qu'avec le drapeau O_APPEND. S'il est appliqué à un répertoire, il interdit la suppression de fichiers du répertoire (via unlink(), rename(), etc.). (Cette restriction s'applique même au superutilisateur.) Seul un processus privilégié (CAP_LINUX_IMMUTABLE) peut définir ou effacer cet attribut.
FS_COMPR_FL 'c'
Stocke le fichier dans un format compressé sur disque. Ce drapeau n'est pas supporté par la plupart des implémentations de systèmes de fichiers courants ; une exception est btrfs(5).
FS_DIRSYNC_FL 'D' (depuis Linux 2.6.0)
Écrit les modifications de répertoire de manière synchrone sur disque. Ce drapeau fournit une sémantique équivalente à l'option MS_DIRSYNC de mount(2), mais par répertoire. Ce drapeau ne peut être appliqué qu'aux répertoires.
FS_IMMUTABLE_FL 'i'
Le fichier est immuable : aucune modification n'est permise sur le contenu ou les métadonnées du fichier (permissions, horodatages, propriété, nombre de liens, etc.). (Cette restriction s'applique même au superutilisateur.) Seul un processus privilégié (CAP_LINUX_IMMUTABLE) peut définir ou effacer cet attribut.
FS_JOURNAL_DATA_FL 'j'
Active la journalisation des données de fichier sur les systèmes de fichiers ext3(5) et ext4(5). Sur un système de fichiers qui journalise en mode ordered ou writeback, un processus privilégié (CAP_SYS_RESOURCE) peut définir ce drapeau pour activer la journalisation des mises à jour de données par fichier.
FS_NOATIME_FL 'A'
Ne met pas à jour le dernier horodatage d'accès au fichier lorsque le fichier est accédé. Cela peut offrir des avantages de performance d'E/S pour les applications qui ne se soucient pas de la précision de cet horodatage. Ce drapeau fournit une fonctionnalité similaire au drapeau MS_NOATIME de mount(2), mais par fichier.
FS_NOCOW_FL 'C' (depuis Linux 2.6.39)
Le fichier ne sera pas soumis aux mises à jour copy-on-write. Ce drapeau n'a d'effet que sur les systèmes de fichiers qui supportent la sémantique copy-on-write, tels que Btrfs. Voir chattr(1) et btrfs(5).
FS_NODUMP_FL 'd'
N'inclut pas ce fichier dans les sauvegardes effectuées à l'aide de dump(8).
FS_NOTAIL_FL 't'
Ce drapeau n'est supporté que sur Reiserfs. Il désactive la fonctionnalité de "tail-packing" de Reiserfs, qui tente de ranger les petits fichiers (et le dernier fragment des fichiers plus grands) dans le même bloc disque que les métadonnées du fichier.
FS_PROJINHERIT_FL 'P' (depuis Linux 4.5)
Hérite de l'identifiant de projet de quota. Les fichiers et sous-répertoires hériteront de l'identifiant de projet du répertoire. Ce drapeau ne peut être appliqué qu'aux répertoires.
FS_SECRM_FL 's'
Marque le fichier pour suppression sécurisée. Cette fonctionnalité n'est implémentée par aucun système de fichiers, car la tâche d'effacer en toute sécurité un fichier d'un support d'enregistrement est étonnamment difficile.
FS_SYNC_FL 'S'
Rend les mises à jour de fichier synchrones. Pour les fichiers, cela rend toutes les écritures synchrones (comme si toutes les ouvertures du fichier étaient faites avec le drapeau O_SYNC). Pour les répertoires, cela a le même effet que le drapeau FS_DIRSYNC_FL.
FS_TOPDIR_FL 'T'
Marque un répertoire pour un traitement spécial sous la stratégie d'allocation de blocs Orlov. Voir chattr(1) pour les détails. Ce drapeau ne peut être appliqué qu'aux répertoires et n'a d'effet que pour ext2, ext3 et ext4.
FS_UNRM_FL 'u'
Permet de "dés-supprimer" le fichier s'il est supprimé. Cette fonctionnalité n'est implémentée par aucun système de fichiers, car il est possible d'implémenter des mécanismes de récupération de fichiers en dehors du noyau.

Dans la plupart des cas, lorsque l'un des drapeaux ci-dessus est défini sur un répertoire, le drapeau est hérité par les fichiers et sous-répertoires créés à l'intérieur de ce répertoire. Les exceptions incluent FS_TOPDIR_FL, qui n'est pas héritable, et FS_DIRSYNC_FL, qui n'est hérité que par les sous-répertoires.

NORMES

Linux.

NOTES

Pour modifier les drapeaux d'inode d'un fichier à l'aide de l'opération FS_IOC_SETFLAGS, l'ID utilisateur effectif de l'appelant doit correspondre au propriétaire du fichier, ou l'appelant doit posséder la capacité CAP_FOWNER.

VOIR AUSSI

ioctl(2), chattr(1), lsattr(1), mount(2), btrfs(5), ext4(5), xfs(5), xattr(7), mount(8)
