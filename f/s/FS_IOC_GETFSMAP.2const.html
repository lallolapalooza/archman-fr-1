ioctl_fsmap(2) Manuel des appels système ioctl_fsmap(2)

NOM

ioctl_fsmap, FS_IOC_GETFSMAP - récupérer la disposition physique du système de fichiers

BIBLIOTHÈQUE

Bibliothèque C standard (libc,-lc)

SYNOPSIS

#include <linux/fsmap.h>  /* Définition de FS_IOC_GETFSMAP,
                             FM?_OF_*et des constantes *FMR_OWN_* */
#include <sys/ioctl.h>
int ioctl(int fd, FS_IOC_GETFSMAP, struct fsmap_head * arg);

DESCRIPTION

Cette opération ioctl(2) récupère les correspondances d'étendues physiques pour un système de fichiers. Ces informations peuvent être utilisées pour découvrir quels fichiers sont mappés vers un bloc physique, examiner l'espace libre ou trouver des blocs connus comme défectueux, entre autres.

Le seul argument de cette opération doit être un pointeur vers une seule struct fsmap_head:


struct fsmap {
    __u32 fmr_device;      /* ID de périphérique */
    __u32 fmr_flags;       /* Drapeaux de correspondance */
    __u64 fmr_physical;    /* Décalage du segment sur le périphérique */
    __u64 fmr_owner;       /* ID du propriétaire */
    __u64 fmr_offset;      /* Décalage du segment dans le fichier */
    __u64 fmr_length;      /* Longueur du segment */
    __u64 fmr_reserved[3]; /* Doit être zéro */
};
struct fsmap_head {
    __u32 fmh_iflags;       /* Drapeaux de contrôle */
    __u32 fmh_oflags;       /* Drapeaux de sortie */
    __u32 fmh_count;        /* Nombre d'entrées dans le tableau, entrée incluse */
    __u32 fmh_entries;      /* Nombre d'entrées remplies (sortie) */
    __u64 fmh_reserved[6];  /* Doit être zéro */
    struct fsmap fmh_keys[2];  /* Clés basse et haute pour
                                  la recherche de correspondance */
    struct fsmap fmh_recs[];   /* Enregistrements retournés */
};

Les deux éléments du tableau fmh_keys spécifient la clé de correspondance inverse la plus basse et la plus haute pour lesquelles l'application souhaite obtenir des informations de correspondance physique. Une clé de correspondance inverse se compose du tuple (périphérique, bloc, propriétaire, décalage). Les champs propriétaire et décalage font partie de la clé car certains systèmes de fichiers prennent en charge le partage de blocs physiques entre plusieurs fichiers et peuvent donc retourner plusieurs correspondances pour un même bloc physique.

Les correspondances du système de fichiers sont copiées dans le tableau fmh_recs , qui suit immédiatement les données d'en-tête.

Champs de struct fsmap_head

Le champ fmh_iflags est un masque de bits passé au noyau pour modifier la sortie. Aucun drapeau n'est actuellement défini, l'appelant doit donc définir cette valeur à zéro.

Le champ fmh_oflags est un masque de bits des drapeaux définis par le noyau concernant les correspondances retournées. Si FMH_OF_DEV_T est défini, alors le champ fmr_device représente une structure dev_t contenant les numéros majeur et mineur du périphérique de bloc.

Le champ fmh_count contient le nombre d'éléments du tableau passé au noyau. Si cette valeur est 0, fmh_entries sera défini au nombre d'enregistrements qui auraient été retournés si le tableau avait été suffisamment grand ; aucune information de correspondance ne sera retournée.

Le champ fmh_entries contient le nombre d'éléments du tableau fmh_recs qui contiennent des informations utiles.

Les champs fmh_reserved doivent être définis à zéro.

Clés

Les deux enregistrements de clés dans fsmap_head.fmh_keys spécifient les enregistrements d'étendues les plus bas et les plus hauts dans l'espace de clés que l'appelant souhaite voir retournés. Un système de fichiers qui peut partager des blocs entre des fichiers nécessite probablement le tuple (périphérique, physique, propriétaire, décalage, drapeaux) pour indexer de manière unique tout enregistrement de correspondance du système de fichiers. Les systèmes de fichiers classiques sans partage peuvent être en mesure d'identifier tout enregistrement avec seulement (périphérique, physique, drapeaux). Par exemple, si la clé basse est définie à (8:0, 36864, 0, 0, 0), le système de fichiers ne retournera que les enregistrements pour les étendues commençant à partir de 36 KiB sur le disque. Si la clé haute est définie à (8:0, 1048576, 0, 0, 0), seuls les enregistrements en dessous de 1 MiB seront retournés. Le format de fmr_device dans les clés doit correspondre au format du même champ dans les enregistrements de sortie, tel que défini ci-dessous. Par convention, le champ fsmap_head.fmh_keys[0] doit contenir la clé basse et fsmap_head.fmh_keys[1] doit contenir la clé haute pour l'opération.

Par commodité, si fmr_length est défini dans la clé basse, il sera ajouté à fmr_block ou fmr_offset selon le cas. L'appelant peut tirer parti de cette subtilité pour préparer des appels ultérieurs en copiant fsmap_head.fmh_recs[fsmap_head.fmh_entries - 1] dans la clé basse. La fonction fsmap_advance (définie dans linux/fsmap.h) fournit cette fonctionnalité.

Champs de struct fsmap

Le champ fmr_device identifie de manière unique le périphérique de stockage sous-jacent. Si le drapeau FMH_OF_DEV_T est défini dans le champ fmh_oflags de l'en-tête, ce champ contient un dev_t à partir duquel les numéros majeur et mineur peuvent être extraits. Si le drapeau n'est pas défini, ce champ contient une valeur qui doit être unique pour chaque périphérique de stockage unique.

Le champ fmr_physical contient l'adresse disque de l'étendue en octets.

Le champ fmr_owner contient le propriétaire de l'étendue. Il s'agit d'un numéro d'inode, sauf si FMR_OF_SPECIAL_OWNER est défini dans le champ fmr_flags , auquel cas la valeur est déterminée par le système de fichiers. Voir la section ci-dessous sur les valeurs de propriétaire pour plus de détails.

Le champ fmr_offset contient l'adresse logique dans l'enregistrement de correspondance en octets. Ce champ n'a pas de sens si les drapeaux FMR_OF_SPECIAL_OWNER ou FMR_OF_EXTENT_MAP sont définis dans fmr_flags.

Le champ fmr_length contient la longueur de l'étendue en octets.

Le champ fmr_flags est un masque de bits des drapeaux d'état d'étendue. Les bits sont :

FMR_OF_PREALLOC
L'étendue est allouée mais pas encore écrite.
FMR_OF_ATTR_FORK
Cette étendue contient des données d'attributs étendus.
FMR_OF_EXTENT_MAP
Cette étendue contient des informations de correspondance d'étendues pour le propriétaire.
FMR_OF_SHARED
Des parties de cette étendue peuvent être partagées.
FMR_OF_SPECIAL_OWNER
Le champ fmr_owner contient une valeur spéciale au lieu d'un numéro d'inode.
FMR_OF_LAST
C'est le dernier enregistrement de l'ensemble de données.

Le champ fmr_reserved sera défini à zéro.

Valeurs de propriétaire

Généralement, la valeur du champ fmr_owner pour les étendues non-métadonnées devrait être un numéro d'inode. Cependant, les systèmes de fichiers ne sont pas tenus de rapporter des numéros d'inodes ; ils peuvent à la place rapporter FMR_OWN_UNKNOWN si le numéro d'inode ne peut pas être facilement récupéré, si l'appelant manque de privilèges suffisants, si le système de fichiers ne prend pas en charge les numéros d'inodes stables, ou pour toute autre raison. Si un système de fichiers souhaite conditionner le rapport des numéros d'inodes en fonction des capacités du processus, il est fortement recommandé d'utiliser la capacité CAP_SYS_ADMIN à cette fin.

Les valeurs de propriétaire spéciales suivantes sont génériques à tous les systèmes de fichiers :
FMR_OWN_FREE
Espace libre.
FMR_OWN_UNKNOWN
Cette étendue est utilisée mais son propriétaire n'est pas connu ou ne peut pas être facilement récupéré.
FMR_OWN_METADATA
Cette étendue est des métadonnées du système de fichiers.

XFS peut retourner les valeurs de propriétaire spéciales suivantes :

XFS_FMR_OWN_FREE
Espace libre.
XFS_FMR_OWN_UNKNOWN
Cet extent est en cours d'utilisation mais son propriétaire n'est pas connu ou n'est pas facilement récupérable.
XFS_FMR_OWN_FS
Métadonnées statiques du système de fichiers qui existent à une adresse fixe. Il s'agit du superblock AG, de l'AGF, de l'AGFL et des en-têtes AGI.
XFS_FMR_OWN_LOG
Le journal du système de fichiers.
XFS_FMR_OWN_AG
Métadonnées du groupe d'allocation, telles que les arbres b de l'espace libre et les arbres b de la correspondance inverse.
XFS_FMR_OWN_INOBT
Les arbres b des inodes et des inodes libres.
XFS_FMR_OWN_INODES
Enregistrements d'inodes.
XFS_FMR_OWN_REFC
Informations de comptage de références.
XFS_FMR_OWN_COW
Cet extent est utilisé pour préparer une copie sur écriture.
XFS_FMR_OWN_DEFECTIVE:
Cet extent a été marqué comme défectueux, soit par le système de fichiers, soit par le périphérique sous-jacent.

ext4 peut retourner les valeurs de propriétaire spéciales suivantes :

EXT4_FMR_OWN_FREE
Espace libre.
EXT4_FMR_OWN_UNKNOWN
Cet extent est en cours d'utilisation mais son propriétaire n'est pas connu ou n'est pas facilement récupérable.
EXT4_FMR_OWN_FS
Métadonnées statiques du système de fichiers qui existent à une adresse fixe. Il s'agit du superblock et des descripteurs de groupe.
EXT4_FMR_OWN_LOG
Le journal du système de fichiers.
EXT4_FMR_OWN_INODES
Enregistrements d'inodes.
EXT4_FMR_OWN_BLKBM
Table de bits des blocs.
EXT4_FMR_OWN_INOBM
Table de bits des inodes.

VALEUR RETOURNÉE

En cas d'erreur, -1 est retourné et errno est défini pour indiquer l'erreur.

ERREURS

L'erreur placée dans errno peut être l'une des suivantes, sans que cette liste soit exhaustive :

EBADF
fd n'est pas ouvert en lecture.
EBADMSG
Le système de fichiers a détecté une erreur de somme de contrôle dans les métadonnées.
EFAULT
Le pointeur passé n'était pas mappé vers une adresse mémoire valide.
EINVAL
Le tableau n'est pas assez long, les clés ne pointent pas vers une partie valide du système de fichiers, la clé basse pointe vers un point plus élevé dans l'espace d'adresses physiques de stockage du système de fichiers que la clé haute, ou une valeur non nulle a été passée dans l'un des champs qui doivent être à zéro.
ENOMEM
Mémoire insuffisante pour traiter l'opération.
EOPNOTSUPP
Le système de fichiers ne prend pas en charge cette opération.
EUCLEAN
Les métadonnées du système de fichiers sont corrompues et nécessitent une réparation.

NORMES

Linux.

Tous les systèmes de fichiers ne le prennent pas en charge.

HISTORIQUE

Linux 4.12.

EXEMPLES

Voir io/fsmap.c dans la xfsprogs distribution pour un programme d'exemple.
