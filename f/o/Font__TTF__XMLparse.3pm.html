Font__TTF__XMLparse(3pm)

Paquet: perl-font-ttf

Licences: Artistic2.0

Font::TTF::XMLparse(3) Documentation Perl fournie par l'utilisateur Font::TTF::XMLparse(3)

NOM

Font::TTF::XMLparse - fournit un support pour l'analyse XML. Nécessite le module Expat XML::Parser::Expat

SYNOPSIS

use Font::TTF::Font;
use Font::TTF::XMLparse;
$f = Font::TTF::Font->new;
read_xml($f, $ARGV[0]);
$f->out($ARGV[1]);

DESCRIPTION

Ce module contient les routines de support pour l'analyse XML et la génération des structures de police Truetype qui en résultent. Le module a été séparé du reste du paquet afin de réduire la dépendance que cela apporterait, de l'ensemble du paquet sur XML::Parser. De cette façon, les personnes sans XML::Parser peuvent toujours utiliser le reste du paquet.

Le paquet interagit avec un autre paquet par l'utilisation d'un contexte contenant un élément 'receiver' qui est un objet susceptible de recevoir l'un des messages suivants:

XML_start
Ce message est appelé lorsqu'une balise ouvrante se produit. Il est appelé avec le contexte, le nom de la balise et les attributs. La valeur de retour n'a pas de signification.
XML_end
Ce message est appelé lorsqu'une balise fermante se produit. Il est appelé avec le contexte, le nom de la balise et les attributs (transmis depuis l'ouverture de la balise). Il y a 3 valeurs de retour possibles pour un tel message:
undef
C'est la valeur de retour par défaut indiquant qu'un traitement par défaut doit avoir lieu, soit l'élément actuel dans l'arbre, soit le texte de cet élément doit être stocké dans l'objet parent.
$context
Cette valeur magique indique que l'élément doit être supprimé du parent. Rien n'est stocké dans le parent. (Ceci plutôt que '' est utilisé pour permettre des retours 0.)
quelque chose
Toute autre chose est considérée comme le contenu de l'élément à stocker dans le parent.

De plus, le hachage de contexte passé à ces messages contient les clés suivantes:

xml
C'est l'objet xml d'expat. Le contexte est également disponible sous la forme $context->{'xml'}{' mycontext'}. Mais c'est une façon longue et compliquée de ne pas dire grand-chose !
police
C'est l'objet de base qui a été passé pour l'analyse XML.
récepteur
Ceci contient le récepteur actuel des événements d'analyse. Il peut être défini dans l'application associée pour ajuster quels objets doivent recevoir les messages quand. Il est également stocké dans la pile d'analyse pour s'assurer que, lorsqu'un objet le modifie lors de XML_start, le même objet qui a reçu XML_start recevra le XML_end correspondant.
pile
C'est la pile d'analyse, utilisée en interne pour conserver le récepteur et les attributs actuels pour chaque élément ouvert, sous forme de hiérarchie complète jusqu'à l'élément racine.
arbre
Cet élément contient l'arbre de stockage correspondant au parent de chaque élément de la pile. L'action par défaut est de pousser undef sur cette pile pendant XML_start, puis de résoudre cela, soit dans l'application associée (en changeant $context->{'tree'}[-1]), soit lors de XML_end d'un élément enfant, moment où nous savons si nous avons affaire à un tableau, un hachage ou autre chose.
texte
Le traitement des caractères consiste à insérer tous les caractères dans l'élément texte du contexte pour une utilisation ultérieure.
