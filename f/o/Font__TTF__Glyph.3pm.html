NOM

Font::TTF::Glyph - Contient les informations pour un seul glyphe

DESCRIPTION

Ceci est la description d'un glyphe unique telle que conservée dans une police TT. À la création, seul son en-tête est lu. Ainsi, vous pouvez obtenir la boîte englobante de chaque glyphe sans avoir à lire toutes les autres informations.

VARIABLES D'INSTANCE

En plus des variables nommées dans l'en-tête d'un glyphe ("xMin" etc.), il existe également des variables d'instance en majuscules pour conserver les informations de travail, principalement issues de la table de localisation.

Variables pour tous les glyphes :

Les attributs standard que chaque glyphe possède sont :

numberOfContours
Pour les glyphes simples, ceci sera le nombre de contours. Pour les glyphes composites, ce sera -1.
xMin
yMin
xMax
yMax
Celles-ci identifient la boîte englobante du glyphe.

Il existe également d'autres variables dinstance dérivées pour chaque glyphe qui sont lues lorsque le glyphe entier est lu (via "read_dat") :

instLen
Nombre d'octets dans les instructions de hinting (Attention, cette variable est obsolète, utilisez "length($g-"{'hints'})>
hints
La chaîne contenant le code de hinting pour le glyphe

Variables pour les glyphes simples (numberOfContours >= 0) :

endPoints
Un tableau des points de fin pour chaque contour dans le glyphe. Il y a "numberOfContours" contours dans un glyphe. Le nombre de points dans un glyphe est égal au point de fin le plus élevé d'un contour.
numPoints
Ceci est une valeur générée qui contient le nombre total de points pour ce glyphe simple.

Il existe également un certain nombre de tableaux indexés par le numéro de point :

flags
Les indicateurs associés à la lecture de ce point. Les indicateurs d'un point sont recalculés pour un point lorsqu'il est "update"d. Ainsi, les indicateurs ne sont pas très utiles. Le seul bit important est le bit 0 qui indique si le point est un point 'on' curve (sur la courbe) ou un point 'off' curve (hors courbe).
x
La coordonnée x absolue du point.
y
La coordonnée y absolue du point

Variables pour les glyphes composites (numberOfContours == -1) :

metric
Ceci conserve le numéro du composant (et non son numéro de glyphe) du composant à partir duquel les métriques de ce glyphe doivent être prises.
comps
Ceci est un tableau de hachages pour chaque composant. Chaque hachage a un certain nombre d'éléments :
glyph
Le numéro de glyphe du glyphe qui compose ce composant du composite. REMARQUE : Dans certaines polices mal générées, "glyph" peut contenir une valeur numérique mais ce glyphe pourrait ne pas réellement exister dans le fichier de police. Cela pourrait se produire pour n'importe quel glyphe, mais est particulièrement probable pour les glyphes qui n'ont pas de traits, tels que ESPACE, U+00A0 ESPACE INSÉPARABLE, ou U+200B ESPACE DE LARGEUR ZÉRO.
args
Un tableau de deux arguments qui peuvent être une coordonnée x, y ou deux points d'attachement (un sur le glyphe de base, l'autre sur le composant). Voir les indicateurs pour plus de détails.
flag
L'indicateur pour ce composant
scale
Un tableau de 4 nombres pour la mise à l'échelle du composant. Cela permet l'étirement, la rotation, etc. Notez que la mise à l'échelle s'applique aux coordonnées de placement (plutôt qu'aux points d'attachement) avant le positionnement plutôt qu'après.
numPoints
Ceci est une valeur générée qui contient le nombre de composants lus pour ce glyphe composite.

Variables d'instance privées :

INFILE (P)
Le fichier d'entrée à partir duquel lire les informations
LOC (P)
Position relative au début de la table glyf dans le fichier lu
BASE (P)
La position de la table glyf dans le fichier lu
LEN (P)
Ceci est le nombre d'octets requis par le glyphe. Il devrait être mis à jour en appelant la "update" méthode chaque fois que le contenu du glyphe change.
OUTLOC (P)
Position relative au début de la table glyf. Cette variable n'est active que pendant le processus de sortie. Elle est utilisée pour informer la table de localisation de l'emplacement du glyphe, car la table glyf est sortie avant la table loca en raison de l'ordre alphabétique.
OUTLEN (P)
Ceci indique la longueur des données du glyphe lorsqu'elles sont sorties. Cela reflète plus précisément la forme en mémoire interne que la "LEN" variable qui ne reflète que la longueur du fichier lu. La "OUTLEN" variable n'est définie qu'après avoir appelé "out" ou "out_dat".

Édition

Si vous souhaitez modifier un glyphe d'une manière ou d'une autre, vous devriez lire le glyphe avec read_dat, puis faire vos modifications et ensuite mettre à jour le glyphe ou définir la $g->{' isDirty'} variable. L'application doit s'assurer que les variables d'instance suivantes sont correctes, à partir desquelles update calculera le reste, y compris les informations de la boîte englobante.

numPoints
numberOfContours
endPoints
x, y, flags         (seulement le bit 0 de flags)
instLen
hints

Pour les composants, les numPoints, x, y, endPoints et flags ne sont pas requis mais les informations suivantes sont requises pour chaque composant.

flag                (bits 2, 10, 11, 12)
glyph
args
scale
metric              (variable d'instance du glyphe)

MÉTHODES

Font::TTF::Glyph->new(%parms)

Crée un nouveau glyphe en définissant diverses variables d'instance

$g->read

Lit le composant en-tête du glyphe (numberOfContours et boîte englobante) et aussi le contenu du glyphe, mais dans un champ de données plutôt que de le décomposer en ses structures constituantes. Utilisez read_dat pour cela.

$g->read_dat

Lit le contenu du glyphe (composants et courbes, etc.) depuis le stockage en mémoire "DAT" vers les structures dans l'objet.

$g->out($fh)

Écrit les données du glyphe vers outfile

$g->out_xml($context, $depth)

Sortie d'une description XML du glyphe

$g->dirty($val)

Cela définit le drapeau « dirty » à la valeur donnée ou à 1 si aucune valeur n'est donnée. Elle renvoie la valeur du drapeau

$g->update

Génère un "$self-"{'DAT'}> à partir des structures internes, si les données ont été lues dans les structures en premier lieu. Si vous construisez un glyphe à partir de zéro, vous devrez définir la variable d'instance ' isDirty'.

$g->update_bbox

Met à jour la boîte englobante de ce glyphe en fonction des points du glyphe

$g->maxInfo

Renvoi de nombreuses informations sur un glyphe afin que la table "maxp" puisse se mettre à jour elle-même. Renvoie un tableau contenant les contributions de ce glyphe à maxPoints, maxContours, maxCompositePoints, maxCompositeContours, maxSizeOfInstructions, maxComponentElements et maxComponentDepth.

$g->empty

Vide le glyphe de toutes ses informations au point de ne plus avoir été lu. Utile pour économiser de la mémoire dans les applications où de nombreux glyphes sont lus

$g->get_points

Cette méthode crée des informations de points pour un glyphe composé. Les informations sont stockées au même endroit que si le glyphe n'était pas un composé, mais comme numberOfContours est négatif, le glyphe est toujours marqué comme étant un composé

$g->get_refs

Renvoi d'un tableau de tous les identifiants de glyphes utilisés pour composer ce glyphe. C'est-à-dire tous les composés et leurs références, et ainsi de suite. Si ce glyphe n'est pas un composé, renvoie un tableau vide.

Veuillez noter l'avertissement concernant les mauvaises polices qui référencent des glyphes inexistants dans la section VARIABLES D'INSTANCE ci-dessus. Cette fonction ne tentera pas de filtrer les numéros de glyphes inexistants.

BUGS

  • Les variables d'instance utilisées ici sont quelque peu lourdes et incohérentes avec les autres tables.
  • "update" ne recalcule pas la boîte englobante ou "numberOfContours".
