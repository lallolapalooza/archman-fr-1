$f->release

Libère TOUTE la mémoire utilisée par la police TTF et tous ses objets composants. Après avoir appelé cette méthode, ne vous attendez PAS à ce qu'il reste quoi que ce soit dans l'objet "Font::TTF::Font".

NOTE, il est important que vous appeliez cette méthode sur tout objet "Font::TTF::Font" lorsque vous souhaitez le détruire et libérer sa mémoire. En interne, nous suivons les choses dans une structure qui peut entraîner des références circulaires, et sans appeler 'release()' elles ne seront pas correctement nettoyées par Perl. Une fois que vous avez appelé cette méthode, cependant, ne vous attendez pas à pouvoir faire quoi que ce soit d'autre avec l'objet "Font::TTF::Font" ; il n'aura absolument aucun état interne.

Note pour le développeur : Dans le cadre du nettoyage brutal effectué ici, cette méthode émettra un message d'avertissement chaque fois que des valeurs de clés inattendues seront trouvées dans l'objet "Font::TTF::Font". Ceci est fait pour aider à assurer que toutes les valeurs inattendues et non libérées vous soient signalées afin que vous puissiez nous faire bugger pour que nous maintenions le module à jour correctement ; sinon, le potentiel de fuites de mémoire dues à des références circulaires pendantes existera.

BUGS

Les bugs abondent, j'en suis sûr. Il y a beaucoup de code ici et une grande place pour des bugs. Les parties du code qui n'ont pas encore été implémentées sont :

Post
Les formats de type 4 ne sont pas encore pris en charge.
Cmap
Le format de type 2 (MBCS) n'a pas encore été implémenté et peut donc causer des résultats quelque peu fallacieux pour ce type de table.
Kern
Seules les tables de type 0 et de type 2 sont prises en charge (les types 1 et 3 sont à venir).
TTC et WOFF
La méthode Font::TTF::Font::out actuelle ne prend pas en charge l'écriture de Collections TrueType ou de fichiers WOFF.
DSIG
N'a pas encore trouvé comment calculer et sortir correctement la table de signature numérique (DSIG).

De plus, il y a des faiblesses ou des caractéristiques de cette bibliothèque de modules.

  • Il y a très peu (voire pas) de rapports d'erreurs. Cela signifie que si vous avez des données corrompues ou des structures de données corrompues, vous risque de générer des polices erronées.
  • L'exposition des structures de données internes partout signifie que faire des réorganisations radicales est presque impossible. Mais cela évite que le code ne devienne ridiculement grand.

À part cela, j'essaie de maintenir le code dans un état de "pas de bugs connus", ce qui, compte tenu de la quantité de tests effectués sur ce code, n'est pas une garantie de haute qualité, pour l'instant.

Pour plus de détails, voir les fichiers de classe appropriés.
