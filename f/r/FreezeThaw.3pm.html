FreezeThaw(3pm)

Paquet: perl-freezethaw

Licences: GPL, PerlArtistic

FreezeThaw(3pm) Documentation Perl fournie par l'utilisateur FreezeThaw(3pm)

NOM

FreezeThaw - convertir des structures Perl en chaînes de caractères et vice versa.

SYNTHAXE

use FreezeThaw qw(freeze thaw cmpStr safeFreeze cmpStrHard);
$string = freeze $data1, $data2, $data3;
...
($olddata1, $olddata2, $olddata3) = thaw $string;
if (cmpStr($olddata2,$data2) == 0) {print "OK!"}

DESCRIPTION

Convertit des données en/depuis une forme chaînée, appropriée pour l'enregistrement/la lecture à partir d'un stockage permanent.

Gère les objets, les listes circulaires, les apparitions répétées de la même référence. Ne gère pas encore l'opérateur de chaînage surchargé stringify.

EXPORT

Par défaut
Aucun.
Exportable
"freeze thaw cmpStr cmpStrHard safeFreeze".

API Utilisateur

"cmpStr"
analogue de "cmp" pour les données. Prend deux arguments et les compare comme des entités séparées.
"cmpStrHard"
analogue de "cmp" pour les données. Prend deux arguments et les compare en considérant comme un groupe.
"freeze"
retourne une chaîne qui encapsule ses arguments (considérés comme un groupe). Le fait de "thaw" cette chaîne entraîne une erreur fatale si les arguments de "freeze" contiennent des références à des "GLOB"s et des "CODE"s.
"safeFreeze"
retourne une chaîne qui encapsule ses arguments (considérés comme un groupe). Le résultat est "thaw"able dans le même processus. Le fait de "thaw" le résultat dans un processus différent devrait entraîner une erreur fatale si les arguments de "safeFreeze" contenaient des références à des "GLOB"s et des "CODE"s.
"thaw"
prend un argument de chaîne et retourne un tableau. Les éléments du tableau sont "équivalents" aux arguments de la commande "freeze" qui a créé la chaîne. Peut entraîner une erreur fatale (voir ci-dessus).

API Développeur

"FreezeThaw" "freeze" et "thaw" les données bénies dans un certain package en appelant les méthodes "Freeze" et "Thaw" dans le package. Les méthodes de repli sont fournies par "FreezeThaw" lui-même. La méthode de repli "Freeze" gèle le "contenu" de l'objet béni (du point de vue de Perl). La méthode de repli "Thaw" bénit les données "thaw"ées de retour dans le package.

Le package doit donc définir ses propres méthodes uniquement si les méthodes de repli échouent (par exemple, pour beaucoup de données, le "contenu" d'un objet est l'adresse de données **C**).

$newcooky = $obj->Freeze($cooky);
$obj = Package->Thaw($content,$cooky);

Pour enregistrer et restaurer les données, les méthodes suivantes sont applicables :

$cooky->FreezeScalar($data,$ignorePackage,$noduplicate);

pendant la "Freeze", et

$data = $cooky->ThawScalar;

Deux arguments optionnels $ignorePackage et $noduplicate régulent si la congélation ne doit pas appeler les méthodes même si $data est une référence à un objet béni, et si les données ne doivent pas être marquées comme déjà vues même si elles l'ont été auparavant. Les méthodes par défaut

sub UNIVERSAL::Freeze {
  my ($obj, $cooky) = (shift, shift);
  $cooky->FreezeScalar($obj,1,1);
}
sub UNIVERSAL::Thaw {
  my ($package, $cooky) = (shift, shift);
  my $obj = $cooky->ThawScalar;
  bless $obj, $package;
}

appellent la méthode "FreezeScalar" de $cooky car le moteur de congélation verra les données une seconde fois lors de cet appel. En effet, c'est le moteur de congélation qui appelle UNIVERSAL::Freeze(), et il l'appelle car il doit congeler $obj. L'appel ci-dessus à $cooky->FreezeScalar() renvoie les mêmes données au moteur, mais comme les indicateurs sont différents, le code ne boucle pas.

Congeler et décongeler $cooky permet également les méthodes supplémentaires suivantes :

$cooky->isSafe;

pour savoir si la congélation actuelle a été initiée par la commande "freeze" ou "safeFreeze". La méthode analogue pour décongeler $cooky retourne si l'opération de décongélation actuelle est considérée comme sûre (c'est-à-dire, soit elle ne contient pas de données mises en cache ailleurs, soit elle provient de la même application). Vous pouvez utiliser

$cooky->makeSafe;

pour interdire les données mises en cache pendant le reste de la congélation ou de la décongélation de l'objet actuel.

Deux méthodes

$value = $cooky->repeatedOK;
$cooky->noRepeated;           # Maintenant les répétitions sont interdites

permettent de connaître/changer le paramètre actuel pour autoriser les références répétées.

Si vous voulez vider le cache des objets enregistrés, vous pouvez utiliser

FreezeThaw->flushCache;

cela peut invalider certaines chaînes gelées, de sorte que leur décongélation résultera en une erreur fatale.

Instanciation

Parfois, lorsqu'un objet d'un package est recréé en présence de références répétées, il n'est pas sûr de recréer la structure interne d'un objet en une seule étape. Dans une telle situation, la recréation d'un objet est effectuée en deux étapes : dans la première, l'objet est "allocate"d, dans la seconde, il est "instantiate"d.

La restriction est que pendant l'étape d'*allocation*, vous ne pouvez pas utiliser de référence à un objet Perl qui peut être référencé depuis un autre endroit. Cette restriction s'applique car cet objet peut ne pas encore exister.

En conséquence, pendant l'étape d'*instanciation*, l'objet précédemment *allocaté* doit être "rempli", c'est-à-dire qu'il peut être modifié de toute manière tant que les références à cet objet restent valides.

Les méthodes sont appelées ainsi :

$pre_object_ref = Package->Allocate($pre_pre_object_ref);
      # Retourne une référence
Package->Instantiate($pre_object_ref,$cooky);
      # Convertit en référence à un objet béni

Les opérations inverses sont

$object_ref->FreezeEmpty($cooky);
$object_ref->FreezeInstance($cooky);

pendant ces appels, l'objet peut "freezeScalar" certaines informations (de manière habituelle) qui seront utilisées lors des appels "Allocate" et "Instantiate" (via "thawScalar"). Notez que la valeur de retour de "FreezeEmpty" est mise en cache pendant la phase de création d'objets non initialisés. Ceci **doit** être utilisé ainsi : la valeur de retour est la référence à l'objet créé, donc elle n'est pas détruite tant que d'autres objets ne sont pas créés, par conséquent les valeurs gelées des différents objets ne partageront pas les mêmes références. Exemple de mauvais résultat :

$o1->FreezeEmpty($cooky)

gèle "{}", et "$o2->FreezeEmpty($cooky)" fait de même. Maintenant, personne ne garantit que ces deux copies de "{}" sont différentes, à moins qu'une référence à la première ne soit conservée pendant l'appel à "$o2->FreezeEmpty($cooky)". Si "$o1->FreezeEmpty($cooky)" retourne la valeur de "{}" qu'il utilise, elle sera conservée par le moteur.

La fonction d'aide "FreezeThaw::copyContents" est fournie pour simplifier l'instanciation. La syntaxe est

FreezeThaw::copyContents $to, $from;
