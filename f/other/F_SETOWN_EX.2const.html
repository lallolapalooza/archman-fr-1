Définit l'identifiant de processus ou l'identifiant de groupe de processus qui recevra les signaux SIGIO et SIGURG pour les événements sur le descripteur de fichier fd. L'identifiant du processus ou du groupe de processus cible est spécifié dans arg. Un identifiant de processus est spécifié comme une valeur positive ; un identifiant de groupe de processus est spécifié comme une valeur négative. En plus de définir le propriétaire du descripteur de fichier, on doit également activer la génération de signaux sur le descripteur de fichier. Cela se fait en utilisant l'opération F_SETFL(2const) pour définir l'indicateur d'état de fichier O_ASYNC sur le descripteur de fichier. Par la suite, un signal SIGIO est envoyé chaque fois qu'une entrée ou une sortie devient possible sur le descripteur de fichier. L'opération fcntl() F_SETSIG peut être utilisée pour obtenir la livraison d'un signal autre que SIGI

NAME

F_SETOWN_EX, F_GETOWN_EX, F_SETSIG, F_GETSIG — gérer les informations de propriétaire de fichier et de signal

LIBRARY

Libc, generally

SYNOPSIS

#include <fcntl.h>

int fcntl(int fd, int cmd, ...);

DESCRIPTION

Voir fcntl(2).

Les commandes F_GETOWN, F_SETOWN, F_GETOWN_EX, F_SETOWN_EX, F_GETSIG et F_SETSIG sont utilisées pour gérer les informations de propriétaire de fichier et de signal associées à un descripteur de fichier.

Ces commandes sont utilisées pour l'I/O asynchrone. Quand une opération d'I/O sur le descripteur de fichier fd devient possible (par exemple, une lecture sur un socket où des données sont arrivées, ou une écriture sur un tube qui n'est plus bloquée), un signal est envoyé. Le signal qui est envoyé est déterminé par l'une des méthodes suivantes, examinées dans l'ordre :

1.
Si le descripteur de fichier est associé à un socket, et que la commande F_SETSIG a été utilisée pour spécifier un signal différent de zéro, alors ce signal est envoyé lorsque le socket est prêt pour l'I/O. Le signal est spécifié dans l'argument arg de F_SETSIG. Si SA_SIGINFO est défini pour le gestionnaire de ce signal, des informations supplémentaires sont disponibles dans la structure siginfo_t passée au gestionnaire (voir sigaction(2)).
2.
Sinon, si la commande F_SETSIG a été utilisée pour spécifier un signal différent de zéro, alors ce signal est envoyé lorsque l'I/O devient possible sur le descripteur de fichier. Encore une fois, le signal est spécifié dans l'argument arg de F_SETSIG.
3.
Sinon, si O_ASYNC a été activé pour le descripteur de fichier, alors le signal SIGIO est envoyé lorsque l'I/O devient possible. (Voir fcntl(2) pour F_SETFL et O_ASYNC.)

Le propriétaire du descripteur de fichier (qui recevra le signal) est défini à l'aide des commandes F_SETOWN ou F_SETOWN_EX. Si aucun propriétaire n'est défini, le signal est envoyé au processus qui a ouvert le descripteur de fichier.

Avec F_SETOWN, l'argument arg spécifie l'ID du propriétaire. Si arg est positif, c'est l'ID du processus. Si arg est négatif, c'est l'ID du groupe de processus.

Avec F_SETOWN_EX, l'argument arg pointe vers une structure de type struct f_owner_ex qui spécifie le type de propriétaire et l'ID du propriétaire. Les types de propriétaires sont F_OWNER_TID pour un thread ID, F_OWNER_PID pour un process ID, et F_OWNER_PGID pour un process group ID.

La commande F_GETOWN renvoie l'ID du processus ou du groupe de processus qui est le propriétaire actuel du descripteur de fichier.

La commande F_GETSIG renvoie le signal qui sera envoyé lorsque l'I/O deviendra possible. Une valeur de zéro indique le comportement traditionnel de SIGIO lorsque O_ASYNC est défini.

Les signaux temps réel (valeur >= SIGRTMIN) peuvent être utilisés pour mettre en file d'attente plusieurs événements d'I/O en utilisant les mêmes numéros de signal. (La mise en file d'attente dépend de la mémoire disponible.) Des informations supplémentaires sont disponibles si SA_SIGINFO est défini pour le gestionnaire de signal, comme ci-dessus.

Notez que Linux impose une limite sur le nombre de signaux temps réel qui peuvent être mis en file d'attente pour un processus (voir getrlimit(2) et signal(7)) et si cette limite est atteinte, le noyau revient à la livraison de SIGIO, et ce signal est livré à l'ensemble du processus plutôt qu'à un thread spécifique.

En utilisant ces mécanismes, un programme peut implémenter une I/O entièrement asynchrone sans utiliser select(2) ou poll(2) la plupart du temps.

L'utilisation de O_ASYNC est spécifique à BSD et Linux. La seule utilisation de F_GETOWN et F_SETOWN spécifiée dans POSIX.1 est en conjonction avec l'utilisation du signal SIGURG sur les sockets. (POSIX ne spécifie pas le signal SIGIO.) F_GETOWN_EX, F_SETOWN_EX, F_GETSIG et F_SETSIG sont spécifiques à Linux. POSIX a l'I/O asynchrone et la structure aio_sigevent pour réaliser des choses similaires ; celles-ci sont également disponibles sous Linux dans le cadre de la bibliothèque GNU C (glibc).

BOGUES

F_GETOWN

Une limitation des conventions d'appel système Linux sur certaines architectures (notamment i386) signifie que si un ID de groupe de processus (négatif) à renvoyer par F_GETOWN tombe dans la plage de -1 à -4095, alors la valeur de retour est mal interprétée par glibc comme une erreur dans l'appel système ; c'est-à-dire que la valeur de retour de fcntl() sera -1, et errno contiendra l'ID de groupe de processus (positif). L'opération F_GETOWN_EX spécifique à Linux évite ce problème. Depuis glibc 2.11, glibc rend le problème F_GETOWN du noyau invisible en implémentant F_GETOWN à l'aide de F_GETOWN_EX.

F_SETOWN

Dans Linux 2.4 et antérieur, il existe un bogue qui peut survenir lorsqu'un processus non privilégié utilise F_SETOWN pour spécifier le propriétaire d'un descripteur de fichier socket comme un processus (groupe) autre que l'appelant. Dans ce cas, fcntl() peut renvoyer -1 avec errno défini à EPERM, même lorsque le processus (groupe) propriétaire est celui auquel l'appelant a la permission d'envoyer des signaux. Malgré ce retour d'erreur, le propriétaire du descripteur de fichier est défini, et les signaux seront envoyés au propriétaire.
