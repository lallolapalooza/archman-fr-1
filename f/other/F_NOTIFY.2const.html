F_NOTIFY(2const) F_NOTIFY(2const)

NOM

F_NOTIFY - notification de changement de fichier et de répertoire

BIBLIOTHÈQUE

Bibliothèque C standard (libc, -lc)

SYNTAXE

#define _GNU_SOURCE
#include <fcntl.h>
int fcntl(int fd, F_NOTIFY, int arg);

DESCRIPTION

Fournir une notification lorsque le répertoire référencé par fd ou l'un des fichiers qu'il contient est modifié. Les événements à notifier sont spécifiés dans arg, qui est un masque de bits spécifié en ORant zéro ou plusieurs des bits suivants :

DN_ACCESS
Un fichier a été accédé (read(2), pread(2), readv(2), et similaires)
DN_MODIFY
Un fichier a été modifié (write(2), pwrite(2), writev(2), truncate(2), ftruncate(2), et similaires).
DN_CREATE
Un fichier a été créé (open(2), creat(2), mknod(2), mkdir(2), link(2), symlink(2), rename(2) dans ce répertoire).
DN_DELETE
Un fichier a été désavoué (unlink(2), rename(2) vers un autre répertoire, rmdir(2)).
DN_RENAME
Un fichier a été renommé dans ce répertoire (rename(2)).
DN_ATTRIB
Les attributs d'un fichier ont été modifiés (chown(2), chmod(2), utime(2), utimensat(2), et similaires).

(Afin d'obtenir ces définitions, le macro de test de fonctionnalité _GNU_SOURCE doit être défini avant d'inclure n'importe quel fichier d'en-tête.)

Les notifications de répertoire sont normalement "à usage unique", et l'application doit se réenregistrer pour recevoir des notifications supplémentaires. Alternativement, si DN_MULTISHOT est inclus dans arg, la notification restera active jusqu'à ce qu'elle soit explicitement supprimée.

Une série de requêtes F_NOTIFY est cumulative, les événements dans arg étant ajoutés à l'ensemble surveillé. Pour désactiver la notification de tous les événements, effectuez un appel F_NOTIFY spécifiant arg comme 0.

La notification se produit par la livraison d'un signal. Le signal par défaut est SIGIO, mais cela peut être modifié en utilisant l'opération F_SETSIG sur fcntl(). (Notez que SIGIO est l'un des signaux standard non-queuing ; passer à l'utilisation d'un signal en temps réel signifie que plusieurs notifications peuvent être mises en file d'attente pour le processus.) Dans ce dernier cas, le gestionnaire de signal reçoit une structure siginfo_t comme son deuxième argument (si le gestionnaire a été établi en utilisant SA_SIGINFO) et le champ si_fd de cette structure contient le descripteur de fichier qui a généré la notification (utile lors de l'établissement de notifications sur plusieurs répertoires).

En particulier lors de l'utilisation de DN_MULTISHOT, un signal en temps réel doit être utilisé pour la notification, afin que plusieurs notifications puissent être mises en file d'attente.

NOTE : Les nouvelles applications devraient utiliser l'interface inotify (disponible depuis Linux 2.6.13), qui fournit une interface beaucoup plus performante pour obtenir des notifications d'événements du système de fichiers. Voir inotify(7).

VALEUR DE RETOUR

Zéro.

En cas d'erreur, -1 est retourné et errno est définie pour indiquer l'erreur.

ERREURS

Voir fcntl(2).

ENOTDIR
fd ne référence pas un répertoire.

NORMES

Linux.

HISTORIQUE

Linux 2.4.

VOIR AUSSI
