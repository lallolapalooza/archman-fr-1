NOM

fakeroot - exécute une commande dans un environnement simulant les privilèges root pour la manipulation de fichiers

SYNTAXE

fakeroot [-l|--lib bibliothèque] [--faked binaire-faked] [-i fichier-chargement] [-s fichier-enregistrement] [-u|--unknown-is-real] [-b|--fd-base] [-h|--help] [-v|--version] [--] [commande]

DESCRIPTION

fakeroot exécute une commande dans un environnement où elle semble avoir les privilèges root pour la manipulation de fichiers. Ceci est utile pour permettre aux utilisateurs de créer des archives (tar, ar, .deb etc.) contenant des fichiers avec les permissions/propriétaires root. Sans fakeroot, il faudrait avoir les privilèges root pour créer les fichiers constitutifs des archives avec les bonnes permissions et propriétaires, puis les empaqueter, ou alors il faudrait construire les archives directement, sans utiliser l'outil d'archivage.

fakeroot fonctionne en remplaçant les fonctions de la bibliothèque de manipulation de fichiers (chmod(2), stat(2) etc.) par d'autres qui simulent l'effet que les fonctions réelles de la bibliothèque auraient eu, si l'utilisateur avait réellement été root. Ces fonctions d'encapsulation se trouvent dans une bibliothèque partagée /usr/lib/*/libfakeroot-*.so ou un emplacement similaire sur votre plateforme. L'objet partagé est chargé via le mécanisme LD_PRELOAD du chargeur dynamique. (Voir ld.so(8))

Si vous avez l'intention de construire des paquets avec fakeroot, essayez d'abord de construire le paquet fakeroot : l'étape "debian/rules build" contient quelques tests (testant principalement des bugs dans les anciennes versions de fakeroot). Si ces tests échouent (par exemple parce que vous avez certains programmes libc5 sur votre système), d'autres paquets que vous construirez avec fakeroot échoueront très probablement aussi, mais potentiellement de manière beaucoup plus subtile.

De plus, notez qu'il est préférable de ne pas faire la construction des binaires eux-mêmes sous fakeroot. En particulier, configure et ses similaires n'aiment pas quand le système se comporte soudainement différemment de ce qu'ils attendent (ou, ils désactivent aléatoirement certaines variables d'environnement, dont certaines sont nécessaires à fakeroot).

OPTIONS

-l bibliothèque, --lib bibliothèque
Spécifie une bibliothèque d'encapsulation alternative.
--faked binaire
Spécifie un binaire alternatif à utiliser comme faked.
[--] commande
Toute commande que vous souhaitez exécuter en tant que fakeroot. Utilisez ‘--’ si dans la commande vous avez d'autres options qui pourraient confondre l'analyse des options de fakeroot.
-s fichier-enregistrement
Enregistre l'environnement fakeroot dans fichier-enregistrement à la sortie. Ce fichier peut être utilisé pour restaurer l'environnement plus tard en utilisant -i. Cependant, ce fichier fuira et fakeroot se comportera de manière étrange à moins que vous ne laissiez les fichiers touchés à l'intérieur de fakeroot intacts lorsque vous êtes en dehors de l'environnement. Néanmoins, cela peut être utile. Par exemple, il peut être utilisé avec rsync(1) pour sauvegarder et restaurer des arbres de répertoires entiers complets avec les informations d'utilisateur, de groupe et de périphérique sans avoir besoin d'être root. Voir /usr/share/doc/fakeroot/README.saving pour plus de détails.
-i fichier-chargement
Charge un environnement fakeroot précédemment enregistré avec -s à partir de fichier-chargement. Notez que cela n'enregistre pas implicitement le fichier, utilisez également -s pour ce comportement. L'utilisation du même fichier pour -i et -s dans une seule invocation de fakeroot est sans danger.
-u, --unknown-is-real
Utilise la propriété réelle des fichiers précédemment inconnus de fakeroot au lieu de prétendre qu'ils appartiennent à root:root.
-b fd
Spécifie la base des descripteurs de fichiers (mode TCP uniquement). fd est le numéro minimum de descripteur de fichier à utiliser pour les connexions TCP ; cela peut être important pour éviter les conflits avec les descripteurs de fichiers utilisés par les programmes exécutés sous fakeroot.
-h
Affiche l'aide.
-v
Affiche la version.

EXEMPLES

Voici un exemple de session avec fakeroot. Notez qu'à l'intérieur de l'environnement fakeroot, la manipulation de fichiers qui nécessite des privilèges root réussit, mais ne se produit pas réellement.

$  whoami
joost
$ fakeroot /bin/bash
#  whoami
root
# mknod hda3 b 3 1
# ls -ld hda3
brw-r--r--   1 root     root       3,   1 Jul  2 22:58 hda3
# chown joost:root hda3
# ls -ld hda3
brw-r--r--   1 joost    root       3,   1 Jul  2 22:58 hda3
# ls -ld /
drwxr-xr-x  20 root     root         1024 Jun 17 21:50 /
# chown joost:users /
# chmod a+w /
# ls -ld /
drwxrwxrwx  20 joost    users        1024 Jun 17 21:50 /
# exit
$ ls -ld /
drwxr-xr-x  20 root     root         1024 Jun 17 21:50 //
$ ls -ld hda3
-rw-r--r--   1 joost    users           0 Jul  2 22:58 hda3

Seuls les effets que l'utilisateur joost pouvait de toute façon réaliser se produisent réellement.

fakeroot a été spécifiquement écrit pour permettre aux utilisateurs de créer des paquets Debian GNU/Linux (au format deb(5)) sans leur donner les privilèges root. Cela peut être fait par des commandes comme dpkg-buildpackage -rfakeroot ou debuild -rfakeroot (en fait, -rfakeroot est par défaut dans debuild de nos jours, donc vous n'avez pas besoin de cet argument).

ASPECTS DE SÉCURITÉ

fakeroot est un programme régulier, non setuid. Il n'augmente pas les privilèges d'un utilisateur, ni ne diminue la sécurité du système.

FICHIERS

/usr/lib/*/libfakeroot-*.so La bibliothèque partagée contenant les fonctions d'encapsulation.

ENVIRONNEMENT

FAKEROOTKEY
La clé utilisée pour communiquer avec le démon fakeroot. Tout programme lancé avec la bonne LD_PRELOAD et un FAKEROOTKEY d'un démon en cours d'exécution se connectera automatiquement à ce démon, et aura la même vue "fausse" des permissions/propriétaires du système de fichiers (en supposant que le démon et le programme de connexion ont été lancés par le même utilisateur).
LD_LIBRARY_PATH
LD_PRELOAD
fakeroot est implémenté en encapsulant les appels système. Ceci est accompli en définissant LD_LIBRARY_PATH=/usr/lib/fakeroot et LD_PRELOAD=libfakeroot.so.0. Cette bibliothèque est chargée avant la bibliothèque C du système, et ainsi la plupart des fonctions de bibliothèque sont interceptées par elle. Si vous avez besoin de définir LD_LIBRARY_PATH ou LD_PRELOAD depuis un environnement fakeroot, cela devrait être défini relativement aux chemins donnés, comme dans LD_LIBRARY_PATH=$LD_LIBRARY_PATH:/foo/bar/

Versions de bibliothèque
Chaque commande exécutée dans fakeroot doit être liée à la même version de la bibliothèque C que fakeroot lui-même.

soit 
touch foo
fakeroot
ls -al foo

ou l'inverse,

fakeroot
touch foo
ls -al foo

fakeroot n'a aucun moyen de savoir que dans le premier cas, le propriétaire de foo devrait réellement être joost alors que dans le second cas, il devrait être root. Pour la création de paquets Debian, attribuer par défaut uid=gid=0 à tous les fichiers « inconnus » est toujours acceptable. La véritable solution consiste à envelopper open() et create(), mais cela crée d'autres problèmes, comme l'a démontré le paquet libtricks. Ce paquet enveloppait beaucoup plus de fonctions et essayait de faire bien plus que fakeroot . Il s'est avéré qu'une mise à jour mineure de libc (d'une version où la fonction stat() n'utilisait pas open() à une version où la fonction stat() l'utilisait (dans certains cas) open() ), provoquait des segfaults inexplicables (c'est-à-dire que le stat() de libc6 appelait le open() enveloppé, qui appelait alors le stat() de libc6, etc). Les corriger n'était pas si facile, mais une fois corrigées, il ne faisait qu'une question de temps avant qu'une autre fonction commence à utiliser open(), sans même parler de la tentative de porter cela vers un autre système d'exploitation. J'ai donc décidé de garder le nombre de fonctions enveloppées par fakeroot aussi petit que possible, pour limiter la probabilité de « collisions ».

GNU configure (et d'autres programmes similaires)
fakeroot modifie en effet la manière dont le système se comporte. Les programmes qui interrogent le système, comme GNU configure, peuvent être déroutés par cela (ou, s'ils ne le sont pas, ils peuvent tellement solliciter fakeroot que fakeroot lui-même en devient confus). Il est donc conseillé de ne pas lancer « configure » depuis fakeroot. Comme configure devrait être appelé dans la cible « debian/rules build », lancer « dpkg-buildpackage -rfakeroot » gère correctement cela.

BOGUES

Cela n'enveloppe pas open(). Ce n'est pas grave en soi, mais si un programme fait open("file", O_WRONLY, 000), écrit dans le fichier « file », le ferme, puis tente à nouveau de l'ouvrir pour lire le fichier, alors cette ouverture échoue, car le mode du fichier sera 000. Le bogue est que si root fait la même chose, open() réussira, car les permissions du fichier ne sont pas du tout vérifiées pour root. J'ai choisi de ne pas envelopper open(), car open() est utilisé par de nombreuses autres fonctions dans libc (y compris celles qui sont déjà enveloppées), créant ainsi des boucles (ou des boucles potentielles futures, lorsque l'implémentation de diverses fonctions de libc change légèrement).
