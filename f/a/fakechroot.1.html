FAKECHROOT(1) FAKECHROOT(1)

NOM

fakechroot - donne un environnement chroot simulé

SYNTAXE

fakechroot [-s|--use-system-libs] [-l|--lib bibliothèque] [-d|--elfloader ldso] [-e|--environment type] [-c|--config-dir répertoire] [-b|--bindir répertoire] [--] [commande]

fakechroot -h|--help

fakechroot -v|--version

DESCRIPTION

fakechroot exécute une commande dans un environnement où il est possible d'utiliser la commande chroot(8) sans privilèges root. Ceci est utile pour permettre aux utilisateurs de créer leur propre environnement chrooté avec la possibilité d'installer d'autres paquets sans nécessiter de privilèges root.

fakechroot remplace certaines fonctions de la bibliothèque C (chroot(2), open(2), etc.) par des fonctions qui simulent l'effet d'une exécution avec les privilèges root.

Ces fonctions enveloppantes sont fournies sous forme d'une bibliothèque partagée libfakechroot.so qui est chargée via le mécanisme "LD_PRELOAD" du chargeur dynamique. (Voir ld.so(8))

Dans un faux chroot, vous pouvez installer par exemple un bootstrap Debian avec la commande debootstrap(8). Dans un tel environnement, vous pouvez exécuter par exemple la commande apt-get(8) pour installer d'autres paquets. Vous n'avez pas besoin de privilèges spéciaux et vous pouvez l'exécuter avec un compte utilisateur commun.

OPTIONS

-b|--bindir répertoire
Spécifie un répertoire qui contient les exécutables de remplacement fournis avec fakechroot. Ce sont des fichiers scripts avec l'extension ".fakechroot". Par défaut, ils sont distribués dans les répertoires "bin" et "sbin" du préfixe d'installation de fakechroot, mais un emplacement fixe au moment de la construction n'est parfois pas réalisable.
-c|--config-dir répertoire
Spécifie un répertoire qui contient la configuration supplémentaire pour fakechroot. Les répertoires par défaut sont "$HOME/.fakechroot" et "/etc/fakechroot".
-d ldso|--elfloader ldso
Spécifie un chargeur dynamique alternatif. Ce chargeur dynamique sera invoqué directement.
-e|--environment type
Charge une configuration supplémentaire avec l'environnement. Ce fichier de configuration est un script shell qui est exécuté avant d'appeler la commande . Le script peut définir des variables d'environnement supplémentaires, comme par exemple : "FAKECHROOT_EXCLUDE_PATH", "FAKECHROOT_CMD_SUBST" ou "LD_LIBRARY_PATH".

Le type d'environnement est déduit du nom de la commande, avec suppression de l'extension éventuelle (par exemple, exécuter gettext.sh charge le fichier d'environnement "gettext"). Si l'argument commande est fakeroot(1), cet argument est omis et l'argument suivant est pris comme type d'environnement.

Le nom du fichier de configuration est type.env et est recherché dans les répertoires $HOME/.fakechroot et /etc/fakechroot.

Le type d'environnement par défaut est default et son nom de fichier de configuration est "default.env".

L'environnement spécial none signifie qu'aucun paramètre d'environnement n'est chargé.

-l bibliothèque|--lib bibliothèque
Spécifie une bibliothèque enveloppante alternative. La valeur par défaut est libfakechroot.so
-h|--help
Affiche l'aide.
-s|--use-system-libs
Utilise les bibliothèques système avant les bibliothèques du chroot. Ceci peut être une solution de contournement si le chargeur dynamique système ne parvient pas à charger libc.so depuis le faux chroot.

Essayez ce réglage si vous observez les erreurs suivantes :

$ fakechroot /usr/sbin/chroot /tmp/sarge /bin/true
/bin/true: relocation error: /srv/sarge/lib/tls/libc.so.6: symbol _dl
_starting_up, version GLIBC_PRIVATE not defined in file ld-linux.so.2
 with link time reference
$ fakechroot /usr/sbin/chroot /tmp/centos4 /bin/true
Segmentation fault
-v|--version
Affiche la version.
[--] commande
Toute commande que vous souhaitez exécuter avec fakechroot. Utilisez '--' si la commande contient d'autres options qui pourraient prêter à confusion lors de l'analyse des options de fakechroot.

FAKEROOT

fakeroot(1) est un outil complémentaire qui émule l'environnement root. fakeroot et fakechroot peuvent encapsuler les mêmes fonctions de la bibliothèque C, par exemple la fonction mknod(2). Il est important de démarrer l'environnement simulé dans le bon ordre. fakeroot doit être démarré à l'intérieur de fakechroot :

$ fakechroot fakeroot chroot /tmp/sid /bin/mknod /tmp/device c 1 2

ASPECTS DE SÉCURITÉ

fakechroot est un programme régulier, non setuid. Il n'augmente pas les privilèges d'un utilisateur.

fakechroot ne doit pas être utilisé comme un outil pour améliorer la sécurité du système, par exemple pour isoler (sandbox) des applications. Il est très facile de s'échapper d'un environnement fake chroot.

fakechroot ne doit pas être exécuté avec les privilèges réels de root. Cela pourrait diminuer la sécurité du système car fakechroot fournit sa propre version des fonctions de base avec un comportement dépendant de certaines variables d'environnement.

FICHIERS

libfakechroot.so
La bibliothèque partagée contenant les fonctions enveloppantes.

ENVIRONNEMENT

FAKECHROOT
La valeur est vraie pour l'environnement fake chroot.
FAKECHROOT_AF_UNIX_PATH
Le répertoire racine pour les sockets unix. La valeur par défaut est la même que "FAKECHROOT_BASE" et peut être définie séparément si "FAKECHROOT_BASE" est trop long et que le chemin du socket unix pourrait dépasser la limite de 108 octets.
FAKECHROOT_BASE
Le répertoire racine de l'environnement fake chroot.
FAKECHROOT_CMD_SUBST
Une liste de substitutions de commandes. Si un programme tente d'exécuter

une des commandes données (chemin relatif par rapport au chroot, le point final est supprimé) alors la commande de substitution s'exécute à la place (le chemin vers la commande de substitution n'est pas chrooté).

La commande substituée hérite des "FAKECHROOT_*" variables mais pas de la variable originale "FAKECHROOT_BASE" qui est sauvegardée en tant que "FAKECHROOT_BASE_ORIG". Cela signifie que la commande substituée s'exécute en dehors de l'environnement fakechroot. De plus, le nom original de la commande est sauvegardé en tant que "FAKECHROOT_CMD_ORIG".

Par exemple :

export FAKECHROOT_CMD_SUBST=/usr/bin/mkfifo=/bin/true

substituera "/bin/true" pour "/usr/bin/mkfifo" et rendra possible l'installation du paquet binaire sysvinit.

Donnez autant de commandes de substitution que vous voulez, séparées par des ":" caractères deux-points.

Il est suggéré de substituer au moins :

  • "/bin/mount=/bin/true"
  • "/sbin/insserv=/bin/true"
  • "/sbin/ldconfig=/bin/true"
  • "/usr/bin/env=/usr/bin/env.fakechroot"
  • "/usr/bin/ischroot=/bin/true"
  • "/usr/bin/ldd=/usr/bin/ldd.fakechroot"
  • "/usr/bin/mkfifo=/bin/true"

pour faire debootstrap(8) fonctionner correctement.

Pour éviter certaines boucles, la substitution de commande n'est effectuée que si la variable "FAKECHROOT_CMD_ORIG" n'est pas définie actuellement.

FAKECHROOT_DEBUG
La bibliothèque fakechroot affichera des informations de débogage si cette variable est définie.
FAKECHROOT_DETECT
Si cette variable est définie, alors la chaîne "fakechroot version" est imprimée sur la sortie standard et le processus courant est terminé avec un statut pris à partir de cette variable. Cela peut être une méthode pour vérifier si fakechroot est préchargé correctement. 
$ case "`FAKECHROOT_DETECT=1 /bin/echo`" in fakechroot*) echo LOADED;; esac
FAKECHROOT_ELFLOADER
Un chemin vers un autre chargeur dynamique (c'est-à-dire /lib/ld-linux.so.2 pour l'architecture i386, /lib64/ld-linux-x86-64.so.2 pour l'architecture x86_64).

Ce chargeur dynamique sera invoqué directement. Le chargeur dynamique ne permet pas de changer "argv[0]" en dehors du nom de fichier du fichier exécutable, donc certaines applications ne fonctionneront pas correctement, c'est-à-dire busybox(1).

FAKECHROOT_EXCLUDE_PATH
La liste des répertoires qui sont exclus d'être chrootés. Les éléments de la liste sont séparés par deux-points.

Les répertoires /dev, /proc et /sys sont exclus par défaut si cette variable d'environnement n'est pas définie.

Cette liste doit contenir au plus 100 éléments.

FAKECHROOT_EXTRA_LIBRARY_PATH
La liste des répertoires supplémentaires dans l'environnement du faux chroot qui sont ajoutés à la variable "LD_LIBRARY_PATH" . Les répertoires peuvent être utilisés par certaines commandes importantes qui utilisent des bibliothèques placées dans le runpath. Dans ce cas, le chargeur dynamique ne peut pas trouver le répertoire correct dans un environnement faux chroot sans le chemin de bibliothèque supplémentaire.

La valeur par défaut est "/lib/systemd:/usr/lib/man-db" pour les commandes systemctl(1) et man(1) .

FAKECHROOT_VERSION
Le numéro de version de la bibliothèque fakechroot courante.
LD_LIBRARY_PATH, LD_PRELOAD
Fakechroot est implémenté en enveloppant les appels système. Cela est accompli en définissant "LD_PRELOAD=libfakechroot.so". Si cette bibliothèque ne peut pas être trouvée par le chargeur dynamique, le fichier /etc/ld.so.conf ou la variable "LD_LIBRARY_PATH" doivent être modifiés.

LIMITATIONS

  • /lib/ld-linux.so.2 et /lib64/ld-linux-x86-64.so.2 sont toujours chargés depuis l'environnement réel. Ce chemin est codé en dur par le chargeur pour tous les binaires. Vous pouvez définir la variable d'environnement "FAKECHROOT_ELFLOADER" ou utiliser l'option "--elfloader" .
  • Chaque commande exécutée dans fakechroot doit être liée à la même version du chargeur dynamique depuis l'environnement réel. Si les bibliothèques dans le chroot ne sont pas compatibles, essayez d'utiliser l'option "--use-system-libs" .
  • Vous pouvez fournir des liens symboliques vers l'extérieur. Le lien symbolique doit être créé avant que chroot soit appelé. Cela peut être utile pour accéder aux répertoires réels /proc et /dev . Vous pouvez aussi définir la variable d'environnement "FAKECHROOT_EXCLUDE_PATH" : 
    $ export FAKECHROOT_EXCLUDE_PATH=/tmp:/proc:/dev:/sys:/var/run:/home
  • Les binaires liés statiquement ne fonctionnent pas, en particulier ldconfig(8), donc vous devez envelopper cette commande avec une version factice et définir la variable d'environnement appropriée "FAKECHROOT_CMD_SUBST" .
  • ldd(1) ne fonctionne pas non plus. Vous devez utiliser "alias ldd='LD_TRACE_LOADED_OBJECTS=1'" ou utiliser un enveloppeur à la place. L'enveloppeur est installé en tant que ldd.fakechroot et peut être utilisé avec la variable d'environnement "FAKECHROOT_CMD_SUBST" .
  • Les applications plein écran se bloquent si le fichier /dev/tty n'est pas un vrai périphérique. Liez le fichier /dev/tty ou tout le répertoire /dev à celui réel ou supprimez-le de l'environnement faux chroot avec la variable "FAKECHROOT_EXCLUDE_PATH" .
  • lckpwdf(3) et ulckpwdf(3) sont ignorés donc la commande passwd(1) devrait fonctionner
  • Votre uid réel doit exister dans /etc/passwd. Créez-le avec adduser --uid realuid realuser à l'intérieur de l'environnement faux chroot.
  • debuild(1) nettoie l'environnement. Utilisez l'option --preserve-env pour empêcher ce comportement.
  • rpmbuild(8) utilise sa propre implémentation glob(3) qui casse fakechroot donc le répertoire buildroot doit être le même à l'intérieur et à l'extérieur de fakechroot.
