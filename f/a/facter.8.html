NOM

facter - Collecter des informations système

SYNOPIS

Collecter et afficher des faits sur le système.

UTILISATION

facter [--color] [--config] [--custom-dir DIR] [-d|--debug] [--external-dir DIR] [--help]
  [-j|--json] [--list-block-groups] [--list-cache-groups] [-l|--log-level LEVEL (=warn)]
  [--no-block] [--no-cache] [--no-color] [--no-custom-facts] [--no-external-facts]
  [--trace] [--verbose] [-v|--version] [-y|--yaml] [--strict] [fact] [fact] [...]

DESCRIPTION

Collecte et affiche des faits sur le système courant. La bibliothèque sous-jacente à Facter est facile à étendre, faisant de Facter un moyen simple de collecter des informations sur un système.

Si aucune requête n'est donnée, tous les faits seront retournés.

Plusieurs options de ligne de commande peuvent également être définies via le fichier de configuration HOCON. Ce fichier peut également être utilisé pour bloquer ou mettre en cache certains groupes de faits.

OPTIONS

      --color                      Activer la sortie colorée.
      --config                     Un emplacement personnalisé pour le fichier de configuration.
      --custom-dir arg             Un répertoire à utiliser pour les faits personnalisés.
-d, [ --debug ]                    Activer la sortie de débogage.
      --external-dir arg           Un répertoire à utiliser pour les faits externes.
      --help                       Afficher l'aide et les informations d'utilisation.
-j, [ --json ]                     Sortir les faits au format JSON.
      --list-block-groups          Lister les noms de tous les groupes de faits bloquables.
      --list-cache-groups          Lister les noms de tous les groupes de faits mettables en cache.
      --show-legacy                Afficher les faits hérités lors de la requête de tous les faits.
-l, [ --log-level ] arg (=warn)    Définir le niveau de journalisation.
                                   Les niveaux supportés sont : none, trace, debug,
                                   info, warn, error, et fatal.
      --no-block                   Désactiver le blocage des faits.
      --no-cache                   Désactiver la mise en cache des faits.
      --no-color                   Désactiver la sortie colorée.
      --no-custom-fact             Désactiver les faits personnalisés.
      --no-external-facts          Désactiver les faits externes.
      --no-ruby                    Désactiver le chargement de Ruby, des faits nécessitant Ruby et des faits personnalisés.
      --trace                      Activer les traces pour les faits personnalisés.
      --verbose                    Activer la sortie détaillée (info).
-v, [ --version ]                  Afficher la version et quitter.
-y, [ --yaml ]                     Sortir les faits au format YAML.

FICHIERS

/etc/puppetlabs/facter/facter.conf
Un fichier de configuration HOCON qui peut être utilisé pour spécifier les répertoires pour les faits personnalisés et externes, définir diverses options de ligne de commande et spécifier les faits à bloquer. Voir l'exemple ci-dessous pour plus de détails, ou visitez le README de GitHub.

EXEMPLE

Afficher tous les faits :

$ facter
disks => {
  sda => {
    model => "Virtual disk",
    size => "8.00 GiB",
    size_bytes => 8589934592,
    vendor => "ExampleVendor"
  }
}
dmi => {
  bios => {
    release_date => "06/23/2013",
    vendor => "Example Vendor",
    version => "6.00"
  }
}
[...]

Afficher un seul fait structuré :

$ facter processors
{
  count => 2,
  isa => "x86_64",
  models => [
    "Intel(R) Xeon(R) CPU E5-2680 v2 @ 2.80GHz",
    "Intel(R) Xeon(R) CPU E5-2680 v2 @ 2.80GHz"
  ],
  physicalcount => 2
}

Afficher un seul fait imbriqué dans un fait structuré :

$ facter processors.isa
x86_64

Afficher un seul fait hérité. Notez que les faits non structurés existants dans les versions précédentes de Facter sont toujours disponibles, mais ne sont pas affichés par défaut en raison de la redondance avec les faits structurés plus récents :

$ facter processorcount
2

Formater les faits en JSON :

$ facter --json os.name os.release.major processors.isa
{
  "os.name": "Ubuntu",
  "os.release.major": "14.04",
  "processors.isa": "x86_64"
}

Un exemple de fichier de configuration.

# toujours chargé (CLI et comme module Ruby)
global : {
    external-dir : "~/external/facts",
    custom-dir   :  [
       "~/custom/facts",
       "~/custom/facts/more-facts"
    ],
    no-external-facts : false,
    no-custom-facts   : false,
    no-ruby           : false
}
# chargé lors de l'exécution depuis la ligne de commande
cli : {
    debug     : false,
    trace     : true,
    verbose   : false,
    log-level : "info"
}
# toujours chargé, configuration spécifique aux faits
facts : {
    # pour des entrées de liste de blocage valides, utilisez --list-block-groups
    blocklist : [ "file system", "EC2" ],
    # pour des entrées de temps de vie valides, utilisez --list-cache-groups
    ttls : [ { "timezone" : 30 days } ]
}
