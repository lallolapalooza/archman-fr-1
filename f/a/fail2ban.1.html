NOM

fail2ban - un ensemble de programmes serveur et client pour limiter les tentatives d'authentification par force brute.

DESCRIPTION

Fail2Ban se compose d'un client, d'un serveur et de fichiers de configuration pour limiter les tentatives d'authentification par force brute.

Le programme serveur fail2ban-server est responsable de la surveillance des fichiers journaux et de l'émission des commandes de bannissement/débannissement. Il est configuré via un protocole simple par fail2ban-client, qui peut également lire les fichiers de configuration et envoyer les commandes de configuration correspondantes au serveur.

Pour plus de détails sur la configuration de fail2ban, consultez la page de manuel jail.conf(5). Une jail (telle que spécifiée dans jail.conf) couple les définitions de filtres et d'actions pour toute liste de fichiers à surveiller.

Pour plus de détails sur les options de ligne de commande de fail2ban-server, consultez la page de manuel fail2ban-server(1).

Pour plus de détails sur les options de ligne de commande et les commandes de configuration du serveur via fail2ban-client, consultez la page de manuel fail2ban-client(1).

Pour tester les expressions régulières spécifiées dans un filtre, le programme fail2ban-regex peut être utile et sa page de manuel est fail2ban-regex(1).

LIMITATION

Fail2Ban est capable de réduire le taux de tentatives d'authentification incorrectes, mais il ne peut pas éliminer le risque présenté par une authentification faible. Configurez les services pour utiliser uniquement des mécanismes d'authentification à deux facteurs ou à clé publique/privée si vous souhaitez réellement protéger les services.

Un utilisateur local peut injecter des messages dans syslog et, en utilisant une jail Fail2Ban qui lit depuis syslog, il peut déclencher efficacement une attaque par déni de service contre n'importe quelle IP. Connaissez ce risque et configurez Fail2Ban/accordez l'accès shell en conséquence.
