posix_fadvise(2) Manuel des appels système posix_fadvise(2)

NOM

posix_fadvise - pré-déclarer un motif d'accès aux données d'un fichier

BIBLIOTHEQUE

Bibliothèque C standard (libc, -lc)

SYNTAXE

#include <fcntl.h>
int posix_fadvise(int fd, off_t offset, off_t size, int advice);
Exigences de macros de test de fonctionnalité pour glibc (voir feature_test_macros(7)) :

posix_fadvise() :

    _POSIX_C_SOURCE >= 200112L

DESCRIPTION

Les programmes peuvent utiliser posix_fadvise() pour annoncer l'intention d'accéder aux données d'un fichier selon un motif spécifique à l'avenir, permettant ainsi au noyau d'effectuer les optimisations appropriées.

Le conseil (advice) s'applique à une région (pas nécessairement existante) commençant à offset et s'étendant sur size octets (ou jusqu'à la fin du fichier si size est 0) dans le fichier référencé par fd. Le conseil n'est pas contraignant ; il constitue simplement une attente de la part de l'application.

Les valeurs autorisées pour advice incluent :

POSIX_FADV_NORMAL
Indique que l'application n'a pas de conseil à donner concernant son motif d'accès aux données spécifiées. Si aucun conseil n'est donné pour un fichier ouvert, c'est l'hypothèse par défaut.
POSIX_FADV_SEQUENTIAL
L'application s'attend à accéder aux données spécifiées séquentiellement (les octets de plus faible adresse étant lus avant ceux de plus haute adresse).
POSIX_FADV_RANDOM
Les données spécifiées seront accédées dans un ordre aléatoire.
POSIX_FADV_NOREUSE
Les données spécifiées ne seront utilisées qu'une seule fois.
Avant Linux 2.6.18, POSIX_FADV_NOREUSE avait les mêmes sémantiques que POSIX_FADV_WILLNEED. C'était probablement un bug ; de Linux 2.6.18 à Linux 6.2, ce drapeau était une opération nulle. Depuis Linux 6.3, POSIX_FADV_NOREUSE signale que l'algorithme de remplacement de page du noyau peut ignorer les accès aux pages mises en cache marqués par ce drapeau. Ceci est utile, par exemple, lors du streaming de fichiers volumineux.
POSIX_FADV_WILLNEED
Les données spécifiées seront accédées dans un futur proche.
POSIX_FADV_WILLNEED initie une lecture non bloquante de la région spécifiée dans le cache de pages. La quantité de données lues peut être réduite par le noyau en fonction de la charge de la mémoire virtuelle. (Quelques mégaoctets seront généralement entièrement satisfaits, et plus est rarement utile.)
POSIX_FADV_DONTNEED
Les données spécifiées ne seront pas accédées dans un futur proche.
POSIX_FADV_DONTNEED tente de libérer les pages mises en cache associées à la région spécifiée. Ceci est utile, par exemple, lors du streaming de fichiers volumineux. Un programme peut périodiquement demander au noyau de libérer les données mises en cache qui ont déjà été utilisées, afin que des pages mises en cache plus utiles ne soient pas écartées à la place.
Les requêtes pour libérer des pages partielles sont ignorées. Il est préférable de préserver les données nécessaires que de libérer des données inutiles. Si l'application exige que les données soient prises en compte pour la libération, alors offset et size doivent être alignés sur des pages.
L'implémentation *peut* tenter d'écrire les pages sales dans la région spécifiée, mais ce n'est pas garanti. Toutes les pages sales non écrites ne seront pas libérées. Si l'application souhaite s'assurer que les pages sales seront libérées, elle devrait appeler fsync(2) ou fdatasync(2) au préalable.

VALEUR RENVOYÉE

En cas de succès, zéro est renvoyé. En cas d'erreur, un numéro d'erreur est renvoyé.

ERREURS

EBADF
L'argument fd n'était pas un descripteur de fichier valide.
EINVAL
Une valeur invalide a été spécifiée pour advice.
ESPIPE
Le descripteur de fichier spécifié fait référence à un pipe ou un FIFO. (ESPIPE est l'erreur spécifiée par POSIX, mais avant Linux 2.6.16, Linux renvoyait EINVAL dans ce cas.)

VERSIONS

Sous Linux, POSIX_FADV_NORMAL définit la fenêtre de lecture anticipée à la taille par défaut pour le périphérique sous-jacent ; POSIX_FADV_SEQUENTIAL double cette taille, et POSIX_FADV_RANDOM désactive complètement la lecture anticipée du fichier. POSIX_FADV_NOREUSE ne modifie pas la taille de la fenêtre de lecture anticipée. Ces changements affectent le fichier entier, pas seulement la région spécifiée (mais d'autres manipulations de fichiers ouvertes sur le même fichier ne sont pas affectées).

Différences bibliothèque C/noyau

Le nom de la fonction d'enveloppement dans la bibliothèque C est posix_fadvise(). L'appel système sous-jacent est appelé fadvise64() (ou, sur certaines architectures, fadvise64_64()) ; la différence entre les deux est que le premier appel système suppose que le type de l'argument size est size_t, tandis que le second attend loff_t à cet endroit.

Variantes spécifiques à l'architecture

Certaines architectures exigent que les arguments 64 bits soient alignés dans une paire de registres appropriée (voir syscall(2) pour plus de détails). Sur de telles architectures, la signature d'appel de posix_fadvise() montrée dans la SYNTAXE forcerait un registre à être perdu comme remplissage entre les arguments fd et offset. Par conséquent, ces architectures définissent une version de l'appel système qui ordonne les arguments de manière appropriée, mais est par ailleurs exactement la même que posix_fadvise().

Par exemple, depuis Linux 2.6.14, ARM a l'appel système suivant :


long arm_fadvise64_64(int fd, int advice,
                      loff_t offset, loff_t size);

Ces détails spécifiques à l'architecture sont généralement masqués aux applications par la fonction d'enveloppement glibc posix_fadvise(), qui appelle l'appel système spécifique à l'architecture approprié.

NORMES

POSIX.1-2024.

HISTORIQUE

POSIX.1-2001.

Le support du noyau est apparu pour la première fois dans Linux 2.5.60 ; l'appel système sous-jacent s'appelle fadvise64(). Le support de la bibliothèque est fourni depuis glibc 2.2, via la fonction d'enveloppement posix_fadvise().

Depuis Linux 3.18, le support de l'appel système sous-jacent est facultatif, en fonction du paramètre de l'option de configuration CONFIG_ADVISE_SYSCALLS.

Le type de l'argument size a été changé de size_t à off_t dans POSIX.1-2001 TC1.

NOTES

Le contenu du cache de tampons du noyau peut être effacé via l'interface /proc/sys/vm/drop_caches décrite dans proc(5).

On peut obtenir un instantané des pages d'un fichier qui sont résidentes dans le cache de tampons en ouvrant un fichier, en le mappant avec mmap(2), puis en appliquant mincore(2) au mapping.

BUGS

Avant Linux 2.6.6, si size était spécifié comme 0, cela était interprété littéralement comme "zéro octet", plutôt que comme signifiant "tous les octets jusqu'à la fin du fichier".
