Fatal(3perl) Guide de référence du programmeur Perl Fatal(3perl)

NOM

Fatal - Remplace les fonctions par des équivalents qui réussissent ou meurent

SYNOPIS

use Fatal qw(open close);
open(my $fh, "<", $filename);  # Pas besoin de vérifier les erreurs !
use File::Copy qw(move);
use Fatal qw(move);
move($file1, $file2); # Pas besoin de vérifier les erreurs !
sub juggle { . . . }
Fatal->import('juggle');

BONNE PRATIQUE

Fatal a été rendu obsolète par le nouveau pragma autodie. Veuillez utiliser autodie de préférence à "Fatal". autodie prend en charge la portée lexicale, lève de véritables objets d'exception et fournit des messages d'erreur beaucoup plus agréables.

L'utilisation de ":void" avec Fatal est déconseillée.

DESCRIPTION

"Fatal" fournit un moyen pratique de remplacer les fonctions qui renvoient normalement une valeur fausse en cas d'échec par des équivalents qui lèvent des exceptions si elles ne réussissent pas. Cela vous permet d'utiliser ces fonctions sans avoir à tester explicitement leurs valeurs de retour à chaque appel. Les exceptions peuvent être interceptées à l'aide de "eval{}". Voir perlfunc et perlvar pour les détails.

Les équivalents « faites ou mourez » sont configurés simplement en appelant la routine "import" de Fatal, en lui passant les noms des fonctions à remplacer. Vous pouvez encapsuler à la fois des fonctions définies par l'utilisateur et des opérateurs CORE surchargeables (sauf "exec", "system", "print", ou tout autre built-in qui ne peut pas être exprimé via des prototypes) de cette manière.

Si le symbole ":void" apparaît dans la liste d'importation, alors les fonctions nommées plus loin dans cette liste d'importation lèvent une exception uniquement lorsqu'elles sont appelées dans un contexte vide, c'est-à-dire lorsque leurs valeurs de retour sont ignorées. Par exemple

use Fatal qw/:void open close/;
# correctement vérifié, donc aucune exception levée en cas d'erreur
if (not open(my $fh, '<', '/bogotic') {
    warn "Impossible d'ouvrir /bogotic : $!";
}
# non vérifié, donc une erreur lève une exception
close FH;

L'utilisation de ":void" est déconseillée, car elle peut entraîner la non-levée d'exceptions si vous appelez *accidentellement* une méthode sans contexte vide. Utilisez autodie à la place si vous avez besoin de pouvoir désactiver le comportement autodying/Fatal pour un petit bloc de code.

DIAGNOSTICS

Nom de sous-routine incorrect pour Fatal : %s
Vous avez appelé "Fatal" avec un argument qui ne ressemble pas à un nom de sous-routine, ni à un commutateur que cette version de Fatal comprend.
%s n'est pas une sous-routine Perl
Vous avez demandé à "Fatal" d'essayer de remplacer une sous-routine qui n'existe pas, ou qui n'a pas encore été définie.
%s n'est ni un built-in, ni une sous-routine Perl
Vous avez demandé à "Fatal" de remplacer une sous-routine, mais ce n'est pas un built-in Perl, et "Fatal" n'a pas pu la trouver comme sous-routine régulière. Elle n'existe pas ou n'a pas encore été définie.
Impossible de rendre le %s non surchargeable fatal
Vous avez essayé d'utiliser "Fatal" sur un built-in Perl qui ne peut pas être surchargé, tel que "print" ou "system", ce qui signifie que "Fatal" ne peut pas vous aider, bien que d'autres modules le puissent. Voir la section « VOIR AUSSI » de cette documentation.
Erreur interne : %s
Vous avez trouvé un bug dans "Fatal". Veuillez le signaler en utilisant la commande "perlbug".

BOGUES

"Fatal" écrase le contexte dans lequel une fonction est appelée et en fait toujours un contexte scalaire, sauf lorsque la balise ":void" est utilisée. Ce problème n'existe pas dans autodie.

Les avertissements « Utilisé une seule fois » peuvent être générés lorsque "autodie" ou "Fatal" est utilisé avec des descripteurs de fichiers de paquet (par exemple, "FILE"). Il est fortement recommandé d'utiliser des descripteurs de fichiers scalaires à la place.
