NOM

faillock.conf - fichier de configuration de pam_faillock

DESCRIPTION

faillock.conf offre un moyen de configurer les paramètres par défaut pour le verrouillage de l'utilisateur après plusieurs tentatives d'authentification échouées. Ce fichier est lu par le module pam_faillock et constitue la méthode préférée par rapport à la configuration directe de pam_faillock.

Le fichier a un format très simple de type nom = valeur avec des commentaires possibles commençant par le caractère #. Les espaces blancs au début de la ligne, à la fin de la ligne et autour du signe = sont ignorés.

OPTIONS

dir=/chemin/vers/le-repertoire-de-comptage

Le répertoire où sont conservés les fichiers utilisateur avec les enregistrements d'échecs. Par défaut, c'est /var/run/faillock.

Note : Ces fichiers disparaissent après le redémarrage sur les systèmes configurés avec le répertoire /var/run/faillock monté sur la mémoire virtuelle.

audit

Enregistrera le nom d'utilisateur dans le journal système si l'utilisateur n'est pas trouvé.

silent

Ne pas afficher de messages informatifs à l'utilisateur. Veuillez noter que lorsque cette option n'est pas utilisée, il y aura une différence dans le comportement d'authentification pour les utilisateurs qui existent sur le système et les utilisateurs inexistants.

no_log_info

Ne pas enregistrer les messages informatifs via syslog(3).

local_users_only

Ne suivre que les tentatives d'authentification échouées des utilisateurs locaux dans /etc/passwd et ignorer les utilisateurs centralisés (AD, IdM, LDAP, etc.). La commande faillock(8) ne suivra pas non plus les tentatives d'authentification échouées des utilisateurs. L'activation de cette option empêchera un scénario de double verrouillage où un utilisateur est verrouillé localement et dans le mécanisme centralisé.

nodelay

Ne pas imposer de délai après les échecs d'authentification.

deny=n

Refuser l'accès si le nombre d'échecs d'authentification consécutifs pour cet utilisateur pendant l'intervalle récent dépasse n. Par défaut, c'est 3.

fail_interval=n

La durée de l'intervalle pendant lequel les échecs d'authentification consécutifs doivent se produire pour que le compte utilisateur soit verrouillé est de n secondes. Par défaut, c'est 900 (15 minutes).

unlock_time=n

L'accès sera rétabli après n secondes après le verrouillage. La valeur 0 a la même signification que la valeur never (jamais) - l'accès ne sera pas rétabli sans réinitialiser les entrées faillock par la commande faillock(8). Par défaut, c'est 600 (10 minutes).

Notez que le répertoire par défaut utilisé par pam_faillock est généralement effacé au démarrage du système, de sorte que l'accès sera également rétabli après le redémarrage du système. Si cela est indésirable, un répertoire de comptage différent doit être défini avec l'option dir.

Notez également qu'il est généralement indésirable de verrouiller définitivement les utilisateurs, car ils peuvent facilement devenir la cible d'une attaque par déni de service, à moins que les noms d'utilisateur ne soient aléatoires et gardés secrets aux attaquants potentiels.

even_deny_root

Le compte root peut être verrouillé, tout comme les comptes réguliers.

root_unlock_time=n

Cette option implique l'option even_deny_root. Permet l'accès après n secondes au compte root après que le compte a été verrouillé. Si l'option n'est pas spécifiée, la valeur est la même que celle de l'option unlock_time.

admin_group=nom

Si un nom de groupe est spécifié avec cette option, les membres du groupe seront traités par ce module de la même manière que le compte root (les options even_deny_root et root_unlock_time leur s'appliqueront). Par défaut, l'option n'est pas définie.

EXEMPLES

Exemple de fichier /etc/security/faillock.conf :

deny=4
unlock_time=1200
silent

FICHIERS

/etc/security/faillock.conf

le fichier de configuration pour les options personnalisées
