DESCRIPTIO

N

fatlabel affichera ou changera l'étiquette de volume ou l'ID de volume du système de fichiers MS-DOS situé sur PÉRIPHÉRIQUE. Par défaut, il fonctionne en mode étiquette. Il peut être basculé en mode ID de volume avec l'option -i ou --volume-id

.

Si NOUVELLE est omise, l'étiquette ou l'ID de volume existant est écrit sur la sortie standard. Une étiquette ne peut pas dépasser 11 octets et devrait être entièrement en majuscules pour une meilleure compatibilité.

Une chaîne vide ou une étiquette composée uniquement d'espaces n'est pas autorisée. Un ID de volume doit
être donné sous forme de nombre hexadécimal (sans « 0x » initial ou similaire) et doit tenir dans 32 bits.

COMPATIBILITÉ et

BOGUES

Pour des raisons historiques, l'étiquette FAT est stockée à deux endroits différents : dans le secteur de démarrage et comme entrée spéciale d'étiquette de volume dans le répertoire racine. MS-DOS 5.00, MS-DOS 6.22, MS-DOS 7.10, Windows 98, Windows XP et aussi Windows 10 lisent l'étiquette FAT uniquement depuis le répertoire racine. L'absence de l'étiquette de volume dans le répertoire racine est interprétée comme une étiquette vide ou nulle, même si le secteur de démarrage contient une étiquette

valide.

Lorsqu'un système Windows XP ou Windows 10 change une étiquette FAT, il la stocke uniquement dans le répertoire racine — laissant le secteur de démarrage inchangé. Ce qui entraîne des problèmes lorsqu'une étiquette est supprimée sous Windows. L'ancienne étiquette est toujours stockée dans le secteur de démarrage mais est supprimée du répertoire

racine.

dosfslabel antérieur à la version 3.0.7 ne fonctionnait qu'avec les étiquettes FAT stockées dans le secteur de démarrage, ignorant complètement une étiquette de volume dans le répertoire

racine.

dosfslabel dans les versions 3.0.7–3.0.15 lit les étiquettes FAT depuis le répertoire racine et en cas d'absence, il revient à une étiquette stockée dans le secteur de démarrage. L'opération de changement entraînait la mise à jour d'une étiquette dans le secteur de démarrage et parfois aussi dans le répertoire racine à cause du bogue. Ce bogue a été corrigé dans dosfslabel version 3.0.16 et depuis cette version dosfslabel met à jour l'étiquette aux deux

endroits.

Depuis la version 4.2, fatlabel lit une étiquette FAT uniquement depuis le répertoire racine (comme les systèmes MS-DOS et Windows), mais change une étiquette FAT dans les deux endroits. Dans la version 4.2, la gestion des étiquettes vides et des étiquettes commençant par l'octet 0xE5 a été corrigée. Également dans cette version, la prise en charge des étiquettes non-ASCII a été ajoutée selon la page de code DOS spécifiée et des vérifications de validité d'une nouvelle étiquette ont été

ajoutées.

Il est fortement déconseillé d'utiliser dosfslabel antérieur à

la vers
ion 3.0.16.

PAGES DE CODE

DOS

Les systèmes MS-DOS et Windows utilisent la page de code DOS (OEM) pour l'encodage et le décodage de l'étiquette FAT. Dans les systèmes Windows, la page de code DOS est globale pour toutes les applications en cours d'exécution et ne peut pas être configurée explicitement. Elle est définie implicitement par l'option Langue pour les programmes non Unicode disponible dans Options régionales et linguistiques via le Panneau de configuration.
