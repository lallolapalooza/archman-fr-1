NOM

fasd - accès rapide aux fichiers et répertoires

SYNOPSIS

fasd [options] [requête ...]

f|a|s|d|z (#options) [requête ...]

fasd [-A|-D] [chemins ...]

OPTIONS

-s          lister les chemins avec leur rang
-l          lister les chemins sans leur rang
-i          mode interactif
-e <cmd>    définir la commande à exécuter sur le fichier résultat
-b <name>   n'utiliser que le backend <name>
-B <name>   ajouter un backend supplémentaire <name>
-a          faire correspondre les fichiers et les répertoires
-d          faire correspondre uniquement les répertoires
-f          faire correspondre uniquement les fichiers
-r          faire correspondre uniquement par rang
-t          faire correspondre uniquement par accès récent
-R          inverser l'ordre de la liste
-h          afficher un court message d'aide
-[0-9]      sélectionner la n-ième entrée

DESCRIPTION

Fasd garde une trace des fichiers et répertoires auxquels vous accédez dans votre shell et vous donne un accès rapide à ceux-ci. Vous pouvez utiliser fasd pour référencer des fichiers ou répertoires avec seulement quelques caractères identifiants. Vous pouvez utiliser fasd pour augmenter votre productivité en ligne de commande en définissant vos propres alias pour lancer des programmes sur des fichiers ou des répertoires. Fasd fournit par défaut quelques alias de base, y compris une fonction de shell « z » qui ressemble à la fonctionnalité de « z » et « autojump ».

Le nom « fasd » vient des alias suggérés par défaut f (fichiers), a (fichiers/répertoires), s (afficher/rechercher/sélectionner), d (répertoires).

Fasd classe les fichiers et les répertoires par « fréquence-récence » (frecency), c'est-à-dire à la fois par « fréquence » et par « récence ». Le terme « frecency » a été inventé par Mozilla et utilisé dans Firefox.

EXEMPLES

z bundle
f -e vim nginx conf
f -i rc$
vi `f nginx conf`
cp update.html `d www`
open `sf pdf`

INITIALISATION DU SHELL

Pour que fasd fonctionne dans un shell, un code d'initialisation doit être exécuté. Placez les lignes ci-dessous dans le fichier de configuration de votre shell compatible POSIX.

eval "$(fasd --init auto)"

Cela configurera un crochet de commande qui s'exécute à chaque commande ainsi qu'une complétion par tabulation avancée pour zsh et bash.

Si vous voulez plus de contrôle sur ce qui entre dans votre environnement shell, vous pouvez passer un ensemble personnalisé d'arguments à fasd --init.

zsh-hook             # définir _fasd_preexec et l'ajouter au tableau preexec de zsh
zsh-ccomp            # définitions de complétion en mode commande pour zsh
zsh-ccomp-install    # configurer la complétion en mode commande pour zsh
zsh-wcomp            # définitions de complétion en mode mot pour zsh
zsh-wcomp-install    # configurer la complétion en mode mot pour zsh
bash-hook            # ajouter le code de crochet à $PROMPT_COMMAND de bash
bash-ccomp           # définitions de complétion en mode commande pour bash
bash-ccomp-install   # configurer la complétion en mode commande pour bash
posix-alias          # définir des alias qui s'appliquent à tous les shells posix
posix-hook           # configurer le crochet $PS1 pour les shells compatibles posix
tcsh-alias           # définir des alias pour tcsh
tcsh-hook            # configurer l'alias precmd de tcsh

Exemple pour une configuration zsh minimale (sans complétion par tabulation) :

eval "$(fasd --init posix-alias zsh-hook)"

Notez que cette méthode augmentera légèrement le temps de démarrage de votre shell, car l'appel de binaires a un surcoût. Vous pouvez mettre en cache le code d'initialisation de fasd si vous voulez un surcoût minimal. Exemple de code pour bash (à placer dans .bashrc) :

fasd_cache="$HOME/.fasd-init-bash"
if [ "$(command -v fasd)" -nt "$fasd_cache" -o ! -s "$fasd_cache" ]; then
  fasd --init posix-alias bash-hook bash-ccomp bash-ccomp-install >| "$fasd_cache"
fi
source "$fasd_cache"
unset fasd_cache

Optionnellement, vous pouvez aussi charger fasd avec source si vous voulez que fasd soit une fonction de shell au lieu d'un exécutable.

Vous pouvez ajuster le code d'initialisation. Par exemple, si vous voulez utiliser « c » au lieu de « z » pour le saut de répertoire, vous pouvez utiliser l'alias ci-dessous :

alias c='fasd_cd -d'
# l'option `-d' est présente pour la complétion de bash
# la fonction fasd_cd est définie dans posix-alias

CORRESPONDANCE

Fasd a trois modes de correspondance : par défaut, insensible à la casse et flou (fuzzy).

Pour un ensemble donné de requêtes (l'ensemble des arguments de ligne de commande passés à fasd), un chemin correspond si et seulement si :

1.
Les requêtes correspondent au chemin dans l'ordre.
2.
La dernière requête correspond au dernier segment du chemin.

Si aucune correspondance n'est trouvée, fasd essaiera le même processus en ignorant la casse. Si aucune correspondance n'est toujours trouvée, fasd autorisera des caractères supplémentaires entre les caractères des requêtes pour une correspondance floue.

Conseils :

•
Si vous voulez que votre dernière requête ne corresponde pas au dernier segment du chemin, ajoutez « / » comme dernière requête.
•
Si vous voulez que votre dernière requête corresponde à la fin du nom de fichier, ajoutez « $ » à la dernière requête.

COMPATIBILITÉ

Les fonctionnalités de base de fasd sont conformes à POSIX, ce qui signifie que vous devriez pouvoir utiliser fasd dans tous les shells conformes à POSIX. Votre shell doit prendre en charge la substitution de commandes dans $PS1 pour que fasd puisse automatiquement suivre vos commandes et vos fichiers. Cette fonctionnalité n'est pas spécifiée par la norme POSIX, mais elle est néanmoins présente dans de nombreux shells conformes à POSIX. Dans les shells sans commande de prompt ou sans substitution de commande de prompt (tcsh par exemple), vous pouvez ajouter des entrées manuellement avec « fasd -A ». Vous êtes les bienvenus pour contribuer du code d'initialisation de shell pour les shells non encore pris en charge.

TAB COMPLETION

Fasd offre deux modes de complétion : complétion en mode commande et complétion en mode mot. La complétion en mode commande fonctionne dans bash et zsh. La complétion en mode mot ne fonctionne que dans zsh.

La complétion en mode commande est similaire à la complétion pour toute autre commande. Elle est déclenchée lorsque vous appuyez sur Tab après une commande fasd ou ses alias. Dans ce mode, vos requêtes peuvent être séparées par un espace. Astuce : si vous constatez que le résultat de la complétion écrase vos requêtes, tapez un espace supplémentaire avant d'appuyer sur Tab.

La complétion en mode mot peut être déclenchée sur toute commande. La complétion en mode mot est déclenchée par tout argument de ligne de commande qui commence par ", " (tout), "f, " (fichiers), ou "d, " (répertoires), ou qui se termine par ",, " (tout), ",,f " (fichiers), ou ",,d " (répertoires). Exemples :

$ vim ,rc,lo<Tab>
$ vim /etc/rc.local
$ mv index.html d,www<Tab>
$ mv index.html /var/www/

Il existe également trois widgets zle : "fasd-complete", "fasd-complete-f", "fasd-complete-d". Vous pouvez les lier à des raccourcis clavier de votre choix :

bindkey '^X^A' fasd-complete    # C-x C-a pour faire fasd-complete (fichiers et répertoires)
bindkey '^X^F' fasd-complete-f  # C-x C-f pour faire fasd-complete-f (seulement les fichiers)
bindkey '^X^D' fasd-complete-d  # C-x C-d pour faire fasd-complete-d (seulement les répertoires)

BACKENDS

Fasd peut exploiter différentes sources de fichiers récents / fréquents. La plupart des environnements de bureau (comme OS X et Gtk) et certains éditeurs (comme Vim) conservent une liste des fichiers consultés. Fasd peut les utiliser comme backends supplémentaires si les données peuvent être converties au format natif de fasd. Ci-dessous une liste des backends disponibles.

•
spotlight : Le spotlight d'OSX, fournit les entrées modifiées aujourd'hui ou ouvertes le mois dernier
•
recently-used : Fichier récemment utilisé de GTK (Généralement disponible sous Linux)
•
current : Fournit tout dans $PWD (où que vous exécutiez fasd)
•
viminfo : Historique d'édition de Vim, utile si vous souhaitez définir un alias uniquement pour éditer des éléments dans vim

Vous pouvez définir votre propre backend en déclarant une fonction portant ce nom dans votre fichier de configuration (#configuration). Vous pouvez définir le backend par défaut avec la variable _FASD_BACKENDS.

CONFIGURATION

À chaque exécution, fasd recherche un fichier de configuration dans l'ordre suivant :

1.
$XDG_CONFIG_HOME/fasd/config
2.
$HOME/.config/fasd/config
3.
$XDG_CONFIG_DIRS/fasd/config
4.
/etc/xdg/fasd/config
5.
/etc/fasdrc et $HOME/.fasdrc (pour la compatibilité ascendante)

Voici les variables disponibles que vous pouvez définir :

$_FASD_DATA
Chemin vers le fichier de données fasd, par défaut "$XDG_CACHE_HOME/fasd" ou "$HOME/.cache/fasd" si $XDG_CACHE_HOME n'est pas défini.
$_FASD_BLACKLIST
Liste des chaînes de caractères mises sur liste noire. Les commandes qui y correspondent ne seront pas traitées.
Par défaut : "--help".
$_FASD_SHIFT
Liste de toutes les commandes qui doivent être décalées, par défaut "sudo busybox".
$_FASD_IGNORE
Liste de toutes les commandes qui seront ignorées, par défaut "fasd ls echo".
$_FASD_TRACK_PWD
Fasd suit par défaut votre "$PWD". Définissez cette valeur à 0 pour désactiver ce comportement.
$_FASD_AWK
Quel awk utiliser. fasd peut détecter et utiliser un awk compatible.
$_FASD_SINK
Fichier pour enregistrer tout STDERR, par défaut "/dev/null".
$_FASD_MAX
Score total / poids maximal, par défaut 2000.
$_FASD_SHELL
Quel shell exécuter. Certains shells s'exécutent plus rapidement que d'autres. fasd
s'exécute plus rapidement avec les variantes de dash et ksh.
$_FASD_BACKENDS
Backends par défaut.
$_FASD_RO
Si cette variable est définie à une chaîne non vide, fasd n'ajoutera ni ne supprimera d'entrées de la
base de données. Vous pouvez définir et exporter cette variable depuis la ligne de commande.
$_FASD_FUZZY
Niveau de "flou" lors de la correspondance floue. Plus précisément, le nombre de
caractères qui peuvent être sautés pour générer une correspondance. Définissez à vide ou 0 pour
désactiver la correspondance floue. La valeur par défaut est 2.
$_FASD_VIMINFO
Chemin vers le fichier .viminfo pour le backend viminfo, par défaut "$HOME/.viminfo"
$_FASD_RECENTLY_USED_XBEL
Chemin vers le fichier XDG recently-used.xbel pour le backend recently-used, par défaut 
"$HOME/.local/share/recently-used.xbel"
$_FASD_NOCASE
Force l'insensibilité à la casse pour la correspondance par défaut avec la valeur 1, par défaut .

DEBUGGING

Fasd est hébergé sur GitHub : https://github.com/clvv/fasd

Si fasd ne fonctionne pas comme prévu, veuillez signaler un bug sur GitHub décrivant le comportement inattendu, ainsi que la version de votre OS, la version de votre shell, la version de awk, la version de sed et un fichier journal.

Vous pouvez définir _FASD_SINK dans votre fichier de configuration (#configuration) pour obtenir un journal.

_FASD_SINK="$HOME/fasd.log"
