NOM

fcgiwrap - servir des applications CGI via FastCGI

SYNTAXE

fcgiwrap [OPTIONS]

DESCRIPTION

fcgiwrap est un serveur simple pour exécuter des applications CGI via FastCGI. Il vise à fournir un support CGI propre à Nginx (et autres serveurs web qui pourraient en avoir besoin).

OPTIONS

-c nombre
Nombre de processus fcgiwrap à préforker.
-f
Rediriger la sortie STDERR des CGI exécutés via FastCGI afin qu'elle apparaisse dans le journal d'erreurs du serveur web. Sinon, elle serait renvoyée sur la sortie STDERR de fcgiwrap, qui pourrait être redirigée. Si exécuté via spawn-fcgi, la sortie STDERR de fcgiwrap est envoyée vers /dev/null, donc cette option fournit un moyen de récupérer cette sortie.
-s url_socket
Une URL pour le socket d'écoute auquel se connecter. Par défaut, fcgiwrap attend qu'un socket d'écoute soit passé sur le descripteur de fichier 0, conformément à la convention FastCGI. La méthode recommandée pour déployer fcgiwrap est de l'exécuter sous un gestionnaire de processus qui se charge d'ouvrir le socket. Cependant, pour des configurations simples et des tests ponctuels, cette option peut être utilisée. Les socket_urls valides incluent unix:/chemin/vers/socket/unix, tcp:dot.ted.qu.ad:port et tcp6:[ipv6_addr]:port.
-h
Afficher un message d'aide et quitter.

ENVIRONNEMENT

Lors de l'exécution, fcgiwrap évalue ces variables d'environnement définies par le serveur web appelant un script fcgi. Les variables DOCUMENT_ROOT et SCRIPT_NAME seront concaténées et l'exécutable résultant sera lancé en tant que script CGI encapsulé en FastCGI, le reste après le nom du script étant disponible comme PATH_INFO. Pour désactiver la manipulation de PATH_INFO, configurez votre serveur web pour passer SCRIPT_FILENAME, qui devrait contenir le chemin complet du script. Alors PATH_INFO ne sera pas modifié.

DOCUMENT_ROOT

répertoire dans lequel se trouve le script
SCRIPT_NAME
exécutable réel
SCRIPT_FILENAME
chemin complet du script CGI. Lorsqu'il est défini, remplace DOCUMENT_ROOT et SCRIPT_NAME

EXEMPLE

Le moyen le plus rapide de voir fcgiwrap faire quelque chose est de le lancer en ligne de commande comme ceci :
fcgiwrap -s unix:/var/run/fcgiwrap.sock
Mis à part d'éventuels problèmes de permissions etc., il devrait être prêt à accepter des requêtes FastCGI et à exécuter des scripts CGI.

Très probablement, vous voudrez lancer fcgiwrap par spawn-fcgi en utilisant une configuration comme celle-ci :

FCGI_SOCKET=/var/run/fcgiwrap.sock
FCGI_PROGRAM=/usr/sbin/fcgiwrap
FCGI_USER=nginx
FCGI_GROUP=www
FCGI_EXTRA_OPTIONS="-M 0700"
ALLOWED_ENV="PATH"

Nginx peut être configuré pour exécuter le CGI arbitraire cgit en tant que FastCGI comme suit :

location / {
fastcgi_param DOCUMENT_ROOT /var/www/localhost/htdocs/cgit/;
fastcgi_param SCRIPT_NAME cgit;
fastcgi_pass unix:/var/run/fastcgi.sock;
}
