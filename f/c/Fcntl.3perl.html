Fcntl(3perl) Guide du programmeur Perl Fcntl(3perl)

NOM

Fcntl - constantes et fonctions d'aide diverses de fcntl.h de C

SYNTAXE

use Fcntl;
use Fcntl qw(:DEFAULT :flock);
use Fcntl qw(F_GETFD F_SETFD FD_CLOEXEC);

DESCRIPTION

Ce module fournit des indicateurs et des fonctions d'aide pour l'utilisation de "chmod" dans perlfunc (S_*), "fcntl" dans perlfunc (F_*), "flock" dans perlfunc (LOCK_*), "seek" dans perlfunc (SEEK_*), "stat" dans perlfunc (S_*), "sysopen" dans perlfunc (O_*), et "sysseek" dans perlfunc (SEEK_*). Ils correspondent aux macros C définies dans fcntl.h.

Tous les symboles ne sont pas disponibles sur tous les systèmes. Sauf indication contraire, les constantes et fonctions fournies par ce module lanceront une exception d'exécution si la macro C correspondante n'est pas disponible. Consultez la documentation de votre système pour connaître la description complète de chaque symbole et sa disponibilité sur votre plateforme : chmod(2), fcntl(2), flock(2), lseek(2), open(2), stat(2).

(En particulier, certains symboles F_* sont très peu portables car ils n'existent que sur une seule plateforme ou nécessitent que des structures de données C spécifiques au système soient passées comme troisième argument à "fcntl", ce qui ne peut pas être construit de manière portable en Perl pur.)

Exportations par défaut et balises d'exportation

De plus, les balises d'exportation suivantes sont disponibles (voir Exporter pour plus d'informations sur les balises d'exportation) :

Équivalent à la liste des symboles d'exportation par défaut (voir "ANNEXE A").

Combinaison avec "LOCK_SH" ou "LOCK_EX" : Le verrou ne doit pas bloquer. Si le verrou ne peut être obtenu immédiatement, sysopen() échoue et retourne une erreur avec $! défini à "EWOULDBLOCK". Symboles utilisables avec "sysopen"

"O_ACCMODE"
Masque de bits pour extraire le mode d'accès au fichier (lecture seule, écriture seule, ou lecture/écriture) des autres drapeaux. Ceci est principalement utile en combinaison avec "F_GETFL".
"O_ALIAS"
(Mac OS) Ouvre le fichier alias (au lieu du fichier auquel l'alias fait référence).
"O_ALT_IO"
(NetBSD) Utilise des sémantiques d'E/S alternatives.
"O_APPEND"
Ouvre le fichier en mode ajout. Les écritures vont toujours à la fin du fichier.
"O_ASYNC"
Active les E/S basées sur les signaux. Lorsqu'un fichier devient lisible ou inscriptible, un signal est envoyé.
"O_BINARY"
(Windows) Ouvre le fichier en mode binaire.
"O_CREAT"
Si le fichier à ouvrir n'existe pas encore, créez-le.
"O_DEFER"
(AIX) Les modifications apportées au fichier sont conservées en mémoire et ne sont pas écrites sur le disque tant que le programme n'effectue pas un appel explicite à $fh->sync().
"O_DIRECT"
Effectue des E/S directes vers/depuis les tampons de l'espace utilisateur ; évite la mise en cache au niveau du système d'exploitation.
"O_DIRECTORY"
Échoue si le nom de fichier à ouvrir ne fait pas référence à un répertoire.
"O_DSYNC"
Synchronise immédiatement les données du fichier, comme si on appelait fdatasync(2) après chaque écriture.
"O_EVTONLY"
(Mac OS) Ouvre le fichier pour les notifications d'événements, pas pour la lecture ou l'écriture.
"O_EXCL"
Si le fichier existe déjà, échoue et définit $! à "EEXIST" (ceci n'a de sens qu'en combinaison avec "O_CREAT").
"O_EXLOCK"
Lors de l'ouverture du fichier, obtient atomiquement un verrou exclusif.
"O_IGNORE_CTTY"
(Hurd) Si le fichier à ouvrir est le terminal de contrôle de ce processus, ne pas le reconnaître comme tel. Les opérations sur ce descripteur de fichier ne déclencheront pas de signaux de contrôle de job.
"O_LARGEFILE"
Sur les plateformes 32 bits, permet d'ouvrir des fichiers dont la taille dépasse 2 Go (2 147 483 647 octets).
"O_NDELAY"
Symbole de compatibilité. Utiliser "O_NONBLOCK" à la place.
"O_NOATIME"
Ne pas mettre à jour l'heure d'accès du fichier lors de la lecture.
"O_NOCTTY"
Si le processus n'a pas de terminal de contrôle et que le fichier à ouvrir est un périphérique terminal, ne pas en faire le terminal de contrôle du processus.
"O_NOFOLLOW"
Si le dernier composant du nom de fichier est un lien symbolique, échoue et définit $! à "ELOOP".
"O_NOINHERIT"
(Windows) Ne pas permettre aux processus enfants d'hériter du descripteur de fichier ouvert.
"O_NOLINK"
(Hurd) Si le fichier à ouvrir est un lien symbolique, ne pas le suivre ; ouvrir le lien lui-même.
"O_NONBLOCK"
Ouvre le fichier en mode non bloquant. Ni l'ouverture elle-même ni aucune opération de lecture/écriture sur le descripteur de fichier ne bloqueront. (Ceci est principalement utile pour les pipes et les sockets. Il n'a aucun effet sur les fichiers réguliers.)
"O_NOSIGPIPE"
Si le fichier à ouvrir est un pipe, ne pas générer "SIGPIPE" pour les opérations d'écriture lorsque l'extrémité de lecture du pipe est fermée ; faire échouer l'écriture avec "EPIPE" à la place.
"O_NOTRANS"
(Hurd) Si le fichier à ouvrir est spécialement traduit, ne pas invoquer le traducteur ; ouvrir le fichier brut lui-même.
"O_RANDOM"
(Windows) Indique que le programme a l'intention d'accéder au contenu du fichier de manière aléatoire (sans schéma prévisible). Ceci est une indication d'optimisation pour le cache de fichiers (mais peut entraîner une utilisation excessive de la mémoire pour les gros fichiers).
"O_RAW"

"O_RDWR"
Ouvre le fichier en lecture et écriture.
"O_RSRC"
(Mac OS) Ouvre la branche de ressources du fichier.
"O_RSYNC"
