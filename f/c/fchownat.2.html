DESCRIPTIO

N

Ces appels système changent le propriétaire et le groupe d'un fichier. Les appels système chown(), fchown() et lchown() ne diffèrent que par la manière dont le fichier est spécifié

:
•
chown() change le propriétaire du fichier spécifié par path, qui est référencé s'il s'agit d'un lien
symbolique.
•
fchown() change le propriétaire du fichier auquel fait référence le descripteur de fichier ouvert fd
.
•
lchown() est comme chown(), mais ne référence pas
les liens
symboliques.

Seul un processus privilégié (Linux : un processus possédant la capacité CAP_CHOWN ) peut changer le propriétaire d'un fichier. Le propriétaire d'un fichier peut changer le groupe du fichier pour n'importe quel groupe dont ce propriétaire est membre. Un processus privilégié (Linux : avec CAP_CHOWN) peut changer le groupe

arbitrairement.

Si le propriétaire ou le groupe est spécifié comme -1, alors cet identifiant n'est pas

changé.

Lorsque le propriétaire ou le groupe d'un fichier exécutable est changé par un utilisateur non privilégié, les bits de mode S_ISUID et S_ISGID sont effacés. POSIX ne spécifie pas si cela devrait également se produire lorsque root effectue le chown() ; le comportement de Linux dépend de la version du noyau, et depuis Linux 2.2.13, root est traité comme les autres utilisateurs. Dans le cas d'un fichier non exécutable par le groupe (c'est-à-dire un fichier pour lequel le bit S_IXGRP n'est pas défini), le bit S_ISGID indique le verrouillage obligatoire et n'est pas effacé par un chown

().

Lorsque le propriétaire ou le groupe d'un fichier exécutable est changé (par n'importe quel utilisateur), tous les ensembles de capacités du fichier sont

effacés.

fchownat(

)

L'appel système fchownat() fonctionne exactement de la même manière que chown(), à l'exception des différences décrites

ici.

Si path est relatif, alors il est interprété relativement au répertoire auquel fait référence le descripteur de fichier dirfd (plutôt que relativement au répertoire de travail courant du processus appelant, comme c'est le cas pour chown() avec un chemin relatif)

.

Si path est relatif et dirfd est la valeur spéciale AT_FDCWD, alors path est interprété relativement au répertoire de travail courant du processus appelant (comme chown())

.

Si path est absolu, alors dirfd est

ignoré.

L'argument flags est un masque de bits créé en combinant par OU logique 0 ou plusieurs des valeurs suivantes

;
AT_EMPTY_PATH (depuis Linux 2.6.
39)
Si path est une chaîne vide, opérer sur le fichier auquel fait référence dirfd (qui peut avoir été obtenu à l'aide de l'indicateur open(2) O_PATH). Dans ce cas, dirfd peut faire référence à n'importe quel type de fichier, pas seulement à un répertoire. Si dirfd est AT_FDCWD, l'appel opère sur le répertoire de travail courant. Cet indicateur est spécifique à Linux ; définir _GNU_SOURCE pour obtenir sa
définition.
AT_SYMLINK_NOFOL
LOW
Si path est un lien symbolique, ne pas le référencer : opérer plutôt sur le lien lui-même, comme lchown(). (Par défaut, fchownat() référence les liens symboliques, comme chow
n()

NOTE

S

Propriété des nouveaux

fichiers

Lorsqu'un nouveau fichier estaté (par, par exemple, open(2) ou mkdir(2)), son propriétaire est rendu identique à l'identifiant utilisateur du système de fichiers du processus créant. Le groupe du fichier dépend d'une série de facteurs, incluant le type de système de fichiers, les options utilisées pour monter le système de fichiers, et si le bit de mode set-group-ID est activé ou non sur le répertoire parent. Si le système de fichiers prend en charge les options de montage -o grpid (ou, synonymement -o bsdgroups) et -o nogrpid (ou, synonymement -o sysvgroups) mount(8), alors les règles sont les suivantes

:
•
Si le système de fichiers est monté avec -o grpid, le groupe d'un nouveau fichier est rendu identique à celui du répertoire
parent.
•
Si le système de fichiers est monté avec -o nogrpid et que le bit set-group-ID est désactivé sur le répertoire parent, le groupe d'un nouveau fichier est rendu identique au GID du système de fichiers du
processus.
•
Si le système de fichiers est monté avec -o nogrpid et que le bit set-group-ID est activé sur le répertoire parent, le
groupe d'un nouveau fichier est rendu
identique à celui du répertoire parent.

En tant que Linux 4.12, les options de montage -o grpid et -o nogrpid sont prises en charge par ext2, ext3, ext4, et XFS. Les systèmes de fichiers qui ne prennent pas en charge ces options de montage suivent les règles -o nog

rp
id.

Notes

glibc

Sur les noyaux plus anciens où fchownat() est indisponible, la fonction wrapper de glibc retombe sur l'utilisation de chown() et lchown(). Quand path est relatif, glibc construit un chemin d'accès basé sur le lien symbolique dans /proc/self/fd qui correspond à l'argument dir

f
d.

NF

S

Les sémantiques de chown() sont volontairement violées sur les systèmes de fichiers NFS qui ont le mappage UID activé. De plus, la sémantique de tous les appels système qui accèdent au contenu du fichier est violée, car chown() peut entraîner une révocation immédiate de l'accès aux fichiers déjà ouverts. La mise en cache côté client peut entraîner un délai entre le moment où la p

ropriété a été modifiée pour permettre l'accès à un utilisateur et le moment où l
e fichier peut réellement être accessible par l'utilisateur sur d'autres clients.

Détails

historiques

Les appels système Linux originaux chown(), fchown(), et lchown() ne prenaient en charge que des identifiants utilisateur et de groupe de 16 bits. Par la suite, Linux 2.4 a ajouté chown32(), fchown32(), et lchown32(), prenant en charge des identifiants de 32 bits. Les fonctions wrapper de glibc chown(), fchown(), et lchown() gèrent de manière transparente les variations entre les versions du

noyau.

Avant Linux 2.1.81 (sauf 2.1.46), chown() ne suivait pas les liens symboliques. Depuis Linux 2.1.81, chown() suit les liens symboliques, et il y a un nouvel appel système lchown() qui ne suit pas les liens symboliques. Depuis Linux 2.1.86, ce nouvel appel (qui a la même sémantique que l'ancien chown()) a obtenu le même numéro d'appel système, et chown() a obtenu le

numéro nou
vellement
introduit.

EXEMPLE

S

Le programme suivant change la propriété du fichier nommé dans son deuxième argument de ligne de commande vers la valeur spécifiée dans son premier argument de ligne de commande. Le nouveau propriétaire peut être spécifié soit comme un identifiant utilisateur numérique, soit comme un nom d'utilisateur (qui est converti en identifiant utilisateur en utilisant getpwnam(3) pour effectuer une recherche dans le fichier de mots de passe du système)

.

Source du

programme 
#include <pwd.h>
#include <stdio.h>
#include <stdlib.h>
#include <sys/types.h>
#include <unistd.h>
int
main(int argc, char *argv[])
{
    char           *endptr;
    uid_t          uid;
    struct passwd  *pwd;
    if (argc != 3 || argv[1][0] == '\0') {
        fprintf(stderr, "%s <owner> <file>\n", argv[0]);
        exit(EXIT_FAILURE);
    }
    uid = strtol(argv[1], &endptr, 10);  /* Allow a numeric string */
    if (*endptr != '\0') {         /* Was not pure numeric string */
        pwd = getpwnam(argv[1]);   /* Try getting UID for username */
        if (pwd == NULL) {
            perror("getpwnam");
            exit(EXIT_FAILURE);
        }
        uid = pwd->pw_uid;
    }
    if (chown(argv[2], uid, -1) == -1) {
        perror("chown");
        exit(EXIT_FAILURE);
    }
    exit(EXIT_SUCCESS)
;
}
