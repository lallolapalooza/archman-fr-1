NOM

fcft_rasterize_char_utf32 - convertir en image matricielle un glyphe pour un seul point de code UTF-32

SYNTAXE

#include <fcft/fcft.h>

const struct fcft_glyph *fcft_rasterize_char_utf32(

struct fcft_font *font, uint32_t cp, enum fcft_subpixel subpixel);

DESCRIPTION

fcft_rasterize_char_utf32() convertit en image matricielle le point de code Unicode encodé en UTF-32 cp en utilisant la police principale, ou l'une des polices de secours, de font.

cp est d'abord recherché dans la police principale. S'il n'est pas trouvé, les polices de secours sont recherchées (dans l'ordre où elles ont été spécifiées dans fcft_from_name()). S'il n'est trouvé dans aucune des polices de secours, la liste de secours de FontConfig pour la police principale est recherchée.

subpixel vous permet de spécifier quel mode subpixel utiliser. C'est l'une des valeurs suivantes :

enum fcft_subpixel {
    FCFT_SUBPIXEL_DEFAULT,
    FCFT_SUBPIXEL_NONE,
    FCFT_SUBPIXEL_HORIZONTAL_RGB,
    FCFT_SUBPIXEL_HORIZONTAL_BGR,
    FCFT_SUBPIXEL_VERTICAL_RGB,
    FCFT_SUBPIXEL_VERTICAL_BGR,
};

Si FCFT_SUBPIXEL_DEFAULT est spécifié, le mode subpixel configuré dans FontConfig est utilisé. Si FCFT_SUBPIXEL_NONE est spécifié, un anti-crénelage en niveaux de gris sera utilisé. Pour toutes les autres valeurs, le mode spécifié est utilisé.

Notez que si l'anti-crénelage a été désactivé (dans FontConfig, soit globalement, soit spécifiquement pour la police actuelle), alors subpixel est ignoré.

L'intention est de permettre aux programmes d'utiliser des modes subpixel par moniteur. Accessoirement, enum fcft_subpixel correspond à enum wl_output_subpixel, l'enum utilisé dans Wayland.

Note : vous ne voudrez probablement pas utiliser autre chose que FCFT_SUBPIXEL_NONE si vous effectuez un mélange avec un arrière-plan transparent.

VALEUR DE RETOUR

En cas d'erreur, NULL est retourné.

En cas de succès, un pointeur vers un glyphe converti en image matricielle est retourné. Le glyphe est mis en cache dans fcft, rendant les appels ultérieurs avec les mêmes arguments très rapides (c'est-à-dire qu'il n'est pas nécessaire que les programmes mettent eux-mêmes les glyphes en cache).

L'objet glyphe est géré par font. Il n'est pas nécessaire de le libérer explicitement ; il est libéré lorsque font est détruit (avec fcft_destroy()).

struct fcft_glyph {
    uint32_t cp;
    int cols;
    const char *font_name;
    pixman_image_t *pix;
    int x;
    int y;
    int width;
    int height;
    struct {
        int x;
        int y;
    } advance;
    bool is_color_glyph;
};

cp est le même cp que celui passé à l'appel fcft_rasterize_char_utf32().

cols est le nombre de "colonnes" occupées par le glyphe (effectivement, wcwidth(cp)). Notez que cette valeur sera incorrecte si les caractères larges (wchar_t) ne sont pas encodés en UTF-32 dans la locale actuelle.

pix est le glyphe converti en image matricielle. Son format dépend d'un certain nombre de facteurs, mais sera l'un des formats suivants : PIXMAN_a1, PIXMAN_a8, PIXMAN_x8r8g8b8, PIXMAN_a8r8g8b8. Utilisez pixman_image_get_format() pour savoir lequel c'est.

PIXMAN_a1 correspond à FT_PIXEL_MODE_MONO. C'est-à-dire que le glyphe est un masque binaire non anti-crénelé. À utiliser comme masque lors du mélange.

PIXMAN_a8 correspond à FT_PIXEL_MODE_GRAY. C'est-à-dire que le glyphe est un masque anti-crénelé en niveaux de gris. À utiliser comme masque lors du mélange.

PIXMAN_x8r8g8b8 correspond soit à FT_PIXEL_MODE_LCD, soit à FT_PIXEL_MODE_LCD_V. pixman_image_set_component_alpha() a déjà été appelé pour vous par fcft. À utiliser comme masque lors du mélange.

PIXMAN_a8r8g8b8 correspond à FT_PIXEL_MODE_BGRA. C'est-à-dire que le glyphe est une image RGBA simple. À utiliser comme source lors du mélange.

x est le décalage horizontal du glyphe, en pixels. Ajoutez ceci à la position actuelle du curseur lors du mélange.

y est le décalage vertical du glyphe, en pixels. Ajoutez ceci à la position actuelle du curseur lors du mélange.

width est la largeur du glyphe, en pixels. Utilisez comme argument 'width' lors du mélange.

height est la hauteur du glyphe, en pixels. Utilisez comme argument 'height' lors du mélange.

advance est l'"avancée" du glyphe, en pixels. Ajoutez ceci à la position du curseur après le mélange ; x pour une disposition horizontale et y pour une disposition verticale.

is_color_glyph est vrai si le glyphe est un glyphe couleur, typiquement un emoji. Lorsque vrai, le glyphe doit être composé PAR-DESSUS la surface de destination, au lieu d'être utilisé comme masque.
