NAME

fconfigure — Configure channel properties

SYNOPSIS

fconfigure channelId ?optionName? ?value? ...

DESCRIPTION

The fconfigure command is used to query or modify the configuration parameters for a Tcl channel. It may be used to get or set options on any channel that has been opened by Tcl, including files, pipes, sockets, etc. The standard channels stdin, stdout, and stderr are also configurable.

The command may be used in several ways:

fconfigure channelId
Return a list of all configuration options that may be set for channelId, along with their current values.
fconfigure channelId ?optionName?
If optionName is specified, return the current value of that option for channelId. If optionName is not specified, return a list containing the names of all options that may be set for channelId.
fconfigure channelId ?optionName? ?value?
If value is specified, set the option optionName to value for channelId. If optionName is not specified, or if value is not specified, then the behaviour is as described above.

The following options are supported by most channel types:

-blocking boolean
Controls whether operations on the channel block or not. If set to true, operations like read and write will block until they can complete or until an error occurs. If set to false, operations will return immediately. If an operation cannot complete immediately, it will return -1 and set the error code to EWOULDBLOCK. This option is useful for implementing event-driven applications.
-buffering none | line | full
Controls how I/O buffering is handled for the channel.
none
No buffering is performed. Reads and writes happen directly to/from the underlying channel. This is the default for interactive terminals.
line
Buffering is performed on a line-by-line basis. Output is written when a newline character is encountered or when the buffer is flushed. Input is read when a newline character is encountered. This is the default for files.
full
Buffering is performed on a larger block basis. Output is written when the buffer is full or explicitly flushed. Input is read when the buffer is empty. This is the default for sockets.
The exact behavior of buffering may vary depending on the underlying channel type and operating system. If the buffering mode is changed, any buffered data may be flushed automatically.
-encoding encodingName
Specifies the character encoding for the channel. When reading from the channel, characters are decoded from the specified encoding into Tcl's internal representation. When writing to the channel, characters are encoded from Tcl's internal representation into the specified encoding. If set to binary, no encoding or decoding is performed. This option is useful for dealing with text files or network streams in different character sets. The available encoding names are locale-dependent, but common ones include ascii, iso-8859-1, utf-8, and cp1252. If not specified, the channel inherits the encoding from its parent or uses a default based on the system's locale.
-eofchar char
Specifies a character that should be treated as an end-of-file marker when reading from the channel. When this character is encountered during a read operation, it is treated as the end of the file, and subsequent read operations will return an empty string (or -1 if blocking is disabled). If set to the empty string, no end-of-file character is used. This option is typically used with binary files or when dealing with systems that use a specific character for EOF.
-translation mode
Specifies how end-of-line characters are translated when reading from or writing to the channel. The possible modes are:
binary
No end-of-line translation occurs. This is the default for binary files and sockets.
lf
End-of-line is represented by a single newline character (\n). When reading, carriage return characters (\r) are ignored. When writing, newline characters are written as is. This is the default for Unix-style text files.
cr
End-of-line is represented by a single carriage return character (\r). When reading, newline characters are converted to carriage returns. When writing, carriage return characters are written as is. This mode is rarely used.
crlf
End-of-line is represented by a carriage return followed by a newline character (\r\n). When reading, \r\n sequences are converted to a single newline character. When writing, newline characters are converted to \r\n sequences. This is the default for Windows-style text files and network protocols like HTTP and FTP.
The binary mode is identical to lf mode, except that it also sets the end-of-file character to the empty string (disabling it) and sets the encoding to binary (disabling encoding filtering). See the description of -eofchar and -encoding for more information.

Internally, i.e. when it comes to the actual behaviour of the translator this value is identical to lf and is therefore reported as such when queried. Even if binary was used to set the translation.

cr
The end of a line in the underlying file or device is represented by a single carriage return character. As the input translation mode, cr mode converts carriage returns to newline characters. As the output translation mode, cr mode translates newline characters to carriage returns.
crlf
The end of a line in the underlying file or device is represented by a carriage return character followed by a linefeed character. As the input translation mode, crlf mode converts carriage-return-linefeed sequences to newline characters. As the output translation mode, crlf mode translates newline characters to carriage-return-linefeed sequences. This mode is typically used on Windows platforms and for network connections.
lf
The end of a line in the underlying file or device is represented by a single newline (linefeed) character. In this mode no translations occur during either input or output. This mode is typically used on UNIX platforms.

STANDARD CHANNELS

The Tcl standard channels (stdin, stdout, and stderr) can be configured through this command like every other channel opened by the Tcl library. Beyond the standard options described above they will also support any special option according to their current type. If, for example, a Tcl application is started by the inet super-server common on Unix system its Tcl standard channels will be sockets and thus support the socket options.

EXAMPLES

Instruct Tcl to always send output to stdout immediately, whether or not it is to a terminal:

fconfigure stdout -buffering none

Open a socket and read lines from it without ever blocking the processing of other events:

set s [socket some.where.com 12345]
fconfigure $s -blocking 0
fileevent $s readable "readMe $s"
proc readMe chan {
    if {[gets $chan line] < 0} {
        if {[eof $chan]} {
            close $chan
            return
        }
        # Could not read a complete line this time; Tcl's
        # internal buffering will hold the partial line for us
        # until some more data is available over the socket.
    } else {
        puts stdout $line
    }
}

Read a PPM-format image from a file:

# Open the file and put it into Unix ASCII mode
set f [open teapot.ppm]
fconfigure $f -encoding ascii -translation lf
# Get the header
if {[gets $f] ne "P6"} {
    error "not a raw-bits PPM"
}
# Read lines until we have got non-comment lines
# that supply us with three decimal values.
set words {}
while {[llength $words] < 3} {
    gets $f line
    if {[string match "#*" $line]} continue
    lappend words {*}[join [scan $line %d%d%d]]
}
# Those words supply the size of the image and its
# overall depth per channel. Assign to variables.
lassign $words xSize ySize depth
# Now switch to binary mode to pull in the data,
# one byte per channel (red,green,blue) per pixel.
fconfigure $f -translation binary
set numDataBytes [expr {3 * $xSize * $ySize}]
set data [read $f $numDataBytes]
close $f
