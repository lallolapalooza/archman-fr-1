chdir(2) Manuel des appels système chdir(2)

NOM

chdir, fchdir - changer le répertoire de travail

BIBLIOTHÈQUE

Bibliothèque C standard (libc, -lc)

SYNTAXE

#include <unistd.h>
int chdir(const char *chemin);
int fchdir(int fd);
Exigences de macros de test de fonctionnalités pour glibc (voir feature_test_macros(7)) :

fchdir() :

    _XOPEN_SOURCE >= 500
        || /* Depuis glibc 2.12 : */ _POSIX_C_SOURCE >= 200809L
        || /* glibc jusqu'à et y compris 2.19 : */ _BSD_SOURCE

DESCRIPTION

chdir() change le répertoire de travail actuel du processus appelant vers le répertoire spécifié dans chemin.

fchdir() est identique à chdir(); la seule différence est que le répertoire est donné par un descripteur de fichier ouvert.

VALEUR RENVOYÉE

En cas de succès, zéro est renvoyé. En cas d'erreur, -1 est renvoyé, et errno est défini pour indiquer l'erreur.

ERREURS

Selon le système de fichiers, d'autres erreurs peuvent être renvoyées. Les erreurs les plus générales pour chdir() sont listées ci-dessous :

EACCES
L'autorisation de recherche est refusée pour l'un des composants de chemin. (Voir aussi path_resolution(7).)
EFAULT
chemin pointe en dehors de votre espace d'adressage accessible.
EIO
Une erreur d'E/S s'est produite.
ELOOP
Trop de liens symboliques ont été rencontrés lors de la résolution de chemin.
ENAMETOOLONG
chemin est trop long.
ENOENT
Le répertoire spécifié dans chemin n'existe pas.
ENOMEM
La mémoire noyau disponible était insuffisante.
ENOTDIR
Un composant de chemin n'est pas un répertoire.

Les erreurs générales pour fchdir() sont listées ci-dessous :

EACCES
L'autorisation de recherche a été refusée sur le répertoire ouvert sur fd.
EBADF
fd n'est pas un descripteur de fichier valide.
ENOTDIR
fd ne se réfère pas à un répertoire.

NORMES

POSIX.1-2024.

HISTORIQUE

POSIX.1-2001, SVr4, 4.4BSD.

NOTES

Le répertoire de travail actuel est le point de départ pour l'interprétation des chemins relatifs (ceux qui ne commencent pas par '/').

Un processus enfant créé via fork(2) hérite du répertoire de travail actuel de son parent. Le répertoire de travail actuel est laissé inchangé par execve(2).

VOIR AUSSI

chroot(2), getcwd(3), path_resolution(7)
