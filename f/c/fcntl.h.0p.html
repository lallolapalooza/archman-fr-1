fcntl.h(0P) Manuel du programmeur POSIX fcntl.h(0P)

PROLOGUE

Cette page manuelle fait partie du Manuel du programmeur POSIX. L'implémentation Linux de cette interface peut différer (consultez la page man correspondante de Linux pour les détails du comportement de Linux), ou l'interface peut ne pas être implémentée sur Linux.

NOM

fcntl.h — options de contrôle de fichier

SYNOPSIS

#include <fcntl.h>

DESCRIPTION

L'en-tête <fcntl.h> doit définir les constantes symboliques suivantes pour l'argument cmd utilisé par fcntl(). Les valeurs doivent être uniques et doivent convenir à une utilisation dans les directives de prétraitement #if

F_DUPFD
Dupliquer un descripteur de fichier.
F_DUPFD_CLOEXEC

Dupliquer un descripteur de fichier avec le drapeau close-on-exec FD_CLOEXEC défini.
F_GETFD
Obtenir les drapeaux du descripteur de fichier.
F_SETFD
Définir les drapeaux du descripteur de fichier.
F_GETFL
Obtenir les drapeaux d'état du fichier et les modes d'accès au fichier.
F_SETFL
Définir les drapeaux d'état du fichier.
F_GETLK
Obtenir les informations de verrouillage d'enregistrement.
F_SETLK
Définir les informations de verrouillage d'enregistrement.
F_SETLKW
Définir les informations de verrouillage d'enregistrement ; attendre si bloqué.
F_GETOWN
Obtenir l'identifiant de processus ou de groupe de processus destinataire des signaux SIGURG.
F_SETOWN
Définir l'identifiant de processus ou de groupe de processus destinataire des signaux SIGURG.

L'en-tête <fcntl.h> doit définir la constante symbolique suivante utilisée pour les drapeaux de descripteur de fichier de fcntl(), qui doit convenir à une utilisation dans les directives de prétraitement #if

FD_CLOEXEC
Fermer le descripteur de fichier lors de l'exécution d'une fonction de la famille exec

L'en-tête <fcntl.h> doit également définir les constantes symboliques suivantes pour l'argument l_type utilisé pour le verrouillage d'enregistrement avec fcntl(). Les valeurs doivent être uniques et doivent convenir à une utilisation dans les directives de prétraitement #if

F_RDLCK
Verrouillage partagé ou en lecture.
F_UNLCK
Déverrouillage.
F_WRLCK
Verrouillage exclusif ou en écriture.

L'en-tête <fcntl.h> doit définir les valeurs utilisées pour l_whence, SEEK_SET, SEEK_CUR et SEEK_END comme décrit dans <stdio.h>.

L'en-tête <fcntl.h> doit définir les constantes symboliques suivantes comme drapeaux de création de fichier pour une utilisation dans la valeur oflag de open() et openat(). Les valeurs doivent être distinctes au niveau des bits et doivent convenir à une utilisation dans les directives de prétraitement #if

O_CLOEXEC
Le drapeau FD_CLOEXEC associé au nouveau descripteur doit être défini pour fermer le descripteur de fichier lors de l'exécution d'une fonction de la famille exec
O_CREAT
Créer le fichier s'il n'existe pas.
O_DIRECTORY
Échouer si le fichier n'est pas un répertoire.
O_EXCL
Drapeau d'utilisation exclusive.
O_NOCTTY
Ne pas attribuer de terminal de contrôle.
O_NOFOLLOW
Ne pas suivre les liens symboliques.
O_TRUNC
Drapeau de troncature.
O_TTY_INIT
Définir les paramètres du terminal de la structure termios sur un état fournissant un comportement conforme ; voir Section 11.2, Paramètres pouvant être définis.

Le drapeau O_TTY_INIT peut avoir la valeur zéro et dans ce cas, il n'a pas besoin d'être distinct au niveau des bits des autres drapeaux.

L'en-tête <fcntl.h> doit définir les constantes symboliques suivantes pour une utilisation comme drapeaux d'état du fichier pour open(), openat() et fcntl(). Les valeurs doivent convenir à une utilisation dans les directives de prétraitement #if

O_APPEND
Activer le mode d'ajout.
O_DSYNC
Écrire selon l'achèvement d'intégrité des données d'E/S synchronisées.
O_NONBLOCK
Mode non bloquant.
O_RSYNC
Opérations d'E/S de lecture synchronisées.
O_SYNC
Écrire selon l'achèvement d'intégrité du fichier d'E/S synchronisées.

L'en-tête <fcntl.h> doit définir la constante symbolique suivante pour une utilisation comme masque des modes d'accès au fichier. La valeur doit convenir à une utilisation dans les directives de prétraitement #if

O_ACCMODE
Masque des modes d'accès au fichier.

L'en-tête <fcntl.h> doit définir les constantes symboliques suivantes pour une utilisation comme modes d'accès au fichier pour open(), openat() et fcntl(). Les valeurs doivent être uniques, sauf que O_EXEC et O_SEARCH peuvent avoir des valeurs égales. Les valeurs doivent convenir à une utilisation dans les directives de prétraitement #if

O_EXEC
Ouvrir en exécution uniquement (fichiers non-répertoires). Le résultat est indéterminé si ce drapeau est appliqué à un répertoire.
O_RDONLY
Ouvrir en lecture uniquement.
O_RDWR
Ouvrir en lecture et écriture.
O_SEARCH
Ouvrir un répertoire pour la recherche uniquement. Le résultat est indéterminé si ce drapeau est appliqué à un fichier non-répertoire.
O_WRONLY
Ouvrir en écriture uniquement.

L'en-tête <fcntl.h> doit définir les constantes symboliques des modes de fichier pour une utilisation comme valeurs de mode_t comme décrit dans <sys/stat.h>.

L'en-tête <fcntl.h> doit définir la constante symbolique suivante comme valeur spéciale utilisée à la place d'un descripteur de fichier pour les fonctions *at() qui prennent un descripteur de fichier répertoire comme paramètre :

AT_FDCWD
Utiliser le répertoire de travail courant pour déterminer la cible des chemins de fichier relatifs.

L'en-tête <fcntl.h> doit définir la constante symbolique suivante comme valeur pour le drapeau utilisé par faccessat() :

AT_EACCESS
Vérifier l'accès en utilisant les identifiants effectifs d'utilisateur et de groupe.

L'en-tête <fcntl.h> doit définir la constante symbolique suivante comme valeur pour le drapeau utilisé par fstatat(), fchmodat(), fchownat() et utimensat() :

AT_SYMLINK_NOFOLLOW

Ne pas suivre les liens symboliques.

L'en-tête <fcntl.h> doit définir la constante symbolique suivante comme valeur pour le drapeau utilisé par linkat() :

AT_SYMLINK_FOLLOW

Suivre le lien symbolique.

L'en-tête <fcntl.h> doit définir la constante symbolique suivante comme valeur pour le drapeau utilisé par unlinkat() :

AT_REMOVEDIR

Supprimer le répertoiretead of file.

Le <fcntl.h> en-tête doit définir les constantes symboliques suivantes pour l' argument utilisé par posix_fadvise() :

POSIX_FADV_DONTNEED

L'application s'attend à ne pas accéder aux données spécifiées dans un avenir proche.
POSIX_FADV_NOREUSE

L'application s'attend à accéder aux données spécifiées une seule fois et à ne pas les réutiliser par la suite.
POSIX_FADV_NORMAL

L'application n'a aucun conseil à donner sur son comportement concernant les données spécifiées. C'est la caractéristique par défaut si aucun conseil n'est donné pour un fichier ouvert.
POSIX_FADV_RANDOM

L'application s'attend à accéder aux données spécifiées dans un ordre aléatoire.
POSIX_FADV_SEQUENTIAL

L'application s'attend à accéder aux données spécifiées séquentiellement à partir de décalages plus bas vers des décalages plus élevés.
POSIX_FADV_WILLNEED

L'application s'attend à accéder aux données spécifiées dans un avenir proche.

Le <fcntl.h> en-tête doit définir la structure flock décrivant un verrou de fichier. Elle doit inclure les membres suivants :

short  l_type   Type de verrou ; F_RDLCK, F_WRLCK, F_UNLCK.
short  l_whence Drapeau pour le décalage de départ.
off_t  l_start  Décalage relatif en octets.
off_t  l_len    Taille ; si 0, alors jusqu'à la fin du fichier (EOF).
pid_t  l_pid    Identifiant du processus détenant le verrou ; renvoyé avec F_GETLK.

Le <fcntl.h> en-tête doit définir les types mode_t, off_tet pid_t tels que décrits dans <sys/types.h>.

Les éléments suivants doivent être déclarés comme des fonctions et peuvent également être définis comme des macros. Les prototypes de fonctions doivent être fournis.

int  creat(const char *, mode_t);
int  fcntl(int, int, ...);
int  open(const char *, int, ...);
int  openat(int, const char *, int, ...);
int  posix_fadvise(int, off_t, off_t, int);
int  posix_fallocate(int, off_t, off_t);

L'inclusion de l'en-tête <fcntl.h> peut également rendre visibles tous les symboles de <sys/stat.h> et de <unistd.h>.

Les sections suivantes sont informatives.

UTILISATION PAR L'APPLICATION

Bien qu'aucune implémentation existante ne définisse AT_SYMLINK_FOLLOW et AT_SYMLINK_NOFOLLOW comme la même valeur numérique, POSIX.1‐2008 ne l'interdit pas car les deux constantes ne sont pas utilisées avec les mêmes interfaces.

JUSTIFICATION

Bien que bon nombre des constantes symboliques introduites dans l'en-tête <fcntl.h> n'aient pas strictement besoin d'être utilisées dans des #if directives du préprocesseur, la pratique historique répandue les a définies comme des macros utilisables dans de telles constructions, et l'examen des applications existantes a montré qu'elles sont occasionnellement utilisées de cette manière. Par conséquent, il a été décidé de conserver cette exigence pour une implémentation dans POSIX.1‐2008.
