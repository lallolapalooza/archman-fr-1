FCGI_Accept(3)

Paquet: fcgi

Licences: custom

() ()
NOM
FCGI_Accept, FCGI_ToFILE, FCGI_ToFcgiStream
- bibliothèque de compatibilité fcgi_stdio

SYNTAXE
#include "fcgi_stdio.h"


int
FCGI_Accept(void);


FILE *
FCGI_ToFILE(FCGI_FILE *);


FCGI_Stream *
FCGI_ToFcgiStream(FCGI_FILE *);

DESCRIPTION
La fonction FCGI_Accept accepte une nouvelle requête du serveur HTTP
et crée un environnement d'exécution compatible CGI pour la requête.


Si l'application a été invoquée en tant que programme CGI, le premier
appel à FCGI_Accept est essentiellement une opération nulle et le deuxième
appel retourne -1. Cela fait qu'une application Répondeur FastCGI correctement codée
exécute une seule requête et se termine, donnant un comportement CGI.


Si l'application a été invoquée en tant que serveur FastCGI, le premier
appel à FCGI_Accept indique que l'application a terminé
son initialisation et est prête à accepter sa première requête.
Les appels ultérieurs à FCGI_Accept indiquent que l'application a
terminé le traitement de sa requête actuelle et est prête à accepter une
nouvelle requête. Une application peut terminer la requête actuelle
sans en accepter une nouvelle en appelant FCGI_Finish(3) ; plus tard, lorsqu'elle est
prête à accepter une nouvelle requête, l'application appelle FCGI_Accept.


En terminant la requête actuelle, FCGI_Accept peut détecter
des erreurs, par exemple une connexion rompue avec un client qui s'est déconnecté
prématurément. FCGI_Accept ignore ces erreurs. Une application
qui souhaite gérer de telles erreurs doit explicitement appeler
fclose(stderr), puis fclose(stdout) ; un retour EOF de
l'un ou l'autre indique une erreur.


Si la variable d'environnement FCGI_WEB_SERVER_ADDRS est définie lorsque
FCGI_Accept est appelée, elle doit contenir une liste d'adresses IP
séparées par des virgules. Chaque adresse IP est écrite sous forme de quatre nombres décimaux
dans la plage [0..255] séparés par des points décimaux.
(nslookup(8) traduit le nom d'hôte IP symbolique plus familier
en cette forme.) Donc une liaison légale pour cette variable est


FCGI_WEB_SERVER_ADDRS=199.170.183.28,199.170.183.71


FCGI_Accept vérifie l'adresse IP du pair de chaque nouvelle connexion pour
l'appartenance à la liste. Si la vérification échoue (y compris la
possibilité que la connexion n'ait pas utilisé le transport TCP/IP),
FCGI_Accept ferme la connexion et en accepte une autre
(sans retourner entre-temps).


Après avoir accepté une nouvelle requête, FCGI_Accept attribue de nouvelles valeurs
aux variables globales stdin, stdout, stderr et environ.
Après que FCGI_Accept retourne, ces variables ont la même
interprétation qu'à l'entrée d'un programme CGI.


FCGI_Accept libère tout stockage alloué par l'appel précédent
à FCGI_Accept. Cela a des conséquences importantes :


NE conserveZ PAS de pointeurs vers le tableau environ ou les chaînes
qu'il contient (par exemple, vers le résultat de l'appel à getenv(3)),
car ils seront libérés par le prochain appel à FCGI_Finish ou
FCGI_Accept.


N'UTILISEZ PAS setenv(3) ou putenv(3) pour modifier le tableau environ
créé par FCGI_Accept, car cela pourrait fuir du stockage
ou faire en sorte que le prochain appel à FCGI_Finish ou FCGI_Accept libère
du stockage qui ne devrait pas être libéré.


Si votre application a besoin d'utiliser setenv ou putenv pour modifier
le tableau environ, elle doit suivre ce modèle de codage :


char **savedEnviron, **requestEnviron;
int acceptStatus;


savedEnviron = environ;
acceptStatus = FCGI_Accept();
requestEnviron = environ;
environ = savedEnviron;
if(acceptStatus >= 0 && !FCGX_IsCGI()) {
/*
* requestEnviron pointe vers des paires nom-valeur dans
* du stockage alloué par FCGI_Accept. OK à lire,
* pas OK à conserver les pointeurs -- faire des copies à la place.
*/
}
/*
* OK pour faire setenv ou putenv, mais attention aux fuites de stockage !
*/


En plus des variables d'environnement CGI standard, la
variable d'environnement FCGI_ROLE est toujours définie sur le rôle
de la requête actuelle. Les rôles actuellement définis sont
RESPONDER, AUTHORIZER et FILTER.


Dans le rôle FILTER, les variables supplémentaires FCGI_DATA_LENGTH
et FCGI_DATA_LAST_MOD sont également définies. Voir la page de manuel
FCGI_StartFilterData(3) pour des informations complètes.


Les macros FCGI_ToFILE et FCGI_ToFcgiStream sont fournies
pour permettre l'évasion vers des fonctions natives qui utilisent les types FILE ou
FCGI_Stream. Dans le cas de FILE, les fonctions devraient être
compilées séparément, car fcgi_stdio.h remplace le
FILE standard par FCGI_FILE.

VALEURS DE RETOUR
0 pour un appel réussi, -1 pour une erreur (l'application doit se terminer).
