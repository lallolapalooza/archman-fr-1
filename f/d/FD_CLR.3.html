select(2) Manuel des appels système select(2)

NOM

select, pselect, FD_CLR, FD_ISSET, FD_SET, FD_ZERO, fd_set - multiplexage d'E/S synchrone

BIBLIOTHÈQUE

Bibliothèque C standard (libc,-lc)

DESCRIPTION

AVERTISSEMENT: select() ne peut surveiller que les numéros de descripteurs de fichiers inférieurs à FD_SETSIZE (1024)—une limite déraisonnablement basse pour de nombreuses applications modernes—et cette limitation ne changera pas. Toutes les applications modernes devraient plutôt utiliser poll(2) ou epoll(7), qui ne souffrent pas de cette limitation.

select() permet à un programme de surveiller plusieurs descripteurs de fichiers, en attendant qu'un ou plusieurs descripteurs de fichiers deviennent « prêts » pour une certaine classe d'opération d'E/S (par ex., lecture possible). Un descripteur de fichiers est considéré comme prêt s'il est possible d'effectuer l'opération d'E/S correspondante (par ex., read(2), ou un write(2)suffisamment petit) sans bloquer.

fd_set

Un type de structure qui peut représenter un ensemble de descripteurs de fichiers. Selon POSIX, le nombre maximal de descripteurs de fichiers dans une structure fd_set est la valeur de la macro FD_SETSIZE.

Ensembles de descripteurs de fichiers

Les arguments principaux de select() sont trois « ensembles » de descripteurs de fichiers (déclarés avec le type fd_set), qui permettent à l'appelant d'attendre trois classes d'événements sur l'ensemble spécifié de descripteurs de fichiers. Chacun des arguments fd_set peut être spécifié comme NULL si aucun descripteur de fichiers n'est à surveiller pour la classe d'événements correspondante.

Bien noter: Au retour, chacun des ensembles de descripteurs de fichiers est modifié sur place pour indiquer quels descripteurs de fichiers sont actuellement « prêts ». Ainsi, si vous utilisez select() dans une boucle, les ensembles doivent être réinitialisés avant chaque appel.

Le contenu d'un ensemble de descripteurs de fichiers peut être manipulé à l'aide des macros suivantes :

FD_ZERO()
Cette macro efface (retire tous les descripteurs de fichiers de) set. Elle doit être utilisée comme première étape lors de l'initialisation d'un ensemble de descripteurs de fichiers.
FD_SET()
Cette macro ajoute le descripteur de fichiers fd à set. Ajouter un descripteur de fichiers déjà présent dans l'ensemble est une opération sans effet, et ne produit pas d'erreur.
FD_CLR()
Cette macro retire le descripteur de fichiers fd de set. Retirer un descripteur de fichiers non présent dans l'ensemble est une opération sans effet, et ne produit pas d'erreur.
FD_ISSET()
select() modifie le contenu des ensembles selon les règles décrites ci-dessous. Après avoir appelé select(), la macro FD_ISSET() peut être utilisée pour tester si un descripteur de fichiers est toujours présent dans un ensemble. FD_ISSET() renvoie une valeur non nulle si le descripteur de fichiers fd est présent dans set, et zéro s'il ne l'est pas.

Arguments

Les arguments de select() sont les suivants :

readfds
Les descripteurs de fichiers dans cet ensemble sont surveillés pour voir s'ils sont prêts à être lus. Un descripteur de fichiers est prêt à être lu si une opération de lecture ne bloquera pas ; en particulier, un descripteur de fichiers est également prêt en cas de fin de fichier.
Après que select() a renvoyé, readfds sera vidé de tous les descripteurs de fichiers sauf ceux qui sont prêts à être lus.
writefds
Les descripteurs de fichiers dans cet ensemble sont surveillés pour voir s'ils sont prêts à être écrits. Un descripteur de fichiers est prêt à être écrit si une opécriture ne bloquera pas. Cependant, même si un descripteur de fichiers est indiqué comme inscriptible, une grande écriture peut encore bloquer.
Après que select() a renvoyé, writefds sera vidé de tous les descripteurs de fichiers sauf ceux qui sont prêts à être écrits.
exceptfds
Les descripteurs de fichiers dans cet ensemble sont surveillés pour des « conditions exceptionnelles ». Pour des exemples de certaines conditions exceptionnelles, voir la discussion de POLLPRI dans poll(2).
Après que select() a renvoyé, exceptfds sera vidé de tous les descripteurs de fichiers sauf ceux pour lesquels une condition exceptionnelle s'est produite.
nfds
Cet argument doit être réglé au numéro de descripteur de fichier le plus élevé dans l'un des trois ensembles, plus 1. Les descripteurs de fichiers indiqués dans chaque ensemble sont vérifiés, jusqu'à cette limite (mais voir BUGS).
timeout
L'argument timeout est une structure timeval (montrée ci-dessous) qui spécifie l'intervalle pendant lequel select() doit bloquer en attendant qu'un descripteur de fichier devienne prêt. L'appel bloquera jusqu'à ce que l'une des situations suivantes se produise :
•
un descripteur de fichier devient prêt ;
•
l'appel est interrompu par un gestionnaire de signal ; ou
•
le délai d'attente expire.
Notez que l'intervalle timeout sera arrondi à la granularité de l'horloge système, et les retards d'ordonnancement du noyau signifient que l'intervalle de blocage peut être dépassé d'une petite quantité.
Si les deux champs de la structure timeval sont à zéro, alors select() renvoie immédiatement. (Cela est utile pour l'interrogation.)
Si timeout est spécifié comme NULL, select() bloque indéfiniment en attendant qu'un descripteur de fichier devienne prêt.

pselect()

L'appel système pselect() permet à une application d'attendre en toute sécurité jusqu'à ce qu'un descripteur de fichier devienne prêt ou jusqu'à ce qu'un signal soit capté.

Le fonctionnement de select() et pselect() est identique, à part ces trois différences :

•
select() utilise un délai d'attente qui est un struct timeval (avec secondes et microsecondes), tandis que pselect() utilise un struct timespec (avec secondes et nanosecondes).
•
select() peut mettre à jour l'argument timeout pour indiquer combien de temps restait. pselect() ne modifie pas cet argument.
•
select() n'a pas d'argument sigmask , et se comporte comme pselect() appelé avec sigmaskNULL.

sigmask est un pointeur vers un masque de signal (voir sigprocmask(2)) ; s'il n'est pas NULL, alors pselect() remplace d'abord le masque de signal courant par celuipointé par sigmask , puis exécute la fonction "select", puis restaure le masque de signaux original. (Si sigmask est NULL, le masque de signaux n'est pas modifié pendant l'appel pselect ().) À part la différence de précision de l'argument timeout [[9]], l'appel suivant à

BUGS

POSIX permet à une implémentation de définir une limite supérieure, annoncée via la constante FD_SETSIZE [[227]], sure de descripteurs de fichiers qui peuvent être spécifiés dans un ensemble de descripteurs de fichiers. Le noyau Linux n'impose pas de limite fixe, mais l'implémentation de glibc en fait fd_set un type de taille fixe, avec FD_SETSIZE défini comme 1024, et les FD_*() macros fonctionnant selon cette limite. Pour surveiller des descripteurs de fichiers supérieurs à 1023, utilisez poll(2) ou epoll(7) à la place.

L'implémentation des fd_set arguments comme arguments valeur-résultat est une erreur de conception qui est évitée dans poll(2) et epoll(7).

Selon POSIX, select() devrait vérifier tous les descripteurs de fichiers spécifiés dans les trois ensembles de descripteurs de fichiers, jusqu'à la limite nfds-1. Cependant, l'implémentation actuelle ignore tout descripteur de fichiers dans ces ensembles qui est supérieur au numéro de descripteur de fichiers maximum que le processus a actuellement ouvert. Selon POSIX, tout descripteur de fichiers de ce type spécifié dans l'un des ensembles devrait entraîner l'erreur EBADF.

À partir de glibc 2.1, glibc a fourni une émulation de pselect() qui était implémentée à l'aide de sigprocmask(2) et select(). Cette implémentation restait vulnérable à la même condition de concurrence que pselect() était conçu pour prévenir. Les versions modernes de glibc utilisent l'appel système (sans concurrence) pselect() sur les noyaux où il est fourni.

Sur Linux, select() peut signaler un descripteur de fichier de socket comme « prêt pour la lecture », alors qu'une lecture ultérieure se bloque néanmoins. Cela pourrait par exemple se produire lorsque des données sont arrivées mais qu'à l'examination elles ont la mauvaise somme de contrôle et sont rejetées. Il peut y avoir d'autres circonstances dans lesquelles un descripteur de fichier est signalé comme prêt à tort. Il peut donc être plus sûr d'utiliser O_NONBLOCK sur les sockets qui ne devraient pas se bloquer.

Sur Linux, select() modifie également timeout si l'appel est interrompu par un gestionnaire de signal (c'est-à-dire le EINTR retour d'erreur). Cela n'est pas autorisé par POSIX.1. L'appel système Linux pselect() a le même comportement, mais le wrapper glibc masque ce comportement en copiant internément le timeout dans une variable locale et en passant cette variable à l'appel système.

EXEMPLES

#include <stdio.h>
#include <stdlib.h>
#include <sys/select.h>
#include <sys/time.h>
int
main(void)
{
    int             retval;
    fd_set          rfds;
    struct timeval  tv;
    /* Surveiller stdin (fd 0) pour voir quand il a des entrées.  */
    FD_ZERO(&rfds);
    FD_SET(0, &rfds);
    /* Attendre jusqu'à cinq secondes.  */
    tv.tv_sec = 5;
    tv.tv_usec = 0;
    retval = select(1, &rfds, NULL, NULL, &tv);
    /* Ne comptez pas sur la valeur de tv maintenant ! */
    if (retval == -1)
        perror("select()");
    else if (retval)
        printf("Data is available now.\n");
        /* FD_ISSET(0, &rfds) sera vrai.  */
    else
        printf("No data within five seconds.\n");
    exit(EXIT_SUCCESS);
}
