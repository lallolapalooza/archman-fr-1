FDOPENDIR(3P) Manuel du programmeur POSIX FDOPENDIR(3P)

PROLOGUE

Cette page manuelle fait partie du Manuel du programmeur POSIX. L'implémentation Linux de cette interface peut différer (consultez la page manuelle Linux correspondante pour les détails du comportement de Linux), ou l'interface peut ne pas être implémentée sur Linux.

NOM

fdopendir, opendir — ouvrir le répertoire associé à un descripteur de fichier

SYNOPSIS

#include <dirent.h>
DIR *fdopendir(int fd);
DIR *opendir(const char *dirname);

DESCRIPTION

La fonction fdopendir() est équivalente à la fonction opendir() sauf que le répertoire est spécifié par un descripteur de fichier plutôt que par un nom. La position du fichier associée au descripteur de fichier au moment de l'appel détermine les entrées qui sont retournées.

Lors du retour réussi de fdopendir(), le descripteur de fichier est sous le contrôle du système, et si toute tentative est faite pour fermer le descripteur de fichier, ou pour modifier l'état de la description associée, autrement que par le biais de closedir(), readdir(), readdir_r(), rewinddir(), ou seekdir(), le comportement est indéfini. Lors de l'appel à closedir() le descripteur de fichier sera fermé.

Il n'est pas spécifié si l'indicateur FD_CLOEXEC sera défini sur le descripteur de fichier par un appel réussi à fdopendir().

La fonction opendir() ouvrira un flux de répertoire correspondant au répertoire nommé par l'argument dirname . Le flux de répertoire est positionné à la première entrée. Si le type DIR est implémenté à l'aide d'un descripteur de fichier, les applications ne pourront ouvrir qu'un total de {OPEN_MAX} fichiers et répertoires.

Si le type DIR est implémenté à l'aide d'un descripteur de fichier, le descripteur sera obtenu comme si l'indicateur O_DIRECTORY avait été passé à open().

VALEUR RENVOYÉE

Lors de l'achèvement réussi, ces fonctions renverront un pointeur vers un objet de type DIR. Sinon, ces fonctions renverront un pointeur nul et définiront errno pour indiquer l'erreur.

ERREURS

La fonction fdopendir() échouera si :

EBADF
L'argument fd n'est pas un descripteur de fichier valide ouvert en lecture.
ENOTDIR
Le descripteur fd n'est pas associé à un répertoire.

La fonction opendir() échouera si :

EACCES
La permission de recherche est refusée pour le composant du préfixe de chemin de dirname ou la permission de lecture est refusée pour dirname.
ELOOP
Une boucle existe dans les liens symboliques rencontrés lors de la résolution de dirname l'argument.
ENAMETOOLONG

La longueur d'un composant d'un chemin d'accès est plus longue que {NAME_MAX}.
ENOENT
Un composant de dirname ne nomme pas un répertoire existant ou dirname est une chaîne vide.
ENOTDIR
Un composant de dirname nomme un fichier existant qui n'est ni un répertoire ni un lien symbolique vers un répertoire.

La fonction opendir() peut échouer si :

ELOOP
Plus de {SYMLOOP_MAX} liens symboliques ont été rencontrés lors de la résolution de l'argument dirname .
EMFILE
Tous les descripteurs de fichier disponibles pour le processus sont actuellement ouverts.
ENAMETOOLONG

La longueur d'un chemin d'accès dépasse {PATH_MAX}, ou la résolution d'un chemin d'accès d'un lien symbolique a produit un résultat intermédiaire avec une longueur qui dépasse {PATH_MAX}.
ENFILE
Trop de fichiers sont actuellement ouverts dans le système.

Trouver et ouvrir un fichier

Le programme suivant parcourt un répertoire donné à la recherche de fichiers dont le nom ne commence pas par un point et dont la taille est supérieure à 1 Mio.

#include <stdio.h>
#include <dirent.h>
#include <fcntl.h>
#include <sys/stat.h>
#include <stdint.h>
#include <stdlib.h>
#include <unistd.h>
int
main(int argc, char *argv[])
{
    struct stat statbuf;
    DIR *d;
    struct dirent *dp;
    int dfd, ffd;
    if ((d = fdopendir((dfd = open("./tmp", O_RDONLY)))) == NULL) {
        fprintf(stderr, "Cannot open ./tmp directory\n");
        exit(1);
    }
    while ((dp = readdir(d)) != NULL) {
        if (dp->d_name[0] == '.')
            continue;
        /* there is a possible race condition here as the file
         * could be renamed between the readdir and the open */
        if ((ffd = openat(dfd, dp->d_name, O_RDONLY)) == -1) {
            perror(dp->d_name);
            continue;
        }
        if (fstat(ffd, &statbuf) == 0 && statbuf.st_size > (1024*1024)) {
            /* found it ... */
            printf("%s: %jdK\n", dp->d_name,
                (intmax_t)(statbuf.st_size / 1024));
        }
        close(ffd);
    }
    closedir(d); // note this implicitly closes dfd
    return 0;
}

UTILISATION PAR LES APPLICATIONS

La fonction opendir() devrait être utilisée en conjonction avec readdir(), closedir(), et rewinddir() pour examiner le contenu du répertoire (voir la section EXEMPLES dans readdir()). Cette méthode est recommandée pour la portabilité.

JUSTIFICATION

Le but de la fonction fdopendir() est de permettre l'ouverture de fichiers dans des répertoires autres que le répertoire de travail courant sans exposition à des conditions de course. Toute partie du chemin d'un fichier pourrait être modifiée en parallèle d'un appel à opendir(), résultant en un comportement indéfini.

Basé sur des implémentations historiques, les règles concernant les descripteurs de fichier s'appliquent également aux flux de répertoire. Cependant, ce volume de POSIX.1‐2017 n'exige pas que le flux de répertoire soit implémenté à l'aide de descripteurs de fichier. La description de closedir() clarifie que si un descripteur de fichier est utilisé pour le flux de répertoire, il est obligatoire que closedir() désalloue le descripteur de fichier. Lorsqu'un descripteur de fichier est utilisé pour implémenter le flux de répertoire, il se comporte comme si le FD_CLOEXEC avait été défini pour le descripteur de fichier.

Les entrées de répertoire pour dot et dot-dot sont facultatives. Ce volume de POSIX.1‐2017 ne fournit pas de moyen de tester a priori leur existence car une application portable doit être écrite pour rechercher (et généralement ignorer) ces entrées. Écrire du code qui présume qu'elles sont les deux premières entrées ne fonctionne pas toujours, car de nombreuses implémentations permettent qu'elles soient autres que les deux premières entrées, avec une entrée « normale » les précédant. Il y a une valeur négligeable à fournir un moyen de déterminer ce que fait l'implémentation car le code pour gérer dot et dot-dot doit être écrit dans tous les cas et parce qu'un tel indicateur ajouterait à la liste de ces indicateurs (qui s'est avéré en soi être objectionnable) et pourraitbused.

Comme la structure et l'allocation du tampon, le cas échéant, pour les opérations de répertoire sont définies par l'implémentation, ce volume de POSIX.1‐2017 n'impose aucune exigence de portabilité pour les constructions de programmes erronées, les données erronées ou l'utilisation de valeurs non spécifiées, comme l'utilisation ou la référence d'une valeur dirp ou d'une valeur de structure dirent après la fermeture d'un flux de répertoire ou après un appel à fork() ou à l'un des appels de fonction exec.
