fopen(3) Manuel des fonctions de bibliothèque fopen(3)

NOM

fopen, fdopen, freopen - fonctions d'ouverture de flux

BIBLIOTHÈQUE

Bibliothèque C standard (libc, -lc)

SYNOPIS

#include <stdio.h>
FILE *fopen(const char *restrict path, const char *restrict mode);
FILE *fdopen(int fd, const char *mode);
FILE *freopen(const char *restrict path, const char *restrict mode,
              FILE *restrict stream);
Conditions de test de fonctionnalité pour glibc (voir feature_test_macros(7)) :

fdopen() :

    _POSIX_C_SOURCE

DESCRIPTION

La fonction fopen() ouvre le fichier dont le nom est la chaîne pointée par path et y associe un flux. Le pointeur mode pointe vers une chaîne commençant par l'une des séquences suivantes (éventuellement suivie de caractères supplémentaires, comme décrit ci-dessous) :

r
Ouvrir un fichier texte en lecture. Le flux est positionné au début du fichier.
r+
Ouvrir en lecture et écriture. Le flux est positionné au début du fichier.
w
Tronquer le fichier à une longueur nulle ou créer un fichier texte en écriture. Le flux est positionné au début du fichier.
w+
Ouvrir en lecture et écriture. Le fichier est créé s'il n'existe pas, sinon il est tronqué. Le flux est positionné au début du fichier.
a
Ouvrir en ajout (écriture en fin de fichier). Le fichier est créé s'il n'existe pas. Le flux est positionné à la fin du fichier.
a+
Ouvrir en lecture et ajout (écriture en fin de fichier). Le fichier est créé s'il n'existe pas. Les sorties sont toujours ajoutées à la fin du fichier. POSIX est silencieux sur la position de lecture initiale lors de l'utilisation de ce mode. Pour glibc, la position initiale du fichier en lecture est au début du fichier, mais pour Android/BSD/MacOS, la position initiale du fichier en lecture est à la fin du fichier.

La chaîne mode peut également inclure la lettre 'b' soit comme dernier caractère, soit comme caractère entre les caractères de l'une des chaînes à deux caractères décrites ci-dessus. Ceci est strictement pour la compatibilité avec ISO C et n'a aucun effet ; le 'b' est ignoré sur tous les systèmes conformes POSIX, y compris Linux. (D'autres systèmes peuvent traiter les fichiers texte et les fichiers binaires différemment, et ajouter le 'b' peut être une bonne idée si vous effectuez des E/S sur un fichier binaire et que vous vous attendez à ce que votre programme soit porté sur des environnements non-UNIX.)

Voir NOTES ci-dessous pour les détails des extensions glibc pour mode.

Tout fichier créé aura le mode S_IRUSR | S_IWUSR | S_IRGRP | S_IWGRP | S_IROTH | S_IWOTH (0666), tel que modifié par le masque umask du processus (voir umask(2)).

Les lectures et écritures peuvent être entremêlées sur les flux de lecture/écriture dans n'importe quel ordre. Notez que ANSI C exige qu'une fonction de positionnement de fichier intervienne entre une sortie et une entrée, à moins qu'une opération d'entrée n'atteigne la fin du fichier. (Si cette condition n'est pas remplie, une lecture peut renvoyer le résultat d'écritures autres que la plus récente.) Il est donc de bonne pratique (et même parfois nécessaire sous Linux) d'insérer une opération fseek(3) ou fsetpos(3) entre les opérations d'écriture et de lecture sur un tel flux. Cette opération peut être un no-op apparent (comme dans fseek(..., 0L, SEEK_CUR) appelé pour son effet de synchronisation).

L'ouverture d'un fichier en mode ajout (a comme premier caractère de mode) provoque l'exécution de toutes les opérations d'écriture ultérieures sur ce flux en fin de fichier, comme si elles étaient précédées de l'appel :


fseek(stream, 0, SEEK_END);

Le descripteur de fichier associé au flux est ouvert comme par un appel à open(2) avec les indicateurs suivants :

Mode fopen() Indicateurs open()
r O_RDONLY
w O_WRONLY | O_CREAT | O_TRUNC
a O_WRONLY | O_CREAT | O_APPEND
r+ O_RDWR
w+ O_RDWR | O_CREAT | O_TRUNC
a+ O_RDWR | O_CREAT | O_APPEND

fdopen()

La fonction fdopen() associe un flux au descripteur de fichier existant, fd. Le mode du flux (l'un des valeurs "r", "r+", "w", "w+", "a", "a+") doit être compatible avec le mode du descripteur de fichier. L'indicateur de position du fichier du nouveau flux est réglé sur celui appartenant à fd, et les indicateurs d'erreur et de fin de fichier sont effacés. Les modes "w" ou "w+" ne provoquent pas de troncature du fichier. Le descripteur de fichier n'est pas dupé et sera fermé lorsque le flux créé par fdopen() sera fermé. Le résultat de l'application de fdopen() à un objet de mémoire partagée est indéfini.

freopen()

La fonction freopen() ouvre le fichier dont le nom est la chaîne pointée par path et associe le flux pointé par stream avec lui. Le flux original (s'il existe) est fermé. L'argument mode est utilisé exactement comme dans la fonction fopen().

Si path est un pointeur nul, freopen() change le mode du flux pour celui spécifié dans mode ; c'est-à-dire que freopen() rouvre le chemin associé au flux. La spécification de ce comportement a été ajoutée dans la norme C99, qui stipule :

Dans ce cas, le descripteur de fichier associé au flux n'a pas besoin d'être fermé si l'appel à freopen() réussit. Il est défini par l'implémentation quelles modifications de mode sont permises (le cas échéant), et dans quelles circonstances.

L'utilisation principale de la fonction freopen() est de changer le fichier associé à un flux texte standard (stderr, stdin, ou stdout).

VALEUR DE RETOUR

En cas de succès, fopen(), fdopen(), et freopen() renvoient un pointeur FILE. Sinon, NULL est renvoyé et errno est défini pour indiquer l'erreur.

ERREURS

EINVAL
Le mode fourni à fopen(), fdopen(), ou freopen() était invalide.

Les fonctions fopen(), fdopen(), et freopen() peuvent également échouer et définir errno pour l'une des erreurs spécifiées pour la routine malloc(3).

La fonction fopen() peut également échouer et définir errno pour l'une des erreurs spécifiées pour la routine open(2).

La fonction fdopen() peut également échouer et définir errno pour l'une des erreurs spécifiées pour la routine fcntl(2).

La fonction freopen() peut également échouer et définir errno pour l'une des erreurs spécifiées pour les routines open(2), fclose(3), et fflush(3).

NOTES

Notes glibc

La bibliothèque C GNU autorise les extensions suivantes pour la chaîne spécifiée dans mode :

c (depuis glibc 2.3.3)
Ne pas faire de l'opération d'ouverture, ou des opérations de lecture et écriture ultérieures, des points d'annulation de thread. Ce drapeau est ignoré pour fdopen().
e (depuis glibc 2.7)
Ouvrir le fichier avec le drapeau O_CLOEXEC. Voir open(2) pour plus d'informations. Ce drapeau est ignoré pour fdopen().
m (depuis glibc 2.3)
Tenter d'accéder au fichier en utilisant mmap(2), plutôt que des appels système d'E/S (read(2), write(2)). Actuellement, l'utilisation de mmap(2) n'est tentée que pour un fichier ouvert en lecture.
x
Ouvrir le fichier exclusivement (comme le drapeau O_EXCL de open(2)). Si le fichier existe déjà, fopen() échoue et définit errno à EEXIST. Ce drapeau est ignoré pour fdopen().

En plus des caractères ci-dessus, fopen() et freopen() prennent en charge la syntaxe suivante dans mode :

,ccs=chaîne

La chaîne donnée est prise comme le nom d'un jeu de caractères codés et le flux est marqué comme orienté vers les caractères larges. Par la suite, les fonctions de conversion internes convertissent les E/S vers et depuis le jeu de caractères chaîne. Si la syntaxe ,ccs=chaîne n'est pas spécifiée, alors l'orientation large du flux est déterminée par la première opération de fichier. Si cette opération est une opération de caractère large, le flux est marqué comme orienté vers les caractères larges, et les fonctions de conversion vers le jeu de caractères codés sont chargées.

BOGUES

Lors de l'analyse des caractères de drapeau individuels dans mode (c'est-à-dire, les caractères précédant la spécification "ccs"), l'implémentation glibc de fopen() et freopen() limite le nombre de caractères examinés dans mode à 7 (ou, avant glibc 2.14, à 6, ce qui n'était pas suffisant pour inclure des spécifications possibles telles que "rb+cmxe"). L'implémentation actuelle de fdopen() analyse au maximum 5 caractères dans mode.
