DESCRIPTIO

N

Cette page manuelle décrit le fichier de configuration de fdm(1). Il définit les comptes à partir desquels récupérer le courrier, un certain nombre de actions possibles à effectuer, et des règles reliant une expression rationnelle à une action. Le fichier est analysé une fois de haut en bas, de sorte que les définitions d'actions et de comptes doivent apparaître avant d'être référencées dans une règle. Les règles sont évaluées de la première à la dernière et (sauf si elles sont annulées par le mot-clé continue) l'évaluation s'arrête à la première

correspondance.

Le fichier a le format suivant

:

Les lignes vides et les lignes commençant par le caractère ‘#’ sont

ignorées.

Les expressions rationnelles et les chaînes doivent être entourées de guillemets doubles. Les caractères spéciaux dans les expressions rationnelles et les chaînes (y compris les mots de passe) doivent être échappés. Notez que cela peut signifier un double échappement dans les expressions

rationnelles.

Indique à fdm(1) de vérifier les certificats SSL pour toutes les connexions SSL.

INCLUSION FICHIERS

D'autres fichiers de configuration peuvent être inclus en utilisant la commande include :

include chemin
 

Le fichier à inclure est recherché d'abord comme un chemin absolu, puis relativement au répertoire contenant le fichier de configuration principal.

MACROS

Les macros peuvent être définies en utilisant la syntaxe suivante :

  • $nom = chaîne
  • %nom = nombre

Les macros sont préfixées par $ pour indiquer une valeur de chaîne et par % pour indiquer une valeur numérique. Une fois définies, une macro peut être utilisée à tout endroit où une chaîne ou un nombre est attendu. Les macros peuvent être intégrées dans des chaînes en entourant leur nom (après le $ ou %) d'accolades, comme suit :

"abc ${macromon} %{uneautremacro} def"

Les mots-clés ifdef, ifndef et endif peuvent être utilisés pour analyser conditionnellement une section du fichier de configuration en fonction de la présence ou de l'absence de la macro donnée. Les blocs ifdef et ifndef peuvent être imbriqués.

COMMANDES SHELL

Le résultat d'une commande shell peut être utilisé à tout moment où une chaîne ou un nombre est attendu en l'entourant de $() ou de %(). Si la première est utilisée, le résultat de la commande est utilisé comme une chaîne ; si la seconde, il est converti en entier. Les commandes shell sont exécutées lors de l'analyse du fichier de configuration.

COMPTES

La commande account est utilisée pour indiquer à fdm(1) de récupérer le courrier d'un compte. La syntaxe est :

account nom [utilisateurs] [désactivé] type [args] [garder]
 

L'argument nom est une chaîne spécifiant un nom pour le compte. L'argument facultatif utilisateurs a la forme suivante :

user utilisateur | users { utilisateur ... }
 

Les deux premières options spécifient un utilisateur ou une liste d'utilisateurs en tant lesquels le courrier doit être délivré lorsqu'une action est exécutée. Si aucun utilisateur n'est spécifié, l'utilisateur par défaut (défini avec set default-user) est utilisé. Les utilisateurs spécifiés dans le cadre de la définition du compte peuvent être remplacés par des arguments similaires aux définitions d'action ou aux règles de correspondance. Si fdm(1) est exécuté en tant que non-root, il exécutera toujours toute action une fois pour chaque utilisateur, mais ne pourra pas basculer vers cet utilisateur, de sorte que l'action sera exécutée plusieurs fois en tant qu'utilisateur actuel.

Le mot-clé désactivé indique à fdm(1) d'ignorer ce compte à moins qu'il ne soit explicitement activé avec une option -a sur la ligne de commande. Si le mot-clé garder est spécifié, tout le courrier collecté à partir de ce compte est conservé (non supprimé) même s'il correspond à une action drop.

Les types de comptes et arguments pris en charge sont :

stdin
Ce type de compte lit le courrier depuis stdin, s'il est connecté à un pipe. Ceci peut être utilisé pour délivrer le courrier de sendmail(8), voir fdm(1) pour les détails.
pop3 serveur hôte [port port] [utilisateur utilisateur] [pass passe] [uniquement] [no-apop] [no-uidl] [starttls] [non-sécurisé]
 
pop3s serveur hôte [port port] [utilisateurpass] [uniquement] [no-apop] [no-verify] [no-uidl] [non-sécurisé]
Ces instructions définissent un compte POP3 ou POP3S. L'élément utilisateurpass a la forme suivante :
[utilisateur utilisateur] [pass passe]
 

Les arguments hôte, utilisateur et passe doivent être des chaînes. Si l'utilisateur ou le mot de passe n'est pas fourni, fdm(1) tente de le rechercher dans le fichier ~/.netrc (voir ftp(1) pour les détails du format du fichier). L'option de port peut être une chaîne qui sera recherchée dans la base de données services(5), ou un nombre. Si elle est omise, le port par défaut (110 pour POP3, 995 pour POP3S) est utilisé.

L'option uniquement prend la forme suivante :

[nouveau-uniquement | ancien-uniquement] cache chemin
 

nouveau-uniquement récupère uniquement le courrier non récupéré précédemment, et ancien-uniquement est l'inverse : il récupère uniquement le courrier qui a déjà été récupéré. Le fichier cache est utilisé pour sauvegarder l'état de la boîte aux lettres POP3. Le drapeau no-apop force fdm(1) à ne pas utiliser la commande POP3 APOP pour l'authentification, et le mot-clé no-verify indique à fdm(1) d'ignorer la validation du certificat SSL pour ce compte. Le mot-clé no-uidl fait que fdm(1) n'utilise pas la commande UIDL pour récupérer les courriers. Ceci est principalement utile pour les serveurs POP3 défectueux.

starttls tente d'utiliser STARTTLS après la connexion.

non-sécurisé permet l'utilisation de protocoles non sécurisés, qui incluent actuellement SSLv2, SSLv3 et TLS1.0.

pop3 pipe commande [utilisateurpass] [uniquement] [no-apop]
Ce type de compte utilise le protocole POP3 transmis via commande, comme ssh(1). Si la commande produit une sortie sur stderr, elle est enregistrée. Pour POP3 sur un pipe, la fourniture d'un nom d'utilisateur et d'un mot de passe n'est pas facultative et ne peut pas être lue à partir de ~/.netrc.

CACHE

S

fdm(1) peut maintenir un fichier cache avec un ensemble de chaînes définies par l'utilisateur. Afin d'utiliser les caches, fdm(1) doit avoir été compilé avec ceux-ci activés. Les caches sont déclarés avec le mot-clé cache

:
cache chemin [expire âge
]
 

Le chemin est l'emplacement du fichier cache. Si le mot-clé expire est spécifié, les éléments du cache sont supprimés après avoir atteint l'âge spécifié. âge peut être donné sans suffixe en secondes, ou suivi de l'un des modificateurs : seconds, hours, minutes, days, months ou years

.

Les caches doivent être déclarés avant d'être utilisés. Les éléments sont ajoutés aux caches à l'aide de l'action add-to-cache, supprimés à l'aide de l'action remove-from-cache, et recherchés à l'aide de la condition in-cache ; voir ci-dessous pour

des informations
sur ceux-ci.

ACTIONS

La commande action est utilisée pour définir des actions. Celles-ci peuvent être spécifiées par nom dans les règles (voir ci-dessous) pour effectuer une action sur un courrier. La syntaxe est :

action nom [utilisateurs] action
 
action nom [utilisateurs] { action ... }
 

Le nom est une chaîne définissant un nom pour l'action. L'argument utilisateurs a la même forme que pour une définition de compte. Le paramètre utilisateur d'une action peut être remplacé dans la règle correspondante.

Les valeurs possibles pour action sont listées ci-dessous. Si plusieurs actions sont spécifiées, elles sont exécutées une fois dans l'ordre spécifié, pour chaque utilisateur.

drop
Écarter le courrier.
keep
Conserver le courrier, ne pas le retirer du compte.
tag chaîne [valeur valeur]
Ceci marque le courrier avec la chaîne, et optionnellement la valeur, qui peut être mise en correspondance en utilisant les conditions tagged ou string.
maildir chemin
Sauvegarder le courrier dans le maildir spécifié par le chemin. Si le maildir ou toute partie de son chemin n'existe pas, il est créé, sauf si l'option no-create est définie.

Le courrier livré à un maildir est marqué avec une étiquette mail_file contenant le chemin complet du fichier de courrier.

mbox chemin [compress]
Ajouter le courrier à la mbox à l'chemin. Si compress est spécifié, fdm(1) ajoutera ‘.gz’ au chemin et tentera d'écrire le courrier en utilisant la compression gzip(1). Si la mbox ou toute partie de son chemin n'existe pas, elle est créée, sauf si l'option no-create est définie.

Le courrier livré à une mbox est marqué avec une étiquette mbox_file contenant le chemin de la mbox.

exec commande
Exécuter la commande.
pipe commande
Transférer le courrier vers la commande. Les commandes exec et pipe sont exécutées en tant qu'utilisateur de la commande.
write chemin
Écrire le courrier dans le chemin.
append chemin
Ajouter le courrier au chemin.
smtp server hôte [port port] [from de] [to à]
Se connecter à un serveur SMTP et tenter d'y livrer le courrier. Si de ou à est spécifié, ils sont transmis au serveur dans les commandes MAIL FROM ou RCPT TO. Sinon, les noms d'utilisateur et d'hôte actuels sont utilisés.
lmtp server chemin | hôte [port port] [from de] [to à]
Se connecter à un serveur LMTP et tenter d'y stocker le courrier. Si un socket UNIX doit être utilisé, le chemin doit être le chemin absolu.

Le port est 24 par défaut. Si de ou à est spécifié, ils sont transmis au serveur dans les commandes MAIL FROM ou RCPT TO. Sinon, les noms d'utilisateur et d'hôte actuels sont utilisés.

rewrite commande
Transférer l'intégralité du courrier via la commande pour générer un nouveau courrier et utiliser ce nouveau courrier pour toute action ou règle ultérieure. Un exemple de l'action rewrite est : 
action "cat" pipe "cat"
action "rewrite" rewrite "sed 's/bob/fred/g'"
# cette règle va réécrire le message
match all action "rewrite" continue
# cette règle va cat le message réécrit
match all action "cat"
add-header nom valeur valeur
Ajouter un en-tête nom avec le contenu valeur.
remove-header nom
 
remove-headers { nom ... }
Supprimer toutes les occurrences d'en-têtes correspondant au modèle fnmatch(3) nom.
stdout
Écrire le courrier sur stdout.
add-to-cache chemin clé clé
Cette action ajoute la chaîne clé au cache spécifié par le chemin. Si la clé existe déjà dans le cache, elle est remplacée.
remove-from-cache chemin clé clé
Supprimer la chaîne clé du cache chemin, si une clé correspondante est présente.
action nom
Ceci invoque une autre action nommée. Un maximum de cinq actions peuvent être appelées en séquence.

RÈGLES

Les règles sont spécifiées en utilisant le mot-clé match. Elle a la forme de base suivante :

match condition [and | or condition ...] [utilisateurs] actions [continue]
 

L'argument condition peut être l'un des suivants :

all
Correspond à tous les courriers.
matched
Correspond uniquement aux courriers qui ont correspondu à une règle précédente et ont été transmis avec continue.
unmatched
L'inverse de matched : correspond uniquement aux courriers qui n'ont correspondu à aucune règle précédente.
account nom | accounts { nom ... }
Correspond uniquement aux courriers récupérés du compte ou des comptes nommés. Les noms de compte peuvent inclure des caractères génériques de type shell pour faire correspondre plusieurs comptes, comme avec les options de ligne de commande -a et -x.
tagged chaîne
Correspond aux courriers marqués avec la chaîne.
[case] regexp [in headers | in body]
Spécifie une expression régulière à comparer avec chaque courrier. Les correspondances de l'expression régulière peuvent être restreintes aux en-têtes ou au corps du message en spécifiant soit in headers soit in body. Le mot-clé case force la correspondance de l'expression régulière à être sensible à la casse : la correspondance par défaut est insensible à la casse.
exec commande [user utilisateur] returns (code de retour, regexp de stdout)

Ces deux conditions exécutent une commande et testent sa valeur de retour et sa sortie. L'argument code de retour est le code de retour numérique attendu et regexp de stdout est une expression régulière à tester contre la sortie de la commande vers stdout. L'un ou l'autre de ces deux arguments peut être omis : s'ils sont tous deux spécifiés, les deux doivent correspondre pour que la condition soit vraie.
