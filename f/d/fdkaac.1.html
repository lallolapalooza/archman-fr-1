NOM

fdkaac - interface en ligne de commande pour l'encodeur libfdk-aac

SYNOPSIS

fdkaac [OPTIONS] [FICHIER]

DESCRIPTION

fdkaac lit de l'audio PCM linéaire au format WAV, PCM brut ou CAF, et l'encode dans un fichier M4A / AAC.

Si le fichier d'entrée est « - », les données sont lues depuis stdin. De même, si le fichier de sortie est « - », les données sont écrites vers stdout si l'un des formats de transport AAC diffusables est sélectionné par -f.

Lorsqu'une entrée CAF et une sortie M4A sont utilisées, les tags du fichier CAF sont copiés dans le M4A résultant.

OPTIONS

-h, --help
Afficher l'aide de la commande
-o <FICHIER>
Nom du fichier de sortie.
-p, --profile <n>
Profil cible (type d'objet audio MPEG4, AOT)
2
MPEG-4 AAC LC (par défaut)
5
MPEG-4 HE-AAC (SBR)
29
MPEG-4 HE-AAC v2 (SBR+PS)
23
MPEG-4 AAC LD
39
MPEG-4 AAC ELD
-b, --bitrate <n>
Débit cible (pour CBR)
-m, --bitrate-mode <n>
Mode de configuration du débit. La valeur de qualité VBR disponible dépend d'autres paramètres tels que le profil, la fréquence d'échantillonnage ou le nombre de canaux.
0
CBR (par défaut)
1-5
VBR (valeur plus élevée -> débit plus élevé)
-w, --bandwidth <n>
Bande passante de fréquence (fréquence de coupure passe-bas) en Hz. Disponible uniquement sur AAC LC.
-a, --afterburner <n>
Configurer le mode afterburner. Lorsqu'il est activé, la qualité est augmentée au détriment d'une charge de calcul supplémentaire.
0
Désactivé
1
Activé (par défaut)
-L, --lowdelay-sbr <n>
Configurer l'activité SBR sur AAC ELD.
-1
Utiliser la configuration automatique ELD SBR
0
Désactiver SBR sur ELD (par défaut)
1
Activer SBR sur ELD
-s, --sbr-ratio <n>
Contrôle l'activation du SBR sous-échantillonné.
0
Utiliser la valeur par défaut de la bibliothèque (par défaut)
1
Utiliser le SBR sous-échantillonné (par défaut pour ELD+SBR)
2
Utiliser le SBR double débit (par défaut pour HE-AAC)

Le SBR double débit est ce qui est normalement utilisé pour le HE-AAC, où l'AAC est encodé à la moitié de la fréquence d'échantillonnage du SBR, d'où le nom « double débit ». D'autre part, le SBR sous-échantillonné utilise la même fréquence d'échantillonnage pour l'AAC et le SBR (débit unique), par conséquent le SBR sous-échantillonné consomme généralement plus de débit.

Le SBR sous-échantillonné est une fonctionnalité nouvellement introduite dans la bibliothèque d'encodeur FDK version 3.4.12. Lorsque libfdk-aac du système ne le prend pas en charge, le SBR double débit sera utilisé. Lorsqu'il est disponible, le SBR double débit est la valeur par défaut pour le HE-AAC et le SBR sous-échantillonné est la valeur par défaut pour ELD+SBR.

Notez que le HE-AAC sous-échantillonné n'est pas aussi courant que le double débit. Lorsque le HE-AAC sous-échantillonné est sélectionné, fdkaac est forcé de choisir une signalisation SBR hiérarchique explicite, qu'au moins iTunes n'accepte pas.

M4A (par défaut)
1
ADIF
2
ADTS
6
LATM MCP=1
7
LATM MCP=0
10
LOAS/LATM (LATM dans LOAS)
-C, --adts-crc-check
Ajouter une protection CRC sur l'en-tête ADTS.
-h, --header-period <n>
Période de répétition StreamMuxConfig/PCE dans la couche de transport.
-G, --gapless-mode <n>
Méthode pour déclarer la quantité de retard d'encodeur (et de remplissage) dans le conteneur M4A. Ces valeurs sont obligatoires pour une lecture sans interruption correcte côté lecteur.
0
iTunSMPB (par défaut)
1
Standard ISO (edts et sgpd)
2
Les deux
--include-sbr-delay
Lorsqu'il est spécifié, compter le retard du décodeur SBR dans le retard d'encodeur.

Ceci n'est pas compatible avec iTunes et entraînera un problème de lecture sans interruption sur un décodeur LC uniquement, mais c'est le comportement par défaut de la bibliothèque FDK.

Le fait de compter ou non le retard du décodeur SBR dans le retard d'encodeur entraîne une incompatibilité de lecture sans interruption. Vous devriez choisir celui qui fonctionnera pour votre lecteur préféré.

Cependant, il vaut mieux ne pas choisir SBR du tout si vous voulez une lecture sans interruption. LC n'a pas de tels problèmes.

-I, --ignorelength
Ignorer le champ de longueur du bloc de données dans le fichier WAV d'entrée.
-S, --silent
Ne pas imprimer les messages de progression.
--moov-before-mdat
Placer le bloc moov avant le bloc mdat dans le conteneur M4A. Cette option peut être importante pour certains lecteurs matériels, qui sont connus pour refuser le bloc moov placé après le bloc mdat.
-R, --raw
Considérer l'entrée comme du PCM brut.
--raw-channels <n>
Spécifier le nombre de canaux de l'entrée brute (par défaut : 2)
--raw-rate <n>
Spécifier la fréquence d'échantillonnage de l'entrée brute (par défaut : 44100)
--raw-format <spec>
Spécifier le format d'échantillon de l'entrée brute (par défaut : « S16L »). Spec est comme suit (insensible à la casse) :
1er caractère -- type d'échantillon
S (igné) | U (nsigné) | F (loat)
2ème partie (en chiffres)
bits par canal
Dernier caractère -- ordre des octets (peut être omis)
L (ittle, par défaut) | B (ig)
--title <chaîne>
Définir le tag de titre.
--artist <chaîne>
Définir le tag d'artiste.
--album <chaîne>
Définir le tag d'album.
--genre <chaîne>
Définir le tag de genre.
--date <chaîne>
Définir le tag de date.e tag.
--composer <chaîne>
Définit la balise du compositeur.
--grouping <chaîne>
Définit la balise de regroupement.
--comment <chaîne>
Définit la balise de commentaire.
--album-artist <chaîne>
Définit la balise de l'artiste de l'album.
--track <nombre[/total]>
Définit la balise de piste, avec ou sans le nombre total de pistes.
--disk <nombre[/total]>
Définit la balise de disque, avec ou sans le nombre total de disques.
--tempo <n>
Définit la balise de tempo (BPM).
--tag <fcc>:<valeur>
Définit une balise prédéfinie iTunes avec une clé fourcc et une valeur explicites. Voir https://code.google.com/p/mp4v2/wiki/iTunesMetadata pour les clés prédéfinies connues. Vous pouvez omettre le premier caractère de fcc s'il s'agit du signe copyright.
--tag-from-file <fcc>:<nom_fichier>
Identique à --tag, mais utilise le contenu du fichier comme valeur de la balise.
--long-tag <nom>:<valeur>
Définit une balise arbitraire comme métadonnée personnalisée iTunes. Stocké dans le champ com.apple.iTunes.
--tag-from-json <nom_fichier[?notation_pointillée]>
Lit les balises depuis un fichier JSON. Par défaut, les balises sont supposées être des enfants directs de l'objet racine dans le JSON. Vous pouvez éventuellement spécifier une notation pointillée arbitraire pour localiser l'objet contenant les balises.

EXEMPLES

Encode un fichier WAV en fichier M4A. MPEG4 AAC LC, qualité VBR 3 :

fdkaac -m3 foo.wav

Encode un fichier WAV en fichier M4A. MPEG4 HE-AAC, débit de 64 kbps :

fdkaac -p5 -b64 foo.wav

Piping depuis ffmpeg (vous avez besoin d'une version prenant en charge la sortie CAF) :

ffmpeg -i foo.flac -f caf - | fdkaac -b128 - -o foo.m4a

Importation de balises via json :

ffprobe -v 0 -of json -show_format foo.flac >foo.json
flac -dc foo.flac | \
fdkaac - -ox.m4a -m2 --import-tag-from-json=foo.json?format.tags

NOTES

Les formats entiers jusqu'à 32 bits ou flottants 64 bits sont pris en charge en entrée. Cependant, la bibliothèque FDK est implémentée sur la base de calculs en virgule fixe et ne prend en charge que le PCM entier 16 bits. Par conséquent, attention au clipping. Vous pourriez vouloir effectuer un dithering/bruitage préalable lorsque votre entrée a une résolution plus élevée.

Les dispositions de canaux suivantes sont prises en charge par l'encodeur.

1 canal
C
2 canaux
L R
3 canaux
C L R
4 canaux
C L R Cs
5 canaux
C L R Ls Rs
5.1 canaux
C L R Ls Rs LFE
7.1 canaux (avant)
C Lc Rc L R Ls Rs LFE
7.1 canaux (arrière)
C L R Ls Rs Rls Rrs LFE
