fsync(2) Manuel des appels système fsync(2)

NOM

fsync, fdatasync - synchroniser l'état en mémoire d'un fichier avec le périphérique de stockage

BIBLIOTHÈQUE

Bibliothèque C standard (libc,-lc)

SYNOPSIS

#include <unistd.h>
int fsync(int fd);
int fdatasync(int fd);
Exigences des macros de test de fonctionnalités pour glibc (voir feature_test_macros(7)) :
fsync() :
    glibc 2.16 et versions ultérieures :
        Aucune macro de test de fonctionnalités n'a besoin d'être définie
    glibc jusqu'à et y compris 2.15 :
        _BSD_SOURCE || _XOPEN_SOURCE
            || /* Depuis glibc 2.8 : */ _POSIX_C_SOURCE >= 200112L

fdatasync() :

    _POSIX_C_SOURCE >= 199309L || _XOPEN_SOURCE >= 500

DESCRIPTION

fsync() transfère (« vide ») toutes les données modifiées en mémoire (c'est-à-dire les pages modifiées du cache tampon) du fichier auquel fait référence le descripteur de fichier fd vers le disque (ou un autre périphérique de stockage permanent) afin que toutes les informations modifiées puissent être récupérées même si le système plante ou redémarre. Cela inclut l'écriture directe ou le vidage d'un cache de disque s'il est présent. L'appel se bloque jusqu'à ce que le périphérique signale que le transfert est terminé.

En plus de vider les données du fichier, fsync() vide également les métadonnées associées au fichier (voir inode(7)).

Appeler fsync() ne garantit pas nécessairement que l'entrée dans le répertoire contenant le fichier a également atteint le disque. Pour cela, un appel explicite à fsync() sur un descripteur de fichier pour le répertoire est également nécessaire.

fdatasync() est similaire à fsync(), mais ne vide pas les métadonnées modifiées à moins que ces métadonnées ne soient nécessaires pour permettre à une récupération de données ultérieure d'être correctement gérée. Par exemple, les changements de st_atime ou st_mtime (respectivement, heure du dernier accès et heure de la dernière modification ; voir inode(7)) ne nécessitent pas de vidage car ils ne sont pas nécessaires pour qu'une lecture de données ultérieure soit correctement gérée. D'un autre côté, un changement de la taille du fichier (st_size, comme réalisé par par exemple ftruncate(2)), nécessiterait un vidage des métadonnées.

Le but de fdatasync() est de réduire l'activité du disque pour les applications qui n'ont pas besoin que toutes les métadonnées soient synchronisées avec le disque.

VALEUR RENVOYÉE

En cas de succès, ces appels système renvoient zéro. En cas d'erreur, -1 est renvoyé, et errno est défini pour indiquer l'erreur.

ERREURS

EBADF
fd n'est pas un descripteur de fichier ouvert valide.
EINTR
La fonction a été interrompue par un signal ; voir signal(7).
EIO
Une erreur s'est produite lors de la synchronisation. Cette erreur peut concerner des données écrites via un autre descripteur de fichier sur le même fichier. Depuis Linux 4.13, les erreurs de remise en cache seront signalées à tous les descripteurs de fichier qui auraient pu écrire les données qui ont déclenché l'erreur. Certains systèmes de fichiers (par ex., NFS) gardent une trace précise des données provenant de quel descripteur de fichier, et donnent des rapports plus précis. D'autres systèmes de fichiers (par ex., la plupart des systèmes de fichiers locaux) signaleront les erreurs à tous les descripteurs de fichier qui étaient ouverts sur le fichier lorsque l'erreur a été enregistrée.
ENOSPC
L'espace disque a été épuisé lors de la synchronisation.
EROFS
EINVAL
fd est lié à un fichier spécial (par ex., un tube, une FIFO ou un socket) qui ne prend pas en charge la synchronisation.
ENOSPC
EDQUOT
fd est lié à un fichier sur NFS ou un autre système de fichiers qui n'alloue pas d'espace au moment d'un appel système write(2) , et une écriture précédente a échoué en raison d'un espace de stockage insuffisant.

VERSIONS

Sur les systèmes POSIX où fdatasync() est disponible, _POSIX_SYNCHRONIZED_IO est défini dans <unistd.h> à une valeur supérieure à 0. (Voir aussi sysconf(3).)

NORMES

POSIX.1-2024.

HISTORIQUE

POSIX.1-2001, 4.2BSD.

Dans Linux 2.2 et les versions antérieures, fdatasync() est équivalent à fsync(), et n'a donc aucun avantage de performance.

Les fsync() implémentations dans les noyaux plus anciens et les systèmes de fichiers moins utilisés ne savent pas comment vider les caches de disque. Dans ces cas, les caches de disque doivent être désactivés à l'aide de hdparm(8) ou sdparm(8) pour garantir un fonctionnement sûr.

Sous AT&T UNIX System V Release 4 fd doit être ouvert en écriture. Cela est en soi incompatible avec l'interface BSD originale et interdit par POSIX, mais survit néanmoins dans HP-UX et AIX.
