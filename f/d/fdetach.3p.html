FDETACH(3P) Manuel du programmeur POSIX FDETACH(3P)

PROLOGUE

Cette page manuelle fait partie du Manuel du programmeur POSIX. L'implémentation Linux de cette interface peut différer (consultez la page man correspondante de Linux pour plus de détails sur le comportement de Linux), ou l'interface peut ne pas être implémentée sur Linux.

NOM

fdetach — détacher un nom d'un descripteur de fichier basé sur STREAMS (STREAMS)

SYNOPSISSE

#include <stropts.h>
int fdetach(const char *path);

DESCRIPTION

La fonction fdetach() doit détacher un fichier basé sur STREAMS du fichier auquel il avait été attaché par un appel précédent à fattach(). L'argument path pointe vers le chemin du nom du fichier STREAMS attaché. Le processus doit disposer des privilèges appropriés ou être le propriétaire du fichier. Un appel réussi à fdetach() doit faire en sorte que tous les chemins de nom qui nommaient le fichier STREAMS attaché nomment à nouveau le fichier auquel le fichier STREAMS était attaché. Toutes les opérations ultérieures sur path doivent porter sur le fichier sous-jacent et non sur le fichier STREAMS.

Toutes les descriptions de fichier ouvertes établies pendant que le fichier STREAMS était attaché au fichier référencé par path doivent toujours se référer au fichier STREAMS après que fdetach() a pris effet.

S'il n'y a pas de descripteurs de fichier ouverts ni d'autres références au fichier STREAMS, alors un appel réussi à fdetach() doit être équivalent à effectuer le dernier close() sur le fichier attaché.

VALEUR RENVOYÉE

Lors de l'achèvement réussi, fdetach() doit renvoyer 0 ; sinon, elle doit renvoyer -1 et définir errno pour indiquer l'erreur.

ERREURS

La fonction fdetach() doit échouer si :

EACCES
La permission de recherche est refusée sur un composant du préfixe de chemin.
EINVAL
L'argument path nomme un fichier qui n'est pas actuellement attaché.
ELOOP
Une boucle existe dans les liens symboliques rencontrés lors de la résolution de l'argument path .
ENAMETOOLONG

La longueur d'un composant d'un chemin de nom est plus longue que {NAME_MAX}.
ENOENT
Un composant de path ne nomme pas un fichier existant, ou path est une chaîne vide.
ENOTDIR
Un composant du préfixe de chemin nomme un fichier existant qui n'est ni un répertoire ni un lien symbolique vers un répertoire, ou l'argument path contient au moins un caractère non-<slash> et se termine par un ou plusieurs caractères <slash> finaux et le dernier composant du chemin de nom nomme un fichier existant qui n'est ni un répertoire ni un lien symbolique vers un répertoire.
EPERM
L'ID utilisateur effectif n'est pas le propriétaire de path et le processus ne dispose pas des privilèges appropriés.

La fonction fdetach() peut échouer si :

ELOOP
Plus de {SYMLOOP_MAX} liens symboliques ont été rencontrés lors de la résolution de l'argument path .
ENAMETOOLONG

La longueur d'un chemin de nom dépasse {PATH_MAX}, ou la résolution du chemin de nom d'un lien symbolique a produit un résultat intermédiaire dont la longueur dépasse {PATH_MAX}.

Les sections suivantes sont informatives.

EXEMPLES

Détacher un fichier

L'exemple suivant détache le fichier basé sur STREAMS /tmp/named-STREAM du fichier auquel il avait été attaché par un appel précédent réussi à fattach(). Les appels ultérieurs pour ouvrir ce fichier se réfèrent au fichier sous-jacent, et non au fichier STREAMS.

#include <stropts.h>
...
    char *pathname = "/tmp/named-STREAM";
    int ret;
    ret = fdetach(pathname);

PERSPECTIVES

La fonction fdetach() peut être supprimée dans une version future.
