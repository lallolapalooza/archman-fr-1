DESCRIPTIO

N

AVERTISSEMENT : select() ne peut surveiller que les numéros de descripteurs de fichiers inférieurs à FD_SETSIZE (1024) — une limite déraisonnablement basse pour de nombreuses applications modernes — et cette limitation ne changera pas. Toutes les applications modernes devraient plutôt utiliser poll(2) ou epoll(7), qui ne souffrent pas de cette

limitation.

select() permet à un programme de surveiller plusieurs descripteurs de fichiers, en attendant qu'un ou plusieurs descripteurs de fichiers deviennent « prêts » pour une certaine classe d'opération d'E/S (par exemple, lecture possible). Un descripteur de fichiers est considéré comme prêt s'il est possible d'effectuer une opération d'E/S correspondante (par exemple, read(2), ou un write(2) suffisamment petit) sans

bloquer.

fd_se

t

Un type de structure qui peut représenter un ensemble de descripteurs de fichiers. Selon POSIX, le nombre maximal de descripteurs de fichiers dans une structure fd_set est la valeur de la macro FD_SETSIZ

fichiers

Les arguments principaux de select() sont trois « ensembles » de descripteurs de fichiers (déclarés avec le type fd_set), qui permettent à l'appelant d'attendre trois classes d'événements sur l'ensemble spécifié de descripteurs de fichiers. Chacun des arguments fd_set peut être spécifié comme NULL si aucun descripteur de fichier n'est à surveiller pour la classe d'événements

correspondante.

Notez bien : au retour, chacun des ensembles de descripteurs de fichiers est modifié sur place pour indiquer quels descripteurs de fichiers sont actuellement « prêts ». Ainsi, si vous utilisez select() dans une boucle, les ensembles doivent être réinitialisés avant chaque

appel.

pselect(

)

L'appel système pselect() permet à une application d'attendre en toute sécurité qu'un descripteur de fichier devienne prêt ou qu'un signal soit

capté.

Le fonctionnement de select() et pselect() est identique, à part ces trois différences

:
•
select() utilise un délai d'attente qui est une struct timeval (avec secondes et microsecondes), tandis que pselect() utilise une struct timespec (avec secondes et nanosecondes)
.
•
select() peut mettre à jour l'argument timeout pour indiquer combien de temps restait. pselect() ne modifie pas cet
argument.
•
select() n'a pas d'argument sigmask et se comporte comme pselect() appelé avec sigmas
k NU
LL.

sigmask est un pointeur vers un masque de signal (voir sigprocmask(2)) ; s'il n'est pas NULL, alors pselect() remplace d'abord le masque de signal courant par celui désigné par sigmask, puis exécute la fonction « select », et restaure ensuite le masque de signaux d'origine. (Si sigmask est NULL, le masque de signaux n'est pas modifié pendant l'appel à pselect().)

Autre que la différence de précision de l'argument timeout, l'appel pselect() suivant :


ready = pselect(nfds, &readfds, &writefds, &exceptfds,
                timeout, &sigmask);

est équivalent à l'exécution *atomique* des appels suivants :


sigset_t origmask;
pthread_sigmask(SIG_SETMASK, &sigmask, &origmask);
ready = select(nfds, &readfds, &writefds, &exceptfds, timeout);
pthread_sigmask(SIG_SETMASK, &origmask, NULL);

La raison pour laquelle pselect() est nécessaire est que si l'on souhaite attendre soit un signal, soit qu'un descripteur de fichier devienne prêt, un test atomique est nécessaire pour éviter les conditions de course. (Supposons que le gestionnaire de signaux définisse un drapeau global et revienne. Un test de ce drapeau global suivi d'un appel à select() pourrait alors se bloquer indéfiniment si le signal arrivait juste après le test mais juste avant l'appel. En revanche, pselect() permet de bloquer d'abord les signaux, de traiter les signaux arrivés, puis d'appeler pselect() avec le sigmask désiré, évitant ainsi la course.)

Le timeout

L'argument timeout pour select() est une structure du type suivant :


struct timeval {
    time_t      tv_sec;         /* secondes */
    suseconds_t tv_usec;        /* microsecondes */
};

L'argument correspondant pour pselect() est une structure timespec(3).

Sous Linux, select() modifie timeout pour refléter le temps passé sans dormir ; la plupart des autres implémentations ne le font pas. (POSIX.1 autorise l'un ou l'autre comportement.) Cela pose des problèmes tant lorsque le code Linux qui lit timeout est porté sur d'autres systèmes d'exploitation, que lorsque du code est porté sous Linux qui réutilise une struct timeval pour plusieurs appels à select() dans une boucle sans la réinitialiser. Considérez timeout comme indéfini après le retour de select().

VALEUR DE RETOUR

En cas de succès, select() et pselect() renvoient le nombre de descripteurs de fichiers contenus dans les trois ensembles de descripteurs retournés (c'est-à-dire le nombre total de bits définis dans readfds, writefds, exceptfds). La valeur de retour peut être nulle si le délai d'attente a expiré avant que des descripteurs de fichiers ne deviennent prêts.

En cas d'erreur, -1 est retourné, et errno est défini pour indiquer l'erreur ; les ensembles de descripteurs de fichiers ne sont pas modifiés, et timeout devient indéfini.

ERREURS

EBADF
Un descripteur de fichier invalide a été fourni dans l'un des ensembles. (Peut-être un descripteur de fichier déjà fermé, ou sur lequel une erreur s'est produite.) Cependant, voir BUGS.
EINTR
Un signal a été intercepté ; voir signal(7).
EINVAL
nfds est négatif ou dépasse la limite de ressources RLIMIT_NOFILE (voir getrlimit(2)).
EINVAL
La valeur contenue dans timeout est invalide.
ENOMEM
Impossible d'allouer de la mémoire pour les tables internes.

VERSIONS

Sur certains autres systèmes UNIX, select() peut échouer avec l'erreur EAGAIN si le système ne parvient pas à allouer les ressources internes du noyau, plutôt qu'avec ENOMEM comme le fait Linux. POSIX spécifie cette erreur pour poll(2), mais pas pour select(). Les programmes portables pourraient souhaiter vérifier EAGAIN et boucler, tout comme avec EINTR.

NOTES

L'en-tête suivant fournit également le type fd_set : <sys/time.h>.

Une fd_set est un tampon de taille fixe. L'exécution de FD_CLR() ou FD_SET() avec une valeur de fd négative ou égale ou supérieure à FD_SETSIZE entraînera un comportement indéfini. De plus, POSIX exige que fd soit un descripteur de fichier valide.

L'opération de select() et pselect() n'est pas affectée par le drapeau O_NONBLOCK.

L'astuce du pipe auto-géré

Sur les systèmes qui n'ont pas pselect(), un piégeage fiable (et plus portable) des signaux peut être réalisé en utilisant l'astuce du pipe auto-géré. Dans cette technique, un gestionnaire de signaux écrit un octet dans un pipe dont l'autre extrémité est surveillée par select() dans le programme principal. (Pour éviter de bloquer éventuellement lors de l'écriture dans un pipe potentiellement plein ou de la lecture d'un pipe potentiellement vide, des E/S non bloquantes sont utilisées lors de la lecture et de l'écriture dans le pipe.)

Émulation de usleep(3)

Avant l'avènement de usleep(3), certains codes utilisaient un appel à select() avec les trois ensembles vides, nfds à zéro, et un timeout non NULL comme moyen relativement portable de dormir avec une précision inférieure à la seconde.

Correspondance entre les notifications de select() et poll()

Dans le code source du noyau Linux, nous trouvons les définitions suivantes qui montrent la correspondance entre les notifications de lecture, d'écriture et de condition exceptionnelle de select() et les notifications d'événement fournies par poll(2) et epoll(7) :


#define POLLIN_SET  (EPOLLRDNORM | EPOLLRDBAND | EPOLLIN |
                     EPOLLHUP | EPOLLERR)
                   /* Prêt pour la lecture */
#define POLLOUT_SET (EPOLLWRBAND | EPOLLWRNORM | EPOLLOUT |
                     EPOLLERR)
                   /* Prêt pour l'écriture */
#define POLLEX_SET  (EPOLLPRI)
                   /* Condition exceptionnelle */

Applications multithreadées

Si un descripteur de fichier surveillé par select() est fermé dans un autre thread, le résultat n'est pas spécifié. Sur certains systèmes UNIX, select() se débloque et retourne, avec une indication que le descripteur de fichier est prêt (une opération d'E/S ultérieure échouera probablement avec une erreur, à moins qu'un autre processus ne rouvre le descripteur de fichier entre le moment où select() est retourné et l'exécution de l'opération d'E/S). Sur Linux (et certains autres systèmes), la fermeture du descripteur de fichier dans un autre thread n'a aucun effet sur select(). En résumé, toute application qui repose sur un comportement spécifique dans ce scénario doit être considérée comme erronée.

Différences bibliothèque C/noyau

Le noyau Linux autorise des ensembles de descripteurs de fichiers de taille arbitraire, déterminant la longueur des ensembles à vérifier à partir de la valeur de nfds. Cependant, dans l'implémentation glibc, le type fd_set est de taille fixe. Voir aussi BUGS.

L'interface pselect() décrite dans cette page est implémentée par glibc. L'appel système Linux sous-jacent est nommé pselect6(). Cet appel système a un comportement quelque peu différent de la fonction wrapper glibc.

L'appel système Linux pselect6() modifie son argument timeout. Cependant, la fonction wrapper glibc masque ce comportement en utilisant une variable locale pour l'argument timeout qui est passé à l'appel système. Ainsi, la fonction glibc pselect() ne modifie pas son argument timeout ; c'est le comportement requis par POSIX.1-2001.

Le dernier argument de l'appel système pselect6() n'est pas un pointeur sigset_t *, mais est plutôt une structure de la forme :


struct {
    const kernel_sigset_t *ss;   /* Pointeur vers l'ensemble de signaux */
    size_t ss_len;               /* Taille (en octets) de l'objet
                                    pointé par 'ss' */
};

Cela permet à l'appel système d'obtenir à la fois un pointeur vers l'ensemble de signaux et sa taille, tout en tenant compte du fait que la plupart des architectures supportent un maximum de 6 arguments à un appel système. Voir sigprocmask(2) pour une discussion sur la différence entre la notion de noyau et de libc concernant l'ensemble de signaux.

Détails historiques glibc

glibc 2.0 a fourni une version incorrecte de pselect() qui ne prenait pas d'argument sigmask.

De glibc 2.1 à glibc 2.2.1, il fallait définir _GNU_SOURCE pour obtenir la déclaration de pselect() depuis <sys/select.h>.

BUGS

POSIX autorise une implémentation à définir une limite supérieure, annoncée via la constante FD_SETSIZE, sur la taille des ensembles de descripteurs de fichiers.

NOTES

La plage de descripteurs de fichiers qui peuvent être spécifiés dans un ensemble de descripteurs de fichiers. Le noyau Linux n'impose aucune limite fixe, mais l'implémentation glibc fait de fd_set un type de taille fixe, avec FD_SETSIZE défini sur 1024, et les macros FD_*() opérant selon cette limite. Pour surveiller des descripteurs de fichiers supérieurs à 1023, utilisez plutôt poll(2) ou epoll(7).

L'implémentation des arguments fd_set en tant qu'arguments valeur-résultat est une erreur de conception qui est évitée dans poll(2) et epoll(7).

Selon POSIX, select() doit vérifier tous les descripteurs de fichiers spécifiés dans les trois ensembles de descripteurs de fichiers, jusqu'à la limite nfds-1. Cependant, l'implémentation actuelle ignore tout descripteur de fichier dans ces ensembles qui est supérieur au numéro de descripteur de fichier maximum que le processus a actuellement ouvert. Selon POSIX, tout descripteur de fichier de ce type spécifié dans l'un des ensembles devrait entraîner l'erreur EBADF.

À partir de glibc 2.1, glibc a fourni une émulation de pselect() implémentée en utilisant sigprocmask(2) et select(). Cette implémentation restait vulnérable à la condition de course même que pselect() a été conçu pour empêcher. Les versions modernes de glibc utilisent l'appel système pselect() (sans condition de course) sur les noyaux où il est fourni.

Sous Linux, select() peut signaler un descripteur de fichier de socket comme étant "prêt en lecture", tout en bloquant néanmoins une lecture ultérieure. Cela pourrait par exemple se produire lorsque des données sont arrivées mais que, lors de l'examen, elles ont une mauvaise somme de contrôle et sont rejetées. Il peut y avoir d'autres circonstances dans lesquelles un descripteur de fichier est faussement signalé comme prêt. Il peut donc être plus sûr d'utiliser O_NONBLOCK sur les sockets qui ne devraient pas bloquer.

Sous Linux, select() modifie également timeout si l'appel est interrompu par un gestionnaire de signaux (c'est-à-dire le retour d'erreur EINTR). Ceci n'est pas autorisé par POSIX.1. L'appel système Linux pselect() a le même comportement, mais l'enrobage glibc cache ce comportement en copiant en interne le timeout vers une variable locale et en passant cette variable à l'appel système.

EXEMPLES

#include <stdio.h>
#include <stdlib.h>
#include <sys/select.h>
#include <sys/time.h>
int
main(void)
{
    int             retval;
    fd_set          rfds;
    struct timeval  tv;
    /* Surveille stdin (fd 0) pour voir s'il y a des entrées.  */
    FD_ZERO(&rfds);
    FD_SET(0, &rfds);
    /* Attend jusqu'à cinq secondes.  */
    tv.tv_sec = 5;
    tv.tv_usec = 0;
    retval = select(1, &rfds, NULL, NULL, &tv);
    /* Ne vous fiez pas à la valeur de tv maintenant ! */
    if (retval == -1)
        perror("select()");
    else if (retval)
        printf("Des données sont disponibles maintenant.\n");
        /* FD_ISSET(0, &rfds) sera vrai.  */
    else
        printf("Aucune donnée dans les cinq secondes.\n");
    exit(EXIT_SUCCESS);
}
