Gestion des

exceptions

val protect : finally:(unit -> unit) -> (unit -> 'a) ->

'a

protect ~finally work invoque work () puis finally () avant que work () ne renvoie sa valeur ou une exception. Dans ce dernier cas, l'exception est relancée après finally () . Si finally () lève une exception, alors l'exception Fun.Finally_raised est levée à la

place.

protect peut être utilisé pour faire respecter des invariants locaux que work () se termine normalement ou lève une exception. Cependant, cela ne protège pas contre les exceptions inattendues levées à l'intérieur de finally () telles que Out_of_memory , Stack_overflow , ou les exceptions asynchrones levées par les gestionnaires de signaux (par ex. Sys.Break )

.

Remarque : il s'agit d'une erreur de programmation si d'autres types d'exceptions sont levés par finally , car toute exception levée dans work () sera perdue en cas d'exception Fun.Finally_raised . Par conséquent, il faut s'assurer de les traiter à l'intérieur du

finally.

exception Finally_raised of ex

n

Finally_raised exn est levée par protect ~finally work lorsque finally lève une exception exn . Cette exception désigne soit une exception inattendue, soit une erreur de programmation. En règle générale, on ne doit pas attraper une exception Finally_raised sauf dans le cadre

d'un gestion
naire catch-all.

Fun.combinators fournissent une façon légère et parfois plus lisible de créer des fonctions anonymes, mieux utilisées comme arguments de courte durée plutôt que comme définitions autonomes. Les exemples ci-dessous le démontreront principalement avec le module

Li
st.

[id

]

List.init avec l'index

lui-même 
  # List.init 3 Fun.id;;
  - : int list = [0; 1; 2]

Utiliser List.filter_map sur une liste int option pour filtrer les éléments Option.t.

None 
  # List.filter_map Fun.id [None; Some 2; Some 3; None; Some 5];;
  - : int list = [2; 3; 5]

Distribuer conditionnellement des fonctions de type foo -> foo ou les prendre comme arguments est un autre endroit où id peut être utile. Considérons une fonction de journalisation primitive qui imprime une chaîne mais donne à son utilisateur la possibilité de préformatage de la chaîne avant l'impression, par ex. pour insérer un

horodatage 
  let log ?(preformat : string -> string = Fun.id) message =
    print_endline (preformat message)

Chaque fois que nous pouvons construire des fermetures, id est souvent utilisé pour le cas de base comme une opération sans effet. Considérons une fonction qui enchaîne une liste de fonctions unaires

: 
  let rec chain = function
    | [] -> Fun.id
    | f :: fs -> fun x -> f (chain fs x)

[const

]

List.init une liste de

zéros 
  # List.init 3 (Fun.const 0);;
  - : int list = [0; 0; 0]

Un prédicat acceptant tout qui pourrait être passé à n'importe quelle fonction de filtrage, par ex. List.filter pour désactiver le filtrage et récupérer toutes les

valeurs 
  # List.filter (Fun.const true) [1; 2; 3];;
  - : int list = [1; 2; 3]

Notez que l'application de const (...) évalue l'expression (...) une fois, et renvoie une fonction qui ne contient que le résultat de cette évaluation. Pour le démontrer, considérons si (...) était un appel à Random.bool ()

:

List.init n (Fun.const (Random.bool())) pour tout n > 0 aura exactement deux résultats

possibles,

- [true; true; ...;

true]

- [false; false; ...;

false]

alors que List.init n (fun _ -> Random.bool()) aura 2^n résultats possibles, car l'effet de hasard est effectué pour chaque

élément.

Pour des utilisations plus réalistes, considérons String.spellcheck avec une distance maximale constante de 2, au lieu de la distance maximale variable par

défaut 
  let spellcheck known_words word =
    let dict_iter yield = List.iter yield known_words in
    String.spellcheck ~max_dist:(Fun.const 2) dict_iter word

[flip

]

Utiliser flip pour inverser le comparateur passé à List.sort , qui trie dans l'ordre

inverse 
  # List.sort (Fun.flip Int.compare) [5; 3; 9; 0; 1; 6; 8];;
  - : int list = [9; 8; 6; 5; 3; 1; 0]

Inverser une liste en accumulant une nouvelle liste avec List.fold_left , qui attend que l'accumulateur soit le premier argument de la fonction qui lui est passée. Nous passons List.cons qui a la liste comme second argument, donc flip est utile

ici 
  # List.fold_left (Fun.flip List.cons) [] [1; 2; 3];;
  - : int list = [3; 2; 1]

Intéressant, flip peut fonctionner avec des fonctions qui ne sont pas binaires, en inversant les deux premiers arguments et en laissant les autres dans l'ordre. C'est parce qu'une fonction qui prend n+2 arguments est, conceptuellement, une fonction binaire qui renvoie une fonction qui prend n arguments. Étant donné une fonction f : a -> b -> c -> d

:

- flip f aura le type b -> a -> c ->

d

- fun x -> flip (f x) aura le type a -> c -> b ->

d

Utiliser flip avec des fonctions non binaires de cette manière est déconseill

é, en raison de son impact négatif s
ur la lisibilité et le raisonnement.

[negate

]

Principalement utilisé pour inverser un prédicat dans une fonction qui en attend un, comme List.find_all et des fonctions

similaires

Trouver toutes les listes qui ne sont pas vides en utilisant List.

is_empty 
  # List.find_all (Fun.negate List.is_empty) [[0]; [1; 2; 3]; []; [4; 5]];;
  - : int list list = [[0]; [1; 2; 3]; [4; 5]]

À partir d'une liste de chemins donnée, trouver tous les chemins qui ne sont pas occupés en utilisant Sys.

file_exists 
  # List.find_all (Fun.negate Sys.file_exists);;
  - : string list -> string list = <fun>

[compose

]

List.map sur des éléments paires avec une fonction sur le second

élément 
  # List.map (Fun.compose String.length snd) [1, "one"; 2, "two"; 3, "three"];;
  - : int list = [3; 3; 5]

Une implémentation potentielle de Fun.

negate 
  let negate f = Fun.compose not f

À partir de Fun.hid , compose aurait pu être utilisé dans la branche

récursive 
  let rec chain = function
    | [] -> Fun.id
    | f :: fs -> Fun.compose f (chain fs)
Ou encore plus concisément 
  let chain fs = List.fold_right Fun.compose fs Fun.id

À partir de Fun.hflip , compose et flip pourraient être utilisés pour condenser la définition de la fonction afin qu'elle

devienne 
  # Fun.compose
      (String.spellcheck ~max_dist:(Fun.const 2))
      (Fun.flip List.iter)
    ;;
  - : string list -> string -> string list = <fun>

Comme on peut le voir ici, cela impacte fortement la lisibilité et la capacité à raisonner à propos de la fonction. Ni String.spellcheck ni Fun.flip ne sont unaires, il y a donc une interaction non triviale avec l'application partielle dans cette

définition.

L'utilisation intensive de ces combinateurs en OCaml est généralemen

t découragée, non seulement parce qu'ils peuvent rapidement impa
cter la lisibilité et le raisonnement, mais aussi parce que les f
onctions produites sont souvent sous forme de valeur, et donc soumis
es à la Restriction de Valeur (voir la section 6.1.2 du manuel). -01 Cam
