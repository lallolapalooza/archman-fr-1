FUTEX_WAIT_BITSET(2const) FUTEX_WAIT_BITSET(2const)

NOM

FUTEX_WAIT_BITSET, FUTEX_WAKE_BITSET - attente et réveil sélectifs de futex

BIBLIOTHÈQUE

Bibliothèque C standard (libc, -lc)

SYNTAXE

#include <linux/futex.h>  /* Définition des constantes FUTEX_* */
#include <sys/syscall.h>  /* Définition des constantes SYS_* */
#include <unistd.h>
long syscall(SYS_futex, uint32_t *uaddr, FUTEX_WAIT_BITSET, uint32_t val,
             const struct timespec *timeout, NULL,
             uint32_t val3);
long syscall(SYS_futex, uint32_t *uaddr, FUTEX_WAKE_BITSET, uint32_t val,
             NULL, NULL,
             uint32_t val3);

DESCRIPTION

FUTEX_WAIT_BITSET
Cette opération est similaire à FUTEX_WAIT(2const) sauf que val3 est utilisé pour fournir un masque de bits de 32 bits au noyau. Ce masque de bits, dans lequel au moins un bit doit être défini, est stocké dans l'état interne du noyau de l'attendant. Voir la description de FUTEX_WAKE_BITSET pour plus de détails.
Si timeout n'est pas NULL, la structure pointée par celui-ci spécifie un délai d'attente absolu pour l'opération. Si timeout est NULL, l'opération peut bloquer indéfiniment.
FUTEX_WAKE_BITSET
Cette opération est identique à FUTEX_WAKE(2const) sauf que l'argument val3 est utilisé pour fournir un masque de bits de 32 bits au noyau. Ce masque de bits, dans lequel au moins un bit doit être défini, est utilisé pour sélectionner quels attendants doivent être réveillés. La sélection est faite par un ET bit à bit du masque de bits "réveil" (c'est-à-dire la valeur dans val3) et le masque de bits qui est stocké dans l'état interne du noyau de l'attendant (le masque de bits "attente" qui est défini en utilisant FUTEX_WAIT_BITSET). Tous les attendants pour lesquels le résultat du ET est non nul sont réveillés ; les attendants restants continuent de dormir.
L'effet de FUTEX_WAIT_BITSET et FUTEX_WAKE_BITSET est de permettre des réveils sélectifs parmi plusieurs attendants bloqués sur le même futex. Cependant, notez que, selon le cas d'utilisation, l'emploi de cette fonctionnalité de multiplexage par masque de bits sur un futex peut être moins efficace que l'utilisation de plusieurs futex, car l'emploi du multiplexage par masque de bits nécessite au noyau de vérifier tous les attendants sur un futex, y compris ceux qui ne sont pas intéressés par le réveil (c'est-à-dire ceux qui n'ont pas le bit pertinent défini dans leur masque de bits "attente").
La constante FUTEX_BITSET_MATCH_ANY, qui correspond à tous les 32 bits définis dans le masque de bits, peut être utilisée comme argument val3 pour FUTEX_WAIT_BITSET et FUTEX_WAKE_BITSET. À part les différences dans la gestion de l'argument timeout, l'opération FUTEX_WAIT(2const) est équivalente à FUTEX_WAIT_BITSET avec val3 spécifié comme FUTEX_BITSET_MATCH_ANY ; c'est-à-dire, autoriser un réveil par n'importe quel réveilleur. L'opération FUTEX_WAKE(2const) est équivalente à FUTEX_WAKE_BITSET avec val3 spécifié comme FUTEX_BITSET_MATCH_ANY ; c'est-à-dire, réveiller n'importe quel(s) attendant(s).

VALEUR DE RETOUR

En cas d'erreur, -1 est retourné, et errno est défini pour indiquer l'erreur.

La valeur de retour en cas de succès dépend de l'opération, comme décrit dans la liste suivante :

FUTEX_WAIT_BITSET
Retourne 0 si l'appelant a été réveillé. Voir futex(2const) pour savoir comment interpréter cela correctement en pratique.
FUTEX_WAKE_BITSET
Retourne le nombre d'attendants qui ont été réveillés.

ERREURS

Voir futex(2).

EAGAIN
(FUTEX_WAIT_BITSET) La valeur pointée par uaddr n'était pas égale à la valeur attendue val au moment de l'appel.
Note : sous Linux, les noms symboliques EAGAIN et EWOULDBLOCK (qui apparaissent tous deux dans différentes parties du code futex du noyau) ont la même valeur.
EFAULT
timeout ne pointait pas vers une adresse valide dans l'espace utilisateur.
EINTR
Une opération FUTEX_WAIT_BITSET a été interrompue par un signal (voir signal(7)). Avant Linux 2.6.22, cette erreur pouvait également être retournée pour un réveil intempestif ; depuis Linux 2.6.22, cela n'arrive plus.
EINVAL
L'argument timeout fourni était invalide (tv_sec était inférieur à zéro, ou tv_nsec n'était pas inférieur à 1 000 000 000).
EINVAL
uaddr2 ne pointe pas vers un objet valide — c'est-à-dire que l'adresse n'est pas alignée sur quatre octets.
EINVAL
Le masque de bits fourni dans val3 est zéro.
EINVAL
(FUTEX_WAKE_BITSET) Le noyau a détecté une incohérence entre l'état de l'espace utilisateur à uaddr et l'état du noyau — c'est-à-dire qu'il a détecté un attendant qui attend dans FUTEX_LOCK_PI(2const) ou FUTEX_LOCK_PI2(2const) sur uaddr.
ETIMEDOUT
Le délai d'attente a expiré avant que l'opération ne soit terminée.

NORMES

Linux.
