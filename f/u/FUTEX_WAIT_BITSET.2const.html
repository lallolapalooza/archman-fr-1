KE_BI
TSET
Cette opération est la même
que
FUTEX_WAKE(2const) sauf que l'argument val3 est utilisé pour fournir un masque de bits de 32 bits au noyau. Ce masque de bits, dans lequel au moins un bit doit être défini, est utilisé pour sélectionner quels attenteurs doivent être réveillés. La sélection est effectuée par un ET binaire du masque de bits de « réveil » (c'est-à-dire la valeur dans val3) et le masque de bits stocké dans l'état interne au noyau de l'attenteur (le masque de bits d'« attente » qui est défini à l'aide de FUTEX_WAIT_BITSET). Tous les attenteurs pour lesquels le résultat de l'ET est non nul sont réveillés ; les attenteurs restants continuent de dormir. L'eff
et
de
FUTEX_WAIT_BITSET et FUTEX_WAKE_BITSET est de permettre des réveils sélectifs parmi plusieurs attenteurs qui sont bloqués sur le même futex. Cependant, notez que, selon le cas d'utilisation, l'utilisation de cette fonctionnalité de multiplexage par masque de bits sur un futex peut être moins efficace que l'utilisation simple de plusieurs futex, car l'utilisation du multiplexage par masque de bits nécessite que le noyau vérifie tous les attenteurs sur un futex, y compris ceux qui ne sont pas intéressés par le réveil (c'est-à-dire qu'ils n'ont pas le bit pertinent défini dans leur masque de bits d'« attente »). La const
ante
FUTEX_BITSET_MATCH_ANY, qui correspond à tous les 32 bits définis dans le masque de bits, peut être utilisée comme argument val3 pour FUTEX_WAIT_BITSET et FUTEX_WAKE_BITSET. À part les différences dans le traitement de l'argument timeout, l'opération FUTEX_WAIT(2const) est équivalente à FUTEX_WAIT_BITSET avec val3 spécifié comme FUTEX_BITSET_MATCH_ANY ; c'est-à-dire, permettre un réveil par n'importe quel réveilleur. L' opération FUTEX_WAKE(2const) est équivalente à FUTEX_WAKE_BITSET avec val3 spécifié comme FUTEX_BITSET_MATCH_ANY ; c'est-à-dire,
réveiller n'impor
te quel ou n'import
e quels attenteurs.
