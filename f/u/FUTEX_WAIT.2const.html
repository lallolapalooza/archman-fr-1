FUTEX_WAIT(2const) FUTEX_WAIT(2const)

NOM

FUTEX_WAIT - attendre qu'une opération FUTEX_WAKE se produise

BIBLIOTHÉQUE

Bibliothèque C standard (libc, -lc)

SYNTAXE

#include <linux/futex.h>  /* Définition des constantes FUTEX_* */
#include <sys/syscall.h>  /* Définition des constantes SYS_* */
#include <unistd.h>
long syscall(SYS_futex, uint32_t *uaddr, FUTEX_WAIT, uint32_t val,
             const struct timespec *_Nullable timeout);

DESCRIPTION

Cette opération teste si la valeur à l'emplacement du mot futex pointé par l'adresse uaddr contient toujours la valeur attendue val, et si c'est le cas, se met en veille en attendant une opération FUTEX_WAKE(2const) sur le mot futex.

Le chargement de la valeur du mot futex est un accès mémoire atomique (c'est-à-dire qu'il utilise les instructions machine atomiques de l'architecture respective). Ce chargement, la comparaison avec la valeur attendue et le début de la mise en veille sont effectués de manière atomique et totalement ordonnée par rapport aux autres opérations futex sur le même mot futex.

Si le thread commence à se mettre en veille, il est considéré comme un attente sur ce mot futex. Si la valeur du futex ne correspond pas à val, alors l'appel échoue immédiatement avec l'erreur EAGAIN.

Le but de la comparaison avec la valeur attendue est d'éviter les réveils perdus. Si un autre thread a modifié la valeur du mot futex après que le thread appelant ait décidé de bloquer en fonction de la valeur précédente, et si l'autre thread a exécuté une opération FUTEX_WAKE(2const) (ou une opération de réveil similaire) après le changement de valeur et avant cette opération FUTEX_WAIT, alors le thread appelant observera le changement de valeur et ne se mettra pas en veille.

Si timeout n'est pas NULL, la structure qu'il pointe spécifie un délai d'attente. (Cet intervalle sera arrondi à la granularité de l'horloge système, et il est garanti qu'il n'expirera pas prématurément.) Si timeout est NULL, l'appel se bloque indéfiniment.

VALEUR DE RETOUR

En cas d'erreur, -1 est retourné, et errno est défini pour indiquer l'erreur.

En cas de succès, FUTEX_WAIT retourne 0 si l'appelant a été réveillé. Notez qu'un réveil peut également être causé par des schémas d'utilisation futex courants dans du code non lié qui a utilisé précédemment l'emplacement mémoire du mot futex (par exemple, les implémentations typiques de mutex Pthreads basées sur futex peuvent provoquer cela dans certaines conditions). Par conséquent, les appelants doivent toujours supposer de manière conservatrice qu'une valeur de retour de 0 peut signifier un réveil fantôme, et utiliser la valeur du mot futex (c'est-à-dire le schéma de synchronisation dans l'espace utilisateur) pour décider s'il faut continuer à bloquer ou non.

ERREURS

Voir futex(2).

EAGAIN
La valeur pointée par uaddr n'était pas égale à la valeur attendue val au moment de l'appel.
Note : sous Linux, les noms symboliques EAGAIN et EWOULDBLOCK (qui apparaissent tous deux dans différentes parties du code futex du noyau) ont la même valeur.
EFAULT
timeout ne pointait pas vers une adresse valide dans l'espace utilisateur.
EINTR
L'opération a été interrompue par un signal (voir signal(7)). Avant Linux 2.6.22, cette erreur pouvait également être retournée pour un réveil fantôme ; depuis Linux 2.6.22, cela ne se produit plus.
EINVAL
L'argument timeout fourni était invalide (tv_sec était inférieur à zéro, ou tv_nsec n'était pas inférieur à 1 000 000 000).
ETIMEDOUT
Le délai d'attente a expiré avant que l'opération ne soit terminée.

NORMES

Linux.

HISTORIQUE

Linux 2.6.0.

LIMITATIONS

timeout est interprété comme une valeur *relative*. Ceci diffère des autres opérations futex, où timeout est interprété comme une valeur absolue. Pour obtenir l'équivalent de FUTEX_WAIT avec un délai d'attente absolu, utilisez FUTEX_WAIT_BITSET(2const) avec val3 spécifié comme FUTEX_BITSET_MATCH_ANY.
