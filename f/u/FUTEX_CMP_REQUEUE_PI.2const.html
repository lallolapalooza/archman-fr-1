FUTEX_CMP_REQUEUE_PI(2const) FUTEX_CMP_REQUEUE_PI(2const)

NOM

FUTEX_CMP_REQUEUE_PI - comparer un futex à héritage de priorité, réveiller un atend-difiant et replacer les autres

BIBLIOTHÈQUE

Bibliothèque C standard (libc, -lc)

SYNTAXE

#include <linux/futex.h>  /* Définition des constantes FUTEX_* */
#include <sys/syscall.h>  /* Définition des constantes SYS_* */
#include <unistd.h>
long syscall(SYS_futex, uint32_t *uaddr, FUTEX_CMP_REQUEUE_PI, 1,
             uint32_t val2, uint32_t *uaddr2,
             uint32_t val3);

DESCRIPTION

Cette opération est une variante sensible aux PI de FUTEX_CMP_REQUEUE(2const). Elle replace les atend-difiants bloqués via FUTEX_WAIT_REQUEUE_PI(2const) sur uaddr depuis un futex source non-PI (uaddr) vers un futex cible PI (uaddr2).

Contrairement à FUTEX_CMP_REQUEUE(2const), cette opération réveille un atend-difiant au maximum 1 atend-difiant qui attend sur le futex à uaddr (puisque le but principal est d'éviter une déferlante). Les autres atend-difiants sont retirés de la file d'attente du futex source à uaddr et ajoutés à la file d'attente du futex cible à uaddr2.

Les arguments val2 et val3 servent aux mêmes fins que pour FUTEX_CMP_REQUEUE(2const).

VALEUR DE RETOUR

En cas d'erreur, -1 est retourné, et errno est défini pour indiquer l'erreur.

En cas de succès, FUTEX_CMP_REQUEUE_PI retourne le nombre total d'atend-difiants qui ont été réveillés ou replacés vers le futex pour le mot futex à uaddr2. Si cette valeur est supérieure à 1, alors la différence représente le nombre d'atend-difiants replacés vers le futex pour le mot futex à uaddr2.

ERREURS

Voir futex(2).

EAGAIN
La valeur pointée par uaddr n'est pas égale à la valeur attendue val3.
EAGAIN
L'ID du thread propriétaire du futex de uaddr2 est sur le point de se terminer, mais n'a pas encore géré le nettoyage de l'état interne. Réessayez.
EDEADLK
Le mot futex à uaddr est déjà verrouillé par l'appelant.
EDEADLK
Lors du remplacement d'un atend-difiant vers le futex PI pour le mot futex à uaddr2, le noyau a détecté un interblocage.
EFAULT
uaddr2 n'a pas pointé vers une adresse mémoire utilisateur valide.
EINVAL
uaddr2 ne pointe pas vers un objet valide—c'est-à-dire, l'adresse n'est pas alignée sur quatre octets.
EINVAL
uaddr est égal à uaddr2 (c'est-à-dire, une tentative a été faite pour remplacer vers le même futex).
EINVAL
Le noyau a détecté une incohérence entre l'état utilisateur à uaddr2 et l'état du noyau ; c'est-à-dire, le noyau a détecté un atend-difiant qui attend via FUTEX_WAIT(2const) ou FUTEX_WAIT_BITSET(2const) sur uaddr2.
EINVAL
Le noyau a détecté une incohérence entre l'état utilisateur à uaddr et l'état du noyau ; c'est-à-dire, le noyau a détecté un atend-difiant qui attend via FUTEX_WAIT(2const) ou FUTEX_WAIT_BITSET(2const) sur uaddr.
EINVAL
Le noyau a détecté une incohérence entre l'état utilisateur à uaddr et l'état du noyau ; c'est-à-dire, le noyau a détecté un atend-difiant qui attend sur uaddr via FUTEX_LOCK_PI(2const) ou FUTEX_LOCK_PI2(2const) (au lieu de FUTEX_WAIT_REQUEUE_PI).
EINVAL
Une tentative a été faite pour remplacer un atend-difiant vers un futex autre que celui spécifié par l'appel correspondant FUTEX_WAIT_REQUEUE_PI pour cet atend-difiant.
EINVAL
Le quatrième argument n'est pas 1.
ENOMEM
Le noyau n'a pas pu allouer de mémoire pour conserver les informations d'état.
ENOSYS
Une vérification à l'exécution a déterminé que l'opération n'est pas disponible. Les opérations PI-futex ne sont pas implémentées sur toutes les architectures et ne sont pas prises en charge sur certaines variantes de CPU.
EPERM
L'appelant n'est pas autorisé à s'attacher au futex à uaddr2. (Cela peut être causé par une corruption de l'état dans l'espace utilisateur.)
ESRCH
L'ID du thread dans le mot futex à uaddr n'existe pas.
ESRCH
L'ID du thread dans le mot futex à uaddr2 n'existe pas.

NORMES

Linux.

HISTORIQUE

Linux 2.6.31.
