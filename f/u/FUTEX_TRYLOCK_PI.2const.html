FUTEX_TRYLOCK_PI(2const) FUTEX_TRYLOCK_PI(2const)

NOM

FUTEX_TRYLOCK_PI - essaie de verrouiller un futex d'héritage de priorité

BIBLIOTHÈQUE

Bibliothèque C standard (libc, -lc)

SYNTAXE

#include <linux/futex.h>  /* Définition des constantes FUTEX_* */
#include <sys/syscall.h>  /* Définition des constantes SYS_* */
#include <unistd.h>
long syscall(SYS_futex, uint32_t *uaddr, FUTEX_TRYLOCK_PI);

DESCRIPTION

Cette opération tente d'acquérir le verrou à uaddr. Elle est invoquée lorsqu'une acquisition atomique dans l'espace utilisateur n'a pas réussi car le mot futex n'était pas 0.

Comme le noyau a accès à plus d'informations d'état que l'espace utilisateur, l'acquisition du verrou peut réussir si elle est effectuée par le noyau dans des cas où le mot futex (c'est-à-dire les informations d'état accessibles par l'espace utilisateur) contient un état obsolète (FUTEX_WAITERS et/ou FUTEX_OWNER_DIED). Cela peut se produire lorsque le propriétaire du futex est décédé. L'espace utilisateur ne peut pas gérer cette condition d'une manière exempte de race, mais le noyau peut corriger cela et acquérir le futex.

VALEUR DE RETOUR

En cas d'erreur, -1 est retourné et errno est défini pour indiquer l'erreur.

En cas de succès, FUTEX_TRYLOCK_PI retourne 0 si le futex a été verrouillé avec succès.

ERREURS

Voir futex(2).

EAGAIN
L'identifiant du thread propriétaire du futex à uaddr est sur le point de se terminer, mais n'a pas encore géré le nettoyage de son état interne. Réessayez.
EDEADLK
Le mot futex à uaddr est déjà verrouillé par l'appelant.
EINVAL
Le noyau a détecté une incohérence entre l'état de l'espace utilisateur à uaddr et l'état du noyau. Cela indique soit une corruption de l'état, soit que le noyau a trouvé un attenteur sur uaddr qui attend via FUTEX_WAIT(2const) ou FUTEX_WAIT_BITSET(2const).
ENOMEM
Le noyau n'a pas pu allouer de mémoire pour conserver les informations d'état.
ENOSYS
Une vérification à l'exécution a déterminé que l'opération n'est pas disponible. Les opérations PI-futex ne sont pas implémentées sur toutes les architectures et ne sont pas prises en charge sur certaines variantes de processeur.
EPERM
L'appelant n'est pas autorisé à s'attacher au futex à uaddr. (Cela peut être causé par une corruption de l'état dans l'espace utilisateur.)
ESRCH
L'identifiant du thread dans le mot futex à uaddr n'existe pas.

NORMES

Linux.

HISTORIQUE

Linux 2.6.18.

VOIR AUSSI
