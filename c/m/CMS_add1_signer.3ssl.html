CMS_add1_signer(3ssl)

Paquet: openssl

Licences: Apache-2.0

CMS_ADD1_SIGNER(3ssl) OpenSSL CMS_ADD1_SIGNER(3ssl)

NOM

CMS_add1_signer, CMS_SignerInfo_sign - ajouter un signataire à une structure de données signée CMS_ContentInfo

SYNOPSIS

#include <openssl/cms.h>
CMS_SignerInfo *CMS_add1_signer(CMS_ContentInfo *cms, X509 *signcert,
                               EVP_PKEY *pkey, const EVP_MD *md,
                               unsigned int flags);
int CMS_SignerInfo_sign(CMS_SignerInfo *si);

DESCRIPTION

CMS_add1_signer() ajoute un signataire avec le certificat signcert et la clé privée pkey en utilisant le digest de message md à la structure SignedData CMS_ContentInfo cms.

La structure CMS_ContentInfo devrait être obtenue à partir d'un appel initial à CMS_sign() avec le drapeau CMS_PARTIAL activé ou dans le cas d'une re-signature d'une structure CMS_ContentInfo SignedData valide.

Si le paramètre md est NULL, alors le digest par défaut pour l'algorithme de clé publique sera utilisé.

Sauf si le drapeau CMS_REUSE_DIGEST est activé, la structure CMS_ContentInfo retournée n'est pas complète et doit être finalisée soit par streaming (si applicable) soit par un appel à CMS_final().

La fonction CMS_SignerInfo_sign() signe explicitement une structure CMS_SignerInfo, son utilisation principale est lorsque les drapeaux CMS_REUSE_DIGEST et CMS_PARTIAL sont tous deux activés.

NOTES

Le but principal de CMS_add1_signer() est de fournir un contrôle plus fin sur une structure de données signée CMS où la fonction plus simple CMS_sign() n'est pas appropriée par défaut. Par exemple, si des multiples signataires ou des algorithmes de digest non par défaut sont nécessaires. De nouveaux attributs peuvent également être ajoutés en utilisant la structure CMS_SignerInfo retournée et les fonctions utilitaires d'attributs CMS ou les fonctions de demande de reçu signé CMS.

Tous les drapeaux suivants (combinés avec un OU) peuvent être passés dans le paramètre flags.

Si CMS_REUSE_DIGEST est activé, une tentative est faite pour copier la valeur du digest du contenu à partir de la structure CMS_ContentInfo : pour ajouter un signataire à une structure existante. Une erreur se produit si une valeur de digest correspondante ne peut être trouvée à copier. La structure CMS_ContentInfo retournée sera valide et finalisée lorsque ce drapeau est activé.

Si CMS_PARTIAL est activé en plus de CMS_REUSE_DIGEST, la structure CMS_SignerInfo ne sera pas finalisée afin que des attributs supplémentaires puissent être ajoutés. Dans ce cas, un appel explicite à CMS_SignerInfo_sign() est nécessaire pour la finaliser.

Si CMS_NOCERTS est activé, le certificat du signataire ne sera pas inclus dans la structure CMS_ContentInfo, le certificat du signataire doit toutefois être fourni dans le paramètre signcert. Cela peut réduire la taille de la signature si le certificat du signataire peut être obtenu par d'autres moyens : par exemple, un message précédemment signé.

La structure SignedData inclut plusieurs CMS signedAttributes, dont l'heure de signature, le type de contenu CMS et la liste des chiffrements supportés dans un attribut SMIMECapabilities. Si CMS_NOATTR est activé, aucun signedAttributes ne sera utilisé du tout. Si CMS_NOSMIMECAP est activé, SMIMECapabilities sera omis. Si CMS_NO_SIGNING_TIME est activé, l'heure de signature sera omise.

OpenSSL identifiera par défaut les certificats de signature en utilisant le nom de l'émetteur et le numéro de série. Si CMS_USE_KEYID est activé, il utilisera la valeur de l'identifiant de clé du sujet à la place. Une erreur se produit si le certificat de signature ne possède pas d'extension d'identifiant de clé du sujet.

S'il est présent, l'attribut SMIMECapabilities indique la prise en charge des algorithmes suivants par ordre de préférence : AES 256 bits, Gost R3411-94, Gost 28147-89, AES 192 bits, AES 128 bits, triple DES, RC2 128 bits, RC2 64 bits, DES et RC2 40 bits. Si l'un de ces algorithmes n'est pas disponible, il ne sera pas inclus : par exemple, les algorithmes GOST ne seront pas inclus si le moteur GOST n'est pas chargé.

CMS_add1_signer() retourne un pointeur interne à la structure CMS_SignerInfo qui vient d'être ajoutée, qui peut être utilisée pour définir des attributs supplémentaires avant sa finalisation.

VALEURS DE RETOUR

CMS_add1_signer() retourne un pointeur interne à la structure CMS_SignerInfo qui vient d'être ajoutée ou NULL si une erreur survient.

CMS_SignerInfo_sign() retourne 1 en cas de succès, 0 en cas d'échec.
