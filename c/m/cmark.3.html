Itérateu

r

Un itérateur parcourra une arborescence de nœuds, en partant d'un nœud racine, en renvoyant un nœud à la fois, avec des informations sur le fait que le nœud est entré ou sorti. L'itérateur descendra d'abord vers un nœud enfant, s'il y en a un. S'il n'y a pas d'enfant, l'itérateur ira au nœud suivant de même niveau. S'il n'y a pas de nœud suivant de même niveau, l'itérateur remontera au parent (mais avec un cmark_event_type de CMARK_EVENT_EXIT). L'itérateur renverra CMARK_EVENT_DONE lorsqu'il atteindra à nouveau le nœud racine. Une application naturelle est un moteur de rendu HTML, où un événement ENTER événement produit une balise d'ouverture et un événement EXIT produit une balise de fermeture. Un itérateur peut aussi être utilisé pour transformer un AST de manière systématique, par exemple en transformant tous les titres de niveau 3 en paragraphes

ordinaires. 
void
usage_example(cmark_node *root) {
    cmark_event_type ev_type;
    cmark_iter *iter = cmark_iter_new(root);
    while ((ev_type = cmark_iter_next(iter)) != CMARK_EVENT_DONE) {
        cmark_node *cur = cmark_iter_get_node(iter);
        // Faire quelque chose avec `cur` et `ev_type`
    }
    cmark_iter_free(iter);
}

Crée un nouvel objet analyseur avec le nœud donné à utiliser comme nœud racine de l'AST

Lors de l'analyse, les enfants sont toujours ajoutés en fin, pas en début ; cela signifie que si root a déjà des enfants, les enfants nouvellement analysés apparaîtront après les enfants

Une généralisation de cmark_parser_new_with_mem

Cela est utile pour créer un document unique à partir de plusieurs fragments de document

analysés.
