TRI DE LA VUE BIBLIOTHEQUE

La vue bibliothèque (celle en forme d'arbre ; pas la vue bibliothèque triée, qui est configurée avec lib_sort - voir OPTIONS DE CONFIGURATION), est triée automatiquement en utilisant les tags des fichiers audio.

Note : Les albums mettant en vedette divers artistes (par exemple, des compilations) sont traités spécialement. Si une balise d'artiste d'album ou le cadre TPE2 d'ID3v2 est défini, il sera utilisé à la place du nom réel de l'artiste. Sinon, cmus détermine si l'album est une compilation (si albumartist ou artist sont définis sur Various Artists, Various, VA, ou V/A ; ou si compilation ou partofacompilation sont définis sur une valeur vraie ; ou si le cadre TCMP d'ID3v2 est défini). Si c'est le cas, l'artiste est nommé <Various Artists>.

Note : Si le nom du fichier est une URL, les tags artiste/album sont définis sur <Stream>. S'il s'agit d'un fichier, cmus définit les tags artiste et/ou album sur <No Name> s'ils ne sont pas déjà définis. Ces noms seront traités de la même manière que les autres noms pour le tri.

En général, trois niveaux de tri sont utilisés dans la vue bibliothèque : le nom de l'artiste, puis l'album, et enfin la piste elle-même.

Premièrement, cmus trie par ordre alphanumérique selon la valeur de la balise d'artiste. Si une balise de tri spéciale est disponible, sa valeur sera utilisée à la place.

Ensuite, cmus trie par album. Les pistes sont regroupées par nom d'album, et les groupes sont triés par la date de la première piste, puis par ordre alphanumérique par le nom de l'album. Si l'en-tête de date n'est pas défini, l'album sera placé en haut de la liste.

Enfin, chaque album est trié par le numéro de disque, le numéro de piste, puis le nom du fichier (pas le nom de la piste).

COMMANDES

Cette section décrit les commandes de cmus, qui peuvent être liées à des touches et à des événements de souris, mises dans des fichiers de configuration, exécutées en mode commande, ou passées à cmus-remote.

Les paramètres optionnels sont entre [crochets], les paramètres requis entre <crochets> et les liaisons de touches par défaut sont (entre parenthèses).

add [-l] [-p] [-q] [-Q] <fichier|dossier|url|playlist>

Ajoute le fichier/dossier/url/playlist à la vue spécifiée ou à la vue courante.
-l

-p
ajouter à la playlist
-q
ajouter à la file d'attente de lecture

Les fichiers pris en charge sont basés sur les plugins d'entrée chargés.
URLs prises en charge : Shoutcast (http://...), CDDA (cdda://...).
Types de playlists pris en charge : texte brut, .m3u, .pls.

bind [-f] <contexte> <touche> <commande>

Ajoute une liaison de touche.
-f
écraser la liaison existante
Contextes valides : common (c'est-à-dire toutes les vues), library (1-2), playlist (3), queue (4), browser (5), filters (6)
Il y a un contexte pour chaque vue. Common est un contexte spécial sur lequel les touches liées fonctionnent dans toutes les vues.
Vous pouvez remplacer des touches spécifiques dans le contexte common pour une vue. Par exemple, i sélectionne la piste courante dans les vues 1-3 mais dans l'explorateur, il est remplacé pour basculer l'affichage des fichiers cachés.
Lors de la définition de liaisons personnalisées dans $XDG_CONFIG_HOME/cmus/rc, il est recommandé d'utiliser l'option -f, sinon bind peut échouer en raison d'une liaison existante dans les fichiers de configuration sauvegardés automatiquement ou au niveau du système.
Astuce : Vous pouvez appuyer sur tab depuis le mode commande pour développer les contextes, les touches et les commandes.

Navigue dans la vue explorateur vers le répertoire parent (5). Cette commande n'a de sens que lorsqu'elle est liée au contexte de touche browser bien qu'il soit possible de l'utiliser même si la vue explorateur n'est pas active.

Variables d'environnement de la

bibliothèque

cmus prend en charge l'utilisation de variables d'environnement pour permettre la relocalisation ou la synchronisation de la bibliothèque, du cache et des listes de lecture. Les variables d'environnement à utiliser sont spécifiées avec l'option de configuration pl_env_vars, qui prend effet lors de la sortie de

cmus.

Un bon point de départ est :set pl_env_vars=HOME. Cela permettra de partager le répertoire .cmus entre appareils ou utilisateurs. Des variables d'environnement supplémentaires peuvent être ajoutées (séparées par des virgules) à pl_env_vars pour rediriger des chemins spécifiques. Les variables d'environnement doivent contenir des chemins absolus pour être utilisées. Le dernier préfixe de répertoire correspondant sera

utilisé.

Si un fichier n'existe pas, il sera traité de la même manière que les fichiers manquants le sont habituellement. Si le fichier est dans le cache, il sera préservé, et une erreur sera affichée lors de la lecture. Si le fichier n'est pas dans le cache, il sera retiré des listes de lecture et de la bibliothèque. Il y a une exception spéciale : si un fichier est manquant parce que la variable d'environnement est invalide/vide/non définie, mais qu'il est toujours dans le cache, il sera préservé dans le cache tel quel, en plus d'être préservé dans la bibliothèque comme

d'habitude.

Lors de l'utilisation de :save/:load et dans la bibliothèque/cache/listes de lecture sur disque, les chemins seront enregistrés avec la variable d'environnement délimitée par le caractère \x1F, qui est le séparateur d'unité ASCII

invisible.

Cette fonctionnalité peut aussi être utilisée pour déplacer rapidement une bibliothèque vers un autre emplacement tout en préservant toutes les métadonnées, les listes de lecture et les compteurs de lecture. Pour ce faire, définissez une variable d'environnement pour chaque chemin de base que vous voulez changer, définissez pl_env_vars avec la liste des variables d'environnement, redémarrez cmus, changez les variables d'environnement, redémarrez cmus, désactivez pl_env_vars, puis redémarrez cmus à

nouveau.

Si une bibliothèque utilisant pl_env_vars est ouverte avec une version de cmus qui ne la prend pas en charge, les pistes référencées avec des variables d'environnement seront oubliées. Pour restaurer les fichiers sur disque afin qu'ils soient compatibles avec les anciennes versions de cmus, désactivez simplement pl_env_vars et redémarrez cmus. Cela restaurera les chemins de toutes les variables d'environnement définies vers leur chemin

réel.
