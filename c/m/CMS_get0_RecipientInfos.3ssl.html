DESCRIPTIO

N

La fonction CMS_get0_RecipientInfos() renvoie toutes les structures CMS_RecipientInfo associées à une structure CMS EnvelopedData

.

CMS_RecipientInfo_type() renvoie le type de la structure CMS_RecipientInfo ri. Elle renverra actuellement CMS_RECIPINFO_TRANS, CMS_RECIPINFO_AGREE, CMS_RECIPINFO_KEK, CMS_RECIPINFO_PASS, CMS_RECIPINFO_KEM, ou CMS_RECIPINFO_OTHER

.

CMS_RecipientInfo_ktri_get0_signer_id() récupère l'identifiant de certificat du destinataire associé à une structure CMS_RecipientInfo spécifique ri, qui doit être de type CMS_RECIPINFO_TRANS. Soit l'identifiant de clé sera défini dans keyid ou à la fois le nom de l'émetteur et le numéro de série dans issuer et sno

.

CMS_RecipientInfo_ktri_cert_cmp() compare le certificat cert à la structure CMS_RecipientInfo ri, qui doit être de type CMS_RECIPINFO_TRANS. Elle renvoie zéro si la comparaison est réussie et non zéro

sinon.

CMS_RecipientInfo_set0_pkey() associe la clé privée pkey à la structure CMS_RecipientInfo ri, qui doit être de type CMS_RECIPINFO_TRANS

.

CMS_RecipientInfo_kari_set0_pkey_and_peer() associe la clé privée pkey et le certificat du pair peer à la structure CMS_RecipientInfo ri, qui doit être de type CMS_RECIPINFO_AGREE

.

CMS_RecipientInfo_kari_set0_pkey() associe la clé privée pkey à la structure CMS_RecipientInfo ri, qui doit être de type CMS_RECIPINFO_AGREE

.

CMS_RecipientInfo_kari_get0_ctx() renvoie le EVP_CIPHER_CTX pour la clé de chiffrement de clé, permettant à l'appelant de spécifier le chiffrement d'enveloppement de clé. La structure CMS_RecipientInfo ri doit être de type CMS_RECIPINFO_AGREE

.

CMS_RecipientInfo_kekri_get0_id() récupère les informations de clé à partir de la structure CMS_RecipientInfo ri qui doit être de type CMS_RECIPINFO_KEK. N'importe lequel des paramètres restants peut être NULL si l'application n'est pas intéressée par la valeur d'un champ. Lorsqu'un champ est facultatif et absent, NULL sera écrit dans le paramètre correspondant. Le champ keyEncryptionAlgorithm est écrit dans palg, le champ keyIdentifier est écrit dans pid, le champ date s'il est présent est écrit dans pdate, si le champ other est présent les composants keyAttrId et keyAttr sont écrits dans les paramètres potherid et pothertype

.

CMS_RecipientInfo_kekri_id_cmp() compare l'ID dans les paramètres id et idlen au keyIdentifier de la structure CMS_RecipientInfo ri, qui doit être de type CMS_RECIPINFO_KEK. Elle renvoie zéro si la comparaison est réussie et non zéro

sinon.

CMS_RecipientInfo_set0_key() associe la clé symétrique key de longueur keylen à la structure CMS_RecipientInfo ri, qui doit être de type CMS_RECIPINFO_KEK

.

CMS_RecipientInfo_kemri_cert_cmp() compare le certificat cert à la structure CMS_RecipientInfo ri, qui doit être de type CMS_RECIPINFO_KEM. Elle renvoie zéro si la comparaison est réussie et non zéro

sinon.

CMS_RecipientInfo_kemri_set0_pkey() associe la clé privée pkey à la structure CMS_RecipientInfo ri, qui doit être de type CMS_RECIPINFO_KEM

.

CMS_RecipientInfo_kemri_get0_ctx() renvoie le EVP_CIPHER_CTX pour la clé de chiffrement de clé, permettant à l'appelant de spécifier le chiffrement d'enveloppement de clé. La structure CMS_RecipientInfo ri doit être de type CMS_RECIPINFO_KEM

.

CMS_RecipientInfo_kemri_get0_kdf_alg() renvoie le X509_ALGOR pour le KDF du RecipientInfo, permettant à l'appelant de spécifier l'algorithme KDF. La structure CMS_RecipientInfo ri doit être de type CMS_RECIPINFO_KEM. Si l'appelant ne spécifie pas d'algorithme KDF, HKDF-SHA256 sera

utilisé.

CMS_RecipientInfo_kemri_set_ukm() définit le matériel de clé utilisateur (UKM) facultatif du RecipientInfo. L'UKM est encodé, avec d'autres informations, dans le paramètre OSSL_KDF_PARAM_INFO du KDF du RecipientInfo. La structure CMS_RecipientInfo ri doit être de type CMS_RECIPINFO_KEM

.

CMS_RecipientInfo_decrypt() tente de déchiffrer la structure CMS_RecipientInfo ri dans la structure cms. Une clé doit avoir été associée à la structure au

préalable.

CMS_RecipientInfo_encrypt() tente de chiffrer la structure CMS_RecipientInfo ri dans la structure cms. Une clé doit avoir été associée à la structure au préalable et la clé de chiffrement du contenu doit être disponible : par exemple par un appel précédent à CMS_RecipientI

nfo_dec
rypt().

NOTE

S

Le but principal de ces fonctions est de permettre à une application de rechercher les clés des destinataires en utilisant n'importe quelle technique appropriée lorsque la méthode plus simple de CMS_decrypt() n'est pas

appropriée.

Dans une utilisation typique, une application récupérera toutes les structures CMS_RecipientInfo en utilisant CMS_get0_RecipientInfos() et vérifiera le type de chacune en utilisant CMS_RecipientInfo_type(). Selon le type, la structure CMS_RecipientInfo peut être ignorée ou ses données d'identifiant de clé récupérées à l'aide d'une fonction appropriée. Ensuite, si le secret correspondant ou la clé privée peuvent être obtenus par n'importe quel moyen approprié ils peuvent alors être associés à la structure et CMS_RecipientInfo_decrypt() appelée. Si c'est un succès CMS_decrypt() peut être appelée avec une clé NULL pour déchiffrer le contenu

enveloppé.

La fonction CMS_RecipientInfo_encrypt() peut être utilisée pour ajouter un nouveau destinataire à une structure de données enveloppées existante. Typiquement, une application déchiffrera d'abord une structure CMS_RecipientInfo appropriée pour rendre la clé de chiffrement du contenu disponible, elle ajoutera ensuite un nouveau destinataire en utilisant une fonction telle que CMS_add1_recipient_cert() et enfin chiffrera la clé de chiffrement du contenu en utilisant CMS_RecipientI

nfo_enc
rypt().

VALEURS DE

RETOUR

CMS_get0_RecipientInfos() renvoies toutes les structures CMS_RecipientInfo, ou NULL si une erreur se

produit.

CMS_RecipientInfo_ktri_get0_signer_id(), CMS_RecipientInfo_set0_pkey(), CMS_RecipientInfo_kekri_get0_id(), CMS_RecipientInfo_set0_key(), CMS_RecipientInfo_kemri_set0_pkey(), CMS_RecipientInfo_kemri_set_ukm(), CMS_RecipientInfo_decrypt() et CMS_RecipientInfo_encrypt() retournent 1 en cas de succès ou 0 si une erreur se

produit.

CMS_RecipientInfo_ktri_cert_cmp(), CMS_RecipientInfo_kemri_cert_cmp() et CMS_RecipientInfo_kekri_cmp() retournent 0 pour une comparaison réussie et une valeur non nulle

sinon.

CMS_RecipientInfo_kemri_get0_ctx() et CMS_RecipientInfo_kari_get0_ctx retournent le EVP_CIPHER_CTX du RecipientInfo ou NULL si une erreur s'est

produite.

CMS_RecipientInfo_kemri_get0_kdf_alg() retourne le X509_ALGOR du KDF du RecipientInfo ou NULL si une erreur s'est

produite.

Toute erreur peut être obtenue à partir de ERR_get_

error
(3).
