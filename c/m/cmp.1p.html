CMP(1P) Manuel du programmeur POSIX CMP(1P)

PROLOGUE

Cette page manuelle fait partie du Manuel du programmeur POSIX. L'implémentation Linux de cette interface peut différer (consultez la page man correspondante pour les détails du comportement sous Linux), ou l'interface peut ne pas être implémentée sur Linux.

NOM

cmp — comparer deux fichiers

SYNOPSIS

cmp [-l|-s] fichier1 fichier2

DESCRIPTION

L'utilitaire cmp compare deux fichiers. L'utilitaire cmp ne produit aucune sortie si les fichiers sont identiques. Avec les options par défaut, s'ils diffèrent, il écrit sur la sortie standard l'octet et le numéro de ligne où la première différence est apparue. Les octets et les lignes sont numérotés à partir de 1.

OPTIONS

L'utilitaire cmp doit se conformer aux directives de syntaxe des utilitaires de la section 12.2 du volume des Définitions de base de POSIX.1‐2017. Section 12.2, Directives de syntaxe des utilitaires.

Les options suivantes doivent être prises en charge :

-l
(Minuscule L.) Écrire le numéro d'octet (décimal) et les octets différents (octal) pour chaque différence.
-s
Ne rien écrire sur la sortie standard ni sur l'erreur standard lorsque les fichiers diffèrent ; indiquer les fichiers différents uniquement par le code de retour. Il n'est pas spécifié si un message de diagnostic est écrit sur l'erreur standard lorsqu'une erreur est rencontrée ; si un message n'est pas écrit, l'erreur est indiquée uniquement par le code de retour.

OPÉRANDES

Les opérandes suivantes doivent être prises en charge :

fichier1
Le chemin du premier fichier à comparer. Si fichier1 est '-', l'entrée standard sera utilisée.
fichier2
Le chemin du second fichier à comparer. Si fichier2 est '-', l'entrée standard sera utilisée.

Si à la fois fichier1 et fichier2 font référence à l'entrée standard ou font référence au même fichier spécial FIFO, spécial de bloc ou spécial de caractère, les résultats sont indéfinis.

ENTRÉE STANDARD

L'entrée standard n'est utilisée que si l'opérande fichier1 ou fichier2 fait référence à l'entrée standard. Voir la section FICHIERS EN ENTRÉE.

FICHIERS EN ENTRÉE

Les fichiers en entrée peuvent être de n'importe quel type.

VARIABLES D'ENVIRONNEMENT

Les variables d'environnement suivantes affectent l'exécution de cmp:

LANG
Fournir une valeur par défaut pour les variables d'internationalisation qui ne sont pas définies ou qui sont vides. (Voir le volume des Définitions de base de POSIX.1‐2017, Section 8.2, Variables d'internationalisation pour la priorité des variables d'internationalisation utilisées pour déterminer les valeurs des catégories de locale.)
LC_ALL
Si défini à une valeur de chaîne non vide, remplace les valeurs de toutes les autres variables d'internationalisation.
LC_CTYPE
Déterminer la locale pour l'interprétation des séquences d'octets de données de texte en tant que caractères (par exemple, caractères d'un seul octet par opposition à caractères multi-octets dans les arguments).
LC_MESSAGES

Déterminer la locale qui doit être utilisée pour affecter le format et le contenu des messages de diagnostic écrits sur l'erreur standard et des messages informatifs écrits sur la sortie standard.
NLSPATH
Déterminer l'emplacement des catalogues de messages pour le traitement de LC_MESSAGES.

ÉVÉNEMENTS ASYNCHRONES

Par défaut.

SORTIE STANDARD

Dans la locale POSIX, les résultats de la comparaison sont écrits sur la sortie standard. Lorsqu'aucune option n'est utilisée, le format est le suivant :

"%s %s differ: char %d, line %d\n", fichier1, fichier2,
    <numéro d'octet>, <numéro de ligne>

Lorsque l'option -l est utilisée, le format est le suivant :

"%d %o %o\n", <numéro d'octet>, <octet différent>,
    <octet différent>

pour chaque octet qui diffère. Le premier numéro d'octet différentprovient de fichier1 tandis que le second provient de fichier2. Dans les deux cas, lenuméro d'octetest relatif au début du fichier, en commençant à 1.

Aucune sortie n'est écrite sur la sortie standard lorsque l'option -s est utilisée.

ERREUR STANDARD

L'erreur standard n'est utilisée que pour les messages de diagnostic. Si l'option -l est utilisée et que fichier1 et fichier2 diffèrent en longueur, ou si l'option -s n'est pas utilisée et que fichier1 et fichier2 sont identiques sur toute la longueur du fichier le plus court, le message de diagnostic suivant est écrit dans la locale POSIX :

"cmp: EOF on %s%s\n", <nom du fichier le plus court>, <informations supplémentaires>

Le champ <informations supplémentaires> doit être vide ou une chaîne qui commence par un <espace> et ne contient aucun caractère <retour à la ligne>. Certaines implémentations rapportent le nombre de lignes dans ce cas.

Si l'option -s est utilisée et qu'une erreur se produit, il n'est pas spécifié si un message de diagnostic est écrit sur l'erreur standard.

FICHIERS EN SORTIE

Aucun.

DESCRIPTION ÉTENDUE

Aucune.

CODE DE RETOUR

Les valeurs de retour suivantes doivent être renvoyées :

0
Les fichiers sont identiques.
1
Les fichiers sont différents ; cela inclut le cas où un fichier est identique à la première partie de l'autre.
>1
Une erreur s'est produite.

CONSÉQUENCES DES ERREURS

Par défaut.

Les sections suivantes sont informatives.

UTILISATION DANS LES APPLICATIONS

Bien que les fichiers en entrée de cmp puissent être de n'importe quel type, les résultats peuvent ne pas être ceux que l'on attendrait sur des fichiers de périphériques spéciaux de caractère ou sur des types de fichiers non décrits par le volume des Interfaces système de POSIX.1‐2017. Puisque ce volume de POSIX.1‐2017 ne spécifie pas la taille de bloc utilisée lors des entrées, les comparaisons de fichiers spéciaux de caractère n'ont pas besoin de comparer toutes les données de ces fichiers.

Pour les fichiers qui ne sont pas des fichiers texte, les numéros de ligne reflètent simplement la présence d'un <retour à la ligne>, sans aucune implication que le fichier est organisé en lignes.

Puisque le comportement de -s diffère entre les implémentations quant à l'écriture des messages d'erreur, la seule façon d'assurer un comportement cohérent de cmp lorsque -s est utilisé est de rediriger l'erreur standard vers /dev/null.

Si les messages d'erreur sont souhaités, au lieu d'utiliser -s la sortie standard devrait être redirigée vers /dev/null, et tout ce qui est écrit sur l'erreur standard devrait être ignoré si le code de retour est 1. Par exemple :

silent_cmp() {
    # comparer les fichiers sans sortie sauf les messages d'erreur
    message=$(cmp "$@" 2>&1 >/dev/null)
    status=$?
    case $status in
    (0|1) ;;
    (*) printf '%s\n'"$message" ;;
    esac
    return $status
}

EXEMPLES

Aucun.

RATIONALE

Le langage global de la Section 1.4, Défauts de description des utilitaires, indique que l'utilisation de deux options mutuellement exclusives produit des résultats non spécifiés. Certaines implémentations System V considèrent l'utilisation des options suivante :

cmp -l -s ...

comme une erreur. Elles traitent également :

cmp -s -l ...

comme si aucune option n'était spécifiée. Ces deux comportements sont considérés comme des bogues, mais sont autorisés.

Le mot char dans le format de sortie standard provient d'un usage historique, même s'il s'agit en réalité d'un nombre d'octets. Lorsque cmp est pris en charge dans d'autres localisations, il est encouragé aux implémentations d'utiliser le mot byte ou son équivalent dans une autre langue. Les utilisateurs ne doivent pas interpréter cette différence comme indiquant que la fonctionnalité de l'utilitaire a changé entre les localisations.

Certaines implémentations signalent le nombre de lignes dans le cas du fichier identique mais plus court. Ceci est autorisé par l'inclusion des champs <informations supplémentaires> dans le format de sortie. La restriction sur un <espace> initial et l'absence de caractères de fin de ligne (<newline>) vise à faciliter l'analyse du nom de fichier. Il est reconnu que certains noms de fichiers contenant des caractères d'espacement rendent l'analyse difficile de toute façon, mais la restriction aide les programmes utilisés sur des systèmes où les noms sont majoritairement bien comportés.

DIRECTIONS FUTURES

Les futures versions de cette norme peuvent exiger que les messages de diagnostic soient écrits sur la sortie d'erreur standard lorsque l'option -s est spécifiée.
