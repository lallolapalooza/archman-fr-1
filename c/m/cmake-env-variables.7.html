La variable d'environnement CMAKE_INSTALL_MODE permet aux utilisateurs de faire fonctionner CMake dans un mode alternatif de file(INSTALL) <#install> et install() <#command:install>

Le comportement par défaut d'une installation est de copier un fichier source d'un répertoire source

vers un répertoire de destination. Cependant, cette variable d'environnement permet à l'utilisateu

d'utilisation

Installer des liens symboliques plutôt que de copier des fichiers peut aider de plusieurs manières

    • disque.
  • Les modifications de la source du lien symbolique sont visibles à la destination d'installation sans avoir à relancer l'étape
    • d'installation.
  • Modifier via le lien à la destination d'installation modifiera la source du lien. Cela peut être utile lors de la gestion de hiérarchies de projets CMake, c'est-à-dire en utilisant ExternalProject <#module:ExternalProject> et

Mises en

garde

Utilisez cette variable d'environnement avec prudence. Les points suivants mettent en évidence certains points à considérer

:
  • CMAKE_INSTALL_MODE n'affecte que les fichiers, pas les
    • répertoires.
  • Les liens symboliques ne sont pas disponibles sur toutes les
    • plateformes.
  • La manière dont cette variable d'environnement interagit avec l'étape d'installation de ExternalProject <#module:ExternalProject> est plus complexe. Pour plus de détails, consultez la documentation de ce
    • module.
  • Un lien symbolique lie la destination à la source de manière persistante. Écrire dans l'un des deux affecte les deux objets du système de fichiers. Cela contraste avec le comportement d'installation normal qui ne fait que copier les fichiers tels qu'ils étaient au moment où l'installation a été effectuée, sans relation durable entre la source et la destination de
    • l'installation.
  • Combiner CMAKE_INSTALL_MODE avec IOS_INSTALL_COMBINED <#prop_tgt:IOS_INSTALL_COMBINED> n'est pas pris en charge.
  • La modification de CMAKE_INSTALL_MODE par rapport à une exécution précédente peut entraîner des résultats inattendus. Le passage d'un mode sans liens symboliques à un mode avec liens symboliques supprimera tout fichier précédent à la destination, mais l'inverse n'est pas vrai. Une fois qu'un lien symbolique existe à la destination, même si vous passez à un mode sans liens symboliques, le lien symbolique continuera d'exister à la destination et ne sera pas remplacé par un fichier réel.

DESTDIR

Ceci est une variable d'environnement CMake <#cmake-language-environment-variables>. Sa valeur initiale est prise de l'environnement du processus appelant.

Sur UNIX, on peut utiliser le mécanisme DESTDIR afin de déplacer l'ensemble de l'installation. DESTDIR signifie DESTination DIRectory (Répertoire de DESTination). Il est couramment utilisé par les créateurs de paquets pour installer des logiciels dans un répertoire de staging.

Par exemple, exécuter

make DESTDIR=/package/stage install

installera le logiciel en utilisant le préfixe d'installation, par exemple /usr/local, précédé de la valeur DESTDIR, ce qui donne /package/stage/usr/local. L'outil d'empaquetage peut alors construire le paquet à partir du contenu du répertoire /package/stage.

Voir la variable CMAKE_INSTALL_PREFIX <#variable:CMAKE_INSTALL_PREFIX> pour contrôler le préfixe d'installation lors de la configuration d'un arbre de construction. Ou, lors de l'utilisation du mode --install <#cmdoption-cmake-install> de l'outil en ligne de commande cmake(1) <#manual:cmake(1)>, on peut spécifier un préfixe différent en utilisant l'option --prefix <#cmdoption-cmake--install-0>.

Remarque :

DESTDIR ne peut pas être utilisé sous Windows car le préfixe d'installation contient généralement une lettre de lecteur comme dans C:/Program Files qui ne peut pas être précédée d'un autre préfixe.

18.

Détermine quelles couleurs sont utilisées par l'interface curses de CMake, lorsqu'elle est exécutée sur un terminal prenant en charge les couleurs. La syntaxe suit les mêmes conventions que LS_COLORS ; c'est-à-dire une liste de paires clé/valeur séparées par :

.

Les clés sont une lettre unique correspondant à un type de variable de cache CMake

:
  • s : une STRIN
    • G.
  • p : une FILEPAT
    • H.
  • c : une valeur qui a une liste de choix
    • associée.
  • y : un BOOL qui a une valeur de type vrai (par ex. ON, YES
    • ).
  • n : un BOOL qui a une valeur de type faux (par ex. OFF, NO
)
.

Les valeurs sont un nombre entier spécifiant quelle couleur utiliser. 0 est le noir (vous ne voulez probablement pas l'utiliser). Les autres sont déterminées par la prise en charge des couleurs de votre terminal. La plupart des terminaux (en couleur) prennent en charge au moins 8 ou 16 couleurs. Certains en prennent en charge jusqu'à 256. Les couleurs correspondront probablement à ce graphique https://upload.wikimedia.org/wikipedia/commons/1/15/Xterm_256color_chart.svg, bien que les 16 premières couleurs puissent correspondre à la palette de couleurs CGA originale https://en.wikipedia.org/wiki/Color_Graphics_Adapter#Color_palette. (De nombreux émulateurs de terminaux modernes permettent également que leur palette de couleurs, au moins pour les 16 premières couleurs, soit configurée par l'utilisateur.

)

Notez qu'un contrôle assez minimal est effectué pour les couleurs invalides (bien qu'une valeur supérieure à ce que curses croit que votre terminal prend en charge sera silencieusement ignorée) ou pour une syntaxe

invalide.
