NOM

cmake-presets - CMakePresets.json

INTRODUCTION

Ajouté dans la version 3.19.

Un problème que les utilisateurs de CMake rencontrent souvent est le partage des paramètres avec d'autres personnes pour des façons courantes de configurer un projet. Cela peut être fait pour prendre en charge les compilations CI, ou pour les utilisateurs qui utilisent fréquemment la même compilation. CMake prend en charge deux fichiers principaux, CMakePresets.json et CMakeUserPresets.json, qui permettent aux utilisateurs de spécifier des options de configuration courantes et de les partager avec d'autres. CMake prend également en charge les fichiers inclus avec le champ include .

CMakePresets.json et CMakeUserPresets.json se trouvent dans le répertoire racine du projet. Ils ont tous deux exactement le même format et sont tous deux facultatifs (bien qu'au moins un doive être présent si --preset <#cmdoption-cmake-preset> est spécifié). CMakePresets.json est destiné à spécifier les détails de compilation à l'échelle du projet, tandis que CMakeUserPresets.json est destiné aux développeurs pour spécifier leurs propres détails de compilation locaux.

CMakePresets.json peut être versionné dans un système de contrôle de versions, et CMakeUserPresets.json ne doit PAS être versionné. Par exemple, si un projet utilise Git, CMakePresets.json peut être suivi, et CMakeUserPresets.json devrait être ajouté au .gitignore.

Une chaîne obligatoire représentant le nom convivial pour la machine du préréglage. Cet identifiant est utilisé dans l'option cmake --build --preset <#build-tool-mode>. Il ne doit pas y avoir deux préréglages de build dans l'union de CMakePresets.json et CMakeUserPresets.json dans le même répertoire avec le même nom. Cependant, un préréglage de build peut avoir le même nom qu'un préréglage de configuration, de test, de paquetage ou de workflow.

Un booléen facultatif spécifiant si un préréglage doit être masqué ou non. Si un préréglage est masqué, il ne peut pas être utilisé dans l'argument --preset <#cmdoption-cmake-preset> et n'a pas besoin d'avoir un configurePresetvalide, même par héritage. Les préréglages hidden sont destinés à être utilisés comme base pour d'autres préréglages à hériter via le champ inherits .

Un tableau facultatif de chaînes représentant les noms des préréglages à hériter. Ce champ peut aussi être une chaîne, ce qui est équivalent à un tableau contenant une chaîne.

Un préréglage ne peut hériter que d'un autre préréglage défini dans le même fichier ou dans l'un des fichiers qu'il inclut (directement ou indirectement). Les préréglages dans CMakePresets.json ne peuvent pas hériter de préréglages dans CMakeUserPresets.json.

Build Preset

Each entry of the buildPresets array is a JSON object that may contain the following fields:

name
A required string representing the machine-friendly name of the preset. This identifier is used in the cmake --build <dir> --preset <name> option. There must not be two build presets in the union of CMakePresets.json and CMakeUserPresets.json in the same directory with the same name. However, a build preset may have the same name as a configure, test, package, or workflow preset.
hidden
An optional boolean specifying whether or not a preset should be hidden. If a preset is hidden, it cannot be used in the --preset <#cmdoption-cmake-build-preset> argument and does not have to have a valid configurePreset, even from inheritance. hidden presets are intended to be used as a base for other presets to inherit via the inherits field.
inherits
An optional array of strings representing the names of presets to inherit from. This field can also be a string, which is equivalent to an array containing one string.

The preset will inherit all of the fields from the inherits presets by default (except name, hidden, inherits, description, and displayName), but can override them as desired. If multiple inherits presets provide conflicting values for the same field, the earlier preset in the inherits array will be preferred.

A preset can only inherit from another preset that is defined in the same file or in one of the files it includes (directly or indirectly). Presets in CMakePresets.json may not inherit from presets in CMakeUserPresets.json.

condition
An optional Condition object. This is allowed in preset files specifying version 3 or above.
vendor
An optional map containing vendor-specific information. CMake does not interpret the contents of this field except to verify that it is a map if it does exist. However, it should follow the same conventions as the root-level vendor field. If vendors use their own per-preset vendor field, they should implement inheritance in a sensible manner when appropriate.
displayName
An optional string with a human-friendly name of the preset.
description
An optional string with a human-friendly description of the preset.
environment
An optional map of environment variables. The key is the variable name (which may not be an empty string), and the value is either null or a string representing the value of the variable. Each variable is set regardless of whether or not a value was given to it by the process's environment.

This field supports macro expansion, and environment variables in this map may reference each other, and may be listed in any order, as long as such references do not cause a cycle (for example, if ENV_1 is $env{ENV_2}, ENV_2 may not be $env{ENV_1}). $penv{NAME} allows one to prepend or append values to existing environment variables by accessing only values from the parent environment.

Environment variables are inherited through the inherits field, and the preset's environment will be the union of its own environment and the environment from all its parents. If multiple presets in this union define the same variable, the standard rules of inherits are applied. Setting a variable to null causes it to not be set, even if a value was inherited from another preset.

configurePreset
An optional string specifying the name of a configure preset to associate with this build preset. If configurePreset is not specified, it must be inherited from the inherits preset (unless this preset is hidden). The build directory is inferred from the configure preset, so the build will take place in the same binaryDir that the configuration did.
inheritConfigureEnvironment
An optional boolean that defaults to true. If true, the environment variables from the associated configure preset are inherited after all inherited build preset environments, but before environment variables explicitly specified in this build preset.
jobs
An optional integer. Equivalent to passing --parallel <#cmdoption-cmake-build-j> or -j on the command line.
targets
An optional string or array of strings. Equivalent to passing --target <#cmdoption-cmake-build-t> or -t on the command line. Vendors may ignore the targets property or hide build presets that explicitly specify targets. This field supports macro expansion.
configuration
An optional string. Equivalent to passing --config <#cmdoption-cmake-build-config> on the command line.
cleanFirst
An optional bool. If true, equivalent to passing --clean-first <#cmdoption-cmake-build-clean-first> on the command line.
resolvePackageReferences
An optional string that specifies the package resolve mode. This is allowed in preset files specifying version 4 or above.

Package references are used to define dependencies to packages from external package managers. Currently only NuGet in combination with the Visual Studio generator is supported. If there are no targets that define package references, this option does nothing. Valid values are:

on
Causes package references to be resolved before attempting a build.
off
Package references will not be resolved. Note that this may cause errors in some build environments, such as .NET SDK style projects.
only
Only resolve package references, but do not perform a build.

Note:

The command line parameter --resolve-package-references <#cmdoption-cmake-build-resolve-package-references> will take priority over this setting. If the command line parameter is not provided and this setting is not specified, an environment-specific cache variable will be evaluated to decide, if package restoration should be performed.

When using the Visual Studio generator, package references are defined using the VS_PACKAGE_REFERENCES <#prop_tgt:VS_PACKAGE_REFERENCES> property. Package references are restored using NuGet. It can be disabled by setting the CMAKE_VS_NUGET_PACKAGE_RESTORE variable to OFF. This can also be done from within a configure preset.

verbose
An optional bool. If true, equivalent to passing --verbose <#cmdoption-cmake-build-v> on the command line.
nativeToolOptions
An optional array of strings. Equivalent to passing options after -- on the command line. The array values support macro expansion.

Package Preset

Les préréglages de paquet peuvent être utilisés dans la version de schéma 6 ou supérieure. Chaque entrée du tableau packagePresets est un objet JSON qui peut contenir les champs suivants :

name
Une chaîne requise représentant le nom convivial pour la machine du préréglage. Cet identifiant est utilisé dans l'option cpack --preset <#cmdoption-cpack-preset>. Il ne doit pas y avoir deux préréglages de paquet dans l'union de CMakePresets.json et CMakeUserPresets.json dans le même répertoire avec le même nom. Cependant, un préréglage de paquet peut avoir le même nom qu'un préréglage de configuration, de compilation, de test ou de flux de travail.
hidden
Un booléen optionnel spécifiant si un préréglage doit être masqué ou non. Si un préréglage est masqué, il ne peut pas être utilisé dans l'argument --preset <#cmdoption-cpack-preset> et n'a pas besoin d'avoir un configurePresetvalide, même par héritage. hidden Les préréglages sont destinés à être utilisés comme base pour d'autres préréglages qui en héritent via le champ inherits .
inherits
Un tableau optionnel de chaînes représentant les noms des préréglages dont hériter. Ce champ peut aussi être une chaîne, ce qui est équivalent à un tableau contenant une seule chaîne.

Le préréglage héritera par défaut de tous les champs des préréglages inherits (sauf name, hidden, inherits, descriptionet displayName), mais peut les remplacer selon les besoins. Si plusieurs préréglages inherits fournissent des valeurs conflictuelles pour le même champ, le préréglage le plus ancien dans le tableau inherits sera préféré.

Un préréglage ne peut hériter que d'un autre préréglage défini dans le même fichier ou dans l'un des fichiers qu'il inclut (directement ou indirectement). Les préréglages dans CMakePresets.json ne peuvent pas hériter des préréglages dans CMakeUserPresets.json.

condition
Un objet Condition optionnel.
vendor
Une map optionnelle contenant des informations spécifiques au fournisseur. CMake n'interprète pas le contenu de ce champ, sauf pour vérifier qu'il s'agit d'une map si celui-ci existe. Cependant, il devrait suivre les mêmes conventions que le champ vendor de niveau racine. Si les fournisseurs utilisent leur propre champ vendor par préréglage, ils devraient implémenter l'héritage de manière raisonnable lorsque c'est approprié.
displayName
Une chaîne optionnelle avec un nom convivial pour le préréglage.
description
Une chaîne optionnelle avec une description conviviale du préréglage.
environment
Une map optionnelle de variables d'environnement. La clé est le nom de la variable (qui ne peut pas être une chaîne vide), et la valeur est soit null soit une chaîne représentant la valeur de la variable. Chaque variable est définie que la valeur lui ait été donnée ou non par l'environnement du processus.

Ce champ prend en charge l'expansion de macro, et les variables d'environnement dans cette map peuvent se référencer mutuellement, et peuvent être listées dans n'importe quel ordre, à condition que ces références ne créent pas de cycle (par exemple, si ENV_1 est $env{ENV_2}, ENV_2 ne peut pas être $env{ENV_1}). $penv{NAME} permet d'ajouter ou de préfixer des valeurs aux variables d'environnement existantes en n'accédant qu'aux valeurs de l'environnement parent.

Les variables d'environnement sont héritées via le champ inherits , et l'environnement du préréglage sera l'union de son propre environment et du environment de tous ses parents. Si plusieurs préréglages dans cette union définissent la même variable, les règles standard de inherits sont appliquées. Définir une variable à null la rend non définie, même si une valeur a été héritée d'un autre préréglage.

configurePreset
Une chaîne optionnelle spécifiant le nom d'un préréglage de configuration à associer à ce préréglage de paquet. Si configurePreset n'est pas spécifié, il doit être hérité du préréglage inherits (sauf si ce préréglage est masqué). Le répertoire de build est déduit du préréglage de configuration, donc le packaging s'exécutera dans le même binaryDir que celui de la configuration et de la compilation.
inheritConfigureEnvironment
Un booléen optionnel dont la valeur par défaut est vrai. Si vrai, les variables d'environnement du préréglage de configuration associé sont héritées après tous les environnements des préréglages de paquet hérités, mais avant les variables d'environnement explicitement spécifiées dans ce préréglage de paquet.
generators
Un tableau optionnel de chaînes représentant les générateurs que CPack doit utiliser.
configurations
Un tableau optionnel de chaînes représentant les configurations de build que CPack doit empaqueter.
variables
Une map optionnelle de variables à passer à CPack, équivalente aux arguments -D <#cmdoption-cpack-D>. Chaque clé est le nom d'une variable, et la valeur est la chaîne à assigner à cette variable.
configFile
Une chaîne optionnelle représentant le fichier de configuration que CPack doit utiliser.
output
Un objet optionnel spécifiant les options de sortie. Les clés valides sont :
debug
Un booléen optionnel spécifiant s'il faut imprimer des informations de débogage ou non. Une valeur de true est équivalente à passer --debug <#cmdoption-cpack-debug> sur la ligne de commande.
verbose
Un booléen optionnel spécifiant s'il faut imprimer de manière verbeuse ou non. Une valeur de true est équivalente à passer --verbose <#cmdoption-cpack-V> sur la ligne de commande.
packageName
Une chaîne optionnelle représentant le nom de la paquet.

packageVersion
Une chaîne optionnelle représentant la version de la paquet.

Note :

En raison de problèmes avec l'implémentation, ce champ n'affecte pas le nom du fichier de paquet final produit. D'autres aspects de la paquet peuvent utiliser la valeur, entraînant des incohérences. Une future version de CMake peut résoudre ce problème, mais d'ici là, il est recommandé de ne pas utiliser ce champ.
packageDirectory
Une chaîne optionnelle représentant le répertoire dans lequel placer la paquet.
vendorName
Une chaîne optionnelle représentant le nom du fournisseur.

Condition

Le champ condition d'un preset, autorisé dans les fichiers de presets spécifiant la version 3 ou supérieure, est utilisé pour déterminer si le preset est activé ou non. Par exemple, cela peut être utilisé pour désactiver un preset sur des plateformes autres que Windows. condition peut être un booléen, null, ou un objet. S'il s'agit d'un booléen, le booléen indique si le preset est activé ou désactivé. S'il s'agit de null, le preset est activé, mais la condition null n'est pas héritée par les presets qui pourraient hériter du preset. Les sous-conditions (par exemple dans une condition not, anyOf ou allOf) ne peuvent pas être null. S'il s'agit d'un objet, il a les champs suivants :

type
Une chaîne de caractères requise avec l'une des valeurs suivantes :
"const"
Indique que la condition est constante. Ceci est équivalent à utiliser un booléen à la place de l'objet. L'objet de condition aura les champs supplémentaires suivants :
value
Un booléen requis qui fournit une valeur constante pour l'évaluation de la condition.

"equals"

"notEquals"
Indique que la condition compare deux chaînes pour voir si elles sont égales (ou inégales). L'objet de condition aura les champs supplémentaires suivants :
lhs
Première chaîne à comparer. Ce champ prend en charge l'expansion des macros.

Deuxième chaîne à comparer. Ce champ prend en charge l'expansion des macros.

Indique que la condition recherche une chaîne dans une liste de chaînes. L'objet de condition aura les champs supplémentaires suivants :
string
Une chaîne de caractères requise à rechercher. Ce champ prend en charge l'expansion des macros.

Indique que la condition recherche une expression régulière dans une chaîne. L'objet de condition aura les champs supplémentaires suivants :

Une expression régulière requise à rechercher. Ce champ prend en charge l'expansion des macros.

Expansion des macros

Comme mentionné ci-dessus, certains champs prennent en charge l'expansion des macros. Les macros sont reconnues sous la forme $<espace-de-nom-macro>{<nom-de-macro>}. Toutes les macros sont évaluées dans le contexte du preset utilisé, même si la macro se trouve dans un champ hérité d'un autre preset. Par exemple, si le preset Base définit la variable PRESET_NAME sur ${presetName}, et que le preset Derived hérite de Base, PRESET_NAME sera défini sur Derived.

Il est erroné de ne pas mettre une accolade fermante à la fin d'un nom de macro. Par exemple, ${sourceDir est invalide. Un signe dollar ($) suivi de tout autre caractère qu'une accolade gauche ({) avec un espace de nom potentiel est interprété comme un signe dollar littéral.

Les macros reconnues incluent :

${sourceDir}
Chemin vers le répertoire source du projet (c'est-à-dire le même que CMAKE_SOURCE_DIR <#variable:CMAKE_SOURCE_DIR>).
${sourceParentDir}
Chemin vers le répertoire parent du répertoire source du projet.
${sourceDirName}
Le dernier composant du nom de fichier de ${sourceDir}. Par exemple, si ${sourceDir} est /chemin/vers/source, ce sera source.
${presetName}
Nom spécifié dans le champ name du preset.

Ceci est une macro spécifique au preset.

${generator}
Générateur spécifié dans le champ generator du preset. Pour les presets de build et de test, cela sera évalué au générateur spécifié par configurePreset.

Ceci est une macro spécifique au preset.

${hostSystemName}
Le nom du système d'exploitation hôte. Contient la même valeur que CMAKE_HOST_SYSTEM_NAME <#variable:CMAKE_HOST_SYSTEM_NAME>. Ceci est autorisé dans les fichiers de presets spécifiant la version 3 ou supérieure.
${fileDir}
Chemin vers le répertoire contenant le fichier de preset qui contient la macro. Ceci est autorisé dans les fichiers de presets spécifiant la version 4 ou supérieure.
${dollar}
Un signe dollar littéral ($).
${pathListSep}
Caractère natif pour séparer les listes de chemins, tel que : ou ;.

Par exemple, en définissant PATH sur /chemin/vers/ninja/bin${pathListSep}$env{PATH}, ${pathListSep} sera développé en caractère du système d'exploitation sous-jacent utilisé pour la concaténation dans PATH.

Ceci est autorisé dans les fichiers de presets spécifiant la version 5 ou supérieure.

$env{<nom-variable>}
Variable d'environnement avec le nom <nom-variable>. Le nom de la variable ne peut pas être une chaîne vide. Si la variable est définie dans le champ environment, cette valeur est utilisée à la place de la valeur de l'environnement parent. Si la variable d'environnement n'est pas définie, cela est évalué comme une chaîne vide.

Notez que bien que les noms de variables d'environnement Windows soient insensibles à la casse, les noms de variables dans un preset restent sensibles à la casse. Cela peut entraîner des résultats inattendus lors de l'utilisation d'une casse incohérente. Pour de meilleurs résultats, conservez la casse des noms de variables d'environnement cohérente.

$penv{<nom-variable>}
Similaire à $env{<nom-variable>}, sauf que la valeur provient uniquement de l'environnement parent, et jamais du champ environment. Cela permet de préfixer ou suffixer des valeurs aux variables d'environnement existantes. Par exemple, définir PATH sur /chemin/vers/ninja/bin:$penv{PATH} ajoutera /chemin/vers/ninja/bin au début de la variable d'environnement PATH. Ceci est nécessaire car $env{<nom-variable>} ne permet pas les références circulaires.
$vendor{<nom-macro>}
Un point d'extension pour les vendeurs afin d'insérer leurs propres macros. CMake ne sera pas en mesure d'utiliser les presets qui ont une macro $vendor{<nom-macro>}, et ignore effectivement ces presets. Cependant, il pourra toujours utiliser d'autres presets du même fichier.

CMake ne fait aucune tentative d'interprétation des macros $vendor{<nom-macro>}. Cependant, pour éviter les collisions de noms, les vendeurs d'IDE devraient préfixer <nom-macro> avec un identifiant de vendeur très court (de préférence <= 4 caractères), suivi d'un ., suivi du nom de la macro. Par exemple, l'IDE Exemple pourrait avoir $vendor{xide.ideInstallDir}.
