CMS_encrypt(3ssl)

Paquet: openssl

Licences: Apache-2.0

CMS_ENCRYPT(3ssl) OpenSSL CMS_ENCRYPT(3ssl)

NOM

CMS_encrypt_ex, CMS_encrypt - créer une structure envelopedData CMS

SYNTAXIS

#include <openssl/cms.h>
CMS_ContentInfo *CMS_encrypt_ex(STACK_OF(X509) *certs, BIO *in,
                                const EVP_CIPHER *cipher, unsigned int flags,
                                OSSL_LIB_CTX *libctx, const char *propq);
CMS_ContentInfo *CMS_encrypt(STACK_OF(X509) *certs, BIO *in,
                             const EVP_CIPHER *cipher, unsigned int flags);

DESCRIPTION

CMS_encrypt_ex() crée et retourne une structure CMS EnvelopedData ou AuthEnvelopedData. certs est une liste de certificats destinataires. in est le contenu à chiffrer. cipher est le chiffrement symétrique à utiliser. flags est un ensemble optionnel d'indicateurs. Le contexte de bibliothèque libctx et la requête de propriétés propq sont utilisés en interne lors de la récupération des algorithmes auprès des fournisseurs.

Seuls les certificats portant des clés RSA, Diffie-Hellman ou EC sont pris en charge par cette fonction.

EVP_des_ede3_cbc() (triple DES) est l'algorithme de choix pour l'utilisation S/MIME car la plupart des clients le prendront en charge.

L'algorithme passé dans le paramètre cipher doit prendre en charge l'encodage ASN1 de ses paramètres. Si le mode de chiffrement est GCM, alors une structure AuthEnvelopedData contenant le MAC est utilisée. Sinon, une structure EnvelopedData est utilisée. Actuellement, les variantes AES en mode GCM sont les seuls algorithmes AEAD pris en charge.

De nombreux navigateurs implémentent une option "signer et chiffrer" qui n'est qu'une structure envelopedData S/MIME contenant un message signé S/MIME. Cela peut être facilement produit en stockant le message signé S/MIME dans un BIO mémoire et en le passant à CMS_encrypt().

Les indicateurs suivants peuvent être passés dans le paramètre flags.

Si l'indicateur CMS_TEXT est défini, les en-têtes MIME pour le type text/plain sont ajoutés avant les données.

Normalement, le contenu fourni est traduit au format canonique MIME (comme requis par les spécifications S/MIME) ; si CMS_BINARY est défini, aucune traduction n'a lieu. Cette option doit être utilisée si les données fournies sont au format binaire, sinon la traduction les corrompra. Si CMS_BINARY est défini, alors CMS_TEXT est ignoré.

OpenSSL identifiera par défaut les certificats destinataires en utilisant le nom de l'émetteur et le numéro de série. Si CMS_USE_KEYID est défini, il utilisera plutôt l'identifiant de clé du sujet. Une erreur se produit si tous les certificats destinataires n'ont pas d'extension d'identifiant de clé du sujet.

Si l'indicateur CMS_STREAM est défini, une structure CMS_ContentInfo partielle est retournée, adaptée aux E/S en flux : aucune donnée n'est lue à partir du BIO in.

Si l'indicateur CMS_PARTIAL est défini, une structure CMS_ContentInfo partielle est retournée à laquelle des destinataires et des attributs supplémentaires peuvent être ajoutés avant la finalisation.

Les données en cours de chiffrement sont incluses dans la structure CMS_ContentInfo, sauf si CMS_DETACHED est défini, auquel cas elles sont omises. Ceci est rarement utilisé en pratique et n'est pas pris en charge par SMIME_write_CMS().

Si l'indicateur CMS_STREAM est défini, la structure CMS_ContentInfo retournée n'est pas complète et la sortie de son contenu via une fonction qui ne finalise pas correctement la structure CMS_ContentInfo donnera des résultats imprévisibles.

Plusieurs fonctions, y compris SMIME_write_CMS(), i2d_CMS_bio_stream(), PEM_write_bio_CMS_stream(), finalisent la structure. Alternativement, la finalisation peut être effectuée en obtenant directement le BIO ASN1 de flux en utilisant BIO_new_CMS().

Les destinataires spécifiés dans certs utilisent une structure d'information CMS KeyTransRecipientInfo. KEKRecipientInfo est également pris en charge en utilisant l'indicateur CMS_PARTIAL et CMS_add0_recipient_key(). KEMRecipientInfo est également pris en charge en utilisant l'indicateur CMS_PARTIAL et CMS_add1_recipient().

Le paramètre certs peut être NULL si CMS_PARTIAL est défini et que les destinataires sont ajoutés plus tard en utilisant CMS_add1_recipient() ou CMS_add1_recipient_cert() avec CMS_add0_recipient_key().

CMS_encrypt() est similaire à CMS_encrypt_ex() mais utilise les valeurs par défaut NULL pour le contexte de bibliothèque libctx et la requête de propriétés propq.

VALEURS DE RETOUR

CMS_encrypt_ex() et CMS_encrypt() retournent soit une structure CMS_ContentInfo, soit NULL si une erreur s'est produite. L'erreur peut être obtenue à partir de ERR_get_error(3).

VOIR AUSSI

ERR_get_error(3), CMS_decrypt(3)

HISTORIQUE

La fonction CMS_encrypt_ex() a été ajoutée dans OpenSSL 3.0.

L'indicateur CMS_STREAM a été pris en charge pour la première fois dans OpenSSL 1.0.0.
