DESCRIPTIO

N

Ces macros sont utilisées pour créer et accéder aux messages de contrôle (également appelés données auxiliaires) qui ne font pas partie de la charge utile du socket. Ces informations de contrôle peuvent inclure l'interface sur laquelle le paquet a été reçu, divers champs d'en-tête rarement utilisés, une description de l'erreur étendue, un ensemble de descripteurs de fichiers ou des identifiants UNIX. Par exemple, les messages de contrôle peuvent être utilisés pour envoyer des champs d'en-tête supplémentaires tels que les options IP. Les données auxiliaires sont envoyées en appelant sendmsg(2) et reçues en appelant recvmsg(2). Consultez leurs pages manuelles pour plus

d'informations.

Les données auxiliaires sont une séquence de structures cmsghdr avec des données annexées. Consultez les pages manuelles des protocoles spécifiques pour connaître les types de messages de contrôle disponibles. La taille maximale du tampon auxiliaire autorisée par socket peut être définie à l'aide de /proc/sys/net/core/optmem_max ; voir socket(

7).

La structure cmsghdr est définie comme suit 

: 


struct cmsghdr {
    size_t cmsg_len;    /* Nombre d'octets de données, en-tête inclus
                           (le type est socklen_t en POSIX) */
    int    cmsg_level;  /* Protocole d'origine */
    int    cmsg_type;   /* Type spécifique au protocole */
/* suivi de
   unsigned char cmsg_data[]; */
}
;

La séquence de structures cmsghdr ne doit jamais être accédée directement. Utilisez plutôt uniquement les macros suivantes 

:
CMSG_FIRSTHD
R()
renvoie un pointeur vers la première cmsghdr dans le tampon de données auxiliaires associé au msghdr transmis. Elle renvoie NULL s'il n'y a pas assez de place pour une cmsghdr dans le
tampon.
CMSG_NXTHDR
()
renvoie la prochaine cmsghdr valide après la cmsghdr transmise. Elle renvoie NULL lorsq
u'il ne reste pas assez
de place dans le tampon.
Lors de l'initialisation d'un tampon qui contiendra une série de structures cmsghdr (par exemple, pour être envoyé avec sendmsg(2)), ce tampon doit d'abord être initialisé à zéro pour garantir le bon fonctionnement de CMSG_NX
THD
R().
CMSG_ALIG
N(),
étant donné une longueur, la renvoie en incluant l'alignement requis. Il s'agit d'une expression
constante.
CMSG_SPACE
()
renvoie le nombre d'octets occupés par un élément auxiliaire dont la charge utile a la longueur de données transmise. Il s'agit d'une expression
constante.
CMSG_DATA
()
renvoie un pointeur vers la partie données d'une cmsghdr. Le pointeur renvoyé ne peut pas être supposé correctement aligné pour accéder à des types de données de charge utile arbitraires. Les applications ne doivent pas le convertir en un type de pointeur correspondant à la charge utile, mais doivent plutôt utiliser memcpy(3) pour copier des données vers ou depuis un objet correctement
déclaré.
CMSG_LEN
()
renvoie la valeur à stocker dans le membre cmsg_len de la structure cmsghdr, en tenant compte de tout alignement nécessaire. Elle pr
end la longueur des données comme argumen
t. Il s'agit d'une expression constante.

Pour créer des données auxiliaires, initialisez d'abord le membre msg_controllen du msghdr avec la longueur du tampon de message de contrôle. Utilisez CMSG_FIRSTHDR() sur le msghdr pour obtenir le premier message de contrôle et CMSG_NXTHDR() pour obtenir tous les suivants. Dans chaque message de contrôle, initialisez cmsg_len (avec CMSG_LEN()), les autres champs d'en-tête cmsghdr et la partie données à l'aide de CMSG_DATA(). Enfin, le champ msg_controllen du msghdr doit être défini à la somme des CMSG_SPACE() de la longueur de tous les messages de contrôle dans le tampon. g(
2).

VERSION

S

Pour la portabilité, les données auxiliaires doivent être accédées uniquement à l'aide des macros décrites

ici.

Dans Linux, CMSG_LEN(), CMSG_DATA() et CMSG_ALIGN() sont des expressions constantes (en supposant que leur argument est constant), ce qui signifie que ces va

leurs peuvent être utilisées pour déclarer la taille de
variables globales. Cela peut toutefois ne pas être portable.

HISTORIQU

E

Ce modèle de données auxiliaires est conforme au brouillon POSIX.1g, 4.4BSD-Lite, à l'API avancée IPv6 décrite dans la RFC 2292 et à

SUSv2.

CMSG_SPACE() et CMSG_LEN() seront incluses dans la prochaine version de POSIX (Issue

8)

EXEMPLE

S

Ce code recherche l'option IP_TTL dans un tampon auxiliaire reçu 

: 


struct msghdr msgh;
struct cmsghdr *cmsg;
int received_ttl;
/* Recevoir les données auxiliaires dans msgh */
for (cmsg = CMSG_FIRSTHDR(&msgh); cmsg != NULL;
        cmsg = CMSG_NXTHDR(&msgh, cmsg)) {
    if (cmsg->cmsg_level == IPPROTO_IP
            && cmsg->cmsg_type == IP_TTL) {
        memcpy(&receive_ttl, CMSG_DATA(cmsg), sizeof(received_ttl));
        break;
    }
}
if (cmsg == NULL) {
    /* Erreur : IP_TTL non activé ou tampon trop petit ou erreur d'E/S */
}
