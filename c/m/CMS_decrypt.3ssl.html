NOM

CMS_decrypt, CMS_decrypt_set1_pkey_and_peer, CMS_decrypt_set1_pkey, CMS_decrypt_set1_password - déchiffre le contenu d'une structure CMS enveloppedData

SYNOPSISSE

#include <openssl/cms.h>
int CMS_decrypt(CMS_ContentInfo *cms, EVP_PKEY *pkey, X509 *cert,
                BIO *dcont, BIO *out, unsigned int flags);
int CMS_decrypt_set1_pkey_and_peer(CMS_ContentInfo *cms,
                EVP_PKEY *pk, X509 *cert, X509 *peer);
int CMS_decrypt_set1_pkey(CMS_ContentInfo *cms, EVP_PKEY *pk, X509 *cert);
int CMS_decrypt_set1_password(CMS_ContentInfo *cms,
                              unsigned char *pass, ossl_ssize_t passlen);

DESCRIPTION

CMS_decrypt() extrait le contenu déchiffré d'une structure CMS EnvelopedData ou AuthEnvelopedData. Elle utilise CMS_decrypt_set1_pkey() pour déchiffrer le contenu avec la clé privée du destinataire pkey si pkey n'est pas NULL. Dans ce cas, il est recommandé de fournir le certificat associé dans cert - voir les REMARQUES ci-dessous. out est un BIO dans lequel écrire le contenu et flags est un ensemble de drapeaux optionnels. Si pkey est NULL, la fonction suppose que le déchiffrement a déjà été effectué (par exemple, en utilisant CMS_decrypt_set1_pkey() ou CMS_decrypt_set1_password()) et se contente de fournir le contenu, sauf si cert, dcont, et out sont également NULL. Le paramètre dcont est utilisé dans le cas rare où le contenu chiffré est détaché. Il sera normalement défini à NULL.

CMS_decrypt_set1_pkey_and_peer() déchiffre la structure CMS_ContentInfo cms en utilisant la clé privée pkey, le certificat correspondant cert, qui est recommandé mais peut être NULL, et le certificat de l'émetteur (optionnel) peer. En cas de succès, elle enregistre également dans cms la clé de déchiffrement pkey, et doit ensuite être suivie par "CMS_decrypt(cms, NULL, NULL, dcont, out, flags)". Ce appel désalloue toute clé de déchiffrement stockée dans cms.

CMS_decrypt_set1_pkey() est identique à CMS_decrypt_set1_pkey_and_peer() avec peer défini à NULL.

CMS_decrypt_set1_password() déchiffre la structure CMS_ContentInfo cms en utilisant le secret pass de longueur passlen . En cas de succès, elle enregistre également danscms la clé de déchiffrement utilisée, et doit ensuite être suivie par "CMS_decrypt(cms, NULL, NULL, dcont, out, flags)" . Ce appel désalloue toute clé de déchiffrement stockée danscms .REMARQUES

Bien que le certificat du destinataire ne soit pas nécessaire pour déchiffrer les données, il est nécessaire pour localiser le (ou les) destinataires appropriés dans la structure CMS.

Si

cert est défini à NULL, tous les destinataires possibles sont essayés. Ce cas est cependant problématique. Pour contrer l'attaque MMA (l'attaque de Bleichenbacher contre le rembourrage PKCS #1 v1.5 pour RSA), tous les destinataires sont essayés, qu'ils réussissent ou non. Si aucun destinataire ne réussit, une clé symétrique aléatoire est utilisée pour déchiffrer le contenu : cela produira généralement des données incohérentes et peut (mais n'est pas garanti de) finalement renvoyer uniquement une erreur de rembourrage. Si CMS_decrypt() renvoyait simplement une erreur lorsque toutes les clés chiffrées des destinataires échouent à être déchiffrées, un attaquant pourrait utiliser cela dans une attaque par minutage. Si le drapeau spécial CMS_DEBUG_DECRYPT est défini, le comportement ci-dessus est modifié et une erreur est renvoyée si aucune clé chiffrée de destinataire ne peut être déchiffrée sans générer une clé de chiffrement de contenu aléatoire. Les applications devraient utiliser ce drapeau avec une extrême prudence , en particulier dans les passerelles automatisées, car cela peut les exposer à des attaques. Il est possible de déterminer la clé correcte du destinataire par d'autres moyens (par exemple en la recherchant dans une base de données) et de la définir à l'avance dans la structure CMS en utilisant les fonctions utilitaires CMS telles que

CMS_set1_pkey() , ou d'utiliserCMS_decrypt_set1_password() si le destinataire possède une clé symétrique. Dans ces cas, à la fois cert et pkey devraient être définis à NULL. Pour traiter les types KEKRecipientInfo,

CMS_set1_key() ou CMS_RecipientInfo_set0_key() et CMS_RecipientInfo_decrypt() devraient être appelés avant CMS_decrypt() et cert et pkey définis à NULL. Les drapeaux suivants peuvent être passés dans le paramètre

flags . Si le

drapeau CMS_TEXT est défini, les en-têtes MIME de type "text/plain" sont supprimés du contenu. Si le contenu n'est pas de type "text/plain" , une erreur est renvoyée. VALEURS RENVOYÉES

CMS_decrypt()

,CMS_decrypt_set1_pkey_and_peer() ,CMS_decrypt_set1_pkey() , etCMS_decrypt_set1_password() renvoient soit 1 en cas de succès, soit 0 en cas d'échec. L'erreur peut être obtenue à partir de ERR_get_error(3) .ANOMALIES

La

partie set1_ de ces noms de fonctions est trompeuse et devrait plutôt se lire : with_.

L'absence de traitement en une seule passe et la nécessité de conserver toutes les données en mémoire, comme mentionné dans CMS_verify() , s'applique également à CMS_decrypt().
