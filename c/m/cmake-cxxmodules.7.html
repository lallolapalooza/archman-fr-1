cmake-cxxmodules - Référence du support des modules C++ de

CMake

Ajouté dans la version 3.

28.

C++ 20 a introduit le concept de « modules » dans le langage. La conception nécessite que les systèmes de build ordonnent les compilations entre elles pour satisfaire les instructions import de manière fiable. L'implémentation de CMake demande au compilateur de scanner les fichiers sources pour les dépendances de modules pendant le bui

ld, compile les résultats du scan pour inférer les contraintes d'ordre, et indiqu
e à l'outil de build comment mettre à jour dynamiquement le graphe de build.

STRATÉGIE DE

COMPILATION

Avec les modules C++, compiler un ensemble de sources C++ n'est plus embarrassingly parallel (parallélisable sans contrainte). C'est-à-dire que toute source donnée peut d'abord nécessiter la compilation d'un autre fichier source afin de fournir un « CMI » (interface de module compilée) ou « BMI » (interface de module binaire) que les compilateurs C++ utilisent pour satisfaire les instructions import dans d'autres sources. Avec les en-têtes, les sources pouvaient partager leurs déclarations afin que n'importe quel consommateur puisse compiler indépendamment. Avec les modules, les déclarations sont maintenant générées dans ces fichiers BMI par le compilateur pendant la compilation en fonction du contenu du fichier source et de ses instructions export

.

L'ordre nécessaire pour la compilation nécessite une résolution au moment du build de l'ordre car l'ordre est contrôlé par le contenu des sources. Cela signifie que l'ordre doit être extrait des sources pendant le build pour éviter de régénérer le graphe de build via une phase de configuration et de génération pour chaque changement de source afin d'obtenir un build

correct.

La stratégie générale consiste à utiliser un « scanner » pour extraire les informations de dépendance d'ordre et à mettre à jour le graphe de build avec de nouvelles arêtes entre les arêtes existantes en prenant les résultats de scan par source (représentés par les fichiers https://www.open-std.org/jtc1/sc22/wg21/docs/papers/2022/p1689r5.html P1689R5) et en « compilant » les dépendances au sein d'une cible et avec les modules produits par des cibles visibles par la cible. La tâche principale est de générer des fichiers « module map » à passer à chaque règle de compilation avec les chemins vers les BMIs nécessaires pour satisfaire les instructions import. Le compilateur de dépendances a également pour tâche d'utiliser les informations au moment du build pour remplir des informations comprenant les règles d'installation pour les unités d'interface de module, leurs BMIs, et les propriétés pour toute cible exportée avec des modules

C++.

Remarque

:
CMake se concentre sur des builds corrects avant d'envisager des améliorations de performance. Il existe des tactiques connues au sein de la stratégie choisie
qui pourraient offrir des améliorations de performance de build. Cependant, elles sont différées jusqu'à ce que nous ayons un modèle fonctionnel auquel les c
omparer. Il est également important de noter qu'une tactique utile dans une situation (par ex., les builds à partir de zéro) peut ne pas être performante da
ns une autre situation (par ex., les builds incrémentaux). Trouver un équilibre et offrir des contrôles pour sélectionner les tactiques est un travail futur.

SCAN

Le fait que les sources soient scannées pour l'utilisation de modules C++ dépend des requêtes suivantes. La première requête qui fournit une réponse oui/non est

  • Si le fichier source appartient à un file set de type CXX_MODULES, il sera
    • scanné.
  • Si la cible n'utilise pas au moins C++ 20, elle ne sera pas
    • scannée.
  • Si le fichier source n'est pas de langage CXX, il ne sera pas
    • scanné.
  • Si la propriété de fichier source CXX_SCAN_FOR_MODULES <#prop_sf:CXX_SCAN_FOR_MODULES> est définie, sa valeur sera
    • utilisée.
  • Si la propriété de cible CXX_SCAN_FOR_MODULES <#prop_tgt:CXX_SCAN_FOR_MODULES> est définie, sa valeur sera utilisée. Définissez la variable CMAKE_CXX_SCAN_FOR_MODULES <#variable:CMAKE_CXX_SCAN_FOR_MODULES> pour initialiser cette propriété sur toutes les cibles lors de leur
    • création.
  • Sinon, le fichier source sera scanné si le compilateur et le générateur prennent en charge le scan. Voir la politique CMP0155 <#
