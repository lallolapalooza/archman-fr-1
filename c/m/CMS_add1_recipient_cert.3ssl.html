NOM

CMS_add1_recipient, CMS_add1_recipient_cert, CMS_add0_recipient_key - ajouter des destinataires à une structure de données chiffrées CMS

SYNOPSIS

#include <openssl/cms.h>
CMS_RecipientInfo *CMS_add1_recipient(CMS_ContentInfo *cms, X509 *recip,
                                      EVP_PKEY *originatorPrivKey,
                                      X509 *originator, unsigned int flags);
CMS_RecipientInfo *CMS_add1_recipient_cert(CMS_ContentInfo *cms,
                                           X509 *recip, unsigned int flags);
CMS_RecipientInfo *CMS_add0_recipient_key(CMS_ContentInfo *cms, int nid,
                                          unsigned char *key, size_t keylen,
                                          unsigned char *id, size_t idlen,
                                          ASN1_GENERALIZEDTIME *date,
                                          ASN1_OBJECT *otherTypeId,
                                          ASN1_TYPE *otherType);

DESCRIPTION

CMS_add1_recipient() ajoute le destinataire recip et fournit la clé privée de l'expéditeur originatorPrivKey et le certificat de l'expéditeur originator à CMS_ContentInfo. Les champs liés à l'expéditeur ne sont pertinents que si la méthode d'accord de clé (keyAgreement) est utilisée pour fournir la clé partagée.

CMS_add1_recipient_cert() ajoute le destinataire recip à la structure de données chiffrées CMS_ContentInfo cms sous la forme d'une structure KeyTransRecipientInfo ou KEMRecipientInfo, ou d'une structure KeyAgreeRecipientInfo avec une clé éphémère.

CMS_add0_recipient_key() ajoute la clé symétrique key de longueur keylen en utilisant l'algorithme de chiffrement nid, l'identifiant id de longueur idlen et les valeurs optionnelles date, otherTypeId et otherType à la structure de données chiffrées CMS_ContentInfo cms sous la forme d'une structure KEKRecipientInfo.

La structure CMS_ContentInfo doit être obtenue à partir d'un appel initial à CMS_encrypt() avec le drapeau CMS_PARTIAL défini.

NOTES

Le but principal de cette fonction est de fournir un contrôle plus fin sur une structure de données chiffrées CMS où les options par défaut plus simples de la fonction CMS_encrypt() ne sont pas appropriées. Par exemple, si une ou plusieurs structures KEKRecipientInfo doivent être ajoutées. De nouveaux attributs peuvent également être ajoutés en utilisant la structure CMS_RecipientInfo retournée et les fonctions utilitaires d'attributs CMS.

OpenSSL identifiera par défaut les certificats des destinataires en utilisant le nom de l'émetteur et le numéro de série. Si CMS_USE_KEYID est défini, il utilisera la valeur de l'identifiant de clé du sujet à la place. Une erreur se produit si tous les certificats des destinataires n'ont pas d'extension d'identifiant de clé du sujet.

Actuellement, seuls les algorithmes de chiffrement AES sont pris en charge pour nid, spécifiquement : NID_id_aes128_wrap, NID_id_aes192_wrap et NID_id_aes256_wrap. Si nid est défini sur NID_undef, un algorithme de chiffrement AES sera utilisé en concordance avec keylen.

VALEURS DE RETOUR

CMS_add1_recipient_cert() et CMS_add0_recipient_key() retournent un pointeur interne vers la structure CMS_RecipientInfo qui vient d'être ajoutée, ou NULL si une erreur se produit.

HISTORIQUE

CMS_add1_recipient_cert et CMS_add0_recipient_key ont été ajoutés dans OpenSSL 3.0.
