DESCRIPTIO

N

L'exécutable cmake est l'interface en ligne de commande du générateur de systèmes de build multiplateforme CMake. Le synopsis ci-dessus liste diverses actions que l'outil peut effectuer, comme décrit dans les sections

ci-dessous.

Pour compiler un projet logiciel avec CMake, générez un système de build de projet. Utilisez éventuellement cmake pour compiler un projet, installer un projet ou exécuter simplement l'outil de build correspondant (par ex. make) directement. cmake peut également être utilisé pour afficher

l'aide.

Les autres actions sont destinées aux développeurs logiciels écrivant des scripts dans le langage CMake <#manual:cmake-language(7)> pour prendre en charge leurs

builds.

Pour les interfaces graphiques pouvant être utilisées à la place de cmake, voir ccmake <#manual:ccmake(1)> et cmake-gui <#manual:cmake-gui(1)>. Pour les interfaces en ligne de commande des fonctionnalités de test et de paquetage de CMake, voir ctest <#manual:ctest(1)> et cpack <#manual:cpack(1)>

.

INTRODUCTION AUX SYSTÈMES DE BUILD

CMAKE

Un système de build décrit comment compiler les exécutables et les bibliothèques d'un projet à partir de son code source en utilisant un outil de build pour automatiser le processus. Par exemple, un système de build peut être un Makefile destiné à être utilisé avec un outil make en ligne de commande ou un fichier de projet pour un environnement de développement intégré (IDE). Afin d'éviter de maintenir plusieurs systèmes de build de ce type, un peut spécifier son système de build de manière abstraite à l'aide de fichiers écrits dans le langage CMake <#manual:cmake-language(7)>. À partir de ces fichiers, CMake génère localement un système de build préféré pour chaque utilisateur via un backend appelé un générateur

.

Pour générer un système de build avec CMake, les éléments suivants doivent être sélectionnés

:
Arborescence
source
Le répertoire de premier niveau contenant les fichiers source fournis par le projet. Le projet spécifie son système de build à l'aide de fichiers comme décrit dans le manuel cmake-language(7) <#manual:cmake-language(7)>, en commençant par un fichier de premier niveau nommé CMakeLists.txt. Ces fichiers spécifient les cibles de build et leurs dépendances comme décrit dans le manuel cmake-buildsystem(7) <#manual:cmake-buildsystem(7)
>.
Arborescence de
build
Le répertoire de premier niveau dans lequel les fichiers du système de build et les artefacts de sortie de build (par ex. exécutables et bibliothèques) doivent être stockés. CMake écrira un fichier CMakeCache.txt pour identifier le répertoire comme une arborescence de build et stocker des informations persistantes telles que les options de configuration du système de build.

Pour maintenir une arborescence source intacte, effectuez un build hors source en utilisant une arborescence de build dédiée séparée. Un build dans la source, où l'arborescence de build est placée dans le même répert

Exécutez cmake --help pour voir la liste des générateurs disponibles localement. Utilisez éventuellement l'option -G ci-dessous pour spécifier un générateur, ou acceptez simplement celui que CMake choisit par défaut pour la plateforme actuelle.
