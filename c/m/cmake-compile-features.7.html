EXIGENCES DE NORMES DE LANGAGE Dans les projets qui utilisent un grand nombre de fonctionnalités couramment disponibles d'une norme de langage particulière (par exemple C++ 11), on peut spécifier une méta-fonctionnalité (par

exemple

cxx_std_11 ) qui nécessite l'utilisation d'un mode de compilateur qui est au minimum conscient de cette norme, mais qui pourrait être supérieur. C'est plus simple que de spécifier toutes les fonctionnalités individuellement, mais cela ne garantit pas l'existence d'une fonctionnalité particulière. Le diagnostic de l'utilisation de fonctionnalités non prises en charge sera différé jusqu'à la compilation. Par exemple, si des fonctionnalités C++ 11 sont utilisées de manière extensive dans les fichiers d'en-tête d'un projet, les clients doivent utiliser un mode de compilateur qui n'est pas inférieur à C++ 11. Cela peut être demandé avec le code : target_compile_features(mylib PUBLIC cxx_std_11) Dans cet exemple, CMake s'assurera que le compilateur est invoqué dans un mode d'au moins C++ 11 (ou C++ 14, C++ 17, ...), en ajoutant des drapeaux tels que -std=gnu++11 si nécessaire. Cela s'applique aux sources au sein de mylib ainsi qu'à tous les dépendants (qui peuvent inclure des en-têtes de mylib ). Note

Les bibliothèques peuvent fournir des fichiers d'en-tête complètement différents en fonction des fonctionnalités de compilateur

demandées.

Par exemple, un en-tête

à

with_variadics/interface.h peut contenir

: 
template<int I, int... Is>
struct Interface;
template<int I>
struct Interface<I>
{
  static int accumulate()
  {
    return I;
  }
};
template<int I, int... Is>
struct Interface
{
  static int accumulate()
  {
    return I + Interface<Is...>::accumulate();
  }
}
;

tandis qu'un en-tête at no_variadics/interface.h peut contenir :

template<int I1, int I2 = 0, int I3 = 0, int I4 = 0>
struct Interface
{
  static int accumulate() { return I1 + I2 + I3 + I4; }
};

Il est possible d'écrire une abstraction interface.h d'en-tête contenant quelque chose comme :

#ifdef HAVE_CXX_VARIADIC_TEMPLATES
#include "with_variadics/interface.h"
#else
#include "no_variadics/interface.h"
#endif

Cependant, cela pourrait être difficile à maintenir s'il y a de nombreux fichiers à abstraire. Ce dont on a besoin est d'utiliser des répertoires d'inclusion alternatifs en fonction des capacités du compilateur.

CMake fournit une COMPILE_FEATURES expression génératrice <#manual:cmake-generator-expressions(7)> pour implémenter de telles conditions. Elle peut être utilisée avec les commandes de propriété de construction telles que target_include_directories() <#command:target_include_directories> et target_link_libraries() <#command:target_link_libraries> pour définir les propriétés du système de construction <#manual:cmake-buildsystem(7)> appropriées :

add_library(foo INTERFACE)
set(with_variadics ${CMAKE_CURRENT_SOURCE_DIR}/with_variadics)
set(no_variadics ${CMAKE_CURRENT_SOURCE_DIR}/no_variadics)
target_include_directories(foo
  INTERFACE
    "$<$<COMPILE_FEATURES:cxx_variadic_templates>:${with_variadics}>"
    "$<$<NOT:$<COMPILE_FEATURES:cxx_variadic_templates>>:${no_variadics}>"
  )

Le code consommateur se lie alors simplement à la cible foo comme d'habitude et utilise le répertoire d'inclusion approprié à la fonctionnalité

add_executable(consumer_with consumer_with.cpp)
target_link_libraries(consumer_with foo)
set_property(TARGET consumer_with CXX_STANDARD 11)
add_executable(consumer_no consumer_no.cpp)
target_link_libraries(consumer_no foo)

COMPILATEURS PRIS EN CHARGE

CMake est actuellement conscient des normes C++ <#prop_tgt:CXX_STANDARD> et des fonctionnalités de compilation <#prop_gbl:CMAKE_CXX_KNOWN_FEATURES> disponibles auprès des identifiants de compilateur <#variable:CMAKE_<LANG>_COMPILER_ID> suivants, pour les versions spécifiées pour chacun :

  • AppleClang: Apple Clang pour les versions d'Xcode 4.4 et ultérieures.
  • Clang: compilateur Clang versions 2.9 et ultérieures.
  • GNU: compilateur GNU versions 4.4 et ultérieures.
  • MSVC: Microsoft Visual Studio versions 2010 et ultérieures.
  • SunPro: Oracle SolarisStudio versions 12.4 et ultérieures.
  • Intel: compilateur Intel versions 12.1 et ultérieures.

CMake est actuellement conscient des normes C <#prop_tgt:C_STANDARD> et des fonctionnalités de compilation <#prop_gbl:CMAKE_C_KNOWN_FEATURES> disponibles auprès des identifiants de compilateur <#variable:CMAKE_<LANG>_COMPILER_ID> suivants, pour les versions spécifiées pour chacun :

  • tous les compilateurs et versions listés ci-dessus pour C++.
  • GNU: compilateur GNU versions 3.4 et ultérieures

CMake est actuellement conscient des normes C++ <#prop_tgt:CXX_STANDARD> et de leurs méta-fonctionnalités associées (par ex. cxx_std_11) disponibles auprès des identifiants de compilateur <#variable:CMAKE_<LANG>_COMPILER_ID> suivants, pour les versions spécifiées pour chacun :

  • Cray: Cray Compiler Environment version 8.1 et ultérieures.
  • Fujitsu: Fujitsu HPC compiler 4.0 et ultérieures.
  • PGI: PGI version 12.10 et ultérieures.
  • NVHPC: NVIDIA HPC compilers version 11.0 et ultérieures.
  • TI: compilateur Texas Instruments.
  • TIClang: compilateurs Texas Instruments basés sur Clang.
  • XL: IBM XL version 10.1 et ultérieures.

CMake est actuellement conscient des normes C <#prop_tgt:C_STANDARD> et de leurs méta-fonctionnalités associées (par ex. c_std_99) disponibles auprès des identifiants de compilateur <#variable:CMAKE_<LANG>_COMPILER_ID> suivants, pour les versions spécifiées pour chacun :

•
tous les compilateurs et versions listés ci-dessus, avec uniquement les méta-fonctionnalités pour C++.

CMake est actuellement conscient des normes CUDA <#prop_tgt:CUDA_STANDARD> et de leurs méta-fonctionnalités associées (par ex. cuda_std_11) disponibles auprès des identifiants de compilateur <#variable:CMAKE_<LANG>_COMPILER_ID> suivants, pour les versions spécifiées pour chacun :

  • Clang: compilateur Clang 5.0 et ultérieures.
  • NVIDIA: compilateur NVIDIA nvcc 7.5 et ultérieures.

INDICATEURS DE NORME DE LANGAGE

Afin de satisfaire les exigences spécifiées par la target_compile_features() <#command:target_compile_features> ou la CMAKE_<LANG>_STANDARD <#variable:CMAKE_<LANG>_STANDARD>, CMake peut passer un indicateur de norme de langage au compilateur, tel que -std=c++11.

Pour les générateurs Visual Studio <#visual-studio-generators>, CMake ne peut pas contrôler précisément le placement de l'indicateur de norme de langage sur la ligne de commande du compilateur. Pour les générateurs Ninja <#ninja-generators>, les générateurs Makefile <#makefile-generators>, et Xcode <#generator:Xcode>, CMake place l'indicateur de norme de langage juste après les indicateurs généraux du langage provenant de CMAKE_<LANG>_FLAGS <#variable:CMAKE_<LANG>_FLAGS> et CMAKE_<LANG>_FLAGS_<CONFIG> <#variable:CMAKE_<LANG>_FLAGS_<CONFIG>>.

Modifié dans la version 3.26 : L'indicateur de norme de langage est placé avant les indicateurs spécifiés par d'autres abstractions telles que la commande target_compile_options() <#command:target_compile_options>. Avant CMake 3.26, l'indicateur de norme de langage était placé après eux.
