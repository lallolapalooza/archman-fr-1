v1 Index de réponse

CMake écrit un fichier index-*.json dans le répertoire v1/reply/ lorsqu'il génère avec succès un système de build. Les clients doivent d'abord lire le fichier d'index de réponse et ne peuvent lire les autres fichiers de réponse v1 qu'en suivant les références. La forme du nom du fichier d'index de réponse est :

<build>/.cmake/api/v1/reply/index-<unspecified>.json

où index- est littéral et <unspecified> est un nom non spécifié sélectionné par CMake. Chaque fois qu'un nouvel index est généré, il reçoit un nouveau nom et l'ancien est supprimé. Pendant le court instant entre ces étapes, il peut y avoir plusieurs fichiers index présents ; celui dont le nom est le plus grand en ordre lexicographique est le fichier index courant.

Ajouté dans la version 4.1 : Le fichier d'index de réponse est décrit sous une forme lisible par machine par ce schéma JSON.

  • une référence à un fichier de réponse v1 vers le fichier de réponse correspondant pour ce kind d'objet et cette version, ou

Le fichier d'index de réponse représente chaque référence à un autre fichier de réponse à l'aide d'un objet JSON avec les membres :

Une chaîne spécifiant l'un des kinds d'objets.
version
Un objet JSON avec les membres major et minor spécifiant les composantes entières de version du kind d'objet.
jsonFile
Une chaîne JSON spécifiant un chemin relatif au fichier d'index de réponse vers un autre fichier JSON contenant l'objet.

v1 Index d'erreur de réponse

Ajouté dans la version 4.1.

CMake écrit un fichier error-*.json dans le répertoire v1/reply/ lorsqu'il échoue à générer un système de build. Cet index d'erreur de réponse suit le même schéma de nommage, la même syntaxe et la même sémantique qu'un fichier d'index de réponse v1, avec les exceptions suivantes :

  • Le préfixe index- est remplacé par un préfixe error- .
  • Lorsqu'un nouvel index d'erreur est généré, les anciens fichiers d'index ne sont pas supprimés. Si un fichier d'index de réponse v1 existe, il indexe les réponses de l'exécution réussie la plus récente. Si plusieurs fichiers index-*.json et/ou error-*.json sont présents, celui dont le nom est le plus grand en ordre lexicographique, en excluant le préfixe index- ou error- , est l'index courant.
  • Seul un sous-ensemble de types d'objets est fourni :
configureLog
Ajouté dans la version 4.1.

Les entrées d'index pour les autres types d'objets contiennent un message d'erreur au lieu d'une référence de fichier de réponse v1.

v1 Fichiers de réponse

Les fichiers de réponse contenant des types d'objets spécifiques sont écrits par CMake. Le nom de ces fichiers n'est pas spécifié et ne doit pas être interprété par les clients. Les clients doivent d'abord lire le fichier d'index de réponse v1 et suivre les références vers les noms des objets de réponse souhaités.

Les fichiers de réponse (y compris le fichier d'index) ne seront jamais remplacés par des fichiers du même nom mais de contenu différent. Cela permet à un client de lire les fichiers de manière concurrente avec un CMake en cours d'exécution qui peut générer une nouvelle réponse. Cependant, après avoir généré une nouvelle réponse, CMake tentera de supprimer les fichiers de réponse des exécutions précédentes qu'il n'a pas juste écrits. Si un client tente de lire un fichier de réponse référencé par l'index mais trouve le fichier manquant, cela signifie qu'un CMake concurrent a généré une nouvelle réponse. Le client peut simplement recommencer en lisant le nouveau fichier d'index de réponse.

TYPES D'OBJETS

L'API basée sur les fichiers de CMake rapporte des informations sémantiques sur le système de build à l'aide des types d'objets JSON suivants. Chaque type d'objet est versionné indépendamment en utilisant le versionnement sémantique avec des composants majeur et mineur. Chaque type d'objet a la forme :

{
  "kind": "<kind>",
  "version": { "major": 1, "minor": 0 },
  "...": {}
}

Le membre kind est une chaîne spécifiant le nom du type d'objet. Le membre version est un objet JSON avec les membres major et minor spécifiant les composants entiers de la version du type d'objet. Les membres de premier niveau supplémentaires sont spécifiques à chaque type d'objet.

Type d'objet « codemodel »

Le type d'objet codemodel décrit la structure du système de build telle que modélisée par CMake.

Il n'existe qu'une seule version majeure de l'objet codemodel , la version 2. La version 1 n'existe pas pour éviter la confusion avec celle du mode cmake-server(7) <#manual:cmake-server(7)>.

projects
Un tableau JSON d'entrées correspondant au projet de premier niveau et aux sous-projets définis dans le système de build. Chaque (sous-)projet correspond à un répertoire source dont le fichier CMakeLists.txt appelle la commande project() <#command:project> avec un nom de projet différent de celui de son répertoire parent. La première entrée correspond au projet de premier niveau.

Chaque entrée est un objet JSON contenant les membres :

name
Une chaîne spécifiant le nom donné à la commande project() <#command:project>.
parentIndex
Membre facultatif présent lorsque le projet n'est pas de premier niveau. La valeur est un index entier non signé basé sur 0 d'une autre entrée dans le tableau principal projects correspondant au projet parent qui a ajouté ce projet comme sous-projet.
childIndexes
Membre facultatif présent lorsque le projet a des sous-projets. La valeur est un tableau JSON d'entrées correspondant aux sous-projets. Chaque entrée est un index entier non signé basé sur 0 d'une autre entrée dans le tableau principal projects .
directoryIndexes
Un tableau JSON d'entrées correspondant aux répertoires du système de build qui font partie du projet. La première entrée correspond au répertoire de premier niveau du projet. Chaque entrée est un index entier non signé basé sur 0 dans le tableau principal directories .
targetIndexes
Membre facultatif présent lorsque le projet lui-même a des cibles du système de build, à l'exclusion de celles appartenant aux sous-projets. La valeur est un tableau JSON d'entrées correspondant aux cibles du système de build. Chaque entrée est un index entier non signé basé sur 0 dans le tableau principal targets .
abstractTargetIndexes
Membre facultatif présent lorsque le projet lui-même a des cibles abstraites, à l'exclusion de celles appartenant aux sous-projets. La valeur est un tableau JSON d'entrées correspondant aux cibles abstraites. Chaque entrée est un index entier non signé basé sur 0 dans le tableau principal abstractTargets .

Ce champ a été ajouté dans le codemodel version 2.9.

targets
Un tableau JSON d'entrées correspondant aux cibles du système de build. De telles cibles sont créées par des appels à add_executable() <#command:add_executable>, add_library() <#command:add_library> et add_custom_target() <#command:add_custom_target>, à l'exclusion des cibles importées et des bibliothèques d'interface qui ne génèrent aucune règle de build. Chaque entrée est un objet JSON contenant les membres :
name
Une chaîne spécifiant le nom de la cible.
id
Une chaîne identifiant de manière unique la cible. Elle correspond au champ id dans le fichier référencé par jsonFile.
directoryIndex
Un index entier non signé basé sur 0 dans le tableau principal directories indiquant le répertoire du système de build dans lequel la cible est définie.
projectIndex
Un index entier non signé basé sur 0 dans le tableau principal projects indiquant le projet du système de build dans lequel la cible est définie.
jsonFile
Une chaîne JSON spécifiant un chemin relatif au fichier codemodel vers un autre fichier JSON contenant un objet "target" du "codemodel" version 2.
abstractTargets
Un tableau JSON d'entrées correspondant à des cibles qui ne sont pas présentes dans le système de build. Il s'agit de cibles importées ou de bibliothèques d'interface créées par des appels à add_executable() <#command:add_executable> ou add_library() <#command:add_library>. Dans le cas des bibliothèques d'interface, seules celles qui ne font pas partie du système de build sont incluses dans ce tableau. Les bibliothèques d'interface qui participent au système de build seront incluses dans le tableau targets à la place.

Chaque entrée est un objet JSON contenant les membres :

name
Une chaîne spécifiant le nom de la cible.
id
Une chaîne identifiant de manière unique la cible. Elle correspond au champ id dans le fichier référencé par jsonFile.
directoryIndex
Un index entier non signé basé sur 0 dans le tableau principal directories indiquant le répertoire du système de build dans lequel la cible est définie.
projectIndex
Un index entier non signé basé sur 0 dans le tableau principal projects indiquant le projet du système de build dans lequel la cible est définie.
jsonFile
Une chaîne JSON spécifiant un chemin relatif au fichier codemodel vers un autre fichier JSON contenant un objet "target" du "codemodel" version 2.

Ce champ a été ajouté dans le codemodel version 2.9.

Ce champ a été ajouté dans la version 2.9 de codemodel.

abstract
Membre facultatif qui est présent avec la valeur booléenne true si la cible est une cible abstraite. Les cibles abstraites ne font pas partie du système de build, elles n'existent que pour décrire des dépendances ou pour fournir des exigences d'utilisation aux cibles qui s'y lient. Les cibles importées et les bibliothèques d'interface sans sources générées en sont des exemples. Les cibles abstraites ne peuvent pas être construites, elles ne doivent donc pas être présentées à l'utilisateur comme une cible constructible.

Ce champ a été ajouté dans la version 2.9 de codemodel. Les cibles abstraites n'étaient pas incluses dans la version 2.8 de codemodel et les versions antérieures.

Membre facultatif qui est présent avec la valeur booléenne true si la cible est SYMBOLIC <#prop_tgt:SYMBOLIC>. Les cibles symboliques sont créées par des appels à add_library(INTERFACE SYMBOLIC) <#interface-symbolic>, et sont également des cibles abstraites qui ne font pas partie du système de build.

Ce champ a été ajouté dans la version 2.9 de codemodel. Les cibles symboliques n'étaient pas incluses dans la version 2.8 de codemodel et les versions antérieures.

Type d'objet "configureLog"

Ajouté dans la version 3.26.

Le configureLog type d'objet décrit l'emplacement et le contenu d'un fichier cmake-configure-log(7) <#manual:cmake-configure-log(7)>.

Il n'existe qu'une seule version majeure de l'objet configureLog , version 1.

Ajouté dans la version 4.1 : La réponse du type d'objet configureLog est décrite sous une forme lisible par machine par ce schéma JSON.

"configureLog" version 1

L'objet configureLog version 1 est un objet JSON :

{
  "kind": "configureLog",
  "version": { "major": 1, "minor": 0 },
  "path": "/path/to/top-level-build-dir/CMakeFiles/CMakeConfigureLog.yaml",
  "eventKindNames": [ "try_compile-v1", "try_run-v1" ]
}

Les membres spécifiques aux objets configureLog sont :

path
Une chaîne de caractères spécifiant le chemin du fichier de journal de configuration. Les clients doivent lire le fichier journal depuis ce chemin, qui peut être différent du chemin documenté par cmake-configure-log(7) <#manual:cmake-configure-log(7)>. Le fichier journal peut ne pas exister si aucun événement n'est journalisé.
eventKindNames
Un tableau JSON dont les entrées sont chacune une chaîne JSON nommant l'un des cmake-configure-log(7) <#manual:cmake-configure-log(7)> types d'événements versionnés. Au plus une version de chaque type d'événement du journal de configuration sera listée. Bien que le journal de configuration puisse contenir d'autres types d'événements (versionnés), les clients doivent ignorer ceux qui ne sont pas listés dans ce champ.

Ajouté dans la version 4.1 : La réponse du type d'objet cache est décrite sous une forme lisible par machine par ce schéma JSON.

Une chaîne de caractères spécifiant la valeur de la propriété d'entrée de cache.

Type d'objet "cmakeFiles"

Le cmakeFiles type d'objet liste les fichiers utilisés par CMake lors de la configuration et de la génération du système de build. Ceux-ci incluent les fichiers CMakeLists.txt ainsi que les fichiers inclus .cmake .

Il n'existe qu'une seule version majeure de l'objet cmakeFiles , version 1.

Ajouté dans la version 4.1 : La réponse du type d'objet cmakeFiles est décrite sous une forme lisible par machine par ce schéma JSON.

"cmakeFiles" version 1

L'objet cmakeFiles version 1 est un objet JSON :

{
  "kind": "cmakeFiles",
  "version": { "major": 1, "minor": 1 },
  "paths": {
    "build": "/path/to/top-level-build-dir",
    "source": "/path/to/top-level-source-dir"
  },
  "inputs": [
    {
      "path": "CMakeLists.txt"
    },
    {
      "isGenerated": true,
      "path": "/path/to/top-level-build-dir/.../CMakeSystem.cmake"
    },
    {
      "isExternal": true,
      "path": "/path/to/external/third-party/module.cmake"
    },
    {
      "isCMake": true,
      "isExternal": true,
      "path": "/path/to/cmake/Modules/CMakeGenericSystem.cmake"
    }
  ],
  "globsDependent": [
    {
      "expression": "src/*.cxx",
      "recurse": true,
      "files": [
        "src/foo.cxx",
        "src/bar.cxx"
      ]
    }
  ]
}

Les membres spécifiques aux objets cmakeFiles sont :

paths
Un objet JSON contenant les membres :
source
Une chaîne de caractères spécifiant le chemin absolu du répertoire source de premier niveau, représenté avec des barres obliques.
build
Une chaîne de caractères spécifiant le chemin absolu du répertoire de build de premier niveau, représenté avec des barres obliques.
inputs
Un tableau JSON dont les entrées sont chacune un objet JSON spécifiant un fichier d'entrée utilisé par CMake lors de la configuration et de la génération du système de build. Les membres de chaque entrée sont :
path
Une chaîne de caractères spécifiant le chemin d'un fichier d'entrée pour CMake, représenté avec des barres obliques. Si le fichier se trouve dans le répertoire source de premier niveau, le chemin est spécifié relativement à ce répertoire. Sinon, le chemin est absolu.
isGenerated
Membre facultatif qui est présent avec la valeur booléenne true si le chemin spécifie un fichier qui se trouve sous le répertoire de build de premier niveau et que le build est hors source (out-of-source). Ce membre n'est pas disponible pour les builds in-source.
isExternal
Membre facultatif qui est présent avec la valeur booléenne true si le chemin spécifie un fichier qui ne se trouve pas sous les répertoires source ou build de premier niveau.
isCMake
Membre facultatif qui est présent avec la valeur booléenne true si le chemin spécifie un fichier dans l'installation de CMake.
globsDependent
Membre facultatif qui est présent lorsque le projet appelle file(GLOB) <#glob> ou file(GLOB_RECURSE) <#glob-recurse> avec l'option CONFIGURE_DEPENDS . La valeur est un tableau JSON d'objets JSON, chacun spécifiant une expression de globbing et la liste des chemins qu'elle a correspondus. Si l'expression de globbing ne correspond plus à la même liste de chemins, CMake considère que le système de build est obsolète.

Ce champ a été ajouté dans la version cmakeFiles 1.1.

Le les membres de chaque entrée sont :

expression
Une chaîne spécifiant l'expression de globbing.
recurse
Membre facultatif qui est présent avec la valeur booléenne true si l'entrée correspond à un appel file(GLOB_RECURSE) <#glob-recurse> . Sinon, l'entrée correspond à un appel file(GLOB) <#glob> .
listDirectories
Membre facultatif qui est présent avec la valeur booléenne true si file(GLOB) <#glob> a été appelé sans LIST_DIRECTORIES false ou si file(GLOB_RECURSE) <#glob-recurse> a été appelé avec LIST_DIRECTORIES true.
followSymlinks
Membre facultatif qui est présent avec la valeur booléenne true si file(GLOB) <#glob> a été appelé avec l'option FOLLOW_SYMLINKS .
relative
Membre facultatif qui est présent si file(GLOB) <#glob> a été appelé avec l'option RELATIVE <path> . La valeur est une chaîne contenant le <path> fourni.
paths
Un tableau JSON de chaînes spécifiant les chemins correspondant à l'appel à file(GLOB) <#glob> ou file(GLOB_RECURSE) <#glob-recurse>.

Type d'objet « toolchains »

Le type d'objet toolchains liste les propriétés des chaînes d'outils utilisées pendant la compilation. Celles-ci incluent le langage, le chemin du compilateur, l'identifiant et la version.

Il n'existe qu'une seule version majeure de l'objet toolchains , la version 1.

Ajouté dans la version 4.1 : La réponse du type d'objet toolchains est décrite sous une forme lisible par machine par ce schéma JSON.

Les membres spécifiques aux objets toolchains sont :

toolchains
Un tableau JSON dont chaque entrée est un objet JSON spécifiant une chaîne d'outils associée à un langage particulier. Les membres de chaque entrée sont :
language
Une chaîne JSON spécifiant le langage de la chaîne d'outils, comme C ou CXX. Les noms de langage sont les mêmes que les noms de langage qui peuvent être passés à la commande project() <#command:project>. Parce que CMake ne prend en charge qu'une seule chaîne d'outils par langage, ce champ peut être utilisé comme clé.
compiler
Un objet JSON contenant les membres :
path
Membre facultatif qui est présent lorsque la variable CMAKE_<LANG>_COMPILER <#variable:CMAKE_<LANG>_COMPILER> est définie pour le langage courant. Sa valeur est une chaîne JSON contenant le chemin vers le compilateur.
id
Membre facultatif qui est présent lorsque la variable CMAKE_<LANG>_COMPILER_ID <#variable:CMAKE_<LANG>_COMPILER_ID> est définie pour le langage courant. Sa valeur est une chaîne JSON contenant l'identifiant (GNU, MSVC, etc.) du compilateur.
version
Membre facultatif qui est présent lorsque la variable CMAKE_<LANG>_COMPILER_VERSION <#variable:CMAKE_<LANG>_COMPILER_VERSION> est définie pour le langage courant. Sa valeur est une chaîne JSON contenant la version du compilateur.
target
Membre facultatif qui est présent lorsque la variable CMAKE_<LANG>_COMPILER_TARGET <#variable:CMAKE_<LANG>_COMPILER_TARGET> est définie pour le langage courant. Sa valeur est une chaîne JSON contenant la cible de compilation croisée du compilateur.
implicit
Un objet JSON contenant les membres :
includeDirectories
Membre facultatif qui est présent lorsque la variable CMAKE_<LANG>_IMPLICIT_INCLUDE_DIRECTORIES <#variable:CMAKE_<LANG>_IMPLICIT_INCLUDE_DIRECTORIES> est définie pour le langage courant. Sa valeur est un tableau JSON de chaînes JSON où chaque chaîne contient un chemin vers un répertoire d'inclusion implicite pour le compilateur.
linkDirectories
Membre facultatif qui est présent lorsque la variable CMAKE_<LANG>_IMPLICIT_LINK_DIRECTORIES <#variable:CMAKE_<LANG>_IMPLICIT_LINK_DIRECTORIES> est définie pour le langage courant. Sa valeur est un tableau JSON de chaînes JSON où chaque chaîne contient un chemin vers un répertoire de liaison implicite pour le compilateur.
linkFrameworkDirectories
Membre facultatif qui est présent lorsque la variable CMAKE_<LANG>_IMPLICIT_LINK_FRAMEWORK_DIRECTORIES <#variable:CMAKE_<LANG>_IMPLICIT_LINK_FRAMEWORK_DIRECTORIES> est définie pour le langage courant. Sa valeur est un tableau JSON de chaînes JSON où chaque chaîne contient un chemin vers un répertoire de framework de liaison implicite pour le compilateur.
linkLibraries
Membre facultatif qui est présent lorsque la variable CMAKE_<LANG>_IMPLICIT_LINK_LIBRARIES <#variable:CMAKE_<LANG>_IMPLICIT_LINK_LIBRARIES> est définie pour le langage courant. Sa valeur est un tableau JSON de chaînes JSON où chaque chaîne contient un chemin vers une bibliothèque de liaison implicite pour le compilateur.
sourceFileExtensions
Membre facultatif qui est présent lorsque la variable CMAKE_<LANG>_SOURCE_FILE_EXTENSIONS <#variable:CMAKE_<LANG>_SOURCE_FILE_EXTENSIONS> est définie pour le langage courant. Sa valeur est un tableau JSON de chaînes JSON où chaque chaîne contient une extension de fichier (sans le point initial) pour le langage.
