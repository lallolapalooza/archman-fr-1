CMSG(3) Manuel des fonctions de la bibliothèque CMSG(3)

NOM

CMSG_ALIGN, CMSG_SPACE, CMSG_NXTHDR, CMSG_FIRSTHDR - accéder aux données auxiliaires

BIBLIOTHÈQUE

Bibliothèque C standard (libc,-lc)

SYNOPSIS

#include <sys/socket.h>
struct cmsghdr *CMSG_FIRSTHDR(struct msghdr *msgh);
struct cmsghdr *CMSG_NXTHDR(struct msghdr *msgh,
                            struct cmsghdr *cmsg);
size_t CMSG_ALIGN(size_t length);
size_t CMSG_SPACE(size_t length);
size_t CMSG_LEN(size_t length);
unsigned char *CMSG_DATA(struct cmsghdr *cmsg);

DESCRIPTION

Ces macros sont utilisées pour créer et accéder aux messages de contrôle (également appelés données auxiliaires) qui ne font pas partie de la charge utile du socket. Ces informations de contrôle peuvent inclure l'interface sur laquelle le paquet a été reçu, divers champs d'en-tête rarement utilisés, une description d'erreur étendue, un ensemble de descripteurs de fichiers ou des identifiants UNIX. Par exemple, les messages de contrôle peuvent être utilisés pour envoyer des champs d'en-tête supplémentaires tels que les options IP. Les données auxiliaires sont envoyées en appelant sendmsg(2) et reçues en appelant recvmsg(2). Consultez leurs pages man pour plus d'informations.

Les données auxiliaires sont une séquence de cmsghdr structures avec des données ajoutées. Consultez les pages man des protocoles spécifiques pour les types de messages de contrôle disponibles. La taille maximale du tampon auxiliaire autorisée par socket peut être définie à l'aide de /proc/sys/net/core/optmem_max; voir socket(7).

La cmsghdr structure est définie comme suit :


struct cmsghdr {
    size_t cmsg_len;    /* Nombre d'octets de données, en-tête inclus
                           (le type est socklen_t en POSIX) */
    int    cmsg_level;  /* Protocole d'origine */
    int    cmsg_type;   /* Type spécifique au protocole */
/* suivi de
   unsigned char cmsg_data[]; */
};

La séquence de cmsghdr structures ne doit jamais être accédée directement. Utilisez plutôt uniquement les macros suivantes :

CMSG_FIRSTHDR()
renvoie un pointeur vers la première cmsghdr dans le tampon de données auxiliaires associé au msghdrpassé. Elle renvoie NULL s'il n'y a pas assez de place pour une cmsghdr dans le tampon.
CMSG_NXTHDR()
renvoie la cmsghdr suivante valide après la cmsghdrpassée. Elle renvoie NULL lorsqu'il ne reste pas assez de place dans le tampon.
Lors de l'initialisation d'un tampon qui contiendra une série de cmsghdr structures (par ex., à envoyer avec sendmsg(2)), ce tampon doit d'abord être initialisé à zéro pour garantir le bon fonctionnement de CMSG_NXTHDR().
CMSG_ALIGN(),
étant donné une longueur, la renvoie en incluant l'alignement requis. C'est une expression constante.
CMSG_SPACE()
renvoie le nombre d'octets occupés par un élément auxiliaire dont la charge utile a la longueur de données passée. C'est une expression constante.
CMSG_DATA()
renvoie un pointeur vers la partie données d'une cmsghdr. Le pointeur renvoyé ne peut pas être supposé correctement aligné pour accéder à des types de données de charge utile arbitraires. Les applications ne doivent pas le convertir en un type de pointeur correspondant à la charge utile, mais doivent plutôt utiliser memcpy(3) pour copier des données vers ou depuis un objet correctement déclaré.
CMSG_LEN()
renvoie la valeur à stocker dans le cmsg_len membre de la cmsghdr structure, en tenant compte de tout alignement nécessaire. Elle prend la longueur des données comme argument. C'est une expression constante.

Pour créer des données auxiliaires, initialisez d'abord le msg_controllen membre du msghdr avec la longueur du tampon de message de contrôle. Utilisez CMSG_FIRSTHDR() sur le msghdr pour obtenir le premier message de contrôle et CMSG_NXTHDR() pour obtenir tous les suivants. Dans chaque message de contrôle, initialisez cmsg_len (avec CMSG_LEN()), les autres cmsghdr champs d'en-tête, et la partie données en utilisant CMSG_DATA(). Enfin, le champ msg_controllen du msghdr doit être défini à la somme des CMSG_SPACE() des longueurs de tous les messages de contrôle dans le tampon. Pour plus d'informations sur le msghdr, voir recvmsg(2).

VERSIONS

Pour la portabilité, les données auxiliaires doivent être accédées uniquement à l'aide des macros décrites ici.

Dans Linux, CMSG_LEN(), CMSG_DATA(), et CMSG_ALIGN() sont des expressions constantes (en supposant que leur argument est constant), ce qui signifie que ces valeurs peuvent être utilisées pour déclarer la taille de variables globales. Cela peut ne pas être portable, cependant.

HISTORIQUE

Ce modèle de données auxiliaires est conforme au projet POSIX.1g, 4.4BSD-Lite, l'API avancée IPv6 décrite dans la RFC 2292 et SUSv2.

CMSG_SPACE() et CMSG_LEN() seront incluses dans la prochaine version de POSIX (Issue 8).

EXEMPLES

Ce code recherche l'option IP_TTL dans un tampon auxiliaire reçu :


struct msghdr msgh;
struct cmsghdr *cmsg;
int received_ttl;
/* Recevoir les données auxiliaires dans msgh */
for (cmsg = CMSG_FIRSTHDR(&msgh); cmsg != NULL;
        cmsg = CMSG_NXTHDR(&msgh, cmsg)) {
    if (cmsg->cmsg_level == IPPROTO_IP
            && cmsg->cmsg_type == IP_TTL) {
        memcpy(&receive_ttl, CMSG_DATA(cmsg), sizeof(received_ttl));
        break;
    }
}
if (cmsg == NULL) {
    /* Erreur : IP_TTL non activé ou tampon trop petit ou erreur d'E/S */
}

Le code ci-dessous transmet un tableau de descripteurs de fichiers sur un socket de domaine UNIX en utilisant SCM_RIGHTS:


struct msghdr msg = { 0 };
struct cmsghdr *cmsg;
int myfds[NUM_FD];  /* Contient les descripteurs de fichiers à transmettre */
char iobuf[1];
struct iovec io = {
    .iov_base = iobuf,
    .iov_len = sizeof(iobuf)
};
union {         /* Tampon de données auxiliaires, enveloppé dans une union
                   afin de garantir qu'il est correctement aligné */
    char buf[CMSG_SPACE(sizeof(myfds))];
    struct cmsghdr align;
} u;
msg.msg_iov = &
msg.msg_iovlen = 1;
msg.msg_control = u.buf;
msg.msg_controllen = sizeof(u.buf);
cmsg = CMSG_FIRSTHDR(&msg);
cmsg->cmsg_level = SOL_SOCKET;
cmsg->cmsg_type = SCM_RIGHTS;
cmsg->cmsg_len = CMSG_LEN(sizeof(myfds));
memcpy(CMSG_DATA(cmsg), myfds, sizeof(myfds));

Pour un exemple de code complet montrant la transmission de descripteurs de fichiers sur un socket de domaine UNIX, voir seccomp_unotify(2).
