cxl-list - Liste les objet

s CXL de la plateforme et
leurs attributs, en json.

SYNOPSI

S 
cxl list [<options>
]

Parcourt la hiérarchie des périphériques compatibles CXL du système et liste toutes les instances de périphériques ainsi que certaines de leurs attributs

principaux.

Des options peuvent être spécifiées pour limiter la sortie à des objets spécifiques. Lorsqu'un seul type d'objet est spécifié, l'objet json retourné est un tableau contenant uniquement ces objets ; lorsque plusieurs types d'objets sont spécifiés, l'objet retourné peut être un tableau de tableaux dont le tableau interne est nommé selon le type d'objet donné. Les tableaux de premier niveau sont omis lorsque les objets peuvent être imbriqués sous un type d'objet supérieur dans la hiérarchie. Les noms potentiels des tableaux de premier niveau et leurs propriétés d'imbrication sont

:

"anon

memdevs"
(périphériques mémoire désactivés) ne s'imbriquent
pas

"buses

"
ne s'imbriquent
pas

"ports

"
s'imbriquent sous les
bus

"endpoints

"
s'imbriquent sous les ports ou les bus (si les ports ne sont pas
émis)

"memdevs

"
s'imbriquent sous les endpoints ou les ports (si les endpoints ne sont pas émis) ou les bus (si les endpoints et les ports ne sont pas
émis)

"root

decoders"
s'imbriquent sous les
bus

"port

decoders"
s'imbriquent sous les ports, ou les bus (si les ports ne sont pas
émis)

"endpoint

decoders"
s'imbriquent sous les endpoints, ou les ports (si les endpoints ne sont pas émis) ou les bus (si les endpoints et les ports ne sont pas
émis)

Les filtres peuvent être spécifiés soit comme un identifiant unique, soit comme une chaîne entre guillemets séparée par des espaces, soit comme une liste séparée par des virgules. Lorsque plusieurs identifiants de filtre sont spécifiés dans une chaîne de filtre, comme "-m mem0,mem1,mem2", ils sont combinés en un filtre OR. Lorsque plusieurs types de chaînes de filtre sont spécifiés, comme "-m mem0,mem1,mem2 -p port10", ils sont combinés en un filtre AND. Ainsi, "-m mem0,mem1,mem2 -p port10" ne listerait que les objets qui se trouvent sous port10 ET qui mappent mem0, mem1, OU

mem2.

Étant donné que de nombreuses requêtes de topologie cherchent à répondre à des questions relatives à un memdev donné, les bus, ports, endpoints et décodeurs peuvent être filtrés par un ou plusieurs memdevs. Par exemple

: 
# cxl list -P -p switch,endpoint -m mem0
[
  {
    "port":"port1",
    "host":"ACPI0016:00",
    "endpoints:port1":[
      {
        "endpoint":"endpoint2",
        "host":"mem0"
      }
    ]
  }
]

De plus, lors de la provisionnement de nouvelles configurations d'entrelacement, il est utile de savoir quels memdevs peuvent être référencés par un décodeur donné comme un décodeur racine, ou mappés par un port donné si les décodeurs ne sont pas

configurés. 
# cxl list -Mu -d decoder0.0
{
  "memdev":"m
em0", "pmem_size":"256.00 MiB (268.44 MB)
", "serial":"0", "host":"0000:35:00.0" }

Notez que pour les filtres -m/--memdev=, -p/--port= et -e/--endpoint=, un nom de périphérique hôte peut être substitué à l'identifiant de l'objet CXL. Pour -m/--memdev=, il s'agit d'un nom de périphérique PCI endpoint de la forme "DDDD:bb:dd.f" (D: Domaine b: Bus d: Périphérique f: Fonction) (voir /sys/bus/pci/devices), pour -p/--port= il s'agit d'un nom de périphérique PCI de port de commutateur amont de la forme "DDDD:bb:dd.f", ou d'un nom de bus PCI de la forme "pciDDDD:bb", et pour -e/--endpoint= le périphérique hôte est un nom d'objet de périphérique mémoire CXL de la forme

"memX".

L'option --human, en plus de reformater certains ch

amps en chaînes plus lisibles, déplie également le
tableau pour réduire le nombre de lignes de sortie.

OPTION

S

-m,

--memdev=
Spécifie le ou les noms de périphérique mémoire CXL ("mem0"), le ou les identifiants de périphérique ("0"), et/ou le ou les noms de périphérique hôte ("0000:35:00.0") pour filtrer la liste. Par exemple
: 
# cxl list -M --memdev="0 mem3 5"
[
  {
    "memdev":"mem0",
    "pmem_size":268435456,
    "serial":0
  },
  {
    "memdev":"mem3",
    "pmem_size":268435456,
    "ram_size":268435456,
    "serial":2
  },
  {
    "memdev":"mem5",
    "pmem_size":268435456,
    "ram_size":268435456,
    "serial":4
  }
]

-s,

--serial=
Spécifie le ou les numéros de série des périphériques mémoire CXL pour filtrer la
liste

-M,

--memdevs
Inclut les périphériques mémoire CXL dans la
liste

-i,

--idle
Inclut les périphériques inactifs (non activés / de taille nulle) dans la
liste

-H,

--health
Inclut les informations d'état de santé dans la liste des memdevs. Exemple de liste
: 
# cxl list -m mem0 -H
[
  {
    "memdev":"mem0",
    "pmem_size":268435456,
    "ram_size":268435456,
    "health":{
      "maintenance_needed":true,
      "performance_degraded":true,
      "hw_replacement_needed":true,
      "media_normal":false,
      "media_not_ready":false,
      "media_persistence_lost":false,
      "media_data_lost":true,
      "media_powerloss_persistence_loss":false,
      "media_shutdown_persistence_loss":false,
      "media_persistence_loss_imminent":false,
      "media_powerloss_data_loss":false,
      "media_shutdown_data_loss":false,
      "media_data_loss_imminent":false,
      "ext_life_used":"normal",
      "ext_temperature":"critical",
      "ext_corrected_volatile":"warning",
      "ext_corrected_persistent":"normal",
      "life_used_percent":15,
      "temperature":25,
      "dirty_shutdowns":10,
      "volatile_errors":20,
      "pmem_errors":30
    }
  }
]

-I,

--partition
Inclut les informations de partition dans la liste des memdevs. Exemple de liste
: 
# cxl list -m mem0 -I
[
  {
    "memdev":"mem0",
    "ram_size":273535729664,
    "partition_info":{
      "total_size":273535729664,
      "volatile_only_size":0,
      "persistent_only_size":0,
      "partition_alignment_size":268435456
      "active_volatile_size":273535729664,
      "active_persistent_size":0,
      "next_volatile_size":0,
      "next_persistent_size":0,
    }
  }
]

-A,

--alert-config
Inclut la configuration des alertes dans la liste des memdevs. Exemple de liste
: 
# cxl list -m mem0 -A
[
  {
    "memdev":"mem0",
    "pmem_size":0,
    "ram_size":273535729664,
    "alert_config":{
      "life_used_prog_warn_threshold_valid":false,
      "dev_over_temperature_prog_warn_threshold_valid":false,
      "dev_under_temperature_prog_warn_threshold_valid":false,
      "corrected_volatile_mem_err_prog_warn_threshold_valid":true,
      "corrected_pmem_err_prog_warn_threshold_valid":false,
      "life_used_prog_warn_threshold_writable":false,
      "dev_over_temperature_prog_warn_threshold_writable":false,
      "dev_under_temperature_prog_warn_threshold_writable":false,
      "corrected_volatile_mem_err_prog_warn_threshold_writable":true,
      "corrected_pmem_err_prog_warn_threshold_writable":false,
      "life_used_crit_alert_threshold":0,
      "life_used_prog_warn_threshold":0,
      "dev_over_temperature_crit_alert_threshold":0,
      "dev_under_temperature_crit_alert_threshold":0,
      "dev_over_temperature_prog_warn_threshold":0,
      "dev_under_temperature_prog_warn_threshold":0,
      "corrected_volatile_mem_err_prog_warn_threshold":0,
      "corrected_pmem_err_prog_warn_threshold":0
    },
  }
]

-B,

--buses
Inclure l'objet bus / racine CXL dans la liste. Généralement, sur les systèmes ACPI, l'objet bus est un singleton associé au périphérique ACPI0017, mais il existe des scénarios de test où il peut y avoir plusieurs hiérarchies de mémoire
CXL. 
# cxl list -B
[
  {
    "bus":"root3",
    "provider":"cxl_test"
  },
  {
    "bus":"root0",
    "provider":"ACPI.CXL"
  }
]

-b,

--bus=
Spécifier le(s) nom(s) de périphérique racine CXL, le(s) identifiant(s) de périphérique et/ou le(s) nom(s) de fournisseur de bus CXL pour filtrer la liste. Les noms de fournisseurs pris en charge sont "ACPI.CXL" et
"cxl_test".

-P,

--ports
Inclure les objets port (ports racines CXL / PCIe + ports amont de commutateur) dans la
liste.

-p,

--port=
Spécifier le(s) nom(s) de périphérique de port CXL ("port2"), le(s) identifiant(s) de périphérique ("2"), le(s) nom(s) de périphérique hôte ("pci0000:34") et/ou le(s) nom(s) de type de port pour filtrer la liste. Les noms de type de port pris en charge sont "root" et "switch". Notez qu'un objet bus est également un port, donc les deux syntaxes suivantes sont équivalentes
: 
# cxl list -B
# cxl list
-P -p root -S 
...où le '-S/--single' est requis car les ports descendants sont toujours
  inclus dans une liste de ports et '
-S/--single' s'arrête après avoir listé le bus. De plus, les objets endpoint sont des ports, donc les command
es suivantes sont équivalentes, et aucun '-S/--single' n'est requis car les ports endpoint sont terminaux : 
# cxl list -E
# cxl list -
P -p endpoint 
Par défaut, seuls les
ports 'switch' sont
listés, c'est-à-dire 
# cxl list -
P # cxl list
-P -p switch 
...sont
équiv
alents.

-S,

--single
Spécifier si la liste doit émettre tous les objets descendants d'un port correspondant au filtre de port, ou uniquement les descendants directs des ports individuels correspondant au filtre. Par défaut, tous les objets descendants sont
listés.

-E,

--endpoints
Inclure les objets endpoint (décodeurs de périphérique mémoire CXL) dans la
liste. 
# cxl list -E
[
  {
    "endpoint":"endpoint2",
    "host":"mem0"
  }
]

-e,

--endpoint
Spécifier le(s) nom(s) de périphérique endpoint CXL ou le(s) identifiant(s) de périphérique pour filtrer le(s) endpoint(s)
émis.

-D,

--decoders
Inclure les objets décodeur (instances de capacité de décodage mémoire CXL dans les bus, les ports et les endpoints) dans la
liste.

-d,

--decoder
Spécifier le(s) nom(s) de périphérique décodeur CXL, le(s) identifiant(s) de périphérique ou le(s) nom(s) de type de décodeur pour filtrer le(s) décodeur(s) émis. Le format d'un nom de décodeur est "decoder<port_id>.<instance_id>". Les noms de type de décodeur possibles sont "root", "switch" ou "endpoint", similaire à la syntaxe du filtre de
port.

-T,

--targets
Étendre les listes de décodeurs avec les informations de cible du port en aval, les listes de ports et de bus avec les informations du port en aval et/ou les régions avec les informations de
mappage. 
# cxl list -BTu -b ACPI.CXL
{
  "bus":"root0",
  "provider":"ACPI.CXL",
  "nr_dports":1,
  "dports":[
    {
      "dport":"ACPI0016:00",
      "alias":"pci0000:34",
      "id":"0"
    }
  ]
}

-R,

--regions
Inclure les objets région dans la
liste.

-X,

--dax
Ajouter les informations DAX aux listes de
régions 
# cxl list -RXu
{
  "region":"region4",
  "resource":"0xf010000000",
  "size":"512.00 MiB (536.87 MB)",
  "interleave_ways":2,
  "interleave_granularity":4096,
  "decode_state":"commit",
  "daxregion":{
    "id":4,
    "size":"512.00 MiB (536.87 MB)",
    "align":2097152,
    "devices":[
      {
        "chardev":"dax4.0",
        "size":"512.00 MiB (536.87 MB)",
        "target_node":0,
        "align":2097152,
        "mode":"system-ram",
        "online_memblocks":0,
        "total_memblocks":4
      }
    ]
  }
}

-r,

--region
Spécifier le(s) nom(s) de périphérique de région CXL ou le(s) identifiant(s) de périphérique pour filtrer la
liste.

-v,

--verbose
Augmenter le niveau de détail de la sortie. Cela peut être spécifié plusieurs fois pour être encore plus verbeux sur les messages d'information et divers, et peut être utilisé pour remplacer les indicateurs omis afin d'afficher des informations spécifiques. Notez que cxl list --verbose --verbose est équivalent à cxl list -vv.
•-v Active --memdevs, --regions, --buses, --ports, --decoders et
--targets.
•-vv Tout ce que -v fournit, plus inclure les périphériques désactivés avec
--idle.
•-vvv Tout ce que -vv fournit, plus active
r --health et
--partition.

--debu

g
Si l'outil cxl a été compilé avec le débogage activé, activer les messages de
débogage.

-u,

--human
Par défaut, la commande produit des données brutes d'entiers faciles à traiter par une machine. À la pla
ce, avec cet indicateur, les nombres représentant la taille du stockage seront formatés sous forme de ch
aînes lisibles par l'homme avec des unités, les autres champs sont convertis en chaînes hexadécimales.
