CPAN::Meta(3perl) Guide de référence des programmeurs Perl CPAN::Meta(3perl)

NOM

CPAN::Meta - les métadonnées de distribution pour une dist CPAN

VERSION

version 2.150010

SYNOPSIS

use v5.10;
use strict;
use warnings;
use CPAN::Meta;
use Module::Load;
my $meta = CPAN::Meta->load_file('META.json');
printf "testing requirements for %s version %s\n",
$meta->name,
$meta->version;
my $prereqs = $meta->effective_prereqs;
for my $phase ( qw/configure runtime build test/ ) {
    say "Requirements for $phase:";
    my $reqs = $prereqs->requirements_for($phase, "requires");
    for my $module ( sort $reqs->required_modules ) {
        my $status;
        if ( eval { load $module unless $module eq 'perl'; 1 } ) {
            my $version = $module eq 'perl' ? $] : $module->VERSION;
            $status = $reqs->accepts_module($module, $version)
                    ? "$version ok" : "$version not ok";
        } else {
            $status = "missing"
        };
        say "  $module ($status)";
    }
}

DESCRIPTION

Les distributions logicielles publiées sur le CPAN incluent un META.json ou, pour les distributions plus anciennes, META.yml, qui décrit la distribution, son contenu et les prérequis pour construire et installer la distribution. La structure de données stockée dans le fichier META.json est décrite dans CPAN::Meta::Spec.

CPAN::Meta fournit une classe simple pour représenter ces métadonnées de distribution (ou distmeta), ainsi que quelques méthodes utiles pour interroger ces données.

La documentation ci-dessous ne concerne que les méthodes de l'objet CPAN::Meta. Pour des informations sur la signification des champs individuels, consultez la spécification.

MÉTHODES

new

my $meta = CPAN::Meta->new($distmeta_struct, \%options);

Renvoie un objet CPAN::Meta valide ou meurt si la référence de hachage de métadonnées fournie ne parvient pas à se valider. Les métadonnées au format plus ancien seront converties en version 2 si elles se valident par rapport à la spécification originale déclarée.

Elle prend une référence de hachage facultative d'options. Les options valides incluent :

•
lazy_validation -- si vrai, new tentera de convertir les métadonnées données en version 2 avant de tenter de les valider. Cela signifie que toute erreur corrigeable sera gérée par CPAN::Meta::Converter avant la validation. (Notez que cela peut entraîner la suppression silencieuse de données optionnelles invalides.) La valeur par défaut est faux.

create

my $meta = CPAN::Meta->create($distmeta_struct, \%options);

C'est la même chose que new(), sauf que les champs "generated_by" et "meta-spec" seront générés s'ils ne sont pas fournis. Cela signifie que la structure de métadonnées est supposée suivre par ailleurs la dernière version de CPAN::Meta::Spec.

load_file

my $meta = CPAN::Meta->load_file($distmeta_file, \%options);

Étant donné un chemin vers un fichier contenant des métadonnées, cette méthode désérialise le fichier selon son suffixe et construit un nouvel objet "CPAN::Meta" , tout comme new(). Elle meurt si la version désérialisée ne parvient pas à se valider par rapport à sa version de spécification déclarée.

Elle prend les mêmes options que new() mais "lazy_validation" vaut vrai par défaut.

load_yaml_string

my $meta = CPAN::Meta->load_yaml_string($yaml, \%options);

Cette méthode renvoie un nouvel objet CPAN::Meta en utilisant le premier document de la chaîne YAML donnée. À tous autres égards, elle est identique à load_file().

load_json_string

my $meta = CPAN::Meta->load_json_string($json, \%options);

Cette méthode renvoie un nouvel objet CPAN::Meta en utilisant la structure représentée par la chaîne JSON donnée. À tous autres égards, elle est identique à load_file().

load_string

my $meta = CPAN::Meta->load_string($string, \%options);

Si vous ne savez pas si une chaîne contient du YAML ou du JSON, cette méthode utilisera Parse::CPAN::Meta pour deviner. À tous autres égards, elle est identique à load_file().

save

$meta->save($distmeta_file, \%options);

Sérialise l'objet en JSON et l'écrit dans le fichier donné. La seule option valide est "version", qui vaut '2' par défaut. Sur Perl 5.8.1 ou ultérieur, le fichier est enregistré avec l'encodage UTF-8.

Pour "version" 2 (ou supérieure), le nom de fichier doit se terminer par '.json'. JSON::PP est le backend JSON par défaut. Utiliser un autre backend JSON nécessite JSON 2.5 ou ultérieur et vous devez définir $ENV{PERL_JSON_BACKEND} sur un backend alternatif pris en charge comme JSON::XS.

Pour "version" inférieure à 2, le nom de fichier doit se terminer par '.yml'. CPAN::Meta::Converter est utilisé pour générer une structure de métadonnées plus ancienne, qui est sérialisée en YAML. CPAN::Meta::YAML est le backend YAML par défaut. Vous pouvez définir $ENV{PERL_YAML_BACKEND} sur un backend alternatif pris en charge, bien que cela ne soit pas recommandé en raison d'incompatibilités subtiles entre les analyseurs YAML sur le CPAN.

meta_spec_version

Cette méthode renvoie la partie version de l'entrée "meta_spec" dans la structure distmeta. Elle est équivalente à :

$meta->meta_spec->{version};

effective_prereqs

my $prereqs = $meta->effective_prereqs;
my $prereqs = $meta->effective_prereqs( \@feature_identifiers );

Cette méthode renvoie un objet CPAN::Meta::Prereqs décrivant tous les prérequis de la distribution. Si une référence de tableau d'identifiants de fonctionnalités est donnée, les prérequis des fonctionnalités identifiées sont fusionnés avec les prérequis principaux de la distribution avant que l'objet CPAN::Meta::Prereqs ne soit renvoyé.

should_index_file

... if $meta->should_index_file( $filename );

Cette méthode renvoie vrai si le fichier donné doit être indexé. Elle décide cela en vérifiant les clés "file" et "directory" dans la propriété "no_index" de la structure distmeta. Notez que ni le format de version ni "release_status" ne sont pris en compte.

$filename doit être donné au format unix.

should_index_package

... if $meta->should_index_package( $package );

Cette méthode renvoie vrai si le paquet donné doit être indexé. Elle décide cela en vérifiant les clés "package" et "namespace" dans la propriété "no_index" de la structure distmeta. Notez que ni le format de version ni "release_status" ne sont pris en compte.

features

my @feature_objects = $meta->features;

Cette méthode renvoie une liste d'objets CPAN::Meta::Feature, un pour chaque fonctionnalité optionnelle décrite par les métadonnées de la distribution.

feature

my $feature_object = $meta->feature( $identifier );

Cette méthode renvoie un objet CPAN::Meta::Feature pour la fonctionnalité optionnelle avec l'identifiant donné. Si aucune fonctionnalité avec cet identifiant n'existe, une une exception sera levée.

as_struct

my $copy = $meta->as_struct( \%options );

Cette méthode retourne une copie profonde des métadonnées de l'objet sous forme d'une référence de hachage non bénie. Elle prend une référence de hachage optionnelle d'options. Si la référence de hachage contient un "version" argument, les métadonnées copiées seront converties vers la version de la spécification et retournées. Par exemple :

my $old_spec = $meta->as_struct( {version => "1.4"} );

as_string

my $string = $meta->as_string( \%options );

Cette méthode retourne une copie sérialisée des métadonnées de l'objet sous forme d'une chaîne de caractères. (Les chaînes ne sont pas encodées en UTF-8.) Elle prend une référence de hachage optionnelle d'options. Si la référence de hachage contient un "version" argument, les métadonnées copiées seront converties vers la version de la spécification et retournées. Par exemple :

my $string = $meta->as_string( {version => "1.4"} );

Pour une "version" supérieure ou égale à 2, la chaîne sera sérialisée en JSON. Pour une "version" inférieure à 2, la chaîne sera sérialisée en YAML. Dans les deux cas, les mêmes règles sont suivies que dans la save() méthode pour choisir un backend de sérialisation.

La structure sérialisée inclura une entrée "x_serialization_backend" donnant le paquet et la version utilisés pour la sérialisation. Toute clé existante dans l'objet $meta donné sera écrasée.

DONNÉES DE TYPE CHAÎNE

Les méthodes suivantes retournent une valeur unique, qui est la valeur pour l'entrée correspondante dans la structure distmeta. Les valeurs doivent être soit undef soit des chaînes.

  • abstract
  • description
  • dynamic_config
  • generated_by
  • name
  • release_status
  • version

DONNÉES DE TYPE LISTE

Ces méthodes retournent des listes de valeurs de chaînes, qui peuvent être représentées dans la structure distmeta comme des références de tableau ou des scalaires :

  • authors
  • keywords
  • licenses

Les méthodes "authors" et "licenses" peuvent aussi être appelées comme "author" et "license", respectivement, pour correspondre au nom de champ dans la structure distmeta.

DONNÉES DE TYPE TABLE DE HACHAGE

Ces accesseurs retournent des références de hachage de structures de données arbitraires non bénies, chacune décrite plus en détail dans la spécification :

  • meta_spec
  • resources
  • provides
  • no_index
  • prereqs
  • optional_features

DONNÉES PERSONNALISÉES

Une liste de clés personnalisées est disponible via la méthode "custom_keys" et des clés particulières peuvent être récupérées avec la "custom" méthode.

say $meta->custom($_) for $meta->custom_keys;

Si une clé personnalisée fait référence à une structure de données, une copie profonde est retournée.
