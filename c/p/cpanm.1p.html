NOM

cpanm - récupérer, décompresser, compiler et installer des modules depuis CPAN

SYNOPSIS

cpanm Test::More                                 # installer Test::More
cpanm MIYAGAWA/Plack-0.99_05.tar.gz              # chemin complet de la distribution
cpanm http://example.org/LDS/CGI.pm-3.20.tar.gz  # installer depuis une URL
cpanm ~/dists/MyCompany-Enterprise-1.00.tar.gz   # installer depuis un fichier local
cpanm --interactive Task::Kensho                 # configurer de manière interactive
cpanm .                                          # installer depuis un répertoire local
cpanm --installdeps .                            # installer toutes les dépendances du répertoire courant
cpanm -L extlib Plack                            # installer Plack et toutes les dépendances non-core dans extlib
cpanm --mirror http://cpan.cpantesters.org/ DBI  # utiliser le miroir à synchronisation rapide
cpanm --from https://cpan.metacpan.org/ Plack    # utiliser uniquement le miroir HTTPS

COMMANDES

(arguments)
Les arguments en ligne de commande peuvent être un nom de module, un fichier de distribution, un chemin de fichier local, une URL HTTP ou une URL de dépôt git. Les commandes suivantes fonctionneront toutes comme prévu. 
cpanm Plack
cpanm Plack/Request.pm
cpanm MIYAGAWA/Plack-1.0000.tar.gz
cpanm /path/to/Plack-1.0000.tar.gz
cpanm https://cpan.metacpan.org/authors/id/M/MI/MIYAGAWA/Plack-0.9990.tar.gz
cpanm git://github.com/plack/Plack.git

De plus, vous pouvez utiliser la notation avec "~" et "@" pour spécifier la version d'un module donné. "~" spécifie l'exigence de version au format CPAN::Meta::Spec, tandis que "@" fixe la version exacte, et est un raccourci pour "~"== VERSION"".

cpanm Plack~1.0000                 # 1.0000 ou plus récent
cpanm Plack~">= 1.0000, < 2.0000"  # le plus récent de 1.xxxx
cpanm Plack@0.9990                 # version spécifique. identique à Plack~"== 0.9990"

La requête de version incluant une version spécifique ou une plage sera envoyée à MetaCPAN pour rechercher des versions précédentes. La requête cherchera dans les archives BackPAN par défaut, sauf si vous spécifiez l'option "--dev" , auquel cas les versions archivées seront filtrées.

Pour un dépôt git, vous pouvez spécifier une branche, un tag ou un SHA de commit à compiler. La valeur par défaut est "master"

cpanm git://github.com/plack/Plack.git@1.0000        # tag
cpanm git://github.com/plack/Plack.git@devel         # branche
-i, --install
Installe les modules. C'est le comportement par défaut et c'est juste une option de compatibilité pour faire fonctionner la commande comme cpan ou cpanp.
--self-upgrade
Se met à jour lui-même. C'est juste un alias pour : 
cpanm App::cpanminus
--info
Affiche les informations de la distribution au format "AUTEUR/NomDist-ver.tar.gz" sur la sortie standard.
--installdeps
Installe les dépendances de la distribution cible mais ne la compile pas elle-même. Pratique si vous voulez essayer l'application depuis un dépôt sous contrôle de version comme git. 
cpanm --installdeps .
--look
Télécharge et décompresse la distribution puis ouvre le répertoire avec votre shell. Pratique pour explorer le code source ou effectuer des tests manuels.
-h, --help
Affiche le message d'aide.
-V, --version
Affiche le numéro de version.

OPTIONS

Vous pouvez spécifier les options par défaut dans la variable d'environnement "PERL_CPANM_OPT" .

-f, --force
Force l'installation des modules même si les tests ont échoué.
-n, --notest
Ignore les tests des modules. Utilisez cette option seulement si vous voulez gagner du temps en installant des centaines de distributions sur le même perl et la même architecture que vous avez déjà testés pour vous assurer qu'ils compilent correctement.

La valeur par défaut est false, et vous pouvez spécifier "--no-notest" pour annuler cette option si elle est définie dans les options par défaut dans "PERL_CPANM_OPT".

--test-only
Exécute uniquement les tests, et n'installe pas le module ou les distributions spécifiés. Pratique si vous voulez vérifier que les nouvelles (ou même anciennes) versions passent leurs tests unitaires sans installer le module.

Notez que si vous spécifiez cette option avec un module ou une distribution qui a des dépendances, ces dépendances seront installées si vous ne les avez pas actuellement.

-S, --sudo
Passe à l'utilisateur root avec "sudo" lors de l'installation des modules. Utilisez cette option si vous voulez installer des modules dans le chemin d'inclusion du perl système.

La valeur par défaut est false, et vous pouvez spécifier "--no-sudo" pour annuler cette option si elle est définie dans les options par défaut dans "PERL_CPANM_OPT".

-v, --verbose
Rend la sortie verbeuse. Active aussi la configuration interactive. (Voir --interactive)
-q, --quiet
Rend la sortie encore plus silencieuse que par défaut. N'affiche que les dépendances réussies/échouées dans la sortie.
-l, --local-lib
Définit le chemin compatible local::lib dans lequel installer les modules. Vous n'avez pas besoin de définir ceci si vous configurez déjà les variables d'environnement du shell avec local::lib, mais cela peut aussi être utilisé pour annuler cette configuration.
-L, --local-lib-contained
Identique à "--local-lib" mais avec --self-contained activé. Toutes les dépendances non-core seront installées même si elles sont déjà installées.

Par exemple,

cpanm -L extlib Plack

installerait Plack et toutes ses dépendances non-core dans le répertoire "extlib", qui peut être chargé depuis votre application avec :

use local::lib '/path/to/extlib';

Notez que cette option ne fonctionne PAS de manière fiable avec les installations de perl fournies par les distributeurs d'opérating system qui suppriment les modules standard de perl, comme RHEL, Fedora et CentOS, SAUF SI vous installez aussi les paquets fournissant tous les modules qui ont été supprimés. Pour ces systèmes, vous voudrez probablement installer le méta-paquet "perl-core" qui fait exactement cela.

--self-contained
Lors de l'examen des dépendances, suppose qu'aucun module non-core n'est installé sur le système. Pratique si vous voulez regrouper les dépendances de l'application dans un seul répertoire pour pouvoir les distribuer sur d'autres machines.
--exclude-vendor
N'inclut pas les modules installés sous les chemins 'vendor' lors de la recherche de modules core lorsque l'indicateur "--self-contained" est actif. Cela restaure le comportement antérieur à la version 1.7023.
--mirror
Spécifie l'URL de base du miroir CPAN à utiliser, comme "http://cpan.cpantesters.org/" (vous pouvez omettre la barre oblique finale). Vous pouvez spécifier plusieurs URL de miroirs en répétant l'option en ligne de commande.

Vous pouvez utiliser un répertoire local qui a la structure d'un miroir CPAN (créé par des outils comme OrePAN ou Pinto) en utilisant un schéma d'URL spécial "file://". Si l'URL donnée commence par `/` (sans aucun schéma), elle est considérée comme un schéma fichier également.

cpanm --mirror file:///path/to/mirror
cpanm --mirror ~/minicpan      # Parce que le shell développe ~ en /home/user

La valeur par défaut est "https://www.cpan.org/".

--mirror-only
Télécharge le fichier d'index 02packages.details.txt.gz du miroir au lieu de interroger la CPAN Meta DB. Celal permet également de se désinscrire efficacement de l'envoi de vos versions locales de Perl vers des serveurs de bases de données backend tels que CPAN Meta DB et MetaCPAN.

Sélectionnez cette option si vous utilisez un miroir local de CPAN, tel que minicpan lorsque vous êtes hors ligne, ou votre propre index CPAN (également appelé darkpan).

--from, -M
cpanm -M https://cpan.metacpan.org/
cpanm --from https://cpan.metacpan.org/

Utilisez l'URL du miroir et son index fournis comme unique source pour rechercher et télécharger des modules.

Cela fonctionne de manière similaire à la combinaison de "--mirror" et "--mirror-only", avec une petite différence : contrairement à "--mirror" qui ajoute l'URL à la liste des miroirs, "--from" (ou "-M" en abrégé) utilise l'URL spécifiée comme sa unique source pour télécharger l'index et les modules. Cela permet à l'option de toujours remplacer le miroir par défaut, qui pourrait avoir été défini via des options globales telles que celle définie par la variable d'environnement "PERL_CPANM_OPT".

Astuce : Il peut être utile de nommer ces options avec vos alias de shell, par exemple :

alias minicpanm='cpanm --from ~/minicpan'
alias darkpan='cpanm --from http://mycompany.example.com/DPAN'
--mirror-index
EXPÉRIMENTAL : Spécifie le chemin d'accès au fichier "02packages.details.txt" pour l'index de recherche de modules.
--cpanmetadb
EXPÉRIMENTAL : Spécifie une URI alternative pour les recherches d'index CPAN MetaDB.
--metacpan
Préfère l'API MetaCPAN à CPAN MetaDB.
--cpanfile
EXPÉRIMENTAL : Spécifie un chemin alternatif pour que cpanfile recherche, lorsque la commande "--installdeps" est utilisée. La valeur par défaut est "cpanfile".
--prompt
Demande une confirmation lorsque les tests échouent, afin que vous puissiez ignorer, forcer l'installation, réessayer ou consulter le shell pour voir ce qui ne va pas. Il demande également lorsque l'une des dépendances échoue si vous souhaitez poursuivre l'installation.

La valeur par défaut est false, et vous pouvez utiliser "--no-prompt" pour remplacer si elle est définie dans les options par défaut de "PERL_CPANM_OPT".

--dev
EXPÉRIMENTAL : recherche également une nouvelle version développeur. La valeur par défaut est false.
--reinstall
cpanm, lorsqu'il reçoit un nom de module dans la ligne de commande (c'est-à-dire "cpanm Plack"), vérifie d'abord la version installée localement et saute l'installation si elle est déjà installée. Cette option permet de sauter cette vérification, donc : 
cpanm --reinstall Plack

réinstallera Plack même si votre version installée localement est la dernière, ou même plus récente (ce qui se produirait si vous installiez une version développeur à partir de dépôts de contrôle de version).

La valeur par défaut est false.

--interactive
Rend la configuration (telle que "Makefile.PL" et "Build.PL") interactive, afin que vous puissiez répondre aux questions de la distribution qui nécessitent une configuration personnalisée ou des distributions Task::.

La valeur par défaut est false, et vous pouvez utiliser "--no-interactive" pour remplacer si elle est définie dans les options par défaut de "PERL_CPANM_OPT".

--pp, --pureperl
Préfère la version Pure perl des modules en définissant "PUREPERL_ONLY=1" pour les distributions basées sur MakeMaker et "--pureperl-only" pour celles basées sur Build.PL. Notez que tous les modules CPAN ne prennent pas encore en charge cette convention.
--with-recommends, --with-suggests
EXPÉRIMENTAL : Installe les dépendances déclarées comme "recommends" et "suggests" respectivement, selon la spécification META. Lorsque ces dépendances échouent à s'installer, cpanm poursuit l'installation, car il s'agit simplement de recommandations/suggestions.

L'activation de cette option pourrait potentiellement créer une dépendance circulaire pour quelques modules sur CPAN, lorsque "recommends" ajoute un module qui "recommends" le module en retour.

Il existe également "--without-recommend" et "--without-suggests" pour remplacer la décision par défaut prise précédemment dans "PERL_CPANM_OPT".

Les deux valeurs par défaut sont false.

--with-develop
EXPÉRIMENTAL : Installe les dépendances de la phase de développement dans les fichiers META ou "cpanfile" lorsqu'il est utilisé avec "--installdeps". La valeur par défaut est false.
--with-configure
EXPÉRIMENTAL : Installe les dépendances de la phase de configuration dans "cpanfile" lorsqu'il est utilisé avec "--installdeps". La valeur par défaut est false.
--with-feature, --without-feature, --with-all-features
EXPÉRIMENTAL : Spécifie la fonctionnalité à activer, si un module prend en charge les fonctionnalités optionnelles selon la spécification META 2.0. 
cpanm --with-feature=opt_csv Spreadsheet::Read

Les fonctionnalités peuvent également être choisies interactivement lorsque l'option "--interactive" est activée.

"--with-all-features" active toutes les fonctionnalités optionnelles, et "--without-feature" peut sélectionner une fonctionnalité à désactiver.

--configure-timeout, --build-timeout, --test-timeout
Spécifie la durée du délai d'attente (en secondes) pour les processus de configuration, de compilation et de test. Les valeurs par défaut actuelles sont : 60 pour la configuration, 3600 pour la compilation et 1800 pour le test.
--configure-args, --build-args, --test-args, --install-args
EXPÉRIMENTAL : Transmet des arguments pour les commandes de configuration/compilation/test/installation respectivement, pour un module donné à installer. 
cpanm DBD::mysql --configure-args="--cflags=... --libs=..."

L'argument n'est activé que pour le module passé en argument de ligne de commande, pas pour les dépendances.

--scandeps
OBSOLÈTE : Analyse les dépendances des modules donnés et affiche l'arbre sous forme de texte. (Voir "--format" ci-dessous pour plus d'options)

Étant donné que cette commande n'installe aucune distribution, il sera utile de taper :

cpanm --scandeps Catalyst::Runtime

vous pouvez vous assurer des modules qui seront installés.

Cette commande prend en compte les modules que vous avez déjà installés sur votre système. Si vous souhaitez voir quels modules seront installés par rapport à une installation Perl vierge, vous pourriez vouloir la combiner avec l'option "-L".

--format
OBSOLÈTE : Détermine le format dans lequel afficher l'arbre de dépendances analysé. Les options disponibles sont "tree", "json", "yaml" et "dists".
tree
Affiche l'arbre dans un format texte brut. C'est la valeur par défaut.
json, yaml
Affiche l'arbre au format JSON ou YAML. Les modules JSON et YAML doivent être installés respectivement. L'arbre de sortie est représenté comme un tuple récursif de : 
[ distribution, dépendances ]

et le conteneur est un tableau contenant les éléments racine. Notez qu'il peut y avoir plusieurs nœuds racine, car vous pouvez donner plusieurs modules à la commande "--scandeps".

dists
"dists" est un format de sortie spécial, où il imprime le nom de fichier de la distribution dans l'ordre de parcours en profondeur après la résolution des dépendances, comme : 
GAAS/MIME-Base64-3.13.tar.gz
GAAS/URI-1.58.tar.gz
PETDANCE/HTML-Tagset-3.20.tar.gz
GAAS/HTML-Parser-3.68.tar.gz
GAAS/libwww-perl-5.837.tar.gz

ce qui signifie que vous pouvez installer ces distributions dans cet ordre sans dépendances supplémentaires. Combiné avec l'option "-L", il sera utile pour rejouer les installations sur d'autres machines.

--save-dists
Spécifie le chemin du répertoire optionnel pour copier les tarballs téléchargés dans la structure de répertoire compatible avec le miroir CPAN, c'est-à-dire authors/id/A/AU/AUTHORS/Foo-Bar-version.tar.gz.

Si le tarball de distribution ne provient pas de CPAN, par exemple d'un fichier local ou de GitHub, il sera enregistré sous vendor/Foo-Bar-version.tar.gz.

--uninst-shadows
Désinstalle les fichiers d'ombre de la distribution que vous installez. Cela évite la confusion si vous essayez d'installer des modules principaux (double vie) de CPAN sur Perl 5.10 ou plus ancien, ou des modules qui étaient auparavant basés sur XS mais qui sont passés à Pure perl à partir d'une certaine version.

Si vous exécutez cpanm en tant que root et utilisez "INSTALL_BASE" ou équivalent pour spécifier un chemin d'installation personnalisé, vous DEVEZ désactiver cette option afin de ne pas désinstaller accidentellement des modules double vie du chemin d'inclusion principal.

La valeur par défaut est true si votre version de Perl est inférieure à 5.12, et vous pouvez la désactiver avec "--no-uninst-shadows".

NOTE : Depuis la version 1.3000, ce drapeau est désactivé par cpanm(1p) — manuel d'installation Linux

NOM

cpanm - exécuter cpanm

SYNOPSIS

cpanm [OPTIONS] [MODULE(S)]

COMMANDES

--install, -i
Installe le ou les modules spécifiés. Ceci est la commande par défaut.
--uninstall, -U
Désinstalle le ou les modules spécifiés.
--show
Affiche les fichiers faisant partie d'une distribution de module.
--path
Affiche le chemin d'installation du module.

OPTIONS

-l DIR
Installe les modules dans le répertoire DIR. Par défaut, cpanm installe les modules dans le répertoire de local::lib s'il est configuré, sinon dans le répertoire de site Perl du système. Cette option est particulièrement utile lorsque vous voulez installer des modules qui nécessitent des privilèges root. Si vous ne spécifiez pas cette option, elle sera définie par défaut pour Perl plus récent que 5.12, car avec 5.12, `@INC` contient le répertoire `site_perl` *avant* le chemin de la bibliothèque Perl principale, et la désinstallation de l'ombre n'est plus nécessaire et fait plus de mal en supprimant des fichiers du chemin de la bibliothèque principale.

--uninstall, -U
Désinstalle un module du chemin de la bibliothèque. Il recherche un fichier packlist pour les modules donnés et supprime tous les fichiers inclus dans la même distribution.

Si vous activez `local::lib`, il ne supprime que les fichiers du répertoire `local::lib`.

Si vous essayez de désinstaller un module dans le répertoire "perl" (c'est-à-dire un module de base), une erreur sera générée.

Une boîte de dialogue sera affichée pour confirmer les fichiers à supprimer. Si vous passez également l'option "-f", la boîte de dialogue sera ignorée et la désinstallation sera forcée.

--cascade-search
EXPÉRIMENTAL : Spécifie s'il faut effectuer une recherche en cascade lorsque vous spécifiez plusieurs miroirs et qu'un miroir n'a pas un module ou a une version inférieure du module demandée. Par défaut à faux.
--skip-installed
Spécifie si un module donné dans la ligne de commande doit être ignoré si sa dernière version est déjà installée. Par défaut à vrai.

NOTE : La variable d'environnement "PERL5LIB" doit être correctement définie pour que cela fonctionne avec les modules installés à l'aide de `local::lib`, à moins que vous n'utilisiez toujours l'option "-l".

--skip-satisfied
EXPÉRIMENTAL : Spécifie si un module (et sa version) donné dans la ligne de commande doit être ignoré s'il est déjà installé.

Si vous exécutez :

cpanm --skip-satisfied CGI DBI~1.2

cpanm ne les installera pas si vous avez déjà CGI (pour n'importe quelle version) ou si vous avez DBI avec une version supérieure à 1.2. C'est similaire à "--skip-installed", mais tandis que "--skip-installed" vérifie si la dernière version de CPAN est installée, "--skip-satisfied" vérifie si une version demandée (ou pas, ce qui signifie n'importe quelle version) est installée.

Par défaut à faux.

--verify
Vérifie l'intégrité des fichiers de distribution récupérés de CPAN en utilisant le fichier CHECKSUMS, et le fichier SIGNATURES (s'il est trouvé dans la distribution). Par défaut à faux.

L'utilisation de cette option ne vérifie pas l'intégrité du fichier CHECKSUMS, et il est peu sûr de se fier à cette option si vous utilisez un miroir CPAN auquel vous ne faites pas confiance.

--report-perl-version
Indique s'il faut signaler la version Perl installée localement aux divers serveurs web dans le cadre de l'User-Agent. Par défaut à vrai sauf si des variables d'environnement liées à l'intégration continue telles que "TRAVIS", "CI" ou "AUTOMATED_TESTING" sont activées. Vous pouvez le désactiver en utilisant "--no-report-perl-version".
--auto-cleanup
Spécifie le nombre de jours après lesquels les répertoires de travail de cpanm expirent. Par défaut à 7, ce qui signifie que les anciens répertoires de travail seront nettoyés dans une semaine.

Vous pouvez définir la valeur à 0 pour que cpan ne nettoie jamais ces répertoires.

--man-pages
Génère les pages de manuel pour les exécutables (man1) et les bibliothèques (man3).

Par défaut à vrai (pages de manuel générées) sauf si l'option "-L|--local-lib-contained" est fournie, auquel cas elle est définie à faux. Vous pouvez la désactiver avec "--no-man-pages".

--lwp
Utilise le module LWP pour télécharger des éléments via HTTP. Par défaut à vrai, et vous pouvez dire "--no-lwp" pour désactiver l'utilisation de LWP, lorsque vous voulez mettre à niveau LWP depuis CPAN sur certains systèmes Perl défaillants.
--wget
Utilise GNU Wget (si disponible) pour télécharger des éléments. Par défaut à vrai, et vous pouvez dire "--no-wget" pour désactiver l'utilisation de Wget (les versions de Wget antérieures à 1.9 ne prennent pas en charge l'option "--retry-connrefused" utilisée par cpanm).
--curl
Utilise cURL (si disponible) pour télécharger des éléments. Par défaut à vrai, et vous pouvez dire "--no-curl" pour désactiver l'utilisation de cURL.

Normalement, avec les options "--lwp", "--wget" et "--curl" définies à vrai (ce qui est le défaut), cpanm essaie LWP, Wget, cURL et HTTP::Tiny (dans cet ordre) et utilise le premier disponible.

VARIABLES D'ENVIRONNEMENT

PERL_CPANM_HOME
Le répertoire que cpanm doit utiliser pour stocker les téléchargements et construire et tester les modules. Par défaut, le répertoire ".cpanm" dans le répertoire personnel de l'utilisateur.
PERL_CPANM_OPT
Si défini, ajoute un ensemble d'options par défaut à chaque commande cpanm. Ces options viennent en premier, et sont donc remplacées par les options de la ligne de commande.
