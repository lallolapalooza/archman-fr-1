DESCRIPTIO

N

cpfind est un détecteur de points de contrôle pour Hugin. Il attend un fichier projet en entrée et écrit un fichier projet avec des points de contrôle en cas de succès. Il dépend d'informations raisonnables sur l'objectif dans le fichier projet

d'entrée.

La première étape est la description des caractéristiques : à cette étape, les images du fichier projet sont chargées et les points d'intérêt (keypoints) sont recherchés. Ils décrivent des caractéristiques distinctives dans l'image. cpfind utilise un descripteur basé sur le gradient pour la description des caractéristiques des points

d'intérêt.

Dans une deuxième étape, l'appariement des caractéristiques, tous les points d'intérêt de deux imag

es sont appariés entre eux pour trouver des caractéristiques présentes sur les deux images. Si cet
appariement est réussi, deux points d'intérêt dans les deux images deviennent un point de contrôle.

UTILISATI

ON

Images rectilignes et images à

fisheye

Cpfind peut trouver des points de contrôle dans des images rectilignes et à fisheye. Pour obtenir de bons points de contrôle, les images avec un champ de vision horizontal élevé (par exemple ultra grand-angle rectiligne ou fisheye) sont

donc remappées dans un espace conforme (cpfind utilise la projection stéréographique) et l'appariement des caractéristiques a lieu dans cet espace. Avant d'écrire les points de contrôle, les coordonnées sont remappées vers l'espace
de l'image. Cela se produit automatiquement en fonction des informations sur l'objectif dans le fichier projet d'entrée. Vérifiez donc que votre fichier projet d'entrée contient des informations raisonnables sur l'objectif utilisé.

Utilisation de

celeste

Les panoramas extérieurs contiennent souvent des nuages. Les nuages sont de mauvaises zones pour placer des points de contrôle car ce sont des objets mobiles. Cpfind peut utiliser le même algorithme que celeste_standalone pour masquer les zones contenant des nuages. (Cela n'est fait qu'en interne pour l'étape de recherche des points d'intérêt et ne modifie pas le canal alpha de votre image. Si vous voulez générer une image de masque, utilisez celeste_standalone). Pour exécuter cpfind avec celeste,

utilisez 
cpfind --celeste -o sortie.pto entrée.
pto

L'utilisation de cpfind avec celeste intégré devrait être supérieure à l'utilisation de cpfind et celeste_standalone de manière séquentielle. Lors de l'exécution de cpfind avec celeste, les zones de nuages, qui contiennent souvent des points d'intérêt avec une mesure de qualité élevée, sont ignorées et les zones sans nuages sont utilisées à la place. Lors de l'exécution de cpfind sans celeste, des points d'intérêt sur les nuages sont également trouvés. Lorsque celeste_standalone est exécuté par la suite, ces points de contrôle sont supprimés. Dans le pire des cas, tous les points de contrôle d'une certaine paire d'images sont

supprimés.

L'exécution de cpfind avec celeste conduit donc à une meilleure « qualité des points de contrôle » pour les panoramas extérieurs (par exemple un panorama avec des nuages). L'exécution de cpfind avec celeste prend plus de temps que cpfind seul. Pour les panoramas intérieurs, cette option n'a donc pas besoin d'être spécifiée (en raison du temps de calcul plus long)

.

L'étape celeste peut être réglée finement par les paramètres --celesteRadius et --celesteThreshol

d
.

Stratégie

d'appariement

Toutes les

paires

C'est la stratégie d'appariement par défaut. Ici, toutes les paires d'images sont appariées entre elles. Par exemple, si votre projet contient 5 images, alors cpfind apparie les paires d'images : 0-1, 0-2, 0-3, 0-4, 1-2, 1-3, 1-4, 2-3, 2-4 et

3-4

Cette stratégie fonctionne pour toutes les stratégies de prise de vue (une seule rangée, plusieurs rangées, non ordonnées). Elle trouve (presque) toutes les paires d'images connectées. Mais elle est coûteuse en calcul pour les projets avec beaucoup d'images, car elle teste de nombreuses paires d'images qui ne sont pas

connectées.

Appariement

linéaire

Cette stratégie d'appariement fonctionne le mieux pour les panoramas à une seule rangée

: 
cpfind --linearmatch -o sortie.pto entrée.
pto

Cela ne détectera que des correspondances entre des images adjacentes, par exemple pour l'exemple des 5 images, il appariera les paires d'images 0-1, 1-2, 2-3 et 3-4. La distance d'appariement peut être augmentée avec l'option --linearmatchlen. Par exemple, avec --linearmatchlen 2, cpfind appariera une image avec l'image suivante et l'image d'après, dans notre exemple ce serait 0-1, 0-2, 1-2, 1-3, 2-3, 2-4 et

3-4.

Appariement

multi-rangées

C'est une stratégie d'appariement optimisée pour les panoramas à une et plusieurs rangées

: 
cpfind --multirow -o sortie.pto entrée.
pto

L'algorithme est le même que celui décrit pour les panoramas multi-rangées. En intégrant cet algorithme dans cpfind, il est plus rapide en utilisant plusieurs cœurs de CPU modernes et ne met pas en cache les points d'intérêt sur le disque (ce qui prend du temps). Si vous voulez utiliser cet appariement multi-rangées dans hugin, définissez le type de détecteur de points de contrôle sur « All images at once » (Toutes les images à la fois)

.

Mise en cache des points d'intérêt sur le

disque

Le calcul des points d'intérêt prend un certain temps. cpfind offre donc la possibilité de sauvegarder les points d'intérêt dans un fichier et de les réutiliser plus tard. Avec --kall, les points d'intérêt pour toutes les images du projet sont sauvegardés sur le disque. Si vous voulez seulement les points d'intérêt d'une image particulière, utilisez le paramètre -k avec le numéro de l'image

: 
cpfind --kall entrée.pto
cpfind -k 0 -k 1 entrée.
pto

Les fichiers de points d'intérêt sont sauvegardés par défaut dans le même répertoire que les images avec l'extension .key. Dans ce cas, aucun appariement d'images n'a lieu et par conséquent aucun fichier projet de sortie n'a besoin d'être spécifié. Si cpfind trouve des fichiers .key pour une image dans le projet, il les utilisera automatiquement et n'exécutera pas à nouveau le descripteur de caractéristiques sur cette image. Si vous voulez les sauvegarder dans un autre répertoire, utilisez l'option

--keypath.

Cette procédure peut également être automatisée avec l'option --cache

: 
cpfind --cache -o sortie.pto entrée.
pto

Dans ce cas, il essaie de charger les fichiers de points d'intérêt existants. Pour les images qui n'ont pas de fichier de points d'intérêt, les points d'intérêt sont détectés et sauvegardés dans le fichier. Ensuite, il apparie tous les points d'intérêt chargés et nouvellement trouvés et écrit le projet de

sortie.

Si vous n'avez plus besoin des fichiers .key, ils peuvent être supprimés automatiquement

par 
cpfind
--cle
an entr
ée.pto

nombreux.
