CPAN::Meta::Converter(3perl) Guide de référence pour programmeurs Perl CPAN::Meta::Converter(3perl)

NOM

CPAN::Meta::Converter - Convertit les structures de métadonnées de distribution CPAN

VERSION

version 2.150010

SYNTAXE

my $struct = decode_json_file('META.json');
my $cmc = CPAN::Meta::Converter->new( $struct );
my $new_struct = $cmc->convert( version => "2" );

DESCRIPTION

Ce module convertit les structures de métadonnées CPAN d'une forme à une autre. L'utilisation principale est de convertir les anciennes structures vers la version la plus moderne de la spécification, mais d'autres transformations pourront être implémentées à l'avenir si nécessaire. (Par exemple, supprimer tous les champs personnalisés ou supprimer tous les champs optionnels.)

MÉTHODES

new

my $cmc = CPAN::Meta::Converter->new( $struct );

Le constructeur doit recevoir une structure de métadonnées valide, mais les structures invalides sont acceptées. Si aucune version de meta-spec n'est fournie, la version 1.0 sera supposée.

Optionnellement, vous pouvez fournir un argument "default_version" après $struct :

my $cmc = CPAN::Meta::Converter->new( $struct, default_version => "1.4" );

Ceci est nécessaire uniquement lors de la conversion d'un fragment de métadonnées qui n'inclut pas de champ "meta-spec".

convert

my $new_struct = $cmc->convert( version => "2" );

Retourne une nouvelle référence de hachage avec les métadonnées converties dans une autre forme. "convert" mourra si une conversion/standardisation résulte encore en une structure invalide.

Les paramètres valides incluent :

•
"version" -- Indique la version de spécification désirée (par exemple, "1.0", "1.1"... "1.4", "2"). Par défaut, la dernière version de la spécification CPAN Meta.

La conversion procède version par version. Par exemple, une structure version 1.2 pourrait être convertie en 1.3, puis en 1.4, et enfin en version 2. Le processus de conversion tente de corriger les erreurs simples et de standardiser les données. Par exemple, si "author" est donné comme un scalaire, il sera converti en une référence de tableau contenant l'élément. (Convertir une structure vers sa propre version nettoiera et standardisera également.)

Lorsque les données sont nettoyées et standardisées, les champs manquants ou invalides seront remplacés par des valeurs par défaut raisonnables lorsque possible. Cela peut être une perte d'information ou imprécis. Par exemple, certains fichiers META.yml mal structurés sur CPAN ont des modules prérequis listés à la fois comme clés et valeurs :

requires => { 'Foo::Bar' => 'Bam::Baz' }

Ceux-ci seraient séparés et chacun serait converti en un prérequis avec une version minimale de zéro.

Lorsque certains champs obligatoires sont manquants ou invalides, la conversion tentera de fournir une valeur par défaut raisonnable ou les remplira avec la valeur 'unknown'. Par exemple, un champ "license" manquant ou non reconnu résultera en un champ "license" de 'unknown'. Les champs qui peuvent obtenir 'unknown' incluent :

  • abstract
  • author
  • license

upgrade_fragment

my $new_struct = $cmc->upgrade_fragment;

Retourne une nouvelle référence de hachage avec les métadonnées converties vers la dernière version de la spécification CPAN Meta. Aucune validation n'est effectuée sur le résultat - vous devez valider après avoir fusionné les fragments en un document de métadonnées complet.

Disponible depuis la version 2.141170.
