CPANPLUS::Shell::Default::Plugins::HOWTO(3) Documentation Perl contribuée par l'utilisateur CPANPLUS::Shell::Default::Plugins::HOWTO(3)

NOM

CPANPLUS::Shell::Default::Plugins::HOWTO -- documentation sur la façon d'écrire vos propres plugins

SYNOPSIS

package CPANPLUS::Shell::Default::Plugins::MyPlugin;
### retourne la correspondance commande => méthode
sub plugins { ( myplugin1 => 'mp1', myplugin2 => 'mp2' ) }
### méthode appelée lorsque la commande '/myplugin1' est émise
sub mp1 { .... }
### méthode appelée lorsque la commande '/? myplugin1' est émise
sub mp1_help { return "Texte d'aide" }

DESCRIPTION

Ce texte de pod explique comment écrire vos propres plugins pour "CPANPLUS::Shell::Default".

COMMENT FAIRE

Enregistrement des modules de plugin

Les plugins sont détectés en utilisant "Module::Pluggable". Chaque module dans le espace de noms "CPANPLUS::Shell::Default::Plugins::*" est considéré comme un plugin et une tentative de chargement est effectuée.

Par conséquent, tout plugin doit être déclaré dans cet espace de noms, dans un fichier ".pm" correspondant.

Enregistrement des commandes de plugin

Pour enregistrer des commandes de plugin, une liste de paires clé valeur doit être retournée par une méthode "plugins" dans votre paquet. Les clés sont les commandes que vous souhaitez enregistrer, les valeurs sont les méthodes du paquet de plugin que vous souhaitez appeler lorsque la commande est émise.

Par exemple, un simple plugin 'Hello, World !':

package CPANPLUS::Shell::Default::Plugins::HW;
sub plugins { return ( helloworld => 'hw' ) };
sub hw { print "Hello, world!\n" }

Lorsque l'utilisateur dans le shell par défaut émet maintenant la commande "/helloworld", cette commande sera transmise au plugin et sa méthode "hw" sera appelée.

Enregistrement de l'aide de plugin

Pour fournir des informations d'utilisation pour votre plugin, l'utilisateur du shell par défaut peut taper "/? COMMANDE_PLUGIN". Dans ce cas, la fonction "COMMANDE_PLUGIN_help" sera appelée dans votre paquet de plugin.

Par exemple, en étendant l'exemple ci-dessus, lorsqu'un utilisateur appelle "/? helloworld", la fonction "hw_help" sera appelée, ce qui pourrait ressembler à ceci :

sub hw_help { "    /helloworld      # affiche "Hello, world!\n" "}

Si vous ne fournissez pas de fonction _help correspondante à vos commandes, le shell par défaut la gérera avec succès, mais l'utilisateur se retrouvera sans informations d'utilisation sur vos commandes, il est donc considéré comme indésirable d'omettre les fonctions d'aide.

Arguments des commandes de plugin

Toute fonction de plugin recevra les arguments suivants lorsqu'elle sera appelée, qui sont tous positionnels :

Nom de classe -- Le nom de votre classe de plugin
Shell -- L'objet CPANPLUS::Shell::Default
Backend -- L'objet CPANPLUS::Backend
Commande -- La commande émise par l'utilisateur
Entrée -- La chaîne d'entrée de l'utilisateur
Options -- Un hashref des options fournies par l'utilisateur

Par exemple, la commande suivante :

/helloworld bob --nofoo --bar=2 joe

Produirait les arguments suivants :

sub hw {
    my $class   = shift;    # CPANPLUS::Shell::Default::Plugins::HW
    my $shell   = shift;    # Objet CPANPLUS::Shell::Default
    my $cb      = shift;    # Objet CPANPLUS::Backend
    my $cmd     = shift;    # 'helloworld'
    my $input   = shift;    # 'bob joe'
    my $opts    = shift;    # { foo => 0, bar => 2 }
    ....
}
