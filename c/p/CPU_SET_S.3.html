CPU_SET(3) Manuel des fonctions de bibliothèque CPU_SET(3)

NOM

CPU_SET, CPU_CLR, CPU_ISSET, CPU_ZERO, CPU_COUNT, CPU_AND, CPU_OR, CPU_XOR, CPU_EQUAL, CPU_ALLOC, CPU_ALLOC_SIZE, CPU_FREE, CPU_SET_S, CPU_CLR_S, CPU_ISSET_S, CPU_ZERO_S, CPU_COUNT_S, CPU_AND_S, CPU_OR_S, CPU_XOR_S, CPU_EQUAL_S - macros pour manipuler des ensembles de CPU

BIBLIOTHÈQUE

Bibliothèque C standard (libc,-lc)

SYNOPSIS

#define _GNU_SOURCE             /* Voir feature_test_macros(7) */
#include <sched.h>
void CPU_ZERO(cpu_set_t *set);
void CPU_SET(int cpu, cpu_set_t *set);
void CPU_CLR(int cpu, cpu_set_t *set);
int  CPU_ISSET(int cpu, cpu_set_t *set);
int  CPU_COUNT(cpu_set_t *set);
void CPU_AND(cpu_set_t *destset,
             cpu_set_t *srcset1, cpu_set_t *srcset2);
void CPU_OR(cpu_set_t *destset,
             cpu_set_t *srcset1, cpu_set_t *srcset2);
void CPU_XOR(cpu_set_t *destset,
             cpu_set_t *srcset1, cpu_set_t *srcset2);
int  CPU_EQUAL(cpu_set_t *set1, cpu_set_t *set2);
cpu_set_t *CPU_ALLOC(int num_cpus);
void CPU_FREE(cpu_set_t *set);
size_t CPU_ALLOC_SIZE(int num_cpus);
void CPU_ZERO_S(size_t setsize, cpu_set_t *set);
void CPU_SET_S(int cpu, size_t setsize, cpu_set_t *set);
void CPU_CLR_S(int cpu, size_t setsize, cpu_set_t *set);
int  CPU_ISSET_S(int cpu, size_t setsize, cpu_set_t *set);
int  CPU_COUNT_S(size_t setsize, cpu_set_t *set);
void CPU_AND_S(size_t setsize, cpu_set_t *destset,
             cpu_set_t *srcset1, cpu_set_t *srcset2);
void CPU_OR_S(size_t setsize, cpu_set_t *destset,
             cpu_set_t *srcset1, cpu_set_t *srcset2);
void CPU_XOR_S(size_t setsize, cpu_set_t *destset,
             cpu_set_t *srcset1, cpu_set_t *srcset2);
int  CPU_EQUAL_S(size_t setsize, cpu_set_t *set1, cpu_set_t *set2);

DESCRIPTION

La structure de données cpu_set_t représente un ensemble de CPU. Les ensembles de CPU sont utilisés par sched_setaffinity(2) et des interfaces similaires.

Le type de données cpu_set_t est implémenté comme un masque de bits. Cependant, la structure de données doit être traitée comme opaque : toute manipulation des ensembles de CPU doit se faire via les macros décrites dans cette page.

Les macros suivantes sont fournies pour opérer sur l'ensemble de CPU set:

CPU_ZERO()
Efface set, de sorte qu'il ne contient aucun CPU.
CPU_SET()
Ajoute le CPU cpu à set.
CPU_CLR()
Supprime le CPU cpu de set.
CPU_ISSET()
Teste si le CPU cpu est un membre de set.
CPU_COUNT()
Renvoie le nombre de CPU dans set.

Lorsqu'un argument cpu est spécifié, il ne doit pas produire d'effets de bord, car les macros ci-dessus peuvent évaluer l'argument plus d'une fois.

Le premier CPU du système correspond à une valeur cpu de 0, le CPU suivant correspond à une valeur cpu de 1, et ainsi de suite. Aucune hypothèse ne doit être faite sur la disponibilité de CPU particuliers, ni sur le fait que l'ensemble des CPU soit contigu, car les CPU peuvent être mis hors ligne dynamiquement ou être absents pour d'autres raisons. La constante CPU_SETSIZE (actuellement 1024) spécifie une valeur supérieure d'une unité au numéro de CPU maximum pouvant être stocké dans cpu_set_t.

Les macros suivantes effectuent des opérations logiques sur les ensembles de CPU :

CPU_AND()
Stocke l'intersection des ensembles srcset1 et srcset2 dans destset (qui peut être l'un des ensembles sources).
CPU_OR()
Stocke l'union des ensembles srcset1 et srcset2 dans destset (qui peut être l'un des ensembles sources).
CPU_XOR()
Stocke le XOR des ensembles srcset1 et srcset2 dans destset (qui peut être l'un des ensembles sources). Le XOR signifie l'ensemble des CPU qui sont dans srcset1 ou srcset2, mais pas dans les deux.
CPU_EQUAL()
Teste si deux ensembles de CPU contiennent exactement les mêmes CPU.

Ensembles de CPU de taille dynamique

Comme certaines applications peuvent nécessiter la capacité de dimensionner dynamiquement les ensembles de CPU (par exemple, pour allouer des ensembles plus grands que celui défini par le type de données standard cpu_set_t ), glibc fournit désormais un ensemble de macros pour prendre en charge cela.

Les macros suivantes sont utilisées pour allouer et libérer des ensembles de CPU :

CPU_ALLOC()
Alloue un ensemble de CPU suffisamment grand pour contenir les CPU dans la plage 0 à num_cpus-1.
CPU_ALLOC_SIZE()
Renvoie la taille en octets de l'ensemble de CPU qui serait nécessaire pour contenir les CPU dans la plage 0 à num_cpus-1. Cette macro fournit la valeur qui peut être utilisée pour l'argument setsize des macros CPU_*_S() décrites ci-dessous.
CPU_FREE()
Libère un ensemble de CPU précédemment alloué par CPU_ALLOC().

Les macros dont les noms se terminent par « _S » sont les analogues des macros de même nom sans le suffixe. Ces macros effectuent les mêmes tâches que leurs analogues, mais opèrent sur le ou les ensembles de CPU alloués dynamiquement dont la taille est de setsize octets.

VALEUR RENVOYÉE

CPU_ISSET() et CPU_ISSET_S() renvoient une valeur non nulle si cpu est dans set; sinon, elles renvoient 0.

CPU_COUNT() et CPU_COUNT_S() renvoient le nombre de CPU dans set.

CPU_EQUAL() et CPU_EQUAL_S() renvoient une valeur non nulle si les deux ensembles de CPU sont égaux ; sinon, elles renvoient 0.

CPU_ALLOC() renvoie un pointeur en cas de succès, ou NULL en cas d'échec. (Les erreurs sont les mêmes que pour malloc(3).)

CPU_ALLOC_SIZE() renvoie le nombre d'octets requis pour stocker un ensemble de CPU de la cardinalité spécifiée.

Les autres fonctions ne renvoient pas de valeur.

NORMES

Linux.

HISTORIQUE

Les macros CPU_ZERO(), CPU_SET(), CPU_CLR(), et CPU_ISSET() ont été ajoutées dans glibc 2.3.3.

CPU_COUNT() est apparue pour la première fois dans glibc 2.6.

CPU_AND(), CPU_OR(), CPU_XOR(), CPU_EQUAL(), CPU_ALLOC(), CPU_ALLOC_SIZE(), CPU_FREE(), CPU_ZERO_S(), CPU_SET_S(), CPU_CLR_S(), CPU_ISSET_S(), CPU_AND_S(), CPU_OR_S(), CPU_XOR_S(), et CPU_EQUAL_S() sont apparues pour la première fois dans glibc 2.7.

NOTES

Pour dupliquer un ensemble de CPU, utilisez memcpy(3).

Comme les ensembles de CPU sont des masques de bits alloués par unités de mots longs, le nombre réel de CPU dans un ensemble de CPU alloué dynamiquement sera arrondi au multiple de sizeof(unsigned long)suivant. Une application doit considérer le contenu de ces bits supplémentaires comme indéfini.

Malgré la similitude dans le noms, notez que la constante CPU_SETSIZE indique le nombre de CPU dans le type de données cpu_set_t (c'est-à-dire qu'il s'effectivement du nombre de bits dans le masque de bits), alors que l' setsize argument des CPU_*_S() macros est une taille en octets.

Les types de données pour les arguments et les valeurs de retour montrés dans la SYNOPSIS sont des indications sur ce qui est attendu dans chaque cas. Cependant, puisque ces interfaces sont implémentées en tant que macros, le compilateur ne détectera pas nécessairement toutes les erreurs de type si vous violez les suggestions.

BUGS

Sur les plateformes 32 bits avec glibc 2.8 et antérieur, CPU_ALLOC() alloue deux fois plus d'espace que nécessaire, et CPU_ALLOC_SIZE() renvoie une valeur deux fois plus grande qu'elle ne devrait. Ce bug ne devrait pas affecter la sémantique d'un programme, mais entraîne un gaspillage de mémoire et une opération moins efficace des macros qui opèrent sur des ensembles de CPU alloués dynamiquement. Ces bugs sont corrigés dans glibc 2.9.

EXEMPLES

Le programme suivant démontre l'utilisation de certaines des macros utilisées pour les ensembles de CPU alloués dynamiquement.

#define _GNU_SOURCE
#include <sched.h>
#include <stdio.h>
#include <stdlib.h>
#include <unistd.h>
#include <assert.h>
int
main(int argc, char *argv[])
{
    cpu_set_t *cpusetp;
    size_t size, num_cpus;
    if (argc < 2) {
        fprintf(stderr, "Usage: %s <num-cpus>\n", argv[0]);
        exit(EXIT_FAILURE);
    }
    num_cpus = atoi(argv[1]);
    cpusetp = CPU_ALLOC(num_cpus);
    if (cpusetp == NULL) {
        perror("CPU_ALLOC");
        exit(EXIT_FAILURE);
    }
    size = CPU_ALLOC_SIZE(num_cpus);
    CPU_ZERO_S(size, cpusetp);
    for (size_t cpu = 0; cpu < num_cpus; cpu += 2)
        CPU_SET_S(cpu, size, cpusetp);
    printf("CPU_COUNT() of set:    %d\n", CPU_COUNT_S(size, cpusetp));
    CPU_FREE(cpusetp);
    exit(EXIT_SUCCESS);
}
