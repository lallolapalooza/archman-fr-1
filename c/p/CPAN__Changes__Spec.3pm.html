DESCRIPTIO

N

Elle est destinée à servir de guide pour les auteurs de modules afin de les encourager

à rédiger des journaux des modifications significatifs ainsi qu'à fournir une in
terface programmatique pour lire et écrire de manière fiable les fichiers Changes.

DONNÉES

n

Les versions doivent être formaté

n-Formats" dans CPAN::Meta::Spec.

Dat

e

Une date/heure au format spécifié par http://www.w3.org/TR/NOTE-datetime aussi connu sous le nom de W3CDTF. Remarque : Le marqueur "T" avant la partie heure est

facultatif.

Afin de satisfaire les événements de publication non rendus publics, ou les dates historiquement inconnues, les chaînes suivantes sont également disponibles

STRUCTUR

E

Éléments

requis

Dans sa forme la plus simple, les seuls éléments requis sont une "Version", une "Date" et les modifications notées. Les lignes vides entre la ligne "Version" et la première ligne "Change" sont facultatives. Les lignes vides entre les lignes "Change" le sont également de manière

facultative. 
<Version>(espaces/caractères non-"word")<Date>
(espaces)
<Change>

REMARQUE : Les caractères entre une "Version" et une "Date" doivent commencer par un espace, mais peuvent ensuite contenir toute combinaison d'espaces et de caractères non-"word". Exemple

: 
0.01 -
2013-12-11

Les lignes "Change" n'ont pas de format spécifique. Généralement, les auteurs utiliseront un tiret "-" suivi d'un espace pour commencer une nouvelle modification, et indenteront les lignes suivantes pour les modifications multi-lignes. Exemple

: 
- Modification simple
- Ceci est une modification
  très très très
longue

Bien qu'il n'y ait pas de limite de long

ueur de ligne, les auteurs coupent
généralement chaque ligne à 78 colonnes.

facultatifs

Note de

publication

Tout texte suivant la partie "Date" de la ligne "Version" sera considéré comme la "Note de publication". Exemple

: 
0.01 2013-04-01 Nom
de code : April Fool
- Première version

Préambul

e

Tout texte avant la première ligne "Version" sera considéré comme faisant partie du préambule. La plupart des distributions existantes incluent quelque chose du type

: 
Historique des révisions pour le module perl My::
Module

ns pour la distributio
n perl My-Distribution

Groupe

s

Les entrées du journal des modifications peuvent être regroupées sous des titres. Les lignes de titre commencent par un crochet carré ouvrant ("[") et se terminent par un crochet carré correspondant ("]"). Lors de l'analyse des titres de groupe, les espaces en début et en fin à l'intérieur des crochets doivent être

ignorés. 
(espaces)[Nom du groupe]
(espaces)
<Change>

Puisque les lignes vides n'ont pas de signification particulière, toutes les lignes "Change" tomberont sous le groupe en cours jusqu'à ce qu'un nouveau titre de groupe soit trouvé. Exemple

: 
[ Premier Groupe ]
- Première modificati
on - Deuxième modification ; dans le pre
mier groupe [ Deuxième Groupe ] - Premièr
e modification ; dans le deuxième groupe
