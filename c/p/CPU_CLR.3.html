DESCRIPTIO

N

La structure de données cpu_set_t représente un ensemble de CPU. Les ensembles de CPU sont utilisés par sched_setaffinity(2) et des interfaces

similaires.

Le type de données cpu_set_t est implémenté comme un masque de bits. Cependant, la structure de données doit être traitée comme opaque : toute manipulation des ensembles de CPU doit se faire via les macros décrites dans cette

page.

Les macros suivantes sont fournies pour opérer sur l'ensemble de CPU set

:
CPU_ZERO
()
Efface set, de sorte qu'il ne contienne aucun
CPU.
CPU_SET
()
Ajoute le CPU cpu à set
.
CPU_CLR
()
Retire le CPU cpu de set
.
CPU_ISSET
()
Teste si le CPU cpu est un membre de set
.
CPU_COUNT
()
Retourne le nombre de CPU dans se
t
.

Lorsqu'un argument cpu est spécifié, il ne doit pas produire d'effets de bord, car les macros ci-dessus peuvent évaluer l'argument plus d'une

fois.

Le premier CPU du système correspond à une valeur cpu de 0, le CPU suivant correspond à une cpu de 1, et ainsi de suite. Aucune hypothèse ne doit être faite sur la disponibilité de CPU particuliers, ni sur le fait que l'ensemble des CPU soit contigu, car les CPU peuvent être mis hors ligne dynamiquement ou être autrement absents. La constante CPU_SETSIZE (actuellement 1024) spécifie une valeur supérieure d'une unité au numéro de CPU maximum qui peut être stocké dans cpu_set_t

.

Les macros suivantes effectuent des opérations logiques sur les ensembles de CPU

:
CPU_AND
()
Stocke l'intersection des ensembles srcset1 et srcset2 dans destset (qui peut être l'un des ensembles sources)
.
CPU_OR
()
Stocke l'union des ensembles srcset1 et srcset2 dans destset (qui peut être l'un des ensembles sources)
.
CPU_XOR
()
Stocke le XOR des ensembles srcset1 et srcset2 dans destset (qui peut être l'un des ensembles sources). Le XOR désigne l'ensemble des CPU qui sont dans srcset1 ou srcset2, mais pas dans les
deux.

NOTE

S

Pour dupliquer un ensemble de CPU, utilisez memcpy(

3).

Puisque les ensembles de CPU sont des masques de bits alloués par unités de mots longs, le nombre réel de CPU dans un ensemble de CPU alloué dynamiquement sera arrondi au multiple de sizeof(unsigned long) suivant. Une application doit considérer le contenu de ces bits supplémentaires comme

indéfini.

Malgré la similitude des noms, notez que la constante CPU_SETSIZE indique le nombre de CPU dans le type de données cpu_set_t (c'est donc un compte effectif des bits dans le masque de bits), alors que le argument setsize des macros CPU_

*_S()

est une

taille en
octets.

Les types de données pour les arguments et les valeurs de retour montrés dans la SYNOPSIS sont des indications sur ce qui est attendu dans chaque cas. Cependant, puisque ces interfaces sont implémentées en tant que macros, le compilateur ne détectera pas nécessairement

toutes les erreurs de type si vous violez ces recommandations.

BUGS Sur les plateformes 32 bits avec glibc 2.8 et antérieur, CPU_ALLOC() alloue deux fois

plus d'espace qu
e nécessaire, et

CPU_ALLOC_SIZE() renvoie une valeur deux fois plus grande qu'elle ne devrait l'être. Ce bug ne devrait pas affecter la sémantique d'un programme, mais entraîne un gaspillage de mémoire et un fonctionnement moins efficace des macros qui opèrent sur des ensembles de CPU alloués dynamiquement.

Ces bugs sont corrigés dans glibc 2.9.

EXEMPLE

S 
Le programme suivant illustre l'utilisation
de certaines des macros utilisées pour
les ensembles de CPU alloués dynamiquement.

#define _GNU_SOURCE #include <sched.h> #include <stdio.h> #include <stdlib.h> #include <unistd.h> #include <assert.h> int main(int argc, char *argv[]) { cpu_set_t *cpusetp; size_t size, num_cpus; if (argc < 2) { fprintf(stderr, "Usage: %s <num-cpus>\n", argv[0]); exit(EXIT_FAILURE); } num_cpus = atoi(argv[1]); cpusetp = CPU_ALLOC(num_cpus); if (cpusetp == NULL) { perror("CPU_ALLOC"); exit(EXIT_FAILURE); } size = CPU_ALLOC_SIZE(num_cpus); CPU_ZERO_S(size, cpusetp); for (size_t cpu = 0; cpu < num_cpus; cpu += 2) CPU_SET_S(cpu, size, cpusetp); printf("CPU_COUNT() of set: %d\n", CPU_COUNT_S(size,

cpusetp)); CPU_FREE(cpusetp); exit(EXIT_SUCCESS); }
