@mods = $cb->search( type => TYPE, allow => AREF, [data => AREF, verbose => BOOL]

)

"search" vous permet de rechercher des objets module ou auteur, en fonction de leurs données. Le "type" que vous pouvez spécifier est l'un des accesseurs spécifiés dans "CPANPLUS::Module::Author" ou "CPANPLUS::Module". "search" déterminera selon le "type" que vous avez spécifié s'il faut rechercher par objet auteur ou objet

module.

Vous devez spécifier une référence de tableau d'expressions régulières ou de chaînes de caractères à faire correspondre. Les règles utilisées pour cette référence de tableau sont les mêmes que dans "Params::Check", consultez donc cette page man pour plus de

détails.

La recherche est une recherche "ou", ce qui signifie que si "un" des critères correspond, la recherche est considérée comme

réussie.

Vous pouvez spécifier le résultat d'une recherche précédente comme "data" pour limiter la nouvelle recherche à ces objets module ou auteur, plutôt qu'à l'ensemble de l'arbre des modules ou des auteurs. C'est ainsi que vous effectuez des recherches "et"

.

Renvoie une liste d'objets module ou auteur en cas de succès et faux en cas

d'échec.

Voir CPANPLUS::Module pour les opérations que vous pouvez effect

uer sur un objet module. Voir CPANPLUS::Module::Author pour l
es opérations que vous pouvez effectuer sur un objet auteur.

save_state

Commande explicite pour sauvegarder l'état de la mémoire sur disque. Cela peut être utilisé pour sauvegarder des informations sur le disque concernant l'endroit où un module a été extrait, le résultat de "make test", etc. Cela sera ensuite rechargé en mémoire lorsqu'une nouvelle session

La capacité de sauvegarder l'état sur disque dépend du moteur source utilisé (Voir "CPANPLUS::Config" pour l'option permettant de choisir votre moteur source). Le moteur de stockage par défaut prend en charge cette

option.

La plupart des utilisateurs n'auront pas besoin de cette commande, mais elle peut être pratique pour les systèmes automatisés comme la configuration des testeurs de fumée (smoke testers) de

CPAN.

PERSONNALISÉES

En plus des sources fournies par les miroirs "CPAN" généraux, il est possible d'ajouter votre propre liste de sources à votre index "CPAN

PLUS".

La méthodologie derrière cela fonctionne beaucoup comme "apt-sources de

Debian".

Les méthodes ci-dessous vous montrent comment utiliser cette fonctionnalité. Notez également que la plupart de ces méthodes sont disponibles via la commande de plugin du shell par défaut "/cs", les rendant disponibles comme raccourcis via le shell et via la ligne de

commande.

Notez que lorsque ajout d'un "URI", la modification de l'arbre en mémoire n'est pas enregistrée tant que vous ne reconstruisez pas ou ne sauvegardez pas à nouveau l'arbre sur disque. Vous pouvez le faire en utilisant la méthode "$cb->r

$bool = $cb->update_custom_source( [remote => URI] )

;

Met à jour les index de toutes vos sources personnalisées. Cela se fait en récupérant un fichier nommé "packages.txt" à la racine de la "URI" des sources personnalisées. Si vous fournissez l'argument "remote", seul l'index de cette "URI" spécifique sera mis à

jour.

Voici un exemple de la manière dont les sources personnalisées se résolvent en fichiers d'index

: 
file:///path/to/sources       =>  file:///path/to/sources/packages.txt
http://example.com/sources    =>  http://example.com/sources/packages.txt
ftp://example.com/sources     =>  ftp://example.com/sources/packages.
txt

Le fichier "packages.txt" contient simplement une liste de paquets pouvant être trouvés sous la racine de la "URI". Ce fichier peut être généré automatiquement pour vous lorsque la source distante est une "URI de type file://". Pour "http://", "ftp://" et similaires, l'administrateur de ce dépôt doit exécuter la méthode "$cb->write_custom_source_index" sur le dépôt pour permettre aux utilisateurs distants de

l'indexer.

Pour plus de détails, voir la méthode "$cb->write_custom_source_i

ndex" ci-dessous.

Tous les paquets ajoutés via ce mécanisme seront attribués à l'auteur avec "CPANID" "LOCAL". Vous pouvez utiliser cet identifian

t pour rechercher tou
s les paquets ajoutés.

$file = $cb->write_custom_source_index( path => /path/to/package/root, [to => /path/to/index/file, verbose => BOOL] )

;

Écrit l'index pour une racine de dépôt personnalisée. La plupart des utilisateurs n'auront pas à s'en soucier, mais les administrateurs d'un dépôt devront s'assurer que leurs index sont à

jour.

L'index sera écrit dans un fichier nommé "packages.txt" dans la racine de votre dépôt, que vous pouvez spécifier avec l'argument "path". Vous pouvez remplacer cet emplacement en spécifiant l'argument "to", mais dans le fonctionnement normal, cela ne devrait pas être

nécessaire.

Une fois le fichier d'index écrit, les utilisateurs peuvent alors ajouter la "URI" pointant vers le dépôt à leur liste personnalisée de sources et commencer à l'utiliser immédiatement. Voir la méthode "$cb->add_custom_sourc
