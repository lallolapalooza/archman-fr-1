Variables spécifiques au générateur CPack External

CPACK_EXTERNAL_REQUESTED_VERSIONS
Cette variable est utilisée pour demander une version spécifique du générateur CPack External. C'est une liste de valeurs major.minor, séparées par des points-virgules.

Si cette variable est définie sur une valeur non vide, le générateur CPack External itérera sur chaque élément de la liste pour rechercher une version qu'il sait générer. Les versions demandées doivent être listées par ordre de préférence décroissante par le logiciel client, car la première version correspondante de la liste sera générée.

Le générateur sait générer la version s'il a un générateur versionné dont la version majeure correspond exactement à la version majeure demandée, et dont la version mineure est supérieure ou égale à la version mineure demandée. Par exemple, si CPACK_EXTERNAL_REQUESTED_VERSIONS contient 1.0, et que le générateur CPack External sait générer 1.1, il générera 1.1. Si le générateur ne sait pas générer une version de la liste, il la saute et passe à la suivante. S'il ne sait générer aucune des versions demandées, une erreur est levée.

Si cette variable n'est pas définie, ou est vide, le générateur CPack External générera la version majeure et mineure la plus élevée qu'il sait générer.

Si une version invalide est rencontrée dans CPACK_EXTERNAL_REQUESTED_VERSIONS (une qui ne correspond pas à major.minor, où major et minor sont des entiers), elle est ignorée.

CPACK_EXTERNAL_ENABLE_STAGING
Cette variable peut être définie sur vrai pour activer l'installation optionnelle dans une zone de staging temporaire qui peut ensuite être récupérée et packagée par un outil de packaging externe. Le répertoire de haut niveau utilisé par CPack pour la tâche de packaging en cours est contenu dans CPACK_TOPLEVEL_DIRECTORY. Il est automatiquement nettoyé à chaque exécution avant que le packaging ne soit initié et peut être utilisé pour des fichiers temporaires personnalisés requis par l'outil de packaging externe. Il contient également la zone de staging CPACK_TEMPORARY_DIRECTORY dans laquelle CPack effectue l'installation lorsque le staging est activé.
CPACK_EXTERNAL_PACKAGE_SCRIPT
Cette variable peut spécifier optionnellement le chemin complet vers un fichier script CMake à exécuter dans le cadre de l'invocation CPack. Il est appelé après le staging (optionnel) et peut exécuter un outil de packaging externe. Le script a accès aux variables définies par le fichier de configuration CPack.
CPACK_EXTERNAL_BUILT_PACKAGES
Ajouté en version 3.19.

Le script CPACK_EXTERNAL_PACKAGE_SCRIPT peut définir cette variable liste avec les chemins complets des fichiers package générés. CPack copiera ces fichiers depuis le répertoire de staging vers le répertoire de construction de haut niveau et produira éventuellement des fichiers de somme de contrôle si CPACK_PACKAGE_CHECKSUM <#variable:CPACK_PACKAGE_CHECKSUM> est défini.

Variables spécifiques au générateur CPack FreeBSD (pkg)

Le générateur CPack FreeBSD peut être utilisé pour créer des packages pkg(8) -- ceux-ci peuvent être utilisés sur FreeBSD, DragonflyBSD, NetBSD, OpenBSD, mais aussi sur Linux ou OSX, en fonction des outils de gestion de packages installés -- en utilisant CPack <#module:CPack>.

Le générateur CPack FreeBSD est un générateur CPack <#module:CPack> et utilise les variables CPACK_XXX utilisées par CPack <#module:CPack>. Il essaie de réutiliser les informations de packaging qui peuvent déjà être spécifiées pour les packages Debian pour le Générateur CPack DEB <#cpack_gen:CPack DEB Generator>. Il essaie également de réutiliser les informations de packaging RPM lorsque Debian ne les spécifie pas.

Le générateur CPack FreeBSD devrait fonctionner sur n'importe quel hôte avec libpkg installé. Les packages qu'il produit sont spécifiques à l'architecture et à l'ABI de l'hôte.

Le générateur CPack FreeBSD définit les métadonnées du package via les variables CPACK_FREEBSD_XXX. Le générateur CPack FreeBSD, contrairement au générateur CPack Deb, ne prend pas spécialement en charge les packages composants ; un seul package est créé à partir de tous les artefacts logiciels créés via CMake.

Toutes les variables peuvent être définies spécifiquement pour le packaging FreeBSD dans le fichier CPackConfig ou dans CMakeLists.txt, mais la plupart d'entre elles ont des valeurs par défaut qui utilisent des paramètres généraux (par exemple, CMAKE_PROJECT_NAME <#variable:CMAKE_PROJECT_NAME>) ou des variables spécifiques à Debian lorsque celles-ci ont du sens (par exemple, la page d'accueil d'un projet amont est généralement inchangée par la saveur du packaging). Lorsqu'il n'y a pas d'informations Debian de repli, mais que le packaging RPM les possède, on se replie sur les informations RPM (par exemple, la licence du package).

Installateur en

Par défaut, ce générateur produit un installateur hors ligne. Cela signifie que tous les fichiers empaquetés sont entièrement contenus dans l'exécutable de

l'installateur.

En revanche, un installateur en ligne téléchargera certains ou tous les composants depuis un serveur

distant.

L'option DOWNLOADED dans la commande cpack_add_component() <#command:cpack_add_component> spécifie qu'un composant doit être téléchargé. Alternativement, l'option ALL dans la commande cpack_configure_downloads() <#command:cpack_configure_downloads> spécifie que tous les composants doivent être

téléchargés.

La commande cpack_ifw_add_repository() <#command:cpack_ifw_add_repository> et la variable CPACK_IFW_DOWNLOAD_ALL permettent une configuration plus

spécifique.

Lorsqu'il y a des composants en ligne, CPack les écrira dans des fichiers d'archive. La page d'aide du module CPackComponent <#module:CPackComponent>, en particulier la section sur la fonction cpack_configure_downloads() <#command:cpack_configure_downloads>, explique

comment rendre ces fichiers access
ibles depuis une URL de téléchargement.

CPACK_PRODUCTBUILD_DOMAINS_USER
Ajouté dans la version 3.23.

Peut être utilisé pour remplacer l'attribut enable_currentUserHome dans l'élément domains du XML de distribution. Lorsqu'il est défini sur vrai, le produit peut être installé dans le répertoire personnel de l'utilisateur actuel. Notez que lors de l'installation dans le répertoire personnel de l'utilisateur, les exigences supplémentaires suivantes s'appliqueront :

  • L'installeur ne peut pas écrire en dehors du répertoire personnel de l'utilisateur.
  • L'installation sera effectuée en tant qu'utilisateur actuel plutôt qu'en tant que root. Cela peut avoir des implications pour CPACK_PREFLIGHT_<COMP>_SCRIPT et CPACK_POSTFLIGHT_<COMP>_SCRIPT.
  • Les privilèges administratifs ne seront pas nécessaires pour effectuer l'installation.

CPACK_PRODUCTBUILD_DOMAINS doit être défini sur vrai pour que cette variable ait un effet.

CPACK_PRODUCTBUILD_DOMAINS_ROOT
Ajouté dans la version 3.23.

Peut être utilisé pour remplacer l'attribut enable_localSystem dans l'élément domains du XML de distribution. Lorsqu'il est défini sur vrai, le produit peut être installé dans le répertoire racine. Cela devrait normalement être défini sur vrai, sauf si le produit ne doit être installé que dans le répertoire personnel de l'utilisateur.

CPACK_PRODUCTBUILD_DOMAINS doit être défini sur vrai pour que cette variable ait un effet.
