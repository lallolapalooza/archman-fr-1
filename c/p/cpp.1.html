NOM

cpp - Le préprocesseur C

SYNTAXE

cpp [-Dmacro[=defn]...] [-Umacro]
[-Idir...] [-iquotedir...]
[-M|-MM] [-MG] [-MF filename]
[-MP] [-MQ cible...]
[-MT cible...]
fichier_entree [[-o] fichier_sortie]

Seules les options les plus utiles sont présentées ci-dessus ; voir ci-dessous pour une liste plus complète d'options spécifiques au préprocesseur. De plus, cpp accepte la plupart des options du pilote gcc, qui ne sont pas listées ici. Se référer à la documentation de GCC pour plus de détails.

DESCRIPTION

Le préprocesseur C, souvent appelé cpp, est un processeur de macros qui est utilisé automatiquement par le compilateur C pour transformer votre programme avant la compilation. Il est appelé processeur de macros car il vous permet de définir des macros, qui sont de brèves abréviations pour des constructions plus longues.

Le préprocesseur C est destiné à être utilisé uniquement avec le code source C, C++ et Objective-C. Par le passé, il a été utilisé abusivement comme processeur de texte général. Il échouera sur une entrée qui ne respecte pas les règles lexicales de C. Par exemple, les apostrophes seront interprétées comme le début de constantes de caractères, et provoqueront des erreurs. De plus, vous ne pouvez pas compter sur lui pour préserver les caractéristiques de l'entrée qui ne sont pas significatives pour les langages de la famille C. Si un Makefile est prétraité, toutes les tabulations seront supprimées et le Makefile ne fonctionnera pas.

Ceci dit, vous pouvez souvent vous en sortir en utilisant cpp sur des choses qui ne sont pas du C. D'autres langages de programmation de type Algol sont souvent sûrs (Ada, etc.) L'assembleur aussi, avec prudence. Le mode -traditional-cpp préserve plus d'espaces blancs et est par ailleurs plus permissif. Beaucoup de problèmes peuvent être évités en écrivant des commentaires de style C ou C++ au lieu de commentaires natifs, et en gardant les macros simples.

Dans la mesure du possible, vous devriez utiliser un préprocesseur adapté au langage dans lequel vous écrivez. Les versions modernes de l'assembleur GNU ont des facilités de macros. La plupart des langages de programmation de haut niveau ont leur propre mécanisme de compilation conditionnelle et d'inclusion. Si tout le reste échoue, essayez un vrai processeur de texte général, tel que GNU M4.

Les préprocesseurs C varient dans certains détails. Ce manuel discute du préprocesseur GNU C, qui fournit un petit sur-ensemble des fonctionnalités du C standard ISO. Dans son mode par défaut, le préprocesseur GNU C ne fait pas certaines choses requises par la norme. Ce sont des fonctionnalités qui sont rarement, voire jamais, utilisées et qui peuvent modifier de manière surprenante la signification d'un programme qui ne les attend pas. Pour obtenir un C ISO standard strict, vous devriez utiliser les options -std=c90, -std=c99, -std=c11 ou -std=c17, en fonction de la version de la norme que vous souhaitez. Pour obtenir tous les diagnostics obligatoires, vous devez également utiliser -pedantic.

Ce manuel décrit le comportement du préprocesseur ISO. Pour minimiser les différences gratuites, là où le comportement du préprocesseur ISO n'entre pas en conflit avec la sémantique traditionnelle, le préprocesseur traditionnel devrait se comporter de la même manière. Les diverses différences qui existent sont détaillées dans la section Mode Traditionnel.

Pour plus de clarté, sauf indication contraire, les références à CPP dans ce manuel font référence à GNU CPP.

OPTIONS

La commande cpp attend deux noms de fichiers en arguments, fichier_entree et fichier_sortie. Le préprocesseur lit fichier_entree ainsi que tous les autres fichiers qu'il spécifie avec #include. Toutes les sorties générées par les fichiers d'entrée combinés sont écrites dans fichier_sortie.

Soit fichier_entree soit fichier_sortie peut être -, ce qui, en tant que fichier_entree, signifie lire depuis l'entrée standard et, en tant que fichier_sortie, signifie écrire vers la sortie standard. Si un fichier est omis, cela signifie la même chose que si - avait été spécifié pour ce fichier. Vous pouvez également utiliser l'option -o fichier_sortie pour spécifier le fichier de sortie.

Sauf indication contraire, ou si l'option se termine par =, toutes les options qui prennent un argument peuvent avoir cet argument apparaissant soit immédiatement après l'option, soit avec un espace entre l'option et l'argument : -Ifoo et -I foo ont le même effet.

Beaucoup d'options ont des noms de plusieurs lettres ; par conséquent, plusieurs options à une seule lettre ne peuvent pas être groupées : -dM est très différent de -d -M.

-D nom
Prédéfinit nom comme une macro, avec la définition 1.
-D nom=définition
Le contenu de définition est tokenisé et traité comme s'il était apparu pendant la phase trois de traduction dans une directive #define. En particulier, la définition est tronquée par les caractères de nouvelle ligne intégrés.

Si vous invoquez le préprocesseur depuis un shell ou un programme de type shell, vous devrez peut-être utiliser la syntaxe de citation du shell pour protéger les caractères tels que les espaces qui ont une signification dans la syntaxe du shell.

Si vous souhaitez définir une macro de type fonction en ligne de commande, écrivez sa liste d'arguments avec des parenthèses autour avant le signe égal (le cas échéant). Les parenthèses sont significatives pour la plupart des shells, vous devriez donc citer l'option. Avec sh et csh, -D'nom(args...)=définition' fonctionne.

Les options -D et -U sont traitées dans l'ordre où elles apparaissent sur la ligne de commande. Toutes les options -imacros fichier et -include fichier sont traitées après toutes les options -D et -U.

-U nom
Annule toute définition précédente de nom, qu'elle soit intégrée ou fournie avec une option -D.
-include fichier
Traite fichier comme si "#include "fichier"" apparaissait comme première ligne du fichier source principal. Cependant, le premier répertoire recherché pour fichier est le répertoire de travail du préprocesseur au lieu du répertoire contenant le fichier source principal. S'il n'est pas trouvé là, il est recherché dans le reste de la chaîne de recherche "#include "..."" comme d'habitude.

Si plusieurs options -include sont données, les fichiers sont inclus dans l'ordre où ils apparaissent sur la ligne de commande.

-imacros fichier
Exactement comme -include, sauf que toute sortie produite par l'analyse de fichier est jetée. Les macros qu'il définit restent définies. Cela vous permet d'acquérir toutes les macros d'un en-tête sans traiter également ses déclarations.

Tous les fichiers spécifiés par -imacros sont traités avant tous les fichiers spécifiés par -include.

-undef
Ne prédéfinit aucune macro spécifique au système ou spécifique à GCC. Les macros prédéfinies standard restent définies.
-pthread
Définit des macros supplémentaires requises pour utiliser la bibliothèque de threads POSIX. Vous devriez utiliser cette option de manière cohérente pour la compilation et l'édition des liens. Cette option est prise en charge sur les cibles GNU/Linux, la plupart des autres dérivés Unix, ainsi que sur les cibles Cygwin et MinGW x86.
-M
Au lieu de produire le résultat du prétraitement, produit une règle adaptée à make décrivant les dépendances du fichier source principal. Le préprocesseur produit une règle make contenant le nom du fichier objet pour ce fichier source, un deux-points, et les noms de tous les fichiers inclus, y compris ceux provenant des options de ligne de commande -include ou -imacros.

Sauf indication explicite (avec -MT ou -MQ), le nom du fichier objet se compose du nom du fichier source avec tout suffixe remplacé par le suffixe du fichier objet et avec toute partie de répertoire initiale supprimée. S'il y a de nombreux fichiers inclus, la règle est divisée en plusieurs lignes utilisant \-nouvelle ligne. La règle n'a pas de commandes.

Cette option ne supprime pas la sortie de débogage du préprocesseur, telle que -dM. Pour éviter de mélanger cette sortie de débogage avec les règles de dépendance, vous devez spécifier explicitement le fichier de sortie de dépendance avec -MF, ou utiliser une variable d'environnement telle que DEPENDENCIES_OUTPUT. La sortie de débogage est toujours envoyée au flux de sortie normal sous forme n

ormal.

Passer -M au pilote implique -E, et supprime les avertissements avec un -wimplicite.

-MM
Comme -M mais ne mentionne pas les fichiers d'en-tête trouvés dans les répertoires d'en-tête système, ni les fichiers d'en-tête qui sont inclus, directement ou indirectement, à partir d'un tel en-tête.

Cela implique que le choix des crochets angulaires ou des guillemets doubles dans une directive #include ne détermine pas en soi si cet en-tête apparaît dans la sortie de dépendances -MM .

-MF fichier
Lorsqu'il est utilisé avec -M ou -MM, spécifie un fichier dans lequel écrire les dépendances. Si aucune option -MF n'est donnée, le préprocesseur envoie les règles au même endroit où il enverrait la sortie prétraitée.

Lorsqu'il est utilisé avec les options du pilote -MD ou -MMD, -MF remplace le fichier de sortie de dépendances par défaut.

Si fichier est -, alors les dépendances sont écrites vers stdout.

-MG
En conjonction avec une option telle que -M demandant la génération de dépendances, -MG suppose que les fichiers d'en-tête manquants sont des fichiers générés et les ajoute à la liste des dépendances sans provoquer d'erreur. Le nom de fichier de la dépendance est pris directement à partir de la directive "#include" sans préfixer aucun chemin. -MG supprime également la sortie prétraitée, car un fichier d'en-tête manquant la rend inutile.

Cette fonctionnalité est utilisée dans la mise à jour automatique des Makefiles.

-Mno-modules
Désactive la génération de dépendances pour les interfaces de modules compilés.
-MP
Cette option indique à CPP d'ajouter une cible fictive pour chaque dépendance autre que le fichier principal, faisant en sorte que chacune ne dépende de rien. Ces règles factices contournent les erreurs make que vous obtiendrez si vous supprimez des fichiers d'en-tête sans mettre à jour le Makefile en conséquence.

Voici une sortie typique :

test.o: test.c test.h

test.h:
-MT cible
Change la cible de la règle émise par la génération de dépendances. Par défaut, CPP prend le nom du fichier d'entrée principal, supprime tous les composants de répertoire et tout suffixe de fichier tel que .c, et ajoute le suffixe d'objet habituel de la plateforme. Le résultat est la cible.

Une option -MT définit la cible comme étant exactement la chaîne que vous spécifiez. Si vous voulez plusieurs cibles, vous pouvez les spécifier comme un seul argument à -MT, ou utiliser plusieurs options -MT .

Par exemple, -MT '$(objpfx)foo.o' pourrait donner

$(objpfx)foo.o: foo.c
-MQ cible
Identique à -MT, mais met entre guillemets tous les caractères qui sont spéciaux pour Make. -MQ '$(objpfx)foo.o' donne 
$$(objpfx)foo.o: foo.c

La cible par défaut est automatiquement mise entre guillemets, comme si elle était donnée avec -MQ.

-MD
-MD est équivalent à -M -MF fichier, sauf que -E n'est pas impliqué. Le pilote détermine fichier en fonction de la présence d'une option -o . Si c'est le cas, le pilote utilise son argument mais avec un suffixe de .d, sinon il prend le nom du fichier d'entrée, supprime tous les composants de répertoire et le suffixe, et applique le suffixe .d .

Si -MD est utilisé en conjonction avec -E, toute option -o est comprise comme spécifiant le fichier de sortie des dépendances, mais si elle est utilisée sans -E, chaque -o est compris comme spécifiant un fichier objet cible.

Puisque -E n'est pas impliqué, -MD peut être utilisé pour générer un fichier de sortie de dépendances comme effet secondaire du processus de compilation.

-MMD
Comme -MD sauf qu'il ne mentionne que les fichiers d'en-tête utilisateur, et non les fichiers d'en-tête système.
-fpreprocessed
Indique au préprocesseur que le fichier d'entrée a déjà été prétraité. Cela supprime des choses comme l'expansion de macro, la conversion des trigraphes, le raccordement des nouvelles lignes échappées, et le traitement de la plupart des directives. Le préprocesseur reconnaît et supprime toujours les commentaires, afin que vous puissiez passer un fichier prétraité avec -C au compilateur sans problème. Dans ce mode, le préprocesseur intégré est peu plus qu'un tokeniseur pour les frontaux.

-fpreprocessed est implicite si le fichier d'entrée a l'une des extensions .i, .ii ou .mi. Ce sont les extensions que GCC utilise pour les fichiers prétraités créés par -save-temps.

-fdirectives-only
Lors du prétraitement, traite les directives, mais n'expande pas les macros.

Le comportement de l'option dépend des options -E et -fpreprocessed .

Avec -E, le prétraitement est limité au traitement des directives telles que "#define", "#ifdef", et "#error". Les autres opérations du préprocesseur, telles que l'expansion de macro et la conversion des trigraphes, ne sont pas effectuées. De plus, l'option -dD est activée implicitement.

Avec -fpreprocessed, la prédéfinition des macros de la ligne de commande et de la plupart des macros intégrées est désactivée. Les macros telles que "__LINE__", qui dépendent du contexte, sont traitées normalement. Cela permet la compilation de fichiers prétraités précédemment avec "-E -fdirectives-only".

Avec à la fois -E et -fpreprocessed, les règles pour -fpreprocessed priment. Cela permet le prétraitement complet de fichiers prétraités précédemment avec "-E -fdirectives-only".

-fdollars-in-identifiers
Accepte $ dans les identifiants.
-fextended-identifiers
Accepte les noms de caractères universels et les caractères étendus dans les identifiants. Cette option est activée par défaut pour C99 (et les versions ultérieures de la norme C) et C++.
-fno-canonical-system-headers
Lors du prétraitement, ne raccourcit pas les chemins des en-têtes système par la canonicalisation.
-fmax-include-depth=profondeur
Définit la profondeur maximale des #include imbriqués. La valeur par défaut est 200.
-fsearch-include-path[=type]
Recherche les fichiers d'entrée sur le chemin #include, et pas seulement dans le répertoire courant. C'est particulièrement utile avec les modules C++20, pour lesquels les unités d'en-tête et les unités d'interface de module doivent être compilées directement : 
g++ -c -std=c++20 -fmodules -fsearch-include-path bits/stdc++.h bits/std.cc

type vaut par défaut user, ce qui recherche sur le chemin de recherche #include "..." ; vous pouvez aussi spécifier explicitement system pour le chemin de recherche "#include <...>" .

-ftabstop=largeur
Définit la distance entre les tabulations. Cela aide le préprocesseur à rapporter des numéros de colonne corrects dans les avertissements ou les erreurs, même si des tabulations apparaissent sur la ligne. Si la valeur est inférieure à 1 ou supérieure à 100, l'option est ignorée. La valeur par défaut est 8.
-ftrack-macro-expansion[=niveau]
Suit les emplacements des jetons à travers les expansions de macro. Cela permet au compilateur d'émettre des diagnostics sur la pile d'expansion de macro courante lorsqu'une erreur de compilation se produit dans une expansion de macro. L'utilisation de cette option fait consommer plus de mémoire au préprocesseur et au compilateur. Le paramètre niveau peut être utilisé pour choisir le niveau de précision du suivi de l'emplacement des jetons, diminuant ainsi la consommation de mémoire si nécessaire. La valeur 0 de niveau désactive cette option. La valeur 1 suit les emplacements des jetons dans un mode dégradé pour minimiser la surcharge mémoire. Dans ce mode, tous les jetons résultant de l'expansion d'un argument d'une macro de type fonction ont le même emplacement. La valeur 2 suit les emplacements des jetons complètement. Cette valeur est la plus gourmande en mémoire. Lorsque cette option est donnée sans argument, la valeur par défaut du paramètre est 2.

Notez que "-ftrack-macro-expansion=2" est activé par défaut.

-fmacro-prefix-map=ancien=nouveau
Lors du prétraitement de fichiers résidant dans le répertoire ancien, étend les macros "__FILE__" et "__BASE_FILE__" comme si les fichiers résidaient dans le répertoire nouveau à la place. Cela peut être utilisé pour changer un chemin absolu en un chemin relatif en utilisant . pour nouveau , ce qui peut donner des constructions plus reproductibles et indépendantes de l'emplacement. Cette option affecte aussi "__builtin_FILE()" lors de la compilation. Voir aussi -ffile-prefix-map et -fcanon-prefix-map.
-fexec-charset=jeu de caractères
Définit le jeu de caractères d'exécution, utilisé pour les constantes de chaîne et de caractère. La valeur par défaut est UTF-8. jeu de caractères peut être n'importe quel encodage pris en charge par la routine de bibliothèque "iconv" du système.
-fwide-exec-charset=jeu de caractères
Définit le jeu de caractères d'exécution large, utilisé pour les constantes de chaîne et de caractère large. La valeur par défaut est UTF-32BE, UTF-32LE, UTF-16BE ou UTF-16LE, selon celui qui correspond à la largeur de "wchar_t" et à l'ordre des octets big-endian ou little-endian utilisé pour la génération de code. Comme avec -fexec-charset, jeu de caractères peut être n'importe quel encodage pris en charge par la routine de bibliothèque "iconv" du système ; cependant, vous aurez des problèmes avec les encodages qui ne tiennent pas exactement dans "wchar_t".
-finput-charset=jeu de caractères
Définit le jeu de caractères d'entrée, utilisé pour la traduction du jeu de caractères du fichier d'entrée vers le jeu de caractères source utilisé par GCC. Si la locale ne spécifie pas, ou GCC ne peut pas obtenir ces informations de la locale, la valeur par défaut est UTF-8. Ceci peut être outrepassé par la locale ou par cette option de ligne de commande. Actuellement, l'option de ligne de commande a la priorité en cas de conflit. charset peut être n'importe quelle codification supportée par la routine de la bibliothèque "iconv" du système.
-fworking-directory
Active la génération de marqueurs de ligne dans la sortie du préprocesseur qui indiquent au compilateur le répertoire de travail courant au moment du préprocesseur. Lorsque cette option est activée, le préprocesseur émet, après le marqueur de ligne initial, un second marqueur de ligne avec le répertoire de travail courant suivi de deux barres obliques. GCC utilise ce répertoire, lorsqu'il est présent dans l'entrée prétraitée, comme le répertoire émis comme répertoire de travail courant dans certains formats d'informations de débogage. Cette option est implicitement activée si les informations de débogage sont activées, mais cela peut être inhibé par la forme niée -fno-working-directory. Si le drapeau -P est présent sur la ligne de commande, cette option n'a aucun effet, car aucune directive "#line" n'est émise du tout.
-A prédicat=réponse
Faire une assertion avec le prédicat prédicat et la réponse réponse. Cette forme est préférable à l'ancienne forme -A prédicat(réponse), qui est toujours supportée, car elle n'utilise pas de caractères spéciaux du shell.
-A -prédicat=réponse
Annuler une assertion avec le prédicat prédicat et la réponse réponse.
-C
Ne pas supprimer les commentaires. Tous les commentaires sont transmis au fichier de sortie, à l'exception des commentaires dans les directives traitées, qui sont supprimés avec la directive.

Vous devez être préparé aux effets secondaires lors de l'utilisation de -C ; cela fait que le préprocesseur traite les commentaires comme des tokens à part entière. Par exemple, les commentaires apparaissant au début de ce qui serait une ligne de directive ont pour effet de transformer cette ligne en une ligne source ordinaire, car le premier token de la ligne n'est plus un #.

-CC
Ne pas supprimer les commentaires, y compris lors de l'expansion des macros. Ceci est similaire à -C, sauf que les commentaires contenus dans les macros sont également transmis au fichier de sortie où la macro est développée.

En plus des effets secondaires de l'option -C, l'option -CC fait que tous les commentaires de style C++ à l'intérieur d'une macro sont convertis en commentaires de style C. Ceci afin d'éviter que l'utilisation ultérieure de cette macro ne commente par inadvertance le reste de la ligne source.

L'option -CC est généralement utilisée pour prendre en charge les commentaires lint.

-P
Inhiber la génération de marqueurs de ligne dans la sortie du préprocesseur. Ceci peut être utile lors de l'exécution du préprocesseur sur quelque chose qui n'est pas du code C, et qui sera envoyé à un programme qui pourrait être confus par les marqueurs de ligne.
-traditional
-traditional-cpp
Essayer d'imiter le comportement des préprocesseurs C pré-standard, par opposition aux préprocesseurs C ISO.

Notez que GCC n'essaie pas par ailleurs d'émuler un compilateur C pré-standard, et ces options ne sont supportées qu'avec le commutateur -E, ou lors de l'invocation explicite de CPP.

-trigraphs
Prendre en charge les trigraphes C ISO. Ce sont des séquences de trois caractères, toutes commençant par ??, qui sont définies par C ISO pour représenter des caractères uniques. Par exemple, ??/ représente \, donc '??/n' est une constante caractère pour un saut de ligne.

Par défaut, GCC ignore les trigraphes, mais dans les modes conformes aux normes, il les convertit. Voir les options -std et -ansi.

-remap
Activer un code spécial pour contourner les systèmes de fichiers qui ne permettent que des noms de fichiers très courts, comme MS-DOS.
-H
Imprimer le nom de chaque fichier d'en-tête utilisé, en plus des autres activités normales. Chaque nom est indenté pour montrer la profondeur dans la pile #include. Les fichiers d'en-tête précompilés sont également imprimés, même s'ils s'avèrent invalides ; un fichier d'en-tête précompilé invalide est imprimé avec ...x et un fichier valide avec ...!.
-dlettres
Indique de faire des vidages de débogage pendant la compilation comme spécifié par lettres. Les drapeaux documentés ici sont ceux pertinents pour le préprocesseur. D'autres lettres sont interprétées par le compilateur principal, ou réservées pour les futures versions de GCC, et sont donc silencieusement ignorées. Si vous spécifiez des lettres dont le comportement est conflictuel, le résultat est indéfini.
-dM
Au lieu de la sortie normale, générer une liste de directives #define pour toutes les macros définies pendant l'exécution du préprocesseur, y compris les macros prédéfinies. Cela vous donne un moyen de savoir ce qui est prédéfini dans votre version du préprocesseur. En supposant que vous n'avez pas de fichier foo.h, la commande 
touch foo.h; cpp -dM foo.h

affiche toutes les macros prédéfinies.

-dD
Similaire à -dM sauf qu'il émet *à la fois* les directives #define et le résultat du préprocesseur. Les deux types de sortie vont vers le fichier de sortie standard.
-dN
Similaire à -dD, mais n'émet que les noms de macros, pas leurs expansions.
-dI
Émettre des directives #include en plus du résultat du préprocesseur.
-dU
Similaire à -dD sauf que seules les macros qui sont développées, ou dont l'existence est testée dans les directives du préprocesseur, sont émises ; la sortie est retardée jusqu'à l'utilisation ou le test de la macro ; et les directives #undef sont également émises pour les macros testées mais non définies à ce moment-là.
-fdebug-cpp
Cette option n'est utile que pour le débogage de GCC. Lorsqu'elle est utilisée depuis CPP ou avec -E, elle affiche des informations de débogage sur les cartes de localisation. Chaque token dans la sortie est précédé du vidage de la carte à laquelle sa localisation appartient.

Lorsqu'elle est utilisée depuis GCC sans -E, cette option n'a aucun effet.

-I rép
-iquote rép
-isystem rép
-idirafter rép
Ajouter le répertoire rép à la liste des répertoires à rechercher pour les fichiers d'en-tête pendant le préprocesseur.

Si rép commence par = ou $SYSROOT, alors le = ou $SYSROOT est remplacé par le préfixe sysroot ; voir --sysroot et -isysroot.

Les répertoires spécifiés avec -iquote s'appliquent uniquement à la forme guillemet de la directive, "#include "fichier"". Les répertoires spécifiés avec -I, -isystem, ou -idirafter s'appliquent à la recherche des directives "#include "fichier"" et "#include <fichier>".

Vous pouvez spécifier n'importe quel nombre ou combinaison de ces options sur la ligne de commande pour rechercher des fichiers d'en-tête dans plusieurs répertoires. L'ordre de recherche est le suivant :

1.
Pour la forme guillemet de la directive include, le répertoire du fichier courant est recherché en premier.
2.
Pour la forme guillemet de la directive include, les répertoires spécifiés par les options -iquote sont recherchés dans l'ordre de gauche à droite, tels qu'ils apparaissent sur la ligne de commande.
3.
Les répertoires spécifiés avec les options -I sont parcourus dans l'ordre de gauche à droite.
4.
Les répertoires spécifiés avec les options -isystem sont parcourus dans l'ordre de gauche à droite.
5.
Les répertoires système standard sont parcourus.
6.
Les répertoires spécifiés avec les options -idirafter sont parcourus dans l'ordre de gauche à droite.

Vous pouvez utiliser -I pour outrepasser un fichier d'en-tête système, en substituant votre propre version, car ces répertoires sont recherchés avant les répertoires de fichiers d'en-tête système standard. Cependant, vous ne devriez pas utiliser cette option pour ajouter des répertoires contenant des fichiers d'en-tête système fournis par des fournisseurs ; utilisez -isystem pour cela.

Les options -isystem et -idirafter marquent également le répertoire comme un répertoire système, de sorte qu'il bénéficie du même traitement spécial appliqué aux répertoires système standard.

Si un répertoire d'inclusion système standard, ou un répertoire spécifié avec -isystem, est également spécifié avec -I, l'option -I est ignorée. Le répertoire est toujours recherché mais comme un répertoire système à sa position normale dans la chaîne d'inclusion système. Ceci afin de s'assurer que la procédure de GCC pour corriger les fichiers d'en-tête système bogués et l'ordre de la directive "#include_next" ne sont pas modifiés involontairement. Si vous avez vraiment besoin de changer l'ordre de recherche des répertoires système, utilisez les options -nostdinc et/ou -isystem.

-I-
Diviser le chemin d'inclusion. Cette option a été dépréciée. Veuillez utiliser -iquote à la place pour les répertoires -I avant le -I- et supprimer l'option -I-.

Tous les répertoires spécifiés avec les options -I avant -I- ne sont recherchés que pour les en-têtes demandés avec "#include "fichier"" ; ils ne sont pas recherchés pour "#include <

A0;<fichier>". Si des répertoires supplémentaires sont spécifiés avec des -I après -I-, ces répertoires sont recherchés pour toutes les directives #include .

De plus, -I- empêche l'utilisation du répertoire du fichier courant comme premier répertoire de recherche pour "#include "fichier"". Il n'y a aucun moyen de contourner cet effet de -I-.

-iprefix préfixe
Spécifie préfixe comme préfixe pour les options -iwithprefix suivantes. Si le préfixe représente un répertoire, vous devriez inclure le caractère final /.
-iwithprefix rép
-iwithprefixbefore rép
Ajoute rép au préfixe spécifié précédemment avec -iprefix, et ajoute le répertoire résultant au chemin de recherche des fichiers d'inclusion. -iwithprefixbefore le place à l'emplacement où -I le placerait ; -iwithprefix le place là où -idirafter le placerait.
-isysroot rép
Cette option est similaire à l'option --sysroot , mais s'applique uniquement aux fichiers d'en-tête (sauf pour les cibles Darwin, où elle s'applique à la fois aux fichiers d'en-tête et aux bibliothèques). Voir l'option --sysroot pour plus d'informations.
-imultilib rép
Utilise rép comme sous-répertoire du répertoire contenant les en-têtes C++ spécifiques à la cible.
-nostdinc
Ne recherche pas les fichiers d'en-tête dans les répertoires système standard. Seuls les répertoires explicitement spécifiés avec les options -I, -iquote, -isystemet/ou -idirafter (et le répertoire du fichier courant, le cas échéant) sont recherchés.
-nostdinc++
Ne recherche pas les fichiers d'en-tête dans les répertoires standard spécifiques au C++, mais recherche toujours les autres répertoires standard. (Cette option est utilisée lors de la construction de la bibliothèque C++.)
--embed-dir=rép
Ajoute le répertoire rép à la liste des répertoires recherchés pour la "#embed" directive de prétraitement ou la macro "__has_embed" . Il n'y a pas de répertoires par défaut pour "#embed".

Si rép commence par = ou $SYSROOT, alors le = ou le $SYSROOT est remplacé par le préfixe sysroot ; voir --sysroot et -isysroot.

-Wcomment
-Wcomments
Avertit chaque fois qu'une séquence de début de commentaire /* apparaît dans un commentaire /* , ou chaque fois qu'un antislash-nouvelle-ligne apparaît dans un commentaire // . Cette avertissement est activé par -Wall.
-Wtrigraphs
Avertit si des trigraphes sont rencontrés qui pourraient changer le sens du programme. Les trigraphes dans les commentaires ne déclenchent pas d'avertissement, sauf ceux qui formeraient des nouvelles lignes échappées.

Cette option est implicite avec -Wall. Si -Wall n'est pas donné, cette option est toujours activée sauf si les trigraphes sont activés. Pour obtenir la conversion des trigraphes sans avertissements, mais obtenir les autres -Wall avertissements, utilisez -trigraphs -Wall -Wno-trigraphs.

-Wundef
Avertit si un identifiant non défini est évalué dans une "#if" directive. Ces identifiants sont remplacés par zéro.
-Wexpansion-to-defined
Avertit chaque fois que defined est rencontré dans l'expansion d'une macro (y compris le cas où la macro est étendue par une #if" directive). Un tel usage n'est pas portable. Cet avertissement est également activé par -Wpedantic et -Wextra.
-Wunused-macros
Avertit à propos des macros définies dans le fichier principal qui ne sont pas utilisées. Une macro est utilisée si elle est étendue ou testée pour son existence au moins une fois. Le préprocesseur avertit également si la macro n'a pas été utilisée au moment où elle est redéfinie ou indéfinie.

Les macros intégrées, les macros définies sur la ligne de commande et les macros définies dans les fichiers d'inclusion ne déclenchent pas d'avertissement.

Remarque : Si une macro est effectivement utilisée, mais uniquement dans des blocs conditionnels ignorés, alors le préprocesseur la signale comme inutilisée. Pour éviter l'avertissement dans un tel cas, vous pourriez améliorer la portée de la définition de la macro en la déplaçant, par exemple, dans le premier bloc ignoré. Alternativement, vous pourriez fournir une utilisation factice avec quelque chose comme :

#if defined la_macro_causant_l_avertissement
#endif
-Wno-endif-labels
Ne pas avertir chaque fois qu'un "#else" ou un "#endif" est suivi de texte. Cela arrive parfois dans les anciens programmes avec du code de la forme 
#if FOO
...
#else FOO
...
#endif FOO

Le deuxième et le troisième "FOO" devraient être dans des commentaires. Cet avertissement est activé par défaut.

ENVIRONNEMENT

Cette section décrit les variables d'environnement qui affectent le fonctionnement de CPP. Vous pouvez les utiliser pour spécifier des répertoires ou des préfixes à utiliser lors de la recherche de fichiers d'inclusion, ou pour contrôler la sortie des dépendances.

Notez que vous pouvez également spécifier des endroits à rechercher en utilisant des options telles que -I, et contrôler la sortie des dépendances avec des options comme -M. Celles-ci ont la priorité sur les variables d'environnement, qui ont elles-mêmes la priorité sur la configuration de GCC.

CPATH
C_INCLUDE_PATH
CPLUS_INCLUDE_PATH
OBJC_INCLUDE_PATH
La valeur de chaque variable est une liste de répertoires séparés par un caractère spécial, très similaire à PATH, dans lesquels chercher les fichiers d'en-tête. Le caractère spécial, "PATH_SEPARATOR", est dépendant de la cible et déterminé à la construction de GCC. Pour les cibles basées sur Microsoft Windows c'est un point-virgule, et pour presque toutes les autres cibles c'est un deux-points.

CPATH spécifie une liste de répertoires à rechercher comme s'ils étaient spécifiés avec -I, mais après tous les chemins donnés avec les options -I sur la ligne de commande. Cette variable d'environnement est utilisée quelle que soit la langue en cours de prétraitement.

Les autres variables d'environnement ne s'appliquent que lors du prétraitement de la langue particulière indiquée. Chacune spécifie une liste de répertoires à rechercher comme s'ils étaient spécifiés avec -isystem, mais après tous les chemins donnés avec les options -isystem sur la ligne de commande.

Dans toutes ces variables, un élément vide indique au compilateur de rechercher dans son répertoire de travail courant. Les éléments vides peuvent apparaître au début ou à la fin d'un chemin. Par exemple, si la valeur de CPATH est ":/special/include", cela a le même effet que -I. -I/special/include".

DEPENDENCIES_OUTPUT
Si cette variable est définie, sa valeur spécifie comment produire les dépendances pour Make basées sur les fichiers d'en-tête non système traités par le compilateur. Les fichiers d'en-tête système sont ignorés dans la sortie des dépendances.

La valeur de DEPENDENCIES_OUTPUT peut être simplement un nom de fichier, auquel cas les règles Make sont écrites dans ce fichier, en devinant le nom de la cible à partir du nom du fichier source. Ou la valeur peut avoir la forme fichier cible, auquel cas les règles sont écrites dans le fichier fichier en utilisant cible comme nom de cible.

En d'autres termes, cette variable d'environnement est équivalente à combiner les options -MM et -MF, avec un interrupteur -MT optionnel aussi.

SUNPRO_DEPENDENCIES
Cette variable est la même que DEPENDENCIES_OUTPUT (voir ci-dessus), sauf que les fichiers d'en-tête système ne sont pas ignorés, donc elle implique -M plutôt que -MM". Cependant, la dépendance sur le fichier d'entrée principal est omise.
SOURCE_DATE_EPOCH
Si cette variable est définie, sa valeur spécifie un horodatage UNIX à utiliser en remplacement de la date et de l'heure actuelles dans les macros "__DATE__" et "__TIME__" , de sorte que les horodatages intégrés deviennent reproductibles.

La valeur de SOURCE_DATE_EPOCH doit être un horodatage UNIX, défini comme le nombre de secondes (excluant les secondes intercalaires) depuis le 01 Jan 1970 00:00:00 représenté en ASCII ; identique à la sortie de "date +%s" sur GNU/Linux et d'autres systèmes qui supportent l'extension %s dans la commande "date" .

La valeur devrait être un horodatage connu tel que l'heure de dernière modification du source ou du paquet et elle devrait être définie par le processus de construction.
