BUG

S

Sur les plateformes 32 bits avec glibc 2.8 et antérieur, CPU_ALLOC() alloue deux fois plus d'espace que nécessaire, et CPU_ALLOC_SIZE() renvoie une valeur deux fois plus grande qu'elle ne devrait l'être. Ce bug ne devrait pas affecter la sémantique d'un programme, mais entraîne un ga

spillage de mémoire et un fonctionnement moins efficace des macros qui opèrent sur
des ensembles de CPU alloués dynamiquement. Ces bugs sont corrigés dans glibc 2.9.

EXAMPLE

S

Le programme suivant démontre l'utilisation de certaines des macros utilisées pour les ensembles de CPU alloués

dynamiquement. 
#define _GNU_SOURCE
#include <sched.h>
#include <stdio.h>
#include <stdlib.h>
#include <unistd.h>
#include <assert.h>
int
main(int argc, char *argv[])
{
    cpu_set_t *cpusetp;
    size_t size, num_cpus;
    if (argc < 2) {
        fprintf(stderr, "Usage: %s <num-cpus>\n", argv[0]);
        exit(EXIT_FAILURE);
    }
    num_cpus = atoi(argv[1]);
    cpusetp = CPU_ALLOC(num_cpus);
    if (cpusetp == NULL) {
        perror("CPU_ALLOC");
        exit(EXIT_FAILURE);
    }
    size = CPU_ALLOC_SIZE(num_cpus);
    CPU_ZERO_S(size, cpusetp);
    for (size_t cpu = 0; cpu < num_cpus; cpu += 2)
        CPU_SET_S(cpu, size, cpusetp);
    printf("CPU_COUNT() of set:    %d\n", CPU_COUNT_S(size, cpusetp));
    CPU_FREE(cpusetp);
    exit(EXIT_SUCCESS);
}
