DESCRIPTIO

N

Cppcheck est un outil en ligne de commande qui tente de détecter des bugs que votre compilateur C/C++ ne voit pas. Il est polyvalent et peut vérifier du code non sta

ndard, y compris diverses extensions de compilateur, du code assembleur en ligne, etc. Son préprocesseur interne peut gérer les inclusions, les macros et plusieurs c
ommandes de préprocesseur. Bien que Cppcheck soit hautement configurable, vous pouvez commencer à l'utiliser simplement en lui donnant un chemin vers le code source.

OPTION

S

Analyse les fichiers C/C++ donnés pour les erreurs

courantes.

--check-confi

g
Vérifie la configuration de Cppcheck. L'analyse de code normale est désactivée par cette
option.

--check-librar

y
Affiche des messages d'information lorsque les fichiers de bibliothèque contiennent des informations
incomplètes.

-D<id

>
Par défaut, Cppcheck vérifie toutes les configurations. Utilisez -D pour limiter la vérification. Lorsque -D est utilisé, la vérification est limitée à la configuration donnée. Exemple : -DDEBUG=1
-D__cplusplus

-U<id

>
Par défaut, Cppcheck vérifie toutes les configurations. Utilisez '-U' pour masquer explicitement certains chemins de code #ifdef <id> de la vérification. Exemple :
'-UDEBUG'

--disable=<id

>
Désactive des vérifications individuelles. Veuillez consulter la documentation de --enable=<id> pour plus de
détails.

--enable=<id

>
Active des vérifications supplémentaires. Les identifiants disponibles sont :

al

l
Active toutes les vérifications. Il est recommandé d'utiliser --enable=all uniquement lorsque tout le programme est analysé, car cela active
unusedFunction.

warnin

g
Active les messages
d'avertissement

styl

e
Active toutes les vérifications de style de codage. Tous les messages avec les sévérités 'style', 'performance' et 'portability' sont
activés.

performanc

e
Active les messages de
performance

portabilit

y
Active les messages de
portabilité

informatio

n
Active les messages
d'information

unusedFunctio

n
Vérifie les fonctions inutilisées. Il est recommandé de n'activer cela que lorsque tout le programme est
analysé

missingInclud

e
Avertit s'il manque des
inclusions

Par défaut, aucune des vérifications supplémentaires n'est activée.

Plusieurs identifiants peuvent être donnés en les séparant par de
s virgules, par ex. --enable=style,unusedFunction. Voir aussi --std

--error-exitcode=<n

>
Si des erreurs sont trouvées, l'entier <n> est renvoyé au lieu de la valeur par défaut 0. EXIT_FAILURE est renvoyé si les arguments ne sont pas valides ou si aucun fichier d'entrée n'est fourni. Notez que votre système d'exploitation peut modifier cette valeur, par ex. 256 peut devenir
0.

--errorlis

t
Affiche une liste de tous les messages d'erreur possibles au format
XML.

--exitcode-suppressions=<fichier

>
Utilisé lorsque certains messages doivent être affichés mais ne doivent pas provoquer un code de sortie non
nul.

--file-list=<fichier

>
Spécifie les fichiers à vérifier dans un fichier texte. Un nom de fichier par ligne. Lorsque le fichier est -, la liste de fichiers sera lue depuis l'entrée
standard.

--filesdi

r
Affiche le FILESDIR
intégré.

-f, --forc

e
Force la vérification des fichiers qui ont beaucoup de configurations. Une erreur est imprimée si un tel fichier est trouvé, il n'y a donc aucune raison d'utiliser cette option par défaut. Si utilisée avec --max-configs=, la dernière option est celle qui prend
effet.

--fsigned-cha

r
Traite le type char comme signé. Cela remplace les options --platform précédentes et est remplacé par les
suivantes.

--funsigned-cha

r
Traite le type char comme non signé. Cela remplace les options --platform précédentes et est remplacé par les
suivantes.

-h, --hel

p
Affiche le texte
d'aide.

-I

<rép>
Donne le chemin où chercher les fichiers d'inclusion. Donnez plusieurs paramètres -I pour donner plusieurs chemins. Le premier chemin donné est d'abord recherché pour les fichiers d'en-tête qu'il contient. Si les chemins sont relatifs aux fichiers sources, cela n'est pas
nécessaire.

--includes-file=<fichier

>
Spécifie les chemins de répertoires où chercher les fichiers d'en-tête inclus dans un fichier texte. Ajoutez un chemin d'inclusion par ligne. Le premier chemin donné est d'abord recherché pour les fichiers d'en-tête qu'il contient. Si les chemins sont relatifs aux fichiers sources, cela n'est pas
nécessaire.

--config-exclude=<rép

>
Chemin (préfixe) à exclure de la vérification de configuration. Les configurations de préprocesseur définies dans les en-têtes (mais pas dans les sources) correspondant au préfixe ne seront pas prises en compte pour l'évaluation des alternatives de
configuration.

--config-exclude-file=<fichier

>
Un fichier qui contient une liste de config-excludes
.

--include=<fichier

>
Force l'inclusion d'un fichier avant le fichier vérifié. Peut être utilisé, par exemple, lors de la vérification du noyau Linux, où autoconf.h doit être inclus pour chaque fichier compilé. Fonctionne de la même manière que l'option -include de
GCC.

-i

<rép>
Donne le chemin à ignorer. Donnez plusieurs paramètres -i pour ignorer plusieurs chemins. Donnez le nom du répertoire ou le nom du fichier avec le chemin comme paramètre. Le nom du répertoire est comparé à toutes les parties du
chemin.

--inconclusiv

e
Permet à Cppcheck de signaler des problèmes même si l'analyse est non concluante. Il y a des faux positifs avec cette option. Chaque résultat doit être soigneusement examiné avant de savoir s'il est bon ou
mauvais.

--inline-supp

r
Active les suppressions en ligne. Utilisez-les en plaçant des commentaires sous la forme : // cppcheck-suppress memleak avant la ligne à
supprimer.

-j

<tâches>
Démarre <tâches> threads pour effectuer le travail de
vérification.

-l

<charge>
Spécifie qu'aucun nouveau thread ne doit être démarré s'il y a d'autres threads en cours d'exécution et que la charge moyenne est d'au moins <charge> (ignoré sur les systèmes non de type
UNIX)

--language=<langage

>
Force cppcheck à vérifier tous les fichiers comme le langage donné. Les valeurs valides sont : c,
c++

--library=<cfg

>
Utilise la configuration de
bibliothèque.

--max-configs=<limite

>
Nombre maximum de configurations à vérifier dans un fichier avant de le sauter. La valeur par défaut est 12. Si utilisée avec --force, la dernière option est celle qui prend
effet.

--max-ctu-depth=<limite

>
Profondeur maximale dans l'analyse du programme entier. La valeur par défaut est
2.

-rp, -rp=<chemins>, --relative-paths;, --relative-paths=<chemins

>
Utiliser des chemins relatifs dans la sortie. Lorsqu'ils sont fournis, les <chemins> sont utilisés comme base. Vous pouvez séparer plusieurs chemins par ';'. Sinon, le chemin où les fichiers sources sont recherchés est utilisé. Par exemple, si la valeur fournie est test, lors de la vérification de test/test.cpp, le chemin dans la sortie sera test.cpp au lieu de test/test.cpp. Cette fonctionnalité utilise une comparaison de chaînes pour créer des chemins relatifs, l'utilisation de ~ pour le dossier personnel ne fonctionne donc pas. Il n'est actuellement possible d'appliquer les chemins de base qu'aux fichiers qui se trouvent à un niveau inférieur dans l'arborescence des
répertoires.

Correspondance d'une expression régulière pour créer vos propres vérifications. Par exemple, la règle "/ 0" peut être utilisée pour vérifier la division par zéro. Cette commande n'est disponible que si cppcheck a été compilé avec

--suppress=<spéc

>
Supprimer un avertissement spécifique. Le format de <spéc> est : [id d'erreur]:[nom de fichier]:[ligne]. Le [nom de fichier] et la [ligne] sont optionnels.
