SPÉCIFICATIONS DE

VERSION

Certains champs nécessitent une spécification de version (ex. "requires", "recommends", "build_requires", etc.) pour indiquer les version(s) particulière(s) d'un autre module qui peut être requise comme prérequis. Cette section détaille les formats de spécification de version actuellement pris en

charge.

Le format le plus simple pour une spécification de version est simplement le numéro de version lui-même, par ex. 2.4. Cela signifie que au moins la version 2.4 doit être présente. Pour indiquer que n'importe quelle version d'un prérequis convient, même si le prérequis ne définit pas de version du tout, utilisez la version 0

.

Vous pouvez également utiliser les opérateurs < (inférieur à), <= (inférieur ou égal), > (supérieur à), >= (supérieur ou égal), == (égal), et != (différent). Par exemple, la spécification < 2.0 signifie que toute version du prérequis inférieure à 2.0

convient.

Pour les situations plus compliquées, les spécifications de version peuvent être combinées par ET (AND) à l'aide de virgules. La spécification >= 1.2, != 1.5, < 2.0 indique une version qui doit être au moins 1.2, inférieure à 2.0, et différente

de
1.5.
