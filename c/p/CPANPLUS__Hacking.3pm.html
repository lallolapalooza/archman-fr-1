NOM

CPANPLUS::Hacking - développement de CPANPLUS

DESCRIPTION

Ce document tente de décrire comment développer le plus facilement dans l'environnement CPANPLUS, comment certaines choses fonctionnent et pourquoi.

Il s'agit essentiellement d'un guide de démarrage rapide pour les personnes qui souhaitent ajouter des fonctionnalités ou des correctifs à CPANPLUS.

OBTENIR CPANPLUS

Récupérez CPANPLUS depuis son dépôt GIT à l'adresse https://github.com/jib/cpanplus-devel .

INSTALLER CPANPLUS

CPANPLUS suit le processus standard d'installation des modules Perl :

perl Makefile.PL
make
make test
make install

CONFIGURER CPANPLUS

Lorsque vous exécutez "perl Makefile.PL" vous serez invité à configurer. Si vous l'avez déjà fait et souhaitez simplement mettre à jour le "Makefile", exécutez simplement :

perl Makefile.PL JFDI=1

Cela conservera votre configuration intacte. Notez cependant que s'il y a des modifications dans le fichier de configuration par défaut "Config.pm-orig", vous devriez soit supprimer votre fichier de configuration actuel et reconfigurer, soit patcher votre fichier de configuration à partir des nouvelles entrées dans "Config.pm-orig".

EXECUTER CPANPLUS DEPUIS L'ENVIRONNEMENT DE DÉVELOPPEMENT

Si vous préférez ne pas installer la version de développement dans votre répertoire "site_perl", ce n'est pas un problème. Vous pouvez définir votre variable d'environnement "PERL5LIB" vers le répertoire "lib" de CPANPLUS, et vous pouvez l'exécuter à partir de là.

EXECUTER LES TESTS CPANPLUS

Les tests nous disent si CPANPLUS fonctionne. Si un test ne fonctionne pas, essayez de l'exécuter explicitement comme ceci :

perl -I/chemin/vers/cpanplus/lib t/XX_nom_du_test.t 1

Le '1' supplémentaire garantit que tous les messages et erreurs (il peut s'agir d'erreurs que nous testons !) sont imprimés plutôt que gardés silencieux. C'est un excellent moyen de trouver le contexte de tout échec qui pourrait survenir.

Si vous pensez que cet échec de test prouve un bug dans CPANPLUS, nous aimerions voir la sortie complète du fichier de test accompagnée de votre rapport de bug.

TROUVER DES BOGUES

Parfois, vous pourriez trouver des bugs dans le comportement de CPANPLUS. Si vous rencontrez ces problèmes dans un instantané de développement, nous apprécierions un correctif complet (comme décrit ci-dessous dans la section « ENVOYER DES CORRECTIFS »).

Si c'est trop compliqué pour vous, alors bien sûr, signaler le bug est toujours mieux que de ne pas le signaler du tout. Avant de le faire cependant, assurez-vous d'avoir la dernière version de développement, et que le bug persiste toujours. Si c'est le cas, signalez le bug à cette adresse :

bug-cpanplus@rt.cpan.org

Un bon "correctif" aurait les caractéristiques suivantes :

Description du problème
Décrivez clairement quel est le bug que vous avez trouvé, et ce qu'il aurait dû faire à la place.
Programme démontrant le bug
Montrez-nous comment reproduire le bug, dans un programme aussi simple que possible.
[OPTIONNEL] Un correctif pour la suite de tests afin de tester le bug
Modifiez notre suite de tests en vous assurant que ce bug sera trouvé dans cette version, et dans les futures versions de CPANPLUS (voir « FOURNIR DES CORRECTIFS »)
[OPTIONNEL] Un correctif pour le code + les tests + la documentation
Corrigez le bug, mettez à jour la documentation et les tests. Ainsi, votre bug disparaîtra à jamais :)

FOURNIR DES CORRECTIFS

Les correctifs sont une bonne chose et sont les bienvenus. Surtout s'ils corrigent des bugs que vous avez trouvés en cours de route, ou que d'autres ont signalés.

Nous préférons les correctifs dans le format suivant :

  • Au format "diff -u" ou "diff -c"
  • Depuis la racine de l'instantané
  • Incluant les correctifs pour le code + les tests + la documentation
  • Envoyés par e-mail à bug-cpanplus@rt.cpan.org
  • Avec un sujet contenant "[PATCH]" + la description du correctif

Vous serez toujours informé si un correctif est appliqué ou rejeté, et en cas de rejet, pourquoi (peut-être pouvez-vous ajuster le correctif pour qu'il soit accepté après tout).
