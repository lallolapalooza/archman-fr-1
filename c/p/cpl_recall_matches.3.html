DESCRIPTION

La fonction cpl_complete_word() fait partie de la bibliothèque tecla (voir la page man libtecla(3)). Elle est généralement appelée en interne par gl_get_line(3), mais peut aussi être appelée séparément.

Étant donné une ligne d'entrée contenant un mot incomplet à compléter, elle appelle une fonction de rappel fournie par l'utilisateur (ou la fonction de rappel de complétion de fichier fournie) pour rechercher tous les suffixes de complétion possibles pour ce mot. La fonction de rappel doit parcourir la ligne vers l'arrière, à partir de la position du curseur spécifiée, pour trouver le début du mot à compléter, puis rechercher tous les compléments possibles de ce mot et les enregistrer, un à la fois, en appelant cpl_add_completion().

Les descriptions des fonctions de ce module sont les suivantes :

  WordCompletion *new_WordCompletion(void)

Cette fonction crée les ressources utilisées par la fonction cpl_complete_word() . En particulier, elle gère la mémoire utilisée pour retourner les résultats de l'appel à cpl_complete_word().

  WordCompletion *del_WordCompletion(WordCompletion *cpl)

Cette fonction supprime les ressources qui ont été retournées par un appel précédent à new_WordCompletion(). Elle retourne toujours NULL (c'est-à-dire un objet supprimé). Elle ne fait rien si l'argument cpl est NULL.

Les fonctions de rappel qui recherchent les compléments possibles doivent être définies avec la macro suivante (qui est définie dans libtecla.h).

  #define CPL_MATCH_FN(fn) int (fn)(WordCompletion *cpl, \
                                    void *data, \
                                    const char *line, \
                                    int word_end)

Les fonctions de ce type sont appelées par cpl_complete_word(), et tous les arguments de la fonction de rappel sont ceux qui ont été passés à ladite fonction. En particulier, l'argument line contient la ligne d'entrée contenant le mot à compléter, et word_end est l'index du caractère qui suit le dernier caractère du mot incomplet dans cette chaîne. La fonction de rappel doit parcourir la chaîne vers l'arrière à partir de word_end pour trouver le début du mot incomplet. Ce qui constitue le début d'un mot dépend clairement de l'application, il est donc logique que la fonction de rappel assume cette responsabilité. Par exemple, la fonction intégrée de complétion de noms de fichiers parcourt la chaîne vers l'arrière jusqu'à ce qu'elle rencontre un espace non échappé ou le début de la ligne. Une fois le début du mot trouvé, la fonction de rappel doit rechercher tous les compléments possibles de ce mot et enregistrer chaque complément via des appels séparés à cpl_add_completion(). Si la fonction de rappel a besoin d'accéder à une table de symboles spécifique à l'application, elle peut la passer, ainsi que toute autre donnée dont elle a besoin, via l'argument data . Cela élimine tout besoin de variables globales.

La fonction de rappel doit retourner 0 si aucune erreur ne se produit. En cas d'échec, elle doit retourner 1 et enregistrer une description concise de l'erreur en appelant cpl_record_error().

  void cpl_record_error(WordCompletion *cpl,
                        const char *errmsg);

Le dernier message d'erreur enregistré en appelant cpl_record_error()peut ensuite être interrogé en appelant cpl_last_error(), comme décrit plus tard.

  int cpl_add_completion(WordCompletion *cpl,
                         const char *line, int word_start,
                         int word_end, const char *suffix,
                         const char *type_suffix,
                         const char *cont_suffix);

La fonction cpl_add_completion() est appelée zéro fois ou plus par la fonction de rappel de complétion pour enregistrer chaque complément possible dans l'objet WordCompletion spécifié. Ces compléments sont ensuite retournés par cpl_complete_word(), comme décrit plus tard. Les arguments cpl, lineet word_end doivent être ceux qui ont été passés à la fonction de rappel. L'argument word_start doit être l'index dans la chaîne de la ligne d'entrée du début du mot qui est en cours de complétion. Cela doit être égal à word_end si une chaîne de longueur zéro est en cours de complétion. L'argument suffix est la chaîne qui devrait être ajoutée au mot incomplet pour le compléter. Si cela nécessite un échappement (par exemple l'ajout de barres obliques inversées avant des caractères spéciaux) pour être valide dans la ligne d'entrée affichée, cela doit être inclus. Une copie de la chaîne suffixe est allouée en interne, il n'est donc pas nécessaire de conserver votre copie de la chaîne après le retour de cpl_add_completion() .

Notez que dans le tableau des compléments possibles que la fonction cpl_complete_word() retourne, le suffixe enregistré par cpl_add_completion() est listé avec la concaténation de ce suffixe et du mot situé entre word_start et word_end dans la ligne d'entrée.

L'argument type_suffix spécifie une chaîne facultative à ajouter au complément s'il est affiché dans le cadre d'une liste de compléments par cpl_list_completions(). L'intention est que cela indique à l'utilisateur le type de chaque complément. Par exemple, la fonction de complétion de fichiers place un séparateur de répertoires après les compléments qui sont des répertoires, pour indiquer leur nature à l'utilisateur. De même, si le complément était une fonction, vous pourriez l'indiquer à l'utilisateur en définissant type_suffix à "()" . Notez que la chaîne type_suffix n'est pas copiée, donc si l'argument n'est pas une chaîne littérale entre guillemets, assurez-vous que la chaîne reste valide au moins aussi longtemps que les résultats de cpl_complete_word() sont nécessaires.

Le cont_suffix est un suffixe de continuation à ajouter au mot complété dans la ligne d'entrée si c'est le seul complément. C'est quelque chose qui ne fait pas partie du complément lui-même, mais qui donne à l'utilisateur une indication sur la manière dont il pourrait continuer à étendre le jeton. Par exemple, la fonction de rappel de complétion de fichiers ajoute un séparateur de répertoires si le mot complété est un répertoire. Si le mot complété était un nom de fonction, vous pourriez de même aider l'utilisateur en faisant en sorte qu'une parenthèse ouvrante soit ajoutée.

  CplMatches *cpl_complete_word(WordCompletion *cpl,
                                const char *line,
                                int word_end, void *data,
                                CplMatchFn *match_fn);

La fonction cpl_complete_word() est normalement appelée en interne par gl_get_line(3), mais peut aussi être appelée séparément si vous allouez séparément un objet WordCompletion . Elle effectue la complétion de mot, comme décrit au début de cette section. Son premier argument est un objet de ressources précédemment retourné par new_WordCompletion(). L'argument line est la chaîne de la ligne d'entrée, contenant le mot à compléter. L'argument word_end contient l'index du caractère dans la ligne d'entrée qui suit juste le dernier caractère du mot à compléter. Lorsqu'elle est appelée par >gl_get_line(), c'est le caractère sur lequel l'utilisateur a appuyé TAB. Le match_fn argument est la fonction pointeur de la fonction de rappel qui recherchera les complétions possibles de le mot, comme décrit ci-dessus, et l'argument data fournit un moyen pour l'application de passer des données arbitraires à la fonction de rappel.

Si aucune erreur ne se produit, la fonction cpl_complete_word() retourne un pointeur vers un conteneur CplMatches , comme défini ci-dessous. Ce conteneur est alloué dans le cadre de l'objet cpl qui a été passé à cpl_complete_word(), et changera donc à chaque appel utilisant le même argument cpl .

  typedef struct {
    char *completion;        /* Une chaîne de complétion */
                             /*  correspondante */
    char *suffix;            /* La partie de la chaîne */
                             /*  de complétion qui */
                             /*  devrait être ajoutée pour */
                             /*  compléter le mot */
                             /*  original. */
    const char *type_suffix; /* Un suffixe à ajouter lors */
                             /*  de la liste des complétions, */
                             /*  pour indiquer le type de */
                             /*  la complétion. */
  } CplMatch;
  typedef struct {
    char *suffix;            /* La partie initiale commune */
                             /*  de tous les suffixes de */
                             /*  complétion. */
    const char *cont_suffix; /* Chaîne de continuation */
                             /*  optionnelle à ajouter à */
                             /*  la seule complétion quand */
                             /*  nmatch==1. */
    CplMatch *matches;       /* Le tableau des chaînes de */
                             /*  complétion possibles, */
                             /*  trié dans l'ordre */
                             /*  lexical. */
    int nmatch;              /* Le nombre d'éléments dans */
                             /*  le tableau matches[] */
                             /*  ci-dessus. */
  } CplMatches;

Si une erreur se produit pendant la complétion, cpl_complete_word() retourne NULL. Une description de l'erreur peut être obtenue en appelant la fonction cpl_last_error() .

  const char *cpl_last_error(WordCompletion *cpl);

La fonction cpl_last_error() retourne une description concise de l' erreur qui s'est produite lors du dernier appel à cpl_complete_word() ou cpl_add_completion().

  CplMatches *cpl_recall_matches(WordCompletion *cpl);

Par commodité, la valeur de retour du dernier appel à cpl_complete_word() peut être rappelée plus tard en appelant cpl_recall_matches(). Si cpl_complete_word() a retourné NULL, il en sera de même pour cpl_recall_matches().

  int cpl_list_completions(CplMatches *result, FILE *fp,
                           int terminal_width);

Quand la fonction cpl_complete_word() retourne plusieurs complétions possibles, la fonction cpl_list_completions() peut être appelée pour les lister, convenablement réparties sur la largeur disponible du terminal. Elle s'arrange pour que les colonnes affichées des complétions aient toutes la même largeur, déterminée par la complétion la plus longue. Elle ajoute également les chaînes type_suffix qui ont été enregistrées avec chaque complétion, indiquant ainsi leurs types à l'utilisateur.

LA FONCTION DE RAPPEL DE COMPLÉTION DE NOM DE FICHIER INTÉGRÉE

Par défaut, la fonction gl_get_line(3) passe la fonction de rappel de complétion suivante à cpl_complete_word(). Cette fonction peut également être utilisée séparément, soit en la passant à cpl_complete_word(), soit en l'appelant directement depuis votre propre fonction de rappel de complétion.

  CPL_MATCH_FN(cpl_file_completions);

Certains aspects du comportement de cette fonction de rappel peuvent être modifiés via son argument data . Si vous êtes satisfait de son comportement par défaut, vous pouvez passer NULL dans cet argument. Sinon, il devrait s'agir d'un pointeur vers un objet CplFileConf , précédemment alloué en appelant new_CplFileConf().

  CplFileConf *new_CplFileConf(void);

Les objets CplFileConf encapsulent les paramètres de configuration decpl_file_completions()

. Ces paramètres, qui commencent avec des valeurs par défaut, peuvent être modifiés en appelant les fonctions d'accès décrites ci-dessous. Par défaut, la fonction de rappel cpl_file_completions() recherche vers l'arrière le début du nom de fichier étant complété, en cherchant le premier espace non échappé ou le début de la ligne d' entrée. Si vous souhaitez spécifier un emplacement différent, appelez cfc_file_start() avec l'index auquel le nom de fichier commence dans la ligne d'entrée. Passer start_index=-1 réactive le comportement par défaut.

  void cfc_file_start(CplFileConf *cfc, int start_index);

Par défaut, quand cpl_file_completions() examine un nom de fichier dans la ligne d'entrée, chaque antislash solitaire dans la ligne d'entrée est interprété comme étant un caractère spécial qui retire toute signification spéciale du caractère qui le suit, comme un espace qui devrait être pris comme partie du nom de fichier plutôt que comme délimitant le début du nom de fichier. Ces antislashes sont donc ignorés lors de la recherche de complétions, et sont ensuite ajoutés avant les espaces, les tabulations et les antislashes littéraux dans la liste des complétions. Pour que les antislashes non échappés soient traités comme des caractères normaux, appelez cfc_literal_escapes() avec une valeur non nulle dans son argument literal .

  void cfc_literal_escapes(CplFileConf *cfc, int literal);

Par défaut, cpl_file_completions() rapporte tous les fichiers dont les noms commencent par le préfixe qui est complété. Si vous ne voulez qu'un sous-ensemble sélectionné de ces fichiers soit rapporté dans la liste des complétions, vous pouvez organiser cela en fournissant une fonction de rappel qui prend le chemin complet d'un fichier, et retourne 0 si le fichier doit être ignoré, ou 1 si le fichier doit être inclus dans la liste des complétions. Pour enregistrer une telle fonction pour une utilisation par cpl_file_completions(), appelez cfc_set_check_fn(), et passez-lui un pointeur vers la fonction, ainsi qu'un pointeur vers toutes les données que vous aimeriez passer à cette fonction de rappel à chaque fois qu'elle est appelée. Votre fonction de rappel peut prendre ses décisions en fonction de n'importe quelle propriété du fichier, comme le nom du fichier lui-même, si le fichier est lisible, inscriptible ou exécutable, ou même en fonction de ce que le fichier contient.

  #define CPL_CHECK_FN(fn) int (fn)(void *data, \
                                    const char *pathname)
  typedef CPL_CHECK_FN(CplCheckFn);
  void cfc_set_check_fn(CplFileConf *cfc,
                        CplCheckFn *chk_fn, void *chk_data);

La fonction cpl_check_exe() est une fonction de rappel fournie du type ci-dessus, pour une utilisation avec cpl_file_completions(). Elle retourne une valeur non nulle si le nom de fichier qui lui est donné représente un fichier normal pour lequel l'utilisateur a la permission d'exécution. Vous pourriez utiliser ceci pour faire en sorte que cpl_file_completions() ne liste que les complétions de fichiers exécutables.

Quand vous avez terminé avec une variable CplFileConf , vous pouvez la passer à la fonction destructrice del_CplFileConf() pour récupérer sa mémoire.

  CplFileConf *del_CplFileConf(CplFileConf *cfc);

SÉCURITÉ DES THREADS

Dans les programmes multi-threads, vous devriez utiliser la version libtecla_r.a de la bibliothèque. Celle-ci utilise les fonctions réentrantes POSIX quand elles sont disponibles (d'où le suffixe _r ), et désactive les fonctionnalités qui reposent sur des fonctions système non réentrantes. Dans le cas de ce module, la seule fonctionnalité désactivée est la complétion de nom d'utilisateur dans les expressions ~username/ , dans cpl_file_completions().

En utilisant la version libtecla_r.a de la bibliothèque, il est sûr d'utiliser les fonctionnalités de ce module dans plusieurs threads, à condition que chaque thread utilise un objet WordCompletion alloué séparément. En d'autres termes, si deux threads veulent faire de la complétion de mots, ils devraient chacun appeler new_WordCompletion() pour allouer leurs propres objets de complétion.
