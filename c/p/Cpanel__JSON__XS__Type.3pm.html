DESCRIPTIO

N

Ce module fournit une prise en charge stable des types JSON pour le codeur Cpanel::JSON::XS qui ne dépend d'aucun drapeau ou caractéristique interne des scalaires perl. De plus, il fournit de vrais types JSON pour le décodeur Cpanel::JSON::

XS.

Dans la plupart des cas, les structures perl passées à encode_json proviennent d'autres fonctions ou d'autres modules et l'appelant du module Cpanel::JSON::XS n'a pas le contrôle des détails internes ou ceux-ci sont sujets à changement. Il est donc difficile de prendre en charge l'imposition de types comme décrit dans la section sur les scalaires

simples.

Pour les services basés sur les contenus JSON, il est parfois nécessaire de traiter et d'imposer correctement les types

JSON.

La fonction decode_json prend un troisième paramètre scalaire optionnel et le remplit avec la spécification des types

json.

La fonction encode_json prend une structure perl en entrée et éventuellement aussi une spécification de type json en deuxième

paramètre.

Si la spécification n'est pas fournie (ou est undef), les drapeaux internes des scalaires perl sont utilisés pour le type JSON résultant. Les drapeaux internes peuvent être modifiés par perl lui-même, mais aussi par des modules externes. Ce qui signifie que les types dans la chaîne JSON résultante ne sont pas stables. En particulier, cela ne fonctionne pas de manière fiable pour les variables duales et les scalaires qui ont été utilisés à la fois dans des opérations numériques et des opérations de chaîne. Voir les scalaires

simples.

Pour imposer que la spécification soit toujours fournie, utilisez "require_types". Dans ce cas, lorsque "encode" est appelé sans deuxième argument (ou est undef), il provoque une erreur fatale. Cela s'applique récursivement pour toutes les sous-structures

.

Spécifications

récursives
json_type_wea
ken
Cette fonction peut être utilisée comme argument pour les fonctions "json_type_arrayof", "json_type_hashof" ou "json_type_anyof" pour créer des références faibles appropriées pour des structures récursives compliquées. Elle dépend de la fonction weaken du module Scalar::Util. Voir l'exemple suivant : 
my $struct = {
    type => JSON_TYPE_STRING,
    array => json_type_arrayof(JSON_TYPE_INT),
};
$struct->{recursive} = json_type_anyof(
    json_type_weaken($struct),
    json_type_arrayof(JSON_TYPE_STRING)
, );

Si vous voulez encoder tous les scalaires perl en types de chaîne JSON peu importe la complexité de la structure perl d'entrée, vous pouvez définir la spécification de type JSON pour les alternatives de manière récursive. Elle pourrait être

définie comme : 
my $type = json_type_anyof();
$type->[0] = JSON_TYPE_STRING_OR_NULL;
$type->[1] = json_type_arrayof(json_type_weaken($type));
$type->[2] = json_type_hashof(json_type_weaken($type));
print encode_json([ 10, "10", { key => 10 } ], $type);
# ["10","10",{"key":
"10"}]
