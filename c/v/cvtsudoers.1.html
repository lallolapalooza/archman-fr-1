CVTSUDOERS(1) Manuel des commandes générales CVTSUDOERS(1)

NOM

cvtsudoers — convertir entre les formats de fichier sudoers

SYNOPSIS

cvtsudoers [-ehMpV] [-b dn] [-c fichier_conf] [-d types_def] [-f format_sortie] [-i format_entree] [-I increment] [-l fichier_log] [-m filtre] [-o fichier_sortie] [-O point_depart] [-P remplissage] [-s sections] [fichier_entree ...]

DESCRIPTION

L'utilitaire cvtsudoers accepte une ou plusieurs politiques de sécurité au format sudoers ou LDIF en entrée, et génère une seule politique au format spécifié en sortie. Le format d'entrée par défaut est sudoers. Le format de sortie par défaut est LDIF. Il n'est possible de convertir un fichier de politique que s'il est syntaxiquement correct.

Si aucun fichier_entree n'est spécifié, ou s'il s'agit de ‘-’, la politique est lue depuis l'entrée standard. Les fichiers d'entrée peuvent être préfixés optionnellement par un nom d'hôte suivi d'un deux-points (‘:’) pour rendre les règles de politique spécifiques à un hôte lors de la fusion de plusieurs fichiers. Par défaut, le résultat est écrit sur la sortie standard.

Les options sont les suivantes :

-b dn, --base=dn
Le DN de base (distinguished name) qui sera utilisé lors des requêtes LDAP. Typiquement, il s'agit de la forme “ou=SUDOers,dc=mon-domaine,dc=com” pour le domaine mon-domaine.com. Si cette option n'est pas spécifiée, la valeur de la variable d'environnement SUDOERS_BASE sera utilisée à la place. Nécessaire uniquement lors de la conversion au format LDIF.
-c fichier_conf, --config=fichier_conf
Spécifie le chemin du fichier de configuration. Par défaut, /etc/cvtsudoers.conf.
-d types_def, --defaults=types_def
Convertir uniquement les entrées Defaults des types spécifiés. Un ou plusieurs types Defaults peuvent être spécifiés, séparés par une virgule (‘,’). Les types supportés sont :
all
Toutes les entrées Defaults.
global
Entrées Defaults globales qui s'appliquent indépendamment de l'utilisateur, du runas, de l'hôte ou de la commande.
user
Entrées Defaults par utilisateur.
runas
Entrées Defaults par utilisateur runas.
host
Entrées Defaults par hôte.
command
Entrées Defaults par commande.

Voir la section Defaults dans sudoers(5) pour plus d'informations.

Si l'option -d n'est pas spécifiée, toutes les entrées Defaults seront converties.

-e, --expand-aliases
Développer les alias dans fichier_entree. Les alias sont préservés par défaut lorsque le format de sortie est JSON ou sudoers.
-f format_sortie, --output-format=format_sortie
Spécifie le format de sortie (insensible à la casse). Les formats suivants sont supportés :
CSV
Les fichiers CSV (Comma-Separated Value) sont souvent utilisés par les tableurs et les générateurs de rapports. Voir la section Format de sortie CSV pour plus de détails.
JSON
Les fichiers JSON (JavaScript Object Notation) sont généralement plus faciles à consommer par des applications tierces que le format sudoers traditionnel. Les différentes valeurs ont des types explicites, ce qui élimine une grande partie de l'ambiguïté du format sudoers. Voir la section Format de sortie JSON pour plus de détails.
LDIF
Les fichiers LDIF (LDAP Data Interchange Format) peuvent être importés dans un serveur LDAP pour être utilisés avec sudoers.ldap(5).

La conversion en LDIF présente les limitations suivantes :

  • Les lignes Defaults spécifiques à une commande, un hôte, un runas ou un utilisateur ne peuvent pas être traduites car elles n'ont pas d'équivalent dans le schéma LDAP de sudoers.
  • Les alias de commande, d'hôte, de runas et d'utilisateur ne sont pas supportés par le schéma LDAP de sudoers, ils sont donc développés lors de la conversion.
sudoers
Format sudoers traditionnel. Un nouveau fichier sudoers sera reconstruit à partir du fichier d'entrée parsé. Les commentaires ne sont pas préservés et les données des fichiers inclus seront affichées en ligne.
--group-file=fichier
Lorsque l'option -M est également spécifiée, effectue des requêtes de groupe en utilisant fichier au lieu de la base de données des groupes du système.
-h, --help
Affiche un court message d'aide sur la sortie standard et quitte.
-i format_entree, --input-format=format_entree
Spécifie le format d'entrée. Les formats suivants sont supportés :
LDIF
Les fichiers LDIF (LDAP Data Interchange Format) peuvent être exportés depuis un serveur LDAP pour convertir les politiques de sécurité utilisées par sudoers.ldap(5). Si un DN de base (distinguished name) est spécifié, seuls les objets sudoRole correspondant au DN de base seront traités. Toutes les sudoOptions spécifiées dans un sudoRole ne peuvent pas être traduites du format LDIF au format sudoers.
sudoers
Format sudoers traditionnel. C'est le format d'entrée par défaut.
-I increment, --increment=increment
Lors de la génération de la sortie LDIF, incrémente l'attribut sudoOrder de la valeur spécifiée. Par défaut, l'incrément est de 1.
-l fichier_log, --logfile=fichier_log
Enregistre les avertissements de conversion dans fichier_log au lieu de l'erreur standard. Ceci est particulièrement utile lors de la fusion de plusieurs fichiers sudoers, qui peuvent générer un grand nombre d'avertissements.
-m filtre, --match=filtre
N'affiche que les règles qui correspondent au filtre spécifié. Une expression de filtre est composée d'une ou plusieurs paires clé = valeur, séparées par une virgule (‘,’). La clé peut être “cmnd” (ou “cmd”), “host”, “group”, ou “user”. Par exemple, user = opérateur ou host = www. Un alias de commande en majuscule, Alias_hôte, ou Alias_Utilisateur peut être spécifié comme la commande « cmd », « hôte » ou « utilisateur ».

Une règle correspondante de sudoers peut également inclure des utilisateurs, des groupes et des hôtes qui ne font pas partie du filtre de filtre.

Cela peut se produire lorsqu'une règle comprend plusieurs utilisateurs, groupes ou hôtes. Pour éliminer tout utilisateur, groupe ou hôte ne correspondant pas aux règles, l'option -p peut être utilisée.

Par défaut, les bases de données de mots de passe et de groupes ne sont pas consultées lors de la correspondance avec le filtre, de sorte que les utilisateurs et les groupes n'ont pas besoin d'être présents sur le système local (voir l'option -M). Seuls les alias référencés par les règles de stratégie filtrées seront affichés.

-M, --match-local
Lorsque l'option -m est également spécifiée, utilisez les informations des bases de données de mots de passe et de groupes lors de la correspondance des utilisateurs et des groupes dans le filtre. Seuls les utilisateurs et les groupes du filtre qui existent sur le système local correspondront, et les groupes d'un utilisateur seront automatiquement ajoutés au filtre. Si le -M n'est pas spécifié, les utilisateurs et les groupes du filtre n'ont pas besoin d'exister sur le système local, mais tous les groupes utilisés pour la correspondance doivent être explicitement listés dans le filtre.
-o fichier_sortie, --output=fichier_sortie
Écrit la sortie convertie dans fichier_sortie. Si aucun fichier_sortie n'est spécifié, ou s'il s'agit de « - », la stratégie sudoers convertie sera écrite dans la sortie standard.
-O point_de_depart, --order-start=point_de_depart
Lors de la génération de la sortie LDIF, utilisez le nombre spécifié par point_de_depart dans l'attribut sudoOrder du premier objet sudoRole. Les objets sudoRole suivants utilisent une valeur sudoOrder générée en ajoutant un incrément, voir l'option -I pour plus de détails. Par défaut, le point de départ est 1. Un point de départ de 0 désactivera la génération des attributs sudoOrder dans le fichier LDIF résultant.
--passwd-file=fichier
Lorsque l'option -M est également spécifiée, effectue des requêtes passwd en utilisant fichier au lieu de la base de données passwd du système.
-p, --prune-matches
Lorsque l'option -m est également spécifiée, cvtsudoers éliminera les utilisateurs, groupes et hôtes ne correspondant pas des entrées correspondantes.
-P remplissage, --padding=remplissage
Lors de la génération de la sortie LDIF, construit la valeur initiale de sudoOrder en concaténant order_start et increment, en remplissant increment avec des zéros jusqu'à ce qu'il comprenne remplissage chiffres. Par exemple, si order_start est 1027, remplissage est 3 et increment est 1, la valeur de sudoOrder pour la première entrée sera 1027000, suivie de 1027001, 1027002, etc. Si le nombre d'entrées sudoRole est supérieur à ce que le remplissage permettrait, cvtsudoers se terminera avec une erreur. Par défaut, aucun remplissage n'est effectué.
-s sections, --suppress=sections
Supprime la sortie de sections spécifiques de la stratégie de sécurité. Un ou plusieurs noms de sections peuvent être spécifiés, séparés par une virgule (« , »). Les noms de sections pris en charge sont : defaults, aliases et privileges (qui peut être abrégé en privs).
-V, --version
Affiche les versions de la grammaire cvtsudoers et sudoers et quitte.

Fusionner plusieurs fichiers

Lorsque plusieurs fichiers d'entrée sont spécifiés, cvtsudoers tentera de les fusionner en un seul fichier de stratégie. On suppose que les noms d'utilisateur et de groupe sont cohérents parmi les fichiers de stratégie à fusionner. Par exemple, l'utilisateur « bob » sur un hôte est le même que l'utilisateur « bob » sur un autre hôte.

Lors de la fusion de fichiers de stratégie, il est possible de préfixer le nom du fichier d'entrée avec un nom d'hôte, séparé par un deux-points (« : »). Lorsque les fichiers sont fusionnés, le nom d'hôte sera utilisé pour restreindre les règles de stratégie à cet hôte spécifique lorsque cela est possible.

Le processus de fusion s'effectue comme suit :

  • Chaque fichier d'entrée est analysé en structures de données sudoers internes.
  • Les alias sont fusionnés et renommés si nécessaire pour éviter les conflits. En cas de conflit, le premier alias trouvé est laissé tel quel et les alias suivants du même nom sont renommés avec un suffixe numérique séparé par un trait de soulignement (« _ »). Par exemple, s'il existe deux alias différents nommés SERVERS, le premier sera laissé tel quel et le second sera renommé SERVERS_1. Les références à l'alias renommé sont également mises à jour dans le fichier de stratégie. Les alias dupliqués (ceux avec un contenu identique) sont supprimés.
  • Les paramètres Defaults sont fusionnés et les doublons sont supprimés. S'il y a des conflits dans les paramètres Defaults, un avertissement est émis pour chaque conflit. Si un nom d'hôte est spécifié avec le fichier d'entrée, cvtsudoers modifiera les paramètres globaux Defaults de ce fichier pour qu'ils soient spécifiques à l'hôte. Un avertissement est émis pour les paramètres Defaults spécifiques à la commande, à l'utilisateur ou à l'exécution qui ne peuvent pas être rendus spécifiques à l'hôte.
  • Les règles par utilisateur sont fusionnées et les doublons sont supprimés. Si un nom d'hôte est spécifié avec le fichier d'entrée, cvtsudoers modifiera les règles spécifiant un nom d'hôte de ALL pour le nom d'hôte associé au fichier de stratégie en cours de fusion. La fusion des règles est actuellement assez simpliste mais sera améliorée dans une future version.

Il est possible de fusionner des fichiers de stratégie de formats différents.

Le fichier cvtsudoers.conf

Les options sous la forme « mot-clé = valeur » peuvent également être spécifiées dans un fichier de configuration, /etc/cvtsudoers.conf par défaut. Les mots-clés suivants sont reconnus :

defaults = types_de_defauts
Voir la description de l'option de ligne de commande -d.
expand_aliases = oui | non
Voir la description de l'option de ligne de commande -e.
group_file = fichier
Voir la description de l'option de ligne de commande --group-file.
input_format = ldif | sudoers
Voir la description de l'option de ligne de commande -i.
match = filtre
Voir la description de l'option de ligne de commande -m.
match_local = oui | non
Voir la description de l'option de ligne de commande -M.
order_increment = incrément
Voir la description de l'option de ligne de commande -I.
order_start = point_de_depart
Voir la description de l'option de ligne de commande -O.
output_format = csv | json | ldif | sudoers
Voir la description de l'option de ligne de commande -f.
padding = remplissage
Voir la description de l'option de ligne de commande -P.
passwd_file = fichier
Voir la description de l'option de ligne de commande --passwd-file.
prune_matches = oui | non
Voir la description de l'option de ligne de commande -p.
sudoers_base = dn
Voir la description de l'option de ligne de commande -b.
suppress = sections
Voir la description de l'option de ligne de commande -s.

Les options sur la ligne de commande remplaceront les valeurs du fichier de configuration.

Format de sortie JSON

Le format JSON sudoers peut contenir n'importe lequel

des objets de premier niveau suivants :

Defaults
Un tableau d'objets, chacun contenant un Options tableau et un Binding tableau facultatif.

Le Options tableau est constitué d'un ou plusieurs objets, chacun contenant une paire « nom:valeur » qui correspond à un paramètre sudoers Defaults . Les Options qui opèrent sur une liste incluront également une entrée operation dans l'objet, avec la valeur « list_assign » pour «=», « list_add » pour «+=», ou « list_remove » pour «-=».

Le Binding tableau facultatif est constitué d'un ou plusieurs objets, chacun contenant une paire « nom:valeur » et une entrée negated facultative, qui annulera toute comparaison effectuée avec l'objet. Si un Binding est présent, le paramètre ne prendra effet que si l'une des entrées spécifiées command, hostname, netgroup, networkaddr, nonunixgid, nonunixgroup, usergid, usergroup, userid, usernameou d'alias correspond.

Par exemple, l'entrée sudoers suivante :

Defaults@somehost set_home, env_keep += DISPLAY

se convertit en :

"Defaults": [
    {
        "Binding": [
            { "hostname": "somehost" }
        ],
        "Options": [
            { "set_home": true },
            {
                "operation": "list_add",
                "env_keep": [
                    "DISPLAY"
                ]
            }
        ]
    }
]
User_Aliases
Un objet JSON contenant une ou plusieurs entrées sudoers User_Alias où chaque alias nommé a pour valeur un tableau contenant un ou plusieurs objets. Chaque objet contient une paire « nom:valeur » et une entrée negated facultative, qui annulera toute comparaison effectuée avec l'objet. Le nom peut être l'un des suivants netgroup, nonunixgid, nonunixgroup, useralias, usergid, usergroup, useridou username.

Par exemple, l'entrée sudoers suivante :

User_Alias SYSADMIN = will, %wheel, +admin

se convertit en :

"User_Aliases": {
    "SYSADMIN": [
        { "username": "will" },
        { "usergroup": "wheel" },
        { "netgroup": "admin" }
    ]
}
Runas_Aliases
Un objet JSON contenant une ou plusieurs entrées sudoers Runas_Alias où chaque alias nommé a pour valeur un tableau contenant un ou plusieurs objets. Chaque objet contient une paire « nom:valeur » et une entrée negated facultative, qui annulera toute comparaison effectuée avec l'objet. Le nom peut être l'un des suivants netgroup, nonunixgid, nonunixgroup, runasalias, usergid, usergroup, useridou username.

Par exemple, l'entrée sudoers suivante :

Runas_Alias DB = oracle, sybase : OP = root, operator

se convertit en :

"Runas_Aliases": {
    "DB": [
        { "username": "oracle" },
        { "username": "sybase" }
    ],
    "OP": [
        { "username": "root" },
        { "username": "operator" }
    ]
}
Host_Aliases
Un objet JSON contenant une ou plusieurs entrées sudoers Host_Alias où chaque alias nommé a pour valeur un tableau contenant un ou plusieurs objets. Chaque objet contient une paire « nom:valeur » et une entrée negated facultative, qui annulera toute comparaison effectuée avec l'objet. Le nom peut être l'un des suivants hostalias, hostname, netgroupou networkaddr.

Par exemple, les entrées sudoers suivantes :

Host_Alias DORMNET = 128.138.243.0, 128.138.204.0/24
Host_Alias SERVERS = boulder, refuge

se convertissent en :

"Host_Aliases": {
    "DORMNET": [
        { "networkaddr": "128.138.243.0" },
        { "networkaddr": "128.138.204.0/24" }
    ],
    "SERVERS": [
        { "hostname": "boulder" },
        { "hostname": "refuge" }
    ]
}
Cmnd_Aliases
Un objet JSON contenant une ou plusieurs entrées sudoers Cmnd_Alias où chaque alias nommé a pour valeur un tableau contenant un ou plusieurs objets. Chaque objet contient une paire « nom:valeur » et une entrée negated facultative, qui annulera toute comparaison effectuée avec l'objet. Le nom peut être un autre cmndalias ou une command. Par exemple, les entrées sudoers suivantes : 
Cmnd_Alias SHELLS = /bin/bash, /bin/csh, /bin/sh, /bin/zsh
Cmnd_Alias VIPW = /usr/bin/chpass, /usr/bin/chfn, /usr/bin/chsh, \
                  /usr/bin/passwd, /usr/sbin/vigr, /usr/sbin/vipw

se convertissent en :

"Cmnd_Aliases": {
    "SHELLS": [
        { "command": "/bin/bash" },
        { "command": "/bin/csh" },
        { "command": "/bin/sh" },
        { "command": "/bin/zsh" }
    ],
    "VIPW": [
        { "command": "/usr/bin/chpass" },
        { "command": "/usr/bin/chfn" },
        { "command": "/usr/bin/chsh" },
        { "command": "/usr/bin/passwd" },
        { "command": "/usr/sbin/vigr" },
        { "command": "/usr/sbin/vipw" }
    ]
}
User_Specs
Un tableau JSON contenant un ou plusieurs objets, chacun représentant une sudoers User_Spec. Chaque objet du User_Specs tableau doit contenir un User_List tableau, un Host_List tableau et un Cmnd_Specs tableau.

Un User_List est constitué d'un ou plusieurs objets. Chaque objet contient une paire « nom:valeur » et une entrée negated facultative, qui annulera toute comparaison effectuée avec l'objet. Le nom peut être l'un des suivants netgroup, nonunixgid, nonunixgroup, useralias, usergid, usergroup, useridou username. Si username est défini à la valeur spéciale ALL, il correspondra à n'importe quel utilisateur.

Un Host_List est constitué d'un ou plusieurs objets. Chaque objet contient une paire « nom:valeur » et une entrée negated facultative, qui annulera toute comparaison effectuée avec l'objet. Le nom peut être l'un des suivants hostalias, hostname, netgroupou networkaddr. Si hostname est défini à la valeur spéciale ALL, il correspondra à n'importe quel hôte.

Le Cmnd_Specs tableau est constitué d'un ou plusieurs objets JSON décrivant une commande qui peut être exécutée. Chaque Cmnd_Specs est composé d'un tableau Commands , d'un tableau runasusers facultatif, d'un tableau runasgroups facultatif et d'un tableau Options facultatif.

Le Commands tableau est constitué d'un ou plusieurs objets contenant des éléments de paire « nom:valeur ». Les noms et valeurs suivants sont pris en charge :

command
Une chaîne contenant la commande à exécuter. La valeur spéciale ALL correspondra à n'importe quelle commande.
negated
Une valeur booléenne qui, si elle est vraie, annulera toute comparaison effectuée avec l'objet.
sha224
Un ou plusieurs empreintes SHA224 pour la command sous forme de chaîne. Plusieurs empreintes du même type sont stockées sous forme de tableau.
sha256
Un ou plusieurs empreintes SHA256 pour la command sous forme de chaîne. Plusieurs empreintes du même type sont stockées sous forme de tableau.
sha384
Un ou plusieurs empreintes SHA384 pour la command sous forme de chaîne. Plusieurs empreintes du même type sont stockées sous forme de tableau.
sha512
Un ou plusieurs empreintes SHA512 pour la command sous forme de chaîne. Plusieurs empreintes du même type sont stockées sous forme de tableau.

Le runasusers tableau est constitué d'objets décrivant les utilisateurs au nom desquels la commande peut être exécutée. Chaque objet contient une paire « nom:valeur » et une entrée negated facultative, qui annulera toute comparaison effectuée avec l'objet. Le nom peut être l'un des suivants netgroup, nonunixgid, nonunixgroup, runasalias, usergid, usergroup, useridou username. Si username est défini à la valeur spéciale ALL, il correspondra à n'importe quel utilisateur. Si username est défini à la chaîne vide « », il correspondra à l'utilisateur appelant.

Le runasgroups tableau est constitué d'objets décrivant les groupes au nom desquels la commande peut être exécutée. Chaque objet contient une#"nom:valeur" paire et une entrée négativée optionnelle, qui inversera toute comparaison effectuée avec l'objet. Le nom peut être runasalias, usergid, ou usergroup. Si usergroup est défini sur la valeur spéciale ALL, il correspondra à n'importe quel groupe.

Le tableau Options est du même format que celui de l'objet Defaults. Toutes les entrées Tag_Spec dans sudoers sont converties en Options. Un utilisateur avec des privilèges « sudo ALL » aura automatiquement l'option setenv activée pour correspondre au comportement implicite fourni par sudoers.

Par exemple, l'entrée sudoers suivante :

millert ALL = (ALL : ALL) NOPASSWD: ALL, !/usr/bin/id

se convertit en :

"User_Specs": [
    {
        "User_List": [
            { "username": "millert" }
        ],
        "Host_List": [
            { "hostname": "ALL" }
        ],
        "Cmnd_Specs": [
            {
                "runasusers": [
                    { "username": "ALL" }
                ],
                "runasgroups": [
                    { "usergroup": "ALL" }
                ],
                "Options": [
                    { "authenticate": false },
                    { "setenv": true }
                ],
                "Commands": [
                    { "command": "ALL" },
                    {
                        "command": "/usr/bin/id",
                        "negated": true
                    }
                ]
            }
        ]
    }
]

Format de sortie CSV

Les fichiers CSV (valeurs séparées par des virgules) sont souvent utilisés par les tableurs et les générateurs de rapports. Pour la sortie CSV, cvtsudoers met entre guillemets doubles les chaînes qui contiennent des virgules. Pour chaque caractère de guillemet double littéral présent à l'intérieur de la chaîne, deux guillemets doubles sont générés. Cette méthode de mise entre guillemets des virgules est compatible avec la plupart des programmes tableurs.

Il y a trois sections possibles dans la sortie CSV de cvtsudoers, chacune séparée par une ligne vide :

defaults
Cette section comprend tous les paramètres Defaults dans sudoers. La section defaults commence par l'en-tête suivant : 
defaults_type,binding,name,operator,value

Les champs sont les suivants :

defaults_type
Le type de paramètre Defaults ; l'un de defaults, defaults_command, defaults_host, defaults_runas, ou defaults_user.
binding
Pour defaults_command, defaults_host, defaults_runas, et defaults_user, c'est la valeur qui doit correspondre pour que le paramètre soit appliqué.
name
Le nom du paramètre Defaults.
operator
L'opérateur détermine comment la valeur est appliquée au paramètre. Il peut être soit « = » (affectation), soit « += » (ajouter), soit « -= » (supprimer).
value
La valeur du paramètre, généralement une chaîne de caractères ou, pour les paramètres utilisés dans un contexte booléen, true ou false.
aliases
Cette section comprend toutes les entrées Cmnd_Alias, Host_Alias, Runas_Alias, ou User_Alias de sudoers. La section aliases commence par l'en-tête suivant : 
alias_type,alias_name,members

Les champs sont les suivants :

alias_type
Le type d'alias ; l'un de Cmnd_Alias, Host_Alias, Runas_Alias, ou User_Alias.
alias_name
Le nom de l'alias ; une chaîne commençant par une lettre majuscule et composée de lettres majuscules, de chiffres ou de traits de soulignement.
members
Une liste de membres appartenant à l'alias, séparés par des virgules. En raison de l'utilisation de virgules, members est entouré de guillemets doubles s'il contient plus d'un membre.
rules
Cette section comprend les règles sudoers qui accordent des privilèges. La section rules commence par l'en-tête suivant : 
rule,user,host,runusers,rungroups,options,command

Les champs sont les suivants :

rule
Ce champ indique une entrée rule de sudoers.
user
L'utilisateur auquel la règle s'applique. Il peut également s'agir d'un groupe Unix (précédé du caractère « % »), d'un groupe non-Unix (précédé de « % : ») ou d'un netgroup (précédé du caractère « + ») ou d'un User_Alias. Si défini sur la valeur spéciale ALL, il correspondra à n'importe quel utilisateur.
host
L'hôte auquel la règle s'applique. Il peut également s'agir d'un netgroup (précédé du caractère « + ») ou d'un Host_Alias. Si défini sur la valeur spéciale ALL, il correspondra à n'importe quel hôte.
runusers
Une liste facultative d'utilisateurs (ou de Runas_Alias) séparés par des virgules, sous lesquels la commande peut être exécutée. Si elle contient plus d'un membre, la valeur est entourée de guillemets doubles. Si défini sur la valeur spéciale ALL, il correspondra à n'importe quel utilisateur. Si vide, l'utilisateur root est supposé.
rungroups
Une liste facultative de groupes (ou de Runas_Alias) séparés par des virgules, sous lesquels la commande peut être exécutée. Si elle contient plus d'un membre, la valeur est entourée de guillemets doubles. Si défini sur la valeur spéciale ALL, il correspondra à n'importe quel groupe. Si vide, le groupe de runuser est utilisé.
options
Une liste facultative de paramètres Defaults à appliquer à la commande. Toutes les entrées Tag_Spec dans sudoers sont converties en options.
command
Une liste de commandes, avec des arguments facultatifs, que l'utilisateur est autorisé à exécuter. Si défini sur la valeur spéciale ALL, il correspondra à n'importe quelle commande.

Par exemple, l'entrée sudoers suivante :

millert ALL = (ALL : ALL) NOPASSWD: ALL, !/usr/bin/id

se convertit en :

rule,millert,ALL,ALL,ALL,"!authenticate","ALL,!/usr/bin/id"

EXEMPLES

Convertir /etc/sudoers au format LDIF (LDAP Data Interchange Format) où le fichier ldap.conf utilise une sudoers_base de my-domain,dc=com, en stockant le résultat dans sudoers.ldif :

$ cvtsudoers -b ou=SUDOers,dc=my-domain,dc=com -o sudoers.ldif \
             /etc/sudoers

Convertir /etc/sudoers au format JSON, en stockant le résultat dans sudoers.json :

$ cvtsudoers -f json -o sudoers.json /etc/sudoers

Analyser /etc/sudoers et afficher uniquement les règles qui correspondent à l'utilisateur ambrose sur l'hôte hastur :

$ cvtsudoers -f sudoers -m user=ambrose,host=hastur /etc/sudoers

Identique à ci-dessus, mais développer les alias et supprimer tous les utilisateurs et hôtes non correspondants des entrées développées.

$ cvtsudoers -ep -f sudoers -m user=ambrose,host=hastur /etc/sudoers

Convertir sudoers.ldif de LDIF au format traditionnel sudoers :

$ cvtsudoers -i ldif -f sudoers -o sudoers.new sudoers.ldif

Fusionner un fichier sudoers global avec deux fichiers de stratégie spécifiques à l'hôte des hôtes « xyzzy » et « plugh » :

$ cvtsudoers -f sudoers -o sudoers.merged sudoers \
    xyzzy:sudoers.xyzzy plugh:sudoers.plugh
