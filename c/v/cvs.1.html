Options de commande communes Cette section décrit les command_options qui sont disponibles pour plusieurs commandes cvs. Ces options sont toujours données à droite de cvs_command . Toutes les commandes ne prennent pas en charge toutes ces options ; chaque option n'est prise en charge que pour les commandes où elle a du sens. Cependant, lorsqu'une commande possède l'une de ces options, vous pouvez presque toujours compter sur le même comportement de l'option que dans les autres commandes. (Les autres options de commande, qui sont listées avec les commandes individuelles, peuvent avoir un comportement différent d'une

commande cvs à l'autre). La commande

history est une exception ; elle prend en charge
de nombreuses options qui entrent même en conflit avec ces options standard. -Ddate_spec Utiliser la révision la plus récente pas plus tard que date_spec

. date_spec est un argument unique, une description de date spécifiant une date passée. La spécification estcollante lorsque vous l'utilisez pour créer une copie privée d'un fichier source ; c'est-à-dire, lorsque vous récupérez un fichier de travail avec -D

Une grande variété de formats de date est prise en charge par

cvs

Les dates ISO8601 ont de nombreuses variantes mais quelques exemples sont : 1972-09-24 1972-09-24 20:05 Il existe beaucoup plus de formats de date ISO8601, et cvs

24 Sep 1972 20:05

24 Sep

La date est interprétée comme étant dans le fuseau horaire local, sauf si un fuseau horaire spécifique est spécifié. Ces deux formats de date sont préférés. Cependant, cvs accepte actuellement une grande variété d'autres formats de date. Ils ne sont volontairement pas documentés ici en détail, et les futures versions de cvs

pourraient ne pas tous les accepter. L'un de ces formats estmois/jour/année . Cela peut dérouter les personnes habituées à avoir le mois et le jour dans l'autre ordre ; 1/4/96

checkout

Extraire les sources pour édition

  • Synopsis : checkout [options] modules...
  • Nécessite : repository.
  • Modifie : working directory.
  • Synonymes : co, get

    Crée ou met à jour un répertoire de travail contenant des copies des fichiers source spécifiés par modules. Vous devez exécuter checkout avant d'utiliser la plupart des autres cvs commandes, car la plupart d'entre elles opèrent sur votre répertoire de travail.

    Les modules sont soit des noms symboliques pour certaines collections de répertoires et de fichiers source, soit des chemins vers des répertoires ou des fichiers dans le dépôt. Les noms symboliques sont définis dans le fichier modules . Voir `modules' dans le manuel CVS.

    Selon les modules que vous spécifiez, checkout peut créer récursivement des répertoires et les remplir avec les fichiers source appropriés. Vous pouvez ensuite éditer ces fichiers source à tout moment (indépendamment du fait que d'autres développeurs logiciels éditent leurs propres copies des sources) ; les mettre à jour pour inclure les nouveaux changements appliqués par d'autres au dépôt de sources ; ou enregistrer votre travail en tant que changement permanent au dépôt de sources.

    Notez que checkout est utilisé pour créer des répertoires. Le répertoire de premier niveau créé est toujours ajouté au répertoire où checkout est invoqué, et a généralement le même nom que le module spécifié. Dans le cas d'un alias de module, le sous-répertoire créé peut avoir un nom différent, mais vous pouvez être sûr qu'il s'agira d'un sous-répertoire, et que checkout affichera le chemin relatif menant à chaque fichier lorsqu'il est extrait dans votre espace de travail privé (sauf si vous spécifiez l'option -Q globale).

    Les fichiers créés par checkout sont créés en lecture-écriture, sauf si l'option -r de cvs (voir le nœud `Global options' dans le manuel CVS) est spécifiée, si la variable d'environnement CVSREAD est spécifiée (voir le nœud `Environment variables' dans le manuel CVS), ou si une surveillance est active pour ce fichier (voir le nœud `Watches' dans le manuel CVS).

    Notez que l'exécution de checkout sur un répertoire qui a déjà été construit par un checkout précédent est également autorisé. C'est similaire à spécifier l'option -d de la update commande dans le sens où les nouveaux répertoires qui ont été créés dans le dépôt apparaîtront dans votre espace de travail. Cependant, checkout prend un nom de module alors que update prend un nom de répertoire. De plus, pour utiliser checkout de cette manière, il doit être exécuté depuis le répertoire de premier niveau (où vous avez initialement exécuté checkout ), donc avant d'exécuter checkout pour mettre à jour un répertoire existant, n'oubliez pas de changer votre répertoire vers le répertoire de premier niveau.

    Pour la sortie produite par la checkout commande, voir le nœud `update output' dans le manuel CVS.

commit

Enregistrer les fichiers dans le dépôt

  • Synopsis : commit [-lRf] [-m 'log_me
  • `commit' `ci' -m message | -F file] [-r revision] [fichiers...]
  • Exigences : répertoire de travail, dépôt.
  • Modifications : dépôt.
  • Synonyme : ci

    Utilisez commit lorsque vous souhaitez intégrer les modifications de vos fichiers source de travail dans le dépôt source.

    Si vous ne spécifiez pas de fichiers particuliers à valider, tous les fichiers de votre répertoire de travail actuel sont examinés. commit veille à ne modifier dans le dépôt que les fichiers que vous avez réellement modifiés. Par défaut (ou si vous spécifiez explicitement l'option -R), les fichiers dans les sous-répertoires sont également examinés et validés s'ils ont été modifiés ; vous pouvez utiliser l'option -l pour limiter commit au répertoire courant uniquement.

    commit vérifie que les fichiers sélectionnés sont à jour par rapport aux révisions actuelles du dépôt source ; il vous notifiera, et quittera sans valider, si l'un des fichiers spécifiés doit d'abord être mis à jour avec update (voir le nœud `update' dans le manuel CVS). commit n'appelle pas la commande update pour vous, mais vous laisse le soin de le faire quand le moment est opportun.

    Lorsque tout va bien, un éditeur est invoqué pour vous permettre d'entrer un message de journalisation qui sera écrit dans un ou plusieurs programmes de journalisation (voir le nœud `modules' dans le manuel CVS, et voir le nœud `loginfo' dans le manuel CVS) et placé dans le fichier rcs à l'intérieur du dépôt. Ce message de journalisation peut être récupéré avec la commande log ; voir le nœud `log' dans le manuel CVS. Vous pouvez spécifier le message de journalisation sur la ligne de commande avec l'option -m message, et ainsi éviter l'invocation de l'éditeur, ou utiliser l'option -F fichier pour spécifier que le fichier argument contient le message de journalisation.

exemples `commit'

Valider sur une branche

Vous pouvez valider vers une révision de branche (une qui a un nombre pair de points) avec l'option -r. Pour créer une révision de branche, utilisez l'option -b des commandes rtag ou tag (voir le nœud `Branches et fusions' dans le manuel CVS). Ensuite, soit checkout soit update peut être utilisé pour baser vos sources sur la branche nouvellement créée. À partir de ce moment, toutes les modifications commit apportées dans ces sources de travail seront automatiquement ajoutées à une révision de branche, ne perturbant ainsi aucunement le développement de la ligne principale. Par exemple, si vous deviez créer un correctif pour la version 1.2 du produit, même si la version 2.0 est déjà en développement, vous pourriez faire :

$ cvs rtag -b -r FCS1_2 FCS1_2_Patch module_produit
$ cvs checkout -r FCS1_2_Patch module_produit
$ cd module_produit
[[ bidouillage ]]
$ cvs commit

Cela fonctionne automatiquement puisque l'option -r est collante.

Créer la branche après édition

Supposons que vous travailliez sur un logiciel extrêmement expérimental, basé sur la dernière révision que vous avez récupérée la semaine dernière. Si d'autres membres de votre groupe souhaitent travailler sur ce logiciel avec vous, sans perturber le développement de la ligne principale, vous pourriez valider votre modification vers une nouvelle branche. Les autres pourront alors récupérer votre matériel expérimental et bénéficier pleinement de la résolution des conflits de cvs. Le scénario pourrait ressembler à ceci :

[[ sources modifiées présentes ]]
$ cvs tag -b EXPR1
$ cvs update -r EXPR1
$ cvs commit

La commande update rendra l'option -r EXPR1 collante sur tous les fichiers. Notez que vos modifications sur les fichiers ne seront jamais supprimées par la commande update. La commit validera automatiquement sur la bonne branche, car le -r est collant. Vous pourriez aussi faire ceci :

[[ sources modifiées présentes ]]
$ cvs tag -b EXPR1
$ cvs commit -r EXPR1

mais alors, seuls les fichiers que vous avez modifiés auront l'indicateur collant -r EXPR1. Si vous modifiez, et validez sans spécifier l'indicateur -r EXPR1, certains fichiers pourraient accidentellement se retrouver sur le tronc principal.

Pour travailler avec vous sur la modification expérimentale, les autres feraient simplement :

$ cvs checkout -r EXPR1 quel_que_soit_le_module

Formats de groupe de lignes

Les formats de groupe de lignes vous permettent de spécifier des formats adaptés à de nombreuses applications qui acceptent les entrées if-then-else, y compris les langages de programmation et les langages de mise en forme de texte. Un format de groupe de lignes spécifie le format de sortie pour un groupe contigu de lignes similaires.

Par exemple, la commande suivante compare le fichier TeX myfile avec la version originale du dépôt, et produit un fichier fusionné dans lequel les anciennes régions sont entourées par des lignes \begin{em}-\end{em} , et les nouvelles régions sont entourées par des lignes \begin{bf}-\end{bf} .

cvs diff \

--old-group-format='\begin{em}
%<\end{em}
' \

--new-group-format='\begin{bf}
%>\end{bf}
' \

myfile

La commande suivante est équivalente à l'exemple ci-dessus, mais elle est un peu plus verbeuse, car elle explicite les formats de groupe de lignes par défaut.

cvs diff \

--old-group-format='\begin{em}
%<\end{em}
' \

--new-group-format='\begin{bf}
%>\end{bf}
' \

--unchanged-group-format='%=' \

--changed-group-format='\begin{em}
%<\end{em}
\begin{bf}
%>\end{bf}
' \

myfile

Voici un exemple plus avancé, qui produit une liste de diff avec des en-têtes contenant des numéros de ligne dans un style « anglais simple ».

cvs diff \

--unchanged-group-format='' \

--old-group-format='-------- %dn line%(n=1?:s) deleted at %df:
%<' \

--new-group-format='-------- %dN line%(N=1?:s) added after %de:
%>' \

--changed-group-format='-------- %dn line%(n=1?:s) changed at %df:
%<-------- to:
%>' \

myfile

Pour spécifier un format de groupe de lignes, utilisez l'une des options listées ci-dessous. Vous pouvez spécifier jusqu'à quatre formats de groupes de lignes, un pour chaque type de groupe de lignes. Vous devriez mettre formatentre guillemets, car il contient généralement des métacaractères de shell.

--old-group-format=format
Ces groupes de lignes sont des blocs contenant uniquement des lignes du premier fichier. Le format de groupe ancien par défaut est le même que le format de groupe modifié s'il est spécifié ; sinon, c'est un format qui affiche le groupe de lignes tel quel.
--new-group-format=format
Ces groupes de lignes sont des blocs contenant uniquement des lignes du deuxième fichier. Le format de groupe nouveau par défaut est le même que le format de groupe modifié s'il est spécifié ; sinon, c'est un format qui affiche le groupe de lignes tel quel.
--changed-group-format=format
Ces groupes de lignes sont des blocs contenant des lignes des deux fichiers. Le format de groupe modifié par défaut est la concaténation des formats de groupe ancien et nouveau.
--unchanged-group-format=format
Ces groupes de lignes contiennent des lignes communes aux deux fichiers. Le format de groupe inchangé par défaut est un format qui affiche le groupe de lignes tel quel.

Dans un format de groupe de lignes, les caractères ordinaires représentent eux-mêmes ; les spécifications de conversion commencent par % et ont l'une des formes suivantes.

%<
représente les lignes du premier fichier, y compris le retour à la ligne final. Chaque ligne est formatée selon le format de ligne ancien (voir le nœud « Line formats » dans le manuel CVS).
%>
représente les lignes du deuxième fichier, y compris le retour à la ligne final. Chaque ligne est formatée selon le format de ligne nouveau.
%=
représente les lignes communes aux deux fichiers, y compris le retour à la ligne final. Chaque ligne est formatée selon le format de ligne inchangé.
%%
représente %.
%c'C'
où C est un caractère unique, représente C. C ne peut pas être une barre oblique inverse ou une apostrophe. Par exemple, %c':' représente un deux-points, même à l'intérieur de la partie alors d'un format si-alors-sinon, qu'un deux-points terminerait normalement.
%c'\O'
où O est une chaîne de 1, 2 ou 3 chiffres octaux, représente le caractère de code octal O. Par exemple, %c'\0' représente un caractère nul.
Fn
où F est une printf spécification de conversion et n est l'une des lettres suivantes, représente n's valeur formatée avec F.
e
Le numéro de ligne de la ligne juste avant le groupe dans l'ancien fichier.
f
Le numéro de ligne de la première ligne du groupe dans l'ancien fichier ; égal à e + 1.
l
Le numéro de ligne de la dernière ligne du groupe dans l'ancien fichier.
m
Le numéro de ligne de la ligne juste après le groupe dans l'ancien fichier ; égal à l + 1.
n
Le nombre de lignes du groupe dans l'ancien fichier ; égal à l - f + 1.
E, F, L, M, N
De même, pour les lignes du nouveau fichier.

La printf spécification de conversion peut être %d, %o, %x, ou %X, spécifiant respectivement une sortie décimale, octale, hexadécimale en minuscules ou hexadécimale en majuscules. Après le % les options suivantes peuvent apparaître en séquence : un - spécifiant l'alignement à gauche ; un entier spécifiant la largeur minimale du champ ; et un point suivi d'un entier optionnel spécifiant le nombre minimal de chiffres. Par exemple, %5dN affiche le nombre de lignes nouvelles dans le groupe dans un champ de largeur 5 caractères, en utilisant le printf format "%5d".

(A=B?T:E)
Si A est égal à B alors T sinon E. A et B sont chacun soit une constante décimale soit une lettre unique interprétée comme ci-dessus. Cette spécification de format est équivalente à T si la valeur de A's valeur est égale à B's ; sinon elle est équivalente à E.

Par exemple, %(N=0?no:%dN) line%(N=1?:s) est équivalent à no lines si N (le nombre de lignes du groupe dans le nouveau fichier) est 0, à 1 line si N est 1, et à %dN lines sinon.

Line formats

Les formats de ligne contrôlent comment chaque ligne prise à partir d'un fichier d'entrée est affichée en tant que partie d'un groupe de lignes dans un format si-alors-sinon.

Par exemple, la commande suivante affiche du texte avec un indicateur de changement d'une colonne à gauche du texte. La première colonne de sortie est - pour les lignes supprimées, | pour les lignes ajoutées, et une espace pour les lignes inchangées. Les formats contiennent des caractères de retour à la ligne là où des retours à la ligne sont souhaités dans la sortie.

cvs diff \

--old-line-format='-%l
' \

--new-line-format='|%l
' \

--unchanged-line-format=' %l
' \

myfile

Pour spécifier un format de ligne, utilisez l'une des options suivantes. Vous devriez mettre formatentre guillemets, car il contient souvent des métacaractères de shell.

--old-line-format=format
formate les lignes uniquement du premier fichier.
--new-line-format=format
formate les lignes uniquement du deuxième fichier.
--unchanged-line-format=format
formate les lignes communes aux deux fichiers.
--line-format=format
formate toutes les lignes ; en effet, cela définit simultanément les trois options ci-dessus.

Dans un format de ligne, les caractères ordinaires représentent eux-mêmes ; les spécifications de conversion commencent par % et ont l'une des formes suivantes.

%l
représente le contenu de la ligne, sans compter son retour à la ligne final (s'il y en a un). Ce format ignore si la ligne est incomplète.
%L
représente le contenu de la ligne, y compris son retour à la ligne final (s'il y en a un). Si une ligne est incomplète, ce format préserve son caractère incomplet.
%%
représente %.
%c'C'
où C est un caractère unique, représente C. C ne peut pas être une barre oblique inverse ou une apostrophe. Par exemple, %c':' représente un deux-points.
%c'\O'
où O est une chaîne de 1, 2 ou 3 chiffres octaux, représente le caractère de code octal O. Par exemple, %c'\0' représente un caractère nul.
Fn
où F est une printf spécification de conversion, représente le numéro de ligne formaté avec F. Par exemple, %.5dn affiche le numéro de ligne en utilisant le printf format "%.5d". Voir le nœud « Line group formats » dans le manuel CVS, pour en savoir plus sur les spécifications de conversion printf.

Le format de ligne par défaut est %l suivi d'un caractère de retour à la ligne.

Si l'entrée contient des caractères de tabulation et qu'il est important qu'ils s'alignent dans la sortie, vous devriez vous assurer que %l ou %L dans un format de ligne est juste après une tabulation (par exemple en faisant précéder %l ou %L d'un caractère de tabulation), ou vous devriez utiliser l'option -t ou --expand-tabs .

Pris ensemble, les formats de ligne et de groupe de lignes vous permettent de spécifier de nombreux formats différents. Par exemple, la commande suivante utilise un format similaire au diff's format normal. Vous pouvez adapter cette commande pour obtenir un contrôle fin sur la sortie de diff.

cvs diff \

--old-line-format='< %l
' \

--new-line-format='> %l
' \

--old-group-format='%df%(f=l?:,%dl)d%dE
%<' \

--new-group-format='%dea%dF%(F=L?:,%dL)
%>' \

--changed-group-format='%df%(f=l?:,%dl)c%dF%(F=L?:,%dL)
%<—
%>' \

--unchanged-group-format='' \

myfile

La ligne suivante produit un Unidiff (-u flag) entre la révision 1.14 et 1.19 de backend.c. En raison du -kk flag, aucun mot-clé n'est substitué, donc les différences qui ne dépendent que de la substitution de mots-clés sont ignorées.

$ cvs diff -kk -u -r 1.14 -r 1.19 backend.c

Supposons que la branche expérimentale EXPR1 était basée sur un ensemble de fichiers étiquetés RELEASE_1_0. Pour voir ce qui s'est passé sur cette branche, la commande suivante peut être utilisée :

$ cvs diff -r RELEASE_1_0 -r EXPR1

Une commande telle que celle-ci peut être utilisée pour produire un diff de contexte entre deux versions :

$ cvs diff -c -r RELEASE_1_0 -r RELEASE_1_1 > diffs

Si vous maintenez des ChangeLogs, une commande comme la suivante, juste avant de valider vos modifications, peut vous aider à rédiger l'entrée du ChangeLog. Toutes les modifications locales qui n'ont pas encore été validées seront imprimées.

$ cvs diff -u | less

  • Synopsis : export [-flNnR] [-r rev|-D date] [-k subst] [-d dir] module...
  • Nécessite : le dépôt.
  • Modifie : le répertoire courant.

    Cette commande est une variante de checkout; utilisez-la lorsque vous voulez une copie des sources d'un module sans les cvs répertoires d'administration. history

Afficher l'état des fichiers et des utilisateurs

  • Synopsis : history [-report] [-flags] [-options args] [files...]
  • Nécessite : le fichier $CVSROOT/CVSROOT/history
  • Modifie : rien.

    cvs peut conserver un fichier d'historique qui suit chaque utilisation des commandes checkout, commit, rtag, update, et release . Vous pouvez utiliser history pour afficher ces informations dans divers formats.

    La journalisation doit être activée en créant le fichier $CVSROOT/CVSROOT/history.

    history utilise -f, -l, -n, et -p de manière à entrer en conflit avec leur utilisation normale à l'intérieur de cvs (voir le nœud « Options courantes » du manuel CVS).

Créer tous les répertoires qui existent dans le dépôt s'ils sont absents du répertoire de travail. Normalement, update n'agit que sur les répertoires et fichiers qui étaient déjà inscrits dans votre répertoire de travail.

Ceci est utile pour mettre à jour des répertoires qui ont été créés dans le dépôt depuis le checkout initial ; mais cela a un effet secondaire regrettable. Si vous avez délibérément évité certains répertoires dans le dépôt lorsque vous avez créé votre répertoire de travail (soit par l'utilisation d'un nom de module, soit en listant explicitement les fichiers et répertoires que vous vouliez sur la ligne de commande), alors la mise à jour avec -d créera ces répertoires, ce qui peut ne pas être ce que vous voulez.

-I nom
Ignorer les fichiers dont les noms correspondent à nom (dans votre répertoire de travail) pendant la mise à jour. Vous pouvez spécifier -I plus d'une fois sur la ligne de commande pour spécifier plusieurs fichiers à ignorer. Utilisez -I ! pour éviter d'ignorer des fichiers du tout. Voir `cvsignore' dans le manuel CVS pour d'autres façons de faire cvs ignorer certains fichiers.
-Wspec
Spécifier les noms de fichiers qui doivent être filtrés pendant la mise à jour. Vous pouvez utiliser cette option de manière répétée.

spec peut être un motif de nom de fichier du même type que celui que vous pouvez spécifier dans le .cvswrappers fichier. Voir `Wrappers' dans le manuel CVS.

-jrevision
Avec deux -j options, fusionner les modifications de la révision spécifiée avec la première -j option à la révision spécifiée avec la deuxième j option, dans le répertoire de travail.

Avec une seule -j option, fusionner les modifications de la révision ancêtre à la révision spécifiée avec l'option -j , dans le répertoire de travail. La révision ancêtre est l'ancêtre commun de la révision sur laquelle le répertoire de travail est basé, et la révision spécifiée dans l'option -j .

Notez que l'utilisation d'un seul -j tagname option plutôt que -j branchname pour fusionner les modifications d'une branche ne supprimera souvent pas les fichiers qui ont été supprimés sur la branche. Voir `Merging adds and removals' dans le manuel CVS pour plus d'informations.

De plus, chaque -j peut contenir une spécification de date facultative qui, lorsqu'elle est utilisée avec des branches, peut limiter la révision choisie à celle située dans une plage de dates spécifique. Une date facultative est spécifiée en ajoutant deux-points (:) à l'étiquette : -jÉtiquette_Symbolique:Spécification_Date.

Voir « Branching and merging » dans le manuel CVS.

Sortie de update

update et checkout vous tiennent informés de leur progression en imprimant une ligne pour chaque fichier, précédée d'un caractère indiquant l'état du fichier :

U fichier
Le fichier a été mis à jour par rapport au dépôt. Cela est fait pour tout fichier qui existe dans le dépôt mais pas dans votre répertoire de travail, et pour les fichiers que vous n'avez pas modifiés mais qui ne sont pas les versions les plus récentes disponibles dans le dépôt.
P fichier
Comme U, mais le serveur cvs envoie un patch au lieu d'un fichier entier. Cela accomplit la même chose que U en utilisant moins de bande passante.
A fichier
Le fichier a été ajouté à votre copie privée des sources, et sera ajouté au dépôt de sources lorsque vous exécuterez commit sur le fichier. C'est un rappel pour vous que le fichier doit être commité.
R fichier
Le fichier a été supprimé de votre copie privée des sources, et sera supprimé du dépôt de sources lorsque vous exécuterez commit sur le fichier. C'est un rappel pour vous que le fichier doit être commité.
M fichier
Le fichier est modifié dans votre répertoire de travail.

M peut indiquer l'un des deux états pour un fichier sur lequel vous travaillez : soit il n'y a eu aucune modification du même fichier dans le dépôt, de sorte que votre fichier reste tel que vous l'avez vu pour la dernière fois ; soit il y a eu des modifications dans le dépôt ainsi que dans votre copie, mais elles ont été fusionnées avec succès, sans conflit, dans votre répertoire de travail.

cvs imprimera quelques messages s'il fusionne votre travail, et une copie de sauvegarde de votre fichier de travail (tel qu'il était avant que vous n'ayez exécuté update) sera créée. Le nom exact de ce fichier est imprimé pendant update .

C fichier
Un conflit a été détecté lors de la tentative de fusion de vos modifications de fichier avec les modifications du dépôt de sources. fichier (la copie dans votre répertoire de travail) est maintenant le résultat de la tentative de fusion des deux révisions ; une copie non modifiée de votre fichier est également dans votre répertoire de travail, avec le nom .#fichier.révision où révision est la révision à partir de laquelle votre fichier modifié a commencé. Résolvez le conflit comme décrit dans « Conflicts example » dans le manuel CVS. (Notez que certains systèmes purgent automatiquement les fichiers qui commencent par .# s'ils n'ont pas été accédés pendant quelques jours. Si vous avez l'intention de conserver une copie de votre fichier original, il est très judicieux de le renommer.) Sous vms, le nom de fichier commence par __ plutôt que .#.
? fichier
fichier est dans votre répertoire de travail, mais ne correspond à rien dans le dépôt de sources, et n'est pas dans la liste des fichiers que cvs doit ignorer (voir la description de l'option -I , et voir le nœud « cvsignore » dans le manuel CVS).
