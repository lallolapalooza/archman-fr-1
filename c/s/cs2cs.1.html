NOM

cs2cs - Filtre de système de coordonnées cartographiques

SYNTAXE

cs2cs [-eEfIlrstvwW [args]]
[[--area <nom_ou_code>] | [--bbox <long_ouest,lat_sud,long_est,lat_nord>]]
[--authority <nom>] [--3d]
[--accuracy <précision>] [--only-best[=oui|=non]] [--no-ballpark]
[--s_epoch {époque}] [--t_epoch {époque}]
([+opt[=arg] ...] [+to +opt[=arg] ...] | {crs_source} {crs_cible})
fichier ...

où {crs_source} ou {crs_cible} est l'une des possibilités acceptées par proj_create(), à condition qu'elle exprime une SRC

  • une chaîne proj,
  • une chaîne WKT,
  • un code d'objet (comme "EPSG:4326", "urn:ogc:def:crs:EPSG::4326", "urn:ogc:def:coordinateOperation:EPSG::1671"),
  • un nom d'objet. Par exemple "WGS 84", "WGS 84 / UTM zone 31N". Dans ce cas, l'unicité n'étant pas garantie, des heuristiques sont appliquées pour déterminer la meilleure correspondance appropriée.
  • un nom de SRC et une époque de coordonnées, séparés par "@". Par exemple "ITRF2014@2025.0". (ajouté en 9.2)
  • un URN OGC combinant des références pour des systèmes de référence de coordonnées composites (par exemple "urn:ogc:def:crs,crs:EPSG::2393,crs:EPSG::5717" ou une syntaxe abrégée personnalisée "EPSG:2393+5717"),
  • un URN OGC combinant des références pour des SRC projetées ou dérivées par exemple pour une SRC 3D projetée "UTM zone 31N / WGS 84 (3D)": "urn:ogc:def:crs,crs:EPSG::4979,cs:PROJ::ENh,coordinateOperation:EPSG::16031" (ajouté en 6.2)
  • un URN OGC combinant des références pour des opérations concaténées (par exemple "urn:ogc:def:coordinateOperation,coordinateOperation:EPSG::3895,coordinateOperation:EPSG::1618")
  • une chaîne PROJJSON. Le schéma JSON est disponible à https://proj.org/schemas/v0.4/projjson.schema.json (ajouté en 6.2)
  • une SRC composite formée de deux noms d'objets séparés par " + ". par exemple "WGS 84 + EGM96 height" (ajouté en 7.1)

Ajouté dans la version 6.0.0.

NOTE :

avant 7.0.1, il était nécessaire d'ajouter +to entre {crs_source} et {crs_cible} lors de l'ajout d'un nom de fichier

DESCRIPTION

cs2cs effectue la transformation entre le système de référence de coordonnées cartographiques source et destination sur un ensemble de points d'entrée. La transformation de système de référence de coordonnées peut inclure la translation entre coordonnées projetées et géographiques ainsi que l'application des changements de datum.

Les paramètres de contrôle suivants peuvent apparaître dans n'importe quel ordre :

-I
Méthode pour spécifier la translation inverse, convertir du système de coordonnées +to vers le système de coordonnées primaire défini.
-t<a>
Où a spécifie un caractère utilisé comme premier caractère pour indiquer une ligne de contrôle à passer sans traitement. Cette option est applicable uniquement à l'entrée ASCII (Le caractère # est la valeur par défaut).
-d <n>
Ajouté dans la version 5.2.0.

Spécifie le nombre de décimales pour l'arrondi dans la sortie.

-e <chaîne>
Où chaîne est une chaîne arbitraire à afficher en cas d'erreur détectée lors des transformations de données. La valeur par défaut est une chaîne de trois caractères : *\t*.
-E
Copie les coordonnées d'entrée sur la ligne de sortie avant d'afficher les valeurs converties.
-l<[=id]>
Liste les identifiants de projection qui peuvent être sélectionnés avec +proj. cs2cs -l=id donne une description étendue de la projection id, par exemple cs2cs -l=merc.
-lp
Liste de tous les identifiants de projection qui peuvent être utilisés avec le paramètre +proj. Équivalent à cs2cs -l.
-lP
Description étendue de toutes les projections qui peuvent être utilisées avec le paramètre +proj.
-le
Liste de tous les ellipsoïdes qui peuvent être sélectionnés avec les paramètres +ellps.
-lm
Liste des méridiennes principales codées en dur qui peuvent être sélectionnées avec le paramètre +pm. Notez que cette liste n'est plus mise à jour, et que certaines valeurs peuvent entrer en conflit avec d'autres sources.
-lu
Liste de toutes les unités de distance qui peuvent être sélectionnées avec le paramètre +units.
-r
Cette option inverse l'ordre des deux premières entrées attendues par rapport à celui spécifié par la SRC vers l'ordre opposé. La troisième coordonnée, typiquement la hauteur, reste en troisième position.
-s
Cette option inverse l'ordre des deux premières sorties attendues par rapport à celui spécifié par la SRC vers l'ordre opposé. La troisième coordonnée, typiquement la hauteur, reste en troisième position.
-f <format>
Où format est une chaîne de format printf pour contrôler la forme des valeurs de sortie. Pour les projections inverses, la sortie sera en degrés lorsque cette option est utilisée. Si un format est spécifié pour une projection inverse, les données de sortie seront en degrés décimaux. Le format par défaut est "%.2f" pour la projection directe et DMS pour l'inverse.
-w<n>
Où n est le nombre de chiffres fractionnaires significatifs à utiliser pour la sortie des secondes (lorsque l'option n'est pas spécifiée, -w3 est supposé).
-W<n>
Où n est le nombre de chiffres fractionnaires significatifs à utiliser pour la sortie des secondes. Lorsque -W est utilisé, les champs auront une largeur constante avec des zéros initiaux. Plage valide : -W0 à -W8.
-v
Affiche la liste des paramètres de contrôle cartographiques testés et utilisés par le programme avant les données d'entrée.
--area <nom_ou_code>
Ajouté dans la version 8.0.0.

Spécifie une zone d'intérêt pour restreindre les résultats lors de la recherche d'opérations de coordonnées entre 2 SRC. La zone d'intérêt peut être spécifiée soit par un nom (par exemple "Danemark - onshore") soit par un AUTORITÉ:CODE (EPSG:3237)

Cette option est mutuellement exclusive avec --bbox.

--bbox <long_ouest,lat_sud,long_est,lat_nord>
Ajouté dans la version 8.0.0.

Spécifie une zone d'intérêt pour restreindre les résultats lors de la recherche d'opérations de coordonnées entre 2 SRC. La zone d'intérêt est spécifiée comme une boîte englobante avec des coordonnées géographiques, exprimées en degrés dans une SRC géographique non spécifiée. long_ouest et long_est doivent être dans la plage [-180,180], et lat_sud et lat_nord dans la plage [-90,90]. long_ouest est généralement inférieur à long_est, sauf dans le cas où la zone d'intérêt traverse l'antiméridien.

OPTIONS

--only-best[=yes|=no]
Ajouté dans la version 9.2.0.

Force cs2cs à n'utiliser que la meilleure transformation connue par PROJ. cs2cs retournera une erreur si une grille nécessaire à la meilleure transformation est manquante.

La meilleure transformation doit être comprise comme la transformation la plus précise disponible parmi toutes celles pertinentes pour le point à transformer, et si toutes les grilles connues nécessaires pour effectuer une telle transformation étaient accessibles (localement ou via le réseau).

Notez que la valeur par défaut pour cette option peut également être définie avec la variable d'environnement PROJ_ONLY_BEST_DEFAULT, ou avec le paramètre only_best_default de proj.ini (--only-best lorsqu'il est spécifié remplace la valeur par défaut).

--no-ballpark
Ajouté dans la version 8.0.0.

Interdit toute opération de coordonnées qui est, ou contient, une transformation ballpark

--accuracy <accuracy>
Ajouté dans la version 8.0.0.

Définit la précision minimale souhaitée pour les opérations de coordonnées candidates.

--authority <name>
Ajouté dans la version 8.0.0.

Cette option peut être utilisée pour restreindre l'autorité des opérations de coordonnées recherchées dans la base de données. Lorsqu'elle n'est pas spécifiée, les opérations de coordonnées de n'importe quelle autorité seront recherchées, avec les restrictions définies dans la table de base de données authority_to_authority_preference liées à l'autorité des CRS source/cible eux-mêmes. Si l'autorité est définie sur any, alors les opérations de coordonnées de n'importe quelle autorité seront recherchées. Si l'autorité est une chaîne non vide différente de any, alors les opérations de coordonnées ne seront recherchées que dans cet espace de noms d'autorité (par exemple EPSG).

Cette option est mutuellement exclusive avec --bbox.

--3d
Ajouté dans la version 9.1.

"Promouvoir" les CRS 2D à leur version 3D, où l'axe vertical est la hauteur ellipsoïdale en mètres, en utilisant l'ellipsoïde du CRS géodésique de base. Selon les versions de PROJ et la nature exacte des CRS impliqués, en particulier avant PROJ 9.1, un mélange de CRS 2D et 3D pouvait entraîner des transformations 2D ou 3D. À partir de PROJ 9.1, les deux CRS doivent être 3D pour qu'une transformation verticale puisse avoir lieu.

--s_epoch
Ajouté dans la version 9.4.

Époque des coordonnées dans le CRS source, en année décimale. S'applique uniquement à un CRS dynamique.

--t_epoch
Ajouté dans la version 9.4.

Époque des coordonnées dans le CRS cible, en année décimale. S'applique uniquement à un CRS dynamique.

Les arguments de ligne de commande +opt sont associés aux paramètres cartographiques.

Le programme cs2cs nécessite deux définitions de système de référence de coordonnées (CRS). La première (ou primaire) est définie sur la base de tous les paramètres de projection n'apparaissant pas après l'argument +to. Tous les paramètres de projection apparaissant après l'argument +to sont considérés comme la définition du second CRS. S'il n'y a pas de second CRS défini, un CRS géographique basé sur le datum et l'ellipsoïde du CRS source est supposé. Notez que le CRS source et destination peuvent être de même nature ou de nature différente (géographique, projeté, CRS composé), ou un de chaque et peuvent avoir des datums identiques ou différents.

Lors de l'utilisation d'une définition WKT ou d'un code AUTORITÉ:CODE, l'ordre des axes du CRS sera appliqué. Ainsi, par exemple, en utilisant EPSG:4326, la première valeur attendue (ou retournée) sera une latitude.

En interne, cs2cs utilise la fonction proj_create_crs_to_crs() pour calculer l'opération de coordonnées appropriée, donc les détails d'implémentation de cette fonction ont un impact direct sur les résultats retournés par le programme.

Le paramètre d'environnement PROJ_DATA établit le répertoire des fichiers de ressources (base de données, grilles de décalage de datum, etc.)

Un ou plusieurs fichiers (traités de gauche à droite) spécifient la source des données à transformer. Un - spécifiera l'emplacement de l'entrée standard de traitement. Si aucun fichier n'est spécifié, l'entrée est supposée provenir de stdin. Pour les données d'entrée, les deux valeurs de données doivent se trouver dans les deux premiers champs séparés par des espaces blancs et lorsque l'entrée et la sortie sont en ASCII, toutes les parties restantes de la ligne d'entrée sont ajoutées à la ligne de sortie.

Les données géographiques d'entrée (longitude et latitude) doivent être au format DMS ou en degrés décimaux et les données cartésiennes d'entrée doivent être dans des unités cohérentes avec les unités du demi-grand axe de l'ellipsoïde ou du rayon de la sphère. Les coordonnées géographiques de sortie seront normalement au format DMS (utilisez -f %.12f pour les degrés décimaux avec 12 décimales), tandis que les coordonnées projetées (cartésiennes) seront dans des unités linéaires (mètres, pieds).

Utilisation des grilles distantes

Ajouté dans la version 7.0.0.

Si la variable d'environnement PROJ_NETWORK est définie sur ON, cs2cs tentera d'utiliser des grilles distantes stockées sur un CDN (Content Delivery Network), lorsqu'elles ne sont pas disponibles localement.

Plus de détails sont disponibles dans la section Fonctionnalités réseau.

EXEMPLES

Utilisation des chaînes PROJ

Le script suivant

cs2cs +proj=latlong +datum=NAD83 +to +proj=utm +zone=10 +datum=NAD27 <<EOF
45°15'33.1" 111.5W
45d15.551666667N -111d30
+45.25919444444 111d30'000w
EOF

transformera les coordonnées géographiques NAD83 d'entrée en coordonnées NAD27 dans la projection UTM avec la zone 10 sélectionnée. Les valeurs géographiques de cet exemple sont équivalentes et servent d'exemples de différentes formes d'entrée DMS. Les données de sortie x-y apparaîtront sous forme de trois lignes de :

1402285.93  5076292.58 0.00

Pour obtenir ces valeurs exactes, vous devez avoir toutes les grilles actuelles installées (dans ce cas, la grille NADCON5 us_noaa_nadcon5_nad27_nad83_1986_conus.tif) localement ou utiliser les capacités réseau mentionnées ci-dessus.

Pour vous assurer d'obtenir le résultat optimal, vous pouvez ajouter --only-best. En supposant que la grille mentionnée ci-dessus n'est pas disponible,

echo -111.5 45.25919444444 | cs2cs --only-best +proj=latlong +datum=NAD83 +to +proj=utm +zone=10 +datum=NAD27

retournerait :

Tentative d'utilisation du changement d'ordre des axes de l'opération de coordonnées (2D) + Inverse de NAD27 à NAD83 (7) + changement d'ordre des axes (2D) + UTM zone 10N a échoué. La grille us_noaa_nadcon5_nad27_nad83_1986_conus.tif n'est pas disponible. Consultez https://proj.org/resource_files.html pour obtenir des instructions.
*   * inf

Sinon, si vous n'avez pas la grille disponible et que vous ne spécifiez pas --only-best :

echo -111.5 45.25919444444 | cs2cs --only-best +proj=latlong +datum=NAD83 +to +proj=utm +zone=10 +datum=NAD27

retournerait :

1402224.57  5076275.42 0.00

ce qui est le résultat lorsque les datums NAD27 et NAD83 sont traités comme identiques, ce qui est une approximation à plusieurs dizaines de mètres.

Utilisation des codes CRS EPSG

Transformation de WGS 84 latitude/longitude (dans cet ordre) vers UTM Zone 31N/WGS 84

cs2cs EPSG:4326 EPSG:32631 <<EOF
45N 2E
EOF

produit

421184.70   4983436.77 0.00

Utilisation des noms de CRS EPSG

Transformation de WGS 84 latitude/longitude (dans cet ordre) avec hauteur EGM96 vers UTM Zone 31N/WGS 84 avec hauteur ellipsoïdale WGS84

echo 45 2 0 | cs2cs "WGS 84 + EGM96 height" "WGS 84 / UTM zone 31N" --3d

produit

421184.70   4983436.77 50.69

NOTE :

Pour obtenir ces valeurs exactes, vous devez avoir la grille EGM96 installée localement ou utiliser les capacités réseau mentionnées ci-dessus.
