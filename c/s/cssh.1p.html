DESCRIPTIO

N

La commande ouvre une console d'administration et un xterm vers tous les hôtes spécifiés. Tout texte tapé dans la console d'administration est répliqué dans toutes les fenêtres. On peut également taper directement dans toutes les

fenêtres.

Cet outil est destiné (mais pas limité) à l'administration de grappes où la même configuration ou les mêmes commandes doivent être exécutées sur chaque nœud de la grappe. L'exécution de ces commandes toutes à la fois via cet outil garantit que tous les nœuds restent

synchronisés.

Les connexions sont ouvertes en utilisant ssh qui doit être correctement installé et

configuré.

Une prudence particulière doit être exercée lors de l'édition de fichiers car les lignes ne sont pas nécessairement dans le même ordre ; supposer que la ligne 5 est la même sur tous les serveurs et la modifier est dangereux. Il est préférable de rechercher la ligne spécifique à modifier et de vérifier que tous les terminaux sont comme attendu avant de valider les

modifications.

Titre des fenêtres à utiliser pour la console et les terminaux.
unmap_on_redraw = no
Demande à Tk d'utiliser la requête UnmapWindow avant de redessiner les fenêtres du terminal. Cela est par défaut à "no" car cela cause des problèmes avec le gestionnaire de fenêtres FVWM. Si vous rencontrez des problèmes avec les redessins, vous pouvez le définir sur "yes" pour permettre à la fenêtre d'être désactivée avant d'être repositionnée.
use_all_a_records = 0
Si un nom d'hôte résout plusieurs adresses IP, définissez sur 1 pour se connecter à toutes, pas seulement à la première trouvée. Voir aussi "--use-all-a-records"}
use_hotkeys = 1
Définir à 0 désactivera tous les raccourcis clavier.
use_natural_sort = 0
Les fenêtres seront normalement triées par ordre alphabétique, c'est-à-dire : host1, host11, host2. Définir sur 1 modifiera l'ordre de tri, c'est-à-dire : host1, host2, host11. REMARQUE : Vous devez avoir le module perl Sort::Naturally installé.
user = $LOGNAME
Définit l'utilisateur par défaut pour l'exécution des commandes sur les clients.
window_tiling = 1
Effectuer le placement des fenêtres en mosaïque (définir sur 0 pour désactiver)
window_tiling_direction = right
Direction pour placer les fenêtres en mosaïque, où "right" signifie commencer en haut à gauche et se déplacer vers la droite puis vers le bas, et tout autre chose signifie commencer en bas à droite et se déplacer vers la gauche puis vers le haut

REMARQUE : Les modificateurs de raccourcis clavier doivent être sous la forme "Control", "Alt" ou "Shift", par exemple avec la première lettre en majuscule et le reste en minuscules. Les touches peuvent également être désactivées individuellement en les définissant sur le mot "null".

$HOME/.clusterssh/send_menu
Ce fichier (facultatif) contient les éléments pour remplir le menu d'envoi. L'entrée par défaut pourrait être écrite comme suit : 
<send_menu>
  <menu title="Utiliser les macros">
      <toggle/>
      <accelerator>ALT-p</accelerator>
  </menu>
  <menu title="Nom d'hôte distant">
      <command>%s</command>
      <accelerator>ALT-n</accelerator>
  </menu>
  <menu title="Nom d'hôte local">
      <command>%s</command>
      <accelerator>ALT-l</accelerator>
  </menu>
  <menu title="Nom d'utilisateur">
      <command>%u</command>
      <accelerator>ALT-u</accelerator>
  </menu>
  <menu title="Texte de test">
      <command>echo "Version de ClusterSSH : %v%n</command>
  </menu>
</send_menu>

Les sous-menus peuvent également être spécifiés comme suit :

<send_menu>
  <menu title="Entrées par défaut">
    <detach>yes</detach>
    <menu title="Nom d'hôte">
        <command>%s</command>
        <accelerator>ALT-n</accelerator>
    </menu>
  </menu>
</send_menu>

Mises en garde :

Il n'y a actuellement aucune vérification de format stricte de ce fichier.
Le format du fichier peut changer à l'avenir
Si le fichier existe, l'entrée par défaut (Nom d'hôte) n'est pas ajoutée

Les macros de remplacement suivantes sont disponibles (notez qu'elles peuvent être modifiées dans le fichier de configuration) :

%s
Partie du nom d'hôte de la chaîne de connexion spécifique à chaque client, moins tout nom d'utilisateur ou port
%u
Partie du nom d'utilisateur de la chaîne de connexion à chaque client
%h
Nom d'hôte du serveur à partir duquel cssh est exécuté
%n
Code de retour "RETURN"

REMARQUE : nécessite l'installation du module XML::Simple

BUGS CONNUS

Si vous avez des idées sur la façon de corriger les bugs ci-dessous, veuillez nous contacter et/ou fournir un correctif.

•
L'échange de bureaux virtuels peut provoquer un redessin de toutes les fenêtres du terminal. Ceci est dû à un manque de distinction dans Tk entre le changement de bureau et la minimisation/maximisation des fenêtres. Tant que Tk ne pourra pas faire la différence entre les deux événements, il n'y aura pas de solution (à part réécrire tout directement en X).

DÉPANNAGE

Si vous rencontrez des problèmes pour exécuter cssh, essayez d'abord :

"cssh -e [user@]<hostname>[:port]"

Cela effectue deux tests pour confirmer que cssh peut fonctionner correctement avec les paramètres fournis dans le fichier $HOME/.clusterssh/config (ou les valeurs par défaut internes).

1.
Tester que la fenêtre du terminal fonctionne avec les options fournies
2.
Tester que ssh fonctionne vers un hôte avec les arguments configurés

Options de configuration à surveiller dans ssh :

  • SSH ne comprend pas "-o ConnectTimeout=10" - supprimez l'option du fichier $HOME/.clusterssh/config
  • OpenSSH-3.8 utilisant des tunnels ssh non fiables - utilisez au lieu de ou utilisez dans $HOME/.ssh/ssh_config (si vous modifiez les options ssh par défaut de "-x" à )
