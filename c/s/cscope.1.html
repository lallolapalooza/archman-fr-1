NAME

cscope — Un outil interactif pour explorer une base de données de code source C

SYNOPSIS

cscope [-b] [-C] [-c] [-d] [-e] [-Fpath] [-ffile] [-ifile] [-k] [-l] [-m] [-nnum] [-pnum] [-R] [-sdir] [-T] [-U] [-v] [-V] [-x] [file ...]

DESCRIPTION

Cscope est un outil interactif pour explorer une base de données de code source C. Il vous permet de rechercher des fonctions, des variables, des chaînes de caractères, des préprocesseurs, des structures, des énumérations et des typedefs. Vous pouvez également voir où une fonction est appelée ou définir une fonction, ou voir où une macro est définie.

Pour utiliser cscope, vous devez d'abord créer une base de données de votre code source. Cela se fait généralement en exécutant la commande cscope -b dans le répertoire racine de votre code source. Cela créera un fichier nommé cscope.out qui contient la base de données.

Une fois la base de données créée, vous pouvez exécuter cscope sans aucune option pour démarrer l'interface interactive. Vous verrez un menu vous permettant de choisir le type de recherche que vous souhaitez effectuer.

Voici les options disponibles pour cscope:

-b
Construit la base de données uniquement. N'exécute pas l'interface interactive.
-C
Ignore la casse lors des recherches.
-c
Utilise un ensemble d'ASCII uniquement pour la base de données.
-d
Ne fait pas de recherche en profondeur dans les répertoires indiqués.
-e
Fait un résumé de l'utilisation de la mémoire.
-Fpath
Ajoute path à la liste des chemins de recherche pour les fichiers inclus.
-ffile
Utilise file comme nom de fichier de base de données. Par défaut, cscope.out.
-ifile
Utilise file comme liste de fichiers à analyser. Par défaut, utilise file, tag et $ENV{ஸிंथेसिस}.
-k
Ignore les fichiers d'en-tête système lors de la recherche.
-l
Utilise l'interface en ligne de commande. Cela signifie que cscope recherche les symboles donnés et imprime les résultats sur la sortie standard.
-m
Affiche le nom du fichier dans la sortie de la recherche.
-nnum
Spécifie le nombre de caractères à afficher dans la colonne des fonctions dans la sortie de la recherche. Par défaut, 0 (pas de limite).
-pnum
Spécifie le nombre de chiffres de chemin à afficher dans la sortie de la recherche. Par défaut, 0 (pas de limite).
-R
Recherche récursivement dans les sous-répertoires.
-sdir
Ajoute dir à la liste des répertoires à analyser.
-T
Traite les symboles de type typedef comme des noms de variables.
-U
N'analyse pas les symboles de type typedef.
-v
Affiche le numéro de version de cscope.
-V
Affiche le numéro de version de cscope.
-x
Désactive la reconnaissance des directives de préprocesseur.

La syntaxe d'une déclaration de fonction est la suivante:

type_de_retour
nom_de_fonction ( arg_decs ) ;
type_de_retour
nom_de_fonction ( ) ;
nom_de_fonction ( arg_decs ) ;
arg_decs
peut inclure des commentaires et des espaces blancs.

Il n'est pas nécessaire qu'une déclaration de fonction commence au début d'une ligne. Le type de retour peut précéder le nom de la fonction ; cscope reconnaîtra toujours la déclaration. Les définitions de fonction qui s'écartent de cette forme ne seront pas reconnues par cscope.

La colonne « Function » de la sortie de recherche pour le champ de saisie « Find functions called by this function » n'affichera que la première fonction appelée sur la ligne, c'est-à-dire, pour cette fonction


e()
{
return (f() + g());
}

l'affichage serait


Functions called by this function: e
File Function Line
a.c f 3 return(f() + g());

Occasionnellement, une définition ou un appel de fonction peut ne pas être reconnu en raison des accolades à l'intérieur des instructions #if. De même, l'utilisation d'une variable peut être incorrectement reconnue comme une définition.

Un nom typedef précédant une instruction de préprocesseur sera incorrectement reconnu comme une définition globale, par exemple,


LDFILE *
#if AR16WR

Les instructions de préprocesseur peuvent également empêcher la reconnaissance d'une définition globale, par exemple,


char flag
#ifdef ALLOCATE_STORAGE
= -1
#endif
;

Une déclaration de fonction à l'intérieur d'une fonction est incorrectement reconnue comme un appel de fonction, par exemple,


f()
{
void g();
}

est incorrectement reconnu comme un appel à g.

cscope reconnaît les classes C++ en recherchant le mot-clé class, mais ne reconnaît pas qu'une struct est également une classe, il ne reconnaît donc pas les définitions de fonctions membres inline dans une structure. Il ne s'attend pas non plus au mot-clé class dans un typedef, il reconnaît donc incorrectement X comme une définition dans


typedef class X * Y;

Il ne reconnaît pas non plus les définitions de fonctions opérateurs


Bool Feature::operator==(const Feature & other)
{
...
}

Ni les définitions de fonctions avec un argument de pointeur de fonction


ParseTable::Recognize(int startState, char *pattern,
int finishState, void (*FinalAction)(char *))
{
...
}
