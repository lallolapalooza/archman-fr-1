NOM

csftp - Outil d'administration de cluster

VERSION

Cette documentation concerne la version : 4.16

SYNOPSIS

csftp [-a '<command>'] [-K <seconds>] [-q] [-c '<filename>'] [-x <cols>] [-C '<filename>'] [--debug [[...] || <INTEGER>]] [-d] [-e '<[user@]<host>[:port]>'] [--fillscreen] [-f '<font>'] [-h] [-L '[tag]'] [-H] [-o '<STRING>'] [-p <port>] [-Q] [-y <rows>] [-s] [-r '<filename>'] [-t '<STRING>'] [-g] [-T '<title>'] [-u] [-?] [-A] [-l '<username>'] [-v]

VOIR AUSSI

Voir également les pages man individuelles de chacune de ces utilitaires

ccon - Utiliser 'console' comme méthode de communication
crsh - Utiliser 'rsh' comme méthode de communication
cssh - Utiliser 'ssh' comme méthode de communication
ctel - Utiliser 'telnet' comme méthode de communication

DESCRIPTION

La commande ouvre une console d'administration et un xterm vers tous les hôtes spécifiés. Tout texte tapé dans la console d'administration est répliqué dans toutes les fenêtres. Il est également possible de taper directement dans toutes les fenêtres.

Cet outil est destiné (mais pas limité) à l'administration de cluster où la même configuration ou les mêmes commandes doivent être exécutées sur chaque nœud du cluster. Exécuter ces commandes toutes en même temps via cet outil garantit que tous les nœuds restent synchronisés.

Les connexions sont ouvertes en utilisant sftp qui doit être correctement installé et configuré.

Une prudence particulière doit être prise lors de la modification de fichiers car les lignes ne sont pas nécessairement dans le même ordre ; supposer que la ligne 5 est la même sur tous les serveurs et la modifier est dangereux. Il vaut mieux rechercher la ligne spécifique à modifier et vérifier que tous les terminaux sont comme attendu avant de valider les changements.

Notes supplémentaires

Veuillez également consulter « BUGS CONNUS ».

  • La ligne pointillée sur un sous-menu est un détachable, c'est-à-dire cliquez dessus et le sous-menu devient sa propre fenêtre.
  • Décocher un nom d'hôte dans le sous-menu Hôtes déconnectera l'hôte de la fenêtre de contrôle du cluster, de sorte que tout texte tapé dans la console ne sera pas envoyé à cet hôte. Le re-sélectionner le rebranchera.
  • Si les barres de menu de votre gestionnaire de fenêtres sont masquées par les fenêtres de terminal, consultez les options « screen_reserve_XXXXX » dans le fichier $HOME/.clusterssh/config (voir « FICHIERS »).
  • Si les terminaux se chevauchent trop, consultez les options « terminal_reserve_XXXXX » dans le fichier $HOME/.clusterssh/config (voir « FICHIERS »).
  • Lors de l'utilisation de ClusterSSH sur un grand nombre de systèmes pour se connecter à un système unique en utilisant un utilitaire SSH (par exemple, vous émettez une commande pour copier un fichier avec scp depuis les ordinateurs distants vers un hôte unique) et lorsque ces connexions nécessitent une authentification (c'est-à-dire que vous allez vous authentifier avec un mot de passe), le démon sshd à cet endroit peut refuser les connexions après que la limite « MaxStartups » dans sshd_config est dépassée. (Si cette valeur n'est pas définie, elle vaut par défaut 10). C'est un comportement attendu ; sshd utilise ce mécanisme pour empêcher les attaques DoS provenant de sources non authentifiées. Veuillez régler sshd_config et recharger le démon SSH, ou envisager d'utiliser le mécanisme ~/.ssh/authorized_keys pour l'authentification si vous rencontrez ce problème.
  • Si les fenêtres clientes ne s'ouvrent pas, essayez d'exécuter :

    « csftp -e {single host name} »

    Cela testera les mécanismes utilisés pour ouvrir des fenêtres vers les hôtes. Cela pourrait être dû soit à l'option de terminal « -xrm » qui active « AllowSendEvents » (certains terminaux ne nécessitent pas cette option, d'autres terminaux ont une autre méthode pour l'activer - consultez la documentation de votre terminal), soit à la configuration de « sftp ».

Direction pour le pavage des fenêtres, où "right" signifie commencer en haut à gauche et aller vers la droite puis vers le bas, et toute autre valeur signifie commencer en bas à droite et aller vers la gauche puis vers le haut.

REMARQUE : Les modificateurs de raccourcis clavier doivent être sous la forme "Control", "Alt" ou "Shift", par exemple avec la première lettre en majuscule et le reste en minuscules. Les touches peuvent également être désactivées individuellement en les réglant sur le mot "null".

$HOME/.clusterssh/send_menu
Ce fichier (optionnel) contient les éléments pour peupler le menu d'envoi. L'entrée par défaut pourrait être écrite comme suit : 
<send_menu>
  <menu title="Utiliser les macros">
      <toggle/>
      <accelerator>ALT-p</accelerator>
  </menu>
  <menu title="Nom d'hôte distant">
      <command>%s</command>
      <accelerator>ALT-n</accelerator>
  </menu>
  <menu title="Nom d'hôte local">
      <command>%s</command>
      <accelerator>ALT-l</accelerator>
  </menu>
  <menu title="Nom d'utilisateur">
      <command>%u</command>
      <accelerator>ALT-u</accelerator>
  </menu>
  <menu title="Texte de test">
      <command>echo "Version de ClusterSSH : %v%n</command>
  </menu>
</send_menu>

Les sous-menus peuvent également être spécifiés comme suit :

<send_menu>
  <menu title="Entrées par défaut">
    <detach>yes</detach>
    <menu title="Nom d'hôte">
        <command>%s</command>
        <accelerator>ALT-n</accelerator>
    </menu>
  </menu>
</send_menu>

Mises en garde :

Il n'y a actuellement aucun contrôle de format strict de ce fichier.
Le format du fichier peut changer à l'avenir.
Si le fichier existe, l'entrée par défaut (Nom d'hôte) n'est pas ajoutée.

Les macros de remplacement suivantes sont disponibles (notez qu'elles peuvent être modifiées dans le fichier de configuration) :

%s
Partie nom d'hôte de la chaîne de connexion spécifique à chaque client, moins l'utilisateur ou le port.
%u
Partie nom d'utilisateur de la chaîne de connexion à chaque client.
%h
Nom d'hôte du serveur sur lequel cssh est exécuté.
%n
Code de code "RETURN".

REMARQUE : nécessite que XML::Simple soit installé.

BUGS CONNUS

Si vous avez des idées sur la façon de corriger les bugs ci-dessous, veuillez nous contacter et/ou fournir un patch.

•
L'échange de bureaux virtuels peut provoquer un redessin de toutes les fenêtres du terminal. Ceci est dû à un manque de distinction dans Tk entre le changement de bureau et la minimisation/maximisation des fenêtres. Tant que Tk ne pourra pas faire la différence entre les deux événements, il n'y aura pas de solution (à part réécrire tout directement en X).

DEPANNAGE

Si vous rencontrez des problèmes pour exécuter csftp, essayez d'abord :

"csftp -e [utilisateur@]<nom_hote>[:port]"

Ceci effectue deux tests pour confirmer que cssh peut fonctionner correctement avec les paramètres fournis dans le fichier $HOME/.clusterssh/config (ou les valeurs par défaut internes).

1.
Tester que la fenêtre du terminal fonctionne avec les options fournies.
2.
Tester que sftp fonctionne vers un hôte avec les arguments configurés.

Options de configuration à surveiller dans ssh :

  • SSH ne comprend pas "-o ConnectTimeout=10" - supprimez l'option du fichier $HOME/.clusterssh/config.
  • OpenSSH-3.8 utilisant des tunnels ssh non fiables - utilisez "-Y" au lieu de "-X" ou utilisez "ForwardX11Trusted yes" dans $HOME/.ssh/ssh_config (si vous changez les options ssh par défaut de "-x" à "-X").
