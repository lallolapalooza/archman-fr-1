DESCRIPTIO

N

La commande csharp est un shell et un hôte de scriptage C# interactif qui permet à l'utilisateur de saisir et d'évaluer des instructions et des expressions C# depuis la ligne de commande ou d'exécuter des scripts C#. Les options habituelles de la ligne de commande de mcs peuvent être utilisées dans cette version du

compilateur.

Les fichiers spécifiés dans la ligne de commande seront chargés et exécutés comme des

scripts.

À partir de Mono 2.10, la commande csharp peut être utilisée comme interpréteur exécuté par des exécutables marqués avec l'attribut d'exécution Unix. Pour cela, faites en sorte que la première ligne de votre code source C# ressemble à ceci

: 
  #!/usr/bin/csharp
  Console.WriteLine ("Hello, World")
;

À partir de Mono 5.0, les arguments de la ligne de commande peuvent désormais être passés à la commande csharp en spécifiant soit l'option -s soit l'option -- (script)

.

L'option -s est idéale pour interpréter des scripts exécutables qui utilisent la syntaxe shebang (introduite dans Mono 2.10). Cela permet de passer des arguments de la ligne de commande au script et qu'ils soient consommés proprement

: 
  #!/usr/bin/csharp -s
  foreach (var arg in Args)
    Console.WriteLine ($"script argument: {arg}
")
;

OPTION

S

Les commandes acceptent toutes les commandes disponibles pour la commande mcs, vous pouvez donc référencer des assemblages, spécifier des chemins, le niveau de langue, etc. depuis la ligne de commande. De plus, les options de ligne de commande suivantes sont prises en charge

:
-s
FICHIER_SCRIPT
Cette option est idéale pour créer des scripts exécutables qui utilisent la fonctionnalité shebang Unix. Unix ajoutera implicitement en argument le chemin du script à exécuter. Lorsque l'exécutable est invoqué, tous les arguments qui lui sont passés seront disponibles dans la variable globale Args. Exemple : #!/usr/bin/env csharp
-s
-
-
Tous les arguments qui suivront ne seront pas passés au pilote du compilateur, mais seront mis à disposition dans la variable globale Args. Exemple : csharp -- a b c donnera Args = { "a", "b", "c" } dans le shell
interactif.
--atta
ch
Il s'agit d'une option avancée et elle ne doit être utilisée que si vous avez une compréhension approfondie du multithreading. Cette option est disponible sur la commande csharp et permet d'injecter le compilateur dans d'autres processus. Cela se fait en injectant le shell C# dans un thread séparé qui s'exécute en parallèle avec votre application. Cela signifie que vous devez prendre des mesures spéciales pour éviter de faire planter l'application cible tout en l'utilisant. Par exemple, vous devrez peut-être prendre les verrous appropriés avant d'émettre des commandes qui pourraient affecter l'état du processus cible, ou envoyer des commandes via un dispatcheur de
méthodes.
-e
EXPRESSION

C# spécifiée
et quittera.

FONCTIONNEMEN

T

Une fois que vous lancez la commande csharp, vous êtes accueilli par l'invite interactive

: 
$ csharp
Mono C# Shell, tapez "help;" pour l'aide
Entrez les instructions ci-dessous.
csharp>

Un certain nombre de noms d'espace sont prédéfinis en C#, notamment System, System.Linq, System.Collections et System.Collections.Generic. Contrairement au mode compilé, il est possible d'ajouter de nouvelles instructions using au fur et à mesure que vous tapez du code, par exemple

: 
csharp> new XmlDocument ();
<interactive>(1,6): erreur CS0246: Le type ou le nom d'espace 'XmlDocument' est introuvable. Vous manque-t-il une directive using ou une référence à un assemblage ?
csharp> using System.Xml;
csharp> new XmlDocument (); 
System.Xml.
XmlDocument

Chaque fois qu'une commande est tapée, la portée de cette commande est celle d'une classe qui dérive de la classe Mono.CSharp.InteractiveBase. Cette classe définit un certain nombre de propriétés et de méthodes statiques. Pour afficher une liste des commandes disponibles, accédez à la propriété `help'

: 
csharp> help;
"Méthodes statiques :
  LoadPackage (pkg); - Charge le paquet donné (comme -pkg:FILE)
  [...]
  ShowVars ();       - Affiche les variables locales définies.
  ShowUsing ();      - Affiche les déclarations using actives.
  help;
"
csharp>

Lorsque des expressions sont saisies, le shell C# affiche le résultat de l'exécution de l'expression

: 
csharp> Math.Sin (Math.PI/4); 
0.707106781186547
csharp> 1+1;
2
csharp> "Hello, world".IndexOf (',');
5

Le shell C# utilise la méthode ToString() sur l'objet retourné pour afficher l'objet, ce qui peut parfois être limitant car les objets qui ne redéfinissent pas la méthode ToString() utiliseront le comportement par défaut de System.Object, qui se contente d'afficher leur nom de type

: 
csharp> var a = new XmlDocument ();
csharp> a;
System.Xml.Document
csharp> csharp> a.Name;    
"#document"
csharp>

Quelques types de données sont traités spécialement par le shell interactif C#, comme les tableaux, System.Collections.Hashtable, les objets qui implémentent System.Collections.IEnumerable et IDictionary, et sont rendus spécifiquement au lieu d'utiliser simplement ToString()

: 
csharp> var pages = new Hashtable () { 
      >  { "Mono",    "http://www.mono-project.com/" },
      >  { "Linux",   "http://kernel.org" } };
csharp> pages;
{{ "Mono", "http://www.mono-project.com/" }, { "Linux", "http://kernel.org" }
}

Il est possible d'utiliser LINQ directement dans le shell interactif C# car l'espace de noms System.Linq a été importé au démarrage. L'exemple suivant obtient la liste de tous les fichiers qui n'ont pas été accédés depuis une semaine depuis /tmp

: 
csharp> using System.IO;
csharp> var last_week = DateTime.Now - TimeSpan.FromDays (7);
csharp> var old_files = from f in Directory.GetFiles ("/tmp") 
      >   let fi = new FileInfo (f) 
      >   where fi.LastAccessTime < LastWeek select f;
csharp>

Vous pouvez bien sûr imprimer les résultats dans une seule instruction aussi

: 
csharp> using System.IO;
csharp> var last_week = DateTime.Now - TimeSpan.FromDays (7);
csharp> from f in Directory.GetFiles ("/tmp") 
      >   let fi = new FileInfo (f) 
      >   where fi.LastAccessTime < last_week select f;
[...]
csharp>

LINQ et ses fondements fonctionnels produisent du code à la demande pour les valeurs de retour IEnumerable. Par exemple, la valeur de retour d'une utilisation de `from' est un IEnumerable qui est évalué à la demande. Le rendu automatique des IEnumerable sur la ligne de commande déclenchera l'exécution du pipeline IEnumerable à ce moment-là au lieu de retarder son exécution jusqu'à un moment

ultérieur.

Si vous souhaitez éviter que le IEnumerable soit rendu à ce moment, assignez simplement la valeur à une

variable.

Contrairement au C# compilé, le type d'une variable peut être changé si une nouvelle déclaration est entrée, par exemple

: 
csharp> var a = 1;
csharp> a.GetType ();
System.Int32
csharp> var a = "Hello";
csharp> a.GetType ();
System.String
csharp> ShowVars ();
string a =
"Hello"

Si une expression ou une instruction n'est pas terminée sur une seule ligne, une invite de continuation est affichée, par exemple

: 
csharp> var protocols = new string [] {
      >    "ftp",
      >    "http",
      >    "gopher" 
      > };
csharp> protocols;
{ "ftp", "http", "gopher"
}

Les calculs de longue durée peuvent être interrompus en utilisant la séquence Control-C

: 
csharp> var done = false;
csharp> while (!done) { }
Interrompu !
System.Threading.ThreadAbortException
: Le thread était en cours d'abandon at Class1.Host (System.Object& $retval) [0x00000] at Mono.C
Sharp.InteractiveShell.ExecuteBlock (Mono.CSharp.Class host, Mono.CSharp.Undo undo) [0x00000] csharp>

MÉTHODES ET PROPRIÉTÉS DE L'INTERFACE

GRAPHIQUE

En plus des méthodes et propriétés disponibles dans la version console, il existe quelques propriétés supplémentaires disponibles dans

la version de l'interface graphique. Par exemple, un "PaneContainer" Gtk.Container est exposé que vous pouvez utiliser pour héberger
des widgets Gtk# lors du prototypage, ou la propriété "MainWindow" qui vous donne accès à la fenêtre de niveau supérieur actuelle.

FICHIERS DE

DÉMARRAGE

Le shell C# chargera tous les assemblages Mono et les fichiers de script C# situés dans le répertoire ~/.config/csharp sur Unix. Les assemblages sont chargés avant que les fichiers source ne soient

chargés.

Les fichiers de script C# sont des fichiers ayant l'extension .cs et ils ne doivent contenir que des instruction

s et des expressions, ils ne peuvent pas contenir de définitions de classe complètes (au moins pas à partir de
Mono 2.0). Les définitions de classe complètes doivent être compilées en dll et stockées dans ce répertoire.
