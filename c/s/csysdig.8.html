NOM

csysdig - l'interface utilisateur ncurses pour sysdig

SYNTAXE

csysdig [option]... [filtre]

DESCRIPTION

csysdig exporte les fonctionnalités de sysdig via une interface utilisateur intuitive et puissante basée sur ncurses.

csysdig a été conçu pour imiter des outils comme top et htop, mais il offre des fonctionnalités plus riches, notamment :

•
Prise en charge de l'analyse en direct et des fichiers de trace sysdig. Les fichiers de trace peuvent provenir de la même machine ou d'une autre.
•
Visibilité sur un large éventail de métriques, y compris le CPU, la mémoire, les E/S disque, les E/S réseau.
•
Capacité à observer l'activité d'entrée/sortie pour les processus, les fichiers, les connexions réseau et plus encore.
•
Capacité à explorer en profondeur les processus, les fichiers, les connexions réseau et plus encore pour examiner leur comportement.
•
Support complet de la personnalisation.
•
Prise en charge du langage de filtrage de sysdig.
•
Prise en charge des conteneurs par conception.

csysdig fonctionne sur n'importe quel terminal, et prend en charge les couleurs et les entrées de souris.

Vues

csysdig est basé sur le concept de « vues », de petits scripts Lua qui déterminent comment les métriques sont collectées, traitées et représentées à l'écran. Inclure une nouvelle visualisation dans csysdig ne nécessite pas de mettre à jour le programme, et il suffit d'ajouter une nouvelle vue. Les vues s'appuient sur le moteur de traitement de sysdig, et cela signifie qu'elles peuvent inclure n'importe quel champ de filtre sysdig. Les vues sont situées dans le chemin du répertoire des burins de sysdig, généralement /usr/share/sysdig/chisels et ~/.chisels.

UTILISATION DE BASE

Voici quelques conseils de base pour commencer avec sysdig :

1.
Si vous exécutez csysdig sans arguments, il affichera les données système en direct, se mettant à jour toutes les 2 secondes. Pour analyser un fichier de trace, utilisez l'option de ligne de commande -r.
2.
Vous pouvez passer à une vue différente en utilisant la touche F2.
3.
Vous pouvez explorer une sélection en cliquant sur Entrée. Vous pouvez revenir en arrière en tapant Retour arrière.
4.
Vous pouvez observer les entrées/sorties de l'entité actuellement sélectionnée en tapant F5
5.
Vous pouvez voir les événements sysdig pour l'entité actuellement sélectionnée en tapant F6

EXPLORER EN PROFONDEUR

Vous explorez en profondeur en sélectionnant un élément dans une vue et en cliquant ensuite sur Entrée. Une fois à l'intérieur d'une sélection, vous pouvez passer à une vue différente, et la nouvelle vue sera appliquée dans le contexte de la sélection. Par exemple, si vous explorez en profondeur un processus appelé foo et que vous passez ensuite à la vue Connexions, la sortie inclura uniquement les connexions effectuées ou reçues par foo.

Pour explorer en profondeur plusieurs fois, continuez à cliquer sur Entrée. Par exemple, vous pouvez cliquer sur un conteneur dans la vue Conteneurs pour obtenir les processus qui y sont exécutés, puis cliquer sur l'un des processus pour voir ses threads.

ACTIONS ET RACCaccourcis

Chaque vue a une liste de commandes qui peuvent être exécutées dans le contexte de la sélection actuelle en appuyant sur des « raccourcis ». Par exemple, appuyer sur 'k' dans la vue Processus tue le processus sélectionné, appuyer sur 'b' dans la vue Conteneurs ouvre un shell bash dans le conteneur sélectionné.

Chaque vue prend en charge différentes actions. Vous pouvez voir quelles actions une vue prend en charge en appuyant sur F8. Vous pouvez personnaliser les actions de la vue en modifiant le fichier Lua de la vue.

PRISE EN CHARGE DES CONTENEURS

Lancer csysdig avec l'option de ligne de commande -pc fera en sorte que plusieurs vues incluent des informations supplémentaires sur les conteneurs. Par exemple, la vue Processus inclura une colonne montrant le conteneur auquel le processus appartient. De même, la vue Connexions indiquera à quel conteneur appartient chaque connexion.

UTILISATION DE LA SOURIS

•
Cliquer sur les en-têtes de colonne permet de trier le tableau.
•
Double-cliquer sur les entrées de ligne effectue une exploration en profondeur.
•
Cliquer sur la chaîne de filtre en haut de l'écran (le texte après 'Filtre:') permet de modifier le filtre sysdig et de personnaliser le contenu de la vue.
•
Vous pouvez utiliser la souris sur les entrées du menu en bas de l'écran pour effectuer les actions correspondantes.

-K btfile | certfile:keyfile[#password][:cacertfile], --k8s-api-cert=_btfile | certfile:keyfile[#password][:cacertfile]_ Utilise les noms de fichiers fournis pour authentifier l'utilisateur et (optionnellement) vérifier l'identité du serveur API K8S. Notez que le format de cette option de ligne de commande interdit l'utilisation de fichiers dont les noms contiennent les caractères ':' ou '#'. -m url[,marathon-url], --mesos-api=_url[,marathon-url]_ Active le support de Mesos en se connectant au serveur API spécifié comme argument (par ex. http://admin:password@127.0.0.1:5050). L'URL de Mesos est requise. L'URL de Marathon est optionnelle, par défaut elle est en mode auto-suivi - si le serveur API de Marathon n'est pas fourni, csysdig essaiera de récupérer (et de suivre ensuite, s'il migre) l'emplacement du serveur API de Marathon depuis le maître Mesos. Notez qu'avec l'auto-suivi, csysdig recevra probablement une adresse IP interne au cluster pour le serveur API de Marathon, de sorte que l'exécution de csysdig avec l'auto-suivi de Marathon depuis un nœud qui ne fait pas partie du cluster Mesos peut ne pas fonctionner. De plus, l'exécution de csysdig avec le support de Mesos sur un nœud qui n'a pas de conteneurs gérés par Mesos est d'une utilité limitée car, bien que les métadonnées du cluster soient collectées, il n'y aura aucune capacité de filtrage Mesos/Marathon. Les serveurs API peuvent également être spécifiés via la variable d'environnement SYSDIG_MESOS_API

PERSONNALISATION DE

CSYSDIG

csysdig est entièrement personnalisable. Cela signifie que vous pouvez modifier n'importe laquelle des vues de csysdig, et même créer vos propres vues. Comme les ciseaux de sysdig, les vues de csysdig sont des scripts Lua. Des informations complètes peuvent être trouvées sur la page du wiki github suivante : https://github.com/draios/sysdig/wiki/csysdig-View-Format-Referenc
