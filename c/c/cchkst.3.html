!>
!> CCHKST vérifie les routines du problème de valeurs propres hermitiennes.
!>
!>    CHETRD décompose A en  U S U* , où * signifie la transposée conjuguée,
!>    S est une matrice tridiagonale symétrique réelle, et U est unitaire.
!>    CHETRD peut utiliser soit uniquement le triangle inférieur soit uniquement le triangle supérieur
!>    de A ; CCHKST vérifie les deux cas.
!>    U est représenté comme un produit de transformations
!>    de Householder, dont les vecteurs sont stockés dans les
!>    premières colonnes de V, et dont les facteurs d'échelle sont dans TAU.
!>
!>    CHPTRD fait la même chose que CHETRD, sauf que A et V sont stockés
!>    au format .
!>
!>    CUNGTR construit la matrice U à partir du contenu de V et TAU.
!>
!>    CUPGTR construit la matrice U à partir du contenu de VP et TAU.
!>
!>    CSTEQR décompose S en  Z D1 Z* , où Z est la matrice
!>    unitaire des vecteurs propres et D1 est une matrice diagonale avec
!>    les valeurs propres sur la diagonale.  D2 est la matrice des
!>    valeurs propres calculée lorsque Z n'est pas calculé.
!>
!>    SSTERF calcule D3, la matrice des valeurs propres, par la
!>    méthode PWK, qui ne produit pas de vecteurs propres.
!>
!>    CPTEQR décompose S en  Z4 D4 Z4* , pour une
!>    matrice tridiagonale hermitienne définie positive.
!>    D5 est la matrice des valeurs propres calculée lorsque Z n'est pas
!>    calculé.
!>
!>    SSTEBZ calcule des valeurs propres sélectionnées.  WA1, WA2, et
!>    WA3 désigneront des valeurs propres calculées avec une
!>    haute précision absolue, avec différentes options de plage.
!>    WR désignera des valeurs propres calculées avec une haute précision
!>    relative.
!>
!>    CSTEIN calcule Y, les vecteurs propres de S, étant donné les
!>    valeurs propres.
!>
!>    CSTEDC décompose S en Z D1 Z* , où Z est la matrice
!>    unitaire des vecteurs propres et D1 est une matrice diagonale avec
!>    les valeurs propres sur la diagonale (option 'I'). Elle peut aussi
!>    mettre à jour une matrice unitaire en entrée, généralement la sortie
!>    de CHETRD/CUNGTR ou CHPTRD/CUPGTR (option 'V'). Elle peut
!>    aussi simplement calculer les valeurs propres (option 'N').
!>
!>    CSTEMR décompose S en Z D1 Z* , où Z est la matrice
!>    unitaire des vecteurs propres et D1 est une matrice diagonale avec
!>    les valeurs propres sur la diagonale (option 'I').  CSTEMR
!>    utilise la représentation robuste relative (Relatively Robust Representation) chaque fois que possible.
!>
!> Lorsque CCHKST est appelé, un certain nombre de tailles de matrices  () et un
!> certain nombre de types de matrices  sont spécifiés.  Pour chaque taille ()
!> et chaque type de matrice, une matrice sera générée et utilisée
!> pour tester les routines propres hermitiennes.  Pour chaque matrice, un certain
!> nombre de tests seront effectués :
!>
!> (1)     | A - V S V* | / ( |A| n ulp ) CHETRD( UPLO='U', ... )
!>
!> (2)     | I - UV* | / ( n ulp )        CUNGTR( UPLO='U', ... )
!>
!> (3)     | A - V S V* | / ( |A| n ulp ) CHETRD( UPLO='L', ... )
!>
!> (4)     | I - UV* | / ( n ulp )        CUNGTR( UPLO='L', ... )
!>
!> (5-8)   Identique à 1-4, mais pour CHPTRD et CUPGTR.
!>
!> (9)     | S - Z D Z* | / ( |S| n ulp ) CSTEQR('V',...)
!>
!> (10)    | I - ZZ* | / ( n ulp )        CSTEQR('V',...)
!>
!> (11)    | D1 - D2 | / ( |D1| ulp )        CSTEQR('N',...)
!>
!> (12)    | D1 - D3 | / ( |D1| ulp )        SSTERF
!>
!> (13)    0 si les valeurs propres réelles (calculées par le comptage de Sturm)
!>         de S sont à moins de THRESH de
!>         celles dans D1.  2*THRESH sinon.  (Testé en utilisant
!>         SSTECH)
!>
!> Pour S définie positive,
!>
!> (14)    | S - Z4 D4 Z4* | / ( |S| n ulp ) CPTEQR('V',...)
!>
!> (15)    | I - Z4 Z4* | / ( n ulp )        CPTEQR('V',...)
!>
!> (16)    | D4 - D5 | / ( 100 |D4| ulp )       CPTEQR('N',...)
!>
!> Lorsque S est également diagonalement dominante par le facteur gamma < 1,
!>
!> (17)    max | D4(i) - WR(i) | / ( |D4(i)| omega ) ,
!>          i
!>         omega = 2 (2n-1) ULP (1 + 8 gamma**2) / (1 - gamma)**4
!>                                              SSTEBZ( 'A', 'E', ...)
!>
!> (18)    | WA1 - D3 | / ( |D3| ulp )          SSTEBZ( 'A', 'E', ...)
!>
!> (19)    ( max { min | WA2(i)-WA3(j) | } +
!>            i     j
!>           max { min | WA3(i)-WA2(j) | } ) / ( |D3| ulp )
!>            i     j
!>                                              SSTEBZ( 'I', 'E', ...)
!>
!> (20)    | S - Y WA1 Y* | / ( |S| n ulp )  SSTEBZ, CSTEIN
!>
!> (21)    | I - Y Y* | / ( n ulp )          SSTEBZ, CSTEIN
!>
!> (22)    | S - Z D Z* | / ( |S| n ulp )    CSTEDC('I')
!>
!> (23)    | I - ZZ* | / ( n ulp )           CSTEDC('I')
!>
!> (24)    | S - Z D Z* | / ( |S| n ulp )    CSTEDC('V')
!>
!> (25)    | I - ZZ* | / ( n ulp )           CSTEDC('V')
!>
!> (26)    | D1 - D2 | / ( |D1| ulp )           CSTEDC('V') et
!>                                              CSTEDC('N')
!>
!> Le test 27 est actuellement désactivé car CSTEMR ne
!> garantit pas une haute précision relative.
!>
!> (27)    max | D6(i) - WR(i) | / ( |D6(i)| omega ) ,
!>          i
!>         omega = 2 (2n-1) ULP (1 + 8 gamma**2) / (1 - gamma)**4
!>                                              CSTEMR('V', 'A')
!>
!> (28)    max | D6(i) - WR(i) | / ( |D6(i)| omega ) ,
!>          i
!>         omega = 2 (2n-1) ULP (1 + 8 gamma**2) / (1 - gamma)**4
!>                                              CSTEMR('V', 'I')
!>
!> Les tests 29 à 34 sont actuellement désactivés car CSTEMR
!> ne gère pas les demandes de spectre partiel.
!>
!> (29)    | S - Z D Z* | / ( |S| n ulp )    CSTEMR('V', 'I')
!>
!> (30)    | I - ZZ* | / ( n ulp )           CSTEMR('V', 'I')
!>
!> (31)    ( max { min | WA2(i)-WA3(j) | } +
!>            i     j
!>           max { min | WA3(i)-WA2(j) | } ) / ( |D3| ulp )
!>            i     j
!>         CSTEMR('N', 'I') vs. CSTEMR('V', 'I')
!>
!> (32)    | S - Z D Z* | / ( |S| n ulp )    CSTEMR('V', 'V')
!>
!> (33)    | I - ZZ* | / ( n ulp )           CSTEMR('V', 'V')
!>
!> (34)    ( max { min | WA2(i)-WA3(j) | } +
!>            i     j
!>           max { min | WA3(i)-WA2(j) | } ) / ( |D3| ulp )
!>            i     j
!>         CSTEMR('N', 'V') vs. CSTEMR('V', 'V')
!>
!> (35)    | S - Z D Z* | / ( |S| n ulp )    CSTEMR('V', 'A')
!>
!> (36)    | I - ZZ* | / ( n ulp )           CSTEMR('V', 'A')
!>
!> (37)    ( max { min | WA2(i)-WA3(j) | } +
!>            i     j
!>           max { min | WA3(i)-WA2(j) | } ) / ( |D3| ulp )
!>            i     j
!>         CSTEMR('N', 'A') vs. CSTEMR('V', 'A')
!>
!> Les tailles sont spécifiées par un tableau NN(1:NSIZES) ; la valeur de
!> chaque élément NN(j) spécifie une taille.
!> Les types sont spécifiés par un tableau logique DOTYPE( 1:NTYPES );
!> si DOTYPE(j) est .TRUE., alors le type de matrice j sera généré.
!> Actuellement, la liste des types possibles est :
!>
!> (1)  La matrice nulle.
!> (2)  La matrice identité.
!>
!> (3)  Une matrice diagonale avec des entrées espacées uniformément
!>      1, ..., ULP et des signes aléatoires.
!>      (ULP = (premier nombre plus grand que 1) - 1 )
!> (4)  Une matrice diagonale avec des entrées espacées géométriquement
!>      1, ..., ULP et des signes aléatoires.
!> (5)  Une matrice diagonale avec des entrées 1, ULP, ..., ULP
!>      et des signes aléatoires.
!>
!> (6)  Identique à (4), mais multipliée par SQRT( seuil de débordement )
!> (7)  Identique à (4), mais multipliée par SQRT( seuil de dépassement négatif )
!>
!> (8)  Une matrice de la forme U* D U, où U est unitaire et
!>      D a des entrées espacées uniformément 1, ..., ULP avec des signes
!>      aléatoires sur la diagonale.
!>
!> (9)  Une matrice de la forme U* D U, où U est unitaire et
!>      D a des entrées espacées géométriquement 1, ..., ULP avec des signes
!>      aléatoires sur la diagonale.
!>
!> (10) Une matrice de la forme U* D U, où U est unitaire et
!>      D a des entrées 1, ULP,..., ULP avec des signes
!>      aléatoires sur la diagonale.
!>
!> (11) Identique à (8), mais multipliée par SQRT( seuil de débordement )
!> (12) Identique à (8), mais multipliée par SQRT( seuil de dépassement négatif )
!>
!> (13) Matrice hermitienne avec des entrées aléatoires choisies dans (-1,1).
!> (14) Identique à (13), mais multipliée par SQRT( seuil de débordement )
!> (15) Identique à (13), mais multipliée par SQRT( seuil de dépassement négatif )
!> (16) Identique à (8), mais les éléments diagonaux sont tous positifs.
!> (17) Identique à (9), mais les éléments diagonaux sont tous positifs.
!> (18) Identique à (10), mais les éléments diagonaux sont tous positifs.
!> (19) Identique à (16), mais multipliée par SQRT( seuil de débordement )
!> (20) Identique à (16), mais multipliée par SQRT( seuil de dépassement négatif )
!> (21) Une matrice tridiagonale à diagonale dominante avec des entrées
!>      diagonales espacées géométriquement 1, ..., ULP.
!>

Paramètres

NSIZES 
!>          NSIZES est INTEGER
!>          Le nombre de tailles de matrices à utiliser. S'il vaut zéro,
!>          CCHKST ne fait rien. Il doit être au moins zéro.
!>

NN

!>          NN est un tableau INTEGER de dimension (NSIZES)
!>          Un tableau contenant les tailles à utiliser pour les matrices.
!>          Les valeurs nulles seront ignorées. Les valeurs doivent être
!>          au moins zéro.
!>

NTYPES

!>          NTYPES est INTEGER
!>          Le nombre d'éléments dans DOTYPE. S'il vaut zéro, CCHKST
!>          ne fait rien. Il doit être au moins zéro. S'il vaut MAXTYP+1
!>          et que NSIZES vaut 1, alors un type supplémentaire, MAXTYP+1, est
!>          défini, qui consiste à utiliser la matrice présente dans A.
!>          Cela n'est utile que si DOTYPE(1:MAXTYP) est .FALSE. et
!>          DOTYPE(MAXTYP+1) est .TRUE. .
!>

DOTYPE

!>          DOTYPE est un tableau LOGICAL de dimension (NTYPES)
!>          Si DOTYPE(j) est .TRUE., alors pour chaque taille dans NN, une
!>          matrice de cette taille et de type j sera générée.
!>          Si NTYPES est inférieur au nombre maximal de types
!>          défini (PARAMÈTRE MAXTYP), les types NTYPES+1 à
!>          MAXTYP ne seront pas générés. Si NTYPES est supérieur
!>          à MAXTYP, DOTYPE(MAXTYP+1) à DOTYPE(NTYPES)
!>          seront ignorés.
!>

ISEED

!>          ISEED est un tableau INTEGER de dimension (4)
!>          À l'entrée, ISEED spécifie la graine du générateur de nombres
!>          aléatoires. Les éléments du tableau doivent être compris entre 0 et 4095 ;
!>          sinon, ils seront réduits modulo 4096. De plus, ISEED(4) doit
!>          être impair. Le générateur de nombres aléatoires utilise une suite
!>          linéaire congruentielle limitée à de petits entiers, et doit donc
!>          produire des nombres aléatoires indépendants de la machine. Les
!>          valeurs de ISEED sont modifiées à la sortie et peuvent être utilisées dans le
!>          prochain appel à CCHKST pour continuer la même suite de nombres
!>          aléatoires.
!>

THRESH

!>          THRESH est REAL
!>          Un test sera considéré comme échoué si le , calculé comme
!>          décrit ci-dessus, dépasse THRESH. Notez que l'erreur
!>          est mise à l'échelle pour être O(1), donc THRESH doit être un multiple
!>          raisonnablement petit de 1, p. ex., 10 ou 100. En particulier,
!>          il ne doit pas dépendre de la précision (simple vs. double)
!>          ni de la taille de la matrice. Il doit être au moins zéro.
!>

NOUNIT

!>          NOUNIT est INTEGER
!>          Le numéro d'unité FORTRAN pour imprimer les messages d'erreur
!>          (p. ex., si une routine retourne IINFO différent de 0).
!>

A

!>          A est un tableau COMPLEX de
!>                                  dimension ( LDA , max(NN) )
!>          Utilisé pour stocker la matrice dont les valeurs propres sont à
!>          calculer. À la sortie, A contient la dernière matrice réellement
!>          utilisée.
!>

LDA

!>          LDA est INTEGER
!>          La dimension principale de A. Elle doit être
!>          au moins 1 et au moins max( NN ).
!>

AP

!>          AP est un tableau COMPLEX de
!>                      dimension( max(NN)*max(NN+1)/2 )
!>          La matrice A stockée au format compact.
!>

SD

!>          SD est un tableau REAL de
!>                             dimension( max(NN) )
!>          La diagonale de la matrice tridiagonale calculée par CHETRD.
!>          À la sortie, SD et SE contiennent la forme tridiagonale de la
!>          matrice dans A.
!>

SE

!>          SE est un tableau REAL de
!>                             dimension( max(NN) )
!>          La sous-diagonale de la matrice tridiagonale calculée par
!>          CHETRD. À la sortie, SD et SE contiennent la forme tridiagonale de
!>          la matrice dans A.
!>

D1

!>          D1 est un tableau REAL de
!>                             dimension( max(NN) )
!>          Les valeurs propres de A, telles que calculées par CSTEQR simultanément
!>          avec Z. À la sortie, les valeurs propres dans D1 correspondent à la
!>          matrice dans A.
!>

D2

!>          D2 est un tableau REAL de
!>                             dimension( max(NN) )
!>          Les valeurs propres de A, telles que calculées par CSTEQR si Z n'est pas
!>          calculé. À la sortie, les valeurs propres dans D2 correspondent à
!>          la matrice dans A.
!>

D3

!>          D3 est un tableau REAL de
!>                             dimension( max(NN) )
!>          Les valeurs propres de A, telles que calculées par SSTERF. À la sortie, les
!>          valeurs propres dans D3 correspondent à la matrice dans A.
!>

D4

!>          D4 est un tableau REAL de
!>                             dimension( max(NN) )
!>          Les valeurs propres de A, telles que calculées par CPTEQR(V).
!>          ZPTEQR décompose S en  Z4 D4 Z4*
!>          À la sortie, les valeurs propres dans D4 correspondent à la matrice dans A.
!>

D5

!>          D5 est un tableau REAL de
!>                             dimension( max(NN) )
!>          Les valeurs propres de A, telles que calculées par ZPTEQR(N)
!>          quand Z n'est pas calculé. À la sortie, les
!>          valeurs propres dans D4 correspondent à la matrice dans A.
!>

WA1

!>          WA1 est un tableau REAL de
!>                             dimension( max(NN) )
!>          Toutes les valeurs propres de A, calculées avec une
!>          précision absolue élevée, avec différentes options de plage.
!>          telles que calculées par SSTEBZ.
!>

WA2

!>          WA2 est un tableau REAL de
!>                             dimension( max(NN) )
!>          Valeurs propres sélectionnées de A, calculées avec une
!>          précision absolue élevée, avec différentes options de plage.
!>          telles que calculées par SSTEBZ.
!>          Choisir des valeurs aléatoires pour IL et IU, et demander les
!>          valeurs propres de la IL-ième à la IU-ième.
!>

WA3

!>          WA3 est un tableau REAL de
!>                             dimension( max(NN) )
!>          Valeurs propres sélectionnées de A, calculées avec une
!>          précision absolue élevée, avec différentes options de plage.
!>          telles que calculées par SSTEBZ.
!>          Déterminer les valeurs VL et VU de la IL-ième et de la IU-ième
!>          valeurs propres et demander toutes les valeurs propres dans cette plage.
!>

WR

!>          WR est un tableau DOUBLE PRECISION de
!>                             dimension( max(NN) )
!>          Toutes les valeurs propres de A, calculées avec une
!>          précision absolue élevée, avec différentes options.
!>          telles que calculées par DSTEBZ.
!>

U

!>          U est un tableau COMPLEX de
!>                             dimension( LDU, max(NN) ).
!>          La matrice unitaire calculée par CHETRD + CUNGTR.
!>

LDU

!>          LDU est INTEGER
!>          La dimension principale de U, Z et V. Elle doit être au moins 1
!>          et au moins max( NN ).
!>

V

!>          V est un tableau COMPLEX de
!>                             dimension( LDU, max(NN) ).
!>          Les vecteurs de Householder calculés par CHETRD en réduisant A à
!>          la forme tridiagonale. Les vecteurs calculés avec UPLO='U' sont
!>          dans le triangle supérieur, et les vecteurs calculés avec UPLO='L'
!>          sont dans le triangle inférieur. (Comme décrit dans CHETRD, la
!>          sous-diagonale et la sur-diagonale ne sont pas mises à 1, bien que le
!>          vrai vecteur de Householder ait un 1 à cette position. Les
!>          routines qui utilisent V, comme CUNGTR, mettent ces entrées à
!>          1 avant de les utiliser, puis les restaurent plus tard.)
!>

VP

!>          VP est un tableau COMPLEX de
!>                      dimension( max(NN)*max(NN+1)/2 )
!>          La matrice V stockée au format compact.
!>

TAU

!>          TAU est un tableau COMPLEX de
!>                             dimension( max(NN) )
!>          Les facteurs de Householder calculés par CHETRD en réduisant A
!>          à la forme tridiagonale.
!>

Z

!>          Z est un tableau COMPLEX de
!>                             dimension( LDU, max(NN) ).
!>          La matrice unitaire des vecteurs propres calculée par CSTEQR,
!>          CPTEQR et CSTEIN.
!>

WORK

!>          WORK est un tableau COMPLEX de
!>                      dimension( LWORK )
!>

LWORK

!>          LWORK est INTEGER
!>          Le nombre d'entrées dans WORK. Il doit être au moins
!>          1 + 4 * Nmax + 2 * Nmax * lg Nmax + 3 * Nmax**2
!>          oùre Nmax = max( NN(j), 2 ) et lg = log base 2.
!
>

IWOR

K 
!>          IWORK est un tableau INTEGER,
!>          Espace de travail.
!
>

LIWOR

K 
!>          LIWORK est INTEGER
!>          Le nombre d'entrées dans IWORK.  Doit être au moins
!>                  6 + 6*Nmax + 5 * Nmax * lg Nmax
!>          où Nmax = max( NN(j), 2 ) et lg = log base 2.
!
>

RWOR

K 
!>          RWORK est un tableau REAL
!
>

LRWOR

K 
!>          LRWORK est INTEGER
!>          Le nombre d'entrées dans LRWORK (dimension( ??? )
!
>

RESUL

T 
!>          RESULT est un tableau REAL, dimension (26)
!>          Les valeurs calculées par les tests décrits ci-dessus.
!>          Les valeurs sont actuellement limitées à 1/ulp, pour
!>          éviter un débordement.
!
>

INF

O 
!>          INFO est INTEGER
!>          Si 0, tout s'est déroulé correctement.
!>           -1: NSIZES < 0
!>           -2: Certains NN(j) < 0
!>           -3: NTYPES < 0
!>           -5: THRESH < 0
!>           -9: LDA < 1 ou LDA < NMAX, où NMAX est max( NN(j) ).
!>          -23: LDU < 1 ou LDU < NMAX.
!>          -29: LWORK trop petit.
!>          Si CLATMR, CLATMS, CHETRD, CUNGTR, CSTEQR, SSTERF,
!>              ou CUNMC2 renvoie un code d'erreur, la
!>              valeur absolue de celui-ci est renvoyée.
!>
!>-----------------------------------------------------------------------
!>
!>       Quelques variables et paramètres locaux :
!>       ---- ----- --------- --- ----------
!>       ZERO, ONE       Réels 0 et 1.
!>       MAXTYP          Le nombre de types définis.
!>       NTEST           Le nombre de tests effectués, ou qui peuvent
!>                       l'être jusqu'ici, pour la matrice courante.
!>       NTESTT          Le nombre total de tests effectués jusqu'ici.
!>       NBLOCK          Taille de bloc renvoyée par ENVIR.
!>       NMAX            La plus grande valeur dans NN.
!>       NMATS           Le nombre de matrices générées jusqu'ici.
!>       NERRS           Le nombre de tests qui ont dépassé THRESH
!>                       jusqu'ici.
