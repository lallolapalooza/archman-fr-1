NOM

ccmake - Référence de commande en mode dialogue ncurses de CMake

SYNTAXE

ccmake [<options>] -B <chemin-vers-build> [-S <chemin-vers-source>]
ccmake [<options>] <chemin-vers-source | chemin-vers-build-existant>

DESCRIPTION

L'exécutable ccmake est l'interface ncurses de CMake. Les paramètres de configuration du projet peuvent être spécifiés de manière interactive via cette interface graphique. Des instructions brèves sont fournies en bas du terminal lorsque le programme est en cours d'exécution.

CMake est un générateur de système de build multiplateforme. Les projets spécifient leur processus de construction avec des fichiers CMake indépendants de la plateforme, inclus dans chaque répertoire d'un arbre source sous le nom CMakeLists.txt. Les utilisateurs construisent un projet en utilisant CMake pour générer un système de build pour un outil natif sur leur plateforme.

OPTIONS

-S <chemin-vers-source>
Chemin vers le répertoire racine du projet CMake à construire.
-B <chemin-vers-build>
Chemin vers le répertoire que CMake utilisera comme racine du répertoire de construction.

Si le répertoire n'existe pas déjà, CMake le créera.

-C <cache-initial>
Charger un script pour pré-remplir le cache.

Lorsque CMake est exécuté pour la première fois dans un répertoire de build vide, il crée un fichier CMakeCache.txt et le remplit avec des paramètres personnalisables pour le projet. Cette option peut être utilisée pour spécifier un fichier à partir duquel charger des entrées de cache avant le premier passage dans les fichiers CMake du projet. Les entrées chargées ont la priorité sur les valeurs par défaut du projet. Le fichier donné doit être un script CMake contenant des commandes set() <#command:set> utilisant l'option CACHE, et non un fichier au format cache.

Les références à CMAKE_SOURCE_DIR <#variable:CMAKE_SOURCE_DIR> et CMAKE_BINARY_DIR <#variable:CMAKE_BINARY_DIR> dans le script s'évaluent comme les répertoires source et de build de niveau supérieur.

-D <var>:<type>=<valeur>, -D <var>=<valeur>
Créer ou mettre à jour une entrée de CACHE CMake.

Lorsque CMake est exécuté pour la première fois dans un répertoire de build vide, il crée un fichier CMakeCache.txt et le remplit avec des paramètres personnalisables pour le projet. Cette option peut être utilisée pour spécifier un paramètre qui a la priorité sur la valeur par défaut du projet. L'option peut être répétée pour autant d'entrées de CACHE que désiré.

Si la partie :<type> est donnée, elle doit être l'un des types spécifiés dans la documentation de la commande set() <#command:set> pour sa signature CACHE. Si la partie :<type> est omise, l'entrée sera créée sans type si elle n'existe pas déjà avec un type. Si une commande dans le projet définit le type sur PATH ou FILEPATH, alors la <valeur> sera convertie en chemin absolu.

Cette option peut aussi être donnée comme un seul argument : -D<var>:<type>=<valeur> ou -D<var>=<valeur>.

Il est important de noter que l'ordre des arguments -C et -D est significatif. Ils seront exécutés dans l'ordre où ils sont listés, le dernier argument ayant la priorité sur les précédents. Par exemple, si vous spécifiez -DCMAKE_BUILD_TYPE=Debug, suivi d'un argument -C avec un fichier qui appelle :

set(CMAKE_BUILD_TYPE "Release" CACHE STRING "" FORCE)

alors l'argument -C aura la priorité, et CMAKE_BUILD_TYPE sera défini sur Release. Cependant, si l'argument -D vient après l'argument -C, il sera défini sur Debug.

Si un appel set(... CACHE ...) dans le fichier -C n'utilise pas FORCE, et qu'un argument -D définit la même variable, l'argument -D aura la priorité quelle que soit l'ordre en raison de la nature des appels set(... CACHE ...) non-FORCE.

-U <expression-globale>
Supprimer les entrées correspondantes du CACHE CMake.

Cette option peut être utilisée pour supprimer une ou plusieurs variables du fichier CMakeCache.txt, les expressions globales utilisant * et ? sont supportées. L'option peut être répétée pour autant d'entrées de CACHE que désiré.

Utilisez avec précaution, vous pourriez rendre votre CMakeCache.txt non fonctionnel.

-G <nom-du-generateur>
Spécifier un générateur de système de build.

CMake peut supporter plusieurs systèmes de build natifs sur certaines plateformes. Un générateur est responsable de la génération d'un système de build particulier. Les noms de générateurs possibles sont spécifiés dans le manuel cmake-generators(7) <#manuel:cmake-generators(7)>.

Si non spécifié, CMake vérifie la variable d'environnement CMAKE_GENERATOR <#envvar:CMAKE_GENERATOR> et sinon utilise une sélection par défaut intégrée.

-T <spec-outillage>
Spécification de l'ensemble d'outils pour le générateur, si supporté.

Certains générateurs CMake supportent une spécification d'ensemble d'outils pour indiquer au système de build natif comment choisir un compilateur. Voir la variable CMAKE_GENERATOR_TOOLSET <#variable:CMAKE_GENERATOR_TOOLSET> pour plus de détails.

-A <nom-plateforme>
Spécifier le nom de la plateforme si supporté par le générateur.

Certains générateurs CMake supportent un nom de plateforme à fournir au système de build natif pour choisir un compilateur ou un SDK. Voir la variable CMAKE_GENERATOR_PLATFORM <#variable:CMAKE_GENERATOR_PLATFORM> pour plus de détails.

--toolchain <chemin-vers-fichier>
Ajouté dans la version 3.21.

Spécifie le fichier de chaîne d'outils pour la compilation croisée, équivalent à définir la variable CMAKE_TOOLCHAIN_FILE <#variable:CMAKE_TOOLCHAIN_FILE>. Les chemins relatifs sont interprétés comme relatifs au répertoire de build, et s'ils ne sont pas trouvés, relatifs au répertoire source.

--install-prefix <répertoire>
Ajouté dans la version 3.21.

Spécifie le répertoire d'installation, utilisé par la variable CMAKE_INSTALL_PREFIX <#variable:CMAKE_INSTALL_PREFIX>. Doit être un chemin absolu.

--project-file <nom-fichier-projet>
Ajouté dans la version 4.0.

Spécifie un nom de fichier de projet alternatif.

Ceci détermine le fichier de haut niveau traité par CMake lors de la configuration d'un projet, et le fichier traité par add_subdirectory() <#command:add_subdirectory>.

Par défaut, il s'agit de CMakeLists.txt. Si réglé sur autre chose, CMakeLists.txt sera utilisé comme solution de secours chaque fois que le fichier spécifié ne pourra pas être trouvé dans un sous-répertoire du projet.

Remarque :

Cette fonctionnalité est destinée à une utilisation temporaire par les développeurs lors d'une transition incrémentale et non à la publication d'un produit final. CMake émettra toujours un avertissement lorsque le fichier de projet est autre que CMakeLists.txt.
