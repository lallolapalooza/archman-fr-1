CCHKST2STG

But :

!>
!> CCHKST2STG  vérifie les routines de problème de valeurs propres hermitiennes
!> en utilisant les techniques de réduction en 2 étapes. Comme la génération
!> de Q ou des vecteurs n'est pas disponible dans cette version, nous comparons uniquement
!> la valeur propre résultante de l'utilisation de la 2 étapes à
!> celle considérée comme référence en utilisant la réduction standard en 1 étape
!> CHETRD. Pour cela, nous appelons CHETRD standard et calculons D1 en utilisant
!> DSTEQR, puis nous appelons CHETRD_2STAGE standard avec Upper et Lower
!> et nous calculons D2 et D3 en utilisant DSTEQR et nous remplaçons ensuite les tests
!> 3 et 4 par les tests 11 et 12. Les tests 1 et 2 restent pour vérifier que
!> les résultats de la 1 étape sont corrects et peuvent être fiables.
!> Cette routine de test convergera vers CCHKST dans la prochaine
!> version lorsque les vecteurs et la génération de Q seront implémentés.
!>
!>    CHETRD factorise A en  U S U* , où * signifie transconjugué,
!>    S est symétrique tridiagonale réelle, et U est unitaire.
!>    CHETRD peut utiliser soit seulement le triangle inférieur, soit seulement le triangle
!>    supérieur de A ; CCHKST2STG vérifie les deux cas.
!>    U est représenté comme un produit de transformations de Householder
!>    dont les vecteurs sont stockés dans les n-1 premières colonnes de V, et dont les facteurs d'échelle sont dans TAU.
!>
!>    CHPTRD fait la même chose que CHETRD, sauf que A et V sont stockés
!>    au format .
!>
!>    CUNGTR construit la matrice U à partir du contenu de V et TAU.
!>
!>    CUPGTR construit la matrice U à partir du contenu de VP et TAU.
!>
!>    CSTEQR factorise S en  Z D1 Z* , où Z est la matrice unitaire
!>    des vecteurs propres et D1 est une matrice diagonale avec
!>    les valeurs propres sur la diagonale.  D2 est la matrice des
!>    valeurs propres calculées lorsque Z n'est pas calculée.
!>
!>    SSTERF calcule D3, la matrice des valeurs propres, par la
!>    méthode PWK, qui ne produit pas de vecteurs propres.
!>
!>    CPTEQR factorise S en  Z4 D4 Z4* , pour une
!>    matrice tridiagonale hermitienne définie positive.
!>    D5 est la matrice des valeurs propres calculées lorsque Z n'est pas
!>    calculée.
!>
!>    SSTEBZ calcule des valeurs propres sélectionnées.  WA1, WA2 et
!>    WA3 représenteront les valeurs propres calculées avec une haute précision
!>    absolue, avec différentes options de plage.
!>    WR représentera les valeurs propres calculées avec une haute précision
!>    relative.
!>
!>    CSTEIN calcule Y, les vecteurs propres de S, étant donné les
!>    valeurs propres.
!>
!>    CSTEDC factorise S en Z D1 Z* , où Z est la matrice unitaire
!>    des vecteurs propres et D1 est une matrice diagonale avec
!>    les valeurs propres sur la diagonale (option 'I'). Il peut aussi
!>    mettre à jour une matrice unitaire d'entrée, généralement le résultat
!>    de CHETRD/CUNGTR ou CHPTRD/CUPGTR (option 'V'). Il peut aussi
!>    simplement calculer des valeurs propres (option 'N').
!>
!>    CSTEMR factorise S en Z D1 Z* , où Z est la matrice unitaire
!>    des vecteurs propres et D1 est une matrice diagonale avec
!>    les valeurs propres sur la diagonale (option 'I').  CSTEMR
!>    utilise la Représentation Relativement Robuste chaque fois que possible.
!>
!> Lorsque CCHKST2STG est appelée, un certain nombre de matrices () et un
!> certain nombre de matrices () sont spécifiés.  Pour chaque taille ()
!> et chaque type de matrice, une matrice sera générée et utilisée
!> pour tester les routines de valeurs propres hermitiennes.  Pour chaque matrice, un certain nombre
!> de tests seront effectués :
!>
!> (1)     | A - V S V* | / ( |A| n ulp ) CHETRD( UPLO='U', ... )
!>
!> (2)     | I - UV* | / ( n ulp )        CUNGTR( UPLO='U', ... )
!>
!> (3)     | A - V S V* | / ( |A| n ulp ) CHETRD( UPLO='L', ... )
!>         remplacé par | D1 - D2 | / ( |D1| ulp ) où D1 est la
!>         matrice des valeurs propres calculée en utilisant S et D2 est la
!>         matrice des valeurs propres calculée en utilisant S_2stage, le résultat de
!>         CHETRD_2STAGE(, ,....). D1 et D2 sont calculés
!>         via DSTEQR('N',...)
!>
!> (4)     | I - UV* | / ( n ulp )        CUNGTR( UPLO='L', ... )
!>         remplacé par | D1 - D3 | / ( |D1| ulp ) où D1 est la
!>         matrice des valeurs propres calculée en utilisant S et D3 est la
!>         matrice des valeurs propres calculée en utilisant S_2stage, le résultat de
!>         CHETRD_2STAGE(, ,....). D1 et D3 sont calculés
!>         via DSTEQR('N',...)
!>
!> (5-8)   Identique à 1-4, mais pour CHPTRD et CUPGTR.
!>
!> (9)     | S - Z D Z* | / ( |S| n ulp ) CSTEQR('V',...)
!>
!> (10)    | I - ZZ* | / ( n ulp )        CSTEQR('V',...)
!>
!> (11)    | D1 - D2 | / ( |D1| ulp )        CSTEQR('N',...)
!>
!> (12)    | D1 - D3 | / ( |D1| ulp )        SSTERF
!>
!> (13)    0 si les vraies valeurs propres (calculées par comptage de Sturm)
!>         de S sont à moins de THRESH de
!>         celles dans D1.  2*THRESH si ce n'est pas le cas.  (Testé en utilisant
!>         SSTECH)
!>
!> Pour S définie positive,
!>
!> (14)    | S - Z4 D4 Z4* | / ( |S| n ulp ) CPTEQR('V',...)
!>
!> (15)    | I - Z4 Z4* | / ( n ulp )        CPTEQR('V',...)
!>
!> (16)    | D4 - D5 | / ( 100 |D4| ulp )       CPTEQR('N',...)
!>
!> Lorsque S est également à dominante diagonale par le facteur gamma < 1,
!>
!> (17)    max | D4(i) - WR(i) | / ( |D4(i)| omega ) ,
!>          i
!>         omega = 2 (2n-1) ULP (1 + 8 gamma**2) / (1 - gamma)**4
!>                                              SSTEBZ( 'A', 'E', ...)
!>
!> (18)    | WA1 - D3 | / ( |D3| ulp )          SSTEBZ( 'A', 'E', ...)
!>
!> (19)    ( max { min | WA2(i)-WA3(j) | } +
!>            i     j
!>           max { min | WA3(i)-WA2(j) | } ) / ( |D3| ulp )
!>            i     j
!>                                              SSTEBZ( 'I', 'E', ...)
!>
!> (20)    | S - Y WA1 Y* | / ( |S| n ulp )  SSTEBZ, CSTEIN
!>
!> (21)    | I - Y Y* | / ( n ulp )          SSTEBZ, CSTEIN
!>
!> (22)    | S - Z D Z* | / ( |S| n ulp )    CSTEDC('I')
!>
!> (23)    | I - ZZ* | / ( n ulp )           CSTEDC('I')
!>
!> (24)    | S - Z D Z* | / ( |S| n ulp )    CSTEDC('V')
!>
!> (25)    | I - ZZ* | / ( n ulp )           CSTEDC('V')
!>
!> (26)    | D1 - D2 | / ( |D1| ulp )           CSTEDC('
V') et !> CSTEDC('N') !> !> Le test 27 est actuellement désactivé car CSTEMR ne !> garantit pas une précision relative élevée. !> !> (27) max | D6(i) - WR(i) | / ( |D6(i)| omega ) , !> i !> omega = 2 (2n-1) ULP (1 + 8 gamma**2) / (1 - Paramètres

NSIZES 
!>          NSIZES est INTEGER
!>          Le nombre de tailles de matrices à utiliser. S'il est zéro,
!>          CCHKST2STG ne fait rien. Il doit être au moins zéro.
!>

NN

!>          NN est un tableau INTEGER, dimension (NSIZES)
!>          Un tableau contenant les tailles à utiliser pour les matrices.
!>          Les valeurs nulles seront ignorées. Les valeurs doivent être
!>          au moins zéro.
!>

NTYPES

!>          NTYPES est INTEGER
!>          Le nombre d'éléments dans DOTYPE. S'il est zéro, CCHKST2STG
!>          ne fait rien. Il doit être au moins zéro. S'il vaut MAXTYP+1
!>          et que NSIZES vaut 1, alors un type supplémentaire, MAXTYP+1, est
!>          défini, qui consiste à utiliser quelle que soit la matrice dans A. Ceci
!>          n'est utile que si DOTYPE(1:MAXTYP) est .FALSE. et
!>          DOTYPE(MAXTYP+1) est .TRUE. .
!>

DOTYPE

!>          DOTYPE est un tableau LOGICAL, dimension (NTYPES)
!>          Si DOTYPE(j) est .TRUE., alors pour chaque taille dans NN, une
!>          matrice de cette taille et de type j sera générée.
!>          Si NTYPES est plus petit que le nombre maximal de types
!>          défini (PARAMÈTRE MAXTYP), alors les types NTYPES+1 à
!>          MAXTYP ne seront pas générés. Si NTYPES est plus grand
!>          que MAXTYP, DOTYPE(MAXTYP+1) à DOTYPE(NTYPES)
!>          seront ignorés.
!>

ISEED

!>          ISEED est un tableau INTEGER, dimension (4)
!>          À l'entrée, ISEED spécifie la graine du générateur de nombres
!>          aléatoires. Les éléments du tableau doivent être compris entre 0 et 4095 ;
!>          sinon, ils seront réduits modulo 4096. De plus, ISEED(4) doit
!>          être impair. Le générateur de nombres aléatoires utilise une suite
!>          linéaire congruentielle limitée à de petits entiers, et doit donc
!>          produire des nombres aléatoires indépendants de la machine. Les
!>          valeurs de ISEED sont modifiées à la sortie, et peuvent être utilisées dans le
!>          prochain appel à CCHKST2STG pour continuer la même suite de nombres
!>          aléatoires.
!>

THRESH

!>          THRESH est REAL
!>          Un test sera considéré comme un échec si l'erreur, calculée comme
!>          décrit ci-dessus, dépasse THRESH. Notez que l'erreur
!>          est mise à l'échelle pour être O(1), donc THRESH doit être un multiple
!>          raisonnablement petit de 1, p. ex., 10 ou 100. En particulier,
!>          il ne doit pas dépendre de la précision (simple vs. double)
!>          ni de la taille de la matrice. Il doit être au moins zéro.
!>

NOUNIT

!>          NOUNIT est INTEGER
!>          Le numéro d'unité FORTRAN pour l'affichage des messages d'erreur
!>          (p. ex., si une routine retourne IINFO différent de 0.)
!>

A

!>          A est un tableau COMPLEX de
!>                                  dimension ( LDA , max(NN) )
!>          Utilisé pour contenir la matrice dont les valeurs propres sont à
!>          calculer. À la sortie, A contient la dernière matrice effectivement
!>          utilisée.
!>

LDA

!>          LDA est INTEGER
!>          La dimension principale de A. Elle doit être
!>          au moins 1 et au moins max( NN ).
!>

AP

!>          AP est un tableau COMPLEX de
!>                      dimension( max(NN)*max(NN+1)/2 )
!>          La matrice A stockée au format compact (packed).
!>

SD

!>          SD est un tableau REAL de
!>                             dimension( max(NN) )
!>          La diagonale de la matrice tridiagonale calculée par CHETRD.
!>          À la sortie, SD et SE contiennent la forme tridiagonale de la
!>          matrice dans A.
!>

SE

!>          SE est un tableau REAL de
!>                             dimension( max(NN) )
!>          La sous-diagonale de la matrice tridiagonale calculée par
!>          CHETRD. À la sortie, SD et SE contiennent la forme tridiagonale de
!>          la matrice dans A.
!>

D1

!>          D1 est un tableau REAL de
!>                             dimension( max(NN) )
!>          Les valeurs propres de A, telles que calculées par CSTEQR simultanément
!>          avec Z. À la sortie, les valeurs propres dans D1 correspondent avec la
!>          matrice dans A.
!>

D2

!>          D2 est un tableau REAL de
!>                             dimension( max(NN) )
!>          Les valeurs propres de A, telles que calculées par CSTEQR si Z n'est pas
!>          calculé. À la sortie, les valeurs propres dans D2 correspondent avec
!>          la matrice dans A.
!>

D3

!>          D3 est un tableau REAL de
!>                             dimension( max(NN) )
!>          Les valeurs propres de A, telles que calculées par SSTERF. À la sortie, les
!>          valeurs propres dans D3 correspondent avec la matrice dans A.
!>

D4

!>          D4 est un tableau REAL de
!>                             dimension( max(NN) )
!>          Les valeurs propres de A, telles que calculées par CPTEQR(V).
!>          CPTEQR décompose S en  Z4 D4 Z4*
!>          À la sortie, les valeurs propres dans D4 correspondent avec la matrice dans A.
!>

D5

!>          D5 est un tableau REAL de
!>                             dimension( max(NN) )
!>          Les valeurs propres de A, telles que calculées par CPTEQR(N)
!>          quand Z n'est pas calculé. À la sortie, les
!>          valeurs propres dans D4 correspondent avec la matrice dans A.
!>

WA1

!>          WA1 est un tableau REAL de
!>                             dimension( max(NN) )
!>          Toutes les valeurs propres de A, calculées avec une
!>          précision absolue élevée, avec différentes options de plage.
!>          telles que calculées par SSTEBZ.
!>

WA2

!>          WA2 est un tableau REAL de
!>                             dimension( max(NN) )
!>          Valeurs propres sélectionnées de A, calculées avec une
!>          précision absolue élevée, avec différentes options de plage.
!>          telles que calculées par SSTEBZ.
!>          Choisir des valeurs aléatoires pour IL et IU, et demander les
!>          valeurs propres de la IL-ième à la IU-ième.
!>

WA3

!>          WA3 est un tableau REAL de
!>                             dimension( max(NN) )
!>          Valeurs propres sélectionnées de A, calculées avec une
!>          précision absolue élevée, avec différentes options de plage.
!>          telles que calculées par SSTEBZ.
!>          Déterminer les valeurs VL et VU de la IL-ième et de la IU-ième
!>          valeurs propres et demander toutes les valeurs propres dans cette plage.
!>

WR

!>          WR est un tableau REAL de
!>                             dimension( max(NN) )
!>          Toutes les valeurs propres de A, calculées avec une
!>          précision absolue élevée, avec différentes options.
!>          telles que calculées par SSTEBZ.
!>

U

!>          U est un tableau COMPLEX de
!>                             dimension( LDU, max(NN) ).
!>          La matrice unitaire calculée par CHETRD + CUNGTR.
!>

LDU

!>          LDU est INTEGER
!>          La dimension principale de U, Z et V. Elle doit être au moins 1
!>          et au moins max( NN ).
!>

V

!>          V est un tableau COMPLEX de
!>                             dimension( LDU, max(NN) ).
!>          Les vecteurs de Householder calculés par CHETRD en réduisant A à la
!>          forme tridiagonale. Les vecteurs calculés avec UPLO='U' sont
!>          dans le triangle supérieur, et les vecteurs calculés avec UPLO='L'             sont dans le triangle inférieur. (Comme décrit dans CHETRD,
          la sous- et super-diagonale ne sont pas mises à 1, bien que le
          vrai vecteur de Householder ait un 1 dans cette position. Les
          routines qui utilisent V, comme CUNGTR, mettent ces entrées à
          1 avant de les utiliser, puis les restaurent plus tard.)

VP

          VP est un tableau COMPLEX de
                      dimension( max(NN)*max(NN+1)/2 )
          La matrice V stockée au format compacté.

TAU

          TAU est un tableau COMPLEX de
                             dimension( max(NN) )
          Les facteurs de Householder calculés par CHETRD lors de la réduction de A
          en forme tridiagonale.

Z

          Z est un tableau COMPLEX de
                             dimension( LDU, max(NN) ).
          La matrice unitaire des vecteurs propres calculés par CSTEQR,
          CPTEQR et CSTEIN.

WORK

          WORK est un tableau COMPLEX de
                      dimension( LWORK )

LWORK

          LWORK est un entier
          Le nombre d'entrées dans WORK. Cela doit être au moins
          1 + 4 * Nmax + 2 * Nmax * lg Nmax + 3 * Nmax**2
          où Nmax = max( NN(j), 2 ) et lg = log base 2.

IWORK

          IWORK est un tableau INTEGER
          Espace de travail.

LIWORK

          LIWORK est un entier
          Le nombre d'entrées dans IWORK. Cela doit être au moins
                  6 + 6*Nmax + 5 * Nmax * lg Nmax
          où Nmax = max( NN(j), 2 ) et lg = log base 2.

RWORK

          RWORK est un tableau REAL

LRWORK

          LRWORK est un entier
          Le nombre d'entrées dans LRWORK (dimension( ??? )

RESULT

          RESULT est un tableau REAL, dimension (26)
          Les valeurs calculées par les tests décrits ci-dessus.
          Les valeurs sont actuellement limitées à 1/ulp, pour éviter
          le dépassement de capacité.

INFO

          INFO est un entier
          Si 0, alors tout s'est bien passé.
           -1: NSIZES < 0
           -2: Certains NN(j) < 0
           -3: NTYPES < 0
           -5: THRESH < 0
           -9: LDA < 1 ou LDA < NMAX, où NMAX est max( NN(j) ).
          -23: LDU < 1 ou LDU < NMAX.
          -29: LWORK trop petit.
          Si CLATMR, CLATMS, CHETRD, CUNGTR, CSTEQR, SSTERF,
              ou CUNMC2 renvoie un code d'erreur, la
              valeur absolue de celui-ci est retournée.

-----------------------------------------------------------------------

Quelques variables et paramètres locaux :

       ZERO, ONE       Réels 0 et 1.
       MAXTYP          Le nombre de types définis.
       NTEST           Le nombre de tests effectués, ou qui peuvent
