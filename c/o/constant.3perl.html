constant(3perl) Guide de référence du programmeur Perl constant(3perl)

NOM

constant - Pragma Perl pour déclarer des constantes

SYNOPIS

use constant PI    => 4 * atan2(1, 1);
use constant DEBUG => 0;
print "Pi vaut ", PI, "...\n" if DEBUG;
use constant {
    SEC   => 0,
    MIN   => 1,
    HOUR  => 2,
    MDAY  => 3,
    MON   => 4,
    YEAR  => 5,
    WDAY  => 6,
    YDAY  => 7,
    ISDST => 8,
};
use constant WEEKDAYS => qw(
    Sunday Monday Tuesday Wednesday Thursday Friday Saturday
);
print "Aujourd'hui c'est ", (WEEKDAYS)[ (localtime)[WDAY] ], ".\n";

DESCRIPTION

Ce pragma permet de déclarer des constantes au moment de la compilation.

Lorsque vous déclarez une constante telle que "PI" en utilisant la méthode décrite ci-dessus, chaque machine sur laquelle votre script s'exécute peut avoir autant de chiffres de précision qu'elle peut en utiliser. De plus, votre programme sera plus facile à lire, plus susceptible d'être maintenu (et maintenu correctement), et beaucoup moins susceptible d'envoyer une sonde spatiale sur la mauvaise planète parce que personne n'a remarqué la seule équation dans laquelle vous aviez écrit 3.14195.

Lorsqu'une constante est utilisée dans une expression, Perl la remplace par sa valeur au moment de la compilation, et peut alors optimiser davantage l'expression. En particulier, tout code dans un bloc "if (CONSTANT)" sera optimisé pour être supprimé si la constante est fausse.

NOTES

Comme pour toutes les directives "use", la définition d'une constante se produit au moment de la compilation. Par conséquent, il n'est probablement pas correct de placer une déclaration de constante à l'intérieur d'une instruction conditionnelle (comme "if ($foo) { use constant ... }").

Les constantes définies à l'aide de ce module ne peuvent pas être interpolées dans les chaînes de caractères comme les variables. Cependant, la concaténation fonctionne très bien :

print "Pi vaut PI...\n";        # FAUX : n'étend pas "PI"
print "Pi vaut ".PI."...\n";    # Juste

Même si une référence peut être déclarée comme une constante, la référence peut pointer vers des données qui peuvent être modifiées, comme le montre ce code.

use constant ARRAY => [ 1,2,3,4 ];
print ARRAY->[1];
ARRAY->[1] = " peut être modifié";
print ARRAY->[1];

Les constantes appartiennent au package dans lequel elles sont définies. Pour faire référence à une constante définie dans un autre package, spécifiez le nom complet du package, comme dans "Some::Package::CONSTANT". Les constantes peuvent être exportées par des modules, et peuvent également être appelées comme des méthodes de classe ou d'instance, c'est-à-dire comme "Some::Package->CONSTANT" ou comme "$obj->CONSTANT" où $obj est une instance de "Some::Package". Les sous-classes peuvent définir leurs propres constantes pour remplacer celles de leur classe parente.

À partir de la version 1.32 de ce module, les constantes peuvent être définies dans des packages autres que l'appelant, en incluant le nom du package dans le nom de la constante :

use constant "OtherPackage::FWIBBLE" => 7865;
constant->import("Other::FWOBBLE",$value); # dynamiquement à l'exécution

L'utilisation de majuscules pour les noms de constantes n'est qu'une convention, bien qu'elle soit recommandée pour faire ressortir les constantes et éviter les collisions avec d'autres mots vides, mots-clés et noms de sous-routines. Les noms de constantes doivent commencer par une lettre ou un underscore. Les noms commençant par un double underscore sont réservés. Certains mauvais choix de noms généreront des avertissements, si les avertissements sont activés au moment de la compilation.

Lister les constantes

Les constantes peuvent être des listes de plusieurs (ou moins) valeurs. Une constante sans valeur est évaluée à "undef" en contexte scalaire. Notez que les constantes avec plusieurs valeurs ne renvoient pas leur dernière valeur en contexte scalaire comme on pourrait s'y attendre. Elles renvoient actuellement le nombre de valeurs, mais **cela pourrait changer à l'avenir**. N'utilisez pas de constantes avec plusieurs valeurs en contexte scalaire.

**NOTE :** Cela implique que l'expression définissant la valeur d'une constante est évaluée en contexte de liste. Cela peut produire des surprises :

use constant TIMESTAMP => localtime;                # FAUX !
use constant TIMESTAMP => scalar localtime;         # Juste

La première ligne ci-dessus définit "TIMESTAMP" comme une liste de 9 éléments, telle que renvoyée par localtime() en contexte de liste. Pour la définir à la chaîne renvoyée par localtime() en contexte scalaire, un mot-clé "scalar" explicite est requis.

Les constantes de liste sont des listes, pas des tableaux. Pour les indexer ou les découper, elles doivent être placées entre parenthèses.

my @workdays = WEEKDAYS[1 .. 5];            # FAUX !
my @workdays = (WEEKDAYS)[1 .. 5];          # Juste

Définir plusieurs constantes en même temps

Au lieu d'écrire plusieurs instructions "use constant", vous pouvez définir plusieurs constantes dans une seule instruction en donnant, au lieu du nom de la constante, une référence à une table associative où les clés sont les noms des constantes à définir. Évidemment, toutes les constantes définies en utilisant cette méthode doivent avoir une valeur unique.

use constant {
    FOO => "Une valeur unique",
    BAR => "Ceci", "ne", "fonctionne", "pas !",        # Erreur !
};

C'est une limitation fondamentale de la manière dont les tables associatives sont construites en Perl. Les messages d'erreur produits lorsque cela se produit seront souvent assez cryptiques -- dans le pire des cas, il peut y en avoir aucun, et vous ne découvrirez que plus tard que quelque chose ne fonctionne pas.

Lors de la définition de plusieurs constantes, vous ne pouvez pas utiliser les valeurs d'autres constantes définies dans la même déclaration. Cela est dû au fait que le package appelant ne connaît aucune constante au sein de ce groupe qu'après la fin de l'instruction "use".

use constant {
    BITMASK => 0xAFBAEBA8,
    NEGMASK => ~BITMASK,                    # Erreur !
};

Constantes magiques

Les valeurs et références magiques peuvent être transformées en constantes au moment de la compilation, permettant des trucs super cool comme ceci. (Ces numéros d'erreur ne sont malheureusement pas totalement portables.)

use constant E2BIG => ($! = 7);
print   E2BIG, "\n";        # quelque chose comme "Liste d'arguments trop longue"
print 0+E2BIG, "\n";        # "7"

Vous ne pouvez pas produire une constante liée en donnant un scalaire lié comme valeur. Les références à des variables liées, cependant, peuvent être utilisées comme constantes sans aucun problème.

NOTES TECHNIQUES

Dans l'implémentation actuelle, les constantes scalaires sont en fait des sous-routines inlinables. Depuis la version 5.004 de Perl, la constante scalaire appropriée est insérée directement à la place de certains appels de sous-routines, économisant ainsi la surcharge d'un appel de sous-routine. Voir "Fonctions constantes" dans perlsub pour plus de détails sur comment et quand cela se produit.

Dans le rare cas où vous auriez besoin de découvrir à l'exécution si une constante particulière a été déclarée via ce module, vous pouvez utiliser cette fonction pour examiner la table associative %constant::declared. Si le nom de la constante donné n'inclut pas de nom de package, le package actuel est utilisé.

sub declared ($) {
    use constant 1.01;              # ne pas omettre !
    my $name = shift;
    $name =~ s/^::/main::/;
    my $pkg = caller;
    my $full_name = $name =~ /::/ ? $name : "${pkg}::$name";
    $constant::declared{$full_name};
}

CAVEATS

Les constantes de liste ne sont pas inlinées sauf si vous utilisez Perl v5.20 ou une version ultérieure. En v5.20 ou une version ultérieure, elles ne sont toujours pas en lecture seule, mais cela pourrait changer dans les versions futures.

Il n'est pas possible d'avoir une sous-routine ou un mot-clé portant le même nom qu'une constante dans le même package. C'est probablement une bonne chose.

Une constante portant un nom dans la liste "STDIN STDOUT STDERR ARGV ARGVOUT ENV INC SIG" n'est autorisée nulle part ailleurs que dans le package "main::", pour des raisons techniques.

NAME

constant - Facility for creating read-only values

SYNOPSIS

    use constant NAME => value;
    use constant NAME => value, NAME2 => value2, ...;
    use constant {
        NAME  => value,
        NAME2 => value2,
        ...
    };
    use constant NAME() => value;
    use constant +NAME => value;

DESCRIPTION

The constant pragma provides a way to create symbolic constants, similar to #define in C. Constants created by this pragma are read-only. If you attempt to modify a constant, a runtime error will occur.

The pragma takes a list of key/value pairs. The keys are the names of the constants to be created, and the values are the values of those constants. The keys must be valid Perl identifiers (typically barewords).

If the value is a subroutine call, the subroutine will be called at compile time, and its return value will be used as the constant's value. If the value is a literal (e.g., a number, string, array reference, or hash reference), that literal will be used directly.

The pragma can be used multiple times within a scope. Constants are lexically scoped.

NOTES

Constants created by constant are essentially subroutines that always return the same value. This means they can be used anywhere a subroutine call is valid.

For example:

    use constant PI => 4 * atan2(1, 1);
    print PI * $radius**2;

This will print the area of a circle with the given radius.

You can also use constants in list contexts:

    use constant COLORS => qw(red green blue);
    my @my_colors = (yellow, COLORS);

Note that COLORS will be interpolated as red, green, blue in list context.

Constants can be defined in any lexical scope:

    sub my_sub {
        use constant DEBUG => 1;
        if (DEBUG) {
            print "Debugging enabled\n";
        }
    }

TECHNICAL NOTES

The constant pragma works by defining subroutines. When you write:

    use constant NAME => value;

Perl essentially replaces this with:

    sub NAME () { value }

The empty parentheses after the subroutine name indicate that the subroutine takes no arguments. This is important for performance and for preventing accidental modification of the constant's value.

CAVEATS

You can get into trouble if you use constants in a context which automatically quotes barewords (as is true for any subroutine call). For example, you can't say $hash{CONSTANT} because "CONSTANT" will be interpreted as a string. Use $hash{CONSTANT()} or $hash{+CONSTANT} to prevent the bareword quoting mechanism from kicking in. Similarly, since the "=>" operator quotes a bareword immediately to its left, you have to say "CONSTANT() => 'value'" (or simply use a comma in place of the big arrow) instead of "CONSTANT => 'value'".
