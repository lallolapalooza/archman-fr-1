NOM

itcl::code - capture le contexte de namespace pour un fragment de code

SYNOPIS

itcl::code ?-namespace nom? commande ?arg arg ...?

DESCRIPTION

Crée une valeur indexée pour la commande spécifiée et ses arguments arg associés. Une valeur indexée est une liste de trois éléments : le mot-clé « @scope », un contexte de namespace et une chaîne de valeur. Par exemple, la commande

namespace foo {
    code puts "Bonjour le monde !"
}
produit la valeur indexée : 
@scope ::foo {puts {Bonjour le monde !}}
Notez que la commande code capture le contexte de namespace actuel. Si le drapeau -namespace est spécifié, alors le contexte actuel est ignoré, et la chaîne nom est utilisée comme contexte de namespace.

Les extensions comme Tk exécutent des fragments de code ordinaires dans le namespace global. Une valeur indexée capture un fragment de code avec son contexte de namespace d'une manière qui permet de l'exécuter correctement plus tard. Elle est nécessaire, par exemple, pour encapsuler des fragments de code lorsqu'un widget Tk est utilisé dans un namespace :

namespace foo {
    private proc report {mesg} {
        puts "clic : $mesg"
    }
    button .b1 -text "Appuyez-moi" -command [code report "Bonjour le monde !"]
    pack .b1
}
Le fragment de code associé au bouton .b1 n'a de sens que dans le contexte du namespace « foo ». De plus, la procédure « report » est privée et ne peut être accédée qu'à l'intérieur de ce namespace. La commande code encapsule le fragment de code d'une manière qui permet de l'exécuter correctement lorsque le bouton est pressé.

Notez également que la commande code préserve l'intégrité des arguments sur la ligne de commande. Cela en fait un remplacement naturel pour la commande list, qui est souvent utilisée pour formater des fragments de code Tcl. En d'autres termes, au lieu d'utiliser la commande list comme ceci :

after 1000 [list puts "Bonjour $name !"]
utilisez la commande code comme ceci : 
after 1000 [code puts "Bonjour $name !"]
Cela formate non seulement la commande correctement, mais capture également son contexte de namespace.

Les commandes indexées peuvent être appelées comme des fragments de code ordinaires, avec ou sans la commande eval. Par exemple, les instructions suivantes fonctionnent correctement :

set cmd {@scope ::foo .b1}
$cmd configure -background red
set opts {-bg blue -fg white}
eval $cmd configure $opts
Notez que les commandes indexées contournent les mécanismes de protection habituels ; la commande : 
@scope ::foo {report {Bonjour le monde !}}
peut être utilisée pour accéder à la procédure « foo::report » depuis n'importe quel contexte de namespace, même si elle est privée.
