NOM

containers-sigstore-signing-params.yaml - syntaxe du fichier de paramètres de signature sigstore

DESCRIPTION

Les fichiers de paramètres de signature sigstore sont utilisés pour stocker les options qui peuvent être requises pour créer des signatures sigstore. Il n'y a pas d'emplacement par défaut pour ces fichiers ; ils sont gérés par l'utilisateur et utilisés comme entrées pour une opération de signature d'image conteneur, par exemple skopeo copy --sign-by-sigstore=fichier-param.yaml ou podman push --sign-by-sigstore=fichier-param.yaml.

FORMAT

Les fichiers de paramètres de signature sigstore utilisent YAML.

De nombreux paramètres sont facultatifs, mais le fichier doit en spécifier suffisamment pour créer une signature ; en particulier une clé privée, ou Fulcio.

Signature avec des clés privées

•
privateKeyFile: chemin

Crée une signature à l'aide d'une clé privée située à chemin.
L'existence de ce champ déclenche l'utilisation d'une clé privée.

•
privateKeyPassphraseFile: chemin_phrase_de_passe

Lit la phrase de passe requise pour utiliser privateKeyFile à partir de chemin_phrase_de_passe.
Facultatif : si ce champ n'est pas défini, l'utilisateur doit fournir la phrase de passe interactivement.

Signature avec des certificats générés par Fulcio

Au lieu d'une clé privée statique, le processus de signature génère une paire de clés à courte durée de vie et demande à un serveur Fulcio d'émettre un certificat pour cette paire de clés, en se basant sur l'authentification de l'utilisateur auprès d'un fournisseur OpenID Connect.

Pour spécifier Fulcio, incluez un sous-objet fulcio avec une ou plusieurs des clés suivantes. De plus, un serveur Rekor doit également être spécifié.

•
fulcioURL: URL

Requis. URL du serveur Fulcio à utiliser.

•
oidcMode: interactive | deviceGrant | staticToken

Requis. Spécifie comment obtenir l'identifiant OpenID Connect nécessaire.

interactive ouvre un navigateur Web sur la même machine, ou si cela n'est pas possible,
demande à l'utilisateur d'ouvrir manuellement un navigateur et de saisir le code fourni.
Cela nécessite que l'utilisateur puisse interagir directement avec le processus de signature.

deviceGrant utilise un flux d'octroi d'autorisation d'appareil (RFC 8628).
Cela nécessite que l'utilisateur puisse lire le texte affiché par le processus de signature et agir en conséquence rapidement.

staticToken fournit un jeton d'identification OpenID Connect préexistant, qui doit avoir été obtenu séparément.

•
oidcIssuerURL: URL

Requis pour oidcMode: interactive ou deviceGrant. URL d'un serveur émetteur OpenID Connect pour s'authentifier.

•
oidcClientID: identifiant client

Utilisé pour oidcMode: interactive ou deviceGrant pour identifier le client lors de la contact du serveur émetteur.
Facultatif mais probablement nécessaire dans ces cas.

•
oidcClientSecret: secret client

Utilisé pour oidcMode: interactive ou deviceGrant pour authentifier le client lors de la contact du serveur émetteur.
Facultatif.

•
oidcIDToken: jeton

Requis pour oidcMode: staticToken.
Un jeton d'identification OpenID Connect qui identifie l'utilisateur (et autorise l'émission du certificat).

Enregistrement de la signature sur un serveur de transparence Rekor

Cela peut être combiné avec une clé privée ou Fulcio. C'est, pratiquement parlant, requis pour Fulcio ; c'est facultatif lorsqu'une clé privée statique est utilisée, mais nécessaire pour l'interopérabilité avec la configuration par défaut de cosign.

•
rekorURL: URL

URL du serveur Rekor à utiliser.

EXEMPLES

Signer en utilisant une clé privée préexistante

Utilise le serveur Rekor de "l'infrastructure communautaire".

privateKeyFile: "/home/user/sigstore/private-key.key"
privateKeyPassphraseFile: "/mnt/user/sigstore-private-key"
rekorURL: "https://rekor.sigstore.dev"

Signer en utilisant un certificat délivré par Fulcio

Utilise les serveurs Fulcio et Rekor de "l'infrastructure communautaire", ainsi que le serveur émetteur OIDC Dex qui délègue à d'autres émetteurs majeurs comme Google et GitHub.

D'autres configurations nécessiteront très probablement également un secret client OIDC.

fulcio:
  fulcioURL: "https://fulcio.sigstore.dev"
  oidcMode: "interactive"
  oidcIssuerURL: "https://oauth2.sigstore.dev/auth"
  oidcClientID: "sigstore"
rekorURL: "https://rekor.sigstore.dev"
