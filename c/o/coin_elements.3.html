Description

détaillée

Les classes d'éléments dans Coin sont les conteneurs d'informations d'état lors des traversées d'actions sur les graphes de

scène.

Un élément correspond généralement à un élément d'information, ou parfois à un groupe de valeurs d'informations liées. Les éléments fonctionnent comme une pile qui est empilée et dépilée à mesure que l'action entre et sort des nœuds SoSeparator, et l'action n'inspectera toujours que le sommet de la pile lorsqu'elle a besoin de connaître une

valeur.

Les éléments sont des détails d'implémentation internes du fonctionnement des nœuds et des actions, et ne sont pas quelque chose dont il faut se soucier avant d'écrire ses propres nœuds d'extension. Écrire des éléments d'extension est encore plus éloigné de l'utilisation simple d'Open Inventor, mais est tout à fait possible pour le développeur Open Inventor expérimenté. Les classes

d'éléments

Les éléments sont principalement internes à Coin, sauf si vous créez de nouveaux nœuds d'extension sur Coin. Dans ce cas, vous aurez probablement besoin de les connaître.
Les éléments font partie de la conception de la traversée des graphes de scène dans Coin.
Cela fonctionne ainsi : toute action de traversée instancie et conserve une seule instance SoState pendant la traversée. L'instance SoState utilise des objets SoElement comme "unités de mémoire" pour suivre l'état actuel de toute fonctionnalité des nœuds du graphe de scène.
À titre d'exemple, considérons le nœud SoPointSize : lorsque le nœud SoPointSize est traversé par par exemple une SoGLRenderAction, il poussera lui-même un SoPointSizeElement sur la pile SoState de l' SoGLRenderAction. Plus tard, lorsqu'un nœud SoPointSet apparaît dans le graphe de scène, il demandera la valeur de taille des points actuelle à la SoState en lisant la valeur de son SoPointSizeElement.
Les nœuds SoSeparator pousseront et retireront des éléments de la pile d'état, de sorte que tout ce qui change l'état en dessous d'un nœud SoSeparator n'influencera rien au-dessus du SoSeparator

.

Pour plus d'informations sur les fondements théoriques de cette conception de traversée, vous devriez envisager de lire la littérature disponible sur le soi-disant "patron de conception Visiteur". Nous recommandons "Design Patterns", de Gamma, Helm, Johnson, Vlissides (alias le "Gang Of Four"). Ce livre utilise en fait le mécanisme de traversée de l'API Inventor comme étude de cas pour expliquer le patron Visiteur.
Pour étendre la bibliothèque Coin avec vos propres classes, nous vous recommandons vivement de vous familiariser avec l'excellent livre The Inventor Toolmaker (ISBN 0-201-62493-1), qui décrit en détail les tâches impliquées. Ce livre a été écrit par les concepteurs originaux d'Inventor de SGI et explique nombre des idées de conception sous-jacentes, ainsi que de nombreux exemples pratiques sur la manière d'étendre la boîte à outils Coin d'une manière fidèle aux idées de conception fondamentales. (The Inventor Toolmaker est également disponible dans la bibliothèque en ligne de SGI, gratuitement. Voir Download The Inventor Toolmaker.) La lecture du code source des classes intégrées dans Coin devrait également s'avérer très

utile.

Et une petite application de test autonome mettant le nouvel élément à utiliser

: 
// [lstextures.cpp]
//
// Le but de ce fichier est de créer un petit "outil" d'enveloppe autour
// de l'élément d'extension TextureFilenameElement, juste pour montrer
// un exemple de code sur la manière d'utiliser un élément personnalisé défini par l'utilisateur.
//
// Le code se présente ainsi :
//
// Nous initialisons l'élément, l'activons pour l'SoCallbackAction, lisons
// un fichier de graphe de scène, définissons des rappels sur SoTexture2 et tous les nœuds de forme
// et appliquons l'SoCallbackAction. Les rappels imprimeront alors les
// informations sur le nom de fichier de texture à partir du TextureFilenameElement
// chaque fois qu'un nœud intéressant est rencontré.
//
//
// Code par Peder Blekken <pederb@sim.no>. Nettoyé, intégré dans la
// distribution Coin et commenté par Morten Eriksen
// <mortene@sim.no>. Copyright (C) Kongsberg Oil & Gas Technologies.
#include <Inventor/SoDB.h>
#include <Inventor/SoInput.h>
#include <Inventor/actions/SoCallbackAction.h>
#include <Inventor/nodes/SoSeparator.h>
#include <Inventor/nodes/SoTexture2.h>
#include <Inventor/nodes/SoShape.h>
#include <Inventor/misc/SoState.h>
#include <cstdio>
#include "texturefilenameelement.h"
SoCallbackAction::Response
pre_tex2_cb(void * data, SoCallbackAction * action, const SoNode * node)
{
  const SbString & filename = ((SoTexture2 *)node)->filename.getValue();
  TextureFilenameElement::set(action->getState(), (SoNode *)node, filename);
  (void)fprintf(stdout, "=> New texture: %s\n",
                filename.getLength() == 0 ?
                "<inlined>" : filename.getString());
  return SoCallbackAction::CONTINUE;
}
SoCallbackAction::Response
pre_shape_cb(void * data, SoCallbackAction * action, const SoNode * node)
{
  const SbString & filename =
    TextureFilenameElement::get(action->getState());
  (void)fprintf(stdout, "   Texturemap on %s: %s\n",
                node->getTypeId().getName().getString(),
                filename.getLength() == 0 ?
                "<inlined>" : filename.getString());
  return SoCallbackAction::CONTINUE;
}
void
usage(const char * appname)
{
  (void)fprintf(stderr, "\n\tUtilisation : %s <modelfile.iv>\n\n", appname);
  (void)fprintf(stderr,
                "\tListe tous les noms de fichiers de texture dans le fichier modèle,\n"
                "\tet les nœuds de forme sur lesquels ils sont utilisés.\n\n"
                "\tLe but de cet utilitaire d'exemple est simplement de\n"
                "\tmontrer comment créer et utiliser un élément d'extension pour\n"
                "\tle parcours du graphe de scène.\n\n");
}
int
main(int argc, char ** argv)
{
  if (argc != 2) {
    usage(argv[0]);
    exit(1);
  }
  SoDB::init();
  TextureFilenameElement::initClass();
  SO_ENABLE(SoCallbackAction, TextureFilenameElement);
  SoInput input;
  if (!input.openFile(argv[1])) {
    (void)fprintf(stderr, "ERREUR : impossible d'ouvrir le fichier \"%s\".\n", argv[1]);
    exit(1);
  }
  SoSeparator * root = SoDB::readAll(&input);
  if (root) {
    root->ref();
    SoCallbackAction cbaction;
    cbaction.addPreCallback(SoTexture2::getClassTypeId(), pre_tex2_cb, NULL);
    cbaction.addPreCallback(SoShape::getClassTypeId(), pre_shape_cb, NULL);
    cbaction.apply(root);
    root->unref();
    return 0;
  }
  return 1;
}
