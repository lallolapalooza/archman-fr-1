DESCRIPTIO

N

L'utilitaire conntrack fournit une interface en espace utilisateur complète pour le système de suivi de connexions Netfilter, destiné à remplacer l'ancienne interface /proc/net/ip_conntrack. Cet outil peut être utilisé pour rechercher, lister, inspecter et maintenir le sous-système de suivi de connexions du noyau

Linux.

En utilisant conntrack, vous pouvez exporter une liste de toutes les connexions actuellement suivies (ou d'une sélection filtrée), supprimer des connexions de la table d'état et même en ajouter de

nouvelles.

De plus, vous pouvez aussi surveiller les événements de sui

vi de connexions, par exemple afficher un message d'événem
ent (une ligne) pour chaque connexion nouvellement établie.

TABLE

S

Le sous-système de suivi de connexions maintient plusieurs tables internes

:
conntra
ck :
C'est la table par défaut. Elle contient une liste de toutes les connexions actuellement suivies par le système. Si vous n'utilisez pas d'exemptions de suivi de connexions (cible iptables NOTRACK), cela signifie toutes les connexions qui passent par le
système.
expec
t :
C'est la table des attentes. Les attentes de suivi de connexions sont le mécanisme utilisé pour « attendre » des connexions RELATED à des connexions existantes. Les attentes sont généralement utilisées par des « assistants de suivi de connexions » (parfois appelés passerelles de niveau application [ALGs]) pour des protocoles plus complexes tels que FTP, SIP ou H.
323.
dying
:
Cette table affiche les entrées conntrack qui ont expiré et qui ont été détruites par le système de suivi de connexions lui-même, ou via l'utilitaire co
nntrack.
unconfirm
ed :
Cette table affiche les nouvelles entrées qui ne sont pas encore insérées dans la table conntrack. Ces entrées sont attachées à des paquets qui traversent la pile, mais qui n'ont pas atteint le point de confirmation à l'accroche postrouting.

Les tables « dying » et « unconfirmed » sont fondamentalement utiles uniquement à des fins de débogage. En fonctionnement normal, il est difficile de voir des entrées dans l'une ou l'autre. Il existe des cas particuliers où il est valide de voir des entrées dans la table unconfirmed, par exemple lorsque des paquets sont mis en file d'attente via nfqueue, et la table dying, par exemple lorsque conntrackd(8) s'

exécute
en mode é
vénement
fiable.

PARAMÈTRE

S
-z,
--zero
Mettre les compteurs à zéro de manière atomique après les avoir lus. Cette option n'est valide qu'en combinaison avec les options de commande « -L, --dump
».
-o, --output [extended,xml,save,timestamp,id,ktimestamp,
labels]
Afficher la sortie dans un certain format. Avec l'option de sortie extended, cet outil affiche les informations de couche 3. Avec ktimestamp, il affiche l'horodatage disponible dans le noyau depuis la version 2.6.38 (vous pouvez l'activer via la clé sysctl(8) net.netfilter.nf_conntrack_timestamp). L'option de sortie labels indique à conntrack d'afficher les noms des étiquettes de suivi de connexions qui peuvent être présentes. L'option de sortie userspace indique si l'événement a été déclenché par un
processus.
-e, --event-mask [ALL|NEW|UPDATES|DESTROY][,.
..]
Définir le masque de bits des événements qui doivent être générés par le code d'événements ctnetlink dans le noyau. En utilisant ce paramètre, vous pouvez réduire les messages d'événements générés par le noyau aux types qui vous intéressent réellement. Cette option ne peut être utilisée qu'en conjonction avec « -E, --event
».
-b, --buffer-size vale
ur
Définir la taille du tampon de la socket Netlink en octets. Cette option est utile si l'outil en ligne de commande signale des erreurs ENOBUFS. Si vous ne passez pas cette option, la valeur par défaut disponible à la clé sysctl(8) net.core.rmem_default est utilisée. L'outil signale ce problème si votre processus est trop lent pour traiter tous les messages d'événements ou, en d'autres termes, si le nombre d'événement
s est assez grand pour déborder le tampon de la socket. Notez que l'utilisation d'un grand tamp
on réduit les chances de rencontrer ENOBUFS, cependant, cela entraîne une consommation de mémo
ire plus importante. Cette option ne peut être utilisée qu'en conjonction avec « -E, --event ».

DIAGNOSTICS

Le code de sortie est 0 en cas de fonctionnement correct. Les erreurs qui semblent être causées par des paramètres de ligne de commande invalides provoquent un code de sortie de 2. Toute autre erreur provoque un code de sortie de 1.

EXEMPLES

conntrack -L
Afficher la table de suivi des connexions au format /proc/net/ip_conntrack
conntrack -L -o extended
Afficher la table de suivi des connexions au format /proc/net/nf_conntrack, avec des informations supplémentaires.
conntrack -L -o xml
Afficher la table de suivi des connexions en XML
conntrack -L -o save
Afficher la table de suivi des connexions au format de syntaxe conntrack
conntrack -L -f ipv6 -o extended
Afficher uniquement les connexions IPv6 au format /proc/net/nf_conntrack, avec des informations supplémentaires.
conntrack -L --src-nat
Afficher les connexions NAT source
conntrack -E -o timestamp
Afficher les événements de connexion avec l'horodatage
conntrack -D -s 1.2.3.4
Supprimer tous les flux dont l'adresse source est 1.2.3.4
