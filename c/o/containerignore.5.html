NOM

.containerignore(.dockerignore) - fichiers à ignorer dans le répertoire de contexte de construction buildah ou podman

INTRODUCTION

Avant que les moteurs de conteneur ne construisent une image, ils recherchent un fichier nommé .containerignore ou .dockerignore dans le répertoire racine du contexte. Si l'un de ces fichiers existe, la CLI modifie le contexte pour exclure les fichiers et répertoires qui correspondent aux motifs spécifiés dans le fichier. Cela évite de les ajouter aux images en utilisant l'instruction ADD ou COPY.

La CLI interprète le fichier .containerignore ou .dockerignore comme une liste de motifs séparés par des sauts de ligne, similaire aux glob de fichiers des shells Unix. Aux fins de correspondance, la racine du contexte est considérée à la fois comme le répertoire de travail et le répertoire racine. Par exemple, les motifs /foo/bar et foo/bar excluent tous deux un fichier ou un répertoire nommé bar dans le sous-répertoire foo de PATH ou dans la racine du dépôt git situé à l'URL. Ni l'un ni l'autre n'exclut autre chose.

Si une ligne dans le fichier .containerignore ou .dockerignore commence par # dans la colonne 1, alors cette ligne est considérée comme un commentaire et est ignorée avant d'être interprétée par la CLI.

EXEMPLES

Voici un exemple de fichier .containerignore :

# commentaire
*/temp*
*/*/temp*
temp?

Ce fichier provoque le comportement de construction suivant : Règle Comportement

# commentaire 	Ignoré.
*/temp* 	Exclure les fichiers et répertoires dont les noms commencent par temp dans n'importe quel sous-répertoire immédiat de la racine.
Par exemple, le fichier simple /somedir/temporary.txt est exclu, tout comme le répertoire /somedir/temp.
*/*/temp* 	Exclure les fichiers et répertoires commençant par temp de tout sous-répertoire situé deux niveaux sous la
racine. Par exemple, /somedir/subdir/temporary.txt est exclu.
temp? 	Exclure les fichiers et répertoires dans le répertoire racine dont les noms sont une extension d'un seul caractère de temp. Par exemple, /tempa et /tempb sont exclus.

La correspondance est effectuée à l'aide des règles filepath.Match de Go. Une étape de prétraitement supprime les espaces blancs de début et de fin et élimine les éléments . et .. en utilisant filepath.Clean de Go. Les lignes vides après prétraitement sont ignorées.

Au-delà des règles filepath.Match de Go, Docker prend également en charge la chaîne de caractères spéciale ** qui correspond à n'importe quel nombre de répertoires (y compris zéro). Par exemple, */.go exclura tous les fichiers qui se terminent par .go et qui se trouvent dans tous les répertoires, y compris la racine du contexte de construction.

Les lignes commençant par ! (point d'exclamation) peuvent être utilisées pour faire des exceptions aux exclusions. Voici un exemple de fichier .containerignore qui utilise ce mécanisme :

*.md
!README.md

Tous les fichiers markdown sauf README.md sont exclus du contexte.

Le placement des règles d'exception ! influence le comportement : la dernière ligne du .containerignore qui correspond à un fichier particulier détermine s'il est inclus ou exclu. Considérons l'exemple suivant :

*.md
!README*.md
README-secret.md

Aucun fichier markdown n'est inclus dans le contexte, à l'exception des fichiers README autres que README-secret.md.

Considérons maintenant cet exemple :

*.md
README-secret.md
!README*.md

Tous les fichiers README sont inclus. La ligne du milieu n'a aucun effet car !README*.md correspond à README-secret.md et vient en dernier.

Vous pouvez même utiliser le fichier .containerignore pour exclure les fichiers Containerfile ou Dockerfile et .containerignore. Ces fichiers sont toujours envoyés au démon car il en a besoin pour faire son travail. Mais les instructions ADD et COPY ne les copient pas dans l'image.

Enfin, vous pouvez vouloir spécifier quels fichiers inclure dans le contexte, plutôt que lesquels exclure. Pour y parvenir, spécifiez * comme premier motif, suivi d'une ou plusieurs règles d'exception !.
