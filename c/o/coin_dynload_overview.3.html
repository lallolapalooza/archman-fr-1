coin_dynload_overview - Chargement dynamique des nœuds d'extension

Lorsque Coin tente d'obtenir un objet de type nœud (SoType) pour une classe basée sur le nom de type donné, il va - si aucun type de nœud de ce genre n'a encore été initialisé - parcourir le système de fichiers à la recherche d'un nœud d'extension chargeable dynamiquement avec ce nom. Cela peut être complètement désactivé en définissant la variable d'environnement COIN_NO_SOTYPE_DYNLOAD à une valeur entière positive, nouveauté depuis Coin v2.5.0.

Sur UNIX, les nœuds d'extension sont des fichiers .so ordinaires. Sur Win32, les nœuds d'extension sont construits en tant que DLL. Sur les systèmes Mac OS X, les nœuds d'extension sont construits en tant que fichiers .dylib. (Note : Les nœuds d'extension doivent être construits avec l'option « -dynamiclib » et non « -bundle ».)

Que les objets chargeables dynamiquement doivent être nommés avec ou sans le préfixe « lib » est facultatif. Les deux schémas fonctionneront.

Les gens ne programment généralement pas de manière à instancier de nouveaux nœuds via l'objet SoType de la classe du nœud, mais c'est ainsi que les nœuds sont créés lors du chargement des fichiers de modèle. Cela signifie que pour toutes les applications Coin qui chargent des fichiers de modèle, les nœuds d'extension personnalisés seront automatiquement pris en charge pour les fichiers de modèle sans que vous ayez à modifier leur code source et à reconstruire les applications.

Voir ftp://ftp.coin3d.org/pub/coin/src/dynloadsample.tar.gz pour un exemple utilisant deux nœuds d'extension chargeables dynamiquement. Vous utilisez seulement un visualiseur d'examinateur pour voir les deux nœuds d'extension en action.

Seul un ensemble limité de compilateurs C++ est pris en charge jusqu'à présent. Ceci est dû au fait que, pour initialiser le nœud d'extension, il est nécessaire de connaître comment le compilateur C++ gère le symbole initClass. Si nous ne le savons pas, il n'y a aucun moyen de localiser la méthode initClass dans la bibliothèque, ce qui signifie que le nœud d'extension ne peut *pas* se faire connaître du système de types.

Si votre compilateur C++ n'est pas pris en charge, le fichier source à modifier pour ajouter le support d'un nouveau compilateur est src/misc/cppmangle.icc. Il est assez simple d'ajouter le support pour de nouveaux compilateurs, mais si vous ne comprenez pas comment faire, demandez-nous simplement. Les correctifs avec le support de nouveaux compilateurs sont bien sûr très bienvenus.
