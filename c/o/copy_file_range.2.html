copy_file_range(2) Manuel des appels système copy_file_range(2)

NOM

copy_file_range - Copie une plage de données d'un fichier à un autre

BIBLIOTHÈQUE

Bibliothèque C standard (libc, -lc)

SYNTAXE

#define _GNU_SOURCE
#define _FILE_OFFSET_BITS 64
#include <unistd.h>
ssize_t copy_file_range(int fd_in, off_t *_Nullable off_in,
                        int fd_out, off_t *_Nullable off_out,
                        size_t size, unsigned int flags);

DESCRIPTION

L'appel système copy_file_range() effectue une copie au niveau du noyau entre deux descripteurs de fichiers, sans le coût supplémentaire du transfert de données du noyau vers l'espace utilisateur, puis de retour vers le noyau. Il copie jusqu'à size octets de données depuis le descripteur de fichier source fd_in vers le descripteur de fichier cible fd_out, écrasant toute donnée existante dans la plage demandée du fichier cible.

Les sémantiques suivantes s'appliquent à off_in, et des déclarations similaires s'appliquent à off_out :

•
Si off_in est NULL, alors les octets sont lus depuis fd_in à partir du décalage du fichier, et le décalage du fichier est ajusté du nombre d'octets copiés.
•
Si off_in n'est pas NULL, alors off_in doit pointer vers un tampon qui spécifie le décalage de départ où les octets de fd_in seront lus. Le décalage du fichier de fd_in n'est pas modifié, mais off_in est ajusté de manière appropriée.

fd_in et fd_out peuvent faire référence au même fichier. S'ils font référence au même fichier, alors les plages source et cible ne sont pas autorisées à se chevaucher.

L'argument flags est fourni pour permettre des extensions futures et doit actuellement être mis à 0.

VALEUR DE RETOUR

En cas de succès, copy_file_range() retourne le nombre d'octets copiés entre les fichiers. Cela peut être inférieur à la taille initialement demandée. Si le décalage du fichier de fd_in est au bout du fichier ou au-delà, aucun octet n'est copié et copy_file_range() retourne zéro.

En cas d'erreur, copy_file_range() retourne -1 et errno est défini pour indiquer l'erreur.

ERREURS

EBADF
Un ou plusieurs descripteurs de fichiers ne sont pas valides.
EBADF
fd_in n'est pas ouvert en lecture ; ou fd_out n'est pas ouvert en écriture.
EBADF
L'indicateur O_APPEND est défini pour la description de fichier ouverte (voir open(2)) référencée par le descripteur de fichier fd_out.
EFBIG
Une tentative d'écriture a été faite à une position au-delà du décalage maximal de fichier pris en charge par le noyau.
EFBIG
Une tentative d'écriture d'une plage dépassant la taille maximale de fichier autorisée a été effectuée. La taille maximale de fichier diffère entre les implémentations de systèmes de fichiers et peut être différente du décalage de fichier maximal autorisé.
EFBIG
Une tentative d'écriture au-delà de la limite de ressources de taille de fichier du processus a été effectuée. Cela peut également entraîner la réception du signal SIGXFSZ par le processus.
EINVAL
L'argument flags n'est pas 0.
EINVAL
fd_in et fd_out font référence au même fichier et les plages source et cible se chevauchent.
EINVAL
Soit fd_in, soit fd_out n'est pas un fichier régulier.
EIO
Une erreur d'E/S de bas niveau s'est produite pendant la copie.
EISDIR
Soit fd_in, soit fd_out fait référence à un répertoire.
ENOMEM
Pas assez de mémoire.
ENOSPC
Il n'y a pas assez d'espace sur le système de fichiers cible pour effectuer la copie.
EOPNOTSUPP (depuis Linux 5.19)
Le système de fichiers ne prend pas en charge cette opération.
EOVERFLOW
La plage source ou destination demandée est trop grande pour être représentée dans les types de données spécifiés.
EPERM
fd_out fait référence à un fichier immuable.
ETXTBSY
Soit fd_in, soit fd_out fait référence à un fichier swap actif.
EXDEV (avant Linux 5.3)
Les fichiers référencés par fd_in et fd_out ne sont pas sur le même système de fichiers.
EXDEV (depuis Linux 5.19)
Les fichiers référencés par fd_in et fd_out ne sont pas sur le même système de fichiers, et les systèmes de fichiers source et cible ne sont pas du même type, ou ne prennent pas en charge la copie inter-systèmes.

VERSIONS

Une refonte majeure de l'implémentation du noyau a eu lieu dans Linux 5.3. Les zones de l'API qui n'étaient pas clairement définies ont été clarifiées et les limites de l'API sont beaucoup plus strictement vérifiées que sur les noyaux précédents.

Depuis Linux 5.19, les copies inter-systèmes peuvent être réalisées lorsque les deux systèmes de fichiers sont du même type et que ce système de fichiers implémente la prise en charge. Voir BUGS pour le comportement avant Linux 5.19.

Les applications doivent cibler le comportement et les exigences de Linux 5.19, qui a également été rétroporté vers d'anciens noyaux stables.

NORMES

Linux, GNU.

HISTORIQUE

Linux 4.5, mais glibc 2.27 fournit une émulation en espace utilisateur lorsqu'elle n'est pas disponible.

NOTES

Si fd_in est un fichier creux (sparse file), alors copy_file_range() peut étendre tous les trous existant dans la plage demandée. Les utilisateurs peuvent bénéficier de l'appel de copy_file_range() dans une boucle, et utiliser les opérations lseek(2) SEEK_DATA et SEEK_HOLE pour trouver les emplacements des segments de données.

copy_file_range() donne aux systèmes de fichiers une opportunité d'implémenter des techniques d'« accélération de copie », telles que l'utilisation de reflinks (c'est-à-dire deux ou plusieurs inodes qui partagent des pointeurs vers les mêmes blocs de disque copy-on-write) ou de copie côté serveur (dans le cas de NFS).

_FILE_OFFSET_BITS doit être défini à 64 dans le code qui utilise off_in ou off_out non-NULL ou qui prend l'adresse de copy_file_range, si le code est destiné à être portable vers les plateformes x86 et ARM 32 bits traditionnelles où la largeur de off_t est par défaut de 32 bits.

BOGUES

Dans Linux 5.3 à Linux 5.18, les copies inter-systèmes de fichiers étaient implémentées par le noyau, si l'opération n'était pas prise en charge par les systèmes de fichiers individuels. Cependant, sur certains systèmes de fichiers virtuels, l'appel échouait à copier, tout en signalant un succès.

copy_file_range(2) — man pages

NAME

copy_file_range - copy a range of data between two file descriptors

LIBRARY

Standard C library (libc, -lc)

SYNOPSIS

#include <sys/syscall.h>
#include <unistd.h>

long copy_file_range(int fd_in, off64_t *off_in, int fd_out,
                       off64_t *off_out, size_t len, unsigned int flags);

DESCRIPTION

The copy_file_range() system call copies at most len bytes of data from a file descriptor fd_in to a file descriptor fd_out. The source file must be seekable. If off_in is not NULL, then the read offset in the source file is taken from the location pointed to by off_in. If off_in is NULL, then the read offset is the current file offset of fd_in. If off_in is not NULL, then the file offset is not updated after the copy. If off_in is NULL, then the file offset is updated by the number of bytes copied.

The destination file must be seekable. If off_out is not NULL, then the write offset in the destination file is taken from the location pointed to by off_out. If off_out is NULL, then the write offset is the current file offset of fd_out. If off_out is not NULL, then the file offset is not updated after the copy. If off_out is NULL, then the file offset is updated by the number of bytes copied.

The len argument specifies the maximum number of bytes to copy. The actual number of bytes copied can be less than len.

The flags argument is reserved for future use and must be set to 0.

If both off_in and off_out are NULL, then the copy is performed from the current file offset of fd_in to the current file offset of fd_out. Both file offsets are updated by the number of bytes copied.

The copy_file_range() call may return a value less than len even if all arguments are valid. This can happen if the disk is full, or if the end of the source file is reached.

The copy_file_range() call is intended to provide a mechanism for efficient file copying, potentially avoiding copying data through user space. An implementation may optimize the copy by using kernel-internal mechanisms, such as zero-copy data transfer.

This system call is useful for implementing efficient file copy utilities, such as cp(1), and for tasks like creating sparse files.

RETURN VALUE

On success, copy_file_range() returns the number of bytes copied. This value may be less than len.

On failure, copy_file_range() returns -1 and sets errno to indicate the error.

ERRORS

EBADF
fd_in or fd_out is not a valid file descriptor.
EACCES
File descriptor fd_in does not have read access, or file descriptor fd_out does not have write access.
EISDIR
fd_in or fd_out refers to a directory.
EINVAL
fd_in or fd_out is not seekable, or flags is not 0.
EINVAL
The source and destination file descriptors refer to the same file, and the specified offset range overlaps.
ENOTSUP
The underlying filesystem does not support this operation.
EXDEV
The source and destination file descriptors refer to files on different filesystems.
EFBIG
The destination file has reached the maximum size.
ENOSPC
No space left on the device.

VERSIONS

The copy_file_range() system call was introduced in Linux kernel 4.5.

STANDARDS

This system call is specific to Linux.

HISTORY

The copy_file_range() system call was added in kernel 4.5.

The copy_file_range() system call was made available via the glibc wrapper function in version 2.26.

NOTES

The copy_file_range() system call is intended to be a more general and flexible alternative to sendfile(2). It can be used for copying between any two file descriptors that support seeking, including regular files, and may avoid data transfer through user space.

The copy_file_range() system call can be used to create sparse files by copying a region containing all zeros from a source file to a destination file, without actually writing those zeros to disk.

If the source and destination file descriptors refer to the same file, copy_file_range() can be used to efficiently move data within the file, provided that the offset ranges do not overlap.

The copy_file_range() system call is not guaranteed to avoid user-space copying in all cases. The actual behavior depends on the underlying filesystem, the kernel version, and the specific arguments provided.

The copy_file_range() system call is atomic with respect to other copy_file_range() calls operating on the same file descriptors, but it is not atomic with respect to other operations on those file descriptors. For example, a read(2) or write(2) operation on one of the file descriptors might occur interleaved with the copy_file_range() operation.

When copying between two regular files, if both off_in and off_out are NULL, the number of bytes copied is returned. The file offsets are updated accordingly. If the number of bytes copied is less than len, it indicates that the end of the file was reached or an error occurred. In such cases, the caller should check errno to determine the cause.

BUGS

There are no known bugs at this time.

EXAMPLES

#include <stdio.h>
#include <stdlib.h>
#include <fcntl.h>
#include <sys/stat.h>
#include <unistd.h>
#include <errno.h>

int main(int argc, char *argv[]) {
    int fd_in, fd_out;
    struct stat stat;
    off_t size;
    ssize_t ret;

    if (argc != 3) {
        fprintf(stderr, "Usage: %s <source> <destination>\n", argv[0]);
        exit(EXIT_FAILURE);
    }

    fd_in = open(argv[1], O_RDONLY);
    if (fd_in == -1) {
        perror("open (argv[1])");
        exit(EXIT_FAILURE);
    }

    if (fstat(fd_in, &stat) == -1) {
        perror("fstat");
        exit(EXIT_FAILURE);
    }
    size = stat.st_size;

    fd_out = open(argv[2], O_CREAT | O_WRONLY | O_TRUNC, 0644);
    if (fd_out == -1) {
        perror("open (argv[2])");
        exit(EXIT_FAILURE);
    }

    // Copy the entire file in one go, if possible
    // For large files, a loop might be necessary if the kernel
    // doesn't support copying more than a certain amount in one call
    // or if the entire file size cannot be handled by size_t.
    // The example below uses a loop for demonstration purposes,
    // although typically you would try to copy the whole file at once
    // if possible.
    off_t total_copied = 0;
    while (size > 0) {
        ret = copy_file_range(fd_in, NULL, fd_out, NULL, size, 0);
        if (ret == -1) {
            if (errno == ENOSPC || errno == EFBIG) {
                fprintf(stderr, "Error: Not enough space on destination or file too large.\n");
                // Handle the error appropriately, maybe break or exit
            } else {
                perror("copy_file_range");
            }
            close(fd_in);
            close(fd_out);
            exit(EXIT_FAILURE);
        }
        if (ret == 0) {
            // End of file reached on source or nothing written
            break;
        }
        size -= ret;
        total_copied += ret;
    }

    printf("Successfully copied %lld bytes from %s to %s\n", (long long)total_copied, argv[1], argv[2]);

    close(fd_in);
    close(fd_out);
    exit(EXIT_SUCCESS);
}
