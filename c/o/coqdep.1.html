COQDEP(1) Manuel des commandes générales COQDEP(1)

NOM

coqdep - calculer les dépendances inter-modules pour les programmes Coq

SYNTAXE

coqdep [ -I répertoire ] [ -coqlib répertoire ] [ -i ] [ -slash ] nom_de_fichier ... répertoire ...

DESCRIPTION

coqdep calcule les dépendances inter-modules des programmes Coq et affiche les dépendances sur la sortie standard dans un format lisible par make. Lorsqu'un répertoire est donné en argument, il est parcouru récursivement.

Les dépendances des modules Coq sont calculées en examinant les commandes Require (Require, Require Export, Require Import, potentiellement restreintes par une clause From), les commandes Declare ML Module, les commandes Add LoadPath et les commandes Load. Les dépendances relatives aux modules de la bibliothèque Coq ne sont pas imprimées, sauf si l'option -boot est donnée.

OPTIONS

-f fichier
Lit les noms de fichiers et les options -I, -R et -Q à partir d'un fichier _CoqProject.
-I/-Q/-R options
Ont le même effet sur le chemin de chargement et les noms de modules que pour les autres commandes Coq (coqtop, coqc).
-coqlib répertoire
Indique où se trouve la bibliothèque Coq. La valeur par défaut a été déterminée lors de l'installation, et par conséquent, cette option ne devrait pas être utilisée dans des circonstances normales.
-exclude-dir rép
Ignore le sous-répertoire rép lors de la recherche -R/-Q.
-sort
Affiche le nom de fichier donné ordonné par dépendances.
-vos
Affiche les dépendances pour les fichiers .vos (ce n'est pas le défaut car cela casse le mode Coq de dune).
-boot
Pour les développeurs Coq, imprime les dépendances sur les fichiers de la bibliothèque Coq (omis par défaut).
-noinit
Aucun effet actuellement.
-vos
Inclut les dépendances concernant les fichiers .vos.
-dyndep (opt|byte|both|no|var)
Définit comment les dépendances sur les modules ML sont imprimées.
-m meta
Résout les noms de plugins en utilisant le fichier meta.
-w w1,...,wn
Configure l'affichage des avertissements comme pour coqc.

STATUT DE SORTIE

1
Un fichier donné sur la ligne de commande ne peut pas être trouvé, ou un fichier ne peut pas être ouvert, ou il y a une erreur de syntaxe dans l'une des commandes reconnues par coqdep.
0
Dans tous les autres cas. En particulier, lorsqu'une dépendance ne peut pas être trouvée ou qu'une option invalide est rencontrée, coqdep affiche un avertissement et se termine avec le statut 0.

VOIR AUSSI

ocamlc(1), coqc(1), make(1)

NOTES

Les analyseurs lexicaux (pour Coq et OCaml) gèrent correctement les commentaires imbriqués et les chaînes de caractères.

Le traitement des liens symboliques est rudimentaire.

Si deux fichiers ont le même nom, dans deux répertoires différents, un avertissement est affiché sur la sortie standard d'erreur.

Il n'y a aucun moyen de limiter la portée de la recherche récursive des répertoires.

EXEMPLES

Considérons les fichiers (dans le même répertoire) :

a.mllib, X.v, Y.v, et Z.v
où
  • a.mllib contient les noms de modules `B' et `C';
  • Y.v contient la commande `Require Foo.X';
  • Z.v contient les commandes `From Foo Require X' et `Declare ML Module "a"'.

Pour obtenir les dépendances des fichiers Coq :

exemple% coqdep -I . -Q . Foo *.v
X.vo X.glob X.v.beautified X.required_vo: X.v
Y.vo Y.glob Y.v.beautified Y.required_vo: Y.v X.vo
Z.vo Z.glob Z.v.beautified Z.required_vo: Z.v X.vo ./a.cma ./a.cmxs
