CONFIG_DATA(1p) Documentation Perl fournie par l'utilisateur CONFIG_DATA(1p)

NOM

config_data - Interroger ou modifier la configuration des modules Perl

SYNTAXE

# Obtenir les valeurs de configuration/fonctionnalités
config_data --module Foo::Bar --feature bazzable
config_data --module Foo::Bar --config magic_number
# Définir les valeurs de configuration/fonctionnalités
config_data --module Foo::Bar --set_feature bazzable=1
config_data --module Foo::Bar --set_config magic_number=42
# Afficher un message d'aide
config_data --help

DESCRIPTION

L'outil "config_data" fournit une interface en ligne de commande pour la configuration des modules Perl. Par "configuration", nous entendons quelque chose d'analogue à des "préférences utilisateur" ou des "paramètres locaux". Il s'agit d'une formalisation et d'une abstraction des systèmes que des personnes comme Andreas Koenig ("CPAN::Config"), Jon Swartz ("HTML::Mason::Config"), Andy Wardley ("Template::Config"), et Larry Wall (le propre Config.pm de Perl) ont développés indépendamment.

Le système de configuration utilisé ici a été développé dans le contexte de "Module::Build". Dans ce système, les informations de configuration pour un module "Foo", par exemple, sont stockées dans un module appelé "Foo::ConfigData" (Je l'aurais appelé "Foo::Config", mais ce nom était déjà pris par tous ces autres systèmes mentionnés dans le paragraphe précédent...). Ces modules "...::ConfigData" contiennent les données de configuration, ainsi que des méthodes publiquement accessibles pour interroger et définir (oui, effectivement réécrire) les données de configuration. Le script "config_data" (dont vous lisez actuellement la documentation) n'est qu'une interface pour ces méthodes. Si vous le souhaitez, vous pouvez créer d'autres interfaces.

Les deux types de données qui peuvent être stockées sont appelés valeurs "config" et valeurs "feature". Une valeur "config" peut être n'importe quel scalaire Perl, y compris des références à des structures de données complexes. Elle doit cependant être sérialisable en utilisant "Data::Dumper". Une "feature" est une valeur booléenne (1 ou 0).

UTILISATION

Ce script fonctionne comme un wrapper basique d'accès/modification autour de la configuration d'un seul module. Sur la ligne de commande, spécifiez quel module est concerné par la configuration, et passez des options pour obtenir ou définir des valeurs "config" ou "feature". Les options suivantes sont supportées :

module
Spécifie le nom du module à configurer (obligatoire).
feature
Lorsqu'elle reçoit le nom d'une "feature", affiche sa valeur. La valeur sera 1 si la fonctionnalité est activée, 0 si elle n'est pas activée, ou vide si la fonctionnalité est inconnue. Lorsqu'aucun nom de fonctionnalité n'est fourni, les noms et valeurs de toutes les fonctionnalités connues seront affichés.
config
Lorsqu'elle reçoit le nom d'une entrée "config", affiche sa valeur. La valeur sera affichée en utilisant "Data::Dumper" (ou similaire) comme code Perl. Lorsqu'aucun nom de configuration n'est fourni, les noms et valeurs de toutes les entrées de configuration connues seront affichés.
set_feature
Définit la "feature" donnée à la valeur booléenne donnée. Spécifiez la valeur comme 1 ou 0.
set_config
Définit l'entrée "config" donnée à la valeur donnée.
eval
Si l'option "--eval" est utilisée, les valeurs dans "set_config" seront évaluées comme du code Perl avant d'être stockées. Cela permet de stocker des structures de données moyennement complexes. Pour des structures vraiment complexes, vous ne devriez probablement pas utiliser cette interface en ligne de commande, utilisez plutôt l'API Perl.
help
Affiche un message d'aide, incluant quelques exemples, et quitte.
