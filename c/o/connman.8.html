CONNMAN(8) Manuel du gestionnaire système CONNMAN(8)

NOM

ConnMan - démon de gestion réseau

SYNOPSIS

connmand [--version|--help]

connmand [-c fichier] [-d fichier[,...]]] [-i interface[,...]] [-I interface[,...]] [-W pilote[,...]] [-p plugin[,...]] [-P plugin[,...]] [-n] [-r]

DESCRIPTION

ConnMan fournit un démon pour gérer les connexions internet sur les appareils exécutant le système d'exploitation Linux. Le Gestionnaire de Connexion est conçu pour être léger et consommer le moins de ressources possible. C'est un système entièrement modulaire qui peut être étendu, par des plugins, pour supporter tous types de technologies filaires ou sans fil. Aussi, les méthodes de configuration, comme DHCP et la résolution de noms de domaine, sont implémentées à l'aide de plugins. L'approche par plugins permet une adaptation et une modification faciles pour divers cas d'utilisation.

OPTIONS

Les options suivantes sont supportées :

-v, --version
Affiche la version du logiciel ConnMan et quitte.
-h, --help
Affiche les options disponibles de ConnMan et quitte.
-c fichier, --config=fichier
Spécifie le fichier de configuration pour paramétrer divers réglages pour ConnMan. Si non spécifié, la valeur par défaut /etc/connman/main.conf est utilisée. Voir connman.conf(5) pour plus d'informations sur le fichier de configuration. L'utilisation d'un fichier de configuration est optionnelle et des valeurs par défaut raisonnables sont utilisées si le fichier de configuration est manquant.
-d fichier[,...]], --debug[=fichier[,...]]
Définit la quantité d'informations que ConnMan envoie à la destination du journal (généralement la facilité "daemon" de syslog). Si les options de fichier sont omises, alors les informations de débogage de tous les fichiers source sont affichées. Si des options de fichier sont présentes, alors seuls les messages de débogage de ce fichier source sont affichés. Exemple :


connmand --debug=src/service.c,plugins/wifi.c

-i interface[,...], --device=interface[,...]
Ne gérer que ces interfaces réseau. Par défaut, toutes les interfaces réseau sont gérées.
-I interface[,...], --nodevice=interface[,...]
Ne jamais gérer ces interfaces réseau. L'option peut être un modèle contenant les caractères "*" et "?".
-p plugin[,...], --plugin=plugin[,...]
Charger uniquement ces plugins. L'option peut être un modèle contenant les caractères "*" et "?".
-P plugin[,...], --noplugin=plugin[,...]
Ne jamais charger ces plugins. L'option peut être un modèle contenant les caractères "*" et "?".
-W pilote[,...], --wifi=pilote[,...]
Pilote Wifi que WiFi/Supplicant doit utiliser. Si ce drapeau est omis, alors la valeur "nl80211,wext" est utilisée par défaut.
-n, --nobacktrace
Ne pas afficher les informations de backtrace.
-n, --nodaemon
Ne pas passer en mode démon. Ceci est utile pour le débogage, et dirige la sortie du journal vers le terminal de contrôle en plus de syslog.
-r, --nodnsproxy
Ne pas agir en tant que proxy DNS ni supporter la résolution DNS externe. Selon la façon dont ConnMan est compilé, il se dirigera par défaut vers lui-même pour tout le trafic DNS en définissant le serveur de noms sur 127.0.0.1 dans le fichier resolv.conf(5) ou laissera la gestion DNS à une entité externe, telle que systemd-resolved. Si ce n'est pas souhaité et que vous voulez que tous les programmes appellent directement un serveur DNS, alors vous pouvez utiliser l'option --nodnsproxy. ConnMan déterminera alors le serveur DNS et le domaine de recherche au démarrage et les configurera dans resolv.conf(5). Si cette option est utilisée, ConnMan ne pourra pas mettre en cache les requêtes DNS car le trafic DNS ne passera pas par ConnMan, ce qui peut entraîner un trafic réseau supplémentaire.
