/proc/sys/kernel/core_pipe_limi

t

Lors de la collecte de core dumps via un pipe vers un programme en espace utilisateur, il peut être utile pour le programme collecteur de rassembler des données sur le processus planté à partir du répertoire /proc/pid de ce processus. Afin de le faire en toute sécurité, le noyau doit attendre que le programme collectant le core dump se termine, afin de ne pas supprimer prématurément les fichiers /proc/pid du processus planté. Cela crée à son tour la possibilité qu'un programme collecteur défaillant bloque le récoltage d'un processus planté en ne se terminant tout simplement

jamais.

Depuis Linux 2.6.32, le /proc/sys/kernel/core_pipe_limit peut être utilisé pour se défendre contre cette possibilité. La valeur dans ce fichier définit combien de processus en cours de plantage peuvent être acheminés vers des programmes en espace utilisateur en parallèle. Si cette valeur est dépassée, alors les processus plantés au-delà de cette valeur sont notés dans le journal du noyau et leurs core dumps sont

ignorés.

Une valeur de 0 dans ce fichier est spéciale. Elle indique qu'un nombre illimité de processus peuvent être capturés en parallèle, mais qu'aucune attente n'aura lieu (c.-à-d. que le programme collecteur n'est pas garanti d'avoir accès à /proc/<PID-du-processus-planté>). La val

eur par défaut pour
ce fichier est 0.

Core dumps et

systemd

Sur les systèmes utilisant le framework d'initialisation systemd(1), les core dumps peuvent être placés dans un emplacement déterminé par systemd(1). Pour ce faire, systemd(1) utilise la fonctionnalité core_pattern qui permet d'acheminer les core dumps vers un programme. On peut vérifier cela en vérifiant si les core dumps sont acheminés vers le programme systemd-coredump(8)

: 


$ cat /proc/sys/kernel/core_pattern;
|/usr/lib/systemd/systemd-coredump %P %u %g %s %t %c
%e

Dans ce cas, les core dumps seront placés dans l'emplacement configuré pour systemd-coredump(8), généralement en tant que fichiers compressés lz4(1) dans le répertoire /var/lib/systemd/coredump/. On peut lister les core dumps qui ont été enregistrés par systemd-coredump(8) en utilisant coredumpctl(1)

: 
$ coredumpctl list | tail -5;
Wed 2017-10-11 22:25:30 CEST  2748 1000 1000 3 present  /usr/bin/sleep
Thu 2017-10-12 06:29:10 CEST  2716 1000 1000 3 present  /usr/bin/sleep
Thu 2017-10-12 06:30:50 CEST  2767 1000 1000 3 present  /usr/bin/sleep
Thu 2017-10-12 06:37:40 CEST  2918 1000 1000 3 present  /usr/bin/cat
Thu 2017-10-12 08:13:07 CEST  2955 1000 1000 3 present
/usr/bin/cat

Les informations affichées pour chaque core dump incluent la date et l'heure du vidage, le PID, l'UID et le GID du processus en cours de vidage, le numéro de signal qui a causé le core dump, et le chemin de l'exécutable qui était en cours d'exécution par le processus vidé. Diverses options de coredumpctl(1) permettent de récupérer un fichier coredump spécifié depuis l'emplacement systemd(1) vers un fichier spécifié. Par exemple, pour extraire le core dump du PID 2955 montré ci-dessus vers un fichier nommé core dans le répertoire courant, on pourrait utiliser

: 


$ coredumpctl dump 295
5 -o core;

Pour plus de détails, voir la page de manuel coredumpct

l(1).

Pour (de manière persistante) désactiver le mécanisme systemd(1) qui archive les core dumps, restaurant un comportement plus proche du comportement Linux traditionnel, on peut définir une surcharge pour le mécanisme systemd(1), en utilisant quelque chose comme

# echo "kernel.core_pattern=core.%p" > \;

/* core_pattern_pipe_test.c */
#define _GNU_SOURCE
#include <sys/stat.h>
#include <fcntl.h>
#include <limits.h>
#include <stdio.h>
#include <stdlib.h>
#include <unistd.h>
#define BUF_SIZE 1024
int
main(int argc, char *argv[])
{
    ssize_t nread, tot;
    char buf[BUF_SIZE];
    FILE *fp;
    char cwd[PATH_MAX];
    /* Change our current working directory to that of the
       crashing process.  */
    snprintf(cwd, PATH_MAX, "/proc/%s/cwd", argv[1]);
    chdir(cwd);
    /* Write output to file "core.info" in that directory.  */
    fp = fopen("core.info", "w+");
    if (fp == NULL)
        exit(EXIT_FAILURE);
    /* Display command-line arguments given to core_pattern
       pipe program.  */
    fprintf(fp, "argc=%d\n", argc);
    for (size_t j = 0; j < argc; j++)
        fprintf(fp, "argc[%zu]=<%s>\n", j, argv[j]);
    /* Count bytes in standard input (the core dump).  */
    tot = 0;
    while ((nread = read(STDIN_FILENO, buf, BUF_SIZE)) > 0)
        tot += nread;
    fprintf(fp, "Total bytes in core dump: %zd\n", tot);
    fclose(fp);
    exit(EXIT_SUCCESS)
;
}
