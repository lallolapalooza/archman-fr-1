NOM

Convert::BinHex - extraire les données des fichiers BinHex Macintosh

AVERTISSEMENT ALPHA : ce code est actuellement en version alpha. Des changements drastiques peuvent survenir tant que l'interface n'est pas stabilisée : si vous avez des suggestions ou des objections, parlez-en maintenant !

RÉSUMÉ

Fonctions simples :

use Convert::BinHex qw(binhex_crc macbinary_crc);
# Calculer le CRC de style HQX7 pour les données, en injectant l'ancien CRC si désiré :
$crc = binhex_crc($data, $crc);
# Calculer le CRC de style MacBinary-II pour les données :
$crc = macbinary_crc($data, $crc);

Hex vers bin, interface de bas niveau. La conversion est en fait effectuée via un objet ("Convert::BinHex::Hex2Bin") qui conserve l'état interne de la conversion :

# Créer et utiliser un objet "traducteur" :
my $H2B = Convert::BinHex->hex2bin;    # obtenir un objet convertisseur
while (<STDIN>) {
    print $STDOUT $H2B->next($_);        # convertir un peu plus d'entrée
}
print $STDOUT $H2B->done;              # plus d'entrée : terminer

Hex vers bin, interface orientée objet. Les opérations suivantes doivent être effectuées dans l'ordre indiqué !

# Lire les données par morceaux :
$HQX = Convert::BinHex->open(FH=>\*STDIN) || die "open: $!";
$HQX->read_header;                  # lire les informations d'en-tête
@data = $HQX->read_data;            # lire toutes les données
@rsrc = $HQX->read_resource;        # lire toutes les ressources

Bin vers hex, interface de bas niveau. La conversion est en fait effectuée via un objet ("Convert::BinHex::Bin2Hex") qui conserve l'état interne de la conversion :

# Créer et utiliser un objet "traducteur" :
my $B2H = Convert::BinHex->bin2hex;    # obtenir un objet convertisseur
while (<STDIN>) {
    print $STDOUT $B2H->next($_);        # convertir un peu plus d'entrée
}
print $STDOUT $B2H->done;              # plus d'entrée : terminer

Bin vers hex, interface fichier. Oui, vous pouvez convertir vers BinHex aussi bien que depuis celui-ci !

# Créer un nouvel objet vide :
my $HQX = Convert::BinHex->new;
# Définir les attributs d'en-tête :
$HQX->filename("logo.gif");
$HQX->type("GIFA");
$HQX->creator("CNVS");
# Lui donner les forks de données et de ressources (l'un ou l'autre peut être absent) :
$HQX->data(Path => "/path/to/data");       # ici, les données sont sur disque
$HQX->resource(Data => $resourcefork);     # ici, les ressources sont en mémoire
# Sortir sous forme de flux BinHex, avec le commentaire d'introduction :
$HQX->encode(\*STDOUT);

PRÉVU !!!! Bin vers hex, interface "CAP". Merci à Ken Lunde d'avoir suggéré ceci.

# Créer un nouvel objet vide à partir d'un arbre CAP :
my $HQX = Convert::BinHex->from_cap("/path/to/root/file");
$HQX->encode(\*STDOUT);

DESCRIPTION

BinHex est un format utilisé par Macintosh pour transporter des fichiers Mac de manière sûre par courrier électronique, sous forme de flux de données ASCII 7 bits, semi-compressés et à lignes courtes. Ce module fournit un moyen de convertir ces flux de données en données binaires.

FORMAT

(Certains textes proviennent de la RFC-1741.) Les fichiers sur Macintosh se composent de deux parties, appelées forks:

Fork de données
Les données réelles incluses dans le fichier. Le fork de données est généralement la seule partie significative d'un fichier Macintosh sur un système non-Macintosh. Par exemple, si un utilisateur Macintosh veut envoyer un fichier de données à un utilisateur sur un IBM-PC, il n'enverra que le fork de données.
Fork de ressources
Contient une collection de paires attribut/valeur arbitraires, incluant des segments de programme, des bitmaps d'icônes et des valeurs paramétriques.

Les informations supplémentaires concernant les fichiers Macintosh sont stockées par le Finder dans un fichier caché, appelé la "Base de données du Bureau".

En raison des complications liées au stockage des différentes parties d'un fichier Macintosh dans un système de fichiers non-Macintosh qui ne gère que des données contiguës en une seule partie, il est courant de convertir le fichier Macintosh dans un autre format avant de le transférer sur le réseau. Le format BinHex compacte ces données en ASCII transmissible comme suit :

1.
Le fichier est produit sous forme de flux d'octets composé de quelques informations d'en-tête de base (nom de fichier, type, créateur), puis du fork de données, puis du fork de ressources.
2.
Le flux d'octets est compressé en recherchant des séries d'octets dupliqués et en les représentant à l'aide d'une séquence d'échappement binaire spéciale (bien sûr, toute occurrence du caractère d'échappement doit également être échappée).
3.
Le flux compressé est encodé via la "6/8 hemiola" commune au base64 et au uuencode: chaque groupe de trois octets de 8 bits (24 bits) est découpé en quatre nombres de 6 bits, qui sont utilisés comme index dans un "alphabet" ASCII. (Je suppose que les octets restants sont complétés par des zéros ; la documentation est sommaire).

FONCTIONS

Calcul de CRC

macbinary_crc DATA, SEED
Calcule le CRC de style MacBinary-II pour les DATA données, avec le CRC initialisé à SEED. Normalement, vous commencez avec un SEED de 0, et vous injectez le CRC précédent comme SEED si vous traitez beaucoup de données un morceau à la fois. C'est-à-dire : 
$crc = 0;
while (<STDIN>) {
    $crc = macbinary_crc($_, $crc);
}

Remarque : Extrait de l'utilitaire mcvert (Doug Moore, avril '87), utilisant un algorithme de "table magique" de Jim Van Verth pour l'efficacité. Converti en Perl5 par Eryq. Non testé.

binhex_crc DATA, SEED
Calcule le CRC de style HQX pour les DATA données, avec le CRC initialisé à SEED. Normalement, vous commencez avec un SEED de 0, et vous injectez le CRC précédent comme SEED si vous traitez beaucoup de données un morceau à la fois. C'est-à-dire : 
$crc = 0;
while (<STDIN>) {
    $crc = binhex_crc($_, $crc);
}

Remarque : Extrait de l'utilitaire mcvert (Doug Moore, avril '87), utilisant un algorithme de "table magique" de Jim Van Verth pour l'efficacité. Converti en Perl5 par Eryq.

INTERFACE ORIENTÉE OBJET

Conversion

bin2hex
Méthode de classe, constructeur. Retourne un objet convertisseur. Crée simplement une nouvelle instance de "Convert::BinHex::Bin2Hex" ; voir cette classe pour les détails.
hex2bin
Méthode de classe, constructeur. Retourne un objet convertisseur. Crée simplement une nouvelle instance de "Convert::BinHex::Hex2Bin" ; voir cette classe pour les détails.

Construction

new PARAMHASH
Méthode de classe, constructeur. Retourne un handle sur une entité convertible en BinHex. En général, les forks de données et de ressources d'une telle entité sont stockés au format natif (binaire).

Les paramètres dans le PARAMHASH sont les mêmes que les noms de méthodes orientés en-tête, et peuvent être utilisés pour définir des attributs :

$HQX = new Convert::BinHex filename => "icon.gif",
                           type    => "GIFB",
                           creator => "CNVS";
open PARAMHASH
Méthode de classe, constructeur. Retourne un handle sur un nouveau flux encodé en BinHex, pour l'analyse. Les paramètres sont :
Data
Lit un flux HEX à partir des données données. Il peut s'agir d'un scalaire, ou d'une référence à un tableau de scalaires.
Expr
Lit un flux HEX à partir de toute expression open()utilisable. Elle sera ouverte et passée en binmode, et le filehandle sera fermé soit sur close() soit lorsque l'objet sera détruit.
FH
Lit un flux HEX à partir du filehandle donné.
NoComment
Si vrai, l'analyseur ne doit pas tenter de sauter un commentaire d'introduction "(This file...)"t; commentaire. Cela signifie que les premiers caractères non blancs rencontrés doivent être les données encodées en binhex.

Obtenir/définir les informations d'en-tête

creator [VALUE]
Méthode d'instance. Obtenir/définir le créateur du fichier. Il s'agit d'une chaîne de quatre caractères (bien que je ne sache pas si elle est garantie d'être en ASCII imprimable !) qui sert de partie de la version Macintosh d'un « content-type » MIME.

Par exemple, un document créé par « Canvas » pourrait avoir comme créateur "CNVS".

data [PARAMHASH]
Méthode d'instance. Obtenir/définir le data fork. Tous les arguments sont passés à la new() méthode de "Convert::BinHex::Fork".
filename [VALUE]
Méthode d'instance. Obtenir/définir le nom du fichier.
flags [VALUE]
Méthode d'instance. Retourne les drapeaux (flags), sous forme d'entier. Utilisez des masques binaires (bitmasking) pour obtenir les valeurs dont vous avez besoin.
header_as_string
Retourne une version sous forme de chaîne de l'en-tête que vous pourriez utiliser à des fins de journalisation/débogage. Elle ressemble à ceci : 
X-HQX-Software: BinHex 4.0 (Convert::BinHex 1.102)
X-HQX-Filename: Something_new.eps
X-HQX-Version: 0
X-HQX-Type: EPSF
X-HQX-Creator: ART5
X-HQX-Data-Length: 49731
X-HQX-Rsrc-Length: 23096

Comme certains d'entre vous l'auront peut-être deviné, ceci est de style RFC-822, et peut être facilement inséré au milieu d'un en-tête de courriel, ou divisé en lignes, etc.

requires [VALUE]
Méthode d'instance. Obtenir/définir la version du logiciel requise pour convertir ce fichier, telle qu'extraite du commentaire qui précédait les données binhex'ées réelles ; par ex. : 
(This file must be converted with BinHex 4.0)

Dans ce cas, après avoir analysé le commentaire, le code :

$HQX->requires;

renverrait "4.0".

resource [PARAMHASH]
Méthode d'instance. Obtenir/définir le resource fork. Tous les arguments sont passés à la new() méthode de "Convert::BinHex::Fork".
type [VALUE]
Méthode d'instance. Obtenir/définir le type du fichier. Il s'agit d'une chaîne de quatre caractères (bien que je ne sache pas si elle est garantie d'être en ASCII imprimable !) qui sert de partie de la version Macintosh d'un « content-type » MIME.

Par exemple, un fichier GIF89a pourrait avoir comme type "GF89".

version [VALUE]
Méthode d'instance. Obtenir/définir la version, sous forme d'entier.

Décodage, haut niveau

read_comment
Méthode d'instance. Passe le commentaire d'ouverture du fichier, qui est de la forme : 
(This file must be converted with BinHex 4.0)

Conformément à la RFC-1741, ce commentaire doit immédiatement précéder les données BinHex, et tout texte avant celui-ci sera ignoré.

Vous n'avez pas besoin d'invoquer cette méthode vous-même ; read_header() le fera pour vous. Après l'appel, le numéro de version dans le commentaire est accessible via la requires() méthode.

read_header
Méthode d'instance. Lit l'en-tête du fichier BinHex. Vous devez faire cela en premier !
read_data [NBYTES]
Méthode d'instance. Lit des informations depuis le data fork. Utilisez-la dans un contexte de tableau pour lire toutes les données dans un tableau de scalaires : 
@data = $HQX->read_data;

Ou utilisez-la dans un contexte scalaire pour obtenir les données par morceaux :

while (defined($data = $HQX->read_data)) {
   # do stuff with $data
}

Le NBYTES à lire par défaut est 2048.

read_resource [NBYTES]
Méthode d'instance. Lit tout ou partie du resource fork. Voir read_data() pour l'utilisation.

Encodage, haut niveau

encode OUT
Encode l'objet en un flux BinHex vers la sortie donnée OUT. OUT peut être un filehandle, ou n'importe quel objet béni qui répond au message print() .

Le commentaire initial est produit, en utilisant l'attribut requires() .

SOUS-MODULES

Convert::BinHex::Bin2Hex

Un convertisseur BINary-to-HEX. Ce type de conversion nécessite une certaine quantité d'informations d'état ; elle ne peut pas être faite en appelant simplement une fonction de manière répétée. Utilisez-le comme ceci :

# Create and use a "translator" object:
my $B2H = Convert::BinHex->bin2hex;    # get a converter object
while (<STDIN>) {
    print STDOUT $B2H->next($_);          # convert some more input
}
print STDOUT $B2H->done;               # no more input: finish up
# Re-use the object:
$B2H->rewind;                 # ready for more action!
while (<MOREIN>) { ...

À chaque itération, next() (et done()) peut retourner soit une chaîne non vide de taille décente (indiquant que plus de données converties sont prêtes pour vous) soit une chaîne vide (indiquant que le convertisseur attend d'amasser plus d'entrée dans ses tampons privés avant de vous remettre plus de choses à produire en sortie.

Notez que done() convertit toujours et vous remet ce qui reste.

Cela aurait pu être une bonne approche. Cela peut ne pas l'être. Un jour, le convertisseur pourrait aussi vous permettre de lui donner un objet qui répond à read(), ou un FileHandle, et il fera tout le remplissage de tampon fastidieux lui-même, en vous servant les choses ligne par ligne :

# Someday, maybe...
my $B2H = Convert::BinHex->bin2hex(\*STDIN);
while (defined($_ = $B2H->getline)) {
    print STDOUT $_;
}

Un jour, peut-être. N'hésitez pas à exprimer vos opinions.

Convert::BinHex::Hex2Bin

Un convertisseur HEX-to-BINary. Ce type de conversion nécessite une certaine quantité d'informations d'état ; elle ne peut pas être faite en appelant simplement une fonction de manière répétée. Utilisez-le comme ceci :

# Create and use a "translator" object:
my $H2B = Convert::BinHex->hex2bin;    # get a converter object
while (<STDIN>) {
    print STDOUT $H2B->next($_);          # convert some more input
}
print STDOUT $H2B->done;               # no more input: finish up
# Re-use the object:
$H2B->rewind;                 # ready for more action!
while (<MOREIN>) { ...

À chaque itération, next() (et done()) peut retourner soit une chaîne non vide de taille décente (indiquant que plus de données converties sont prêtes pour vous) soit une chaîne vide (indiquant que le convertisseur attend d'amasser plus d'entrée dans ses tampons privés avant de vous remettre plus de choses à produire en sortie.

Notez que done() convertit toujours et vous remet ce qui reste.

Notez que ce convertisseur ne trouve pas le commentaire initial de « BinHex version ». Vous devez le sauter vous-même. Il ne traite que les données entre les ":"d'ouverture et de fermeture.

Convert::BinHex::Fork

Un fork dans un fichier Macintosh.

# How to get them...
$data_fork = $HQX->data;      # get the data fork
$rsrc_fork = $HQX->resource;  # get the resource fork
# Make a new fork:
$FORK = Convert::BinHex::Fork->new(Path => "/tmp/file.data");
$FORK = Convert::BinHex::Fork->new(Data => $scalar);
$FORK = Convert::BinHex::Fork->new(Data => \@array_of_scalars);
# Get/set the length of the data fork:
$len = $FORK->length;
$FORK->length(170);        # this overrides the REAL value: be careful!
# Get/set the path to the underlying data (if in a disk file):
$path = $FORK->path;
$FORK->path("/tmp/file.data");
# Get/set the in-core data itself, which may be a scalar or an arrayref:
$data = $FORK->data;
$FORK->data($scalar);
$FORK->data(\@array_of_scalars);
# Get/set the CRC:
$crc = $FORK->crc;
$FORK->crc($crc);

SOUS LE CAPOT

Problèmes de conception

BinHex nécessite un analyseur avec état
Contrairement à ses cousins base64 et uuencode, le format BinHex n'est pas propice à être analysé ligne par ligne. Il ne semble pas y avoir de garantie que les lignes contiennent 4n caractères encodés... et même s'il y en a une, l'algorithme de compression BinHex interfère : même lorsque vous pouvez décoder une ligne à la fois, vous ne pouvez pas nécessairement décompresser une ligne à la fois.

Par exemple : une ligne décodée se terminant par l'octet "\x90" (le caractère d'échappement ou « mark ») est ambiguë : selon l'octet décodé suivant, elle pourrait signifier un "\x90" littéral (si l'octet suivant est un "\x00"), ou elle pourrait signifier n-1 répétitions supplémentaires du caractère précédent (si l'octet suivant est un quelconque "n"non nul).

Pour cette raison, un analyseur BinHex doit être quelque peu avec état : vous ne pouvez pas avoir de code comme ceci :

#### NO! #### NO! #### NO! #### NO! #### NO! ####
while (<STDIN>) {            # read HEX
    print hexbin($_);          # convert and write BIN
}

à moins qu'il ne se passe quelque chose « en coulisses » pour garder une trace de ce qui a été fait en dernier.
