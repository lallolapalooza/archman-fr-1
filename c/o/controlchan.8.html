CONTROLCHAN(8) Documentation InterNetNews CONTROLCHAN(8)

NOM

controlchan - Gestionnaire de messages de contrôle alimenté par canal

SYNTAXE

controlchan [-ch]

DESCRIPTION

controlchan retire la responsabilité de la gestion des messages de contrôle (sauf les annulations) à innd et les traite plutôt à partir d'un canal ou d'un flux de fichiers.

Les deux modules Perl "Encode" et "MIME::Parser" sont requis par controlchan.

Pour réduire la charge, controlchan conserve une copie de control.ctl et control.ctl.local en mémoire et vérifie les permissions (y compris les en-têtes PGP requis) avant que tout script ne soit appelé. Ces deux fichiers de configuration sont automatiquement rechargés lorsque controlchan détecte qu'ils ont été modifiés. De plus, le cas par défaut d'un article de contrôle non reconnu est géré en interne. Le cas "drop" est géré avec beaucoup moins de tracas.

Normalement, controlchan est invoqué par innd comme configuré dans newsfeeds. Un exemple d'entrée est ci-dessous. Assurez-vous que le groupe de nouvelles "control.cancel" existe afin que controlchan n'ait pas à analyser les annulations, qu'il ne traitera de toute façon pas.

controlchan!\
    :!*,control,control.*,!control.cancel\
    :AC,Tc,Wnsm\
    :<chemin vers bin dans inn.conf>/controlchan

controlchan peut également être invoqué manuellement avec un simple chemin vers un fichier (contenant un article de contrôle complet avec ses en-têtes et son corps) ou un jeton sur son entrée standard :

echo '/chemin/vers/un/article/de/contrôle' | controlchan
echo '@0303465234000000000000235AE000000002@' | controlchan

Notez que dans le cas (très, très improbable) où vous auriez besoin de traiter les messages de contrôle ihave/sendme, assurez-vous que logipaddr est défini sur false dans inn.conf, car dans ce cas, controlchan a besoin d'un nom de site, et non d'une adresse IP.

controlchan essaie de rapporter tous les messages de journalisation via syslog(3), sauf s'il est connecté à un terminal interactif.

OPTIONS

-c
Par défaut, controlchan ne traite pas les articles dont les champs d'en-tête Date ou Injection-Date sont trop anciens (plus de artcutoff jours, tels que définis dans inn.conf) ou un jour dans le futur. Cela permet d'empêcher une relecture malveillante de vieux articles de contrôle.

L'utilisation de l'indicateur -c désactive cette vérification sur la date limite.

-h
Affiche les informations d'utilisation.
