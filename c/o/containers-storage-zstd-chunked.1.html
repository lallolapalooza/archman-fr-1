NOM

containers-storage-zstd-chunked - Informations sur zstd:chunked

DESCRIPTION

Le format traditionnel pour les couches d'images de conteneurs est application/vnd.oci.image.layer.v1.tar+gzip ⟨https://github.com/opencontainers/image-spec/blob/main/layer.md#gzip-media-types⟩. Plus récemment, la norme a été complétée par zstd : application/vnd.oci.image.layer.v1.tar+zstd ⟨https://github.com/opencontainers/image-spec/blob/main/layer.md#zstd-media-types⟩ qui est un format de compression plus moderne et efficace.

zstd:chunked est une variante du type de média application/vnd.oci.image.layer.v1.tar+zstd qui utilise des images sautables zstd ⟨https://github.com/facebook/zstd/blob/dev/doc/zstd_compression_format.md#skippable-frames⟩ pour inclure des métadonnées supplémentaires (en particulier une « table des matières ») qui incluent le SHA-256 et les décalages de morceaux individuels de fichiers. De plus, les morceaux sont compressés séparément. Cela permet à un client de ne récupérer dynamiquement que le contenu qu'il ne possède pas déjà en utilisant des requêtes de plage HTTP.

Au moment de la rédaction, la prise en charge de cela est activée par défaut dans le code.

Vous pouvez activer ou désactiver explicitement zstd:chunked avec les modifications suivantes dans containers-storage.conf :

[storage.options.pull_options]
enable_partial_images = "true" | "false"

Notez que la valeur de ce champ doit être une « chaîne booléenne », elle ne peut pas être un booléen TOML natif.

IMPLÉMENTATION

Chaque couche a une clé associée « big data » appelée chunked-manifest-cache qui est un format binaire personnalisé adapté à mmap() et qui contient des métadonnées d'index pour chaque couche avec le digest sha256 complet de chaque fichier plus ses « morceaux » (tels que calculés par zstd:chunked).

Lorsque toute image est récupérée, toutes les autres couches existantes sont analysées à l'aide de chunked-manifest-cache pour voir si elles contiennent un fichier avec un digest correspondant. Si un tel fichier est trouvé, l'autre fichier est lié en dur si use_hardlinks = "true", sinon il est reflinké (si pris en charge par le système de fichiers, ou une copie physique complète est effectuée). Une tentative est faite pour activer fsverity sur le fichier s'il est configuré (voir ⟨https://github.com/containers/storage/issues/2017⟩).

Pour plus d'informations, au moment de la rédaction, le fichier contenant le plus d'informations est pkg/chunked/internal/compression.go ⟨https://github.com/containers/storage/blob/39d469c34c96db67062e25954bc9d18f2bf6dae3/pkg/chunked/internal/compression.go⟩. Ce qui précède est un lien permanent pour la stabilité, mais assurez-vous de vérifier s'il y a également de nouveaux changements.

STANDARDIZATION

Au moment de la rédaction, le format n'est pas officiellement standardisé ou documenté au-delà des commentaires et du code dans l'implémentation de référence.

NOTES

Ce langage est problématique et divise, et devrait être modifié. Cependant, ces termes sont actuellement utilisés dans le noyau Linux et doivent être utilisés tels quels à ce moment-là. Lorsque les mainteneurs du noyau rectifieront cette utilisation, Containers Storage suivra immédiatement.
