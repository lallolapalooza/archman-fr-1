DESCRIPTIO

N

Ceci est un module interne qui permet d'utiliser des méthodes orientées objet pour accéder à des parties de votre fichier de

configuration.

Normalement, vou

s ne l'appelez
pas directement.

MÉTHODE

S
configfile('filenam
e')
Définit le nom de fichier à utiliser par save vers « filename ». Elle renvoie le nom de fichier actuellement configuré si elle est appelée sans
arguments.
obj('key
')
Renvoie un nouvel objet (de la classe Config::General::Extended) à partir de la clé donnée. Court exemple : supposons que vous ayez la configuration suivante : 
<individual>
     <martin>
        age   23
     </martin>
     <joseph>
        age   56
     </joseph>
</individual>
<other>
     blah     blubber
     blah     gobble
     leer
</other>

et que vous l'ayez déjà lue en utilisant Config::General::Extended::new(), alors vous pouvez obtenir un nouvel objet à partir du bloc « individual » de cette

manière : 
$individual = $conf->obj("individual")
;

Maintenant, si vous appelez getall sur $individual (juste pour référence) vous

obtiendriez : 
$VAR1 = (
   martin => { age => 13 }
);

Ou, voici une autre

utilisation : 
my $individual = $conf->obj("individual");
foreach my $person ($conf->keys("individual")) {
   $man = $individual->obj($person);
   print "$person is " . $man->value("age") . " years old\n";
}

Voir la discussion sur hash() et value()

ci-dessous.

Si la clé à partir de laquelle vous voulez créer un nouvel objet est vide, un objet vide sera renvoyé. Si vous exécutez ce qui suit sur la configuration

ci-dessus : 
$obj = $conf->obj("other")->obj("leer")
;

Alors $obj sera vide, comme si vous aviez exécuté

ceci : 
$obj = Config::General::Extended->new(
() );

Les opérations de lecture sur cet objet vide ne renverront rien ou échoueront même. Mais vous pouvez utiliser un objet vide pour créer une nouvelle configuration en utilisant des opérations d'écriture,

c'est-à-dire : 
$obj->someoption("value")
;

Voir la discussion sur MÉTHODES AUTOLOAD c

i-dessous.

Si la clé pointe vers une liste de hashs, une liste d'objets sera renvoyée. Étant donné l'exemple de configuration

suivant : 
<option>
  name = max
</option>
<option>
  name = bea
</option>

vous pourriez écrire du code comme ceci pour accéder à la liste de manière

OOP : 
my $objlist = $conf->obj("option");
foreach my $option (@{$objlist}) {
 print $option->
name; }

Veuillez noter que la liste sera renvoyée comme une référence vers un

tableau.

Les éléments vides ou les éléme

nts non-hash de la liste, s'il
y en a, seront ignorés.
hash('key
')
Cette méthode renvoie un hash (si c'en est un !) de la configuration qui est référencée par « key ». Étant donné l'exemple de configuration ci-dessus, vous obtiendriez : 
my %sub_hash = $conf->hash("individual");
print Dumper(\%sub_hash);
$VAR1 = {
   martin => { age => 13 }
};
array('key
')
C'est l'équivalent de hash() mentionné ci-dessus, sauf qu'il renvoie un tableau. Encore une fois, nous utilisons l'exemple de configuration mentionné ci-dessus : 
$other = $conf->obj("other");
my @blahs
= $other->array("blah"); print Dumper(\@
blahs); $VAR1 = [ "blubber", "gobble" ];
value('key
')
Cette méthode renvoie la valeur scalaire d'une clé donnée. Étant donné l'exemple de configuration suivant : 
name  = arthur
age
= 23

vous pourriez faire quelque chose

comme ceci : 
print $conf->value("name") . " is " . $conf->value("age") . " years
old\n";

Vous pouvez aussi utiliser cette méthode pour définir la valeur de « key » à quelque chose si vous fournissez en plus de la clé une référence de hash, une référence de tableau ou un scalaire. Un

exemple : 
$conf->value("key", \%somehash);
# ou
$conf->value("key", \@somearray);
# ou
$conf->value("key", $somescalar)
;

Veuillez noter que cette méthode ne se plaint pas des valeurs existantes dans «

key
» !
is_hash('key') is_array('key')
is_scalar('key')
Comme vu ci-dessus, vous pouvez accéder à des parties de votre configuration actuelle en utilisant les méthodes hash, tableau ou scalaire. Mais vous avez raison de deviner que cela pourrait devenir problématique si, par exemple, vous appelez hash() sur une clé qui n'est en réalité pas un hash mais un scalaire. Dans des circonstances normales, perl refuserait cela et mourrait.

Pour éviter un tel comportement, vous pouvez utiliser l'une des méthodes is_hash() is_array() is_scalar() pour vérifier si la valeur de « key » est vraiment ce que vous attendez qu'elle

soit.

Un exemple (basé sur l'exemple de configuration

ci-dessus) : 
if($conf->is_hash("individual") {
   $individual = $conf->obj("individual");
}
else {
   die "You need to configure a "individual" block!
\n";
}
exists('key
')
Cette méthode renvoie juste vrai si la clé donnée existe dans la
configuration.
keys('key
')
Renvoie un tableau des clés sous la « key » spécifiée. Si vous utilisez l'exemple de configuration ci-dessus, vous pourriez faire ceci : 
print Dumper($conf->keys("individual");
$VAR1 = [ "martin", "joseph"
];

Si aucun nom de clé n'a été fourni, alors les clés de l'objet lui-même seront

renvoyées.

Vous pouvez utiliser cette méthode dans des boucles foreach comme vu dans un exemple ci-dessus (obj(

delete('key
')
Cette méthode supprime la clé donnée et toutes les données associées de la structure de hash interne. Si « key » contenait des données, alors ces données seront renvoyées, sinon undef sera
renvoyé.

t)
Étant donné une liste de nœuds, ->find cherchera un arbre qui se ramifie de cette manière exacte, renvoyant l'objet Config::General::Extended qu'il trouve au bas s'il existe. Vous pouvez aussi chercher à mi-chemin dans l'arbre et ->find devrait renvoyer là où vous vous êtes arrêté.

Par exemple, étant donné les valeurs find (qw (A B C)) et l'arbre suivant (les balises </end> sont omises par

concision) :

       <FOO>
               ...
       <B>
               <BAZ>
                       ...
               <C>
                       BAR
= shoo

renverra.

MÉTHODES

AUTOLOAD

Une autre fonctionnalité utile est implémentée dans cette classe en utilisant la fonctionnalité AUTOLOAD de perl. Si vous connaissez les noms de clés d'un bloc dans votre configuration, vous pouvez accéder aux valeurs de chaque clé individuelle en utilisant la notation de méthode. Voir l'exemple suivant et vous comprendrez

:

Nous supposons la configuration suivante

: 
<person>
   name    = Moser
   prename = Peter
   birth   = 12.10.1972
</person>

Maintenant nous la lisons et la traitons

: 
my $conf = Config::General::Extended->new("configfile");
my $person = $conf->obj("person");
print $person->prename . " " . $person->name . " is " . $person->age . " years
old\n";

Cette notation ne supporte que les valeurs scalaires ! Vous devez vous assurer que le bloc <person> ne contient aucun sous-bloc ou d'options identiques multiples (ce qui deviendra un tableau après l'analyse)

!

Si vous accédez à une clé inexistante de cette manière, Config::General provoquera une erreur fatale. Vous pouvez désactiver ce comportement en définissant -StrictObjects à 0 ou "no". Dans ce cas, undef sera

retourné.

Bien sûr, vous pouvez utiliser ce type de méthodes pour écrire des données aussi

: 
$person->name("Neustein")
;

Cela change la valeur de la clé "name" en "Neustein". Cette fonctionnalité se comporte exactement comme value(), ce qui signifie que vous pouvez également assigner des références de hacha

ge ou de tableaux et que les valeurs ex
istantes sous la clé donnée seront écrasées.
