NOM

containers-certs.d - Répertoire pour stocker les configurations TLS personnalisées des registres de conteneurs

DESCRIPTION

Une configuration TLS personnalisée pour un registre de conteneurs peut être configurée en créant un répertoire sous $HOME/.config/containers/certs.d ou /etc/containers/certs.d. Le nom du répertoire doit correspondre à l'hôte[:port] du registre (par exemple, mon-registre.com:5000).

La présence / absence de la partie port doit correspondre précisément à l'utilisation du port dans les références d'images, par exemple pour affecter podman pull registry.example/foo, utiliser un répertoire nommé registry.example, pas registry.example:443. registry.example:443 affecterait podman pull registry.example:443/foo.

Structure du répertoire

Un répertoire certs peut contenir un ou plusieurs fichiers avec les extensions suivantes :

  • Les fichiers *.crt avec cette extension seront interprétés comme des certificats d'autorité de certification (CA)
  • Les fichiers *.cert avec cette extension seront interprétés comme des certificats clients
  • Les fichiers *.key avec cette extension seront interprétés comme des clés clients

Notez que la paire certificat-clé client sera sélectionnée par le nom de fichier (par exemple, client.{cert,key}). Une configuration exemple pour un registre fonctionnant à mon-registre.com:5000 peut ressembler à ceci :

/etc/containers/certs.d/    <- Répertoire des certificats
└── mon-registre.com:5000    <- Nom d'hôte[:port]
   ├── client.cert          <- Certificat client
   ├── client.key           <- Clé client
   └── ca.crt               <- Autorité de certification qui a signé le certificat du registre
