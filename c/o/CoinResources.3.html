Description détaillée

Fonctions utilitaires statiques pour la gestion des ressources de données au niveau des tampons de base.

Cette classe est simplement une portée statique pour certaines fonctions de gestion de ressources. Avec cela, Coin peut enregistrer des ressources par défaut intégrées qui peuvent être récupérées ultérieurement via le même localisateur de ressource, soit depuis le disque (si présent) et en dernier recours, le tampon intégré (compilé).

Les localisateurs de ressources prennent la forme d'une URL avec `coin` comme schéma et un hôte vide, par ex. "coin://path/to/resource.ext".

Le préfixe "coin:" sert à Coin à différencier un localisateur de ressource d'un nom de fichier (pour une utilisation multifonctionnelle).

Le chemin/vers/ressource.ext est, pour la plupart des plateformes, le chemin sous la variable d'environnement $COINDIR où le fichier doit être présent. Pour Mac OS X, le chemin se trouve sous le répertoire Resources/ du framework Inventor, si Coin a été installé en tant que framework.

Le fichier sur disque peut être une version mise à jour par rapport au tampon compilé, c'est pourquoi les fichiers externalisés sont prioritaires sur les tampons intégrés.

Une ressource n'a pas besoin d'avoir un fichier correspondant. Ceci est configuré dans le paramètre `flags` lors de la définition de la ressource. Vous pouvez donc également enregistrer des ressources uniquement intégrées.

Documentation des fonctions

SbByteBuffer CoinResources::get (const char * resloc)

Retourne une ressource si elle existe. Si l'installation de Coin le permet, la ressource sera chargée depuis un fichier, mais si le fichier ne peut pas être trouvé ou chargé, des versions intégrées seront retournées à la place.

Retourne

TRUE en cas de succès, et FALSE s'il n'y a pas de telle ressource.

SbBool CoinResources::set (const char * resloc, const SbByteBuffer & buffer, ResourceFlags flags = NONE)

Cette fonction enregistre une nouvelle ressource. Le localisateur de ressource (resloc) doit avoir la forme "coin:" suivie d'un chemin de fichier relatif qui devrait mener à la représentation du fichier de la ressource à partir de l'endroit où la variable d'environnement COINDIR pointe. Le chemin relatif doit utiliser / comme séparateur de répertoire, et non \ si sous Microsoft Windows.

Si vous mettez COIN_RESOURCE_NOT_A_FILE dans l'argument flags, alors la recherche automatique de fichier ne sera pas effectuée.

Retourne

TRUE si la ressource a été définie, et FALSE si quelque chose s'est mal passé. FALSE serait très probablement retourné car la ressource existe déjà.

void CoinResources::freeLoadedExternals (void )

Cette fonction désalloue tous les tampons qui ont été chargés depuis le disque. Les tampons internes ne seront pas libérés, car on s'attend à ce qu'ils soient compilés dans la section de données de la bibliothèque Coin.
