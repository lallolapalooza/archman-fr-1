  my $input = '' ;
  binmode STDIN;
  binmode STDOUT;
  my ($output, $status) ;
OUTER:
  while (read(STDIN, $input, 4096))
  {
      do
      {
          $status = $x->inflate($input, $output) ;
          print $output ;
          last OUTER
              unless $status == Z_OK || $status == Z_BUF_ERROR ;

      while length $input;

Ces fonctions permettent de fusionner des sommes de contrôle. Consultez la documentation de zlib

L'option

LimitOutput.

Par défaut "$i->inflate($entrée, $sortie)" décompressera toutes les données dans $entrée et écrira toutes les données décompressées qu'il a générées dans $sortie. Cela rend l'interface de "inflate" beaucoup plus simple - si la méthode a décompressé $entrée avec succès toutes les données compressées dans $entrée auront été traitées. Donc si vous lisez depuis une source d'entrée et décompresser au fur et à mesure, le code ressemblera à quelque chose comme

ceci 
use strict ;
use warnings ;
use Compress::Raw::Zlib;
my $x = new Compress::Raw::Zlib::Inflate()
   or die "Cannot create a inflation stream\n" ;
my $input = '' ;
my ($output, $status) ;
while (read(STDIN, $input, 4096))
{
    $status = $x->inflate($input, $output) ;
    print $output ;
    last if $status != Z_OK ;
}
die "inflation failed\n"
    unless $status == Z_STREAM_END
;

Les points à noter

sont
  • La boucle de traitement principale dans le code gère la lecture des données compressées depuis
    • STDIN.
  • Le code de statut renvoyé par "inflate" ne déclenchera l'arrêt de la boucle de traitement principale que s'il n'est pas "Z_OK". Quand "LimitOutput" n'a pas été utilisé, le statut "Z_OK" signifie que la fin du flux de données compressées a été atteinte ou qu'il y a eu une erreur lors de la
    • décompression.
  • Après l'appel à "inflate" toutes les données décompressées dans $entrée auront été traitées. Cela signifie que l'appel suivant à "read" peut écraser son conte
    • nu sans a
ucun problème.

Pour la plupart des cas d'utilisation, le comportement décrit ci-dessus est acceptable (ce module et son prédécesseur, "Compress::Zlib", l'ont utilisé pendant plus de 10 ans sans aucun problème), mais dans quelques cas d'utilisation très spécifiques, la quantité de mémoire requise pour $sortie peut être prohibitivement grande. Par exemple, si le flux de données compressées contient le même motif répété des milliers de fois, un flux de données compressé relativement petit peut se décompresser en centaines de mégaoctets. Rappelez-vous que "inflate" continuera à allouer de la mémoire jusqu'à ce que toutes les données décompressées aient été écrites dans le tampon de sortie - la taille de $sortie est

illimitée.

L'option "LimitOutput" est conçue pour aider avec ce cas

d'utilisation.

La principale différence dans votre code lorsque vous utilisez "LimitOutput" est de devoir gérer les cas où le paramètre $entrée contient encore des données non décompressées que "inflate" n'a pas encore traitées. Le code de statut renvoyé par "inflate" sera "Z_OK" si une décompression a eu lieu et "Z_BUF_ERROR" si le tampon de sortie est

plein.

Voici un code typique montrant comment utiliser "LimitOutput"

. 
  use strict ;
  use warnings ;
  use Compress::Raw::Zlib;
  my $x = new Compress::Raw::Zlib::Inflate(LimitOutput => 1)
     or die "Cannot create a inflation stream\n" ;
  my $input = '' ;
  binmode STDIN;
  binmode STDOUT;
  my ($output, $status) ;
OUTER:
  while (read(STDIN, $input, 4096))
  {
      do
      {
          $status = $x->inflate($input, $output) ;
          print $output ;
          last OUTER
              unless $status == Z_OK || $status == Z_BUF_ERROR ;
      }
      while length $input;
  }
  die "inflation failed\n"
      unless $status == Z_STREAM_END
;

Points à noter cette fois

:
  • Il y a maintenant deux boucles imbriquées dans le code : la boucle externe pour lire les données compressées depuis STDIN, comme avant ; et la boucle interne pour effectuer la
    • décompression.
  • Il y a deux points de sortie de la boucle interne de décompression.

    Premièrement, quand "inflate" a renvoyé un statut autre que "Z_OK" ou "Z_BUF_ERROR". Cela signifie que soit la fin du flux de données compressées a été atteinte ("Z_STREAM_END"), soit il y a une erreur dans les données compressées. Dans l'un ou l'autre de ces cas, il n'y a aucun intérêt à continuer la lecture des données compressées, donc les deux boucles sont

    terminées.

    Le second point de sortie teste s'il reste des données dans le tampon d'entrée, $entrée - rappelez-vous que l'option "ConsumeInput" est automatiquement activée quand "LimitOutput" est utilisé. Quand le tampon d'entrée est épuisé, la boucle externe peut s'exécuter à nouveau et écraser un $entrée

    main
    • tena
nt v
