NOM

copr-cli - interface en ligne de commande pour le service Copr

SYNOPSIS

copr-cli [-h] [--version] [--config CONFIG] {list,create,build} ...

DESCRIPTION

Cette commande vous permet d'interagir avec le service Copr depuis la ligne de commande.

Vous devez d'abord configurer l'authentification (voir la section AUTHENTIFICATION ci-dessous).

OPTIONS

-h, --help

afficher ce message d'aide et quitter

--version

afficher le numéro de version du programme et quitter

--config

chemin vers un fichier de configuration alternatif (par défaut ~/.config/copr).

ACTION LIST

list [username|@groupname]

Lister tous les projets du nom d'utilisateur fourni. Si aucun nom d'utilisateur n'est fourni, vos projets sont listés.

create

Créer un nouveau projet.

delete

Supprimer un projet entier.

build

Compiler des paquets pour un projet spécifié.

status

Obtenir l'état de la compilation.

cancel

Annuler une compilation dont l'identifiant est donné.

download-build

Télécharger une compilation dans un répertoire local.

modify

Modifier un copr existant

regenerate-repos

Régénérer les métadonnées du dépôt pour un projet

add-package-*

Ajouter un nouveau paquet du type de source spécifié (par ex. add-package-tito)

edit-package-*

Modifier la définition de la source et le type d'un paquet existant (par ex. edit-package-tito)

list-packages

Lister tous les paquets d'un copr au format json

list-package-names

Afficher uniquement les noms des paquets du copr donné

get-package

Afficher les détails d'un seul paquet au format json

delete-package

Supprimer un paquet d'un copr ainsi que toutes ses compilations

reset-package

Effacer la définition de la source d'un paquet et son type de source

build-package

Compiler un paquet à partir de sa définition de source

mock-config

Obtenir le profil mock (similaire à koji mock-config)

ACTIONS DE COMPILATION

copr-cli build [options]

utilisation : copr-cli build [-h] [-r, --chroot CHROOTS] [--memory MEMORY] [--timeout TIMEOUT] [--nowait] [--background] [--isolation {default, nspawn, simple}] [--enable-net {on,off}] copr_repo PKG [PKG ...]

-r, --chroot

Si vous n'avez pas besoin de cette compilation pour tous les chroots du projet. Vous pouvez l'utiliser plusieurs fois pour chaque chroot dont vous avez besoin.

--exclude-chroot

Si vous n'avez pas besoin de cette compilation pour tous les chroots du projet. Vous pouvez l'utiliser plusieurs fois pour chaque chroot dont vous n'avez pas besoin.

--memory

Surcharger la mémoire pour cette compilation. Ceci n'est en fait pas utilisé et n'a aucun effet.

--timeout

Spécifier le délai d'attente de la compilation (secondes) ; si la compilation prend plus de temps, elle est terminée et échoue. La valeur par défaut est généralement fixée à 5 heures sur le Frontend Copr.

--nowait

Ne pas attendre la fin de la compilation.

--background

Exécuter la compilation à une priorité plus basse.

--isolation ISOLATION

Choisir la méthode d'isolation pour l'exécution des commandes dans le buildroot.

--enable-net

Si le réseau doit être activé pour cette compilation.

copr_repo

Le dépôt copr dans lequel compiler le paquet. Il peut s'agir du nom simple de l'un de vos projets ou il peut être spécifié complètement sous la forme username/project ou @groupname/project. De cette façon, vous pouvez compiler dans le projet d'un autre utilisateur ou groupe, à condition d'avoir les permissions pour le faire. Enfin, au lieu du simple nom du projet, vous pouvez aussi passer project:tag. Dans ce cas, la compilation atterrira dans le dépôt secondaire du projet au lieu du dépôt principal. Le dépôt secondaire nommé project:tag sera automatiquement créé s'il n'existe paset. Vous pouvez par exemple utiliser cette fonctionnalité pour lancer des builds de test pendant que le dépôt principal destiné aux utilisateurs reste intact. Vous pouvez spécifier n'importe quelle étiquette appropriée pour le ou les builds concernés.

PKG

Il peut s'agir d'un fichier sur votre poste de travail local ou de l'URL du paquet à construire. Lorsqu'une URL est utilisée, le paquet doit être placé sur un serveur web ou ftp public. Notez que vous ne pouvez pas combiner des chemins de fichiers locaux et des URL dans une seule ligne de commande et que les builds à partir de fichiers locaux sont limités au premier PKG spécifié. Cette limitation provient de l'API COPR.

usage : copr delete-build [-h] build_id [build_id ...]

build_id

ID du build à supprimer. Peut être spécifié plusieurs fois. Notez que spécifier plusieurs build_id est beaucoup plus rapide que d'appeler copr delete-build plusieurs fois, car dans le premier cas createrepo n'est appelé qu'une seule fois.
