DESCRIPTIO

N

Ce module ouvre un fichier de configuration et analyse son contenu pour vous. La méthode new nécessite un paramètre qui doit être un nom de fichier. La méthode getall renvoie un hachage qui contient toutes les options et leurs valeurs associées de votre fichier de

configuration.

Le format des fichiers de configuration pris en charge par Config::General est inspiré du bien connu format de configuration Apache, en fait, ce module est 100% compatible avec les configurations Apache, mais vous pouvez aussi simplement utiliser des paires
nom/valeur simples dans vos fichiers de

configuration.

En plus des capacités d'un fichier de configuration Apache, il

prend en charge quelques améliorations telles que les here-docum
ents, les commentaires de style C ou les options multilignes.

-FlagBi

Cette option prend un paramètre requis, qui doit être une référence de hachage.

La référence de hachage fournie doit définir les variables pour lesquelles vous souhaitez prédéfinir des valeurs. Chaque variable que vous avez définie dans cette référence de hachage et qui apparaît dans votre fichier de configuration, entraînera le fait que cette variable soit définie sur les valeurs prédéfinies auxquelles la valeur du fichier de configuration fait

Plusieurs indicateurs peuvent être utilisés, séparés par le caractère pipe

|.

Eh bien, un exemple clarifiera les

        -ConfigFile => "rcfile",
        -FlagBits => {
             Mode => {
                CLEAR    => 1,
                STRONG   => 1,
                UNSECURE => "32bit" }
} );

Dans cet exemple, nous définissons une variable nommée "Mode" qui peut contenir un ou plusieurs des "CLEAR", "STRONG" et "UNSECURE" comme

valeur.

L'entrée de configuration appropriée peut ressembler

à ceci :

UNSECURE

L'analyseur créera un hachage qui sera la valeur de la clé "Mode". Ce hachage contiendra tous les indicateurs que vous avez prédéfinis, mais seulement ceux qui ont été définis dans la configuration contiendront la valeur prédéfinie, les autres seront

indéfinis.

La structure de configuration résultante ressemblerait à ceci après

l'analyse : 
%config = (
            Mode => {
                      CLEAR    => 1,
                      UNSECURE => "32bit",
                      STRONG   => undef,
                    }
);

Cette méthode permet à l'utilisateur (ou, au "mainteneur" du fichier de configuration de votre application) de définir plusieurs valeurs prédéfinies pour une

option.

Veuillez noter que toutes les occurrences de ces variables seront traitées de cette manière, il n'y a aucun moyen de distinguer les variables dans différents domaines de visibilité. Cela signifie que si "Mode" apparaissait aussi à l'intérieur d'un bloc nommé, il serait aussi analysé de cette

manière.

Les valeurs qui ne sont pas définies dans la référence de hachage fournie au paramètre -FlagBits et utilisées dans la variable correspondante dans la configuration seront

ignorées.

Exemple

CLEAR

-T

-Tie prend le nom d'une classe Tie comme argument, à partir de laquelle chaque nouveau hachage doit être basé.

Ce hachage sera utilisé comme 'hachage de support' au lieu d'un hachage Perl standard, ce qui vous permet d'influencer la manière dont le stockage des variables sera fait. Vous pourriez, par exemple, fournir un hachage lié, disons Tie::DxHash, qui préserve l'ordre des clés dans la configuration (ce qu'un hachage Perl standard ne fera pas). Ou, vous pourriez fournir un hachage lié à un fichier DBM pour enregistrer les variables analysées sur

disque.

Il y a beaucoup plus de choses à faire dans le monde du tie, voir tie pour obtenir quelques idées

intéressantes.

Si vous souhaitez utiliser la fonctionnalité -Tie avec -DefaultConfig, assurez-vous que le hachage fourni à -DefaultConfig doit être lié à la même classe

Tie.

Assurez-vous que le hachage qui reçoit la structure de hachage générée (par exemple, celui que vous utilisez dans l'affectation : %hash = $config->getall()) doit être lié à la même classe

Tie.

C'est parce que Config::General n'utilise pas les noms de blocs pour vérifier si un bloc se termine, il utilise plutôt un compteur d'état interne, qui indique la fin d'un

OPTIONS IDENTIQUES

(TABLEAUX)

Vous pouvez avoir plus d'une ligne pour la même option avec des valeurs différentes. Exemple

:

log  log2
log
log2

Vous obtiendrez un scalaire si l'option n'est apparue qu'une seule fois, ou un tableau si elle est apparue plus d'une fois. Si vous vous attendez à plusieurs options identiques, vous devrez peut-être vérifier si une option est apparue plus d'une fois

: 
$allowed = $hash{jonas}->{tablestructure}->{allowed};
if (ref($allowed) eq "ARRAY") {
  @ALLOWED = @{$allowed};
  else {
    @ALLOWED = ($allowed);
  }
}

La même chose s'applique aux blocs et aux blocs nommés (qui sont décrits plus en détail ci-dessous). Par exemple, si vous avez la configuration suivante

: 
<dir blah>
 user max
</dir>
<dir blah>
 user hannes
</dir>

alors vous vous retrouverez avec une structure de données comme celle-ci

: 
$VAR1 = {
         'dir' => {
                   'blah' => [
                              {
                               'user' => 'max'
                              },
                              {
                               'user' => 'hannes'
                              }
                             ]
                  }
        }
;

Comme vous pouvez le voir, les deux blocs identiques sont stockés dans un hachage qui contient un tableau (référence) de

hachages.

Dans certaines conditions rares, vous ne voudrez peut-être pas ce comportement avec les blocs (et les blocs nommés aussi). Si vous voulez obtenir un seul hachage avec le contenu des deux blocs identiques, vous devrez activer le paramètre new() -MergeDuplicateBlocks (voir ci-dessus). La structure analysée de l'exemple ci-dessus ressemblerait alors à ceci

: 
$VAR1 = {
         'dir' => {
                   'blah' => {
                              'user' => [
                                         'max',
                                         'hannes'
                                        ]
                             }
                  }
        }
;

Comme vous pouvez le voir, il n'y a qu'un seul hachage "dir->{blah}" contenant plusieurs entrées "user". Comme vous pouvez aussi le voir, activer -MergeDuplicateBlocks n'affecte pas les options scalaires (c'est-à-dire "option = valeur"). En fait, vous pouvez régler la fusion des blocs et options dupliqués indépendamment les uns des

autres.

Si vous ne voulez pas autoriser plus d'une option identique, vous pouvez la désactiver en définissant le drapeau AllowMultiOptions dans la méthode new() sur "no". Si désactivé, Config::General se plaindra des options apparaissant plusieurs fois avec des noms identiques

!

INCLUSION

S

Vous pouvez inclure un fichier externe à n'importe quelle position dans votre fichier de configuration en utilisant l'instruction suivante dans votre fichier de configuration

: 
<<include externalconfig.rc>
>

Si vous avez activé -UseApacheInclude (voir new()), vous pouvez aussi utiliser l'instruction suivante pour inclure un fichier externe

: 
include externalconfig.
rc

Ce fichier sera inséré à la position où il a été trouvé comme si le contenu de ce fichier se trouvait directement à cette

position.

Vous pouvez aussi inclure des fichiers récursivement, de sorte qu'un fichier inclus puisse en inclure un autre, et ainsi de suite. Veillez à ne pas charger récursivement le même fichier, vous finirez avec un message d'erreur comme "too many open files in system!

".

Par défaut, les fichiers inclus avec un chemin relatif seront ouverts depuis le répertoire de travail courant. Dans certaines circonstances, il peut être possible d'ouvrir les fichiers inclus depuis le répertoire où se trouve le fichier de configuration. Vous devez activer l'option -IncludeRelative (voir new()) si vous voulez cela. Un exemple

: 
my $conf = Config::General(
 -ConfigFile => "/etc/crypt.d/server.cfg"
 -IncludeRelative => 1
)
;

/etc/crypt.d/server.cfg

: 
<<include acl.cfg>
>

Dans cet exemple, Config::General essaiera d'inclure acl.cfg depuis /etc/crypt.d

: 
/etc/crypt.d/acl.
cfg

Le comportement par défaut (si -IncludeRelative n'est pas défini !) sera d'ouvrir simplement acl.cfg, où qu'il se trouve, c'est-à-dire si vous avez fait un chdir("/usr/local/etc"), alors Config::General inclura

: 
/usr/local/etc/acl.
cfg

Les instructions include peuvent être insensibles à la casse (ajouté dans la version 1.25)

.

Les instructions include seront ignorées dans les commentaires C et les

here-documents.

Par défaut, un fichier de configuration ne sera inclus que la première fois qu'il est référencé. Si vous souhaitez inclure un fichier à plusieurs endroits, définissez /-IncludeAgain sur true. Mais soyez averti : cela peut entraîner des boucles infinies, alors assurez-vous de ne pas inclure le même fichier depuis lui-même

!

Exemple

: 
# main.cfg
<object billy>
 class=Some::Class
<printers>
 include printers.cfg
</printers>
# ...
</object>
 <object bob>
  class=Another::Class
 <printers>
 include printers.cfg
 </printers>
 # ...
</object>

Maintenant "printers.cfg" sera inclus dans les deux objets "billy" et "bob"

.

Vous devrez faire attention à ne pas in

clure récursivement un fichier. Le
comportement dans ce cas est indéfini.

COMMENTAIRE

S

Un commentaire commence par le signe dièse #, il peut y avoir n'importe quel nombre d'espaces et/ou de tabulations devant le

#.

Un commentaire peut aussi apparaître après une instruction de configuration. Exemple

: 
username = max  # this is the
comment

Si vous voulez commenter un grand bloc, vous pouvez utiliser des commentaires de style C. Un /* signale le début d'un bloc de commentaire et le */ signale la fin du bloc de commentaire. Exemple

: 
user  = max # valid option
db    = tothemmax
/*
user  = andors
db    = toand
*/

Dans cet exemple, les deuxièmes options de user et db seront ignorées. Veuillez noter que si le module trouve une chaîne /* qui est le début d'un bloc de commentaire, mais pas de bloc de fin correspondant, il ignorera tout le reste du fichier de configuration

!

NOTE : Si vous avez besoin que le caractère # (signe dièse) reste dans la valeur de l'option, vous pouvez utiliser un backslash devant celui-ci, pour l'échapper. Exemple

: 
bgcolor =
\#ffffcc

Dans cet exemple, la valeur de $config{bgcolor} sera "#ffffcc", Config::General ne traitera pas le signe dièse comme le début d'un commentaire à cause du backslash

initial.

À l'intérieur des here-docum

ents, l'échappement des signe
s dièse n'est PAS requis !
