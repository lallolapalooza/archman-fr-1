DESCRIPTIO

N

"Config::Tiny" est une classe Perl pour lire et écrire des fichiers de configuration de style .ini avec le moins de code possible, réduisant ainsi le temps de chargement et la surcharge

mémoire.

La plupart du temps, on admet que les applications Perl utilisent beaucoup de mémoire et de

modules.

La famille de modules *::Tiny est spécifiquement destinée à fournir une alternative ultralégère aux modules

standard.

Ce module est principalement destiné à la lecture de fichiers écrits par des humains, et tout ce que nous écrivons ne devrait pas nécessiter de documentation/commentaires. Si vous avez besoin de quelque chose de plus puissant, passez à Config::Simple, Config::General ou à l'un des nombreux autres modules "Config::

*".

Enfin, Config::Tiny ne conserve pas vos commentaires, votre espacement ou l'ordre de votre fichier de

configuration.

Voir Config::Tiny::Ordered (et éventuel

lement d'autres) pour la préservation
de l'ordre des entrées dans le fichier.

SYNTAXE DU FICHIER DE

CONFIGURATION

Les fichiers sont au même format que les fichiers "*.ini" de MS Windows. Par exemple

: 
[section]
var1=value1
var2=value2

Mais voir aussi SYNTAXE DE TABLEAU juste en

dessous.

Si une propriété se trouve en dehors d'une section au début d'un fichier, elle sera assignée à la "section racine", accessible via "$Config->{_}

".

Les lignes commençant par '#' ou ';' sont considérées comme des commentaires et ignorées, tout comme les lignes

vides.

Lors de la réécriture du fichier de configuration, tous les commentaires, l'espacement personnalisé et l'ordre

des éléments de votre fichier de configuration sont perdus. Si vous avez besoin de conserver les éléments huma
ins d'une configuration lors de la réécriture, passez à quelque chose de mieux, ce module n'est pas pour vous.

SYNTAXE DE

TABLEAU

Syntaxe de

base

Depuis la version 2.30, ce module prend en charge le cas d'une clé ayant un tableau de

valeurs.

Données d'exemple (copiées depuis t/test.conf)

: 
root=something
[section]
greetings[]=Hello
one=two
Foo=Bar
greetings[]=World!
this=Your Mother!
blank=
[Section Two]
something else=blah
 remove =
whitespace

Notez spécifiquement que le nom de clé greetings a la paire de crochets vides [] comme suffixe. Cela indique au code qu'il ne doit pas écraser la 1ère valeur avec la 2ème, mais plutôt pousser ces valeurs sur une pile appelée

'greetings'.

Notez également que vous auriez pu utiliser

: 
[section]
greetings[]=Hello
greetings[]=World!
one=two
Foo=Bar
this=Your Mother!
blank=

Clairement, les 2 lignes utilisant greetings[] n'ont pas à être côte à

côte.

Si vous utilisez par exemple Data::Dumper::Concise pour obtenir une fonction (et non méthode) Dumper(), alors 'say Dumper($Config)' donnera une sortie qui ressemblera à

: 
bless( {
  "Section Two" => {
     remove => "whitespace",
     "something else" => "blah",
   },
   _ => {
     root => "something",
   },
   section => {
     Foo => "Bar",
     blank => "",
     greetings => [
       "Hello",
       "World!",
     ],
     one => "two",
     this => "Your Mother!",
   },
 }, 'Config::Tiny'
)

Vous pouvez voir cette structure dans t/02.main.t à partir de la ligne 45. Observez aussi que les noms de clés sont rapportés dans l'ordre alphabétique (par le module Data::Dumper::Concise) malgré l'ordre différent de la définition de ces clés, et que le résultat de la syntaxe tableau est que greetings a un tableau comme

valeur.

Pour accéder à ces valeurs, utilisez du code comme ceci

: 
Dumper($Config);
Dumper($Config->{section});
Dumper($Config->{sect
ion}->{greetings}); Dumper($Config->{section}->{greetings}->[0]);
Dumper($Config->{section}->{greetings}->[1]); Dumper(ref $Config);

Avertisseme

nt

$Config est une valeur bénie (blessed), ce qui signifie qu'elle est accessible différemment que si c'était une référence de hachage. Cette dernière pourrait être accessible comme

: 
Dumper($$Config{section}{greetings}); # Ne faites pas ceci pour les valeurs bénies
!

Enfin, s'il s'agit d'une référence de hachage plutôt que d'une valeur bénie, vous pourriez aussi utiliser, comme ci-dessus

: 
Dumper($Config->{section}->{greetings}); # Ne faites pas ceci pour les valeurs bénies
!

Ma préférence personnelle (Ron Savage) pour les références de hachage est celle sans les caractères grossiers '->', mais cela vous oblige à doubler le caractère $ initial (j'espère que vous l'avez remarqué

!
)
.

Le constructeur "new" crée et renvoie un objet "Config::

Ceci sera normalement une configuration nouvelle et vide, mais vous pouvez aussi passer ici une référence de hachage qui sera transformée en objet de cette classe. Ici, les [] indiquent un paramètre

optionnel.

Le constructeur "read" lit un fichier de configuration, $filename, et renvoie un nouvel objet "Config::Tiny" contenant

AVERTISSEMEN

TS

Certains cas limites dans les en-têtes de section ne sont pas pris en charge et peuvent en outre ne pas être détectés lors de l'écriture du fichier de

configuration.

Plus précisément, les en-têtes de section avec des espaces de début, des espaces

de fin, ou des sauts de ligne n'importe où dans l'en-tête de section ne seront pas éc
rits correctement dans le fichier et peuvent provoquer une corruption du fichier.
