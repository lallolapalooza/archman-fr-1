Description détaillée

Les classes d'impression vectorielle servent à rendre sur des périphériques vectoriels au lieu de périphériques raster.

Vous pouvez l'utiliser pour, par exemple, générer des images PostScript évolutives pour l'impression au lieu d'images raster qui deviendront pixelisées lorsque vous les redimensionnerez.

Voir ci-dessous pour Un aperçu de HardCopy. Un aperçu de HardCopy

L'API principale pour le support de HardCopy dans Coin est la classe abstraite SoVectorizeAction. SoVectorizeAction extrait la géométrie d'un graphe de scène Inventor et projette la géométrie sur une page spécifiée. Comme les formats de fichiers vectoriels comme PostScript ne supportent pas le z-buffer ou le découpage en profondeur, toute la géométrie est rendue à l'aide d'un simple algorithme de peintre (la géométrie est triée en fonction de la distance à la caméra).

SoVectorizePSAction hérite de SoVectorizeAction et générera un fichier PostScript.

Les polygones texturés ne sont pas pris en charge, car ils ne sont pas pris en charge par les formats de fichiers vectoriels, du moins pas en PostScript. Le rendu Gouraud n'est pas pris en charge dans le langage PostScript (du moins pas pour la V2.0), mais une approximation est implémentée à l'aide d'un algorithme qui divise le triangle en plusieurs petits triangles (rendus en aplat). La qualité du rendu Gouraud (le nombre de sous-triangles) est contrôlée par une valeur epsilon. La fonction de rendu Gouraud est écrite par Frederic Delhoume (delhoume (arobase) ilog.fr) et est un logiciel libre (domaine public).

L'utilisation typique de SoVectorizePSAction est montrée dans le morceau de code suivant :

SoVectorizePSAction * ps = new SoVectorizePSAction;
SoVectorOutput * out = ps->getOutput();
if (!out->openFile("output.ps")) {
  return -1; // impossible d'ouvrir le fichier de sortie
}
// pour activer le rendu Gouraud. 0.1 est une bonne valeur epsilon
// ps->setGouraudThreshold(0.1f);
// effacer avec un fond blanc. Pas vraiment nécessaire si vous
// voulez un fond blanc
ps->setBackgroundColor(TRUE, SbColor(1.0f, 1.0f, 1.0f));
// sélectionner l'orientation LANDSCAPE (paysage) ou PORTRAIT (portrait)
ps->setOrientation(SoVectorizeAction::LANDSCAPE);
// commencer la création d'une nouvelle page (page A4, avec une marge de 10 mm).
ps->beginPage(SbVec2f(10.0f, 10.0f), SbVec2f(190.0f, 277.0f));
// Il existe également des énumérations pour A0-A10. Exemple :
// ps->beginStandardPage(SoVectorizeAction::A4, 10.0f);
// calibrer de sorte que le texte, les lignes, les points et les images aient la
// même taille dans le fichier PostScript que sur l'écran.
ps->calibrate(viewer->getViewportRegion());
// appliquer l'action sur le graphe de scène du spectateur. N'oubliez pas d'utiliser
// le graphe de scène de SoSceneManager afin que la caméra soit incluse.
ps->apply(viewer->getSceneManager()->getSceneGraph());
// cela créera le fichier PostScript
ps->endPage();
// fermer le fichier
out->closeFile();
delete ps;

Il est également possible d'avoir plusieurs vues (viewports) et/ou couches sur une page. Ceci est utile si votre application possède plusieurs couches de géométrie, par exemple des annotations en 2D par-dessus un graphe de scène 3D. Pour créer plusieurs couches, les fonctions beginViewport() et endViewport() peuvent être utilisées.

Depuis

TGS fournit le support HardCopy comme extension séparée pour TGS Inventor.
