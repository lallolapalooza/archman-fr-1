DESCRIPTIO

N

La fonction CONF_get1_default_config_file() détermine le chemin du fichier de configuration par défaut comme suit. Si la variable d'environnement OPENSSL_CONF est définie, sa valeur est retournée. Sinon, la fonction retourne le chemin obtenu en utilisant X509_get_default_cert_area(3) avec le nom de fichier "openssl.cnf" ajouté. L'appelant est responsable de libérer toute chaîne

retournée.

La fonction CONF_modules_load_file_ex() configure OpenSSL en utilisant le contexte de bibliothèque libctx, le fichier filename et le nom d'application appname. Si filename est NULL, le fichier de configuration standard d'OpenSSL est utilisé tel que déterminé en appelant CONF_get1_default_config_file(). Si appname est NULL, le nom d'application standard d'OpenSSL openssl_conf est utilisé. Le comportement peut être personnalisé en utilisant flags. Notez que la suppression d'erreurs peut être contournée par config_diagnostics comme décrit dans config(

5).

CONF_modules_load_file() est identique à CONF_modules_load_file_ex() mais avec un contexte de bibliothèque

NULL.

CONF_modules_load() est identique à CONF_modules_load_file() sauf qu'il lit les informations de configuration depuis cn

f
.

NOTE

S

Les drapeaux suivants sont actuellement reconnus

:

Si CONF_MFLAGS_IGNORE_ERRORS est défini, les erreurs retournées par les modules de configuration individuels sont ignorées. S'il n'est pas défini, la première erreur de module est considérée comme fatale et aucun autre module n'est

chargé.

Normalement, les erreurs de modules ajouteront des informations d'erreur à la file d'erreurs. Si CONF_MFLAGS_SILENT est défini, aucune information d'erreur n'est

ajoutée.

Si CONF_MFLAGS_IGNORE_RETURN_CODES est défini, la fonction retourne inconditionnellement le succès. C'est utilisé par défaut dans OPENSSL_init_crypto(3) pour ignorer toute erreur dans le fichier de configuration par défaut au niveau du système, car faire échouer le démarrage de toutes les applications OpenSSL lorsqu'il y a potentiellement des problèmes mineurs dans le fichier est trop risqué. Les applications appelant CONF_modules_load_file_ex explicitement ne devraient généralement pas définir ce

drapeau.

Si CONF_MFLAGS_NO_DSO est défini, le chargement des modules de configuration depuis les DSO est

désactivé.

CONF_MFLAGS_IGNORE_MISSING_FILE, s'il est défini, fera que CONF_load_modules_file() ignore les fichiers de configuration manquants. Normalement, un fichier de configuration manquant retourne une

erreur.

CONF_MFLAGS_DEFAULT_SECTION, s'il est défini et que appname n'est pas NULL, utilisera la section par défaut pointée par openssl_conf si appname n'existe

pas.

En utilisant CONF_modules_load_file_ex() avec des drapeaux appropriés, une application peut personnaliser sa configuration pour mieux répondre à ses besoins. Dans certains cas, l'utilisation d'un fichier de configuration est facultative et son absence n'est pas une erreur : dans ce cas CONF_MFLAGS_IGNORE_MISSING_FILE serait

défini.

Les erreurs pendant la configuration peuvent aussi être traitées différemment par différentes applications. Par exemple, dans certains cas, une erreur peut simplement afficher un message d'avertissement et l'application continue. Dans d'autres cas, une application peut considérer une erreur de fichier de configuration comme fatale et sortir

immédiatement.

Les applications peuvent utiliser la fonction CONF_modules_load() si elles souhaitent charger un fichier de configuration e

lles-mêmes et avoir un contrôle plus fin s
ur la manière dont les erreurs sont traitées.

VALEURS DE

RETOUR

Ces fonctions retournent 1 en cas de succès et une valeur nulle ou négative en cas

d'échec. Si les erreurs de module ne sont pas ignorées, le code de retour reflétera
la valeur de retour du module en échec (celle-ci sera toujours nulle ou négative).

EXEMPLE

S

Charger un fichier de configuration et afficher toutes les erreurs puis sortir (fichier manquant considéré comme fatal)

: 
if (CONF_modules_load_file_ex(libctx, NULL, NULL, 0) <= 0) {
    fprintf(stderr, "FATAL: error loading configuration file\n");
    ERR_print_errors_fp(stderr);
    exit(1);
}

Charger le fichier de configuration par défaut en utilisant la section indiquée par "myapp", tolérer les fichiers manquants, mais sortir sur les autres erreurs

: 
if (CONF_modules_load_file_ex(NULL, NULL, "myapp",
                              CONF_MFLAGS_IGNORE_MISSING_FILE) <= 0) {
    fprintf(stderr, "FATAL: error loading configuration file\n");
    ERR_print_errors_fp(stderr);
    exit(1);
}

Charger un fichier de configuration et une section personnalisés, afficher uniquement les avertissements en cas d'erreur, fichier de configuration manquant ignoré

: 
if (CONF_modules_load_file_ex(NULL, "/something/app.cnf", "myapp",
                              CONF_MFLAGS_IGNORE_MISSING_FILE) <= 0) {
    fprintf(stderr, "WARNING: error loading configuration file\n");
    ERR_print_errors_fp(stderr);
}

Charger et analyser manuellement le fichier de configuration, gestion d'erreur personnalisée

: 
FILE *fp;
CONF *cnf = NULL;
long eline;
fp = fopen("/somepath/app.cnf", "r");
if (fp == NULL) {
    fprintf(stderr, "Error opening configuration file\n");
    /* Other missing configuration file behaviour */
} else {
    cnf = NCONF_new_ex(libctx, NULL);
    if (NCONF_load_fp(cnf, fp, &eline) == 0) {
        fprintf(stderr, "Error on line %ld of configuration file\n", eline);
        ERR_print_errors_fp(stderr);
        /* Other malformed configuration file behaviour */
    } else if (CONF_modules_load(cnf, "appname", 0) <= 0) {
        fprintf(stderr, "Error configuring application\n");
        ERR_print_errors_fp(stderr);
        /* Other configuration error behaviour */
    }
    fclose(fp);
    NCONF_free(cnf);
}
