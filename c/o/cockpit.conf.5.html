NOM

cockpit.conf - Fichier de configuration de Cockpit

DESCRIPTION

Cockpit peut être configuré via /etc/cockpit/cockpit.conf. Si $XDG_CONFIG_DIRS est défini, alors le premier chemin contenant un ../cockpit/cockpit.conf est utilisé à la place. D'autres fichiers et répertoires de configuration sont recherchés de la même manière.

Ce fichier n'est pas requis et pourrait devoir être créé manuellement. Le fichier a une syntaxe de fichier INI et contient donc des paires clé/valeur, regroupées en sections thématiques. Voir les exemples ci-dessous pour plus de détails.

Remarque : Le port sur lequel cockpit écoute ne peut pas être modifié dans ce fichier. Pour changer le port, modifiez le fichier systemd cockpit.socket.

WEBSERVICE

Origins

Par défaut, cockpit n'acceptera pas les connexions websocket cross-domain. Utilisez ce paramètre pour autoriser l'accès depuis des domaines alternatifs. Les origines doivent inclure le schéma, l'hôte et le port, si nécessaire. Les caractères génériques et les expressions glob sont autorisés. 
[WebService]
Origins = https://somedomain1.com https://somedomain2.com:9090 https://*.somedomain3.com

ProtocolHeader

Configurez cockpit pour qu'il examine le contenu de cet en-tête afin de déterminer si une connexion utilise TLS. Ceci ne doit être utilisé que lorsque cockpit se trouve derrière un proxy inverse, et il faut veiller à s'assurer que les requêtes entrantes ne peuvent pas définir cet en-tête. 
[WebService]
ProtocolHeader = X-Forwarded-Proto

ForwardedForHeader

Configurez cockpit pour qu'il examine le contenu de cet en-tête afin de déterminer l'origine réelle d'une connexion. Ceci ne doit être utilisé que lorsque cockpit se trouve derrière un proxy inverse, et il faut veiller à s'assurer que les requêtes entrantes ne peuvent pas définir cet en-tête. 
[WebService]
ForwardedForHeader = X-Forwarded-For

LoginTitle

Définit le titre du navigateur pour l'écran de connexion.

LoginTo

Lorsque défini sur true, l'option Se connecter à sur l'écran de connexion est visible et permet de se connecter à un autre serveur. Lorsque défini sur false, les connexions à distance directes sont interdites. Si cette option n'est pas spécifiée, elle sera automatiquement détectée en fonction de l'installation du paquet cockpit-bridge et de la disponibilité du programme ssh.

Si cockpit-ws est exposé sur Internet, et a également accès à un réseau interne privé, il est recommandé de définir explicitement LoginTo=false. Cela empêche les attaquants distants non authentifiés de scanner le réseau interne à la recherche de machines existantes et de ports ouverts.

RequireHost

Lorsque défini sur true, cockpit exigera des utilisateurs qu'ils utilisent l'option Se connecter à pour spécifier l'hôte auquel se connecter.

AllowMultiHost

Lorsque défini sur true, cockpit permettra aux utilisateurs de se connecter à plusieurs hôtes dans une seule session. Le comportement par défaut dépend du système d'exploitation.

Lors de la connexion à plusieurs serveurs, JavaScript s'exécute sans isolation. Tous les systèmes seront vulnérables à d'éventuelles attaques provenant d'autres hôtes connectés. Activez cette option uniquement lorsque tous les hôtes sont approuvés.

MaxStartups

Identique à l'option de configuration sshd du même nom. Spécifie le nombre maximum de tentatives de connexion simultanées autorisées. Les connexions supplémentaires seront abandonnées jusqu'à ce que l'authentification réussisse ou que les connexions soient fermées. Par défaut, 10.

Alternativement, le rejet précoce aléatoire peut être activé en spécifiant les trois valeurs séparées par des deux-points : start:rate:full (par exemple, "10:30:60"). Cockpit commencera à refuser les tentatives d'authentification avec une probabilité de rate/100 (30%) s'il y a actuellement start (10) connexions non authentifiées. La probabilité augmente linéairement et toutes les tentatives de connexion sont refusées si le nombre de connexions non authentifiées atteint full (60).

AllowUnencrypted

Si true, cockpit acceptera les connexions HTTP non chiffrées. Sinon, il redirigera toutes les connexions HTTP vers HTTPS. Les exceptions concernent les connexions depuis localhost et pour certaines URL (comme /ping). Par défaut, false.

UrlRoot

L'URL racine où vous servirez cockpit. Lorsqu'elle est fournie, cockpit s'attendra à ce que toutes les requêtes soient préfixées par l'URL donnée. Ceci est surtout utile lorsque vous utilisez cockpit derrière un proxy inverse, tel que nginx. /cockpit/ et /cockpit+ sont réservés et ne doivent pas être utilisés. Par exemple, /cockpit-new/ est acceptable. /cockpit/ et /cockpit+new/ ne le sont pas.

ClientCertAuthentication

Si true, activez l'authentification par certificat client TLS pour les utilisateurs. Communément, ceux-ci sont fournis par une carte à puce, mais il est tout aussi possible d'importer des certificats directement dans le navigateur web. Veuillez consulter la section Authentification par certificat/carte à puce[1] du guide Cockpit pour plus de détails.

Shell

L'URL relative du composant de niveau supérieur à afficher dans Cockpit une fois connecté. Par défaut, /shell/index.html

LOG

Fatal

Le type de messages de journal dans le bridge à considérer comme fatals. Séparez plusieurs valeurs par des espaces. Les valeurs pertinentes sont : criticals et warnings.

OAUTH

Cockpit peut être configuré pour prendre en charge le flux d'autorisation OAuth implicit grant[2]. En cas de succès, le jeton oauth résultant sera passé à cockpit-ws en utilisant le schéma d'authentification Bearer. Pour qu'une connexion réussisse, cockpit devra également être configuré pour vérifier et autoriser les jetons Bearer.

URL

C'est l'URL vers laquelle cockpit redirigera le navigateur des utilisateurs lorsqu'il aura besoin d'obtenir un jeton oauth. Cockpit ajoutera un paramètre redirect_uri à l'URL avec l'emplacement où le fournisseur oauth devra rediriger une fois qu'un jeton aura été obtenu.

ErrorParam

Lorsqu'un fournisseur oauth redirige un utilisateur vers cockpit, recherchez ce paramètre dans la chaîne de requête ou la partie fragment de l'URL pour trouver un message d'erreur. S'il n'est pas fourni, il sera par défaut error_description

TokenParam

Lorsqu'un fournisseur oauth redirige un utilisateur vers cockpit, recherchez ce paramètre dans la chaîne de requête ou la partie fragment de l'URL pour trouver le jeton d'accès. S'il n'est pas fourni, il sera par défaut access_token

SESSION

Banner

Le contenu du fichier spécifié (communément /etc/issue) est affiché sur la page de connexion. Par défaut, aucune bannière n'est affichée.

IdleTimeout

Temps en minutes après lequel la session expire et l'utilisateur est déconnecté si aucune action utilisateur n'a été effectuée dans le délai imparti. Ce délai d'inactivité ne s'applique qu'aux connexions par mot de passe interactives. Avec des méthodes d'authentification non interactives comme Kerberos, OAuth ou la connexion par certificat, le navigateur ne peut pas oublier les identifiants, et donc les déconnexions automatiques ne sont pas utiles pour protéger les identifiants des sessions oubliées. Définissez à 0 pour désactiver le délai d'expiration de la session. 
[Session]
IdleTimeout=15
Lorsqu'elle n'est pas spécifiée, il n'y a pas de délai d'inactivité par défaut.

WarnBeforeConnecting

Indique s'il faut avertir avant de se connecter à des hôtes distants depuis le Shell. Par défaut, true. 
[Session]
WarnBeforeConnecting=false

BOGUES

Veuillez envoyer les rapports de bogues soit au traqueur de bogues de la distribution, soit au traqueur de bogues en amont[3].
