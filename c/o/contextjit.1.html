NOM


mtx-context - Gestion des processus ConTeXt

SYNOPSIS

mtxrun --script context [ OPTIONS ... ] [ NOMSDEFICHIERS ]

DESCRIPTION

Gestion des processus ConTeXt

OPTIONS : DE BASE

--run
traiter (un ou plusieurs) fichiers (action par défaut)
--make
créer les formats context
--ctx=name
utiliser le fichier ctx (spécification de gestion des processus)
--noctx
ignorer les directives et drapeaux ctx
--interface
utiliser l'interface utilisateur spécifiée (par défaut : en)
--autopdf
fermer le fichier pdf dans la visionneuse et lancer la visionneuse pdf par la suite
--purge
purger les fichiers ou non après une exécution (--pattern=...)
--purgeall
purger tous les fichiers ou non après une exécution (--pattern=...)
--usemodule=list
charger le module ou le style donné, faisant normalement partie de la distribution
--environment=list
charger d'abord le fichier d'environnement donné (styles de document)
--mode=list
activer les modes donnés (traitement conditionnel dans les styles)
--path=list
consulter aussi les chemins donnés lors de la recherche de fichiers
--arguments=list
définir des variables qui peuvent être consultées pendant une exécution (paires clé/valeur)
--randomseed=number
définir la graine aléatoire
--result=name
renommer la sortie résultante avec le nom donné
--trackers=list
définir les variables de suivi (afficher la liste avec --showtrackers)
--directives=list
définir les variables de directive (afficher la liste avec --showdirectives)
--silent=list
désactiver les catégories de journalisation (afficher la liste avec --showlogcategories)
--strip
supprimer le code Lua (uniquement destiné à la production où aucune erreur n'est attendue)
--errors=list
afficher les erreurs à la fin d'une exécution, quitter si présentes dans la liste (aussi avec --silent)
--htmlerrorpage
générer une page d'erreur html à la place (optionnel : =scite)
--noconsole
désactiver la journalisation sur la console (fichier journal uniquement)
--nodummy
ne pas créer de fichier factice (peut perturber les visionneuses pdf qui gardent le fichier en vue)
--purgeresult
purger le fichier de résultat avant l'exécution
--find=string
rechercher le motif donné dans les sources de la documentation
--forcexml
forcer le squelette xml
--forcecld
forcer le squelette cld (document lua context)
--forcelua
forcer le squelette lua (comme texlua)
--forcemp
forcer le squelette mp
--arrange
exécuter une passe d'imposition supplémentaire, à condition que le style configure l'imposition
--noarrange
ignorer les spécifications d'imposition dans le style
--pages
rapporter les numéros de page des pages nommées et lister les références (--page=... ou --page=...)
--jit
utiliser luajittex avec jit désactivé (utiliser uniquement la machine virtuelle plus rapide)
--jiton
utiliser luajittex avec jit activé (dans la plupart des cas pas plus rapide, voire plus lent)
--once
exécuter une seule fois (aucun fichier de données multi-passe n'est produit)
--runs
traiter au plus ce nombre de fois
--forcedruns
traiter ce nombre de fois (permet des passes d'essai d'optimisation)
--batchmode
exécuter sans s'arrêter et ne pas afficher de messages sur la console
--nonstopmode
exécuter sans s'arrêter
--nocompactfonts
revenir à la mise à l'échelle des polices moins efficace (traditionnelle)
--nosynctex
n'initialise jamais synctex (pour les exécutions de production)
--synctex
exécuter avec synctex activé (mieux vaut utiliser tupsynctex[state=start])
--nodates
omettre les dates d'exécution dans le fichier pdf (valeur optionnelle : un nombre (décalage 1970) ou une chaîne "AAAA-MM-JJ HH:MM")
--nocompression
désactive de force la compression dans le backend
--trailerid
identifiant de trailer alternatif (ou constant)
--generate
générer la base de données de fichiers etc. (comme le fait luatools)
--paranoid
ne pas descendre dans .. et ../..
--version
rapporter la version de context installée
--global
supposer que le fichier donné est présent ailleurs
--nofile
utiliser un fichier factice comme nom de travail
--forceinput
utiliser ce fichier comme fichier d'entrée au lieu de celui donné
--expert
afficher quelques options supplémentaires

OPTIONS : EXPERT

--touch
mettre à jour le numéro de version de context (fournir aussi --expert, fournir éventuellement --basepath)
--nostatistics
omettre les statistiques d'exécution à la fin de la passe
--profile
profiler le travail (utiliser : mtxrun --script profile --analyze)
--timing
générer un aperçu du chronométrage et des statistiques
--keeptuc
conserver les fichiers tuc précédents (nomdutravail-tuc-[run].tmp)
--keeppdf
conserver les fichiers pdf précédents (nomdutravail-pdf-keep.tmp)
--keeplog
conserver les fichiers journal précédents (nomdutravail-log-[run].tmp)
--notuc
ne pas écrire de fichier tuc
--lmtx
forcer le mode lmtx (lorsqu'il est disponible)
contextjit(1) - Arch manual pages

OPTIONS: BASIC

--overloadmode=error|warning|0--6|255
activer la vérification de surcharge csname
--extra=name
traiter les extras (mtx-context-... dans la distribution)
--extras
afficher les extras
--ownerpassword
chiffrer le fichier (pdf) en utilisant ce mot de passe maître
--userpassword
utiliser un mot de passe supplémentaire pour ouvrir le document
--permissions
liste de : print, modify, extract, add, fillin, assemble, quality
--wtpdf
ajouter une balise de conformité wtpdf mais vérifier d'abord si elle s'applique

OPTIONS: EXPERT

--pdftex
traiter le fichier avec texexec en utilisant pdftex
--xetex
traiter le fichier avec texexec en utilisant xetex
--mkii
traiter le fichier avec texexec
--pipe
ne pas vérifier le fichier et entrer en mode défilement (--dummyfile=whatever.tmp)
--parallel
traiter plusieurs fichiers en même temps (vous pouvez spécifier un nombre de processus, par défaut : 8)
--parallellist
traiter les commandes dans ce fichier (les lignes commençant par 'context')
--sandbox
traiter le fichier dans un environnement limité
--addbinarypath
ajouter le binarypath (trouvé) au début des runners
