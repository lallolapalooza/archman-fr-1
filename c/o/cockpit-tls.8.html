NOM

cockpit-tls - Proxy TLS pour le service web Cockpit

SYNOPSIS

cockpit-tls [--help] [--port PORT] [--no-tls] [--idle-timeout SECONDS]

DESCRIPTION

Le programme cockpit-tls est un proxy HTTP terminant les connexions TLS pour cockpit-ws(8). Il gère un ensemble d'instances cockpit-ws isolées, une par certificat client TLS, plus une pour TLS sans certificat client, et une pour le HTTP non chiffré. Ainsi, une session ne peut pas interférer avec une autre via d'éventuelles vulnérabilités de sécurité.

Les utilisateurs ou les administrateurs ne devraient jamais avoir besoin de démarrer ce programme car il est automatiquement démarré par systemd(1) via l'activation par socket.

SÉCURITÉ DU TRANSPORT

Pour spécifier le certificat TLS que le service web doit utiliser, déposez simplement un fichier avec l'extension .cert dans le répertoire /etc/cockpit/ws-certs.d, ou en dessous de $XDG_CONFIG_DIRS s'il est défini (voir cockpit.conf[1]). S'il y a plusieurs fichiers dans ce répertoire, le fichier ayant la plus haute priorité est choisi après le tri.

Le fichier .cert doit contenir au moins deux blocs PEM de style OpenSSL. Le premier bloc ou plusieurs blocs BEGIN CERTIFICATE pour le certificat serveur et les autorités de certification intermédiaires, et un second bloc contenant un BEGIN PRIVATE KEY ou similaire. La clé ne doit pas être chiffrée.

S'il n'y a pas de certificat TLS, un certificat auto-signé est automatiquement généré en utilisant sscg (si disponible) ou openssl et stocké dans le fichier 0-self-signed.cert.

Lors de l'inscription à un domaine FreeIPA, un certificat SSL est demandé au serveur IPA et stocké dans 10-ipa.cert.

Pour vérifier quel certificat cockpit-ws utilisera, exécutez la commande suivante.

$ sudo /usr/libexec/cockpit-certificate-ensure --check

Ou, sur les systèmes basés sur Debian :

$ sudo /usr/lib/cockpit/cockpit-certificate-ensure --check

Si vous utilisez certmonger pour gérer les certificats, la commande suivante peut être utilisée pour générer une paire certificat/clé :

CERT_FILE=/etc/cockpit/ws-certs.d/50-certmonger.crt
KEY_FILE=/etc/cockpit/ws-certs.d/50-certmonger.key
getcert request -f ${CERT_FILE} -k ${KEY_FILE} -D $(hostname --fqdn)

OPTIONS

--help

Affiche les options d'aide.

--port PORT

Sert les requêtes HTTP sur PORT au lieu du port 9090. Normalement, Cockpit est démarré à la demande par l'activation par socket de systemd, et cette option n'a aucun effet. Mettez à jour le fichier cockpit.socket avec la directive ListenStream de la manière habituelle pour systemd.

--no-tls

N'utilise pas TLS. Les certificats ne seront pas lus et les connexions https seront refusées. Dans ce cas, cockpit-tls ne gérera qu'une seule instance cockpit-ws, et n'aura donc pas de comportement différent de l'exécution directe de cockpit-ws --no-tls. Utilisez ceci uniquement pour le débogage ou les tests.

--idle-timeout SECONDS

Si supérieur à 0, quitte si aucune connexion n'a eu lieu pendant le nombre de secondes donné, c'est-à-dire si le serveur est inactif. Si non spécifié, la valeur par défaut est 90.

ENVIRONNEMENT

Le programme cockpit-tls attend que la variable d'environnement RUNTIME_DIRECTORY soit définie sur un répertoire vide (de préférence dans /run/) qui n'est accessible que par l'utilisateur système sous lequel il s'exécute. Ce répertoire contient les sockets Unix pour la communication avec les instances de cockpit-ws, et à l'avenir, des informations sur l'état des certificats clients. Cette variable est normalement définie par l'unité systemd cockpit.service.

En outre, cockpit-tls utilisera la variable d'environnement XDG_CONFIG_DIRS de la **Spécification XDG basée sur le répertoire**[2] pour trouver ses certificats et le fichier de configuration cockpit.conf(5).
