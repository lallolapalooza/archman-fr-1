COMM(1P) Manuel du programmeur POSIX COMM(1P)

PROLOG

Cette page de manuel fait partie du Manuel du programmeur POSIX. L'implémentation Linux de cette interface peut différer (consultez la page de manuel Linux correspondante pour les détails du comportement sous Linux), ou l'interface peut ne pas être implémentée sous Linux.

NOM

comm — sélectionner ou rejeter les lignes communes à deux fichiers

SYNTAXE

comm [-123] fichier1 fichier2

DESCRIPTION

L'utilitaire comm lira fichier1 et fichier2, qui doivent être triés selon la séquence de classement actuelle, et produira trois colonnes de texte en sortie : les lignes uniquement dans fichier1, les lignes uniquement dans fichier2, et les lignes présentes dans les deux fichiers.

Si les lignes des deux fichiers ne sont pas triées conformément à la séquence de classement de la locale actuelle, les résultats ne sont pas spécifiés.

Si la séquence de classement de la locale actuelle n'a pas d'ordre total sur tous les caractères (voir le volume Définitions de base de POSIX.1‐2017, Section 7.3.2, LC_COLLATE) et si des lignes des fichiers d'entrée se classent de manière égale mais ne sont pas identiques, comm devrait les traiter comme des lignes différentes mais peut les traiter comme étant identiques. S'il les traite comme différentes, comm devrait s'attendre à ce qu'elles soient triées selon une comparaison supplémentaire octet par octet en utilisant la séquence de classement pour la locale POSIX et si elles ne sont pas triées de cette manière, la sortie de comm peut identifier ces lignes comme étant à la fois uniques à fichier1 et uniques à fichier2 au lieu d'être présentes dans les deux fichiers.

OPTIONS

L'utilitaire comm doit être conforme aux Définitions de base du volume POSIX.1‐2017, Section 12.2, Conventions de syntaxe des utilitaires.

Les options suivantes doivent être prises en charge :

-1
Supprimer la colonne de sortie des lignes uniques à fichier1.
-2
Supprimer la colonne de sortie des lignes uniques à fichier2.
-3
Supprimer la colonne de sortie des lignes dupliquées dans fichier1 et fichier2.

OPÉRANDES

Les opérandes suivants doivent être pris en charge :

fichier1
Un chemin d'accès du premier fichier à comparer. Si fichier1 est '-', l'entrée standard sera utilisée.
fichier2
Un chemin d'accès du second fichier à comparer. Si fichier2 est '-', l'entrée standard sera utilisée.

Si fichier1 et fichier2 font tous deux référence à l'entrée standard ou au même fichier FIFO spécial, fichier bloc spécial ou fichier caractère spécial, les résultats ne sont pas définis.

STDIN

L'entrée standard ne sera utilisée que si l'un des opérandes fichier1 ou fichier2 fait référence à l'entrée standard. Voir la section FICHIERS D'ENTRÉE.

FICHIERS D'ENTRÉE

Les fichiers d'entrée doivent être des fichiers texte.

VARIABLES ENVIRONNEMENT

Les variables d'environnement suivantes affecteront l'exécution de comm :

LANG
Fournit une valeur par défaut pour les variables d'internationalisation qui ne sont pas définies ou sont vides. (Voir le volume Définitions de base de POSIX.1‐2017, Section 8.2, Variables d'internationalisation pour la priorité des variables d'internationalisation utilisées pour déterminer les valeurs des catégories de locale.)
LC_ALL
Si définie à une chaîne de caractères non vide, remplace les valeurs de toutes les autres variables d'internationalisation.
LC_COLLATE

Détermine la locale pour la séquence de classement que comm s'attend à avoir été utilisée lors du tri des fichiers d'entrée.
LC_CTYPE
Détermine la locale pour l'interprétation des séquences d'octets de données texte en caractères (par exemple, caractères mono-octet par opposition à multi-octets dans les arguments et les fichiers d'entrée).
LC_MESSAGES

Détermine la locale qui doit être utilisée pour affecter le format et le contenu des messages de diagnostic écrits sur la sortie standard d'erreur.
NLSPATH
Détermine l'emplacement des catalogues de messages pour le traitement de LC_MESSAGES.

ÉVÉNEMENTS ASYNCHRONES

Par défaut.

STDOUT

L'utilitaire comm produira une sortie en fonction des options sélectionnées. Si les options -1, -2 et -3 sont toutes sélectionnées, comm n'écrira rien sur la sortie standard.

Si l'option -1 n'est pas sélectionnée, les lignes contenues uniquement dans fichier1 seront écrites en utilisant le format :

"%s\n", <ligne dans fichier1>

Si l'option -2 n'est pas sélectionnée, les lignes contenues uniquement dans fichier2 sont écrites en utilisant le format :

"%s%s\n", <préfixe>, <ligne dans fichier2>

où la chaîne <préfixe> est la suivante :

<tab>
L'option -1 n'est pas sélectionnée.
chaîne nulle
L'option -1 est sélectionnée.

Si l'option -3 n'est pas sélectionnée, les lignes contenues dans les deux fichiers seront écrites en utilisant le format :

"%s%s\n", <préfixe>, <ligne dans les deux>

où la chaîne <préfixe> est la suivante :

<tab><tab>
Ni l'option -1 ni l'option -2 ne sont sélectionnées.
<tab>
Exactement une des options -1 et -2 est sélectionnée.
chaîne nulle
Les options -1 et -2 sont sélectionnées.

Si les fichiers d'entrée étaient triés conformément à la séquence de classement de la locale actuelle, les lignes écrites seront dans la séquence de classement de la locale actuelle. Si les fichiers d'entrée contenaient des lignes qui se classaient de manière égale mais n'étaient pas identiques et que dans chaque fichier ces lignes étaient triées selon une comparaison supplémentaire octet par octet en utilisant la séquence de classement pour la locale POSIX, et que comm les traitait comme des lignes différentes, alors les lignes écrites qui se classent de manière égale mais ne sont pas identiques devraient être triées selon une comparaison supplémentaire octet par octet en utilisant la séquence de classement pour la locale POSIX.

STDERR

La sortie standard d'erreur ne sera utilisée que pour les messages de diagnostic.

FICHIERS DE SORTIE

Aucun.

DESCRIPTION ÉTENDUE

Aucune.

STATUT DE SORTIE

Les valeurs de sortie suivantes seront retournées :

 0
Tous les fichiers d'entrée ont été correctement sortis comme spécifié.
>0
Une erreur s'est produite.

en utilisant comm pour traiter les noms de chemins, il est recommandé que LC_ALL, ou au moins LC_CTYPE et LC_COLLATE, soient définis sur POSIX ou C dans l'environnement, car les noms de chemins peuvent contenir des séquences d'octets qui ne forment pas de caractères valides dans certaines locales, auquel cas le comportement de l'utilitaire serait indéfini. Dans la locale POSIX, chaque octet est un caractère simple d'un seul octet valide, et donc ce problème est

évité.

Si la séquence de collation de la locale actuelle n'a pas un ordre total de tous les caractères, cela peut affecter le comportement de comm de la manière suivante

:
*
Si comm considère les lignes comme identiques uniquement si elles sont identiques, certaines lignes peuvent être identifiées de manière trompeuse comme étant à la fois uniques à file1 et uniques à file
2.
*
Si comm considère les lignes comme identiques si elles ont la même collation et qu'une ligne de file1 a la même collation qu'une ligne de file2 mais n'est pas identique à celle-ci, l'une des lignes est identifiée de manière trompeu
se comme étant dans les deux fichiers et l'
autre n'est pas écrite dans la sortie du tout.

Ces problèmes peuvent être évités en forçant l'utilisation de la locale POSIX ; par exemple, ce qui suit identifie les lignes dans les deux file1 et file2

: 
LC_ALL=POSIX sort file1 > file1.posix
LC_AL
L=POSIX sort file2 > file2.posix LC_ALL=PO
SIX comm -12 file1.posix file2.posix | sort

Le sort final réordonne la sortie de comm selon la séquence de collation de la locale d'origine. Cela peut être difficile si

plus d'une colonne est en sortie et que les <blancs> initiaux ne peuvent pas être ignorés.
