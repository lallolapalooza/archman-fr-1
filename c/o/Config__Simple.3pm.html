RÉSUM

É

La lecture et l'écriture de fichiers de configuration est l'une des tâches les plus fréquentes de toute conception logicielle. Config::Simple est la bibliothèque qui vous aide à y

parvenir.

Config::Simple est une classe représentant un objet fichier de configuration. Elle prend en charge plus

ieurs syntaxes de fichiers de configuration et tente d'identifier automatiquement la syntaxe du fichier.
La bibliothèque prend en charge l'analyse, la mise à jour et la création de fichiers de configuration.

À PROPOS DES FICHIERS DE

CONFIGURATION

Conserver des variables configurables dans le code source de votre programme est laid, vraiment. Et pour les personnes sans beaucoup d'expérience en programmation, configurer vos programmes revient à pratiquer la magie noire. De plus, si vous devez accéder à ces valeurs depuis plusieurs fichiers, si vous voulez que vos programmes puissent mettre à jour les fichiers de configuration ou si vous souhaitez fournir une interface utilisateur plus conviviale pour vos fichiers de configuration, vous devez simplement les stocker dans un fichier externe. C'est là que Config::Simple entre en jeu, rendant la lecture et l'écriture de fichiers de configuration très

faciles.

Si vous n'avez jamais utilisé de fichiers de configuration auparavant, voici un bref aperçu des différentes syntaxes parmi lesquelles choisir. Sinon, vous pouvez passer directement à « STYLE DE PROGRAMMATION »

.

FICHIER DE CONFIGURATION

SIMPLE

La syntaxe simple est ce dont vous avez besoin pour la plupart de vos projets. Ce sont, comme le nom l'affirme, les plus simples. Le fichier se compose de paires clé/valeur, délimitées par rien d'autre que des espaces. Les clés (variables) doivent être strictement alphanumériques avec des tirets possibles (-). Les valeurs peuvent contenir n'importe quel texte arbitraire. Voici un exemple d'un tel fichier de configuration

: 
Alias     /exec
TempFile
/usr/tmp

Les commentaires commencent par un signe diè

se ('#') et ne peuvent pas partager la même l
igne avec d'autres données de configuration.

SYNTAXE DE TYPE

HTTP

Ce format de séparation des paires clé/valeur est utilisé par les messages HTTP. Chaque paire clé/valeur est séparée par un deux-points (:). Les clés sont des chaînes alphanumériques avec des tirets possibles. Les valeurs peuvent être n'importe quel texte arbitraire

:

Exemple

: 
Alias: /exec
TempFile:
/usr/tmp

Il est acceptable d'avoir des espaces autour du ':'. Les

commentaires commencent par '#' et ne peuvent pas partag
er la même ligne avec d'autres données de configuration.

FICHIER

INI

Ces fichiers de configuration sont plus natifs pour les systèmes Win32. Les données sont organisées en blocs. Chaque paire clé/valeur est délimitée par un signe égal (=). Les blocs sont déclarés sur leurs propres lignes, entourés de '[' et ']'

: 
[BLOC1]
CLE1=VALEUR1
CLE2=VALEUR2
[BLOC2]
CLE1=VALEUR1
CLE2=VALEUR2

Votre liste de lecture Winamp 2.x est un exemple d'un tel fichier de

configuration.

C'est le choix parfait si vous devez organiser votre fichier de configuration en catégories

: 
[site]
url="http://www.handalak.com"
title="Web site of a \"Geek\""
author=sherzodr
[mysql]  
dsn="dbi:mysql:db_name;host=handalak.com"
user=sherzodr
password=marley
0
1

FICHIER INI

SIMPLIFIÉ

Ces fichiers sont assez similaires aux fichiers ini traditionnels, sauf qu'ils n'ont aucune déclaration de bloc. Ce style est pratique si vous ne voulez aucune catégorisation dans votre fichier de configuration, mais que vous voulez toujours utiliser des paires clé/valeur délimitées par '='. Lors du travail avec de tels fichiers, Config::Simple les assigne à un bloc par défaut, appelé 'default' par défaut :-)

. 
url = "http://www.handalak.
com"

Les commentaires peuvent commencer so

it par un dièse ('#'), soit par un po
int-virgule (';'). Chaque commentaire
doit se trouver sur sa propre ligne.

STYLE DE

PROGRAMMATION

La plupart des programmes ont simplement besoin de pouvoir lire les paramètres d'un fichier de configuration et les assigner à un hash. Si c'est tout ce dont vous avez besoin, vous pouvez simplement utiliser sa méthode de classe import_from() avec le nom du fichier de configuration et une référence à un hash existant (éventuellement vide)

: 
Config::Simple->import_from('myconf.cfg', \%Config)
;

Maintenant votre hash %Config contient toutes les paires clé/valeur du fichier de configuration. Les clés du hash sont les noms de variables à l'intérieur de votre fichier de configuration, et les valeurs sont leurs valeurs respectives. Si "myconf.cfg" était un fichier ini traditionnel, les clés du hash se composent du nom du bloc et de la variable délimités par un point, comme "bloc.

var".

Si c'est tout ce dont vous avez besoin, vous pouvez vous arrêter ici. Sinon, poursuivez votre lecture. Config::Simple offre bien plus

encore.

LECTURE DU FICHIER DE

CONFIGURATION

Pour pouvoir utiliser plus de fonctionnalités de la bibliothèque, vous devrez utiliser son interface objet

: 
$cfg = new Config::Simple('app.cfg')
;

La ligne ci-dessus lit et analyse le fichier de configuration en conséquence. Elle tente de deviner quelle syntaxe est utilisée en passant le fichier à la méthode guess_syntax(). Alternativement, vous pouvez créer un objet vide, puis seulement ensuite lire le fichier de configuration

: 
$cfg = new Config::Simple();
$cfg->read('app.cfg')
;

Comme dans le premier exemple, read() appelle également la méthode guess_syntax() sur le

fichier.

Si, pour une raison quelconque, il échoue à deviner la syntaxe correctement (ce qui est peu probable), vous pouvez essayer de déboguer en utilisant sa méthode guess_syntax(). Elle attend un descripteur de fichier pour un fichier de configuration et retourne le nom d'une syntaxe. La valeur de retour est l'un de "ini", "simple" ou

"http". 
open(FH, "app.cfg");
printf("Ce fichier utilise la syntaxe '%s'\n", $cfg->guess_syntax(\*FH)
)
;

ACCÈS AUX

VALEURS

Après avoir lu le fichier de configuration avec succès, vous pouvez utiliser la méthode param() pour accéder aux valeurs de configuration. Par exemple

: 
$user = $cfg->param("User")
;

retournera la valeur de "User" à partir d'un fichier de configuration simple, ou d'une configuration de style http ainsi que des fichiers ini simplifiés. Pour accéder à la valeur d'un fichier ini traditionnel, considérez la syntaxe suivante

: 
$user = $cfg->param("mysql.user")
;

Ce qui précède retourne la valeur de "user" à l'intérieur du bloc "[mysql]". Remarquez l'utilisation du point "." pour délimiter les noms de bloc et de

clé.

Config::Simple prend également en charge la méthode vars(), qui, selon le contexte utilisé, retourne toutes les valeurs soit sous forme de référence de hash, soit sous forme de hash

: 
my %Config = $cfg->vars();
print "Nom d'utilisateur : $Config{User}";
# S'il s'agissait d'un fichier ini traditionnel :
print "Nom d'utilisateur : $Config{'mysql.user'}
";

Si vous appelez vars() en contexte scalaire, vous obtiendrez une référence à un hash

: 
my $Config = $cfg->vars();
print "Nom d'utilisateur : $Config->{User}
";

Si vous savez ce que vous faites, vous pouvez également avoir l'option d'importer tous les noms du fichier de configuration dans votre espace de noms actuel en tant que variables globales. Tous les noms de bloc/clé seront mis en majuscules et convertis en noms de variables valides pour Perl ; c'est-à-dire que tous les points (séparateur bloc-clé) et autres caractères '\W' seront remplacés par le soulignement '_'

: 
$cfg = new Config::Simple('app.cfg');
$cfg->import_names();
# ou, en une seule ligne :
Config::Simple->new('app.cfg')->import_names();

print STDERR "Le mode débogage est activé" if
$DEBUG_MODE;

Dans l'exemple ci-dessus, s'il y avait variable 'mode' under '[debug]' block, it will be now accessible via $DEBUG_MODE, as opposed to $cfg->param('debug.mode')

;

import_names() by default imports the values to its caller's name space. Optionally, you can specify where to import the values by passing the name of the name space as the first argument. It also prevents potential name

collisions: 
Config::Simple->new('app.cfg')->import_names('CFG');
print STDERR "Debugging mode is on" if $CFG::
DEBUG_MODE;

If all you want is to import values from a configuration file, the above syntax may still seem longer than necessary. That's why Config::Simple supports import_from() - class method, which is called with the name of the configuration file. It will call import_names() for

you: 
Config::Simple->import_from('app.cfg')
;

The above line imports all the variables into the caller's name space. It's similar to calling import_names() on an object. If you pass a string as the second argument, it will treat it as the alternative name space to import the names into. As we already showed in the very first example, you can also pass a reference to an existing hash as the second argument. In this case, that hash will be modified with the values of the configuration

file. 
# import into $CFG name space:
Config::Simple->import_from('app.cfg', 'CFG');
# import into %Config hash:
Config::Simple->import_from('app.cfg', \%Config)
;

The above line imports all the values to 'CFG' name space. import_from() returns underlying Config::Simple object (which you may not even need anymore)

: 
$cfg = Config::Simple->import
_from('app.cfg', \my %Config)
; $cfg->write('app.cfg.bak');

MISE À JOUR DES

VALEURS

Configuration values, once read into Config::Simple, can be updated from within your program by using the same param() method used for accessing them. For

example: 
$cfg->param("User", "sherzodR")
;

The above line changes the value of "User" to "sherzodR". Similar syntax is applicable for ini-files as

well: 
$cfg->param("mysql.user", "sherzodR")
;

If the key you're trying to update does not exist, it will be created. For example, to add a new "[session]" block to your ini-file, assuming this block doesn't already

exist: 
$cfg->param("session.life", "+1M")
;

You can also delete values calling delete() method with the name of the

variable: 
$cfg->delete('mysql.u
ser'); # deletes 'user
' under [mysql] block

SAUVEGARDE/ÉCRITURE DES FICHIERS DE

CONFIGURATION

The above updates to the configuration values are in-memory operations. They do not reflect in the file itself. To modify the files accordingly, you need to call either "write()" or "save()" methods on the

object: 
$cfg->write()
;

The above line writes the modifications to the configuration file. Alternatively, you can pass a name to either write() or save() to indicate the name of the file to create instead of modifying existing configuration

file: 
$cfg->write("app.cfg.bak")
;

If you want the changes saved at all times, you can turn "autosave" mode on by passing true value to $cfg->autosave(). It will make sure before your program is terminated, all the configuration values are written back to its

file: 
$cfg = new Config::
Simple('aff.cfg');
$cfg->autosave(1);

CRÉATION DE FICHIERS DE

CONFIGURATION

Occasionally, your programs may want to create their own configuration files on the fly, possibly from a user input. To create a configuration file from scratch using Config::Simple, simply create an empty configuration file object and define your syntax. You can do it by either passing "syntax" option to new(), or by calling syntax() method. Then play with param() method as you normally would. When you're done, call write() method with the name of the configuration

file: 
$cfg = new Config::Simple(syntax=>'ini');
# or you could also do:
# $cfg->autosave('ini')
$cfg->param("mysql.dsn", "DBI:mysql:db;host=handalak.com");
$cfg->param("mysql.user", "sherzodr");
$cfg->param("mysql.pass", 'marley01');
$cfg->param("site.title", 'sherzodR "The Geek"');
$cfg->write("new.cfg")
;

This creates a file "new.cfg" with the following

content: 
; Config::Simple 4.43
; Sat Mar  8 00:32:49 2003
[site]
title=sherzodR "The Geek"
[mysql]
pass=marley01
dsn=DBI:mysql:db;host=handalak.com
user=sherzodr

Neat, huh? Supported syntax keywords are "ini",

"simple" or "http". Currently there is no
support for creating simplified ini-files.

VALEURS

MULTIPLES

Ever wanted to define array of values in your single configuration variable? I have! That's why Config::Simple supports this fancy feature as well. Simply separate your values with a

comma: 
Files hp.cgi, template.html, styles.
css

Now param() method returns an array of

values: 
@files = $cfg->param("Files");
unlink $_ for
@files;

If you want a comma as part of a value, enclose the value(s) in double

quotes: 
CVSFiles "hp.cgi,v", "template.html,v", "styles.css,
v"

In case you want either of the values to hold literal quote ("), you can escape it with a

backlash: 
SiteTitle "
sherzod \"
The Geek\""

INTERFACE

TIE

If OO style intimidates you, and import_from() is too simple for you, Config::Simple also supports tie() interface. This interface allows you to tie() an ordinary Perl hash to the configuration file. From that point on, you can use the variable as an ordinary Perl

hash. 
tie %Config, "Config::Simple", 'app.cfg';
# Using %Config as an ordinary hash
print "Username is '$Config{User}'\n";
$Config{User} =
'sherzodR';

The difference between "import_from($file, \%Hash)" is, all the changes you make to the hash after tie()ing it, will also reflect in the configuration file object. If autosave() was turned on, they will also be written back to

file: 
tie %Config, "Config::Simple", "app.cfg";
tied(%Config)->autosave(1)
;

To access the method provided in OO syntax, you need to get underlying Config::Simple object. You can do so with tied()

function: 
tied(%Config)->write()
;

xperimental and not well te
sted yet. Let me know
if you encounter a problem.

DIVER

S

SENSIBILITÉ À LA

CASSE

By default, configuration file keys and values are case sensitive. Which means, $cfg->param("User") and $cfg->param("user") are referring to two different values. But it is possible to force Config::Simple to ignore cases all together by enabling "-lc" switch while loading the

library: 
use Config::Simple ('-lc')
;

WARNING: If you call write() or save(), while working on "-lc" mode, all the case information of the original fil

e will be lost. So use it if y
ou know what you're doing.

UTILISATION DES

GUILLEMETS

Some people suggest if values consist of none alpha-numeric strings, they should be enclosed in double quotes. Well, says them! Although Config::Simple supports parsing such configuration files already, it doesn't follow this rule while writing them. If you really need it to generate such compatible configuration files, "-strict" switch is what you

need: 
use Config::Simple
'-strict';

Now, when you write the configuration data back to files, if values hold

any none alpha-numeric strings, they will be quoted accordingly. All the d
ouble quotes that are part of the value will be escaped with a backslash.

GESTION DES

EXCEPTIONS

Config::Simple doesn't believe in dying that easily (unless you insult it using wrong syntax). It leaves the decision to the programmer implementing the library. You can use its error() - class method to access underlying error message. Methods that require you to check for their return values are read() and write(). If you pass filename to new(), you will need to check its return value as well. They return any true value indicating success, undef

otherwise: 
# following new() always returns true:
$cfg = new Config::Simple();
# read() can fail:
$cfg->read('app.cfg') or die $cfg->error();
# f
ollowing new() can fail: $cfg = new Config::Simple('app.cfg') or die Config::Simple->error(); # import_from() calls read(), so it can f
ail: Config::Simple->import_from('app.cfg', \%Config) or die Config::Simple->error(); # write() may fail: $cfg->write() or die $cfg->er
ror(); # tie() may fail, since it calls new() with a filename tie %Config, "Config::Simple", 'app.cfg' or die Config::Simple->error();
