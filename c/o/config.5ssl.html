SSL

Configuration

Le nom ssl_conf dans la section d'initialisation nomme la section contenant la liste des configurations SSL/TLS. Comme pour les fournisseurs, chaque nom dans cette section identifie une section avec la configuration pour ce nom. Par exemple

: 
[ssl_configuration]
server = server_tls_config
client = client_tls_config
system_default = tls_system_default
[server_tls_config]
... configuration pour les serveurs SSL/TLS ...
[client_tls_config]
... configuration pour les clients SSL/TLS ..
.

Le nom de configuration system_default a une signification spéciale. S'il existe, il est appliqué chaque fois qu'un objet SSL_CTX est créé. Par exemple, pour imposer des versions de protocole TLS et DTLS minimales à l'échelle du système

: 
[tls_system_default]
MinProtocol = TLSv1.2
MinProtocol = DTLSv1.
2

Le protocole TLS minimum est appliqué aux objets SSL_CTX qui sont basés sur TLS, et le protocole DTLS minimum à ceux qui sont basés sur DTLS. La même chose s'applique aussi aux versions maximales définies avec MaxProtocol

.

Chaque section de configuration se compose de paires nom/valeur qui sont analysées par SSL_CONF_cmd(3), qui sera appelé par SSL_CTX_config() ou SSL_config(), de manière appropriée. Notez que n'importe quels caractères avant un point initial dans la section de configuration sont ignorés, afin que la même commande puisse être utilisée plusieurs fois. C'est probablement le plus utile pour charger différents types de clés, comme montré ici

: 
[server_tls_config]
RSA.Certif
icate = server-rsa.pem ECDSA.
Certificate = server-ecdsa.pem

BOGUE

S

Il n'existe aucun moyen d'inclure des caractères en utilisant la forme octale \nnn. Les chaînes sont toutes terminées par un octet nul, donc les octets nuls ne peuvent pas faire partie de la

valeur.

L'échappement n'est pas tout à fait correct : si vous voulez utiliser des séquences comme \n, vous ne pouvez utiliser aucun échappement de guillemet sur la même

ligne.

La limite selon laquelle un seul répertoire peu

t être ouvert et lu à la fois peut être cons
idérée comme un bogue et devrait être corrigée.

E

ins de fichiers, seul le caractère guillemet double était reconnu, et les commentaires commençaient par un point-virgule. Cette foncti
on a été dépréciée dans OpenSSL 3.0 ; les applications avec des fichiers de configuration utilisant cette syntaxe devront être modifiées.
