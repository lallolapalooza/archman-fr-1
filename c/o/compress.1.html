DESCRIPTIO

N

Compress réduit la taille des fichiers nommés en utilisant le codage adaptatif de Lempel-Ziv. Chaque fois que c'est possible, chaque fichier est remplacé par un fichier avec l'extension .Z, tout en conservant les mêmes modes de propriété, les dates d'accès et de modification. Si aucun fichier n'est spécifié, l'entrée standard est compressée vers la sortie standard. Compress ne tentera de compresser que les fichiers réguliers. En particulier, il ignorera les liens symboliques. Si un fichier a plusieurs liens physiques, compress refusera de le compresser sauf si l'option -f est

donnée.

Si -f n'est pas donnée et compress est exécuté en premier plan, l'utilisateur est invité à indiquer si un fichier existant doit être

écrasé.

Les fichiers compressés peuvent être restaurés dans leur forme originale en utilisant uncompress ou zcat

.

uncompress prend une liste de fichiers sur sa ligne de commande et remplace chaque fichier dont le nom se termine par .Z et qui commence par le nombre magique correct par un fichier non compressé sans le .Z. Le fichier non compressé aura le mode, la propriété et les horodatages du fichier

compressé.

L'option -k fait que compress/uncompress conserve les fichiers d'entrée au lieu de les supprimer automatiquement

.

L'option -c fait que compress/uncompress écrit vers la sortie standard ; aucun fichier n'est

modifié.

zcat est identique à uncompress -c. zcat décompresse soit une liste de fichiers sur la ligne de commande, soit son entrée standard et écrit les données non compressées sur la sortie standard. zcat décompressera les fichiers qui ont le nombre magique correct, qu'ils aient ou non un suffixe .Z

.

Si l'option -r est spécifiée, compress fonctionnera récursivement. Si l'un des noms de fichiers spécifiés sur la ligne de commande est un répertoire, compress descendra dans le répertoire et compressera tous les fichiers qu'il y trouve. Lors de la compression, les fichiers déjà compressés seront ignorés, et lors de la décompression, les fichiers déjà décompressés seront

ignorés.

L'option -v indique à chacun de ces programmes d'afficher sa version et son niveau de correctif, ainsi que les éventuels drapeaux de préprocesseur spécifiés lors de la compilation, sur stderr avant d'effectuer toute compression ou

décompression.

Compress utilise l'algorithme de Lempel-Ziv modifié popularisé dans "A Technique for High Performance Data Compression", Terry A. Welch, IEEE Computer, vol. 17, no. 6 (juin 1984), pp. 8-19. Les sous-chaînes communes dans le fichier sont d'abord remplacées par des codes de 9 bits à partir de 257. Lorsque le code 512 est atteint, l'algorithme passe à des codes de 10 bits et continue à utiliser plus de bits jusqu'à la limite spécifiée par l'option -b (par défaut 16). Les bits doivent être compris entre 9 et 16. La valeur par défaut peut être modifiée dans le code source pour permettre à compress de s'exécuter sur une machine plus

petite.

Une fois la limite des bits atteinte, compress vérifie périodiquement le taux de compression. S'il augmente, compress continue d'utiliser le dictionnaire de codes existant. Cependant, si le taux de compression diminue, compress jette la table de sous-chaînes et la reconstruit à partir de zéro. Cela permet à l'algorithme de s'adapter au prochain "bloc" du

fichier.

Notez que l'option -b est omise pour uncompress, car le paramètre bits spécifié lors de la compression est encodé dans la sortie, avec un nombre magique pour s'assurer que ni la décompression de données aléatoires ni la recompression de données compressées n'est

tentée.

Le taux de compression obtenu dépend de la taille de l'entrée, du nombre de bits par code et de la distribution des sous-chaînes communes. En général, un texte tel que du code source ou de l'anglais est réduit de 50 à 60 %. La compression est généralement bien meilleure que celle obtenue par le codage de Huffman (comme utilisé dans pack), ou par le codage de Huffman adaptatif (compact), et prend moins de temps à

calculer.

Avec l'option -v, un message est imprimé indiquant le pourcentage de réduction pour chaque fichier

compressé.

-- peut être utilisé pour arrêter l'analyse des options et forcer

tous les arguments restants
à être traités comme des chemins.

DIAGNOSTIC

S

Le code de sortie est normalement 0 ; si le dernier fichier est plus grand après (la tentative de) compression, le code est 2 ; si une erreur se produit, le code de sortie est

1.

Utilisation : compress [-dfvcVr] [-b maxbits] [fichier ...]
Des options invalides ont été spécifiées sur la ligne de commande.
maxbits manquant
Maxbits doit suivre -b.
fichier : n'est pas au format compressé
Le fichier spécifié à uncompress n'a pas été compressé.
fichier : compressé avec xx bits, ne peut traiter que yy bits
Le fichier a été compressé par un programme qui pouvait gérer plus de bits que le code compress de cette machine. Recomprimez le fichier avec moins de bits.
fichier : a déjà le suffixe .Z -- aucune modification
Le fichier est supposé être déjà compressé. Renommez le fichier et réessayez.
fichier : nom de fichier trop long pour ajouter .Z
Le fichier ne peut pas être compressé car son nom est plus long que 12 caractères. Renommez-le et réessayez. Ce message n'apparaît pas sur les systèmes BSD.
fichier existe déjà ; voulez-vous l'écraser (y ou n) ?
Répondez "y" si vous voulez que le fichier de sortie soit remplacé ; "n" sinon.
uncompress : entrée corrompue
Une violation SIGSEGV a été détectée, ce qui signifie généralement que le fichier d'entrée a été corrompu.
Compression : xx.xx%
Pourcentage de l'entrée économisé par la compression. (Pertinent uniquement pour -v.)
-- n'est pas un fichier régulier ou un répertoire : ignoré
Lorsque le fichier d'entrée n'est pas un fichier régulier ou un répertoire (par ex. un lien symbolique, un socket, un FIFO, un fichier de périphérique), il est laissé inchangé.
-- a xx autres liens : inchangé
Le fichier d'entrée a des liens ; il est laissé inchangé. Voir ln(1) pour plus d'informations. Utilisez l'option -f pour forcer la compression des fichiers à liens multiples.
-- fichier inchangé
Aucune économie n'est réalisée par la compression. L'entrée reste intacte.
