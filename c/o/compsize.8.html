NOM

compsize - calculer le ratio de compression d'un ensemble de fichiers sur btrfs

SYNTAXE

compsize fichier-ou-répertoire [ fichier-ou-répertoire ... ]

DESCRIPTION

compsize prend une liste de fichiers sur un système de fichiers btrfs (en parcourant récursivement les répertoires) et mesure les types de compression utilisés ainsi que le ratio de compression effectif. En plus de la compression, compsize affiche l'effet des reflinks (cp --reflink, snapshots, déduplication) et de certains types de gaspillage de btrfs.

Le programme donne un rapport similaire à :
90319 fichiers traités.
Type % Utilisation Disque Non compressé Référencé
TOTAL 79% 1.4G 1.8G 1.9G
none 100% 1.0G 1.0G 1.0G
lzo 53% 446M 833M 843M

Les champs ci-dessus sont :

Type
algorithme de compression
%
utilisation disque / non compressé (ratio de compression)
Utilisation Disque
blocs sur le disque ; c'est ce que le stockage de ces fichiers vous coûte réellement (à l'exception des considérations RAID)
Non compressé
étendues non compressées ; ce dont vous auriez besoin sans compression - inclut les économies de déduplication et le gaspillage des étendues épinglées
Référencé
tailles apparentes des fichiers (sans les trous) ; c'est ce qu'un système de fichiers traditionnel qui supporte les trous et l'empaquetage efficace des queues, ou tar -S, aurait besoin pour stocker ces fichiers

Voyons cela sur un exemple : un fichier de 128 Ko est stocké sous la forme d'une seule étendue A qui a été compressée en une seule page de 4 Ko. Il reçoit ensuite une écriture de 32 Ko à l'offset 32 Ko, qui a également été compressée en une seule page de 4 Ko, stockée sous la forme de l'étendue B.

Le fichier apparaît maintenant comme :
+-------+-------+---------------+
étendue A | utilisé | gaspillage | utilisé |
+-------+-------+---------------+
étendue B | utilisé |
+-------+

Le "gaspillage" à l'intérieur de l'étendue A ne peut pas être récupéré tant que l'étendue entière n'est pas réécrite (par exemple par defrag). Si elle est compressée, l'étendue entière doit être lue à chaque fois que cette partie du fichier est lue, donc le "gaspillage" est toujours requis.

Dans ce cas, nous avons : Utilisation Disque : 8 Ko, Non compressé : 160 Ko, Référencé : 128 Ko.

OPTIONS

-b/--bytes
Afficher les comptes bruts en octets plutôt que des tailles lisibles par l'homme.
-x/--one-file-system
Ignorer les fichiers et répertoires sur des systèmes de fichiers différents.

SIGNAUX

USR1
Affiche des données partielles pour les fichiers traités jusqu'à présent.

AVERTISSEMENTS

Les fichiers récemment écrits peuvent apparaître comme n'occupant aucun espace jusqu'à ce qu'ils soient effectivement alloués et compressés ; cela se produit une fois qu'ils sont synchronisés ou lors de la sortie naturelle, généralement de l'ordre de 30 secondes.

Les ioctls utilisés par ce programme nécessitent les privilèges root.

Les étendues en ligne sont considérées comme toujours uniques, même si elles partagent les mêmes octets sur le disque.

Ce programme ne supporte pas actuellement les systèmes de fichiers de plus de 8 To sur des machines 32 bits, mais les autres outils btrfs non plus.
