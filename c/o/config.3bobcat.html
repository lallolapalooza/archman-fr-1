DESCRIPTIO

N

Les objets Config traitent les fichiers de configuration standard de style unix. Les espaces initiaux (blancs et tabulations) sont supprimés des lignes traitées. Si une ligne se termine par une barre oblique inverse (\), la barre oblique inverse est supprimée et la ligne suivante (espaces initiaux supprimés) est ajoutée à la ligne

courante.

Si le drapeau rmComment est défini à true, les lignes vides et les informations sur les lignes à partir du premier # sont supprimées. Si une barre oblique inverse précède le caractère de commentaire (c'est-à-dire \#), alors cela n'est pas considéré comme un commentaire, mais il est remplacé par un seul caractère #. De même, si le drapeau rmComment était défini, deux caractères de barre oblique inverse consécutifs sont remplacés par un seul caractère de barre oblique

inverse.

Toutes les lignes du fichier de configuration (éventuellement sans commentaire) sont stockées dans l' objet Config. Leurs numéros de ligne peuvent également être

récupérés.

Au moment de la construction, le traitement des commentaires (conserver le commentaire / supprimer le commentaire) et le type de recherche (sensible à la casse / insensible) peuvent être

spécifiés.

En plus de l'un des constructeurs, le membre load peut être utilisé pour traiter un fichier de configuration, en remplaçant le contenu actuel de l'objet par le contenu d'un autre fichier de configuration. Le membre load ne peut pas être utilisé pour modifier les paramètres de traitement du fichier de configuration, mais l'affectation surchargée est prise en charge et le traitement des commentaires et de la casse peut être modifié par les membres

set.

Souvent, les lignes dans la configuration présentent la structure suivante

: 
    id: valeur   contenu restant
Si id est un identifiant C++, il est appelé un ID dans cette page man. Lors de la recherche des ID, tous les caractères non blancs immédiatement suivant le ID sont ignorés (dans l'exemple, l'ID est id). Une clé est définie comme la première entrée délimitée par des espaces sur les lignes. Dans l'exemple, la clé est id:. La première entrée délimitée par des espaces suivant la clé est appelée la valeur de la ligne, tandis que tout le contenu de la ligne commençant à la valeur est appelé la queue de la ligne.

Les objets Config offrent divers membres pour traiter les lignes de fichier de configuration structurées de cette manière. Cependant, les lignes ne doivent pas être structurées de cette manière. Toutes les lignes d'un fichier de configuration sont mises à disposition par les objets Config et peuvent être traitées de

plusieurs autres
manières également.

EXEMPL

E

Supposons que le fichier de configuration soit nommé config.rc, contenant les lignes suivantes

: 
# ceci est ignoré
noline: celui-ci aussi
line: ceci est trouvé
ceci n'est pas une ligne contenant line: au début de la ligne
line: celui-ci est
    line: qu'en est-il de celui-ci ? il s'étend sur plusieurs lignes
et il peut bien sûr y avoir plus de lignes dans ce
fichier

Le programme suivant peut être compilé et exécuté comme a.out conf

ig.rc : 
#include <iostream>
#include <algorithm>
#include <string>
#include <bobcat/config>
using namespace std;
using namespace FBB;
int main(int argc, char **argv)
{
    Config cf(argv[1]);
    cout << *cf.find("this one") << ’\n’; // find text within a line
                                     // find all lines specifying ID ’line’
    auto [begin, end] = cv.beginEndID("line");
    copy(begin, end, ostream_iterator<CF_Line>(cout, "\n"));
}

Produisant la sortie

: 
line: this is found
line: this o
ne is line: what about this one
? it extends over multiple lines
