COLLECTL2PCP(1) Manuel général des commandes COLLECTL2PCP(1)

NOM

collectl2pcp - importer des données collectl dans une archive PCP

SYNTAXE

collectl2pcp [-fv?] [-D debug] fichier [fichier ...] archive

DESCRIPTION

collectl2pcp lit les données brutes de collectl(1) à partir de chaque fichier et crée une nouvelle archive PCP dont le nom de base est archive. Chaque fichier d'entrée peut être gzippé (avec le suffixe .gz). L' archive PCP et au moins un fichier d'entrée sont des arguments requis.

OPTIONS

Les options de ligne de commande disponibles sont :

-f, --force
Écrase archive (ainsi que les fichiers d'index et meta) s'ils existent déjà.
-v, --verbose
Rapporte la progression et les erreurs de manière verbeuse. Ceci rapporte également le nombre de métriques non supportées dans le(s) fichier(s) d'entrée collectl(1), qui sont normalement ignorées silencieusement.
-?, --help
Affiche le message d'utilisation et quitte.
fichier [fichier ...]
Ce sont les fichiers d'entrée collectl(1). S'il y en a plusieurs, ils doivent contenir des données pour le même hôte et être fournis dans l'ordre chronologique des horodatages sur la ligne de commande. Notez que lorsque collectl(1) est exécuté en tant que service, il crée normalement des fichiers avec des noms basés sur la date qui seront triés chronologiquement (par exemple, /var/log/collectl/*.gz sera trié correctement).

ENVIRONNEMENT PCP

Les variables d'environnement commençant par le préfixe PCP_ sont utilisées pour paramétrer les noms de fichiers et de répertoires utilisés par PCP. Sur chaque installation, le fichier /etc/pcp.conf contient les valeurs locales de ces variables. La variable $PCP_CONF peut être utilisée pour spécifier un fichier de configuration alternatif, comme décrit dans pcp.conf(5).

Pour les variables d'environnement affectant les outils PCP, voir pmGetOptions(3).

OPTIONS DE DÉBOGAGE

L'option -D ou --debug active la sortie de diagnostics supplémentaires sur stderr pour aider à résoudre les problèmes, bien que l'information soit parfois cryptique et principalement destinée aux développeurs plutôt qu'aux utilisateurs finaux. debug est une liste d'options de débogage séparées par des virgules ; utilisez pmdbg(1) avec l'option -l pour obtenir une liste des options de débogage disponibles et leur signification.

VOIR AUSSI

collectl(1), PCPIntro(1), LOGIMPORT(3), pcp.conf(5), pcp.env(5) et PMNS(5).
