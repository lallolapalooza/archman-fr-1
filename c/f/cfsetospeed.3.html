N

Les fonctions termios décrivent une interface de terminal générale qui est fournie pour contrôler les ports de communication

asynchrones.

La structure

Beaucoup des fonctions décrites ici ont un argument termios_p qui est un pointeur vers une structure termios. Cette structure contient au moins les membres suivants

cfgetospeed() renvoie le débit en bauds de sortie

NOM

cfgetospeed, cfsetospeed, cfgetispeed, cfsetispeed, cfsetspeed - obtenir et définir la vitesse du port série

SYNOPSIS

#include <termios.h>

speed_t cfgetospeed(const struct termios *termios_p);

int cfsetospeed(struct termios *termios_p, speed_t speed);

speed_t cfgetispeed(const struct termios *termios_p);

int cfsetispeed(struct termios *termios_p, speed_t speed);

int cfsetspeed(struct termios *termios_p, speed_t speed);

DESCRIPTION

La structure termios définit les paramètres de contrôle d'un terminal (voir termios(3)).

La fonction cfgetospeed() retourne la vitesse de transmission de sortie stockée dans la structure termios pointée par termios_p.

La fonction cfsetospeed() définit la vitesse de transmission de sortie stockée dans la structure termios pointée par termios_p à speed, qui doit être l'une des constantes suivantes :

Ces constantes sont également prises en charge sur les architectures non-SPARC :

B2500000

En raison des différences entre les architectures, les applications portables doivent vérifier si une constante Bnnn particulière est définie avant de l'utiliser.

Le débit nul, B0, est utilisé pour terminer la connexion. Si B0 est spécifié, les lignes de contrôle du modem ne seront plus assertées. Normalement, cela déconnectera la ligne. CBAUDEX est un masque pour les vitesses au-delà de celles définies dans POSIX.1 (57600 et au-dessus). Ainsi, B57600 & CBAUDEX est non nul.

Il est possible de définir la vitesse de transmission à une valeur autre que celles définies par les constantes Bnnn via l'appel ioctl TCSETS2 ; voir ioctl_tty(2).

La fonction cfgetispeed() retourne la vitesse de transmission d'entrée stockée dans la structure termios.

La fonction cfsetispeed() définit la vitesse de transmission d'entrée stockée dans la structure termios à speed, qui doit être spécifiée comme l'une des constantes Bnnn listées ci-dessus pour cfsetospeed(). Si la vitesse de transmission d'entrée est définie à la constante littérale 0 (pas la constante symbolique B0), la vitesse de transmission d'entrée sera égale à la vitesse de transmission de sortie.

La fonction cfsetspeed() est une extension 4.4BSD. Elle prend les mêmes arguments que cfsetispeed() et définit les vitesses d'entrée et de sortie.

VALEUR RETOURNEE

La fonction cfgetispeed() retourne la vitesse de transmission d'entrée stockée dans la structure termios.

La fonction cfgetospeed() retourne la vitesse de transmission de sortie stockée dans la structure termios.

0
En cas de succès.
-1
En cas d'échec et définissent errno pour indiquer l'erreur.

Notez que tcsetattr() retourne le succès si *une* des modifications demandées a pu être effectuée avec succès. Par conséquent, lors de multiples modifications, il peut être nécessaire de suivre cet appel par un appel supplémentaire à tcgetattr() pour vérifier que toutes les modifications ont été effectuées avec succès.

NOTES

UNIX V7 et plusieurs systèmes ultérieurs ont une liste de vitesses de transmission où après les valeurs B0 à B9600 on trouve les deux constantes EXTA, EXTB ("External A" et "External B"). De nombreux systèmes étendent la liste avec des vitesses de transmission beaucoup plus élevées.

L'effet d'une duration non nulle avec tcsendbreak() varie. SunOS spécifie une rupture de duration * N secondes, où N est au moins 0.25 et pas plus de 0.5. Linux, AIX, DU, Tru64 envoient une rupture de duration millisecondes. FreeBSD et NetBSD et HP-UX et MacOS ignorent la valeur de duration. Sous Solaris et UnixWare, tcsendbreak() avec une duration non nulle se comporte comme tcdrain().

BOGUES

Sur l'architecture Alpha avant Linux 4.16 (et glibc avant glibc 2.28), la valeur XTABS était différente de TAB3 et elle était ignorée par le code de discipline de ligne N_TTY du pilote de terminal en conséquence (car elle ne faisait pas partie du masque TABDLY).
