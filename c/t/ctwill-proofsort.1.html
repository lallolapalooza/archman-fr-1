Il prend soin des détails typographiques tels que la mise en page et l'utilisation de l'indentation, de l'italique, du gras, etc., et fournit des informations d'indexation croisée approfondies qu'il recueille automatiquement. CWEB vous permet de préparer un seul document contenant toutes les

informations

nécessaires à la fois pour produire un programme C/C++ compilable et pour produire un document bien formaté décrivan

ainsi qu'avec C/C++. UTILISATION La ligne de commande doit contenir un, deux ou trois noms. Le premier est considéré

comm

e

le fichier d'entrée CWEB (et .w est ajouté s'il n'y a pas d'extension). S'il y a un deuxième nom, c'est un fichier de modifications (et .ch est ajouté s'il n'y a pas d'extension). Le fichier de modifications remplace des parties du fichier CWEB, comme décrit dans la documentation. S'il y a un troisième nom, il remplace le nom par défaut du fichier de sortie, qui est habituellement le même que le nom du fichier d'entrée (mais dans le répertoire courant) avec l'extension .tex. Si vous voulez simplement changer le nom du fichier de sortie, mais que vous n'avez pas de fichier de modifications à appliquer, vous pouvez utiliser ` -' comme deuxième argument. ctwill est exactement comme cweavesauf qu'il produit

une

documentation beaucoup meilleure, pour laquelle vous devez travailler beaucoup plus dur. Vous devriez exécuter ctwill deux fois, une fois pour amorcer la pompe et une fois pour obtenir des résultats décents. De plus, vous devez exécuter la sortie deux fois à travers TeX. Après tex foo, vous

aurez

une sortie qui ressemble à des pages finales sauf que les entrées des mini-index ne seront pas classées par ordre alphabétique. La première exécution produit un fichier étrange appelé foo. ref. Dites ctwill-refsort < foo.ref > foo.sref et ensuite une autre tex foo produira une sortie classée par ordre alphabétique.

Le

p rogramme ctwill-twinx compile un index maître pour un ensemble de programmes liés qui ont été traités par ctwill ( pas par cweave,notez bien !). Les programmes individuels doivent définir leurs noms avec une ligne de la forme \def\title{NOM}. Pour votre commodité, ctwill-twinx prend le premier « mot » dans \title et le met en majuscules. Vous devriez adapter le fichier twinx-startup.tex pour la première page de l'index maître. Les mini-index listent les identifiants qui

sont

utilisés mais non définis sur chaque double page. À la fin de chaque section, ctwill donne à TeX une liste des identifiants utilisés dans cette section et des informations sur l'endroit où ils sont définis. La signification actuelle de chaque

identifiant

est initialement \uninitialized. Ensuite ctwill lit le fichier .aux pour votre travail, s'il y en a un. Avant de lire le fichier .

aux,

ctwill cherche en fait un fichier appelé system.bux, qui sera lu s'il est présent. Et après foo.aux, une troisième possibilité est foo.bux. La convention générale est de mettre les définitions des procédures système telles que printf dans system.bux, et de mettre les définitions trouvées dans les fichiers d'en-tête spécifiquement foo-ish dans foo.bux. Comme les fichiers .aux, les fichiers .bux ne devraient contenir que des spécifications @$. La signification spécifiée

par

@$...@> a généralement quatre composantes : un identifiant (suivi d'un espace), un nom de programme (entre accolades), un numéro de section (suivi d'un espace), et une partie TeX. Un mode spécial proofmode

est

fourni afin que vous puissiez vérifier les conclusions de ctwill sur les références croisées. Exécutez ctwill avec l'indicateur +P, et TeX produira un document spécialement formaté avec des mini-index pour chaque section, afin que vous puissiez vérifier que vos spécifications sont correctes. Ce format

proofmode

est utilisé en conjonction avec pdfctproofmac.tex qui crée des hyperliens actifs dans les sorties PDF et HINT. Vous pouvez utiliser ctwill-proofsort pour obtenir les entrées d'index dans l'ordre alphabétique ; invoquez simplement ( ctwill-proofsor

ENVIRONNEMEN

T

La variable d'environnement CWEBINPUTS est utilisée pour rechercher les fichiers d'entrée, ou la valeur par défaut du système si CWEBINPUTS n'est pas définie. Voir tex(1) pour les détails de la recherche. Pour éviter les conflits avec d'autres programmes qui utilisent également l'environnement CWEBINPUTS, vous pouvez être plus précis et utiliser CWEBINPUTS_cweb pour des besoins particuliers dans

CWEB.

Si préparé pour la prise en charge de NLS, ctwill, comme ctangle et cweave, utilise la variable d'environnement TEXMFLOCALEDIR pour configurer le répertoire parent où les « GNU gettext utilities » recherchent les catalogues de

traduction.

Ces variables sont préconfigurées dans le texmf.cnf d

 Live.
