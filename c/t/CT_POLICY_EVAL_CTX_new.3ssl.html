CT_POLICY_EVAL_CTX_new(3ssl)

CT_POLICY_EVAL_CTX_NEW(3ssl) OpenSSL CT_POLICY_EVAL_CTX_NEW(3ssl)

NOM

CT_POLICY_EVAL_CTX_new_ex, CT_POLICY_EVAL_CTX_new, CT_POLICY_EVAL_CTX_free, CT_POLICY_EVAL_CTX_get0_cert, CT_POLICY_EVAL_CTX_set1_cert, CT_POLICY_EVAL_CTX_get0_issuer, CT_POLICY_EVAL_CTX_set1_issuer, CT_POLICY_EVAL_CTX_get0_log_store, CT_POLICY_EVAL_CTX_set_shared_CTLOG_STORE, CT_POLICY_EVAL_CTX_get_time, CT_POLICY_EVAL_CTX_set_time - Encapsule les données nécessaires pour évaluer si les SCT répondent à une politique de Transparence des Certificats

SYNOPSIS

#include <openssl/ct.h>
CT_POLICY_EVAL_CTX *CT_POLICY_EVAL_CTX_new_ex(OSSL_LIB_CTX *libctx,
                                              const char *propq);
CT_POLICY_EVAL_CTX *CT_POLICY_EVAL_CTX_new(void);
void CT_POLICY_EVAL_CTX_free(CT_POLICY_EVAL_CTX *ctx);
X509* CT_POLICY_EVAL_CTX_get0_cert(const CT_POLICY_EVAL_CTX *ctx);
int CT_POLICY_EVAL_CTX_set1_cert(CT_POLICY_EVAL_CTX *ctx, X509 *cert);
X509* CT_POLICY_EVAL_CTX_get0_issuer(const CT_POLICY_EVAL_CTX *ctx);
int CT_POLICY_EVAL_CTX_set1_issuer(CT_POLICY_EVAL_CTX *ctx, X509 *issuer);
const CTLOG_STORE *CT_POLICY_EVAL_CTX_get0_log_store(const CT_POLICY_EVAL_CTX *ctx);
void CT_POLICY_EVAL_CTX_set_shared_CTLOG_STORE(CT_POLICY_EVAL_CTX *ctx,
                                               CTLOG_STORE *log_store);
uint64_t CT_POLICY_EVAL_CTX_get_time(const CT_POLICY_EVAL_CTX *ctx);
void CT_POLICY_EVAL_CTX_set_time(CT_POLICY_EVAL_CTX *ctx, uint64_t time_in_ms);

DESCRIPTION

Un CT_POLICY_EVAL_CTX est utilisé par les fonctions qui évaluent si les Timestamps de Certificat Signés (SCTs) remplissent une politique de Transparence des Certificats (CT). Cette politique peut être, par exemple, qu'au moins un SCT valide soit disponible. Pour déterminer cela, l'horodatage et la signature d'un SCT doivent être vérifiés. Cela nécessite :

  • la clé publique du log qui a émis le SCT
  • le certificat pour lequel le SCT a été émis
  • le certificat de l'émetteur (si le SCT a été émis pour un pré-certificat)
  • l'heure actuelle

Les exigences ci-dessus sont satisfaites en utilisant les mutateurs décrits ci-dessous.

CT_POLICY_EVAL_CTX_new_ex() crée un contexte d'évaluation de politique vide et l'associe au contexte de librairie donné libctx et à la chaîne de requête de propriété propq.

CT_POLICY_EVAL_CTX_new() fait la même chose que CT_POLICY_EVAL_CTX_new_ex() sauf qu'il utilise le contexte de librairie par défaut et la chaîne de requête de propriété.

Le CT_POLICY_EVAL_CTX doit ensuite être rempli en utilisant :

  • CT_POLICY_EVAL_CTX_set1_cert() pour fournir le certificat pour lequel les SCTs ont été émis

    Incrémente le compteur de références du certificat.

  • CT_POLICY_EVAL_CTX_set1_issuer() pour fournir le certificat de l'émetteur

    Incrémente le compteur de références du certificat.

  • CT_POLICY_EVAL_CTX_set_shared_CTLOG_STORE() pour fournir une liste des logs qui sont considérés comme fiables comme sources de SCTs

    Conserve un pointeur vers le CTLOG_STORE, donc le CTLOG_STORE doit survivre au CT_POLICY_EVAL_CTX.

  • CT_POLICY_EVAL_CTX_set_time() pour définir l'heure à laquelle les SCTs doivent être comparés pour déterminer s'ils sont valides

    L'horodatage du SCT sera comparé à cette heure pour vérifier si le SCT a été émis dans le futur. RFC6962 stipule que "les clients TLS DOIVENT rejeter les SCTs dont l'horodatage est dans le futur". Par défaut, cela sera réglé à 5 minutes dans le futur (par exemple, (time() + 300) * 1000), pour permettre une dérive de l'horloge.

    L'heure doit être en millisecondes depuis l'Époque Unix.

Chaque mutateur a un accesseur correspondant pour accéder à la valeur actuelle.

Lorsqu'il n'est plus nécessaire, le CT_POLICY_EVAL_CTX doit être passé à CT_POLICY_EVAL_CTX_free() pour le supprimer. Si l'argument de CT_POLICY_EVAL_CTX_free() est NULL, rien n'est fait.

NOTES

Le certificat de l'émetteur doit seulement être fourni si au moins un des SCTs a été émis pour un pré-certificat. Ce sera le cas pour les SCTs intégrés dans un certificat (c'est-à-dire ceux d'une extension X.509), mais pas nécessairement pour les SCTs trouvés dans l'extension TLS SCT ou la réponse OCSP.

VALEURS DE RETOUR

CT_POLICY_EVAL_CTX_new_ex() et CT_POLICY_EVAL_CTX_new() renverront NULL si malloc échoue.
