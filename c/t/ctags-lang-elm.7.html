Nom

ctags-lang-elm - Notes diverses sur l'indexation du code source Elm avec Universal Ctags

SYNTAXE

ctags ... --languages=+Elm ...
ctags ... --language-force=Elm ...
ctags ... --map-Elm=+.elm ...

DESCRIPTION

L'analyseur Elm est un analyseur PEG utilisant PackCC, qui fait partie de l'infrastructure ctags. Il devrait traiter correctement toutes les instructions de haut niveau, cependant il existe une limitation concernant les fonctions intégrées dans les blocs let/in. Elles seront la plupart du temps correctes, mais parfois une fonction dans un bloc let/in sera omise.

EXEMPLES

Importations

Les modules importés sont indexés, et leur rôle est "imported" (importé), pas "def". Les types, fonctions, etc. qui sont exposés via un module importé ont leur rôle comme "exposed" (exposé).

Les éléments exposés sont marqués comme étant dans la portée de leur propre module, pas dans celle du module qui effectue l'importation.

« input.elm »

module SomeMod exposing (..)
import MyMod exposing
  ( map
  , Maybe
  , Result(..)
  , MyList(Empty)
  )

« output.tags » avec « --options=NONE -o - --sort=no --extras=+r --fields=+r input.elm »

SomeMod input.elm       /^module SomeMod exposing (..)$/;"      m       roles:def
MyMod   input.elm       /^import MyMod exposing$/;"     m       roles:imported
map     input.elm       /^  ( map$/;"   f       module:MyMod    roles:exposed
Maybe   input.elm       /^  , Maybe$/;" t       module:MyMod    roles:exposed
Result  input.elm       /^  , Result(..)$/;"    t       module:MyMod    roles:exposed
MyList  input.elm       /^  , MyList(Empty)$/;" t       module:MyMod    roles:exposed
Empty   input.elm       /^  , MyList(Empty)$/;" c       type:MyMod.MyList       roles:exposed

Espaces de noms

Les espaces de noms sont indexés et leur rôle est "def".

« input.elm »

module AMod exposing (..)
import MyImport as NSpace exposing (impFunc)

« output.tags » avec « --options=NONE -o - --sort=no --extras=+r --fields=+r input.elm »

AMod    input.elm       /^module AMod exposing (..)$/;" m       roles:def
NSpace  input.elm       /^import MyImport as NSpace exposing (impFunc)$/;"      n       module:AMod     roles:def       moduleName:MyImport
MyImport        input.elm       /^import MyImport as NSpace exposing (impFunc)$/;"      m       roles:imported
impFunc input.elm       /^import MyImport as NSpace exposing (impFunc)$/;"      f       module:MyImport roles:exposed

Noms de types

Les constructeurs et les fonctions de haut niveau auront des noms de types.

« input.elm »

funcA : Int -> Int
funcA a = a + 1
type B
    = B1Cons
      { x : Float
      , y : Float
      }
    | B2Cons String Integer
    | B3Cons

« output.tags » avec « --options=NONE -o - --sort=no --extras=+r --fields=+r input.elm »

funcA   input.elm       /^funcA a = a + 1$/;"   f       typeref:typename:Int -> Int     roles:def
B       input.elm       /^type B$/;"    t       roles:def
B1Cons  input.elm       /^    = B1Cons$/;"      c       type:B  typeref:typename:{ x : Float , y : Float } -> B roles:def
B2Cons  input.elm       /^    | B2Cons String Integer$/;"       c       type:B  typeref:typename:String -> Integer -> B roles:def
B3Cons  input.elm       /^    | B3Cons$/;"      c       type:B  typeref:typename:B      roles:def

Listes de paramètres de fonctions

Les listes de paramètres de fonctions peuvent être extraites dans le champ signature du fichier tags. Ce ne sont pas vraiment des signatures de fonctions, mais c'est le concept le plus proche disponible dans ctags. Utilisez « --fields=+S ».

funcA a1 a2 =
    a1 + a2

« output.tags » avec « --sort=no --extras=+r --fields=+rS »

funcA       input.elm       /^funcA a1 a2 =$/;"     f       signature:a1 a2 roles:def

LIMITATIONS CONNUES

Le champ signature de ctags est utilisé pour les listes de paramètres de fonctions, même si ce n'est pas un champ idéal. Voir ci-dessus.

Elm exige que toutes les instructions au même niveau logique aient la même indentation. S'il y a une indentation supplémentaire, cette ligne fait partie de la précédente. Par conséquent, sans compliquer excessivement l'analyseur PEG, nous avons les limitations suivantes...

Parfois, les fonctions dans les blocs let/in seront omises.

Les fonctions dans les blocs let/in seront marquées comme étant dans la portée de leur fonction externe, quelle que soit la profondeur de imbrication du bloc let/in.

Les fonctions dans les blocs let/in n'auront pas de noms de types.
