NOM

ctel - Outil d'administration de cluster

VERSION

Cette documentation concerne la version : 4.16

SYNOPSIS

ctel [-K <seconds>] [-q] [-c '<filename>'] [-x <cols>] [-C '<filename>'] [--debug [[...] || <INTEGER>]] [-d] [-e '<[user@]<host>[:port]>'] [--fillscreen] [-f '<font>'] [-h] [-L '[tag]'] [-H] [-p <port>] [-Q] [-y <rows>] [-s] [-r '<filename>'] [-t '<STRING>'] [-g] [-T '<title>'] [-u] [-?] [-A] [-v]

VOIR AUSSI

Voir également les pages man individuelles pour chacune de ces utilitaires

ccon - Utiliser 'console' comme méthode de communication
crsh - Utiliser 'rsh' comme méthode de communication
csftp - Utiliser 'sftp' comme méthode de communication
cssh - Utiliser 'ssh' comme méthode de communication

DESCRIPTION

La commande ouvre une console d'administration et un xterm vers tous les hôtes spécifiés. Tout texte tapé dans la console d'administration est répliqué dans toutes les fenêtres. Il est également possible de taper directement dans toutes les fenêtres.

Cet outil est destiné (mais pas limité) à l'administration de cluster où la même configuration ou les mêmes commandes doivent être exécutées sur chaque nœud du cluster. Exécuter ces commandes toutes en même temps via cet outil garantit que tous les nœuds restent synchronisés.

Les connexions sont ouvertes en utilisant telnet qui doit être correctement installé et configuré.

Une prudence particulière doit être prise lors de l'édition de fichiers car les lignes ne sont pas nécessairement dans le même ordre ; supposer que la ligne 5 est la même sur tous les serveurs et la modifier est dangereux. Il vaut mieux rechercher la ligne spécifique à modifier et vérifier que tous les terminaux sont comme attendu avant que les changements ne soient appliqués.

Notes supplémentaires

Veuillez également consulter "KNOWN BUGS".

  • La ligne pointillée sur un sous-menu est un détachable, c'est-à-dire cliquez dessus et le sous-menu devient sa propre fenêtre.
  • Décocher un nom d'hôte dans le sous-menu Hosts débranchera l'hôte de la fenêtre de contrôle du cluster, de sorte que tout texte tapé dans la console ne sera pas envoyé à cet hôte. Le re-sélectionner le rebranchera.
  • Si les barres de menu de votre gestionnaire de fenêtres sont masquées par les fenêtres de terminal, consultez les "screen_reserve_XXXXX" options dans le $HOME/.clusterssh/config fichier (voir "FILES").
  • Si les terminaux se chevauchent trop, consultez les "terminal_reserve_XXXXX" options dans le $HOME/.clusterssh/config fichier (voir "FILES").
  • Lors de l'utilisation de ClusterSSH sur un grand nombre de systèmes pour se connecter à un système unique en utilisant un utilitaire SSH (par exemple, vous émettez une commande pour copier un fichier en utilisant scp depuis les ordinateurs distants vers un hôte unique) et lorsque ces connexions nécessitent une authentification (c'est-à-dire que vous allez vous authentifier avec un mot de passe), le démon sshd à cet endroit peut refuser les connexions après que la limite "MaxStartups" dans sshd_config soit dépassée. (Si cette valeur n'est pas définie, elle vaut par défaut 10). C'est un comportement attendu ; sshd utilise ce mécanisme pour empêcher les attaques DoS de sources non authentifiées. Veuillez régler sshd_config et recharger le démon SSH, ou envisager d'utiliser le mécanisme ~/.ssh/authorized_keys pour l'authentification si vous rencontrez ce problème.
  • Si les fenêtres clientes ne s'ouvrent pas, essayez d'exécuter :

    "ctel -e {single host name}"

    Cela testera les mécanismes utilisés pour ouvrir des fenêtres vers les hôtes. Cela pourrait être dû soit à l'option de terminal "-xrm" qui active "AllowSendEvents" (certains terminaux ne nécessitent pas cette option, d'autres terminaux ont une autre méthode pour l'activer - consultez la documentation de votre terminal) soit à la configuration de "telnet".

OPTIONS

Certaines de ces options peuvent également être définies dans le fichier de configuration. Les options par défaut sont affichées en tant que telles.

--autoclose <seconds>, -K <seconds>
Nombre de secondes à attendre avant de fermer les fenêtres de terminal terminées.
--autoquit, -q
Bascule la sortie automatique après la fermeture de la dernière fenêtre cliente (en écrasant le fichier de configuration).
--cluster-file '<filename>', -c '<filename>'
Utilise le fichier fourni comme fichier de cluster supplémentaire (voir aussi "FILES").
--cols <cols>, -x <cols>
Nombre de colonnes
--config-file '<filename>', -C '<filename>'
Utilise le fichier fourni comme fichier de configuration supplémentaire (voir aussi "FILES").
--debug [[...] || <INTEGER>]
Active le débogage. Soit un niveau peut être fourni, soit l'option peut être répétée plusieurs fois. Le niveau maximum est 9.
--dump-config, -d
Affiche la configuration actuelle dans le même format utilisé par le $HOME/.clusterssh/config fichier.
--evaluate '<[user@]<host>[:port]>', -e '<[user@]<host>[:port]>'
Affiche et évalue les arguments de terminal et de connexion pour afficher les éventuelles erreurs. Le <hostname> est requis pour aider à l'évaluation.
--fillscreen
Redimensionne les fenêtres de terminal pour remplir tout l'écran disponible
--font '<font>', -f '<font>'
Spécifie la police à utiliser dans les fenêtres de terminal. Utilisez la notation standard des polices X telle que "5x8".
--help, -h
Affiche le texte d'aide de base et quitte
--list '[tag]', -L '[tag]'
Liste les tags de cluster disponibles. Le tag est optionnel. Si un tag est fourni, les hôtes pour ce tag sont listés. NOTE : le format de la sortie change lorsque l'option "--quiet" ou "-Q" est utilisée.
--man, -H
Affiche le texte d'aide complet (la page man) et quitte
--port <port>, -p <port>
Spécifie un port alternatif pour les connexions.
--quiet, -Q
Ne produit pas de texte supplémentaire lors de l'utilisation de certaines options
--rows <rows>, -y <rows>
Nombre de lignes
--show-history, -s
Affiche l'historique dans la fenêtre de console.
--tag-file '<filename>', -r '<filename>'
Utilise le fichier fourni comme fichier de tag supplémentaire (voir aussi "FILES")
--term-args '<STRING>', -t '<STRING>'
Spécifie les arguments à passer aux terminaux utilisés.
--tile, -g
Bascule le pavage des fenêtres (en écrasant le fichier de configuration).
--title '<title>', -T '<title>'
Spécifie la partie initiale du titre utilisé dans la console et les fenêtres clientes.
--unique-servers, -u
Bascule la connexion à chaque hôte une seule fois lorsqu'un nom d'hôte a été spécifié plusieurs fois.
--usage, -?
Affiche le synopsis et quitte
--use-all-a-records, -A
Si un nom d'hôte se résout en plusieurs adresses IP, bascule si oui ou non se connecter à toutes, ou seulement à la première (voir aussi l'entrée du fichier de configuration).
--version, -v
Afficher les informations de version et quitter

ARGUMENTS

Les arguments suivants sont pris en charge :

[user@]<hostname>[:port] ...
Ouvrir un xterm vers l'hôte donné et se connecter à la console d'administration. Le numéro de port optionnel peut être utilisé si le serveur n'écoute pas sur le port standard.
<tag> ...
Ouvrir une série de xterms définis par <tag> dans l'un des fichiers de configuration supplémentaires (voir « FILES »).

Note : spécifier un nom d'utilisateur sur un tag de cluster remplacera tous les noms d'utilisateur définis dans le cluster.

RACCOURCIS CLAVIER

Les raccourcis clavier suivants sont disponibles dans la fenêtre de la console, et tous peuvent être modifiés via les fichiers de configuration.

Control-Shift-plus
Ouvrir la boîte de dialogue « Add Host(s) or Cluster(s) ». Plusieurs noms d'hôtes ou de clusters peuvent être saisis, séparés par des espaces.
Alt-n
Coller la partie nom d'hôte de la chaîne de connexion spécifique à chaque client, sans le nom d'utilisateur ni le port, par ex.

"scp /etc/hosts server:files/<Alt-n>.hosts"

remplacerait <Alt-n> par le nom du client dans chaque fenêtre.

Alt-l
Coller le nom d'hôte du serveur sur lequel cssh est exécuté
Alt-q
Quitter le programme et fermer toutes les connexions et fenêtres.
Alt-r
Réorganiser toutes les fenêtres clients.
Alt-u
Coller le nom d'utilisateur pour la connexion
Alt-1
Alt-2
Alt-3
Alt-4
Exécuter la macro utilisateur correspondante sur le serveur et envoyer la sortie au client

EXEMPLES

Ouvrir une session vers 3 serveurs
$ ctel server1 server2 server3
Ouvrir une session vers un cluster de serveurs identifié par le tag 'farm1' et donner à la fenêtre de contrôle un titre spécifique, où le tag est défini dans l'un des fichiers de configuration par défaut
$ ctel -T 'Web Farm Cluster 1' farm1
Se connecter à différents serveurs en utilisant différents noms de connexion. NOTE : cela peut aussi être réalisé en configurant des options appropriées dans les fichiers de configuration. Ne pas fermer la console lorsque le dernier terminal se termine.
$ ctel user1@server1 admin@server2
Ouvrir un cluster défini dans un fichier de configuration non par défaut
$ ctel -c$HOME/cssh.extra_clusters db_cluster
Remplacer le port configuré/par défaut pour utiliser 2022 à la place
$ ctel -p 2022 server1 server2

FICHIERS

/etc/clusters, $HOME/.clusterssh/clusters
Ces fichiers contiennent une liste de correspondances entre des tags et des noms de serveurs. Lorsqu'un nom est utilisé sur la ligne de commande, il est vérifié pour voir s'il s'agit d'un tag. S'il s'agit d'un tag, alors le tag est remplacé par la liste de serveurs. Le format est le suivant :

<tag> [user@]<server>[:port] [user@]<server>[:port] [...]

par ex.

# Liste des serveurs en production
live admin1@server1 admin2@server2:2022 server3 server4

Tous les commentaires (marqués par un #) et les lignes vides sont ignorés. Les tags peuvent être imbriqués, mais faites attention à l'utilisation de tags récursifs car ils ne sont pas vérifiés.

Les serveurs peuvent être définis en utilisant des macros d'expansion :

"webservers websvr{a,b,c}"

serait étendu en

"webservers websvra websvrb websvrc"

et

"webservers websvr{6..9}"

serait étendu en

"webservers websvr6 websvr7 websvr8 websvr9"

Des fichiers de clusters supplémentaires peuvent également être spécifiés soit comme option sur la ligne de commande (voir "cluster-file") ou dans le fichier $HOME/.clusterssh/config de l'utilisateur (voir l'option de configuration "extra_cluster_file").

NOTE : le dernier tag lu remplace tout tag préexistant portant ce nom.

NOTE : il existe un tag de cluster spécial appelé "default" - tout tag ou hôte inclus dans ce tag sera automatiquement ouvert si rien n'est spécifié sur la ligne de commande.

/etc/tags, $HOME/.clusterssh/tags
Très similaire aux fichiers clusters mais la définition est inversée. Le format est :

<host> <tag> [...]

Cela permet à un hôte d'être spécifié comme membre d'un certain nombre de tags. Ce format peut être plus clair que l'utilisation des fichiers clusters .

Des fichiers de tags supplémentaires peuvent être spécifiés soit comme option (voir "tag-file") ou dans le fichier $HOME/.clusterssh/config de l'utilisateur (voir "extra_tag_file" l'option de configuration).

NOTE : Tous les tags sont ajoutés ensemble

/etc/csshrc & $HOME/.clusterssh/config
Ce fichier contient des remplacements de configuration - les valeurs par défaut sont indiquées comme telles. Les options par défaut sont d'abord remplacées par le fichier global, puis par le fichier utilisateur.

NOTE : les valeurs des entrées n'ont pas besoin d'être entre guillemets sauf si c'est nécessaire pour passer des arguments, par ex.

"terminal_allow_send_events="-xrm '*.VT100.allowSendEvents:true'""

devrait être écrit comme

"terminal_allow_send_events=-xrm '*.VT100.allowSendEvents:true'"

auto_close = 5
Fermer la fenêtre du terminal après ce nombre de secondes. Si défini à 0, attendra plutôt une saisie de l'utilisateur dans chaque fenêtre avant de fermer. Voir aussi --autoclose et --no-autoclose
auto_quit = 1
Quitter automatiquement après la fermeture de la dernière fenêtre client. Définir à 0 pour désactiver. Voir aussi --autoquit
auto_wm_decoration_offsets = no
Activer ou désactiver l'algorithme alternatif pour le calcul du positionnement des terminaux.
command_pre =
command_post =
Ajouter des commandes supplémentaires autour de la méthode de communication. Par exemple :

command_pre= . $HOME/virtualenvs/default/bin/active ; command_post= | ct

permettrait d'utiliser des environnements virtuels Python puis de faire passer toute la sortie du shell à travers "chromaterm" pour la coloration syntaxique. Note : vous devez utiliser des séparateurs/terminateurs de commande appropriés pour conserver le sens du pipeline de commandes (comme ";" et "|" entre les commandes).

Celles-ci ne sont pas soumises à l'analyse des macros.

comms = telnet
Définit la méthode de communication par défaut (initialement prise du nom du programme, mais peut être remplacée ici).
console_position = <null>
Définit la position initiale de la console - si vide, laisse le gestionnaire de fenêtres décider. Le format est '+<x>+<y>', c'est-à-dire '+0+0' est le coin supérieur gauche de l'écran, '+0-70' est le côté inférieur gauche de l'écran (plus ou moins).
external_command_mode = 0600
Bits de mode de fichier pour external_command_pipe.
external_command_pipe = <null>
Définit le chemin complet vers un pipe de commande externe vers lequel on peut écrire pour contrôler certains aspects de ClusterSSH, comme l'ouverture de sessions vers plus de clusters.

Commandes :

"open <tag|hostname>" - ouvrir de nouvelles sessions vers le tag ou l'hôte fourni

"retile" - forcer la réorganisation des fenêtres

par ex. : "echo 'open localhost'" /path/to/external_command_pipe >>

external_cluster_command = <null>
Définit le chemin complet vers une commande externe qui peut être utilisée pour résoudre les tags en noms d'hôtes. Cette commande peut être écrite dans n'importe quel langage. Le script doit accepter une liste de tags à résoudre et produire une liste d'hôtes (séparés par des espaces sur une seule ligne). Tout tag qui ne peut pas être résolu doit être renvoyé inchangé.

Un code de sortie non nul sera considéré comme une erreur, un avertissement sera imprimé et la sortie ignorée.

Si l'option "-L" est donnée à la commande externe, elle doit produire une liste de tags (séparés par des espaces sur une seule ligne) qu'elle peut résoudre

extra_cluster_file = <null>gt;
Définir un fichier de cluster supplémentaire au format de /etc/clusters. Plusieurs fichiers peuvent être spécifiés, séparés par des virgules. ~ et $HOME sont tous deux acceptés comme référence au répertoire personnel de l'utilisateur, par exemple

"extra_cluster_file = ~/clusters, $HOME/clus"

extra_tag_file = <null>
Définir un fichier de tags supplémentaire au format de /etc/tags. Plusieurs fichiers peuvent être spécifiés, séparés par des virgules. ~ et $HOME sont tous deux acceptés comme référence au répertoire personnel de l'utilisateur, par exemple

"extra_tag_file = ~/tags, $HOME/tags"

$HOME/.clusterssh/send_menu
Ce fichier (optionnel) contient des éléments pour remplir le menu d'envoi. L'entrée par défaut pourrait être écrite comme suit : 
<send_menu>
  <menu title="Use Macros">
      <toggle/>
      <accelerator>ALT-p</accelerator>
  </menu>
  <menu title="Remote Hostname">
      <command>%s</command>
      <accelerator>ALT-n</accelerator>
  </menu>
  <menu title="Local Hostname">
      <command>%s</command>
      <accelerator>ALT-l</accelerator>
  </menu>
  <menu title="Username">
      <command>%u</command>
      <accelerator>ALT-u</accelerator>
  </menu>
  <menu title="Test Text">

  </menu>
</send_menu>

Des sous-menus peuvent aussi être spécifiés comme suit :

<send_menu>

    <menu title="Hostname">
        <command>%s</command>
        <accelerator>ALT-n</accelerator>
    </menu>
  </menu>
</send_menu>

Avertissements :

Il n'y a actuellement aucune vérification stricte du format de ce fichier.
Le format du fichier peut changer à l'avenir
Si le fichier existe, l'entrée par défaut (Hostname) n'est pas ajoutée

Les macros de remplacement suivantes sont disponibles (note : celles-ci peuvent être modifiées dans le fichier de configuration) :

%s
Partie nom d'hôte de la chaîne de connexion spécifique à chaque client, sans nom d'utilisateur ni port
%u
Partie nom d'utilisateur de la chaîne de connexion à chaque client
%h
Nom d'hôte du serveur d'où cssh est exécuté
%n
code "RETURN"

NOTE : nécessite l'installation de XML::Simple

BUGS CONNUS

Si vous avez des idées sur la façon de corriger les bugs ci-dessous, veuillez contacter et/ou fournir un patch.

•
Le changement de bureaux virtuels peut provoquer un redessin de toutes les fenêtres de terminal. Cela est dû à un manque de distinction dans Tk entre le changement de bureau et la minimisation/agrandissement des fenêtres. Tant que Tk ne pourra pas faire la différence entre ces deux événements, il n'y a pas de solution (sauf à réécrire tout directement en X).

DÉPANNAGE

Si vous rencontrez des problèmes avec ctel, essayez d'abord :

"ctel -e [user@]<hostname>[:port]"

Cela effectue deux tests pour confirmer que cssh est capable de fonctionner correctement avec les paramètres fournis dans le $HOME/.clusterssh/config fichier (ou les valeurs par défaut internes).

1.
Tester que la fenêtre de terminal fonctionne avec les options fournies
2.
Tester que telnet fonctionne vers un hôte avec les arguments configurés

Les options de configuration à surveiller pour ssh sont :

  • SSH ne comprend pas "-o ConnectTimeout=10" - retirez l'option du $HOME/.clusterssh/config fichier
  • OpenSSH-3.8 utilisant des tunnels ssh non fiables - utilisez "-Y" au lieu de "-X" ou utilisez "ForwardX11Trusted yes" dans $HOME/.ssh/ssh_config (si vous changez les options ssh par défaut de "-x" à "-X")

    VERSION

    La première version de CTEL a été écrite par B. G. Potter, J. R. Mashey et D. R. Hedges à la Bell Telephone Laboratories, Inc.

    SYNOPSIS

    ctel [-v] [-f filename] [-a algorithm] [-r rate] [-l length] [-d delay] [-t threshold] [-c count]

    RELATED

    telnet(1), rlogin(1), ssh(1)

    DESCRIPTION

    ctel est un programme de simulation de terminal qui permet de simuler le comportement d'un terminal interactif sur un réseau. Il est utile pour tester des applications réseau qui dépendent des caractéristiques spécifiques d'un terminal, telles que la latence, le débit et la taille du tampon.

    OPTIONS

    -v
    Active le mode verbeux.
    -f filename
    Spécifie un fichier à utiliser comme entrée pour le terminal simulé.
    -a algorithm
    Définit l'algorithme de simulation à utiliser (par exemple, fixed, random).
    -r rate
    Définit le débit de transmission simulé en caractères par seconde.
    -l length
    Définit la longueur maximale des paquets simulés.
    -d delay
    Définit le délai de transmission simulé en millisecondes.
    -t threshold
    Définit le seuil de remplissage du tampon pour déclencher la transmission.
    -c count
    Définit le nombre de caractères à transmettre avant de s'arrêter.

    ARGUMENTS

    Aucun argument n'est requis. Les options spécifient le comportement du terminal simulé.

    KEY SHORTCUTS

    ctel n'utilise pas de raccourcis clavier spécifiques pour son fonctionnement principal. L'interaction se fait via les entrées standard et les options de ligne de commande.

    EXAMPLES

    ctel -r 1200 -d 50: Simule un terminal avec un débit de 1200 caractères par seconde et un délai de 50 millisecondes.

    ctel -f input.txt -c 1000: Utilise le fichier input.txt comme entrée et transmet 1000 caractères.

    FILES

    Aucun fichier spécifique n'est requis par ctel, sauf si un fichier d'entrée est spécifié avec l'option -f.

    KNOWN BUGS

    Cette section est vide.

    TROUBLESHOOTING

    Si vous rencontrez des problèmes, assurez-vous que les options spécifiées sont valides et que le fichier d'entrée (s'il y en a un) existe et est lisible.
