DESCRIPTIO

N

ctanify est destiné aux développeurs qui ont un paquet LaTeX qu'ils souhaitent distribuer via le Comprehensive TeX Archive Network (CTAN). Étant donné une liste de noms de fichiers, ctanify crée une archive tar (un fichier .tar.gz) avec les fichiers disposés selon la structure préférée de CTAN. L'archive contient en outre un fichier ZIP (.zip) avec des copies de tous les fichiers disposés selon la structure de répertoires T

eX standard (TDS), ce qui facilite l'incl
usion du paquet dans la distribution TeX Live.

DIAGNOSTIC

S
"Failed to copy nom-de-fichier (No such file or directory)
"
Ce message est généralement causé par un fichier .ins qui génère nom-de-fichier mais qui n'a pas encore été exécuté avec tex ou latex pour produire réellement nom-de-fichier. ctanify n'exécute pas automatiquement tex ou latex ; cela doit être fait manuellement par l'utilisateur. Voir "AVERTISSEMENTS" pour plus
d'informations.
"Modified nom-de-fichier to use Unix line endings (use --no-unixify to prevent this)
"
Par cohérence, CTAN stocke tous les fichiers texte avec des fins de ligne de style Unix (un seul caractère de saut de ligne sans caractère de retour à la ligne). Pour aider dans cet effort, ctanify remplace automatiquement les fins de ligne non de style Unix. Le message précédent notifie simplement l'utilisateur qu'il ne doit pas s'inquiéter de voir une taille différente pour nom-de-fichier dans l'archive par rapport au fichier nom-de-fichier original sur le disque (que ctanify ne modifie jamais). S'il y a une bonne raison de préserver les fins de ligne d'origine (et c'est rarement le cas), l'option --no-unixify peut être utilisée pour empêcher ctanify d'altérer des fichiers lors de leur stockage dans
l'archive.
"Excluding nom-de-fichier (use --no-skip to force inclusion)
"
ctanify ignore normalement les fichiers--même lorsqu'ils sont explicitement spécifiés sur la ligne de commande--que CTAN préfère ne pas recevoir. Ceux-ci incluent les fichiers dont les noms commencent par "." (fichiers cachés Unix), se terminent par "~" (sauvegardes automatiques Emacs), ou qui proviennent d'un répertoire CVS ou .svn (fichiers de métadonnées de contrôle de version). S'il y a une bonne raison de soumettre de tels fichiers à CTAN (et c'est rarement le cas), l'option --no-skip peut être utilisée pour empêcher ctanify de les
ignorer.
"CTAN prefers having only PDF documentation (re: nom-de-fichier)
"
En raison de la popularité du format PDF, CTAN souhaite avoir autant de documentation que possible distribuée en PDF. Le message précédent demande à l'utilisateur de remplacer toute documentation PostScript ou DVI par du PDF si possible. (ctanify inclura quand même la documentation PostScript et DVI dans l'archive ; le message précédent est simplement une demande polie.
)
"Not including nom-de-fichier in the TDS tree (unknown extension)
"
ctanify place les fichiers dans l'arborescence TDS en fonction d'une table d'extensions de fichiers. Par exemple, tous les fichiers .sty sont placés dans tex/latex/nom-du-paquet. Si ctanify ne sait pas où mettre un fichier, il ne le met nulle part. Voir le dernier paragraphe de "OPTIONS" pour une explication sur la façon de spécifier explicitement l'emplacement cible d'un fichier dans l'arborescence TDS. Pour les extensions de fichiers courantes qui se trouvent absentes de la table de ctanify, envisagez également de notifier l'auteur de ctanify à l'adres
se indiquée ci
-dessous sous
"AUTEUR".

EXEMPLE

S

Le cas

courant

Normalement, tout ce qui est nécessaire est de dire à ctanify le nom du fichier .ins (ou .sty si le paquet n'utilise pas DocStrip) et la documentation pré-construite, le cas échéant

: 
$ ctanify mypackage.ins mypackage.pdf README
  490347  mypackage.tar.gz
              1771  mypackage/README
             15453  mypackage/mypackage.dtx
              1957  mypackage/mypackage.ins
            277683  mypackage/mypackage.pdf
            246935  mypackage.tds.zip
                        1771  doc/latex/mypackage/README
                      277683  doc/latex/mypackage/mypackage.pdf
                       15453  source/latex/mypackage/mypackage.dtx
                        1957  source/latex/mypackage/mypackage.ins
                        1725  tex/latex/mypackage/mypackage.
sty

ctanify affiche la taille en octets de l'archive tarball résultante, de chaque fichier qu'elle contient, et de chaque fichier du fichier ZIP inclus. Dans l'exemple précédent, notez comment ctanify a automatiquement effectué toutes les opérations suivantes

:
  • inclure mypackage.dtx (trouvé en analysant mypackage.ins) à la fois dans le répertoire mypackage et dans le fichier
    • ZIP,
  • inclure mypackage.sty (trouvé en analysant mypackage.ins) dans le fichier ZIP mais, car c'est un fichier généré, pas dans le répertoire mypackage,
    • et
  • placer tous les fichiers dans les répertoires
    • TDS appropriés (documentation, source, p
aquet principal) à l'intérieur du fichier ZIP.

Considérez ce qu'il faudrait faire pour produire manuellement un fichier mypackage.tar.gz équivalent. ctanify est définitivement une altern

ative plus simple
et plus rapide.

Utilisation

avancée

ctanify suppose que les fichiers PostScript sont de la documentation et les stocke donc sous doc/latex/nom-du-paquet/ dans l'arborescence TDS à l'intérieur du fichier ZIP. Cependant, supposez qu'un paquet LaTeX utilise un ensemble de fichiers PostScript pour contrôler la sortie de dvips. Dans ce cas, il faut indiquer à ctanify d'inclure ces fichiers PostScript dans le répertoire du paquet, et non dans le répertoire de

documentation. 
$ ctanify mypackage.ins "mypackage*.ps=tex/latex/mypacka

AVERTISSEMEN

TS

ctanify n'invoque pas tex ou latex de lui-même, par ex. pour traiter un fichier .ins. La raison est que ctanify ne sait pas, en général, comment produire tous les fichiers générés d'un paquet. Il a été jugé préférable de ne rien faire plutôt que de risquer d'écraser des fichiers .sty (ou autres) existants ou d'inclure des fichiers générés obsolètes dans l'archive. En bref, avant d'exécuter ctanify, vous devriez traiter manuellement tous les fichiers .ins et générer autrement tous les fichiers qui doivent être envoyés à

CTAN.

ctanify n'a été testé que sous Linux. Il pourrait fonctionner sous OS X. On m'a dit qu'il fonctionne sous Windows lorsqu'il est exécuté avec Cygwin. Les volontaires disposés à aider à porter ctanify vers d'autres platef

ormes sont
les bienvenus.
