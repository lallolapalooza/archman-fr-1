CTERMID(3P) Manuel du programmeur POSIX CTERMID(3P)

PROLOGUE

Cette page manuelle fait partie du Manuel du programmeur POSIX. L'implémentation Linux de cette interface peut différer (consultez la page man correspondante de Linux pour les détails du comportement de Linux), ou l'interface peut ne pas être implémentée sur Linux.

NOM

ctermid — générer un chemin d'accès pour le terminal de contrôle

SYNOPSIS

#include <stdio.h>
char *ctermid(char *s);

DESCRIPTION

La fonction ctermid() génère une chaîne qui, lorsqu'elle est utilisée comme chemin d'accès, fait référence au terminal de contrôle actuel du processus courant. Si ctermid() retourne un chemin d'accès, l'accès au fichier n'est pas garanti.

La fonction ctermid() n'a pas besoin d'être sûre pour les threads si elle est appelée avec un paramètre NULL.

VALEUR RENVOYÉE

Si s est un pointeur nul, la chaîne sera générée dans une zone qui peut être statique, dont l'adresse sera retournée. L'application ne doit pas modifier la chaîne retournée. Le pointeur retourné peut être invalidé ou le contenu de la chaîne peut être écrasé par un appel ultérieur à ctermid(). Le pointeur retourné peut également être invalidé si le thread appelant est terminé. Si s n'est pas un pointeur nul, s est supposé pointer vers un tableau d'au moins L_ctermid octets ; la chaîne est placée dans ce tableau et la valeur de s sera retournée. La constante symbolique L_ctermid est définie dans <stdio.h>, et doit avoir une valeur supérieure à 0.

La fonction ctermid() doit retourner une chaîne vide si le chemin d'accès qui ferait référence au terminal de contrôle ne peut pas être déterminé, ou si la fonction échoue.

ERREURS

Aucune erreur n'est définie.

Les sections suivantes sont informatives.

EXEMPLES

Déterminer le terminal de contrôle du processus courant

L'exemple suivant retourne un pointeur vers une chaîne qui identifie le terminal de contrôle du processus courant. Le chemin d'accès du terminal est stocké dans le tableau pointé par l'argument ptr , qui a une taille de L_ctermid octets, comme indiqué par l'argument term .

#include <stdio.h>
...
char term[L_ctermid];
char *ptr;
ptr = ctermid(term);

UTILISATION PAR LES APPLICATIONS

La différence entre ctermid() et ttyname() est que ttyname() doit recevoir un descripteur de fichier et retourne le chemin du terminal associé à ce descripteur de fichier, tandis que ctermid() retourne une chaîne (comme "/dev/tty") qui fait référence au terminal de contrôle actuel si elle est utilisée comme chemin d'accès.

JUSTIFICATION

L_ctermid doit être défini de manière appropriée pour une implémentation donnée et doit être supérieur à zéro afin que les déclarations de tableaux l'utilisant soient acceptées par le compilateur. La valeur inclut l'octet nul de terminaison.

Les applications conformes qui utilisent plusieurs threads ne peuvent pas appeler ctermid() avec NULL comme paramètre. Si s n'est pas NULL, la fonction ctermid() génère une chaîne qui, lorsqu'elle est utilisée comme chemin d'accès, fait référence au terminal de contrôle actuel du processus courant. Si s est NULL, la valeur de retour de ctermid() est indéfinie.

Il n'y a pas de charge supplémentaire pour le programmeur — passer à l'utilisation d'une version sûre pour les threads hypothétique de ctermid() en plus d'allouer un tampon est plus contraignant que d'allouer simplement un tampon. Le code de l'application ne doit pas supposer que la chaîne retournée est courte, car certaines implémentations ont plus de deux composants de chemin d'accès avant d'atteindre un nom de périphérique logique.
