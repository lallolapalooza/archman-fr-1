DESCRIPTIO

N

ctlinnd envoie un message au canal de contrôle de innd(8), le démon principal

InterNetNews.

Dans le mode de fonctionnement normal, le message est envoyé au serveur, qui effectue alors l'action demandée et renvoie une réponse avec un message texte et un code de sortie pour ctlinnd. Si le serveur a exécuté la commande avec succès, ctlinnd affichera la réponse sur la sortie standard et se terminera avec un statut de zéro. Si le serveur n'a pas pu exécuter la commande, il indiquera à ctlinnd de se terminer avec un statut de un. Par défaut, ctlinnd attendra indéfiniment une réponse de innd ; cela peut être modifié avec l'indicateur -t

.

Les commandes "shutdown", "xabort" et "xexec" ne génèrent pas de réponse, car elles provoquent la sortie de innd. Après ces commandes, ctlinnd se terminera toujours sile

ncieusement avec u
n statut de zéro.

OPTION

S
-
h
Affiche un résumé des commandes. Si une commande est donnée avec l'indicateur -h, seul l'usage de cette commande sera
affiché.
-
s
Si la commande a réussi, ne pas afficher la sortie de inn
d.
-t déla
i
Spécifie combien de temps attendre la réponse du serveur, pour les commandes autres que "shutdown", "xabort" et "xexec". délai est le nombre de secondes à attendre. Une valeur de zéro indique d'attendre indéfiniment, et une valeur inférieure à zéro indique de ne pas attendre du tout mais de se terminer immédiatement avec le statut zéro. En attendant une réponse, ctlinnd vérifiera toutes les deux minutes que le serveur est toujours en cours d'exécution, pour réduire la probabilité que ctlinnd se bloque simplement.

La valeur par défaut est zéro, indiquant que ctlinnd doit

reload what reas
on
Met à jour la copie en mémoire des fichiers de configuration du serveur. what identifie ce qui doit être rechargé, et reason est rapporté à syslog dans le message notant le rechargement.

Il n'y a aucun moyen de recharger inn.conf, storage.conf, ou d'autres fichiers de configuration pour les backends de stockage ou de vue d'ensemble. Pour prendre en compte les modifications de ces fichiers, utilisez "ctlinnd xexec innd" pour redémarrer inn

d.

Si what est la chaîne vide ou le mot "all", tout est rechargé. S'il s'agit du mot "history", la base de données d'historique est fermée et rouverte. S'il s'agit du mot "incoming.conf", le fichier correspondant est rechargé. S'il s'agit du mot "active" ou "newsfeeds", à la fois les fichiers active et newsfeeds sont rechargés, ce qui causera aussi le vidage et le redémarrage de tous les flux

sortants.

Si what est le mot "filter.perl", le fichier filter_innd.pl est rechargé. (Ce fichier n'est cependant pas disponible pour le rechargement sauf si INN a été compilé avec la prise en charge du filtrage Perl.) Si le filtre Perl a défini une fonction "filter_before_reload", celle-ci sera appelée avant de relire filter_innd.pl. Si la fonction Perl "filter_after_reload" est défini, il sera appelé après filter_innd.pl a été rechargé. Le rechargement du filtre Perl n'active pas le filtrage s'il a été désactivé ; utilisez plutôt "perl y" pour cela. startup_innd.pl ne peut pas être

rechargé.

Si le mot-clé est "filter.python", le fichier filter_innd.py est rechargé. (Ce fichier n'est cependant pas disponible pour le rechargement si INN n'a pas été compilé avec le support du filtrage Python.) Si une méthode Python nommée "filter_before_reload" existe, elle sera appelée avant de relire filter_innd.py. Si une méthode Python nommée "__init__" existe, elle sera appelée après filter_innd.py a été rechargé. Le rechargement du filtre Python n'active pas le filtrage s'il a été désactivé ; utilisez plutôt "python y"

pour
cela.

NOTE

S

En plus d'être traitées par le serveur, certaines commandes peuvent être transférées à un processus enfant approprié. Si le site qui reçoit la commande est un explodeur (comme buffchan) ou un entonnoir qui alimente un explodeur, la commande peut être transférée. Dans ce cas, le serveur enverra une ligne de commande à l'explodeur qui se compose du nom de commande ctlinnd. Si le site alimente un explodeur qui a un astérisque ("*") dans son drapeau "W" (voir newsfeeds(5) pour plus d'informations sur les spécifications de flux), le

nom du site sera ajouté à la command
e ; sinon, aucun argument n'est ajouté.

BUG

S

ctlinnd utilise des sockets de domaine Unix sur la plupart des systèmes pour communiquer avec innd et est donc limité par la taille maximale de paquet que le système d'exploitation impose aux datagrammes

de domaine Unix. Cela peut signifier que les réponse
s du serveur sont limitées à 4 Ko sur certains systèmes.
