ctags-lang-tcl - Notes diverses sur l'étiquetage du code source tcl avec Universal Ctags

SYNOPSIS

ctags ... --languages=+Tcl ...
ctags ... --language-force=Tcl ...
ctags ... --map-Tcl=+.tcl ...

DESCRIPTION

Cette page de manuel rassemble des notes diverses sur l'étiquetage du code source tcl.

TAGGING language objects of OO Extensions

Les analyseurs TclOO et ITcl sont des sous-analyseurs exécutés sur l'analyseur Tcl. Comme leurs noms l'indiquent, ils servent à étiqueter les objets de langage des extensions de programmation orientée objet pour le langage Tcl.

Un motif, "namespace import oo" dans un fichier d'entrée active l'analyseur TclOO. Un motif, "namespace import itcl" dans un fichier d'entrée active l'analyseur ITcl.

Il existe des cas où l'une des extensions OO est utilisée sans que les deux motifs apparaissent dans un fichier d'entrée.

Considérez les fichiers d'entrée suivants :

"main.tcl"

package require Itcl
namespace import itcl::*
source input.tcl

"input.tcl"

class MyClass {
        public method foo {} {
        }
}

Le motif d'activation de l'analyseur ITcl n'apparaît pas dans "input.tcl" bien que la commande "class" soit utilisée. En conséquence, ctags ne peut pas extraire "MyClass".

Les paramètres TclOO.forceUse=true|[false] et ITcl.forceuse=true|[false] permettent de gérer cette situation. Avec ces paramètres, vous pouvez forcer ctags à activer l'un des sous-analyseurs.

Vous pouvez utiliser ces paramètres comme --param-ITcl.forceuse=true en ligne de commande.

Notez que vous ne pouvez activer qu'un seul des analyseurs ITcl ou TclOO. L'activation des deux analyseurs en spécifiant les paramètres peut entraîner des résultats inattendus.
