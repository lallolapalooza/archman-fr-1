Stockage des

annotations

Comme l'analyseur Python stocke les décorations dans le champ decorations, l'analyseur GDScript stocke les annotations commençant par @ dans le champ spécifique au langage, annotations. Bien que le champ soit activé explicitement dans les exemples suivants, le champ est activé par

défaut.

"input.

gd" 
@export
var s =
"Hello" @master
func f(msg):
print(msg)

"output.tags" avec "--options=NONE --sort=no --fields-GDScript=+{annotations} -o - input.

gd" 
s       input.gd        /^var
s = "Hello"$/;" v anno
tations:export f input.
gd /^func f(msg):$/;"
m annotations:master

Extraction de

func

Un objet de langage défini avec le mot-clé func est marqué avec le type method. Comme les annotations, l'analyseur stocke les mots-clés modifiant func comme static dans le champ annotations

.

"input.

gd" 
func f(x):
        return
x static func f_s(x):
reutrn x remote func
f_r(x): return x

"output.tags" avec "--options=NONE --sort=no --fields=+K --fields-GDScript=+{annotations} -o - input.

gd" 
f       input.gd        /^func f(x):$/;"
method f_s input.gd /^static
func f_s(x):$/;" method annotations:s
tatic f_r input.gd /^remote func
f_r(x):$/;" method annotations:remote

Marquage des classes définies

implicitement

« Un fichier est une classe ! » en GDScript. Une classe est définie implicitement. Les fonctions, les variables, les constantes et les signaux font partie de la classe bien que la classe soit nommée par

défaut.

Si l'option spécifique au langage, implicitClass, est activée, l'analyseur crée une étiquette anonyme pour la classe. L'analyseur remplit les champs scope des étiquettes pour tous les objets de langage définis dans le fichier avec l'étiquette

anonyme.

Voyons un exemple démontrant l'effet de

l'option.

Désactivation de l'option

:

"input.

gd" 
func f(
x):
r
eturn x

"output.tags" avec "--options=NONE --fields=+KZ --extras-GDScript=-{implicitClass} -o - input.

gd" 
f       input.
gd /^f
unc f(x):$/;"
method

Activation de l'option

:

x):

Marquage du nom spécifié avec

class_name

class_name est un mot-clé pour donner un nom à la classe définie implicitement. Si implicitClass est désactivé, l'analyseur extrait simplement le nom venant après le mot-clé avec le type class. Si implicitClass est activé, l'analyseur convertit l'étiquette anonyme en une étiquette non anonyme avec le nom spécifié. Lors de la conversion, l'analyseur met également à jour les champs scope des autres étiquettes dans le

fichier.

Désactivation de l'option

:

"input.

gd" 
class_name
c func f(
x):
return x

"output.tags" avec "--options=NONE --fields=+KZ --extras-GDScript=-{implicitClass} -o - input.

gd" 
c       input.gd        /^c
lass_name c$/;" class
f input.gd /^f
unc f(x):$/;" method

Activation de l'option

:

"input.

gd" 
class_name
C func g(
x):
return x

"output.tags" avec "--options=NONE --fields=+KZ --extras-GDScript=+{implicitClass} -o - input.

gd" 
C       input.gd        /
^class_name C$/;" c
lass g input.gd
/^func g(x):$/;"
method scope:class:C

Remplissage du champ

inherits

Le mot-clé extends spécifie la classe mère pour la classe définie implicitement. Si l'option implicitClass est activée, l'analyseur remplit le champ inherits de l'étiquette pour la classe définie implicitement avec le nom de la classe

mère.

"input.

gd" 
extend
s B c
lass_
name C

"output.tags" avec "--options=NONE --fields=+Ki --extras-GDScript=+{implicitClass} -o - input.

gd" 
C       input.gd
/^class_n
ame C$/;" cl
ass inherits:B

Lorsque --extras=+r est donné, l'analyseur extrait la classe spécifiée avec le mot-clé extends comme une étiquette de référence de type class avec le rôle extended

.

gd"
