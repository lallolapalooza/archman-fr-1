Nom

ctags-json-output - Sortie JSON de ctags

SYNOPSIS

ctags --output-format=json ...

DESCRIPTION

Universal Ctags prend en charge le format de sortie JSON https://www.json.org/ (plus précisément JSON Lines https://jsonlines.org/) si l'exécutable ctags est compilé avec libjansson. La sortie JSON va vers la sortie standard par défaut.

FORMAT

Chaque ligne JSON représente une balise.

$ ctags --extras=+p --output-format=json --fields=-s input.py
{"_type": "ptag", "name": "JSON_OUTPUT_VERSION", "path": "1.0", "pattern": "in development"}
{"_type": "ptag", "name": "TAG_FILE_SORTED", "path": "1", "pattern": "0=unsorted, 1=sorted, 2=foldcase"}
...
{"_type": "tag", "name": "Klass", "path": "/tmp/input.py", "pattern": "/^class Klass:$/", "language": "Python", "kind": "class"}
{"_type": "tag", "name": "method", "path": "/tmp/input.py", "pattern": "/^    def method(self):$/", "language": "Python", "kind": "member", "scope": "Klass", "scopeKind": "class"}
...

Une clé ne commençant pas par _ est mappée à un champ de ctags. Les options "--output-format=json --list-fields" listent les champs.

Une clé commençant par _ représente des métadonnées de la ligne JSON. Actuellement, seule la clé _type est utilisée. Si la valeur de la clé est tag, la ligne JSON représente une balise normale. Si la valeur est ptag, la ligne représente une pseudo-balise.

Le format de sortie peut être modifié à l'avenir. La pseudo-balise JSON_OUTPUT_VERSION permet aux outils clients de gérer les changements. La version actuelle est "1.0". Un outil client peut extraire la version avec la clé path de la pseudo-balise.

Le format de sortie JSON est nouvellement conçu et ne présente aucune des limitations trouvées dans le format de fichier de balises par défaut.

  • Les valeurs de la clé kind sont représentées par des drapeaux en nom long. Aucun caractère unique ici.
  • Les noms de portée et les types de portée ont des clés distinctes : scope et scopeKind. Elles sont combinées dans le format de fichier de balises par défaut.

TYPE DE DONNÉES UTILISÉ DANS UN CHAMP

Les valeurs de la plupart des champs sont représentées en type chaîne JSON. Cependant, certaines sont représentées en chaînes, entiers et/ou booléens.

Les options "--output-format=json --list-fields" montrent quel type de données est utilisé dans un champ JSON.

$ ctags --output-format=json --list-fields
#LETTER NAME           ENABLED LANGUAGE         JSTYPE FIXED DESCRIPTION
F       input          yes     NONE             s--    no    input file
...
P       pattern        yes     NONE             s-b    no    pattern
...
f       file           yes     NONE             --b    no    File-restricted scoping
...
e       end            no      NONE             -i-    no    end lines of various items
...

La colonne JSTYPE indique les types de données.

's'
chaîne de caractères
'i'
entier
'b'
booléen (vrai ou faux)

Par exemple, la valeur du champ pattern de ctags peut prendre une chaîne de caractères ou une valeur booléenne.

VERSIONS

Changement depuis "0.0"

•
Nouvelle clé kindName pour la pseudo-balise TAG_ROLE_DESCRIPTION

kindName est ajoutée pour stocker le nom du type dans les pseudo-balises TAG_ROLE_DESCRIPTION.

En 0.0, une pseudo-balise "TAG_ROLE_DESCRIPTION" était affichée comme suit :

{"_type": "ptag", "name": "TAG_ROLE_DESCRIPTION",
                  "parserName": "LANG!KIND", }

En 1.0, elle est affichée comme suit :

{"_type": "ptag", "name": "TAG_ROLE_DESCRIPTION",
                  "parserName": "LANG",
                  "kindName": "KIND",  }
