CTLOG_STORE_new(3ssl)

Paquet: openssl

Licences: Apache-2.0

CTLOG_STORE_NEW(3ssl) OpenSSL CTLOG_STORE_NEW(3ssl)

NOM

CTLOG_STORE_new_ex, CTLOG_STORE_new, CTLOG_STORE_free, CTLOG_STORE_load_default_file, CTLOG_STORE_load_file - Créer et peupler une liste de journaux de transparence des certificats

SYNOPIS

#include <openssl/ct.h>
CTLOG_STORE *CTLOG_STORE_new_ex(OSSL_LIB_CTX *libctx, const char *propq);
CTLOG_STORE *CTLOG_STORE_new(void);
void CTLOG_STORE_free(CTLOG_STORE *store);
int CTLOG_STORE_load_default_file(CTLOG_STORE *store);
int CTLOG_STORE_load_file(CTLOG_STORE *store, const char *file);

DESCRIPTION

Un CTLOG_STORE est un conteneur pour une liste de CTLOGs (journaux de transparence des certificats). La liste peut être chargée à partir d'un ou plusieurs fichiers, puis recherchée par LogID (voir RFC 6962, Section 3.2, pour la définition d'un LogID).

CTLOG_STORE_new_ex() crée une liste vide de journaux CT associée au contexte de bibliothèque libctx et à la chaîne de requête de propriété propq.

CTLOG_STORE_new() fait la même chose que CTLOG_STORE_new_ex() mais avec le contexte de bibliothèque et la chaîne de requête de propriété par défaut.

Le CTLOG_STORE est ensuite peuplé par CTLOG_STORE_load_default_file() ou CTLOG_STORE_load_file(). CTLOG_STORE_load_default_file() charge à partir du fichier par défaut, nommé ct_log_list.cnf dans OPENSSLDIR (voir la sortie de openssl-version(1)). Ceci peut être annulé en utilisant une variable d'environnement nommée CTLOG_FILE. CTLOG_STORE_load_file() charge à partir d'un chemin de fichier spécifié par l'appelant à la place. Ces deux fonctions ajoutent les journaux CT chargés au CTLOG_STORE.

Le format attendu du fichier est :

enabled_logs=foo,bar
[foo]
description = Journal 1
key = <SubjectPublicKeyInfo DER encodée en base64 ici>
[bar]
description = Journal 2
key = <SubjectPublicKeyInfo DER encodée en base64 ici>

Une fois qu'un CTLOG_STORE n'est plus requis, il doit être passé à CTLOG_STORE_free(). Cela supprimera tous les CTLOGs stockés à l'intérieur, ainsi que le CTLOG_STORE lui-même. Si l'argument est NULL, rien n'est fait.

NOTES

S'il y a des journaux CT invalides dans un fichier, ils sont ignorés et les journaux valides restants seront toujours ajoutés au CTLOG_STORE. Un journal CT sera considéré comme invalide s'il manque un champ "key" ou "description".

VALEUR DE RETOUR

CTLOG_STORE_load_default_file et CTLOG_STORE_load_file retournent 1 si tous les journaux CT du fichier sont analysés et chargés avec succès, 0 sinon.

VOIR AUSSI

ct(7), CTLOG_STORE_get0_log_by_id(3), SSL_CTX_set_ctlog_list_file(3)

HISTORIQUE

CTLOG_STORE_new_ex a été ajouté dans OpenSSL 3.0. Toutes les autres fonctions ont été ajoutées dans OpenSSL 1.1.0.
