Nom

ctags-lang-i18nrubygem - Notes diverses sur le balisage d'entrées pour le Gem Ruby I18n avec Universal Ctags

SYNOPSIS

ctags ... --extras=+s --languages=+I18nRubyGem ...
ctags ... --extras=+s --language-force=I18nRubyGem ...
ctags ... --extras=+s --map-I18nRubyGem=+.yaml ...
ctags ... --extras=+s --map-I18nRubyGem=+.yml ...

DESCRIPTION

Cette page de manuel rassemble des notes diverses sur le balisage d'entrées pour le Gem Ruby I18n [RUBYI18N]. I18nRubyGem est un sous-analyseur fonctionnant sur le noyau d'analyse Yaml. Si un jeton scalaire de premier niveau d'une entrée source Yaml donnée est un nom local [ISOCODES], I18nRubyGem s'active. Sinon, I18nRubyGem ne fait rien.

"input.yaml"

---
ja:
  msg:
    error: エラー
    function: 関数

"output.tags" avec "--options=NONE -o - --fields=+E input.yaml"

error   input.yaml      /^    error: エラー$/;"    k       keyInMiddle:ja.msg      extras:subparser
function        input.yaml      /^    function: 関数$/;"  k       keyInMiddle:ja.msg      extras:subparser
ja.msg.error    input.yaml      /^    error: エラー$/;"    k       keyInMiddle:ja.msg      extras:subparser,localeful
ja.msg.function input.yaml      /^    function: 関数$/;"  k       keyInMiddle:ja.msg      extras:subparser,localeful
msg.error       input.yaml      /^    error: エラー$/;"    k       locale:ja       extras:subparser,localeless
msg.function    input.yaml      /^    function: 関数$/;"  k       locale:ja       extras:subparser,localeless

Avec les options, l'analyseur émet trois entrées de balise pour une clé : « error », « js.msg.error » et « msg.error » pour la clé « error ». L'analyseur émet « error » à la première ligne toujours.

Pour émettre « ja.msg.error », une balise extra localeful, à la cinquième ligne toujours. Si vous spécifiez --extra=+q ou --extra=+{qualified}, ctags émet la même balise deux fois : une balise localeful et une balise qualified. Vous pouvez supprimer les balises extra localeful en spécifiant --extras-I18nRubyGem=-{localeful}.

Pour émettre « msg.error », une balise extra localeless, à la cinquième ligne toujours. L'analyseur crée une balise extra localeless en tronquant le premier composant (par exemple, « ja. ») de la balise extra qualifiée associée (par exemple, « ja.msg.error »). L'extra localeless est activé par défaut. Si vous n'avez pas besoin des balises extra localeless, spécifiez --extras-I18nRubyGem=-{localeless}.

L'analyseur ne crée pas d'entrées de balise pour les composants de niveau supérieur et intermédiaire comme ja et msg par défaut. Si vous en avez besoin, spécifiez --kinds-I18nRubyGem=+{locale} et/ou --kinds-I18nRubyGem=+{keyInMiddle}.

BUGS CONNUS

Le mécanisme d'activation du sous-analyseur I18nRubyGem ne fonctionne pas bien pour les entrées sources YAML contenant plusieurs documents.
