DESCRIPTIO

N

Le programme ctwill convertit un document source CWEB en un fichier TeX qui peut être mis en forme et imprimé de la manière habituelle. Il prend soin des détails typographiques appropriés tels que la mise en page et l'utilisation de l'indentation, de l'italique, du gras, etc., et fournit des informations d'index croisé étendues qu'il collecte automatiquement

.

CWEB vous permet de préparer un unique document contenant toutes les informations nécessaires à la fois pour pro

duire un programme C/C++ compilable et pour produire un document bien mis en forme décrivant le programme a
ussi en détail que l'auteur le désire. L'utilisateur de CWEB devrait être familier avec TeX ainsi qu'avec C/C++.

UTILISATI

ON

La ligne de commande devrait contenir un, deux ou trois noms. Le premier est considéré comme le fichier d'entrée CWEB (et .w est ajouté s'il n'y a pas d'extension). S'il y a un deuxième nom, c'est un fichier de modifications (et .ch est ajouté s'il n'y a pas d'extension). Le fichier de modifications remplace des parties du fichier CWEB, comme décrit dans la documentation. S'il y a un troisième nom, il remplace le nom par défaut du fichier de sortie, qui est ordinairement le même que le nom du fichier d'entrée (mais dans le répertoire courant) avec l'extension .tex. Si vous voulez simplement changer le nom du fichier de sortie, mais que vous n'avez pas de fichier de modifications à appliquer, vous pouvez utiliser `-' comme deuxième

argument.

ctwill est exactement comme cweave sauf qu'il produit une bien meilleure documentation, pour laquelle vous devez travailler beaucoup plus dur. Vous devriez exécuter ctwill deux fois, une fois pour amorcer la pompe et une fois pour obtenir des résultats décents. De plus, vous devez faire passer la sortie deux fois à travers

TeX.

Après tex foo vous aurez une sortie qui ressemble à des pages finales sauf que les entrées des mini-index ne seront pas alphabetisées. La première exécution produit un fichier étrange appelé foo.ref. Dites ctwill-refsort < foo.ref > foo.sref et ensuite une autre tex foo produira une sortie

alphabetisée.

Le programme ctwill-twinx compile un index maître pour un ensemble de programmes liés qui ont été traités par ctwill (pas par cweave, notez-le !). Les programmes individuels devraient définir leurs noms avec une ligne de la forme \def\title{NOM}. Pour votre commodité, ctwill-twinx prend le premier « mot » dans \title et le transforme en majuscules. Vous devriez adapter le fichier twinx-startup.tex pour la première page de l'index

maître.

Les mini-index listent les identifiants qui sont utilisés mais pas définis sur chaque double page. À la fin de chaque section, ctwill donne à TeX une liste des identifiants utilisés dans cette section et des informations sur l'endroit où ils sont

définis.

La signification actuelle de chaque identifiant est initialement \uninitialized. Ensuite ctwill lit le fichier .aux pour votre travail, s'il

existe.

Avant de lire le fichier .aux, ctwill cherche en fait un fichier appelé system.bux, qui sera lu s'il est présent. Et après foo.aux, une troisième possibilité est foo.bux. La convention générale est de mettre les définitions des procédures système telles que printf dans system.bux, et de mettre les définitions trouvées dans les fichiers d'en-tête spécifiquement foo dans foo.bux. Comme les fichiers .aux, les fichiers .bux devraient contenir uniquement des spécifications @$

.

La signification spécifiée par @$...@> a généralement quatre composants : un identifiant (suivi d'un espace), un nom de programme (entre accolades), un numéro de section (suivi d'un espace), et une partie

TeX.

Un mode spécial proofmode est fourni pour que vous puissiez vérifier les conclusions de ctwill sur les références croisées. Exécutez ctwill avec l'indicateur +P, et TeX produira un document spécialement formaté (sans mini-index) dans lequel vous pouvez vérifier que vos spécifications sont

correctes.

Plus de détails sur la façon d'utiliser ctwill peuvent être trouvés dans les premières sections de son code source, respectivement le fichier de modifications cweav-twill.ch applicable à la source cweave.w. Un exemple complet avec toutes les options est décrit dans Mini-Indexes for Literate Programs, pages 225–245 de Digital Typo

graphy d
e Knuth.

DIFFÉRENCES PAR RAPPORT À CTWILL

ORIGINAL

La présente incarnation de ctwill et de ses utilitaires essaie d'être un remplacement direct du paquet original. Il y a cependant quelques différences à noter

:
•
Cette version est basée sur la version la plus récente de CWEB (4.
8).
•
Dans TeX Live, les programmes utilitaires sont préfixés avec ctwill- et les fichiers de macros avec ct pour des raisons
techniques.
•
Les options --help, --quiet, --verbose, --version, et les indicateurs +c, -i, -o, et +lX sont nouveaux dans CWEBbin et TeX
Live.
•
L'option +lX est accompagnée de fichiers d'enveloppement d'exemple pour ctwimac.tex et ctproofmac.tex avec des légendes traduites pour l'allemand (+ld
).
•
L'option +lX est aussi accompagnée d'un pdfctwimac.tex étendu pour la production de sortie PDF avec hyperliens actifs (+lpdf
).
•
ctwill dans TeX Live fonctionne silencieusement par défaut ; utilisez l'option --verbose pour obtenir le comportement
original.
•
La recherche de fichier avec la variable d'environnement CWEBINPUTS est étendue pour permettre plusieurs chemins séparés par des deux-points ; voir ENVIRONNEMENT
ci-dessous.
•
Si correctement configuré, le programme principal ctwill est localisé avec
les « u
tilitaires G
NU gettext ».

ENVIRONNEMEN

T

La variable d'environnement CWEBINPUTS est utilisée pour rechercher les fichiers d'entrée, ou la valeur par défaut du système si CWEBINPUTS n'est pas définie. Voir tex(1) pour les détails de la recherche. Pour éviter les conflits avec d'autres programmes qui utilisent aussi l'environnement CWEBINPUTS, vous pouvez être plus précis et utiliser CWEBINPUTS_cweb pour des besoins spécifiques à

CWEB.

Si préparé pour le support NLS, ctwill, tout comme ctangle et cweave, utilise la variable d'environnement TEXMFLOCALEDIR pour configurer le répertoire parent dans lequel les « GNU gettext utilities » recherchent les catalogues de

traduction.

Ces variables sont préconfigurées dans le fichier texmf.cnf d

e TeX
 Live.

sortie.

actifs.
•
