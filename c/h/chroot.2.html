chroot(2) Manuel des appels système chroot(2)

NOM

chroot - changer le répertoire racine

BIBLIOTHÈQUE

Bibliothèque C standard (libc, -lc)

SYNTAXE

#include <unistd.h>
int chroot(const char *path);
Exigences relatives aux macros de test de fonctionnalités pour glibc (voir feature_test_macros(7)) :

chroot():

    Depuis glibc 2.2.2 :
        _XOPEN_SOURCE && ! (_POSIX_C_SOURCE >= 200112L)
            || /* Depuis glibc 2.20 : */ _DEFAULT_SOURCE
            || /* glibc <= 2.19 : */ _BSD_SOURCE
    Avant glibc 2.2.2 :
        aucun

DESCRIPTION

chroot() change le répertoire racine du processus appelant pour celui spécifié dans path. Ce répertoire sera utilisé pour les noms de chemin commençant par /. Le répertoire racine est hérité par tous les enfants du processus appelant.

Seul un processus privilégié (Linux : celui possédant la capacité CAP_SYS_CHROOT dans son espace de noms utilisateur) peut appeler chroot().

Cet appel modifie un ingrédient du processus de résolution de nom de chemin et ne fait rien d'autre. En particulier, il n'est pas destiné à être utilisé à des fins de sécurité, ni pour cloisonner complètement un processus, ni pour restreindre les appels système de système de fichiers. Par le passé, chroot() a été utilisé par les démons pour se restreindre avant de passer des chemins fournis par des utilisateurs non fiables à des appels système tels que open(2). Cependant, si un dossier est déplacé hors du répertoire chroot, un attaquant peut l'exploiter pour sortir également du répertoire chroot. La manière la plus simple de le faire est de faire chdir(2) vers le répertoire à déplacer, attendre qu'il soit déplacé hors du répertoire, puis ouvrir un chemin comme ../../../etc/passwd.

Une variation légèrement plus subtile fonctionne également dans certaines circonstances si chdir(2) n'est pas autorisé. Si un démon autorise la spécification d'un "répertoire chroot", cela signifie généralement que si vous voulez empêcher les utilisateurs distants d'accéder aux fichiers en dehors du répertoire chroot, vous devez vous assurer que les dossiers ne sont jamais déplacés hors de celui-ci.

Cet appel ne modifie pas le répertoire de travail actuel, de sorte qu'après l'appel, '.' peut être en dehors de l'arborescence racine de '/'. En particulier, le superutilisateur peut s'échapper d'une "prison chroot" en faisant :


mkdir foo;
chroot foo;
cd ..;

Cet appel ne ferme pas les descripteurs de fichiers ouverts, et de tels descripteurs de fichiers peuvent permettre l'accès à des fichiers en dehors de l'arborescence chroot.

VALEUR DE RETOUR

En cas de succès, zéro est retourné. En cas d'erreur, -1 est retourné, et errno est défini pour indiquer l'erreur.

ERREURS

En fonction du système de fichiers, d'autres erreurs peuvent être renvoyées. Les erreurs les plus générales sont listées ci-dessous :

EACCES
La permission de recherche est refusée sur un composant du préfixe du chemin. (Voir aussi path_resolution(7).)
EFAULT
path pointe en dehors de votre espace d'adressage accessible.
EIO
Une erreur d'entrée/sortie s'est produite.
ELOOP
Trop de liens symboliques ont été rencontrés lors de la résolution de path.
ENAMETOOLONG
path est trop long.
ENOENT
Le fichier n'existe pas.
ENOMEM
Mémoire noyau insuffisante disponible.
ENOTDIR
Un composant de path n'est pas un répertoire.
EPERM
L'appelant n'a pas les privilèges suffisants.

NORMES

Aucune.

HISTORIQUE

SVr4, 4.4BSD, SUSv2 (marqué comme LEGACY). Cette fonction ne fait pas partie de POSIX.1-2001.

NOTES

Un processus enfant créé via fork(2) hérite du répertoire racine de son parent. Le répertoire racine n'est pas modifié par execve(2).

Le lien symbolique magique, /proc/pid/root, peut être utilisé pour découvrir le répertoire racine d'un processus ; voir proc(5) pour plus de détails.

FreeBSD dispose d'un appel système jail() plus robuste.

VOIR AUSSI

chroot(1), chdir(2), pivot_root(2), path_resolution(7), switch_root(8)
