DESCRIPTIO

N

Pragma "use charnames" est utilisé pour obtenir l'accès aux noms des caractères Unicode et des séquences de caractères nommées, et pour vous permettre de définir vos propres noms de caractères et de séquences de

caractères.

Toutes les formes du pragma permettent l'utilisation des 3 fonctions suivantes

:
  • "charnames::string_vianame(name)" pour la recherche à l'exécution d'un nom de caractère ou d'une séquence de caractères nommée, en renvoyant sa représentation sous forme de
    • chaîne
  • "charnames::vianame(name)" pour la recherche à l'exécution d'un nom de caractère (mais pas d'une séquence de caractères nommée) afin d'obtenir sa valeur ordinale (point de
    • code)
  • "charnames::viacode(code)" pour la recherche à l'exécution d'un
    • point de code afin d'ob
tenir son nom Unicode.

À partir de Perl v5.16, toute occurrence de "\N{CHARNAME}" dans une chaîne entre guillemets charge automatiquement ce module avec les arguments ":full" et ":short" (décrits ci-dessous) s'il n'a pas déjà été chargé avec des arguments différents, afin de compiler le caractère Unicode nommé à sa position dans la chaîne. Avant la v5.16, une "use charnames" explicite était nécessaire pour activer cette utilisation. (Cependant, avant la v5.16, la forme "use charnames ()" n'activait pas "\N{CHARNAME}".

)

Notez que "\N{U+...}", où ... est un nombre hexadécimal, insère également un caractère dans une chaîne. Le caractère inséré est celui dont le point de code Unicode (valeur ordinale) est égal au nombre. Par exemple, "\N{U+263a}" est le visage souriant Unicode (fond blanc, premier plan noir) équivalent à "\N{WHITE SMILING FACE}". Notez également que "\N{...}" peut signifier un quantificateur d'expression régulière au lieu d'un nom de caractère, lorsque ... est un nombre (ou une paire de nombres séparés par une virgule (voir "QUANTIFIERS" dans perlreref), et n'est pas lié à ce

pragma.

Le pragma "charnames" prend en charge les arguments ":full", ":loose", ":short", les noms d'écriture et les alias

personnalisés.

Si ":full" est présent, pour l'expansion de "\N{CHARNAME}", la chaîne CHARNAME est d'abord recherchée dans la liste des noms de caractères Unicode

standard.

":loose" est une variante de ":full" qui permet à CHARNAME d'être spécifié de manière moins précise. Les détails sont dans "LOOSE

MATCHES".

Si ":short" est présent, et que CHARNAME a la forme "SCRIPT:CNAME", alors CNAME est recherché comme une lettre dans l'écriture SCRIPT, comme décrit dans le paragraphe suivant. Ou, si "use charnames" est utilisé avec des arguments de nom d'écriture, alors pour "\N{CHARNAME}" le nom CHARNAME est recherché comme une lettre dans les écritures données (dans l'ordre spécifié). Les alias personnalisés peuvent remplacer ceux-ci, et sont expliqués dans "CUSTOM

ALIASES".

CORRESPONDANCES SOUPLES En spécifiant ":loose", les règles de correspondance souple des noms de caractères Unicode http://www.unicode.org/reports/tr44#Matching_Rules sont sélectionnées au lieu de la correspondance exacte stricte utilisée autrement. Cela signifie que CHARNAME n'a pas à être spécifié de manière aussi précise. La casse (majuscule/minuscule) n'a pas d'importance (sauf avec les écritures comme mentionné ci-dessus), pas plus que les traits de soulignement, et les seuls traits d'union qui comptent sont ceux au début ou à la fin d'un mot dans le nom (avec une exception : le trait d'union dans U+1180 "HANGUL JUNGSEONG O-E" compte). De plus, les espaces non adjacents aux traits d'union n'ont pas d'importance. Les noms Unicode officiels sont assez variables quant à l'endroit où ils utilisent des traits d'union plutôt que des espaces pour séparer les unités de type mot, et cette option vous permet de ne pas avoir à vous en soucier autant. La raison pour laquelle les traits d'union non médians comptent est à cause de cas commee U+0F60 « TIBETAN LETTER -A » par rapport à U+0F68 « TIBETAN LETTER A ». Le trait d'union ici est significatif, comme l'espace qui le précède, et les deux doivent donc être

inclus.

« :loose » ralentit les recherches d'un facteur de 2 à 3 par rapport à « :full », mais le compromis peut en valoir la peine pour vous. Chaque recherche individuelle prend très peu de temps, et les résultats sont mis en cache, de sorte que la différence de vitesse ne deviendrait un facteur que dans les programmes qui effectuent des recherches de nombreux orthographes différents, et probablement seulement lorsque ces recherches sont effectuées via vianame() et string_vian

Comme mentionné ci-dessus sous « ALIAS », Unicode 6.1 définit des noms supplémentaires (synonymes ou alias) pour certains points de code, dont la plupart étaient déjà disponibles en tant qu'extensions Perl. Tous ceux-ci sont acceptés par « \N{...} » et les autres fonctions de ce module, mais « viacode » doit choisir quel nom retourner pour un point de code donné, donc il retourne le nom « le meilleur ». Pour comprendre comment cela fonctionne, il est utile d'en savoir plus sur les propriétés de nom Unicode. Tous les points de code n'ont en réalité qu'un seul nom, qui (à partir d'Unicode 2.0) ne peut jamais changer une fois qu'un caractère a été attribué au point de code. Mais des erreurs ont été commises dans l'attribution des noms, par exemple parfois une erreur de copie a été faite lors de la publication de le Standard, ce qui a causé des fautes d'orthographe dans des mots, et il n'y avait aucun moyen de corriger ceux-ci. La propriété Name_Alias a finalement été créée pour gérer ces situations. Si un nom était incorrect, un synonyme corrigé serait publié pour celui-ci, en utilisant Name_Alias. "viacode" renverra ce synonyme corrigé comme le « meilleur » nom pour un point de code. Le nom Unicode pour chacun des caractères de contrôle (comme LINE FEED) est la chaîne vide. Cependant, presque tous avaient des noms assignés par d'autres standards, comme le standard ASCII, ou étaient en usage courant. "viacode" renvoie ces noms comme les « meilleurs » disponibles. Unicode 6.1 a créé des Name_Aliases pour chacun d'entre eux, y compris des noms alternatifs, comme NEW LINE. "viacode" utilise le nom original, "LINE FEED" de préférence à l'alternatif. De même, le nom renvoyé pour U+FEFF est "ZERO WIDTH NO-BREAK SPACE", et non "BYTE ORDER

MARK".

Jusqu'à Unicode 6.1, les 4 caractères de contrôle U+0080, U+0081, U+0084 et U+0099 n'avaient ni noms ni alias. Pour préserver la compatibilité ascendante, tout alias que vous définissez pour ces points de code sera renvoyé par cette fonction, de préférence au nom

officiel.

Certains points de code ont également des noms abrégés, tels que "LF" ou "NL". "viacode" ne renvoie jamais

ceux-ci.

Parce qu'une correction de nom peut être ajoutée dans de futures versions d'Unicode, le nom que "viacode" renvoie peut changer en conséque

PERSONNALISÉS

Le mécanisme de traduction des échappements "\N{...}" est général et n'est pas codé en dur dans charnames.pm. Un module peut installer des traductions personnalisées (dans la portée qui "use"s le module) avec l'incantation magique suivante

: 
sub import {
    shift;
    $^H{charnames} = \&
}

Ici translator() est une sous-routine qui prend CHARNAME comme argument, et renvoie le texte à insérer dans la chaîne à la place de l'échappement "\N{CHARNAME}"

.

C'est la seule façon de créer une séquence de points de code nommée

personnalisée.

Puisque le texte à insérer devrait être différent en mode "bytes" et en dehors de celui-ci, la fonction devrait vérifier l'état actuel de l'indicateur "bytes" comme ceci

: 
use bytes ();                      # pour $bytes::hint_bits
sub translator {
    if ($^H & $bytes::hint_bits) {
        return bytes_translator(@_);
    }
    else {
        return utf8_translator(@_);
    }
}

Voir « ALIAS PERSONNALISÉS » ci-dessus pour les restrictions sur CHARNAME
