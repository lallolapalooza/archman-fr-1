DESCRIPTIO

N

Les appels système chmod() et fchmod() modifient les bits de mode d'un fichier. (Le mode du fichier se compose des bits de permission du fichier plus les bits set-user-ID, set-group-ID et sticky.) Ces appels système ne diffèrent que par la manière dont le fichier est spécifié

:
•
chmod() modifie le mode du fichier spécifié dont le chemin d'accès est donné dans path, qui est déréférencé s'il s'agit d'un lien
symbolique.
•
fchmod() modifie le mode du fichier auquel fait référence le descripteur de fichier ouvert fd
.

Le nouveau mode de fichier est spécifié dans mode, qui est un masque de bits créé en combinant par OU logique zéro ou plusieurs des éléments suivants

:
S_ISUID
(04000)

2))

(02000)

2))

L'UID effectif du processus appelant doit correspondre au propriétaire du fichier, ou le processus doit être privilégié (sous Linux : il doit posséder la capacité CAP_FOWNER)

.

Si le processus appelant n'est pas privilégié (sous Linux : ne possède pas la capacité CAP_FSETID), et que le groupe du fichier ne correspond ni au GID effectif du processus ni à l'un de ses groupes supplémentaires, le bit S_ISGID sera désactivé, mais cela ne provoquera pas le retour d'une

erreur.

Par mesure de sécurité, selon le système de fichiers, les bits d'exécution set-user-ID et set-group-ID peuvent être désactivés si un fichier est écrit. (Sous Linux, cela se produit si le processus d'écriture ne possède pas la capacité CAP_FSETID.) Sur certains systèmes de fichiers, seul le superutilisateur peut définir le bit sticky, qui peut avoir une signification particulière. Pour le bit sticky, et pour les bits set-user-ID et set-group-ID sur les répertoires, voir inode(

7).

Sur les systèmes de fichiers NFS, la restriction des permissions influencera immédiatement les fichiers déjà ouverts, car le contrôle d'accès est effectué sur le serveur, mais les fichiers ouverts sont maintenus par le client. L'élargissement des permissions peut être retardé pour d'autres clients si la mise en cache des attributs est activée sur

ceux-ci.

fchmodat(

)

L'appel système fchmodat() fonctionne exactement de la même manière que chmod(), à l'exception des différences décrites

ici.

Si path est relatif, alors il est interprété par rapport au répertoire auquel fait référence le descripteur de fichier dirfd (plutôt que par rapport au répertoire de travail courant du processus appelant, comme le fait chmod() pour un chemin d'accès relatif)

.

Si path est relatif et dirfd est la valeur spéciale AT_FDCWD, alors path est interprété par rapport au répertoire de travail courant du processus appelant (comme chmod())

.

Si path est absolu, alors dirfd est

ignoré.

flags peut être 0, ou inclure les drapeaux suivants
