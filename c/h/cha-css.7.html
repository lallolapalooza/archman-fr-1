CSS dans Chawan

Ce document décrit les fonctionnalités CSS prises en charge par Chawan, ainsi que ses extensions propriétaires et ses écarts par rapport aux normes.

Si vous découvrez un écart qui n'est pas couvert par ce document, veuillez ouvrir un ticket sur https://todo.sr.ht/~bptato/chawan.

Propriétés standard

Liste des propriétés standard prises en charge, avec des notes sur les valeurs non implémentées :

  • background-color (voir color)
  • background-image (n'affiche que des emplacements réservés)
  • border-collapse
  • border-*-style, border-*-color, border-*-width (mais voir les bordures)
  • border-spacing
  • bottom
  • box-sizing
  • caption-side
  • clear
  • color (valeurs hexadécimales et fonctions rgb, rgba, hsl, hsla)
  • content (chaîne, (no-)open/close-quote, counter())
  • counter-increment
  • counter-reset
  • counter-set
  • display (block, inline-block, list-item, table, table-*, flex, inline-flex, flow-root)
  • flex-basis (mais content non pris en charge)
  • flex-direction
  • flex-grow
  • flex-shrink
  • flex-wrap
  • float

  • font-style (oblique interprété comme italic)
  • font-weight (les propriétés numériques > 500 sont interprétées comme gras, les autres comme régulier)
  • height
  • left

  • list-style-type (mais pas de styles de liste personnalisés)

Raccourcis :

  • all
  • margin
  • padding
  • border, border-style, border-color, border-width (mais voir les bordures)
  • background (uniquement color et url ; les autres composants sont ignorés)
  • list-style (list-style-image est ignoré)
  • flex
  • flex-flow
  • overflow

Les variables (la fonction var() ) sont entièrement prises en charge.

Les valeurs de type <length> ou <color> prennent entièrement en charge les expressions calc() .

Sélecteurs

Tous les types de sélecteurs de CSS 2.1 sont pris en charge, à l'exception des espaces de noms.

Les pseudo-classes standard suivantes sont prises en charge : :first-child, :last-child, :only-child, :hover, :root, :nth-child(), :nth-last-child(), :checked, :focus, :is(), :not(), :where(), :lang(), :link, :target, :disabled.

:visited est analysé, mais pour l'instant il n'est pas mis en correspondance.

:defined, :host, et :host() sont mis en correspondance pour la compatibilité ; cependant, les éléments personnalisés et le DOM fantôme ne sont pas encore pris en charge.

Les pseudo-éléments standard ::before, ::after, et ::marker sont pris en charge. ::backdrop est analysé pour la compatibilité, mais n'est pas encore pris en charge.

Règles @

Les règles suivantes commençant par un signe @ sont prises en charge.

@media

Les fonctionnalités média grid, hover, prefers-color-scheme, scripting, width, et height sont entièrement prises en charge.

Les fonctionnalités color, color-index, et monochrome sont prises en charge, mais ne prennent en compte que le nombre de couleurs de texte prises en charge (ce qui peut différer du nombre de couleurs dans les images Sixel/Kitty).

@import

L'importation vers des couches est prise en charge.

@import combiné avec des requêtes média n'est pas encore pris en charge.

@layer

@layer est entièrement pris en charge. (Je crois.)

Extensions propriétaires

  • text-align accepte les valeurs -cha-center, -cha-left, et -cha-right pour prendre en charge les éléments HTML <center>, <div align=left> et <div align=right> . (Analogue à -moz-center etc.)
  • Les propriétés avec une valeur <color> acceptent la fonction -cha-ansi(), qui correspond aux couleurs spécifiques au terminal (« ANSI »). La fonction prend l'un des éléments suivants :
  • Un entier sur 8 bits, indiquant une valeur de couleur telle que définie par la fonctionnalité de couleur indexée de XTerm.
  • L'une des chaînes « black », « red », « green », « yellow », « blue », « magenta », « cyan », « white » pour une couleur ANSI, éventuellement préfixée par la chaîne « bright- » pour indiquer une valeur de couleur 16 aixterm.
  • text-decoration accepte le mot-clé -cha-reverse, qui définit le paramètre vidéo inversée sur le texte. (Ceci est utilisé par la feuille de style UA pour mettre en évidence le texte dans les balises <code> .)
  • text-transform accepte le mot-clé -cha-half-width, qui a l'effet opposé à full-width.

Cela peut être utilisé dans les feuilles de style utilisateur pour compresser le texte ruby distrayant : rt{text-transform: -cha-half-width}. Les caractères sans équivalents en demi-largeur sont laissés intacts, sauf que le hiragana est traité comme du katakana.

  • Les propriétés -cha-colspan et -cha-rowspan ont le même effet que les attributs colspan et rowspan sur les tableaux.
  • Les pseudo-classes :-cha-first-node et :-cha-last-node s'appliquent aux éléments qui n'ont aucun nœud frère précédent/suivant qui soit un nœud élément ou un nœud texte avec un contenu non vide. (Modélisé d'après :-moz-first-node et :-moz-last-node.)
  • Si buffer.mark-links est défini, le pseudo-élément ::-cha-link-marker sera généré sur tous les éléments d'ancrage.
  • En mode d'indices (par défaut, la touche f ), les marqueurs sont implémentés en générant ::-cha-link-hint sur tous les éléments applicables. Vous pouvez donc changer l'arrière-plan du marqueur dans votre user-style cha-css(7) — Chawan — Arch Linux

    7 -- Chawan CSS Extensions

    CSS in Chawan

    Chawan extends CSS to better suit the model of displaying web content on a cell-based terminal. These extensions are non-standard and subject to change.

    Some CSS properties are implemented by modifying the content of the cell, while others are implemented by modifying the cell itself. The following properties are currently implemented:

    background
    Sets the background color of the cell. Colors are specified using standard CSS color formats. The transparency of colors is not supported.
    border
    Sets the border of the cell. See Borders for details.
    border-collapse
    Supported only for tables. See Borders for details.
    border-spacing
    Supported only for tables. See Borders for details.
    box-sizing
    Supported only for border-box. See Borders for details.
    color
    Sets the foreground color of the cell. See Color correction.
    display
    Supported values are block, inline, inline-block, inline-flex, list-item, and none.
    height
    See Sizing and positioning.
    margin
    See Sizing and positioning.
    overflow
    See Scroll bars.
    padding
    See Sizing and positioning.
    position
    Supported values are static, relative, absolute, fixed, and sticky. See Sizing and positioning and position: fixed, position: sticky.
    width
    See Sizing and positioning.

    Custom selectors

    The following custom pseudo-classes and pseudo-elements are supported:

    ::-cha-link-hint
    This pseudo-element represents the background of a link hint. It can be styled in the config.toml file (see the [buffer] section in config.toml):
    ::-cha-link-hint { background: gainsboro }
    •
    The -cha-content-type media feature can be used to filter documents for their content type. For example, you can add
    @media (-cha-content-type: "text/markdown") { body { width: 80ch } }

    to your user-style to set the body width of all markdown documents to 80 characters. (The string is matched case-insensitively.)

    Rendering quirks

    These are willful violations of the standard, usually made to better fit the display model inherent to projecting the web to a cell-based screen.

    User agent style sheet

    The user agent style sheet is a combination of the styles suggested by the HTML standard and a CSS port of w3m’s rendering. In general, faithfulness to w3m is preferred over the standard’s suggestions, unless w3m’s rendering breaks on existing websites.

    Link colors differ depending on the terminal’s color scheme.

    Sizing and positioning

    Layout is performed on a finite canvas of coordinates represented by a 32-bit fixed-point number with 6 bits of precision. After layout, these positions are divided by the cell width and/or height, with the fractional part truncated. (This is subject to change.)

    In case of Kitty images, the fractional part is preserved, and is used as an in-cell offset.

    The lengths 1em and 1ch compute to the cell height and cell width respectively.

    In outer inline boxes (inline-block, inline-flex) and list-item boxes, margins and padding that are smaller than one cell (on the respective axis) are ignored. This does not apply to blockified inline boxes.

    When calculating clip boxes (overflow: hidden or clip), the clip box’s offset is floored, and its size is ceiled to the nearest cell’s boundaries. This means that “width: 1px; overflow: hidden” will still display the first character of a text box.

    Scroll bars

    Chawan does not have scroll bars, as they would complicate on-page navigation and would not work in dump mode. Instead, the “overflow-x/y” properties are handled as follows.

    1.
    If overflow is auto or scroll, and the intrinsic minimum size of the box is greater than its specified size, then the former overrides the latter.
    2.
    Content that spills out of a scroll container on the X axis is displayed, while content that spills out of a scroll container on the Y axis is clipped.

    position: fixed, position: sticky

    To keep the document model static, these do not change their position based on the viewport’s scroll status. Instead:

    • position: sticky is treated as position: static, except it also behaves as an absolute position container.
    • position: fixed is placed at the bottom of the document.

    Right now, position: fixed is always positioned at the bottom of the root element’s margin box. This breaks on pages that overflow it (e.g. by setting height: 100% on the root element), so it will be moved to the bottom of its overflow box in the future.

    Color correction

    Some authors only specify one of the foreground or the background color, assuming a black-on-white canvas. The display.minimum-contrast option adjusts the foreground color so that text remains readable even if the terminal background does not match this expectation. (The exact algorithm is unspecified and subject to change.)

    To avoid breaking spoiler mechanisms that rely on “black on black” text, color correction is not invoked on cells that have an RGB color (typically specified by the author.)

    Borders

    CSS borders are difficult to accurately display on a cell-based display. So while the functionality exists, it has some limitations:

    • On tables, borders are always collapsed, even when border-collapse is set to separate.
    • With border-collapse: separate, the spacing between cells is the largest of border-spacing times two and the cell width.
    • border-*-width is interpreted as a binary value: a width of 0 results in no border, while any other width results in a border of a single type. If the width is smaller than one cell (in the respective direction), the rest is subtracted from the margin (if there is any margin).
    • box-sizing: border-box actually sets the padding box size, so that borders rounded up to the cell size do not accidentally take all space from the actual content. (That in turn would cause problems if a child box set overflow: hidden, etc.)
