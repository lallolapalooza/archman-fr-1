NOM

Chart::Manual::Workflows - différentes manières de créer des graphiques

APERÇU

Quatre des cinq étapes principales pour créer une image de graphique sont fixes dans leur ordre. Vous devez d'abord charger le module, deuxièmement créer l'objet. Après cela, vous
pouvez modifier certaines propriétés. Et toujours comme dernière étape, vous créez l'image, que la sortie soit vers STDOUT ou dans un fichier.

La seule flexibilité réside dans la manière dont vous préférez fournir les données. Et ici, vous avez trois options. Le plus souvent, vous ajoutez un jeu de données à la fois, ce qui pourrait également être compris comme une ligne du tableau de données complet. La deuxième option consiste à construire le tableau colonne par colonne. Troisièmement, vous pouvez laisser tomber le tableau complet en une seule fois, soit par référence à une structure de données, soit à un fichier contenant les données. La dernière option est fermée si vous avez déjà fourni des données à l'objet. Il n'est pas conseillé de réutiliser un objet de graphique pour la création d'images supplémentaires en dehors des projets d'art moderne.

ÉTAPE

La plupart des étapes sont déjà expliquées ailleurs et l'APERÇU y renvoie. Les éléments manquants sont présentés ici.

use Chart

Comme avec tout autre module, vous devez :

use Chart::[Type];

Type étant un espace réservé pour le nom d'un type de graphique, qui sont : Bars, Composite, Direction, ErrorBars, HorizontalBars, Lines, LinesPoints, Mountain, Pareto, Pie, Points, Split, StackedBars. Pour en savoir plus, lisez Chart::Manual::Types.

Alternativement, écrivez pour charger tous les types de graphiques en une fois avec

use Chart;

Les deux n'importent aucun symbole dans votre espace de noms mais chargent Carp et GD.

drop data

Toutes les méthodes listées dans la dernière section, qui créent l'image finale, prennent en deuxième argument optionnel les données. Ces données peuvent être livrées soit sous forme de référence à un tableau de tableaux :

my $data = [ [ 1, 4, 3 ... ], # jeu de données 0
             [ 5, 8, 2 ... ], # jeu de données 1
             ...
];
$graph->png( 'file.png', $data );

soit sous forme de fichier. L'argument doit alors être un nom de fichier ou un descripteur de fichier (ancienne école comme dans "FILE" ou moderne comme dans $FH). Alternativement, utilisez la méthode add_datafile.

data files

Ce sont des fichiers texte nommés arbitrairement contenant une ou plusieurs lignes de nombres, qui doivent être séparés par des espaces ou des tabulations (\t) (mélange autorisé). Les commentaires de style Perl ou les lignes vides seront ignorés, mais les lignes contenant un nombre différent de chiffres causeront des problèmes.

create image

Actuellement, nous ne prenons en charge que les images au format PNG et JPEG. Les méthodes pour les créer sont nommées de manière simple : ->png et ->jpeg. Les deux prennent les mêmes arguments et produisent des fichiers image. Pour les scripts shell ou la programmation web, vous avez besoin du binaire de l'image, que vous obtenez avec : ->cgi_png ou ->cgi_jpeg. Certains utilisateurs pourraient même vouloir l'objet GD pour un traitement ultérieur par votre programme Perl. Dans ce cas, veuillez utiliser : ->scalar_png ou ->scalar_jpeg.

Après avoir créé un graphique à des fins web, vous pourriez également vouloir utiliser imagemap_dump.
