STRINGS

La directive SAY permet au script d'envoyer des chaînes à l'utilisateur sur le terminal via la sortie d'erreur standard. Si chat est exécuté par pppd, et que pppd tourne en tant que démon (détaché de son terminal de contrôle), la sortie d'erreur standard sera normalement redirigée vers le fichier /etc/ppp/connect-errors

REPORT

STRINGS

Une chaîne de rapport est similaire à la chaîne ABORT. La différence est que les chaînes, et tous les caractères jusqu'au prochain caractère de contrôle tel qu'un retour à la ligne, sont écrits dans le fichier de

rapport.

Les chaînes de rapport peuvent être utilisées pour isoler le débit de transmission de la chaîne de connexion du modem et renvoyer la valeur à l'utilisateur de chat. L'analyse de la logique des chaînes de rapport se fait en conjonction avec les autres traitements de chaînes comme la recherche de la chaîne attendue. L'utilisation de la même chaîne pour une séquence de rapport et d'abandon n'est probablement pas très utile, cependant, c'est

possible.

Les chaînes de rapport ne changent pas le code de fin du

programme.

Ces chaînes "de rapport" peuvent être spécifiées dans le script en utilisant la séquence REPORT. Elle est écrite dans le script comme dans l'exemple suivant

:
REPORT CONNECT ABORT B
USY '' ATDT5551212 CO
NNECT '' ogin: account

Cette séquence n'attend rien ; puis envoie la chaîne ATDT5551212 pour composer le numéro de téléphone. La chaîne attendue est CONNECT. Si la chaîne CONNECT est reçue, le reste du script est exécuté. De plus, le programme écrira dans le fichier

d'attente la chaîne "CONNECT" plus tout caract
ère qui la suit tel que le débit de connexion.

Les options echo contrôlent si la sortie du modem est répétée vers stderr. Cette option peut être définie avec l' option -e, mais elle peut aussi être contrôlée par le mot-clé ECHO. La paire "expect-send" ECHO ON active la répétition, et ECHO OFF la désactive. Avec ce mot-clé, vous pouvez sélectionner quelles parties de la conversation doivent être visibles. HANGU

P

Les options HANGUP contrôlent si une déconnexion du modem doit être considérée comme une erreur ou non. Cette option est utile dans les scripts pour composer vers des systèmes qui vont se déconnecter et rappeler votre système. Les options HANGUP peuvent être ON ou OFF.
Quand HANGUP est défini sur OFF et que le modem se déconnecte (par ex., après le premier stade de connexion à un système de rappel), chat continuera d'exécuter le script (par ex., en attendant l'appel entrant et l'invite de connexion du second stade). Dès que l'appel entrant est connecté, vous devriez utiliser la directive HANGUP ON pour réinstaller le comportement normal des signaux de déconnexion. Voici un exemple de script (simple)

:
ABORT 'BUSY'
'' ATZ
OK\r\n ATD1234567
\r\n \c
CONNECT \c
'Callback login:' call_back_ID
HANGUP OFF
ABORT "Bad Login"
'Callback Password:' Call_back_password
TIMEOUT 120
CONNECT \c
HANGUP ON
ABORT "NO CARRIER"

SENDING

EOT

La chaîne de réponse spéciale EOT indique que le programme chat doit envoyer un caractère EOT au distant. C'est normalement la séquence de caractères de fin de fichier. Un caractère de retour n'est pas envoyé après le EOT. La séquence EOT peut être intégrée dans la chaîne d'envoi en utilisant la séquence ^D

.

GENERATING

BREAK

La chaîne de réponse spéciale BREAK causera l'envoi d'une condition de break. Le break est un signal spécial sur l'émetteur. Le traitement normal sur le récepteur est de changer le débit de transmission. Il peut être utilisé pour parcourir les débits de transmission disponibles sur le distant jusqu'à ce que vous puissiez recevoir une invite de connexion valide. La séquence break peut être intégrée dans la chaîne d'envoi en utilisant la séquence \K

.
