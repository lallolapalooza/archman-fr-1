DESCRIPTIO

N

La fonction chmod() doit changer S_ISUID, S_ISGID, S_ISVTX et les bits de permission du fichier du fichier nommé par le chemin d'accès pointé par l'argument path vers les bits correspondants dans l'argument mode. L'application doit s'assurer que l'identifiant utilisateur effectif du processus correspond au propriétaire du fichier ou que le processus dispose des privilèges appropriés afin de le

faire.

S_ISUID, S_ISGID, S_ISVTX et les bits de permission du fichier sont décrits dans <sys/stat.h>

.

Si le processus appelant ne dispose pas des privilèges appropriés, et si l'identifiant de groupe du fichier ne correspond pas à l'identifiant de groupe effectif ni à aucun des identifiants de groupe supplémentaires, et si le fichier est un fichier ordinaire, le bit S_ISGID (définir l'identifiant de groupe à l'exécution) dans le mode du fichier doit être effacé lors du retour réussi de chmod

().

Des restrictions supplémentaires définies par l'implémentation peuvent faire que les bits S_ISUID et S_ISGID dans mode soient

ignorés.

À la fin réussie, chmod() doit marquer pour mise à jour l'horodatage du dernier changement d'état du

fichier.

La fonction fchmodat() doit être équivalente à la fonction chmod() sauf dans le cas où path spécifie un chemin d'accès relatif. Dans ce cas, le fichier à modifier est déterminé par rapport au répertoire associé au descripteur de fichier fd au lieu du répertoire de travail courant. Si le mode d'accès de la description de fichier ouverte associée au descripteur de fichier n'est pas O_SEARCH, la fonction doit vérifier si les recherches dans les répertoires sont autorisées en utilisant les permissions actuelles du répertoire sous-jacent au descripteur de fichier. Si le mode d'accès est O_SEARCH, la fonction n'effectue pas la

vérification.

chmod, fchmod, fchmodat — modifier les permissions d'un fichier

PROLOG

Ce document décrit la syntaxe des commandes et des fonctions des utilitaires du standard POSIX tels qu'ils apparaissent dans les utilitaires man-pages. Les traductions peuvent différer de celles du système d'exploitation ; consultez les pages de manuel spécifiques à votre système d'exploitation pour les détails précis de votre implémentation.

NAME

chmod, fchmod, fchmodat — modifier les permissions d'un fichier

SYNOPSIS

    #include <sys/stat.h>

    int chmod(const char *path, mode_t mode);
    int fchmod(int fd, mode_t mode);
    int fchmodat(int dirfd, const char *pathname, mode_t mode, int flags);

DESCRIPTION

Ces fonctions modifient les permissions d'accès d'un fichier.

La fonction chmod() change les permissions du fichier dont le nom est indiqué par path pour correspondre aux bits de mode spécifiés par mode. Si le fichier est un lien symbolique, le comportement est indéfini.

La fonction fchmod() change les permissions du fichier associé au descripteur de fichier ouvert fd pour correspondre aux bits de mode spécifiés par mode.

La fonction fchmodat() est identique à chmod() sauf pour la gestion des liens symboliques et les cas où pathname n'est pas un chemin absolu. Si pathname n'est pas un chemin absolu, le chemin est résolu par rapport au répertoire pointé par le descripteur de fichier dirfd (obtenu par exemple avec open() sur un répertoire sans le flag O_PATH). Si dirfd est le descripteur de fichier spécial AT_FDCWD, alors pathname est résolu par rapport au répertoire de travail courant, comme pour chmod().

Les bits de permissions sont définis dans <sys/stat.h>.

Pour chmod() et fchmod(), le mode est construit à partir de la OR bit à bit des constantes suivantes :

S_IRWXU
Lecture, écriture, exécution pour le propriétaire.
S_IRUSR
Lecture pour le propriétaire.
S_IWUSR
Écriture pour le propriétaire.
S_IXUSR
Exécution pour le propriétaire.
S_IRWXG
Lecture, écriture, exécution pour le groupe.
S_IRGRP
Lecture pour le groupe.
S_IWGRP
Écriture pour le groupe.
S_IXGRP
Exécution pour le groupe.
S_IRWXO
Lecture, écriture, exécution pour les autres.
S_IROTH
Lecture pour les autres.
S_IWOTH
Écriture pour les autres.
S_IXOTH
Exécution pour les autres.

Les bits de mode spéciaux sont :

S_ISUID
Définir l'ID utilisateur lors de l'exécution.
S_ISGID
Définir l'ID groupe lors de l'exécution.
S_ISVTX
Sticky bit.

Lorsque les bits S_ISUID et S_ISGID sont définis, ils peuvent être interprétés différemment en fonction des permissions d'exécution. Voir la section RATIONALE.

Dans le cas de fchmodat(), le paramètre flags peut être 0 ou AT_SYMLINK_NOFOLLOW.

Si flags vaut 0, le comportement est le même que pour chmod(). Si flags contient AT_SYMLINK_NOFOLLOW, alors si pathname désigne un lien symbolique, le lien symbolique est affecté et le fichier visé par le lien n'est pas affecté.

RETURN VALUE

En cas de succès, ces fonctions retournent 0. En cas d'échec, elles retournent -1 et errno est défini pour indiquer l'erreur.

ERRORS

Les erreurs suivantes peuvent être définies pour ces fonctions :

EACCES
Le processus n'a pas la permission d'écrire dans le répertoire contenant le fichier.

EBADF
fd n'est pas un descripteur de fichier valide.

EFAULT
path pointe en dehors de l'espace d'adressage accessible.

EINTR
Une interruption non masquée s'est produite pendant l'opération.

EINVAL
Une valeur non valide a été spécifiée dans mode ou flags.

ELOOP
Trop de liens symboliques ont été rencontrés lors de la résolution de path.

EMLINK
Le lien existe déjà.

ENOENT
Le fichier spécifié par path n'existe pas, ou pathname est un chemin vide ou dirfd est invalide.

ENOTDIR
Un composant du chemin path n'est pas un répertoire et pathname n'est pas un chemin absolu, ou dirfd est un descripteur de fichier faisant référence à un fichier normal et pathname n'est pas un chemin absolu.

ENOSPC
Le système de fichiers est plein, et les bits de permissions ne peuvent pas être modifiés.

EROFS
Le fichier est sur un système de fichiers en lecture seule.

ESRCH
dirfd est introuvable.

ETXTBSY
Le fichier est ouvert pour exécution par au moins un processus.

acesso (pour fchmodat seulement)
dirfd était un descripteur de fichier invalide.

EXAMPLES

Définir les permissions d'un fichier :

#include <sys/types.h>
#include <sys/stat.h>

int status;
struct stat buffer;
...

status = stat("/home/cnd/mod1", &buffer);

APPLICATION USAGE

Pour s'assurer que les bits S_ISUID et S_ISGID sont définis, une application nécessitant cela devrait utiliser stat() après un appel réussi à chmod() pour vérifier cela.

Tout descripteur de fichier actuellement ouvert par un processus sur le fichier pourrait devenir invalide si le mode du fichier est modifié d'une manière qui refuserait l'accès à ce processus. Une situation où cela pourrait se produire est sur un système de fichiers sans état (stateless). Ce comportement ne se produira pas dans un environnement conforme.

RATIONALE

Ce volume de POSIX.1-2017 spécifie que le bit S_ISGID est effacé par chmod() sur un fichier régulier sous certaines conditions. Ceci est spécifié dans l'hypothèse que les fichiers réguliers peuvent être exécutés, et que le système devrait empêcher les utilisateurs de créer des fichiers exécutables setgid() qui s'exécuteraient avec des privilèges que l'appelant ne possède pas. Sur les implémentations qui supportent l'exécution d'autres types de fichiers, le bit S_ISGID devrait être effacé pour ces types de fichiers dans les mêmes circonstances.

Les implémentations qui utilisent le bit S_ISUID pour indiquer une autre fonction (par exemple, le verrouillage d'enregistrement obligatoire) sur les fichiers non exécutables n'ont pas besoin d'effacer ce bit lors de l'écriture. Elles devraient effacer le bit pour les fichiers exécutables et dans tous les autres cas où le bit accorderait des pouvoirs spéciaux aux processus qui modifient le contenu du fichier. Des commentaires similaires s'appliquent au bit S_ISGID.

Le but de la fonction fchmodat() est de permettre de modifier le mode des fichiers dans des répertoires autres que le répertoire de travail courant sans s'exposer à des conditions de concurrence (race conditions). N'importe quelle partie du chemin d'un fichier pourrait être modifiée en parallèle à un appel à chmod(), résultant en un comportement indéfini. En ouvrant un descripteur de fichier pour le répertoire cible et en utilisant la fonction fchmodat(), il peut être garanti que le fichier modifié est situé par rapport au répertoire souhaité. Certaines implémentations pourraient permettre de modifier le mode des liens symboliques. Ceci n'est pas supporté par les interfaces de la spécification POSIX. Les systèmes qui ont un tel support fournissent une interface nommée lchmod(). Pour supporter de telles implémentations, fchmodat() a un paramètre flags.
