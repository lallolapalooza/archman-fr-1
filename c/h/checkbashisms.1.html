CHECKBASHISMS(1) Manuel des commandes générales CHECKBASHISMS(1)

NOM

checkbashisms - vérifie les bashismes dans les scripts /bin/sh

SYNTAXE

checkbashisms script ...
checkbashisms --help|--version

DESCRIPTION

checkbashisms, basé sur l'une des vérifications du système lintian, effectue des vérifications de base sur les scripts shell /bin/sh pour la présence possible de bashismes. Il prend les noms des scripts shell en ligne de commande et affiche des avertissements si des bashismes potentiels sont détectés.

Notez que la définition d'un bashisme dans ce contexte équivaut grossièrement à « une fonctionnalité shell qui n'est pas obligatoirement prise en charge par POSIX » ; cela signifie que certains problèmes signalés peuvent être autorisés dans des sections optionnelles de POSIX, telles que XSI ou User Portability.

Dans les cas où POSIX et la Politique Debian divergent, checkbashisms autorise par défaut les extensions permises par la Politique mais peut également fournir des options pour une vérification plus stricte.

OPTIONS

--help, -h
Affiche un résumé des options.
--newline, -n
Vérifie l'utilisation de « echo -n » (non POSIX mais requis par la Politique Debian 10.4.).
--posix, -p
Vérifie les problèmes qui ne sont pas POSIX mais qui doivent être pris en charge par la Politique Debian 10.4 (implique -n).
--force, -f
Force la vérification de chaque script, même s'il ne le serait normalement pas (par exemple, s'il a un shebang bash ou non POSIX, ou s'il semble être un wrapper shell).
--lint, -l
Agit comme un linter, pour l'intégration dans un éditeur de texte. Les bashismes possibles seront affichés sur stdout, comme suit :
{nom_fichier}:{num_ligne}:1: avertissement : bashisme possible ; {explication}
--extra, -x
Met en évidence les lignes qui, bien qu'elles ne contiennent pas de bashismes, peuvent être utiles pour déterminer si un problème particulier est un faux positif qui peut être ignoré. Par exemple, l'utilisation de « $BASH_ENV » peut être précédée d'une vérification pour voir si « $BASH » est défini.
--early-fail, -e
Sortir immédiatement après avoir vu la première erreur.
--version, -v
Affiche les informations de version et de copyright.

VALEURS DE RETOUR

La valeur de retour sera 0 si aucun bashisme potentiel ou autre problème n'a été détecté. Sinon, ce sera la somme des valeurs d'erreur suivantes :

1
Un bashisme potentiel a été détecté.
2
Un fichier a été ignoré pour une raison quelconque, par exemple parce qu'il n'était pas lisible ou introuvable. Le message d'avertissement donnera des détails.
4
Aucun bashisme n'a été détecté dans un script bash.
