NOTES

Propriété des nouveaux fichiers

Lorsqu'un nouveau fichier est créé (par exemple, par open(2) ou mkdir(2)), son propriétaire est défini sur l'ID utilisateur du système de fichiers du processus créateur. Le groupe du fichier dépend d'un ensemble de facteurs, y compris le type de système de fichiers, les options utilisées pour monter le système de fichiers et si le bit de mode set-group-ID est activé sur le répertoire parent. Si le système de fichiers prend en charge les options de montage -o grpid (ou, de manière synonyme, -o bsdgroups) et -o nogrpid (ou, de manière synonyme, -o sysvgroups), alors les règles sont les suivantes :

•
Si le système de fichiers est monté avec -o grpid, alors le groupe d'un nouveau fichier est défini sur celui du répertoire parent.
•
Si le système de fichiers est monté avec -o nogrpid et que le bit set-group-ID est désactivé sur le répertoire parent, alors le groupe d'un nouveau fichier est défini sur le GID du système de fichiers du processus.
•
Si le système de fichiers est monté avec -o nogrpid et que le bit set-group-ID est activé sur le répertoire parent, alors le groupe d'un nouveau fichier est défini sur celui du répertoire parent.

Depuis Linux 4.12, les options de montage -o grpid et -o nogrpid sont prises en charge par ext2, ext3, ext4 et XFS. Les systèmes de fichiers qui ne prennent pas en charge ces options de montage suivent les règles de -o nogrpid.

Notes glibc

Sur les anciens noyaux où fchownat() n'est pas disponible, la fonction wrapper glibc se rabat sur l'utilisation de chown() et lchown(). Lorsque path est relatif, glibc construit un nom de chemin basé sur le lien symbolique dans /proc/self/fd qui correspond à l'argument dirfd.

NFS

Les sémantiques de chown() sont délibérément violées sur les systèmes de fichiers NFS qui ont le mappage UID activé. De plus, les sémantiques de tous les appels système qui accèdent au contenu du fichier sont violées, car chown() peut entraîner une révocation d'accès immédiate sur des fichiers déjà ouverts. La mise en cache côté client peut entraîner un délai entre le moment où la propriété a été modifiée pour autoriser l'accès à un utilisateur et le moment où le fichier peut réellement être accédé par l'utilisateur sur d'autres clients.

Détails historiques

Les appels système Linux originaux chown(), fchown() et lchown() ne prenaient en charge que les IDs utilisateur et groupe de 16 bits. Par la suite, Linux 2.4 a ajouté chown32(), fchown32() et lchown32(), prenant en charge les IDs de 32 bits. Les fonctions wrapper glibc chown(), fchown() et lchown() gèrent de manière transparente les variations entre les versions du noyau.

Avant Linux 2.1.81 (sauf 2.1.46), chown() ne suivait pas les liens symboliques. Depuis Linux 2.1.81, chown() suit les liens symboliques, et il existe un nouvel appel système lchown() qui ne suit pas les liens symboliques. Depuis Linux 2.1.86, ce nouvel appel (qui a les mêmes sémantiques que l'ancien chown()) a le même numéro de syscall, et chown() a le numéro nouvellement introduit.

EXEMPLES

Le programme suivant modifie la propriété du fichier nommé dans son deuxième argument de ligne de commande à la valeur spécifiée dans son premier argument de ligne de commande. Le nouveau propriétaire peut être spécifié soit comme un ID utilisateur numérique, soit comme un nom d'utilisateur (qui est converti en ID utilisateur en utilisant getpwnam(3) pour effectuer une recherche dans le fichier système des mots de passe).

Source du programme

#include <pwd.h>
#include <stdio.h>
#include <stdlib.h>
#include <sys/types.h>
#include <unistd.h>
int
main(int argc, char *argv[])
{
    char           *endptr;
    uid_t          uid;
    struct passwd  *pwd;
    if (argc != 3 || argv[1][0] == '\0') {
        fprintf(stderr, "%s <propriétaire> <fichier>\n", argv[0]);
        exit(EXIT_FAILURE);
    }
    uid = strtol(argv[1], &endptr, 10);  /* Permettre une chaîne numérique */
    if (*endptr != '\0') {         /* Ce n'était pas une chaîne purement numérique */
        pwd = getpwnam(argv[1]);   /* Essayer d'obtenir l'UID pour le nom d'utilisateur */
        if (pwd == NULL) {
            perror("getpwnam");
            exit(EXIT_FAILURE);
        }
        uid = pwd->pw_uid;
    }
    if (chown(argv[2], uid, -1) == -1) {
        perror("chown");
        exit(EXIT_FAILURE);
    }
    exit(EXIT_SUCCESS);
}
