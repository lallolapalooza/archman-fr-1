!>
!> CHEEVR calcule les valeurs propres sélectionnées et, optionnellement, les vecteurs
!> propres d'une matrice hermitienne complexe A. Les valeurs propres et les vecteurs
!> propres peuvent être sélectionnés en spécifiant soit un intervalle de valeurs, soit un
!> intervalle d'indices pour les valeurs propres souhaitées. Des invocations avec des
!> choix différents pour ces paramètres peuvent entraîner le calcul de valeurs propres
!> et/ou de vecteurs propres légèrement différents pour la même matrice. La raison de
!> ce comportement est qu'il existe une variété d'algorithmes (chacun fonctionnant
!> au mieux pour un ensemble particulier d'options) et que CHEEVR tente de sélectionner
!> le meilleur en fonction des divers paramètres. Dans tous les cas, les valeurs calculées
!> sont précises dans les limites de l'arithmétique en virgule flottante à précision finie.
!>
!> CHEEVR réduit d'abord la matrice A à une forme tridiagonale T par un appel
!> à CHETRD. Ensuite, chaque fois que c'est possible, CHEEVR appelle CSTEMR pour calculer
!> le spectre propre en utilisant des représentations robustes relatives (Relatively Robust
!> Representations). CSTEMR calcule les valeurs propres par l'algorithme dqds, tandis que
!> les vecteurs propres orthogonaux sont calculés à partir de diverses représentations
!> L D L^T (également connues sous le nom de représentations robustes relatives).
!> L'orthogonalisation de Gram-Schmidt est évitée autant que possible. Plus précisément,
!> les diverses étapes de l'algorithme sont les suivantes.
!>
!> Pour chaque bloc (sous-matrice) non réduit de T,
!>    (a) Calculer T - sigma I  = L D L^T, de sorte que L et D
!>        définissent toutes les valeurs propres souhaitées avec une grande précision relative.
!>        Cela signifie que de petites variations relatives dans les entrées de D et L
!>        n'entraînent que de petites variations relatives dans les valeurs propres et
!>        les vecteurs propres. La représentation standard (non factorisée) de la
!>        matrice tridiagonale T n'a généralement pas cette propriété.
!>    (b) Calculer les valeurs propres avec une précision appropriée.
!>        Si les vecteurs propres sont souhaités, l'algorithme n'atteint la pleine
!>        précision des valeurs propres calculées qu'à l'instant précédant
!>        le calcul des vecteurs correspondants, voir les étapes c) et d).
!>    (c) Pour chaque groupe de valeurs propres proches, sélectionner un nouveau
!>        décalage (shift) proche du groupe, trouver une nouvelle factorisation, et affiner
!>        les valeurs propres décalées avec une précision appropriée.
!>    (d) Pour chaque valeur propre avec une séparation relative suffisante, calculer
!>        le vecteur propre correspondant en formant une factorisation tordue révélatrice de rang.
!>        Retourner à (c) pour tous les groupes restants.
!>
!> La précision souhaitée de la sortie peut être spécifiée par le paramètre
!> d'entrée ABSTOL.
!>
!> Pour plus de détails, voir la documentation de CSTEMR et :
!> - Inderjit S. Dhillon et Beresford N. Parlett :
!>   Linear Algebra and its Applications, 387(1), pp. 1-28, août 2004.
!> - Inderjit Dhillon et Beresford Parlett : SIAM Journal on Matrix Analysis and Applications, Vol. 25,
!>   2004. Aussi LAPACK Working Note 154.
!> - Inderjit Dhillon : ,
!>   Computer Science Division Technical Report No. UCB/CSD-97-971,
!>   UC Berkeley, mai 1997.
!>
!>
!> Remarque 1 : CHEEVR appelle CSTEMR lorsque le spectre complet est demandé
!> sur les machines qui se conforment au standard de virgule flottante ieee-754.
!> CHEEVR appelle SSTEBZ et CSTEIN sur les machines non-ieee et
!> lorsque des demandes de spectre partiel sont faites.
!>
!> L'exécution normale de CSTEMR peut créer des NaN et des infinis et
!> peut donc s'interrompre en raison d'une exception de virgule flottante dans les environnements
!> qui ne gèrent pas les NaN et les infinis de la manière par défaut du standard ieee.
!
>

NAME


cheevr - Computes the eigenvalues and eigenvectors of a complex
    Hermitian matrix.


SYNOPSIS


    SUBROUTINE CHEEVR( JOBZ, RANGE, UPLO, N, A, LDA, VL, VU, IL, IU, ABSTOL,
                 M, W, Z, LDZ, ISUPPZ, WORK, LWORK, RWORK, LRWORK, IWORK,
                 LIWORK, INFO )



Function/Subroutine Documentation


CHE

!>          JOBZ = 'V':  Compute the eigenvectors of A.
!>          JOBZ = 'N':  Compute the eigenvalues only.
!>
!>          Eigenvalues are computed in the range (VL, VU] if RANGE='V',
!>          and as eigenvalues number IL through IU if RANGE='I',
!>          and as the whole set if RANGE='A'.
!>
!>          UPLO = 'U':  Upper triangle of A is stored.
!>          UPLO = 'L':  Lower triangle of A is stored.
!> 


N


!>          N is INTEGER
!>          The order of the matrix A.  N >= 0.
!> 


A


!>          A is COMPLEX array, dimension (LDA,N)
!>          On entry, the upper or lower triangular part of the Hermitian
!>          matrix A.
!> 


LDA


!>          LDA is INTEGER
!>          The leading dimension of A. LDA >= (1 + offset of most
!>          distant element of A, CDIST(i) for some i).
!> 


VL


!>          VL is REAL
!>          If RANGE='V', the lower bound of the interval to be searched
!>          for eigenvalues.
!> 


VU


!>          VU is REAL
!>          If RANGE='V', the upper bound of the interval to be searched
!>          for eigenvalues.
!> 


IL


!>          IL is INTEGER
!>          If RANGE='I', the index of the smallest eigenvalue to be
!>          returned.
!> 


IU


!>          IU is INTEGER
!>          If RANGE='I', the index of the largest eigenvalue to be
!>          returned.
!> 


ABSTOL


!>          ABSTOL is REAL
!>          The absolute error tolerance for the eigenvalues when
!>          RANGE='V'.
!>
!>          If ABSTOL <= 0, then the default value is used, and it is
!>          set to twice the machine precision times the norm of A.
!>
!>          See Demmel and Kahan, LAPACK Working Note #3 for a discussion
!>          of how ABSTOL affects the accuracy of the eigenvalues.
!>
!>          If high relative accuracy is important, set ABSTOL to
!>          SLAMCH( 'Safe minimum' ). Doing so will guarantee that
!>          eigenvalues are computed to high relative accuracy when
!>          possible in future releases. The current code does not
!>          make any guarantees about high relative accuracy, but
!>          future releases will. See J. Barlow and J. Demmel,
!>          , LAPACK Working Note #7, for a discussion
!>          of which matrices define their eigenvalues to high relative
!>          accuracy.
!> 


M


!>          M is INTEGER
!>          The total number of eigenvalues found.  0 <= M <= N.
!>          If RANGE = 'A', M = N, and if RANGE = 'I', M = IU-IL+1.
!> 


W


!>          W is REAL array, dimension (N)
!>          The first M elements contain the selected eigenvalues in
!>          ascending order.
!> 


Z


!>          Z is COMPLEX array, dimension (LDZ, max(1,M))
!>          If JOBZ = 'V', then if INFO = 0, the first M columns of Z
!>          contain the orthonormal eigenvectors of the matrix A
!>          corresponding to the selected eigenvalues, with the i-th
!>          column of Z holding the eigenvector associated with W(i).
!>          If JOBZ = 'N', then Z is not referenced.
!>          Note: the user must ensure that at least max(1,M) columns are
!>          supplied in the array Z; if RANGE = 'V', the exact value of M
!>          is not known in advance and an upper bound must be used.
!>          Supplying N columns is always safe.
!> 


LDZ


!>          LDZ is INTEGER
!>          The leading dimension of the array Z. LDZ >= 1, and if
!>          JOBZ = 'V', LDZ >= max(1,N).
!> 


ISUPPZ


!>          ISUPPZ is INTEGER array, dimension ( 2*max(1,M) )
!>          The support of the eigenvectors in Z, i.e., the indices
!>          indicating the nonzero elements in Z. The i-th eigenvector
!>          is nonzero only in elements ISUPPZ( 2*i-1 ) through
!>          ISUPPZ( 2*i ). This is an output of CSTEMR (tridiagonal
!>          matrix). The support of the eigenvectors of A is typically
!>          1:N because of the unitary transformations applied by CUNMTR.
!>          Implemented only for RANGE = 'A' or 'I' and IU - IL = N - 1
!> 


WORK


!>          WORK is COMPLEX array, dimension (MAX(1,LWORK))
!>          On exit, if INFO = 0, WORK(1) returns the optimal LWORK.
!> 


LWORK


!>          LWORK is INTEGER
!>          The length of the array WORK.
!>          If N <= 1, LWORK >= 1, else LWORK >= 2*N.
!>          For optimal efficiency, LWORK >= (NB+1)*N,
!>          where NB is the max of the blocksize for CHETRD and for
!>          CUNMTR as returned by ILAENV.
!>
!>          If LWORK = -1, then a workspace query is assumed; the routine
!>          only calculates the optimal sizes of the WORK, RWORK and
!!>          IWORK arrays, returns these values as the first entries of
!>          the WORK, RWORK and IWORK arrays, and no error message
!>          related to LWORK or LRWORK or LIWORK is issued by XERBLA.
!> 


RWORK


!>          RWORK is REAL array, dimension (MAX(1,LRWORK))
!>          On exit, if INFO = 0, RWORK(1) returns the optimal
!>          (and minimal) LRWORK.
!> 


LRWORK


!>          LRWORK is INTEGER
!>          The length of the array RWORK.
!>          If N <= 1, LRWORK >= 1, else LRWORK >= 24*N.
!>
!>          If LRWORK = -1, then a workspace query is assumed; the
!>          routine only calculates the optimal sizes of the WORK, RWORK
!>          and IWORK arrays, returns these values as the first entries
!>          of the WORK, RWORK and IWORK arrays, and no error message
!>          related to LWORK or LRWORK or LIWORK is issued by XERBLA.
!> 


IWORK


!>          IWORK is INTEGER array, dimension (MAX(1,LIWORK))
!>          On exit, if INFO = 0, IWORK(1) returns the optimal
!>          (and minimal) LIWORK.
!> 


LIWORK


!>          LIWORK is INTEGER
!>          The dimension of the array IWORK.
!>          If N <= 1, LIWORK >= 1, else LIWORK >= 10*N.
!>
!>          If LIWORK = -1, then a workspace query is assumed; the
!>          routine only calculates the optimal sizes of the WORK, RWORK
!>          and IWORK arrays, returns these values as the first entries
!>          of the WORK, RWORK and IWORK arrays, and no error message
!>          related to LWORK or LRWORK or LIWORK is issued by XERBLA.
!> 


INFO


!>          INFO is INTEGER
!>          = 0:  successful exit
!>          < 0:  if INFO = -i, the i-th argument had an illegal value
!>          > 0:  Internal error
!>
