CHA-URIMETHODMAP(5) Manuel des formats de fichiers CHA-URIMETHODMAP(5)

Support de la carte méthode URI dans Chawan

Chawan peut être utilisé pour mapper des protocoles non reconnus à des protocoles connus en utilisant le format urimethodmap.

Le cas d'utilisation principal est l'implémentation de gestionnaires pour des protocoles inconnus de Chawan via un protocole que le navigateur comprend.

Chemin de recherche

Le chemin de recherche des fichiers urimethodmap peut être remplacé en utilisant la variable de configuration external.urimethodmap.

Le chemin de recherche par défaut pour les fichiers urimethodmap est :

$HOME/.urimethodmap:$HOME/.w3m/urimethodmap:/etc/urimethodmap:/usr/local/etc/urimethodmap

Format

Le format urimethodmap est pris 1:1 de w3m, avec quelques modifications à l'interprétation des modèles.

Une tentative approximative de description formelle de ceci :

URIMethodMap-File = *URIMethodMap-ligne
URIMethodMap-Ligne = Commentaire / EntréeURIMethodMap
EntréeURIMethodMap = Protocole *ESPACEBLANC Modèle *ESPACEBLANC CR
Protocole = 1*CHAR DEUX-POINTS
Modèle = [voir ci-dessous]
Commentaire = *ESPACEBLANC CR / "#" *CHAR CR

Notez qu'un signe deux-points ASCII (:) doit être présent après le nom du protocole. Cependant, l'espace blanc peut être omis.

Exemples :

# Ceci est correct :
protocole:	/cgi-bin/interpret-protocol?%s
# Ceci est correct aussi :
protocole:/cgi-bin/interpret-protocol?%s
# Les espaces et les tabulations sont tous deux autorisés, donc ceci est également correct :
protocole:	/cgi-bin/interpret-protocol?%s
# Cependant, ceci est incorrect, car le signe deux-points est manquant :
protocole	/cgi-bin/interpret-protocol?%s

Le modèle de redirection est l'URL cible. Si la chaîne %s est contenue dans le modèle, elle sera remplacée par l'URL cible.

Pour la compatibilité avec w3m, les modèles commençant par /cgi-bin/ et file:/cgi-bin/ sont traités spécialement et la chaîne de départ est remplacée par cgi-bin:. Ainsi, par exemple, le modèle /cgi-bin/w3mdict.cgi est identique à cgi-bin:w3mdict.cgi (et il en va de même pour file:/cgi-bin/w3mdict.cgi).

Exemple :

# Les lignes suivantes sont identiques dans Chawan
protocole:	/cgi-bin/interpret-protocol?%s
protocole:	file:/cgi-bin/interpret-protocol?%s
# Note : cette dernière entrée ne fonctionne pas dans w3m.
protocole:	cgi-bin:interpret-protocol?%s

Notez cependant que les chemins absolus vers les scripts cgi NE sont PAS traités spécialement, donc par exemple file:///usr/local/libexec/w3m/cgi-bin/w3mdict.cgi ouvrira simplement w3mdict.cgi dans le visualiseur de fichiers. (Contrairement à w3m, où il pourrait exécuter w3mdict.cgi en fonction de la configuration de l'utilisateur.)

Exemples

Dans config.toml

# Définit le chemin de recherche urimethodmap par rapport au fichier
# de configuration. Ainsi, si votre fichier de configuration se trouve dans
# ~/.config/chawan/config.toml, Chawan utilisera ~/.config/chawan/urimethodmap.
# S'il se trouve dans ~/.chawan/config.toml, alors il utilise ~/.chawan/urimethodmap.
[external]
urimethodmap = "urimethodmap"

Dans urimethodmap

magnet.cgi

# Utilise le script shell CGI `magnet.cgi` pour passer les liens magnet à Transmission.
magnet:		/cgi-bin/magnet.cgi?%s

magnet.cgi se trouve dans le répertoire bonus/. Vous pouvez également écrire un wrapper CGI local pour passer les liens à votre client BitTorrent de choix.

dict

Dans w3m, urimethodmap est couramment utilisé (abusé) pour définir des raccourcis pour les scripts CGI.

Cela fonctionne aussi dans Chawan ; par exemple, vous pourriez définir un raccourci tl: comme ceci :

# (trans.cgi est un script que vous pouvez trouver et étudier dans le répertoire bonus/.)
tl:		/cgi-bin/trans.cgi?%s

Ensuite, vous pourriez ouvrir la traduction de n'importe quel mot en utilisant tl:mot.

Notez cependant que Chawan dispose d'un système plus puissant pour les raccourcis de substitution de ce type sous la forme de règles omni. Donc, si vous souhaitez rediriger vers un site de dictionnaire en ligne avec tl:mot au lieu de fournir une interface CGI locale, il est plus facile d'utiliser des règles omni plutôt que urimethodmap + redirection CGI locale.
