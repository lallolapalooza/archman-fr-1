Dépannage Chawan

Ce document liste les problèmes courants que vous pourriez rencontrer en utilisant Chawan.

Si vous rencontrez un problème non décrit dans ce document, veuillez ouvrir un ticket à l'adresse https://todo.sr.ht/~bptato/chawan.

Il ne compile pas ?

Veuillez ouvrir un ticket. N'oubliez pas d'inclure l'erreur de compilation, ainsi que votre système d'exploitation (et sa version).

Il plante ?

Veuillez ouvrir un ticket décrivant comment reproduire le crash. N'oubliez pas d'inclure le message d'erreur que vous voyez après la disparition de votre buffer.

Si vous ne voyez pas de message d'erreur, essayez : cha example.org -o start.console-buffer=false 2>err.log. Ensuite, vérifiez le contenu de err.log après le crash.

Si vous ne voyez *toujours* pas de message d'erreur, ce n'est pas grave, signalez simplement que vous n'avez pas pu obtenir de message d'erreur.

Je ne peux pas sélectionner/copier du texte avec ma souris ?

Clic droit -> sélectionner le texte, puis clic droit -> copier la sélection. (Vous pouvez également double-cliquer et faire glisser la souris vers la gauche/droite pour sélectionner.)

Si Chawan se plaint de xsel, installez-le ou modifiez external.copy-cmd et external.paste-cmd selon vos préférences.

Vous pouvez également désactiver temporairement le suivi de la souris en maintenant la touche Maj enfoncée, ou de manière permanente en réglant dans config.toml :

[input]
use-mouse = false

On m'a promis des images mais je ne vois rien ?

La raison la plus courante est que vous n'avez pas ajouté ce qui suit à config.toml :

[buffer]
images = true

La deuxième raison la plus courante est que votre terminal ne prend en charge ni les images Sixel ni les images Kitty.

Les autres raisons sont énumérées dans cha-image(7)

Pourquoi ai-je des couleurs étranges/incorrectes/laides ?

Par défaut, les capacités d'affichage de Chawan sont limitées à ce que votre terminal rapporte. En particulier :

  • Si la variable d'environnement $COLORTERM n'est pas définie, il peut se rabattre sur les couleurs 8 bits ou ANSI. Assurez-vous de l'exporter en tant que COLORTERM=truecolor.
  • S'il ne répond pas à la requête de la couleur d'arrière-plan, alors la correction du contraste des couleurs de Chawan fonctionnera probablement mal. Vous pouvez corriger cela en utilisant les options display.default-background-color et display.default-foreground-color.

Voir Display dans cha-config(5) pour les détails.

J'ai configuré mon $PAGER en cha et maintenant les pages man sont illisibles.

La plupart des implémentations de man impriment les pages de manuel formatées par défaut, ce que Chawan peut analyser si elles sont passées par l'entrée standard.

Malheureusement, mandoc nous passe le document formaté comme un *fichier*, ce que Chawan interprète raisonnablement comme du texte brut sans mise en forme.

À ce stade, vous avez deux options :

  • export PAGER='cha -T text/x-ansi' et voyez que man fonctionne soudainement comme prévu.
  • alias man=mancha et voyez que man fonctionne soudainement mieux que prévu.

Idéalement, vous devriez faire les deux, pour gérer les cas comme git help qui appelle man directement.

Il reste un problème avec cette solution : certains programmes essaieront d'appeler $PAGER sans expansion de shell, ce qui brisera l'astuce -T text/x-ansi. Pour résoudre ce problème, placez un script quelque part dans votre PATH :

#!/bin/sh
exec cha -T text/x-ansi "$@"

et export PAGER=pcha (ou quel que soit le nom que vous avez donné au script).

Comment visualiser des fichiers texte avec retour à la ligne ?

Par défaut, les fichiers texte ne sont pas renvoyés à la ligne automatiquement, de sorte que la visualisation de fichiers texte brut qui n'ont pas été correctement renvoyés à la ligne par les auteurs est quelque peu agaçante.

Une solution de contournement consiste à ajouter ceci à la section [page] de votre configuration :

' f' = "pager.externFilterSource('fmt')

et ensuite appuyer sur <espace> f pour visualiser une version renvoyée à la ligne du fichier texte actuel. (Cela suppose que votre système dispose d'un programme fmt - sinon, fold -s peut être une alternative.)

Pour renvoyer toujours automatiquement à la ligne, vous pouvez ajouter ceci à votre style utilisateur :

plaintext { white-space: pre-wrap }

Pour faire de même pour le texte HTML et ANSI, utilisez plaintext, pre.

Pourquoi $WEBSITE a-t-il l'air affreux ?

Généralement, c'est parce qu'il utilise des fonctionnalités CSS qui ne sont pas encore implémentées dans Chawan. Le coupable le plus courant est grid.

Il y a trois façons de gérer cela :

1.
Si le contenu du site web est principalement du texte, installez rdrview. Ensuite, liez la commande suivante à une touche de votre choix dans la configuration (par exemple, <espace> r) :

' r' = "pager.externFilterSource('rdrview -Hu \"$CHA_URL\"')

Cela ne résout pas le problème principal, mais améliore considérablement votre expérience de lecture.

2.
Plaintes ici, et attendez que le problème disparaisse. Il est utile si vous pouvez réduire le problème à un exemple minimal reproductible (idéalement un petit fragment HTML.)
3.
Écrivez un patch pour résoudre le problème et envoyez-le ici.

$WEBSITE - les fonctionnalités interactives ne fonctionnent pas !

Quelques solutions potentielles :

  • Se connecter aux sites web nécessite des cookies. Certains sites web nécessitent également le partage de cookies entre les domaines. Pour des raisons de sécurité, Chawan ne permet rien de tout cela par défaut, vous devrez donc bricoler la configuration du site pour le résoudre. Voir pour les détails.
  • Définissez la valeur siteconf referer-from sur true ; cela amènera Chawan à envoyer un en-tête Referer lors de la navigation vers d'autres URL à partir de l'URL cible.
  • Activez JavaScript. Si quelque chose ne va pas, tapez M-c M-c pour vérifier la console du navigateur, puis suivez l'étape 3. de la réponse précédente.

Lorsque Chawan lance un éditeur de texte externe, il passe simplement la commande $EDITOR au shell, puis examine son code de retour pour déterminer si votre éditeur s'est terminé correctement. Cela fonctionne si l'éditeur ne reçoit jamais de signal, ou si votre shell implémente

WCE.

.
