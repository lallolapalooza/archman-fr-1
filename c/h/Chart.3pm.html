DESCRIPTIO

N

Chart vous aide à créer des images PNG et JPG avec des visualisations de données numériques. Cette page vous donne un résumé de la manière de l'utiliser. Pour une documentation plus approfondie et beaucoup de code d'exemple, veuillez visiter le Chart::

Manual.

Utiliser

Chart

Bon, vous m'avez eu. Il n'y a vraiment pas de module Chart::type. Tous les différents types de graphiques (Points, Lines, Bars, LinesPoints, Composite, StackedBars, Pie, Pareto, HorizontalBars, Split, ErrorBars, Direction et Mountain pour l'instant) sont des classes à part entière, chacune héritant d'un tas de méthodes de la classe Chart::Base. Remplacez simplement le mot type par le type de graphique que vous voulez et vous êtes sur la bonne voie. Par

exemple, 
use Chart::
Lines;

invoquerait le module lines. Alternativement, chargez tous les types de graphiques d'un coup et écrivez

: 
use
Cha
rt;

Obtenir un

objet

La méthode new peut être appelée sans arguments, auquel cas elle renvoie un objet avec la taille d'image par défaut (400x300 pixels), ou vous pouvez spécifier la largeur et la hauteur de l'image. Souvenez-vous simplement de remplacer type par le type de graphique que vous voulez. Par

exemple, 
$obj = Chart::Bars->new (600,400)
;

renverrait un objet Chart::Bars contenant une image de 600x4

00 pixels. New initialise également la plupart des variables par
défaut, que vous pouvez ensuite changer avec la méthode set.

Définir différentes

options

C'est là que le plaisir commence. Set cherche un hachage de clés et de valeurs. Vous pouvez lui passer un hachage que vous avez déjà construit,

comme 
%hash = ( property_name => 'new value' );
$obj->set (%hash)
;

ou vous pouvez essayer de construire le hachage directement dans l'appel à set,

comme 
$obj->set ( property_name => 'new value' )
;

Chart::Manual::Properties liste

toutes les clés et valeurs
actuellement prises en charge.

Envoyer l'image vers un
fichier
L'invocation de la méthode png fait tracer le graphique et le sauvegarde dans un fichier. Elle prend le nom du fichier de sortie et une référence aux données comme arguments. Par exemple, 
$obj->png ("foo.png", \@data)
;

tracerait les données dans @data, et sauvegarderait ensuite l'image dans foo.png. Bien sûr, cela soulève alors la question « À quoi devrait ressembler @data ? ». Eh bien, tout comme GIFgraph, @data devrait contenir des références à des tableaux de données, la première référence de tableau pointant vers un tableau d'étiquettes de graduations x.

Par exemple, 
@data = ( [ 'foo', 'bar', 'junk' ],
      [ 30.2,  23.5,  92.1
] );

mettrait en place un graphique avec un jeu de données, et trois points de données dans cet ensemble. En général, le tableau @data devrait ressembler à quelque

chose comme 
@data = ( \@x_tick_labels, \@dataset1, ... , \@dataset_n
);

Et pas d'inquiétude, je fais ma propre

La méthode cgi_png affichera le graphique, avec l'en-tête http approprié, vers stdout, vous permettant d'appeler des scripts générant des graphiques directement depuis vos pages html (c'est-à-dire avec une balise HTML <lt>img src=image.pl<gt>). Le tableau @data devrait être confi

guré de la même

API basée sur les

colonnes

Vous pourriez demander : « Et si je veux juste ajouter quelques points au graphique, puis l'afficher, sans toutes ces références à des références ? ». Eh bien, ami, la solution est simple. Empruntant l'idée de add_pt du module Graph de Matt Kruse, vous faites simplement quelques appels à la méthode add_pt, comme ceci

: 
$obj->add_pt ('foo', 30, 25);
$obj->add_pt ('bar', 16, 32)
;

Ou, si vous voulez pouvoir ajouter des jeux de données entiers, utilisez simplement la méthode add_dataset

: 
$obj->add_dataset ('foo', 'bar');
$obj->add_dataset (30, 16);
$obj->add_dataset (25, 32)
;

Ces méthodes vérifient que les points et les jeux de données que vous ajoutez sont de la même taille que ceux déjà présents. Ainsi, si vous avez actuellement deux jeux de données stockés, et que vous essayez d'ajouter un point de données avec trois valeurs différentes, elle émettra un avertissement (via le module Carp) avec un message d'erreur. De même, si vous essayez d'ajouter un jeu de données avec 4 points de données, et que tous les autres jeux de données ont 3 points de données, elle émettra un avertissement avec un message

d'erreur.

N'oubliez pas, lorsque vous utilisez cette API, que je traite le premier jeu de données comme une série d'étiquettes de graduations x. Ainsi, dans les exemples ci-dessus, le graphique aurait deux graduations x, étiquetées 'foo' et 'bar', chacune avec deux points de données. Pie et ErrorBars le gèrent différemment, consultez la documentation pour voir comment cela

fonctionne.
Ajouter un fichier de
données
Vous pouvez aussi ajouter un fichier de données complet à un objet de graphique. Utilisez simplement la méthode add_datafile(). 
$obj->add_datafile('file', 'set' or
'pt');

file peut être le nom du fichier de données ou un filehandle. 'set' ou 'pt' est le type du fichier de données. Si le paramètre est 'set', alors chaque ligne du fichier de données doit être un jeu de données complet. La valeur de l'ensemble doit être séparée par des espaces blancs. Par exemple, le fichier ressemble

à ceci : 
'foo'  'bar'
30     16
25
32

Si le paramètre est 'pt', une ligne doit inclure toutes les valeurs d'un point de données séparées par des espaces blancs. Par

exemple : 
'foo'  30  25
'bar'
16
32

Prise en charge des

imagemap

Chart peut également renvoyer les informations de positionnement des pixels afin que vous puissiez créer des imagemap à partir des png générés par Chart. Définissez simplement l'option 'imagemap' à 'true' avant de générer le png, puis appelez la méthode imagemap_dump() ensuite pour récupérer les informations. Vous recevrez une structure de données presque identique au tableau @data décrit ci-dessus pour passer les données à

Chart. 
$imagemap_data = $obj->imagemap_dump ()
;

Au lieu de valeurs de données uniques, vous recevrez des références à des tableaux d'informations de pixels. Pour les graphiques Bars, HorizontalBars et StackedBars, les tableaux contiendront deux paires x-y (spécifiant le coin supérieur gauche et le coin inférieur droit de la barre), comme

ceci 
( $x1, $y1, $x2, $y2 ) = @{ $imagemap_data->[$dataset][$datapoint] }
;

Pour Lines, Points, ErrorBars, Split et LinesPoints, les tableaux contiendront une seule paire x-y (spécifiant le centre du point), comme

ceci 
( $x, $y ) = @{ $imagemap_data->[$dataset][$datapoint] }
;

Quelques avertissements s'appliquent ici. Tout d'abord, GD traite le coin supérieur gauche du png comme le point (0,0), donc les valeurs y positives sont mesurées à partir du haut du png, et non du bas. Deuxièmement, ces valeurs contiendront très probablement des valeurs décimales longues. GD, bien sûr, doit les tronquer en valeurs de pixel uniques. Comme je ne sais pas comment GD le fait, je ne peux pas tronquer de la même manière. Dans le pire des cas, cela entraînera une erreur d'un pixel sur votre imagemap. Si c'est vraiment un problème, votre seule option est de l'expérimenter, ou de contacter Lincoln Stein et de le lui demander. Troisièmement, veuillez vous rappeler que le jeu de données 0 sera vide, car c'est l'endroit dans le tableau @data pour les

étiquettes
de points
de données.

PLA

N

Ce module est actuellement en cours de reconstruction complète, qui se déroulera en deux phases. Premièrement : réécrire toutes les fonctionnalités au sein d'une architecture modulaire et d'un système de propriétés hiérarchique. Cela sera accessible via une API centrale en utilisant le module Chart jusqu'ici inutilisé 'my $c = Chart->new(...);'. Cette API aura en partie des noms de méthodes et de propriétés différents, mais l'ancienne API ne sera pas touchée. Dans une deuxième phase, nous verrons combien de

nouveau code peut être utilisé par les anciens modules et quelles nouvelles fonctionnalités pe
uvent être apportées aux parties héritées, qui seront alors découragées, mais pas abandonnées.
