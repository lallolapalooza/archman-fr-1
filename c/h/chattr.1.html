SYNOPSI

S

chattr [ -RVf ] [ -v version ] [ -p projet ] [ mode ] fichiers.

.

DESCRIPTIO

N

chattr modifie les attributs de fichiers sur un système de fichiers

Linux.

Le format d'un mode symbolique est +-=[aAcCdDeFijmPs

StTux].

L'opérateur '+' ajoute les attributs sélectionnés aux attributs existants des fichiers ; '-' les supprime ; et '=' en fait les seuls attributs que les fichiers

possèdent.

Les lettres 'aAcCdDeFijmPsStTux' sélectionnent les nouveaux attributs des fichiers : ajout uniquement (a), pas de mise à jour de l'atime (A), compressé (c), pas de copie à l'écriture (C), pas de sauvegarde (d), mises à jour de répertoire synchrones (D), format extent (e), recherches de répertoire insensibles à la casse (F), immuable (i), journalisation des données (j), ne pas compresser (m), hiérarchie de projet (P), suppression sécurisée (s), mises à jour synchrones (S), pas de fusion de queue (t), sommet de la hiérarchie de répertoires (T), non supprimable (u), et accès direct pour les fichiers (x)

.

Les attributs suivants sont en lecture seule et peuvent être listés par lsattr(1) mais pas modifiés par chattr : chiffré (E), répertoire indexé (I), données en ligne (N), et verity (V)

.

Tous les drapeaux ne sont pas pris en charge ou utilisés par tous les systèmes de fichiers ; consultez les pages man propres au système de fichiers telles que btrfs(5), ext4(5), mkfs.f2fs(8), et xfs(5) pour plus de détails prop

res au syst
ème de fichiers.

ATTRIBUT

S
a
Un fichier avec l'attribut 'a' défini ne peut être ouvert qu'en mode ajout pour l'écriture. Seul le superutilisateur ou un processus possédant la capacité CAP_LINUX_IMMUTABLE peut définir ou effacer cet
attribut.
A
Lorsqu'un fichier avec l'attribut 'A' défini est accédé, son enregistrement atime n'est pas modifié. Cela évite une certaine quantité d'E/S disque pour les systèmes
portables.
c
Un fichier avec l'attribut 'c' défini est automatiquement compressé sur le disque par le noyau. Une lecture de ce fichier renvoie des données non compressées. Une écriture sur ce fichier compresse les données avant de les stocker sur le disque. Remarque : veuillez vous assurer de lire la section sur les bogues et les limitations à la fin de ce document. (Remarque : Pour btrfs, si le drapeau 'c' est défini, alors le drapeau 'C' ne peut pas être défini. Entre également en conflit avec l'option de montage btrfs
'nodatasum')
C
Un fichier avec l'attribut 'C' défini ne sera pas sujet aux mises à jour par copie à l'écriture. Ce drapeau n'est pris en charge que sur les systèmes de fichiers qui effectuent une copie à l'écriture. (Remarque : Pour btrfs, le drapeau 'C' devrait être défini sur de nouveaux fichiers ou des fichiers vides. S'il est défini sur un fichier qui possède déjà des blocs de données, il est indéfini quand les blocs assignés au fichier seront entièrement stables. Si le drapeau 'C' est défini sur un répertoire, il n'aura aucun effet sur le répertoire, mais les nouveaux fichiers créés dans ce répertoire auront l'attribut No_COW défini. Si le drapeau 'C' est défini, alors le drapeau 'c' ne peut pas être défini.
)
d
Un fichier avec l'attribut 'd' défini n'est pas un candidat pour la sauvegarde lorsque le programme dump(8) est
exécuté.
D
Lorsqu'un répertoire avec l'attribut 'D' défini est modifié, les changements sont écrits de manière synchrone sur le disque ; cela équivaut à l'option de montage 'dirsync' appliquée à un sous-ensemble des
fichiers.
e
L'attribut 'e' indique que le fichier utilise des extents pour la mise en correspondance des blocs sur le disque. Il ne peut pas être supprimé à l'aide de chattr(
1).
E
Un fichier, répertoire ou lien symbolique avec l'attribut 'E' défini est chiffré par le système de fichiers. Cet attribut ne peut pas être défini ou effacé à l'aide de chattr(1), bien qu'il puisse être affiché par lsattr(
1).
F
Un répertoire avec l'attribut 'F' défini indique que toutes les recherches de chemins à l'intérieur de ce répertoire sont effectuées de manière insensible à la casse. Cet attribut ne peut être modifié que dans des répertoires vides sur les systèmes de fichiers avec la fonctionnalité casefold
activée.
i
Un fichier avec l'attribut 'i' ne peut pas être modifié : il ne peut pas être supprimé ou renommé, aucun lien ne peut être créé vers ce fichier, la plupart des métadonnées du fichier ne peuvent pas être modifiées, et le fichier ne peut pas être ouvert en mode écriture. Seul le superutilisateur ou un processus possédant la capacité CAP_LINUX_IMMUTABLE peut définir ou effacer cet
attribut.
I
L'attribut 'I' est utilisé par le code htree pour indiquer qu'un répertoire est indexé à l'aide d'arbres hachés. Il ne peut pas être défini ou effacé à l'aide de chattr(1), bien qu'il puisse être affiché par lsattr(
1).
j
Un fichier avec l'attribut 'j' a toutes ses données écrites dans le journal ext3 ou ext4 avant d'être écrites dans le fichier lui-même, si le système de fichiers est monté avec les options "data=ordered" ou "data=writeback" et que le système de fichiers possède un journal. Lorsque le système de fichiers est monté avec l'option "data=journal", toutes les données de fichiers sont déjà journalisées et cet attribut n'a aucun effet. Seul le superutilisateur ou un processus possédant la capacité CAP_SYS_RESOURCE peut définir ou effacer cet
attribut.
m
Un fichier avec l'attribut 'm' est exclu de la compression sur les systèmes de fichiers qui prennent en charge la compression par
fichier.
N
Un fichier avec l'attribut 'N' défini indique que le fichier a des données stockées en ligne, à l'intérieur de l'inode lui-même. Il ne peut pas être défini ou effacé à l'aide de chattr(1), bien qu'il puisse être affiché par lsattr(
1).
P
Un répertoire avec l'attribut 'P' défini imposera une structure hiérarchique pour les identifiants de projet. Cela signifie que les fichiers et répertoires créés dans le répertoire hériteront de l'identifiant de projet du répertoire, les opérations de renommage sont contraintes de sorte que lorsqu'un fichier ou répertoire est déplacé vers un autre répertoire, les identifiants de projet doivent correspondre. De plus, un lien dur vers un fichier ne peut être créé que lorsque l'identifiant de projet du fichier et celui du répertoire de destination
correspondent.
s
Lorsqu'un fichier avec l'attribut 's' défini est supprimé, ses blocs sont mis à zéro et réécrits sur le disque. Remarque : veuillez vous assurer de lire la section sur les bogues et les limitations à la fin de ce
document.
S
Lorsqu'un fichier avec l'attribut 'S' défini est modifié, les changements sont écrits de manière synchrone sur le disque ; cela équivaut à l'option de montage 'sync' appliquée à un sous-ensemble des
fichiers.
t
Un fichier avec l'attribut 't' n'aura pas de fragment de bloc partielnt at the end of the file merged with other files (for those file systems which support tail-merging). This is necessary for applications such as LILO which read the file system directly, and which don't understand tail-merged files. Note: As of this writing, the ext2, ext3, and ext4 file systems do not support
tail-merging.
T
Un répertoire avec l'attribut 'T' sera considéré comme le sommet des hiérarchies de répertoires aux fins de l'allocateur de blocs Orlov. Il s'agit d'un indice donné à l'allocateur de blocs utilisé par ext3 et ext4 indiquant que les sous-répertoires de ce répertoire ne sont pas liés entre eux et doivent donc être éparpillés aux fins d'allocation. Par exemple, il est très judicieux de définir l'attribut 'T' sur le répertoire /home, afin que /home/john et /home/mary soient placés dans des groupes de blocs séparés. Pour les répertoires où cet attribut n'est pas défini, l'allocateur de blocs Orlov essaiera de regrouper les sous-répertoires aussi près que possible les uns des
autres.
u
Lorsqu'un fichier avec l'attribut 'u' défini est supprimé, son contenu est conservé. Cela permet à l'utilisateur de demander sa restauration. Note : veuillez lire la section sur les bogues et les limitations à la fin de ce
document.
x
Un fichier avec l'attribut 'x' demande l'utilisation du mode d'accès direct (dax), si le noyau prend en charge DAX. Cela peut être annulé par l'option de montage 'dax=never'. Pour plus d'informations, voir la documentation du noyau sur dax : https://www.kernel.org/doc/htm
l/latest/filesy
stems/dax.html.
Si l'attribut est défini sur un répertoire existant, il sera hérité par tous les fichiers et sous-répertoires créés ultérieurement dans le répertoire. Si un répertoire existant contient déjà des fichiers et des sous-répertoires, la modification de l'attribut sur le répertoire parent ne change pas les attributs de ces fichiers et sous-répertoire
s
.
V
Un fichier avec l'attribut 'V' défini a fs-verity activé. Il ne peut pas être écrit, et le système de fichiers vérifiera automatiquement toutes les données lues à partir de celui-ci par rapport à un hachage cryptographique couvrant l'intégralité du contenu du fichier, par exemple via un arbre de Merkle. Cela rend possible l'authentification efficace du fichier. Cet attribut ne peut pas être défini ou effacé à l'aide de chattr(1), bien qu'il puisse être affiché par lsat
tr
(1
).

BOGUES ET

LIMITATIONS

Les attributs 'c', 's' et 'u' ne sont pas pris en compte par les systèmes de fichiers ext2, ext3 et ext4 tels qu'ils sont implémentés dans les noyaux Linux actuels. La définition des attributs 'a' et 'i' n'affecte pas la capacité d'écrire dans les descripteurs de fichiers déjà

existants.

L'option 'j' n'est utile que pour les systèmes de fichiers ext3 et

ext4.

L'option 'D' n'est utile qu

e sur le noyau Linux 2.5.19
et versions ultérieures.
