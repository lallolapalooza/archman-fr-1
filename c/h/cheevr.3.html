sous-routine cheevr (character jobz, character range, character uplo, integer n, complex, dimension( lda, * ) a, integer lda, real vl, real vu, integer il, integer iu, real abstol, integer m, real, dimension( * ) w, complex, dimension( ldz, * ) z, integer ldz, integer, dimension( * ) isuppz, complex, dimension( * ) work, integer lwork, real, dimension( * ) rwork, integer lrwork, integer, dimension( * ) iwork, integer liwork, integer info)

CHEEVR calcule les valeurs propres et, de manière optionnelle, les vecteurs propres gauche et/ou droit pour les matrices HE

But :

!>
!> CHEEVR calcule les valeurs propres sélectionnées et, de manière optionnelle, les vecteurs propres
!> d'une matrice hermitienne complexe A. Les valeurs propres et les vecteurs propres peuvent être
!> sélectionnés en spécifiant soit une plage de valeurs soit une plage d'indices
!> pour les valeurs propres souhaitées. Des invocations avec des choix différents pour
!> ces paramètres peuvent entraîner le calcul de valeurs propres et/ou de vecteurs propres
!> légèrement différents pour la même matule. La raison de
!> ce comportement est qu'il existe une variété d'algorithmes (chacun
!> performant au mieux pour un ensemble particulier d'options) avec CHEEVR
!> tentant de sélectionner le meilleur en fonction des divers paramètres. Dans tous
!> les cas, les valeurs calculées sont précises dans les limites de l'arithmétique
!> en virgule flottante à précision finie.
!>
!> CHEEVR réduit d'abord la matrice A à une forme tridiagonale T avec un appel
!> à CHETRD. Ensuite, chaque fois que c'est possible, CHEEVR appelle CSTEMR pour calculer
!> le spectre propre en utilisant des Représentations Robustes Relatives (Relatively Robust Representations). CSTEMR
!> calcule les valeurs propres par l'algorithme dqds, tandis que les vecteurs propres
!> orthogonaux sont calculés à partir de diverses représentations L D L^T
!> (également connues sous le nom de Représentations Robustes Relatives). L'orthogonalisation
!> de Gram-Schmidt est évitée autant que possible. Plus précisément,
!> les diverses étapes de l'algorithme sont les suivantes.
!>
!> Pour chaque bloc (sous-matrice) non réduit de T,
!>    (a) Calculer T - sigma I = L D L^T, de sorte que L et D
!>        définissent toutes les valeurs propres souhaitées avec une haute précision relative.
!>        Cela signifie que de petites variations relatives dans les entrées de D et L
!>        n'entraînent que de petites variations relatives dans les valeurs propres et
!>        les vecteurs propres. La représentation standard (non factorisée) de la
!>        matrice tridiagonale T n'a pas cette propriété en général.
!>    (b) Calculer les valeurs propres avec une précision appropriée.
!>        Si les vecteurs propres sont souhaités, l'algorithme n'atteint la pleine
!>        précision des valeurs propres calculées qu'à l'instant précédant
!>        le calcul des vecteurs correspondants, voir les étapes c) et d).
!>    (c) Pour chaque groupe de valeurs propres proches, sélectionner un nouveau
!>        décalage (shift) proche du groupe, trouver une nouvelle factorisation, et affiner
!>        les valeurs propres décalées avec une précision appropriée.
!>    (d) Pour chaque valeur propre avec une séparation relative suffisante, calculer
!>        le vecteur propre correspondant en formant une factorisation tordue révélatrice de rang (rank revealing twisted
!>        factorization). Retourner à (c) pour tous les groupes restants.
!>
!> La précision souhaitée de la sortie peut être spécifiée par le paramètre
!> d'entrée ABSTOL.
!>
!> Pour plus de détails, voir la documentation de CSTEMR et :
!> - Inderjit S. Dhillon et Beresford N. Parlett :
!>   Linear Algebra and its Applications, 387(1), pp. 1-28, August 2004.
!> - Inderjit Dhillon et Beresford Parlett : SIAM Journal on Matrix Analysis and Applications, Vol. 25,
!>   2004. Aussi LAPACK Working Note 154.
!> - Inderjit Dhillon : ,
!>   Computer Science Division Technical Report No. UCB/CSD-97-971,
!>   UC Berkeley, May 1997.
!>
!>
!> Remarque 1 : CHEEVR appelle CSTEMR lorsque le spectre complet est demandé
!> sur les machines qui se conforment à la norme de virgule flottante ieee-754.
!> CHEEVR appelle SSTEBZ et CSTEIN sur les machines non-ieee et
!> lorsque des demandes de spectre partiel sont faites.
!>
!> L'exécution normale de CSTEMR peut créer des NaN et des infinis et
!> peut donc s'interrompre en raison d'une exception de virgule flottante dans les environnements
!> qui ne gèrent pas les NaN et les infinis de la manière par défaut de la norme ieee.
!>

Paramètres

JOBZ 
!>          JOBZ est CHARACTER*1
!>          = 'N' : calculer uniquement les valeurs propres ;
!>          = 'V' : calculer les valeurs propres et les vecteurs propres.
!>
!>          Ce paramètre influence le choix de l'algorithme et
!>          peut modifier les valeurs calculées.
!>

RANGE

!>          RANGE est CHARACTER*1
!>          = 'A' : toutes les valeurs propres seront trouvées.
!>          = 'V' : toutes les valeurs propres dans l'intervalle semi-ouvert (VL,VU]
!>                 seront trouvées.
!>          = 'I' : les valeurs propres de la IL-ième à la IU-ième seront trouvées.
!>          Pour RANGE = 'V' ou 'I' et IU - IL < N - 1, SSTEBZ et
!>          CSTEIN sont appelés.
!>
!>          Ce paramètre influence le choix de l'algorithme et
!>          peut modifier les valeurs calculées.
!>

UPLO

!>          UPLO est CHARACTER*1
!>          = 'U' : le triangle supérieur de A est stocké ;
!>          = 'L' : le triangle inférieur de A est stocké.
!>

N

!>          N est INTEGER
!>          L'ordre de la matrice A. N >= 0.
!>

A

!>          A est un tableau COMPLEX, dimension (LDA, N)
!>          À l'entrée, la matrice hermitienne A. Si UPLO = 'U', la
!>          partie triangulaire supérieure N par N de A contient la
!>          partie triangulaire supérieure de la matrice A. Si UPLO = 'L',
!>          la partie triangulaire inférieure N par N de A contient
!>          la partie triangulaire inférieure de la matrice A.
!>          À la sortie, le triangle inférieur (si UPLO='L') ou le triangle
!>          supérieur (si UPLO='U') de A, y compris la diagonale, est
!>          détruit.
!>

LDA

!>          LDA est INTEGER
!>          La dimension principale du tableau A. LDA >= max(1,N).
!>

VL

!>          VL est REAL
!>          Si RANGE='V', la borne inférieure de l'intervalle dans
!>          lequel rechercher les valeurs propres. VL < VU.
!>          Non référencé si RANGE = 'A' ou 'I'.
!>

VU

!>          VU est REAL
!>          Si RANGE='V', la borne supérieure de l'intervalle dans
!>          lequel rechercher les valeurs propres. VL < VU.
!>          Non référencé si RANGE = 'A' ou 'I'.
!>

IL

!>          IL est INTEGER
!>          Si RANGE='I', l'indice de la
!>          plus petite valeur propre à retourner.
!>          1 <= IL <= IU <= N, si N > 0 ; IL = 1 et IU = 0 si N = 0.
!>          Non référencé si RANGE = 'A' ou 'V'.
!>

IU

!>          IU est INTEGER
!>          Si RANGE='I', l'indice de la
!>          plus grande valeur propre à retourner.
!>          1 <= IL <= IU <= N, si N > 0 ; IL = 1 et IU = 0 si N = 0.
!>          Non référencé si RANGE = 'A' ou 'V'.
!>

ABSTOL

!>          ABSTOL est REAL
!>          La tolérance d'erreur absolue pour les valeurs propres.
!>          Une valeur propre approximative est acceptée comme convergée
!>          lorsqu'il est déterminé qu'elle se situe dans un intervalle [a,b]
!>          de largeur inférieure ou égale à
!>
!>                  ABSTOL + EPS *   max( |a|,|b| ) ,
!>
!>          où EPS est la précision machine. Si ABSTOL est inférieur ou
!>          égal à zéro, alors EPS*|T| sera utilisé à sa place,
!>          où |T| est la 1-norme de la matrice tridiagonale obtenue
!>          en réduisant A à une forme tridiagonaleorm.
!>
!>          Voir  par Demmel et
!>          Kahan, LAPACK Working Note #3.
!>
!>          Si une grande précision relative est importante, définissez ABSTOL à
!>          SLAMCH( 'Safe minimum' ).  Cela garantira que
!>          les valeurs propres sont calculées avec une grande précision relative lorsque
!>          c'est possible dans les futures versions.  Le code actuel ne
!>          donne aucune garantie de grande précision relative, mais
!>          les futures versions le feront. Voir J. Barlow et J. Demmel,
!>          , LAPACK Working Note #7, pour une discussion
!>          sur les matrices qui définissent leurs valeurs propres avec une grande précision
!>          relative.
!>

M

!>          M est INTEGER
!>          Le nombre total de valeurs propres trouvées.  0 <= M <= N.
!>          Si RANGE = 'A', M = N, et si RANGE = 'I', M = IU-IL+1.
!>

W

!>          W est un tableau REAL, de dimension (N)
!>          Les M premiers éléments contiennent les valeurs propres sélectionnées
!>          dans l'ordre croissant.
!>

Z

!>          Z est un tableau COMPLEX, de dimension (LDZ, max(1,M))
!>          Si JOBZ = 'V', alors si INFO = 0, les M premières colonnes de Z
!>          contiennent les vecteurs propres orthonormaux de la matrice A
!>          correspondant aux valeurs propres sélectionnées, avec la i-ième
!>          colonne de Z contenant le vecteur propre associé à W(i).
!>          Si JOBZ = 'N', alors Z n'est pas référencé.
!>          Remarque : l'utilisateur doit s'assurer qu'au moins max(1,M) colonnes sont
!>          fournies dans le tableau Z ; si RANGE = 'V', la valeur exacte de M
!>          n'est pas connue à l'avance et une borne supérieure doit être utilisée.
!>          Fournir N colonnes est toujours sûr.
!>

LDZ

!>          LDZ est INTEGER
!>          La dimension principale du tableau Z.  LDZ >= 1, et si
!>          JOBZ = 'V', LDZ >= max(1,N).
!>

ISUPPZ

!>          ISUPPZ est un tableau INTEGER, de dimension ( 2*max(1,M) )
!>          Le support des vecteurs propres dans Z, c'est-à-dire les indices
!>          indiquant les éléments non nuls dans Z. Le i-ième vecteur propre
!>          est non nul uniquement dans les éléments ISUPPZ( 2*i-1 ) à
!>          ISUPPZ( 2*i ). Ceci est une sortie de CSTEMR (matrice
!>          tridiagonale). Le support des vecteurs propres de A est typiquement
!>          1:N en raison des transformations unitaires appliquées par CUNMTR.
!>          Implémenté uniquement pour RANGE = 'A' ou 'I' et IU - IL = N - 1
!>

WORK

!>          WORK est un tableau COMPLEX, de dimension (MAX(1,LWORK))
!>          À la sortie, si INFO = 0, WORK(1) renvoie la valeur optimale de LWORK.
!>

LWORK

!>          LWORK est INTEGER
!>          La longueur du tableau WORK.
!>          Si N <= 1, LWORK >= 1, sinon LWORK >= 2*N.
!>          Pour une efficacité optimale, LWORK >= (NB+1)*N,
!>          où NB est le maximum de la taille de bloc pour CHETRD et pour
!>          CUNMTR tel que renvoyé par ILAENV.
!>
!>          Si LWORK = -1, alors une interrogation d'espace de travail est supposée ; la routine
!>          calcule uniquement les tailles optimales des tableaux WORK, RWORK et
!>          IWORK, renvoie ces valeurs comme les premières entrées
!>          des tableaux WORK, RWORK et IWORK, et aucun message d'erreur
!>          lié à LWORK ou LRWORK ou LIWORK n'est émis par XERBLA.
!>

RWORK

!>          RWORK est un tableau REAL, de dimension (MAX(1,LRWORK))
!>          À la sortie, si INFO = 0, RWORK(1) renvoie la valeur optimale
!>          (et minimale) de LRWORK.
!>

LRWORK

!>          LRWORK est INTEGER
!>          La longueur du tableau RWORK.
!>          Si N <= 1, LRWORK >= 1, sinon LRWORK >= 24*N.
!>
!>          Si LRWORK = -1, alors une interrogation d'espace de travail est supposée ; la
!>          routine calcule uniquement les tailles optimales des tableaux WORK, RWORK
!>          et IWORK, renvoie ces valeurs comme les premières entrées
!>          des tableaux WORK, RWORK et IWORK, et aucun message d'erreur
!>          lié à LWORK ou LRWORK ou LIWORK n'est émis par XERBLA.
!>

IWORK

!>          IWORK est un tableau INTEGER, de dimension (MAX(1,LIWORK))
!>          À la sortie, si INFO = 0, IWORK(1) renvoie la valeur optimale
!>          (et minimale) de LIWORK.
!>

LIWORK

!>          LIWORK est INTEGER
!>          La dimension du tableau IWORK.
!>          Si N <= 1, LIWORK >= 1, sinon LIWORK >= 10*N.
!>
!>          Si LIWORK = -1, alors une interrogation d'espace de travail est supposée ; la
!>          routine calcule uniquement les tailles optimales des tableaux WORK, RWORK
!>          et IWORK, renvoie ces valeurs comme les premières entrées
!>          des tableaux WORK, RWORK et IWORK, et aucun message d'erreur
!>          lié à LWORK ou LRWORK ou LIWORK n'est émis par XERBLA.
!>

INFO

!>          INFO est INTEGER
!>          = 0:  sortie réussie
!>          < 0:  si INFO = -i, le i-ième argument avait une valeur illégale
!>          > 0:  Erreur interne
!>
