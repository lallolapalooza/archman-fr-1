CHA-CONFIG(5) Manuel des formats de fichiers CHA-CONFIG(5)

Configuration de Chawan

Chawan prend en charge la configuration de diverses options telles que les raccourcis clavier, les feuilles de style utilisateur, les préférences de site, etc. Le format de configuration est similaire à toml, avec les exceptions suivantes :

  • Les tableaux en ligne peuvent s'étendre sur plusieurs lignes.
  • Les tableaux réguliers ([table]) et les tableaux en ligne (table = {}) ont des sémantiques différentes. Le premier est additif, ce qui signifie que les anciennes valeurs ne sont pas supprimées. Le second est destructif et efface toutes les définitions dans le tableau spécifié.
  • [[table-array]] est un raccourci pour [table-array.n], où n est le nombre de tableaux de tableaux déclarés. Par exemple, vous pouvez déclarer des siteconfs anonymes en utilisant la syntaxe [[siteconf]].

Le chemin canonique du fichier de configuration est ~/.chawan/config.toml, mais le chemin de recherche prend également en charge les répertoires de base XDG :

1.
fichier de configuration spécifié via l'option -C -> utiliser celui-ci
2.
$CHA_DIR est défini -> utiliser $CHA_DIR/config.toml
3.
${XDG_CONFIG_HOME:-~/.config}/chawan/config.toml existe -> utiliser celui-ci
4.
~/.chawan/config.toml existe -> utiliser celui-ci

Voir la section sur le traitement des chemins pour plus de détails sur la manière d'accéder au répertoire de configuration.

Démarrage

Les options de démarrage doivent être placées dans la section [start] .

Voici une liste des options de démarrage :

Nom Valeur Par défaut Fonction
visual-home url « about:chawan » Page ouverte lorsque Chawan est appelé avec l'option -V et qu'aucune autre page n'est passée en argument.
startup-script Code JavaScript « » Script exécuté par Chawan au démarrage. Les pages ne seront pas chargées tant que cette fonction ne se sera pas terminée. (Notez cependant que les fonctions asynchrones comme setTimeout ne bloquent pas le chargement.)
headless booléen / « dump » false Lorsqu'il est défini à true ou « dump », le navigateur ne prend pas d'entrée ; il imprime plutôt une version rendue de tous les tampons dans l'ordre, puis se termine. La différence entre true et « dump » est que true attend d'abord que tous les scripts et requêtes réseau se terminent, alors que « dump » ne le fait pas. Cela signifie que true peut ne jamais se terminer si le scripting est activé (par ex. si un script définit setInterval.) Rediriger cha vers un programme externe ou passer l'option -d a le même effet que de définir cette option à « dump ».
console-buffer booléen true Indique si Chawan doit ouvrir un tampon de console en mode non headless. Avertissement : ceci n'est utile que pour le débogage. Désactiver cette option sans rediriger manuellement la sortie d'erreur standard entraînera l'apparition aléatoire de messages d'erreur sur votre écran.

Tampon

Les options de tampon doivent être placées dans la section [buffer] .

Ces options sont globales à tous les tampons. Pour un filtrage plus fin, utilisez [[siteconf]].

Exemple :

[buffer]
# afficher les images sur tous les sites web
images = true
# désactiver le CSS des sites web
styling = false
# Spécifier les styles utilisateur.
user-style = '''
/* vous pouvez importer des styles UA externes comme ceci : */
@import 'user.css';
/* ou simplement insérer le style en ligne comme suit. */
/* imposer la text-decoration par défaut pour les liens (c.-à-d. soulignement). */
a[href] { text-decoration: revert !important }
@media (monochrome) { /* uniquement en mode couleur "monochrome" (ou -M) */
	/* désactiver le style UA de la police en gras (pas besoin de important ici) */
	a[href]:hover { font-weight: initial }
	/* ...et mettre la police en italique au survol à la place.
	 * ici nous utilisons important parce que nous ne voulons pas que les sites web
	 * puissent surcharger la valeur. */
	a[href]:hover { font-style: italic !important }
}
'''
# Vous *pouvez* définir scripting à true ici, mais je recommande fortement d'utiliser
# [[siteconf]] pour l'activer par site à la place.

Voici une liste des options de tampon :

Nom Valeur Par défaut Fonction
styling booléen true Active/désactive les feuilles de style de l'auteur. Notez que la désactivation de cette option n'affecte pas les styles utilisateur.
scripting booléen / « app » false Active/désactive JavaScript dans tous les tampons. "app" active également les API JavaScript qui peuvent être utilisées pour empreinter les utilisateurs (par ex. en interrogeant la taille de la fenêtre.) Cela peut améliorer la compatibilité avec les sites web qui se comportent comme des applications, au prix d'une confidentialité réduite. Pour des raisons de sécurité, il est recommandé aux utilisateurs d'activer sélectivement JavaScript avec [[siteconf]] plutôt que d'utiliser ce paramètre.
images booléen false Active/désactive l'affichage des images en ligne.
cookie booléen / « save » false Active/désactive les cookies sur les sites. Si la chaîne « save » est spécifiée, les cookies sont également enregistrés dans external.cookie-file. true lit toujours cookies.txt, mais ne le modifie pas. Dans Chawan, chaque site web dispose d'un pot de cookies séparé, de sorte que les sites web s'appuyant sur des cookies intersites peuvent ne pas fonctionner comme prévu. Vous pouvez utiliser le paramètre [[siteconf]] "share-cookie-jar" pour ajuster ce comportement pour des sites spécifiques.
referer-from booléen false Active/désactive l'en-tête « Referer ». Par défaut à false. Pour des raisons de confidentialité, il est recommandé de laisser cette option désactivée, ne l'activant que pour des sites spécifiques dans [[siteconf]].
autofocus booléen false Lorsqu'il est défini à true, les éléments avec un attribut « autofocus » sont automatiquement mis au focus après le chargement du tampon. Si le scripting est activé, cela permet également aux scripts de mettre le focus sur des éléments.
meta-refresh « never » / « always » / « ask » « ask » Indique si les balises meta http-equiv=refresh doivent être respectées ou non. « never » les désactive complètement, « always » les accepte automatiquement toutes, « ask » fait apparaître un menu contextuel.
history booléen true Indique si l'historique de navigation doit être enregistré sur le disque.
mark-links booléen false Ajoute des marqueurs numériques avant les liens. En mode headless/dump, cela imprime également une liste d'URL après la page.
user-style chaîne « » Une feuille de style utilisateur appliquée à tous les tampons. Les feuilles de style externes peuvent être importées en utilisant la syntaxe @import 'file.css'; . Les chemins sont relatifs au répertoire de configuration. Les @import imbriqués ne sont pas encore pris en charge.

Recherche

Les options de recherche doivent être placées dans la section [search] .

Voici une liste des options de recherche :

Nom Valeur Par défaut Fonction
wrap booléen true Indique si les recherches dans la page doit englober l'ensemble du document.
ignorer la casse « auto » / booléen « auto » Lorsqu'il est défini sur true, les recherches dans tout le document ignorent la casse par défaut. Lorsqu'il est défini sur « auto », les recherches ne sont sensibles à la casse que lorsque le terme de recherche contient une lettre majuscule. Remarque : cela peut également être remplacé en ligne dans la barre de recherche (style vim), avec les séquences d'échappement \c (ignorer la casse) et \C (cas strict). Voir le mode de recherche pour plus de détails.)

Encodage

Les options d'encodage doivent être placées dans la section [encoding] .

Voici une liste des options d'encodage :

Nom Valeur Par défaut Fonction
document-charset tableau de chaînes d'étiquettes de jeu de caractères [« utf-8 », « sjis », « euc-jp », « latin2 »] Liste des jeux de caractères pour le chargement des documents. Tous les jeux de caractères listés sont essayés jusqu'à ce que le document soit décodé sans erreur. En HTML, les balises meta et le BOM peuvent remplacer cela par un jeu de caractères différent, à condition que le jeu de caractères spécifié puisse décoder le document correctement.
display-charset chaîne « auto » Jeu de caractères pour la saisie au clavier et l'affichage des documents. Utilisé également en mode dump. (Cela signifie que par exemplecha -I EUC-JP -O UTF-8 a > b est approximativement équivalent à iconv -f EUC-JP -t UTF-8.)

Externe

Les options externes doivent être placées dans la section [external] .

Voici une liste des options externes :

Nom Valeur Par défaut Fonction
tmpdir chemin {généralement /tmp/cha-tmp-user} Répertoire utilisé pour enregistrer les fichiers temporaires.

mailcap tableau de chemins {voir la documentation de mailcap} Chemin de recherche des fichiers mailcap. (Voir cha-mailcap(5) pour plus de détails.) Les répertoires spécifiés en premier ont une priorité plus élevée.
mime-types tableau de chemins {voir la documentation de mime.types} Chemin de recherche des fichiers mime.types. (Voir cha-mime.types(5) pour plus de détails.)
auto-mailcap chemin « auto.mailcap » Fichier mailcap pour les entrées qui sont exécutées automatiquement. La invite « Ouvrir en » enregistre également les entrées dans ce fichier.
cgi-dir tableau de chemins {voir la documentation de CGI local} Chemin de recherche des scripts CGI locaux. (Voir cha-localcgi(5) pour plus de détails.)
urimethodmap tableau de chemins {voir la documentation d'urimethodmap} Chemin de recherche des fichiers urimethodmap. (Voir cha-urimethodmap(5) pour plus de détails.)
w3m-cgi-compat booléen false Active la compatibilité CGI locale avec w3m. En bref, cela redirige file:///cgi-bin/* et file:///$LIB/cgi-bin/* vers cgi-bin:*. Pour plus de détails, voir cha-localcgi(5).
download-dir chemin {identique à tmpdir} Chemin à pré-remplir pour les invites « Enregistrer sous : ».
show-download-panel booléen true Indique si about:downloads doit être affiché après le début d'un téléchargement.
copy-cmd commande shell « xsel -bi » Commande à utiliser pour les opérations « copier dans le presse-papiers ».
paste-cmd commande shell « xsel -bo » Commande à utiliser pour les opérations « lire depuis le presse-papiers ».
bookmark chemin « bookmark.md » Chemin vers le fichier bookmark.md. (Le fichier auquel il pointe doit avoir une extension .md, afin que son type puisse être correctement déduit.)
history-file chemin « history.uri » Chemin vers le fichier d'historique.
history-size nombre 100 Longueur maximale du fichier d'historique.
cookie-file chemin « cookies.txt » Chemin vers le fichier de cookies. Le format est équivalent au format « cookies.txt » de curl, sauf qu'une partie « jar@ » est préfixée pour les cookies qui appartiennent à un autre jar que le domaine. Les cookies de ce fichier sont utilisés si « buffer.cookie » (ou son équivalent siteconf) est défini à true ou "save". Cela signifie que true définit le cookie-file en mode « lecture seule ».

Entrée

Les options d'entrée doivent être placées dans la section [input] .

Nom Valeur Par défaut Fonction
vi-numeric-prefix booléen true Indique si les préfixes numériques de style vi doivent être acceptés pour les commandes. Ne s'applique qu'aux raccourcis clavier définis dans [page].
use-mouse booléen true Indique si Chawan est autorisé à intercepter les clics de souris. L'implémentation actuelle imite w3m.
osc52-copy booléen / « auto » auto Indique si Chawan doit utiliser la séquence d'échappement OSC 52 pour copier directement dans le presse-papiers via le terminal. Lorsqu'il est disponible, OSC 52 remplace external.copy-cmd. Lorsqu'il est défini sur « auto » (par défaut), Chawan tente de détecter si OSC 52 est disponible au lancement.
bracketed-paste booléen true Indique si Chawan doit demander le collage entre crochets (bracketed paste). Lorsque c'est true, le terminal (normalement) marquera le texte collé avec des séquences d'échappement, ce qui a) garantit que le collage d'un caractère de nouvelle ligne dans l'éditeur de ligne ne soumet pas l'éditeur, b) permet à Chawan d'intercepter le texte collé dans le pager, le chargeant automatiquement dans la barre d'URL du navigateur.
wheel-scroll nombre 5 Nombre de lignes à faire défiler pour un événement de molette de souris.
side-wheel-scroll nombre 5 Nombre de colonnes à faire défiler pour un événement de molette latérale de souris.
link-hint-chars chaîne abcdefghijklmnoprstuvxyz Une chaîne de caractères à utiliser dans toggleLinkHints. Tout point de code Unicode est accepté, et ils sont ordonnés comme spécifié dans cette option.

Exemples :

[input]
vi-numeric-prefix = true
[page]
# Ici, la fonction fléchée sera appelée avec le préfixe numérique vi si
# un a été saisi, et sans argument sinon.
# Le préfixe numérique ne peut jamais être zéro, il est donc sûr de tester
# l'undefined à l'aide de l'opérateur ternaire.
G = 'n => n ? pager.gotoLine(n) : pager.cursorLastLine()'

Réseau

Les options réseau doivent être placées dans la section [network] .

Nom Valeur Par défaut Fonction
max-redirect nombre 10 Nombre maximum de redirections à suivre.
max-net-connections nombre 12 Nombre maximum de connexions réseau simultanées autorisées dans un même buffer. Les connexions supplémentaires sont retenues jusqu'à ce que le nombre repasse sous le seuil.
prepend-scheme chaîne « https:// » Préfixer ceci aux URL passées à Chawan sans schéma. Remarque : les fichiers locaux (schémafile: ) seront toujours vérifiés en premier ; seulement si cela échoue, Chawan réessaiera la requête avec prepend-scheme défini comme schéma.
proxy URL non défini Spécifier un proxy pour toutes les requêtes réseau que Chawan effectue. Actuellement, les formats http://user:pass@domain et socks5://user:pass@domain sont acceptés. (Contrairement à curl, socks5h est un alias de socks5, et les requêtes DNS sont toujours tunnelisées.) Peut être remplacé par siteconf.
default-headers table {omis} Spécifier une liste d'en-têtes par défaut pour toutes les requêtes réseau HTTP(S). Peut être remplacé par siteconf.
allow-http-from-file booléen false AVERTISSEMENT : réfléchissez à deux fois avant d'activer ceci. Autorise HTTP et Hrequêtes provenant des schémas file: et stream: . C'est généralement une très mauvaise idée, car cela permet à des fichiers locaux de pinguer des serveurs distants (une fonctionnalité couramment abusée par les e-mails HTML pour suivre l'activité de votre boîte mail.) D'un autre côté, cela permet de charger des images dans les e-mails HTML si vous ne vous souciez pas des implications en matière de confidentialité.

Affichage

Les options d'affichage doivent être placées dans la section [display] .

Voici une liste des options d'affichage :

Nom Valeur Par défaut Fonction

format-mode “auto” / [“bold”, “italic”, “underline”, “reverse”, “strike”, “overline”, “blink”] “auto” Spécifie les modes de formatage de sortie. Accepte la chaîne “auto” ou un tableau d'attributs spécifiques. Un tableau vide ([]) désactive complètement le formatage.
no-format-mode [“bold”, “italic”, “underline”, “reverse”, “strike”, “overline”, “blink”] “overline” Désactive des modes de formatage spécifiques.
image-mode “auto” / “none” / “sixel” / “kitty” “auto” Spécifie le mode de sortie d'images. “sixel” utilise les sixels pour la sortie, “kitty” utilise le protocole d'affichage d'images Kitty, “none” désactive complètement l'affichage des images. “auto” tente de détecter la prise en charge de sixel ou kitty, et revient à “none” si aucun des deux n'est disponible. sixel-colors “auto” / 2..65535 “auto” Ne s'applique que lorsque display.image-mode="sixel". Définir un nombre remplace le nombre de registres de couleurs sixel signalés par le terminal.
alt-screen “auto” / booléen “auto” Active/désactive l'écran alternatif.
highlight-color couleur “cyan” Définit la couleur de surlignage pour la recherche incrémentale et les marques. Les valeurs hexadécimales et les noms de couleurs CSS sont acceptés. En mode monochrome, ce réglage est ignoré ; à la place, la vidéo inversée est utilisée.
highlight-marks booléen true Active/désactive le surlignage des marques.
double-width-ambiguous booléen false Suppose que le terminal affiche les caractères de la catégorie East Asian Ambiguous comme des caractères de double largeur. Utile lorsque, par exemple, ○ occupe deux cellules.
minimum-contrast nombre 100 Spécifie la différence minimale entre la luminance (Y) de l'arrière-plan et celle du premier plan. -1 désactive cette fonction (c'est-à-dire autorise les lettres noires sur fond noir, etc.).
force-clear booléen false Force l'écran à être complètement effacé à chaque redessinage.
set-title booléen true Définit le titre de la fenêtre de l'émulateur de terminal sur celui de la page actuelle.
default-background-color “auto” / couleur “auto” Remplace la couleur d'arrière-plan supposée du terminal. “auto” laisse la détection de la couleur d'arrière-plan à Chawan.
default-foreground-color “auto” / couleur “auto” Définit la couleur de premier plan supposée du terminal. “auto” laisse la détection de la couleur de premier plan à Chawan.
query-da1 bool true Active/désactive l'interrogation des Attributs du Périphérique Principal (Primary Device Attributes), et avec elle, toute l'interrogation “dynamique” du terminal. Ne modifiez pas cette valeur à moins que Chawan ne vous l'ait dit ; la sortie sera affreuse.
columns, lines, pixels-per-column, pixels-per-line nombre 80, 24, 9, 18 Valeurs de repli pour le nombre de colonnes, de lignes, de pixels par colonne et de pixels par ligne dans les cas où cela ne peut pas être déterminé automatiquement. (Par exemple, ces valeurs sont utilisées en mode dump.)
force-columns, force-lines, force-pixels-per-column, force-pixels-per-line booléen false Force le nombre de colonnes, de lignes, de pixels par colonne ou de pixels par ligne aux valeurs de repli fournies ci-dessus.

Omnirègle

La barre omni (ouverte par défaut avec C-l) peut être utilisée pour effectuer des recherches en utilisant des omni-règles. Celles-ci doivent être spécifiées en tant que sous-clés du tableau [omnirule]. (La sous-clé elle-même est ignorée ; vous pouvez utiliser n'importe quoi tant qu'il n'entre pas en conflit avec d'autres clés.)

Exemples :

# Recherche avec DuckDuckGo Lite.
# (Cette règle est incluse dans la configuration par défaut, bien que C-k invoque
# la recherche Brave.)
[omnirule.ddg]
match = '^ddg:'
substitute-url = '(x) => "https://lite.duckduckgo.com/lite/?kp=-1&kd=-1&q=" + encodeURIComponent(x.split(":").slice(1).join(":"))'
# Pour utiliser la règle ci-dessus, ouvrez la barre d'URL avec C-k, effacez-la avec
# C-u, et tapez ddg:motclé.
# Alternativement, vous pouvez aussi redéfinir C-k comme :
[page]
'C-k' = '() => pager.load("ddg:")'
# Recherche avec Wikipédia, à la manière de Firefox.
# La syntaxe [[omnirule]] introduit une omnirègle anonyme ; elle est
# équivalente à celle avec un nom.
[[omnirule]]
match = '^@wikipedia'
substitute-url = '(x) => "https://en.wikipedia.org/wiki/Special:Search?search=" + encodeURIComponent(x.replace(/@wikipedia/, ""))'

Comme mentionné ci-dessus, la configuration par défaut inclut certaines règles intégrées, sélectionnées selon la préférence du mainteneur et le critère minimal qu'elles doivent fonctionner sans cookies ni JavaScript. Actuellement, celles-ci sont :

  • ddg: - DuckDuckGo Lite.
  • br: - Brave Search.
  • wk: - Wikipédia en anglais.
  • wd: - Wikitionary en anglais.
  • mo: - Mojeek.

Options d'omnirègle :

Nom Valeur Fonction
match expression régulière Expression régulière utilisée pour correspondre à la chaîne d'entrée. Notez que les sites web passés en arguments sont également appariés. Note : les expressions régulières sont traitées selon les règles de traitement des regexes du mode de correspondance.
substitute-url fonction JavaScript Une fonction JavaScript à laquelle Chawan passera la chaîne d'entrée. Si une nouvelle chaîne est retournée, elle sera analysée à la place de l'ancienne.

Siteconf

Des options de configuration peuvent être spécifiées pour des sites individuels. Les entrées doivent être spécifiées en tant que sous-clés du tableau [siteconf]. (La sous-clé elle-même est ignorée ; vous pouvez utiliser n'importe quoi tant qu'il n'entre pas en conflit avec d'autres clés.)

La plupart des options de siteconf peuvent également être spécifiées globalement ; voir le champ “overrides”.

Exemples :

# Activez les cookies sur le site orange pour la connexion.
[siteconf.hn]
url = 'https://news\.ycombinator\.com/.*'
cookie = true
# Redirige npr.org vers text.npr.org.
[siteconf.npr]
host = '(www\.)?npr\.org'
rewrite-url = '''
(x) => {
	x.host = "text.npr.org";
	const s = x.pathname.split('/');
	x.pathname = s.at(s.length > 2 ? -2 : 1);
	/* Pas besoin de retourner ; les objets URL sont passés par référence. */
}
'''
# Autorise le partage de cookies sur les domaines *sr.ht.
[siteconf.sr-ht]
host = '(.*\.)?sr\.ht' # soit 'something.sr.ht' soit 'sr.ht'
cookie = true # activez les cookies (lecture seule ; utilisez "save" pour les persister)
share-cookie-jar = 'sr.ht' # utilisez le cookie jar de 'sr.ht' pour tous les hôtes appariés
# Utilisez le thème "vector" sur Wikipédia.
# La syntaxe [[siteconf]] introduit une siteconf anonyme ; elle est
# équivalente à celles ci-dessus.
[[siteconf]]
url = '^https?://[a-z]+\.wikipedia\.org/wiki/(?!.*useskin=.*)'
rewrite-url = 'x => x.searchParams.append("useskin", "vector")'
# Faites en sorte qu'imgur nous envoie des images.
[siteconf.imgur]
host = '(i\.)?imgur\.com'
default-headers = {
	User-Agent = "Mozilla/5.0 chawan",
	Accept = "*/*",
	Accept-Encod{
	"ing": "\"gzip, deflate\"",
	"Accept-Language": "\"en;q=1.0\"",
	"Pragma": "\"no-cache\"",
	"Cache-Control": "\"no-cache\""
}
```

Options de configuration du site :

Nom Valeur Remplace Fonction
url regex n/a Expression régulière utilisée pour faire correspondre l'URL. L'une ou l'autre de cette option ou de l'option host doit être spécifiée. Remarque : les expressions régulières sont gérées conformément aux règles de gestion des expressions régulières du mode de correspondance.
host regex n/a Expression régulière utilisée pour faire correspondre la partie hôte de l'URL (c'est-à-dire le nom de domaine/l'adresse IP). L'une ou l'autre de cette option ou de l'option url doit être spécifiée. Remarque : les expressions régulières sont gérées conformément aux règles de gestion des expressions régulières du mode de correspondance.
rewrite-url Fonction JavaScript n/a Une fonction JavaScript à laquelle Chawan passera l'objet URL du site. Si une nouvelle URL est renvoyée, ou si l'objet URL est modifié d'une quelconque manière, Chawan redirigera l'utilisateur de manière transparente vers cette nouvelle URL.
cookie booléen / « save » buffer.cookie Indique si le chargement (avec « save », qui inclut également la sauvegarde) des cookies doit être autorisé pour cette URL.
share-cookie-jar host n/a Bac à biscuits à utiliser pour ce domaine. Utile par exemple pour partager des cookies avec des sous-domaines.
referer-from booléen buffer.referer-from Indique si un en-tête Referer doit être envoyé lors de l'ouverture de requêtes provenant de ce domaine. Exemple simplifié : si vous cliquez sur un lien sur a.com qui renvoie à b.com, et que referer-from est vrai, b.com reçoit « a.com » comme en-tête Referer.
scripting booléen / « app » buffer.scripting Active/désactive l'exécution de JavaScript sur ce site. Voir buffer.scripting pour plus de détails.
styling booléen buffer.styling Active/désactive les styles d'auteur (CSS) sur ce site.
images booléen buffer.images Active/désactive l'affichage des images sur ce site.

Raccourcis clavier

Les raccourcis clavier doivent être placés dans les sections suivantes :

  • pour l'interaction avec le pager : [page]
  • pour l'édition de ligne : [line]

Les raccourcis clavier sont configurés en utilisant la syntaxe

'<raccourci-clavier>' = '<action>'

Où <raccourci-clavier> est une combinaison de caractères Unicode avec ou sans modificateurs. Les modificateurs sont les préfixes C- et M-, qui ajoutent respectivement le contrôle ou l'échappement au raccourci clavier (rendant essentiellement M- identique à C-[). Les modificateurs peuvent être échappés avec le signe \.

<action> est soit une commande définie dans la section [cmd], soit une expression JavaScript. Nous décrivons ici uniquement les actions prédéfinies dans la configuration par défaut ; pour une description de l'API, veuillez consulter :

La documentation de l'API sur cha-api(7).

Exemples :

# afficher le changement d'URL lorsque Control, Escape et j sont pressés
'C-M-j' = 'load'
# aller à la première ligne de la page lorsque g est pressé deux fois sans nombre précédent
# ou à la ligne lorsqu'un nombre précédent est donné.
'gg' = 'gotoLineOrStart'
# les fonctions et expressions JS sont également acceptées. Ce qui suit remplace le
# moteur de recherche par défaut par DuckDuckGo Lite.
# (Voir api.md pour une liste des fonctions disponibles, et une discussion sur la façon
# d'ajouter vos propres commandes « namespacées » comme ci-dessus.)
'C-k' = '() => pager.load("ddg:")'

Annexe

Gestion des expressions régulières

Les expressions régulières sont actuellement gérées à l'aide de la bibliothèque libregexp de QuickJS. Cela signifie que toutes les expressions régulières fonctionnent comme en JavaScript.

Il existe deux modes de prétraitement des expressions régulières dans Chawan : le mode « recherche » et le mode « correspondance ». Le mode correspondance est utilisé pour les configurations (c'est-à-dire pour toutes les valeurs de ce document décrites comme « regex »). Le mode recherche est utilisé pour la fonction de recherche sur page (en utilisant searchForward/isearchForward, etc.).

Mode de correspondance

Les expressions régulières sont considérées comme des correspondances exactes, sauf lorsqu'elles commencent par un accent circonflexe (^) ou se terminent par un signe dollar ($) non échappé.

En d'autres termes, les transformations suivantes se produisent :

^abcd -> ^abcd (aucun changement, seule le début est trouvé)
efgh$ -> efgh$ (aucun changement, seule la fin est trouvée)
^ijkl$ -> ^ijkl$ (aucun changement, la ligne entière est trouvée)
mnop -> ^mnop$ (transformé en correspondance exacte, la ligne entière est trouvée)

Le mode correspondance n'a aucun moyen de basculer les indicateurs regex JavaScript comme i.

Mode de recherche

Pour la recherche sur page, les transformations ci-dessus ne s'appliquent pas ; la recherche /abcd recherche la chaîne abcd dans toutes les lignes.

Le mode de recherche offre également d'autres transformations pratiques (qui ne fonctionnent pas en mode correspondance) :

  • La chaîne \c (barre oblique inverse + c minuscule) dans une regex en mode recherche active la recherche insensible à la casse.
  • Inversement, \C (barre oblique inverse + C majuscule) désactive la recherche insensible à la casse. (Utile si ignore-case est défini sur true, ce qui est le comportement par défaut.)
  • \< et \> sont convertis en \b (comme dans vi, grep, etc.)

Comme le mode de correspondance, le mode de recherche opère sur des lignes individuelles. Cela signifie que les motifs de recherche ne correspondent pas au texte réparti sur plusieurs lignes.

Gestion des chemins

Les règles de gestion des chemins sont similaires à la façon dont le shell gère les chaînes.

  • L'expansion de tilde est utilisée pour déterminer le répertoire personnel de l'utilisateur. Ainsi, par exemple, ~/whatever fonctionne.
  • Les variables d'environnement peuvent être utilisées comme $ENV_VAR.
  • Les chemins relatifs sont relatifs au répertoire de configuration de Chawan (c'est-à-dire $CHA_DIR).

Certaines variables d'environnement sont également exportées par Chawan :

  • $CHA_BIN_DIR : le répertoire où se trouve le binaire cha. Les liens symboliques sont automatiquement résolus pour déterminer ce chemin.
  • $CHA_LIBEXEC_DIR : le répertoire pour tous les exécutables que Chawan utilise pour fonctionner. Par défaut, il s'agit de $CHA_BIN_DIR/../libexec/chawan.
  • $CHA_DIR : le répertoire de configuration. (Ceci peut également être défini par l'utilisateur ; voir la section supérieure pour plus de détails.)
  • $CHA_DATA_DIR : si le fichier de configuration utilise les répertoires de base XDG, il s'agit de ${XDG_DATA_HOME:-$HOME/.local/share}/chawan. Sinon, il est identique à $CHA_DIR.
•
Exception : si $CHA_DIR est défini avant que cha ne soit invoqué, alors $CHA_DATA_DIR est également lu. Ceci afin de permettre aux invocations imbriquées de fonctionner dans des configurations avec des répertoires de base XDG.

Types de mots

Les commandes de pager basées sur les mots peuvent fonctionner avec différentes définitions de mots. Actuellement, il existe :

  • Mots w3m
  • Mots vi
  • Grands mots

Mot w3m

Un mot w3m est une séquence de caractères alphanumériques. Les symboles sont traités de la même manière que les espaces blancs.

Mot vi

Un mot vi est une séquence de caractères de la même catégorie de caractères. Actuellement, les catégories de caractères sont les caractères alphanumériques, les symboles, les lettres han, hiragana, katakana et hangul.

Les mots vi peuvent être séparés par des espaces blancs ; cependant, les mots vi de catégories différentes ne doivent pas nécessairement être séparés par des espaces blancs. Par exemple, la séquence de caractères suivante contient deux mots :

hello[]+{}@`!

Grand mot

Un grand mot est une séquence de caractères non blancs.

C'est essentiellement la même chose qu'un mot w3m, mais les symboles sont définis comme non blancs.
