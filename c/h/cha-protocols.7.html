Protocole

s

Chawan prend en charge le téléchargement de ressources via divers protocoles : HTTP, FTP, SFTP, Gopher, Gemini, Spartan et Finger. Les détails sur ces protocoles, ainsi que des informations sur la manière dont les utilisateurs peuvent ajouter la prise en charge de leurs protocoles préférés, sont décrits dans ce

document.

Vous pouvez trouver les adaptateurs réseau dans le répertoire adapter/protocol de la distribution source. Pour les formats de fichiers spécifiques aux protocoles (comme le gemtext ou les répertoires Gopher), vous trouverez également un convertisseur HTML approprié dans adapter/format - notez que ceux-ci sont finalement compilés en un seul programme tohtml qui dispatche en fonction de son argv[0]. Schémas locaux : file:,

man:

Bien que ceux-ci ne soient pas nécessairement des protocoles, ils sont implémentés de manière similaire aux protocoles listés ci-dessus (et peuvent donc aussi être remplacés, si l'utilisateur le souhaite ; voir ci-dessous)

.

file: charge un fichier depuis le système de fichiers local. Dans le cas des répertoires, il affiche la liste du répertoire en utilisant dirlist2html comme pour

FTP.

man:, man-k: et man-l: sont des enveloppes autour des commandes man, man -k et man -l. Celles-ci recherchent des pages man en utilisant /usr/bin/man et transforment les références sur la page en liens. Une commande enveloppe mancha existe également ; elle a une interface similaire à man. (Cela était basé sur w3mman2html.cgi, mais ce

la a été réécrit en tant q
ue programme Nim autonome.)

Schémas internes : cgi-bin:, stream:, cache:, data:,

about:

Cinq protocoles internes existent : cgi-bin:, stream:, cache:, data: et about:. Ceux-ci sont les blocs de construction fondamentaux pour l'implémentation de chaque protocole mentionné ci-dessus ; pour cette raison, ceux-ci ne peuvent pas être remplacés et sont implémentés dans le binaire principal du

navigateur.

cgi-bin: exécute un script CGI local. Ce schéma est utilisé pour l'implémentation réelle des protocoles non internes mentionnés ci-dessus. Les scripts CGI locaux peuvent également être utilisés pour implémenter des enveloppes d'autres programmes dans Chawan (par exemple des dictionnaires)

.

stream: est utilisé pour les flux renvoyés par des programmes externes. Il diffère de cgi-bin: en ce qu'il ne coopère pas avec le processus externe, et que le chargeur ne suit pas d'où vient le flux. Par conséquent, il convient à la lecture de la sortie des entrées mailcap, ou pour transformer stdin en

URL.

Il n'est pas possible de recharger les URL stream:. Pour prendre en charge le rembobinage et « voir la source », la sortie des stream: est stockée dans un fichier cache jusqu'à ce que le buffer soit

détruit.

cache: n'est pas quelque chose qu'un utilisateur final verrait normalement ; il est utilisé pour le rembobinage ou la réinterprétation de flux déjà

téléchargés.

Le fonctionnement du cache est différent de celui de la plupart des autres navigateurs ; les fichiers sont chargés de manière déterministe cha-protocols(7) — Manuel Chawan

cha-protocols

7 — Protocoles pris en charge par Chawan

Protocoles

Les protocoles suivants sont pris en charge par Chawan :

http:, https:, ftp:
Ces protocoles sont récupérés à partir du cache ou du réseau selon certaines actions, mais aucun n'est utilisé comme solution de repli pour l'autre.
data:
Décode une URL de données telle que définie dans la RFC 2397. Il s'agissait auparavant d'un module CGI, mais il a été réintégré dans le processus de chargement car ces URL peuvent devenir si longues qu'elles ne tiennent plus dans l'environnement.
about:
Se trouve dans le chargeur pour permettre une implémentation du panneau de liste de téléchargement. Il devrait être transformé en module CGI une fois que le chargeur aura des capacités RPC.

Les pages about suivantes sont disponibles : about:chawan, about:blank, about:license, about:downloads.

Protocoles personnalisés

Le binaire cha lui-même ne sait pas grand-chose sur les protocoles listés ci-dessus ; il les charge plutôt via une combinaison de CGI locaux, urimethodmap, et si une conversion en HTML ou texte brut est nécessaire, mailcap (en utilisant x-htmloutput, x-ansioutput et copiosoutput).

urimethodmap peut également être utilisé pour remplacer les gestionnaires par défaut des protocoles listés ci-dessus. C'est similaire à la façon dont w3m vous permet de remplacer l'affichage par défaut de la liste des répertoires, mais beaucoup plus puissant ; de cette façon, n'importe quelle bibliothèque ou programme capable de récupérer et de sortir du texte via un certain protocole peut être combiné avec Chawan.

Par exemple, considérez la définition urimethodmap de finger :

finger:		cgi-bin:finger

Cela commande à Chawan de charger le script CGI finger, en définissant les variables $MAPPED_URI_* sur les parties de l'URL cible dans le processus.

Ensuite, finger utilise ces parties passées pour construire une commande curl appropriée qui récupérera l'URL finger: spécifiée ; il imprime l'en-tête 'Content-Type: text/plain' à la sortie, puis une ligne vide, puis le corps de la ressource récupérée. En cas d'erreur, il imprime plutôt un en-tête Cha-Control avec un code d'erreur et un message d'erreur spécifique.

Ajouter un nouveau protocole

Ici, nous allons ajouter un protocole appelé "cowsay", afin que l'URL cowsay:text affiche la sortie de cowsay text après une seconde d'attente.

mkdir -p ~/.chawan/cgi-bin, et créez un script CGI dans ~/.chawan/cgi-bin/cowsay.cgi :

#!/bin/sh
# Nous allons attendre une seconde à partir de maintenant, mais nous voulons que Chawan affiche
# "Téléchargement..." au lieu de "Connexion...". Donc, signaler au navigateur
# que la connexion a réussi.
printf 'Cha-Control: Connected\n'
sleep 1 # pause
# Status est un en-tête spécial qui signale le code d'état HTTP équivalent.
printf 'Status: 200' # HTTP OK
# Indiquer au navigateur qu'aucun autre en-tête de contrôle n'est à attendre.
# Ceci n'est utile que lorsque vous souhaitez envoyer des en-têtes reçus à distance ;
# dans ce cas, ce serait un vecteur d'attaque d'envoyer simplement les en-têtes sans
# ControlDone, car rien n'empêche le site Web d'envoyer un en-tête Cha-Control.
# Avec ControlDone envoyé, les en-têtes Cha-Control suivants seront
# interprétés comme des en-têtes normaux.
printf 'Cha-Control: ControlDone\n'
# Comme en HTTP, vous devez envoyer une ligne vide avant le corps.
printf '\n'
# Maintenant, imprimez le corps. Nous prenons le chemin passé à l'URL ; urimethodmap
# le définit comme MAPPED_URI_PATH. Il est encodé en URI, nous exécutons donc également l'utilitaire urldec
# dessus.
cowsay "$(printf '%s\n' "$MAPPED_URI_PATH" | "$CHA_LIBEXEC_DIR"/urldec)"

Maintenant, créez un fichier ".urimethodmap" dans votre répertoire $HOME.

Ensuite, entrez-y ce qui suit :

cowsay:		/cgi-bin/cowsay.cgi

Essayez maintenant cha cowsay:Hello,%20world.. Si vous avez tout fait correctement, cela devrait attendre une seconde, puis afficher une vache disant "Hello, world.".
