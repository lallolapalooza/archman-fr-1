CHPASSWD(8) Commandes de gestion système CHPASSWD(8)

NOM

chpasswd - mettre à jour les mots de passe en mode batch

SYNTAXE

chpasswd [options]

DESCRIPTION

La commande chpasswd lit une liste de paires nom d'utilisateur et mot de passe depuis l'entrée standard et utilise ces informations pour mettre à jour un groupe d'utilisateurs existants. Chaque ligne est du format :

nom_utilisateur:mot_de_passe

Par défaut, les mots de passe doivent être fournis en texte clair et sont chiffrés par chpasswd. L'âge du mot de passe sera également mis à jour s'il est présent.

Par défaut, les mots de passe sont chiffrés par PAM, mais (même si ce n'est pas recommandé) vous pouvez sélectionner une méthode de chiffrement différente avec les options -e, -m, ou -c.

Sauf lorsque PAM est utilisé pour chiffrer les mots de passe, chpasswd met d'abord à jour tous les mots de passe en mémoire, puis enregistre toutes les modifications sur le disque si aucune erreur n'est survenue pour aucun utilisateur.

Lorsque PAM est utilisé pour chiffrer les mots de passe (et mettre à jour les mots de passe dans la base de données système), si un mot de passe ne peut pas être mis à jour, chpasswd continue de mettre à jour les mots de passe des utilisateurs suivants et retournera un code d'erreur à la sortie.

Cette commande est destinée à être utilisée dans un environnement de système de grande taille où de nombreux comptes sont créés simultanément.

OPTIONS

Les options qui s'appliquent à la commande chpasswd sont :

-c, --crypt-method METHODE

Utilise la méthode spécifiée pour chiffrer les mots de passe.

Les méthodes disponibles sont DES, MD5, SHA256, SHA512, YESCRYPT et NONE si votre libc supporte ces méthodes.

Par défaut, PAM est utilisé pour chiffrer les mots de passe.

-e, --encrypted

Les mots de passe fournis sont sous forme chiffrée.

-h, --help

Affiche le message d'aide et quitte.

-m, --md5

Utilise le chiffrement MD5 au lieu de DES lorsque les mots de passe fournis ne sont pas chiffrés.

-R, --root REPERTOIRE_CHROOT

Applique les modifications dans le répertoire REPERTOIRE_CHROOT et utilise les fichiers de configuration du répertoire REPERTOIRE_CHROOT. Seuls les chemins absolus sont pris en charge.

-P, --prefix REPERTOIRE_PREFIXE

Applique les modifications aux fichiers de configuration sous le système de fichiers racine trouvé dans le répertoire REPERTOIRE_PREFIXE. Cette option ne fait pas de chroot et est destinée à la préparation d'une cible de compilation croisée. Certaines limitations : les utilisateurs/groupes NIS et LDAP ne sont pas vérifiés. L'authentification PAM utilise les fichiers de l'hôte. Pas de support SELINUX.

-s, --sha-rounds TOURS

Utilise le nombre spécifié de tours pour chiffrer les mots de passe.

Vous ne pouvez utiliser cette option qu'avec les méthodes de chiffrement : SHA256, SHA512, YESCRYPT.

Par défaut, le nombre de tours pour SHA256 ou SHA512 est défini par les variables SHA_CRYPT_MIN_ROUNDS et SHA_CRYPT_MAX_ROUNDS dans /etc/login.defs.

Une valeur minimale de 1000 et une valeur maximale de 999 999 999 seront appliquées pour SHA256 et SHA512. Le nombre par défaut de tours est de 5000.

Par défaut, le nombre de tours pour YESCRYPT est défini par YESCRYPT_COST_FACTOR dans /etc/login.defs.

Une valeur minimale de 1 et une valeur maximale de 11 seront appliquées pour YESCRYPT. Le nombre par défaut de tours est de 5.

AVERTISSEMENTS

N'oubliez pas de définir les permissions ou l'umask pour empêcher la lecture des fichiers non chiffrés par d'autres utilisateurs.

CONFIGURATION

Les variables de configuration suivantes dans /etc/login.defs modifient le comportement de cet outil :

SHA_CRYPT_MIN_ROUNDS (nombre), SHA_CRYPT_MAX_ROUNDS (nombre)

Lorsque ENCRYPT_METHOD est défini sur SHA256 ou SHA512, ceci définit le nombre de tours SHA utilisés par l'algorithme de chiffrement par défaut (lorsque le nombre de tours n'est pas spécifié sur la ligne de commande).

Avec un grand nombre de tours, il est plus difficile de casser le mot de passe par force brute. Mais notez également que plus de ressources CPU seront nécessaires pour authentifier les utilisateurs.

Si non spécifié, la libc choisira le nombre de tours par défaut (5000), ce qui est beaucoup trop faible pour le matériel moderne.

Les valeurs doivent être comprises dans la plage 1000-999 999 999.

Si seule l'une des valeurs SHA_CRYPT_MIN_ROUNDS ou SHA_CRYPT_MAX_ROUNDS est définie, alors cette valeur sera utilisée.

Si SHA_CRYPT_MIN_ROUNDS > SHA_CRYPT_MAX_ROUNDS, la valeur la plus élevée sera utilisée.

Remarque : Ceci n'affecte que la génération des mots de passe de groupe. La génération des mots de passe d'utilisateur est effectuée par PAM et soumise à la configuration PAM. Il est recommandé de définir cette variable de manière cohérente avec la configuration PAM.

YESCRYPT_COST_FACTOR (nombre)

Lorsque ENCRYPT_METHOD est défini sur YESCRYPT, ceci définit le facteur de coût utilisé par l'algorithme de chiffrement par défaut (lorsque le facteur de coût n'est pas spécifié sur la ligne de commande).

Avec un facteur de coût élevé, il est plus difficile de casser le mot de passe par force brute. Mais notez également que plus de ressources CPU seront nécessaires pour authentifier les utilisateurs.

La valeur doit être comprise dans la plage 1-11.

Remarque : Ceci n'affecte que la génération des mots de passe de groupe. La génération des mots de passe d'utilisateur est effectuée par PAM et soumise à la configuration PAM. Il est recommandé de définir cette variable de manière cohérente avec la configuration PAM.
