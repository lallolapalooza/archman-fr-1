CK_HS_INIT(3) Manuel des fonctions de bibliothèque CK_HS_INIT(3)

NOM

ck_hs_init — initialiser un ensemble de hachage

BIBLIOTHÈQUE

Concurrency Kit (libck, -lck)

SYNOPSIS

#include <ck_hs.h>

typedef unsigned long
ck_hs_hash_cb_t(const void *key, unsigned long seed);

typedef bool
ck_hs_compare_cb_t(const void *c1, const void *c2);

bool
ck_hs_init(ck_hs_t *hs, unsigned int mode, ck_hs_hash_cb_t *hash_function, ck_hs_compare_cb_t *compare, struct ck_malloc *allocator, unsigned long capacity, unsigned long seed);

DESCRIPTION

La ck_hs_init() fonction initialise l'ensemble de hachage auquel pointe le pointeur hs .

L'argument mode spécifie le type de paires clé-valeur à stocker dans l'ensemble de hachage ainsi que le modèle d'accès concurrent attendu. La valeur de mode se compose d'un champ de bits contenant l'un des éléments suivants :

CK_HS_MODE_OBJECT
L'ensemble de hachage est destiné à stocker des pointeurs vers des objets. Cela fournit un indice selon lequel seuls CK_MD_VMA_BITS sont nécessaires pour encoder l'argument clé. Tout bit de pointeur inutilisé est exploité pour des optimisations internes.
CK_HS_MODE_DIRECT
L'ensemble de hachage est destiné à stocker directement des valeurs de clés et tous les bits de la clé sont utilisés pour encoder les valeurs.

Le modèle d'accès concurrent est spécifié par :

CK_HS_MODE_SPMC
L'ensemble de hachage devrait permettre des lecteurs concurrents en présence d'un seul écrivain.
CK_HS_MODE_MPMC
L'ensemble de hachage devrait permettre des lecteurs concurrents en présence d'écrivains concurrents. Cela n'est actuellement pas pris en charge.

Le développeur est libre de spécifier des indices de charge de travail supplémentaires. Ces indices sont l'un des suivants :

CK_HS_MODE_DELETE
On s'attend à ce que l'ensemble de hachage ait une charge de travail axée sur la suppression. Au prix d'une augmentation d'environ 13 % de l'utilisation de la mémoire, cela permet des limites de sondage par emplacement plus strictes pour combattre les effets de l'accumulation de pierres tombales.

L'argument hash_function est un pointeur obligatoire vers une fonction de hachage spécifiée par l'utilisateur. Une fonction de hachage spécifiée par l'utilisateur prend deux arguments. L'argument key est un pointeur vers une clé. L'argument seed est la graine initiale associée à l'ensemble de hachage. Cette graine initiale est spécifiée par l'utilisateur dans ck_hs_init(3).

L'argument compare est un pointeur facultatif vers une fonction de comparaison de clés spécifiée par l'utilisateur. Si NULL est spécifié dans cet argument, l'égalité des pointeurs sera utilisée pour déterminer l'égalité des clés. Une fonction de comparaison spécifiée par l'utilisateur prend deux arguments représentant des pointeurs vers les objets dont on compare l'égalité. Elle doit renvoyer true si les clés ont la même valeur et false sinon.

L'argument allocator est un pointeur vers une structure contenant les pointeurs de fonctions malloc et free qui définissent respectivement les fonctions d'allocation et de destruction de mémoire à utiliser par l'ensemble de hachage en cours d'initialisation.

L'argument capacity représente le nombre initial de clés que l'ensemble de hachage est censé contenir. Cet argument est simplement un indice et l'implémentation sous-jacente est libre d'allouer plus ou moins de mémoire que nécessaire pour contenir le nombre d'entrées capacity spécifié.

L'argument seed spécifie la graine initiale utilisée par la fonction de hachage sous-jacente. L'utilisateur est libre de choisir une valeur de son choix.

VALEURS RENVOYÉES

En cas de réussite ck_hs_init() renvoie la valeur true et renvoie sinon la valeur false pour indiquer une erreur.

ERREURS

Le comportement de ck_hs_init() est indéfini si hs n'est pas un pointeur vers un objet ck_hs_t .
