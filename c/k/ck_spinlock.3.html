DESCRIPTIO

N

Une famille d'implémentations de verrous à rotation (spinlock) en attente active. L'implémentation ck_spinlock_t est simplement un empaquetage autour de l'implémentation échange-récupération (ck_spinlock_fas_t). Le tableau ci-dessous fournit un résumé des implémentations

actuelles. 
|            Espace de noms | Algorithme                  | Type          | Restrictions            | Équitable |
´----------------------|-----------------------------|---------------|-------------------------|-----------'
  ck_spinlock_anderson   Anderson                      Tableau        Nombre fixe de fils       Oui
       ck_spinlock
_cas Compare-and-Swap Centralisé Aucune Non ck_spinlock_clh Craig, Landin et Hagersten File Exigences de durée de vie Oui ck_spinlock_dec Décrément (noyau Linux) Centralisé Concurrency UINT_MAX Non ck_spinlock_fas Fetch-and-store Centr
alisé Aucune Non ck_spinlock_hclh CLH hiérarchique File Exigences de durée de vie Oui * ck_spinlock_mcs Mellor-Crummey et Scott File Aucune Oui ck_spinlock_ticket Ticket Centralisé Aucune Oui

* Le CLH hiérarchique n'offre qu'une équité faible pour les fils à travers les nœuds de

cluster.

Si la contention est faible et qu'il n'y a pas d'exigence stricte d'absence de famine, un verrou centralisé avide (inéquitable) est recommandé. Si la contention est élevée et qu'il n'y a pas d'exigence d'absence de famine, un verrou centralisé avide est recommandé à utiliser avec un mécanisme de backoff exponentiel. Si la contention est généralement faible et qu'il y a une exigence stricte d'absence de famine, le verrou ticket est recommandé. Si la contention est élevée et qu'il y a une exigence stricte d'absence de famine, le verrou à file Craig, Landin et Hagersten est recommandé, sauf si une allocation sur la pile est nécessaire ou si le facteur NUMA est élevé, auquel cas le verrou Mellor-Crummey et Scott est recommandé. Si vous ne pouvez pas vous permettre une utilisation d'espace O(n) des verrous à tableau ou à file mais exigez toujours l'équité sous forte contention, alors le verrou ticket avec backoff proportionnel est recommandé. Si le facteur NUMA est élevé mais que vous préférez un verrou avide, alors veuillez consulter ck_coh

ort(
3).

EXEMPL

E 
#include <ck_spinlock.h>
#include <stdbool.h>

/*
 * Alternativement, le mutex peut être initialisé à l'exécution avec
 * ck_spinlock_init(&mutex).
 */
ck_spinlock_t mutex = CK_SPINLOCK_INITIALIZER;

void
example(void)
{

        ck_spinlock_lock(&mutex);
        /*
         * Section critique.
         */
        ck_spinlock_unlock(&mutex);

        ck_spinlock_lock_eb(&mutex);
        /*
         * Section critique.
         */
        ck_spinlock_unlock(&mutex);

        if (ck_spinlock_trylock(&mutex) == true) {
                /*
                 * Section critique.
                 */
                ck_spinlock_unlock(&mutex);
}
}
