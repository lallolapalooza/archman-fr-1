NOM

ckpasswd - Authentificateur de mot de passe pour nnrpd

SYNTAXE

ckpasswd [-gs] [-d base de données] [-f nom de fichier] [-u nom d'utilisateur -p mot de passe]

DESCRIPTION

ckpasswd est l'authentificateur de mot de passe de base pour nnrpd, adapté pour être exécuté à partir d'une section auth dans readers.conf. Voir readers.conf(5) pour plus d'informations sur la configuration d'un authentificateur nnrpd.

ckpasswd accepte un nom d'utilisateur et un mot de passe de nnrpd et indique à nnrpd(8) si c'est le mot de passe correct pour cet utilisateur. Par défaut, lorsqu'il est appelé sans arguments, il tente de vérifier le mot de passe en utilisant PAM si le support de PAM a été trouvé lors de la compilation de INN. À défaut, il tente de vérifier le mot de passe par rapport au champ de mot de passe renvoyé par getpwnam(3). Notez que de nos jours, la plupart des systèmes ne rendent plus les vrais mots de passe disponibles via getpwnam(3) (certains le font encore si et seulement si le programme appelant getpwnam(3) s'exécute en tant que root).

Lors de l'utilisation de PAM, ckpasswd s'identifie comme "nnrpd", et non comme "ckpasswd", et la configuration PAM doit être configurée en conséquence. Les détails de la configuration PAM varient selon les systèmes d'exploitation (et même selon les distributions Linux) ; voir les "EXEMPLES" ci-dessous pour commencer, et cherchez une page de manuel pam(7) ou pam.conf(4) sur votre système.

Lors de l'utilisation d'une méthode autre que PAM, ckpasswd s'attend à ce que tous les mots de passe soient stockés cryptés par la fonction crypt(3) du système et appelle crypt(3) sur le mot de passe fourni avant de le comparer au mot de passe attendu. Tout algorithme de hachage de mot de passe supporté par votre libc ou libcrypt peut être utilisé.

OPTIONS

-d base de données
Lire les mots de passe à partir d'une base de données (format ndbm, gdbm ou dbm selon ce que votre système possède) plutôt qu'en utilisant getpwnam(3). ckpasswd s'attend à ce que base de données.dir et base de données.pag existent et constituent une base de données indexée par le nom d'utilisateur avec les mots de passe cryptés comme valeurs.

Bien qu'INN ne fournisse pas de programme spécifiquement conçu pour créer de telles bases de données, sur la plupart des systèmes, il est assez facile d'écrire un script Perl pour le faire. Quelque chose comme :

#!/usr/bin/perl
use NDBM_File;
use Fcntl;
tie (%db, 'NDBM_File', '/chemin/vers/base_de_donnees', O_RDWR|O_CREAT, 0640)
    or die "Impossible d'ouvrir /chemin/vers/base_de_donnees: $!\n";
$| = 1;
print "Nom d'utilisateur: ";
my $user = <STDIN>;
chomp $user;
print "Mot de passe: ";
my $passwd = <STDIN>;
chomp $passwd;
my @alphabet = ('.', '/', 0..9, 'A'..'Z', 'a'..'z');
my $salt = join '', @alphabet[rand 64, rand 64];
$db{$user} = crypt ($passwd, $salt);
untie %db;

Notez que cela renverra le mot de passe lorsqu'il sera tapé ; des améliorations évidentes pourraient être apportées à cela, mais cela devrait être un point de départ raisonnable. Parfois, un programme comme celui-ci est disponible sous le nom de dbmpasswd.

Cette option ne sera pas disponible sur les systèmes sans bibliothèques ndbm, gdbm ou dbm.

-f nom de fichier
Lire les mots de passe à partir du fichier spécifié plutôt que d'utiliser getpwnam(3). Chaque ligne du fichier doit ressembler à ceci : 
nom_utilisateur:$5$Hlb2yXPd$2nOO/QR9P1mnRFr/i6L9ybxbgSDXd4UlatKqbcY4eoB
joe:FCjOJnpOo50IE:Ancien algorithme de hachage faible utilisé pour Joe

Chaque ligne contient au moins deux champs séparés par un deux-points. Le premier champ contient le nom d'utilisateur ; le second champ contient un mot de passe haché avec la fonction crypt(3). Des deux-points et des données supplémentaires peuvent apparaître après le mot de passe crypté ; ces données seront ignorées par ckpasswd. Les lignes commençant par un signe dièse ("#") sont ignorées.

INN ne fournit pas d'utilitaire pour créer les mots de passe cryptés, mais OpenSSL peut le faire et c'est aussi une tâche rapide avec Perl (voir le script d'une ligne ci-dessous).

Une ligne dans nom de fichier pour l'utilisateur "utilisateur" avec le mot de passe "motdepasse" serait "utilisateur:" suivie de la sortie de la commande suivante en utilisant SHA-256 comme schéma de hachage :

% openssl passwd -5 motdepasse
$5$UIhtJSBOaC0Ap3Vk$nbKgmykshoQ2HmvA3s/nI.X4uhhNHBKTYhBS3pYLjJ6

Voir la page de manuel de openssl-passwd(1) pour la liste des schémas de hachage qu'il peut générer. Vous devez choisir un schéma que votre fonction crypt(3) du système gère (tapez "man 3 crypt" ou "man 5 crypt" pour trouver les schémas de hachage supportés).

Si OpenSSL n'est pas installé sur votre serveur, vous pouvez également utiliser la commande Perl suivante qui fait le même travail avec SHA-256 (voir les détails ci-dessous pour définir "VotreSel" sur une valeur appropriée ; 5 est le préfixe pour SHA-256, qui n'attend aucun paramètre) :

% perl -le 'print crypt("motdepasse", q{$5$VotreSel$})'
$5$VotreSel$V5hqwFg1nhKb5as6md9KTe5b2NyavsMS6dBYVKfp5W7

Comme Perl utilise crypt(3), vous avez accès à tous les schémas de hachage disponibles sur vos systèmes. Par exemple, si yescript est supporté, vous pouvez générer un mot de passe crypté avec un argument comme "$y$j9T$VotreSel$" à la fonction Perl crypt, où "y" est le préfixe pour yescript, "j9T" les paramètres passés à crypt_gensalt(3) pour générer le mot de passe haché (ces paramètres contrôlent la configuration yescript, et correspondent dans cet exemple au drapeau "YESCRYPT_DEFAULTS", la saveur recommandée qui a la valeur "j" en 2023, avec un facteur de coût de 4096 comme nombre de blocs et 32 comme taille de bloc) et "VotreSel" une chaîne qui doit être choisie au hasard et différente pour chaque utilisateur. La syntaxe et la longueur optimale du sel dépendent du schéma de hachage (par exemple, une longueur multiple de 4 pour yescript) et des recommandations cryptographiques (par exemple, au moins 32 bits aléatoires de longueur, suivant les recommandations NIST SP 800-63B en 2023).

Pour résumer, dans la commande suivante, vous devez seulement changer le mot de passe "motdepasse" et la chaîne aléatoire "VotreSel", différente pour chaque utilisateur, et laisser le reste de la commande tel quel :

% perl -le 'print crypt("motdepasse", q{$y$j9T$VotreSel$})'
$y$j9T$VotreSel$X4tB48vKNDT6mK0vNOc7ppKPWvEsyMg5LwoQfO50r2A

Un sel aléatoire de 12 caractères peut être obtenu avec la commande suivante (le résultat correspond à 72 bits aléatoires car chaque caractère est sélectionné dans une plage de 6 bits parmi 64 caractères possibles) :

% perl -le 'print join("",
      (".", "/", 0..9, A..Z, a..z)[map {rand 64} (1..12)])'
k2W/17eJu58r
-g
Tenter de rechercher le groupe système correspondant au nom d'utilisateur et retourner une chaîne telle que "utilisateur@groupe" à faire correspondre dans readers.conf. Cette option est incompatible avec les options -d et -f.
-p mot de passe
Utiliser mot de passe comme mot de passe pour l'authentification plutôt que de lire un mot de passe en utilisant le protocole d'authentificateur nnrpd. Cette option est utile uniquement pour tester votre système d'authentification (en particulier car elle implique de mettre un mot de passe sur la ligne de commande), et ne fonctionne pas lorsque ckpasswd est exécuté par nnrpd. Si cette option est donnée, -u doit également être donné.
-s
Vérifier les mots de passe par rapport au résultat de getspnam(3) au lieu de getpwnam(3). Cette fonction, sur les systèmes qui la supportent, lit à partir de i

EXEMPLES

Pour utiliser PAM pour l'authentification, vous devrez configurer votre fichier de configuration PAM. Sur la plupart des systèmes Linux, cela signifie créer un fichier appelé "/etc/pam.d/nnrpd" qui contient des lignes telles que :

auth       required     pam_unix.so
account    required     pam_unix.so

Vous pourriez aussi vouloir ajouter des restrictions sur quels utilisateurs sont autorisés à se connecter ; par exemple, pour n'autoriser que les utilisateurs qui sont dans le groupe "usenet", vous ajouteriez la ligne suivante à la section `account`:

account    required     pam_group.so even_deny group=usenet

La configuration exacte dépend de votre système et des modules PAM que vous avez disponibles. Vous pourriez avoir besoin de consulter la documentation de votre système pour plus de détails.

La plupart des systèmes nécessitent des privilèges spéciaux pour appeler getspnam(3), donc afin d'utiliser cette option, vous devrez peut-être rendre ckpasswd setgid sur un groupe (comme le groupe "shadow") ou même setuid root. ckpasswd n'a pas été spécifiquement audité pour de telles utilisations ! C'est cependant un très petit programme que vous devriez pouvoir vérifier à la main pour des raisons de sécurité.

-u nom d'utilisateur
S'authentifier en tant que nom d'utilisateur. Cette option est utile uniquement pour les tests (afin que vous puissiez tester facilement votre système d'authentification) et ne fonctionne pas lorsque ckpasswd est exécuté par nnrpd. Si cette option est donnée, -p doit également être donné.

EXEMPLES

Voir readers.conf(5) pour des exemples de configuration d'authentification de nnrpd(8) qui utilise ckpasswd pour vérifier les mots de passe.

Une configuration PAM d'exemple pour /etc/pam.conf qui indique à ckpasswd de vérifier les noms d'utilisateur et les mots de passe par rapport aux comptes système est :

nnrpd auth    required pam_unix.so
nnrpd account required pam_unix.so

Votre système peut vous demander de créer plutôt un fichier nommé nnrpd dans /etc/pam.d avec des lignes comme :

auth    required pam_unix.so
account required pam_unix.so

Ce n'est que la configuration la plus simple. Vous pourrez peut-être inclure des fichiers partagés communs, et vous pourriez vouloir empiler d'autres modules, soit pour permettre différentes méthodes d'authentification, soit pour appliquer des restrictions telles que des listes d'utilisateurs qui ne peuvent pas s'authentifier en utilisant ckpasswd. Le meilleur guide est la documentation de votre système et les autres configurations PAM que vous utilisez déjà.

Pour tester et vous assurer que ckpasswd fonctionne correctement, vous pouvez l'exécuter manuellement, puis lui fournir le nom d'utilisateur (précédé de "ClientAuthname:") et le mot de passe (précédé de "ClientPassword:") sur l'entrée standard. Par exemple :

(echo 'ClientAuthname: test' ; echo 'ClientPassword: testing') \
    | ckpasswd -f /chemin/vers/fichier/passwd

vérifiera un nom d'utilisateur de "test" et un mot de passe de "testing" par rapport aux noms d'utilisateur et mots de passe stockés dans /chemin/vers/fichier/passwd. En cas de succès, ckpasswd affichera "User:test" et se terminera avec le statut 0. En cas d'échec, il affichera un message d'erreur et se terminera avec un statut non nul.
