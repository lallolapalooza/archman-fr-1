CKSUM(1) Commandes utilisateur CKSUM(1)

NOM

cksum — calculer et vérifier les sommes de contrôle de fichiers

SYNTAXE

cksum [OPTION]... [FICHIER]...

DESCRIPTION

Affiche ou vérifie les sommes de contrôle. Par défaut, utilise l'algorithme CRC sur 32 bits.

Sans FICHIER, ou lorsque FICHIER est -, lit l'entrée standard.

Les arguments obligatoires des options longues sont aussi obligatoires pour les options courtes.

-a, --algorithm=TYPE
sélectionne le type de résumé à utiliser. Voir RESUMÉ ci-dessous.
--base64
émet des résumés encodés en base64, pas en hexadécimal.
-c, --check
lit les sommes de contrôle depuis les FICHIERS et les vérifie.
-l, --length=BITS
longueur du résumé en bits ; ne doit pas dépasser la taille maximale et doit être un multiple de 8 pour blake2b ; doit être 224, 256, 384 ou 512 pour sha2 ou sha3.
--raw
émet un résumé binaire brut, pas hexadécimal.
--tag
crée une somme de contrôle de style BSD (par défaut).
--untagged
crée une somme de contrôle de style inversé, sans type de résumé.
-z, --zero
termine chaque ligne de sortie avec NUL, pas avec une nouvelle ligne, et désactive l'échappement des noms de fichiers.

Les cinq options suivantes sont utiles uniquement lors de la vérification des sommes de contrôle :

--ignore-missing
ne pas échouer ou signaler l'état pour les fichiers manquants.
--quiet
ne pas afficher OK pour chaque fichier vérifié avec succès.
--status
ne rien afficher, le code d'état indique le succès.
--strict
quitter avec un code non nul pour les lignes de somme de contrôle mal formatées.
-w, --warn
avertir des lignes de somme de contrôle mal formatées.
--debug
indiquer quelle implémentation est utilisée.
--help
afficher cette aide et quitter.
--version
afficher les informations de version et quitter.

RESUMÉ détermine l'algorithme de résumé et le format de sortie par défaut :

sysv
(équivalent à sum -s).
bsd
(équivalent à sum -r).
crc
(équivalent à cksum).
crc32b
(uniquement disponible via cksum).
md5
(équivalent à md5sum).
sha1
(équivalent à sha1sum).
sha2
(équivalent à sha{224,256,384,512}sum).
sha3
(uniquement disponible via cksum).
blake2b
(équivalent à b2sum).
sm3
(uniquement disponible via cksum).

Lors de la vérification, l'entrée doit être une sortie antérieure de ce programme, ou d'un programme autonome équivalent.

    CKSUM(1) Manuel de l'utilisateur CKSUM(1)

    NOM

    cksum - vérifie l'intégrité d'un fichier

    SYNOPSIS

    cksum [FICHIER]...

    DESCRIPTION

    Calcule et affiche la somme de contrôle cyclique de Redundancy Check (CRC) et le nombre d'octets pour chaque FICHIER. S'il n'y a pas de FICHIER, ou si un FICHIER est-, la somme de contrôle est lue à partir de l'entrée standard.

    Le format de sortie est :

    CRC FICHIER octets

    Cette commande est utile pour vérifier l'intégrité des données lors de transferts de fichiers. La commande cksum utilise l'algorithme CRC à 32 bits, différent de la commande sum qui utilise un algorithme simple d'addition.

    OPTIONS

    Cette commande ne prend pas en charge les options longues.

    BOGUES

    Les versions antérieures utilisaient l'algorithme sum. Il n'y a aucune norme pour le format de sortie, donc d'autres programmes qui vérifient les sommes de contrôle peuvent ne pas utiliser cksum.

    VOIR AUSSI

    md5sum(1), sha1sum(1), sha224sum(1), sha256sum(1), sha384sum(1), sha512sum(1), sum(1)
