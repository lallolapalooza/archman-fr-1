CK_RHS_INIT(3) Manuel des fonctions de bibliothèque CK_RHS_INIT(3)

NOM

ck_rhs_init — initialiser un ensemble de hachage

BIBLIOTHÉQUE

Concurrency Kit (libck, -lck)

SYNTAXE

#include <ck_rhs.h>

typedef unsigned long
ck_rhs_hash_cb_t(const void *key, unsigned long seed);

typedef bool
ck_rhs_compare_cb_t(const void *c1, const void *c2);

bool
ck_rhs_init(ck_rhs_t *hs, unsigned int mode, ck_rhs_hash_cb_t *hash_function, ck_rhs_compare_cb_t *compare, struct ck_malloc *allocator, unsigned long capacity, unsigned long seed);

DESCRIPTION

La fonction ck_rhs_init() initialise l'ensemble de hachage pointé par le pointeur hs.

L'argument mode spécifie le type de paires clé-valeur à stocker dans l'ensemble de hachage ainsi que le modèle d'accès concurrent attendu. La valeur de mode consiste en un champ de bits de l'un des suivants :

CK_RHS_MODE_OBJECT
L'ensemble de hachage est destiné à stocker des pointeurs vers des objets. Cela fournit un indice indiquant que seuls les CK_MD_VMA_BITS sont nécessaires pour encoder l'argument clé. Tous les bits de pointeur inutilisés sont exploités pour des optimisations internes.
CK_RHS_MODE_DIRECT
L'ensemble de hachage est destiné à stocker directement des valeurs de clé et que tous les bits de la clé sont utilisés pour encoder des valeurs.
CK_RHS_MODE_READ_MOSTLY
Optimiser les opérations de lecture par rapport aux opérations de mise en place/suppression.

Le modèle d'accès concurrent est spécifié par :

CK_RHS_MODE_SPMC
L'ensemble de hachage doit permettre des lecteurs concurrents en présence d'un seul écrivain.
CK_RHS_MODE_MPMC
L'ensemble de hachage doit permettre des lecteurs concurrents en présence d'écrivains concurrents. Ceci n'est actuellement pas supporté.

Le développeur est libre de spécifier des indices de charge de travail supplémentaires. Ces indices sont :

L'argument hash_function est un pointeur obligatoire vers une fonction de hachage spécifiée par l'utilisateur. Une fonction de hachage spécifiée par l'utilisateur prend deux arguments. L'argument key est un pointeur vers une clé. L'argument seed est la graine initiale associée à l'ensemble de hachage. Cette graine initiale est spécifiée par l'utilisateur dans ck_rhs_init(3).

L'argument compare est un pointeur optionnel vers une fonction de comparaison de clé spécifiée par l'utilisateur. Si NULL est spécifié dans cet argument, alors l'égalité des pointeurs sera utilisée pour déterminer l'égalité des clés. Une fonction de comparaison spécifiée par l'utilisateur prend deux arguments représentant des pointeurs vers les objets comparés pour l'égalité. Elle est censée renvoyer vrai si les clés ont la même valeur et faux sinon.

L'argument allocator est un pointeur vers une structure contenant des pointeurs de fonction malloc et free qui définissent respectivement les fonctions d'allocation et de destruction de mémoire à utiliser par l'ensemble de hachage à initialiser.

L'argument capacity représente le nombre initial de clés que l'ensemble de hachage est censé contenir. Cet argument n'est qu'un indice et l'implémentation sous-jacente est libre d'allouer plus ou moins de mémoire que nécessaire pour contenir le nombre d'entrées spécifié par capacity.

L'argument seed spécifie la graine initiale utilisée par la fonction de hachage sous-jacente. L'utilisateur est libre de choisir une valeur de son choix.

VALEURS DE RETOUR

En cas de succès, ck_rhs_init() renvoie la valeur true et sinon renvoie la valeur false pour indiquer une erreur.

ERREURS

Le comportement de ck_rhs_init() est indéfini si hs n'est pas un pointeur vers un objet ck_rhs_t.
