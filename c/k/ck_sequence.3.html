ck_sequence(3) Manuel des fonctions de bibliothèque ck_sequence(3)

NOM

ck_sequence_init, ck_sequence_read_begin, ck_sequence_read_retry, ck_sequence_write_begin, ck_sequence_write_end — verrous de séquence

BIBLIOTHÈQUE

Concurrency Kit (libck, -lck)

SYNOPSIS

#include <ck_sequence.h>

ck_sequence_t seqlock = CK_SEQUENCE_INITIALIZER;


void
ck_sequence_init(ck_sequence_t *sq);

unsigned int
ck_sequence_read_begin(const ck_sequence_t *sq);

bool
ck_sequence_read_retry(const ck_sequence_t *sq, unsigned int version);

void
ck_sequence_write_begin(ck_sequence_t *sq);

void
ck_sequence_write_end(ck_sequence_t *sq);

DESCRIPTION

Il est recommandé d'utiliser ck_sequence lorsqu'une petite quantité de données qui ne peuvent pas être accédées de manière atomique doit être synchronisée avec les lecteurs d'une manière qui ne bloque aucun écrivain. Les lecteurs peuvent exécuter leurs sections critiques côté lecture sans aucune opération atomique. Une ck_sequence_t doit être initialisée avant utilisation. Elle peut être initialisée en utilisant soit un initialiseur statique (CK_SEQUENCE_INITIALIZER), soit en utilisant ck_sequence_init(). Avant que les lecteurs tentent de lire des données qui peuvent être modifiées concurremment, ils doivent d'abord enregistrer la valeur de retour de ck_sequence_read_begin(). Pendant ou après que le lecteur a terminé la copie des données associées à une ck_sequence_t, il doit passer la valeur de retour antérieure de ck_sequence_read_begin() à ck_sequence_read_retry(). Si ck_sequence_read_retry() renvoie true, alors la copie des données peut être incohérente et le processus de lecture doit être retenté. Les écrivains doivent s'appuyer sur leurs propres primitives de synchronisation. Une fois qu'un écrivain a accédé à sa section critique respective, il doit appeler ck_sequence_write_begin() pour signaler son intention de mettre à jour les données protégées par la ck_sequence_t. Avant que l'écrivain ne quitte sa section critique, il doit exécuter ck_sequence_write_end() pour indiquer que les mises à jour ont laissé les objets respectifs dans un état cohérent.

EXEMPLE

#include <ck_sequence.h>
#include <stdlib.h>

static struct example {
	int a;
	int b;
	int c;
} global;

static ck_sequence_t seqlock = CK_SEQUENCE_INITIALIZER;

void
reader(void)
{
	struct example copy;
	unsigned int version;

	/*
	 * Tente une lecture de la structure de données. Si la structure
	 * a été modifiée entre ck_sequence_read_begin et
	 * ck_sequence_read_retry alors retente une lecture puisque
	 * les données peuvent être dans un état incohérent.
	 */
	do {
		version = ck_sequence_read_begin(&seqlock);
		copy = global;
	} while (ck_sequence_read_retry(&seqlock, version));

	/*
	 * Ce qui précède peut également être exprimé à l'aide de CK_SEQUENCE_READ.
	 * Il est généralement recommandé d'utiliser seulement ck_sequence_read_retry
	 * si vous souhaitez détecter une écriture conflictuelle à une granularité
	 * plus élevée.
	 */
	CK_SEQUENCE_READ(&seqlock, &version) {
		copy = global;
	}

	return;
}

void
writer(void)
{

	for (;;) {
		ck_sequence_write_begin(&seqlock);
		global.a = rand();
		global.b = global.a + global.b;
		global.c = global.b + global.c;
		ck_sequence_write_end(&seqlock);
	}

	return;
}
