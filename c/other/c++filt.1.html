DESCRIPTIO

N

Les langages C++ et Java fournissent le surchargement de fonctions, ce qui signifie que vous pouvez écrire plusieurs fonctions portant le même nom, à condition que chaque fonction prenne des paramètres de types différents. Afin de pouvoir distinguer ces fonctions de même nom, C++ et Java les encodent en un nom d'assembleur de bas niveau qui identifie de manière unique chaque version différente. Ce processus est connu sous le nom de mangling (mélange). Le programme c++filt [1] effectue le mapping inverse : il décode les noms de bas niveau (dé-mangle) en noms de haut niveau afin qu'ils puissent être

lus.

Chaque mot alphanumérique (composé de lettres, de chiffres, de tirets bas, de dollars ou de points) vu dans l'entrée est un nom potentiellement manglé. Si le nom se décode en un nom C++, le nom C++ remplace le nom de bas niveau dans la sortie, sinon le mot original est produit. De cette façon, vous pouvez passer un fichier source assembleur entier, contenant des noms manglés, à travers c++filt et voir le même fichier source contenant des noms

dé-manglés.

Vous pouvez également utiliser c++filt pour déchiffrer des symboles individuels en les passant sur la ligne de commande

: 
c++filt
<symbole>

Si aucun argument symbole n'est donné, c++filt lit les noms de symboles depuis l'entrée standard à la place. Tous les résultats sont imprimés sur la sortie standard. La différence entre la lecture des noms depuis la ligne de commande et la lecture des noms depuis l'entrée standard est que les arguments de la ligne de commande sont censés être simplement des noms manglés et aucune vérification n'est effectuée pour les séparer du texte environnant. Ainsi, par exemple

: 
c++filt -n
_Z1fv

fonctionnera et dé-manglera le nom en « f() » alors que

: 
c++filt -n
_Z1fv,

ne fonctionnera pas. (Notez la virgule supplémentaire à la fin du nom mangé qui le rend invalide). Cette commande fonctionnera cependant

: 
echo _Z1fv, | c++filt
-n

et affichera « f(), », c'est-à-dire le nom dé-manglé suivi d'une virgule finale. Ce comportement est dû au fait que lorsque les noms sont lus depuis l'entrée standard, on s'attend à ce qu'ils puissent faire partie d'un fichier source assembleur où il peut y avoir des caractères supplémentaires, superflus, après un nom mangé. Par exemple

: 
.type
_Z1fv, @
function

--no-recursion-li
mit
Active ou désactive une limite sur la quantité de récursion effectuée lors du dé-mangling des chaînes. Puisque les formats de mangling de noms permettent un niveau de récursion infini, il est possible de créer des chaînes dont le décodage épuisera la quantité d'espace de pile disponible sur la machine hôte, déclenchant une faute de mémoire. La limite tente d'empêcher cela en limitant la récursion à 2048 niveaux d'imbrication.

La valeur par défaut est que cette limite soit activée, mais la désactiver peut être nécessaire afin de dé-mangler des noms véritablement compliqués. Notez cependant que si la limite de récursion est désactivée, une épuisement de la pile est possible et tout rapport de bogue concernant un tel événement sera

rejeté.

L'option -r est un synonyme de l'option --no-recurse-limit. L'option -R est un synonyme de l'option --recurse-lim
