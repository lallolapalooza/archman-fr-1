DESCRIPTIO

N

clazy analyse le code source C++/Qt à la recherche de problèmes liés aux bonnes pratiques de codage avec Qt5. Dans une utilisation typique, lors de la compilation du code avec clazy, vous verrez ces avertissements imprimés dans la sortie normalement comme vous le feriez avec n'importe quels avertissements de

compilateur.

clazy a la capacité de « corriger » le code fautif dans certains cas. Voir la description de la variable d'environnement CLAZY

_FIXIT ci-dessous p
our plus d'informations.

DIRECTIVES DANS LE

CODE

clazy prend en charge la liste suivante de directives dans le code

:
clazy:
skip 
Exempte un fichier entier de toute
s les vérifications. Aucun test cla
zy ne sera exécuté sur le fichier.
clazy:excludeall=<nom1[,nom2,...,nomN]
> 
Exempte le fichier entier des vérifications
spécifiées. Les vérifications clazy nom1, e
tc. ne seront pas exécutées sur ce fichier.
clazy:exclude=<nom1[,nom2,...,nomN]
> 
Exclut des lignes individuelles de vérifications spécifiqu
es. Les tests des vérifications clazy nom1, etc. ne seront
pas exécutés sur la ligne où cette directive est trouvée.
clazy:exclude-next-line=<nom1[,nom2,...,nomN]
> 
Exclut les véri
fications clazy
données de la
ligne suivante.

N'incluez pas le préfixe 'clazy-'. Par exemple, pour désactiver la vérification "qstring-allocations", vous écririez

: 
// clazy:exclude=qstring-allocation
s

et

non 
// clazy:exclude=clazy-qstring-allocation
s

Notez également que ces directives doivent

être des commentaires de style C++ ;
les commentaires de style C sont ignorés.

ENVIRONNEMEN

T

CLAZY_CHECKS - une liste séparée par des virgules de vérificateurs ou ensembles de vérifications à exécuter. Par défaut, tous les vérificateurs des ensembles de vérifications "level0" et "level1" seront

exécutés.

Exemples

:
1. Active uniquement les 2 vérificateurs "unneeded-cast" et "virtual-call-ctor"
:
% export CLAZY_CHECKS="unneeded-cast,virtual-call-ct
or"
2. Active toutes les vérifications de l'ensemble "level0", sauf "qenums"
:
% export CLAZY_CHECKS="level0,
no-qenums"
3. Active toutes les vérifications de l'ensemble "level0" ainsi que le vérificateur "detaching-temporary"
:
% export CLAZY_CHECKS="level0,detaching-temporar
y
"

CLAZY_FIXIT - certains vérificateurs sont capables de réécrire automatiquement votre code source lorsqu'ils rencontrent du code qu'ils peuvent « corriger ». Activez cette fonctionnalité "fixit" en définissant cette variable sur le nom du vérificateur ayant une capacité

"fixit".

Exemples

:
1. Corriger les allocations qlatin1string
:
% export CLAZY_FIXIT="fix-qlatin1string-allocatio
ns"
2. Corriger les instructions connect de style ancien (cas simples)
:
% export CLAZY_FIXIT=fix-old-style-connect

Plus de documentation est fournie en exécutant clazy avec l' option de ligne de commande

--explain.

Notez également qu

'un seul vérificate
ur fixit peut être
exécuté à la fois.

CLAZY_EXTRA_OPTIONS - certains vérificateurs peuvent adapter leur comportement en fonction de la valeur de cette variable d'environnement. Plus de documentation est fournie en exécutant clazy avec l' option de ligne de commande

--explain.

CLAZY_NO_WERROR - si cette variable est définie, clazy ne traitera pas les avertissements comme des erreurs, même si l'option de compilateur -Werror est spécifiée. C'est utile si vous voulez utiliser -Werror uniquement pour les avertissements réguliers gcc/clang mais pas pour les avertissements

clazy.

CLAZY_CHECKS_AS_ERRORS - liste séparée par des virgules de vérifications qui seront promues en erreurs de compilateur. Notez que cela n'active pas les vérifications spécifiées

ici.

CLAZY_IGNORE_DIRS - Une expression régulière pour les chemins à exclure du traitement. Par exemple

:

% export CLAZY_

IGNORE_DIRS=".*
my_qt_folder.*"
