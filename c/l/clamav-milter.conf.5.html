ClamdSocket
STRING
Définit le socket clamd auquel se connecter pour l'analyse. Cette option est obligatoire ! Syntaxe :
ClamdSocket unix:chemin
ClamdSocket tcp:hôte:port
La première syntaxe spécifie un socket unix local (nécessite un chemin absolu) par exemple :
ClamdSocket unix:/run/clamav/clamd.sock
La deuxième syntaxe spécifie un socket tcp local ou distant : l'hôte peut être un nom de machine ou une adresse ip ; le champ ":port" n'est requis que pour les adresses IPv6, sinon il vaut par défaut 3310 par exemple :
ClamdSocket tcp:192.168.0.1
Cette option peut être répétée plusieurs fois avec différents sockets ou même avec le même socket : les serveurs clamd seront sélectionnés de manière circulaire (round-robin).

LocalNet
STRING
Les messages provenant de ces hôtes/réseaux ne seront pas analysés. Cette option prend un couple hôte(nom)/masque en notation CIDR et peut être répétée plusieurs fois. Si "/masque" est omis, un hôte est supposé. Pour spécifier un courriel d'origine locale, non-smtp, utilisez le mot-clé "local"
Par défaut : non défini (tout analyser quelle que soit
l'origine)
AllowList
STRING
Cette option spécifie un fichier qui contient une liste d'expressions régulières POSIX basiques. Les adresses (expédiées vers ou depuis - voir ci-dessous) correspondant à ces expressions régulières ne seront pas analysées. Optionnellement, chaque ligne peut commencer par la chaîne "From:" ou "To:" (note : pas d'espace après le deux-points) indiquant s'il s'agit respectivement de l'expéditeur ou du destinataire à autoriser. Si le champ est manquant, "To:" est supposé. Les lignes commençant par #, : ou ! sont ignorées.
Par défaut : non défini (aucune exclusion
appliquée)
SkipAuthenticated
STRING
Les messages provenant d'utilisateurs SMTP authentifiés correspondant à cette expression régulière POSIX étendue (de type egrep) ne seront pas analysés. Comme alternative, un fichier contenant une liste simple (non regex) de noms (un par ligne) peut être spécifié en utilisant le préfixe "file:". par exemple SkipAuthenticated file:/etc/good_guys. Note : ceci est le nom de connexion AUTH !
Par défaut : non défini (aucune autorisation basée sur l'authentification
SMTP)

SIZE

ACTION

S

Le groupe d'options suivant contrôle le processus de livraison dans différentes circonstances. Les actions suivantes sont disponibles :
- Accept : Le message est accepté pour la livraison
- Reject : Refuser immédiatement la livraison (une erreur 5xx est renvoyée au pair)
- Defer : Renvoyer un message d'échec temporaire (4xx) au pair
- Blackhole (non disponible pour OnFail) : Comme Accept mais le message est envoyé vers l'oubli
- Quarantine (non disponible pour OnFail) : Comme Accept mais le message est mis en quarantaine au lieu d'être livré. NOTE : Dans Sendmail, la file de quarantaine peut être examinée via mailq -qQ. Pour Postfix, cela provoque la mise du message en

attente.
OnClean
STRING
Action à effectuer sur les messages propres (surtout utile pour les tests)
Par défaut :
Accept
OnInfected
STRING
Action à effectuer sur les messages infectés
Par défaut :
Quarantine
OnFail
STRING
Action à effectuer en cas d'erreur (cela inclut l'échec d'allocation des structures de données, l'absence de scanners disponibles, les délais d'attente réseau, les réponses de scanner inconnues et ainsi de suite)
Par défaut :
Defer
RejectMsg
STRING
Cette option vous permet de définir une raison de rejet spécifique pour les messages infectés et n'est donc utile qu'en conjonction avec "OnInfected Reject". La chaîne "%v", si présente, sera remplacée par le nom du virus.
Par défaut : spécifique au
MTA
AddHeader
STRING
Si cette option est définie à "Replace" (ou "Yes"), un en-tête "X-Virus-Scanned" et un "X-Virus-Status" seront ajoutés à chaque message traité, remplaçant éventuellement les en-têtes existants. Si elle est définie à Add, les en-têtes X-Virus sont ajoutés éventuellement parf des existants. Notez que si « Replace » peut potentiellement casser les signatures DKIM, « Add » peut déconcerter procmail et des filtres similaires.
Par défaut :
non
ReportHostname
STRING
Lorsque AddHeader est utilisé, cette option vous permet de définir le nom d'hôte signalé. Cela peut être souhaitable afin d'éviter de divulguer des noms internes. Si elle n'est pas définie, le vrai nom de la machine est utilisé.
Par défaut :
désactivé
VirusAction
STRING
Exécute une commande (éventuellement en cherchant dans PATH) lorsqu'un message infecté est trouvé. Les paramètres suivants sont transmis au programme invoqué dans cet ordre : nom du virus, identifiant de file d'attente, expéditeur, destination, objet, identifiant de message, date du message. Remarque 1 : cela nécessite que les macros MTA soient disponibles (voir LogInfected ci-dessous). Remarque 2 : le processus est invoqué dans le contexte de clamav-milter. Remarque 3 : clamav-milter attendra la fin du processus. Soyez rapide ou créez un processus fils pour éviter des retards inutiles dans la livraison des courriels.

faut

Par défaut :
non
LogInfected
STRING
Cette option vous permet d'ajuster ce qui est journalisé lorsqu'un message est infecté. Les valeurs possibles sont Off (par défaut - rien n'est journalisé), Basic (informations minimales journalisées), Full (informations détaillées journalisées)
Remarque : Pour que cela fonctionne correctement dans sendmail, assurez-vous que les macros msg_id, mail_addr, rcpt_addr et i sont disponibles dans eom. En d'autres termes, ajoutez une ligne comme : Milter.macros.eom={msg_id}, {mail_addr}, {rcpt_addr}, i à votre fichier .cf. Ou utilisez alternativement la macro : define(`confMILTER_MACROS_EOM', `{msg_id}, {mail_addr}, {rcpt_addr}, i')
Postfix devrait fonctionner correctement avec les paramètres par défaut.
Par défaut :
désactivé
LogClean
STRING
Cette option vous permet d'ajuster ce qui est journalisé lorsqu'aucune menace n'est trouvée dans un message scanné.
Voir LogInfected pour les valeurs possibles et les avertissements.
Utile pour le débogage mais augmente considérablement la taille du journal.
Par défaut :
désactivé
SupportMultipleRecipients
BOOL
Cette option affecte le comportement de LogInfected, LogClean et VirusAction lorsqu'un message avec plusieurs destinataires est scanné :
Si SupportMultipleRecipients est désactivé (par défaut), une seule entrée de journal est générée pour le message et, si le message est déterminé comme malveillant, la commande indiquée par VirusAction n'est exécutée qu'une seule fois. Dans les deux cas, seul le dernier destinataire est signalé.
Si SupportMultipleRecipients est activé, une ligne est journalisée pour chaque destinataire et la commande indiquée par VirusAction est également exécutée une fois pour chaque destinataire.
Remarque : bien qu'il soit probablement judicieux d'activer cette option, la valeur par défaut est actuellement définie sur désactivé pour des raisons de compatibilité.
Par
défa
ut :
non
