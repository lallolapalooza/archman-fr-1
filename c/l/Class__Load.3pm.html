DESCRIPTIO

N

"require EXPR" n'accepte que les noms de modules de style "Class/Name.pm", pas "Class::Name". Quelle frustration ! Pour cela, nous fournissons "load_class 'Class

::Name'".

Il est souvent utile de tester si un module peut être chargé, plutôt que de provoquer une erreur lorsqu'il n'est pas disponible. Pour cela, nous fournissons "try_load_class 'Clas

s::Name'".

Enfin, parfois nous devons savoir si une classe particulière a été chargée. Interroger %INC est une option, mais cela manquera les paquets internes et toute classe dont le nom de fichier ne correspond pas au nom du paquet. Pour cela, nous fournissons "is_class_loaded

'Class:
:Name'".

FONCTION

S

load_class Class::Name,

\%options

"load_class" chargera "Class::Name" ou provoquera une erreur, un peu comme "require"

.

Si "Class::Name" est déjà chargé (vérifié avec "is_class_loaded") alors il ne tentera pas de charger la classe. C'est utile lorsque vous avez des paquets internes que "require" ne vérifie

pas.

Le hash %options accepte actuellement une seule clé, "-version". Si vous spécifiez une version, alors cette sous-routine appellera "Class::Name->VERSION( $options{-version} )" en interne, ce qui provoquera une erreur si la version de la classe n'est pas égale ou supérieure à la version que vous avez

demandée.

Cette méthode renver

ra le nom de la clas
se en cas de succès.

try_load_class Class::Name, \%options -> (0|1, message

d'erreur)

Renvoie 1 si la classe a été chargée, 0 si elle ne l'a pas été. Si la classe n'a pas été chargée, l'erreur sera renvoyée comme deuxième valeur de retour en contexte

liste.

Encore une fois, si "Class::Name" est déjà chargé (vérifié avec "is_class_loaded") alors il ne tentera pas de charger la classe. C'est utile lorsque vous avez des paquets internes que "require" ne vérifie

pas.

Comme "load_class", vous pouvez passer une "-version" dans %options. Si la version n'est pas suffisante

, alors cette sous-
routine renverra faux.

is_class_loaded Class::Name, \%options ->

0|1

Cela utilise un certain nombre d'heuristiques pour déterminer si la classe "Class::Name" est chargée. Ces heuristiques ont été prises de l'ancienne implémentation pure-perl de Class::

MOP.

Comme "load_class", vous pouvez passer une "-version" dans %options. Si la version n'est pas suffisante

, alors cette sous-
routine renverra faux.

load_first_existing_class Class::Name, \%options, ..

.

Cela tente de charger la première classe chargeable dans la liste de classes donnée. Chaque nom de classe peut être suivi d'une référence vers un hash

d'options.

Si l'une des classes se charge et passe la vérification de version facultative, ce nom de classe sera renvoyé. Si aucune des classes ne peut être chargée (ou aucune ne passe sa vérification de version), alors une erreur sera

provoquée.

Si, lors de la tentative de chargement d'une classe, cel

le-ci échoue à se charger en raison d'une erreur de
syntaxe, alors une erreur sera provoquée immédiatement.

load_optional_class Class::Name, \%options ->

0|1

"load_optional_class" ressemble beaucoup à "try_load_class", mais aussi beaucoup à "load_class"

.

Si la classe existe et fonctionne, alors elle renverra 1. Si vous spécifiez une version dans %options, alors la vérification de version doit réussir, sinon elle renverra

0.

Si la classe n'existe pas et qu'elle semble ne pas exister sur le disque non plus, elle renverra

0.

Si la classe existe sur le disque, mais que le chargement depuis le disque résulte en une erreur (ex. : une erreur de syntaxe), alors elle "croak" avec cette

erreur.

C'est utile si vous voulez un système de module de repli, c'est-à-dire

: 
my $class = load_optional_class($foo) ? $foo :
$default;

De cette façon, si $foo existe bien mais ne peut pas être chargé en r

aison d'une erreur, vous n
'aurez pas le comportement
d'une simple inexistence.

AVERTISSEMEN

TS

En raison de certaines des heuristiques que ce module utilise pour inférer si un module a été chargé, de faux positifs peuvent survenir dans les vérifications "is_class_loaded" (qui sont également effectuées en interne dans d'autres interfaces) -- si une classe a commencé à être chargée mais meurt ensuite, il peut sembler qu'elle ait déjà été chargée, ce qui peut amener d'autres éléments à

prendre la mauvaise décision. Module::Runtime n'a pas ce problème, mais il ne fait pas non plus certaines choses que ce module
fait -- par exemple gérer gracieusement les paquets qui ont été définis en ligne dans le même fichier qu'un autre paquet.
