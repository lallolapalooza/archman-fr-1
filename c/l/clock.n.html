RÉSOLUTION La plupart

des

sous-commandes prises en charge par la commande clock traitent des temps représentés comme un nombre de secondes depuis le temps de l'époque, et c'est la représentation que clock seconds retourne. Il y a trois exceptions, qui sont toutes destinées à être utilisées là où des temps de plus haute résolution sont requis. clock milliseconds retourne le nombre de millisecondes depuis le temps de l'époque, et clock microseconds retourne le nombre de microsecondes depuis le temps de l'époque. De plus, il y a une commande clock clicks qui retourne un minuteur haute résolution dépendant de la plateforme. Contrairement à clock seconds et clock milliseconds, la valeur de clock clicks n'est pas garantie d'être liée à une époque fixe ; elle est simplement destinée à être l'interv

alle de minuteur le plus précis disponible, et n'es

Ces règles par défaut signifient que dans tous les fuseaux horaires européens, russes et américains (ou compatibles), les calculs de DST seront corrects pour les dates en 2007 et ultérieures, sauf si les règles changent à nouveau à

l'avenir.

ANALYSE EN FORME

LIBRE

Si la commande clock scan est invoquée sans option -format, alors elle demande une analyse en forme libre. Cette forme d'analyse est obsolète. La raison de l'obsolescence est qu'il y a trop d'ambiguïtés. (Est-ce que la chaîne « 2000 » représente une année, une heure du jour, ou une quantité ?) Aucun ensemble de règles pour interpréter les dates et heures en forme libre n'a été trouvé pour donner des résultats non surprenants dans tous les

cas.

Tcl Commands

NAME

clock – manage and format system clock, dates, and times

SYNOPSIS

package require Tcl 8.6
clock command ?arg...?

DESCRIPTION

The clock command provides a number of subcommands for managing and formatting system clock, dates, and times. Many of these subcommands accept time specifications as arguments, described below.

A time specification is typically an integer, representing the number of seconds since the Unix epoch (00:00:00 UTC, January 1, 1970). Some commands, such as clock format and clock scan, accept a wider variety of specifications, including strings.

clock accuracy
clock appendvar
clock breakpoints
clock capture
clock compare
clock date
clock delta
clock diff
clock format
clock normalize
clock seconds
clock scan
clock set
clock start
clock stop
clock string
clock systime
clock throw
clock until
clock when

CLOCK ARITHMETIC

The clock command supports arithmetic on times. When adding or subtracting values, the arguments are taken to be seconds. For example:

clock add 1000000000 3600

The clock diff command computes the difference between two times, returning the result in seconds.

clock diff $time1 $time2

The clock normalize command converts a time value into a standard format. For example, it may be used to convert a date and time into seconds since the epoch.

clock normalize “10:00”

The clock compare command compares two times, returning -1 if the first is earlier, 0 if they are equal, and 1 if the first is later.

clock compare $time1 $time2

HIGH RESOLUTION TIMERS

The clock seconds command returns the current time as the number of seconds since the Unix epoch. The clock monotonic command returns a high-resolution timer value. This timer is guaranteed to be monotonically increasing, and may be used for measuring time intervals. The timer may be implemented using gettimeofday or other system calls.

The clock accurate command returns the accuracy of the clock in seconds. A value of 1.0 means the clock is accurate to the nearest second. A value of 0.001 means the clock is accurate to the nearest millisecond.

FORMATTING TIMES

The clock format command formats a time value into a human-readable string. The time value is specified as the number of seconds since the Unix epoch. If no time value is given, the current time is used.

clock format $time ?switches?

The following switches are available:

-format
Specifies a format string according to the rules of strftime(3).
-gmt
If specified, the time is formatted using Greenwich Mean Time.

SCANNING TIMES

The clock scan command parses a time string and returns the number of seconds since the Unix epoch. The time string may contain a variety of formats, including absolute dates and times, relative times, and ISO 8601 specifications.

clock scan $string ?switches?

The following switches are available:

-base
Specifies a base time value in seconds since the epoch. If specified, relative times are interpreted relative to this base time. The default base time is the current system time. The -base flag affects the interpretation of the input string, but not the computation of Greenwich Mean Time.
-gmt
If specified, the time is interpreted as Greenwich Mean Time. -gmt, if specified, affects only the computed time value; it does not impact the interpretation of -base.

If the -base flag is specified, the next argument should contain an integer clock value. Only the date in this value is used, not the time. This is useful for determining the time on a specific day or doing other date-relative conversions.

The inputString argument consists of zero or more specifications of the following form:

time
A time of day, which is of the form: hh?:mm?:ss?? ?meridian? ?zone? or hhmm ?meridian? ?zone? If no meridian is specified, hh is interpreted on a 24-hour clock.
date
A specific month and day with optional year. The acceptable formats are “mm/dd?/yy?”, “monthname dd?, yy?”, “day, dd monthname ?yy?”, “dd monthname yy”, “?CC?yymmdd”, and “dd-monthname-?CC?yy”. The default year is the current year. If the year is less than 100, we treat the years 00-68 as 2000-2068 and the years 69-99 as 1969-1999. Not all platforms can represent the years 38-70, so an error may result if these years are used.
ISO 8601 point-in-time
An ISO 8601 point-in-time specification, such as “CCyymmddThhmmss”, where T is the literal “T”, “CCyymmdd hhmmss”, “CCyymmddThh:mm:ss”, or “CCyy-mm-ddThh:mm:ss”. Note that only these four formats are accepted. The command does not accept the full range of point-in-time specifications specified in ISO8601. Other formats can be recognized by giving an explicit -format option to the clock scan command.
relative time
A specification relative to the current time. The format is number unit. Acceptable units are year, fortnight, month, week, day, hour, minute (or min), and second (or sec). The unit can be specified as a singular or plural, as in 3 weeks. These modifiers may also be specified: tomorrow, yesterday, today, now, last, this, next, ago.

The actual date is calculated according to the following steps.

First, any absolute date and/or time is processed and converted. Using that time as the base, day-of-week specifications are added. Next, relative specifications are used. If a date or day is specified, and no absolute or relative time is given, midnight is used. Finally, a correction is applied so that the correct hour of the day is produced after allowing for daylight savings time differences and the correct date is given when going from the end of a long month to a short month.

FORMAT GROUPS

The clock format command supports predefined format groups for common date and time formats.

-format group
Specifies a format group. The following groups are supported:

“date” for the locale's appropriate date representation, “time” for the locale's appropriate time representation, and “full” for the locale's appropriate date and time representation.

TIME ZONES

The clock scan command can parse time zone abbreviations. The clock format command can output time zone abbreviations.

The time zone is specified using the -zone switch to clock scan, or by including the time zone abbreviation in the input string.

The time zone is specified using the -gmt switch to clock format, or by including the time zone abbreviation in the format string.

LOCALIZATION

The clock command uses the locale settings of the Tcl interpreter to format dates and times. This means that month names, day names, and time formats will be displayed according to the current locale.

FREE FORM SCAN

The clock scan command can parse a wide variety of free-form date and time specifications. This includes relative times, absolute dates and times, and combinations thereof.

For example, the following commands are all valid:

clock scan “next Tuesday at 3pm”

clock scan “3 weeks ago”

clock scan “10/31/05 14:30:00 EST”

The clock scan command attempts to be flexible and interpret as much of the input string as possible. However, for precise control over the input format, it is recommended to use the -format option.
