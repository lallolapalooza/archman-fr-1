NOM

clevis - Cadre de politique de déchiffrement automatisé

SYNTAXE

clevis COMMANDE [OPTIONS]

APERÇU

Clevis est un cadre de politique de déchiffrement automatisé. Il vous permet de définir une politique au moment du chiffrement qui doit être satisfaite pour que les données soient déchiffrées. Une fois cette politique remplie, les données sont déchiffrées.

Clevis est extensible. Nos extensions sont appelées des broches (pins). Le travail d'une broche est de prendre une politique comme premier argument et du texte brut en entrée standard, et de chiffrer les données de manière à ce qu'elles puissent être automatiquement déchiffrées si la politique est remplie. Examinons un exemple.

LIAISON TANG

Clevis offre un support pour le serveur de liaison réseau Tang. Tang fournit une alternative légère et sans état à l'escrow. Le chiffrement des données en utilisant la broche Tang fonctionne de manière similaire à notre broche HTTP ci-dessus :

$ clevis encrypt tang '{"url":"http://tang.srv"}' < PT > JWE
L'annonce contient les clés de signature suivantes :
_OsIk0T-E2l6qjfdDiwVmidoZjA
Souhaitez-vous faire confiance à ces clés ? [ynYN] y

Comme vous pouvez le voir ci-dessus, Tang utilise un flux de travail de confiance lors de la première utilisation. Alternativement, Tang peut effectuer un chiffrement entièrement hors ligne si vous partagez au préalable l'annonce du serveur. Le déchiffrement fonctionne également comme dans notre premier exemple :

$ clevis decrypt < JWE > PT

Pour plus d'informations, voir clevis-encrypt-tang(1).

LIAISON TPM2

Clevis offre un support pour chiffrer une clé dans une puce TPM 2.0 (Trusted Platform Module 2.0). La clé aléatoire et cryptographiquement forte utilisée pour le chiffrement est chiffrée à l'aide de la puce TPM2, puis lors du déchiffrement, elle est déchiffrée à l'aide de la TPM2 pour permettre à clevis de déchiffrer le secret stocké dans le JWE.

Le chiffrement des données en utilisant la broche tpm2 fonctionne de la même manière que pour les broches mentionnées ci-dessus :

$ clevis encrypt tpm2 '{}' < PT > JWE

La broche a des valeurs par défaut raisonnables pour sa configuration, mais une hiérarchie, un hachage et des algorithmes de clé différents peuvent être choisis si les valeurs par défaut utilisées ne conviennent pas.

Le déchiffrement fonctionne également de manière similaire aux autres broches, seul le JWE doit être fourni :

$ clevis decrypt < JWE > PT

Notez que, comme pour les autres broches, aucune configuration n'est utilisée pour le déchiffrement, car clevis stocke les clés publiques et privées pour désceller l'objet chiffré par TPM2 dans le JWE afin que clevis puisse récupérer ces informations à partir de là.

Pour plus d'informations, voir clevis-encrypt-tpm2(1).

PARTAGE DE SECRET DE SHAMIR

Clevis offre un moyen de mélanger des broches pour créer des politiques de déverrouillage sophistiquées et de haute disponibilité. Ceci est accompli en utilisant un algorithme appelé Partage de Secret de Shamir (SSS).

SSS est un schéma de seuillage. Il crée une clé et la divise en un certain nombre de fragments. Chaque fragment est chiffré en utilisant une autre broche (potentiellement même SSS récursivement). De plus, vous définissez le seuil t. Si au moins t fragments peuvent être déchiffrés, alors la clé de chiffrement peut être récupérée et le déchiffrement peut réussir.

Par exemple, créons une configuration de haute disponibilité en utilisant Tang :

$ cfg='{"t":1,"pins":{"tang":[{"url":...},{"url":...}]}}'
$ clevis encrypt sss "$cfg" < PT > JWE

Dans cette politique, nous déclarons que nous avons un seuil de 1, mais qu'il existe plusieurs fragments de clé chiffrés à l'aide de différents serveurs Tang. Puisque notre seuil est de 1, tant qu'un des serveurs Tang est disponible, le déchiffrement réussira. Comme toujours, le déchiffrement se résume à :

$ clevis decrypt < JWE > PT

Pour plus d'informations, voir clevis-encrypt-tang(1).

LIAISON LUKS

Clevis peut être utilisé pour lier un volume LUKS existant à sa politique d'automatisation. Ceci est accompli avec une simple commande :

$ clevis luks bind -d /dev/sda tang '{"url":...}'

Cette commande effectue quatre étapes :

1. Crée une nouvelle clé avec la même entropie que la clé maîtresse LUKS — le nombre maximum de bits d'entropie est de 256.
2. Chiffre la nouvelle clé avec Clevis.
3. Stocke le JWE Clevis dans l'en-tête LUKS.
4. Active la nouvelle clé pour une utilisation avec LUKS.

Ce disque peut maintenant être déverrouillé avec votre mot de passe existant ainsi qu'avec la politique Clevis. Clevis fournit deux déverrouilleurs pour les volumes LUKS. Premièrement, nous fournissons une intégration avec Dracut pour déverrouiller automatiquement votre volume racine au début du démarrage. Deuxièmement, nous fournissons une intégration avec UDisks2 pour déverrouiller automatiquement vos médias amovibles dans votre session de bureau.

Pour plus d'informations, voir clevis-luks-bind(1).
