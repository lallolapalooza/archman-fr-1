rpc(3) Manuel des fonctions de bibliothèque rpc(3)

NOM

rpc - routines de bibliothèque pour les appels de procédure distante

BIBLIOTHÈQUE

Bibliothèque C standard (libc, -lc)

SYNOPSIS ET DESCRIPTION

Ces routines permettent aux programmes C d'effectuer des appels de procédure sur d'autres machines à travers le réseau. D'abord, le client appelle une procédure pour envoyer un paquet de données au serveur. À la réception du paquet, le serveur appelle une routine de distribution pour effectuer le service demandé, puis renvoie une réponse. Enfin, l'appel de procédure retourne au client.

Pour utiliser ces routines, incluez le fichier d'en-tête <rpc/rpc.h>.

Les prototypes ci-dessous utilisent les types suivants :

typedef int bool_t;
typedef typeof(bool_t (XDR *, void *, ...))  *xdrproc_t;
typedef typeof(bool_t (caddr_t resp, struct sockaddr_in *raddr)
    *resultproc_t;

Consultez les fichiers d'en-tête pour les déclarations des types AUTH, CLIENT, SVCXPRT et XDR.

void auth_destroy(AUTH *auth);
Une macro qui détruit les informations d'authentification associées à auth. La destruction implique généralement la désallocation des structures de données privées. L'utilisation de auth est indéfinie après l'appel de auth_destroy().
AUTH *authnone_create(void);
Crée et renvoie un descripteur d'authentification RPC qui transmet des informations d'authentification non utilisables avec chaque appel de procédure distante. C'est l'authentification par défaut utilisée par RPC.
AUTH *authunix_create(char *host, uid_t uid, gid_t gid,
                      int n, gid_t aup_gids[n]);
Crée et renvoie un descripteur d'authentification RPC contenant des informations d'authentification. Le paramètre host est le nom de la machine sur laquelle les informations ont été créées ; uid est l'ID utilisateur de l'utilisateur ; gid est l'ID de groupe courant de l'utilisateur ; n et aup_gids font référence à un tableau compté de groupes auxquels l'utilisateur appartient. Il est facile d'usurper l'identité d'un utilisateur.
AUTH *authunix_create_default(void);
Appelle authunix_create() avec les paramètres appropriés.
int callrpc(char *host, unsigned long prognum,
            unsigned long versnum, unsigned long procnum,
            xdrproc_t inproc, const char *in,
            xdrproc_t outproc, char *out);
Appelle la procédure distante associée à prognum, versnum et procnum sur la machine host. Le paramètre in est l'adresse de l'argument (ou des arguments) de la procédure, et out est l'adresse où placer le (ou les) résultat(s) ; inproc est utilisé pour encoder les paramètres de la procédure, et outproc est utilisé pour décoder les résultats de la procédure. Cette routine renvoie zéro en cas de succès, ou la valeur de enum clnt_stat convertie en entier en cas d'échec. La routine clnt_perrno() est utile pour traduire les statuts d'échec en messages.
Attention : l'appel de procédures distantes avec cette routine utilise UDP/IP comme transport ; voir clntudp_create() pour les restrictions. Vous n'avez pas le contrôle des délais d'attente ou de l'authentification avec cette routine.
enum clnt_stat clnt_broadcast(unsigned long prognum,
                     unsigned long versnum, unsigned long procnum,
                     xdrproc_t inproc, char *in,
                     xdrproc_t outproc, char *out,
                     resultproc_t eachresult);
Similaire à callrpc(), sauf que le message d'appel est diffusé sur tous les réseaux de diffusion locaux. Chaque fois qu'il reçoit une réponse, cette routine appelle eachresult(), dont la forme est :

eachresult(char *out, struct sockaddr_in *addr);

où out est le même que out passé à clnt_broadcast(), sauf que la sortie de la procédure distante y est décodée ; addr pointe vers l'adresse de la machine qui a envoyé les résultats. Si eachresult() renvoie zéro, clnt_broadcast() attend d'autres réponses ; sinon, il retourne avec le statut approprié.
Attention : les sockets de diffusion sont limitées en taille au maximum de l'unité de transfert de la liaison de données. Pour Ethernet, cette valeur est de 1500 octets.
enum clnt_stat clnt_call(CLIENT *clnt, unsigned long procnum,
                    xdrproc_t inproc, char *in,
                    xdrproc_t outproc, char *out,
                    struct timeval tout);
Une macro qui appelle la procédure distante procnum associée au descripteur client, clnt, qui est obtenu avec une routine de création de client RPC telle que clnt_create(). Le paramètre in est l'adresse de l'argument (ou des arguments) de la procédure, et out est l'adresse où placer le (ou les) résultat(s) ; inproc est utilisé pour encoder les paramètres de la procédure, et outproc est utilisé pour décoder les résultats de la procédure ; tout est le temps accordé pour le retour des résultats.
clnt_destroy(CLIENT *clnt);
Une macro qui détruit le descripteur RPC du client. La destruction implique généralement la désallocation des structures de données privées, y compris clnt lui-même. L'utilisation de clnt est indéfinie après l'appel de clnt_destroy(). Si la bibliothèque RPC a ouvert le socket associé, elle le fermera également. Sinon, le socket reste ouvert.
CLIENT *clnt_create(const char *host, unsigned long prog,
                    unsigned long vers, const char *proto);
Routine générique de création de client. host identifie le nom de la machine distante où se trouve le serveur. proto indique quel type de protocole de transport utiliser. Les valeurs actuellement supportées pour ce champ sont « udp » et « tcp ». Des délais d'attente par défaut sont définis, mais peuvent être modifiés en utilisant clnt_control().
Attention : l'utilisation d'UDP présente des inconvénients. Comme les messages RPC basés sur UDP ne peuvent contenir que jusqu'à 8 K octets de données encodées, ce transport ne peut pas être utilisé pour des procédures qui prennent de grands arguments ou renvoient d'énormes résultats.
bool_t clnt_control(CLIENT *cl, int req, char *info);
Une macro utilisée pour modifier ou récupérer diverses informations concernant un objet client. req indique le type d'opération, et info est un pointeur vers les informations. Pour UDP et TCP, les valeurs supportées de req et leurs types d'arguments, ainsi que ce qu'ils font, sont :

CLSET_TIMEOUT  struct timeval // définit le délai d'attente total
CLGET_TIMEOUT  struct timeval // obtient le délai d'attente total

Note : si vous définissez le délai d'attente à l'aide de clnt_control(), le paramètre de délai d'attente passé à clnt_call() sera ignoré dans tous les appels futurs.

CLGET_SERVER_ADDR  struct sockaddr_in
                // obtient l'adresse du serveur

Les opérations suivantes sont valides pour UDP uniquement :

CLSET_RETRY_TIMEOUT  struct timeval // définit le délai de nouvelle tentative
CLGET_RETRY_TIMEOUT  struct timeval // obtient le délai de nouvelle tentative

Le délai de nouvelle tentative est le temps pendant lequel « RPC UDP » attend la réponse du serveur avant de retransmettre la requête.
clnt_freeres(CLIENT * clnt, xdrproc_t outproc, char *out);
Une macro qui libère toutes les données allouées par le système RPC/XDR lors du décodage des résultats d'un appel RPC. Le paramètre out est l'adresse des résultats, et outproc est la routine XDR décrivant les résultats. Cette routine renvoie un si les résultats ont été libérés avec succès, et zéro sinon.
