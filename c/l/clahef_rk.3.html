CLAHEF_RK calcule une factorisation partielle d'une matrice complexe hermitienne indéfinie en utilisant la méthode de pivotement diagonal bornée de Bunch-Kaufman (rook).

Objectif :

!> CLAHEF_RK calcule une factorisation partielle d'une matrice complexe hermitienne
!> A en utilisant la méthode de pivotement diagonal bornée de Bunch-Kaufman (rook).
!> La factorisation partielle a la forme :
!>
!> A  =  ( I  U12 ) ( A11  0  ) (  I       0    )  si UPLO = 'U', ou :
!>       ( 0  U22 ) (  0   D  ) ( U12**H U22**H )
!>
!> A  =  ( L11  0 ) (  D   0  ) ( L11**H L21**H )  si UPLO = 'L',
!>       ( L21  I ) (  0  A22 ) (  0       I    )
!>
!> où l'ordre de D est au plus NB. L'ordre réel est renvoyé dans
!> l'argument KB, et est soit NB, soit NB-1, soit N si N <= NB.
!>
!> CLAHEF_RK est une sous-routine auxiliaire appelée par CHETRF_RK. Elle utilise
!> du code bloqué (appelant BLAS de niveau 3) pour mettre à jour la sous-matrice
!> A11 (si UPLO = 'U') ou A22 (si UPLO = 'L').
!>

Paramètres

UPLO 
!>          UPLO est CHARACTER*1
!>          Spécifie si la partie triangulaire supérieure ou inférieure de la
!>          matrice hermitienne A est stockée :
!>          = 'U' : Triangulaire supérieure
!>          = 'L' : Triangulaire inférieure
!>

N

!>          N est INTEGER
!>          L'ordre de la matrice A. N >= 0.
!>

NB

!>          NB est INTEGER
!>          Le nombre maximum de colonnes de la matrice A qui doivent être
!>          factorisées. NB doit être au moins 2 pour permettre des blocs de pivot
!>          de 2 par 2.
!>

KB

!>          KB est INTEGER
!>          Le nombre de colonnes de A qui ont effectivement été factorisées.
!>          KB est soit NB-1, soit NB, soit N si N <= NB.
!>

A

!>          A est un tableau COMPLEX de dimension (LDA,N)
!>          À l'entrée, la matrice hermitienne A.
!>            Si UPLO = 'U' : la partie triangulaire supérieure N-par-N
!>            principale de A contient la partie triangulaire supérieure de la
!>            matrice A, et la partie strictement triangulaire inférieure de A n'est pas
!>            référencée.
!>
!>            Si UPLO = 'L' : la partie triangulaire inférieure N-par-N
!>            principale de A contient la partie triangulaire inférieure de la
!>            matrice A, et la partie strictement triangulaire supérieure de A n'est pas
!>            référencée.
!>
!>          À la sortie, contient :
!>            a) UNIQUEMENT les éléments diagonaux de la matrice hermitienne bloc-diagonale
!>               D sur la diagonale de A, c'est-à-dire D(k,k) = A(k,k);
!>               (les éléments supradiagonaux (ou subdiagonaux) de D
!>                sont stockés à la sortie dans le tableau E), et
!>            b) Si UPLO = 'U' : facteur U dans la partie supradiagonale de A.
!>               Si UPLO = 'L' : facteur L dans la partie subdiagonale de A.
!>

LDA

!>          LDA est INTEGER
!>          La dimension principale du tableau A. LDA >= max(1,N).
!>

E

!>          E est un tableau COMPLEX de dimension (N)
!>          À la sortie, contient les éléments supradiagonaux (ou subdiagonaux)
!>          de la matrice hermitienne bloc-diagonale D
!>          avec des blocs diagonaux de 1x1 ou 2x2, où
!>          Si UPLO = 'U' : E(i) = D(i-1,i), i=2:N, E(1) est mis à 0;
!>          Si UPLO = 'L' : E(i) = D(i+1,i), i=1:N-1, E(N) est mis à 0.
!>
!>          NOTE : Pour un bloc diagonal de 1x1 D(k), où
!>          1 <= k <= N, l'élément E(k) est mis à 0 dans les deux
!>          cas UPLO = 'U' ou UPLO = 'L'.
!>

IPIV

!>          IPIV est un tableau INTEGER de dimension (N)
!>          IPIV décrit la matrice de permutation P dans la factorisation
!>          de la matrice A comme suit. La valeur absolue de IPIV(k)
!>          représente l'indice de la ligne et de la colonne qui ont été
!>          échangées avec la k-ième ligne et colonne. La valeur de UPLO
!>          décrit l'ordre dans lequel les échanges ont été appliqués.
!>          De plus, le signe de IPIV représente la structure de bloc
!>          de la matrice hermitienne bloc-diagonale D avec des blocs
!>          diagonaux de 1x1 ou 2x2 qui correspondent à 1 ou 2 échanges
!>          à chaque étape de factorisation.
!>
!>          Si UPLO = 'U',
!>          ( dans l'ordre de factorisation, k décroît de N à 1 ):
!>            a) Une seule entrée positive IPIV(k) > 0 signifie :
!>               D(k,k) est un bloc diagonal de 1x1.
!>               Si IPIV(k) != k, les lignes et colonnes k et IPIV(k) ont été
!>               échangées dans la sous-matrice A(1:N,N-KB+1:N);
!>               Si IPIV(k) = k, aucun échange n'a eu lieu.
!>
!>
!>            b) Une paire d'entrées négatives consécutives
!>               IPIV(k) < 0 et IPIV(k-1) < 0 signifie :
!>               D(k-1:k,k-1:k) est un bloc diagonal de 2x2.
!>               (NOTE : les entrées négatives dans IPIV n'apparaissent QU'EN PAIRES).
!>               1) Si -IPIV(k) != k, les lignes et colonnes
!>                  k et -IPIV(k) ont été échangées
!>                  dans la matrice A(1:N,N-KB+1:N).
!>                  Si -IPIV(k) = k, aucun échange n'a eu lieu.
!>               2) Si -IPIV(k-1) != k-1, les lignes et colonnes
!>                  k-1 et -IPIV(k-1) ont été échangées
!>                  dans la sous-matrice A(1:N,N-KB+1:N).
!>                  Si -IPIV(k-1) = k-1, aucun échange n'a eu lieu.
!>
!>            c) Dans les deux cas a) et b), ABS( IPIV(k) ) <= k est toujours vrai.
!>
!>            d) NOTE : Toute entrée IPIV(k) est toujours NON NULLE en sortie.
!>
!>          Si UPLO = 'L',
!>          ( dans l'ordre de factorisation, k augmente de 1 à N ):
!>            a) Une seule entrée positive IPIV(k) > 0 signifie :
!>               D(k,k) est un bloc diagonal de 1x1.
!>               Si IPIV(k) != k, les lignes et colonnes k et IPIV(k) ont été
!>               échangées dans la sous-matrice A(1:N,1:KB).
!>               Si IPIV(k) = k, aucun échange n'a eu lieu.
!>
!>            b) Une paire d'entrées négatives consécutives
!>               IPIV(k) < 0 et IPIV(k+1) < 0 signifie :
!>               D(k:k+1,k:k+1) est un bloc diagonal de 2x2.
!>               (NOTE : les entrées négatives dans IPIV n'apparaissent QU'EN PAIRES).
!>               1) Si -IPIV(k) != k, les lignes et colonnes
!>                  k et -IPIV(k) ont été échangées
!>                  dans la sous-matrice A(1:N,1:KB).
!>                  Si -IPIV(k) = k, aucun échange n'a eu lieu.
!>               2) Si -IPIV(k+1) != k+1, les lignes et colonnes
!>                  k-1 et -IPIV(k-1) ont été échangées
!>                  dans la sous-matrice A(1:N,1:KB).
!>                  Si -IPIV(k+1) = k+1, aucun échange n'a eu lieu.
!>
!>            c) Dans les deux cas a) et b), ABS( IPIV(k) ) >= k est toujours vrai.
!>
!>            d) NOTE : Toute entrée IPIV(k) est toujours NON NULLE en sortie.
!>

W

!>          W est un tableau COMPLEX de dimension (LDW,NB)
!>

LDW

!>          LDW est INTEGER
!>          La dimension principale du tableau W. LDW >= max(1,N).
!>

INFO

!>          INFO est INTEGER
!>          = 0 : succès de l'exécution
!>
!>          < 0 : Si INFO = -k, le k-ième argument avait une valeur illégale
!>
!>          > 0 : Si INFO = k, la matrice A est singulière, car :

clahef_rk(3)

LAPACK Version 3.12.0

NOM

clahef_rk - la factorisation d'une matrice complexe H dans le cas où la matrice diagonale en blocs est singulière.

SYNTAXE

  SUBROUTINE CLAHEF_RK( UPLO, N, NB, A, LDA, D, SD, WORK, LDWORK, INFO )

La sous-routine CLAHEF_RK peut appeler d'autres routines de sous-programme.

ARGUMENTS

UPLO

CHARACTER*1. Sur l'entrée :

UPLO = 'U' : le haut triangulaire supérieur de A est stocké.

UPLO = 'L' : le bas triangulaire inférieur de A est stocké.

N

INTEGER

L'ordre de la matrice A. N >= 0.

NB

INTEGER

Taille du bloc.

A

COMPLEX*16, dimension ( LDA, N ).

Sur l'entrée, la matrice A.

Sur la sortie, le haut (si UPLO = 'U') ou le bas (si UPLO = 'L') triangulaire de la matrice A, et les sous-diagonales de la matrice D.

LDA

INTEGER

La plus grande dimension de A.

D

COMPLEX*16, dimension ( N ).

Sur la sortie, la matrice des éléments diagonaux de D.

SD

COMPLEX*16, dimension ( N ).

Sur la sortie, la matrice des éléments de la sous-diagonale de D.

WORK

COMPLEX*16, dimension ( LDWORK, M ), où M est le nombre de blocs.

LDWORK

INTEGER

La plus grande dimension de WORK.

INFO

INTEGER

= 0: succès ; < 0: si INFO = -i, alors le i-ème argument avait une valeur inadmissible. > 0: si INFO = k, alors la factorisation a été effectuée, mais le k-ème bloc diagonal est exactement singulier. La factorisation peut ne pas être utile pour résoudre un système d'équations.

NOTE : INFO ne stocke que la première occurrence d'une singularité ; toute occurrence ultérieure de singularité n'est pas stockée dans INFO même si la factorisation se termine toujours.

Description

Cette routine effectue une factorisation H en blocs de la forme :

 A = P * D * U**H

où U est une matrice unitaire avec des unités sur la diagonale, D est une matrice diagonale en blocs dont les blocs diagonaux sont soit de taille 1x1, soit de taille 2x2, et P est une matrice de permutation.

La factorisation est calculée par blocs et est particulièrement adaptée aux matrices bande.

La routine gère la singularité du bloc diagonal D. Si un bloc diagonal est singulier, la factorisation est quand même complétée, mais un code d'information est retourné pour avertir l'utilisateur.

Les éléments de la matrice diagonale en blocs D sont stockés dans les tableaux D et SD.

Les blocs diagonaux de taille 1x1 sont stockés dans D.

Les blocs diagonaux de taille 2x2 sont stockés sous la forme :

 [ D(i)  SD(i)  ]
 [ conjg(SD(i)) D(i+1) ]

dans les tableaux D et SD.

La factorisation est effectuée en supposant que la matrice A est donnée par ses éléments triangulaires supérieurs ou inférieurs.

Le tableau WORK est utilisé comme espace de travail pour les calculs.

Le paramètre INFO indique si la factorisation a réussi et si des blocs diagonaux singuliers ont été rencontrés.

Si la factorisation est effectuée, mais que le bloc diagonal D est exactement singulier, une division par zéro se produira si D est utilisé pour résoudre un système d'équations.

NOTE : INFO ne stocke que la première occurrence d'une singularité ; toute occurrence ultérieure de singularité n'est pas stockée dans INFO même si la factorisation se termine toujours.
