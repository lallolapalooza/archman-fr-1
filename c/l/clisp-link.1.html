NOM

clisp-link - lie un nouveau module externe à CLISP[1].

SYNOPSIS

clisp-link [create] [module] [file...]

clisp-link [add] [source] [destination] [module...]

clisp-link [run] [source] [module...]

clisp-link [install] [module...]

DESCRIPTION

Ce script shell opère sur les ensembles de modules et les ensembles de liaison de CLISP[1] : et les ensembles de liaison :

•createcrée de nouveaux ensembles de modules à partir de fichiers source
•addajoute des ensembles de modules à un ensemble de liaison pour produire un nouvel ensemble de liaison
•runexécute CLISP[1] avec des ensembles de modules ajoutés
•Uniquement dans CLISP[1] compilé sans l'option de configuration --without-dynamic-modules.

installinstalle de nouveaux ensembles de modules pour un usage général

OPTIONS

create

La commande 
$ clisp-link create module file ...

crée un ensemble de modules dans le répertoire module qui fait référence (via des liens symboliques) aux fichiers file... Les fichiers sont censés être des modules en soi.

add

La commande 
$ clisp-link add source destination module ...

combine l'ensemble de liaison dans le répertoire source et les modules dans les répertoires module... en un nouvel ensemble de liaison, dans le répertoire destination qui est créé à cet effet.

run

La commande 
$ clisp-link run source module ...

exécute l'ensemble de liaison dans le répertoire source, avec les modules dans les répertoires module... Sauf si CLISP[1] a été compilé avec l'option de configuration --without-dynamic-modules, le chargement sera effectué en utilisant SYS::DYNLOAD-MODULES. Sinon - ce qui est beaucoup plus lent - un ensemble de liaison temporaire sera créé puis supprimé par la suite.

install

Uniquement dans CLISP[1] compilé sans l'option de configuration --without-dynamic-modules.

La commande

$ clisp-link install module ...

installe les modules dans les répertoires module... dans CUSTOM:*LIB-DIRECTORY* ou, si ce dernier n'est pas accessible en écriture pour l'utilisateur (par ex., si une installation CLISP[1] globale est utilisée et l'utilisateur n'a pas les privilèges administratifs), dans CUSTOM:*USER-LIB-DIRECTORY*.

La variable CUSTOM:*USER-LIB-DIRECTORY* est initialement définie à (MERGE-PATHNAMES[2] ".clisp/" (USER-HOMEDIR-PATHNAME[3])) si ce répertoire existe, et peut être réinitialisée dans le fichier RC.


Note
Ne pas ajouter CUSTOM:*USER-LIB-DIRECTORY* à CUSTOM:*LOAD-PATHS* ni sous aucun de ses éléments. Utilisez REQUIRE au lieu de LOAD pour charger des modules dynamiques.
Pour que cette commande fonctionne, chaque répertoire module doit contenir un Makefile avec une cible clisp-module-distrib qui utilise LN pour distribuer les fichiers nécessaires à l'exécution du module dans destdir. Ceci s'ajoute à l'exigence générale que link.sh soit présent.

EXEMPLES

Voir la section 32.2.6, « Exemple ».

FICHIERS

clisp-link nécessite un répertoire « link kit » contenant :

•"modules.c"
•"clisp.h"

clisp-link s'attend à trouver ces fichiers dans un sous-répertoire linkkit/ du répertoire d'installation (c'est-à-dire CUSTOM:*LIB-DIRECTORY*) qu'il obtient en exécutant

$ `dirname $0`/clisp -b

Cela peut être remplacé par la variable d'environnement[4] CLISP_LINKKIT.
