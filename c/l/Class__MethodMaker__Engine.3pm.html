SYNOPSI

Cette classe est destinée uniquement à l'implémentation interne. Ce n'est pas une API

publique.

Les méthodes non-structures de données font partie de l'API publique, mais ne sont pas appelées directement : elles sont plutôt appelées via l'interface"import", comme pour les mét

hodes de struct

Le Moteur d'Installation de Méthodes de Class::

MethodMaker

impor

t

Cela effectue l'analyse des arguments pour préparer l'appel à create_methods. En particulier, c'est le point où les appels v1 et v2 sont

distingués.

C'est implicitement appelé dans le cadre d'une instruction "use"

: 
use Class::MethodMaker
  [ scalar => [qw/ foo bar baz /],
    new    => [qw/ new /]        ,
  ]
;

est équivalent

à 
Class::MethodMaker->import([scalar => [qw/ foo bar baz /],
                            new    => [qw/ new /]        ,
                           ])
;

Voir perldoc -f use pour les détails de cette

équivalence.

Les méthodes créées sont installées dans la classe appelant import - ou plus précisément, la première classe en remontant la pile d'appels qui n'est pas "Class::MethodMaker" ou une sous-classe de

celle-ci.
SYNOPS
IS 
Class::MethodMaker->import([scalar => [+{ -type   => 'File::Stat',
                                          -forward => [qw/ mode size /],
                                          '*_foo' => '*_fig',
                                          '*_gop' => undef,
                                          '*_bar' => '*_bar',
                                          '*_hal' => '*_sal',
                                         },
                                       qw/ -static bob /,
                                      ]
]
)

Une référence de hachage. Certaines options ("static", "type", "default", "default_ctor") sont gérées par l'auto-extender. Celles-ci seront invoquées si le nom est présent en tant que clé et que la valeur est vraie. Toute autre option est transmise à la méthode en question. Une liste de renommages personnalisés. C'est une référence de hachage du nom de méthode vers le renommage. Le nom de méthode est le nom générique (c'est-à-dire, comportant un "*" à remplacer par le nom du composant). Le renommage est la valeur avec laquelle renommer. Elle peut elle-même contenir un "*" à remplacer par le nom du composant. Si le renommage est undef, la méthode n'est pas installée. Pour les méthodes qui ne seraient pas installées par défaut, utiliser une valeur de renommage identique au nom de la méthode.

Ainsi, si un type installerait normalement les

use Class::MethodMaker
  [ new => 'new' ]
;

Crée un constructeur

basique.

Prend une chaîne unique ou une référence à un tableau de chaînes comme argument. Pour chaque chaîne, crée une méthode simple qui crée et retourne un objet de la classe

appropriée.

La méthode générée peut être appelée comme méthode de classe, comme d'habitude, ou comme méthode d'instance, auquel cas un nouvel objet de la même classe que l'instance sera

créé.

Option

s
-ha
sh
Le constructeur acceptera comme arguments une liste de paires, allant du nom du composant à la valeur initiale. Pour chaque paire, le composant nommé est initialisé en appelant la méthode du même nom avec la valeur donnée. Par exemple : 
package MyClass;
use Class::MethodMaker
  [ new    => [qw/ -hash new /],
    scalar => [qw/ b c /],
  ];
sub d {
  my $self = shift;
  $self->{d} = $_[0]
    if @_;
  return $self->{d};
}
package main;
# L'éstatement ci-dessous appelle implicitement
# $m->b(1); $m->c(2); $m->d(3)
# sur le m nouvellement construit.
my $m = MyClass->new(b => 1, c => 2, d
=> 3);

Notez que cela peut également appeler des méthodes fournies par l'utilisateur ayant le nom du

composant.

Au lieu d'une liste de paires, un hashref unique peut également être passé, qui sera développé de manière appropriée. Ainsi l'exemple ci-dessus est équivalent

à : 
my $m = MyClass->new({ b => 1, c => 2, d =>
3 });

Utilisateurs avancés : le renommage des méthodes de Class::MethodMaker est pris en compte, donc même si la méthode "*" est renommée ou supprim

ée, cela continue
ra de fonctionner.
-in
it
Cette option fait que la méthode new appelle une méthode d'initialisation. La méthode est appelée "init" (original, hein ?) par défaut, mais l'option peut recevoir une valeur alternative. La méthode init reçoit tous les arguments qui ont été passés au constructeur, mais la méthode est invoquée sur l'instance nouvellement construite. 
use Class::MethodMaker
  [ new => [qw/ -init new1 /, { -init => 'bob' } => 'init2'
]];

La construction avec new1 implique un appel implicite à "init", tandis que la construction avec new2 implique un appel implicite à "bob" (au lieu de "init

").

Il est de la responsabilité de l'utilisateur de s'assurer qu'une méthode "init" (ou quel que soi

t son nom) est
définie.
-singlet
on
Crée un constructeur basique qui ne retourne jamais qu'une seule instance de la classe : c'est-à-dire, après le premier appel, les appels répétés à ce constructeur retournent la même instance. Notez que l'instance es
t instanciée au
moment du premie
r appel, pas avant.

abstrac

t 
use Class::MethodMaker
  [ abstract => [ qw / foo bar baz / ] ]
;

Cela crée un certain nombre de méthodes qui échoueront si elles sont a

ppelées. Cela est destiné à supporter l'utilisation de méthodes ab
straites, qui doivent être surchargées dans une sous-classe utile.

cop

y 
use Class::MethodMaker
  [ copy => [qw/ shallow -deep deep /] ]
;

Cela crée une méthode qui produit une copie de self. La copie est par défaut une copie superficielle ; toute référence sera partagée par l'instance sur laquelle la méthode est appelée et le nouveau-né retourné. Une option est prise, "-deep", qui fait que la méthode crée des copies profondes à la place (c'est-à-dire, les références sont copiées récursivement)

.

Note d'implémentation

:

Les copies profondes sont effectuées en utilisant le module "Storable" si disponible, sinon "Data::Dumper". Le module "Storable" est susceptible d'être beaucoup plus rapide. Cependant, cette note d'implémentation n'est pas une spécification d'API : les détails d'implémentation sont susceptibles de changer dans une future version à mesure que des moyens plus rapides/meilleurs d'effectuer une copie profonde deviennent

disponibles.

Notez que la copie profonde ne

prend actuellement pas en charg
e la copie de coderefs, de
ties ou d'objets basés sur XS.
