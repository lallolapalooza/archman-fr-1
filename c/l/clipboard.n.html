clipboard(n) Commandes intégrées Tk clipboard(n)

NOM

clipboard - Manipuler le presse-papiers Tk

SYNTAXE

clipboard option ?arg arg ...?

DESCRIPTION

Cette commande fournit une interface Tcl au presse-papiers Tk, qui stocke les données pour une récupération ultérieure à l'aide du mécanisme de sélection (via l'option -selection CLIPBOARD). Afin de copier des données dans le presse-papiers, clipboard clear doit être appelée, suivie d'une séquence d'un ou plusieurs appels à clipboard append. Pour garantir que le presse-papiers est mis à jour de manière atomique, toutes les ajouts doivent être terminés avant de retourner à la boucle d'événements.

Le premier argument de clipboard détermine le format du reste des arguments et le comportement de la commande. Les formes suivantes sont actuellement prises en charge :

clipboard append ?-displayof fenêtre? ?-format format? ?-type type? ?--? données
Ajoute les données au presse-papiers sur l'affichage de la fenêtre dans la forme donnée par type avec la représentation donnée par format et revendique la propriété du presse-papiers sur l'affichage de la fenêtre.

Type spécifie la forme dans laquelle la sélection doit être renvoyée (la “cible” souhaitée pour la conversion, dans la terminologie ICCCM), et doit être un nom d'atome tel que STRING ou FILE_NAME ; voir le Manuel des conventions de communication inter-clients pour plus de détails. Type prend par défaut la valeur STRING.

L'argument format spécifie la représentation qui doit être utilisée pour transmettre la sélection au demandeur (la deuxième colonne du Tableau 2 de l'ICCCM), et prend par défaut la valeur STRING. Si format est STRING, la sélection est transmise sous forme de caractères ASCII 8 bits. Si format est ATOM, alors les données sont divisées en champs séparés par des espaces ; chaque champ est converti en sa valeur d'atome, et la valeur d'atome de 32 bits est transmise au lieu du nom de l'atome. Pour tout autre format, données sont divisées en champs séparés par des espaces et chaque champ est converti en un entier de 32 bits ; un tableau d'entiers est transmis au demandeur de sélection. Notez que les chaînes passées à clipboard append sont concaténées avant la conversion, donc l'appelant doit prendre soin d'assurer un espacement approprié entre les limites des chaînes. Tous les éléments ajoutés au presse-papiers avec le même type doivent avoir le même format.

L'argument format n'est nécessaire que pour la compatibilité avec les demandeurs de presse-papiers qui n'utilisent pas Tk. Si la boîte à outils Tk est utilisée pour récupérer la sélection CLIPBOARD, la valeur est reconvertie en chaîne de caractères côté demandeur, donc format est sans importance.

Un argument -- peut être spécifié pour marquer la fin des options : l'argument suivant sera toujours utilisé comme données. Cette fonctionnalité peut être pratique si, par exemple, données commence par un -.

clipboard clear ?-displayof fenêtre?
Revendique la propriété du presse-papiers sur l'affichage de la fenêtre et supprime tout contenu précédent. Fenêtre prend par défaut la valeur “.”. Renvoie une chaîne vide.
clipboard get ?-displayof fenêtre? ?-type type?
Récupère les données du presse-papiers sur l'affichage de la fenêtre. Fenêtre prend par défaut la valeur “.”. Type spécifie la forme dans laquelle les données doivent être renvoyées et doit être un nom d'atome tel que STRING ou FILE_NAME. Type prend par défaut la valeur STRING. Cette commande est équivalente à “selection get -selection CLIPBOARD”.

Notez que sur les systèmes X11 modernes, le type le plus utile à récupérer pour les chaînes transférées n'est pas STRING, mais plutôt UTF8_STRING.

EXEMPLES

Obtenir le contenu actuel du presse-papiers.

if {[catch {clipboard get} contents]} {
    # Il n'y avait aucun contenu dans le presse-papiers
}

Définir le presse-papiers pour qu'il contienne une chaîne fixe.

clipboard clear
clipboard append "une chaîne fixe"

Vous pouvez placer des données personnalisées dans le presse-papiers en utilisant une option -type personnalisée. Ce n'est pas nécessairement portable, mais peut être très utile. La méthode de transmission de scripts Tcl de cette manière est efficace, mais devrait être mélangée avec des interpréteurs sûrs dans le code de production.

# Ceci est un sérialiseur de canvas très simple ;
# il produit un script qui recrée l'élément (les éléments) lorsqu'il est exécuté
proc getItemConfig {canvas tag} {
   set script {}
   foreach item [$canvas find withtag $tag] {
      append script {$canvas create } [$canvas type $item]
      append script { } [$canvas coords $item] { }
      foreach config [$canvas itemconf $item] {
         lassign $config name - - - value
         append script [list $name $value] { }
      }
      append script \n
   }
   return [string trim $script]
}
# Configurer une liaison sur un canvas pour couper et coller un élément
set c [canvas .c]
pack $c
$c create text 150 30 -text "coupez et collez-moi"
bind $c <<Cut>> {
   clipboard clear
   clipboard append -type TkCanvasItem \
         [getItemConfig %W current]
   # Supprimer car il s'agit d'une coupe, pas d'une copie.
   %W delete current
}
bind $c <<Paste>> {
   catch {
      set canvas %W
      eval [clipboard get -type TkCanvasItem]
   }
}
