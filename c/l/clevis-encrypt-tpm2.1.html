NOM

clevis-encrypt-tpm2 - Chiffre à l'aide d'une politique de liaison de puce TPM2.0

SYNTAXE

clevis encrypt tpm2 CONFIG < PT > JWE

APERÇU

La commande clevis encrypt tpm2 chiffre à l'aide d'une puce Trusted Platform Module 2.0 (TPM2). Son seul argument est l'objet de configuration JSON.

Lors de l'utilisation du mécanisme tpm2, nous créons une nouvelle clé aléatoire, cryptographiquement forte. Cette clé est chiffrée à l'aide de la puce TPM2. Ensuite, au moment du déchiffrement, la clé est à nouveau déchiffrée à l'aide de la puce TPM2.

$ clevis encrypt tpm2 '{}' < PT > JWE

Le mécanisme a des valeurs par défaut raisonnables pour sa configuration, mais un autre espace de hiérarchie, algorithme de hachage et algorithmes de clé peuvent être choisis si les valeurs par défaut utilisées ne conviennent pas :

$ clevis encrypt tpm2 '{"hash":"sha1","key":"rsa"}' < PT > JWE

Pour déchiffrer les données, fournissez simplement le texte chiffré (JWE) :

$ clevis decrypt < JWE > PT

Notez que, comme les autres mécanismes, aucune configuration n'est utilisée pour le déchiffrement. Ceci est dû au fait que clevis stocke les clés publiques et privées pour déverrouiller l'objet chiffré par TPM2 dans le JWE, de sorte que clevis puisse récupérer ces informations à partir de là.

Le mécanisme prend également en charge le scellement des données à un état de registres de configuration de plateforme (PCR). De cette façon, les données ne peuvent être déverrouillées que si les valeurs de hachage des PCR correspondent à la politique utilisée lors du scellement.

Par exemple, pour sceller les données au PCR avec les indices 0 et 1 pour la banque SHA1 :

$ clevis encrypt tpm2 '{"pcr_bank":"sha1","pcr_ids":"0,1"}' < PT > JWE

Les valeurs de résumé des PCR sont recherchées à partir des valeurs de hachage actuelles pour les PCR, mais un résumé peut également être fourni si les données doivent être scellées avec des valeurs différentes des valeurs actuelles, en transmettant le hachage binaire encodé en base64 :

$ clevis encrypt tpm2 '{"pcr_ids":"0","pcr_digest":"xy7J5svCtqlfM03d1lE5gdoA8MI"}' < PT > JWE

MODÈLE DE MENACE

Le modèle de sécurité Clevis repose sur le fait qu'un attaquant ne pourra pas accéder simultanément aux données chiffrées et à la clé de déchiffrement.

Pour la plupart des mécanismes Clevis, la clé de déchiffrement n'est pas stockée localement, de sorte que la politique de déchiffrement n'est satisfaite que si la clé de déchiffrement peut être accédée à distance. Elle pourrait, par exemple, être stockée sur un serveur distant ou sur un périphérique d'authentification matériel qui doit être branché sur la machine.

Le mécanisme tpm2 est différent à cet égard, car une clé est enveloppée par une puce TPM2 qui est toujours présente dans la machine. Cela ne signifie pas qu'il n'y a pas de cas d'utilisation pour ce mécanisme, mais il est important de comprendre que si un attaquant a accès à la fois aux données chiffrées et à la puce TPM2 locale, il pourra déchiffrer les données.

CONFIG

Cette commande utilise les propriétés de configuration suivantes :

•hash (chaîne) : Algorithme de hachage utilisé dans le calcul du nom de l'objet (défaut : sha256) 
Il doit être l'un des suivants :
•sha1
•sha256
•sha384
•sha512
•sm3_256
•key (chaîne) : Type d'algorithme pour la clé générée (défaut : ecc) 
Il doit être l'un des suivants :
•rsa
•keyedhash
•ecc
•symcipher
•pcr_bank (chaîne) : Banque d'algorithmes PCR à utiliser pour la politique (défaut : sha1) 
Il doit être l'un des suivants :
•sha1
•sha256
•pcr_ids (chaîne) : Liste de PCR séparés par des virgules utilisés pour la politique. Si absent, aucune politique n'est utilisée
•pcr_digest (chaîne) : Hachages binaires des PCR encodés en base64. Si absent, les valeurs de hachage sont recherchées
