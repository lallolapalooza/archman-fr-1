DESCRIPTION

Ces routines permettent aux programmes C d'effectuer des appels de procédures sur d'autres machines à travers le réseau. D'abord, le client appelle une procédure pour envoyer un paquet de données au serveur. À la réception du paquet, le serveur appelle une routine de distribution pour effectuer le service demandé, puis renvoie une réponse. Enfin, l'appel de procédure retourne au

client.

Pour utiliser ces routines, inclure le fichier d'en-tête <rpc/rpc.h>

.

enum clnt_stat clnt_broadcast(unsigned long prognum,
                     unsigned long versnum, unsigned long procnum,
                     xdrproc_t inproc, char *in,
                     xdrproc_t outproc, char *out,
                     resultproc_t eachresult)
;
Comme callrpc(), sauf que le message d'appel est diffusé à tous les réseaux de diffusion localement connectés. Chaque fois qu'elle reçoit une réponse, cette routine appelle eachresult(), dont la forme

approprié.
Avertissement : les sockets de diffusion sont limités en

void svc_destroy(SVCXPRT *xprt);
Une macro qui détruit le descripteur de transport de service RPC, xprt. La destruction implique généralement la désallocation des structures de données privées, y compris xprt lui-même. L'utilisation de xprt est indéfinie après l'appel de cette routine.
fd_set svc_fdset ;
Une variable globale reflétant le masque de bits du descripteur de fichier de lecture du côté service RPC ; elle convient comme paramètre pour l'appel système select(2). Ceci n'est pertinent que si un implémenteur de service effectue son propre traitement d'événements asynchrones, au lieu d'appeler svc_run(). Cette variable est en lecture seule (ne pas passer son adresse à select(2) !), et pourtant elle peut changer après les appels à svc_getreqset() ou à toute routine de création.
int svc_fds ;
Similaire à svc_fdset, mais limité à 32 descripteurs de fichiers. Cette interface est obsolète par svc_fdset.
svc_freeargs(SVCXPRT *xprt, xdrproc_t inproc, char *in);
Une macro qui libère toute donnée allouée par le système RPC/XDR lors du décodage des arguments d'une procédure de service à l'aide de svc_getargs(). Cette routine renvoie 1 si les résultats ont été libérés avec succès, et zéro sinon.
svc_getargs(SVCXPRT *xprt, xdrproc_t inproc, char *in);
Une macro qui décode les arguments d'une requête RPC associée au descripteur de transport de service RPC, xprt. Le paramètre in est l'adresse où les arguments seront placés ; inproc est la routine XDR utilisée pour décoder les arguments. Cette routine renvoie un si le décodage réussit, et zéro sinon.

void svc_getreqset(fd_set *rdfds);
Cette routine n'intéresse que si un implémenteur de service n'appelle pas svc_run(), mais implémente à la place un traitement d'événements asynchrones personnalisé. Elle est appelée lorsque l'appel système select(2) a déterminé qu'une requête RPC est arrivée sur un ou plusieurs sockets RPC ; rdfds est le masque de bits résultant des descripteurs de fichiers lus. La routine retourne lorsque tous les sockets associés à la valeur de rdfds ont été traités.
void svc_getreq(int rdfds);
Similaire à svc_getreqset(), mais limité à 32 descripteurs de fichiers. Cette interface est obsolète par svc_getreqset().
bool_t svc_register(SVCXPRT *xprt, unsigned long prognum,
                    unsigned long versnum,
                    typeof(void (struct svc_req *, SVCXPRT *)) *dispatch,
                    unsigned long protocol);
Associe prognum et versnum à la procédure de distribution de service, dispatch. Si protocol est zéro, le service n'est pas enregistré auprès du service portmap. Si protocol est non nul, alors un mappage du triplet [prognum,versnum,protocol] vers xprt->xp_port est établi avec le service portmap local (généralement protocol est zéro, IPPROTO_UDP ou IPPROTO_TCP). La procédure dispatch a la forme suivante :

dispatch(struct svc_req *request, SVCXPRT *xprt);

La routine svc_register() renvoie un si elle réussit, et zéro sinon.
void svc_run(void);
Cette routine ne retourne jamais. Elle attend que des requêtes RPC arrivent et appelle la procédure de service appropriée en utilisant svc_getreq() lorsqu'une arrive. Cette procédure attend généralement qu'un appel système select(2) retourne.
bool_t svc_sendreply(SVCXPRT *xprt, xdrproc_t outproc, char *out);
Appelée par la routine de distribution d'un service RPC pour envoyer les résultats d'un appel de procédure distante. Le paramètre xprt est le descripteur de transport associé à la requête ; outproc est la routine XDR utilisée pour encoder les résultats ; et out est l'adresse des résultats. Cette routine renvoie un si elle réussit, zéro sinon.
void svc_unregister(unsigned long prognum, unsigned long versnum);
Supprime tous les mappages du double [prognum,versnum] vers les routines de distribution, et du triplet [prognum,versnum,*] vers le numéro de port.

void svcerr_decode(SVCXPRT *xprt);

void svcerr_noproc(SVCXPRT *xprt);
Appelée par une routine de distribution de service qui n'implémente pas le numéro de procédure demandé par l'appelant.
void svcerr_noprog(SVCXPRT *xprt);
Appelée lorsque le programme désiré n'est pas enregistré auprès du package RPC. Les implémenteurs de service n'ont généralement pas besoin de cette routine.

Appelée lorsque la version désirée d'un programme n'est pas enregistrée auprès du package RPC. Les implémenteurs de service n'ont généralement pas besoin de cette routine.

Appelée par une routine de distribution de service lorsqu'elle détecte une erreur système non couverte par un protocole particulier. Par exemple, si un service ne peut plus allouer de stockage, il peut appeler cette routine.

Appelée par une routine de distribution de service qui refuse d'effectuer un appel de procédure distante en raison de paramètres d'authentification insuffisants. La routine appelle svcerr_auth(xprt, AUTH_TOOWEAK).
SVCXPRT *svcfd_create(int fd, unsigned int sendsize,
                      unsigned int recvsize);
Crée un service au-dessus de tout descripteur de fichier ouvert. Typiquement, ce descripteur de fichier est un socket connecté pour un protocole de flux tel que TCP. sendsize et recvsize indiquent les tailles des tampons d'envoi et de réception. S'ils sont zéro, une valeur par défaut raisonnable est choisie.
SVCXPRT *svcraw_create(void);
Cette routine crée un transport de service RPC jouet, auquel elle retourne un pointeur. Le transport est en réalité un tampon dans l'espace d'adressage du processus, donc le client RPC correspondant doit résider dans le même espace d'adressage ; voir clntraw_create(). Cette routine permet de simuler RPC et d'acquérir les surcoûts RPC (tels que les temps d'aller-retour), sans aucune interférence du noyau. Cette routine retourne NULL si elle échoue.
SVCXPRT *svctcp_create(int sock, unsigned int send_buf_size,
                       unsigned int recv_buf_size);
Cette routine crée un transport de service RPC basé sur TCP/IP, auquel elle retourne un pointeur. Le transport est associé au socket sock, qui peut être RPC_ANYSOCK, auquel cas un nouveau socket est créé. Si le socket n'est pas lié à un port TCP local, cette routine le lie à un port arbitraire. À l'issue de l'exécution, xprt->xp_sock est le descripteur de socket du transport, et xprt->xp_port est le numéro de port du transport. Cette routine retourne NULL si elle échoue. Comme le RPC basé sur TCP utilise des E/S bufferisées, les utilisateurs peuvent spécifier la taille des tampons ; les valeurs nulles choisissent des valeurs par défaut appropriées.
SVCXPRT *svcudp_bufcreate(int sock, unsigned int sendsize,
                          unsigned int recosize);
Cette routine crée un transport de service RPC basé sur UDP/IP, auquel elle retourne un pointeur. Le transport est associé au socket sock, qui peut être RPC_ANYSOCK, auquel cas un nouveau socket est créé. Si le socket n'est pas lié à un port UDP local, cette routine le lie à un port arbitraire. À l'issue de l'exécution, xprt->xp_sock est le descripteur de socket du transport, et xprt->xp_port est le numéro de port du transport. Cette routine retourne NULL si elle échoue.
Cela permet à l'utilisateur de spécifier la taille maximale de paquet pour les messages RPC basés sur UDP envoyés et reçus.
SVCXPRT *svcudp_create(int sock);
Cet appel est équivalent à svcudp_bufcreate(sock,SZ,SZ) pour une taille par défaut SZ.
bool_t xdr_accepted_reply(XDR *xdrs, struct accepted_reply *ar);
Utilisé pour l'encodage des messages de réponse RPC. Cette routine est utile pour les utilisateurs qui souhaitent générer des messages de style RPC sans utiliser le package RPC.

Une fois les gestionnaires de transport de services RPC créés, ils doivent s'enregistrer auprès du package de services RPC. Cette routine modifie la variable globale svc_fds. Les implémenteurs de services n'ont généralement pas besoin de cette routine.
