NOM

clevercsv-standardize - Convertir un fichier CSV en un fichier conforme à la RFC-4180

SYNTAXE

clevercsv standardize [-e ENCODING | --encoding=ENCODING]
                      [-E TARGET_ENCODING | --target-encoding=TARGET_ENCODING]
                      [-i | --in-place] [-n NUM_CHARS | --num-chars=NUM_CHARS]
                      [-o OUTPUT | --output=OUTPUT] [-t | --transpose]
                      <chemin [chemin ...]>

DESCRIPTION

La commande standardize peut être utilisée pour convertir un fichier CSV non standard au format standard RFC-4180 [1]. Lors de l'utilisation de l'option --in-place, le code de retour de CleverCSV peut être utilisé pour vérifier si un fichier a été modifié ou non. Le code de retour sera 2 si le fichier a été modifié et 0 sinon.

[1]: https://tools.ietf.org/html/rfc4180

OPTIONS

-h, --help

afficher ce message d'aide et quitter

-e, --encoding

Le codage du fichier CSV donné est automatiquement détecté à l'aide de chardet. Bien que chardet soit incroyablement précis, il n'est pas parfait. Dans les rares cas où il commet une erreur dans la détection du codage du fichier, vous pouvez remplacer le codage en le fournissant via ce drapeau. Pour cette commande, le codage fourni sera également utilisé pour les fichiers de sortie. Lorsque un seul codage est donné, il sera utilisé pour tous les fichiers fournis sur la ligne de commande. Lorsque plusieurs codages sont donnés, leur nombre doit correspondre au nombre de fichiers fournis en entrée.

-E, --target-encoding

Si omis, le codage du fichier de sortie sera le même que celui du fichier original.

-i, --in-place

Standardiser et écraser les fichiers d'entrée

-n, --num-chars

Sur les gros fichiers CSV, la détection du dialecte peut parfois être un peu lente en raison du grand nombre de dialectes possibles à considérer. Pour atténuer cela, vous pouvez limiter le nombre de caractères à utiliser pour la détection.

Un aspect à garder à l'esprit est que CleverCSV peut avoir besoin de lire un nombre spécifique de caractères pour pouvoir inférer correctement le dialecte. Par exemple, dans le fichier ``imdb.csv`` du dépôt GitHub, le dialecte correct ne peut être trouvé qu'après la lecture d'au moins 66 lignes du fichier. Par conséquent, s'il est possible d'exécuter CleverCSV sur l'ensemble du fichier, cela est généralement recommandé.

-o, --output

Les fichiers de sortie dans lesquels écrire les fichiers d'entrée standardisés. L'ordre des fichiers d'entrée et l'ordre des fichiers de sortie doivent correspondre si cette option est utilisée avec plusieurs fichiers d'entrée.

-t, --transpose

Transposer les colonnes des fichiers d'entrée avant l'écriture

<chemin>

Chemin vers un ou plusieurs fichiers CSV
