void clnt_geterr(CLIENT *clnt, struct rpc_err *errp);
Une macro qui copie la structure d'erreur du descripteur client vers la structure à l'adresse errp.
void clnt_pcreateerror(const char *s);
Affiche un message sur la sortie d'erreur standard indiquant pourquoi un descripteur RPC client n'a pas pu être créé. Le message est précédé de la chaîne s et d'un deux-points. Utilisé lorsqu'un appel à clnt_create(), clntraw_create(), clnttcp_create() ou clntudp_create() échoue.
void clnt_perrno(enum clnt_stat stat);
Affiche un message sur la sortie d'erreur standard correspondant à la condition indiquée par stat. Utilisé après callrpc().
clnt_perror(CLIENT *clnt, const char *s);
Affiche un message sur la sortie d'erreur standard indiquant pourquoi un appel RPC a échoué ; clnt est le descripteur utilisé pour effectuer l'appel. Le message est précédé de la chaîne s et d'un deux-points. Utilisé après clnt_call().
char *clnt_spcreateerror(const char *s);
Similaire à clnt_pcreateerror(), sauf qu'il renvoie une chaîne au lieu d'afficher sur la sortie d'erreur standard.
Bugs : renvoie un pointeur vers des données statiques qui sont écrasées à chaque appel.
char *clnt_sperrno(enum clnt_stat stat);
Prend les mêmes arguments que clnt_perrno(), mais au lieu d'envoyer un message sur la sortie d'erreur standard indiquant pourquoi un appel RPC a échoué, renvoie un pointeur vers une chaîne contenant le message. La chaîne se termine par un RETOUR À LA LIGNE.
clnt_sperrno() est utilisé à la place de clnt_perrno() si le programme n'a pas de sortie d'erreur standard (comme un programme s'exécutant en tant que serveur n'en a probablement pas), ou si le programmeur ne souhaite pas que le message soit émis avec printf(3), ou si un format de message différent de celui pris en charge par clnt_perrno() doit être utilisé. Remarque : contrairement à clnt_sperror() et clnt_spcreateerror(), clnt_sperrno() renvoie un pointeur vers des données statiques, mais le résultat ne sera pas écrasé à chaque appel.
char *clnt_sperror(CLIENT *rpch, const char *s);
Similaire à clnt_perror(), sauf que (comme clnt_sperrno()) il renvoie une chaîne au lieu d'afficher sur la sortie d'erreur standard.
Bugs : renvoie un pointeur vers des données statiques qui sont écrasées à chaque appel.
CLIENT *clntraw_create(unsigned long prognum, unsigned long versnum);
Cette routine crée un client RPC jouet pour le programme distant prognum, version versnum. Le transport utilisé pour passer des messages au service est en réalité un tampon dans l'espace d'adressage du processus, de sorte que le serveur RPC correspondant doit résider dans le même espace d'adressage ; voir svcraw_create(). Cela permet de simuler le RPC et d'acquérir les surcoûts du RPC, tels que les temps d'aller-retour, sans aucune interférence du noyau. Cette routine renvoie NULL en cas d'échec.
CLIENT *clnttcp_create(struct sockaddr_in *addr,
                unsigned long prognum, unsigned long versnum,
                int *sockp, unsigned int sendsz, unsigned int recvsz);
Cette routine crée un client RPC pour le programme distant prognum, version versnum ; le client utilise TCP/IP comme transport. Le programme distant est situé à l'adresse Internet *addr. Si addr->sin_port est zéro, il est défini sur le port réel sur lequel le programme distant écoute (le service portmap distant est consulté pour cette information). Le paramètre sockp est une socket ; si c'est RPC_ANYSOCK, cette routine en ouvre une nouvelle et définit sockp. Comme le RPC basé sur TCP utilise des E/S mises en tampon, l'utilisateur peut spécifier la taille des tampons d'envoi et de réception avec les paramètres sendsz et recvsz ; des valeurs de zéro choisissent des valeurs par défaut appropriées. Cette routine renvoie NULL en cas d'échec.
CLIENT *clntudp_create(struct sockaddr_in *addr,
                unsigned long prognum, unsigned long versnum,
                struct timeval wait, int *sockp);
Cette routine crée un client RPC pour le programme distant prognum, version versnum ; le client utilise UDP/IP comme transport. Le programme distant est situé à l'adresse Internet addr. Si addr->sin_port est zéro, il est défini sur le port réel sur lequel le programme distant écoute (le service portmap distant est consulté pour cette information). Le paramètre sockp est une socket ; si c'est RPC_ANYSOCK, cette routine en ouvre une nouvelle et définit sockp. Le transport UDP renvoie le message d'appel à intervalles de temps wait jusqu'à ce qu'une réponse soit reçue ou que l'appel expire. Le temps total d'expiration de l'appel est spécifié par clnt_call().
Attention : étant donné que les messages RPC basés sur UDP ne peuvent contenir que jusqu'à 8 Ko de données encodées, ce transport ne peut pas être utilisé pour les procédures qui prennent de gros arguments ou renvoient des résultats volumineux.
CLIENT *clntudp_bufcreate(struct sockaddr_in *addr,
            unsigned long prognum, unsigned long versnum,
            struct timeval wait, int *sockp,
            unsigned int sendsize, unsigned int recosize);
Cette routine crée un client RPC pour le programme distant prognum, version versnum ; le client utilise UDP/IP comme transport. Le programme distant est situé à l'adresse Internet addr. Si addr->sin_port est zéro, il est défini sur le port réel sur lequel le programme distant écoute (le service portmap distant est consulté pour cette information). Le paramètre sockp est une socket ; si c'est RPC_ANYSOCK, cette routine en ouvre une nouvelle et définit sockp. Le transport UDP renvoie le message d'appel à intervalles de temps wait jusqu'à ce qu'une réponse soit reçue ou que l'appel expire. Le temps total d'expiration de l'appel est spécifié par clnt_call().
Cela permet à l'utilisateur de spécifier la taille maximale du paquet pour l'envoi et la réception de messages RPC basés sur UDP.
void get_myaddress(struct sockaddr_in *addr);
Remplit la structure *addr avec l'adresse IP de la machine, sans consulter les routines de la bibliothèque qui traitent /etc/hosts. Le numéro de port est toujours défini sur htons(PMAPPORT).
struct pmaplist *pmap_getmaps(struct sockaddr_in *addr);
Une interface utilisateur pour le service portmap, qui renvoie une liste des mappages actuels de programmes RPC vers ports sur l'hôte situé à l'adresse IP *addr. Cette routine peut renvoyer NULL. La commande rpcinfo -p utilise cette routine.
unsigned short pmap_getport(struct sockaddr_in *addr,
                    unsigned long prognum, unsigned long versnum,
                    unsigned int protocol);
Une interface utilisateur pour le service portmap, qui renvoie le numéro de port sur lequel attend un service qui prend en charge le numéro de programme prognum, la version versnum, et parle le protocole de transport associé à protocol. La valeur de protocol est très probablement IPPROTO_UDP ou IPPROTO_TCP. Une valeur de retour de zéro signifie que le mappage n'existe pas ou que le système RPC n'a pas réussi à contacter le service portmap distant. Dans ce dernier cas, la variable globale rpc_createerr contient le statut RPC.
enum clnt_stat pmap_rmtcall(struct sockaddr_in *addr,
                    unsigned long prognum, unsigned long versnum,
                    unsigned long procnum,
                    xdrproc_t inproc, char *in,
                    xdrproc_t outproc, char *out,
                    struct timeval tout, unsigned long *portp);
Une interface utilisateur pour le service portmap, qui demande au portmap sur l'hôte à l'adresse IP *addr d'effectuer un appel RPC en votre nom vers une procédure sur cet hôte. Le paramètre *portp sera modifié pour contenir le numéro de port du programme si la procédure réussit. Les définitions des autres paramètres sont décrites dans callrpc() et clnt_call(). Cette procédure doit être utilisée uniquement pour un « ping » et rien d'autre. Voir aussi clnt_broadcast().
bool_t pmap_set(unsigned long prognum, unsigned long versnum,
                int protocol, unsigned short port);
Une interface utilisateur pour le service portmap, qui établit un mappage entre le triplet [prognum,versnum,protocol] et port sur le service portmap de la machine. La valeur de protocol est très probablement IPPROTO_UDP ou IPPROTO_TCP. Cette routine renvoie un si elle réussit, zéro sinon. Automatiquement effectué par svc_register().
bool_t pmap_unset(unsigned long prognum, unsigned long versnum);
Une interface utilisateur pour le service portmap, qui détruit tous les mappages entre le triplet [prognum,versnum,*] et les ports sur le service portmap de la machine. Cette routine renvoie un si elle réussit, zéro sinon.
int registerrpc(unsigned long prognum, unsigned long versnum,
                unsigned long procnum, typeof(char *(char *)) *procname,
                xdrproc_t inproc, xdrproc_t outproc);
Enregistre la procédure procname auprès du package de services RPC. Si une requête arrive pour le programme prognum, la version versnum et la procédure procnum, procname est appelée avec un pointeur vers ses paramètres ; procname doit renvoyer un pointeur vers ses résultats statiques ; inproc est utilisé pour décoder les paramètres tandis que outproc est utilisé pour encoder les résultats. Cette routine renvoie zéro si l'enregistrement a réussi, -1 sinon.
Attention : les procédures distantes enregistrées sous cette forme sont accessibles en utilisant le protocole UDP/IP
transport ; voir svcudp_create() pour les restrictions. 
struct rpc_createerr rpc_createerr ;
Une variable globale dont la valeur est définie par toute routine de création de client RPC qui n'aboutit pas. Utilisez la routine clnt_pcreateerror() pour afficher la raison.
void svc_destroy(SVCXPRT *xprt);
Une macro qui détruit le descripteur de transport du service RPC, xprt. La destruction implique généralement la désallocation des structures de données privées, y compris xprt lui-même. L'utilisation de xprt est indéfinie après l'appel de cette routine.
fd_set svc_fdset ;
Une variable globale reflétant le masque de bits des descripteurs de fichiers en lecture du côté service RPC ; elle convient comme paramètre pour l'appel système select(2). Ceci n'est intéressant que si un implémenteur de service effectue son propre traitement asynchrone d'événements, au lieu d'appeler svc_run(). Cette variable est en lecture seule (ne pas passer son adresse à select(2) !), pourtant elle peut changer après les appels à svc_getreqset() ou à toute routine de création.
int svc_fds ;
Similaire à svc_fdset, mais limité à 32 descripteurs de fichiers. Cette interface est obsolète par svc_fdset.
svc_freeargs(SVCXPRT *xprt, xdrproc_t inproc, char *in);
Une macro qui libère toute donnée allouée par le système RPC/XDR lors de la dé-sérialisation des arguments d'une procédure de service à l'aide de svc_getargs(). Cette routine retourne 1 si les résultats ont été libérés avec succès, et zéro sinon.
svc_getargs(SVCXPRT *xprt, xdrproc_t inproc, char *in);
Une macro qui dé-sérialise les arguments d'une requête RPC associée au descripteur de transport du service RPC, xprt. Le paramètre in est l'adresse où seront placés les arguments ; inproc est la routine XDR utilisée pour dé-sérialiser les arguments. Cette routine retourne un si la dé-sérialisation réussit, et zéro sinon.
struct sockaddr_in *svc_getcaller(SVCXPRT *xprt);
La manière approuvée d'obtenir l'adresse réseau de l'appelant d'une procédure associée au descripteur de transport du service RPC, xprt.
void svc_getreqset(fd_set *rdfds);
Cette routine n'intéresse que si un implémenteur de service n'appelle pas svc_run(), mais implémente à la place un traitement personnalisé asynchrone d'événements. Elle est appelée lorsque l'appel système select(2) a déterminé qu'une requête RPC est arrivée sur un ou plusieurs sockets RPC ; rdfds est le masque de bits des descripteurs de fichiers en lecture résultant. La routine retourne lorsque tous les sockets associés à la valeur de rdfds ont été traités.
void svc_getreq(int rdfds);
Similaire à svc_getreqset(), mais limité à 32 descripteurs de fichiers. Cette interface est obsolète par svc_getreqset().
bool_t svc_register(SVCXPRT *xprt, unsigned long prognum,
                    unsigned long versnum,
                    typeof(void (struct svc_req *, SVCXPRT *)) *dispatch,
                    unsigned long protocol);
Associe prognum et versnum à la procédure de dispatch du service, dispatch. Si protocol est zéro, le service n'est pas enregistré auprès du service portmap. Si protocol est non nul, alors un mappage du triplet [prognum,versnum,protocol] à xprt->xp_port est établi avec le service portmap local (généralement protocol est zéro, IPPROTO_UDP ou IPPROTO_TCP). La procédure dispatch a la forme suivante :

dispatch(struct svc_req *request, SVCXPRT *xprt);

La routine svc_register() retourne un si elle réussit, et zéro sinon.
void svc_run(void);
Cette routine ne retourne jamais. Elle attend que des requêtes RPC arrivent, et appelle la procédure de service appropriée en utilisant svc_getreq() lorsqu'une arrive. Cette procédure attend généralement qu'un appel système select(2) retourne.
bool_t svc_sendreply(SVCXPRT *xprt, xdrproc_t outproc, char *out);
Appelée par la routine de dispatch d'un service RPC pour envoyer les résultats d'un appel de procédure distante. Le paramètre xprt est le descripteur de transport associé à la requête ; outproc est la routine XDR qui est utilisée pour sérialiser les résultats ; et out est l'adresse des résultats. Cette routine retourne un si elle réussit, zéro sinon.
void svc_unregister(unsigned long prognum, unsigned long versnum);
Supprime tous les mappages du double [prognum,versnum] aux procédures de dispatch, et du triplet [prognum,versnum,*] au numéro de port.
void svcerr_auth(SVCXPRT *xprt, enum auth_stat why);
Appelée par une routine de dispatch de service qui refuse d'effectuer un appel de procédure distante en raison d'une erreur d'authentification.
void svcerr_decode(SVCXPRT *xprt);
Appelée par une routine de dispatch de service qui ne parvient pas à dé-sérialiser ses paramètres. Voir aussi svc_getargs().
void svcerr_noproc(SVCXPRT *xprt);
Appelée par une routine de dispatch de service qui n'implémente pas la procédure numéro demandée par l'appelant.
void svcerr_noprog(SVCXPRT *xprt);
Appelée lorsque le programme désiré n'est pas enregistré auprès du package RPC. Les implémenteurs de service n'ont généralement pas besoin de cette routine.
void svcerr_progvers(SVCXPRT *xprt, unsigned long low_vers,
                     unsigned long high_vers);
Appelée lorsque la version désirée d'un programme n'est pas enregistrée auprès du package RPC. Les implémenteurs de service n'ont généralement pas besoin de cette routine.
void svcerr_systemerr(SVCXPRT *xprt);
Appelée par une routine de dispatch de service lorsqu'elle détecte une erreur système non couverte par un protocole particulier. Par exemple, si un service ne parvient plus à allouer de stockage, il peut appeler cette routine.
void svcerr_weakauth(SVCXPRT *xprt);
Appelée par une routine de dispatch de service qui refuse d'effectuer un appel de procédure distante en raison de paramètres d'authentification insuffisants. La routine appelle svcerr_auth(xprt, AUTH_TOOWEAK).
SVCXPRT *svcfd_create(int fd, unsigned int sendsize,
                      unsigned int recvsize);
Crée un service au-dessus de tout descripteur de fichier ouvert. Typiquement, ce descripteur de fichier est un socket connecté pour un protocole de flux comme TCP. sendsize et recvsize indiquent les tailles des tampons d'envoi et de réception. S'ils sont zéro, un défaut raisonnable est choisi.
SVCXPRT *svcraw_create(void);
Cette routine crée un transport de service RPC "jouet", auquel elle retourne un pointeur. Le transport est en réalité un tampon dans l'espace d'adressage du processus, donc le client RPC correspondant devrait résider dans le même espace d'adressage ; voir clntraw_create(). Cette routine permet de simuler RPC et d'acquérir les surcoûts RPC (tels que les temps d'aller-retour), sans aucune interférence du noyau. Cette routine retourne NULL si elle échoue.
SVCXPRT *svctcp_create(int sock, unsigned int send_buf_size,
                       unsigned int recv_buf_size);
Cette routine crée un transport de service RPC basé sur TCP/IP, auquel elle retourne un pointeur. Le transport est associé au socket sock, qui peut être RPC_ANYSOCK, auquel cas un nouveau socket est créé. Si le socket n'est pas lié à un port TCP local, alors cette routine le lie à un port arbitraire.
