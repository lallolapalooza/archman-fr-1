;
Cette routine crée un client RPC fictif pour le programme distant prognum, version versnum. Le transport utilisé pour passer les messages au service est en réalité un tampon dans l'espace d'adressage du processus, de sorte que le serveur RPC correspondant doit se trouver dans le même espace d'adressage ; voir svcraw_create(). Cela permet la simulation de RPC et l'acquisition des surcoûts RPC, comme les tem

CLIENT *clnttcp_create(struct sockaddr_in *addr,
                unsigned long prognum, unsigned long versnum,
                int *sockp, unsigned int sendsz, unsigned int recvsz)
;
Cette routine crée un client RPC pour le programme distant prognum, version versnum ; le client utilise TCP/IP comme transport. Le programme distant est situé à l'adresse Internet *addr. Si addr->sin_port est zéro, alors il est défini sur le port réel sur lequel le programme distant écoute (le service portmap distant est consulté pour cette information). Le paramètre sockp est un socket ; s'il est RPC_ANYSOCK, alors cette routine en ouvre un nouveau et définit sockp. Puisque le RPC basé sur TCP utilise une E/S tamponnée, l'utilisateur peut spécifier la taille des tampons d'envoi et de réception avec les paramètres sendsz et recvsz ; des valeurs de zéro choisissent des valeurs par défaut

void svc_destroy(SVCXPRT *xprt) ;
Une macro qui détruit le handle de transport du service RPC, xprt. La destruction implique généralement la désallocation des structures de données privées, y compris xprt lui-même. L'utilisation de xprt est indéfinie après l'appel de cette routine.
fd_set svc_fdset ;
Une variable globale reflétant le masque de bits des descripteurs de fichiers à lire du côté du service RPC ; elle convient comme paramètre à l'appel système select(2). Ceci n'est pertinent que si un implémenteur de service effectue son propre traitement asynchrone d'événements, au lieu d'appeler svc_run(). Cette variable est en lecture seule (ne pas passer son adresse à select(2) !), et elle peut changer après les appels à svc_getreqset() ou à toute routine de création.
int svc_fds ;
Similaire à svc_fdset, mais limité à 32 descripteurs de fichiers. Cette interface est obsolète par svc_fdset.
svc_freeargs(SVCXPRT *xprt, xdrproc_t inproc, char *in) ;
Une macro qui libère toute donnée allouée par le système RPC/XDR lors du décodage des arguments d'une procédure de service à l'aide de svc_getargs(). Cette routine renvoie 1 si les résultats ont été libérés avec succès, et zéro sinon.
svc_getargs(SVCXPRT *xprt, xdrproc_t inproc, char *in) ;
Une macro qui décode les arguments d'une requête RPC associée au handle de transport du service RPC, xprt. Le paramètre in est l'adresse où les arguments seront placés ; inproc est la routine XDR utilisée pour décoder les arguments. Cette routine renvoie un si le décodage réussit, et zéro sinon.
struct sockaddr_in *svc_getcaller(SVCXPRT *xprt) ;
La méthode approuvée pour obtenir l'adresse réseau de l'appelant d'une procédure associée au handle de transport du service RPC, xprt.
void svc_getreqset(fd_set *rdfds) ;
Cette routine n'intéresse que si un implémenteur de service n'appelle pas svc_run(), mais implémente plutôt un traitement asynchrone personnalisé d'événements. Elle est appelée lorsque l'appel système select(2) a déterminé qu'une requête RPC est arrivée sur un ou plusieurs sockets RPC ; rdfds est le masque de bits résultant des descripteurs de fichiers à lire. La routine retourne lorsque tous les sockets associés à la valeur de rdfds ont été traités.
void svc_getreq(int rdfds) ;
Similaire à svc_getreqset(), mais limité à 32 descripteurs de fichiers. Cette interface est obsolète par svc_getreqset().
bool_t svc_register(SVCXPRT *xprt, unsigned long prognum,
                    unsigned long versnum,
                    typeof(void (struct svc_req *, SVCXPRT *)) *dispatch,
                    unsigned long protocol) ;
Associe prognum et versnum à la procédure de dispatch du service, dispatch. Si protocol est zéro, le service n'est pas enregistré auprès du service portmap. Si protocol est non nul, alors un mappage du triple [prognum,versnum,protocol] à xprt->xp_port est établi avec le service local portmap (généralement protocol est zéro, IPPROTO_UDP ou IPPROTO_TCP). La procédure dispatch a la forme suivante :

dispatch(struct svc_req *request, SVCXPRT *xprt) ;

La routine svc_register() renvoie un si elle réussit, et zéro sinon.
void svc_run(void) ;
Cette routine ne retourne jamais. Elle attend l'arrivée de requêtes RPC et appelle la procédure de service appropriée en utilisant svc_getreq() lorsqu'une arrive. Cette procédure attend généralement qu'un appel système select(2) retourne.
bool_t svc_sendreply(SVCXPRT *xprt, xdrproc_t outproc, char *out) ;
Appelée par la routine de dispatch d'un service RPC pour envoyer les résultats d'un appel de procédure distante. Le paramètre xprt est le handle de transport associé à la requête ; outproc est la routine XDR utilisée pour encoder les résultats ; et out est l'adresse des résultats. Cette routine renvoie un si elle réussit, zéro sinon.
void svc_unregister(unsigned long prognum, unsigned long versnum) ;

                      unsigned int recvsize) ;
Crée un service basé sur un descripteur de fichier ouvert. SVCXPRT *svcraw_create(void) ;
Cette routine crée un transport de service RPC jouet, auquel elle renvoie un pointeur. Le transport est en fait un tampon dans l'espace d'adressage du processus, donc le client RPC correspondant doit résider dans le même espace d'adressage ; voir clntraw_create(). Cette routine permet de simuler RPC et d'acquérir les surcoûts RPC (tels que les temps d'aller-retour), sans aucune interférence du noyau. Cette routine renvoie NULL en cas d'échec.
