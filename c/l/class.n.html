NOM

itcl::class - créer une classe d'objets

SYNOPSIS

itcl::class className {
    inherit baseClass ?baseClass...?
    constructor args ?init? body
    destructor body
    method name ?args? ?body?
    proc name ?args? ?body?
    variable varName ?init? ?config?
    common varName ?init?
    public command ?arg arg ...?
    protected command ?arg arg ...?
    private command ?arg arg ...?
    set varName ?value?
    array option ?arg arg ...?
}
className objName ?arg arg ...?
objName method ?arg arg ...?
className::proc ?arg arg ...?

DESCRIPTION

La construction fondamentale dans [incr Tcl] est la définition de classe. Chaque classe agit comme un modèle pour les objets réels qui peuvent être créés. La classe elle-même est un espace de noms qui contient les éléments communs à tous les objets. Chaque objet possède son propre ensemble unique de données qui contient des instances des "variables" définies dans la définition de classe. Chaque objet possède également une variable intégrée nommée "this", qui contient le nom de l'objet. Les classes peuvent également avoir des membres de données "common" (communs) partagés par tous les objets d'une classe.

Deux types de fonctions peuvent être inclus dans la définition de classe. Les "methods" (méthodes) sont des fonctions qui opèrent sur un objet spécifique et ont donc accès à la fois aux membres de données "variables" et "common". Les "procs" sont des procédures ordinaires dans l'espace de noms de la classe et n'ont accès qu'aux membres de données "common".

Si le corps d'une méthode ou d'une proc commence par@", il est traité comme le nom symbolique d'une procédure C. Sinon, il est traité comme un script de code Tcl. Voir ci-dessous pour plus de détails sur l'enregistrement et l'utilisation des procédures C.

Une classe ne peut être définie qu'une seule fois, bien que les corps des méthodes et des procs de la classe puissent être définis encore et encore pour le débogage interactif. Voir les commandes body et configbody pour plus de détails.

Chaque espace de noms peut avoir sa propre collection d'objets et de classes. La liste des classes disponibles dans le contexte actuel peut être interrogée à l'aide de la commande "itcl::find classes", et la liste des objets, avec la commande "itcl::find objects".

Une classe peut être supprimée à l'aide de la commande "delete class". Les objets individuels peuvent être supprimés à l'aide de la commande "delete object".

DÉFINITIONS DE CLASSES

class className definition
Fournit la définition pour une classe nommée className. Si la classe className existe déjà, ou si une commande appelée className existe dans le contexte d'espace de noms actuel, cette commande renvoie une erreur. Si la définition de classe est analysée avec succès, className devient une commande dans le contexte actuel, gérant la création d'objets pour cette classe.

La définition definition de la classe est évaluée comme une série d'instructions Tcl qui définissent des éléments au sein de la classe. Les commandes de définition de classe suivantes sont reconnues :

inherit baseClass ?baseClass...?
Fait hériter la classe actuelle de caractéristiques d'une ou plusieurs classes de base. Les classes doivent avoir été définies par une commande class précédente, ou doivent être disponibles pour la fonctionnalité de chargement automatique (voir "AUTO-LOADING" ci-dessous). Une définition de classe unique ne peut contenir qu'une seule commande inherit .

L'ordre des noms baseClass dans la liste inherit affecte la résolution des noms pour les membres de la classe. Lorsque le même nom de membre apparaît dans deux classes de base ou plus, la classe de base qui apparaît en premier dans la liste inherit a la priorité. Par exemple, si les classes "Foo" et "Bar" contiennent toutes deux le membre "x", et si une autre classe a l'instruction "inherit" :

inherit Foo Bar

alors le nom "x" signifie "Foo::x". Les autres membres hérités nommés "x" doivent être référencés avec leur nom explicite, comme "Bar::x".

constructor args ?init? body
Déclare la liste d'arguments args et le body utilisés pour le constructeur, qui est automatiquement invoqué chaque fois qu'un objet est créé.

Avant que le body ne soit exécuté, l'instruction facultative init est utilisée pour invoquer les constructeurs de classe de base qui nécessitent des arguments. Les variables dans la spécification args peuvent être accessibles dans le fragment de code init et passées aux constructeurs de classe de base. Après l'évaluation de l'instruction init , les constructeurs de classe de base qui n'ont pas été exécutés sont invoqués automatiquement sans arguments. Cela garantit que toutes les classes de base sont entièrement construites avant que le body du constructeur ne soit exécuté. Par défaut, ce schéma fait que les constructeurs sont invoqués dans l'ordre du moins spécifique au plus spécifique. C'est exactement l'opposé de l'ordre dans lequel les classes sont rapportées par la commande info heritage .

Si la construction réussit, le constructeur renvoie toujours le nom de l'objet, quelle que soit la façon dont le body est défini, et le nom de l'objet devient une commande dans le contexte d'espace de noms actuel. Si la construction échoue, un message d'erreur est renvoyé.

destructor body
Déclare le body utilisé pour le destructeur, qui est automatiquement invoqué lorsqu'un objet est supprimé. Si le destructeur réussit, les données de l'objet sont détruites et le nom de l'objet est supprimé en tant que commande de l'interpréteur. Si la destruction échoue, un message d'erreur est renvoyé et l'objet reste.

Lorsqu'un objet est détruit, tous les destructeurs de sa hiérarchie de classes sont invoqués dans l'ordre du plus spécifique au moins spécifique. C'est l'ordre dans lequel les classes sont rapportées par la commande "info heritage", et c'est exactement l'opposé de l'ordre par défaut des constructeurs.

method name ?args? ?body?
Déclare une méthode appelée name. Lorsque le body de la méthode est exécuté, il aura un accès automatique aux variables spécifiques à l'objet et aux membres de données communs.

Si la liste args est spécifiée, elle établit les informations d'utilisation pour cette méthode. La commande body peut être utilisée pour redéfinir le corps de la méthode, mais la liste args doit correspondre à cette spécification.

Dans le corps d'une autre méthode de classe, une méthode peut être invoquée comme n'importe quelle autre commande, simplement en utilisant son nom. En dehors du contexte de la classe, le nom de la méthode doit être préfixé par un nom d'objet, qui fournit le contexte pour les données qu'il manipule. Les méthodes dans une classe de base qui sont redéfinies dans la classe actuelle, ou masquées par une autre classe de base, peuvent être qualifiées à l'aide de la syntaxe "className::method".

proc name ?args? ?body?
Déclare une proc appelée name. Une proc est une procédure ordinaire dans l'espace de noms de la classe. Contrairement à une méthode, une proc est invoquée sans faire référence à un objet spécifique. Lorsque le body de la proc est exécuté, il n'aura un accès automatique qu'aux membres de données communs.

Si la liste args est spécifiée, elle établit les informations d'utilisation pour cette proc. La commande body peut être utilisée pour redéfinir le corps de la proc, mais la liste args doit correspondre à cette spécification.

Dans le corps d'une autre méthode ou proc de classe, une proc peut être invoquée comme n'importe quelle autre commande, simplement en utilisant son nom. Dans tout autre contexte d'espace de noms, la proc est invoquée à l'aide d'un nom qualifié comme "className::proc". Les procs dans une classe de base qui sont redéfinies dans la classe actuelle, ou masquées par une autre classe de base, peuvent également être accessibles via leur nom qualifié.

CHAÎNAGE DE MÉTHODES/PROCÉDURE

S

Parfois, une classe de base a une méthode ou une procédure qui est redéfinie avec le même nom dans une classe dérivée. C'est une façon de faire en sorte que la classe dérivée gère les mêmes opérations que la classe de base, mais avec son propre comportement spécialisé. Par exemple, supposons que nous ayons une classe Toaster qui ressemble à ceci

: 
itcl::class Toaster {
    variable crumbs 0
    method toast {nslices} {
        if {$crumbs > 50} {
            error "== FIRE! FIRE! =="
        }
        set crumbs [expr {$crumbs+4*$nslices}]
    }
    method clean {} {
        set crumbs 0
    }
}

Nous pourrions créer une autre classe comme SmartToaster qui redéfinit la méthode "toasthod. Si nous voulons accéder à une méthode de la classe de base, nous pouvons la qualifier avec le nom de la classe de base, pour éviter toute ambiguïté :

itcl::class SmartToaster {
    inherit Toaster
    method toast {nslices} {
        if {$crumbs > 40} {
            clean
        }
        return [Toaster::toast $nslices]
    }
}

Au lieu de coder en dur le nom de la classe de base, nous pouvons utiliser la commande « chain » comme ceci :

itcl::class SmartToaster {
    inherit Toaster
    method toast {nslices} {
        if {$crumbs > 40} {
            clean
        }
        return [chain $nslices]
    }
}

La commande chain recherche dans la hiérarchie des classes une implémentation légèrement plus générique (classe de base) d'une méthode ou d'une procédure, et l'invoque avec les arguments spécifiés. Elle commence dans le contexte de la classe actuelle et recherche dans les classes de base dans l'ordre où elles sont rapportées par la commande « info heritage ». Si une autre implémentation n'est pas trouvée, cette commande ne fait rien et retourne la chaîne nulle.

CHARGEMENT AUTOMATIQUE

Les définitions de classes n'ont pas besoin d'être chargées explicitement ; elles peuvent être chargées au besoin par le mécanisme habituel de chargement automatique de Tcl. Chaque répertoire contenant des fichiers de définition de classes doit avoir un fichier « tclIndex » accompagnateur. Chaque ligne de ce fichier identifie une procédure Tcl ou une définition de classe [incr Tcl] et le fichier où la définition peut être trouvée.

Par exemple, supposons qu'un répertoire contienne les définitions des classes « Toaster » et « SmartToaster ». Alors le fichier « tclIndex » pour ce répertoire ressemblerait à ceci :

# Fichier d'index de chargement automatique Tcl, version 2.0 pour [incr Tcl]
# Ce fichier est généré par la commande « auto_mkindex »
# et sourcé pour mettre en place les informations d'indexation pour une ou
# plusieurs commandes. Généralement, chaque ligne est une commande qui
# définit un élément dans le tableau auto_index, où le
# nom de l'élément est le nom d'une commande et la valeur est
# un script qui charge la commande.
set auto_index(::Toaster) "source $dir/Toaster.itcl"
set auto_index(::SmartToaster) "source $dir/SmartToaster.itcl"

La commande auto_mkindex est utilisée pour générer automatiquement des fichiers « tclIndex ».

Le chargeur automatique doit être informé de ce répertoire en ajoutant le nom du répertoire à la variable « auto_path ». Lorsque cela est en place, les classes seront chargées automatiquement au besoin lorsqu'elles seront utilisées dans une application.

PROCÉDURES C

Les procédures C peuvent être intégrées dans une définition de classe [incr Tcl] pour implémenter des méthodes, des procédures et le code « config » pour les variables publiques. Tout corps qui commence par « @ » est traité comme le nom symbolique d'une procédure C.

Les noms symboliques sont établis en enregistrant des procédures via Itcl_RegisterC(). Cela est généralement fait dans la procédure Tcl_AppInit(), qui est automatiquement appelée au démarrage de l'interpréteur. Dans l'exemple suivant, la procédure My_FooCmd() est enregistrée sous le nom symbolique « foo ». Cette procédure peut être référencée dans la commande body sous la forme « @foo ».

int
Tcl_AppInit(interp)
    Tcl_Interp *interp;     /* Interpréteur pour l'application. */
{
    if (Itcl_Init(interp) == TCL_ERROR) {
        return TCL_ERROR;
    }
    if (Itcl_RegisterC(interp, "foo", My_FooCmd) != TCL_OK) {
        return TCL_ERROR;
    }
}

Les procédures C sont implémentées comme des commandes Tcl ordinaires. Voir la page de manuel CrtCommand pour plus de détails. À l'intérieur de la procédure, les membres de données de classe peuvent être accédés comme des variables ordinaires en utilisant Tcl_SetVar(), Tcl_GetVar(), Tcl_TraceVar(), etc. Les méthodes et procédures de classe peuvent être exécutées comme des commandes ordinaires en utilisant Tcl_Eval(). [incr Tcl] rend cela possible en configurant automatiquement le contexte avant d'exécuter la procédure C.

Ce schéma offre un chemin de migration naturel pour le développement de code. Les classes peuvent être développées rapidement en utilisant du code Tcl pour implémenter les corps. Une application entière peut être construite et testée. Lorsque nécessaire, des corps individuels peuvent être implémentés avec du code C pour améliorer les performances.
