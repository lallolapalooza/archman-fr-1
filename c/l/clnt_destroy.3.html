rpc(3) Manuel des fonctions de bibliothèque rpc(3)

NOM

rpc - routines de bibliothèque pour les appels de procédure distante

BIBLIOTHÈQUE

Bibliothèque C standard (libc, -lc)

SYNOPSIS ET DESCRIPTION

Ces routines permettent aux programmes C de faire des appels de procédure sur d'autres machines à travers le réseau. D'abord, le client appelle une procédure pour envoyer un paquet de données au serveur. À la réception du paquet, le serveur appelle une routine de dispatch pour effectuer le service demandé, puis renvoie une réponse. Enfin, l'appel de procédure retourne au client.

Pour utiliser ces routines, incluez le fichier d'en-tête <rpc/rpc.h>.

Les prototypes ci-dessous utilisent les types suivants :

typedef int bool_t;
typedef typeof(bool_t (XDR *, void *, ...))  *xdrproc_t;
typedef typeof(bool_t (caddr_t resp, struct sockaddr_in *raddr)
    *resultproc_t;

Consultez les fichiers d'en-tête pour les déclarations des types AUTH, CLIENT, SVCXPRT et XDR.

void auth_destroy(AUTH *auth);
Une macro qui détruit les informations d'authentification associées à auth. La destruction implique généralement la désallocation des structures de données privées. L'utilisation de auth est indéfinie après l'appel à auth_destroy().
AUTH *authnone_create(void);
Crée et renvoie un handle d'authentification RPC qui passe des informations d'authentification non utilisables avec chaque appel de procédure distante. C'est l'authentification par défaut utilisée par RPC.
AUTH *authunix_create(char *host, uid_t uid, gid_t gid,
                      int n, gid_t aup_gids[n]);
Crée et renvoie un handle d'authentification RPC contenant des informations d'authentification. Le paramètre host est le nom de la machine sur laquelle les informations ont été créées ; uid est l'ID utilisateur ; gid est l'ID de groupe actuel de l'utilisateur ; n et aup_gids font référence à un tableau indexé des groupes auxquels l'utilisateur appartient. Il est facile d'usurper l'identité d'un utilisateur.
AUTH *authunix_create_default(void);
Appelle authunix_create() avec les paramètres appropriés.
int callrpc(char *host, unsigned long prognum,
            unsigned long versnum, unsigned long procnum,
            xdrproc_t inproc, const char *in,
            xdrproc_t outproc, char *out);
Appelle la procédure distante associée à prognum, versnum et procnum sur la machine host. Le paramètre in est l'adresse des arguments de la procédure, et out est l'adresse où placer le(s) résultat(s) ; inproc est utilisé pour encoder les paramètres de la procédure, et outproc est utilisé pour décoder les résultats de la procédure. Cette routine renvoie zéro en cas de succès, ou la valeur de enum clnt_stat convertie en entier en cas d'échec. La routine clnt_perrno() est pratique pour traduire les statuts d'échec en messages.
Avertissement : l'appel de procédures distantes avec cette routine utilise UDP/IP comme transport ; consultez clntudp_create() pour connaître les restrictions. Vous n'avez pas le contrôle des délais d'attente ou de l'authentification avec cette routine.
enum clnt_stat clnt_broadcast(unsigned long prognum,
                     unsigned long versnum, unsigned long procnum,
                     xdrproc_t inproc, char *in,
                     xdrproc_t outproc, char *out,
                     resultproc_t eachresult);
Similaire à callrpc(), sauf que le message d'appel est diffusé à tous les réseaux locaux de diffusion connectés. Chaque fois qu'il reçoit une réponse, cette routine appelle eachresult(), dont la forme est :

eachresult(char *out, struct sockaddr_in *addr);

où out est le même que out passé à clnt_broadcast(), sauf que la sortie de la procédure distante y est décodée ; addr pointe vers l'adresse de la machine qui a envoyé les résultats. Si eachresult() renvoie zéro, clnt_broadcast() attend d'autres réponses ; sinon, elle retourne avec le statut approprié.
Avertissement : les sockets de diffusion sont limitées en taille à l'unité de transfert maximale de la liaison de données. Pour ethernet, cette valeur est de 1500 octets.
enum clnt_stat clnt_call(CLIENT *clnt, unsigned long procnum,
                    xdrproc_t inproc, char *in,
                    xdrproc_t outproc, char *out,
                    struct timeval tout);
Une macro qui appelle la procédure distante procnum associée au handle client, clnt, qui est obtenu avec une routine de création client RPC telle que clnt_create(). Le paramètre in est l'adresse des arguments de la procédure, et out est l'adresse où placer le(s) résultat(s) ; inproc est utilisé pour encoder les paramètres de la procédure, et outproc est utilisé pour décoder les résultats de la procédure ; tout est le temps alloué pour le retour des résultats.
clnt_destroy(CLIENT *clnt);
Une macro qui détruit le handle RPC du client. La destruction implique généralement la désallocation des structures de données privées, y compris clnt lui-même. L'utilisation de clnt est indéfinie après l'appel à clnt_destroy(). Si la bibliothèque RPC a ouvert le socket associé, elle le fermera également. Sinon, le socket reste ouvert.
CLIENT *clnt_create(const char *host, unsigned long prog,
                    unsigned long vers, const char *proto);
Routine générique de création de client. host identifie le nom de l'hôte distant où se trouve le serveur. proto indique quel type de protocole de transport utiliser. Les valeurs actuellement prises en charge pour ce champ sont “udp” et “tcp”. Des délais d'attente par défaut sont définis, mais peuvent être modifiés à l'aide de clnt_control().
Avertissement : l'utilisation d'UDP présente des inconvénients. Étant donné que les messages RPC basés sur UDP ne peuvent contenir que jusqu'à 8 Koctets de données encodées, ce transport ne peut pas être utilisé pour les procédures qui prennent de grands arguments ou renvoient des résultats volumineux.
bool_t clnt_control(CLIENT *cl, int req, char *info);
Une macro utilisée pour modifier ou récupérer diverses informations sur un objet client. req indique le type d'opération, et info est un pointeur vers les informations. Pour UDP et TCP, les valeurs prises en charge pour req et leurs types d'arguments et ce qu'ils font sont :

CLSET_TIMEOUT  struct timeval // définir le délai d'attente total
CLGET_TIMEOUT  struct timeval // obtenir le délai d'attente total

Note : si vous définissez le délai d'attente à l'aide de clnt_control(), le paramètre de délai d'attente passé à clnt_call() sera ignoré dans tous les appels futurs.

CLGET_SERVER_ADDR  struct sockaddr_in
                // obtenir l'adresse du serveur

Les opérations suivantes sont valides pour UDP uniquement :

CLSET_RETRY_TIMEOUT  struct timeval // définir le délai de nouvelle tentative
CLGET_RETRY_TIMEOUT  struct timeval // obtenir le délai de nouvelle tentative

Le délai de nouvelle tentative est le temps pendant lequel "UDP RPC" attend la réponse du serveur avant de retransmettre la requête.
clnt_freeres(CLIENT * clnt, xdrproc_t outproc, char *out);
Une macro qui libère toutes les données allouées par le système RPC/XDR lors du décodage des résultats d'un appel RPC. Le paramètre out est l'adresse des résultats, et outproc est la routine XDR décrivant les résultats. Cette routine renvoie un si les résultats ont été libérés avec succès, et zéro sinon.
void clnt_geterr(CLIENT *clnt, struct rpc_err
*errp);
Une macro qui copie la structure d'erreur de la poignée client vers la structure à l'adresse errp.
void clnt_pcreateerror(const char *s);
Affiche un message sur la sortie d'erreur standard indiquant pourquoi une poignée RPC client n'a pas pu être créée. Le message est précédé par la chaîne s et un deux-points. Utilisé lorsqu'un appel à clnt_create(), clntraw_create(), clnttcp_create(), ou clntudp_create() échoue.
void clnt_perrno(enum clnt_stat stat);
Affiche un message sur la sortie d'erreur standard correspondant à la condition indiquée par stat. Utilisé après callrpc().
clnt_perror(CLIENT *clnt, const char *s);
Affiche un message sur la sortie d'erreur standard indiquant pourquoi un appel RPC a échoué ; clnt est la poignée utilisée pour effectuer l'appel. Le message est précédé par la chaîne s et un deux-points. Utilisé après clnt_call().
char *clnt_spcreateerror(const char *s);
Similaire à clnt_pcreateerror(), mais retourne une chaîne de caractères au lieu d'afficher sur la sortie d'erreur standard.
Bugs : retourne un pointeur vers des données statiques qui sont écrasées à chaque appel.
char *clnt_sperrno(enum clnt_stat stat);
Prend les mêmes arguments que clnt_perrno(), mais au lieu d'envoyer un message sur la sortie d'erreur standard indiquant pourquoi un appel RPC a échoué, retourne un pointeur vers une chaîne contenant le message. La chaîne se termine par un saut de ligne.
clnt_sperrno() est utilisé à la place de clnt_perrno() si le programme n'a pas de sortie d'erreur standard (ce qui est fort probable pour un programme s'exécutant en tant que serveur), ou si le programmeur ne souhaite pas que le message soit affiché avec printf(3), ou si un format de message différent de celui pris en charge par clnt_perrno() doit être utilisé. Note : contrairement à clnt_sperror() et clnt_spcreateerror(), clnt_sperrno() retourne un pointeur vers des données statiques, mais le résultat ne sera pas écrasé à chaque appel.
char *clnt_sperror(CLIENT *rpch, const char *s);
Similaire à clnt_perror(), mais (comme clnt_sperrno()) il retourne une chaîne de caractères au lieu d'afficher sur la sortie d'erreur standard.
Bugs : retourne un pointeur vers des données statiques qui sont écrasées à chaque appel.
CLIENT *clntraw_create(unsigned long prognum, unsigned long versnum);
Cette routine crée un client RPC jouet pour le programme distant prognum, version versnum. Le transport utilisé pour passer les messages au service est en fait un tampon dans l'espace d'adressage du processus, donc le serveur RPC correspondant devrait vivre dans le même espace d'adressage ; voir svcraw_create(). Cela permet de simuler les RPC et d'acquérir les surcoûts RPC, tels que les temps d'aller-retour, sans aucune interférence du noyau. Cette routine retourne NULL en cas d'échec.
CLIENT *clnttcp_create(struct sockaddr_in *addr,
                unsigned long prognum, unsigned long versnum,
                int *sockp, unsigned int sendsz, unsigned int recvsz);
Cette routine crée un client RPC pour le programme distant prognum, version versnum ; le client utilise TCP/IP comme transport. Le programme distant est situé à l'adresse Internet *addr. Si addr->sin_port est zéro, il est alors défini sur le port réel sur lequel le programme distant écoute (le service portmap distant est consulté pour cette information). Le paramètre sockp est une socket ; s'il est égal à RPC_ANYSOCK, cette routine en ouvre une nouvelle et définit sockp. Comme les RPC basés sur TCP utilisent des entrées/sorties mises en tampon, l'utilisateur peut spécifier la taille des tampons d'envoi et de réception avec les paramètres sendsz et recvsz ; des valeurs de zéro choisissent des valeurs par défaut appropriées. Cette routine retourne NULL en cas d'échec.
CLIENT *clntudp_create(struct sockaddr_in *addr,
                unsigned long prognum, unsigned long versnum,
                struct timeval wait, int *sockp);
Cette routine crée un client RPC pour le programme distant prognum, version versnum ; le client utilise UDP/IP comme transport. Le programme distant est situé à l'adresse Internet addr. Si addr->sin_port est zéro, il est alors défini sur le port réel sur lequel le programme distant écoute (le service portmap distant est consulté pour cette information). Le paramètre sockp est une socket ; s'il est égal à RPC_ANYSOCK, cette routine en ouvre une nouvelle et définit sockp. Le transport UDP renvoie le message d'appel à intervalles de temps wait jusqu'à ce qu'une réponse soit reçue ou que l'appel expire. Le temps total pour l'expiration de l'appel est spécifié par clnt_call().
Avertissement : comme les messages RPC basés sur UDP ne peuvent contenir que jusqu'à 8 Ko de données encodées, ce transport ne peut pas être utilisé pour des procédures qui prennent de grands arguments ou retournent d'énormes résultats.
CLIENT *clntudp_bufcreate(struct sockaddr_in *addr,
            unsigned long prognum, unsigned long versnum,
            struct timeval wait, int *sockp,
            unsigned int sendsize, unsigned int recosize);
Cette routine crée un client RPC pour le programme distant prognum, sur versnum ; le client utilise UDP/IP comme transport. Le programme distant est situé à l'adresse Internet addr. Si addr->sin_port est zéro, il est alors défini sur le port réel sur lequel le programme distant écoute (le service portmap distant est consulté pour cette information). Le paramètre sockp est une socket ; s'il est égal à RPC_ANYSOCK, cette routine en ouvre une nouvelle et définit sockp. Le transport UDP renvoie le message d'appel à intervalles de temps wait jusqu'à ce qu'une réponse soit reçue ou que l'appel expire. Le temps total pour l'expiration de l'appel est spécifié par clnt_call().
Cela permet à l'utilisateur de spécifier la taille maximale des paquets pour envoyer et recevoir des messages RPC basés sur UDP.
void get_myaddress(struct sockaddr_in *addr);
Insère l'adresse IP de la machine dans *addr, sans consulter les routines de bibliothèque qui traitent /etc/hosts. Le numéro de port est toujours défini sur htons(PMAPPORT).
struct pmaplist *pmap_getmaps(struct sockaddr_in *addr);
Une interface utilisateur pour le service portmap, qui retourne une liste des mappages actuels programme RPC vers port sur l'hôte situé à l'adresse IP *addr. Cette routine peut retourner NULL. La commande rpcinfo -p utilise cette routine.
unsigned short pmap_getport(struct sockaddr_in *addr,
                    unsigned long prognum, unsigned long versnum,
                    unsigned int protocol);
Une interface utilisateur pour le service portmap, qui retourne le numéro de port sur lequel attend un service qui prend en charge le numéro de programme prognum, la version versnum, et parle le protocole de transport associé à protocol. La valeur de protocol est très probablement IPPROTO_UDP ou IPPROTO_TCP. Une valeur de retour de zéro signifie que le mappage n'existe pas ou que le système RPC n'a pas réussi à contacter le service portmap distant. Dans ce dernier cas, la variable globale rpc_createerr contient le statut RPC.
enum clnt_stat pmap_rmtcall(struct sockaddr_in *addr,
                    unsigned long prognum, unsigned long versnum,
                    unsigned long procnum,
                    xdrproc_t inproc, char *in,
                    xdrproc_t outproc, char *out,
                    struct timeval tout, unsigned long *portp);
Une interface utilisateur pour le service portmap, qui demande au portmap sur l'hôte à l'adresse IP *addr d'effectuer un appel RPC en votre nom vers une procédure sur cet hôte. Le paramètre *portp sera modifié pour indiquer le numéro de port du programme si la procédure réussit. Les définitions des autres paramètres sont discutées dans callrpc() et clnt_call(). Cette procédure doit être utilisée pour un « ping » et rien d'autre. Voir également clnt_broadcast().
bool_t pmap_set(unsigned long prognum, unsigned long versnum,
                int protocol, unsigned short port);
Une interface utilisateur pour le service portmap, qui établit un mappage entre le triplet [prognum,versnum,protocol] et port sur le service portmap de la machine. La valeur de protocol est très probablement IPPROTO_UDP ou IPPROTO_TCP. Cette routine retourne un si elle réussit, zéro sinon. Automatiquement fait par svc_register().
bool_t pmap_unset(unsigned long prognum, unsigned long versnum);
Une interface utilisateur pour le service portmap, qui détruit tous les mappages entre le triplet [prognum,versnum,*] et les ports sur le service portmap de la machine. Cette routine retourne un si elle réussit, zéro sinon.
int registerrpc(unsigned long prognum, unsigned long versnum,
                unsigned long procnum, typeof(char *(char *)) *procname,
                xdrproc_t inproc, xdrproc_t outproc);
Enregistre la procédure procname auprès du paquet de services RPC. Si une requête arrive pour le programme prognum, la version versnum et la procédure procnum, procname est appelée avec un pointeur vers ses paramètres ; procname doit retourner un pointeur vers ses résultats statiques ; inproc est utilisé pour décoder les paramètres tandis que outproc est utilisé pour encoder les résultats. Cette routine retourne zéro si l'enregistrement a réussi, -1 sinon.
