NOM

clevis-encrypt-tang - Chiffre en utilisant une stratégie de serveur de liaison Tang

SYNTAXE

clevis encrypt tang CONFIG [-y] < PT > JWE

APERÇU

La commande clevis encrypt tang chiffre en utilisant une stratégie de serveur de liaison Tang. Son seul argument est l'objet de configuration JSON.

Clevis fournit un support pour le serveur de liaison réseau Tang. Tang fournit une alternative légère et sans état aux dépôts. Le chiffrement des données à l'aide de la broche Tang se déroule comme suit :

$ clevis encrypt tang '{"url":"http://tang.srv"}' < PT > JWE
Les annonces contiennent les clés de signature suivantes :
_OsIk0T-E2l6qjfdDiwVmidoZjA
Souhaitez-vous faire confiance à ces clés ? [ynYN] y

Pour déchiffrer les données, il suffit de les passer à la commande clevis decrypt :

$ clevis decrypt < JWE > PT

Comme vous pouvez le voir ci-dessus, Tang utilise un flux de travail de confiance lors de la première utilisation. Si vous connaissez déjà l'empreinte d'une clé de confiance, vous pouvez la spécifier dans la configuration au moment du chiffrement :

$ cfg='{"url":"http://tang.srv","thp":"_OsIk0T-E2l6qjfdDiwVmidoZjA"}'
$ clevis encrypt tang "$cfg" < PT > JWE

Obtenir l'empreinte d'une clé de signature de confiance est facile. Si vous avez accès au serveur Tang, exécutez simplement :

$ tang-show-keys <PORT>

où <PORT> est le port sur lequel le serveur Tang est en écoute.

Si tang-show-keys n'est pas disponible, mais que vous avez accès au répertoire de la base de données du serveur Tang, vous pouvez exécuter ceci à la place :

$ jose jwk thp -i $DBDIR/$SIG.jwk

Tang peut également effectuer un chiffrement entièrement hors ligne si vous partagez l'annonce du serveur à l'avance. Vous pouvez récupérer l'annonce avec une simple commande (faites juste attention à ce que votre réseau ne soit pas compromis !)

$ curl -f $URL/adv > adv.jws

Une fois que vous avez le fichier d'annonce, fournissez-le simplement :

$ clevis encrypt tang '{"url":...,"adv":"adv.jws"}' < PT > JWE

CONFIG

Cette commande utilise les propriétés de configuration suivantes :

•url (chaîne) : L'URL de base du serveur Tang (REQUIS)
•thp (chaîne) : L'empreinte d'une clé de signature de confiance
•adv (chaîne) : Un nom de fichier contenant une annonce de confiance
•adv (objet) : Une annonce de confiance (JSON brut)

OPTIONS

•-y : Répond automatiquement oui à toutes les questions. Utilisez cette option pour ignorer la vérification de confiance de l'annonce. Cela peut être utile dans les déploiements automatisés : 
$ clevis encrypt tang '{"url":...}' -y < PT > JWE
