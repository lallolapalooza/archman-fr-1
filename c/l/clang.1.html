NOM

clang - le compilateur C, C++ et Objective-C de Clang

SYNTAXE

clang [options] nom_fichier ...

DESCRIPTION

clang est un compilateur C, C++ et Objective-C qui comprend le prétraitement, l'analyse syntaxique, l'optimisation, la génération de code, l'assemblage et l'édition de liens. Selon le réglage du mode de haut niveau passé, Clang s'arrêtera avant de réaliser une édition de liens complète. Bien que Clang soit hautement intégré, il est important de comprendre les étapes de compilation pour savoir comment l'invoquer. Ces étapes sont :

Pilote (Driver)
L'exécutable clang est en fait un petit pilote qui contrôle l'exécution globale d'autres outils tels que le compilateur, l'assembleur et l'éditeur de liens. Généralement, vous n'avez pas besoin d'interagir avec le pilote, mais vous l'utilisez de manière transparente pour exécuter les autres outils.
Prétraitement
Cette étape gère la tokenisation du fichier source d'entrée, l'expansion des macros, l'expansion de #include et la gestion des autres directives du préprocesseur. Le résultat de cette étape est généralement appelé un fichier « .i » (pour C), « .ii » (pour C++), « .mi » (pour Objective-C) ou « .mii » (pour Objective-C++).
Analyse syntaxique et Analyse sémantique
Cette étape analyse le fichier d'entrée, traduisant les tokens du préprocesseur en un arbre d'analyse. Une fois sous la forme d'un arbre d'analyse, elle applique l'analyse sémantique pour calculer les types des expressions ainsi que pour déterminer si le code est bien formé. Cette étape est responsable de la génération de la plupart des avertissements du compilateur ainsi que des erreurs d'analyse. Le résultat de cette étape est un « Arbre Syntaxique Abstrait » (AST).
Génération de code et Optimisation
Cette étape traduit un AST en code intermédiaire de bas niveau (connu sous le nom de « LLVM IR ») et finalement en code machine. Cette phase est responsable de l'optimisation du code généré et de la gestion de la génération de code spécifique à la cible. Le résultat de cette étape est généralement appelé un fichier « .s » ou un fichier « assembleur ».

Clang prend également en charge l'utilisation d'un assembleur intégré, où le générateur de code produit directement des fichiers objets. Cela évite la surcharge de la génération du fichier « .s » et de l'appel à l'assembleur cible.

Assembleur
Cette étape exécute l'assembleur cible pour traduire la sortie du compilateur en un fichier objet cible. Le résultat de cette étape est généralement appelé un fichier « .o » ou un fichier « objet ».
Éditeur de liens
Cette étape exécute l'éditeur de liens cible pour fusionner plusieurs fichiers objets en un exécutable ou une bibliothèque dynamique. Le résultat de cette étape est généralement appelé un fichier « a.out », « .dylib » ou « .so ».

Analyseur statique Clang

L'analyseur statique Clang est un outil qui analyse le code source pour tenter de trouver des bugs grâce à l'analyse de code. Cet outil utilise de nombreuses parties de Clang et est intégré dans le même pilote. Veuillez consulter <https://clang-analyzer.llvm.org> pour plus de détails sur l'utilisation de l'analyseur statique.

OPTIONS

Options de sélection d'étape

-E
Exécuter l'étape du préprocesseur.
-fsyntax-only
Exécuter les étapes du préprocesseur, de l'analyse syntaxique et de l'analyse sémantique.
-S
Exécuter les étapes précédentes ainsi que les étapes de génération LLVM et d'optimisation et la génération de code spécifique à la cible, en produisant un fichier assembleur.
-c
Exécuter toutes les étapes ci-dessus, plus l'assembleur, en générant un fichier objet cible « .o ».
aucune option de sélection d'étape
Si aucune option de sélection d'étape n'est spécifiée, toutes les étapes ci-dessus sont exécutées, et l'éditeur de liens est exécuté pour combiner les résultats en un exécutable ou une bibliothèque partagée.

Ne recherche pas dans les répertoires système standard ni dans les répertoires intégrés du compilateur pour les fichiers d'inclusion.
-nostdlibinc
Ne recherche pas dans les répertoires système standard pour les fichiers d'inclusion, mais recherche dans les répertoires d'inclusion intégrés du compilateur.
-nobuiltininc
Ne recherche pas dans le répertoire intégré de clang pour les fichiers d'inclusion.
-nostdinc++
Ne recherche pas dans le répertoire de la bibliothèque standard C++ du système pour les fichiers d'inclusion.
-fkeep-system-includes
Utilisable uniquement avec -E. Ne copie pas le contenu prétraité des en-têtes « système » vers la sortie ; conservez plutôt la directive #include. Cela peut considérablement réduire le volume de texte produit par -E, ce qui peut être utile lorsque vous essayez de produire un cas de test « petit » et reproductible.

Cette option ne garantit toutefois pas la reproductibilité. Si le code source incluant définit des symboles du préprocesseur qui influencent le comportement des en-têtes système (par exemple, _XOPEN_SOURCE), le fonctionnement de -E supprimera cette définition et pourra donc modifier la sémantique de l'en-tête inclus. De plus, l'utilisation d'une version différente des en-têtes système (en particulier une version différente de la STL) peut entraîner un comportement différent. Vérifiez toujours le fichier prétraité en le compilant séparément.

ENVIRONNEMENT

TMPDIR, TEMP, TMP
Ces variables d'environnement sont vérifiées, dans l'ordre, pour l'emplacement où écrire les fichiers temporaires utilisés pendant le processus de compilation.
CPATH
Cette variable d'environnement spécifie des chemins de recherche d'en-têtes supplémentaires (non système) à utiliser pour trouver les fichiers d'en-tête inclus. Ces chemins sont recherchés après les chemins spécifiés avec l'option -I<répertoire>, mais avant tout chemin de recherche d'en-tête système. Les chemins sont délimités par le délimiteur dépendant de la plateforme tel qu'utilisé dans la variable d'environnement PATH. Les entrées vides dans la liste de chemins délimités, y compris celles au début ou à la fin de la liste, sont traitées comme spécifiant le répertoire de travail courant du compilateur.
C_INCLUDE_PATH, OBJC_INCLUDE_PATH, CPLUS_INCLUDE_PATH, OBJCPLUS_INCLUDE_PATH
Ces variables d'environnement spécifient des chemins de recherche supplémentaires pour les fichiers d'en-tête système à utiliser lors du traitement du langage correspondant. Les chemins de recherche sont délimités comme pour la variable d'environnement CPATH.
MACOSX_DEPLOYMENT_TARGET
Si -mmacos-version-min n'est pas spécifié, la cible de déploiement par défaut est lue à partir de cette variable d'environnement. Cette option n'affecte que les cibles Darwin.

BOGUES

Pour signaler des bogues, veuillez visiter <https://github.com/llvm/llvm-project/issues/>. La plupart des rapports de bogues devraient inclure les fichiers sources prétraités (utilisez l'option -E) et la sortie complète du compilateur, ainsi que des informations pour reproduire le problème.
