UTILISATI

ON

Définition des

attributs

Définissez les attributs sous forme de liste d'arguments d'importation

: 
package Foo::Bar;
use Class::Tiny qw(
    name
    id
    height
    weight
)
;

Pour chaque attribut, un accesseur lecture-écriture est créé à moins qu'une sous-routine de ce nom n'existe déjà

: 
$obj->name;               # accesseur de lecture
$obj->name( "John Doe" ); # accesseur
d'écriture

Les noms d'attributs doivent être des identifiants de sous-routines valides, sinon une exception sera

levée.

Vous pouvez spécifier des valeurs par défaut paresseuses en définissant les attributs avec une référence de hachage. Les clés définissent les noms des attributs et les valeurs sont des constantes ou des références de code qui seront évaluées lorsque l'attribut est accédé pour la première fois si aucune valeur n'a été définie. L'objet est passé comme argument à une référence de

code. 
package Foo::WithDefaults;
use Class::Tiny qw/name id/, {
    title     => 'Peon',
    skills    => sub { [] },
    hire_date => sub { $_[0]->_build_hire_date },
}
;

Lors de la sous-classification, si plusieurs accesseurs du même nom existent dans différentes classes, toute valeur par défaut (ou absence de valeur par défaut) est déterminée par l'ordre standard de résolution des

méthodes.

Pour créer vos propres accesseurs personnalisés, déclarez simplement le nom de la méthode avant de charger Class::Tiny

: 
package Foo::Bar;
use subs 'id';
use Class::Tiny qw( name id );
sub id { ...
}

Même si vous déclarez à l'avance un nom de méthode, vous devez l'inclure dans la liste des attributs pour que Class::Tiny l'enregistre comme attribut

valide.

Si vous définissez une valeur par défaut pour un accesseur personnalisé, votre accesseur devra récupérer cette valeur par défaut et faire quelque chose avec elle

: 
package Foo::Bar;
use subs 'id';
use Class::Tiny qw( name ), { id => sub { int(rand(2*31)) } };
sub id {
    my $self = shift;
    if (@_) {
        return $self->{id} = shift;
    }
    elsif ( exists $self->{id} ) {
        return $self->{id};
    }
    else {
        my $defaults =
            Class::Tiny->get_all_attribute_defaults_for( ref $self );
        return $self->{id} = $defaults->{id}->();
    }
}

Class::Tiny::Object est votre classe de

base

Si votre classe n'hérite pas déjà d'une classe, alors Class::Tiny::Object sera ajouté à votre @ISA pour fournir "new" et "DESTROY"

.

Si votre classe hérite de quelque chose, alors aucun héritage supplémentaire n'est configuré. Si la classe parente sous-classifie Class::Tiny::Object, tout va bien. Sinon, vous aurez des accesseurs configurés mais pas de constructeur ni de destructeur. Ne faites pas cela à moins d'avoir vraiment un besoin

spécial.

Définissez les sous-classes normalement. Il est préférable de les définir avec base, parent ou superclass avant de définir les attributs avec Class::Tiny afin que le tableau @ISA soit déjà rempli à la compilation

: 
package Foo::Bar::More;
use parent 'Foo::Bar';
use Class::Tiny qw( shoe_size
)
;

Construction des

objets

Si votre classe hérite de Class::Tiny::Object (ce qui devrait être le cas si vous avez suivi les conseils ci-dessus), elle fournit le constructeur "new" pour

vous.

Les objets peuvent être créés avec des attributs donnés sous forme de référence de hachage ou de liste de paires clé/valeur

: 
$obj = Foo::Bar->new( name => "David" );
$obj = Foo::Bar->new( { name => "David" } )
;

Si une référence est passée en tant qu'argument unique, elle doit pouvoir être déréférencée comme un hachage, sinon une exception est

levée.

Les attributs inconnus dans les arguments du constructeur seront ignorés. Avant la version 1.000, les attributs inconnus provoquaient une erreur, mais cela rendait plus difficile la sous-classification propre des classes Class::Tiny, alors cette fonctionnalité a été

supprimée.

Vous pouvez définir une méthode "BUILDARGS" pour changer la façon dont les arguments de new sont traités. Elle recevra les arguments du constructeur tels qu'ils ont été fournis et doit renvoyer une référence de hachage de paires clé/valeur (ou lever une exception)

. 
sub BUILDARGS {
   my $class = shift;
   my $name = shift || "John Doe";
   return { name => $name };
 };
 Foo::Bar->new( "David" );
 Foo::Bar->new(); # "John
Doe"

Les attributs inconnus renvoyés par "BUILDARGS" se

ront i
gnorés.

BUIL

D

Si votre classe ou toute superclasse définit une méthode "BUILD", elle sera appelée par le constructeur de la classe parente la plus éloignée jusqu'à la classe enfant après la création de

l'objet.

Elle reçoit les arguments du constructeur sous forme de référence de hachage. La valeur de retour est ignorée. Utilisez "BUILD" pour la validation, la vérification des attributs requis ou le réglage de valeurs par défaut qui dépendent d'autres

attributs. 
sub BUILD {
    my ($self, $args) = @_;
    for my $req ( qw/name age/ ) {
        croak "$req attribute required" unless defined $self->$req;
    }
    croak "Age must be non-negative" if $self->age < 0;
    $self->msg( "Hello " . $self->name );
}

La référence d'argument est une copie, donc la suppression d'éléments n'affectera pas les données de l'original (mais les modifications seront passées aux autres méthodes BUILD dans @IS

A
).

DEMOLIS

H

Class::Tiny fournit une méthode "DESTROY". Si votre classe ou toute superclasse définit une méthode "DEMOLISH", elles seront appelées de la classe enfant vers la classe parente la plus éloignée lors de la destruction de l'objet. Un argument booléen unique indiquant si Perl est en destruction globale lui est fourni. Les valeurs de retour sont ignorées. Les erreurs sont capturées et

relancées. 
sub DEMOLISH {
    my ($self, $global_destruct) = @_;
    $self->cleanup();
}
