DESCRIPTIO

N

Class::Autouse est un chargeur de classes à l'exécution qui vous permet de spécifier des classes qui ne seront chargées que lorsqu'une méthode de cette classe est

appelée.

Pour les grandes classes ou les arbres de classes qui pourraient ne pas être utilisés pendant l'exécution d'un programme, comme Date::Manip, cela peut vous faire économiser de grandes quantités de mémoire et réduire considérablement le temps de chargement du

script.

Class::Autouse fournit également un certain nombre de fonctionnalités « non sûres » pour la génération de classes à l'exécution et l'implémentation de sucre syntaxique. Ces fonctionnalités utilisent l'accrochage (malveillant) de UNIVERSAL::AUTOLOAD et sont implémentées dans cette classe car ces accrochages ne peuvent être faits que par un seul module, et Class::Autouse sert d'endroit utile pour centraliser ce genre de méchanceté :

)

Classe, et non

Module

La terminologie « chargement de classe » au lieu de « chargement de module » est utilisée intentionnellement. Les modules ne seront chargés que s'ils agissent comme une

classe.

C'est-à-dire qu'ils ne seront chargés que lors d'un appel Class->méthode. Si vous essayez d'utiliser une sous-routine directement, par exemple avec Class::méthode(), la classe ne sera pas chargée et une erreur fatale surviendra très

probablement.

Cette limitation est faite pour permettre des fonctionnalités plus puissantes dans d'autres domaines, car nous pouvons nous concentrer uniquement sur le chargement des modules et n'avons pas à gérer

l'importation.

Et vraiment, si vous faites de la

POO en Perl, vous devriez éviter
l'importation autant que possible.

Utilisation comme

pragma

Class::Autouse peut être utilisé comme pragma, en spécifiant une liste de classes à charger comme arguments. Par

exemple 
use Class::Autouse qw{CGI Data::Manip This::That}
;

est équivalent

à 
use Class::Autouse;
Class::Autouse->autouse( 'CGI'         );
Class::Autouse->autouse( 'Data::Manip' );
Class::Autouse->autouse( 'This::That'
)
;

Mode

Développeur

"Class::Autouse" propose un mode développeur. En mode développeur, les classes sont chargées immédiatement, tout comme elles le seraient avec une instruction 'use' normale (bien que la sous-routine import ne soit pas appelée)

.

Cela permet de faire de la vérification des erreurs pendant le développement, au prix d'une surcharge mémoire plus importante. Le mode développeur est activé soit avec la méthode "devel", soit en utilisant :devel dans n'importe lequel des arguments du pragma. Par exemple, cela chargerait CGI.pm

immédiatement 
use Class::Autouse qw{:devel CGI}
;

Bien que le mode développeur soit à peu près équivalent à l'utilisation d'une simple commande use normale, pour un grand nombre de modules,

il vous permet d'utiliser la notation d'autoload et de simplement commenter ou décommenter une seule ligne pour activer ou désactiver le mo
de développeur. Vous pouvez le laisser activé pendant le développement et le désactiver pour des raisons de performance lors du déploiement.

Chargement

Récursif

En alternative au super loader, les méthodes "autouse_recursive" et "load_recursive" peuvent être utilisées pour autouser ou charger un arbre entier de

classes.

Par exemple, ce qui suit vous donnerait accès à toutes les classes liées à URI installées sur la

machine. 
Class::Autouse->autouse_recursive( 'URI' )
;

Veuillez noter que les chargements n'auront lieu q

ue le long d'une seule branche du chemin d'inclusio
n, celle où se trouve la classe de premier niveau.

Mode

No-Stat

Pour les situations où un module existe sur un disque distant ou dans un autre emplacement relativement coûteux, vous pouvez appeler "Class::Autouse" avec le paramètre :nostat pour désactiver la vérification initiale de l'existence du fichier au moment de

l'accrochage. 
# Désactive la vérification de l'exi
stence du fichier au moment de l'auto
load use Class::Autouse qw{:nostat};

Mode Super

Loader

Activer le super loader de "Class::Autouse" vous permet de charger automatiquement N'IMPORTE QUELLE classe sans la spécifier au préalable. Ainsi, ce qui suit fonctionne et est complètement

légal. 
use Class::Autouse qw{:superloader};
print CGI->b('Wow!')
;

Le super loader peut être activé soit avec la méthode "Class::Autouse->superloader", soit avec l' argument de pragma ":

superloader".

Veuillez noter que contrairement au chargement automatique normal un à la fois, le super-loader effectue des changements globaux et n'est donc pas complètement

autonome.

Il a le potentiel de causer des effets non intentionnels à distance. Si vous rencontrez un comportement inhabituel, revenez à l'autouse un à la fois, ou utilisez le chargement

récursif.

L'utilisation du Super Loader est fortement déconseillée pour les applications publiques ou les modules largement distribués, sauf en cas d'absolue nécessité. Ne l'utilisez PAS juste pour être paresse

ux et économiser quel
ques lignes de code.

Chargement avec des Expressions

Régulières

Comme une autre alternative au superloader et au chargement récursif, une expression

régulière compilée (qr//) peut être fournie comme chargeur. Notez que ce chargeur
implémente UNIVERSAL::AUTOLOAD et a les mêmes effets secondaires que le superloader.

Enregistrement d'un Rappel pour la Création Dynamique de

Classes

vrai.

Étant donné que le surchargement de UNIVERSAL::AUTOLOAD ne peut être fait qu'une seule fois dans une application Perl donnée, cette fonctionnalité permet de partager UNIVERSAL::AUTOLOAD. Veuillez l'utiliser plutôt que d'implémenter votre propre UNIVERSAL::

AUTOLOAD.

Voir les avertissements sous « Super Loader Module » ci-dessus, qui s'appliquent à toutes les fonctionnalités qui surchargent UNIVERSAL::

AUTOLOAD.

C'est au rappel de définir la classe, dont les détails dépassent le cadre de ce document. Voir l'exemple ci-dessous pour une référence rapide

sucre

syntaxique

Cette méthode est fournie pour supporter le « sucre syntaxique » : permettre au développeur de mettre des choses dans Perl qui ne ressemblent pas à du Perl régulier. Il y a plusieurs façons de faire cela en Perl. Les stratégies qui nécessitent de redéfinir UNIVERSAL::AUTOLOAD peuvent utiliser cette interface à la place pour partager cette méthode avec le superchargeur, et avec les générateurs de

classes.

Lorsque Perl est incapable de trouver une sous-routine/méthode, et que tous les chargeurs de classes sont épuisés, les rappels enregistrés via sugar() sont appelés. Les rappels reçoivent le nom de la classe, le nom de la méthode, et les paramètres de

l'appel.

Si le rappel ne retourne rien, Class::Autouse continuera à itérer à travers les autres rappels. Le premier rappel qui retourne une valeur vraie mettra fin à l'itération. Cette valeur est censée être une référence CODE qui répondra à l'appel

AUTOLOAD.

Note : le(s) rappel(s) de sucre ne seront déclenchés par UNIVERSAL::AUTOLOAD qu'après que toutes les autres tentatives de chargement de la classe soient terminées, et après les tentatives d'utiliser un AUTOLOAD régulier pour gérer l'appel de méthode. Il n'est jamais déclenché par isa() ou can(). Il sera déclenché de manière répétée pour la même classe. Pour générer des classes, utilisez le support régulier de référence CODE dans autouse

().

mod_per

l

Le mécanisme que "Class::Autouse" utilise n'est pas compatible avec mod_perl. En particulier avec les modules de rechargement comme Apache::Reload. "Class::Autouse" détecte la présence de mod_perl et se comporte normalement, mais chargera toujours toutes les classes immédiatement, équivalent à avoir le mode développeur

activé.

C'est en fait bénéfique, car sous mod_perl les classes devraient être préchargées dans le processus parent mod_perl de toute façon, pour éviter qu'elles doivent être chargées par les classes filles Apache. Cela économise aussi des quantités ÉNORMES de

mémoire.

Notez que les classes générées dynamiquement et les classes chargées via regex NE PEUVENT PA

S être préchargées automatiquement avant la création des processus enfants. Elles seront to
ujours chargées à la demande, souvent dans le processus enfant. Voir prefork ci-dessous.

prefor

k

Comme avec mod_perl, "Class::Autouse" est compatible avec le module prefork, et tous les modules spécifiquement autoloadés seront chargés avant la création des processus enfants correctement, lorsque demandé par

prefork.

Puisque les modules générés via callback ou regex ne peuvent pas être chargés au

tomatiquement par prefork de manière générique, il est conseillé d'utiliser prefork
directement pour charger/générer des classes lors de l'utilisation de mod_perl.

Optimisations de

performance
:
nostat
Comme décrit ci-dessus, cette option est utile lorsque le module en question est sur un disque
distant.
:
noprebless
Lorsqu'elle est définie, Class::Autouse suppose que les objets qui sont déjà bénis ont leur classe chargée.

C'est vrai dans la plupart des cas, mais cassera si le développeur a l'intention de

reconstituer des objets sérialisés à partir de Data::Dumper, FreezeThaw ou ses cousi
ns, et a configuré Class::Autouse pour charger les classes concernées juste-à-temps.
:
staticisa
Lorsqu'elle est définie, suppose que @ISA ne changera pas pour une classe une fois qu'elle est chargée. L'arrière-grand-parent d'une classe recevra les implémentations can/isa
originales qui sont plus rapides que celles que Class::Autouse insta
lle dans UNIVERSAL. C'est un réglage de performance utile dans la plu
part des cas, mais est désactivé par défaut pour éviter des bogues obscurs.

Le débogueur

interne

Class::Autouse fournit un débogueur interne, qui peut être utilisé pour déboguer tous les cas limites étranges que vous pourriez rencontrer lors de son

utilisation.

Si la variable $Class::Autouse::DEBUG est vraie lorsque "Class::Autouse" est chargé pour la première fois, le débogage sera compilé. Ce débogage imprime une sortie comme la suivante sur

STDOUT. 
Class::Autouse::autouse_recursive( 'Foo' )
    Class::Autouse::_recursive( 'Foo', 'load' )
        Class::Autouse::load( 'Foo' )
        Class::Autouse::_children( 'Foo' )
        Class::Autouse::load( 'Foo::Bar' )
            Class::Autouse::_file_exists( 'Foo/Bar.pm' )
            Class::Autouse::load -> Loading in Foo/Bar.pm
        Class::Autouse::load( 'Foo::More' )
            etc..
.

Veuillez noter que parce que ceci est optimisé hors si non util

isé, vous ne pouvez plus (depuis 1.20) activer le débogage
à l'exécution. Cette décision a été prise pour supprimer un
grand nombre de branches inutiles et accélérer le chargement.

La méthode load charge une ou plusieurs classes en mémoire. C'est fonctionnellement équivalent à utiliser

require pour charger la liste des classes, sauf que load détectera et supprimera le crochet d'autoloading
d'une classe précédemment autoused, alors que use ignore la classe efficacement, et ne la charge pas.

La méthode superloader active le super

chargeur.

Veuillez noter qu'une fois que vous avez activé le superloader, il ne peut pas être désactivé. C

ela est dû au fait que du code qui pourrait s'y fier ne serait pas capable d'autoloader ses cla
sses lorsque un autre morceau de code décide qu'il ne le veut plus, et désactive le superloader.

class_exists

$class

Méthode pratique lorsque l'on fait le genre de tâches que "Class::Autouse" fait. Étant donné un nom de classe, elle retournera vrai si la classe peut être chargée ( c.-à-d. dans @INC ), faux si la classe ne peut pas être chargée, et undef si le nom de classe est

invalide.

Notez que cela ne charge pas réellement la classe, teste juste pour voir

si elle peut être chargée. Le chargement peut encore échouer. Pour un en
semble plus complet de méthodes de cette nature, voir Class::Inspector.
