NOM

clamd - un démon antivirus

SYNTAXE

clamd [options]

DESCRIPTION

Le démon écoute les connexions entrantes sur les sockets Unix et/ou TCP et analyse les fichiers ou répertoires à la demande. Il lit la configuration depuis /etc/clamav/clamd.conf

COMMANDES

Il est recommandé de préfixer les commandes clamd par la lettre z (par ex. zSCAN) pour indiquer que la commande sera délimitée par un caractère NUL et que clamd continuera à lire les données de commande jusqu'à ce qu'un caractère NUL soit lu. Le délimiteur nul assure que la commande complète et son argument entier seront traités comme une seule commande. Alternativement, les commandes peuvent être préfixées par la lettre n (par ex. nSCAN) pour utiliser un caractère de nouvelle ligne comme délimiteur. Les réponses de clamd respecteront le terminateur demandé en retour. Si clamd ne reconnaît pas la commande, ou si la commande ne suit pas les exigences spécifiées ci-dessous, il répondra avec un message d'erreur et fermera la connexion.

Clamd reconnaît les commandes suivantes :

PING
Vérifie l'état du serveur. Il doit répondre par "PONG".
VERSION
Affiche les versions du programme et des bases de données.
RELOAD
Recharge les bases de données de virus.
SHUTDOWN
Effectue une sortie propre.
SCAN fichier/répertoire
Analyse un fichier ou un répertoire (récursivement) avec le support des archives activé (si non désactivé dans clamd.conf). Un chemin complet est requis.
CONTSCAN fichier/répertoire
Analyse un fichier ou un répertoire (récursivement) avec le support des archives activé et n'arrête pas l'analyse lorsqu'un virus est trouvé.
MULTISCAN fichier/répertoire
Analyse un fichier de manière standard ou analyse un répertoire (récursivement) en utilisant plusieurs threads (pour accélérer l'analyse sur les machines SMP).
ALLMATCHSCAN fichier/répertoire
ALLMATCHSCAN fonctionne comme SCAN sauf qu'il définit un mode où l'analyse continue après avoir trouvé une correspondance dans un fichier.
INSTREAM
Il est obligatoire de préfixer cette commande par n ou z.

Analyse un flux de données. Le flux est envoyé à clamd par morceaux, après INSTREAM, sur le même socket que celui sur lequel la commande a été envoyée. Cela évite la surcharge de l'établissement de nouvelles connexions TCP et les problèmes avec NAT. Le format du morceau est : '<longueur><données>' où <longueur> est la taille des données suivantes en octets exprimée sous forme d'entier non signé de 4 octets en ordre d'octets réseau et <données> sont les données réelles du morceau. Le streaming est terminé par l'envoi d'un morceau de longueur zéro. Note : ne pas dépasser StreamMaxLength tel que défini dans clamd.conf, sinon clamd répondra par INSTREAM size limit exceeded et fermera la connexion.

FILDES
Il est obligatoire de terminer cette commande par une nouvelle ligne, ou de la préfixer par n ou z.

Cette commande ne fonctionne que sur les sockets de domaine UNIX. Analyse un descripteur de fichier. Après avoir émis une commande FILDES, un paquet rfc2292/bsd4.4 ultérieur (avec au moins un caractère fictif) est envoyé à clamd, transportant le descripteur de fichier à analyser dans les données auxiliaires. Alternativement, le descripteur de fichier peut être envoyé dans le même paquet, y compris le caractère supplémentaire.

STATS
Il est obligatoire de terminer cette commande par une nouvelle ligne, ou de la préfixer par n ou z, il est recommandé de n'utiliser que le préfixe z.

Répond avec des statistiques sur la file d'attente d'analyse, le contenu de la file d'attente d'analyse et l'utilisation de la mémoire. Le format de réponse exact est sujet à modification dans les futures versions.

IDSESSION, END
Il est obligatoire de préfixer cette commande par n ou z, et toutes les commandes à l'intérieur d'IDSESSION doivent être préfixées.

Démarre/termine une session clamd. Au sein d'une session, plusieurs commandes SCAN, INSTREAM, FILDES, VERSION, STATS peuvent être envoyées sur le même socket sans ouvrir de nouvelles connexions. Les réponses de clamd seront sous la forme '<id>: <réponse>' où <id> est le numéro de requête (en ascii, commençant à 1) et <réponse> est la réponse habituelle de clamd. Les lignes de réponse auront le même délimiteur que la commande correspondante. Clamd traitera les commandes de manière asynchrone et répondra dès qu'il aura terminé le traitement.

Clamd exige que les clients lisent toutes les réponses qu'il a envoyées avant d'envoyer d'autres commandes afin d'éviter les blocages de send(). La manière recommandée d'implémenter un client utilisant IDSESSION est avec des sockets non bloquants et une boucle select()/poll() : chaque fois que send bloquerait, dormir dans select/poll jusqu'à ce que vous puissiez écrire plus de données, ou lire plus de réponses. Notez que l'utilisation de sockets non bloquants sans la boucle select/poll et l'alternance recv()/send() n'est pas conforme aux exigences de clamd.

Si clamd détecte qu'un client est bloqué, il fermera la connexion. Notez que clamd peut également fermer une connexion IDSESSION si vous ne respectez pas les exigences du protocole. Le client peut utiliser la commande PING pour maintenir la connexion active.

VERSIONCOMMANDS
Il est obligatoire de préfixer cette commande par n ou z. Il est recommandé d'utiliser nVERSIONCOMMANDS.

Affiche les versions du programme et des bases de données, suivies de "| COMMANDS:" et d'une liste de commandes prises en charge séparées par des espaces. Clamd <0.95 reconnaîtra cela comme la commande VERSION et répondra uniquement avec sa version, sans la liste des commandes.

Cette commande peut être utilisée comme un moyen simple de vérifier la prise en charge d'IDSESSION, par exemple.

COMMANDES PÉRIMÉES
STREAM
Analyse de flux - sur cette commande, clamd retournera le "numéro de PORT" auquel vous devriez vous connecter et envoyer des données à analyser. (PÉRIMÉ, utilisez INSTREAM à la place)
COMMANDES NON PRISES EN CHARGE
SESSION, END
Démarre/termine une session clamd qui vous permettra d'exécuter plusieurs commandes par session TCP. (utilisez IDSESSION à la place)

OPTIONS

-h, --help
Affiche les informations d'aide et quitte.
-V, --version
Affiche le numéro de version et quitte.
-F, --foreground
Exécute en premier plan ; ne pas daemoniser.
--debug
Active le mode débogage.
-c FICHIER, --config-file=FICHIER
Lit la configuration depuis FICHIER.
--fail-if-cvd-older-than=jours
Retourne avec un code d'erreur non nul si la base de données de virus est plus ancienne que le nombre de jours spécifié.
--datadir=RÉPERTOIRE
Charge les signatures depuis RÉPERTOIRE.
-p FICHIER, --pid=FICHIER
Écrit le pid du démon dans FICHIER.
--cvdcertsdir=DIR
Spécifie un répertoire contenant le certificat racine CA nécessaire pour vérifier les signatures numériques CVD détachées. S'il n'est pas fourni, clamd recherchera dans le répertoire par défaut.
