adjtimex(2) Manuel des appels système adjtimex(2)

NOM

adjtimex, clock_adjtime, ntp_adjtime - régler l'horloge du noyau

BIBLIOTHÈQUE

Bibliothèque C standard (libc, -lc)

SYNTAXE

#include <sys/timex.h>
int adjtimex(struct timex *buf);
int clock_adjtime(clockid_t clk_id, struct timex *buf);
int ntp_adjtime(struct timex *buf);

DESCRIPTION

Linux utilise l'algorithme d'ajustement d'horloge de David L. Mills (voir RFC 5905). L'appel système adjtimex() lit et définit optionnellement les paramètres d'ajustement pour cet algorithme. Il prend un pointeur vers une structure timex, met à jour les paramètres du noyau à partir des valeurs de champs (sélectionnées), et renvoie la même structure mise à jour avec les valeurs actuelles du noyau. Cette structure est déclarée comme suit :


struct timex {
    int  modes;      /* Sélecteur de mode */
    long offset;     /* Décalage temporel ; nanosecondes, si le
                        flag d'état STA_NANO est activé, sinon
                        microsecondes */
    long freq;       /* Décalage de fréquence ; voir NOTES pour les unités */
    long maxerror;   /* Erreur maximale (microsecondes) */
    long esterror;   /* Erreur estimée (microsecondes) */
    int  status;     /* Commande/état de l'horloge */
    long constant;   /* Constante de temps de la PLL (boucle à verrou
                        de phase) */
    long precision;  /* Précision de l'horloge
                        (microsecondes, en lecture seule) */
    long tolerance;  /* Tolérance de fréquence de l'horloge (en lecture
                        seule) ; voir NOTES pour les unités */
    struct timeval time;
                     /* Heure actuelle (en lecture seule, sauf pour
                        ADJ_SETOFFSET) ; au retour, time.tv_usec
                        contient des nanosecondes, sinon des
                        microsecondes */
    long tick;       /* Microsecondes entre les ticks de l'horloge */
    long ppsfreq;    /* Fréquence PPS (impulsion par seconde)
                        (en lecture seule) ; voir NOTES pour les unités */
    long jitter;     /* Jitter PPS (en lecture seule) ; nanosecondes,
                        si le flag d'état STA_NANO est activé, sinon
                        microsecondes */
    int  shift;      /* Durée de l'intervalle PPS
                        (secondes, en lecture seule) */
    long stabil;     /* Stabilité PPS (en lecture seule) ;
                        voir NOTES pour les unités */
    long jitcnt;     /* Compteur d'événements de dépassement de limite
                        de jitter PPS (en lecture seule) */
    long calcnt;     /* Compteur d'intervalles de calibration PPS
                        (en lecture seule) */
    long errcnt;     /* Compteur d'erreurs de calibration PPS (en lecture
                        seule) */
    long stbcnt;     /* Compteur d'événements de dépassement de limite
                        de stabilité PPS (en lecture seule) */
    int  tai;         /* Décalage TAI, tel que défini par une opération
                        ADJ_TAI précédente (secondes, en lecture seule,
                        depuis Linux 2.6.26) */
    /* Octets de remplissage supplémentaires pour permettre une future expansion */
};

Le champ modes détermine quels paramètres, le cas échéant, sont définis. (Comme décrit plus loin dans cette page, les constantes utilisées pour ntp_adjtime() sont équivalentes mais nommées différemment.) C'est un masque de bits contenant une combinaison OU bit à bit de zéro ou plus des bits suivants :

ADJ_OFFSET
Définit le décalage temporel à partir de buf.offset. Depuis Linux 2.6.26, la valeur fournie est limitée à la plage (-0.5s, +0.5s). Dans les anciens noyaux, une erreur EINVAL se produit si la valeur fournie est hors plage.
ADJ_FREQUENCY
Définit le décalage de fréquence à partir de buf.freq. Depuis Linux 2.6.26, la valeur fournie est limitée à la plage (-32768000, +32768000). Dans les anciens noyaux, une erreur EINVAL se produit si la valeur fournie est hors plage.
ADJ_MAXERROR
Définit l'erreur temporelle maximale à partir de buf.maxerror.
ADJ_ESTERROR
Définit l'erreur temporelle estimée à partir de buf.esterror.
ADJ_STATUS
Définit les bits d'état de l'horloge à partir de buf.status. Une description de ces bits est fournie ci-dessous.
ADJ_TIMECONST
Définit la constante de temps de la PLL à partir de buf.constant. Si le flag d'état STA_NANO (voir ci-dessous) est désactivé, le noyau ajoute 4 à cette valeur.
ADJ_SETOFFSET (depuis Linux 2.6.39)
Ajoute buf.time à l'heure actuelle. Si buf.status inclut le flag ADJ_NANO, alors buf.time.tv_usec est interprété comme une valeur en nanosecondes ; sinon, il est interprété comme des microsecondes.
La valeur de buf.time est la somme de ses deux champs, mais le champ buf.time.tv_usec doit toujours être non négatif. L'exemple suivant montre comment normaliser un timeval avec une résolution en nanosecondes.

while (buf.time.tv_usec < 0) {
    buf.time.tv_sec  -= 1;
    buf.time.tv_usec += 1000000000;
}

ADJ_MICRO (depuis Linux 2.6.26)
Sélectionne la résolution en microsecondes.
ADJ_NANO (depuis Linux 2.6.26)
Sélectionne la résolution en nanosecondes. Un seul des flags ADJ_MICRO et ADJ_NANO doit être spécifié.
ADJ_TAI (depuis Linux 2.6.26)
Définit le décalage TAI (Temps Atomique International) à partir de buf.constant.
ADJ_TAI ne doit pas être utilisé conjointement avec ADJ_TIMECONST, car ce dernier mode utilise également le champ buf.constant.
Pour une explication complète du TAI et de la différence entre le TAI et l'UTC, voir BIPM
ADJ_TICK
Définit la valeur du tick à partir de buf.tick.

Alternativement, modes peut être spécifié comme l'une des valeurs suivantes (masque multibit), auquel cas d'autres bits ne doivent pas être spécifiés dans modes :

ADJ_OFFSET_SINGLESHOT
Ancienne méthode adjtime(3) : ajuste (progressivement) le temps de la valeur spécifiée dans buf.offset, qui spécifie un ajustement en microsecondes.
ADJ_OFFSET_SS_READ (fonctionnel depuis Linux 2.6.28)
Renvoie (dans buf.offset) la durée restante à ajuster après une opération ADJ_OFFSET_SINGLESHOT précédente. Cette fonctionnalité a été ajoutée dans Linux 2.6.24, mais n'a pas fonctionné correctement avant Linux 2.6.28.

Les utilisateurs ordinaires sont limités à une valeur de 0 ou ADJ_OFFSET_SS_READ pour modes. Seul le superutilisateur peut définir des paramètres.

Le champ buf.status est un masque de bits utilisé pour définir et/ou récupérer les bits d'état associés à l'implémentation NTP. Certains bits du masque sont lisibles et modifiables, tandis que d'autres sont en lecture seule.

STA_PLL (lecture-écriture)
Active les mises à jour de la boucle à verrou de phase (PLL) via ADJ_OFFSET.
STA_PPSFREQ (lecture-écriture)
Active la discipline de fréquence PPS (impulsion par seconde).
STA_PPSTIME (lecture-écriture)
Active la discipline temporelle PPS.
STA_FLL (lecture-écriture)
Sélectionne le mode boucle à verrou de fréquence (FLL).
STA_INS (lecture-écriture)
Insère une seconde intercalaire après la dernière seconde du jour UTC, prolongeant ainsi la dernière minute du jour d'une seconde. L'insertion de seconde intercalaire se produira chaque jour, tant que ce flag restera activé.
STA_DEL (lecture-écriture)
Supprime une seconde intercalaire à la dernière seconde du jour UTC. La suppression de seconde intercalaire se produira chaque jour, tant que ce flag restera activé.
STA_UNSYNC (lecture-écriture)
Horloge désynchronisée.

NOTE

S

Dans la structure timex, freq, ppsfreq et stabil sont en ppm (parties par million) avec une partie fractionnaire sur 16 bits, ce qui signifie qu'une valeur de 1 dans l'un de ces champs signifie en réalité 2^-16 ppm, et 2^16=65536 est 1 ppm. C'est le cas pour les valeurs d'entrée (dans le cas de freq) et les valeurs de

sortie.

Le traitement des secondes intercalaires déclenché par STA_INS et STA_DEL est effectué par le noyau dans le contexte du minutage. Ainsi, il faudra

un tick dans la seconde pour que la secon
de intercalaire soit insérée ou supprimée.
