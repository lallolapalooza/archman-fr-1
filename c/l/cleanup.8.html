NAME

cleanup - canonicalise et met en file d'attente le message Postfix

SYNOPSIS

cleanup [options générales de démon Postfix]

DESCRIPTION


Le démon cleanup(8) traite les courriels entrants, les insère dans la file d'attente de messagerie incoming et informe le gestionnaire de file d'attente de leur arrivée.

Le démon cleanup(8) effectue les transformations suivantes :

  • Insérer les en-têtes de message manquants : (Resent-) From:, To:, Message-Id: et Date:.
    Ceci est activé avec les paramètres local_header_rewrite_clients et always_add_missing_headers.
  • Transformer les adresses d'enveloppe et d'en-tête vers la forme standard utilisateur@domaine-entièrement-qualifié attendue par les autres programmes Postfix. Cette tâche dépend du démon trivial-rewrite(8).
    La transformation d'en-tête est activée avec le paramètre local_header_rewrite_clients.
  • Éliminer les adresses de destinataires d'enveloppe dupliquées.
    Ceci est activé avec le paramètre duplicate_filter_limit.
  • Supprimer les en-têtes de message : Bcc, Content-Length, Resent-Bcc, Return-Path.
    Ceci est activé avec le paramètre message_drop_headers.
  • Optionnellement, réécrire toutes les adresses d'enveloppe et d'en-tête selon les mappages spécifiés dans les tables de recherche canonical(5).
    La transformation d'en-tête est activée avec le paramètre local_header_rewrite_clients.
  • Optionnellement, masquer les adresses d'expéditeur d'enveloppe et les adresses d'en-tête de message (c'est-à-dire supprimer les informations de l'hôte ou du domaine en dessous de tous les domaines listés dans masquerade_domains, sauf pour les noms d'utilisateur listés dans masquerade_exceptions). Par défaut, le masquage d'adresse n'affecte pas les destinataires d'enveloppe.
    La transformation d'en-tête est activée avec le paramètre local_header_rewrite_clients.
  • Optionnellement, développer les destinataires d'enveloppe selon les informations trouvées dans les tables de recherche virtual_alias_maps.

Le démon cleanup(8) effectue des vérifications de validité du contenu de chaque message. Lorsqu'il trouve un problème, par défaut, il renvoie un statut de diagnostic au client du service de nettoyage, et laisse au client le soin de gérer le problème. Alternativement, le client peut demander au démon cleanup(8) de rejeter le message à l'expéditeur en cas de problème.

DIAGNOSTICS


Les problèmes et les transactions sont enregistrés dans syslogd(8) ou postlogd(8).

BOGUES


Les règles de réécriture basées sur des tables rendent difficile l'expression de conditions if then else et d'autres relations logiques.

PARAMÈTRES DE CONFIGURATION

Les modifications de main.cf sont prises en compte automatiquement, car les processus cleanup(8) ne fonctionnent que pendant une durée limitée. Utilisez la commande "postfix reload" pour accélérer une modification.

Le texte ci-dessous ne fournit qu'un résumé des paramètres. Consultez postconf(5) pour plus de détails, y compris des exemples.

CONTRÔLES DE COMPATIBILITÉ

undisclosed_recipients_header (voir la sortie de 'postconf -d')
En-tête de message que le serveur cleanup(8) de Postfix insère lorsqu'un message ne contient pas d'en-tête To: ou Cc:.

Disponible dans Postfix version 2.1 seulement :

enable_errors_to (no)
Signaler les erreurs de livraison de courrier à l'adresse spécifiée avec l'en-tête de message non standard Errors-To:, au lieu de l'adresse de l'expéditeur d'enveloppe (cette fonctionnalité est supprimée avec la version 2.2 de Postfix, est désactivée par défaut avec la version 2.1 de Postfix, et est toujours activée avec les versions plus anciennes de Postfix).

Disponible dans Postfix version 2.6 et ultérieures :

always_add_missing_headers (no)
Ajouter toujours les en-têtes (Resent-) From:, To:, Date: ou Message-ID: lorsqu'ils sont absents.

Disponible dans Postfix version 2.9 et ultérieures :

enable_long_queue_ids (no)
Activer les identifiants de file d'attente longs et non répétitifs (noms de fichiers de file d'attente).
