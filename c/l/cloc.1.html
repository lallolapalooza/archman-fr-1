cloc(1) Commandes utilisateur cloc(1)

NOM

cloc - Compte, ou calcule les différences de, lignes de code source et de commentaires.

SYNTAXE

cloc [options] <FICHIER|RÉPERTOIRE> ...

DESCRIPTION

Compte, ou calcule les différences de, lignes physiques de code source dans les fichiers donnés (peuvent être des archives telles que des tarballs compressés ou des fichiers zip, ou des hachages de commits git ou des noms de branches) et/ou récursivement sous les répertoires donnés. Il est entièrement écrit en Perl, utilisant uniquement des modules de la distribution standard.

OPTIONS

Options d'entrée

Pour compter l'entrée standard, utilisez le nom de fichier spécial - et soit --stdin-name=FICHIER pour indiquer à cloc le nom du fichier qui est transmis par pipe, soit --force-lang=LANG pour appliquer le compteur LANG à toute l'entrée.

--extract-with=CMD
Cette option n'est nécessaire que si cloc ne parvient pas à déterminer comment extraire le contenu des fichiers d'entrée par lui-même. Utilisez CMD pour extraire des fichiers d'archives binaires (par exemple : .tar.gz, .zip, .Z). Utilisez le littéral '>FICHIER<' comme remplacement pour le(s) fichier(s) réel(s) à extraire. Par exemple, pour compter les lignes de code dans les fichiers d'entrée gcc-4.2.tar.gz perl-5.8.8.tar.gz sous Unix, utilisez : 
--extract-with='gzip -dc >FICHIER< | tar xf -

ou, si vous avez GNU tar :

--extract-with='tar zxf >FICHIER<'

et sous Windows, utilisez, par exemple :

--extract-with="\"c:\Program Files\WinZip\WinZip32.exe\" -e -o >FICHIER<
--list-file=FICHIER
Prendre la liste des noms de fichiers et/ou de répertoires à traiter à partir de FICHIER, qui contient un nom de fichier/répertoire par ligne. Seules les correspondances exactes sont comptées ; les noms de chemins relatifs seront résolus à partir du répertoire où cloc est invoqué. Définir FICHIER à - pour lire les noms de fichiers depuis une entrée standard (STDIN). Voir aussi --exclude-list-file, --config.
--diff-list-file=FICHIER
Prendre les paires de noms de fichiers à comparer à partir de FICHIER, dont le format correspond à la sortie de --diff-alignment. (Exécutez avec cette option pour voir un exemple.) L'identifiant de langue à la fin de chaque ligne est ignoré. Cela active le mode --diff et contourne la logique d'alignement des paires de fichiers. Voir aussi --config.
--vcs=VCS
Invoquer un appel système à VCS pour obtenir une liste de fichiers sur lesquels travailler. Si VCS est 'git', alors il invoquera 'git ls-files' pour obtenir une liste de fichiers et 'git submodule status' pour obtenir une liste de sous-modules dont le contenu sera ignoré. Voir aussi --git qui accepte les hachages de commits git et les noms de branches. Si VCS est 'svn', alors il invoquera 'svn list -R'. Le principal avantage est que cloc ignorera alors les fichiers explicitement exclus par l'outil de versionnement en question, c'est-à-dire ceux dans .gitignore ou ayant la propriété svn:ignore. Alternativement, VCS peut être n'importe quelle commande système qui génère une liste de fichiers. Note : cloc doit se trouver dans un répertoire qui peut lire les fichiers tels qu'ils sont retournés par VCS. cloc ne téléchargera pas de fichiers depuis des dépôts distants. 'svn list -R' peut faire référence à un dépôt distant pour obtenir les noms de fichiers (et peut donc nécessiter une authentification auprès du dépôt distant), mais les fichiers eux-mêmes doivent être locaux. Définir VCS à 'auto' sélectionne entre 'git' et 'svn' (ou aucun) en fonction de la présence d'un sous-répertoire .git ou .svn sous le répertoire où cloc est invoqué.
--unicode
Vérifier les fichiers binaires pour voir s'ils contiennent du texte ASCII étendu Unicode. Cela entraîne une baisse notable des performances.

Options de traitement

--autoconf
Compte les fichiers .in (tels que traités par GNU autoconf) des langages reconnus. Voir aussi --no-autogen.
--by-file
Rapporte les résultats pour chaque fichier source rencontré.
--by-file-by-lang
Rapporte les résultats pour chaque fichier source rencontré en plus du rapport par langage.
--config FICHIER
Lit les options de la ligne de commande depuis FICHIER au lieu de l'emplacement par défaut de ~/.config/cloc/options.txt. Le fichier doit contenir une option, avec ses arguments (le cas échéant), par ligne. Les lignes vides et les lignes commençant par '#' sont ignorées. Les options données sur la ligne de commande ont la priorité sur les entrées lues depuis le fichier. Si un répertoire est également donné avec l'une de ces options : --list-file, --exclude-list-file, --read-lang-def, --force-lang-def, --diff-list-file et qu'un fichier de configuration existe dans ce répertoire, il aura la priorité sur ~/.config/cloc/options.txt.
--count-and-diff SET1 SET2
Effectue d'abord des comptages de code directs des fichiers sources de SET1 et SET2 séparément, puis effectue une différence de ceux-ci. Les entrées peuvent être des paires de fichiers, de répertoires ou d'archives. Si --out ou --report-file est donné, trois fichiers de sortie seront créés, un pour chacun des deux comptages et un pour la différence. Voir aussi --diff, --diff-alignment, --diff-timeout, --ignore-case, --ignore-whitespace.
--diff SET1 SET2
Calcule les différences de code et de commentaires entre les fichiers sources de SET1 et SET2. Les entrées peuvent être des paires de fichiers, de répertoires ou d'archives. Utilisez --diff-alignment pour générer une liste montrant quelles paires de fichiers ont été comparées. Voir aussi --count-and-diff, --diff-alignment, --diff-timeout, --ignore-case, --ignore-whitespace.
--diff-timeout N
Ignore les fichiers qui prennent plus de N secondes à traiter. La valeur par défaut est 10 secondes. Définir N à 0 permet un temps illimité. (Les fichiers volumineux avec de nombreuses lignes répétées peuvent faire prendre des heures à Algorithm::Diff::sdiff().)
--docstring-as-code
cloc considère les docstrings comme des commentaires, mais ce n'est pas toujours correct car les docstrings représentent des chaînes de caractères normales lorsqu'elles apparaissent à droite d'une affectation ou comme arguments de fonction. Ce commutateur force les docstrings à être comptées comme du code.
--follow-links
[Unix uniquement] Suivre les liens symboliques vers des répertoires (les liens symboliques vers des fichiers sont toujours suivis).
--force-lang=LANG[,EXT]
Traiter tous les fichiers ayant une extension EXT avec le compteur pour le langage LANG. Par exemple, pour compter tous les fichiers .f avec le compteur Fortran 90 (qui attend des fichiers se terminant par .f90) au lieu du compteur Fortran 77 par défaut, utilisez : 
--force-lang="Fortran 90",f

Si EXT est omis, chaque fichier sera compté avec le compteur LANG. Cette option peut être spécifiée plusieurs fois (mais cela n'est utile que lorsque EXT est donné à chaque fois). Voir aussi --script-lang, --lang-no-ext.

--force-lang-def=FICHIER
Charger les filtres de traitement de langage depuis FICHIER, puis utiliser ces filtres au lieu des filtres intégrés. Note : les langages qui correspondent à la même extension de fichier (par exemple : MATLAB/Objective-C/MUMPS ; Pascal/PHP ; Lisp/OpenCL ; Lisp/Julia ; Perl/Prolog) seront ignorés car ils nécessitent un traitement supplémentaire qui ne s'exprime pas dans les fichiers de définition de langage. Utilisez --read-lang-def pour définir de nouveaux filtres de langage sans remplacer les filtres intégrés (voir aussi --write-lang-def, --write-lang-def-incl-dup).
--git
Force l'interprétation des entrées comme des cibles git (hachages de commit, noms de branches, etc.) si elles ne sont pas d'abord identifiées comme des noms de fichiers ou de répertoires. Cette option remplace la logique --vcs=git si elle est donnée ; en d'autres termes, --git obtient sa liste de fichiers sur lesquels travailler directement de git en utilisant le hachage ou le nom de branche plutôt que 'git ls-files'. Cette option peut être utilisée avec --diff pour effectuer des différences de comptage de lignes entre commits git, ou entre un commit git et un fichier, un répertoire ou une archive. Utilisez -v/--verbose pour voir les commandes système git que cloc émet.

Ce site n'est en aucun cas associé à Arch Linux ni affilié à ce projet. Le contenu est uniquement une traduction des pages de manuel d'Arch publiées sur man.archlinux.org.

Remplacer les marqueurs de commentaires intégrés dans les chaînes par 'xx'. trouvés.

--fmt
=N
Format de sortie texte alternatif où N est un nombre de 1 à 5, ou -1 à -5. 'total lines' (lignes totales) signifie la somme des lignes de code, de commentaires et de lignes vides. Les valeurs négatives sont identiques aux valeurs positives mais conservent, au lieu de supprimer, le fichier JSON intermédiaire qui est écrit. Le nom du fichier JSON est généré aléatoirement sauf si --out/--report-file est donné. Les formats sont :
1 : par langage (identique à la sortie par défaut de cloc)
2 : par langage avec une colonne supplémentaire pour les lignes totales
3 : par fichier avec le langage
4 : par fichier avec une colonne de lignes totales
5 : par fichier avec le langage et une colonne de lignes
totales

EXEMPLE

S

Compter les lignes de code dans le fichier tar compressé de Perl 5.10.0 sur un système d'exploitation de type UNIX

: 
cloc perl-5.10.0.tar.
gz

Compter les changements dans les fichiers, le code et les commentaires entre les versions de Python 2.6.6 et 2.7

: 
cloc --diff Python-2.6.6.tar.bz  Python-2.7.tar.
bz2

Pour voir comment cloc aligne les fichiers pour la comparaison entre deux bases de code, utilisez l'option --diff-alignment=FICHIER. Ici, les informations d'alignement sont écrites dans "align.tx

t" : 
cloc --diff-alignment=align.txt gcc-4.4.0.tar.bz2  gcc-4.5.0.tar.
bz2

Compter les changements de fichiers, de code et de commentaires entre deux commits git

: 
cloc --git --diff b409850824
HEAD

Afficher les langages reconnus

: 
cloc
--show-lang

Supprimer les commentaires de "foo.c" et enregistrer le résultat dans "foo.c.nc" ("nc" est une extension arbitraire ; utilisée ici pour signifier "no comments" (pas de commentaires))

cloc --strip-comments=nc foo.
c
