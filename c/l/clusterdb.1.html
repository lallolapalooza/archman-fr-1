CLUSTERDB(1) Documentation PostgreSQL 18.1 CLUSTERDB(1)

NOM

clusterdb - regrouper une base de données PostgreSQL

SYNTAXE

clusterdb [option-connexion...] [option...] [ --table | -t table ]... [dbname | -a | --all]

DESCRIPTION

clusterdb est un utilitaire pour réorganiser le regroupement des tables d'une base de données PostgreSQL. Il trouve les tables qui ont déjà été regroupées et les regroupe à nouveau sur le même index utilisé pour la dernière fois. Les tables qui n'ont jamais été regroupées ne sont pas affectées.

clusterdb est une enveloppe autour de la commande SQL CLUSTER(7). Il n'y a pas de différence effective entre le regroupement des bases de données via cet utilitaire et via d'autres méthodes d'accès au serveur.

OPTIONS

clusterdb accepte les arguments de ligne de commande suivants :

-a
--all

Regrouper toutes les bases de données.

[-d] dbname
[--dbname=]dbname

Spécifie le nom de la base de données à regrouper, lorsque -a/--all n'est pas utilisé. Si ceci n'est pas spécifié, le nom de base de données est lu à partir de la variable d'environnement PGDATABASE. Si celle-ci n'est pas définie, le nom d'utilisateur spécifié pour la connexion est utilisé. Le dbname peut être une chaîne de connexion. Dans ce cas, les paramètres de la chaîne de connexion remplaceront toute option de ligne de commande conflictuelle.

-e
--echo

Affiche les commandes que clusterdb génère et envoie au serveur.

-q
--quiet

N'affiche pas les messages de progression.

-t table
--table=table

Regrouper uniquement la table table. Plusieurs tables peuvent être regroupées en utilisant plusieurs options -t.

-v
--verbose

Affiche des informations détaillées pendant le traitement.

-V
--version

Affiche la version de clusterdb et quitte.

-?
--help

Affiche l'aide sur les arguments de ligne de commande de clusterdb et quitte.

clusterdb accepte également les arguments de ligne de commande suivants pour les paramètres de connexion :

-h host
--host=host

Spécifie le nom d'hôte de la machine sur laquelle le serveur est en cours d'exécution. Si la valeur commence par un slash, elle est utilisée comme répertoire pour le socket Unix.

-p port
--port=port

Spécifie le port TCP ou l'extension de fichier de socket Unix local sur lequel le serveur écoute les connexions.

-U username
--username=username

Nom d'utilisateur pour la connexion.

-w
--no-password

Ne jamais demander de mot de passe. Si le serveur exige l'authentification par mot de passe et qu'un mot de passe n'est pas disponible par d'autres moyens, tels qu'un fichier .pgpass, la tentative de connexion échouera. Cette option peut être utile dans les travaux batch et les scripts où aucun utilisateur n'est présent pour saisir un mot de passe.

-W
--password

Force clusterdb à demander un mot de passe avant de se connecter à une base de données.

Cette option n'est jamais essentielle, car clusterdb demandera automatiquement un mot de passe si le serveur exige une authentification par mot de passe. Cependant, clusterdb tentera une connexion inutile pour découvrir que le serveur veut un mot de passe. Dans certains cas, il peut être utile de taper -W pour éviter cette tentative de connexion supplémentaire.

--maintenance-db=dbname

Lorsque -a/--all est utilisé, se connecte à cette base de données pour collecter la liste des bases de données à regrouper. Si elle n'est pas spécifiée, la base de données postgres sera utilisée, ou si elle n'existe pas, template1 sera utilisée. Ceci peut être une chaîne de connexion. Dans ce cas, les paramètres de la chaîne de connexion remplaceront toute option de ligne de commande conflictuelle. De plus, les paramètres de la chaîne de connexion, autres que le nom de la base de données elle-même, seront réutilisés lors de la connexion à d'autres bases de données.

ENVIRONNEMENT

PGDATABASE
PGHOST
PGPORT
PGUSER

Paramètres de connexion par défaut

PG_COLOR

Spécifie si les messages de diagnostic doivent utiliser la couleur. Les valeurs possibles sont toujours, auto et jamais.

Cet utilitaire, comme la plupart des autres utilitaires PostgreSQL, utilise également les variables d'environnement prises en charge par libpq (voir la section 32.15).

DIAGNOSTICS

En cas de difficulté, consultez CLUSTER(7) et psql(1) pour des discussions sur les problèmes potentiels et les messages d'erreur. Le serveur de base de données doit être en cours d'exécution sur l'hôte cible. De plus, tous les paramètres de connexion par défaut et variables d'environnement utilisés par la bibliothèque frontale libpq s'appliqueront.

EXEMPLES

Pour regrouper la base de données test :

$ clusterdb test

Pour regrouper une seule table foo dans une base de données nommée xyzzy :

$ clusterdb --table=foo xyzzy
