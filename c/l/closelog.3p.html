CLOSELOG(3P) Manuel du programmeur POSIX CLOSELOG(3P)

PROLOGUE

Cette page de manuel fait partie du Manuel du programmeur POSIX. L'implémentation Linux de cette interface peut différer (consultez la page de manuel Linux correspondante pour les détails du comportement sous Linux), ou l'interface peut ne pas être implémentée sous Linux.

NOM

closelog, openlog, setlogmask, syslog — contrôle du journal système

SYNTAXE

#include <syslog.h>
void closelog(void);
void openlog(const char *ident, int logopt, int facility);
int setlogmask(int maskpri);
void syslog(int priority, const char *message, ... /* arguments */);

DESCRIPTION

La fonction syslog() envoie un message à une installation de journalisation définie par l'implémentation, qui peut le consigner dans un journal système défini par l'implémentation, l'écrire sur la console système, le transférer à une liste d'utilisateurs, ou le transférer à l'installation de journalisation d'un autre hôte sur le réseau. Le message consigné doit inclure un en-tête de message et un corps de message. L'en-tête du message contient au moins un horodatage et une chaîne de balise.

Le corps du message est généré à partir de message et des arguments suivants de la même manière que si c'étaient des arguments pour printf(), sauf que la spécification de conversion supplémentaire %m sera reconnue ; elle ne convertira aucun argument, provoquera la sortie de la chaîne de message d'erreur associée à la valeur de errno à l'entrée de syslog(), et pourra être mélangée avec des spécifications d'arguments de la forme "%n$". Si une spécification de conversion complète avec le caractère de spécification de conversion m n'est pas seulement %m, le comportement est indéfini. Un saut de ligne final peut être ajouté si nécessaire.

Les valeurs de l'argument priority sont formées en combinant un niveau de sévérité et une valeur de facilité optionnelle. Si aucune valeur de facilité n'est spécifiée, la valeur de facilité par défaut actuelle est utilisée.

Les valeurs possibles du niveau de sévérité comprennent :

LOG_EMERG
Une condition de panique.
LOG_ALERT
Une condition qui devrait être corrigée immédiatement, telle qu'une base de données système corrompue.
LOG_CRIT
Conditions critiques, telles que des erreurs matérielles.
LOG_ERR
Erreurs.
LOG_WARNING

Messages d'avertissement.
LOG_NOTICE
Conditions qui ne sont pas des erreurs, mais qui peuvent nécessiter un traitement spécial.
LOG_INFO
Messages informatifs.
LOG_DEBUG
Messages contenant des informations généralement utiles uniquement lors du débogage d'un programme.

La facilité indique l'application ou le composant système générant le message. Les valeurs de facilité possibles comprennent :

LOG_USER
Messages générés par des processus arbitraires. C'est l'identifiant de facilité par défaut si aucun n'est spécifié.
LOG_LOCAL0
Réservé pour un usage local.
LOG_LOCAL1
Réservé pour un usage local.
LOG_LOCAL2
Réservé pour un usage local.
LOG_LOCAL3
Réservé pour un usage local.
LOG_LOCAL4
Réservé pour un usage local.
LOG_LOCAL5
Réservé pour un usage local.
LOG_LOCAL6
Réservé pour un usage local.
LOG_LOCAL7
Réservé pour un usage local.

La fonction openlog() définit les attributs du processus qui affectent les appels ultérieurs à syslog(). L'argument ident est une chaîne qui est ajoutée au début de chaque message. L'argument logopt indique les options de journalisation. Les valeurs pour logopt sont construites par un OU bit-à-bit inclusif de zéro ou plusieurs des éléments suivants :

LOG_PID
Enregistrer l'ID du processus avec chaque message. Ceci est utile pour identifier des processus spécifiques.
LOG_CONS
Écrire les messages sur la console système s'ils ne peuvent pas être envoyés à l'installation de journalisation. La fonction syslog() s'assure que le processus n'acquiert pas la console comme terminal de contrôle lors de l'écriture du message.
LOG_NDELAY
Ouvrir la connexion à l'installation de journalisation immédiatement. Normalement, l'ouverture est retardée jusqu'à ce que le premier message soit enregistré. Ceci est utile pour les programmes qui doivent gérer l'ordre d'allocation des descripteurs de fichiers.
LOG_ODELAY
Retarder l'ouverture jusqu'à ce que syslog() soit appelé.
LOG_NOWAIT
Ne pas attendre les processus enfants qui pourraient avoir été créés pendant le processus de journalisation du message. Cette option doit être utilisée par les processus qui activent la notification de terminaison d'enfant avec SIGCHLD, car syslog() pourrait sinon bloquer en attendant un enfant dont le statut de sortie a déjà été collecté.

L'argument facility encode une facilité par défaut à attribuer à tous les messages qui n'ont pas déjà une facilité explicite encodée. La facilité par défaut initiale est LOG_USER.

Les fonctions openlog() et syslog() peuvent allouer un descripteur de fichier. Il n'est pas nécessaire d'appeler openlog() avant d'appeler syslog().

La fonction closelog() ferme tous les descripteurs de fichiers ouverts alloués par des appels précédents à openlog() ou syslog().

La fonction setlogmask() définit le masque de priorité de journalisation pour le processus courant à maskpri et renvoie le masque précédent. Si l'argument maskpri est 0, le masque de journalisation courant n'est pas modifié. Les appels par le processus courant à syslog() avec une priorité non définie dans maskpri seront rejetés. Le masque de journalisation par défaut autorise la journalisation de toutes les priorités. Un appel à openlog() n'est pas requis avant d'appeler setlogmask().

Les constantes symboliques à utiliser comme valeurs pour les arguments logopt, facility, priority et maskpri sont définies dans l'en-tête <syslog.h>.

VALEUR DE RETOUR

La fonction setlogmask() renvoie le masque de priorité de journalisation précédent. Les fonctions closelog(), openlog() et syslog() ne renvoient aucune valeur.

ERREURS

Aucune erreur n'est définie.

Les sections suivantes sont informatives.

EXEMPLES

Utilisation de openlog()

L'exemple suivant fait en sorte que les appels ultérieurs à syslog() enregistrent l'ID du processus avec chaque message et écrivent les messages sur la console système s'ils ne peuvent pas être envoyés à l'installation de journalisation.

#include <syslog.h>
char *ident = "Process demo";
int logopt = LOG_PID | LOG_CONS;
int facility = LOG_USER;
...
openlog(ident, logopt, facility);

Utilisation de setlogmask()

L'exemple suivant fait en sorte que les appels ultérieurs à syslog() acceptent les messages d'erreur et rejettent tous les autres messages.

#include <syslog.h>
int result;
int mask = LOG_MASK (LOG_ERR);
...
result = setlogmask(mask);
