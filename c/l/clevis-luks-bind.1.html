NOM

clevis-luks-bind - Associe un périphérique LUKS en utilisant la politique spécifiée

SYNTAXE

clevis luks bind [-f] [-y] -d DEV [-t TKN_ID] [-s SLT] [-k KEY] [-e EXISTING_TOKEN_ID] PIN CFG

APERÇU

La commande clevis luks bind associe un périphérique LUKS en utilisant la politique spécifiée. Ceci est accompli avec une commande simple :

$ clevis luks bind -d /dev/sda tang '{"url":...}'

Cette commande effectue quatre étapes :

1. Crée une nouvelle clé avec la même entropie que la clé maître LUKS — le nombre maximal de bits d'entropie est de 256.
2. Chiffre la nouvelle clé avec Clevis.
3. Stocke le JWE Clevis dans l'en-tête LUKS.
4. Active la nouvelle clé pour une utilisation avec LUKS.

Ce disque peut maintenant être déverrouillé avec votre mot de passe existant ainsi qu'avec la politique Clevis. Vous devrez en outre activer un ou plusieurs des déverrouilleurs Clevis LUKS. Voir clevis-luks-unlockers(7).

OPTIONS

•-f : Ne pas demander l'initialisation de LUKSMeta
•-y : Répondre automatiquement oui à toutes les questions. Lors de l'utilisation de tang, cela permet de sauter la vérification de confiance de la publicité, ce qui peut être utile dans les déploiements automatisés
•-d DEV : Le périphérique LUKS sur lequel effectuer l'association
•-s SLT : L'emplacement LUKSMeta à utiliser pour le stockage des métadonnées
•-t TKN_ID : L'identifiant du jeton LUKS à utiliser ; disponible uniquement pour LUKS2
•-k KEY : Lire de manière non interactive le mot de passe LUKS à partir d'un fichier KEY
•-k - : Lire de manière non interactive le mot de passe LUKS depuis l'entrée standard
•-e E_TKN_ID : Identifiant du jeton LUKS pour le mot de passe existant ; disponible uniquement pour LUKS2. Ce paramètre permet de fournir un jeton configuré dans LUKS2 contenant le mot de passe existant pour ce périphérique, de sorte que le mot de passe existant ne soit pas demandé par clevis

MISE EN GARDE

Cette commande ne modifie pas la clé maître LUKS. Cela implique que si vous créez une image chiffrée LUKS à utiliser dans un environnement de machine virtuelle ou dans le cloud, toutes les instances exécutant cette image partageront une clé maître. Ceci est extrêmement dangereux et doit être évité à tout prix.

Ce n'est pas une limitation de Clevis mais un principe de conception de LUKS. Si vous souhaitez avoir des volumes racines chiffrés dans le cloud, vous devrez vous assurer que vous effectuez la méthode d'installation du système d'exploitation pour chaque instance dans le cloud. Les images ne peuvent pas être partagées sans partager également une clé maître.
