cyme(1) Manuel des commandes générales cyme(1)

NOM

cyme - Liste les bus et périphériques USB du système. Un lsusb moderne et multiplateforme

SYNTAXE

cyme [-l|--lsusb] [-t|--tree] [-d|--vidpid] [-s|--show] [-D|--device] [--filter-name] [--filter-serial] [--filter-class] [-v|--verbose]... [-b|--blocks] [--bus-blocks] [--config-blocks] [--interface-blocks] [--endpoint-blocks] [--block-operation] [-m|--more] [--sort-devices] [--sort-buses] [--group-devices] [--hide-buses] [--hide-hubs] [--list-root-hubs] [--decimal] [--no-padding] [--color] [--encoding] [--icon] [--headings] [--json] [--from-json] [-F|--force-libusb] [-c|--config] [-z|--debug]... [--mask-serials] [--system-profiler] [-h|--help] [-V|--version] [sous-commandes]

DESCRIPTION

Liste les bus et périphériques USB du système. Un lsusb moderne et multiplateforme

OPTIONS

-l, --lsusb
Tente de maintenir la compatibilité avec la sortie de lsusb
-t, --tree
Affiche la hiérarchie des périphériques USB sous forme d'arbre
-d, --vidpid <VIDPID>
N'affiche que les périphériques avec les identifiants de vendeur et de produit spécifiés (en hexadécimal) au format VID:[PID]
-s, --show <SHOW>
N'affiche que les périphériques avec les numéros de périphérique et/ou de bus spécifiés (en décimal) au format [[bus]:][devnum]
-D, --device <DEVICE>
Sélectionne le périphérique que lsusb examinera - fourni sous forme de chemin de style Linux /dev/bus/usb/BBB/DDD
--filter-name <FILTER_NAME>
Filtre sur la chaîne contenue dans le nom
--filter-serial <FILTER_SERIAL>
Filtre sur la chaîne contenue dans le numéro de série
--filter-class <FILTER_CLASS>
Filtre sur le code de classe USB

Valeurs possibles :

  • use-interface-descriptor : La classe de l'appareil est non spécifiée, les descripteurs d'interface sont utilisés pour déterminer les pilotes nécessaires
  • audio : Haut-parleur, microphone, carte son, MIDI
  • cdc-communications : L'interface série moderne ; apparaît comme un port UART/RS232 sur la plupart des systèmes
  • hid : Périphérique d'interface humaine ; manettes de jeu, claviers, souris, etc. Également couramment utilisé comme interface de données de périphérique plutôt que de créer quelque chose à partir de zéro
  • physical : Joystick à retour de force
  • image : Périphérique de capture d'images fixes ; scanners, appareils photo
  • printer : Imprimante laser, imprimante jet d'encre, machine CNC
  • mass-storage : Périphériques de stockage de masse (MSD) : clé USB, lecteur de carte mémoire, lecteur audio numérique, appareil photo numérique, disque externe
  • hub : Hub USB haute vitesse
  • cdc-data : Utilisé conjointement avec la classe 02h (Communications et contrôle CDC) ci-dessus
  • smart-card : Lecteur de carte à puce USB
  • content-security : Lecteur d'empreintes digitales
  • video : Webcam
  • personal-healthcare : Moniteur de pouls (montre)
  • audio-video : Webcam, TV
  • billboard : Décrit les modes alternatifs USB-C pris en charge par le périphérique
  • usb-type-c-bridge : Une interface pour exposer et configurer les capacités USB Type-C des connecteurs sur les hubs USB ou les adaptateurs de mode alternatif
  • bdp : Cette classe de base est définie pour les périphériques qui se conforment à la spécification « VESA USB BDP Device Specification » trouvée sur le site Web de VESA. Cette spécification définit l'ensemble utilisable des valeurs de sous-classe et de protocole. Les valeurs en dehors de cette spécification définie sont réservées. Ces codes de classe ne peuvent être utilisés que dans les descripteurs d'interface
  • mctp : Cette classe de base est définie pour les périphériques qui se conforment à la spécification « MCTP over USB » trouvée sur le site Web du DMTF sous DSP0283. Cette spécification définit l'ensemble utilisable des valeurs de sous-classe et de protocole. Les valeurs en dehors de cette spécification définie sont réservées. Ces codes de classe ne peuvent être utilisés que dans les descripteurs d'interface
  • i3c-device : Une interface pour exposer et configurer la fonction I3C au sein d'un périphérique USB afin de permettre l'interaction entre le logiciel hôte et le périphérique I3C, pour piloter les transactions sur le bus I3C vers/depuis les périphériques cibles
  • diagnostic : Équipement de traçage et de débogage
  • wireless-controller : Contrôleurs sans fil : adaptateurs Bluetooth, Microsoft RNDIS
  • miscellaneous : Cette classe de base est définie pour les définitions de périphériques divers. Certaines sous-classes et protocoles correspondants sont définis sur le site Web de l'USB-IF
  • application-specific-interface : Cette classe de base est définie pour les périphériques qui se conforment à plusieurs spécifications de classe trouvées sur le site Web de l'USB-IF
  • vendor-specific-class : Cette classe de base est définie pour que les fournisseurs l'utilisent comme ils le souhaitent
-v, --verbose
Niveau de verbosité (répéter fournit un compte) : 1 affiche les configurations du périphérique ; 2 affiche les interfaces ; 3 affiche les points de terminaison des interfaces ; 4 affiche tout et plus de blocs
-b, --blocks <BLOCS>...
Spécifie les blocs qui seront affichés pour chaque périphérique et dans quel ordre. Fournir l'argument plusieurs fois ou sous forme de csv pour spécifier plusieurs blocs.

[défaut : numéro de bus,numéro de périphérique,icône,identifiant vendeur,identifiant produit,nom,numéro de série,vitesse]

Valeurs possibles :

  • bus-number : Numéro du bus auquel le périphérique est connecté
  • device-number : Numéro de périphérique attribué par le bus
  • branch-position : Position du périphérique dans la branche parente
  • port-path : Chemin du port de style Linux
  • sys-path : Chemin système udev signalé par Linux
  • driver : Pilote signalé par udev Linux chargé pour le périphérique
  • icon : Icône basée sur VID/PID
  • vendor-id : Identifiant vendeur unique - acheté auprès de l'USB IF
  • product-id : Identifiant produit unique du vendeur
  • vid-pid : Identifiant vendeur unique et identifiant produit sous forme de chaîne formatée "vid:pid" comme lsusb
  • name : Le nom du périphérique tel que rapporté dans le descripteur ou en utilisant usb_ids si absent
  • manufacturer : Le fabricant du périphérique tel que fourni dans le descripteur ou en utilisant usb_ids si absent
  • product-name : Le nom du produit du périphérique tel que rapporté par la recherche usb_ids vidpid
  • vendor-name : Le nom du vendeur du périphérique tel que rapporté par la recherche usb_ids vid
  • serial : Chaîne de numéro de série du périphérique telle que rapportée par le descripteur
  • speed : Vitesse du périphérique annoncée
  • negotiated-speed : Vitesse du périphérique négociée telle que connectée
  • tree-positions : Position le long de toutes les branches jusqu'au périphérique racine
  • bus-power : Seulement pour system_profiler de macOS - réellement le courant du bus en mA, pas la puissance !
  • bus-power-used : Seulement pour system_profiler de macOS - réellement le courant du bus utilisé en mA, pas la puissance !
  • extra-current-used : Seulement pour system_profiler de macOS - réellement le courant du bus utilisé en mA, pas la puissance !
  • bcd-device : La version du périphérique
  • bcd-usb : La version USB prise en charge
  • base-class : Énumération de la classe de base de l'interface fournie par l'USB IF - disponible uniquement lors de l'utilisation de libusb
  • sub-class : Valeur de sous-classe de l'interface fournie par l'USB IF - disponible uniquement lors de l'utilisation de libusb
  • protocol : Valeur du protocole pour l'interface fournie par l'USB IF - disponible uniquement lors de l'utilisation de libusb
  • uid-class : Nom de classe du dépôt USB IDs
  • uid-sub-class : Nom de sous-classe du dépôt USB IDs
  • uid-protocol : Nom du protocole du dépôt USB IDs
  • class : Code de classe USB entièrement défini basé sur le triplet BaseClass/SubClass/Protocol
  • base-value : Classe de base sous forme de valeur numérique plutôt que d'énumération
  • last-event : Dernière fois que le périphérique a été vu
  • event-icon : Icône de l'événement
--bus-blocks <BUS_BLOCKS>...
Spécifie les blocs qui seront affichés pour chaque bus et dans quel ordre. Fournir l'argument plusieurs fois ou sous forme de csv pour spécifier plusieurs blocs.

[défaut : chemin du port,nom,contrôleur hôte,périphérique contrôleur hôte]

Valeurs possibles :

  • bus-number : Identifiant du numéro de bus système
  • icon : Icône basée sur VID/PID
  • name : Nom interne du bus système basé sur

Lists USB devices.

OPTIONS

--bus-blocks <BUS_BLOCKS>...
Specify the blocks which will be displayed for each bus and in what order. Supply arg multiple times or csv to specify multiple blocks.

[default: number,root-hub,bus-name]

Possible values:

  • name: Name of the bus
  • number: Bus number
  • root-hub: Root Hub device name
  • host-controller: System internal bus provider name
  • host-controller-vendor: Vendor name of PCI Host Controller from pci.ids
  • host-controller-device: Device name of PCI Host Controller from pci.ids
  • pci-vendor: PCI vendor ID (VID)
  • pci-device: PCI device ID (PID)
  • pci-revision: PCI Revsision ID
  • port-path: syspath style port path to bus, applicable to Linux only
--config-blocks <CONFIG_BLOCKS>...
Specify the blocks which will be displayed for each configuration and in what order. Supply arg multiple times or csv to specify multiple blocks.

[default: number,icon-attributes,max-power,name]

Possible values:

  • name: Name from string descriptor
  • number: Number of config, bConfigurationValue; value to set to enable to configuration
  • num-interfaces: Interfaces available for this configuruation
  • attributes: Attributes of configuration, bmAttributes
  • icon-attributes: Icon representation of bmAttributes
  • max-power: Maximum current consumption in mA
--interface-blocks <INTERFACE_BLOCKS>...
Specify the blocks which will be displayed for each interface and in what order. Supply arg multiple times or csv to specify multiple blocks.

[default: port-path,icon,alt-setting,base-class,sub-class]

Possible values:

  • name: Name from string descriptor
  • number: Interface number
  • port-path: Interface port path (only applicable on Linux)
  • base-class: Base class enum of interface provided by USB IF
  • sub-class: Sub-class value of interface provided by USB IF
  • protocol: Prototol value for interface provided by USB IF
  • alt-setting: Interfaces can have the same number but an alternate settings defined here
  • driver: Driver obtained from udev (Linux only)
  • sys-path: syspath obtained from udev (Linux only)
  • dev-path: The /dev/ device paths for the interface if any exist (Linux only)
  • mount-paths: Mount paths for MSD interfaces in CSV partition_no:mount_path format (Linux only)
  • num-endpoints: An interface can have many endpoints
  • icon: Icon based on BaseClass/SubCode/Protocol
  • uid-class: Class name from USB IDs repository
  • uid-sub-class: Sub-class name from USB IDs repository
  • uid-protocol: Protocol name from USB IDs repository
  • class: Fully defined USB Class Code based on BaseClass/SubClass/Protocol triplet
  • base-value: Base class as number value rather than enum
--endpoint-blocks <ENDPOINT_BLOCKS>...
Specify the blocks which will be displayed for each endpoint and in what order. Supply arg multiple times or csv to specify multiple blocks.

[default: number,direction,transfer-type,sync-type,usage-type,max-packet-size]

Possible values:

  • number: Endpoint number on interface
  • direction: Direction of data into endpoint
  • transfer-type: Type of data transfer endpoint accepts
  • sync-type: Synchronisation type (Iso mode)
  • usage-type: Usage type (Iso mode)
  • max-packet-size: Maximum packet size in bytes endpoint can send/recieve
  • interval: Interval for polling endpoint data transfers. Value in frame counts. Ignored for Bulk & Control Endpoints. Isochronous must equal 1 and field may range from 1 to 255 for interrupt endpoints
--block-operation <BLOCK_OPERATION> [default: new]
Operation to perform on the blocks supplied via --blocks, --bus-blocks, --config-blocks, --interface-blocks and --endpoint-blocks

Default is 'new' for legacy reasons but 'add' is probably more useful

Possible values:

  • add: Add new blocks to the existing blocks, ignoring duplicates
  • append: Append new blocks to the end of the existing blocks
  • new: Replace all blocks with new ones
  • prepend: Prepend new blocks to the start of the existing blocks
  • remove: Remove matching blocks from the existing blocks
-m, --more
Print more blocks by default at each verbosity

Only works if --blocks,--x--blocks not supplied as args or in config

--sort-devices <SORT_DEVICES>
Sort devices operation

[default: device-number]

Possible values:

  • device-number: Sort by bus device number
  • branch-position: Sort by position in parent branch
  • no-sort: No sorting; whatever order it was parsed
--sort-buses
Sort devices by bus number. If using any sort-devices other than no-sort, this happens automatically
--group-devices <GROUP_DEVICES>
Group devices by value when listing

[default: no-group]

Possible values:

  • no-group: No grouping
  • bus: Group into buses with bus info as heading - like a flat tree
--hide-buses
Hide empty buses when printing tree; those with no devices
--hide-hubs
Hide empty hubs when printing tree; those with no devices. When listing will hide hubs regardless of whether empty of not
--list-root-hubs
Show root hubs when listing; Linux only
--decimal
Show base16 values as base10 decimal instead
--no-padding
Disable padding to align blocks - will cause --headings to become maligned
--color <COLOR>
Output coloring mode

[default: auto]

Possible values:

  • auto: Show colours if the output goes to an interactive console
  • always: Always apply colouring to the output
  • never: Never apply colouring to the output
--encoding <ENCODING>
Output character encoding

[default: glyphs]

Possible values:

  • glyphs: Use UTF-8 private use area characters such as those used by NerdFont to show glyph icons
  • utf8: Use only standard UTF-8 characters for the output; no private use area glyph icons
  • ascii: Use only ASCII characters for the output; 0x00 - 0x7F (127 chars)
--icon <ICON>
When to print icon blocks

[default: auto]

Possible values:

  • auto: Show icon blocks if the [`Encoding`] supports icons matched in the [`icon::IconTheme`]
  • always: Always print icon blocks if included in configured blocks
  • never: Never print icon blocks
--headings
Show block headings
--json
Output as json format after sorting, filters and tree settings are applied; without -tree will be flattened dump of devices
--from-json <FROM_JSON>
Read from json output rather than profiling system
-F, --force-libusb
Force pure libusb profiler on macOS rather than combining system_profiler output

Has no effect on other platforms or when using nusb

-c, --config <CONFIG>
Path to user config file to use for custom icons, colours and default settings
-z, --debug
Turn debugging information on. Alternatively can use RUST_LOG env: INFO, DEBUG, TRACE
--mask-serials <MASK_SERIALS>
Mask serial numbers with '*' or random chars

Possible values:

  • no-mask: No masking
  • hide: Hide with '*' char
  • scramble: Mask by randomising existing chars
  • replace: Mask by replacing length with random chars
--system-profiler
Use the system_profiler command on macOS to get USB data

If not using nusb this is the default for macOS, merging with libusb data for verbose output. nusb uses IOKit directly so does not use system_profiler by default

-h, --help
Print help (see a summary with '-h')
-V, --version
Print version
