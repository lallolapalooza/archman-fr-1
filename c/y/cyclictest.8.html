OPTION

S

Ces programmes suivent la syntaxe habituelle des lignes de commande GNU, avec les options longues commençant par deux tirets ('--').
Un résumé des options est inclus

ci-dessous.
-a, --affinity[=PROC-S
ET]
Exécute les threads sur l'ensemble de processeurs donné par PROC-SET. Si PROC-SET n'est pas spécifié, tous les processeurs seront utilisés. Les threads seront assignés aux processeurs de l'ensemble dans l'ordre numérique, de manière circulaire.
L'ensemble de processeurs peut être spécifié comme A,B,C, ou A-C, ou A-B,D-F, et ainsi de suite*. Le caractère ! peut être utilisé pour nier un ensemble. Par exemple, !B-D signifie utiliser tous les CPU disponibles sauf B à D. Les numéros de CPU sont les mêmes que ceux affichés dans le champ processo
r
de /proc/cpuinfo. Voir numa(3) pour plus d'informations sur la spécification d'ensembles de CPU. * Le support des ensembles de CPU nécessite libnuma version >= 2. Pour libnuma v1, PROC-SET, si spécifié,
doit être un numéro de CPU unique.
-A,
--align=USEC
Aligne les réveils des threads sur un décalage spécifique en
microsecondes
-b, --breaktrace=US
EC
Envoie la commande de trace d'interruption lorsque la
latence > USEC
-c, --clock=CLOCK
sélectionne l'horloge
0 = CLOCK_MONOTONIC (par
défaut)
1 =
CLOCK_REALTIME
--deepest-idle-state=
n
Réduit la latence de sortie du mode inactif en limitant l'état inactif jusqu'à n sur les CPU utilisés (-1 désactive tous les états inactifs). La gestion de l'alimentation n'est pas
supprimée sur les autres CPU.
--default-syste
m
N'essaie pas de régler le système depuis cyclictest. La gestion de l'alimentation n'est pas supprimée. Cela pourrait donner des résultats plus pauvres, mais vous permettra de découvrir si vous avez
besoin de régler le système.
-d,
--distance=DIST
Distance des intervalles de threads en µs, par défaut
= 500
-D, --duration=TIME
Spécifie une durée pour l'exécution du
test.
Ajoutez 'm', 'h' ou 'd' pour spécifier des minutes, des heures ou
des jours.
-F,
--fifo=<path>
Crée un tube nommé à path et y écrit les
statistiques
-h,
--histogram=US
Affiche l'histogramme de latence sur stdout après l'exécution. US est le temps de latence maximal à suivre en microsecondes. Cette option exécute tous les threads à la même
priorité.
-H, --histofall=MAXLATENCYINU
S
Identique à -h sauf qu'une colonne d'histogramme supplémentaire est affichée à la droite contenant les données récapitulatives de tous les histogrammes de threads. Si cyclictest n'exécute qu'un seul
thread, l'option -H est équivalente à -h.
--histfile=<path> Écrit l'histogramme de latence dans <path> au lieu de
stdout.
-i,
--interval=INTV
Définit l'intervalle de base du/des thread(s) en microsecondes (par défaut 1000µs). Cela définit l'intervalle du premier thread. Voir aussi
-d.
--json=FILEN
AME
Écrit les résultats finaux dans FILENAME, au format
JSON.
--lapt
op
Économise la batterie lors de l'exécution de cyclictest. Cela vous donnera des résultats temps réel plus pauvres, mais ne videra pas votre batterie aussi
rapidement.
--latency=PM_
Q0S
valeur cible de latence de gestion de l'alimentation. Cette valeur est écrite dans /dev/cpu_dma_latency et affecte les c-states. La valeur par défaut
est 0
-l,
--loops=LOOPS
Définit le nombre de boucles. La valeur par défaut est 0 (infini). Cette option est utile pour les tests automatisés avec un nombre donné de cycles de test. Cyclictest est arrêté une fois le nombre d'intervalles de minuterie
atteint.
--mainaffinity=CPU
SET
Exécute le thread principal sur le CPU #N. Cela n'affecte que le thread principal et non les threads de
mesure
-m,
--mlockall
Verrouille les allocations mémoire actuelles et futures pour empêcher leur mise en
pagination
-M,
--refresh_on_max
Retarde la mise à jour de l'écran jusqu'à ce qu'une nouvelle latence maximale soit atteinte. (utile pour exécuter cyclictest sur des connexions à faible bande
passante)
-N,
--nsecs
Affiche les résultats en nanosecondes au lieu de microsecondes, qui est l'unité par
défaut.
-o,
--oscope=RED
Mode oscilloscope, réduit la sortie verbeuse de
RED.
-p,
--prio=PRIO
Définit la priorité du premier thread. La priorité donnée est définie pour le premier thread de test. Chaque thread suivant reçoit une priorité plus basse : Priorité(Thread N) = max(Priorité(Thread N-1) - 1,
0)
--policy=NA
ME
définit la politique d'ordonnancement des threads de mesure où NAME est l'un des suivants : other, normal, batch, idle, fifo,
rr
--priospre
ad
répartit les niveaux de priorité à partir d'une valeur
spécifiée
-q,
--quiet
N'affiche un résumé qu'à la sortie. Utile pour les tests automatisés, où seule la sortie récapitulative doit être
capturée.
-r,
--relative
Utilise des minuteurs relatifs au lieu d'absolus. Le comportement par défaut des tests est d'utiliser des minuteurs absolus. Cette option est là pour complétude et ne devrait pas être utilisée pour des tests
reproductibles.
-R,
--resolution
Vérifie la résolution de l'horloge, en appelant clock_gettime() de nombreuses fois. La liste des valeurs de lock_gettime() sera rapportée avec
-X
--secaligned
[USEC]
aligne les réveils des threads sur la seconde pleine suivante et applique le décalage
optionnel.
-s,
--system
Utilise sys_nanosleep et sys_setitimer au lieu des minuteurs posix. Notez que -s ne peut être utilisé qu'avec un seul thread car les itimers sont par processus et non par thread. -s utilise l'appel système nanosleep et n'est pas restreint à un seul
thread.
-S,
--smp
Définit les options pour les tests standard sur les systèmes SMP. Équivalent à l'utilisation des options : "-t -a" ainsi qu'à maintenir toute priorité spécifiée égale entre tous les
threads
--spike=<trigg
er>
enregistre tous les pics >
trigger
--spike-nodes=[num of
nodes]
Ce sont le nombre maximal de pics que nous pouvons enregistrer.
La valeur par défaut est 1024 si non
spécifié.
--s
mi
Active le comptage/détection SMI sur les processeurs prenant en charge le comptage
SMI.
-t,
--threads[=NUM]
Définit le nombre de threads de test (par défaut 1). Crée NUM threads de test. Si NUM n'est pas spécifié, NUM est défini au nombre de CPU disponibles. Voir -d, -i et -p pour plus
d'informations.
--tracema
rk
écrit une marque de trace lorsque la latence -b est
dépassée.
-u,
--unbuffered
force une sortie non tamponnée pour le traitement en
direct
-v,
--verbose
Affiche les valeurs sur stdout pour les statistiques. Cette option est utilisée pour recueillir des informations statistiques sur la distribution de la latence. La sortie est envoyée sur stdout. Le format de sortie est :

n:

c:v ss="Pp">où n=numéro de tâche c=compteur v=valeur de latence en µs.

--dbg_cyclictest
Affiche des informations utiles pour déboguer cyclictest
-x, --posix_timers
Utilise les minuteurs POSIX au lieu de clock_nanosleep.
