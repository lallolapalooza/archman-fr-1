CIDR_TABLE(5) Manuel des formats de fichiers CIDR_TABLE(5)

NOM

cidr_table - format des tables CIDR de Postfix

SYNTAXE

postmap -q "chaîne" cidr:/etc/postfix/nom_de_fichier
postmap -q - cidr:/etc/postfix/nom_de_fichier <fichier_entrée

DESCRIPTION


Le système de messagerie Postfix utilise des tables de recherche optionnelles. Ces tables sont généralement au format dbm ou db. Alternativement, les tables de recherche peuvent être spécifiées sous forme CIDR (Classless Inter-Domain Routing). Dans ce cas, chaque entrée est comparée à une liste de motifs. Lorsqu'une correspondance est trouvée, le résultat correspondant est retourné et la recherche est terminée.

Pour savoir quels types de tables de recherche votre système Postfix prend en charge, utilisez la commande "postconf -m".

Pour tester les tables de recherche, utilisez la commande "postmap -q" comme décrit dans la SYNTAXE ci-dessus.

FORMAT DE TABLE

La forme générale d'une table CIDR Postfix est :

motif résultat
Lorsqu'une chaîne de recherche correspond au motif spécifié, utilisez la valeur résultat correspondante. Le motif doit être sous forme réseau/préfixe ou adresse_réseau (voir SYNTAXE DES MOTIFS D'ADRESSE ci-dessous).
!motif résultat
Lorsqu'une chaîne de recherche ne correspond pas au motif spécifié, utilisez la valeur résultat spécifiée. Le motif doit être sous forme réseau/préfixe ou adresse_réseau (voir SYNTAXE DES MOTIFS D'ADRESSE ci-dessous).

Cette fonctionnalité est disponible dans Postfix 3.2 et versions ultérieures.

si motif
finsi
Lorsqu'une chaîne de recherche correspond au motif spécifié, faites correspondre cette chaîne de recherche aux motifs situés entre si et finsi. Le motif doit être sous forme réseau/préfixe ou adresse_réseau (voir SYNTAXE DES MOTIFS D'ADRESSE ci-dessous). Les blocs si..finsi peuvent être imbriqués.

Note : n'ajoutez pas d'espacement avant le texte situé entre si..finsi.

Cette fonctionnalité est disponible dans Postfix 3.2 et versions ultérieures.

si !motif
finsi
Lorsqu'une chaîne de recherche ne correspond pas au motif spécifié, faites correspondre cette chaîne de recherche aux motifs situés entre si et finsi. Le motif doit être sous forme réseau/préfixe ou adresse_réseau (voir SYNTAXE DES MOTIFS D'ADRESSE ci-dessous). Les blocs si..finsi peuvent être imbriqués.

Note : n'ajoutez pas d'espacement avant le texte situé entre si..finsi.

Cette fonctionnalité est disponible dans Postfix 3.2 et versions ultérieures.

lignes vides et commentaires
Les lignes vides et les lignes contenant uniquement des espaces sont ignorées, de même que les lignes dont le premier caractère non-espacé est un `#'.
texte sur plusieurs lignes
Une ligne logique commence par du texte non-espacé. Une ligne qui commence par un espace continue une ligne logique.

ORDRE DE RECHERCHE DE TABLE

Les motifs sont appliqués dans l'ordre spécifié dans la table, jusqu'à ce qu'un motif correspondant à la chaîne de recherche soit trouvé.

SYNTAXE DES MOTIFS D'ADRESSE

Les tables CIDR de Postfix sont basées sur des motifs. Un motif est soit une adresse_réseau qui nécessite une correspondance exacte, soit une adresse_réseau/longueur_préfixe où la partie longueur_préfixe spécifie la longueur du préfixe de l'adresse_réseau qui doit correspondre (les autres bits de la partie adresse_réseau doivent être à zéro).

Une adresse réseau IPv4 est une séquence de quatre octets décimaux séparés par des ".", et une adresse réseau IPv6 est une séquence de trois à huit paires d'octets hexadécimaux séparées par des ":" ou "::", où ce dernier est une abréviation pour une séquence d'une ou plusieurs paires d'octets entièrement zéro. Le motif 0.0.0.0/0 correspond à toutes les adresses IPv4, et ::/0 correspond à toutes les adresses IPv6. La prise en charge IPv6 est disponible depuis Postfix 2.2.

Avant que les comparaisons ne soient effectuées, les clés de recherche et les entrées de table sont converties de chaînes en binaires. Par conséquent, les motifs IPv6 correspondront indépendamment des zéros non significatifs (un zéro non significatif dans un octet d'adresse IPv4 indique une notation octale).

Note : les informations d'adresse peuvent être entourées de crochets "[]" mais cette forme n'est pas requise.

SPECIFICATION EN LIGNE

Le contenu d'une table peut être spécifié dans le nom de la table (Postfix 3.7 et versions ultérieures). La syntaxe de base est :

main.cf:
    paramètre = .. cidr:{ { règle-1 }, { règle-2 } .. } ..
master.cf:
    .. -o { paramètre = .. cidr:{ { règle-1 }, { règle-2 } .. } .. } ..

Postfix développe récursivement toute instance de $nom_paramètre dans la valeur de paramètre ci-dessus, ignore les espaces après '{' et avant '}', et écrit chaque règle comme une ligne de texte dans un fichier en mémoire :

fichier en mémoire :
    règle-1
    règle-2
    ..

Postfix analyse le résultat comme s'il s'agissait d'un fichier dans /etc/postfix.

Note : si une règle contient $, spécifiez $$ pour empêcher Postfix d'essayer d'effectuer l'expansion $nom lors de l'évaluation d'une valeur de paramètre.

EXEMPLE CARTE ACCES SMTPD

/etc/postfix/main.cf:
    smtpd_client_restrictions = ... cidr:/etc/postfix/client.cidr ...
/etc/postfix/client.cidr:
    # L'ordre des règles est important. Placez les entrées de liste blanche
    # plus spécifiques avant les entrées de liste noire plus générales.
    192.168.1.1             OK
    192.168.0.0/16          REJECT
    2001:db8::1             OK
    2001:db8::/32           REJECT
