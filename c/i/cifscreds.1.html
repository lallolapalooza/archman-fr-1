CIFSCREDS(1) Manuel des commandes générales CIFSCREDS(1)

NOM

cifscreds - gérer les identifiants NTLM dans le trousseau du noyau

SYNTAXE

cifscreds add|clear|clearall|update [-u nom_utilisateur] [-d] hôte|domaine [-t délai]

DESCRIPTION

Le programme cifscreds est un outil permettant de gérer les identifiants (nom d'utilisateur et mot de passe) dans le but d'établir des sessions pour les montages multi-utilisateurs.

Lorsqu'un système de fichiers cifs est monté avec l'option "multiuser" et n'utilise pas l'authentification krb5, il doit être capable d'obtenir les identifiants de chaque utilisateur à partir d'une source. Le programme cifscreds est l'outil utilisé pour fournir ces identifiants au noyau.

Le premier argument sans option de cifscreds est une commande (voir la section COMMANDES ci-dessous). Le second argument sans option est un nom d'hôte ou une adresse, ou un nom de domaine NT.

COMMANDES

add
Ajoute des identifiants au noyau pour être utilisés lors de la connexion au serveur donné, ou aux serveurs du domaine donné.
clear
Supprime les identifiants d'un hôte ou d'un domaine spécifique du noyau.
clearall
Supprime tous les identifiants cifs du noyau.
update
Met à jour les identifiants stockés dans le noyau avec un nouveau nom d'utilisateur et mot de passe.

OPTIONS

-d, --domain
L'argument hôte/domaine fourni est un nom de domaine NT.

Normalement, le deuxième argument fourni à cifscreds est traité comme un nom d'hôte ou une adresse IP. Cette option indique au programme cifscreds de traiter cet argument comme un nom de domaine NT à la place.

S'il n'y a pas d'identifiants spécifiques à l'hôte pour le serveur monté, le noyau recherchera alors un ensemble d'identifiants de domaine équivalents à l'option domain= fournie lors du montage.

-u, --username
Normalement, le nom d'utilisateur est dérivé du nom d'utilisateur Unix de l'utilisateur qui ajoute les identifiants. Cette option permet à l'utilisateur de substituer un nom d'utilisateur différent.
-t, --timeout
Définit le délai d'expiration de la clé en secondes. Si non défini, utilise le délai d'expiration système par défaut pour les clés de connexion.

NOTES

L'utilitaire cifscreds nécessite un noyau compilé avec le support du type de clé login. Ce type de clé a été ajouté dans la version 3.3 des noyaux Linux principaux.

Étant donné que cifscreds ajoute des clés au trousseau de session, il est fortement recommandé d'utiliser pam_keyinit pour s'assurer qu'un trousseau de session est établi lors de la connexion.
