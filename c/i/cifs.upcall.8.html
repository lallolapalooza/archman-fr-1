DESCRIPTIO

N

Cet outil fait partie de la suite

cifs-utils.

cifs.upcall est un programme d'assistance en espace utilisateur pour le système de fichiers client CIFS de Linux. Il existe un certain nombre d'activités que le noyau ne peut pas facilement effectuer lui-même. Ce programme est un programme d'appel qui effectue ces tâches pour le noyau puis renvoie le

résultat.

cifs.upcall est généralement destiné à être exécuté lorsque le noyau appelle request-key(8) pour un type de clé particulier. Bien qu

'il puisse être exécuté directement depuis la ligne de commande,
il n'est généralement pas destiné à être utilisé de cette manière.

--no-env-probe
|-E
Normalement, cifs.upcall interrogera l'espace des variables d'environnement du processus qui a initié l'appel afin de récupérer la valeur de $KRB5CCNAME. Cela peut aider le programme à trouver les caches d'identifiants dans des emplacements non par défaut. Si cette option est définie, le programme ne le fera pas et s'appuiera sur la recherche des caches d'identifiants dans les emplacements par défaut spécifiés dans krb5.conf. Notez que cela n'est jamais effectué lorsque l'uid est 0. L'emplacement par défaut du cache d'identifiants est toujours utilisé lorsque l'uid est 0, quelle que soit la définition de la variable d'environnement dans le
processus.

Cette option permet aux administrateurs de spécifier un fichier keytab à utiliser. Lorsqu'un utilisateur n'a pas encore de cache d'identifiants établi, cifs.upcall essaiera d'utiliser ce keytab pour les acquérir. Le par défaut est le keytab système /etc/krb5.k
eytab.
--trust-dns|
-t
Avec les appels krb5, le nom utilisé comme partie hôte du principal de service est par défaut la partie nom d'hôte du UNC. Cette option permet au programme d'appel de résoudre en inverse l'adresse réseau du serveur afin d'obtenir le nom d'hôte.

C'est moins sûr que de ne pas faire confiance au DNS. Lors de l'utilisation de cette option, il est possible qu'un attaquant prenne le contrôle du DNS et trompe

le client pour qu'il monte complètement un autre serveur. Il est préférable d'ajouter à la place des principaux de serveur au KDC pour chaque nom d'hôte possible,
mais cette option existe pour les cas où cela n'est pas possible. Par défaut, on ne fait pas confiance aux recherches de noms d'hôte inversées de cette manière.
--legacy-uid
|-l
Traditionnellement, le noyau n'a envoyé qu'un seul paramètre uid= à l'appel pour l'appel SPNEGO utilisé pour déterminer quel cache d'identifiants d'utilisateur utiliser. Ce paramètre est affecté par l'option de montage uid=, qui gouverne également la propriété des fichiers sur le montage.

Les noyaux plus récents envoient également une option creduid=, qui contient l'uid qu'ils pensent posséder réellement les identifiants qu'ils recherchent.

Au moment du montage, ceci est généralement défini sur l'uid réel de l'utilisateur effectuant le montage. Pour les montages multisession, il est défini sur
le fsuid de l'utilisateur de montage. Définissez cette option si vous voulez que cifs.upcall utilise l'ancien paramètre uid= au lieu du paramètre creduid=.

CONFIGURATION POUR

KEYCTL

cifs.upcall est conçu pour être appelé depuis le noyau via le programme d'appel request-key. Cela nécessite que request-key soit informé de l'endroit et de la manière d'appeler ce programme. Le programme actuel cifs.upcall gère deux types de clés différents

:
cifs.
spnego
Ce type de clé est destiné à récupérer les clés de session
kerberos
dns_resolv
er
Ce type de clé est destiné à résoudre les noms d'hôte en adresses IP. Le support de ce type de clé sera éventuellement obsolète (voir ci-dessous).

Pour rendre ce programme utile pour CIFS,

vous devrez configurer des entrées pour
elles dans request-key.conf(5). Voici un e
xemple d'entrée pour chaque type de clé : 
#OPERATION  TYPE           D C PROGRAM ARG1 ARG2...
#===
====== ============= = = =============================
=== create cifs.spnego * * /usr/bin/cifs.upcall %
k create dns_resolver * * /usr/bin/cifs.upcall %k

Voir request-key.conf(5) pour plus d'informations sur chaque

champ.

Le paquet keyutils a également commencé à inclure un programme de gestion dns_resolver qui est préféré à celui de cifs.upcall. Si vous utilisez une version de keyutils égale ou supérieure à 1.5, vous devriez utiliser key.dns_resolver pour gérer le type de clé dns_resolver au lieu de cifs.upcall. Voir key.d

ns_resolver(8
) pour plus d'
informations.
