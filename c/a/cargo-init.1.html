cargo-init — Créer un nou

veau paquet Cargo dans u
n répertoire existant

SYNOPSI

S

cargo init [options] [chemi

n
]

DESCRIPTIO

N

Cette commande créera un nouveau manifeste Cargo dans le répertoire courant. Indiquez un chemin en argument pour créer dans le répertoire

indiqué.

S'il existe déjà des fichiers sources Rust aux noms habituels dans le répertoire, ceux-ci seront utilisés. Sinon, un fichier exemple src/main.rs sera créé, ou src/lib.rs si --lib est

passé.

Si le répertoire n'est pas déjà dans un dépôt VCS, un nouveau dépôt est créé (voir --vcs ci-dessous)

.

Voir cargo-new(1) pour une commande similaire qui créer

a un nouveau paquet da
ns un nouveau répertoire.

OPTION

S

Options

d'initialisation

--bi

n
Créer un paquet avec une cible binaire (src/main.rs). C'est le comportement par
défaut.

--li

b
Créer un paquet avec une cible bibliothèque (src/lib.rs)
.

--edition editio

n
Spécifier l'édition Rust à utiliser. La valeur par défaut est 2024. Valeurs possibles : 2015, 2018, 2021,
2024

--name nam

e
Définir le nom du paquet. Par défaut, le nom du
répertoire.

--vcs vc

s
Initialiser un nouveau dépôt VCS pour le système de contrôle de version indiqué (git, hg, pijul ou fossil) ou ne pas initialiser de contrôle de version du tout (none). Si non spécifié, la valeur par défaut est git ou la valeur de configuration cargo-new.vcs, ou none si l'on se trouve déjà dans un dépôt
VCS.

--registry registr

y
Cela définit le champ publish dans Cargo.toml au nom du registre indiqué, ce qui restreindra la publication à ce seul registre.

Les noms de registres sont définis dans les fichiers de configuration de Cargo https://doc.rust-lang.org/cargo/reference/config.html. Si non spécifié, le registre par défaut défini par la clé de configuration registry.default est utilisé. Si le registre par défaut n'est pas défini et que --registry n'est pas utilisé, le champ publish ne sera pas défini, ce qui s

ignifie que la
publication ne se
ra pas restreinte.

Options

d'affichage

-v, --verbos

e
Utiliser une sortie verbeuse. Peut être spécifié deux fois pour une sortie « très verbeuse » incluant des sorties supplémentaires telles que les avertissements de dépendances et la sortie des scripts de build. Peut aussi être spécifié avec la term.verbose valeur de configuration https://doc.rust-lang.org/cargo/refe
rence/config.html.

-q, --quie

t
Ne pas afficher les messages de journal de cargo. Peut aussi être spécifié avec la term.quiet valeur de configuration https://doc.rust-lang.org/cargo/refe
rence/config.html.

--color quan

d
Contrôler quand la sortie colorée est utilisée. Valeurs valides :
•auto (par défaut) : détecter automatiquement si le terminal prend en charge les
couleurs.
•always : toujours afficher les
couleurs.
•never : ne jamais afficher les
couleurs.

Peut aussi être spécifié avec la term.color valeur de configuration https://doc.rust-lang.

org/cargo/
reference/c
onfig.html.

Options

communes

+toolchai

n
Si Cargo a été installé avec rustup, et que le premier argument de cargo commence par +, il sera interprété comme un nom de chaîne d'outils rustup (tel que +stable ou +nightly). Voir la documentation de rustup https://rust-lang.github.io/rustup/overrides.html pour plus d'informations sur le fonctionnement des substitutions de chaîne
d'outils.

--config KEY=VALUE ou PAT

H
Remplace une valeur de configuration de Cargo. L'argument doit être en syntaxe TOML de KEY=VALUE, ou fourni comme chemin vers un fichier de configuration supplémentaire. Cet indicateur peut être spécifié plusieurs fois. Voir la section sur les remplacements en ligne de commande https://doc.rust-lang.org/cargo/reference/config.html#command-line-overrides pour plus
d'informations.

-C PAT

H
Change le répertoire de travail courant avant d'exécuter toute opération spécifiée. Cela affecte des choses telles que l'endroit où cargo cherche par défaut le manifeste du projet (Cargo.toml), ainsi que les répertoires parcourus pour découvrir .cargo/config.toml, par exemple. Cette option doit apparaître avant le nom de la commande, par exemple cargo -C chemin/vers/mon-projet build.

Cette option n'est disponible que sur le canal nightly https://doc.rust-lang.org/book/appendix-07-nightly-rust.html et nécessite l'indicateur -Z unstable-options pour être activée (voir #10098 https://github.com/rust-

lang/cargo/is
sues/10098).

-h, --hel

p
Affiche les informations
d'aide.

-Z fla

g
Indicateurs instables (réservés à nightly) pour Cargo. Exécuter cargo -Z help
pour p
lus de d
étails.
