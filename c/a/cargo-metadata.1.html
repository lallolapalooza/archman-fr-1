DESCRIPTIO

N

Affiche sur la sortie standard du JSON contenant des informations sur les membres de l'espace de travail et les dépendances résolues du paquet

courant.

Le format de sortie est susceptible de changer dans les futures versions de Cargo. Il est recommandé d'inclure l'indicateur --format-version pour rendre votre code résistant aux changements futurs et garantir que la sortie correspond au format attendu. Pour plus d'informations sur les attentes, voir « Compatibilité »

.

Voir la crate cargo_metadata https://crates.io/crates/cargo_metadata pour une

API Rust permettant de l
ire les métadonnées.

SORTIE

Compatibilit

é

Au sein de la même version de format de sortie, la compatibilité est maintenue, à quelques exceptions près. La liste suivante n'est pas exhaustive des changements qui ne sont pas considérés comme incompatibles

:
•Ajout de nouveaux champs — De nouveaux champs seront ajoutés selon les besoins. Cette réserve permet à Cargo d'évoluer sans augmenter trop souvent la version du
format.
•Ajout de nouvelles valeurs pour les champs de type énumération — Comme pour l'ajout de nouveaux champs. Cela permet aux métadonnées d'évoluer sans
stagner.
•Changement de représentations opaques — Les représentations internes de certains champs sont des détails d'implémentation. Par exemple, les champs liés au « Source ID » sont tr
aités comme des identifiants opaques pour différencier les paquets ou les sources. Les co
nsommateurs ne doivent pas s'appuyer sur ces représentations, sauf indication contraire.

--locked

Affirme que les mêmes dépendances et versions exactes sont utilisées que lors de la génération du fichier Cargo.lock existant. Cargo se terminera par une erreur lorsque l'un des scénarios suivants se présentera :
•Le fichier de verrouillage est manquant.
•Cargo a tenté de modifier le fichier de verrouillage en raison d'une résolution de dépendance différente.

Il peut être utilisé dans des environnements où des builds déterministes sont souhaités, comme dans les pipelines CI.

--offline

Empêche Cargo d'accéder au réseau pour quelque raison que ce soit. Sans ce drapeau, Cargo s'arrêtera avec une erreur s'il a besoin d'accéder au réseau et que le réseau n'est pas disponible. Avec ce drapeau, Cargo tentera de continuer sans le réseau si possible.

Attention, cela peut entraîner une résolution de dépendances différente de celle du mode en ligne. Cargo se limitera aux crates qui sont téléchargés localement, même s'il existe une version plus récente indiquée dans la copie locale de l'index. Voir la commande cargo-fetch(1) pour télécharger les dépendances avant de passer hors ligne.

Peut également être spécifié avec la valeur de configuration net.offline https://doc.rust-lang.org/cargo/reference/config.html.

--frozen

Équivalent à spécifier à la fois --locked et --offline.

--lockfile-path PATH

Modifie le chemin du fichier de verrouillage du chemin par défaut (<workspace_root>/Cargo.lock) à PATH. PATH doit se terminer par Cargo.lock (par exemple, --lockfile-path /tmp/temporary-lockfile/Cargo.lock). Notez que la fourniture de --lockfile-path ignorera le fichier de verrouillage existant au chemin par défaut, et utilisera à la place le fichier de verrouillage de PATH, ou écrira un nouveau fichier de verrouillage dans le PATH fourni s'il n'existe pas. Ce drapeau peut être utilisé pour exécuter la plupart des commandes dans des répertoires en lecture seule, en écrivant le fichier de verrouillage dans le PATH fourni.

Cette option n'est disponible que sur le canal nightly https://doc.rust-lang.org/book/appendix-07-nightly-rust.html et nécessite le drapeau -Z unstable-options pour être activé (voir #14421 https://github.com/rust-lang/cargo/issues/14421).

Options communes

+toolchain

Si Cargo a été installé avec rustup, et que le premier argument de cargo commence par +, il sera interprété comme un nom de toolchain rustup (tel que +stable ou +nightly). Voir la documentation rustup https://rust-lang.github.io/rustup/overrides.html pour plus d'informations sur le fonctionnement des remplacements de toolchain.

--config KEY=VALUE ou PATH

Remplace une valeur de configuration Cargo. L'argument doit être dans la syntaxe TOML de KEY=VALUE, ou fourni comme chemin vers un fichier de configuration supplémentaire. Ce drapeau peut être spécifié plusieurs fois. Voir la section des remplacements en ligne de commande https://doc.rust-lang.org/cargo/reference/config.html#command-line-overrides pour plus d'informations.

-C PATH

Change le répertoire de travail actuel avant d'exécuter toute opération spécifiée. Cela affecte, par exemple, où cargo recherche par défaut le manifeste du projet (Cargo.toml), ainsi que les répertoires recherchés pour découvrir .cargo/config.toml. Cette option doit apparaître avant le nom de la commande, par exemple cargo -C path/to/my-project build.

Cette option n'est disponible que sur le canal nightly https://doc.rust-lang.org/book/appendix-07-nightly-rust.html et nécessite le drapeau -Z unstable-options pour être activé (voir #10098 https://github.com/rust-lang/cargo/issues/10098).

-h, --help

Affiche l'aide.

-Z flag

Drapeaux instables (uniquement nightly) pour Cargo. Exécutez cargo -Z help pour plus de détails.
