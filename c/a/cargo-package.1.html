NOM

cargo-package — Assemble le paquet local dans une archive distribuable

SYNTAXE

cargo package [options]

DESCRIPTION

Cette commande créera un fichier .crate distribuable et compressé avec le code source du paquet dans le répertoire courant. Le fichier résultant sera stocké dans le répertoire target/package. Cela effectue les étapes suivantes :

1. Charge et vérifie l'espace de travail courant, en effectuant quelques vérifications de base.
•Les dépendances par chemin ne sont pas autorisées à moins qu'elles n'aient une clé de version. Cargo ignorera la clé de chemin pour les dépendances dans les paquets publiés. Les dev-dependencies n'ont pas cette restriction.
2. Crée le fichier .crate compressé.
•Le fichier Cargo.toml original est réécrit et normalisé.
•Les sections [patch], [replace] et [workspace] sont supprimées du manifeste.
•Cargo.lock est toujours inclus. En cas d'absence, un nouveau fichier de verrouillage sera généré à moins que le drapeau --exclude-lockfile ne soit utilisé. cargo-install(1) utilisera le fichier de verrouillage empaqueté si le drapeau --locked est utilisé.
•Un fichier .cargo_vcs_info.json est inclus, contenant des informations sur le hash du checkout VCS actuel si disponible, ainsi qu'un indicateur si le répertoire de travail est modifié.
•Les liens symboliques sont réduits à leurs fichiers cibles.
•Les fichiers et répertoires sont inclus ou exclus en fonction des règles mentionnées dans les champs [include] et [exclude] https://doc.rust-lang.org/cargo/reference/manifest.html#the-exclude-and-include-fields.
3. Extrait le fichier .crate et le construit pour vérifier qu'il peut être compilé.
•Cela reconstruira votre paquet à partir de zéro pour s'assurer qu'il peut être construit à partir d'un état vierge. Le drapeau --no-verify peut être utilisé pour sauter cette étape.
4. Vérifie que les scripts de construction n'ont modifié aucun fichier source.

La liste des fichiers inclus peut être contrôlée avec les champs include et exclude dans le manifeste.

Voir la référence https://doc.rust-lang.org/cargo/reference/publishing.html pour plus de détails sur l'empaquetage et la publication.

Format de .cargo_vcs_info.json

Génère un fichier .cargo_vcs_info.json dans le format suivant :

{
 "git": {
   "sha1": "aac20b6e7e543e6dd4118b246c77225e3a3a1302",
   "dirty": true
 },
 "path_in_vcs": ""
}

dirty indique que le répertoire de travail Git était modifié lorsque le paquet a été construit.

path_in_vcs sera défini sur un chemin relatif au dépôt pour les paquets dans des sous-répertoires du dépôt de contrôle de version.

La compatibilité de ce fichier est maintenue sous la même politique que la sortie JSON de cargo-metadata(1).

Notez que ce fichier fournit un aperçu des informations VCS fait de son mieux. Cependant, la provenance du paquet n'est pas vérifiée. Il n'y a aucune garantie que le code source dans l'archive corresponde aux informations VCS.

OPTIONS

Options de paquet

-l, --list

Affiche les fichiers inclus dans un paquet sans en créer un.

--no-verify

Ne vérifie pas le contenu en le construisant.

--no-metadata

Ignore les avertissements concernant le manque de métadonnées exploitables par l'homme (comme la description ou la licence).

--allow-dirty

Permet d'empaqueter des répertoires de travail avec des modifications VCS non commitées.

--exclude-lockfile

N'inclut pas le fichier de verrouillage lors de l'empaquetage.

Ce drapeau n'est pas pour une utilisation générale. Certains outils peuvent s'attendre à ce qu'un fichier de verrouillage soit présent (par ex. cargo install --locked). Envisagez d'autres options avant d'utiliser celui-ci.

--index index

L'URL de l'index du registre à utiliser.

--registry registry

Nom du registre pour lequel empaqueter ; voir cargo publish --help pour plus de détails sur la configuration des noms de registres. Les paquets ne seront pas publiés sur ce registre, mais si nous empaquetons plusieurs crates interdépendants, les fichiers de verrouillage seront générés en supposant que les dépendances seront publiées sur ce registre.

--message-format fmt

Spécifie le format des messages de sortie. Actuellement, cela ne fonctionne qu'avec --list et affecte le format de la liste des fichiers. Ceci est instable et nécessite -Zunstable-options. Formats de sortie valides :
•human (défaut) : Affiche en format fichier par ligne.
•json : Émet des informations lisibles par machine au format JSON pour chaque paquet. Un paquet par ligne JSON (JSON délimité par des sauts de ligne). 
{
  /* Le spécificateur d'ID du paquet. */
  "id": "path+file:///home/foo#0.0.0",
  /* Fichiers de ce paquet */
  "files" {
    /* Chemin relatif dans l'archive. */
    "Cargo.toml.orig": {
      /* D'où vient le fichier.
         - "generate" pour les fichiers générés pendant l'empaquetage
         - "copy" pour les fichiers copiés depuis un autre emplacement.
      */
      "kind": "copy",
      /* Pour le genre "copy",
         c'est un chemin absolu vers le contenu réel du fichier.
         Pour le genre "generate",
         c'est le fichier original sur lequel le fichier généré est basé.
      */
      "path": "/home/foo/Cargo.toml"
    },
    "Cargo.toml": {
      "kind": "generate",
      "path": "/home/foo/Cargo.toml"
    },
    "src/main.rs": {
      "kind": "copy",
      "path": "/home/foo/src/main.rs"
    }
  }
}

Sélection de paquet

Par défaut, lorsqu'aucune option de sélection de paquet n'est donnée, les paquets sélectionnés dépendent du fichier manifeste sélectionné (basé sur le répertoire de travail courant si --manifest-path n'est pas donné). Si le manifeste est la racine d'un espace de travail, alors les membres par défaut de l'espace de travail sont sélectionnés, sinon seul le paquet défini par le manifeste sera sélectionné.

Les membres par défaut d'un espace de travail peuvent être définis explicitement avec la clé workspace.default-members dans le manifeste racine. Si cela n'est pas défini, un espace de travail virtuel inclura tous les membres de l'espace de travail (équivalent à passer --workspace), et un espace de travail non virtuel n'inclura que le crate racine lui-même.

-p spec…, --package spec…

Empaquette uniquement les paquets spécifiés. Voir cargo-pkgid(1) pour le format SPEC. Ce drapeau peut être spécifié plusieurs fois et prend en charge les motifs glob Unix courants comme *, ? et []. Cependant, pour éviter que votre shell n'étende accidentellement les motifs glob avant que Cargo ne les traite, vous devez utiliser des guillemets simples ou doubles autour de chaque motif.

--workspace

Empaquette tous les membres de l'espace de travail.

--exclude SPEC…

Exclut les paquets spécifiés. Doit être utilisé en conjonction avec le drapeau --workspace. Ce drapeau peut être spécifié plusieurs fois et prend en charge les motifs glob Unix courants comme *, ? et []. Cependant, pour éviter que votre shell n'étende accidentellement les motifs glob avant que Cargo ne les traite, vous devez utiliser des guillemets simples ou doubles autour de chaque motif.

NAME

cargo-package - Crée un fichier .crate compressé du paquet actuel

SYNOPSIS

cargo package [options]

DESCRIPTION

La commande cargo package construit le paquet actuel et le compresse dans un fichier .crate. Ce fichier est le format utilisé pour publier des paquets sur crates.io. Les fichiers .crate sont des archives tgz contenant le code source du paquet, des métadonnées, et des binaires précompilés s'ils existent.

Ce processus est également effectué automatiquement avant qu'une publication sur crates.io soit effectuée par cargo publish. Vous pouvez utiliser cargo package pour vérifier que votre paquet est prêt à être publié sans réellement le publier.

OPTIONS

La commande cargo package prend en charge la plupart des options communes de Cargo, telles que --verbose, --quiet, --manifest-path, etc. Voir cargo(1) pour une liste complète.

Il existe également quelques options spécifiques à cargo package :

-v, --verbose
Utilise une sortie plus verbeuse. N'est pas une option spécifique à cargo package.
--list
Affiche les fichiers qui seraient inclus dans le paquet sans le construire.
--no-verify
Ne vérifie pas le paquet après sa création.
--allow-dirty
Autorise la création d'un paquet même si le dépôt de contrôle de version n'est pas propre. Par défaut, Cargo refusera de construire un paquet si le répertoire de travail n'est pas propre (c'est-à-dire qu'il y a des modifications non commitées ou non suivies).

ENVIRONMENT

Voir la section ENVIRONNEMENT de cargo(1) pour plus d'informations.

EXIT STATUS

0 en cas de succès, supérieur à 0 en cas d'échec.

EXAMPLES

1.Crée un fichier .crate compressé du paquet actuel : 
cargo package
