CATOPEN(3P) Manuel du programmeur POSIX CATOPEN(3P)

PROLOGUE

Cette page de manuel fait partie du Manuel du programmeur POSIX. L'implémentation Linux de cette interface peut différer (consultez la page de manuel Linux correspondante pour les détails du comportement sous Linux), ou l'interface peut ne pas être implémentée sous Linux.

NOM

catopen — ouvrir un catalogue de messages

SYNTAXE

#include <nl_types.h>
nl_catd catopen(const char *name, int oflag);

DESCRIPTION

La fonction catopen() ouvre un catalogue de messages et retourne un descripteur de catalogue de messages. L'argument name spécifie le nom du catalogue de messages à ouvrir. Si name contient un '/', alors name spécifie un chemin d'accès pour le catalogue de messages. Sinon, la variable d'environnement NLSPATH est utilisée avec name substitué à la spécification de conversion %N (voir le volume Définitions de base de POSIX.1‐2017, Chapitre 8, Variables d'environnement); si NLSPATH existe dans l'environnement lorsque le processus démarre, alors si le processus possède les privilèges appropriés, le comportement de catopen() est indéfini. Si NLSPATH n'existe pas dans l'environnement, ou si un catalogue de messages ne peut être trouvé dans aucun des composants spécifiés par NLSPATH, alors un chemin par défaut défini par l'implémentation sera utilisé. Ceci peut être affecté par le réglage de LC_MESSAGES si la valeur de oflag est NL_CAT_LOCALE, ou la variable d'environnement LANG si oflag est 0.

Un descripteur de catalogue de messages reste valide dans un processus jusqu'à ce que ce processus le ferme, ou qu'un appel réussi à l'une des fonctions exec. Un changement dans le réglage de la catégorie LC_MESSAGES peut invalider les catalogues ouverts existants.

Si un descripteur de fichier est utilisé pour implémenter les descripteurs de catalogue de messages, l'indicateur FD_CLOEXEC sera défini ; voir <fcntl.h>.

Si la valeur de l'argument oflag est 0, la variable d'environnement LANG est utilisée pour localiser le catalogue sans tenir compte de la catégorie LC_MESSAGES. Si l'argument oflag est NL_CAT_LOCALE, la catégorie LC_MESSAGES est utilisée pour localiser le catalogue de messages (voir le volume Définitions de base de POSIX.1‐2017, Section 8.2, Variables d'internationalisation).

VALEUR DE RETOUR

En cas de succès, catopen() retourne un descripteur de catalogue de messages à utiliser lors des appels ultérieurs à catgets() et catclose(). Sinon, catopen() retourne (nl_catd) -1 et définit errno pour indiquer l'erreur.

ERREURS

La fonction catopen() peut échouer si :

EACCES
L'autorisation de recherche est refusée pour le composant du préfixe de chemin du catalogue de messages ou l'autorisation de lecture est refusée pour le catalogue de messages.
EMFILE
Tous les descripteurs de fichiers disponibles pour le processus sont actuellement ouverts.
ENAMETOOLONG

La longueur d'un composant d'un nom de chemin est supérieure à {NAME_MAX}.
ENAMETOOLONG

La longueur d'un nom de chemin dépasse {PATH_MAX}, ou la résolution du nom de chemin d'un lien symbolique a produit un résultat intermédiaire dont la longueur dépasse {PATH_MAX}.
ENFILE
Trop de fichiers sont actuellement ouverts dans le système.
ENOENT
Le catalogue de messages n'existe pas ou l'argument name pointe vers une chaîne vide.
ENOMEM
Espace de stockage insuffisant disponible.
ENOTDIR
Un composant du préfixe de chemin du catalogue de messages nomme un fichier existant qui n'est ni un répertoire ni un lien symbolique vers un répertoire, ou le nom de chemin du catalogue de messages contient au moins un caractère non-<slash> et se termine par un ou plusieurs <slash> finaux et le dernier composant du nom de chemin nomme un fichier existant qui n'est ni un répertoire ni un lien symbolique vers un répertoire.

EXEMPLES

UTILISATION PAR APPLICATION

Certaines implémentations de catopen() utilisent malloc() pour allouer de l'espace pour des zones tampons internes. La fonction catopen() peut échouer s'il n'y a pas suffisamment d'espace de stockage disponible pour ces tampons.

Les applications conformes doivent supposer que les descripteurs de catalogue de messages ne sont pas valides après un appel à l'une des fonctions exec.

Les développeurs d'applications doivent être conscients que des directives pour l'emplacement des catalogues de messages n'ont pas encore été élaborées. Par conséquent, ils doivent veiller à éviter les conflits avec les catalogues utilisés par d'autres applications et les utilitaires standard.

Pour s'assurer que les messages produits par une application fonctionnant avec des privilèges appropriés ne peuvent pas être utilisés par un attaquant définissant une valeur inattendue pour NLSPATH dans l'environnement pour tromper un administrateur système, de telles applications devraient utiliser des chemins contenant un '/' pour obtenir un comportement défini lors de l'utilisation de catopen() pour ouvrir un catalogue de messages.
