CANONICAL(5) Manuel des formats de fichiers CANONICAL(5)

NOM

canonical - Format de la table canonique Postfix

SYNOPSIS

postmap /etc/postfix/canonical
postmap -q "chaîne" /etc/postfix/canonical
postmap -q - /etc/postfix/canonical <fichier_entrée

DESCRIPTION


La table optionnelle canonical(5) spécifie un mappage d'adresses pour les adresses locales et non locales. Le mappage est utilisé par le démon cleanup(8), avant que le courrier ne soit stocké dans la file d'attente. Le mappage d'adresses est récursif.

Normalement, la table canonical(5) est spécifiée sous forme de fichier texte servant d'entrée à la commande postmap(1). Le résultat, un fichier indexé au format dbm ou db, est utilisé pour une recherche rapide par le système de messagerie. Exécutez la commande "postmap /etc/postfix/canonical" pour reconstruire un fichier indexé après avoir modifié le fichier texte correspondant.

Lorsque la table est fournie par d'autres moyens tels que NIS, LDAP ou SQL, les mêmes recherches sont effectuées que pour les fichiers indexés ordinaires.

Alternativement, la table peut être fournie sous forme de table d'expressions régulières où les motifs sont donnés sous forme d'expressions régulières, ou les recherches peuvent être dirigées vers un serveur basé sur TCP. Dans ces cas, les recherches sont effectuées d'une manière légèrement différente, comme décrit ci-dessous sous "TABLES D'EXPRESSIONS RÉGULIÈRES" ou "TABLES BASÉES SUR TCP".

Par défaut, le mappage canonical(5) affecte à la fois les adresses d'en-tête de message (c'est-à-dire les adresses qui apparaissent à l'intérieur des messages) et les adresses d'enveloppe de message (par exemple, les adresses utilisées dans les commandes du protocole SMTP). Ceci est contrôlé par le paramètre canonical_classes.

NOTE : Les versions de Postfix 2.2 et ultérieures réécrivent les en-têtes de message provenant des clients SMTP distants uniquement si le client correspond au paramètre local_header_rewrite_clients, ou si le paramètre de configuration remote_header_rewrite_domain spécifie une valeur non vide. Pour obtenir le comportement d'avant Postfix 2.2, spécifiez "local_header_rewrite_clients = static:all".

Généralement, on utiliserait la table canonical(5) pour remplacer les noms de connexion par Prénom.Nom, ou pour nettoyer les adresses produites par des systèmes de messagerie obsolètes.

Le mappage canonical(5) ne doit pas être confondu avec le support des alias virtuels ou avec les alias locaux. Pour changer la destination mais pas les en-têtes, utilisez plutôt la table virtual(5) ou aliases(5).

PLIAGE DE CAS

La chaîne de recherche est pliée en minuscules avant la recherche dans la base de données. Depuis Postfix 2.3, la chaîne de recherche n'est pas pliée en minuscules avec les types de base de données tels que regexp: ou pcre: dont les champs de recherche peuvent correspondre aux lettres majuscules et minuscules.

FORMAT DE TABLE

Le format d'entrée pour la commande postmap(1) est le suivant :

motif adresse
Lorsque motif correspond à une adresse de messagerie, remplacez-la par l'adresse correspondante.
lignes vides et commentaires
Les lignes vides et les lignes ne contenant que des espaces sont ignorées, tout comme les lignes dont le premier caractère non-espace est un `#'.
texte multiligne
Une ligne logique commence par du texte non-espace. Une ligne qui commence par des espaces continue une ligne logique.

ORDRE DE RECHERCHE DE TABLE

Avec les recherches dans des fichiers indexés tels que DB ou DBM, ou à partir de tables réseau telles que NIS, LDAP ou SQL, chaque requête utilisateur@domaine produit une séquence de motifs de requête comme décrit ci-dessous.

Chaque motif de requête est envoyé à chaque table de recherche spécifiée avant d'essayer le motif de requête suivant, jusqu'à ce qu'une correspondance soit trouvée.

utilisateur@domaine adresse
Remplacez utilisateur@domaine par adresse. Cette forme a la plus haute priorité.

Ceci est utile pour nettoyer les adresses produites par des systèmes de messagerie obsolètes. Cela peut également être utilisé pour produire des adresses de style Prénom.Nom, mais voyez ci-dessous pour une solution plus simple.

utilisateur adresse
Remplacez utilisateur@site par adresse lorsque site est égal à $myorigin, lorsque site est listé dans $mydestination, ou lorsqu'il est listé dans $inet_interfaces ou $proxy_interfaces.

Cette forme est utile pour remplacer les noms de connexion par Prénom.Nom.

@domaine adresse
Remplacez les autres adresses dans domaine par adresse. Cette forme a la plus basse priorité.

Remarque : @domaine est un caractère générique. Lorsque cette forme est appliquée aux adresses de destinataires, le serveur SMTP de Postfix accepte le courrier pour n'importe quel destinataire dans domaine, indépendamment de l'existence de ce destinataire. Cela peut transformer votre système de messagerie en une source de backscatter : Postfix accepte d'abord le courrier pour des destinataires inexistants, puis tente de renvoyer ce courrier comme "non distribuable" à l'adresse de l'expéditeur souvent falsifiée.

Pour éviter le backscatter avec le courrier d'un domaine générique, remplacez le mappage générique par des mappages explicites 1:1, ou ajoutez une restriction reject_unverified_recipient pour ce domaine :

    smtpd_recipient_restrictions =
        ...
        reject_unauth_destination
        check_recipient_access
            inline:{example.com=reject_unverified_recipient}
    unverified_recipient_reject_code = 550

Dans l'exemple ci-dessus, Postfix peut contacter un serveur distant si le destinataire est réécrit vers une adresse distante.

REECRITURE D'ADRESSE DE RÉSULTAT

Le résultat de la recherche est soumis à une réécriture d'adresse :

  • Lorsque le résultat a la forme @autre-domaine, le résultat devient le même utilisateur dans autre-domaine.
  • Lorsque "append_at_myorigin=yes", ajoutez "@$myorigin" aux adresses sans "@domaine".
  • Lorsque "append_dot_mydomain=yes", ajoutez ".$mydomain" aux adresses sans ".domaine".

EXTENSION D'ADRESSE

Lorsque le localpart d'une adresse de messagerie contient le délimiteur de destinataire optionnel (par exemple, utilisateur+foo@domaine), l'ordre de recherche devient : utilisateur+foo@domaine, utilisateur@domaine, utilisateur+foo, utilisateur, et @domaine.

Le paramètre propagate_unmatched_extensions contrôle si une extension d'adresse non appariée (+foo) est propagée au résultat de la recherche de table.

TABLES D'EXPRESSIONS RÉGULIÈRES

Cette section décrit comment les recherches de table changent lorsque la table est fournie sous forme d'expressions régulières. Pour une description de la syntaxe des tables de recherche d'expressions régulières, voir regexp_table(5) ou pcre_table(5).

Chaque motif est une expression régulière appliquée à l'adresse entière faisant l'objet de la recherche. Ainsi, les adresses de messagerie utilisateur@domaine ne sont pas décomposées en leurs parties utilisateur et @domaine constituantes, pas plus que utilisateur+foo n'est décomposé en utilisateur et foo.

Les motifs sont appliqués dans l'ordre spécifié dans la table, jusqu'à ce qu'un motif soit trouvé qui corresponde à la chaîne de recherche.

Les résultats sont les mêmes qu'avec les recherches de fichiers indexés, avec la fonction supplémentaire que les sous-chaînes entre parenthèses du motif peuvent être interpolées sous forme de $1, $2 et ainsi de suite.

TABLES BASÉES SUR TCP

Cette section décrit comment les recherches de table changent lorsque les recherches sont dirigées vers un serveur basé sur TCP. Pour une description du protocole de recherche client/serveur TCP, voir tcp_ta

ble(5). Cette fonctionnalité n'est pas disponible jusqu'à et y compris la version 2.4 de Postfix.

Chaque opération de recherche utilise l'adresse entière une fois. Ainsi, user@domain les adresses de courrier ne sont pas divisées en leurs parties constituantes et @domain , et user+foo n'est pas divisé en user et foo.

Les résultats sont les mêmes qu'avec les recherches dans des fichiers indexés.

BOGUES


Le format de table ne comprend pas les conventions de guillemets.

PARAMÈTRES DE CONFIGURATION

Les paramètres suivants de main.cf sont particulièrement pertinents. Le texte ci-dessous fournit seulement un résumé des paramètres. Voir postconf(5) pour plus de détails, y compris des exemples.

canonical_classes (envelope_sender, envelope_recipient, header_sender, header_recipient)
Quelles adresses sont soumises au mappage d'adresses canonical_maps.
canonical_maps (vide)
Tables de recherche de mappage d'adresses facultatives pour les en-têtes et les enveloppes des messages.
recipient_canonical_maps (vide)
Tables de recherche de mappage d'adresses facultatives pour les adresses des destinataires des enveloppes et des en-têtes.
sender_canonical_maps (vide)
Tables de recherche de mappage d'adresses facultatives pour les adresses des expéditeurs des enveloppes et des en-têtes.
propagate_unmatched_extensions (canonical, virtual)
Quelles tables de recherche d'adresses copient une extension d'adresse de la clé de recherche vers le résultat de la recherche.

Autres paramètres d'intérêt :

inet_interfaces (all)
Les adresses des interfaces réseau locales sur lesquelles ce système de messagerie reçoit le courrier.
local_header_rewrite_clients (permit_inet_interfaces)
Réécrire ou ajouter des en-têtes de message dans le courrier provenant de ces clients, en complétant les adresses incomplètes avec le nom de domaine dans $myorigin ou $mydomain, et en ajoutant les en-têtes manquants.
proxy_interfaces (vide)
Les adresses des interfaces réseau distantes sur lesquelles ce système de messagerie reçoit le courrier par l'intermédiaire d'un proxy ou d'une unité de traduction d'adresses réseau.
masquerade_classes (envelope_sender, header_sender, header_recipient)
Quelles adresses sont soumises au déguisement d'adresses (masquerading).
masquerade_domains (vide)
Liste facultative de domaines dont la structure de sous-domaine sera supprimée dans les adresses de courrier électronique.
masquerade_exceptions (vide)
Liste facultative de noms d'utilisateurs qui ne sont pas soumis au déguisement d'adresses, même lorsque leurs adresses correspondent à $masquerade_domains.
mydestination ($myhostname, localhost.$mydomain, localhost)
La liste des domaines qui sont livrés via le mécanisme de livraison de courrier $local_transport.
myorigin ($myhostname)
Le nom de domaine d'où semble provenir le courrier posté localement, et vers lequel le courrier posté localement est livré.
owner_request_special (yes)
Activer le traitement spécial des entrées owner-listname dans le fichier aliases(5) , et ne pas diviser les parties locales des adresses owner-listname et listname-request lorsque le recipient_delimiter est défini sur "-".
remote_header_rewrite_domain (vide)
Réécrire ou ajouter des en-têtes de message dans le courrier provenant de clients distants si la valeur du paramètre remote_header_rewrite_domain n'est pas vide, en complétant les adresses incomplètes avec le domaine spécifié dans le paramètre remote_header_rewrite_domain, et en ajoutant les en-têtes manquants.
