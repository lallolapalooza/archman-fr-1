CARGO-REMOVE(1) Manuel des commandes générales CARGO-REMOVE(1)

NOM

cargo-remove — Supprime des dépendances d'un fichier manifeste Cargo.toml

SYNTAXE

cargo remove [options] dépendance…

DESCRIPTION

Supprime une ou plusieurs dépendances d'un manifeste Cargo.toml.

OPTIONS

Options de section

--dev

Supprime en tant que dépendance de développement https://doc.rust-lang.org/cargo/reference/specifying-dependencies.html#development-dependencies.

--build

Supprime en tant que dépendance de compilation https://doc.rust-lang.org/cargo/reference/specifying-dependencies.html#build-dependencies.

--target cible

Supprime en tant que dépendance pour la plateforme cible donnée https://doc.rust-lang.org/cargo/reference/specifying-dependencies.html#platform-specific-dependencies.

Pour éviter les expansions de shell inattendues, vous pouvez utiliser des guillemets autour de chaque cible, par exemple, --target 'cfg(unix)'.

Options diverses

--dry-run

N'écrit pas réellement dans le manifeste.

Options d'affichage

-v, --verbose

Utilise une sortie verbeuse. Peut être spécifié deux fois pour une sortie “très verbeuse” qui inclut des informations supplémentaires telles que des avertissements de dépendance et la sortie des scripts de compilation. Peut aussi être spécifié avec la valeur de configuration term.verbose https://doc.rust-lang.org/cargo/reference/config.html.

-q, --quiet

N'imprime pas les messages de journalisation de cargo. Peut aussi être spécifié avec la valeur de configuration term.quiet https://doc.rust-lang.org/cargo/reference/config.html.

--color quand

Contrôle quand la sortie colorée est utilisée. Valeurs valides :
•auto (par défaut) : Détecte automatiquement si le support de la couleur est disponible sur le terminal.
•always : Affiche toujours les couleurs.
•never : N'affiche jamais les couleurs.

Peut aussi être spécifié avec la valeur de configuration term.color https://doc.rust-lang.org/cargo/reference/config.html.

Options de manifeste

--manifest-path chemin

Chemin vers le fichier Cargo.toml. Par défaut, Cargo recherche le fichier Cargo.toml dans le répertoire courant ou dans tout répertoire parent.

--locked

Affirme que les mêmes dépendances et versions exactes sont utilisées que lors de la génération originale du fichier Cargo.lock existant. Cargo se terminera avec une erreur dans les cas suivants :
•Le fichier de verrouillage est manquant.
•Cargo a tenté de modifier le fichier de verrouillage en raison d'une résolution de dépendance différente.

Il peut être utilisé dans des environnements où des builds déterministes sont souhaités, comme dans les pipelines CI.

--offline

Empêche Cargo d'accéder au réseau pour quelque raison que ce soit. Sans ce drapeau, Cargo s'arrêtera avec une erreur s'il a besoin d'accéder au réseau et que celui-ci n'est pas disponible. Avec ce drapeau, Cargo tentera de continuer sans le réseau si possible.

Attention, cela peut entraîner une résolution de dépendances différente de celle du mode en ligne. Cargo se limitera aux crates qui sont téléchargés localement, même s'il existe peut-être une version plus récente comme indiqué dans la copie locale de l'index. Voir la commande cargo-fetch(1) pour télécharger les dépendances avant de passer hors ligne.

Peut aussi être spécifié avec la valeur de configuration net.offline https://doc.rust-lang.org/cargo/reference/config.html.

--frozen

Équivalent à spécifier à la fois --locked et --offline.

--lockfile-path CHEMIN

Modifie le chemin du fichier de verrouillage par défaut (<workspace_root>/Cargo.lock) pour qu'il soit CHEMIN. CHEMIN doit se terminer par Cargo.lock (par exemple, --lockfile-path /tmp/temporary-lockfile/Cargo.lock). Notez que la fourniture de --lockfile-path ignorera le fichier de verrouillage existant au chemin par défaut, et utilisera à la place le fichier de verrouillage de CHEMIN, ou écrira un nouveau fichier de verrouillage dans le CHEMIN fourni s'il n'existe pas. Ce drapeau peut être utilisé pour exécuter la plupart des commandes dans des répertoires en lecture seule, en écrivant le fichier de verrouillage dans le CHEMIN fourni.

Cette option n'est disponible que sur le canal nightly https://doc.rust-lang.org/book/appendix-07-nightly-rust.html et nécessite le drapeau -Z unstable-options pour être activé (voir #14421 https://github.com/rust-lang/cargo/issues/14421).

Sélection de paquet

-p spécification…, --package spécification…

Paquet à supprimer.

Options communes

+toolchain

Si Cargo a été installé avec rustup, et que le premier argument de cargo commence par +, il sera interprété comme un nom de toolchain rustup (tel que +stable ou +nightly). Voir la documentation rustup https://rust-lang.github.io/rustup/overrides.html pour plus d'informations sur le fonctionnement des substitutions de toolchain.

--config CLÉ=VALEUR ou CHEMIN

Remplace une valeur de configuration Cargo. L'argument doit être au format TOML CLÉ=VALEUR, ou fourni comme chemin vers un fichier de configuration supplémentaire. Ce drapeau peut être spécifié plusieurs fois. Voir la section des substitutions en ligne de commande https://doc.rust-lang.org/cargo/reference/config.html#command-line-overrides pour plus d'informations.

-C CHEMIN

Change le répertoire de travail courant avant d'exécuter les opérations spécifiées. Cela affecte où cargo recherche par défaut le manifeste du projet (Cargo.toml), ainsi que les répertoires recherchés pour découvrir .cargo/config.toml, par exemple. Cette option doit apparaître avant le nom de la commande, par exemple cargo -C chemin/vers/mon-projet build.

Cette option n'est disponible que sur le canal nightly https://doc.rust-lang.org/book/appendix-07-nightly-rust.html et nécessite le drapeau -Z unstable-options pour être activé (voir #10098 https://github.com/rust-lang/cargo/issues/10098).

-h, --help

Affiche les informations d'aide.

-Z drapeau

Drapeaux instables (réservés à la nightly) pour Cargo. Exécutez cargo -Z help pour plus de détails.

ENVIRONNEMENT

Voir la référence https://doc.rust-lang.org/cargo/reference/environment-variables.html pour les détails sur les variables d'environnement que Cargo lit.
