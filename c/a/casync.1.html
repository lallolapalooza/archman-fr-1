NOM

casync - Documentation de casync

SYNTAXE

casync [OPTIONS...] make [ARCHIVE | ARCHIVE_INDEX | BLOB_INDEX] [PATH]
casync [OPTIONS...] extract [ARCHIVE | ARCHIVE_INDEX | BLOB_INDEX] [PATH]
casync [OPTIONS...] list [ARCHIVE | ARCHIVE_INDEX | DIRECTORY] [PATH]
casync [OPTIONS...] mtree [ARCHIVE | ARCHIVE_INDEX | DIRECTORY] [PATH]
casync [OPTIONS...] stat [ARCHIVE | ARCHIVE_INDEX | DIRECTORY] [PATH]
casync [OPTIONS...] digest [ARCHIVE | BLOB | ARCHIVE_INDEX | BLOB_INDEX | DIRECTORY] [PATH]
casync [OPTIONS...] mount [ARCHIVE | ARCHIVE_INDEX] PATH
casync [OPTIONS...] mkdev [BLOB | BLOB_INDEX] [NODE]
casync [OPTIONS...] gc BLOB_INDEX | ARCHIVE_INDEX ...

DESCRIPTION

Outil de synchronisation de données adressable par contenu

COMMANDES

casync make [ARCHIVE | ARCHIVE_INDEX] [DIRECTORY]
casync make [BLOB_INDEX] FILE | DEVICE

Ceci créera soit une archive .catar, soit un index .caidx pour le DIRECTORY donné, soit un index .caibx pour le FILE ou le périphérique bloc DEVICE donné. Le type de sortie est automatiquement choisi en fonction de l'extension du fichier (cela peut être remplacé avec --what=). DIRECTORY est optionnel, et le répertoire courant sera utilisé s'il n'est pas spécifié.

Lorsqu'un fichier .caidx ou .caibx est créé, un répertoire de stockage .castr sera également créé, situé par défaut dans le même répertoire, et nommé default.castr sauf configuration contraire (voir l'option --store=).

Les métadonnées incluses dans l'archive sont contrôlées par les options --with-* et --without-*.

casync extract [ARCHIVE | ARCHIVE_INDEX] [DIRECTORY]
casync extract BLOB_INDEX FILE | DEVICE

Ceci extraira le contenu d'une archive .catar ou d'un index .caidx dans le DIRECTORY spécifié, ou le contenu spécifié par BLOB_INDEX vers le FILE ou le périphérique bloc DEVICE spécifié. DIRECTORY peut être omis, et le répertoire courant sera utilisé par défaut.

Les métadonnées rejouées depuis l'archive sont contrôlées par les options --with-* et --without-*.

casync list [ARCHIVE | ARCHIVE_INDEX | DIRECTORY] [PATH]

Ceci listera tous les fichiers et répertoires à PATH tels qu'ils sont trouvés dans ARCHIVE ou ARCHIVE_INDEX ou sous DIRECTORY. Les deux arguments sont optionnels. Le premier prend par défaut le répertoire courant. Le second prend par défaut le chemin de niveau supérieur de l'archive (/).

La sortie inclut le masque de permissions et les noms de fichiers :

$ casync list /usr/share/doc/casync
drwxr-xr-x
-rw-r--r-- README.md
-rw-r--r-- TODO
casync mtree [ARCHIVE | ARCHIVE_INDEX | DIRECTORY] [PATH]

Ceci est similaire à list, mais inclut des informations sur chaque entrée au format clé=valeur défini par le fichier mtree(5) de BSD :

$ casync mtree /usr/share/doc/casync
. type=dir mode=0755 uid=0 gid=0 time=1500343585.721189650
README.md type=file mode=0644 size=7286 uid=0 gid=0 time=1498175562.000000000 sha256digest=af75eacac1f00abf6adaa7510a2c7fe00a4636daf9ea910d69d96f0a4ae85df4
TODO type=file mode=0644 size=2395 uid=0 gid=0 time=1498175562.000000000 sha256digest=316f11a03c08ec39f0328ab1f7446bd048507d3fbeafffe7c32fad4942244b7d
casync stat [ARCHIVE | ARCHIVE_INDEX | DIRECTORY] [PATH]

Ceci affichera des informations détaillées sur un fichier ou un répertoire PATH, tel que trouvé dans ARCHIVE ou ARCHIVE_INDEX ou sous DIRECTORY. Les deux arguments sont optionnels. Le premier prend par défaut le répertoire courant, et le second le chemin de niveau supérieur (/).

Exemple de sortie :

$ casync stat .
    File: .
    Mode: drwxrwxr-x
FileAttr: ----------
 FATAttr: ---
  Offset: 0
    Time: 2017-07-17 22:53:30.723304050
    User: zbyszek (1000)
   Group: zbyszek (1000)
casync digest [BLOB | BLOB_INDEX | DIRECTORY]
casync digest ARCHIVE | ARCHIVE_INDEX [PATH]

Ceci calculera et affichera la somme de contrôle du fichier ou du répertoire, ou du PATH donné tel que trouvé dans ARCHIVE ou ARCHIVE_INDEX. Les deux arguments sont optionnels. Le premier prend par défaut le répertoire courant. Le second prend par défaut le chemin de niveau supérieur de l'archive (/).

Exemple :

$ casync digest
d1698b0c4c27163284abea5d1e369b92e89dd07cb74378638849800e0406baf7
$ casync digest .
d1698b0c4c27163284abea5d1e369b92e89dd07cb74378638849800e0406baf7
casync mount [ARCHIVE | ARCHIVE_INDEX] PATH

Ceci montera l'archive .catar ou l'index .caidx spécifié à l'emplacement PATH spécifié, en utilisant le protocole FUSE.

casync mkdev [BLOB | BLOB_INDEX] [NODE]

Ceci créera un périphérique bloc NODE avec le contenu spécifié par le BLOB_INDEX .caibx ou simplement le fichier ou le périphérique bloc BLOB, en utilisant le protocole NBD.

Exemple :

$ sudo casync -v mkdev README.md
Attached: /dev/nbd0
(dans un autre terminal)
$ sudo head -n1 /dev/nbd0
# casync — Outil de synchronisation de données adressable par contenu

Lorsque casync mkdev est arrêté, le périphérique est détruit.

casync gc ARCHIVE_INDEX | BLOB_INDEX ...

Ceci supprimera tous les blocs qui ne sont pas utilisés par l'un des indices spécifiés (un ou plusieurs indices de blocs et d'archives peuvent être donnés). Si --store n'est pas spécifié, le stockage par défaut du premier index sera utilisé.

Cette commande peut être utilisée pour élaguer les blocs inutilisés d'un stockage de blocs partagé.

FONCTIONNALITÉS

D'ARCHIVE

Les divers paramètres --with= et --without= contrôlent l'ensemble précis des métadonnées à stocker dans l'archive, ou à restaurer lors de l'extraction. Ces drapeaux ne s'appliquent que si casync opère au niveau du

système de
fichiers.

EXCLURE DES FICHIERS ET RÉPERTOIRES DE

L'ARCHIVAGE

Lors de la génération d'une archive ou d'un index à partir d'une arborescence de répertoires du système de fichiers, certains fichiers et répertoires sont exclus par défaut et d'autres peuvent être exclus facultativement

:
1
.
Les fichiers et répertoires des systèmes de fichiers API virtuels exposés par le noyau (c.-à-d. procfs, sysfs, cgroupfs, devpts … — mais pas tmpfs/devtmpfs) sont exclus sans
condition.
2
.
Selon que les liens symboliques, les nœuds de périphérique, les fifos et les sockets soient activés pour l'archivage avec --with= et --without=, les nœuds de fichier de ces types sont
exclus.
3
.
Par défaut, les fichiers et répertoires avec le drapeau +d chattr(1) défini sont exclus, cependant ce comportement peut être désactivé avec --exclude-nod
ump=no.
4
.
Facultativement, les fichiers et répertoires contenus dans les sous-montages de l'arborescence de système de fichiers spécifiée sont exclus, si --exclude-submounts=yes est
spécifié.
5
.
Par défaut, tous les fichiers et répertoires listés dans les fichiers .caexclude dans la hiérarchie de fichiers sont exclus, cependant l'interprétation de ces fichiers peut être désactivée avec --exclude-file=no. Ces fichiers fonctionnent de manière similaire à le concept .gitignore de git : ils sont lus comme un fichier texte où chaque ligne est soit vide, soit commence par # (auquel cas elle n'a aucun effet, ce qui peut être utilisé pour des commentaires), ou liste un motif de chemin avec jokers de fichiers/dossiers à ignorer. Si une ligne ne contient pas de / caractère, la ligne s'applique au dossier dans lequel se trouve le fichier .caexclude ainsi qu'à tous ses sous-dossiers. Si elle contient au moins un caractère /, elle est considérée comme strictement relative au dossier dans lequel se trouve le fichier .caexclude. Les fichiers .caexclude peuvent apparaître dans n'importe quel dossier de l'arborescence de fichiers archivée, cependant ils n'ont aucun effet lorsqu'ils sont placés dans des dossiers marqués pour exclusion via des fichiers .caexclude placés plus haut dans l'arborescence des dossiers. Lorsqu'une ligne se termine par un caractère /, elle s'applique uniquement aux dossiers, et non aux fichiers réguliers ou aux autres types de nœuds de fichiers. Si une ligne est préfixée par un caractère !, les fichiers correspondants sont exclus de l'exclusion, c'est-à-dire que l'effet des autres lignes correspondantes qui ne sont pas préfixées de cette manière est annulé pour les fichiers correspondants. Les lignes ! ont priorité inconditionnelle sur les lignes non marquées de cette manière. De plus, les lignes préfixées par ! annulent également l'effet des motifs dans les fichiers .caexclude
placés
dans des dos
siers plus h
aut dans l'arborescence. 2024
