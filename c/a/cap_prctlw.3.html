Pour être de manière significative sécurisée, cependant, les ensembles de capacités doivent être répliqués par tout les threads au sein d'un programme commun car les threads ne sont pas isolés en mémoire. Si votre programme utilise des threads POSIX, pour obtenir une manipulation significative des capacités sémantiques POSIX, vous devez lier votre programme avec :

ou,

gcc ... -lcap $(pkg-config --libs --cflags libpsx)

Lorsqu'il est lié de cette manière, grâce à la magie de l'éditeur de liens, libcap utilise psx_syscall(3) et psx_syscall6(3) pour effectuer des appels système de réglage d'état. Notamment, cela garantit également que cap_prctlw() peut être utilisé pour s'assurer que les bits de contrôle de processus sont partagés entre tous les threads d'un même processus.

capgetp() et capsetp()

La bibliothèque prend également en charge les fonctions dépréciées :

int capgetp(pid_t pid, cap_t cap_d);

int capsetp(pid_t pid, cap_t cap_d);

capgetp() tente d'obtenir les capacités d'un autre processus ; stockant les capacités dans un cap_d pré-alloué. Voir cap_init() pour des informations sur l'allocation d'un ensemble de capacités vide. Cette fonction est dépréciée ; vous devriez utiliser cap_get_pid().

capsetp() tente de définir les capacités du processus appelant ou d'un ou plusieurs autres processus, pid. Notez que la définition des capacités d'un autre processus n'est possible que sur les anciens noyaux qui ne fournissent pas de support VFS pour la définition des capacités de fichier. Voir capset(2) pour des informations sur les noyaux qui fournissent un tel support.

Si pid est positif, il fait référence à un processus spécifique ; s'il est nul, il fait référence au processus appelant ; -1 fait référence à tous les processus autres que le processus appelant et le processus '1' (typiquement init(8)) ; d'autres valeurs négatives font référence au groupe de processus -pid.

Pour utiliser cette fonction, le noyau doit la supporter et le processus appelant doit avoir CAP_SETPCAP élevé dans son ensemble de capacités effectives. Les capacités définies dans le(s) processus cible(s) sont celles contenues dans cap_d.

Les noyaux qui prennent en charge les capacités de système de fichiers redéfinissent la sémantique de CAP_SETPCAP et sur de tels systèmes, capsetp() échouera toujours pour toute cible autre que le processus appelant. capsetp() renvoie zéro en cas de succès, et -1 en cas d'échec.

Sur les noyaux où elle était (était) prise en charge, capsetp() doit être utilisée avec prudence. Elle existait, principalement, pour surmonter un manque précoce de support pour les capacités dans les systèmes de fichiers pris en charge par Linux. Notez que sur les anciens noyaux où capsetp() pouvait être utilisé pour définir les capacités d'un autre processus, les seuls processus qui avaient CAP_SETPCAP disponible par défaut étaient les processus démarrés comme threads du noyau. (Typiquement, cela inclut init(8), kflushd et kswapd.) Une recompilation du noyau était nécessaire pour modifier ce comportement par défaut.

EXEMPLE

Le segment de code ci-dessous élève les capacités effectives CAP_FOWNER et CAP_SETFCAP pour l'appelant :

    ...
    cap_t caps;
    const cap_value_t cap_list[2] = {CAP_FOWNER, CAP_SETFCAP};
    if (!CAP_IS_SUPPORTED(CAP_SETFCAP))
        /* gérer l'erreur */
    caps = cap_get_proc();
    if (caps == NULL)
        /* gérer l'erreur */;
    if (cap_set_flag(caps, CAP_EFFECTIVE, 2, cap_list, CAP_SET) == -1)
        /* gérer l'erreur */;
    if (cap_set_proc(caps) == -1)
        /* gérer l'erreur */;
    if (cap_free(caps) == -1)
        /* gérer l'erreur */;
    ...

Alternativement, pour abandonner complètement les privilèges dans un programme lancé setuid-root mais souhaitant s'exécuter en tant qu'ID utilisateur spécifique, etc., de telle sorte qu'il ne puisse plus acquérir de privilèges, ni lui ni ses enfants :

    ...
    uid_t nobody = 65534;
    const gid_t groups[] = {65534};
    if (cap_setgroups(groups[0], 1, groups) != 0)
        /* gérer l'erreur */;
    if (cap_setuid(nobody) != 0)
        /* gérer l'erreur */;
    /*
     * le privilège est toujours disponible ici
     */
    if (cap_set_mode(CAP_MODE_NOPRIV) != 0)
        /* gérer l'erreur */
    ...

Notez que la séquence ci-dessus peut être effectuée par l'outil capsh comme suit :

sudo capsh --user=nobody --mode=NOPRIV --print

où --print affiche l'état de privilège résultant.
