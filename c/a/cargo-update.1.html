CARGO-UPDATE(1) Manuel des commandes générales CARGO-UPDATE(1)

NOM

cargo-update — Met à jour les dépendances enregistrées dans le fichier de verrouillage local

SYNTAXE

cargo update [options] spécification

DESCRIPTION

Cette commande mettra à jour les dépendances dans le fichier Cargo.lock vers la dernière version. Si le fichier Cargo.lock n'existe pas, il sera créé avec les dernières versions disponibles.

OPTIONS

Options de mise à jour

spécification…

Met à jour uniquement les paquets spécifiés. Cet indicateur peut être spécifié plusieurs fois. Voir cargo-pkgid(1) pour le format SPEC.

Si des paquets sont spécifiés avec spécification, une mise à jour conservatrice du fichier de verrouillage sera effectuée. Cela signifie que seule la dépendance spécifiée par SPEC sera mise à jour. Ses dépendances transitives seront mises à jour uniquement si SPEC ne peut pas être mis à jour sans mettre à jour les dépendances. Toutes les autres dépendances resteront verrouillées à leurs versions enregistrées actuellement.

Si spécification n'est pas spécifiée, toutes les dépendances sont mises à jour.

--recursive

Lorsqu'il est utilisé avec spécification, les dépendances de spécification sont également forcées de se mettre à jour. Ne peut pas être utilisé avec --precise.

--precise précis

Lorsqu'il est utilisé avec spécification, permet de spécifier un numéro de version spécifique auquel régler le paquet. Si le paquet provient d'un dépôt git, il peut s'agir d'une révision git (comme un hachage SHA ou une étiquette).

Bien que non recommandé, vous pouvez spécifier une version retirée (yanked) d'un paquet. Dans la mesure du possible, essayez d'autres versions compatibles SemVer non retirées ou demandez de l'aide aux mainteneurs du paquet.

Une version pré-release compatible peut également être spécifiée même si l'exigence de version dans Cargo.toml ne contient pas d'identifiant de pré-release (uniquement en nightly).

--breaking répertoire

Met à jour spécification vers la dernière version sémantiquement incompatible (breaking).

Les exigences de version seront modifiées pour autoriser cette mise à jour.

Cela ne s'applique qu'aux dépendances lorsque

•Le paquet est une dépendance d'un membre de l'espace de travail
•La dépendance n'est pas renommée
•Une version sémantiquement incompatible est disponible
•L'« Opérateur SemVer » est utilisé (^ qui est le défaut)

Cette option est instable et disponible uniquement sur le canal nightly https://doc.rust-lang.org/book/appendix-07-nightly-rust.html et nécessite l'indicateur -Z unstable-options pour être activé. Voir https://github.com/rust-lang/cargo/issues/12425 pour plus d'informations.

-w, --workspace

Tente de mettre à jour uniquement les paquets définis dans l'espace de travail. Les autres paquets sont mis à jour uniquement s'ils n'existent pas déjà dans le fichier de verrouillage. Cette option est utile pour mettre à jour Cargo.lock après avoir modifié les numéros de version dans Cargo.toml.

--dry-run

Affiche ce qui serait mis à jour, mais n'écrit pas réellement le fichier de verrouillage.

Options d'affichage

-v, --verbose

Utilise une sortie détaillée. Peut être spécifié deux fois pour une sortie « très détaillée » qui inclut des sorties supplémentaires telles que des avertissements de dépendances et la sortie du script de compilation. Peut également être spécifié avec la valeur de configuration term.verbose https://doc.rust-lang.org/cargo/reference/config.html.

-q, --quiet

N'affiche pas les messages de journalisation de cargo. Peut également être spécifié avec la valeur de configuration term.quiet https://doc.rust-lang.org/cargo/reference/config.html.

--color quand

Contrôle quand la sortie colorée est utilisée. Valeurs valides :
•auto (par défaut) : Détecte automatiquement si le support des couleurs est disponible sur le terminal.
•always : Affiche toujours les couleurs.
•never : N'affiche jamais les couleurs.

Peut également être spécifié avec la valeur de configuration term.color https://doc.rust-lang.org/cargo/reference/config.html.

Options du manifeste

--manifest-path chemin

Chemin vers le fichier Cargo.toml. Par défaut, Cargo recherche le fichier Cargo.toml dans le répertoire courant ou dans tout répertoire parent.

--ignore-rust-version

Ignore la spécification rust-version dans les paquets.

--locked

Affirme que les mêmes dépendances et versions que celles utilisées lors de la génération initiale du fichier Cargo.lock existant sont utilisées. Cargo se terminera avec une erreur lorsque l'un des scénarios suivants se présentera :
•Le fichier de verrouillage est manquant.
•Cargo a tenté de modifier le fichier de verrouillage en raison d'une résolution de dépendance différente.

Il peut être utilisé dans des environnements où des builds déterministes sont souhaités, comme dans les pipelines CI.

--offline

Empêche Cargo d'accéder au réseau pour quelque raison que ce soit. Sans cet indicateur, Cargo s'arrêtera avec une erreur s'il a besoin d'accéder au réseau et que celui-ci n'est pas disponible. Avec cet indicateur, Cargo tentera de continuer sans le réseau si possible.

Attention, cela peut entraîner une résolution de dépendances différente de celle du mode en ligne. Cargo se limitera aux crates qui sont téléchargés localement, même s'il existe peut-être une version plus récente comme indiqué dans la copie locale de l'index. Voir la commande cargo-fetch(1) pour télécharger les dépendances avant de passer hors ligne.

Peut également être spécifié avec la valeur de configuration net.offline https://doc.rust-lang.org/cargo/reference/config.html.

--frozen

Équivalent à spécifier à la fois --locked et --offline.

--lockfile-path CHEMIN

Change le chemin du fichier de verrouillage par défaut (<racine_espace_travail>/Cargo.lock) vers CHEMIN. CHEMIN doit se terminer par Cargo.lock (par exemple, --lockfile-path /tmp/temporary-lockfile/Cargo.lock). Notez que la fourniture de --lockfile-path ignorera le fichier de verrouillage existant au chemin par défaut, et utilisera à la place le fichier de verrouillage de CHEMIN, ou écrira un nouveau fichier de verrouillage dans le CHEMIN fourni s'il n'existe pas. Cet indicateur peut être utilisé pour exécuter la plupart des commandes dans des répertoires en lecture seule, en écrivant le fichier de verrouillage dans le CHEMIN fourni.

Cette option n'est disponible que sur le canal nightly https://doc.rust-lang.org/book/appendix-07-nightly-rust.html et nécessite l'indicateur -Z unstable-options pour être activé (voir #14421 https://github.com/rust-lang/cargo/issues/14421).

Options communes

+toolchain

Si Cargo a été installé avec rustup, et que le premier argument de cargo commence par +, il sera interprété comme un nom de toolchain rustup (tel que +stable ou +nightly). Voir la documentation rustup https://rust-lang.github.io/rustup/overrides.html pour plus d'informations sur le fonctionnement des substitutions de toolchain.

--config CLÉ=VALEUR ou CHEMIN

Remplace une valeur de configuration Cargo. L'argument doit être au format TOML de CLÉ=VALEUR, ou fourni comme chemin vers un fichier de configuration supplémentaire. Cet indicateur peut être spécifié plusieurs fois. Voir la section sur les remplacements en ligne de commande h

-C PAT

H

Cela affecte des éléments tels que l'endroit où cargo recherche par défaut le manifeste du projet (Cargo.toml), ainsi que les répertoires parcourus pour découvrir .cargo/config.toml, par exemple.
