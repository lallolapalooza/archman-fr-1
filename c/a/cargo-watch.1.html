Ce fichier peut être utilisé pour spécifier des fichiers qui devraient être ignorés par cargo watch mais versionnés dans git, sans ajouter constamment les options --ignore abc la ligne de commande. Notez que les fichiers .ignore peuvent également être utilisés par d'autres programmes, comme ripgrep(1). Pour cesser de les prendre en compte, passez --no-dot-ignores

Cargo watch possède également une liste interne d'ignorances par défaut en plus de celles spécifiées dans les fichiers, comme target/ et .git/ ainsi que divers autres types courants (journaux, fichiers d'échange d'éditeur, fichiers de verrouillage, etc)

Pour ignorer absolument toutes les ignorances, utilisez l'option --ignore

Syntaxe

d'ignorance

Voir la documentation de glob::Pattern0 https://doc.rust-lang.org/glob/glob/struct.Pattern.html pour une spécification plus détaillée de la syntaxe de correspondance de motifs (glob) utilisée pour --ignore

Sous Windows, les motifs doivent être spécifiés avec des séparateurs de style Windows (\\). Les séparateurs de style Unix (/) ne correspondraient pas aux chemins Windows, ce qui pourrait être déroutant et donner l'impression que les ignorances en ligne de commande ne fonctionnent pas. Par commodité, les / dans les ignorances en ligne de commande sont automatiquement traduits en \\ lors de l'exécution sous Windows, mais il est préférable d'essay

r la plateforme, car il peut y a
voir des différences plus subtiles.

BOGUE

S

Veuillez ouvrir un problème1 https://github.com/watchexec/cargo-watch/issues, ou consulter les problèmes

existants.

Si vous souhaitez une sortie plus détaillée, essayez d'exécuter avec l'option --debug. Notez que cela activera également le mode débogage pour watchexec. Lors de la création d'un problème, assurez-vous d'inclure un journal avec --debug activé afin que les problèmes puissent être diagnostiqués, ainsi que votre --version et votre système

d'exploitation.

Si votre problème concerne watchexec (notre principal projet amont), ouvrez-le directement là-bas2 https://github.com/watchexec/watchexec/issues. Si vous n'êtes pas sûr, n'hésitez pas à l'ouvrir sur le suivi des problèmes de cargo-watch, mais s'il s'agit d'un problème de watchexec, il sera transféré là-bas tout de

même.

BOGUES

CONNUS

Dans la version 7.8.0, l'option --workdir change le répertoire avant le traitement de toute autre option, donc par exemple les chemins --watch peuvent ne pas fonctionner comme prévu. Cela est corrigé en amont dans la bibliothèque Watchexec

2.

Dans la version 8.x, les options -B, -L, -E, --env-var, --env-file injectent des variables d'environnement dans le processus principal de cargo-watch, ce qui

peut être non fiable dans certaines situations et peu
t aussi affecter cargo-watch lui-même. Cela est c
orrigé en amont dans la bibliothèque Watchexec 2.
