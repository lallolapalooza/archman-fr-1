CARGO-RUSTDOC(1) Manuel des commandes générales CARGO-RUSTDOC(1)

NOM

cargo-rustdoc — Construire la documentation d'un paquet, en utilisant des indicateurs personnalisés spécifiés

SYNOPSIS

cargo rustdoc [options] [-- args]

DESCRIPTION

La cible spécifiée pour le paquet actuel (ou le paquet spécifié par -p s'il est fourni) sera documentée avec les args spécifiés, qui seront passés à l'invocation finale de rustdoc. Les dépendances ne seront pas documentées dans le cadre de cette commande. Notez que rustdoc recevra toujours inconditionnellement des arguments tels que -L, --extern et --crate-type, et les args spécifiés seront simplement ajoutés à l'invocation de rustdoc.

Voir https://doc.rust-lang.org/rustdoc/index.html pour la documentation sur les indicateurs de rustdoc.

Cette commande requiert qu'une seule cible soit compilée lorsque des arguments supplémentaires sont fournis. Si plus d'une cible est disponible pour le paquet actuel, les filtres de --lib, --bin, etc. doivent être utilisés pour sélectionner la cible à compiler.

Pour passer des indicateurs à tous les processus rustdoc lancés par Cargo, utilisez la variable d'environnement RUSTDOCFLAGS https://doc.rust-lang.org/cargo/reference/environment-variables.html ou la valeur de configuration build.rustdocflags https://doc.rust-lang.org/cargo/reference/config.html.

OPTIONS

Options de documentation

--open

Ouvrir la documentation dans un navigateur après l'avoir construite. Ceci utilisera votre navigateur par défaut, sauf si vous en définissez un autre dans la variable d'environnement BROWSER ou si vous utilisez l'option de configuration doc.browser https://doc.rust-lang.org/cargo/reference/config.html#docbrowser.

Sélection du paquet

Par défaut, le paquet dans le répertoire de travail actuel est sélectionné. L'indicateur -p peut être utilisé pour choisir un autre paquet dans un espace de travail.

-p spécification, --package spécification

Le paquet à documenter. Voir cargo-pkgid(1) pour le format SPEC.

Sélection de la cible

Lorsqu'aucune option de sélection de cible n'est donnée, cargo rustdoc documentera toutes les cibles binaires et de bibliothèque du paquet sélectionné. Le binaire sera ignoré si son nom est identique à celui de la cible lib. Les binaires sont ignorés s'ils ont des required-features qui sont manquantes.

La fourniture d'indicateurs de sélection de cible documentera uniquement les cibles spécifiées.

Notez que les indicateurs --bin, --example, --test et --bench prennent également en charge les modèles glob de style Unix communs tels que *, ? et []. Cependant, pour éviter que votre shell n'étende accidentellement les modèles glob avant que Cargo ne les traite, vous devez utiliser des guillemets simples ou doubles autour de chaque modèle glob.

--lib

Documenter la bibliothèque du paquet.

--bin nom…

Documenter le binaire spécifié. Cet indicateur peut être spécifié plusieurs fois et prend en charge les modèles glob Unix courants.

--bins

Documenter toutes les cibles binaires.

--example nom…

Documenter l'exemple spécifié. Cet indicateur peut être spécifié plusieurs fois et prend en charge les modèles glob Unix courants.

--examples

Documenter toutes les cibles d'exemple.

--test nom…

Documenter le test d'intégration spécifié. Cet indicateur peut être spécifié plusieurs fois et prend en charge les modèles glob Unix courants.

--tests

Documenter toutes les cibles qui ont l'indicateur de manifeste test = true défini. Par défaut, cela inclut la bibliothèque et les binaires construits comme tests unitaires, ainsi que les tests d'intégration. Sachez que cela compilera également toutes les dépendances requises, donc la cible lib peut être compilée deux fois (une fois comme test unitaire, et une fois comme dépendance pour les binaires, les tests d'intégration, etc.). Les cibles peuvent être activées ou désactivées en définissant l'indicateur test dans les paramètres du manifeste pour la cible.

--bench nom…

Documenter le benchmark spécifié. Cet indicateur peut être spécifié plusieurs fois et prend en charge les modèles glob Unix courants.

--benches

Documenter toutes les cibles qui ont l'indicateur de manifeste bench = true défini. Par défaut, cela inclut la bibliothèque et les binaires construits comme benchmarks, ainsi que les cibles de benchmark. Sachez que cela compilera également toutes les dépendances requises, donc la cible lib peut être compilée deux fois (une fois comme benchmark, et une fois comme dépendance pour les binaires, les benchmarks, etc.). Les cibles peuvent être activées ou désactivées en définissant l'indicateur bench dans les paramètres du manifeste pour la cible.

--all-targets

Documenter toutes les cibles. Ceci est équivalent à spécifier --lib --bins --tests --benches --examples.

Sélection des fonctionnalités

Les indicateurs de fonctionnalités vous permettent de contrôler quelles fonctionnalités sont activées. Lorsqu'aucune option de fonctionnalité n'est donnée, la fonctionnalité default est activée pour chaque paquet sélectionné.

Voir la documentation des fonctionnalités https://doc.rust-lang.org/cargo/reference/features.html#command-line-feature-options pour plus de détails.

-F fonctionnalités, --features fonctionnalités

Liste de fonctionnalités séparées par des espaces ou des virgules à activer. Les fonctionnalités des membres de l'espace de travail peuvent être activées avec la syntaxe nom-paquet/nom-fonctionnalité. Cet indicateur peut être spécifié plusieurs fois, ce qui active toutes les fonctionnalités spécifiées.

--all-features

Activer toutes les fonctionnalités disponibles de tous les paquets sélectionnés.

--no-default-features

Ne pas activer la fonctionnalité default des paquets sélectionnés.

Options de compilation

--target triple

Documenter pour l'architecture cible spécifiée. L'indicateur peut être spécifié plusieurs fois. La cible par défaut est l'architecture hôte. Le format général du triple est <arch><sub>-<vendor>-<sys>-<abi>.

Valeurs possibles :

•Toute cible prise en charge dans rustc --print target-list.
•"host-tuple", qui sera interne substitué par la cible de la machine hôte. Cela peut être particulièrement utile si vous croisez la compilation de certains crates, et que vous ne voulez pas spécifier la machine hôte comme cible (par exemple, un xtask dans un projet partagé qui peut être développé par de nombreux hôtes).
•Un chemin vers une spécification de cible personnalisée. Voir Chemin de recherche des cibles personnalisées https://doc.rust-lang.org/rustc/targets/custom.html#custom-target-lookup-path pour plus d'informations.

Ceci peut également être spécifié avec la valeur de configuration build.target https://doc.rust-lang.org/cargo/reference/config.html.

Notez que la spécification de cet indicateur fait fonctionner Cargo dans un mode différent où les artefacts de la cible sont placés dans un répertoire séparé. Voir la documentation sur le cache de build https://doc.rust-lang.org/cargo/reference/build-cache.html pour plus de détails.
