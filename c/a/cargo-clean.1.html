CARGO-CLEAN(1) Manuel des commandes générales CARGO-CLEAN(1)

NOM

cargo-clean — Supprimer les artefacts générés

SYNTAXE

cargo clean [options]

DESCRIPTION

Supprime les artefacts du répertoire cible que Cargo a générés par le passé.

Sans aucune option, cargo clean supprime l'intégralité du répertoire cible.

OPTIONS

Sélection de paquets

Lorsqu'aucun paquet n'est sélectionné, tous les paquets et toutes les dépendances de l'espace de travail sont nettoyés.

-p spéc…, --package spéc…

Nettoie uniquement les paquets spécifiés. Cet indicateur peut être spécifié plusieurs fois. Voir cargo-pkgid(1) pour le format SPEC.

Options de nettoyage

--dry-run

Affiche un résumé de ce qui serait supprimé sans rien supprimer. Utilisez avec --verbose pour afficher les fichiers réels qui seraient supprimés.

--doc

Cette option amène cargo clean à supprimer uniquement le répertoire doc dans le répertoire cible.

--release

Supprime tous les artefacts du répertoire release.

--profile nom

Supprime tous les artefacts du répertoire portant le nom de profil donné.

--target-dir répertoire

Répertoire pour tous les artefacts générés et les fichiers intermédiaires. Peut également être spécifié avec la variable d'environnement CARGO_TARGET_DIR, ou la valeur de configuration build.target-dir https://doc.rust-lang.org/cargo/reference/config.html. Par défaut, il s'agit de target à la racine de l'espace de travail.

--target triple

Nettoie pour l'architecture cible spécifiée. L'indicateur peut être spécifié plusieurs fois. La valeur par défaut est l'architecture hôte. Le format général de la triple est <arch><sub>-<vendor>-<sys>-<abi>.

Valeurs possibles :

•Toute cible prise en charge dans rustc --print target-list.
•"host-tuple", qui sera substitué en interne par la cible de l'hôte. Cela peut être particulièrement utile si vous compilez certaines caisses de manière croisée et que vous ne souhaitez pas spécifier la machine hôte comme cible (par exemple, un xtask dans un projet partagé qui peut être traité par plusieurs hôtes).
•Un chemin vers une spécification de cible personnalisée. Voir Chemin de recherche de cible personnalisé https://doc.rust-lang.org/rustc/targets/custom.html#custom-target-lookup-path pour plus d'informations.

Cela peut également être spécifié avec la valeur de configuration build.target https://doc.rust-lang.org/cargo/reference/config.html.

Notez que la spécification de cet indicateur fait fonctionner Cargo dans un mode différent où les artefacts cibles sont placés dans un répertoire séparé. Voir la documentation du cache de compilation https://doc.rust-lang.org/cargo/reference/build-cache.html pour plus de détails.

Options d'affichage

-v, --verbose

Utilise une sortie verbeuse. Peut être spécifié deux fois pour une sortie « très verbeuse » qui inclut des sorties supplémentaires comme des avertissements de dépendance et la sortie du script de compilation. Peut également être spécifié avec la valeur de configuration term.verbose https://doc.rust-lang.org/cargo/reference/config.html.

-q, --quiet

N'affiche pas les messages de journal de cargo. Peut également être spécifié avec la valeur de configuration term.quiet https://doc.rust-lang.org/cargo/reference/config.html.

--color quand

Contrôle quand la sortie colorée est utilisée. Valeurs valides :
•auto (par défaut) : Détecte automatiquement si le support des couleurs est disponible sur le terminal.
•always : Affiche toujours les couleurs.
•never : N'affiche jamais les couleurs.

Peut également être spécifié avec la valeur de configuration term.color https://doc.rust-lang.org/cargo/reference/config.html.

Options de manifeste

--manifest-path chemin

Chemin vers le fichier Cargo.toml. Par défaut, Cargo recherche le fichier Cargo.toml dans le répertoire courant ou dans tout répertoire parent.

--locked

Affirme que les mêmes dépendances et versions exactes sont utilisées que lors de la génération originale du fichier Cargo.lock. Cargo se terminera avec une erreur lorsque l'un des scénarios suivants se présente :
•Le fichier de verrouillage est manquant.
•Cargo a tenté de modifier le fichier de verrouillage en raison d'une résolution de dépendance différente.

Il peut être utilisé dans des environnements où des compilations déterministes sont souhaitées, comme dans les pipelines CI.

--offline

Empêche Cargo d'accéder au réseau pour quelque raison que ce soit. Sans cet indicateur, Cargo s'arrêtera avec une erreur s'il a besoin d'accéder au réseau et que celui-ci n'est pas disponible. Avec cet indicateur, Cargo tentera de continuer sans le réseau si possible.

Attention, cela peut entraîner une résolution de dépendance différente de celle du mode en ligne. Cargo se limitera aux caisses téléchargées localement, même s'il pourrait y avoir une version plus récente indiquée dans la copie locale de l'index. Voir la commande cargo-fetch(1) pour télécharger les dépendances avant de passer hors ligne.

Peut également être spécifié avec la valeur de configuration net.offline https://doc.rust-lang.org/cargo/reference/config.html.

--frozen

Équivalent à spécifier à la fois --locked et --offline.

--lockfile-path CHEMIN

Modifie le chemin du fichier de verrouillage par rapport au défaut (<workspace_root>/Cargo.lock) à CHEMIN. CHEMIN doit se terminer par Cargo.lock (par exemple, --lockfile-path /tmp/temporary-lockfile/Cargo.lock). Notez que la fourniture de --lockfile-path ignorera le fichier de verrouillage existant au chemin par défaut, et utilisera soit le fichier de verrouillage provenant de CHEMIN, soit écrira un nouveau fichier de verrouillage dans le CHEMIN fourni s'il n'existe pas. Cet indicateur peut être utilisé pour exécuter la plupart des commandes dans des répertoires en lecture seule, en écrivant le fichier de verrouillage dans le CHEMIN fourni.

Cette option n'est disponible que sur le canal nightly https://doc.rust-lang.org/book/appendix-07-nightly-rust.html et nécessite l'indicateur -Z unstable-options pour être activé (voir #14421 https://github.com/rust-lang/cargo/issues/14421).

Options communes

+toolchain

Si Cargo a été installé avec rustup et que le premier argument de cargo commence par +, il sera interprété comme un nom de toolchain rustup (tel que +stable ou +nightly). Voir la documentation rustup https://rust-lang.github.io/rustup/overrides.html pour plus d'informations sur le fonctionnement des remplacements de toolchain.

--config CLÉ=VALEUR ou CHEMIN

Remplace une valeur de configuration Cargo. L'argument doit être au format TOML de CLÉ=VALEUR, ou être fourni comme chemin vers un fichier de configuration supplémentaire. Cet indicateur peut être spécifié plusieurs fois. Voir la section remplacements en ligne de commande -C PAT

H
Change le répertoire de travail courant avant d'exécuter les opérations spécifiées. Cela affecte des éléments comme l'endroit où Cargo recherche par défaut le manifeste du projet (Cargo.toml), ainsi que les répertoires parcourus pour découvrir .cargo/config.toml, par exemple. Cette option doit apparaître avant le nom de la commande, par exemple cargo -C chemin/vers/mon-projet build.

Cette option n'est disponible que sur la chaîne nightly https://doc.rust-lang.org/book/appendix-07-nightly-rust.html et nécessite l'indicateur -Z unstable-options pour être activée (voir #10098 https://github.com/rust-
