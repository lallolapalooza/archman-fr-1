FORMATS DE TEXTE DES CAPACITÉS

La bibliothèque de capacités libcap(3) utilise deux formats de texte pour représenter les capacités : le format texte original pour l'ensemble de capacités standard (`Set') et pris en charge par les outils en ligne de commande getcap(8), setcap(8) et capsh(8) ; et le format texte tuple IAB, qui est utilisable par le module Linux-PAM pam_cap(8), captree(8) et capsh(8). Ces formats texte sont largement pris en charge par libcap(3) et le package Go 'kernel.org/pub/linux/libs/security/libcap/cap'.

LE FORMAT TEXTUEL DES ENSEMBLES DE CAPACITÉS

Ce format texte est spécifié dans le projet POSIX.1e abandonné [1] qui a introduit les capacités. Il est capable de représenter les capacités des processus et des fichiers.

La représentation textuelle des ensembles de capacités consiste en une ou plusieurs clauses séparées par des espaces. Chaque clause spécifie certaines opérations sur un ensemble de capacités ; l'ensemble commence avec toutes les capacités abaissées, et la signification de la chaîne est l'état de l'ensemble de capacités après que toutes les clauses aient été appliquées dans l'ordre.

Chaque clause consiste en une liste de noms de capacités séparés par des virgules (ou le mot `all'), suivie d'une liste d'actions. Une liste d'actions consiste en une séquence de paires opérateur drapeau. Les opérateurs valides sont : `=', '+' et `-'. Les drapeaux valides sont : `e', `i' et `p'. Ces drapeaux sont sensibles à la casse et spécifient respectivement les ensembles Effectif, Héritable et Permis.

Dans les listes de noms de capacités, tous les noms sont insensibles à la casse. Le nom spécial `all' spécifie toutes les capacités ; il est équivalent à une liste nommant chaque capacité individuellement.

Les capacités sans nom peuvent également être spécifiées par leur numéro. Cette fonctionnalité garantit que libcap peut prendre en charge des capacités qui n'étaient pas allouées au moment de la compilation de libcap. Cependant, généralement, la mise à jour de libcap ajoutera des noms pour les capacités récemment allouées.

L'opérateur `=' indique que les capacités listées sont d'abord réinitialisées dans les trois ensembles de capacités. Les drapeaux suivants (qui sont facultatifs lorsqu'ils sont associés à cet opérateur) indiquent que les capacités listées pour l'ensemble correspondant doivent être augmentées. Par exemple : "all=p" signifie abaisser toutes les capacités des ensembles Effectif et Héritable, mais augmenter toutes les capacités Permises ; ou, "cap_fowner=ep" signifie augmenter la capacité d'override-file-ownership Effective et Permise, tout en abaissant cette capacité Héritable.

Dans le cas où l'opérateur initial est `=', et qu'aucune liste de capacités n'est fournie, la liste d'actions est supposée se référer à `all' capacités. Par exemple, les trois clauses suivantes sont équivalentes les unes aux autres (et indiquent un ensemble de capacités complètement vide) : "all=" ; "=" ; "cap_chown,<toute-autre-capacité>=".

Les opérateurs `+' et `-' nécessitent tous deux une liste explicite de capacités précédente et un ou plusieurs drapeaux explicites suivants. L'opérateur `+' augmentera toutes les capacités listées dans les ensembles de capacités marqués. L'opérateur `-' abaissera toutes les capacités listées dans les ensembles de capacités marqués. Par exemple : "all+p" augmentera toutes les capacités Permises et "cap_fowner-i" abaissera la capacité d'override-file-ownership dans l'ensemble Héritable.

La liste d'actions peut consister en plusieurs paires opérateur drapeau ; les actions sont effectuées dans l'ordre de gauche à droite. Ainsi, par exemple, "cap_fowner+p-i" est équivalent à "cap_fowner+p cap_fowner-i". Comme autre exemple, "cap_fowner+pe-i" et "cap_fowner=+pe" sont équivalents.

LE FORMAT TEXTUEL TUPLE IAB

Ce format est une extension pure Linux. Il a vu le jour sous la forme du format utilisé par pam_cap(8) et peut être utilisé par capsh(8).

Le format texte tuple IAB est une liste de valeurs de capacités séparées par des virgules. Chaque capacité est précédée de rien (ou %) (Inh) ; ! (Bound, mais pensez Bloqué) ; ^ (Amb). Ou, une combinaison de ceux-ci. Étant donné que le vecteur Amb est contraint de ne pas dépasser le vecteur Inh, ^ est équivalent à %^. De plus, à moins que B ne soit non nul, % peut être omis. Les représentations textuelles suivantes sont valides : "!%cap_chown" (Bound mais Inh), "!cap_chown,^cap_chown" (Bound, Inh+Amb). "cap_setuid,!cap_chown" (Inh, Bound). Comme indiqué ci-dessus, cette représentation textuelle est utilisée dans la syntaxe du fichier de configuration (voir capability.conf(5)) pour le module de sécurité Linux-PAM pam_cap(8).
