NOM

CALL - invoquer une procédure

SYNTAXE

CALL nom ( [ argument ] [, ...] )

DESCRIPTION

CALL exécute une procédure.

Si la procédure a des paramètres de sortie, alors une ligne de résultat sera renvoyée, contenant les valeurs de ces paramètres.

PARAMÈTRES

nom

Le nom (éventuellement qualifié par un schéma) de la procédure.

argument

Une expression d'argument pour l'appel de procédure.

Les arguments peuvent inclure des noms de paramètres, en utilisant la syntaxe nom => valeur. Cela fonctionne de la même manière que dans les appels de fonction ordinaires ; voir la Section 4.3 pour plus de détails.

Des arguments doivent être fournis pour tous les paramètres de procédure qui n'ont pas de valeur par défaut, y compris les paramètres OUT. Cependant, les arguments correspondant aux paramètres OUT ne sont pas évalués, il est donc courant de simplement écrire NULL pour eux. (Écrire autre chose pour un paramètre OUT pourrait causer des problèmes de compatibilité avec les futures versions de PostgreSQL.)

NOTES

L'utilisateur doit avoir le privilège EXECUTE sur la procédure pour pouvoir l'invoquer.

Pour appeler une fonction (pas une procédure), utilisez plutôt SELECT.

Si CALL est exécuté dans un bloc de transaction, alors la procédure appelée ne peut pas exécuter d'instructions de contrôle de transaction. Les instructions de contrôle de transaction ne sont autorisées que si CALL est exécuté dans sa propre transaction.

PL/pgSQL gère les paramètres de sortie dans les commandes CALL différemment ; voir la Section 41.6.3.

EXEMPLES

CALL do_db_maintenance();

COMPATIBILITÉ

CALL est conforme à la norme SQL, à l'exception de la gestion des paramètres de sortie. La norme indique que les utilisateurs doivent écrire des variables pour recevoir les valeurs des paramètres de sortie.
