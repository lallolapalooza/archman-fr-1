DESCRIPTION
Un lanceur fournit un
mécanisme

permettant d'exécut

e
r

une

fonction

de rappel et/ou un exécutable de programme dans un environnement avec un contexte de sécurité modifié. Essentiellement, il fournit un mécanisme permettant à un programme de fork(2) un nouveau contexte à partir de celui du programme principal, de manipuler les capacités et d'autres états privilégiés dans ce processus fork(2) avant (éventuellement) execve(2) un nouveau programme. Lorsque l'application est liée à -lpsx, cette fonctionnalité est nécessaire pour exécuter de manière robuste le code lancé sans modifier le privilège de toute l'application principale (respectant la sémantique POSIX).

Un

lanceur est défini par l'une de ces deux fonctions : cap_new_launcher() ou cap_func_launcher(). La valeur de retour étant de type opaque cap_launch_t, une valeur de retour NULL indique qu'une erreur s'est

produite.

Une fois défini, une valeur cap_launch_t peut être utilisée avec cap_launch() pour exécuter ce lanceur. Dans de tels cas, une valeur de retour non négative indique le succès : zéro signifie le succès sans qu'un programme soit invoqué ; non zéro est égal à l'identifiantde processus ( pid_t) du

programme

n ouvellement lancé. Un cap_launch_t occupe de la mémoire allouée et doit être libéré avec cap_free(3) . Avant d'être libéré par cap_free(3), une valeur cap_value_t peut être réutilisée pour plusieurs lancements indépendants. L'argument detail de cap_launch(), en conjonction avec la fonction de rappel du lanceur, peut être utilisé pour personnaliser l'invocation du lancement. Il faut faire attention à utiliser de la mémoire partagée personnalisée (voir mmap(2)) ou un autre IPC pour renvoyer des valeurs au programme principal via detail, car le rappel et toute exécution ultérieure de programme se produiront en dehors du processus principal de l'application appelante.

   cap_launcher_callback(cmd, &answer_detail_fn);

Les fonctions suivantes peuvent être utilisées pour indiquer au lanceur de modifier l'état de sécurité du programme invoqué sans altérer l'état du programme appelant. De telles modifications doivent être effectuées avant d'appeler cap_launch() si elles doivent avoir l'effet désiré. De plus, elles ne sont invoquées qu'après la fin de tout rappel installé. Par exemple, on peut abandonner ou modifier des capacités, juste pour l'exécution

Appeler cette fonction avec une valeur IAB de NULL configurera le lanceur pour ne pas définir de valeur IAB (par défaut). Voir cap_iab(3) pour des détails sur l'ensemble IAB. Notez que le lanceur est directement associé à la valeur iab fournie et n'en fait pas de copie. Cette valeur iab est verrouillée pour le lanceur et ne peut pas être modifiée tant qu'elle est associée au lanceur.
