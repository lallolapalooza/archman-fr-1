CARGO-VENDOR(1) Manuel des commandes générales CARGO-VENDOR(1)

NOM

cargo-vendor — Fournir toutes les dépendances localement

SYNOPIS

cargo vendor [options] [chemin]

DESCRIPTION

Cette sous-commande de cargo fournira toutes les dépendances crates.io et git pour un projet dans le répertoire spécifié à <chemin>. Après que cette commande ait terminé, le répertoire de fournisseurs spécifié par <chemin> contiendra toutes les sources distantes des dépendances spécifiées. Des manifestes supplémentaires au-delà du manifeste par défaut peuvent être spécifiés avec l'option -s.

La configuration nécessaire pour utiliser les sources fournies sera imprimée sur la sortie standard après que cargo vendor ait terminé le processus de fourniture. Vous devrez l'ajouter ou la rediriger vers votre fichier de configuration Cargo, qui est généralement .cargo/config.toml localement pour le paquet courant.

Cargo traite les sources fournies comme étant en lecture seule, tout comme il le fait pour les sources de registre et de git. Si vous avez l'intention de modifier une caisse provenant d'une source distante, utilisez [patch] ou une dépendance de type path pointant vers une copie locale de cette caisse. Cargo gérera alors correctement la caisse lors des reconstructions incrémentielles, car il sait qu'il ne s'agit plus d'une dépendance en lecture seule.

OPTIONS

Options de fourniture

-s manifeste, --sync manifeste

Spécifie un fichier manifeste Cargo.toml supplémentaire pour les espaces de travail qui devraient également être fournis et synchronisés avec la sortie. Peut être spécifié plusieurs fois.

--no-delete

Ne supprime pas le répertoire “vendor” lors de la fourniture, mais conserve plutôt tout le contenu existant du répertoire de fournisseurs.

--respect-source-config

Au lieu d'ignorer la configuration [source] par défaut dans .cargo/config.toml, la lit et l'utilise lors du téléchargement de caisses depuis crates.io, par exemple.

--versioned-dirs

Normalement, les versions ne sont ajoutées que pour désambiguïser plusieurs versions du même paquet. Cette option fait que tous les répertoires du répertoire “vendor” sont versionnés, ce qui rend plus facile le suivi de l'historique des paquets fournis au fil du temps et peut aider aux performances de re-fourniture lorsque seule une partie des paquets a changé.

Options du manifeste

--manifest-path chemin

Chemin vers le fichier Cargo.toml. Par défaut, Cargo recherche le fichier Cargo.toml dans le répertoire courant ou dans tout répertoire parent.

--locked

Affirme que les mêmes dépendances et versions exactes sont utilisées que celles lors de la génération du fichier Cargo.lock existant. Cargo se terminera avec une erreur lorsque l'un des scénarios suivants se présentera :
•Le fichier de verrouillage est manquant.
•Cargo a tenté de modifier le fichier de verrouillage en raison d'une résolution de dépendance différente.

Il peut être utilisé dans des environnements où des builds déterministes sont souhaités, comme dans les pipelines d'intégration continue.

--offline

Empêche Cargo d'accéder au réseau pour quelque raison que ce soit. Sans ce drapeau, Cargo s'arrêtera avec une erreur s'il a besoin d'accéder au réseau et que le réseau n'est pas disponible. Avec ce drapeau, Cargo tentera de continuer sans le réseau si possible.

Attention, cela peut entraîner une résolution de dépendance différente de celle du mode en ligne. Cargo se limitera aux caisses qui sont téléchargées localement, même s'il pourrait y avoir une version plus récente comme indiqué dans la copie locale de l'index. Voir la commande cargo-fetch(1) pour télécharger les dépendances avant de passer hors ligne.

Peut également être spécifié avec la valeur de configuration net.offline https://doc.rust-lang.org/cargo/reference/config.html.

--frozen

Équivalent à spécifier à la fois --locked et --offline.

--lockfile-path CHEMIN

Modifie le chemin du fichier de verrouillage par défaut (<racine_de_l_espace_de_travail>/Cargo.lock) pour CHEMIN. CHEMIN doit se terminer par Cargo.lock (par exemple, --lockfile-path /tmp/temporary-lockfile/Cargo.lock). Notez que la fourniture de --lockfile-path ignorera le fichier de verrouillage existant au chemin par défaut, et utilisera à la place le fichier de verrouillage de CHEMIN, ou écrira un nouveau fichier de verrouillage dans le CHEMIN fourni s'il n'existe pas. Ce drapeau peut être utilisé pour exécuter la plupart des commandes dans des répertoires en lecture seule, en écrivant le fichier de verrouillage dans le CHEMIN fourni.

Cette option n'est disponible que sur le canal nightly https://doc.rust-lang.org/book/appendix-07-nightly-rust.html et nécessite le drapeau -Z unstable-options pour être activé (voir #14421 https://github.com/rust-lang/cargo/issues/14421).

Options d'affichage

-v, --verbose

Utiliser une sortie verbeuse. Peut être spécifié deux fois pour une sortie “très verbeuse” qui inclut une sortie supplémentaire telle que des avertissements de dépendance et la sortie des scripts de build. Peut également être spécifié avec la valeur de configuration term.verbose https://doc.rust-lang.org/cargo/reference/config.html.

-q, --quiet

Ne pas imprimer les messages de log de cargo. Peut également être spécifié avec la valeur de configuration term.quiet https://doc.rust-lang.org/cargo/reference/config.html.

--color quand

Contrôle quand la sortie colorée est utilisée. Valeurs valides :
•auto (par défaut) : Détecte automatiquement si le support couleur est disponible sur le terminal.
•always : Affiche toujours les couleurs.
•never : N'affiche jamais les couleurs.

Peut également être spécifié avec la valeur de configuration term.color https://doc.rust-lang.org/cargo/reference/config.html.

Options communes

+toolchain

Si Cargo a été installé avec rustup, et que le premier argument de cargo commence par +, il sera interprété comme un nom de toolchain rustup (comme +stable ou +nightly). Voir la documentation rustup https://rust-lang.github.io/rustup/overrides.html pour plus d'informations sur le fonctionnement des remplacements de toolchain.

--config CLÉ=VALEUR ou CHEMIN

Remplace une valeur de configuration Cargo. L'argument doit être en syntaxe TOML de CLÉ=VALEUR, ou fourni comme un chemin vers un fichier de configuration supplémentaire. Ce drapeau peut être spécifié plusieurs fois. Voir la section sur les remplacements en ligne de commande https://doc.rust-lang.org/cargo/reference/config.html#command-line-overrides pour plus d'informations.

-C CHEMIN

Change le répertoire de travail courant avant d'exécuter les opérations spécifiées. Cela affecte, par exemple, où cargo recherche par défaut le manifeste du projet (Cargo.toml), ainsi que les répertoires recherchés pour découvrir .cargo/config.toml. Cette option doit apparaître avant le nom de la commande, par exemple cargo -C chemin/vers/mon-projet build.

Cette option n'est disponible que sur le canal nightly https://doc.rust-lang.org/book/appendix-07-nightly-rust.html et nécessite le drapeau -Z unstable-options pour être activé (voir #10098 https://github.com/rust-lang/cargo/issues/10098).

-h, --help

Affiche l'aide.

-Z flag

Drapeaux instables (réservés à la version nightly) pour Cargo. Exécutez cargo -Z help pour les détails.

EXEMPLES

Fournir les dépendances dans le répertoire ./vendor :

cargo vendor ./vendor

Fournir les dépendances dans le répertoire ./vendor et ne pas supprimer les fichiers existants :

cargo vendor --no-delete ./vendor

CONFIGURER CARGO POUR UTILISER LES SOURCES FOURNIES

Après avoir exécuté la commande cargo vendor, il faut dire à Cargo d'utiliser les sources fournies. Pour ce faire, créez un fichier .cargo/config.toml dans la racine de votre projet (ou ajoutez-y les lignes suivantes) :

[source.<nom_de_votre_registre_ou_url>]
replace-with = "vendored"

Par exemple, si vous utilisez le registre par défaut de crates.io, le fichier .cargo/config.toml ressemblerait à ceci :

[source.crates-io]
replace-with = "vendored"

Cargo s'attend à ce que les sources fournies soient accessibles via un serveur local. Cela est géré par la sortie de cargo vendor elle-même, qui ressemblera à ceci :

<path> = "path/to/vendor"

En remplaçant <path> par le chemin réel du répertoire que vous avez spécifié à la commande cargo vendor. Le fichier .cargo/config.toml pourrait également être ajouté à votre répertoire ~/.cargo/config.toml pour être utilisé par tous vos projets.

VENDOR ET LES DÉPENDANCES GIT

Les dépendances de type git sont également copiées dans le répertoire de fournisseurs. Pour que Cargo les utilise, vous devrez peut-être créer des entrées [replace] dans votre fichier .cargo/config.toml.

Par exemple, si vous avez une dépendance git comme ceci :

[dependencies]
my-git-crate = { git = "https://github.com/user/my-git-crate.git", branch = "main" }

Vous devrez ajouter ce qui suit à votre .cargo/config.toml :

[replace."https://github.com/user/my-git-crate.git"]
git = "path/to/vendor/my-git-crate-local"

Note : Le chemin path/to/vendor/my-git-crate-local doit correspondre à l'endroit où cargo vendor a copié la dépendance git. Si vous utilisez l'option --versioned-dirs, le chemin sera légèrement différent.

EXEMPLES

1.Mettre en dépôt toutes les dépendances dans un dossier local « vendor » 
cargo vendor
2.Mettre en dépôt toutes les dépendances dans un dossier local « third-party/vendor » 
cargo vendor third-party/vendor
3.Mettre en dépôt l'espace de travail courant ainsi qu'un autre dans « vendor » 
cargo vendor -s ../path/to/Cargo.toml
4.Mettre en dépôt et rediriger les configurations de dépôt nécessaires vers un fichier de configuration. 
cargo vendor > path/to/my/cargo/config.toml
