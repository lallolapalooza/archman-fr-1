L'appelant doit libérer toute mémoire libérable lorsque l'état de capacités dans la mémoire de travail n'est plus requis, en appelant cap_free() avec le cap_t comme argument. cap_set_proc() définit les valeurs de tous les indicateurs de capacités pour toutes les capacités dans l'état de capacités identifié par cap_p.

Le

nouvel état de capacités du processus sera entièrement déterminé par le contenu de cap_p lors du retour réussi de cette fonction. Si un indicateur dans cap_p est défini pour une capacité actuellement non autorisée pour le processus appelant, la fonction échouera et l'état de capacités du processus restera inchangé. cap_get_pid() renvoie un cap_t, voir cap_init(3), avec les capacités du processus connu de l'appelant sous le nom de pid. Si pid vaut 0, les capacités

du

processus appelant sont renvoyées. Ces informations peuvent également être obtenues à partir du fichier /proc/<pid>/status. (Les entrées de ce fichier peuvent être traduites avec la ligne de commande capsh --decode= XXX.) Lorsque l'appelant opère dans un espace de noms ( CLONE_NEWPID), l'argument numérique pid est interprété dans la plage de cet espacede noms. Ainsi, la notion qu'a l'appelant du pid cible peutdifférer de celle du processus cible lorsqu'ils opèrent dans des espaces de noms pid différents. Voir pid_namespaces(7) pour plus de détails. De plus, la valeur cap_t renvoyée contient les capacités que le pid cible pense posséder. Si la cible opère dans un espace de noms ( CLONE_NEWUSER), le privilège global de ces capacités d'espace de noms utilisateur peut être considérablement réduit. Voir user_namespaces(7) pour plus de détails.cap_get_bound() avec un cap comme argument renvoie la valeur actuelle de cet indicateur de capacité de l'ensemble de délimitation en vigueur pour le processus

Pour être de manière significative sécurisé, cependant, les ensembles de capacités doivent être en miroired by all threads within a common program because threads are not memory isolated. As a workaround for this, libcap is packaged with a separate POSIX semantics system call library: libpsx. If your program uses POSIX threads, to achieve meaningful POSIX semantics capability manipulation, you should link your program
