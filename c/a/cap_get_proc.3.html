L'appelant doit libérer toute mémoire libérable lorsque l'état de capacités dans la mémoire de travail n'est plus requis, en appelant cap_free() avec le cap_t comme argument. cap_set_proc() définit les valeurs de tous les indicateurs de capacités pour toutes les capacités de l'état de

capacités

identifié par cap_p. Le nouvel état de capacités du processus sera complètement déterminé par le contenu de cap_p lors du retour réussi de cette fonction. Si un indicateur dans cap_p est défini pour une capacité actuellement non autorisée pour le processus appelant, la fonction échouera et l'état de capacités du processus restera inchangé. cap_get_pid() renvoie un cap_t, voir cap_init(3), avec les capacités du processus connu de l'appelant sous le nom de pid. Si pid

vaut

0, les capacités du processus appelant sont renvoyées. Ces informations peuvent également être obtenues à partir du fichier /proc/<pid> /status. (Les entrées de ce fichier peuvent être traduites avec la ligne de commande capsh --decode= XXX.) Lorsque l'appelant opère dans un espace de noms ( CLONE_NEWPID), l'argument numérique pid est interprétédans la plage de cet espace de noms. Ainsi, la notion de pidcible de l'appelant peut différer de celle du processus cible lorsqu'ils opèrent dans des espaces de noms pid différents. Voir pid_namespaces(7) pour plus de détails. De plus, la valeur cap_t renvoyée contient les capacités que la pid cible pense avoir. Si la cible opère dans un espace de noms ( CLONE_NEWUSER), le privilège global de ces capacités d'espace de noms utilisateur peut être considérablement réduit. C'est-à-dire que la modification des ensembles de capacités n'affecte par défaut que le thread en cours d'exécution. Pour être significativement sûr, cependant, les ensembles de capacités doivent être répliqués par tous les threads d'un programme commun car les threads ne sont pas isolés en mémoire. capgetp() et

La bibliothèque supporte aussi les fonctions dépréciées

capgetp() tente d'obtenir les capacités d'un autre processus ; stockant les capacités dans un cap_d pré-alloué. Voir cap_init() pour des informations sur l'allocation d'un ensemble de capacités vide. Cette fonction est dépréciée ; vous devriez utiliser cap_get_p

id().

capsetp() tente de configurer les capacités du processus appelant ou d'un ou plusieurs autres processus, pid. Notez que la configuration des capacités d'un autre processus n'est possible que sur les anciens noyaux qui ne fournissent pas de support VFS pour la configuration des capacités de fichier. Voir capset(2) pour des informations sur les noyaux qui fournissent un tel

support.

Si pid est positif, il se réfère à un processus spécifique ; s'il est zéro, il se réfère au processus appelant ; -1 se réfère à tous les processus autres que le processus appelant et le processus '1' (typiquement init(8)) ; les autres valeurs négatives se réfèrent au groupe de processus

-pid.

Afin d'utiliser cette fonction, le noyau doit la supporter et le processus appelant doit avoir CAP_SETPCAP activé dans son ensemble de capacités Effectives. Les capacités configurées dans le ou les processus cibles sont celles contenues dans cap_d

.

Les noyaux qui supportent les capacités de système de fichiers redéfinissent la sémantique de CAP_SETPCAP et sur de tels systèmes, capsetp() échouera toujours pour toute cible différente du processus appelant. capsetp() retourne zéro pour succès, et -1 en cas

d'échec.

Sur les noyaux où cela est (était) supporté, capsetp() devrait être utilisé avec précaution. Elle existait principalement pour surmonter un manque précoce de support pour les capacités dans les systèmes de fichiers supportés par Linux. Notez que sur les anciens noyaux où capsetp() pouvait être utilisé pour configurer les capacités d'un autre processus, les seuls processus qui avaient CAP_SETPCAP disponible pour eux par défaut étaient les processus démarrés en tant que threads du noyau. (Typiquement cela inclut init(8), kflushd et kswapd.) Une recompilation

    cap_t caps;
    const cap_value_t cap_list[2] = {CAP_FOWNER, CAP_SETFCAP};

        /* handle error */
    caps = cap_get_proc();
    if (caps == NULL)
        /* handle error */;
    if (cap_set_flag(caps, CAP_EFFECTIVE, 2, cap_list, CAP_SET) == -1)
        /* handle error */;
    if (cap_set_proc(caps) == -1)
        /* handle error */;
    if (cap_free(caps) == -1)
        /* handle error */;
