CAPABILITY.CONF(5) Manuel des formats de fichiers CAPABILITY.CONF(5)

NOM

capability.conf - Fichier de configuration du module pam_cap

SYNTAXE

/etc/security/capability.conf

DESCRIPTION

La syntaxe des lignes de ce fichier de configuration est :

# <-- Le caractère « # » précède un commentaire

<IAB><ESPACE><QUI>

Où <IAB> fait référence au format textuel d'un tuple de capacité IAB héritable, voir cap_text_formats(7) , ou aux mots all ou none.

Le mot réservé all n'accorde *pas* *toutes les* *capacités héritables*, mais agit comme une simple *transmission* pour toutes les capacités de tuple IAB prévalentes. Le mot réservé none fait référence à un ensemble de capacités *Héritables* vide (et par extension un vecteur *Ambiant* vide).

Ici <QUI> fait référence aux noms d'utilisateurs PAM séparés par des espaces qui recevront le tuple IAB spécifié. Un nom précédé du caractère @ fait référence aux utilisateurs définis localement dans /etc/group etc. répertoriés sous ce nom de groupe. Un astérisque « * » peut être utilisé pour désigner tous les utilisateurs.

L'analyse du fichier choisit la première ligne qui s'applique à l'utilisateur s'authentifiant, et tente de l'appliquer et seulement elle.

Exemples de syntaxe valide :

# seul root peut conserver ce qu'il avait
all                                root
# ceci devrait s'appliquer uniquement à l'utilisateur beta, qui aura
# cap_chown retiré de son ensemble de limites.
!cap_chown                         beta
# le prochain devrait attraper les membres du groupe « three »
# leur accordant cap_setuid et cap_chown
cap_setuid,cap_chown               @three
# ceci s'appliquerait à beta et gamma, mais beta se voit déjà
# refuser cap_chown plus haut. De plus, si gamma est
# dans le groupe « three », il n'atteindrait pas cette ligne.
cap_chown                          beta gamma
# les membres du groupe « one » reçoivent la capacité héritable cap_setuid,
# mais cap_chown est retiré de leur ensemble de limites.
!cap_chown,cap_setuid              @one
# l'utilisateur alpha obtient une capacité ambiante (sauf s'il est également
# membre des groupes « three » ou « one »).
^cap_setuid                        alpha
# l'utilisateur delta (s'il n'est pas membre des groupes « one » et « three »)
# obtiendra les capacités ambiantes cap_chown et cap_setgid, mais aura
# cap_setuid retiré de son ensemble de limites.
^cap_chown,^cap_setgid,!cap_setuid delta
# tous les membres restants du groupe « four » obtiendront la capacité
# héritable cap_setuid.
cap_setuid                         @four

VOIR AUSSI

pam_cap(8), cap_iab(3), cap_text_formats(7).
