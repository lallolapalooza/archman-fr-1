cacheflush(2) Manuel des appels système cacheflush(2)

NOM

cacheflush - vide le contenu du cache d'instructions et/ou de données

BIBLIOTHÈQUE

Bibliothèque C standard (libc, -lc)

SYNTAXE

#include <sys/cachectl.h>
int cacheflush(int nbytes;
               void addr[nbytes], int nbytes, int cache);

Note : Sur certaines architectures, il n'y a pas de wrapper glibc pour cet appel système ; voir VERSIONS.

DESCRIPTION

cacheflush() vide le contenu du ou des caches indiqués pour les adresses utilisateur dans l'intervalle addr à (addr+nbytes-1). cache peut être l'une des valeurs suivantes :

ICACHE
Vide le cache d'instructions.
DCACHE
Écrit en mémoire et invalide les lignes de cache valides affectées.
BCACHE
Identique à (ICACHE|DCACHE).

VALEUR DE RETOUR

cacheflush() retourne 0 en cas de succès. En cas d'erreur, il retourne -1 et définit errno pour indiquer l'erreur.

ERREURS

EFAULT
Tout ou partie de l'intervalle d'adresses addr à (addr+nbytes-1) n'est pas accessible.
EINVAL
cache n'est ni ICACHE, ni DCACHE, ni BCACHE (mais voir BUGS).

VERSIONS

Il ne faut pas utiliser cacheflush() dans des programmes destinés à être portables. Sous Linux, cet appel système est apparu pour la première fois sur l'architecture MIPS, mais de nos jours, Linux fournit un appel système cacheflush() sur certaines autres architectures, mais avec des arguments différents.

Variantes spécifiques à l'architecture

glibc fournit un wrapper pour cet appel système, avec le prototype indiqué dans SYNTAXE, pour les architectures suivantes : ARC, CSKY, MIPS et NIOS2.

Sur certaines autres architectures, Linux fournit cet appel système, avec des arguments différents :

M68K :
int cacheflush(unsigned long addr, int scope, int cache,
               unsigned long size);
SH :
int cacheflush(unsigned long addr, unsigned long size, int op);
NDS32 :
int cacheflush(unsigned int start, unsigned int end, int cache);

Sur les architectures ci-dessus, glibc ne fournit pas de wrapper pour cet appel système ; appelez-le via syscall(2).

Alternative GCC

Sauf si vous avez besoin du contrôle plus fin que cet appel système fournit, vous voudrez probablement utiliser la fonction intégrée GCC __builtin___clear_cache(), qui fournit une interface portable sur les plateformes supportées par GCC et les compilateurs compatibles :


void __builtin___clear_cache(void *begin, void *end);

Sur les plateformes qui ne nécessitent pas de vidage du cache d'instructions, __builtin___clear_cache() n'a aucun effet.

Note : Sur certains compilateurs compatibles GCC, le prototype de cette fonction intégrée utilise char * au lieu de void * pour les paramètres.

NORMES

Historiquement, cet appel système était disponible sur toutes les variantes UNIX MIPS, y compris RISC/os, IRIX, Ultrix, NetBSD, OpenBSD et FreeBSD (et aussi sur certains systèmes d'exploitation MIPS non-UNIX), de sorte que l'existence de cet appel dans les systèmes d'exploitation MIPS est une norme de facto.

BOGUES

Les noyaux Linux antérieurs à Linux 2.6.11 ignorent les arguments addr et nbytes, ce qui rend cette fonction assez coûteuse. Par conséquent, tout le cache est toujours vidé.

Cette fonction se comporte toujours comme si BCACHE avait été passé pour l'argument cache et n'effectue aucune vérification d'erreur sur l'argument cache.
