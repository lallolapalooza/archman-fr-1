RÉSUM

use Capture::Tiny ':all';
# capture depuis une commande externe
($stdout, $stderr, $exit) = capture {
  system( $cmd, @args );
};
# capture depuis un code arbitraire (Perl ou externe)
($stdout, $stderr, @result) = capture {
  # votre code ici
};
# capture d'une sortie partielle ou fusionnée
$stdout = capture_stdout { ... };
$stderr = capture_stderr { ... };
$merged = capture_merged { ... };
# tee de la sortie
($stdout, $stderr) = tee {
  # votre code ici
};
$stdout = tee_stdout { ... };
$stderr = tee_stderr { ... };
$merged = tee_merged { ...
}
;

DESCRIPTIO

N

Capture::Tiny fournit un moyen simple et portable de capturer presque tout ce qui est envoyé à STDOUT ou STDERR, que cela provienne de Perl, de code XS ou d'un progra

mme externe. En option, la sortie peut être dupliquée (tee) afin d'être capturée tout en étant transmise aux descripteurs de fichiers d'origine. Oui, cela fonctionne m
ême sur Windows (généralement). Arrêtez de deviner lequel des dizaines de modules de capture utiliser dans une situation particulière et utilisez simplement celui-ci.

UTILISATI

ON

Les fonctions suivantes sont disponibles. Aucune n'est exportée par

défaut.

captur

e 
($stdout, $stderr, @result) = capture \&
$stdout = capture
\&

La fonction "capture" prend une référence de code et renvoie ce qui est envoyé à STDOUT et STDERR ainsi que toutes les valeurs de retour de la référence de code. En contexte scalaire, elle renvoie uniquement STDOUT. Si aucune sortie n'a été reçue pour un descripteur de fichier, elle renvoie une chaîne vide pour ce descripteur. Quel que soit le contexte d'appel, toute la sortie est capturée -- rien n'est transmis aux descripteurs de fichiers

existants.

Elle est prototypée pour prendre une référence de sous-routine comme argument. Ainsi, elle peut être appelée sous forme de bloc

: 
($stdout, $stderr) = capture {
  # votre code ici ...
}
;

Notez que la référence de code est évaluée en contexte liste. Si vous souhaitez forcer le contexte scalaire sur la valeur de retour, vous devez utiliser le mot-clé "sc

alar". 
($stdout, $stderr, $count) = capture {
  my @list = qw/one two three/;
  return scalar @list; # $count sera 3
}
;

Notez également qu'à l'intérieur de la référence de code, la variable @_ sera vide. N'utilisez donc pas les arguments d'une sous-routine englobante sans les copier d'abord dans un tableau

: 
sub wont_work {
  my ($stdout, $stderr) = capture { do_stuff( @_ ) };    # INCORRECT
  ...
}
sub will_work {
  my @args = @_;
  my ($stdout, $stderr) = capture { do_stuff( @args ) }; # CORRECT
  ...
}

Les captures sont normalement effectuées vers un descripteur de fichier temporaire anonyme. Pour capturer via un fichier nommé (par ex. pour surveiller de l'extérieur une capture de longue durée), fournissez des descripteurs de fichier personnalisés sous forme de liste d'options en fin d'appel

: 
my $out_fh = IO::File->new("out.txt", "w+");
my $err_fh = IO::File->new("err.txt", "w+");
capture { ... } stdout => $out_fh, stderr =>
$err_fh;

Les descripteurs de fichiers doivent être en lecture/écriture et cherchables. Modifier les fichiers ou les descripteurs de fichiers pendant une opération de capture donnera des résultats imprévisibles. Les couches IO existantes sur ceux-ci peuvent être modifiées par la

capture.

Lorsqu'elle est appelée en contexte void, "capture" économise de la mémoire et du temps en ne

relisant pas depuis le
s descripteurs de capture.

LIMITATION

S

Portabilit

é

La portabilité est un objectif, pas une garantie. "tee" nécessite fork, sauf sur Windows où "system(1, @cmd)" est utilisé à la place. Pas encore testé sur des plateformes particulièrement exotiques. Voir la Matrice des testeurs CPAN http://matrix.cpantesters.org/?dist=Capture-Tiny

pour les résultats
de test par plateforme.

Couches

PerlIO

Capture::Tiny fait de son mieux pour préserver les couches PerlIO telles que ':utf8' ou ':crlf' lors de la capture (uniquement pour Perl 5.8.1+). Les couches doivent être appliquées à STDOUT ou STDERR avant l'appel à "capture" ou "tee". Cela peut ne pas fonctionner pour les des

cripteurs de fichier
liés (voir ci-dessous).

Modification des descripteurs de fichier avant la

capture

En règle générale, vous devriez effectuer peu ou pas de manipulation des descripteurs de fichiers d'entrée/sortie standard avant d'utiliser Capture::Tiny. En particulier, fermer, rouvrir, localiser ou lier les descripteurs de fichiers standard avant la capture peut provoquer divers comportements inattendus, indésirables et/ou peu fiables, comme décrit ci-dessous. Capture::Tiny fait de son mieux pour compenser ces situations, mais les résultats peuvent ne pas être ceux que vous

désirez.

Descripteurs de fichier

fermés

Capture::Tiny fonctionnera même si STDIN, STDOUT ou STDERR ont étéont été précédemment fermés. Cependant, comme ils seront rouverts pour capturer ou répliquer (tee) la sortie, tout code à l'intérieur du bloc capturé qui dépend du fait de les trouver fermés ne les trouvera bien sûr pas fermés. S'ils étaient fermés au départ, Capture::Tiny les refermera lorsque le bloc de capture se

termine.

Notez que cette réouverture se produira même pour STDIN ou un descripteur de fichier non capturé afin de s'assurer que le descripteur de fichier utilisé pour la capture n'est pas ouvert sur le descripteur de fichier 0, car cela cause des problèmes sur diverses

plateformes.

Avant Perl 5.12, un STDIN fermé combiné à PERL_UNICODE=D fuit des descripteurs de fichier et casse également tee() pour des raisons indéterminées. Donc ne faites pas

cela.

Descripteurs de fichier

localisés

Si le code localise l'un des descripteurs de fichier standard de Perl avant la capture, la capture affectera les descripteurs de fichier localisés et non les originaux. Les appels système externes ne sont pas affectés par la localisation d'un descripteur de fichier en Perl et continueront d'envoyer la sortie vers les descripteurs de fichier originaux (qui ne seront donc pas capturés)

.

Descripteurs de fichier

scalaire

Si STDOUT ou STDERR sont réouverts vers des descripteurs de fichier scalaire avant l'appel à "capture" ou "tee", alors Capture::Tiny remplacera le descripteur de fichier de sortie pendant la durée de l'appel "capture" ou "tee" puis, pour "tee", enverra la sortie capturée vers le descripteur de fichier de sortie une fois la capture terminée. (Nécessite Perl 5.

8)

Capture::Tiny tente de préserver la sémantique de STDIN ouvert sur une référence scalaire, mais notez que les processus externes ne pourront pas lire depuis un tel descripteur. Capture::Tiny essaie de s'assurer que les processus externes liront à la place depuis le périphérique nul, mais cela n'est pas

garanti.

Descripteurs de fichier de sortie liés

(tied)

Si STDOUT ou STDERR sont liés avant l'appel à "capture" ou "tee", alors Capture::Tiny tentera de remplacer le lien pour la durée de l'appel "capture" ou "tee" puis enverra la sortie capturée vers le descripteur de fichier lié une fois la capture terminée. (Nécessite Perl 5.

8)

Capture::Tiny peut ne pas réussir à renvoyer des données encodées UTF-8 vers un descripteur de fichier STDOUT ou STDERR lié. Les caractères peuvent apparaître sous forme d'octets. Si le descripteur de fichier lié est basé sur Tie::StdHandle, alors Capture::Tiny tentera de déterminer des couches appropriées comme ":utf8" à partir du descripteur de fichier sous-jacent et fera ce qu'il

faut.

Descripteur de fichier d'entrée

lié

Capture::Tiny tente de préserver la sémantique de STDIN lié, mais cela nécessite Perl 5.8 et n'est pas entièrement prévisible. Les processus externes ne pourront pas lire depuis un tel

descripteur.

À moins que d'avoir STDIN lié soit crucial, il peut être plus sûr de localiser STDIN lors de la capture

: 
my ($out, $err) = do { local *STDIN; capture { ... }
}
;

Modifier les descripteurs de fichier pendant une

capture

Tenter de modifier STDIN, STDOUT ou STDERR pendant "capture" ou "tee" causera presque certainement des problèmes. Ne faites pas

cela.

Forker à l'intérieur d'une

capture

Les fork ne sont pas portables. Le comportement des descripteurs de fichier pendant un fork l'est encore moins. Si Capture::Tiny détecte qu'un fork s'est produit au cours d'une capture, il prendra un raccourci dans le processus enfant et renverra des chaînes vides pour les captures. D'autres problèmes peuvent également survenir dans l'enfant ou le parent. Il n'est pas recommandé de forker dans un bloc de

capture.

Utiliser des

threads

Les descripteurs de fichier sont globaux. Mélanger les E/S et les captures dans différents threads sans coordination causera des problèmes. De plus, les threads sont officiellement

déconseillés.

Abandonner des privilèges pendant une

capture

Si vous abandonnez des privilèges pendant une capture,

les fichiers temporaires créés pour faciliter la
capture peuvent ne pas être nettoyés par la suite.

PERL_CAPTURE_TINY_TIMEOU

T

Capture::Tiny utilise des sous-processus en interne pour "tee". Par défaut, Capture::Tiny expirera avec une erreur si de tels sous-processus ne sont pas prêts à recevoir des données dans les 30 secondes (ou quelle que soit la valeur de $Capture::Tiny::TIMEOUT). Un délai d'attente alternatif peut être spécifié en définissant la variable d'environnement "PERL_CAPTURE_TINY_TIMEOUT". La définir à zéro désactivera les délais d'attente. NOTE, cela n'applique pas de délai d'attente à la référence de code capturée -- cela e

mpêche seulement Capture::Tiny lui-même de bl
oquer votre processus en attendant que se
s processus enfants soient prêts à continuer.

VOIR

AUSSI

Ce module a été inspiré par IO::CaptureOutput, qui fournit des fonctionnalités similaires sans la capacité de répliquer (tee) la sortie et avec du code et une API plus compliqués. IO::CaptureOutput ne gère pas les couches ni la plupart des cas inhabituels décrits dans la section "LIMITATIONS" et je ne le recommande

plus.

Il existe de nombreux autres modules CPAN qui fournissent une sorte de capture de sortie, bien qu'avec diverses limitations qui ne les rendent appropriés que dans des circonstances particulières. J'en oublie probablement certains. La longue liste est fournie pour montrer pourquoi j'ai estimé que Capture::Tiny était

nécessaire.
