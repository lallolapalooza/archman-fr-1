NOM

CA.pl - interface plus conviviale pour les programmes de certificats OpenSSL

SYNOPSIS

CA.pl -? | -h | -help

CA.pl -newcert | -newreq | -newreq-nodes | -xsign | -sign | -signCA | -signcert | -crl | -newca [-extra-cmd paramètre]

CA.pl -pkcs12 [nomdecertificat]

CA.pl -verify fichièredescertificats ...

CA.pl -revoke fichièredescertificats [raison]

DESCRIPTION

Le script CA.pl est un script perl qui fournit les arguments de ligne de commande pertinents à la commande openssl(1) pour certaines opérations courantes sur les certificats. Il vise à simplifier le processus de création et de gestion des certificats grâce à l'utilisation de quelques options simples.

Le script est destiné à être une interface simple pour le programme openssl(1) à l'usage des débutants. Son comportement n'est pas toujours celui souhaité. Pour un meilleur contrôle sur le comportement des commandes de certificats, appelez directement la commande openssl(1) .

La plupart des noms de fichiers mentionnés ci-dessous peuvent être modifiés en éditant le script CA.pl .

Dans certains environnements, il peut ne pas être possible d'exécuter directement le script CA.pl (par exemple sous Win32) et l'emplacement du fichier de configuration par défaut peut être incorrect. Dans ce cas, la commande :

perl -S CA.pl

peut être utilisée et la variable d'environnement OPENSSL_CONF peut être définie pour pointer vers le chemin correct du fichier de configuration.

OPTIONS

-?, -h, -help
Affiche un message d'utilisation.
-newcert
Crée un nouveau certificat auto-signé. La clé privée est écrite dans le fichier newkey.pem et la demande est écrite dans le fichier newreq.pem. Appelle openssl-req(1).
-newreq
Crée une nouvelle demande de certificat. La clé privée est écrite dans le fichier newkey.pem et la demande est écrite dans le fichier newreq.pem. Exécute openssl-req(1) en interne.
-newreq-nodes
Est similaire à -newreq sauf que la clé privée ne sera pas chiffrée. Utilise openssl-req(1).
-newca
Crée une nouvelle hiérarchie d'autorité de certification (AC) pour une utilisation avec le programme ca (ou les options -signcert et -xsign ). L'utilisateur est invité à entrer le nom de fichier des certificats de l'AC (qui devrait également contenir la clé privée) ou, en appuyant sur ENTRÉE, les détails de l'AC lui seront demandés. Les fichiers et répertoires pertinents sont créés dans un répertoire nommé demoCA dans le répertoire courant. Utilise openssl-req(1) et openssl-ca(1).

Si le répertoire demoCA existe déjà, la commande -newca ne l'écrasera pas et ne fera rien. Cela peut se produire si un appel précédent utilisant l'option -newca s'est terminé anormalement. Pour obtenir le comportement correct, supprimez le répertoire s'il existe déjà.

-pkcs12
Crée un fichier PKCS#12 contenant le certificat utilisateur, la clé privée et le certificat de l'AC. Il s'attend à ce que le certificat utilisateur et la clé privée se trouvent dans le fichier newcert.pem et le certificat de l'AC dans le fichier demoCA/cacert.pem, il crée un fichier newcert.p12. Cette commande peut donc être appelée après l'option -sign . Le fichier PKCS#12 peut être importé directement dans un navigateur. S'il y a un argument supplémentaire sur la ligne de commande, il sera utilisé comme « nom convivial » pour le certificat (qui est généralement affiché dans la liste du navigateur), sinon le nom « My Certificate » est utilisé. Délègue le travail à openssl-pkcs12(1).
-sign, -signcert, -xsign
Appelle la commande openssl-ca(1) pour signer une demande de certificat. Elle s'attend à ce que la demande se trouve dans le fichier newreq.pem. Le nouveau certificat est écrit dans le fichier newcert.pem sauf dans le cas de l'option -xsign où il est écrit sur la sortie standard.
-signCA
Cette option est la même que l'option -sign sauf qu'elle utilise la section de configuration v3_ca et rend donc la demande signée un certificat d'AC valide. C'est utile lors de la création d'une AC intermédiaire à partir d'une AC racine. Des paramètres supplémentaires sont passés à openssl-ca(1).
-signcert
Cette option est la même que -sign sauf qu'elle s'attend à ce qu'un certificat auto-signé soit présent dans le fichier newreq.pem. Des paramètres supplémentaires sont passés à openssl-x509(1) et openssl-ca(1).
-crl
Génère une CRL. Exécute openssl-ca(1).
-revoke fichièredescertificats [raison]
Révoque le certificat contenu dans le fichièredescertificatsspécifié. Une raison optionnelle peut être spécifiée, et doit être l'une des suivantes : unspecified, keyCompromise, CACompromise, affiliationChanged, superseded, cessationOfOperation, certificateHold, ou removeFromCRL. Utilise openssl-ca(1).
-verify
Vérifie les certificats par rapport au certificat de l'AC pour demoCA. Si aucun certificat n'est spécifié sur la ligne de commande, elle essaie de vérifier le fichier newcert.pem. Appelle openssl-verify(1).
-extra-cmd paramètre
Pour chaque option extra-cmd, passe le paramètre à la sous-commande openssl(1) portant le même nom que cmd, si cette sous-commande est appelée. Par exemple, si openssl-req(1) est appelée, le paramètre donné avec -extra-req lui sera passé. Pour les paramètres à plusieurs mots, répétez l'option ou mettez les paramètres entre guillemets pour qu'ils ressemblent à un seul mot pour votre shell. Consultez la documentation de chaque commande pour plus d'informations.

EXEMPLES

Créer une hiérarchie d'AC :

CA.pl -newca

Exemple complet de création de certificat : créer une AC, créer une demande, signer la demande et enfin créer un fichier PKCS#12 la contenant.

CA.pl -newca
CA.pl -newreq
CA.pl -sign
CA.pl -pkcs12 "My Test Certificate"

ENVIRONNEMENT

La variable d'environnement OPENSSL peut être utilisée pour spécifier le nom du programme OpenSSL. Il peut s'agir d'un chemin complet ou d'un chemin relatif.

La variable d'environnement OPENSSL_CONFIG peut être utilisée pour spécifier une option de configuration et sa valeur aux commandes req et ca appelées par ce script. Sa valeur doit être l'option et le chemin, comme dans "-config /path/to/conf-file".
