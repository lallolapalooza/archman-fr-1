NOM

cargo-bench — Exécute les benchmarks d'un paquet

SYNTAXE

cargo bench [options] [nom_bench] [-- options_bench]

DESCRIPTION

Compile et exécute les benchmarks.

L'argument de filtrage de benchmark nom_bench et tous les arguments suivant les deux tirets (--) sont passés aux exécutables de benchmark et donc à libtest (le framework de test unitaire et de micro-benchmark intégré à rustc). Si vous passez des arguments à la fois à Cargo et à l'exécutable, ceux après -- vont à l'exécutable, ceux avant vont à Cargo. Pour plus de détails sur les arguments de libtest, voir la sortie de cargo bench -- --help et consulter le chapitre du livre rustc sur le fonctionnement des tests à https://doc.rust-lang.org/rustc/tests/index.html.

Par exemple, ceci n'exécutera que le benchmark nommé foo (et ignorera d'autres benchmarks nommés de manière similaire comme foobar) :

cargo bench -- foo --exact

Les benchmarks sont construits avec l'option --test de rustc, qui crée un exécutable spécial en liant votre code à libtest. L'exécutable exécute automatiquement toutes les fonctions annotées avec l'attribut #[bench]. Cargo passe le drapeau --bench au harnais de test pour lui dire de n'exécuter que les benchmarks, que le harnais soit libtest ou un harnais personnalisé.

Le harnais libtest peut être désactivé en réglant harness = false dans les paramètres du manifeste de la cible, auquel cas votre code devra fournir sa propre fonction main pour gérer l'exécution des benchmarks.

Note : L'attribut #[bench] https://doc.rust-lang.org/nightly/unstable-book/library-features/test.html est actuellement instable et uniquement disponible sur le canal nightly https://doc.rust-lang.org/book/appendix-07-nightly-rust.html. Il existe certains paquets disponibles sur crates.io https://crates.io/keywords/benchmark qui peuvent aider à exécuter des benchmarks sur le canal stable, tels que Criterion https://crates.io/crates/criterion.

Par défaut, cargo bench utilise le profil bench https://doc.rust-lang.org/cargo/reference/profiles.html#bench, qui active les optimisations et désactive les informations de débogage. Si vous avez besoin de déboguer un benchmark, vous pouvez utiliser l'option de ligne de commande --profile=dev pour passer au profil dev. Vous pourrez ensuite exécuter le benchmark activé pour le débogage dans un débogueur.

Répertoire de travail des benchmarks

Le répertoire de travail de chaque benchmark est défini sur le répertoire racine du paquet auquel le benchmark appartient. Définir le répertoire de travail des benchmarks sur le répertoire racine du paquet permet aux benchmarks d'accéder de manière fiable aux fichiers du paquet en utilisant des chemins relatifs, peu importe d'où cargo bench a été exécuté.

OPTIONS

Options de benchmark

--no-run

Compile, mais n'exécute pas les benchmarks.

--no-fail-fast

Exécute tous les benchmarks indépendamment de leur échec. Sans ce drapeau, Cargo s'arrêtera après le premier échec d'un exécutable. Le harnais de test Rust exécutera tous les benchmarks au sein de l'exécutable jusqu'à leur complétion, ce drapeau ne s'applique qu'à l'exécutable dans son ensemble.

Sélection de paquets

Par défaut, lorsqu'aucune option de sélection de paquet n'est donnée, les paquets sélectionnés dépendent du fichier manifeste sélectionné (basé sur le répertoire de travail actuel si --manifest-path n'est pas donné). Si le manifeste est la racine d'un espace de travail, alors les membres par défaut de l'espace de travail sont sélectionnés, sinon seul le paquet défini par le manifeste sera sélectionné.

Les membres par défaut d'un espace de travail peuvent être définis explicitement avec la clé workspace.default-members dans le manifeste racine. Si celle-ci n'est pas définie, un espace de travail virtuel inclura tous les membres de l'espace de travail (équivalent à passer --workspace), et un espace de travail non virtuel inclura uniquement le crate racine lui-même.

-p spec…, --package spec…

Benchmark uniquement les paquets spécifiés. Voir cargo-pkgid(1) pour le format SPEC. Ce drapeau peut être spécifié plusieurs fois et supporte les modèles glob Unix courants comme *, ? et []. Cependant, pour éviter que votre shell n'étende accidentellement les modèles glob avant que Cargo ne les traite, vous devez utiliser des guillemets simples ou doubles autour de chaque modèle.

--workspace

Benchmark tous les membres de l'espace de travail.

--all

Alias obsolète pour --workspace.

--exclude SPEC…

Exclut les paquets spécifiés. Doit être utilisé en conjonction avec le drapeau --workspace. Ce drapeau peut être spécifié plusieurs fois et supporte les modèles glob Unix courants comme *, ? et []. Cependant, pour éviter que votre shell n'étende accidentellement les modèles glob avant que Cargo ne les traite, vous devez utiliser des guillemets simples ou doubles autour de chaque modèle.

Sélection de cible

Lorsqu'aucune option de sélection de cible n'est donnée, cargo bench construira les cibles suivantes des paquets sélectionnés :

•lib — utilisé pour lier avec les binaires et les benchmarks
•bins (uniquement si des cibles de benchmark sont construites et que les fonctionnalités requises sont disponibles)
•lib comme benchmark
•bins comme benchmarks
•cibles de benchmark

Le comportement par défaut peut être modifié en réglant le drapeau bench pour la cible dans les paramètres du manifeste. Le réglage des exemples sur bench = true construira et exécutera l'exemple comme un benchmark, remplaçant la fonction main de l'exemple par le harnais libtest.

Le réglage des cibles sur bench = false les empêchera d'être benchmarkées par défaut. Les options de sélection de cible qui prennent une cible par nom (comme --example foo) ignoreront le drapeau bench et benchmarkeront toujours la cible donnée.

Voir Configuration d'une cible https://doc.rust-lang.org/cargo/reference/cargo-targets.html#configuring-a-target pour plus d'informations sur les paramètres par cible.

Les cibles binaires sont construites automatiquement s'il existe un test d'intégration ou un benchmark sélectionné pour être benchmarké. Cela permet à un test d'intégration d'exécuter le binaire pour l'exercer et tester son comportement. La variable d'environnement CARGO_BIN_EXE_<nom> https://doc.rust-lang.org/cargo/reference/environment-variables.html#environment-variables-cargo-sets-for-crates est définie lorsque le test d'intégration est construit afin qu'il puisse utiliser la macro env https://doc.rust-lang.org/std/macro.env.html pour localiser l'exécutable.

Passer des options de sélection de cible benchmarkera uniquement les cibles spécifiées.

Notez que les drapeaux --bin, --example, --test et --bench supportent également les modèles glob Unix courants comme *, ? et []. Cependant, pour éviter que votre shell n'étende accidentellement les modèles glob avant que Cargo ne les traite, vous devez utiliser des guillemets simples ou doubles autour de chaque modèle glob.

--lib

Benchmark la bibliothèque du paquet.

--bin nom…

Benchmark le binaire spécifié. Ce drapeau peut être spécifié plusieurs fois et supporte les modèles glob courants.

--test nom…

Benchmark le test spécifié. Ce drapeau peut être spécifié plusieurs fois et supporte les modèles glob courants.

--example nom…

Benchmark l'exemple spécifié. Ce drapeau peut être spécifié plusieurs fois et supporte les modèles glob courants.

--bench nom…

Benchmark le benchmark spécifié. Ce drapeau peut être spécifié plusieurs fois et supporte les modèles glob courants.

Options de couplage

--release

Utilise le profil de construction release. Le profil release est également activé par défaut pour les benchmarks.

--profile profile-name

Utilise un profil de construction personnalisé.

--features feat…

Espace séparé des fonctionnalités à activer. Les fonctionnalités du manifeste sont activées en utilisant la syntaxe --features nom-fonctionnalite. Les fonctionnalités de l'espace de travail sont activées en utilisant la syntaxe --workspace --features nom-fonctionnalite. Les fonctionnalités sont utilisées pour activer des parties spécifiques du code. Pour activer plusieurs fonctionnalités, répétez le drapeau --features.

--all-features

Active toutes les fonctionnalités du paquet.

--no-default-features

Désactive les fonctionnalités par défaut du paquet.

--target target

Benchmark pour une architecture cible spécifique. Voir cargo-build cargo-build(1) pour plus d'informations.

Options de configuration

Voir cargo build cargo-build(1) pour les options de configuration disponibles.

EXEMPLES

Exécuter tous les benchmarks dans le répertoire courant :

$ cargo bench

Exécuter un benchmark spécifique :

$ cargo bench -- foo

Exécuter un benchmark spécifique et passer des arguments à celui-ci :

$ cargo bench -- bench_name -- --exact

Construire tous les benchmarks dans un espace de travail mais ne pas les exécuter :

$ cargo bench --workspace --no-run

Benchmark le paquet my-package et ses dépendances :

$ cargo bench -p my-package

Benchmark le paquet my-package mais exclure le paquet my-dependency :

$ cargo bench --workspace --exclude my-dependency

Benchmark la bibliothèque du paquet :

$ cargo bench --lib

Benchmark tous les binaires du paquet :

$ cargo bench --bin '*'

Benchmark le binaire nommé my-binary :

$ cargo bench --bin my-binary
