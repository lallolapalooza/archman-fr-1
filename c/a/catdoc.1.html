DESCRIPTIO

N

catdoc se comporte de manière très similaire à cat(1), mais il lit un fichier MS-Word et produit du texte lisible par l'humain sur la sortie standard. Il peut éventuellement utiliser les séquences d'échappement latex(1) pour les caractères ayant une signification particulière pour LaTeX. Il s'efforce également de reconnaître les tableaux MS-Word, bien qu'il n'essaie jamais d'écrire des en-têtes corrects pour l'environnement tabular de LaTeX. Des formats de sortie supplémentaires, tels que HTML, peuvent être facilement

définis.

catdoc n'essaie pas d'extraire les informations de mise en forme autres que les tableaux du document MS-Word ; les différents modes de sortie signifient donc principalement que différents caractères doivent être échappés et que différentes méthodes sont utilisées pour représenter les caractères absents du jeu de caractères de sortie. Voir SUBSTITUTION DE CARACTÈRES

ci-dessous.

catdoc utilise une représentation interne unicode(4) du texte, il est donc capable de convertir des textes lorsque le jeu de caractères du document source ne correspond pas au jeu de caractères du système cible. Voir JEUX DE CARACTÈRES

ci-dessous.

Si aucun nom de fichier n'est fourni, catdoc traite son entrée standard, à moins qu'il ne s'agisse d'un terminal. Il est peu probable que quelqu'un tape un document Word au clavier ; ainsi, si catdoc est invoqué sans arguments et que stdin n'est pas redirigé, il affiche un bref message d'utilisation et se termine. Le traitement de l'entrée standard (même parmi d'autres fichiers) peut être forcé en utilisant le tiret '-' comme nom de

fichier.

Par défaut, catdoc effectue un retour à la ligne pour les lignes de plus de 72 caractères et sépare les paragraphes par des lignes vides. Ce comportement peut être désactivé par l'option -w. En mode large catdoc affiche chaque paragraphe sur une seule longue ligne, adapté à l'importat

ion dans des traiteurs de texte qui ef
fectuent le retour à la ligne automatique.

JEUX DE

CARACTÈRES

Lors du traitement d'un fichier MS-Word catdoc utilise des informations sur deux jeux de caractères, généralement différents
- en entrée et en sortie. Ils sont stockés dans des fichiers texte brut dans le répertoire de bibliothèque de catdoc. Les fichiers de jeu de caractères doivent contenir deux nombres hexadécimaux séparés par des espaces - le code sur 8 bits dans le jeu de caractères et le code Unicode sur 16 bits. Tout ce qui va du signe de dièse à la fin de la ligne est ignoré, ainsi que les lignes

vides.

La distribution de catdoc inclut certains de ces jeux de caractères. Des définitions de jeu de caractères supplémentaires, directement utilisables par catdoc peuvent être obtenues depuis ftp.unicode.org. Les fichiers de jeu de caractères ont le suffixe .txt, qui ne doit pas être spécifié en ligne de commande ou dans les fichiers de

configuration.

Notez que catdoc est distribué avec les jeux de caractères cyrilliques par défaut. Si vous n'êtes pas russe, vous ne le souhaitez probablement pas et devriez reconfigurer catdoc au moment de la compilation ou dans le fichier de configuration à

l'exécution.

Lorsque vous traitez des documents avec des jeux de caractères autres que le jeu par défaut, rappelez-vous que Microsoft n'utilise jamais les jeux de caractère

s ISO. Bien que les lettres, par exemple dans cp1252, soient à la même position que dans ISO-8859-1, certains signes de ponctuation seraient perdus si vous spéc
ifiez ISO-8859-1 comme jeu de caractères d'entrée. Si vous utilisez cp1252, catdoc traitera ces signes comme décrit dans SUBSTITUTION DE CARACTÈRES ci-dessous.

SUBSTITUTION DE

CARACTÈRES

catdoc convertit le fichier MS-Word en la représentation Unicode interne suivante

:
1. Les paragraphes sont séparés par le symbole ASCII Line Feed
(0x000A)
2. Les cellules de tableau au sein d'une ligne sont séparées par le symbole ASCII Field
Separator
(0x001
C)
3. Les lignes de tableau sont séparées par le symbole ASCII Record Separator
(0x001E)
4. Tous les caractères imprimables, y compris les espaces, sont représentés par
leurs
codes UN
ICODE res
pectifs.

Cette représentation UNICODE est ensuite convertie en texte sur 8 bits dans le jeu de caractères cible à l'aide de l'algorithme suivant en quatre étapes

:
1. La liste des caractères spéciaux est recherchée pour le caractère Unicode
donné.
Si trouvé, une séquence multi-caractères appropriée est produite à la place du
caractère.
2. S'il existe un équivalent dans le jeu de caractères cible, il est
produit.
3. Sinon, la liste de remplacement est recherchée et, s'il existe une
substitution
multi-caractères pour ce caractère UNICODE, elle est
produite.
4. Si tout ce qui précède échoue, le symbole "caractère inconnu" (point d'interrogation) est
produit.

Les listes de caractères spéciaux et la liste de substitution sont indépendantes du jeu de caractères, car les caractères spéciaux doivent être échappés quelle que soit leur existence dans le jeu de caractères cible (généralement, ils font partie de US-ASCII et existent donc dans n'importe quel jeu de caractères) et la liste de remplacement n'est recherchée que pour les caractères qui ne sont pas trouvés dans le jeu de caractères

cible.

Ces listes sont stockées dans le répertoire de bibliothèque de catdoc dans des fichiers avec le préfixe du nom de format. Ces fichiers ont le format suivant

:

Chaque ligne peut être soit un commentaire (commençant par un signe de dièse) ou contiennent la valeur UNICODE hexadécimale, séparée par des espaces de la chaîne, qui serait substituée à sa place. Si la chaîne ne contient pas d'espace, elle peut être utilisée telle quelle, sinon elle doit être entourée de guillemets simples ou doubles. Les séquences de barre oblique habituelles comme '\n','\t' peuvent être utilis

ées dans
ces chaînes.

CONFIGURATION À

L'EXÉCUTION

Au démarrage, catdoc lit son fichier de configuration système ( catdocrc dans le répertoire de la bibliothèque de catdoc) puis le fichier de configuration spécifique à l'utilisateur ${HOME}/.

catdocrc.

Ces fichiers peuvent contenir les directives suivantes

:
source_charset = nom-de-jeu-de-carac
tères
Définit le jeu de caractères source par défaut, qui sera utilisé si aucune option -s n'est spécifiée. Consultez la configuration d'un poste Windows voisin pour trouver celui dont vous avez
besoin.
target_charset = nom-de-jeu-de-carac
tères

Définit le jeu de caractères de sortie par défaut. Vous savez probablement lequel vous
utilisez.
charset_path = liste-de-réperto
ires
liste de répertoires séparés par des deux-points, où les fichiers de jeu de caractères sont recherchés. Cela vous permet d'installer des jeux de caractères supplémentaires dans votre répertoire personnel. Si le premier composant du chemin est ~, il est remplacé par le contenu de la variable d'environnement HOME. Sur la plateforme MS-DOS, si le nom du répertoire commence par %s, il est remplacé par le répertoire du fichier exécutable. Un élément vide dans la liste (c'est-à-dire deux deux-points consécutifs) est considéré comme le répertoire courant. (voir ci-de
ssus)
map_path = liste-de-réperto
ires
liste de répertoires séparés par des deux-points, où la carte de caractères spéciaux et la carte de remplacement sont recherchées. Les mêmes règles de substitution que dans charset_path sont
appliquées.
format = nom-de-form
at
Format de sortie qui sera utilisé par défaut. catdoc est livré avec deux formats - ascii et tex mais rien ne vous empêche d'écrire votre propre format (définir deux fichiers de carte - une carte de caractères spéciaux et une carte de remplacement)
.
unknown_char = spécification-de-caract
ère
définit le caractère à afficher à la place d'un caractère Unicode inconnu (par défaut '?'). La spécification de caractère peut prendre l'une des deux formes - un caractère entouré de guillemets simples ou un code
hexadécimal.
use_locale =(yes|n
o)
Active ou désactive la sélection automatique du jeu de caractères de sortie (par défaut yes),
basée sur les paramètres de locale du système (si activé à la compilation). Si la détection automatique est activée, les paramètre
s du jeu de caractères de sortie dans les fichiers de configuration (mais pas dans la ligne de commande) sont ignorés, et le jeu d
e caractères de la locale système courante est utilisé à la place. Il n'y a pas de choix automatique du jeu de caractères d'entrée
basé sur la langue de la locale, car la plupart des fichiers Word modernes (depuis Word 97) sont en Unicode de toute façon.
