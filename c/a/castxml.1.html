NOM

castxml - Sortie XML de l'arbre syntaxique abstrait (AST) de la famille C

SYNOPSIS

castxml ( <castxml-opt> | <clang-opt> | <src> )...

DESCRIPTION

Analyse les fichiers sources de la famille C et écrit optionnellement un sous-ensemble de l'arbre syntaxique abstrait (AST) sous forme de représentation XML.

OPTIONS

Les options de ligne de commande suivantes sont interprétées par castxml. Les options restantes sont transmises au compilateur Clang interne.

--castxml-cc-<id> <cc>, --castxml-cc-<id> "(" <cc> <cc-opt>... ")"
Configure le préprocesseur Clang interne et la plateforme cible pour correspondre à ceux de la commande de compilateur donnée. L'<id> nomme un compilateur de référence auquel la commande donnée est compatible. Il doit être l'un des suivants :
  • gnu : GNU Compiler Collection C++ (g++)
  • gnu-c : GNU Compiler Collection C (gcc)
  • msvc : Microsoft Visual C++ (cl)
  • msvc-c : Microsoft Visual C (cl)

<cc> nomme un compilateur (par exemple /usr/bin/gcc ou cl) et <cc-opt>... spécifie des options qui peuvent affecter sa cible (par exemple -m32). La plateforme cible détectée à partir du compilateur donné peut être remplacée par une option Clang -target distincte. Le niveau de norme de langage détecté à partir du compilateur donné peut être remplacé par une option Clang -std= distincte.

--castxml-output=<v>
Écrit la sortie XML dans <src>.xml ou dans le fichier nommé par -o. Le <v> spécifie le numéro de version du format « epic » à générer, et doit être 1.
--castxml-gccxml
Génère une sortie XML dans un format proche de celui de gccxml. Écrit la sortie dans <src>.xml ou dans le fichier nommé par -o. Le format gccxml ne prend pas en charge les modes de langage Clang autres que -std=c++98 ou -std=c89. Ce format de sortie peut être utilisé avec les modes de langage -std=c++11, -std=c++14, -std=c99 et -std=c11, mais la sortie ne contiendra pas de constructeurs de déplacement implicites ni d'opérateurs d'affectation de déplacement, et peut contenir des éléments <Unimplemented/> sur des constructions non c++98.
--castxml-start <name>[,<name>]...
Démarre le parcours de l'AST aux déclarations ayant les noms qualifiés donnés. Plusieurs noms peuvent être spécifiés sous forme de liste séparée par des virgules ou en répétant l'option.
-help, --help
Affiche les informations d'utilisation de castxml et du compilateur Clang interne.
-o <file>
Si une sortie est générée (par exemple, via --castxml-output=<v>), écrit la sortie dans <file>. Au plus un fichier <src> peut être spécifié en entrée.
--version
Affiche les informations de version de castxml et du compilateur Clang interne.

Les versions de publication de CastXML utilisent le format :

<major>.<minor>.<patch>[-rc<n>][-<id>]

où le composant <patch> est inférieur à 20000000, <n> est un numéro optionnel de candidat à la publication, et <id> peut contenir du texte arbitraire (en cas de développement entre les versions de patch).

Les versions de développement de CastXML utilisent le format :

<major>.<minor>.<date>[-<id>]

où le composant <date> est au format CCYYMMDD et <id> peut contenir du texte arbitraire. Cela représente le développement à une date particulière suivant la version majeure <major>.<minor>.

VERSIONS DU FORMAT DE SORTIE

Avec --castxml-output=<v>

L'élément racine XML sera de la forme :

<CastXML format="1.4.0">
  • Le premier composant est le numéro de version du format epic donné à l'indicateur --castxml-output=<v>, et doit actuellement toujours être 1.
  • Le deuxième composant est le numéro de version du format majeur et s'incrémente lorsqu'un nouvel élément XML est ajouté ou pour d'autres changements majeurs. Les clients devront être mis à jour.
  • Le troisième composant est le numéro de version du format mineur et s'incrémente chaque fois qu'un nouvel attribut XML est ajouté à un élément existant ou qu'un bogue mineur est corrigé dans la sortie XML d'un élément ou attribut existant (les clients devraient fonctionner sans changement sauf s'ils veulent les nouvelles informations).

PRETRAITEMENT

CastXML prétraite les fichiers sources à l'aide d'un compilateur Clang interne en utilisant par défaut ses propres macros prédéfinies pour la plateforme cible. L'option --castxml-cc-<id> remplace les macros prédéfinies pour correspondre à celles détectées à partir de la commande du compilateur donnée. Dans les deux cas, CastXML ajoute toujours les macros prédéfinies suivantes :

__castxml_major__
Défini sur le numéro de version majeure de CastXML en décimal.
__castxml_minor__
Défini sur le numéro de version mineure de CastXML en décimal.
__castxml_patch__
Défini sur le numéro de version de correctif de CastXML en décimal.
__castxml_check(major,minor,patch)
Défini sur une expression constante encodant les trois composants de version pour la comparaison avec __castxml__. L'encodage réel n'est pas spécifié.
__castxml__
Défini sur une expression constante encodant les composants de version de CastXML :
__castxml_check(__castxml_major__,__castxml_minor__,__castxml_patch__)
__castxml_clang_major__
Défini sur la valeur de __clang_major__ du Clang interne.
__castxml_clang_minor__
Défini sur la valeur de __clang_minor__ du Clang interne.
__castxml_clang_patchlevel__
Défini sur la valeur de __clang_patchlevel__ du Clang interne.

Les fichiers sources peuvent utiliser ces macros pour identifier l'outil qui effectue réellement le prétraitement, même lorsque --castxml-cc-<id> modifie les macros prédéfinies.

Pourquoi ne vois-je pas les modèles dans la sortie ?

Cette fonctionnalité n'a pas été implémentée car le projet pilote pour lequel CastXML a été écrit n'avait pas besoin de modèles non instanciés. Les instanciations de modèles seront tout de même extraites. Par exemple :

template <class T> struct foo {};
typedef foo<int>::foo foo_int;

instanciera foo<int>, qui sera inclus dans la sortie. Cependant, il n'y aura aucun endroit qui liste explicitement l'ensemble des types utilisés pour l'instanciation en dehors du nom. Cela est dû au fait que la manière correcte de procéder est d'extraire également les modèles et de les référencer depuis les instanciations avec les arguments de modèle listés. Comme les fonctionnalités seront liées, elles devraient être implémentées ensemble.
