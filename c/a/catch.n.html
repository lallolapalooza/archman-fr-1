catch(n)

Paquet: tcl

Licences: TCL

catch(n) Commandes intégrées Tcl catch(n)

NOM

catch - Évaluer un script et intercepter les retours exceptionnels

SYNTAXE

catch script ?nomVariableResultat? ?nomVariableOptions?

DESCRIPTION

La commande catch peut être utilisée pour empêcher les erreurs d'interrompre l'interprétation des commandes. La commande catch appelle l'interpréteur Tcl de manière récursive pour exécuter script, et revient toujours sans lever d'erreur, quelles que soient les erreurs qui pourraient survenir lors de l'exécution de script.

Si script lève une erreur, catch retournera une valeur entière non nulle correspondant au code de retour exceptionnel renvoyé par l'évaluation de script. Tcl définit le code de retour normal de l'évaluation d'un script comme étant zéro (0), ou TCL_OK. Tcl définit également quatre codes de retour exceptionnels : 1 (TCL_ERROR), 2 (TCL_RETURN), 3 (TCL_BREAK) et 4 (TCL_CONTINUE). Les erreurs lors de l'évaluation d'un script sont indiquées par un code de retour de TCL_ERROR. Les autres codes de retour exceptionnels sont renvoyés par les commandes return, break et continue, ainsi que dans d'autres situations spéciales comme documenté. Les paquets Tcl peuvent définir de nouvelles commandes qui renvoient d'autres valeurs entières comme codes de retour, et les scripts qui utilisent la commande return -code peuvent également avoir des codes de retour autres que les cinq définis par Tcl.

Si l'argument nomVariableResultat est fourni, alors la variable qu'il nomme est définie avec le résultat de l'évaluation du script. Lorsque le code de retour du script est 1 (TCL_ERROR), la valeur stockée dans nomVariableResultat est un message d'erreur. Lorsque le code de retour du script est 0 (TCL_OK), la valeur stockée dans nomVariableResultat est la valeur renvoyée par script.

Si l'argument nomVariableOptions est fourni, alors la variable qu'il nomme est définie avec un dictionnaire d'options de retour renvoyées par l'évaluation de script. Tcl spécifie deux entrées qui sont toujours définies dans le dictionnaire : -code et -level. Lorsque le code de retour de l'évaluation de script n'est pas TCL_RETURN, la valeur de l'entrée -level sera 0, et la valeur de l'entrée -code sera la même que le code de retour. Ce n'est que lorsque le code de retour est TCL_RETURN que les valeurs des entrées -level et -code seront différentes, comme décrit plus en détail dans la documentation de la commande return.

Lorsque le code de retour de l'évaluation de script est TCL_ERROR, quatre entrées supplémentaires sont définies dans le dictionnaire des options de retour stockées dans nomVariableOptions : -errorinfo, -errorcode, -errorline et -errorstack. La valeur de l'entrée -errorinfo est une trace de pile formatée contenant plus d'informations sur le contexte dans lequel l'erreur s'est produite. La trace de pile formatée est destinée à être lue par une personne. La valeur de l'entrée -errorcode est une information supplémentaire sur l'erreur stockée sous forme de liste. La valeur -errorcode est destinée à être traitée davantage par des programmes, et peut ne pas être particulièrement lisible par les humains. La valeur de l'entrée -errorline est un entier indiquant quelle ligne de script était en cours d'évaluation lorsque l'erreur s'est produite. La valeur de l'entrée -errorstack est une liste de taille paire composée de paires token-paramètre accumulées lors du déroulement de la pile. Le token peut être “CALL”, auquel cas le paramètre est une liste composée du nom de la procédure et de ses arguments au niveau correspondant ; ou il peut être “UP”, auquel cas le paramètre est le niveau relatif (comme dans uplevel) du CALL précédent. Les différences notables par rapport à -errorinfo sont que :

[1]
c'est une forme lisible par machine qui peut être traitée avec [foreach {tok prm} ...],
[2]
elle contient les valeurs réelles (substituées) passées aux fonctions, au lieu du texte statique des sites d'appel, et
[3]
elle est plus grossière, avec un seul élément par cadre de pile (comme les procédures ; pas d'éléments séparés pour les constructions foreach par exemple).

Les valeurs des entrées -errorinfo et -errorcode de la dernière erreur sont également disponibles comme valeurs des variables globales ::errorInfo et ::errorCode respectivement. La valeur de l'entrée -errorstack apparaît sous la forme info errorstack.

Les paquets Tcl peuvent fournir des commandes qui définissent d'autres entrées dans le dictionnaire des options de retour, et la commande return peut être utilisée par les scripts pour définir des options de retour en plus de celles définies ci-dessus.

EXEMPLES

La commande catch peut être utilisée dans un if pour brancher en fonction du succès d'un script.

if { [catch {open $someFile w} fid] } {
    puts stderr "Impossible d'ouvrir $someFile en écriture\n$fid"
    exit 1
}

Il existe des exemples d'utilisation de catch plus complexes dans la documentation de la commande return.
