NOM

caff -- CA - Fire and Forget (Tirer et Oublier)

SYNTAXE

caff [-eERS] [-m oui|demander-oui|demander-non|non] [-u votrecléid] cléid [cléid ..]
caff [-eERS] [-m oui|demander-oui|demander-non|non] [-u votrecléid] [cléid ..] </chemin/vers/ksp-annoté.txt

DESCRIPTION

CA Fire and Forget est un script qui vous aide dans la signature de clés. Il prend une liste d'identifiants de clés en ligne de commande, les récupère depuis un serveur de clés et appelle GnuPG pour que vous puissiez les signer. Il envoie ensuite chaque clé à toutes ses adresses e-mail - en incluant uniquement l'UID que nous envoyons dans chaque mail, élagué de toutes les signatures sauf les auto-signatures et les signatures que vous avez faites. La clé envoyée par mail est chiffrée avec elle-même comme moyen de vérifier que la clé appartient au destinataire.

La liste des clés à signer peut également être fournie via l'entrée standard de caff, sous forme de contenu formaté par gpgparticipants(1). Seules les clés pour lesquelles les cases « Fingerprint OK » et « ID OK » sont cochées (c'est-à-dire marquées d'un « x ») sont considérées pour la signature. De plus, l'en-tête d'entrée doit inclure au moins une ligne de somme de contrôle, et toutes les cases de somme de contrôle doivent être marquées comme vérifiées (avec un « x »).

OPTIONS

-e, --export-old
Exporter les anciennes signatures. Par défaut, l'utilisateur est interrogé pour chaque ancienne signature.
-E, --no-export-old
Ne pas exporter les anciennes signatures. Par défaut, l'utilisateur est interrogé pour chaque ancienne signature.
-m, --mail oui|demander-oui|demander-non|non
Indique s'il faut envoyer un mail après la signature. Par défaut, on demande pour chaque uid, avec une valeur par défaut de oui.
-R, --no-download
Ne pas récupérer la clé à signer depuis un serveur de clés.
-S, --no-sign
Ne pas signer les clés.
-u votrecléid, --local-user votrecléid
Sélectionne la clé utilisée pour la signature, au cas où vous auriez plus d'une clé. Pour signer avec plusieurs clés à la fois, séparez les identifiants de clés par des virgules. Cette option nécessite que les clés soient définies via la variable keyid dans le fichier de configuration.
--key-file fichier
Importer les clés depuis un fichier. Peut être spécifié plusieurs fois.
--keys-from-gnupg
Essayer d'importer les clés depuis vos trousseaux de clés GnuPG standards.
--debug
Activer les messages de débogage.

ENVIRONNEMENT

HOME
Le répertoire personnel par défaut.
GNUPGBIN
Le binaire gpg. Par défaut : "gpg".
GNUPGHOME
Le répertoire de travail par défaut pour gpg. Par défaut : "$HOME/.gnupg".

FICHIERS

$HOME/.caffrc - fichier de configuration
$HOME/.caff/keys/aaaa-mm-jj/ - clés traitées
$HOME/.caff/gnupghome/ - répertoire de travail de caff pour gpg
$HOME/.caff/gnupghome/gpg.conf - configuration gpg (voir NOTES ci-dessous)
les options utiles incluent use-agent, keyserver, keyserver-options, default-cert-level, etc.

OPTIONS DU FICHIER DE CONFIGURATION

Le fichier de configuration est un script perl qui définit des valeurs dans la table d'association %CONFIG. Le fichier est généré lorsqu'il n'existe pas.

Exemple :

$CONFIG{'owner'} = q{Peter Palfrader};
$CONFIG{'email'} = q{peter@palfrader.org};
$CONFIG{'keyid'} = [ qw{DE7AAF6E94C09C7F 62AF4031C82E0039} ];

Paramètres de base requis

owner [chaîne]
Votre nom. REQUIS.
email [chaîne]
Votre adresse e-mail, utilisée dans les lignes From:. REQUIS.
keyid [liste d'identifiants de clés]
Une liste de vos clés. Ceci est utilisé pour déterminer quelles signatures conserver lors de l'étape d'élagage. Si vous sélectionnez une clé avec -u, elle doit être dans cette liste. REQUIS.

Paramètres généraux

caffhome [chaîne]
Répertoire de base pour les fichiers stockés par caff. Par défaut : $HOME/.caff/.
colors [table]
Comment colorer les messages de sortie. Voir la documentation de "Term::ANSIColor" pour la liste des couleurs supportées ; la sortie colorée peut être désactivée en définissant cette option sur une table vide {}. Par défaut : 
{ error => 'bold bright_red'
, warn => 'bright_red'
, notice => 'bold'
, info => ''
, success => 'green' # utilisé en combinaison avec 'notice' et 'info'
, fail => 'yellow'   # utilisé en combinaison avec 'notice' et 'info'
}

Paramètres GnuPG

gpg [chaîne]
Chemin vers le binaire GnuPG. Par défaut : La valeur de la variable d'environnement GNUPGBIN si elle est définie, sinon "gpg".
secret-keyring [chaîne]
Chemin vers votre trousseau de clés secret (GnuPG < 2.1), ou vers le GnuPGHOME de l'agent gérant les clés secrètes (GnuPG >= 2.1). Par défaut : $HOME/.gnupg/secring.gpg. Si la valeur n'est pas un répertoire avec GnuPG >= 2.1, le répertoire parent (c'est-à-dire $HOME/.gnupg par défaut) est considéré à la place.
also-encrypt-to [cléid, ou liste de clésid]
Clésid supplémentaires auxquelles chiffrer les messages. Par défaut : aucune.
gpg-sign-type [chaîne]
Le préfixe de la commande « sign » utilisée pour créer la signature depuis le shell de gpg. Peut être réglé sur un mélange de « l » (local), « nr » (non révocable) ou « t » (confiance) pour créer une signature du type donné. Voir gpg(1) pour plus de détails. Par défaut : "" (c'est-à-dire, créer une signature normale et exportable).
gpg-sign-args [chaîne]
Commandes supplémentaires à passer à gpg après la commande « sign ». Par défaut : aucune.

Paramètres d'importation de clés

no-download [booléen]
Si vrai, ignorer l'étape de récupération des clés depuis le serveur de clés. Par défaut : 0.
key-files [liste de fichiers]
Une liste de fichiers contenant les clés à importer.

Paramètres de signature

no-sign [booléen]
Si vrai, ignorer l'étape de signature. Par défaut : 0.
ask-sign [boolean]
Si vrai, faire une pause avant de continuer à l'étape de signature. Ceci est utile pour la signature hors ligne. Par défaut : 0.
export-sig-age [secondes]
Ne pas exporter les UID par défaut, dont la dernière signature est plus ancienne que cet âge. Par défaut : 24*60*60 (c'est-à-dire un jour).
local-user [id de clé, ou liste d'ids de clés]
Sélectionner la clé utilisée pour la signature, si vous avez plus d'une clé. Avec plusieurs ids de clés, signer avec chaque clé à tour de rôle.
also-lsign-in-gnupghome [auto|demander|non]
S'il faut signer localement les UID dans GnuPGHOME de l'utilisateur, en plus des signatures de caff dans son propre GnuPGHOME. Ces signatures ne sont pas exportables. Cela peut être utile lorsque le destinataire oublie de télécharger les signatures envoyées par caff (ou si elles sont également non exportables), car cela permet de garder une trace des UID qui ont été vérifiés. Cependant, notez que les signatures locales ne seront pas supprimées une fois que le destinataire aura effectué le téléchargement et que le signataire aura mis à jour son trousseau de clés.

Si la valeur n'est pas non et si gpg-sign-type contient "l", chaque signature (locale) est simplement exportée du propre GnuPGHOME de caff vers celui de l'utilisateur. Sinon, si la valeur est auto, chaque UID signé dans le propre GnuPGHOME de caff est automatiquement signé localement dans celui de l'utilisateur, en utilisant le même niveau de certification ; cela nécessite un gpg-agent(1) fonctionnel. Si demander, l'utilisateur est invité à choisir les UID à signer localement. Par défaut : non.

show-photos [booléen]
Si vrai, alors avant de signer une clé, gpg affichera les photos qui y sont attachées, le cas échéant. (Le visualiseur de photos peut être spécifié avec une option "photo-viewer" dans le GnuPGHOME de caff.) Par défaut : 0.

Paramètres de courrier

mail [oui|demander-oui|demander-non|non]
Indique s'il faut envoyer des courriels. Il s'agit d'une option quadruple, avec laquelle vous pouvez définir le comportement : oui envoie toujours, non n'envoie jamais ; demander-oui et demander-non demandent, pour chaque uid, avec des valeurs par défaut appropriées pour la question. Par défaut : demander-oui.

Dans tous les cas, les messages sont également écrits dans $CONFIG{'caffhome'}/keys/

mail-cant-encrypt [oui|demander-oui|demander-non|non]
La valeur de cette option est prise en compte au lieu de celle de mail pour les clés de destinataires sans capacité de chiffrement. Par défaut, la valeur de mail.
mail-subject [chaîne]
Définit la valeur du champ d'en-tête "Subject:". %k sera développé en l'id de clé long de la clé signée. Par défaut : "Votre clé PGP signée 0x%k".
mail-template [chaîne]
Modèle d'e-mail utilisé comme corps du texte pour l'e-mail envoyé au lieu du texte par défaut s'il est spécifié. Les variables Perl suivantes peuvent être utilisées dans le modèle :
{owner} [chaîne]
Votre nom tel que spécifié dans le paramètre owner.
{key} [chaîne]
L'id de clé que vous avez signée.
{@uids} [tableau]
Les UID dont les signatures sont incluses dans le courrier.

Notez que vous devriez probablement personnaliser le modèle si vous envisagez d'envoyer des signatures non exportables (c'est-à-dire si gpg-sign-type contient "l"), car le téléchargement de telles signatures n'a pas de sens, et elles nécessitent l'option d'importation "import-local-sigs" qui n'est pas définie par défaut.

reply-to [chaîne]
Ajoute un en-tête Reply-To: aux messages envoyés. Par défaut : aucun.
bcc [chaîne]
Adresse à laquelle envoyer des copies carbone aveugles lors de l'envoi d'e-mails. Par défaut : aucun.
mailer-send [tableau]
Paramètres à passer à Mail::Mailer. Par défaut : aucun. L'utilisation de cette option est fortement déconseillée : corrigez plutôt votre MTA local.

Cela pourrait par exemple être

$CONFIG{'mailer-send'} =  [ 'smtp', Server => 'mail.server', Auth => ['user', 'pass'] ];

pour utiliser le client SMTP de Perl, ou

$CONFIG{'mailer-send'} =  [ 'sendmail', '-f', $CONFIG{'email'}, '-it' ];

pour passer des arguments au programme sendmail. Pour spécifier un binaire sendmail, vous pouvez définir la variable d'environnement "PERL_MAILERS" comme suit :

$ENV{'PERL_MAILERS'} = 'sendmail:/path/to/sendmail_compatible_mta';

Pour plus d'informations, voir Mail::Mailer(3pm).

NOTES

Comme indiqué ci-dessus, caff utilise son propre GnuPGHOME et son propre fichier de configuration GnuPG. En fait, il n'a besoin que de son propre trousseau de clés pour le travail de signature, mais il serait dangereux de réutiliser le même fichier de configuration GnuPG car l'utilisateur pourrait avoir défini une option dans $HOME/.gnupg/gpg.conf qui casserait caff.

Par conséquent, les options GnuPG destinées à être utilisées avec caff, telles que "keyserver" ou "cert-digest-algo", doivent être placées dans $HOME/.caff/gnupghome/gpg.conf à la place. Si ce fichier n'existe pas, les options GnuPG trouvées dans $HOME/.gnupg/gpg.conf qui sont connues pour être sûres (et utiles) pour caff, sont passées à gpg(1) en tant qu'options de ligne de commande.
