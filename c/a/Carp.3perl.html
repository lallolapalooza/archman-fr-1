@CARP_NO

T

Cette variable, dans votre paquet, indique quels paquets ne doivent pas être considérés comme l'emplacement d'une erreur. Les fonctions carp() et cluck() ignoreront les appelants lors du signalement de l'emplacement d'une

erreur.

NB : Cette variable doit se trouver dans la table de symboles du paquet, ainsi

: 
# Ceci fonctionne
our @CARP_NOT; # portée du fichier
use vars qw(@CARP_NOT); # portée du paquet
@My::Package::CARP_NOT = ... ; # variable de paquet explicite
# Ceci ne fonctionne pas
sub xyz { ... @CARP_NOT = ... } # sans les déclarations ci-dessus
my @CARP_NOT; # même au niveau
supérieur

Exemple d'utilisation

: 
package My::Carping::Package;
use Carp;
our @CARP_NOT;
sub bar     { .... or _error('Wrong input') }
sub _error  {
    # contrôle temporaire de l'origine, __PACKAGE__ est implicite
    local @CARP_NOT = qw(My::Friendly::Caller);
    carp(@_)
}

Cela ferait que "Carp" signale l'erreur comme provenant d'un appelant n'étant pas dans "My::Carping::Package", ni de "My::Friendly::

Caller".

Internal

Ceci indique quels paquets sont internes à Perl. "Carp" ne signalera jamais une erreur comme provenant d'une ligne dans un paquet interne à Perl. Par exemple

%Carp::

CarpInternal

Ceci indique quels paquets sont internes au système d'avertissements de Perl. Pour générer une trace d'appels complète, c'est la même chose qu'être interne à Perl ; la trace d'appels ne commencera pas à l'intérieur des paquets listés dans %Carp::CarpInternal. Mais c'est légèrement différent pour le message résumé généré par "carp" ou "croak". Dans ces cas, les erreurs ne seront pas signalées sur les lignes qui appellent des paquets dans %Carp::CarpIn

ternal.

Par exemple, "Carp" lui-même est listé dans %Carp::CarpInternal. Par conséquent, la trace d'appels complète de "confess" ne commencera pas à l'intérieur de "Carp", et le message court généré par "croak" n'est pas placé sur la ligne où "croak" a

été ap

$Carp::

CarpLevel

Cette variable détermine combien de cadres d'appel supplémentaires doivent être ignorés, qui ne le seraient pas autrement, lors du signalement de l'emplacement d'une erreur lors d'un appel à l'une des fonctions de "Carp". Il est assez facile de compter ces cadres d'appel sur les appels qui génèrent une trace d'appels complète. Cependant, c'est beaucoup plus difficile de faire ce calcul pour les appels qui génèrent un message court. Habituellement, les gens ignorent trop de cadres d'appel. S'ils ont de la chance, ils en ignorent assez pour que "Carp" traverse toute la pile d'appels, réalise que quelque chose ne va pas, et génère alors une trace d'appels complète. S'ils n'ont pas de la chance, l'erreur est signalée depuis un endroit trompeur très haut dans la pile

d'appels.

Par conséquent, il est préférable d'éviter $Carp::CarpLevel. Utilisez plutôt @CARP_NOT, %Carp::Internal et %Carp::CarpIn

ternal.
