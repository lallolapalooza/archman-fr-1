UTILISATION PAR

L'APPLICATION

L'option -u a une valeur dans la prototypage de lectures non bloquantes depuis des FIFO. L'intention est de prendre en charge la séquence suivante

: 
mkfifo foo
cat -
u foo > /dev/tty1
3 & cat -u > foo

Il n'est pas spécifié si la sortie standard est ou n'est pas mise en tampon dans le cas par défaut. Cela est parfois d'intérêt lorsque la sortie standard est associée à un terminal, car la mise en tampon peut retarder la sortie. La présence de l'option -u garantit que l'E/S sans tampon est disponible. Il est défini par l'implémentation si l'utilitaire cat met la sortie en tampon si l'option -u n'est pas spécifiée. Traditionnellement, l'option -u est implémentée en utilisant l'équivalent de la fonction setvbuf() définie dans le volume

Interfaces systèm
e de POSIX.1‐2017.

EXEMPLE

S

La commande suivante

: 
cat
myf
ile

écrit le contenu du fichier myfile sur la sortie

standard.

La commande suivante

: 
cat doc1
doc2 >
doc.all

concatène les fichiers doc1 et doc2 et écrit le résultat dans doc.a

ll.

En raison du mécanisme de langage shell utilisé pour effectuer la redirection de sortie, une commande telle que celle-ci

: 
cat doc
doc.en
d > doc

fait que les données originales dans doc sont perdues avant que cat ne commence même l'exécution. C'est vrai que la commande cat échoue avec une erreur ou réussit silencieusement (la spécification permet les deux comportements). Afin d'ajouter le contenu de doc.end sans perdre le contenu original de doc, la commande suivante devrait être utilisée à la place

: 
cat do
c.end
>> doc

La commande

: 
cat start
- middle -
end > file

lorsque l'entrée standard est un terminal, obtient deux morceaux arbitraires d'entrée depuis le terminal avec une seule invocation de cat. Notez cependant que si l'entrée standard est un fichier régulier, cela serait équivalent à la commande

: 
cat start - m
iddle /dev/nu
ll end > file

car le contenu entier du fichier serait consommé par cat la première fois que '-' a été utilisé comme opérande fichier et une condition de fin de fichier serait détectée immédiatement lorsque '-' a été référenc

é la deuxi
ème fois.

JUSTIFICATIO

N

Les versions historiques de l'utilitaire cat incluent les options -e, -t et -v, qui permettent respectivement de rendre visibles dans la sortie les fins de ligne, les caractères <tab> et les caractères invisibles. Les développeurs de la norme ont omis ces options car elles fournissent un degré de contrôle trop fin sur ce qui est rendu visible, et une sortie similaire peut être obtenue en utilisant une commande telle que

: 
sed -n
l pa
thname

Ce dernier a aussi l'avantage que sa sortie est non ambiguë, alors que la sortie de cat -etv historique ne l'est

pas.

L'option -s a été omise car elle correspond à différentes fonctions dans les systèmes BSD et basés sur System V. Le -s BSD l'option pour comprimer les lignes vides peut être réalisée par le script shell montré dans l'exemple suivant

: 
sed -n '
# Écrire les lignes non vides.
/./   {
      p
      d
      }
# Écrire une seule ligne vide, puis chercher d'autres lignes vides.
/^$/  p
# Lire la ligne suivante, écarter le <newline> conservé (ligne vide),
# et chercher d'autres lignes vides.
:Empty
/^$/  {
      N
      s/.//
      b Empty
      }
# Écrire la ligne non vide avant de retourner chercher
# la première d'un ensemble de lignes vides.
p
'

L'option -s de System V pour supprimer les messages d'erreur peut être réalisée en redirigeant la sortie d'erreur standard. Remarquez que la documentation BSD pour cat utilise le terme « blank line » (ligne blanche) pour signifier la même chose que « empty line » (ligne vide) de POSIX : une ligne composée uniquement d'un <newline>

.

L'option -n de BSD a été omise car une fonctionnalité similaire peut être obtenue à partir de l'option -n de l'utilitaire pr

.
