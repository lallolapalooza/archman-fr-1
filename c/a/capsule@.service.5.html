NOM

capsule@.service - Gestionnaire système pour le service de capsule

SYNTAXE

capsule@NOM.service

DESCRIPTION

Les gestionnaires de services pour les capsules s'exécutent dans les unités système capsule@NOM.service, avec le nom de la capsule comme identifiant d'instance. Les capsules sont un moyen d'exécuter des instances supplémentaires du gestionnaire de services, sous des identifiants d'utilisateur dynamiques, c'est-à-dire des UID qui sont alloués lors du démarrage du gestionnaire de services de la capsule et libérés lors de son arrêt.

À bien des égards, capsule@.service est similaire au gestionnaire de services user@.service par utilisateur, mais il existe quelques distinctions importantes :

•Le gestionnaire de services de capsule utilise DynamicUser= (voir systemd.exec(5)) pour allouer un nouvel UID dynamiquement lors de l'invocation. Le nom d'utilisateur est automatiquement généré à partir du nom de la capsule, en préfixant "c-". L'UID est libéré lorsque le service est terminé. Le gestionnaire de services utilisateur, en revanche, fonctionne sous un ID utilisateur statiquement alloué qui doit exister avant que le gestionnaire de services utilisateur ne soit invoqué.
•Les gestionnaires de services utilisateur s'enregistrent auprès de pam(8), les gestionnaires de services de capsule ne le font pas.
•Les gestionnaires de services utilisateur lisent typiquement leur configuration à partir d'un répertoire $HOME sous /home/, les gestionnaires de services de capsule à partir d'un répertoire $HOME sous /var/lib/capsules/.
•Les gestionnaires de services utilisateur sont collectivement contenus dans l'unité user.slice, les gestionnaires de services de capsule dans capsule.slice. Voir également systemd.special(7).
•Les gestionnaires de services utilisateur démarrent initialement la cible par défaut des unités utilisateur, default.target. Les gestionnaires de services de capsule invoquent à la place la cible des unités utilisateur, capsule@.target.

Le gestionnaire de services de capsule et le broker de bus de la capsule sont accessibles via le commutateur --capsule= de systemctl(1), systemd-run(1) et busctl(1).

De nouvelles capsules peuvent être démarrées via une simple commande systemctl start capsule@NOM.service, et arrêtées via systemctl stop capsule@NOM.service. Démarrer une capsule créera implicitement un répertoire personnel /var/lib/capsules/NOM/, s'il est manquant. Un répertoire d'exécution est créé sous /run/capsules/NOM/. Pour supprimer ces ressources, utilisez systemctl clean capsule@NOM.service, par exemple avec le commutateur --what=all.

L'unité capsule@.service invoque un processus de gestionnaire de services systemd --user. Cela signifie que les fichiers d'unité sont recherchés selon les mêmes règles que pour les gestionnaires de services utilisateur réguliers, par exemple dans /var/lib/capsules/NOM/.config/systemd/user/.

Les noms de capsules peuvent être choisis librement par l'utilisateur, cependant, ils doivent être appropriés comme noms de fichiers UNIX (c'est-à-dire 255 caractères maximum, et ne contenant pas de "/"), et lorsqu'ils sont préfixés par "c-", être appropriés comme nom d'utilisateur respectant les règles POSIX strictes, voir Syntaxe des noms d'utilisateur/groupe[1] pour plus de détails.

Ajouté dans la version 256.

EXEMPLES

Exemple 1. Créer une nouvelle capsule, invoquer deux programmes dedans (un interactivement), la terminer, et nettoyer tout

# systemctl start capsule@tatze.service
# systemd-run --capsule=tatze --unit=sleeptest.service sleep 999
# systemctl --capsule=tatze status sleeptest.service
# systemd-run -t --capsule=tatze bash
# systemctl --capsule=tatze stop sleeptest.service
# systemctl stop capsule@tatze.service
# systemctl clean --all capsule@tatze.service
