CAP_GET_FILE(3) Manuel du programmeur Linux CAP_GET_FILE(3)

NOM

cap_get_file, cap_set_file, cap_get_fd, cap_set_fd, cap_get_nsowner, cap_set_nsowner - manipulation des capacités sur les fichiers

SYNTAXE

#include <sys/capability.h>
cap_t cap_get_file(const char *path_p);
int cap_set_file(const char *path_p, cap_t cap_p);
cap_t cap_get_fd(int fd);
int cap_set_fd(int fd, cap_t caps);
uid_t cap_get_nsowner(cap_t caps);
int cap_set_nsowner(cap_t caps, uid_t rootuid);

Lier avec -lcap.

DESCRIPTION

cap_get_file() et cap_get_fd() allouent un état de capacité en mémoire de travail et le définissent pour représenter l'état de capacité du chemin nommé pointé par path_p ou du fichier ouvert sur le descripteur fd. Ces fonctions retournent un pointeur vers l'état de capacité nouvellement créé. Les effets de la lecture de l'état de capacité depuis un fichier autre qu'un fichier ordinaire sont indéfinis. L'appelant doit libérer toute mémoire libérable, lorsque l'état de capacité en mémoire de travail n'est plus requis, en appelant cap_free() avec le cap_t utilisé comme argument.

cap_set_file() et cap_set_fd() définissent les valeurs pour tous les drapeaux de capacité pour toutes les capacités du chemin nommé pointé par path_p ou du fichier ouvert sur le descripteur fd, avec l'état de capacité identifié par cap_p. Le nouvel état de capacité du fichier est complètement déterminé par le contenu de cap_p. Une valeur NULL pour cap_p est utilisée pour indiquer que les capacités du fichier doivent être supprimées. Pour que ces fonctions réussissent, le processus appelant doit avoir la capacité CAP_SETFCAP dans son ensemble effectif et soit l'ID utilisateur effectif du processus doit correspondre au propriétaire du fichier, soit le processus appelant doit avoir la capacité CAP_FOWNER dans son ensemble de capacités effectives. Les effets de l'écriture de l'état de capacité sur tout type de fichier autre qu'un fichier ordinaire sont indéfinis.

Un ensemble de capacités détenu en mémoire peut être associé à l'ID d'utilisateur root en cours d'utilisation dans un espace de noms utilisateur spécifique. Il est possible d'obtenir et de définir cette valeur (dans la copie mémoire) avec cap_get_nsowner() et cap_set_nsowner() respectivement. L'ID d'utilisateur root est ignoré par la bibliothèque libcap dans tous les cas autres que lorsque la capacité est écrite dans un fichier. Ce n'est que si la valeur est non nulle que la bibliothèque tentera de l'inclure dans l'ensemble des capacités du fichier écrit.

VALEUR DE RETOUR

cap_get_file() et cap_get_fd() retournent une valeur non NULL en cas de succès, et NULL en cas d'échec.

cap_set_file() et cap_set_fd() retournent zéro en cas de succès, et -1 en cas d'échec.

En cas d'échec, errno est défini à EACCES, EBADFD, ENAMETOOLONG, ENOENT, ENOMEM, ENOTDIR, EPERM ou EROFS.

CONFORMITÉ

Ces fonctions sont spécifiées par la spécification brouillon POSIX.1e retirée.

NOTES

Le support des capacités de fichier est fourni sous Linux depuis la version 2.6.24.

Sous Linux, l'ensemble effectif de fichier est un seul bit. S'il est activé, toutes les capacités autorisées sont activées dans l'ensemble effectif du processus appelant lors de l'exécution du fichier ; sinon, aucune capacité n'est activée dans l'ensemble effectif du processus suite à un execve(2). Étant donné que l'ensemble effectif de fichier est un seul bit, si une capacité est activée dans l'ensemble effectif du cap_t donné à cap_set_file() ou cap_set_fd(), alors toutes les capacités dont le drapeau Permis ou Héritable est activé doivent également avoir le drapeau Effectif activé. Inversement, si le bit Effectif est activé sur un fichier, alors le cap_t retourné par cap_get_file() et cap_get_fd() aura le drapeau Effectif activé pour chaque capacité ayant le drapeau Permis ou Héritable activé.
