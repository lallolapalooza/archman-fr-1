CALC LIGNE DE

COMMANDE

Sans arguments calc_cmd, calc fonctionne de manière interactive. Si un ou plusieurs arguments sont donnés sur la ligne de commande et que -s n'est PAS donné, alors calc les lira et les exécutera et tentera soit de passer en mode interactif selon que le drapeau -i était

présent

ou absent. Si -s est donné, calc n'évaluera aucun argument calc_cmd mais les rendra plutôt disponibles sous forme de chaînes de caractères pour la fonction intégrée argv()

.

Des commandes suffisamment simples sans caractères comme les parenthèses, les crochets, les points-virgules, '*', qui ont des interprétations spéciales dans les shells UNIX, peuvent être saisies, éventuellement avec des espaces, jusqu'à la nouvelle ligne de fin. Par exemple

: 


calc 23 +
47

affichera 70. Cependant, les lignes de commande poseront problème

: 


calc 23 * 47

calc -23 +
47

Le premier exemple ci-dessus échoue car le shell interprète le '*' comme un glob de fichiers. Le second exemple échoue car '-23' est considéré comme une option de calc (ce qu'il n'est pas) et calc proteste contre ce qu'il considère comme une option inconnue. Ces cas peuvent généralement être résolus comme prévu en entourant la commande entre guillemets

: 


calc '23 * 47'

calc "print sqrt(2), exp(1)
"

ou entre parenthèses et guillemets pour éviter les tirets initiaux comme dans

: 


calc '(-23 + 47)
'

On peut aussi utiliser un double tiret pour indiquer que les options de calc sont terminées, comme dans

: 


calc -- -23 + 47

calc -q -- -23 +
47

Si '!' doit être utilisé pour indiquer la fonction factorielle, pour des shells comme csh(1) pour lesquels '!' suivi d'un caractère non espace est utilisé pour la substitution d'historique, il peut être nécessaire d'inclure un espace ou d'utiliser une barre oblique inverse pour échapper à la signification spéciale de '!'. Par exemple, la commande

: 


print 27!
^2

devra peut-être être remplacée par

: 


print 27! ^2    ou      print 27\!
^2

La lecture depuis l'entrée standard lorsque calc fait partie d'un pipe fonctionne tant que le drapeau -p est donné à calc. Par exemple, cela affichera chongo was here

: 


echo chongo was here | calc -p 'print fgetline(files(0));
'

alors que cela ne le fait pas

: 


echo chongo was here | calc 'print fgetline(files(0));
'

et cela n'affichera pas non plus chongo was here

: 


echo chongo was here | calc -i 'print fgetline(files(0));
'

C'est parce que sans -p, l'analyseur interactif, dans sa tentative d'analyser des c

ommandes interactives, vide les
données sur l'entrée standard.

CALC FICHIERS DE

DÉMARRAGE

Normalement au démarrage, si la variable d'environnement $CALCRC est indéfinie et calc est invoqué sans le drapeau -q, ou si $CALCRC est définie et calc est invoqué avec -e, calc cherche un fichier "startup" dans le répertoire de ressources de calc, .calcrc dans le répertoire personnel de l'utilisateur, et .calcinit dans le répertoire courant. Si un ou plusieurs de ces fichiers sont trouvés, ils sont lus successivement en tant que scripts calc et leurs commandes sont exécutées. Lorsqu'elle est définie, $CALCRC doit contenir une liste de noms de fichiers séparés par des ':', et si calc est ensuite invoqué sans les drapeaux -q

ou

-e, ces fichiers sont lus successivement et leurs commandes sont exécutées. Aucune condition d'erreur n'est produite si un fichier listé n'est pas trouvé. Si le mode spécifié par -m désactive l'ouverture de fichiers pour la lecture, alors la lecture des fichiers de démarrage est également

désactivée
comme si

-q avait été

donné.

MODE SCRIPT SHELL Si la première ligne d'un fichier exécutable commence par #! suivi du chemin absolu du programme calc et que la première ligne se termine

par le 


drapeau -f comme dans : #!/usr/bin/calc [drapeaux_optionnels_autres
...]

-f le reste du fichier sera traité en mode script shell. Notez que -s -f doit être à la fin de la ligne ``#!'' initiale. Tout autre drapeau_optionnel_autre doit venir

avant le

drapeau -f. En mode script shell, le contenu du fichier est lu et exécuté comme s'il s'agissait d'un fichier traité par une commande read, sauf qu'une "commande" commençant par '#' suivi d'espaces blancs et se terminant à la nouvelle ligne suivante est traitée comme un commentaire.

Tout

drapeau_optionnel_autre sera analysé en premier, suivi des lignes ultérieures du script lui-même. En mode script shell, -s est toujours supposé. De plus, -d et -p sont automatiquement définis

si

-i n'est pas donné. NOTE : L'utilisation de -f n'implique PAS -q et donc on devrait

utiliser

name

pour désactiver également l'utilisation des fichiers de démarrage de

calc.

Par exemple, si le fichier /tmp/merse

nne : 


#!/usr/bin/calc-q -f
/* setup */
argc = argv();
program = argv(0);
stderr = files(2);
/* parse args */
if (argc != 2) {
    fprintf(stderr, "usage: %s exp0, program);
    abort "must give one exponent arg";
}
exp = eval(argv(1));
if (!isint(exp) || exp < 0) {
    fprintf(stderr, "%s: exp must be non-negative integer0, program);
    abort "must give one exponent arg";
}
/* print the mersenne number */
print "2^": exp : "-1 =",
2^exp-1;

est rendu exécutable par

: 


chmod +x
/tmp/mersenne

puis la ligne de commande

: 


/tmp/mersenne
127

affichera

: 


2^127-1 = 17014118346046923173168730371588410572
7

Notez que parce que -s est requis en mode script shell, les arguments sans tiret sont disponibles sous forme de chaînes de caractères via la fonction intégrée argv(). Par conséquent

: 


2^eval(argv(1))
-1

affichera la valeur décimale de 2^n-1 alors

que 


2^argv(1)
-1

ne le fera

pas.

Par défaut, en utilisant le démarrage de calc en mode script shell, calc fermera l'entrée standard (stdin). Ainsi, des fonctions intégrées comme prompt(str) échoueront (retourneront une valeur nulle). Les scripts shell calc qui appellent la fonction intégrée prompt(str) ne fonctionneront pas correctement (la fonction intégrée prompt échouera toujours et retournera une valeur nulle) sauf sihe l'option -p est donnée sur la ligne de

commande.

Le script shell suivant affichera toujours "got null" car l'entrée standard sera fermée par calc au démarrage

: 


#!/usr/bin/calc -q -f
# L'invite échouera TOUJOURS et retournera une valeur nulle
n = prompt("Test> ");
if (isnull(n)) {
  print("got null");
} else {
  print("got " + n);
}

Cependant, le script shell suivant (notez le -p avant le -f sur la 1ère ligne) sera interactif, affichera l'invite "Test> " et affichera le résultat "got" comme prévu

: 


#!/usr/bin/calc -q -p -f
n = prompt("Test> ");
if (isnull(n)) {
  print("got null");
} else {
  print("got " + n);
}

Notez que dans l'exemple ci-dessus, l'option -p doit être donnée avant l'option de ligne de commande -f fi

nal
e.

TYPES DE

DONNÉES

Les types de données intégrés fondamentaux incluent les entiers, les nombres réels, les nombres rationnels, les nombres complexes et les chaînes de

caractères.

À l'aide d'un objet, on peut définir des types de données arbitrairement complexes. On peut définir le comportement de tels objets pour un large éventail d'opérations telles que l'addition, la soustraction, la multiplication, la division, la négation, le carré, le module, l'arrondi, l'exponentiation, l'égalité, la comparaison, l'affichage,

etc.

Pour plus d'informations, utilisez les commandes calc suivantes

:


help types
help obj
show objfuncs

VARIABLE

S

Les variables dans calc sont sans type. En d'autres termes, le type fondamental d'une variable est déterminé par son contenu. Avant qu'une variable ne reçoive une valeur, elle a la valeur

zéro.

La portée d'une variable peut être globale, locale à un fichier, ou locale à une procédure. Les valeurs peuvent être regroupées dans une matrice, ou dans une liste qui permet des opérations de style pile et file

d'attente.

Pour plus d'informations, utilisez les commandes calc suivantes

:


help variable
help mat
help list
show globals

ENTRÉE/SORTI

E

Un préfixe ``0x'' indique une valeur hexadécimale, un préfixe ``0b'' indique une valeur binaire, et un ``0'' suivi d'un chiffre indique une valeur octale. Les nombres complexes sont indiqués par un suffixe ``i'' comme dans ``3+4i''. Les chaînes de caractères peuvent être délimitées soit par une paire de guillemets simples, soit par une paire de guillemets doubles. Par défaut, calc affiche les valeurs comme s'il s'agissait de nombres en virgule flottante. On peut changer ce comportement par défaut pour afficher les valeurs dans un certain nombre de modes, y compris les fractions, les entiers et les

exponentielles.

Un certain nombre d'opérations d'E/S de fichiers de type stdio sont fournies. On peut ouvrir, lire, écrire, positionner et fermer des fichiers. Les noms de fichiers sont soumis à l'expansion de ``~'' vers les répertoires personnels d'une manière similaire à celle du Korn Shell ou du

C-Shell.

Par exemple

:


~/.calcrc
~chongo/lib/fft_multiply.cal

Pour plus d'informations, utilisez la commande calc suivante

:


help file

LANGAGE

CALC

Le langage calc est un langage de type C. Le langage inclut des commandes telles que les déclarations de variables, les expressions, les tests, les étiquettes, les boucles, les opérations sur les fichiers, les appels de fonctions. Ces commandes sont très similaires à leurs équivalents en

C.

Le langage inclut également un certain nombre de commandes propres à calc lui-même. Celles-ci incluent des commandes telles que la définition de fonction, l'aide, la lecture de fichiers de ressources, le vidage de fichiers vers un fichier, la notification d'erreurs, le contrôle de configuration et le

statut.

Pour plus d'informations, utilisez la commande calc suivante

:


help command
help statement
help expression
help operator
help config
