DESCRIPTIO

N

La prise en charge et l'utilisation des capacités Linux peuvent être explorées et contraintes avec cet outil.

Cet outil fournit une enveloppe pratique pour certains types de tests de capacités et de création d'environ
nements. Il fournit également certaines fonctionnalités de débogage utiles pour résumer l'état des capacités.

OPTION

S

capsh accepte un certain nombre d'arguments facultatifs, agissant sur eux dans l'ordre où ils sont fournis. Ce sont les suivants

:
--he
lp
Affiche la liste des commandes prises en charge par caps
h.
--pri
nt
Affiche les capacités et l'état associé en
vigueur.
--curre
nt
Affiche l'état des capacités en vigueur, les capacités 1e et le vecteur
IAB.
-- [arg
s]
Exécute /bin/bash avec les arguments restants. Notez que vous pouvez utiliser -c 'commande à exécuter' pour des commandes
spécifiques.
-+ [arg
s]
Utilise cap_launch(3) pour créer un processus fils qui exécute le shell. Lorsque le fils se termine, capsh se termine avec l'état du fils ou 1 dans le cas où le fils a été terminé par un
signal.
== [arg
s]
Exécute capsh à nouveau avec les arguments restants. Utile pour tester le comportement de exec(). Notez que le chemin est recherché lorsque le capsh en cours d'exécution a été trouvé via la recherche de chemin du shell. Si le exec se produit après un argument --chroot=/chemin/quelconque, le binaire trouvé via le chemin peut ne pas être résolu vers le même binaire que celui exécuté initialement. Ce comportement est une fonctionnalité prévue car il peut compléter la transition
chroot.
=+ [arg
s]
Utilise cap_launch(3) pour créer un processus fils qui ré-exécute capsh. Lorsque ce fils se termine, capsh se termine avec l'état du fils ou 1 dans le cas où le fils a été terminé par un
signal.
--caps=jeu-de-capa
cités
Définit les capacités du processus en vigueur à celles spécifiées par jeu-de-capacités. Où jeu-de-capacités est une représentation textuelle d'un « ensemble » de capacités tel que défini dans cap_text_form
ats(7).
--drop=liste-de-capa
cités
Supprime les capacités listées de l'ensemble englobant en vigueur. Les capacités sont une liste de capacités séparées par des virgules telles que reconnues par la fonction cap_from_name(3). L'utilisation de cette fonctionnalité nécessite que capsh fonctionne avec CAP_SETPCAP dans son ensemble
effectif.
--inh=liste-de-capa
cités
Définit l'ensemble héritable des capacités pour le processus actuel à égalité avec celles fournies dans la liste séparée par des virgules. Pour que cette action réussisse, le processus en vigueur devrait déjà avoir chacune de ces capacités dans l'union des ensembles de capacités héritables et permises actuels, ou capsh devrait fonctionner avec CAP_SETPCAP dans son ensemble
effectif.
--user=nom-d'utilis
ateur
Prend l'identité de l'utilisateur nommé. C'est-à-dire, recherche l'UID et le GID de l'utilisateur avec getpwuid(3) et ses appartenances de groupe avec getgrouplist(3) et les définit tous en utilisant cap_setuid(3) et cap_setgroups(3). À la suite de cette commande, les capacités effectives seront effacées, mais l'ensemble permis ne le sera pas, de sorte que le programme en cours d'exécution est toujours
privilégié.
--mo
de
Affiche le mode libcap en vigueur tel que deviné par la fonction cap_get_mode(3)
.
--mode=<mod
e>
Force le programme dans un mode de sécurité cap_set_mode(3). C'est un ensemble de bits de sécurité (securebits) et d'arrangement des capacités en vigueur recommandé pour sa position de sécurité
prédéterminée.
--mod
es
Liste tous les modes libcap pris en charge par --mode=<m
ode>.
--inmode=<mo
de>
Confirme que le mode en vigueur est celui spécifié dans <mode>, ou se termine avec un état
1.
--uid=i
d
Force toutes les valeurs d'UID à égalité avec id en utilisant l'appel système setuid(2). Cet argument peut nécessiter une préparation explicite de l'ensemble
effectif.
--cap-uid=<u
id>
utilise la fonction cap_setuid(3) pour définir l'UID du processus actuel. Cela effectue toutes les préparations pour définir l'UID sans supprimer de capacités dans le processus. À la suite de cette commande, les capacités effectives en vigueur seront
abaissées.
--is-uid=<i
d>
Se termine avec l'état 1 sauf si l'UID actuel est égal à <id
>.
--gid=<i
d>
Force toutes les valeurs de GID à égalité avec id en utilisant l'appel système setgid(
2).
--is-gid=<i
d>
Se termine avec l'état 1 sauf si le GIQ actuel est égal à <id
>.
--groups=<liste-de-g
id>
Définit les groupes supplémentaires à la liste numérique fournie. Les groupes sont définis avec l'appel système setgroups(2). Voir --user pour une façon plus pratique de faire
cela.
--keep=<0|
1>
Dans un mode de capacités non pur, le noyau accorde des privilèges libéraux à le super-utilisateur. Cependant, il est normalement le cas que lorsque le super-utilisateur change d'UID vers un utilisateur moins privilégié, les capacités sont supprimées. Pour ces situations, le noyau peut permettre au processus de conserver ses capacités après un appel système setuid(2). Cette fonctionnalité est connue sous le nom de prise en charge de keep-caps. La façon de l'activer en utilisant ce programme est avec cet argument. Définir la valeur à 1 causera que keep-caps soit actif. Le définir à 0 causera que keep-caps se désactive pour le processus actuel. Dans tous les cas, keep-caps est désactivé lorsqu'un exec() est effectué. Voir --secbits et--mode pour des façons de désactiver cette
fonctionnalité.
--secbits=
N
Définit les bits de sécurité pour le programme. Cela est fait en utilisant l'opération prctl(2) PR_SET_SECUREBITS. La liste des bits pris en charge et leur signification peut être trouvée dans le fichier d'en-tête <sys/secbits.h>. Le programme listera ces bits via la commande --print. L'argument est exprimé sous forme de masque de bits numérique, dans n'importe lequel des formats autorisés par strtoul(3). Une alternative à cette manipulation de bits est intégrée dans les arguments de ligne de commande --mode*
.
--chroot=/chemin/quelco
nque
Exécute l'appel système chroot(2) avec le nouveau répertoire racine (/) égal à chemin. Cette opération nécessite que CAP_SYS_CHROOT soit en
vigueur.
--forkfor=se
c
Cette commande fait en sorte que le programme crée un processus fils pendant autant de secondes. Le fils dormira pendant ce temps puis se terminera avec l'état 0. Le but de cette commande est de soutenir l'exploration de la façon dont les processus peuvent être tués face aux changements de capacités. Voir la commande --killit. Un seul fork peut être actif à la
fois.
--killit=si
g
Cette commande fait en sorte qu'un fils de --forkfor soit tué avec kill(2) avec le signal spécifié. La commande attend ensuite que le fils se termine. Si l'état de sortie ne correspond pas au signal utilisé pour le tuer, le programme capsh se termine avec l'état
1.
--explain=cap_x
xx
Donne une brève description textuellel description of what privileges the specified capability makes available to a running program. Note, instead of cap_xxx, one can provide a decimal number and capsh will look up the corresponding capability's
description.
--shell=/full/pa
th
This option changes the shell that is invoked when the argument == is
encountered.
--stri
ct
This option toggles the suppression of subsequent attempts to fixup --caps= and --inh= arguments. That is, when the prevailing Effective flag does not contain CAP_SETPCAP the to be raised Inheritable Flag values (in strict mode) are limited to those in the Permitted set. The strict mode defaults to off. Supplying this argument an even number of times restores this default
behavior.
--suggest=phra
se
Scan each of the textual descriptions of capabilities, known to capsh, and display all descriptions that include phras
e.

--supports=xx
x
As the kernel evolves, more capabilities are added. This option can be used to verify the existence of a capability on the system. For example, --supports=cap_syslog will cause capsh to promptly exit with a status of 1 when run on kernel 2.6.27. However, when run on kernel 2.6.38 it will silently
succeed.
--has-p=xx
x
Exit with status 1 unless the permitted vector has capability xxx rai
sed.
--has-ambie
nt
Performs a check to see if the running kernel supports ambient capabilities. If not, capsh exits with status
1.
--has-a=xx
x
Exit with status 1 unless the ambient vector has capability xxx rai
sed.
--has-b=xx
x
Exit with status 1 unless the bounding vector has capability xxx in its (default) non-blocked
state.
--iab=xx
x
Attempts to set the IAB tuple of inheritable capability vectors. The text conventions used for xxx are those of cap_iab_from_text(3), and described in cap_text_form
ats(7).
--addamb=xx
x
Adds the specified ambient capability to the running
process.
--delamb=xx
x
Removes the specified ambient capability from the running
process.
--noa
mb
Drops all ambient capabilities from the running
process.
--noe
nv
Suppresses overriding of the HOME and USER environment variables when a subsequent --user argument is
processed.
--qui
et
This argument is ignored unless it is the first one. If p
resent, it suppresses the capsh runtime check to co
nfirm the running libcap is recent enough that it ca
n name all of the kernel supported capability values.
