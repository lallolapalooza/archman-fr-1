sous-routine cgejsv (character*1 joba, character*1 jobu, character*1 jobv, character*1 jobr, character*1 jobt, character*1 jobp, integer m, integer n, complex, dimension( lda, * ) a, integer lda, real, dimension( n ) sva, complex, dimension( ldu, * ) u, integer ldu, complex, dimension( ldv, * ) v, integer ldv, complex, dimension( lwork ) cwork, integer lwork, real, dimension( lrwork ) rwork, integer lrwork, integer, dimension( * ) iwork, integer

info)

CGEJS

V

But

: 
!>
!> CGEJSV calcule la décomposition en valeurs singulières (SVD) d'une matrice
!> complexe M par N [A], où M >= N. La SVD de [A] est écrite comme suit :
!>
!>              [A] = [U] * [SIGMA] * [V]^*,
!>
!> où [SIGMA] est une matrice N par N (ou M par N) qui est nulle sauf pour ses
!> N éléments diagonaux, [U] est une matrice unitaire M par N (ou M par M), et
!> [V] est une matrice unitaire N par N. Les éléments diagonaux de [SIGMA] sont
!> les valeurs singulières de [A]. Les colonnes de [U] et [V] sont les vecteurs
!> singuliers gauche et droit de [A], respectivement. Les matrices [U] et [V]
!> sont calculées et stockées dans les tableaux U et V, respectivement. La
!> diagonale de [SIGMA] est calculée et stockée dans le tableau SVA.
!
>

Paramètre

s
JOBA 
!>          JOBA est de type CHARACTER*1
!>         Spécifie le niveau de précision :
!>       = 'C' : Cette option fonctionne bien (précision relative élevée) si A = B * D,
!>              avec B bien conditionnée et D une matrice diagonale quelconque.
!>              La précision ne peut être altérée par la mise à l'échelle des COLONNES.
!>              La précision de la sortie calculée dépend du conditionnement de
!>              B, et la procédure vise la meilleure précision théorique.
!>              L'erreur relative max_{i=1:N}|d sigma_i| / sigma_i est
!>              bornée par f(M,N)*epsilon* cond(B), indépendamment de D.
!>              La matrice d'entrée est prétraitée avec la factorisation QRF avec
!>              pivotement de colonnes. Ce prétraitement initial et ce
!>              préconditionnement par une factorisation QR révélatrice de rang
!>              sont communs à toutes les valeurs de JOBA. Des actions
!>              supplémentaires sont spécifiées comme suit :
!>       = 'E' : Calcul identique à 'C' avec une estimation supplémentaire du
!>              nombre de conditionnement de B. Cela fournit une borne d'erreur réaliste.
!>       = 'F' : Si A = D1 * C * D2 avec des mises à l'échelle diagonales
!>              mal conditionnées D1, D2, et une matrice C bien conditionnée,
!>              cette option donne une précision supérieure à l'option 'C'. Si la
!>              structure de la matrice d'entrée n'est pas connue et qu'une
!>              précision relative est souhaitée, alors cette option est conseillée.
!>              La matrice d'entrée A est prétraitée avec une factorisation QR avec
!>              pivotement COMPLET (lignes et colonnes).
!>       = 'G' : Calcul identique à 'F' avec une estimation supplémentaire du
!>              nombre de conditionnement de B, où A=B*D. Si A a des lignes très
!>              pondérées, alors l'utilisation de ce nombre de conditionnement donne
!>              une borne d'erreur trop pessimiste.
!>       = 'A' : Les petites valeurs singulières ne sont pas bien déterminées par les
!>              données et sont considérées comme bruitées ; la matrice est traitée
!>              comme étant de rang numérique déficient. L'erreur dans les valeurs
!>              singulières calculées est bornée par f(m,n)*epsilon*||A||.
!>              La SVD calculée A = U * S * V^* restaure A à
!>              f(m,n)*epsilon*||A|| près.
!>              Cela donne à la procédure l'autorisation d'écarter (mettre à zéro)
!>              toutes les valeurs singulières inférieures à N*epsilon*||A||.
!>       = 'R' : Similaire à 'A'. La propriété de révélation de rang de la
!>              factorisation QR initiale est utilisée pour révéler (à l'aide du
!>              facteur triangulaire) un écart sigma_{r+1} < epsilon * sigma_r,
!>              dans lequel cas le RANG numérique est déclaré être r. La SVD est
!>              calculée avec des bornes d'erreur absolues, mais plus
!>              précisément qu'avec 'A'.
!
>

JOB

U 
!>          JOBU est de type CHARACTER*1
!>         Spécifie s'il faut calculer les colonnes de U :
!>       = 'U' : N colonnes de U sont retournées dans le tableau U.
!>       = 'F' : l'ensemble complet des M vecteurs singuliers gauches est retourné
!>              dans le tableau U.
!>       = 'W' : U peut être utilisé comme espace de travail de longueur M*N. Voir la
!>              description de U.
!>       = 'N' : U n'est pas calculé.
!
>

JOB

V 
!>          JOBV est de type CHARACTER*1
!>         Spécifie s'il faut calculer la matrice V :
!>       = 'V' : N colonnes de V sont retournées dans le tableau V ; les rotations
!>              de Jacobi ne sont pas explicitement accumulées.
!>       = 'J' : N colonnes de V sont retournées dans le tableau V, mais elles sont
!>              calculées comme le produit des rotations de Jacobi, si JOBT = 'N'.
!>       = 'W' : V peut être utilisé comme espace de travail de longueur N*N. Voir la
!>              description de V.
!>       = 'N' : V n'est pas calculé.
!
>

JOB

R 
!>          JOBR est de type CHARACTER*1
!>         Spécifie la PLAGE pour les valeurs singulières. Donne l'autorisation de
!>         mettre à zéro les petites valeurs singulières positives si elles sont
!>         en dehors de la plage spécifiée. Si A .NE. 0 est mise à l'échelle de
!>         sorte que la plus grande valeur singulière de c*A soit autour de
!>         SQRT(BIG), BIG=SLAMCH('O'), alors JOBR donne l'autorisation de
!>         supprimer les colonnes de A dont la norme dans c*A est inférieure à
!>         SQRT(SFMIN) (pour JOBR = 'R'), ou inférieure à SMALL=SFMIN/EPSLN,
!>         où SFMIN=SLAMCH('S'), EPSLN=SLAMCH('E').
!>       = 'N' : Ne pas supprimer les petites colonnes de c*A. Cette option suppose
!>              que les BLAS et les factorisations QR et les résolveurs
!>              triangulaires sont implémentés pour fonctionner dans cette plage.
!>              Si le conditionnement de A est supérieur à BIG, utilisez CGESVJ.
!>       = 'R' : La plage RESTREINTE pour sigma(c*A) est [SQRT(SFMIN), SQRT(BIG)]
!>              (grosso modo, comme décrit ci-dessus). Cette option est recommandée.
!>                                             ===========================
!>         Pour calculer les valeurs singulières dans la plage COMPLÈTE [SFMIN,BIG]
!>         utilisez CGESVJ.
!
>

JOB

T 
!>          JOBT est de type CHARACTER*1
!>         Si la matrice est carrée, la procédure peut décider d'utiliser A
!>         transposée si A^* semble meilleure en ce qui concerne la convergence.
!>         Si la matrice n'est pas carrée, JOBT est ignoré.
!>         La décision est basée sur deux valeurs d'entropie sur l'orbite
!>         adjointe de A^* * A. Voir les descriptions de RWORK(6) et RWORK(7).
!>       = 'T' : transposer si le test d'entropie indique une convergence
!>         possiblement plus rapide du processus de Jacobi si A^* est prise comme
!>         entrée. Si A est remplacée par A^*, alors le pivotement de lignes est
!>         inclus automatiquement.
!>       = 'N' : ne pas spéculer.
!>         L'option 'T' peut être utilisée pour calculer uniquement les valeurs
!>         singulières, ou la SVD complète (U, SIGMA et V). Pour un seul ensemble
!>         de vecteurs singuliers (U ou V), l'appelant doit fournir à la fois U et
!>         V, car l'une des matrices est utilisée comme espace de travail si la
!>         matrice A est transposée.
!>         L'implémenteur peut facilement supprimer cette contrainte et rendre le
!>         code plus compliqué. Voir les descriptions de U et V.
!>         En général, cette option est considérée comme expérimentale, et 'N' devrait
!>         être préféré. Cela est sujet à changement à l'avenir.
!
>

JOB

P 
!>          JOBP est de type CHARACTER*1
!>         Donne l'autorisation d'introduire des perturbations structurées pour noyer
!>         les nombres dénormalisés. Cette licence devrait être active si les
!>        dénormalisés sont mal implémentés, causant des calculs lents,
!>        surtout dans les cas de convergence rapide (!). Pour details voir [1,2].
!>         Pour la simplicité, ces perturbations ne sont incluses que
!>         lorsque la SVD complète ou uniquement les valeurs singulières sont demandées. L'
!>         implémenteur/utilisateur peut facilement ajouter la perturbation pour les cas de
!>         calcul d'un ensemble de vecteurs singuliers.
!>       = 'P' : introduire une perturbation
!>       = 'N' : ne pas perturber
!>

M

!>          M est un entier (INTEGER)
!>         Le nombre de lignes de la matrice d'entrée A.  M >= 0.
!>

N

!>          N est un entier (INTEGER)
!>         Le nombre de colonnes de la matrice d'entrée A. M >= N >= 0.
!>

A

!>          A est un tableau complexe (COMPLEX array), de dimension (LDA,N)
!>          En entrée, la matrice A de taille M par N.
!>

LDA

!>          LDA est un entier (INTEGER)
!>         La dimension principale du tableau A.  LDA >= max(1,M).
!>

SVA

!>          SVA est un tableau réel (REAL array), de dimension (N)
!>          En sortie,
!>          - Pour RWORK(1)/RWORK(2) = ONE : Les valeurs singulières de A. Pendant
!>            le calcul, SVA contient les normes euclidiennes des colonnes des
!>            matrices itérées dans le tableau A.
!>          - Pour RWORK(1) .NE. RWORK(2) : Les valeurs singulières de A sont
!>            (RWORK(1)/RWORK(2)) * SVA(1:N). Cette forme factorisée est utilisée si
!>            sigma_max(A) déborde (overflow) ou si de petites valeurs singulières ont été
!>            sauvegardées contre le sous-dépassement (underflow) en mettant à l'échelle la matrice d'entrée A.
!>          - Si JOBR='R', alors certaines des valeurs singulières peuvent être retournées
!>            comme des zéros exacts obtenus car elles sont
!>            en dessous du seuil de rang numérique ou sont des nombres dénormalisés.
!>

U

!>          U est un tableau complexe (COMPLEX array), de dimension ( LDU, N ) ou ( LDU, M )
!>          Si JOBU = 'U', alors U contient en sortie la matrice M par N des
!>                         vecteurs singuliers gauches.
!>          Si JOBU = 'F', alors U contient en sortie la matrice M par M des
!>                         vecteurs singuliers gauches, incluant une base orthonormée (ONB)
!>                         du complément orthogonal de l'image (Range(A)).
!>          Si JOBU = 'W'  .ET. (JOBV = 'V' .ET. JOBT = 'T' .ET. M = N),
!>                         alors U est utilisé comme espace de travail si la procédure
!>                         remplace A par A^*. Dans ce cas, [V] est calculé
!>                         dans U comme vecteurs singuliers gauches de A^* puis
!>                         copié dans le tableau V. Cette option 'W' est juste
!>                         un rappel à l'appelant que dans ce cas U est
!>                         réservé comme espace de travail de longueur N*N.
!>          Si JOBU = 'N'  U n'est pas référencé, sauf si JOBT='T'.
!>

LDU

!>          LDU est un entier (INTEGER)
!>          La dimension principale du tableau U,  LDU >= 1.
!>          SI  JOBU = 'U' ou 'F' ou 'W',  alors LDU >= M.
!>

V

!>          V est un tableau complexe (COMPLEX array), de dimension ( LDV, N )
!>          Si JOBV = 'V', 'J' alors V contient en sortie la matrice N par N des
!>                         vecteurs singuliers droits ;
!>          Si JOBV = 'W', ET (JOBU = 'U' ET JOBT = 'T' ET M = N),
!>                         alors V est utilisé comme espace de travail si la procédure
!>                         remplace A par A^*. Dans ce cas, [U] est calculé
!>                         dans V comme vecteurs singuliers droits de A^* puis
!>                         copié dans le tableau U. Cette option 'W' est juste
!>                         un rappel à l'appelant que dans ce cas V est
!>                         réservé comme espace de travail de longueur N*N.
!>          Si JOBV = 'N'  V n'est pas référencé, sauf si JOBT='T'.
!>

LDV

!>          LDV est un entier (INTEGER)
!>          La dimension principale du tableau V,  LDV >= 1.
!>          Si JOBV = 'V' ou 'J' ou 'W', alors LDV >= N.
!>

CWORK

!>          CWORK est un tableau complexe (COMPLEX array), de dimension (MAX(2,LWORK))
!>          Si l'appel à CGEJSV est une requête d'espace de travail (indiquée par LWORK=-1 ou
!>          LRWORK=-1), alors en sortie CWORK(1) contient la longueur requise de 
!>          CWORK pour les paramètres de job utilisés dans l'appel.
!>

LWORK

!>          LWORK est un entier (INTEGER)
!>          La longueur de CWORK pour confirmer l'allocation correcte de l'espace de travail.
!>          LWORK dépend du job :
!>
!>          1. Si SEULEMENT SIGMA est nécessaire ( JOBU = 'N', JOBV = 'N' ) et
!>            1.1 .. aucune estimation de nombre de conditionnement mis à l'échelle requise (JOBA.NE.'E'.AND.JOBA.NE.'G') :
!>               LWORK >= 2*N+1. C'est l'exigence minimale.
!>               ->> Pour des performances optimales (code bloqué), la valeur optimale
!>               est LWORK >= N + (N+1)*NB. Ici NB est la taille de bloc optimale
!>               pour CGEQP3 et CGEQRF.
!>               En général, LWORK optimal est calculé comme
!>               LWORK >= max(N+LWORK(CGEQP3),N+LWORK(CGEQRF), LWORK(CGESVJ)).        
!>            1.2. .. une estimation du nombre de conditionnement mis à l'échelle de A est
!>               requise (JOBA='E', ou 'G'). Dans ce cas, LWORK, l'exigence minimale
!>               est LWORK >= N*N + 2*N.
!>               ->> Pour des performances optimales (code bloqué), la valeur optimale
!>               est LWORK >= max(N+(N+1)*NB, N*N+2*N)=N**2+2*N.
!>               En général, la longueur LWORK optimale est calculée comme
!>               LWORK >= max(N+LWORK(CGEQP3),N+LWORK(CGEQRF), LWORK(CGESVJ),
!>                            N*N+LWORK(CPOCON)).
!>          2. Si SIGMA et les vecteurs singuliers droits sont nécessaires (JOBV = 'V'),
!>             (JOBU = 'N')
!>            2.1   .. aucune estimation de nombre de conditionnement mis à l'échelle requise (JOBE = 'N') :    
!>            -> l'exigence minimale est LWORK >= 3*N.
!>            -> Pour des performances optimales, 
!>               LWORK >= max(N+(N+1)*NB, 2*N+N*NB)=2*N+N*NB,
!>               où NB est la taille de bloc optimale pour CGEQP3, CGEQRF, CGELQF,
!>               CUNMLQ. En général, la longueur LWORK optimale est calculée comme
!>               LWORK >= max(N+LWORK(CGEQP3), N+LWORK(CGESVJ),
!>                       N+LWORK(CGELQF), 2*N+LWORK(CGEQRF), N+LWORK(CUNMLQ)).
!>            2.2 .. une estimation du nombre de conditionnement mis à l'échelle de A est
!>               requise (JOBA='E', ou 'G').
!>            -> l'exigence minimale est LWORK >= 3*N.      
!>            -> Pour des performances optimales, 
!>               LWORK >= max(N+(N+1)*NB, 2*N,2*N+N*NB)=2*N+N*NB,
!>               où NB est la taille de bloc optimale pour CGEQP3, CGEQRF, CGELQF,
!>               CUNMLQ. En général, la longueur LWORK optimale est calculée comme
!>               LWORK >= max(N+LWORK(CGEQP3), LWORK(CPOCON), N+LWORK(CGESVJ),
!>                       N+LWORK(CGELQF), 2*N+LWORK(CGEQRF), N+LWORK(CUNMLQ)).   
!>          3. Si SIGMA et les vecteurs singuliers gauches sont nécessaires
!>            3.1  .. aucune estimation de nombre de conditionnement mis à l'échelle requise (JOBE = 'N') :
!>            -> l'exigence minimale est LWORK >= 3*N.
!>            -> Pour des performances optimales :
!>               si JOBU = 'U' :: LWORK >= max(3*N, N+(N+1)*NB, 2*N+N*NB)=2*N+N*NB,
!>               où NB est la taille de bloc optimale pour CGEQP3, CGEQRF, CUNMQR.
!>               En général, la longueur LWORK optimale est calculée comme
!>               LWORK >= max(N+LWORK(CGEQP3), 2*N+LWORK(CGEQRF), N+LWORK(CUNMQR)). 
!>            3.2  .. une estimation du nombre de conditionnement mis à l'échelle de A est
!>               requise (JOBA='E', ou 'G').
!>            -> l'exigence minimale est LWORK >= 3*N.
!>            -> Pour des performances optimales :
!>               si JOBU = 'U' :: LWORK >= max(3*N, N+(N+1)*NB, 2*N+N*NB)=2*N+N*NB,
!>               où NB est la taille de bloc optimale pour CGEQP3, CGEQRF, CUNMQR.
!>               En général, la longueur LWORK optimale est calculée comme
!>               LWORK >= max(N+LWORK(CGEQP3),N+LWORK(CPOCON),
!>                        2*N+LWORK(CGEQRF), N+LWORK(CUNMQR)).
!>
!>          4. Si la SVD complète est nécessaire : (JOBU = 'U' ou JOBU = 'F') et
!>            4.1. si JOBV = 'V'
!>               l'exigence minimale est LWORK >= 5*N+2*N*N.
!>            4.2. si JOBV = 'J' l'exigence minimale est
!>               LWORK >= 4*N+N*N.
!>            Dans les deux cas, le CWORK alloué peut accueillir des exécutions bloquées
!>            de CGEQP3, CGEQRF, CGELQF, CUNMQR, CUNMLQ.
!> 
!>          Si l'appel à CGEJSV est une requête d'espace de travail (indiquée par LWORK=-1 ou
!>          LRWORK=-1), alors en sortie CWORK(1) contient la longueur optimale et CWORK(2) contient la
!>          longueur minimale de CWORK pour les paramètres de job utilisés dans l'appel.        
!>

RWORK

!>          RWORK est un tableau réel (REAL array), de dimension (MAX(7,LRWORK))
!>          En sortie,
!>          RWORK(1) = Détermine le facteur de mise à l'échelle SCALE = RWORK(2) / RWORK(1)
!>                    tel que SCALE*SVA(1:N) sont les valeurs singulières calculées
!>                    de A. (Voir la description de SVA().)
!>          RWORK(2) = Voir la description de RWORK(1).
!>          RWORK(3) = SCONDA est une estimation du nombre de conditionnement
!>                    de A équilibrée par colonnes. (Si JOBA = 'E' ou 'G')
!>                    SCONDA est une estimation de SQRT(||(R^* * R)^(-1)||_1).
!>                    Elle est calculée en utilisant CPOCON. Elle satisfait
!>                    N^(-1/4) * SCONDA <= ||R^(-1)||_2 <= N^(1/4) * SCONDA
!>                    où R est le facteur triangulaire de la QRF de A.
!>                    Cependant, si R est tronqué et que le rang numérique est
!>                    déterminé comme étant strictement inférieur à N, SCONDA est
!>                    retourné comme -1, indiquant ainsi que les plus petites
!>                    valeurs singulières pourraient être perdues.
!>
!>          Si la SVD complète est nécessaire, les deux nombres de conditionnement suivants sont
!>          utiles pour l'analyse de l'algorithme. Ils sont fournis pour
!>          un développeur/implémenteur familier avec les détails
!>          de la méthode.
!>
!>          RWORK(4) = une estimation du nombre de conditionnement mis à l'échelle du
!>                    facteur triangulaire dans la première factorisation QR.
!>          RWORK(5) = une estimation du nombre de conditionnement mis à l'échelle du
!>                    facteur triangulaire dans la seconde factorisation QR.
!>          Les deux paramètres suivants sont calculés si JOBT = 'T'.
!>          Ils sont fournis pour un développeur/implémenteur familier
!>          avec les détails de la méthode.
!>          RWORK(6) = l'entropie de A^* * A :: c'est l'entropie de Shannon
!>                    de diag(A^* * A) / Trace(A^* * A) considéré comme un point dans le
!>                    simplexe de probabilité.
!>          RWORK(7) = l'entropie de A * A^*. (Voir la description de RWORK(6).)
!>          Si l'appel à CGEJSV est une requête d'espace de travail (indiquée par LWORK=-1 ou
!>          LRWORK=-1), alors en sortie RWORK(1) contient la longueur requise de
!>          RWORK pour les paramètres de job utilisés dans l'appel.
!>

LRWORK

!>          LRWORK est un entier (INTEGER)
!>          La longueur de RWORK pour confirmer l'allocation correcte de l'espace de travail.
!>          LRWORK dépend du job :
!>
!>       1. Si seulement les valeurs singulières sont demandées, c'est-à-dire si
!>          LSAME(JOBU,'N') .ET. LSAME(JOBV,'N')
!>          alors :
!>          1.1. Si LSAME(JOBT,'T') .OU. LSAME(JOBA,'F') .OU. LSAME(JOBA,'G'),
!>               alors : LRWORK = max( 7, 2 * M ).
!>
1.2. Sinon, LRWORK = max( 7, N ). !> 2. Si les valeurs singulières avec les vecteurs singuliers droits sont demandées !> c.-à-d. si !> (LSAME(JOBV,'V').OR.LSAME(JOBV,'J')) .AND. !> .NOT.(LSAME(JOBU,'U').OR.LSAME(JOBU,'F')) !> alors : !> 2.1. Si LSAME(JOBT,'T') .OR. LSAME(JOBA,'F') .OR. LSAME(JOBA,'G'), !> alors LRWORK = max( 7, 2 * M ). !> 2.2. Sinon, LRWORK = max( 7, N ). !> 3. Si les valeurs singulières avec les vecteurs singuliers gauches sont demandées, c.-à-d. si !> (LSAME(JOBU,'U').OR.LSAME(JOBU,'F')) .AND. !> .NOT.(LSAME(JOBV,'V').OR.LSAME(JOBV,'J')) !> alors : !> 3.1. Si LSAME(JOBT,'T') .OR. LSAME(JOBA,'F') .OR. LSAME(JOBA,'G'), !> alors LRWORK = max( 7, 2 * M ). !> 3.2. Sinon, LRWORK = max( 7, N ). !> 4. Si les valeurs singulières avec à la fois les vecteurs singuliers gauches et droits !> sont demandées, c.-à-d. si !> (LSAME(JOBU,'U').OR.LSAME(JOBU,'F')) .AND. !> (LSAME(JOBV,'V').OR.LSAME(JOBV,'J')) !> alors : !> 4.1. Si LSAME(JOBT,'T') .OR. LSAME(JOBA,'F') .OR. LSAME(JOBA,'G'), !> alors LRWORK = max( 7, 2 * M ). !> 4.2. Sinon, LRWORK = max( 7, N ). !> !> Si, à l'entrée, LRWORK = -1 ou LWORK=-1, une interrogation d'espace de travail est supposée et !> la longueur de RWORK est renvoyée dans RWORK(1). !>

IWOR

K 
!>          IWORK est un tableau INTEGER, de dimension au moins 4, qui dépend en outre
!>          de la tâche :
!> 
!>          1. Si seules les valeurs singulières sont demandées alors :
!>             Si ( LSAME(JOBT,'T') .OR. LSAME(JOBA,'F') .OR. LSAME(JOBA,'G') ) 
!>             alors la longueur de IWORK est N+M ; sinon la longueur de IWORK est N.
!>          2. Si les valeurs singulières et les vecteurs singuliers droits sont demandés alors :
!>             Si ( LSAME(JOBT,'T') .OR. LSAME(JOBA,'F') .OR. LSAME(JOBA,'G') ) 
!>             alors la longueur de IWORK est N+M ; sinon la longueur de IWORK est N. 
!>          3. Si les valeurs singulières et les vecteurs singuliers gauches sont demandés alors :
!>             Si ( LSAME(JOBT,'T') .OR. LSAME(JOBA,'F') .OR. LSAME(JOBA,'G') ) 
!>             alors la longueur de IWORK est N+M ; sinon la longueur de IWORK est N. 
!>          4. Si les valeurs singulières avec à la fois les vecteurs singuliers gauches et droits
!>             sont demandés, alors :      
!>             4.1. Si LSAME(JOBV,'J') la longueur de IWORK est déterminée comme suit :
!>                  Si ( LSAME(JOBT,'T') .OR. LSAME(JOBA,'F') .OR. LSAME(JOBA,'G') ) 
!>                  alors la longueur de IWORK est N+M ; sinon la longueur de IWORK est N. 
!>             4.2. Si LSAME(JOBV,'V') la longueur de IWORK est déterminée comme suit :
!>                  Si ( LSAME(JOBT,'T') .OR. LSAME(JOBA,'F') .OR. LSAME(JOBA,'G') ) 
!>                  alors la longueur de IWORK est 2*N+M ; sinon la longueur de IWORK est 2*N.
!>        
!>          À la sortie,
!>          IWORK(1) = le rang numérique déterminé après la factorisation
!>                     QR initiale avec pivotement. Voir les descriptions
!>                     de JOBA et JOBR.
!>          IWORK(2) = le nombre des valeurs singulières non nulles calculées
!>          IWORK(3) = si non nul, un message d'avertissement :
!>                     Si IWORK(3) = 1 alors certaines des normes de colonnes de A
!>                     étaient des flottants dénormalisés. La haute précision demandée
!>                     n'est pas garantie par les données.
!>          IWORK(4) = 1 ou -1. Si IWORK(4) = 1, alors la procédure a utilisé A^* pour
!>                     effectuer la tâche telle que spécifiée par les paramètres JOB.
!>          Si l'appel à CGEJSV est une interrogation d'espace de travail (indiquée par LWORK = -1 et 
!>          LRWORK = -1), alors à la sortie IWORK(1) contient la longueur requise de 
!>          IWORK pour les paramètres de tâche utilisés dans l'appel.

Détails supplémentaires

: 
!>  CGEJSV implémente un algorithme SVD de Jacobi préconditionné. Il utilise CGEQP3,
!>  CGEQRF, et CGELQF comme préprocesseurs et préconditionneurs. En option, un
!>  pivotement de lignes supplémentaire peut être utilisé comme préprocesseur, ce qui dans certains
!>  cas donne une précision beaucoup plus élevée. Un exemple est la matrice A avec la
!>  structure A = D1 * C * D2, où D1, D2 sont des matrices diagonales arbitrairement mal conditionnées
!>  et C est une matrice bien conditionnée. Dans ce cas, le pivotement complet
!>  dans les premières factorisations QR fournit une précision dépendant du
!>  nombre de conditionnement de C, et indépendant de D1, D2. Cette précision accrue n'est
!>  pas entièrement comprise théoriquement, mais elle fonctionne bien en pratique.
!>  De plus, si A peut être écrit comme A = B*D, avec B bien conditionné et une certaine
!>  diagonale D, alors la haute précision est garantie, tant théoriquement que
!>  dans le logiciel, indépendamment de D. Pour plus de détails voir [1], [2].
!>     La plage de calcul pour les valeurs singulières peut être la plage complète
!>  ( UNDERFLOW,OVERFLOW ), à condition que l'arithmétique de la machine et les routines BLAS
!>  & LAPACK appelées par CGEJSV soient implémentées pour fonctionner dans cette plage.
!>  Si ce n'est pas le cas, alors la restriction pour un calcul sûr avec
!>  les valeurs singulières dans la plage des nombres IEEE normalisés est que le
!>  nombre de conditionnement spectral kappa(A)=sigma_max(A)/sigma_min(A) ne déborde pas.
!>  Ce code (CGEJSV) est mieux utilisé dans cette plage restreinte,
!>  ce qui signifie que les valeurs singulières de magnitude inférieure à ||A||_2 / SLAMCH('O') sont
!>  renvoyées comme zéros. Voir JOBR pour les détails à ce sujet.
!>     De plus, cette implémentation est quelque peu plus lente que celle décrite
!>  dans [1,2] en raison du remplacement de certains composants non-LAPACK, et parce que
!>  le choix de certains paramètres de réglage dans la partie itérative (CGESVJ) est
!>  laissé à l'implémentateur sur une machine particulière.
!>     La factorisation QR révélant le rang (dans ce code : CGEQP3) devrait être
!>  implémentée comme dans [3]. Nous avons une nouvelle version de CGEQP3 en développement
!>  qui est plus robuste que l'actuelle dans LAPACK, avec une coupure plus nette dans
!>  les cas de rang déficient. Elle sera disponible dans la bibliothèque SIGMA [4].
!>  Si M est beaucoup plus grand que N, il est évident que la QRF initiale avec
!>  pivotement de colonnes peut être prétraitée par la QRF sans pivotement. Cet
!>  astuce bien connue n'est pas utilisée dans CGEJSV car dans certains cas un fort
!>  pondération des lignes peut être traitée avec un pivotement complet. La surcharge dans les cas
!>  M beaucoup plus grand que N n'est alors due qu'au pivotement, mais les bénéfices en
!>  termes de précision ont prévalu. L'implémentateur/l'utilisateur peut intégrer
!>  cette étape QRF supplémentaire facilement. L'implémentateur peut également améliorer le déplacement
!>  des données (transposition de matrice, copie de matrice, copie transposée de matrice) - cette
!>  implémentation de CGEJSV utilise uniquement le déplacement de données le plus simple et naïf.
!
