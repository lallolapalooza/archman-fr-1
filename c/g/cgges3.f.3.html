sous-routine cgges3 (character jobvsl, character jobvsr, character sort, external selctg, integer n, complex, dimension( lda, * ) a, integer lda, complex, dimension( ldb, * ) b, integer ldb, integer sdim, complex, dimension( * ) alpha, complex, dimension( * ) beta, complex, dimension( ldvsl, * ) vsl, integer ldvsl, complex, dimension( ldvsr, * ) vsr, integer ldvsr, complex, dimension( * ) work, integer lwork, real, dimension( * ) rwork, logical, dimension( * ) bwork, integer info)

CGGES3 calcule les valeurs propres, la forme de Schur, et, optionnellement, la matrice des vecteurs de Schur pour les matrices GE (algorithme bloqué)

Objectif :

!>
!> CGGES3 calcule pour une paire de matrices complexes non symétriques N x N
!> (A,B), les valeurs propres généralisées, la forme de Schur généralisée
!> (S, T), et optionnellement les vecteurs de Schur gauches et/ou droits (VSL
!> et VSR). Ceci donne la factorisation de Schur généralisée
!>
!>         (A,B) = ( (VSL)*S*(VSR)**H, (VSL)*T*(VSR)**H )
!>
!> où (VSR)**H est la conjuguée transposée de VSR.
!>
!> Optionnellement, il ordonne également les valeurs propres de sorte qu'un
!> cluster sélectionné de valeurs propres apparaisse dans les blocs diagonaux
!> principaux de la matrice triangulaire supérieure S et de la matrice
!> triangulaire supérieure T. Les colonnes principales de VSL et VSR forment
!> alors une base unitaire pour les sous-espaces gauche et droits
!> correspondants (sous-espaces déflationnés).
!>
!> (Si seules les valeurs propres généralisées sont nécessaires, utilisez le pilote
!> CGGEV à la place, qui est plus rapide.)
!>
!> Une valeur propre généralisée pour une paire de matrices (A,B) est un scalaire w
!> ou un rapport alpha/beta = w, tel que A - w*B est singulière. Elle est
!> généralement représentée par la paire (alpha,beta), car il existe une
!> interprétation raisonnable pour beta=0, et même pour les deux étant nuls.
!>
!> Une paire de matrices (S,T) est en forme de Schur complexe généralisée si S
!> et T sont triangulaires supérieures et, en outre, les éléments diagonaux
!> de T sont des nombres réels non négatifs.
!>

Paramètres

JOBVSL 
!>          JOBVSL est CHARACTER*1
!>          = 'N':  ne pas calculer les vecteurs de Schur gauches ;
!>          = 'V':  calculer les vecteurs de Schur gauches.
!>

JOBVSR

!>          JOBVSR est CHARACTER*1
!>          = 'N':  ne pas calculer les vecteurs de Schur droits ;
!>          = 'V':  calculer les vecteurs de Schur droits.
!>

SORT

!>          SORT est CHARACTER*1
!>          Spécifie si les valeurs propres doivent être ordonnées ou non
!>          sur la diagonale de la forme de Schur généralisée.
!>          = 'N':  Les valeurs propres ne sont pas ordonnées ;
!>          = 'S':  Les valeurs propres sont ordonnées (voir SELCTG).
!>

SELCTG

!>          SELCTG est une FONCTION LOGIQUE de deux arguments COMPLEXES
!>          SELCTG doit être déclarée EXTERNE dans la sous-routine appelante.
!>          Si SORT = 'N', SELCTG n'est pas référencé.
!>          Si SORT = 'S', SELCTG est utilisé pour sélectionner les valeurs propres à trier
!>          en haut à gauche de la forme de Schur.
!>          Une valeur propre ALPHA(j)/BETA(j) est sélectionnée si
!>          SELCTG(ALPHA(j),BETA(j)) est vrai.
!>
!>          Notez qu'une valeur propre complexe sélectionnée peut ne plus satisfaire
!>          SELCTG(ALPHA(j),BETA(j)) = .TRUE. après l'ordonnancement, car
!>          l'ordonnancement peut modifier la valeur des valeurs propres complexes
!>          (surtout si la valeur propre est mal conditionnée), dans ce
!>          cas INFO est mis à N+2 (Voir INFO ci-dessous).
!>

N

!>          N est INTEGER
!>          L'ordre des matrices A, B, VSL et VSR.  N >= 0.
!>

A

!>          A est un tableau COMPLEX, dimension (LDA, N)
!>          En entrée, la première de la paire de matrices.
!>          En sortie, A a été écrasé par sa forme de Schur généralisée
!>          S.
!>

LDA

!>          LDA est INTEGER
!>          La dimension principale de A.  LDA >= max(1,N).
!>

B

!>          B est un tableau COMPLEX, dimension (LDB, N)
!>          En entrée, la seconde de la paire de matrices.
!>          En sortie, B a été écrasé par sa forme de Schur généralisée
!>          T.
!>

LDB

!>          LDB est INTEGER
!>          La dimension principale de B.  LDB >= max(1,N).
!>

SDIM

!>          SDIM est INTEGER
!>          Si SORT = 'N', SDIM = 0.
!>          Si SORT = 'S', SDIM = nombre de valeurs propres (après tri)
!>          pour lesquelles SELCTG est vrai.
!>

ALPHA

!>          ALPHA est un tableau COMPLEX, dimension (N)
!>

BETA

!>          BETA est un tableau COMPLEX, dimension (N)
!>          En sortie, ALPHA(j)/BETA(j), j=1,...,N, seront les
!>          valeurs propres généralisées. ALPHA(j), j=1,...,N et BETA(j),
!>          j=1,...,N sont les diagonales de la forme de Schur complexe (A,B)
!>          renvoyée par CGGES3. Les BETA(j) seront réels non négatifs.
!>
!>          Note : les quotients ALPHA(j)/BETA(j) peuvent facilement
!>          déborder ou sous-écouler, et BETA(j) peut même être zéro. Ainsi,
!>          l'utilisateur doit éviter de calculer naïvement le rapport alpha/beta.
!>          Cependant, ALPHA sera toujours inférieur et généralement comparable
!>          à norm(A) en magnitude, et BETA toujours inférieur et généralement
!>          comparable à norm(B).
!>

VSL

!>          VSL est un tableau COMPLEX, dimension (LDVSL,N)
!>          Si JOBVSL = 'V', VSL contiendra les vecteurs de Schur gauches.
!>          Non référencé si JOBVSL = 'N'.
!>

LDVSL

!>          LDVSL est INTEGER
!>          La dimension principale de la matrice VSL. LDVSL >= 1, et
!>          si JOBVSL = 'V', LDVSL >= N.
!>

VSR

!>          VSR est un tableau COMPLEX, dimension (LDVSR,N)
!>          Si JOBVSR = 'V', VSR contiendra les vecteurs de Schur droits.
!>          Non référencé si JOBVSR = 'N'.
!>

LDVSR

!>          LDVSR est INTEGER
!>          La dimension principale de la matrice VSR. LDVSR >= 1, et
!>          si JOBVSR = 'V', LDVSR >= N.
!>

WORK

!>          WORK est un tableau COMPLEX, dimension (MAX(1,LWORK))
!>          En sortie, si INFO = 0, WORK(1) renvoie LWORK optimal.
!>

LWORK

!>          LWORK est INTEGER
!>          La dimension du tableau WORK. LWORK >= MAX(1,2*N).
!>          Pour de bonnes performances, LWORK doit généralement être plus grand.
!>
!>          Si LWORK = -1, alors une requête de mémoire est supposée ; la routine
!>          calcule seulement la taille optimale du tableau WORK, renvoie
!>          cette valeur comme première entrée du tableau WORK, et aucun message
!>          d'erreur lié à LWORK n'est émis par XERBLA.
!>

RWORK

!>          RWORK est un tableau REAL, dimension (8*N)
!>

BWORK

!>          BWORK est un tableau LOGICAL, dimension (N)
!>          Non référencé si SORT = 'N'.
!>

INFO

!>          INFO est INTEGER
!>          = 0:  sortie réussie
!>          < 0:  si INFO = -i, le i-ème argument avait une valeur illégale.
!>          =1,...,N:
!>                L'itération QZ a échoué. (A,B) ne sont pas en Sc
hur !> form, mais ALPHA(j) et BETA(j) devraient être corrects pour !> j=INFO+1,...,N. !> > N: =N+1: autre que l'échec de l'itération QZ dans CLAQZ0 !> =N+2: après réordonnancement, l'arrondi a modifié les valeurs de !> certaines valeurs propres complexes de sorte que les !> valeurs propres dominantes dans la forme de Schur généralisée !> ne satisfassent plus SELCTG=.TRUE. Cela pourrait aussi !> être causé par une mise à l'échelle. !> =N+3: échec du réordonnancement dans CTGSEN. !>
