Constructeur. Retourne un nouvel objet session, ou undef en cas d'échec. Le message d'erreur est accessible via errstr() - méthode de classe. Si appelée sur une session déjà initialisée, elle réinitialisera la session en se basant sur l'objet déjà configuré. Cela n'est utile qu'après un appel à load(

).

Peut accepter jusqu'à trois arguments, $dsn - Data Source Name (nom de source de données), $query||$sid - objet query OU une chaîne représentant l'identifiant de session, et enfin, \%dsn_args, les arguments utilisés par les composants de

$dsn.

Si appelée sans aucun argument, $dsn par défaut est driver:file;serializer:default;id:md5, $query||$sid par défaut est "CGI->new()", et "\%dsn_args" par défaut est undef

.

Si appelée avec un seul argument, il sera traité soit comme un objet $query, ou $sid, en fonction de son type. Si l'argument est une chaîne , new() le traitera comme un identifiant de session et tentera de récupérer la session depuis le stockage de données. Si cela échoue, elle créera un nouvel identifiant de session, qui sera accessible via la méthode id(). Si l'argument est un objet, les méthodes cookie() et param() seront appelées sur cet objet pour récupérer un $sid potentiel et le récupérer depuis le stockage de données. Si cela échoue, new() créera un nouvel identifiant de session, qui sera accessible via la méthode id(). name() définira le nom du paramètre de requête et/ou le nom du cookie à demander, par défaut CGISESSID

.

Si appelée avec deux arguments, le premier sera traité comme $dsn, et le second sera traité comme $query ou $sid ou undef, en fonction de son type. Quelques exemples de cette syntaxe

: 
$s = CGI::Session->new("driver:mysql", undef);
$s = CGI::Session->new("driver:sqlite", $sid);
$s = CGI::Session->new("driver:db_file", $query);
$s = CGI::Session->new("serializer:storable;id:incr", $sid);
# etc..
.

Brièvement, new() retournera un objet session initialisé avec un identifiant valide, alors que load() peut retourner un objet session vide avec un identifiant

indéfini.

Des tests sont fournis (t/new_with_undef.t et t/load_with_undef.t) pour clarifier le résultat d'un appel à new() et load() avec undef, ou avec un objet CGI initialisé avec un CGISESSID indéfini ou

fictif.

Il est fortement conseillé de lancer l'ancienne méthode 'make test TEST_FILES=t/new_with_undef.t TEST_VERBOSE=1' ou la nouvelle 'prove -v t/new_with_undef.t', pour les deux new*.t et load*.t, et d'examiner la

sortie.

Le vidage automatique peut être peu fiable pour les raisons suivantes. Un vidage explicite après les mises à jour clés de la session est

recommandé.
Si le gestionnaire "DBI" sort de portée avant que la variable de
session
Pour les sessions stockées dans une base de données, si le gestionnaire "DBI" est sorti de portée avant que le vidage automatique ne se produise, le vidage automatique
échouera.
Références
circulaires
Si le code appelant contient une référence circulaire, il est possible que votre objet "CGI::Session" ne sera pas détruit avant qu'il ne soit trop tard pour que le vidage automatique fonctionne. Vous pouvez trouver les références circulaires avec un outil comme Devel::Cycle.

En particulier, ces modules so

nt connus pour contenir des
références circulaires
qui conduisent à ce problème :
CGI::Application::Plugin::DebugScreen V
0.06
CGI::Application::Plugin::ErrorPage avant la version
1.20
Gestionnaires de
signaux
Si votre application peut recevoir des signaux, il y a une
probabilité accrue que le signal arrive après que l
a session a été mise à jour mais avant qu'elle ne soit
vidée automatiquement lors de la destruction de l'objet.

Lorsque vous utilisez CGI.pm, vous pouvez utiliser $q->charset('UTF-8'). Cel
a revient à passer 'UTF-8' à la méthode C<header()> de CGI. Alternativement, lorsque vous utilisez CGI::Session
, vous pouvez utiliser $session->header(charset => 'utf-8'), qui sera passé à la méthode C<header()> de l'objet
requête. C'est clairement préférable lorsque l'objet requête pourrait ne pas être de type CGI. Voir L</header()
> pour une discussion plus complète de l'utilisation de la méthode C<header()> en conjonction avec les cookies.
