NOM

CGI::Session::Driver::file - Pilote par défaut de CGI::Session

SYNTAXE

$s = CGI::Session->new();
$s = CGI::Session->new("driver:file", $sid);
$s = CGI::Session->new("driver:file", $sid, {Directory=>'/tmp'});

DESCRIPTION

Lorsque l'objet CGI::Session est créé sans spécifier explicitement le driver, file est supposé. Le pilote file stockera les données de session dans des fichiers plats, où chaque session sera stockée dans un fichier séparé.

Les conventions de nommage des fichiers de session sont définies par la variable globale $CGI::Session::Driver::file::FileName. La valeur par défaut de cette variable est cgisess_%s, où %s sera remplacé par l'identifiant de session correspondant. Si vous souhaitez définir votre propre modèle de FileName, faites-le avant de demander l'objet de session :

use CGI::Session::Driver::file; # Cette ligne est obligatoire.
# Le temps passe...
$CGI::Session::Driver::file::FileName = "%s.dat";
$s = CGI::Session->new();

Pour la compatibilité ascendante avec la version 3.x, vous pouvez également utiliser le nom de variable $CGI::Session::File::FileName, qui remplacera celui ci-dessus.

ARGUMENTS DU PILOTE

Si vous souhaitez spécifier un répertoire de session, utilisez l'option Directory, qui indique l'emplacement du répertoire où les identifiants de session doivent être conservés. Si Directory n'est pas défini, il prend par défaut ce que retourne File::Spec->tmpdir(). Ainsi, les trois lignes de la section SYNOPSIS de ce manuel produisent le même résultat sur une machine UNIX.

Si le Directory spécifié n'existe pas, toute la hiérarchie de répertoires nécessaire sera créée.

Par défaut, les sessions sont créées avec un umask de 0660. Si vous souhaitez modifier l'umask d'une session, passez une option UMask avec une représentation octale de l'umask que vous souhaitez pour ladite session.

NOTES

Si votre système d'exploitation ne prend pas en charge flock, vous devriez comprendre les risques de travailler sans verrouillage des fichiers de session. Étant donné que les sessions ont tendance à être utilisées dans des environnements où des conditions de concurrence peuvent survenir en raison de l'accès concurrent aux fichiers par différents processus, le verrouillage est généralement considéré comme une chose bonne et très nécessaire. Si vous souhaitez tout de même utiliser ce pilote mais que vous ne voulez pas de flock, définissez $CGI::Session::Driver::file::NoFlock sur 1 ou passez "NoFlock => 1" et ce pilote fonctionnera sans verrous.
