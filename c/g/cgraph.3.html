DESCRIPTION

Libcgraph prend en charge la programmation de graphes en maintenant des graphes en mémoire et en lisant et écrivant des fichiers de graphes. Les graphes sont composés de nœuds, d'arêtes et de sous-graphes imbriqués. Ces objets de graphe peuvent être attribués avec des paires nom-valeur de chaînes et des enregistrements définis par le programmeur (voir Attributs).

Tous les symboles globaux de Libcgraph ont le préfixe ag (casse variable). Dans ce qui suit, si une fonction a un paramètre int createflag et que l'objet n'existe pas, la fonction créera l'objet spécifié si createflag est non nul ; sinon, elle renverra NULL.

GRAPHE ET SOUS-GRAPHES

Un graphe « principal » ou « racine » définit un espace de noms pour une collection d'objets de graphe (sous-graphes, nœuds, arêtes) et leurs attributs. Les objets peuvent être nommés par des chaînes uniques ou par des identifiants entiers.

agopen crée un nouveau graphe avec le nom et le type donnés. (Les types de graphes sont Agdirected, Agundirected, Agstrictdirected, et Agstrictundirected. Un graphe strict ne peut pas avoir d'arêtes multiples ni de boucles.) Le dernier argument pointe vers une structure de discipline qui peut être utilisée pour adapter l'E/S et l'allocation des ID. Typiquement, une valeur NULL sera utilisée pour indiquer la discipline par défaut AgDefaultDisc. agclose supprime un graphe, libérant le stockage associé. agread, agwrite, et agconcat effectuent des opérations d'E/S de fichier en utilisant le langage de fichier de graphe décrit ci-dessous. agread construit un nouveau graphe tandis que agconcat fusionne le contenu du fichier avec un graphe préexistant. Bien que les méthodes d'E/S puissent être surchargées, par défaut l'argument channel est un pointeur FILE stdio. Dans ce cas, si l'un des flux est orienté large, le comportement est indéfini. agmemread tente de lire un graphe depuis la chaîne d'entrée.

Les fonctions agisdirected, agisundirected, agisstrict, et agissimple peuvent être utilisées pour interroger si un graphe est dirigé, non dirigé, strict (au plus une arête avec une queue et une tête données), ou simple (strict sans boucles), respectivement,

agsubg trouve ou crée un sous-graphe par nom. agidsubg permet à un programmeur de spécifier le sous-graphe par un identifiant entier unique. Un nouveau sous-graphe est initialement vide et est du même type que son parent. Des arbres de sous-graphes imbriqués peuvent être créés. Le nom d'un sous-graphe n'est interprété que relativement à son parent. Un programme peut parcourir les sous-graphes sous un graphe donné en utilisant agfstsubg et agnxtsubg. Un sous-graphe est supprimé avec agdelsubg (ou agclose). La fonction agparent renvoie le graphe parent immédiat d'un sous-graphe, ou lui-même si le graphe est déjà un graphe racine.

Par défaut, les nœuds sont stockés dans des ensembles ordonnés pour un accès aléatoire efficace à l'insertion, la recherche et la suppression de nœuds. Les arêtes d'un nœud sont également stockées dans des ensembles ordonnés. Les ensembles sont maintenus en interne sous forme de dictionnaires d'arbres splay en utilisant la bibliothèque cdt de Phong Vo.

agnnodes, agnedges, et agnsubg renvoient les tailles des ensembles de nœuds, d'arêtes et de sous-graphes d'un graphe. La fonction agdegree renvoie la taille de l'ensemble des arêtes d'un nœud, et prend des drapeaux pour sélectionner les arêtes entrantes, sortantes, ou les deux. La fonction agcountuniqedges renvoie la taille de l'ensemble des arêtes d'un nœud, et prend des drapeaux pour sélectionner les arêtes entrantes, sortantes, ou les deux. Contrairement à agdegree, chaque boucle n'est comptée qu'une seule fois.

NŒUDS

Un nœud estcréée en donnant un nom de chaîne unique ou un ID entier défini par le programmeur, et est représentée par un objet interne unique. (L'égalité des nœuds peut être vérifiée par comparaison de pointeurs.)

agnode recherche dans un graphe ou un sous-graphe un nœud portant le nom donné et le retourne s'il est trouvé. agidnode permet à un programmeur de spécifier le nœud par un ID entier unique. agsubnode effectue une opération similaire sur un nœud existant et un sous-graphe.

agfstnode et agnxtnode parcourent les listes de nœuds. agprvnode et aglstnode sont symétriques mais parcourent la liste à l'envers. La séquence par défaut est l'ordre de création (horodatage de l'objet). agdelnode supprime un nœud d'un graphe ou d'un sous-graphe.

ARÊTES

Une arête abstraite a deux nœuds d'extrémité appelés queue et tête, où toutes les arêtes sortantes d'un même nœud l'ont comme valeur de queue et de même toutes les arêtes entrantes l'ont comme tête. Dans un graphe non orienté, la tête et la queue sont interchangeables. Si un graphe a des multi-arêtes entre la même paire de nœuds, le nom de chaîne de l'arête sert de clé secondaire.

agedge recherche dans un graphe ou un sous-graphe une arête entre les extrémités données (avec un nom de sélecteur de multi-arête facultatif) et la retourne si elle est trouvée ou créée. Notez que, dans les graphes non orientés, une recherche essaie les deux ordonnancements des nœuds queue et tête. Si le nom est NULL, alors une valeur interne anonyme est générée. agidedge permet à un programmeur de créer une arête en donnant son ID entier unique. agsubedge effectue une opération similaire sur une arête existante et un sous-graphe. agfstin, agnxtin, agfstout, et agnxtout visitent les listes d'arêtes entrantes et sortantes, et ne s'appliquent ordinairement que dans les graphes orientés. agfstedge et agnxtedge visitent toutes les arêtes incidentes à un nœud. agtail et aghead obtiennent l'extrémité d'une arête. agdeledge supprime une arête d'un graphe ou d'un sous-graphe.

Notez qu'une arête abstraite a deux représentations concrètes distinctes : comme arête entrante et comme arête sortante. En particulier, le pointeur comme arête sortante est différent du pointeur comme arête entrante. La fonction ageqedge canonicalise les pointeurs avant de faire une comparaison et peut donc être utilisée pour tester l'égalité des arêtes. Le sens d'une arête peut être inversé en utilisant agopp.

ATTRIBUTS INTERNES

Les valeurs définies par le programmeur peuvent être attachées dynamiquement aux graphes, sous-graphes, nœuds et arêtes. Ces valeurs sont soit des données de chaîne de caractères (pour les E/S), soit des enregistrements binaires non interprétés (pour implémenter efficacement des algorithmes).

ATTRIBUTS DE CHAÎNE

Les attributs de chaîne sont gérés automatiquement lors de la lecture et de l'écriture des fichiers de graphe. Un attribut de chaîne est identifié par un nom et par une entrée de table de symboles interne (Agsym_t) créée par Libcgraph. Les attributs des nœuds, des arêtes et des graphes (avec leurs sous-graphes) ont des espaces de noms séparés. Le contenu d'un Agsym_t a un char* name pour le nom de l'attribut, un champ char* defval pour la valeur par défaut de l'attribut, et un champ int id contenant l'index de la valeur spécifique de l'attribut pour un objet dans le tableau de valeurs d'attributs de l'objet.

agattr crée ou recherche des attributs. kind peut être AGRAPH, AGNODE, ou AGEDGE. Si value est (char*)0), la demande est de rechercher un attribut existant du type et du nom donnés. Sinon, si l'attribut existe déjà, sa valeur par défaut pour la création de nouveaux objets est définie à la valeur donnée ; s'il n'existe pas, un nouvel attribut est créé avec la valeur par défaut donnée, et la valeur par défaut est appliquée à tous les objets préexistants du type donné. Si g est NULL, la valeur par défaut est définie pour tous les graphes créés par la suite. agattrsym est une fonction auxiliaire qui recherche un attribut pour un objet de graphe donné en argument. agnxtattr permet de parcourir la liste des attributs d'un type donné. Si NULL est passé en argument, elle obtient le premier attribut ; sinon elle retourne le suivant en succession ou retourne NULL à la fin de la liste. agget et agset permettent de récupérer et de mettre à jour un attribut de chaîne pour un objet en prenant le nom de l'attribut comme argument. agxget et agxset font cela mais avec une entrée de table de symboles d'attribut comme argument (pour éviter le coût de la recherche de chaîne). Notez que agset échouera sauf si l'attribut est d'abord défini en utilisant agattr. agsafeset est une fonction de commodité qui s'assure que l'attribut donné est déclaré avant de le définir localement sur un objet.

Il est parfois pratique de copier tous les attributs d'un objet vers un autre. Cela peut être fait en utilisant agcopyattr. Cela échoue et retourne non-zéro si les objets arguments sont de types différents, ou si tous les attributs de l'objet source n'ont pas été déclarés pour l'objet cible.

CHAÎNES

Libcgraph effectue sa propre gestion du stockage des chaînes sous forme de chaînes à comptage de références. L'appelant n'a pas besoin d'allouer dynamiquement du stockage.

agstrdup retourne un pointeur vers une copie à comptage de références de la chaîne argument, en en créant une si nécessaire. agstrbind retourne un pointeur vers une chaîne à comptage de références si elle existe, ou NULL sinon. Tous les usages des chaînes cgraph doivent être libérés en utilisant agstrfree afin de maintenir correctement le comptage de références.

L'analyseur cgraph gère les chaînes de type HTML. Celles-ci devraient être indiscernables des autres chaînes pour la plupart des usages. Pour créer une chaîne de type HTML, utilisez agstrdup_html. La fonction aghtmlstr peut être utilisée pour interroger si une chaîne est une chaîne ordinaire ou une chaîne de type HTML.

agstrcanon retourne un pointeur vers une version de la chaîne d'entrée canonicalisée pour la sortie afin d'être ré-analysée ultérieurement. Cela inclut le guillemetage des caractères spéciaux et des mots-clés. L'application passe un tampon comme second argument. Notez que le tampon peut ne pas être utilisé ; si la chaîne d'entrée est déjà sous forme canonique, la fonction retournera simplement un pointeur vers elle. La chaîne d'entrée doit avoir été créée en utilisant agstrdup ou agstrdup_html.

ENREGISTREMENTS

Des enregistrements non interprétés peuvent être attachés aux graphes, sous-graphes, nœuds et arêtes pour des opérations efficaces sur des valeurs telles que des marques, des poids, des compteurs et des pointeurs nécessaires aux algorithmes. Les programmeurs d'applications définissent les champs de ces enregistrements, mais ils doivent être déclarés avec un en-tête commun comme montré ci-dessous.

typedef struct {
    Agrec_t        header;
    /* les champs définis par le programmeur suivent */
} user_data_t;

Les enregistrements sont créés et gérés par Libcgraph. Un programmeur doit les attacher explicitement aux objets d'un graphe, soit aux objets individuels un à la fois via agbindrec, soit à tous les objets de la même classe dans un graphe via aginit. (Notez que pour les graphes, aginit est appliqué récursivement au graphe et à ses sous-graphes si rec_size est négatif (de la valeur réelle de rec_size).) L'argument name d'un enregistrement distingue les différents types d'enregistrements, et est défini par le programmeur (Libcgraph réserve le préfixe _ag). Si size est 0, l'appel à agbindrec est simplement une recherche. La fonction aggetrec peut aussi être utilisée pour la recherche. agdelrec supprime un enregistrement nommé d'un objet. agclean fait de même pour tous les objets de la même classe dans un graphe entier.

En interne, les enregistrements sont maintenus dans des listes circulaires attachées aux objets de graphe. Pour permettre de référencer des données dépendantes de l'application sans appels de fonction ni recherche, Libcgraph permet de définir et de verrouiller le pointeur de liste d'un graphe, d'un nœud ou d'une arête sur un enregistrement particulier. Ce pointeur peut être obtenu avec la macro AGDATA(obj). Un cast, généralement dans une macro ou une fonction en ligne, est généralement appliqué pour convertir le pointeur de liste en un type approprié défini par le programmeur.

Pour contrôler la définition de ce pointeur, l'indicateur move_to_front peut être TRUE ou FALSE. Si move_to_front est TRUE, l'enregistrement sera verrouillé en tête de liste, afin qu'il puisse être accédé directement par AGDATA(obj). Le verrou peut être ensuite libéré ou réinitialisé par un appel à aggetrec.

DISCIPLINES

(Cette section n'est pas destinée aux utilisateurs occasionnels.) Les disciplines définies par le programmeur personnalisent certaines ressources - espace de noms d'ID et E/S - nécessaires à Libcgraph. Une structure de discipline (ou NULL) est passée au moment de la création du graphe.

struct Agdisc_s {            /* la discipline de l'utilisateur */
    Agiddisc_t            *id;
    Agiodisc_t            *io;
} ;

Une discipline par défaut est fournie lorsque NULL est donné pour l'un de ces champs.

DISCIPLINE D'ID

Une discipline d'allocation d'ID permet à un client de contrôler l'attribution des ID (valeurs entières non interprétées) aux objets, et éventuellement comment ils sont mappés vers et depuis des chaînes.

struct Agiddisc_s {             /* allocateur d'ID d'objet */
    void *(*open) (Agraph_t * g, Agdisc_t*);       /* associé à un graphe */
    long (*map) (void *state, int objtype, char *str, unsigned long *id, int createflag);
    long (*alloc) (void *state, int objtype, unsigned long id);
    void (*free) (void *state, int objtype, unsigned long id);
    char *(*print) (void *state, int objtype, unsigned long id);
    void (*close) (void *state);
};

open permet à la discipline d'ID d'initialiser toutes les structures de données qu'elle maintient par graphe individuel. Sa valeur de retour est ensuite passée comme premier argument (void *state) à tous les appels ultérieurs du gestionnaire d'ID.

alloc informe le gestionnaire d'ID que Libcgraph tente de créer un objet avec un ID spécifique qui a été donné par un client. Le gestionnaire d'ID devrait retourner TRUE (non-nul) si l'ID peut être alloué, ou FALSE (ce qui annule l'opération).

free est appelé pour informer le gestionnaire d'ID que l'objet étiqueté avec l'ID donné est sur le point de cesser d'exister.

map est appelé pour créer ou rechercher des ID par nom de chaîne (si supporté par le gestionnaire d'ID). Retourner TRUE (non-nul) dans tous les cas signifie que la demande a réussi (avec un ID valide stocké à travers result. Il y a quatre cas :

•
name != NULL et createflag == 1: Cela demande le mappage d'une chaîne (par exemple un nom dans un fichier de graphe) vers un nouvel ID. Si le gestionnaire d'ID peut s'y conformer, alors il stocke le résultat et retourne TRUE. Il est alors aussi responsable de pouvoir print l'ID à nouveau comme une chaîne. Sinon le gestionnaire d'ID peut retourner FALSE mais il doit implémenter ce qui suit (au moins pour que la lecture et l'écriture des fichiers de graphe fonctionnent):
•
name == NULL et createflag == 1: Le gestionnaire d'ID crée un nouvel ID unique de son propre choix. Il peut retourner FALSE s'il ne supporte pas les objets anonymes, mais c'est fortement déconseillé (pour supporter les « noms locaux » dans les fichiers de graphes.)
•
name != NULL et createflag == 0: Ceci est une sonde d'espace de noms. Si le nom a été précédemment associé à un ID alloué par le gestionnaire d'ID, alors le gestionnaire doit retourner cet ID. Sinon, le gestionnaire d'ID peut soit retourner FALSE, soit stocker un ID non alloué dans result. (C'est pratique, par exemple, si les noms sont connus pour être des chaînes de chiffres directement converties en valeurs entières.)
•
name == NULL et createflag == 0: interdit.

print est autorisé à retourner un pointeur vers un tampon statique ; un appelant doit copier sa valeur si elle est nécessaire au-delà des appels suivants. NULL doit être retourné par les gestionnaires d'ID qui ne font pas de correspondance de noms.

Les appels map et alloc ne passent pas de pointeur vers l'objet nouvellement alloué. Si un client a besoin d'installer des pointeurs d'objets dans une table de handles, il peut les obtenir via les rappels de nouvel objet.

DISCIPLINE E/S

La discipline E/S fournit une abstraction pour la lecture et l'écriture de graphes.

struct Agiodisc_s {
    int        (*fread)(void *chan, char *buf, int bufsize);
    int        (*putstr)(void *chan, char *str);
    int        (*flush)(void *chan);    /* sync */
} ;

Normalement, la structure FILE et ses fonctions associées sont utilisées pour les E/S. Parfois, cependant, une application peut avoir besoin d'utiliser un type de source de caractères totalement différent. L'état ou les informations de flux associés sont fournis par l'argument chan de agread ou agwrite. Les fonctions de discipline fread et putstr fournissent les fonctions correspondantes pour la lecture et l'écriture.

RAPPELS

Un Agcbdisc_t définit des rappels à invoquer par Libcgraph lors de l'initialisation, de la modification ou de la finalisation d'objets de graphe. Les disciplines sont conservées sur une pile. Libcgraph appelle automatiquement les méthodes sur la pile, de haut en bas. Les rappels sont installés avec agpushdisc, désinstallés avec agpopdisc, et peuvent être maintenus en attente ou libérés via agcallbacks.

OBJETS GÉNÉRIQUES

agroot prend n'importe quel objet de graphe (graphe, sous-graphe, nœud, arête) et retourne le graphe racine dans lequel il se trouve. agraphof fait de même, sauf qu'il est la fonction identité sur les graphes et les sous-graphes. Notez qu'il n'existe pas de fonction pour retourner le sous-graphe le plus petit contenant un objet, en partie parce que ce n'est pas bien défini car les nœuds et les arêtes peuvent être dans des sous-graphes incomparables.

agcontains(g,obj) retourne non-zéro si obj est un membre du (sous-)graphe g. agdelete(g,obj) est équivalent à agclose, agdelnode, et agdeledge pour obj étant respectivement un graphe, un nœud ou une arête. Il retourne -1 si obj n'appartient pas à g.

AGDATA, AGID, et AGTYPE sont des macros retournant les champs spécifiés de l'objet argument. La première est décrite dans la section RECORDS ci-dessus. La seconde retourne l'ID entier unique associé à l'objet. La dernière retourne AGRAPH, AGNODE, et AGEDGE selon le type de l'objet.

agnameof retourne un descripteur de chaîne pour l'objet. Il retourne le nom du nœud ou du graphe, et la clé d'une arête. agobjkind est un synonyme pour AGTYPE.

RAPPORT D'ERREURS

La bibliothèque fournit une variété de mécanismes pour contrôler le rapport des erreurs et des avertissements. Actuellement, il y a fondamentalement deux types de messages : les avertissements et les erreurs. Un message n'est écrit que si son type a une priorité plus élevée qu'un minimum contrôlé par le programmeur, qui est AGWARN par défaut. Le programmeur peut définir cette valeur en utilisant agseterr, qui retourne la valeur précédente. Appeler agseterr(AGMAX) désactive l'écriture des messages.

La fonction agerr est le point d'entrée principal pour signaler une anomalie. Le premier argument indique le type de message. Habituellement, le premier argument est AGWARN ou AGERR pour indiquer respectivement les avertissements et les erreurs. Parfois, des informations de contexte supplémentaires ne sont disponibles que dans les fonctions appelant la fonction où l'erreur est réellement détectée. Dans ce cas, la fonction appelante peut indiquer qu'elle continue l'erreur en cours en utilisant AGPREV comme premier argument. Les arguments restants de agerr sont les mêmes que les arguments de printf.

Les fonctions agwarningf et agerrorf sont des raccourcis pour agerr(AGWARN,...) et agerr(AGERR,...), respectivement.

Certaines applications souhaitent contrôler directement l'écriture des messages. Une telle application peut utiliser la fonction agseterrf pour enregistrer la fonction que la bibliothèque doit appeler pour écrire réellement le message. La fonction d'erreur précédente est retournée. Par défaut, le message est écrit vers stderr.

Les erreurs non écrites sont stockées dans un fichier journal. La dernière erreur enregistrée peut être récupérée en appelant aglasterr. À moins que l'impression des messages d'erreur ait été complètement désactivée par un appel à agseterr(AGMAX), la sortie d'erreur standard ne doit pas être orientée large, même si une fonction d'impression d'erreur fournie par l'utilisateur est utilisée.

La fonction agerrors retourne non-zéro si des erreurs ont été signalées.

PROGRAMME D'EXEMPLE

#include <cgraph.h>
#include <stdbool.h>
#include <stddef.h>
#include <stdio.h>
typedef struct {
  Agrec_t hdr;
  int x;
  int y;
  int z;
} mydata;
int main(int argc, char **argv) {
  Agraph_t *g;
    mydata      *p;
  if ((g = agread(stdin, NULL))) {
    int cnt = 0;
    Agsym_t *attr = NULL;
    while ((attr = agnxtattr(g, AGNODE, attr))) {
      cnt++;
    }
    printf("The graph %s has %d attributes\n", agnameof(g), cnt);
    // make the graph have a node color attribute, default is blue
    attr = agattr_text(g, AGNODE, "color", "blue");
    // create a new graph of the same kind as g
    Agraph_t *h = agopen("tmp", g->desc, NULL);
    // this is a way of counting all the edges of the graph
    cnt = 0;
    for (Agnode_t *v = agfstnode(g); v != NULL; v = agnxtnode(g, v)) {
      for (Agedge_t *e = agfstout(g, v); e != NULL; e = agnxtout(g, e)) {
        cnt++;
      }
    }
    // attach records to edges
    for (Agnode_t *v = agfstnode(g); v != NULL; v = agnxtnode(g, v)) {
      for (Agedge_t *e = agfstout(g, v); e != NULL; e = agnxtout(g, e)) {
        p = (mydata *)agbindrec(e, "mydata", sizeof(mydata), true);
        p->x = 27; // meaningless data access example
        ((mydata *)(AGDATA(e)))->y = 999; // another example
      }
    }
  }
  return 0;
}

BOGUES

Il est difficile de changer les points d'extrémité des arêtes, de supprimer des attributs de chaîne ou de modifier les clés d'arêtes. Le contournement consiste à créer un nouvel objet et à copier le contenu d'un ancien (mais le nouvel objet a évidemment un ID, une adresse interne et un horodatage de création d'objet différents).

L'API manque de fonctions pratiques pour substituer un ordonnancement des nœuds et des arêtes défini par le programmeur, mais en principe cela peut être supporté.

La bibliothèque n'est pas sûre pour les threads.
