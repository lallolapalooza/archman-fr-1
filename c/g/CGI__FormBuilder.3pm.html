use CGI::FormBuilder;
# Supposez que nous avons effectué une requête DBI pour obtenir les valeurs existantes
my $dbval = $sth->fetchrow_hashref;
# Créons d'abord notre formulaire
my $form = CGI::FormBuilder->new(
                name     => 'acctinfo',
                method   => 'post',
                stylesheet => '/chemin/vers/style.css',
                values   => $dbval,   # valeurs par défaut
           );
# Créons maintenant les champs du formulaire, dans l'ordre
# FormBuilder déterminera automatiquement le type pour vous
$form->field(name => 'fname', label => 'Prénom');
$form->field(name => 'lname', label => 'Nom');
# Configurer le champ de genre avec des options
$form->field(name => 'gender',
             options => [qw(Male Female)] );
# Inclure la validation pour le champ email
$form->field(name => 'email',
             size => 60,
             validate => 'EMAIL',
             required => 1);
# Et le champ téléphone (facultatif)
$form->field(name => 'phone',
             size => 10,
             validate => '/^1?-?\d{3}-?\d{3}-?\d{4}$/',
             comment  => '<i>facultatif</i>');
# Vérifier si le formulaire a été soumis et est valide
if ($form->submitted && $form->validate) {
    # Obtenir les champs du formulaire sous forme de référence de hachage
    my $field = $form->fields;
    # Faire quelque chose pour mettre à jour vos données (vous devrez écrire cela)
    do_data_update($field->{lname}, $field->{fname},
                   $field->{email}, $field->{phone},
                   $field->{gender});
    # Afficher l'écran de confirmation
    print $form->confirm(header => 1);
} else {
    # Afficher le formulaire
    print $form->render(header => 1);
}

Aperç

Je déteste générer et traiter des formulaires. Je déteste ça, je déteste ça, je déteste ça, je déteste ça. Mes formulaires finissent presque toujours par avoir le même aspect, et presque toujours par faire la même chose. Malheureusement, il n'y a pas vraiment eu d'outils qui simplifient le processus. Beaucoup de modules se contentent de substituer du Perl à du code HTML

: 
# La méthode manuelle
print qq(<input name="email" type="text" size="20">);
# La méthode avec un module

;

Le problème est que cela ne vous fait vraiment gagner rien - vous avez toujours autant de code. Des modules comme "CGI.pm" sont excellents pour décoder les paramètres, mais pas pour générer et traiter des formulaires

entiers.

Le but de CGI::FormBuilder (FormBuilder) est de fournir un moyen facile de générer et de traiter des applications CGI entières basées sur des formulaires. Ses caractéristiques principales sont

:
Abstraction des
champs
Considérer les champs comme des entités (et non simplement des paramètres), où la représentation HTML, les valeurs CGI, la validation, etc. sont des propriétés de chaque
champ.
Magie
DWIM
Beaucoup d'"intelligence" intégrée (comme la détermination automatique du type de champ), vous offrant un ratio d'environ 4:1 entre le code généré et ce que vous devez
écrire.
Validation
intégrée
Validation par expressions régulières complète pour les champs, incluant même la génération de code
JavaScript.
Prise en charge des
gabarits
Prise en charge extensible pour des moteurs de gabarits externes, tels que "HTML::Template", "Text::Template", "Template Toolkit", et "CGI::Fast
Templ
ate".

De plus, le HTML généré n

ativement est du XHTML 1
.0 Transitional valide.

# Créer le formulaire

   # Options importantes
   fields     => \@array | \%hash,   # définir les champs du formulaire
   header     => 0 | 1,              # envoyer le Content-type ?
   method     => 'post' | 'get',     # par défaut est get
   name       => $string,            # espace de noms (recommandé)
   reset      => 0 | 1 | $str,            # bouton "Réinitialiser"
   submit     => 0 | 1 | $str | \@array,  # bouton(s) "Soumettre"
   text       => $text,              # affiché au-dessus du formulaire
   title      => $title,             # affiché en haut
   required   => \@array | 'ALL' | 'NONE',  # champs obligatoires ?
   values     => \%hash | \@array,   # depuis DBI, session, etc.
   validate   => \%hash,             # validation automatique des champs
   # Options moins utilisées
   action     => $script,            # pas nécessaire (boucle sur lui-même)
   cookies    => 0 | 1,              # utiliser les cookies pour l'identifiant de session ?
   debug      => 0 | 1 | 2 | 3,      # écrire dans error_log ?
   fieldsubs  => 0 | 1,              # autoriser $form->$field()
   javascript => 0 | 1 | 'auto',     # générer le code JS validate() ?
   keepextras => 0 | 1 | \@array,    # conserver les paramètres non-champs ?
   params     => $object,            # au lieu de CGI.pm
   sticky     => 0 | 1,              # garder les valeurs CGI "collantes" ?
   messages   => $file | \%hash | $locale | 'auto',
   template   => $file | \%hash | $object,   # HTML personnalisé
   # Options de formatage HTML et JavaScript
   body       => \%attr,             # {background => 'black'}
   disabled   => 0 | 1,              # afficher en gris ?
   fieldsets  => \@arrayref          # diviser le formulaire en <fieldsets>
   font       => $font | \%attr,     # 'arial,helvetica'
   jsfunc     => $jscode,            # code JS dans validate()
   jshead     => $jscode,            # code JS dans <head>
   linebreaks => 0 | 1,              # mettre des sauts de ligne dans le formulaire ?
   selectnum  => $threshold,         # pour la génération automatique de type
   smartness  => 0 | 1 | 2,          # ajuster l'"intelligence"
   static     => 0 | 1 | 2,          # afficher un formulaire non modifiable ?
   styleclass => $string,            # classe de style à utiliser ("fb")
   stylesheet => 0 | 1 | $path,      # activer style class=
   table      => 0 | 1 | \%attr,     # envelopper le formulaire dans une <table> ?
   td         => \%attr,             # options de <td>
   tr         => \%attr,             # options de <tr>
   # Ces options sont obsolètes, vous devriez utiliser field() à la place
   fieldtype  => 'type',
   fieldattr  => \%attr,
   labels     => \%hash,
   options    => \%hash,
   sortopts   => 'NAME' | 'NUM' | 1 | \&sub,
   # Fichier source externe (voir CGI::FormBuilder::Source::File)
   source     => $file,
);
# Ajuster les champs individuellement
$form->field(
   # Options importantes
   name       => $name,          # nom du champ (requis)
   label      => $string,        # affiché devant <input>
   type       => $type,          # normalement déterminé automatiquement
   multiple   => 0 | 1,          # autoriser plusieurs valeurs ?
   options    => \@options | \%options,   # radio/select/checkbox
   value      => $value | \@values,       # valeur par défaut
   # Options moins utilisées
   fieldset   => $string,        # mettre le champ dans un <fieldset>
   force      => 0 | 1,          # remplacer la valeur CGI ?
   growable   => 0 | 1 | $limit, # agrandir les entrées texte/fichier ?
   jsclick    => $jscode,        # au lieu de onclick
   jsmessage  => $string,        # en cas d'échec de la validation JS
   message    => $string,        # autre échec de validation
   other      => 0 | 1,          # créer une entrée "Autre :" ?
   required   => 0 | 1,          # doit-on remplir le champ ?
   validate   => '/regex/',      # valider la saisie de l'utilisateur
   # Options de formatage HTML
   cleanopts  => 0 | 1,          # échapper les options en HTML ?
   columns    => 0 | $width,     # envelopper les options du champ à $width
   comment    => $string,        # affiché après le champ
   disabled   => 0 | 1,          # afficher en gris ?
   labels     => \%hash,         # obsolète (utiliser "options")
   linebreaks => 0 | 1,          # insérer des sauts dans les options ?
   nameopts   => 0 | 1,          # nommer automatiquement les options ?
   sortopts   => 'NAME' | 'NUM' | 1 | \&sub,   # trier les options ?
   # Changer la taille, la longueur maximale ou tout autre attribut HTML
   $htmlattr  => $htmlval,
);
# Vérifier la soumission
if ($form->submitted && $form->validate) {
    # Obtenir une valeur unique
    my $value = $form->field('name');
    # Obtenir la liste des champs
    my @field = $form->field;
    # Obtenir une référence de hachage de paires clé/valeurs
    my $field = $form->field;
    my $value = $field->{name};
}
# Afficher le formulaire
print $form->render(any_opt_from_new => $some_value)
;

QUESTIONS FRÉQUENTES

(FAQ)

Il y a quelques questions et pièges subtils qui semblent déranger les gens régulièrement. Voici quelques

indications.

Je suis confus. Pourquoi ne fonctionne-t-il pas comme CGI.pm

?

Si vous êtes habitué à "CGI.pm", vous devez faire un petit changement de mentalité lorsque vous travaillez avec ce

module.

FormBuilder est conçu pour traiter les champs comme des entités abstraites. C'est-à-dire que vous ne créez pas une "case à cocher" ou un "groupe de boutons radio" en soi. À la place, vous créez un champ pour les données que vous voulez collecter. La représentation HTML n'est qu'une propriété de ce

champ.

Donc, si vous voulez une case à cocher à option unique, dites simplement quelque chose comme ceci

: 
$form->field(name    => 'join_mailing_list',
             options => ['Yes'])
;

Si vous voulez qu'elle soit cochée par défaut, vous ajoutez l'argument "value

" : 
$form->field(name    => 'join_mailing_list',
             options => ['Yes'],
             value   => 'Yes')
;

Vous voyez, vous créez un champ qui a une option possible : "Yes". Ensuite, vous dites que sa valeur actuelle est, en fait, "Yes". Cela aura pour résultat que FormBuilder crée un champ à option unique (qui est une case à cocher par défaut) et sélectionne la valeur demandée (ce qui signifie que la case sera cochée)

.

Si vous voulez plusieurs valeurs, alors tout ce que vous avez à faire est de spécifier plusieurs options

: 
$form->field(name    => 'join_mailing_list',
             options => ['Yes', 'No'],
             value   => 'Yes')
;

Maintenant vous obtiendrez un groupe de boutons radio, et "Yes" sera sélectionné pour vous ! En considérant les champs comme des entités de données (au lieu de balises HTML) vous obtenez beaucoup plus de flexibilité et moins de maintenance de code. Si vous voulez pouvoir accepter plusieurs valeurs, utilisez simplement l'argument "multipl

e" : 
$form->field(name     => 'favorite_colors',
             options  => [qw(red green blue)],
             multiple => 1)
;

Dans tous ces exemples, pour récupérer les données vous utilisez simplement la méthode field()

: 
my @colors = $form->field('favorite_colors')
;

Et le reste es

t pris en cha

Comment faire un formulaire multi-écrans/multi-modes

?

C'est facilement faisable, mais vous devez vous souvenir de quelques choses. Surtout, que FormBuilder ne connaît que ces champs que vous lui avez indiqués. Donc, supposons que vous allez utiliser un paramètre spécial appelé "mode" pour contrôler le mode de votre application afin de pouvoir l'appeler ainsi

myapp.cgi?mode=edit&...

Et ainsi de suite. Vous devez faire deux choses. D'abord, vous avez besoin de l'option "keepextr

as" : 
my $form = CGI::FormBuilder->new(..., keepextras => 1)
;

Cela maintiendra le champ "mode" comme champ caché à travers les requêtes automatiquement. Ensuite, vous devez réaliser que puisque le "mode" n'est pas un champ défini, vous devez l'obtenir via la méthode cgi_param()

my $mode = $form->cgi_param('mode')
;

Cela vous permettra de construire facilement une grande application multi-écrans, même en l'intégrant avec des modules comme "CGI::Application" si vous le

souhaitez.

Vous pouvez aussi faire cela en définissant simplement "mode" comme un champ dans votre déclaration "fields". La raison pour laquelle c'est déconseillé est que lorsque vous itérez sur vos champs vous obtiendrez "mode", que vous ne voulez probablement pas (p

Pourquoi CGI::FormBuilder ne fonctionne-t-il pas avec les requêtes post

Il le fera, mais il y a de fortes chances que vous fassiez probablement quelque chose comme ceci

use CGI qw(:standard);

                    method => 'post',
                    fields => [qw(...)],

.

Heureusement, il y a une solution facile. D'abord, vous devez modifier votre code pour utiliser la forme OO de "CGI.pm". Ensuite, indiquez simplement l'objet "CGI" que vous créez à l'option "params" de FormBuild

use CGI;

                    method => 'post',
                    fields => [qw(...)],

                    method => 'post',
                    fields => [qw(...)],

RÉFÉRENCE

S

Cela n'a vraiment pas sa place ici, mais malheureusement beaucoup de gens sont déconcertés par les références en Perl. Ne l'êtes pas - ce n'est pas si compliqué. Quand vous prenez une référence, vous transformez essentiellement quelque chose en une valeur scalaire. En quelque sorte. Vous devez faire cela si vous voulez passer des tableaux intacts à des fonctions en Perl

5.

Une référence est prise en faisant précéder la variable d'une barre oblique inverse (\). Dans nos exemples ci-dessus, vous avez vu quelque chose de similaire à ceci

: 
my @fields = ('name', 'email');   # same as = qw(name email)
my $form = CGI::FormBuilder->new(fields => \@fields)
;

Ici, "\@fields" est une référence. Plus précisément, c'est une référence de tableau, ou "arrayref" pour faire

court.

De même, nous pouvons faire la même chose avec les hashs

: 
my %validate = (
    name  => 'NAME';
    email => 'EMAIL',
);
my $form = CGI::FormBuilder->new( ... validate => \%validate)
;

Ici, "\%validate" est une référence de hash, ou

"hashref".

Fondamentalement, si vous ne comprenez pas les références et que vous avez du mal à les appréhender, vous pouvez essayer cette règle simple : Chaque fois que vous passez un tableau ou un hash à une fonction, vous devez le faire précéder d'une barre oblique inverse. C'est généralement le cas pour les modules

CPAN.

Enfin, il existe deux autres types de références : les tableaux anonymes et les hashs anonymes. Ceux-ci sont créés avec "[]" et "{}", respectivement. Ainsi, pour nos besoins, il n'y a pas de réelle différence entre ce code

: 
my @fields = qw(name email);
my %validate = (name => 'NAME', email => 'EMAIL');
my $form = CGI::FormBuilder->new(
                fields   => \@fields,
                validate => \%validate
           )
;

Et ce code

: 
my $form = CGI::FormBuilder->new(
                fields   => [ qw(name email) ],
                validate => { name => 'NAME', email => 'EMAIL' }
           )
;

Sauf que ce dernier ne nécessite pas que nous créions d'abord @fields et %validate

vari
ables.
