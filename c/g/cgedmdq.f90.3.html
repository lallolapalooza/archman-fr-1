CGEDMDQ calcule la Décomposition de Mode Dynamique (DMD) pour une paire de matrices d'instantanés de

données.

But

: 
!>    CGEDMDQ calcule la Décomposition de Mode Dynamique (DMD) pour
!>    une paire de matrices d'instantanés de données, en utilisant une
!>    compression des données basée sur une factorisation QR.
!>    Pour les matrices d'entrée X et Y telles que Y = A*X avec une
!>    matrice A inaccessible, CGEDMDQ calcule un certain nombre de
!>    paires de Ritz de A en utilisant l'extraction standard
!>    Rayleigh-Ritz à partir d'un sous-espace de l'image de X qui est
!>    déterminé à l'aide des vecteurs singuliers gauches principaux de X.
!>    En option, CGEDMDQ renvoie les résidus des paires de Ritz
!>    calculées, les informations nécessaires pour un raffinement des
!>    vecteurs de Ritz, ou les vecteurs propres du DMD Exact.
!>    Pour plus de détails, voir les références listées ci-dessous.
!>    Pour plus de détails sur l'implémentation, voir [3].
!
>

Paramètre

s
JOBS 
!>    JOBS (entrée) CHARACTER*1
!>    Détermine si les instantanés de données initiaux sont mis à l'échelle
!>    par une matrice diagonale. Les instantanés de données sont les colonnes
!>    de F. Les N-1 premières colonnes de F sont notées X et les N-1 dernières
!>    colonnes sont notées Y.
!>    'S' :: Les matrices d'instantanés de données X et Y sont multipliées
!>           par une matrice diagonale D de sorte que X*D ait des colonnes
!>           non nulles de norme unitaire (dans la 2-norme euclidienne)
!>    'C' :: Les instantanés sont mis à l'échelle comme avec l'option 'S'.
!>           S'il est constaté que la i-ème colonne de X est un vecteur nul
!>           et que la i-ème colonne correspondante de Y est non nulle,
!>           alors la i-ème colonne de Y est mise à zéro et un indicateur
!>           d'avertissement est levé.
!>    'Y' :: Les matrices d'instantanés de données X et Y sont multipliées
!>           par une matrice diagonale D de sorte que Y*D ait des colonnes
!>           non nulles de norme unitaire (dans la 2-norme euclidienne)
!>    'N' :: Pas de mise à l'échelle des données.
!
>

JOB

Z 
!>    JOBZ (entrée) CHARACTER*1
!>    Détermine si les vecteurs propres (modes de Koopman) seront
!>    calculés.
!>    'V' :: Les vecteurs propres (modes de Koopman) seront calculés
!>           et renvoyés dans la matrice Z.
!>           Voir la description de Z.
!>    'F' :: Les vecteurs propres (modes de Koopman) seront renvoyés
!>           sous forme factorisée comme le produit Z*V, où Z
!>           est orthonormale et V contient les vecteurs propres
!>           du quotient de Rayleigh correspondant.
!>           Voir les descriptions de F, V, Z.
!>    'Q' :: Les vecteurs propres (modes de Koopman) seront renvoyés
!>           sous forme factorisée comme le produit Q*Z, où Z
!>           contient les vecteurs propres de la compression de
!>           l'opérateur discretisé sous-jacent sur l'enveloppe des
!>           instantanés de données. Voir les descriptions de F, V, Z.
!>           Q provient de la factorisation QR initiale.
!>    'N' :: Les vecteurs propres ne sont pas calculés.
!
>

JOB

R 
!>    JOBR (entrée) CHARACTER*1
!>    Détermine s'il faut calculer les résidus.
!>    'R' :: Les résidus des paires de valeurs propres calculées seront
!>           calculés et stockés dans le tableau RES.
!>           Voir la description de RES.
!>           Pour que cette option soit légale, JOBZ doit être 'V'.
!>    'N' :: Les résidus ne sont pas calculés.
!>

JOBQ

!>    JOBQ (entrée) CHARACTER*1
!>    Spécifie s'il faut calculer et retourner explicitement la
!>    matrice unitaire issue de la factorisation QR.
!>    'Q' :: La matrice Q de la factorisation QR de la matrice
!>           des instantanés de données est calculée et stockée
!>           dans le tableau F. Voir la description de F.
!>    'N' :: La matrice Q n'est pas calculée explicitement.
!>

JOBT

!>    JOBT (entrée) CHARACTER*1
!>    Spécifie s'il faut retourner le facteur triangulaire
!>    supérieur issu de la factorisation QR.
!>    'R' :: La matrice R de la factorisation QR de la matrice
!>           des instantanés de données F est retournée dans le
!>           tableau Y. Voir la description de Y et les détails
!>           supplémentaires.
!>    'N' :: La matrice R n'est pas retournée.
!>

JOBF

!>    JOBF (entrée) CHARACTER*1
!>    Spécifie s'il faut stocker les informations nécessaires au
!>    post-traitement (par ex. le calcul de vecteurs Ritz
!>    raffinés).
!>    'R' :: La matrice nécessaire au raffinement des vecteurs
!>           Ritz est calculée et stockée dans le tableau B.
!>           Voir la description de B.
!>    'E' :: Les vecteurs propres non mis à l'échelle du DMD
!>           Exact sont calculés et retournés dans le tableau B.
!>           Voir la description de B.
!>    'N' :: Aucune donnée de raffinement de vecteurs propres
!>           n'est calculée.
!>    Pour être utile à la sortie, cette option nécessite
!>    JOBQ='Q'.
!>

WHTSVD

!>    WHTSVD (entrée) INTEGER, WHSTVD dans { 1, 2, 3, 4 }
!>    Permet de sélectionner l'algorithme SVD de la
!>    bibliothèque LAPACK.
!>    1 :: CGESVD (l'algorithme SVD par QR)
!>    2 :: CGESDD (l'algorithme Diviser pour Régner ; si assez
!>         d'espace de travail est disponible, c'est l'option la
!>         plus rapide)
!>    3 :: CGESVDQ (le SVD par QR préconditionné ; ceci et 4
!>         sont les options les plus précises)
!>    4 :: CGEJSV (le SVD de Jacobi préconditionné ; ceci et 3
!>         sont les options les plus précises)
!>    Pour les quatre méthodes ci-dessus, une différence
!>    significative dans la précision des petites valeurs
!>    singulières est possible si les instantanés varient en
!>    norme de sorte que X soit sévèrement mal conditionné.
!>    Si les petites valeurs singulières (plus petites que
!>    EPS*||X||) sont d'intérêt et que JOBS=='N', alors les
!>    options (3, 4) donnent les résultats les plus précis, où
!>    l'option 4 est légèrement meilleure et avec un
!>    fondement théorique plus solide.
!>    Si JOBS=='S', c.-à-d. que les colonnes de X seront
!>    normalisées, alors toutes les méthodes donnent des
!>    résultats presque également précis.
!>

M

!>    M (entrée) INTEGER, M >= 0
!>    La dimension de l'espace d'état (le nombre de lignes de
!>    F).
!>

N

!>    N (entrée) INTEGER, 0 <= N <= M
!>    Le nombre d'instantanés de données d'une seule
!>    trajectoire, pris à des temps discrets équidistants. C'est
!>    le nombre de colonnes de F.
!>

F

!>    F (entrée/sortie) COMPLEX(KIND=WP) tableau M-par-N
!>    > À l'entrée,
!>    les colonnes de F sont la séquence d'instantanés de
!>    données d'une seule trajectoire, pris à des temps discrets
!>    équidistants. On suppose que les normes de colonne de F
!>    sont dans la plage des nombres flottants normalisés.
!>    < À la sortie,
!>    Si JOBQ == 'Q', le tableau F contient la matrice
!>    orthogonale/le facteur de la factorisation QR de la matrice
!>    initiale des instantanés de données F. Voir la description
!>    de JOBQ.
!>    Si JOBQ == 'N', les entrées de F strictement sous la
!>    diagonale principale contiennent, colonne par colonne, les
!>    informations sur les vecteurs Householder, telles que
!>    retournées par CGEQRF. L'information restante pour
!>    reconstruire la matrice orthogonale de la factorisation QR
!>    initiale est stockée dans ZWORK(1:MIN(M,N)).
!>    Voir la description de ZWORK.
!>

LDF

!>    LDF (entrée) INTEGER, LDF >= M
!>    La dimension principale du tableau F.
!>

X

!>    X (espace de travail/sortie) COMPLEX(KIND=WP) tableau
!>    MIN(M,N)-par-(N-1)
!>    X est utilisé comme espace de travail pour contenir les
!>    représentations des N-1 premiers instantanés dans la base
!>    orthonormale calculée dans la factorisation QR de F.
!>    À la sortie, les K premières colonnes de X contiennent les
!>    K premiers vecteurs singuliers gauches du contenu de X
!>    décrit ci-dessus. Pour les élever à l'espace des vecteurs
!>    singuliers gauches U(:,1:K) des données d'entrée,
!>    pré-multiplier par le facteur Q de la factorisation QR
!>    initiale.
!>    Voir les descriptions de F, K, V et Z.
!>

LDX

!>    LDX (entrée) INTEGER, LDX >= N
!>    La dimension principale du tableau X.
!>

Y

!>    Y (espace de travail/sortie) COMPLEX(KIND=WP) tableau
!>    MIN(M,N)-par-(N)
!>    Y est utilisé comme espace de travail pour contenir les
!>    représentations des N-1 derniers instantanés dans la base
!>    orthonormale calculée dans la factorisation QR de F.
!>    À la sortie,
!>    Si JOBT == 'R', Y contient le facteur triangulaire
!>    supérieur MIN(M,N)-par-N issu de la factorisation QR de la
!>    matrice des instantanés de données F.
!>

LDY

!>    LDY (entrée) INTEGER , LDY >= N
!>    La dimension principale du tableau Y.
!>

NRNK

!>    NRNK (entrée) INTEGER
!>    Détermine le mode de calcul du rang numérique,
!>    c.-à-d. comment tronquer les petites valeurs singulières
!>    de la matrice d'entrée X. À l'entrée, si
!>    NRNK = -1 :: la i-ème valeur singulière sigma(i) est
!>                 tronquée si sigma(i) <= TOL*sigma(1)
!>                 Cette option est recommandée.
!>    NRNK = -2 :: la i-ème valeur singulière sigma(i) est
!>                 tronquée si sigma(i) <= TOL*sigma(i-1)
!>                 Cette option est incluse à des fins de R&D.
!>                 Elle nécessite un SVD hautement précis, ce
!>                 qui peut ne pas être réalisable.
!>    Le rang numérique peut être imposé en utilisant une valeur
!>    positive de NRNK comme suit :
!>    0 < NRNK <= N-1 :: au plus NRNK des plus grandes valeurs
!>    singulières seront utilisées. Si le nombre des valeurs
!>    singulières non nulles calculées est inférieur à NRNK,
!>    alors seules ces valeurs non nulles seront utilisées et la
!>    dimension réellement utilisée est inférieure à NRNK. Le
!>    nombre réel de valeurs singulières non nulles est retourné
!>    dans la variable K. Voir la description de K.
!>

TOL

!>    TOL (entrée) REAL(KIND=WP), 0 <= TOL < 1
!>    La tolérance pour tronquer les petites valeurs
!>    singulières.
!>    Voir la description de NRNK.
!>

K

!>    K (sortie) INTEGER,  0 <= K <= N
!>    La dimension de la base SVD/POD pour les N-1 premiers
!>    instantanés de données (colonnes de F) et le nombre de
!>    paires de Ritz calculées. La valeur de K est déterminée
!>    selon la règle définie par les paramètres NRNK et TOL.
!>    Voir les descriptions de NRNK et TOL.
!>

EIGS

!>    EIGS (sortie) COMPLEX(KIND=WP) tableau (N-1)-par-1
!>    Les K premières entrées (K<=N-1) de EIGS contiennent
!>    les valeurs propres calculées (valeurs de Ritz).
!>    Voir les descriptions de K et Z.
!>

Z

!>    Z (espace de travail/sortie) COMPLEX(KIND=WP) tableau
!>    M-par-(N-1)
!>    Si JOBZ =='V' alors Z contient les vecteurs de Ritz.
!>    Z(:,i) est un vecteur propre de la i-ème valeur de Ritz ;
!>    ||Z(:,i)||_2=1.
!>    Si JOBZ == 'F', alors les Z(:,i) sont donnés implicitement
!>    comme Z*V, où Z contient la matrice orthonormale (le
!>    produit de Q de la factorisation QR initiale et de la
!>    base SVD/POD retournée par CGEDMD dans X) et le second
!>    facteur (les vecteurs propres du quotient de Rayleigh)
!>    est dans le tableau V, tel que retourné par CGEDMD. C'est-
!>    à-dire, X(:,1:K)*V(:,i) est un vecteur propre
!>    correspondant à EIGS(i). Les colonnes de V(1:K,1:K) sont
!>    les vecteurs propres calculés du quotient de Rayleigh
!>    K-par-K.
!>    Voir les descriptions de EIGS, X et V.
!>

LDZ

!>    LDZ (entrée) INTEGER , LDZ >= M
!>    La dimension principale du tableau Z.
!>

RES

!>    RES (sortie) REAL(KIND=WP) tableau (N-1)-par-1
!>    RES(1:K) contient les résidus pour les K paires de Ritz
!>    calculées,
!>    RES(i) = || A * Z(:,i) - EIGS(i)*Z(:,i))||_2.
!>    Voir la description de EIGS et Z.
!>

B

!>    B (sortie) COMPLEX(KIND=WP) tableau MIN(M,N)-par-(N-1).
!>    Si JOBF =='R', B(1:N,1:K) contient A*U(:,1:K), et peut
!>    être utilisé pour calculer les vecteurs raffinés ; voir les
!>    détails supplémentaires dans les références fournies.
!>    Si JOBF == 'E', B(1:N,1;K) contient
!>    A*U(:,1:K)*W(1:K,1:K), qui sont les vecteurs du DMD
!>    Exact, à l'échelle près de l'inverse des valeurs propres.
!>    Dans les deux cas, le contenu de B peut être élevé à la
!>    dimension originale des données d'entrée en pré-multipliant
!>    par le facteur Q de la factorisation QR initiale.
!>    Ici, A désigne une compression de l'opérateur sous-jacent.
!>    Voir les descriptions de F et X.
!>    Si JOBF =='N', alors B n'est pas référencé.
!>

LDB

!>    LDB (entrée) INTEGER, LDB >= MIN(M,N)
!>    La dimension principale du tableau B.
!>

V

!>    V (espace de travail/sortie) COMPLEX(KIND=WP) tableau
!>    (N-1)-par-(N-1)
!>    À la sortie, V(1:K,1:K) V contient les K vecteurs propres
!>    du quotient de Rayleigh. Les vecteurs de Ritz (retournés
!>    dans Z) sont le produit de Q de la factorisation QR
!>    initiale (voir la description de F) X (voir la description
!>    de X) et V.
!>

LDV

!>    LDV (entrée) INTEGER, LDV >= N-1
!>    La dimension principale du tableau V.
!>

S

!>    S (sortie) COMPLEX(KIND=WP) tableau (N-1)-par-(N-1)
!>    Le tableau S(1:K,1:K) est utilisé pour le quotient de
!>    Rayleigh de matrice. Ce contenu est écrasé pendant la
!>    décomposition en valeurs propres par CGEEV.
!>    Voir la description de K.
!>

LDS

!>    LDS (entrée) INTEGER, LDS >= N-1
!>    La dimension principale du tableau S.
!>

ZWORK

!>    ZWORK (espace de travail/sortie) COMPLEX(KIND=WP)
!>    tableau LWORK-par-1
!>    À la sortie,
!>    ZWORK(1:MIN(M,N)) contient les facteurs scalaires des
!>    réflecteurs élémentaires tels que retournés par CGEQRF de
!>    la matrice d'entrée M-par-N F.
!>    Si l'appel à CGEDMDQ est uniquement une interrogation
!>    d'espace de travail, alors ZWORK(1) contient la longueur
!>    minimale de l'espace de travail complexe et ZWORK(2) est
!>    la longueur optimale de l'espace de travail complexe.
!>    Ainsi, la longueur du travail est au moins 2.
!>    Voir la description de LZWORK.
!>

LZWORK

!>    LZWORK (entrée) INTEGER
!>    La longueur minimale du vecteur d'espace de travail ZWORK.
!>    LZWORK est calculé comme suit :
!>    Soit MLWQR  = N (espace de travail minimal pour
!>                   CGEQRF[M,N])
!>        MLWDMD = espace de travail minimal pour CGEDMD (voir
!>                 la description de LWORK dans CGEDMD)
!>        MLWMQR = N (espace de travail minimal pour
!>                   ZUNMQR['L','N',M,N,N])
!>        MLWGQR = N (espace de travail minimal pour
!>                   ZUNGQR[M,N,N])
!>        MINMN  = MIN(M,N)
!>    Alors
!>    LZWORK = MAX(2, MIN(M,N)+MLWQR, MINMN+MLWDMD)
!>    est ensuite mis à jour comme suit :
!>       si   JOBZ == 'V' ou JOBZ == 'F' ALORS
!>            LZWORK = MAX( LZWORK, MINMN+MLWMQR )
!>       si   JOBQ == 'Q' ALORS
!>            LZWORK = MAX( ZLWORK, MINMN+MLWGQR)
!
>

WOR

K 
!>    WORK (espace de travail/sortie) tableau REAL(KIND=WP) de dimension LWORK par 1
!>    À la sortie,
!>    WORK(1:N-1) contient les valeurs singulières de
!>    la sous-matrice d'entrée F(1:M,1:N-1).
!>    Si l'appel à CGEDMDQ est uniquement une interrogation
!>    d'espace de travail, alors
!>    WORK(1) contient la longueur minimale de l'espace de travail et
!>    WORK(2) est la longueur optimale de l'espace de travail. Par conséquent, la
!>    longueur de work est au moins 2.
!>    Voir la description de LWORK.
!
>

LWOR

K 
!>    LWORK (entrée) INTEGER
!>    La longueur minimale du vecteur d'espace de travail WORK.
!>    LWORK est le même que dans CGEDMD, car dans CGEDMDQ
!>    seul CGEDMD nécessite un espace de travail réel pour les instantanés
!>    de dimensions MIN(M,N) par (N-1).
!>    Si à l'entrée LWORK = -1, alors une interrogation d'espace de travail est
!>    supposée et la procédure calcule uniquement les longueurs minimale
!>    et optimale de l'espace de travail pour WORK et
!>    IWORK. Voir les descriptions de WORK et IWORK.
!
>

IWOR

K 
!>    IWORK (espace de travail/sortie) tableau INTEGER de dimension LIWORK par 1
!>    Espace de travail qui n'est requis que si WHTSVD vaut
!>    2 , 3 ou 4. (Voir la description de WHTSVD).
!>    Si à l'entrée LWORK =-1 ou LIWORK=-1, alors la
!>    longueur minimale de IWORK est calculée et retournée dans
!>    IWORK(1). Voir la description de LIWORK.
!
>

LIWOR

K 
!>    LIWORK (entrée) INTEGER
!>    La longueur minimale du vecteur d'espace de travail IWORK.
!>    Si WHTSVD == 1, alors seul IWORK(1) est utilisé ; LIWORK >=1
!>    Soit M1=MIN(M,N), N1=N-1. Alors
!>    Si WHTSVD == 2, alors LIWORK >= MAX(1,8*MIN(M,N))
!>    Si WHTSVD == 3, alors LIWORK >= MAX(1,M+N-1)
!>    Si WHTSVD == 4, alors LIWORK >= MAX(3,M+3*N)
!>    Si à l'entrée LIWORK = -1, alors une interrogation d'espace de travail est
!>    supposée et la procédure calcule uniquement les longueurs minimale
!>    et optimale de l'espace de travail pour WORK et
!>    IWORK. Voir les descriptions de WORK et IWORK.
!
>

INF

O 
!>    INFO (sortie) INTEGER
