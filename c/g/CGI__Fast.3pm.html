DESCRIPTIO

N

CGI::Fast est une sous-classe de l'objet CGI créé par CGI.pm. Elle est spécialisée pour fonctionner avec le module FCGI, qui accélère considérablement les scripts CGI en les transformant en processus serveur persistants. Les scripts qui effectuent des initialisations longues, comme le chargement de gros modules ou l'ouverture de connexions de base de données persistantes, verront de grandes améliorations de

performance.

Notez que CGI::Fast étant basé sur CGI.pm, il n'est plus recommandé d'écrire des applications web Perl avec lui. Voir https://metacpan.org/pod/CGI#CGI.pm-HAS-BEEN-REMOVED-FRO

us d'informations à ce sujet

ÉCRIRE DES SCRIPTS PERL

FASTCGI

Les scripts FastCGI sont persistants : une ou plusieurs copies du script sont démarrées lorsque le serveur s'initialise, et restent en activité jusqu'à ce que le serveur se termine ou qu'elles meurent naturellement. Après avoir effectué l'initialisation unique dont elles ont besoin, les scripts entrent dans une boucle en attente de connexions entrantes, traitent la requête, et attendent à

nouveau.

Un script FastCGI typique ressemblera à ceci

: 
#!perl
use CGI::Fast;
do_some_initialization();
while ($q = CGI::Fast->new) {
    process_request($q);
}

À chaque nouvelle requête, CGI::Fast renvoie un objet CGI à votre boucle. Le reste du temps, votre script attend dans l'appel à new(). Lorsque le serveur demande la terminaison de votre script, new() renverra undef. Vous pouvez bien sûr sortir plus tôt si vous le souhaitez. Une nouvelle version du script sera relancée pour le remplacer (cela peut être nécessaire pour éviter les fuites de mémoire Perl dans les scripts à longue durée de vie)

.

Le mode objet CGI par défaut de CGI.pm fonctionne aussi. Modifiez simplement la boucle de cette manière

: 
while (CGI::Fast->new) {
    process_request();
}

Les appels à header(), start_form(), etc. opéreront to

us sur la r
equête en cours.

INVOCATION D'UN SERVEUR FASTCGI

EXTERNE

FastCGI prend en charge un mécanisme de transport TCP/IP qui permet aux scripts FastCGI de s'exécuter en dehors du serveur web, peut-être sur une machine distante. Pour configurer le serveur web afin qu'il se connecte à un serveur FastCGI externe, vous ajouteriez ce qui suit à votre srm.conf

: 
FastCgiExternalServer /usr/etc/httpd/fcgi-bin/file_upload.fcgi -host sputnik:
8888

Deux variables d'environnement affectent la manière dont l'objet "CGI::Fast" est créé, permettant "CGI::Fast" d'être utilisé comme serveur FastCGI externe. (Voir la documentation de "FCGI" pour "FCGI::OpenSocket" pour plus d'informations.

)

Vous pouvez définir ces variables en tant que variables ENV ou en tant qu'imports dans l'instruction use CGI::Fast. Si les variables ENV sont définies, elles seront préférées, ce qui vous permet de remplacer les instructions d'importation depuis la ligne de commande,

etc.
FCGI_SOCKET_PATH /
socket_path
L'adresse (TCP/IP) ou le chemin (Domaine UNIX) du socket auquel le script FastCGI externe doit se lier et écouter les connexions entrantes du serveur
web.
FCGI_SOCKET_PERM /
socket_perm
Permissions pour le socket de domaine
UNIX.
FCGI_LISTEN_QUEUE /
listen_queue
Longueur maximale de la fil
e d'attente des connexions
en attente, par défaut 100.

Par exemple

: 
use CGI::Fast
    socket_path  => "sputnik:8888",
    listen_queue => "50"
;
use CGI qw/ :standard /;
do_some_initialization();
while ($q = CGI::Fast->new) {
    process_request($q);
}

Ou

: 
use CGI::Fast;
use CGI qw/ :standard /;
do_some_initialization();
$ENV{FCGI_SOCKET_PATH} = "sputnik:8888";
$ENV{FCGI_LISTEN_QUEUE} = 50;
while ($q = CGI::Fast->new) {
    process_request($q);
}

Notez l'importance d'avoir use CGI après use CGI::Fast, car cela empêchera toute pragme d'importation CGI d'être écrasé par CGI::Fast. Vous pouvez utiliser CGI::Fast comme un remplacement direct comme ceci

: 
use CGI::F
ast qw/ :
standard /

GESTION DES

FICHIERS

FCGI utilise par défaut STDOUT et STDERR comme ses descripteurs de fichiers de sortie - cela peut entraîner une redirection inattendue de la sortie si vous migrez des scripts de CGI.pm vers CGI::Fast. Pour contourner cela, vous pouvez utiliser la méthode file_handles, que vous devez utiliser avant le premier appel à CGI::Fast->new. Par exemple, avec IO::Handle

: 
CGI::Fast->file_handles({
    fcgi_output_file_handle => IO::Handle->new,
    fcgi_error_file_handle  => IO::Handle->new,
});
while (CGI::Fast->new) {
    ..
}

t au moins les requêtes POST.
