NOM

cgitrc - configuration d'exécution pour cgit

SYNTAXE

Cgitrc contient tous les paramètres d'exécution de cgit, y compris la liste des dépôts git, formatée en une liste de paires NOM=VALEUR séparées par des retours à la ligne. Les lignes vides et les lignes commençant par # sont ignorées.

EMPLACEMENT

L'emplacement par défaut de cgitrc, défini lors de la compilation, est /etc/cgitrc. À l'exécution, cgit consultera la variable d'environnement CGIT_CONFIG et, si elle est définie, utilisera sa valeur à la place.

PARAMÈTRES GÉNÉRAUX

about-filter

Spécifie une commande qui sera invoquée pour formater le contenu des pages "about" (à la fois au niveau supérieur et pour chaque dépôt). La commande recevra le contenu du fichier "about" sur son STDIN, le nom du fichier comme premier argument, et la sortie standard (STDOUT) de la commande sera incluse verbatim dans la page "about". Valeur par défaut : aucune. Voir aussi : "API DES FILTRES".

agefile

Spécifie un chemin, relatif au chemin de chaque dépôt, qui peut être utilisé pour spécifier la date et l'heure du commit le plus récent dans le dépôt. La première ligne du fichier est utilisée comme entrée pour la fonction "parse_date" de libgit. Le format d'horodatage recommandé est "yyyy-mm-dd hh:mm:ss". Vous pourriez vouloir générer ce fichier à partir d'un hook post-receive. Valeur par défaut : "info/web/last-modified".

auth-filter

Spécifie une commande qui sera invoquée pour l'authentification de l'accès aux dépôts. Reçoit un nombre considérable d'arguments, et des données sur l'entrée et la sortie standard (stdin et stdout) pour le traitement de l'authentification. Les détails suivent plus loin dans ce document. Si aucun auth-filter n'est spécifié, aucune authentification n'est effectuée. Valeur par défaut : aucune. Voir aussi : "API DES FILTRES".

branch-sort

Indicateur qui, lorsqu'il est défini sur "age", active le tri par date dans la liste des références de branches, et lorsqu'il est défini sur "name", active le tri par nom de branche. Valeur par défaut : "name".

cache-about-ttl

Nombre qui spécifie la durée de vie (time-to-live), en minutes, de la version mise en cache de la page "about" du dépôt. Voir aussi : "CACHE". Valeur par défaut : "15".

cache-dynamic-ttl

Nombre qui spécifie la durée de vie (time-to-live), en minutes, de la version mise en cache des pages de dépôt accédées sans SHA1 fixe. Voir aussi : "CACHE". Valeur par défaut : "5".

cache-repo-ttl

Nombre qui spécifie la durée de vie (time-to-live), en minutes, de la version mise en cache de la page de résumé du dépôt. Voir aussi : "CACHE". Valeur par défaut : "5".

cache-root

Chemin utilisé pour stocker les entrées du cache cgit. Valeur par défaut : "/var/cache/cgit". Voir aussi : "EXPANSION DES MACROS".

cache-root-ttl

Nombre qui spécifie la durée de vie (time-to-live), en minutes, de la version mise en cache de la page d'index des dépôts. Voir aussi : "CACHE". Valeur par défaut : "5".

cache-scanrc-ttl

Nombre qui spécifie la durée de vie (time-to-live), en minutes, du résultat du scan d'un chemin à la recherche de dépôts git. Voir aussi : "CACHE". Valeur par défaut : "15".

case-sensitive-sort

Trie les éléments de la liste des dépôts de manière sensible à la casse. Valeur par défaut : "1". Voir aussi : repository-sort, section-sort.

cache-size

Le nombre maximum d'entrées dans le cache cgit. Lorsqu'il est défini sur "0", la mise en cache est désactivée. Voir aussi : "CACHE". Valeur par défaut : "0"

cache-snapshot-ttl

Nombre qui spécifie la durée de vie (time-to-live), en minutes, de la version mise en cache des instantanés (snapshots). Voir aussi : "CACHE". Valeur par défaut : "5".

cache-static-ttl

Nombre qui spécifie la durée de vie (time-to-live), en minutes, de la version mise en cache des pages de dépôt accédées avec un SHA1 fixe. Voir aussi : "CACHE". Valeur par défaut : -1".

clone-prefix

Liste de préfixes courants séparés par des espaces qui, combinés à une URL de dépôt, génèrent des URL de clonage valides pour le dépôt. Ce paramètre n'est utilisé que si repo.clone-url n'est pas spécifié. Valeur par défaut : aucune.

clone-url

Liste de modèles d'URL de clonage séparés par des espaces. Ce paramètre n'est utilisé que si repo.clone-url n'est pas spécifié. Valeur par défaut : aucune. Voir aussi : "EXPANSION DES MACROS", "API DES FILTRES".

commit-filter

Spécifie une commande qui sera invoquée pour formater les messages de commit. La commande recevra le message sur son STDIN, et la sortie standard (STDOUT) de la commande sera incluse verbatim comme message de commit, c'est-à-dire que cela peut être utilisé pour implémenter l'intégration de bugtrackers. Valeur par défaut : aucune. Voir aussi : "API DES FILTRES".

commit-sort

Indicateur qui, lorsqu'il est défini sur "date", active un tri strict par date dans le journal des commits, et lorsqu'il est défini sur "topo", active un tri topologique strict. S'il n'est pas défini, le tri par défaut de "git log" est utilisé. Valeur par défaut : non défini.

css

URL qui spécifie le document css à inclure dans toutes les pages cgit. Valeur par défaut : "/cgit.css". Peut être donné plusieurs fois, chaque chemin d'URL css est ajouté à la section head du document à tour de rôle.

email-filter

Spécifie une commande qui sera invoquée pour formater les noms et adresses électroniques des committeurs, auteurs et taggers, tels qu'ils sont représentés dans divers endroits de l'interface cgit. Cette commande recevra une adresse électronique et une chaîne indiquant la page d'origine comme arguments de ligne de commande, et le texte à formater sur STDIN. Elle doit écrire le texte formaté en retour sur STDOUT. Valeur par défaut : aucune. Voir aussi : "API DES FILTRES".

embedded

Indicateur qui, lorsqu'il est défini sur "1", fera générer à cgit un fragment html adapté à l'intégration dans d'autres pages html. Valeur par défaut : aucune. Voir aussi : "noheader".

enable-blame

Indicateur qui, lorsqu'il est défini sur "1", permettra à cgit de fournir une page "blame" pour les fichiers, et générera des liens vers cette page aux endroits appropriés. Valeur par défaut : "0".

enable-commit-graph

Indicateur qui, lorsqu'il est défini sur "1", affichera un graphique d'historique de commit en art ASCII à gauche des messages de commit sur la page du journal des commits. Valeur par défaut : "0".

enable-filter-overrides

Indicateur qui, lorsqu'il est défini sur "1", permet à tous les paramètres de filtre d'être remplacés dans les fichiers cgitrc spécifiques au dépôt. Valeur par défaut : aucune.

enable-follow-links

Indicateur qui, lorsqu'il est défini sur "1", permet aux utilisateurs de suivre un fichier dans la vue du journal. Valeur par défaut : "0".

enable-git-config

Indicateur qui, lorsqu'il est défini sur "1", permettra à cgit d'utiliser la configuration git pour définir des paramètres spécifiques à chaque dépôt. Cette option est utilisée conjointement avec "scan-path", et doit être définie au préalable, pour compléter les paramètres spécifiques au dépôt. Les clés gitweb.owner, gitweb.category, gitweb.description et gitweb.homepage seront mappées aux clés cgit repo.owner, repo.section, repo.desc et repo.homepage respectivement. Toutes les clés de configuration git qui commencent par "cgit." seront mappées à la clé "repo." correspondante dans cgit. Valeur par défaut : "0". Voir aussi : scan-path, section-from-path.

enable-http-clone

S'il est défini sur "1", cgit agira comme un point d'extrémité HTTP "dumb" pour les clonages git. Vous pouvez ajouter "http://$HTTP_HOST$SCRIPT_NAME/$CGIT_REPO_URL" à clone-url pour exposer cette fonctionnalité. Si vous utilisez une autre méthode pour servir des dépôts git, vous pourriez vouloir désactiver ceci. Valeur par défaut : "1".

enable-html-serving

Indicateur qui, lorsqu'il est défini sur "1", permettra au gestionnaire /plain de servir des en-têtes de type MIME qui entraînent que le fichier soit traité comme HTML par le navigateur. Lorsqu'il est défini sur "0", de tels types de fichiers sont plutôt renvoyés comme text/plain ou application/octet-stream. Valeur par défaut : "0". Voir aussi : "repo.enable-html-serving".

enable-index-links

Indicateur qui, lorsqu'il est défini sur "1", fera générer à cgit des liens supplémentaires pour chaque dépôt dans l'index des dépôts (spécifiquement, vers les pages "summary", "commit" et "tree"). Valeur par défaut : "0".

enable-index-owner

Indicateur qui, lorsqu'il est défini sur "1", affichera le propriétaire de chaque dépôt dans l'index des dépôts. Valeur par défaut : "1"

Ce site n'est en aucun cas associé à Arch Linux ni affilié à ce projet. Le contenu est uniquement une traduction des pages de manuel d'Arch publiées sur man.archlinux.org.

s

enable-subject-link

s

enable-tree-linenumber

s
Drapeau qui, lorsqu'il est défini à « 1 », fera en sorte que cgit génère des liens de numérotation de lignes pour les blobs de texte brut affichés dans la vue arbre. Valeur par défaut : « 1 »

n
URL utilisée comme lien vers une icône de raccourci pour cgit. Il est recommandé d'utiliser la valeur « /favicon.ico » car certains navigateurs ignoreront les autres valeurs. Valeur par défaut : « /favicon.ico »
.

e

e

mimetype-fil

e
Spécifie le fichier à utiliser pour la recherche automatique de mimetype. Si spécifié, ce champ est utilisé comme solution de repli lorsqu'aucune correspondance « mimetype.<ext> » n'est trouvée. Si non spécifié, aucune telle recherche n'est effectuée. Le fichier typique à utiliser sur un système Linux est /etc/mime.types. Le format du fichier doit se conformer à :
•une ligne de commentaire est une ligne vide ou une ligne commençant par une dièse (#), éventuellement précédée
d'espaces
•une ligne non-commentaire commence par le mimetype (comme image/png), suivie d'une ou plusieurs extensions de fichier (comme jpg), toutes séparées par des espaces Valeur par défaut : aucune. Voir aussi : « mimetype.<ext>
»

module-lin

k
Texte qui sera utilisé comme chaîne de format pour un lien hypertexte lorsqu'un sous-module est affiché dans une liste de répertoire. Les arguments pour la chaîne de format sont le chemin et le SHA1 du commit du sous-module. Valeur par défaut :
aucune.

noplainemai

l
S'il est défini à « 1 », l'affichage des adresses e-mail complètes des auteurs sera désactivé. Valeur par défaut : « 0 »
.

noheade

r
Drapeau qui, lorsqu'il est défini à « 1 », fera en sorte que cgit omette l'en-tête standard sur toutes les pages. Valeur par défaut : aucune. Voir aussi : « embedded »
.

owner-filte

r
Spécifie une commande qui sera invoquée pour formater la colonne Owner de la page principale. La commande recevra le propriétaire sur STDIN, et le STDOUT de la commande sera inclus tel quel dans le tableau. Cela peut être utilisé pour créer un lien vers un contexte supplémentaire tel que la page d'accueil d'un propriétaire. Lorsqu'il est actif, ce filtre est utilisé à la place de l'URL de requête propriétaire par défaut. Valeur par défaut : aucune. Voir aussi : « FILTER API »
.

project-lis

t
Une liste de sous-répertoires à l'intérieur de scan-path, relatifs à celui-ci, qui doivent être chargés en tant que dépôts git. Cela doit être défini avant scan-path. Valeur par défaut : aucune. Voir aussi : scan-path, « MACRO EXPANSION »
.

readm

e
Texte qui sera utilisé comme valeur par défaut pour « repo.readme ». Plusieurs clés de configuration peuvent être spécifiées, et cgit utilisera le premier fichier trouvé dans cette liste. C'est utile en conjonction avec scan-path. Valeur par défaut : aucune. Voir aussi : scan-path, repo.
readme.

remove-suffi

x
S'il est défini à « 1 » et que scan-path est activé, si des dépôts sont trouvés avec un suffixe « .git », ce suffixe sera supprimé pour l'URL et le nom. Cela doit être défini avant scan-path. Valeur par défaut : « 0 ». Voir aussi :
scan-path.

renamelimi

t
Nombre maximal de fichiers à considérer lors de la détection des renommages. La valeur « -1 » utilise la valeur à la compilation dans git (pour plus d'informations, consultez man git-diff). Valeur par défaut : « -1 »
.

repository-sor

t
La manière dont les dépôts dans chaque section sont triés. Les valeurs valides sont « name » pour trier par le nom du dépôt ou « age » pour trier par le dépôt le plus récemment mis à jour. Valeur par défaut : « name ». Voir aussi : section, case-sensitive-sort,
section-sort.

robot

s
Texte utilisé comme contenu pour la méta-balise « robots ». Valeur par défaut : « index, nofollow »
.

root-des

c
Texte affiché sous le titre sur la page d'index du dépôt. Valeur par défaut : « a fast webinterface for the git dscm »
.

root-readm

e
Le contenu du fichier spécifié avec cette option sera inclus tel quel sous le lien « about » sur la page d'index du dépôt. Valeur par défaut :
aucune.

root-titl

e
Texte affiché comme titre sur la page d'index du dépôt. Valeur par défaut : « Git Repository Browser »
.

scan-hidden-pat

h
S'il est défini à « 1 » et que scan-path est activé, scan-path parcourra récursivement les répertoires dont le nom commence par un point (.). Sinon, scan-path évitera ces répertoires (considérés comme « cachés »). Notez que cela ne s'applique pas au répertoire « .git » dans les dépôts non nus. Cela doit être défini avant scan-path. Valeur par défaut : 0. Voir aussi :
scan-path.

scan-pat

h
Un chemin qui sera parcouru à la recherche de dépôts. Si la mise en cache est activée, le résultat sera mis en cache en tant que fichier include cgitrc dans le répertoire de cache. Si project-list a été défini avant scan-path, scan-path charge uniquement les répertoires listés dans le fichier pointé par project-list. Notez que seuls les paramètres globaux pris avant la directive scan-path seront appliqués à chaque dépôt. Valeur par défaut : aucune. Voir aussi : cache-scanrc-ttl, project-list, « MACRO EXPANSION »
.

sectio

n
Le nom de la section de dépôt courante - tous les dépôts définis après cette option hériteront du nom de section courant. Valeur par défaut :
aucune.

section-sor

t
Drapeau qui, lorsqu'il est défini à « 1 », triera les sections de la liste des dépôts par nom. Définissez ce drapeau à « 0 » si l'ordre dans le fichier cgitrc doit être préservé. Valeur par défaut : « 1 ». Voir aussi : section, case-sensitive-sort, repository-sort
.

section-from-pat

h
Un nombre qui, s'il est défini avant scan-path, spécifie combien d'éléments de chemin de chaque chemin de dépôt utiliser comme nom de section par défaut. S'il est négatif, cgit ignorera le nombre spécifié d'éléments de chemin au-dessus du répertoire du dépôt. Valeur par défaut : « 0 »
.

side-by-side-diff

s
S'il est défini à « 1 », affiche les diffs côte à côte au lieu des unidiffs par défaut. Valeur par défaut : « 0 »
.

snapshot

s
Texte qui spécifie l'ensemble par défaut des formats de snapshot pour lesquels cgit génère des liens. La valeur est une liste d'éléments séparés par des espaces de zéro ou plusieurs des valeurs « tar », « tar.gz », « tar.bz2 », « tar.lz », « tar.xz », « tar.zst » et « zip ». La valeur spéciale « all » active tous les formats de snapshot. Valeur par défaut : aucune. Tous les compresseurs utilisent les paramètres par défaut. Certains paramètres peuvent être influencés par des variables d'environnement, par exemple définir ZSTD_CLEVEL=10 dans l'environnement du serveur web pour une compression zstd plus élevée (mais plus lente)
.

source-filte

r
Spécifie une commande qui sera invoquée pour formater les blobs de texte brut dans la vue arbre. La commande recevra le contenu du blob sur son STDIN et le nom du blob comme unique argument de ligne de commande. Le STDOUT de la commande sera inclus tel quel commeblob contents, c'est-à-dire que cela peut être utilisé pour implémenter par exemple la coloration syntaxique. Valeur par défaut : none. Voir aussi : "API DES FILTRES".

branches-resumee

Spécifie le nombre de branches à afficher dans la vue "resume" du dépôt. Valeur par défaut : "10".

log-resumee

Spécifie le nombre d'entrées de log à afficher dans la vue "resume" du dépôt. Valeur par défaut : "10".

tags-resumee

Spécifie le nombre d'étiquettes à afficher dans la vue "resume" du dépôt. Valeur par défaut : "10".

export-strict

Nom de fichier qui, s'il est spécifié, doit être présent dans le dépôt pour que cgit autorise l'accès à ce dépôt. Ceci peut être utilisé pour émuler les fonctionnalités EXPORT_OK et STRICT_EXPORT de gitweb et limiter les dépôts de cgit à ceux exportés par git-daemon. Cette option doit être définie avant scan-path.

racine-virtuelle

URL qui, si elle est spécifiée, sera utilisée comme racine pour tous les liens cgit. Elle amènera également cgit à générer des *URLs virtuelles*, c'est-à-dire des URLs comme /cgit/tree/README par opposition à ?r=cgit&p=tree&path=README. Valeur par défaut : none. REMARQUE : cgit a récemment appris à utiliser PATH_INFO pour obtenir le même type d'URLs virtuelles, donc cette option sera probablement obsolète.

PARAMETRES DU DÉPÔT

repo.filtre-a-propos

Remplace le filtre par défaut pour les informations "à propos". Valeur par défaut : none. Voir aussi : "activer-remplacements-filtre". Voir aussi : "API DES FILTRES".

repo.tri-branches

Indicateur qui, lorsqu'il est défini sur "âge", active le tri par date dans la liste des références de branches, et lorsqu'il est défini sur "nom" active le tri par nom de branche. Valeur par défaut : "nom".

repo.url-clonage

Une liste d'URLs séparées par des espaces qui peuvent être utilisées pour cloner ce dépôt. Valeur par défaut : none. Voir aussi : "EXPANSION DES MACROS".

repo.filtre-commit

Remplace le filtre par défaut pour les commits. Valeur par défaut : none. Voir aussi : "activer-remplacements-filtre". Voir aussi : "API DES FILTRES".

repo.tri-commits

Indicateur qui, lorsqu'il est défini sur "date", active le tri strict par date dans le journal des commits, et lorsqu'il est défini sur "topo" active le tri topologique strict. S'il n'est pas défini, le tri par défaut de "git log" est utilisé. Valeur par défaut : non défini.

repo.branche-defaut

Le nom de la branche par défaut pour ce dépôt. Si aucune branche de ce nom n'existe dans le dépôt, la première branche nommée (lors du tri) est utilisée comme défaut à la place. Valeur par défaut : la branche pointée par HEAD, ou "master" s'il n'y a pas de HEAD approprié.

repo.desc

La valeur à afficher comme description du dépôt. Valeur par défaut : none.

repo.filtre-email

Remplace le filtre par défaut pour les emails. Valeur par défaut : none. Voir aussi : "activer-remplacements-filtre". Voir aussi : "API DES FILTRES".

repo.activer-blame

Un indicateur qui peut être utilisé pour désactiver le paramètre global 'activer-blame'. Valeur par défaut : none.

repo.activer-graphique-commits

Un indicateur qui peut être utilisé pour désactiver le paramètre global 'activer-graphique-commits'. Valeur par défaut : none.

repo.activer-servage-html

Un indicateur qui peut être utilisé pour remplacer le paramètre global activer-servage-html. Valeur par défaut : none.

repo.activer-compte-fichiers-log

Un indicateur qui peut être utilisé pour désactiver le paramètre global 'activer-compte-fichiers-log'. Valeur par défaut : none.

repo.activer-compte-lignes-log

Un indicateur qui peut être utilisé pour désactiver le paramètre global 'activer-compte-lignes-log'. Valeur par défaut : none.

repo.activer-branches-distantes

Indicateur qui, lorsqu'il est défini sur "1", fera afficher par cgit les branches distantes dans les vues résumé et refs. Valeur par défaut : <activer-branches-distantes>.

repo.activer-liens-sujets

Un indicateur qui peut être utilisé pour remplacer le paramètre global 'activer-liens-sujets'. Valeur par défaut : none.

repo.contenu-tete-supplementaire

Cette valeur sera ajoutée verbatim dans la section head de chaque page affichée pour ce dépôt. Valeur par défaut : none.

repo.masquer

Indicateur qui, lorsqu'il est défini sur "1", masque le dépôt de l'index des dépôts. Le dépôt peut toujours être accédé en fournissant un chemin direct. Valeur par défaut : "0". Voir aussi : "repo.ignorer".

repo.page-accueil

La valeur à afficher comme page d'accueil du dépôt. Valeur par défaut : none.

repo.ignorer

Indicateur qui, lorsqu'il est défini sur "1", ignore le dépôt. Le dépôt n'est pas affiché dans l'index et ne peut pas être accédé en fournissant un chemin direct. Valeur par défaut : "0". Voir aussi : "repo.masquer".

repo.logo

URL qui spécifie la source d'une image qui sera utilisée comme logo sur les pages de ce dépôt. Valeur par défaut : logo global.

repo.lien-logo

URL chargée lors du clic sur l'image du logo cgit. Si non spécifié, l'URL calculée de la page d'index du dépôt sera utilisée. Valeur par défaut : lien-logo global.

repo.lien-module

Texte qui sera utilisé comme chaîne de formatage pour un lien hypertexte lorsqu'un sous-module est affiché dans une liste de répertoires. Les arguments pour la chaîne de formatage sont le chemin et le SHA1 du commit du sous-module. Valeur par défaut : <lien-module>

repo.lien-module.<chemin>

Texte qui sera utilisé comme chaîne de formatage pour un lien hypertexte lorsqu'un sous-module avec le chemin de sous-répertoire spécifié est affiché dans une liste de répertoires. Le seul argument pour la chaîne de formatage est le SHA1 du commit du sous-module. Valeur par défaut : none.

repo.max-stats

Remplace la période maximale de statistiques par défaut. Les valeurs valides sont égales aux valeurs spécifiées pour le paramètre global "max-stats". Valeur par défaut : none.

repo.nom

La valeur à afficher comme nom du dépôt. Valeur par défaut : <repo.url>.

repo.proprietaire

Une valeur utilisée pour identifier le propriétaire du dépôt. Valeur par défaut : none.

repo.filtre-proprietaire

Remplace le filtre par défaut pour les propriétaires. Valeur par défaut : none. Voir aussi : "activer-remplacements-filtre". Voir aussi : "API DES FILTRES".

repo.chemin

Un chemin absolu vers le répertoire du dépôt. Pour les dépôts non nus, il s'agit du répertoire .git. Valeur par défaut : none.

repo.readme

Un chemin (relatif à <repo.path>) qui spécifie un fichier à inclure tel quel comme page "À propos" de ce dépôt. Vous pouvez également spécifier une référence git par nom ou par hachage en préfixant la référence suivie d'un deux-points. Par exemple, "master:docs/readme.mkd". Si la valeur commence par un deux-points, par exemple ":docs/readme.rst", la tête donnée dans la requête ou la branche par défaut du dépôt sera utilisée. Le partage de n'importe quel fichier exposera cet arbre de répertoires entier aux points de terminaison "/about/PATH", assurez-vous donc qu'aucun fichier non public ne se trouve dans le même répertoire que le fichier readme. Valeur par défaut : <readme>.

repo.section

Remplace le nom de section actuel pour ce dépôt. Valeur par défaut : none.

repo.instantanés

Un masque de formats d'instantanés pour ce dépôt pour lesquels cgit génère des liens, restreint par le paramètre global "instantanés". Valeur par défaut : <instantanés>.

repo.prefixe-instantané

Préfixe à utiliser pour les liens d'instantanés au lieu du nom de base du dépôt. Par exemple, le dépôt "linux-stable" pourrait souhaiter définir ceci sur "linux" afin que les instantanés soient au format "linux-3.15.4" au lieu de "linux-stable-3.15.4". Valeur par défaut : <vide> ce qui signifie utiliser le nom de base du dépôt.

repo.filtre-source

Remplace le filtre par défaut pour la source. Valeur par défaut : none. Voir aussi : "activer-remplacements-filtre". Voir aussi : "API DES FILTRES".

repo.url

L'URL relative utilisée pour accéder au dépôt. Ceci doit être le premier paramètre spécifié pour chaque dépôt. Valeur par défaut : none.

FICHIER CGITRC SPÉCIFIQUE AU DÉPÔT

Lorsque l'option "scan-path" est utilisée pour découvrir automatiquement les dépôts git, cgit tentera de parser le fichier "cgitrc" dans tout dépôt trouvé. Un tel fichier de configuration spécifique au dépôt peut contenir toutes les options spécifiques au dépôt décrites ci-dessus, à l'exception de "repo.url" et "repo.path". De plus, les options "filter" ne sont reconnues dans les fichiers de configuration spécifiques au dépôt que lorsque "enable-filter-overrides" est défini sur "1".

Remarque : le préfixe "repo." est supprimé des noms d'options dans les fichiers de configuration spécifiques au dépôt, par exemple "repo.desc" devient "desc".

API DES FILTRES

Par défaut, les filtres sont des processus séparés qui sont exécutés chaque fois qu'ils sont nécessaires. Des technologies alternatives peuvent être utilisées en préfixant la spécification du filtre avec la chaîne pertinente ; les valeurs disponibles sont :

exec:

Le mode par défaut "un processus par filtre".

lua:

Exécute le script en utilisant un interpréteur Lua intégré. Le script est chargé une fois par exécution de cgit, et peut être appelé plusieurs fois pendant la durée de vie de cgit, ce qui en fait un bon choix pour les filtres répétés comme le *filtre email*. Il répond à trois fonctions :

filter_open(argument1, argument2, argument3, ...)

Ceci est appelé lors de l'activation du filtre pour un ensemble de données particulier.

filter_write(buffer)

Ceci est appelé chaque fois que cgit écrit des données sur la page web.

filter_close()

Ceci est appelé lorsque l'opération de filtrage actuelle est terminée. Elle doit retourner une valeur entière. Généralement 0 indique le succès.

CACH

E

Toutes les valeurs ttl de cache sont en minutes. Les valeurs ttl négatives indiquent qu'un type de page n'expirera jamais, et ainsi la pr

emière fois qu'une URL est accédée, le résultat sera mis en cache indéfiniment, même si le dépôt git sous-jacent change. Inversement,
lorsqu'une valeur ttl est zéro, le cache est désactivé pour ce type de page particulier, et le type de page n'est jamais mis en cache.

SIGNATURE

S

Cgit peut héberger des signatures .asc correspondant à divers formats d'instantané, via l'utilisation de notes git. Par exemple, la commande suivante peut être utilisée pour ajouter une signature à une archive .tar.xz

: 
git notes --ref=refs/notes/signatures/tar.xz add -C
"$( gpg --output - --armor --detach-sign cgit-
1.1.tar.xz | git hash-object -w --stdin )" v1.1

S'il est plutôt souhaitable d'attacher une signature du .tar sous-jacent, celle-ci sera liée, comme cas spécial, à côté d'un lien .tar.* qui n'a pas sa propre signature. Par exemple, une signature d'une archive tar du dernier tag pourrait être ajoutée avec une commande similaire

: 
tag="$(git describe --abbrev=0)"
git notes --ref=refs/notes/signatures/tar add
-C "$( git archive --format tar --prefix "cgit-${tag#v}/" "$tag" | g
pg --output - --armor --detach-sign | git hash-object -w --stdin )" "$tag"

Étant donné que git-archive(1) est censé produire une sor

tie stable entre les versions, cela permet de générer
une signature à long terme du contenu d'un tag donné.
