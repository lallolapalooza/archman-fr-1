CGGEV calcule les valeurs propres et, optionnellement, les vecteurs propres gauche et/ou droit pour les matrices GE

But :

!>
!> CGGEV calcule, pour une paire de matrices complexes non symétriques
!> N par N (A,B), les valeurs propres généralisées et, optionnellement,
!> les vecteurs propres généralisés gauche et/ou droit.
!>
!> Une valeur propre généralisée pour une paire de matrices (A,B) est un
!> scalaire lambda ou un rapport alpha/beta = lambda, tel que
!> A - lambda*B soit singulière. Elle est généralement représentée sous
!> forme de paire (alpha,beta), car il existe une interprétation
!> raisonnable pour beta=0, et même pour les deux valant zéro.
!>
!> Le vecteur propre généralisé droit v(j) correspondant à la valeur
!> propre généralisée lambda(j) de (A,B) satisfait
!>
!>              A * v(j) = lambda(j) * B * v(j).
!>
!> Le vecteur propre généralisé gauche u(j) correspondant à la valeur
!> propre généralisée lambda(j) de (A,B) satisfait
!>
!>              u(j)**H * A = lambda(j) * u(j)**H * B
!>
!> où u(j)**H est le conjugué-transposé de u(j).
!>

Paramètres

JOBVL 
!>          JOBVL est CHARACTER*1
!>          = 'N' : ne pas calculer les vecteurs propres généralisés gauches ;
!>          = 'V' : calculer les vecteurs propres généralisés gauches.
!>

JOBVR

!>          JOBVR est CHARACTER*1
!>          = 'N' : ne pas calculer les vecteurs propres généralisés droits ;
!>          = 'V' : calculer les vecteurs propres généralisés droits.
!>

N

!>          N est INTEGER
!>          L'ordre des matrices A, B, VL et VR.  N >= 0.
!>

A

!>          A est un tableau COMPLEX, dimension (LDA, N)
!>          À l'entrée, la matrice A de la paire (A,B).
!>          À la sortie, A a été écrasée.
!>

LDA

!>          LDA est INTEGER
!>          La dimension principale de A.  LDA >= max(1,N).
!>

B

!>          B est un tableau COMPLEX, dimension (LDB, N)
!>          À l'entrée, la matrice B de la paire (A,B).
!>          À la sortie, B a été écrasée.
!>

LDB

!>          LDB est INTEGER
!>          La dimension principale de B.  LDB >= max(1,N).
!>

ALPHA

!>          ALPHA est un tableau COMPLEX, dimension (N)
!>

BETA

!>          BETA est un tableau COMPLEX, dimension (N)
!>          À la sortie, ALPHA(j)/BETA(j), j=1,...,N, seront les
!>          valeurs propres généralisées.
!>
!>          Remarque : les quotients ALPHA(j)/BETA(j) peuvent facilement
!>          déborder ou être trop petits, et BETA(j) peut même être zéro.
!>          Ainsi, l'utilisateur devrait éviter de calculer naïvement le
!>          rapport alpha/beta.
!>          Cependant, ALPHA sera toujours inférieur et généralement
!>          comparable en magnitude à norm(A), et BETA toujours inférieur
!>          et généralement comparable à norm(B).
!>

VL

!>          VL est un tableau COMPLEX, dimension (LDVL,N)
!>          Si JOBVL = 'V', les vecteurs propres généralisés gauches u(j)
!>          sont stockés les uns après les autres dans les colonnes de VL,
!>          dans le même ordre que leurs valeurs propres.
!>          Chaque vecteur propre est mis à l'échelle de sorte que sa
!>          plus grande composante ait abs(partie réelle) +
!>          abs(partie imaginaire) = 1.
!>          Non référencé si JOBVL = 'N'.
!>

LDVL

!>          LDVL est INTEGER
!>          La dimension principale de la matrice VL. LDVL >= 1, et
!>          si JOBVL = 'V', LDVL >= N.
!>

VR

!>          VR est un tableau COMPLEX, dimension (LDVR,N)
!>          Si JOBVR = 'V', les vecteurs propres généralisés droits v(j)
!>          sont stockés les uns après les autres dans les colonnes de VR,
!>          dans le même ordre que leurs valeurs propres.
!>          Chaque vecteur propre est mis à l'échelle de sorte que sa
!>          plus grande composante ait abs(partie réelle) +
!>          abs(partie imaginaire) = 1.
!>          Non référencé si JOBVR = 'N'.
!>

LDVR

!>          LDVR est INTEGER
!>          La dimension principale de la matrice VR. LDVR >= 1, et
!>          si JOBVR = 'V', LDVR >= N.
!>

WORK

!>          WORK est un tableau COMPLEX, dimension (MAX(1,LWORK))
!>          À la sortie, si INFO = 0, WORK(1) renvoie la valeur optimale de LWORK.
!>

LWORK

!>          LWORK est INTEGER
!>          La dimension du tableau WORK.  LWORK >= max(1,2*N).
!>          Pour de bonnes performances, LWORK doit généralement être plus grand.
!>
!>          Si LWORK = -1, une interrogation d'espace de travail est supposée ; la routine
!>          ne calcule que la taille optimale du tableau WORK, renvoie
!>          cette valeur comme première entrée du tableau WORK, et aucun message
!>          d'erreur lié à LWORK n'est émis par XERBLA.
!>

RWORK

!>          RWORK est un tableau REAL, dimension (8*N)
!>

INFO

!>          INFO est INTEGER
!>          = 0 :  sortie réussie
!>          < 0 :  si INFO = -i, le i-ème argument avait une valeur illégale.
!>          =1,...,N :
!>                L'itération QZ a échoué.  Aucun vecteur propre n'a été
!>                calculé, mais ALPHA(j) et BETA(j) devraient être
!>                corrects pour j=INFO+1,...,N.
!>          > N :  =N+1 : autre échec que l'itération QZ dans CHGEQZ,
!>                =N+2 : retour d'erreur de CTGEVC.
!>

    Nom

    cggev - Algorithme généralisé des valeurs propres pour les matrices complexes générales.

    Synopsis

    subroutine cggev(jobvl, jobvr, n, a, lda, b, ldb, alphar, alphai, beta, vl, ldvl, vr, ldvr, work, lwork, rwork, info)

    Description

    cggev calcule les valeurs propres généralisées et, optionnellement, les vecteurs propres à gauche et à droite pour deux matrices complexes générales $A$ et $B$.

    Le problème des valeurs propres généralisées est de trouver des scalaires $\alpha$ et $\beta$, non tous deux nuls, tels que $A \mathbf{x} = \beta B \mathbf{x}$ pour les vecteurs propres à droite $\mathbf{x}$, ou $\mathbf{y}^H A = \beta \mathbf{y}^H B$ pour les vecteurs propres à gauche $\mathbf{y}$.

    La routine transforme d'abord le problème en un problème de valeurs propres standard $C z = \lambda D z$ en appliquant des transformations unitaires à gauche et à droite sur $A$ et $B$. Ensuite, elle calcule les valeurs propres et les vecteurs propres de cette nouvelle matrice.

    Arguments

    • jobvl (character) : Indique s'il faut calculer les vecteurs propres à gauche.
      - 'N' : Les vecteurs propres à gauche ne sont pas calculés.
      - 'V' : Les vecteurs propres à gauche sont calculés.
    • jobvr (character) : Indique s'il faut calculer les vecteurs propres à droite.
      - 'N' : Les vecteurs propres à droite ne sont pas calculés.
      - 'V' : Les vecteurs propres à droite sont calculés.
    • n (integer) : La taille de la matrice (nombre de lignes et de colonnes).
    • a (complex*16) : Matrice d'entrée complexe de taille $N \times N$.
    • lda (integer) : Le premier indice de dimension de la matrice a.
    • b (complex*16) : Matrice d'entrée complexe de taille $N \times N$.
    • ldb (integer) : Le premier indice de dimension de la matrice b.
    • alphar (double precision) : Tableau de taille N. Les parties réelles des valeurs propres $\alpha$.
    • alphai (double precision) : Tableau de taille N. Les parties imaginaires des valeurs propres $\alpha$.
    • beta (double precision) : Tableau de taille N. Les valeurs $\beta$. Les valeurs propres généralisées sont $\alpha_i / \beta_i$. Si $\beta_i=0$, la valeur propre est infinie.
    • vl (complex*16) : Tableau de taille LDVL $\times$ N (si jobvl='V'). Si jobvl='V', vl contient les vecteurs propres à gauche unitaires, où le $i$-ème vecteur colonne $vl( :, i )$ est normalisé de telle sorte que $\sum_{j=1}^N |vl(j,i)|^2 = 1$.
    • ldvl (integer) : Le premier indice de dimension de la matrice vl.
    • vr (complex*16) : Tableau de taille LDVR $\times$ N (si jobvr='V'). Si jobvr='V', vr contient les vecteurs propres à droite unitaires, où le $i$-ème vecteur colonne $vr( :, i )$ est normalisé de telle sorte que $\sum_{j=1}^N |vr(j,i)|^2 = 1$.
    • ldvr (integer) : Le premier indice de dimension de la matrice vr.
    • work (complex*16) : Tableau de travail de taille LWORK.
    • lwork (integer) : La dimension du tableau work. La valeur optimale est calculée par cggev si lwork=-1.
    • rwork (double precision) : Tableau de travail réel de taille $8N$.
    • info (integer) : Indicateur de sortie.
      - 0 : Exécution réussie.
      - < 0 : Si info = -i, alors l'i-ème argument n'a pas une valeur valide.
      - > 0 : Si info = i, alors la factorisation QR de la matrice $B$ au rang i n'a pas réussi. Le problème peut ne pas avoir de solution.

    Utilisation

    Exemple d'utilisation de cggev :

        PROGRAM EXAMPLE_CGGEV
        IMPLICIT NONE

        INTEGER :: N, LDA, LDB, LDVL, LDVR, LWORK, INFO
        COMPLEX*16 :: A(3,3), B(3,3), VL(3,3), VR(3,3)
        DOUBLE PRECISION :: ALPHAR(3), ALPHAI(3), BETA(3), RWORK(24)
        COMPLEX*16 :: WORK(100)

        ! Initialisation des matrices A et B
        A = ...
        B = ...

        N = 3
        LDA = 3
        LDB = 3
        LDVL = 3
        LDVR = 3

        ! Détermination de la taille optimale de LWORK
        LWORK = -1
        CALL CGGEV('V', 'V', N, A, LDA, B, LDB, ALPHAR, ALPHAI, BETA, VL, LDVL, VR, LDVR, WORK, LWORK, RWORK, INFO)
        LWORK = INT(WORK(1)) ! La taille optimale est retournée dans WORK(1)

        ! Appel de CGGEV pour calculer les valeurs propres et les vecteurs propres
        CALL CGGEV('V', 'V', N, A, LDA, B, LDB, ALPHAR, ALPHAI, BETA, VL, LDVL, VR, LDVR, WORK, LWORK, RWORK, INFO)

        IF (INFO .EQ. 0) THEN
            PRINT *, "Exécution réussie."
            ! Traitement des résultats (valeurs propres et vecteurs propres)
            DO i = 1, N
                PRINT *, "Valeur propre ", i, ": (", ALPHAR(i), " + i*", ALPHAI(i), ") / ", BETA(i)
                PRINT *, "Vecteur propre gauche ", i, ": ", VL(:,i)
                PRINT *, "Vecteur propre droit ", i, ": ", VR(:,i)
            END DO
        ELSE
            PRINT *, "Erreur lors de l'exécution de CGGEV, INFO = ", INFO
        END IF

    END PROGRAM EXAMPLE_CGGEV

    Retour

    Les valeurs propres sont stockées dans les tableaux alphar, alphai et beta. Les vecteurs propres à gauche sont stockés dans la matrice vl et les vecteurs propres à droite dans la matrice vr, si demandés.
