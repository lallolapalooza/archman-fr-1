CGEDMD calcule la Décomposition en Modes Dynamiques (DMD) pour une paire de matrices d'instantanés de

données.

But

: 
!>    CGEDMD calcule la Décomposition en Modes Dynamiques (DMD) pour
!>    une paire de matrices d'instantanés de données. Pour les matrices
!>    d'entrée X et Y telles que Y = A*X avec une matrice A
!>    inaccessible, CGEDMD calcule un certain nombre de paires de Ritz de A en utilisant
!>    l'extraction standard de Rayleigh-Ritz d'un sous-espace de
!>    l'image de X qui est déterminé à l'aide des vecteurs singuliers gauches
!>    principaux de X. En option, CGEDMD renvoie les résidus
!>    des paires de Ritz calculées, les informations nécessaires pour
!>    un raffinement des vecteurs de Ritz, ou les vecteurs propres de
!>    la DMD Exacte.
!>    Pour plus de détails, voir les références listées
!>    ci-dessous. Pour plus de détails sur l'implémentation, voir [3].
!
>

!>        and experimental data,

!>        decompositions: analysis and enhancements,

!>        Dynamics 1(2), 391 -421, 2014.
!

Paramètre

s
JOBS 
!>    JOBS (entrée) CHARACTER*1
!>    Détermine si les instantanés de données initiaux sont mis à l'échelle
!>    par une matrice diagonale.
!>    'S' :: Les matrices d'instantanés de données X et Y sont multipliées
!>           par une matrice diagonale D de sorte que X*D ait des colonnes
!>           non nulles de norme unitaire (dans la 2-norme euclidienne)
!>    'C' :: Les instantanés sont mis à l'échelle comme avec l'option 'S'.
!>           S'il est constaté que la i-ème colonne de X est un vecteur
!>           nul et que la i-ème colonne correspondante de Y est
!>           non nulle, alors la i-ème colonne de Y est mise à
!>           zéro et un indicateur d'avertissement est levé.
!>    'Y' :: Les matrices d'instantanés de données X et Y sont multipliées
!>           par une matrice diagonale D de sorte que Y*D ait des colonnes
!>           non nulles de norme unitaire (dans la 2-norme euclidienne)
!>    'N' :: Pas de mise à l'échelle des données.
!
>

JOB

Z 
!>    JOBZ (entrée) CHARACTER*1
!>    Détermine si les vecteurs propres (modes de Koopman) seront
!>    calculés.
!>    'V' :: Les vecteurs propres (modes de Koopman) seront calculés
!>           et renvoyés dans la matrice Z.
!>           Voir la description de Z.
!>    'F' :: Les vecteurs propres (modes de Koopman) seront renvoyés
!>           sous forme factorisée comme le produit X(:,1:K)*W, où X
!>           contient une base POD (vecteurs singuliers gauches
!>           principaux de la matrice de données X) et W contient les vecteurs propres
!>           du quotient de Rayleigh correspondant.
!>           Voir les descriptions de K, X, W, Z.
!>    'N' :: Les vecteurs propres ne sont pas calculés.
!
>

JOB

R 
!>    JOBR (entrée) CHARACTER*1
!>    Détermine s'il faut calculer les résidus.
!>    'R' :: Les résidus pour les paires propres calculées seront
!>           calculés et stockés dans le tableau RES.
!>           Voir la description de RES.
!>           Pour que cette option soit valide, JOBZ doit être 'V'.
!>    'N' :: Les résidus ne sont pas calculés.
!
>

JOB

F 
!>    JOBF (entrée) CHARACTER*1
!>    Spécifie s'il faut stocker les informations nécessaires pour le post-
!>    traitement (par exemple, le calcul de vecteurs de Ritz raffinés)
!>    'R' :: La matrice nécessaire pour le raffinement des vecteurs
!>           de Ritz est calculée et stockée dans le tableau B.
!>           Voir la description de B.
!>    'E' :: Les vecteurs propres non mis à l'échelle de la DMD Exacte sont
!>           calculés et renvoyés dans le tableau B. Voir la
!>           description de B.
!>    'N' :: Aucune donnée de raffinement de vecteurs propres n'est calculée.
!
>

WHTSV

D 
!>    WHTSVD (entrée) INTEGER, WHSTVD dans { 1, 2, 3, 4 }
!>    Permet la sélection de l'algorithme SVD à partir de la
!>    bibliothèque LAPACK.
!&gt;    1 :: CGESVD (l'algorithme QR SVD)
!>    2 :: CGESDD (l'algorithme Divide and Conquer ; si suffisamment
!>         d'espace de travail est disponible, c'est l'option la plus rapide)
!>    3 :: CGESVDQ (l'algorithme QR SVD préconditionné ; ceci et 4
!>         sont les options les plus précises)
!>    4 :: CGEJSV (l'algorithme Jacobi SVD préconditionné ; ceci et 3
!>         sont les options les plus précises)
!>    Pour les quatre méthodes ci-dessus, une différence significative dans
!>    la précision des petites valeurs singulières est possible si
!>    les snapshots varient en norme de telle sorte que X soit fortement
!>    mal conditionné. Si les petites valeurs singulières (inférieures à EPS*||X||)
!>    sont d'intérêt et que JOBS=='N', alors les options (3, 4) donnent les résultats les plus précis, où
!>    l'option 4 est légèrement meilleure et avec un fondement théorique plus solide.
!>    Si JOBS=='S', c'est-à-dire que les colonnes de X seront normalisées,
!>    alors toutes les méthodes donnent des résultats presque également précis.
!>

M

!>    M (entrée) INTEGER, M>= 0
!>    La dimension de l'espace d'états (la dimension des lignes de X, Y).
!>

N

!>    N (entrée) INTEGER, 0 <= N <= M
!>    Le nombre de paires d'instantanés de données
!>    (le nombre de colonnes de X et Y).
!>

X

!>    X (entrée/sortie) COMPLEX(KIND=WP) tableau M-par-N
!>    > À l'entrée, X contient la matrice d'instantanés de données X. Il est
!>    supposé que les normes des colonnes de X sont dans la plage de
!>    nombres flottants normalisés.
!>    < À la sortie, les K premières colonnes de X contiennent une base POD,
!>    c'est-à-dire les K premiers vecteurs singuliers gauches de la matrice de données d'entrée
!>    X, U(:,1:K). Toutes les N colonnes de X contiennent tous les
!>    vecteurs singuliers gauches de la matrice de données d'entrée X.
!>    Voir les descriptions de K, Z et W.
!>

LDX

!>    LDX (entrée) INTEGER, LDX >= M
!>    La dimension principale du tableau X.
!>

Y

!>    Y (entrée/espace de travail/sortie) COMPLEX(KIND=WP) tableau M-par-N
!>    > À l'entrée, Y contient la matrice d'instantanés de données Y
!>    < À la sortie,
!>    Si JOBR == 'R', les K premières colonnes de Y contiennent
!>    les vecteurs résiduels pour les paires de Ritz calculées.
!>    Voir la description de RES.
!>    Si JOBR == 'N', Y contient les données d'entrée originales,
!>                    normalisées selon la valeur de JOBS.
!>

LDY

!>    LDY (entrée) INTEGER, LDY >= M
!>    La dimension principale du tableau Y.
!>

NRNK

!>    NRNK (entrée) INTEGER
!>    Détermine le mode de calcul du rang numérique,
!>    c'est-à-dire comment tronquer les petites valeurs singulières de la matrice d'entrée
!>    X. À l'entrée, si
!>    NRNK = -1 :: la i-ème valeur singulière sigma(i) est tronquée
!>                 si sigma(i) <= TOL*sigma(1)
!>                 Cette option est recommandée.
!>    NRNK = -2 :: la i-ème valeur singulière sigma(i) est tronquée
!>                 si sigma(i) <= TOL*sigma(i-1)
!>                 Cette option est incluse à des fins de R&D.
!>                 Elle nécessite une SVD très précise, ce qui
!>                 peut ne pas être réalisable.
!>    Le rang numérique peut être imposé en utilisant une valeur positive
!>    de NRNK comme suit :
!>    0 < NRNK <= N :: au plus NRNK plus grandes valeurs singulières
!>    seront utilisées. Si le nombre de valeurs singulières non nulles calculées
!>    est inférieur à NRNK, alors seules ces
!>    valeurs non nulles seront utilisées et la dimension réellement utilisée
!>    sera inférieure à NRNK. Le nombre réel de
!>    valeurs singulières non nulles est retourné dans la variable
!>    K. Voir les descriptions de TOL et K.
!>

TOL

!>    TOL (entrée) REAL(KIND=WP), 0 <= TOL < 1
!>    La tolérance pour tronquer les petites valeurs singulières.
!>    Voir la description de NRNK.
!>

K

!>    K (sortie) INTEGER,  0 <= K <= N
!>    La dimension de la base POD pour la matrice d'instantanés de données
!>    X et le nombre de paires de Ritz calculées.
!>    La valeur de K est déterminée selon la règle définie
!>    par les paramètres NRNK et TOL.
!>    Voir les descriptions de NRNK et TOL.
!>

EIGS

!>    EIGS (sortie) COMPLEX(KIND=WP) tableau N-par-1
!>    Les K premières entrées (K<=N) de EIGS contiennent
!>    les valeurs propres calculées (valeurs de Ritz).
!>    Voir les descriptions de K et Z.
!>

Z

!>    Z (espace de travail/sortie) COMPLEX(KIND=WP) tableau M-par-N
!>    Si JOBZ =='V' alors Z contient les vecteurs de Ritz. Z(:,i)
!>    est un vecteur propre de la i-ème valeur de Ritz ; ||Z(:,i)||_2=1.
!>    Si JOBZ == 'F', alors les Z(:,i) sont donnés implicitement comme
!>    les colonnes de X(:,1:K)*W(1:K,1:K), c'est-à-dire que X(:,1:K)*W(:,i)
!>    est un vecteur propre correspondant à EIGS(i). Les colonnes
!>    de W(1:k,1:K) sont les vecteurs propres calculés du
!>    quotient de Rayleigh K-par-K.
!>    Voir les descriptions de EIGS, X et W.
!>

LDZ

!>    LDZ (entrée) INTEGER, LDZ >= M
!>    La dimension principale du tableau Z.
!>

RES

!>    RES (sortie) REAL(KIND=WP) tableau N-par-1
!>    RES(1:K) contient les résidus pour les K paires de Ritz calculées,
!>    RES(i) = || A * Z(:,i) - EIGS(i)*Z(:,i))||_2.
!>    Voir la description de EIGS et Z.
!>

B

!>    B (sortie) COMPLEX(KIND=WP) tableau M-par-N.
!>    SI JOBF =='R', B(1:M,1:K) contient A*U(:,1:K), et peut
!>    être utilisé pour calculer les vecteurs affinés ; voir plus de
!>    détails dans les références fournies.
!>    Si JOBF == 'E', B(1:M,1:K) contient
!>    A*U(:,1:K)*W(1:K,1:K), qui sont les vecteurs de l'Exact DMD,
!>    à l'échelle près par l'inverse des valeurs propres.
!>    Si JOBF =='N', alors B n'est pas référencé.
!>    Voir les descriptions de X, W, K.
!>

LDB

!>    LDB (entrée) INTEGER, LDB >= M
!>    La dimension principale du tableau B.
!>

W

!>    W (espace de travail/sortie) COMPLEX(KIND=WP) tableau N-par-N
!>    À la sortie, W(1:K,1:K) contient les K vecteurs propres calculés
!>    du quotient de Rayleigh matriciel.
!>    Les vecteurs de Ritz (retournés dans Z) sont le
!>    produit de X (contenant une base POD pour la matrice d'entrée
!>    X) et W. Voir les descriptions de K, S, X et Z.
!>    W est également utilisé comme espace de travail pour stocker temporairement
!>    les vecteurs singuliers droits de X.
!>

LDW

!>    LDW (entrée) INTEGER, LDW >= N
!>    La dimension principale du tableau W.
!>

S

!>    S (espace de travail/sortie) COMPLEX(KIND=WP) tableau N-par-N
!>    Le tableau S(1:K,1:K) est utilisé pour le quotient de Rayleigh matriciel.
!>    Son contenu est écrasé pendant
!>    la décomposition en valeurs propres par CGEEV.
!>    Voir la description de K.
!>

LDS

!>    LDS (entrée) INTEGER, LDS >= N
!>    La dimension principale du tableau S.
!>

ZWORK

!>    ZWORK (espace de travail/sortie) COMPLEX(KIND=WP) tableau LZWORK-par-1
!>    ZWORK est utilisé comme espace de travail complexe dans la SVD complexe, comme
!>    spécifié par WHTSVD (1,2, 3 ou 4) et pour CGEEV pour le calcul
!>    des valeurs propres d'un quotient de Rayleigh.
!>    Si l'appel à CGEDMD est une simple requête d'espace de travail, alors
!>    ZWORK(1) contient la longueur minimale de l'espace de travail complexe et
!>    ZWORK(2) est la longueur optimale de l'espace de travail complexe.
!>    Par conséquent, la longueur de work est au moins de 2.
!>    Voir la description de LZWORK.
!>

LZWORK

!>    LZWORK (entrée) INTEGER
!>    La longueur minimale du tableau d'espace de travail ZWORK.
!>    LZWORK est calculé comme MAX(LZWORK_SVD, LZWORK_CGEEV),
!>    où LZWORK_CGEEV = MAX( 1, 2*N )  et la longueur minimale
!>    LZWORK_SVD est calculée comme suit :
!>    Si WHTSVD == 1 :: CGESVD ::
!>       LZWORK_SVD = MAX(1,2*MIN(M,N)+MAX(M,N))
!>    Si WHTSVD == 2 :: CGESDD ::
!>       LZWORK_SVD = 2*MIN(M,N)*MIN(M,N)+2*MIN(M,N)+MAX(M,N)
!>    Si WHTSVD == 3 :: CGESVDQ ::
!>       LZWORK_SVD = obtenable par une requête
!>    Si WHTSVD == 4 :: CGEJSV ::
!>       LZWORK_SVD = obtenable par une requête
!>    Si à l'entrée LZWORK = -1, alors une requête d'espace de travail est
!>    supposée et la procédure calcule uniquement les longueurs minimale
!>    et optimale de l'espace de travail et les retourne dans
!>    LZWORK(1) et LZWORK(2), respectivement.
!>

RWORK

!>    RWORK (espace de travail/sortie) REAL(KIND=WP) tableau LRWORK-par-1
!>    À la sortie, RWORK(1:N) contient les valeurs singulières de
!>    X (pour JOBS=='N') ou de X mis à l'échelle des colonnes (JOBS=='S', 'C').
!>    Si WHTSVD==4, alors RWORK(N+1) et RWORK(N+2) contiennent
!>    le facteur de mise à l'échelle RWORK(N+2)/RWORK(N+1) utilisé pour mettre à l'échelle X
!>    et Y afin d'éviter le dépassement dans la SVD de X.
!>    Cela peut être intéressant si l'option de mise à l'échelle est désactivée
!>    et que le plus grand nombre possible de plus petites valeurs propres est
!>    souhaité avec la plus haute précision réalisable.
!>    Si l'appel à CGEDMD est une simple requête d'espace de travail, alors
!>    RWORK(1) contient la longueur minimale de l'espace de travail.
!>    Voir la description de LRWORK.
!>

LRWORK

!>    LRWORK (entrée) INTEGER
!>    La longueur minimale du tableau d'espace de travail RWORK.
!>    LRWORK est calculé comme suit :
!>    LRWORK = MAX(1, N+LRWORK_SVD,N+LRWORK_CGEEV), où
!>    LRWORK_CGEEV = MAX(1,2*N) et RWORK_SVD est l'espace de travail réel
!>    pour la sous-routine SVD déterminée par le paramètre d'entrée
!>    WHTSVD.
!>    Si WHTSVD == 1 :: CGESVD ::
!>       LRWORK_SVD = 5*MIN(M,N)
!>    Si WHTSVD == 2 :: CGESDD ::
!>       LRWORK_SVD =  MAX(5*MIN(M,N)*MIN(M,N)+7*MIN(M,N),
!>       2*MAX(M,N)*MIN(M,N)+2*MIN(M,N)*MIN(M,N)+MIN(M,N) ) )
!>    Si WHTSVD == 3 :: CGESVDQ ::
!>       LRWORK_SVD = obtenable par une requête
!>    Si WHTSVD == 4 :: CGEJSV ::
!>       LRWORK_SVD = obtenable par une requête
!>    Si à l'entrée LRWORK = -1, alors une requête d'espace de travail est
!>    supposée et la procédure calcule uniquement la longueur minimale
!>    de l'espace de travail réel et la retourne dans RWORK(1).
!>

IWORK

!>    IWORK (espace de travail/sortie) INTEGER tableau LIWORK-par-1
!>    Espace de travail requis uniquement si WHTSVD est égal à
!>    2 , 3 ou 4. (Voir la description de WHTSVD).
!>    Si à l'entrée LWORK =-1 ou LIWORK=-1, alors la
!>    longueur minimale de IWORK est calculée et retournée dans
!>    IWORK(1). Voir la description de LIWORK.
!>

LIWORK

!>    LIWORK (entrée) INTEGER
!>    La longueur minimale du tableau d'espace de travail IWORK.
!>    Si WHTSVD == 1, alors seul IWORK(1) est utilisé ; LIWORK >=1
!>    Si WHTSVD == 2, alors LIWORK >= MAX(1,8*MIN(M,N))
!>    Si WHTSVD == 3, alors LIWORK >= MAX(1,M+N-1)
!>    Si WHTSVD == 4, alors LIWORK >= MAX(3,M+3*N)
!>    Si à l'entrée LIWORK = -1, alors une requête d'espace de travail est
!>    supposée et la procédure calcule uniquement les longueurs minimale
!>    et optimale pour ZWORK, RWORK et
!>    IWORK. Voir les descriptions de ZWORK, RWORK et IWORK.
!>

INFO

!>    INFO (sortie) INTEGER
!>    -i < 0 :: À l'entrée, le i-ème argument avait une
!>              valeur illégale
!>       = 0 :: Retour réussi.
!>       = 1 :: Entrée vide. Sortie rapide (M=0 ou N=0).
!>       = 2 :: Le calcul de SVD de X n'a pas convergé.
!>
Suggestion : Vérifier les données d'entrée et/ou !> répéter avec un WHTSVD différent. !> = 3 :: Le calcul des valeurs propres n'a pas !> convergé. !> = 4 :: Si la mise à l'échelle des données a été demandée en entrée et !> que la procédure a trouvé une incohérence dans les données !> telle que pour un certain indice de colonne i, !> X(:,i) = 0 mais Y(:,i) /= 0, alors Y(:,i) est mis !> à zéro si JOBS=='C'. Le calcul se poursuit !> avec les données originales ou modifiées et le !> drapeau d'avertissement est défini avec INFO=4. !
>
