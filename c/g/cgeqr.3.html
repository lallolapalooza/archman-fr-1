sous-programme cgeqr (integer m, integer n, complex, dimension( lda, * ) a, integer lda, complex, dimension( * ) t, integer tsize, complex, dimension( * ) work, integer lwork, integer info)

CGEQR

Objectif :

!>
!> CGEQR calcule une factorisation QR d'une matrice complexe M par N A :
!>
!>    A = Q * ( R ),
!>            ( 0 )
!>
!> où :
!>
!>    Q est une matrice orthogonale M par M ;
!>    R est une matrice triangulaire supérieure N par N ;
!>    0 est une matrice nulle (M-N) par N, si M > N.
!>
!>

Paramètres

M 
!>          M est un entier
!>          Le nombre de lignes de la matrice A.  M >= 0.
!>

N

!>          N est un entier
!>          Le nombre de colonnes de la matrice A.  N >= 0.
!>

A

!>          A est un tableau de type COMPLEX, dimension (LDA,N)
!>          À l'entrée, la matrice M par N A.
!>          En sortie, les éléments sur et au-dessus de la diagonale du tableau
!>          contiennent la matrice trapézoïdale supérieure R de dimension min(M,N) par N
!>          (R est triangulaire supérieure si M >= N) ;
!>          les éléments en dessous de la diagonale sont utilisés pour stocker une partie de la 
!>          structure de données représentant Q.
!>

LDA

!>          LDA est un entier
!>          La dimension principale du tableau A.  LDA >= max(1,M).
!>

T

!>          T est un tableau de type COMPLEX, dimension (MAX(5,TSIZE))
!>          En sortie, si INFO = 0, T(1) contient la dimension TSIZE optimale (ou minimale ou optimale,
!>          si une requête est supposée). Voir TSIZE pour les détails.
!>          Le reste de T contient une partie de la structure de données utilisée pour représenter Q.
!>          Si l'on veut appliquer ou construire Q, il faut conserver T 
!>          (en plus de A) et le passer à d'autres sous-programmes.
!>

TSIZE

!>          TSIZE est un entier
!>          Si TSIZE >= 5, la dimension du tableau T.
!>          Si TSIZE = -1 ou -2, alors une requête d'espace de travail est supposée. La routine
!>          calcule uniquement les dimensions des tableaux T et WORK, renvoie ces
!>          valeurs comme premières entrées des tableaux T et WORK, et aucun message d'erreur
!>          concernant T ou WORK n'est émis par XERBLA.
!>          Si TSIZE = -1, la routine calcule la taille optimale de T pour
!>          une performance optimale et renvoie cette valeur dans T(1).
!>          Si TSIZE = -2, la routine calcule la taille minimale de T et 
!>          renvoie cette valeur dans T(1).
!>

WORK

!>          (espace de travail) Tableau de type COMPLEX, dimension (MAX(1,LWORK))
!>          En sortie, si INFO = 0, WORK(1) contient la dimension LWORK optimale (ou minimale ou optimale,
!>          si une requête a été supposée).
!>          Voir LWORK pour les détails.
!>

LWORK

!>          LWORK est un entier
!>          La dimension du tableau WORK. LWORK >= 1.
!>          Si LWORK = -1 ou -2, alors une requête d'espace de travail est supposée. La routine
!>          calcule uniquement les dimensions des tableaux T et WORK, renvoie ces
!>          valeurs comme premières entrées des tableaux T et WORK, et aucun message d'erreur
!>          concernant T ou WORK n'est émis par XERBLA.
!>          Si LWORK = -1, la routine calcule la taille optimale de WORK pour
!>          une performance optimale et renvoie cette valeur dans WORK(1).
!>          Si LWORK = -2, la routine calcule la taille minimale de WORK et 
!>          renvoie cette valeur dans WORK(1).
!>

INFO

!>          INFO est un entier
!>          = 0 : sortie réussie
!>          < 0 : si INFO = -i, le i-ème argument était invalide
!>

Détails supplémentaires

!>
!> L'objectif de l'interface est de donner une liberté maximale aux développeurs pour
!> créer tout algorithme de factorisation QR qu'ils souhaitent. La matrice triangulaire 
!> (trapézoïdale) R doit être stockée dans la partie supérieure de A. La partie inférieure de A
!> et le tableau T peuvent être utilisés pour stocker toute information pertinente pour appliquer ou
!> construire le facteur Q. Le tableau WORK peut être ignoré en toute sécurité après la sortie.
!>
!> Attention : Il ne faut pas s'attendre à ce que les tailles de T et WORK soient les mêmes d'une
!> implémentation LAPACK à l'autre, ni même d'une exécution à l'autre.
!> Une requête d'espace de travail (pour T et WORK) est nécessaire à chaque exécution. Cependant, 
!> pour une exécution donnée, la taille de T et WORK est fixe et ne changera pas
!> d'une requête à l'autre.
!>
!>

Détails supplémentaires propres à cette implémentation LAPACK :

!>
!> Ces détails sont spécifiques à cette implémentation LAPACK. Les utilisateurs ne doivent pas
!> les considérer comme acquis. Ces détails peuvent changer à l'avenir, et ne sont probablement pas
!> vrais pour une autre implémentation LAPACK. Ces détails sont pertinents si l'on souhaite
!> essayer de comprendre le code. Ils ne font pas partie de l'interface.
!>
!> Dans cette version,
!>
!>          T(2) : taille de bloc de lignes (MB)
!>          T(3) : taille de bloc de colonnes (NB)
!>          T(6:TSIZE) : structure de données nécessaire pour Q, calculée par
!>                           CLATSQR ou CGEQRT
!>
!>  Selon les dimensions de la matrice M et N, et les tailles de bloc de lignes et de colonnes
!>  MB et NB renvoyées par ILAENV, CGEQR utilisera soit
!>  CLATSQR (si la matrice est longue et étroite) soit CGEQRT pour calculer
!>  la factorisation QR.
!>
!>
