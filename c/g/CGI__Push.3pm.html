DESCRIPTIO

N

CGI::Push est une sous-classe de l'objet CGI créé par CGI.pm. Elle est spécialisée pour les opérations de push serveur, qui vous permettent de créer des pages animées dont le contenu change à intervalles

réguliers.

Vous fournissez à CGI::Push un pointeur vers une sous-routine qui dessinera une page. Chaque fois que votre sous-routine est appelée, elle génère une nouvelle page. Le contenu de la page sera transmis au navigateur de telle manière qu'il remplacera ce qui s'y trouvait auparavant. La technique fonctionnera avec les pages HTML ainsi qu'avec les fichiers graphiques, vous permettant de créer des GIF

animés.

n charge le push serveur. Intern
et Explorer ne le fait pas.

UTILISATION DE CGI::

Push

CGI::Push ajoute une nouvelle méthode à la suite standard de CGI, do_push(). Lorsque vous appelez cette méthode, vous lui transmettez une référence vers une sous-routine responsable du dessin de chaque nouvelle page, un délai d'intervalle, et une sous-routine facultative pour dessiner la dernière page. Les autres paramètres facultatifs incluent la plupart de ceux reconnus par la méthode header() de

CGI.

Vous pouvez appeler do_push() de manière orientée objet ou non, selon votre préférence

: 
use CGI::Push;
$q = CGI::Push->new;
$q->do_push(-next_page=>\&draw_a_page);
    -ou-
use CGI::Push qw(:standard);
do_push(-next_page=>\&draw_a_page)
;

La sous-routine doit s'attendre à deux paramètres consistant en l'objet CGI et un compteur indiquant le nombre de fois que la sous-routine a été appelée. Elle doit retourner le contenu de la page sous forme d'un tableau d'un ou plusieurs éléments à imprimer. Elle peut retourner une valeur fausse (ou un tableau vide) afin d'interrompre la boucle de redessinage et d'imprimer la page finale (s'il

Pages

hétérogènes

Ordinairement, toutes les pages affichées par CGI::Push partagent un type MIME commun. Cependant, en fournissant la valeur "heterogeneous" ou "dynamic" dans le paramètre -type de do_push(), vous pouvez spécifier le type MIME de chaque page au cas par

cas.

Si vous utilisez cette option, vous serez responsable de produire l' en-tête HTTP pour chaque page. Modifiez simplement votre routine de dessin pour qu'elle ressemble à ceci

: 
sub my_draw_routine {
    my($q,$counter) = @_;
    return header('text/html'),   # notez que nous produisons l'en-tête ici
    ....
}

Vous pouvez ajouter les champs d'en-tête que vous voulez, mais certains (y compris les cookies et les champs de statut) peuvent ne pas être interprétés par le navigateur. Un effet intéressant est d'afficher une série de pages, puis, après la dernière page, de rediriger le navigateur vers une nouvelle URL. Parce que redirect() ne b<fonctionne> pas, la façon la plus simple est avec un champ d'en-tête -refresh, comme montré ci-dessous

: 
sub my_draw_routine {
    my($q,$counter) = @_;
    return undef if $counter > 10;
    return header('text/html'),   # notez que nous produisons l'en-tête ici
    ...
}
sub my_last_page {
    return header(-refresh=>'5; URL=http://somewhere.else/finished.html',
                  -type=>'text/html'),
    ...
}

Le délai peut être fractionnaire. Sans paramètres, push_delay() retourn

INSTALLATION DES SCRIPTS CGI::

Push

Les scripts de push serveur doivent être installés comme scripts no-parsed-header (NPH) afin de fonctionner correctement sur de nombreux serveurs. Sur les systèmes Unix, cela est le plus souvent accompli en préfixant le nom du script avec "nph-". La reconnaissance des scripts NPH se fait automatiquement avec WebSTAR et Microsoft IIS. Les utilisateurs d'autres serveurs doivent consulter leur documentation pour obtenir de

l'aide.

Le serveur web Apache à partir de la version 1.3b2 n'a pas besoin que les scripts de push serveur soient installés comme scripts NPH : le paramètre -nph de do_push() peut être défini à une valeur fausse pour désactiv

er les en-têtes supplémentaires
nécessaires à un script NPH.
