CGI::HTML::Functions(3) Documentation Perl contribuée par les utilisateurs CGI::HTML::Functions(3)

NOM

CGI::HTML::Functions - Documentation pour les fonctionnalités HTML héritées de CGI.pm

SYNOPSIS

Rien ici - veuillez ne pas utiliser cette fonctionnalité, elle est considérée comme héritée et essentiellement dépréciée. Cette documentation existe uniquement pour aider à la maintenance et à la migration du code hérité utilisant cette fonctionnalité et il vous est fortement recommandé de migrer vers autre chose. Si vous travaillez sur du nouveau code, vous devriez utiliser un moteur de gabarits. Pour plus d'informations, voir CGI::Alternatives.

Si vous voulez vraiment continuer à utiliser la fonctionnalité de génération HTML de CGI.pm, alors vous devriez plutôt jeter un œil à HTML::Tiny, qui peut vous offrir une voie de migration loin des fonctions de génération HTML de CGI.pm ; je vous encourage vivement à vous orienter vers la génération de pages pilotée par des gabarits pour tout ce qui implique du balisage, car cela rendra le portage de votre application vers d'autres frameworks beaucoup plus facile à long terme.

DESCRIPTION

La documentation ici doit être considérée comme un supplément aux sections de la documentation CGI - les sections ici portent les mêmes noms que celles du perldoc CGI.

Appel des routines de CGI.pm

Les fonctions de balises HTML ont à la fois des attributs (les paires attribute="value" à l'intérieur de la balise elle-même) et un contenu (la partie entre les paires d'ouverture et de fermeture). Pour distinguer les attributs du contenu, CGI.pm utilise la convention de passer les attributs HTML sous forme de référence de hachage en premier argument, et le contenu, s'il y en a, en arguments suivants. Cela fonctionne comme ceci :

Code                           HTML généré
----                           --------------
h1()                           <h1 />
h1('quelques','contenus');     <h1>quelques contenus</h1>
h1({-align=>left});            <h1 align="LEFT">
h1({-align=>left},'contenus'); <h1 align="LEFT">contenus</h1>

Beaucoup de nouveaux utilisateurs de CGI.pm sont déconcertés par la différence entre les conventions d'appel des raccourcis HTML, qui exigent des accolades autour des attributs de balises HTML, et les conventions d'appel des autres routines, qui parviennent à générer des attributs sans les accolades. Ne soyez pas confus. Par commodité, les accolades sont facultatives partout sauf dans les raccourcis HTML. Si vous le souhaitez, vous pouvez utiliser des accolades lors de l'appel de n'importe quelle routine qui prend des arguments nommés. Par exemple :

print $q->header( { -type => 'image/gif', -expires => '+3d' } );

Si vous utilisez les avertissements, vous serez averti que certains noms d'arguments de CGI.pm entrent en conflit avec les fonctions perl intégrées. Le plus fréquent de ceux-ci est l'argument -values, utilisé pour créer des menus à valeurs multiples, des groupes de boutons radio et ainsi de suite. Pour contourner cet avertissement, vous avez plusieurs choix :

1.
Utilisez un autre nom pour l'argument, si un est disponible. Par exemple, -value est un alias pour -values.
2.
Changez la casse, par exemple -Values
3.
Mettez des guillemets autour du nom de l'argument, par exemple '-values'

Exports de l'interface orientée fonction HTML

Voici une liste des ensembles de fonctions liées à HTML que vous pouvez importer :

:form
Importe toutes les méthodes de génération de formulaires à remplir, telles que textfield().
:html2
Importe toutes les méthodes qui génèrent des éléments standard HTML 2.0.
:html3
Importe toutes les méthodes qui génèrent des éléments HTML 3.0 (tels que <table>, <super> et <sub>).
:html4
Importe toutes les méthodes qui génèrent des éléments HTML 4 (tels que <abbrev>, <acronym> et <thead>).
:netscape
Importe les balises <blink>, <fontsize> et <center>.
:html
Importe tous les raccourcis de génération HTML (c'est-à-dire 'html2', 'html3', 'html4' et 'netscape')
:standard
Importe les fonctionnalités "standard", 'html2', 'html3', 'html4', 'ssl', 'form' et 'cgi'.

Si vous importez l'une des méthodes CGI de maintien d'état ou de génération de formulaires, un objet CGI par défaut sera créé et initialisé automatiquement la première fois que vous utiliserez l'une des méthodes qui nécessitent sa présence. Cela inclut param(), textfield(), submit() et ainsi de suite. (Si vous avez besoin d'un accès direct à l'objet CGI, vous pouvez le trouver dans la variable globale $CGI::Q).

Pragmas

Pragmas supplémentaires liés à la génération HTML :

-nosticky
Par défaut, le module CGI implémente un comportement de préservation d'état appelé champs "collants" (sticky). Le principe est que si vous régénérez un formulaire, les méthodes qui génèrent les valeurs des champs de formulaire interrogeront param() pour voir si des paramètres de même nom sont présents dans la chaîne de requête. S'ils trouvent un paramètre de même nom, ils l'utiliseront pour définir leurs valeurs par défaut.

Parfois, ce n'est pas ce que vous voulez. Le pragma -nosticky empêche ce comportement. Vous pouvez également modifier sélectivement le comportement collant dans chaque élément que vous générez.

-tabindex
Ajoute automatiquement des attributs d'index de tabulation à chaque champ de formulaire. Avec cette option désactivée, vous pouvez toujours ajouter des index de tabulation manuellement en passant une option -tabindex à chaque méthode de génération de champ.
-no_xhtml
Par défaut, les versions 2.69 et supérieures de CGI.pm émettent du XHTML (http://www.w3.org/TR/xhtml1/). Le pragma -no_xhtml désactive cette fonctionnalité. Merci à Michalis Kabrianis <kabrianis@hellug.gr> pour cette fonctionnalité.

Si start_html()'s paramètre -dtd spécifie un DTD HTML 2.0, 3.2, 4.0 ou 4.01, XHTML sera automatiquement désactivé sans avoir besoin d'utiliser ce pragma.

Formes spéciales pour importer des fonctions de balises HTML

Beaucoup des méthodes génèrent des balises HTML. Comme décrit ci-dessous, les fonctions de balises génèrent automatiquement à la fois la balise d'ouverture et la balise de fermeture. Par exemple :

Cette méthode retourne un en-tête HTML prédéfini et la balise d'ouverture <body>. Tous les paramètres sont facultatifs. CRÉATION D'ÉLÉMENTS HTML STANDARD

:

CGI.pm définit des méthodes de raccourci HTML générales pour de nombreuses balises HTML. Les raccourcis HTML sont nommés d'après un seul élément HTML et renvoient un fragment de texte HTML. Exemple

: 
print $q->blockquote(
                  "Many years ago on the island of",
                  $q->a({href=>"http://crete.org/"},"Crete"),
                  "there lived a Minotaur named",
                  $q->strong("Fred."),
                 ),
    $q->
hr;

Cela produit le code HTML suivant (des sauts de ligne supplémentaires ont été ajoutés pour la lisibilité)

: 
<blockquote>
Many years ago on the island of
<a href="http://crete.org/">Crete</a> there lived
a minotaur named <strong>Fred.</strong> 
</blockquote>
<hr>

Si vous trouvez la syntaxe d'appel des raccourcis HTML peu pratique, vous pouvez les importer dans votre espace de noms et vous passer complètement de la syntaxe objet (voir la section suivante pour plus de détails)

: 
use CGI ':standard';
print blockquote(
   "Many years ago on the island of",
   a({href=>"http://crete.org/"},"Crete"),
   "there lived a minotaur named",
   strong("Fred."),
   ),
hr;

Fournir des arguments aux raccourcis

HTML

Les méthodes HTML acceptent zéro, un ou plusieurs arguments. Si vous ne fournissez aucun argument, vous obtenez une balise unique

: 
print hr;    #
<hr>

Si vous fournissez un ou plusieurs arguments de chaîne, ils sont concaténés ensemble avec des espaces et placés entre les balises d'ouverture et de fermeture

: 
print h1("Chapter","1"); # <h1>Chapter 1</h1>
"

Si le premier argument est une référence de hachage, alors les clés et les valeurs du hachage deviennent les attributs de la balise HTML

: 
print a({-href=>'fred.html',-target=>'_new'},
   "Open a new frame");
         <a href="fred.html",target="_new">Open a new
frame</a>

Vous pouvez vous passer des tirets devant les noms d'attributs si vous préférez

: 
print img {src=>'fred.gif',align=>'LEFT'};
        <img align="LEFT" src="fred.
gif">

Parfois, un attribut de balise HTML n'a pas d'argument. Par exemple, les listes ordonnées peuvent être marquées comme COMPACT. La syntaxe pour cela est un argument qui pointe vers une chaîne undef

print ol({compact=>undef},li('one'),li('two'),li('three'))
;

Avant la version 2.41 de CGI.pm, fournir une chaîne vide ('') comme argument d'attribut était équivalent à fournir undef. Cependant, cela a changé pour accommoder ceux qui veulent créer des balises de la forme <img alt="">. La différence est montrée dans ces deux morceaux de code

stributive des

L'une des caractéristiques cool des raccourcis HTML est qu'ils sont distributifs. Si vous leur donnez un argument constitué

d'une

référence vers une liste, la balise sera distribuée à travers chaque élément de la liste. Par exemple, voici une manière de faire une liste ordonnée

  <li type="disc">Doc</li>
  <li type="disc">Sleepy</li>

Ceci est extrêmement utile pour créer des tableaux. Par exemple :

        caption('When Should You Eat Your Vegetables?'),
        Tr({-align=>'CENTER',-valign=>'TOP'},
        [
           th(['Vegetable', 'Breakfast','Lunch','Dinner']),
           td(['Tomatoes' , 'no', 'yes', 'yes']),
           td(['Broccoli' , 'no', 'no',  'yes']),
           td(['Onions'   , 'yes','yes', 'yes'])

Raccourcis HTML et interpolation de listes

Considérez ce bout de code :

print blockquote(em('Hi'),'mom!'));

Il renverra habituellement la chaîne que vous vous attendez probablement à obtenir, à savoir :

<blockquote><em>Hi</em> mom!</blockquote>

Notez l'espace entre l'élément "Hi" et l'élément "mom!". CGI.pm ajoute cet espace supplémentaire en utilisant l'interpolation de tableau, qui est contrôlée par la variable magique $" . Parfois, cet espace supplémentaire n'est pas ce que vous voulez, par exemple, lorsque vous essayez d'aligner une série d'images. Dans ce cas, vous pouvez simplement changer la valeur de $" en une chaîne vide.

{
   local($") = '';
   print blockquote(em('Hi'),'mom!'));
 }

Je vous suggère de mettre le code dans un bloc comme montré ici. Sinon, la modification de $" affectera tout le code suivant jusqu'à ce que vous la réinitialisiez explicitement.

Raccourcis HTML non standard

Quelques balises HTML ne suivent pas le motif standard pour diverses raisons.

comment() génère un commentaire HTML (<!-- comment -->). Appelez-le comme ceci :

print comment('here is my comment');

En raison de conflits avec les fonctions perl intégrées, les fonctions suivantes commencent par une majuscule :

Select
Tr
Link
Delete
Accept
Sub

De plus, start_html(), end_html(), start_form(), end_form(), start_multipart_form() et toutes les balises de formulaire à remplir sont spéciales. Voir leurs sections respectives.

Échappement automatique HTML

Par défaut, tout le HTML émis par les fonctions de génération de formulaires passe par une fonction appelée escapeHTML():

$escaped_string = escapeHTML("unescaped string");
Échappe les caractères de formatage HTML dans une chaîne. En interne, cela appelle HTML::Entities (encode_entities), donc vous devriez vraiment utiliser cela à la place - la liste par défaut des caractères qui seront encodés (passée à la méthode encode_entities de HTML::Entities) est : 
& < > " \x8b \x9b '

vous pouvez contrôler cette liste en définissant la valeur de $CGI::ENCODE_ENTITIES :

# only encode < >
$CGI::ENCODE_ENTITIES = q{<>}

si vous voulez encoder toutes les entités, alors mettez undef $CGI::ENCODE_ENTITIES :

# encode all entities
$CGI::ENCODE_ENTITIES = undef;

L'échappement automatique ne s'applique pas aux autres raccourcis, tels que h1(). Vous devriez appeler escapeHTML() vous-même sur des données non fiables afin de protéger vos pages contre les mauvais tours que les gens peuvent entrer dans les livres d'or, etc.. Pour changer le jeu de caractères, utilisez charset(). Pour désactiver complètement l'échappement automatique, utilisez autoEscape(0):

$charset = charset([$charset]);
Récupère ou définit le jeu de caractères actuel.
$flag = autoEscape([$flag]);
Récupère ou définit la valeur du drapeau d'échappement automatique.

CRÉATION DE FORMULAIRES À REMPLIR :

Note générale Les différentes méthodes de création de formulaire renvoient toutes des chaînes à l'appelant, contenant la ou les balises qui créeront l'élément de formulaire demandé. C'est à vous d'imprimer réellement ces chaînes. C'est configuré de cette manière pour que vous puissiez placer des balises de mise en forme autour des éléments de formulaire.

Autre note Les valeurs par défaut que vous spécifiez pour les formulaires ne sont utilisées que la première fois que le script est invoqué (quand il n'y a pas de chaîne de requête). Lors des invocations ultérieures du script (quand il y a une chaîne de requête), les anciennes valeurs sont utilisées même si elles sont vides.

Si vous voulez changer la valeur d'un champ par rapport à sa valeur précédente, vous avez deux choix :

(1) appelez la méthode param() pour la définir.

(2) utilisez le paramètre -override (alias -force) (une nouvelle fonctionnalité dans la version 2.15). Cela force l'utilisation de la valeur par défaut, quelle que soit la valeur précédente :

print textfield(-name=>'field_name',
                        -default=>'starting value',
                        -override=>1,
                        -size=>50,
                        -maxlength=>80);

Encore une autre note Par défaut, le texte et les libellés des éléments de formulaire sont échappés selon les règles HTML. Cela signifie que vous pouvez utiliser "<CLICK ME>" en toute sécurité comme libellé pour un bouton. Cependant, cela interfère également avec votre capacité à incorporer des séquences de caractères HTML spéciales, telles que &, dans vos champs. Si vous souhaitez désactiver l'échappement automatique, appelez la méthode autoEscape() avec une valeur fausse immédiatement après la création de l'objet CGI :

$q = CGI->new;
$q->autoEscape(0);

Notez que autoEscape() est exclusivement utilisé pour influencer le comportement de la manière dont certaines fonctions de génération HTML de CGI.pm gèrent l'échappement. Appeler escapeHTML() explicitement échappera toujours le HTML.

Un piège latent ! Certaines des méthodes de génération d'éléments de formulaire renvoient plusieurs balises. Dans un contexte scalaire, les balises seront concaténées avec des espaces, ou quelle que soit la valeur actuelle de $" global. Dans un contexte de liste, les méthodes renverront une liste d'éléments, vous permettant de les modifier si vous le souhaitez. Habituellement, vous ne remarquerez pas ce comportement, mais méfiez-vous de ceci :

printf("%s\n",end_form())

end_form() produit plusieurs balises, et seule la première sera imprimée car le format ne s'attend qu'à une seule valeur.

  <... various form stuff ...>
print end_form;

start_form() renverra une balise <form> avec la méthode, l'action et le codage de formulaire facultatifs que vous spécifiez. Les valeurs par défaut sont :

method: POST
action: this script
enctype: application/x-www-form-urlencoded for non-XHTML
         multipart/form-data for XHTML, see multipart/form-data below.

end_form() renvoie la balise de fermeture </form>.

start_form()L'argument enctype indique au navigateur comment empaqueter les différents champs du formulaire avant de l'envoyer au serveur. Deux valeurs sont possibles :

application/x-www-form-urlencoded
C'est le type de codage le plus ancien. Il est compatible avec de nombreux scripts CGI et convient aux champs courts contenant des données textuelles. Pour votre commodité, CGI.pm stocke le nom de ce type de codage dans &CGI::URL_ENCODED.
multipart/form-data
C'est le type de codage le plus récent. Il convient aux formulaires qui contiennent des champs très volumineux ou qui sont destinés au transfert de données binaires. Surtout, il permet la fonctionnalité de "téléversement de fichier". Pour votre commodité, CGI.pm stocke le nom de ce type de codage dans &CGI::MULTIPART

Les formulaires qui utilisent ce type de codage ne sont pas facilement interprétés par les scripts CGI à moins qu'ils n'utilisent CGI.pm ou une autre bibliothèque conçue pour les gérer.

Si XHTML est activé (par défaut), les formulaires seront automatiquement créés en utilisant ce type de codage.

La start_form() méthode utilise l'ancienne forme de codage par défaut, sauf si XHTML est demandé. Si vous voulez utiliser la nouvelle forme de codage par défaut, vous pouvez appeler start_multipart_form() au lieu de start_form(). La méthode end_multipart_form() est un alias pour end_form().

JAVASCRIPT : Les -name et -onSubmit paramètres sont fournis pour une utilisation avec JavaScript. Le paramètre -name donne un nom au formulaire pour qu'il puisse être identifié et manipulé par des fonctions JavaScript. -onSubmit doit pointer vers une fonction JavaScript qui sera exécutée juste avant que le formulaire ne soit soumis à votre serveur. Vous pouvez utiliser cette occasion pour vérifier le contenu du formulaire pour sa cohérence et son exhaustivité. Si vous trouvez quelque chose de mal, vous pouvez afficher une boîte d'alerte ou peut-être corriger les choses vous-même. Vous pouvez annuler la soumission en retournant false depuis cette fonction.

Habituellement, la majeure partie des fonctions JavaScript est définie dans un bloc <script> dans l'en-tête HTML et -onSubmit pointe vers un appel à l'une de ces fonctions. Voir start_html() pour plus de détails.

Éléments de formulaire

Après avoir démarré un formulaire, vous créerez typiquement un ou plusieurs champs de texte, menus contextuels, groupes de boutons radio et d'autres éléments de formulaire. Chacun de ces éléments prend un ensemble standard d'arguments nommés. Certains éléments ont aussi des arguments facultatifs. Les arguments standard sont les suivants :

-name
Le nom du champ. Après la soumission, ce nom peut être utilisé pour récupérer la valeur du champ en utilisant la méthode param() .
-value, -values
<dd>La valeur initiale du champ qui sera retournée au script après la soumission du formulaire. Certains éléments de formulaire, tels que les champs de texte, prennent un argument scalaire unique -value. D'autres, tels que les menus contextuels, prennent une référence vers un tableau de valeurs. Les deux arguments sont des synonymes.
-tabindex
Une valeur numérique qui définit l'ordre dans lequel l'élément de formulaire reçoit le focus lorsque l'utilisateur appuie sur la touche de tabulation. Les éléments avec des valeurs plus basses reçoivent le focus en premier.
-id
Un identifiant de chaîne qui peut être utilisé pour identifier cet élément pour JavaScript et DHTML.
-override
Un booléen, qui, s'il est vrai, force l'élément à prendre la valeur spécifiée par -value, remplaçant le comportement collant décrit précédemment pour le pragma -nosticky .
-onChange, -onFocus, -onBlur, -onMouseOver, -onMouseOut, -onSelect
Ceux-ci sont utilisés pour assigner des gestionnaires d'événements JavaScript. Voir la section JavaScripting pour plus de détails.

Les autres arguments courants sont décrits dans la section suivante. En plus de ceux-ci, tous les attributs décrits dans les spécifications HTML sont pris en charge.

Création d'un champ de texte

print textfield(-name=>'field_name',
                -value=>'starting value',
                -size=>50,
                -maxlength=>80);
    -ou-
print textfield('field_name','starting value',50,80);

textfield() renverra un champ de saisie de texte.

Paramètres

1.
Le premier paramètre est le nom requis pour le champ (-name).
2.
Le deuxième paramètre facultatif est la valeur de départ par défaut pour le contenu du champ (-value, anciennement connu sous le nom de -default).
3.
Le troisième paramètre facultatif est la taille du champ en
caractères (-size).
4.
Le quatrième paramètre facultatif est le nombre maximum de caractères que
le champ acceptera (-maxlength).

Comme avec toutes ces méthodes, le champ sera initialisé avec son contenu précédent provenant des appels antérieurs du script. Lorsque le formulaire est traité, la valeur du champ de texte peut être récupérée avec :

$value = param('foo');

Si vous souhaitez le réinitialiser à sa valeur initiale après que le script a été appelé une fois, vous pouvez le faire comme ceci :

param('foo',"I'm taking over this value!");

Création d'un grand champ de texte

print textarea(-name=>'foo',
                       -default=>'starting value',
                       -rows=>10,
                       -columns=>50);
     -ou
print textarea('foo','starting value',10,50);

textarea() est juste comme textfield, mais il vous permet de spécifier des lignes et des colonnes pour une zone de saisie de texte multiligne. Vous pouvez fournir une valeur de départ pour le champ, qui peut être longue et contenir plusieurs lignes.

Création d'un champ de mot de passe

print password_field(-name=>'secret',
                             -value=>'starting value',
                             -size=>50,
                             -maxlength=>80);
     -ou-
print password_field('secret','starting value',50,80);

password_field() est identique à textfield(), sauf que son contenu sera affiché avec des astérisques sur la page web.

Création d'un champ de téléversement de fichier

print filefield(-name=>'uploaded_file',
                        -default=>'starting value',
                        -size=>50,
                        -maxlength=>80);
    -ou-
print filefield('uploaded_file','starting value',50,80);

filefield() renverra un champ de téléversement de fichier. Afin de tirer pleinement parti de cela vous devez utiliser le nouveau schéma de codage multipart pour le formulaire. Vous pouvez le faire soit en appelant start_form() avec un type de codage de &CGI::MULTIPART, ou en appelant la nouvelle méthode start_multipart_form() au lieu du start_form()standard.

Paramètres

1.
Le premier paramètre est le nom requis pour le champ (-name).
2.
Le deuxième paramètre facultatif est la valeur de départ pour le contenu du champ à utiliser comme nom de fichier par défaut (-default).

Pour des raisons de sécurité, les navigateurs ne prêtent aucune attention à ce champ, et donc la valeur de départ sera toujours vide. Pire, le champ perd son comportement « collant » et oublie son contenu précédent. Le champ de valeur de départ est exigé dans la spécification HTML, cependant, et peut-être qu'un navigateur finira par fournir une prise en charge pour celui-ci.

3.
Le troisième paramètre facultatif est la taille du champ en caractères (-size).
4.
Le quatrième paramètre facultatif est le nombre maximum de caractères que le champ acceptera (-maxlength).

JAVASCRIPTING : Les -onChange, -onFocus, -onBlur, -onMouseOver, -onMouseOut et -onSelect paramètres sont reconnus. Voir textfield() pour les détails.

Création d'un menu contextuel

print popup_menu('menu_name',
                         ['eenie','meenie','minie'],
                         'meenie');
   -ou-
%labels = ('eenie'=>'your first choice',
           'meenie'=>'your second choice',
           'minie'=>'your third choice');
%attributes = ('eenie'=>{'class'=>'class of first choice'});
print popup_menu('menu_name',
                         ['eenie','meenie','minie'],
       'meenie',\%labels,\%attributes);
     -ou (style de paramètre nommé)-
print popup_menu(-name=>'menu_name',
                         -values=>['eenie','meenie','minie'],
                         -default=>['meenie','minie'],
       -labels=>\%labels,
       -attributes=>\%attributes);

popup_menu() crée un menu. Veuillez noter que l'option -multiple sera ignorée si elle est passée - utilisez scrolling_list() si vous voulez créer un menu qui prend en charge les sélections multiples

1.
Le premier argument requis est le nom du menu (-name).
2.
Le deuxième argument requis (-values) est une référence de tableau contenant la liste des éléments du menu dans le menu. Vous pouvez passer à la méthode un tableau anonyme, comme montré dans l'exemple, ou une référence vers un tableau nommé, tel que "\@foo".
3.
Le troisième paramètre facultatif (-default) est le nom du choix de menu par défaut. S'il n'est pas spécifié, le premier élément sera le défaut. Les valeurs du choix précédent seront maintenues à travers les requêtes. Passez une référence de tableau pour sélectionner plusieurs valeurs par défaut.
4.
Le quatrième paramètre facultatif (-labels) est fourni pour les personnes qui veulent utiliser des valeurs différentes pour l'étiquette visible par l'utilisateur à l'intérieur du menu contextuel et la valeur retournée à votre script. C'est un pointeur vers une table de hachage reliant les valeurs du menu aux étiquettes visibles par l'utilisateur. Si vous laissez ce paramètre vide, les valeurs du menu seront affichées par défaut. (Vous pouvez aussi laisser une étiquette indéfinie si vous le souhaitez).
5.
Le cinquième paramètre facultatif (-attributes) est fourni pour assigner n'importe lequel des attributs HTML courants à un élément de menu individuel. C'est un pointeur vers une table de hachage reliant les valeurs du menu à une autre table de hachage avec le nom de l'attribut comme clé et la valeur de l'attribut comme valeur.

Lorsque le formulaire est traité, la valeur sélectionnée du menu contextuel peut être récupérée en utilisant :

$popup_menu_value = param('menu_name');

Création d'un groupe d'options

Style de paramètre nommé

print popup_menu(-name=>'menu_name',
                -values=>[qw/eenie meenie minie/,
                          optgroup(-name=>'optgroup_name',
                                           -values => ['moe','catch'],
                                           -attributes=>{'catch'=>{'class'=>'red'}})],
                -labels=>{'eenie'=>'one',
                          'meenie'=>'two',
                          'minie'=>'three'},
                -default=>'meenie');
Ancien style
print popup_menu('menu_name',
                ['eenie','meenie','minie',
                 optgroup('optgroup_name', ['moe', 'catch'],
                                 {'catch'=>{'class'=>'red'}})],'meenie',
                {'eenie'=>'one','meenie'=>'two','minie'=>'three'});

optgroup() crée un groupe d'options à l'intérieur d'un menu contextuel.

1.
Le premier argument requis (-name) est l'attribut label de l'optgroup et n'est pas inséré dans la liste de paramètres de la requête.
2.
Le deuxième argument requis (-values) est une référence de tableau contenant la liste des éléments du menu dans le menu. Vous pouvez passer à la méthode un tableau anonyme, comme montré dans l'exemple, ou une référence vers un tableau nommé, tel que \@foo. Si vous passez une référence de HASH, les clés seront utilisées pour les valeurs du menu, et les valeurs seront utilisées pour les étiquettes du menu (voir -labels ci-dessous).
3.
Le troisième paramètre facultatif (-labels) vous permet de passer une référence vers une table de hachage contenant des étiquettes visibles par l'utilisateur pour un ou plusieurs des éléments du menu. Vous pouvez utiliser ceci lorsque vous voulez que l'utilisateur voie une chaîne de menu, mais que le navigateur retourne à votre programme une chaîne différente. Si vous ne spécifiez pas ceci, la chaîne de valeur sera utilisée à la place ("eenie", "meenie" et "minie" dans cet exemple). C'est équivalent à utiliser une référence de tableau de hachage pour le paramètre -values.
4.
Un quatrième paramètre facultatif (-labeled) peut être défini à une valeur vraie et indique que les valeurs devraient être utilisées comme l'attribut label pour chaque élément option à l'intérieur de l'optgroup.
5.
Un cinquième paramètre facultatif (-novals) peut être défini à une valeur vraie et indique de supprimer l'attribut val dans chaque élément option à l'intérieur de l'optgroup.

Voir la discussion sur optgroup sur W3C (http://www.w3.org/TR/REC-html40/interact/forms.html#edef-OPTGROUP) pour les détails.

6.
Un sixième paramètre facultatif (-attributes) est fourni pour assigner n'importe lequel des attributs HTML courants à un élément de menu individuel. C'est un pointeur vers une table de hachage reliant les valeurs du menu à une autre table de hachage avec l'attribute's name as the key and the attribute's value as the value.

checkbox_group() crée une liste de cases à cocher qui sont liées par le même nom.

Paramètres :

1.
Les premier et deuxième arguments sont respectivement le nom et les valeurs de la case à cocher (-name et -values). Comme dans le menu contextuel, le deuxième argument doit être une référence de tableau. Ces valeurs sont utilisées pour les libellés lisibles par l'utilisateur imprimés à côté des cases à cocher ainsi que pour les valeurs transmises à votre script dans la chaîne de requête.
2.
Le troisième argument facultatif (-default) peut être soit une référence à une liste contenant les valeurs à cocher par défaut, soit une valeur unique à cocher. Si cet argument est manquant ou indéfini, rien n'est sélectionné lorsque la liste apparaît pour la première fois.
3.
Le quatrième argument facultatif (-linebreak) peut être défini sur true pour placer des sauts de ligne entre les cases à cocher afin qu'elles apparaissent comme une liste verticale. Sinon, elles seront alignées sur une ligne horizontale.

Les paramètres facultatifs -rows, et -columns font que checkbox_group() retourne un tableau compatible HTML3 contenant le groupe de cases à cocher formaté avec le nombre spécifié de lignes et de colonnes. Vous pouvez fournir uniquement le paramètre -columns si vous le souhaitez ; checkbox_group calculera le nombre correct de lignes pour vous.

L'option -disabled prend un tableau de valeurs de cases à cocher et les désactive en les grisant (cela peut ne pas être pris en charge par tous les navigateurs).

L'argument facultatif -attributes est fourni pour attribuer n'importe lequel des attributs HTML courants à un élément de menu individuel. C'est un pointeur vers un hachage reliant les valeurs du menu à un autre hachage avec le nom de l'attribut comme clé et la valeur de l'attribut comme valeur.

L'argument facultatif -tabindex peut être utilisé pour contrôler l' ordre dans lequel les boutons radio reçoivent le focus lorsque l'utilisateur appuie sur la touche tabulation. Si on lui passe une valeur numérique scalaire, le premier élément du groupe recevra cet index de tabulation et les éléments suivants seront incrémentés de un. Si on lui donne une référence à un tableau de valeurs de boutons radio, les index seront ajustés de sorte que l'ordre spécifié dans le tableau corresponde à l'ordre de tabulation. Vous pouvez également passer une référence à un hachage dans lequel les clés du hachage sont les valeurs des boutons radio et les valeurs sont les index de tabulation de chaque bouton. Exemples :

-tabindex => 100    #  this group starts at index 100 and counts up
-tabindex => ['moe','minie','eenie','meenie']  # tab in this order
-tabindex => {meenie=>100,moe=>101,minie=>102,eenie=>200} # tab in this order

L'argument facultatif -labelattributes contiendra les attributs attachés à l'élément <label> qui entoure chaque bouton.

Lorsque le formulaire est traité, toutes les cases cochées seront retournées en tant que liste sous le nom de paramètre 'group_name'. Les valeurs des cases "on" peuvent être récupérées avec :

&use_in_creative_way(@h);

SUPPORT LIMITÉ DES FEUILLES DE STYLE EN CASCADE

Le module CGI.pm a un support limité des feuilles de style en cascade (css) de HTML3. Pour incorporer une feuille de style dans votre document, passez à la méthode start_html() un paramètre -style . La valeur de ce paramètre peut être un scalaire, auquel cas il est traité comme l'URL source de la feuille de style, ou elle peut être une référence de hachage. Dans ce dernier cas, vous devez fournir au hachage une ou plusieurs des clés -src ou -code. -src pointe vers une URL où une feuille de style définie en externe peut être trouvée. -code pointe vers une valeur scalaire à incorporer dans une section <style>. Les définitions de style dans -code remplacent celles de même nom dans -src, d'où le nom « en cascade ».

Vous pouvez également spécifier le type de la feuille de style en ajoutant le paramètre optionnel -type au hachage pointé par -style. S'il n'est pas spécifié, le type de style par défaut est 'text/css'.

Pour faire référence à un style dans le corps de votre document, ajoutez le paramètre -class à n'importe quel élément HTML :

print h1({-class=>'Fancy'},'Welcome to the Party');

Ou définissez des styles à la volée avec le paramètre -style :

print h1({-style=>'Color: red;'},'Welcome to Hell');

Vous pouvez également utiliser le nouvel élément span() pour appliquer un style à une section de texte :

print span({-style=>'Color: red;'},
           h1('Welcome to Hell'),
           "Where did that handbasket get to?"
           );

Notez que vous devez importer les définitions ":html3" pour avoir la méthode span() disponible. Voici un exemple rapide et simple d'utilisation des CSS. Voir la spécification CSS sur http://www.w3.org/Style/CSS/ pour plus d'informations.

use CGI qw/:standard :html3/;
#here's a stylesheet incorporated directly into the page
$newStyle=<<END;
<!-- 
P.Tip {
    margin-right: 50pt;
    margin-left: 50pt;
    color: red;
}
P.Alert {
    font-size: 30pt;
    font-family: sans-serif;
  color: red;
}
-->
END
print header();
print start_html( -title=>'CGI with Style',
                  -style=>{-src=>'http://www.capricorn.com/style/st1.css',
                           -code=>$newStyle}
                 );
print h1('CGI with Style'),
      p({-class=>'Tip'},
        "Better read the cascading style sheet spec before playing with this!"),
      span({-style=>'color: magenta'},
           "Look Mom, no hands!",
           p(),
           "Whooo wee!"
           );
print end_html;

Passez une référence de tableau à -code ou -src afin d'incorporer plusieurs feuilles de style dans votre document.

Si vous souhaitez incorporer une feuille de style verbatim incluant un formatage arbitraire dans l'en-tête, vous pouvez passer une balise -verbatim au hachage -style, comme suit :

print start_html (-style => {-verbatim => '@import url("/server-common/css/'.$cssFile.'");',
-src => '/server-common/css/core.css'});

Cela générera un en-tête HTML contenant ceci :

<link rel="stylesheet" type="text/css"  href="/server-common/css/core.css">
  <style type="text/css">
  @import url("/server-common/css/main.css");
  </style>

Tous les arguments supplémentaires passés dans la valeur de -style seront incorporés dans la balise <link>. Par exemple :

start_html(-style=>{-src=>['/styles/print.css','/styles/layout.css'],
                         -media => 'all'});

Cela donnera :

<link rel="stylesheet" type="text/css" href="/styles/print.css" media="all"/>
<link rel="stylesheet" type="text/css" href="/styles/layout.css" media="all"/>

<p>

Pour créer des balises <link> plus complexes, utilisez la fonction Link() et passez-la à start_html() dans l'argument -head, comme ceci :

@h = (Link({-rel=>'stylesheet',-type=>'text/css',-src=>'/ss/ss.css',-media=>'all'}),
      Link({-rel=>'stylesheet',-type=>'text/css',-src=>'/ss/fred.css',-media=>'paper'}));
print start_html({-head=>\@h})

Pour créer une feuille de style primaire et une feuille de style « alternative », utilisez l'option -alternate :

start_html(-style=>{-src=>[
                          {-src=>'/styles/print.css'},
                          {-src=>'/styles/alt.css',-alternate=>1}
                          ]
                   });
