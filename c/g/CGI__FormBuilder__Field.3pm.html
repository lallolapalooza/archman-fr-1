NOM

CGI::FormBuilder::Field - Classe de base pour les champs FormBuilder

SYNOPSIS

use CGI::FormBuilder::Field;
# délégué directement depuis FormBuilder
my $f = CGI::FormBuilder::Field->new($form, name => 'whatever');
# fonctions d'attribut
my $n = $f->name;         # nom du champ
my $n = "$f";             # conversion en chaîne vers $f->name
my $t = $f->type;         # type automatique
my @v = $f->value;        # adhérence automatique
my @o = $f->options;      # options, alignées et triées
my $l = $f->label;        # étiquette automatique
my $h = $f->tag;          # balise XHTML du champ (name/type/value)
my $s = $f->script;       # script de validation JS par champ
my $m = $f->message;      # message d'erreur si invalide
my $m = $f->jsmessage;    # message d'erreur JavaScript
my $r = $f->required;     # requis ?
my $k = $f->validate;     # exécuter la vérification de validation
my $v = $f->tag_value;    # valeur dans la balise (gestion de l'adhérence)
my $v = $f->cgi_value;    # valeur CGI s'il y en a une
my $v = $f->def_value;    # valeur spécifiée manuellement
$f->field(opt => 'val');  # appel field() de FormBuilder

DESCRIPTION

Ce module est utilisé en interne par FormBuilder pour créer et maintenir les informations de champ. Habituellement, vous ne voudrez pas accéder directement à cet ensemble de structures de données. Cependant, une grande exception est si vous allez micro-contrôler le rendu du formulaire. Dans ce cas, vous devrez accéder directement aux objets de champ.

Pour ce faire, vous voudrez parcourir les champs dans l'ordre :

for my $field ($form->field) {
    # $field contient un objet converti en chaîne vers un nom de champ
    if ($field =~ /_date$/) {
        $field->sticky(0);  # effacer la valeur CGI
        print "Enter $field here:", $field->tag;
    } else {
        print $field->label, ': ', $field->tag;
    }
}

Comme illustré, chaque $field variable contient en fait un objet convertible en chaîne. Cela signifie que si vous les imprimez, vous obtiendrez le nom du champ, ce qui vous permet de vérifier certains champs. Cependant, puisque c'est un objet, vous pouvez ensuite exécuter des méthodes d'accès directement sur cet objet.

La méthode la plus utile est tag(). Elle génère la balise d'entrée HTML pour le champ, incluant toutes les options et la gestion du type, et retourne une chaîne que vous pouvez ensuite imprimer ou manipuler de manière appropriée.

Après cette méthode vient la "script" méthode, qui retourne la routine de validation JavaScript appropriée pour ce champ. C'est utile en haut de votre rendu de formulaire, lorsque vous imprimez la section "<head>" de votre document HTML. Elle est appelée par la méthode $form du même nom.

Les méthodes suivantes sont fournies pour chaque objet $field .

MÉTHODES

new($form, %args)

Cela crée un nouvel objet $field . Le premier argument doit être une référence à l'objet de niveau supérieur $form , pour les rappels. Les arguments restants doivent être un hash, dont une paire "clé/valeur" doit spécifier le "name" du champ. Normalement, vous ne devriez pas toucher à cette méthode. Jamais.

field(%args)

Ceci est un appel de champ délégué. C'est ainsi que FormBuilder ajuste ses champs. Une fois que vous avez un objet $field , vous appelez cette méthode exactement de la même manière que vous appelleriez la méthode principale field() , à l'exception du nom du champ. Encore une fois, vous devriez utiliser l'appel de niveau supérieur à la place.

inflate($subref)

Cela définit l'attribut inflate : référence de sous-routine utilisée pour gonfler les valeurs retournées par value() en objets ou ce que vous voulez. Si aucun paramètre, retourne la référence de sous-routine inflate qui est définie. Par exemple :

use DateTime::Format::Strptime;
my $date_format = DateTime::Format::Strptime->new(
   pattern   => '%D',    # pour les dates américaines MM/DD/YYYY
   locale    => 'en_US',
   time_zone => 'America/Los_Angeles',
);
$field->inflate( sub { return $date_format->format_datetime(shift) } );

invalid

Cela retourne la valeur opposée que validate() retournerait, avec un peu de magie supplémentaire qui conserve l'état à des fins de rendu de formulaire.

jsfunc()

Retourne le code de validation JavaScript approprié (voir ci-dessus).

label($str)

Cela définit et retourne l'étiquette du champ. Si elle n'est pas définie, elle sera générée à partir du nom du champ.

tag($type)

Retourne une balise d'entrée de formulaire XHTML (voir ci-dessus). Par défaut, elle rend la balise basée sur le type défini depuis la méthode de champ de niveau supérieur :

$form->field(name => 'poetry', type => 'textarea');

Cependant, si vous faites un rendu personnalisé, vous pouvez temporairement le remplacer en passant le type explicitement. Cela n'est généralement pas utile à moins que vous n'ayez un module de rendu personnalisé qui remplace de force les types pour certains champs.

type($type)

Cela définit et retourne le type du champ. S'il n'est pas défini, il générera automatiquement le type de champ approprié, dépendant du nombre d'options et de si plusieurs valeurs sont autorisées :

Champ a des options ?
    Non = text (fait)
    Oui :
        Moins que le paramètre 'selectnum' ?
            Non = select (fait)
            Oui :
                L'option 'multiple' est-elle définie ?
                Oui = checkbox (fait)
                Non :
                    Avez-vous juste une seule option ?
                        Oui = checkbox (fait)
                        Non = radio (fait)

Pour un exemple, regardez l'intérieur des entrailles de ce module.

validate($pattern)

Cela retourne 1 si le champ passe le(s) motif(s) de validation et le "required" statut défini précédemment via required() et (possiblement) l'appel de niveau supérieur new() dans FormBuilder. Habituellement, exécuter des appels validate() par champ n'est pas ce que vous voulez. À la place, vous voulez exécuter celui sur $form, qui à son tour appelle chaque champ individuel et sauvegarde un peu d'état temporaire.

value($val)

Cela définit la valeur du champ. Elle retourne aussi la valeur appropriée : CGI si définie, sinon la valeur par défaut manuelle. Identique à l'utilisation de field() pour récupérer les valeurs.

tag_value()

Cela obéit à l'indicateur "sticky" pour donner une interprétation différente des valeurs CGI. Utilisez ceci pour obtenir la valeur si vous générez votre propre balise. Sinon, ignorez-la complètement.

cgi_value()

Cela retourne toujours la valeur CGI, indépendamment de "sticky".

def_value()

Cela retourne toujours la valeur par défaut, indépendamment de "sticky".

tag_name()

Cela retourne le nom de balise de l'élément courant. Ceci a été ajouté pour que vous puissiez sous-classer, disons, "CGI::FormBuilder::Field::select" et changer la balise HTML en "<b:select>" à la place. Ceci est une fonctionnalité expérimentale et sujette à des changements importants (suggestions bienvenues).

accesseurs

En plus des méthodes ci-dessus, des accesseurs sont fournis pour manipuler directement les valeurs comme si à partir d'un appel field() :

Accesseur                Identique à...
----------------------- -----------------------------------
$f->force(0|1)          $form->field(force => 0|1)
$f->options(\@opt)      $form->field(options => \@opt)
$f->multiple(0|1)       $form->field(multiple => 0|1)
$f->message($mesg)      $form->field(message => $mesg)
$f->jsmessage($mesg)    $form->field(jsmessage => $mesg)
$f->jsclick($code)      $form->field(jsclick => $code)
$f->sticky(0|1)         $form->field(sticky => 0|1);
$f->force(0|1)          $form->field(force => 0|1);
$f->growable(0|1)       $form->field(growable => 0|1);
$f->other(0|1)          $form->field(other => 0|1);
