CGEESX calcule les valeurs propres, la forme de Schur et, optionnellement, la matrice des vecteurs de Schur pour les matrices

GE

But

: 
!>
!> CGEESX calcule pour une matrice complexe non symétrique A de dimension N par N,
!> les valeurs propres, la forme de Schur T et, optionnellement, la matrice des
!> vecteurs de Schur Z. Cela donne la factorisation de Schur A = Z*T*(Z**H).
!>
!> Optionnellement, il ordonne aussi les valeurs propres sur la diagonale de la
!> forme de Schur de sorte que les valeurs propres sélectionnées soient en haut à
!> gauche ; calcule un nombre de condition réciproque pour la moyenne des valeurs
!> propres sélectionnées (RCONDE) ; et calcule un nombre de condition réciproque
!> pour le sous-espace invariant droit correspondant aux valeurs propres
!> sélectionnées (RCONDV). Les colonnes principales de Z forment une base
!> orthonormale pour ce sous-espace invariant.
!>
!> Pour une explication plus détaillée des nombres de condition réciproques RCONDE
!> et RCONDV, voir la section 4.10 du Guide des utilisateurs de LAPACK (où ces
!> quantités sont appelées s et sep respectivement).
!>
!> Une matrice complexe est en forme de Schur si elle est triangulaire supérieure.
!
>

Paramètre

s
JOBVS 
!>          JOBVS est CHARACTER*1
!>          = 'N' : les vecteurs de Schur ne sont pas calculés ;
!>          = 'V' : les vecteurs de Schur sont calculés.
!
>

SOR

T 
!>          SORT est CHARACTER*1
!>          Indique s'il faut ou non ordonner les valeurs propres sur la
!>          diagonale de la forme de Schur.
!>          = 'N' : les valeurs propres ne sont pas ordonnées ;
!>          = 'S' : les valeurs propres sont ordonnées (voir SELECT).
!
>

SELEC

T 
!>          SELECT est une fonction LOGICAL d'un argument COMPLEX
!>          SELECT doit être déclarée EXTERNAL dans la sous-routine appelante.
!>          Si SORT = 'S', SELECT est utilisée pour sélectionner les valeurs
!>          propres à ordonner en haut à gauche de la forme de Schur.
!>          Si SORT = 'N', SELECT n'est pas référencée.
!>          Une valeur propre W(j) est sélectionnée si SELECT(W(j)) est vraie.
!
>

SENS

E 
!>          SENSE est CHARACTER*1
!>          Détermine quels nombres de condition réciproques sont calculés.
!>          = 'N' : aucun n'est calculé ;
!>          = 'E' : calculé uniquement pour la moyenne des valeurs propres
!>                  sélectionnées ;
!>          = 'V' : calculé uniquement pour le sous-espace invariant droit
!>                  sélectionné ;
!>          = 'B' : calculé pour les deux.
!>          Si SENSE = 'E', 'V' ou 'B', SORT doit être égal à 'S'.
!
>

N 
!>          N est INTEGER
!>          L'ordre de la matrice A. N >= 0.
!
>

A 
!>          A est un tableau COMPLEX, dimension (LDA, N)

>

W

>

WORK !> WORK est un tableau COMPLEX, dimension (MAX(1,LWORK)) !> À la sortie, si INFO = 0, WORK(1)

renvoie le LWORK optimal. !> LWORK 
!>          LWORK est INTEGER
!>          La dimension du tableau WORK. LWORK >= max(1,2*N).
!>          De plus, si SENSE = 'E' ou 'V' ou 'B', LWORK >= 2*SDIM*(N-SDIM),
!>          où SDIM est le nombre de valeurs propres sélectionnées calculées
!>          par cette routine. Notez que 2*SDIM*(N-SDIM) <= N*N/2. Notez
!>          également qu'une erreur n'est renvoyée que si LWORK < max(1,2*N),
!>          mais si SENSE = 'E' ou 'V' ou 'B', cela peut ne pas être
!>          suffisant. Pour de bonnes performances, LWORK doit généralement
!>          être plus grand.
!>
!>          Si LWORK = -1, une interrogation d'espace de travail est supposée ;
!>          la routine calcule uniquement une borne supérieure sur la taille
!>          optimale du tableau WORK, renvoie cette valeur comme première
!>          entrée du tableau WORK, et aucun message d'erreur lié à LWORK n'est
!>          émis par
XERBLA. !>

RWOR

K

>

K

INF

O 
!>          INFO est INTEGER
!>          = 0 : sortie réussie
!>          < 0 : si INFO = -i, le i-ème argument avait une valeur illégale.
!>          > 0 : si INFO = i, et i est
!>             <= N : l'algorithme QR a échoué à calculer toutes les
!>                    valeurs propres ; les éléments 1:ILO-1 et i+1:N de W
!>                    contiennent les valeurs propres qui ont convergé ; si
!>                    JOBVS = 'V', VS contient la transformation qui
!>                    réduit A à sa forme de Schur partiellement convergée.
!>             = N+1 : les valeurs propres n'ont pas pu être réordonnées car
!>                     certaines valeurs propres étaient trop proches pour
!>                     être séparées (le problème est très mal conditionné) ;

!>                     valeurs de certaines valeurs propres complexes de
!>                     sorte que les valeurs propres principales dans la
!>                     forme de Schur ne satisfont plus SELECT=.TRUE.. Cela
