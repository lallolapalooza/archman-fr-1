DESCRIPTIO

N

CGI::Session::Driver est une classe de base pour tous les pilotes natifs de CGI::Session. El

le documente également les spécifications des pilotes pour ceux qui souhaitent écrire des p
ilotes pour différentes bases de données actuellement non prises en charge par CGI::Session.

QU'EST-CE QU'UN

PILOTE

Un pilote est un morceau de code qui aide la bibliothèque CGI::Session à communiquer avec des moteurs de bases de données ou des mécanismes de stockage spécifiques. Plus précisément, un pilote est un fichier .pm qui hérite de CGI::Session::Driver et définit retrieve(), store() et remove

().

MODÈL

E

La meilleure façon d'apprendre les spécifications est de regarder un modèle de pilote

: 
package CGI::Session::Driver::your_driver_name;
use strict;
use base qw( CGI::Session::Driver CGI::Session::ErrorHandler );
sub init {
    my ($self) = @_;
    # facultatif
}
sub DESTROY {
    my ($self) = @_;
    # facultatif
}
sub store {
    my ($self, $sid, $datastr) = @_;
    # Stocker $datastr, qui est une chaîne de données déjà sérialisée.
}
sub retrieve {
    my ($self, $sid) = @_;
    # Retourner $datastr, qui a été stocké précédemment avec la méthode store() ci-dessus.
    # Retourner $datastr si $sid a été trouvé. Retourner 0 ou "" si $sid n'existe pas
    }
sub remove {
    my ($self, $sid) = @_;
    # Supprimer le stockage associé à $sid. Retourner toute valeur vraie indiquant le succès,
    # ou undef en cas d'échec.
}
sub traverse {
    my ($self, $coderef) = @_;
    # exécuter $coderef pour chaque identifiant de session en passant l'identifiant de session
    # comme premier et unique argument
}
1;

Tous les attributs passés en deuxième argument aux méthodes new() ou load() de CGI::Session seront automatiquement convertis en attributs de l'objet pilote. Par exemple, si l'objet session a été initialisé comme suit

: 
$s = CGI::Session->new("driver:your_driver_name", undef, {Directory=>'/tmp/sessions'})
;

Vous pouvez accéder à la valeur de 'Directory' depuis votre pilote comme ceci

: 
sub store {
    my ($self, $sid, $datastr) = @_;
    my $dir = $self->{Directory};   # <-- dans cet exemple sera '/tmp/sessions'
}

Vous pouvez définir facultativement la méthode init() dans votre pilote pour effectuer une initialisation globale spécifique au pilote. La méthode init() ne sera invoquée qu'une seule fois pendant le cycle de vie de votre pilote, ce qui correspond au cycle de vie d'un objet

session.

Pour des exemples de init(), consultez le code

MÉTHODE

S

Cette section liste et décrit toutes les méthodes des pilotes. Toutes les méthodes du pilote recevront l'objet pilote ($self) en premier argument. Les méthodes qui concernent une session individuelle (telles que retrieve(), store() et remove()) recevront également l'identifiant de session ($sid) en deuxième

argument.

La liste suivante décrit chaque méthode du pilote, y compris sa liste d'arguments et l'étape de la vie de la session à laquelle elle sera invoquée. Comprendre cela peut aider les auteurs de

pilotes.
retrieve($self,
$sid)
Appelée chaque fois qu'une session spécifique est demandée, soit via "CGI::Session->new()" ou la syntaxe "CGI::Session->load()". La méthode doit essayer de récupérer les données associées à $sid et les retourner. Si aucune donnée ne peut être récupérée pour $sid, 0 (zéro) ou "" doit être retourné. undef ne doit être retourné que pour signaler une erreur. Le message d'erreur doit être défini via set_error(), qui peut être héritée de CGI::Session::ErrorHandler.

Astuce : set_error() retourne toujours undef.

Utilisez-le à
votre avantage.
store($self, $sid,
$datastr)
Appelée chaque fois que des données de session modifiées doivent être enregistrées sur le disque. Cela se produit chaque fois que CGI::Session->flush() est appelé sur une session modifiée. Puisque CGI::Session->DESTROY() appelle flush(), store() est demandée chaque fois qu'un objet session doit être terminé.

store() est appelée à la fois pour stocker de nouvelles sessions et pour mettre à jour des sessions déjà stockées. Il appartient à l'auteur du pilote de déterminer quelle opération doit être

effectuée.

$datastr, qui est passé en troisième argument, représente des données de session déjà sérialisées qui doivent être

sauvegardées.

store() peut retourner toute valeur vraie indiquant le succès ou undef en cas d'échec. Le message d'erreur doit être transmis à set_err

or
()
remove($self,
$sid)
Appelée chaque fois que des données de session doivent être supprimées, c'est-à-dire lorsque CGI::Session->delete() est appelé. Doit retourner toute valeur vraie indiquant le succès, undef en cas d'échec. Le message d'erreur doit être consigné dans set_erro
r().
traverse($self,
\&coderef)
Appelée uniquement depuis CGI::Session->find(). Le rôle de traverse() est d'appeler \&coderef pour chaque session unique stockée sur le disque en passant l'identifiant de la session comme premier et unique argument : $coderef->( $sid
)
init($sel
f)
Facultatif. Appelée chaque fois que l'objet pilote doit être initialisé, ce qui ne se produit qu'une seule fois pendant le cycle de vie de l'objet CGI::Session. Ici, vous pouvez effectuer une initialisation globale du pilote, comme ouvrir une connexion à un serveur de base de
données.
DESTROY($sel
f)
Facultatif. Perl appelle automatiquement cette méthode sur les objets juste avant qu
'ils ne soient terminés. Cela donne à votre pilote la possibilité de fermer toutes les con
nexions à la base de données ou de fermer tous les descripteurs de fichiers ouverts.

COMPATIBILITÉ

DESCENDANTE

La version 4.0 des spécifications des pilotes de CGI::Session n'est PAS rétrocompatible avec la spécification précédente. Si vous avez déjà un pilote développé pour fonctionner avec la version précédente, il est fortement recommandé de mettre à jour le code de votre pilote pour le rendre compatible avec la version actuelle. Heureusement, les spécifications actuelles des pilotes sont beaucoup plus faciles à

adapter.
