Documentation de fonction/sous-routine

sous-routine cgees (character jobvs, character sort, external select, integer n, complex, dimension( lda, * ) a, integer lda, integer sdim, complex, dimension( * ) w, complex, dimension( ldvs, * ) vs, integer ldvs, complex, dimension( * ) work, integer lwork, real, dimension( * ) rwork, logical, dimension( * ) bwork, integer info)

CGEES calcule les valeurs propres, la forme de Schur, et, optionnellement, la matrice des vecteurs de Schur pour les matrices GE

Objectif :

!>
!> CGEES calcule pour une matrice complexe N-par-N non symétrique A, les
!> valeurs propres, la forme de Schur T, et, optionnellement, la matrice des
!> vecteurs de Schur Z. Cela donne la factorisation de Schur A = Z*T*(Z**H).
!>
!> Optionnellement, elle ordonne également les valeurs propres sur la diagonale
!> de la forme de Schur de sorte que les valeurs propres sélectionnées soient
!> en haut à gauche. Les colonnes de tête de Z forment alors une base orthonormée
!> pour le sous-espace invariant correspondant aux valeurs propres sélectionnées.
!>
!> Une matrice complexe est en forme de Schur si elle est triangulaire supérieure.
!>

Paramètres

JOBVS 
!>          JOBVS est CHARACTER*1
!>          = 'N': les vecteurs de Schur ne sont pas calculés ;
!>          = 'V': les vecteurs de Schur sont calculés.
!>

SORT

!>          SORT est CHARACTER*1
!>          Spécifie si les valeurs propres doivent être ordonnées sur la
!>          diagonale de la forme de Schur.
!>          = 'N': les valeurs propres ne sont pas ordonnées :
!>          = 'S': les valeurs propres sont ordonnées (voir SELECT).
!>

SELECT

!>          SELECT est une FONCTION LOGIQUE d'un argument COMPLEXE
!>          SELECT doit être déclarée EXTERNAL dans la sous-routine appelante.
!>          Si SORT = 'S', SELECT est utilisée pour sélectionner les valeurs propres à ordonner
!>          en haut à gauche de la forme de Schur.
!>          SI SORT = 'N', SELECT n'est pas référencée.
!>          La valeur propre W(j) est sélectionnée si SELECT(W(j)) est vrai.
!>

N

!>          N est INTEGER
!>          L'ordre de la matrice A. N >= 0.
!>

A

!>          A est un tableau COMPLEXE, dimension (LDA,N)
!>          En entrée, la matrice N-par-N A.
!>          En sortie, A est remplacée par sa forme de Schur T.
!>

LDA

!>          LDA est INTEGER
!>          La dimension principale du tableau A. LDA >= max(1,N).
!>

SDIM

!>          SDIM est INTEGER
!>          Si SORT = 'N', SDIM = 0.
!>          Si SORT = 'S', SDIM = nombre de valeurs propres pour lesquelles
!>                         SELECT est vrai.
!>

W

!>          W est un tableau COMPLEXE, dimension (N)
!>          W contient les valeurs propres calculées, dans le même ordre qu'elles
!>          apparaissent sur la diagonale de la forme de Schur de sortie T.
!>

VS

!>          VS est un tableau COMPLEXE, dimension (LDVS,N)
!>          Si JOBVS = 'V', VS contient la matrice unitaire Z des vecteurs de Schur.
!>          Si JOBVS = 'N', VS n'est pas référencé.
!>

LDVS

!>          LDVS est INTEGER
!>          La dimension principale du tableau VS. LDVS >= 1; si
!>          JOBVS = 'V', LDVS >= N.
!>

WORK

!>          WORK est un tableau COMPLEXE, dimension (MAX(1,LWORK))
!>          En sortie, si INFO = 0, WORK(1) contient la taille optimale de LWORK.
!>

LWORK

!>          LWORK est INTEGER
!>          La dimension du tableau WORK. LWORK >= max(1,2*N).
!>          Pour de bonnes performances, LWORK doit généralement être plus grand.
!>
!>          Si LWORK = -1, une requête de dimension de travail est supposée ; la routine
!>          calcule uniquement la taille optimale du tableau WORK, la retourne
!>          comme première entrée du tableau WORK, et aucun message d'erreur
!>          relatif à LWORK n'est émis par XERBLA.
!>

RWORK

!>          RWORK est un tableau REAL, dimension (N)
!>

BWORK

!>          BWORK est un tableau LOGICAL, dimension (N)
!>          Non référencé si SORT = 'N'.
!>

INFO

!>          INFO est INTEGER
!>          = 0 : succès
!>          < 0 : si INFO = -i, alors le i-ème argument avait une valeur illégale.
!>          > 0 : si INFO = i, et i est
!>               <= N :  l'algorithme QR n'a pas réussi à calculer toutes les
!>                      valeurs propres ; les éléments 1:ILO-1 et i+1:N de W
!>                      contiennent les valeurs propres qui ont convergé ;
!>                      si JOBVS = 'V', VS contient la matrice qui
!>                      réduit A à sa forme de Schur partiellement convergée.
!>               = N+1 : les valeurs propres n'ont pas pu être réordonnées car
!>                      certaines valeurs propres étaient trop proches pour être séparées (le
!>                      problème est très mal conditionné) ;
!>               = N+2 : après réordonnancement, les erreurs d'arrondi ont modifié les valeurs
!>                      de certaines valeurs propres complexes de sorte que les valeurs propres de tête
!>                      de la forme de Schur ne satisfont plus SELECT = .TRUE.. Ceci pourrait
!>                      aussi être causé par un sous-flux dû à une mise à l'échelle.
!>
