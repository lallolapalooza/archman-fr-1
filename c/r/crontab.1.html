CRONTAB(1) Commandes utilisateur CRONTAB(1)

NOM

crontab — maintient les fichiers crontab pour les utilisateurs individuels

SYNOPSIS

crontab [-u utilisateur] <fichier |->
crontab [-T] <fichier |->
crontab [-u utilisateur] <-l | -r | -e> [-i] [-s]
crontab -n[ nomhôte ]
crontab -c
crontab -V

DESCRIPTION

Crontab est le programme utilisé pour installer un fichier de table crontab fichier, supprimer ou lister les tables existantes utilisées pour servir le démon cron(8) . Chaque utilisateur peut avoir son propre crontab, et bien que ce soient des fichiers dans /var/spool/, ils ne sont pas destinés à être édités directement. Pour SELinux en mode MLS, vous pouvez définir plus de crontabs pour chaque plage. Pour plus d'informations, voir selinux(8).

Dans cette version de Cron il est possible d'utiliser un /var/spool/cron partagé monté sur le réseau /var/spool/cron à travers un cluster d'hôtes et spécifier que seul un des hôtes doit exécuter les tâches crontab dans le répertoire particulier à un moment donné. Vous pouvez également utiliser crontab depuis n'importe lequel de ces hôtes pour éditer le même ensemble partagé de fichiers crontab, et pour définir et interroger quel hôte doit exécuter les tâches crontab.

La planification des tâches cron avec crontab peut être autorisée ou interdite pour différents utilisateurs. À cette fin, utilisez les fichiers cron.allow et cron.deny . Si le fichier cron.allow existe, un utilisateur doit y être listé pour être autorisé à utiliser crontab. Si le fichier cron.allow n'existe pas mais que le fichier cron.deny existe , alors un utilisateur ne doit pas être listé dans le fichier cron.deny pour utiliser crontab. Si aucun de ces fichiers n'existe, alors seul le super utilisateur est autorisé à utiliser crontab.

Une autre manière de restreindre la planification des tâches cron au-delà de crontab est d'utiliser l'authentification PAM dans /etc/security/access.conf pour configurer les utilisateurs, qui sont autorisés ou interdits d'utiliser crontab ou de modifier les tâches cron du système dans le répertoire /etc/cron.d/ .

Le répertoire temporaire peut être défini dans une variable d'environnement. S'il n'est pas défini par l'utilisateur, le répertoire /tmp est utilisé.

Lors de l'affichage d'un crontab sur un terminal, la sortie sera colorée sauf si une variable d'environnement NO_COLOR est définie.

Lors de l'édition ou de la suppression du crontab, une sauvegarde du dernier crontab sera enregistrée dans $XDG_CACHE_HOME/crontab/crontab.bak ou $XDG_CACHE_HOME/crontab/crontab.<utilisateur>.bak si -u est utilisé. Si la variable d'environnement XDG_CACHE_HOME n'est pas définie, $HOME/.cache sera utilisé à la place.

OPTIONS

-u
Spécifie le nom de l'utilisateur dont le crontab doit être modifié. Si cette option n'est pas utilisée, crontab examine « votre » crontab, c'est-à-dire le crontab de la personne exécutant la commande. Si aucun crontab n'existe pour un utilisateur particulier, il est créé pour lui la première fois que la commande crontab -u est utilisée sous son nom d'utilisateur.
-T
Teste la syntaxe du fichier crontab sans l'installer. Une fois qu'un problème est trouvé, la validation est interrompue, donc cela ne retournera pas tous les problèmes existants en une seule exécution.
-l
Affiche le crontab actuel sur la sortie standard.
-r
Supprime le crontab actuel.
-e
Édite le crontab actuel en utilisant l'éditeur spécifié par les variables d'environnement VISUAL ou EDITOR . Après votre sortie de l'éditeur, le crontab modifié sera installé automatiquement.
-i
Cette option modifie l'option -r pour demander à l'utilisateur une réponse 'y/Y' avant de supprimer réellement le crontab.
-s
Ajoute la chaîne de contexte de sécurité SELinux actuelle comme paramètre MLS_LEVEL au fichier crontab avant que l'édition/remplacement n'ait lieu — voir la documentation de MLS_LEVEL dans crontab(5).
-n
Cette option n'est pertinente que si cron(8) a été démarré avec l'option -c , pour activer le support de clustering. Elle est utilisée pour définir l'hôte dans le cluster qui doit exécuter les tâches spécifiées dans les fichiers crontab dans le répertoire /var/spool/cron . Si un nom d'hôte est fourni, l'hôte dont le nom d'hôte retourné par gethostname(2) correspond au nom d'hôte fourni, sera sélectionné pour exécuter les tâches cron sélectionnées par la suite. S'il n'y a pas d'hôte dans le cluster correspondant au nom d'hôte fourni, ou si vous spécifiez explicitement un nom d'hôte vide, alors les tâches sélectionnées ne seront pas exécutées du tout. Si le nom d'hôte est omis, le nom de l'hôte local retourné par gethostname(2) est utilisé. L'utilisation de cette option n'a aucun effet sur le fichier /etc/crontab et les fichiers dans le répertoire /etc/cron.d , qui sont toujours exécutés et considérés comme spécifiques à l'hôte. Pour plus d'informations sur le support de clustering, voir cron(8).
-c
Cette option n'est pertinente que si cron(8) a été démarré avec l'option -c , pour activer le support de clustering. Elle est utilisée pour interroger quel hôte dans le cluster est actuellement défini pour exécuter les tâches spécifiées dans les fichiers crontab dans le répertoire /var/spool/cron , tel que défini avec l'option -n .
-V
Affiche la version et quitte.

AVERTISSEMENTS

Les fichiers cron.allow et cron.deny ne peuvent pas être utilisés pour restreindre l'exécution des tâches cron ; ils restreignent seulement l'utilisation de crontab. En particulier, restreindre l'accès à crontab n'a aucun effet sur un crontab existant d'un utilisateur. Ses tâches continueront d'être exécutées jusqu'à ce que le crontab soit supprimé.

Les fichiers cron.allow et cron.deny doivent être lisibles par l'utilisateur invoquant crontab. Si ce n'est pas le cas, alors ils sont traités comme inexistants.

VOIR AUSSI

FICHIERS

/etc/cron.allow
/etc/cron.deny

NORMES

La commande crontab est conforme à IEEE Std1003.2-1992 (« POSIX ») avec une exception : pour remplacer le crontab actuel avec des données provenant de l'entrée standard, le - doit être spécifié sur la ligne de commande si l'entrée standard est un TTY. Cette nouvelle syntaxe de commande diffère des versions précédentes de Vixie Cron, ainsi que de la syntaxe classique SVR3.

DIAGNOSTICS

Un message d'utilisation informatif apparaît si vous exécutez un crontab avec une commande défectueuse définie en lui.
