CRLUTIL(1) Outils de sécurité NSS CRLUTIL(1)

NOM

crlutil - Lister, générer, modifier ou supprimer des CRL dans les fichiers de la base de données de sécurité NSS et lister, créer, modifier ou supprimer des entrées de certificats dans une CRL particulière.

SYNTAXE

crlutil [options] [[arguments]]

STATUT

Cette documentation est toujours en cours de développement. Veuillez contribuer à la revue initiale dans le bug 836477 de Mozilla NSS[1]

DESCRIPTION

L'outil de gestion des listes de révocation de certificats (CRL), crlutil, est un utilitaire en ligne de commande qui peut lister, générer, modifier ou supprimer des CRL dans les fichiers de la base de données de sécurité NSS, et lister, créer, modifier ou supprimer des entrées de certificats dans une CRL particulière.

Le processus de gestion des clés et des certificats commence généralement par la création de clés dans la base de données de clés, puis par la génération et la gestion des certificats dans la base de données de certificats (voir l'outil certutil), et se poursuit avec l'expiration ou la révocation des certificats.

Ce document traite de la gestion des listes de révocation de certificats. Pour des informations sur la gestion de la base de données de modules de sécurité, voir Utilisation de l'outil de gestion de la base de données de modules de sécurité. Pour des informations sur la gestion des bases de données de certificats et de clés, voir Utilisation de l'outil de gestion de la base de données de certificats.

Pour exécuter l'outil de gestion des listes de révocation de certificats, tapez la commande

crlutil option [arguments]

où options et arguments sont des combinaisons des options et arguments listés dans la section suivante. Chaque commande prend une option. Chaque option peut prendre zéro ou plusieurs arguments. Pour voir une chaîne d'aide, lancez la commande sans options, ou avec l'option -H.

OPTIONS ET ARGUMENTS

Options

Les options spécifient une action. Les arguments des options modifient une action. Les options et arguments de la commande crlutil sont définis comme suit :

-D

Supprime une liste de révocation de certificats (CRL) de la base de données de certificats.

-E

Efface toutes les CRL du type spécifié de la base de données de certificats.

-G

Crée une nouvelle liste de révocation de certificats (CRL).

-I

Importe une CRL dans la base de données de certificats.

-L

Liste les CRL existantes situées dans le fichier de la base de données de certificats.

-M

Modifie une CRL existante qui peut être située dans la base de données de certificats ou dans un fichier arbitraire. Si elle est située dans un fichier, elle doit être encodée au format ASN.1.

-S

Affiche le contenu d'un fichier CRL qui n'est pas stocké dans la base de données.

Arguments

Les arguments des options modifient une action.

-a

Utilise le format ASCII ou autorise l'utilisation du format ASCII pour l'entrée et la sortie. Ce formatage suit la RFC #1113.

-B

Ignore les vérifications de signature de l'AC.

-c fichier-script-gen-crl

Spécifie le fichier script qui sera utilisé pour contrôler la génération/modification de la CRL. Voir le format fichier-script-crl ci-dessous. Si les options -M|-G sont utilisées et que -c fichier-script-crl n'est pas spécifié, crlutil lira les données du script depuis l'entrée standard.

-d répertoire

Spécifie le répertoire de la base de données contenant les fichiers de base de données de certificats et de clés. Sur Unix, l'outil de base de données de certificats utilise par défaut $HOME/.netscape (c'est-à-dire ~/.netscape). Sous Windows NT, la valeur par défaut est le répertoire courant.

Les fichiers de base de données NSS doivent résider dans le même répertoire.

-f fichier-mot-de-passe

Spécifie un fichier qui fournira automatiquement le mot de passe à inclure dans un certificat ou à utiliser pour accéder à une base de données de certificats. Il s'agit d'un fichier texte contenant un seul mot de passe. Assurez-vous d'empêcher tout accès non autorisé à ce fichier.

-i fichier-crl

Spécifie le fichier qui contient la CRL à importer ou à afficher.

-l nom-algorithme

Spécifie un algorithme de signature spécifique. Liste des algorithmes possibles : MD2 | MD4 | MD5 | SHA1 | SHA256 | SHA384 | SHA512

-n surnom

Spécifie le surnom d'un certificat ou d'une clé à lister, créer, ajouter à une base de données, modifier ou valider. Entourez la chaîne du surnom de guillemets si elle contient des espaces.

-o fichier-sortie

Spécifie le nom du fichier de sortie pour la nouvelle CRL. Entourez la chaîne fichier-sortie de guillemets si elle contient des espaces. Si cet argument n'est pas utilisé, la destination de sortie est la sortie standard par défaut.

-P préfixe-db

Spécifie le préfixe utilisé sur les fichiers de base de données de sécurité NSS (par exemple, my_cert8.db et my_key3.db). Cette option est fournie à titre exceptionnel. Changer les noms des bases de données de certificats et de clés n'est pas recommandé.

-t type-crl

Spécifie le type de CRL. Les types possibles sont : 0 - SEC_KRL_TYPE, 1 - SEC_CRL_TYPE. Cette option est obsolète.

-u url

Spécifie l'URL.

-w chaîne-mdp

Fournit le mot de passe de la base de données en ligne de commande.

-Z algorithme

Spécifie l'algorithme de hachage à utiliser pour signer la CRL.

SYNTAXE DU SCRIPT DE GÉNÉRATION DE CRL

Le fichier script de génération de CRL a la syntaxe suivante :

* Les lignes contenant des commentaires doivent commencer par #.

* Définit les champs "cette mise à jour" ou "prochaine mise à jour" de la CRL :

update=YYYYMMDDhhmmssZ nextupdate=YYYYMMDDhhmmssZ

Le champ "prochaine mise à jour" est facultatif. L'heure doit être au format GeneralizedTime (YYYYMMDDhhmmssZ). Par exemple : 20050204153000Z

* Ajoute une extension à une CRL ou à une entrée de certificat CRL :

addext nom-extension critique/non-critique [arg1[arg2 ...]]

Où :

nom-extension : valeur de chaîne d'un nom d'extension connu. critique/non-critique : 1 si l'extension est critique et 0 sinon. arg1, arg2 : spécifiques aux paramètres de l'extension de type extension

addext utilise la plage définie précédemment par addcert et installera une extension pour chaque entrée de certificat dans la plage.

* Ajoute une ou plusieurs entrées de certificat à la CRL :

addcert plage date

plage : deux valeurs entières séparées par un tiret : plage de certificats qui seront ajoutés par cette commande. Le tiret est utilisé comme délimiteur. Un seul certificat sera ajouté s'il n'y a pas de délimiteur. date : date de révocation d'un certificat. La date doit être représentée au format GeneralizedTime (YYYYMMDDhhmmssZ).

* Supprime une ou plusieurs entrées de certificat de la CRL

rmcert plage

Où :

plage : deux valeurs entières séparées par un tiret : plage de certificats qui seront ajoutés par cette commande. Le tiret est utilisé comme délimiteur. Un seul certificat sera ajouté s'il n'y a pas de délimiteur.

* Modifie une ou plusieurs entrées de certificat dans la CRL

range nouvelle-plage

Où :

nouvelle-plage : deux valeurs entières séparées par un tiret : plage de certificats qui seront ajoutés par cette commande. Le tiret est utilisé comme délimiteur. Un seul certificat sera ajouté s'il n'y a pas de délimiteur.

Extensions Implémentées

Les extensions définies pour les CRL fournissent des méthodes pour associer des attributs supplémentaires aux CRL ou à leurs entrées. Pour plus d'informations, voir RFC #3280.

* Ajoute l'extension Identifiant de clé d'autorité :

L'extension Identifiant de clé d'autorité fournit un moyen d'identifier la clé publique correspondant à la clé privée utilisée pour signer une CRL.

authKeyId critique [id-clé | nom-dn cert-serial]

Où :

authKeyIdent : identifie le nom d'une extension. critique : valeur de 1 ou 0. Doit être défini à 1 si cette extension est critique, sinon 0. id-clé : identifiant de clé représenté sous forme de chaîne d'octets. nom-dn : nom distinctif de l'AC. cert-serial : numéro de série du certificat d'autorité.

* Ajoute l'extension Nom alternatif de l'émetteur :

L'extension Noms alternatifs de l'émetteur permet d'associer des identités supplémentaires à l'émetteur de la CRL. Les options définies incluent un nom rfc822 (adresse électronique), un nom DNS, une adresse IP et un URI.

issuerAltNames non-critique liste-noms

Où :

subjAltNames : identifie le nom de l'extension. Doit être défini à 0 car c'est une extension non critique. liste-noms : liste de noms séparés par des virgules.

* Ajoute l'extension Numéro de CRL :

Le numéro de CRL est une C

extension RL qui transmet une séquence de numéros croissante de manière monotone pour une portée de CRL et un émetteur de CRL donnés. Cette extension permet aux utilisateurs de déterminer facilement quand une CRL particulière remplace une autre

CRL

crlNumber nombre non

critique

Où

:

crlNumber : identifie le nom d'une extension critique : doit être défini à 0 car il s'agit d'une extension non critique number : valeur de long qui identifie le numéro de séquence d'une

CRL.

* Ajouter l'extension Reason Code (code de révocation)

:

reasonCode est une extension d'entrée de CRL non critique qui identifie la raison de la révocation du

certificat.

reasonCode code non

critique

Où

:

reasonCode : identifie le nom d'une extension non critique : doit être défini à 0 car il s'agit d'une extension non critique code : les codes suivants sont disponibles

:

unspecified (0), keyCompromise (1), cACompromise (2), affiliationChanged (3), superseded (4), cessationOfOperation (5), certificateHold (6), removeFromCRL (8), privilegeWithdrawn (9), aACompromise

(10)

* Ajouter l'extension Invalidity Date (date d'invalidité)

:

La date d'invalidité est une extension d'entrée de CRL non critique qui fournit la date à laquelle il est connu ou suspecté que la clé privée a été compromise ou que le certificat est devenu invalide pour autre

raison.

invalidityDate date non

critique

Où

:

crlNumber : identifie le nom d'une extension non critique : doit être défini

à 0 car il s'agit d'une extension non critique date : date d'invalidité d'un cert. La date doit être représentée au format GeneralizedTime (AAAAJJhhmmssZ).

ON

requis.

paramètres.
