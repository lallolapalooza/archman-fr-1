idmap options de

montage

Si l'option idmap est spécifiée, le montage est mappé par ID en utilisant l'espace de noms d'utilisateur cible du conteneur. Il s'agit d'une fonctionnalité expérimentale et peut changer à tout moment sans

préavis.

L'option idmap prend en charge un mappage personnalisé qui peut être différent de l'espace de noms d'utilisateur utilisé par le

conteneur.

Le mappage peut être spécifié après l'option idmap comme suit : idmap=uids=0-1-10#10-11-10;

gids=0-100-10.

Pour chaque triplet, la première valeur est le début des ID du système de fichiers de support qui sont mappés vers la deuxième valeur sur l'hôte. La longueur de ce mappage est donnée dans la troisième

valeur.

Plusieurs plages sont séparées par #

.

Ces valeurs sont écrites dans les fichiers /proc/$PID/uid_map et /proc/$PID/gid_map pour créer l'espace de noms d'utilisateur du montage mappé par

ID.

Les seules deux options actuellement prises en charge après idmap sont uids et gids

.

Lorsqu'un mappage personnalisé est spécifié, un nouvel espace de noms d'utilisateur est créé pour le montage mappé par

ID.

Si aucune option n'est spécifiée, l'espace de noms d'utilisateur du conteneur est

utilisé.

Si le mappage spécifié est préfixé par un '@', le mappage est considéré comme relatif à l'espace de noms d'utilisateur du conteneur. L'ID hôte pour le mappage est modifié pour tenir compte de la position relative de l'utilisateur du conteneur dans l'espace de noms d'utilisateur du

conteneur.

Par exemple, le mappage : uids=@1-3-10, donné une configuration

comme 
"uidMappings": [
      {
        "containerID": 0,
        "hostID": 0,
        "size": 1
      },
      {
        "containerID": 1,
        "hostID": 2,
        "size": 1000
      }
]

sera converti en la valeur absolue uids=1-4-10, où 4 est calculé en ajoutant 3 (ID du conteneur dans le mappage uids=) et 1 (hostID - containerID pour le mappage de l'espace de noms d'utilisateur où containerID = 1 est trouvé)

.

L'implémentation actuelle ne prend pas en compte plusieurs plages d'espaces de noms d'uti

lisateur ; il incombe donc à l'appelant de diviser un mappage s'il chevauche plusieurs pla
ges dans l'espace de noms d'utilisateur. Dans un tel cas, aucune erreur ne sera signalée.
