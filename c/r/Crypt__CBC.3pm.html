NOM

Crypt::CBC - Chiffrement des données avec le mode de chaînage par blocs de chiffrement

SYNOPSIS

use Crypt::CBC;
$cipher = Crypt::CBC->new( -pass   => 'my secret password',
                           -cipher => 'Cipher::AES'
                          );
# one shot mode
$ciphertext = $cipher->encrypt("This data is hush hush");
$plaintext  = $cipher->decrypt($ciphertext);
# stream mode
$cipher->start('encrypting');
open(F,"./BIG_FILE");
while (read(F,$buffer,1024)) {
    print $cipher->crypt($buffer);
}
print $cipher->finish;
# do-it-yourself mode -- specify key && initialization vector yourself
$key    = Crypt::CBC->random_bytes(8);  # assuming a 8-byte block cipher
$iv     = Crypt::CBC->random_bytes(8);
$cipher = Crypt::CBC->new(-pbkdf       => 'none',
                          -header      => 'none',
                          -key         => $key,
                          -iv          => $iv);
$ciphertext = $cipher->encrypt("This data is hush hush");
$plaintext  = $cipher->decrypt($ciphertext);
# encrypting via a filehandle (requires Crypt::FileHandle>
$fh = Crypt::CBC->filehandle(-pass => 'secret');
open $fh,'>','encrypted.txt" or die $!
print $fh "This will be encrypted\n";
close $fh;

DESCRIPTION

Ce module est une implémentation pure Perl du mode cryptographique de chaînage par blocs de chiffrement (CBC). En combinaison avec un chiffrement par blocs tel qu'AES ou Blowfish, vous pouvez chiffrer et déchiffrer des messages de longueur arbitraire. Les messages chiffrés sont compatibles avec le format de chiffrement utilisé par le OpenSSL paquet.

Pour utiliser ce module, vous créerez d'abord un objet chiffrement Crypt::CBC avec new(). Lors de la création du chiffrement, vous spécifiez une clé de chiffrement à utiliser et, optionnellement, un algorithme de chiffrement par blocs. Vous appellerez ensuite la start() méthode pour initialiser le processus de chiffrement ou de déchiffrement, crypt() pour chiffrer ou déchiffrer un ou plusieurs blocs de données, et enfin finish(), pour compléter et chiffrer le dernier bloc. Pour votre commodité, vous pouvez appeler les encrypt() et decrypt() méthodes pour opérer sur une valeur de données entière d'un coup.

$cipher = Crypt::CBC->new( -pass   => 'my secret key',

Crypt::CBC nécessite trois informations pour faire son travail. D'abord, il a besoin du nom de l'algorithme de chiffrement par blocs qui chiffrera ou déchiffrera les données en blocs de longueur fixe connue sous le nom de "taille de bloc" du chiffrement. Deuxièmement, il a besoin d'une clé de chiffrement/déchiffrement à passer au chiffrement par blocs. Troisièmement, il a besoin d'un vecteur d'initialisation (IV) qui sera utilisé pour propager l'information d'un bloc chiffré au suivant. La clé et le IV doivent être exactement de la même longueur que la taille de bloc du chiffrement choisi.

Crypt::CBC peut dériver la clé et le IV à partir d'une phrase secrète que vous fournissez, ou peut vous laisser spécifier la vraie clé et le IV manuellement. De plus, vous avez la possibilité d'intégrer suffisamment d'informations pour régénérer le IV dans un court en-tête qui est émis au début du flux chiffré, ou de produire un flux de chiffrement sans en-tête. Dans le premier cas, Crypt::CBC pourra déchiffrer le flux étant donné seulement la clé originale ou la phrase secrète. Dans le second cas, vous devrez fournir le IV original ainsi que la clé/la phrase secrète.

L' -cipher option spécifie quel algorithme de chiffrement par blocs utiliser pour encoder chaque section du message. Cet argument est optionnell et utiliseront par défaut l'algorithme sécurisé Crypt::Cipher::AES. Vous pouvez utiliser n'importe quel algorithme de chiffrement par bloc compatible que vous avez installé. Actuellement, cela inclut Crypt::Cipher::AES, Crypt::DES, Crypt::DES_EDE3, Crypt::IDEA, Crypt::Blowfish, Crypt::CAST5 et Crypt::Rijndael. Vous pouvez les référencer en utilisant leurs noms complets ("Crypt::IDEA") ou sous forme abrégée ("IDEA")

.

Au lieu de passer le nom d'une classe de chiffrement, vous pouvez passer un objet de chiffrement par bloc déjà créé. Cela vous permet de tirer parti des algorithmes de chiffrement qui ont des constructeurs new() paramétrés, tels que Crypt::Eksblowfish : my $eksblowfish = Crypt::Eksblowfish->new(8,$salt,$key); my $cbc = Crypt::CBC->new(-cipher=>$eksblowfish); L'argument -pas

L' argument -chaining_mode permet de sélectionner parmi plusieurs modes de chaînage de blocs différents. Les valeurs sont

:

'cbc' -- [défaut] le mode traditionnel de chaînage par blocs de chiffrement (Cipher-Block Chaining). Il a la propriété que si un bloc dans le message chiffré est endommagé, seul ce bloc et le suivant seront rendus indéchiffrables. 'pcbc' -- le mode de chaînage par blocs de chiffrement sur texte clair (Plaintext Cipher-Block Chaining). Il a la propriété qu'un bloc de texte chiffré endommagé rendra le reste du message illisible. 'cfb' -- le mode de rétroaction par blocs (Cipher Feedback Mode). Dans ce mode, à la fois le chiffrement et le déchiffrement sont effectués en utilisant l'algorithme "encrypt" du chiffrement par bloc. Le comportement de propagation d'erreur est similaire à celui de CBC. 'ofb' -- le mode de rétroaction de sortie (Output Feedback Mode). Similaire à CFB, l'algorithme de chiffrement du chiffrement par bloc est utilisé à la fois pour le chiffrement et le déchiffrement. Si un bit du message en clair ou chiffré est endommagé, le dommage est limité à un seul bloc du texte chiffré ou en clair correspondant, et des algorithmes de correction d'erreur peuvent être utilisés pour reconstruire la partie endommagée. 'ctr' -- le mode compteur (Counter Mode). Ce mode utilise un "nonce" (nombre utilisé une seule fois) au lieu d' un IV. Le nonce est incrémenté de un pour chaque bloc de texte en clair ou chiffré, chiffré à l'aide de l'algorithme choisi, puis appliqué au bloc de texte. Si un bit du texte d'entrée est endommagé, il n'affecte qu'un bit du texte de sortie. Pour utiliser le mode CTR, vous devrez installer le module Perl Math::Int128. Cette méthode de chaînage est environ deux fois moins rapide que les autres en raison de l'arithmétique sur les entiers. Le passage d'un argu

de valeur vraie aura le même effet que -chaining_mode=>'pcbc', et est inclus pour des raisons de compatibilité ascendante. [déprécié]. Pour plus d'informations sur les modes de chaînage, voir http://www.crypto-it.net/eng/theory/modes-of-block-ciphers.html

Méthodes de
remplissage

Utilisez l'option 'padding' pour changer la méthode de

remplissage.

Lorsque le dernier bloc de texte clair est plus court que la taille du bloc, il doit être rempli. Les méthodes de remplissage incluent : "standard" (c'est-à-dire, PKCS#5), "oneandzeroes", "space", "rijndael_compat", "null", et

"none". 
standard : (par défaut) Sûr pour les données binaires
   remplit avec le nombre d'octets qui doivent être tronqués. Ainsi, si
   la taille du bloc est 8, alors "0A0B0C" sera rempli avec "05", résultant en
   "0A0B0C0505050505". Si le dernier bloc est un bloc complet de 8
   octets, alors un bloc complet de "0808080808080808" est ajouté.
oneandzeroes : Sûr pour les données binaires
   remplit avec "80" suivi d'autant de "00" que nécessaire pour compléter le
   bloc. Si le dernier bloc est un bloc complet et que la taille du bloc est 8, un
   bloc de "8000000000000000" sera ajouté.
rijndael_compat : Sûr pour les données binaires, avec des réserves
   similaire à oneandzeroes, sauf qu'aucun remplissage n'est effectué si
   le dernier bloc est un bloc complet. Ceci est fourni pour
   la compatibilité avec le MODE_CBC intégré de Crypt::Rijndael.
   Notez que l'implémentation de CBC de Crypt::Rijndael ne
   fonctionne qu'avec des messages qui sont des multiples pairs de 16 octets.
null : uniquement pour le texte
   remplit avec autant de "00" que nécessaire pour compléter le bloc. Si le dernier
   bloc est un bloc complet et que la taille du bloc est 8, un bloc de
   "0000000000000000" sera ajouté.
space : uniquement pour le texte
   identique à "null", mais avec "20".
none :
   aucun remplissage ajouté. Utile pour les applications à usage spécial où
   vous souhaitez ajouter un remplissage
personnalisé au message.

Les remplissages standard et oneandzeroes sont tous deux sûrs pour les données binaires. Les remplissages space et null ne sont recommandés que pour les données textuelles. Le type de remplissage que vous utilisez dépend de si vous souhaitez communiquer avec une bibliothèque externe (non Crypt::CBC). Si c'est le cas, utilisez la méthode de remplissage compatible. Vous pouvez également passer une fonction de remplissage personnalisée. Pour cela, créez une fonction qui prend les arguments : $padded_block = function($block,$blocksize,$direction); où $block est le bloc de données actuel, $blocksize est la taille à laquelle le remplir, $direction est "e" pour le chiffrement et "d" pour le déchiffrement, et

$padded_block

est le résultat après remplissage ou dé-remplissage. Lors du chiffrement, la fonction doit toujours renvoyer une chaîne de longueur <blocksize>, et lors du déchiffrement, on peut s'attendre à ce que la chaîne entrante ait toujours cette longueur. Comparaison

avec Crypt
::Mode::CBC

Les modules CryptX Crypt::Mode::CBC, Crypt::Mode::OFB, Crypt::Mode::CFB, et Crypt::Mode::CTR fournissent des implémentations rapides des modes de chaînage de blocs de chiffres respectifs (environ 5 fois la vitesse de Crypt::CBC). Crypt::CBC a été conçu pour chiffrer et déchiffrer des messages d'une manière compatible avec la fonction "enc" d'OpenSSL. Par conséquent, il gère la dérivation de la clé et de l'IV à partir d'une phrase secrète en utilisant les mêmes conventions que OpenSSL, et il écrit un en-tête compatible OpenSSL dans le message chiffré d'une manière

qui permet à la clé et à l'IV d'être régénérés lors du déchiffrement.

En revanche, les modules CryptX ne dérivent pas automatiquement la clé et l'IV à partir d'une phr

ase secrète et n'écrivent pas d'en-tête chiffré. Vous devrez dériver et stocker la clé et l'IV pa
r d'autres moyens (par ex. avec le module Crypt::KeyDerivation de CryptX, ou avec Crypt::PBKDF2).
