SYNOPSI

S

cryptsetup refresh [<options>] <name>

DESCRIPTIO

N

Actualise les paramètres du mapping actif <name>

.

Met à jour les paramètres du périphérique actif <name> sans avoir besoin de désactiver le périphérique (et de démonter le système de fichiers). Actuellement, il prend en charge l'actualisation des paramètres sur les périphériques suivants : LUKS1, LUKS2 (y compris le chiffrement authentifié), crypt en mode plain et

loop-AES.

Les paramètres obligatoires sont identiques à ceux d'une action open pour le type de périphérique

respectif.

Vous pouvez modifier les paramètres suivants sur tous les périphériques --perf-same_cpu_crypt, --perf-submit_from_crypt_cpus, --perf-no_read_workqueue, --perf-no_write_workqueue et --allow-discards

.

L'actualisation du périphérique sans aucun paramètre optionnel actualisera le périphérique avec le paramètre par défaut (selon le type de périphérique)

.

LUKS2 uniquement

:

Le paramètre --integrity-no-journal n'affecte que les périphériques LUKS2 avec le périphérique dm-integrity

sous-jacent.

L'ajout de l'option --persistent enregistre toute combinaison de paramètres de périphérique ci-dessus dans les métadonnées LUKS2 (uniquement après une opération d'actualisation réussie)

.

Le paramètre --disable-keyring actualise un périphérique avec la clé de volume passée dans le pilote

dm-crypt.

<options> peut être [--allow-discards, --perf-same_cpu_crypt, --perf-submit_from_crypt_cpus, --perf-no_read_workqu

eue, --perf-no_write_workqueue, --header, --disable-keyri
ng, --disable-locks, --persistent, --integrity-no-journal].

OPTION

S

--allow-discard

s
Autorise l'utilisation des requêtes discard (TRIM) pour le périphérique. Cela n'est également pas pris en charge pour les périphériques LUKS2 avec protection d'intégrité des données.

AVERTISSEMENT : Cette commande peut avoir un impact négatif sur la sécurité car elle peut rendre les opérations au niveau du système de fichiers visibles sur le périphérique physique. Par exemple, des informations révélant le type de système de fichiers, l'espace utilisé, etc., peuvent être extraites du périphérique physique si les blocs éliminés peuvent être localisés ultérieurement. En cas de doute, ne l'utilisez

pas.

Une version du noyau de 3.1 ou supérie

ure est nécessaire. Pour les noyaux ant
érieurs, cette option est ignorée.

--batch-mode, -

q
Supprime toutes les questions de confirmation. À utiliser avec prudence !

Si l'option --verify-passphrase n'est pas

spécifiée, cette option désactive égale
ment la vérification de la phrase secrète.

--debug ou --debug-jso

n
Exécute en mode débogage avec des journaux de diagnostic complets. Les lignes de sortie de débogage sont toujours préfixées par #.

Si --debug-json est utilisé, les s

tructures de données JSON LUKS2 s
upplémentaires sont imprimées.

--disable-keyrin

g
Ne charge pas la clé de volume dans le trousseau du noyau ; la stocke directement dans la cible dm-crypt à la place. Cette option n'est prise en charge que pour le type
LUKS2.

--disable-lock

s
Désactive la protection par verrou des métadonnées sur le disque. Cette option n'est valide que pour LUKS2 et est ignorée pour les autres formats.

AVERTISSEMENT : N'utilisez pas cette option à moins d'exécuter cryptsetup dans un environnement rest

reint où le verrouillage est impossible à effectuer (
où le répertoire /run ne peut pas être utilisé).

--header <périphérique ou fichier stockant l'en-tête

LUKS>
Utilise un périphérique ou fichier de métadonnées détaché (séparé) où l'en-tête LUKS est stocké. Cette option permet de stocker le texte chiffré et l'en-tête LUKS sur des périphériques différents.

Pour les commandes qui modifient l'en-tête LUKS (par ex., luksAddKey), spécifiez directement le périphérique ou le

fichier avec l'en-tête LUKS
comme périphérique LUKS.

--help, -

?
Affiche le texte d'aide et les paramètres par
défaut.

--integrity-no-journa

l
Active le périphérique avec protection d'intégrité sans utiliser de journal de données (écriture directe des données et des étiquettes d'intégrité). Notez que sans journal, une panne de courant peut provoquer des écritures non atomiques et une corruption des données. À utiliser uniquement si la journalisation est effectuée sur une couche de stockage
différente.

--perf-high_priorit

y
Définit les files de travail dm-crypt et le thread d'écriture en priorité haute. Cela améliore le débit et la latence de dm-crypt tout en dégradant la réactivité générale du système.

Cette option n'est disponible que pour le réglage fin des performances de dm-crypt de

bas niveau, à utiliser uniquement si vous avez besoin d'un changement du compor
tement par défaut de dm-crypt. Nécessite le noyau 6.10 ou une version ultérieure.

--perf-no_read_workqueue, --perf-no_write_workqueu

e
Contourne la file de travail interne de dm-crypt et traite les requêtes de lecture ou d'écriture de manière synchrone.

Ces options ne sont disponibles que pour le réglage fin des performances de dm-crypt

de bas niveau, à utiliser uniquement si vous avez besoin d'un changement du compo
rtement par défaut de dm-crypt. Nécessite le noyau 5.9 ou une version ultérieure.

--perf-same_cpu_cryp

t
Effectue le chiffrement en utilisant le même CPU sur lequel l'E/S a été soumise. Par défaut, une file de travail non liée est utilisée afin que le travail de chiffrement soit automatiquement équilibré entre les CPU disponibles.

Cette option n'est disponible que pour le réglage fin des performa

nces de dm-crypt de bas niveau, à utiliser uniquement si vous a
vez besoin d'un changement du comportement par défaut de dm-crypt.

--perf-submit_from_crypt_cpu

s
Délègue les écritures à un thread séparé après le chiffrement. Il existe des situations où le déchargement des bios d'écrition des threads de chiffrement vers un seul thread dégrade considérablement les performances. Par défaut, les bios d'écriture sont déchargés vers le même thread.

Cette option n'est disponible que pour le réglage fin des performa

nces de dm-crypt de bas niveau, à utiliser uniquement si vous a
vez besoin d'un changement du comportement par défaut de dm-crypt.

--persisten

t
S'il est utilisé avec des périphériques LUKS2 et des commandes d'activation comme open ou refresh, les indicateurs d'activation spécifiés sont écrits de manière persistante dans les métadonnées et utilisés automatiquement la prochaine fois, même pour une activation normale. (Pas besoin d'utiliser cryptab ou d'autres fichiers de configuration système.)

Si vous devez supprimer un indicateur persistant, utilisez --persistent sans l'indicateur que vous souhaitez supprimer (par ex., pour désactiver l'indicateur discard stocké de manière persistante, utilisez --persistent sans --allow-discards)

.

Seuls --allow-discards, --perf-same_cpu_crypt, --perf-submit_from_c

rypt_cpus, --perf-no_read_workqueue, --perf-no_write_workqueue et
--integrity-no-journal peuvent être stockés de manière persistante.
