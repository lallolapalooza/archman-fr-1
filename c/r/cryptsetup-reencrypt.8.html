CRYPTSETUP-REENCRYPT(8) Commandes de maintenance CRYPTSETUP-REENCRYPT(8)

NOM

cryptsetup-reencrypt - Réencrypte les volumes chiffrés LUKS sur place

SYNTAXE

cryptsetup reencrypt [<options>] <périphérique> ou --nom-actif <nom> [<nouveau_nom>]

DESCRIPTION

Exécute la réencrytion d'un périphérique LUKS.

Il existe 3 modes d'opération de base :

• Réencrytion du périphérique (reencrypt)
• Chiffrement du périphérique (reencrypt --encrypt/--new/-N)
• Déchiffrement du périphérique (reencrypt --decrypt)

<périphérique> ou --nom-actif <nom> (LUKS2 uniquement) est un paramètre obligatoire.

L'action reencrypt de Cryptsetup peut être utilisée pour modifier les paramètres de réencrytion, qui nécessitent autrement une modification complète des données sur le disque (réencrytion). L'action reencrypt réencrypte les données sur le périphérique LUKS sur place.

Vous pouvez régénérer la **clé de volume** (la clé réelle utilisée dans le chiffrement sur disque déverrouillé par le mot de passe), le **chiffrement**, le **mode de chiffrement** ou la **taille des secteurs de chiffrement** (LUKS2 uniquement).

Si vous devez utiliser à la fois luksChangeKey et reencrypt (par exemple, pour récupérer d'une fuite), vous devez les utiliser dans cet ordre pour éviter de fuiter la nouvelle clé de volume.

Le processus de réencrytion peut être interrompu en toute sécurité par un utilisateur via le signal SIGINT (Ctrl+C). Il en va de même pour le signal SIGTERM (c'est-à-dire émis par systemd lors de l'arrêt du système).

Pour le mode de chiffrement sur place, l'action reencrypt prend en outre toutes les options disponibles pour l'action luksFormat pour la version LUKS respective (voir la page man cryptsetup-luksFormat pour plus de détails). Voir cryptsetup-luksFormat(8).

Notez que pour les modes de chiffrement et de déchiffrement, le périphérique entier doit être traité comme non chiffré — il n'y a aucune garantie de confidentialité car une partie du périphérique contient des données en clair.

ASSUREZ-VOUS TOUJOURS D'AVOIR UNE SAUVEGARDE FIABLE AVANT D'UTILISER CETTE ACTION SUR UN PÉRIPHÉRIQUE LUKS.

<options> peut inclure : [--mode-batch, --taille-bloc, --chiffrement, --debug, --debug-json, --decrypt, --taille-périphérique, --desactiver-verrous, --encrypt, --forcer-reencrypt-hors-ligne, --hachage, --en-tete, --taille-zone-active, --temps-iter, --init-seulement, --garder-cle, --fichier-cle, --taille-cle, --slot-cle, --decalage-fichier-cle, --taille-fichier-cle, --essais, --delai, --pbkdf, --iter-pbkdf-forcer, --memoire-pbkdf, --parallele-pbkdf, --frequence-progression, --progression-json, --reduire-taille-périphérique, --resilience, --hachage-resilience, --resume-seulement, --taille-secteur, --utiliser-directio, --utiliser-aleatoire, --utiliser-urandom, --utiliser-fsync, --uuid, --verbose, --fichier-cle-volume, --ecrire-log].

RÉENCRYPTION LUKS2

Avec le paramètre <périphérique>, cryptsetup recherche le mappage actif <périphérique> dm. Si aucun mappage actif n'est détecté, il démarre la réencrytion LUKS2 hors ligne ; sinon, la réencrytion en ligne se produit.

Pour reprendre une réencrytion déjà initialisée ou interrompue, exécutez simplement à nouveau la commande cryptsetup reencrypt pour continuer l'opération de réencrytion. La réencrytion peut être reprise avec des valeurs différentes pour --resilience ou --taille-zone-active, sauf si le mode de résilience de décalage de données implicite est utilisé : soit en mode chiffrement avec l'option --reduire-taille-périphérique, soit en mode déchiffrement avec l'en-tête LUKS2 d'origine exporté dans le fichier --en-tete.

Si le processus de réencrytion a été interrompu brusquement (crash du processus de réencrytion, crash système ou coupure de courant), il peut nécessiter une récupération. La récupération est lancée automatiquement lors de la prochaine activation (action open) lorsque nécessaire ou explicitement par l'utilisateur (action repair).

Le paramètre optionnel <nouveau_nom> prend effet uniquement avec l'option de chiffrement, et il active le périphérique <nouveau_nom> immédiatement après la fin de l'initialisation du chiffrement. C'est utile lorsque le périphérique doit être prêt le plus rapidement possible et monté (utilisé) avant que le chiffrement complet de la zone de données ne soit terminé.

RÉENCRYPTION LUKS1

Le répertoire de travail courant doit être accessible en écriture, et les fichiers temporaires créés pendant la réencrytion doivent être présents. Pendant la réencrytion, le périphérique LUKS1 est marqué comme indisponible et doit être hors ligne (pas de mappage dm-crypt ou de système de fichiers monté).

ATTENTION : Le code de réencrytion LUKS1 n'est pas résistant aux pannes matérielles ou du noyau pendant la réencrytion (vous pourriez perdre vos données dans ce cas).

OPTIONS

--align-payload <nombre de secteurs de 512 octets> (OBSOLÈTE, utiliser --offset)

Aligne la charge utile à une frontière de valeur secteurs de 512 octets.

Si non spécifié, cryptsetup essaie d'utiliser les informations de topologie fournies par le noyau pour le périphérique sous-jacent afin d'obtenir un alignement optimal. Si non disponible (ou si la valeur calculée est un multiple de la valeur par défaut), les données sont par défaut alignées sur une frontière de 1 Mio (c'est-à-dire 2048 secteurs de 512 octets).

Pour un en-tête LUKS détaché, cette option spécifie le décalage sur le périphérique de données. Voir également l'option --en-tete.

Cette option est OBSOLÈTE et a un impact inattendu sur le décalage des données et la taille de la zone de clés (pour LUKS2) en raison de l'arrondi complexe. Pour un décalage fixe du périphérique de données, utiliser l'option --offset à la place.

--mode-batch, -q

Supprime toutes les questions de confirmation. À utiliser avec précaution !

Si l'option --verifier-mot-de-passe n'est pas spécifiée, cette option désactive également la vérification du mot de passe.

--taille-bloc valeur (LUKS1 uniquement)

Utilise une taille de bloc de réencrytion de valeur en Mio.

Les valeurs peuvent être comprises entre 1 et 64 Mio.

--chiffrement, -c <spec-chiffrement>

LUKS2 : Définit la chaîne de spécification du chiffrement pour le segment de données uniquement.

LUKS1 : Définit la chaîne de spécification du chiffrement pour le segment de données et les slots de clés.

Le chiffrement par défaut est appliqué si la spécification de chiffrement est omise en mode chiffrement.

En mode réencrytion, si aucune nouvelle spécification de chiffrement n'est demandée, le chiffrement existant sera conservé. La seule exception est si le chiffrement est « cipher_null », auquel cas le chiffrement par défaut est utilisé.

cryptsetup --help affiche les valeurs par défaut compilées.

Si un hachage fait partie de la spécification du chiffrement, il est alors utilisé dans le cadre de la génération de l'IV. Par exemple, ESSIV a besoin d'une fonction de hachage, tandis que « plain64 » n'en a pas besoin et n'en spécifie donc aucune.

Pour le mode XTS, vous pouvez éventuellement définir une taille de clé de 512 bits avec l'option -s. La taille de clé pour le mode XTS est le double de celle des autres modes pour le même niveau de sécurité.

--debug ou --debug-json

Exécute en mode débogage avec des journaux de diagnostic complets. Les lignes de sortie de débogage sont toujours préfixées par #.

Si --debug-json est utilisé, des structures de données JSON LUKS2 supplémentaires sont imprimées.

--decrypt

Initialise (et exécute) le mode de déchiffrement du périphérique.

--taille-périphérique taille[unités]

Au lieu de la taille réelle du périphérique, utilisez la valeur spécifiée. Cela signifie que seule la zone spécifiée (du début du périphérique à la taille spécifiée) sera réencrypée.

LUKS2 : Lorsque utilisé avec --reduire-taille-périphérique, seule la valeur initiale de taille (--paramètre taille-périphérique) des données est décalée vers l'arrière tout en étant chiffrée.

La somme des valeurs --taille-périphérique et --reduire-taille-périphérique ne doit pas dépasser la taille réelle du périphérique.

ATTENTION : Ceci est une opération destructive. Les données au-delà de la limite --taille-périphérique peuvent être perdues une fois l'opération terminée.

Si aucun suffixe d'unité n'est spécifié, la taille est en octets.

Le suffixe d'unité peut être S pour les secteurs de 512 octets, K/M/G/T (ou KiB, MiB, GiB, TiB) pour les unités de base 1024 ou KB/MB/GB/TB pour la base 1000 (échelle SI).

--desactiver-blkid

Désactive l'utilisation de la bibliothèque blkid pour vérifier et effacer les signatures sur disque.

--desactiver-keyring

Ne charge pas la clé de volume dans le keyring du noyau ; stocke-la directement dans la cible dm-crypt à la place. Cette option n'est prise en charge que pour le type LUKS2.

--desactiver-verrous

Désactive la protection par verrouillage des métadonnées sur disque. Cette option n'est valide que pour LUKS2 et est ignorée pour les autres formats.

Lorsque les verrous sont désactivés, les images LUKS2 dans des fichiers peuvent être entièrement (ré)chiffrées o

ffline sans nécessiter de privilèges superutilisateur à condition que les chiffrements par bloc utilisés soient disponibles dans le backend cryptographique.

ATTENTION : N'utilisez pas cette option à moins que vous n'exécutiez cryptsetup dans un environnement restreint où le verrouillage ne peut pas être effectué (où le répertoire /run ne peut pas être utilisé).

--encrypt, --new, -N

Initialise (et exécute) le périphérique en mode de chiffrement sur place.

--force-no-keyslots (LUKS2 uniquement)

Force l'initialisation de l'opération de réchiffrement avec des paramètres supplémentaires --volume-key-file, --new-volume-key-file, --volume-key-keyring ou --new-volume-key-keyring. Cela entraînerait la suppression de tous les emplacements de clés LUKS2 restants contenant la clé du volume.

Un emplacement de clé LUKS2 avec la nouvelle clé de volume peut être ajouté une fois l'opération de réchiffrement terminée. Voir la commande cryptsetup-luksAddKey(8).

ATTENTION : Utilisez avec une extrême prudence ! Si vous perdez la clé du volume stockée dans un fichier ou dans un keyring du noyau avant d'ajouter l'emplacement de clé LUKS2 contenant la nouvelle clé de volume, le périphérique deviendra inutilisable et toutes les données seront perdues.

--force-offline-reencrypt (LUKS2 uniquement)

Ignore la détection automatique active du périphérique et force le réchiffrement hors ligne.

Cette option est particulièrement utile pour le réchiffrement d'images LUKS2 placées dans des fichiers (la détection automatique n'est pas fiable dans ce scénario).

Elle peut également aider au cas où la détection automatique active du périphérique sur un périphérique de données particulier ne fonctionne pas ou signale des erreurs.

ATTENTION : Utilisez avec une extrême prudence ! Cela peut détruire des données si le périphérique est activé et/ou utilisé activement.

--force-password

N'utilise pas le contrôle de qualité des mots de passe pour les nouveaux mots de passe LUKS.

Cette option est ignorée si cryptsetup est compilé sans prise en charge du contrôle de qualité des mots de passe.

Pour plus d'informations sur le contrôle de qualité des mots de passe, voir les pages de manuel pwquality.conf(5) et passwdqc.conf(5).

--hash, -h <spécification-hash>

LUKS1 : Spécifie le hash utilisé dans le schéma de configuration de clé LUKS1 et le digest de la clé du volume.

Si ce paramètre n'est pas spécifié, l'algorithme de hachage par défaut est toujours utilisé pour un nouvel en-tête de périphérique LUKS1.

LUKS2 : Ignoré à moins que l'algorithme du nouvel emplacement de clé pbkdf ne soit défini sur PBKDF2 (voir --pbkdf).

--header <périphérique ou fichier stockant l'en-tête LUKS>

Utilise un périphérique ou un fichier de métadonnées détaché (séparé) où l'en-tête LUKS est stocké. Cette option permet de stocker le texte chiffré et l'en-tête LUKS sur des périphériques différents.

Si elle est utilisée avec l'option --encrypt/--new, le fichier d'en-tête sera créé (ou écrasé). À utiliser avec précaution.

LUKS2 : En mode de déchiffrement, l'option peut être utilisée pour exporter l'en-tête LUKS2 d'origine vers un fichier détaché. Le fichier futur passé ne doit pas exister au moment de l'initialisation de l'opération de déchiffrement. Cela libère de l'espace en tête du périphérique de données afin que les données puissent être déplacées à l'emplacement d'origine de l'en-tête LUKS2. Plus tard, l'opération de déchiffrement continue comme si un en-tête détaché ordinaire avait été passé.

ATTENTION : Ne placez jamais un fichier d'en-tête exporté dans un système de fichiers au-dessus du périphérique que vous êtes sur le point de déchiffrer ! Cela provoquerait un interblocage.

--help, -?

Affiche le texte d'aide et les paramètres par défaut.

--hotzone-size taille (LUKS2 uniquement)

Cette option peut être utilisée pour définir une limite supérieure à la taille de la zone de réchiffrement (zone active). La taille peut être spécifiée avec un suffixe d'unité (par exemple, 50M). Notez que la taille réelle de la zone active peut être inférieure à la taille spécifiée <taille> en raison d'autres limitations (espace libre dans la zone des emplacements de clés ou mémoire disponible).

Avec le mode de déchiffrement pour les périphériques dont l'en-tête LUKS2 est placé en tête du périphérique de données, l'option spécifie la taille du premier segment de données déplacé à partir du pointeur de décalage de données d'origine.

--init-only (LUKS2 uniquement)

Initialise uniquement l'opération de réchiffrement (quel que soit le mode) dans les métadonnées LUKS2 et quitte. Si une opération de réchiffrement est déjà initialisée dans les métadonnées, la commande avec le paramètre --init-only échoue.

--iter-time, -i <nombre de millisecondes>

Le nombre de millisecondes à consacrer au traitement de la phrase secrète PBKDF pour le nouvel en-tête LUKS.

--keep-key

LUKS2 : Ne modifie pas la clé de volume effective et modifie d'autres paramètres si demandé.

LUKS1 : Ne fait que réchiffrer l'en-tête et les emplacements de clés LUKS1. Saute le réchiffrement des données sur place.

--key-file, -d fichier

Lit la phrase secrète à partir du fichier.

Si le nom donné est "-", alors la phrase secrète sera lue depuis stdin. Dans ce cas, la lecture ne s'arrêtera pas aux caractères de nouvelle ligne.

L'option --key-file ne peut être utilisée que s'il n'y a qu'un seul emplacement de clé actif, ou alternativement, également si l'option --key-slot est spécifiée (alors tous les autres emplacements de clés seront désactivés dans le nouveau périphérique LUKS).

Si cette option n'est pas utilisée, cryptsetup demandera les phrases secrètes de tous les emplacements de clés actifs.

--keyfile-offset valeur

Ignore valeur octets au début du fichier clé.

--keyfile-size, -l valeur

Lit un maximum de valeur octets à partir du fichier clé. La valeur par défaut est de lire le fichier entier jusqu'à la limite compilée qui peut être interrogée avec --help. Fournir plus de données que la limite compilée interrompt l'opération.

Cette option est utile pour couper les nouvelles lignes finales, par exemple. Si --keyfile-offset est également donné, le comptage de la taille commence après le décalage.

--key-size, -s bits

LUKS2 : Fournit la taille de clé actuelle en bits. L'argument doit être un multiple de 8. Utile lors de la spécification de la taille de la clé de volume actuelle lorsqu'aucun emplacement de clé n'est actif.

LUKS1 : Voir --new-key-size.

--key-slot, -S <0-N>

Pour les opérations LUKS qui ajoutent du matériel de clé, cette option vous permet de spécifier quel emplacement de clé est sélectionné pour la nouvelle clé.

Pour le mode de réchiffrement, il sélectionne un emplacement de clé spécifique (et une phrase secrète) qui peut être utilisé pour déverrouiller la nouvelle clé de volume. S'il est utilisé, tous les autres emplacements de clés seront supprimés une fois l'opération de réchiffrement terminée.

Le nombre maximum d'emplacements de clés dépend de la version LUKS. LUKS1 peut avoir jusqu'à 8 emplacements de clés. LUKS2 peut avoir jusqu'à 32 emplacements de clés en fonction de la taille de la zone des emplacements de clés et de la taille de la clé, mais un identifiant d'emplacement de clé valide peut toujours être compris entre 0 et 31 pour LUKS2.

--keyslot-cipher <spécification-chiffrement>

Cette option peut être utilisée pour définir un chiffrement spécifique pour la zone des emplacements de clés LUKS2.

--keyslot-key-size <bits>

Cette option peut être utilisée pour définir une taille de clé spécifique pour la zone des emplacements de clés LUKS2.

--label <étiquette>, --subsystem <sous-système>

Définit l'étiquette et la description du sous-système pour le périphérique LUKS2. Ceux-ci sont similaires aux étiquettes de système de fichiers. L'étiquette et le sous-système sont des champs facultatifs et peuvent être utilisés plus tard dans les scripts udev pour déclencher des actions utilisateur une fois le périphérique marqué par ces étiquettes détecté.

--luks2-keyslots-size taille

Cette option peut être utilisée pour définir une taille spécifique de la zone binaire des emplacements de clés LUKS2 (le matériel de clé y est chiffré). La valeur doit être alignée sur un multiple de 4096 octets avec une taille maximale de 128 Mo. La <taille> peut être spécifiée avec un suffixe d'unité (par exemple, 128k).

--luks2-metadata-size taille

Cette option peut être utilisée pour agrandir la zone de métadonnées (JSON) LUKS2. La taille comprend 4096 octets pour les métadonnées binaires (la zone JSON utilisable est plus petite que la zone binaire). Conformément à la spécification LUKS2, seules les valeurs suivantes sont valides : 16, 32, 64, 128, 256, 512, 1024, 2048 et 4096 Ko. La <taille> peut être spécifiée avec un suffixe d'unité (par exemple, 128k).

--new-key-size bits

Définit la nouvelle taille de clé en bits. L'argument doit être un multiple de 8. Les tailles de clé possibles sont limitées par le nouveau chiffrement et le mode utilisés lors du réchiffrement.

Voir /proc/crypto pour plus d'informations. Notez que la taille de clé dans /proc/crypto est indiquée en octets.

LUKS1 : Si vous augmentez la taille de clé, il doit y avoir suffisamment d'espace dans l'en-tête LUKS pour les emplacements de clés agrandis (le décalage de données doit être suffisamment grand), sinon le réchiffrement ne pourra pas être effectué.

S'il n'y a pas assez d'espace pour les emplacements de clés avec la nouvelle taille de clé, vous pouvez réduire le périphérique de manière destructive avec l'option --reduce-device-size.

--new-volume-key-file fichier

Utilise (définit) la nouvelle clé de volume stockée dans un fichier. L'option doit être associée au paramètre --new-key-size lors de l'initialisation de l'opération de réchiffrement.

ATTENTION : Si vous créez votre propre clé de volume, vous devez vous assurer de le faire correctement. Sinon, vous pourriez vous retrouver avec une clé de volume de faible entropie ou partiellement prévisible, ce qui compromettrait la sécurité.

--new-volume-key-keyring <description de clé>

Utilise (définit) la nouvelle clé de volume stockée dans un keyring.

La taille de la clé stockée dans un keyring doit être compatible avec le nouveau chiffrement utilisé dans l'opération de réchiffrement. Voir /proc/crypto pour plus d'informations. Notez que la taille de clé dans /proc/crypto est indiquée en octets.

La <description de clé> utilise la syntaxe compatible avec keyctl. Il peut s'agir d'un identifiant de clé numérique ou d'un nom de chaîne au format %<type de clé>:<nom de clé>. Voir également la section IDENTIFIANTS DE CLÉ de keyctl(1). Lorsqu'aucun préfixe %<type de clé>: n'est spécifié, nous supposons que le type de clé est user (type par défaut).

ATTENTION : Si vous créez votre propre clé de volume, vous devez vous assurer de le faire correctement. Sinon, vous pourriez vous retrouver avec une clé de volume de faible entropie ou partiellement prévisible, ce qui compromettrait la sécurité.

--offset, -o <nombre de secteurs de 512 octets>

Décalage de départ dans le périphérique backend en secteurs de 512 octets. Cette option n'est pertinente que pour le mode de chiffrement.

L'option --offset définit le décalage des données (charge utile) du périphérique de données et doit être alignée sur des secteurs de 4096 octets (doit être un multiple de 8). Cette option ne peut pas être combinée avec l'option --align-payload.

--pbkdf <spécification PBKDF>

Définit la fonction de dérivation de clé basée sur mot de passe (PBKDF) pour l'emplacement de clé LUKS. Le PBKDF peut
be : pbkdf2 (pour PBKDF2 selon RFC2898), argon2i pour Argon2i ou argon2id pour Argon2id (voir Argon2 https://www.cryptolux.org/index.php/Argon2 pour plus d'informations).

Pour LUKS1, seul PBKDF2 est accepté (pas besoin d'utiliser cette option). PBKDF par défaut pour LUKS2 est défini au moment de la compilation et est disponible dans la sortie de cryptsetup --help.

Un PBKDF est utilisé pour augmenter le coût des attaques par dictionnaire et par force brute des mots de passe des clés. Les paramètres peuvent être le temps, la mémoire et le coût parallèle.

Pour PBKDF2, seul le coût temporel (nombre d'itérations) s'applique. Pour Argon2i/id, il y a aussi le coût mémoire (mémoire requise pendant le processus de dérivation de clé) et le coût parallèle (nombre de threads exécutés en parallèle pendant la dérivation de clé).

Notez que l'augmentation du coût mémoire augmente également le temps, donc les valeurs finales des paramètres sont mesurées par un benchmark. Le benchmark tente de trouver le temps d'itération (--iter-time) avec le coût mémoire requis --pbkdf-memory. Si ce n'est pas possible, le coût mémoire est également diminué. Le coût parallèle --pbkdf-parallel est constant et est vérifié par rapport aux cœurs CPU disponibles.

Vous pouvez voir tous les paramètres PBKDF pour un slot de clé LUKS2 particulier avec la commande cryptsetup-luksDump(8).

Si vous ne souhaitez pas utiliser le benchmark et souhaitez spécifier tous les paramètres directement, utilisez --pbkdf-force-iterations avec --pbkdf-memory et --pbkdf-parallel. Cela remplacera les valeurs sans benchmark. Notez que cela peut entraîner un temps de déverrouillage extrêmement long ou des conditions de manque de mémoire avec une terminaison de processus inconditionnelle. À utiliser uniquement dans des cas spécifiques, par exemple, si vous savez que le périphérique formaté sera utilisé sur un petit système embarqué.

COÛTS PBKDF MINIMAUX ET MAXIMAUX : Pour PBKDF2, le nombre minimum d'itérations est de 1000 et le maximum est de 4294967295 (maximum pour un entier non signé de 32 bits). Les coûts mémoire et parallèle ne sont pas pris en charge pour PBKDF2. Pour Argon2i et Argon2id, le nombre minimum d'itérations (coût CPU) est de 4 et le maximum est de 4294967295 (maximum pour un entier non signé de 32 bits). Le coût mémoire minimum est de 32 KiB et le maximum est de 4 GiB. Si le paramètre de coût mémoire est benchmarké (non spécifié par un paramètre), il se situe toujours dans la plage de 64 MiB à 1 GiB. Un coût mémoire supérieur à 1 Go (jusqu'au maximum de 4 Go) ne peut être configuré qu'avec le paramètre --pbkdf-memory. Le coût parallèle minimum est de 1 et le maximum de 4 (si suffisamment de cœurs CPU sont disponibles, sinon il est diminué par les cœurs CPU disponibles).

AVERTISSEMENT : Augmenter les coûts de calcul PBKDF au-delà des limites mentionnées apporte une amélioration négligeable de la sécurité. Bien que des coûts élevés augmentent considérablement la surcharge des attaques par force brute, ils offrent une protection négligeable contre les attaques par dictionnaire. L'augmentation marginale des coûts pour le traitement d'un dictionnaire entier reste fondamentalement insuffisante.

Les limites PBKDF codées en dur représentent des compromis techniques entre la sécurité cryptographique et l'utilisabilité opérationnelle. LUKS maintient la portabilité et doit être utilisé dans un délai raisonnable sur des systèmes aux ressources limitées.

Cryptsetup restreint délibérément les paramètres de coût mémoire maximum (4 GiB) et de coût parallèle (4) en raison de limitations architecturales (telles que les systèmes embarqués et hérités).

Le coût mémoire PBKDF impose une allocation réelle de RAM physique avec des opérations d'écriture intensives qui doivent rester en RAM physique. Toute utilisation de swap entraîne une dégradation inacceptable des performances. La gestion de la mémoire suralloue souvent des allocations au-delà de la mémoire physique disponible, en s'attendant à ce que la plupart de la mémoire allouée reste inutilisée. Dans de telles situations, comme PBKDF utilise toujours toute la mémoire allouée, il provoque fréquemment des échecs de manque de mémoire qui interrompent les opérations cryptsetup.

--pbkdf-force-iterations nombre

Évite le benchmark PBKDF et définit directement le coût temporel (itérations). Il ne peut être utilisé que pour un périphérique LUKS/LUKS2. Voir l'option --pbkdf pour plus d'informations.

--pbkdf-memory nombre

Définit le coût mémoire pour PBKDF (pour Argon2i/id, le nombre représente des kilo-octets). Notez qu'il s'agit de la valeur maximale ; le benchmark PBKDF ou la mémoire physique disponible peuvent la diminuer. Cette option n'est pas disponible pour PBKDF2.

--pbkdf-parallel nombre

Définit le coût parallèle pour PBKDF (nombre de threads, jusqu'à 4). Notez qu'il s'agit de la valeur maximale ; elle est automatiquement diminuée si le nombre de cœurs CPU en ligne est inférieur. Cette option n'est pas disponible pour PBKDF2.

--progress-frequency secondes

Affiche une ligne séparée toutes les secondes avec la progression du ré-chiffrement.

--progress-json

Affiche les données de progression au format JSON, ce qui convient principalement au traitement par machine. Il affiche une ligne séparée toutes les demi-secondes (ou en fonction de la valeur de --progress-frequency). La sortie JSON ressemble à ceci pendant la progression (sauf qu'il s'agit d'une seule ligne compacte) : 
{
  "device":"/dev/sda",      // périphérique ou fichier sous-jacent
  "device_bytes":"8192",    // octets d'E/S jusqu'à présent
  "device_size":"44040192", // octets totaux d'E/S à venir
  "speed":"126877696",      // vitesse calculée en octets par seconde (basée sur la progression jusqu'à présent)
  "eta_ms":"2520012",       // temps estimé pour terminer une opération en millisecondes
  "time_ms":"5561235"       // temps total passé dans l'opération d'E/S en millisecondes
}

Remarque sur les nombres dans la sortie JSON : En raison des limitations du analyseur JSON, tous les nombres sont représentés sous forme de chaînes de caractères en raison de la nécessité d'entiers non signés de 64 bits complets.

--reduce-device-size taille

Cela signifie que les taille derniers secteurs du périphérique d'origine seront perdus, et les données seront effectivement décalées du nombre spécifié de secteurs.

Cela peut être utile si vous avez ajouté de l'espace à la partition sous-jacente ou au volume logique (de sorte que les derniers taille secteurs ne contiennent aucune donnée).

Pour le suffixe d'unités, voir la description du paramètre --device-size.

AVERTISSEMENT : Il s'agit d'une opération destructive et irréversible. À utiliser avec une extrême prudence - les systèmes de fichiers accidentellement écrasés sont généralement irrécupérables.

LUKS2 : Initialise le ré-chiffrement LUKS2 avec une réduction de la taille du périphérique de données (actuellement, seul le mode de chiffrement est pris en charge). Les taille derniers secteurs du périphérique en clair d'origine sont utilisés pour stocker temporairement le premier segment de données d'origine. L'ancien premier segment de données est remplacé par un en-tête LUKS2 (la moitié de la valeur de taille), et les données en clair sont décalées vers l'arrière (encore la moitié de la valeur de taille) pendant le chiffrement.

La taille minimale recommandée est le double de la taille par défaut de l'en-tête LUKS2 (--reduce-device-size 32M) pour le mode de chiffrement.

La somme des valeurs de --device-size et --reduce-device-size ne doit pas dépasser la taille réelle du périphérique.

LUKS1 : Augmente le décalage des données à la valeur spécifiée en réduisant la taille du périphérique.

Vous ne pouvez pas réduire le périphérique de plus de 64 MiB (131072 secteurs).

--resilience mode (LUKS2 uniquement)

Le mode de résilience de ré-chiffrement peut être checksum, journal ou none.

checksum : mode par défaut, où les sommes de contrôle individuelles des secteurs de la zone active du texte chiffré sont stockées, de sorte que le processus de récupération peut détecter quels secteurs ont déjà été ré-chiffrés. Cela nécessite que l'écriture des secteurs du périphérique soit atomique.

journal : La zone active est journalisée dans la zone binaire (donc les données sont écrites deux fois).

none : Mode performance. Il n'y a pas de protection, et la seule façon d'interrompre le ré-chiffrement en toute sécurité est similaire à un ancien utilitaire de ré-chiffrement hors ligne.

Les modes de résilience peuvent être modifiés sauf si le mode datashift est utilisé pour l'initialisation de l'opération (chiffrement avec l'option --reduce-device-size).

--resilience-hash hash (LUKS2 uniquement)

L'algorithme de hash est utilisé uniquement avec "--resilience checksum". Le hash par défaut est sha256. Avec d'autres modes de résilience, le paramètre de hash est ignoré.

--resume-only (LUKS2 uniquement)

Reprend l'opération de ré-chiffrement (quel que soit le mode) déjà décrite dans les métadonnées LUKS2. Si aucune opération de ré-chiffrement n'est initialisée, la commande avec le paramètre --resume-only échoue. Utile pour reprendre l'opération de ré-chiffrement sans déclencher accidentellement une nouvelle opération de ré-chiffrement.

--sector-size octets (LUKS2 uniquement)

Ré-chiffre le périphérique avec une nouvelle taille de secteur de chiffrement appliquée.

AVERTISSEMENT : Augmenter la taille du secteur de chiffrement peut endommager le système de fichiers hébergé. Ne lancez pas de ré-chiffrement avec --force-offline-reencrypt si vous n'êtes pas sûr de la taille de bloc avec laquelle le système de fichiers a été formaté.

Notez que l'utilisation d'une taille de secteur supérieure à la taille de secteur physique du périphérique de stockage sous-jacent peut entraîner une corruption des données en cas de pannes de courant inattendues. Une panne de courant pendant les opérations d'écriture peut entraîner une achèvement partiel de l'écriture du secteur de chiffrement, laissant les données chiffrées dans un état incohérent qui ne peut pas être correctement déchiffré.

--timeout, -t secondes

Le nombre de secondes à attendre avant un délai d'expiration pour la saisie du mot de passe via le terminal. Il est pertinent chaque fois qu'un mot de passe est demandé. Il n'a aucun effet s'il est utilisé en conjonction avec --key-file.

Cette option est utile lorsque le système ne doit pas se bloquer si l'utilisateur n'entre pas de mot de passe, par exemple, au démarrage. La valeur par défaut est de 0 seconde, ce qui signifie attendre indéfiniment.

--token-id

Initialisation du ré-chiffrement LUKS2 : Spécifie quels slots de clé (associés au jeton sélectionné) utiliser pour le ré-chiffrement LUKS2. Si l'opération de ré-chiffrement modifie la clé de volume effective, seuls les slots de clé associés au jeton et déverrouillés avec succès seront disponibles une fois l'opération de ré-chiffrement terminée.

Reprise du ré-chiffrement LUKS2 : Spécifie quel jeton utiliser et autorise l'invite PIN du jeton à avoir la priorité sur l'invite interactive du mot de passe du slot de clé. S'il est omis, tous les jetons disponibles (non protégés par PIN) seront vérifiés avant de poursuivre avec l'invite du mot de passe.

--token-only

Initialisation du ré-chiffrement LUKS2 : Spécifie que tous les slots de clé associés à un jeton seront utilisés pour le ré-chiffrement LUKS2. Si l'opération de ré-chiffrement modifie la clé de volume effective, seuls les slots de clé associés à un jeton seront disponibles une fois l'opération de ré-chiffrement terminée.

Reprise du ré-chiffrement LUKS2 : Ne pas poursuivre l'action si le déverrouillage du slot de clé basé sur un jeton a échoué. Sans l'option, l'action demande un mot de passe pour continuer.

EXEMPLES DE CHIFFREMENT

LUKS2

Chiffre un support LUKS2 (sur place). Assurez-vous que les 32 MiB finaux sur /dev/plaintext ne sont pas utilisés (par ex., ne contiennent pas de données de système de fichiers)

:

cryptsetup reencrypt --encrypt --type luks2 --reduce-device-size 32m /dev/plaintext_devic

e

Chiffre un support LUKS2 (sur place). Seules les 1 GiB initiales des données originales /dev/plaintext sont chiffrées tout en étant déplacées vers l'arrière. Assurez-vous que les 32 MiB finaux (queue) du support de données ne sont pas utilisés (par ex., ne contiennent aucune donnée)

:

cryptsetup reencrypt --encrypt --type luks2 --device-size 1g --reduce-device-size 32m /dev/plaintext_devic

e

Chiffre un support LUKS2 (sur place) avec un en-tête détaché, placé dans un fichier

:

cryptsetup reencrypt --encrypt --type luks2 --header my_luks2_header /dev/plaintext_devic

e

Initialise uniquement l'opération de chiffrement LUKS2 sur place et active le support (pas encore chiffré)

:

cryptsetup reencrypt --encrypt --type luks2 --init-only --reduce-device-size 32m /dev/plaintext_device my_future_luks_devic

e

Reprend le chiffrement en ligne sur le support initialisé dans l'exemple ci-dessus

:

cryptsetup reencrypt --resume-only /dev/plaintext_device ou cryptsetup reencrypt --active-name my_future_luks_devi
