NOM

CREATE_EVENT_TRIGGER - définir un nouveau déclencheur d'événement

SYNTAXE

CREATE EVENT TRIGGER nom
    ON événement
    [ WHEN variable_filtre IN (valeur_filtre [, ... ]) [ AND ... ] ]
    EXECUTE { FUNCTION | PROCEDURE } nom_fonction()

DESCRIPTION

CREATE EVENT TRIGGER crée un nouveau déclencheur d'événement. Chaque fois que l'événement désigné se produit et que la condition WHEN associée au déclencheur, le cas échéant, est satisfaite, la fonction de déclenchement sera exécutée. Pour une introduction générale aux déclencheurs d'événement, voir Chapitre 38. L'utilisateur qui crée un déclencheur d'événement en devient le propriétaire.

PARAMETRES

nom

Le nom à donner au nouveau déclencheur. Ce nom doit être unique au sein de la base de données.

événement

Le nom de l'événement qui déclenche un appel à la fonction donnée. Voir Section 38.1 pour plus d'informations sur les noms d'événements.

variable_filtre

Le nom d'une variable utilisée pour filtrer les événements. Cela permet de restreindre le déclenchement du déclencheur à un sous-ensemble des cas où il est pris en charge. Actuellement, la seule variable_filtre prise en charge est TAG.

valeur_filtre

Une liste de valeurs pour la variable_filtre associée pour lesquelles le déclencheur doit se déclencher. Pour TAG, cela signifie une liste de balises de commande (par exemple, 'DROP FUNCTION').

nom_fonction

Une fonction fournie par l'utilisateur qui est déclarée comme ne prenant aucun argument et retournant le type event_trigger.

Dans la syntaxe de CREATE EVENT TRIGGER, les mots-clés FUNCTION et PROCEDURE sont équivalents, mais la fonction référencée doit dans tous les cas être une fonction, pas une procédure. L'utilisation du mot-clé PROCEDURE ici est historique et déconseillée.

NOTES

Seuls les superutilisateurs peuvent créer des déclencheurs d'événement.

Les déclencheurs d'événement sont désactivés en mode mono-utilisateur (voir postgres(1)) ainsi que lorsque event_triggers est défini sur false. Si un déclencheur d'événement erroné désactive la base de données au point que vous ne pouvez même pas supprimer le déclencheur, redémarrez avec event_triggers défini sur false pour désactiver temporairement les déclencheurs d'événement, ou en mode mono-utilisateur, et vous pourrez le faire.

EXEMPLES

Interdire l'exécution de toute commande DDL :

CREATE OR REPLACE FUNCTION abort_any_command()
  RETURNS event_trigger
 LANGUAGE plpgsql
  AS $$
BEGIN
  RAISE EXCEPTION 'commande % désactivée', tg_tag;
END;
$$;
CREATE EVENT TRIGGER abort_ddl ON ddl_command_start
   EXECUTE FUNCTION abort_any_command();

COMPATIBILITE

Il n'y a pas d'instruction CREATE EVENT TRIGGER dans la norme SQL.

VOIR AUSSI
