DESCRIPTIO

N

Crash est un outil pour analyser de manière interactive l'état du système Linux pendant son fonctionnement, ou après qu'un crash du noyau s'est produit et qu'un vidage de cœur a été créé par les netdump, diskdump, LKCD, kdump, xendump kvmdump ou les VMware fonctionnalités. Il est vaguement basé sur la commande UNIX crash de SVR4, mais a été considérablement amélioré en le fusionnant complètement avec le gdb(1) débogueur. Le mariage des deux combine efficacement la nature spécifique au noyau de l'utilitaire UNIX crash traditionnel avec les capacités de débogage au niveau du code source de gdb(1)

.

Dans la forme fichier de vidage, à la fois un argument NOMLISTE et un argument IMAGE-MÉMOIRE doivent être saisis. Dans la forme système en fonctionnement, l'argument NOMLISTE doit être saisi si le fichier vmlinux du noyau n'est pas situé dans un emplacement connu, tel que le répertoire /usr/lib/debug/lib/modules/

<version-du-noyau>.

L'utilitaire crash a également été étendu pour prendre en charge l'analyse des fichiers de vidage générés par un crash de l'hyperviseur Xen. Dans ce cas, l'argument NOMLISTE doit être celui du binaire xen-syms. L'analyse d'un système en fonctionnement n'est pas prise en charge pour l'hyperviseur

Xen.

L'ensemble de commandes de l'utilitaire crash se compose d'outils d'analyse de cœurs de noyau courants tels que les traces d'appels de pile du noyau de tous les processus, le désassemblage du code source, l'affichage formaté des structures et variables du noyau, les données de mémoire virtuelle, les vidages de listes liées, etc., ainsi que plusieurs commandes qui approfondissent l'analyse de sous-systèmes spécifiques du noyau. Des commandes gdb appropriées peuvent également être saisies, qui sont à leur tour transmises au module gdb pour exécution. Si vous le souhaitez, les commandes peuvent être placées soit dans un fichier $HOME/.crashrc et/ou dans un fichier .crashrc dans le répertoire courant. Lors de l'initialisation, les commandes dans $HOME/.crashrc sont exécutées en premier, suivies de celles dans le fichier ./.cr

ashrc.

L'utilitaire crash est conçu pour être indépendant des dépendances de version de Linux. Lorsque de nouveaux codes source du noyau affectent le bon fonctionnement de crash et de son ensemble de commandes, l'utilitaire sera mis à jour pour reconnaître les nouveaux ch

angements de code du noyau, tout en maintenant la
rétrocompatibilité avec les versions précédentes.

IMAGE-MÉMOIRE[@ADRES
SE]
Un fichier de vidage de cœur du noyau créé par les netdump, diskdump, LKCD kdump, xendump kvmdump ou les VMware fonctionnalités.

Si un argument IMAGE-MÉMOIRE n'est pas saisi, la session sera lancée sur le système en fonctionnement, ce qui nécessite généralement les privilèges de root en raison du fichier de périphérique utilisé pour accéder à la RAM du système. Par défaut, /dev/crash sera utilisé s'il existe. S'il n'existe pas, alors /dev/mem sera utilisé ; mais si le noyau a été configuré avec CONFIG_STRICT_DEVMEM, alors /proc/kcore sera utilisé. Il est permis de saisir explicitement /dev/crash, /dev/mem ou /proc/kc

ore.

Une valeur @ADRESSE doit être ajoutée à l'IMAGE-MÉMOIRE si le fichier de vidage est un fichier de vidage RAM brut qui n'a pas d'informations d'en-tête décrivant le contenu du fichier. Plusieurs paires ordonnées IMAGE-MÉMOIRE@ADRESSE peuvent être saisies, chaque fichier de vidage contenant un bloc contigu de RAM, où la valeur ADRESSE est l'adresse de départ physique du bloc exprimée en hexadécimal. La ou les valeurs d'adresse physique seront utilisées pour créer un en-tête ELF temporaire dans /var/tmp, qui n'existera que pendant la session de crash. Si un fichier de vidage RAM brut représente une source de mémoire en direct, telle que celle spécifiée par l'argument mem-path de QEMU d'un objet memory-backend-file, alors "live:" doit être préfixé au nom de

l'IMAGE-MÉMOIRE.

En tant que fonctionnalité VMware, l'utilitaire crash est capable de traiter un vidage de mémoire de machine virtuelle VMware généré par la suspension de la machine virtuelle ou le vidage de cœur

de l'invité. Dans ce cas, un fichier .vmss ou .guest doit être utilisé comme
IMAGE-MÉMOIRE et le fichier .vmem doit se trouver dans le même dossier.
