NOM

CREATE_LANGUAGE - définir un nouveau langage procédural

SYNTAXE

CREATE [ OR REPLACE ] [ TRUSTED ] [ PROCEDURAL ] LANGUAGE nom
    HANDLER gestionnaire_appel [ INLINE gestionnaire_inline ] [ VALIDATOR fonction_validation ]
CREATE [ OR REPLACE ] [ TRUSTED ] [ PROCEDURAL ] LANGUAGE nom

DESCRIPTION

CREATE LANGUAGE enregistre un nouveau langage procédural dans une base de données PostgreSQL. Par la suite, des fonctions et des procédures peuvent être définies dans ce nouveau langage.

CREATE LANGUAGE associe effectivement le nom du langage aux fonction(s) de gestionnaire qui sont responsables de l'exécution des fonctions écrites dans ce langage. Se référer au Chapitre 57 pour plus d'informations sur les gestionnaires de langage.

CREATE OR REPLACE LANGUAGE créera soit un nouveau langage, soit remplacera une définition existante. Si le langage existe déjà, ses paramètres sont mis à jour conformément à la commande, mais la propriété du langage et les permissions ne changent pas, et les fonctions existantes écrites dans ce langage sont supposées toujours valides.

Il faut avoir le privilège de superutilisateur PostgreSQL pour enregistrer un nouveau langage ou modifier les paramètres d'un langage existant. Cependant, une fois le langage créé, il est possible de lui assigner la propriété à un non-superutilisateur, qui pourra alors le supprimer, modifier ses permissions, le renommer ou l'attribuer à un nouveau propriétaire. (Ne pas, cependant, attribuer la propriété des fonctions C sous-jacentes à un non-superutilisateur ; cela créerait un chemin d'escalade de privilèges pour cet utilisateur.)

La forme de CREATE LANGUAGE qui ne fournit pas de fonction gestionnaire est obsolète. Pour des raisons de compatibilité ascendante avec les anciens fichiers de sauvegarde, elle est interprétée comme CREATE EXTENSION. Cela fonctionnera si le langage a été conditionné en une extension du même nom, ce qui est la manière conventionnelle de configurer les langages procéduraux.

PARAMÈTRES

TRUSTED

TRUSTED spécifie que le langage ne donne pas accès à des données auquelles l'utilisateur n'aurait pas autrement accès. Si ce mot-clé est omis lors de l'enregistrement du langage, seuls les utilisateurs ayant le privilège de superutilisateur PostgreSQL peuvent utiliser ce langage pour créer de nouvelles fonctions.

PROCEDURAL

C'est un mot-clé bruyant (sans effet fonctionnel).

nom

Le nom du nouveau langage procédural. Le nom doit être unique parmi les langages de la base de données.

HANDLER gestionnaire_appel

gestionnaire_appel est le nom d'une fonction préalablement enregistrée qui sera appelée pour exécuter les fonctions du langage procédural. Le gestionnaire d'appel pour un langage procédural doit être écrit dans un langage compilé tel que C avec la convention d'appel version 1 et enregistré auprès de PostgreSQL en tant que fonction ne prenant aucun argument et retournant le type language_handler, un type de substitution utilisé simplement pour identifier la fonction comme un gestionnaire d'appel.

INLINE gestionnaire_inline

gestionnaire_inline est le nom d'une fonction préalablement enregistrée qui sera appelée pour exécuter un bloc de code anonyme (commande DO) dans ce langage. Si aucune fonction gestionnaire_inline n'est spécifiée, le langage ne prend pas en charge les blocs de code anonymes. La fonction gestionnaire doit prendre un argument de type internal, qui sera la représentation interne de la commande DO, et elle retournera typiquement void. La valeur de retour du gestionnaire est ignorée.

VALIDATOR fonction_validation

fonction_validation est le nom d'une fonction préalablement enregistrée qui sera appelée lorsqu'une nouvelle fonction dans le langage sera créée, pour valider la nouvelle fonction. Si aucune fonction de validation n'est spécifiée, alors une nouvelle fonction ne sera pas vérifiée lorsqu'elle sera créée. La fonction de validation doit prendre un argument de type oid, qui sera l'OID de la fonction à créer, et elle retournera typiquement void.

Une fonction de validation inspecterait typiquement le corps de la fonction pour vérifier sa correction syntaxique, mais elle peut également examiner d'autres propriétés de la fonction, par exemple si le langage ne peut pas gérer certains types d'arguments. Pour signaler une erreur, la fonction de validation devrait utiliser la fonction ereport(). La valeur de retour de la fonction est ignorée.

NOTES

Utilisez DROP LANGUAGE pour supprimer les langages procéduraux.

Le catalogue système pg_language (voir Section 52.29) enregistre les informations sur les langages actuellement installés. De plus, la commande \dL de psql liste les langages installés.

Pour créer des fonctions dans un langage procédural, un utilisateur doit avoir le privilège USAGE pour le langage. Par défaut, USAGE est accordé à PUBLIC (c'est-à-dire à tout le monde) pour les langages fiables. Cela peut être révoqué si désiré.

Les langages procéduraux sont locaux à chaque base de données. Cependant, un langage peut être installé dans la base de données template1, ce qui fera qu'il sera automatiquement disponible dans toutes les bases de données créées ultérieurement.

EXEMPLES

Une séquence minimale pour créer un nouveau langage procédural est :

CREATE FUNCTION plsample_call_handler() RETURNS language_handler
    AS '$libdir/plsample'
    LANGUAGE C;
CREATE LANGUAGE plsample
    HANDLER plsample_call_handler;

Typiquement, cela serait écrit dans un script de création d'extension, et les utilisateurs feraient ceci pour installer l'extension :

CREATE EXTENSION plsample;

COMPATIBILITÉ

CREATE LANGUAGE est une extension PostgreSQL.
