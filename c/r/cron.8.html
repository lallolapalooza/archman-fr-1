Dans cette

version

de Cron, il est possible d'utiliser un /var/spool/cron monté sur le réseau et partagé à travers un cluster d'hôtes et de spécifier que seul l'un des hôtes doit exécuter les tâches crontab dans ce répertoire à un moment donné. Cela se fait en démarrant Cron avec l'option -c, et en faisant en sorte que le fichier /var/spool/cron/. cron.hostname contienne une seule ligne, qui représente le nom d'hôte de l'hôte du cluster qui doit exécuter les tâches. Si ce fichier n'existe pas, ou si le nom d'hôte qu'il contient ne correspond pas à celui retourné par gethostname(2), alors tous les fichiers crontab de ce répertoire sont ignorés. Cela n'a aucun effet sur les tâches cron spécifiées dans le fichier /etc/crontab ou sur les fichiers dans le répertoire /etc/cron.d. Ces fichiers sont toujours exécutés et considérés comme spécifiques à l'hôte. Plutôt que

d'éditer

/var/spool/cron/.cron. hostname directement, utilisez l'option -n de crontab(1) pour spécifier l'hôte. Vous devez vous assurer que

tous

les hôtes d'un cluster, et le serveur de fichiers depuis lequel ils montent le répertoire de crontab partagé, ont des horloges étroitement synchronisées, par exemple en utilisant ntpd(8), sinon les résultats seront très imprévisibles. L'utilisation

du

partage de cluster désactive automatiquement la prise en charge de inotify, car inotify ne peut pas être fiabled sur les systèmes de fichiers partagés montés sur le réseau.

MISES EN GARDE

Tous les fichiers crontab doivent être des fichiers réguliers ou des liens symboliques vers des fichiers réguliers, ils ne doivent pas être exécutables ni inscriptibles par quelqu'un d'autre que le propriétaire. Cette exigence peut être remplacée en utilisant l'option -p sur la ligne de commande de crond. Si le support inotify est utilisé, les changements dans les crontabs liés symboliquement ne sont pas automatiquement détectés par le démon cron. Le démon cron doit recevoir un signal SIGHUP pour recharger les crontabs. C'est une limitation de l'API inotify.

La sortie syslog sera utilisée à la place des e-mails, lorsque sendmail n'est pas installé.
