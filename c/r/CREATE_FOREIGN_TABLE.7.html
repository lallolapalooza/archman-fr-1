DESCRIPTIO

N

CREATE FOREIGN TABLE crée une nouvelle table distante dans la base de données courante. La table appartiendra à l'utilisateur qui émet la

commande.

Si un nom de schéma est donné (par exemple, CREATE FOREIGN TABLE monschema.matable ...) alors la table est créée dans le schéma spécifié. Sinon, elle est créée dans le schéma courant. Le nom de la table distante doit être distinct du nom de toute autre relation (table, séquence, index, vue, vue matérialisée ou table distante) dans le même

schéma.

CREATE FOREIGN TABLE crée également automatiquement un type de données représentant le type composite correspondant à une ligne de la table distante. Par conséquent, les tables distantes ne peuvent pas porter le même nom qu'un type de données existant dans le même

schéma.

Si la clause PARTITION OF est spécifiée, la table est créée comme une partition de table_parent avec les bornes

spécifiées.

Pour pouvoir créer une table distante, vous devez disposer du pr

ivilège USAGE sur le serveur distant, ainsi que du privilège
USAGE sur tous les types de colonnes utilisés dans la table.

PARAMÈTRE

S

IF NOT

EXISTS
Ne pas lever d'erreur si une relation portant le même nom existe déjà. Un avis est émis dans ce cas. Notez qu'il n'y a aucune garantie que la relation existante ressemble à celle qui aurait été
créée.

nom_tabl

e
Le nom (éventuellement qualifié par le schéma) de la table à
créer.

nom_colonn

e
Le nom d'une colonne à créer dans la nouvelle
table.

type_donnée

s
Le type de données de la colonne. Cela peut inclure des spécificateurs de tableau. Pour plus d'informations sur les types de données pris en charge par PostgreSQL, consultez le Chapitre 
8.

COLLATE collatio

n
La clause COLLATE assigne une collation à la colonne (qui doit être de type de données pouvant être collationnée). Si elle n'est pas spécifiée, la collation par défaut du type de données de la colonne est
utilisée.

INHERITS ( table_parent [, ... ]

)
La clause facultative INHERITS spécifie une liste de tables dont la nouvelle table distante hérite automatiquement de toutes les colonnes. Les tables parentes peuvent être des tables ordinaires ou des tables distantes. Voir la forme similaire de CREATE TABLE pour plus de
détails.

PARTITION OF table_parent { FOR VALUES spec_bornes_partition | DEFAULT

}
Cette forme peut être utilisée pour créer la table distante comme partition de la table parente donnée avec les valeurs de bornes de partition spécifiées. Voir la forme similaire de CREATE TABLE pour plus de détails. Notez qu'il est actuellement interdit de créer la table distante comme partition de la table parente s'il existe des index UNIQUE sur la table parente. (Voir aussi ALTER TABLE ATTACH
PARTITION.)

LIKE table_source [ option_like ...

]
La clause LIKE spécifie une table dont la nouvelle table copie automatiquement tous les noms de colonnes, leurs types de données et leurs contraintes de non-nullité.

Contrairement à INHERITS, la nouvelle table et la table d'origine sont complètement découplées une fois la création terminée. Les modifications apportées à la table d'origine ne seront pas appliquées à la nouvelle table, et il n'est pas possible d'inclure les données de la nouvelle table dans les balayages de la table

d'origine.

Contrairement également à INHERITS, les colonnes et les contraintes copiées par LIKE ne sont pas fusionnées avec les colonnes et contraintes de même nom. Si le même nom est spécifié explicitement ou dans une autre clause LIKE, une erreur est

signalée.

Les clauses option_like facultatives spécifient quelles propriétés supplémentaires de la table d'origine copier. Spécifier INCLUDING copie la propriété, spécifier EXCLUDING omet la propriété. EXCLUDING est la valeur par défaut. Si plusieurs spécifications sont faites pour le même type d'objet, la dernière est utilisée. Les options disponibles sont

:

INCLUDING

COMMENTS
Les commentaires des colonnes et des contraintes copiées seront copiés. Le comportement par défaut est d'exclure les commentaires, ce qui fait que les colonnes et les contraintes copiées dans la nouvelle table n'ont pas de
commentaires.

INCLUDING

CONSTRAINTS
Les contraintes CHECK seront copiées. Aucune distinction n'est faite entre les contraintes de colonne et les contraintes de table. Les contraintes de non-nullité sont toujours copiées vers la nouvelle
table.

INCLUDING

DEFAULTS
Les expressions par défaut des définitions de colonnes copiées seront copiées. Sinon, les expressions par défaut ne sont pas copiées, ce qui fait que les colonnes copiées dans la nouvelle table ont des valeurs par défaut nulles. Notez que la copie de valeurs par défaut qui appellent des fonctions de modification de base de données, telles que nextval, peut créer un lien fonctionnel entre les tables d'origine et
nouvelle.

INCLUDING

GENERATED
Toutes les expressions de génération des définitions de colonnes copiées seront copiées. Par défaut, les nouvelles colonnes seront des colonnes de base
ordinaires.

INCLUDING

STATISTICS
Les statistiques étendues sont copiées vers la nouvelle
table.

INCLUDING

ALL
INCLUDING ALL est une forme abrégée sélectionnant toutes les options individuelles di
sponibles. (Il peut être utile d'écrire des clauses EXCLUDING individuelles après IN
CLUDING ALL pour sélectionner toutes les options sauf certaines options spécifiques.)

CONSTRAINT nom_contraint

e
Un nom facultatif pour une contrainte de colonne ou de table. Si la contrainte est violée, le nom de la contrainte est présent dans les messages d'erreur, de sorte que des noms de contraintes comme col must be positive peuvent être utilisés pour communiquer des informations utiles sur la contrainte aux applications clientes. (Des guillemets doubles sont nécessaires pour spécifier des noms de contraintes contenant des espaces.) Si un nom de contrainte n'est pas spécifié, le système génère un
nom.

NOT NULL [ NO INHERIT

]
La colonne ne peut pas contenir de valeurs nulles.

Une contrainte marquée avec

NO INHERIT ne sera pas prop
agée aux tables filles.

NUL

L
La colonne peut contenir des valeurs nulles. C'est la valeur par défaut.

Cette clause n'est fournie que pour des raisons de compatib

ilité avec les bases de données SQL non standard. Son ut
ilisation est déconseillée dans les nouvelles applications.

CHECK ( expression ) [ NO INHERIT

]
La clause CHECK spécifie une expression produisant un résultat booléen que chaque ligne de la table distante est censée satisfaire ; c'est-à-dire que l'expression devrait produire TRUE ou UNKNOWN, jamais FALSE, pour toutes les lignes de la table distante. Une contrainte de vérification spécifiée comme contrainte de colonne ne devrait référencer que la valeur de cette colonne, tandis qu'une expression apparaissant dans une contrainte de table peut référencer plusieurs colonnes.

Actuellement, les expressions CHECK ne peuvent pas contenir de sous-requêtes ni faire référence à d'autres variables que les colonnes de la ligne courante. La colonne système tableoid peut être référencée, mais pas une autre colonne

système.

Une contrainte marquée avec

NO INHERIT ne sera pas prop
agée aux tables filles.

DEFAULT expr_par_défau

t
La clause DEFAULT assigne une valeur de données par défaut pour la colonne à l'intérieur de la définition de colonne dans laquelle il apparaît. La valeur est toute expression sans variable (les sous-requises et les références croisées à d'autres colonnes de la table actuelle ne sont pas autorisées). Le type de données de l'expression par défaut doit correspondre au type de données de la colonne.

L'expression par défaut sera utilisée dans toute opération d'insertion

qui ne spécifie pas de valeur pour la colonne. S'il n'y a pas de vale
ur par défaut pour une colonne, alors la valeur par défaut est null.

GENERATED ALWAYS AS ( generation_expr ) [ STORED | VIRTUAL

]
Cette clause crée la colonne comme colonne générée. La colonne ne peut pas être écrite, et lorsqu'elle est lue, le résultat de l'expression spécifiée sera renvoyé.

Lorsque VIRTUAL est spécifié, la colonne sera calculée lorsqu'elle est lue. (Le connecteur de données externes la verra comme une valeur null dans les nouvelles lignes et peut choisir de la stocker comme une valeur null ou de l'ignorer complètement.) Lorsque STORED est spécifié, la colonne sera calculée à l'écriture. (La valeur calculée sera présentée au connecteur de données externes pour stockage et doit être renvoyée lors de la lecture.) VIRTUAL est la valeur par

défaut.

L'expression de génération peut faire référence à d'autres colonnes de la table,

mais pas à d'autres colonnes générées. Toutes les fonctions et opérateurs utilisés
doivent être immuables. Les références à d'autres tables ne sont pas autorisées.

server_nam

e
Le nom d'un serveur distant existant à utiliser pour la table distante. Pour plus de détails sur la définition d'un serveur, voir CREATE SERVER (CREATE_SERVER(7))
.

OPTIONS ( option 'value' [, ...]

)
Options à associer à la nouvelle table distante ou à l'une de ses colonnes. Les noms d'options et les valeurs autorisés sont spécifiques
à chaque connecteur de données externes et sont validés à l'aide de la fonction de validation du connecteur de données externes. Les noms
d'options en double ne sont pas autorisés (bien qu'il soit acceptable qu'une option de table et une option de colonne aient le même nom).

NOTE

S

Les contraintes sur les tables distantes (telles que les clauses CHECK ou NOT NULL) ne sont pas appliquées par le système PostgreSQL principal, et la plupart des connecteurs de données externes n'essaient pas non plus de les appliquer ; c'est-à-dire que la contrainte est simplement supposée être vraie. Un tel application n'aurait que peu d'intérêt car elle ne s'appliquerait qu'aux lignes insérées ou mises à jour via la table distante, et non aux lignes modifiées par d'autres moyens, comme directement sur le serveur distant. À la place, une contrainte attachée à une table distante doit représenter une contrainte qui est appliquée par le serveur

distant.

Certains connecteurs de données externes à usage spécial pourraient être le seul mécanisme d'accès pour les données auxquelles ils accèdent, et dans ce cas, il pourrait être approprié que le connecteur de données externes lui-même effectue l'application des contraintes. Mais vous ne devez pas supposer qu'un connecteur le fait à moins que sa documentation ne le

dise.

Bien que PostgreSQL n'essaie pas d'appliquer les contraintes sur les tables distantes, il suppose qu'elles sont correctes aux fins de l'optimisation des requêtes. S'il y a des lignes visibles dans la table distante qui ne satisfont pas à une contrainte déclarée, les requêtes sur la table peuvent produire des erreurs ou des réponses incorrectes. Il est de la responsabilité de l'utilisateur de s'assurer que la définition de la contrainte correspond à la

réalité.

Attention

Lorsqu'une table distante est utilisée comme partition d'une table partitionnée, il existe une contrainte implicite selon la

quelle son contenu doit satisfaire la règle de partitionnement. Encore une fois, il est de la responsabilité de l'utilisate
ur de s'assurer que c'est vrai, ce qui se fait mieux en installant une contrainte correspondante sur le serveur distant.

Au sein d'une table partitionnée contenant des partitions de tables distantes, une UPDATE qui change la valeur de la clé de partition peut causer le déplacement d'une ligne d'une partition locale vers une partition de table distante, à condition que le connecteur de données externes prenne en charge le routage des tuples. Cependant, il n'est actuellement pas possible de déplacer une ligne d'une partition de table distante vers une autre partition. Une UPDATE qui nécessiterait de faire cela échouera en raison de la contrainte de partitionnement, en supposant qu'elle est correctement appliquée par le serveur

distant.

Des considérations similaires s'appliquent aux colonnes générées. Les colonnes générées stockées sont calculées lors de l'insertion ou de la mise à jour sur le serveur PostgreSQL l

ocal et remises au connecteur de données externes pour être écrites dans le magasin de données distant, mais il n'est pas garanti qu'une requête sur la table distante renvoie
des valeurs pour les colonnes générées stockées qui sont cohérentes avec l'expression de génération. Encore une fois, cela pourrait entraîner des résultats de requête incorrects.

S

COMPATIBILIT

É

La commande CREATE FOREIGN TABLE est en grande partie conforme à la norme SQL ; cependant, tout comme avec CREATE TABLE, les contraintes NULL et les tables distantes à zéro colonne sont autorisées. La possibilité de spécifier des valeurs par défaut de colonne est également une extens

ion PostgreSQL. L'héritage de table, dans la forme définie par PostgreSQL, n'est pas stan
dard. La clause LIKE, telle que prise en charge dans cette commande, n'est pas standard.
