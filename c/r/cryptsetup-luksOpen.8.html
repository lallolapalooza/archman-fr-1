CRYPTSETUP-OPEN(8) Commandes de maintenance CRYPTSETUP-OPEN(8)

NOM

cryptsetup-open, cryptsetup-create, cryptsetup-plainOpen, cryptsetup-luksOpen, cryptsetup-loopaesOpen, cryptsetup-tcryptOpen, cryptsetup-bitlkOpen, cryptsetup-fvault2Open - ouvre un périphérique chiffré et crée un mappage avec un nom spécifié

SYNTAXE

cryptsetup open --type <type_périphérique> [<options>] <périphérique> <nom>

DESCRIPTION

Ouvre (crée un mappage avec) <nom> basé sur le périphérique <périphérique>.

Le type de périphérique peut être plain, luks (par défaut), luks1, luks2, loopaes ou tcrypt.

Pour la compatibilité ascendante, il existe des alias de commande open :

create (ordre des arguments <nom> <périphérique>) : open --type plain
plainOpen : open --type plain
luksOpen : open --type luks
loopaesOpen : open --type loopaes
tcryptOpen : open --type tcrypt
bitlkOpen : open --type bitlk

<options> sont spécifiques au type et sont décrites ci-dessous pour les types de périphériques individuels. Pour create, l'ordre des options <nom> et <périphérique> est inversé pour des raisons historiques ; tous les autres alias utilisent l'ordre standard <périphérique> <nom>.

PLAIN

open --type plain <périphérique> <nom> --cipher <spécification> --key-size <bits> --hash <alg>
plainOpen <périphérique> <nom> (ancienne syntaxe)
create <nom> <périphérique> (syntaxe OBSOLÈTE)

Ouvre (crée un mappage avec) <nom> basé sur le périphérique <périphérique>.

Vous devriez toujours spécifier les options --cipher, --key-size et (si aucun fichier clé ou aucun keyring n'est utilisé) ensuite aussi --hash pour éviter l'incompatibilité, car les valeurs par défaut peuvent différer dans les anciennes versions de cryptsetup.

Le format plain permet également de récupérer une clé de volume à partir d'un keyring du noyau spécifié par --volume-key-keyring. La clé dans le keyring du noyau doit être configurée avant d'émettre des commandes cryptsetup, car cryptsetup ne télécharge aucune clé dans le keyring en mode plain. Pour les commandes ultérieures (comme resize), l'utilisateur doit s'assurer que la clé dans le keyring n'est pas modifiée. Sinon, le rechargement de la clé peut entraîner une corruption des données après un changement de clé inattendu.

<options> peuvent être [--hash, --cipher, --sector-size, --key-file, --keyfile-size, --keyfile-offset, --key-size, --offset, --skip, --device-size, --size, --readonly, --shared, --allow-discards, --refresh, --timeout, --verify-passphrase, --iv-large-sectors, --volume-key-keyring].

EXEMPLES :

Pour mapper le périphérique chiffré /dev/sda10 au périphérique déchiffré /dev/mapper/e1, vous pouvez utiliser :

cryptsetup open --type plain --cipher aes-cbc-essiv:sha256 --key-size 256 --hash sha256 /dev/sda10 e1

Le périphérique déchiffré peut ensuite être utilisé comme un périphérique bloc normal pour monter un système de fichiers.

Pour mapper un périphérique avec une clé de volume dans le keyring de confiance ou chiffré préconfiguré, vous devez spécifier le keyring avec la clé et supprimer la spécification hash, par exemple, pour utiliser %trusted:mykey :

cryptsetup open --type plain /dev/sda10 e1 --volume-key-keyring=%trusted:mykey --cipher aes-xts-plain64 --key-size 256

Notez que la taille de clé doit correspondre à la clé préconfigurée dans le keyring.

LUKS

open <périphérique> <nom>
open --type <luks1|luks2> <périphérique> <nom> (demande de version explicite)
luksOpen <périphérique> <nom> (ancienne syntaxe)

Ouvre le périphérique LUKS <périphérique> et configure un mappage <nom> après vérification réussie de la phrase de passe fournie.

Premièrement, la phrase de passe est recherchée dans les jetons LUKS2 non protégés par un code PIN. Si un tel jeton n'existe pas (ou ne parvient pas à déverrouiller le slot de clé) et que la phrase de passe n'est pas fournie via --key-file, la commande demande la phrase de passe de manière interactive.

S'il existe un jeton LUKS2 valide mais qu'il nécessite un code PIN pour déverrouiller le slot de clé attribué, il n'est pas utilisé sauf si l'une des options suivantes est ajoutée : --token-only, --token-type où le type correspond au jeton protégé par code PIN souhaité ou --token-id avec l'id correspondant au jeton protégé par code PIN.

<options> peuvent être [--key-file, --keyfile-offset, --keyfile-size, --readonly, --test-passphrase, --allow-discards, --header, --key-slot, --volume-key-file, --token-id, --token-only, --token-type, --disable-external-tokens, --disable-keyring, --disable-locks, --type, --refresh, --serialize-memory-hard-pbkdf, --unbound, --tries, --timeout, --verify-passphrase, --persistent, --volume-key-keyring, --link-vk-to-keyring, --external-tokens-path].

loopAES

open --type loopaes <périphérique> <nom> --key-file <fichier_clé>
loopaesOpen <périphérique> <nom> --key-file <fichier_clé> (ancienne syntaxe)

Ouvre le périphérique loop-AES <périphérique> et configure un mappage <nom>.

Si le fichier clé est chiffré avec GnuPG, vous devez utiliser --key-file=- et le déchiffrer avant utilisation, par exemple : gpg --decrypt <fichier_clé> | cryptsetup loopaesOpen --key-file=- <périphérique> <nom>.

L'extension loop-AES ne peut pas utiliser l'entrée directe du fichier clé sur le terminal réel car les clés sont séparées par une fin de ligne, et seule une partie du fichier multi-clé serait lue. Si vous en avez besoin dans un script, utilisez simplement la redirection de pipe : echo $fichier_clé | cryptsetup loopaesOpen --key-file=- <périphérique> <nom>.

Utilisez --keyfile-size pour spécifier la bonne longueur de clé si nécessaire.

Utilisez --offset pour spécifier le décalage du périphérique. Notez que les unités doivent être spécifiées en secteurs de 512 octets.

Utilisez --skip pour spécifier le décalage de l'IV. Si le périphérique d'origine utilisait un décalage mais ne l'utilisait pas dans les calculs de secteur IV, vous devez explicitement utiliser --skip 0 en plus du paramètre d'offset.

Utilisez --hash pour remplacer la fonction de hachage par défaut pour le hachage de phrase de passe (sinon elle est détectée en fonction de la taille de la clé).

<options> peuvent être [--cipher, --key-file, --keyfile-size, --keyfile-offset, --key-size, --offset, --skip, --hash, --readonly, --allow-discards, --refresh].

TrueCrypt et VeraCrypt

open --type tcrypt <périphérique> <nom>
tcryptOpen <périphérique> <nom> (ancienne syntaxe)

Ouvre le périphérique TCRYPT (compatible TrueCrypt et VeraCrypt) <périphérique> et configure un mappage <nom>.

L'option --key-file permet une combinaison du contenu du fichier avec la phrase de passe. L'option --key-file peut être répétée. Notez que l'utilisation de fichiers clés diffère de la logique des fichiers clés LUKS.

Si les options --cipher ou --hash sont utilisées, seules les chaînes de chiffrement ou les variantes PBKDF2 avec les algorithmes de hachage spécifiés sont vérifiées. Cela pourrait accélérer le déverrouillage du périphérique (mais révèle également certaines informations sur le conteneur).

Si vous utilisez --header en combinaison avec des options cachées ou système, le fichier d'en-tête doit contenir des en-têtes spécifiques aux mêmes positions que le conteneur chiffré d'origine.

L'option --allow-discards ne peut pas être combinée avec l'option --tcrypt-hidden. Pour un mappage normal, cela peut entraîner la destruction du volume caché (le volume caché apparaît comme un espace inutilisé pour le volume extérieur, donc cet espace peut être ignoré).

<options> peuvent être [--key-file, --tcrypt-hidden, --tcrypt-system, --tcrypt-backup, --readonly, --test-passphrase, --allow-discards, --veracrypt (ignoré), --disable-veracrypt, --veracrypt-pim, --veracrypt-query-pim, --header, --cipher, --hash, --tries, --timeout, --verify-passphrase].

<options> peuvent être [--key-file, --keyfile-offset, --keyfile-size, --key-size, --readonly, --test-passphra

olume-key-file, --tries, --timeout, --verify-passphrase].

--persistent

Si utilisé avec des appareils LUKS2 et des commandes d'activation comme open ou refresh, les drapeaux d'activation spécifiés sont écrits de manière persistante dans les métadonnées et utilisés automatiquement la prochaine fois, même pour une activation normale. (Pas besoin d'utiliser cryptab ou d'autres fichiers de configuration système.)

Si vous devez supprimer un drapeau persistant, utilisez --persistent sans le drapeau que vous souhaitez supprimer (par exemple, pour désactiver le drapeau discard stocké de manière persistante, utilisez --persistent sans --allow-discards).

Seuls --allow-discards, --perf-same_cpu_crypt, --perf-submit_from_crypt_cpus, --perf-no_read_workqueue, --perf-no_write_workqueue et --integrity-no-journal peuvent être stockés de manière persistante.

--readonly, -r

Configure un mappage en lecture seule.

--refresh

Actualise un périphérique actif avec un nouvel ensemble de paramètres. Voir cryptsetup-refresh(8) pour plus de détails.

--sector-size octets

Définit la taille du secteur de chiffrement à utiliser avec le type de périphérique plain. Doit être une puissance de deux et comprise entre 512 et 4096 octets. La taille du secteur de chiffrement par défaut est de 512 octets.

Augmenter la taille du secteur de 512 à 4096 octets peut améliorer les performances sur la plupart des périphériques de stockage modernes et avec certains accélérateurs matériels de chiffrement.

Notez qu'utiliser une taille de secteur supérieure à la taille physique du secteur du périphérique de stockage sous-jacent peut entraîner une corruption des données lors de coupures de courant inattendues. Une coupure de courant pendant les opérations d'écriture peut entraîner une écriture partielle du secteur de chiffrement, laissant les données chiffrées dans un état incohérent qui ne peut pas être correctement déchiffré.

--serialize-memory-hard-pbkdf

Utilise un verrou global pour sérialiser le déverrouillage des emplacements de clés utilisant PBKDF à usage intensif de mémoire.

Ceci est une solution de contournement pour une situation spécifique où plusieurs périphériques sont activés en parallèle et que le système, au lieu de signaler une mémoire insuffisante, commence à arrêter inconditionnellement les processus utilisant le tueur de processus hors mémoire.

N'UTILISEZ PAS ce commutateur tant que vous n'implémentez pas l'environnement de démarrage avec l'activation parallèle des périphériques !

--shared

Crée un mappage supplémentaire pour un périphérique de chiffrement commun. Les mappages arbitraires sont pris en charge. Cette option n'est pertinente que pour le type de périphérique plain. Utilisez --offset, --size et --skip pour spécifier la zone mappée.

--size, -b <nombre de secteurs de 512 octets>

Définit la taille du périphérique en secteurs de 512 octets. Utilisable uniquement avec le type de périphérique plain.

--skip, -p <nombre de secteurs de 512 octets>

Décalage de départ utilisé dans le calcul de l'IV en secteurs de 512 octets (combien de secteurs de données chiffrées ignorer au début). Cette option n'est pertinente qu'avec les types de périphériques plain ou loopaes.

Par conséquent, si --offset n, et --skip s, le secteur n (le premier secteur du périphérique chiffré) obtiendra le numéro de secteur s pour le calcul de l'IV.

--tcrypt-backup, --tcrypt-hidden, --tcrypt-system

Spécifie quel en-tête TrueCrypt sur disque sera utilisé pour ouvrir le périphérique. Voir la section TCRYPT de cryptsetup(8) pour plus d'informations.

L'utilisation d'un périphérique chiffré par le système avec l'option --tcrypt-system nécessite des paramètres spécifiques pour fonctionner comme prévu.

TrueCrypt/VeraCrypt prend en charge le chiffrement complet du système (seule une table de partitions n'est pas chiffrée) ou le chiffrement de partition système (seule une partition système est chiffrée). L'en-tête de métadonnées contient alors le décalage et la taille de la zone chiffrée. Cryptsetup doit connaître le décalage de partition spécifique pour calculer les paramètres de chiffrement. Pour mapper correctement une partition, vous devez spécifier un périphérique de partition réel afin que cryptsetup puisse calculer ce décalage.

Bien que vous puissiez utiliser un périphérique complet comme paramètre (/dev/sdb), privilégiez toujours la spécification de la partition que vous souhaitez mapper (/dev/sdb1), car seul le mode de partition système peut être détecté de cette manière.

Pour mapper des images (stockées dans un fichier), vous pouvez utiliser l'option supplémentaire --header avec le périphérique de partition réel. Si --header est utilisé (et qu'il est différent de l'image de données), cryptsetup s'attend à ce que l'image de données contienne un instantané de la partition de données uniquement.

Si --header n'est pas utilisé (ou pointe vers la même image), cryptsetup s'attend à ce que l'image contienne un disque complet (y compris la table de partitions). Cela peut mapper une zone chiffrée complète qui n'est pas directement montable en tant que système de fichiers. Veuillez privilégier la création d'un périphérique de boucle avec des partitions (losetup -P, voir la page de manuel losetup(8)) et utiliser une partition réelle (/dev/loopXp1) comme paramètre de périphérique.

--test-passphrase

N'active pas le périphérique, vérifie simplement la phrase de passe. Le nom du mappage du périphérique n'est pas obligatoire si cette option est utilisée.

--timeout, -t secondes

Nombre de secondes à attendre avant une expiration pour la saisie de la phrase de passe via le terminal. C'est pertinent chaque fois qu'une phrase de passe est demandée. N'a aucun effet lorsqu'utilisé conjointement avec --key-file.

Cette option est utile lorsque le système ne doit pas se bloquer si l'utilisateur ne saisit pas de phrase de passe, par exemple, au démarrage. La valeur par défaut est de 0 seconde, ce qui signifie attendre indéfiniment.

--token-id

Spécifie quel jeton utiliser et permet à l'invite PIN du jeton de prendre le pas sur l'invite interactive de phrase de passe de l'emplacement de clé. S'il est omis, tous les jetons disponibles (non protégés par PIN) seront vérifiés avant de continuer avec l'invite de phrase de passe.

--token-only

Ne pas poursuivre l'action si le déverrouillage de l'emplacement de clé basé sur un jeton a échoué. Sans l'option, l'action demande une phrase de passe pour continuer.

Elle permet aux jetons LUKS2 protégés par PIN de prendre le pas sur l'invite interactive de phrase de passe de l'emplacement de clé.

--token-type type

Restreint les jetons éligibles pour l'opération à un type de jeton spécifique. Utile principalement lorsqu'aucun --token-id n'est spécifié.

Elle permet aux jetons LUKS2 de type protégés par PIN de prendre le pas sur l'invite interactive de phrase de passe de l'emplacement de clé.

--tries, -T

Nombre de fois où la saisie de la phrase de passe doit être réessayée. Le défaut est de 3 tentatives.

--type type

Spécifie le type de périphérique requis, pour plus d'informations, lisez la section ACTIONS DE BASE dans cryptsetup(8).

--unbound

Autorisé uniquement avec le paramètre --test-passphrase, il permet de tester la phrase de passe d'un emplacement de clé LUKS2 non lié. Sinon, une phrase de passe d'emplacement de clé non liée ne peut être testée qu'en sélectionnant un emplacement de clé spécifique via le paramètre --key-slot.

--usage

Afficher une aide sur les options courtes.

--veracrypt

Cette option est ignorée car le mode compatible VeraCrypt est pris en charge par défaut.

--veracrypt-pim, --veracrypt-query-pim

Utilise un multiplicateur d'itérations personnel (PIM) personnalisé pour le périphérique VeraCrypt. Voir la section TCRYPT de cryptsetup(8) pour plus d'informations.

--verify-passphrase, -y

Lors de la demande interactive d'une phrase de passe, demandez-la deux fois et signalez une erreur si les deux saisies ne correspondent pas. Recommandé lors de la création d'un mappage de type plain pour la première fois. Ignoré lors de l'entrée à partir d'un fichier ou de stdin.

--version, -V

Afficher la version du programme.

--volume-key-file fichier, --master-key-file fichier (alias OBSOLÈTE)

Utilise une clé de volume stockée dans un fichier.

Cela permet d'ouvrir les types de périphériques luks et bitlk sans fournir de phrase de passe.

Pour les périphériques en cours de réencapsulation, l'option peut être utilisée deux fois pour spécifier les clés de volume ancienne et nouvelle. Lorsque vous utilisez l'option deux fois, assurez-vous d'associer chaque option --volume-key-file au paramètre --key-size respectif.

--volume-key-keyring <description de clé>

Utilise une clé de volume stockée dans un keyring. Cela permet d'ouvrir les types de périphériques luks et plain sans fournir de phrase de passe.

Pour LUKS, la clé et le type associé doivent être lisibles depuis l'espace utilisateur afin que le résumé de la clé de volume puisse être vérifié avant l'activation. Pour les périphériques en cours de réencapsulation, l'option peut être utilisée deux fois pour spécifier les clés de volume ancienne et nouvelle.

Pour le type PLAIN, l'utilisateur doit s'assurer que la clé dans le keyring est inchangée depuis l'activation. Sinon, le rechargement de la clé peut entraîner une corruption des données après un changement de clé inattendu.

La <description de clé> utilise la syntaxe compatible avec keyctl. Il peut s'agir d'un ID de clé numérique ou d'un nom de chaîne au format %<type de clé>:<nom de clé>. Voir également la section IDENTIFIATEURS DE CLÉ de keyctl(1). Lorsqu'aucun préfixe %<type de clé>: n'est spécifié, on suppose que le type de clé est user (type par défaut).
