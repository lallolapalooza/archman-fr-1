CRYPTSETUP-OPEN(8) Commandes de maintenance CRYPTSETUP-OPEN(8)

NOM

cryptsetup-open, cryptsetup-create, cryptsetup-plainOpen, cryptsetup-luksOpen, cryptsetup-loopaesOpen, cryptsetup-tcryptOpen, cryptsetup-bitlkOpen, cryptsetup-fvault2Open - ouvrir un périphérique chiffré et créer un mapping avec un nom spécifié

SYNTAXE

cryptsetup open --type <type_de_périphérique> [<options>] <périphérique> <nom>

DESCRIPTION

Ouvre (crée un mapping avec) <nom> supporté par le périphérique <périphérique>.

Le type de périphérique peut être plain, luks (par défaut), luks1, luks2, loopaes ou tcrypt.

Pour la compatibilité ascendante, il existe des alias de commande open :

create (ordre des arguments <nom> <périphérique>) : open --type plain
plainOpen : open --type plain
luksOpen : open --type luks
loopaesOpen : open --type loopaes
tcryptOpen : open --type tcrypt
bitlkOpen : open --type bitlk

<options> sont spécifiques au type et sont décrites ci-dessous pour les types de périphériques individuels. Pour create, l'ordre des options <nom> et <périphérique> est inversé pour des raisons historiques ; tous les autres alias utilisent l'ordre standard <périphérique> <nom>.

PLAIN

open --type plain <périphérique> <nom> --cipher <spécification> --key-size <bits> --hash <alg>
plainOpen <périphérique> <nom> (ancienne syntaxe)
create <nom> <périphérique> (syntaxe OBSOLÈTE)

Ouvre (crée un mapping avec) <nom> supporté par le périphérique <périphérique>.

Vous devriez toujours spécifier les options --cipher, --key-size et (si aucun fichier clé ou keyring n'est utilisé) alors aussi --hash pour éviter l'incompatibilité, car les valeurs par défaut peuvent différer dans les anciennes versions de cryptsetup.

Le format plain permet également de récupérer une clé de volume à partir d'un keyring du noyau spécifié par --volume-key-keyring. La clé dans le keyring du noyau doit être configurée avant d'émettre des commandes cryptsetup, car cryptsetup ne télécharge aucune clé dans le keyring en mode plain. Pour les commandes ultérieures (comme resize), l'utilisateur doit s'assurer que la clé dans le keyring n'est pas modifiée. Sinon, le rechargement de la clé peut entraîner une corruption des données après un changement de clé inattendu.

<options> peuvent être [--hash, --cipher, --sector-size, --key-file, --keyfile-size, --keyfile-offset, --key-size, --offset, --skip, --device-size, --size, --readonly, --shared, --allow-discards, --refresh, --timeout, --verify-passphrase, --iv-large-sectors, --volume-key-keyring].

EXEMPLES :

Pour mapper le périphérique chiffré /dev/sda10 au périphérique déchiffré /dev/mapper/e1, vous pouvez utiliser :

cryptsetup open --type plain --cipher aes-cbc-essiv:sha256 --key-size 256 --hash sha256 /dev/sda10 e1

Le périphérique déchiffré peut ensuite être utilisé comme un périphérique de bloc normal pour monter un système de fichiers.

Pour mapper un périphérique avec une clé de volume dans le keyring préconfiguré de confiance ou chiffré, vous devez spécifier le keyring avec la clé et supprimer la spécification du hash, par exemple, pour utiliser %trusted:mykey :

cryptsetup open --type plain /dev/sda10 e1 --volume-key-keyring=%trusted:mykey --cipher aes-xts-plain64 --key-size 256

Notez que la taille de la clé doit correspondre à la clé préconfigurée dans le keyring.

LUKS

open <périphérique> <nom>
open --type <luks1|luks2> <périphérique> <nom> (version explicite demandée)
luksOpen <périphérique> <nom> (ancienne syntaxe)

Ouvre le périphérique LUKS <périphérique> et configure un mapping <nom> après vérification réussie de la phrase de passe fournie.

Premièrement, la phrase de passe est recherchée dans les jetons LUKS2 non protégés par PIN. Si aucun jeton de ce type n'existe (ou échoue à déverrouiller le keyslot) et que la phrase de passe n'est pas fournie via --key-file, la commande demande interactivement la phrase de passe.

S'il existe un jeton LUKS2 valide mais qu'il nécessite un PIN pour déverrouiller le keyslot attribué, il n'est pas utilisé à moins que l'une des options suivantes ne soit ajoutée : --token-only, --token-type où le type correspond au jeton souhaité protégé par PIN ou --token-id avec un id correspondant au jeton protégé par PIN.

<options> peuvent être [--key-file, --keyfile-offset, --keyfile-size, --readonly, --test-passphrase, --allow-discards, --header, --key-slot, --volume-key-file, --token-id, --token-only, --token-type, --disable-external-tokens, --disable-keyring, --disable-locks, --type, --refresh, --serialize-memory-hard-pbkdf, --unbound, --tries, --timeout, --verify-passphrase, --persistent, --volume-key-keyring, --link-vk-to-keyring, --external-tokens-path].

loopAES

open --type loopaes <périphérique> <nom> --key-file <fichier_clé>
loopaesOpen <périphérique> <nom> --key-file <fichier_clé> (ancienne syntaxe)

Ouvre le périphérique loop-AES <périphérique> et configure un mapping <nom>.

Si le fichier clé est chiffré avec GnuPG, alors vous devez utiliser --key-file=- et le déchiffrer avant utilisation, par exemple comme ceci : gpg --decrypt <fichier_clé> | cryptsetup loopaesOpen --key-file=- <périphérique> <nom>.

L'extension loop-AES ne peut pas utiliser l'entrée directe du fichier clé sur le terminal réel car les clés sont séparées par des fins de ligne, et seule une partie du fichier multi-clés serait lue. Si vous en avez besoin dans un script, utilisez simplement la redirection par pipe : echo $fichier_clé | cryptsetup loopaesOpen --key-file=- <périphérique> <nom>.

Utilisez --keyfile-size pour spécifier la longueur correcte de la clé si nécessaire.

Utilisez --offset pour spécifier le décalage du périphérique. Notez que les unités doivent être spécifiées en secteurs de 512 octets.

Utilisez --skip pour spécifier le décalage IV. Si le périphérique d'origine utilisait un décalage mais ne l'utilisait pas dans les calculs de secteurs IV, vous devez explicitement utiliser --skip 0 en plus du paramètre d'offset.

Utilisez --hash pour remplacer la fonction de hachage par défaut pour le hachage de phrase de passe (sinon elle est détectée selon la taille de la clé).

<options> peuvent être [--cipher, --key-file, --keyfile-size, --keyfile-offset, --key-size, --offset, --skip, --hash, --readonly, --allow-discards, --refresh].

TrueCrypt et VeraCrypt

open --type tcrypt <périphérique> <nom>
tcryptOpen <périphérique> <nom> (ancienne syntaxe)

Ouvre le périphérique TCRYPT (compatible TrueCrypt et VeraCrypt) <périphérique> et configure un mapping <nom>.

L'option --key-file permet une combinaison du contenu du fichier avec la phrase de passe. L'option --key-file peut être répétée. Notez que l'utilisation de fichiers clés diffère de la logique des fichiers clés LUKS.

Si les options --cipher ou --hash sont utilisées, seules les chaînes de chiffrement ou les variantes PBKDF2 avec les algorithmes de hachage spécifiés sont vérifiées. Cela pourrait accélérer le déverrouillage du périphérique (mais révèle également certaines informations sur le conteneur).

Si vous utilisez --header en combinaison avec des options cachées ou système, le fichier d'en-tête doit contenir des en-têtes spécifiques aux mêmes positions que le conteneur chiffré d'origine.

L'option --allow-discards ne peut pas être combinée avec l'option --tcrypt-hidden. Pour un mapping normal, elle peut causer la destruction du volume caché (le volume caché apparaît comme un espace inutilisé pour le volume externe, donc cet espace peut être rejeté).

<options> peuvent être [--key-file, --tcrypt-hidden, --tcrypt-system, --tcrypt-backup, --readonly, --test-passphrase, --allow-discards, --veracrypt (ignoré), --disable-veracrypt, --veracrypt-pim, --veracrypt-query-pim, --header, --cipher, --hash, --tries, --timeout, --verify-passphrase].

FileVault2

open --type fvault2 <device> <name>
fvault2Open <device> <name> (ancienne syntaxe)

Ouvre le FVAULT2 (compatible FileVault2) <device> et met en place un mappage <name>.

<options> peut être [--key-file, --keyfile-offset, --keyfile-size, --key-size, --readonly, --test-passphrase, --allow-discards --volume-key-file, --tries, --timeout, --verify-passphrase].

OPTIONS

--allow-discards

Autorise l'utilisation des requêtes de suppression (TRIM) pour le périphérique. Ceci n'est pas non plus supporté pour les périphériques LUKS2 avec protection de l'intégrité des données.

AVERTISSEMENT : Cette commande peut avoir un impact négatif sur la sécurité car elle peut rendre les opérations au niveau du système de fichiers visibles sur le périphérique physique. Par exemple, des informations divulguant le type de système de fichiers, l'espace utilisé, etc., peuvent être extractibles du périphérique physique si les blocs supprimés peuvent être localisés plus tard. En cas de doute, ne l'utilisez pas.

Une version du noyau 3.1 ou ultérieure est nécessaire. Pour les noyaux antérieurs, cette option est ignorée.

--batch-mode, -q

Supprime toutes les questions de confirmation. À utiliser avec prudence !

Si l'option --verify-passphrase n'est pas spécifiée, cette option désactive également la vérification de la passphrase.

--cipher, -c <cipher-spec>

Définit la chaîne de spécification du chiffrement pour le type de périphérique plain.

Pour le type de périphérique tcrypt, cela restreint les chaînes de chiffrement vérifiées lors de la recherche de l'en-tête.

cryptsetup --help affiche les valeurs par défaut compilées.

Si un hachage fait partie de la spécification du chiffrement, il est alors utilisé comme partie de la génération de l'IV. Par exemple, ESSIV nécessite une fonction de hachage, tandis que "plain64" n'en a pas besoin et n'en spécifie donc aucune.

Pour le mode XTS, vous pouvez éventuellement définir une taille de clé de 512 bits avec l'option -s. La taille de la clé pour le mode XTS est le double de celle des autres modes pour le même niveau de sécurité.

--debug ou --debug-json

Exécuter en mode débogage avec des journaux de diagnostic complets. Les lignes de sortie de débogage sont toujours préfixées par #.

Si --debug-json est utilisé, des structures de données JSON LUKS2 supplémentaires sont imprimées.

--device-size taille[unités]

Au lieu de la taille réelle du périphérique, utilisez la valeur spécifiée. Utilisable uniquement avec le type de périphérique plain.

Si aucun suffixe d'unité n'est spécifié, la taille est en octets.

Le suffixe d'unité peut être S pour des secteurs de 512 octets, K/M/G/T (ou KiB, MiB, GiB, TiB) pour des unités de base 1024 ou KB/MB/GB/TB pour une base 1000 (échelle SI).

--disable-external-tokens

Désactiver le chargement des plugins pour les tokens LUKS2 externes.

--disable-keyring

Ne pas charger la clé du volume dans le keyring du noyau ; la stocker directement dans la cible dm-crypt à la place. Cette option n'est supportée que pour le type LUKS2.

--disable-locks

Désactive la protection par verrouillage des métadonnées sur disque. Cette option n'est valide que pour LUKS2 et est ignorée pour les autres formats.

AVERTISSEMENT : N'utilisez pas cette option à moins que vous n'exécutiez cryptsetup dans un environnement restreint où le verrouillage est impossible à effectuer (où le répertoire /run ne peut pas être utilisé).

--disable-veracrypt

Cette option peut être utilisée pour désactiver le mode compatible VeraCrypt (seuls les périphériques TrueCrypt sont reconnus). Voir la section TCRYPT dans cryptsetup(8) pour plus d'informations.

--external-tokens-path <chemin absolu>

Remplace le chemin du répertoire système où cryptsetup recherche les gestionnaires de tokens externes (ou plugins de tokens). Il doit s'agir d'un chemin absolu (commençant par le caractère '/').

--hash, -h <hash-spec>

Spécifie le hachage de la passphrase. S'applique uniquement aux types de périphériques plain et loopaes.

Pour le type de périphérique tcrypt, cela restreint les variantes PBKDF2 vérifiées lors de la recherche de l'en-tête.

--header <périphérique ou fichier stockant l'en-tête LUKS>

Spécifie un périphérique ou fichier de métadonnées détaché (séparé) où l'en-tête est stocké.

AVERTISSEMENT : Il n'y a aucune vérification pour savoir si le périphérique de chiffrement spécifié appartient réellement à l'en-tête donné. En fait, vous pouvez spécifier un périphérique arbitraire comme périphérique de chiffrement avec l'option --header. À utiliser avec prudence.

--help, -?

Affiche le texte d'aide et les paramètres par défaut.

--iv-large-sectors

Compte le vecteur d'initialisation (IV) en secteurs de plus grande taille (si défini) au lieu de secteurs de 512 octets. Cette option ne peut être utilisée qu'avec le type de périphérique plain.

Cette option n'a aucun impact sur les performances ou la sécurité ; utilisez-la uniquement pour accéder à des images disque existantes incompatibles provenant d'autres systèmes qui nécessitent cette option.

--key-description texte

Définit la description de la clé dans le keyring qui sera utilisée pour la récupération de la passphrase.

--key-file, -d fichier

Lit la passphrase depuis le fichier.

Si le nom donné est "-", la passphrase sera lue depuis stdin. Dans ce cas, la lecture ne s'arrêtera pas aux caractères de nouvelle ligne.

Avec le type de périphérique plain, la passphrase obtenue via l'option --key-file est passée directement dans dm-crypt. Contrairement au mode interactif (stdin), où le digest de la passphrase est passé dans dm-crypt à la place.

Voir la section NOTES SUR LE TRAITEMENT DES PASSPHRASE dans cryptsetup(8) pour plus d'informations.

--keyfile-offset valeur

Saute valeur octets au début du fichier de clé.

--keyfile-size, -l valeur

Lit un maximum de valeur octets du fichier de clé. La valeur par défaut est de lire le fichier entier jusqu'au maximum compilé qui peut être interrogé avec --help. La fourniture de plus de données que le maximum compilé interrompt l'opération.

Cette option est utile pour couper les nouvelles lignes finales, par exemple. Si --keyfile-offset est également donné, le comptage de la taille commence après l'offset.

--key-size, -s bits

Définit la taille de la clé en bits. L'argument doit être un multiple de 8. Les tailles de clés possibles sont limitées par le chiffrement et le mode utilisés.

Voir /proc/crypto pour plus d'informations. Notez que la taille de la clé dans /proc/crypto est indiquée en octets.

Cette option peut être utilisée pour les périphériques plain et luks. Pour les périphériques LUKS2 en cours de ré-chiffrement, vous pouvez utiliser le paramètre deux fois pour spécifier les anciennes et nouvelles tailles de clé de volume. Chaque option --key-size correspond au paramètre --volume-key-file respectif (également autorisé à être utilisé jusqu'à deux fois).

--key-slot, -S <0-N>

Cette option sélectionne un slot de clé spécifique pour comparer la passphrase. Si la passphrase donnée ne correspond qu'à un slot de clé différent, l'opération échoue.

Le nombre maximum de slots de clé dépend de la version de LUKS. LUKS1 peut avoir jusqu'à 8 slots de clé. LUKS2 peut avoir jusqu'à 32 slots de clé en fonction de la taille de la zone de slot de clé et de la taille de la clé, mais un identifiant de slot de clé valide peut toujours être compris entre 0 et 31 pour LUKS2.

--link-vk-to-keyring <description_keyring>::<description_clé>

Lie la clé du volume dans un keyring avec le nom de clé spécifié. La clé du volume n'est liée que si l'action demandée est terminée avec succès (avec --test-passphrase, la clé de volume vérifiée est liée dans un keyring sans prendre d'autres mesures).

La chaîne <description_keyring> doit contenir la description du keyring du noyau existant. Le nom du keyring peut éventuellement être préfixé par des descriptions de type "%:" ou "%keyring:". Ou bien, le keyring peut également être spécifié directement par son ID numérique. De plus, des notations spéciales de keyring commençant par "@" peuvent être utilisées pour sélectionner des keyrings du noyau prédéfinis existants.

La chaîne "::" est un délimiteur utilisé pour séparer la description du keyring et la description de la clé.

La partie <description_clé> décrit le type de clé et le nom de la clé du volume liée dans le keyring décrit dans <description_keyring>. Le type peut être spécifié en ajoutant un préfixe "%<nom_type>:" devant le nom de la clé. Si le type est manquant, le type user par défaut est appliqué. Si une clé du même nom et type existe déjà (déjà liée dans le keyring), elle sera remplacée dans le processus.

Voir également la section IDENTIFIANTS DE CLÉ de keyctl(1).

--offset, -o <nombre de secteurs de 512 octets>

Décalage de démarrage dans le périphérique backend en secteurs de 512 octets. Cette option n'est pertinente qu'avec les types de périphériques plain ou loopaes.

--perf-high_priority

Définit les workqueues de dm-crypt et le thread d'écriture sur une priorité élevée. Cela améliore le débit et la latence de dm-crypt tout en dégradant la réactivité générale du système.

Cette option n'est disponible que pour le réglage de performance de dm-crypt de bas niveau, utilisez-la uniquement si vous avez besoin d'un changement par rapport au comportement par défaut de dm-crypt. Nécessite le noyau 6.10 ou une version ultérieure.

--perf-no_read_workqueue, --perf-no_write_workqueue

Contourne la workqueue interne de dm-crypt et traite les requêtes de lecture ou d'écriture de manière synchrone.

Ces options ne sont disponibles que pour le réglage de performance de dm-crypt de bas niveau, utilisez-les uniquement si vous avez besoin d'un changement par rapport au comportement par défaut de dm-crypt. Nécessite le noyau 5.9 ou une version ultérieure.

--perf-same_cpu_crypt

Effectue le chiffrement en utilisant le même CPU sur lequel cette E/S a été soumise. Par défaut, une workqueue non liée est utilisée afin que le travail de chiffrement soit automatiquement équilibré entre les CPU disponibles.

Cette option n'est disponible que pour le réglage de performance de dm-crypt de bas niveau, utilisez-la uniquement si vous avez besoin d'un changement par rapport au comportement par défaut de dm-crypt.

--perf-submit_from_crypt_cpus

Désactive le déchargement des écritures vers un thread séparé après le chiffrement. Dans certaines situations, le déchargement des bios d'écriture des threads de chiffrement vers un seul thread dégrade considérablement les performances. Par défaut, les bios d'écriture sont déchargés vers le même thread.

Cette option n'est disponible que pour le réglage de performance de dm-crypt de bas niveau, utilisez-la uniquement si vous avez besoin d'un changement
