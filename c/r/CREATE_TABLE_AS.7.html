DESCRIPTIO

N

CREATE TABLE AS crée une table et la remplit avec des données calculées par une commande SELECT. Les colonnes de la table portent les noms et les types de données associés aux colonnes de sortie de la SELECT (sauf que vous pouvez remplacer les noms de colonnes en fournissant une liste explicite de nouveaux noms de colonnes)

.

CREATE TABLE AS présente certaines similitudes avec la création d'une vue, mais en réalité c'est tout à fait différent : cela crée une nouvelle table et évalue la requête une seule fois pour remplir initialement la nouvelle table. La nouvelle table ne suivra pas les modifications ultérieures des tables sources de la requête. En revanche, une vue réévalue sa instruction SELECT définissante chaque fois qu'elle est

interrogée.

CREATE TABLE AS nécessite le privilège CREA

TE sur le schéma
utilisé pour la table.

PARAMÈTRE

S

GLOBAL ou

LOCAL
Ignoré pour des raisons de compatibilité. L'utilisation de ces mots-clés est déconseillée ; voir CREATE TABLE (CREATE_TABLE(7)) pour plus de
détails.

TEMPORARY ou

TEMP
Si spécifié, la table est créée en tant que table temporaire. Voir CREATE TABLE (CREATE_TABLE(7)) pour plus de
détails.

UNLOGGE

D
Si spécifié, la table est créée en tant que table non journalisée (unlogged). Voir CREATE TABLE (CREATE_TABLE(7)) pour plus de
détails.

IF NOT

EXISTS
Ne pas lever d'erreur si une relation portant le même nom existe déjà ; émettre simplement un avertissement et laisser la table
inchangée.

table_nam

e
Le nom (éventuellement qualifié par le schéma) de la table à
créer.

column_nam

e
Le nom d'une colonne dans la nouvelle table. Si les noms de colonnes ne sont pas fournis, ils sont repris des noms de colonnes de sortie de la
requête.

USING metho

d
Cette clause facultative spécifie la méthode d'accès à la table à utiliser pour stocker le contenu de la nouvelle table ; la méthode doit être une méthode d'accès de type TABLE. Voir le Chapitre 62 pour plus d'informations. Si cette option n'est pas spécifiée, la méthode d'accès par défaut est choisie pour la nouvelle table. Voir default_table_access_method pour plus
d'informations.

WITH ( storage_parameter [= value] [, ... ]

)
Cette clause spécifie des paramètres de stockage facultatifs pour la nouvelle table ; voir les Paramètres de stockage dans la documentation de CREATE TABLE (CREATE_TABLE(7)) pour plus de détails. Pour des raisons de compatibilité ascendante, la clause WITH d'une table peut également inclure OIDS=FALSE pour spécifier que les lignes de la nouvelle table ne doivent contenir aucun OID (identifiant d'objet) ; OIDS=TRUE n'est plus pris en
charge.

WITHOUT

OIDS
Il s'agit d'une syntaxe rétrocompatible pour déclarer une table WITHOUT OIDS ; la création d'une table WITH OIDS n'est plus prise en
charge.

ON

COMMIT
Le comportement des tables temporaires à la fin d'un bloc de transaction peut être contrôlé à l'aide de ON COMMIT. Les trois options sont :

PRESERVE

ROWS
Aucune action spéciale n'est entreprise à la fin des transactions. C'est le comportement par
défaut.

DELETE

ROWS
Toutes les lignes de la table temporaire seront supprimées à la fin de chaque bloc de transaction. Essentiellement, un TRUNCATE automatique est effectué à chaque
validation.

DRO

P

upprimée à la fin du bl

TABLESPACE tablespace_nam

e
Le tablespace_name est le nom du tablespace dans lequel la nouvelle table doit être créée. S'il n'est pas spécifié, default_tablespace est consulté, ou temp_tablespaces si la table est
temporaire.

quer

y
Une SELECT, TABLE, ou VALUES commande, ou une EXECUTE commande qui exécute une SELECT, TABLE, ou VALUES requête
préparée.

WITH [ NO ]

DATA
Cette clause spécifie si les données produites par la requête doive
nt être copiées dans la nouvelle table ou non. Si non, seule la st

NOTE

S

Cette commande est fonctionnellement similaire à SELECT INTO (SELECT_INTO(7)), mais elle est préférée car elle est moins susceptible d'être confondue avec d'autres utilisations de la syntaxe SELECT INTO. De plus, CREATE TABLE AS offre un sur-ensemble des fonctionnalités offertes par SELECT

IN
TO.

EXEMPLE

S

Créer une nouvelle table films_recent composée uniquement des entrées récentes de la table films

: 
CREATE TABLE films_recent AS
SELECT * FROM films WHER
E date_prod >= '2002-01-01';

Pour copier une table complètement, la forme courte utilisant la commande TABLE peut également être utilisée

: 
CREATE TABLE
films2 AS
TABLE films;

Créer une nouvelle table temporaire films_recent, composée uniquement des entrées récentes de la table films, à l'aide d'une instruction préparée. La nouvelle table sera supprimée à la validation

: 
PREPARE recentfilms(date) AS
  SELECT *
FROM films WHERE date_prod > $1; CREATE
TEMP TABLE films_recent ON COMMIT DROP
AS EXECUTE recentfilms('2002-01-01');

COMPATIBILIT

É

CREATE TABLE AS est conforme à la norme SQL. Les éléments suivants sont des extensions non standard

:
•La norme exige des parenthèses autour de la clause sous-requête ; dans PostgreSQL, ces parenthèses sont
facultatives.
•Dans la norme, la clause WITH [ NO ] DATA est requise ; dans PostgreSQL, elle est
facultative.
•PostgreSQL gère les tables temporaires d'une manière plutôt différente de la norme ; voir CREATE TABLE (CREATE_TABLE(7)) pour plus de
détails.
•La clause WITH est une extension PostgreSQL ; les paramètres de stockage ne font pas partie de la
norme.
•Le concept de tablespaces de PostgreSQL ne
fait pas partie de la norme. Par conséque
nt, la clause TABLESPACE est une extension.
