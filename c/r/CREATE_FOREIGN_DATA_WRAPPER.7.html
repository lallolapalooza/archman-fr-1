CREATE FOREIGN DATA WRAPPER(7) Documentation PostgreSQL 18.1 CREATE FOREIGN DATA WRAPPER(7)

NOM

CREATE_FOREIGN_DATA_WRAPPER - définir un nouveau wrapper de données étrangères

SYNTAXE

CREATE FOREIGN DATA WRAPPER nom
    [ HANDLER fonction_gestionnaire | NO HANDLER ]
    [ VALIDATOR fonction_validateur | NO VALIDATOR ]
    [ OPTIONS ( option 'valeur' [, ... ] ) ]

DESCRIPTION

CREATE FOREIGN DATA WRAPPER crée un nouveau wrapper de données étrangères. L'utilisateur qui définit un wrapper de données étrangères en devient le propriétaire.

Le nom du wrapper de données étrangères doit être unique dans la base de données.

Seuls les superutilisateurs peuvent créer des wrappers de données étrangères.

PARAMETRES

nom

Le nom du wrapper de données étrangères à créer.

HANDLER fonction_gestionnaire

fonction_gestionnaire est le nom d'une fonction préalablement enregistrée qui sera appelée pour récupérer les fonctions d'exécution des tables étrangères. La fonction gestionnaire ne doit prendre aucun argument et son type de retour doit être fdw_handler.

Il est possible de créer un wrapper de données étrangères sans fonction gestionnaire, mais les tables étrangères utilisant un tel wrapper ne pourront être que déclarées, pas accédées.

VALIDATOR fonction_validateur

fonction_validateur est le nom d'une fonction préalablement enregistrée qui sera appelée pour vérifier les options génériques fournies au wrapper de données étrangères, ainsi que les options pour les serveurs étrangers, les mappages d'utilisateurs et les tables étrangères utilisant le wrapper de données étrangères. Si aucune fonction validateur ou NO VALIDATOR n'est spécifié, les options ne seront pas vérifiées au moment de la création. (Les wrappers de données étrangères ignoreront ou rejetteront potentiellement les spécifications d'options invalides au moment de l'exécution, selon l'implémentation.) La fonction validateur doit prendre deux arguments : un de type text[], qui contiendra le tableau des options telles qu'elles sont stockées dans les catalogues système, et un de type oid, qui sera l'OID du catalogue système contenant les options. Le type de retour est ignoré ; la fonction doit signaler les options invalides en utilisant la fonction ereport(ERROR).

OPTIONS ( option 'valeur' [, ... ] )

Cette clause spécifie les options pour le nouveau wrapper de données étrangères. Les noms et valeurs d'options autorisés sont spécifiques à chaque wrapper de données étrangères et sont validés à l'aide de la fonction validateur du wrapper de données étrangères. Les noms d'options doivent être uniques.

NOTES

La fonctionnalité des données étrangères de PostgreSQL est encore en développement actif. L'optimisation des requêtes est primitive (et laissée en grande partie au wrapper également). Par conséquent, il y a une marge considérable pour des améliorations de performance futures.

EXEMPLES

Créer un wrapper de données étrangères inutile nommé dummy :

CREATE FOREIGN DATA WRAPPER dummy;

Créer un wrapper de données étrangères nommé file avec la fonction gestionnaire file_fdw_handler :

CREATE FOREIGN DATA WRAPPER file HANDLER file_fdw_handler;

Créer un wrapper de données étrangères mywrapper avec quelques options :

CREATE FOREIGN DATA WRAPPER mywrapper
    OPTIONS (debug 'true');

COMPATIBILITE

CREATE FOREIGN DATA WRAPPER est conforme à la norme ISO/IEC 9075-9 (SQL/MED), à l'exception du fait que les clauses HANDLER et VALIDATOR sont des extensions et que les clauses standard LIBRARY et LANGUAGE ne sont pas implémentées dans PostgreSQL.

Notez, cependant, que la fonctionnalité SQL/MED dans son ensemble n'est pas encore conforme.
