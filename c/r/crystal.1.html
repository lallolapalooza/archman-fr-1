DESCRIPTIO

N

Crystal est un langage de programmation à ty

page statique. Il a été créé en pensant à
la beauté de Ruby et aux performances de C.

UTILISATI

ON

Vous pouvez compiler et exécuter un programme en invoquant le compilateur avec un seul nom de fichier

: 
crystal
some_pr
ogram.cr

Les fichiers Crystal se terminent généralement par l'extension .cr, bien que cela ne soit pas

obligatoire.

Vous pouvez également utiliser la commande run

: 
crystal r
un some_p
rogram.cr

Pour créer un exécutable, utilisez la commande build

: 
crystal bu
ild some_
program.cr

Cela créera un exécutable nommé « some_program »

.

Notez que par défaut, les exécutables générés ne sont pas entièrement optimisés. Pour activer les optimisations, utilisez l'indicateur --relea

se : 
crystal build
--release so
me_program.cr

Assurez-vous d'utiliser toujours --release pour les exécutables prêts pour la production et lors de l'exécution de

benchmarks.

Les optimisations ne sont pas activées par défaut car les temps de compilation sont beaucoup plus rapides sans elles et les performances du programme sont toujours assez bonnes sans elles, ce qui permet d'utiliser la commande crystal presque comme si

elle était un
interpréteur.

suivantes

Options

:

--cross-compil

e
Génère un fichier objet pour la compilation croisée et affiche la commande pour construire l'exécutable. Le fichier objet doit être copié sur le système cible et la commande affichée doit y être exécutée. Cet indicateur existe principalement pour porter le compilateur vers de nouvelles plateformes ; si possible, exécutez le compilateur directement sur la plateforme
cible.

-d, --debu

g
Génère la sortie avec des symboles de débogage symboliques. Ceux-ci sont lus lors du débogage du programme compilé avec des outils comme lldb, gdb, valgrind etc. et fournissent des correspondances avec le code source original pour ces
outils.

--no-debu

g
Génère la sortie sans aucun symbole de débogage
symbolique.

-D INDICATEUR, --define INDICATE

UR
Définit un indicateur de compilation. C'est utile pour définir conditionnellement des types, des méthodes ou des commandes en fonction des indicateurs disponibles à la compilation. Les indicateurs par défaut proviennent de la triple cible donnée avec --target-triple ou celle de l'hôte par défaut, si aucune n'est
donnée.

--emit [asm|llvm-bc|llvm-ir|obj

]
Liste séparée par des virgules des types de sortie que le compilateur doit émettre. Vous pouvez utiliser ceci pour voir l'IR LLVM généré, le bitcode LLVM, l'assemblage et les fichiers
objets.

--x86-asm-syntax [a

tt|intel]
Sélectionne le dialecte d'assemblage pour --emit=asm. La valeur par défaut est att, qui signifie la syntaxe AT&T prise en charge par des outils comme l'assembleur GNU. intel sélectionne la syntaxe Intel qui est préférée pour les outils
Windows.

--frame-pointers [auto|always|non-leaf

]
Contrôle la préservation des pointeurs de trame. La valeur par défaut, --frame-pointers=auto, préservera les pointeurs de trame lors des compilations de débogage et essaiera de les omettre lors des compilations de release (certaines plateformes exigent qu'ils restent activés). --frame-pointers=always les préservera toujours, et non-leaf forcera uniquement leur préservation sur les fonctions non
terminales.

-f text|json, --format tex

t|json
Format de sortie. Par défaut, text. Le format json peut être utilisé pour obtenir une sortie plus facile à
analyser.

--error-trac

e
Affiche la trace complète de l'erreur. Désactivé par défaut, car la trace complète rend généralement les messages d'erreur moins lisibles et peut ne pas toujours fournir des informations
pertinentes.

--l

l
Vide le fichier d'assemblage LLVM dans le répertoire de
sortie.

--link-flags INDICATEU

RS
Transmet des indicateurs supplémentaires au lieur. Bien que vous puissiez spécifier ces indicateurs dans le code source, c'est utile pour transmettre directement au lieur des informations spécifiques à l'environnement, comme des chemins de bibliothèque non standard ou des noms. Pour plus d'informations sur la spécification des indicateurs du lieur dans le code source, vous pouvez lire la section « C bindings » de la documentation disponible sur le site web
officiel.

--mcpu CP

U
Spécifie un CPU particulier pour lequel générer du code. Cela transmettra un indicateur -mcpu à LLVM, et n'est destiné qu'à être utilisé pour la compilation croisée. Pour une liste des CPU disponibles, passez --mcpu help lors de la compilation de tout code source Crystal. Passer --mcpu native transmettra le nom du CPU hôte pour optimiser les performances sur
l'hôte.

--mattr CP

U
Remplace ou contrôle des attributs spécifiques de la cible, comme le fait que les opérations SIMD soient activées ou non. Le jeu d'attributs par défaut est défini par le CPU actuel. Cela transmettra un indicateur -mattr à LLVM, et n'est destiné qu'à être utilisé pour la compilation croisée. Pour une liste des attributs disponibles, invoquez « llvm-as < /dev/null | llc -march=xyz -mattr=help »
.

--mcmodel default|kernel|tiny|small|medium|larg

e
Spécifie un modèle de code particulier pour lequel générer du code. Cela transmettra un indicateur --code-model à
LLVM.

--no-colo

r
Désactive la sortie en
couleurs.

fichier.

particulier.

Génère un module LLVM unique. Par défaut, un module LLVM est créé pour chaque type dans un programme. --release implique cette

Nombre maximal de threads à utiliser pour la génération de code. La valeur par défaut est 8

Nom du fichier source à lire depuis STDIN.

docs

Génère la documentation à partir des commentaires en utilisant un sous-ensemble de markdown. La sortie est enregistrée au format html dans le dossier docs/ créé. Plus d'informations sur les conventions de documentation sont disponibles sur https://crystal-lang.org/docs/conventions/documenting_code.html.

Options :

--project-name NOM

Définit le nom du projet. La valeur par défaut est extraite de shard.yml si disponible.

Si aucun défaut ne peut être trouvé, cette option est obligatoire.

--project-version VERSION

Définit la version du projet. La valeur par défaut est extraite du commit git actuel ou de shard.yml si disponible.

Si aucun défaut ne peut être trouvé, cette option est obligatoire.

--json-config-url URL

Définit l'URL pointant vers un fichier de configuration (utilisé pour découvrir les versions).

--source-refname NOMREF

Définit le nom de référence de la source (par exemple, tag git, hash de commit). La valeur par défaut est extraite du commit git actuel si disponible.

Si cette option est manquante et ne peut pas être déterminée automatiquement, le générateur ne peut pas produire de liens vers le code source.

--source-url-pattern URL

Définit le modèle d'URL pour les liens vers le code source. La valeur par défaut est extraite des remotes git ("origin" ou le premier) si disponible et que le modèle d'URL du fournisseur est reconnu.

Balises de remplacement prises en charge :

%{refname}

Référence du commit

%{path}

Chemin d'accès au fichier source dans le dépôt

%{filename}

Nom de base du fichier source

%{line}

Numéro de ligne

Si cette option est manquante et ne peut pas être déterminée automatiquement, le générateur ne peut pas produire de liens vers le code source.

-o DIR, --output DIR

Définit le répertoire de sortie (par défaut : ./docs).

-b URL, --canonical-base-url URL

Indique l'URL préférée avec l'élément de lien rel="canonical".

-b URL, --sitemap-base-url URL

Définit l'URL de base du sitemap. Le sitemap ne sera généré que lorsque cette option sera définie.

--sitemap-priority PRIO

Définit la priorité attribuée aux entrées du sitemap (par défaut : 1.0).

--sitemap-changefreq FREQ

Définit la fréquence de changement attribuée aux entrées du sitemap (par défaut : never).

OPTIMIZATION

S

Le niveau d'optimisation spécifie l'effort de génération de code pour produire un code optimal. C'est un compromis entre les performances de compilation (diminuant par niveau d'optimisation) et les performances d'exécution (augmentant par niveau d'optimisation)

.

Les builds de production devraient généralement avoir le niveau d'optimisation le plus élevé. Les meilleurs résultats sont obtenus avec --release qui implique aussi --single-modul

CRYSTAL_CACHE_DI

R

Définit le chemin où Crystal met en cache les résultats de compilation partiels pour des builds suivants plus rapides. Ce chemin est aussi utilisé pour stocker temporairement les exécutables lorsque les programmes Crystal sont exécutés avec 'crystal run' plutôt que 'crystal

bui
ld'.

CRYSTAL_EXEC_PAT

H

Détermine le chemin où c

rystal recherche les so
us-commandes externes.

CRYSTAL_LIBRARY_PAT

H

Définit les chemins où Crystal recherche les bibliothèques (binaires). Plusieurs chemins peuvent être séparés par ":". Ces chemins sont passés au lienur sous forme de drapeaux

-L.

Le motif '$ORIGIN' au début du chemin est remplacé par le répertoire où se trouve le binaire du compilateur. Par exe

mple, '$ORIGIN/../lib/crystal' résout le chemin de la bibliothèque standard de manière générique par rapport à l'
emplacement du compilateur, indépendamment des chemins absolus (en supposant que l'emplacement relatif est correct).

CRYSTAL_PAT

H

Définit les chemins où Crystal recherche les fichiers source requis. Plusieurs chemins peuvent être séparés par ":

".

Le motif '$ORIGIN' au début du chemin est remplacé par le répertoire où se trouve le binaire du compilateur. Par exemple

, '$ORIGIN/../share/crystal/src' résout le chemin de la bibliothèque standard de manière générique par rapport à l'
emplacement du compilateur, indépendamment des chemins absolus (en supposant que l'emplacement relatif est correct).

CRYSTAL_OPT

S

Définit les options à utiliser pour le compilateur Crystal en plus des argum

ents de la ligne de commande. La syntaxe est identique à celle des arguments
de la ligne de commande. C'est pratique lors de l'utilisation de Crystal dans
des configurations de build, par exemple 'CRYSTAL_OPTS=--debug make build'.
