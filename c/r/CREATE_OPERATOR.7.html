SYNOPSI

S 
CREATE OPERATOR nom (
    {FUNCTION|PROCEDURE} = nom_fonction
    [, LEFTARG = type_gauche ] [, RIGHTARG = type_droite ]
    [, COMMUTATOR = op_commutateur ] [, NEGATOR = op_negateur ]
    [, RESTRICT = proc_restriction ] [, JOIN = proc_jointure ]
    [, HASHES ] [, MERGES ]
)

DESCRIPTIO

N

CREATE OPERATOR définit un nouvel opérateur, nom. L'utilisateur qui définit un opérateur en devient le propriétaire. Si un nom de schéma est fourni, l'opérateur est créé dans le schéma spécifié. Sinon, il est créé dans le schéma

courant.

Le nom de l'opérateur est une séquence d'au plus NAMEDATALEN-1 (63 par défaut) caractères pris dans la liste suivante

: 
+ - * / < > = ~ ! @ # % ^ & |
`
?

Il existe quelques restrictions sur le choix du nom

:
•-- et /* ne peuvent apparaître nulle part dans un nom d'opérateur, car ils seront interprétés comme le début d'un
commentaire.
•Un nom d'opérateur multcaractère ne peut pas se terminer par + ou -, à moins que le nom contienne également au moins un de ces caractères : 
~ ! @ # % ^ & |
`
?

Par exemple, @- est un nom d'opérateur autorisé, mais *- ne l'est

pas. Cette restriction permet à PostgreSQL d'analyser des com
mandes conformes à SQL sans exiger d'espaces entre les jetons.
•Le symbole => est réservé par la grammaire SQL, il ne peut donc pas être utilisé comme nom
d'opérateur.

L'opérateur != est converti en <> à l'entrée, ces deux noms sont donc toujours

équivalents.

Pour les opérateurs binaires, LEFTARG et RIGHTARG doivent tous deux être définis. Pour les opérateurs préfixés, seul RIGHTARG doit être défini. La fonction nom_fonction doit avoir été préalablement définie à l'aide de CREATE FUNCTION et doit être définie pour accepter le nombre correct d' arguments (un ou deux) des types

indiqués.

Dans la syntaxe de CREATE OPERATOR, les mots-clés FUNCTION et PROCEDURE sont équivalents, mais la fonction référencée doit dans tous les cas être une fonction, et non une procédure. L'utilisation du mot-clé PROCEDURE ici est historique et

obsolète.

Les autres clauses spécifient des attributs d'optimisation facultatifs de l'opérateur. Leur signification est détaillée à la section 36.

15.

Pour pouvoir créer un opérateur, vous devez disposer du privilège USAGE sur les types d'argume

nts et le type de retour, ainsi que du privilège EXECUTE sur la fonction sous-jacente. Si un o
pérateur commutateur ou négateur est spécifié, vous devez être propriétaire de ces opérateurs.

REMARQUE

S

Consultez la section 36.14 et la section 36.15 pour plus

d'informations.

Lorsque vous définissez un opérateur auto-commutatif, vous le faites simplement. Lorsque vous définissez une paire d'opérateurs commutatifs, les choses sont un peu plus délicates : comment le premier opérateur défini peut-il référencer l'autre, que vous n'avez pas encore défini ? Il existe trois solutions à ce problème

:
•Une manière consiste à omettre la clause COMMUTATOR dans le premier opérateur que vous définissez, puis à en fournir une dans la définition du second opérateur. Puisque PostgreSQL sait que les opérateurs commutatifs viennent par paires, lorsqu'il voit la seconde définition, il revient automatiquement pour compléter la clause COMMUTATOR manquante dans la première
définition.
•Une autre manière, plus directe, consiste simplement à inclure des clauses COMMUTATOR dans les deux définitions. Lorsque PostgreSQL traite la première définition et réalise que COMMUTATOR fait référence à un opérateur inexistant, le système créera une entrée factice pour cet opérateur dans le catalogue système. Cette entrée factice n'aura de données valides que pour le nom de l'opérateur, les types d'opérandes gauche et droit, et le propriétaire, car c'est tout ce que PostgreSQL peut déduire à ce stade. L'entrée au catalogue du premier opérateur sera liée à cette entrée factice. Plus tard, lorsque vous définirez le second opérateur, le système mettra à jour l'entrée factice avec les informations supplémentaires de la seconde définition. Si vous essayez d'utiliser l'opérateur factice avant qu'il ait été complété, vous obtiendrez simplement un message
d'erreur.
•Alternativement, les deux opérateurs peuvent être définis sans clauses COMMUTATOR, puis ALTER OPERATOR peut être utilisé pour établir leurs liens de commutation. Il suffit de ALTERER l'un ou l'autre de la
paire.

Dans les trois cas, vous devez être propriétaire des deux opérateurs afin de les marquer comme

commutateurs.

Les paires d'opérateurs négateurs peuvent être définies en utilisant les mêmes méthodes que pour les paires de

commutateurs.

Il n'est pas possible de spécifier la précédence lexicale d'un opérateur dans CREATE OPERATOR, car le comportement de précédence de l'analyseur est intégré. Consultez la section 4.1.6 pour les détails sur la

précédence.

Les options obsolètes SORT1, SORT2, LTCMP et GTCMP étaient autrefois utilisées pour spécifier les noms des opérateurs de tri associés à un opérateur jointurable par fusion. Cela n'est plus nécessaire, car les informations sur les opérateurs associés sont trouvées en examinant les familles d'opérateurs B-tree. Si l'une de ces options est donnée, elle est ignorée sauf pour mettre implicitement MERGES à

true.

Utilisez DROP OPERATOR pour supprimer les opérateurs définis par l'utilisateur d'une base de données. Utilisez ALTER OPERATOR pour modifier les o

pérateurs dans une
base de données.
