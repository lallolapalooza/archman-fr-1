en - ouvrir un périphérique chiffré et créer une correspondance avec un nom spécifié

SYNOPSI

S

cryptsetup open --type <device_type> [<options>] <device> <name>

DESCRIPTIO

N

Ouvre (crée une correspondance avec) <name> basée sur le périphérique <device>

.

Le type de périphérique peut être plain, luks (par défaut), luks1, luks2, loopaes ou tcrypt

.

Pour des raisons de compatibilité ascendante, il existe des alias de la commande open

:

create (ordre des arguments <name> <device>) : open --type plain
plainOpen : open --type plain
luksOpen : open --type luks
loopaesOpen : open --type loopaes
tcryptOpen : open --type tcrypt
bitlkOpen : open --type

bitlk

<options> sont spécifiques au type et sont décrites ci-dessous pour les types de périphériques individuels. Pour create, l'ordre des options <name> et <device> est inversé pour des raisons historiques ; tous les autres alias utilisent l'ordre standard <device> <name>

.

PLAI

N

open --type plain <device> <name> --cipher <spec> --key-size <bits> --hash <alg>
plainOpen <device> <name> (ancienne syntaxe)
create <name> <device> (syntaxe

OBSOLÈTE)

Ouvre (crée une correspondance avec) <name> basée sur le périphérique <device>

.

Vous devriez toujours spécifier les options --cipher, --key-size et (si aucun fichier de clé ou keyring n'est utilisé) également --hash pour éviter toute incompatibilité, car les valeurs par défaut peuvent différer dans les anciennes versions de

cryptsetup.

Le format plain permet également de récupérer une clé de volume à partir d'un keyring du noyau spécifié par --volume-key-keyring. La clé dans le keyring du noyau doit être configurée avant d'émettre les commandes cryptsetup, car cryptsetup ne téléverse aucune clé vers le keyring en mode plain. Pour les commandes suivantes (comme resize), l'utilisateur doit s'assurer que la clé dans le keyring est inchangée. Sinon, le rechargement de la clé peut causer une corruption des données après un changement de clé

inattendu.

<options> peut être [--hash, --cipher, --sector-size, --key-file, --keyfile-size, --keyfile-offset, --key-size, --offset, --skip, --device-size, --size, --readonly, --shared, --allow-discards, --refresh, --timeout, --verify-passphrase, --iv-large-sectors, --volume-key-keyring]

.

EXEMPLES

:

Pour mapper le périphérique chiffré /dev/sda10 vers le périphérique déchiffré /dev/mapper/e1, vous pouvez utiliser

:

cryptsetup open --type plain --cipher aes-cbc-essiv:sha256 --key-size 256 --hash sha256 /dev/sda10

e1

Le périphérique déchiffré peut ensuite être utilisé comme un périphérique bloc normal pour monter un système de

fichiers.

Pour mapper un périphérique avec une clé de volume dans le keyring de confiance ou chiffré préconfiguré, vous devez spécifier le keyring avec la clé et supprimer la spécification de hachage, par exemple, pour utiliser %trusted:m

ykey:

cryptsetup open --type plain /dev/sda10 e1 --volume-key-keyring=%trusted:mykey --cipher aes-xts-plain64 --key-size

256

Notez que la taille de la clé

doit correspondre à la clé
préconfigurée dans le keyring.

Ouvre le périphérique LUKS <device> et configure une correspondance <name> après la vérification réussie de la phrase de passe

Tout d'abord, la phrase de passe est recherchée dans les jetons LUKS2 non protégés par PIN. Si un tel jeton n'existe pas (ou échoue à déverrouiller le keyslot) et que la phrase de passe n'est pas fournie via --key-file, la commande invite à saisir la phrase de passe de manière

S'il existe un jeton LUKS2 valide mais qu'il nécessite un PIN pour déverrouiller le keyslot assigné, il n'est pas utilisé à moins que l'une des options suivantes ne soit ajoutée : --token-only, --token-type où type correspond au jeton protégé par PIN souhaité, ou --token-id avec id correspondant au jeton protégé par

PIN.

<options> peut être [--key-file, --keyfile-offset, --keyfile-size, --readonly, --test-passphrase, --allow-discards, --header, --key-slot, --volume-key-file, --token-id, --token-only, --token-type, --disable-external-tokens

--allow-discard

s
Autorise l'utilisation des requêtes discard (TRIM) pour le périphérique. Ceci n'est pas non plus pris en charge pour les périphériques LUKS2 avec protection d'intégrité des données.

clé>
Lie la clé de volume dans un trousseau avec le nom de clé spécifié. La clé de volume n'est liée que si l'action demandée est terminée avec succès (avec --test-passphrase, la clé de volume vérifiée est liée dans un trousseau sans effectuer d'action supplémentaire).

La chaîne <description du trousseau> doit contenir la description du trousseau de noyau existant. Le nom du trousseau peut éventuellement être préfixé par des descriptions de type "%:" ou "%keyring:". Ou, le trousseau peut également être spécifié directement par identifiant numérique de clé. De plus, des notations de trousseau spéciales commençant par "@" peuvent être utilisées pour sélectionner des trousseaux de noyau prédéfinis

existants.

La chaîne "::" est un délimiteur utilisé pour séparer la description du trousseau et la description de la

clé.

Le type peut être spécifié en ajoutant un préfixe "%<type_name>:" devant le nom de la clé. Si le type est manquant, le type par défaut user est appliqué. Si la clé du même nom et du même type existe déjà (déjà liée dans le trousseau), elle sera remplacée dans le

processus.

--persistent

Si utilisé avec les périphériques LUKS2 et les commandes d'activation comme open ou refresh, les indicateurs d'activation spécifiés sont écrits de manière persistante dans les métadonnées et utilisés automatiquement la prochaine fois, même pour l'activation normale. (Pas besoin d'utiliser cryptab ou d'autres fichiers de configuration système.)

Si vous devez supprimer un indicateur persistant, utilisez --persistent sans l'indicateur que vous souhaitez supprimer (par exemple, pour désactiver l'indicateur discard stocké de manière persistante, utilisez --persistent sans --allow-discards).

Seuls --allow-discards, --perf-same_cpu_crypt, --perf-submit_from_crypt_cpus, --perf-no_read_workqueue, --perf-no_write_workqueue et --integrity-no-journal peuvent être stockés de manière persistante.

--readonly, -r

Configure un mappage en lecture seule.

--refresh

Actualise un périphérique actif avec un nouvel ensemble de paramètres. Voir cryptsetup-refresh(8) pour plus de détails.

--sector-size octets

Définit la taille du secteur de chiffrement à utiliser avec le type de périphérique plain. Elle doit être une puissance de deux et comprise dans la plage de 512 à 4096 octets. La taille de secteur de chiffrement par défaut est de 512 octets.

Augmenter la taille du secteur de 512 à 4096 octets peut améliorer les performances sur la plupart des périphériques de stockage modernes et avec certains accélérateurs de chiffrement matériels.

Notez que l'utilisation d'une taille de secteur supérieure à la taille de secteur physique du périphérique de stockage sous-jacent peut entraîner une corruption des données lors de pannes de courant inattendues. Une panne de courant pendant les opérations d'écriture peut entraîner une complétion partielle de l'écriture du secteur de chiffrement, laissant les données chiffrées dans un état incohérent qui ne peut pas être correctement déchiffré.

--serialize-memory-hard-pbkdf

Utilise un verrouillage global pour sérialiser le déverrouillage des clés à l'aide de PBKDF à mémoire intensive.

Ceci est une solution de contournement pour une situation spécifique lorsque plusieurs périphériques sont activés en parallèle, et que le système, au lieu de signaler un manque de mémoire, commence à arrêter inconditionnellement les processus utilisant le tueur de processus en cas de manque de mémoire.

N'UTILISEZ PAS ce commutateur tant que vous n'implémentez pas l'environnement de démarrage avec une activation de périphériques parallèle !

--shared

Crée un mappage supplémentaire pour un périphérique de chiffrement commun. Les mappages arbitraires sont pris en charge. Cette option n'est pertinente que pour le type de périphérique plain. Utilisez --offset, --size et --skip pour spécifier la zone mappée.

--size, -b <nombre de secteurs de 512 octets>

Définit la taille du périphérique en secteurs de 512 octets. Utilisable uniquement avec le type de périphérique plain.

--skip, -p <nombre de secteurs de 512 octets>

Décalage de départ utilisé dans le calcul de l'IV en secteurs de 512 octets (combien de secteurs de données chiffrées ignorer au début). Cette option n'est pertinente qu'avec les types de périphériques plain ou loopaes.

Par conséquent, si --offset n, et --skip s, le secteur n (le premier secteur du périphérique chiffré) aura un numéro de secteur de s pour le calcul de l'IV.

--tcrypt-backup, --tcrypt-hidden, --tcrypt-system

Spécifie quel en-tête TrueCrypt sur disque sera utilisé pour ouvrir le périphérique. Voir la section TCRYPT de cryptsetup(8) pour plus d'informations.

L'utilisation d'un périphérique chiffré par le système avec l'option --tcrypt-system nécessite des réglages spécifiques pour fonctionner comme prévu.

TrueCrypt/VeraCrypt prend en charge le chiffrement complet du système (seule une table de partitions n'est pas chiffrée) ou le chiffrement de partition système (seule une partition système est chiffrée). L'en-tête de métadonnées contient alors le décalage et la taille de la zone chiffrée. Cryptsetup doit connaître le décalage spécifique de la partition pour calculer les paramètres de chiffrement. Pour mapper correctement une partition, vous devez spécifier un périphérique de partition réel afin que cryptsetup puisse calculer ce décalage.

Bien que vous puissiez utiliser un périphérique complet comme paramètre (/dev/sdb), préférez toujours spécifier la partition que vous souhaitez mapper (/dev/sdb1), car seul le mode partition système peut être détecté de cette manière.

Pour mapper des images (stockées dans un fichier), vous pouvez utiliser l'option supplémentaire --header avec le périphérique de partition réel. Si --header est utilisé (et qu'il est différent de l'image de données), cryptsetup s'attend à ce que l'image de données contienne un instantané de la partition de données uniquement.

Si --header n'est pas utilisé (ou pointe vers la même image), cryptsetup s'attend à ce que l'image contienne un disque complet (y compris la table des partitions). Cela peut mapper une zone chiffrée complète qui n'est pas directement montable en tant que système de fichiers. Veuillez préférer créer un périphérique loop avec des partitions (losetup -P, voir la page de manuel de losetup(8)) et utiliser une partition réelle (/dev/loopXp1) comme paramètre de périphérique.

--test-passphrase

Ne pas activer le périphérique, juste vérifier la phrase de passe. Le nom du mappage du périphérique n'est pas obligatoire si cette option est utilisée.

--timeout, -t secondes

Le nombre de secondes à attendre avant un délai d'expiration pour la saisie de la phrase de passe via le terminal. C'est pertinent chaque fois qu'une phrase de passe est demandée. Cela n'a aucun effet si utilisé en conjonction avec --key-file.

Cette option est utile lorsque le système ne doit pas se bloquer si l'utilisateur ne saisit pas de phrase de passe, par exemple, pendant le démarrage. La valeur par défaut est 0 seconde, ce qui signifie attendre indéfiniment.

--token-id

Spécifie quel jeton utiliser et permet à l'invite de code PIN du jeton de prendre la priorité sur l'invite interactive de phrase de passe de la clé. S'il est omis, tous les jetons disponibles (non protégés par un code PIN) seront vérifiés avant de continuer avec l'invite de phrase de passe.

--token-only

Ne pas continuer l'action si le déverrouillage de la clé basé sur un jeton a échoué. Sans l'option, l'action demande une phrase de passe pour continuer.

Elle permet aux jetons LUKS2 protégés par un code PIN de prendre la priorité sur l'invite interactive de phrase de passe de la clé.

--token-type type

Restreint les jetons éligibles à l'opération à un type de jeton spécifique. Utile principalement lorsqu'aucun --token-id n'est spécifié.

Elle permet aux jetons LUKS2 de type protégés par un code PIN de prendre la priorité sur l'invite interactive de phrase de passe de la clé.

--tries, -T

Combien de fois la saisie de la phrase de passe sera réessayée. La valeur par défaut est 3 essais.

--type type

Spécifie le type de périphérique requis. Pour plus d'informations, lisez la section ACTIONS DE BASE dans cryptsetup(8).

--unbound

Autorisé uniquement avec le paramètre --test-passphrase, il permet de tester la phrase de passe d'une clé LUKS2 non liée. Sinon, une phrase de passe de clé non liée ne peut être testée que lorsqu'une clé spécifique est sélectionnée via le paramètre --key-slot.

--usage

Afficher une aide rapide sur les options.

--veracrypt

Cette option est ignorée car le mode compatible VeraCrypt est pris en charge par défaut.

--veracrypt-pim, --veracrypt-query-pim

Utilise un multiplicateur d' itérations personnel (PIM) personnalisé pour le périphérique VeraCrypt. Voir la section TCRYPT de cryptsetup(8) pour plus d'informations.

--verify-passphrase, -y

Lors de la demande interactive d'une phrase de passe, demandez-la deux fois et signalez une erreur si les deux saisies ne correspondent pas. Recommandé lors de la création d'un mappage de type plain pour la première fois. Ignoré lors de la saisie depuis un fichier ou stdin.

--version, -V

Afficher la version du programme.

--volume-key-file fichier, --master-key-file fichier (alias OBSOLETE)

Utilise une clé de volume stockée dans un fichier.

Cela permet d'ouvrir les types de périphériques luks et bitlk sans fournir de phrase de passe.

Pour les périphériques en cours de réencodage, l'option peut être utilisée deux fois pour spécifier les clés de volume ancienne et nouvelle. Lorsque vous utilisez l'option deux fois, assurez-vous de coupler chaque option --volume-key-file avec le paramètre --key-size respectif également.

--volume-key-keyring <description de clé>

Utilise une clé de volume stockée dans un keyring. Cela permet d'ouvrir les types de périphériques luks et plain sans fournir de phrase de passe.

Pour LUKS, la clé et le type associé doivent être lisibles depuis l'espace utilisateur afin que le résumé de la clé de volume puisse être vérifié avant l'activation. Pour les périphériques en cours de réencodage, l'option peut être utilisée deux fois pour spécifier les clés de volume ancienne et nouvelle.

Pour le type PLAIN, l'utilisateur doit s'assurer que la clé dans le keyring n'a pas été modifiée depuis l'activation. Sinon, le rechargement de la clé peut entraîner une corruption des données après un changement de clé inattendu.

La <description de clé> utilise la syntaxe compatible avec keyctl. Cela peut être un identifiant de clé numérique ou un nom sous la forme %<type de clé>:<nom de clé>. Voir également la section IDENTIFIEURS DE CLÉ de keyctl(1). Lorsqu'aucun préfixe %<type de clé>: n'est spécifié, nous supposons que le type de clé est user (type par défaut).
