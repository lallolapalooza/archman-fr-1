SYNOPSI

S

cryptsetup token <add|remove|import|export|unassign> [<options>] <périphérique>

DESCRIPTIO

N

L'action add crée un nouveau jeton keyring pour permettre l'auto-activation du périphérique. Pour l'auto-activation, la phrase secrète doit être stockée dans le keyring avec la description spécifiée. Habituellement, la phrase secrète doit être stockée dans le user ou user-session keyring. La commande token n'est prise en charge que pour

LUKS2.

Pour ajouter un nouveau jeton keyring, l'option --key-description est obligatoire. De plus, un nouveau jeton est assigné au keyslot spécifié avec l'option --key-slot ou à tous les keyslots actifs si l'option --key-slot est

omise.

Pour supprimer un jeton existant, spécifiez l'ID du jeton à supprimer avec l'option

--token-id.

AVERTISSEMENT : L'action token remove supprime tout type de jeton, pas seulement le type keyring du slot de jeton spécifié par l'option

--token-id.

L'action import peut stocker des données JSON valides arbitraires dans le jeton LUKS2. Elles peuvent être transmises via l'entrée standard ou un fichier passé dans l'option --json-file. Si vous spécifiez --key-slot, un jeton importé avec succès est également assigné au

keyslot.

L'action export écrit le JSON du jeton demandé dans un fichier passé avec --json-file ou dans la sortie

standard.

L'action unassign supprime la liaison du jeton au keyslot spécifié. Le jeton et le keyslot doivent être spécifiés par les paramètres --token-id et

--key-slot.

Si --token-id est utilisé avec l'action add ou l'action import et qu'un jeton avec cet ID existe déjà, l'option --token-replace peut remplacer le jeton

existant.

<options> peut être [--header, --token-id, --key-slot, --key-description, --disable-external-tokens, --

disable-locks, --disable-keyring, --json-file, --
token-replace, --unbound, --external tokens-path].

--debug ou --debug-jso

n
Exécute en mode débogage avec des journaux de diagnostic complets. Les lignes de sortie de débogage sont toujours préfixées par #.

Si --debug-json est utilisé, les s

--disable-external-token

s
Désactive le chargement des plugins pour les jetons externes
LUKS2.

--disable-keyrin

g
Ne charge pas la clé de volume dans le keyring du noyau ; la stocke directement dans la cible dm-crypt à la place. Cette option n'est prise en charge que pour le type
LUKS2.

--disable-lock

s
Désactive la protection par verrouillage des métadonnées sur le disque. Cette option n'est valide que pour LUKS2 et est ignorée pour les autres formats.

AVERTISSEMENT : N'utilisez pas cette option à moins d'exécuter cryptsetup dans un environnement rest

reint où le verrouillage est impossible à effectuer (
où le répertoire /run ne peut pas être utilisé).

--external-tokens-path <chemin

absolu>
Remplace le chemin du répertoire système où cryptsetup recherche les gestionnaires de jetons externes (ou plugins de jeton). Il doit s'agir d'un chemin absolu (commençant par le caractère '/')
.

--header <périphérique ou fichier stockant l'en-tête

LUKS>
Utilise un périphérique ou un fichier de métadonnées détaché (séparé) où l'en-tête LUKS est stocké. Cette option permet de stocker le texte chiffré et l'en-tête LUKS sur des périphériques différents.

Pour les commandes qui modifient l'en-tête LUKS (par ex., luksAddKey), spécifiez directement le périphérique ou le

fichier avec l'en-tête LUKS
comme périphérique LUKS.

--help, -

?
Affiche le texte d'aide et les paramètres par
défaut.

--json-fil

e
Lit le JSON du jeton depuis un fichier ou y écrit le jeton. L'option --json-file=- lit le JSON depuis l'entrée standard ou l'écrit dans la sortie standard,
respectivement.

--key-description text

e
Définit la description de la clé dans le keyring qui sera utilisée pour la récupération de la phrase
secrète.

--key-slot, -S <0-N

>
Pour les opérations LUKS qui ajoutent du matériel de clé, cette option permet de spécifier quel keyslot est sélectionné pour la nouvelle clé.

Le nombre maximal de keyslots dépend de la version LUKS. LUKS1 peut avoir jusqu'à 8 keyslots.

LUKS2 peut avoir jusqu'à 32 keyslots en fonction de la taille de la zone keyslot et de la taill
e de la clé, mais un ID de keyslot valide peut toujours être compris entre 0 et 31 pour LUKS2.

--token-i

d
Spécifie le numéro de jeton. Si omis, le premier ID de jeton non utilisé est utilisé lors de l'ajout ou de l'importation d'un nouveau
jeton.

--token-replac

e
Remplace un jeton existant lors de l'ajout ou de l'importation d'un jeton avec l'option
--token-id.

--unboun

d
Crée un nouveau jeton keyring LUKS2 assigné à aucun keyslot. Utilisable uniquement avec l' action
add.
