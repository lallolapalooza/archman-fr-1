en - ouvrir un périphérique chiffré et créer une correspondance avec un nom spécifié

SYNOPSI

S

cryptsetup open --type <device_type> [<options>] <device> <name>

DESCRIPTIO

N

Ouvre (crée une correspondance avec) <name> basée sur le périphérique <device>

.

Le type de périphérique peut être plain, luks (par défaut), luks1, luks2, loopaes ou tcrypt

.

Pour des raisons de compatibilité ascendante, il existe des alias de la commande open

:

create (ordre des arguments <name> <device>) : open --type plain
plainOpen : open --type plain
luksOpen : open --type luks
loopaesOpen : open --type loopaes
tcryptOpen : open --type tcrypt
bitlkOpen : open --type

bitlk

<options> sont spécifiques au type et sont décrites ci-dessous pour les types de périphériques individuels. Pour create, l'ordre des options <name> et <device> est inversé pour des raisons historiques ; tous les autres alias utilisent l'ordre standard <device> <name>

.

PLAI

N

open --type plain <device> <name> --cipher <spec> --key-size <bits> --hash <alg>
plainOpen <device> <name> (ancienne syntaxe)
create <name> <device> (syntaxe

OBSOLÈTE)

Ouvre (crée une correspondance avec) <name> basée sur le périphérique <device>

.

Vous devriez toujours spécifier les options --cipher, --key-size et (si aucun fichier de clé ou keyring n'est utilisé) également --hash pour éviter toute incompatibilité, car les valeurs par défaut peuvent différer dans les anciennes versions de

cryptsetup.

Le format plain permet également de récupérer une clé de volume depuis un keyring du noyau spécifié par --volume-key-keyring. La clé dans le keyring du noyau doit être configurée avant d'émettre les commandes cryptsetup, car cryptsetup ne téléverse aucune clé vers le keyring en mode plain. Pour les commandes suivantes (comme resize), l'utilisateur doit s'assurer que la clé dans le keyring est inchangée. Sinon, le rechargement de la clé peut causer une corruption des données après un changement de clé

inattendu.

<options> peuvent être [--hash, --cipher, --sector-size, --key-file, --keyfile-size, --keyfile-offset, --key-size, --offset, --skip, --device-size, --size, --readonly, --shared, --allow-discards, --refresh, --timeout, --verify-passphrase, --iv-large-sectors, --volume-key-keyring]

.

EXEMPLES

:

Pour mapper le périphérique chiffré /dev/sda10 vers le périphérique déchiffré /dev/mapper/e1, vous pouvez utiliser

:

cryptsetup open --type plain --cipher aes-cbc-essiv:sha256 --key-size 256 --hash sha256 /dev/sda10

e1

Le périphérique déchiffré peut ensuite être utilisé comme un périphérique bloc normal pour monter un système de

fichiers.

Pour mapper un périphérique avec une clé de volume dans le keyring de confiance ou chiffré préconfiguré, vous devez spécifier le keyring avec la clé et supprimer la spécification de hachage, par exemple, pour utiliser %trusted:m

ykey:

cryptsetup open --type plain /dev/sda10 e1 --volume-key-keyring=%trusted:mykey --cipher aes-xts-plain64 --key-size

256

Notez que la taille de la clé

doit correspondre à la clé
préconfigurée dans le keyring.

OPTIONS

--allow-discards

Autorise l'utilisation des requêtes de suppression (TRIM) pour le périphérique. Ceci n'est pas non plus pris en charge pour les périphériques LUKS2 avec protection de l'intégrité des données.

ATTENTION : Cette commande peut avoir un impact négatif sur la sécurité car elle peut rendre visibles les opérations au niveau du système de fichiers sur le périphérique physique. Par exemple, des informations révélant le type de système de fichiers, l'espace utilisé, etc., peuvent être extraites du périphérique physique si les blocs supprimés peuvent être localisés ultérieurement. En cas de doute, ne l'utilisez pas.

Une version du noyau 3.1 ou ultérieure est nécessaire. Pour les noyaux antérieurs, cette option est ignorée.

--batch-mode, -q

Supprime toutes les questions de confirmation. À utiliser avec prudence !

Si l'option --verify-passphrase n'est pas spécifiée, cette option désactive également la vérification de la phrase de passe.

--cipher, -c <spécification-chiffrement>

Définit la chaîne de spécification du chiffrement pour le type de périphérique plain.

Pour le type de périphérique tcrypt, cela restreint les chaînes de chiffrement vérifiées lors de la recherche de l'en-tête.

cryptsetup --help affiche les valeurs par défaut intégrées.

Si un hachage fait partie de la spécification du chiffrement, il est alors utilisé dans le cadre de la génération de l'IV. Par exemple, ESSIV nécessite une fonction de hachage, tandis que "plain64" n'en nécessite pas et qu'ainsi aucune n'est spécifiée.

Pour le mode XTS, vous pouvez éventuellement définir une taille de clé de 512 bits avec l'option -s. La taille de la clé pour le mode XTS est le double de celle des autres modes pour le même niveau de sécurité.

--debug ou --debug-json

Exécute en mode débogage avec des journaux de diagnostic complets. Les lignes de sortie de débogage sont toujours précédées de #.

Si --debug-json est utilisé, des structures de données LUKS2 JSON supplémentaires sont imprimées.

--device-size taille[unités]

Au lieu de la taille réelle du périphérique, utilise la valeur spécifiée. Utilisable uniquement avec le type de périphérique plain.

Si aucun suffixe d'unité n'est spécifié, la taille est en octets.

Le suffixe d'unité peut être S pour des secteurs de 512 octets, K/M/G/T (ou KiB, MiB, GiB, TiB) pour des unités de base 1024 ou KB/MB/GB/TB pour une base 1000 (échelle SI).

--disable-external-tokens

Désactive le chargement des plugins pour les jetons LUKS2 externes.

--disable-keyring

Ne charge pas la clé du volume dans le trousseau de clés du noyau ; la stocke directement dans la cible dm-crypt à la place. Cette option n'est prise en charge que pour le type LUKS2.

--disable-locks

Désactive la protection par verrouillage des métadonnées sur disque. Cette option n'est valide que pour LUKS2 et est ignorée pour les autres formats.

ATTENTION : N'utilisez pas cette option à moins d'exécuter cryptsetup dans un environnement restreint où le verrouillage est impossible (où le répertoire /run ne peut pas être utilisé).

--disable-veracrypt

Cette option peut être utilisée pour désactiver le mode compatible VeraCrypt (seuls les périphériques TrueCrypt sont reconnus). Voir la section TCRYPT dans cryptsetup(8) pour plus d'informations.

--external-tokens-path <chemin absolu>

Remplace le chemin du répertoire système où cryptsetup recherche les gestionnaires de jetons externes (ou plugins de jetons). Ce doit être un chemin absolu (commençant par le caractère '/').

--hash, -h <spécification-hachage>

Spécifie le hachage de la phrase de passe. S'applique uniquement aux types de périphériques plain et loopaes.

Pour le type de périphérique tcrypt, cela restreint les variantes PBKDF2 vérifiées lors de la recherche de l'en-tête.

--header <périphérique ou fichier stockant l'en-tête LUKS>

Spécifie un périphérique ou un fichier de métadonnées détaché (séparé) où l'en-tête est stocké.

ATTENTION : Aucune vérification n'est effectuée pour déterminer si le périphérique de chiffrement spécifié appartient réellement à l'en-tête donné. En fait, vous pouvez spécifier un périphérique arbitraire comme périphérique de chiffrement avec l'option --header. Utilisez avec prudence.

--help, -?

Affiche le texte d'aide et les paramètres par défaut.

--iv-large-sectors

Compte le vecteur d'initialisation (IV) par secteur de plus grande taille (s'il est défini) au lieu de secteurs de 512 octets. Cette option ne peut être utilisée qu'avec le type de périphérique plain.

Cette option n'a aucun impact sur les performances ou la sécurité ; utilisez-la uniquement pour accéder à des images disque existantes incompatibles provenant d'autres systèmes qui nécessitent cette option.

--key-description texte

Définit la description de la clé dans le trousseau de clés qui sera utilisée pour la récupération de la phrase de passe.

--key-file, -d fichier

Lit la phrase de passe à partir du fichier.

Si le nom donné est "-", la phrase de passe sera lue depuis stdin. Dans ce cas, la lecture ne s'arrêtera pas aux caractères de nouvelle ligne.

Avec le type de périphérique plain, la phrase de passe obtenue via l'option --key-file est passée directement dans dm-crypt. Contrairement au mode interactif (stdin), où le résumé de la phrase de passe est passé dans dm-crypt à la place.

Voir la section NOTES SUR LE TRAITEMENT DES PHRASES DE PASSE dans cryptsetup(8) pour plus d'informations.

--keyfile-offset valeur

Saute valeur octets au début du fichier clé.

--keyfile-size, -l valeur

Lit un maximum de valeur octets à partir du fichier clé. Par défaut, on lit tout le fichier jusqu'au maximum intégré qui peut être interrogé avec --help. Fournir plus de données que le maximum intégré arrête l'opération.

Cette option est utile pour couper les nouvelles lignes finales, par exemple. Si --keyfile-offset est également donné, le comptage de la taille commence après le décalage.

--key-size, -s bits

Définit la taille de la clé en bits. L'argument doit être un multiple de 8. Les tailles de clé possibles sont limitées par le chiffrement et le mode utilisés.

Voir /proc/crypto pour plus d'informations. Notez que la taille de la clé dans /proc/crypto est indiquée en octets.

Cette option peut être utilisée pour les périphériques plain et luks. Pour les périphériques LUKS2 en ré-chiffrement, vous pouvez utiliser le paramètre deux fois pour spécifier les anciennes et nouvelles tailles de clé de volume. Chaque option --key-size correspond au paramètre --volume-key-file respectif (également autorisé à être utilisé jusqu'à deux fois).

--key-slot, -S <0-N>

Cette option sélectionne un slot de clé spécifique pour comparer la phrase de passe. Si la phrase de passe donnée ne correspond qu'à un slot de clé différent, l'opération échoue.

Le nombre maximum de slots de clés dépend de la version de LUKS. LUKS1 peut avoir jusqu'à 8 slots de clés. LUKS2 peut avoir jusqu'à 32 slots de clés en fonction de la taille de la zone du slot de clés et de la taille de la clé, mais un identifiant de slot de clés valide peut toujours être compris entre 0 et 31 pour LUKS2.

--link-vk-to-keyring <description-troussau::<description-clé>

Lie la clé de volume dans un trousseau de clés avec le nom de clé spécifié. La clé de volume n'est liée que si l'action demandée est terminée avec succès (avec --test-passphrase, la clé de volume vérifiée est liée dans un trousseau de clés sans prendre d'autres mesures).

La chaîne <description-troussau> doit contenir la description du trousseau de clés du noyau existant. Le nom du trousseau de clés peut éventuellement être précédé de descriptions de type "%:" ou "%keyring:". Ou, le trousseau de clés peut également être spécifié directement par son identifiant numérique. De plus, des notations spéciales de trousseau de clés commençant par "@" peuvent être utilisées pour sélectionner des trousseaux de clés prédéfinis existants.

La chaîne "::" est un délimiteur utilisé pour séparer la description du trousseau de clés et la description de la clé.

La partie <description-clé> décrit le type de clé et le nom de la clé de volume liés dans le trousseau de clés décrit dans <description-troussau>. Le type peut être spécifié en ajoutant un préfixe "%<nom_type>:" devant le nom de la clé. Si le type est manquant, le type user par défaut est appliqué. Si la clé du même nom et type existe déjà (déjà liée dans le trousseau de clés), elle sera remplacée dans le processus.

Voir également la section IDENTIFIANTS DE CLÉS de keyctl(1).

--offset, -o <nombre de secteurs de 512 octets>

Décalage de départ dans le périphérique de backend en secteurs de 512 octets. Cette option n'est pertinente qu'avec les types de périphériques plain ou loopaes.

--perf-high_priority

Définit les files de travail dm-crypt et le thread d'écriture sur une priorité élevée. Cela améliore le débit et la latence de dm-crypt tout en dégradant la réactivité générale du système.

Cette option n'est disponible que pour le réglage fin des performances dm-crypt de bas niveau, utilisez-la uniquement si vous avez besoin d'une modification du comportement par défaut de dm-crypt. Nécessite le noyau 6.10 ou ultérieur.

--perf-no_read_workqueue, --perf-no_write_workqueue

Contourne la file de travail interne de dm-crypt et traite les requêtes de lecture ou d'écriture de manière synchrone.

Ces options ne sont disponibles que pour le réglage fin des performances dm-crypt de bas niveau, utilisez-les uniquement si vous avez besoin d'une modification du comportement par défaut de dm-crypt. Nécessite le noyau 5.9 ou ultérieur.

--perf-same_cpu_crypt

Effectue le chiffrement en utilisant le même CPU sur lequel cette IO a été soumise. Par défaut, on utilise une file de travail non liée afin que le travail de chiffrement soit automatiquement équilibré entre les CPU disponibles.

Cette option n'est disponible que pour le réglage fin des performances dm-crypt de bas niveau, utilisez-la uniquement si vous avez besoin d'une modification du comportement par défaut de dm-crypt.

--perf-submit_from_crypt_cpus

Désactive le déchargement des écritures vers un thread séparé après le chiffrement. Il existe des situations où le déchargement des bios d'écriture des threads de chiffrement vers un seul thread dégrade considérablement les performances. Par défaut, les bios d'écriture sont déchargés vers le même thread.

Cette option n'est disponible que pour le réglage fin des performances dm-crypt de bas niveau, utilisez-la uniquement si vous avez besoin d'une modification de
