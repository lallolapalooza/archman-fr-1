CREATE SCHEMA(7) Documentation PostgreSQL 18.1 CREATE SCHEMA(7)

NOM

CREATE_SCHEMA - définir un nouveau schéma

SYNOPIS

CREATE SCHEMA nom_du_schema [ AUTHORIZATION specification_role ] [ element_schema [ ... ] ]
CREATE SCHEMA AUTHORIZATION specification_role [ element_schema [ ... ] ]
CREATE SCHEMA IF NOT EXISTS nom_du_schema [ AUTHORIZATION specification_role ]
CREATE SCHEMA IF NOT EXISTS AUTHORIZATION specification_role
où specification_role peut être :
    nom_utilisateur
  | CURRENT_ROLE
  | CURRENT_USER
  | SESSION_USER

DESCRIPTION

CREATE SCHEMA enregistre un nouveau schéma dans la base de données courante. Le nom du schéma doit être distinct du nom de tout schéma existant dans la base de données courante.

Un schéma est essentiellement un espace de noms : il contient des objets nommés (tables, types de données, fonctions et opérateurs) dont les noms peuvent faire doublon avec ceux d'autres objets existant dans d'autres schémas. Les objets nommés sont accessibles soit en « qualifiant » leurs noms avec le nom du schéma comme préfixe, soit en définissant un chemin de recherche qui inclut le(s) schéma(s) désiré(s). Une commande CREATE spécifiant un nom d'objet non qualifié crée l'objet dans le schéma courant (celui en tête du chemin de recherche, qui peut être déterminé avec la fonction current_schema).

Optionnellement, CREATE SCHEMA peut inclure des sous-commandes pour créer des objets dans le nouveau schéma. Les sous-commandes sont traitées essentiellement comme des commandes séparées exécutées après la création du schéma, à l'exception du cas où la clause AUTHORIZATION est utilisée, tous les objets créés appartiendront à cet utilisateur.

PARAMÈTRES

nom_du_schema

Le nom d'un schéma à créer. Si ceci est omis, le nom_utilisateur est utilisé comme nom de schéma. Le nom ne peut pas commencer par pg_, car de tels noms sont réservés aux schémas système.

nom_utilisateur

Le nom du rôle de l'utilisateur qui sera propriétaire du nouveau schéma. Si omis, il prend par défaut l'utilisateur exécutant la commande. Pour créer un schéma appartenant à un autre rôle, vous devez pouvoir utiliser SET ROLE sur ce rôle.

element_schema

Une instruction SQL définissant un objet à créer dans le schéma. Actuellement, seuls CREATE TABLE, CREATE VIEW, CREATE INDEX, CREATE SEQUENCE, CREATE TRIGGER et GRANT sont acceptés comme clauses dans CREATE SCHEMA. D'autres types d'objets peuvent être créés dans des commandes séparées après la création du schéma.

IF NOT EXISTS

Ne rien faire (sauf émettre un avis) si un schéma portant le même nom existe déjà. Les sous-commandes element_schema ne peuvent pas être incluses lorsque cette option est utilisée.

NOTES

Pour créer un schéma, l'utilisateur appelant doit avoir le privilège CREATE pour la base de données courante. (Bien sûr, les superutilisateurs contournent cette vérification.)

EXEMPLES

Créer un schéma :

CREATE SCHEMA myschema;

Créer un schéma pour l'utilisateur joe ; le schéma sera également nommé joe :

CREATE SCHEMA AUTHORIZATION joe;

Créer un schéma nommé test qui appartiendra à l'utilisateur joe, sauf s'il existe déjà un schéma nommé test. (Peu importe que joe possède le schéma préexistant.)

CREATE SCHEMA IF NOT EXISTS test AUTHORIZATION joe;

Créer un schéma et y créer une table et une vue :

CREATE SCHEMA hollywood
    CREATE TABLE films (title text, release date, awards text[])
    CREATE VIEW winners AS
        SELECT title, release FROM films WHERE awards IS NOT NULL;

Notez que les sous-commandes individuelles ne se terminent pas par des points-virgules.

La façon suivante permet d'accomplir le même résultat :

CREATE SCHEMA hollywood;
CREATE TABLE hollywood.films (title text, release date, awards text[]);
CREATE VIEW hollywood.winners AS
    SELECT title, release FROM hollywood.films WHERE awards IS NOT NULL;

COMPATIBILITÉ

La norme SQL autorise une clause DEFAULT CHARACTER SET dans CREATE SCHEMA, ainsi que plus de types de sous-commandes que ceux actuellement acceptés par PostgreSQL.

La norme SQL spécifie que les sous-commandes dans CREATE SCHEMA peuvent apparaître dans n'importe quel ordre. L'implémentation actuelle de PostgreSQL ne gère pas tous les cas de références antérieures dans les sous-commandes ; il peut parfois être nécessaire de réordonner les sous-commandes afin d'éviter les références antérieures.

Selon la norme SQL, le propriétaire d'un schéma possède toujours tous les objets qu'il contient. PostgreSQL permet aux schémas de contenir des objets appartenant à des utilisateurs autres que le propriétaire du schéma. Cela ne peut se produire que si le propriétaire du schéma accorde le privilège CREATE sur son schéma à quelqu'un d'autre, ou si un superutilisateur choisit de créer des objets en son sein.

L'option IF NOT EXISTS est une extension PostgreSQL.

VOIR AUSSI

ALTER SCHEMA (ALTER_SCHEMA(7)), DROP SCHEMA (DROP_SCHEMA(7))
