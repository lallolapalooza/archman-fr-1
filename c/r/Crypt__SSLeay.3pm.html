NOM

Crypt::SSLeay - Support d'OpenSSL pour LWP

AVERTISSEMENT HEARTBLEED

"perl Makefile.PL" affichera un avertissement s'il pense que votre OpenSSL pourrait être vulnérable au bogue Heartbleed https://cve.mitre.org/cgi-bin/cvename.cgi?name=CVE-2014-0160. Vous pouvez bien sûr continuer et installer le module, mais vous devez être conscient que votre système pourrait être exposé à une vulnérabilité extrêmement grave. Ceci n'est qu'une heuristique basée sur la version rapportée par OpenSSL. Il est tout à fait possible que votre distribution ait en réalité fourni une bibliothèque corrigée, donc si vous avez des inquiétudes, vous devriez investiguer davantage.

SYNOPSIS

use Net::SSL;
use LWP::UserAgent;
my $ua  = LWP::UserAgent->new(
    ssl_opts => { verify_hostname => 0 },
);
my $response = $ua->get('https://www.example.com/');
print $response->content, "\n";

DESCRIPTION

Ce module Perl fournit le support du protocole HTTPS sous LWP, pour permettre à un objet LWP::UserAgent d'effectuer des requêtes GET, HEAD et POST sur des connexions de socket chiffrées. Veuillez consulter LWP pour plus d'informations sur les requêtes POST.

Le "Crypt::SSLeay" paquet fournit "Net::SSL", qui, si demandé, est chargé par "LWP::Protocol::https" pour les requêtes https et fournit le nécessaire lien SSL.

Cette distribution rend également disponibles les modules suivants dépréciés :

Crypt::SSLeay::CTX
Crypt::SSLeay::Conn
Crypt::SSLeay::X509

AVEZ-VOUS BESOIN DE Crypt::SSLeay ?

À partir de la version 6.02 de LWP, "https" le support a été séparé dans LWP::Protocol::https. Ce module spécifie comme l'une de ses prérequis IO::Socket::SSL qui est automatiquement utilisé par LWP::UserAgent à moins que cette préférence soit surchargée séparément. "IO::Socket::SSL" est une implémentation plus complète, et, de manière cruciale, il permet la vérification du nom d'hôte. "Crypt::SSLeay" ne supporte pas cela. À ce stade, "Crypt::SSLeay" est maintenu pour supporter les logiciels existants qui en dépendent déjà. Cependant, il est possible que votre logiciel ne dépende pas vraiment de "Crypt::SSLeay", seulement de la capacité de "LWP::UserAgent" à communiquer avec des sites via SSL/TLS.

Si vous utilisez la version "LWP" 6.02 ou ultérieure, et avez donc installé "LWP::Protocol::https" et ses dépendances, et n'utilisez pas explicitement "use" "Net::SSL" avant de charger "LWP::UserAgent", ou ne surchargez pas la classe de socket par défaut, vous utilisez probablement "IO::Socket::SSL" et n'avez pas vraiment besoin de "Crypt::SSLeay".

Si vous avez à la fois "Crypt::SSLeay" et "IO::Socket::SSL" installés, et souhaitez forcer "LWP::UserAgent" à utiliser "Crypt::SSLeay", vous pouvez utiliser :

use Net::HTTPS;
$Net::HTTPS::SSL_SOCKET_CLASS = 'Net::SSL';
use LWP::UserAgent;

ou

local $ENV{PERL_NET_HTTPS_SSL_SOCKET_CLASS} = 'Net::SSL';
use LWP::UserAgent;

ou

use Net::SSL;
use LWP::UserAgent;

INSTALLATION

OpenSSL

Vous devez avoir OpenSSL installé avant de compiler ce module. Vous pouvez obtenir le dernier paquet OpenSSL depuis https://www.openssl.org/source/. Nous ne supportons plus les versions d'OpenSSL antérieures à 2000.

Si vous compilez OpenSSL à partir des sources, veuillez suivre les instructions incluses dans le paquet source.

Crypt::SSLeay via Makefile.PL

"Makefile.PL" accepte les arguments de ligne de commande suivants :

"incpath"
Chemin vers les en-têtes OpenSSL. Peut aussi être spécifié via $ENV{OPENSSL_INCLUDE}. Si l'argument de ligne de commande est fourni, il surcharge toute valeur spécifiée via la variable d'environnement. Bien sûr, vous pouvez ignorer à la fois l'argument de ligne de commande et la variable d'environnement, et simplement ajouter le chemin à votre variable d'environnement spécifique au compilateur telle que "CPATH" ou "INCLUDE" etc.
"libpath"
Chemin vers les bibliothèques OpenSSL. Peut aussi être spécifié via $ENV{OPENSSL_LIB}. Si l'argument de ligne de commande est fourni, il surcharge toute valeur spécifiée par la variable d'environnement. Bien sûr, vous pouvez ignorer à la fois l'argument de ligne de commande et la variable d'environnement et simplement ajouter le chemin à votre variable d'environnement spécifique au compilateur telle que "LIBRARY_PATH" ou "LIB" etc.
"live-tests"
Utilisez "--live-tests" pour demander des tests qui essaient de se connecter à un site web externe, et "--no-live_tests" pour empêcher de tels tests de s'exécuter. Si vous exécutez "Makefile.PL" de manière interactive, et que cet argument n'est pas spécifié sur la ligne de commande, vous serez invité à fournir une valeur.

La valeur par défaut est false.

"static"
Booléen. La valeur par défaut est false. À FAIRE: Est-ce que ça marche ?
"verbose"
Booléen. La valeur par défaut est false. Si vous passez "--verbose" sur la ligne de commande, à la fois "Devel::CheckLib" et "ExtUtils::CBuilder" les instances seront configurées pour écho ce qu'elles font.

Si tout se compile correctement, mais que vous obtenez des échecs lors des tests, assurez-vous que "LD_LIBRARY_PATH" pointe vers l'emplacement où se trouvent les bibliothèques partagées correctes.

Si vous utilisez une compilation personnalisée d'OpenSSL, veuillez garder à l'esprit que "Crypt::SSLeay" doit être compilé avec le même compilateur et les mêmes outils de compilation utilisés pour compiler "perl" et OpenSSL. Cela peut être plus problématique sur Windows. Si vous utilisez Active State Perl, installez le paquet MinGW distribué par eux, et compilez OpenSSL avec celui-ci avant d'essayer de compiler ce module. Si vous avez compilé votre propre Perl à l'aide des outils ou IDE de Microsoft SDK, assurez-vous de compiler OpenSSL avec les mêmes

outils.

Selon votre système d'exploitation, des paquets OpenSSL précompilés peuvent être disponibles. Pour obtenir les en-têtes requis et les bibliothèques d'importation, vous devrez peut-être installer une version de développement du paquet de la bibliothèque OpenSSL de votre système d'exploitation. L'essentiel est que "Crypt::SSLeay" effectue des appels à la bibliothèque OpenSSL, et la manière de le faire est spécifiée dans les fichiers d'en-tête C qui accompagnent la bibliothèque. Certains

systèmes séparent les fichiers d'en-tête dans un paquet distinct de celui des bibliothè

SUPPORT

Pour les problèmes liés à l'utilisation de "Crypt::SSLeay" et "Net::SSL" avec LWP de Perl, veuillez envoyer un courriel à "libwww@perl.org".

Pour OpenSSL ou le support SSL général, y compris les problèmes associés à la compilation et à l'installation d'OpenSSL sur votre système, veuillez envoyer un courriel à la liste de diffusion des utilisateurs OpenSSL à l'adresse "openssl-users@openssl.org". Voir http://www.openssl.org/support/community.html pour d'autres listes de diffusion et archives.

Veuillez signaler tous les bogues en utilisant rt.cpan.org http://rt.cpan.org/NoAuth/Bugs.html?Dist=Crypt-SSLeay.
