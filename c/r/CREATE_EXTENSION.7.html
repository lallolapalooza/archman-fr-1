DESCRIPTIO

N

CREATE EXTENSION charge une nouvelle extension dans la base de données courante. Il ne doit pas déjà y avoir d'extension du même nom

chargée.

Charger une extension revient essentiellement à exécuter le fichier script de l'extension. Ce script crée généralement de nouveaux objets SQL tels que des fonctions, des types de données, des opérateurs et des méthodes de support d'index. CREATE EXTENSION enregistre également les identités de tous les objets créés, afin qu'ils puissent être supprimés à nouveau si DROP EXTENSION est

exécuté.

L'utilisateur qui exécute CREATE EXTENSION devient le propriétaire de l'extension aux fins des vérifications de privilèges ultérieures, et devient normalement aussi le propriétaire de tout objet créé par le script de

l'extension.

Le chargement d'une extension nécessite normalement les mêmes privilèges que ceux requis pour créer ses objets composants. Pour de nombreuses extensions, cela signifie que des privilèges de superutilisateur sont nécessaires. Cependant, si l'extension est marquée comme de c

onfiance (trusted) dans son fichier de contrôle, elle peut être installée par tout utilisateur disposant du privilège CREATE sur la base de données courante. Dans ce cas, l'objet extension lui-même appartiendra à l'utilisateur appelant, mais les objets contenus apparti
endront au superutilisateur bootstrap (sauf si le script de l'extension les attribue explicitement à l'utilisateur appelant). Cette configuration donne à l'utilisateur appelant le droit de supprimer l'extension, mais pas de modifier les objets individuels qu'elle contient.

PARAMÈTRE

S

IF NOT

EXISTS
Ne pas générer d'erreur si une extension du même nom existe déjà. Un avertissement est émis dans ce cas. Notez qu'il n'y a aucune garantie que l'extension existante ressemble à celle qui aurait été créée à partir du fichier script actuellement
disponible.

extension_nam

e
Le nom de l'extension à installer. PostgreSQL créera l'extension en utilisant les détails du fichier extension_name.control, trouvé via le chemin de contrôle des extensions du serveur (défini par extension_control_path.
)

schema_nam

e
Le nom du schéma dans lequel installer les objets de l'extension, à condition que l'extension permette le déplacement de son contenu. Le schéma nommé doit déjà exister. S'il n'est pas spécifié, et si le fichier de contrôle de l'extension ne spécifie pas non plus de schéma, le schéma de création d'objets par défaut courant est utilisé.

Si l'extension spécifie un paramètre schema dans son fichier de contrôle, ce schéma ne peut pas être remplacé par une clause SCHEMA. Normalement, une erreur sera levée si une clause SCHEMA est donnée et qu'elle entre en conflit avec le paramètre schema de l'extension. Cependant, si la clause CASCADE est également donnée, alors schema_name est ignoré en cas de conflit. Le schema_name donné sera utilisé pour l'installation des extensions nécessaires qui ne spécifient pas de schema dans leurs fichiers de

contrôle.

Rappelez-vous que l'extension elle-même n'est pas considérée comme étant dans un schéma

: les extensions ont des noms non qualifiés qui doivent être uniques dans toute la base
de données. Mais les objets appartenant à l'extension peuvent se trouver dans des schémas.

versio

n
La version de l'extension à installer. Elle peut être écrite soit sous forme d'identifiant, soit sous forme de littéral de chaîne. La version par défaut est celle spécifiée dans le fichier de contrôle de
l'extension.

CASCAD

E
Installe automatiquement toutes les extensions dont cette extension dépend et qui ne sont pas déjà installées. Leurs dépendances sont également installées
automatiquement, de manière récursive. La clause SCHEMA, si elle est donnée, s'applique à toutes les extensions installées de cette manière. Les autres optio
ns de l'instruction ne s'appliquent pas aux extensions installées automatiquement ; en particulier, leurs versions par défaut sont toujours sélectionnées.

REMARQUE

S

Avant de pouvoir utiliser CREATE EXTENSION pour charger une extension dans une base de données, les fichiers de support de l'extension doivent être installés. Des informations sur l'installation des extensions fournies avec PostgreSQL peuvent être trouvées dans Modules fournis supplémentaires

.

Les extensions actuellement disponibles pour le chargement peuvent être identifiées à partir des vues système pg_available_extensions ou pg_available_extension_versions

.

Attention

Installer une extension en tant que superutilisateur nécessite de faire confiance au fait que l'auteur de l'extension a rédigé le script d'installation de l'extension de manière sécurisée. Il n'est pas très difficile pour un utilisateur malveillant de créer des objets cheval de Troie qui compromettront l'exécution ultérieure d'un script d'extension mal écrit, permettant à cet utilisateur d'obtenir des privilèges de superutilisateur. Cependant, les objets cheval de Troie ne sont dangereux que s'ils se trouvent dans le search_path lors de l'exécution du script, ce qui signifie qu'ils se trouvent dans le schéma cible d'installation de l'extension ou dans le schéma d'une extension dont elle dépend. Par conséquent, une bonne règle empirique lors du traitement d'extensions dont les scripts n'ont pas été soigneusement examinés est de ne les installer que dans des schémas pour lesquels le privilège CREATE n'a pas été et ne sera pas accordé à des utilisateurs non dignes de confiance. De même pour toute extension dont elles

dépendent.

On pense que les extensions fournies avec PostgreSQL sont sécurisées contre les attaques de ce type au moment de l'installation, à l'e

xception de quelques-unes qui dépendent d'autres extensions. Comme indiqué dans la documentation de ces extensions, elles doivent
être installées dans des schémas sécurisés, ou installées dans les mêmes schémas que les extensions dont elles dépendent, ou les deux.

Pour des informations sur la r

édaction de nouvelles extensio
ns, voir la Section 36.17.
