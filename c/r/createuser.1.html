createuser - définir

un nouveau compte ut

SYNOPSI

S

createuser [option-connexion...] [option...] [nom_utilisate

ur

DESCRIPTIO

N

createuser crée un nouvel utilisateur PostgreSQL (ou plus précisément, un rôle). Seuls les superutilisateurs et les utilisateurs disposant du privilège CREATEROLE peuvent créer de nouveaux utilisateurs ; createuser doit donc être invoqué par une personne pouvant se connecter en tant que superutilisateur ou utilisateur disposant du privilège

CREATEROLE.

Si vous souhaitez créer un rôle disposant des privilèges SUPERUSER, REPLICATION ou BYPASSRLS, vous devez vous connecter en tant que superutilisateur, et pas seulement avec le privilège CREATEROLE. Être superutilisateur implique la capacité de contourner toutes les vérifications de permissions d'accès au sein de la base de données ; l'accès superutilisateur ne doit donc pas être accordé à la légère. CREATEROLE confère également des privilèges très

étendus.

createuser est un enveloppe autour de la commande SQL CREATE ROLE. Il n'y a pas de différence effective entre la création d'util

isateurs via cette utilitaire et vi
a d'autres méthodes d'accès au serveur.

OPTION

S

createuser accepte les arguments de ligne de commande suivants

:

nom_utilisate

ur
Spécifie le nom de l'utilisateur PostgreSQL à créer. Ce nom doit être différent de tous les rôles existants dans cette installation
PostgreSQL.

-a rôle
--with-admin=rôl

e
Spécifie un rôle existant qui sera automatiquement ajouté comme membre du nouveau rôle avec l'option admin, lui donnant le droit d'accorder l'appartenance au nouveau rôle à d'autres. Plusieurs rôles existants peuvent être spécifiés en écrivant plusieurs interrupteu
rs -a.

-c nombre
--connection-limit=nombr

e
Définit un nombre maximal de connexions pour le nouvel utilisateur. Par défaut, aucune limite n'est
définie.

-d
--created

b
Le nouvel utilisateur sera autorisé à créer des bases de
données.

-D
--no-created

b
Le nouvel utilisateur ne sera pas autorisé à créer des bases de données. C'est le comportement par
défaut.

-e
--ech

o
Affiche les commandes que createuser génère et envoie au
serveur.

-E
--encrypte

d
Cette option est obsolète mais reste acceptée pour des raisons de compatibilité
ascendante.

-g rôle
--member-of=rôle
--role=rôle (obso

lète)
Spécifie que le nouveau rôle doit être automatiquement ajouté comme membre du rôle existant spécifié. Plusieurs rôles existants peuvent être spécifiés en écrivant plusieurs interrupteu
rs -g.

-i
--inheri

t
Le nouveau rôle héritera automatiquement des privilèges des rôles dont il est membre. C'est le comportement par
défaut.

-I
--no-inheri

t
Le nouveau rôle n'héritera pas automatiquement des privilèges des rôles dont il est
membre.

--interactiv

e
Invite à saisir le nom de l'utilisateur si aucun n'est spécifié sur la ligne de commande, et invite également à saisir l'une des options -d/-D, -r/-R, -s/-S qui n'est pas spécifiée sur la ligne de commande. (C'était le comportement par défaut jusqu'à PostgreSQL 9.1.
)

-l
--logi

n
Le nouvel utilisateur sera autorisé à se connecter (c'est-à-dire que le nom d'utilisateur peut être utilisé comme identifiant utilisateur initial de session). C'est le comportement par
défaut.

-L
--no-logi

n
Le nouvel utilisateur ne sera pas autorisé à se connecter. (Un rôle sans privilège de connexion reste utile comme moyen de gestion des permissions de la base de données.
)

-m rôle
--with-member=rôl

e
Spécifie un rôle existant qui sera automatiquement ajouté comme membre du nouveau rôle. Plusieurs rôles existants peuvent être spécifiés en écrivant plusieurs interrupteu
rs -m.

-P
--pwpromp

t
Si spécifié, createuser demandera le mot de passe du nouvel utilisateur. Cela n'est pas nécessaire si vous n'envisagez pas d'utiliser l'authentification par mot de
passe.

-r
--createrol

e
Le nouvel utilisateur sera autorisé à créer, modifier, supprimer, commenter, changer l'étiquette de sécurité d'autres rôles ; c'est-à-dire que cet utilisateur aura le privilège CREATEROLE. Voir la création de rôles pour plus de détails sur les capacités conférées par ce
privilège.

-R
--no-createrol

e
Le nouvel utilisateur ne sera pas autorisé à créer de nouveaux rôles. C'est le comportement par
défaut.

-s
--superuse

r
Le nouvel utilisateur sera un superutilisateur
.

-S
--no-superuse

r
Le nouvel utilisateur ne sera pas un superutilisateur. C'est le comportement par
défaut.

-v horodatage
--valid-until=horodatag

e
Définit une date et une heure après lesquelles le mot de passe du rôle n'est plus valide. Par défaut, aucune date d'expiration du mot de passe n'est
définie.

-V
--versio

n
Affiche la version de createuser et
quitte.

--bypassrl

s
Le nouvel utilisateur contournera toutes les politiques de sécurité au niveau des lignes (RLS)
.

--no-bypassrl

s
Le nouvel utilisateur ne contournera pas les politiques de sécurité au niveau des lignes (RLS). C'est le comportement par
défaut.

--replicatio

n
Le nouvel utilisateur aura le privilège REPLICATION, qui est décrit plus en détail dans la documentation pour CREATE ROLE (CREATE_ROLE(7))
.

--no-replicatio

n
Le nouvel utilisateur n'aura pas le privilège REPLICATION, qui est décrit plus en détail dans la documentation pour CREATE ROLE (CREATE_ROLE(7)). C'est le comportement par
défaut.

-?
--hel

p
Affiche l'aide concernant les arguments de ligne de commande de createuser et
quitte.

createuser accepte également les arguments de ligne de commande suivants pour les paramètres de connexion

:

-h hôte
--host=hôt

e
Spécifie le nom d'hôte de la machine sur laquelle le serveur s'exécute. Si la valeur commence par une barre oblique, elle est utilisée comme répertoire pour le socket de domaine
Unix.

-p port
--port=por

t
Spécifie le port TCP ou l'extension du fichier de socket de domaine Unix local sur lequel le serveur écoute les
connexions.

-U nom_utilisateur
--username=nom_utilisate

ur
Nom d'utilisateur pour la connexion (pas le nom d'utilisateur à créer)
.

-w
--no-passwor

d
Ne demande jamais de mot de passe. Si le serveur exige une authentification par mot de passe et qu'un mot de passe n'est pas disponible par d'autres moyens tels qu'un fichier .pgpass, la tentative de connexion échouera. Cette option peut être utile dans des tâches par lots et des scripts où aucun utilisateur n'est présent pour saisir un mot de
passe.

-W
--passwor

d
Force createuser à demander un mot de passe (pour la connexion au serveur, pas pour le mot de passe du nouvel utilisateur).

Cette option n'est jamais essentielle, car createuser demandera automatiquement un mot de passe si le serveur exige une authentification par mot de passe. Cependant, createuser gaspillera une tentative de connexion pour découvrir que le serveur veut un mot de passe. Dans certains cas, il vaut la peine de taper -W pour éviter la tent

ative de con
nexion supp
lémentaire.

T

PGUSE

Paramètres de connexion par
défaut

PG_COLO

R
Spécifie s'il faut utiliser la couleur dans les messages de diagnostic. Les valeurs possibles sont always, auto et

15)
.

DIAGNOSTIC

S

En cas dey, voir CREATE ROLE (CREATE_ROLE(7)) et psql(1) pour des discussions sur les problèmes potentiels et les messages d'erreur. Le serveur de base de données doit être en cours d'exécution sur l'hôte cible. De plus, tous les paramètres de connexion par défaut et les variables d'environnement utilisés par la bibliothèque front-end libpq s'appliqueront.

EXEMPLES

Pour créer un utilisateur joe sur le serveur de base de données par défaut :

$ createuser joe

Pour créer un utilisateur joe sur le serveur de base de données par défaut en demandant certains attributs supplémentaires :

$ createuser --interactive joe
Le nouveau rôle sera-t-il un superutilisateur ? (o/n) n
Le nouveau rôle sera-t-il autorisé à créer des bases de données ? (o/n) n
Le nouveau rôle sera-t-il autorisé à créer d'autres nouveaux rôles ? (o/n) n

Pour créer le même utilisateur joe en utilisant le serveur sur l'hôte eden, port 5000, avec des attributs spécifiés explicitement, en examinant la commande sous-jacente :

$ createuser -h eden -p 5000 -S -D -R -e joe
CREATE ROLE joe NOSUPERUSER NOCREATEDB NOCREATEROLE INHERIT LOGIN;

Pour créer l'utilisateur joe en tant que superutilisateur et lui attribuer un mot de passe immédiatement :

$ createuser -P -s -e joe
Entrez le mot de passe pour le nouveau rôle : xyzzy
Entrez-le à nouveau : xyzzy
CREATE ROLE joe PASSWORD 'md5b5f5ba1a423792b526f799ae4eb3d59e' SUPERUSER CREATEDB CREATEROLE INHERIT LOGIN;

Dans l'exemple ci-dessus, le nouveau mot de passe n'est pas réellement affiché lorsqu'il est tapé, mais nous montrons ce qui a été tapé pour plus de clarté. Comme vous le voyez, le mot de passe est chiffré avant d'être envoyé au client.
