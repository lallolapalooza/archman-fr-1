SYNOPSI

S 
CREATE OPERATOR CLASS nom [ DEFAULT ] FOR TYPE type_de_données
  USING méthode_index [ FAMILY nom_famille ] AS
  {  OPERATOR numéro_de_stratégie nom_opérateur [ ( type_op, type_op ) ] [ FOR SEARCH | FOR ORDER BY nom_famille_de_tri ]
   | FUNCTION numéro_de_support [ ( type_op [ , type_op ] ) ] nom_fonction ( type_argument [, ...] )
   | STORAGE type_stockage
  } [, ...
]

DESCRIPTIO

N

CREATE OPERATOR CLASS crée une nouvelle classe d'opérateurs. Une classe d'opérateurs définit comment un type de données particulier peut être utilisé avec un index. La classe d'opérateurs spécifie que certains opérateurs rempliront des rôles ou « stratégies » particulières pour ce type de données et cette méthode d'index. La classe d'opérateurs spécifie également les fonctions de support à utiliser par la méthode d'index lorsque la classe d'opérateurs est sélectionnée pour une colonne d'index. Tous les opérateurs et fonctions utilisés par une classe d'opérateurs doivent être définis avant que la classe d'opérateurs puisse être

créée.

Si un nom de schéma est fourni, la classe d'opérateurs est créée dans le schéma spécifié. Sinon, elle est créée dans le schéma courant. Deux classes d'opérateurs dans le même schéma peuvent avoir le même nom seulement si elles sont pour des méthodes d'index

différentes.

L'utilisateur qui définit une classe d'opérateurs en devient le propriétaire. Actuellement, l'utilisateur créateur doit être un superutilisateur. (Cette restriction est imposée car une définition erronée de classe d'opérateurs pourrait perturber ou même faire planter le serveur.

)

CREATE OPERATOR CLASS ne vérifie pas actuellement si la définition de la classe d'opérateurs inclut tous les opérateurs et fonctions requis par la méthode d'index, ni si les opérateurs et fonctions forment un ensemble cohérent. Il est de la responsabilité de l'utilisateur de définir une classe d'opérateurs

valide.

Les classes d'opérateurs liées peuvent être regroupées en familles d'opérateurs. Pour ajouter une nouvelle classe d'opérateurs à une famille existante, spécifiez l'option FAMILY dans CREATE OPERATOR CLASS. Sans cette option, la nouvelle classe est placée dans une famille portant le même nom que la nouvelle classe (cette famille est créée si elle n'existe pas déjà)

.

Voir la section

36.16 pour plus
d'informations.

DEFAUL

T
S'il est présent, la classe d'opérateurs deviendra la classe d'opérateurs par défaut pour son type de données. Au plus une classe d'opérateurs peut être la par défaut pour un type de données et une méthode d'index
spécifiques.

type_de_donnée

s
Le type de données de la colonne pour lequel cette classe d'opérateurs est
destinée.

méthode_inde

x
Le nom de la méthode d'index pour laquelle cette classe d'opérateurs est
destinée.

nom_famill

e
Le nom de la famille d'opérateurs existante à laquelle ajouter cette classe d'opérateurs. Si non spécifié, une famille portant le même nom que la classe d'opérateurs est utilisée (elle est créée si elle n'existe pas déjà)
.

numéro_de_stratégi

e
Le numéro de stratégie de la méthode d'index pour un opérateur associé à la classe
d'opérateurs.

nom_opérateu

r
Le nom (éventuellement qualifié par un schéma) d'un opérateur associé à la classe
d'opérateurs.

type_o

p
Dans une clause OPERATOR, le ou les types de données des opérandes de l'opérateur, ou NONE pour signifier un opérateur de préfixe. Les types de données des opérandes peuvent être omis dans le cas normal où ils sont identiques au type de données de la classe d'opérateurs.

Dans une clause FUNCTION, le ou les types de données des opérandes que la fonction est censée prendre en charge, si différents des types de données d'entrée de la fonction (pour les fonctions de comparaison B-tree et les fonctions de hachage) ou du type de données de la classe (pour les fonctions de support de tri B-tree, les fonctions d'image d'égalité B-tree, et toutes les fonctions dans les classes d'opérateurs GiST, SP-GiST, GIN et BRIN). Ces valeurs par défaut sont correctes, et donc op_type n'a pas besoin d'être spécifié dans les clauses FUNCTION, sauf dans le cas d'une fonction de sup

port de tri B-tree qui est censée prendre en char
ge les comparaisons entre types de données différents.

nom_famille_de_tr

i
Le nom (éventuellement qualifié par un schéma) d'une famille d'opérateurs btree existante qui décrit l'ordre de tri associé à un opérateur d'ordre.

Si ni FOR SEARCH ni FOR ORDER

BY n'est spécifié, FOR SEARCH
est la valeur par défaut.

numéro_de_suppor

t
Le numéro de fonction de support de la méthode d'index pour une fonction associée à la classe
d'opérateurs.

nom_fonctio

n
Le nom (éventuellement qualifié par un schéma) d'une fonction qui est une fonction de support de méthode d'index pour la classe
d'opérateurs.

type_argumen

t
Le ou les types de données des paramètres de la
fonction.

type_stockag

e
Le type de données réellement stocké dans l'index. Normalement, c'est le même que le type de données de la colonne, mais certaines méthodes d'index (actuellement GiST, GIN, SP-GiST et BRIN) permettent qu'il soit différent. La clause STORAGE doit être omise sauf si la méthode d'index permet l'utilisation d'un type différent. Si la colonne type_de_données est spécifiée comme anyarray, le type_stockage peut être déclaré comme anyelement pour indiquer que les entrées d'index sont des membres du type élément appartenant au type de tableau réel pour lequel chaque index particulier est
créé.

Les clauses OPERATOR, FUNCTION

et STORAGE peuvent apparaître
dans n'importe quel ordre.

NOTE

S

Comme le mécanisme d'index ne vérifie pas les permissions d'accès sur les fonctions avant de les utiliser, inclure une fonction ou un opérateur dans une classe d'opérateurs équivaut à accorder une permission d'exécution publique sur celui-ci. Cela n'est généralement pas un problème pour les types de fonctions utiles dans une classe

d'opérateurs.

Les opérateurs ne devraient pas être définis par des fonctions SQL. Une fonc

tion SQL a tendance à être intégrée dans la requête appelante, ce qui emp
êchera l'optimiseur de reconnaître que la requête correspond à un index.

EXEMPLE

S

La commande d'exemple suivante définit une classe d'opérateurs d'index GiST pour le type de données _int4 (tableau de int4). Voir le module intarray pour l'exemple

complet. 
CREATE OPERATOR CLASS gist__int_ops
    DEFAULT FOR TYPE _int4 USING gist AS
        OPERATOR        3       &&,
        OPERATOR        6       = (anyarray, anyarray),
        OPERATOR        7
@>, OPERATOR 8 <@, OPERATOR 20 @@ (_int4, query_int), FUNCTION 1 g_int_consistent (internal, _int4, smallint, oid, internal),
FUNCTION 2 g_int_union (internal, internal), FUNCTION 3 g_int_compress (internal), FUNCTION 4 g_int_decompress (internal), FUNCTION
5 g_int_penalty (internal, internal, internal), FUNCTION 6 g_int_picksplit (internal, internal), FUNCTION 7 g_int_same (_int4, _int4, internal);
