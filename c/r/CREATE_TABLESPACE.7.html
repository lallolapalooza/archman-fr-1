Paquet: postgresql

Licences: PostgreSQL

CREATE TABLESPACE(7) Documentation PostgreSQL 18.1 CREATE TABLESPACE(7)

NOM

CREATE_TABLESPACE - définir un nouvel espace de tables

SYNTAXE

CREATE TABLESPACE nom_espace_tables
    [ OWNER { nouveau_propriétaire | CURRENT_ROLE | CURRENT_USER | SESSION_USER } ]
    LOCATION 'répertoire'
    [ WITH ( option_espace_tables = valeur [, ... ] ) ]

DESCRIPTION

CREATE TABLESPACE enregistre un nouvel espace de tables à l'échelle du cluster. Le nom de l'espace de tables doit être distinct du nom de tout espace de tables existant dans le cluster de bases de données.

Un espace de tables permet aux superutilisateurs de définir un emplacement alternatif sur le système de fichiers où peuvent résider les fichiers de données contenant les objets de base de données (tels que les tables et les index).

Un utilisateur disposant des privilèges appropriés peut passer nom_espace_tables à CREATE DATABASE, CREATE TABLE, CREATE INDEX ou ADD CONSTRAINT pour que les fichiers de données de ces objets soient stockés dans l'espace de tables spécifié.


Attention

Un espace de tables ne peut pas être utilisé indépendamment du cluster dans lequel il est défini ; voir la Section 22.6.

PARAMÈTRES

nom_espace_tables

Le nom d'un espace de tables à créer. Le nom ne peut pas commencer par pg_, car de tels noms sont réservés aux espaces de tables système.

nom_utilisateur

Le nom de l'utilisateur qui sera propriétaire de l'espace de tables. Si omis, il prend par défaut l'utilisateur qui exécute la commande. Seuls les superutilisateurs peuvent créer des espaces de tables, mais ils peuvent en attribuer la propriété à des utilisateurs non superutilisateurs.

répertoire

Le répertoire qui sera utilisé pour l'espace de tables. Le répertoire doit exister (CREATE TABLESPACE ne le créera pas), doit être vide et doit appartenir à l'utilisateur système PostgreSQL. Le répertoire doit être spécifié par un chemin d'accès absolu.

option_espace_tables

Un paramètre d'espace de tables à définir ou à réinitialiser. Actuellement, les seuls paramètres disponibles sont seq_page_cost, random_page_cost, effective_io_concurrency et maintenance_io_concurrency. La définition de ces valeurs pour un espace de tables particulier remplacera l'estimation habituelle du planificateur du coût de lecture des pages des tables dans cet espace de tables, et le nombre d'E/S concurrentes émises, tel qu'établi par les paramètres de configuration du même nom (voir seq_page_cost, random_page_cost, effective_io_concurrency, maintenance_io_concurrency). Cela peut être utile si un espace de tables est situé sur un disque plus rapide ou plus lent que le reste du sous-système d'E/S.

NOTES

CREATE TABLESPACE ne peut pas être exécuté à l'intérieur d'un bloc transactionnel.

EXEMPLES

Pour créer un espace de tables dbspace à l'emplacement du système de fichiers /data/dbs, créez d'abord le répertoire à l'aide des fonctionnalités du système d'exploitation et définissez le propriétaire correct :

mkdir /data/dbs
chown postgres:postgres /data/dbs

Puis émettez la commande de création d'espace de tables à l'intérieur de PostgreSQL :

CREATE TABLESPACE dbspace LOCATION '/data/dbs';

Pour créer un espace de tables appartenant à un autre utilisateur de base de données, utilisez une commande comme celle-ci :

CREATE TABLESPACE indexspace OWNER genevieve LOCATION '/data/indexes';

COMPATIBILITÉ

CREATE TABLESPACE est une extension PostgreSQL.
