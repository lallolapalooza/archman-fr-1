DESCRIPTION

Implémentation basée sur OCI du Démon d'Interface de Gestion des Conteneurs de Kubernetes

crio est destiné à fournir un chemin d'intégration entre les gestionnaires de conteneurs conformes à OCI et le kubelet. Plus précisément, il implémente l'Interface de Gestion des Conteneurs du Kubelet (CRI) en utilisant des gestionnaires conformes à OCI. Le périmètre de crio est lié au périmètre de la CRI.

1.
Prise en charge de plusieurs formats d'images, y compris les formats d'images Docker et OCI existants.
2.
Prise en charge de plusieurs moyens de télécharger des images, y compris la confiance et la vérification des images.
3.
Gestion des images de conteneurs (gestion des couches d'images, systèmes de fichiers en superposition, etc.).
4.
Gestion du cycle de vie des processus de conteneurs.
5.
Surveillance et journalisation nécessaires pour satisfaire la CRI.
6.
Isolation des ressources telle que requise par la CRI.

Utilisation:

crio [OPTIONS GLOBALES] commande [OPTIONS DE COMMANDE] [ARGUMENTS...]

OPTIONS GLOBALES

--absent-mount-sources-to-reject="" : Une liste de chemins qui, lorsqu'ils sont absents de l'hôte, provoqueront l'échec de la création d'un conteneur (par opposition au comportement actuel qui consiste à créer un répertoire).

--add-inheritable-capabilities: Ajoute des capacités à l'ensemble héritable, ainsi qu'au groupe par défaut des capacités autorisées, de limitation et effectives.

--additional-devices="" : Périphériques à ajouter aux conteneurs.

--allowed-devices="" : Périphériques qu'un utilisateur est autorisé à spécifier avec l'annotation autorisée "io.kubernetes.cri-o.Devices". (par défaut : "/dev/fuse", "/dev/net/tun")

--apparmor-profile="" : Nom du profil apparmor à utiliser comme profil par défaut du gestionnaire de conteneurs. Cela n'a d'effet que si l'utilisateur ne spécifie pas de profil via l'annotation des métadonnées du Pod Kubernetes. (par défaut : "crio-default")

--auto-reload-registries: Si vrai, CRI-O rechargera automatiquement le registre miroir lorsqu'il y a une mise à jour du répertoire 'registries.conf.d'. La valeur par défaut est 'false'.

--big-files-temporary-dir="" : Chemin du répertoire temporaire à utiliser pour stocker les gros fichiers, utilisé pour stocker les blobs d'images et les flux de données liés à la gestion des images de conteneurs.

--bind-mount-prefix="" : Un préfixe à utiliser pour la source des montages par liaison. Cette option serait utile si vous exécutiez CRI-O dans un conteneur. Et que '/' était monté sur '/host' dans votre conteneur. Alors, si vous exécutiez CRI-O avec l'option '--bind-mount-prefix=/host', CRI-O ajouterait /host à tous les montages par liaison qui lui sont transmis via CRI. Si Kubernetes demandait à avoir '/var/lib/foobar' monté par liaison dans le conteneur, alors CRI-O monterait '/host/var/lib/foobar' par liaison. Puisque CRI-O lui-même s'exécute dans un conteneur avec '/' ou l'hôte monté sur '/host', le conteneur se retrouverait avec '/var/lib/foobar' de l'hôte monté dans le conteneur plutôt que '/var/lib/foobar' du conteneur CRI-O.

--blockio-config-file="" : Chemin du fichier de configuration des classes blockio pour configurer le contrôleur blockio des cgroups.

--blockio-reload: Recharge blockio-config-file et rescanne les périphériques blockio du système avant d'appliquer les paramètres blockio.

--cdi-spec-dirs="" : Répertoires à scanner pour les fichiers de spécification CDI. (par défaut : "/etc/cdi", "/run/cdi")

--cgroup-manager="" : Gestionnaire de cgroups (cgroupfs ou systemd). (par défaut : "systemd")

--clean-shutdown-file="" : Emplacement où CRI-O place le fichier d'arrêt propre. Il indique si nous avons eu le temps de synchroniser les modifications sur le disque avant l'arrêt. S'il est introuvable, crio wipe effacera le répertoire de stockage. (par défaut : "/var/lib/crio/clean.shutdown")

--cni-config-dir="" : Répertoire des fichiers de configuration CNI. (par défaut : "/etc/cni/net.d/")

--cni-default-network="" : Nom du réseau CNI par défaut à sélectionner. S'il n'est pas défini ou est "", alors CRI-O choisira le premier trouvé dans --cni-config-dir.

--cni-plugin-dir="" : Répertoire des binaires des plugins CNI.

--collection-period="" : Le nombre de secondes entre la collecte des statistiques pod/conteneur et les métriques du bac à sable du pod. Si défini à 0, les métriques/statistiques sont collectées à la demande. (par défaut : 0)

--config, -c="" : Chemin du fichier de configuration (par défaut : "/etc/crio/crio.conf")

--config-dir, -d="" : Chemin du répertoire de configuration de type drop-in.
Ce répertoire sera parcouru récursivement et chaque fichier sera appliqué
à la configuration dans leur ordre de traitement. Cela signifie qu'un
fichier de configuration nommé '00-default' a une priorité inférieure à un fichier
nommé '01-my-overwrite'.
Le fichier de configuration global, fourni via '--config,-c' ou par défaut dans
/etc/crio/crio.conf, atoujours une priorité inférieure à celle des fichiers du répertoire spécifié
par '--config-dir,-d'.
De plus, les paramètres de ligne de commande fournis ont une priorité supérieure
à celle de tout fichier de configuration. (par défaut : "/etc/crio/crio.conf.d")

--conmon="": Chemin vers le binaire conmon, utilisé pour surveiller l'exécution OCI. Sera recherché dans $PATH si vide. Cette option est dépréciée et sera supprimée dans le futur.

--conmon-cgroup="": cgroup à utiliser pour le processus conmon. Cette option est dépréciée et sera supprimée dans le futur.

--conmon-env="": Liste de variables d'environnement pour le processus conmon, utilisée pour passer les variables d'environnement nécessaires à conmon ou à l'exécution. Cette option est dépréciée et sera supprimée dans le futur.

--container-attach-socket-dir="": Chemin vers le répertoire pour les sockets d'attachement de conteneurs. (par défaut : "/run/crio")

--container-exits-dir="": Chemin vers le répertoire dans lequel les fichiers de sortie des conteneurs sont écrits par conmon. (par défaut : "/run/crio/exits")

--ctr-stop-timeout="": Le temps minimal en secondes à attendre avant d'émettre un délai d'expiration concernant la terminaison correcte du conteneur. La valeur possible la plus basse est 30s, les valeurs inférieures ne sont pas prises en compte par CRI-O. (par défaut : 30)

--decryption-keys-path="": Chemin pour charger les clés de déchiffrement des images. (par défaut : "/etc/crio/keys/")

--default-capabilities="": Capacités à ajouter aux conteneurs. (par défaut : "CHOWN", "DAC_OVERRIDE", "FSETID", "FOWNER", "SETGID", "SETUID", "SETPCAP", "NET_BIND_SERVICE", "KILL")

--default-env="": Variables d'environnement supplémentaires à définir pour tous les conteneurs.

--default-mounts-file="": Chemin vers le fichier de montages par défaut.

--default-runtime="": Exécution OCI par défaut à partir de la configuration des exécutions. (par défaut : "crun")

--default-sysctls="": Sysctls à ajouter aux conteneurs.

--default-transport="": Un préfixe à ajouter aux noms d'images qui ne peuvent pas être tirées telles quelles. (par défaut : "docker://")

--default-ulimits="": Ulimits à appliquer aux conteneurs par défaut (nom=soft:hard).

--device-ownership-from-security-context: Définir la propriété uid/gid des périphériques à partir de runAsUser/runAsGroup.

--disable-hostport-mapping: Si vrai, CRI-O désactiverait le mappage du port hôte.

--drop-infra-ctr: Détermine si les pods sont créés sans conteneur infra, lorsque le pod n'utilise pas d'espace de noms PID au niveau du pod.

--enable-criu-support: Activer l'intégration CRIU, nécessite que le binaire criu soit disponible dans $PATH.

--enable-metrics: Activer le point de terminaison des métriques pour le serveur.

--enable-nri: Activer la prise en charge de NRI (Node Resource Interface).

--enable-pod-events: Si vrai, CRI-O commence à envoyer les événements des conteneurs au kubelet

--enable-profile-unix-socket: Activer le profilur pprof sur la socket de domaine unix de crio.

--enable-tracing: Activer l'exportation des données de trace OpenTelemetry.

--gid-mappings="": Spécifier les mappements de GID à utiliser pour l'espace de noms utilisateur. Cette option est dépréciée et sera remplacée dans le futur par la prise en charge des espaces de noms d'utilisateur Kubernetes (KEP-127).

--global-auth-file="": Chemin vers un fichier comme /var/lib/kubelet/config.json contenant les identifiants nécessaires pour tirer des images depuis des registres sécurisés.

--grpc-max-recv-msg-size="": Taille maximale de réception des messages grpc en octets. (par défaut : 83886080)

--grpc-max-send-msg-size="": Taille maximale de réception des messages grpc. (par défaut : 83886080)

--help, -h: afficher l'aide

--hooks-dir="": Définir le chemin du répertoire des hooks OCI (peut être défini plusieurs fois)
Si l'un des répertoires n'existe pas, CRI-O les ignorera
automatiquement.
Chaque fichier '*.json' dans le chemin configure un hook pour les
conteneurs CRI-O. Pour plus de détails sur la syntaxe des fichiers JSON et
la sémantique de l'injection de hooks, voir 'oci-hooks(5)'. CRI-O
prend actuellement en charge les schémas de hooks 1.0.0 et 0.1.0, bien que
le schéma 0.1.0 soit déprécié.
Cette option peut être définie plusieurs fois ; les chemins des options suivantes
ont une priorité supérieure ('oci-hooks(5)' discute de la
priorité des répertoires).
Pour les conditions d'annotation, CRI-O utilise les annotations
Kubernetes, qui sont un sous-ensemble des annotations passées à
l'exécution OCI. Par exemple, 'io.kubernetes.cri-o.Volumes' fait partie
des annotations de configuration de l'exécution OCI, mais ne fait pas partie
des annotations Kubernetes correspondant aux hooks.
Pour les conditions de montage par liaison, seuls les montages explicitement
demandés par la configuration Kubernetes sont considérés. Les montages par
liaison que CRI-O insère par défaut (par ex. '/dev/shm') ne sont pas considérés. (par défaut : "/usr/share/containers/oci/hooks.d")

--hostnetwork-disable-selinux: Détermine si SELinux doit être désactivé dans un pod lorsqu'il s'exécute dans l'espace de noms réseau de l'hôte.

--image-volumes="": Gestion des volumes d'images ('mkdir', 'bind' ou 'ignore')
1. mkdir : Un répertoire est créé dans le système de fichiers racine du conteneur pour
les volumes.
2. bind : Un répertoire est créé dans le répertoire d'état du conteneur et monté
par liaison dans le conteneur pour les volumes. 3. ignore : Tous les volumes sont simplement ignorés et aucune action n'est entreprise. (par défaut : "mkdir")

--imagestore="": Stocker les images nouvellement tirées dans le chemin spécifié, plutôt que le chemin fourni par --root.

--included-pod-metrics="": Une liste de métriques de pod à inclure. Spécifiez les noms des métriques à inclure dans cette liste.

--infra-ctr-cpuset="": Ensemble de CPU pour exécuter les conteneurs infra, si non spécifié CRI-O utilisera tous les CPU en ligne pour exécuter les conteneurs infra.

--insecure-registry="": Activer la communication avec les registres non sécurisés, c'est-à-dire activer la communication non chiffrée et/ou non fiable.
Cette option est dépréciée. Veuillez utiliser "insecure" dans registries.conf à la place.
1. La liste des registres non sécurisés peut contenir un élément avec une notation CIDR pour
spécifier un sous-réseau entier.
2. Les registres non sécurisés acceptent HTTP ou acceptent HTTPS avec des certificats de
CA inconnus.
3. Activer '--insecure-registry' est utile lors de l'exécution d'un registre local.
Cependant, car son utilisation crée des vulnérabilités de sécurité, il ne doit ÊTRE
activé que dans un but de test. Pour une sécurité accrue, les utilisateurs devraient ajouter
leur CA à la liste des CA de confiance de leur système au lieu d'utiliser
'--insecure-registry'.

--internal-repair: Si vrai, CRI-O vérifiera si le stockage des conteneurs et des images a été corrompu après un redémarrage soudain, et tentera de réparer le stockage si c'est le cas.

--internal-wipe: Si CRI-O doit effacer les conteneurs après un redémarrage et les images après une mise à jour lorsque le serveur démarre. Si défini à false, l'utilisateur doit exécuter 'crio wipe' pour effacer les conteneurs et les images dans ces situations. Cette option est dépréciée et sera supprimée dans le futur.

--irqbalance-config-file="": Le fichier de configuration du service irqbalance utilisé par CRI-O. (par défaut : "/etc/sysconfig/irqbalance")

--irqbalance-config-restore-file="": Détermine si CRI-O doit tenter de restaurer la configuration d'irqbalance au démarrage avec le masque dans ce fichier. Utilisez la valeur 'disable' pour désactiver complètement le flux de restauration. (par défaut : "/etc/sysconfig/orig_irq_banned_cpus")

--listen="": Chemin vers la socket de CRI-O. (par défaut : "/run/crio/crio.sock")

--log="": Définir le chemin du fichier de journal où les informations de débogage internes sont écrites.

--log-dir="": Répertoire de journal par défaut où tous les journaux iront sauf si spécifié directement par le kubelet. (par défaut : "/var/log/crio/pods")

--log-filter="": Filtrer les messages de journal par l'expression régulière fournie. Par exemple 'request.*' filtre toutes les requêtes gRPC.

--log-format="": Définir le format utilisé par les journaux : 'text' ou 'json'. (par défaut : "text")

--log-journald: Journaliser dans le journal systemd (journald) en plus du fichier de journal kubernetes.

--log-level, -l="": Journaliser les messages au-dessus du niveau spécifié : trace, debug, info, warn, error, fatal ou panic. (par défaut : "info")

--log-size-max="": Taille maximale du journal en octets pour un conteneur. Si c'est positif, il doit être >= 8192 pour correspondre/dépasser le tampon de lecture de conmon. Cette option est dépréciée. L'indicateur de kubelet '--container-log-max-size' devrait être utilisé à la place. (par défaut : -1)

--metrics-cert="": Certificat pour le point de terminaison des métriques sécurisé.

--metrics-collectors="": Collecteurs de métriques activés. (par défaut : "image_pulls_layer_size", "containers_events_dropped_total", "containers_oom_total", "processes_defunct", "operations_total", "operations_latency_seconds", "operations_latency_seconds_total", "operations_errors_total", "image_pulls_bytes_total", "image_pulls_skipped_bytes_total", "image_pulls_failure_total", "image_pulls_success_total", "image_layer_reuse_total", "containers_oom_count_total", "containers_seccomp_notifier_count_total", "resources_stalled_at_stage", "containers_stopped_monitor_count")

--metrics-host="": Hôte pour le point de terminaison des métriques. (par défaut : "127.0.0.1")

--metrics-key="": Clé du certificat pour le point de terminaison des métriques sécurisé.

--metrics-port="": Port pour le point de terminaison des métriques. (par défaut : 9090)

--metrics-socket="": Socket pour le point de terminaison des métriques.

--minimum-mappable-gid="": Spécifier le GID hôte le plus bas qui peut être spécifié dans les mappements pour un pod qui sera exécuté avec un UID autre que 0. Cette option est dépréciée et sera remplacée par la prise en charge des espaces de noms d'utilisateur Kubernetes (KEP-127) dans le futur. (par défaut : -1)

--minimum-mappable-uid="": Spécifier le UID hôte le plus bas qui peut être spécifié dans les mappements pour un pod qui sera exécuté avec un UID autre que 0. Cette option est dépréciée et sera remplacée par la prise en charge des espaces de noms d'utilisateur Kubernetesr support de l'espace de noms (KEP-127) à l'avenir. (défaut : -1)

--namespaces-dir="" : Le répertoire où l'état des espaces de noms gérés est suivi. Utilisé uniquement lorsque manage-ns-lifecycle est vrai. (défaut : "/run")

--no-pivot : Si vrai, le runtime n'utilisera pas 'pivot_root', mais utilisera 'MS_MOVE'.

--nri-disable-connections : Désactive les connexions des plugins NRI démarrés extérieurement.

--nri-enable-default-validator : Active le plugin de validation NRI par défaut.

--nri-listen="" : Socket sur lequel écouter pour que les plugins NRI démarrés extérieurement se connectent. (défaut : "/run/nri/nri.sock")

--nri-plugin-config-dir="" : Répertoire à scanner pour la configuration des plugins NRI préinstallés. (défaut : "/etc/nri/conf.d")

--nri-plugin-dir="" : Répertoire à scanner pour les plugins NRI préinstallés à démarrer automatiquement. (défaut : "/opt/nri/plugins")

--nri-plugin-registration-timeout="" : Délai pour qu'un plugin s'enregistre auprès de NRI. (défaut : 5s)

--nri-plugin-request-timeout="" : Délai pour qu'un plugin traite une requête NRI. (défaut : 2s)

--nri-validator-reject-custom-seccomp-adjustment : Rejette l'ajustement de la politique seccomp personnalisée par le plugin NRI.

--nri-validator-reject-namespace-adjustment : Rejette l'ajustement des espaces de noms Linux par le plugin NRI.

--nri-validator-reject-oci-hook-adjustment : Rejette l'ajustement des OCI Hooks par le plugin NRI.

--nri-validator-reject-runtime-default-seccomp-adjustment : Rejette l'ajustement de la politique seccomp par défaut du runtime par le plugin NRI.

--nri-validator-reject-unconfined-seccomp-adjustment : Rejette l'ajustement de la politique seccomp non restreinte par le plugin NRI.

--nri-validator-required-plugins="" : Liste des plugins NRI requis qui doivent être présents.

--nri-validator-tolerate-missing-plugins-annotation="" : Nom de l'annotation utilisée pour indiquer la tolérance aux plugins NRI requis manquants.

--oci-artifact-mount-support : Si vrai, CRI-O peut monter des artefacts OCI comme volumes.

--pause-command="" : Chemin d'accès à l'exécutable pause dans l'image pause. (défaut : "/pause")

--pause-image="" : Image contenant l'exécutable pause. (défaut : "registry.k8s.io/pause:3.10.1")

--pause-image-auth-file="" : Chemin d'accès à un fichier de configuration contenant les informations d'identification pour --pause-image.

--pids-limit="" : Nombre maximum de processus autorisés dans un conteneur. Cette option est obsolète. L'option Kubelet '--pod-pids-limit' doit être utilisée à la place. (défaut : -1)

--pinned-images="" : Une liste d'images qui seront exclues du garbage collection du kubelet.

--pinns-path="" : Chemin pour trouver le binaire pinns, nécessaire pour gérer le cycle de vie des espaces de noms. Sera recherché dans $PATH si vide.

--privileged-seccomp-profile="" : Active un profil seccomp pour les conteneurs privilégiés à partir du chemin local.

--profile : Active le profileur distant pprof sur 127.0.0.1:6060.

--profile-cpu="" : Écrit un profil CPU pprof dans le chemin fourni.

--profile-mem="" : Écrit un profil mémoire pprof dans le chemin fourni.

--profile-port="" : Port pour le profileur pprof. (défaut : 6060)

--pull-progress-timeout="" : Délai d'attente pour qu'une extraction d'image progresse avant que l'opération d'extraction ne soit annulée. Cette valeur sera également utilisée pour calculer l'intervalle de progression de l'extraction à --pull-progress-timeout / 10. Peut être défini à 0 pour désactiver le délai d'attente ainsi que la sortie de progression. (défaut : 0s)

--rdt-config-file="" : Chemin d'accès au fichier de configuration RDT pour configurer le pseudo-système de fichiers resctrl.

--read-only : Configure tous les conteneurs non privilégiés pour qu'ils s'exécutent en lecture seule. Monte automatiquement le tmpfs des conteneurs sur '/run', '/tmp' et '/var/tmp'.

--root, -r="" : Le répertoire racine de CRI-O. (défaut : "/var/lib/containers/storage")

--runroot="" : Le répertoire d'état de CRI-O. (défaut : "/run/containers/storage")

--runtimes="" : Runtimes OCI, format : 'nom_runtime:chemin_runtime:root_runtime:type_runtime:sans_privilèges_sans_périphériques_hôtes:chemin_config_runtime:mémoire_minimale_conteneur'.

--seccomp-profile="" : Chemin d'accès au profil seccomp.json à utiliser comme valeur par défaut du runtime. S'il n'est pas spécifié, le profil seccomp par défaut interne sera utilisé.

--selinux : Active le support SELinux. Cette option est obsolète et sera interprétée à partir de la présence de SELinux sur l'hôte à l'avenir.

--separate-pull-cgroup="" : [EXPÉRIMENTAL] Tirer dans un nouveau cgroup.

--shared-cpuset="" : Ensemble de CPU qui sera utilisé pour les conteneurs garantis qui souhaitent accéder aux CPU partagés.

--short-name-mode="" : Décrit le mode de résolution des noms courts. Les valeurs autorisées sont 'enforcing' et 'disabled'. (défaut : "enforcing")

--signature-policy="" : Chemin d'accès au fichier JSON de politique de signature.

--signature-policy-dir="" : Chemin d'accès au répertoire racine pour les politiques de signature par espace de noms. Doit être un chemin absolu. (défaut : "/etc/crio/policies")

--stats-collection-period="" : Nombre de secondes entre la collecte des statistiques de pod et de conteneur. Si défini à 0, les statistiques sont collectées à la demande. OBSOLÈTE : Cette option sera supprimée à l'avenir. (défaut : 0)

--storage-driver, -s="" : Driver de stockage OCI.

--storage-opt="" : Option du driver de stockage OCI.

--stream-address="" : Adresse de connexion pour le socket de streaming. (défaut : "127.0.0.1")

--stream-enable-tls : Active le transport TLS chiffré du serveur de streaming.

--stream-idle-timeout="" : Durée avant que les flux ouverts ne se terminent en raison d'un manque d'activité.

--stream-port="" : Port de connexion pour le socket de streaming. Si le port est défini sur '0', CRI-O allouera un numéro de port libre aléatoire. (défaut : "0")

--stream-tls-ca="" : Chemin d'accès au(x) fichier(s) CA x509 utilisé(s) pour vérifier et authentifier la communication client avec le flux chiffré. Ce fichier peut changer et CRI-O le prendra automatiquement en compte.

--stream-tls-cert="" : Chemin d'accès au fichier certificat x509 utilisé pour servir le flux chiffré. Ce fichier peut changer et CRI-O le prendra automatiquement en compte.

--stream-tls-key="" : Chemin d'accès au fichier de clé utilisé pour servir le flux chiffré. Ce fichier peut changer et CRI-O le prendra automatiquement en compte.

--timezone, --tz="" : Pour définir le fuseau horaire d'un conteneur dans CRI-O. Si une chaîne vide est fournie, CRI-O conserve son comportement par défaut. Utilisez 'Local' pour correspondre au fuseau horaire de la machine hôte.

--tracing-endpoint="" : Adresse sur laquelle le collecteur de traces gRPC écoutera. (défaut : "127.0.0.1:4317")

--tracing-sampling-rate-per-million="" : Nombre d'échantillons à collecter par million de spans OpenTelemetry. Défini à 1000000 pour toujours échantillonner. (défaut : 0)

--uid-mappings="" : Spécifie les mappages UID à utiliser pour l'espace de noms utilisateur. Cette option est obsolète et sera remplacée par le support des espaces de noms utilisateur de Kubernetes (KEP-127) à l'avenir.

--version, -v : affiche la version

--version-file="" : Emplacement où CRI-O doit déposer le fichier de version temporaire. Il est utilisé pour vérifier si crio wipe doit effacer les conteneurs, ce qui devrait toujours se produire lors du redémarrage d'un nœud. (défaut : "/run/crio/version")

--version-file-persist="" : Emplacement où CRI-O doit déposer le fichier de version persistant. Il est utilisé pour vérifier si crio wipe doit effacer les images, ce qui ne devrait se produire que lors d'une mise à niveau de CRI-O.

COMMANDES

check

Vérifie le répertoire de stockage CRI-O pour les erreurs.

Cette commande peut également réparer les conteneurs, images et couches endommagés.

Par défaut, l'intégrité des données du répertoire de stockage est vérifiée, ce qui peut être une opération intensive en E/S et en CPU. L'option --quick peut être utilisée pour réduire le nombre de vérifications effectuées.

Lors de l'utilisation de l'option --repair, en particulier avec l'option --force, CRI-O et tout conteneur en cours d'exécution doivent être arrêtés si possible pour garantir qu'aucun accès concurrent au répertoire de stockage ne se produise.

L'option --wipe peut être utilisée pour tenter automatiquement de supprimer les conteneurs et les images en cas d'échec de réparation. Cette option, combinée à l'option --force, peut être utilisée pour supprimer entièrement le contenu du répertoire de stockage en cas d'erreurs irrécupérables. Cela doit être utilisé en dernier recours, et de manière similaire à l'option --repair, il est préférable que CRI-O et tout conteneur en cours d'exécution soient arrêtés.

--age, -a="" : Âge maximum autorisé pour les couches non référencées (défaut : "24h")

--force, -f : Supprime les conteneurs endommagés

--quick, -q : Effectue uniquement des vérifications rapides

--repair, -r : Supprime les images et couches endommagées

--wipe, -w : Efface le répertoire de stockage en cas d'échec de réparation
