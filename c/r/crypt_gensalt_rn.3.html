CRYPT_GENSALT(3) Manuel des fonctions de bibliothèque CRYPT_GENSALT(3)

NOM

crypt_gensalt, crypt_gensalt_rn, crypt_gensalt_ra — encoder les paramètres pour le hachage de phrase de passe

BIBLIOTHÈQUE

Bibliothèque Crypt (libcrypt, -lcrypt)

SYNOPSIS

#include <crypt.h>

char *
crypt_gensalt(const char *prefix, unsigned long count, const char *rbytes, int nrbytes);

char *
crypt_gensalt_rn(const char * prefix, unsigned long count, const char *rbytes, int nrbytes, char * output, int output_size);

char *
crypt_gensalt_ra(const char *prefix, unsigned long count, const char *rbytes, int nrbytes);

DESCRIPTION

Les fonctions crypt_gensalt, crypt_gensalt_rnet crypt_gensalt_ra compilent une chaîne destinée à être utilisée comme argument setting pour crypt, crypt_r, crypt_rnet crypt_ra. prefix sélectionne la méthode de hachage à utiliser. count contrôle le coût de traitement du hachage ; la plage valide et la signification exacte de count dépendent de la méthode de hachage, mais des nombres plus grands correspondent à des hachages plus coûteux en termes de temps CPU et éventuellement d'utilisation de la mémoire. rbytes doit pointer vers nrbytes octets aléatoires au sens cryptographique à utiliser comme « sel ».

Si prefix est un pointeur nul, la meilleure méthode de hachage disponible sera sélectionnée. (ATTENTION: si prefix est une chaîne vide, la méthode de hachage « traditionnelle » basée sur DES sera sélectionnée ; cette méthode est faible de manière inacceptable selon les standards modernes.) Si count est 0, un coût par défaut faible sera sélectionné. Si rbytes est un pointeur nul, un nombre approprié d'octets aléatoires sera obtenu depuis le système d'exploitation, et nrbytes est ignoré.

Voir crypt(5) pour d'autres chaînes pouvant être utilisées comme prefix, et les valeurs valides de count pour chacune.

VALEURS RETOURNÉES

crypt_gensalt, crypt_gensalt_rnet crypt_gensalt_ra retournent un pointeur vers une chaîne de paramètres encodée. Cette chaîne sera entièrement en ASCII imprimable et ne contiendra ni espace ni les caractères «:», «;», «*», «!» ou «\». Voir crypt(5) pour plus de détails sur le format de cette chaîne. En cas d'erreur, elles retournent un pointeur nul et définissent errno avec un code d'erreur approprié. Lorsque les fonctions réussissent, la valeur de errno est indéterminée et ne doit pas être utilisée comme référence.

crypt_gensalt place son résultat dans une zone de stockage statique, qui sera écrasée par les appels suivants à crypt_gensalt. Il n'est pas sûr d'appeler crypt_gensalt depuis plusieurs threads simultanément. Il n'est pas non plus recommandé d'utiliser le pointeur retourné comme argument pour un autre appel à crypt_gensalt, car certaines implémentations, y compris les versions antérieures de libxcrypt, peuvent écraser le tampon de sortie statique sous-jacent avant de calculer les paramètres. Cependant, il est sûr de passer la chaîne retournée par crypt_gensalt directement à crypt sans la copier ; chaque fonction a sa propre zone de stockage statique.

crypt_gensalt_rn place son résultat dans le tampon output fourni, qui dispose de output_size octets de stockage. output_size devrait être supérieur ou égal à CRYPT_GENSALT_OUTPUT_SIZE. Il n'est pas non plus recommandé d'utiliser le pointeur retourné comme argument pour un autre appel à crypt_gensalt_rn en utilisant le même tampon output pour les appels suivants, car certaines implémentations, y compris les versions antérieures de libxcrypt, peuvent écraser le tampon fourni avant de calculer les paramètres.

crypt_gensalt_ra alloue de la mémoire pour son résultat en utilisant malloc(3). Elle doit être libérée avec free(3) après utilisation.

En cas d'erreur, en plus de retourner un pointeur nul, crypt_gensalt et crypt_gensalt_rn écriront une chaîne de paramètres invalide dans leur tampon de sortie, s'il y a assez d'espace ; cette chaîne commencera par un «*» et ne sera pas égale à prefix.

ERREURS

EINVAL
prefix est invalide ou non pris en charge par cette implémentation ; count est invalide pour le prefixdemandé ; l'entrée nrbytes est insuffisante pour le plus petit sel valide avec le prefixdemandé.
ERANGE
crypt_gensalt_rn uniquement : output_size est trop petit pour contenir la chaîne setting compilée.
ENOMEM
Échec de l'allocation de la mémoire de travail interne.
crypt_gensalt_ra uniquement : échec de l'allocation de mémoire pour la chaîne setting compilée.
ENOSYS, EACCES, EIO, etc.
L'obtention d'octets aléatoires depuis le système d'exploitation a échoué. Cela ne peut se produire que lorsque rbytes est un pointeur nul.

MACROS DE TEST DE FONCTIONNALITÉ

Les macros suivantes sont définies par <crypt.h>:

CRYPT_GENSALT_IMPLEMENTS_DEFAULT_PREFIX
Un pointeur nul peut être spécifié comme argument prefix .
CRYPT_GENSALT_IMPLEMENTS_AUTO_ENTROPY
Un pointeur nul peut être spécifié comme argument rbytes .

NOTES DE PORTABILITÉ

Les fonctions crypt_gensalt, crypt_gensalt_rnet crypt_gensalt_ra ne font partie d'aucune standard. Elles proviennent du projet Openwall. Une fonction nommée crypt_gensalt existe aussi sur Solaris 10 et versions ultérieures, mais son prototype et sa sémantique diffèrent.

Les fonctionnalités de préfixe par défaut et d'entropie automatique sont disponibles depuis la version 4.0.0 de libxcrypt. Un logiciel portable peut utiliser les macros de test de fonctionnalité pour savoir si des pointeurs nuls peuvent être utilisés pour les crypt_gensalt_rn(3) — libxcrypt — The Arch Linux man-pages project

NOM

crypt_gensalt_rn, crypt_gensalt_ra, crypt_gensalt - générer un sel pour crypt'(3)

BIBLIOTHÈQUE

Bibliothèque de cryptographie (libcrypt, -lcrypt)

SYNTAXE

#include <crypt.h> 

char *crypt_gensalt_rn(const char *salt_prefix, size_t salt_len,
    const char *rbytes, size_t rbytes_len);
char *crypt_gensalt_ra(const char *salt_prefix, size_t salt_len,
    const char *rbytes, size_t rbytes_len);
char *crypt_gensalt(const char *salt_prefix, size_t salt_len);

DESCRIPTION

La fonction crypt_gensalt_rn génère un motif de sel aléatoire pour une méthode de hachage donnée.

Le paramètre salt_prefix est un pointeur vers une chaîne qui spécifie le début du motif de sel. Le paramètre salt_len spécifie la longueur de salt_prefix.

Si salt_prefix est NULL, un préfixe par défaut sera utilisé. Si salt_len est 0, la longueur du préfixe sera déterminée par la fonction.

Les paramètres rbytes et rbytes_len sont facultatifs. Si ils sont fournis, les octets aléatoires seront utilisés pour générer le sel. Sinon, des octets aléatoires seront générés par la fonction.

La fonction crypt_gensalt_ra est identique à crypt_gensalt_rn, mais utilise un générateur de nombres aléatoires différent.

La fonction crypt_gensalt est une ancienne interface qui utilise un préfixe de sel par défaut et génère des octets aléatoires.

La chaîne de sel générée est destinée à être utilisée comme argument de sel pour la fonction crypt(3).

L'ensemble des méthodes de hachage prises en charge varie considérablement d'un système à l'autre.
