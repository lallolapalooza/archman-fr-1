SYNOPSI

cryptsetup luksResume [<options>] <name>

DESCRIPTIO

N

Reprend un périphérique suspendu et rétablit la clé de chiffrement. Invite à saisir une phrase secrète de manière interactive si aucun jeton n'est utilisable (LUKS2 uniquement) ou si --key-file n'est pas

fourni.

<options> peut être [--key-file, --keyfile-size, --keyfile-offset, --key-slot, --header, --disable-keyring, --disable-locks, --token-id, --token-only, --t

oken-type, --disable-external-tokens, --type, --tries, --timeout, --verify-pas
sphrase, --volume-key-keyring, --link-vk-to-keyring, --external-tokens-path].

--key-slot, -S <0-N

>
Pour les opérations LUKS qui ajoutent du matériel de clé, cette option permet de spécifier quel emplacement de clé est sélectionné pour la nouvelle clé.

Le nombre maximal d'emplacements de clés dépend de la version LUKS. LUKS1 peut avoir jusqu'à 8 emplacements de clés.

LUKS2 peut avoir jusqu'à 32 emplacements de clés en fonction de la taille de la zone d'emplacement de clé et de la t
aille de la clé, mais un identifiant d'emplacement de clé valide peut toujours être compris entre 0 et 31 pour LUKS2.

--link-vk-to-keyring <keyring description>::<key

description>
Lie la clé de volume dans un trousseau de clés avec le nom de clé spécifié. La clé de volume n'est liée que si l'action demandée est terminée avec succès (avec --test-passphrase, la clé de volume vérifiée est liée dans un trousseau sans effectuer d'action supplémentaire).

La chaîne <keyring description> doit contenir la description du trousseau de clés du noyau existant. Le nom du trousseau peut éventuellement être préfixé par des descriptions de type « %: » ou « %keyring: ». Ou, le trousseau peut également être spécifié directement par identifiant numérique de clé. De plus, des notations de trousseau de clés commençant par « @ » peuvent être utilisées pour sélectionner des trousseaux de clés prédéfinis du

noyau.

La chaîne « :: » est un délimiteur utilisé pour séparer la description du trousseau et la description de la

clé.

La partie <key description> décrit le type de clé et le nom de la clé de volume liée dans le trousseau décrit dans <keyring description>. Le type peut être spécifié en ajoutant un préfixe « %<type_name>: » devant le nom de la clé. Si le type est absent, le type par défaut user est appliqué. Si la clé du même nom et du même type existe déjà (déjà liée dans le trousseau), elle sera remplacée dans le

processus.

Voir également la section KEY IDENTIFIERS de keyct

l(1
).

--timeout, -t second

s
Le nombre de secondes à attendre avant un délai d'attente sur la saisie de la phrase secrète via le terminal. C'est pertinent chaque fois qu'une phrase secrète est demandée. Cela n'a aucun effet si utilisé en conjonction avec --key-file.

Cette option est utile lorsque le système ne doit pas se bloquer si l'utili

sateur ne saisit pas de phrase secrète, par ex., lors du démarrage. La v
aleur par défaut est 0 secondes, ce qui signifie attendre indéfiniment.

secrète.

y

--volume-key-keyring <key

description>
Utilise une clé de volume stockée dans un trousseau de clés. Cela permet d' ouvrir les types de périphériques luks et plain sans fournir de phrase secrète.

Pour LUKS, la clé et le type associé doivent être lisibles depuis l'espace utilisateur afin que l'empreinte de la clé de volume puisse être vérifiée avant l'activation. Pour les périphériques en réchiffrement, l'option peut être utilisée deux fois pour spécifier à la fois l'ancienne et la nouvelle clé de

volume.

Pour le type PLAIN, l'utilisateur doit s'assurer que la clé dans le trousseau de clés n'a pas changé depuis l'activation. Sinon, le rechargement de la clé peut provoquer une corruption de données après un changement de clé

inattendu.

La <key description> utilise une syntaxe compatible avec keyctl. Il peut s'agir d'un identifiant numérique de clé ou d'un nom de chaîne au format %<key type>:<key name>. Voir également la section KEY IDENTIFIERS de /man/keyctl.1.en'>keyctl(1). Lorsque %<type de clé>: n'est pas spécifié, nous supposons que le type de clé est user (t

ype p
