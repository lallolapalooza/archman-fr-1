CRYPTSETUP-RESIZE(8) Commandes de maintenance CRYPTSETUP-RESIZE(8)

NOM

cryptsetup-resize - redimensionner un mappage actif

SYNTAXE

cryptsetup resize [<options>] <nom>

DESCRIPTION

Redimensionne un mappage actif <nom>.

Si --size (en secteurs de 512 octets) ou --device-size n'est pas spécifié, la taille est calculée à partir du périphérique sous-jacent. Pour LUKS, il s'agit de la taille du périphérique sous-jacent sans la zone réservée à l'en-tête LUKS (voir le décalage de la charge utile de données dans la commande luksDump). Pour un périphérique de chiffrement brut (plain), la taille totale du périphérique est utilisée.

Notez que cela ne modifie pas la géométrie brute du périphérique ; cela change simplement le nombre de secteurs du périphérique brut représentés dans le périphérique mappé.

Si cryptsetup a détecté une clé de volume pour le périphérique actif chargée dans le service de keyring du noyau, l'action de redimensionnement tentera d'abord de récupérer la clé à l'aide d'un jeton. Ce n'est qu'en cas d'échec qu'il demandera un mot de passe pour déverrouiller un slot de clé (LUKS) ou pour dériver à nouveau une clé de volume (mode brut). Le keyring du noyau est utilisé par défaut pour les périphériques LUKS2.

<options> peut être [--size, --device-size, --token-id, --token-only, --token-type, --key-slot, --key-file, --keyfile-size, --keyfile-offset, --timeout, --disable-external-tokens, --disable-locks, --disable-keyring, --volume-key-keyring, --verify-passphrase, --timeout, --external-tokens-path].

OPTIONS

--batch-mode, -q

Supprime toutes les questions de confirmation. À utiliser avec précaution !

Si l'option --verify-passphrase n'est pas spécifiée, cette option désactive également la vérification du mot de passe.

--debug ou --debug-json

Exécute en mode débogage avec des journaux de diagnostic complets. Les lignes de sortie de débogage sont toujours précédées de #.

Si --debug-json est utilisé, des structures de données JSON LUKS2 supplémentaires sont imprimées.

--device-size taille[unités]

Définit la nouvelle taille du périphérique. Si non définie, la taille réelle du périphérique est utilisée.

Si aucun suffixe d'unité n'est spécifié, la taille est en octets.

Le suffixe d'unité peut être S pour des secteurs de 512 octets, K/M/G/T (ou KiB, MiB, GiB, TiB) pour des unités de base 1024 ou KB/MB/GB/TB pour une base de 1000 (échelle SI).

--disable-external-tokens

Désactive le chargement des plugins pour les jetons LUKS2 externes.

--disable-keyring

Ne charge pas la clé de volume dans le keyring du noyau ; stocke-la directement dans la cible dm-crypt à la place. Cette option n'est supportée que pour le type LUKS2.

--disable-locks

Désactive la protection par verrouillage des métadonnées sur disque. Cette option n'est valide que pour LUKS2 et est ignorée pour les autres formats.

AVERTISSEMENT : N'utilisez pas cette option sauf si vous exécutez cryptsetup dans un environnement restreint où le verrouillage est impossible (où le répertoire /run ne peut pas être utilisé).

--external-tokens-path <chemin absolu>

Remplace le chemin du répertoire système où cryptsetup recherche les gestionnaires de jetons externes (ou plugins de jetons). Il doit s'agir d'un chemin absolu (commençant par le caractère '/').

--header <périphérique ou fichier stockant l'en-tête LUKS>

Utilise un périphérique ou un fichier de métadonnées détaché (séparé) où l'en-tête LUKS est stocké. Cette option permet de stocker le chiffrement et l'en-tête LUKS sur des périphériques différents.

Pour les commandes qui modifient l'en-tête LUKS (par exemple, luksAddKey), spécifiez directement le périphérique ou le fichier avec l'en-tête LUKS comme périphérique LUKS.

--help, -?

Affiche le texte d'aide et les paramètres par défaut.

--key-description texte

Définit la description de la clé dans le keyring qui sera utilisée pour la récupération du mot de passe.

--key-file, -d fichier

Lit le mot de passe depuis le fichier.

Si le nom donné est "-", alors le mot de passe sera lu depuis stdin. Dans ce cas, la lecture ne s'arrêtera pas aux caractères de nouvelle ligne.

Consultez la section NOTES SUR LE TRAITEMENT DES MOTS DE PASSE de cryptsetup(8) pour plus d'informations.

--keyfile-offset valeur

Ignore valeur octets au début du fichier clé.

--keyfile-size, -l valeur

Lit un maximum de valeur octets à partir du fichier clé. La valeur par défaut est de lire le fichier entier jusqu'au maximum compilé qui peut être interrogé avec --help. Fournir plus de données que le maximum compilé interrompt l'opération.

Cette option est utile pour supprimer les nouvelles lignes de fin, par exemple. Si --keyfile-offset est également donné, le comptage de la taille commence après le décalage.

--key-slot, -S <0-N>

Pour les opérations LUKS qui ajoutent du matériel de clé, cette option vous permet de spécifier quel slot de clé est sélectionné pour la nouvelle clé.

Le nombre maximum de slots de clé dépend de la version LUKS. LUKS1 peut avoir jusqu'à 8 slots de clé. LUKS2 peut avoir jusqu'à 32 slots de clé en fonction de la taille de la zone de slot et de la taille de la clé, mais un ID de slot de clé valide peut toujours être compris entre 0 et 31 pour LUKS2.

--size, -b <nombre de secteurs de 512 octets>

Définit la taille du périphérique en secteurs de 512 octets.

--timeout, -t secondes

Le nombre de secondes à attendre avant un délai d'expiration pour la saisie du mot de passe via le terminal. Il est pertinent chaque fois qu'un mot de passe est demandé. Il n'a aucun effet lorsqu'il est utilisé avec --key-file.

Cette option est utile lorsque le système ne doit pas se bloquer si l'utilisateur ne saisit pas de mot de passe, par exemple, pendant le démarrage. La valeur par défaut est de 0 seconde, ce qui signifie attendre indéfiniment.

--token-id

Spécifie quel jeton utiliser et permet à la demande de PIN du jeton de prendre la priorité sur la demande interactive de mot de passe du slot de clé. Si omis, tous les jetons disponibles (non protégés par PIN) seront vérifiés avant de poursuivre avec la demande de mot de passe.

--token-only

Ne pas poursuivre l'action si le déverrouillage du slot de clé basé sur un jeton a échoué. Sans l'option, l'action demande un mot de passe pour continuer.

Elle permet aux jetons LUKS2 protégés par PIN de prendre la priorité sur la demande interactive de mot de passe du slot de clé.

--token-type type

Restreint les jetons éligibles pour l'opération à un type de jeton spécifique. Utile surtout lorsqu'aucun --token-id n'est spécifié.

Elle permet aux jetons LUKS2 de type spécifique protégés par PIN de prendre la priorité sur la demande interactive de mot de passe du slot de clé.

--usage

Affiche une aide succincte sur les options.

--verify-passphrase, -y

Lors de la demande interactive d'un mot de passe, demande-le deux fois et signale une erreur si les deux saisies ne correspondent pas. Ignoré lors de la lecture à partir d'un fichier ou de stdin.

--version, -V

Affiche la version du programme.

--volume-key-keyring <description de clé>

Utilise une clé de volume stockée dans un keyring. Cela permet d'ouvrir les types de périphériques luks et plain sans fournir de mot de passe.

Pour LUKS, la clé et le type associé doivent être lisibles depuis l'espace utilisateur afin que le résumé de la clé de volume puisse être vérifié avant l'activation. Pour les périphériques en cours de ré-chiffrement, l'option peut être utilisée deux fois pour spécifier les anciennes et les nouvelles clés de volume.

Pour le type PLAIN, l'utilisateur doit s'assurer que la clé dans le keyring n'a pas été modifiée depuis l'activation. Sinon, le rechargement de la clé peut entraîner une corruption des données après un changement de clé inattendu.

La <description de clé> utilise la syntaxe compatible keyctl. Il peut s'agir d'un ID de clé numérique ou d'un nom de chaîne au format %<type de clé>:<nom de clé>. Voir également la section IDENTIFIERS DE CLÉ de keyctl(1). Lorsqu'aucun préfixe %<type de clé>: n'est spécifié, nous supposons que le type de clé est user (type par défaut).
