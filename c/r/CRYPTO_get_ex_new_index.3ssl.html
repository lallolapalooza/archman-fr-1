Les types d'exdata sont identifiés par un index , un entier garanti unique au sein des structures pour la durée de vie du programme. Les applications utilisant les exdata appellent généralement CRYPTO_get_ex_new_index au démarrage, et stockent le résultat dans une variable globale, ou écrivent une fonction enveloppe pour fournir une évaluation paresseuse. La sémantique de ces rappels est décrite ci-dessous. Lors de la copie ou de la libération d'objets avec des exdata, les fonctions de rappel sont appelées dans l'ordre croissant de leur index . Si une bibliothèque dynamique peut être déchargée, elle doit appeler CRYPTO_free_ex_inde

x()

lorsque cela est terminé. Cela remplacera les rappels par des opérations nulles afin que les applications ne se crashent pas. Toute exdata existante sera fuitée. Pour définir ou récupérer les exdata sur un objet, la routine appropriée spécifique au type doit être utilisée. C'est parce que la structure conteneur est opaque et le champ CRYPTO_EX_DATA n'est pas accessible. Dans les deux API, le paramètre idx doit être une valeur d'index déjà créée. Lors de la définition des exdata, le pointeur spécifié avec un index particulier est enregistré, et renvoyé lors d'un appel « get » ultérieur. Si l'application va libérer les données, elle doit s'assurer de définir une valeur NULL à l'index, pour éviter des plantages probables dus à une double libération. La fonction CRYPTO_free_ex_dat

Cette section décrit comment les fonctions de rappel sont utilisées. Les applications qui définissent leurs propres exdata en utilisant CYPRTO_EX_INDEX_APP doivent les appeler comme décrit

ici.

Lorsqu'une structure est initialement allouée (comme avec RSA_new() ) alors

new_func()

est appelé pour chaque index défini. Il n'y a pas d'exigence que la structure parente, ou conteneur, entière ait été mise en place. La fonction new_func() n'est généralement utilisée que pour allouer de la mémoire afin de stocker les exdata, et peut-être un drapeau « initialisé » dans cette mémoire. La valeur exdata peut être allouée plus tard avec CRYPTO_alloc_ex_data() , ou peut être définie en

appelant

CRYPTO_set_ex_data(

)

. Lorsqu'une structure est libérée (comme avec SSL_CTX_free() ) alors la fonction

free_func()

est appelée pour chaque index défini. Encore une fois, l'état de la structure parente n'est pas garanti. La fonction free_func() peut être appelée avec un pointeur NULL. Les fonctions new_func() et free_func() prennent les mêmes paramètres. Le parent est le pointeur vers la structure qui contient les exdata. Le ptr est l'élément exdata

actuel ; pour

new_func() cela sera généralement NULL. Le paramètre r est un pointeur vers le champ exdata de l'objet. Le idx est l'index et est la valeur renvoyée lorsque les rappels ont été initialement enregistrés via CRYPTO_get_ex_new_index(

)

et peut être utilisé si le même rappel gère différents types d'exdata. La fonction dup_func() est appelée lorsqu'une structure est copiée. Cela n'est fait que pour les objets SSL , SSL_SESSION , EC_KEY et les chaînes BIO via BIO_dup_chain() . Les paramètres to et from sont respectivement des pointeurs vers les structures CRYPTO_EX_DATA de destination et de source. Le

paramètre

*from_d est un pointeur vers les exdata source. Lorsque dup_func() se termine, la valeur dans *from_d est copiée dans les ex_data de destination. Si le pointeur contenu dans *pptr n'est pas modifié par dup_func() , alors à la fois to et from pointeront vers les mêmes données. Les paramètres idx , argl et argp sont comme décrit pour les deux autres rappels. Si dup_func() renvoie 0 toute la fonction CRYPTO_dup_ex_data() échouera.
