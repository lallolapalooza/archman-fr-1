CREATE MATERIALIZED VIEW(7) Documentation PostgreSQL 18.1 CREATE MATERIALIZED VIEW(7)

NOM

CREATE_MATERIALIZED_VIEW - définir une nouvelle vue matérialisée

SYNTAXE

CREATE MATERIALIZED VIEW [ IF NOT EXISTS ] nom_table
    [ (nom_colonne [, ...] ) ]
    [ USING méthode ]
    [ WITH ( paramètre_stockage [= valeur] [, ... ] ) ]
    [ TABLESPACE nom_tablespace ]
    AS requête
    [ WITH [ NO ] DATA ]

DESCRIPTION

CREATE MATERIALIZED VIEW définit une vue matérialisée d'une requête. La requête est exécutée et utilisée pour peupler la vue au moment où la commande est émise (sauf si WITH NO DATA est utilisé) et peut être actualisée ultérieureement en utilisant REFRESH MATERIALIZED VIEW.

CREATE MATERIALIZED VIEW est similaire à CREATE TABLE AS, à la différence qu'elle mémorise également la requête utilisée pour initialiser la vue, de sorte qu'elle puisse être actualisée ultérieurement sur demande. Une vue matérialisée possède de nombreuses propriétés similaires à celles d'une table, mais il n'y a pas de support pour les vues matérialisées temporaires.

CREATE MATERIALIZED VIEW nécessite le privilège CREATE sur le schéma utilisé pour la vue matérialisée.

PARAMÈTRES

IF NOT EXISTS

Ne génère pas d'erreur si une vue matérialisée portant le même nom existe déjà. Une notification est émise dans ce cas. Il n'y a aucune garantie que la vue matérialisée existante ressemble à celle qui aurait été créée.

nom_table

Le nom (éventuellement qualifié par un schéma) de la vue matérialisée à créer. Le nom doit être distinct de celui de toute autre relation (table, séquence, index, vue, vue matérialisée ou table étrangère) dans le même schéma.

nom_colonne

Le nom d'une colonne dans la nouvelle vue matérialisée. Si les noms de colonnes ne sont pas fournis, ils sont tirés des noms de colonnes de sortie de la requête.

USING méthode

Cette clause optionnelle spécifie la méthode d'accès aux tables à utiliser pour stocker le contenu de la nouvelle vue matérialisée ; la méthode doit être une méthode d'accès de type TABLE. Voir le Chapitre 62 pour plus d'informations. Si cette option n'est pas spécifiée, la méthode d'accès aux tables par défaut est choisie pour la nouvelle vue matérialisée. Voir default_table_access_method pour plus d'informations.

WITH ( paramètre_stockage [= valeur] [, ... ] )

Cette clause spécifie les paramètres de stockage optionnels pour la nouvelle vue matérialisée ; voir Paramètres de stockage dans CREATE TABLE (CREATE_TABLE(7)) pour plus d'informations. Tous les paramètres pris en charge pour CREATE TABLE sont également pris en charge pour CREATE MATERIALIZED VIEW. Voir CREATE TABLE (CREATE_TABLE(7)) pour plus d'informations.

TABLESPACE nom_tablespace

Le nom_tablespace est le nom du tablespace dans lequel la nouvelle vue matérialisée doit être créée. Si non spécifié, default_tablespace est consulté.

requête

Une commande SELECT, TABLE ou VALUES. Cette requête sera exécutée dans le cadre d'une opération restreinte en termes de sécurité ; en particulier, les appels à des fonctions qui créent elles-mêmes des tables temporaires échoueront. De plus, pendant l'exécution de la requête, le search_path est temporairement modifié en pg_catalog, pg_temp.

WITH [ NO ] DATA

Cette clause spécifie si la vue matérialisée doit être peuplée ou non lors de sa création. Si ce n'est pas le cas, la vue matérialisée sera marquée comme non scannable et ne pourra pas être interrogée tant que REFRESH MATERIALIZED VIEW n'aura pas été utilisé.

COMPATIBILITÉ

CREATE MATERIALIZED VIEW est une extension PostgreSQL.
