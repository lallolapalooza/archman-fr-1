CDRECORD(1) COMMANDES UTILISATEUR de Schily CDRECORD(1)

NOM

cdrecord - enregistrer des CD, DVD ou BluRay audio ou de données

SYNTAXE

cdrecord [ options générales ][ dev=périphérique ][ options de piste ] piste1...pisten

DESCRIPTION

Cdrecord est utilisé pour enregistrer des CD de données ou audio sur un graveur de CD Orange Book, pour écrire des médias DVD sur un graveur de DVD ou pour écrire des médias BluRay sur un graveur BluRay.

Nommage du périphérique

La plupart des utilisateurs n'ont pas besoin de se soucier du nommage des périphériques. Si aucune option dev= n'est spécifiée, cdrecord implémente le support cible automatique et trouve automatiquement le lecteur s'il n'y a qu'un seul lecteur de type CD-ROM disponible dans le système. S'il existe plusieurs lecteurs de type CD-ROM dans le système, une liste des noms de périphériques possibles peut être obtenue avec cdrecord -scanbus ou à partir de l'exemple de cible dans la sortie de cdrecord dev=help, puis le paramètre dev= peut être défini en fonction de la liste des périphériques.

Le paramètre périphérique de l'option dev= expliquée ci-dessous fait référence à la notation standard SCSI CAM pour busscsi/cible/lun du graveur CD/DVD/BluRay. Si un fichier /etc/default/cdrecord existe, le paramètre de l'option dev= peut également être une étiquette de nom de lecteur dans ledit fichier (voir la section FICHIERS).

Contraintes pour lancer cdrecord

Sur les systèmes conformes SVr4, cdrecord utilise la classe temps réel pour obtenir la priorité de planification la plus élevée possible (supérieure à tous les processus du noyau). Sur les systèmes avec planification temps réel POSIX, cdrecord utilise également la planification temps réel, mais peut ne pas être en mesure d'obtenir une priorité supérieure à tous les processus du noyau.

Pour pouvoir utiliser le sous-système de transport SCSI du système d'exploitation, s'exécuter à priorité maximale et se verrouiller dans le noyau, cdrecord doit soit être exécuté en tant que root, soit être installé en tant que suid root, soit être appelé via un mécanisme de privilèges finement granulé, tel que le mécanisme de privilèges(5) de Solaris via exec_attr(4) ou le mécanisme de capacités(7) de Linux via setcap(8) pour permettre à cdrecord d'être utilisé par un utilisateur ordinaire.

Mappage fichier-piste

En mode Track At Once, chaque piste correspond à un seul fichier contenant les données préparées pour cette piste. Si l'argument est `-', l'entrée standard est utilisée pour cette piste. Une seule piste peut être extraite de stdin. Dans les autres modes d'écriture, la relation directe fichier-piste peut ne pas être implémentée. En mode -clone, un seul fichier contient toutes les données pour l'ensemble du disque. Pour permettre l'écriture de DVD sur des plateformes qui n'implémentent pas le support de fichiers volumineux, cdrecord concatène tous les arguments de fichier en une seule piste lors de l'écriture sur des médias DVD.

OPTIONS GÉNÉRALES

Les options générales doivent précéder tout nom de fichier de piste ou option de piste.

Options informatives

-aide
affiche les informations de version de cdrecord sur la sortie standard.
-version
Affiche les informations de version et quitte.
-v
Incrémente le niveau de verbosité générale de un. Ceci est utilisé par exemple pour afficher la progression du processus d'écriture.

Options de mode d'écriture médias

-factice
L'option -factice modifie la stratégie d'écriture actuelle. Le graveur CD/DVD/BluRay effectuera toutes les étapes du processus d'enregistrement, mais le laser sera éteint pendant cette procédure. Il est recommandé d'effectuer plusieurs tests avant d'écrire réellement sur un disque compact ou un disque polyvalent numérique, si le timing et la réponse de charge du système actuel ne sont pas encore connus.

L'option -factice ne fonctionne pas avec tous les médias et modes d'écriture. Les médias DVD+ et BluRay ne supportent pas les écritures factices et la plupart des graveurs CD ne supportent pas les écritures factices en mode brut.

-multi
Permet la création de CD multi-sessions ou de DVD multi-bords. Ce drapeau doit être présent sur toutes les sessions d'un disque multi-session ou multi-bords, sauf si vous souhaitez créer une session sur un CD qui sera la dernière session sur le support CD.

Pour les médias CD, la fixation sera effectuée de manière à permettre au graveur CD/DVD/BluRay d'ajouter des sessions ultérieurement. Ceci est réalisé en générant une TOC avec un lien vers la zone de programme suivante. Les médias ainsi générés ne sont pas 100% compatibles avec les CD manufacturés (sauf pour CDplus). Utilisez uniquement pour l'enregistrement de CD multi-sessions. Si cette option est présente, le type de piste par défaut est CD-ROM XA mode 2 form 1 et la taille de secteur est de 2048 octets. Les sous-en-têtes de secteur XA seront créés par le lecteur. Les lecteurs Sony n'ont pas de support matériel pour CD-ROM XA mode 2 form 1. Vous devez spécifier l'option -data pour créer des disques multi-sessions sur ces lecteurs. Si vous souhaitez enregistrer un disque multi-sessions en mode SAO, vous devez forcer les secteurs CD-ROM en incluant l'option -data. Tous les lecteurs ne permettent pas les CD multi-sessions en mode SAO.

Pour les médias DVD, -multi passe le mode d'écriture en enregistrement par paquets incrémentiel. Il n'y a actuellement aucun moyen d'empêcher la possibilité d'ajouter des sessions supplémentaires et il n'y a actuellement qu'un support pour les médias DVD-R/DVD-RW. Pour réutiliser un DVD-RW qui a précédemment été écrit en mode enregistrement par paquets incrémentiel pour d'autres modes d'écriture, vous devez effacer tout le média au préalable.

-dao
-sao
Définit le mode d'écriture SAO (Session At Once), généralement appelé mode Disk At Once. Cela ne fonctionne actuellement qu'avec les lecteurs MMC qui prennent en charge le mode Session At Once. Notez que cdrecord doit connaître la taille de chaque piste à l'avance pour ce mode (voir l'option mkisofs -print-size et la section EXEMPLES pour plus d'informations).

Il existe plusieurs graveurs de CD avec un firmware défectueux qui entraînent des disques corrompus lors de l'écriture en mode TAO ou SAO. Si vous rencontrez des problèmes avec la mise en page d'un disque ou avec le contenu des sous-canaux (par exemple, des temps incorrects affichés lors de la lecture du CD) et que votre graveur prend en charge l'écriture en mode -raw96r ou -raw16, vous devriez essayer.

-tao
Définit le mode d'écriture TAO (Track At Once). C'est le mode d'écriture par défaut dans les versions précédentes de cdrecord. Avec la plupart des lecteurs, ce mode d'écriture est requis pour l'enregistrement multi-session.

Il existe plusieurs graveurs de CD avec un firmware défectueux qui entraînent des disques corrompus lors de l'écriture en mode TAO ou SAO. Si vous rencontrez des problèmes avec la mise en page d'un disque ou avec le contenu des sous-canaux (par exemple, des temps incorrects affichés lors de la lecture du CD) et que votre graveur prend en charge l'écriture en mode -raw96r ou -raw16, vous devriez essayer.

-raw
Définit le mode d'écriture BRUT (RAW). L'utilisation de cette option est par défaut -raw96r. Notez que cdrecord doit connaître la taille de chaque piste à l'avance pour ce mode (voir l'option mkisofs -print-size et la section EXEMPLES pour plus d'informations).
-raw96r
Définit le mode d'écriture BRUT (RAW) avec des secteurs de 2352 octets plus 96 octets de données brutes du sous-canal P-W, résultant en une taille de secteur de 2448 octets. C'est le mode d'écriture brut préféré car il offre le meilleur contrôle sur le processus d'écriture du CD. L'écriture de disques de données en mode brut nécessite beaucoup plus de temps CPU que les autres modes d'écriture. Si votre CPU est trop lent, cela peut entraîner des sous-débits. Notez que cdrecord doit connaître la taille de chaque piste
en avance pour ce mode (voir l'option mkisofs -print-size et la section EXEMPLES pour plus d'informations).
-raw96p
Définir le mode d'écriture RAW avec des secteurs de 2352 octets plus 96 octets de données de sous-canal P-W packées, résultant en une taille de secteur de 2448 octets. C'est le mode d'écriture brute moins préféré car seuls quelques graveurs le prennent en charge et certains de ces graveurs ont des bugs dans l'implémentation du firmware. N'utilisez pas ce mode si votre graveur prend en charge -raw96r ou -raw16. L'écriture de disques de données en mode brut nécessite beaucoup plus de temps CPU que les autres modes d'écriture. Si votre CPU est trop lent, cela peut entraîner des sous-débits de tampon. Notez que cdrecord doit connaître la taille de chaque piste à l'avance pour ce mode (voir l'option mkisofs -print-size et la section EXEMPLES pour plus d'informations).
-raw16
Définir le mode d'écriture RAW avec des secteurs de 2352 octets plus 16 octets de données de sous-canal P-Q, résultant en une taille de secteur de 2368 octets. Si un graveur ne prend pas en charge -raw96r, c'est le mode d'écriture brute préféré. Il ne permet pas d'écrire de CD-Text ou de CD+Graphics mais c'est le seul mode d'écriture brute dans les graveurs de CD bon marché, car ces graveurs bon marché dans la plupart des cas ne prennent pas en charge le mode -dao. N'utilisez pas ce mode si votre graveur prend en charge -raw96r. L'écriture de disques de données en mode brut nécessite beaucoup plus de temps CPU que les autres modes d'écriture. Si votre CPU est trop lent, cela peut entraîner des sous-débits de tampon. Notez que cdrecord doit connaître la taille de chaque piste à l'avance pour ce mode (voir l'option mkisofs -print-size et la section EXEMPLES pour plus d'informations).

Options fonctionnelles de Cdrecord

-abort
Essaye d'envoyer une séquence d'abandon au lecteur. Si vous utilisez uniquement cdrecord, cela ne devrait jamais être nécessaire ; mais un autre logiciel peut laisser un lecteur dans un état inutilisable. Appeler cdrecord -reset peut être nécessaire si une écriture précédente a été interrompue et que le logiciel n'a pas indiqué au lecteur qu'il n'allait pas continuer à écrire.
-atip
Récupère et affiche les informations ATIP (Absolute Time In Pre-groove) des médias enregistrables CD/DVD/BluRay ou réinscriptibles CD/DVD/BluRay. Avec cette option, cdrecord essaiera de récupérer les informations ATIP. Si le lecteur actuel ne prend pas en charge la lecture des informations ATIP, il se peut que seul un ensemble réduit d'informations soit enregistré ou même rien ne soit affiché. Seul un nombre limité de lecteurs compatibles MMC prend en charge la lecture des informations ATIP.

Si cdrecord est capable de récupérer le temps de début du lead-in pour la première session, il essaiera de décoder et d'afficher les informations du fabricant à partir du média. Les médias DVD n'ont pas d'informations ATIP mais il existe des informations pré-enregistrées équivalentes qui sont lues et affichées.

blank=type
Efface un CD-RW et quitte ou efface un CD-RW avant l'écriture. Le type d'effacement peut être l'un des suivants :
help
Affiche une liste des types d'effacement possibles.
all
Efface le disque entier. Cela peut prendre beaucoup de temps.
fast
Efface minimalement le disque. Cela efface le PMA, le TOC et le pregap.
track
Efface la dernière piste.
unreserve
Annule la réservation d'une piste réservée.
trtail
Efface la fin d'une piste.
unclose
Ne ferme pas la dernière session.
session
Efface la dernière session.

Tous les lecteurs ne prennent pas en charge tous les types d'effacement. Il peut être nécessaire d'utiliser blank=all si un lecteur signale une commande spécifiée comme invalide. S'il est utilisé avec le drapeau -force, cette option peut être utilisée pour effacer les disques CD-RW qui ne peuvent pas être effacés autrement. Notez qu'il vous faudra peut-être spécifier blank=all car certains lecteurs ne continueront pas avec certains types de CD-RW défectueux. Notez également que cdrecord fait de son mieux si le drapeau -force est utilisé, mais cela dépend finalement du firmware du lecteur pour que l'opération d'effacement réussisse ou non.

-checkdrive
Vérifie si un pilote pour le lecteur actuel est présent et quitte. Si le lecteur est un lecteur connu, cdrecord utilise le code de sortie 0.
-clone
Indique à cdrecord de gérer les images créées par readcd -clone. Le mode d'écriture -clone ne peut être utilisé qu'en conjonction avec l'option -raw96r ou -raw16. L'utilisation de -clone avec -raw96r est préférée car elle permet d'écrire toutes les données de sous-canal. L'option -raw16 ne doit être utilisée qu'avec des lecteurs qui ne prennent pas en charge l'écriture en mode -raw96r.

Notez que la copie en mode clone désactive certains niveaux de correction d'erreurs et entraîne donc toujours une dégradation de la qualité. Évitez de copier des CD audio en mode clone pour cette raison.

cuefile=nom_fichier
Prend toutes les informations relatives à l'enregistrement à partir d'un fichier CUE sheet conforme à CDRWIN. Aucun argument de piste-fichier pour cdrecord n'est autorisé lorsque cette option est présente et l'une des options suivantes : -dao, -sao, -raw, -raw16, -raw96r est nécessaire en plus.
defpregap=#
Définit la taille par défaut du pré-gap pour toutes les pistes sauf la piste numéro 1. Cette option n'est actuellement pertinente qu'avec les lecteurs suivants :

Teac CD-R50S, Teac CD-R55S, JVC XR-W2010, Pinnacle RCD-5020

lors de la création de disques piste-à-la-volée sans le silence de 2 secondes avant chaque piste.
Cette option pourrait disparaître à l'avenir.

driver=nom
Permet à l'utilisateur de sélectionner manuellement un pilote pour le périphérique. La raison de l'existence de l'option driver=nom est de permettre aux utilisateurs d'utiliser cdrecord avec des lecteurs qui sont similaires à des lecteurs pris en charge mais qui ne sont pas directement connus par cdrecord. Tous les lecteurs fabriqués après 1997 devraient être conformes à la norme MMC et donc pris en charge par l'un des pilotes MMC. Il est très peu probable que cdrecord ne parvienne pas à trouver le bon pilote automatiquement. Utilisez cette option avec la plus grande prudence. Si un pilote incorrect est utilisé pour un périphérique, la possibilité de créer des disques corrompus est élevée. Le problème minimum lié à un mauvais pilote est que -speed ou -dummy ne fonctionneront pas.

L'indicateur de périphérique distant est soit REMOTE:user@host: ou REMOTE:host: Un nom de périphérique SCSI distant valide peut être : REMOTE:user@host: pour permettre le balayage du bus SCSI distant ou REMOTE:user@host:1,0,0 pour accéder au périphérique SCSI situé sur host connecté au bus SCSI n° 1, target 0, lun 0. Afin de permettre l'accès distant à un host spécifique, le programme rscsi(1) doit être présent et configuré sur le hos

Transports SCSI alternatifs
Cdrecord est entièrement basé sur les commandes SCSI, mais ce n'est pas un problème car tous les graveurs CD/DVD/BluRay jamais fabriqués utilisent des commandes SCSI pour la communication. Même les lecteurs ATAPI sont simplement des lecteurs SCSI qui utilisent intrinsèquement l' interface paquet ATA comme couche de transport de commandes SCSI intégrée dans le transport IDE (ATA). Vous devrez peut-être spécifier une couche de transport alternative sur la ligne de commande si votre système d'exploitation n'implémente pas un sous-système de pilotes noyau entièrement intégré permettant d'accéder à n'importe quel lecteur en utilisant des commandes SCSI via une seule interface utilisateur

unique.

Pour accéder aux périphériques SCSI via des couches de transport alternatives, vous devez faire précéder le nom du périphérique SCSI par un indicateur de couche de transport. L'indicateur de couche de transport peut être quelque chose comme USCSI: ou ATAPI:. Pour obtenir une liste des couches de transport prises en charge pour votre plateforme, utilisez dev= HEL

Copier un CD audio sans fichier intermédiaire

cdda2wav dev=1,0 -vall cddb=0 -info-only

cdda2wav dev=1,0 -no-infofile -B -Oraw - | \

Si vous souhaitez écrire depuis stdin, assurez-vous que cdrecord est appelé avec une taille de FIFO suffisamment grande (par exemple, fs=128m), réduisez la vitesse d'écriture à une valeur inférieure à la vitesse de lecture du lecteur source (par exemple, speed=12), et activez l'option de gravure sans interruption pour le lecteur d'enregistrement en ajoutant driveropts=burnfree. Réplication d'un simple CD-ROM/DVD-ROM/BD-ROM

Pour copier un disque simple, lisez d'abord le master en utilisant :


readcd dev=1,0 f=somefile

Puis écrivez le disque en utilisant :


cdrecord dev=2,0 -v somefile

Réplication d'un CD-ROM en mode clone

Pour copier un CD en mode clone, lisez d'abord le CD master en utilisant :


readcd dev=1,0 -clone f=somefile

ou (si le CD contient de nombreux secteurs intentionnellement illisibles) en appelant :


readcd dev=1,0 -clone -nocorr f=somefile

Cela créera les fichiers somefile et somefile.toc. Ensuite, gravez le CD en utilisant :


cdrecord dev=2,0 -raw96r -clone -v somefile

Création d'un CD audio

Pour graver un CD-DA (audio) pur à vitesse simple, chaque piste étant contenue dans des fichiers nommés track01.cdaudio, track02.cdaudio, etc. :


cdrecord -v speed=1 dev=2,0 -dao -audio track*.cdaudio

Pour vérifier s'il sera possible d'utiliser la double vitesse pour l'exemple ci-dessus, utilisez l'option d'écriture factice :


cdrecord -v -dummy speed=2 dev=2,0 -dao -audio track*.cdaudio

Création d'un CD mixte audio-données

Pour graver un CD mixte avec un système de fichiers ISO-9660 à partir de cdimage.raw sur la première piste, les autres pistes étant des pistes audio provenant des fichiers track01.cdaudio, track02.cdaudio, etc. :


cdrecord -v dev=2,0 -dao cdimage.raw -audio track*.cdaudio

Création d'un CD-ROM/DVD-ROM/BD-ROM

Pour graver un disque pur à double vitesse, en utilisant les données du fichier cdimage.raw :


cdrecord -v speed=2 dev=2,0 -dao cdimage.raw

Pour créer une image d'un système de fichiers ISO-9660 avec les extensions Rock Ridge :


mkisofs -R -o cdimage.raw /home/joerg/master/tree

Pour vérifier le fichier résultant avant de graver sur disque sous Solaris :


mount -r -F fbk -o type=hsfs /dev/fbk0:cdimage.raw /mnt

Solaris 9 ou plus récent est livré avec une variante de l'idée originale de fbk appelée lofi. La commande pour la variante lofi est :

mount -r -F hsfs ` lofiadm -a /tmp/cdimage.raw ` /mnt

Notez que lofiadm a besoin de chemins absolus.

mount cdimage.raw -r -t iso9660 -o loop /mnt

ls -lR /mnt
umount /mnt

Si la vitesse globale du système est suffisante et que la structure du système de fichiers n'est pas trop complexe, cdrecord fonctionnera sans créer d'image du système de fichiers ISO-9660. Exécutez simplement le pipeline :


mkisofs -R /master/tree | cdrecord -v -dao fs=6m speed=2 dev=2,0 -

La taille minimale recommandée de la FIFO pour exécuter ce pipeline est de 4 Mo. Comme la taille par défaut de la FIFO est de 4 Mo, l'option fs= n'est nécessaire que si vous souhaitez utiliser une taille de FIFO différente. Si votre système est chargé, vous devriez également exécuter mkisofs dans la classe temps réel. Pour augmenter la priorité de mkisofs, remplacez la commande


mkisofs -R /master/tree
par
priocntl -e -c RT -p 59 mkisofs -R /master/tree

sous Solaris et par


nice --18 mkisofs -R /master/tree

sur les systèmes qui n'ont pas de planification temps réel conforme à UNIX International.

Cdrecord s'exécute à la priorité 59 sous Solaris, vous devriez exécuter mkisofs à une priorité maximale de 58. Sur d'autres systèmes, vous devriez exécuter mkisofs à une priorité minimale de nice --18.

La création d'un CD-ROM sans image de système de fichiers sur disque a été testée sur un Sparcstation-2 avec un Yamaha CDR-400. Cela a fonctionné jusqu'à quatre fois la vitesse lorsque la machine n'était pas chargée. Une machine plus rapide pourrait gérer la vitesse quadruple même en cas de charge.

Pour gérer les lecteurs qui doivent connaître la taille d'une piste avant de commencer à graver, exécutez d'abord


mkisofs -R -quiet -print-size /master/tree

puis exécutez


mkisofs -R /master/tree | cdrecord -v -dao speed=2 dev=2,0 tsize=XXXs -

où XXX est remplacé par la sortie de l'exécution précédente de mkisofs.

Définition des options du lecteur

Pour définir les options du lecteur sans graver de disque (par exemple, pour passer un lecteur en mode session unique), exécutez


cdrecord dev=2,0 -setdropts driveropts=singlesession

Si vous souhaitez le faire lorsqu'aucun disque n'est dans le lecteur, appelez


cdrecord dev=2,0 -force -setdropts driveropts=singlesession

RSH
Si l'environnement RSH est présent, la connexion distante ne sera pas créée via rcmd(3) mais en appelant le programme pointé par RSH. Utilisez par exemple RSH=/usr/bin/ssh pour créer une connexion sécurisée par shell.

Notez que cela force cdrecord à créer un pipe vers le programme rsh(1) et empêche cdrecord d'accéder directement au socket réseau du serveur distant. Cela rend impossible la configuration des paramètres de performance et ralentit la connexion par rapport à une connexion rcmd(3) initiée par root.

RSCSI
Si l'environnement RSCSI est présent, le serveur SCSI distant ne sera pas le programme /opt/schily/sbin/rscsi mais le programme pointé par RSCSI. Notez que le nom du programme serveur SCSI distant sera ignoré si vous vous connectez en utilisant un compte créé avec un programme serveur SCSI distant comme shell de connexion.

Cette commande est utilisée pour spécifier le code d'enregistrement standard international (ISRC) d'une piste. C'est un code qui devrait

ISRC isrc-code

This command is used to specify the International Standard Recording Code (ISRC) for commercial audio tracks.

The ISRC code must be 12 characters in length. The first two characters are characters that are from the two character country code. The next three characters are alphanumeric and describe the studio code. The next two characters are the last two digits from the recording year. The last 5 characters are digits that form a serial number that is unique for the same studio and year.

If cdrecord specific CUE extensions are permitted, the four fields of the ISRC may be separated by a minus sign.

If the ISRC command is used, it must appear after a TRACK command but before any INDEX command.

MESSAGE message-string
This command is used to specify the test of a message for a disk that includes CD-Text enhancements.

The parameter is the test of a message. If the string contains any spaces, it must be enclosed in quotation marks.

If the MESSAGE command appears before any TRACK command, the string parameter will be encoded as the message of the entire disk. If the MESSAGE command appears after a TRACK command, the string parameter will be encoded the the message of the current track.

This command is only accepted if the cdrecord specific CUE extensions are permitted.

PERFORMER performer-string
This command is used to specify the name of a performer for a disk that includes CD-Text enhancements.

The parameter is the name of the performer. If the string contains any spaces, it must be enclosed in quotation marks.

If the PERFORMER command appears before any TRACK command, the string parameter will be encoded as the performer of the entire disk. If the PERFORMER command appears after a TRACK command, the string parameter will be encoded the the performer of the current track.

POSTGAP mm:ss:ff
This command is used to specify the length of a postgap at the end of a track. The postgap data is generated internally by cdrecord. No data is consumed from the current data file.

The parameter specifies the postgap length in minutes, seconds and frames.

The POSTGAP command must appear after all INDEX commands for the current track. Only one POSTGAP command is allowed per track.

PREGAP mm:ss:ff
This command is used to specify the length of a pregap at the beginning of a track. The pregap data is generated internally by cdrecord. No data is consumed from the current data file.

The parameter specifies the postgap length in minutes, seconds and frames.

The PREGAP command must appear after a TRACK command but before any INDEX command. Only one PREGAP command is allowed per track.

REM comment
This command is used to put comments into a CUE file.

The text that appears in the line after a REM command is usually ignored. There is an exception: The special comment REM CDRTOOLS is used to enable cdrecord specific CUE extensions in the parser.

SONGWRITER songwriter-string
This command is used to specify the name of a songwriter for a disk that includes CD-Text enhancements.

The parameter is the name of a songwriter. If the string contains any spaces, it must be enclosed in quotation marks.

If the SONGWRITER command appears before any TRACK command, the string parameter will be encoded as the songwriter of the entire disk. If the SONGWRITER command appears after a TRACK command, the string parameter will be encoded the the songwriter of the current track.

TITLE title-string
This command is used to specify a title for a disk that includes CD-Text enhancements.

The parameter is the title for a track or for the disk. If the string contains any spaces, it must be enclosed in quotation marks.

If the TITLE command appears before any TRACK command, the string parameter will be encoded as the title of the entire disk. If the TITLE command appears after a TRACK command, the string parameter will be encoded the the title of the current track.

TRACK number datatype
This command is used to start a new TRACK.

The first parameter is a track number in the range 1-99.

The second parameter specifies the track data type.

The following datatypes are permitted:

AUDIO
Audio/Music (2352)
CDG
Karaoke CD+G (2448)
MODE1/2048
CDROM Mode1 Data (cooked)
MODE1/2352
CDROM Mode1 Data (raw)
MODE2/2336
CDROM-XA Mode2 Data
MODE2/2352
CDROM-XA Mode2 Data
CDI/2336
CDI Mode2 Data
CDI/2352
CDI Mode2 Data

All track numbers must be between 1 and 99 inclusive. The first track number can be greater than one, but all track numbers after the first must be sequential. There must be at least one track per file.

NOTES

Not all options described in this manual may be supported by the OpenSource variant of cdrecord. Cdrecord issues a warning if an attempt is made to use an option that has been disabled in the OpenSource variant.

On Solaris before Solaris 10 Update 1, you need to stop the volume management if you like to use the USCSI fallback SCSI transport code. Even things like cdrecord -scanbus will not work if the volume management is running.

Disks made in Track At Once mode are not suitable as a master for direct mass production by CD-manufacturers. You will need the disk at once option to record such disks. Nevertheless the disks made in Track At Once will normally be read in all CD-players. Some old audio CD-players however may produce a two second click between two audio tracks.

The minimal size of a track is 4 seconds or 300 sectors. If you write smaller tracks, the CD-recorder will add dummy blocks. This is not an error, even though the SCSI-error message looks this way.

Cdrecord has been tested on an upgraded Philips CDD-521 recorder at single and double speed on a SparcStation 20/502 with no problems, slower computer systems should work also. The newer Philips/HP/Plasmon/Grundig drives as well as Yamaha CDR-100 and CDR-102 work also. The Plasmon RF-4100 works, but has not been tested in multi-session. A Philips CDD-521 that has not been upgraded will not work. The Sony CDU-924 has been tested, but does not support XA-mode2 in hardware. The Sony therefore cannot create conforming multi-session disks. The Ricoh RO-1420C works, but some people seem to have problems to use them with speed=2, try speed=0 in this case.

The Yamaha CDR-400 and all new SCSI-3/mmc conforming drives are supported in single and multi-session.

You should run several tests in all supported speeds of your drive with the -dummy option turned on if you are using cdrecord on an unknown system. Writing a CD is a real-time process. NFS will not always deliver constantly the needed data rates. If you want to use cdrecord with CD-images that are located on a NFS mounted filesystem, be sure that the FIFO size is big enough. The author used cdrecord with medium load on a SS20/502 and even at quad speed on a Sparcstation-2 which was heavily loaded, but it is recommended to leave the system as lightly loaded as possible while writing a CD. If you want to make sure that buffer underruns are not caused by your source disk, you may use the command

cdrecord -dummy dev=2,0 padsize=600m /dev/null

to create a disk that is entirely made of dummy data. Cdrecord needs to run as root to get access to the /dev/scg? device nodes and to be able to lock itself into memory.

If you don't want to allow users to become root on your system, cdrecord may safely be installed suid root. This allows all users or a group of users with no root privileges to use cdrecord. Cdrecord in this case checks if the real user would have been able to read the specified files. To give all users access to use cdrecord, enter:

chown root /opt/schily/bin/cdrecord
chmod 4711 /opt/schily/bin/cdrecord

To give a restricted group of users access to cdrecord enter:

chown root /opt/schily/bin/cdrecord
chgrp cdburners /opt/schily/bin/cdrecord
chmod 4710 /opt/schily/bin/cdrecord

and add a group cdburners on your system.

Never give write permissions for non root users to the /dev/scg? devices unless you would allow anybody to read/write/format all your disks.

You should not connect old drives that do not support disconnect/reconnect to either the SCSI bus that is connected to the CD-recorder or the source disk.

A Compact Disc can have no more than 99 tracks.

When creating a disc with both audio and data tracks, the data should be on track 1 otherwise you should create a CDplus disk which is a multi-session disk with the first session containing the audio tracks and the followin

g session contenant la piste de données.

De nombreux systèmes d'exploitation ne sont pas capables de lire plus d'une piste de données, ou ont besoin d'un logiciel spécial pour le faire.

Plus d'informations sur l'ensemble de commandes SCSI d'un graveur HP CD peuvent être trouvées à l'adresse:

http://www.hp.com/isgsupport/cdr/index.html

Si vous avez plus d'informations ou des manuels de commandes SCSI pour des graveurs CD/DVD/BluRay actuellement non supportés, veuillez contacter l'auteur.

Le graveur CD Philips CDD 521 (même dans la version mise à niveau) présente plusieurs bugs firmwares. Certains d'entre eux vous obligeront à redémarrer l'appareil ou à redémarrer la machine.

Lorsque vous utilisez cdrecord avec le pilote générique SCSI de Linux, vous devez noter que cdrecord utilise une couche qui tente d'émuler la fonctionnalité du pilote scg par-dessus les lecteurs du système d'exploitation local. Malheureusement, le pilote sg sous Linux présente plusieurs défauts:

•
Il ne peut pas savoir si une commande SCSI n'a pas pu être envoyée du tout.
•
Il ne peut pas obtenir l'octet d'état SCSI. Cdrecord ne peut pour cette raison pas signaler les commandes SCSI défaillantes dans certaines situations.
•
Il ne peut pas obtenir le compte réel de transfert DMA. Cdrecord ne peut pas vous dire s'il y a un compte résiduel DMA.
•
Il ne peut pas obtenir le nombre d'octets valides dans les données de requête automatique. Cdrecord ne peut pas vous dire si l'appareil ne transfère aucune donnée de requête.
•
Il récupère trop peu de données dans la requête automatique (CCS/SCSI-2/SCSI-3 nécessite >= 18).

Le pourcentage de remplissage du FIFO est calculé juste après qu'un bloc de données a été écrit sur le graveur CD/DVD/BluRay. Pour cette raison, il n'y aura jamais 100% de remplissage du FIFO en mode streaming.

DIAGNOSTICS

Vous avez 9 secondes pour taper ^C afin d'interrompre cdrecord après avoir vu le message:

Starting to write CD at speed %d in %s mode for %s session.

Un message d'erreur typique pour une commande SCSI ressemble à :

cdrecord: I/O error. test unit ready: scsi sendcmd: no error
CDB:  00 20 00 00 00 00
status: 0x2 (CHECK CONDITION)
Sense Bytes: 70 00 05 00 00 00 00 0A 00 00 00 00 25 00 00 00 00 00
Sense Key: 0x5 Illegal Request, Segment 0
Sense Code: 0x25 Qual 0x00 (logical unit not supported) Fru 0x0
Sense flags: Blk 0 (not valid)
cmd finished after 0.002s timeout 40s

La première ligne donne des informations sur le transport de la commande. Le texte après les deux points donne le message d'erreur de l'appel système du point de vue du noyau. Il est généralement : I/O error sauf si d'autres problèmes surviennent. Les mots suivants contiennent une courte description de la commande SCSI qui échoue. Le reste de la ligne vous indique s'il y a eu des problèmes lors du transport de la commande sur le bus SCSI. fatal error signifie qu'il n'a pas été possible de transporter la commande (par exemple, aucun périphérique présent à l'adresse SCSI demandée).

La deuxième ligne affiche le bloc descripteur de commande SCSI pour la commande défaillante.

La troisième ligne donne des informations sur le code d'état SCSI retourné par la commande, si le transport de la commande réussit. Ce sont des informations d'erreur provenant du périphérique SCSI.

La quatrième ligne est une représentation hexadécimale des informations de requête automatique pour la commande.

La cinquième ligne est le texte d'erreur pour la clé de requête si elle est disponible, suivi du numéro de segment qui n'est valide que si la commande était une commande de copie. Si le message d'erreur n'est pas directement lié à la commande actuelle, le texte deferred error est ajouté.

La sixième ligne est le texte d'erreur pour le code de requête et le qualificateur de requête si disponibles. Si le type de périphérique est connu, les données de requête sont décodées à partir de tables dans scsierrs.c. Le texte est suivi de la valeur d'erreur pour une unité remplaçable sur site.

La septième ligne affiche le numéro de bloc lié à la commande défaillante et le texte de plusieurs indicateurs d'erreur. Le numéro de bloc peut ne pas être valide.

La huitième ligne rapporte le délai d'attente défini pour cette commande et le temps que la commande a réellement mis à se terminer.

Le message suivant n'est pas une erreur:

Track 01: Total bytes read/written: 2048/2048 (1 sectors).
cdrecord: I/O error. flush cache: scsi sendcmd: no error
CDB:  35 00 00 00 00 00 00 00 00 00
status: 0x2 (CHECK CONDITION)
Sense Bytes: F0 00 05 80 00 00 27 0A 00 00 00 00 B5 00 00 00 00 00
Sense Key: 0x5 Illegal Request, Segment 0
Sense Code: 0xB5 Qual 0x00 (dummy data blocks added) Fru 0x0
Sense flags: Blk -2147483609 (valid)
cmd finished after 0.002s timeout 40s

Il indique simplement qu'une piste plus petite que la taille minimum a été étendue à 300 secteurs.
