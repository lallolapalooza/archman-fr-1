DESCRIPTIO

N

cdrdao crée des CD-R audio et données en mode disc-at-once (DAO) piloté par un fichier de description appelé toc-file. En mode DAO, il est possible de créer des silences de piste non standard dont la durée diffère de 2 secondes et qui contiennent des données audio non nulles. C'est par exemple utile pour diviser des enregistrements en direct en pistes, là où des silences de 2 secondes seraient quelque peu

gênants.

Au lieu d'un toc-file, un fichier cue (utilisé par un célèbre outil de mastering DOS/Win

dows) peut être utilisé. Voir la sectio
n FICHIERS CUE pour plus de détails.

Seul l'affichage du lecteur CD se comportera légèrement différemment dans la zone de transition entre deux pistes.

Cette option pourrait également aider si read-toc échoue avec votre lecteur autrement.

--buffers buffer-count
Spécifie le nombre de tampons alloués pour éviter les sous-dépassements de tampon. Le nombre minimum de tampons est fixé à 10, par défaut 32, sauf sur les systèmes FreeBSD, où le défaut est 20. Chaque tampon contient 1 seconde de données audio, donc diviser buffer-count par la vitesse de gravure donne le temps maximum pendant lequel la lecture des données audio peut être interrompue.
--multi
Si cette option est spécifiée, la session ne sera pas fermée après que les données audio ont été gravées avec succès. Il est possible d'ajouter une autre session sur de tels disques, par exemple pour créer un CD-EXTRA.
--overburn
Par défaut, cdrdao ne permet pas de graver plus de données sur un support que ce qui est spécifié par le support actuel. Cette option permet d'ignorer cette condition.

--swap
Inverse l'ordre des octets de tous les échantillons envoyés au graveur CD.
--session session-nr
Utilisé pour read-toc et read-cd pour spécifier la session qui doit être traitée sur les CD multi-sessions.
--reload
Indique que le tiroir peut être ouvert avant la gravure sans demander à l'utilisateur de réinitialiser l'état du disque après une simulation.
--force
Force l'exécution d'une opération qui ne serait pas effectuée autrement.
--paranoia-mode mode
Définit le mode de correction pour l'extraction audio numérique. 0 : Pas de vérification, les données sont copiées directement depuis le lecteur. 1 : Lecture chevauchée pour éviter le jitter. 2 : Comme 1 mais avec des vérifications supplémentaires des données audio lues. 3 : Comme 2 mais avec détection et réparation supplémentaires des rayures.

La vitesse d'extraction diminue de 0 à 3.

Par défaut, c'est le mode paranoia complet (3).

FICHIERS TOC

Le fichier toc décrit quelles données sont gravées sur le CD-R et permet de contrôler les positions des pistes/index, les pré-espaces et les informations de sous-canal. C'est un simple fichier texte, utilisez votre éditeur de texte préféré pour le créer.

Un fichier toc contient un en-tête optionnel et une séquence de spécifications de piste. Les commentaires commençant par '//' allant jusqu'à la fin de la ligne peuvent être placés n'importe où.

En-tête

CATALOG "ddddddddddddd"
Spécifie le numéro de catalogue optionnel du CD. La chaîne doit contenir exactement 13 chiffres.

Les indicateurs suivants spécifient le type de session qui sera créé. Ils sont utilisés pour créer le format CD-TOC correct et pour vérifier la cohérence des modes de piste pour le type de session souhaité. Si plusieurs indicateurs sont donnés, le dernier prendra effet.

CD_DA
Le disque contient uniquement des pistes audio.
CD_ROM
Le disque contient uniquement des pistes de mode 1 ou des pistes de mode 1 et audio (CD en mode mixte).
CD_ROM_XA
Le disque contient des pistes de mode 2 forme 1 ou mode 2 forme 2. Des pistes audio sont également autorisées. Ce type doit être utilisé si des disques multi-sessions sont créés (option --multi).
CD_TEXT { ... }
Définit les données CD-TEXT globales telles que le titre de l'album et les langues utilisées. Voir la section CD-TEXT ci-dessous pour la syntaxe du contenu du bloc CD-TEXT.

FICHIERS CUE

Les fichiers Cue peuvent être utilisés partout où un fichier toc est attendu. Le fichier bin correspondant n'est pas extrait de l'instruction FILE d'un fichier cue mais est construit à partir du nom du fichier cue en remplaçant ".cue" par ".bin". Le fichier cue doit avoir exactement une instruction FILE.

Actuellement, les modes de piste suivants sont pris en charge : MODE1/2048, MODE1/2352, MODE2/2336, MODE2/2352. Les instructions CATALOG, ISRC et POSTGAP sont analysées mais pas encore évaluées.

PARAMÈTRES

Certaines des options en ligne de commande peuvent être stockées en tant que paramètres aux emplacements suivants. Les fichiers seront lus au démarrage de cdrdao dans cet ordre :

1. /etc/cdrdao.conf

2. /etc/defaults/cdrdao

3. /etc/default/cdrdao

4. $HOME/.cdrdao

Les options en ligne de commande remplaceront les paramètres chargés. Le fichier de paramètres contient des paires nom - valeur séparées par deux points. Les valeurs de chaîne doivent être entourées de guillemets. Le fichier est automatiquement écrit si l'option en ligne de commande --save est utilisée, mais il est également possible de le modifier manuellement. Les valeurs suivantes sont définies :

write_device
Périphérique utilisé pour les opérations simulate, write, copy, blank, disk-info et unlock. Option correspondante : --device
write_driver
Pilote (y compris les options du pilote) utilisé pour les opérations simulate, write, copy, blank, disk-info et unlock. Option correspondante : --driver
write_speed
Spécifie la vitesse d'écriture. Option correspondante : --speed
write_buffers
Spécifie les tampons fifo utilisés pour l'enregistrement. Option correspondante : --buffers
read_device
Périphérique utilisé pour les opérations read-toc, read-cd et copy. Option correspondante : --device ou --source-device
read_driver
Pilote (y compris les options du pilote) utilisé pour les opérations read-toc, read-cd et copy. Option correspondante : --driver ou --source-driver
read_paranoia_mode
Mode Paranoia utilisé pour les opérations read-cd et copy. Option correspondante : --paranoia-mode
cddb_server_list
Liste des serveurs CDDB pour read-cddb. Option correspondante : --cddb-servers
cddb_timeout
Délai d'attente de connexion CDDB en secondes utilisé par read-cddb. Option correspondante : --cddb-timeout
cddb_directory
Répertoire local où seront stockés les enregistrements CDDB récupérés, utilisé par read-cddb. Option correspondante : --cddb-directory
tmp_file_dir
Répertoire où seront créés les fichiers WAV temporaires à partir du décodage des fichiers MP3 et Ogg Vorbis. Option correspondante : --tmpdir

BOGUES

Si le programme est terminé pendant le processus d'écriture/simulation, les ressources IPC utilisées peuvent ne pas être libérées. Utilisez ipcs(8) et ipcrm(8) pour les supprimer.
