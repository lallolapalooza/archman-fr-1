Paquet: tinycdb

cdb(1) Manuel des commandes générales cdb(1)

NOM

cdb - Outil de manipulation de base de données constante

SYNTAXE

cdb -q [-m] [-n num] dbname clé
cdb -d [-m] [dbname|-]
cdb -l [-m] [dbname|-]
cdb -s [dbname|-]
cdb -c [-m] [-t nomtmp|-] [-p perms] [-weru0] dbname [fichierentree...]

DESCRIPTION

cdb est utilisé pour interroger, extraire, lister, analyser ou créer des fichiers CDB (Constant DataBase). Le format du cdb est décrit dans la page de manuel cdb(5). Cette page de manuel correspond à la version 0.81 du paquet tinycdb.

Interrogation

cdb -q recherche la clé donnée dans le fichier cdb dbname donné, et écrit la valeur associée sur la sortie standard si elle est trouvée (et se termine avec zéro), ou se termine avec une valeur non nulle si elle n'est pas trouvée. dbname doit être un fichier accessible en recherche, et stdin ne peut pas être utilisé comme entrée. Par défaut, cdb affichera *tous* les enregistrements trouvés. Options reconnues en mode interrogation :

-nnum
demande à cdb de trouver et d'écrire un enregistrement avec un numéro donné num commençant par 1 — lorsqu'il y a plusieurs enregistrements avec une clé donnée.
-m
une nouvelle ligne sera ajoutée après chaque valeur imprimée. Par défaut, les valeurs multiples seront écrites sans aucun délimiteur.

Extraction/Liste

cdb -d extrait le contenu, et cdb -l liste les clés de cdbfile (ou l'entrée standard si non spécifié) vers la sortie standard, dans un format contrôlé par la présence de l'option -m. Voir la sous-section « Formats » ci-dessous. La sortie de cdb -d peut être utilisée comme entrée pour cdb -c.

Création

La base de données Cdb est créée en deux étapes : une base de données temporaire est créée, et une fois terminée, elle est renommée atomiquement à son emplacement permanent. Cela évite les exigences de verrouillage entre les lecteurs et les écrivains (ou créateurs). cdb -c tentera de créer le cdb dans le fichier nomtmp (ou dbname avec « .tmp » ajouté si aucune option -t n'est donnée) puis le renommera en dbname. Il lira les fichiersentree fournis (ou l'entrée standard si aucun n'est spécifié). Options reconnues en mode création :

-t nomtmp
utilise le fichier nomtmp donné comme fichier temporaire. Par défaut, dbname.tmp (c'est-à-dire avec le fichier de sortie auquel .tmp est ajouté). Notez que nomtmp doit être dans le même système de fichiers que le fichier de sortie, car cdb utilise rename(2) pour finaliser la procédure de création de la base de données. Si nomtmp est un simple trait d'union (-), aucun fichier temporaire ne sera créé, la base de données sera construite sur place. Ce mode est utile lorsque le renommage final est effectué par l'appelant.
-p perms
permissions pour le nouveau fichier créé (généralement un nombre octal, comme 0644). Par défaut, les permissions sont 0666 (avec l'umask du processus actuel appliqué). Si cette option est spécifiée, la valeur de l'umask actuelle n'a aucun effet.
-w
avertit des clés dupliquées.
-e
abandonne en cas de clés dupliquées (implique -w).
-r
remplace une clé existante par une nouvelle en cas de doublon. Cela peut nécessiter une réécriture du fichier de base de données pour supprimer les anciens enregistrements, et peut être lent.
-0
remplit de zéros les enregistrements existants lors de l'ajout d'enregistrements dupliqués. C'est plus rapide que -r, mais laisse des zéros supplémentaires dans le fichier de base de données en cas de doublons.
-u
n'ajoute pas d'enregistrements dupliqués.
-m
interprète l'entrée comme une séquence de lignes, un enregistrement par ligne, avec la valeur séparée de la clé par des espaces ou des tabulations, au lieu du format cdb natif (voir ci-dessous « Format d'entrée/sortie »).

Notez que l'utilisation de toute option nécessitant la vérification des doublons ralentira *significativement* le processus de création, en particulier pour les grandes bases de données.

Statistiques

cdb -s analysera dbfile et affichera un résumé sur la sortie standard. Les statistiques comprennent : le nombre total de lignes dans le fichier, les longueurs minimale, moyenne et maximale des clés et des valeurs, les tables de hachage (max 256) et les entrées utilisées, le nombre de collisions de hachage (c'est-à-dire plus d'une clé pointe vers la même entrée de table de hachage), la taille minimale, moyenne et maximale de la table de hachage (des tables non vides), et le nombre de clés qui se situent à 10 distances différentes de leur index de table de hachage calculé — les clés à une distance de 0 nécessitent une seule consultation de table de hachage, 1 — deux, et ainsi de suite ; plus il y a de clés à une plus grande distance, plus la recherche dans la base de données est lente.

Format d'entrée/sortie

Par défaut, cdb attend (pour l'opération de création) ou écrit (pour l'extraction/liste) des données au format cdb natif. Le format cdb natif est une séquence d'enregistrements sous la forme :
+klen,vlen:clé->val\n
où « + », « , », « : », « - », « > » et « \n » (nouvelle ligne) sont des caractères littéraux, klen et vlen sont les longueurs de la clé et de la valeur en nombres décimaux, et clé et val sont la clé et la valeur elles-mêmes. La série d'enregistrements est terminée par une ligne vide. C'est le seul format où la clé et la valeur peuvent contenir n'importe quel caractère, y compris une nouvelle ligne, un zéro (\0) et ainsi de suite.

Lorsque l'option -l est demandée (mode liste de clés), cdb produira une sortie légèrement modifiée sous la forme :
+klen:clé\n
(notez que vlen et val sont omis, ainsi que les délimiteurs environnants).

Si l'option -m est donnée, cdb attendra ou produira une ligne pour chaque enregistrement (la nouvelle ligne est un délimiteur d'enregistrement), et chaque ligne contiendra des espaces optionnels, une clé, des espaces et une valeur jusqu'à la fin de la ligne. Les lignes commençant par un caractère dièse (#) et les lignes vides sont ignorées. C'est le même format que celui attendu par l'utilitaire mkmap(1).

RÉSUMÉ DES OPTIONS

Voici un résumé des options acceptées par l'utilitaire cdb :

-0
remplit de zéros les enregistrements dupliqués en mode création (-c).
-c
mode création.
-d
mode extraction.
-e
abandonne (erreur) en cas de clé dupliquée en mode création (-c).
-h
affiche une aide courte et quitte.
-l
mode liste.
-m
l'entrée ou la sortie est au format « map », pas au format cdb natif. En mode interrogation, ajoute une nouvelle ligne après chaque valeur écrite.
-nnum
trouve et imprime le num-ième enregistrement en mode interrogation (-q).
-q
mode interrogation.
-r
remplace les clés dupliquées en mode création (-c).
-s
mode statistiques.
-t fichiertemp
spécifie le fichier temporaire lors de la création (-c) d'un fichier cdb (utilisez un simple trait d'union (-) comme fichiertemp pour ne pas utiliser de fichier temporaire).
-u
n'insère pas de clés dupliquées (unique) en mode création (-c).
-w
avertit des clés dupliquées en mode création (-c).
