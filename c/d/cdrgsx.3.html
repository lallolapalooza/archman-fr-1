!>
!> CDRGSX vérifie le pilote expert CGGESX pour le problème de valeurs propres généralisées non symétriques (forme de Schur).
!>
!> CGGES factorise A et B comme Q*S*Z'  et Q*T*Z' , où ' signifie transposée conjuguée,
!> S et T sont triangulaires supérieures (c'est-à-dire sous forme de Schur généralisée),
!> et Q et Z sont unitaires. Il calcule également les valeurs propres généralisées
!> (alpha(j),beta(j)), j=1,...,n. Ainsi, w(j) = alpha(j)/beta(j) est une racine de l'équation
!> caractéristique
!>
!>                 det( A - w(j) B ) = 0
!>
!> Optionnellement, il réorganise également les valeurs propres de sorte qu'un
!> cluster de valeurs propres sélectionnées apparaisse dans le bloc diagonal principal
!> des formes de Schur ; calcule un nombre de condition réciproque pour la moyenne
!> des valeurs propres sélectionnées ; et calcule un nombre de condition réciproque
!> pour les sous-espaces défléchissants droit et gauche correspondant aux
!> valeurs propres sélectionnées.
!>
!> Lorsque CDRGSX est appelée avec NSIZE > 0, cinq (5) types de paires de matrices
!> intégrées sont utilisées pour tester la routine CGGESX.
!>
!> Lorsque CDRGSX est appelée avec NSIZE = 0, elle lit les données de la matrice de test
!> pour tester CGGESX.
!> (plus de détails sur le type de données lues sont nécessaires).
!>
!> Pour chaque paire de matrices, les tests suivants seront effectués et
!> comparés au seuil THRESH, à l'exception des tests (7) et (9) :
!>
!> (1)   | A - Q S Z' | / ( |A| n ulp )
!>
!> (2)   | B - Q T Z' | / ( |B| n ulp )
!>
!> (3)   | I - QQ' | / ( n ulp )
!>
!> (4)   | I - ZZ' | / ( n ulp )
!>
!> (5)   si A est sous forme de Schur (c'est-à-dire forme triangulaire)
!>
!> (6)   maximum sur j de D(j)  où :
!>
!>                     |alpha(j) - S(j,j)|        |beta(j) - T(j,j)|
!>           D(j) = ------------------------ + -----------------------
!>                  max(|alpha(j)|,|S(j,j)|)   max(|beta(j)|,|T(j,j)|)
!>
!> (7)   si le tri a fonctionné et SDIM est le nombre de valeurs propres
!>       qui ont été sélectionnées.
!>
!> (8)   la valeur estimée DIF ne diffère pas des valeurs réelles de
!>       Difu et Difl plus qu'un facteur 10*THRESH. Si l'estimation DIF
!>       est égale à zéro, les valeurs réelles correspondantes de Difu
!>       et Difl devraient être inférieures à EPS*norm(A, B). Si la valeur
!>       réelle de Difu et Difl est égale à zéro, l'estimation DIF devrait
!>       être inférieure à EPS*norm(A, B).
!>
!> (9)   Si INFO = N+3 est renvoyé par CGGESX, la réorganisation
!>       et nous vérifions que DIF = PL = PR = 0 et que la valeur réelle
!>       de Difu et Difl est < EPS*norm(A, B). Nous comptons les événements
!>       où INFO=N+3.
!>
!> Pour les matrices de test lues, les mêmes tests sont exécutés sauf que la
!> valeur exacte de DIF (et PL) sont des données d'entrée. De plus, il y a
!> un test supplémentaire exécuté pour les matrices de test lues :
!>
!> (10)  la valeur estimée PL ne diffère pas de la valeur réelle de
!>       PLTRU plus qu'un facteur THRESH. Si l'estimation PL égale
!>       zéro, la valeur réelle correspondante de PLTRU devrait être
!>       inférieure à EPS*norm(A, B). Si la valeur réelle de PLTRU est
!>       égale à zéro, l'estimation PL devrait être inférieure à
!>       EPS*norm(A, B).
!>
!> Notez que pour les tests intégrés, un total de 10*NSIZE*(NSIZE-1)
!> paires de matrices sont générées et testées. NSIZE doit être maintenu petit.
!>
!> SVD (routine CGESVD) est utilisé pour calculer la valeur réelle de DIF_u
!> et DIF_l lors des tests des problèmes de test intégrés.
!>
!> Matrices de Test Intégrées
!> ======================
!>
!> Toutes les matrices de test intégrées sont le bloc 2x2 de matrices triangulaires
!>
!>          A = [ A11 A12 ]    et      B = [ B11 B12 ]
!>              [     A22 ]                 [     B22 ]
!>
!> où pour différents types, A11 et A22 sont donnés comme suit.
!> A12 et B12 sont choisis de telle sorte que l'équation de Sylvester généralisée
!>
!>          A11*R - L*A22 = -A12
!>          B11*R - L*B22 = -B12
!>
!> ait des solutions prescrites R et L.
!>
!> Type 1 :  A11 = J_m(1,-1) et A_22 = J_k(1-a,1).
!>          B11 = I_m, B22 = I_k
!>          où J_k(a,b) est le bloc de Jordan kxk avec "a" sur la
!>          diagonale et "b" sur la superdiagonale.
!>
!> Type 2 :  A11 = (a_ij) = ( 2(.5-sin(i)) ) et
!>          B11 = (b_ij) = ( 2(.5-sin(ij)) ) pour i=1,...,m, j=i,...,m
!>          A22 = (a_ij) = ( 2(.5-sin(i+j)) ) et
!>          B22 = (b_ij) = ( 2(.5-sin(ij)) ) pour i=m+1,...,k, j=i,...,k
!>
!> Type 3 :  A11, A22 et B11, B22 sont choisis comme pour le Type 2, mais chaque
!>          deuxième bloc diagonal dans A_11 et chaque troisième bloc diagonal
!>          dans A_22 sont des blocs de 2x2.
!>
!> Type 4 :  A11 = ( 20(.5 - sin(ij)) ) et B22 = ( 2(.5 - sin(i+j)) )
!>             pour i=1,...,m,  j=1,...,m et
!>          A22 = ( 20(.5 - sin(i+j)) ) et B22 = ( 2(.5 - sin(ij)) )
!>             pour i=m+1,...,k,  j=m+1,...,k
!>
!> Type 5 :  (A,B) ont potentiellement des valeurs propres proches ou communes et
!>          un très grand écart par rapport à la diagonale par blocs. A_11
!>          est choisi comme la sous-matrice principale m x m de A_1 :
!>                  |  1  b                            |
!>                  | -b  1                            |
!>                  |        1+d  b                    |
!>                  |         -b 1+d                   |
!>           A_1 =  |                  d  1            |
!>                  |                 -1  d            |
!>                  |                        -d  1     |
!>                  |                        -1 -d     |
!>                  |                               1  |
!>          et A_22 est choisi comme la sous-matrice principale k x k de A_2 :
!>                  | -1  b                            |
!>                  | -b -1                            |
!>                  |       1-d  b                     |
!>                  |       -b  1-d                    |
!>           A_2 =  |                 d 1+b            |
!>                  |               -1-b d             |
!>                  |                       -d  1+b    |
!>                  |                      -1+b  -d    |
!>                  |                              1-d |
!>          et la matrice B sont choisies comme des matrices identité (voir SLATM5).
!>
!>

Paramètres

NSIZE 
!>          NSIZE est ENTIER
!>          La taille maximale des matrices à utiliser. NSIZE >= 0.
!>          Si NSIZE = 0, aucune matrice de test intégrée n'est utilisée, mais
!>          des matrices de test lues sont utilisées pour tester SGGESX.
!>

NCMAX

!>          NCMAX est ENTIER
!>          Taille maximale autorisée NMAX pour la génération de la matrice de Kronecker
!>          dans l'appel à CLAKF2
!>

THRESH

!>          THRESH est RÉEL
!>          Un test comptera comme  si le , calculé comme
!>          d
décrite ci-dessus, dépasse THRESH. Notez que l'erreur !> est mise à l'échelle pour être O(1), donc THRESH devrait être un multiple !> raisonnablement petit de 1, p. ex., 10 ou 100. En particulier, !> il ne devrait pas dépendre de la précision (simple vs. double) !> ni de la taille de la matrice. THRESH >= 0. !>

NI

N 
!>          NIN est INTEGER
!>          Le numéro d'unité FORTRAN pour lire le fichier de données
!>          des problèmes à résoudre.
!
>
