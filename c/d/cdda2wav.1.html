CDDA2WAV(1) Manuel des commandes générales CDDA2WAV(1)

NOM

cdda2wav - extrait les données audio de CD dans des fichiers sonores avec vérification de données supplémentaire

SYNOPSIS

cdda2wav [ options ][ dev=périphérique ] [fichiers ou répertoires]

DESCRIPTION

cdda2wav peut récupérer les pistes audio des lecteurs CDROM capables de lire les données audio numériquement via SCSI (CDDA).

Comme cdda2wav implémente des stratégies pour contourner les défauts typiques des CD audio qu'il lit, il lit de nombreux disques qui ne peuvent pas être lus par d'autres logiciels. Comme cdda2wav peut utiliser libparanoia (voir l'option -paranoia ci-dessous) pour vérifier les données lues depuis le support, il offre une qualité supérieure même si le support est poussiéreux, rayé ou si d'autres problèmes surviennent.

Comme cdda2wav peut être dirigé pour écrire les données audio sur la sortie standard, il écrit toutes ses informations de sortie sur stderr par défaut. Voir l'option out-fd=descripteur ci-dessous.

Paramètres par défaut

Cdda2wav lit par défaut la première piste audio du support et le niveau de verbosité par défaut est réglé sur -vtoc,summary,sectors,titles et cdda2wav écrit par défaut des fichiers *.inf. Pour extraire toutes les pistes audio avec vérification de qualité, il est recommandé d'appeler :

cdda2wav -vall cddb=0 speed=4 -paranoia paraopts=proof -B

Pour des indices sur la manière de spécifier manuellement de meilleurs paramètres, voir la description de paraopts= ci-dessous.

Nommage des périphériques

La plupart des utilisateurs n'ont pas besoin de se soucier du nommage des périphériques. Si aucune option dev= n'a été spécifiée, cdda2wav implémente le support de la cible automatique et trouve automatiquement le lecteur lorsqu'un seul lecteur de type CD-ROM est disponible dans le système. Lorsqu'il y a plus d'un lecteur de type CD-ROM, une liste de paramètres de nom de périphérique possibles peut être récupérée avec cdda2wav -scanbus ou à partir de l'exemple de cible dans la sortie de cdda2wav dev=help, puis le paramètre dev= peut être défini sur la base de la liste des périphériques.

Le paramètre périphérique de l'option dev= expliquée ci-dessous fait référence à la notation standard SCSI CAM pour scsibus/target/lun de l'enregistreur CD/DVD/BluRay. Si un fichier /etc/default/cdrecord existe, le paramètre de l'option dev= peut également être une étiquette de nom de lecteur dans ledit fichier (voir la section FICHIERS).

Le format de fichier *.inf implémente plus de fonctionnalités de CD audio que le format CUE CDRWIN et permet de créer des copies 1:1 s'il y a un fichier de données audio par piste. Utilisez le format de fichier CUE pour les métadonnées uniquement si vous avez réellement besoin de ce format.

Pour permettre à cdda2wav de créer des fichiers CUE, vous devez également spécifier -t all pour passer cdda2wav en mode de création d'un seul fichier de données audio pour tout le CD.

-paranoia
Utilise la bibliothèque paranoia comme filtre par-dessus les routines de lecture de cdda2wav. En mode paranoia, le temps de latence pour le mode -interactive et avec une taille de tampon de prélecture de 150 à 300 secteurs, est augmenté à typiquement 5 à 10 secondes. Ceci est dû au code paranoia qui lit tout au moins deux fois et doit vider le cache RAM du lecteur CD-ROM.

La taille de la zone de prélecture doit être supérieure à la taille de la RAM du lecteur pour permettre à libparanoia de vider le cache RAM du lecteur. Comme la taille de la zone de prélecture était dans le passé une constante compilée dans le code de libparanoia, la qualité d'extraction lors de l'utilisation de libparanoia n'était plus suffisante avec les lecteurs construits après l'an 2000. Voir le paramètre readahead= de l'option paraopts= ci-dessous.

Si le mode paranoia est utilisé, cdda2wav affiche des statistiques de qualité pour chaque piste extraite. Les éléments suivants apparaissent dans la liste :

Valeur Description
rderr Nombre d'erreurs de lecture matérielles
skip Nombre de secteurs sautés en raison de l'épuisement des tentatives
atom Nombre de jitters intra-secteurs détectés (jitters d'image)
edge Nombre de jitters entre secteurs détectés
drop Nombre d'octets perdus corrigés
dup Nombre d'octets dupliqués corrigés
drift Nombre de dérives détectées
c2 Nombre de secteurs avec erreurs C2

overlap Nombre d'augmentations dynamiques de la taille du chevauchement

Les indicateurs de qualité en détail :

rderr
Le nombre de requêtes de lecture de bas niveau échouées. Chaque lecture couvre sectors-per-request secteurs. La taille sectors-per-request est généralement inférieure à la taille de prélecture.
skip
Le nombre de secteurs qui ont été sautés car le nombre de tentatives de correction d'erreur de lecture était épuisé et aucune lecture réussie n'était possible.
atom
Le nombre de jitters détectés à l'intérieur des secteurs. Cela ne devrait jamais se produire, mais chaque fois qu'une erreur C2 non corrigeable se produit, le lecteur peut perdre le flux. Augmenter la taille du tampon de prélecture peut réduire les résultats des erreurs atomiques.
edge
Le nombre de jitters détectés aux bords des secteurs. Cela pourrait être causé par des erreurs de positionnement de secteur. Augmenter la taille du tampon de prélecture peut réduire les résultats des erreurs de bord.
drop
Le nombre d'échantillons perdus. Cela pourrait être causé par des erreurs de positionnement de secteur. Augmenter la taille du tampon de prélecture peut réduire les résultats des erreurs de bord.
dup
Les échantillons dupliqués pourraient être causés par des erreurs de positionnement de secteur comme des échantillons perdus. Augmenter la taille du tampon de prélecture peut réduire les résultats des erreurs de bord.
drift
C'est la quantité de dérives détectées lors de la vérification de la zone de chevauchement.
c2
Le nombre de secteurs avec des erreurs C2 observés lors de la lecture de la dernière piste. Comme le code paranoia a tendance à lire de nombreuses fois les mauvaises parties du disque, ce nombre est généralement supérieur au nombre qui apparaîtrait lorsque le disque est lu une seule fois de manière linéaire. Utilisez paraopts=disable,c2check pour voir un nombre qui représente l'état du support.
reads
Le nombre de blocs de prélecture lus pour la dernière piste par la couche supérieure et le pourcentage de données lues par rapport à la taille de la piste. Ce pourcentage est généralement de 200 % car le code paranoia lit toutes les données au moins deux fois. S'il y a beaucoup de chevauchements et beaucoup de problèmes de lecture, ce pourcentage augmente.
overlap
Le nombre d'augmentations de la taille du chevauchement. Cela se produit lorsque la taille du chevauchement est inférieure à la taille maximale du chevauchement et que des erreurs sont détectées dans la zone de chevauchement.

N

cdda2wav est capable de lire directement et numériquement des parties d'un CD audio ou d'un CDROM multimédia (contenant des parties audio). Ces parties peuvent être écrites dans un fichier, un pipe, ou vers un périphérique

son.

cdda2wav signifie CDDA vers WAV (où CDDA signifie compact disc digital audio et WAV est un format d'échantillons sonores introduit par MS Windows). Il permet de copier des données audio CDDA depuis le lecteur CDROM vers un fichier au format WAV ou dans d'autres

formats.

Certaines versions de cdda2wav peuvent essayer d'obtenir des priorités d'ordonnancement temps réel plus élevées pour assurer un fonctionnement fluide (sans interruption). Ces priorités sont disponibles pour les super-utilisateurs et sont plus élevées que celles des processus « normaux ». Ainsi, les retards sont

minimisés.

Si vous n'avez qu'un seul CDROM et qu'il contient un CD audio, vous pouvez simplement invoquer cdda2wav et il créera le fichier son audio.wav enregistrant la piste entière à partir de la piste 1 en stéréo à 16 bits à une fréquence d'échantillonnage de 44100 Hz, si votre système de fichiers a assez d'espace libre. Sinon, la durée d'enregistrement sera limitée. Pour plus de détails, voir les fichiers README et README.INS

TALL.

Si vous avez plus d'un lecteur de type CD-ROM dans le système, vous devez spécifier l'option de

v=

Définir le format

-O audiotype peut être wav (pour les fichiers wav) ou au ou sun (pour les fichiers PCM sun) ou cdr ou raw (pour les fichiers sans en-tête à utiliser pour les graveurs de CD). Tous les échantillons de fichier sont codés en modulation d'impulsion en linéaire (comme dans le format de disque compact audio). Cela vaut pour tous les formats audio. Les fichiers wav sont compatibles avec les fichiers son Wind*ws, ils ont l'ordre d'octets lsb,msb qui est l'opposé de l'ordre d'octets utilisé sur le CD audio. L'extension de nom de fichier par défaut est '.wav'. Les fichiers de type Sun ne sont pas comme les anciens fichiers .au courants codés logarithmiquement, mais au lieu de cela, comme mentionné ci-dessus, le PCM linéaire est utilisé. L'ordre d'octets est msb,lsb po

ur être compatible. L'extension de nom de fichier par défaut est '.au'. L'AIFF et la variante plus récente AIFC du monde Apple/SGI stockent leurs échantillons au format bigendian (msb,lsb). Dans AIFC, aucune compression n'est utilisée. Enfin le 'format' le plus simple, le format cdr aussi appelé raw. Il est fait par défaut dans l'

Comme il n'y a pas d'information d'en-tête dans ce format, les paramètres d'échantillonnage ne peuvent être identifiés qu'en jouant les échantillons sur une carte son ou similaire. L'extension de nom de fichier par défaut est '.cdr' ou '.raw'.
