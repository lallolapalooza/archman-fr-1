DESCRIPTIO

N

cdb est une bibliothèque pour créer et accéder aux fichiers Constant DataBase. Le fichier stocke des paires (clé,valeur) et est utilisé pour trouver rapidement une valeur à partir d'une clé donnée. Les fichiers Cdb sont des fichiers créés une seule fois, c'est-à-dire qu'une fois créés, le fichier ne peut pas être mis à jour mais doit être recréé à partir de zéro -- c'est pourquoi la base de données est appelée constante. Le fichier Cdb est optimisé pour un accès rapide. Le format de ce type de fichier est décrit dans la page man cdb(5). Cette page manuelle correspond à la version 0.81 du paquet tin

ycdb.

La bibliothèque définit deux interfaces non entrelacées : pour interroger les données d'un fichier cdb existant (mode lecture seule) et pour créer un tel fichier (presque écriture seule). Strictement parlant, ces modes permettent également un ensemble très limité d'opérations opposées (c'est-à-dire qu'en mode interrogation, il est possible de mettre à jour la valeur d'une clé)

.

Toutes les routines de cette bibliothèque sont sûres pour les threads car aucune donnée globale n'est utilisée, à l'exception de la variable errno pour l'indication

d'erreur.

Les fichiers de données cdb peuvent être déplacés entre systèmes en

toute sécurité, car le forma
t ne dépend pas de l'architecture.

MODE

D'INTERROGATION

Deux modes d'interrogation sont disponibles. Le premier utilise une structure qui représente une base de données cdb, tout comme la structure FILE de la bibliothèque stdio, et l'autre travaille avec un descripteur de fichier simple. Le premier mode est plus sophistiqué et flexible, et généralement un peu plus rapide. Il utilise mmap(2) en interne. Ce mode peut paraître plus « naturel » ou orienté objet par rapport au

second.

Mode d'interrogation

2

Dans ce mode, il faut ouvrir un fichier cdb en utilisant l'un des appels système standards (comme open(2)) pour obtenir un descripteur de fichier, puis passer ce descripteur de fichier aux routines cdb. Les méthodes disponibles pour interroger une base de données cdb en utilisant uniquement un descripteur de fichier incluent

: 
int cdb_seek(fd, key, klen, dlenp)
  int fd;
  const void *key;
  unsigned klen;
  unsigned *dlenp
;
recherche dans une base de données cdb (comme pointée par le descripteur de fichier fd) une clé donnée par (key, klen), et positionne le pointeur de fichier au début des données associées à cette clé si elle est trouvée, de sorte que la prochaine opération de lecture depuis ce descripteur de fichier lira cette valeur, et place la longueur de la valeur, en octets, dans la variable pointée par dlenp. Renvoie une valeur positive si l'opération a réussi, 0 si la clé n'a pas été trouvée, ou une valeur négative en cas d'erreur. Pour lire les données depuis un fichier cdb, la routine cdb_bread() ci-dessous peut être
utilisée.pre>int cdb_bread(fd, buf, len) int fd; void *buf; int len;
lit les données d'un fichier (tel qu'indiqué par le descripteur de fichier fd ) et place octets de ce fichier dans un tampon pointé par le pointeur buf. Retourne 0 si exactement octets ont été lus, ou une valeur négative en cas d'erreur ou de fin de fichier. Cette routine ignore les erreurs d'interruption (EINTR). Définit la variable errno à EIO en cas de condition de fin de fichier (lorsqu'il reste moins de octets disponibl
es à la l
ecture).

Note

s

Notez que la valeur d'une clé donnée peut être mise à jour sur place par une autre valeur de même taille, en écrivant dans le fichier à la position trouvée par cdb_find() ou cdb_seek(). Cependant, il faut être très prudent lorsqu'on fait cela, car l'opération d'écriture peut ne pas réussir en cas de, par exemple, panne de courant, laissant ainsi des données cor

rompues. Lorsque la base de données est (re)créée, on peut garantir qu'aucune donnée incorrec
te ne sera écrite dans la base de données, mais pas avec une mise à jour sur place. Notez égalem
ent qu'il n'est pas possible de mettre à jour une clé ou de changer la longueur d'une valeur.

MODE DE

CRÉATION

Le fichier de base de données cdb devrait généralement être créé en deux étapes : d'abord, un fichier temporaire est créé et écrit sur le disque, et ensuite, ce fichier temporaire est renommé vers son emplacement permanent. L'appel Unix rename(2) est une opération atomique, elle supprime le fichier de destination s'il existe ET renomme un autre fichier en une seule étape. De cette façon, il est garanti que les lecteurs ne verront pas une base de données incomplète. Pour empêcher des mises à jour simultanées multiples, un verrouillage peut également être

utilisé.

Toutes les routines utilisées pour créer une base de données cdb travaillent avec un objet struct cdb_make qui est opaque pour l'application. L'application peut supposer que struct cdb_make a au moins le(s) même(s) membre(s) que publié dans struct cdb ci-

dessus. 
int cdb_make_start(cdbmp, fd)
   struct cdb_make *cdbmp;
   int fd
;
initialise la structure pour créer une base de données. Le fichier fd devrait être ouvert en lecture-écriture et devrait être positionnable. Retourne 0 en cas de succès ou une valeur négative en cas
d'erreur. 
int cdb_make_add(cdbmp, key, klen, val, vlen)
   struct cdb_make *cdbmp;
   const void *key, *val;
   unsigned klen, vlen
;
ajoute un enregistrement avec la clé (key,klen) et la valeur (val,vlen) à une base de données. Retourne 0 en cas de succès ou une valeur négative en cas d'erreur. Notez que cette routine ne vérifie pas si la clé donnée existe déjà, mais cdb_find() ne verra pas le second enregistrement avec la même clé. Il n'est pas possible de continuer la construction d'une base de données si cdb_make_add() a retourné un indicateur
d'erreur. 
int cdb_make_finish(cdbmp)
   struct cdb_make *cdbmp
;
finalise le fichier de base de données, construisant tous les index nécessaires, et libère les structures mémoire. Elle ne ferme pas le descripteur de fichier. Retourne 0 en cas de succès ou une valeur négative en cas
d'erreur. 
int cdb_make_exists(cdbmp, key, klen)
   struct cdb_make *cdbmp;
   const void *key;
   unsigned klen
;
Cette routine tente de trouver la clé donnée par (key,klen) dans une base de données pas encore terminée. Elle peut ralentir considérablement l'ensemble du processus, et actuellement elle vide le tampon interne sur le disque à chaque appel avec une clé dont la valeur de hachage existe déjà dans la base de données. Retourne 0 si une telle clé n'existe pas, 1 si elle existe, ou une valeur négative en cas d'erreur. Notez que le fichier de base de données devrait être ouvert en lecture-écriture (et non en écriture seule) pour utiliser cette routine. Si cdb_make_exists() a retourné une erreur, il peut ne pas être possible de continuer la construction de la base de
données. 
int cdb_make_find(cdbmp, key, klen, mode)
   struct cdb_make *cdbmp;

   unsigned klen;
   int mode
;
Cette routine tente de trouver la clé donnée par (key,klen) dans la base de données en cours de création. Si la clé donnée existe déjà, une action spécifiée par mode sera effectuée :

base de données. Les enregistrements insérés en de

Si aucune clé correspondante n'a été trouvée, la routine retourne 0. Si au moins un enregistrement a été trouvé/supprimé, une valeur positive sera retournée. En cas d'erreur, une valeur négative sera retournée et errno sera défini en conséquence. C'est équivalent à appeler cdb_make_find() avec le mode CDB_FIND_REMOVE suivi de l'appel à cdb_make_a
