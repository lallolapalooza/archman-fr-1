!>
!>      CDRVST vérifie les pilotes du problème de valeurs propres hermitien.
!>
!>              CHEEVD calcule toutes les valeurs propres et, optionnellement,
!>              les vecteurs propres d'une matrice hermitienne complexe,
!>              en utilisant un algorithme de type diviser pour mieux régner.
!>
!>              CHEEVX calcule des valeurs propres sélectionnées et, optionnellement,
!>              les vecteurs propres d'une matrice hermitienne complexe.
!>
!>              CHEEVR calcule des valeurs propres sélectionnées et, optionnellement,
!>              les vecteurs propres d'une matrice hermitienne complexe
!>              en utilisant la représentation robuste relative lorsque c'est possible.
!>
!>              CHPEVD calcule toutes les valeurs propres et, optionnellement,
!>              les vecteurs propres d'une matrice hermitienne complexe en stockage compact,
!>              en utilisant un algorithme de type diviser pour mieux régner.
!>
!>              CHPEVX calcule des valeurs propres sélectionnées et, optionnellement,
!>              les vecteurs propres d'une matrice hermitienne complexe en stockage compact.
!>
!>              CHBEVD calcule toutes les valeurs propres et, optionnellement,
!>              les vecteurs propres d'une matrice hermitienne complexe par bandes,
!>              en utilisant un algorithme de type diviser pour mieux régner.
!>
!>              CHBEVX calcule des valeurs propres sélectionnées et, optionnellement,
!>              les vecteurs propres d'une matrice hermitienne complexe par bandes.
!>
!>              CHEEV calcule toutes les valeurs propres et, optionnellement,
!>              les vecteurs propres d'une matrice hermitienne complexe.
!>
!>              CHPEV calcule toutes les valeurs propres et, optionnellement,
!>              les vecteurs propres d'une matrice hermitienne complexe en stockage compact.
!>
!>              CHBEV calcule toutes les valeurs propres et, optionnellement,
!>              les vecteurs propres d'une matrice hermitienne complexe par bandes.
!>
!>      Lorsque CDRVST est appelé, un nombre de tailles de matrices et un
!>      nombre de types de matrices sont spécifiés. Pour chaque taille
!>      et chaque type de matrice, une matrice sera générée et utilisée
!>      pour tester les pilotes appropriés. Pour chaque matrice et chaque
!>      routine pilote appelée, les tests suivants seront effectués :
!>
!>      (1)     | A - Z D Z' | / ( |A| n ulp )
!>
!>      (2)     | I - Z Z' | / ( n ulp )
!>
!>      (3)     | D1 - D2 | / ( |D1| ulp )
!>
!>      où Z est la matrice des vecteurs propres retournée lorsque
!>      l'option vecteurs propres est donnée et D1 et D2 sont les valeurs propres
!>      retournées avec et sans l'option vecteurs propres.
!>
!>      Les tailles sont spécifiées par un tableau NN(1:NSIZES) ; la valeur de
!>      chaque élément NN(j) spécifie une taille.
!>      Les types sont spécifiés par un tableau logique DOTYPE( 1:NTYPES ) ;
!>      si DOTYPE(j) est .TRUE., alors le type de matrice j sera généré.
!>      Actuellement, la liste des types possibles est :
!>
!>      (1)  La matrice nulle.
!>      (2)  La matrice identité.
!>
!>      (3)  Une matrice diagonale à entrées uniformément espacées
!>           1, ..., ULP et signes aléatoires.
!>           (ULP = (premier nombre plus grand que 1) - 1 )
!>      (4)  Une matrice diagonale à entrées géométriquement espacées
!>           1, ..., ULP et signes aléatoires.
!>      (5)  Une matrice diagonale à entrées 1, ULP, ..., ULP
!>           et signes aléatoires.
!>
!>      (6)  Identique à (4), mais multipliée par SQRT( seuil de débordement )
!>      (7)  Identique à (4), mais multipliée par SQRT( seuil de dépassement négatif )
!>
!>      (8)  Une matrice de la forme  U* D U, où U est unitaire et
!>           D a des entrées uniformément espacées 1, ..., ULP avec des signes
!>           aléatoires sur la diagonale.
!>
!>      (9)  Une matrice de la forme  U* D U, où U est unitaire et
!>           D a des entrées géométriquement espacées 1, ..., ULP avec des signes
!>           aléatoires sur la diagonale.
!>
!>      (10) Une matrice de la forme  U* D U, où U est unitaire et
!>           D a des entrées 1, ULP,..., ULP avec des signes
!>           aléatoires sur la diagonale.
!>
!>      (11) Identique à (8), mais multipliée par SQRT( seuil de débordement )
!>      (12) Identique à (8), mais multipliée par SQRT( seuil de dépassement négatif )
!>
!>      (13) Matrice symétrique à entrées aléatoires choisies dans (-1,1).
!>      (14) Identique à (13), mais multipliée par SQRT( seuil de débordement )
!>      (15) Identique à (13), mais multipliée par SQRT( seuil de dépassement négatif )
!>      (16) Une matrice par bandes dont la demi-largeur de bande est choisie aléatoirement entre
!>           0 et N-1, avec des valeurs propres uniformément espacées 1, ..., ULP
!>           et des signes aléatoires.
!>      (17) Identique à (16), mais multipliée par SQRT( seuil de débordement )
!>      (18) Identique à (16), mais multipliée par SQRT( seuil de dépassement négatif )
!> 
!>  NSIZES  INTEGER
!>          Le nombre de tailles de matrices à utiliser. S'il est zéro,
!>          CDRVST ne fait rien. Il doit être au moins zéro.
!>          Non modifié.
!>
!>  NN      tableau INTEGER, dimension (NSIZES)
!>          Un tableau contenant les tailles à utiliser pour les matrices.
!>          Les valeurs nulles seront ignorées. Les valeurs doivent être au moins
!>          zéro.
!>          Non modifié.
!>
!>  NTYPES  INTEGER
!>          Le nombre d'éléments dans DOTYPE. S'il est zéro, CDRVST
!>          ne fait rien. Il doit être au moins zéro. S'il vaut MAXTYP+1
!>          et que NSIZES vaut 1, alors un type supplémentaire, MAXTYP+1, est
!>          défini, qui consiste à utiliser la matrice présente dans A. Cela
!>          n'est utile que si DOTYPE(1:MAXTYP) est .FALSE. et
!>          DOTYPE(MAXTYP+1) est .TRUE. .
!>          Non modifié.
!>
!>  DOTYPE  tableau LOGICAL, dimension (NTYPES)
!>          Si DOTYPE(j) est .TRUE., alors pour chaque taille dans NN, une
!>          matrice de cette taille et de type j sera générée.
!>          Si NTYPES est plus petit que le nombre maximal de types
!>          défini (PARAMETER MAXTYP), alors les types NTYPES+1 à
!>          MAXTYP ne seront pas générés. Si NTYPES est plus grand
!>          que MAXTYP, DOTYPE(MAXTYP+1) à DOTYPE(NTYPES)
!>          seront ignorés.
!>          Non modifié.
!>
!>  ISEED   tableau INTEGER, dimension (4)
!>          À l'entrée, ISEED spécifie la graine du générateur de nombres
!>          aléatoires. Les éléments du tableau doivent être compris entre 0 et 4095 ;
!>          sinon, ils seront réduits modulo 4096. De plus, ISEED(4) doit
!>          être impair. Le générateur de nombres aléatoires utilise une suite
!>          linéaire congruentielle limitée à de petits entiers, et doit donc
!>          produire des nombres aléatoires indépendants de la machine. Les
!>          valeurs de ISEED sont modifiées à la sortie, et peuvent être utilisées dans le
!>          prochain appel à CDRVST pour continuer la même suite de nombres aléatoires.r
!>          séquence.
!>          Modifié.
!>
!>  THRESH  REAL
!>          Un test sera considéré comme réussi si , calculé comme
!>          décrit ci-dessus, dépasse THRESH. Notez que l'erreur
!>          est mise à l'échelle pour être O(1), donc THRESH devrait être un multiple
!>          raisonnablement petit de 1, p. ex., 10 ou 100. En particulier,
!>          il ne doit pas dépendre de la précision (simple vs. double)
!>          ni de la taille de la matrice. Il doit être au moins zéro.
!>          Non modifié.
!>
!>  NOUNIT  INTEGER
!>          Le numéro d'unité FORTRAN pour l'impression des messages d'erreur
!>          (p. ex., si une routine retourne IINFO différent de 0.)
!>          Non modifié.
!>
!>  A       COMPLEX array, dimension (LDA , max(NN))
!>          Utilisé pour stocker la matrice dont les valeurs propres doivent être
!>          calculées. À la sortie, A contient la dernière matrice réellement
!>          utilisée.
!>          Modifié.
!>
!>  LDA     INTEGER
!>          La dimension principale de A. Elle doit être au
!>          moins 1 et au moins max( NN ).
!>          Non modifié.
!>
!>  D1      REAL array, dimension (max(NN))
!>          Les valeurs propres de A, telles que calculées par CSTEQR simultanément
!>          avec Z. À la sortie, les valeurs propres dans D1 correspondent à la
!>          matrice dans A.
!>          Modifié.
!>
!>  D2      REAL array, dimension (max(NN))
!>          Les valeurs propres de A, telles que calculées par CSTEQR si Z n'est pas
!>          calculé. À la sortie, les valeurs propres dans D2 correspondent à
!>          la matrice dans A.
!>          Modifié.
!>
!>  D3      REAL array, dimension (max(NN))
!>          Les valeurs propres de A, telles que calculées par SSTERF. À la sortie, les
!>          valeurs propres dans D3 correspondent à la matrice dans A.
!>          Modifié.
!>
!>  WA1     REAL array, dimension
!>
!>  WA2     REAL array, dimension
!>
!>  WA3     REAL array, dimension
!>
!>  U       COMPLEX array, dimension (LDU, max(NN))
!>          La matrice unitaire calculée par CHETRD + CUNGC3.
!>          Modifié.
!>
!>  LDU     INTEGER
!>          La dimension principale de U, Z et V. Elle doit être au
!>          moins 1 et au moins max( NN ).
!>          Non modifié.
!>
!>  V       COMPLEX array, dimension (LDU, max(NN))
!>          Les vecteurs de Householder calculés par CHETRD en réduisant A à
!>          la forme tridiagonale.
!>          Modifié.
!>
!>  TAU     COMPLEX array, dimension (max(NN))
!>          Les facteurs de Householder calculés par CHETRD en réduisant A
!>          à la forme tridiagonale.
!>          Modifié.
!>
!>  Z       COMPLEX array, dimension (LDU, max(NN))
!>          La matrice unitaire des vecteurs propres calculée par CHEEVD,
!>          CHEEVX, CHPEVD, CHPEVX, CHBEVD, et CHBEVX.
!>          Modifié.
!>
!>  WORK  - COMPLEX array of dimension ( LWORK )
!>           Espace de travail.
!>           Modifié.
!>
!>  LWORK - INTEGER
!>           Le nombre d'entrées dans WORK. Cela doit être au moins
!>           2*max( NN(j), 2 )**2.
!>           Non modifié.
!>
!>  RWORK   REAL array, dimension (3*max(NN))
!>           Espace de travail.
!>           Modifié.
!>
!>  LRWORK - INTEGER
!>           Le nombre d'entrées dans RWORK.
!>
!>  IWORK   INTEGER array, dimension (6*max(NN))
!>          Espace de travail.
!>          Modifié.
!>
!>  LIWORK - INTEGER
!>           Le nombre d'entrées dans IWORK.
!>
!>  RESULT  REAL array, dimension (??)
!>          Les valeurs calculées par les tests décrits ci-dessus.
!>          Les valeurs sont actuellement limitées à 1/ulp, pour éviter
!>          le débordement.
!>          Modifié.
!>
!>  INFO    INTEGER
!>          Si 0, tout s'est bien passé.
!>           -1: NSIZES < 0
!>           -2: Certains NN(j) < 0
!>           -3: NTYPES < 0
!>           -5: THRESH < 0
!>           -9: LDA < 1 ou LDA < NMAX, où NMAX est max( NN(j) ).
!>          -16: LDU < 1 ou LDU < NMAX.
!>          -21: LWORK trop petit.
!>          Si  SLATMR, SLATMS, CHETRD, SORGC3, CSTEQR, SSTERF,
!>              ou SORMC2 retourne un code d'erreur, la
!>              valeur absolue de celui-ci est retournée.
!>          Modifié.
!>
!>-----------------------------------------------------------------------
!>
!>       Quelques variables et paramètres locaux :
!>       ---- ----- --------- --- ----------
!>       ZERO, ONE       Réels 0 et 1.
!>       MAXTYP          Le nombre de types définis.
!>       NTEST           Le nombre de tests effectués, ou qui peuvent
!>                       être effectués jusqu'ici, pour la matrice courante.
!>       NTESTT          Le nombre total de tests effectués jusqu'ici.
!>       NMAX            La plus grande valeur dans NN.
!>       NMATS           Le nombre de matrices générées jusqu'ici.
!>       NERRS           Le nombre de tests qui ont dépassé THRESH
!>                       jusqu'ici (calculé par SLAFTS).
!>       COND, IMODE     Valeurs à passer aux générateurs de matrices.
!>       ANORM           Norme de A ; passée aux générateurs de matrices.
!>
!>       OVFL, UNFL      Seuils de débordement et de sous-flux.
!>       ULP, ULPINV     Précision relative la plus fine et son inverse.
!>       RTOVFL, RTUNFL  Racines carrées des 2 valeurs précédentes.
!>               Les quatre tableaux suivants décodent JTYPE :
!>       KTYPE(j)        Le type général (1-10) pour le type .
!>       KMODE(j)        La valeur MODE à passer au générateur de
!>                       matrices pour le type .
!>       KMAGN(j)        L'ordre de grandeur ( O(1),
!>                       O(overflow^(1/2) ), O(underflow^(1/2) )
!
