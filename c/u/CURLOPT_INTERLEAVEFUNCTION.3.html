CURLOPT_INTERLEAVEFUNCTION(3) Manuel de la bibliothèque CURLOPT_INTERLEAVEFUNCTION(3)

NOM

CURLOPT_INTERLEAVEFUNCTION - fonction de rappel pour les données entrelacées RTSP

SYNTAXE

#include <curl/curl.h>
size_t interleave_callback(void *ptr, size_t size, size_t nmemb,
                           void *userdata);
CURLcode curl_easy_setopt(CURL *handle, CURLOPT_INTERLEAVEFUNCTION,
                          interleave_callback);

DESCRIPTION

Passez un pointeur vers votre fonction de rappel, qui doit correspondre au prototype montré ci-dessus.

Cette fonction de rappel est appelée par libcurl dès qu'elle a reçu des données RTP entrelacées. Cette fonction est appelée pour chaque bloc de Données, et contient donc une unité de protocole de couche supérieure (par exemple, un paquet RTP) par appel. Curl écrit l'en-tête entrelacé ainsi que les données incluses pour chaque appel. Le premier octet est toujours un signe dollar ASCII. Le signe dollar est suivi d'un identifiant de canal sur un octet et d'une longueur sur 2 octets en ordre d'octets réseau. Voir la RFC 2326 Section 10.12 pour plus d'informations sur le comportement de l'entrelacement RTP. Si elle n'est pas définie ou définie à NULL, curl utilise la fonction d'écriture par défaut.

L'entrelacement RTP pose certains défis à l'application cliente. Étant donné que les données du flux partagent la connexion de contrôle RTSP, il est essentiel de gérer le RTP en temps opportun. Si les données RTP ne sont pas traitées rapidement, le traitement des réponses ultérieures peut être déraisonnablement retardé et la connexion peut se fermer. L'application peut utiliser CURL_RTSPREQ_RECEIVE pour traiter les données RTP lorsqu'aucune requête n'est souhaitée. Si l'application effectue une requête (par exemple, CURL_RTSPREQ_PAUSE), le gestionnaire de réponse traite toutes les données RTP en attente avant de marquer la requête comme terminée.

Le CURLOPT_INTERLEAVEDATA(3) est passé dans l'argument userdata de la fonction de rappel.

Votre fonction de rappel doit retourner le nombre d'octets réellement traités. Si ce nombre diffère de celui passé à votre fonction de rappel, cela signale une condition d'erreur à la bibliothèque. Cela provoque l'abandon du transfert et la fonction libcurl utilisée retourne CURLE_WRITE_ERROR.

Vous pouvez également abandonner le transfert en retournant CURL_WRITEFUNC_ERROR. (7.87.0)

PAR DÉFAUT

NULL, les données entrelacées sont alors passées à la fonction d'écriture régulière : CURLOPT_WRITEFUNCTION(3).

PROTOCOLES

Cette fonctionnalité affecte uniquement rtsp

EXEMPLE

struct local {
  void *custom;
};
static size_t rtp_write(void *ptr, size_t size, size_t nmemb, void *userp)
{
  struct local *l = userp;
  printf("notre ptr: %p\n", l->custom);
  /* traitez le paquet dans 'ptr', puis retournez... */
  return size * nmemb;
}
int main(void)
{
  struct local rtp_data;
  CURL *curl = curl_easy_init();
  if(curl) {
    curl_easy_setopt(curl, CURLOPT_INTERLEAVEFUNCTION, rtp_write);
    curl_easy_setopt(curl, CURLOPT_INTERLEAVEDATA, &rtp_data);
  }
}

DISPONIBILITE

Ajouté dans curl 7.20.0

VALEUR DE RETOUR

curl_easy_setopt(3) retourne un code CURLcode indiquant le succès ou l'erreur.

CURLE_OK (0) signifie que tout s'est bien passé, une valeur non nulle indique qu'une erreur s'est produite, voir libcurl-errors(3).
