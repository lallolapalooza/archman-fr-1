CURLOPT_HTTP_VERSION(3)

Paquet: curl

Licences: MIT

CURLOPT_HTTP_VERSION(3) Manuel de fonctions de bibliothèque CURLOPT_HTTP_VERSION(3)

NOM

CURLOPT_HTTP_VERSION - Version du protocole HTTP à utiliser

SYNTAXE

#include <curl/curl.h>
CURLcode curl_easy_setopt(CURL *handle, CURLOPT_HTTP_VERSION, long version);

DESCRIPTION

Passez version un long, défini sur l'une des valeurs décrites ci-dessous. Elles demandent à libcurl d'utiliser les versions HTTP spécifiques.

Notez que la version HTTP n'est qu'une requête. libcurl priorise toujours la réutilisation des connexions existantes, il pourrait donc réutiliser une connexion utilisant une version HTTP que vous n'avez pas demandée.

CURL_HTTP_VERSION_NONE
Peu importe la version que la bibliothèque utilise. libcurl utilise ce qu'il juge approprié.
CURL_HTTP_VERSION_1_0
Forcer les requêtes HTTP 1.0.
CURL_HTTP_VERSION_1_1
Forcer les requêtes HTTP 1.1.
CURL_HTTP_VERSION_2_0
Tenter des requêtes HTTP 2. libcurl revient à HTTP 1.1 si HTTP 2 ne peut pas être négocié avec le serveur.

Lorsque libcurl utilise HTTP/2 sur HTTPS, il n'exige pas lui-même TLS 1.2 ou supérieur, même si cela est requis par la spécification. Un utilisateur peut ajouter cette exigence de version avec CURLOPT_SSLVERSION(3).

L'alias CURL_HTTP_VERSION_2 a été ajouté pour mieux refléter le nom du protocole réel.

CURL_HTTP_VERSION_2TLS
Tenter HTTP 2 sur TLS (HTTPS) uniquement. libcurl revient à HTTP 1.1 si HTTP 2 ne peut pas être négocié avec le serveur HTTPS. Pour les serveurs HTTP en clair, libcurl utilise 1.1.
CURL_HTTP_VERSION_2_PRIOR_KNOWLEDGE
Émettre des requêtes HTTP non TLS utilisant HTTP/2 sans mise à niveau HTTP/1.1. Cela nécessite une connaissance préalable que le serveur prend en charge HTTP/2 immédiatement. Les requêtes HTTPS utilisent toujours HTTP/2 de manière standard avec la version du protocole négociée dans la négociation TLS.

Depuis la version 8.10.0, si cette option est définie pour une requête HTTPS, le protocole de niveau application (ALPN) proposé au serveur est uniquement HTTP/2. Avant cela, HTTP/1.1 et HTTP/2 étaient proposés.

CURL_HTTP_VERSION_3
(Ajouté en 7.66.0) Cette option permet à libcurl de tenter d'utiliser HTTP/3 sur l'hôte spécifié dans l'URL, avec un repli vers les versions HTTP antérieures si nécessaire.
CURL_HTTP_VERSION_3ONLY
(Ajouté en 7.88.0) Définir ceci permet à libcurl de tenter d'utiliser HTTP/3 directement sur le serveur spécifié dans l'URL et ne rétrograde pas vers une version HTTP antérieure si le serveur ne prend pas en charge HTTP/3.

PAR DÉFAUT

Depuis curl 8.13.0 : CURL_HTTP_VERSION_NONE

Depuis curl 7.62.0 : CURL_HTTP_VERSION_2TLS

Avant cela : CURL_HTTP_VERSION_1_1

PROTOCOLES

Cette fonctionnalité affecte uniquement http

EXEMPLE

int main(void)
{
  CURL *curl = curl_easy_init();
  if(curl) {
    CURLcode ret;
    curl_easy_setopt(curl, CURLOPT_URL, "https://example.com/");
    curl_easy_setopt(curl, CURLOPT_HTTP_VERSION, CURL_HTTP_VERSION_2TLS);
    ret = curl_easy_perform(curl);
    if(ret == CURLE_HTTP_RETURNED_ERROR) {
      /* un problème d'erreur de réponse HTTP */
    }
  }
}

HISTORIQUE

Les énumérations CURL_HTTP_VERSION_* sont devenues des types long en 8.13.0, avant cette version, un cast long était nécessaire lorsqu'ils étaient passés à curl_easy_setopt(3).

DISPONIBILITÉ

Ajouté dans curl 7.9.1

VALEUR DE RETOUR

curl_easy_setopt(3) renvoie un CURLcode indiquant le succès ou l'erreur.

CURLE_OK (0) signifie que tout s'est bien passé, une valeur non nulle indique une erreur, voir libcurl-errors(3).

VOIR AUSSI
