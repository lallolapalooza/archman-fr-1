curl_multi_poll(3)

Paquet: curl

Licences: MIT

curl_multi_poll(3) Manuel des fonctions de bibliothèque curl_multi_poll(3)

NOM

curl_multi_poll - sonder tous les descripteurs faciles dans un descripteur multiple

SYNTAXE

#include <curl/curl.h>
CURLMcode curl_multi_poll(CURLM *multi_handle,
                          struct curl_waitfd extra_fds[],
                          unsigned int extra_nfds,
                          int timeout_ms,
                          int *numfds);

DESCRIPTION

curl_multi_poll(3) sonde tous les descripteurs de fichiers utilisés par les descripteurs faciles de curl contenus dans l'ensemble du descripteur multiple donné. Il bloque jusqu'à ce qu'une activité soit détectée sur au moins un des descripteurs ou que timeout_ms soit écoulé. Alternativement, si le descripteur multiple a un délai d'attente interne en attente dont l'expiration est plus courte que timeout_ms, ce temps plus court est utilisé à la place pour garantir une précision raisonnable du délai d'attente.

L'application appelante peut passer des structures curl_waitfd supplémentaires qui sont similaires à la structure pollfd de poll(2) à attendre lors du même appel.

À la fin, si numfds n'est pas NULL, il est rempli avec le nombre total de descripteurs de fichiers sur lesquels des événements intéressants se sont produits. Ce nombre peut inclure à la fois les descripteurs internes de libcurl ainsi que les descripteurs fournis dans extra_fds.

La fonction curl_multi_wakeup(3) peut être utilisée depuis un autre thread pour réveiller cette fonction et retourner plus rapidement. C'est l'un des détails qui distingue cette fonction de curl_multi_wait(3) qui ne peut pas être réveillée de cette manière.

Si aucun descripteur de fichier supplémentaire n'est fourni et que libcurl n'a aucun descripteur de fichier à proposer pour l'attente, cette fonction attend pendant timeout_ms millisecondes (ou moins si une minuterie interne l'indique). C'est l'autre détail qui distingue cette fonction de curl_multi_wait(3).

Il est recommandé d'utiliser cette fonction au lieu de select(3) lors de l'utilisation de l'interface multiple pour permettre aux applications de contourner plus facilement le problème courant de 1024 descripteurs de fichiers maximum.

curl_waitfd

struct curl_waitfd {
  curl_socket_t fd;
  short events;
  short revents;
};
CURL_WAIT_POLLIN
Indicateur de bit pour curl_waitfd.events indiquant que le socket doit sonder les événements de lecture tels que les nouvelles données reçues.
CURL_WAIT_POLLPRI
Indicateur de bit pour curl_waitfd.events indiquant que le socket doit sonder les événements de lecture à haute priorité tels que les données hors bande.
CURL_WAIT_POLLOUT
Indicateur de bit pour curl_waitfd.events indiquant que le socket doit sonder les événements d'écriture tels que le socket est prêt à écrire sans bloquer.

PROTOCOLES

Cette fonctionnalité affecte tous les protocoles pris en charge

EXEMPLE

extern void handle_fd(int);
int main(void)
{
  CURL *easy_handle;
  CURLM *multi_handle;
  int still_running = 0;
  int myfd = 2; /* c'est notre propre descripteur de fichier */
  multi_handle = curl_multi_init();
  easy_handle = curl_easy_init();
  /* ajouter le descripteur facile individuel */
  curl_multi_add_handle(multi_handle, easy_handle);
  do {
    CURLMcode mc;
    int numfds;
    mc = curl_multi_perform(multi_handle, &still_running);
    if(mc == CURLM_OK) {
      struct curl_waitfd myown;
      myown.fd = myfd;
      myown.events = CURL_WAIT_POLLIN; /* attendre l'entrée */
      myown.revents = 0; /* l'effacer */
      /* attendre l'activité sur les descripteurs de curl ou sur le nôtre,
         ou le délai d'attente */
      mc = curl_multi_poll(multi_handle, &myown, 1, 1000, &numfds);
      if(myown.revents) {
        /* notre descripteur a-t-il reçu un événement ? */
        handle_fd(myfd);
      }
    }
    if(mc != CURLM_OK) {
      fprintf(stderr, "curl_multi a échoué, code %d.\n", mc);
      break;
    }
  } while(still_running);
  curl_multi_remove_handle(multi_handle, easy_handle);
}

DISPONIBILITE

Ajouté dans curl 7.66.0

VALEUR DE RETOUR

Cette fonction retourne un CURLMcode indiquant le succès ou l'erreur.

CURLM_OK (0) signifie que tout était correct, une valeur non nulle indique une erreur, voir libcurl-errors(3).
