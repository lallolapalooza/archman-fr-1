CURLOPT_CONNECT_TO(3)

Paquet: curl

Licences: MIT

CURLOPT_CONNECT_TO(3) Manuel des fonctions de bibliothèque CURLOPT_CONNECT_TO(3)

NOM

CURLOPT_CONNECT_TO - se connecter à un autre hôte et port à la place

SYNTAXE

#include <curl/curl.h>
CURLcode curl_easy_setopt(CURL *handle, CURLOPT_CONNECT_TO,
                          struct curl_slist *connect_to);

DESCRIPTION

Passez un pointeur vers une liste chaînée de chaînes avec des informations "connect to" à utiliser pour établir des connexions réseau avec ce handle. La liste chaînée doit être une liste entièrement valide de structures struct curl_slist correctement remplies. Utilisez curl_slist_append(3) pour créer la liste et curl_slist_free_all(3) pour nettoyer une liste entière.

Chaque chaîne individuelle doit être écrite en utilisant le format HÔTE:PORT:HÔTE-DE-CONNEXION:PORT-DE-CONNEXION où HÔTE est l'hôte de la requête, PORT est le port de la requête, HÔTE-DE-CONNEXION est le nom d'hôte auquel se connecter, et PORT-DE-CONNEXION est le port auquel se connecter.

La première chaîne qui correspond à l'hôte et au port de la requête est utilisée.

Les adresses IP numériques pointées sont supportées pour HÔTE et HÔTE-DE-CONNEXION. Une adresse IPv6 numérique doit être écrite entre [crochets].

N'importe laquelle des quatre valeurs peut être vide. Lorsque HÔTE ou PORT est vide, l'hôte ou le port correspondent toujours (l'hôte ou le port de la requête est ignoré). Lorsque HÔTE-DE-CONNEXION ou PORT-DE-CONNEXION est vide, la fonctionnalité "connect to" est désactivée pour l'hôte ou le port, et l'hôte ou le port de la requête sont utilisés pour établir la connexion réseau.

Cette option est appropriée pour diriger la requête vers un serveur spécifique, par exemple vers un nœud de cluster spécifique dans un cluster de serveurs.

L'hôte et le port "connect to" sont uniquement utilisés pour établir la connexion réseau. Ils n'affectent PAS l'hôte et le port utilisés pour TLS/SSL (par exemple, SNI, vérification de certificat) ou pour les protocoles applicatifs.

Contrairement à CURLOPT_RESOLVE(3), l'option CURLOPT_CONNECT_TO(3) ne pré-remplit pas le cache DNS et n'affecte donc pas les transferts futurs d'autres handles easy qui ont été ajoutés au même handle multi.

L'hôte et le port "connect to" sont ignorés s'ils sont identiques à l'hôte et au port de l'URL de la requête, car se connecter à l'hôte et au port de l'URL de la requête est le comportement par défaut.

Si un proxy HTTP est utilisé pour une requête ayant un hôte ou un port "connect to" spécial, et que l'hôte ou le port "connect to" diffère de l'hôte et du port de la requête, le proxy HTTP est automatiquement basculé en mode tunnel pour cette requête spécifique. Ceci est nécessaire car il n'est pas possible de se connecter à un hôte ou un port spécifique en mode normal (non-tunnel).

Lorsque cette option est passée à curl_easy_setopt(3), libcurl ne copie pas la liste, vous devez donc la conserver jusqu'à ce que vous n'utilisiez plus ce handle pour un transfert avant d'appeler curl_slist_free_all(3) sur la liste.

L'utilisation de cette option plusieurs fois fait que la dernière liste définie remplace les précédentes. Définissez-la à NULL pour désactiver son utilisation à nouveau.

DÉFAUT

NULL

PROTOCOLES

Cette fonctionnalité affecte tous les protocoles supportés

EXEMPLE

int main(void)
{
  CURL *curl;
  struct curl_slist *connect_to = NULL;
  connect_to = curl_slist_append(NULL, "example.com::server1.example.com:");
  curl = curl_easy_init();
  if(curl) {
    curl_easy_setopt(curl, CURLOPT_CONNECT_TO, connect_to);
    curl_easy_setopt(curl, CURLOPT_URL, "https://example.com");
    curl_easy_perform(curl);
    /* toujours nettoyer */
    curl_easy_cleanup(curl);
  }
  curl_slist_free_all(connect_to);
}

DISPONIBILITÉ

Ajouté dans curl 7.49.0

VALEUR DE RETOUR

curl_easy_setopt(3) renvoie un CURLcode indiquant succès ou erreur.

CURLE_OK (0) signifie que tout s'est bien passé, non-zéro indique une erreur, voir libcurl-errors(3).
