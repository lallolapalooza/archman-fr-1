Paquet: curl

Licences: MIT

CURLOPT_ACCEPT_ENCODING(3) Manuel des fonctions de bibliothèque CURLOPT_ACCEPT_ENCODING(3)

NOM

CURLOPT_ACCEPT_ENCODING - décompression automatique des téléchargements HTTP

SYNTAXE

#include <curl/curl.h>
CURLcode curl_easy_setopt(CURL *handle, CURLOPT_ACCEPT_ENCODING, char *enc);

DESCRIPTION

Passe un pointeur de caractère en argument spécifiant le type de codage souhaité.

Définit le contenu de l'en-tête Accept-Encoding: envoyé dans une requête HTTP et active le décodage d'une réponse lorsqu'un en-tête Content-Encoding: est reçu.

libcurl prend potentiellement en charge plusieurs algorithmes de compression différents en fonction du support intégré.

Pour éviter aux applications de se soucier des algorithmes spécifiques pris en charge par cette version de libcurl, libcurl permet de définir une chaîne de caractères de longueur nulle ("") pour demander l'utilisation d'un en-tête Accept-Encoding: contenant tous les codages pris en charge intégrés.

Alternativement, vous pouvez spécifier exactement le codage ou la liste des codages que vous souhaitez dans la réponse. Les codages suivants sont pris en charge : identity, qui signifie non compressé, deflate qui demande au serveur de compresser sa réponse en utilisant l'algorithme zlib, gzip qui demande l'algorithme gzip, (depuis curl 7.57.0) br qui est brotli et (depuis curl 7.72.0) zstd qui est zstd. Fournissez-les dans la chaîne sous forme de liste séparée par des virgules de codages acceptés, comme suit : "br, gzip, deflate".

Définissez CURLOPT_ACCEPT_ENCODING(3) sur NULL pour le désactiver explicitement, ce qui empêche libcurl d'envoyer un en-tête Accept-Encoding: et de décompresser automatiquement les contenus reçus.

Vous pouvez également choisir d'inclure uniquement l'en-tête Accept-Encoding: dans votre requête avec CURLOPT_HTTPHEADER(3), mais il n'y aura alors pas de décompression automatique lors de la réception des données.

Ceci est une requête, pas un ordre ; le serveur peut ou non le faire. Cette option doit être définie (à n'importe quelle valeur non NULL) sinon toute compression non sollicitée effectuée par le serveur sera ignorée.

Les serveurs peuvent répondre avec Content-Encoding même sans recevoir de Accept-Encoding: dans la requête. Les serveurs peuvent répondre avec un Content-Encoding différent de celui demandé dans la requête.

La Content-Length: envoyée par les serveurs pour une réponse compressée est censée indiquer la longueur du contenu compressé. Ainsi, lorsque la décompression automatique est activée, elle peut ne pas correspondre à la somme des octets rapportés par les rappels d'écriture (bien que l'envoi de la longueur du contenu non compressé soit une erreur courante des serveurs).

L'application n'a pas à conserver la chaîne après avoir défini cette option.

L'utilisation de cette option plusieurs fois fait que la dernière chaîne définie écrase les précédentes.

HISTORIQUE

Cette option s'appelait CURLOPT_ENCODING avant la version 7.21.6.

NOTES

La version spécifique de libcurl que vous utilisez doit avoir été compilée avec zlib pour pouvoir décompresser les réponses gzip et deflate, avec la bibliothèque brotli pour décompresser les réponses brotli, et avec la bibliothèque zstd pour décompresser les réponses zstd.

DÉFAUT

NULL

PROTOCOLES

Cette fonctionnalité affecte uniquement http.

EXEMPLE

int main(void)
{
  CURL *curl = curl_easy_init();
  if(curl) {
    curl_easy_setopt(curl, CURLOPT_URL, "https://example.com");
    /* activer toutes les compressions intégrées prises en charge */
    curl_easy_setopt(curl, CURLOPT_ACCEPT_ENCODING, "");
    /* Effectuer la requête */
    curl_easy_perform(curl);
  }
}

DISPONIBILITÉ

Ajouté dans curl 7.21.6

VALEUR DE RETOUR

curl_easy_setopt(3) renvoie un CURLcode indiquant le succès ou l'erreur.

CURLE_OK (0) signifie que tout s'est bien passé, une valeur non nulle indique qu'une erreur s'est produite, voir libcurl-errors(3).

VOIR AUSSI
