CURLOPT_HEADERFUNCTION(3)

Paquet: curl

Licences: MIT

CURLOPT_HEADERFUNCTION(3) Manuel des fonctions de bibliothèque CURLOPT_HEADERFUNCTION(3)

NOM

CURLOPT_HEADERFUNCTION - callback qui reçoit les données d'en-tête

SYNOPSIS

#include <curl/curl.h>
size_t header_callback(char *buffer,
                       size_t size,
                       size_t nitems,
                       void *userdata);
CURLcode curl_easy_setopt(CURL *handle, CURLOPT_HEADERFUNCTION,
                          header_callback);

DESCRIPTION

Passez un pointeur vers votre fonction de rappel, qui doit correspondre au prototype indiqué ci-dessus.

Cette fonction de rappel est appelée par libcurl dès qu'elle a reçu des données d'en-tête. Le rappel d'en-tête est appelé une fois pour chaque en-tête et seules les lignes d'en-tête complètes sont transmises au rappel. L'analyse des en-têtes est facile à faire en utilisant ce rappel. buffer pointe vers les données livrées, et la taille de ces données est nitems ; size est toujours 1. La ligne d'en-tête fournie n'est pas terminée par null. Ne modifiez pas le tampon passé.

Le pointeur nommé userdata est celui que vous avez défini avec l'option CURLOPT_HEADERDATA(3).

Votre fonction de rappel doit renvoyer le nombre d'octets effectivement traités. Si ce montant diffère du montant passé à votre fonction de rappel, cela signale une condition d'erreur à la bibliothèque. Cela provoque l'interruption du transfert et la fonction libcurl utilisée renvoie CURLE_WRITE_ERROR.

Vous pouvez également annuler le transfert en retournant CURL_WRITEFUNC_ERROR. (7.87.0)

Un en-tête HTTP complet qui est passé à cette fonction peut faire jusqu'à CURL_MAX_HTTP_HEADER (100 Ko) octets et inclut le terminateur de ligne final.

Si cette option n'est pas définie, ou si elle est définie sur NULL, mais que CURLOPT_HEADERDATA(3) est défini sur autre chose que NULL, la fonction utilisée pour accepter les données de réponse est utilisée à la place. C'est la fonction spécifiée avec CURLOPT_WRITEFUNCTION(3), ou si elle n'est pas spécifiée ou est NULL - la fonction par défaut d'écriture en flux.

Il est important de noter que le rappel est invoqué pour les en-têtes de toutes les réponses reçues après l'initiation d'une requête et pas seulement la réponse finale. Cela inclut toutes les réponses qui surviennent pendant la négociation d'authentification. Si vous avez besoin d'opérer uniquement sur les en-têtes de la réponse finale, vous devez collecter les en-têtes dans la fonction de rappel vous-même et utiliser des lignes de statut HTTP, par exemple, pour délimiter les frontières de réponse.

Pour un transfert HTTP, la ligne de statut et la ligne vide précédant le corps de la réponse sont toutes deux incluses comme en-têtes et passées à cette fonction.

Lorsqu'un serveur envoie un transfert codé par morceaux, il peut contenir une bande-annonce. Cette bande-annonce est identique à un en-tête HTTP et si une telle bande-annonce est reçue, elle est également transmise à l'application en utilisant ce rappel. Il existe plusieurs façons de la détecter comme une bande-annonce et non comme un en-tête ordinaire : 1) elle arrive après le corps de la réponse. 2) elle arrive après la ligne d'en-tête finale (CR LF) 3) un en-tête Trailer: parmi les en-têtes de réponse réguliers mentionne quel(s) en-tête(s) attendre dans la bande-annonce.

Pour les protocoles autres que HTTP comme FTP, POP3, IMAP et SMTP, cette fonction est appelée avec les réponses du serveur aux commandes que libcurl envoie.

Une manière plus pratique d'obtenir les en-têtes HTTP pourrait être d'utiliser curl_easy_header(3).

LIMITATIONS

libcurl ne déplie pas les "en-têtes repliés" HTTP (dépréciés depuis RFC 7230). Un en-tête replié est un en-tête qui continue sur une ligne suivante et commence par un espace blanc. Ces replis sont passés au rappel d'en-tête séparément, bien qu'ils soient strictement des continuations des lignes précédentes.

PAR DÉFAUT

Rien.

PROTOCOLES

Cette fonctionnalité affecte ftp, http, imap, pop3 et smtp

EXEMPLE

static size_t header_callback(char *buffer, size_t size,
                              size_t nitems, void *userdata)
{
  /* l'en-tête reçu fait 'nitems' octets dans 'buffer' NON TERMINÉ PAR NULL */
  /* 'userdata' est défini avec CURLOPT_HEADERDATA */
  return nitems;
}
int main(void)
{
  CURL *curl = curl_easy_init();
  if(curl) {
    curl_easy_setopt(curl, CURLOPT_URL, "https://example.com");
    curl_easy_setopt(curl, CURLOPT_HEADERFUNCTION, header_callback);
    curl_easy_perform(curl);
  }
}

DISPONIBILITÉ

Ajouté dans curl 7.7.2

VALEUR DE RETOUR

curl_easy_setopt(3) renvoie un CURLcode indiquant le succès ou l'erreur.

CURLE_OK (0) signifie que tout va bien, une valeur non nulle indique une erreur, voir libcurl-errors(3).

VOIR AUSSI

CURLOPT_HEADERDATA(3), CURLOPT_WRITEFUNCTION(3), curl_easy_header(3)
