Paquet: curl

curl_ws_recv(3) Manuel des fonctions de bibliothèque curl_ws_recv(3)

NOM

curl_ws_recv - recevoir des données WebSocket

SYNTAXE

#include <curl/curl.h>
CURLcode curl_ws_recv(CURL *curl, void *buffer, size_t buflen,
                      size_t *recv, const struct curl_ws_frame **meta);

DESCRIPTION

Récupère autant que possible d'une trame WebSocket reçue dans le buffer, mais pas plus que buflen octets. recv est défini au nombre d'octets réellement stockés.

Si l'appel de fonction réussit, le pointeur meta est défini pour pointer vers une struct curl_ws_frame constante qui contient des informations sur les données reçues. Cette structure ne doit pas être libérée et son contenu ne doit plus être considéré comme fiable une fois qu'une autre fonction WebSocket est appelée. Voir curl_ws_meta(3) pour plus de détails sur cette structure.

L'application doit vérifier meta->bytesleft pour déterminer si la trame complète a été reçue. Si plus de données utiles sont en attente, l'application doit rappeler cette fonction avec un buffer et une buflen mis à jour pour reprendre la réception. Cela peut par exemple se produire lorsque les données ne tiennent pas dans le buffer fourni ou lorsque toutes les données de la trame n'ont pas encore été transmises sur le réseau.

Si l'application souhaite lire les métadonnées sans consommer de données utiles, elle peut appeler cette fonction avec une buflen de zéro. Définir buffer à un pointeur NULL est autorisé dans ce cas. Notez que les trames sans données utiles sont consommées par cette action.

Si le message reçu se compose de plusieurs fragments, le bit CURLWS_CONT est défini dans toutes les trames sauf la dernière. Le flag approprié CURLWS_TEXT ou CURLWS_BINARY est défini dans chaque trame, qu'il s'agisse du premier fragment, d'un fragment intermédiaire ou du fragment final. L'application est responsable de la réassemblage des messages fragmentés. Une attention particulière doit être accordée à la gestion correcte des trames de contrôle (c'est-à-dire CLOSE, PING et PONG) arrivant entre des fragments consécutifs d'un message TEXT ou BINARY fragmenté. Voir curl_ws_meta(3) pour plus de détails sur CURLWS_CONT.

Le protocole WebSocket se compose de messages qui peuvent être transmis sur le fil en une ou plusieurs trames - mais comme une trame peut être trop grande pour être mise en tampon en mémoire, libcurl peut avoir besoin de livrer des trames partielles à l'application. Fragments, ou morceaux, de trames.

PROTOCOLES

Cette fonctionnalité affecte uniquement ws

EXEMPLE

int main(void)
{
  char buffer[256];
  size_t offset = 0;
  CURLcode res = CURLE_OK;
  CURL *curl = curl_easy_init();
  curl_easy_setopt(curl, CURLOPT_URL, "wss://example.com/");
  curl_easy_setopt(curl, CURLOPT_CONNECT_ONLY, 2L);
  /* démarre la connexion HTTPS et passe à WSS, puis retourne le contrôle */
  curl_easy_perform(curl);
  /* Note : Cet exemple néglige les messages fragmentés. (bit CURLWS_CONT)
           Une application réelle doit les gérer de manière appropriée. */
  while(!res) {
    size_t recv;
    const struct curl_ws_frame *meta;
    res = curl_ws_recv(curl, buffer + offset, sizeof(buffer) - offset, &recv,
                       &meta);
    offset += recv;
    if(res == CURLE_OK) {
      if(meta->bytesleft == 0)
        break; /* réception terminée */
      if(meta->bytesleft > sizeof(buffer) - offset)
        res = CURLE_TOO_LARGE;
    }
    if(res == CURLE_AGAIN)
      /* dans une application réelle : attendre le socket ici, par exemple en utilisant select() */
      res = CURLE_OK;
  }
  curl_easy_cleanup(curl);
  return (int)res;
}

DISPONIBILITÉ

Ajouté dans curl 7.86.0

VALEUR DE RETOUR

Cette fonction retourne un CURLcode indiquant le succès ou une erreur.

CURLE_OK (0) signifie que tout s'est bien passé, une valeur non nulle indique une erreur, voir libcurl-errors(3). Si CURLOPT_ERRORBUFFER(3) a été défini avec curl_easy_setopt(3), un message d'erreur peut être stocké dans le tampon d'erreur lorsque la valeur retournée est non nulle.

Retourne CURLE_GOT_NOTHING si la connexion associée est fermée.

Au lieu de bloquer, la fonction retourne CURLE_AGAIN. Le comportement correct est alors d'attendre que le socket signale qu'il est lisible avant de rappeler cette fonction.

Toute autre valeur de retour non nulle indique une erreur. Voir la page de manuel libcurl-errors(3) pour la liste complète avec descriptions.

Retourne CURLE_GOT_NOTHING si la connexion associée est fermée.
