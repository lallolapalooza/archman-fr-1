Paquet: curl

Licences: MIT

CURLOPT_HAPPY_EYEBALLS_TIMEOUT_MS(3) Manuel des fonctions de bibliothèque CURLOPT_HAPPY_EYEBALLS_TIMEOUT_MS(3)

NOM

CURLOPT_HAPPY_EYEBALLS_TIMEOUT_MS - temporisation des tentatives de connexion

SYNTAXE

#include <curl/curl.h>
CURLcode curl_easy_setopt(CURL *handle, CURLOPT_HAPPY_EYEBALLS_TIMEOUT_MS,
                          long timeout);

DESCRIPTION

Happy eyeballs est un algorithme qui contrôle la connexion à un hôte qui se résout en plusieurs adresses IP. Une configuration courante consiste à exposer une adresse IPv4 et une adresse IPv6 (double pile). D'autres hôtes proposent une gamme d'adresses pour une ou deux piles.

Adresses IP
Lorsque curl est compilé avec le support IPv6, il tente d'abord de se connecter en IPv6, lorsque cela est disponible. En cas d'échec, une autre tentative de connexion pour la première adresse IPv4 (là encore, si disponible) est lancée. En cas d'échec, la prochaine adresse IPv6 est utilisée, puis la prochaine IPv4, etc. S'il n'y a que des adresses pour une pile, celles-ci sont essayées l'une après l'autre.

Lorsqu'il n'y a ni réponse positive ni négative à une tentative, une autre tentative est lancée après que timeout se soit écoulé. Puis une autre, après que timeout se soit à nouveau écoulé. Tant qu'il reste des adresses disponibles.

Lorsque toutes les adresses ont été essayées et ont échoué, le transfert échoue. Toutes les tentatives sont abandonnées après que CURLOPT_CONNECTTIMEOUT_MS(3) se soit écoulé, compté à partir de la première tentative.

La plage des valeurs utiles suggérées pour timeout est limitée. Le RFC 6555 de Happy Eyeballs dit : "Il est RECOMMANDÉ que les tentatives de connexion soient espacées de 150 à 250 ms pour équilibrer les facteurs humains et la charge réseau." libcurl utilise actuellement 200 ms par défaut. Firefox et Chrome utilisent actuellement 300 ms par défaut.

Par exemple, pour un hôte qui se résout en 'a1_v4, a2_v4, a3_v6, a4_v6', curl ouvre d'abord un socket vers 'a3_v6'. Lorsque celui-ci ne répond pas, il ouvre un autre socket vers 'a1_v4' après 200 ms. Le premier socket reste ouvert et pourrait encore réussir. Lorsque 200 ms se sont écoulés à nouveau, un socket pour 'a4_v6' est ouvert. 200 ms plus tard, 'a2_v4' est essayé.

À ce stade, 4 sockets sont ouverts (à moins que le réseau n'ait renvoyé quelque chose). Cela a pris 3 fois le délai de happy eyeballs, soit 600 ms dans la configuration par défaut. Lorsque l'un de ces quatre signale un succès, ce socket est utilisé pour le transfert et les trois autres sont fermés.

Il existe des situations où les tentatives de connexion échouent, mais l'échec est considéré comme non concluant. Le protocole QUIC peut rencontrer cela. Lorsqu'un serveur QUIC redémarre, il peut envoyer des réponses indiquant qu'il n'accepte pas les connexions pour le moment, mais peut-être plus tard.

Ces échecs de tentative de connexion "inclusifs" entraînent un redémarrage de la tentative, avec la même adresse sur un nouveau socket, fermant le précédent. Répété jusqu'à ce que CURLOPT_CONNECTTIMEOUT_MS(3) frappe.

HTTPS
Lorsqu'une connexion avec le protocole HTTPS vers un hôte qui peut parler HTTP/3, HTTP/2 ou HTTP/1.1, curl applique une stratégie similaire de happy eyeballs lors de la tentative de ces versions.

Lorsque HTTPS implique uniquement une connexion TCP, les versions sont négociées via ALPN, l'extension TLS, en une seule connexion. Comme HTTP/3 fonctionne sur QUIC (qui fonctionne sur UDP), il nécessite une tentative de connexion distincte.

La tentative HTTP/3 est lancée en premier et, après l'expiration du timeout, la tentative HTTP/2 (ou 1.1) est lancée en parallèle.

DÉFAUT

CURL_HET_DEFAULT (actuellement défini comme 200L)

PROTOCOLES

Cette fonctionnalité affecte tous les protocoles pris en charge

EXEMPLE

int main(void)
{
  CURL *curl = curl_easy_init();
  if(curl) {
    curl_easy_setopt(curl, CURLOPT_URL, "https://example.com");
    curl_easy_setopt(curl, CURLOPT_HAPPY_EYEBALLS_TIMEOUT_MS, 300L);
    curl_easy_perform(curl);
    /* toujours nettoyer */
    curl_easy_cleanup(curl);
  }
}

DISPONIBILITÉ

Ajouté dans curl 7.59.0

VALEUR DE RETOUR

curl_easy_setopt(3) renvoie un CURLcode indiquant le succès ou l'erreur.

CURLE_OK (0) signifie que tout s'est bien passé, une valeur non nulle indique une erreur, voir libcurl-errors(3).
