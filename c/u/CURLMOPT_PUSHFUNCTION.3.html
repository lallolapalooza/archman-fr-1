CURLMOPT_PUSHFUNCTION(3)

Paquet: curl

Licences: MIT

CURLMOPT_PUSHFUNCTION(3) Manuel des fonctions de bibliothèque CURLMOPT_PUSHFUNCTION(3)

NOM

CURLMOPT_PUSHFUNCTION - fonction de rappel qui approuve ou refuse les pushs serveur

SYNTAXE

#include <curl/curl.h>
int curl_push_callback(CURL *parent,
                       CURL *easy,
                       size_t num_headers,
                       struct curl_pushheaders *headers,
                       void *clientp);
CURLMcode curl_multi_setopt(CURLM *handle, CURLMOPT_PUSHFUNCTION,
                            curl_push_callback func);

DESCRIPTION

Cette fonction de rappel est appelée lorsqu'un nouveau flux HTTP/2 est poussé par le serveur (en utilisant le cadre PUSH_PROMISE). Si aucune fonction de rappel de push n'est définie, tous les pushs proposés sont automatiquement refusés.

DESCRIPTION DU RAPPEL

La fonction de rappel reçoit ses arguments comme suit :

parent est le handle du flux sur lequel ce push arrive. Le nouveau handle a été dupliqué à partir du parent, ce qui signifie qu'il a hérité de toutes ses options. Il appartient ensuite à l'application de modifier les options si désiré.

easy est un handle nouvellement créé qui représente ce transfert à venir.

num_headers est le nombre de paires nom+valeur qui ont été reçues et peuvent être accédées.

headers est un handle utilisé pour accéder aux en-têtes de push en utilisant les fonctions d'accès décrites ci-dessous. Ceci accède et ne fournit que les en-têtes PUSH_PROMISE, les en-têtes de réponse normaux sont fournis dans la fonction de rappel d'en-tête comme d'habitude.

clientp est le pointeur défini avec CURLMOPT_PUSHDATA(3)

Si la fonction de rappel renvoie CURL_PUSH_OK, le nouveau handle easy est ajouté au handle multi, la fonction de rappel ne doit pas le faire elle-même.

La fonction de rappel peut accéder aux en-têtes PUSH_PROMISE avec deux fonctions d'accès. Ces fonctions ne peuvent être utilisées qu'à l'intérieur de cette fonction de rappel et ne peuvent accéder qu'aux en-têtes PUSH_PROMISE : curl_pushheader_byname(3) et curl_pushheader_bynum(3). Les en-têtes de réponse normaux sont transmis à la fonction de rappel d'en-tête pour les flux poussés, tout comme pour les flux normaux.

Les champs d'en-tête peuvent également être accédés avec curl_easy_header(3), introduit dans les versions ultérieures de libcurl.

VALEUR DE RETOUR DU RAPPEL

CURL_PUSH_OK (0)
L'application a accepté le flux et il peut maintenant commencer à recevoir des données, la propriété du handle curl a été reprise par l'application.
CURL_PUSH_DENY (1)
La fonction de rappel refuse le flux et aucune donnée n'atteint l'application, le handle easy est détruit par libcurl.
CURL_PUSH_ERROROUT (2)
Le retour de ce code rejette le flux poussé et renvoie une erreur au flux parent, le faisant se fermer avec une erreur. (Ajouté en 7.72.0)
*
Tous les autres codes de retour sont réservés pour une utilisation future.

PAR DÉFAUT

NULL, pas de fonction de rappel

PROTOCOLES

Cette fonctionnalité affecte uniquement http

EXEMPLE

#include <string.h>
/* n'autoriser les pushs que pour les noms de fichiers commençant par "push-" */
int push_callback(CURL *parent,
                  CURL *easy,
                  size_t num_headers,
                  struct curl_pushheaders *headers,
                  void *clientp)
{
  char *headp;
  int *transfers = (int *)clientp;
  FILE *out;
  headp = curl_pushheader_byname(headers, ":path");
  if(headp && !strncmp(headp, "/push-", 6)) {
    fprintf(stderr, "Le PATH est %s\n", headp);
    /* sauvegarder le push ici */
    out = fopen("pushed-stream", "wb");
    /* écrire dans ce fichier */
    curl_easy_setopt(easy, CURLOPT_WRITEDATA, out);
    (*transfers)++; /* un de plus */
    return CURL_PUSH_OK;
  }
  return CURL_PUSH_DENY;
}
int main(void)
{
  int counter;
  CURLM *multi = curl_multi_init();
  curl_multi_setopt(multi, CURLMOPT_PUSHFUNCTION, push_callback);
  curl_multi_setopt(multi, CURLMOPT_PUSHDATA, &counter);
}

DISPONIBILITÉ

Ajouté dans curl 7.44.0

VALEUR DE RETOUR

curl_multi_setopt(3) renvoie un code CURLMcode indiquant le succès ou l'erreur.

CURLM_OK (0) signifie que tout s'est bien passé, une valeur non nulle indique une erreur. Voir libcurl-errors(3).
