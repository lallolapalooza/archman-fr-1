NOM

curl_mime_encoder - définit l'encodeur d'une partie mime et le codage de transfert de contenu

SYNOPSIS

#include <curl/curl.h>
CURLcode curl_mime_encoder(curl_mimepart *part, const char *encoding);

DESCRIPTION

curl_mime_encoder() demande que le contenu d'une partie mime soit encodé avant d'être transmis.

part est le descripteur de la partie auquel attribuer un encodeur. encoding est un pointeur vers un schéma d'encodage se terminant par un caractère nul. Il peut être défini sur NULL pour désactiver un encodeur précédemment attaché à la partie. Le stockage du schéma d'encodage peut être réutilisé en toute sécurité après le retour de cette fonction.

Définir l'encodeur d'une partie plusieurs fois est valide : seule la valeur définie par le dernier appel est conservée.

Lors du rendu multipart, le contenu de la partie est encodé selon le schéma pertinent et un en-tête "Content-Transfer-Encoding" correspondant est ajouté à la partie.

Les schémas d'encodage pris en charge sont :

"binary" : les données sont laissées inchangées, l'en-tête est ajouté.

"8bit" : en-tête ajouté, aucune modification des données.

"7bit" : les données sont inchangées, mais chaque octet est vérifié pour être une valeur 7 bits ; sinon, une erreur de lecture se produit.

"base64" : les données sont converties en encodage base64, puis divisées en lignes terminées par CRLF d'au plus 76 caractères.

"quoted-printable" : les données sont encodées en lignes quoted-printable d'au plus 76 caractères. Comme la taille résultante des données finales ne peut pas être déterminée avant la lecture des données d'origine, elle est laissée inconnue, provoquant un transfert segmenté (chunked) en HTTP. Pour la même raison, cet encodeur ne peut pas être utilisé avec IMAP. Cet encodeur cible les données textuelles qui sont majoritairement en ASCII et ne doit pas être utilisé avec d'autres types de données.

Si les données d'origine sont déjà encodées selon un tel schéma, un en-tête personnalisé Content-Transfer-Encoding doit être ajouté avec curl_mime_headers(3) au lieu de définir un encodeur de partie.

L'encodage ne doit pas être appliqué aux multiparts, ainsi l'utilisation de cette fonction sur une partie dont le contenu est défini avec curl_mime_subparts(3) est fortement déconseillée.

PROTOCOLES

Cette fonctionnalité affecte http, imap et smtp.

EXEMPLE

int main(void)
{
  curl_mime *mime;
  curl_mimepart *part;
  CURL *curl = curl_easy_init();
  if(curl) {
    /* créer un descripteur mime */
    mime = curl_mime_init(curl);
    /* ajouter une partie */
    part = curl_mime_addpart(mime);
    /* envoyer un fichier */
    curl_mime_filedata(part, "image.png");
    /* encoder les données du fichier en base64 pour le transfert */
    curl_mime_encoder(part, "base64");
  }
}

DISPONIBILITÉ

Ajouté dans curl 7.56.0

VALEUR DE RETOUR

Cette fonction retourne un CURLcode indiquant le succès ou une erreur.

CURLE_OK (0) signifie que tout s'est bien passé, une valeur non nulle indique une erreur, voir libcurl-errors(3). Si CURLOPT_ERRORBUFFER(3) a été défini avec curl_easy_setopt(3), un message d'erreur peut être stocké dans le tampon d'erreur lorsque la valeur renvoyée est non nulle.
