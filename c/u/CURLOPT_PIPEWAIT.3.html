CURLOPT_PIPEWAIT(3)

Paquet: curl

Licences: MIT

CURLOPT_PIPEWAIT(3) Manuel des fonctions de bibliothèque CURLOPT_PIPEWAIT(3)

NOM

CURLOPT_PIPEWAIT - attendre le multiplexage

SYNTAXE

#include <curl/curl.h>
CURLcode curl_easy_setopt(CURL *handle, CURLOPT_PIPEWAIT, long wait);

DESCRIPTION

Définissez wait à 1L pour indiquer à libcurl de préférer attendre qu'une connexion confirme ou refuse la possibilité de multiplexage avant de continuer.

Lorsqu'il est sur le point d'effectuer un nouveau transfert qui autorise le multiplexage, libcurl vérifie les connexions existantes à utiliser. Si aucune connexion de ce type n'existe, il continue immédiatement et crée une nouvelle connexion à utiliser.

En définissant cette option à 1 - et en ayant CURLMOPT_PIPELINING(3) activé pour le handle multi auquel ce transfert est associé - libcurl attendra plutôt que la connexion révèle s'il est possible de multiplexer avant de continuer. Cela permet à libcurl de minimiser le nombre de connexions lors de l'utilisation de protocoles de multiplexage.

Avec cette option activée, libcurl préfère attendre et réutiliser une connexion existante pour le multiplexage plutôt que le contraire : préférer ouvrir une nouvelle connexion plutôt que d'attendre.

Le temps d'attente est aussi long qu'il faut pour que la connexion soit établie et que libcurl obtienne la réponse nécessaire l'informant de son protocole et de son niveau de support.

DÉFAUT

0 (désactivé)

PROTOCOLES

Cette fonctionnalité affecte uniquement http

EXEMPLE

int main(void)
{
  CURL *curl = curl_easy_init();
  if(curl) {
    curl_easy_setopt(curl, CURLOPT_URL, "https://example.com/");
    curl_easy_setopt(curl, CURLOPT_PIPEWAIT, 1L);
    /* ajoutez maintenant ce handle easy au handle multi */
  }
}

DISPONIBILITÉ

Ajouté dans curl 7.43.0

VALEUR DE RETOUR

curl_easy_setopt(3) renvoie un CURLcode indiquant le succès ou l'erreur.

CURLE_OK (0) signifie que tout s'est bien passé, une valeur non nulle indique une erreur, voir libcurl-errors(3).
