DESCRIPTIO

N

curl est un outil pour transférer des données depuis ou vers un serveur en utilisant des URL. Il prend en charge les protocoles suivants : DICT, FILE, FTP, FTPS, GOPHER, GOPHERS, HTTP, HTTPS, IMAP, IMAPS, LDAP, LDAPS, MQTT, POP3, POP3S, RTMP, RTMPS, RTSP, SCP, SFTP, SMB, SMBS, SMTP, SMTPS, TELNET, TFTP, WS et

WSS.

curl est propulsé par libcurl pour toutes les fonctionnalités liées au transfert. Voir libcurl(3) pour

plus de
détails.

UR

L

La syntaxe de l'URL dépend du protocole. Vous trouverez une description détaillée dans la RFC

3986.

Si vous fournissez une URL sans le schéma protocol:// en tête, curl devine quel protocole vous voulez. Il utilise HTTP par défaut mais suppose d'autres protocoles en se basant sur les préfixes d'hôtes couramment utilisés. Par exemple, pour les noms d'hôtes commençant par "ftp.", curl suppose que vous voulez

FTP.

Vous pouvez spécifier un nombre quelconque d'URL sur la ligne de commande. Elles sont récupérées de manière séquentielle dans l'ordre spécifié, sauf si vous utilisez --parallel. Vous pouvez spécifier des options de ligne de commande et des URL de manière mélangée et dans n'importe quel ordre sur la ligne de

commande.

curl tente de réutiliser les connexions lors de transferts multiples, afin que la récupération de nombreux fichiers depuis le même serveur n'utilise pas plusieurs connexions et poignées de main de configuration. Cela améliore la vitesse. La réutilisation de connexion ne peut être effectuée que pour les URL spécifiées pour une seule invocation de ligne de commande et ne peut pas être effectuée entre des exécutions distinctes de

curl.

Fournissez un identifiant de zone IPv6 dans l'URL avec un signe pourcent échappé. Comme

dans http://[fe80::3%25eth0]/

Tout ce qui est fourni sur la ligne de commande et qui n'

est pas une option de ligne de commande ou son argumen
t, curl suppose que c'est une URL et le traite comme tel.

GLOBBIN

G

Vous pouvez spécifier plusieurs URL ou des parties d'URL en écrivant des listes entre accolades ou des plages entre crochets. Nous appelons cela « globbing »

.

Fournissez une liste avec trois noms différents comme ceci

: http://site.{one,two,three}.com

Faites des séquences de séries alphanumériques en utilisant [] comme ceci

: 
ftp://ftp.example.com/file[1-100].
txt

Avec des zéros en tête

: 
ftp://ftp.example.com/file[001-100].
txt

Avec des lettres à travers l'alphabet

: 
ftp://ftp.example.com/file[a-z].
txt

Les séquences imbriquées ne sont pas prises en charge, mais vous pouvez en utiliser plusieurs les unes à côté des autres

: http://example.com/archive[1996-1999]/vol[1-4]/part{a,b,c}.html

Vous pouvez spécifier un compteur de pas pour les plages afin d'obtenir chaque Nième nombre ou lettre

: 
http://example.com/file[1-100:10].txt
http://example.com/file[a-z:2].
txt

Lors de l'utilisation de séquences [] ou {} depuis une invite de ligne de commande, vous devrez probablement mettre l'URL complète entre guillemets doubles pour éviter que le shell n'interfère avec elle. Cela vaut aussi pour d'autres caractères traités spécialement, comme par exemple '&', '?' et

'*'.

VARIABLE

S

curl prend en charge les variables de ligne de commande (ajoutées en 8.3.0). Définissez les variables avec --variable nom=contenu ou --variable nom@fichier (où « fichier » peut être stdin s'il est défini comme un tiret simple (-))

.

Le contenu des variables peut être développé dans les paramètres d'options en utilisant « {{nom}} » si le nom de l'option est préfixé avec «--expand- ». Cela insère le contenu de la variable « nom », ou une chaîne vide si le nom n'existe pas en tant que variable. Insérez « {{ » littéralement dans la chaîne en le préfixant avec une barre oblique inverse, comme « \{{ »

.

Vous accédez et développez les variables d'environnement en les important d'abord. Vous choisissez soit d'exiger que la variable d'environnement soit définie, soit vous pouvez fournir une valeur par défaut au cas où elle ne serait pas déjà définie. Simplement «--variable %nom » importe la variable appelée « nom » mais se termine avec une erreur si cette variable d'environnement n'est pas déjà définie. Pour fournir une valeur par défaut si elle n'est pas définie, utilisez «--variable %nom=contenu » ou «--variable %nom@contenu »

.

Exemple. Récupérer la variable d'environnement USER dans l'URL, échouer si USER n'est pas définie

: 
--variable '%USER'
--expand-url = "https://example.com/api/{{USER}}
/method"

Lors du développement des variables, curl prend en charge un ensemble de fonctions qui peuvent rendre le contenu des variables plus pratique à utiliser. Il peut supprimer les espaces de début et de fin avec « trim », il peut afficher le contenu sous forme de chaîne JSON entre guillemets avec « json », encoder la chaîne en URL avec « url », l'encoder en base64 avec « b64 » et la décoder en base64 avec « 64dec ». Pour appliquer des fonctions à un développement de variable, ajoutez-les séparées par des deux-points à droite de la variable. Le contenu de la variable contenant des octets nuls qui ne sont pas encodés lors du développement provoque une

erreur.

Exemple : récupérer le contenu d'un fichier appelé $HOME/.secret dans une variable appelée « fix ». Assurez-vous que le contenu est nettoyé et encodé en pourcentage lorsqu'il est envoyé en tant que données POST

: 
--variable %HOME
--expand-variable fix@{{HOME}}/.secret
--expand-data "{{fix:trim:url}}"
https://example.
com/

COMPTEUR DE

PROGRESSION

curl affiche normalement un compteur de progression pendant les opérations, indiquant la quantité de données transférées, les vitesses de transfert et le temps restant estimé, etc. Le compteur de progression affiche le taux de transfert en octets par seconde. Les suffixes (« k » pour kilo, « M » pour méga, « G » pour giga, « T » pour téra et « P » pour péta) sont basés sur 1024. Par exemple, 1k est 1024 octets. 1M est 1048576

octets.

curl affiche ces données sur le terminal par défaut, donc si vous invoquez curl pour effectuer une opération et qu'il est sur le point d'écrire des données sur le terminal, il désactive le compteur de progression car sinon il gâcherait la sortie en mélangeant le compteur de progression et les données de

réponse.

Si vous voulez un compteur de progression pour les requêtes HTTP POST ou PUT, vous devez rediriger la sortie de la réponse vers un fichier, en utilisant la redirection du shell (>), --output ou

similaire.

Cela ne s'applique pas aux envois FTP car cette opération ne produit aucune donnée de réponse sur le

terminal.

Si vous préférez une barre de progression plutôt que le compteur habituel, --progress-bar est votre ami. Vous pouvez aussi désactiver complètement le compteur de progression avec l'option --si

len

OPTION

S

Les options commencent par un ou deux tirets. Beaucoup d'options nécessitent une valeur supplémentaire à côté d'elles. Si le texte fourni ne commence pas par un tiret, on suppose qu'il s'agit d'une URL et il est traité comme

tel.

La forme courte « tiret simple » des options, -d par exemple, peut être utilisée avec ou sans espace entre elle et sa valeur, bien qu'un espace soit le séparateur recommandé. La forme longue double tiret, --data par exemple, exige un espace entre elle et sa

valeur.

Les options en version courte qui ne nécessitent aucune valeur supplémentaire peuvent être utilisées immédiatement les unes à côté des autres, comme par exemple vous pouvez spécifier toutes les options -O, -L et -v en une seule fois comme -OLv

.

En général, toutes les options booléennes sont activées avec --option et désactivées à nouveau avec --no-option. C'est-à-dire que vous utilisez le même nom d'option mais avec le préfixe « no- ». Cependant, dans cette liste nous listons et montrons principalement la version --option de

celles-ci.

Quand --next est utilisé, il réinitialise l'état du parseur et vous recommencez avec un état d'options vierge, sauf pour les options qui sont globales. Les options globales conservent leurs valeurs et leur signification même après --next

.

Si le nom de l'option longue se termine par un signe égal (« = »), l'argument est le texte qui suit à sa droite. (Ajouté en 8.16.

0)

Le premier argument qui est exactement deux tirets (« -- »), marque la fin des options ; tout argument après la fin des options est interprété comme un argument d'URL même s'il commence par un

tiret.

curl effectue peu ou pas de vérification du contenu des arguments de la ligne de commande. Passer des « octets créatifs » comme des retours à la ligne peut déclencher des résultats

inattendus.

Les options suivantes sont globales : --fail-early, --libcurl, --parallel-immediate, --parallel-max-host, --parallel-max, --parallel, --progress-bar, --rate, --show-error, --stderr, --styled-output, --trace-ascii, --trace-config, --trace-ids, --trace-time, --trace et --ver

bos

--cacert <fichier>
(TLS) Utilise le fichier de certificat spécifié pour vérifier le pair. Le fichier peut contenir plusieurs certificats d'autorité de certification. Les certificat(s) doivent être au format PEM. Normalement, curl est compilé pour utiliser un fichier par défaut pour cela, donc cette option est généralement utilisée pour modifier ce fichier par défaut.

curl reconnaît la variable d'environnement nommée 'CURL_CA_BUNDLE' si elle est définie et si le backend TLS n'est pas Schannel, et utilise le chemin donné comme chemin vers un bundle de certificats d'autorité de certification. Cette option remplace cette variable.

(Windows) curl recherche automatiquement un fichier de certificats d'autorité de certification nommé 'curl-ca-bundle.crt', soit dans le même répertoire que curl.exe, soit dans le répertoire de travail actuel, soit dans n'importe quel dossier de votre PATH.

curl 8.11.0 a ajouté une option de compilation pour désactiver ce comportement de recherche, et une autre option pour restreindre la recherche au répertoire de l'application.

(Schannel) Cette option est prise en charge pour Schannel sous Windows 7 ou version ultérieure (ajoutée en 7.60.0). Cette option est prise en charge pour la compatibilité descendante avec d'autres moteurs SSL ; il est plutôt recommandé d'utiliser le magasin de certificats racine de Windows (la valeur par défaut pour Schannel).

Si --cacert est fourni plusieurs fois, la dernière valeur définie est utilisée.

Exemple :

curl --cacert CA-file.txt https://example.com

Voir également --capath, --dump-ca-embed et --insecure.

--capath <répertoire>
(TLS) Utilise le répertoire de certificats spécifié pour vérifier le pair. Si curl est compilé avec OpenSSL, plusieurs répertoires peuvent être fournis en les séparant par le séparateur spécifique à la plateforme (par exemple, "chemin1:chemin2:chemin3" sur les plateformes de style Unix pour "chemin1;chemin2;chemin3" sous Windows).

Les certificats doivent être au format PEM, et si curl est compilé avec OpenSSL, le répertoire doit avoir été traité à l'aide de l'utilitaire c_rehash fourni avec OpenSSL. L'utilisation de --capath peut permettre à curl, basé sur OpenSSL, d'établir des connexions SSL beaucoup plus efficacement que l'utilisation de --cacert si le fichier --cacert contient de nombreux certificats d'autorité de certification.

Si cette option est définie, la valeur par défaut du capath est ignorée.

Si --capath est fourni plusieurs fois, la dernière valeur définie est utilisée.

Exemple :

curl --capath /local/directory https://example.com

Voir également --cacert, --dump-ca-embed et --insecure.

-E, --cert <certificat[:motdepasse]>
(TLS) Utilise le fichier de certificat client spécifié lors de la récupération d'un fichier avec HTTPS, FTPS ou un autre protocole basé sur SSL. Le certificat doit être au format PEM. Si le mot de passe facultatif n'est pas spécifié, il est demandé dans le terminal. Notez que cette option suppose un fichier de certificat qui est la clé privée et le certificat client concaténés. Voir --cert et --key pour les spécifier indépendamment.

Dans la partie <certificat> de l'argument, vous devez échapper le caractère ":" par "\:" afin qu'il ne soit pas reconnu comme délimiteur de mot de passe. De même, vous devez échapper le caractère guillemet double par \" afin qu'il ne soit pas reconnu comme caractère d'échappement.

Si curl est compilé avec OpenSSL, et que le moteur pkcs11 ou le fournisseur pkcs11 est disponible, alors un URI PKCS#11 (RFC 7512) peut être utilisé pour spécifier un certificat situé dans un appareil PKCS#11. Une chaîne commençant par "pkcs11:" est interprétée comme un URI PKCS#11. Si un URI PKCS#11 est fourni, alors l'option --engine est définie comme "pkcs11" si aucune n'a été fournie et l'option --cert-type est définie comme "ENG" ou "PROV" si aucune n'a été fournie (selon la version d'OpenSSL).

Si curl est compilé avec GnuTLS, un URI PKCS#11 peut être utilisé pour spécifier un certificat situé dans un appareil PKCS#11. Une chaîne commençant par "pkcs11:" est interprétée comme un URI PKCS#11.

(Schannel) Les certificats clients doivent être spécifiés par une expression de chemin vers un magasin de certificats. (Le chargement de PFX n'est pas pris en charge ; vous pouvez l'importer dans un magasin au préalable). Vous pouvez utiliser "<emplacement du magasin>\<nom du magasin>\<empreinte>" pour faire référence à un certificat dans le magasin de certificats système, par exemple, "CurrentUser\MY\934a7ac6f8a5d579285a74fa61e19f23ddfe8d7a". L'empreinte est généralement une chaîne hexadécimale SHA-1 que vous pouvez voir dans les détails du certificat. Les emplacements de magasin suivants sont pris en charge : CurrentUser, LocalMachine, CurrentService, Services, CurrentUserGroupPolicy, LocalMachineGroupPolicy et LocalMachineEnterprise.

Si --cert est fourni plusieurs fois, la dernière valeur définie est utilisée.

Exemple :

curl --cert certfile --key keyfile https://example.com

Voir également --cert-type, --key et --key-type.

Spécifie la fréquence de transfert maximale que vous autorisez curl à utiliser - en nombre de démarrages de transfert par unité de temps (parfois appelé taux de requêtes). Sans cette option, curl démarre le transfert suivant aussi rapidement que possible.

--resolve <[+]host:port:addr[,addr]...>

It means you need several entries if you want to provide addresses for the same host but different ports.

The provided address set by this option is used even if --ipv4 or --ipv6 is set to make curl use another IP version.

By prefixing the host with a '+' you can make the entry time out after curl's default timeout (1 minute). Note that this only makes sense for long running parallel transfers with a lot of files. In such cases, if this option is used curl tries to resolve the host as it normally would once the timeout has expired.

Provide IPv6 addresses within [brackets].

To redirect connects from a specific hostname or any hostname, independently of port number, consider the --connect-to option.

Support for resolving with wildcard was added in 7.64.0.

--retry <num>
If a transient error is returned when curl tries to perform a transfer, it retries this number of times before giving up. Setting the number to 0 makes curl do no retries (which is the default). Transient error means either: a timeout, an FTP 4xx response code or an HTTP 408, 429, 500, 502, 503, 504, 522 or 524 response code.

When curl is about to retry a transfer, it first waits one second and then for all forthcoming retries it doubles the waiting time until it reaches 10 minutes, which then remains the set fixed delay time between the rest of the retries. By using --retry-delay you disable this exponential backoff algorithm. See also --retry-max-time to limit the total time allowed for retries.

curl complies with the Retry-After: response header if one was present to know when to issue the next retry (added in 7.66.0).

If --retry is provided several times, the last set value is used.

Example:

curl --retry 7 https://example.com

See also --retry-max-time, --retry-connrefused and --retry-delay.

--retry-all-errors
Retry on any error. This option is used together with --retry.

This option is the "sledgehammer" of retrying. Do not use this option by default (for example in your curlrc), there may be unintended consequences such as sending or receiving duplicate data. Do not use with redirected input or output. You might be better off handling your unique problems in a shell script. Please read the example below.

WARNING: For server compatibility curl attempts to retry failed flaky transfers as close as possible to how they were started, but this is not possible with redirected input or output. For example, before retrying it removes output data from a failed partial transfer that was written to an output file. However this is not true of data redirected to a | pipe or > file, which are not reset. We strongly suggest you do not parse or record output via redirect in combination with this option, since you may receive duplicate data.

By default curl does not return an error for transfers with an HTTP response code that indicates an HTTP error, if the transfer was successful. For example, if a server replies 404 Not Found and the reply is fully received then that is not an error. When --retry is used then curl retries on some HTTP response codes that indicate transient HTTP errors, but that does not include most 4xx response codes such as 404. If you want to retry on all response codes that indicate HTTP errors (4xx and 5xx) then combine with --fail.

Providing --retry-all-errors multiple times has no extra effect. Disable it again with --no-retry-all-errors.

Example:

curl --retry 5 --retry-all-errors https://example.com

Added in 7.71.0. See also --retry.
