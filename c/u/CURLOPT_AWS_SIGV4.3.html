Paquet: curl

Licences: MIT

CURLOPT_AWS_SIGV4(3) Manuel des fonctions de la bibliothèque CURLOPT_AWS_SIGV4(3)

NOM

CURLOPT_AWS_SIGV4 - Signature V4

SYNOPSIS

#include <curl/curl.h>
CURLcode curl_easy_setopt(CURL *handle, CURLOPT_AWS_SIGV4, char *param);

DESCRIPTION

Fournit une authentification par signature AWS V4 sur l'en-tête HTTP(S).

Passez un pointeur de caractère qui est la collection d'arguments spécifiques utilisés pour créer les en-têtes d'authentification sortants. Le format de l'option param est :

fournisseur1[:fournisseur2[:région[:service]]]
fournisseur1, fournisseur2
Les arguments des fournisseurs sont utilisés pour générer certains paramètres d'authentification tels que « Algorithm », « date », « type de requête » et « en-têtes signés ».
région
L'argument est une zone géographique d'une collection de ressources. Il est extrait de l'hôte spécifié dans l'URL s'il est omis.
service
L'argument est une fonction fournie par un cloud. Il est extrait de l'hôte spécifié dans l'URL s'il est omis.

NOTE : Cet appel définit CURLOPT_HTTPAUTH(3) sur CURLAUTH_AWS_SIGV4. Appeler CURLOPT_HTTPAUTH(3) avec CURLAUTH_AWS_SIGV4 est équivalent à appeler celui-ci avec « aws:amz » comme paramètre.

Exemple avec « Test:Try », lorsque curl utilise l'algorithme, il génère « TEST-HMAC-SHA256 » pour « Algorithm », « x-try-date » et « X-Try-Date » pour « date », « test4_request » pour « type de requête », « SignedHeaders=content-type;host;x-try-date » pour « en-têtes signés »

Si vous utilisez seulement « test », au lieu de « test:try », test est utilisé pour chaque chaîne générée.

Définir CURLOPT_HTTPAUTH(3) avec le bit CURLAUTH_AWS_SIGV4 défini est équivalent à définir cette option avec un paramètre « aws:amz ».

L'application n'a pas à conserver la chaîne après avoir défini cette option.

L'utilisation de cette option plusieurs fois permet à la dernière chaîne définie de remplacer les précédentes. Définissez-la sur NULL pour désactiver son utilisation à nouveau.

DÉFAUT

NULL

PROTOCOLES

Cette fonctionnalité affecte uniquement http

EXEMPLE

int main(void)
{
  CURL *curl = curl_easy_init();
  if(curl) {
    curl_easy_setopt(curl, CURLOPT_URL,
                    "https://service.region.example.com/uri");
    curl_easy_setopt(curl, CURLOPT_AWS_SIGV4, "provider1:provider2");
    /* service et région peuvent également être définis dans CURLOPT_AWS_SIGV4 */
    curl_easy_setopt(curl, CURLOPT_URL, "https://example.com/uri");
    curl_easy_setopt(curl, CURLOPT_AWS_SIGV4,
                     "provider1:provider2:region:service");
    curl_easy_setopt(curl, CURLOPT_USERPWD, "MY_ACCESS_KEY:MY_SECRET_KEY");
    curl_easy_perform(curl);
  }
}

NOTES

Cette option remplace les autres types d'authentification que vous auriez pu définir dans CURLOPT_HTTPAUTH(3), ce qui rend cette méthode d'authentification spéciale. Cette méthode ne peut pas être combinée avec d'autres types d'authentification.

Une somme de contrôle sha256 de la charge utile de la requête est utilisée comme entrée pour le calcul de la signature. Pour les requêtes POST, il s'agit d'une somme de contrôle de CURLOPT_POSTFIELDS(3). Sinon, il s'agit de la somme de contrôle d'un tampon vide. Pour les requêtes comme PUT, vous pouvez fournir votre propre somme de contrôle dans un en-tête HTTP nommé x-provider2-content-sha256.

Pour aws:s3, un en-tête x-amz-content-sha256 est ajouté à chaque requête si elle n'est pas déjà présente. Pour les requêtes s3 avec une charge utile inconnue, cet en-tête prend la valeur spéciale « UNSIGNED-PAYLOAD ».

DISPONIBILITÉ

Ajouté dans curl 7.75.0

VALEUR DE RETOUR

curl_easy_setopt(3) retourne un CURLcode indiquant le succès ou une erreur.

CURLE_OK (0) signifie que tout s'est bien passé, une valeur non nulle indique une erreur, voir libcurl-errors(3).

VOIR AUSSI

CURLOPT_HEADEROPT(3), CURLOPT_HTTPAUTH(3), CURLOPT_HTTPHEADER(3), CURLOPT_PROXYAUTH(3)
