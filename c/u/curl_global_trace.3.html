DESCRIPTIO

N

Cette fonction configure le comportement de journalisation pour rendre certaines parties de curl plus verbeuses ou plus silencieuses que

d'autres.

Cette fonction peut être appelée pendant la phase d'initialisation d'un programme. Ce n'est pas obligatoire. Elle peut même être appelée plusieurs fois, éventuellement en écrasant les paramètres des appels

précédents.

Appeler cette fonction après le début des transferts est indéfini. Sur certaines plateformes/architectures, cela peut prendre effet, sur d'autres

non.

Cette fonction est sûre pour les threads depuis libcurl 8.3.0 si curl_version_info(3) a le bit de fonctionnalité CURL_VERSION_THREADSAFE défini (la plupart des plateformes)

.

Si ce n'est pas sûr pour les threads, vous ne devez pas appeler cette fonction lorsque un autre thread du programme (c'est-à-dire un thread partageant la même mémoire) est en cours d'exécution. Cela ne signifie pas seulement qu'aucun autre thread n'utilise libcurl. Parce que curl_global_init(3) peut appeler des fonctions d'autres bibliothèques qui sont de manière similaire non sûres pour les threads, cela pourrait entrer en conflit avec n'importe quel autre thread qui utilise ces autres

bibliothèques.

Si vous initialisez libcurl à partir d'une DLL Windows, vous ne devriez pas l'initialiser à partir de DllMain ou d'un initialiseur statique car Windows détient le verrou du chargeur pendant ce temps et cela pourrait causer un

interblocage.

La chaîne config est une liste de noms de composants séparés par des virgules. Les noms ne sont pas sensibles à la casse et les noms inconnus sont ignorés. Le nom spécial "all" s'applique à tous les composants. Les noms peuvent être préfixés avec '+' ou '-' pour activer ou désactiver la journalisation détaillée pour un

composant.

La liste des noms de composants ne fait pas partie de l'API publique de curl. Des noms peuvent être ajoutés ou disparaître dans les futures versions de libcurl. Puisque les noms inconnus sont silencieusement ignorés, les configurations de journalisation obsolètes ne causent pas d'erreurs lors de la mise à niveau de libcurl. Étant donné cela, certains noms peuvent être considérés comme relativement stables et sont listés ci-dessous pour référence

facile.

Notez que la configuration de journalisation ne s'applique qu'aux transferts où la journalisation de débogage est activée. Voir CURLOPT_VERBOSE(3) ou CURLOPT_DEBUGFUNCTION(3) pour

savoir comment
contrôler cela.
