CURLOPT_USERPWD(3)

Paquet: curl

Licences: MIT

CURLOPT_USERPWD(3) Manuel des fonctions de bibliothèque CURLOPT_USERPWD(3)

NOM

CURLOPT_USERPWD - nom d'utilisateur et mot de passe à utiliser dans l'authentification

SYNTAXE

#include <curl/curl.h>
CURLcode curl_easy_setopt(CURL *handle, CURLOPT_USERPWD, char *userpwd);

DESCRIPTION

Passe un pointeur char en paramètre, pointant vers une chaîne de connexion de détails de connexion terminée par un nul. Le format est : [nom d'utilisateur]:[mot de passe].

Lors de l'utilisation de l'authentification Kerberos V5 avec un serveur basé sur Windows, vous devez spécifier la partie nom d'utilisateur avec le nom de domaine afin que le serveur obtienne avec succès un ticket Kerberos. Si vous ne le faites pas, la partie initiale de la poignée de main d'authentification peut échouer.

Lors de l'utilisation de NTLM, le nom d'utilisateur peut être spécifié simplement comme le nom d'utilisateur sans le nom de domaine si le serveur fait partie d'un seul domaine et d'une seule forêt.

Pour spécifier le nom de domaine, utilisez les formats de connexion vers le bas (Down-Level Logon Name) ou UPN (User Principal Name). Par exemple EXAMPLEser et user@example.com respectivement.

Certains serveurs HTTP (sur Windows) prennent également en charge l'inclusion du domaine pour l'authentification de base.

Lors de l'utilisation de HTTP et CURLOPT_FOLLOWLOCATION(3), libcurl peut effectuer plusieurs requêtes vers des hôtes potentiellement différents. libcurl n'envoie ces informations d'utilisateur et de mot de passe qu'aux hôtes utilisant le nom d'hôte initial (sauf si CURLOPT_UNRESTRICTED_AUTH(3) est défini), donc si libcurl suit les redirections vers d'autres hôtes, il n'envoie pas l'utilisateur et le mot de passe à ceux-ci. Ceci est appliqué pour éviter la fuite accidentelle d'informations.

Utilisez CURLOPT_HTTPAUTH(3) pour spécifier la méthode d'authentification pour les connexions basées sur HTTP ou CURLOPT_LOGIN_OPTIONS(3) pour contrôler les options IMAP, POP3 et SMTP.

Les chaînes d'utilisateur et de mot de passe ne sont pas décodées d'URL, il n'y a donc aucun moyen d'envoyer un nom d'utilisateur contenant un deux-points en utilisant cette option. Utilisez CURLOPT_USERNAME(3) pour cela, ou incluez-le dans l'URL.

L'application n'a pas à conserver la chaîne après avoir défini cette option.

L'utilisation répétée de cette option fait que la dernière chaîne définie remplace les précédentes. Définissez-la sur NULL pour désactiver son utilisation à nouveau.

PAR DÉFAUT

NULL

PROTOCOLES

Cette fonctionnalité affecte tous les protocoles pris en charge

EXEMPLE

int main(void)
{
  CURL *curl = curl_easy_init();
  if(curl) {
    CURLcode res;
    curl_easy_setopt(curl, CURLOPT_URL, "https://example.com/foo.bin");
    curl_easy_setopt(curl, CURLOPT_USERPWD, "clark:kent");
    res = curl_easy_perform(curl);
    curl_easy_cleanup(curl);
  }
}

DISPONIBILITÉ

Ajouté dans curl 7.1

VALEUR DE RETOUR

curl_easy_setopt(3) renvoie un CURLcode indiquant le succès ou l'erreur.

CURLE_OK (0) signifie que tout était OK, une valeur non nulle indique une erreur, voir libcurl-errors(3).

VOIR AUSSI

CURLOPT_PASSWORD(3), CURLOPT_PROXYUSERPWD(3), CURLOPT_USERNAME(3)
