DESCRIPTIO

N

Cue2toc convertit cuefile du format CUE en format TOC et écrit le résultat dans tocfile. Si cuefile ou tocfile est omis ou si un simple tiret "-" est utilisé, cue2toc lit depuis l'entrée standard et écrit vers la sortie standard

respectivement.

Les fichiers CUE sont des fichiers texte décrivant la disposition d'un CD-Rom et portent généralement l'extension « .cue »

.

Cdrdao est une application de gravure de CD qui possède son propre format natif TOC pour décrire la disposition du disque. Bien que cdrdao prenne en charge directement la lecture des fichiers CUE, cette fonctionnalité est actuellement limitée aux pistes de données uniquement. Ainsi l'utilité principale de cue2toc réside dans la conversion des fichiers CUE contenant des pistes

audio.

La sortie des données CD-Text peut être désactivée avec l'option -n

.

Les fichiers CUE sont souvent accompagnés de fichiers MP3, mais comme cdrdao ne prend pas en charge le décodage à la volée, ils doivent probablement être décodés par d'autres moyens avant la gravure du CD (par exemple en utilisant lame). Pour cette raison, vous pouvez spécifier un nom de fichier avec l'option -w à utiliser pour toutes les pistes audio au lieu de celui du fichier CUE. Cela n'est évidemment vraiment utile que si toutes les pistes sont basées sur le même fichier. C'est cependant souvent le

cas.

Cue2toc affiche normalement des messages d'avertissement pour les commandes et les constructions non prises en charge. L'option -q désactive ces

avertis
sements.

FORMAT

CUE

Ce qui suit est une description du format CUE attendu par cue2toc. Pour des informations sur le format TOC, veuillez consulter la page de manuel cdrdao(

1).

Les fichiers CUE se composent de commandes et de leurs arguments qui doivent être séparés les uns des autres par un ou plusieurs caractères d'espacement. L'espace, la tabulation horizontale, le saut de ligne et le retour à la ligne sont reconnus comme caractères d'espacement, sauf à l'intérieur des chaînes entourées de guillemets doubles, où ils font partie de la chaîne. Les commandes ne sont pas sensibles à la casse. Les données CD-Text peuvent contenir au plus 80 caractères par

élément.

Les valeurs de code temporel sont acceptées sous les formes « X:X:X », « X:X » et « X » où chaque « X » doit être composé d'au plus deux chiffres et peut être complété par des zéros à gauche. Elles sont interprétées comme « M:S:F », « S:F » et « F » respectivement où « M » signifie « minutes » et doit être compris dans la plage 0 <= M <= 99, « S » signifie « secondes » et doit être compris dans la plage 0 <= S <= 59, et « F » signifie « trames » et doit être compris dans la plage 0 <= F <=

74.

Les fichiers CUE sont divisés logiquement en une section globale et de une à 99 sections de piste. À l'intérieur de ces sections, les commandes suivantes sont autorisées

LIMITATION

S

La commande CDTEXTFILE et l'indicateur SCMS n'ont pas d'équivalent dans le format TOC et sont

ignorés.

Les fichiers CUE contenant des pistes de données qui spécifient un temps de départ supérieur à zéro ne peuvent pas être convertis par cue2toc car le format TOC ne fournit aucun moyen de spécifier un temps de départ pour les pistes de données. Cependant

, si le fichier CUE ne contient aucune piste audio, vous pouvez
essayer d'utiliser directement le fichier CUE avec cdrdao.

EXEMPL

E

Supposons que nous ayons le fichier CUE suivant "uwe.froehn.cue" décrivant un CD audio avec des données CD-Text

: 
REM Example CUE file with audio tracks
CATALOG 1234567890123
TITLE "Der Berg ruft"
PERFORMER "Uwe Froehn"
FILE "uwe.froehn.mp3" MP3
TRACK 01 AUDIO
  TITLE "Meine Mama ist die Beste"
  PERFORMER "Uwe Froehn"
  SONGWRITER "Hansi Klabuster"
  REM two seconds pregap filled with audio data
  INDEX 00 00:00:00
  INDEX 01 00:02:00
  REM subindexes
  INDEX 02 00:35:17
  INDEX 03 01:12:44
TRACK 02 AUDIO
  TITLE "Hoch oben im Tal"
  SONGWRITER "Gabi Geil"
  REM no pregap
  INDEX 01 02:45:38
TRACK 03 AUDIO
  REM pregap with zero data
  PREGAP 00:4:47
  INDEX 01 07:58:74
  REM postgap with zero data
  POSTGAP 00:35:00

Puisque cdrdao ne peut pas décoder le fichier MP3 à la volée, cette étape doit être effectuée manuellement, par exemple en utilisant lame

: 
lame --decode uwe.froehn.mp3 uwe.froehn.wav

Bien que le nom de fichier n'apparaisse qu'une seule fois dans le fichier CUE d'exemple, il est écrit pour chaque piste dans le fichier TOC, vous devriez donc modifier de nombreuses occurrences du nom de fichier dans le fichier TOC manuellement. Pour cette raison, vous pouvez spécifier une chaîne avec l'option -w à utiliser par cue2toc comme nom de fichier pour toutes les pistes audio. La

commande 
cue2toc -w uwe.froehn.wav -o uwe.froehn.toc uwe.froehn.cue

devrait produire le fichier uwe.froehn.toc avec le contenu suivant

: 
CATALOG "1234567890123"

    LANGUAGE_MAP {
        0 : EN
    }

        }
    }
    AUDIOFILE "uwe.froehn.wav" 00:00:00 02:45:38

    AUDIOFILE "uwe.froehn.wav" 07:58:74
    SILENCE 00:35:00

BUG

S

Puisque la définition du format CUE par cue2toc est entièrement basée sur un certain nombre de fichiers CUE différents que l'auteur a rencontrés, il y a une très forte probabilité qu'elle ne fonctionne pas correctement avec tous les autres fichiers CUE que vous pourriez rencontrer. Si c'est votre cas, veuillez envoyer le fichier CUE problématique avec le numéro de version de cue2toc à <d

ermatsch@
gmx.de>.
