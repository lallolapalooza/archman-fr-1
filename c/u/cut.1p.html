UTILISATION PAR LES

APPLICATIONS

Les cut et fold peuvent être utilisés pour créer des fichiers texte à partir de fichiers ayant des longueurs de lignes arbitraires. L'utilitaire cut doit être utilisé lorsque le nombre de lignes (ou d'enregistrements) doit rester constant. L'utilitaire fold doit être utilisé lorsque le contenu de lignes longues doit être conservé de manière

contiguë.

Les versions antérieures de l'utilitaire cut fonctionnaient dans un environnement où les octets et les caractères étaient considérés comme équivalents (modulo le traitement de <backspace> et <tab> dans certaines implémentations). Dans le monde étendu des caractères multi-octets, la nouvelle option -b a été ajoutée. L'option -n (utilisée avec -b) permet d'agir sur des octets arrondis aux limites de caractères. L'algorithme spécifié pour -n garantit que

: 
cut -b 1-500 -n fil
e > file1 cut -b 5
01- -n file > file2

se termine avec tous les caractères de file apparaissant exactement une fois dans file1 ou file2. (Il y a cependant un <newline> à la fois dans file1 et file2 pour chaque <newline> dans fil

e
.)

La plupart des utilitaires de ce volume de POSIX.1‐2017 travaillent sur des fichiers texte. L'utilitaire cut peut être utilisé pour transformer des fichiers ayant des longueurs de lignes arbitraires en un ensemble de fichiers texte contenant les mêmes données. L'utilitaire paste peut être utilisé pour créer (ou recréer) des fichiers ayant des longueurs de lignes arbitraires. Par exemple, si file contient des lignes longues

: 
cut -b 1-500 -n fil
e > file1 cut -b 5
01- -n file > file2

crée file1 (un fichier texte) avec des lignes ne dépassant pas 500 octets (plus le <newline>) et file2 qui contient le reste des données de file. (Notez que file2 n'est pas un fichier texte s'il y a des lignes dans file qui sont plus longues que 500 + {LINE_MAX} octets.) Le fichier original peut être recréé à partir de file1 et file2 en utilisant la commande

: 
paste -d
"\0" fi

JUSTIFICATIO

N

Certaines implémentations historiques ne comptent pas les caractères <backspace> lors de la détermination du nombre de caractères avec l'option -c. Cela peut être utile pour utiliser cut pour traiter la sortie de nroff. Il a été décidé délibérément de ne pas faire traiter à l'option -c les caractères <backspace> ou <tab> de manière spéciale. L'utilitaire fold traite ces caractères de manière

spéciale.

Contrairement à d'autres utilitaires, certaines implémentations historiques de cut se terminent après ne pas avoir trouvé un fichier d'entrée, plutôt que de continuer à traiter les opérandes file restants. Ce comportement est interdit par ce volume de POSIX.1‐2017, où seul le statut de sortie est affecté par ce

problème.

Le comportement de cut lorsqu'il est fourni avec des options mutuellement exclusives ou des options qui ne fonctionnent pas logiquement ensemble a été délibérément laissé non spécifié au profit d'une formulation générale dans la section 1.4, Valeurs par défaut de la descriptio

n des utilitaires.

La section OPTIONS a été modifiée en réponse à l'interprétation IEEE PASC 1003.2 #149. Le changement représente la pratique historique sur tous les systèmes connus. La norme originale était ambiguë quant à la nature de la

sortie.

Les arguments d'options liste sont historiquement utilisés pour sélectionner les portions de la ligne à écrire, mais n'affectent pas l'ordre des données. Par exemple

: 
echo abcdef
ghi | cut
-c6,2,4-7,1

produit "abdefg"

.
