CURLOPT_PROXY(3) Manuel des fonctions de bibliothèque CURLOPT_PROXY(3)

NOM

CURLOPT_PROXY - proxy à utiliser

SYNOPSIS

#include <curl/curl.h>
CURLcode curl_easy_setopt(CURL *handle, CURLOPT_PROXY, char *proxy);

DESCRIPTION

Définit le proxy à utiliser pour les transferts avec ce gestionnaire facile. Le paramètre doit être un char * vers une chaîne terminée par un caractère nul contenant le nom d'hôte ou l'adresse IP numérique au format pointé. Une adresse IPv6 numérique doit être écrite entre [crochets].

Pour spécifier le numéro de port dans cette chaîne, ajoutez :[port] à la fin du nom d'hôte. Le numéro de port du proxy peut éventuellement (mais ce n'est pas recommandé) être spécifié avec l'option séparée CURLOPT_PROXYPORT(3). S'il n'est pas spécifié, libcurl utilise par défaut le port 1080 pour les proxys.

La chaîne de proxy peut être préfixée par [schéma]:// pour spécifier quel type de proxy est utilisé.

L'utilisation multiple de cette option fait que la dernière chaîne définie remplace les précédentes. Définissez-la sur NULL pour désactiver à nouveau son utilisation.

L'application n'a pas besoin de conserver la chaîne après avoir défini cette option.

http://
Proxy HTTP. Par défaut, aucun schéma ni type de proxy n'est spécifié.
https://
Proxy HTTPS. (Ajouté en 7.52.0 pour OpenSSL et GnuTLS. Depuis 7.87.0, il fonctionne également pour mbedTLS, Rustls, Schannel et wolfSSL.)

Cela utilise HTTP/1 par défaut. Le fait de définir CURLOPT_PROXYTYPE(3) sur CURLPROXY_HTTPS2 permet à libcurl de négocier l'utilisation de HTTP/2 avec le proxy.

socks4://
Proxy SOCKS4.
socks4a://
Proxy SOCKS4a. Le proxy résout le nom d'hôte de l'URL.
socks5://
Proxy SOCKS5.
socks5h://
Proxy SOCKS5. Le proxy résout le nom d'hôte de l'URL.

Sans préfixe de schéma, CURLOPT_PROXYTYPE(3) peut être utilisé pour spécifier quel type de proxy la chaîne identifie.

Lorsque vous indiquez à la bibliothèque d'utiliser un proxy HTTP, libcurl convertit transparentment les opérations en HTTP, même si vous spécifiez une URL FTP etc. Cela peut avoir un impact sur les autres fonctionnalités de la bibliothèque que vous pouvez utiliser, telles que CURLOPT_QUOTE(3) et les spécificités FTP similaires qui ne fonctionnent pas à moins de créer un tunnel via le proxy HTTP. Un tel tunnel est activé avec CURLOPT_HTTPPROXYTUNNEL(3).

Définir la chaîne de proxy sur "" (chaîne vide) désactive explicitement l'utilisation d'un proxy, même s'il existe une variable d'environnement définie pour celui-ci.

Les sockets de domaine Unix sont pris en charge pour les proxys socks depuis 7.84.0. Définissez localhost pour la partie hôte. Par exemple : socks5h://localhost/path/to/socket.sock

Lorsque vous définissez un nom d'hôte à utiliser, ne supposez pas qu'il existe un numéro de port particulier largement utilisé pour les proxys. Spécifiez-le.

Lorsqu'un proxy est utilisé, le mode FTP actif défini avec CUROPT_FTPPORT(3)ne peut pas être utilisé.

Faire du FTP via un proxy HTTP sans CURLOPT_HTTPPROXYTUNNEL(3] défini fait que libcurl fait du HTTP avec une URL FTP via le proxy. Pour de tels transferts, les options spécifiques au FTP courantes ne fonctionnent pas, par exemple CURLOPT_USE_SSL(3).

Authentification

Le proxy peut également être spécifié avec ses identifiants associés comme pour les URL ordinaires, sous la forme : schéma://nom_utilisateur:mot_de_passe@nom_hôte

Ou, définissez-les en utilisant CURLOPT_PROXYUSERNAME(3) et CURLOPT_PROXYPASSWORD(3).

Variables d'environnement

libcurl prend en compte les variables d'environnement de proxy nommées http_proxy, ftp_proxy, sftp_proxy etc. Si définies, libcurl utilise le proxy spécifié pour ce schéma d'URL. Pour une URL "FTP://", le ftp_proxy est pris en compte. all_proxy est utilisé si aucun proxy spécifique au protocole n'a été défini.

Si no_proxy (ou NO_PROXY) est défini, c'est l'équivalent exact de définir l'option CURLOPT_NOPROXY(3) .

Les options CURLOPT_PROXY(3) et CURLOPT_NOPROXY(3) remplacent les variables d'environnement.

PAR DÉFAUT

NULL

PROTOCOLES

Cette fonctionnalité affecte tous les protocoles pris en charge

EXEMPLE

int main(void)
{
  CURL *curl = curl_easy_init();
  if(curl) {
    curl_easy_setopt(curl, CURLOPT_URL, "https://example.com/file.txt");
    curl_easy_setopt(curl, CURLOPT_PROXY, "http://proxy:80");
    curl_easy_perform(curl);
  }
}

HISTORIQUE

Depuis la version 7.14.1, les noms des variables d'environnement de proxy peuvent inclure le schéma de protocole.

Depuis la version 7.21.7, la chaîne de proxy prend en charge les protocoles socks comme "schémas".

Depuis la version 7.50.2, les schémas non pris en charge dans les chaînes de proxy font que libcurl renvoie une erreur.

DISPONIBILITÉ

Ajouté dans curl 7.1

VALEUR DE RETOUR

curl_easy_setopt(3) renvoie un CURLcode indiquant le succès ou une erreur.

CURLE_OK (0) signifie que tout s'est bien passé, une valeur non nulle signifie qu'une erreur s'est produite, voir libcurl-errors(3).

VOIR AUSSI
