curl_ws_send(3)

Paquet: curl

Licences: MIT

curl_ws_send(3) Manuel des fonctions de bibliothèque curl_ws_send(3)

NOM

curl_ws_send - envoie des données WebSocket

SYNTAXE

#include <curl/curl.h>
CURLcode curl_ws_send(CURL *curl, const void *buffer, size_t buflen,
                      size_t *sent, curl_off_t fragsize,
                      unsigned int flags);

DESCRIPTION

Envoie le morceau de message spécifique via une connexion WebSocket établie. buffer doit pointer vers un emplacement mémoire valide contenant (au moins) buflen octets de données utiles.

sent est défini sur le nombre d'octets de données utiles réellement envoyés. Si la valeur de retour est CURLE_OK mais que sent est inférieur au buflen donné, libcurl n'a pas pu consommer la charge utile complète en un seul appel. Dans ce cas, l'application doit rappeler cette fonction jusqu'à ce que toutes les données utiles soient traitées. buffer et buflen doivent être mis à jour à chaque invocation suivante pour ne pointer que vers le reste de la charge utile.

fragsize doit toujours être défini sur zéro, sauf si une trame (énorme) doit être envoyée en utilisant plusieurs appels avec un contenu partiel par appel explicitement. Dans ce cas, vous devez définir le bit CURLWS_OFFSET et définir le fragsize comme documenté dans la section sur CURLWS_OFFSET ci-dessous.

flags doit contenir au moins un indicateur indiquant le type du message. Pour envoyer un message fragmenté composé de plusieurs trames, définissez également le bit CURLWS_CONT dans toutes les trames sauf la dernière. L'indicateur de type de message approprié doit être défini dans chaque trame d'un message fragmenté sans exception. Omettre le type de message pour les trames de continuation d'un message fragmenté n'est pris en charge que pour des raisons de compatibilité descendante et est fortement déconseillé.

Pour plus de détails sur les indicateurs pris en charge, voir ci-dessous et dans curl_ws_meta(3).

Si CURLWS_RAW_MODE est activé dans CURLOPT_WS_OPTIONS(3), l'argument flags doit être défini sur 0.

Attention : bien qu'il soit possible d'appeler cette fonction depuis une fonction de rappel, un tel appel est bloquant dans cette situation, c'est-à-dire qu'il ne retourne qu'après que toutes les données ont été envoyées ou qu'une erreur est survenue.

FLAGS

Prend en charge tous les indicateurs documentés dans curl_ws_meta(3) et en plus les indicateurs suivants.

CURLWS_OFFSET
Les données fournies ne constituent qu'une partie d'une trame et il y en aura d'autres dans un appel ultérieur à curl_ws_send(). Lors de l'envoi d'une seule partie de la trame de cette manière, le fragsize doit être fourni avec la taille totale attendue de la trame lors du premier appel et doit être zéro dans tous les appels suivants.

PROTOCOLES

Cette fonctionnalité affecte uniquement ws

EXEMPLE

#include <string.h> /* pour strlen */
int main(void)
{
  const char *buffer = "PAYLOAD";
  size_t offset = 0;
  CURLcode res = CURLE_OK;
  CURL *curl = curl_easy_init();
  curl_easy_setopt(curl, CURLOPT_URL, "wss://example.com/");
  curl_easy_setopt(curl, CURLOPT_CONNECT_ONLY, 2L);
  /* démarre la connexion HTTPS et la met à niveau vers WSS, puis renvoie le contrôle */
  curl_easy_perform(curl);
  while(!res) {
    size_t sent;
    res = curl_ws_send(curl, buffer + offset, strlen(buffer) - offset, &sent,
                       0, CURLWS_TEXT);
    offset += sent;
    if(res == CURLE_OK) {
      if(offset == strlen(buffer))
        break; /* fin de l'envoi */
    }
    if(res == CURLE_AGAIN)
      /* dans une application réelle : attendre le socket ici, par exemple en utilisant select() */
      res = CURLE_OK;
  }
  curl_easy_cleanup(curl);
  return (int)res;
}

DISPONIBILITE

Ajouté dans curl 7.86.0

VALEUR DE RETOUR

Cette fonction renvoie un CURLcode indiquant le succès ou l'erreur.

CURLE_OK (0) signifie que tout s'est bien passé, une valeur non nulle indique une erreur, voir libcurl-errors(3). Si CURLOPT_ERRORBUFFER(3) a été défini avec curl_easy_setopt(3), un message d'erreur peut être stocké dans le tampon d'erreur lorsque la valeur renvoyée est non nulle.

Au lieu de bloquer, la fonction renvoie CURLE_AGAIN. Le comportement correct est alors d'attendre que le socket signale la possibilité de lecture avant de rappeler cette fonction.

Toute autre valeur de retour non nulle indique une erreur. Voir la page de manuel libcurl-errors(3) pour la liste complète avec descriptions.
