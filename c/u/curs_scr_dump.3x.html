curs_scr_dump(3X) Appels de bibliothèque curs_scr_dump(3X)

NOM

scr_dump, scr_restore, scr_init, scr_set - lire/écrire un écran curses depuis/vers un fichier

SYNTAXE

#include <curses.h>
int scr_dump(const char *filename);
int scr_restore(const char *filename);
int scr_init(const char *filename);
int scr_set(const char *filename);

DESCRIPTION

curses fournit aux applications la capacité d'écrire le contenu de l'écran dans un fichier et de le lire à nouveau. Pour lire/écrire une fenêtre (plutôt que l'écran entier) depuis/vers un fichier, utilisez getwin(3X) et putwin(3X), respectivement.

scr_dump

scr_dump écrit dans filename le contenu de l'écran virtuel ; voir curscr(3X).

scr_restore

scr_restore met à jour l'écran virtuel pour qu'il contienne le contenu de filename (s'il a été correctement écrit avec scr_dump). Aucun rafraîchissement n'est effectué ; après avoir effectué toutes les mises à jour souhaitées, appelez doupdate(3X) ou une fonction similaire.

scr_init

scr_init lit filename, l'utilisant pour initialiser les structures de données curses décrivant l'état de l'écran du terminal. Si ces données sont valides, curses base sa prochaine mise à jour de l'écran sur ces informations plutôt que de le vider et de recommencer depuis le début.

Les données échouent à la vérification de validité

  • si le terminal utilise les capacités terminfo exit_ca_mode (rmcup) ou non_rev_rmcup (nrrmc) sont définies, ou
  • si curses sait que le terminal a été écrit depuis l'appel précédent à scr_dump.

scr_init pourrait être utilisé après initscr(3X) ou system(3) pour partager l'écran avec un autre processus qui a effectué un scr_dump après un appel à endwin(3X).

scr_set

La routine scr_set est une combinaison de scr_restore et scr_init. Elle indique au programme que les informations contenues dans filename correspondent à ce qui est actuellement à l'écran, et également à ce que le programme souhaite voir à l'écran. Cela peut être considéré comme une fonction d'héritage d'écran.

VALEUR DE RETOUR

Ces fonctions retournent OK en cas de succès et ERR en cas d'échec.

X/Open ne définit aucune condition d'échec. Dans cette implémentation, chaque fonction échoue si elle ne parvient pas à ouvrir filename.

NOTES

scr_init, scr_set, et scr_restore peuvent être des macros.

PORTABILITE

X/Open Curses, Issue 4 décrit ces fonctions.

SVr4 a omis les qualificateurs const.

La documentation SVr4 décrit scr_init de telle sorte que les données sauvegardées soient également considérées comme invalides “si l'horodatage du tty est ancien” mais ne définit pas ce que signifie “ancien”.
