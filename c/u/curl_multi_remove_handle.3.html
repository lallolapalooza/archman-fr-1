NOM

curl_multi_remove_handle - supprimer une poignée easy d'une session multi

SYNTAXE

#include <curl/curl.h>
CURLMcode curl_multi_remove_handle(CURLM *multi_handle, CURL *easy_handle);

DESCRIPTION

Supprime la easy_handle donnée du multi_handle. Cela retire la poignée easy spécifiée du contrôle de cette pile multi.

Une fois que la poignée easy a été retirée d'une pile multi, il est de nouveau parfaitement légal d'invoquer curl_easy_perform(3) sur cette poignée easy.

Retirer une poignée easy pendant son utilisation est parfaitement légal et interrompt efficacement le transfert en cours impliquant cette poignée easy. Toutes les autres poignées easy et transferts restent inchangés.

Il est possible de retirer une poignée à tout moment pendant un transfert, mais pas depuis une fonction de rappel de libcurl.

Retirer une poignée easy de la pile multi avant que le transfert correspondant ne soit terminé peut amener libcurl à fermer la connexion — si l'état de celle-ci et du gestionnaire de protocole interne le jugent nécessaire. Sinon, libcurl maintient la connexion active dans le pool de connexions associé à la pile multi, prête à être réutilisée pour un futur transfert utilisant cette pile multi.

PROTOCOLES

Cette fonctionnalité affecte tous les protocoles pris en charge

EXEMPLE

int main(void)
{
  CURLM *multi = curl_multi_init();
  int queued = 0;
  /* lorsqu'une poignée easy est terminée, retirez-la */
  CURLMsg *msg = curl_multi_info_read(multi, &queued);
  if(msg) {
    if(msg->msg == CURLMSG_DONE) {
      /* un transfert est terminé */
      fprintf(stderr, "Transfert terminé\n");
      curl_multi_remove_handle(multi, msg->easy_handle);
    }
  }
}

DISPONIBILITÉ

Ajouté dans curl 7.9.6

VALEUR DE RETOUR

Cette fonction renvoie un CURLMcode indiquant le succès ou une erreur.

CURLM_OK (0) signifie que tout s'est bien passé, une valeur non nulle indique une erreur, voir libcurl-errors(3).
