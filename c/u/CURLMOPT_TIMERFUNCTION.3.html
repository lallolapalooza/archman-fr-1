CURLMOPT_TIMERFUNCTION(3)

Paquet: curl

Licences: MIT

CURLMOPT_TIMERFUNCTION(3) Manuel des fonctions de bibliothèque CURLMOPT_TIMERFUNCTION(3)

NOM

CURLMOPT_TIMERFUNCTION - rappel pour recevoir les valeurs de délai d'attente

SYNTAXE

#include <curl/curl.h>
int timer_callback(CURLM *multi,    /* handle multi */
                   long timeout_ms, /* délai d'attente en millisecondes */
                   void *clientp);  /* pointeur de rappel privé */
CURLMcode curl_multi_setopt(CURLM *handle, CURLMOPT_TIMERFUNCTION, timer_callback);

DESCRIPTION

Passez un pointeur vers votre fonction de rappel, qui doit correspondre au prototype montré ci-dessus.

Certaines fonctionnalités, telles que les délais d'attente et les nouvelles tentatives, nécessitent que vous appeliez libcurl même lorsqu'il n'y a pas d'activité sur les descripteurs de fichiers.

Votre fonction de rappel timer_callback doit installer un seul minuteur non répétitif avec un temps d'expiration de timeout_ms millisecondes. Lorsque ce minuteur se déclenche, appelez soit curl_multi_socket_action(3), soit curl_multi_perform(3), selon l'interface que vous utilisez.

Si ce rappel est appelé lorsqu'un minuteur est déjà en cours d'exécution, ce nouveau temps d'expiration remplace le délai d'attente précédent. L'application doit alors annuler efficacement l'ancien délai d'attente et en définir un nouveau en utilisant ce nouveau temps d'expiration.

Une valeur de timeout_ms de -1 passée à ce rappel signifie que vous devez supprimer le minuteur. Toutes les autres valeurs sont des temps d'expiration valides en millisecondes, y compris zéro milliseconde.

Le rappel timer_callback est appelé lorsque le temps d'expiration du minuteur est modifié.

Le pointeur clientp est défini avec CURLMOPT_TIMERDATA(3).

Le rappel de minuteur doit retourner 0 en cas de succès et -1 en cas d'erreur. Si ce rappel retourne une erreur, tous les transferts en cours dans ce handle multi sont abandonnés et échouent.

Ce rappel peut être utilisé à la place, ou en plus, de curl_multi_timeout(3).

AVERTISSEMENT : n'appelez pas libcurl directement depuis le rappel lui-même lorsque la valeur timeout_ms est zéro, car cela risque de déclencher un comportement récursif désagréable qui appelle immédiatement un autre appel au rappel avec un délai d'attente nul...

PAR DÉFAUT

NULL

PROTOCOLES

Cette fonctionnalité affecte tous les protocoles pris en charge

EXEMPLE

struct priv {
  void *custom;
};
static int timerfunc(CURLM *multi, long timeout_ms, void *clientp)
{
  struct priv *mydata = clientp;
  printf("notre ptr: %p\n", mydata->custom);
  if(timeout_ms >= 0) {
    /* c'est le nouveau délai d'attente unique à attendre, y compris zéro */
  }
  else {
    /* supprimer le délai d'attente, rien à attendre pour l'instant */
  }
  return 0;
}
int main(void)
{
  struct priv mydata;
  CURLM *multi = curl_multi_init();
  curl_multi_setopt(multi, CURLMOPT_TIMERFUNCTION, timerfunc);
  curl_multi_setopt(multi, CURLMOPT_TIMERDATA, &mydata);
}

DISPONIBILITÉ

Ajouté dans curl 7.16.0

VALEUR DE RETOUR

curl_multi_setopt(3) retourne un CURLMcode indiquant succès ou erreur.

CURLM_OK (0) signifie que tout va bien, une valeur non nulle indique une erreur, voir libcurl-errors(3).
