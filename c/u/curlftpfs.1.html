NOM

curlftpfs - monter un hôte ftp comme un répertoire local

SYNTAXE

curlftpfs [options] hôte chemin

DESCRIPTION

Le programme curlftpfs est un outil pour monter des hôtes ftp distants comme des répertoires locaux. Il se connecte au serveur FTP de l'hôte et mappe sa structure de répertoire au répertoire chemin.

curlftpfs est alimenté par libcurl pour toutes les fonctionnalités liées au transfert. Voir libcurl(3) pour les détails. La partie système de fichiers est implémentée au-dessus de FUSE. Voir http://fuse.sourceforge.net/ pour les détails.

OPTIONS FTP

-h/--aide
Afficher les options d'aide.
-v/--verbeux
Faire imprimer à libcurl une sortie de débogage verbeuse.
-V/--version
Afficher les versions de curlftpfs, libcurl et fuse.
-o
Les options sont spécifiées avec un indicateur -o suivi d'une chaîne d'options séparées par des virgules.
cacert=<fichier>
(SSL) Fournir une chaîne nommant un fichier contenant un ou plusieurs certificats pour vérifier le pair.

Notez que cette option est définie par défaut sur le chemin système où le bundle cacert de libcurl est censé être stocké, tel que déterminé au moment de la compilation.

capath=<répertoire>
(SSL) Indique à curlftpfs d'utiliser le répertoire de certificats spécifié pour vérifier le pair. Les certificats doivent être au format PEM, et le répertoire doit avoir été traité à l'aide de l'utilitaire c_rehash fourni avec openssl. L'utilisation de capath peut permettre à curlftpfs de faire des connexions beaucoup plus efficacement qu'en utilisant cacert si le fichier cacert contient de nombreux certificats d'autorité de certification.
cert=<certificat>
(SSL) Indique à curlftpfs d'utiliser le fichier de certificat spécifié. Le format par défaut est "PEM" et peut être modifié avec cert_type.
cert_type=<type>
(SSL) Indique à curlftpfs le type de certificat du certificat fourni. PEM, DER et ENG sont des types reconnus.
ciphers=<liste de chiffrements>
(SSL) Spécifie quels chiffrements utiliser dans la connexion. La liste doit être syntaxiquement correcte, elle se compose d'une ou plusieurs chaînes de chiffrements séparées par des deux-points. Les virgules ou les espaces sont également des séparateurs acceptables mais les deux-points sont normalement utilisés, , - et + peuvent être utilisés comme opérateurs. Des exemples valides de listes de chiffrements incluent 'RC4-SHA', 'SHA1+DES', 'TLSv1' et 'DEFAULT'. La liste par défaut est normalement définie lors de la compilation d'OpenSSL.

Lisez les détails sur les listes de chiffrements SSL à cette URL : http://www.openssl.org/docs/apps/ciphers.html

codepage=<nom>
Définit le codage utilisé par le serveur ftp pour coder les noms de fichiers.
connect_timeout=<secondes>
Temps maximum en secondes autorisé pour la connexion au serveur. Ceci ne limite que la phase de connexion, une fois que curlftpfs est connecté, cette option n'est plus utile.
custom_list=<commande>
Commande utilisée par curlftpfs pour lister les fichiers. La commande par défaut est "LIST -a" mais certains serveurs peuvent nécessiter des options supplémentaires, par exemple "LIST -la".
disable_eprt
Indique à curlftpfs de désactiver l'utilisation des commandes EPRT et LPRT lors des transferts FTP actifs. Curlftpfs tentera normalement toujours d'abord d'utiliser EPRT, puis LPRT avant d'utiliser PORT, mais avec cette option, il utilisera PORT immédiatement. EPRT et LPRT sont des extensions du protocole FTP d'origine, peuvent ne pas fonctionner sur tous les serveurs mais permettent plus de fonctionnalités d'une meilleure manière que la commande PORT traditionnelle.
disable_epsv
Indique à curlftpfs de désactiver l'utilisation de la commande EPSV lors des transferts FTP passifs. Ceci est le comportement par défaut.
enable_epsv
Indique à curlftpfs d'activer l'utilisation de la commande EPSV lors des transferts FTP passifs. Curlftpfs tentera d'abord d'utiliser EPSV avant PASV.
engine=<nom>
Sélectionne le moteur de cryptographie OpenSSL à utiliser pour les opérations de chiffrement. Utilisez :
curl --engine list
pour afficher une liste des moteurs pris en charge au moment de la compilation. Notez que tout ou partie des moteurs peuvent ne pas être disponibles au moment de l'exécution.
ftpfs_debug
Fait imprimer à curlftpfs beaucoup d'informations de débogage. Utile uniquement en conjonction avec l'option -d.
ftp_method=<méthode>
Contrôle quelle méthode curlftpfs doit utiliser pour atteindre un fichier sur le serveur. L'argument méthode doit être l'une des alternatives suivantes :
multicwd
curlftpfs effectue une opération CWD unique pour chaque partie du chemin dans l'URL donnée. Pour les hiérarchies profondes, cela signifie de très nombreuses commandes. C'est ainsi que RFC1738 dit que cela devrait être fait. C'est le comportement par défaut mais aussi le plus lent.
singlecwd
curlftpfs effectue un seul CWD avec le répertoire cible complet et opère ensuite sur le fichier "normalement" (comme dans le cas multicwd).
ftp_port=<adresse>
Inverse les rôles initiateur/écouteur lors de la connexion avec ftp. Ce commutateur fait utiliser à curlftpfs la commande PORT au lieu de PASV. En pratique, PORT indique au serveur de se connecter à l'adresse et au port spécifiés par le client, tandis que PASV demande au serveur une adresse IP et un port vers lesquels se connecter. <adresse> doit être l'un des éléments suivants :
interface
c.-à-d. "eth0" pour spécifier quelle interface IP utiliser
adresse IP
c.-à-d. "192.168.10.1" pour spécifier un numéro IP exact
nom d'hôte
c.-à-d. "mon.hote.domaine" pour spécifier une machine
-
fait choisir à curlftpfs la même adresse IP qui est déjà utilisée pour la connexion de contrôle

Désactivez la tentative d'utilisation de la commande EPRT au lieu de PORT en utilisant disable_eprt. EPRT est vraiment PORT++.

httpproxy
Définit le type de proxy sur HTTP. C'est le type par défaut.
interface=<nom>
Fournit une chaîne comme paramètre. Ceci définit le nom de l'interface à utiliser comme interface réseau sortante. Le nom peut être un nom d'interface, une adresse IP ou un nom d'hôte.
iocharset=<nom>
Définit le jeu de caractères utilisé par le côté client pour la traduction du jeu de caractères codepage. Par défaut : UTF8.
ipv4
Si libcurl est capable de résoudre une adresse en plusieurs versions IP (ce qui est le cas s'il est compatible IPv6), cette option indique à libcurl de résoudre les noms en adresses IPv4 uniquement.
ipv6
Si libcurl est capable de résoudre une adresse en plusieurs versions IP (ce qui est le cas s'il est compatible IPv6), cette option indique à libcurl de résoudre les noms en adresses IPv6 uniquement.
key=<clé>
(SSL) Nom du fichier de clé privée. Permettre
vous permet de fournir votre clé privée dans ce fichier séparé. Le format par défaut est « PEM » et peut être modifié avec key_type.

Le format « ENG » vous permet de charger la clé privée depuis un module de cryptographie (crypto engine). Dans ce cas, key est utilisé comme identifiant passé au module. Vous devez configurer le module de cryptographie avec l'option engine. Le fichier de clé au format « DER » ne fon
