CURLOPT_CA_CACHE_TIMEOUT(3)

Paquet: curl

Licences: MIT

CURLOPT_CA_CACHE_TIMEOUT(3) Manuel des fonctions de la bibliothèque CURLOPT_CA_CACHE_TIMEOUT(3)

NOM

CURLOPT_CA_CACHE_TIMEOUT - durée de vie des certificats d'autorité de certification mis en cache

SYNTAXE

#include <curl/curl.h>
CURLcode curl_easy_setopt(CURL *handle, CURLOPT_CA_CACHE_TIMEOUT, long age);

DESCRIPTION

Passez un long, cela définit le délai d'attente en secondes. Cela indique à libcurl le temps maximum pendant lequel tout magasin de certificats d'autorité de certification mis en cache qu'il détient en mémoire peut être conservé et réutilisé pour de nouvelles connexions. Une fois le délai d'attente expiré, une récupération ultérieure nécessitant un certificat d'autorité de certification doit le recharger.

La construction d'un magasin de certificats d'autorité à partir d'un fichier CURLOPT_CAINFO(3) est une opération lente, de sorte que curl peut mettre en cache le magasin de certificats généré en interne pour accélérer les connexions futures.

Définissez le délai d'attente à zéro pour désactiver complètement la mise en cache, ou à -1 pour conserver le magasin mis en cache indéfiniment. Par défaut, libcurl met en cache ces informations pendant 24 heures.

DÉFAUT

86400 (24 heures)

PROTOCOLES

Cette fonctionnalité affecte tous les protocoles basés sur TLS : HTTPS, FTPS, IMAPS, POP3S, SMTPS, etc.

Cette option ne fonctionne qu'avec les backends TLS suivants : GnuTLS, OpenSSL, Schannel et wolfSSL

EXEMPLE

int main(void)
{
  CURL *curl = curl_easy_init();
  if(curl) {
    CURLcode res;
    curl_easy_setopt(curl, CURLOPT_URL, "https://example.com/foo.bin");
    /* réutiliser les magasins de certificats uniquement pendant une courte période */
    curl_easy_setopt(curl, CURLOPT_CA_CACHE_TIMEOUT, 60L);
    res = curl_easy_perform(curl);
    /* dans cette deuxième requête, le cache n'est pas utilisé si plus de
       soixante secondes se sont écoulées depuis la connexion précédente */
    res = curl_easy_perform(curl);
    curl_easy_cleanup(curl);
  }
}

HISTORIQUE

Cette option est prise en charge par OpenSSL et ses forks (depuis 7.87.0), Schannel (depuis 8.5.0), wolfSSL (depuis 8.9.0) et GnuTLS (depuis 8.9.0).

DISPONIBILITÉ

Ajouté dans curl 7.87.0

VALEUR DE RETOUR

curl_easy_setopt(3) retourne un CURLcode indiquant le succès ou l'erreur.

CURLE_OK (0) signifie que tout s'est bien passé, une valeur non nulle indique une erreur, voir libcurl-errors(3).

VOIR AUSSI

CURLOPT_CAINFO(3), CURLOPT_CAINFO_BLOB(3), CURLOPT_CAPATH(3), CURLOPT_SSL_VERIFYHOST(3), CURLOPT_SSL_VERIFYPEER(3)
