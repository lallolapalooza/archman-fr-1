DESCRIPTION

Ces fonctions de bas niveau doivent être appelées par les programmes qui traitent directement la base de données terminfo pour gérer certaines capacités du terminal, comme la programmation des touches de fonction. Pour toute autre fonctionnalité, les fonctions curses sont plus adaptées et leur utilisation est recommandée.

Aucune de ces fonctions n'utilise (ou n'est consciente) de chaînes de caractères multibytes comme UTF-8.

  • Les noms et codes des capacités utilisent l'ensemble de caractères portable POSIX.
  • Les valeurs de chaînes de capacités n'ont pas d'encodage associé ; ce sont des chaînes de caractères 8 bits.

Initialisation

Initialement, setupterm doit être appelé. Les fonctions curses de haut niveau initscr et newterm appellent setupterm pour initialiser l'ensemble de bas niveau des variables dépendantes du terminal listées dans term_variables(3X).

Les applications peuvent utiliser les capacités du terminal soit directement (via les définitions d'en-tête), soit par des fonctions spéciales. Les fichiers d'en-tête curses.h et term.h doivent être inclus (dans cet ordre) pour obtenir les définitions de ces chaînes, nombres et drapeaux.

Les variables terminfo lines et columns sont initialisées par setupterm comme suit.

  • Si use_env(FALSE) a été appelé, les valeurs pour lines et columns spécifiées dans terminfo sont utilisées.
  • Sinon, si les variables d'environnement LINES et COLUMNS existent, leurs valeurs sont utilisées. Si ces variables d'environnement n'existent pas et que le programme s'exécute dans une fenêtre, la taille actuelle de la fenêtre est utilisée. Sinon, si les variables d'environnement n'existent pas, les valeurs pour lines et columns spécifiées dans la base de données terminfo sont utilisées.

Les chaînes paramétrées doivent être passées par tparm pour les instancier. Toutes les chaînes terminfo (y compris la sortie de tparm) doivent être envoyées au périphérique terminal avec tputs ou putp. Appelez reset_shell_mode pour restaurer les modes du terminal avant de quitter ; voir curs_kernel(3X).

Les programmes qui utilisent l'adressage du curseur doivent

  • afficher enter_ca_mode au démarrage et
  • afficher exit_ca_mode avant de quitter.

Les programmes qui exécutent des sous-processus shell doivent

  • appeler reset_shell_mode et afficher exit_ca_mode avant que le shell ne soit appelé et
  • afficher enter_ca_mode et appeler reset_prog_mode après le retour du shell.

setupterm lit la base de données terminfo, initialisant les structures terminfo, mais ne configure pas les structures de virtualisation de sortie utilisées par curses. Ses paramètres suivent.

term
est le type de terminal, une chaîne de caractères. Si term est nul, la variable d'environnement TERM est lue.
filedes
est le descripteur de fichier utilisé pour obtenir et définir les modes d'E/S du terminal.
Les applications de plus haut niveau utilisent newterm(3X) pour initialiser le terminal, en passant un flux de sortie plutôt qu'un descripteur. Dans curses, les deux sont identiques car newterm appelle setupterm, en passant le descripteur de fichier dérivé de son paramètre de flux de sortie.
errret
pointe vers un emplacement optionnel où un code d'erreur peut être renvoyé à l'appelant. Si errret n'est pas nul, alors setupterm retourne OK ou ERR et stocke une valeur d'état dans l'entier pointé par errret. Une valeur de retour de OK combinée à un état de 1 dans errret est normale.
Si ERR est retourné, examinez errret :
1
signifie que le terminal est une copie papier (hardcopy), et ne peut pas être utilisé pour les applications curses.
setupterm détermine si l'entrée est un type copie papier en vérifiant la capacité hardcopy (hc).
0
signifie que le terminal n'a pas pu être trouvé, ou qu'il s'agit d'un type générique, ayant trop peu d'informations pour que les applications curses puissent s'exécuter.
setupterm détermine si l'entrée est un type générique en vérifiant la capacité generic_type (gn).
-1
signifie que la base de données terminfo n'a pas pu être trouvée.
Si errret est nul, setupterm signale un message d'erreur en cas de problème et quitte. Par conséquent, l'appel le plus simple est :
setupterm((char *)0, 1, (int *)0);
ce qui utilise toutes les valeurs par défaut et envoie la sortie vers stdout.

L'état du terminal

setupterm stocke ses informations sur le terminal dans une structure TERMINAL pointée par la variable globale cur_term. S'il détecte une erreur, ou décide que le terminal est inadapté (copie papier ou générique), il jette ces informations, les rendant indisponibles pour les applications.

Si setupterm est appelé plusieurs fois pour le même type de terminal, il réutilisera les informations. Il ne maintient qu'une seule copie des capacités d'un terminal donné en mémoire. S'il est appelé pour différents types de terminaux, setupterm alloue un nouvel espace pour chaque ensemble de capacités de terminal

Tamponnage de

sortie

Les versions antérieures de ncurses supposaient que le descripteur de fichier passé à setupterm depuis initscr ou newterm utilise une E/S tamponnée, et écrirait dans le flux correspondant. En plus de la limitation selon laquelle le terminal était laissé en mode tampon par blocs à la sortie (comme System V curses), cela était problématique car ncurses ne permettait pas un moyen fiable de nettoyer à la réception de SIGTSTP

La version actuelle (ncurses6) utilise des tampons de sortie gérés directement par ncurses. Certaines des fonctions de bas niveau décrites dans cette page de manuel écrivent dans la sortie standard. Elles ne sont pas sûres vis-à-vis des signaux. Les fonctions de haut niveau dans ncurses emploient des versions alternatives de ces f

Autres questions de

Dans SVr4, set_curterm renvoie un int, OK ou ERR. Nous avons choisi d'implémenter la sémantique de X/Open

Curses.

Dans SVr4, le troisième argument de tputs a le type «int (*putc)(char) »

X/Open Curses note qu'après avoir appelé mvcur, l'état curses peut ne pas correspondre à l'état réel du terminal, et qu'une application doit toucher et rafraîchir la fenêtre avant de reprendre les appels normaux de curses. Ainsi, bien qu'elle soit documentée comme une fonction terminfo, mvcur est en réalité une fonction curses qui n'est pas bien

spécifiée.
