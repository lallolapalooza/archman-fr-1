CURLOPT_SSLVERSION(3)

CURLOPT_SSLVERSION(3) Manuel des fonctions de bibliothèque CURLOPT_SSLVERSION(3)

NOM

CURLOPT_SSLVERSION - version TLS/SSL préférée

SYNTAXE

#include <curl/curl.h>
CURLcode curl_easy_setopt(CURL *handle, CURLOPT_SSLVERSION, long version);

DESCRIPTION

Passe un entier long (long) en paramètre pour contrôler la plage des versions SSL/TLS à utiliser.

Les versions SSL et TLS ont typiquement évolué des versions les moins sécurisées vers des versions de plus en plus sécurisées dans cet ordre historique : SSL v2, SSLv3, TLS v1.0, TLS v1.1, TLS v1.2 et le plus récent TLS v1.3.

Utilisez l'une des définitions disponibles à cet effet. Les options disponibles sont :

CURL_SSLVERSION_DEFAULT
La plage de versions acceptables par défaut. La version minimale acceptable est par défaut TLS v1.2 depuis la version 8.16.0 (sauf si la bibliothèque TLS a une règle plus stricte).
CURL_SSLVERSION_TLSv1
TLS v1.0 ou ultérieur
CURL_SSLVERSION_SSLv2
SSL v2 - refusé
CURL_SSLVERSION_SSLv3
SSL v3 - refusé
CURL_SSLVERSION_TLSv1_0
TLS v1.0 ou ultérieur
CURL_SSLVERSION_TLSv1_1
TLS v1.1 ou ultérieur
CURL_SSLVERSION_TLSv1_2
TLS v1.2 ou ultérieur
CURL_SSLVERSION_TLSv1_3
TLS v1.3 ou ultérieur

La version TLS maximale peut être définie en utilisant une des macros CURL_SSLVERSION_MAX_ ci-dessous. Il est également possible d'utiliser l'opérateur OU binaire (`|`) pour combiner une des macros CURL_SSLVERSION_ avec une des macros CURL_SSLVERSION_MAX_.

CURL_SSLVERSION_MAX_DEFAULT
Ce drapeau définit la version TLS maximale prise en charge par libcurl, ou la valeur par défaut de la bibliothèque SSL est utilisée. libcurl utilise une valeur maximale par défaut raisonnable, qui était TLS v1.2 avant la version 7.61.0 et est TLS v1.3 depuis - en supposant que la bibliothèque TLS le supporte.
CURL_SSLVERSION_MAX_TLSv1_0
Ce drapeau définit la version TLS maximale prise en charge comme TLS v1.0.
CURL_SSLVERSION_MAX_TLSv1_1
Ce drapeau définit la version TLS maximale prise en charge comme TLS v1.1.
CURL_SSLVERSION_MAX_TLSv1_2
Ce drapeau définit la version TLS maximale prise en charge comme TLS v1.2.
CURL_SSLVERSION_MAX_TLSv1_3
Ce drapeau définit la version TLS maximale prise en charge comme TLS v1.3.

DÉFAUT

CURL_SSLVERSION_DEFAULT

PROTOCOLES

Cette fonctionnalité affecte tous les protocoles basés sur TLS : HTTPS, FTPS, IMAPS, POP3S, SMTPS, etc.

Tous les backends TLS prennent en charge cette option.

EXEMPLE

int main(void)
{
  CURL *curl = curl_easy_init();
  if(curl) {
    curl_easy_setopt(curl, CURLOPT_URL, "https://example.com");
    /* demander à libcurl d'utiliser TLS version 1.0 ou ultérieure */
    curl_easy_setopt(curl, CURLOPT_SSLVERSION, CURL_SSLVERSION_TLSv1);
    /* Exécuter la requête */
    curl_easy_perform(curl);
  }
}

HISTORIQUE

SSLv2 est désactivé par défaut depuis la version 7.18.1. La disponibilité d'autres versions SSL peut varier en fonction du backend pour lequel libcurl a été compilé.

SSLv3 est désactivé par défaut depuis la version 7.39.0.

SSLv2 et SSLv3 sont complètement refusés depuis curl 7.77.0

Depuis la version 8.10.0, wolfSSL est entièrement pris en charge. Avant la version 8.10.0, les macros MAX n'étaient pas prises en charge avec wolfSSL et les autres macros ne définissaient pas un minimum, mais limitaient la version TLS à uniquement celle spécifiée.

Le support de Rustls a été ajouté dans la version 8.10.0.

Les macros CURL_SSLVERSION_* sont devenues des types long dans la version 8.16.0 ; avant cette version, un transtypage en long était nécessaire lorsqu'elles étaient passées à curl_easy_setopt(3).

DISPONIBILITÉ

Ajouté dans curl 7.1

VALEUR DE RETOUR

curl_easy_setopt(3) retourne un code CURLcode indiquant succès ou erreur.

CURLE_OK (0) signifie que tout s'est bien passé, une valeur non nulle indique qu'une erreur s'est produite. Voir libcurl-errors(3).

VOIR AUSSI

CURLOPT_HTTP_VERSION(3), CURLOPT_IPRESOLVE(3), CURLOPT_PROXY_SSLVERSION(3), CURLOPT_USE_SSL(3)
