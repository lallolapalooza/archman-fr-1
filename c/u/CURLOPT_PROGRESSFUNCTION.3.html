CURLOPT_PROGRESSFUNCTION(3)

Paquet: curl

Licences: MIT

CURLOPT_PROGRESSFUNCTION(3) Manuel des fonctions de bibliothèque CURLOPT_PROGRESSFUNCTION(3)

NOM

CURLOPT_PROGRESSFUNCTION - fonction de rappel de suivi de progression

SYNOPSIS

#include <curl/curl.h>
int progress_callback(void *clientp,
                      double dltotal,
                      double dlnow,
                      double ultotal,
                      double ulnow);
CURLcode curl_easy_setopt(CURL *handle, CURLOPT_PROGRESSFUNCTION,
                          progress_callback);

DESCRIPTION

Passez un pointeur vers votre fonction de rappel, qui doit correspondre au prototype indiqué ci-dessus.

Cette option est obsolète et nous encourageons les utilisateurs à utiliser plutôt la nouvelle fonction CURLOPT_XFERINFOFUNCTION(3), si possible.

Cette fonction est appelée par libcurl à la place de son équivalent interne à intervalles fréquents. Pendant que les données sont transférées, elle est invoquée fréquemment, et pendant les périodes lentes, comme lorsque rien n'est transféré, elle peut ralentir jusqu'à un appel par seconde.

clientp est le pointeur défini avec CURLOPT_PROGRESSDATA(3), il n'est pas utilisé par libcurl mais est uniquement transmis de l'application à la fonction de rappel.

La fonction de rappel est informée de la quantité de données que libcurl est sur le point de transférer et a transférée, en nombre d'octets. dltotal est le nombre total d'octets que libcurl s'attend à télécharger dans ce transfert. dlnow est le nombre d'octets téléchargés jusqu'à présent. ultotal est le nombre total d'octets que libcurl s'attend à téléverser dans ce transfert. ulnow est le nombre d'octets téléversés jusqu'à présent.

Les valeurs d'arguments inconnues/inutilisées passées à la fonction de rappel sont définies à zéro (par exemple, si vous téléchargez uniquement des données, la taille de téléversement reste à 0). Souvent, la fonction de rappel est appelée une ou plusieurs fois d'abord, avant de connaître les tailles de données, donc un programme doit être conçu pour gérer cela.

Retournez zéro depuis la fonction de rappel si tout va bien.

Si votre fonction de rappel renvoie CURL_PROGRESSFUNC_CONTINUE, libcurl continue d'exécuter la fonction de suivi par défaut.

Retournez 1 depuis cette fonction de rappel pour faire abandonner le transfert à libcurl et renvoyer CURLE_ABORTED_BY_CALLBACK.

Si vous transférez des données avec l'interface multi, cette fonction n'est pas appelée pendant les périodes d'inactivité, sauf si vous appelez la fonction libcurl appropriée qui effectue les transferts.

CURLOPT_NOPROGRESS(3) doit être défini à 0 pour que cette fonction soit effectivement appelée.

DÉFAUT

NULL. libcurl a un indicateur de progression interne. Cela est rarement souhaité par les utilisateurs.

PROTOCOLES

Cette fonctionnalité affecte tous les protocoles pris en charge

EXEMPLE

struct progress {
  char *private;
  size_t size;
};
static int progress_callback(void *clientp,
                             double dltotal,
                             double dlnow,
                             double ultotal,
                             double ulnow)
{
  struct progress *memory = clientp;
  printf("private: %p\n", memory->private);
  /* utiliser les valeurs */
  return 0; /* tout va bien */
}
int main(void)
{
  struct progress data;
  CURL *curl = curl_easy_init();
  if(curl) {
    /* passer la structure à la fonction de rappel */
    curl_easy_setopt(curl, CURLOPT_PROGRESSDATA, &data);
    curl_easy_setopt(curl, CURLOPT_PROGRESSFUNCTION, progress_callback);
    curl_easy_perform(curl);
  }
}

OBSOLÈTE

Obsolète depuis la version 7.32.0.

DISPONIBILITÉ

Ajouté dans curl 7.1

VALEUR DE RETOUR

curl_easy_setopt(3) renvoie un code CURLcode indiquant le succès ou l'erreur.

CURLE_OK (0) signifie que tout s'est bien passé, une valeur non nulle indique une erreur, voir libcurl-errors(3).
