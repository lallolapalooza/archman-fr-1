CURLOPT_TCP_NODELAY(3)

Paquet: curl

Licences: MIT

CURLOPT_TCP_NODELAY(3) Manuel des fonctions de bibliothèque CURLOPT_TCP_NODELAY(3)

NOM

CURLOPT_TCP_NODELAY - l'option TCP_NODELAY

SYNOPIS

#include <curl/curl.h>
CURLcode curl_easy_setopt(CURL *handle, CURLOPT_TCP_NODELAY, long nodelay);

DESCRIPTION

Passe un long spécifiant si l'option TCP_NODELAY doit être activée ou désactivée (1L = activée, 0 = désactivée). L'option est activée par défaut. Cela n'a aucun effet une fois la connexion établie.

L'activation de cette option sur 1L désactive l'algorithme de Nagle sur les connexions créées à l'aide de ce handle. Le but de cet algorithme est de minimiser le nombre de petits paquets sur le réseau (où "petits paquets" signifie des segments TCP inférieurs à la taille maximale de segment pour le réseau).

Maximiser la quantité de données envoyées par segment TCP est une bonne chose car cela amortit les frais d'envoi. Cependant, dans certains cas, de petits segments peuvent devoir être envoyés sans délai. C'est moins efficace que d'envoyer de plus grandes quantités de données à la fois, et peut contribuer à la congestion du réseau si cela est excessif.

DÉFAUT

1

PROTOCOLES

Cette fonctionnalité affecte uniquement tcp

EXEMPLE

int main(void)
{
  CURL *curl = curl_easy_init();
  if(curl) {
    curl_easy_setopt(curl, CURLOPT_URL, "https://example.com");
    /* laisser Nagle activé */
    curl_easy_setopt(curl, CURLOPT_TCP_NODELAY, 0L);
    curl_easy_perform(curl);
  }
}

HISTORIQUE

Le défaut a été changé de 1 à 0 dans la version 7.50.2.

DISPONIBILITÉ

Ajouté dans curl 7.11.2

VALEUR DE RETOUR

curl_easy_setopt(3) renvoie un code CURLcode indiquant le succès ou l'erreur.

CURLE_OK (0) signifie que tout était correct, une valeur non nulle indique une erreur, voir libcurl-errors(3).
