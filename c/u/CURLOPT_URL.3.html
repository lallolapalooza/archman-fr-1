DESCRIPTIO

N

Passez un pointeur vers l' URL à utiliser. Le paramètre doit être un char * vers une chaîne terminée par un caractère nul qui doit être encodée en URL selon le format suivant

:

scheme://host:

port/path

Pour une explication plus détaillée du format, veuillez consulter la RFC

3986.

libcurl ne valide pas la syntaxe et n'utilise pas l'URL avant le début du transfert. Même si vous définissez une valeur absurde ici, curl_easy_setopt(3) pourrait quand même renvoyer CURLE_OK

.

Si l'URL fournie ne contient pas de nom de schéma (comme "http://" ou "ftp://" etc), alors libcurl le déduit à partir de l'hôte. Si le nom de sous-domaine le plus externe correspond à DICT, FTP, IMAP, LDAP, POP3 ou SMTP, alors ce protocole est utilisé, sinon HTTP est utilisé. Depuis la version 7.45.0, la déduction peut être désactivée en définissant un protocole par défaut, voir CURLOPT_DEFAULT_PROTOCOL(3) pour plus de

détails.

Si le protocole, qu'il soit spécifié par le schéma de l'URL ou déduit par libcurl à partir du nom d'hôte, n'est pas pris en charge par libcurl, alors CURLE_UNSUPPORTED_PROTOCOL est renvoyé soit par curl_easy_perform(3) ou curl_multi_perform(3) lorsque vous les appelez. Utilisez curl_version_info(3) pour obtenir des informations détaillées sur les protocoles pris en charge par la version de libcurl que vous

utilisez.

CURLOPT_PROTOCOLS_STR(3) peut être utilisé pour limiter les protocoles que libcurl peut utiliser pour ce transfert, indépendamment de ceux que libcurl a été compilé pour prendre en charge. Cela peut être utile si vous acceptez l'URL d'une source externe et souhaitez limiter l'accessibilité

.

La chaîne de CURLOPT_URL(3) est ignorée si CURLOPT_CURLU(3) est

défini.

Soit CURLOPT_URL(3) ou CURLOPT_CURLU(3) doit être défini avant le début d'un

transfert.

L'application n'a pas besoin de conserver la chaîne après avoir défini cette

option.

Utiliser cette option plusieurs fois fait que la dernière chaîne définie remplace les précédentes. Définissez-la à NULL pour désactiver son utilisation à nouveau. Notez cependant que libcurl a besoin d'une URL définie pour pouvoir effectuer un

transfert.

L'analyseur utilisé pour traiter l'URL définie avec CURLOPT_URL(3) est le même que celui utilisé par cu

rl_url_
set(3).

E

La chaîne pointée par l'argument CURLOPT_URL(3) est généralement censée être une séquence de caractères utilisant une compatibilité

ASCII.

Si libcurl est compilé avec la prise en charge IDN, la partie nom de serveur de l'URL peut utiliser un « nom international » en utilisant l'encodage courant (selon la locale) ou UTF-8 (lorsque WinIDN est utilisé ; ou une version Unicode Windows utilisant libidn2)

.

PRÉOCCUPATIONS DE

SÉCURITÉ

Les applications peuvent parfois trouver pratique de permettre aux utilisateurs de spécifier des URL à diverses fins et cette chaîne serait alors transmise à cette

option.

Obtenir une URL d'une partie externe non fiable soulève plusieurs préoccupations de sécurité

:

Si vous avez une application qui s'exécute comme ou dans une application serveur, obtenir une URL non filtrée peut facilement tromper votre application pour accéder à une ressource locale au lieu d'une ressource distante. Se protéger contre les accès localhost est difficile lorsque l'on accepte des URL fournies par

l'utilisateur.

De telles URL personnalisées peuvent également accéder à d'autres ports que ceux prévus, car les numéros de port font partie du format d'URL standard. La combinaison d'un hôte local et d'un numéro de port personnalisé peut permettre à des utilisateurs externes de jouer des tours avec vos services

locaux.

Accepter des URL externes peut également utiliser d'autres protocoles que http:// ou d'autres protocoles courants. Restreignez ce que vous acceptez avec CURLOPT_PROTOCOLS

_STR(3).

Les URL fournies par l'utilisateur peuvent également être faites pour pointer vers des sites qui redirigent plus loin (possiblement vers d'autres protocoles aussi). Considérez vos CURLOPT_FOLLOWLOCATION(3) et CURLOPT_REDIR_PROTOCOLS

_STR(3)
paramètres.

RETOUR

curl_easy_setopt(3) renvoie un CURLcode indiquant le succès ou une

erreur.

CURLE_OK (0) signifie que tout s'est bien passé, une valeur non nulle signifie qu'une erreur s'est produite, voir libcurl-erro

rs(3).

Notez que curl_easy_setopt(3) n'analyse pas la chaîne donnée, donc si une URL invalide est fournie, elle n'est pas détectée jusqu'à ce que curl_easy_perform(3) ou

similaire
soit appelé.
