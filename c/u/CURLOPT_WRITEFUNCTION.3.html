CURLOPT_WRITEFUNCTION(3)

Paquet: curl

Licences: MIT

CURLOPT_WRITEFUNCTION(3) Manuel des fonctions de bibliothèque CURLOPT_WRITEFUNCTION(3)

NOM

CURLOPT_WRITEFUNCTION - callback pour l'écriture des données reçues

SYNTAXE

#include <curl/curl.h>
size_t write_callback(char *ptr, size_t size, size_t nmemb, void *userdata);
CURLcode curl_easy_setopt(CURL *handle, CURLOPT_WRITEFUNCTION, write_callback);

DESCRIPTION

Passez un pointeur vers votre fonction de rappel, qui doit correspondre au prototype montré ci-dessus.

Cette fonction de rappel est appelée par libcurl dès qu'il y a des données reçues qui doivent être enregistrées. Pour la plupart des transferts, cette fonction de rappel est appelée plusieurs fois et chaque invocation délivre un autre bloc de données. ptr pointe vers les données délivrées, et la taille de ces données est nmemb ; size est toujours égal à 1.

Les données passées à cette fonction ne sont pas terminées par un caractère nul.

La fonction de rappel reçoit autant de données que possible à chaque invocation, mais vous ne devez faire aucune supposition. Cela peut être un octet, cela peut être des milliers. La quantité maximale de données de corps passées à la fonction de rappel d'écriture est définie dans le fichier d'en-tête curl.h : CURL_MAX_WRITE_SIZE (la valeur par défaut habituelle est de 16 Ko). Si CURLOPT_HEADER(3) est activé, ce qui fait que les données d'en-tête sont passées à la fonction de rappel d'écriture, vous pouvez recevoir jusqu'à CURL_MAX_HTTP_HEADER octets de données d'en-tête. Cela signifie généralement 100 Ko.

Cette fonction peut être appelée avec zéro octet de données si le fichier transféré est vide.

Définissez l'argument userdata avec l'option CURLOPT_WRITEDATA(3).

Votre fonction de rappel doit renvoyer le nombre d'octets réellement traités. Si ce montant diffère du montant passé à votre fonction de rappel, cela signale une condition d'erreur à la bibliothèque. Cela provoque l'abandon du transfert et la fonction libcurl utilisée renvoie CURLE_WRITE_ERROR.

Vous pouvez également abandonner le transfert en renvoyant CURL_WRITEFUNC_ERROR (ajouté dans la version 7.87.0), ce qui fait que CURLE_WRITE_ERROR soit renvoyé.

Si la fonction de rappel renvoie CURL_WRITEFUNC_PAUSE, elle met en pause ce transfert. Voir curl_easy_pause(3) pour plus de détails.

Définissez cette option sur NULL pour utiliser la fonction interne par défaut à la place de votre fonction de rappel. La fonction interne par défaut écrit les données dans le FILE * donné avec CURLOPT_WRITEDATA(3).

Cette option n'active pas HSTS, vous devez utiliser CURLOPT_HSTS_CTRL(3) pour ce faire.

DÉFAUT

fwrite(3)

PROTOCOLES

Cette fonctionnalité affecte tous les protocoles pris en charge

EXEMPLE

#include <stdlib.h> /* pour realloc */
#include <string.h> /* pour memcpy */
struct memory {
  char *response;
  size_t size;
};
static size_t cb(char *data, size_t size, size_t nmemb, void *clientp)
{
  size_t realsize = nmemb;
  struct memory *mem = (struct memory *)clientp;
  char *ptr = realloc(mem->response, mem->size + realsize + 1);
  if(!ptr)
    return 0;  /* out of memory */
  mem->response = ptr;
  memcpy(&(mem->response[mem->size]), data, realsize);
  mem->size += realsize;
  mem->response[mem->size] = 0;
  return realsize;
}
int main(void)
{
  struct memory chunk = {0};
  CURLcode res;
  CURL *curl = curl_easy_init();
  if(curl) {
    /* send all data to this function  */
    curl_easy_setopt(curl, CURLOPT_WRITEFUNCTION, cb);
    /* we pass our 'chunk' struct to the callback function */
    curl_easy_setopt(curl, CURLOPT_WRITEDATA, (void *)&chunk);
    /* send a request */
    res = curl_easy_perform(curl);
    /* remember to free the buffer */
    free(chunk.response);
    curl_easy_cleanup(curl);
  }
}

HISTORIQUE

Le support du code de retour CURL_WRITEFUNC_PAUSE a été ajouté dans la version 7.18.0.

DISPONIBILITÉ

Ajouté dans curl 7.1

VALEUR DE RETOUR

Retourne CURLE_OK.
