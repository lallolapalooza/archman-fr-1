CURLOPT_UNRESTRICTED_AUTH(3)

Paquet: curl

Licences: MIT

CURLOPT_UNRESTRICTED_AUTH(3) Manuel des fonctions de bibliothèque CURLOPT_UNRESTRICTED_AUTH(3)

NOM

CURLOPT_UNRESTRICTED_AUTH - envoyer les identifiants à d'autres hôtes également

SYNTAXE

#include <curl/curl.h>
CURLcode curl_easy_setopt(CURL *handle, CURLOPT_UNRESTRICTED_AUTH,
                          long goahead);

DESCRIPTION

Définissez le paramètre long goahead à 1L pour que libcurl continue d'envoyer les identifiants (utilisateur+mot de passe) ou les en-têtes de cookie explicitement définis lors du suivi des emplacements, même lorsque l'hôte change. Cette option n'est pertinente que lorsque CURLOPT_FOLLOWLOCATION(3) est définie.

En outre, lorsque cette option n'est pas utilisée ou est définie sur 0L, libcurl n'envoie pas les en-têtes Authentication: ou Cookie: personnalisés ni générés en interne aux hôtes autres que celui utilisé pour l'URL initiale. Un hôte différent signifie que le nom d'hôte, le schéma de protocole ou le numéro de port a changé.

Par défaut, libcurl n'envoie les en-têtes Authentication: ou Cookie: explicitement définis qu'à l'hôte initial tel que donné dans l'URL d'origine, afin d'éviter de divulguer le nom d'utilisateur + mot de passe à d'autres sites.

Cette option doit être utilisée avec prudence : lorsque curl suit les redirections, il récupère aveuglément la prochaine URL comme indiqué par le serveur. Définir CURLOPT_UNRESTRICTED_AUTH(3) à 1L fait confiance à curl envers le serveur et envoie des identifiants potentiellement sensibles à n'importe quel hôte vers lequel le serveur pointe, possiblement encore et encore car les hôtes suivants peuvent continuer à rediriger vers de nouveaux hôtes.

En raison du fonctionnement de HTTP, presque tous les en-têtes peuvent être faits pour contenir des données qu'un client peut ne pas vouloir transmettre à d'autres serveurs que l'hôte initialement prévu et pour tous les autres en-têtes que les deux mentionnés ci-dessus, il n'y a aucune protection contre cela lorsque libcurl est invité à suivre les redirections.

PAR DÉFAUT

0

PROTOCOLES

Cette fonctionnalité affecte uniquement http

EXEMPLE

int main(void)
{
  CURL *curl = curl_easy_init();
  if(curl) {
    curl_easy_setopt(curl, CURLOPT_URL, "https://example.com");
    curl_easy_setopt(curl, CURLOPT_FOLLOWLOCATION, 1L);
    curl_easy_setopt(curl, CURLOPT_UNRESTRICTED_AUTH, 1L);
    curl_easy_perform(curl);
  }
}

DISPONIBILITÉ

Ajouté dans curl 7.10.4

VALEUR DE RETOUR

curl_easy_setopt(3) retourne un CURLcode indiquant le succès ou l'erreur.

CURLE_OK (0) signifie que tout s'est bien passé, une valeur non nulle indique une erreur, voir libcurl-errors(3).

VOIR AUSSI

CURLINFO_REDIRECT_COUNT(3), CURLOPT_FOLLOWLOCATION(3), CURLOPT_MAXREDIRS(3), CURLOPT_REDIR_PROTOCOLS_STR(3), CURLOPT_USERPWD(3)
