curl_global_cleanup(3) Manuel des fonctions de bibliothèque curl_global_cleanup(3)

NOM

curl_global_cleanup - nettoyage global de libcurl

SYNOPSIS

#include <curl/curl.h>
void curl_global_cleanup(void);

DESCRIPTION

Cette fonction libère les ressources acquises par curl_global_init(3).

Vous devez appeler curl_global_cleanup(3) une fois pour chaque appel que vous effectuez à curl_global_init(3), une fois que vous avez terminé d'utiliser libcurl.

Cette fonction est thread-safe depuis libcurl 7.84.0 si curl_version_info(3) possède le bit de fonctionnalité CURL_VERSION_THREADSAFE (sur la plupart des plateformes).

Si ce n'est pas thread-safe, vous ne devez pas appeler cette fonction lorsqu'un autre fil d'exécution du programme (c'est-à-dire un fil d'exécution partageant la même mémoire) est actif. Cela ne concerne pas seulement les autres fils d'exécution qui utilisent libcurl. Étant donné que curl_global_cleanup(3) appelle des fonctions d'autres bibliothèques qui ne sont pas thread-safe de la même manière, cela pourrait entrer en conflit avec tout autre fil d'exécution utilisant ces autres bibliothèques.

Voir la description dans libcurl(3) des exigences de l'environnement global pour plus de détails sur la façon d'utiliser cette fonction.

MISE EN GARDE

curl_global_cleanup(3) ne bloque pas en attendant la terminaison des fils d'exécution créés par libcurl (tels que les fils d'exécution utilisés pour la résolution de noms). Si un module contenant libcurl est déchargé dynamiquement pendant que des fils d'exécution créés par libcurl sont encore actifs, votre programme peut planter ou d'autres corruptions peuvent se produire. Nous vous recommandons de ne pas exécuter libcurl à partir d'un module qui peut être déchargé dynamiquement. Ce comportement pourrait être corrigé à l'avenir.

libcurl pourrait ne pas être en mesure de nettoyer complètement après OpenSSL multi-threadé, en fonction de la manière dont OpenSSL a été compilé et chargé en tant que bibliothèque. Il est possible, dans de rares circonstances, qu'une fuite de mémoire se produise à moins que vous n'implémentiez votre propre nettoyage des threads OpenSSL. Référez-vous à libcurl-thread(3).

PROTOCOLES

Cette fonctionnalité affecte tous les protocoles pris en charge

EXEMPLE

int main(void)
{
  curl_global_init(CURL_GLOBAL_DEFAULT);
  /* utilisez libcurl, puis avant de quitter... */
  curl_global_cleanup();
}

DISPONIBILITÉ

Ajouté dans curl 7.8

VALEUR DE RETOUR

Aucune
