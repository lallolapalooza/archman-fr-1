curl_multi_socket_action(3)

Paquet: curl

Licences: MIT

curl_multi_socket_action(3) Manuel des fonctions de bibliothèque curl_multi_socket_action(3)

NOM

curl_multi_socket_action - lire/écrire les données disponibles étant donné une action

SYNTAXE

#include <curl/curl.h>
CURLMcode curl_multi_socket_action(CURLM *multi_handle,
                                   curl_socket_t sockfd,
                                   int ev_bitmask,
                                   int *running_handles);

DESCRIPTION

Lorsque l'application a détecté une action sur un socket géré par libcurl, elle doit appeler curl_multi_socket_action(3) avec l'argument sockfd défini sur le socket ayant l'action. Lorsque les événements sur un socket sont connus, ils peuvent être passés sous forme de masque de bits d'événements ev_bitmask en initialisant d'abord ev_bitmask à 0, puis en ajoutant, par opération OU binaire (|), toute combinaison d'événements parmi CURL_CSELECT_IN, CURL_CSELECT_OUT ou CURL_CSELECT_ERR. Lorsque les événements sur un socket sont inconnus, passez 0 à la place, et libcurl teste le descripteur en interne. Il est également permis de passer CURL_SOCKET_TIMEOUT au paramètre sockfd afin d'initier tout le processus ou lorsqu'un délai expire.

Au retour, running_handles pointe vers le nombre de poignées "easy" actives dans la poignée "multi". Lorsque ce nombre atteint zéro, tous les transferts sont terminés/finis. Lorsque vous appelez curl_multi_socket_action(3) sur un socket spécifique et que le compteur diminue d'un, cela ne signifie PAS nécessairement que ce socket/ce transfert précis est celui qui s'est terminé. Utilisez curl_multi_info_read(3) pour savoir quelle poignée "easy" s'est terminée.

La fonction curl_multi_socket_action(3) informe l'application des mises à jour du statut du socket (descripteur de fichier) en effectuant aucun, un, ou plusieurs appels à la fonction de rappel de socket définie avec l'option CURLMOPT_SOCKETFUNCTION(3) à curl_multi_setopt(3). Elles mettent à jour le statut avec les changements depuis le dernier appel de la fonction de rappel.

Obtenez le temps d'attente en définissant l'option CURLMOPT_TIMERFUNCTION(3) avec curl_multi_setopt(3). Votre application sera alors appelée avec des informations sur la durée maximale d'attente pour les actions sur les sockets avant d'effectuer l'action de délai d'attente : appelez la fonction curl_multi_socket_action(3) avec le paramètre sockfd défini sur CURL_SOCKET_TIMEOUT. Vous pouvez également utiliser la fonction curl_multi_timeout(3) pour interroger la valeur à tout moment, mais pour un système basé sur les événements, l'utilisation de la fonction de rappel est bien meilleure que de dépendre de l'interrogation de la valeur de délai d'attente.

Lorsque cette fonction retourne une erreur, l'état de tous les transferts est incertain et ils ne peuvent pas être poursuivis. curl_multi_socket_action(3) ne doit plus être appelée sur la même poignée "multi" après qu'une erreur ait été retournée, à moins de retirer au préalable toutes les poignées et d'en ajouter de nouvelles.

USAGE TYPIQUE

1. Créez une poignée "multi"

2. Définissez la fonction de rappel de socket avec CURLMOPT_SOCKETFUNCTION(3)

3. Définissez la fonction de rappel de délai d'attente avec CURLMOPT_TIMERFUNCTION(3), pour savoir quelle valeur de délai d'attente utiliser lors de l'attente des activités sur les sockets.

4. Ajoutez des poignées "easy" avec curl_multi_add_handle()

5. Fournissez des moyens de gérer les sockets utilisés par libcurl, afin de pouvoir vérifier leur activité. Cela peut être fait par le code de votre application, ou via une bibliothèque externe comme libevent ou glib.

6. Appelez curl_multi_socket_action(..., CURL_SOCKET_TIMEOUT, 0, ...) pour démarrer le tout. Pour obtenir un ou plusieurs appels de fonctions de rappel.

7. Attendez une activité sur l'un des sockets de libcurl, utilisez la valeur de délai d'attente qui a été communiquée à votre fonction de rappel.

8. Lorsqu'une activité est détectée, appelez curl_multi_socket_action() pour le(s) socket(s) concerné(s). Si aucune activité n'est détectée et que le délai d'attente expire, appelez curl_multi_socket_action(3) avec CURL_SOCKET_TIMEOUT.

PROTOCOLES

Cette fonctionnalité affecte tous les protocoles pris en charge

EXEMPLE

int main(void)
{
  /* la bibliothèque d'événements est informée lorsqu'il y a une activité sur le
     socket 'fd', ce que nous traduisons par un appel à
     curl_multi_socket_action() */
  int running = 0;
  int fd = 3; /* le descripteur qui a eu une action */
  int bitmask = 2; /* quelle activité s'est produite */
  CURLM *multi = curl_multi_init();
  CURLMcode mc = curl_multi_socket_action(multi, fd, bitmask, &running);
  if(mc)
    printf("erreur : %s\n", curl_multi_strerror(mc));
}

DISPONIBILITÉ

Ajouté dans curl 7.15.4

VALEUR DE RETOUR

Cette fonction renvoie un CURLMcode indiquant le succès ou l'erreur.

CURLM_OK (0) signifie que tout s'est bien passé, une valeur non nulle indique qu'une erreur s'est produite, voir libcurl-errors(3).
