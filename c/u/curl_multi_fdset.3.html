Paquet: curl

Licences: MIT

curl_multi_fdset(3) Manuel des fonctions de la bibliothèque curl_multi_fdset(3)

NOM

curl_multi_fdset - extraire les informations des descripteurs de fichier d'un gestionnaire multiple

SYNTAXE

#include <curl/curl.h>
CURLMcode curl_multi_fdset(CURLM *multi_handle,
                           fd_set *read_fd_set,
                           fd_set *write_fd_set,
                           fd_set *exc_fd_set,
                           int *max_fd);

DESCRIPTION

Cette fonction extrait les informations des descripteurs de fichier d'un multi_handle donné. libcurl renvoie ses ensembles fd_set. L'application peut les utiliser pour faire un select(), mais assurez-vous de les FD_ZERO avant d'appeler cette fonction car curl_multi_fdset(3) ajoute seulement ses propres descripteurs, elle ne met pas à zéro et n'enlève pas autrement aucun autre. La fonction curl_multi_perform(3) doit être appelée dès que l'un d'eux est prêt pour la lecture ou l'écriture.

L'argument read_fd_set doit pointer vers un objet de type fd_set qui, au retour, spécifie les descripteurs de fichier à vérifier pour être prêts à la lecture.

L'argument write_fd_set doit pointer vers un objet de type fd_set qui, au retour, spécifie les descripteurs de fichier à vérifier pour être prêts à l'écriture.

L'argument exc_fd_set doit pointer vers un objet de type fd_set qui, au retour, spécifie les descripteurs de fichier à vérifier pour les conditions d'erreur.

Si aucun descripteur de fichier n'est défini par libcurl, max_fd contient -1 au retour de cette fonction. Sinon, il contient le numéro de descripteur le plus élevé défini par libcurl. Lorsque libcurl renvoie -1 dans max_fd, c'est parce que libcurl fait actuellement quelque chose qui ne peut pas être surveillé par votre application avec un socket et malheureusement, vous ne pouvez alors pas savoir exactement quand l'action en cours est terminée en utilisant select(). Vous devez alors attendre un certain temps avant de continuer et d'appeler de toute façon curl_multi_perform(3). Combien de temps attendre ? Sauf si curl_multi_timeout(3) vous donne un nombre inférieur, nous suggérons 100 millisecondes environ, mais vous voudrez peut-être le tester dans vos propres conditions pour trouver une valeur appropriée.

Lors de l'utilisation de select(), vous devriez utiliser curl_multi_timeout(3) pour déterminer combien de temps attendre l'action. Appelez curl_multi_perform(3) même si aucune activité n'a été vue sur les fd_sets après l'expiration du délai, car sinon les nouvelles tentatives internes et les délais d'attente peuvent ne pas fonctionner comme vous le pensez et le souhaitez.

Si l'un des sockets utilisés par libcurl est plus grand que ce qui peut être défini dans un fd_set, ce qui, sur les systèmes POSIX, signifie que le descripteur de fichier est plus grand que FD_SETSIZE, alors libcurl essaie de ne pas le définir. Définir un descripteur de fichier trop grand dans un fd_set implique une écriture hors limites qui peut provoquer des plantages, ou pire. L'effet de ne PAS le stocker pourrait éventuellement vous sauver du crash, mais fait que votre programme n'attend PAS les sockets qu'il devrait attendre...

PROTOCOLES

Cette fonctionnalité affecte tous les protocoles pris en charge

EXEMPLE

int main(void)
{
  fd_set fdread;
  fd_set fdwrite;
  fd_set fdexcep;
  int maxfd;
  int rc;
  CURLMcode mc;
  struct timeval timeout = {1, 0};
  CURLM *multi = curl_multi_init();
  do {
    /* appeler curl_multi_perform() */
    FD_ZERO(&fdread);
    FD_ZERO(&fdwrite);
    FD_ZERO(&fdexcep);
    /* obtenir les descripteurs de fichier des transferts */
    mc = curl_multi_fdset(multi, &fdread, &fdwrite, &fdexcep, &maxfd);
    if(mc != CURLM_OK) {
      fprintf(stderr, "curl_multi_fdset() a échoué, code %d.\n", mc);
      break;
    }
    /* attendre une activité sur l'un des sockets */
    rc = select(maxfd + 1, &fdread, &fdwrite, &fdexcep, &timeout);
  } while(!mc);
}

DISPONIBILITÉ

Ajouté dans curl 7.9.6

VALEUR DE RETOUR

Cette fonction renvoie un code CURLMcode indiquant le succès ou l'erreur.

CURLM_OK (0) signifie que tout était correct, une valeur non nulle indique une erreur, voir libcurl-errors(3).
