CURLOPT_SSL_VERIFYPEER(3) Manuel des fonctions de la bibliothèque CURLOPT_SSL_VERIFYPEER(3)

NOM

CURLOPT_SSL_VERIFYPEER - vérifier le certificat SSL du pair

SYNTAXE

#include <curl/curl.h>
CURLcode curl_easy_setopt(CURL *handle, CURLOPT_SSL_VERIFYPEER, long verify);

DESCRIPTION

Passez un entier long en paramètre pour activer ou désactiver.

Cette option détermine si curl vérifie l'authenticité du certificat du pair. Une valeur de 1 signifie que curl vérifie ; 0 (zéro) signifie qu'il ne vérifie pas.

Lors de la négociation d'une connexion TLS ou SSL, le serveur envoie un certificat indiquant son identité. curl vérifie si le certificat est authentique, c'est-à-dire si vous pouvez faire confiance que le serveur est bien celui qu'il prétend être. Cette confiance est basée sur une chaîne de signatures numériques, racinée dans des certificats d'autorité de certification (AC) que vous fournissez. curl utilise un paquet par défaut de certificats d'AC (dont le chemin est déterminé au moment de la compilation) et vous pouvez spécifier des certificats alternatifs avec l'option CURLOPT_CAINFO(3) ou l'option CURLOPT_CAPATH(3).

Lorsque CURLOPT_SSL_VERIFYPEER(3) est activé, et que la vérification ne parvient pas à prouver que le certificat est signé par une AC, la connexion échoue.

Lorsque cette option est désactivée (mise à zéro), les certificats d'AC ne sont pas chargés et la vérification du certificat du pair est simplement ignorée.

L'authentification du certificat n'est pas suffisante pour être sûr du serveur. Vous voudrez généralement également vous assurer que le serveur est celui avec lequel vous avez l'intention de communiquer. Utilisez CURLOPT_SSL_VERIFYHOST(3) pour cela. La vérification que le nom d'hôte dans le certificat est valide pour le nom d'hôte auquel vous vous connectez est effectuée indépendamment de l'option CURLOPT_SSL_VERIFYPEER(3).

AVERTISSEMENT : désactiver la vérification du certificat permet aux mauvais acteurs d'intercepter la communication (attaque de l'homme du milieu) sans que vous le sachiez. Désactiver la vérification rend la communication non sécurisée. Avoir simplement un chiffrement sur un transfert ne suffit pas, car vous ne pouvez pas être sûr que vous communiquez avec le point d'extrémité correct.

Lorsque libcurl utilise des protocoles sécurisés, il fait confiance aux réponses et autorise, par exemple, le stockage et l'utilisation ultérieure d'informations HSTS et Alt-Svc. La désactivation de la vérification du certificat peut amener libcurl à faire confiance et à utiliser ces informations provenant de serveurs malveillants.

DEFAUT

1 - activé

PROTOCOLES

Cette fonctionnalité affecte tous les protocoles basés sur TLS : HTTPS, FTPS, IMAPS, POP3S, SMTPS, etc.

Tous les backends TLS prennent en charge cette option.

EXEMPLE

int main(void)
{
  CURL *curl = curl_easy_init();
  if(curl) {
    curl_easy_setopt(curl, CURLOPT_URL, "https://example.com");
    /* Définir la valeur par défaut : vérification stricte du certificat, s'il vous plaît */
    curl_easy_setopt(curl, CURLOPT_SSL_VERIFYPEER, 1L);
    curl_easy_perform(curl);
  }
}

DISPONIBILITE

Ajouté dans curl 7.4.2

VALEUR DE RETOUR

curl_easy_setopt(3) retourne un code CURLcode indiquant le succès ou l'erreur.

CURLE_OK (0) signifie que tout s'est bien passé, une valeur non nulle indique une erreur, voir libcurl-errors(3).
