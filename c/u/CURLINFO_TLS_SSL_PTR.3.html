CURLINFO_TLS_SSL_PTR(3)

Paquet: curl

Licences: MIT

CURLINFO_TLS_SSL_PTR(3) Manuel des fonctions de bibliothèque CURLINFO_TLS_SSL_PTR(3)

NOM

CURLINFO_TLS_SESSION, CURLINFO_TLS_SSL_PTR - obtenir des informations sur la session TLS

SYNOPSIS

#include <curl/curl.h>
CURLcode curl_easy_getinfo(CURL *handle, CURLINFO_TLS_SSL_PTR,
                           struct curl_tlssessioninfo **session);
/* if you need compatibility with libcurl < 7.48.0 use
   CURLINFO_TLS_SESSION instead: */
CURLcode curl_easy_getinfo(CURL *handle, CURLINFO_TLS_SESSION,
                           struct curl_tlssessioninfo **session);

DESCRIPTION

Passez un pointeur vers une struct curl_tlssessioninfo *. Le pointeur est initialisé pour référencer une struct curl_tlssessioninfo * qui contient une énumération indiquant la bibliothèque SSL utilisée pour la négociation et un pointeur vers la structure de session TLS interne respective de cette bibliothèque SSL sous-jacente.

Cette option peut être utile, par exemple, pour extraire des informations de certificat dans un format adapté à un traitement ultérieur, comme une validation manuelle. Voir la section LIMITATIONS .

struct curl_tlssessioninfo {
  curl_sslbackend backend;
  void *internals;
};

Le membre de structure backend est l'une de ces définitions : CURLSSLBACKEND_NONE (lorsqu'il est compilé sans prise en charge TLS), CURLSSLBACKEND_WOLFSSL, CURLSSLBACKEND_SECURETRANSPORT, CURLSSLBACKEND_GNUTLS, CURLSSLBACKEND_MBEDTLS, CURLSSLBACKEND_NSS, CURLSSLBACKEND_OPENSSL ou CURLSSLBACKEND_SCHANNEL. (Notez que les forks d'OpenSSL sont tous signalés simplement comme OpenSSL ici.)

Le membre de structure internals pointe vers un pointeur spécifique à la bibliothèque TLS pour la connexion SSL active (« en cours d'utilisation »), avec les types sous-jacents suivants :

GnuTLS
gnutls_session_t
OpenSSL
CURLINFO_TLS_SESSION(3): SSL_CTX *

CURLINFO_TLS_SSL_PTR(3): SSL * Depuis la version 7.48.0, le membre internals peut également pointer vers ces autres backends SSL : mbedTLS

mbedTLS
mbedTLS_ssl_context *
Secure Channel
CtxtHandle *
wolfSSL
SSL *

Si le pointeur internals est NULL, alors soit le backend SSL n'est pas pris en charge, soit une session SSL n'a pas encore été établie, soit la connexion n'est plus associée au handle facile (par exemple curl_easy_perform(3) est retourné).

LIMITATIONS

Cette option a certaines limitations qui pourraient la rendre dangereuse lorsqu'il s'agit de la vérification manuelle des certificats.

Cette option ne récupère que le premier pointeur de session SSL en cours d'utilisation pour votre handle facile, cependant votre handle facile peut avoir plus d'une session SSL en cours d'utilisation si vous utilisez FTP sur SSL. C'est parce que le protocole FTP a un canal de contrôle et un canal de données et que l'un ou les deux peuvent passer par SSL. Actuellement, il n'y a aucun moyen de récupérer une deuxième session SSL en cours d'utilisation associée à un handle facile.

Cette option n'a pas été testée à fond avec les protocoles en texte clair qui peuvent être mis à niveau/rétrogradés vers/depuis SSL : FTP, SMTP, POP3, IMAP lorsqu'ils sont utilisés avec CURLOPT_USE_SSL(3). Bien que vous puissiez récupérer le pointeur SSL, il est possible qu'avant que vous ne puissiez le faire, des données (y compris l'authentification) aient déjà été envoyées sur une connexion après qu'elle ait été mise à niveau.

Renégociation. Si votre bibliothèque SSL autorise une renégociation non sécurisée ou une renégociation de telle sorte que le certificat est autorisé à changer, cela peut se produire et le certificat peut changer, et des données peuvent continuer à être envoyées ou reçues après la renégociation mais avant que vous ne puissiez obtenir le pointeur SSL (possiblement) modifié, avec les informations de certificat (possiblement) modifiées.

Au lieu d'utiliser cette option pour interroger les changements de certificat, utilisez CURLOPT_SSL_CTX_FUNCTION(3) pour définir un rappel de vérification, si c'est pris en charge. C'est plus sûr et ne souffre d'aucun des problèmes ci-dessus.

Comment utilisez-vous cette option ? Êtes-vous affecté par l'une de ces limitations ? Merci de nous le faire savoir en laissant un commentaire à https://github.com/curl/curl/issues/685

PROTOCOLES

Cette fonctionnalité affecte tous les protocoles basés sur TLS : HTTPS, FTPS, IMAPS, POP3S, SMTPS, etc.

Cette option ne fonctionne qu'avec les backends TLS suivants : GnuTLS, OpenSSL, Schannel, mbedTLS et wolfSSL

EXEMPLE

#include <curl/curl.h>
#include <openssl/ssl.h>
CURL *curl;
static size_t wf(void *ptr, size_t size, size_t nmemb, void *stream)
{
  const struct curl_tlssessioninfo *info = NULL;
  CURLcode res = curl_easy_getinfo(curl, CURLINFO_TLS_SSL_PTR, &info);
  if(info && !res) {
    if(CURLSSLBACKEND_OPENSSL == info->backend) {
      printf("OpenSSL ver. %s\n", SSL_get_version((SSL*)info->internals));
    }
  }
  return size * nmemb;
}
int main(int argc, char **argv)
{
  CURLcode res;
  curl = curl_easy_init();
  if(curl) {
    curl_easy_setopt(curl, CURLOPT_URL, "https://example.com");
    curl_easy_setopt(curl, CURLOPT_WRITEFUNCTION, wf);
    res = curl_easy_perform(curl);
    curl_easy_cleanup(curl);
  }
  return res;
}

HISTORIQUE

Cette option remplace CURLINFO_TLS_SESSION(3) qui a été ajoutée dans la version 7.34.0. Cette option est exactement la même que cette option, sauf dans le cas d'OpenSSL.

DISPONIBILITÉ

Ajoutée dans curl 7.48.0

VALEUR DE RETOUR

curl_easy_getinfo(3) renvoie un CURLcode indiquant le succès ou une erreur.

CURLE_OK (0) signifie que tout s'est bien passé, une valeur non nulle signifie qu'une erreur s'est produite, voir libcurl-errors(3).

VOIR AUSSI

CURLINFO_TLS_SESSION(3), curl_easy_getinfo(3), curl_easy_setopt(3)
