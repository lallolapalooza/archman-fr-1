NOM

cupsd-logs - Fichiers journaux de cupsd (access_log, error_log et page_log)

DESCRIPTION

cupsd(8) maintient normalement trois fichiers journaux : access_log pour suivre les requêtes soumises au planificateur, error_log pour suivre la progression et les erreurs, et page_log pour suivre les pages imprimées. Les directives de configuration dans cupsd.conf(5) et cups-files.conf(5) contrôlent quelles informations sont journalisées et où elles sont stockées.

FORMAT DU FICHIER JOURNAL D'ACCÈS

Le fichier access_log liste chaque ressource HTTP qui est accédée par un navigateur web ou un client. Chaque ligne est dans une version étendue du soi-disant « Common Log Format » utilisé par de nombreux serveurs web et outils de rapports web :

    hôte groupe utilisateur date-heure "méthode ressource version" statut octets
      opération-ipp statut-ipp

Par exemple :

    10.0.1.2 - - [01/Dec/2005:21:50:28 +0000] "POST / HTTP/1.1" 200 317
      CUPS-Get-Printers successful-ok-ignored-or-substituted-attributes
    localhost - - [01/Dec/2005:21:50:32 +0000] "GET /admin HTTP/1.1"
      200 0 - -
    localhost - - [01/Dec/2005:21:50:32 +0000] "POST / HTTP/1.1"
      200 157 CUPS-Get-Printers
      successful-ok-ignored-or-substituted-attributes
    localhost - - [01/Dec/2005:21:50:32 +0000] "POST / HTTP/1.1"
      200 1411 CUPS-Get-Devices -
    localhost - - [01/Dec/2005:21:50:32 +0000] "GET /admin HTTP/1.1"
      200 6667 - -

Le champ host ne contiendra normalement qu'une adresse IP, sauf si vous avez activé la directive HostNameLookups dans le fichier cupsd.conf ou si l'adresse IP correspond à votre machine locale.

Le champ group contient toujours « - ».

Le champ user est le nom d'utilisateur authentifié de l'utilisateur demandant. Si aucun nom d'utilisateur et mot de passe ne sont fournis pour la requête, ce champ contient « - ».

Le champ date-time est la date et l'heure de la requête en heure locale et est au format « [DD/MON/YYYY:HH:MM:SS +ZZZZ] ».

Le champ method est la méthode HTTP utilisée : « GET », « HEAD », « OPTIONS », « POST » ou « PUT ». Les requêtes « GET » sont utilisées pour obtenir des fichiers du serveur, à la fois pour l'interface web et pour obtenir les fichiers de configuration et les journaux. Les requêtes « HEAD » sont utilisées pour obtenir des informations sur une ressource avant un « GET ». Les requêtes « OPTIONS » sont utilisées pour mettre à niveau les connexions vers le chiffrement TLS. Les requêtes « POST » sont utilisées pour les formulaires de l'interface web et les requêtes IPP. Les requêtes « PUT » sont utilisées pour téléverser des fichiers de configuration.

Le champ resource est le nom de fichier de la ressource demandée.

Le champ version est la version de spécification HTTP utilisée par le client. Pour les clients CUPS, ce sera toujours « HTTP/1.1 ».

Le champ status contient le statut HTTP du résultat de la requête, comme suit :

200
Opération réussie.
201
Fichier créé/modifié avec succès.
304
Le fichier demandé n'a pas changé.
400
Requête HTTP invalide ; cela signifie généralement que vous avez un programme malveillant qui essaie d'accéder à votre serveur.
401
Non autorisé, une authentification (nom d'utilisateur + mot de passe) est requise.
403
Accès interdit ; cela signifie généralement qu'un client a essayé d'accéder à un fichier ou à une ressource pour laquelle il n'a pas la permission.
404
Le fichier ou la ressource n'existe pas.
405
La méthode d'accès à l'URL n'est pas autorisée ; cela signifie généralement que vous avez un navigateur web utilisant votre serveur comme proxy.
413
Requête trop grande ; cela signifie généralement qu'un client a essayé d'imprimer un fichier plus grand que ce que MaxRequestSize autorise.
426
Mise à niveau vers une connexion chiffrée TLS.
500
Erreur de serveur ; cela se produit généralement lorsque le serveur est incapable d'ouvrir/créer un fichier - consultez le fichier error_log pour plus de détails.
501
Le client a demandé le chiffrement mais le support du chiffrement n'est pas activé/compilé.
505
Numéro de version HTTP non pris en charge ; cela signifie généralement que vous avez un programme malveillant qui essaie d'accéder à votre serveur.

Le champ bytes contient le nombre d'octets dans la requête. Pour les requêtes POST, le champ bytes contient le nombre d'octets de données non-IPP qui sont reçus du client.

Le champ ipp-operation contient soit « - » pour les requêtes non-IPP, soit le nom de l'opération IPP pour les requêtes POST contenant une requête IPP.

Le champ ipp-status contient soit « - » pour les requêtes non-IPP, soit le nom du code de statut IPP pour les requêtes POST contenant une réponse IPP.

FORMAT DU FICHIER JOURNAL D'ERREURS

Le fichier error_log liste les messages du planificateur - erreurs, avertissements, etc. La directive LogLevel dans le fichier cupsd.conf(5) contrôle quels messages sont journalisés :

    niveau date-heure message

Par exemple :

    I [20/May/1999:19:18:28 +0000] [Job 1] Queued on 'DeskJet' by 'mike'.
    D [20/May/1999:19:18:28 +0000] [Job 1] argv[0]="DeskJet"
    D [20/May/1999:19:18:28 +0000] [Job 1] argv[1]="1"
    D [20/May/1999:19:18:28 +0000] [Job 1] argv[2]="mike"
    D [20/May/1999:19:18:28 +0000] [Job 1] argv[3]="myjob"
    D [20/May/1999:19:18:28 +0000] [Job 1] argv[4]="1"
    D [20/May/1999:19:18:28 +0000] [Job 1] argv[5]="media=
      na_letter_8.5x11in sides=one-sided"
    D [20/May/1999:19:18:28 +0000] [Job 1] argv[6]="/var/spool/cups/
      d000001-001"
    I [20/May/1999:19:21:02 +0000] [Job 2] Queued on 'DeskJet' by 'mike'.
    I [20/May/1999:19:22:24 +0000] [Job 2] Canceled by 'mike'.

Le champ level contient le type de message :

A
Message d'alerte (LogLevel alert)
C
Message d'erreur critique (LogLevel crit)
D
Message de débogage (LogLevel debug)
d
Message de débogage détaillé (LogLevel debug2)
E
Message d'erreur normal (LogLevel error)
I
Message d'information (LogLevel info)
N
Message de notification (LogLevel notice)
W
Message d'avertissement (LogLevel warn)
X
Message d'erreur d'urgence (LogLevel emerg)

Le champ date-time contient la date et l'heure à laquelle la page a commencé à être imprimée. Le format de ce champ est identique au champ date-heure du fichier access_log .

Le champ message contient un message textuel libre. Les messages des filtres de travaux sont préfixés par « [Job NNN] » où « NNN » est l'identifiant du travail.

FORMAT DU FICHIER JOURNAL DES PAGES

Le fichier page_log liste le nombre total de pages (feuilles) qui sont imprimées. Par défaut, chaque ligne contient les informations suivantes :

    imprimante utilisateur identifiant-travail date-heure total nombre-feuilles facturation-travail
      nom-hôte-origine-travail nom-travail support côtés

Par exemple, l'entrée pour un travail de deux pages appelé « myjob » pourrait ressembler à :

    DeskJet root 1 [20/May/1999:19:21:06 +0000] total 2 acme-123
      localhost myjob na_letter_8.5x11in one-sided

La directive PageLogFormat dans le fichier cupsd.conf(5) peut être utilisée pour changer ces informations.

Le champ printer contient le nom de l'imprimante qui a imprimé la page. Si vous envoyez un travail à une classe d'imprimantes, ce champ contiendra le nom de l'imprimante à laquelle le travail a été attribué.

Le champ user contient le nom de l'utilisateur (l'attribut IPP requesting-user-name) qui a soumis ce fichier pour impression.

Le champ job-id contient le numéro du travail de la page en cours d'impression.

Le champ date-time contient la date et l'heure à laquelle la page a commencé à être imprimée. Le format de ce champ est identique au champ date-heure du fichier access_log .

Le num-sheets fournit le nombre total de pages (feuilles) qui ont été imprimées pour le travail.

Le champ job-billing contient une copie des attributs job-billing ou job-account-id fournis avec les requêtes IPP Create-Job ou Print-Job, ou "-" si aucun n'a été fourni.

Le champ job-originating-host-name contient le nom d'hôte ou l'adresse IP du client qui a imprimé le travail.

Le champ job-name contient une copie de l'attribut job-name fourni avec les requêtes IPP Create-Job ou Print-Job, ou "-" si aucun n'a été fourni.

Le champ media contient une copie des attributs media ou media-col/media-size fournis avec les requêtes IPP Create-Job ou Print-Job, ou "-" si aucun n'a été fourni.

Le champ sides contient une copie de l'attribut sides fourni avec les requêtes IPP Create-Job ou Print-Job, ou "-" si aucun n'a été fourni.
