curl_global_sslset(3)

Paquet: curl

Licences: MIT

curl_global_sslset(3) Manuel de fonctions de bibliothèque curl_global_sslset(3)

NOM

curl_global_sslset - sélectionner le backend SSL à utiliser

SYNTAXE

#include <curl/curl.h>
CURLsslset curl_global_sslset(curl_sslbackend id,
                              const char *name,
                              const curl_ssl_backend ***avail);

DESCRIPTION

Cette fonction configure à l'exécution quel backend SSL utiliser avec libcurl. Cette fonction ne peut être utilisée pour sélectionner un backend SSL qu'une seule fois, et elle doit être appelée avant curl_global_init(3).

Le backend peut être identifié par son id (par exemple, CURLSSLBACKEND_OPENSSL). Le backend peut également être spécifié via le paramètre name pour une correspondance insensible à la casse (en passant CURLSSLBACKEND_NONE comme id). Si le id et le name sont spécifiés, le name est ignoré.

Si ni l'id ni le name ne sont spécifiés, la fonction échoue avec CURLSSLSET_UNKNOWN_BACKEND et le pointeur avail est défini sur la liste se terminant par NULL des backends disponibles. Les backends disponibles sont ceux que cette version particulière de libcurl prend en charge.

Depuis libcurl 7.60.0, le pointeur avail est toujours défini sur la liste des alternatives si non NULL.

En cas de succès, la fonction retourne CURLSSLSET_OK.

Si le backend SSL spécifié n'est pas disponible, la fonction retourne CURLSSLSET_UNKNOWN_BACKEND et définit le pointeur avail sur une liste se terminant par NULL des backends SSL disponibles. Dans ce cas, vous pouvez appeler la fonction à nouveau pour essayer de sélectionner un autre backend.

Le backend SSL ne peut être défini qu'une seule fois. S'il a déjà été configuré, une tentative ultérieure de le modifier entraîne le retour de CURLSSLSET_TOO_LATE.

Cette fonction est thread-safe depuis libcurl 7.84.0 si curl_version_info(3) possède le bit de fonctionnalité CURL_VERSION_THREADSAFE défini (sur la plupart des plateformes).

Si elle n'est pas thread-safe, vous ne devez pas appeler cette fonction lorsque tout autre thread du programme (c'est-à-dire un thread partageant la même mémoire) est en cours d'exécution. Cela ne concerne pas seulement les autres threads utilisant libcurl.

Noms

Noms des backends SSL (insensibles à la casse) : GnuTLS, mbedTLS, OpenSSL, Rustls, Schannel, wolfSSL

Le nom "OpenSSL" est utilisé pour toutes les versions d'OpenSSL et ses forks/variantes associées dans cette fonction. OpenSSL, BoringSSL, LibreSSL, quictls et AmiSSL sont tous pris en charge par libcurl, mais du point de vue de curl_global_sslset(3), ils sont tous simplement "OpenSSL". Ils fournissent tous globalement la même API. curl_version_info(3) peut retourner des informations plus spécifiques sur la saveur et le numéro de version exacts d'OpenSSL utilisés.

struct

typedef struct {
  curl_sslbackend id;
  const char *name;
} curl_ssl_backend;
typedef enum {
  CURLSSLBACKEND_NONE = 0,
  CURLSSLBACKEND_OPENSSL = 1, /* ou un de ses forks */
  CURLSSLBACKEND_GNUTLS = 2,
  CURLSSLBACKEND_NSS = 3,
  CURLSSLBACKEND_GSKIT = 5, /* obsolète */
  CURLSSLBACKEND_POLARSSL = 6, /* obsolète */
  CURLSSLBACKEND_WOLFSSL = 7,
  CURLSSLBACKEND_SCHANNEL = 8,
  CURLSSLBACKEND_SECURETRANSPORT = 9, /* obsolète */
  CURLSSLBACKEND_AXTLS = 10, /* obsolète */
  CURLSSLBACKEND_MBEDTLS = 11,
  CURLSSLBACKEND_MESALINK = 12, /* obsolète */
  CURLSSLBACKEND_BEARSSL = 13, /* obsolète */
  CURLSSLBACKEND_RUSTLS = 14
} curl_sslbackend;

PROTOCOLES

Cette fonctionnalité affecte tous les protocoles pris en charge.

EXEMPLE

int main(void)
{
  int i;
  /* choisir un backend spécifique */
  curl_global_sslset(CURLSSLBACKEND_WOLFSSL, NULL, NULL);
  /* lister ceux qui sont disponibles */
  const curl_ssl_backend **list;
  curl_global_sslset(CURLSSLBACKEND_NONE, NULL, &list);
  for(i = 0; list[i]; i++)
    printf("Backend SSL #%d: '%s' (ID: %d)\n",
           i, list[i]->name, list[i]->id);
}

DISPONIBILITE

Ajouté dans curl 7.56.0.

VALEUR DE RETOUR

Si cette fonction retourne CURLSSLSET_OK, le backend a été sélectionné avec succès.

Si le backend choisi est inconnu (ou si le support du backend choisi n'a pas été compilé dans libcurl), la fonction retourne CURLSSLSET_UNKNOWN_BACKEND.

Si le backend avait été configuré précédemment, ou si curl_global_init(3) a déjà été appelé, la fonction retourne CURLSSLSET_TOO_LATE.

Si libcurl a été compilé entièrement sans prise en charge SSL, sans aucun backend, cette fonction retourne CURLSSLSET_NO_BACKENDS.
