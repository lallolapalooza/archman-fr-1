NOM

#include <curses.h>
/* variables */
int COLOR_PAIRS;
int COLORS;
int start_color(void);
bool has_colors(void);
bool can_change_color(void);
int init_pair(short pair, short f, short b);
int init_color(short color, short r, short g, short b);
/* extensions */
int init_extended_pair(int pair, int f, int b);
int init_extended_color(int color, int r, int g, int b);
int color_content(short color, short *r, short *g, short *b);
int pair_content(short pair, short *f, short *b);
/* extensions */
int extended_color_content(int color, int *r, int *g, int *b);
int extended_pair_content(int pair, int *f, int *b);
/* extension */
void reset_color_pairs(void);
int COLOR_PAIR(int n);
PAIR_NUMBER(int attr);

DESCRIPTION

Aperçu

curses supporte les attributs de couleur sur les terminaux qui en ont la capacité. Appelez start_color (typiquement juste après initscr(3X)) pour activer cette fonctionnalité. Les couleurs sont toujours utilisées par paires. Une paire de couleurs couple une couleur de premier plan pour les caractères avec une couleur d'arrière-plan pour le champ vide sur lequel les caractères sont rendus. init_pair initialise une paire de couleurs. La macro COLOR_PAIR(n) peut alors convertir la paire en un attribut vidéo.

Si un terminal a la capacité pertinente, init_color permet (re)définir une couleur. has_colors et can_change_color retournent TRUE ou FALSE, selon que le terminal a la capacité de couleur et que le programmeur peut changer les couleurs. color_content permet d'extraire les composantes rouge, verte et bleue d'une couleur initialisée. pair_content permet de découvrir la définition actuelle d'une paire de couleurs.

Rendu

curses combine les données suivantes pour rendre une cellule de caractère. Chacune d'elles peut inclure des informations de couleur.

  • Attributs de caractère curses, comme avec waddch(3X) ou wadd_wch(3X)
  • Attributs de fenêtre, comme avec wattrset(3X) ou wattr_set(3X)
  • Attributs de caractère d'arrière-plan de fenêtre, comme avec wbkgdset(3X) ou wbkgrndset(3X)

Les attributs par caractère et par fenêtre sont généralement définis via un paramètre de fonction contenant des attributs incluant une valeur de paire de couleurs. Certaines fonctions, telles que wattr_set, utilisent un paramètre séparé pour le numéro de la paire de couleurs.

Le caractère d'arrière-plan est un cas particulier : il inclut un code de caractère, comme s'il était passé à waddch.

La bibliothèque curses effectue le travail réel de combinaison de ces paires de couleurs dans une fonction interne appelée depuis waddch :

•
Si le paramètre passé à waddch est vide, et qu'il utilise la paire de couleurs spéciale 0,
  • curses vérifie ensuite l'attribut de fenêtre.
  • Si l'attribut de fenêtre n'utilise pas la paire de couleurs 0, curses utilise la paire de couleurs de l'attribut de fenêtre.
  • Sinon, curses utilise le caractère d'arrière-plan.
•
Si le paramètre passé à waddch n'est pas vide, ou s'il n'utilise pas la paire de couleurs spéciale 0, curses préfère la paire de couleurs du paramètre, si elle est non nulle. Sinon, il essaie ensuite l'attribut de fenêtre, et enfin le caractère d'arrière-plan.

Certaines fonctions curses comme wprintw appellent waddch. Celles-ci ne combinent pas leur paramètre avec une paire de couleurs. Par conséquent, ces appels n'utilisent que l'attribut de fenêtre ou le caractère d'arrière-plan.

CONSTANTES

Dans <curses.h> les macros suivantes sont définies. Ce sont les couleurs standard (ISO-6429). curses suppose également que COLOR_BLACK est la couleur d'arrière-plan par défaut pour tous les terminaux.

      COLOR_BLACK
      COLOR_RED
      COLOR_GREEN
      COLOR_YELLOW
      COLOR_BLUE
      COLOR_MAGENTA
      COLOR_CYAN
      COLOR_WHITE

Certains terminaux supportent plus de huit (8) couleurs “ANSI”. Il n'y a pas de noms standard pour ces couleurs supplémentaires.

VARIABLES

COLORS

est initialisée par start_color au nombre maximum de couleurs que le terminal peut supporter.

COLOR_PAIRS

est initialisée par start_color au nombre maximum de paires de couleurs que le terminal peut supporter. Souvent, sa valeur est le produit COLORS × COLORS, mais ce n'est pas toujours le cas.

  • Quelques terminaux utilisent l'espace colorimétrique HLS (voir start_color ci-dessous), ignorant cette règle ; et
  • les terminaux supportant un grand nombre de couleurs sont limités au nombre de paires de couleurs qu'une valeur short signé peut représenter.

FONCTIONS

start_color

La routine start_color ne prend pas d'arguments. Elle doit être appelée si le programmeur souhaite utiliser les couleurs, et avant toute autre routine de manipulation des couleurs. Il est conseillé d'appeler cette routine juste après initscr. start_color fait ceci :

  • Elle initialise deux variables globales, COLORS et COLOR_PAIRS (définissant respectivement le nombre maximum de couleurs et de paires de couleurs que le terminal peut supporter).
  • Elle initialise la paire de couleurs spéciale 0 aux couleurs de premier plan et d'arrière-plan par défaut. Aucune autre paire de couleurs n'est initialisée.
  • Elle restaure les couleurs du terminal aux valeurs qu'elles avaient lorsque le terminal a été allumé.
  • Si le terminal supporte la capacité initc (initialize_color), start_color initialise sa table interne représentant les composantes rouge, verte et bleue de la palette de couleurs.
Les composantes dépendent du fait que le terminal utilise le CGA (alias “ANSI”) ou le HLS (c'est-à-dire que la capacité hls (hue_lightness_saturation) est définie). La table est initialisée d'abord pour huit couleurs de base (noir, rouge, vert, jaune, bleu, magenta, cyan et blanc), en utilisant des poids qui dépendent du choix CGA/HLS. Pour les couleurs “ANSI”, les poids sont 680 ou 0 selon que la composante rouge, verte ou bleue correspondante est utilisée ou non. Cela permet d'utiliser 1000 pour représenter les couleurs vives/claires. Après les huit couleurs initiales (si le terminal supporte plus de huit couleurs), les composantes sont initialisées en utilisant le même schéma, mais avec des poids de 1000. SVr4 utilise un schéma similaire, mais utilise 1000 pour les composantes des huit couleurs initiales.

Ces limites s'appliquent aux valeurs de couleur et aux paires de couleurs. Les valeurs en dehors de ces limites ne sont pas valides et peuvent entraîner une erreur d'exécution :

  • COLORS correspond à la capacité max_colors de la base de données du terminal, (voir terminfo(5)).
  • les valeurs de couleur doivent être dans l'intervalle 0 à COLORS-1, inclus (y compris 0 et COLORS-1).
  • une valeur de couleur spéciale -1 est utilisée dans certaines fonctions étendues pour désigner la couleur par défaut (voir use_default_colors(3X)).
  • COLOR_PAIRS correspond à la capacité max_pairs de la base de données du terminal, (voir terminfo(5)).
  • les valeurs de paire de couleurs valides sont dans l'intervalle 1 à COLOR_PAIRS-1, inclus.
  • la paire de couleurs 0 est spéciale ; elle désigne « pas de couleur ».
La paire de couleurs 0 est supposée être du blanc sur du noir, mais c'est en réalité ce que le terminal implémente avant l'initialisation des couleurs. Elle ne peut pas être modifiée par l'application.

has_colors

La routine has_colors ne nécessite aucun argument. Elle renvoie TRUE si le terminal peut manipuler les couleurs ; sinon, elle renvoie FALSE. Cette routine facilite l'écriture de programmes indépendants du terminal. Par exemple, un programmeur peut l'utiliser pour décider d'utiliser la couleur ou une autre attribute vidéo.

can_change_color

La routine can_change_color ne nécessite aucun argument. Elle renvoie TRUE si le terminal prend en charge les couleurs et peut modifier leurs définitions ; sinon, elle renvoie FALSE. Cette routine facilite l'écriture de programmes indépendants du terminal.

init_pair

La routine init_pair modifie la définition d'une paire de couleurs. Elle prend trois arguments : le numéro de la paire de couleurs à modifier, le numéro de la couleur de premier plan et le numéro de la couleur d'arrière-plan. Pour des applications portables :

  • Le premier argument doit être une valeur de paire de couleurs valide. Si des couleurs par défaut sont utilisées (voir use_default_colors(3X)) la limite supérieure est ajustée pour prendre en compte des paires supplémentaires utilisant une couleur par défaut en premier plan et/ou en arrière-plan.
  • Les deuxième et troisième arguments doivent être des valeurs de couleur valides.

Si la paire de couleurs a été initialisée précédemment, l'écran est rafraîchi et toutes les occurrences de cette paire de couleurs sont changées pour la nouvelle définition.

En extension, ncurses vous permet de définir la paire de couleurs 0 via la assume_default_colors(3X) routine, ou de spécifier l'utilisation de couleurs par défaut (numéro de couleur -1) si vous invoquez d'abord la use_default_colors(3X) routine.

init_extended_pair

Parce que init_pair utilise des shorts signés pour ses paramètres, cela limite les paires de couleurs et les valeurs de couleur à 32767 sur le matériel moderne. L'extension init_extended_pair utilise des ints pour la paire de couleurs et la valeur de couleur, permettant de prendre en charge un plus grand nombre de couleurs.

init_color

La routine init_color modifie la définition d'une couleur. Elle prend quatre arguments : le numéro de la couleur à modifier suivi de trois valeurs RGB (pour les quantités de composantes rouge, verte et bleue).

  • Le premier argument doit être une valeur de couleur valide ; les couleurs par défaut ne sont pas autorisées ici. (Voir la section Colors pour l'index de couleur par défaut.)
  • Chacun des trois derniers arguments doit être une valeur dans l'intervalle 0 à 1000.

Quand init_color est utilisé, toutes les occurrences de cette couleur sur l'écran changent immédiatement pour la nouvelle définition.

init_extended_color

Parce que init_color utilise des shorts signés pour ses paramètres, cela limite les valeurs de couleur et leurs composantes rouge, verte et bleue à 32767 sur le matériel moderne. L'extension init_extended_color utilise des ints pour la valeur de couleur et pour définir les composantes rouge, verte et bleue, permettant de prendre en charge un plus grand nombre de couleurs.

color_content

La routine color_content donne aux programmeurs un moyen de trouver l'intensité des composantes rouge, verte et bleue (RGB) d'une couleur. Elle nécessite quatre arguments : le numéro de couleur et trois adresses de shorts pour stocker les informations sur les quantités de composantes rouge, verte et bleue dans la couleur donnée.

  • Le premier argument doit être une valeur de couleur valide, c'est-à-dire 0 à COLORS-1, inclus.
  • Les valeurs stockées aux adresses pointées par les trois derniers arguments sont dans l'intervalle 0 (pas de composante) à 1000 (quantité maximale de composante), incluses.

extended_color_content

Parce que color_content utilise des shorts signés pour ses paramètres, cela limite les valeurs de couleur et leurs composantes rouge, verte et bleue à 32767 sur le matériel moderne. L'extension extended_color_content utilise des ints pour la valeur de couleur et pour retourner les composantes rouge, verte et bleue, permettant de prendre en charge un plus grand nombre de couleurs.

pair_content

La routine pair_content permet aux programmeurs de découvrir de quelles couleurs une paire de couleurs donnée est composée. Elle nécessite trois arguments : le numéro de paire de couleurs et deux adresses de shorts pour stocker les numéros de couleur de premier plan et d'arrière-plan.

  • Le premier argument doit être une valeur de couleur valide, c'est-à-dire dans l'intervalle 1 à COLOR_PAIRS-1, inclus.
  • Les valeurs stockées aux adresses pointées par les deuxième et troisième arguments sont dans l'intervalle 0 à COLORS, inclus.

extended_pair_content

Parce que pair_content utilise des shorts signés pour ses paramètres, cela limite les paires de couleurs et les valeurs de couleur à 32767 sur le matériel moderne. L'extension extended_pair_content utilise des ints pour la paire de couleurs et pour retourner les couleurs de premier plan et d'arrière-plan, permettant de prendre en charge un plus grand nombre de couleurs.

reset_color_pairs

L'extension reset_color_pairs indique à ncurses de supprimer toutes les informations de paires de couleurs qui ont été définies avec init_pair. Elle touche également l'écran courant et l'écran standard, permettant à une application de changer rapidement de palette de couleurs.

COLOR_PAIR

COLOR_PAIR(n) convertit un numéro de paire de couleurs en un attribut. Les attributs peuvent contenir des paires de couleurs dans l'intervalle 0 à 255. Si vous avez besoin d'une paire de couleurs plus grande que cela, vous devez utiliser des fonctions telles que attr_set (qui passent la paire de couleurs comme paramètre séparé) plutôt que les fonctions héritées telles que attrset.

PAIR_NUMBER

PAIR_NUMBER(attr) extrait les informations de couleur de son paramètre attr et les retourne sous forme de numéro de paire de couleurs ; c'est l'opération inverse de COLOR_PAIR.

VALEUR DE RETOUR

Les routines can_change_color et has_colors retournent TRUE ou FALSE.

Toutes les autres routines retournent l'entier ERR en cas d'échec et un OK (SVr4 ne spécifie qu'« une valeur entière autre que ERR») en cas de réussite.

X/Open ne définit aucune condition d'erreur. SVr4 documente certaines conditions d'erreur qui s'appliquent en général :

•
Cette implémentation retournera ERR en cas de tentative d'utilisation de valeurs de couleur en dehors de l'intervalle 0 à COLORS-1 (sauf pour l'extension des couleurs par défaut), ou d'utilisation de paires de couleurs en dehors de l'intervalle 0 à COLOR_PAIRS-1.
Les valeurs de couleur utilisées dans init_color doivent être dans l'intervalle 0 à 1000.
Une erreur est retournée de toutes les fonctions si le terminal n'a pas été initialisé.
Une erreur est retournée des fonctions secondaires telles que init_pair si start_color n'a pas été appelée.
•
SVr4 fait de même, sauf qu'il retourne ERR depuis pair_content si la paire n'a pas été initialisée avec init_pairs et qu'il retourne ERR depuis color_content si le terminal ne prend pas en charge le changement de couleurs.
Cette implémentation ne retourne pas ERR dans aucun des deux cas.

Les fonctions spécifiques effectuent des vérifications supplémentaires :

init_color
retourne une erreur si le terminal ne prend pas en charge cette fonctionnalité, par exemple, si la capacité initialize_color est absente de la description du terminal.
start_color
retourne une erreur si la table de couleurs ne peut pas être allouée.

NOTES

Dans l'implémentation ncurses , il y a un indicateur d'activation de couleur séparé, une palette de couleurs, une table de paires de couleurs et des compteurs COLORS et COLOR_PAIRS associés pour chaque écran ; la fonction start_color n'affecte que l'écran courant. L'interface SVr4/XSI n'est pas vraiment conçue en tenant compte de cela, et les implémentations historiques peuvent utiliser une palette de couleurs partagée unique.

Définir une couleur d'arrière-plan implicite via une paire de couleurs n'affecte que lesractères que les opérations d'écriture de caractères touchent explicitement. Pour changer la couleur d'arrière-plan utilisée lorsque des parties d'une fenêtre sont effacées par des opérations d'effacement ou de défilement, voir curs_bkgd(3X).

Plusieurs avertissements s'appliquent aux anciennes machines x86 (p. ex., i386, i486) avec graphiques compatibles VGA :

  • COLOR_YELLOW est en réalité brun. Pour obtenir du jaune, utilisez COLOR_YELLOW combiné avec l'attribut A_BOLD .
  • L'attribut A_BLINK devrait en théorie rendre l'arrière-plan lumineux. Cela échoue souvent, et même certaines cartes pour lesquelles cela fonctionne en grande partie (comme les cartes Paradise et compatibles) se comportent de manière incorrecte lorsque vous essayez de définir un arrière-plan jaune « lumineux » (vous obtenez plutôt un premier plan jaune clignotant).
  • Les valeurs RVB des couleurs ne sont pas définissables.

EXTENSIONS

Les fonctions marquées comme extensions ont été conçues pour ncurses(3X), et ne se trouvent pas dans SVr4 curses, 4.4BSD curses, ni dans aucune autre implémentation de curses antérieure.

PORTABILITÉ

Les applications utilisant des ncurses extensions devraient conditionner leur utilisation à la visibilité de la NCURSES_VERSION macro de préprocesseur.

Cette implémentation satisfait les maxima minima d'X/Open Curses pour COLORS et COLOR_PAIRS.

La routine init_pair accepte des valeurs négatives pour les couleurs de premier plan et d'arrière-plan afin de prendre en charge l' use_default_colors(3X) extension, mais seulement si cette routine a été invoquée en premier.

L'hypothèse selon laquelle COLOR_BLACK est la couleur d'arrière-plan par défaut pour tous les terminaux peut être modifiée à l'aide de l' assume_default_colors(3X) extension.

Cette implémentation vérifie les pointeurs, p. ex., pour les valeurs retournées par color_content et pair_content, et les traitera comme des paramètres optionnels lorsqu'ils sont nuls.

X/Open Curses ne spécifie pas de limite pour le nombre de couleurs et de paires de couleurs qu'un terminal peut prendre en charge. Cependant, dans son utilisation de short pour les paramètres, il reprend le détail d'implémentation de SVr4 pour la base de données terminfo compilée, qui utilise des nombres signés sur 16 bits. Cette implémentation fournit des versions étendues de ces fonctions qui utilisent des paramètres short , permettant aux applications d'utiliser des numéros de couleur et de paire plus grands.

La fonction reset_color_pairs est une extension de ncurses.

HISTORIQUE

SVr3.2 a introduit la prise en charge des couleurs dans curses en 1987.

SVr4 a apporté des changements internes, p. ex., en déplaçant le stockage de l'état des couleurs depuis SP (la structure SCREEN ) vers cur_term (la structure TERMINAL ), mais a fourni le même ensemble de fonctions de bibliothèque.

SVr4 curses limite le nombre de paires de couleurs à 64, réservant la paire de couleurs zéro (0) comme état initial non coloré du terminal. Cette limite découle du fait que l'information de paire de couleurs est un champ de bits dans le chtype type de données (désigné par A_COLOR).

D'autres implémentations de curses avaient des limites différentes :

  • PCCurses (1987-1990) ne prévoyait que huit (8) couleurs.
  • PDCurses (1992-présent) a hérité de la limitation de 8 couleurs de PCCurses, mais l'a changée à 256 dans la version 2.5 (2001), tout en changeant chtype de 16 bits à 32 bits.
  • X/Open Curses (1992-présent) a ajouté une nouvelle structure cchar_t pour stocker le caractère, les attributs et les valeurs de paire de couleurs, permettant une plage accrue de paires de couleurs. Les paires de couleurs et les valeurs de couleur utilisaient un shortsigné, limitant les valeurs à 15 bits.
  • ncurses (1992-présent) utilise huit bits pour A_COLOR dans les valeurs chtype .
La version 5.3 a fourni une interface large (2002), mais a laissé les paires de couleurs comme partie du champ d'attributs.
Depuis la version 6 (2015), ncurses utilise un int séparé pour les paires de couleurs dans les valeurs cchar_t . Lorsque ces valeurs de paire de couleurs tiennent dans 8 bits, ncurses permet de manipuler les paires de couleurs via les fonctions utilisant les valeurs chtype .
•
NetBSD curses a utilisé 6 bits de 2000 (lorsque les couleurs ont été pour la première fois prises en charge) jusqu'en 2004. À ce moment-là, NetBSD a changé pour utiliser 10 bits. En 2021, cette taille est inchangée. Comme ncurses avant la version 6, l'information de paire de couleurs de NetBSD est stockée dans le champ d'attributs de cchar_t, limitant le nombre de paires de couleurs par la taille du champ de bits.
