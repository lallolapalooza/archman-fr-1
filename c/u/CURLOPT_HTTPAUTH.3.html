DESCRIPTIO

N

Passez un long en paramètre, défini à un masque de bits, pour indiquer à libcurl quelle(s) méthode(s) d'authentification vous souhaitez qu'elle utilise pour communiquer avec le serveur

distant.

Les bits disponibles sont listés ci-dessous. Si plus d'un bit est défini, libcurl interroge d'abord l'hôte pour voir quelles méthodes d'authentification il prend en charge, puis choisit la meilleure que vous l'autorisez à utiliser. Pour certaines méthodes, cela entraîne un aller-retour réseau supplémentaire. Définissez le nom et le mot de passe réels avec l' option CURLOPT_USERPWD(3) ou avec les options CURLOPT_USERNAME(3) et CURLOPT_PASSW

ORD(3).

Pour l'authentification avec un proxy, voir CURLOPT_PROXYA

UTH(3).
CURLAUTH_BAS
IC
Authentification HTTP Basic. C'est le choix par défaut et la seule méthode largement utilisée et prise en charge pratiquement partout. Elle envoie le nom d'utilisateur et le mot de passe sur le réseau en clair, facilement interceptables par
d'autres.
CURLAUTH_DIG
EST
Authentification HTTP Digest. L'authentification Digest est définie dans la RFC 2617 et constitue une méthode plus sûre d'effectuer une authentification sur les réseaux publics que la méthode Basic
classique.
CURLAUTH_DIGEST
_IE
Authentification HTTP Digest avec un style IE. L'authentification Digest est définie dans la RFC 2617 et constitue une méthode plus sûre d'effectuer une authentification sur les réseaux publics que la méthode Basic classique. Le style IE signifie simplement que libcurl utilise une « particularité » spéciale que IE est connu pour avoir utilisée avant la version 7 et que certains serveurs exigent que le client
utilise.
CURLAUTH_BEA
RER
Authentification par jeton Bearer HTTP, utilisée principalement dans le protocole OAuth 2.0.

Vous pouvez définir le jeton Bearer à utiliser avec CURLOPT_XOAUT

H2_BEAR
ER(3).
CURLAUTH_NEGOTI
ATE
Authentification HTTP Negotiate (SPNEGO). L'authentification Negotiate est définie dans la RFC 4559 et constitue la méthode la plus sûre d'effectuer une authentification sur HTTP.

Vous devez compiler libcurl avec une bibl

iothèque GSS-API appropriée ou S
SPI sur Windows pour que cela fonctionne.
CURLAUTH_NT
LM
Authentification HTTP NTLM. Un protocole propriétaire inventé et utilisé par Microsoft. Il utilise un concept de défi-réponse et de hachage similaire à Digest, pour empêcher l'écoute du mot de passe.

NTLM utilise des algorithmes cryptographiques faibles et n'est pas considéré

comme
sûr.
CURLAUTH_NTLM
_WB
La prise en charge de ceci a été supprimée depuis libcurl 8.8.0.

NTLM délégué à l'assistant winbind. L'authentification est effectuée par une application binaire distincte qui est exécutée lorsque nécessaire. Le nom de l'application est spécifié au moment de la compilation mais est typiquement /usr/bin/ntlm_a

uth.

Notez que libcurl crée un fork si nécessaire pour exécuter l'application winbind et la tue lorsque c'est terminé, en appelant waitpid() pour attendre sa sortie une fois terminé. Sur les systèmes d'exploitation POSIX, tuer le processus provoque l'émission d'un signal SIGCHLD (que CURLOPT_NOSIGNAL(3) soit défini ou non), qui doit être géré intelligemment par l'application. En particulier, l'application ne doit pas appeler inconditionnellement wait() dans son

gestionnaire de signal SIGCHLD afin d'éviter d'être soumise à une condition de concurrence
. Ce comportement est susceptible de changer dans les futures versions de libcurl.
CURLAUTH_A
NY
C'est une macro de commodité qui définit tous les bits et fait donc choisir à libcurl toute méthode qu'elle trouve appropriée. libcurl sélectionne automatiquement celle qu'elle trouve la plus
sûre.
CURLAUTH_ANYS
AFE
C'est une macro de commodité qui définit tous les bits sauf Basic et fait donc choisir à libcurl toute méthode qu'elle trouve appropriée. libcurl sélectionne automatiquement celle qu'elle trouve la plus
sûre.
CURLAUTH_ON
LY
C'est un symbole méta. Faites un OU logique de cette valeur avec une valeur d'authentification spécifique unique pour forcer libcurl à sonder l'authentification illimitée et si ce n'est pas le cas, seule cette algorithme d'authentification unique est
acceptable.
CURLAUTH_AWS_SI
GV4
fournit l'authentification par signature AWS V4 sur l'en-tête HTTPS, voir CURLOPT_
AWS_S
IGV4
(3).

int main(void)
{
  CURL *curl = curl_easy_init();
  if(curl) {
    CURLcode ret;
    curl_easy_setopt(curl, CURLOPT_URL, "https://example.com/");
    /* allow whatever auth the server speaks */
    curl_easy_setopt(curl, CURLOPT_HTTPAUTH, CURLAUTH_ANY);
    curl_easy_setopt(curl, CURLOPT_USERPWD, "james:bond");
    ret = curl_easy_perform(curl);
  }
}
