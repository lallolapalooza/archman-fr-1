Cela inclut les espaces et les caractères de contrôle. La première ligne d'une

requête

HTTP (contenant la méthode, généralement un GET ou un POST) n'est pas un en-tête et ne peut pas être remplacée à l'aide de cette option. Seules les lignes suivant la ligne de requête sont des en-têtes. Ajouter cette ligne de méthode dans cette liste d'en-têtes ne fait qu'envoyer une requête avec un en-tête invalide. Utilisez CURLOPT_CUSTOMREQUEST(3) pour changer la méthode. Lorsque cette

option

Vous devriez donc utiliser cette option avec prudence. Si vous vous connectez par exemple au site distant via un proxy et une requête CONNECT, vous devriez vous demander si ce proxy doit également recevoir les en-têtes. Ils peuvent être privés

ou

Les en-têtes personnalisés sont envoyés dans toutes les requêtes effectuées par le handle easy, cequi implique que si vous demandez à libcurl de suivre les redirections ( CURLOPT_FOLLOWLOCATION(3)), le même ensemble d'en-têtes personnalisés est envoyé dans la requête suivante.
