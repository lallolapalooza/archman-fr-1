curs_get_wstr(3x)

Paquet: ncurses

Licences: MIT-open-group

curs_get_wstr(3X) Appels de bibliothèque curs_get_wstr(3X)

NOM

get_wstr, getn_wstr, wget_wstr, wgetn_wstr, mvget_wstr, mvgetn_wstr, mvwget_wstr, mvwgetn_wstr - obtenir une chaîne de caractères larges depuis le clavier d'un terminal curses

SYNTAXE

#include <curses.h>
int get_wstr(wint_t *wstr);
int getn_wstr(wint_t *wstr, int n);
int wget_wstr(WINDOW *win, wint_t *wstr);
int wgetn_wstr(WINDOW *win, wint_t *wstr, int n);
int mvget_wstr(int y, int x, wint_t *wstr);
int mvgetn_wstr(int y, int x, wint_t *wstr, int n);
int mvwget_wstr(WINDOW *win, int y, int x, wint_t *wstr);
int mvwgetn_wstr(WINDOW *win, int y, int x, wint_t *wstr, int n);

DESCRIPTION

La fonction wgetn_wstr est équivalente à une série d'appels à wget_wch(3X) jusqu'à ce qu'un retour chariot ou nouvelle ligne termine la série :

  • Le caractère de terminaison n'est pas inclus dans la chaîne retournée.
  • Une condition de fin de fichier est représentée par WEOF, telle que définie dans <wchar.h>.
  • Dans tous les cas, la fin de la chaîne est terminée par un wchar_t nul.
  • La fonction stocke le résultat dans la zone pointée par le paramètre wstr.
  • La fonction lit au plus n caractères, empêchant ainsi un débordement potentiel du tampon d'entrée.
Toute tentative d'entrer plus de caractères (autres que le retour chariot ou nouvelle ligne de terminaison) provoque un bip.
Les touches de fonction provoquent également un bip et sont ignorées.

Les caractères erase et kill de l'utilisateur sont interprétés :

•
Le caractère erase (par ex., ^H) efface le caractère à la fin du tampon, déplaçant le curseur vers la gauche.
Si le mode keypad est activé pour la fenêtre, KEY_LEFT et KEY_BACKSPACE sont tous deux considérés comme équivalents au caractère erase de l'utilisateur.
•
Le caractère kill (par ex., ^U) efface tout le tampon, laissant le curseur au début du tampon.

Les caractères saisis sont affichés uniquement si echo est actuellement activé. Dans ce cas, le retour arrière est affiché comme une suppression du caractère précédent (généralement un déplacement vers la gauche).

Les fonctions getn_wstr, mvgetn_wstr, mvwgetn_wstr et wgetn_wstr sont identiques aux fonctions get_wstr, mvget_wstr, mvwget_wstr et wget_wstr, respectivement, sauf que les versions *n_* lisent au plus n caractères, permettant à l'application d'éviter le débordement du tampon d'entrée.

VALEUR DE RETOUR

Toutes ces fonctions retournent l'entier OK en cas de succès. En cas d'échec, elles retournent ERR.

X/Open ne définit aucune condition d'erreur.

Dans cette implémentation, ces fonctions retournent une erreur

  • si le pointeur de fenêtre est nul,
  • si son délai d'attente expire sans aucune donnée, ou
  • si l'appel associé à wget_wch a échoué.

Les fonctions préfixées par « mv » effectuent d'abord un déplacement du curseur et échouent si la position (y, x) est en dehors des limites de la fenêtre.

NOTES

Toutes ces fonctions, à l'exception de wgetn_wstr, peuvent être des macros.

L'utilisation de get_wstr, mvget_wstr, mvwget_wstr ou wget_wstr pour lire une ligne qui dépasse la taille du tableau pointé par wstr entraîne des résultats indéfinis. L'utilisation de getn_wstr, mvgetn_wstr, mvwgetn_wstr ou wgetn_wstr, respectivement, est recommandée.

Ces fonctions ne peuvent pas retourner de valeurs KEY_ car il n'y a pas moyen de distinguer une valeur KEY_ d'une valeur wchar_t valide.

PORTABILITÉ

Ces fonctions sont décrites dans The Single Unix Specification, Version 2. Aucune condition d'erreur n'est définie.

Cette implémentation retourne ERR si le pointeur de fenêtre est nul, ou si l'appel de niveau inférieur wget_wch retourne un ERR. Dans ce dernier cas, un retour ERR sans autre donnée est traité comme une condition de fin de fichier, et le tableau retourné contient un WEOF suivi d'un wchar_t nul.

X/Open Curses a documenté ces fonctions pour passer un tableau de wchar_t en 1997, mais c'était une erreur à cause de cette partie de la description :

L'effet de get_wstr est comme si une série d'appels à get_wch étaient faits, jusqu'à ce qu'un caractère nouvelle ligne, un caractère fin de ligne, ou un caractère fin de fichier soit traité.

La fonction get_wch peut retourner une valeur négative, tandis que wchar_t est un type non signé. Tous les fournisseurs implémentent cela en utilisant wint_t, conformément à la norme.

X/Open Curses, Issue 7 (2009) n'est pas clair quant à savoir si le wchar_t nul de terminaison est compté dans le paramètre de longueur n. X/Open Curses, Issue 7 a révisé la description correspondante de wgetnstr pour aborder ce problème. La description non révisée de wget_nwstr peut être interprétée de l'une ou l'autre manière. Cette implémentation compte le terminateur dans la longueur.

X/Open Curses ne spécifie pas ce qui se passe si la longueur n est négative.

  • Par analogie avec wgetnstr, ncurses 6.2 utilise une limite (basée sur LINE_MAX).
  • D'autres implémentations (comme Solaris xcurses) font de même, tandis que d'autres (PDCurses) ne le permettent pas.
  • NetBSD 7 curses imite ncurses 6.1 à cet égard, traitant un -1 comme un nombre indéfini de caractères.

VOIR AUSSI

curs_getstr(3X) décrit des fonctions comparables de la bibliothèque ncurses dans sa configuration sans caractères larges.
