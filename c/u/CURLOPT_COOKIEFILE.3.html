CURLOPT_COOKIEFILE(3) Manuel des fonctions de bibliothèque CURLOPT_COOKIEFILE(3)

NOM

CURLOPT_COOKIEFILE - fichier à partir duquel lire les cookies

SYNTAXE

#include <curl/curl.h>
CURLcode curl_easy_setopt(CURL *handle, CURLOPT_COOKIEFILE, char *filename);

DESCRIPTION

Passez un pointeur vers une chaîne terminée par null comme paramètre. Il doit pointer vers le nom du fichier contenant les données de cookies à lire. Les données de cookies peuvent être soit dans l'ancien format de cookies Netscape / Mozilla, soit simplement des en-têtes HTTP réguliers (style Set-Cookie) déversés dans un fichier.

Cela active également le moteur de cookies, ce qui permet à libcurl d'analyser et d'envoyer des cookies lors des requêtes ultérieures avec ce descripteur.

En passant une chaîne vide ("") à cette option, vous activez le moteur de cookies sans lire de cookies initiaux. Si vous indiquez à libcurl que le nom du fichier est "-" (juste un simple signe moins), libcurl lit alors depuis l'entrée standard.

Cette option ne fait que lire les cookies. Pour que libcurl écrive les cookies dans un fichier, voir CURLOPT_COOKIEJAR(3).

Si vous lisez des cookies à partir d'un fichier d'en-têtes HTTP brut et qu'il ne spécifie pas de domaine dans la ligne Set-Cookie, alors le cookie n'est pas envoyé car le domaine du cookie ne correspond pas à celui de l'URL cible. Pour résoudre ce problème, définissez un domaine dans la ligne Set-Cookie (cela inclut les sous-domaines) ou, de préférence : utilisez le format Netscape.

L'application n'a pas besoin de conserver la chaîne après avoir défini cette option.

Si vous utilisez cette option plusieurs fois, vous ajoutez d'autres fichiers à partir desquels lire les cookies. Définir cette option à NULL désactive le moteur de cookies et efface la liste des fichiers à partir desquels lire les cookies.

Les cookies sont chargés à partir du ou des fichiers spécifiés lorsque le transfert démarre, pas lorsque cette option est définie.

PRÉOCCUPATIONS DE SÉCURITÉ

Ce document mentionnait précédemment comment la spécification d'un fichier non existant pouvait également activer le moteur de cookies. Bien que ce soit vrai, nous déconseillons fortement d'utiliser cette méthode car il est trop difficile d'être sûr que les fichiers restent ainsi sur le long terme.

PAR DÉFAUT

NULL

PROTOCOLES

Cette fonctionnalité affecte uniquement http

EXEMPLE

int main(void)
{
  CURL *curl = curl_easy_init();
  if(curl) {
    CURLcode res;
    curl_easy_setopt(curl, CURLOPT_URL, "https://example.com/foo.bin");
    /* obtenir les cookies d'un fichier existant */
    curl_easy_setopt(curl, CURLOPT_COOKIEFILE, "/tmp/cookies.txt");
    res = curl_easy_perform(curl);
    curl_easy_cleanup(curl);
  }
}

Format du fichier de cookies

Le format du fichier de cookies et les concepts généraux des cookies dans curl sont décrits ici en ligne : https://curl.se/docs/http-cookies.html

DISPONIBILITÉ

Ajouté dans curl 7.1

VALEUR DE RETOUR

curl_easy_setopt(3) renvoie un CURLcode indiquant le succès ou l'erreur.

CURLE_OK (0) signifie que tout s'est bien passé, une valeur non nulle indique une erreur, voir libcurl-errors(3).
