DESCRIPTIO

N

Le gestionnaire url sur lequel travailler, transmis en premier argument, doit être un gestionnaire précédemment créé par curl_url(3) ou curl_url_du

p(3).

Cette fonction définit ou met à jour des composants ou parties d'URL individuels, contenus dans l'objet URL identifié par le

gestionnaire.

L'argument part doit identifier la partie d'URL particulière (voir la liste ci-dessous) à définir ou modifier, avec content pointant vers une chaîne terminée par un caractère nul contenant le nouveau contenu pour cette partie d'URL. Le contenu doit être sous la forme et l'encodage qu'il utiliserait dans une URL : encodé en

URL.

Lors de la définition d'une partie dans l'objet URL qui avait déjà été définie précédemment, elle remplace les données précédemment stockées pour cette partie par le nouveau content

.

L'appelant n'a pas besoin de conserver content après un appel réussi car cette fonction copie le

contenu.

Définir une partie sur un pointeur NULL supprime le contenu de cette partie du gestionnaire

CURLU.

Cette fonction a une limite de longueur maximale de 8 Mo pour toutes les chaînes d'entrée fournies. Dans la réalité, des champs excessivement longs dans les URL causent des problèmes même si cette fonction les

accepte.

Lors de la définition ou de la mise à jour du contenu de parties d'URL individuelles, curl_url_set(3) pourrait accepter des données qui ne pourraient pas autrement être définies dans la chaîne lorsqu'elle est peuplée à la suite d'une analyse complète d'URL. Attention. Si c'est le cas, l'extraction d'une URL complète ultérieurement à partir de tels composants pourrait produire une URL

invalide.

L'argument flags est un masque de bits avec d

es fonctionnalités
indépendantes.

PARTIE

S
CURLUPART_U
RL
Permet de remplacer l'URL complète du gestionnaire. Si le gestionnaire est déjà peuplé d'une URL, la nouvelle URL peut être relative à la précédente.

Lors de la définition réussie d'une nouvelle URL, relative ou absolue, le contenu du gestionnaire est remplacé par les composants de la nouvelle URL

définie.

Transmettez un pointeur vers une chaîne terminée par un caractère nul au paramètre url. La chaîne doit pointer vers une URL correctement formatée « RFC 3986+ » ou être un pointeur NULL. L'analyseur d'URL ne comprend et n'analyse que le sous-ensemble des URL qui sont « hiérarchiques » et contiennent donc un séparateur :// - pas celles qui sont normalement spécifiées avec seulement un séparateur

deux-points.

Par défaut, cette API n'analyse que les URL utilisant des schémas pour des protocoles pris en charge intégralement. Pour que libcurl analyse les URL de manière générique même pour des schémas qu'il ne connaît pas, le bit de drapeau CURLU_NON_SUPPORT_SCHEME doit être défini. Sinon, cette fonction renvoie CURLUE_UNSUPPORTED_SCHEME pour les schémas d'URL qu'elle ne reconnaît

pas.

Sauf si CURLU_NO_AUTHORITY est défini, un nom d'hôte vide n'est pas autorisé dans

l'URL.

Lorsqu'une URL complète est définie (analysée), le composant nom d'hôte est stocké décodé

en URL.

Il est considéré comme acceptable de définir une URL vide ("") comme redirection,

mais pas comme URL normale. Par conséquent, définir une URL "" fonctionne correc
tement si le gestionnaire contient déjà une URL, sinon cela déclenche une erreur.

long.

ER
Si seule la partie utilisateur est définie et non le mot de passe, l'URL est représentée avec un mot de passe
vide.
CURLUPART_PASSW

Si seule la partie mot de passe est définie et non l'utilisateur, l'URL est représentée avec un utilisateur
vide.
CURLUPART_OPTI
ONS
Le champ options est un champ facultatif qui peut suivre le mot de passe dans la partie userinfo. Il n'est reconnu/utilisé que lors de l'analyse d'URL pour les schémas suivants : pop3, smtp et imap. Cette fonction permet cependant aux utilisateurs de définir ce champ
indépendamment.
CURLUPART_HO
ST
Le nom d'hôte. S'il s'agit d'un nom de domaine international (IDN), la chaîne doit alors être encodée selon votre locale ou en UTF-8 (lorsque WinIDN est utilisé). S'il s'agit d'une adresse IPv6 numérique entre crochets, elle peut contenir un identifiant de zone (ou vous pouvez utiliser CURLUPART_ZONEID).

Notez que si vous définissez une adresse IPv6, elle est corrompue et provoque une erreur si vous définissez également le drapeau

CURLU_URLENCODE.

erreur.
CURLUPART_PA

DRAPEAU

X

L'argument flags est zéro, un ou plusieurs bits définis dans un masque de

bits.
CURLU_APPENDQU
ERY
Peut être utilisé lors de la définition du composant CURLUPART_QUERY. La nouvelle partie fournie est alors ajoutée à la fin de la requête existante - et si la partie précédente ne se terminait pas par une esperluette (&), une esperluette est insérée avant la nouvelle partie ajoutée.

Lorsque CURLU_APPENDQUERY est utilisé avec CURLU_URLENCODE, le premier symbole '=' n'est pas encodé

en
URL.
CURLU_NON_SUPPORT_SCH
EME
S'il est défini, permet à curl_url_set(3) de définir un schéma non pris en charge. Il ne peut alors évidemment pas savoir si le schéma fourni est valide ou
non.
CURLU_URLENC
ODE
Lorsqu'il est défini, curl_url_set(3) encode la partie en URL à l'entrée, sauf pour scheme, port et URL.

Lors de la définition du composant chemin avec l'encodage URL activé, les caractères suivants sont laissés tels quels s'ils sont

présents : 
! $ & ' ( ) { } [ ] * + , ;
= : @

La partie requête convertit les espaces en plus avant que la conversion en URL ne soit

appliquée.

Cet encodage URL est inconscient

du jeu de caractères et convertit
l'entrée octet par octet.
CURLU_DEFAULT_SCH
EME
S'il est défini, permet de définir l'URL sans schéma et définit alors celui-ci sur le schéma par défaut : HTTPS. Remplace l'option CURLU_GUESS_SCHEME si les deux sont
définis.
CURLU_GUESS_SCH
EME
S'il est défini, permet de définir l'URL sans schéma et « devine » à la place quel schéma était destiné en se basant sur le nom d'hôte. Si le nom de sous-domaine le plus externe correspond à DICT, FTP, IMAP, LDAP, POP3 ou SMTP, alors ce schéma est utilisé, sinon il choisit HTTP. Entre en conflit avec l'option CURLU_DEFAULT_SCHEME qui prend la priorité si les deux sont définis.

Si la devinette n'est pas autorisée et qu'il n'y a pas de schéma par défaut set, tenter d'analyser une URL sans schéma renvoie une

erreur.

Si le schéma est défini à la suite d'une déduction, c'est-à-dire s'il n'est pas réellement présent dans l'URL analysée, il peut ensuite être identifié en utilisant le drapeau CURLU_NO_GUESS_SCHEME lors de l'obtention ultérieure de l'URL ou du schéma avec curl_url

_get
(3).
CURLU_NO_AUTHOR
ITY
S'il est défini, ignore les vérifications d'autorité. La RFC permet à des schémas individuels d'omettre la partie hôte (normalement la seule partie obligatoire de l'autorité), mais libcurl ne peut pas savoir si cela est autorisé pour les schémas personnalisés. Spécifier ce drapeau permet des sections d'autorité vides, de la même manière que le schéma file est
géré.
CURLU_PATH_AS
_IS
Lorsqu'il est défini pour CURLUPART_URL, cela évite la normalisation du chemin. C'est-à-dire la procédure par laquelle libcurl supprime sinon les séquences de point-slash et de point-point etc. La même option utilisée pour les transferts est appelée CURLOPT_PATH_AS
_IS(3).
CURLU_ALLOW_SP
ACE
S'il est défini, l'analyseur d'URL autorise l'espace (ASCII 32) lorsque c'est possible. La syntaxe des URL n'autorise normalement pas les espaces nulle part, mais ils devraient être encodés en %20 ou '+'. Lorsque les espaces sont autorisés, ils ne sont toujours pas autorisés dans le schéma. Lorsqu'un espace est utilisé et autorisé dans une URL, il est stocké tel quel sauf si CURLU_URLENCODE est également défini, ce qui fait alors que libcurl encode l'espace en URL avant de le stocker. Cela affecte la manière dont l'URL est construite lorsque curl_url_get(3) est ensuite utilisé pour extraire l'URL complète ou des parties individuelles. (Ajouté en 7.78.
0)
CURLU_DISALLOW_U
SER
S'il est défini, l'analyseur d'URL n'accepte pas les identifiants intégrés pour le CURLUPART_URL, et renvoie à la place CURLUE_USER_NOT_ALLO
WED
pour de t
elles URL.

EXEMPL

E 
int main(void)
{
  CURLUcode rc;
  CURLU *url = curl_url();
  rc = curl_url_set(url, CURLUPART_URL, "https://example.com", 0);
  if(!rc) {
    /* change it to an FTP URL */
    rc = curl_url_set(url, CURLUPART_SCHEME, "ftp", 0);
  }
  curl_url_cleanup(url);
}
