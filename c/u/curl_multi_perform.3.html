curl_multi_perform(3) Manuel des fonctions de bibliothèque curl_multi_perform(3)

NOM

curl_multi_perform - exécute tous les transferts jusqu'à ce qu'ils doivent attendre

SYNTAXE

#include <curl/curl.h>
CURLMcode curl_multi_perform(CURLM *multi_handle, int *running_handles);

DESCRIPTION

Cette fonction exécute les transferts sur toutes les poignées (handles) ajoutées qui nécessitent une attention, de manière non bloquante. Les poignées faciles ont été précédemment ajoutées à la poignée multiple avec curl_multi_add_handle(3).

Lorsqu'une application a découvert qu'il y a des données disponibles pour la poignée multiple ou qu'un délai d'attente a expiré, l'application doit appeler cette fonction pour lire/écrire tout ce qui est disponible à lire ou écrire pour le moment, etc. curl_multi_perform(3) retourne dès que les lectures/écritures sont terminées. Cette fonction ne requiert pas qu'il y ait effectivement des données disponibles à lire ou que des données puissent être écrites, elle peut être appelée juste au cas où. Elle stocke le nombre de poignées qui transfèrent encore des données dans le pointeur entier du deuxième argument.

Si le nombre de running_handles change par rapport à l'appel précédent (ou est inférieur au nombre de poignées faciles que vous avez ajoutées à la poignée multiple), vous savez qu'il y a un ou plusieurs transferts moins « en cours ». Vous pouvez alors appeler curl_multi_info_read(3) pour obtenir des informations sur chaque transfert individuel terminé, et ces informations retournées incluent le code CURLcode et plus encore. Si une poignée ajoutée échoue rapidement, elle peut ne jamais être comptée comme une poignée en cours d'exécution. Vous pourriez utiliser curl_multi_info_read(3) pour suivre le statut réel des poignées ajoutées dans ce cas.

Lorsque running_handles est mis à zéro (0) lors du retour de cette fonction, il n'y a plus de transferts en cours.

Lorsque cette fonction retourne une erreur, l'état de tous les transferts est incertain et ils ne peuvent pas être poursuivis. curl_multi_perform(3) ne doit plus être appelé sur la même poignée multiple après qu'une erreur ait été retournée, à moins de retirer d'abord toutes les poignées et d'en ajouter de nouvelles.

PROTOCOLES

Cette fonctionnalité affecte tous les protocoles pris en charge

EXEMPLE

int main(void)
{
  int still_running;
  CURLM *multi = curl_multi_init();
  CURL *curl = curl_easy_init();
  if(curl) {
    curl_multi_add_handle(multi, curl);
    do {
      CURLMcode mc = curl_multi_perform(multi, &still_running);
      if(!mc && still_running)
        /* attendre une activité, un délai d'attente ou « rien » */
        mc = curl_multi_poll(multi, NULL, 0, 1000, NULL);
      if(mc) {
        fprintf(stderr, "curl_multi_poll() a échoué, code %d.\n", (int)mc);
        break;
      }
    /* s'il y a encore des transferts, continuer la boucle */
    } while(still_running);
  }
}

DISPONIBILITE

Ajouté dans curl 7.9.6

VALEUR DE RETOUR

Cette fonction retourne un code CURLMcode indiquant succès ou erreur.

CURLM_OK (0) signifie que tout était correct, une valeur non nulle indique une erreur, voir libcurl-errors(3).

Cette fonction retourne des erreurs concernant toute la pile multiple. Des problèmes sur des transferts individuels peuvent s'être produits même lorsque cette fonction retourne CURLM_OK. Utilisez curl_multi_info_read(3) pour savoir comment les transferts individuels se sont comportés.

USAGE TYPIQUE

La plupart des applications utilisent curl_multi_poll(3) pour faire attendre libcurl une activité sur l'une des transferts en cours. Dès qu'un ou plusieurs descripteurs de fichiers sont actifs ou que la fonction expire, l'application appelle curl_multi_perform(3).
