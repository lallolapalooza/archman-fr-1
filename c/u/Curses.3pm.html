DESCRIPTIO

N

"Curses" est l'interface entre Perl et la bibliothèque curses(3) de votre système. Pour des descriptions sur l'utilisation d'une fonction, variable ou constante donnée, consultez la documentation de votre système, car ces informations varient invariablement (:-) entre les différentes bibliothèques curses(3) et les différents systèmes d'exploitation. Ce document décrit l'interface elle-même et suppose que vous savez déjà comment fonctionne la bibliothèque curses(3) de votre

système.

Fonctions

unifiées

De nombreuses fonctions curses(3) ont des variantes commençant par les préfixes w-, mv- et/ou wmv-. Ces variantes ne diffèrent que par l'ajout explicite d'une fenêtre, ou par l'ajout de deux coordonnées utilisées pour déplacer d'abord le curseur. Par exemple, addch() a trois autres variantes : waddch(), mvaddch() et mvwaddch(). Les variantes ne sont pas très intéressantes ; en fait, nous pourrions regrouper toutes les variantes dans la fonction originale en autorisant un nombre variable d'arguments et en analysant la liste d'arguments pour déterminer quelle variante l'utilisateur voulait

appeler.

Malheureusement, curses(3) est antérieur à varargs(3), donc en C, nous étions coincés avec toutes les variantes. Cependant, "Curses" est une interface Perl, nous sommes donc libres de « unifier » ces variantes en une seule fonction. La section « Fonctions disponibles » ci-dessous liste toutes les fonctions curses(3) que "Curses" rend disponibles en tant qu'équivalents Perl, avec une colonne indiquant si la fonction est unifiée. Si c'est le cas, elle prend un nombre variable d'arguments comme suit

:
"function( [win], [y, x], args );"

win est un argument de fenêtre facultatif, par défaut "stdscr" s'il n'est pas

spécifié.

y, x est une paire de coordonnées facultative utilisée pour déplacer le curseur, par défaut aucun déplacement s'il n'est pas

spécifié.

args sont les arguments requis de la fonction. Ce sont les arguments que vous spéci

fieriez si vous appeliez simplement la fonc
tion de base et non l'une des variantes.

Cela rend les variantes obsolètes, car leur fonctionnalité a été fusionnée en une seule fonction, donc "Curses" ne les définit pas par défaut. Vous pouvez toujours les obtenir si vous le souhaitez, en définissant la variable $Curses::OldCurses à une valeur non nulle avant d'utiliser le paquet "Curses". Voir « Compatibilité avec "cursperl" Perl 4.X »

pour un
exemple.

Fonctions sensibles aux caractères à large

largeur

Ce qui suit sont les fonctions préférées pour travailler avec des chaînes, bien qu'elles ne suivent pas la convention de nommage des fonctions unifiées normales (basée sur les noms de la bibliothèque Curses) décrite ci-dessus. Malgré le nommage, chacune correspond à une fonction de la bibliothèque Curses. Par exemple, un appel "getchar" effectue une fonction de la bibliothèque Curses dans la famille "getch"

.

En plus de ces fonctions, le module "Curses" contient des fonctions correspondantes avec la convention de nommage habituelle (par ex. "getch") ; la duplication est pour des raisons historiques. Les fonctions préférées étaient nouvelles dans Curses 1.29 (avril 2014). Elles utilisent les fonctions de caractères à large largeur de la bibliothèque Curses si disponibles (sinon, elles utilisent les versions traditionnelles non à large largeur). Elles ont également une interface plus perlienne, prenant en charge certains détails techniques sous le capot dont un programmeur Perl ne devrait pas avoir à

s'inquiéter.

La raison de l'existence de deux ensembles de fonctions de gestion des chaînes est historique. Le module Perl Curses d'origine est antérieur aux bibliothèques Curses qui comprennent les encodages de caractères multi-octets. De plus, le module a été conçu pour avoir une interface Perl qui ressemble étroitement à l'interface C syntaxiquement et transmet directement la représentation interne en octets des chaînes Perl au code C. C'était probablement acceptable avant que Perl n'ait des fonctionnalités Unicode, mais aujourd'hui, Perl stocke les chaînes internement en Latin-1 ou UTF-8 Unicode et le module d'origine n'était pas sensible à l'encodage

utilisé.

Bien que la plupart des problèmes puissent être contournés dans le code Perl en utilisant l'interface traditionnelle, il est difficile de le faire correctement et vous avez de toute façon besoin d'une bibliothèque curses sensible aux caractères à large largeur (par ex. ncursesw) pour que cela fonctionne correctement. Comme les consommateurs existants du module Curses peuvent s'appuyer sur le comportement traditionnel, les concepteurs du module Curses n'ont pas pu simplement modifier les fonctions existantes pour qu'elles comprennent les caractères à large largeur et convertissent vers et depuis les chaînes

Perl.

Aucune de ces fonctions n'existe si Perl est antérieur à 5.

6.

"getchar"

Cela appelle wget_wch(). Elle retourne un caractère -- plus précisément, une chaîne d'un caractère (pas nécessairement un octet !) contenant le caractère -- pour une touche normale et une liste à deux éléments "(undef, numéro-de-touche)" pour une touche de fonction. Elle retourne "undef" en cas

d'erreur.

Si vous n'attendez pas de touches de fonction (c'est-à-dire avec "keypad(0))", vous pouvez simplement

faire 
my $ch = getchar;
die "getchar failed" unless defined
$ch;

Si vous attendez des touches de fonction (c'est-à-dire avec keypad(1)), vous pouvez toujours assigner le résultat à une variable scalaire comme ci-dessus. En raison de la façon dont fonctionne l'opérateur virgule, cette variable recevra soit "undef", soit la chaîne, soit le nombre, et vous pouvez la décoder

vous-même. 
my $ch = getchar;
die "getchar failed" unless defined $ch;
if (<$ch looks like a number >= 0x100>) {
        <handle function key>
} else {
        <handle normal key>
}

ou

faire 
my ($ch, $key) = getchar;
if (defined $key) {
        <handle function key $key>
} else if (defined $ch) {
        <handle normal key $ch>
} else {
        die "getchar failed";
}

Si wget_wch() n'est pas disponible (c'est-à-dire si la bibliothèque Curses ne comprend pas les caractères à large largeur), cela appelle wgetch(), mais retourne néanmoins les valeurs décrites ci-dessus. Cela peut être un problème car avec un encodage de caractères multi-octets comme UTF-8, vous recevrez deux chaînes d'un caractère pour un caractère de deux octets (par ex. "ï¿½ï¿½ï¿½ï¿½" et "â�½" pour "â�½"). Si vous ajoutez ces caractères à une chaîne Perl, cette chaîne peut contenir internement une encodage UTF-8 valide d'un caractère, mais Perl ne l'interprétera pas de cette façon. Perl peut même essayer de convertir ce qu'il croit être deux caractères en UTF-8, vous donnant quatre

octets.

"getstring"

Cela appelle "wgetn_wstr" et retourne une chaîne ou "undef". Elle ne peut pas retourner la valeur d'une touche de fonction ; la bibliothèque Curses interprétera elle-même KEY_LEFT et

KEY_BACKSPACE.

Si wgett_wstr() est indisponible, cela appelle wgetstr

().

Dans les deux cas, la fonction alloue un tampon de taille fixe pour contenir le résultat de l'appel à la bibliothèque

Curses. 
my $s = getstring();
die "getstring failed" unless defined
$s;

"addstring"/"insstring"

Cela ajoute/insère la chaîne Perl passée en argument à la fenêtre Curses en utilisant waddnwstr()/wins_nwstr() ou, si indisponible, waddnstr()/winsnstr(). Elle retourne une valeur vraie en cas de succès, fausse en cas

d'échec. 
addstring("Hâ�½llâ�¡, Wâ�¡rld") || die "addstring
failed";

"instring"

Cela renvoie une chaîne Perl (ou "undef" en cas d'échec) contenant les caractères depuis la position actuelle du curseur jusqu'à la fin de la ligne. Elle utilise winnwstr() si disponible, et sinon innstr

(). 
my $s = instring();
die "instring failed" unless defined
$s;

"ungetchar"

Cela remet un caractère (passé sous forme de chaîne Perl d'un seul caractère) dans la file d'attente d'entrée. Elle utilise unget_wch() ou ungetch(). Elle renvoie une valeur vraie en cas de succès, fausse en cas d'échec. Elle ne peut pas remettre une touche de fonction ; la bibliothèque Curses ne fournit aucun moyen de remettre des touches de fonction, seulement des

caractères. 
ungetchar("X") or die "ungetchar
failed";

Le module "Curses" ne fournit aucune interface pour les routines de caractères complexes (wadd_wch(), wadd_wchnstr(), wecho_wchar(), win_wch(), win_wchnstr(), wins_wch()) car il n'existe aucun moyen sensé de convertir depuis Perl vers un "cchar_t" C ou l'i

nver
se.

Préoccupations de

sécurité

C'est toujours été le cas avec les fonctions curses, mais veuillez noter que les fonctions suivantes

: 
getstr()   (et éventuellement wgetstr(), mvgetstr(), et mvwgetstr())
inchstr()  (et éventuellement winchstr(), mvinchstr(), et mvwinchstr())
instr()    (et éventuellement winstr(), mvinstr(), et mvwinstr()
)

sont sujettes à une attaque par débordement de tampon. C'est parce que vous passez le tampon à remplir, qui doit être de longueur finie, mais il n'y a aucun moyen d'empêcher un méchant de

taper.

Afin d'éviter ce problème, utilisez les fonctions alternatives

: 
getnstr()
inchnstr()
innstr()

qui prennent un argument supplémentaire "taille du tampon" ou les versions conscientes des caractères larges getstring() et inst

COMPATIBILIT

É

Compatibilité avec "cursperl" de Perl 4.

X

"Curses" a été écrit pour tirer parti des caractéristiques de Perl 5 et ultérieur. L'auteur pensait qu'il valait mieux fournir un environnement de programmation curses amélioré qu'être compatible à 100 %. Cependant, de nombreuses vieilles applications "curseperl" fonctionneront probablement toujours en commençant le script par

: 
BEGIN { $Curses::OldCurses = 1; }
use
Curses;

Toute vieille application qui ne fonctionne toujours pas devrait imprimer un message d'erreur compréhensible expliquant le

problème.

Certaines fonctions et variables ne sont pas disponibles à travers "Curses", même avec la ligne "BEGIN". Elles sont listées sous "Curses items not available through Perl

Curses".

Les variables $stdscr et $curscr sont aussi disponibles comme fonctions "stdscr" et "curscr". C'est à cause d'un bug de Perl. Vo

ir la section LIMITATIO
NS pour plus de détails.

Incompatibilités avec les versions précédentes de

"Curses"

Dans les versions précédentes de ce logiciel, certaines fonctions Perl prenaient un ensemble de paramètres différent de leurs homologues C. Ce n'est pas le cas dans la version actuelle. Vous devriez maintenant utiliser getstr($str) et "getyx($y, $x)" au lieu de "$str = getstr()" et "($y, $x

) = g
etyx
()".

LIMITATION

S

Si vous utilisez les variables $stdscr et $curscr au lieu de leurs homologues fonctionnels ("stdscr" et "curscr"), vous pourriez rencontrer un bug dans Perl où la "magie" n'est pas appelée assez tôt. Cela se manifeste par le fait que le paquet "Curses" vous dit que $stdscr n'est pas une fenêtre. Une solution de contournement est de mettre une ligne comme "$stdscr = $stdscr" près du
