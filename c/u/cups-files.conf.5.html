NOM

cups-files.conf - Fichier de configuration des fichiers et des répertoires pour cups

DESCRIPTION

Le fichier cups-files.conf configure les fichiers et les répertoires utilisés par l'ordonnanceur CUPS, cupsd(8). Il se trouve normalement dans le répertoire /etc/cups .

Chaque ligne du fichier peut être une directive de configuration, une ligne vide ou un commentaire. Les directives de configuration se composent généralement d'un nom et d'une ou plusieurs valeurs séparées par des espaces. Le nom de la directive de configuration et les valeurs ne sont pas sensibles à la casse. Les lignes de commentaire commencent par le caractère #.

DIRECTIVES

Les directives suivantes sont comprises par cupsd(8):

AccessLog
AccessLog nom-de-fichier
AccessLog stderr
AccessLog syslog
Définit le nom de fichier du journal d'accès. La spécification d'un nom de fichier vide désactive la génération du journal d'accès. La valeur « stderr » fait que les entrées du journal sont envoyées au fichier d'erreur standard lorsque l'ordonnanceur s'exécute en premier plan, ou au démon de journalisation du système lorsqu'il s'exécute en arrière-plan. La valeur « syslog » fait que les entrées du journal sont envoyées au démon de journalisation du système. Le nom du serveur peut être inclus dans les noms de fichier à l'aide de la chaîne « %s », par exemple : 
    AccessLog /var/log/cups/%s-access_log
La valeur par défaut est « /var/log/cups/access_log ».
CacheDir répertoire
Spécifie le répertoire à utiliser pour les fichiers temporaires de longue durée (cache). La valeur par défaut est « /var/spool/cups/cache » ou « /var/cache/cups » selon la plateforme.
ConfigFilePerm mode
Spécifie les permissions pour tous les fichiers de configuration écrits par l'ordonnanceur. La valeur par défaut est « 0644 » sur macOS et « 0640 » sur tous les autres systèmes d'exploitation.

Remarque : Les permissions du fichier printers.conf sont actuellement masquées pour n'autoriser l'accès qu'à partir de l'utilisateur de l'ordonnanceur (généralement root). Cela est fait parce que les URI de périphérique d'impression contiennent parfois des informations d'authentification sensibles qui ne devraient pas être connues généralement sur le système. Il n'existe aucun moyen de désactiver cette fonctionnalité de sécurité.

CreateSelfSignedCerts yes
CreateSelfSignedCerts no
Spécifie si l'ordonnanceur crée automatiquement des certificats auto-signés pour les connexions client utilisant TLS. La valeur par défaut est yes.
DataDir chemin
Spécifie le répertoire où les fichiers de données peuvent être trouvés. La valeur par défaut est généralement « /usr/share/cups ».
DocumentRoot répertoire
Spécifie le répertoire racine pour le contenu de l'interface web CUPS. La valeur par défaut est généralement « /usr/share/doc/cups ».
ErrorLog
ErrorLog nom-de-fichier
ErrorLog stderr
ErrorLog syslog
Définit le nom de fichier du journal des erreurs. La spécification d'un nom de fichier vide désactive la génération du journal des erreurs. La valeur « stderr » fait que les entrées du journal sont envoyées au fichier d'erreur standard lorsque l'ordonnanceur s'exécute en premier plan, ou au démon de journalisation du système lorsqu'il s'exécute en arrière-plan. La valeur « syslog » fait que les entrées du journal sont envoyées au démon de journalisation du système. Le nom du serveur peut être inclus dans les noms de fichier à l'aide de la chaîne « %s », par exemple : 
    ErrorLog /var/log/cups/%s-error_log
La valeur par défaut est « /var/log/cups/error_log ».
FatalErrors none
FatalErrors all -kind [ ... -kind ]
FatalErrors kind [ ... kind ]
Spécifie quelles erreurs sont fatales, provoquant la sortie de l'ordonnanceur. La valeur par défaut est « config ». Les chaînes kind sont :
none
Aucune erreur n'est fatale.
all
Toutes les erreurs ci-dessous sont fatales.
browse
Les erreurs d'initialisation de la navigation sont fatales, par exemple les connexions échouées au démon DNS-SD.
config
Les erreurs de syntaxe du fichier de configuration sont fatales.
listen
Les erreurs Listen ou Port sont fatales, sauf pour les échecs IPv6 sur les adresses loopback ou « any ».
log
Les erreurs de création ou d'écriture des fichiers journaux sont fatales.
permissions
Les mauvaises permissions des fichiers de démarrage sont fatales, par exemple les fichiers de certificat et de clé TLS partagés avec des permissions de lecture pour tous.
Group nom-ou-numéro-de-groupe
Spécifie le nom ou l'ID de groupe qui sera utilisé lors de l'exécution de programmes externes. Le groupe par défaut dépend du système d'exploitation mais est généralement « lp » ou « nobody ».

LogFileGroup nom-ou-numéro-de-groupe
Spécifie le nom ou l'ID de groupe qui sera utilisé pour les fichiers journaux. Le groupe par défaut dépend du système d'exploitation mais est généralement « lp » ou « nobody ».
LogFilePerm mode
Spécifie les permissions de tous les fichiers journaux écrits par l'ordonnanceur. La valeur par défaut est « 0644 ».
PageLog [ nom-de-fichier ]
PageLog stderr
PageLog syslog
Définit le nom de fichier du journal des pages. La valeur « stderr » fait que les entrées du journal sont envoyées au fichier d'erreur standard lorsque l'ordonnanceur s'exécute en premier plan, ou au démon de journalisation du système lorsqu'il s'exécute en arrière-plan. La valeur « syslog » fait que les entrées du journal sont envoyées au démon de journalisation du système. La spécification d'un nom de fichier vide désactive la génération du journal des pages. Le nom du serveur peut être inclus dans les noms de fichier à l'aide de la chaîne « %s », par exemple : 
    PageLog /var/log/cups/%s-page_log
La valeur par défaut est « /var/log/cups/page_log ».
PassEnv variable [ ... variable ]
Transmet la ou les variables d'environnement spécifiées aux processus enfants. Remarque : les variables d'environnement standard des filtres et des backends CUPS ne peuvent pas être remplacées à l'aide de cette directive.
PeerCred off
PeerCred on
PeerCred root-only
Spécifie si les identifiants du pair sont utilisés pour l'autorisation lors de la communication via le socket de domaine UNIX. Lorsque on, les identifiants du pair de n'importe quel utilisateur sont acceptés pour l'autorisation. La valeur off désactive complètement l'utilisation des identifiants du pair, tandis que la valeur root-only n'autorise les identifiants du pair que pour l'utilisateur root. Remarque : pour des raisons de sécurité, le paramètre on est réduit à root-only pour l'autorisation des requêtes PUT.
RemoteRoot nom-d'utilisateur
Spécifie le nom d'utilisateur associé aux accès non authentifiés des clients qui prétendent être l'utilisateur root. La valeur par défaut est "remroot".
RequestRoot répertoire
Spécifie le répertoire qui contient les travaux d'impression et d'autres données de requêtes HTTP. La valeur par défaut est "/var/spool/cups".
Sandboxing relaxed
Sandboxing strict
Spécifie le niveau de sandboxing de sécurité appliqué aux filtres d'impression, aux backends et à d'autres processus enfants du planificateur. La valeur par défaut est "strict". Cette directive est actuellement uniquement utilisée/prise en charge sur macOS.
ServerBin répertoire
Spécifie le répertoire contenant les backends, les programmes CGI, les filtres, les programmes d'assistance, les notificateurs et les moniteurs de ports. La valeur par défaut est "/usr/lib/cups" ou "/usr/libexec/cups" selon la plateforme.
ServerKeychain chemin
Spécifie l'emplacement des certificats TLS et des clés privées. La valeur par défaut est "/Library/Keychains/System.keychain" sur macOS et "/etc/cups/ssl" sur tous les autres systèmes d'exploitation. macOS utilise sa base de données de trousseaux pour stocker les certificats et les clés, tandis que les autres plateformes utilisent des fichiers séparés dans le répertoire spécifié, *.crt pour les certificats encodés en PEM et *.key pour les clés privées encodées en PEM.
ServerRoot répertoire
Spécifie le répertoire contenant les fichiers de configuration du serveur. La valeur par défaut est "/etc/cups".
SetEnv variable valeur
Définit la variable d'environnement spécifiée à transmettre aux processus enfants. Note : les variables d'environnement standard des filtres et backends CUPS ne peuvent pas être remplacées à l'aide de cette directive.
StateDir répertoire
Spécifie le répertoire à utiliser pour les fichiers PID et les certificats locaux. La valeur par défaut est "/var/run/cups" ou "/etc/cups" selon la plateforme.
StripUserDomain Yes
StripUserDomain No
Spécifie s'il faut supprimer le domaine du nom d'utilisateur lors de l'authentification locale de l'utilisateur (par exemple, "utilisateur@example.com" -> "utilisateur"). Cette pratique peut être bénéfique pour maintenir la compatibilité avec les anciennes versions de Kerberos. Cependant, l'activation de cette option peut avoir des conséquences négatives. Elle peut entraîner une confusion entre les utilisateurs de domaine et les utilisateurs locaux portant des noms identiques, conduisant potentiellement à une attribution incorrecte des permissions utilisateur et à une escalade de privilèges involontaire, créant ainsi un risque de sécurité. Par conséquent, il est conseillé d'éviter d'utiliser cette option dans la plupart des cas.
SyncOnClose Yes
SyncOnClose No
Spécifie si le planificateur appelle fsync(2) après avoir écrit des fichiers de configuration ou d'état.
SystemGroup nom-groupe [ ... nom-groupe ]
Spécifie le ou les groupes à utiliser pour l'authentification du groupe @SYSTEM. La valeur par défaut contient "admin", "lpadmin", "root", "sys" et/ou "system".
TempDir répertoire
Spécifie le répertoire où sont stockés les fichiers temporaires de courte durée. La valeur par défaut est "/var/spool/cups/tmp".
User nom-utilisateur
Spécifie le nom d'utilisateur ou l'ID utilisé lors de l'exécution de programmes externes. La valeur par défaut est "lp".

DIRECTIVES OBSOLÈTES

Les directives suivantes sont obsolètes et seront supprimées d'une future version de CUPS :

FileDevice Yes
FileDevice No
Spécifie si le pseudo-périphérique de fichier peut être utilisé pour les nouvelles files d'attente d'imprimante. L'URI "file:///dev/null" est toujours autorisée. Les périphériques de fichier ne peuvent pas être utilisés avec les files d'attente d'impression "raw" - un fichier PPD est requis. Le fichier spécifié est écrasé pour chaque travail d'impression. L'écriture dans des répertoires n'est pas prise en charge.
Printcap nom-fichier
Spécifie un fichier rempli d'une liste des files d'attente d'impression locales.
PrintcapFormat bsd
PrintcapFormat plist
PrintcapFormat solaris
Spécifie le format à utiliser pour le fichier Printcap. "bsd" est le format historique du fichier LPD printcap. "plist" est le format de fichier plist d'Apple. "solaris" est le format historique du fichier LPD printcap de Solaris.

NOTES

Le planificateur DOIT être redémarré manuellement après avoir apporté des modifications au fichier cups-files.conf. Sous Linux, cela se fait généralement à l'aide de la commande systemctl(8), tandis que sous macOS, la commande launchctl(8) est utilisée.
