NOM

Curses::UI::Notebook - Créer et manipuler des widgets carnet d'adresses.

HIÉRARCHIE DE CLASSES

Curses::UI::Widget
   |
   +----Curses::UI::Container
           |
           +----Curses::UI::Notebook

RÉSUMÉ

use Curses::UI;
my $cui = new Curses::UI;
my $win = $cui->add(undef, 'Window');
my $notebook = $win->add(undef, 'Notebook');
my $page1 = $notebook->add_page('page 1');
$page1->add(
    undef, 'Label',
    -x    => 15,
    -y    => 6,
    -text => "Page #1.",
);
my $page2 = $notebook->add_page('page 2');
$page2->add(
    undef, 'Label',
    -x    => 15,
    -y    => 6,
    -text => "Page #2.",
);
my $page3 = $notebook->add_page('page 3', -on_activate => \&sub );
$page3->add(
    undef, 'Label',
    -x    => 15,
    -y    => 6,
    -text => "Page #3.",
);
$notebook->focus;
$cui->mainloop;

DESCRIPTION

Ce paquet implémente un widget carnet similaire à celui trouvé dans Motif. Un carnet contient plusieurs fenêtres, ou pages, dont une seule est visible à la fois ; des onglets en haut du widget listent les pages disponibles. De cette façon, une grande quantité d'informations peut être affichée dans une zone d'écran relativement petite. [Les utilisateurs de Windows reconnaîtront peut-être cela comme une boîte de dialogue à onglets.]

OPTIONS STANDARD

-x, -y, -width, -height, -pad, -padleft, -padright, -padtop, -padbottom, -ipad, -ipadleft, -ipadright, -ipadtop, -ipadbottom, -border, -sbborder, -bg, -fg, -intellidraw, -onchange, -onblur.

Voir Curses::UI::Widget pour une discussion de chacune de ces options.

Notez que -border est activé et que -ipadleft et -ipadright sont définis à 1 par défaut lors de la création des objets carnet.

OPTIONS SPÉCIFIQUES AU WIDGET

  • -bindings < HASHREF >

    Les clés de cette référence de hachage sont des frappes de touches et les valeurs sont les routines auxquelles elles doivent être liées. En cas de touche vide, la routine correspondante deviendra la routine par défaut que process_bindings applique aux frappes de touches non reconnues qu'elle reçoit.

    Par défaut, les correspondances suivantes sont utilisées :

    TOUCHE               ROUTINE
------------------  ----------
KEY_HOME, Ctrl-A    first_page
KEY_END, Ctrl-E     last_page
KEY_NPAGE, Ctrl-N   next_page
KEY_PPAGE, Ctrl-P   prev_page
  • -routines < HASHREF >

    Les clés de cette référence de hachage sont des routines et les valeurs sont soit des valeurs scalaires, soit des références de code. process_bindings associe les frappes de touches à des routines, puis à soit une valeur scalaire, qu'il retourne, soit une référence de code, qu'il exécute.

    Par défaut, les correspondances suivantes sont utilisées :

    ROUTINE         ACTION
----------      -------------------------
first_page      rendre la première page active
last_page       rendre la dernière page active
next_page       rendre la page suivante active
prev_page       rendre la page précédente active
  • -wraparound < BOOLEAN >

    Si BOOLEAN a une valeur vraie, le défilement circulaire est activé. Cela signifie que le passage à la page suivante bouclera de la dernière à la première page et, de même, le passage à la page précédente bouclera de la première à la dernière page.

    Par défaut, il est vrai.

MÉTHODES

  • new ( OPTIONS )

    Construit un nouvel objet carnet en utilisant les options dans le hachage OPTIONS.

  • layout ( )

    Dispose l'objet carnet, s'assure qu'il tient dans l'écran disponible et crée les fenêtres curses pour les étiquettes de bordure / onglet ainsi que la zone de dessin effective.

  • draw ( BOOLEAN )

    Dessine l'objet carnet ainsi que la fenêtre de la page active. Si BOOLEAN est vrai, l'écran n'est pas mis à jour après le dessin.

    Par défaut, BOOLEAN est vrai afin que l'écran soit mis à jour.

  • intellidraw ( )
  • focus ( )
  • onFocus ( CODEREF )
  • onBlur ( CODEREF )

    Voir Curses::UI::Widget pour des explications de ces méthodes.

  • add_page ( PAGE [ , -on_activate => sub_ref ] [, -on_delete => ] )

    Ajoute la page spécifiée à l'objet carnet et crée un objet fenêtre associé. Retourne l'objet fenêtre ou undef en cas d'échec.

    Note : l'ajout échoue si la page ferait autrement déborder la fenêtre d'onglets ou si elle fait déjà partie de l'objet carnet.

    Le "-on_activate" paramètre spécifie un rappel optionnel qui sera invoqué lorsque la page est activée. Ce rappel sera appelé avec le widget carnet et le nom de la page comme paramètres.

    De même pour le rappel "-on_delete" . Celui-ci est invoqué lorsque la page est supprimée.

  • delete_page ( PAGE )

    Supprime la page spécifiée de l'objet carnet et détruit son objet fenêtre associé. Si la page était active, la première page est rendue active.

  • active_page ( )

    Retourne la page actuellement active dans l'objet carnet.

  • first_page ( )

    Retourne la première page dans l'objet carnet.

  • last_page ( )

    Retourne la dernière page dans l'objet carnet.

  • prev_page ( )

    Retourne la page précédente dans l'objet carnet.

  • next_page ( )

    Retourne la page suivante dans l'objet carnet.

  • activate_page ( PAGE )

    Rend la page spécifiée dans l'objet carnet active et la retourne, redessinant l'objet carnet au passage.

  • mouse_button1 ( )

    Traite les clics du bouton de souris n°1. Si l'utilisateur clique avec le bouton gauche sur l'un des onglets, activate_page est appelé avec la page correspondante pour la rendre active ; sinon, le clic est transmis à la fenêtre active.
