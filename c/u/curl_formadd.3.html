curl_formadd(3) Manuel des fonctions de bibliothèque curl_formadd(3)

NOM

curl_formadd - ajouter une section à une soumission de formulaire multipart

SYNOPSIS

#include <curl/curl.h>
CURLFORMcode curl_formadd(struct curl_httppost **firstitem,
                          struct curl_httppost **lastitem, ...);

DESCRIPTION

Cette fonction est obsolète. Utilisez plutôt curl_mime_init(3).

curl_formadd() est utilisée pour ajouter des sections lors de la construction d'une soumission de formulaire multipart. Ajoutez une section à la fois jusqu'à ce que vous ayez ajouté toutes les sections que vous souhaitez inclure, puis passez le pointeur firstitem comme paramètre à CURLOPT_HTTPPOST(3). lastitem est défini après chaque appel à curl_formadd(3) et lors d'invocations répétées, il doit rester tel quel pour permettre aux invocations répétées de trouver plus rapidement la fin de la liste.

Après le pointeur lastitem suivent les arguments réels.

Les pointeurs firstitem et lastitem doivent tous deux pointer vers NULL lors du premier appel à cette fonction. Toutes les données de liste sont allouées par la fonction elle-même. Vous devez appeler curl_formfree(3) sur firstitem après que la soumission du formulaire a été effectuée pour libérer les ressources.

L'utilisation de POST avec HTTP 1.1 implique l'utilisation d'un en-tête "Expect: 100-continue". Vous pouvez désactiver cet en-tête avec CURLOPT_HTTPHEADER(3) comme d'habitude.

Tout d'abord, il y a quelques bases que vous devez comprendre concernant les soumissions de formulaires multipart. Chaque partie se compose au moins d'un NOM et d'un CONTENU. Si la partie est destinée au téléchargement de fichiers, il y a également un TYPE DE CONTENU et un NOM DE FICHIER stockés. Ci-dessous, nous discutons des options que vous utilisez pour définir ces propriétés dans les parties que vous souhaitez ajouter à votre soumission.

Les options listées en premier concernent la création de parties normales. Les options de CURLFORM_FILE à CURLFORM_BUFFERLENGTH concernent les parties de téléchargement de fichiers.

OPTIONS

CURLFORM_COPYNAME
suivi d'une chaîne qui fournit le nom de cette partie. libcurl copie la chaîne, de sorte que votre application n'a pas besoin de la conserver après cet appel de fonction. Si le nom n'est pas terminé par null, vous devez définir sa longueur avec CURLFORM_NAMELENGTH. Le nom ne doit pas contenir d'octets nuls. Les données copiées sont libérées par curl_formfree(3).
CURLFORM_PTRNAME
suivi d'une chaîne qui fournit le nom de cette partie. libcurl utilise le pointeur et fait référence aux données de votre application, vous devez donc vous assurer qu'elles restent disponibles jusqu'à ce que curl n'en ait plus besoin. Si le nom n'est pas terminé par null, vous devez définir sa longueur avec CURLFORM_NAMELENGTH. Le nom ne doit pas contenir d'octets nuls.
CURLFORM_COPYCONTENTS
suivi d'un pointeur vers le contenu de cette partie, les données réelles à envoyer. libcurl copie les données fournies, de sorte que votre application n'a pas besoin de les conserver après cet appel de fonction. Si les données ne sont pas terminées par null, ou si vous souhaitez qu'elles contiennent des octets nuls, vous devez définir la longueur du nom avec CURLFORM_CONTENTSLENGTH. Les données copiées sont libérées par curl_formfree(3).
CURLFORM_PTRCONTENTS
suivi d'un pointeur vers le contenu de cette partie, les données réelles à envoyer. libcurl utilise le pointeur et fait référence aux données de votre application, vous devez donc vous assurer qu'elles restent disponibles jusqu'à ce que curl n'en ait plus besoin. Si les données ne sont pas terminées par null, ou si vous souhaitez qu'elles contiennent des octets nuls, vous devez définir leur longueur avec CURLFORM_CONTENTSLENGTH.
CURLFORM_CONTENTLEN
suivi d'une valeur curl_off_t donnant la longueur du contenu. Notez que pour le contenu CURLFORM_STREAM, cette option est obligatoire.

Si vous passez 0 (zéro) pour cette option, libcurl appelle strlen() sur le contenu pour déterminer la taille. Si vous souhaitez réellement envoyer un contenu de zéro octet, vous devez vous assurer que strlen() sur le pointeur de données retourne zéro.

CURLFORM_CONTENTSLENGTH
(Cette option est obsolète. Utilisez CURLFORM_CONTENTLEN à la place.)

suivi d'un long donnant la longueur du contenu. Notez que pour le contenu CURLFORM_STREAM, cette option est obligatoire.

Si vous passez 0 (zéro) pour cette option, libcurl appelle strlen() sur le contenu pour déterminer la taille. Si vous souhaitez réellement envoyer un contenu de zéro octet, vous devez vous assurer que strlen() sur le pointeur de données retourne zéro.

CURLFORM_FILECONTENT
suivi d'un nom de fichier, provoque la lecture de ce fichier et l'utilisation de son contenu comme données dans cette partie. Cette partie ne devient pas automatiquement une partie de téléchargement de fichier simplement parce que ses données ont été lues à partir d'un fichier.

Le fichier spécifié doit être conservé jusqu'à la fin du transfert associé.

CURLFORM_FILE
suivi d'un nom de fichier, fait de cette partie une partie de téléchargement de fichier. Il définit le champ filename sur le nom de base du nom de fichier fourni, il lit le contenu du fichier et le transmet comme données, et définit le type de contenu si le fichier donné correspond à l'une des extensions de fichier connues en interne. Pour CURLFORM_FILE, l'utilisateur peut envoyer un ou plusieurs fichiers dans une partie en fournissant plusieurs arguments CURLFORM_FILE, chacun suivi du nom de fichier (et chaque CURLFORM_FILE est autorisé à avoir un CURLFORM_CONTENTTYPE).

Le fichier à télécharger doit exister dans son intégralité dans le système de fichiers au moment où le téléchargement commence, car libcurl doit lire la taille correcte du fichier au préalable.

Le fichier spécifié doit être conservé jusqu'à la fin du transfert associé.

CURLFORM_CONTENTTYPE
est utilisé en combinaison avec CURLFORM_FILE. Suivi d'un pointeur vers une chaîne qui fournit le type de contenu pour cette partie, éventuellement au lieu d'un type choisi en interne.
CURLFORM_FILENAME
est utilisé en combinaison avec CURLFORM_FILE. Suivi d'un pointeur vers une chaîne, il indique à libcurl d'utiliser la chaîne donnée comme nom de fichier dans la partie de téléchargement de fichier au lieu du nom de fichier réel.
CURLFORM_BUFFER
est utilisé pour les parties de téléchargement de fichiers personnalisées sans utiliser CURLFORM_FILE. Il indique à libcurl que le contenu du fichier est déjà présent dans un tampon. Le paramètre est une chaîne qui fournit le champ filename dans l'en-tête de contenu.
CURLFORM_BUFFERPTR
est utilisé en combinaison avec CURLFORM_BUFFER. Le paramètre est un pointeur vers le tampon à télécharger. Ce tampon ne doit pas être libéré avant l'appel de curl_easy_cleanup(3). Vous devez également utiliser CURLFORM_BUFFERLENGTH pour définir le nombre d'octets dans le tampon.
CURLFORM_BUFFERLENGTH
est utilisé en combinaison avec CURLFORM_BUFFER. Le paramètre est un long qui donne la longueur du tampon.
CURLFORM_STREAM
Indique à libcurl d'utiliser la fonction de rappel CURLOPT_READFUNCTION(3) pour obtenir les données. Le paramètre que vous passez à CURLFORM_STREAM est le pointeur passé au quatrième argument de la fonction de rappel de lecture. Si vous souhaitez que la partie ressemble à une partie de téléchargement de fichier, définissez également le paramètre CURLFORM_FILENAME. Notez que lors de l'utilisation de CURLFORM_STREAM, CURLFORM_CONTENTSLENGTH doit également être défini avec la longueur totale attendue de la partie, sauf si la soumission du formulaire est envoyée en utilisant le codage par morceaux.
CURLFORM_ARRAY
Une autre possibilité pour envoyer des options à curl_formadd() est l'option CURLFORM_ARRAY, qui passe un pointeur de tableau struct curl_forms

EXEMPL

E 
#include <string.h> /* pour strlen */
static const char record[]="data in a buffer";
int main(void)
{
  CURL *curl = curl_easy_init();
  if(curl) {
    struct curl_httppost *post = NULL;
    struct curl_httppost *last = NULL;
    char namebuffer[] = "name buffer";
    long namelength = strlen(namebuffer);
    char buffer[] = "test buffer";
    char htmlbuffer[] = "<HTML>test buffer</HTML>";
    long htmlbufferlength = strlen(htmlbuffer);
    struct curl_forms forms[3];
    char file1[] = "my-face.jpg";
    char file2[] = "your-face.jpg";
    /* ajouter un caractère nul dans htmlbuffer, pour démontrer que
       les transferts de tampons contenant des caractères nuls fonctionnent réellement
    */
    htmlbuffer[8] = '\0';
    /* Ajouter une section simple nom/contenu */
    curl_formadd(&post, &last, CURLFORM_COPYNAME, "name",
                 CURLFORM_COPYCONTENTS, "content", CURLFORM_END);
    /* Ajouter une section simple nom/contenu/type de contenu */
    curl_formadd(&post, &last, CURLFORM_COPYNAME, "htmlcode",
                 CURLFORM_COPYCONTENTS, "<HTML></HTML>",
                 CURLFORM_CONTENTTYPE, "text/html", CURLFORM_END);
    /* Ajouter une section nom/ptrcontenu */
    curl_formadd(&post, &last, CURLFORM_COPYNAME, "name_for_ptrcontent",
                 CURLFORM_PTRCONTENTS, buffer, CURLFORM_END);
    /* Ajouter une section ptrnom/ptrcontenu */
    curl_formadd(&post, &last, CURLFORM_PTRNAME, namebuffer,
                 CURLFORM_PTRCONTENTS, buffer, CURLFORM_NAMELENGTH,
                 namelength, CURLFORM_END);
    /* Ajouter une section nom/ptrcontenu/type de contenu */
    curl_formadd(&post, &last, CURLFORM_COPYNAME, "html_code_with_hole",
                 CURLFORM_PTRCONTENTS, htmlbuffer,
                 CURLFORM_CONTENTSLENGTH, htmlbufferlength,
                 CURLFORM_CONTENTTYPE, "text/html", CURLFORM_END);
    /* Ajouter une section fichier simple */
    curl_formadd(&post, &last, CURLFORM_COPYNAME, "picture",
                 CURLFORM_FILE, "my-face.jpg", CURLFORM_END);
    /* Ajouter une section fichier/type de contenu */
    curl_formadd(&post, &last, CURLFORM_COPYNAME, "picture",
                 CURLFORM_FILE, "my-face.jpg",
                 CURLFORM_CONTENTTYPE, "image/jpeg", CURLFORM_END);
    /* Ajouter une section de deux fichiers */
    curl_formadd(&post, &last, CURLFORM_COPYNAME, "pictures",
                 CURLFORM_FILE, "my-face.jpg",
                 CURLFORM_FILE, "your-face.jpg", CURLFORM_END);
    /* Ajouter une section de deux fichiers en utilisant CURLFORM_ARRAY */
    forms[0].option = CURLFORM_FILE;
    forms[0].value  = file1;
    forms[1].option = CURLFORM_FILE;
    forms[1].value  = file2;
    forms[2].option  = CURLFORM_END;
    /* Ajouter un tampon à téléverser */
    curl_formadd(&post, &last,
                 CURLFORM_COPYNAME, "name",
                 CURLFORM_BUFFER, "data",
                 CURLFORM_BUFFERPTR, record,
                 CURLFORM_BUFFERLENGTH, sizeof(record),
                 CURLFORM_END);
    /* aucune option nécessaire pour le marqueur de fin */
    curl_formadd(&post, &last, CURLFORM_COPYNAME, "pictures",
                 CURLFORM_ARRAY, forms, CURLFORM_END);
    /* Ajouter le contenu d'un fichier comme valeur de texte de POST normale */
    curl_formadd(&post, &last, CURLFORM_COPYNAME, "filecontent",
                 CURLFORM_FILECONTENT, ".bashrc", CURLFORM_END);
    /* Définir les informations du formulaire */
    curl_easy_setopt(curl, CURLOPT_HTTPPOST, post);
    curl_easy_perform(curl);
    curl_easy_cleanup(curl);
    curl_formfree(post);
  }
}

OBSOLÈT

E

Obsolète depuis la version 7.56.0. Avant cette version, les noms de champs pouvaient contenir des octets de valeur nulle. Le pseudo-nom de fichier "-" pour lire stdin est découragé bi

en que toujours pris en charge, mais les données ne sont pas lues avant d'être effectivement envoyées : la taille effective des données ne peut alors pas être déterminée automatiquem
ent, ce qui entraîne un transfert avec encodage chunked. Les antislashs et les guillemets doubles dans les noms de champs et de fichiers sont désormais échappés avant la transmission.
