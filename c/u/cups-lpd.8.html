NOM

cups-lpd - reçoit les travaux d'impression et signale l'état de l'imprimante aux clients lpd (obsolète)

SYNTAXE

cups-lpd [ -h nom_hote[:port] ] [ -n ] [ -o option=valeur ]

DESCRIPTION

cups-lpd est le mini-serveur CUPS Line Printer Daemon (« LPD ») qui prend en charge les anciens systèmes clients utilisant le protocole LPD. cups-lpd n'agit pas comme un démon réseau autonome, mais fonctionne plutôt en utilisant l'un des « super-serveurs » Internet tels que inetd(8), launchd(8), et systemd(8).

OPTIONS

-h nom_hote[:port]
Définit le serveur CUPS (et le port) à utiliser.
-n
Désactive les recherches d'adresses inversées ; normalement, cups-lpd tentera de découvrir le nom d'hôte du client via une recherche DNS inversée.
-o nom=valeur
Insère des options pour toutes les files d'attente d'impression. Le plus souvent, cela est utilisé pour désactiver le filtre « l｣ » afin que les travaux d'impression distants soient filtrés au besoin pour l'impression ; l'exemple inetd(8) ci-dessous définit l'option « document-format » sur « application/octet-stream », ce qui force la détection automatique du format du fichier d'impression.

CONFORMITE

cups-lpd n'impose pas le numéro de port source restreint spécifié dans la RFC 1179, car l'utilisation de ports restreints n'empêche pas les utilisateurs de soumettre des travaux d'impression. Bien que ce comportement diffère des implémentations Berkeley LPD standard, il ne devrait pas affecter les opérations normales des clients.

La sortie des requêtes d'état suit la RFC 2569, Mapping entre les protocoles LPD et IPP. Comme de nombreuses implémentations LPD s'écartent de cette définition, le rapport d'état à distance aux clients LPD peut être peu fiable.

ERREURS

Les erreurs sont envoyées au journal système.

FICHIERS

/etc/inetd.conf
/etc/xinetd.d/cups-lpd
/System/Library/LaunchDaemons/org.cups.cups-lpd.plist

NOTES

Le programme cups-lpd est obsolète et ne sera plus pris en charge dans une future version de CUPS.

PERFORMANCE

cups-lpd offre de bonnes performances avec un petit nombre de clients et d'imprimantes. Cependant, comme un nouveau processus est créé pour chaque connexion et que chaque processus doit interroger le système d'impression avant chaque soumission de travail, il ne convient pas aux configurations plus importantes. Nous recommandons fortement que les configurations volumineuses utilisent plutôt le support IPP natif fourni par CUPS.

SÉCURITÉ

cups-lpd n'effectue actuellement aucun contrôle d'accès basé sur les paramètres de cupsd.conf(5) ou dans les fichiers hosts.allow(5) ou hosts.deny(5) utilisés par les wrappers TCP. Par conséquent, l'exécution de cups-lpd sur votre serveur permettra à tout ordinateur de votre réseau (et peut-être de l'Internet entier) d'imprimer sur votre serveur.

Bien que xinetd(8) dispose d'un support de contrôle d'accès intégré, vous devriez utiliser le paquet des wrappers TCP avec inetd(8) pour limiter l'accès uniquement aux ordinateurs qui devraient être autorisés à imprimer via votre serveur.

cups-lpd n'est pas activé par la distribution CUPS standard. Veuillez consulter le fournisseur de votre système d'exploitation pour déterminer s'il est activé par défaut sur votre système.

EXEMPLE

Si vous utilisez inetd(8), ajoutez la ligne suivante au fichier inetd.conf pour activer le mini-serveur cups-lpd :

    printer stream tcp nowait lp /usr/lib/cups/daemon/cups-lpd cups-lpd \
        -o document-format=application/octet-stream

CUPS inclut des fichiers de configuration pour launchd(8), systemd(8) et xinetd(8). Il suffit d'activer le service cups-lpd en utilisant le programme de contrôle correspondant.
