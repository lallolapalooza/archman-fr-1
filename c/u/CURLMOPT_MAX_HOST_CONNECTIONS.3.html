CURLMOPT_MAX_HOST_CONNECTIONS(3)

Paquet: curl

Licences: MIT

CURLMOPT_MAX_HOST_CONNECTIONS(3) Manuel de la bibliothèque CURLMOPT_MAX_HOST_CONNECTIONS(3)

NOM

CURLMOPT_MAX_HOST_CONNECTIONS - nombre maximum de connexions vers un hôte unique

SYNTAXE

#include <curl/curl.h>
CURLMcode curl_multi_setopt(CURLM *handle, CURLMOPT_MAX_HOST_CONNECTIONS,
                            long max);

DESCRIPTION

Passez un long pour indiquer max, le nombre maximum de connexions simultanément ouvertes que libcurl peut maintenir vers un seul hôte (un hôte étant identique à une paire nom d'hôte + numéro de port). Pour chaque nouveau transfert vers le même hôte, libcurl peut ouvrir une nouvelle connexion jusqu'à la limite définie par CURLMOPT_MAX_HOST_CONNECTIONS(3). Lorsque la limite est atteinte, les nouvelles sessions restent en attente jusqu'à ce qu'une connexion devienne disponible.

La valeur par défaut de max est 0, ce qui signifie illimité. Cette limite définie est également utilisée pour les connexions proxy, et le proxy est alors considéré comme l'hôte pour lequel cette limite est comptée.

Lorsque plus de transferts sont ajoutés au handle multi qu'il n'est possible d'en effectuer en raison de la limite définie, ils sont mis en file d'attente en attendant leur tour.

Tant qu'un transfert est mis en file d'attente en interne en attendant une connexion, le délai d'attente CURLOPT_TIMEOUT_MS(3) est compté, y compris le temps d'attente. Ainsi, si vous définissez un délai d'attente trop court, le transfert pourrait ne même pas commencer avant d'expirer. Le temps de CURLOPT_CONNECTTIMEOUT_MS(3) est également traité de manière similaire comme un délai d'attente par connexion et peut expirer même avant qu'une nouvelle connexion ne soit autorisée.

Il est possible de modifier cette valeur pendant que des transferts sont en cours. La nouvelle valeur sera utilisée lors des prochaines vérifications. Diminuer la valeur ne ferme pas les transferts actifs, cela permet simplement de ne pas en créer de nouveaux.

DEFAUT

0

PROTOCOLES

Cette fonctionnalité affecte tous les protocoles pris en charge

EXEMPLE

int main(void)
{
  CURLM *m = curl_multi_init();
  /* ne pas dépasser 2 connexions par hôte */
  curl_multi_setopt(m, CURLMOPT_MAX_HOST_CONNECTIONS, 2L);
}

DISPONIBILITE

Ajouté dans curl 7.30.0

VALEUR DE RETOUR

curl_multi_setopt(3) renvoie un CURLMcode indiquant le succès ou l'erreur.

CURLM_OK (0) signifie que tout s'est bien passé, une valeur non nulle indique qu'une erreur s'est produite, voir libcurl-errors(3).
