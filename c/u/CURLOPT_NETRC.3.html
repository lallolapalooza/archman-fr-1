CURLOPT_NETRC(3) Manuel des fonctions de bibliothèque CURLOPT_NETRC(3)

NOM

CURLOPT_NETRC - activer l'utilisation de .netrc

SYNOPSIS

#include <curl/curl.h>
CURLcode curl_easy_setopt(CURL *handle, CURLOPT_NETRC, long level);

DESCRIPTION

Ce paramètre contrôle le niveau de préférence niveau de libcurl entre l'utilisation des noms d'utilisateur et des mots de passe provenant de votre ~/.netrc fichier, par rapport aux noms d'utilisateur et aux mots de passe dans l'URL fournie avec CURLOPT_URL(3). Si la variable d'environnement NETRC est définie, ce nom de fichier est utilisé comme fichier netrc. (Ajouté dans 8.16.0)

Sur Windows, libcurl vérifie principalement la présence de .netrc dans %HOME%. Si %HOME% n'est pas défini sur Windows, libcurl utilise %USERPROFILE%comme solution de repli. Si le fichier n'existe pas, il vérifie la présence d'un fichier nommé _netrc - utilisant un souligné au lieu d'un point.

Vous pouvez également indiquer à libcurl un nom de fichier différent à utiliser avec CURLOPT_NETRC_FILE(3).

libcurl utilise un nom d'utilisateur (et un mot de passe fourni ou demandé) fourni avec CURLOPT_USERPWD(3) ou CURLOPT_USERNAME(3) de préférence à n'importe laquelle des options contrôlées par ce paramètre.

Seuls le nom de machine, le nom d'utilisateur et le mot de passe sont pris en compte (les macros d'initialisation et choses similaires ne sont pas prises en charge).

Le fichier netrc fournit des identifiants pour un nom d'hôte indépendamment du protocole et du numéro de port utilisés.

libcurl ne vérifie pas que le fichier a les propriétés correctes définies (comme le fait le client ftp Unix standard). Il ne devrait être lisible que par l'utilisateur.

niveau est un long qui devrait être défini à l'une des valeurs décrites ci-dessous.

CURL_NETRC_IGNORED (0)
libcurl ignore le fichier .netrc . C'est la valeur par défaut.
CURL_NETRC_OPTIONAL (1)
L'utilisation du fichier .netrc est facultative, et les informations dans l'URL doivent être préférées. Le fichier est parcouru pour rechercher l'hôte et le nom d'utilisateur (pour trouver uniquement le mot de passe) ou pour l'hôte uniquement, afin de trouver le premier nom d'utilisateur et mot de passe après ce machine, selon que les informations ne sont pas spécifiées.
CURL_NETRC_REQUIRED (2)
L'utilisation du fichier .netrc est requise, et toute information d'identifiant présente dans l'URL est ignorée. Le fichier est parcouru pour rechercher l'hôte et le nom d'utilisateur (pour trouver uniquement le mot de passe) ou pour l'hôte uniquement, afin de trouver le premier nom d'utilisateur et mot de passe après ce machine, selon que les informations ne sont pas spécifiées.

FORMAT DU FICHIER

Le format du fichier .netrc est simple : vous spécifiez des lignes avec un nom de machine et suivez du login et du mot de passe associés à cette machine.

Chaque champ est fourni sous forme d'une séquence de lettres qui se termine par un espace ou un saut de ligne. À partir de la version 7.84.0, libcurl prend également en charge les chaînes entre guillemets. Elles commencent et se terminent par des guillemets doubles et prennent en charge les caractères d'échappement ", n, r et t. Les chaînes entre guillemets sont le seul moyen d'utiliser un espace dans un nom d'utilisateur ou un mot de passe.

machine <nom>
Fournit des identifiants pour un hôte appelé nom. libcurl recherche dans le fichier .netrc un jeton machine correspondant au nom d'hôte spécifié dans l'URL. Une fois la correspondance trouvée, les jetons suivants sont traités, en s'arrêtant lorsque la fin du fichier est atteinte ou qu'un autre "machine" est rencontré.
default
C'est la même chose que machine nom sauf que default correspond à n'importe quel nom. Il ne peut y avoir qu'un seul jeton default, et il doit être après tous les jetons machine. Pour fournir un login anonyme par défaut pour les hôtes qui ne sont pas autrement appariés, ajoutez une ligne similaire à celle-ci à la fin : 
default login anonymous password user@domain
login <nom>
La chaîne de nom d'utilisateur pour la machine distante.
password <secret>
Fournit un mot de passe. Si ce jeton est présent, curl fournit la chaîne spécifiée si le serveur distant exige un mot de passe dans le cadre du processus de login. Notez que si ce jeton est présent dans le fichier .netrc, vous devriez vraiment vous assurer que le fichier n'est lisible par personne d'autre que l'utilisateur.
macdef <nom>
Définit une macro. Cette fonctionnalité n'est pas prise en charge par libcurl. Afin que le reste du .netrc fonctionne toujours correctement, libcurl saute proprement chaque définition faite avec "macdef" qu'il trouve.

PAR DÉFAUT

CURL_NETRC_IGNORED

PROTOCOLES

Cette fonctionnalité affecte tous les protocoles pris en charge

EXEMPLE

int main(void)
{
  CURL *curl = curl_easy_init();
  if(curl) {
    CURLcode ret;
    curl_easy_setopt(curl, CURLOPT_URL, "ftp://example.com/");
    curl_easy_setopt(curl, CURLOPT_NETRC, CURL_NETRC_OPTIONAL);
    ret = curl_easy_perform(curl);
  }
}

HISTORIQUE

CURL_NETRC_* les énumérations sont devenues des types long dans la version 8.13.0, avant cette version un long cast était nécessaire lors du passage à curl_easy_setopt(3).

DISPONIBILITÉ

Ajouté dans curl 7.1

VALEUR DE RETOUR

curl_easy_setopt(3) retourne un CURLcode indiquant le succès ou une erreur.

CURLE_OK (0) signifie que tout s'est bien passé, une valeur non nulle signifie qu'une erreur s'est produite, voir libcurl-errors(3).
