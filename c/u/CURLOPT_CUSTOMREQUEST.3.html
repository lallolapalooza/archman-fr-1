CURLOPT_CUSTOMREQUEST(3) Manuel des fonctions de bibliothèque CURLOPT_CUSTOMREQUEST(3)

NOM

CURLOPT_CUSTOMREQUEST - méthode de requête personnalisée

SYNTAXE

#include <curl/curl.h>
CURLcode curl_easy_setopt(CURL *handle, CURLOPT_CUSTOMREQUEST, char *method);

DESCRIPTION

Passe un pointeur vers une chaîne terminée par null en tant que paramètre.

Lors du changement de la méthode de requête en définissant CURLOPT_CUSTOMREQUEST(3), vous ne changez pas réellement la manière dont libcurl se comporte ou agit : vous ne changez que la chaîne réelle envoyée dans la requête.

libcurl transmet la chaîne verbatim dans sa requête sans aucun filtre ou autre garde-fou. Cela inclut les espaces blancs et les caractères de contrôle.

L'application n'a pas à conserver la chaîne après avoir défini cette option.

L'utilisation de cette option plusieurs fois fait que la dernière chaîne définie remplace les précédentes. Restaurez la valeur par défaut interne en définissant cela sur NULL.

Cette option peut être utilisée pour spécifier la requête :

HTTP
Au lieu de GET ou HEAD lors de l'exécution de requêtes basées sur HTTP. Ceci est particulièrement utile, par exemple, pour effectuer une requête HTTP DELETE.

Par exemple :

Lorsque vous dites à libcurl de faire une requête HEAD, mais que vous spécifiez ensuite un GET via une requête personnalisée, libcurl se comporte toujours comme s'il avait envoyé un HEAD. Pour passer à un vrai HEAD, utilisez CURLOPT_NOBODY(3), pour passer à un vrai POST utilisez CURLOPT_POST(3) ou CURLOPT_POSTFIELDS(3) et pour passer à un vrai GET utilisez CURLOPT_HTTPGET(3).

Beaucoup de gens ont utilisé à tort cette option pour remplacer l'intégralité de la requête par la leur, y compris plusieurs en-têtes et contenus POST. Bien que cela puisse fonctionner dans de nombreux cas, cela pourrait amener libcurl à envoyer des requêtes invalides et pourrait potentiellement confondre gravement le serveur distant. Utilisez CURLOPT_POST(3) et CURLOPT_POSTFIELDS(3) pour définir les données POST. Utilisez CURLOPT_HTTPHEADER(3) pour remplacer ou étendre l'ensemble des en-têtes envoyés par libcurl. Utilisez CURLOPT_HTTP_VERSION(3) pour changer la version HTTP.

Lorsque cette option est utilisée avec CURLOPT_FOLLOWLOCATION(3), la méthode définie personnellement remplace la méthode que libcurl pourrait autrement changer pour les requêtes ultérieures. Vous pouvez affiner cette décision en utilisant le bit CURLFOLLOW_OBEYCODE de CURLOPT_FOLLOWLOCATION(3) pour que les redirections respectent le code de réponse de redirection tel qu'indiqué par le protocole.

FTP
Au lieu de LIST et NLST lors de l'exécution de listages de répertoires FTP.
IMAP
Au lieu de LIST lors de l'émission de requêtes IMAP.
POP3
Au lieu de LIST et RETR lors de l'émission de requêtes POP3.

Par exemple :

Lorsque vous dites à libcurl d'utiliser une requête personnalisée, elle se comporte comme si une commande LIST ou RETR avait été envoyée là où elle attend des données à renvoyer par le serveur. Ainsi, CURLOPT_NOBODY(3) doit être utilisé lors de la spécification de commandes telles que DELE et NOOP par exemple.

SMTP
Au lieu de HELP ou VRFY lors de l'émission de requêtes SMTP.

Par exemple :

Normalement, une réponse multiligne est renvoyée, qui peut être utilisée, conjointement avec CURLOPT_MAIL_RCPT(3), pour spécifier une requête EXPN. Si l'option CURLOPT_NOBODY(3) est spécifiée, la requête peut être utilisée pour émettre les commandes NOOP et RSET.

DÉFAUT

NULL

PROTOCOLES

Cette fonctionnalité affecte ftp, http, imap, pop3 et smtp

EXEMPLE

int main(void)
{
  CURL *curl = curl_easy_init();
  if(curl) {
    CURLcode res;
    curl_easy_setopt(curl, CURLOPT_URL, "https://example.com/foo.bin");
    /* Supprimer le chemin donné */
    curl_easy_setopt(curl, CURLOPT_CUSTOMREQUEST, "DELETE");
    res = curl_easy_perform(curl);
    curl_easy_cleanup(curl);
  }
}

DISPONIBILITÉ

Ajouté dans curl 7.1

VALEUR DE RETOUR

curl_easy_setopt(3) renvoie un CURLcode indiquant le succès ou une erreur.

CURLE_OK (0) signifie que tout s'est bien passé, une valeur non nulle indique une erreur, voir libcurl-errors(3).

VOIR AUSSI

CURLINFO_EFFECTIVE_METHOD(3), CURLOPT_HTTPHEADER(3), CURLOPT_NOBODY(3), CURLOPT_REQUEST_TARGET(3)
