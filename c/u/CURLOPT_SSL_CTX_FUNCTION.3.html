DESCRIPTIO

N

Passez un pointeur vers votre fonction de rappel, qui doit correspondre au prototype montré

ci-dessus.

Cette fonction de rappel est appelée par libcurl juste avant l'initialisation d'une connexion SSL, après avoir traité toutes les autres options liées à SSL, afin de donner une dernière chance à l'application de modifier le comportement de l'initialisation SSL. Le paramètre ssl_ctx est un pointeur vers le SSL_CTX de la bibliothèque SSL pour OpenSSL ou wolfSSL, un pointeur vers mbedtls_ssl_config pour mbedTLS. Si une erreur est renvoyée depuis le rappel, aucune tentative d'établissement de connexion n'est effectuée et l'opération perform renvoie le code d'erreur du rappel. Définissez l'argument clientp passé à ce rappel avec l'option CURLOPT_SSL_CTX_DATA(3)

.

Cette fonction est appelée pour toutes les nouvelles connexions établies avec un serveur, pendant la négociation SSL. Bien que ssl_ctx pointe vers un objet nouvellement initialisé à chaque fois, le pointeur peut toujours être le même que lors d'un appel

précédent.

Pour utiliser ce rappel, une connaissance non trivial de votre bibliothèque SSL est nécessaire. Par exemple, vous pouvez utiliser cette fonction pour appeler des rappels spécifiques à la bibliothèque afin d'ajouter du code de validation supplémentaire pour les certificats, et même pour changer l'URI réelle d'une requête

HTTPS.

Pour OpenSSL, la vérification asynchrone des certificats via SSL_set_retry_verify est prise en charge. Quand SSL_set_retry_verify est défini, le transfert est mis en pause. Quand la vérification doit continuer, appelez curl_easy_pause(3) pour reprendre le transfert. (Ajouté en 8.3.0, mise en pause ajoutée en 8.16.

0)

Le rappel CURLOPT_SSL_CTX_FUNCTION(3) permet à l'application d'intervenir et de modifier les détails SSL dans la connexion sans que libcurl lui-même ne le sache, ce qui peut ensuite conduire libcurl à réutiliser involontairement des connexions SSL avec des propriétés différentes. Pour remédier à cela, vous pouvez définir CURLOPT_FORBID_REUSE(3) depuis la fonction de

rappel.

Si vous utilisez DNS-over-HTTPS (DoH) via CURLOPT_DOH_URL(3), ce rappel est également appelé pour ces transferts et le handle curl est défini comme un handle interne. Ce comportement est susceptible de changer. Nous recommandons de définir CURLOPT_PRIVATE(3) sur votre handle curl afin de pouvoir l'identifier correctement dans le rappel de contexte. Si vous avez une raison de modifier le contexte SSL DoH, veuillez nous le signaler sur la liste de diffusion curl-library car nous envisageons de supprimer cette

fonctionnalité.

libcurl ne garantit pas la durée de vie de l'objet passé une fois que cette fonction de rappel est retournée. Votre application ne doit pas supposer qu'elle peut continuer à utiliser le contexte SSL ou les données en dérivant une fois que cette fonction est

terminée.

Pour les compilations de libcurl utilisant des backends TLS qui prennent en charge la mise en cache des CA et si CURLOPT_CA_CACHE_TIMEOUT(3) n'est pas défini à zéro, plusieurs appels à

ce rappel peuvent être effectués a
vec le même magasin de CA en mémoire.

E 
/* Spécifique à OpenSSL */
#include <openssl/ssl.h>
#include <curl/curl.h>
#include <stdio.h>
static CURLcode sslctx_function(CURL *curl, void *sslctx, void *pointer)
{
  X509_STORE *store;
  X509 *cert = NULL;
  BIO *bio;
  char *mypem = pointer;
  /* obtenir un BIO */
  bio = BIO_new_mem_buf(mypem, -1);
  /* l'utiliser pour lire le certificat formaté PEM depuis la mémoire dans une
   * structure X509 que SSL peut utiliser
   */
  PEM_read_bio_X509(bio, &cert, 0, NULL);
  if(!cert)
    printf("PEM_read_bio_X509 failed...\n");
  /* obtenir un pointeur vers le magasin de certificats X509 (qui peut être vide) */
  store = SSL_CTX_get_cert_store((SSL_CTX *)sslctx);
  /* ajouter notre certificat à ce magasin */
  if(X509_STORE_add_cert(store, cert) == 0)
    printf("error adding certificate\n");
  /* diminuer les comptes de références */
  X509_free(cert);
  BIO_free(bio);
  /* tout est prêt */
  return CURLE_OK;
}
int main(void)
{
  CURL *ch;
  CURLcode rv;
  char *mypem = /* Certificat CA au format PEM, remplacez les XXX */
    "-----BEGIN CERTIFICATE-----\n"
    "XXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXX\n"
    "XXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXX\n"
    "XXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXX\n"
    "XXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXX\n"
    "XXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXX\n"
    "XXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXX\n"
    "-----END CERTIFICATE-----\n";
  curl_global_init(CURL_GLOBAL_ALL);
  ch = curl_easy_init();
  curl_easy_setopt(ch, CURLOPT_SSLCERTTYPE, "PEM");
  curl_easy_setopt(ch, CURLOPT_SSL_VERIFYPEER, 1L);
  curl_easy_setopt(ch, CURLOPT_URL, "https://www.example.com/");
  curl_easy_setopt(ch, CURLOPT_SSL_CTX_FUNCTION, *sslctx_function);
  curl_easy_setopt(ch, CURLOPT_SSL_CTX_DATA, mypem);
  rv = curl_easy_perform(ch);
  if(!rv)
    printf("*** transfer succeeded ***\n");
  else
    printf("*** transfer failed ***\n");
  curl_easy_cleanup(ch);
  curl_global_cleanup();
  return rv;
}
