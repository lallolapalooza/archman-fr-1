CURLMOPT_NOTIFYFUNCTION(3) Manuel de fonctions de bibliothèque CURLMOPT_NOTIFYFUNCTION(3)

NOM

CURLMOPT_NOTIFYFUNCTION - rappel recevant des notifications

SYNTAXE

#include <curl/curl.h>
void notify_callback(CURLM *multi,     /* handle multi */
                     unsigned int notification, /* type de notification */
                     CURL *easy,       /* handle easy */
                     void *notifyp);   /* pointeur privé de notification */
CURLMcode curl_multi_setopt(CURLM *handle, CURLMOPT_NOTIFYFUNCTION, notify_callback);

DESCRIPTION

Passez un pointeur vers votre fonction de rappel, qui doit correspondre au prototype indiqué ci-dessus.

Lorsque le handle multi traite des transferts, des changements peuvent être observés en recevant des notifications à leur sujet. Cela peut éliminer le besoin d'interroger constamment le handle multi pour observer de tels changements et agir en conséquence.

Les notifications sont collectées et envoyées à la fonction de rappel de l'application à un moment approprié.

Le rappel de notification est différent des autres rappels car il peut utiliser davantage de fonctions de l'API libcurl. Outre curl_multi_perform(3), curl_multi_socket(3), curl_multi_socket_action(3), curl_multi_socket_all(3) et curl_multi_cleanup(3), il peut appeler toutes les autres méthodes sur les handles multi et easy. Cela inclut l'ajout et la suppression de handles easy au/du handle multi.

Ce rappel peut être invoqué à tout moment lors de l'interaction avec libcurl. Cela peut même se produire après la fin de tous les transferts et peut également se produire *pendant* un appel à curl_multi_cleanup(3) lorsque les connexions mises en cache sont fermées.

ARGUMENTS DE RAPPEL

multi identifie le handle multi qui a déclenché la notification.

notification est le type de notification, c'est-à-dire ce qui s'est passé. Les types suivants sont disponibles actuellement. À l'avenir, de nouveaux types pourraient être ajoutés.

CURLMNOTIFY_INFO_READ
Lorsqu'il est activé via curl_multi_notify_enable(3), cela informe l'application qu'il y a de nouveaux messages à traiter via curl_multi_info_read(3).

Cette notification se produit chaque fois qu'un message est ajouté à une pile de messages vide dans le handle multi, et non pour les ajouts subséquents. Le rappel de notification est alors censé lire tous les messages disponibles, vidant la pile, de sorte qu'un ajout ultérieur déclenche à nouveau la notification.

Le handle easy passé est un handle interne.

CURLMNOTIFY_EASY_DONE
Lorsqu'il est activé via curl_multi_notify_enable(3), cette notification est déclenchée lorsqu'un handle easy est terminé. Cela se produit à la fois pour les transferts réussis et échoués.

Le handle easy passé est le transfert terminé. Il peut s'agir d'un handle interne lorsque DoH ou d'autres fonctionnalités sont utilisées.

easy identifie le transfert impliqué. Il peut s'agir d'un des handles easy de l'application ou d'un handle interne.

notifyp est défini avec CURLMOPT_NOTIFYDATA(3).

PAR DÉFAUT

NULL (aucun rappel)

PROTOCOLES

Cette fonctionnalité affecte tous les protocoles pris en charge

EXEMPLE

struct priv {
  void *ours;
};
static void notify_cb(CURLM *multi, unsigned int notification,
                      CURL *easy, void *notifyp)
{
  struct priv *p = notifyp;
  printf("mon ptr: %p\n", p->ours);
  /* ... */
}
int main(void)
{
  struct priv setup;
  CURLM *multi = curl_multi_init();
  /* ... utiliser le rappel de socket et le pointeur personnalisé */
  curl_multi_setopt(multi, CURLMOPT_NOTIFYFUNCTION, notify_cb);
  curl_multi_setopt(multi, CURLMOPT_NOTIFYDATA, &setup);
  curl_multi_notify_enable(multi, CURLMNOTIFY_INFO_READ);
}

DISPONIBILITÉ

Ajouté dans curl 8.17.0

VALEUR DE RETOUR

Retourne CURLM_OK.
