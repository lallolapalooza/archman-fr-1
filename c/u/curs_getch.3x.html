NOM

getch, wgetch, mvgetch, mvwgetch, ungetch, has_key - obtenir (ou remettre dans la file) des caractères depuis le clavier du terminal curses

SYNTAXE

#include <curses.h>
int getch(void);
int wgetch(WINDOW *win);
int mvgetch(int y, int x);
int mvwgetch(WINDOW *win, int y, int x);
int ungetch(int c);
/* extension */
int has_key(int c);

DESCRIPTION

Lecture des caractères

wgetch collecte une frappe de clavier associée à une fenêtre curses nommée win. ncurses(3X) décrit les variantes de cette fonction.

Lorsqu'une entrée est en attente, wgetch renvoie un entier identifiant la frappe de clavier ; pour les touches alphanumériques et de ponctuation, cette valeur correspond au code de caractères utilisé par le terminal. L'utilisation de la touche Contrôle comme modificateur donne souvent un code distinct. Le comportement des autres touches dépend de si win est en mode clavier ; voir le sous-paragraphe « Mode clavier » ci-dessous.

Si aucune entrée n'est en attente, alors si le drapeau "pas d'attente" (no-delay) est activé dans la fenêtre (voir nodelay(3X)), la fonction renvoie ERR ; sinon, curses attend qu'une entrée soit disponible sur le terminal. Si cbreak(3X) a été appelée, cela se produit après la lecture d'un seul caractère. Si nocbreak(3X) a été appelée, cela se produit à la lecture du prochain caractère de nouvelle ligne. Si halfdelay(3X) a été appelée, curses attend qu'un caractère soit tapé ou que le délai spécifié s'écoule.

Si echo(3X) a été appelée, et que la fenêtre n'est pas un "pad", curses écrit le caractère renvoyé c dans la fenêtre (à la position du curseur) selon les règles suivantes.

  • Si c correspond au caractère d'effacement du terminal, le curseur se déplace d'une position vers la gauche et la nouvelle position est effacée comme si wmove(3X) puis wdelch(3X) avaient été appelées. Lorsque le mode clavier de la fenêtre est activé (voir ci-dessous), KEY_LEFT et KEY_BACKSPACE sont traités de la même manière.
  • curses écrit tout autre c dans la fenêtre, comme avec wechochar(3X).
  • Si la fenêtre a été déplacée ou modifiée depuis le dernier appel à wrefresh(3X), curses appelle wrefresh.

Si c est un retour chariot et nl(3X) a été appelée, wgetch renvoie le code caractère de saut de ligne à la place.

Mode clavier

Pour curses, les frappes de clavier qui ne proviennent pas de la section alphabétique du clavier (celles correspondant à l'ensemble de caractères ECMA-6 — voir ascii(7) — optionnellement modifiées par les touches Contrôle ou Maj) sont traitées comme des touches de fonction. (Dans curses, le terme « touche de fonction » inclut, mais sans s'y limiter, les touches gravées avec « F1 », « PF1 », etc.) Si la fenêtre est en mode clavier, celles-ci produisent un code numérique correspondant aux symboles KEY_ listés dans le sous-paragraphe « Codes de touches prédéfinis » ci-dessous ; sinon, elles transmettent une séquence de codes commençant typiquement par le caractère d'échappement, et qui doit être collectée avec plusieurs appels à wgetch.

  • Le fichier d'en-tête curses.h déclare de nombreuses touches de fonction prédéfinies dont les noms commencent par KEY_ ; ces macros de type objet ont des valeurs en dehors de la plage des codes de caractères sur huit bits.
  • Dans ncurses, les touches de fonction définies par l'utilisateur sont configurées avec define_key(3X) ; elles n'ont pas de noms, mais sont également censées avoir des valeurs en dehors de la plage des codes sur huit bits.

Une variable destinée à contenir un code de touche de fonction doit donc être de type short ou supérieur.

La plupart des terminaux rencontrés suivent la norme ECMA-48 en ce qui concerne les séquences de caractères préfixées par le caractère d'échappement ESC que leurs touches de fonction produisent. Ce fait implique que curses ne peut pas savoir si le terminal a envoyé une frappe de la touche ESC ou le début d'une séquence de touches de fonction sans attendre de voir si, et combien de temps après, une entrée supplémentaire arrive. Lorsque curses lit un tel caractère ambigu, il démarre un minuteur. Si le reste de la séquence n'arrive pas dans le délai imparti, wgetch renvoie le caractère préfixe ; sinon, il renvoie le code de la touche de fonction correspondant à la séquence unique définie par le terminal. Par conséquent, un utilisateur d'une application curses peut subir un délai après avoir appuyé sur ESC pendant que curses désambiguïse l'entrée ; voir la section « EXTENSIONS » ci-dessous. Si la fenêtre est en mode « pas de délai d'attente » (no time-out), le minuteur n'expire pas ; il a une valeur infinie (ou très grande). Voir notimeout(3X). Étant donné que les séquences de touches de fonction commencent généralement par un caractère d'échappement, le terminal peut sembler se bloquer en mode « pas de délai d'attente » après que l'utilisateur ait appuyé sur ESC. Généralement, une saisie ultérieure « réveille » curses.

Remettre des caractères dans la file

ungetch place c dans la file d'attente d'entrée pour être renvoyé par le prochain appel à wgetch. Une seule file d'entrée sert toutes les fenêtres.

Certaines frappes de touches sont indiscernables des caractères de contrôle ; par exemple, KEY_ENTER peut être identique à ^M, et KEY_BACKSPACE peut être identique à ^H ou ^?. Consultez l' entrée terminfo du terminal pour déterminer si c'est le cas ; voir infocmp(1). spéciale.
