CURLOPT_POST(3) Manuel des fonctions de bibliothèque CURLOPT_POST(3)

NOM

CURLOPT_POST - effectuer une requête POST HTTP

SYNTAXE

#include <curl/curl.h>
CURLcode curl_easy_setopt(CURL *handle, CURLOPT_POST, long post);

DESCRIPTION

Un paramètre défini à 1 indique à libcurl d'effectuer une requête POST HTTP normale. Cela fait également que libcurl utilise un en-tête "Content-Type: application/x-www-form-urlencoded". C'est la méthode POST la plus couramment utilisée.

Utilisez l'une des options CURLOPT_POSTFIELDS(3) ou CURLOPT_COPYPOSTFIELDS(3) pour spécifier les données à envoyer et CURLOPT_POSTFIELDSIZE(3) ou CURLOPT_POSTFIELDSIZE_LARGE(3) pour définir la taille des données.

Optionnellement, vous pouvez fournir des données à envoyer via POST en utilisant les options CURLOPT_READFUNCTION(3) et CURLOPT_READDATA(3), mais vous devez alors vous assurer de ne pas définir CURLOPT_POSTFIELDS(3) à autre chose que NULL. Lorsque vous fournissez des données via un rappel, vous devez les transmettre en utilisant l'encodage par transfert par morceaux (chunked) ou vous devez définir la taille des données avec les options CURLOPT_POSTFIELDSIZE(3) ou CURLOPT_POSTFIELDSIZE_LARGE(3). Pour activer l'encodage par morceaux, il suffit de passer l'en-tête Transfer-Encoding approprié, voir l'exemple post-callback.c.

Vous pouvez remplacer l'en-tête POST Content-Type: par défaut en définissant le vôtre avec CURLOPT_HTTPHEADER(3).

Utiliser POST avec HTTP 1.1 implique l'utilisation d'un en-tête "Expect: 100-continue". Vous pouvez désactiver cet en-tête avec CURLOPT_HTTPHEADER(3) comme d'habitude.

Si vous utilisez POST vers un serveur HTTP 1.1, vous pouvez envoyer des données sans connaître leur taille avant de commencer la requête POST si vous utilisez l'encodage par morceaux. Vous activez cela en ajoutant un en-tête comme "Transfer-Encoding: chunked" avec CURLOPT_HTTPHEADER(3). Avec HTTP 1.0 ou sans transfert par morceaux, vous devez spécifier la taille dans la requête. (Depuis la version 7.66.0, libcurl utilise automatiquement l'encodage par morceaux pour les requêtes POST si la taille est inconnue.)

Lors de la définition de CURLOPT_POST(3) à 1, libcurl définit automatiquement CURLOPT_NOBODY(3) et CURLOPT_HTTPGET(3) à 0.

Si vous effectuez une requête POST et que vous souhaitez ensuite en effectuer une en HEAD ou GET en utilisant le même descripteur réutilisé, vous devez explicitement définir le nouveau type de requête en utilisant CURLOPT_NOBODY(3) ou CURLOPT_HTTPGET(3) ou similaire.

Lors de la définition de CURLOPT_POST(3) à 0, libcurl réinitialise le type de requête à sa valeur par défaut pour désactiver le POST. Typiquement, cela signifie que GET est réinitialisé à GET. Au lieu de cela, vous devriez définir explicitement un nouveau type de requête comme décrit ci-dessus.

DÉFAUT

0, désactivé

PROTOCOLES

Cette fonctionnalité affecte uniquement http

EXEMPLE

int main(void)
{
  CURL *curl = curl_easy_init();
  if(curl) {
    CURLcode res;
    curl_easy_setopt(curl, CURLOPT_URL, "https://example.com/foo.bin");
    curl_easy_setopt(curl, CURLOPT_POST, 1L);
    /* configurer le rappel de lecture avec CURLOPT_READFUNCTION */
    res = curl_easy_perform(curl);
    curl_easy_cleanup(curl);
  }
}

DISPONIBILITÉ

Ajouté dans la version curl 7.1

VALEUR DE RETOUR

curl_easy_setopt(3) retourne un code CURLcode indiquant le succès ou une erreur.

CURLE_OK (0) signifie que tout s'est bien passé, une valeur non nulle indique une erreur, voir libcurl-errors(3).
