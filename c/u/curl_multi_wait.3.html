curl_multi_wait(3)

Paquet: curl

Licences: MIT

curl_multi_wait(3) Manuel des fonctions de bibliothèque curl_multi_wait(3)

NOM

curl_multi_wait - interroger tous les descripteurs faciles dans un descripteur multiple

SYNTAXE

#include <curl/curl.h>
CURLMcode curl_multi_wait(CURLM *multi_handle,
                          struct curl_waitfd extra_fds[],
                          unsigned int extra_nfds,
                          int timeout_ms,
                          int *numfds);

DESCRIPTION

curl_multi_wait(3) interroge tous les descripteurs de fichier utilisés par les descripteurs faciles de curl contenus dans l'ensemble de descripteurs multiples donné. Il bloque jusqu'à ce qu'une activité soit détectée sur au moins un des descripteurs ou que timeout_ms soit écoulé. Alternativement, si le descripteur multiple a un délai d'attente interne en attente dont l'expiration est plus courte que timeout_ms, ce temps plus court est utilisé à la place pour garantir que la précision du délai d'attente est raisonnablement conservée.

L'application appelante peut fournir des structures curl_waitfd supplémentaires qui sont similaires à la structure pollfd de poll(2) pour être attendues dans le même appel.

À l'achèvement, si numfds n'est pas NULL, il est rempli avec le nombre total de descripteurs de fichier sur lesquels des événements intéressants se sont produits. Ce nombre peut inclure à la fois les descripteurs internes de libcurl ainsi que les descripteurs fournis dans extra_fds.

Si aucun descripteur de fichier supplémentaire n'est fourni et que libcurl n'a aucun descripteur de fichier à proposer pour attente, cette fonction retourne immédiatement. (Envisagez d'utiliser curl_multi_poll(3) pour éviter ce comportement.)

Il est recommandé d'utiliser cette fonction au lieu de select(3) lors de l'utilisation de l'interface multiple pour permettre aux applications de contourner plus facilement le problème courant des 1024 descripteurs de fichier maximum.

curl_waitfd

struct curl_waitfd {
  curl_socket_t fd;
  short events;
  short revents;
};
CURL_WAIT_POLLIN
Indicateur de bit pour curl_waitfd.events indiquant que le socket doit interroger les événements de lecture tels que les nouvelles données reçues.
CURL_WAIT_POLLPRI
Indicateur de bit pour curl_waitfd.events indiquant que le socket doit interroger les événements de lecture à haute priorité tels que les données hors bande.
CURL_WAIT_POLLOUT
Indicateur de bit pour curl_waitfd.events indiquant que le socket doit interroger les événements d'écriture tels que le socket est prêt à écrire sans bloquer.

PROTOCOLES

Cette fonctionnalité affecte tous les protocoles pris en charge

EXEMPLE

int main(void)
{
  CURL *easy;
  CURLM *multi = curl_multi_init();
  int still_running;
  easy = curl_easy_init();
  /* ajouter le descripteur facile individuel */
  curl_multi_add_handle(multi, easy);
  do {
    CURLMcode mc;
    int numfds;
    mc = curl_multi_perform(multi, &still_running);
    if(mc == CURLM_OK) {
      /* attendre l'activité, le délai d'attente ou "rien" */
      mc = curl_multi_wait(multi, NULL, 0, 1000, &numfds);
    }
    if(mc != CURLM_OK) {
      fprintf(stderr, "curl_multi a échoué, code %d.\n", mc);
      break;
    }
  } while(still_running);
  curl_multi_remove_handle(multi, easy);
}

DISPONIBILITÉ

Ajouté dans curl 7.28.0

VALEUR DE RETOUR

Cette fonction retourne un CURLMcode indiquant le succès ou l'erreur.

CURLM_OK (0) signifie que tout était correct, une valeur différente de zéro indique une erreur, voir libcurl-errors(3).
