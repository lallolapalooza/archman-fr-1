CURLSHOPT_SHARE(3) Manuel des fonctions de bibliothèque CURLSHOPT_SHARE(3)

NOM

CURLSHOPT_SHARE - ajouter des données à partager

SYNTAXE

#include <curl/curl.h>
CURLSHcode curl_share_setopt(CURLSH *share, CURLSHOPT_SHARE, long type);

DESCRIPTION

Le paramètre type spécifie quelles données spécifiques doivent être partagées et conservées dans l'objet de partage qui a été créé avec curl_share_init(3). Le type donné doit être l'une des valeurs décrites ci-dessous. Vous pouvez définir CURLSHOPT_SHARE(3) plusieurs fois avec différents arguments de données pour que l'objet de partage partage plusieurs types de données. Annulez un type en définissant CURLSHOPT_UNSHARE(3).

Si des données doivent être partagées entre plusieurs threads, des fonctions de rappel mutex doivent également être définies. Voir CURLSHOPT_LOCKFUNC(3) et CURLSHOPT_UNLOCKFUNC(3).

CURL_LOCK_DATA_COOKIE
Les données de cookies sont partagées entre les handles easy utilisant cet objet de partage. Notez que cela n'active pas la gestion des cookies d'un handle easy. Vous pouvez le faire séparément en utilisant par exemple CURLOPT_COOKIEFILE(3).

Le partage de cookies entre plusieurs threads simultanés n'est pas pris en charge.

CURL_LOCK_DATA_DNS
Les hôtes DNS mis en cache sont partagés entre les handles easy utilisant cet objet de partage. Notez que lorsque vous utilisez l'interface multi, tous les handles easy ajoutés au même handle multi partagent le cache DNS par défaut sans utiliser cette option.
CURL_LOCK_DATA_SSL_SESSION
Les sessions SSL sont partagées entre les handles easy utilisant cet objet de partage. Cela réduit le temps passé dans la négociation SSL lors de la reconnexion au même serveur.

Notez que lorsque vous utilisez l'interface multi, tous les handles easy ajoutés au même handle multi partagent le cache de session SSL par défaut sans utiliser cette option.

CURL_LOCK_DATA_CONNECT
Place le cache de connexion dans l'objet de partage et fait en sorte que tous les handles easy utilisant cet objet de partage partagent le cache de connexion.

Le partage de connexions entre plusieurs threads simultanés n'est pas pris en charge.

Les connexions utilisées pour le multiplexage HTTP/2 ou HTTP/3 ne reçoivent des transferts supplémentaires que si la connexion existante est détenue par le même handle multi ou easy. libcurl ne prend pas en charge les flux multiplexés dans différents threads utilisant une connexion partagée.

Notez que lorsque vous utilisez l'interface multi, tous les handles easy ajoutés au même handle multi partagent le cache de connexion par défaut sans utiliser cette option.

CURL_LOCK_DATA_PSL
La liste des suffixes publics stockée dans l'objet de partage est rendue disponible à tous les handles easy liés à celui-ci par la suite. Comme la liste des suffixes publics est actualisée périodiquement, cela évite les mises à jour dans trop de contextes différents.

Ajouté dans la version 7.61.0.

Notez que lorsque vous utilisez l'interface multi, tous les handles easy ajoutés au même handle multi partagent le cache PSL par défaut sans utiliser cette option.

CURL_LOCK_DATA_HSTS
Le cache HSTS en mémoire.

Le partage du HSTS entre plusieurs threads simultanés n'est pas pris en charge.

Ajouté dans la version 7.88.0

PROTOCOLES

Cette fonctionnalité affecte tous les protocoles pris en charge.

EXEMPLE

int main(void)
{
  CURLSHcode sh;
  CURLSH *share = curl_share_init();
  sh = curl_share_setopt(share, CURLSHOPT_SHARE, CURL_LOCK_DATA_COOKIE);
  if(sh)
    printf("Erreur : %s\n", curl_share_strerror(sh));
}

DISPONIBILITE

Ajouté dans curl 7.10.3

VALEUR DE RETOUR

CURLSHE_OK (zéro) signifie que l'option a été correctement définie, une valeur non nulle indique qu'une erreur s'est produite. Voir libcurl-errors(3) pour la liste complète avec descriptions.
