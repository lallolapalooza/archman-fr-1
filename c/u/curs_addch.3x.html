Jeu de

caractères

X/Open Curses suppose que le paramètre passé à waddch contient un seul caractère. Comme discuté dans curs_attr(3X), ce caractère peut avoir été plus de huit bits de large dans une implémentation SVr3 ou SVr4, mais dans le modèle X/Open Curses, les détails ne sont pas donnés. La distinction importante entre SVr4 curses et X/Open Curses est que ce dernier sépare les informations non caractères (attributs et couleur) du code de caractère, que SVr4 emballe dans un chtype pour le transmettre à waddch

.

Dans ncurses, chtype contient un caractère de huit bits. Mais la bibliothèque permet de passer un caractère multi-octets dans une succession d'appels à waddch. D'autres implémentations ne le font pas ; un appel waddch transmet exactement un caractère, qui peut être rendu à un ou plusieurs emplacements de l'écran selon qu'il est imprimable ou

non.

Selon les paramètres de la locale, ncurses inspecte l'octet passé dans chaque appel waddch, et vérifie si le dernier appel continue une séquence multi-octets. Lorsqu'un caractère est complet, ncurses affiche le caractère et avance le

curseur.

Si l'application appelante interrompt la succession d'octets d'une séquence de caractères multi-octets en changeant l'emplacement courant—par exemple avec wmove(3X)—ncurses abandonne le caractère

incomplet.

Pour la portabilité avec d'autres implémentations, ne comptez pas sur ce comportement. Vérifiez si un caractère peut être représenté sur un seul octet dans la locale

courante.

  • S'il ne peut pas l'être, utilisez uniquement wadd_
    • wch
