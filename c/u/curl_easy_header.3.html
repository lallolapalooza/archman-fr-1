curl_easy_header(3)

Paquet: curl

Licences: MIT

curl_easy_header(3) Manuel des fonctions de bibliothèque curl_easy_header(3)

NOM

curl_easy_header - obtenir un en-tête HTTP

SYNOPSIS

#include <curl/curl.h>
CURLHcode curl_easy_header(CURL *easy,
                           const char *name,
                           size_t index,
                           unsigned int origin,
                           int request,
                           struct curl_header **hout);

DESCRIPTION

curl_easy_header(3) renvoie un pointeur vers une structure "curl_header" dans hout contenant les données de l'en-tête de réponse HTTP name. Le nom d'en-tête, insensible à la casse et terminé par un caractère nul, doit être spécifié sans les deux-points.

index 0 signifie demander la première occurrence de l'en-tête. Si la structure d'en-tête renvoyée a amount défini à une valeur supérieure à 1, cela signifie qu'il existe d'autres occurrences du même nom d'en-tête disponibles. Demander un index trop grand fait renvoyer CURLHE_BADINDEX .

L'argument origin sert à spécifier quels en-têtes recevoir, car un seul transfert HTTP peut fournir des en-têtes provenant de plusieurs endroits différents, qui peuvent alors avoir une importance différente pour l'utilisateur, et des en-têtes utilisant le même nom peuvent être utilisés. L' origin est un masque de bits indiquant les sources d'en-têtes souhaitées. Voir les descriptions ci-dessous.

L'argument request indique à libcurl à quelle requête vous voulez les en-têtes. Un seul transfert peut consister en une série de requêtes HTTP et cet argument vous permet de spécifier la requête individuelle particulière dont vous voulez les en-têtes. 0 correspond à la première requête, puis le nombre augmente pour les redirections suivantes ou lorsque l'authentification multi-états est utilisée. Passer -1 est un raccourci pour « la dernière » requête de la série, indépendamment du nombre réel de requêtes utilisées.

libcurl stocke et fournit les en-têtes « corrects » effectivement utilisés. Si par exemple deux en-têtes avec le même nom arrivent et que le second remplace le premier, alors seul le second est fourni. Si le premier en-tête survit au second, alors seul le premier est fourni. Une application utilisant cette API n'a pas à se soucier de plusieurs en-têtes utilisés à tort.

La mémoire de la structure renvoyée est associée à la poignée facile et les appels suivants à curl_easy_header(3) écrasent la structure utilisée dans les appels précédents pour la même poignée facile. L'application doit copier les données si elle veut les conserver. La mémoire utilisée pour la structure est libérée lors de l'appel à curl_easy_cleanup(3) de la poignée facile.

La première ligne d'une réponse HTTP est appelée la ligne de statut. Elle n'est pas considérée comme un en-tête par cette fonction. Les en-têtes sont les lignes « nom : valeur » suivant le statut.

Cette fonction peut être utilisée avant que (tous) les en-têtes aient été reçus et peut être appelée depuis des rappels de libcurl. Elle renvoie l'état des en-têtes au moment de l'appel.

La structure d'en-tête

struct curl_header {
   char *name;
   char *value;
   size_t amount;
   size_t index;
   unsigned int origin;
   void *anchor;
};

Les données vers lesquelles pointe le champ name sont les mêmes que le nom demandé, mais peuvent avoir une casse différente.

Les données vers lesquelles pointe le champ value proviennent exactement telles que livrées sur le réseau, mais avec les espaces et sauts de ligne de début et de fin supprimés. Les données value sont terminées par un caractère nul. Pour les « en-têtes pliés » hérités d'HTTP/1, cette API fournit la valeur complète unique de manière dépliée avec un espace unique entre les lignes.

amount indique combien d'en-têtes utilisant ce nom existent, dans la portée de l'origine et de la requête demandée.

index est le numéro d'entrée à base zéro de cet en-tête particulier, qui, si cet en-tête a été utilisé plus d'une fois dans la portée demandée, peut être supérieur à 0 mais est toujours inférieur à amount.

Le champ origin dans la structure "curl_header" a un des bits d'origine défini, indiquant d'où provient l'en-tête. Au moment de la rédaction de ce document, il y a 5 bits avec une utilisation définie. Les 27 bits restants non documentés sont réservés à une utilisation future et ne doivent pas être supposés avoir une valeur particulière.

anchor est une poignée privée utilisée par les composants internes de libcurl. Ne pas modifier.

ORIGINES

CURLH_HEADER
L'en-tête est arrivé en tant qu'en-tête du serveur.
CURLH_TRAILER
L'en-tête est arrivé en tant que traîneau. Un en-tête qui arrive après le corps.
CURLH_CONNECT
L'en-tête est arrivé dans une réponse CONNECT. Une requête CONNECT est en cours pour configurer un transfert « à travers » un proxy HTTP(S).
CURLH_1XX
L'en-tête est arrivé dans une réponse HTTP 1xx. Une réponse 1xx est une réponse « intermédiaire » qui peut survenir avant la réponse « réelle ».
CURLH_PSEUDO
L'en-tête est un pseudo-en-tête HTTP/2 ou HTTP/3

PROTOCOLES

Cette fonctionnalité n'affecte que http

EXEMPLE

int main(void)
{
  struct curl_header *type;
  CURL *curl = curl_easy_init();
  if(curl) {
    CURLHcode h;
    curl_easy_setopt(curl, CURLOPT_URL, "https://example.com");
    curl_easy_perform(curl);
    h = curl_easy_header(curl, "Content-Type", 0, CURLH_HEADER, -1, &type);
    curl_easy_cleanup(curl);
  }
}

DISPONIBILITÉ

Ajouté dans curl 7.83.0

VALEUR RENVOYÉE

Cette fonction renvoie un CURLHcode indiquant le succès ou une erreur. CURLHE_OK (0) signifie que tout s'est bien passé, une valeur non nulle signifie qu'une erreur s'est produite, voir libcurl-errors(3).
