CURLOPT_SEEKFUNCTION(3)

Paquet: curl

Licences: MIT

CURLOPT_SEEKFUNCTION(3) Manuel des fonctions de bibliothèque CURLOPT_SEEKFUNCTION(3)

NOM

CURLOPT_SEEKFUNCTION - callback utilisateur pour la recherche dans le flux d'entrée

SYNTAXE

#include <curl/curl.h>
/* Ce sont les codes de retour pour les callbacks de recherche */
#define CURL_SEEKFUNC_OK       0
#define CURL_SEEKFUNC_FAIL     1 /* Échouer le transfert complet */
#define CURL_SEEKFUNC_CANTSEEK 2 /* Indiquer à libcurl que la recherche ne peut pas être effectuée, de sorte que
                                    libcurl puisse essayer d'autres moyens à la place */
int seek_callback(void *clientp, curl_off_t offset, int origin);
CURLcode curl_easy_setopt(CURL *handle, CURLOPT_SEEKFUNCTION, seek_callback);

DESCRIPTION

Passez un pointeur vers votre fonction de rappel, qui doit correspondre au prototype indiqué ci-dessus.

Cette fonction est appelée par libcurl pour se positionner à un certain endroit dans le flux d'entrée et peut être utilisée pour avancer rapidement un fichier dans un téléversement repris (au lieu de lire tous les octets téléversés avec la fonction/callback de lecture normale). Elle est également appelée pour rembobiner un flux lorsque des données ont déjà été envoyées au serveur et doivent être renvoyées. Cela peut se produire lors d'un PUT ou POST HTTP avec une méthode d'authentification multi-passes, ou lorsqu'une connexion HTTP existante est réutilisée trop tard et que le serveur ferme la connexion. La fonction doit se comporter comme fseek(3) ou lseek(3) et reçoit SEEK_SET, SEEK_CUR ou SEEK_END comme argument pour origin, bien que libcurl ne passe actuellement que SEEK_SET.

clientp est le pointeur que vous avez défini avec CURLOPT_SEEKDATA(3).

La fonction de rappel doit retourner CURL_SEEKFUNC_OK en cas de succès, CURL_SEEKFUNC_FAIL pour provoquer l'échec de l'opération de téléversement ou CURL_SEEKFUNC_CANTSEEK pour indiquer que, bien que la recherche ait échoué, libcurl est libre de contourner le problème si possible. Ce dernier peut parfois être fait en lisant depuis l'entrée ou de manière similaire.

Si vous transmettez directement les arguments d'entrée à fseek(3) ou lseek(3), notez que le type de données pour offset n'est pas le même que celui défini pour curl_off_t sur de nombreux systèmes.

DÉFAUT

NULL

PROTOCOLES

Cette fonctionnalité affecte ftp, http et sftp

EXEMPLE

#include <unistd.h> /* pour lseek */
struct data {
  int notre_fd;
};
static int seek_cb(void *clientp, curl_off_t offset, int origin)
{
  struct data *d = (struct data *)clientp;
  lseek(d->notre_fd, offset, origin);
  return CURL_SEEKFUNC_OK;
}
int main(void)
{
  struct data seek_data;
  CURL *curl = curl_easy_init();
  if(curl) {
    curl_easy_setopt(curl, CURLOPT_SEEKFUNCTION, seek_cb);
    curl_easy_setopt(curl, CURLOPT_SEEKDATA, &seek_data);
  }
}

DISPONIBILITÉ

Ajouté dans curl 7.18.0

VALEUR DE RETOUR

curl_easy_setopt(3) retourne un CURLcode indiquant le succès ou une erreur.

CURLE_OK (0) signifie que tout était OK, une valeur non nulle indique une erreur, voir libcurl-errors(3).
