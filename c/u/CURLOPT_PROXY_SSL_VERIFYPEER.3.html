CURLOPT_PROXY_SSL_VERIFYPEER(3) Manuel des fonctions de bibliothèque CURLOPT_PROXY_SSL_VERIFYPEER(3)

NOM

CURLOPT_PROXY_SSL_VERIFYPEER - vérifier le certificat SSL du proxy

SYNTAXE

#include <curl/curl.h>
CURLcode curl_easy_setopt(CURL *handle, CURLOPT_PROXY_SSL_VERIFYPEER,
                          long verify);

DESCRIPTION

Passez un long en paramètre défini à 1L pour activer ou 0L pour désactiver.

Cette option indique à curl de vérifier l'authenticité du certificat du proxy HTTPS. Une valeur de 1 signifie que curl vérifie ; 0 (zéro) signifie qu'il ne le fait pas.

Ceci est la version proxy de CURLOPT_SSL_VERIFYPEER(3) qui est utilisée pour les serveurs HTTPS ordinaires.

Lors de la négociation d'une connexion TLS ou SSL, le serveur envoie un certificat indiquant son identité. curl vérifie si le certificat est authentique, c'est-à-dire si vous pouvez faire confiance au serveur quant à son identité réelle. Cette confiance est basée sur une chaîne de signatures numériques, ancrée dans les certificats d'autorité de certification (AC) que vous fournissez. curl utilise un paquet par défaut de certificats d'AC (le chemin de celui-ci est déterminé au moment de la compilation) et vous pouvez spécifier des certificats alternatifs avec l'option CURLOPT_PROXY_CAINFO(3) ou l'option CURLOPT_PROXY_CAPATH(3).

Lorsque CURLOPT_PROXY_SSL_VERIFYPEER(3) est activé, et que la vérification échoue à prouver que le certificat est authentique, la connexion échoue. Lorsque l'option est à zéro, la vérification du certificat du pair réussit indépendamment.

L'authentification du certificat n'est pas suffisante pour être sûr du serveur. Vous voudrez généralement également vous assurer que le serveur est bien celui auquel vous avez l'intention de vous connecter. Utilisez CURLOPT_PROXY_SSL_VERIFYHOST(3) pour cela. La vérification que le nom d'hôte dans le certificat est valide pour le nom d'hôte auquel vous vous connectez est effectuée indépendamment de l'option CURLOPT_PROXY_SSL_VERIFYPEER(3).

AVERTISSEMENT : désactiver la vérification du certificat permet aux pirates de s'interposer dans la communication (man-in-the-middle) sans que vous ne le sachiez. Désactiver la vérification rend la communication non sécurisée. Le simple fait d'avoir un chiffrement lors d'un transfert ne suffit pas, car vous ne pouvez pas être sûr que vous communiquez avec le bon point de terminaison.

DEFAUT

1

PROTOCOLES

Cette fonctionnalité affecte tous les protocoles basés sur TLS : HTTPS, FTPS, IMAPS, POP3S, SMTPS, etc.

Tous les backends TLS prennent en charge cette option.

EXEMPLE

int main(void)
{
  CURL *curl = curl_easy_init();
  if(curl) {
    curl_easy_setopt(curl, CURLOPT_URL, "https://example.com");
    /* Définir la valeur par défaut : vérification stricte du certificat s'il vous plaît */
    curl_easy_setopt(curl, CURLOPT_PROXY_SSL_VERIFYPEER, 1L);
    curl_easy_perform(curl);
  }
}

DISPONIBILITE

Ajouté dans curl 7.52.0

VALEUR DE RETOUR

curl_easy_setopt(3) retourne un CURLcode indiquant le succès ou une erreur.

CURLE_OK (0) signifie que tout s'est bien passé, une valeur non nulle indique une erreur, voir libcurl-errors(3).
