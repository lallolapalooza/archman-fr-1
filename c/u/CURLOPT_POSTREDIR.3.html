CURLOPT_POSTREDIR(3)

Paquet: curl

Licences: MIT

CURLOPT_POSTREDIR(3) Manuel des fonctions de bibliothèque CURLOPT_POSTREDIR(3)

NOM

CURLOPT_POSTREDIR - comment agir sur une redirection POST HTTP

SYNTAXE

#include <curl/curl.h>
CURLcode curl_easy_setopt(CURL *handle, CURLOPT_POSTREDIR,
                          long bitmask);

DESCRIPTION

Passez un masque de bits pour contrôler comment libcurl agit sur les redirections après des POST qui reçoivent une réponse 301, 302 ou 303. Un paramètre avec le bit 0 défini (valeur CURL_REDIR_POST_301) dit à la bibliothèque de respecter la RFC 7231 (sections 6.4.2 à 6.4.4) et de ne pas convertir les requêtes POST en requêtes GET lors du suivi d'une redirection 301. La définition du bit 1 (valeur CURL_REDIR_POST_302) fait en sorte que libcurl maintienne la méthode de requête après une redirection 302, tandis que la définition du bit 2 (valeur CURL_REDIR_POST_303) fait en sorte que libcurl maintienne la méthode de requête après une redirection 303. La valeur CURL_REDIR_POST_ALL est une définition de commodité qui définit les trois bits.

Le comportement non-RFC est omniprésent dans les navigateurs web, donc la bibliothèque effectue la conversion par défaut pour maintenir la cohérence. Cependant, un serveur peut exiger qu'un POST reste un POST après une telle redirection. Cette option n'est significative que lorsque CURLOPT_FOLLOWLOCATION(3) est définie.

DÉFAUT

0

PROTOCOLES

Cette fonctionnalité n'affecte que http

EXEMPLE

int main(void)
{
  CURL *curl = curl_easy_init();
  if(curl) {
    curl_easy_setopt(curl, CURLOPT_URL, "https://example.com");
    /* un exemple de POST bidon */
    curl_easy_setopt(curl, CURLOPT_POSTFIELDS, "data=true");
    /* example.com est redirigé, nous disons donc à libcurl d'envoyer le POST sur les codes de réponse HTTP 301,
       302 et 303 */
    curl_easy_setopt(curl, CURLOPT_POSTREDIR, CURL_REDIR_POST_ALL);
    curl_easy_perform(curl);
  }
}

HISTORIQUE

Cette option était connue sous le nom de CURLOPT_POST301 jusqu'à la version 7.19.0 car elle ne prenait en charge que le 301 à l'époque. CURL_REDIR_POST_303 a été ajouté dans la version 7.26.0.

Les macros CURL_REDIR_* sont devenues des types long dans la version 8.16.0, avant cette version, une conversion long était nécessaire lorsqu'elle était passée à curl_easy_setopt(3).

DISPONIBILITÉ

Ajouté dans curl 7.19.1

VALEUR DE RETOUR

curl_easy_setopt(3) renvoie un CURLcode indiquant le succès ou une erreur.

CURLE_OK (0) signifie que tout était correct, une valeur non nulle indique une erreur, voir libcurl-errors(3).
