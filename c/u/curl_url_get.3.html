curl_url_get(3) Manuel des fonctions de bibliothèque curl_url_get(3)

NOM

curl_url_get - extraire une partie d'une URL

SYNOPSIS

#include <curl/curl.h>
CURLUcode curl_url_get(const CURLU *url,
                       CURLUPart part,
                       char **content,
                       unsigned int flags);

DESCRIPTION

Étant donné un handle url d'un objet URL, cette fonction en extrait une partie individuelle ou l'URL complète.

L'argument part spécifie quelle partie extraire (voir la liste ci-dessous) et content pointe vers un 'char *' qui sera mis à jour pour pointer vers une chaîne nouvellement allouée avec le contenu.

L'argument flags est un masque de bits avec des fonctionnalités individuelles.

Le pointeur de contenu retourné doit être libéré avec curl_free(3) après utilisation.

FLAGS

L'argument flags est zéro, un ou plusieurs bits définis dans un masque de bits.

CURLU_DEFAULT_PORT
Si le handle n'a pas de port stocké, cette option permet à curl_url_get(3) de retourner le port par défaut pour le schéma utilisé.
CURLU_DEFAULT_SCHEME
Si le handle n'a pas de schéma stocké, cette option permet à curl_url_get(3) de retourner le schéma par défaut au lieu d'une erreur.
CURLU_NO_DEFAULT_PORT
Indique à curl_url_get(3) de ne pas retourner de numéro de port s'il correspond au port par défaut du schéma.
CURLU_URLDECODE
Demande à curl_url_get(3) de décoder l'URL avant de la retourner. Elle ne décode pas le schéma, le numéro de port ou l'URL complète.

La partie requête bénéficie également d'une conversion des plus en espaces lorsqu'elle est activée.

Notez que ce décodage d'URL n'est pas conscient de l'encodage et que vous obtenez une chaîne terminée par un caractère nul avec des données qui pourraient être destinées à un encodage particulier.

S'il y a des valeurs d'octets inférieures à 32 dans la chaîne décodée, l'opération get retourne une erreur.

CURLU_URLENCODE
Si elle est définie, curl_url_get(3) encode en URL la partie nom d'hôte lors de la récupération d'une URL complète. Si elle n'est pas définie (par défaut), libcurl retourne l'URL avec le nom d'hôte brut pour prendre en charge les noms IDN tels quels.

Notez que même lorsque l'encodage URL n'est pas demandé, le caractère '%' (octet 37) est encodé en URL pour garantir que le nom d'hôte reste valide.

CURLU_PUNYCODE
Si elle est définie et que CURLU_URLENCODE n'est pas définie, et qu'on demande à récupérer les parties CURLUPART_HOST ou CURLUPART_URL, libcurl retourne le nom d'hôte dans sa version punycode s'il contient des octets non-ASCII (et qu'il s'agit d'un nom IDN).

Si libcurl est compilé sans capacités IDN, l'utilisation de ce bit fait que curl_url_get(3) retourne CURLUE_LACKS_IDN si le nom d'hôte contient quelque chose en dehors de la plage ASCII.

(Ajouté dans curl 7.88.0)

CURLU_PUNY2IDN
Si elle est définie et qu'on demande à récupérer les parties CURLUPART_HOST ou CURLUPART_URL, libcurl retourne le nom d'hôte dans sa version IDN (International Domain Name) UTF-8 s'il s'agit autrement d'une version punycode. Si le nom punycode ne peut pas être converti correctement en IDN, libcurl retourne CURLUE_BAD_HOSTNAME.

Si libcurl est compilé sans capacités IDN, l'utilisation de ce bit fait que curl_url_get(3) retourne CURLUE_LACKS_IDN si le nom d'hôte utilise du punycode.

(Ajouté dans curl 8.3.0)

CURLU_GET_EMPTY
Lorsque ce drapeau est utilisé dans curl_url_get(), il fait en sorte que la fonction retourne des parties requête et fragment vides ou lorsqu'elle est utilisée dans l'URL complète. Par défaut, libcurl considère autrement les parties vides comme inexistantes.

Une partie requête vide est une partie où il n'y a rien après le point d'interrogation (avant le fragment éventuel). Une partie fragment vide est une partie où il n'y a rien après le signe dièse.

(Ajouté dans curl 8.8.0)

CURLU_NO_GUESS_SCHEME
Lorsque ce drapeau est utilisé dans curl_url_get(), il traite le schéma comme inexistant s'il a été défini à la suite d'une supposition antérieure ; lorsque CURLU_GUESS_SCHEME a été utilisé pour analyser une URL.

L'utilisation de ce drapeau lors de la récupération de CURLUPART_SCHEME si le schéma a été défini suite à une supposition fait que curl_url_get() retourne CURLUE_NO_SCHEME.

L'utilisation de ce drapeau lors de la récupération de CURLUPART_URL si le schéma a été défini suite à une supposition fait que curl_url_get() retourne l'URL complète sans le composant schéma. Une telle URL ne peut alors être analysée avec curl_url_set() que si CURLU_GUESS_SCHEME est utilisé.

(Ajouté dans curl 8.9.0)

PARTIES

CURLUPART_URL
Lorsqu'on demande à retourner l'URL complète, curl_url_get(3) retourne une version légèrement nettoyée de l'URL complète en utilisant toutes les parties disponibles.

Nous conseillons d'utiliser l'option CURLU_PUNYCODE pour obtenir l'URL aussi "normalisée" que possible, car IDN permet d'écrire les noms d'hôtes de différentes manières qui aboutissent toutes à la même version punycode.

Les requêtes et fragments de longueur nulle sont exclus de l'URL sauf si CURLU_GET_EMPTY est défini.

CURLUPART_SCHEME
Le schéma ne peut pas être décodé en URL lors de la récupération.
CURLUPART_USER
CURLUPART_PASSWORD
CURLUPART_OPTIONS
Le champ options est un champ facultatif qui peut suivre le mot de passe dans la partie userinfo. Il n'est reconnu/utilisé que lors de l'analyse des URL pour les schémas suivants : pop3, smtp et imap. L'API URL permet toujours aux utilisateurs de définir et d'obtenir ce champ indépendamment du schéma lors de l'analyse d'URL complètes.
CURLUPART_HOST
Le nom d'hôte. S'il s'agit d'une adresse IPv6 numérique, l'ID de zone n'en fait pas partie mais est fourni séparément dans CURLUPART_ZONEID. Les adresses numériques IPv6 sont retournées entre crochets ([]).

Les noms IPv6 sont normalisés lors de leur définition, ce qui devrait les rendre aussi courts que possible tout en conservant une syntaxe correcte.

CURLUPART_ZONEID
Si le nom d'hôte est une adresse IPv6 numérique, ce champ peut également être défini.
CURLUPART_PORT
Un port ne peut pas être décodé en URL lors de la récupération. Ce numéro est retourné dans une chaîne, comme toutes les autres parties. Cette chaîne est garantie de contenir un numéro de port valide en ASCII sur base 10.
CURLUPART_PATH
La partie est toujours au moins une barre oblique ('/') même si aucun chemin n'a été fourni dans l'URL. Un chemin d'URL commence toujours par une barre oblique.
CURLUPART_QUERY
Le point d'interrogation initial qui marque le début de la partie requête n'est qu'un délimiteur. Il ne fait pas partie du contenu de la requête.

Une requête absente retourne part à NULL.

Une requête de longueur nulle retourne part à NULL sauf si CURLU_GET_EMPTY est défini.

La partie requête voit ses plus convertis en espaces lorsqu'on demande à décoder en URL lors de la récupération avec le bit CURLU_URLDECODE.

CURLUPART_FRAGMENT
Le signe dièse initial qui marque le début du fragment n'est qu'un délimiteur. Il ne fait pas partie du contenu du fragment.

class="Pp">Un fragment absent renvoie part défini à NULL.

Un fragment de longueur nulle renvoie part comme NULL, sauf si CURLU_GET_EMPTY est défini.

PROTOCOLES

Cette fonctionnalité concerne tous les protocoles pris en charge

EXEMPLE

int main(void)
{
  CURLUcode rc;
  CURLU *url = curl_url();
  rc = curl_url_set(url, CURLUPART_URL, "https://example.com", 0);
  if(!rc) {
    char *scheme;
    rc = curl_url_get(url, CURLUPART_SCHEME, &scheme, 0);
    if(!rc) {
      printf("the scheme is %s\n", scheme);
      curl_free(scheme);
    }
    curl_url_cleanup(url);
  }
}

DISPONIBILITÉ

Ajouté dans curl 7.62.0

VALEUR RENVOYÉE

Renvoie une valeur d'erreur CURLUcode, qui vaut CURLUE_OK (0) si tout s'est bien passé. Voir la page de manuel libcurl-errors(3) pour la liste complète avec les descriptions.

Si cette fonction renvoie une erreur, aucune partie d'URL n'est renvoyée.
