CURLMOPT_NETWORK_CHANGED(3) Manuel des fonctions de bibliothèque CURLMOPT_NETWORK_CHANGED(3)

NOM

CURLMOPT_NETWORK_CHANGED - signaler un changement réseau

SYNTAXE

#include <curl/curl.h>
CURLMcode curl_multi_setopt(CURLM *handle, CURLMOPT_NETWORK_CHANGED,
                            long value);

DESCRIPTION

Passez un entier long (long) avec un masque de bits pour indiquer comment libcurl doit réagir au handle multi. Les valeurs suivantes dans le masque sont définies. Tous les bits non mentionnés sont réservés pour des extensions futures.

Cette option peut être définie à tout moment et de manière répétée. Chaque appel n'affecte que les connexions et informations DNS actuellement mises en cache. Toute connexion créée ou information DNS ajoutée par la suite est à nouveau mise en cache comme d'habitude. Pour le dire autrement : l'option n'est pas persistante mais sa définition sert de "déclencheur" pour vider les caches.

L'appel n'affecte que le cache de connexion et de DNS du handle multi lui-même et non ceux appartenant aux handles SHARE.

CURLMNWC_CLEAR_CONNS
Ne réutilisez plus aucune connexion existante dans le cache de connexions du handle multi. Cela ferme toutes les connexions qui ne sont pas en cours d'utilisation. Les transferts en cours continuent sur les connexions sur lesquelles ils opèrent.
CURLMNWC_CLEAR_DNS
Vide le cache DNS du handle multi.

DÉFAUT

0, ce qui n'a aucun effet.

PROTOCOLES

Cette fonctionnalité affecte tous les protocoles pris en charge.

EXEMPLE

int main(void)
{
  CURLM *m = curl_multi_init();
  /* effectuer des transferts sur le handle multi */
  /* ne pas réutiliser les connexions existantes */
  curl_multi_setopt(m, CURLMOPT_NETWORK_CHANGED, CURLMNWC_CLEAR_CONNS);
}

DISPONIBILITÉ

Ajouté dans curl 8.16.0

VALEUR DE RETOUR

curl_multi_setopt(3) renvoie un CURLMcode indiquant le succès ou l'erreur.

CURLM_OK (0) signifie que tout s'est bien passé, une valeur non nulle indique qu'une erreur s'est produite, voir libcurl-errors(3).

VOIR AUSSI
