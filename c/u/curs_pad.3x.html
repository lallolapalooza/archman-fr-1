curs_pad(3X) Appels de bibliothèque curs_pad(3X)

NOM

newpad, subpad, prefresh, pnoutrefresh, pechochar, pecho_wchar - créer et afficher des pads curses

SYNOPIS

#include <curses.h>
WINDOW *newpad(int nlines, int ncols);
WINDOW *subpad(WINDOW *parent, int nlines, int ncols,
      int begin_y, int begin_x);
int prefresh(WINDOW *pad, int pminrow, int pmincol,
      int sminrow, int smincol, int smaxrow, int smaxcol);
int pnoutrefresh(WINDOW *pad, int pminrow, int pmincol,
      int sminrow, int smincol, int smaxrow, int smaxcol);
int pechochar(WINDOW *pad, chtype ch);
int pecho_wchar(WINDOW *pad, const cchar_t *wch);

DESCRIPTION

Un pad curses est similaire à une fenêtre, sauf qu'il n'est pas limité par la taille de l'écran, et n'est pas nécessairement associé à une partie particulière de l'écran. Les pads peuvent être utilisés lorsqu'une grande fenêtre est nécessaire, dont seule une partie doit être visible sur l'écran. Les pads ne sont pas automatiquement rafraîchis par les opérations de défilement ou d'écho d'entrée.

Les pads ne peuvent pas être rafraîchis avec wrefresh(3X); utilisez plutôt prefresh ou pnoutrefresh.

newpad

newpad crée et retourne un pointeur vers une nouvelle structure de données de pad avec le nombre donné de lignes, nlines, et de colonnes, ncols.

subpad

subpad crée et retourne un pointeur vers une sous-fenêtre à l'intérieur d'un pad avec le nombre donné de lignes, nlines, et de colonnes, ncols. Contrairement à subwin(3X), qui utilise les coordonnées de l'écran, le nouveau pad est positionné en (begin_y, begin_x) par rapport à son parent. Ainsi, les modifications apportées à un pad peuvent affecter les deux. Lors de l'opération sur un sous-pad, il est souvent nécessaire d'appeler touchwin(3X) ou touchline(3X) sur parent avant d'appeler prefresh.

prefresh, pnoutrefresh

prefresh et pnoutrefresh sont analogues à wrefresh(3X) et wnoutrefresh(3X) sauf qu'ils opèrent sur des pads plutôt que sur des fenêtres. Ils nécessitent des paramètres supplémentaires pour indiquer quelles portions du pad et de l'écran sont impliquées.

  • pminrow et pmincol spécifient le coin supérieur gauche d'une vue rectangulaire du pad.
  • sminrow, smincol, smaxrow, et smaxcol spécifient les sommets du rectangle à afficher à l'écran.

Le coin inférieur droit du rectangle à afficher dans le pad est calculé à partir des coordonnées de l'écran, car les rectangles doivent avoir la même taille. Les deux rectangles doivent être entièrement contenus dans leurs structures respectives. curses traite les valeurs négatives de n'importe lequel de ces paramètres comme zéro.

pechochar

pechochar est fonctionnellement équivalent à appeler waddch(3X) suivi de prefresh. Il suggère à l'optimiseur curses qu'un seul caractère est émis ; un avantage considérable en termes de performance peut ainsi être obtenu. L'emplacement du caractère ch écrit dans le pad est utilisé pour remplir les arguments de prefresh.

pecho_wchar

pecho_wchar est fonctionnellement équivalent à appeler wadd_wch(3X) suivi de prefresh. Il suggère à l'optimiseur curses qu'un seul caractère large est émis ; un avantage considérable en termes de performance peut ainsi être obtenu. L'emplacement du caractère wch écrit dans le pad est utilisé pour remplir les arguments de prefresh.

VALEUR DE RETOUR

Les fonctions qui retournent un entier retournent ERR en cas d'échec et OK (SVr4 spécifie seulement « une valeur entière autre que ERR ») en cas de succès.

Les fonctions qui retournent des pointeurs retournent NULL en cas d'erreur, et définissent errno à ENOMEM.

X/Open Curses ne spécifie aucune condition d'erreur. Dans cette implémentation

prefresh et pnoutrefresh
retournent une erreur si le pointeur de fenêtre est nul, si la fenêtre n'est pas vraiment un pad, si la zone à rafraîchir s'étend hors de l'écran, ou si les coordonnées minimales sont supérieures aux coordonnées maximales.
pechochar
retourne une erreur si la fenêtre n'est pas vraiment un pad et si l'appel associé à wechochar retourne une erreur.
pecho_wchar
retourne une erreur si la fenêtre n'est pas vraiment un pad et si l'appel associé à wecho_wchar retourne une erreur.

NOTES

pechochar peut être une macro.

PORTABILITÉ

Le curses BSD n'a pas de fonctionnalité de pad.

Le curses SVr2 (1986) fournissait newpad et les fonctions associées, les documentant en une seule ligne chacune. SVr3 (1987) fournissait une documentation plus étendue.

La documentation n'explique pas le terme pad. Cependant, le système d'exploitation de station de travail graphique Aegis d'Apollo prenait en charge une fonctionnalité pad graphique :

  • Ces pads graphiques pouvaient être beaucoup plus grands que l'écran de l'ordinateur.
  • La sortie en lecture seule d'une commande pouvait être déroulée pour inspecter et sélectionner du texte à partir du pad.

Les deux utilisations peuvent être liées.

X/Open Curses, Issue 4 décrit ces fonctions, sans changement significatif par rapport à la documentation SVr3. Il ne décrit aucune condition d'erreur. Le comportement de subpad si la fenêtre parente n'est pas un pad est non documenté, et n'est pas vérifié par les implémentations Unix du vendeur :

•
Le curses SVr4 place un indicateur dans la structure WINDOW dans newpad qui indique si la fenêtre est un pad.
Cependant, il n'utilise cette information que dans waddch (pour décider s'il doit appeler wrefresh) et wscrl (pour éviter de faire défiler un pad), et ne vérifie pas dans wrefresh pour s'assurer que le pad est correctement rafraîchi.
•
Le xcurses Solaris vérifie si une fenêtre est un pad dans wnoutrefresh, retournant ERR dans ce cas.
Cependant, il ne définit l'indicateur pour les sous-fenêtres que si la fenêtre parente est un pad. Sa fonction newpad ne définit pas cette information. Par conséquent, la vérification ne échouera jamais.
Il ne fait pas de vérification comparable dans pnoutrefresh, bien qu'intéressant, un commentaire dans le code source indique que l'absence de vérification était une extension MKS.
•
Le curses NetBSD 7 place un indicateur dans la structure WINDOW pour newpad et subpad, utilisant cela pour aider à la distinction entre wnoutrefresh et pnoutrefresh.
Il ne vérifie pas le cas où une sous-fenêtre est créée dans un pad en utilisant subwin ou derwin.
La fonction dupwin retourne une fenêtre régulière lors de la duplication d'un pad. De même, getwin retourne toujours une fenêtre, même si les données sauvegardées provenaient d'un pad.

Cette implémentation

  • définit un indicateur dans la structure WINDOW pour newpad et subpad,
  • permet à un appel subwin ou derwin de réussir en ayant un parent de type pad en forçant la sous-fenêtre à être un pad,
  • vérifie dans wnoutrefresh et
b> et pnoutrefresh pour garantir que les tampons (pads) et les fenêtres sont traités distinctement, et
  • garantit que dupwin et getwin traitent les tampons par rapport aux fenêtres de manière cohérente.
