CURLOPT_XFERINFOFUNCTION(3) Manuel des fonctions de bibliothèque CURLOPT_XFERINFOFUNCTION(3)

NOM

CURLOPT_XFERINFOFUNCTION - fonction de rappel de l'indicateur de progression

SYNTAXE

#include <curl/curl.h>
int progress_callback(void *clientp,
                      curl_off_t dltotal,
                      curl_off_t dlnow,
                      curl_off_t ultotal,
                      curl_off_t ulnow);
CURLcode curl_easy_setopt(CURL *handle, CURLOPT_XFERINFOFUNCTION,
                          progress_callback);

DESCRIPTION

Passez un pointeur vers votre fonction de rappel, qui doit correspondre au prototype indiqué ci-dessus.

Cette fonction est appelée par libcurl à la place de son équivalent interne, à un intervalle fréquent. Pendant le transfert de données, elle est appelée fréquemment, et pendant les périodes lentes, comme lorsque rien n'est transféré, elle peut ralentir à environ un appel par seconde.

clientp est le pointeur défini avec CURLOPT_XFERINFODATA(3), il n'est pas utilisé par libcurl mais est simplement transmis de l'application au rappel.

Le rappel reçoit des informations sur la quantité de données que libcurl est sur le point de transférer et a déjà transféré, en nombre d'octets. dltotal est le nombre total d'octets que libcurl s'attend à télécharger lors de ce transfert. dlnow est le nombre d'octets téléchargés jusqu'à présent. ultotal est le nombre total d'octets que libcurl s'attend à téléverser lors de ce transfert. ulnow est le nombre d'octets téléversés jusqu'à présent.

Les valeurs d'arguments inconnues/non utilisées passées au rappel sont définies à zéro (par exemple, si vous téléchargez uniquement des données, la taille de téléversement reste à 0). Souvent, le rappel est appelé une ou plusieurs fois d'abord, avant de connaître les tailles des données, un programme doit donc être capable de gérer cela.

Retournez zéro depuis le rappel si tout va bien.

Retournez 1 depuis ce rappel pour que libcurl abandonne le transfert et retourne CURLE_ABORTED_BY_CALLBACK.

Si votre fonction de rappel retourne CURL_PROGRESSFUNC_CONTINUE, cela indique à libcurl de continuer à exécuter la fonction de progression par défaut.

Si vous transférez des données avec l'interface multi, cette fonction n'est pas appelée pendant les périodes d'inactivité, sauf si vous appelez la fonction libcurl appropriée qui effectue les transferts.

CURLOPT_NOPROGRESS(3) doit être défini à 0 pour que cette fonction soit réellement appelée.

DÉFAUT

NULL - utilise l'indicateur de progression interne. Ceci est rarement souhaité par les utilisateurs.

PROTOCOLES

Cette fonctionnalité affecte tous les protocoles pris en charge

EXEMPLE

struct progress {
  char *private;
  size_t size;
};
static int xferinfo_callback(void *clientp,
                             curl_off_t dltotal,
                             curl_off_t dlnow,
                             curl_off_t ultotal,
                             curl_off_t ulnow)
{
  struct progress *memory = clientp;
  printf("mon ptr: %p\n", memory->private);
  /* utiliser les valeurs */
  return 0; /* tout va bien */
}
int main(void)
{
  CURL *curl = curl_easy_init();
  if(curl) {
    struct progress data;
    /* passer la structure au rappel */
    curl_easy_setopt(curl, CURLOPT_XFERINFODATA, &data);
    /* activer l'appel de la fonction de rappel de progression */
    curl_easy_setopt(curl, CURLOPT_NOPROGRESS, 0L);
    curl_easy_setopt(curl, CURLOPT_XFERINFOFUNCTION, xferinfo_callback);
  }
}

DISPONIBILITÉ

Ajouté dans curl 7.32.0

VALEUR DE RETOUR

curl_easy_setopt(3) renvoie un CURLcode indiquant le succès ou une erreur.

CURLE_OK (0) signifie que tout s'est bien passé, une valeur non nulle indique une erreur, voir libcurl-errors(3).
