CURLOPT_SSL_VERIFYHOST(3)

Paquet: curl

Licences: MIT

CURLOPT_SSL_VERIFYHOST(3) Manuel des fonctions de la bibliothèque CURLOPT_SSL_VERIFYHOST(3)

NOM

CURLOPT_SSL_VERIFYHOST - vérifier le nom du certificat par rapport à l'hôte

SYNTAXE

#include <curl/curl.h>
CURLcode curl_easy_setopt(CURL *handle, CURLOPT_SSL_VERIFYHOST, long verify);

DESCRIPTION

Passez un long réglé sur 2L pour que libcurl vérifie le nom d'hôte dans le certificat TLS du serveur.

Lors de la négociation d'une connexion TLS, le serveur envoie un certificat indiquant son identité.

Lorsque CURLOPT_SSL_VERIFYHOST(3) est réglé sur 1 ou 2, le certificat du serveur doit indiquer qu'il a été fait pour le nom d'hôte ou l'adresse à laquelle curl se connecte, sinon la connexion échoue. Autrement dit, le nom dans le certificat doit être le même que celui utilisé dans l'URL sur laquelle vous effectuez l'opération.

curl considère que le serveur est celui prévu lorsque le champ Common Name ou un champ Subject Alternate Name dans le certificat correspond au nom d'hôte dans l'URL à laquelle vous avez dit à curl de se connecter.

Lorsque la valeur verify est 0, la connexion réussit indépendamment des noms dans le certificat. Utilisez cette capacité avec prudence.

Cette option contrôle la vérification de l'identité revendiquée par le certificat du serveur. Les options distinctes CURLOPT_SSL_VERIFYPEER(3) activent/désactivent la vérification que le certificat est signé par une autorité de certification approuvée.

ATTENTION : désactiver la vérification du certificat permet aux attaquants d'intercepter la communication (man-in-the-middle) sans que vous ne vous en rendiez compte. Désactiver la vérification rend la communication non sécurisée. Le simple fait d'avoir un chiffrement lors d'un transfert ne suffit pas, car vous ne pouvez pas être sûr de communiquer avec le point d'extrémité correct.

Lorsque libcurl utilise des protocoles sécurisés, il fait confiance aux réponses et permet, par exemple, le stockage et l'utilisation ultérieure des informations HSTS et Alt-Svc. La désactivation de la vérification des certificats peut amener libcurl à faire confiance et à utiliser de telles informations provenant de serveurs malveillants.

CORRESPONDANCE

Un certificat peut avoir le nom sous forme de joker. Le seul astérisque (*) doit alors être le caractère le plus à gauche et il doit être suivi d'un point. Le joker doit en outre contenir plus d'un point car il ne peut pas être défini pour un domaine de premier niveau.

Un certificat peut être défini pour une adresse IP numérique (IPv4 ou IPv6), mais il doit alors s'agir d'un type Subject Alternate Name et son type doit identifier correctement le champ comme une adresse IP.

DÉFAUT

2

PROTOCOLES

Cette fonctionnalité affecte tous les protocoles basés sur TLS : HTTPS, FTPS, IMAPS, POP3S, SMTPS, etc.

Tous les backends TLS prennent en charge cette option.

EXEMPLE

int main(void)
{
  CURL *curl = curl_easy_init();
  if(curl) {
    curl_easy_setopt(curl, CURLOPT_URL, "https://example.com");
    /* Définir la valeur par défaut : vérification stricte du nom s'il vous plaît */
    curl_easy_setopt(curl, CURLOPT_SSL_VERIFYHOST, 2L);
    curl_easy_perform(curl);
  }
}

DISPONIBILITÉ

Ajouté dans curl 7.8.1

HISTORIQUE

Dans les versions 7.28.0 et antérieures : la valeur 1 était traitée comme une option de débogage en quelque sorte, plus supportée car conduisant fréquemment à des erreurs de programmeur.

De 7.28.1 à 7.65.3 : la définition à 1 faisait que curl_easy_setopt(3) retournait une erreur et laissait le drapeau intact.

À partir de 7.66.0 : libcurl traite 1 et 2 pour cette option de la même manière.

VALEUR DE RETOUR

curl_easy_setopt(3) retourne un code CURLcode indiquant le succès ou l'erreur.

CURLE_OK (0) signifie que tout s'est bien passé, une valeur non nulle indique une erreur, voir libcurl-errors(3).
