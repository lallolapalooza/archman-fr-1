CEC-COMPLIANCE(1) Commandes utilisateur CEC-COMPLIANCE(1)

NOM

cec-compliance - Une application pour vérifier les périphériques CEC distants

SYNOPIS

cec-compliance [-h] [-d <périph>] [autres options]

DESCRIPTION

L'utilitaire cec-compliance peut être utilisé pour tester la conformité des périphériques CEC distants avec la spécification CEC. Il peut également être utilisé pour tester l'adaptateur CEC local (avec l'option -A).

Par défaut, il exécute tous les tests, mais si une ou plusieurs options de test de fonctionnalité sont spécifiées, seuls ces tests seront effectués. Un ensemble de tests de base est toujours exécuté.

L'adaptateur CEC doit être configuré avant d'être utilisé pour exécuter des tests avec cec-compliance. Utilisez cec-ctl pour la configuration.

Si l'adaptateur CEC a revendiqué plusieurs adresses logiques, l'ensemble de tests est exécuté à partir de chaque adresse logique successivement. Le périphérique distant doit signaler une adresse physique valide pour exécuter des tests sur celui-ci.

Lors de l'exécution des tests de conformité, cec-follower doit être exécuté sur le même adaptateur. cec-follower répondra aux messages qui ne sont pas gérés par cec-compliance. cec-follower surveillera également le périphérique testé pour les comportements non conformes à la spécification. Avant chaque exécution de test, cec-follower doit être redémarré s'il est déjà en cours d'exécution, afin d'initialiser le périphérique émulé avec un état initial propre et connu.

Certains tests nécessitent le mode interactif (avec l'option -i) pour confirmer que le test a réussi. En mode interactif, l'utilisateur est invité à observer ou à effectuer des actions sur le périphérique distant. Certains tests donnent également des résultats concluants lorsqu'ils sont exécutés en mode interactif.

Lors du test de la conformité de l'adaptateur CEC avec l'API CEC, au moins un périphérique distant doit être présent pour tester la transmission et la réception.

Les tests de conformité peuvent avoir plusieurs résultats possibles en plus de passer et échouer :


OK Le test a réussi.


OK (Inattendu) Le test a réussi, mais il était inattendu que le périphérique
testé le prenne en charge. Cela peut par exemple se produire
lorsqu'un téléviseur répond aux messages dans la fonction de contrôle du lecteur
(Deck Control).


OK (Non pris en charge) La fonctionnalité testée n'est pas prise en charge par le
périphérique testé, et cette fonctionnalité n'était pas obligatoire
pour que le périphérique réussisse.


OK (Présumé) Rien ne s'est mal passé pendant le test, mais le test ne peut pas
vérifier positivement que les effets requis du test
se sont produits. Le programme de test doit vérifier que le test
a réussi en observant manuellement le périphérique testé. C'est
typiquement le résultat des tests qui envoient
des messages auxquels il n'est pas répondu, mais qui induisent un effet secondaire
sur le périphérique testé, tel qu'un téléviseur
changeant d'entrée ou envoyant une commande de télécommande.


OK (Refusé) Le périphérique prend en charge la fonctionnalité ou le message testé,
mais a répondu <Feature Abort> ["Refused"] pour indiquer
qu'il ne peut pas effectuer l'opération donnée. Cela peut par exemple se produire
lors de la tentative de test de la fonctionnalité d'enregistrement en une touche
sur un téléviseur avec protection contre la copie activée.


FAIL Le test a échoué et était censé réussir sur le périphérique.


OK (Échec attendu) Échec mais cela était attendu. Cela ne peut se produire
que si l'option --expect a été utilisée et spécifiait
qu'un test particulier renverrait un résultat ÉCHEC.


FAIL (Attendu X, obtenu Y) Le test a renvoyé un résultat différent de celui
attendu.
Cela ne peut se produire que si l'option --expect a été utilisée
et spécifiait qu'un test particulier renverrait un résultat spécifique
non-ÉCHEC.

Certains tests dépendent du succès d'autres tests. Ceux-ci ne sont pas exécutés si les tests dont ils dépendent ont échoué, et ils ne seront pas affichés dans la liste des tests.

OPTIONS

-d, --device <périph>
Utilise le périphérique <périph> comme périphérique CEC. Si <périph> est un nombre, alors /dev/cec<périph> est utilisé.
-D, --driver <drv>
Utilise un périphérique cec dont le nom de pilote est <drv>, tel que renvoyé par l'ioctl CEC_ADAP_G_CAPS. Cette option peut être combinée avec -a pour identifier de manière unique un périphérique CEC sans avoir à se fier au numéro du nœud de périphérique.
-a, --adapter <nom-adap>
Utilise un périphérique cec dont le nom d'adaptateur est <nom-adap>, tel que renvoyé par l'ioctl CEC_ADAP_G_CAPS. Cette option peut être combinée avec -D pour identifier de manière unique un périphérique CEC sans avoir à se fier au numéro du nœud de périphérique.
-E, --exit-on-fail
Quitte cette application lors de la première défaillance au lieu de continuer avec un état potentiellement incohérent.
-l, --list-tests
Liste tous les tests et les résultats possibles. Ceci est utilisé par l'option --expect.
-e, --expect <test>=<résultat>
-n, --expect-with-no-warnings <test>=<résultat> Échoue si le test a donné un résultat différent. L'option --list-tests liste tous les tests possibles et les valeurs de résultat qui peuvent être utilisées.

Ceci peut être utilisé dans les scripts de test pour vérifier qu'un résultat spécifique a été renvoyé par le test. Un cas d'utilisation est de vérifier qu'une fonctionnalité optionnelle est effectivement prise en charge, de sorte qu'un résultat OK au lieu d'un résultat OK (Non pris en charge) est attendu.

Il peut également être utilisé pour accepter des échecs connus. Dans ce cas, le test n'échouera pas, mais renverra un résultat OK (Échec attendu).

La variante --expect-with-no-warnings est plus stricte et vérifiera également que le test n'a produit aucun avertissement.

-v, --verbose
Active le rapport détaillé.
--version
Affiche les informations de version.
-w, --wall-clock
Affiche les horodatages en heure locale.
-S, --show-timestamp
Pour chaque test, affiche l'horodatage du début du test.
-T, --trace
Trace tous les ioctls appelés. Utile pour le débogage.
-h, --help
Imprime le message d'aide.
-W, --exit-on-warn
Quitte cette application lors du premier avertissement au lieu de continuer.
-s, --skip-info
Ignore la section d'informations sur le pilote.
-C, --color <quand>
Met en surbrillance les chaînes OK/avertissement/échec/ÉCHEC avec des couleurs. OK est marqué en vert, avertissement est marqué en gras, et échec/ÉCHEC sont marqués en rouge vif si activé. <quand> peut être toujours, jamais, ou auto (par défaut).
-N, --no-warnings
Désactive les messages d'avertissement.
-r, --remote <la>
En tant qu'initiateur, teste l'adresse logique distante <la> ou toutes les LA si aucune LA n'a été donnée.
-i, --interactive
Mode interactif lors des tests à distance.
-R, --reply-threshold <délai>
Avertit si les réponses prennent plus de temps que ce seuil (par défaut 1000ms).
-t, --timeout <secondes>
Définit le délai d'attente veille/reprise au nombre de secondes donné. Par défaut, 60s.
-A, --test-adapter
Teste l'API de l'adaptateur CEC
-F, --test-fuzzing
Teste l'adaptateur CEC distant en créant aléatoirement des messages CEC. Ceci s'exécute indéfiniment jusqu'à ce qu'une erreur se produise.
test=résultat
Identifie un test spécifique qui doit produire le résultat donné.

EXEMPL

E

Nous souhaitons tester la conformité d'un téléviseur lorsqu'il interagit avec un appareil de lecture. Le nœud de l'appareil de l'adaptateur CEC auquel le téléviseur est connecté est

/dev/cec1.

L'adaptateur CEC local doit d'abord être configuré en tant qu'appareil de lecture, et il doit avoir une adresse physique appropriée. Il est important que l'adresse physique soit correcte, afin de ne pas confondre l'appareil en cours de test. Par exemple, si l'adaptateur CEC est connecté à la première entrée du téléviseur, l'adresse physique 1.0.0.0 devrait généralement être

utilisée.


cec-ctl -d1 --playback --phys-addr 1.0.0.

0

La plupart des adaptateurs CEC détecteront automatiquement l'adresse physique, et pour ces adaptateurs l'option --phys-addr n'est pas

nécessaire.

Ensuite, cec-follower doit également être démarré sur le même appareil

:


cec-follower

-d1

cec-compliance peut maintenant être exécuté vers le téléviseur en fournissant l'option -r avec l'adresse logique 0

:


cec-com

pliance
-d1 -r0
