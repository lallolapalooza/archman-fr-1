CERTMAP.CONF(5) Manuel des formats de fichiers CERTMAP.CONF(5)

NOM

/etc/dirsrv/config/certmap.conf - Fichier de configuration pour l'authentification client TLS dans 389 Directory Server.

SYNOPIS

/etc/dirsrv/config/certmap.conf

DESCRIPTION

certmap.conf

Ce fichier configure la manière dont un certificat est mappé à une entrée LDAP. Consultez la documentation pour plus d'informations sur ce fichier : https://access.redhat.com/documentation/en-us/red_hat_directory_server/10/html/configuration_command_and_file_reference/configuration_file_reference#certmap_conf

SYNTAXE

Le format de ce fichier est le suivant :
certmap <nom> <issuerDN>
<nom>:<prop1> [<val1>]
<nom>:<prop2> [<val2>]

Notes :


1. Les mappages peuvent être définis par émetteur d'un certificat. Si aucun mappage n'existe
pour un 'issuerDN' particulier, le serveur utilise le mappage par défaut.


2. Il doit y avoir une entrée pour <nom>=default et issuerDN "default".
Ce mappage est le mappage par défaut.


3. '#' peut être utilisé pour commenter une ligne.


4. DNComps & FilterComps sont utilisés pour former le DN de base et le filtre responsable de
la recherche LDAP lors du mappage du certificat à une entrée utilisateur.

OPTIONS

DNComps
Le paramètre DNComps détermine comment le serveur d'annuaire génère le DN de base utilisé pour rechercher un utilisateur dans l'annuaire. Ce réglage accepte une liste d'attributs séparés par des virgules pour former un DN. Cependant, l'ordre des attributs dans le paramètre DNComps doit correspondre à l'ordre dans le sujet du certificat. Par exemple, si le sujet de votre certificat est "e=user_name@example.com,cn=user_name,o=Example Inc.,c=US", et que vous souhaitez que le serveur d'annuaire utilise "cn=user_name,o=Example Inc.,c=US" comme DN de base lors de la recherche de l'utilisateur, définissez le paramètre DNComps sur "cn, o, c".

Commentez ou ne définissez pas ce paramètre si le champ sujet du certificat correspond exactement au DN de l'utilisateur dans le serveur d'annuaire ou si vous souhaitez utiliser le réglage du paramètre CmapLdapAttr.

Si la valeur est vide, il recherchera dans l'ensemble de l'arbre LDAP en utilisant le paramètre FilterComps.

FilterComps
Ce paramètre définit quels attributs du champ sujet du certificat le serveur d'annuaire utilise pour générer le filtre de recherche afin de localiser l'utilisateur.

Définissez ce paramètre sur une liste d'attributs séparés par des virgules utilisés dans le sujet du certificat. Le serveur d'annuaire utilisera ces attributs dans une opération ET dans le filtre.

Note - Les sujets de certificats utilisent l'attribut e pour l'adresse e-mail, qui n'existe pas dans le schéma par défaut du serveur d'annuaire. Pour cette raison, le serveur d'annuaire mappe automatiquement cet attribut à l'attribut mail. Cela signifie que si vous utilisez l'attribut mail dans le paramètre FilterComps, le serveur d'annuaire lit la valeur de l'attribut e du sujet du certificat.

Par exemple, si le sujet d'un certificat est "e=user_name@example.com,cn=user_name,dc=example,dc=com,o=Example Inc.,c=US" et que vous souhaitez générer dynamiquement le filtre "(&(mail=username@domain)(cn=user_name))", définissez le paramètre FilterComps sur "mail, cn".

Si le paramètre est commenté ou défini sur une valeur vide, le filtre (objectclass=*) sera utilisé.

verifycert
Le serveur d'annuaire vérifie toujours si le certificat a été délivré par une Autorité de Certification (AC) de confiance. Cependant, si vous activez en plus le paramètre verifycert, le serveur d'annuaire vérifie en outre que le certificat correspond aux règles d'encodage distinctes (DER) formatées en DER et stockées dans l'attribut binaire userCertificate de l'utilisateur.

Si vous ne définissez pas ce paramètre, verifycert est désactivé.

CmapLdapAttr
Si vos entrées utilisateur contiennent un attribut qui stocke le DN du sujet du certificat utilisateur, définissez CmapLdapAttr sur ce nom d'attribut. Le serveur d'annuaire utilisera cet attribut et le DN du sujet pour localiser l'utilisateur. Dans ce cas, aucun filtre n'est généré sur la base des attributs du paramètre FilterComps.

EXEMPLES

certmap default default
default:DNComps cn, o, c
#default:FilterComps e, uid
#default:verifycert on
#default:CmapLdapAttr certSubjectDN

certmap example o=Example Inc.,c=US
example:DNComps
