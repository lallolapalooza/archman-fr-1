DESCRIPTIO

N

Outil pour analyser et générer des certificats X.509, des demandes et des clés privées. Il peut être utilisé de manière interactive ou non interactive en spécifiant l'option de modèle sur la ligne de

commande.

L'outil accepte des fichiers ou des URI pris en charge via l'option --infile

. Si un code PIN est requis pour l'accès à l'URI, vous pouvez le fournir
en utilisant les variables d'environnement GNUTLS_PIN et GNUTLS_SO_PIN.

Format du fichier modèle de certtool
Un fichier modèle peut être utilisé pour éviter les questions interactives de certtool. Créez initialement un fichier nommé 'cert.cfg' contenant les informations sur le certificat. Le modèle peut être utilisé comme suit

: 


$ certtool --generate-certificate --load-privkey key.pem     --template cert.cfg --outfile cert.pem    --load-ca-certificate ca-cert.pem --load-ca-privkey ca-key.pem

Un exemple de fichier modèle certtool qui peut être utilisé pour générer une demande de certificat ou un certificat auto-signé

suit. 


# X.509 Certificate options
#
# DN options

# The organization of the subject.
organization = "Koko inc."

# The organizational unit of the subject.
unit = "sleeping dept."

# The locality of the subject.
# locality =

# The state of the certificate owner.
state = "Attiki"

# The country of the subject. Two letter code.
country = GR

# The common name of the certificate owner.
cn = "Cindy Lauper"

# A user id of the certificate owner.
#uid = "clauper"

# Set domain components
#dc = "name"
#dc = "domain"

# If the supported DN OIDs are not adequate you can set
# any OID here.
# For example set the X.520 Title and the X.520 Pseudonym
# by using OID and string pairs.
#dn_oid = "2.5.4.12 Dr."
#dn_oid = "2.5.4.65 jackal"

# This is deprecated and should not be used in new
# certificates.
# pkcs9_email = "none@none.org"

# An alternative way to set the certificate's distinguished name directly
# is with the "dn" option. The attribute names allowed are:
# C (country), street, O (organization), OU (unit), title, CN (common name),
# L (locality), ST (state), placeOfBirth, gender, countryOfCitizenship, 
# countryOfResidence, serialNumber, telephoneNumber, surName, initials, 
# generationQualifier, givenName, pseudonym, dnQualifier, postalCode, name, 
# businessCategory, DC, UID, jurisdictionOfIncorporationLocalityName, 
# jurisdictionOfIncorporationStateOrProvinceName,
# jurisdictionOfIncorporationCountryName, XmppAddr, and numeric OIDs.

#dn = "cn = Nikos,st = New Something,C=GR,surName=Mavrogiannopoulos,2.5.4.9=Arkadias"

# The serial number of the certificate
# The value is in decimal (i.e. 1963) or hex (i.e. 0x07ab).
# Comment le champ pour un numéro de série aléatoire.
serial = 007

# Dans combien de jours, à compter d'aujourd'hui, ce certificat expirera.
# Utilisez -1 s'il n'y a pas de date d'expiration.
expiration_days = 700

EXEMPLES

Génération de clés privées
Pour créer une clé privée RSA, exécutez : 

$ certtool --generate-privkey --outfile key.pem --rsa

Pour créer une clé privée DSA ou à courbes elliptiques (ECDSA), utilisez la commande ci-dessus combinée avec les options 'dsa' ou 'ecc'.

Génération de demandes de certificat
Pour créer une demande de certificat (nécessaire lorsque le certificat est émis par une autre partie), exécutez : 

certtool --generate-request --load-privkey key.pem    --outfile request.pem

Si la clé privée est stockée dans une carte à puce, vous pouvez générer une demande en spécifiant l'URL de l'objet de clé privée. 

$ ./certtool --generate-request --load-privkey "pkcs11:..."   --load-pubkey "pkcs11:..." --outfile request.pem

Génération d'un certificat auto-signé
Pour créer un certificat auto-signé, utilisez la commande : 

$ certtool --generate-privkey --outfile ca-key.pem
$ certtool --generate-self-signed --load-privkey ca-key.pem    --outfile ca-cert.pem

Notez qu'un certificat auto-signé appartient généralement à une autorité de certification, qui signe d'autres certificats.

Génération d'un certificat
Pour générer un certificat en utilisant la demande précédente, utilisez la commande : 

$ certtool --generate-certificate --load-request request.pem    --outfile cert.pem --load-ca-certificate ca-cert.pem    --load-ca-privkey ca-key.pem

Pour générer un certificat en utilisant uniquement la clé privée, utilisez la commande : 

$ certtool --generate-certificate --load-privkey key.pem    --outfile cert.pem --load-ca-certificate ca-cert.pem    --load-ca-privkey ca-key.pem

Informations sur le certificat
Pour afficher les informations du certificat, utilisez : 

$ certtool --certificate-info --infile cert.pem

Changement du format du certificat
Pour convertir le certificat du format PEM au format DER, utilisez : 

$ certtool --certificate-info --infile cert.pem --outder --outfile cert.der

Génération de la structure PKCS #12
Pour générer une structure PKCS #12 en utilisant la clé et le certificat précédents, utilisez la commande : 

$ certtool --load-certificate cert.pem --load-privkey key.pem    --to-p12 --outder --outfile key.p12

Certains outils (apparemment les navigateurs web) ont des problèmes avec ce fichier car il ne contient pas le certificat de l'AC pour le certificat. Pour contourner ce problème dans l'outil, vous pouvez utiliser le paramètre --load-ca-certificate comme suit :


$ certtool --load-ca-certificate ca.pem   --load-certificate cert.pem --load-privkey key.pem   --to-p12 --outder --outfile key.p12

Obtention des paramètres Diffie-Hellman
Pour obtenir les paramètres RFC7919 pour l'échange de clés Diffie-Hellman, utilisez la commande : 

$ certtool --get-dh-params --outfile dh.pem --sec-param medium

Vérification d'un certificat
Pour vérifier un certificat dans un fichier par rapport au magasin de confiance CA du système, utilisez la commande suivante : 

$ certtool --verify --infile cert.pem

Il est également possible de simuler la vérification du nom d'hôte avec les options suivantes : 

$ certtool --verify --verify-hostname www.example.com --infile cert.pem

Génération de certificats de mandataire
Un certificat de mandataire peut être used pour déléguer votre identifiant à un certificat temporaire, généralement de courte durée. Pour en créer un à partir du certificat précédemment créé, créez d'abord une clé temporaire, puis générez un certificat mandataire pour celle-ci, à l'aide des commandes

: 


$ certtool --generate-privkey > proxy-key.pem
$ certtool --generate-proxy --load-ca-privkey key.pem   --load-privkey proxy-key.pem --load-certificate cert.pem   --outfile proxy-cert.pem

Génération d'une liste de révocation de certificats
Pour créer une liste de révocation de certificats (CRL) vide, exécutez

: 


$ certtool --generate-crl --load-ca-privkey x509-ca-key.pem            --load-ca-certificate x509-ca.pem

Pour créer une CRL contenant des certificats révoqués, placez les certificats dans un fichier et utilisez --load-certificate comme suit

: 


$ certtool --generate-crl --load-ca-privkey x509-ca-key.pem   --load-ca-certificate x509-ca.pem --load-certificate revoked-certs.pem

Pour vérifier une liste de révocation de certificats (CRL), exécutez

: 


$ certtool --verify-crl --load-ca-certificate x509-ca.pem < crl.pem
