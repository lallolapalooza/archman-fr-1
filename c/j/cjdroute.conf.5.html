cjdroute.conf -

Fichier de config
uration de Cjdns

DESCRIPTIO

N

Le fichier cjdroute.conf configure le moteur de routage cjdns, cjdns(8), généralement via cjdroute

(1).

La configuration est écrite dans une variante du format JSON qui accepte également des commentaires de style C traditionnels tels que les commentaires sur une seule ligne (//) et les commentaires multilignes (/* et */). De plus, les valeurs JSON inutilisées trouvées dans cjdroute.conf sont ignorées par cjdns et peuvent être util

isées comme une forme de c
ommentaires conformes à JSON.

CONFIGURATIO

N

"privateKey": "...

"
La clé privée de votre nœud. Elle doit rester secrète car votre confidentialité et l'intégrité de vos données en
dépendent.

"publicKey": "...

"
La clé publique de votre nœud. Basée sur votre clé privée, il est acceptable que quiconque la
connaisse.

"ipv6": "...

"
L'adresse IPv6 de votre nœud lorsqu'il est sur le réseau. Elle est générée en utilisant les 16 premiers octets d'un double SHA-512 de votre clé publique. Toutes les adresses IPv6 de cjdns doivent commencer par "fc", sinon elles sont
invalides.

"authorizedPasswords": [...

]
Un tableau de mots de passe pouvant être utilisés pour se connecter (peer) à votre nœud.

"password": "...

"
Un mot de passe pouvant être utilisé pour établir un peer avec votre
nœud.

"user": "...

"
Une chaîne lisible par l'humain qui identifie quel mot de passe un pair utilise sur l'interface d'administration. Si omis, le mot de passe sera identifié par sa position dans le tableau (à partir de
0)

Exemple :
"authorizedPasswords":
[
{ "password": "AnExamplePassword", "user": "Bob" },
{ "password": "YetAnotherExample", "user": "Alice" },
{ "password": "j3fus4r3gkhv80xdz1yqc0qvn1p91hr", "user": "Eve" }

]

"admin": {...

}
Un objet qui définit à quoi se lier pour le serveur RPC d'administration ainsi que le mot de passe pour le serveur RPC d'administration. Les deux chaînes requises sont "bind", qui doit être au format "IP:PORT", et "password", qui devrait de préférence être une longue chaîne aléatoire de
caractères.

"interfaces": {...

}
Un objet qui définit aux interfaces cjdns doit se lier et à quels pairs se connecter. Il y a deux interfaces différentes, UDPInterface et ETHInterface, qui sont toutes deux des tableaux. Dans chaque tableau il y a une variété d'options différentes

"bind": "...

"
Définit à quoi l'interface doit se lier. Dans UDPInterface, le bind est une chaîne IP:PORT, telle que "0.0.0.0:12345", tandis que dans ETHInterface le bind est une interface réseau, telle que
"eth0".

"beacon":

Entier
Cette option ne se trouve que dans ETHInterface et définit si des balises de connexion automatique doivent être envoyées ou écoutées. C'est utile pour un réseau local sans configuration.
0 -- Désactivé.
1 -- Accepter les balises entrantes et essayer de se connecter à l'émetteur.
2 -- Accepter les balises e
ntrantes et diffuser des b
alises sur le réseau local.

"connectTo": {...

}
Définit aux nœuds cjdns doit se connecter avec l'interface spécifiée. Plusieurs nœuds peuvent être placés dans un seul "connectTo" à condition qu'ils soient séparés par des virgules. Si un nœud est hors ligne ou devient hors ligne pendant l'exécution, cjdns essaiera de se reconnecter à intervalles réguliers. La seule différence dans cette option entre UDPInterface et ETHInterface est que UDPInterface se connecte à un "IP:PORT" tandis qu'ETHInterface se connecte à une adresse MAC.

Exemple UDPInterface :
"connectTo":

{
"1.2.3.4:54321":
{
"login": "login From Your Peer's authorizedPasswords",
"password": "password From Your Peer's authorizedPasswords",
"publicKey": "Your Peer's publicKey.k"
},
"5.6.7.8:46321":
{
"login": "cueball",
"password": "Correct Horse Battery Staple",
"publicKey": "Other Peer's publicKey.k"
}
}

"router": {...

}
Un objet qui contient les informations de configuration du routeur

"interface": {...

}
Définit le type d'interface utilisé pour se connecter au réseau cjdns. Elle nécessite une chaîne "type", et éventuellement une chaîne "tunDevice". La chaîne "type" définit le type d' interface utilisé, cependant seul "TUNInterface" est pris en charge à l'heure actuelle. La chaîne "tunDevice" définit le nom d'un périphérique TUN persistant à utiliser, ce qui est utile pour démarrer cjdroute en tant qu'utilisateur plutôt qu'en tant que
root.

"ipTunnel": {...

}
Un système pour tunneliser l'IPv4 ICANN et l'IPv6 ICANN à travers cjdns. Cela utilise la couche de commutation cjdns comme support de VPN.

NOTE : Modifier simplement votre fichier de configuration n'est pas suffisant pour configurer une passerelle ipTunnel. Veuillez lire tunnel/README.md dans l'arbre git de cjdns pour plus

d'informations

"allowedConnections": [...

]
Nœuds autorisés à se connecter à nous, spécifiés par leur clé publique, et à quelle(s) adresse(s) IP leur donner. Il est acceptable de ne spécifier qu'une seule adresse.

Exemple

:

"allowedConnections":
[
{
"publicKey": "f64hfl7c4uxt6krmhPutTheRealAddressOfANodeHere7kfm5m0.k",
"ip4Address": "192.168.1.24",
"ip4Prefix": 24,
"ip6Address": "2001:123:ab::10",
"ip6Prefix": 0
},
{
"publicKey": "ydq8csdk8p8ThisIsJustAnExampleAddresstxuyqdf27hvn2z0.k",
"ip4Address": "192.168.1.25",
"ip4Prefix": 24
}

]

"outgoingConnections": [...

]
Un tableau de nœuds auxquels se connecter et demander des adresses IP.

Exemple

:

"outgoingConnections":
[
"6743gf5tw80ExampleExampleExampleExamplevlyb23zfnuzv0.k",
"pw9tfmr8pcrExampleExampleExampleExample8rhg1pgwpwf80.k",
"g91lxyxhq0kExampleExampleExampleExample6t0mknuhw75l0.k"

]

"security": [...

]
Un tableau qui définit vers quel utilisateur passer après le démarrage et s'il faut exempter le processus Angel de ce changement d'utilisateur.

"setuser":

"username"
Utilisateur vers lequel basculer après le démarrage, pour des raisons de sécurité. La valeur par défaut est
"nobody".

"exemptAngel":

Entier
S'il faut ou non exempter le processus Angel du changement d'utilisateur. L'Angel est un petit morceau de code isolé qui existe en dehors de la sandbox stricte du cœur mais ne gère pas le trafic réseau. Cette option doit être activée pour qu'ipTunnel définisse automatiquement les adresses IP pour le périphérique TUN.

0 -- Faux
1

"logging": {...

}
Ajoutez ou décommentez "logTo":"stdout" pour que cjdns journalise vers stdout plutôt que de rendre les journaux disponibles via le socket d'administratio
n

"noBackground":

Entier
S'il est défini sur une valeur non nulle, cjdns ne se détachera pas en arrière-plan. Recommandé pour une utilisation conjointe avec "logTo":
"stdout".

"dns": {...

}
Cette section est utilisée pour configurer les capacités DNS ajoutées à cjdns. Malheureusement, il n'y a pas de documentation pour cette section DNS pour le moment.
