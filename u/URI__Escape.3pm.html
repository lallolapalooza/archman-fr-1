NOM

URI::Escape - Encode et décode les caractères non sûrs en utilisant le pourcentage

SYNTAXE

use URI::Escape;
$safe = uri_escape("10% est suffisant\n");
$verysafe = uri_escape("foo", "\0-\377");
$str  = uri_unescape($safe);

DESCRIPTION

Ce module fournit des fonctions pour encoder et décoder en pourcentage les chaînes d'URI telles que définies par la RFC 3986. L'encodage en pourcentage des URI est informellement appelé "échappement d'URI". C'est la terminologie utilisée par ce module, qui précède la formalisation des termes par la RFC de plusieurs années.

Une URI est constituée d'un ensemble restreint de caractères. Cet ensemble restreint de caractères comprend les chiffres, les lettres et quelques symboles graphiques choisis parmi ceux couramment disponibles dans la plupart des systèmes d'encodage de caractères et des facilités d'entrée pour les utilisateurs d'Internet. Ils sont composés des ensembles de caractères "non réservés" et "réservés" tels que définis dans la RFC 3986.

unreserved    = ALPHA / DIGIT / "-" / "." / "_" / "~"
reserved      = ":" / "/" / "?" / "#" / "[" / "]" / "@"
                "!" / "$" / "&" / "'" / "(" / ")"
              / "*" / "+" / "," / ";" / "="

En outre, tout octet peut être représenté dans une URI par une séquence d'échappement : un triplet composé du caractère "%" suivi de deux chiffres hexadécimaux. Un octet peut également être représenté directement par un caractère, en utilisant le caractère US-ASCII correspondant à cet octet.

Certains caractères sont réservés pour être utilisés comme délimiteurs ou comme partie de certains composants d'URI. Ceux-ci doivent être échappés s'ils doivent être traités comme des données ordinaires. Lisez la RFC 3986 pour plus de détails.

Les fonctions fournies (et exportées par défaut) par ce module sont :

uri_escape( $string )
uri_escape( $string, $unsafe )
Remplace chaque caractère non sûr dans la $string par la séquence d'échappement correspondante et renvoie le résultat. La $string doit être une chaîne d'octets. La fonction uri_escape() échouera si on lui donne des caractères dont le code est supérieur à 255. Utilisez uri_escape_utf8() si vous savez que vous avez de tels caractères ou si vous voulez que les caractères dans la plage 128 .. 255 soient traités comme UTF-8.

La fonction uri_escape() accepte un second argument optionnel qui remplace l'ensemble des caractères à échapper. L'ensemble est spécifié comme une chaîne qui peut être utilisée dans une classe de caractères d'expression régulière (entre [ ]). Par exemple :

"\x00-\x1f\x7f-\xff"          # tous les caractères de contrôle et les caractères à bit élevé
"a-z"                         # tous les caractères en minuscules
"^A-Za-z"                     # tout ce qui n'est pas une lettre

L'ensemble par défaut des caractères à échapper est tous ceux qui ne font pas partie de la classe de caractères "unreserved" montrée ci-dessus, ainsi que les caractères réservés. C'est-à-dire que par défaut, c'est :

"^A-Za-z0-9\-\._~"

Le second argument peut également être spécifié comme un objet d'expression régulière :

qr/[^A-Za-z]/

Toutes les chaînes correspondant à cette expression régulière auront tous leurs caractères échappés.

uri_escape_utf8( $string )
uri_escape_utf8( $string, $unsafe )
Fonctionne comme uri_escape(), mais encode les caractères en UTF-8 avant de les échapper. Cela permet à cette fonction de traiter les caractères dont le code est supérieur à 255 dans $string. Notez que les caractères dans la plage 128 .. 255 seront échappés différemment par cette fonction par rapport à ce que uri_escape() ferait. Pour les caractères dans la plage 0 .. 127, il n'y a pas de différence.

Équivalent à :

utf8::encode($string);
my $uri = uri_escape($string);

Note : JavaScript possède une fonction appelée escape() qui produit la séquence "%uXXXX" pour les caractères dans la plage 256 .. 65535. Cette fonction n'a vraiment rien à voir avec l'échappement d'URI, mais certaines personnes se sont confondues car elle "fait la bonne chose" dans la plage 0 .. 255. Pour cette raison, on voit parfois des "URI" avec ce genre d'échappements. La fonction JavaScript encodeURIComponent() est similaire à uri_escape_utf8().

uri_unescape($string,...)
Renvoie une chaîne avec chaque séquence %XX remplacée par l'octet réel.

Ceci fait la même chose que :

$string =~ s/%([0-9A-Fa-f]{2})/chr(hex($1))/eg;

mais ne modifie pas la chaîne en place comme le ferait cette RE. Utiliser la fonction uri_unescape() au lieu de la RE peut rendre le code plus clair et demande moins de frappe.

Dans un test de benchmark simple que j'ai effectué, appeler la fonction (au lieu de la RE en ligne ci-dessus) s'il y avait peu de caractères à décoder était environ 40% plus lent, et environ 700% plus lent s'il n'y en avait aucun. Si vous devez décoder beaucoup de fois, il pourrait être judicieux d'intégrer la RE.

Si la fonction uri_unescape() est passée plusieurs chaînes, chacune d'elles est renvoyée décodée.

Le module peut également exporter le hachage %escapes, qui contient le mappage de tous les 256 octets aux codes d'échappement correspondants. Une recherche dans ce hachage est plus rapide que d'évaluer "sprintf("%%%02X", ord($byte))" à chaque fois.
