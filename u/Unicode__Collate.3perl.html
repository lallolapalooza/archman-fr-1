Unicode::Collate(3perl) Guide de référence pour programmeurs Perl Unicode::Collate(3perl)

NOM

Unicode::Collate - Algorithme de tri Unicode

SYNTAXE

use Unicode::Collate;
# construction
$Collator = Unicode::Collate->new(%paramètres_personnalisés);
# tri
@trie = $Collator->sort(@non_trie);
# comparaison
$resultat = $Collator->cmp($a, $b); # renvoie 1, 0 ou -1.

Note : Les chaînes dans @non_trie, $a et $b sont interprétées selon le support Unicode de Perl. Voir perlunicode, perluniintro, perlunitut, perlunifaq, utf8. Sinon, vous pouvez utiliser "preprocess" ou vous devriez les décoder au préalable.

DESCRIPTION

Ce module est une implémentation de la norme technique Unicode #10 (alias UTS #10) - Algorithme de tri Unicode (alias UCA).

Constructeur et personnalisation

La méthode "new" renvoie un objet collateur. Si new() est appelé sans paramètres, le collateur devrait effectuer le tri par défaut.

$Collator = Unicode::Collate->new(
   UCA_Version => $UCA_Version,
   alternate => $alternate, # alias pour 'variable'
   backwards => $niveauNombre, # ou \@niveauxNombres
   entry => $element,
   hangul_terminator => $poidsPrimaireTerminaison,
   highestFFFF => $booleen,
   identical => $booleen,
   ignoreName => qr/$ignoreNom/,
   ignoreChar => qr/$ignoreChar/,
   ignore_level2 => $booleen,
   katakana_before_hiragana => $booleen,
   level => $niveauTri,
   long_contraction => $booleen,
   minimalFFFE => $booleen,
   normalization  => $formeNormalisation,
   overrideCJK => \&overrideCJK,
   overrideHangul => \&overrideHangul,
   preprocess => \&preprocess,
   rearrange => \@listeChar,
   rewrite => \&rewrite,
   suppress => \@listeChar,
   table => $nomFichier,
   undefName => qr/$undefNom/,
   undefChar => qr/$undefChar/,
   upper_before_lower => $booleen,
   variable => $variable,
);
UCA_Version
Si le numéro de révision (précédemment "version de suivi") de l'UCA est donné, le comportement de cette révision est émule lors du tri. Si omis, la valeur renvoyée par UCA_Version() est utilisée.

Les révisions suivantes sont supportées. La valeur par défaut est 43.

  UCA       Norme Unicode         DUCET (@version)
-------------------------------------------------------
   8              3.1                3.0.1 (3.0.1d9)
   9     3.1 avec Corrigendum 3      3.1.1
  11             4.0.0
  14             4.1.0
  16             5.0.0
  18             5.1.0
  20             5.2.0
  22             6.0.0
  24             6.1.0
  26             6.2.0
  28             6.3.0
  30             7.0.0
  32             8.0.0
  34             9.0.0
  36            10.0.0
  38            11.0.0
  40            12.0.0
  41            12.1.0
  43            13.0.0

* Voir ci-dessous pour "long_contraction" avec "UCA_Version" 22 et 24.

* Les non-caractères (par ex. U+FFFF) ne sont pas ignorés, et peuvent être redéfinis depuis "UCA_Version" 22.

* Les points de code hors plage (supérieurs à U+10FFFF) ne sont pas ignorés, et peuvent être redéfinis depuis "UCA_Version" 22.

* Les caractères entièrement ignorables étaient ignorés, et n'interrompaient pas les contractions avec "UCA_Version" 9 et 11.

* Le traitement des caractères ignorables après les variables et certains comportements ont été modifiés à "UCA_Version" 9.

* Les caractères considérés comme des idéogrammes unifiés CJK (cf. "overrideCJK") dépendent de "UCA_Version".

* De nombreux jamos Hangul sont attribués à "UCA_Version" 20, ce qui affectera "hangul_terminator".

alternate
-- voir 3.2.2 Tri Alternatif, version 8 de UTS #10

Pour des raisons de compatibilité ascendante, "alternate" (ancien nom) peut être utilisé comme alias pour "variable".

backwards
-- voir 3.4 Accents Arrière, UTS #10. 
backwards => $niveauNombre ou \@niveauxNombres

Poids dans l'ordre inverse ; par ex. niveau 2 (ordre des diacritiques) en français. Si omis (ou si $niveauNombre est "undef" ou si \@niveauxNombres est "[]"), le tri se fait dans l'ordre normal à tous les niveaux.

entry
-- voir 5 Personnalisation ; 9.1 Format du fichier Allkeys, UTS #10.

Si le même caractère (ou une séquence de caractères) existe dans la table des éléments de tri via "table", le mappage vers les éléments de tri est redéfini. S'il n'existe pas, le mappage est défini supplémentairement.

    entry => <<'ENTRY', # pour DUCET v4.0.0 (allkeys-4.0.0.txt)
0063 0068 ; [.0E6A.0020.0002.0063] # ch
0043 0068 ; [.0E6A.0020.0007.0043] # Ch
0043 0048 ; [.0E6A.0020.0008.0043] # CH
006C 006C ; [.0F4C.0020.0002.006C] # ll
004C 006C ; [.0F4C.0020.0007.004C] # Ll
004C 004C ; [.0F4C.0020.0008.004C] # LL
00F1      ; [.0F7B.0020.0002.00F1] # n-tilde
006E 0303 ; [.0F7B.0020.0002.00F1] # n-tilde
00D1      ; [.0F7B.0020.0008.00D1] # N-tilde
004E 0303 ; [.0F7B.0020.0008.00D1] # N-tilde
ENTRY
    entry => <<'ENTRY', # pour DUCET v4.0.0 (allkeys-4.0.0.txt)
00E6 ; [.0E33.0020.0002.00E6][.0E8B.0020.0002.00E6] # ae ligature comme <a><e>
00C6 ; [.0E33.0020.0008.00C6][.0E8B.0020.0008.00C6] # AE ligature comme <A><E>
ENTRY

NOTE : Le point de code dans le format de fichier UCA (avant ';') doit être un point de code Unicode (défini en hexadécimal), et non un point de code natif. Ainsi 0063 doit toujours désigner "U+0063", mais pas un caractère de "\x63".

Le tri peut varier en fonction de la table des éléments de tri. Assurez-vous donc que les poids définis dans "entry" seront cohérents avec ceux de la table des éléments de tri chargée via "table".

Dans DUCET v4.0.0, le poids primaire de "C" est 0E60 et celui de "D" est "0E6D". Ainsi, définir le poids primaire de "CH" à "0E6A" (une valeur entre 0E60 et "0E6D") permet un tri comme "C < CH < D". Plus précisément, DUCET contient déjà certains caractères entre "C" et "D" : le "petit C majuscule" ("U+1D04") avec un poids primaire 0E64, le "c-crochet/C-crochet" ("U+0188/U+0187") avec 0E65, et le "c-boucle" ("U+0255") avec 0E69. Ensuite, un poids primaire "0E6A" pour "CH" place "CH" entre le "c-boucle" et "D".

hangul_terminator
-- voir 7.1.4 Poids Terminaux, UTS #10.

Si une valeur vraie est donnée (non nulle mais doit être positive), elle sera ajoutée comme poids primaire de terminaison à la fin de chaque syllabe Hangul standard. Les poids secondaires et supérieurs pour la terminaison sont mis à zéro. Si la valeur est fausse ou si la clé "hangul_terminator" n'existe pas, l'insertion de poids de terminaison ne sera pas effectuée.

Les frontières des syllabes Hangul sont déterminées selon le comportement de jonction des Jamos dans *la Norme Unicode* et *HangulSyllableType.txt*.

Hangul

Ces paramètres sont spécifiques au coréen. Les règles par défaut du collationnement de l'Unicode peuvent ne pas être appropriées pour le coréen.

Notez que les Jamo de compatibilité (par exemple, "U+3131", "LATIN SMALL LETTER U WITH DIAERESIS") ne sont pas censés être des Jamo. La plupart des tableaux de collationnement du monde ne comportent pas de règles pour eux.

La plupart des chaînes de caractères coréens doivent être composées de Jamo modernes (par exemple, "U+1100", "HANGUL CHOSEONG KIYEOK").

addTerminator
constituent
-- voir A.2.3 Conflation, UTS #10.

Si le paramètre est activé, le Jamo de base (consonne ou voyelle) sont traités comme des caractères terminaux. Par exemple, en ignorant les différences entre les niveaux 2 et 3 (accents et casse), "a\u1100" serait égal à "a\u1100\u1161" (la forme décomposée de la syllabe coréenne "\uAC00"). Cela est dû au fait que la syllabe coréenne est traitée comme une combinaison de Jamo.

expansion

Si le paramètre est activé, le Jamo est traité comme une syllabe. Par exemple, "a\u1100\u1161" est égal à "\uAC00".

NOTE: Ce comportement par défaut du Jamo est différent de celui de la plupart des Jamo coréens décrits dans le document UTC mentionné ci-dessus. Les tableaux de collationnement de l'Unicode ont l'intention de traiter les Jamo comme des caractères de niveau 1.

expansion_table
-- voir 3.8.1 Mapping de Table, UTS #10.

Utilise une table d'expansion pour les syllabes coréennes. La table spécifie comment les syllabes coréennes (par exemple, "\uAC00") sont mappées à des séquences de Jamo (par exemple, "\u1100\u1161").

terminator

Si le paramètre est activé, une terminaison est ajoutée à la fin des syllabes coréennes. Cela est particulièrement utile lorsque la syllabe coréenne est suivie d'un caractère qui n'est pas un Jamo.

Hangul_Jamo
-- voir 4.2.3 Jamo, UTS #10.
Hangul_Syllable
-- voir 4.2.2 Syllable, UTS #10.
Implementation Note:

(1) Pour le mappage d'expansion (caractère Unicode mappé à une séquence d'éléments de collationnement), un terminateur ne sera pas ajouté entre les éléments de collationnement, même si une limite de syllabe Hangul existe. L'ajout du terminateur est restreint à la position suivante du dernier élément de collationnement.

(2) Les lettres Hangul non conjointes (Jamo de compatibilité, Jamo demi-largeur et lettres incluses) ne sont pas automatiquement terminées par un poids primaire de terminaison. Ces caractères peuvent nécessiter un terminateur inclus dans une table d'éléments de collationnement au préalable.

highestFFFF
-- voir 2.4 Poids non caractère pour adaptation, UTS #35 (LDML) Partie 5: Collationnement.

Si le paramètre est activé, "U+FFFF" a un poids primaire le plus élevé. Lorsqu'un booléen de "$coll->ge($str, "abc")" et "$coll->le($str, "abc\x{FFFF}")" est vrai, il est attendu que $str commence par "abc", ou un équivalent primaire. $str peut être "abcd", "abc012", mais ne doit pas inclure "U+FFFF" tel que "abc\x{FFFF}xyz".

"$coll->le($str, "abc\x{FFFF}")" fonctionne presque comme "$coll->lt($str, "abd")", mais ce dernier a un problème : vous devez savoir quelle lettre suit "c". Pour une certaine langue où "ch" est la lettre suivante, "abch" est plus grand que "abc\x{FFFF}", mais plus petit que "abd".

Note : Ceci est équivalent à "(entry => 'FFFF ; [.FFFE.0020.0005.FFFF]')". Tout autre caractère que "U+FFFF" peut être adapté par "entry".

identical
-- voir A.3 Comparaison Déterministe, UTS #10.

Par défaut, les chaînes dont les poids sont égaux doivent être égales, même si leurs points de code ne le sont pas. Les caractères complètement ignorables sont ignorés.

Si le paramètre est activé, un niveau de rupture de lien final est utilisé. Si aucune différence de poids n'est trouvée après la comparaison à travers tous les niveaux spécifiés par "level", la comparaison avec les points de code sera effectuée. Pour la comparaison de rupture de lien, la clé de tri a les points de code de la chaîne d'origine en annexe. Les caractères complètement ignorables ne sont pas ignorés.

Si "preprocess" et/ou "normalization" est appliqué, les points de code de la chaîne après ceux-ci (par défaut en NFD) sont utilisés.

ignoreChar
ignoreName
-- voir 3.6 Poids Variable, UTS #10.

Rend l'entrée dans la table complètement ignorables ; c'est-à-dire comme si les poids étaient nuls à tous les niveaux.

Via "ignoreChar", tout caractère correspondant à "qr/$ignoreChar/" sera ignoré. Via "ignoreName", tout caractère dont le nom (indiqué dans le fichier "table" comme commentaire) correspond à "qr/$ignoreName/" sera ignoré.

Par exemple, lorsque 'a' et 'e' sont ignorables, 'element' est égal à 'lament' (ou 'lmnt').

ignore_level2
-- voir 5.1 Adaptation Paramétrique, UTS #10.

Par défaut, la comparaison sensible à la casse (c'est-à-dire la différence de niveau 3) n'ignore pas les accents (c'est-à-dire la différence de niveau 2).

Si le paramètre est activé, les accents (et autres caractères primairement ignorables) sont ignorés, même si les casse sont prises en compte.

NOTE : "level" devrait être 3 ou plus.

katakana_before_hiragana
-- voir 7.2 Table des Poids Tertiaires, UTS #10.

Par défaut, les hiragana précèdent les katakana. Si le paramètre est activé, cela est inversé.

NOTE : Ce paramètre suppose naïvement que toutes les distinctions hiragana/katakana doivent se produire au niveau 3, et que leurs poids au niveau 3 doivent être identiques à ceux mentionnés en 7.3.1, UTS #10. Si vous définissez vos éléments de collationnement de manière à violer cette exigence, ce paramètre ne fonctionnera pas valablement.

level
-- voir 4.3 Forme la Clé de Tri, UTS #10.

Définit le niveau maximum. Tous les niveaux supérieurs à celui spécifié sont ignorés.

Niveau 1 : ordre alphabétique
Niveau 2 : ordre des diacritiques
Niveau 3 : ordre des casse
Niveau 4 : rupture de lien (par exemple, lorsque la variable est 'shifted')
ex.level => 2,

S'il est omis, le maximum est 4.

NOTE : Le DUCET inclut des poids supérieurs à 0xFFFF au 4ème niveau. Mais ce module n'utilise que des poids inférieurs à 0xFFFF. Lorsque "variable" est 'blanked' ou 'non-ignorable' (autre que 'shifted' et 'shift-trimmed'), le niveau 4 peut être peu fiable.

Voir aussi "identical".

long_contraction
-- voir 3.8.2 Bien-formé du DUCET, 4.2 Produire le Tableau, UTS #10.

Si le paramètre est activé, pour une contraction de trois caractères ou plus (surnommée ici "longue contraction"), les sous-chaînes initiales seront traitées. Par exemple, une contraction ABC, où A est un démarreur et B et C sont des non-démarreurs (caractère avec une classe de caractères combinants non nulle), sera détectée même s'il n'y a pas AB comme contraction.

Par défaut : Habituellement faux. Si "UCA_Version" est 22 ou 24, et que la valeur de "long_contraction" n'est pas spécifiée dans new(), une valeur vraie est définie implicitement. C'est une solution de contournement pour passer les Tests de Conformité pour Unicode 6.0.0 et 6.1.0.

change() gère "long_contraction" explicitement uniquement. Si "long_contraction" n'est pas spécifié dans change(), même si "UCA_Version" est modifié, "long_contraction" ne sera pas changé.

Limitation : L'analyse des non-démarreurs est unidirectionnelle (pas de retour arrière). Si AB est trouvé mais pas ABC, une autre longue contraction dont le premier caractère est A et le second n'est pas B peut ne pas être trouvée.

Sous "(normalization => undef)", l'étape de détection des contractions discontiguës sera sautée.

Note : Les contractions suivantes dans le DUCET ne sont pas considérées dans les étapes S2.1.1 à S2.1.3, où elles sont discontiguës.

0FB2 0F71 0F80 (Voyelle de la langue Tibétaine RR)
0FB3 0F71 0F80 (Voyelle de la langue Tibétaine LL)

Par exemple, "Voyelle de la langue Tibétaine RR" avec "TILDE SUR L'ÉCRITURE COMBINANTE" ("U+0344") est "0FB2 0344 0F71 0F80" en NFD. Dans ce cas, "0FB2 0F80" ("Voyelle de la langue Tibétaine R") est détectée, au lieu de "0FB2 0F71 0F80". L'insertion de 0344 rend "0FB2 0F71 0F80" discontiguë et l'absence de contraction "0FB2 0F71" empêche "0FB2 0F71 0F80" d'être détectée.

minimalFFFE
-- voir 1.1.1 U+FFFE, UTS #35 (LDML) Partie 5: Collationnement.

Si le paramètre est activé, "U+FFFE" a un poids primaire minimal. La comparaison entre "$a1\x{FFFE}$a2" et "$b1\x{FFFE}$b2" compare d'abord $a1 et $b1 au niveau 1, puis $a2 et $b2 au niveau 1, comme suit.

"ab\x{FFFE}a"
"Ab\x{FFFE}a"
"ab\x{FFFE}c"
"Ab\x{FFFE}c"
"ab\x{FFFE}xyz"
"abc\x{FFFE}def"
"abc\x{FFFE}xYz"
"aBc\x{FFFE}xyz"
"abcX\x{FFFE}def"
"abcx\x{FFFE}xyz"
"b\x{FFFE}aaa"
"bbb\x{FFFE}a"

Note : Ceci est équivalent à "(entry => 'FFFE ; [.0001.0020.0005.FFFE]')". Tout autre caractère que "U+FFFE" peut être adapté par "entry".

normalization
-- voir 4.1 Normaliser, UTS #10.

Si spécifié, les chaînes sont normalisées avant la préparation des clés de tri (la normalisation est exécutée après preprocess).

Un nom de forme que Unicode::Normalize::normalize() accepte sera appliqué comme $normalization_form. Les noms acceptables incluent 'NFD', 'NFC', 'NFKD', et 'NFKC'. Voir Unicode::Normalize::normalize() pour plus de détails. S'il est omis, 'NFD' est utilisé.

"normalization" est effectué après "preprocess" (s'il est défini).

De plus, des valeurs spéciales, "undef" et "prenormalized", peuvent être utilisées, bien qu'elles ne concernent pas Unicode::Normalize::normalize().

Si "undef" (pas une chaîne

normalization
-- see 6.2 Normalization, UTS #10.

If you specify "(normalization => undef)", any normalization is not performed. This may make tailoring easier if any normalization is not desired. Under "(normalization => undef)", only contiguous contractions are resolved; e.g. even if "A-ring" (and "A-ring-cedilla") is ordered after "Z", "A-cedilla-ring" would be primary equal to "A". In this point, "(normalization => undef, preprocess => sub { NFD(shift) })" is not equivalent to "(normalization => 'NFD')".

In the case of "(normalization => "prenormalized")", any normalization is not performed, but discontiguous contractions with combining characters are performed. Therefore "(normalization => 'prenormalized', preprocess => sub { NFD(shift) })" is equivalent to "(normalization => 'NFD')". If source strings are finely prenormalized, "(normalization => 'prenormalized')" may save time for normalization.

Except "(normalization => undef)", Unicode::Normalize is required (see also CAVEAT).

overrideCJK
-- see 7.1 Derived Collation Elements, UTS #10.

By default, CJK unified ideographs are ordered in Unicode codepoint order, but those in the CJK Unified Ideographs block are less than those in the CJK Unified Ideographs Extension A etc.

In the CJK Unified Ideographs block:
U+4E00..U+9FA5 if UCA_Version is 8, 9 or 11.
U+4E00..U+9FBB if UCA_Version is 14 or 16.
U+4E00..U+9FC3 if UCA_Version is 18.
U+4E00..U+9FCB if UCA_Version is 20 or 22.
U+4E00..U+9FCC if UCA_Version is 24 to 30.
U+4E00..U+9FD5 if UCA_Version is 32 or 34.
U+4E00..U+9FEA if UCA_Version is 36.
U+4E00..U+9FEF if UCA_Version is 38, 40 or 41.
U+4E00..U+9FFC if UCA_Version is 43.
In the CJK Unified Ideographs Extension blocks:
Ext.A (U+3400..U+4DB5)   if UCA_Version is  8 to 41.
Ext.A (U+3400..U+4DBF)   if UCA_Version is 43.
Ext.B (U+20000..U+2A6D6) if UCA_Version is  8 to 41.
Ext.B (U+20000..U+2A6DD) if UCA_Version is 43.
Ext.C (U+2A700..U+2B734) if UCA_Version is 20 or later.
Ext.D (U+2B740..U+2B81D) if UCA_Version is 22 or later.
Ext.E (U+2B820..U+2CEA1) if UCA_Version is 32 or later.
Ext.F (U+2CEB0..U+2EBE0) if UCA_Version is 36 or later.
Ext.G (U+30000..U+3134A) if UCA_Version is 43.

Through "overrideCJK", ordering of CJK unified ideographs (including extensions) can be overridden.

ex. CJK unified ideographs in the JIS code point order.

overrideCJK => sub {
    my $u = shift;             # get a Unicode codepoint
    my $b = pack('n', $u);     # to UTF-16BE
    my $s = your_unicode_to_sjis_converter($b); # convert
    my $n = unpack('n', $s);   # convert sjis to short
    [ $n, 0x20, 0x2, $u ];     # return the collation element
},

The return value may be an arrayref of 1st to 4th weights as shown above. The return value may be an integer as the primary weight as shown below. If "undef" is returned, the default derived collation element will be used.

overrideCJK => sub {
    my $u = shift;             # get a Unicode codepoint
    my $b = pack('n', $u);     # to UTF-16BE
    my $s = your_unicode_to_sjis_converter($b); # convert
    my $n = unpack('n', $s);   # convert sjis to short
    return $n;                 # return the primary weight
},

The return value may be a list containing zero or more of an arrayref, an integer, or "undef".

ex. ignores all CJK unified ideographs.

overrideCJK => sub {()}, # CODEREF returning empty list
 # where ->eq("Pe\x{4E00}rl", "Perl") is true
 # as U+4E00 is a CJK unified ideograph and to be ignorable.

If a false value (including "undef") is passed, "overrideCJK" has no effect. "$Collator->change(overrideCJK => 0)" resets the old one.

But assignment of weight for CJK unified ideographs in "table" or "entry" is still valid. If "undef" is passed explicitly as the value for this key, weights for CJK unified ideographs are treated as undefined. However when "UCA_Version" > 8, "(overrideCJK => undef)" has no special meaning.

Note: In addition to them, 12 CJK compatibility ideographs ("U+FA0E", "U+FA0F", "U+FA11", "U+FA13", "U+FA14", "U+FA1F", "U+FA21", "U+FA23", "U+FA24", "U+FA27", "U+FA28", "U+FA29") are also treated as CJK unified ideographs. But they can't be overridden via "overrideCJK" when you use DUCET, as the table includes weights for them. "table" or "entry" has priority over "overrideCJK".

overrideHangul
-- see 7.1 Derived Collation Elements, UTS #10.

By default, Hangul syllables are decomposed into Hangul Jamo, even if "(normalization => undef)". But the mapping of Hangul syllables may be overridden.

This parameter works like "overrideCJK", so see there for examples.

If you want to override the mapping of Hangul syllables, NFD and NFKD are not appropriate, since NFD and NFKD will decompose Hangul syllables before overriding. FCD may decompose Hangul syllables as the case may be.

If a false value (but not "undef") is passed, "overrideHangul" has no effect. "$Collator->change(overrideHangul => 0)" resets the old one.

If "undef" is passed explicitly as the value for this key, weight for Hangul syllables is treated as undefined without decomposition into Hangul Jamo. But definition of weight for Hangul syllables in "table" or "entry" is still valid.

overrideOut
-- see 7.1.1 Handling Ill-Formed Code Unit Sequences, UTS #10.

Perl seems to allow out-of-range values (greater than 0x10FFFF). By default, out-of-range values are replaced with "U+FFFD" (REPLACEMENT CHARACTER) when "UCA_Version" >= 22, or ignored when "UCA_Version" <= 20.

When "UCA_Version" >= 22, the weights of out-of-range values can be overridden. Though "table" or "entry" are available for them, out-of-range values are too many.

"overrideOut" can perform it algorithmically. This parameter works like "overrideCJK", so see there for examples.

ex. ignores all out-of-range values.

overrideOut => sub {()}, # CODEREF returning empty list

If a false value (including "undef") is passed, "overrideOut" has no effect. "$Collator->change(overrideOut => 0)" resets the old one.

NOTE ABOUT U+FFFD:

UCA recommends that out-of-range values should not be ignored for security reasons. Say, "pe\x{110000}rl" should not be equal to "perl". However, "U+FFFD" is wrongly mapped to a variable collation element in DUCET for Unicode 6.0.0 to 6.2.0, that means out-of-range values will be ignored when "variable" isn't "Non-ignorable".

The mapping of "U+FFFD" is corrected in Unicode 6.3.0. see http://www.unicode.org/reports/tr10/tr10-28.html#Trailing_Weights (7.1.4 Trailing Weights). Such a correction is reproduced by this.

overrideOut => sub { 0xFFFD }, # CODEREF returning a very large integer

This workaround is unnecessary since Unicode 6.3.0.

preprocess
-- see 5.4 Preprocessing, UTS #10.

If specified, the coderef is used to preprocess each string before the formation of sort keys.

ex. dropping English articles, such as "a" or "the". Then, "the pen" is before "a pencil".

preprocess => sub {
      my $str = shift;
      $str =~ s/\b(?:an?|the)\s+//gi;
      return $str;
   },

"preprocess" is performed before "normalization" (if defined).

ex. decoding strings in a legacy encoding such as shift-jis:

$sjis_collator = Unicode::Collate->new(
    preprocess => \&your_shiftjis_to_unicode_decoder,
);
@result = $sjis_collator->sort(@shiftjis_strings);

Note: Strings returned from the coderef will be interpreted according to Perl's Unicode support. See perlunicode, perluniintro, perlunitut, perlunifaq, utf8.

rearrange
-- see 3.5 R
rangement, UTS #10.

Les caractères qui ne sont pas codés dans l'ordre logique et qui doivent être réarrangés. Si "UCA_Version" est égal ou inférieur à 11, la valeur par défaut est :

réarranger => [ 0x0E40..0x0E44, 0x0EC0..0x0EC4 ],

Si vous souhaitez interdire tout réarrangement, passez "undef" ou "[]" (une référence à une liste vide) comme valeur pour cette clé.

Si "UCA_Version" est égal ou supérieur à 14, la valeur par défaut est "[]" (c'est-à-dire pas de réarrangement).

Selon la version 9 de l'UCA, ce paramètre ne doit pas être utilisé ; mais il n'est pas averti pour le moment.

réécrire
Si spécifié, le coderef est utilisé pour réécrire les lignes dans "table" ou "entry". Le coderef recevra chaque ligne, puis devra retourner une ligne réécrite selon le format du fichier UCA. Si le coderef retourne une ligne vide, la ligne sera ignorée.

par ex. tout caractère primaire ignorable en caractère tertiaire ignorable :

réécrire => sous {
    mon $ligne = shift;
    $ligne =~ s/\[\.0000\..{4}\..{4}\./[.0000.0000.0000./g;
    return $ligne;
},

Cet exemple montre la réécriture des poids. "réécrire" est autorisé à affecter les points de code, les poids et le nom.

NOTE : "table" est disponible pour utiliser un autre fichier de table ; préparer une table modifiée une fois serait plus efficace que de réécrire les lignes à chaque lecture d'une table non modifiée.

supprimer
-- voir 3.12 Commandes à usage spécial, UTS #35 (LDML) Partie 5 : Tri.

Les contractions commençant par les caractères spécifiés sont supprimées, même si ces contractions sont définies dans "table".

Un exemple pour le russe et certaines langues utilisant l'alphabet cyrillique :

supprimer => [0x0400..0x0417, 0x041A..0x0437, 0x043A..0x045F],

où 0x0400 représente "U+0400", LETTRE CYRILLIQUE CAPITALE IE AVEC ACCENT GRAVE.

NOTE : Les contractions via "entry" ne seront pas supprimées.

table
-- voir 3.8 Table d'éléments de tri Unicode par défaut, UTS #10.

Vous pouvez utiliser une autre table d'éléments de tri si vous le souhaitez.

Le fichier de table doit se trouver dans le répertoire Unicode/Collate de @INC. Par exemple, si le nom du fichier est Foo.txt, le fichier de table est recherché comme Unicode/Collate/Foo.txt dans @INC.

Par défaut, allkeys.txt (comme nom de fichier de DUCET) est utilisé. Si vous préparez votre propre fichier de table, tout nom autre que allkeys.txt pourrait être préférable pour éviter les conflits de nom.

NOTE : Lorsque XSUB est utilisé, le DUCET est compilé lors de la construction de ce module, et cela peut faire gagner du temps à l'exécution. Indiquer explicitement "(table => 'allkeys.txt')", ou utiliser une autre table, ou utiliser "ignoreChar", "ignoreName", "undefChar", "undefName" ou "rewrite" empêchera ce module d'utiliser le DUCET compilé.

Si "undef" est explicitement passé comme valeur pour cette clé, aucun fichier n'est lu (mais vous pouvez définir des éléments de tri via "entry").

Une façon typique de définir une table d'éléments de tri sans aucun fichier de table :

   $onlyABC = Unicode::Collate->new(
       table => undef,
       entry => << 'ENTRIES',
0061 ; [.0101.0020.0002.0061] # LETTRE LATINE MINUSCULE A
0041 ; [.0101.0020.0008.0041] # LETTRE LATINE CAPITALE A
0062 ; [.0102.0020.0002.0062] # LETTRE LATINE MINUSCULE B
0042 ; [.0102.0020.0008.0042] # LETTRE LATINE CAPITALE B
0063 ; [.0103.0020.0002.0063] # LETTRE LATINE MINUSCULE C
0043 ; [.0103.0020.0008.0043] # LETTRE LATINE CAPITALE C
ENTRIES
    );

Si "ignoreName" ou "undefName" est utilisé, les noms de caractères doivent être spécifiés comme commentaire (après "#") sur chaque ligne.

undefChar
undefName
-- voir 6.3.3 Réduction du répertoire, UTS #10.

Annule l'élément de tri comme s'il était non attribué dans la "table". Cela réduit la taille de la table. Si un caractère non attribué apparaît dans la chaîne à trier, la clé de tri est formée à partir de son point de code comme un élément de tri à caractère unique, car il est supérieur à tout autre élément de tri attribué (dans l'ordre des points de code parmi les caractères non attribués). Cependant, il serait préférable d'ignorer les caractères qui vous sont inconnus et qui ne sont peut-être jamais utilisés.

Via "undefChar", tout caractère correspondant à "qr/$undefChar/" sera annulé. Via "undefName", tout caractère dont le nom (donné dans le fichier "table" sous forme de commentaire) correspond à "qr/$undefName/" sera annulé.

ex. Les poids de tri pour les caractères au-delà de BMP ne sont pas stockés dans l'objet :

undefChar => qr/[^\0-\x{fffd}]/,
majuscule_avant_minuscule
-- voir 6.6 Comparaisons de casse, UTS #10.

Par défaut, la minuscule précède la majuscule. Si le paramètre est rendu vrai, cela est inversé.

NOTE : Ce paramètre suppose naïvement que toutes les distinctions minuscule/majuscule doivent survenir au niveau 3, et que leurs poids au niveau 3 doivent être identiques à ceux mentionnés en 7.3.1, UTS #10. Si vous définissez vos éléments de tri d'une manière différente de cette exigence, ce paramètre ne fonctionnera pas valablement.

variable
-- voir 3.6 Poids variables, UTS #10.

Cette clé permet le pondération variable des éléments de tri variables, qui sont marqués d'un ASTÉRISQUE dans la table (NOTE : De nombreux signes de ponctuation et symboles sont variables dans allkeys.txt).

variable => 'vidé', 'non-ignorable', 'décalé', ou 'décalé-tronqué'.

Ces noms sont insensibles à la casse. Par défaut (si la spécification est omise), 'décalé' est adopté.

'Vidé'        Les éléments variables sont rendus ignorables aux niveaux 1 à 3 ;
                 considérés au 4ème niveau.
'Non-Ignorable'  Les éléments variables ne sont pas réinitialisés à ignorables.
'Décalé'       Les éléments variables sont rendus ignorables aux niveaux 1 à 3
                 leur poids de niveau 4 est remplacé par l'ancien poids de niveau 1.
                 Le poids de niveau 4 pour les éléments non variables est 0xFFFF.
'Décalé-tronqué' Identique à 'décalé', mais tous les FFFF au 4ème niveau
                 sont tronqués.

"@sorted = $Collator->sort(@not_sorted)"
Trie une liste de chaînes.
"$result = $Collator->cmp($a, $b)"
Retourne 1 (quand $a est supérieur à $b) ou 0 (quand $a est égal à $b) ou -1 (quand $a est inférieur à $b).
"$result = $Collator->eq($a, $b)"
"$result = $Collator->ne($a, $b)"
"$result = $Collator->lt($a, $b)"
"$result = $Collator->le($a, $b)"
"$result = $Collator->gt($a, $b)"
"$result = $Collator->ge($a, $b)"
Ils fonctionnent comme les opérateurs du même nom que les leurs. 
eq : si $a est égal à $b.
ne : si $a n'est pas égal à $b.
lt : si $a est inférieur à $b.
le : si $a est inférieur à $b ou égal à $b.
gt : si $a est supérieur à $b.
ge : si $a est supérieur à $b ou égal à $b.
"$sortKey = $Collator->getSortKey($string)"
-- voir 4.3 Formulaire de clé de tri, UTS #10.

Retourne une clé de tri.

Vous comparez les clés de tri à l'aide d'une comparaison binaire et obtenez le résultat de la comparaison des chaînes à l'aide de l'UCA.

$Collator->getSortKey($a) cmp $Collator->getSortKey($b)
   équivaut à
$Collator->cmp($a, $b)
"$sortKeyForm = $Collator->viewSortKey($string)"
Convertit une clé de tri en sa forme de représentation. Si "UCA_Version" est 8, la sortie est légèrement différente. 
use Unicode::Collate;
mon $c = Unicode::Collate->new();
print $c->viewSortKey("Perl"),"\n";

# [0B67 0A65 0B7F 0B03 | 0020 0020 0020 0020 | 0008 0002 0002 0002 | FFFF FFFF FFFF FFFF]
#  Niveau 1               Niveau 2               Niveau 3               Niveau 4

Méthodes pour la Recherche

Les méthodes "match", "gmatch", "subst", "gsubst" fonctionnent comme "m//", "m//g", "s///", "s///g", respectivement, mais elles ne sont pas conscientes de tout motif, seulement d'une sous-chaîne littérale.

AVERTISSEMENT : Si "preprocess" ou "normalization" est vrai pour $Collator, l'appel de ces méthodes ("index", "match", "gmatch", "subst", "gsubst") provoque une erreur (croaked), car la position et la longueur pourraient différer de celles de la chaîne spécifiée.

Matching and Searching

The following methods are defined for matching a $substring against a $string.

The default behavior of case-insensitive matching depends on the default collation tailoring. The variables "caselevel" and "alt" are useful here. As an example, how to make the collator match case-insensitively regardless of the default tailoring:

my $Collator = Unicode::Collate->new( caselevel => 2, alt => 2 );
# or
my $Collator = Unicode::Collate->new( caselevel => 2, alt => undef );

Note that the variables "katakana_before_hiragana" and "upper_before_lower" are ignored. They are never used, and therefore they are ignored. The values of these variables are effectively irrelevant because the Unicode Collation Algorithm doesn't define tie-breaking rules for characters of different scripts or cases beyond level 1. Therefore, unless you specify a custom tailoring that includes these rules, they are effectively ignored.

"$position = $Collator->index($string, $substring[, $position])"
"($position, $length) = $Collator->index($string, $substring[, $position])"
If $substring matches a part of $string, returns the position of the first occurrence of the matching part in scalar context; in list context, returns a two-element list of the position and the length of the matching part.

If $substring does not match any part of $string, returns -1 in scalar context and an empty list in list context.

e.g. when the content of $str is ""Ich mu"ß" studieren Perl."", you say the following where $sub is ""M"ü"SS"",

my $Collator = Unicode::Collate->new( normalization => undef, level => 1 );
                                   # (normalization => undef) is REQUIRED.
my $match;
if (my($pos,$len) = $Collator->index($str, $sub)) {
    $match = substr($str, $pos, $len);
}

and get ""mu"ß""" in $match, since ""mu"ß""" is primary equal to ""M"ü"SS"".

"$match_ref = $Collator->match($string, $substring)"
"($match) = $Collator->match($string, $substring)"
If $substring matches a part of $string, in scalar context, returns a reference to the first occurrence of the matching part ($match_ref is always true if matches, since every reference is true); in list context, returns the first occurrence of the matching part.

If $substring does not match any part of $string, returns "undef" in scalar context and an empty list in list context.

e.g.

if ($match_ref = $Collator->match($str, $sub)) { # scalar context
    print "matches [$$match_ref].\n";
} else {
    print "doesn't match.\n";
}
 or
if (($match) = $Collator->match($str, $sub)) { # list context
    print "matches [$match].\n";
} else {
    print "doesn't match.\n";
}
"@match = $Collator->gmatch($string, $substring)"
If $substring matches a part of $string, returns all the matching parts (or matching count in scalar context).

If $substring does not match any part of $string, returns an empty list.

"$count = $Collator->subst($string, $substring, $replacement)"
If $substring matches a part of $string, the first occurrence of the matching part is replaced by $replacement ($string is modified) and $count (always equals to 1) is returned.

$replacement can be a "CODEREF", taking the matching part as an argument, and returning a string to replace the matching part (a bit similar to "s/(..)/$coderef->($1)/e").

"$count = $Collator->gsubst($string, $substring, $replacement)"
If $substring matches a part of $string, all the occurrences of the matching part are replaced by $replacement ($string is modified) and $count is returned.

$replacement can be a "CODEREF", taking the matching part as an argument, and returning a string to replace the matching part (a bit similar to "s/(..)/$coderef->($1)/eg").

e.g.

my $Collator = Unicode::Collate->new( normalization => undef, level => 1 );
                                   # (normalization => undef) is REQUIRED.
my $str = "Camel donkey zebra came\x{301}l CAMEL horse cam\0e\0l...";
$Collator->gsubst($str, "camel", sub { "<b>$_[0]</b>" });
# now $str is "<b>Camel</b> donkey zebra <b>came\x{301}l</b> <b>CAMEL</b> horse <b>cam\0e\0l</b>...";
# i.e., all the camels are made bold-faced.
 Examples: levels and ignore_level2 - what does camel match?
---------------------------------------------------------------------------
 level  ignore_level2  |  camel  Camel  came\x{301}l  c-a-m-e-l  cam\0e\0l
-----------------------|---------------------------------------------------
   1        false      |   yes    yes      yes          yes        yes
   2        false      |   yes    yes      no           yes        yes
   3        false      |   yes    no       no           yes        yes
   4        false      |   yes    no       no           no         yes
-----------------------|---------------------------------------------------
   1        true       |   yes    yes      yes          yes        yes
   2        true       |   yes    yes      yes          yes        yes
   3        true       |   yes    no       yes          yes        yes
   4        true       |   yes    no       yes          no         yes
---------------------------------------------------------------------------
 note: if variable => non-ignorable, camel doesn't match c-a-m-e-l
       at any level.

Other Methods

"%old_tailoring = $Collator->change(%new_tailoring)"
"$modified_collator = $Collator->change(%new_tailoring)"
Changes the value of specified keys and returns the changed part. 
$Collator = Unicode::Collate->new(level => 4);
$Collator->eq("perl", "PERL"); # false
%old = $Collator->change(level => 2); # returns (level => 4).
$Collator->eq("perl", "PERL"); # true
$Collator->change(%old); # returns (level => 2).
$Collator->eq("perl", "PERL"); # false

Not all "(key,value)"s are allowed to be changed. See also @Unicode::Collate::ChangeOK and @Unicode::Collate::ChangeNG.

In the scalar context, returns the modified collator (but it is not a clone from the original).

$Collator->change(level => 2)->eq("perl", "PERL"); # true
$Collator->eq("perl", "PERL"); # true; now max level is 2nd.
$Collator->change(level => 4)->eq("perl", "PERL"); # false
"$version = $Collator->version()"
Returns the version number (a string) of the Unicode Standard which the "table" file used by the collator object is based on. If the table does not include a version line (starting with @version), returns "unknown".
UCA_Version()
Returns the revision number of UTS #10 this module consults, that should correspond with the DUCET incorporated.
Base_Unicode_Version()
Returns the version number of UTS #10 this module consults, that should correspond with the DUCET incorporated.

INSTALL

Though this module can be used without any "table" file, to use this module easily, it is recommended to install a table file in the UCA format, by copying it under the directory <a place in @INC>/Unicode/Collate.

The most preferable one is "The Default Unicode Collation Element Table" (aka DUCET), available from the Unicode Consortium's website:

http://www.unicode.org/Public/UCA/
http://www.unicode.org/Public/UCA/latest/allkeys.txt
(latest version)

If DUCET is not installed, it is recommended to copy the file from http://www.unicode.org/Public/UCA/latest/allkeys.txt to <a place in @INC>/Unicode/Collate/allkeys.txt manually.

NOM

Unicode::Collate - ressources pour les données de tri Unicode

SYNOPSIS

    use Unicode::Collate;

    my $collator = Unicode::Collate->new(locale => 'en');
    my $string1  = 'ä';
    my $string2  = 'z';

    if ($collator->cmp($string1, $string2) == -1) {
        print "";
    }

DESCRIPTION

Ce module implémente l'algorithme de collation Unicode (UCA) spécifié dans Unicode Collation Algorithm - UTS #10. Il fournit un moyen de comparer des chaînes de caractères en tenant compte des règles de tri spécifiques à la langue.

L'UCA est implémenté via le tableau des éléments de collation Unicode par défaut (DUCET) et peut être personnalisé via des tables de collation spécifiques à la locale.

Pour plus d'informations sur les locales et les tables de collation, veuillez consulter les ressources Unicode, notamment UTS #35.

EXPORT

Aucun export par défaut.

INSTALLATION

Pour installer ce module, utilisez le gestionnaire de paquets de votre distribution.

Si vous souhaitez l'installer manuellement à partir des sources, vous pouvez utiliser la commande suivante :

    perl Makefile.PL
    make
    make install

Unicode::Normalize est requis pour exécuter le test de conformité.

Le support EBCDIC est expérimental.

CAVEATS

La gestion des caractères de contrôle et des caractères non imprimables peut nécessiter des configurations spécifiques. La valeur du niveau de tri pour les éléments "non ignorable" doit être définie à 3.

Unicode::Normalize est requis pour exécuter le test de conformité.
