DESCRIPTION

UI signifie User Interface (Interface Utilisateur) et constitue un ensemble de routines polyvalentes pour solliciter des informations textuelles auprès de l'utilisateur. Grâce à des méthodes écrites par l'utilisateur (voir UI_create_method(3)), les sollicitations peuvent être effectuées de toute manière imaginable, que ce soit par une simple invite textuelle, par des boîtes de dialogue ou depuis un téléphone portable.

Toutes les fonctions opèrent via un contexte de type UI. Ce contexte contient toutes les informations nécessaires pour effectuer les invites correctement, ainsi qu'une référence à une UI_METHOD, qui est un vecteur ordonné de fonctions exécutant les sollicitations réelles.

La première chose à faire est de créer une UI avec UI_new() ou UI_new_method(), puis d'y ajouter des informations avec les fonctions UI_add ou UI_dup. De plus, des données aléatoires définies par l'utilisateur peuvent être transmises à la méthode sous-jacente via des appels à UI_add_user_data() ou UI_dup_user_data(). La méthode UI par défaut ne se soucie pas de ces données, mais d'autres méthodes pourraient.

Enfin, utilisez UI_process() pour effectuer réellement les invites et UI_get0_result() et UI_get_result_length() pour trouver le résultat de l'invite et sa longueur.

Une UI peut contenir plus d'une invite, qui sont exécutées dans l'ordre donné. Chaque invite reçoit un numéro d'index qui est retourné par les fonctions UI_add et UI_dup, et doit être utilisé pour obtenir le résultat correspondant avec UI_get0_result() et UI_get_result_length().

UI_process() peut être appelée plus d'une fois sur la même UI, permettant ainsi à une UI d'avoir une longue durée de vie, mais peut tout aussi bien avoir une courte durée de vie.

Les fonctions sont les suivantes :

UI_new() crée une nouvelle UI en utilisant la méthode UI par défaut. Une fois cette UI terminée, elle doit être libérée avec UI_free().

UI_new_method() crée une nouvelle UI en utilisant la méthode UI donnée. Une fois cette UI terminée, elle doit être libérée avec UI_free().

UI_OpenSSL() renvoie la méthode UI intégrée (note : pas nécessairement celle par défaut, car la valeur par défaut peut être changée. Voir plus loin). Cette méthode est la partie la plus dépendante de la machine/OS d'OpenSSL et pose normalement le plus de problèmes lors du portage.

UI_null() renvoie une méthode UI qui ne fait rien. Son utilité est d'éviter d'obtenir les valeurs par défaut internes pour les pointeurs UI_METHOD passés.

UI_free() supprime une UI de la mémoire, ainsi que toutes les autres zones mémoire qui y sont connectées, comme les chaînes d'entrée dupliquées, les résultats et autres. Si ui est NULL, rien n'est fait.

UI_add_input_string() et UI_add_verify_string() ajoutent une invite à l'UI, ainsi que des indicateurs (flags), un tampon de résultat et les tailles minimale et maximale souhaitées du résultat, sans compter le caractère NUL final. Les informations fournies sont utilisées pour demander des informations, par exemple un mot de passe, et pour vérifier un mot de passe (c'est-à-dire demander à l'utilisateur de le saisir deux fois et de vérifier que la même chaîne a été saisie deux fois). UI_add_verify_string() prend un argument supplémentaire qui doit être un pointeur vers le tampon de résultat de la chaîne d'entrée qu'il est censé vérifier, sinon la vérification échouera.

UI_add_input_boolean() ajoute une invite à l'UI qui est censée être répondue de manière booléenne, avec un seul caractère pour oui et un caractère différent pour non. Un ensemble de caractères pouvant être utilisés pour annuler l'invite est également fourni. L'invite elle-même est divisée en deux, une partie étant le texte descriptif (fourni via l'argument prompt) et une décrivant les réponses possibles (fourni via l'argument action_desc).

UI_add_info_string() et UI_add_error_string() ajoutent des chaînes qui sont affichées en même temps que l'invite pour des informations supplémentaires ou pour afficher une chaîne d'erreur. La différence entre les deux est purement conceptuelle. Avec la méthode intégrée, il n'y a pas de différence technique entre elles. D'autres méthodes peuvent faire une distinction, cependant.

Les indicateurs actuellement supportés sont UI_INPUT_FLAG_ECHO, qui est pertinent pour UI_add_input_string() et fera que la réponse de l'utilisateur sera affichée (lorsqu'on demande un mot de passe, cet indicateur ne doit évidemment pas être utilisé), et UI_INPUT_FLAG_DEFAULT_PWD, ce qui signifie qu'un mot de passe par défaut d'une certaine sorte sera utilisé (entièrement dépendant de l'application et de la méthode UI).

UI_dup_input_string(), UI_dup_verify_string(), UI_dup_input_boolean(), UI_dup_info_string() et UI_dup_error_string() sont fondamentalement identiques à leurs homologues UI_add, sauf qu'ils créent leurs propres copies de toutes les chaînes.

UI_construct_prompt() est une fonction d'aide qui peut être utilisée pour créer une invite à partir de deux éléments d'information : une description de phrase phrase_desc et un nom d'objet object_name, où ce dernier peut être NULL. Le constructeur par défaut (s'il n'en est pas fourni par la méthode utilisée) crée une chaîne "Enter phrase_desc for object_name:" où la partie " for object_name" est omise si object_name est NULL. Avec la description "pass phrase" et le nom de fichier "foo.key", cela devient "Enter pass phrase for foo.key:". D'autres méthodes peuvent créer n'importe quelle chaîne et peuvent inclure des encodages qui seront traités par les autres fonctions de la méthode.

UI_add_user_data() ajoute un pointeur de données utilisateur que la méthode peut utiliser à tout moment. La méthode UI intégrée ne se soucie pas de ces informations. Notez que plusieurs appels à cette fonction n'ajoutent pas de données, ils remplacent le bloc précédent par celui fourni en argument.

UI_dup_user_data() duplique les données utilisateur et sert d'alternative à UI_add_user_data() lorsque les données utilisateur doivent être conservées plus longtemps, peut-être même pendant toute la durée de vie de l'application. L'objet UI prend possession de cette duplication et la libérera lorsqu'elle sera remplacée ou que l'UI sera détruite. UI_dup_user_data() retourne 0 en cas de succès, ou -1 en cas d'échec d'allocation mémoire ou si la méthode n'a pas de fonction de duplication.

UI_get0_user_data() récupère les données qui ont été précédemment transmises à l'UI avec UI_add_user_data() ou UI_dup_user_data.

UI_get0_result() retourne un pointeur vers le tampon de résultat associé à l'information indexée par i.

DESCRIPTION

The UI module implements a framework for handling user interaction. Different parts of OpenSSL may need to interact with the user, for example to ask for a password or to display some information. The UI module allows these interactions to be handled in a generic way, irrespective of the actual way the interaction is performed.

A UI object is created using UI_new() or UI_new_method(). A UI object is associated with a UI_METHOD structure. This structure defines the actual methods for how the user interaction is performed. OpenSSL provides some built-in methods, such as UI_OpenSSL(), which uses the standard input and output, and UI_null(), which performs no interaction at all.

The default UI method can be changed using UI_set_default_method() and retrieved using UI_get_default_method().

UI_free() frees a UI object.

UI_add_input_string(), UI_dup_input_string(), UI_add_verify_string(), UI_dup_verify_string(), UI_add_input_boolean(), UI_dup_input_boolean(), UI_add_info_string(), UI_dup_info_string(), UI_add_error_string() and UI_dup_error_string() add a prompt or information to the UI object. The functions ending with _dup allocates memory for the prompt or information. The _input_string and _verify_string functions expect the user to input a string. The _input_boolean function expects the user to input a 'y' or 'n'. The _info_string and _error_string functions display information or error messages to the user. The flags argument can be used to specify options like UI_INPUT_FLAG_ECHO. The result is stored in the result parameter. The functions where result is NULL are meant for the caller to duplicate the result, for example, for later use.

UI_construct_prompt() constructs a prompt string. The object_desc and object_name parameters are used to describe the object for which the prompt is constructed. This can be useful for internationalization.

UI_process() goes through the information given so far, does all the printing and prompting and returns the final status, which is -2 on out-of-band events (Interrupt, Cancel, ...), -1 on error and 0 on success.

UI_ctrl() adds extra control for the application author. For now, it understands two commands: UI_CTRL_PRINT_ERRORS, which makes UI_process() print the OpenSSL error stack as part of processing the UI, and UI_CTRL_IS_REDOABLE, which returns a flag saying if the used UI can be used again or not.

UI_set_default_method() changes the default UI method to the one given. This function is not thread-safe and should not be called at the same time as other OpenSSL functions.

UI_get_default_method() returns a pointer to the current default UI method.

UI_get_method() returns the UI method associated with a given UI.

UI_set_method() changes the UI method associated with a given UI.

NOTES

The resulting strings that the built in method UI_OpenSSL() generate are assumed to be encoded according to the current locale or (for Windows) code page. For applications having different demands, these strings need to be converted appropriately by the caller. For Windows, if the OPENSSL_WIN32_UTF8 environment variable is set, the built-in method UI_OpenSSL() will produce UTF-8 encoded strings instead.

RETURN VALUES

UI_new() and UI_new_method() return a valid UI structure or NULL if an error occurred.

UI_add_input_string(), UI_dup_input_string(), UI_add_verify_string(), UI_dup_verify_string(), UI_add_input_boolean(), UI_dup_input_boolean(), UI_add_info_string(), UI_dup_info_string(), UI_add_error_string() and UI_dup_error_string() return a positive number on success or a value which is less than or equal to 0 otherwise.

UI_construct_prompt() returns a string or NULL if an error occurred.

UI_dup_user_data() returns 0 on success or -1 on error.

UI_get0_result() returns a string or NULL on error.

UI_get_result_length() returns a positive integer or 0 on success; otherwise it returns -1 on error.

UI_process() returns 0 on success or a negative value on error.

UI_ctrl() returns a mask on success or -1 on error.

UI_get_default_method(), UI_get_method(), UI_OpenSSL(), UI_null() and UI_set_method() return either a valid UI_METHOD structure or NULL respectively.
