UFFDIO_API(2const) UFFDIO_API(2const)

NOM

UFFDIO_API - activer l'opération de userfaultfd et effectuer la poignée de main API

BIBLIOTHÈQUE

Bibliothèque C standard (libc, -lc)

SYNTAXE

#include <linux/userfaultfd.h>  /* Définition des constantes UFFD* */
#include <sys/ioctl.h>
int ioctl(int fd, UFFDIO_API, struct uffdio_api *argp);
#include <linux/userfaultfd.h>
struct uffdio_api {
    __u64 api;       /* Version de l'API demandée (entrée) */
    __u64 features;  /* Fonctionnalités demandées (entrée/sortie) */
    __u64 ioctls;    /* Opérations ioctl() disponibles (sortie) */
};

DESCRIPTION

Active l'opération de userfaultfd et effectue la poignée de main API.

Le champ api désigne la version de l'API demandée par l'application. Le noyau vérifie qu'il peut prendre en charge la version de l'API demandée et définit les champs features et ioctls avec des masques de bits représentant toutes les fonctionnalités disponibles et les opérations ioctl(2) génériques disponibles.

Avant Linux 4.11, le champ features doit être initialisé à zéro avant l'appel à UFFDIO_API, et zéro (c'est-à-dire aucun bit de fonctionnalité) est placé dans le champ features par le noyau au retour de ioctl(2).

Depuis Linux 4.11, userfaultfd prend en charge des fonctionnalités qui doivent être activées explicitement. Pour activer n'importe laquelle de ces fonctionnalités, il faut définir les bits de fonctionnalité correspondants dans features lors de l'appel à l'ioctl UFFDIO_API.

Pour des raisons historiques, un userfaultfd temporaire est nécessaire pour sonder quelles fonctionnalités userfaultfd le noyau prend en charge. L'application doit créer un userfaultfd temporaire, effectuer un appel ioctl UFFDIO_API avec features mis à zéro. Une fois que l'ioctl UFFDIO_API est revenu avec succès, features doit contenir toutes les fonctionnalités userfaultfd que le noyau prend en charge. Le userfaultfd temporaire peut être fermé en toute sécurité après la sonde.

Si l'application définit des bits de fonctionnalité non pris en charge, le noyau mettra à zéro la structure uffdio_api retournée et renverra EINVAL.

Les bits de fonctionnalité suivants peuvent être définis :

UFFD_FEATURE_EVENT_FORK (depuis Linux 4.11)
Lorsque cette fonctionnalité est activée, les objets userfaultfd associés à un processus parent sont dupliqués dans le processus enfant lors de fork(2) et un événement UFFD_EVENT_FORK est délivré au moniteur userfaultfd.
UFFD_FEATURE_EVENT_REMAP (depuis Linux 4.11)
Si cette fonctionnalité est activée, lorsque le processus qui cause le défaut appelle mremap(2), le moniteur userfaultfd recevra un événement de type UFFD_EVENT_REMAP.
UFFD_FEATURE_EVENT_REMOVE (depuis Linux 4.11)
Si cette fonctionnalité est activée, lorsque le processus qui cause le défaut appelle madvise(2) avec les conseils MADV_DONTNEED ou MADV_REMOVE pour libérer une zone de mémoire virtuelle, le moniteur userfaultfd recevra un événement de type UFFD_EVENT_REMOVE.
UFFD_FEATURE_EVENT_UNMAP (depuis Linux 4.11)
Si cette fonctionnalité est activée, lorsque le processus qui cause le défaut démappe la mémoire virtuelle soit explicitement avec munmap(2), soit implicitement lors de mmap(2) ou mremap(2), le moniteur userfaultfd recevra un événement de type UFFD_EVENT_UNMAP.
UFFD_FEATURE_MISSING_HUGETLBFS (depuis Linux 4.11)
Si ce bit de fonctionnalité est défini, le noyau prend en charge l'enregistrement de plages userfaultfd sur des zones de mémoire hugetlbfs.
UFFD_FEATURE_MISSING_SHMEM (depuis Linux 4.11)
Si ce bit de fonctionnalité est défini, le noyau prend en charge l'enregistrement de plages userfaultfd sur des zones de mémoire partagée. Cela inclut toutes les API de mémoire partagée du noyau : mémoire partagée System V, tmpfs(5), mappages partagés de /dev/zero, mmap(2) avec le drapeau MAP_SHARED défini, memfd_create(2), et ainsi de suite.
UFFD_FEATURE_SIGBUS (depuis Linux 4.14)
Si ce bit de fonctionnalité est défini, aucun événement de défaut de page (UFFD_EVENT_PAGEFAULT) ne sera délivré. Au lieu de cela, un signal SIGBUS sera envoyé au processus fautif. Les applications utilisant cette fonctionnalité n'auront pas besoin d'utiliser un moniteur userfaultfd pour traiter les accès mémoire aux régions enregistrées avec userfaultfd.
UFFD_FEATURE_THREAD_ID (depuis Linux 4.14)
Si ce bit de fonctionnalité est défini, uffd_msg.pagefault.feat.ptid sera défini sur l'ID du thread fautif pour chaque message de défaut de page.
UFFD_FEATURE_PAGEFAULT_FLAG_WP (depuis Linux 5.10)
Si ce bit de fonctionnalité est défini, userfaultfd prend en charge les défauts d'écriture protégée pour la mémoire anonyme. (Notez que la prise en charge de shmem / hugetlbfs est indiquée par une fonctionnalité distincte.)
UFFD_FEATURE_MINOR_HUGETLBFS (depuis Linux 5.13)
Si ce bit de fonctionnalité est défini, le noyau prend en charge l'enregistrement de plages userfaultfd en mode mineur sur des zones de mémoire basées sur hugetlbfs.
UFFD_FEATURE_MINOR_SHMEM (depuis Linux 5.14)
Si ce bit de fonctionnalité est défini, le noyau prend en charge l'enregistrement de plages userfaultfd en mode mineur sur des zones de mémoire basées sur shmem.
UFFD_FEATURE_EXACT_ADDRESS (depuis Linux 5.18)
Si ce bit de fonctionnalité est défini, uffd_msg.pagefault.address sera défini sur l'adresse exacte du défaut de page rapportée par le matériel, et ne masquera pas le décalage dans la page. Notez que les anciennes versions de Linux peuvent également indiquer l'adresse exacte, même si le bit de fonctionnalité n'est pas défini.
UFFD_FEATURE_WP_HUGETLBFS_SHMEM (depuis Linux 5.19)
Si ce bit de fonctionnalité est défini, userfaultfd prend en charge les défauts d'écriture protégée pour la mémoire hugetlbfs et shmem / tmpfs.
UFFD_FEATURE_WP_UNPOPULATED (depuis Linux 6.4)
Si ce bit de fonctionnalité est défini, le noyau gérera la mémoire anonyme de la même manière que la mémoire fichier, en permettant à l'utilisateur de protéger en écriture les entrées de table de pages non peuplées.
UFFD_FEATURE_POISON (depuis Linux 6.6)
Si ce bit de fonctionnalité est défini, le noyau prend en charge la résolution des défauts avec l'ioctl UFFDIO_POISON.
UFFD_FEATURE_WP_ASYNC (depuis Linux 6.7)
Si ce bit de fonctionnalité est défini, les défauts de protection en écriture seraient résolus de manière asynchrone par le noyau.
UFFD_FEATURE_MOVE (depuis Linux 6.8)
Si ce bit de fonctionnalité est défini, le noyau prend en charge la résolution des défauts avec l'ioctl UFFDIO_MOVE.

Le champ argp->ioctls retourné peut contenir les bits suivants :

1 << _UFFDIO_API
L'opération UFFDIO_API est prise en charge.
1 << _UFFDIO_REGISTER
L'opération UFFDIO_REGISTER est prise en charge.
1 << _UFFDIO_UNREGISTER
L'opération UFFDIO_UNREGISTER est prise en charge.

VALEUR DE RETOUR

En cas de succès, 0 est retourné.

En cas d'erreur, -1 est retourné et errno est défini pour indiquer l'erreur.

>

ERREURS

EFAULT
argp fait référence à une adresse qui se trouve en dehors de l'espace d'adressage accessible du processus appelant.
EINVAL
La version de l'API demandée dans le champ api n'est pas prise en charge par ce noyau, ou le champ features transmis au noyau inclut des bits de fonctionnalités qui ne sont pas pris en charge par la version actuelle du noyau.
EINVAL
Un appel précédent à UFFDIO_API a déjà activé une ou plusieurs fonctionnalités pour ce userfaultfd. Appeler UFFDIO_API deux fois, la première fois sans aucune fonctionnalité activée, est explicitement autorisé conformément à la poignée de main en deux étapes de détection des fonctionnalités.
EPERM
La fonctionnalité UFFD_FEATURE_EVENT_FORK était activée, mais le processus appelant ne possède pas la capacité CAP_SYS_PTRACE.

NORMES

Linux.

HISTORIQUE

Linux 4.3.

ATTENTION

Si une erreur se produit, le noyau peut mettre à zéro la structure uffdio_api fournie. L'appelant doit considérer son contenu comme non spécifié et le réinitialiser avant de tenter un autre appel à UFFDIO_API.

BOGUES

Afin de détecter les fonctionnalités userfault disponibles et d'activer un sous-ensemble de ces fonctionnalités, le descripteur de fichier userfaultfd doit être fermé après la première opération UFFDIO_API qui interroge la disponibilité des fonctionnalités, et rouvert avant la seconde opération UFFDIO_API qui active réellement les fonctionnalités souhaitées.

EXEMPLES

Voir userfaultfd(2).

VOIR AUSSI

ioctl(2), ioctl_userfaultfd(2), mmap(2), userfaultfd(2)
