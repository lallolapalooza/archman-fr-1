URI::geo(3) Documentation Perl fournie par la communauté URI::geo(3)

NOM

URI::geo - Schéma URI pour les identifiants géographiques

SYNTAXE

use URI;
# URI Geo à partir d'une URI textuelle
my $guri = URI->new( 'geo:54.786989,-2.344214' );
# À partir des coordonnées
my $guri = URI::geo->new( 54.786989, -2.344214 );
# Décodage
my ( $lat, $lon, $alt ) = $guri->location;
my $latitude = $guri->latitude;
# Mise à jour
$guri->location( 55, -1 );
$guri->longitude( -43.23 );

DESCRIPTION

Extrait de http://geouri.org/ :

De plus en plus de protocoles et de formats de données sont étendus par des méthodes
pour ajouter des informations géographiques. Cependant, toutes ces options sont liées
à ce protocole ou format de données spécifique.
Un schéma d'Uniform Resource Identifier (URI) dédié aux emplacements géographiques
serait indépendant de tout protocole, utilisable par tout
logiciel/format de données capable de gérer des URI génériques. Comme une URI
"mailto:" lance votre application de messagerie préférée aujourd'hui, une URI "geo:" pourrait
bientôt lancer votre service de cartographie préféré, ou mettre en file d'attente cet emplacement pour
un appareil de navigation.

SOUS-ROUTINES/METHODES

"new"

Crée un nouvel URI::geo. Les arguments doivent être soit

  • latitude, longitude et éventuellement altitude
  • une référence à un tableau contenant lat, lon, alt
  • une référence à une table de hachage avec des clés nommées de manière appropriée, ou
  • une référence à un objet avec des accesseurs nommés de manière appropriée

Pour maximiser la probabilité que vous puissiez passer un objet représentant un emplacement géographique et que URI::geo fasse le travail correctement, nous essayons un certain nombre de noms d'accesseurs différents.

Si l'objet possède une méthode "latlong" (par exemple, Geo::Point), nous l'utiliserons. S'il existe une méthode "location", nous l'appellerons. Sinon, nous recherchons des accesseurs nommés "lat", "latitude", "lon", "long", "longitude", "ele", "alt", "elevation" ou "altitude" et les utiliserons.

Souvent, si vous avez un objet ou une référence de table de hachage représentant un point, vous pouvez le passer directement à "new" ; ainsi, par exemple, ceci fonctionnera :

use URI::geo;
use Geo::Point;
my $pt = Geo::Point->latlong( 48.208333, 16.372778 );
my $guri = URI::geo->new( $pt );

Tout comme ceci :

my $guri = URI::geo->new( { lat => 55, lon => -1 } );

Et ceci :

my $guri = URI::geo->new( 55, -1 );

Notez que vous pouvez également créer un nouvel "URI::geo" en passant une URI Geo à "URI::new" :

use URI;
my $guri = URI->new( 'geo:55,-1' );

"location"

Obtient ou définit l'emplacement de cette URI geo.

my ( $lat, $lon, $alt ) = $guri->location;
$guri->location( 55.3, -3.7, 120 );

Lors de la définition de l'emplacement, il est possible de passer n'importe lequel des types d'arguments pouvant être passés à "new".

"latitude"

Obtient ou définit la latitude de cette URI geo.

"longitude"

Obtient ou définit la longitude de cette URI geo.

"altitude"

Obtient ou définit l'altitude https://en.wikipedia.org/wiki/Geo_URI_scheme#Altitude de cette URI geo. Pour supprimer l'altitude, définissez-la sur "undef".

"crs"

Obtient ou définit le Système de Référence Coordonnée https://en.wikipedia.org/wiki/Geo_URI_scheme#Coordinate_reference_systems de cette URI geo. Pour supprimer le CRS, définissez-le sur "undef".

"uncertainty"

Obtient ou définit l'incertitude https://en.wikipedia.org/wiki/Geo_URI_scheme#Uncertainty de cette URI geo. Pour supprimer l'incertitude, définissez-la sur "undef".

"field"

CONFIGURATION ET ENVIRONNEMENT

URI::geo ne nécessite aucun fichier de configuration ni variable d'environnement.

DEPENDANCES

URI

DIAGNOSTICS

"Trop d'arguments"
La méthode new ne peut accepter que trois paramètres ; latitude, longitude et altitude.
"Ne sait pas comment convertir le point"
La méthode new ne sait pas comment convertir les paramètres fournis en un objet URI::geo.
"Nécessite lat, lon ou lat, lon, alt"
La méthode new nécessite deux (latitude et longitude) ou trois (latitude, longitude et altitude) paramètres dans une liste. Moins ou plus que cela constitue une erreur.
"Champ inexistant : %s"
Ce champ n'est pas un champ connu pour l'objet URI::geo.
"URI geo mal formée"
L'URI ne peut pas être analysée comme une URI.
"URI geo mal formée"
L'URI ne peut pas être analysée comme une URI.
"Latitude hors plage"
La latitude ne peut être comprise qu'entre -90 et +90.
"Longitude hors plage"
La longitude ne peut être comprise qu'entre -180 et +180.
