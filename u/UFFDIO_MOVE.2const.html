UFFDIO_MOVE(2const) UFFDIO_MOVE(2const)

NOM

UFFDIO_MOVE - déplacer atomiquement un bloc de mémoire continu dans la plage enregistrée par userfault

BIBLIOTHÈQUE

Bibliothèque C standard (libc, -lc)

SYNTAXE

#include <linux/userfaultfd.h>  /* Définition des constantes UFFD* */
#include <sys/ioctl.h>
int ioctl(int fd, UFFDIO_MOVE, struct uffdio_move *argp);
#include <linux/userfaultfd.h>
struct uffdio_move {
    __u64  dst;   /* Destination du déplacement */
    __u64  src;   /* Source du déplacement */
    __u64  len;   /* Nombre d'octets à déplacer */
    __u64  mode;  /* Indicateurs contrôlant le comportement du déplacement */
    __s64  move;  /* Nombre d'octets déplacés, ou erreur négative */
};

DESCRIPTION

Déplace atomiquement un bloc de mémoire continu dans la plage enregistrée par userfault et réveille éventuellement le thread bloqué.

La valeur suivante peut être combinée par OU bit à bit dans .mode pour modifier le comportement de l'opération UFFDIO_MOVE :

UFFDIO_MOVE_MODE_DONTWAKE
Ne pas réveiller le thread qui attend la résolution du défaut de page.
UFFDIO_MOVE_MODE_ALLOW_SRC_HOLES
Autoriser les trous dans la plage virtuelle source qui est déplacée. Lorsqu'elle n'est pas spécifiée, les trous entraîneront une erreur ENOENT. Lorsqu'elle est spécifiée, les trous seront considérés comme de la mémoire déplacée avec succès. Ceci est principalement utile pour déplacer des régions virtuelles alignées sur des pages volumineuses sans savoir s'il existe des pages volumineuses transparentes dans les régions ou non, mais en évitant le risque de devoir diviser la page volumineuse pendant l'opération.

Le champ .move est utilisé par le noyau pour retourner le nombre d'octets réellement déplacés, ou une erreur (une valeur négative de style errno). Le champ .move est en sortie uniquement ; il n'est pas lu par l'opération UFFDIO_MOVE.

VALEUR DE RETOUR

En cas de succès, 0 est retourné. Dans ce cas, la zone entière a été déplacée.

En cas d'erreur, -1 est retourné et errno est défini pour indiquer l'erreur.

ERREURS

EAGAIN
Le nombre d'octets déplacés (c'est-à-dire la valeur retournée dans le champ .move) n'est pas égal à la valeur spécifiée dans le champ .len.
EINVAL
Soit .dst, soit .len n'était pas un multiple de la taille de page du système, soit la plage spécifiée par .src et .len ou .dst et .len était invalide.
EINVAL
Un bit invalide a été spécifié dans le champ .mode.
ENOENT
La plage de mémoire virtuelle source contient des trous non mappés et UFFDIO_MOVE_MODE_ALLOW_SRC_HOLES n'est pas défini.
EEXIST
La plage de mémoire virtuelle de destination est entièrement ou partiellement mappée.
EBUSY
Les pages de la plage de mémoire virtuelle source sont soit épinglées, soit non exclusives au processus. Une fois que KSM a dédupliqué des pages ou que fork(2) a partagé des pages en écriture après copie (COW) lors d'un fork(2) avec des processus enfants, elles ne sont plus exclusives. Le noyau peut seulement effectuer des vérifications légères pour détecter si les pages sont exclusives. Pour augmenter les chances de succès de l'opération, KSM doit être désactivé, fork(2) doit être évité ou MADV_DONTFORK doit être configuré pour la zone de mémoire virtuelle source avant fork(2).
ENOMEM
L'allocation de la mémoire nécessaire à l'opération a échoué.
ESRCH
Le processus cible s'est terminé au moment de l'opération UFFDIO_MOVE.

NORMES

Linux.

HISTORIQUE

Linux 6.8.
