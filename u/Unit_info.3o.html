Module Unit_info
: sig end

Ce module centralise la gestion des fichiers de compilation et de leurs métadonnées.

Plus important encore, ce module fournit des fonctions pour dériver des noms de modules à partir de chaînes de caractères ou de noms de fichiers.

Convention et calcul du nom de module

type intf_or_impl =
| Intf
| Impl

type modname = string

type filename = string

type file_prefix = string

type error =
| Invalid_encoding of filename

exception Error of error

val modulize : string -> modname

modulize s met en majuscule la première lettre de s.

val normalize : string -> string

normalize s met en minuscule la première lettre de s.

val lax_modname_from_source : filename -> modname

lax_modname_from_source filename est modulize stem où stem est le nom de base du nom de fichier filename débarrassé de toutes ses extensions. Par exemple, lax_modname_from_source "/pa.th/x.ml.pp" est "X".

val strict_modname_from_source : filename -> modname

Identique à Unit_info.lax_modname_from_source mais déclenche une erreur Unit_info.error.Invalid_encoding sur les noms de fichiers avec un encodage utf8 invalide.

Fonction de validation du nom de module

val is_unit_name : modname -> bool

is_unit_name name est vrai seulement si name peut être utilisé comme un nom de module valide.

Métadonnées pour une unité de compilation

type t

Métadonnées pour une unité de compilation :

- le nom du module associé à l'unité

- le préfixe du nom de fichier (nom du répertoire + nom de base sans extensions) pour les artefacts de compilation

- le fichier source d'entrée Par exemple, lors de l'appel à ocamlopt dir/x.mli -o target/y.cmi ,

- le fichier source d'entrée est dir/x.mli

- le nom du module est Y

- le préfixe est target/y

val source_file : t -> filename

source_file u est le fichier source de u.

val prefix : t -> file_prefix

prefix u est le préfixe du nom de fichier de l'unité.

val modname : t -> modname

modname u ou artifact_modname a est le nom du module de l'unité ou de l'artefact de compilation.

val kind : t -> intf_or_impl

kind u est le type (interface ou implémentation) de l'unité.

val check_unit_name : t -> unit

check_unit_name u affiche un avertissement si le nom de module dérivé modname u ne doit pas être utilisé comme nom de module tel que spécifié par Unit_info.is_unit_name ~strict:true.

val make : ?check_modname:bool -> source_file:filename -> intf_or_impl -> file_prefix -> t

make ~check ~source_file kind prefix associe à la fois le source_file et le nom du module Unit_info.lax_modname_from_source target_prefix au chemin du système de fichiers prefix.

Si check_modname=true , cette fonction émet un avertissement si le nom de module dérivé n'est pas valide conformément à Unit_info.check_unit_name.

module Artifact : sig end

Artefacts de construction

Métadonnées dérivées des artefacts de construction

val cmi : t -> Artifact.t

Ces fonctions dérivent des métadonnées d'artefact spécifiques à partir des métadonnées d'unité.

val cmo : t -> Artifact.t

val cmx : t -> Artifact.t

val obj : t -> Artifact.t

val cmt : t -> Artifact.t

val cmti : t -> Artifact.t

val annot : t -> Artifact.t

val companion_obj : Artifact.t -> Artifact.t

Les fonctions ci-dessous modifient le type d'un artefact en mettant à jour l'extension de son nom de fichier. Ces fonctions ne couvrent délibérément pas tous les types d'artefacts car nous voulons suivre quels artefacts sont censés être regroupés.

val companion_cmt : Artifact.t -> Artifact.t

val companion_cmi : Artifact.t -> Artifact.t

Attention, companion_cmi a supprime toutes les extensions du nom de fichier de a avant d'ajouter le suffixe ".cmi" contrairement aux autres fonctions qui ne suppriment que l'extension la plus à droite. En d'autres termes, le cmi compagnon d'un fichier something.d.cmo est something.cmi et non something.d.cmi.

Mli et cmi dérivés de fichiers d'implémentation

La compilation des implémentations de modules change en présence de fichiers mli et cmi, les fonctions ci-dessous aident à gérer cela.

val mli_from_source : t -> filename

mli_from_source u est le nom du fichier source de l'interface associé à l'unité u. Le suffixe réel dépend de Config.interface_suffix.

val mli_from_artifact : Artifact.t -> filename

mli_from_artifact t est le nom du fichier source de l'interface dérivé de l'artefact t. Cette variante est nécessaire lors de la gestion d'artefacts dérivés de fichiers sources inconnus (par exemple, modules packés).

val is_cmi : Artifact.t -> bool

Vérifie si l'artefact est un cmi.

val find_normalized_cmi : t -> Artifact.t

find_normalized_cmi u trouve dans le load_path un fichier correspondant au nom du module modname u.

Raises Not_found si aucun cmi correspondant n'existe.
