DÉTAILS

Le Format de l'Archiveur Texte Brut

Noms de classe simplifiés

Il y a trop de travail pour spécifier des noms de classe complets à chaque endroit où vous souhaitez créer un nouvel objet avec des données. C'est pourquoi les abréviations sont introduites. Utilisez new(abréviations) ou abréviations() pour ajouter des abréviations supplémentaires ou pour en remplacer certaines prédéfinies.

Noms prédéfinis :
user User::Identity
email Mail::Identity
location User::Identity::Location
system User::Identity::System
list User::Identity::Collection::Emails

Il aurait été plus agréable de faire référence à une personne plutôt qu'à un utilisateur, mais cela aurait ajouté à la confusion avec l'espace de noms.

L'indentation dit tout

La syntaxe est aussi simple que possible. Une indentation supplémentaire sur une ligne signifie que la variable ou la classe est une collection au sein de la classe sur la ligne précédente.

user markov
  location home
     country NL
  email home
     address  mark@overmeer.net
     location home
  email work
     address  solutions@overmeer.bet
email tux
   address tux@fish.net

Ce qui précède définit deux éléments : un User::Identity nommé "markov", et une adresse e-mail "tux". L'utilisateur a deux collections : l'une contient une seule localisation, et l'autre stocke deux adresses e-mail.

Pour ajouter à la confusion : la "location" est définie comme un champ dans "email" et comme une collection. La différence est facilement détectable : s'il y a des champs indentés suivant la ligne, c'est une collection. Les erreurs entraîneront dans la plupart des cas un message d'erreur.

Lignes longues

Si vous souhaitez continuer sur la ligne suivante, car votre contenu est trop volumineux, ajoutez une barre oblique inverse à la fin, comme ceci :

email home
   description Ceci est mon adresse personnelle,     \
               Mais j'utilise aussi celle-ci pour \
               le travail
   address tux@fish.aq

Les continuations ne jouent pas le jeu de l'indentation, vous pouvez donc aussi faire :

email home
   description               \
Ceci est mon adresse personnelle,     \
Mais j'utilise aussi celle-ci pour

User::Identity::Archive::Plain(3pm) — Arch Linux

NAME

User::Identity::Archive::Plain - extension to read/write plain user identity files

INHERITANCE

 User::Identity::Archive::Plain
   is a User::Identity::Archive

SYNOPSIS

 use User::Identity::Archive::Plain;
 my $archive = User::Identity::Archive::Plain->new(
     file => $filename,
 );
 my $found = $archive->get($user_id);
 $archive->put($user_id, $data);
 $archive->remove($user_id);

DESCRIPTION

This extension provides access to plain text user identity files. These files are used by User::Identity to store user information. The format is simple and very similar to the passwd(5) file format.

A user identity file contains a list of user definitions. Each user definition is a list of named properties, which are key-value pairs.

The properties can be organized in groups. The first property on a line must be the name of the property. Values follow after blanks. Multi-line values are indented.

Example:

# my own entry
user me
   email   me@myself.org
   location home
      address 1.st street
      zipcode 12345
   email work
      address me@work.org
      # note that this is a comment

In this example, the user "me" has a property "email" which is a list of two addresses. It also has a property "location" which has two sub-properties "address" and "zipcode". The "work" email address has a comment line.

A definition of a user starts with the keyword "user" followed by the user identifier. All subsequent lines which start with blanks are part of the definition of the user. All subsequent lines which start with a keyword are the start of a new property. A line starting with "user" again starts a new user definition.

user me
   email   me@myself.org
user you
   email   you@myself.org

If a line does not start with blanks, it means the end of the current definition. It could be the start of a new user definition or something else.

You can group properties. For example, you can define multiple email addresses for the same user.

user me
   email
      work   me@work.org
      home   me@home.org

This example defines a user "me" with property "email" which has two sub-properties "work" and "home".

The User::Identity package uses this archive to store and retrieve user information. The mapping is direct: A property "email" becomes a key "email" in the hash which is returned for the user.

# Example of a User::Identity object
my $id = User::Identity->new;
my $user = $id->get('me');
print $user->{email}->{work}; # prints me@work.org

The archive handles the storage. The new() constructor takes optional arguments:

file
The name of the file to read from or write to.
separator
The character used to separate properties and values. Defaults to space. If you use tabs, they will be translated to spaces when written.
comment
The character used to start a comment line. Defaults to '#'.
indentchar
The character used for indentation. Defaults to space. If you use tabs, they will be translated to spaces when written.
userspace
When true, lines starting with "user" are parsed as new users. This is the default.

The methods User::Identity calls are:

get( $user_id )
Read the definition for $user_id from the file. Returns a hash reference with the user properties.
put( $user_id, $data )
Write the user definition $data to the file $user_id. $data must be a hash reference.
remove( $user_id )
Remove the definition for $user_id from the file.
list()
Return a list of all user identifiers found in the file.

Example:

use User::Identity::Archive::Plain;
my $archive = User::Identity::Archive::Plain->new(file => 'users.txt');

# Get user 'markov'
my $user = $archive->get('markov');
print $user->{email}->{work};

# Add a new user
my $new_user_data = {
    email => {
        home => 'markov@overmeer.net',
    },
    location => {
        home => 'The Netherlands',
    },
};
$archive->put('markov', $new_user_data);

# List all users
my @users = $archive->list;
foreach my $uid (@users) {
    print "$uid\n";
}

The file format is flexible. You can mix comments, blank lines and real data. Lines starting with the comment character are ignored.

user tux
   # this is a comment
   # and another one
   email home
      address tux@fish.aq
   email work
      address tux@work.fish.aq
      # work address configuration
      priority 10
   # this is the end of tux definition
user admin
   email work
      address admin@fish.aq
   home
      address home.tux.fish.aq

Lines starting with blanks are indented. The indentation defines the structure. The archive object will automatically create the nested hash structure.

The put() method takes a hash reference. The keys of the hash reference are the property names. If the value is another hash reference, it is treated as a sub-property.

# User definition
user markov
   # email property with subproperties work and home
   email
      work   markov@work.overmeer.net
      home   markov@home.overmeer.net
   # location property with subproperties work and home
   location
      work   Amsterdam
      home   The Netherlands

The parser understands indentation. You can use tabs or spaces for indentation. The actual file written will use spaces. The number of spaces used for each indentation level is determined by the indentchar parameter (default 1 space) and the tabstop parameter (default 8).

If you want to store a value that contains the separator character, you can quote the value.

user me
   address "123 Main St, Anytown"

The archive will store the value literally. When reading, quotes are removed.

If a value needs to span multiple lines, you can use indentation:

user me
   comment
      This is a multi-line
      comment describing the user.
      It is indented by one level.

The put() method does not overwrite the file. It first reads the entire file, modifies the data in memory, and then writes the whole file back. This means that concurrent modifications can lead to race conditions.

If the file does not exist, it will be created upon the first put() or remove() operation. If you want to explicitly create the file, you can add an empty user entry:

user empty

A special user name "*" can be used to store default values for all users. These values are inherited by all other users, unless they override them.

user *
   location default
      country The Netherlands
user me
   # inherits default country
   location home
      address 1.st street
      zipcode 12345

This means that $user->{location}->{country} will be "The Netherlands" for user "me".

The file format itself is a subset of the features of the User::Identity module. It is simple and designed to be easily human-readable and editable.

OVERLOADED

None.

METHODS

See User::Identity::Archive for methods that are inherited and not documented here.

new ( %options )
Creates a new User::Identity::Archive::Plain object. The following options are supported:
   file       # filename to use
   separator  # field separator (default space)
   comment    # comment character (default '#')
   indentchar # indentation character (default space)
   userspace  # boolean, default true
get ( $uid )
Returns the user data for $uid as a hash reference.
put ( $uid, \%data )
Stores the user data \%data for user $uid in the archive file.
remove ( $uid )
Removes the user definition for $uid from the archive file.
list ( )
Returns a list of all user identifiers stored in the archive.

DETAILS

The archive file is a plain text file. Lines starting with '#' are comments. Blank lines are ignored. Lines starting with 'user' introduce a new user entry.

user tux
   email home
      address tux@fish.aq

The fields "comment" and "address" must be correctly indented. The line terminations are lost, which is useful for most fields. However, if you need them, you have to check the description of the applicable field.

Comments

You may add comments and white spaces. Comments start with a '#' as first non-blank character on the line. Comments are not allowed on the same line as real data, as some languages (like Perl) permit.

You can insert comments and blank lines on all places where you need them:

user markov
   # my home address
   email home
      # useless comment statement
      address tux@fish.aq
      location #mind_the_hash

is equivalent to:

user markov
   email home
      address tux@fish.aq
      location #mind_the_hash

References

Often you will have the need to add the same information to two items, for instance, multiple people share the same address. In this case, you can create a reference. However, this is only permitted for whole items: you can refer to someone's location, but not to the person's street.

To create a reference to an item of someone else, use

user markov
   location home = user(cleo).location(home)
   location work
      organization   MARKOV Solutions

Configuration parameters

You can add some configuration lines as well. On the moment, the only one defined is

tabstop = 4

which can be used to change the meaning of tabs in the file. The default setting is 8, but some people prefer 4 (or other values).

DIAGNOSTICS

Error: $object is not a collection.
The first argument is an object, but not of a class which extends User::Identity::Collection. Cast by addCollection()
Error: Cannot load collection module for $type ($class).
Either the specified $type does not exist, or that module named $class returns compilation errors. If the type as specified in the warning is not the name of a package, you specified a nickname which was not defined. Maybe you forgot the 'require' the package which defines the nickname. Cast by addCollection()
Warning: Cannot read archive from $source
Cast by from()
Error: Creation of a collection via $class failed.
The $class did compile, but it was not possible to create an object of that class using the options you specified. Cast by addCollection()
Error: Don't know what type of collection you want to add.
If you add a collection, it must either by a collection object or a list of options which can be used to create a collection object. In the latter case, the type of collection must be specified. Cast by addCollection()
Warning: No collection $name
The collection with $name does not exist and can not be created. Cast by add()
