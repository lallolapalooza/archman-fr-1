Unicode::Stringprep(3pm) Documentation Perl fournie par l'utilisateur Unicode::Stringprep(3pm)

NOM

Unicode::Stringprep - Préparation des chaînes internationalisées (RFC 3454)

SYNOPSIS

use Unicode::Stringprep;
use Unicode::Stringprep::Mapping;
use Unicode::Stringprep::Prohibited;
my $prepper = Unicode::Stringprep->new(
  3.2,
  [ { 32 => '<ESPACE>'},  ],
  'KC',
  [ @Unicode::Stringprep::Prohibited::C12, @Unicode::Stringprep::Prohibited::C22,
    @Unicode::Stringprep::Prohibited::C3, @Unicode::Stringprep::Prohibited::C4,
    @Unicode::Stringprep::Prohibited::C5, @Unicode::Stringprep::Prohibited::C6,
    @Unicode::Stringprep::Prohibited::C7, @Unicode::Stringprep::Prohibited::C8,
    @Unicode::Stringprep::Prohibited::C9 ],
  1, 0 );
$output = $prepper->($input)

DESCRIPTION

Ce module implémente le framework stringprep pour préparer les chaînes de texte Unicode afin d'augmenter la probabilité que l'entrée de chaînes et la comparaison de chaînes fonctionnent d'une manière qui a du sens pour les utilisateurs typiques du monde entier. Le protocole stringprep est utile pour les valeurs d'identificateurs de protocole, les noms d'entreprises et de personnes, les noms de domaine internationalisés et d'autres chaînes de texte.

Le framework stringprep ne spécifie pas comment les protocoles doivent préparer les chaînes de texte. Les protocoles doivent créer des profils de stringprep afin de spécifier entièrement les options de traitement.

FONCTIONS

Ce module fournit une seule fonction, "new", qui crée une fonction perl implémentant un profil stringprep.

Ce module n'exporte rien.

new($version_unicode, $tables_mappage, $normalisation_unicode, $tables_interdites, $verif_bidi, $verif_non_assigne)
Crée une référence de fonction "bless"ée qui implémente un profil stringprep.

Cette fonction prend les paramètres suivants :

$version_unicode
La version Unicode spécifiée par le profil stringprep.

Actuellement, ce paramètre doit être 3.2 (numérique).

$tables_mappage
Les tables de mappage utilisées pour stringprep.

Le paramètre peut être une référence à un hachage ou à un tableau, ou "undef". Un hachage doit mapper des points de code Unicode (en tant qu'entiers, par ex. 0x0020 pour U+0020) à des chaînes de remplacement (en tant que chaînes perl). Un tableau peut contenir des paires de points de code Unicode et de chaînes de remplacement ainsi que des références à des hachages et des tableaux imbriqués.

Unicode::Stringprep::Mapping fournit les tables de la RFC 3454, Annexe B.

Pour plus d'informations sur l'étape de mappage, voir la RFC 3454, section 3.

$normalisation_unicode
La normalisation Unicode à utiliser.

Actuellement, "undef"/'' (aucune normalisation) et 'KC' (composé de compatibilité) sont spécifiés pour stringprep.

Pour plus d'informations sur l'étape de normalisation, voir la RFC 3454, section 4.

La forme de normalisation KC activera également les vérifications pour certaines séquences problématiques pour lesquelles la normalisation ne peut pas être implémentée de manière interopérable.

Pour plus d'informations, voir "ATTENTION" ci-dessous.

$tables_interdites
La liste des caractères de sortie interdits pour stringprep.

Le paramètre peut être une référence à un tableau, ou "undef". Le tableau contient des paires de points de code, qui définissent le début et la fin d'une plage de caractères Unicode (en tant qu'entiers). Le caractère de fin peut être "undef", spécifiant une plage d'un seul caractère. Le tableau peut également contenir des références à des tableaux imbriqués.

Unicode::Stringprep::Prohibited fournit les tables de la RFC 3454, Annexe C.

Pour plus d'informations sur l'étape de vérification des interdictions, voir la RFC 3454, section 5.

$verif_bidi
Indique s'il faut employer des vérifications pour un texte bidirectionnel confus. Une valeur booléenne.

Pour plus d'informations sur l'étape de vérification bidi, voir la RFC 3454, section 6.

$verif_non_assigne
Indique s'il faut vérifier et interdire les caractères non assignés. Une valeur booléenne.

La vérification doit être utilisée lors de la création de chaînes *stockées*. Elle ne doit pas être utilisée pour les chaînes de *requête*, augmentant ainsi la probabilité que les caractères nouvellement assignés fonctionnent comme prévu.

Pour plus d'informations sur les chaînes *stockées* et de *requête*, voir la RFC 3454, section 7.

La fonction retournée peut être appelée avec un seul paramètre, la chaîne à préparer, et retourne la chaîne préparée. Elle mourra si la chaîne d'entrée ne peut pas être préparée avec succès car elle contiendrait une sortie invalide (utilisez donc "eval" si nécessaire).

Pour des raisons de performance, il est fortement recommandé d'appeler la fonction "new" aussi peu de fois que possible, c'est-à-dire exactement une fois par profil stringprep. Il pourrait également être préférable de ne pas utiliser ce module directement mais d'utiliser (ou d'écrire) un module implémentant un profil, tel que Authen::SASL::SASLprep.

IMPLÉMENTATION DES PROFILS

Vous pouvez facilement implémenter un profil stringprep sans sous-classe :

package ACME::ExamplePrep;
use Unicode::Stringprep;
use Unicode::Stringprep::Mapping;
use Unicode::Stringprep::Prohibited;
*exampleprep = Unicode::Stringprep->new(
  3.2,
  [ \@Unicode::Stringprep::Mapping::B1, ],
  '',
  [ \@Unicode::Stringprep::Prohibited::C12,
    \@Unicode::Stringprep::Prohibited::C22, ],
  1,
);

Cela lie "ACME::ExamplePrep::exampleprep" à la fonction créée par "Unicode::Stringprep->new".

Généralement, il n'est pas nécessaire de sous-classer ce module. La sous-classe de ce module n'est pas recommandée.

CAVEATS

Dans Unicode 3.2 à 4.0.1, la spécification d'UAX #15 : Formes de normalisation Unicode pour les formes NFC et NFKC n'est pas logiquement autoconsistante. Ceci a été corrigé dans le rectificatif #5 (http://unicode.org/versions/corrigendum5.html).

NAME

Unicode::Stringprep - Perl module for string preparation as specified by RFC 3454

SYNOPSIS

    use Unicode::Stringprep;

    my $ustr = Unicode::Stringprep->new();
    my $prepared = $ustr->prepare("string to prepare", "nameprep");

DESCRIPTION

This module implements the string preparation algorithm as specified by RFC 3454 (Internationalizing Domain Names in Applications (IDNA) and other protocols).

RFC 3454 defines a framework for preparing strings for comparison. It consists of a set of steps that transform a string into a canonical form, which can then be used for comparisons.

The preparation process involves several steps:

  • Normalization: The string is first normalized according to the Unicode Normalization Form (e.g., NFC or NFKC).

  • Mapping: Certain characters are mapped to other characters or sequences of characters based on predefined tables (e.g., case folding).

  • Prohibiting: Certain characters are prohibited and will cause the preparation to fail if present.

  • First-Ucharacter-Reference: This step handles Unicode characters that have a first-U character reference property.

  • Bidirectional (Bidi) properties: This step handles Unicode bidirectional characters.

  • Trailing- and Leading-Space-and-Control-Characters: This step removes trailing and leading spaces and control characters.

FUNCTIONS

Unicode::Stringprep->new()
Creates a new Unicode::Stringprep object.
$ustr->prepare($string, $profile)`
Prepares the given string according to the specified profile. Supported profiles include:
        nameprep (RFC 3491)
        i-d46-ldap (RFC 4518)
        i-d46-email (RFC 5891)

The profile is a string specifying the preparation algorithm to use. If the profile is not recognized, the method will throw an error.

IMPLEMENTING PROFILES

This module implements the following profiles from RFC 3454:

nameprep
As specified in RFC 3491, Section 5.
i-d46-ldap
As specified in RFC 4518, Section 5.
i-d46-email
As specified in RFC 5891, Section 4.

DATA TABLES

This module uses data tables derived from the Unicode Character Database (UCD) and RFC 3454.

CAVEATS

The Unicode standard defines certain characters that are disallowed in strings prepared with specific profiles. For example, non-characters and characters with the Bidi_Control property are disallowed in the nameprep profile.

Additionally, Unicode 4.1 introduced a set of characters that are disallowed in strings prepared with nameprep and i-d46-ldap. These are characters that have the NFKC_Closure property, and are not already disallowed by other rules. This is to prevent certain forms of denial-of-service attacks.

See http://unicode.org/reports/tr15/#Stability_Prior_to_Unicode41 for details.

This module will check for these strings and, if normalization is done, prohibit them in output as it is not possible to interoperate under these circumstandes.

Please note that due to this, the normalization step may cause the preparation to fail. That is, the preparation function may die even if there are no prohibited characters and no checks for bidi sequences and unassigned characters, which may be surprising.
