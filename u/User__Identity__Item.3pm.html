NOM

User::Identity::Item - classe de base générale pour User::Identity

HÉRITAGE

User::Identity::Item est étendu par
  Mail::Identity
  User::Identity
  User::Identity::Archive
  User::Identity::Collection
  User::Identity::Location
  User::Identity::System

SYNOPSIS

DESCRIPTION

La classe de base "User::Identity::Item" est étendue en modules utiles : elle n'a pas d'usage par elle-même.

MÉTHODES

Constructeurs

$classe->new( [$nom], %options )
-Option     --Défaut
 description  undef
 name         <requis>
 parent       undef
description => CHAÎNE
Description en format libre de l'élément collecté.
name => CHAÎNE
Un nom simple pour cet élément. Essayez de donner un nom utile dans le contexte du temps de l'élément. Chaque fois que vous recherchez des éléments, vous devez spécifier ce nom, donc il doit être unique et pas trop difficile à gérer dans votre programme. Par exemple, lorsqu'une personne est adressée, vous lui donnerez généralement ce surnom.
parent => OBJET
L'objet encapsulant : l'objet qui collecte celui-ci.

Attributs

$obj->description()
Description en format libre de cet élément. Veuillez ne pas donner de signification particulière au contenu de ce champ : si vous avez besoin d'un attribut supplémentaire, veuillez contacter l'auteur du module pour l'implémenter, ou étendre l'objet pour répondre à vos besoins.
$obj->name( [$nouveau_nom] )
Le nouveau nom de cet élément. Les noms sont uniques au sein d'une collection... un deuxième objet portant le même nom dans une collection détruira l'objet existant portant ce nom.

Changer le nom d'un élément est assez dangereux. Vous voudrez probablement appeler User::Identity::Collection::renameRole() à la place.

Collections

$obj->add($collection, $role)
Le $role est ajouté à la $collection. La $collection est le nom d'une collection, qui sera créée automatiquement avec addCollection() si nécessaire. La $collection peut également être spécifiée comme un objet de collection existant.

Le $role est tout ce qui est acceptable pour User::Identity::Collection::addRole() de la collection en question, et est retourné. $role est typiquement une liste de paramètres pour un rôle, ou une référence à un tableau contenant ces valeurs.

» exemple :

my $ui   = User::Identity->new(...);
my $home = $ui->add(location => [home => street => '27 Roadstreet', ...] );
my $work = $ui->add(location => work, tel => '+31-2231-342-13', ... );
my $travel = User::Identity::Location->new(travel => ...);
$ui->add(location => $travel);
my $system = User::Identity::Collection::System->new(...);
$ui->add($system => 'localhost');
$obj->addCollection( $objet | <[$type], %options> )
Ajoute une nouvelle collection de rôles à un élément. Cela peut être réalisé de deux manières : soit créer un objet User::Identity::Collection $objet vous-même, puis le passer à cette méthode, soit fournir toutes les %options nécessaires pour créer un tel objet et il sera créé pour vous. L'objet qui est ajouté est retourné, et peut être utilisé directement pour de nombreuses méthodes.

Pour les %options, voir le type spécifique de collection. Les options supplémentaires sont listées ci-dessous.

-Option--Défaut
 type    <requis>
type => CHAÎNE|CLASSE
Le nom de code d'une classe de collection ou le nom de CLASSE lui-même de l'objet à créer. Requis si un objet doit être créé. Les noms de type prédéfinis sont "email", "system" et "location".

» exemple :

my $me   = User::Identity->new(...);
my $locs = User::Identity::Collection::Locations->new();
$me->addCollection($locs);
my $email = $me->addCollection(type => 'email');
my $email = $me->addCollection('email');
$obj->collection($nom)
En contexte scalaire, l'objet de collection avec le $nom est retourné. En contexte liste, tous les rôles au sein de la collection sont retournés.

» exemple :

my @roles = $me->collection('email');        # liste des éléments collectés
my @roles = $me->collection('email')->roles; # idem pour les éléments collectés
my $coll  = $me->collection('email');        # une User::Identity::Collection
$obj->parent( [$parent] )
Retourne le parent d'un Élément (l'élément englobant). Ceci peut retourner "undef" si l'objet est autonome.
$obj->removeCollection($objet|$nom)
$any->type()
Retourne un nom symbolique agréable pour le type.
$obj->user()
Va de cet objet à son parent, puis à son parent, et ainsi de suite, jusqu'à ce qu'un User::Identity soit trouvé ou que le sommet de l'arbre des objets ait été atteint.

» exemple :

print $email->user->fullName;

Recherche

$obj->find($collection, $role)
Retourne l'objet avec le $role spécifié dans la collection nommée. La collection peut être spécifiée comme nom ou objet.

» exemple :

my $role  = $me->find(location => 'work');       # une localisation
my $role  = $me->collection('location')->find('work'); # idem
my $email = $me->addCollection('email');
$me->find($email => 'work');
$email->find('work');   # idem

DIAGNOSTICS

Erreur: $objet n'est pas une collection.
Le premier argument est un objet, mais pas d'une classe qui étend User::Identity::Collection. Appel via addCollection()
Erreur: Impossible de charger le module de collection pour $type ($classe).
Soit le $type spécifié n'existe pas, soit ce module nommé $classe retourne des erreurs de compilation. Si le type tel que spécifié dans l'avertissement n'est pas le nom d'un paquet, vous avez spécifié un nom de code qui n'était pas défini. Peut-être avez-vous oublié le 'require' du paquet qui définit le nom de code. Appel via addCollection()
Erreur: La création d'une collection via $classe a échoué.
La $classe a compilé, mais il n'a pas été possible de créer un objet de cette classe en utilisant les options que vous avez spécifiées. Appel via addCollection()
Erreur: Je ne sais pas quel type de collection vous voulez ajouter.
Si vous ajoutez une collection, cela doit être soit un objet de collection, soit une liste d'options qui peuvent être utilisées pour créer un objet de collection. Dans ce dernier cas, le type de collection doit être spécifié. Appel via addCollection()
Erreur: Chaque élément requiert un nom
Vous devez spécifier un nom pour chaque élément. Ces noms doivent être uniques au sein d'une collection, mais n'hésitez pas à donner le même nom à une adresse e-mail et à une localisation. Appel via
