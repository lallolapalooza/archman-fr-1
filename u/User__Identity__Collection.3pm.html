NOM

User::Identity::Collection - classe de base pour la collecte des rôles d'un utilisateur

HÉRÉDITÉ

User::Identity::Collection
  est un User::Identity::Item
User::Identity::Collection est étendu par
  User::Identity::Collection::Emails
  User::Identity::Collection::Locations
  User::Identity::Collection::Systems
  User::Identity::Collection::Users

SYNOPIS

use User::Identity;
use User::Identity::Collection;
my $moi    = User::Identity->new(...);
my $set    = User::Identity::Collection::Emails->new(...);
$moi->addCollection($set);
# Plus simple
use User::Identity;
my $moi    = User::Identity->new(...);
my $set    = $moi->addCollection(type => 'email', ...)
my $set    = $moi->addCollection('email', ...)
my @roles  = $moi->collection('email');  # liste des éléments collectés
my $coll   = $moi->collection('email');  # un User::Identity::Collection
my @roles  = $coll->roles;
my @roles  = @$coll;                    # idem, par surcharge
my $role   = $moi->collection('email')->find($coderef);
my $role   = $moi->collection('location')->find('work');
my $role   = $moi->find(location => 'work');

DESCRIPTION

L'objet "User::Identity::Collection" maintient un ensemble d'objets liés à l'utilisateur. Il aide à sélectionner ces objets, ce qui est partiellement commun à toutes les collections (par exemple, chaque objet a un nom donc vous pouvez rechercher par nom), et parfois spécifique à l'extension de cette collection.

Les extensions actuellement implémentées sont

  • people est une collection d'utilisateurs
  • whereabouts sont des lieux
  • une mailinglist est une

    collection d'adresses email

  • un network contient

    des groupes de systèmes

Étend "DESCRIPTION" dans User::Identity::Item.

SOBRECHARGE

surcharge : "" conversion en chaîne
Retourne le nom de la collection et une liste triée des éléments définis.

» exemple :

print "$collection\n";  #   location: home, work
surcharge : @{} déréférencement de tableau
Lorsque la référence à un objet de collection est utilisée comme référence de tableau, elle sera présentée comme une liste de rôles.

» exemple :

my $locations = $ui->collection('location');
foreach my $loc (@$location) ...
print $location->[0];

Maintien des rôles

$obj->addRole($role|([$name], %options))
Ajoute un nouveau rôle à cette collection. $role est un objet du type approprié (ce type dépend de l'extension de ce module) ou une liste de %options utilisées pour créer un tel rôle. Les options peuvent également être passées sous forme de référence à un ARRAY. Le rôle ajouté est retourné.

» exemple :

my $uicl = User::Identity::Collection::Locations->new;
my $uil  = User::Identity::Location->new(home => ...);
$uicl->addRole($uil);
$uicl->addRole(  home => address => 'rue 32' );
$uicl->addRole( [home => address => 'rue 32'] );

Plus simple

$ui      = User::Identity;
$ui->add(location => 'home', address => 'rue 32' );
$ui->add(location => [ 'home', address => 'rue 32' ] );
$obj->removeRole($role|$name)
Le rôle supprimé est retourné (s'il existait).
$obj->renameRole( <$role|$ancien_nom>, $nouveau_nom )
Donne un nom différent au rôle et le déplace dans la collection.
$obj->sorted()
Retourne les rôles triés par nom, alphabétiquement et en respectant la casse.

Recherche

Étend "Searching" dans User::Identity::Item.

$obj->find($name|CODE|undef)
Trouve l'objet avec le $name spécifié dans cette collection. Avec "undef", un rôle sélectionné aléatoirement est retourné.

Lorsqu'une référence de code est spécifiée, tous les rôles collectés sont parcourus un par un (dans un ordre inconnu). Pour chaque rôle,

CODE->($object, $collection)

est appelé. Lorsque le "CODE" retourne "true", le rôle est sélectionné. En contexte de liste, tous les rôles sélectionnés sont retournés. En contexte scalaire, la première correspondance est retournée et le parcours est immédiatement interrompu. Améliore la base, voir "Searching" dans User::Identity::Item

» exemple :

my $emails = $ui->collection('emails');
$emails->find('work');
sub find_work($$) {
   my ($mail, $emails) = @_;
   $mail->location->name eq 'work';
}
my @at_work = $emails->find(\&find_work);
my @at_work = $ui->find(location => \&find_work);
my $any     = $ui->find(location => undef );

DIAGNOSTICS

Erreur : $objet n'est pas une collection.
Le premier argument est un objet, mais pas d'une classe qui étend User::Identity::Collection. Appel par addCollection()
Erreur : impossible de créer un $type pour l'ajouter à ma collection.
Certaines options sont spécifiées pour créer un objet $type , qui est natif à cette collection. Cependant, pour une raison quelconque, cela a échoué. Appel par addRole()
Erreur : impossible de charger le module de collection pour $type ($class).
Soit le $type spécifié n'existe pas, soit le module nommé $class renvoie des erreurs de compilation. Si le type tel que spécifié dans l'avertissement n'est pas le nom d'un package, vous avez spécifié un surnom qui n'était pas défini. Peut-être avez-vous oublié le 'require' du package qui définit le surnom. Appel par addCollection()
Erreur : impossible de renommer $name en $newname : existe déjà
Appel par renameRole()
Erreur : impossible de renommer $name en $newname : n'existe pas
Appel par renameRole()
Erreur : la création d'une collection via $class a échoué.
Le $class a été compilé, mais il n'a pas été possible de créer un objet de cette classe en utilisant les options que vous avez spécifiées. Appel par addCollection()
Erreur : je ne sais pas quel type de collection vous voulez ajouter.
Si vous ajoutez une collection, il doit s'agir soit d'un objet collection, soit d'une liste d'options qui peuvent être utilisées pour créer un objet collection. Dans ce dernier cas, le type de collection doit être spécifié. Appel par addCollection()
Avertissement : Pas de collection $name
La collection avec $name n'existe pas et ne peut pas être créée. Appel par add()
Erreur : mauvais type de rôle pour $collection : attend un $expect mais a obtenu un $type
Chaque $collection regroupe des ensembles de rôles d'un type spécifique ($expect). Vous ne pouvez pas ajouter des objets d'un $type différent. Appel par addRole()
