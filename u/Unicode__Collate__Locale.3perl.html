Unicode::Collate::Locale(3perl) Guide de référence du programmeur Perl Unicode::Collate::Locale(3perl)

NOM

Unicode::Collate::Locale - Adaptation linguistique pour DUCET via Unicode::Collate

SYNOPSIS

use Unicode::Collate::Locale;
# construction
$Collator = Unicode::Collate::Locale->
    new(locale => $nom_locale, %adaptation);
# tri
@triés = $Collator->sort(@non_triés);
# comparaison
$resultat = $Collator->cmp($a, $b); # retourne 1, 0 ou -1.

Note : Les chaînes dans @non_triés, $a et $b sont interprétées conformément au support Unicode de Perl. Voir perlunicode, perluniintro, perlunitut, perlunifaq, utf8. Sinon, vous pouvez utiliser "preprocess" (cf. "Unicode::Collate") ou les décoder au préalable.

DESCRIPTION

Ce module fournit une adaptation linguistique pour tirer parti de "Unicode::Collate".

Constructeur

La méthode "new" renvoie un objet collateur.

Une liste de paramètres pour le constructeur est une table de hachage, qui peut inclure une clé spéciale "locale" et sa valeur (insensible à la casse) représentant un code de langue de base Unicode (à deux ou trois lettres). Par exemple, "Unicode::Collate::Locale->new(locale => 'ES')" renvoie un collateur adapté pour l'espagnol.

$nom_locale peut être suffixé d'un code de script Unicode (quatre lettres), d'un code de région (territoire) Unicode, d'un code de variante linguistique Unicode. Ces codes sont insensibles à la casse et séparés par '_' ou '-'. Par exemple, "en_US" pour l'anglais aux États-Unis, "az_Cyrl" pour l'azéri en script cyrillique, "es_ES_traditional" pour l'espagnol d'Espagne (traditionnel).

Si $nom_locale n'est pas disponible, un mécanisme de repli est sélectionné dans l'ordre suivant :

1. langue avec un code de variante
2. langue avec un code de script
3. langue avec un code de région
4. langue
5. défaut

Les balises d'adaptation fournies par "Unicode::Collate" sont autorisées tant qu'elles ne sont pas utilisées pour le support de "locale". Notamment, la balise "table" n'est jamais adaptable, car elle est réservée à DUCET.

Cependant, "entry" est autorisé, même s'il est utilisé pour le support de "locale", pour ajouter ou remplacer des mappages.

Par exemple, un collateur pour l'espagnol, qui ignore les diacritiques et la différence de casse (c'est-à-dire niveau 1), avec un ordre de casse inversé et aucune normalisation.

Unicode::Collate::Locale->new(
    level => 1,
    locale => 'es',
    upper_before_lower => 1,
    normalization => undef
)

Le remplacement d'un comportement déjà adapté par "locale" est interdit si une telle adaptation est passée à new().

Unicode::Collate::Locale->new(
    locale => 'da',
    upper_before_lower => 0, # provoque une erreur car réservé par 'da'
)

Cependant, change(), hérité de "Unicode::Collate", permet une telle adaptation qui est réservée par "locale". Exemples :

new(locale => 'fr_ca')->change(backwards => undef)
new(locale => 'da')->change(upper_before_lower => 0)
new(locale => 'ja')->change(overrideCJK => undef)

Méthodes

"Unicode::Collate::Locale" est une sous-classe de "Unicode::Collate" et les méthodes autres que "new" sont héritées de "Unicode::Collate".

Voici une liste de méthodes supplémentaires :

"$Collator->getlocale"
Retourne un code de langue accepté et réellement utilisé pour la collation. Si aucune adaptation linguistique n'est fournie pour un code de langue que vous avez passé (intentionnellement pour certaines langues, ou en raison d'une implémentation incomplète), cette méthode renvoie la chaîne 'default', signifiant aucune adaptation spéciale.
"$Collator->locale_version"
(Depuis Unicode::Collate::Locale 0.87) Retourne le numéro de version (peut-être "/\d\.\d\d/") de la locale, comme celle de Locale/*.pl.

Note : Locale/*.pl qu'un collateur utilise doit être identifié par une combinaison des valeurs de retour de "getlocale" et "locale_version".

Note

[1] ja: Les idéogrammes sont triés selon l'ordre JIS X 0208. Les formes pleine chasse et demi-chasse sont identiques à leur forme régulière. La différence entre hiragana et katakana se situe au 4ème niveau, la comparaison nécessite également "(variable => 'Non-ignorable')", et ensuite "katakana_before_hiragana" n'a aucun effet.

[2] ko: De nombreux idéogrammes sont triés par leur lecture. Un tel idéogramme est primaire (niveau 1) égal, et secondaire (niveau 2) supérieur, à la syllabe hangul correspondante.

[3] zh__pinyin, zh__stroke et zh__zhuyin: implémenté alt='short', où un plus petit nombre d'idéogrammes sont adaptés.

INSTALLATION

L'installation de "Unicode::Collate::Locale" nécessite Collate/Locale.pm, Collate/Locale/*.pm, Collate/CJK/*.pm et Collate/allkeys.txt. Lors de la construction, "Unicode::Collate::Locale" ne nécessite aucun de data/*.txt, gendata/*, et mklocale. Les tests pour "Unicode::Collate::Locale" sont nommés t/loc_*.t.

MISE EN GARDE

L'adaptation n'est pas maximale
Même si une certaine lettre est adaptée, son équivalent ne le sera pas toujours autant. Par exemple, même si W est adapté, W pleine chasse ("U+FF37"), W avec accent aigu ("U+1E82"), etc., ne sont pas adaptés. Le résultat peut dépendre du fait que les chaînes sources soient normalisées ou non, et décomposées ou composées. Ainsi "(normalization => undef)" est moins préférable.
Le réordonnancement de la collation n'est pas supporté
L'ordre d'aucun groupe, y compris les scripts, n'est modifié.
