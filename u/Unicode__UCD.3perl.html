DESCRIPTION

Le module Unicode::UCD offre une série de fonctions qui fournissent une interface simple à la base de données des caractères Unicode.

Argument point de code

Certaines fonctions sont appelées avec un argument point de code, qui est soit un scalaire décimal ou hexadécimal désignant un point de code dans le jeu de caractères natif de la plateforme (étendu à Unicode), soit une chaîne contenant "U+" suivi d'hexadécimaux désignant un point de code Unicode. Un 0 initial forcera une interprétation hexadécimale, tout comme un chiffre hexadécimal qui n'est pas un chiffre décimal.

Exemples :

223     # Décimal 223 dans le jeu de caractères natif
0223    # Hexadécimal 223, natif (= 547 décimal)
0xDF    # Hexadécimal DF, natif (= 223 décimal)
'0xDF'  # Forme chaîne de l'hexadécimal (= 223 décimal)
'U+DF'  # Hexadécimal DF, dans le jeu de caractères d'Unicode
                          (= LETTRE MINUSCULE LETTRE SHARP S)

Notez que le plus grand point de code dans Unicode est U+10FFFF.

charinfo()

use Unicode::UCD 'charinfo';
my $charinfo = charinfo(0x41);

Ceci retourne des informations sur l'"argument point de code" d'entrée sous forme de référence à un hash des champs tels que définis par la norme Unicode. Si l'"argument point de code" n'est pas assigné dans la norme (c'est-à-dire qu'il a la catégorie générale "Cn" signifiant "Non attribué") ou est un non-caractère (ce qui signifie qu'il est garanti de ne jamais être attribué dans la norme), "undef" est retourné.

Les champs qui ne sont pas applicables au point de code d'entrée existant dans le hash retourné, sont vides.

Pour des résultats moins "bruts" que ce que cette fonction retourne, ou pour obtenir les valeurs de n'importe quelle propriété, pas seulement celles couvertes par cette fonction, utilisez la fonction "charprop()".

Les clés du hash avec la signification de leurs valeurs sont :

code
l'argument point de code natif d'entrée exprimé en hexadécimal, avec des zéros initiaux ajoutés si nécessaire pour qu'il contienne au moins quatre chiffres hexadécimaux
name
nom de code, TOUT EN MAJUSCULES. Certains points de code de type contrôle n'ont pas de noms. Ce champ sera vide pour les points de code "Surrogate" et "Private Use", et pour les autres sans nom, il contiendra une description entre crochets, comme "<control>".
category
Le nom court de la catégorie générale de code. Ceci correspondra à l'une des clés du hash retourné par "general_categories()".

La fonction "prop_value_aliases()" peut être utilisée pour obtenir tous les synonymes du nom de la catégorie.

combining
le numéro de classe de combinaison pour code utilisé dans l'Algorithme de Tri Canonique. Pour Unicode 5.1, ceci est décrit dans la Section 3.11 "Canonical Ordering Behavior" disponible à http://www.unicode.org/versions/Unicode5.1.0/

La fonction "prop_value_aliases()" peut être utilisée pour obtenir tous les synonymes du numéro de classe de combinaison.

bidi
type bidirectionnel de code. Ceci correspondra à l'une des clés du hash retourné par "bidi_types()".

La fonction "prop_value_aliases()" peut être utilisée pour obtenir tous les synonymes du nom du type bidirectionnel.

decomposition
est vide si code n'a pas de décomposition ; ou est un ou plusieurs codes (séparés par des espaces) qui, pris dans l'ordre, représentent une décomposition pour code. Chacun a au moins quatre chiffres hexadécimaux. Les codes peuvent être précédés d'un mot entre crochets, suivi d'un espace, comme "<compat> ", indiquant le type de décomposition.

Cette décomposition peut être une décomposition intermédiaire dont les composants sont également décomposables. Utilisez Unicode::Normalize pour obtenir la décomposition finale en une seule étape.

decimal
si code représente un chiffre décimal, ceci est sa valeur numérique entière
digit
si code représente un autre nombre de type chiffre, ceci est sa valeur numérique entière
numeric
si code représente un nombre entier ou rationnel, ceci est sa valeur numérique. Les valeurs rationnelles sont exprimées sous forme de chaîne comme "1/4".
mirrored
"Y" ou "N" indiquant si code est reflet dans le texte bidirectionnel
unicode10
nom de code dans la norme Unicode 1.0 s'il en existait un pour ce point de code et qu'il est différent du nom actuel
comment
À partir d'Unicode 6.0, ceci est toujours vide.
upper
est, si non vide, le mapping en majuscules pour code exprimé en au moins quatre chiffres hexadécimaux. Ceci indique que le mapping complet en majuscules est un seul caractère, et est identique au mapping simple (caractère unique uniquement). Lorsque ce champ est vide, cela signifie que le mapping simple en majuscules est code lui-même ; vous aurez besoin d'un autre moyen (comme "charprop()" ou "casespec()" pour obtenir le mapping complet.
lower
est, si non vide, le mapping en minuscules pour code exprimé en au moins quatre chiffres hexadécimaux. Ceci indique que le mapping complet en minuscules est un seul caractère, et est identique au mapping simple (caractère unique uniquement). Lorsque ce champ est vide, cela signifie que le mapping simple en minuscules est code lui-même ; vous aurez besoin d'un autre moyen (comme "charprop()" ou
"casespec()" pour obtenir le mappage complet.
title
est, s'il n'est pas vide, le mappage en casse de titre pour code exprimé par au moins quatre chiffres hexadécimaux. Ceci indique que le mappage complet en casse de titre est un seul caractère et est identique au mappage simple (un seul caractère uniquement). Lorsque ce champ est vide, cela signifie que le mappage simple en casse de titre est code lui-même ; vous aurez besoin d'autres moyens, (comme "charprop()" ou "casespec()") pour obtenir le mappage complet.
block
le bloc auquel code appartient (utilisé dans "\p{Blk=...}"). La fonction "prop_value_aliases()" peut être utilisée pour obtenir tous les synonymes du nom du bloc.

Voir "Blocs versus Scripts".

script
le script auquel code appartient. La fonction "prop_value_aliases()" peut être utilisée pour obtenir tous les synonymes du nom du script. Notez qu'il s'agit de l'ancienne propriété "Script", et non de la valeur améliorée "Script_Extensions".

Voir "Blocs versus Scripts".

Notez que vous ne pouvez pas effectuer la composition (ou décomposition) et la mise en casse en vous basant uniquement sur les champs decomposition, combining, lower, upper et title ; vous aurez également besoin de la fonction "casespec()" et de la propriété "Composition_Exclusion". (Ou vous pourriez simplement utiliser les fonctions lc(), uc() et ucfirst(), ainsi que le module Unicode::Normalize.)

charprop()

  use Unicode::UCD 'charprop';
  print charprop(0x41, "Gc"), "\n";
  print charprop(0x61, "General_Category"), "\n";
produit
  Lu
  Ll

Ceci retourne la valeur de la propriété Unicode donnée par le second paramètre pour le "point de code argument" donné par le premier.

La propriété passée peut être spécifiée comme l'un des synonymes retournés par "prop_aliases()".

La valeur retournée est toujours un scalaire, soit une chaîne, soit un nombre. Pour les propriétés pour lesquelles il existe des synonymes de valeurs, le synonyme retourné par cette fonction est la forme la plus longue et la plus descriptive, celle retournée par "prop_value_aliases()" lorsqu'elle est appelée dans un contexte scalaire. Bien sûr, vous pouvez appeler "prop_value_aliases()" sur le résultat pour obtenir d'autres synonymes.

Les valeurs retournées sont plus "traitées" que celles de "charinfo()". Par exemple, la valeur de la propriété "uc" est la chaîne réelle contenant le mappage complet en majuscules du point de code d'entrée. Vous devez faire des efforts supplémentaires avec "charinfo" pour obtenir cette valeur de son élément de hachage "upper" lorsque le mappage complet diffère du mappage simple.

Une note spéciale doit être faite sur les valeurs retournées pour quelques propriétés :

Block
La valeur retournée est le nouveau style (voir "Ancien style versus nouveau style de noms de blocs").
Decomposition_Mapping
Comme "charinfo()", le résultat peut être une décomposition intermédiaire dont les composantes sont également décomposables. Utilisez Unicode::Normalize pour obtenir la décomposition finale en une seule étape.

Contrairement à "charinfo()", ceci n'inclut pas le type de décomposition. Utilisez la propriété "Decomposition_Type" pour l'obtenir.

Name_Alias
Si le nom du point de code d'entrée a plus d'un synonyme, ils sont retournés joints en une seule chaîne séparée par des virgules.
Numeric_Value
Si le résultat est une fraction, il est converti en un nombre à virgule flottante avec la précision de votre plateforme.
Script_Extensions
Si le résultat est plusieurs noms de scripts, ils sont retournés joints en une seule chaîne séparée par des virgules.

Lorsqu'elle est appelée avec une propriété qui est une extension Perl qui n'est pas exprimable sous forme composée, cette fonction retourne actuellement "undef", car les deux seules valeurs possibles sont vrai ou faux (1 ou 0 j'imagine). Ce comportement peut changer à l'avenir, ne donc pas écrire de code qui en dépend. "Present_In" est une extension Perl qui est exprimable sous forme bipartite ou composée (par exemple, "\p{Present_In=4.0}"), donc "charprop" l'accepte. Mais "Any" est une extension Perl qui n'est pas exprimable de cette manière, donc "charprop" retourne "undef" pour elle. De même, "charprop" retourne "undef" pour toutes les extensions Perl qui sont internes uniquement.

charprops_all()

use Unicode::UCD 'charprops_all';
my $%properties_of_A_hash_ref = charprops_all("U+41");

Ceci retourne une référence à un hachage dont les clés sont toutes les propriétés distinctes de l'Unicode (pas d'extensions Perl), et dont les valeurs sont les valeurs respectives de ces propriétés pour le "point de code argument" d'entrée.

Chaque clé est le nom de la propriété dans sa forme la plus longue et la plus descriptive. Les valeurs sont ce que retournerait "charprop()".

Cette fonction est coûteuse en temps et en mémoire.

charblock()

use Unicode::UCD 'charblock';
my $charblock = charblock(0x41);
my $charblock = charblock(1234);
my $charblock = charblock(0x263a);
my $charblock = charblock("U+263a");
my $range     = charblock('Armenian');

Avec un "point de code argument", charblock() retourne le bloc auquel le point de code appartient, par exemple "Basic Latin". Le nom de bloc ancien style est retourné (voir "Ancien style versus nouveau style de noms de blocs"). La fonction "prop_value_aliases()" peut être utilisée pour obtenir tous les synonymes du nom du bloc.

Si le point de code n'est pas assigné, ceci retourne le bloc auquel il appartiendrait s'il était assigné. (Si la version Unicode utilisée est si ancienne qu'elle n'a pas de blocs, tous les points de code sont considérés comme étant dans "No_Block".)

Voir aussi "Blocs versus Scripts".

Si un argument qui ne peut pas être un point de code est fourni, charblock() essaie de faire le contraire et d'interpréter l'argument comme un nom de bloc ancien style. Sur une plateforme ASCII, la valeur retournée est un ensemble de plages avec une plage : un tableau anonyme avec un seul élément qui consiste en un autre tableau anonyme dont le premier élément est le premier point de code du bloc, et dont le second élément est le point de code final du bloc. Sur une plateforme EBCDIC, les deux premiers blocs Unicode ne sont pas contigus. Leurs ensembles de plages sont des listes contenant des paires de points de code début-de-plage, fin-de-plage. Vous pouvez tester si un point de code se trouve dans un ensemble de plages en utilisant la fonction "charinrange()". (Pour être précis, chaque ensemble de plages contient un troisième élément de tableau, après les limites de plage : le nom de bloc _ancien_style.)

Si l'argument de charblock() n'est pas un bloc connu, "undef" est retourné.

charscript()

use Unicode::UCD 'charscript';
my $charscript = charscript(0x41);
my $charscript = charscript(1234);
my $charscript = charscript("U+263a");
my $range      = charscript('Thai');

Avec un "point de code argument", charscript() retourne le script auquel le point de code appartient, par exemple, "Latin", "Greek", "Han". Si le point de code n'est pas assigné ou si la version Unicode utilisée est si ancienne qu'elle n'a pas de scripts, cette fonction retourne "Unknown". La fonction "prop_value_aliases()" peut être utilisée pour obtenir tous les synonymes du nom du script.

Notez que la propriété Script_Extensions est une version améliorée de la propriété Script, et vous devriez probablement l'utiliser à la place, avec la fonction "charprop()".

Si un argument qui ne peut pas être un point de code est fourni, charscript() essaie de faire le contraire et d'interpréter l'argument comme un nom de script. La valeur retournée est un ensemble de plages : un tableau anonyme de tableaux qui contiennent des paires de points de code début-de-plage, fin-de-plage. Vous pouvez tester si un point de code se trouve dans un ensemble de plages en utilisant la fonction "charinrange()". (Pour être précis, chaque ensemble de plages contient un troisième élément de tableau, après les limites de plage : le nom du script.)

Si l'argument de charscript() n'est pas un script connu, "undef" est retourné.

Voir aussi "Blocs versus Scripts".

charblocks()

use Unicode::UCD 'charblocks';
my $charblocks = charblocks();

charblocks() retourne une référence à un hachage avec les noms de blocs connus comme clés, et les plages de points de code (voir "charblock()") comme valeurs.

Les noms sont en ancien style (voir "Ancien style versus nouveau style de noms de blocs").

prop_invmap("block") peut être utilisé pour obtenir ces mêmes données dans un type de structure de données différent.

prop_values("Block") peut être utilisé pour obtenir tous les noms de blocs nouveau style connus sous forme de liste, sans les plages de points de code.

Voir aussi "Blocs versus Scripts".

charscripts()

use Unicode::UCD 'charscripts';
my $charscripts = charscripts();

charscripts() retourne une référence à un hachage avec les noms de scripts connus comme clés, et les plages de points de code (voir "charscript()") comme valeurs.

prop_invmap("script") peut être utilisé pour obtenir ces mêmes données dans un type de structure de données différent. Puisque la propriété Script_Extensions est une version améliorée de la propriété Script, vous devriez plutôt utiliser prop_invmap("scx").

prop_values("Script") peut être utilisé pour obtenir tous les

names des scripts sous forme de liste, sans les points de code intervalles.

Voir aussi "Blocs versus Scripts".

charinrange()

En plus d'utiliser les constructions "\p{Blk=...}" et "\P{Blk=...}", vous pouvez également tester si un point de code se trouve dans la plage telle que retournée par "charblock()" et "charscript()" ou telle qu'elle est dans les valeurs du hachage retourné par "charblocks()" et "charscripts()" en utilisant charinrange() :

use Unicode::UCD qw(charscript charinrange);
$range = charscript('Hiragana');
print "ressemble à hiragana\n" if charinrange($range, $codepoint);

general_categories()

use Unicode::UCD 'general_categories';
my $categories = general_categories();

Ceci retourne une référence à un hachage qui a des noms de catégorie générale courts (tels que "Lu", "Nd", "Zs", "S") comme clés et des noms longs (tels que "UppercaseLetter", "DecimalNumber", "SpaceSeparator", "Symbol") comme valeurs. Le hachage est réversible au cas où vous auriez besoin de passer des noms longs aux noms courts. La catégorie générale est celle retournée par "charinfo()" sous la clé "category".

Les fonctions "prop_values()" et "prop_value_aliases()" peuvent être utilisées comme alternative à cette fonction ; la première retournant une simple liste des noms courts de catégorie ; et la seconde obtient tous les synonymes d'un nom de catégorie donné.

bidi_types()

use Unicode::UCD 'bidi_types';
my $categories = bidi_types();

Ceci retourne une référence à un hachage qui a les noms courts de type bidi (bidirectionnel) (tels que "L", "R") comme clés et des noms longs (tels que "Left-to-Right", "Right-to-Left") comme valeurs. Le hachage est réversible au cas où vous auriez besoin de passer des noms longs aux noms courts. Le type bidi est celui retourné par "charinfo()" sous la clé "bidi". Pour la signification exacte des diverses classes bidi, la lecture du TR9 de l'Unicode est recommandée : http://www.unicode.org/reports/tr9/ (à partir de Unicode 5.0.0)

Les fonctions "prop_values()" et "prop_value_aliases()" peuvent être utilisées comme alternative à cette fonction ; la première retournant une simple liste des noms courts de type bidi ; et la seconde obtient tous les synonymes d'un nom de type bidi donné.

compexcl()

AVERTISSEMENT : L'Unicode déconseille l'utilisation de cette fonction ou de tout autre mécanisme alternatif listé dans cette section (la documentation de compexcl()), sauf en interne dans les implémentations de l'algorithme de normalisation Unicode. Vous devriez utiliser Unicode::Normalize directement à la place de ces fonctions. Leur utilisation conduira probablement à des résultats incomplets.

use Unicode::UCD 'compexcl';
my $compexcl = compexcl(0x09dc);

Cette routine retourne "undef" si la version d'Unicode utilisée est suffisamment ancienne pour ne pas disposer de cette propriété.

compexcl() est incluse pour des raisons de compatibilité descendante, mais à partir de Perl 5.12 et des versions d'Unicode plus modernes, pour la plupart des usages, il est probablement plus pratique d'utiliser l'une des options suivantes à la place :

my $compexcl = chr(0x09dc) =~ /\p{Comp_Ex};
my $compexcl = chr(0x09dc) =~ /\p{Full_Composition_Exclusion};

ou même

my $compexcl = chr(0x09dc) =~ /\p{CE};
my $compexcl = chr(0x09dc) =~ /\p{Composition_Exclusion};

Les deux premières formes retournent vrai si le "point de code argument" ne doit pas être produit par la normalisation de composition. Pour que les deux dernières formes retournent vrai, il est en outre requis que ce fait ne puisse pas être déterminé autrement à partir de la base de données Unicode.

Cette routine se comporte de manière identique aux deux dernières formes. C'est-à-dire qu'elle ne retourne pas vrai si le point de code a une décomposition constituée d'un autre point de code unique, ni si sa décomposition commence par un point de code dont la classe de combinaison est non nulle. Les points de code qui satisfont l'une ou l'autre de ces conditions ne devraient pas non plus être produits par la normalisation de composition, ce qui explique probablement pourquoi vous devriez utiliser la propriété "Full_Composition_Exclusion" à la place, comme montré ci-dessus.

La routine retourne faux sinon.

casefold()

use Unicode::UCD 'casefold';
my $casefold = casefold(0xDF);
if (defined $casefold) {
    my @full_fold_hex = split / /, $casefold->{'full'};
    my $full_fold_string =
                join "", map {chr(hex($_))} @full_fold_hex;
    my @turkic_fold_hex =
                    split / /, ($casefold->{'turkic'} ne "")
                                    ? $casefold->{'turkic'}
                                    : $casefold->{'full'};
    my $turkic_fold_string =
                    join "", map {chr(hex($_))} @turkic_fold_hex;
}
if (defined $casefold && $casefold->{'simple'} ne "") {
    my $simple_fold_hex = $casefold->{'simple'};
    my $simple_fold_string = chr(hex($simple_fold_hex));
}

Ceci retourne le repliage de casse (presque) indépendant de la locale du caractère spécifié par le "point de code argument". (À partir de Perl v5.16, la fonction noyau fc() retourne le mappage "full" (décrit ci-dessous) plus rapidement que celle-ci, et ce pour des chaînes entières.)

S'il n'y a pas de repliage de casse pour le point de code d'entrée, "undef" est retourné.

S'il existe un repliage de casse pour ce point de code, une référence à un hachage contenant les champs suivants est retournée :

code
le point de code natif d'entrée argumenté, exprimé en hexadécimal, avec des zéros initiaux ajoutés si nécessaire pour qu'il contienne au moins quatre chiffres hexadécimaux.
full
un ou plusieurs codes (séparés par des espaces) qui, pris dans l'ordre, donnent les points de code pour le repliage de casse de code. Chacun a au moins quatre chiffres hexadécimaux.
simple
est vide, ou est exactement un code avec au moins quatre chiffres hexadécimaux qui peut être utilisé comme repliage de casse alternatif lorsque le programme appelant ne peut pas gérer le fait que le repliage soit une séquence de plusieurs points de code. Si full est juste un point de code, alors simple est égal à full. S'il n'y a pas de repliage de point de code unique défini pour code, alors simple est la chaîne vide. Sinon, c'est un repliage inférieur, mais toujours mieux que rien, par rapport à full.
mapping
est identique à simple si simple n'est pas vide, et est identique à full sinon. Il peut être considéré comme le repliage le plus simple possible pour code. Il est défini principalement pour des raisons de compatibilité descendante.
status
est "C" (pour "common") si le meilleur repliage possible est un point de code unique (simple égal à full égal à mapping). C'est "S" s'il y a des repliages distincts, simple et full (mapping égal à simple). Et c'est "F" s'il n'y a qu'un repliage full (mapping égal à full ; simple est vide). Notez que ceci décrit le contenu de mapping. Il est défini principalement pour des raisons de compatibilité descendante.

Pour les versions d'Unicode comprises entre 3.1 et 3.1.1 inclusives, status peut également être "I", ce qui est identique à "C" mais est un cas spécial pour le I majuscule pointé et le i minuscule non pointé :

* Si vous utilisez ce mappage "I"
le résultat est insensible à la casse, mais les I pointés et non pointés ne sont pas distingués.
* Si vous excluez ce mappage "I"
le résultat n'est pas totalement insensible à la casse, mais les I pointés et non pointés sont distingués.
turkic
contient tout repliage spécial pour les langues turques. Pour les versions d'Unicode à partir de 3.2, ce champ est vide sauf si code a un repliage différent dans les langues turques, auquel cas il contient un ou plusieurs codes (séparés par des espaces) qui, pris dans l'ordre, donnent les points de code pour le repliage de casse de code dans ces langues. Chaque code a au moins quatre chiffres hexadécimaux. Notez que ce repliage ne maintient pas l'équivalence canonique sans traitement supplémentaire.

Pour les versions d'Unicode comprises entre 3.1 et 3.1.1 inclusives, ce champ est vide sauf s'il existe un repliage spécial pour les langues turques, auquel cas status est "I", et mapping, full, simple, et turkic sont tous égaux.

Les programmes qui souhaitent une généralité complète et les meilleurs résultats de repliage devraient utiliser le repliage contenu dans le champ full. Mais notez que le repliage de certains points de code sera une séquence de plusieurs points de code.

Les programmes qui ne peuvent pas gérer le fait que le mappage de repliage soit multiple peuvent utiliser le repliage contenu dans le champ simple, au prix d'une perte de généralité. Dans Unicode 5.1, environ 7% des repliages définis n'ont pas de repliage de point de code unique.

La plupart des propriétés Unicode ont plusieurs noms synonymes. Généralement, il existe au moins un nom court, pratique à taper, et un nom long qui décrit plus complètement la propriété, et est donc plus facile à comprendre.

Si vous connaissez un nom pour une propriété Unicode, vous pouvez utiliser "prop_aliases" pour trouver soit le nom long (lorsqu'il est appelé dans un contexte scalaire), soit une liste de tous les noms, quelque peu ordonnée de sorte que le nom court soit dans le 0ème élément, le nom long dans l'élément suivant, et tous les autres synonymes dans les éléments restants, dans aucun ordre particulier.

Le nom long est renvoyé dans une forme joliment capitalisée, adaptée à l'impression.

Le nom du paramètre d'entrée est mis en correspondance de manière lâche, ce qui signifie que les espaces blancs, les tirets et les tirets bas sont ignorés (à l'exception du tiret bas final dans le nom grandfathered-in de forme ancienne "L_", qui est mieux écrit comme "LC", et les deux signifiant "General_Category=Cased Letter").

Si le nom est inconnu, "undef" est renvoyé (ou une liste vide en contexte de liste). Notez que Perl reconnaît généralement les noms de propriétés dans les expressions régulières avec un préfixe optionnel ""Is_"" (avec ou sans le tiret bas), tel que "\p{isgc=punct}". Cette fonction ne reconnaît pas ceux-ci dans l'entrée, renvoyant "undef". Ils ne sont pas non plus inclus dans la sortie comme synonymes possibles.

"prop_aliases" connaît les extensions Perl aux propriétés Unicode, telles que "Any" et "XPosixAlpha", et les formes uniques équivalentes aux propriétés Unicode telles que "XDigit", "Greek", "In_Greek", et "Is_Greek". Le dernier exemple montre que le préfixe "Is_" est reconnu pour ces extensions ; il est nécessaire pour résoudre les ambiguïtés. Par exemple, prop_aliases('lc') renvoie la liste "(lc, Lowercase_Mapping)", mais prop_aliases('islc') renvoie "(Is_LC, Cased_Letter)". Ceci parce que "islc" est une extension Perl qui est l'abréviation de "General_Category=Cased Letter". Les listes renvoyées pour les extensions Perl n'incluront pas le préfixe "Is_" (que l'entrée l'ait eu ou non) sauf si nécessaire pour résoudre les ambiguïtés, comme montré dans l'exemple "islc", où la liste renvoyée avait un élément contenant "Is_", et l'autre sans.

Il est également possible que l'inverse se produise : prop_aliases('isc') renvoie la liste "(isc, ISO_Comment)" ; tandis que prop_aliases('c') renvoie "(C, Other)" (ce dernier étant une extension Perl signifiant "General_Category=Other". "Propriétés accessibles via Unicode::UCD" dans perluniprops liste les formes disponibles, y compris celles qui sont déconseillées d'utilisation.

Ces formes déconseillées sont acceptées comme entrée pour "prop_aliases", mais ne sont pas renvoyées dans les listes. prop_aliases('isL&') et prop_aliases('isL_'), qui sont d'anciens synonymes de "Is_LC" et ne devraient pas être utilisés dans du nouveau code, en sont des exemples. Ces deux fonctions renvoient "(Is_LC, Cased_Letter)". Ainsi, cette fonction vous permet de prendre une forme déconseillée et d'en trouver ses alternatives acceptables. Il en va de même pour les équivalences de propriétés de bloc à forme unique. Seules les formes commençant par "In_" ne sont pas déconseillées ; si vous passez "prop_aliases" une forme déconseillée, vous obtiendrez les équivalents commençant par "In_". Sinon, cela ressemblera à un nom de bloc de nouveau style (voir. "Noms de blocs ancien style versus nouveau style").

"prop_aliases" ne connaît pas les propriétés définies par l'utilisateur, et renverra "undef" si elle est appelée avec l'une d'entre elles. Il en va de même pour les propriétés internes de Perl, à l'exception de "Perl_Decimal_Digit" qu'elle connaît (et qui est documentée ci-dessous dans "prop_invmap()").

prop_invlist()

"prop_invlist" retourne une liste d'inversion (décrite ci-dessous) qui définit tous les points de code pour la propriété Unicode binaire (ou paire "propriété=valeur") donnée par la chaîne de paramètres d'entrée :

use feature 'say';
use Unicode::UCD 'prop_invlist';
say join ", ", prop_invlist("Any");
affiche :
0, 1114112

Si l'entrée est inconnue, "undef" est retourné en contexte scalaire ; une liste vide en contexte de liste. Si l'entrée est connue, le nombre d'éléments dans la liste est retourné si appelée en contexte scalaire.

perluniprops donne la liste des propriétés que cette fonction accepte, ainsi que toutes les formes possibles pour celles-ci (y compris avec les préfixes facultatifs "Is_"). (Sauf que cette fonction n'accepte aucune propriété interne à Perl, dont certaines sont listées là.) Cette fonction utilise les mêmes règles de correspondance lâches ou plus strictes pour résoudre le nom de la propriété d'entrée que celles utilisées pour les expressions régulières. Celles-ci sont également spécifiées dans perluniprops. Exemples d'utilisation de la forme "propriété=valeur" sont :

say join ", ", prop_invlist("Script_Extensions=Shavian");
affiche :
66640, 66688
say join ", ", prop_invlist("ASCII_Hex_Digit=No");
affiche :
0, 48, 58, 65, 71, 97, 103
say join ", ", prop_invlist("ASCII_Hex_Digit=Yes");
affiche :
48, 58, 65, 71, 97, 103

Les listes d'inversion sont un moyen compact de spécifier les définitions de propriétés-valeurs Unicode. Le 0ème élément de la liste est le plus bas point de code qui a la propriété-valeur. L'élément suivant (élément [1]) est le plus bas point de code au-delà de celui-ci qui N'A PAS la propriété-valeur. Et l'élément suivant au-delà de celui-ci ([2]) est le plus bas point de code au-delà de celui-ci qui A la propriété-valeur, et ainsi de suite. Autrement dit, chaque élément de la liste donne le début d'une plage qui a la propriété-valeur (pour les éléments de numéro pair) ou n'a pas la propriété-valeur (pour les éléments de numéro impair). Le nom de cette structure de données découle du fait que chaque élément de la liste bascule (ou inverse) si la plage correspondante est ou n'est pas dans la liste.

Dans le dernier exemple ci-dessus, le premier chiffre hexadécimal ASCII est le point de code 48, le caractère "0", et tous les points de code de celui-ci à 57 (un "9") sont des chiffres hexadécimaux ASCII. Les points de code 58 à 64 ne le sont pas, mais 65 (un "A") à 70 (un "F") le sont, tout comme 97 ("a") à 102 ("f"). 103 commence une plage de points de code qui ne sont pas des chiffres hexadécimaux ASCII. Cette plage s'étend à l'infini, qui sur votre ordinateur peut être trouvé dans la variable $Unicode::UCD::MAX_CP. (Cette variable est aussi proche de l'infini que Perl peut l'être sur votre plateforme, et peut être trop élevée pour que certaines opérations fonctionnent ; vous pourriez souhaiter utiliser un nombre plus petit pour vos besoins.)

Notez que les listes d'inversion retournées par cette fonction peuvent potentiellement inclure des points de code non-Unicode, c'est-à-dire tout ce qui est supérieur à 0x10FFFF. Les propriétés Unicode ne sont pas définies sur de tels points de code. Vous pourriez souhaiter modifier la sortie pour ne pas les inclure. Ajoutez simplement 0x110000 à la fin de la liste retournée non vide si ce n'est pas déjà cette valeur ; et supprimez cette valeur si elle l'est ; comme ceci :

my @list = prop_invlist("foo");

    if ($list[-1] == 0x110000) {
        pop @list;  # Désactiver l'activation pour au-dessus d'Unicode
    }
    else {
        push @list, 0x110000; # Désactiver pour au-dessus d'Unicode
    }
}

"prop_invmap" est utilisée pour obtenir la définition complète du mapping pour une propriété, sous la forme d'une map d'inversion. Une map d'inversion se compose de deux tableaux parallèles. L'un est une liste ordonnée de points de code qui marquent les débuts de plages, et l'autre donne la valeur (ou le mapping) que tous les points de code dans la plage correspondante ont.

"prop_invmap" est appelée avec le nom de la propriété désirée. Le nom est faiblement mis en correspondance, ce qui signifie que les différences de casse, d'espacement, de tirets et de soulignements ne sont pas significatives (sauf pour le soulignement final dans la propriété ancienne de catégorie générale "L_", qui est mieux écrite comme "LC", ou même mieux, "Gc=LC").

Beaucoup de propriétés Unicode ont plus d'un nom (ou alias). "prop_invmap" les comprend tous, y compris les extensions Perl. Les ambiguïtés sont résolues comme décrit ci-dessus pour "prop_aliases()" (sauf si une propriété a à la fois un mapping complet et un mapping binaire "Y"/"N", alors spécifier le nom de la propriété préfixé par "is" provoque le retour du mapping binaire). La propriété interne Perl "Perl_Decimal_Digit, décrite ci-dessous, est également acceptée. Une liste vide est retournée si le nom de la propriété est inconnu. Voir "Propriétés accessibles via Unicode::UCD" dans perluniprops pour les propriétés acceptables en entrée de cette fonction.

C'est une erreur fatale d'appeler cette fonction sauf en contexte de liste .

En plus des deux tableaux qui forment la map d'inversion, "prop_invmap" retourne deux autres valeurs ; l'une est un scalaire qui donne des détails sur le format des entrées du tableau de la map ; l'autre est une valeur par défaut, utile dans les maps dont le nom de format commence par la lettre "a", comme décrit ci-dessous dans sa sous-section ; et pour des usages spécialisés, comme la conversion vers une autre structure de données, décrite à la fin de cette section principale.

Cela signifie que "prop_invmap" retourne une liste de 4 éléments. Par exemple,

my ($blocks_ranges_ref, $blocks_maps_ref, $format, $default)
                                                = prop_invmap("Block");

Dans cet appel, les deux tableaux seront remplis comme indiqué ci-dessous (pour Unicode 6.0) :

La première ligne (avec l'Index [0]) signifie que la valeur pour le point de code 0 est "Basic Latin". L'entrée "0x0080" dans la colonne @blocks_ranges de la deuxième ligne signifie que la valeur de la première ligne, "Basic Latin", s'étend à tous les points de code de la plage de 0 jusqu'à, mais sans inclure, 0x0080, c'est-à-dire jusqu'à 127. En d'autres termes, les points de code de 0 à 127 sont tous dans le bloc "Basic Latin". De même, tous les points de code dans la plage de 0x0080 jusqu'à (mais sans inclure) 0x0100 sont dans le bloc nommé "Latin-1 Supplement", etc. (Notez que le retour est les noms de blocs de style ancien ; voir "Noms de blocs de style ancien par rapport au style nouveau").

La dernière ligne (avec l'Index [242]) signifie que la valeur pour tous les points de code supérieurs au maximum légal de points de code Unicode a la valeur "No_Block", qui est le terme que Unicode utilise pour un bloc inexistant.

Les tableaux spécifient complètement les mappings pour tous les points de code possibles. Le dernier élément d'une map d'inversion retournée par cette fonction sera toujours pour la plage qui consiste en tous les points de code qui ne sont pas des points de code Unicode légaux, mais qui sont exprimables sur la plateforme. (C'est-à-dire qu'elle commence au point de code 0x110000, le premier point de code après le maximum légal Unicode, et s'étend à l'infini.) La valeur pour cette plage sera la même que celle que tout point de code typiquement non assigné a pour la propriété spécifiée. (Certains points de code non assignés ne sont pas "typiques" ; par exemple les points de code non-caractères, ou ceux dans des blocs qui doivent être écrits de droite à gauche. La valeur de la plage au-dessus d'Unicode n'est pas basée sur ces points de code atypiques.) On pourrait soutenir qu'au lieu de traiter ces points de code comme des points de code Unicode non assignés, la valeur pour cette plage devrait être "undef". Si vous le souhaitez, vous pouvez modifier les tableaux retournés en conséquence.

Les cartes pour presque toutes les propriétés sont de simples scalaires qui doivent être interprétés tels quels. Ces valeurs sont celles fournies dans les fichiers de données Unicode, qui peuvent être incohérentes en ce qui concerne la casse et les synonymes des valeurs de propriétés utilisés. Les résultats peuvent être normalisés en utilisant la fonction "prop_value_aliases()".

Il existe des exceptions aux cartes scalaires simples. Certaines propriétés ont des éléments dans leur liste de cartes qui sont eux-mêmes des listes de scalaires ; et certaines chaînes spéciales sont retournées qui ne doivent pas être interprétées telles quelles. L'élément [2] (placé dans $format dans l'exemple ci-dessus) de la liste retournée de quatre éléments vous indique si la carte contient ou non certains de ces éléments spéciaux, comme suit :

"s"
signifie que tous les éléments du tableau de mappage sont des scalaires simples, sans éléments spéciaux. Presque toutes les propriétés sont comme ça, comme l'exemple "block" ci-dessus.
"sl"
signifie que certains des éléments du tableau de mappage ont la forme donnée par "s", et les autres sont des listes de scalaires. Par exemple, voici une partie de la sortie de l'appel à "prop_invmap"() avec la propriété "Script Extensions" : 
@scripts_ranges  @scripts_maps
     ...
     0x0953      Devanagari
     0x0964      [ Bengali, Devanagari, Gurmukhi, Oriya ]
     0x0966      Devanagari
     0x0970      Common

Ici, les points de code 0x964 et 0x965 sont tous deux utilisés en bengali, devanagari, gurmukhi et oriya, mais dans aucun autre script.

La propriété Name_Alias est également de cette forme. Mais chaque scalaire se compose de deux composants : 1) le nom, et 2) le type d'alias. Ils sont séparés par deux-points et un espace. Dans Unicode 6.1, il existe plusieurs types d'alias :

"correction"
indique que le nom est une forme corrigée du nom original (qui reste valide) pour le même point de code.
"control"
ajoute un nouveau nom pour un caractère de contrôle.
"alternate"
est un nom alternatif pour un caractère
"figment"
est un nom pour un caractère qui a été documenté mais n'a jamais été inclus dans une norme réelle.
"abbreviation"
est une abréviation courante pour un caractère

Les listes sont ordonnées (approximativement) de sorte que les noms les plus préférés précèdent les moins préférés.

Par exemple,

   ...
   0x009E        [ 'PRIVACY MESSAGE: control', 'PM: abbreviation' ]
   0x009F        [ 'APPLICATION PROGRAM COMMAND: control',
                   'APC: abbreviation'
                 ]
   0x00A0        'NBSP: abbreviation'
   0x00A1        ""
   0x00AD        'SHY: abbreviation'
   0x00AE        ""
   0x01A2        'LATIN CAPITAL LETTER GHA: correction'
   0x01A3        'LATIN SMALL LETTER GHA: correction'
   0x01A4        ""
   ...

Une carte vers la chaîne vide signifie qu'aucun alias n'est défini pour le point de code.

"a"
est comme "s" en ce sens que tous les éléments du tableau de mappage sont des scalaires, mais ici, ils sont tous restreints à être des entiers, et certains doivent être ajustés (d'où le nom "a") pour obtenir le résultat correct. Par exemple, dans : 
my ($uppers_ranges_ref, $uppers_maps_ref, $format, $default)
                         = prop_invmap("Simple_Uppercase_Mapping");

les tableaux retournés ressemblent à ceci :

@$uppers_ranges_ref    @$uppers_maps_ref   Note
      0                      0
     97                     65          'a' correspond à 'A', b => B ...
    123                      0
    181                    924          MICRO SIGN => Lettre capitale grecque MU
    182                      0
    ...

et $default est 0.

Commençons par la deuxième ligne. Elle indique que la casse supérieure du point de code 97 est 65 ; ou uc("a") == "A". Mais la ligne concerne toute la plage de points de code 97 à 122. Pour obtenir le mappage de n'importe quel point de code dans cette plage, vous prenez son décalage par rapport au premier point de code de la plage et vous l'ajoutez au mappage de ce premier point de code. Ainsi, le mappage pour 122 ("z") est obtenu en prenant le décalage de 122 par rapport à 97 (=25) et en l'ajoutant à 65, ce qui donne 90 ("Z"). De même pour tout ce qui se trouve entre les deux.

Exiger cet ajustement simple permet aux tableaux retournés d'être nettement plus petits qu'autrement, jusqu'à un facteur 10, accélérant ainsi la recherche.

Les plages qui correspondent à $default, "0", se comportent différemment. Pour celles-ci, chaque point de code correspond à lui-même. Ainsi, dans la première ligne de l'exemple, "ord(uc(chr(0)))" est 0, "ord(uc(chr(1)))" est 1, .. "ord(uc(chr(96)))" est 96.

"al"
signifie que certains des éléments du tableau de mappage ont la forme donnée par "a", et les autres sont des listes ordonnées de points de code. Par exemple, dans : 
my ($uppers_ranges_ref, $uppers_maps_ref, $format, $default)
                                = prop_invmap("Uppercase_Mapping");

les tableaux retournés ressemblent à ceci :

@$uppers_ranges_ref    @$uppers_maps_ref
      0                      0
     97                     65
    123                      0
    181                    924
    182                      0
    ...
   0x0149              [ 0x02BC 0x004E ]
   0x014A                    0
   0x014B                  330
    ...

C'est la propriété complète Uppercase_Mapping (par opposition à la Simple_Uppercase_Mapping donnée dans l'exemple pour le format "a"). La seule différence entre les deux dans les plages montrées est que le point de code à 0x0149 (LATIN SMALL LETTER N PRECEDED BY APOSTROPHE) correspond à une chaîne de deux caractères, 0x02BC (MODIFIER LETTER APOSTROPHE) suivi de 0x004E (LATIN CAPITAL LETTER N).

Aucun ajustement n'est nécessaire pour les entrées qui sont des références à des tableaux ; chaque entrée de ce type aura exactement un élément dans sa plage, donc le décalage est toujours de 0.

Le quatrième élément (index [3]) ($default) de la liste retournée pour ce format est 0.

"ae"
C'est comme "a", mais certains éléments sont une chaîne vide et ne doivent pas être ajustés. La seule propriété interne de Perl accessible par "prop_invmap" est de ce type : "Perl_Decimal_Digit" retourne une carte d'inversion qui donne les valeurs numériques représentées par les caractères Unicode de chiffre décimal. Les caractères qui ne représentent pas de chiffres décimaux correspondent à une chaîne vide, comme ceci :

Cela signifie que les points de code de 0 à 0x2F ne représentent pas de chiffres décimaux ; le point de code 0x30 (CHIFFRE ZÉRO) représente 0 ; le point de code 0x31, (CHIFFRE UN), représente 0+1-0 = 1 ; ... le point de code 0x39, (CHIFFRE NEUF), représente 0+9-0 = 9 ; ... les points de code 0x3A à 0x65F ne représentent pas de chiffres décimaux ; 0x660 (CHIFFRE ZÉRO ARABE-INDIEN), représente 0 ; ... 0x07C1 (CHIFFRE UN NKO), représente 0+1-0 = 1 ...

Le quatrième élément (index [3]) ($default) de la liste retournée pour ce format est la chaîne vide.

"al"
est une combinaison du type "al" et du type "ae". Certains des éléments du tableau de mappage ont les formes données par "al", et les autres sont la chaîne vide. Les propriétés "NFKC_Casefold" et "NFKC_Simple_Casefold" ont cette forme. Une tranche d'exemple est :

   ...

  0x00AB        0
  0x00AD                         SOUS-TRAIT DE SÉPARATION => ""
  0x00AE        0
  0x00AF     [ 0x0020, 0x0304 ]  MACRON => ESPACE . MACRON COMBINANT
  0x00B0        0
  ...

Le quatrième élément (index [3]) ($default) de la liste retournée pour ce format est 0.

"ar"
signifie que tous les éléments du tableau de mappage sont soit des nombres rationnels, soit la chaîne "NaN", signifiant "Not a Number" (Pas un nombre). Un nombre rationnel est soit un entier, soit deux entiers séparés par un slash ("/"). Le deuxième entier représente le dénominateur de la division impliquée par le slash, et il est en fait toujours positif, il est donc garanti de ne pas être 0 et de ne pas être signé. Lorsque l'élément est un simple entier (sans le slash), il peut nécessiter un ajustement pour obtenir la valeur correcte en ajoutant le décalage, tout comme d'autres propriétés "a". Aucun ajustement n'est nécessaire pour les fractions, car la plage est garantie de n'avoir qu'un seul élément, et donc le décalage est toujours de 0.

Si vous souhaitez convertir la carte retournée en nombres entièrement scalaires, vous pouvez utiliser quelque chose comme ceci :

my ($invlist_ref, $invmap_ref, $format) = prop_invmap($property);
if ($format && $format eq "ar") {
    map { $_ = eval $_ if $_ ne 'NaN' } @$map_ref;
}

"n"
signifie la propriété Name. Tous les éléments du tableau de mappage sont de simples scalaires, mais certains d'entre eux contiennent des chaînes spéciales qui nécessitent plus de travail pour obtenir le nom réel.

Des entrées telles que :

CJK UNIFIED IDEOGRAPH-<code point>

signifient que le nom du point de code est "CJK UNIFIED IDEOGRAPH-" auquel est ajouté le point de code (exprimé en hexadécimal), comme "CJK UNIFIED IDEOGRAPH-3403" (de même pour "CJK COMPATIBILITY IDEOGRAPH-<code point>").

De plus, des entrées comme

<hangul syllable>

signifient que le nom est calculé algorithmiquement. Ceci est facilement fait par la fonction "charnames::viacode(code)" dans charnames.

Notez que pour les caractères de contrôle ("Gc=cc"), les fichiers de données Unicode ont la chaîne ""<control>"", mais le vrai nom de chacun de ces caractères est la chaîne vide. Cette fonction renvoie ce vrai nom, la chaîne vide. (Il existe des noms pour ces caractères, mais ils sont considérés comme des alias, pas comme le nom de la propriété Name, et se trouvent dans la propriété "Name_Alias".)

"ad"
signifie la propriété Decomposition_Mapping. Cette propriété est similaire aux propriétés "al", sauf qu'un des éléments scalaires est de la forme : 
<hangul syllable>

Cela signifie que cette entrée doit être remplacée par les décompositions pour tous les points de code dont la décomposition est calculée algorithmiquement. (Tous sont actuellement dans une plage et aucun autre en dehors de la plage ne sera probablement jamais ajouté à Unicode ; le format "n" a cette même entrée.) Celles-ci peuvent être générées via la fonction Unicode::Normalize::NFD().

Notez que le mappage est celui spécifié dans les fichiers de données Unicode, et pour obtenir la décomposition finale, il peut être nécessaire de l'appliquer récursivement. Unicode décourage en fait l'utilisation de cette propriété, sauf en interne dans les implémentations de l'algorithme de normalisation Unicode.

Le quatrième élément (index [3]) ($default) dans la liste retournée pour ce format est 0.

Notez qu'un format commence par la lettre "a" si et seulement si la propriété pour laquelle il est destiné nécessite des ajustements en ajoutant les décalages dans les plages à plusieurs éléments. Pour toutes ces propriétés, une entrée ne doit être ajustée que si le mappage est un scalaire qui est un entier. C'est-à-dire qu'il doit correspondre à l'expression régulière :

/ ^ -? \d+ $ /xa

De plus, le premier élément d'une plage n'a jamais besoin d'être ajusté, car l'ajustement serait simplement l'ajout de 0.

Une recherche binaire telle que celle fournie par "search_invlist()", peut être utilisée pour trouver rapidement un point de code dans la liste d'inversion, et donc son mappage correspondant.

Le quatrième et dernier élément (index [3], assigné à $default dans l'exemple "block") dans la liste de quatre éléments retournée par cette fonction est utilisé avec les types de format "a" ; il peut également être utile pour les applications qui souhaitent convertir la structure de données de liste d'inversion retournée en une autre, telle qu'une table de hachage. Il donne le mappage auquel la plupart des points de code sont mappés sous la propriété. Si vous établissez la convention selon laquelle tout point de code non explicitement répertorié dans votre structure de données est mappé à cette valeur, vous pouvez potentiellement rendre votre structure de données beaucoup plus petite. Lors de la construction de votre structure de données à partir de celle retournée par cette fonction, ignorez simplement les plages qui correspondent à cette valeur. Par exemple, pour convertir vers la structure de données interrogeable par "charinrange()", vous pouvez suivre cette recette pour les propriétés qui ne nécessitent pas d'ajustements :

my ($list_ref, $map_ref, $format, $default) = prop_invmap($property);
my @range_list;
# Examiner chaque élément de la liste, mais le -2 est nécessaire car nous
# regardons $i+1 dans la boucle, et le dernier élément est garanti de mapper
# à $default par prop_invmap(), nous le sautions donc de toute façon.
for my $i (0 .. @$list_ref - 2) {
   next if $map_ref->[$i] eq $default;
   push @range_list, [ $list_ref->[$i],
                       $list_ref->[$i+1],
                       $map_ref->[$i]
                     ];
}
print charinrange(\@range_list, $code_point), "\n";

Avec cela, charinrange() retournera "undef" si son point de code d'entrée correspond à $default. Vous pouvez éviter cela en omettant l'instruction "next", et en ajoutant une ligne après la boucle pour traiter le dernier élément de la liste d'inversion.

De même, cette recette peut être utilisée pour les propriétés qui nécessitent des ajustements :

for my $i (0 .. @$list_ref - 2) {
   next if $map_ref->[$i] eq $default;
   # prop_invmap() garantit que si le mappage est vers un tableau, la
   # plage n'a qu'un seul élément, il n'y a donc pas lieu de s'inquiéter des ajustements.
   if (ref $map_ref->[$i]) {
       push @range_list,
                  [ $list_ref->[$i], $list_ref->[$i], $map_ref->[$i] ];
   }
   else {  # Sinon, chaque élément est effectivement mappé à une valeur distincte,
           # donc la plage doit être divisée en plages de points de code uniques.
       my $adjustment = 0;
       # Pour chaque point de code qui est mappé à quelque chose...
       for my $j ($list_ref->[$i] .. $list_ref->[$i+1] -1 ) {
           # ... ajouter une plage composée uniquement de ce point de code mappé à l'original plus l'ajustement, qui est incrémenté pour la prochaine itération, car le décalage augmente de 1
           # pour chaque élément de la plage.
           push @range_list,
                            [ $j, $j, $map_ref->[$i] + $adjustment++ ];
       }
   }
}

Notez que les listes d'inversion retournées pour les propriétés "Case_Folding" et "Simple_Case_Folding" n'incluent pas les mappages de locale turcique. Utilisez "casefold()" pour ceux-ci.

"prop_invmap" ne connaît aucune propriété définie par l'utilisateur, et retournera "undef" si elle est appelée avec l'une d'entre elles.

Les valeurs retournées pour les propriétés d'extension Perl, telles que "Any" et "Greek", sont quelque peu trompeuses. Les valeurs sont soit "Y", soit ""N"". Toutes les propriétés Unicode sont biparties, vous pouvez donc en fait utiliser "Y" ou ""N"" dans une expression régulière Perl pour celles-ci, comme "qr/\p{ID_Start=Y/}" ou "qr/\p{Upper=N/}". Mais les extensions Perl ne sont pas spécifiées de cette manière, seulement comme "/qr/\p{Any}", *etc*. Vous ne pouvez pas réellement utiliser "Y" et ""N"" dedans.

Obtenir tous les noms disponibles

Au lieu de lire la base de données Unicode directement à partir de fichiers, comme vous avez pu le faire pendant longtemps, il est recommandé d'utiliser les fonctions fournies. Ainsi, au lieu de lire "Name.pl" directement, qui a changé de format dans la version 5.32, et pourrait le faire à nouveau à l'avenir sans préavis ou même disparaître, vous devriez utiliser "prop_invmap()" comme suit :

my (%name, %cp, %cps, $n);
# Tous les points de code
foreach my $cat (qw( Name Name_Alias )) {
    my ($codepoints, $names, $format, $default) = prop_invmap($cat);
    # $format => "n", $default => ""
    foreach my $i (0 .. @$codepoints - 2) {
        my ($cp, $n) = ($codepoints->[$i], $names->[$i]);
        # Si $n est une référence, le même point de code a plusieurs noms
        foreach my $name (ref $n ? @$n : $n) {
            $name{$cp} //= $name;
            $cp{$name} //= $cp;
        }
    }
}
# Séquences nommées
{   my %ns = namedseq();
    foreach my $name (sort { $ns{$a} cmp $ns{$b} } keys %ns) {
        $cp{$name} //= [ map { ord } split "" => $ns{$name} ];
    }
}

search_invlist()

use Unicode::UCD qw(prop_invmap prop_invlist);
use Unicode::UCD 'search_invlist';
my @invlist = prop_invlist($property_name);
print $code_point, ((search_invlist(\@invlist, $code_point) // -1) % 2)
                    ? " n'est pas"
                    : " est",
    " dans $property_name\n";
my ($blocks_ranges_ref, $blocks_map_ref) = prop_invmap("Block");
my $index = search_invlist($blocks_ranges_ref, $code_point);
print "$code_point est dans le bloc ", $blocks_map_ref->[$index], "\n";

"search_invlist" est utilisé pour rechercher dans une liste d'inversion retournée par "prop_invlist" ou "prop_invmap" un "argument de point de code" particulier. "undef" est retourné si le point de code n'est pas trouvé dans la liste d'inversion (cela se produit uniquement lorsqu'il ne s'agit pas d'un "argument de point de code" valide, ou s'il est inférieur au premier élément de la liste). Un avertissement est généré dans le premier cas.

Sinon, il retourne l'index dans la liste de la plage qui contient le point de code ; c'est-à-dire, trouver "i" tel que

list[i]<= code_point < list[i+1].

Comme expliqué dans "prop_invlist()", qu'un point de code soit dans la liste ou non dépend si l'index est pair (dans) ou impair (pas dans). Et comme expliqué dans "prop_invmap()", l'index est utilisé avec le tableau parallèle retourné pour trouver le mappage.

Unicode::UCD::UnicodeVersion

Ceci retourne la version de la base de données de caractères Unicode, en d'autres termes, la version de la norme Unicode que la base de données implémente. La version est une chaîne de nombres délimités par des points ('.').

Blocs versus Scripts

La différence entre un bloc et un script est que les scripts sont plus proches de la notion linguistique d'un ensemble de points de code nécessaires pour représenter des langues, tandis qu'un bloc est davantage un artefact de la numérotation des points de code Unicode et de la séparation en blocs de points de code consécutifs (jusqu'à présent, la taille d'un bloc est un multiple de 16, comme 128 ou 256).

Par exemple, le **script** latin est réparti sur plusieurs **blocs**, tels que "Basic Latin", "Latin 1 Supplement", "Latin Extended-A", et Unicode::UCD(3perl) - Perl manual page

NAME

Unicode::UCD - Access to the Unicode Character Database

SYNOPSIS

  use Unicode::UCD;
  my $name = charname(0x00C5); # returns "LATIN CAPITAL LETTER A WITH RING ABOVE"
  my $codepoint = utf2char(0xC5); # returns 197
  my $ucd_version = ucd_version(); # returns "15.0"
  my $script = script(0x00C5); # returns "Latin"
  my $block = charblock(0x00C5); # returns "Latin-1 Supplement"
  my $general_category = category(0x00C5); # returns "Lu"
  my $is_assigned = assigned(0x00C5); # returns 1 (true)

DESCRIPTION

This module provides access to the Unicode Character Database (UCD) via Perl functions.

The functions provided by this module map to the properties and characters defined by the UCD. See http://www.unicode.org/ucd/ for details.

The module supports the properties defined by Unicode Consortium. Newer Unicode versions may define new properties, or change existing ones. The module attempts to keep up with these changes, but it may lag behind the latest Unicode releases.

The module does not (and cannot) implement the full rules of Unicode normalization, case mapping, etc., as those are complex algorithms. It does provide access to the data tables used by those algorithms.

The module can be configured to use a specific version of the UCD data by setting the environment variable UNICODE_XSD_VERSION. For example:

    $ export UNICODE_XSD_VERSION=14.0
    $ perl script.pl

Or, in a Perl script:

    use Unicode::UCD qw( ucd_version );
    BEGIN { Unicode::UCD::set_unicode_version('14.0') }
    use Unicode::UCD qw( ... ); # Import other functions *after* setting version

If no version is specified, the module defaults to the latest version available when the module was installed.

The UCD defines many properties. This module implements access to many of them, including:

The script of a character (e.g. Greek, Cyrillic, Armenian).
General_Category
The general category of a character (e.g. Letter, Number, Punctuation).
Block
The block the character belongs to (e.g. Basic Latin, Latin-1 Supplement, Greek).
Name
The official name of the character.

The Unicode version in which the character was introduced.
Bidirectional
Properties related to bidirectional text handling.
Joining_Type
Properties related to Arabic script joining.
Numeric_Type
Various numeric values associated with characters.
White_Space
Whether the character is considered whitespace.
Bidi_Mirrored
Whether the character is mirrored in bidirectional text.
Dash
Whether the character is a dash.
Hyphen
Whether the character is a hyphen.
Alphabetic
Whether the character is alphabetic.
Lowercase
Whether the character is lowercase.
Uppercase
Whether the character is uppercase.
White_Space
Whether the character is whitespace.
XID_Start

Whether the character is suitable for continuing an identifier.

Rules for line breaking.

Rules for sentence breaking.

The names of properties and their values are often used in regular expressions. For example, to match any character in the Tibetan script:

  if ($char =~ /\p{Script=Tibetan}/) { ... }

Or using the short form:

  if ($char =~ /\p{Tibetan}/) { ... }

To match any character in the Cyrillic block:

  if ($char =~ /\p{Blk=Cyrillic}/) { ... }

Or using the short form:

  if ($char =~ /\p{In_Cyrillic}/) { ... }

Note that the short form for blocks is In_BlockName.

It's important to understand the distinction between scripts and blocks.

A **script** is a set of characters representing a writing system. For example, the 'Latin' script includes characters like 'a', 'b', 'c', 'A', 'B', 'C', etc.

A **block** is a contiguous range of 256 code points in the Unicode character encoding space. Blocks are used for organizing the character space, often grouping characters that belong to the same script or have similar visual properties. For example, the 'Basic Latin' block contains the first 256 Unicode code points (U+0000 to U+00FF), which includes ASCII characters, Latin letters, digits, and punctuation. The 'Latin Extended-B' block contains additional Latin characters.

The Latin script contains characters that are spread across multiple blocks, such as 'Basic Latin' and 'Latin Extended-B'. On the other hand, the Latin script does not contain all the characters of the "Basic Latin" block (also known as ASCII): it includes only the letters, and not, for example, the digits nor the punctuation.

For blocks see http://www.unicode.org/Public/UNIDATA/Blocks.txt

For scripts see UTR #24: http://www.unicode.org/reports/tr24/

Matching Scripts and Blocks

Scripts are matched with the regular-expression construct "\p{...}" (e.g. "\p{Tibetan}" matches characters of the Tibetan script), while "\p{Blk=...}" is used for blocks (e.g. "\p{Blk=Tibetan}" matches any of the 256 code points in the Tibetan block).

Old-style versus new-style block names

Unicode publishes the names of blocks in two different styles, though the two are equivalent under Unicode's loose matching rules.

The original style uses blanks and hyphens in the block names (except for "No_Block"), like so:

Miscellaneous Mathematical Symbols-B

The newer style replaces these with underscores, like this:

Miscellaneous_Mathematical_Symbols_B

This newer style is consistent with the values of other Unicode properties. To preserve backward compatibility, all the functions in Unicode::UCD that return block names (except as noted) return the old-style ones. "prop_value_aliases()" returns the new-style and can be used to convert from old-style to new-style:

my $new_style = prop_values_aliases("block", $old_style);

Perl also has single-form extensions that refer to blocks, "In_Cyrillic", meaning "Block=Cyrillic". These have always been written in the new style.

To convert from new-style to old-style, follow this recipe:

$old_style = charblock((prop_invlist("block=$new_style"))[0]);

(which finds the range of code points in the block using "prop_invlist", gets the lower end of the range (0th element) and then looks up the old name for its block using "charblock").

Note that starting in Unicode 6.1, many of the block names have shorter synonyms. These are always given in the new style.

Use with older Unicode versions

The functions in this module work as well as can be expected when used on earlier Unicode versions. But, obviously, they use the available data from that Unicode version. For example, if the Unicode version predates the definition of the script property (Unicode 3.1), then any function that deals with scripts is going to return "undef" for the script portion of the return value.
