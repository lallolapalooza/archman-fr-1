UNIVERSAL(3perl) Guide de référence du programmeur Perl UNIVERSAL(3perl)

NOM

UNIVERSAL - classe de base pour TOUTES les classes (références bénies)

SYNTAXE

my $obj_is_io    = $fd->isa("IO::Handle");
my $cls_is_io    = Class->isa("IO::Handle");
my $obj_does_log = $obj->DOES("Logger");
my $cls_does_log = Class->DOES("Logger");
my $obj_sub      = $obj->can("print");
my $cls_sub      = Class->can("print");
my $eval_sub     = eval { $ref->can("fandango") };
my $ver          = $obj->VERSION;
# mais ne faites jamais ça !
my $is_io        = UNIVERSAL::isa($fd, "IO::Handle");
my $sub          = UNIVERSAL::can($obj, "print");

DESCRIPTION

"UNIVERSAL" est la classe de base de laquelle héritent toutes les références bénies. Voir perlobj.

"UNIVERSAL" fournit les méthodes suivantes :

"$obj->isa( TYPE )"
"CLASS->isa( TYPE )"
"eval { VAL->isa( TYPE ) }"
Où
"TYPE"
est un nom de paquet
$obj
est une référence bénie ou un nom de paquet
"CLASS"
est un nom de paquet
"VAL"
est l'un des éléments ci-dessus ou une référence non bénie

Lorsqu'elle est utilisée comme méthode d'instance ou de classe ("$obj->isa( TYPE )"), "isa" retourne *vrai* si $obj est béni dans le paquet "TYPE" ou hérite du paquet "TYPE".

Lorsqu'elle est utilisée comme méthode de classe ("CLASS->isa( TYPE )"), parfois appelée méthode statique), "isa" retourne *vrai* si "CLASS" hérite du nom du paquet "TYPE" (ou est ce nom) ou hérite du paquet "TYPE".

Si vous n'êtes pas sûr de ce que vous avez (cas "VAL"), enveloppez l'appel de méthode dans un bloc "eval" pour intercepter l'exception si "VAL" est indéfini ou une référence non bénie. L'opérateur "isa" est une alternative qui retourne simplement faux dans ce cas, donc l'"eval" n'est pas nécessaire.

Si vous voulez être sûr que vous appelez "isa" sur une instance, et non une classe, vérifiez l'invocant avec "blessed" de Scalar::Util d'abord :

use Scalar::Util 'blessed';
if ( blessed( $obj ) && $obj->isa("Some::Class") ) {
    ...
}
"$obj->DOES( ROLE )"
"CLASS->DOES( ROLE )"
"DOES" vérifie si l'objet ou la classe exécute le rôle "ROLE". Un rôle est un groupe nommé de comportements spécifiques (souvent des méthodes de noms et signatures particuliers), similaire à une classe, mais pas nécessairement une classe complète en soi. Par exemple, la journalisation ou la sérialisation peuvent être des rôles.

"DOES" et "isa" sont similaires, en ce sens que si l'un est vrai, vous savez que l'objet ou la classe sur lequel la méthode est appelée peut exécuter des comportements spécifiques. Cependant, "DOES" est différent de "isa" en ce qu'il ne se soucie pas de *comment* l'invocant exécute les opérations, seulement qu'il le fait. ("isa" impose bien sûr une relation d'héritage. D'autres relations incluent l'agrégation, la délégation et la simulation.)

Par défaut, les classes en Perl n'exécutent que le rôle "UNIVERSAL", ainsi que le rôle de toutes les classes dans leur héritage. En d'autres termes, par défaut "DOES" répond de manière identique à "isa".

Il existe une relation entre les rôles et les classes, car chaque classe implique l'existence d'un rôle du même nom. Il existe aussi une relation entre l'héritage et les rôles, car une sous-classe qui hérite d'une classe ancêtre exécute implicitement tous les rôles que son parent exécute. Ainsi, vous pouvez utiliser "DOES" à la place de "isa" en toute sécurité, car il renverra vrai dans tous les cas où "isa" renverra vrai (à condition que les méthodes "DOES" *et* "isa" surchargées se comportent correctement).

"$obj->can( METHOD )"
"CLASS->can( METHOD )"
"eval { VAL->can( METHOD ) }"
"can" vérifie si l'objet ou la classe a une méthode appelée "METHOD". Si c'est le cas, il renvoie une référence vers la sous-routine. Sinon, il renvoie *undef*. Cela inclut les méthodes héritées ou importées par $obj, "CLASS", ou "VAL".

"can" ne peut pas savoir si un objet sera capable de fournir une méthode via AUTOLOAD (sauf si la classe de l'objet a surchargé "can" correctement), donc une valeur de retour de *undef* ne signifie pas nécessairement que l'objet ne pourra pas gérer l'appel de méthode. Pour contourner cela, certains auteurs de modules utilisent une déclaration anticipée (voir perlsub) pour les méthodes qu'ils géreront via AUTOLOAD. Pour de telles sous-routines 'factices', "can" renverra toujours une référence de code qui, lorsqu'elle sera appelée, basculera vers AUTOLOAD. Si aucun AUTOLOAD approprié n'est fourni, l'appel de la référence de code provoquera une erreur.

Vous pouvez appeler "can" en tant que méthode de classe (statique) ou méthode d'objet.

Encore une fois, la même règle concernant un invocant valide s'applique -- utilisez un bloc "eval" ou "blessed" si vous avez besoin d'être particulièrement prudent.

"VERSION ( [ REQUIRE ] )"
"VERSION" renverra la valeur de la variable $VERSION dans le paquet auquel l'objet est béni. Si "REQUIRE" est donné, alors il effectuera une comparaison et mourra si la version du paquet n'est pas supérieure ou égale à "REQUIRE", ou si $VERSION ou "REQUIRE" ne sont pas des nombres de version "laxis" (tels que définis par le module version).

La valeur de retour de "VERSION" sera en fait la version sérialisée en chaîne de caractères en utilisant le scalaire $VERSION du paquet, qui est garanti d'être équivalent mais peut ne pas être précisément le contenu du scalaire $VERSION. Si vous voulez le contenu réel de $VERSION, utilisez plutôt $CLASS::VERSION.

"VERSION" peut être appelé en tant que méthode de classe (statique) ou méthode d'objet.

AVERTISSEMENTS

NOTE : "can" utilise directement le code interne de Perl pour la recherche de méthodes, et "isa" utilise une méthode et une stratégie de mise en cache très similaires. Cela peut entraîner des effets étranges si le code Perl modifie dynamiquement @ISA dans un paquet quelconque.

Vous pouvez ajouter d'autres méthodes à la classe UNIVERSAL via du code Perl ou XS. Vous n'avez pas besoin de "use UNIVERSAL" pour rendre ces méthodes disponibles à votre programme (et vous ne devriez pas le faire).

EXPORTATIONS

Aucune.

Les versions précédentes de cette documentation suggéraient d'utiliser "isa" comme une fonction pour déterminer le type d'une référence :

$yes = UNIVERSAL::isa($h, "HASH");
$yes = UNIVERSAL::isa("Foo", &quo
t;Bar");

Le problème est que ce code n'appellerait *jamais* une méthode "isa" redéfinie dans aucune classe. Au lieu de cela, utilisez "reftype" de Scalar::Util pour le premier cas :

use Scalar::Util 'reftype';
$yes = reftype( $h ) eq "HASH";

et la forme méthode de "isa" pour le second :

$yes = Foo->isa("Bar");
