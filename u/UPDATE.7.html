NOM

UPDATE - mettre à jour les lignes d'une table

SYNTAXE

[ WITH [ RECURSIVE ] requete_avec [, ...] ]
UPDATE [ ONLY ] nom_table [ * ] [ [ AS ] alias ]
    SET { nom_colonne = { expression | DEFAULT } |
          ( nom_colonne [, ...] ) = [ ROW ] ( { expression | DEFAULT } [, ...] ) |
          ( nom_colonne [, ...] ) = ( sous-SELECT )
        } [, ...]
    [ FROM element_from [, ...] ]
    [ WHERE condition | WHERE CURRENT OF nom_curseur ]
    [ RETURNING [ WITH ( { OLD | NEW } AS alias_sortie [, ...] ) ]
                { * | expression_sortie [ [ AS ] nom_sortie ] } [, ...] ]

DESCRIPTION

UPDATE modifie les valeurs des colonnes spécifiées dans toutes les lignes qui satisfont la condition. Seules les colonnes à modifier doivent être mentionnées dans la clause SET ; les colonnes non explicitement modifiées conservent leurs valeurs précédentes.

Il existe deux façons de modifier une table en utilisant des informations contenues dans d'autres tables de la base de données : en utilisant des sous-requêtes, ou en spécifiant des tables supplémentaires dans la clause FROM. La technique la plus appropriée dépend des circonstances spécifiques.

La clause RETURNING optionnelle provoque le calcul et le retour de valeurs par UPDATE, basés sur chaque ligne effectivement mise à jour. Toute expression utilisant les colonnes de la table, et/ou les colonnes d'autres tables mentionnées dans FROM, peut être calculée. Par défaut, les nouvelles valeurs (après mise à jour) des colonnes de la table sont utilisées, mais il est également possible de demander les anciennes valeurs (avant mise à jour). La syntaxe de la liste RETURNING est identique à celle de la liste de sortie de SELECT.

Vous devez avoir le privilège UPDATE sur la table, ou au moins sur la ou les colonnes listées pour être mises à jour. Vous devez également avoir le privilège SELECT sur toute colonne dont les valeurs sont lues dans les expressions ou la condition.

PARAMÈTRES

requete_avec

La clause WITH permet de spécifier une ou plusieurs sous-requêtes qui peuvent être référencées par leur nom dans la requête UPDATE. Voir la Section 7.8 et SELECT(7) pour plus de détails.

nom_table

Le nom (éventuellement qualifié par un schéma) de la table à mettre à jour. Si ONLY est spécifié avant le nom de la table, les lignes correspondantes sont mises à jour uniquement dans la table nommée. Si ONLY n'est pas spécifié, les lignes correspondantes sont également mises à jour dans toutes les tables héritant de la table nommée. Optionnellement, * peut être spécifié après le nom de la table pour indiquer explicitement que les tables descendantes sont incluses.

alias

Un nom substitut pour la table cible. Lorsqu'un alias est fourni, il masque complètement le nom réel de la table. Par exemple, pour UPDATE foo AS f, le reste de l'instruction UPDATE doit faire référence à cette table comme f et non foo.

nom_colonne

Le nom d'une colonne dans la table nommée par nom_table. Le nom de la colonne peut être qualifié par un nom de sous-champ ou un indice de tableau, si nécessaire. N'incluez pas le nom de la table dans la spécification d'une colonne cible — par exemple, UPDATE table_name SET table_name.col = 1 est invalide.

expression

Une expression à assigner à la colonne. L'expression peut utiliser les anciennes valeurs de cette colonne et d'autres colonnes de la table.

DEFAULT

Définit la colonne à sa valeur par défaut (qui sera NULL s'il n'y a pas d'expression par défaut spécifique qui lui a été assignée). Une colonne identitaire sera définie à une nouvelle valeur générée par la séquence associée. Pour une colonne générée, spécifier ceci est autorisé mais spécifie simplement le comportement normal de calcul de la colonne à partir de son expression de génération.

sous-SELECT

Une sous-requête SELECT qui produit autant de colonnes de sortie qu'il y en a dans la liste de colonnes entre parenthèses qui la précède. La sous-requête ne doit renvoyer qu'une seule ligne lorsqu'elle est exécutée. Si elle renvoie une ligne, ses valeurs de colonne sont assignées aux colonnes cibles ; si elle ne renvoie aucune ligne, des valeurs NULL sont assignées aux colonnes cibles. La sous-requête peut faire référence aux anciennes valeurs de la ligne actuelle de la table en cours de mise à jour.

element_from

Une expression de table permettant aux colonnes d'autres tables d'apparaître dans la condition WHERE et les expressions de mise à jour. Ceci utilise la même syntaxe que la clause FROM d'une instruction SELECT ; par exemple, un alias pour le nom de la table peut être spécifié. Ne répétez pas la table cible comme element_from à moins d'avoir l'intention d'une jointure externe (auquel cas elle doit apparaître avec un alias dans element_from).

condition

Une expression qui retourne une valeur de type booléen. Seules les lignes pour lesquelles cette expression retourne vrai seront mises à jour.

nom_curseur

Le nom du curseur à utiliser dans une condition WHERE CURRENT OF. La ligne à mettre à jour est celle qui a été le plus récemment extraite de ce curseur. Le curseur doit être une requête sans regroupement sur la table cible de l'UPDATE. Notez que WHERE CURRENT OF ne peut pas être spécifié en même temps qu'une condition booléenne. Voir DECLARE(7) pour plus d'informations sur l'utilisation de curseurs avec WHERE CURRENT OF.

alias_sortie

Un nom substitut optionnel pour les lignes OLD ou NEW dans la liste RETURNING.

Par défaut, les anciennes valeurs de la table cible peuvent être renvoyées en écrivant OLD.nom_colonne ou OLD.*, et les nouvelles valeurs peuvent être renvoyées en écrivant NEW.nom_colonne ou NEW.*. Lorsqu'un alias est fourni, ces noms sont masqués et les lignes anciennes ou nouvelles doivent être référencées en utilisant l'alias. Par exemple RETURNING WITH (OLD AS o, NEW AS n) o.*, n.*.

expression_sortie

Une expression à calculer et à retourner par la commande UPDATE après la mise à jour de chaque ligne. L'expression peut utiliser tous les noms de colonnes de la table nommée par nom_table ou les tables listées dans FROM. Écrire * pour retourner toutes les colonnes.

Un nom de colonne ou * peut être qualifié en utilisant OLD ou NEW, ou l'alias_sortie correspondant pour OLD ou NEW, pour provoquer le retour d'anciennes ou nouvelles valeurs. Un nom de colonne non qualifié, ou *, ou un nom de colonne ou * qualifié en utilisant le nom de la table cible ou un alias retournera de nouvelles valeurs.

nom_sortie

Un nom à utiliser pour une colonne retournée.

SORTIES

Au terme de son exécution, une commande UPDATE retourne une étiquette de commande de la forme

UPDATE compte

Le compte est le nombre de lignes mises à jour, y compris les lignes correspondantes dont les valeurs n'ont pas changé. Notez que le nombre peut être inférieur au nombre de lignes qui correspondent à la condition lorsque les mises à jour ont été supprimées par un déclencheur BEFORE UPDATE. Si compte est 0, aucune ligne n'a été mise à jour par la requête (ceci n'est pas considéré comme une erreur).

Si la commande UPDATE contient une clause RETURNING, le résultat ressemblera à celui d'une instruction SELECT contenant les colonnes et les valeurs définies dans la liste RETURNING, calculées sur la ou les lignes mises à jour par la commande.

NOTES

Lorsqu'une clause FROM est présente, ce qui se produit essentiellement est que la table cible est jointe aux tables mentionnées dans la liste element_from, et chaque ligne de sortie de la jointure représente une opération de mise à jour pour la table cible. En utilisant FROM, vous devriez vous assurer que la jointure produit au plus une ligne de sortie pour chaque ligne à modifier. En d'autres termes, une ligne cible ne devrait pas joindre plus d'une ligne des autres tables. Si c'est le cas, seule l'une des lignes de jointure sera utilisée pour mettre à jour la ligne cible, mais celle qui sera utilisée n'est pas facilement prévisible.

En raison de cette indétermination, référencer d'autres tables uniquement dans des sous-requêtes est plus sûr, bien que souvent plus difficile à lire et plus lent que d'utiliser une jointure.

Dans le cas d'une table partitionnée, la mise à jour d'une ligne peut la faire ne plus satisfaire la contrainte de partition de la partition contenante. Dans ce cas, s'il existe une autre partition dans l'arbre de partition pour laquelle cette ligne satisfait sa contrainte de partition, alors la ligne est déplacée vers cette partition. S'il n'existe pas de telle partition, une erreur se produira. En coulisses, le déplacement de la ligne est en fait une opération DELETE et INSERT.

Il est possible qu'un UPDATE ou DELETE concurrent sur la ligne déplacée provoque une erreur de sérialisation. Supposons que la session 1 effectue un UPDATE sur une clé de partition, et pendant ce temps, une session 2 concurrente pour laquelle cette ligne est visible

Dans un tel cas, l'opération UPDATE ou DELETE de la session 2 détectera le déplacement de ligne et lèvera une erreur de défaillance de sérialisation (qui renvoie toujours avec un code SQLSTATE '40001'). Les applications peuvent souhaiter réessayer la transaction si cela se produit. Notez que si les lignes peuvent être déplacées de partitions locales vers une partition de table étrangère (à condition que le wrapper de données étrangères prenne en charge le routage de tuples), elles ne peuvent pas être déplacées d'une partition de table étrangère vers une autre partition.

Une tentative de déplacer une ligne d'une partition à une autre échouera si une clé étrangère est trouvée pour référencer directement un ancêtre de la partition source qui n'est pas le même que l'ancêtre mentionné dans la requête UPDATE.

EXEMPLES

Changez le mot Drama en Dramatic dans la colonne kind de la table films :

UPDATE films SET kind = 'Dramatic' WHERE kind = 'Drama';

Ajustez les entrées de température et réinitialisez les précipitations à leur valeur par défaut dans une ligne de la table weather :

UPDATE weather SET temp_lo = temp_lo+1, temp_hi = temp_lo+15, prcp = DEFAULT
  WHERE city = 'San Francisco' AND date = '2003-07-03';

Effectuez la même opération et renvoyez les entrées mises à jour, ainsi que l'ancienne valeur des précipitations :

UPDATE weather SET temp_lo = temp_lo+1, temp_hi = temp_lo+15, prcp = DEFAULT
  WHERE city = 'San Francisco' AND date = '2003-07-03'
  RETURNING temp_lo, temp_hi, prcp, old.prcp AS old_prcp;

Utilisez la syntaxe alternative de liste de colonnes pour effectuer la même mise à jour :

UPDATE weather SET (temp_lo, temp_hi, prcp) = (temp_lo+1, temp_lo+15, DEFAULT)
  WHERE city = 'San Francisco' AND date = '2003-07-03';

Incrémentez le nombre de ventes du vendeur qui gère le compte de Acme Corporation, en utilisant la syntaxe de la clause FROM :

UPDATE employees SET sales_count = sales_count + 1 FROM accounts
  WHERE accounts.name = 'Acme Corporation'
  AND employees.id = accounts.sales_person;

Effectuez la même opération, en utilisant une sous-requête dans la clause WHERE :

UPDATE employees SET sales_count = sales_count + 1 WHERE id =
  (SELECT sales_person FROM accounts WHERE name = 'Acme Corporation');

Mettez à jour les noms de contact dans une table de comptes pour qu'ils correspondent aux vendeurs actuellement assignés :

UPDATE accounts SET (contact_first_name, contact_last_name) =
    (SELECT first_name, last_name FROM employees
     WHERE employees.id = accounts.sales_person);

Un résultat similaire pourrait être obtenu avec une jointure :

UPDATE accounts SET contact_first_name = first_name,
                    contact_last_name = last_name
  FROM employees WHERE employees.id = accounts.sales_person;

Cependant, la deuxième requête peut donner des résultats inattendus si employees.id n'est pas une clé unique, tandis que la première requête garantit une erreur si plusieurs correspondances d'id existent. De plus, s'il n'y a pas de correspondance pour une entrée accounts.sales_person donnée, la première requête définira les champs de nom correspondants sur NULL, tandis que la deuxième requête ne mettra pas à jour cette ligne du tout.

Mettez à jour les statistiques dans une table de résumé pour correspondre aux données actuelles :

UPDATE summary s SET (sum_x, sum_y, avg_x, avg_y) =
    (SELECT sum(x), sum(y), avg(x), avg(y) FROM data d
     WHERE d.group_id = s.group_id);

Tentez d'insérer un nouvel article en stock avec la quantité de stock. Si l'article existe déjà, mettez plutôt à jour le décompte de stock de l'article existant. Pour ce faire sans échouer toute la transaction, utilisez des points de sauvegarde :

BEGIN;
-- autres opérations
SAVEPOINT sp1;
INSERT INTO wines VALUES('Chateau Lafite 2003', '24');
-- Supposons que l'opération ci-dessus échoue en raison d'une violation de clé unique,
-- alors nous émettons maintenant ces commandes :
ROLLBACK TO sp1;
UPDATE wines SET stock = stock + 24 WHERE winename = 'Chateau Lafite 2003';
-- continuez avec d'autres opérations, et éventuellement
COMMIT;

Modifiez la colonne kind de la table films dans la ligne sur laquelle le curseur c_films est actuellement positionné :

UPDATE films SET kind = 'Dramatic' WHERE CURRENT OF c_films;

Les mises à jour affectant de nombreuses lignes peuvent avoir des effets négatifs sur les performances du système, tels que le gonflement de la table, l'augmentation du décalage de réplication et l'augmentation de la contention des verrous. Dans de telles situations, il peut être judicieux d'effectuer l'opération par petits lots, éventuellement avec une opération VACUUM sur la table entre les lots. Bien qu'il n'y ait pas de clause LIMIT pour UPDATE, il est possible d'obtenir un effet similaire grâce à l'utilisation d'une Common Table Expression et d'une auto-jointure. Avec la méthode d'accès aux tables standard de PostgreSQL, une auto-jointure sur la colonne système ctid est très efficace :

WITH exceeded_max_retries AS (
  SELECT w.ctid FROM work_item AS w
    WHERE w.status = 'active' AND w.num_retries > 10
    ORDER BY w.retry_timestamp
    FOR UPDATE
    LIMIT 5000
)
UPDATE work_item SET status = 'failed'
  FROM exceeded_max_retries AS emr
  WHERE work_item.ctid = emr.ctid;

Cette commande devra être répétée jusqu'à ce qu'il ne reste plus de lignes à mettre à jour. L'utilisation d'une clause ORDER BY permet à la commande de prioriser les lignes à mettre à jour ; elle peut également éviter les interblocages avec d'autres opérations de mise à jour si celles-ci utilisent le même ordre. Si la contention de verrouillage est une préoccupation, alors SKIP LOCKED peut être ajouté à la CTE pour empêcher plusieurs commandes de mettre à jour la même ligne. Cependant, une dernière UPDATE sans SKIP LOCKED ou LIMIT sera alors nécessaire pour garantir qu'aucune ligne correspondante n'a été négligée.

COMPATIBILITÉ

Cette commande est conforme à la norme SQL, à l'exception des clauses FROM et RETURNING qui sont des extensions PostgreSQL, tout comme la possibilité d'utiliser WITH avec UPDATE.

D'autres systèmes de bases de données proposent une option FROM dans laquelle la table cible est censée être répertoriée à nouveau dans FROM. Ce n'est pas ainsi que PostgreSQL interprète FROM. Soyez prudent lorsque vous portez des applications utilisant cette extension.

Selon la norme, la valeur source pour une sous-liste entre parenthèses de noms de colonnes cibles peut être n'importe quelle expression de ligne produisant le nombre correct de colonnes. PostgreSQL n'autorise que la valeur source à être un constructeur de ligne ou une sous-SELECT. La valeur mise à jour d'une colonne individuelle peut être spécifiée comme DEFAULT dans le cas du constructeur de ligne, mais pas à l'intérieur d'une sous-SELECT.
