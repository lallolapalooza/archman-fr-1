DESCRIPTIO

N

Un gestionnaire de chaîne d'outils DocBook qui traduit un fichier texte AsciiDoc FICHIER_SOURCE en PDF, EPUB, DVI, PS, LaTeX, XHTML (page unique ou fragmenté), page de manuel, HTML Help ou formats texte brut en utilisant asciidoc(1) et d'autres applications (voir la section PRÉREQUIS). FICHIER_SOURCE peut aussi être un f

ichier DocBook avec
une extension .xml.

OPTION

S

-a, --attribute=ATTRIBU

T
Définir la valeur d'attribut de asciidoc(1) (raccourci pour --asciidoc-opts="-a ATTRIBUT" option). Cette option peut être spécifiée plus d'une
fois.

--asciidoc-opts=OPTIONS_ASCIIDO

C
Options asciidoc(1) supplémentaires. Cette option peut être spécifiée plus d'une
fois.

--conf-file=FICHIER_CON

F
Charger le fichier de configuration. Voir la section FICHIERS DE
CONF.

-D, --destination-dir=RÉPERTOIRE_DESTINATIO

N
Répertoire de sortie. Par défaut, le répertoire de FICHIER_SOURCE. Cette option ne s'applique qu'aux formats de sortie basés sur HTML et les pages de manuel (chunked, epub, htmlhelp, xhtml, manpag

-d, --doctype=TYPE_DOCUME

NT
Type de document DocBook : article, manpage ou book. Le type de document par défaut est article sauf si le format est manpage (auquel cas il est par défaut manpag

FICHIERS DE

SORTIE

Les fichiers de sortie sont écrits dans le répertoire spécifié par l'option --destination-dir. Si aucune option --destination-dir n'est définie, les fichiers de sortie sont écrits dans le répertoire de FICHIER_SOURCE

.

Les fichiers de sortie ont le même nom que le FICHIER_SOURCE mais avec une extension de nom de fichier appropriée : .html pour xhtml ; .epub pour epub ; .hhp pour htmlhelp ; .pdf pour pdf ; .text pour text, .xml pour docbook. Par convention, les pages de manuel n'ont pas d'extension .man (seulement le numéro de section de la page de manuel). Les noms de répertoires HTML fragmentés ont une extension .chunked ; les noms de répertoires HTML Help fragmentés ont une extension .

htmlhelp.

Les fichiers existants portant le même nom sont

écrasés.

En plus de générer des fichiers HTML, les formats xhtml, epub, chunked et htmlhelp s'assurent que les fichiers de ressources sont copiés v

ers leurs emplacements corrects da
ns les répertoires de destination.

RESSOURCE

S

Les ressources sont des fichiers (généralement CSS et images) nécessaires aux sorties basées sur HTML (xhtml, epub, chunked, formats htmlhelp). a2x analyse les fichiers HTML générés et construit une liste des fichiers CSS et d'images nécessaires. Des fichiers de ressources supplémentaires peuvent être spécifiés explicitement en utilisant l'option --resource

.

a2x recherche les fichiers de ressources aux emplacements suivants dans l'ordre suivant

:
1.Le répertoire de FICHIER_SOURCE
.
2.Les répertoires de ressources spécifiés par l'option --resource (recherchés récursivement)
.
3.Les répertoires de ressources spécifiés par l'option --resource-manifest (recherchés récursivement dans l'ordre où ils apparaissent dans le fichier manifeste)
.
4.Les répertoires d'images et de feuilles de style standards dans le

RESOURCES

Les fichiers de ressources sont recherchés dans le répertoire de sortie (ou DESTINATION_DIR) dans cet ordre :

1. Les fichiers de ressources spécifiés avec l'option --resource.
2. Les répertoires de configuration de asciidoc(1) (recherchés récursivement).
3. Le répertoire de destination.

Lorsqu'un fichier de ressource est trouvé, il est copié dans le répertoire de destination relatif correct. Les sous-répertoires de destination manquants sont créés automatiquement.

Il existe deux mécanismes distincts pour spécifier des ressources supplémentaires :

1. Un répertoire de ressources qui sera recherché récursivement pour les fichiers de ressources manquants.
2. Un fichier de ressources qui sera copié dans le répertoire de destination de sortie.

Les ressources sont spécifiées avec des valeurs d'option --resource qui peuvent être l'un des formats suivants :

<resource_dir>
<resource_file>[=<destination_file>]
.<ext>=<mimetype>

Où :

<resource_dir>

Spécifie un répertoire (absolu ou relatif au SOURCE_FILE) qui est recherché récursivement pour les fichiers de ressources manquants. Pour éliminer l'ambiguïté, le nom <resource_dir> doit se terminer par un caractère séparateur de répertoire.

<resource_file>

Spécifie un fichier de ressources (absolu ou relatif au SOURCE_FILE) qui sera copié vers <destination_file>. Si <destination_file> n'est pas spécifié, il est le même que <resource_file>.

<destination_file>

Spécifie la destination du fichier source copié. Le chemin <destination_file> est relatif au répertoire de destination (les chemins absolus ne sont pas autorisés). L'emplacement du répertoire de destination dépend du FORMAT de sortie (voir la section OUTPUT FILES pour plus de détails) :

chunked, htmlhelp

Le répertoire de sortie découpé.

epub

Le répertoire archivé OEBPS.

xhtml

Le DESTINATION_DIR de sortie.

.<ext>=<mimetype>

Lors de l'ajout de ressources aux fichiers EPUB, le mimetype est déduit de l'extension du fichier de destination. Si le mimetype ne peut pas être deviné, une erreur se produit. La syntaxe de ressource .<ext>=<mimetype> peut être utilisée pour définir explicitement les mimetypes. <ext> est l'extension du nom de fichier, <mimetype> est le type MIME correspondant.

Exemples d'options de ressources :

--resource ../images/
--resource doc/README.txt=README.txt
--resource ~/images/tiger.png=images/tiger.png
--resource .ttf=application/x-font-ttf

EXEMPLES

a2x -f pdf doc/source-highlight-filter.txt

Génère le fichier doc/source-highlight-filter.pdf.

a2x -f xhtml -D ../doc --icons -r ../images/ team.txt

Crée le fichier HTML ../doc/team.html, utilise des icônes d'avertissement et recherche récursivement le répertoire ../images/ pour toutes les ressources manquantes.

a2x -f manpage doc/asciidoc.1.txt

Génère la page de manuel doc/asciidoc.1.

PRÉREQUIS

a2x utilise les programmes suivants :

•Asciidoc : https://asciidoc.org/
•xsltproc : (tous les formats sauf texte) : http://xmlsoft.org/XSLT/
•DocBook XSL Stylesheets (tous les formats sauf texte) : https://github.com/docbook/xslt10-stylesheets
•dblatex (formats pdf, dvi, ps, tex) : http://dblatex.sourceforge.net/
•FOP (format pdf — générateur de fichiers PDF alternatif) : https://xmlgraphics.apache.org/fop/
•w3m (format texte) : http://w3m.sourceforge.net/index.en.html
•Lynx (format texte — générateur de fichiers texte alternatif) : https://invisible-island.net/lynx/
•epubcheck (format epub — validateur de fichiers EPUB) : https://github.com/w3c/epubcheck

Voir également le dernier fichier README.

FICHIERS DE CONF

Un fichier de configuration contient du code Python exécutable qui remplace les paramètres de configuration globaux dans a2x.py. Les fichiers de configuration optionnels sont chargés dans l'ordre suivant :

1.a2x.conf du répertoire contenant l'exécutable a2x.py.
2.a2x.conf du répertoire de configuration global AsciiDoc. Ignorer cette étape si nous exécutons une copie installée localement (non systémique).
3.a2x.conf du répertoire de configuration $HOME/.asciidoc d'AsciiDoc.
4.Le CONF_FILE spécifié dans l'option --conf-file.

Voici les valeurs par défaut des options du fichier de configuration :

# Dictionnaire de variables d'environnement optionnelles passées aux
# programmes exécutés. Si défini sur None, l'environnement existant
# est utilisé.
ENV = None
# Exécutables externes.
ASCIIDOC = 'asciidoc'
XSLTPROC = 'xsltproc'
DBLATEX = 'dblatex'         # Génération PDF.
FOP = 'fop'                 # Génération PDF (option --fop).
W3M = 'w3m'                 # Générateur de fichiers texte principal.
LYNX = 'lynx'               # Générateur de fichiers texte alternatif.
XMLLINT = 'xmllint'         # Définir sur '' pour désactiver.
EPUBCHECK = 'epubcheck'     # Définir sur '' pour désactiver.
# Options par défaut des exécutables externes.
ASCIIDOC_OPTS = ''
BACKEND_OPTS = ''
DBLATEX_OPTS = ''
FOP_OPTS = ''
LYNX_OPTS = '-dump'
W3M_OPTS = '-dump -cols 70 -T text/html -no-graph'
XSLTPROC_OPTS = ''

Notez qu'il est possible de redéfinir W3M et LYNX pour utiliser différents navigateurs textuels, par exemple links : http://links.twibright.com/ ou elinks : http://elinks.or.cz/. LYNX_OPTS et W3M_OPTS peuvent être utilisés pour passer des options au navigateur sélectionné. S'ils sont définis, ils remplacent les valeurs par défaut respectives listées ci-dessus (n'oubliez donc pas d'inclure l'option -dump dans votre définition : elle est obligatoire au moins avec w3m, lynx, links et elinks afin d'envoyer le texte formaté vers stdout).
