AGE(1) Manuel des commandes générales AGE(1)

NOM

age - chiffrement de fichiers simple, moderne et sécurisé

SYNOPIS

age [--encrypt] (-r DESTINATAIRE | -R CHEMIN)... [--armor] [-o SORTIE] [ENTRÉE]
age [--encrypt] --passphrase [--armor] [-o SORTIE] [ENTRÉE]
age --decrypt [-i CHEMIN | -j PLUGIN]... [-o SORTIE] [ENTRÉE]

DESCRIPTION

age chiffre ou déchiffre ENTRÉE vers SORTIE. L'argument ENTRÉE est optionnel et utilise l'entrée standard par défaut. Un seul fichier ENTRÉE peut être spécifié. Si -o n'est pas spécifié, SORTIE utilise la sortie standard par défaut.

Si -p/--passphrase est spécifié, le fichier est chiffré avec une phrase secrète demandée interactivement. Sinon, il est chiffré pour un ou plusieurs DESTINATAIRES spécifiés avec -r/--recipient ou -R/--recipients-file. Chaque destinataire peut déchiffrer le fichier.

En mode -d/--decrypt, les fichiers chiffrés par phrase secrète sont détectés automatiquement et la phrase secrète est demandée interactivement. Sinon, un ou plusieurs IDENTITÉS spécifiés avec -i/--identity sont utilisés pour déchiffrer le fichier.

Les fichiers chiffrés par age sont binaires et non malléables, avec environ 200 octets de surcharge par destinataire, plus 16 octets tous les 64 Ko de texte brut.

OPTIONS

-o, --output=SORTIE
Écrit le fichier chiffré ou déchiffré vers SORTIE au lieu de la sortie standard. Si SORTIE existe déjà, elle sera écrasée.
Lors du chiffrement sans --armor, age refuse de sortir des données binaires vers un TTY. Ceci peut être forcé en spécifiant - comme SORTIE.
--version
Affiche la version et quitte.

Options de chiffrement

-e, --encrypt
Chiffre ENTRÉE vers SORTIE. C'est le comportement par défaut.
-r, --recipient=DESTINATAIRE
Chiffre pour le DESTINATAIRE explicitement spécifié. Voir la section DESTINATAIRES ET IDENTITÉS pour les formats possibles de destinataire.
Cette option peut être répétée et combinée avec d'autres indicateurs de destinataire, et le fichier peut être déchiffré par tous les destinataires fournis indépendamment.
-R, --recipients-file=CHEMIN
Chiffre pour les DESTINATAIRES listés dans le fichier à CHEMIN, un par ligne. Les lignes vides et celles commençant par # sont ignorées en tant que commentaires.
Si CHEMIN est -, les destinataires sont lus depuis l'entrée standard. Dans ce cas, l'argument ENTRÉE doit être spécifié.
Cette option peut être répétée et combinée avec d'autres indicateurs de destinataire, et le fichier peut être déchiffré par tous les destinataires fournis indépendamment.
-p, --passphrase
Chiffre avec une phrase secrète, demandée interactivement depuis le terminal. age proposera de générer automatiquement une phrase secrète sécurisée.
Cette option ne peut pas être utilisée avec d'autres indicateurs de destinataire.
-a, --armor
Chiffre dans un encodage ASCII uniquement, dit "blindé" (armored).
Le blindage d'age est une version stricte de PEM avec le type AGE ENCRYPTED FILE, du Base64 canonique "strict", pas d'en-têtes, et pas de support pour des données supplémentaires au début et à la fin.
Le déchiffrement détecte et décode automatiquement le blindage ASCII.
-i, --identity=CHEMIN
Chiffre pour les DESTINATAIRES correspondant aux IDENTITÉS listées dans le fichier à CHEMIN. Ceci est équivalent à convertir le fichier à CHEMIN en un fichier de destinataires avec age-keygen -y, puis à le passer à -R/--recipients-file.
Pour le format de CHEMIN, voir la définition de -i/--identity dans la section Options de déchiffrement.
-e/--encrypt doit être explicitement spécifié lors de l'utilisation de -i/--identity en mode chiffrement pour éviter toute confusion.
-j PLUGIN
Chiffre en utilisant le plugin sans données PLUGIN.
Ceci est équivalent à utiliser -i/--identity avec un fichier contenant une seule IDENTITÉ de plugin qui n'encode aucune donnée spécifique au plugin.
-e/--encrypt doit être explicitement spécifié lors de l'utilisation de -j en mode chiffrement pour éviter toute confusion.

Options de déchiffrement

-d, --decrypt
Déchiffre ENTRÉE vers SORTIE.
Si ENTRÉE est chiffrée par phrase secrète, elle sera automatiquement détectée et la phrase secrète sera demandée interactivement. Sinon, les IDENTITÉS spécifiées avec -i/--identity sont utilisées.
Le blindage ASCII est automatiquement détecté et décodé.
-i, --identity=CHEMIN
Déchiffre en utilisant les IDENTITÉS à CHEMIN.
CHEMIN peut être l'un des suivants :
a. Un fichier listant les IDENTITÉS une par ligne. Les lignes vides et celles commençant par "#" sont ignorées en tant que commentaires.
b. Un fichier age chiffré par phrase secrète, contenant des IDENTITÉS une par ligne comme ci-dessus. La phrase secrète est demandée interactivement. Notez que les fichiers d'identité protégés par phrase secrète ne sont pas nécessaires pour la plupart des cas d'utilisation, où l'accès au fichier d'identité chiffré implique l'accès à l'ensemble du système.
c. Un fichier de clé privée SSH, au format PKCS#1, PKCS#8 ou OpenSSH. Si la clé privée est protégée par mot de passe, le mot de passe est demandé interactivement uniquement si l'identité SSH correspond au fichier. Voir la section Clés SSH pour plus d'informations, y compris les types de clés supportés.
d. "-", ce qui fait lire l'une des options ci-dessus depuis l'entrée standard. Dans ce cas, l'argument ENTRÉE doit être spécifié.
Cette option peut être répétée. Les identités sont essayées dans l'ordre où elles sont fournies, et la première qui correspond à l'un des destinataires du fichier est utilisée. Les identités inutilisées sont ignorées, mais c'est une erreur si le fichier ENTRÉE est chiffré par phrase secrète et que -i/--identity est spécifié.
-j PLUGIN
Déchiffre en utilisant le plugin sans données PLUGIN.
Ceci est équivalent à utiliser -i/--identity avec un fichier contenant une seule IDENTITÉ de plugin qui n'encode aucune donnée spécifique au plugin.

DESTINATAIRES ET IDENTITÉS

Les DESTINATAIRES sont des valeurs publiques, comme une clé publique, vers lesquelles un fichier peut être chiffré. Les IDENTITÉS sont des valeurs privées, comme une clé privée, qui permettent de déchiffrer un fichier chiffré pour le DESTINATAIRE correspondant.

Clés X25519 natives

Les paires de clés age natives sont générées avec age-keygen(1) et fournissent des encodages petits et un chiffrement fort basé sur X25519. Elles sont le type de destinataire recommandé pour la plupart des applications.

Un encodage de DESTINATAIRE commence par age1 et ressemble à ce qui suit :

a

Ce site n'est en aucun cas associé à Arch Linux ni affilié à ce projet. Le contenu est uniquement une traduction des pages de manuel d'Arch publiées sur man.archlinux.org.

ge1gde3ncmahlqd9gg50tanl99r960llztrhfapnmx853s4tjum03uqfssgdh

Un IDENTITÉ commence par AGE-SECRET-KEY-1 et ressemble à ce qui suit :

AGE-SECRET-KEY-1KTYK6RVLN5TAPE7VF6FQQSKZ9HWWCDSKUGXXNUQDWZ7XXT5YK5LSF3UTKQ

Un fichier chiffré ne peut pas être lié au destinataire natif vers lequel il est chiffré sans accès à l'identité correspondante.

Clés SSH

Par commodité, age prend également en charge le chiffrement vers des clés ssh(1) RSA ou Ed25519. Les clés RSA doivent faire au moins 2048 bits. Cette fonctionnalité utilise une cryptographie plus complexe et ne devrait être utilisée que lorsqu'une clé native n'est pas disponible pour le destinataire. Notez que les clés SSH peuvent ne pas être protégées à long terme par le destinataire, car elles sont révocables lorsqu'elles sont utilisées uniquement pour l'authentification.

Un DESTINATAIRE est une clé publique SSH au format authorized_keys (voir la SECTION FORMAT DE FICHIER AUTHORIZED_KEYS de sshd(8)), commençant par ssh-rsa ou ssh-ed25519, comme ceci :

ssh-rsa AAAAB3NzaC1yc2EAAAADAQABAAABgQDULTit0KUehbi[...]GU4BtElAbzh8=
ssh-ed25519 AAAAC3NzaC1lZDI1NTE5AAAAIH9pO5pz22JZEas[...]l1uZc31FGYMXa

Le commentaire à la fin de la ligne, s'il est présent, est ignoré.

Dans les fichiers de destinataires passés à -R/--recipients-file, les clés publiques SSH valides mais non prises en charge sont ignorées avec un avertissement, afin de faciliter l'utilisation des fichiers authorized_keys ou .keys de GitHub. (Voir EXEMPLES.)

Une IDENTITÉ est un fichier de clé privée SSH passé individuellement à -i/--identity. Notez que les clés stockées sur des jetons matériels tels que les YubiKeys ou accessibles via ssh-agent(1) ne sont pas prises en charge.

Un fichier chiffré peut être lié à la clé publique SSH vers laquelle il a été chiffré. Cela permet à age d'identifier la clé privée SSH correcte avant de demander son mot de passe, le cas échéant.

Plugins

age peut être étendu via des plugins. Un plugin n'est chargé que si un DESTINATAIRE ou IDENTITÉ correspondant est spécifié. (Le simple déchiffrement d'un fichier chiffré avec un plugin ne le fera pas se charger, pour des raisons de sécurité entre autres.)

Un DESTINATAIRE pour un plugin nommé example commence par age1example1, tandis qu'une IDENTITÉ commence par AGE-PLUGIN-EXAMPLE-1. Tous deux encodent des données arbitraires spécifiques au plugin et sont générés par le plugin.

Lorsque l'un ou l'autre est spécifié, age recherche age-plugin-example dans le PATH et l'exécute pour effectuer le chiffrement ou le déchiffrement de l'en-tête du fichier. Le plugin peut demander une saisie à l'utilisateur via age pour terminer l'opération.

Les plugins peuvent être librement mélangés avec d'autres plugins ou des clés prises en charge nativement.

Un plugin n'est pas limité à chiffrer ou déchiffrer uniquement les fichiers destinés ou générés par le plugin. Par exemple, un plugin peut être utilisé pour déchiffrer des fichiers chiffrés vers un destinataire X25519 natif DESTINATAIRE ou même avec une phrase secrète. De même, un plugin peut chiffrer un fichier de sorte qu'il puisse être déchiffré sans utiliser aucun plugin.

Pour les plugins pour lesquels la distinction IDENTITÉ/DESTINATAIRE n'a pas de sens (comme un plugin de chiffrement symétrique), il peut ne générer qu'une IDENTITÉ et indiquer à l'utilisateur d'effectuer le chiffrement avec les -e/--encrypt et -i/--identity . Pour les plugins pour lesquels le concept d'identités séparées n'a pas de sens (comme un plugin de chiffrement par mot de passe), il peut indiquer à l'utilisateur d'utiliser l'option -j .

CODE DE RETOUR

age se terminera par 0 si et seulement si le chiffrement ou le déchiffrement sont réussis sur toute la longueur de l'entrée.

Si une erreur survient lors du déchiffrement, une sortie partielle peut être générée, mais seulement s'il a été possible de l'authentifier de manière sécurisée. Aucune sortie non authentifiée n'est jamais libérée.

COMPATIBILITÉ DESCENDANTE

Les fichiers chiffrés avec une version stable (ni alpha, ni bêta, ni version candidate de age), ou avec n'importe quelle bêta ou version candidate de la v1.0.0, seront déchiffrés avec toute version ultérieure de l'outil.

Si le déchiffrement de fichiers plus anciens pose un risque de sécurité, cela peut provoquer une erreur par défaut. Dans ce cas, une option sera fournie pour forcer l'opération.

EXEMPLES

Générer une nouvelle identité, chiffrer des données et déchiffrer :

$ age-keygen -o key.txt
Clé publique : age1ql3z7hjy54pw3hyww5ayyfg7zqgvc7w3j2elw8zmrj2kg5sfn9aqmcac8p
$ tar cvz ~/data | age -r age1ql3z7hjy54pw3hyww5ayyfg7zqgvc7w3j2elw8zmrj2kg5sfn9aqmcac8p > data.tar.gz.age
$ age -d -o data.tar.gz -i key.txt data.tar.gz.age

Chiffrer example.jpg vers plusieurs destinataires et sortir vers example.jpg.age:

$ age -o example.jpg.age -r age1ql3z7hjy54pw3hyww5ayyfg7zqgvc7w3j2elw8zmrj2kg5sfn9aqmcac8p \
    -r age1lggyhqrw2nlhcxprm67z43rta597azn8gknawjehu9d9dl0jq3yqqvfafg example.jpg

Chiffrer vers une liste de destinataires :

$ cat > recipients.txt
# Alice
age1ql3z7hjy54pw3hyww5ayyfg7zqgvc7w3j2elw8zmrj2kg5sfn9aqmcac8p
# Bob
age1lggyhqrw2nlhcxprm67z43rta597azn8gknawjehu9d9dl0jq3yqqvfafg
$ age -R recipients.txt example.jpg > example.jpg.age

Chiffrer et déchiffrer un fichier avec une phrase secrète :

$ age -p secrets.txt > secrets.txt.age
