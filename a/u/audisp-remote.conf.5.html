DESCRIPTIO

N

audisp-remote.conf est le fichier qui contrôle la configuration du sous-système de journalisation d'audit distante. Les options disponibles sont les suivantes

:
remote_serv
er
Il s'agit d'une chaîne de caractères d'un seul mot qui est le nom d'hôte ou l'adresse du serveur distant vers lequel ce plugin enverra les informations de journal. Il peut s'agir de l'adresse numérique ou d'un nom d'hôte
résoluble.
po
rt
Cette option est un entier non signé qui indique le port sur lequel se connecter sur la machine
distante.
local_po
rt
Cette option est un entier non signé qui indique le port local à partir duquel se connecter sur la machine locale. S'il n'est pas spécifié (par défaut) ou s'il est défini sur le mot any, alors n'importe quel port non privilégié disponible est utilisé. C'est un mécanisme de sécurité pour empêcher les applications utilisateur non fiables d'injecter des événements dans le démon d'audit. Vous devriez le définir sur un port inutilisé < 1024 pour vous assurer que seuls les utilisateurs privilégiés peuvent se lier à ce port. Définissez également tcp_client_ports dans le fichier auditd.conf agrégant pour qu'il corresponde aux ports à partir desquels les clients
envoient.
transpo
rt
Ce paramètre indique à l'application de journalisation distante comment envoyer les événements au système distant. Les options valides sont TCP et KRB5. S'il est défini sur TCP, l'application de journalisation distante établira simplement une connexion normale en texte clair avec le système distant. S'il est défini sur KRB5, alors Kerberos 5 sera utilisé pour l'authentification et le chiffrement. La valeur par défaut est
TCP.
mo
de
Ce paramètre indique à l'application de journalisation distante quelle stratégie utiliser pour envoyer les enregistrements au système distant. Les valeurs valides sont immediate et forward. S'il est défini sur immediate, l'application de journalisation distante tentera d'envoyer les événements immédiatement après les avoir reçus. forward signifie qu'elle stockera les événements sur disque puis tentera d'envoyer les enregistrements. Si la connexion ne peut pas être établie, elle mettra les enregistrements en file d'attente jusqu'à ce qu'elle puisse se connecter au système distant. La profondeur de la file d'attente est contrôlée par l'option queue_dept
h.
queue_fi
le
Chemin d'un fichier utilisé pour la file d'attente des événements si mode est défini sur forward. La valeur par défaut est /var/spool/audit/re
mote.log.
queue_dep
th
Cette option est un entier non signé qui détermine combien d'enregistrements peuvent être mis en mé tampon sur disque ou en mémoire avant de considérer qu'il s'agit d'un échec d'envoi. Ce paramètre affecte le mode forward de l'option mode et la mise en file d'attente interne pour les pannes réseau temporaires. La profondeur par défaut est
2048.
form
at
Ce paramètre indique à l'application de journalisation distante quel format de données sera utilisé pour les messages envoyés sur le réseau. La valeur par défaut est managed qui ajoute un certain surcoût pour s'assurer que chaque message est correctement traité à l'extrémité distante, et pour recevoir les messages de statut du serveur distant. Si ascii est donné à la place, chaque message est une simple ligne de texte ASCII sans aucun surcoût. Le format ascii est un protocole très simpliste. S'il y a des problèmes réseau, cela provoquera la sortie d'audisp-remote. Auditd peut ou non le redémarrer au prochain événement. Si quelque chose de plus robuste est nécessaire, utilisez le format managed. Si mode est défini sur forward, format doit être manage
d.
network_retry_t
ime
Le temps, en secondes, entre les nouvelles tentatives lorsqu'une erreur réseau est détectée. Notez que cette pause s'applique à partir de la deuxième tentative, afin d'éviter des retards inutiles si une reconnexion suffit à résoudre le problème. La valeur par défaut est 1
seconde.
max_tries_per_rec
ord
Le nombre maximal de tentatives pour livrer chaque message. La valeur minimale est un, car même une livraison complètement réussie nécessite au moins une tentative. Si trop de tentatives sont effectuées, l'action network_failure_action est effectuée. La valeur par défaut est
3.
max_time_per_rec
ord
Le temps maximal, en secondes, passé à tenter de livrer chaque message. Notez que cet élément et max_tries_per_record devraient être définis, car chaque tentative peut prendre du temps avant d'expirer. La valeur par défaut est 5 secondes. Si trop de temps est utilisé pour un message, l'action network_failure_action est
effectuée.
heartbeat_time
out
Ce paramètre détermine à quelle fréquence, en secondes, le client doit envoyer un événement de battement de cœur au serveur distant. Cela permet au client et au serveur de savoir que chaque extrémité est vivante et n'a pas terminé d'une manière qui n'a pas fermé la connexion proprement. Cette valeur doit être coordonnée avec le paramètre tcp_client_max_idle du serveur. La valeur par défaut est 0, ce qui désactive l'envoi d'un battement de
cœur.
network_failure_act
ion
Ce paramètre indique au système quelle action entreprendre lorsqu'une erreur est détectée lors de l'envoi des événements d'audit au système distant. Les valeurs valides sont ignore, syslog, exec, warn_once, suspend, single, halt et stop. S'il est défini sur ignore, l'application de journalisation distante ne fait rien. Si un événement a été envoyé, il est retiré de la file d'attente. Syslog signifie qu'elle émettra un avertissement à syslog. Si un événement a été envoyé, il est retiré de la file d'attente. C'est la valeur par défaut. exec /chemin-vers-le-script exécutera le script. Vous ne pouvez pas passer de paramètres au script. Si un événement a été envoyé, il est retiré de la file d'attente. warn_once_continue est comme syslog sauf qu'un seul message est mis dans syslog jusqu'à ce qu'un événement soit transféré avec succès. warn_once est comme warn_once_continue sauf que l'événement n'est pas retiré de la file d'attente. Suspend fera arrêter l'application de journalisation distante d'envoyer des enregistrements au système distant. L'application de journalisation restera en vie. Si un événement a été envoyé, il n'est pas retiré de la file d'attente. L'option single fera passer l'application de journalisation distante l'ordinateur en mode utilisateur unique. Si un événement a été envoyé, il n'est pas retiré de la file d'attente. L'option stop fera sortir l'application de journalisation distante, mais laissera les autres plugins en cours d'exécution. Si un événement a été envoyé, il n'est pas retiré de la file d'attente. L'option halt fera arrêter l'application de journalisation distante l'ordinateur. Si un événement a été envoyé, il n'est pas retiré de la file d'attente. La valeur par défaut est
stop.
disk_low_act
ion
De même, ce paramètre indique au système quelle action entreprendre si l'extrémité distante signale une erreur de disque faible. La valeur par défaut est
ignore.
disk_full_act
ion
De même, ce paramètre indique au système quelle action entreprendre si l'extrémité distante signale une erreur de disque plein. La valeur par défaut est
warn_once.
disk_error_act
ion
De même, ce paramètre indique au système quelle action entreprendre si l'extrémité distante signale une erreur de disque. La valeur par défaut est
warn_once.
remote_ending_act
ion
De même, ce paramètre indique au système quelle action entreprendre si la connexion réseau est perdue. Cette action a une option supplémentaire, reconnect qui indique au plugin distant de tenter de se reconnecter au serveur à la réception de l'enregistrement d'audit suivant. Si un événement était en cours d'envoi lorsque quelque chose a déclenché cette action, il n'est pas retiré de la file d'attente. Si la reconnexion échoue, l'enregistrement d'audit pourrait être perdu. La valeur par défaut est
reconnect.
generic_error_act
ion
De même, ce paramètre indique au système quelle action entreprendre si l'extrémité distante signale une erreur que nous ne reconnaissons pas. La valeur par défaut est de la consigner dans
syslog.
generic_warning_act
ion
De même, ce paramètre indique au système quelle action entreprendre si l'extrémité distante signale un avertissement que nous ne reconnaissons pas. La valeur par défaut est de la consigner dans
syslog.

NAME

audisp-remote.conf — configuration file for audispd-remote

DESCRIPTION

The audisp-remote.conf file is used to configure the audispd-remote plugin. This plugin forwards audit events to a remote syslog server. The configuration options are described below. Comments can be added to the file using a hash mark ('#') which will be ignored by the parser.

All configuration parameters are optional and have sensible defaults.

The parameters are typically arranged in key-value pairs. Whitespace is ignored around the key and value. For example:

remote_server = server.example.com
port = 12345
transport = TCP
queue_error_action
De même, ce paramètre indique au système quelle action entreprendre en cas de problème lors du traitement d'une file d'attente d'enregistrements locale. La valeur par défaut est stop.
overflow_action
Ce paramètre indique au système quelle action entreprendre si la file d'attente interne des événements déborde. Les valeurs valides sont ignore, syslog, suspend, single et halt. Si défini sur ignore, l'application de journalisation distante ne fait rien. Syslog signifie qu'elle émettra un avertissement à syslog. C'est la valeur par défaut. Suspend entraînera l'arrêt de l'envoi d'enregistrements au système distant par l'application de journalisation. L'application de journalisation sera toujours active. L'option single mettra le système informatique en mode mono-utilisateur. L'option halt arrêtera le système informatique par l'application de journalisation.
startup_failure_action
Ce paramètre indique au système quelle action entreprendre en cas d'erreur lors de la connexion au système distant au démarrage. Généralement, cela est bénin car le comportement par défaut du plugin est de tenter de se reconnecter jusqu'à ce qu'il réussisse. Mais il peut y avoir des moments où vous souhaitez faire quelque chose de différent. Les valeurs valides sont ignore, syslog, exec, warn_once et warn_once_continue. Si défini sur ignore, l'application de journalisation distante ne fait rien. Syslog signifie qu'elle émettra un avertissement à syslog. exec /chemin/vers/script exécutera le script. Vous ne pouvez pas passer de paramètres au script. warn_once est comme syslog, sauf qu'un seul message est envoyé à syslog jusqu'à ce qu'un événement soit transféré avec succès. warn_once_continue est comme warn_once sauf qu'il ignore le problème. C'est la valeur par défaut.
enable_krb5
Cette option est obsolète. Utilisez l'option transport pour activer la prise en charge de Kerberos. Si cette option suit l'option de configuration de transport, elle remplacera le paramètre de transport. Ce serait le comportement normal attendu pour la compatibilité descendante. Si défini sur yes, Kerberos 5 sera utilisé pour l'authentification et le chiffrement. La valeur par défaut est no. Notez que le chiffrement ne peut être utilisé qu'avec des connexions gérées, pas avec du texte brut ASCII.
krb5_principal
S'il est spécifié, c'est le principal attendu pour le serveur. Le client et le serveur utiliseront le principal spécifié pour négocier le chiffrement. Le format de krb5_principal est similaire à somename/hostname, voir la page de manuel auditd.conf pour plus de détails. S'il n'est pas spécifié, les valeurs krb5_client_name et remote_server sont utilisées.
krb5_client_name
Ceci spécifie la partie nom du principal du client lui-même. Si non spécifié, la valeur par défaut est "auditd". Le reste du principal sera constitué du nom de domaine complet de l'hôte et du domaine Kerberos par défaut, comme suit : auditd/host14.example.com@EXAMPLE.COM (en supposant que vous avez donné "auditd" comme krb_client_name). Notez que le client et le serveur doivent avoir le même nom de principal et le même domaine.
krb5_key_file
Emplacement de la clé pour le principal de ce client. Notez que le fichier de clés doit appartenir à root et avoir le mode 0400. La valeur par défaut est /etc/audisp/audisp-remote.key

NOTES

La spécification d'un port local peut rendre difficile le redémarrage du sous-système d'audit en raison de la connexion précédente en état TIME_WAIT, si vous vous reconnectez aux mêmes hôtes et ports qu'auparavant.

La logique de défaillance réseau fonctionne comme suit : la première tentative de livraison normale "fonctionne". Si ce n'est pas le cas, une deuxième tentative est immédiatement effectuée, peut-être après la reconnexion au serveur. Si la deuxième tentative échoue également, audispd-remote fait une pause pendant le temps configuré et réessaie. Il continue de faire une pause et de réessayer jusqu'à ce que trop de tentatives aient été effectuées ou que le temps autorisé soit écoulé. Notez que ces temps régissent le temps maximum autorisé pour que le serveur distant redémarre, si vous souhaitez maintenir la journalisation lors d'un redémarrage.

Il est recommandé de définir un q_depth élevé dans auditd.conf si vous utilisez ce plugin. Définissez également un q_depth encore plus grand dans audisp-remote.conf. Définissez également heartbeat_timeout sur une valeur non nulle, mais coordonnez-le avec le serveur de sorte qu'il soit égal à la moitié de la valeur tcp_client_max_idle du serveur. Ceci est nécessaire pour obtenir des nouvelles tentatives dans un délai raisonnable en cas de problème réseau.
