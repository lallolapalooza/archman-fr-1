AUDIT_ADD_RULE_DATA(3) API d'audit Linux AUDIT_ADD_RULE_DATA(3)

NOM

audit_add_rule_data - Ajouter une nouvelle règle d'audit

SYNTAXE

#include <libaudit.h>
int audit_add_rule_data(int fd, struct audit_rule_data *rule, int flags, int action);"

DESCRIPTION

audit_add_rule_data ajoute une règle d'audit préalablement construite avec audit_rule_fieldpair_data(3) à l'un des filtres d'événements du noyau. Le filtre est spécifié par le descripteur de fichier fd et l'argument flags. Les valeurs possibles pour flags sont :

•
AUDIT_FILTER_USER - Appliquer la règle aux messages générés par l'espace utilisateur. C'est le filtre utilisateur. Normalement, tous les événements initiés par l'espace utilisateur sont acceptés. Les règles sur ce filtre sont typiquement écrites pour bloquer des événements spécifiques.
•
AUDIT_FILTER_TASK - Appliquer la règle lors de la création de tâche (pas un appel système). C'est le filtre de tâche. Il est normalement utilisé pour exclure une application de l'audit.
•
AUDIT_FILTER_EXIT - Appliquer la règle à la sortie d'un appel système. C'est le filtre principal utilisé pour les appels système et les surveillances de système de fichiers. Normalement, tous les appels système ne déclenchent pas d'événements, donc il est normalement utilisé pour spécifier les événements qui sont d'intérêt.
•
AUDIT_FILTER_EXCLUDE - Appliquer la règle lors de audit_log_start. C'est le filtre d'exclusion qui ignore tous les enregistrements correspondants. Le type d'action est ignoré pour ce filtre, par défaut à "jamais".
•
AUDIT_FILTER_FS - Appliquer la règle lors de l'ajout d'enregistrements auxiliaires PATH aux événements SYSCALL. C'est le filtre du système de fichiers. Il est utilisé pour ignorer les enregistrements PATH qui ne sont pas d'intérêt.

L'action de la règle a deux valeurs possibles :

•
AUDIT_NEVER - Ne pas construire de contexte si la règle correspond.
•
AUDIT_ALWAYS - Générer un enregistrement d'audit si la règle correspond.

VALEUR DE RETOUR

La valeur de retour est <= 0 en cas d'erreur, sinon c'est l'identifiant de séquence netlink. Cette fonction peut avoir toute erreur que sendto pourrait rencontrer.

VOIR AUSSI

audit_rule_fieldpair_data(3), audit_delete_rule_data(3), auditctl(8).
