INTRODUCTION
Tcl inclut une
bibliothèque de procédures Tcl pour

Le

L'emplacement de la bibliothèque Tcl est renvoyé par la commande info library. En plus de la bibliothèque Tcl, chaque application aura normalement sa propre bibliothèque de procédures de support ; l'emplacement de cette bibliothèque est normalement donné par la valeur de la $ app _library variable globale, où app est le nom de l'application. Le chemin de chargement automatique est donné par la variable globale auto_path si elle existe. S'il n'existe pas de variable auto_path, alors la variable d'environnement TCLLIBPATH est utilisée, si elle existe. Sinon, le chemin de chargement automatique ne consiste qu'en le répertoire de la bibliothèque Tcl. Dans chaque répertoire du chemin de chargement automatique, il doit y avoir un fichier tclIndex qui décrit une ou plusieurs commandes définies dans ce répertoire et un script à évaluer pour charger chacune des commandes. Le fichier tclIndex devrait être généré avec la commande auto_mkindex. Si cmd est trouvé dans un fichier d'index, alors le script approprié est évalué pour créer la commande. La commande auto_load renvoie 1 si cmd a été créée avec succès. La commande renvoie 0 s'il n'y avait pas d'entrée d'index pour cmd ou si le script n'a pas réellement défini cmd (par exemple parce que les informations d'index sont obsolètes). Si une erreur se produit lors du traitement du script, alors cette erreur est renvoyée. Auto_load ne lit les informations d'index qu'une seule fois et les enregistre dans le tableau auto_index ; les appels futurs à auto_load vérifient la présence de cmd dans le tableau plutôt que de relire les fichiers d'index. Les informations d'index en cache peuvent être supprimées avec la commande auto_reset. Cela forcera la prochaine commande auto_load à recharger la base de données d'index depuis le disque. auto_mkindex dir

namespace
Calcule une liste de noms entièrement qualifiés pour command. Cette liste reflète le chemin qu'un interpréteur Tcl standard suit pour les recherches de commandes : d'abord il cherche la commande dans l'espace de noms courant, puis dans l'espace de noms global. En conséquence, si command est relative et namespace n'est pas ::, la liste renvoyée a deux éléments : command délimité par namespace, comme s'il s'agissait d'une commande dans l'espace de noms namespace ; et command comme s'il s'agissait d'une commande dans l'espace de noms global. varNamedd>Ceci est une procédure de recherche standard à utiliser par les extensions lors de leur initialisation. Elles appellent cette procédure pour rechercher leur bibliothèque de scripts dans plusieurs répertoires standard. Le dernier composant du nom du répertoire de la bibliothèque est normalement basenameversion (par ex., tk8.0), mais il peut être « library » dans les hiérarchies de compilation. Le fichier initScript sera chargé dans l'interpréteur une fois qu'il est trouvé. Le répertoire dans lequel ce fichier est trouvé est stocké dans la variable globale varName. Si cette variable est déjà définie (par ex., par du code C lors de l'initialisation de l'application), alors aucune recherche n'est effectuée. Sinon, la recherche examine ces répertoires : le répertoire nommé par la variable d'environnement enVarName ; par rapport au répertoire de la bibliothèque Tcl ; par rapport au fichier exécutable dans le répertoire standard d'installation bin ou bin/arch ; par rapport au fichier exécutable dans l'arborescence de compilation actuelle ; par rapport au fichier exécutable dans une arborescence de compilation parallèle.

Une fin de mot est définie comme le premier caractère non mot suivant le premier caractère mot après le point de départ. Renvoie -1 s'il n'y a plus de fins de mot après le point de point. Voir la description de tcl_wordchars et tcl_nonwordchars ci-dessous pour plus de détails sur la manière dont Tcl détermine quels caractères sont des caractères de
mot.
