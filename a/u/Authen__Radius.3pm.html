SYNOPSI

S 
  use Authen::Radius;
  $r = new Authen::Radius(Host => 'myserver', Secret => 'mysecret');
  print "auth result=", $r->check_pwd('myname', 'mypwd'), "\n";
  $r = new Authen::Radius(Host => 'myserver', Secret => 'mysecret');
  Authen::Radius->load_dictionary();
  $r->add_attributes (
        { Name => 'User-Name', Value => 'myname' },
        { Name => 'Password', Value => 'mypwd' },
# RFC 2865 http://www.ietf.org/rfc/rfc2865.txt appelle cet attribut
# User-Password. Vérifiez votre dictionnaire RADIUS local pour savoir
# quel nom est utilisé sur votre système
#       { Name => 'User-Password', Value => 'mypwd' },
        { Name => 'h323-return-code', Value => '0' }, # Paire AV Cisco
        { Name => 'Digest-Attributes', Value => { Method => 'REGISTER' } }
  );
  $r->send_packet(ACCESS_REQUEST) and $type = $r->recv_packet();
  print "server response type = $type\n";
  for $a ($r->get_attributes()) {
    print "attr: name=$a->{'Name'} value=$a->{'Value'}\n";
}

DESCRIPTIO

N

Le module "Authen::Radius" fournit une classe simple qui vous permet d'en

voyer/recevoir des requêtes/répons
es Radius à/depuis un serveur Radius.

CONSTRUCTEU

R
new ( Host => HOST, Secret => SECRET [, TimeOut => TIMEOUT] [,Service => SERVICE] [, Debug => Bool] [, LocalAddr => hostname[:port]] [,Rfc3579MessageAuth => Bool] [,NodeList= NodeListArrayRef]
)
Crée et retourne une référence bénie à un objet Radius, ou undef en cas d'échec. Le statut d'erreur peut être récupéré avec "Authen::Radius::get_error" (code d'erreur) ou "Authen::Radius::strerror" (chaîne d'erreur détaillée).

Le "Service" par défaut est "radius", l'alternative est "radius-acct". Si vous ne spécifiez pas le port dans le "Host" sous la forme "hostname:port", alors le port spécifié dans votre /etc/services sera utilisé. S'il n'y a rien là-dedans, et que vous n'avez pas non plus spécifié de port, alors la valeur par défaut est 1645 pour "radius" et 1813 pour "radius-a

cct".

Le paramètre optionnel "Debug" avec une valeur Perl "vraie" active le débogage (mode

verbeux).

Le paramètre optionnel "LocalAddr" peut contenir l'adresse locale IP/hôte de liaison à partir de laquelle les paquets RADIUS sont

envoyés.

Le paramètre optionnel "Rfc3579MessageAuth" avec une valeur Perl "vraie" active la génération du Message-Authenticator pour Access-Request (RFC3579, section 3.2). Le Message-Authenticator est toujours généré pour les paquets

Status-Server.

Le paramètre optionnel "NodeList" peut contenir une référence Perl à un tableau, contenant une liste de nœuds de cluster Radius. Chaque nœud de la liste peut être spécifié en utilisant un nom d'hôte ou une IP (avec un numéro de port optionnel), c'est-à-dire 'radius1.mytel.com' ou 'radius.myhost.com:1812'. Un cluster Radius contient un ensemble de serveurs Radius ; à un moment donné, un seul serveur est considéré comme "actif" (les requêtes sont donc envoyées à ce serveur). Comment le nœud actif est-il déterminé ? Initialement, en plus du paramètre "NodeList", vous pouvez fournir le paramètre "Host" et spécifier quel serveur doit devenir le premier nœud actif. Si ce paramètre est absent, ou si

le nœud actif actuel ne répond plus, le processus
de "découverte" sera effectué : une requête sera
envoyée à tous les nœuds et la communication se
poursuivra avec le nœud qui répondra en premier.

MÉTHODE

S
load_dictionary ( [ DICTIONARY ], [format => 'freeradius' | 'gnuradius']
)
Charge les définitions du fichier de dictionnaire Radius spécifié (format standard Livingston radiusd). Tente de charger "/etc/raddb/dictionary" quand aucun argument n'est spécifié, ou meurt. "format" doit être spécifié si le dictionnaire a un autre format (actuellement pris en charge : FreeRADIUS et GNU Radius)

REMARQUE : vous devez charger un dictionnaire valide si vous prévoyez d'envoyer des requêtes RADIUS avec des attributs autres que simplement "User-Name"/"Passwo

rd
".
check_pwd ( USERNAME, PASSWORD [,NASIPADDRESS]
)
Vérifie auprès du serveur RADIUS si le "PASSWORD" spécifié est valide pour l'utilisateur "USERNAME". Sauf si "NASIPADDRESS" est spécifié, le script tentera de déterminer son adresse IP locale (l'adresse IP pour la socket RADIUS) et cette valeur sera placée dans l'attribut NAS-IP-Address. Cette méthode est en réalité un enrobage pour les appels suivants à "clear_attributes", "add_attributes", "send_packet" et "recv_packet". Elle retourne 1 si le "PASSWORD" est correct, ou undef
sinon.
add_attributes ( { Name => NAME, Value => VALUE [, Type => TYPE] [, Vendor => VENDOR] [, Tag => TAG ] }, ..
. )
Ajoute un nombre quelconque d'attributs Radius à l'objet Radius actuel. Les attributs sont spécifiés sous forme de liste de hachages anonymes. Ils peuvent être "nommés" avec leur nom de dictionnaire (à condition qu'un dictionnaire ait été chargé au préalable), ou avec leurs valeurs brutes de type d'attribut Radius. La paire "Type" doit être spécifiée lors de l'ajout d'attributs qui ne sont pas dans le dictionnaire (ou quand aucun dictionnaire n'a été chargé). Les valeurs pour "TYPE" peuvent être '"string"', '"integer"', '"ipaddr"', '"ipv6addr"', '"ipv6prefix"', '"ifid"' ou '"avpair"'. Le "VENDOR" peut être le nom du fournisseur (Vendor) du dictionnaire ou son identifiant entier. Pour les attributs étiquetés (RFC2868), l'étiquette (tag) peut être spécifiée dans le "Name" en utilisant le format 'Name:Tag', ou en utilisant la paire "Tag". On s'attend à ce que la valeur TAG soit un entier, dans la plage [1:31] (la valeur zéro n'est pas prise en charge)
.
get_attribut
es
Retourne une liste de références à des hachages anonymes avec les paires clé/valeur suivantes : { Name => NAME, Code => RAWTYPE, Value => VALUE, RawValue => RAWVALUE, Vendor => VENDOR, Tag => TAG, AttrName => NAME }. Chaque hachage représente un attribut dans l'objet actuel. Les paires "Name" et "Value" contiendront les valeurs telles que traduites par le dictionnaire (si un a été chargé). Les paires "Code" et "RawValue" contiennent toujours le type d'attribut brut et la valeur tels que reçus du serveur. Si un attribut n'existe pas dans le dictionnaire ou si le type d'attribut n'est pas spécifié, alors la "Value" correspondante est indéfinie et le "Name" est défini à l'ID de l'attribut (la valeur"Code"). Pour un attribut étiqueté (RFC2868), l'étiquette sera incluse dans le "NAME" sous la forme 'Name:Tag'. Le nom original est stocké dans "AttrName". La valeur de l'étiquette est également stockée dans "Tag" (undef pour les attributs non étiquetés)
.
clear_attribu
tes
Efface tous les attributs pour l'objett
objet.
send_packet ( REQUEST_TYPE, RETRANSMIT
)
Prépare un paquet Radius basé sur le secret courant et les attributs et l'envoie au serveur avec un type de requête de "REQUEST_TYPE". Les méthodes exportées "REQUEST_TYPE" sont "ACCESS_REQUEST", "ACCESS_ACCEPT", "ACCESS_REJECT", "ACCESS_CHALLENGE", "ACCOUNTING_REQUEST", "ACCOUNTING_RESPONSE", "ACCOUNTING_STATUS", "STATUS_SERVER", "DISCONNECT_REQUEST", "DISCONNECT_ACCEPT", "DISCONNECT_REJECT", "COA_REQUEST", "COA_ACCEPT", "COA_REJECT", "COA_ACK", et "COA_NAK". Renvoie le nombre d'octets envoyés, ou undef en cas d'échec.

Si le paramètre RETRANSMIT est fourni et contient une valeur non nulle, alors

on considère que nous renvoyons la requête, qui a déjà été envoyée précédemme
nt. Dans ce cas, la valeur précédente de l'identifiant de paquet est utilisée.
recv_packet ( DETECT_BAD_ID
)
Reçoit un paquet de réponse Radius. Renvoie le type de réponse Radius (voir les valeurs possibles pour "REQUEST_TYPE" dans la méthode "send_packet") ou undef en cas d'échec. Notez que l'échec peut être dû à un recv() échoué ou à un authentificateur de réponse Radius invalide. Utilisez "get_error" pour le savoir.

Si le paramètre DETECT_BAD_ID est fourni et contient une valeur non nulle, alors le calcul de l'identifiant de paquet est effectué avant la vérification de l'authentificateur et l'erreur EBADID est renvoyée dans le cas où l'identifiant de paquet de la réponse ne correspond pas à celui de la requête. Si le paramètre DETECT_BAD_ID n'est pas fourni ou contient la valeur zéro, alors EBADAUTH est renvoyé dans un

tel
cas.
set_timeout ( TIMEOUT
)
Définit le délai d'attente d'activité d'E/S du socket. "TIMEOUT" doit être spécifié en secondes flottantes depuis
l'époque.
get_err
or
Renvoie le dernier "ERRORCODE" pour l'objet courant. Les codes d'erreur sont des chaînes d'un seul mot commençant toujours par un '"E"
'.
strerror ( [ ERRORCODE
] )
Renvoie une chaîne d'erreur détaillée pour la dernière erreur de l'objet courant, ou pour le "ERRORCODE" sp
écifié.
error_comme
nt
Renvoie la dernière explication d'erreur pour l'objet courant. L'explication d'erreur est générée par un appel
système.

ent actif en notation standard
chiffres-et-points avec l
