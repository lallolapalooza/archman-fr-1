INTRODUCTIO

N

autoexpect vous observe en train d'interagir avec un autre programme et crée un script Expect qui reproduit vos interactions. Pour les scripts linéaires, autoexpect fait gagner un temps considérable par rapport à l'écriture de scripts à la main. Même si vous êtes un expert d'Expect, vous trouverez pratique d'utiliser autoexpect pour automatiser les parties les plus mécaniques des interactions. Il est beaucoup plus facile de copier/coller des blocs de scripts autoexpect que de les écrire à partir de zéro. Et si vous êtes débutant, vous pourrez peut-être vous en tirer en n'apprenant rien de plus sur Expect que la façon d'appeler

autoexpect.

La façon la plus simple d'utiliser autoexpect est de l'appeler depuis la ligne de commande sans arguments. Par exemple

:

%

autoexpect

Par défaut, autoexpect lance un shell pour vous. Étant donné un nom de programme et des arguments, autoexpect lance ce programme. Par exemple

:

% autoexpect ftp ftp.cme.nist.

gov

Une fois votre programme lancé en cours d'exécution, interagissez normalement. Lorsque vous avez quitté le shell (ou le programme que vous avez spécifié), autoexpect créera un nouveau script pour vous. Par défaut, autoexpect écrit le nouveau script dans « script.exp ». Vous pouvez remplacer cela avec l'option -f suivie d'un nouveau nom de

script.

L'exemple suivant exécute « ftp ftp.cme.nist.gov » et stocke le script Expect résultant dans le fichier « nist »

. 
% autoexpect -f nist ftp ftp.cme.nist.gov
Il est important de comprendre qu'autoexpect ne garantit pas un script fonctionnel car il doit nécessairement deviner certaines choses - et il se trompe parfois. Cependant, il est généralement très facile d'identifier et de corriger ces problèmes. Les problèmes typiques sont les suivants :
•
Chronométrage. Un nombre étonnamment élevé de programmes (rn, ksh, zsh, telnet, etc.) et de périphériques (par exemple, les modems) ignorent les frappes qui arrivent « trop rapidement » après les invites. Si vous trouvez que votre nouveau script se bloque à un endroit, essayez d'ajouter un court sleep juste avant le send précédent.

Vous pouvez forcer ce comportement tout au long en remplaçant la variable « force_conservative » près du début du script généré. Ce mode « conservateur » fait qu'autoexpect met automatiquement en pause brièvement (un dixième de seconde) avant d'envoyer chaque caractère. Cela apaise tous les programmes que je

connais.

Ce mode conservateur est utile si vous voulez simplement vous assurer rapidement que le problème est lié au chronométrage (ou si vous ne vous souciez vraiment pas de la vitesse d'exécution du script). Ce même mode peut être forcé avant la génération du script en utilisant l'option

-c.

Heureusement, ces points de synchronisation sont rares. Par exemple, telnet n'ignore les caractères qu'après avoir entré sa séquence d'échappement. Les modems n'ignorent les caractères qu'immédiatement après s'y être connectés pour la première fois. Quelques programmes présentent ce comportement tout le temps mais ont généralement un commutateur pour le désactiver. Par exemple, l'option -T de rn désactive ce

comportement.

L'exemple suivant démarre autoexpect en mode

conservateur. 
autoexpect -c
L'option -C définit une touche pour basculer le mode conservateur. L'exemple suivant démarre autoexpect (en mode non conservateur) avec ^L comme commutateur. (Notez que le ^L est saisi littéralement - c'est-à-dire, saisissez un vrai control-L). 
autoexpect -C ^L
L'exemple suivant démarre autoexpect en mode conservateur avec ^L comme commutateur. 
autoexpect -c
-C
^L
•
Écho. De nombreux programmes font écho des caractères. Par exemple, si vous tapez « more » dans un shell, ce qu'autoexpect voit réellement est : 
vous avez tapé 'm',
l'ordinateur a tapé 'm',
vous avez tapé 'o',
l'ordinateur a tapé 'o',
vous avez tapé 'r',
l'ordinateur a tapé
'r', ...

Sans connaissance spécifique du programme, il est impossible de savoir si vous attendez de voir chaque caractère faire écho avant de taper le suivant. Si autoexpect voit des caractères faire écho, il suppose qu'il peut les envoyer tous en un seul groupe plutôt que de les entrelacer de la manière dont ils sont apparus à l'origine. Cela rend le script plus agréable à lire. Cependant, il pourrait concevablement être incorrect si vous deviez réellement attendre pour voir chaque caractère

faire
écho.
•
Changement. Autoexpect enregistre chaque caractère de l'interaction dans le script. C'est souhaitable car cela vous donne la capacité de porter des jugements sur ce qui est important et ce qui peut être remplacé par une correspondance de motif.

D'un autre côté, si vous utilisez des commandes dont la sortie diffère d'une exécution à l'autre, les scripts générés ne seront pas corrects. Par exemple, la commande « date » produit toujours une sortie différente. Ainsi, utiliser la commande date pendant l'exécution d'autoexpect est un moyen sûr de produire un script qui nécessitera une édition pour

fonctionner.

L'option -p met autoexpect en « mode invite ». Dans ce mode, autoexpect ne cherchera que la dernière ligne de sortie du programme - qui est généralement l'invite. Cela résout le problème de date (voir ci-dessus) et la plupart des

autres.

L'exemple suivant démarre autoexpect en mode

invite. 
autoexpect -p
L'option -P définit une touche pour basculer le mode invite. L'exemple suivant démarre autoexpect (en mode non invite) avec ^P comme commutateur. Notez que le ^P est saisi littéralement - c'est-à-dire, saisissez un vrai control-P. 
autoexpect -P ^P
L'exemple suivant démarre autoexpect en mode invite avec ^P comme commutateur.

STYL

E

Je ne sais pas s'il existe un « style » pour les programmes Expect mais autoexpect ne devrait certainement pas être pris comme modèle de style. Par exemple, autoexpect utilise des fonctionnalités d'Expect qui sont destinées spécifiquement au scripting généré par ordinateur. N'essayez donc pas d'écrire fidèlement des scripts qui semblent s'ils avaient été générés par autoexpect. Cela n'est pas

utile.

D'un autre côté, les scripts autoexpect montrent certaines choses utiles. Pa

r exemple, vous pouvez voir comment toute chaîne doit être citée pour l'util
iser dans un script Tcl simplement en faisant passer les chaînes par autoexpect.

    autoexpect(1)

    autoexpect - génère un script d'attente à partir d'une session interactive

    SYNOPSIS

    autoexpect [-f fichier_attendu] [commande ...]

    DESCRIPTION

    autoexpect capture une session interactive et génère un script correspondant qui peut ensuite être utilisé par expect(1) pour reproduire la session.

    Il est utile pour automatiser des programmes qui nécessitent une interaction utilisateur, comme la configuration de certains logiciels ou la connexion à des systèmes distants. Vous lancez autoexpect, vous effectuez les interactions nécessaires, puis vous quittez la session. autoexpect créera alors un fichier (par défaut nommé expect.script) qui contient les commandes et les réponses correspondant à votre session.

    OPTIONS

    -f fichier_attendu
    Spécifie le nom du fichier dans lequel le script généré sera sauvegardé. Si cette option n'est pas utilisée, le fichier par défaut sera expect.script.

    EXEMPLE

    Pour automatiser l'installation d'un paquet qui demande des informations, vous pourriez faire :

    $ autoexpect apt-get install mon-paquet

    Vous répondrez aux questions d'installation comme d'habitude. Une fois l'installation terminée et que vous avez quitté la session, un fichier nommé expect.script sera créé. Vous pouvez ensuite utiliser ce script avec expect :

    $ expect expect.script

    Ou l'éditer pour des modifications plus complexes.
