NOM

auth_krb5 - Authentificateur Kerberos v5 pour nnrpd

SYNTAXE

auth_krb5 [-i instance]

DESCRIPTION

Ce programme effectue l'authentification pour nnrpd contre un KDC Kerberos v5. Ce n'est PAS une authentification Kerberos réelle utilisant des tickets de service ; au lieu de cela, un nom d'utilisateur et un mot de passe sont utilisés pour tenter d'obtenir un TGT Kerberos v5 afin de confirmer leur validité. En tant que tel, cet authentificateur suppose que nnrpd a reçu le nom d'utilisateur et le mot de passe de l'utilisateur, et n'est donc pas aussi sécurisé qu'une authentification Kerberos réelle. Il ne devrait généralement être utilisé qu'avec NNTP sur TLS pour protéger le mot de passe contre l'écoute clandestine.

Normalement, vous ne voulez pas utiliser cet authentificateur. Utilisez plutôt ckpasswd avec le support PAM et configurez la pile PAM de nnrpd pour utiliser un module PAM Kerberos. Un module PAM Kerberos complet est plus sophistiqué dans la manière dont il valide les mots de passe et offre un éventail beaucoup plus large d'options que cet authentificateur.

OPTIONS

-i instance
Si cette option est donnée, instance sera utilisée comme instance du principal reçu de nnrpd et l'authentification sera effectuée contre ce principal au lieu du principal de base. En d'autres termes, un principal comme "utilisateur", lorsqu'il est passé à auth_krb5 appelé avec "-i nntp", sera transformé en "utilisateur/nntp" avant de tenter l'authentification Kerberos.

Étant donné que la transmission de son mot de passe à nnrpd n'est pas aussi sécurisée qu'une authentification Kerberos normale, cette option prend en charge une configuration où tous les utilisateurs reçoivent une instance séparée juste pour l'authentification de nouvelles avec son propre mot de passe, de sorte que leur mot de passe de compte régulier ne soit pas exposé via NNTP.

EXEMPLE

Le fragment readers.conf(5) suivant indique à nnrpd d'authentifier les utilisateurs en tentant d'obtenir des TGT Kerberos v5 pour eux, en ajoutant une instance "nntp" aux noms d'utilisateur avant de le faire :

auth kerberos {
    auth: "auth_krb5 -i nntp"
}
access kerberos {
    users: "*/nntp"
    newsgroups: example.*
}

L'accès est accordé aux groupes example.* pour tous les utilisateurs qui s'authentifient avec succès.

BOGUES

Actuellement, tout nom d'utilisateur contenant des informations de royaume (contenant "@") est rejeté. Ceci afin d'empêcher quelqu'un de fournir un nom d'utilisateur correspondant à un principal dans un autre royaume auquel il a accès et d'y accéder via le serveur de nouvelles. Cependant, c'est aussi quelque chose que les gens peuvent souhaiter faire dans certaines circonstances, il devrait donc y avoir une meilleure façon de le gérer (par exemple, peut-être une liste de royaumes acceptables ou un indicateur -r spécifiant le royaume dans lequel tenter l'authentification).

Il n'est pas clair quelle est la bonne chose à faire lorsque le nom d'utilisateur fourni contient un "/" et que -i a également été donné. Pour le moment, auth_krb5 créera un principal Kerberos mal formé avec plusieurs instances et tentera de s'authentifier contre celui-ci, ce qui échouera mais peut-être pas avec le meilleur message d'erreur.
