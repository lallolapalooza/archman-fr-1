autodie::exception(3perl) Guide de référence du programmeur Perl autodie::exception(3perl)

NOM

autodie::exception - Exceptions des fonctions à autodie.

SYNTAXE

eval {
    use autodie;
    open(my $fh, '<', 'quel_fichier.txt');
    ...
};
if (my $E = $@) {
    say "Oups!  ",$E->caller," a eu des problèmes: $@";
}

DESCRIPTION

Lorsqu'une fonction activée par autodie échoue, elle génère un objet "autodie::exception". Celui-ci peut être interrogé pour obtenir des informations supplémentaires sur l'erreur survenue.

Ce document est divisé en deux sections ; celles des méthodes les plus utiles pour le développeur final, et celles pour quiconque souhaite sous-classer ou se familiariser en profondeur avec "autodie::exception".

Méthodes courantes

Ces méthodes sont destinées à être utilisées dans la gestion quotidienne des exceptions.

Les lignes suivantes supposent que l'erreur a été copiée dans un scalaire séparé :

if ($E = $@) {
    ...
}

Ce n'est pas obligatoire, mais recommandé au cas où du code serait appelé et pourrait réinitialiser ou modifier $@.

args

my $refs_array = $E->args;

Fournit une référence vers les arguments passés à la sous-routine qui a échoué.

function

my $sub = $E->function;

La sous-routine (incluant le package) qui a lancé l'exception.

file

my $file = $E->file;

Le fichier dans lequel l'erreur s'est produite (par exemple, "monscript.pl" ou "MonTest.pm").

package

my $package = $E->package;

Le package depuis lequel la sous-routine exceptionnelle a été appelée.

caller

my $caller = $E->caller;

La sous-routine qui a appelé le code exceptionnel.

line

my $line = $E->line;

La ligne dans "$E->file" où le code exceptionnel a été appelé.

context

my $context = $E->context;

Le contexte dans lequel la sous-routine a été appelée par autodie ; généralement le même que le contexte dans lequel vous avez appelé la sous-routine autodying. Cela peut être 'list', 'scalar', ou indéfini (inconnu). Ce ne sera jamais 'void', car "autodie" capture toujours la valeur de retour d'une manière ou d'une autre.

Pour certaines fonctions de base qui retournent toujours une valeur scalaire quel que soit leur contexte (par exemple, "chown"), cela peut être 'scalar', même si vous avez utilisé un contexte de liste.

return

my $valeur_retour = $E->return;

La ou les valeurs retournées par la sous-routine défaillante. Lorsque la sous-routine a été appelée dans un contexte de liste, ce sera toujours une référence vers un tableau contenant les résultats. Lorsque la sous-routine a été appelée dans un contexte scalaire, ce sera le scalaire réel retourné.

errno

my $errno = $E->errno;

La valeur de $! au moment où l'exception s'est produite.

NOTE : Cette méthode quittera la classe principale "autodie::exception" et fera partie d'un rôle dans le futur. Vous ne devriez appeler "errno" que pour les exceptions où $! aurait raisonnablement été défini en cas d'échec.

eval_error

my $ancien_eval_erreur = $E->eval_error;

Le contenu de $@ juste après qu'autodie ait déclenché une exception. Cela peut être utile lorsqu'on traite des modules comme Text::Balanced qui définissent (mais ne lancent pas) $@ en cas d'erreur.

matches

if ( $e->matches('open') ) { ... }
if ( 'open' ~~ $e ) { ... }

"matches" est utilisé pour déterminer si une exception donnée correspond à un rôle particulier.

Une exception est considérée comme correspondant à une chaîne si :

  • Pour une chaîne ne commençant pas par un deux-points, la chaîne correspond exactement au package et à la sous-routine qui ont lancé l'exception. Par exemple, "MyModule::log". Si la chaîne ne contient pas de nom de package, "CORE::" est supposé.
  • Pour une chaîne qui commence par un deux-points, si la sous-routine qui lance l'exception réalise ce comportement. Par exemple, la sous-routine "CORE::open" réalise ":file", ":io" et ":all".

    Voir "CATÉGORIES" dans autodie pour plus d'informations.

    Sur Perl 5.10 et versions ultérieures, l'utilisation du smart-match ("~~") avec un objet "autodie::exception" utilisera "matches" en arrière-plan. Ce module recommandait autrefois d'utiliser le smart-match avec l'objet exception côté gauche, mais cela risque de ne plus fonctionner dans les futures versions de Perl. La fonctionnalité de smart-match de cette classe ne doit être utilisée qu'avec l'objet exception côté droit. Avoir l'objet exception à droite est à la fois pérenne et portable vers les anciennes versions de Perl, à partir de la 5.10. Attention, cette fonctionnalité ne peut être utilisée que lorsqu'il est certain que l'objet exception est bien un objet "autodie::exception" ; elle n'est pas plus performante qu'un appel explicite à la méthode "matches".

Méthodes avancées

Les méthodes suivantes, bien qu'utilisables de n'importe où, sont principalement destinées aux développeurs souhaitant sous-classer "autodie::exception", écrire du code qui enregistre des messages d'erreur personnalisés, ou travailler plus étroitement avec le modèle "autodie::exception".

register

autodie::exception->register( 'CORE::open' => \&mysub );

La méthode "register" permet l'enregistrement d'un gestionnaire de message pour une sous-routine donnée. Le nom complet de la sous-routine incluant le package doit être utilisé.

Les gestionnaires de messages enregistrés recevront l'objet "autodie::exception" comme premier paramètre.

add_file_and_line

say "Problème survenu",$@->add_file_and_line;

Retourne la chaîne " à %s ligne %d", où %s est remplacé par le nom du fichier, et %d par le numéro de ligne.

Principalement destinée à être utilisée par les gestionnaires de format.

stringify

say "L'erreur était : ",$@->stringify;

Formate l'erreur en une chaîne lisible par l'homme. Généralement, il n'y a pas lieu d'appeler cela directement, car cela est utilisé automatiquement si un objet "autodie::exception" est jamais utilisé comme une chaîne.

Les classes enfants peuvent redéfinir cette méthode pour changer la façon dont elles sont représentées en chaîne.

format_default

my $chaine_erreur = $E->format_default;

Produit la chaîne d'erreur par défaut pour l'exception donnée, sans utiliser de gestionnaires de messages enregistrés. Elle est principalement destinée à être appelée depuis un gestionnaire de message lorsqu'on lui a passé une exception qu'il ne souhaite pas formater.

Les classes enfants peuvent redéfinir cette méthode pour changer la façon dont les messages par défaut sont formatés.

new

my $error = autodie::exception->new(
    args => \@_,
    function => "CORE::open",
    errno => $!,
    context => 'scalar',
    return => undef,
);

Crée un nouvel objet "autodie::exception". Normalement appelé directement depuis une fonction autodying. L'argument "function" est requis, c'est la fonction que nous essayions d'appeler qui a généré l'exception. Le paramètre "args" est optionnel.

La valeur "errno" est optionnelle. Dans les versions d'« autodie::exception » 1.99 et antérieures, le code tentait d'utiliser automatiquement la valeur actuelle de $!, mais c'était peu fiable et n'est plus supporté.

Des attributs tels que package, file et caller sont déterminés automatiquement, et ne peuvent pas être spécifiés.
