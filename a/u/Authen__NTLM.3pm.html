NOM

Authen::NTLM - Un module d'authentification NTLM

SYNOPIS

use Mail::IMAPClient;
use Authen::NTLM;
my $imap = Mail::IMAPClient->new(Server=>'imaphost');
ntlm_user($username);
ntlm_password($password);
$imap->authenticate("NTLM", Authen::NTLM::ntlm);
:
$imap->logout;
ntlm_reset;
:

ou

ntlmv2(1);
ntlm_user($username);
ntlm_host($host);
ntlm_password($password);
:

ou

my $ntlm = Authen::NTLM-> new(
    host     => $host,
    user     => $username,
    domain   => $domain,
    password => $password,
    version  => 1,
);
$ntlm-> challenge;
:
$ntlm-> challenge($challenge);

DESCRIPTION

Ce module fournit des méthodes pour utiliser l'authentification NTLM. Il peut
être utilisé comme méthode d'authentification avec le module Mail::IMAPClient
pour réaliser le mécanisme de défi/réponse pour les connexions NTLM, ou il peut
être utilisé seul pour l'authentification NTLM avec d'autres protocoles (par
exemple, HTTP).
L'implémentation est un portage direct du code de F<fetchmail> qui, lui-même,
a basé son implémentation NTLM sur F<samba>. En tant que tel, ce code n'est
pas particulièrement efficace, cependant il prendra toujours une fraction de
seconde pour négocier une connexion dans un PII, ce qui est probablement suffisant
pour la plupart des situations.

FONCTIONS

ntlm_domain()
Définit le domaine à utiliser dans les messages d'authentification NTLM.
Retourne le nouveau domaine. Sans argument, cette fonction
retourne l'entrée du domaine actuel.
ntlm_user()
Définit le nom d'utilisateur à utiliser dans les messages d'authentification NTLM.
Retourne le nouveau nom d'utilisateur. Sans argument, cette fonction
retourne l'entrée du nom d'utilisateur actuel.
ntlm_password()
Définit le mot de passe à utiliser dans les messages d'authentification NTLM.
Retourne le nouveau mot de passe. Sans argument, cette fonction
retourne l'entrée du mot de passe actuel.
ntlm_reset()
Réinitialise la machine d'état de défi/réponse NTLM afin que le prochain
appel à C<ntlm()> produise un message de connexion initial.
ntlm()
Génère une réponse à un défi. Le protocole NTLM implique un
défi initial vide du serveur nécessitant une réponse par message
contenant le nom d'utilisateur et le domaine (qui peuvent être vides).
Le premier appel à C<ntlm()> génère ce premier message en ignorant
tous les arguments.
La deuxième fois qu'il est appelé, on suppose que l'argument est
la chaîne de défi envoyée par le serveur. Celle-ci contiendra 8
octets de données qui sont utilisés dans les fonctions DES pour générer les
chaînes d'authentification de réponse. Le résultat de l'appel est la
chaîne d'authentification finale.
Si C<ntlm_reset()> est appelé, alors le prochain appel à C<ntlm()>
redémarrera le processus, permettant plusieurs authentifications au sein
d'une application.
ntlmv2()
Utilise l'authentification NTLM v2.

API OBJET

new %options
Crée un objet qui accepte les options suivantes : "user", "host", "domain", "password", "version".
challenge [$challenge]
Si $challenge n'est pas fourni, une chaîne de défi de premier étage est générée. Sinon, le défi de troisième étage est généré, où $challenge est supposé être extrait de la seconde étape de l'échange NTLM. Le résultat de l'appel est la chaîne d'authentification finale.
