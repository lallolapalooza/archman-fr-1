AUDITD(8) Utilitaires d'administration système AUDITD(8)

NOM

auditd - Le démon d'audit Linux

SYNTAXE

auditd [-f] [-l] [-n] [-s disable|enable|nochange] [-c <répertoire_config>]

DESCRIPTION

auditd est le composant utilisateur du système d'audit Linux. Il est responsable de l'écriture des enregistrements d'audit sur le disque. La visualisation des journaux se fait avec les utilitaires ausearch ou aureport. La configuration du système d'audit ou le chargement des règles se fait avec l'utilitaire auditctl. Lors du démarrage, les règles dans /etc/audit/audit.rules sont lues par auditctl et chargées dans le noyau. Alternativement, il existe également un programme augenrules qui lit les règles situées dans /etc/audit/rules.d/ et les compile en un fichier audit.rules. Le démon d'audit lui-même possède des options de configuration que l'administrateur peut souhaiter personnaliser. Elles se trouvent dans le fichier auditd.conf.

OPTIONS

-f
maintient le démon d'audit au premier plan pour le débogage. Les messages sont également envoyés à stderr plutôt qu'au journal d'audit.
-l
autorise le démon d'audit à suivre les liens symboliques pour les fichiers de configuration.
-n
pas de fork. Ceci est utile pour exécuter à partir d'inittab ou de systemd.
-s=ETAT_ACTIVATION
spécifie au démarrage si auditd doit modifier la valeur actuelle du drapeau d'activation du noyau. Les valeurs valides pour ETAT_ACTIVATION sont "disable", "enable" ou "nochange". La valeur par défaut est d'activer (et de désactiver à la terminaison d'auditd). La valeur du drapeau d'activation peut être modifiée pendant la durée de vie d'auditd en utilisant 'auditctl -e'.
-c
Spécifie un répertoire de configuration alternatif. Notez que ce même répertoire sera passé au dispatcher. (défaut : /etc/audit/)

SIGNAUX

SIGHUP
provoque la reconfiguration d'auditd. Cela signifie qu'auditd relit le fichier de configuration. S'il n'y a pas d'erreurs de syntaxe, il procédera à la mise en œuvre des changements demandés. Si la reconfiguration est réussie, un événement DAEMON_CONFIG est enregistré dans les journaux. En cas d'échec, la gestion des erreurs est contrôlée par les paramètres space_left_action, admin_space_left_action, disk_full_action et disk_error_action dans auditd.conf.
SIGTERM
provoque l'arrêt du traitement des événements d'audit par auditd, l'écriture d'un événement d'arrêt du système et la sortie.
SIGUSR1
provoque la rotation immédiate des journaux par auditd. Il consultera max_log_file_action pour voir s'il doit conserver les journaux ou non.
SIGUSR2
provoque la tentative par auditd de reprendre la journalisation et le passage des événements aux plugins. Ceci est généralement nécessaire après que la journalisation ait été suspendue ou que la file d'attente interne soit pleine. L'une ou l'autre de ces conditions dépend des paramètres de configuration applicables.
SIGCONT
provoque la décharge par auditd d'un rapport d'état interne dans /run/audit/auditd.state.

CODES DE SORTIE

1
Impossible d'ajuster la priorité, de démoniser, d'ouvrir le netlink d'audit, d'écrire le fichier pid, de démarrer les plugins, de résoudre le nom de la machine, de définir le pid d'audit, ou autres tâches d'initialisation.
2
Arguments de la ligne de commande invalides ou excessifs
4
Le démon d'audit n'a pas les privilèges suffisants
6
Erreur dans le fichier de configuration

FICHIERS

/etc/audit/auditd.conf - fichier de configuration du démon d'audit

/etc/audit/audit.rules - règles d'audit à charger au démarrage

/etc/audit/rules.d/ - répertoire contenant des ensembles individuels de règles à compiler en un seul fichier par augenrules.

/etc/audit/plugins.d/ - répertoire contenant des fichiers de configuration individuels de plugins.

/etc/audit/audit-stop.rules - Ces règles sont chargées lorsque le démon d'audit s'arrête.

/run/audit/auditd.state - rapport sur l'état interne.

NOTES

Un paramètre de démarrage audit=1 doit être ajouté pour s'assurer que tous les processus qui s'exécutent avant le démarrage du démon d'audit sont marqués comme auditable par le noyau. Ne pas le faire rendra impossible l'audit correct de certains processus.

Le démon d'audit peut recevoir des événements d'audit d'autres démons d'audit via le plugin audisp-remote. Le démon d'audit peut être lié avec tcp_wrappers pour contrôler quelles machines peuvent se connecter. Si c'est le cas, vous pouvez ajouter une entrée dans hosts.allow et deny.

VOIR AUSSI
