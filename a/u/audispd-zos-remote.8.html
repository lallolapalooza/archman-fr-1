NOM

audispd-zos-remote - Module d'audit de dispatch pour les services distants z/OS

SYNOPSIS

audispd-zos-remote [ fichier-de-configuration ]

DESCRIPTION

audispd-zos-remote est un module d'audit à distance pour le sous-système d'audit. Il doit être démarré par le démon auditd(8) et transmettra tous les événements d'audit entrants, au fur et à mesure qu'ils se produisent, à une base de données z/OS SMF (Service Management Facility) configurée, via un serveur IBM Tivoli Directory Server (ITDS) configuré pour le service d'audit distant. Voir la CORRESPONDANCE SMF section ci-dessous pour plus d'informations sur le format des enregistrements SMF résultants.

auditd(8) doit être configuré pour démarrer le module. Cela est fait par un fichier de configuration généralement situé dans /etc/audit/plugins.d/audispd-zos-remote.conf, mais plusieurs instances peuvent être créées en ayant plusieurs fichiers de configuration dans /etc/audit/plugins.d pour le même exécutable de module (voir auditd(8)).

Chaque instance a besoin d'un fichier de configuration, situé par défaut dans /etc/audit/zos-remote.conf. Consultez zos-remote.conf(5) pour les détails sur la configuration du module.

OPTIONS

fichier-de-configuration
Utiliser un fichier de configuration alternatif au lieu de /etc/audit/zos-remote.conf.

SIGNAUX

audispd-zos-remote réagit aux signaux SIGTERM et SIGHUP (selon la spécification de auditd(8) ) :

SIGHUP
Indique au module audispd-zos-remote de relire sa configuration et de fermer les connexions réseau existantes.
SIGTERM
Effectue une sortie propre. audispd-zos-remote attendra jusqu'à 10 secondes s'il y a des événements en file d'attente à livrer, abandonnant tout événement restant en file d'attente après ce délai.

Configuration du serveur IBM z/OS ITDS et de RACF

Pour utiliser ce module, vous devez disposer d'un serveur IBM z/OS v1R8 (ou supérieur) avec IBM Tivoli Directory Server (ITDS) configuré pour le service d'audit distant. Pour des informations plus détaillées sur la configuration du serveur z/OS pour l'audit à distance, consultez z/OS V1R8.0-9.0 Integrated Security Services Enterprise Identity Mapping (EIM) Guide and Reference

(http://publibz.boulder.ibm.com/cgi-bin/bookmgr_OS390/FRAMESET/EIMA1140/CCONTENTS?DT=20070827115119),
chapitre « 2.0 - Working with remote services ».

Activer ITDS pour traiter les requêtes d'audit à distance

Pour permettre à ITDS de traiter les requêtes d'audit à distance, l'identifiant utilisateur associé à ITDS doit se voir accorder l'accès READ au profil de classe FACILITY IRR.AUDITX (le profil utilisé pour protéger le service R_Auditx). Cet identifiant utilisateur se trouve généralement dans le profil de classe STARTED pour la procédure de démarrage d'ITDS. Si l'identité associée à ITDS est ITDSUSER, l'administrateur peut configurer RACF pour accorder le traitement de l'audit à distance à ITDS avec les commandes TSO suivantes :

Commandes TSO : Accorder à ITDSUSER l'accès READ au profil de classe FACILITY IRR.AUDITX
rdefine FACILITY IRR.RAUDITX uacc(none)
permit IRR.RAUDITX class(FACILITY) id(ITDSUSER) access(READ)

Créer/activer un identifiant utilisateur RACF pour effectuer des requêtes d'audit à distance

Le module a besoin d'un identifiant utilisateur RACF z/OS - Chaque requête d'audit effectuée par le module utilisera un identifiant utilisateur RACF, tel que configuré dans la configuration du module zos-remote.conf(5). Cet identifiant utilisateur a besoin d'un accès READ à la ressource de classe FACILITY IRR.LDAP.REMOTE.AUDIT. Si l'identifiant utilisateur est BINDUSER, l'administrateur peut configurer RACF pour permettre à cet utilisateur d'effectuer des requêtes d'audit à distance avec les commandes TSO suivantes :

Commandes TSO : Activer BINDUSER pour effectuer des requêtes d'audit à distance
rdefine FACILITY IRR.LDAP.REMOTE.AUDIT uacc(none)
permit IRR.LDAP.REMOTE.AUDIT class(FACILITY) id(BINDUSER) access(READ)

Ajouter la classe @LINUX à RACF

Lors de la réalisation de requêtes d'audit à distance, le module audispd-zos-remote utilisera la classe CDT spéciale @LINUX CDT Class et le type d'enregistrement d'audit (ex. : SYSCALL, AVC, PATH...) comme CDT Resource Class pour tous les événements traités. Pour vous assurer que les événements sont journalisés, le serveur RACF doit être configuré avec une classe CDT dynamique nommée @LINUX avec les tailles et attributs corrects. Les commandes TSO suivantes peuvent être utilisées pour ajouter cette classe :

Commandes TSO : Ajouter la classe CDT @LINUX
rdefine cdt @LINUX cdtinfo(posit(493) FIRST(alpha,national,numeric,special) OTHER(alpha,national,numeric,special) RACLIST(REQUIRED) case(asis) generic(allowed) defaultuacc(none) maxlength(246))
setr classact(cdt)
setr raclist(cdt)
setr raclist(cdt) refresh
setr classact(@LINUX)
setr raclist(@LINUX)
setr generic(@LINUX)

Ajouter des profils à la classe @LINUX

Une fois la classe CDT définie, vous pouvez y ajouter des profils, en spécifiant les ressources (caractères génériques autorisés) à journaliser ou à ignorer. Voici des exemples :

Commandes TSO : Journaliser uniquement les enregistrements AVC (un profil générique et un profil discret) :
rdefine @LINUX * uacc(none) audit(none(read)) 
rdefine @LINUX AVC uacc(none) audit(all(read)) 
setr raclist(@LINUX) refresh
Commandes TSO : Journaliser tout (un profil générique) :
rdefine @LINUX * uacc(none) audit(all(read))
setr raclist(@LINUX) refresh

Les ressources correspondent toujours au seul profil avec la correspondance la meilleure .

Il existe de nombreuses autres façons de définir la journalisation dans RACF. Veuillez consulter la documentation du serveur pour plus de détails.

Correspondance SMF

Le service d'audit à distance ITDS créera des enregistrements SMF de type 83 sous-type 4 à chaque fois qu'il traite une requête. Ce module émettra une requête d'audit à distance pour chaque enregistrement d'audit Linux entrant (signifiant qu'un enregistrement Linux correspondra à un enregistrement SMF), et remplira les enregistrements de ce type avec les éléments suivants :

Valeur de lien

Le numéro de série de l'événement Linux, encodé en représentation hexadécordale dans l'ordre des octets du réseau. Les enregistrements au sein du même événement partagent la même valeur de lien.

Violation

Toujours zéro (0) - Faux

Code d'événement

Toujours deux (2) - Événement d'autorisation

Qualificateur d'événement

Zéro (0) - Succès, si l'événement a rapporté success=yes ou res=success, Trois (3) - Échec, si l'événement a rapporté success=no ou res=failed, ou Un (1) - Info sinon.

Classe

Toujours @LINUX

Ressource

Le type d'enregistrement Linux pour l'enregistrement traité. ex. : SYSCALL</i>,AVC,PATH,CWD etc.

Log String

Message textuelle indiquant l'identifiant utilisateur RACF utilisé pour effectuer la requête, ainsi que le nom d'hôte Linux et le type d'enregistrement du premier enregistrement de l'événement traité. Par exemple : Remote audit request from RACFUSER. Linux (hostname.localdomain):USER_AUTH

Data Field List

Aussi connu sous le nom de relocations, cette liste contient tous les noms de champs et leurs valeurs au format fieldname=value , sous forme de relocation de type 114 (Application specific Data). Le greffon essaiera d'interpréter ces champs (c'est-à-dire utiliser le nom d'utilisateur lisible par l'humain root à la place de l'identifiant numérique 0) chaque fois que c'est possible. Actuellement, ce greffon ajoutera également une relocation de type 113 (Date And Time Security Event Occurred) avec l'horodatage de l'événement au format renvoyé par ctime(3).

ERREURS

Les erreurs et les avertissements sont signalés à syslog (sous la facilité DAEMON). Dans les situations où l'événement a été soumis mais où le serveur z/OS a renvoyé une condition d'erreur, le message journalisé contient un nom suivi d'une description lisible par l'humain. Voici quelques conditions d'erreur courantes :

NOTREQ - No logging required
La ressource (type d'enregistrement d'audit) n'est pas configurée pour être journalisée dans le serveur RACF - Le profil de classe @LINUX régissant ce type d'enregistrement d'audit est configuré pour l'ignorer. Voir IBM z/OS RACF Server configuration
UNDETERMINED - Undetermined result
Aucun profil trouvé pour la ressource spécifiée. Aucune classe @LINUX n'est configurée ou aucun profil de classe @LINUX n'est associé à ce type d'enregistrement d'audit. Voir IBM z/OS RACF Server configuration
UNAUTHORIZED - The user does not have authority the R_auditx service
L'identifiant utilisateur associé à l'ITDS n'a pas d'accès READ au profil de classe FACILITY IRR.AUDITX. Voir IBM z/OS RACF Server configuration
UNSUF_AUTH - The user has insufficient authority for the requested function
L'identifiant utilisateur RACF utilisé pour effectuer les requêtes d'audit distant (tel que configuré dans zos-remote.conf(5)) n'a pas accès au profil de classe FACILITY IRR.LDAP.REMOTE.AUDIT. Voir IBM z/OS RACF Server configuration

BUGS

Le greffon effectue actuellement l'audit distant au mieux de ses capacités et rejettera les événements si le serveur z/OS ne peut pas être contacté (pannes réseau) ou dans tout autre cas où la soumission de l'événement échoue.

FICHIERS
