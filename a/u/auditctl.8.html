CONSEILS DE

PERFORMANCE

Les règles de syscall sont évaluées pour chaque syscall de chaque programme. Si vous avez 10 règles de syscall, chaque programme de votre système sera retardé pendant un syscall pendant que le système d'audit évalue chaque règle. Trop de règles de syscall nuiront aux performances. Essayez d'en combiner autant que possible lorsque le filtre, l'action, la clé et les champs sont identiques. Par exemple

: 
auditctl -a always,exit -F arch=b64 -S openat -F
success=0 
auditctl -a always,exit -F arch=b64 -S truncate -F
success=0

pourrait être réécrit en une seule règle

: 
auditctl -a always,exit -F arch=b64 -S openat -S truncate -F
success=0

De plus, essayez d'utiliser l'audit du système de fichiers partout où c'est pratique. Cela améliore les performances. Par exemple, si vous vouliez capturer tous les open et truncate échoués comme ci-dessus, mais que vous ne vous souciez que des fichiers dans /etc et pas de /usr ou /sbin, il est possible d'utiliser cette règle

: 
auditctl -a always,exit -F arch=b64 -S openat,truncate -F dir=/etc -F
success=0

Cela sera plus performant car le noyau ne l'évaluera pas à chaque

syscall. Il sera géré par le code d'audit du système de fichiers
et vérifié uniquement lors des syscalls liés au système de fichiers.

EXEMPLE

S

Pour voir tous les syscalls effectués par un programme spécifique

: 
# Par pid :
auditctl -a always,exit -S all -F pid=1005
# Par chemin de l'exécutable
auditctl -a always,exit -S all -F
exe=/usr/bin/ls

Pour voir les fichiers ouverts par un utilisateur spécifique

: 
auditctl -a always,exit -S openat -F
auid=510

Pour voir les appels openat infructueux

: 
auditctl -a always,exit -S openat -F
success=0

Pour surveiller un fichier pour les modifications (2 façons de l'exprimer)

: 
auditctl -w /etc/shadow -p wa # Notez que cela ralentit le système
auditctl -a always,exit -F arch=b64 -F path=/etc/shadow -F
perm=wa

Pour surveiller récursivement un répertoire pour les modifications (2 façons de l'exprimer)

: 
auditctl -w /etc/ -p wa # Notez que cela ralentit le système
auditctl -a always,exit -F arch=b64 -F dir=/etc/ -F
perm=wa

Pour voir si un administrateur accède aux fichiers d'autres utilisateurs

: 
auditctl -a always,exit -F dir=/home/ -F uid=0 -C auid!
=obj_uid

Voici un exemple de fichier de règles

:

DÉFAUT

Sur de nombreux systèmes, auditd est configuré pour installer une règle -a never,task par défaut. Cette règle fait que chaque nouveau processus saute tout le traitement des règles d'audit. C'est généralement fait pour éviter un léger surcoût de performance imposé par l'audit des syscalls. Si vous voulez utiliser auditd, vous devez supprimer cette règle en supprimant 10-no-audit.rules et en ajoutant 10-base-config.rules au répertoire des règles

d'audit.

ur vous assurer qu'il n'y a pas de règle never,task là.
