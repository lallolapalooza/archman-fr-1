INTRODUCTIO

N

Tcl inclut une bibliothèque de procédures Tcl pour les fonctions couramment nécessaires. Les procédures définies dans la bibliothèque Tcl sont génériques et conviennent à une utilisation par de nombreuses applications différentes. L'emplacement de la bibliothèque Tcl est renvoyé par la commande info library. En plus de la bibliothèque Tcl, chaque application aura normalement sa propre bibliothèque de procédures de support ; l'emplacement de cette bibliothèque est normalement donné par la valeur de la $app_library variable globale, où app est le nom de l'application. Par exemple, l'emplacement de la bibliothèque Tk est conservé dans la variable tk_library

.

Pour accéder aux procédures de la bibliothèque Tcl, une application doit charger le fichier init.tcl de la bibliothèque, par exemple avec la commande

Tcl 
source [file j
oin [info libr
ary] init.tcl]

Si la procédure de bibliothèque Tcl_Init est appelée depuis la procédure Tcl_AppInit d'une application, cela se produit automatiquement. Le code dans init.tcl définira la procédure unknown et arrangera le chargement des autres procédures à la demande

en utilisant le mécanisme de charge
ment automatique défini ci-dessous.

COMMANDES

PROCÉDURES

Les procédures suivantes sont fournies dans la bibliothèque Tcl

:
auto_execok cm
d
Détermine s'il existe un fichier exécutable ou une commande interne du shell portant le nom cmd. Si c'est le cas, il renvoie une liste d'arguments à passer à exec pour exécuter le fichier exécutable ou la commande interne du shell nommée par cmd. Sinon, il renvoie une chaîne vide. Cette commande examine les répertoires du chemin de recherche actuel (donné par la variable d'environnement PATH) lors de sa recherche d'un fichier exécutable nommé cmd. Sur les plateformes Windows, la recherche est étendue avec les mêmes répertoires et extensions de fichiers que ceux utilisés par exec. Auto_execok se souvient des informations sur les recherches précédentes dans un tableau nommé auto_execs ; cela évite la recherche de chemin lors des appels futurs pour le même cmd. La commande auto_reset peut être utilisée pour forcer auto_execok à oublier ses informations en
cache.
auto_import patte
rn
Auto_import est invoqué lors d'un namespace import pour voir si les commandes importées spécifiées par pattern se trouvent dans une bibliothèque chargée automatiquement. Si c'est le cas, les commandes sont chargées afin qu'elles soient disponibles pour l'interpréteur lors de la création des liens d'importation. Si les commandes ne se trouvent pas dans une bibliothèque chargée automatiquement, auto_import ne fait rien. La correspondance de motif est effectuée selon les règles de correspondance de namespace i
mport.
auto_load cm
d
Cette commande tente de charger la définition d'une commande Tcl nommée cmd. Pour ce faire, elle recherche un chemin de chargement automatique, qui est une liste d'un ou plusieurs répertoires. Le chemin de chargement automatique est donné par la variable globale auto_path si elle existe. S'il n'y a pas de variable auto_path, alors la variable d'environnement TCLLIBPATH est utilisée, si elle existe. Sinon, le chemin de chargement automatique ne consiste qu'en le répertoire de la bibliothèque Tcl. Dans chaque répertoire du chemin de chargement automatique, il doit y avoir un fichier tclIndex qui décrit une ou plusieurs commandes définies dans ce répertoire et un script à évaluer pour charger chacune des commandes. Le fichier tclIndex doit être généré avec la commande auto_mkindex. Si cmd est trouvé dans un fichier d'index, alors le script approprié est évalué pour créer la commande. La commande auto_load renvoie 1 si cmd a été créée avec succès. La commande renvoie 0 s'il n'y avait pas d'entrée d'index pour cmd ou si le script n'a pas réellement défini cmd (par exemple parce que les informations d'index sont obsolètes). Si une erreur se produit lors du traitement du script, alors cette erreur est renvoyée. Auto_load ne lit les informations d'index qu'une seule fois et les enregistre dans le tableau auto_index ; les appels futurs à auto_load vérifient la présence de cmd dans le tableau plutôt que de relire les fichiers d'index. Les informations d'index en cache peuvent être supprimées avec la commande auto_reset. Cela forcera la prochaine commande auto_load à recharger la base de données d'index depuis le
disque.
auto_mkindex dir pattern pattern
...
Génère un index adapté à une utilisation par auto_load. La commande recherche dans dir tous les fichiers dont les noms correspondent à l'un des arguments pattern (la correspondance est effectuée avec la commande glob), génère un index de toutes les procédures de commandes Tcl définies dans tous les fichiers correspondants, et stocke les informations d'index dans un fichier nommé tclIndex dans dir. Si aucun pattern n'est donné, un pattern de *.tcl sera supposé. Pa
r exemple,
la commande 
auto_mk
index fo
o *.tcl

lira tous les fichiers .tcl dans le sous-répertoire foo et générera un nouveau fichier d'index foo/tclIndex

.

Auto_mkindex analyse les scripts Tcl en les chargeant dans un interpréteur enfant et en surveillant les commandes proc et namespace qui sont exécutées. Les extensions peuvent utiliser le paquet (non documenté) auto_mkindex_parser pour enregistrer d'autres commandes qui peuvent contribuer à l'index auto_load. Vous devrez lire auto.tcl pour voir comment cela

fonctionne.

Auto_mkindex_old (qui a la même syntaxe que auto_mkindex) analyse les scripts Tcl d'une manière relativement peu sophistiquée : si une ligne contient le mot «proc » comme ses premiers caractères, alors il est supposé s'agir d'une définition de procédure et le mot suivant de la ligne est pris comme le nom de la procédure. Les définitions de procédures qui n'apparaissent pas de cette manière (par exemple, elles ont des espaces avant proc) ne seront pas indexées. Si votre script contient du code « dangereux », comme du code d'initialisation globale ou des noms de procédures avec des caractères spéciaux comme $, *, [ ou ], vous êtes plus en sécurité en utilisant auto_mkindex_ol

d

Détruit toutes les informations mises en cache par auto_execok et auto_load. Ces informations seront relues depuis le disque la prochaine fois qu'elles seront nécessaires. Auto_reset supprime également toutes les procédures listées dans l'index de chargement automatique, afin que des copies neuves soient chargées la prochaine fois qu'elles seront

auto_qualify command
namespace
Calcule une liste de noms entièrement qualifiés pour command. Cette liste reflète le chemin qu'un interpréteur Tcl standard suit pour les recherches de commandes : d'abord il cherche la commande dans l'espace de noms courant, puis dans l'espace de noms global. En conséquence, si command est relative et namespace n'est pas ::, la liste renvoyée a deux éléments : command délimité par namespace, comme s'il s'agissait d'une commande dans l'espace de noms namespace ; et command comme s'il s'agissait d'une commande dans l'espace de noms global. Sinon, si command est absolu (il commence par ::), ou si namespace est ::, la liste contient seulement command comme s'il s'agissait d'une c
ommande dans l'espa
ce de noms global.

Auto_qualify est utilisé par les mécanismes de chargement automatique de Tcl, à la fois pour produire des index de chargement automatique tels que pkgIndex.tcl, et pour effectuer le chargement

automatique réel des f
onctions à l'exécution.
tcl_findLibrary basename version patch initScript enVarName
varName
C'est une procédure de recherche standard destinée aux extensions lors de leur initialisation. Elles appellent cette procédure pour rechercher leur bibliothèque de scripts dans plusieurs répertoires standard. Le dernier composant du nom du répertoire de la bibliothèque est normalement basenameversion (par exemple, tk8.0), mais il peut être « library » dans les hiérarchies de compilation. Le fichier initScript sera chargé dans l'interpréteur une fois qu'il est trouvé. Le répertoire dans lequel ce fichier est trouvé est stocké dans la variable globale varName. Si cette variable est déjà définie (par exemple, par du code C lors de l'initialisation de l'application), aucune recherche n'est effectuée. Sinon, la recherche s'effectue dans ces répertoires : le répertoire nommé par la variable d'environnement enVarName ; par rapport au répertoire de la bibliothèque Tcl ; par rapport au fichier exécutable dans le répertoire standard d'installation bin ou bin/arch ; par rapport au fichier exécutable dans l'arborescence de compilation actuelle ; par rapport au fichier exécutable dans une arborescence de compilation
parallèle.

n?

ArrayName doit être un tableau accessible à l'appelant de parray. Il peut êt

tcl_endOfWord str
start
Renvoie l'indice de la première fin de mot qui apparaît après un indice de départ start dans la chaîne str. Une fin de mot est définie comme le premier caractère non mot suivant le premier caractère mot après le point de départ. Renvoie -1 s'il n'y a plus de fins de mot après le point de point. Voir la description de tcl_wordchars et tcl_nonwordchars ci-dessous pour plus de détails sur la manière dont Tcl détermine quels caractères sont des caractères
mot.
tcl_startOfNextWord str
start
Renvoie l'indice du premier début de mot qui apparaît après un indice de départ start dans la chaîne str. Un début de mot est défini comme le premier caractère mot suivant un caractère non mot. Renvoie -1 s'il n'y a plus de débuts de mot après le point de
départ.
tcl_startOfPreviousWord str
start
Renvoie l'indice du premier début de mot qui apparaît avant un indice de départ start dans la chaîne str. Renvoie -1 s'il n'y a plus de débuts de mot avant le point de
départ.
tcl_wordBreakAfter str
start
Renvoie l'indice de la première limite de mot après l'indice de départ start dans la chaîne str. Renvoie -1 s'il n'y a plus de limites après le point de départ dans la chaîne donnée. L'indice renvoyé fait référence au deuxième caractère de la paire qui constitue une
limite.

start

mot.

tcl_nonwordch

Cette variable contient une expression rationnelle utilisée par des routines comme tcl_endOfWord pour identifier si un caractère fait partie d'un mot ou non.
