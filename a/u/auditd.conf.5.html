AUDITD.CONF(5) Utilitaires d'administration système AUDITD.CONF(5)

NOM

auditd.conf - fichier de configuration du démon d'audit

DESCRIPTION

Le fichier /etc/audit/auditd.conf contient les informations de configuration spécifiques au démon d'audit. Chaque ligne doit contenir un mot-clé de configuration, un signe égal, suivi des informations de configuration appropriées. Tous les noms d'options et les valeurs ne sont pas sensibles à la casse. Les mots-clés reconnus sont listés et décrits ci-dessous. Chaque ligne doit être limitée à 160 caractères, sinon elle sera ignorée. Vous pouvez ajouter des commentaires au fichier en commençant la ligne par un caractère '#'.

local_events
Ce mot-clé oui/non spécifie s'il faut inclure ou non les événements locaux. Normalement, vous voulez les événements locaux, donc la valeur par défaut est oui. Les cas où vous définiriez cela sur non sont lorsque vous souhaitez agréger uniquement des événements provenant du réseau. Pour le moment, cela est utile si le démon d'audit s'exécute dans un conteneur. Cette option ne peut être définie qu'une seule fois au démarrage du démon. Le rechargement du fichier de configuration n'a aucun effet.
log_file
Ce mot-clé spécifie le chemin d'accès complet au fichier journal où les enregistrements d'audit seront stockés. Ce doit être un fichier régulier. Le chemin par défaut est /var/log/audit/audit.log s'il n'est pas explicitement défini.
write_logs
Ce mot-clé oui/non détermine s'il faut écrire ou non les journaux sur le disque. Normalement, vous le souhaitez, donc la valeur par défaut est oui.
log_format
Le format du journal décrit comment les informations doivent être stockées sur le disque. Il y a 2 options : raw et enriched. Si défini sur RAW, les enregistrements d'audit seront stockés dans un format exactement tel que le noyau l'envoie. L'option ENRICHED résoudra toutes les informations d'uid, gid, syscall, architecture et adresse de socket avant d'écrire l'événement sur le disque. Cela aide à comprendre les événements créés sur un système mais rapportés/analysés sur un autre système. L'option NOLOG est maintenant obsolète. Si vous définissiez ce format, vous devriez maintenant définir l'option write_logs sur non.
log_group
Ce mot-clé spécifie le groupe qui est appliqué aux permissions du fichier journal. La valeur par défaut est root. Le nom du groupe peut être numérique ou orthographié.
priority_boost
C'est un nombre non négatif qui indique au démon d'audit quel boost de priorité il doit prendre. La valeur par défaut est 4. Aucun changement n'est 0.
flush
Les valeurs valides sont none, incremental, incremental_async, data, et sync. Si défini sur none, aucun effort spécial n'est fait pour vider les enregistrements d'audit sur le disque. Si défini sur incremental, alors le paramètre freq est utilisé pour déterminer la fréquence à laquelle une vidange explicite sur disque est émise. Le paramètre incremental_async est très similaire à incremental, sauf que la vidange est effectuée de manière asynchrone pour de meilleures performances. Le paramètre data indique au démon d'audit de garder la partie données du fichier disque synchronisée à tout moment. L'option sync indique au démon d'audit de garder à la fois les données et les métadonnées entièrement synchronisées à chaque écriture sur disque. La valeur par défaut est incremental_async.
freq
C'est un nombre non négatif qui indique au démon d'audit combien d'enregistrements écrire avant d'émettre une commande de vidange explicite sur disque. Cette valeur n'est valide que lorsque le mot-clé flush est défini sur incremental ou incremental_async.
num_logs
Ce mot-clé spécifie le nombre de fichiers journaux à conserver si rotate est donné comme max_log_file_action. Si le nombre est < 2, les journaux ne sont pas pivotés. Ce nombre doit être de 999 ou moins. La valeur par défaut est 0 - ce qui signifie aucune rotation. À mesure que vous augmentez le nombre de fichiers journaux pivotés, vous devrez peut-être ajuster la mémoire tampon du noyau vers le haut car il faut plus de temps pour faire pivoter les fichiers. Ceci est généralement fait dans /etc/audit/audit.rules. Si la rotation des journaux est configurée pour se produire, le démon vérifiera les journaux excédentaires et les supprimera afin de conserver l'espace disque disponible. La vérification des journaux excédentaires n'est effectuée qu'au démarrage et lorsqu'une reconfiguration entraîne une vérification de l'espace.
name_format
Cette option contrôle la manière dont les noms d'ordinateurs sont insérés dans le flux d'événements d'audit. Elle propose les choix suivants : none, hostname, fqd, numeric, et user. None signifie qu'aucun nom d'ordinateur n'est inséré dans l'événement d'audit. hostname est le nom retourné par l'appel système gethostname. fqd signifie qu'il prend le nom d'hôte et le résout avec DNS pour un nom de domaine entièrement qualifié de cette machine. Numeric est similaire à fqd, sauf qu'il résout l'adresse IP de la machine. Pour utiliser cette option, vous pourriez vouloir tester que 'hostname -i' ou 'domainname -i' renvoie une adresse numérique. De plus, cette option n'est pas recommandée si DHCP est utilisé car vous pourriez avoir des adresses différentes au fil du temps pour la même machine. User est une chaîne définie par l'administrateur à partir de l'option name. La valeur par défaut est none.
name
C'est la chaîne définie par l'administrateur qui identifie la machine si user est donné comme option name_format.
max_log_file
Ce mot-clé spécifie la taille maximale du fichier en mébioctets (MiB). Lorsque cette limite est atteinte, elle déclenche une action configurable. La valeur donnée doit être numérique.
max_log_file_action
Ce paramètre indique au système quelle action entreprendre lorsque le système a détecté que la limite de taille de fichier maximale a été atteinte. Les valeurs valides sont ignore, syslog, exec, suspend, rotate et keep_logs. Si défini sur ignore, le démon d'audit ne fait rien. syslog signifie qu'il émettra un avertissement à syslog. exec /chemin/vers/script exécutera le script. Vous ne pouvez pas passer de paramètres au script. Le script est également responsable d'indiquer au démon auditd de reprendre la journalisation une fois son action terminée. Ceci peut être fait en ajoutant auditdctl --signal resume au script. Notez également que la journalisation est arrêtée lorsque ce script s'exécute. Tout ce qu'il fait doit être très rapide car les événements s'accumulent dans le noyau. Le script DOIT supprimer ou renommer /var/log/audit/audit.log ou lorsque la journalisation reprendra, il réexécutera le script. suspend fera en sorte que le démon d'audit cesse d'écrire des enregistrements sur le disque. Le démon sera toujours actif. L'option rotate fera pivoter les journaux par le démon d'audit. Il convient de noter que les journaux avec des numéros plus élevés sont plus anciens que les journaux avec des numéros plus bas. C'est la même convention utilisée par l'utilitaire logrotate. L'option keep_logs est similaire à rotate, sauf qu'elle n'utilise pas le paramètre num_logs. Cela empêche l'écrasement des journaux d'audit. L'effet est que les journaux s'accumulent et ne sont pas supprimés, ce qui déclenchera space_left_action si le volume se remplit. Ceci est mieux utilisé en combinaison avec un script externe utilisé pour archiver les journaux périodiquement.
verify_email
Cette option détermine si l'adresse e-mail donnée dans action_mail_acct est vérifiée pour voir si le nom de domaine peut être résolu. Cette option doit être donnée avant action_mail_acct ou la valeur par défaut oui sera utilisée.
action_mail_acct
Cette option doit contenir une adresse e-mail valide ou un alias. Les adresses peuvent utiliser le sous-adressage style RFC 5233 avec le caractère '+'. Les caractères autorisés sont alphanumériques, '@', '.', '-', '_', et '+'. L'adresse par défaut est root. Si l'adresse e-mail n'est pas locale à la machine, vous devez vous assurer que votre e-mail est correctement configuré sur votre machine et votre réseau. Cette option nécessite que /usr/lib/sendmail existe sur la machine. De nombreux clients le fournissent sous forme de lien symbolique.
space_left
Si l'espace libre dans le système de fichiers contenant log_file tombe en dessous de cette valeur, le démon d'audit prend l'action spécifiée par space_left_action. Si la valeur de space_left est spécifiée comme un nombre entier, elle est interprétée en MiB. Si elle se termine par K, M, ou G, elle est interprétée en KiB, MiB, ou GiB respectivement.

Ce paramètre indique au système quelle action effectuer lorsque le système a détecté que l'espace disque commence à manquer. Les valeurs valides sont ignore, syslog, rotate, email, exec, suspend, et single. S'il est réglé sur ignore, le démon d'audit ne fait rien. syslog signifie qu'il émettra un avertissement vers syslog. rotate fera tourner les journaux, en perdant les plus anciens pour libérer de l'espace. Email signifie qu'il enverra un avertissement au compte de messagerie spécifié dans action_mail_acct ainsi qu'il enverra le message à syslog. exec /chemin-vers-le-script exécutera le script. Vous ne pouvez pas passer de paramètres au script. Le script est également responsable de dire au démon auditd de reprendre la journalisation une fois son action terminée. Cela peut être fait en ajoutant service auditd resume au script. suspend causera au démon d'audit d'arrêter d'écrire des enregistrements sur le disque. Le démon sera toujours en vie. L'option single causera au démon d'audit de mettre l'ordinateur en mode utilisateur unique. Sauf pour rotate, il effectuera cette action une seule fois. L'option halt précédemment disponible, qui causerait au démon d'audit d'arrêter l'ordinateur, a été dépréciée et ne devrait plus être utilisée. Il a été déterminé que l'arrêt du système à ce stade pourrait entraîner des conséquences involontaires et est considéré comme une mauvaise action si elle est sélectionnée.

Les notifications d'espace disque suivent une progression en trois étapes. Le space_left_action est le seuil d'alerte et sert de premier avertissement que l'espace disque est en train de baisser. L'arrêt à ce stade n'est pas recommandé, car il empêche les administrateurs de prendre des mesures correctives. L'étape suivante, admin_space_left_action, indique un niveau d'urgence où une action immédiate est requise pour libérer de l'espace disque. Les administrateurs devraient configurer des réponses critiques pour ce niveau. Enfin, le disk_full_action se produit lorsque le disque est complètement plein. À ce stade, le système peut déjà avoir été arrêté, et les mesures préventives configurées dans les étapes précédentes détermineront le

NOTE

S

Dans un environnement CAPP, la piste d'audit est considérée si importante que l'accès aux ressources système doit être refusé si une piste d'audit ne peut pas être créée. Dans cet environnement, il serait suggéré que /var/log/audit soit sur sa propre partition. Cela est fait pour s'assurer que la détection de l'espace est précise et qu'aucun autre processus ne vienne en consommer une

partie.

Le paramètre flush devrait être défini à sync ou

data.

Max_log_file et num_logs doivent être ajustés pour que vous obteniez une utilisation complète de votre partition. Il convient de noter que plus il y a de fichiers à faire tourner, plus il faut de temps pour revenir à la réception des événements d'audit. Max_log_file_action devrait être défini à

keep_logs.

Space_left devrait être défini à un nombre qui donne à l'administrateur suffisamment de temps pour réagir à tout message d'alerte et effectuer une certaine maintenance pour libérer de l'espace sur le disque. Cela impliquerait généralement d'exécuter le rapport aureport -t et de déplacer les journaux les plus anciens vers une zone d'archive. La valeur de space_left dépend du site car le taux auquel les événements sont générés varie selon chaque déploiement. Il est recommandé de définir space_left_action à email. Si vous avez besoin de quelque chose comme un trap snmp, vous pouvez utiliser l'option exec pour en envoyer

un.

Admin_space_left devrait être défini à la quantité d'espace disque sur la partition d'audit nécessaire pour que les actions d'administration soient enregistrées. Admin_space_left_action serait défini à single afin que l'utilisation de la machine soit restreinte à la seule

console.

disk_full_action est déclenché lorsqu'il n'y a plus de place sur la partition. Tout accès devrait être terminé car il n'y a plus de capacité d'audit. Cela peut être défini à single ou

halt.

disk_error_action devrait être défini à syslog, single, ou halt selon vos politiques locales concernant la gestion des défaillances

matérielles.

Spécifier un seul port client autorisé peut rendre difficile pour le client de redémarrer son sous-système d'audit, car il sera incapable de recréer une connexion avec les mêmes adresses et ports d'hôte tant que l'état TIME_WAIT de fermeture de connexion n'aura pas

expiré.

Les événements auditd sont composés d'un ou plusieurs enregistrements. Le système auditd ne peut pas garantir que l'ensemble des enregistrements composant un événement se produira de manière atomique, c'est-à-dire que le flux aura des enregistrements entrelacés d'événements différents, c'est à

dire

event0_record0
event1_record0
event2_record0
event1_record3
event2_record1
event1_record4
event3_record0

Le système auditd ne garantit pas que les enregistrements composant un événement apparaîtront dans l'ordre. Ainsi, lors du traitement des flux d'événements, nous devons maintenir une liste d'événements avec leur propre liste d'enregistrements, d'où le traitement d'événements List of List (LOL)

.

Lors du traitement d'un flux d'événements, nous définissons la fin d'un événement

via
type d'enregistrement = AUDIT_EOE (type d'enregistrement de fin d'événement d'audit), ou
type d'enregistrement = AUDIT_PROCTITLE (nous notons que AUDIT_PROCTITLE est toujours le dernier enregistrement), ou
type d'enregistrement = AUDIT_KERNEL (les événements du noyau sont des événements à un seul enregistrement), ou
type d'enregistrement < AUDIT_FIRST_EVENT (seuls les événements à un seul enregistrement apparaissent avant ce type), ou
type d'enregistrement >= AUDIT_FIRST_ANOM_MSG (seuls les événements à un seul enregistrement apparaissent après ce type), ou
type d'enregistrement >= AUDIT_MAC_UNLBL_ALLOW && type d'enregistrement <= AUDIT_MAC_CALIPSO_DEL (ce sont aussi des événements à un seul enregistrement), ou
pour le flux en cours de traitemen
t, l'heure de l'événement a plus d
e end_of_event_timeout secondes.
