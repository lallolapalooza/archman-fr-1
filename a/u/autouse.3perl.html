autouse(3perl) Guide du programmeur Perl autouse(3perl)

NOM

autouse - reporter le chargement des modules jusqu'à ce qu'une fonction soit utilisée

SYNOPIS

use autouse 'Carp' => qw(carp croak);
carp "ce carp a été prédéclaré et autoused ";

DESCRIPTION

Si le module "Module" est déjà chargé, alors la déclaration

use autouse 'Module' => qw(func1 func2($;$));

est équivalente à

use Module qw(func1 func2);

si "Module" définit func2() avec le prototype "($;$)", et func1() n'a pas de prototypes. (Du moins si "Module" utilise "import" de "Exporter", sinon c'est une erreur fatale.)

Si le module "Module" n'est pas encore chargé, alors la déclaration ci-dessus déclare les fonctions func1() et func2() dans le paquet courant. Lorsque ces fonctions sont appelées, elles chargent le paquet "Module" si nécessaire, et se remplacent par les définitions correctes.

AVERTISSEMENT

Utiliser "autouse" déplacera des étapes importantes de l'exécution de votre programme du temps de compilation vers le temps d'exécution. Cela peut

  • Casser l'exécution de votre programme si le module que vous avez utilisé avec "autouse" a une initialisation qu'il attend d'être effectuée tôt.
  • Cacher des bugs dans votre code, car des vérifications importantes (comme la correction des prototypes) sont déplacées du temps de compilation au temps d'exécution. En particulier, si le prototype que vous avez spécifié sur la ligne "autouse" est incorrect, vous ne le découvrirez que lorsque la fonction correspondante sera exécutée. Ce sera très malheureux pour les fonctions qui ne sont pas toujours appelées (notez que pour de telles fonctions, l'"autouse" apporte le plus grand gain ; pour une solution de contournement, voir ci-dessous).

Pour atténuer le deuxième problème (partiellement), il est conseillé d'écrire vos scripts comme ceci:

use Module;
use autouse Module => qw(carp($) croak(&$));
carp "ce carp a été prédéclaré et autoused ";

La première ligne garantit que les erreurs dans votre spécification d'arguments sont trouvées tôt. Lorsque vous livrez votre application, vous devriez commenter la première ligne, car elle rend la seconde inutile.
