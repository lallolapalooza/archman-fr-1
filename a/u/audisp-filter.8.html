NOM

audisp-filter - plugin pour filtrer les événements d'audit et les transmettre à d'autres plugins

SYNTAXE

audisp-filter MODE FICHIER_CONFIG BINAIRE [ ARGUMENTS_BINAIRE ]

DESCRIPTION

audisp-filter est un plugin de distribution d'événements d'audit conçu pour filtrer des événements spécifiques en fonction de sa configuration fournie. De plus, il a la capacité de transmettre les journaux restants à d'autres plugins. Le plugin est universellement compatible, permettant une intégration transparente avec tout plugin d'audit existant qui attend des messages d'audit sur son entrée standard. Actuellement, il prend en charge les arguments suivants :

MODE
Le mode de fonctionnement peut être soit une liste blanche (allowlist) soit une liste noire (blocklist). En mode liste blanche, le plugin transmet tout sauf les événements qui correspondent aux expressions ausearch spécifiées dans la configuration. Inversement, en mode liste noire, il s'abstient de transmettre quoi que ce soit, sauf les événements listés dans la configuration.
FICHIER_CONFIG
Chemin vers le fichier de configuration principal contenant les expressions ausearch.
BINAIRE
Chemin vers un programme externe qui recevra constamment les événements d'audit filtrés via son entrée standard.
ARGUMENTS_BINAIRE
Optionnellement, vous pouvez passer des arguments supplémentaires au programme externe.

CONFIGURATION ET ÉVALUATION DES RÈGLES

Chaque plugin qui souhaite bénéficier de la capacité de filtrage d'événements doit créer son propre fichier de configuration. C'est une bonne pratique de placer ce fichier dans le répertoire de configuration d'audit, en suivant la convention de nommage audisp-filter-nomplugin.conf, par exemple, audisp-filter-syslog.conf pour filtrer les événements d'audit avant de les envoyer à syslog.

Chaque ligne dans une configuration représente une expression ausearch (5). En interne, ces expressions sont jointes en utilisant l'opérateur OU. Par conséquent, chaque expression est substituée par (PE || CE), où PE représente l'expression précédente et CE désigne l'expression actuelle en cours de traitement. Les lignes commençant par un caractère '#' sont traitées comme des commentaires et n'influencent pas l'ensemble des règles finales.

Lors de la création d'un événement d'audit, le moteur de filtrage parcourt la liste des expressions, construisant l'expression finale représentant notre ensemble de règles. L'événement en question sera recherché à l'aide de cette expression. La décision de transmettre un événement d'audit au binaire configuré dépend de deux facteurs : le mode de fonctionnement d'audisp-filter et si l'expression correspond à l'événement en cours.

EXEMPLE

Exemple 1 : Ne pas envoyer à syslog les événements d'audit contenant des appels système openat non réussis.

Tout d'abord, dans la configuration du plugin, assurez-vous que le mode de fonctionnement est défini sur liste blanche, que le binaire pointe vers /sbin/audispFyslog et fournissez tous les arguments supplémentaires si nécessaire. Ensuite, créez le fichier de configuration spécifique au plugin avec le contenu ci-dessous. Avant d'activer le plugin d'audit, assurez-vous toujours que la syntaxe est correcte. Cela peut être vérifié en appelant audisp-filter --check chemin/vers/fichier/config.

(type r= SYSCALL && syscall i= openat && success r= yes)
