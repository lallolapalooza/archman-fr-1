AUSEARCH(8) Utilitaires d'administration système AUSEARCH(8)

NOM

ausearch - un outil pour interroger les journaux du démon d'audit

SYNTAXE

ausearch [options]

DESCRIPTION

ausearch est un outil qui permet d'interroger les journaux du démon d'audit en se basant sur différents critères de recherche d'événements. L'utilitaire ausearch peut également recevoir des entrées depuis l'entrée standard tant que l'entrée est constituée de données brutes de journalisation. Chaque option de ligne de commande fournie forme une déclaration "et". Par exemple, rechercher avec -m et -ui signifie retourner les événements qui ont à la fois le type demandé et correspondent à l'identifiant utilisateur donné. Une exception concerne les options -m et -n ; plusieurs types d'enregistrements et nœuds sont autorisés dans une recherche, ce qui retournera n'importe quel nœud et enregistrement correspondant.

Il convient également de noter que chaque excursion d'appel système de l'espace utilisateur vers le noyau et retour vers l'espace utilisateur a un identifiant d'événement unique. Tous les événements audibles déclenchés pendant ce trajet partagent cet identifiant afin qu'ils puissent être corrélés.

Différentes parties du noyau peuvent ajouter des enregistrements supplémentaires. Par exemple, un événement d'audit sur l'appel système "open" provoquera également l'émission par le noyau d'un enregistrement PATH avec le nom du fichier. L'utilitaire ausearch présentera tous les enregistrements qui composent un événement ensemble. Cela peut signifier que même si vous recherchez un type d'enregistrement spécifique, les événements résultants peuvent contenir des enregistrements SYSCALL.

Soyez également conscient que tous les types d'enregistrements ne contiennent pas les informations demandées. Par exemple, un enregistrement PATH ne contient pas de nom d'hôte ni d'identifiant de connexion (loginuid).

OPTIONS

-a, --event identifiant-evenement-audit
Recherche un événement basé sur l'identifiant d'événement donné. Les messages commencent toujours par quelque chose comme msg=audit(1116360555.329:2401771). L'identifiant de l'événement est le nombre après le ':'. Tous les événements d'audit enregistrés à partir d'un appel système d'une application ont le même identifiant d'événement d'audit. Un deuxième appel système effectué par la même application aura un identifiant d'événement différent. De cette façon, ils sont uniques.
--arch CPU
Recherche des événements basés sur une architecture CPU spécifique. Si vous ne connaissez pas l'architecture de votre machine mais que vous souhaitez utiliser la table d'appels système 32 bits et que votre machine prend en charge le 32 bits, vous pouvez également utiliser b32 pour l'architecture. Il en va de même pour la table d'appels système 64 bits, vous pouvez utiliser b64. L'architecture de votre machine peut être trouvée en tapant 'uname -m'.
-c, --comm nom-comm
Recherche un événement basé sur le nom de commande donné. Le nom de commande est le nom de l'exécutable provenant de la structure de tâche.
--debug
Écrit les événements malformés qui sont ignorés sur stderr.
--checkpoint fichier-checkpoint
Marque la sortie entre les invocations successives de ausearch de sorte que seuls les événements non précédemment affichés soient imprimés lors des invocations ultérieures.

Un événement d'audit est composé d'un ou plusieurs enregistrements. Lors du traitement des événements, ausearch définit les événements comme complets ou incomplets. Un événement complet est soit un événement à enregistrement unique, soit un événement dont le temps est antérieur de 2 secondes à celui de l'événement en cours de traitement.

Un point de contrôle est réalisé en enregistrant le dernier événement complet affiché ainsi que le numéro de périphérique et l'inode du fichier dans lequel le dernier événement complet est apparu dans fichier-checkpoint. Lors d'une invocation ultérieure, ausearch chargera ces données de point de contrôle et, lors du traitement des fichiers journaux, il ignorera tous les événements complets jusqu'à ce qu'il corresponde à celui du point de contrôle. À ce moment-là, il commencera à afficher les événements complets.

Si le fichier ou le dernier événement du point de contrôle n'est pas trouvé, une série d'erreurs se produira et ausearch se terminera. Voir STATUT DE SORTIE pour plus de détails.

--eoe-timeout secondes
Définit le délai d'expiration de l'analyse de fin d'événement. Voir end_of_event_timeout dans auditd.conf(5) pour les détails. Notez que la définition de cette valeur remplacera toute valeur configurée trouvée dans /etc/auditd/auditd.conf.
-e, --exit code-sortie-ou-errno
Recherche un événement basé sur le code de sortie ou errno d'appel système donné.
--escape option
Cette option détermine si la sortie est échappée pour rendre le contenu plus sûr pour certaines utilisations. Les options sont raw, tty, shell et shell_quote. Chaque mode inclut les caractères du mode précédent et échappe davantage de caractères. Cela signifie que shell inclut tous les caractères échappés par tty et en ajoute d'autres. tty est la valeur par défaut.
--extra-keys 
Lorsque le mode format est csv, cette option ajoutera une colonne finale avec des informations clés si elles existent pour l'événement. Cela ne se produirait que sur les enregistrements SYSCALL résultant du déclenchement d'une règle d'audit qui définit une clé.
--extra-labels 
Lorsque le mode format est csv, cette option ajoutera des colonnes d'informations sur les étiquettes sujet et objet lorsqu'elles existent.
--extra-obj2 
Lorsque le mode format est csv, cette option ajoutera des colonnes d'informations sur un second objet lorsqu'il existe. Il est rare qu'un second objet fasse partie d'un enregistrement. Quelques exemples sont lorsqu'un fichier est renommé d'un nom à un autre ou lorsqu'un périphérique est monté sur un chemin.
--extra-time 
Lorsque le mode format est csv, cette option ajoutera des colonnes d'informations temporelles décomposées pour faciliter la sous-division.
-f, --file nom-fichier
Recherche un événement basé sur le nom de fichier donné. L'argument correspondra aux fichiers normaux ainsi qu'aux sockets af_unix.
--format option
Les événements qui correspondent aux critères de recherche sont formatés en utilisant cette option. Les formats pris en charge sont : raw, default, interpret, csv et text. L'option raw est décrite dans l'option de ligne de commande --raw. L'option default est ce que vous obtenez lorsque aucune option de formatage n'est passée. Elle inclut une ligne comme séparateur visuel indiquant l'horodatage, puis les enregistrements de l'événement suivent. L'option interpret est expliquée dans l'option de ligne de commande -i. L'option csv affiche les résultats de la recherche sous forme d'événement normalisé au format de valeurs séparées par des virgules (CSV), adapté à l'importation dans des programmes analytiques. L'option text transforme l'événement en une phrase en anglais plus facile à comprendre que les autres options, mais cela se fait au détriment de la perte de détails. Dans la plupart des cas, c'est parfaitement acceptable car l'événement d'origine conserve toutes les informations originales.
-ga, --gid-all id-groupe-tout
Recherche un événement avec soit l'identifiant de groupe effectif, soit l'identifiant de groupe correspondant à l'identifiant de groupe donné.
-ge, --gid-effective id-groupe-effectif
Recherche un événement avec l'identifiant de groupe effectif ou le nom de groupe donné.
-gi, --gid id-groupe
Recherche un événement avec l'identifiant de groupe ou le nom de groupe donné.
-h, --help
Aide
-hn, --host nom-hote
Recherche un événement avec le nom d'hôte donné. Le nom d'hôte peut être un nom d'hôte, un nom de domaine complet ou une adresse réseau numérique. Aucune tentative n'est faite pour résoudre les adresses numériques en noms de domaine ou alias. Cette recherche correspond généralement au champ addr ou host des événements d'audit. Voir aussi la commande --node qui recherche le champ node.

checkpoint signifie ausearch utilisera l'horodatage trouvé dans un fichier de point de contrôle valide en ignorant l'inode, le périphérique, le numéro de série, le nœud et le type d'événement également trouvés dans un fichier de point de contrôle. Essentiellement, c'est l'action de récupération au cas où une invocation de ausearch avec une option de point de contrôle échouerait avec un code de sortie de 10, 11 ou 12. Cela pourrait être utilisé dans un script shell comme

ceci : 


ausearch --checkpoint /etc/audit/auditd_checkpoint.txt -i
_au_status=$?
if test ${_au_status} eq 10 -o ${_au_status} eq 11 -o ${_au_status} eq 12
then
  ausearch --checkpoint /etc/audit/auditd_checkpoint.txt --start checkpoint
-i fi

NOT

E

L'option de temps de démarrage est une fonction de commodité et a des limitations. Le temps qu'elle calcule est basé sur le temps actuel moins /proc/uptime. Si après le démarrage l'horloge système a été ajustée, peut-être par ntp, alors le calcul peut être erroné. Dans ce cas, vous devrez spécifier complètement l'heure. Vous pouvez vérifier l'heure qui serait utilisée en exécutant

:

date -d "`cut -f

1 -d. /proc/upti
me` seconds ago"
