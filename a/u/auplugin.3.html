AUPLUGIN(3) API d'audit Linux AUPLUGIN(3)

NOM

auplugin_init, auplugin_stop, auplugin_event_loop, auplugin_event_feed - Assistants de traitement des événements de plugin

SYNTAXE

#include <auplugin.h>

int auplugin_init(int inbound_fd, unsigned queue_size, int q_flags, const char *path);
void auplugin_stop(void);
void auplugin_event_loop(auplugin_callback_ptr callback);
int auplugin_event_feed(auparse_callback_ptr callback, unsigned timer_interval, auplugin_timer_callback_ptr timer_cb);

DESCRIPTION

auplugin_init initialise le framework des plugins. Le paramètre inbound_fd spécifie le descripteur de fichier qui fournira les messages d'audit, typiquement l'entrée standard. L'argument queue_size contrôle le nombre maximum d'événements qui peuvent être mis en file d'attente pour traitement. Le paramètre q_flags sélectionne le stockage en mémoire ou sur fichier à l'aide des constantes AUPLUGIN_Q_* définies dans auplugin.h. Si q_flags inclut AUPLUGIN_Q_IN_FILE, path spécifie le fichier de sauvegarde. Tous les événements déjà présents dans le fichier sont mis en file d'attente au démarrage afin que les plugins reprennent le traitement des enregistrements précédemment non traités. La bibliothèque maintient un état global pour sa file d'attente et ses threads de travail. Une seule instance de plugin est supportée, les appelants ne doivent donc pas invoquer auplugin_init() simultanément à partir de plusieurs threads. La fonction retourne 0 en cas de succès ou -1 si l'initialisation échoue.

auplugin_stop signale au framework de se terminer. Elle est normalement appelée à partir d'un gestionnaire SIGTERM ou d'une autre logique d'arrêt.

auplugin_event_loop démarre un thread de travail pour livrer les événements mis en file d'attente à la fonction callback fournie, un enregistrement à la fois. La fonction bloque l'appelant jusqu'à ce que auplugin_stop soit invoquée.

auplugin_event_feed se comporte comme auplugin_event_loop, sauf que les événements mis en file d'attente sont fournis à libauparse. Le callback fourni doit correspondre au type auparse_callback_ptr. L'argument timer_interval spécifie combien de secondes le thread de travail attendra de nouveaux enregistrements. Une valeur de 0 désactive la logique du minuteur. Lorsque l'intervalle expire, auparse_feed_age_events est appelée pour vider les événements expirés. Si timer_cb n'est pas NULL, il est appelé avec l'intervalle avant la vidange. Passer un timer_cb de NULL conserve le comportement par défaut consistant à appeler uniquement auparse_feed_age_events. La fonction retourne 0 en cas de succès ou -1 si libauparse n'a pas pu être initialisé.

Les plugins peuvent interroger les statistiques de la file d'attente avec auplugin_queue_depth, auplugin_queue_max_depth, et auplugin_queue_overflow. Enregistrez un callback avec auplugin_register_stats_callback, et appelez-le en utilisant auplugin_report_stats.

GESTION DES SIGNaux

Les plugins doivent établir des gestionnaires de signaux avec sigaction(2) avant d'entrer dans la boucle d'événements. Le gestionnaire SIGTERM doit appeler auplugin_stop() pour arrêter le thread de travail. Les gestionnaires pour d'autres signaux, tels que SIGHUP ou SIGUSR1, doivent définir des indicateurs globaux qui sont traités dans les callbacks d'événements ou de minuteur.

Exemple :

static volatile sig_atomic_t reload;
static void handler(int sig)
{
    if (sig == SIGTERM)
        auplugin_stop();
    else if (sig == SIGHUP)
        reload = 1;
}
