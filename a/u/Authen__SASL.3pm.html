Authen::SASL(3) Documentation Perl contribuée par les utilisateurs Authen::SASL(3)

NOM

Authen::SASL - Cadre d'authentification SASL

VERSION

version 2.1900

SYNOPSIS

use Authen::SASL;
$sasl = Authen::SASL->new(
  mechanism => 'CRAM-MD5 PLAIN ANONYMOUS',
  callback => {
    pass => \&fetch_password,
    user => $user,
  }
);

DESCRIPTION

SASL est un mécanisme générique d'authentification utilisé par plusieurs protocoles réseau. Authen::SASL fournit un cadre d'implémentation que tous les protocoles devraient pouvoir partager.

Le cadre permet d'insérer différentes implémentations de la classe de connexion. Au moment de la rédaction, il existait deux plugins de ce type.

Authen::SASL::Perl
Ce module implémente plusieurs mécanismes et est entièrement implémenté en Perl.
Authen::SASL::XS
Ce module utilise la bibliothèque C Cyrus SASL (les versions 1 et 2 sont prises en charge).
Authen::SASL::Cyrus
Ce module est le prédécesseur d'Authen::SASL::XS.

Jusqu'à la version 2.16, Authen::SASL::Cyrus était chargé comme alternative à Authen::SASL::XS.

Par défaut, Authen::SASL essaie d'abord de charger Authen::SASL::XS, puis Authen::SASL::Perl en cas d'échec. Si vous souhaitez modifier l'ordre ou utiliser spécifiquement une seule implémentation, faites simplement

use Authen::SASL qw(Perl);

ou si vous avez un autre module plugin qui prend en charge l'API Authen::SASL

use Authen::SASL qw(My::SASL::Plugin);

CONSTRUCTEUR

new ( OPTIONS )
Le constructeur peut être appelé avec ou sans arguments. Passer des arguments est simplement un raccourci pour appeler les méthodes "mechanism" et "callback" .
callback => { NAME => VALUE, NAME => VALUE, ... }
Définit les rappels (callbacks). Voir la méthode callback pour plus de détails.
mechanism => NAMES
mech => NAMES
Définit la liste des mécanismes parmi lesquels choisir. Voir la méthode mechanism pour plus de détails.
debug => VALUE
Définit le niveau de débogage (valeur de bits) à "VALUE"

La sortie de débogage sera envoyée vers "STDERR". Les bits de cette valeur sont :

1   Afficher les messages de débogage dans les modules Perl des mécanismes.
    (Actuellement utilisé uniquement dans GSSAPI)
4   Avec les couches de sécurité en place, afficher des informations sur les paquets lus.
8   Avec les couches de sécurité en place, afficher des informations sur les paquets écrits.

La valeur par défaut est 0.

MÉTHODES

mechanism ( )
Renvoie la liste actuelle des mécanismes
mechanism ( NAMES )
Définit la liste des mécanismes parmi lesquels choisir. "NAMES" doit être une chaîne d'objets de noms séparés par des espaces.
callback ( NAME )
Renvoie le rappel (callback) actuel associé à "NAME".
callback ( NAME => VALUE, NAME => VALUE, ... )
Définit les rappels donnés aux valeurs données
client_new ( SERVICE, HOST, SECURITY )
Crée et renvoie un nouvel objet de connexion pour une connexion côté client.
server_new ( SERVICE, HOST, OPTIONS )
Crée et renvoie un nouvel objet de connexion pour une connexion côté serveur.
error ( )
Renvoie toute erreur de la dernière connexion

La Classe de Connexion

server_start ( CHALLENGE )
server_start commence l'authentification en utilisant le mécanisme choisi. Si le mécanisme n'est pas pris en charge par le SASL installé, cela échoue. Comme pour certains mécanismes le client doit commencer la négociation, vous pouvez fournir le défi du client en paramètre.
server_step ( CHALLENGE )
server_step effectue l'étape suivante du processus de négociation. Le premier paramètre que vous fournissez est le défi/réponse du client.
client_start ( )
L'étape initiale à effectuer. Renvoie la valeur initiale à transmettre au serveur ou une liste vide en cas d'erreur.
client_step ( CHALLENGE )
Cette méthode est appelée lorsqu'une réponse du serveur l'exige. CHALLENGE est la valeur provenant du serveur. Renvoie la valeur suivante à transmettre au serveur ou une liste vide en cas d'erreur.
need_step ( )
Renvoie vrai si le mécanisme sélectionné nécessite une autre étape avant la fin (erreur ou succès).
answer ( NAME )
La méthode renverra la valeur renvoyée par le dernier appel au rappel NAME
property ( NAME )
Renvoie la valeur de propriété associée à "NAME".
property ( NAME => VALUE, NAME => VALUE, ... )
Définit les propriétés nommées à leurs valeurs associées.
service ( )
Renvoie l'argument de service qui a été passé aux méthodes *_new.
host ( )
Renvoie l'argument d'hôte qui a été passé aux méthodes *_new.
mechanism ( )
Renvoie le nom du mécanisme choisi.
is_success ( )
Une fois que need_step() renvoie faux, vous pouvez alors vérifier si l'authentification a réussi en appelant cette méthode qui renvoie une valeur booléenne.

Rappels (Callbacks)

Il existe trois façons différentes dont un rappel (callback) peut être transmis

CODEREF
Si la valeur transmise est une référence de code, alors, si nécessaire, elle sera appelée et l'objet de connexion sera passé en premier argument. De plus, certains rappels peuvent recevoir des arguments supplémentaires.
ARRAYREF
Si la valeur transmise est une référence de tableau, le premier élément du tableau doit être une référence de code. Lorsque le rappel est appelé, la référence de code sera appelée avec l'objet de connexion passé en premier argument et toutes les autres valeurs du tableau passées après.
SCALAR
Toutes les autres valeurs transmises seront utilisées directement. C'est-à-dire que c'est la même chose que de passer une référence de code qui, lorsqu'elle est appelée, renvoie la valeur.
