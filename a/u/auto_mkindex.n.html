execok cmd Détermine s'il existe un

Cette commande examine les répertoires du chemin de recherche actuel (donné par la variable d'environnement PATH) lors de sa recherche d'un fichier exécutable nommé cmd. Sur les plateformes Windows, la recherche est étendue avec les mêmes répertoires et extensions de fichier que ceux utilisés par exec. Auto_execok se souvient des informations sur les recherches précédentes dans un tableau nommé auto_execs ; cela évite la recherche de chemin lors des appels futurs pour le même cmd. La commande auto_reset peut être utilisée pour forcer auto_execok à oublier ses informations en cache. auto_import pattern Auto_import est invoqué pendant namespace import pour voir si les

Si c'est le cas, les commandes sont chargées afin qu'elles soient disponibles pour l'interpréteur lors de la création des liens d'importation. Si les commandes ne se trouvent pas dans une bibliothèque chargée automatiquement, auto_import ne fait rien. La correspondance de motifs est effectuée selon les règles de correspondance de namespace import. auto_load cmd Cette commande tente de charger la définition
d'une
commande Tcl nom
mée
cmd. Pour ce faire, elle recherche un chemin de chargement automatique, qui est une liste d'un ou plusieurs répertoires. Le chemin de chargement automatique est donné par la variable globale auto_path si elle existe. S'il n'y a pas de variable auto_path, alors la variable d'environnement TCLLIBPATH est utilisée, si elle existe. Sinon, le chemin de chargement automatique ne consiste qu'en le répertoire de la bibliothèque Tcl. Dans chaque répertoire du chemin de chargement automatique, il doit y avoir un fichier tclIndex qui décrit une ou plusieurs commandes définies dans ce répertoire et un script à évaluer pour charger chacune des commandes. Le fichier tclIndex doit être généré avec la commande auto_mkindex. Si cmd est trouvé dans un fichier d'index, alors le script approprié est évalué pour créer la commande. La commande auto_load renvoie 1 si cmd a été créé avec succès. La commande renvoie 0 s'il n'y avait pas d'entrée d'index pour cmd ou si le script n'a pas réellement défini cmd (par exemple parce que les informations d'index sont obsolètes). Si une erreur se produit lors du traitement du script, alors cette erreur est renvoyée. Auto_load ne lit les informations d'index qu'une seule fois et les enregistre dans le tableau auto_index ; les appels futurs à auto_load vérifient cmd dans le tableau plutôt que de relire les fichiers d'index. Les informations d'index en cache peuvent être supprimées avec la commande auto_reset. Cela forcera la prochaine commande auto_load à recharger la base de données d'index depuis le disque. auto_mkindex dir pattern pattern ... Génère

auto_qualify command namespace
Calcule
une liste de noms entièrement qualifiés pour command. Cette liste reflète le chemin qu'un interpréteur Tcl standard suit pour les recherches de commandes : d'abord il cherche la commande dans l'espace de noms courant, puis dans l'espace de noms global. En conséquence, si command est relative et namespace n'est pas ::, la liste renvoyée a deux éléments : command délimité par namespace, comme s'il s'agissait d'une commande dans l'espace de noms namespace ; et command comme s'il s'agissait d'une commande dans l'espace de noms global. Sinon, si soit command est absolu (il commence par ::), soit namespace est ::, la liste contient seulement command comme s'il s'agissait d'une commande dans l'e
space de noms glo

varNamedd>Ceci est une procédure de recherche standard à utiliser par les extensions lors de leur initialisation. Elles appellent cette procédure pour rechercher leur bibliothèque de scripts dans plusieurs répertoires standards. Le dernier composant du nom du répertoire de la bibliothèque est normalement basenameversion (par exemple, tk8.0), mais il peut être « library » dans les hiérarchies de construction. Le fichier initScript sera chargé dans l'interpréteur une fois qu'il est trouvé. Le répertoire dans lequel ce fichier est trouvé est stocké dans la variable globale varName. Si cette variable est déjà définie (par exemple, par du code C lors de l'initialisation de l'application), alors aucune recherche n'est effectuée. Sinon, la recherche examine ces répertoires : le répertoire nommé par la variable d'environnement enVarName ; relativement au répertoire de la bibliothèque Tcl ; relativement au fichier exécutable dans le répertoire standard d'installation bin ou bin/arch ; relativement au fichier exécutable dans l'arborescence de construction actuelle ; relativement au fichier exécutable dans une arborescence de construction parallèle.

tcl_endOfWord str
start
Renvoie l'indice de la première fin de mot qui apparaît après un indice de départ start dans la chaîne str. Une fin de mot est définie comme le premier caractère non mot suivant le premier caractère mot après le point de départ. Renvoie -1 s'il n'y a plus de fins de mot après le point de départ. Voir la description de tcl_wordchars et tcl_nonwordchars ci-dessous pour plus de détails sur la manière dont Tcl détermine quels caractères sont des caractères de
mot.

start
Renvoie l'indice du premier début de mot qui apparaît après un indice de départ start dans la chaîne str. Un début de mot est défini comme le premier caractère mot suivant un caractère non mot. Renvoie -1 s'il n'y a plus de débuts de mot après le point de
départ.

start

Cette variable contient une expression régulière utilisée par des routines comme tcl_endOfWord pour identifier si un caractère fait partie d'un mot ou non.
