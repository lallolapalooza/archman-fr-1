DESCRIPTIO

N

add_key() crée ou met à jour une clé du type et de la description donnés, l'instancie avec le payload de taille size, l'attache au keyring désigné, et renvoie le numéro de série de la

clé.

La clé peut être rejetée si les données fournies sont dans le mauvais format ou si elles sont invalides d'une autre

manière.

Si le keyring de destination contient déjà une clé qui correspond au type et à la description spécifiés, alors, si le type de clé le prend en charge, cette clé sera mise à jour plutôt que d'en créer une nouvelle ; sinon, une nouvelle clé (avec un ID différent) sera créée et elle remplacera le lien vers la clé existante dans le

keyring.

Le numéro de série du keyring de destination peut être celui d'un keyring valide pour lequel l'appelant dispose de la permission d'écriture. Alternativement, il peut s'agir de l'un des ID de keyring spéciaux suivants

:
KEY_SPEC_THREAD_KEYR
ING
Spécifie le keyring propre au thread de l'appelant (thread-keyrin
g(7)).
KEY_SPEC_PROCESS_KEYR
ING
Spécifie le keyring propre au processus de l'appelant (process-keyri
ng(7)).
KEY_SPEC_SESSION_KEYR
ING
Spécifie le keyring propre à la session de l'appelant (session-keyri
ng(7)).
KEY_SPEC_USER_KEYR
ING
Spécifie le keyring propre à l'UID de l'appelant (user-keyrin
g(7)).
KEY_SPEC_USER_SESSION_KEYR
ING
Spécifie le keyring session-UID de l'appelant (user-session
-keyrin
g(7)).

Types de

clés

Le type de clé est une chaîne qui spécifie le type de la clé. En interne, le noyau définit un certain nombre de types de clés disponibles dans le code de gestion des clés du noyau. Parmi les types disponibles pour une utilisation depuis l'espace utilisateur et pouvant être spécifiés comme argument type à add_key(), on trouve les suivants

:
"keyrin
g"
Les keyrings sont des types de clés spéciaux qui peuvent contenir des liens vers des séquences d'autres clés de n'importe quel type. Si cette interface est utilisée pour créer un keyring, alors payload doit être NULL et size doit être
zéro.
"use
r"
C'est un type de clé général dont le payload peut être lu et mis à jour par les applications de l'espace utilisateur. La clé est entièrement conservée en mémoire noyau. Le payload des clés de ce type est un blob de données arbitraires d'au plus 32 767
octets.
"logon" (depuis Linux
3.3)
Ce type de clé est essentiellement le même que "user", mais il ne permet pas de lire la clé. Cela convient pour stocker de
s payloads que vous ne voulez pas p
ouvoir lire depuis l'espace utilisateur.

Ce type de clé vérifie la description pour s'assurer qu'elle est qualifiée par un préfixe "service", en vérifiant que la description contient un ':' précédé d'autres

caractères.
"big_key" (depuis Linux 3.
13)
Ce type de clé est similaire à "user", mais peut contenir un payload d'au plus 1 Mio. Si le payload de la clé est assez volumineux,
il peut être stocké chiffré dans tmpfs (qui peu
t être mis en swap) plutôt qu'en mémoire noyau.

Pour plus de détails sur ces types de clés, voir keyri

ng
s(7
).

EXEMPLE

S

Le programme ci-dessous crée une clé avec le type, la description et le payload spécifiés dans ses arguments de ligne de commande, et lie cette clé au keyring de session. La session de shell suivante illustre l'utilisation du programme

: 


$ ./a.out user mykey "Some payload";
Key ID is 64a4dca
$ grep '64a4dca' /proc/keys;
064a4dca I--Q---    1 perm 3f010000  1000  1000 user    mykey:
12

Source du

programme 
#include <keyutils.h>
#include <stdint.h>
#include <stdio.h>
#include <stdlib.h>
#include <string.h>
int
main(int argc, char *argv[])
{
    key_serial_t key;
    if (argc != 4) {
        fprintf(stderr, "Usage: %s type description payload\n",
                argv[0]);
        exit(EXIT_FAILURE);
    }
    key = add_key(argv[1], argv[2], argv[3], strlen(argv[3]),
                  KEY_SPEC_SESSION_KEYRING);
    if (key == -1) {
        perror("add_key");
        exit(EXIT_FAILURE);
    }
    printf("Key ID is %jx\n", (uintmax_t)key);
    exit(EXIT_SUCCESS);
}
