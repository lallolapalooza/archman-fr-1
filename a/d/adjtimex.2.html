adjtimex(2) Manuel des appels système adjtimex(2)

NOM

adjtimex, clock_adjtime, ntp_adjtime - régler l'horloge du noyau

BIBLIOTHÈQUE

Bibliothèque C standard (libc,-lc)

SYNOPSIS

#include <sys/timex.h>
int adjtimex(struct timex *buf);
int clock_adjtime(clockid_t clk_id, struct timex *buf);
int ntp_adjtime(struct timex *buf);

DESCRIPTION

Linux utilise l'algorithme de réglage d'horloge de David L. Mills (voir RFC 5905). L'appel système adjtimex() lit et définit éventuellement les paramètres de réglage de cet algorithme. Il prend un pointeur vers une structure timex , met à jour les paramètres du noyau à partir des valeurs de champs (sélectionnés), et renvoie la même structure mise à jour avec les valeurs actuelles du noyau. Cette structure est déclarée comme suit :


struct timex {
    int  modes;      /* Sélecteur de mode */
    long offset;     /* Décalage temporel ; nanosecondes si l'indicateur
                        d'état STA_NANO est défini, sinon
                        microsecondes */
    long freq;       /* Décalage de fréquence ; voir NOTES pour les unités */
    long maxerror;   /* Erreur maximale (microsecondes) */
    long esterror;   /* Erreur estimée (microsecondes) */
    int  status;     /* Commande/état de l'horloge */
    long constant;   /* Constante de temps du PLL (boucle à verrouillage de
                        phase) */
    long precision;  /* Précision de l'horloge
                        (microsecondes, lecture seule) */
    long tolerance;  /* Tolérance de fréquence de l'horloge (lecture seule) ;
                        voir NOTES pour les unités */
    struct timeval time;
                     /* Heure actuelle (lecture seule, sauf pour
                        ADJ_SETOFFSET) ; au retour, time.tv_usec
                        contient des nanosecondes si l'indicateur
                        d'état STA_NANO est défini, sinon des
                        microsecondes */
    long tick;       /* Microsecondes entre deux ticks de l'horloge */
    long ppsfreq;    /* Fréquence PPS (pulse per second) (lecture
                        seule) ; voir NOTES pour les unités */
    long jitter;     /* Gigue PPS (lecture seule) ; nanosecondes si
                        l'indicateur d'état STA_NANO est défini, sinon
                        microsecondes */
    int  shift;      /* Durée de l'intervalle PPS
                        (secondes, lecture seule) */
    long stabil;     /* Stabilité PPS (lecture seule) ;
                        voir NOTES pour les unités */
    long jitcnt;     /* Comptage PPS des événements de dépassement de la
                        limite de gigue (lecture seule) */
    long calcnt;     /* Comptage PPS des intervalles de calibration
                        (lecture seule) */
    long errcnt;     /* Comptage PPS des erreurs de calibration
                        (lecture seule) */
    long stbcnt;     /* Comptage PPS des événements de dépassement de la
                        limite de stabilité (lecture seule) */
    int tai;         /* Décalage TAI, tel que défini par l'opération
                        ADJ_TAI précédente (secondes, lecture seule,
                        depuis Linux 2.6.26) */
    /* Octets de remplissage supplémentaires pour permettre une future
       expansion */
};

Le champ modes détermine quels paramètres, le cas échéant, définir. (Comme décrit plus tard dans cette page, les constantes utilisées pour ntp_adjtime() sont équivalentes mais différemment nommées.) C'est un masque de bits contenant une combinaison de bits OU bit à bit de zéro ou plusieurs des bits suivants :

ADJ_OFFSET
Définir le décalage temporel à partir de buf.offset. Depuis Linux 2.6.26, la valeur fournie est contrainte à l'intervalle (-0.5s, +0.5s). Dans les noyaux plus anciens, une erreur EINVAL se produit si la valeur fournie est hors de l'intervalle.
ADJ_FREQUENCY
Définir le décalage de fréquence à partir de buf.freq. Depuis Linux 2.6.26, la valeur fournie est contrainte à l'intervalle (-32768000, +32768000). Dans les noyaux plus anciens, une erreur EINVAL se produit si la valeur fournie est hors de l'intervalle.
ADJ_MAXERROR
Définir l'erreur temporelle maximale à partir de buf.maxerror.
ADJ_ESTERROR
Définir l'erreur temporelle estimée à partir de buf.esterror.
ADJ_STATUS
Définir les bits d'état de l'horloge à partir de buf.status. Une description de ces bits est fournie ci-dessous.
ADJ_TIMECONST
Définir la constante de temps du PLL à partir de buf.constant. Si l'indicateur d'état STA_NANO (voir ci-dessous) est effacé, le noyau ajoute 4 à cette valeur.
ADJ_SETOFFSET (depuis Linux 2.6.39)
Ajouter buf.time à l'heure actuelle. Si buf.status inclut l'indicateur ADJ_NANO , alors buf.time.tv_usec est interprété comme une valeur en nanosecondes ; sinon il est interprété comme des microsecondes.
La valeur de buf.time est la somme de ses deux champs, mais le champ buf.time.tv_usec doit toujours être non négatif. L'exemple suivant montre comment normaliser un timeval avec une résolution en nanosecondes.

while (buf.time.tv_usec < 0) {
    buf.time.tv_sec  -= 1;
    buf.time.tv_usec += 1000000000;
}

ADJ_MICRO (depuis Linux 2.6.26)
Sélectionner la résolution en microsecondes.
ADJ_NANO (depuis Linux 2.6.26)
Sélectionner la résolution en nanosecondes. Seul un des indicateurs ADJ_MICRO et ADJ_NANO devrait être spécifié.
ADJ_TAI (depuis Linux 2.6.26)
Définir le décalage TAI (Heure Atomique Internationale) à partir de buf.constant.
ADJ_TAI ne devrait pas être utilisé en conjonction avec ADJ_TIMECONST, car ce dernier mode utilise également le champ buf.constant .
Pour une explication complète du TAI et de la différence entre le TAI et l'UTC, voir BIPM
ADJ_TICK
Définir la valeur de tick à partir de buf.tick.

Alternativement, modes peut être spécifié comme l'une des valeurs suivantes (masque multi-bits), auquel cas d'autres bits ne devraient pas être spécifiés dans modes:

ADJ_OFFSET_SINGLESHOT
Ancien style adjtime(3): (graduellement) ajuster le temps par la valeur spécifiée dans buf.offset, qui spécifie un ajustement en microsecondes.
ADJ_OFFSET_SS_READ (fonctionnel depuis Linux 2.6.28)
Renvoyer (dans buf.offset) le montant restant du temps à ajuster après une opération ADJ_OFFSET_SINGLESHOT précédente. Cette fonctionnalité a été ajoutée dans Linux 2.6.24, mais n'a pas fonctionné correctement avant Linux 2.6.28.

Les utilisateurs ordinaires sont limités à une valeur de 0 ou ADJ_OFFSET_SS_READ pour modes. Seul le superutilisateur peut définir des paramètres.

Le champ buf.status est un masque de bits utilisé pour définir et/ou récupérer les bits d'état associés à l'implémentation NTP. Certains bits du masque sont à la fois lisibles et définissables, tandis que d'autres sont en lecture seule.

STA_PLL (lecture-écriture)
Activer les mises à jour de la boucle à verrouillage de phase (PLL) via ADJ_OFFSET.
STA_PPSFREQ (lecture-écriture)
Activer la régulation de fréquence PPS (pulse-per-second).
STA_PPSTIME (lecture-écriture)
Activer la régulation temporelle PPS.
STA_FLL (lecture-écriture)
Sélectionner le mode boucle à verrouillage de fréquence (FLL).
STA_INS (lecture-écriture)
Insérer une seconde intercalaire après la dernière seconde du jour UTC, étendant ainsi la dernière minute du jour d'une seconde. L'insertion de seconde intercalaire se produira chaque jour, tant que cet indicateur reste défini.
STA_DEL (lecture-écriture)
Supprimer une seconde intercalaire à la dernière seconde de la journée UTC. La suppression de seconde intercalaire se produira chaque jour, tant que ce drapeau reste défini.
STA_UNSYNC (lecture-écriture)
Horloge non synchronisée.
STA_FREQHOLD (lecture-écriture)
Maintenir la fréquence. Normalement, les ajustements effectués via ADJ_OFFSET entraînent également la réalisation d'ajustements de fréquence amortis. Ainsi, un seul appel corrige le décalage actuel, mais à mesure que des décalages dans la même direction sont effectués à plusieurs reprises, les petites corrections de fréquence s'accumuleront pour corriger la dérive à long terme.
Ce drapeau empêche la réalisation de la petite correction de fréquence lors de la correction d'une valeur ADJ_OFFSET .
STA_PPSSIGNAL (lecture seule)
Un signal PPS (pulse-per-second, une impulsion par seconde) valide est présent.
STA_PPSJITTER (lecture seule)
La gigue du signal PPS a été dépassée.
STA_PPSWANDER (lecture seule)
La dérive du signal PPS a été dépassée.
STA_PPSERROR (lecture seule)
Erreur d'étalonnage du signal PPS.
STA_CLOCKERR (lecture seule)
Défaut du matériel de l'horloge.
STA_NANO (lecture seule ; depuis Linux 2.6.26)
Résolution (0 = microseconde, 1 = nanoseconde). Défini via ADJ_NANO, effacé via ADJ_MICRO.
STA_MODE (depuis Linux 2.6.26)
Mode (0 = boucle à verrouillage de phase, 1 = boucle à verrouillage de fréquence).
STA_CLK (lecture seule ; depuis Linux 2.6.26)
Source d'horloge (0 = A, 1 = B) ; actuellement inutilisé.

Les tentatives de modification des bits de statut en lecture seule sont silencieusement ignorées.

clock_adjtime ()

L'appel système clock_adjtime() (ajouté dans Linux 2.6.39) se comporte comme adjtimex() mais prend un argument supplémentaire clk_id pour spécifier l'horloge particulière sur laquelle agir.

ntp_adjtime ()

La fonction de bibliothèque ntp_adjtime() (décrite dans le "Kernel Application Program API" de NTP, KAPI) est une interface plus portable pour effectuer la même tâche que adjtimex(). En dehors des points suivants, elle est identique à adjtimex() :

•
Les constantes utilisées dans modes sont préfixées par "MOD_" plutôt que "ADJ_", et ont les mêmes suffixes (ainsi, MOD_OFFSET, MOD_FREQUENCY, etc.), à l'exception des cas notés dans les points suivants.
•
MOD_CLKA est le synonyme de ADJ_OFFSET_SINGLESHOT.
•
MOD_CLKB est le synonyme de ADJ_TICK.
•
Il n'existe pas de synonyme pour ADJ_OFFSET_SS_READ, qui n'est pas décrit dans le KAPI.

VALEUR RENVOYÉE

En cas de succès, adjtimex() et ntp_adjtime() renvoient l'état de l'horloge, c'est-à-dire l'une des valeurs suivantes :

TIME_OK
Horloge synchronisée, aucune ajustement de seconde intercalaire en attente.
TIME_INS
Indique qu'une seconde intercalaire sera ajoutée à la fin de la journée UTC.
TIME_DEL
Indique qu'une seconde intercalaire sera supprimée à la fin de la journée UTC.
TIME_OOP
L'insertion d'une seconde intercalaire est en cours.
TIME_WAIT
L'insertion ou la suppression d'une seconde intercalaire a été terminée. Cette valeur sera renvoyée jusqu'à ce que l'opération ADJ_STATUS suivante efface les STA_INS et STA_DEL drapeaux.
TIME_ERROR
L'horloge système n'est pas synchronisée avec un serveur fiable. Cette valeur est renvoyée lorsque l'une des conditions suivantes est vraie :
•
Soit STA_UNSYNC ou STA_CLOCKERR est défini.
•
STA_PPSSIGNAL est effacé et soit STA_PPSFREQ ou STA_PPSTIME est défini.
•
STA_PPSTIME et STA_PPSJITTER sont tous deux définis.
•
STA_PPSFREQ est défini et soit STA_PPSWANDER ou STA_PPSJITTER est défini.
Le nom symbolique TIME_BAD est un synonyme de TIME_ERROR, fourni pour la compatibilité ascendante.

Notez qu'à partir de Linux 3.4, l'appel fonctionne de manière asynchrone et la valeur renvoyée ne reflétera généralement pas un changement d'état causé par l'appel lui-même.

En cas d'échec, ces appels renvoient -1 et définissent errno pour indiquer l'erreur.

ERREURS

EFAULT
buf ne pointe pas vers une mémoire accessible en écriture.
EINVAL (avant Linux 2.6.26)
Une tentative a été faite pour définir buf.freq à une valeur en dehors de la plage (-33554432, +33554432).
EINVAL (avant Linux 2.6.26)
Une tentative a été faite pour définir buf.offset à une valeur en dehors de la plage autorisée. Avant Linux 2.0, la plage autorisée était (-131072, +131072). À partir de Linux 2.0, la plage autorisée était (-512000, +512000).
EINVAL
Une tentative a été faite pour définir buf.status à une valeur autre que celles listées ci-dessus.
EINVAL
Le clk_id donné à clock_adjtime() est invalide pour l'une des deux raisons suivantes. Soit la valeur d'identifiant d'horloge positive codée en dur de style System-V est hors plage, soit le clk_id dynamique ne fait pas référence à une instance valide d'un objet horloge. Voir clock_gettime(2) pour une discussion sur les horloges dynamiques.
EINVAL
Une tentative a été faite pour définir buf.tick à une valeur en dehors de la plage 900000/HZ à 1100000/HZ, où HZ est la fréquence d'interruption du minutage système.
ENODEV
L'appareil à connexion à chaud (comme USB par exemple) représenté par un clk_id dynamique a disparu après l'ouverture de son périphérique caractère. Voir clock_gettime(2) pour une discussion sur les horloges dynamiques.
EOPNOTSUPP
Le clk_id donné ne prend pas en charge l'ajustement.
EPERM
buf.modes n'est ni 0 ni ADJ_OFFSET_SS_READ, et l'appelant ne dispose pas des privilèges suffisants. Sous Linux, la capacité CAP_SYS_TIME est requise.

NORMES

clock_adjtime()
Linux.

L'API recommandée pour le démon NTP est ntp_adjtime().

NOTES

Dans la structure timex, freq, ppsfreqet stabil sont en ppm (parties par million) avec une partie fractionnaire sur 16 bits, ce qui signifie qu'une valeur de 1 dans l'un de ces champs signifie en réalité 2^-16 ppm, et que 2^16=65536 correspond à 1 ppm. C'est le cas pour les valeurs d'entrée (dans le cas de freq) et pour les valeurs de sortie.

Le traitement des secondes intercalaires déclenché par STA_INS et STA_DEL est effectué par le noyau dans le contexte du minutage. Ainsi, il faudra un tick dans la seconde pour que la seconde intercalaire soit insérée ou supprimée.
