ADMIN(1P) Manuel du programmeur POSIX ADMIN(1P)

PROLOGUE

Cette page de manuel fait partie du Manuel du programmeur POSIX. L'implémentation Linux de cette interface peut différer (consultez la page de manuel Linux correspondante pour les détails du comportement sous Linux), ou l'interface peut ne pas être implémentée sous Linux.

NOM

admin — créer et administrer des fichiers SCCS (DÉVELOPPEMENT)

SYNTAXE

admin -i[nom] [-n] [-a connexion] [-d flag] [-e connexion] [-f flag]
    [-m liste_mr] [-r rel] [-t[nom] [-y[commentaire]] nouveau_fichier
admin -n [-a connexion] [-d flag] [-e connexion] [-f flag] [-m liste_mr]
    [-t[nom]] [-y[commentaire]] nouveau_fichier...
admin [-a connexion] [-d flag] [-m liste_mr] [-r rel] [-t[nom]] fichier...
admin -h fichier...
admin -z fichier...

DESCRIPTION

L'utilitaire admin crée de nouveaux fichiers SCCS ou modifie les paramètres de ceux existants. Si un fichier nommé n'existe pas, il est créé et ses paramètres sont initialisés conformément aux options spécifiées. Les paramètres non initialisés par une option reçoivent une valeur par défaut. Si un fichier nommé existe déjà, les paramètres correspondant aux options spécifiées sont modifiés, et les autres paramètres restent inchangés.

Tous les noms de fichiers SCCS fournis par l'application doivent être du format s.nom_de_fichier. Les nouveaux fichiers SCCS reçoivent le mode d'autorisation en lecture seule. Une autorisation d'écriture dans le répertoire parent est requise pour créer un fichier. Toutes les écritures effectuées par admin se font sur un fichier temporaire x-file, nommé x.nom_de_fichier (voir get), créé en lecture seule si admin crée un nouveau fichier SCCS, ou créé avec le même mode que celui du fichier SCCS si le fichier existe déjà. Après l'exécution réussie de admin, le fichier SCCS est supprimé (s'il existe) et le x-file est renommé avec le nom du fichier SCCS. Cela garantit que les modifications ne sont apportées au fichier SCCS qu'en l'absence d'erreurs.

L'utilitaire admin utilise également un fichier de verrouillage temporaire (nommé z.nom_de_fichier), qui sert à empêcher les mises à jour simultanées du fichier SCCS ; voir get.

OPTIONS

L'utilitaire admin est conforme aux Définitions de Base du volume POSIX.1‐2017, Section 12.2, Directives de Syntaxe d'Utilité, à l'exception des options -i, -t et -y qui acceptent des arguments d'option facultatifs. Ces arguments d'option facultatifs ne doivent pas être présentés comme des arguments séparés. Les options suivantes sont supportées :

-n
Crée un nouveau fichier SCCS. Lorsque -n est utilisé sans -i, le fichier SCCS est créé avec des informations de contrôle mais sans aucune donnée de fichier.
-i[nom]
Spécifie le nom d'un fichier à partir duquel le texte d'un nouveau fichier SCCS sera pris. Le texte constitue le premier delta du fichier (voir l'option -r pour le schéma de numérotation des deltas). Si l'option -i est utilisée, mais que l'argument d'option nom est omis, le texte est obtenu en lisant l'entrée standard. Si cette option est omise, le fichier SCCS est créé avec des informations de contrôle mais sans aucune donnée de fichier. L'option -i implique l'option -n.
-r SID
Spécifie le SID du delta initial à insérer. Ce SID doit être un SID de branche principale ; c'est-à-dire que les numéros de branche et de séquence sont nuls ou manquants. Le numéro de niveau est facultatif et vaut par défaut 1.
-t[nom]
Spécifie le nom d'un fichier à partir duquel le texte descriptif du fichier SCCS sera pris. Dans le cas de fichiers SCCS existants (ni -i ni -n n'est spécifié) :
*
Une option -t sans argument d'option nom provoque la suppression du texte descriptif (le cas échéant) actuellement dans le fichier SCCS.
*
Une option -t avec un argument d'option nom provoque le remplacement du texte (le cas échéant) du fichier nommé par le texte descriptif (le cas échéant) actuellement dans le fichier SCCS.
-f flag
Spécifie un flag, et éventuellement une valeur pour le flag, à placer dans le fichier SCCS. Plusieurs options -f peuvent être fournies sur une seule ligne de commande admin. Les implémentations doivent reconnaître les flags suivants et leurs valeurs associées :
b
Autorise l'utilisation de l'option -b sur une commande get pour créer des deltas de branche.
cplancher
Spécifie la plus haute révision (c'est-à-dire le plafond), un nombre inférieur ou égal à 9999, qui peut être récupéré par une commande get pour édition. La valeur par défaut pour un flag c non spécifié est 9999.
fplancher
Spécifie la plus basse révision (c'est-à-dire le plancher), un nombre supérieur à 0 mais inférieur à 9999, qui peut être récupéré par une commande get pour édition. La valeur par défaut pour un flag f non spécifié est 1.
dSID
Spécifie le numéro de delta par défaut (SID) à utiliser par une commande get.
ichaine
Traite le message "Aucun mot-clé d'identification" émis par get ou delta comme une erreur fatale. En l'absence de ce flag, le message n'est qu'un avertissement. Le message est émis si aucun mot-clé d'identification SCCS (voir get) n'est trouvé dans le texte récupéré ou stocké dans le fichier SCCS. Si une valeur est fournie, l'application doit s'assurer que les mots-clés correspondent exactement à la chaîne donnée ; cependant, la chaîne doit contenir un mot-clé, et aucun caractère de nouvelle ligne (<newline>) incorporé.
j
Autorise des commandes get concurrentes pour édition sur le même SID d'un fichier SCCS. Cela permet des mises à jour concurrentes multiples de la même version du fichier SCCS.
lliste
Spécifie une liste de révisions auxquelles les deltas ne peuvent plus être appliqués (c'est-à-dire que get -e contre l'une de ces révisions verrouillées échoue). Les applications conformes doivent utiliser la syntaxe suivante pour spécifier une liste. Les implémentations peuvent accepter des formes supplémentaires en tant qu'extension :
<liste> ::= a | <liste-de-plages>
<liste-de-plages> ::= <plage> | <liste-de-plages>, <plage>
<plage> ::= <SID>

Le caractère a dans la liste est équivalent à la spécification de toutes les révisions pour le fichier SCCS nommé. Le non-terminal <SID> dans plage est le numéro de delta d'un delta existant associé au fichier SCCS.

n
Induit delta à créer un delta nul dans chacune de ces révisions (le cas échéant) qui sont sautées lors de la création d'un delta dans une nouvelle révision (par exemple, en créant le delta 5.1 après le delta 2.7, les révisions 3 et 4 sont sautées). Ces deltas nuls servent de points d'ancrage afin que des deltas de branche puissent être créés ultérieurement à partir d'eux. L'absence de ce flag fait que les révisions sautées n'existent pas dans le fichier SCCS, empêchant la création de deltas de branche à partir d'elles à l'avenir. Lors de la création initiale d'un fichier SCCS, le flag n peut être ignoré ; c'est-à-dire que si l'option -r est utilisée pour définir le numéro de révision du SID initial à une valeur supérieure à 1, des deltas nuls ne sont pas nécessairement créés pour les révisions ``sautées''.
qtexte
Remplace les occurrences du mot-clé %Q% par le texte définissable par l'utilisateur dans le texte du fichier SCCS récupéré par get.
mmod
Spécifie le nom du module du fichier SCCS substitué à toutes les occurrences du mot-clé %M% dans le texte du fichier SCCS récupéré par get.

>. Si le drapeau m n'est pas spécifié, la valeur attribuée sera le nom du fichier SCCS avec le '.' de tête supprimé.
ttype
Spécifiez le type de module dans le fichier SCCS substitué à toutes les occurrences du mot-clé %Y% dans le texte du fichier SCCS récupéré par get.
vpgm
Force delta à demander les numéros de demande de modification (MR) comme raison de la création d'un delta. La valeur optionnelle spécifie le nom d'un programme de validation des numéros MR. (Si ce drapeau est défini lors de la création d'un fichier SCCS, l'application doit s'assurer que l'option m est également utilisée même si sa valeur est nulle.)
-d flag
Supprime (efface) le flag spécifié d'un fichier SCCS. Plusieurs options -d peuvent être fournies sur une seule commande admin. Voir l'option -f pour les noms de flag autorisés. (Le flag llist donne une liste des versions à déverrouiller. Voir l'option -f pour une description plus détaillée du flag l et la syntaxe d'une liste.)
-a login
Spécifiez un nom d'utilisateur (login) ou un identifiant de groupe numérique à ajouter à la liste des utilisateurs autorisés à créer des deltas (modifications) dans le fichier SCCS. Un identifiant de groupe doit être équivalent à la spécification de tous les noms d'utilisateur (login) appartenant à cet identifiant de groupe. Plusieurs options -a peuvent être utilisées sur une seule ligne de commande admin. Autant de logins ou d'identifiants de groupe numériques que souhaité peuvent être présents simultanément sur la liste. Si la liste des utilisateurs est vide, alors n'importe qui peut ajouter des deltas. Si le login ou l'identifiant de groupe est précédé d'un '!', les utilisateurs ainsi spécifiés se verront refuser la permission de créer des deltas.
-e login
Spécifiez un nom d'utilisateur (login) ou un identifiant de groupe numérique à effacer de la liste des utilisateurs autorisés à créer des deltas (modifications) dans le fichier SCCS. La spécification d'un identifiant de groupe est équivalente à la spécification de tous les noms d'utilisateur (login) appartenant à cet identifiant de groupe. Plusieurs options -e peuvent être utilisées sur une seule ligne de commande admin.
-y[commentaire]
Insérez le texte du commentaire dans le fichier SCCS comme commentaire pour le delta initial, d'une manière identique à celle de delta. Dans la locale POSIX, l'omission de l'option -y entraînera l'insertion d'une ligne de commentaire par défaut sous la forme :
"date et heure de création %s %s par %s", <date>, <heure>, <login>

où <date> est exprimée au format de la spécification de conversion %y/%m/%d de l'utilitaire date, <heure> au format de la spécification de conversion %T de l'utilitaire date, et <login> est le nom d'utilisateur de la personne créant le fichier.

-m mrlist
Insérez la liste des numéros de demande de modification (MR) dans le fichier SCCS comme raison de la création du delta initial, d'une manière identique à delta. L'application doit s'assurer que le drapeau v est défini et que les numéros MR sont validés si le drapeau v a une valeur (le nom d'un programme de validation des numéros MR). Un message de diagnostic sera écrit si le drapeau v n'est pas défini ou si la validation MR échoue.
-h
Vérifiez la structure du fichier SCCS et comparez la nouvelle somme de contrôle calculée avec la somme de contrôle stockée dans le fichier SCCS. Si la nouvelle somme de contrôle calculée ne correspond pas à la somme de contrôle dans le fichier SCCS, un message de diagnostic sera écrit.
-z
Recalculez la somme de contrôle du fichier SCCS et stockez-la dans la première ligne du fichier SCCS (voir l'option -h ci-dessus). Notez que l'utilisation de cette option sur un fichier réellement corrompu peut empêcher la détection future de la corruption.

OPERANDES

Les opérandes suivants seront pris en charge :

file
Un chemin vers un fichier SCCS existant ou un répertoire. Si file est un répertoire, l'utilitaire admin se comportera comme si chaque fichier du répertoire était spécifié comme un fichier nommé, sauf que les fichiers non SCCS (le composant final du chemin ne commence pas par s.) et les fichiers illisibles seront ignorés silencieusement.
newfile
Un chemin vers un fichier SCCS à créer.

Si exactement un opérande file ou newfile apparaît, et qu'il s'agit de '-', l'entrée standard sera lue ; chaque ligne de l'entrée standard sera considérée comme le nom d'un fichier SCCS à traiter. Les fichiers non SCCS et les fichiers illisibles seront ignorés silencieusement.

STDIN

L'entrée standard sera un fichier texte utilisé uniquement si -i est spécifié sans argument d'option ou si un opérande file ou newfile est spécifié comme '-'. Si le premier caractère d'une ligne d'entrée standard est <SOH> dans la locale POSIX, les résultats ne sont pas spécifiés.

FICHIERS ENTRÉE

Les fichiers SCCS existants seront des fichiers texte d'un format non spécifié.

L'application garantira que le fichier nommé par l'argument d'option name de l'option -i sera un fichier texte ; si le premier caractère d'une ligne de ce fichier est <SOH> dans la locale POSIX, les résultats ne sont pas spécifiés. Si ce fichier contient plus de 99999 lignes, le nombre de lignes enregistrées dans l'en-tête pour ce fichier sera de 99999 pour ce delta.

VARIABLES ENVIRONNEMENT

Les variables d'environnement suivantes affecteront l'exécution d'admin :

LANG
Fournit une valeur par défaut pour les variables d'internationalisation qui sont non définies ou vides. (Voir le volume Définitions de base de POSIX.1‐2017, Section 8.2, Variables d'internationalisation pour la précédence des variables d'internationalisation utilisées pour déterminer les valeurs des catégories de locale.)
LC_ALL
Si défini sur une chaîne de caractères non vide, remplace les valeurs de toutes les autres variables d'internationalisation.
LC_CTYPE
Détermine la locale pour l'interprétation des séquences d'octets de données textuelles en caractères (par exemple, caractères mono-octet par opposition aux caractères multi-octets dans les arguments et les fichiers d'entrée).
LC_MESSAGES

Détermine la locale qui doit être utilisée pour affecter le format et le contenu des messages de diagnostic écrits sur la sortie d'erreur standard et le contenu du commentaire par défaut -y.
NLSPATH
Détermine l'emplacement des catalogues de messages pour le traitement de LC_MESSAGES.

EVENEMENTS ASYNCHRONES

Par défaut.

STDOUT

Non utilisé.

STDERR

La sortie d'erreur standard sera utilisée uniquement pour les messages de diagnostic.

FICHIERS SORTIE

Tous les fichiers SCCS créés seront des fichiers texte d'un format non spécifié. Lors du traitement d'un fichier, un fichier de verrouillage z-file, tel que décrit dans get, peut être créé et supprimé.

DESCRIPTION ETENDUE

Aucune.

CODE RETOUR

Les valeurs de sortie suivantes seront retournées :

 0
Exécution réussie.
>0
Une erreur s'est produite.

CONSEQUENCES ERREURS

Par défaut.

Les sections suivantes sont informatives.

UTILISATION APPLICATION

Il est recommandé que les répertoires contenant des fichiers SCCS soient inscriptibles uniquement par le propriétaire, et que les fichiers SCCS eux-mêmes soient en lecture seule. Le mode des répertoires ne devrait autoriser que le propriétaire à modifier les fichiers SCCS qu'ils contiennent. Le mode des fichiers SCCS empêche toute modification, sauf par les commandes SCCS.
