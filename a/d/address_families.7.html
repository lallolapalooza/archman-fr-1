address_families(7) Manuel d'informations diverses address_families(7)

NOM

address_families - familles d'adresses de sockets (domaines)

SYNTAXE

#include <sys/types.h>          /* Voir NOTES */
#include <sys/socket.h>
int socket(int domain, int type, int protocol);

DESCRIPTION

L'argument domain de la fonction socket(2) spécifie un domaine de communication ; cela sélectionne la famille de protocoles qui sera utilisée pour la communication. Ces familles sont définies dans <sys/socket.h>. Les formats actuellement reconnus par le noyau Linux incluent :

AF_UNIX
AF_LOCAL
Communication locale. Pour plus d'informations, voir unix(7).
AF_INET
Protocoles Internet IPv4. Pour plus d'informations, voir ip(7).
AF_AX25
Protocole AX.25 de radio amateur. Pour plus d'informations, voir ax25(4).
AF_IPX
Protocoles IPX - Novell.
AF_APPLETALK
AppleTalk. Pour plus d'informations, voir ddp(7).
AF_NETROM
Protocole de couche paquet AX.25. Pour plus d'informations, voir netrom(4), The Packet Radio Protocols and Linux et les chapitres AX.25, NET/ROM et ROSE network programming du Linux Amateur Radio AX.25 HOWTO.
AF_BRIDGE
Ne peut pas être utilisé pour créer des sockets ; principalement utilisé pour les liens de pont dans les commandes du protocole rtnetlink(7).
AF_ATMPVC
Accès aux Circuits Virtuels Permanents (PVC) ATM. Pour plus d'informations, voir ATM on Linux HOWTO.
AF_X25
Protocole ITU-T X.25 / ISO/IEC 8208. Pour plus d'informations, voir x25(7).
AF_INET6
Protocoles Internet IPv6. Pour plus d'informations, voir ipv6(7).
AF_ROSE
RATS (Radio Amateur Telecommunications Society). Protocole de couche paquet AX.25 en environnement ouvert (ROSE). Pour plus d'informations, voir les ressources listées pour AF_NETROM.
AF_DECnet
Sockets du protocole DECnet. Voir Documentation/networking/decnet.txt dans l'arborescence des sources du noyau Linux pour les détails.
AF_NETBEUI
Réservé pour le "projet 802.2LLC" ; jamais utilisé.
AF_SECURITY
Il s'agissait d'une famille de protocoles de courte durée (entre Linux 2.1.30 et 2.1.99pre2) pour les appels système de pare-feu (firewall upcalls).
AF_KEY
Protocole de gestion de clés, initialement développé pour être utilisé avec IPsec (depuis Linux 2.1.38). Cela n'a aucun rapport avec keyctl(2) et le système de stockage de clés en noyau. Voir RFC 2367 PF_KEY Key Management API, Version 2 pour les détails.
AF_NETLINK
Interface utilisateur noyau. Pour plus d'informations, voir netlink(7).
AF_PACKET
Interface de paquets de bas niveau. Pour plus d'informations, voir packet(7).
AF_ECONET
Protocole Acorn Econet (supprimé dans Linux 3.5). Voir la documentation Econet pour les détails.
AF_ATMSVC
Accès aux Circuits Virtuels Commutés (SVC) ATM. Voir le ATM on Linux HOWTO pour les détails.
AF_RDS
Protocole Reliable Datagram Sockets (RDS) (depuis Linux 2.6.30). RDS sur RDMA n'a aucun rapport avec AF_SMC ou AF_XDP. Pour plus d'informations, voir rds(7), rds-rdma(7), et Documentation/networking/rds.txt dans l'arborescence des sources du noyau Linux.
AF_IRDA
Interface de socket sur IrDA (déplacé vers staging dans Linux 4.14, supprimé dans Linux 4.17). Pour plus d'informations, voir irda(7).
AF_PPPOX
Couche de transport générique PPP, pour la configuration de tunnels L2 (L2TP et PPPoE). Voir Documentation/networking/l2tp.txt dans l'arborescence des sources du noyau Linux pour les détails.
AF_WANPIPE
Protocole obsolète pour la connectivité de réseau étendu (WAN) qui était utilisé par les cartes WAN Sangoma (appelées "WANPIPE") ; supprimé dans Linux 2.6.21.
AF_LLC
Protocole Logical link control (IEEE 802.2 LLC), partie supérieure de la couche liaison de données de la pile de protocoles réseau ISO/OSI (depuis Linux 2.4) ; n'a aucun rapport avec AF_PACKET. Voir le chapitre 13.5.3. Logical Link Control dans Understanding Linux Kernel Internals (O'Reilly Media, 2006) et IEEE Standards for Local Area Networks: Logical Link Control (The Institute of Electronics and Electronics Engineers, Inc., New York, New York, 1985) pour les détails. Voir également quelques notes historiques concernant son développement.
AF_IB
Adressage natif InfiniBand (depuis Linux 3.11).
AF_MPLS
Multiprotocol Label Switching (depuis Linux 4.1) ; principalement utilisé pour configurer le routage MPLS via netlink(7), car il n'expose pas de capacité de création de sockets à l'espace utilisateur.
AF_CAN
Protocole de bus automobile Controller Area Network (depuis Linux 2.6.25). Voir Documentation/networking/can.rst dans l'arborescence des sources du noyau Linux pour les détails.
AF_TIPC
TIPC, protocole "cluster domain sockets" (depuis Linux 2.6.16). Voir TIPC Programmer's Guide et la description du protocole pour les détails.
AF_BLUETOOTH
Protocole de socket de bas niveau Bluetooth (depuis Linux 3.11). Voir Aperçu de l'API de gestion Bluetooth et Introduction à la programmation Bluetooth par Albert Huang pour les détails.
AF_IUCV
Protocole IUCV (inter-user communication vehicle) z/VM pour l'interaction hyperviseur-invité (depuis Linux 2.6.21) ; n'a aucun rapport avec AF_VSOCK et/ou AF_SMC. Voir Aperçu du protocole IUCV pour les détails.
AF_RXRPC
Protocoles RPC (Remote Procedure Call) pour le système de fichiers Andrew (AFS) (depuis Linux 2.6.36). Voir Documentation/networking/rxrpc.rst dans l'arborescence des sources du noyau Linux pour les détails.
AF_LLWO
Système d'exploitation pour la gestion des réseaux virtuels (Virtual machine network OS) (depuis Linux 3.18).
AF_AAL5
Connectivité ATM Adaptation Layer 5 (depuis Linux 2.6.26). Voir Documentation/networking/aal5.rst dans l'arborescence des sources du noyau Linux pour les détails.
AF_MAX
La valeur maximale pour les familles d'adresses.

Le domaine AF_UNSPEC est utilisé pour spécifier un domaine indéterminé. Pour la famille de protocoles spécifiée, le troisième argument de la fonction socket(2), protocol, spécifie un protocole particulier à utiliser dans le domaine sélectionné. La spécification d'un protocole particulier est facultative. Si protocol est zéro, le protocole générique pour le type de socket demandé est choisi.

Les familles d'adresses sont souvent associées à des protocoles de communication, et les noms des familles d'adresses sont souvent représentés par des constantes commençant par AF_ (par exemple, AF_INET) et les constantes correspondantes pour les protocoles de sockets sont souvent représentées par des constantes commençant par PF_ (par exemple, PF_INET). La fonction socket(2) traite ces deux familles de noms de manière identique.

En plus des familles de protocoles mentionnées ci-dessus, il existe les valeurs spéciales suivantes :

AF_UNSPEC
Domaine indéterminé.

Pour une liste exhaustive des familles d'adresses prises en charge et de leurs protocoles associés, vous pouvez consulter le fichier d'en-tête <sys/socket.h> dans votre système.

Les familles d'adresses sont couramment utilisées pour sélectionner des protocoles de communication spécifiques. Les noms des familles d'adresses sont généralement représentés par des constantes commençant par AF_ (par exemple, AF_INET), tandis que les constantes correspondantes pour les protocoles de sockets sont souvent représentées par des constantes commençant par PF_ (par exemple, PF_INET). La fonction socket(2) traite ces deux noms de famille de manière identique.

NOTES

L'inclusion de certains en-têtes peut définir d'autres constantes d'en-tête qui sont nécessaires pour utiliser certaines fonctions. Par exemple, pour utiliser certaines fonctionnalités réseau, vous pourriez avoir besoin de fichiers d'en-tête supplémentaires comme <netinet/in.h>.

Certaines familles d'adresses sont spécifiques à certaines architectures ou versions du noyau et peuvent ne pas être disponibles sur tous les systèmes.

Les liens vers des documents externes (HOWTOs, RFCs, etc.) fournis dans cette page manuelle sont donnés à titre indicatif. Il est recommandé de consulter la documentation officielle ou les versions les plus récentes de ces documents si nécessaire.

VOIR AUSSI

address_families(7) — Linux manual pages

NAME

address_families — protocol families

DESCRIPTION

This manual page lists the protocol families (also known as address families) that are supported by the Linux kernel. These families are used with the socket(2) system call to specify the communication domain in which a socket should be created.

The supported protocol families include:

AF_UNIX
Local communication socket. This is the default protocol family for the socket(2) system call. See unix(7) for details.
AF_INET
IPv4 protocol family. See ip(7) for details.
AF_IPX
IPX protocol family (used by Novell NetWare). This is deprecated and may be removed in future kernel versions.
AF_PACKET
Low-level packet interface. This allows you to receive and send raw network packets directly. See packet(7) for details.
AF_AX25
Amateur radio AX.25 protocol family. See ax25(4) for details.
AF_X25
ISO X.25 Protocol. Deprecated.
AF_INET6
IPv6 protocol family. See ipv6(7) for details.
AF_ROSE
Radio Open Systems Network (ROSE) protocol. Deprecated.
AF_DECnet
Digital Equipment Corporation DECnet protocol family. Deprecated.
AF_NETLINK
Kernel user interface netlink socket. This is a flexible interface for kernel-userspace communication. See netlink(7) for details.
AF_RDS
Reliable Datagram Sockets (RDS) protocol, used for high-performance cluster communication. See rds(7) for details.
AF_SCTP
Stream Control Transmission Protocol (SCTP). See sctp(7) for details.
AF_LLC
Link-Level Control protocol. Used for some older networking protocols.
AF_IB
Native InfiniBand socket protocol family. See rdma(7) for details.
AF_MPLS
MPLS (Multi-Protocol Label Switching) protocol family. See mpls(7) for details.
AF_CAN
Controller Area Network (CAN) protocol family. Used for automotive diagnostics and control. See can(7) for details.
AF_TIPC
TIPC (Transparent Inter-Process Communication) protocol. Used for clustering and high availability. See tipc(7) for details.
AF_BLUETOOTH
Bluetooth protocol family. See bluetooth(7) for details.
AF_IUCV
IBM's Inter-User Communications Vehicle protocol. Used for communication between guest and host on IBM mainframes. See iucv(7) for details.
AF_RXRPC
RXRPC protocol (since Linux 2.6.22). See Documentation/networking/rxrpc.txt in the Linux kernel source tree for details.
AF_ISDN
New "modular ISDN" driver interface protocol (since Linux 2.6.27). See the mISDN wiki for details.
AF_PHONET
Nokia cellular modem IPC/RPC interface (since Linux 2.6.31). See Documentation/networking/phonet.txt in the Linux kernel source tree for details.
AF_IEEE802154
IEEE 802.15.4 WPAN (wireless personal area network) raw packet protocol (since Linux 2.6.31). See Documentation/networking/ieee802154.txt in the Linux kernel source tree for details.
AF_CAIF
Ericsson's Communication CPU to Application CPU interface (CAIF) protocol (since Linux 2.6.36). See Documentation/networking/caif/Linux-CAIF.txt in the Linux kernel source tree for details.
AF_ALG
Interface to kernel crypto API (since Linux 2.6.38). See Documentation/crypto/userspace-if.rst in the Linux kernel source tree for details.
AF_VSOCK
VMWare VSockets protocol for hypervisor-guest interaction (since Linux 3.9); has no relation to AF_IUCV and AF_SMC. For further information, see vsock(7).
AF_KCM
KCM (kernel connection multiplexer) interface (since Linux 4.6). See Documentation/networking/kcm.txt in the Linux kernel source tree for details.
AF_QIPCRTR
Qualcomm IPC router interface protocol (since Linux 4.7).
AF_SMC
SMC-R (shared memory communications over RDMA) protocol (since Linux 4.11), and SMC-D (shared memory communications, direct memory access) protocol for intra-node z/VM quest interaction (since Linux 4.19); has no relation to AF_RDS, AF_IUCV or AF_VSOCK. See RFC 7609 IBM's Shared Memory Communications over RDMA (SMC-R) Protocol for details regarding SMC-R. See SMC-D Reference Information for details regarding SMC-D.
AF_XDP
XDP (express data path) interface (since Linux 4.18). See Documentation/networking/af_xdp.rst in the Linux kernel source tree for details.
AF_MCTP
MCTP (Management Component Transport Protocol) interface (since Linux 5.15), as defined by the DMTF specification DSP0236. For further information, see mctp(7).
