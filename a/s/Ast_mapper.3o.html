L'interface d'un réécrivain -ppx

Un réécrivain -ppx est un programme qui accepte un arbre de syntaxe abstraite sérialisé et en produit un autre, éventuellement modifié, arbre de syntaxe abstraite. Ce module encapsule l'interface entre le compilateur et les réécrivains -ppx, en gérant des détails tels que le format de sérialisation, la transmission des options de ligne de commande et le stockage de l'état.

Ast_mapper.mapper permet la réécriture de l'AST en utilisant la récursion ouverte. Un mapper typique serait basé sur Ast_mapper.default_mapper , un mapper d'identité profonde, et y recourrait pour gérer la syntaxe qu'il ne modifie pas. Par exemple :

open Asttypes
open Parsetree
open Ast_mapper
let test_mapper argv =
  { default_mapper with
    expr = fun mapper expr ->
      match expr with
      | { pexp_desc = Pexp_extension ({ txt = "test" }, PStr [])} ->
        Ast_helper.Exp.constant (Pconst_integer ("42", None))
      | other -> default_mapper.expr mapper other; }
let () =
  register "ppx_test" test_mapper

Ce réécrivain -ppx, qui remplace [%test] dans les expressions par la constante 42 , peut être compilé en utilisant ocamlc -o ppx_test -I +compiler-libs ocamlcommon.cma ppx_test.ml .

Avertissement : ce module est instable et fait partie de Compiler_libs .

Un enregistrement mapper implémente une « méthode » par catégorie syntaxique, en utilisant un style de récursion ouverte : chaque méthode prend comme premier argument le mapper à appliquer aux enfants dans l'arbre de syntaxe.

val default_mapper : mapper

Un mapper par défaut, qui implémente un mapping d'identité « profonde ».

Apply mappers to compilation units

val tool_name : unit -> string

Peut être utilisé dans un préprocesseur ppx pour savoir quel outil l'appelle "ocamlc" , "ocamlopt" , "ocamldoc" , "ocamldep" , "ocaml" , ... Certaines variables globales qui reflètent les options de ligne de commande sont automatiquement synchronisées entre l'outil appelant et le préprocesseur ppx : Clflags.include_dirs , Clflags.hidden_include_dirs , Load_path , Clflags.open_modules , Clflags.for_package , Clflags.debug .

val apply : source:string -> target:string -> mapper -> unit

Applique un mapper (paramétré par le nom de l'unité) à un parsetree sérialisé trouvé dans le fichier source et place le résultat dans le fichier target . Le champ structure ou signature du mapper est appliqué à l'implémentation ou à l'interface.

val run_main : (string list -> mapper) -> unit

Point d'entrée à appeler pour implémenter un réécrivain -ppx autonome à partir d'un mapper, paramétré par les arguments de la ligne de commande. Le nom de l'unité courante peut être obtenu à partir de Location.input_name . Cette fonction implémente un rapport d'erreurs approprié pour les exceptions non capturées.

Registration API

val register_function : (string -> (string list -> mapper) -> unit) ref

val register : string -> (string list -&gt; mapper) -> unit

Applique le register_function . Le comportement par défaut est d'exécuter le mapper immédiatement, en prenant les arguments de la ligne de commande du processus. Cela permet de prendre en charge le scénario où un mapper est lié en tant qu'exécutable autonome.

Il est possible de remplacer le register_function pour définir des « drivers -ppx », qui combinent plusieurs mappers dans un seul processus. Typiquement, un driver commence par définir register_function avec une implémentation personnalisée, puis laisse les réécritures ppx (liées statiquement ou dynamiquement) s'enregistrer elles-mêmes, et exécute ensuite toutes ou certaines d'entre elles. Il est également possible que les drivers -ppx appliquent les réécritures uniquement à des parties spécifiques d'un AST.

Le premier argument de register est un nom symbolique utilisé par le driver ppx.

Fonctions de commodité pour écrire des mappers

val map_opt : ('a -> 'b) -> 'a option -> 'b option

val extension_of_error : Location.error -> Parsetree.extension

Encode une erreur dans un nœud d'extension 'ocaml.error' qui peut être inséré dans un Parsetree généré. Le compilateur sera responsable de signaler l'erreur.

val attribute_of_warning : Location.t -> string -> Parsetree.attribute

Encode un message d'avertissement dans un attribut 'ocaml.ppwarning' qui peut être inséré dans un Parsetree généré. Le compilateur sera responsable de signaler l'avertissement.

Fonctions utilitaires pour appeler des mappers externes

val add_ppx_context_str : tool_name:string -> Parsetree.structure -> Parsetree.structure

Extrait des informations de l'environnement courant et les encode dans un attribut qui est préfixé à la liste des éléments de structure afin de passer les informations à un processeur externe.

val add_ppx_context_sig : tool_name:string -> Parsetree.signature -> Parsetree.signature

Identique à add_ppx_context_str , mais pour les signatures.

val drop_ppx_context_str : restore:bool -> Parsetree.structure -> Parsetree.structure

Supprime l'attribut ocaml.ppx.context d'une structure. Si restore est vrai, restaure également les données associées dans le processus courant.

val drop_ppx_context_sig : restore:bool -> Parsetree.signature -> Parsetree.signature

Identique à drop_ppx_context_str , mais pour les signatures.
