ASCII(1)   ASCII(1)

NOM

ascii - signaler les alias de caractères

SYNTAXE

ascii [-d] [-x] [-o] [-h] [-v] [alias-caractère]

OPTIONS

Appelé sans options, ascii se comporte comme "ascii -h". Les options sont les suivantes :

-t

Mode adapté aux scripts, n'émet que les encodages ISO/décimal/hexadécimal/octal/binaire du caractère.

-s

Analyser plusieurs caractères. Moyen pratique d'analyser des chaînes de caractères.

-a

Afficher en aspect vertical (4 colonnes par 16 lignes) plutôt qu'en 16x4. Cette option ne se combine qu'avec -d -o -x -b et doit les précéder.

-d

Table ASCII en décimal.

-x

Table ASCII en hexadécimal.

-o

Table ASCII en octal.

-b

Table ASCII en binaire.

-h, -?

Afficher un résumé des options et une table ASCII simple.

-v

Afficher la version du programme.

DESCRIPTION

Les caractères de l'ensemble ASCII peuvent avoir de nombreux alias, en fonction du contexte. Les noms possibles d'un caractère incluent :

•Son modèle de bits (représentation binaire).
•Ses représentations hexadécimale, décimale et octale.
•Son mnémonique de téléscripteur et sa forme en notation caret (pour les caractères de contrôle).
•Sa forme d'échappement par antislash en C (pour certains caractères de contrôle).
•Sa forme imprimée (pour les caractères imprimables).
•Son nom officiel ISO en anglais.
•Sa référence de table de code ISO/ECMA.
•Son nom en tant qu'entité HTML/SGML.
•Des noms argotiques et autres largement utilisés pour celui-ci parmi les hackers.

Cet utilitaire accepte des chaînes de caractères en ligne de commande et tente de les interpréter comme l'une des options ci-dessus. Lorsqu'il trouve une valeur, il imprime *tous* les noms du caractère. Les constructions de la liste suivante peuvent être utilisées pour spécifier les valeurs des caractères. Si un argument peut être interprété de plusieurs manières, les noms de tous les caractères différents qu'il pourrait être sont renvoyés.

caractère

Tout caractère non décrit par l'une des conventions suivantes représente le caractère lui-même.

^caractère

Un caret suivi d'un caractère.

\[abfnrtv0]: Un antislash suivi de certains caractères spéciaux (abfnrtv).

mnémonique

Un mnémonique de téléscripteur ASCII.

hexadécimal

Une séquence hexadécimale (hex) consiste en un ou deux caractères hexadécimaux insensibles à la casse (01234567890abcdef). Pour garantir l'interprétation hexadécimale, utilisez l'un des préfixes h, 0x, x ou \x.

décimal

Une séquence décimale consiste en un, deux ou trois chiffres décimaux (0123456789). Pour garantir l'interprétation décimale, utilisez l'un des préfixes d, 0d ou \d.

octal

Une séquence octale consiste en un, deux ou trois chiffres octaux (01234567). Pour garantir l'interprétation octale, utilisez l'un des préfixes 0o, o ou \o.

modèle de bits

Une séquence de modèle de bits (binaire) consiste en un à huit chiffres binaires (01). Pour garantir l'interprétation des bits, utilisez l'un des préfixes 0bm b ou \b.

code ISO/ECMA

Une séquence de code ISO/ECMA consiste en un ou deux chiffres décimaux, une barre oblique et un ou deux chiffres décimaux.

nom

Un nom officiel ASCII ou un nom (non officiel) en argot.

:classe:

Une classe de caractères POSIX nommée.

Les noms argotiques reconnus et imprimés proviennent d'une liste assez complète qui est apparue pour la première fois sur USENET début 1990 et a été continuellement mise à jour depuis. Les mnémoniques reconnus et imprimés incluent l'ensemble ASCII officiel, certains noms ISO officiels (lorsqu'ils diffèrent) et quelques alternatives couramment utilisées (telles que NL pour LF). Les noms d'entités HTML/SGML sont également imprimés le cas échéant. Toutes les comparaisons sont insensibles à la casse et les tirets sont remplacés par des espaces. Tous les arguments non reconnus ou les valeurs hors limites sont ignorés silencieusement. Notez que l'option <option>-s</option> ne reconnaîtra pas les noms « longs », car elle ne peut pas les différencier des autres parties de la chaîne.

Pour des résultats corrects, veillez à échapper ou à mettre entre guillemets les métacaractères du shell dans les arguments (en particulier l'antislash).

Cet utilitaire est particulièrement utile pour interpréter les horribles messages d'erreur d'octet octal de cc(1), ou lors du codage de quoi que ce soit lié aux communications série. En tant qu'effet secondaire, il sert de convertisseur de base pratique pour des valeurs aléatoires de 8 bits.
