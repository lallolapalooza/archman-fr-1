NOM

astraceroute - utilitaire de traceroute pour système autonome

SYNOPSIS

astraceroute [options]

DESCRIPTION

astraceroute est un petit utilitaire pour obtenir des informations sur le chemin d'accès de manière similaire à traceroute, mais avec des informations supplémentaires sur la localisation géographique. Il suit le chemin d'un paquet de l'hôte local vers l'hôte distant en augmentant successivement le champ TTL de l'IP, à partir de 1, dans l'espoir que chaque nœud intermédiaire enverra une notification ICMP TIME_EXCEEDED à l'hôte local lorsque la valeur TTL est décrémentée à 0.

astraceroute prend en charge les requêtes IPv4 et IPv6 et affichera les informations de pays et de ville, si disponibles, le numéro d'AS auquel le saut appartient, et le nom de son FAI. astraceroute affiche également des informations de temporisation et des données DNS inversées.

En raison de la configurabilité d'astraceroute, il est également possible de recueillir des informations plus utiles sur le saut concernant ce qu'il autorise et n'autorise pas à passer. Ceci est fait en utilisant des chaînes de texte en clair pour sonder les DPI ou les « grands pare-feu » afin de déterminer s'ils filtreront les mots-clés critiques bloqués. Cet outil pourrait être un bon point de départ pour une analyse plus approfondie de tels systèmes.

OPTIONS

-H <host>, --host <host>
Nom d'hôte ou adresse IPv4 ou IPv6 de l'hôte distant vers lequel la route AS doit être tracée. Dans le cas d'une adresse ou d'un hôte IPv6, l'option -6 doit être utilisée. IPv4 est la valeur par défaut.
-p <port>, --port <port>
Port TCP à utiliser pour l'hôte distant. Si non spécifié, le port par défaut utilisé est 80.
-i <device>, -d <device>, --dev <device>
Périphérique réseau à partir duquel commencer le traceroute, par ex. eth0, wlan0.
-b <IP>, --bind <IP>
Adresse IP à lier autre que celle du périphérique réseau. Vous devez spécifier -6 pour une adresse IPv6.
-f <ttl>, --init-ttl <ttl>
Valeur TTL initiale à utiliser. Cette option peut être utile si vous n'êtes pas intéressé par les n premiers sauts, mais seulement par les suivants. La valeur TTL initiale par défaut est 1.
-m <ttl>, --max-ttl <ttl>
Valeur TTL maximale à utiliser. Si non spécifiée autrement, la valeur TTL maximale est 30. Ainsi, après que celle-ci a été atteinte, astraceroute se termine.
-q <num>, --num-probes <num>
Spécifie le nombre de requêtes à effectuer sur un saut particulier. La valeur par défaut est 2 requêtes de sonde.
-x <sec>, --timeout <sec]]
Indique à astraceroute le délai d'attente de réponse de la sonde en secondes, en d'autres termes le temps maximum qu'astraceroute doit attendre pour une réponse ICMP du saut actuel. La valeur par défaut est 3 secondes.
-X <string>, --payload <string>
Place une chaîne de texte ASCII en clair dans la charge utile du paquet. Le texte en clair contenant des espaces doit être mis entre guillemets (ex. : "censor me").
-l <len>, --totlen <len>
Spécifie la longueur totale du paquet. La charge utile qui ne contient pas de chaîne de texte en clair est complétée par des données aléatoires.
-4, --ipv4
Utiliser uniquement des requêtes IPv4. C'est la valeur par défaut.
-6, --ipv6
Utiliser uniquement des requêtes IPv6. Ceci doit être utilisé lors du passage d'un hôte IPv6 en argument.
-n, --numeric
Indique à astraceroute de ne pas effectuer de résolution DNS inversée pour les réponses des sauts. L'option inverse est -N.
-u, --update
Le mécanisme de mise à jour intégré de la base de données géo sera invoqué pour obtenir la dernière version de Maxmind. Pour configurer les emplacements de recherche des bases de données, le fichier /etc/netsniff-ng/geoip.conf contient les adresses possibles. Ainsi, pour économiser de la bande passante ou pour faire un miroir des bases de données de Maxmind (pour contourner leur politique de limite de trafic), différents hôtes ou adresses IP peuvent être placés dans geoip.conf, séparés par un saut de ligne.
-L, --latitude
Afficher également la latitude et la longitude des sauts.
-N, --dns
Indique à astraceroute d'effectuer une résolution DNS inversée pour les réponses des sauts. L'option inverse est -n.
-S, --syn
Utiliser l'indicateur SYN de TCP pour la requête.
-A, --ack
Utiliser l'indicateur ACK de TCP pour la requête.
-F, --fin
Utiliser l'indicateur FIN de TCP pour la requête.
-P, --psh
Utiliser l'indicateur PSH de TCP pour la requête.
-U, --urg
Utiliser l'indicateur URG de TCP pour la requête.
-R, --rst
Utiliser l'indicateur RST de TCP pour la requête.
-E, --ecn-syn
Utiliser l'indicateur ECN de TCP pour la requête.
-t <tos>, --tos <tos>
Spécifier explicitement le TOS de l'IP.
-G, --nofrag
Définir l'indicateur de non-fragmentation de l'IP.
-Z, --show-packet
Afficher et disséquer le paquet retourné.
-v, --version
Afficher les informations de version et quitter.
-h, --help
Afficher l'aide utilisateur et quitter.

EXEMPLE D'UTILISATION

astraceroute -i eth0 -N -S -H netsniff-ng.org
Cela envoie une sonde TCP SYN via le périphérique réseau ''eth0'' vers l'hôte IPv4 distant netsniff-ng.org. Cette requête a de fortes chances de passer. De plus, indique à astraceroute d'effectuer des résolutions DNS inversées pour chaque saut.
astraceroute -6 -i eth0 -S -E -N -H www.6bone.net
Dans cet exemple, une sonde TCP SYN/ECN pour l'hôte IPv6 www.6bone.net est effectuée. Dans ce cas également, le périphérique ''eth0'' est utilisé ainsi qu'une résolution DNS inversée pour chaque saut.
astraceroute -i eth0 -N -F -H netsniff-ng.org
Ici, nous envoyons une sonde TCP FIN vers l'hôte distant netsniff-ng.org. De nouveau, une résolution DNS inversée est effectuée sur chaque saut et les requêtes sont transmises depuis ''eth0''. IPv4 est utilisé.
astraceroute -i eth0 -N -FPU -H netsniff-ng.org
Comme dans la plupart des autres exemples, nous effectuons un traceroute vers l'hôte IPv4 netsniff-ng.org et faisons cette fois une sonde TCP Xmas.
astraceroute -i eth0 -N -H netsniff-ng.org -X censor-me -Z
Dans cet exemple, nous avons une sonde Null vers l'hôte distant netsniff-ng.org, port 80 (par défaut) et cette fois, nous ajoutons la chaîne de texte en clair "censor-me" dans la charge utile du paquet pour tester si un pare-feu ou un DPI laissera passer cette chaîne. Un tel traceroute pourrait être fait une fois sans et une fois avec une chaîne bloquée pour recueillir des informations possibles sur la censure.

NOTE

Si une sonde basée sur TCP échoue après un certain nombre de tentatives, astraceroute reviendra automatiquement à des sondes basées sur ICMP pour passer les pare-feu et les routeurs utilisés dans l'équilibrage de charge par exemple.

Pour recueillir plus d'informations sur les numéros d'AS affichés par astraceroute, voir par ex. : http://bgp.he.net/AS<number>.

BOGUES

Les emplacements géographiques sont estimés à l'aide de la base de données GeoIP de Maxmind et peuvent différer de la localisation physique réelle. Pour diminuer les erreurs possibles, mettez régulièrement à jour la base de données en utilisant l'option --update d'astraceroute.

À un moment donné, nous avons besoin d'une approche similaire pour recueillir des informations de chemin plus fiables, comme dans l'outil paris-traceroute.

En raison de la nature générique d'astraceroute, il dispose actuellement d'un mécanisme intégré pour arrêter le traçage après un nombre fixe de sauts, puisque les drapeaux TCP configurables peuvent inclure n'importe quoi. Il est possible de diminuer ce nombre, bien sûr. À l'avenir, si une sonde SYN est envoyée, il devrait y avoir un écouteur afin que nous puissions arrêter le traçage si nous détectons une négociation en cours.
