Activer et personnaliser le préprocesseur

De nombreux compilateurs Fortran, y compris GNU Fortran, permettent de passer le code source par un préprocesseur C (CPP ; parfois aussi appelé préprocesseur Fortran, FPP) pour permettre la compilation conditionnelle. Dans le cas de GNU Fortran, il s'agit du préprocesseur GNU C en mode traditionnel. Sur les systèmes dont les noms de fichiers sont sensibles à la casse, le préprocesseur est automatiquement appelé si l'extension du nom de fichier est .F, .FOR, .FTN, .fpp, .FPP, .F90, .F95, .F03 ou .F08. Pour appeler manuellement le préprocesseur sur n'importe quel fichier, utilisez -cpp, pour désactiver le prétraitement sur les fichiers où le préprocesseur est appelé automatiquement, utilisez -nocpp.

Si un fichier prétraité inclut un autre fichier avec l'instruction Fortran "INCLUDE", le fichier inclus n'est pas prétraité. Pour prétraiter les fichiers inclus, utilisez l'instruction de préprocesseur équivalente "#include".

Si GNU Fortran appelle le préprocesseur, "__GFORTRAN__" est défini. Les macros "__GNUC__", "__GNUC_MINOR__" et "__GNUC_PATCHLEVEL__" peuvent être utilisées pour déterminer la version du compilateur. Voir Top,,Overview,cpp,The C Preprocessor pour plus de détails.

GNU Fortran prend en charge un certain nombre de types de "INTEGER" et "REAL" en plus des types de genre requis par la norme Fortran. La disponibilité de tout type de genre donné dépend de l'architecture. Les macros prédéfinies suivantes du préprocesseur peuvent être utilisées pour inclure conditionnellement du code pour ces types de genre supplémentaires : "__GFC_INT_1__", "__GFC_INT_2__", "__GFC_INT_8__", "__GFC_INT_16__", "__GFC_REAL_10__" et "__GFC_REAL_16__".

Alors que CPP est la norme de facto pour le prétraitement du code Fortran, la partie 3 de la norme Fortran 95 (ISO/IEC 1539-3:1998) définit

Compilation conditionnelle, qui n'est pas largement utilisée et n'est pas directement prise en charge par le compilateur GNU

Fortran.

-falign-comm

Par défaut, gfortran applique un alignement correct à toutes les variables d'un bloc "COMMON" en les complétant par des octets de remplissage si nécessaire. Sur certaines plateformes, cela est obligatoire, sur d'autres, cela augmente les performances. Si un bloc "COMMON" n'est pas déclaré avec des types de données cohérents partout, ce remplissage peut causer des problèmes, et -fno-align-commons peut être utilisé pour désactiver l'alignement automatique. La même forme de cette option doit être utilisée pour tous les fichiers qui partagent un bloc "COMMON". Pour éviter des problèmes d'alignement potentiels dans les blocs "COMMON", il est recommandé d'ordonner les objets du plus grand au plus
petit.
