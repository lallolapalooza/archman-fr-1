Ne recherchez pas les fichiers d'en-tête dans les répertoires standard spécifiques à C++, mais recherchez toujours les autres répertoires standard. (Cette option est utilisée lors de la compilation de la bibliothèque C++.)

-Wtrigraphs
Avertissez si des trigraphes sont rencontrés qui pourraient changer la signification du programme. Les trigraphes dans les commentaires ne sont pas signalés, sauf ceux qui formeraient des nouvelles lignes échappées.

Cette option est implicite par -Wall. Si -Wall n'est pas donné, cette option est toujours activée à moins que les trigraphes ne soient activés. Pour obtenir la conversion des trigraphes sans avertissements, mais obtenir les autres avertissements de -Wall, utilisez -trigraphs -Wall -Wno-trigraphs.

-Wundef
Avertissez si un identifiant indéfini est évalué dans une directive "#if". Ces identifiants sont remplacés par zéro.
-Wexpansion-to-defined
Avertissez chaque fois que defined est rencontré dans l'expansion d'une macro (y compris le cas où la macro est étendue par une directive #if). Une telle utilisation n'est pas portable. Cet avertissement est également activé par -Wpedantic et -Wextra.
-Wunused-macros
Avertissez sur les macros définies dans le fichier principal qui ne sont pas utilisées. Une macro est utilisée si elle est développée ou testée pour son existence au moins une fois. Le préprocesseur avertit également si la macro n'a pas été utilisée au moment où elle est redéfinie ou annulée.

Les macros intégrées, les macros définies en ligne de commande, et les macros définies dans les fichiers d'inclusion ne font pas l'objet d'un avertissement.

Note : Si une macro est effectivement utilisée, mais seulement utilisée dans des blocs conditionnels ignorés, alors le préprocesseur la signale comme non utilisée. Pour éviter l'avertissement dans un tel cas, vous pourriez améliorer la portée de la définition de la macro en, par exemple, la déplacer dans le premier bloc ignoré. #if defined la_macro_qui_provoque_l_avertissement
#endif

ENVIRONNEMENT

Cette section décrit les variables d'environnement qui affectent le fonctionnement de CPP. Vous pouvez les utiliser pour spécifier des répertoires ou des préfixes à utiliser lors de la recherche de fichiers d'inclusion, ou pour contrôler la sortie des dépendances.

Notez que vous pouvez également spécifier des emplacements à rechercher à l'aide d'options telles que -I, et contrôler la sortie des dépendances avec des options telles que -M. Celles-ci ont la priorité sur les variables d'environnement, qui à leur tour ont la priorité sur la configuration de GCC.

CPATH
C_INCLUDE_PATH
CPLUS_INCLUDE_PATH
OBJC_INCLUDE_PATH
La valeur de chaque variable est une liste de répertoires séparés par un caractère spécial, similaire à PATH, dans lesquels rechercher les fichiers d'en-tête. Le caractère spécial, "PATH_SEPARATOR", dépend de la cible et est déterminé au moment de la compilation de GCC. Pour les cibles basées sur Microsoft Windows, c'est un point-virgule, et pour presque toutes les autres cibles, c'est un deux-points.

CPATH spécifie une liste de répertoires à rechercher comme s'ils étaient spécifiés avec -I, mais après les chemins donnés avec les options -I sur la ligne de commande. Cette variable d'environnement est utilisée quelle que soit la langue en cours de pré-traitement.

Les autres variables d'environnement s'appliquent uniquement lors du pré-traitement de la langue particulière indiquée. Chacune spécifie une liste de répertoires à rechercher comme s'ils étaient spécifiés avec -isystem, mais après les chemins donnés avec les options -isystem sur la ligne de commande.

Dans toutes ces variables, un élément vide demande au compilateur de rechercher dans son répertoire de travail courant. Les éléments vides peuvent apparaître au début ou à la fin d'un chemin. Par exemple, si la valeur de CPATH est ":/special/include", cela a le même effet que -I. -I/special/include.

DEPENDENCIES_OUTPUT
Si cette variable est définie, sa valeur spécifie comment générer les dépendances pour Make basées sur les fichiers d'en-tête non système traités par le compilateur. Les fichiers d'en-tête système sont ignorés dans la sortie des dépendances.

La valeur de DEPENDENCIES_OUTPUT peut être simplement un nom de fichier, auquel cas les règles Make sont écrites dans ce fichier, en devinant le nom de cible à partir du nom du fichier source. Ou bien, la valeur peut avoir la forme fichier cible, auquel cas les règles sont écrites dans le fichier fichier en utilisant cible comme nom de cible.

Autrement dit, cette variable d'environnement équivaut à combiner les options -MM et -MF, avec un commutateur -MT optionnel.

SUNPRO_DEPENDENCIES
Cette variable est identique à DEPENDENCIES_OUTPUT (voir ci-dessus), à l'exception que les fichiers d'en-tête système ne sont pas ignorés, donc elle implique -M plutôt que -MM. Cependant, la dépendance sur le fichier d'entrée principal est omise.
SOURCE_DATE_EPOCH
Si cette variable est définie, sa valeur spécifie un horodatage UNIX à utiliser en remplacement de la date et de l'heure actuelles dans les macros "__DATE__" et "__TIME__", de sorte que les horodatages intégrés deviennent reproductibles.

La valeur de SOURCE_DATE_EPOCH doit être un horodatage UNIX, défini comme le nombre de secondes (hors secondes bissextiles) depuis le 01 jan 1970 00:00:00 représenté en ASCII ; identique à la sortie de "date +%s" sur GNU/Linux et d'autres systèmes qui supportent l'extension %s dans la commande "date".

La valeur doit être un horodatage connu tel que l'heure de dernière modification de la source ou du paquet et elle devrait être définie par le processus de construction.
