AA_GETCON(2) AppArmor AA_GETCON(2)

NOM

aa_getprocattr_raw, aa_getprocattr - lire et analyser les données procattr

aa_getcon, aa_gettaskcon - obtenir des informations de confinement de tâche

aa_getpeercon - obtenir le confinement de l'autre extrémité d'une socket (pair)

SYNTAXE

#include <sys/apparmor.h>

int aa_getprocattr_raw(pid_t tid, const char *attr, char *buf, int len, char **mode);

int aa_getprocattr(pid_t tid, const char *attr, char **label, char **mode);

int aa_gettaskcon(pid_t target, char **label, char **mode);

int aa_getcon(char **label, char **mode);

int aa_getpeercon_raw(int fd, char *buf, int *len, char **mode);

int aa_getpeercon(int fd, char **label, char **mode);

Lier avec -lapparmor lors de la compilation.

DESCRIPTION

La fonction aa_getcon récupère le contexte de confinement AppArmor actuel pour la tâche en cours. Le contexte de confinement se compose d'une étiquette et d'un mode. L'étiquette est généralement juste le nom du profil AppArmor qui restrint la tâche, mais elle peut inclure l'espace de noms du profil ou dans certains cas un ensemble de noms de profils (connu sous le nom de pile de profils). Le mode est une chaîne qui décrit comment le noyau applique la politique définie dans le profil. Les profils chargés en mode "enforce" appliqueront la politique définie dans le profil ainsi que le signalement des tentatives de violation de politique. Les profils en mode "complain" n'appliqueront pas la politique mais signaleront les tentatives de violation de politique.

Quelques exemples de chaînes d' *étiquette* possibles retournées sont "unconfined", "/sbin/dhclient" et "Firefox". La chaîne peut contenir n'importe quels caractères non NUL mais elle sera terminée par NUL. La chaîne d' *étiquette* doit être libérée à l'aide de free().

Les chaînes de *mode* possibles sont "enforce" et "complain". De plus, *mode peut être NULL lorsque *label est "unconfined". La chaîne *mode ne doit pas être libérée. Les chaînes *label et *mode proviennent d'une seule allocation de tampon et sont séparées par un caractère NUL.

La fonction aa_gettaskcon est similaire à la fonction aa_getcon, sauf qu'elle fonctionne pour n'importe quelle tâche arbitraire du système.

La fonction aa_getpeercon est similaire à aa_gettaskcon, sauf qu'elle renvoie les informations de confinement pour la tâche à l'autre bout d'une connexion socket.

La fonction aa_getpeercon_raw est le backend de la fonction aa_getpeercon et ne gère pas l'allocation de mémoire tampon.

La fonction aa_getprocattr est le backend des fonctions aa_getcon et aa_gettaskcon et gère la lecture et l'analyse des données de confinement à partir de différents fichiers attr arbitraires et renvoie les résultats traités dans un tampon alloué.

La fonction aa_getprocattr_raw() est le backend de la fonction aa_getprocattr et ne gère pas l'allocation de mémoire tampon.

VALEUR DE RETOUR

En cas de succès, la taille des données placées dans le tampon est renvoyée, y compris le mode le cas échéant et tous les caractères de terminaison. En cas d'erreur, -1 est renvoyé et errno(3) est défini de manière appropriée.

ERREURS

EINVAL
Le module noyau apparmor n'est pas chargé ou la communication via /proc/*/attr/file n'a pas respecté le protocole.
ENOMEM
Mémoire insuffisante côté noyau disponible.
EACCES
L'accès au fichier/tâche spécifié a été refusé.
ENOENT
Le fichier/tâche spécifié n'existe pas ou n'est pas visible.
ERANGE
Les données de confinement sont trop volumineuses pour tenir dans le tampon fourni.
ENOPROTOOPT
Le noyau ne prend pas en charge l'option SO_PEERLABEL pour les sockets. Cela se produit principalement lorsque le noyau ne dispose pas du support de "médiation Unix fine". Cela peut également se produire sur les noyaux à empilement LSM où un autre LSM a revendiqué cette interface et décide de renvoyer cette erreur, bien que ce soit un cas d'angle.

NOTES

Si aa_getpeercon_raw renvoie -1 et que errno est ERANGE, la valeur de *len peut être utilisée pour réallouer buf afin qu'il soit suffisamment grand pour stocker les données de confinement.
