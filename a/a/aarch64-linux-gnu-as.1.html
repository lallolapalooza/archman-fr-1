DESCRIPTIONGNUas est en réalité une famille d'assembleurs. Si vous utilisez (ou avez utilisé) l'assembleur GNU sur une architecture, vous devriez trouver un environnement assez similaire lorsque vous l'utilisez sur une autre architecture. Chaque version a beaucoup en commun avec les autres, y compris les

formats de fichiers objet, la plupart des
directives d'assemblage (souvent appelées

pseudo-opérations) et la syntaxe

d'assemblage.

as est principalement destiné à assembler la sortie du compilateur C GNU "gcc" pour utilisation par l'éditeur de liens "ld". Néanmoins, nous avons essayé de faire en sorte

que

as assemble correctement tout ce que d'autres assembleurs pour la même machine assembleraient. Toutes les exceptions sont explicitement documentées. Cela ne signifie pas que as utilise toujours la même syntaxe qu'un autre assembleur pour la même architecture ; par exemple, nous connaissons plusieurs versions incompatibles de la syntaxe du langage d'assemblage 680x0. Chaque fois que vous exécutez as, il assemble exactement un programme source. Le programme source est constitué d'un ou plusieurs fichiers. (L'entrée standard est aussi un fichier.) Vous donnez

à

as une ligne de commande contenant zéro ou plusieurs noms de fichiers d'entrée. Les fichiers d'entrée sont lus (du nom de fichier de gauche à celui de droite). Un argument de ligne de commande (à n'importe quelle position) qui n'a pas de signification particulière est considéré comme un nom de fichier d'entrée. Si vous ne donnez pas de noms de fichier

à

as, il essaie de lire un fichier d'entrée depuis l' entrée standard

de

as, qui est normalement votre terminal. Vous devrez peut-être taper ctl-D pour indiquer à as qu'il n'y a plus de programme à assembler. Utilisez -- si vous devez nommer explicitement le fichier d'entrée standard dans votre ligne de

commande.

Si la source est vide, as produit un petit fichier objet

vide.

as peut écrire des avertissements et des messages d'erreur dans le fichier d'erreur standard (généralement votre terminal). Cela ne devrait pas se produire lorsque le compilateur exécute as automatiquement. Les avertissements signalent une hypothèse faite pour

que

as puisse continuer à assembler un programme imparfait ; les erreurs signalent un problème grave qui arrête l'assemblage. Si vous invoquez as via le compilateur C GNU, vous pouvez utiliser

l'option

-Wa pour transmettre des arguments à l'assembleur. Les arguments de l'assembleur doivent être séparés les uns des autres (et de -Wa) par des virgules. Par exemple : gcc -c -g -O -Wa,-alh,-L fichier.c Cela transmet deux options à l'assembleur

: 
-alh (émettre une liste vers la sortie standard avec le code source de haut niveau et le code d'assemblage)
et

-L (conserver les symboles locaux dans la table des symboles). Habituellement, vous n'avez pas besoin d'utiliser ce mécanisme -Wa, car de nombreuses options de ligne de commande du compilateur sont automatiquement transmises à l'assembleur par le compilateur. (Vous pouvez appeler le pilote du compilateur GNU avec

l'option

-v pour voir précisément quelles options il transmet à chaque passe de compilation, y compris l'assembleur.) OPTI

--alternate
Commence en mode macro alternatif.
--compress-debug-sections
Compresse les sections de débogage DWARF en utilisant zlib avec SHF_COMPRESSED de l'ABI ELF. Le fichier objet résultant peut ne pas être compatible avec les anciens linkers et utilitaires de fichiers objets. Notez que si la compression rend une section donnée plus grande, alors elle n'est pas compressée.
--compress-debug-sections=none
--compress-debug-sections=zlib
--compress-debug-sections=zlib-gnu
--compress-debug-sections=zlib-gabi
--compress-debug-sections=zstd
Ces options contrôlent la compression des sections de débogage DWARF. --compress-debug-sections=none est équivalent à --nocompress-debug-sections. --compress-debug-sections=zlib et --compress-debug-sections=zlib-gabi sont équivalents à --compress-debug-sections. --compress-debug-sections=zlib-gnu compresse les sections de débogage DWARF en utilisant le format zlib-gnu obsolète. Les sections de débogage sont renommées pour commencer par .zdebug. --compress-debug-sections=zstd compresse les sections de débogage DWARF en utilisant zstd. Notez que si la compression rendait une section plus grande, elle ne serait ni compressée ni renommée.
--nocompress-debug-sections
Ne pas compresser les sections de débogage DWARF. C'est généralement la valeur par défaut pour toutes les cibles sauf x86/x86_64, mais une option de configuration peut être utilisée pour remplacer cela.
-D
Active le débogage dans les backends spécifiques à la cible, si supporté. Sinon, ignoré. Même si ignoré, cette option est acceptée pour la compatibilité des scripts avec les appels à d'autres assembleurs.
--debug-prefix-map ancien=nouveau
Lors de l'assemblage de fichiers dans le répertoire ancien, enregistrer les informations de débogage les décrivant comme dans nouveau à la place.
--defsym sym=valeur
Définit le symbole sym à la valeur valeur avant d'assembler le fichier d'entrée. valeur doit être une constante entière. Comme en C, un préfixe 0x indique une valeur hexadécimale, et un préfixe 0 indique une valeur octale. La valeur du symbole peut être remplacée à l'intérieur d'un fichier source via l'utilisation d'une pseudo-instruction ".set".
--dump-config
Affiche comment l'assembleur est configuré, puis quitte.
--elf-stt-common=no
--elf-stt-common=yes
Ces options contrôlent si l'assembleur ELF doit générer des symboles communs avec le type "STT_COMMON". La valeur par défaut peut être contrôlée par une option de configuration --enable-elf-stt-common.
--emulation=nom
Si l'assembleur est configuré pour supporter plusieurs configurations cibles différentes, alors cette option peut être utilisée pour sélectionner la forme désirée.
-f
"rapide"---saute le pré-traitement des espaces blancs et des commentaires (suppose que la source est le résultat du compilateur).
-g
--gen-debug
Génère des informations de débogage pour chaque ligne source de l'assembleur en utilisant le format de débogage préféré par la cible. Cela signifie actuellement soit STABS, ECOFF ou DWARF2. Lorsque le format de débogage est DWARF, une section ".debug_info" et ".debug_line" n'est émise que lorsque le fichier assembleur n'en génère pas lui-même.
--gstabs
Génère des informations de débogage stabs pour chaque ligne de l'assembleur. Cela peut aider au débogage du code assembleur, si le débogueur peut le gérer.
--gstabs+
Génère des informations de débogage stabs pour chaque ligne de l'assembleur, avec des extensions GNU que probablement seul gdb peut gérer, et qui pourraient faire planter ou refuser de lire votre programme par d'autres débogueurs. Cela peut aider au débogage du code assembleur. Actuellement, la seule extension GNU est l'emplacement du répertoire de travail courant au moment de l'assemblage.
--gdwarf-2
Génère des informations de débogage DWARF2 pour chaque ligne de l'assembleur. Cela peut aider au débogage du code assembleur, si le débogueur peut le gérer. Notez que cette option n'est supportée que par certaines cibles, pas toutes.
--gdwarf-3
Cette option est identique à l'option --gdwarf-2, sauf qu'elle permet la possibilité de générer des informations de débogage supplémentaires selon la version 3 de la spécification DWARF. Notez que l'activation de cette option ne garantit pas la génération d'informations supplémentaires, le choix de le faire est fait par cible.
--gdwarf-4
Cette option est identique à l'option --gdwarf-2, sauf qu'elle permet la possibilité de générer des informations de débogage supplémentaires selon la version 4 de la spécification DWARF. Notez que l'activation de cette option ne garantit pas la génération d'informations supplémentaires, le choix de le faire est fait par cible.
--gdwarf-5
Cette option est identique à l'option --gdwarf-2, sauf qu'elle permet la possibilité de générer des informations de débogage supplémentaires selon la version 5 de la spécification DWARF. Notez que l'activation de cette option ne garantit pas la génération d'informations supplémentaires, le choix de le faire est fait par cible.
--gdwarf-sections
Au lieu de créer une section .debug_line, crée une série de sections .debug_line.foo où foo est le nom de la section de code correspondante. Par exemple, une section de code nommée .text.func aura ses informations de ligne de débogage placées dans une section nommée .debug_line.text.func. Si la section de code est simplement nommée .text, alors la section de ligne de débogage sera toujours nommée .debug_line sans suffixe.
--gdwarf-cie-version=version
Contrôle quelle version des entrées d'information communes DWARF (CIE) est produite. Lorsque ce drapeau n'est pas spécifié, la valeur par défaut est la version 1, bien que certaines cibles puissent modifier cette valeur par défaut. D'autres valeurs possibles pour version sont 3 ou 4.
--generate-missing-build-notes=yes
--generate-missing-build-notes=no
Ces options contrôlent si l'assembleur ELF doit générer des notes d'attributs GNU Build si aucune n'est présente dans les sources d'entrée. La valeur par défaut peut être contrôlée par l'option de configuration --enable-generate-build-notes.
--gsframe
--gsframe
Crée une section .sframe à partir des directives CFI.
--hash-size N
Ignoré. Supporté pour la compatibilité de la ligne de commande avec d'autres assembleurs.
--help

--target-help

--info
Ne pas supprimer les messages d'information.
--no-info
Supprimer les messages d'information.

-J

-K
Émettre des avertissements lorsque les tables de différence sont modifiées pour des déplacements longs.
