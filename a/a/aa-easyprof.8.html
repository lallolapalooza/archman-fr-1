DESCRIPTIO

N

aa-easyprof fournit une interface facile à utiliser pour la génération de politiques AppArmor. aa-easyprof prend en charge l'utilisation de modèles et de groupes de politiques pour profiler rapidement une application. Veuillez noter que bien que cet outil puisse aider à la génération de politiques, son utilité dépend de la qualité des modèles, des groupes de politiques et des abstractions utilisés. De plus, cet outil peut créer une politique moins restrictive que si elle était créée à la main ou avec aa-genprof et aa-logpro

f
.

OPTION

S

aa-easyprof accepte les arguments suivants

:
-t TEMPLATE, --template=TEMPL
ATE
Spécifie le modèle à utiliser. Peut spécifier soit un modèle système depuis /usr/share/apparmor/easyprof/templates, soit un nom de fichier pour le modèle à utiliser. Si non spécifié, utilise /usr/share/apparmor/easyprof/templates/defau
lt.
-p POLICYGROUPS, --policy-groups=POLICYGRO
UPS
Spécifie POLICY sous forme de liste de groupes de politiques séparés par des virgules. Voir --list-templates pour les groupes de politiques pris en charge. Les groupes de politiques disponibles se trouvent dans /usr/share/apparmor/easyprof/policy. Les groupes de politiques sont simplement des regroupements de règles ou de politiques AppArmor. Ils sont similaires aux abstractions AppArmor, mais couvrent généralement plus de règles de
politique.
--parser
PATH
Spécifie le chemin (PATH) du binaire apparmor_parser à utiliser lors de la vérification de la politique. Si cette option n'est pas spécifiée, aa-easyprof essaiera de localiser le chemin en commençant par /sbin/apparmor_pars
er.
-a ABSTRACTIONS, --abstractions=ABSTRACTI
ONS
Spécifie ABSTRACTIONS sous forme de liste d'abstractions AppArmor séparées par des virgules. Il est généralement recommandé d'utiliser les groupes de politiques à la place, mais cette option est fournie par commodité. Les abstractions AppArmor se trouvent dans /etc/apparmor.d/abstractions. Voir apparmor.d(5) pour plus de
détails.
-b PATH,
--base=PATH
Définit le chemin de base (PATH) pour résoudre les abstractions spécifiées par --abstractions. Voir la même option dans apparmor_parser(8) pour plus de
détails.
-I PATH,
--Include=PATH
Ajoute PATH aux chemins de recherche utilisés pour résoudre les abstractions spécifiées par --abstractions. Voir la même option dans apparmor_parser(8) pour plus de
détails.
-r PATH,
--read-path=PATH
Spécifie un chemin (PATH) pour autoriser les lectures par le propriétaire. Peut être spécifié plusieurs fois. Si le chemin se termine par un '/', alors le chemin est traité comme un répertoire et les lectures sont autorisées pour tous les fichiers sous ce répertoire. Peut utiliser facultativement '/*' à la fin du chemin pour n'autoriser les lectures que des fichiers directement dans le
chemin.
-w PATH,
--write-dir=PATH
Comme --read-path mais autorise aussi les écritures par le propriétaire en plus des
lectures.
-n NAME,
--name=NAME
Spécifie le nom (NAME) de la politique. Si non spécifié, le nom est défini sur le nom du binaire. Le nom de la politique n'est généralement utilisé que pour les métadonnées du profil et ne spécifie pas le nom du profil
AppArmor.
--profile-name=PROFILEN
AME
Spécifie le nom du profil AppArmor. Lorsqu'il est défini, utilise 'profile PROFILENAME' dans le profil. Lorsqu'il est défini et qu'un binaire est spécifié, utilise 'profile PROFILENAME BINARY' dans le profil. S'il n'est pas défini, le binaire sera utilisé comme nom de profil et comme point d'attachement du
profil.
--template-var="@{VAR}
=VALUE"
Définit VAR sur VALUE dans la politique résultante. Cela n'a généralement de sens que si le modèle spécifié utilise cette valeur. Peut être spécifié plusieurs
fois.

--policy-version=VERS

Doit être utilisé avec --policy-vendor et sert à spécifier la version des groupes de politiques et des modèles. Lorsqu'elle est spécifiée, aa-easyprof recherche le sous-répertoire VENDOR/VERSION dans les répertoires des groupes de politiques et des modèles. La version spécifiée doit être un nombre décimal positif compatible avec le type JSON Number. Par exemple, lors de l'utilisation de :

              --policy-vendor="foo" \
              --policy-version=1.
0

Alors /usr/share/apparmor/easyprof/templates/foo/1.0 sera

recherché pour les modèles et /usr/share/apparmor
/easyprof/policygroups/foo/1.0 pour les groupes de politiques.

-m MANIFEST, --manifest=MANIF
EST
aa-easyprof prend également en charge l'utilisation d'un fichier manifeste JSON pour spécifier des options liées à la politique. Contrairement aux arguments de la ligne de commande, le fichier JSON peut spécifier plusieurs profils. La structure du JSON est : 
{
  "security": {
    "profiles": {
      "<profile name 1>": {
        ... attributes specific to this profile ...
      },
      "<profile name 2>": {
        ...
      }
    }
} }

Chaque objet JSON de profil (c'est-à-dire tout ce qui se trouve sous un nom de profil) peut spécifier tous les champs liés à la politique. L'objet conteneur JSON "security" est facultatif et peut être omis. Un exemple de fichier manifeste démontrant tous les

champs est : 
{
  "security": {
    "profiles": {
      "com.example.foo": {
        "abstractions": [
          "audio",
          "gnome"
        ],
        "author": "Your Name",
        "binary": "/opt/foo/**",
        "comment": "Unstructured single-line comment",
        "copyright": "Unstructured single-line copyright statement",
        "name": "My Foo App",
        "policy_groups": [
          "networking",
          "user-application"
        ],
        "policy_vendor": "somevendor",
        "policy_version": 1.0,
        "read_path": [
          "/tmp/foo_r",
          "/tmp/bar_r/"
        ],
        "template": "user-application",
        "template_variables": {
          "APPNAME": "foo",
          "VAR1": "bar",
          "VAR2": "baz"
        },
        "write_path": [
          "/tmp/foo_w",
          "/tmp/bar_w/"
        ]
      }
    }
} }

Un fichier manifeste ne doit pas nécessairement inclure tous les champs. Par exemple, un fichier manifeste pour une application Ubuntu SDK pourrait être :

{
  "security": {
    "profiles": {
      "com.ubuntu.developer.myusername.MyCoolApp": {
        "policy_groups": [
          "networking",
          "online-accounts"
        ],
        "policy_vendor": "ubuntu",
        "policy_version": 1.0,
        "template": "ubuntu-sdk",
        "template_variables": {
          "APPNAME": "MyCoolApp",
          "APPVERSION": "0.1.2"
        }
      }
    }
  }
}
--verify-manifest
Lorsqu'il est utilisé avec --manifest, avertit des définitions potentiellement dangereuses dans le fichier manifeste.
--output-format=FORMAT
Spécifie text (par défaut si non spécifié) pour la sortie de la politique AppArmor ou json pour le format du manifeste JSON.
--output-directory=DIR
Spécifie le répertoire de sortie pour le profil. Si non spécifié, la politique est envoyée à la sortie standard.

EXEMPLES

Exemple d'utilisation pour un programme nommé 'foo' installé dans /opt/foo :

$ aa-easyprof --template=user-application --template-var="@{APPNAME}=foo" \
              --policy-groups=opt-application,user-application \
              /opt/foo/bin/FooApp

Lors de l'utilisation d'un fichier manifeste :

$ aa-easyprof --manifest=manifest.json

Pour générer un fichier manifeste basé sur les arguments de aa-easyprof :

$ aa-easyprof --output-format=json \
              --author="Votre Nom" \
              --comment="Commentaire non structuré sur une seule ligne" \
              --copyright="Déclaration de copyright non structurée sur une seule ligne" \
              --name="Mon App Foo" \
              --profile-name="com.example.foo" \
              --template="user-application" \
              --policy-groups="user-application,networking" \
              --abstractions="audio,gnome" \
              --read-path="/tmp/foo_r" \
              --read-path="/tmp/bar_r/" \
              --write-path="/tmp/foo_w" \
              --write-path=/tmp/bar_w/ \
              --template-var="@{APPNAME}=foo" \
              --template-var="@{VAR1}=bar" \
              --template-var="@{VAR2}=baz" \
              "/opt/foo/**"
