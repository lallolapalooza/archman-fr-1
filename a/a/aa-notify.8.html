NOM

aa-notify - afficher des informations sur les messages AppArmor journalisés.

SYNOPSIS

aa-notify [option]

DESCRIPTION

aa-notify affichera un résumé ou fournira des notifications de bureau pour les messages AppArmor DENIED.

OPTIONS

aa-notify accepte les arguments suivants :

-p, --poll
interroge les journaux AppArmor et affiche des notifications de bureau. Peut être utilisé avec l'option '-s' pour afficher un résumé au démarrage.
--display $DISPLAY
définit la variable d'environnement DISPLAY à $DISPLAY (peut être nécessaire si sudo réinitialise $DISPLAY)
-f FICHIER, --file=FICHIER
recherche dans FICHIER les messages AppArmor.
-l, --since-last
affiche le résumé depuis la dernière connexion.
-s NUM, --since-days=NUM
affiche le résumé pour les NUM derniers jours.
-u UTILISATEUR, --user=UTILISATEUR
utilisateur vers lequel rétrograder les privilèges lors de l'exécution privilégiée. Utilisé avec l'option -p, il doit être défini sur l'utilisateur qui recevra les notifications de bureau. Cela n'a aucun effet lors de l'exécution sous sudo.
-w NUM, --wait=NUM
attend NUM secondes avant d'afficher les notifications (pour utilisation avec -p).
-v, --verbose
affiche les messages avec des résumés.
-h, --help
affiche un bref énoncé d'utilisation.

CONFIGURATION

La configuration à l'échelle du système pour aa-notify se fait via /etc/apparmor/notify.conf :

# Mettre à 'no' pour désactiver globalement les notifications AppArmor
show_notifications="yes"
# Profils spéciaux utilisés pour supprimer les privilèges des binaires non confinés utilisant les espaces de noms utilisateur. En cas de doute, laisser tel quel.
userns_special_profiles="unconfined,unprivileged_userns"
# Thème pour l'interface graphique de aa-notify. Voir https://ttkthemes.readthedocs.io/en/latest/themes.html pour les thèmes disponibles.
interface_theme="ubuntu"
# Binaires pour lesquels nous ignorons les dénis de capacité liés aux espaces de noms utilisateur
ignore_denied_capability="sudo,su"
# OPTIONNEL - sorte d'opérations qui affichent une invite popup.
prompt_filter="userns"
# OPTIONNEL - restreindre l'utilisation de aa-notify aux utilisateurs du groupe donné
# (si non défini, tout le monde qui a les permissions de lire le fichier log peut l'utiliser)
# use_group="admin"
# OPTIONNEL - corps du message de notification personnalisé
message_body="Ceci est un message de notification personnalisé."
# OPTIONNEL - pied de page du message de notification personnalisé
message_footer="Pour plus d'informations, visitez https://foo.com"
# OPTIONNEL - filtrage personnalisé des notifications
# Les filtres sont utilisés pour réduire la sortie d'informations aux seules entrées qui correspondent au filtre. Les filtres utilisent la syntaxe d'expression régulière de Python.
filter.profile="^(foo|bar)$"  # Correspond au profil :            Affiche uniquement les notifications pour les profils "foo" ou "bar"
filter.operation="^open$"     # Correspond à l'opération :          Affiche uniquement les notifications pour l'opération "open"
filter.name="^(?!/usr/lib/)"  # Correspond au nom :               Exclut les notifications pour les noms commençant par "/usr/lib/"
filter.denied="^r$"           # Correspond au masque denied_mask : Affiche uniquement les notifications où "r", et seulement "r", a été refusé
filter.family="^inet$"        # Correspond à la famille réseau :    Affiche uniquement les notifications pour la famille "inet"
filter.socket="stream"        # Correspond au type de socket réseau : Affiche uniquement les notifications pour les sockets "stream"

La configuration par utilisateur se fait via $XDG_CONFIG_HOME/apparmor/notify.conf (ou le déprécié ~/.apparmor/notify.conf s'il existe) :

# définir à 'yes' pour activer les notifications AppArmor DENIED
show_notifications="yes"

BOGUES

aa-notify doit pouvoir lire les fichiers journaux contenant les messages AppArmor DENIED.

Si vous trouvez des bogues supplémentaires, veuillez les signaler sur Gitlab à l'adresse https://gitlab.com/apparmor/apparmor/-/issues.
