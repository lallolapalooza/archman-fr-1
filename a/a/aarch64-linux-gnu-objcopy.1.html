DESCRIPTIO

N

L'utilitaire GNU objcopy copie le contenu d'un fichier objet vers un autre. objcopy utilise la bibliothèque GNU BFD pour lire et écrire les fichiers objets. Il peut écrire le fichier objet de destination dans un format différent de celui du fichier objet source. Le comportement exact de objcopy est contrôlé par les options de la ligne de commande. Notez que objcopy devrait être capable de copier un fichier entièrement lié entre n'importe quels deux formats. Cependant, la copie d'un fichier objet relocalisable entre n'importe quels deux formats peut ne pas fonctionner comme

prévu.

objcopy crée des fichiers temporaires pour effectuer ses conversions et les supprime par la suite. objcopy utilise BFD pour effectuer tout son travail de conversion ; il a accès à tous les formats décrits dans BFD et est donc capable de reconnaître la plupart des formats sans qu'on le lui indique

explicitement.

objcopy peut être utilisé pour générer des enregistrements S en utilisant une cible de sortie srec (par exemple, utilisez -O sre

c).

objcopy peut être utilisé pour générer un fichier binaire brut en utilisant une cible de sortie binary (par exemple, utilisez -O binary). Lorsque objcopy génère un fichier binaire brut, il produit essentiellement un vidage mémoire du contenu du fichier objet d'entrée. Tous les symboles et informations de relocalisation seront supprimés. Le vidage mémoire commencera à l'adresse de chargement de la section la plus basse copiée dans le fichier de

sortie.

Lors de la génération d'un enregistrement S ou d'un fichier binaire brut, il peut être utile d'utiliser -S pour supprimer les sections contenant des informations de débogage. Dans certains cas, -R sera utile pour supprimer les sections qui contiennent des informations dont le fichier binaire n'a pas

besoin.

Note---objcopy n'est pas capable de changer l'endianness de ses fichiers d'entrée. Si le format d'entrée a une endianness (certains formats n'en ont pas), objcopy ne peut copier les entrées que vers des formats de fichier ayant la même endianness ou n'ayant pas d'endianness (par exemple, srec). (Cependant, voir l'option --re

--keep-section-symbols
Lors du dépouillement d'un fichier, éventuellement avec --strip-debug ou --strip-unneeded, conserver tous les symboles spécifiant les noms de sections, qui seraient autrement dépouillés.
--keep-file-symbols
Lors du dépouillement d'un fichier, éventuellement avec --strip-debug ou --strip-unneeded, conserver tous les symboles spécifiant les noms de fichiers sources, qui seraient autrement dépouillés.
--only-keep-debug
Dépouille un fichier, en supprimant le contenu de toutes les sections qui ne seraient pas dépouillées par --strip-debug et en laissant les sections de débogage intactes. Dans les fichiers ELF, cela préserve toutes les sections de notes dans la sortie.

Note - les en-têtes de section des sections dépouillées sont préservés, y compris leurs tailles, mais le contenu de la section est jeté. Les en-têtes de section sont préservés afin que d'autres outils puissent faire correspondre le fichier d'informations de débogage avec l'exécutable réel, même si cet exécutable a été relocalisé dans un espace d'adressage différent.

L'intention est que cette option soit utilisée conjointement avec --add-gnu-debuglink pour créer un exécutable en deux parties. Une, un binaire dépouillé qui occupera moins d'espace en RAM et dans une distribution, et la seconde, un fichier d'informations de débogage qui n'est nécessaire que si des capacités de débogage sont requises. La procédure suggérée pour créer ces fichiers est la suivante :

1.<Liez l'exécutable normalement. En supposant qu'il s'appelle>
"foo" alors...
1.<Exécutez "objcopy --only-keep-debug foo foo.dbg" pour>
créer un fichier contenant les informations de débogage.
1.<Exécutez "objcopy --strip-debug foo" pour créer un>
exécutable dépouillé.
1.<Exécutez "objcopy --add-gnu-debuglink=foo.dbg foo">
pour ajouter un lien vers les informations de débogage dans l'exécutable dépouillé.

Note - le choix de ".dbg" comme extension pour le fichier d'informations de débogage est arbitraire. De plus, l'étape "--only-keep-debug" est facultative. Vous pourriez plutôt faire ceci :

1.<Liez l'exécutable normalement.>
1.<Copiez "foo" dans "foo.full">
1.<Exécutez "objcopy --strip-debug foo">
1.<Exécutez "objcopy --add-gnu-debuglink=foo.full foo">

c'est-à-dire que le fichier pointé par --add-gnu-debuglink peut être l'exécutable complet. Il n'a pas à être un fichier créé par le commutateur --only-keep-debug.

Note - ce commutateur est uniquement destiné à être utilisé sur des fichiers entièrement liés. Il n'est pas logique de l'utiliser sur des fichiers objets où les informations de débogage peuvent être incomplètes. De plus, la fonctionnalité gnu_debuglink ne prend actuellement en charge que la présence d'un seul nom de fichier contenant des informations de débogage, et non de multiples noms de fichiers sur une base un par fichier objet.
