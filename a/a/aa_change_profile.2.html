aa_change_profile(2)

Paquet: apparmor

Licences: GPL-2.0-only, LGPL-2.0-only, LGPL-2.1-only

AA_CHANGE_PROFILE(2) AppArmor AA_CHANGE_PROFILE(2)

NOM

aa_change_profile, aa_change_onexec - changer le profil d'une tâche

SYNTAXE

#include <sys/apparmor.h>

int aa_change_profile(const char *profile);

int aa_change_onexec(const char *profile);

Liez avec -lapparmor lors de la compilation.

DESCRIPTION

Un profil AppArmor s'applique à un programme exécutable ; si une partie du programme a besoin d'autorisations d'accès différentes des autres parties, le programme peut « changer de profil » pour un profil différent. Pour passer à un nouveau profil, il peut utiliser la fonction aa_change_profile(). Il transmet un pointeur vers le profil vers lequel passer. Les programmes confinés souhaitant utiliser aa_change_profile() doivent avoir des règles autorisant le changement vers le profil nommé. Voir apparmor.d(8) pour les détails.

Si un programme souhaite sortir du profil actuel pour revenir au profil d'origine, il peut utiliser aa_change_hat(2). Sinon, les deux profils doivent avoir des règles autorisant le changement entre les deux profils.

Les descripteurs de fichiers ouverts peuvent ne pas être corrigés après un appel à aa_change_profile(), le programme appelant doit donc close(2) les descripteurs de fichiers ouverts pour s'assurer qu'ils ne sont pas disponibles après l'appel à aa_change_profile(). Comme aa_change_profile() est généralement utilisé juste avant execve(2), vous pourriez vouloir utiliser open(2) ou fcntl(2) avec close-on-exec.

La fonction aa_change_onexec() est similaire à la fonction aa_change_profile(), sauf qu'elle spécifie que la transition de profil doit avoir lieu lors du prochain exec au lieu de le faire immédiatement. Le changement de profil différé prend la priorité sur les règles de transition exec dans le profil de confinement. Différer la frontière du profil présente quelques avantages : elle élimine le besoin de profils de transition fantoches et la frontière exec est une couche de sécurité naturelle où la mémoire potentiellement sensible est désactivée (unmapped).

VALEUR DE RETOUR

En cas de succès, zéro est retourné. En cas d'erreur, -1 est retourné et errno(3) est correctement défini.

ERREURS

EINVAL
Le module noyau apparmor n'est pas chargé, aucun profil ni aucun espace de noms n'a été spécifié, ou la communication via le fichier /proc/*/attr/current n'a pas été conforme au protocole.
ENOMEM
Mémoire noyau insuffisante disponible.
EPERM
L'application appelante est confinée par apparmor et le bit no_new_privs est défini.
EACCES
La tâche n'a pas les permissions suffisantes pour changer son domaine.
ENOENT
Le profil spécifié n'existe pas, ou n'est pas visible depuis l'espace de noms actuel.

EXEMPLE

L'exemple suivant montre une utilisation simple, quoique artificielle, de aa_change_profile() ; une utilisation typique de aa_change_profile() sera juste avant un execve(2) afin que le nouveau processus fils soit confiné de manière permanente.

#include <stdlib.h>
#include <string.h>
#include <sys/apparmor.h>
#include <sys/types.h>
#include <sys/stat.h>
#include <fcntl.h>
#include <stdio.h>
#include <unistd.h>
int main(int argc, char * argv[])
{
        int fd;
        char buf[10];
        char *execve_args[4];
        printf("Avant aa_change_profile():\n");
        if ((fd=open("/etc/passwd", O_RDONLY)) < 0) {
               perror("Échec de l'ouverture de /etc/passwd");
               return 1;
        }
        /* Confirmer nous-mêmes que nous pouvons vraiment lire /etc/passwd */
        memset(&buf, 0, 10);
        if (read(fd, &buf, 10) == -1) {
                perror("Échec de la lecture de /etc/passwd");
                return 1;
        }
        buf[9] = '\0';
        printf("/etc/passwd: %s\n", buf);
        close(fd);
        printf("Après aa_change_profile():\n");
        /* changer le profil vers le profil "i_cant_be_trusted_anymore", qui
         * ne devrait pas avoir accès en lecture à /etc/passwd. */
        if (aa_change_profile("i_cant_be_trusted_anymore") < 0) {
            perror("Échec du changement de profil -- abandon");
            _exit(1);
        }
        /* confirmer que nous ne pouvons pas lire /etc/passwd */
        execve_args[0] = "/usr/bin/head";
        execve_args[1] = "-1";
        execve_args[2] = "/etc/passwd";
        execve_args[3] = NULL;
        execve("/usr/bin/head", execve_args, NULL);
        perror("execve");
        _exit(1);
}

Cet exemple de code nécessite qu'un profil similaire au suivant soit chargé avec apparmor_parser(8) :

profile i_cant_be_trusted_anymore {
    /etc/ld.so.cache      mr,
    /lib/ld-*.so*         mrix,
    /lib/libc*.so*        mr,
    /usr/bin/head ix,
}

La sortie lors de l'exécution :

$ /tmp/change_p
Avant aa_change_profile():
/etc/passwd: root:x:0:
Après aa_change_profile():
/usr/bin/head: impossible d'ouvrir `/etc/passwd' en lecture : Permission refusée
$

Si /tmp/change_p doit également être confiné, alors le profil suivant peut être utilisé (en plus de celui pour 'i_cant_be_trusted_anymore', ci-dessus) :

# Confiner change_p pour pouvoir lire /etc/passwd et utiliser aa_change_profile()
# vers le profil 'i_cant_be_trusted_anymore'.
/tmp/change_p {
    /etc/ld.so.cache          mr,
    /lib/ld-*.so*             mrix,
    /lib/libc*.so*            mr,
    /etc/passwd               r,
    # Nécessaire pour aa_change_profile()
    /usr/lib/libapparmor*.so* mr,
    /proc/[0-9]*/attr/current w,
    change_profile -> i_cant_be_trusted_anymore,
}

BOGUES

Aucun connu. Si vous en trouvez, veuillez les signaler à https://gitlab.com/apparmor/apparmor/-/issues. Notez que l'utilisation de aa_change_profile(2) sans execve(2) ne fournit pas de barrières mémoire entre différentes zones d'un programme ; si une séparation de l'espace d'adressage est nécessaire, alors des processus séparés doivent être utilisés.
