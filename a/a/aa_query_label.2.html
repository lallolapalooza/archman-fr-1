AA_QUERY_LABEL(2) AppArmor AA_QUERY_LABEL(2)

NOM

aa_query_label - interroger la permission d'accès associée à une étiquette

aa_query_file_path, aa_query_file_path_len - interroger les permissions d'accès d'un chemin de fichier

aa_query_link_path, aa_query_link_path_len - interroger les permissions d'accès d'un chemin de lien symbolique

SYNTAXE

#include <sys/apparmor.h>

int aa_query_label(uint32_t mask, char *query, size_t size, int *allowed, int *audited);

int aa_query_file_path(uint32_t mask, const char *label, size_t label_len, const char *path, int *allowed, int *audited);

int aa_query_file_path_len(uint32_t mask, const char *label, size_t label_len, const char *path, size_t path_len, int *allowed, int *audited);

int aa_query_link_path(const char *label, const char *target, const char *link, int *allowed, int *audited);

int aa_query_link_path_len(const char *label, size_t label_len, const char *target, size_t target_len, const char *link, size_t link_len, int *allowed, int *audited);

Lier avec -lapparmor lors de la compilation.

DESCRIPTION

La fonction aa_query_label récupère les permissions courantes accordées par l'étiquette spécifiée label dans la chaîne de requête query.

La requête est une requête brute au format binaire, contenant l'étiquette et la requête de permission à effectuer. Les valeurs retournées allowed et audited sont des valeurs booléennes interprétées, indiquant simplement si la requête est autorisée et si elle est auditée.

Le masque de la chaîne de requête est un masque de bits des permissions à interroger et dépend du type de classe (voir les entrées AA_CLASS_xxx dans sys/apparmor.h).

Le format de la chaîne de requête dépend également de la classe AA_CLASS et, par conséquent, les fonctions d'aide aa_query_xxx devraient généralement être utilisées à la place de l'utilisation directe de aa_query_label. Si l'interface est utilisée directement, la chaîne query doit avoir un en-tête de AA_QUERY_CMD_LABEL_SIZE qui sera utilisé par aa_query_label.

Les fonctions aa_query_file_path et aa_query_file_path_len sont des fonctions d'aide qui assemblent une requête de chemin de fichier correctement formatée pour la fonction aa_query_label. L'étiquette label est une étiquette apparmor valide telle que retournée par aa_splitcon, où label_len est la longueur de l'étiquette label. Le chemin path est tout chemin système de fichiers valide pour lequel interroger les permissions. Pour la variante aa_query_file_path_len, le paramètre path_len spécifie le nombre d'octets dans le chemin path à utiliser dans le cadre de la requête.

Les fonctions aa_query_link_path et aa_query_link_path_len sont des fonctions d'aide qui assemblent une requête de chemin de lien symbolique correctement formatée pour la fonction aa_query_label. Les paramètres link_len et target_len spécifient le nombre d'octets dans le lien link et la cible target à utiliser dans le cadre de la requête.

VALEUR DE RETOUR

En cas de succès, 0 est retourné, et les paramètres allowed et audited contiennent une valeur booléenne de 0 (non autorisé/non audité) ou 1 (autorisé/audité). En cas d'erreur, -1 est retourné et errno(3) est défini en conséquence.

ERREURS

EINVAL
Le mask demandé est vide.

La taille de la requête est inférieure à la taille de requête AA_QUERY_CMD_LABEL_SIZE.

Le module noyau apparmor n'est pas chargé ou l'interface d'accès à l'interface noyau n'est pas disponible.

ENOMEM
La mémoire insuffisante était disponible.
EACCES
L'accès à l'étiquette label spécifiée ou à l'interface de requête a été refusé.
ENOENT
L'étiquette label spécifiée n'existe pas ou n'est pas visible.
ERANGE
Les données de confinement sont trop volumineuses pour tenir dans le tampon fourni.

NOTES

Les permissions d'étiquette retournées ne sont valides que pour le moment de la requête et peuvent changer à tout moment par la suite.
