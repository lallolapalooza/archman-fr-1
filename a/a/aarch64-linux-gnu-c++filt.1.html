Paquet: aarch64-linux-gnu-binutils

C++FILT(1) Outils de développement GNU C++FILT(1)

NOM

c++filt - dé-mangle les symboles C++ et Java

SYNOPSIS

c++filt [-_|--strip-underscore]
[-n|--no-strip-underscore]
[-p|--no-params]
[-t|--types]
[-i|--no-verbose]
[-r|--no-recurse-limit]
[-R|--recurse-limit]
[-s format|--format=format]
[--help] [--version] [symbol...]

DESCRIPTION

Les langages C++ et Java fournissent le surchargement de fonctions, ce qui signifie que vous pouvez écrire plusieurs fonctions portant le même nom, à condition que chaque fonction prenne des paramètres de types différents. Afin de pouvoir distinguer ces fonctions de noms similaires, C++ et Java les encodent dans un nom d'assembleur bas niveau qui identifie de manière unique chaque version différente. Ce processus est connu sous le nom de mangling. Le programme c++filt [1] effectue le mapping inverse : il décode les noms bas niveau (dé-mangle) en noms de haut niveau afin qu'ils puissent être lus.

Chaque mot alphanumérique (composé de lettres, chiffres, underscores, dollars ou points) rencontré dans l'entrée est un nom potentiellement manglé. Si le nom se décode en un nom C++, le nom C++ remplace le nom bas niveau dans la sortie, sinon le mot original est produit. De cette façon, vous pouvez passer un fichier source assembleur entier, contenant des noms mangés, à travers c++filt et voir le même fichier source contenant les noms dé-manglés.

Vous pouvez également utiliser c++filt pour déchiffrer des symboles individuels en les passant sur la ligne de commande :

c++filt <symbol>

Si aucun argument symbol n'est donné, c++filt lit les noms de symboles depuis l'entrée standard à la place. Tous les résultats sont imprimés sur la sortie standard. La différence entre la lecture des noms depuis la ligne de commande et la lecture des noms depuis l'entrée standard est que les arguments de la ligne de commande sont censés être de simples noms mangés et aucune vérification n'est effectuée pour les séparer du texte environnant. Ainsi, par exemple :

c++filt -n _Z1fv

fonctionnera et dé-manglera le nom en "f()" alors que :

c++filt -n _Z1fv,

ne fonctionnera pas. (Notez la virgule supplémentaire à la fin du nom mangé qui le rend invalide). Cette commande fonctionnera cependant :

echo _Z1fv, | c++filt -n

et affichera "f(),", c'est-à-dire le nom dé-manglé suivi d'une virgule finale. Ce comportement est dû au fait que lorsque les noms sont lus depuis l'entrée standard, on s'attend à ce qu'ils puissent faire partie d'un fichier source assembleur où il peut y avoir des caractères supplémentaires, superflus après un nom mangé. Par exemple :

.type   _Z1fv, @function

OPTIONS

-_
--strip-underscore
Sur certains systèmes, à la fois les compilateurs C et C++ placent un underscore devant chaque nom. Par exemple, le nom C "foo" obtient le nom bas niveau "_foo". Cette option supprime l'underscore initial. Que c++filt supprime l'underscore par défaut dépend de la cible.
-n
--no-strip-underscore
Ne pas supprimer l'underscore initial.
-p
--no-params
Lors du dé-mangling du nom d'une fonction, ne pas afficher les types des paramètres de la fonction.
-t
--types
Tenter de dé-mangler les types ainsi que les noms de fonctions. Ceci est désactivé par défaut car les types mangés ne sont normalement utilisés qu'en interne dans le compilateur, et ils peuvent être confondus avec des noms non mangés. Par exemple, une fonction appelée "a" traitée comme un nom de type mangé serait dé-manglée en "signed char".
-i
--no-verbose
Ne pas inclure les détails d'implémentation (s'il y en a) dans la sortie dé-manglée.
-r
-R
--recurse-limit
--no-recurse-limit
--recursion-limit
--no-recursion-limit
Active ou désactive une limite sur la quantité de récursion effectuée lors du dé-mangling des chaînes. Puisque les formats de mangling de noms permettent un niveau de récursion infini, il est possible de créer des chaînes dont le décodage épuisera la quantité d'espace de pile disponible sur la machine hôte, déclenchant une faute mémoire. La limite tente d'empêcher cela en restreignant la récursion à 2048 niveaux d'imbrication.

La valeur par défaut est que cette limite soit activée, mais la désactiver peut être nécessaire afin de dé-mangler des noms véritablement compliqués. Notez cependant que si la limite de récursion est désactivée, une épuisement de la pile est possible et tout rapport de bogue concernant un tel événement sera rejeté.

L'option -r est un synonyme pour l'option --no-recurse-limit . L'option -R est un synonyme pour l'option --recurse-limit .

-s format
--format=format
c++filt peut décoder diverses méthodes de mangling, utilisées par différents compilateurs. L'argument de cette option sélectionne la méthode qu'il utilise :
"auto"
Sélection automatique basée sur l'exécutable (la méthode par défaut)
"gnu"
celle utilisée par le compilateur GNU C++ (g++)
"lucid"
celle utilisée par le compilateur Lucid (lcc)
"arm"
celle spécifiée par le Manuel de Référence Annoté C++
"hp"
celle utilisée par le compilateur HP (aCC)
"edg"
celle utilisée par le compilateur EDG
"gnu-v3"
celle utilisée par le compilateur GNU C++ (g++) avec l'ABI V3.
"java"
celle utilisée par le compilateur GNU Java (gcj)
"gnat"
celle utilisée par le compilateur GNU Ada (GNAT).
--help
Afficher un résumé des options pour c++filt et quitter.
--version
Afficher le numéro de version de c++filt et quitter.
@file
Lire les options de la ligne de commande depuis file. Les options lues sont insérées à la place de l'option originale @file . Si file n'existe pas ou ne peut pas être lu, l'option sera traitée littéralement et ne sera pas supprimée.

Les options dans file sont séparées par des espaces. Un caractère d'espace peut être inclus dans une option en entourant l'option entière soit par des guillemets simples soit par des guillemets doubles. Tout caractère (y compris une barre oblique inverse) peut être inclus en préfixant le caractère à inclure avec une barre oblique inverse. Le fichier peut lui-même contenir des options @file supplémentaires ; de telles options seront traitées récursivement.

NOTES DE BAS DE PAGE

1.
MS-DOS ne permet pas les caractères "+" dans les noms de fichiers, donc sur MS-DOS ce programme est nommé CXXFILT.
