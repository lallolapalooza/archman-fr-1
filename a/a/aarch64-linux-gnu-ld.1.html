LD(1) Outils de développement GNU LD(1)

NOM

ld - L'éditeur de liens GNU

SYNTAXE

ld [options] fichier-objet ...

DESCRIPTION

ld combine un certain nombre de fichiers objets et d'archives, relocalise leurs données et résout les références de symboles. Habituellement, la dernière étape de la compilation d'un programme consiste à exécuter ld.

ld accepte des fichiers de langage de commande de l'éditeur de liens écrits dans un sur-ensemble de la syntaxe du langage de commande de l'éditeur de liens d'AT&T, afin de fournir un contrôle explicite et total sur le processus de liaison. Pour plus de détails sur le langage de commande et d'autres aspects de l'éditeur de liens GNU, consultez l'entrée ld dans "info".

Cette version de ld utilise les bibliothèques BFD à usage général pour opérer sur les fichiers objets. Cela permet à ld de lire, combiner et écrire des fichiers objets dans de nombreux formats différents, par exemple COFF ou "a.out". Différents formats peuvent être liés ensemble pour produire n'importe quel type de fichier objet disponible.

Outre sa flexibilité, l'éditeur de liens GNU est plus utile que d'autres éditeurs de liens pour fournir des informations diagnostiques. De nombreux éditeurs de liens abandonnent immédiatement l'exécution en cas d'erreur ; dans la mesure du possible, ld continue à s'exécuter, vous permettant d'identifier d'autres erreurs (ou, dans certains cas, d'obtenir un fichier de sortie malgré l'erreur).

L'éditeur de liens GNU ld est conçu pour couvrir un large éventail de situations et être aussi compatible que possible avec d'autres éditeurs de liens. Par conséquent, vous avez de nombreux choix pour contrôler son comportement.

OPTIONS

L'éditeur de liens prend en charge une pléthore d'options en ligne de commande, mais en pratique, peu d'entre elles sont utilisées dans un contexte particulier. Par exemple, une utilisation fréquente de ld est de lier des fichiers objets Unix standard sur un système Unix standard et pris en charge. Sur un tel système, pour lier un fichier "hello.o" :

ld -o <sortie> /lib/crt0.o hello.o -lc

Cela indique à ld de produire un fichier nommé sortie comme résultat de la liaison du fichier "/lib/crt0.o" avec "hello.o" et la bibliothèque "libc.a", qui proviendra des répertoires de recherche standard. (Voir la discussion de l'option -l ci-dessous.)

Certaines des options en ligne de commande de ld peuvent être spécifiées à n'importe quel point de la ligne de commande. Cependant, les options qui font référence à des fichiers, telles que -l ou -T, font que le fichier est lu au point où l'option apparaît dans la ligne de commande, par rapport aux fichiers objets et autres options de fichier. Répéter des options qui ne sont pas des fichiers avec un argument différent n'aura aucun effet supplémentaire, ou annulera les occurrences précédentes (celles plus à gauche sur la ligne de commande) de cette option. Les options qui peuvent être spécifiées plus d'une fois de manière significative sont notées dans les descriptions ci-dessous.

Les arguments qui ne sont pas des options sont des fichiers objets ou des archives qui doivent être liés ensemble. Ils peuvent suivre, précéder ou être mélangés avec des options en ligne de commande, à l'exception qu'un argument de fichier objet ne peut pas être placé entre une option et son argument.

Généralement, l'éditeur de liens est appelé avec au moins un fichier objet, mais vous pouvez spécifier d'autres formes de fichiers d'entrée binaires en utilisant -l, -R et le langage de commande de script. Si aucun fichier d'entrée binaire n'est spécifié du tout, l'éditeur de liens ne produit aucune sortie et émet le message Aucun fichier d'entrée.

Si l'éditeur de liens ne parvient pas à reconnaître le format d'un fichier objet, il supposera qu'il s'agit d'un script d'éditeur de liens. Un script spécifié de cette manière complète le script d'éditeur de liens principal utilisé pour la liaison (soit le script d'éditeur de liens par défaut, soit celui spécifié à l'aide de -T). Cette fonctionnalité permet à l'éditeur de liens de se lier à un fichier qui semble être un objet ou une archive, mais qui définit en réalité certaines valeurs de symboles, ou utilise "INPUT" ou "GROUP" pour charger d'autres objets. La spécification d'un script de cette manière complète simplement le script d'éditeur de liens principal, avec les commandes supplémentaires placées après le script principal ; utilisez l'option -T pour remplacer entièrement le script d'éditeur de liens par défaut, mais notez l'effet de la commande "INSERT".

Pour les options dont les noms sont une seule lettre, les arguments d'option doivent soit suivre la lettre d'option sans espace blanc intermédiaire, soit être donnés comme arguments séparés immédiatement après l'option qui les requiert.

Pour les options dont les noms sont constitués de plusieurs lettres, un ou deux traits d'union peuvent précéder le nom de l'option ; par exemple, -trace-symbol et --trace-symbol sont équivalents. Notez qu'il y a une exception à cette règle. Les options à plusieurs lettres qui commencent par une minuscule 'o' ne peuvent être précédées que de deux traits d'union. Ceci est fait pour réduire la confusion avec l'option -o. Ainsi, par exemple, -omagic définit le nom du fichier de sortie sur magic, tandis que --omagic définit le drapeau NMAGIC sur la sortie.

Les arguments des options à plusieurs lettres doivent soit être séparés du nom de l'option par un signe égal, soit être donnés comme arguments séparés immédiatement après l'option qui les requiert. Par exemple, --trace-symbol foo et --trace-symbol=foo sont équivalents. Des abréviations uniques des noms des options à plusieurs lettres sont acceptées.

Notez que si l'éditeur de liens est appelé indirectement, via un pilote de compilateur (par exemple, gcc), alors toutes les options de ligne de commande de l'éditeur de liens doivent être précédées de -Wl, (ou de ce qui est approprié pour le pilote de compilateur particulier), comme ceci :

gcc -Wl,--start-group foo.o bar.o -Wl,--end-group

Ceci est important, car sinon le programme pilote du compilateur peut ignorer silencieusement les options de l'éditeur de liens, entraînant une mauvaise liaison. La confusion peut également survenir lors du passage d'options qui nécessitent des valeurs via un pilote, car l'utilisation d'un espace entre l'option et l'argument agit comme un séparateur, et amène le pilote à ne passer que l'option à l'éditeur de liens et l'argument au compilateur. Dans ce cas, il est plus simple d'utiliser les formes jointes des options à une et plusieurs lettres, telles que :

gcc foo.o bar.o -Wl,-eENTRY -Wl,-Map=a.map

-L répertoire_recherche
--library-path=répertoire_recherche
Ajoute le chemin répertoire_recherche à la liste des chemins que ld recherchera pour les bibliothèques d'archives et les scripts de contrôle ld. --remap-inputs=motif=nom_fichier
--remap-inputs-file=fichier
Ces options permettent de modifier les noms des fichiers d'entrée avant que l'éditeur de liens ne tente de les ouvrir. L'option --remap-inputs=foo.o=bar.o fera en sorte que toute tentative de chargement d'un fichier nommé foo.o tente plutôt de charger un fichier nommé bar.o. Les motifs génériques sont autorisés dans le premier nom de fichier, ainsi --remap-inputs=foo*.o=bar.o renommera tout fichier d'entrée correspondant à foo*.o en bar.o.

Une forme alternative de l'option --remap-inputs-file=nom_fichier permet de lire les remappages à partir d'un fichier. Chaque ligne du fichier peut contenir un seul remappage. Les lignes vides sont ignorées. Tout ce qui suit un caractère dièse (#) jusqu'à la fin d'une ligne est considéré comme un commentaire et est également ignoré. Le motif de mappage peut être séparé du nom de fichier par un espace blanc ou un signe égal (=).

Les options peuvent être spécifiées plusieurs fois. Leur contenu s'accumule. Les remappages seront traités dans l'ordre où ils apparaissent sur la ligne de commande, et s'ils proviennent d'un fichier, dans l'ordre où ils apparaissent dans le fichier. Si une correspondance est trouvée, aucune vérification supplémentaire pour ce nom de fichier ne sera effectuée.

Si le nom de fichier de remplacement est /dev/null ou simplement NUL, alors le remappage provoquera en fait l'ignorance du fichier d'entrée. Cela peut être un moyen pratique d'expérimenter la suppression de fichiers d'entrée dans un environnement de construction complexe.

Notez que cette option dépend de la position et n'affecte que les noms de fichiers qui la suivent sur la ligne de commande. Ainsi :

ld foo.o --remap-inputs=foo.o=bar.o

N'aura aucun effet, alors que :

ld --remap-inputs=foo.o=bar.o foo.o

Renommera le fichier d'entrée foo.o en bar.o.

Notez que ces options affectent également les fichiers référencés par les instructions INPUT dans les scripts d'éditeur de liens. Mais comme les scripts d'éditeur de liens sont traités après la lecture de toute la ligne de commande, la position des options de remappage sur la ligne de commande n'est pas significative.

Si l'option verbose est activée, tout remappage correspondant sera signalé, bien que là encore, l'option verbose doive être activée sur la ligne de commande avant que les noms de fichiers remappés n'apparaissent.

Si les options -Map ou --print-map sont activées, la liste des remappages sera incluse dans la sortie de la carte.

    Une deuxième solution consiste à forcer l'une des 'constantes' à être une variable, c'est-à-dire inconnue et non optimisable au moment de la compilation. Pour les tableaux, il existe deux possibilités : a) rendre l'indice (l'adresse du tableau) une variable, ou b) rendre l'indice 'constant' une variable. Ainsi :

    ou

    Pour les structures (et la plupart des autres types de données multi-octets), la seule option est de rendre la structure elle-même (ou le long long, ou le ...) variable :

    extern struct s extern_struct;
extern_struct.field -->
   { volatile struct s *t=&extern_struct; t->field }

    ou

    extern long long extern_ll;

  { volatile long long * local_ll=&extern_ll; *local_ll }

    Vous pouvez modifier le comportement de ld avec les variables d'environnement "GNUTARGET", "LDEMULATION" et "COLLECT_NO_DEMANGLE"

    "GNUTARGET" détermine le format objet du fichier d'entrée si vous n'utilisez pas -b (ou son synonyme --format). Sa valeur doit être l'un des noms BFD pour un format d'entrée. S'il n'y a pas de "GNUTARGET" dans l'environnement, ld utilise le format naturel de la cible. Si "GNUTARGET" est défini à "default", alors BFD tente de découvrir le format d'entrée en examinant les fichiers binaires d'entrée ; cette méthode réussit souvent, mais il y a des ambiguïtés potentielles, car il n'existe pas de méthode pour garantir que le nombre magique utilisé pour spécifier les formats de fichiers objets est unique. Cependant, la procédure de configuration de BFD sur chaque système place le format conventionnel pour ce système en premier dans la liste de recherche, de sorte que les ambiguïtés sont résolues en faveur de la

    convention.
