DESCRIPTIO

N

L'appel système accept() est utilisé avec les types de sockets basés sur la connexion (SOCK_STREAM, SOCK_SEQPACKET). Il extrait la première demande de connexion sur la file des connexions en attente pour le socket d'écoute, sockfd, crée un nouveau socket connecté et renvoie un nouveau descripteur de fichier pointant vers ce socket. Le socket nouvellement créé n'est pas en état d'écoute. Le socket d'origine sockfd n'est pas affecté par cet

appel.

L'argument sockfd est un socket qui a été créé avec socket(2), lié à une adresse locale avec bind(2), et qui écoute les connexions après un listen(

2).

L'argument addr est un pointeur vers une structure sockaddr. Cette structure est remplie avec l'adresse du socket distant, telle que connue par la couche de communication. Le format exact de l'adresse renvoyée addr est déterminé par la famille d'adresses du socket (voir socket(2) et les pages man des protocoles respectifs). Lorsque addr est NULL, rien n'est rempli ; dans ce cas, addrlen n'est pas utilisé et devrait également être

NULL.

L'argument addrlen est un argument valeur-résultat : l'appelant doit l'initialiser pour qu'il contienne la taille (en octets) de la structure pointée par addr ; au retour, il contiendra la taille réelle de l'adresse du

pair.

L'adresse renvoyée est tronquée si le tampon fourni est trop petit ; dans ce cas, addrlen renverra une valeur supérieure à celle fournie à

l'appel.

S'il n'y a aucune connexion en attente sur la file et que le socket n'est pas marqué comme non bloquant, accept() bloque l'appelant jusqu'à ce qu'une connexion soit présente. Si le socket est marqué non bloquant et qu'aucune connexion en attente n'est présente sur la file, accept() échoue avec l'erreur EAGAIN ou EWOULDBLOCK

.

Afin d'être notifié des connexions entrantes sur un socket, vous pouvez utiliser select(2), poll(2) ou epoll(7). Un événement lisible sera délivré lorsqu'une nouvelle connexion est tentée et vous pouvez alors appeler accept() pour obtenir un socket pour cette connexion. Alternativement, vous pouvez configurer le socket pour qu'il délivre SIGIO lorsqu'une activité se produit sur un socket ; voir socket(7) pour plus de

détails.

Gestion des

erreurs

Linux accept() (et accept4()) transmet les erreurs réseau déjà en attente sur le nouveau socket sous forme de code d'erreur provenant de accept(). Ce comportement diffère des autres implémentations de sockets BSD. Pour un fonctionnement fiable, l'application devrait détecter les erreurs réseau définies pour le protocole après accept() et les traiter comme EAGAIN en réessayant. Dans le cas de TCP/IP, ce sont ENETDOWN, EPROTO, ENOPROTOOPT, EHOSTDOWN, ENONET, EHOSTUNREACH, EOPNOTSUPP et ENETU

VERSION

S

Sur Linux, le nouveau socket renvoyé par accept() n'hérite pas des indicateurs d'état de fichier tels que O_NONBLOCK et O_ASYNC du socket d'écoute. Ce comportement diffère de l'implémentation canonique des sockets BSD. Les programmes portables ne devraient pas se fier à l'héritage ou à la non-héritage des indicateurs d'état de fichier et devraient toujours définir explicitement tous les indicateurs requis sur le socket renvoyé par acce

pt(

REMARQUE

S

Il peut ne pas toujours y avoir une connexion en attente après la livraison d'un SIGIO ou après le retour de select(2), poll(2), ou epoll(7) avec un événement de lisibilité, car la connexion peut avoir été supprimée par une erreur réseau asynchrone ou par un autre thread avant l'appel à accept(). Si cela se produit, l'appel se bloquera en attendant l'arrivée de la prochaine connexion. Pour garantir que accept() ne se bloque jamais, la socket passée sockfd doit avoir le drapeau O_NONBLOCK défini (voir socket(7))

.

Pour certains protocoles qui nécessitent une confirmation explicite, tels que DECnet, accept() peut être considéré comme simplement retirant la prochaine demande de connexion de la file, sans impliquer de confirmation. La confirmation peut être implicite lors d'une lecture ou d'une écriture normale sur le nouveau descripteur de fichier, et le rejet peut être implicite en fermant la nouvelle socket. Actuellement, seul DECnet a ces sémantiques sur

Linux.

socklen_t
