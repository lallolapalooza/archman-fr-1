acct_gather.conf(5) Fichier de configuration Slurm acct_gather.conf(5)

NOM

acct_gather.conf - Fichier de configuration Slurm pour les plugins liés à acct_gather

DESCRIPTION

acct_gather.conf est un fichier formaté UTF8 qui définit les paramètres utilisés par les plugins Slurm liés à acct_gather. Le fichier se trouvera toujours dans le même répertoire que slurm.conf.

Les noms des paramètres ne sont pas sensibles à la casse mais les valeurs des paramètres le sont. Tout texte suivant un "#" dans le fichier de configuration est traité comme un commentaire jusqu'à la fin de la ligne. La taille de chaque ligne du fichier est limitée à 1024 caractères.

Les modifications du fichier de configuration prennent effet lors du redémarrage des démons Slurm.

Les paramètres acct_gather.conf suivants sont définis pour contrôler le comportement général de divers plugins dans Slurm.

Le fichier acct_gather.conf est différent des autres fichiers .conf de Slurm. Chaque plugin définit les options disponibles. Chaque plugin à charger doit être spécifié dans slurm.conf sous les entrées de configuration suivantes :

• AcctGatherEnergyType (type de plugin =acct_gather_energy)
• AcctGatherInterconnectType (type de plugin =acct_gather_interconnect)
• AcctGatherFilesystemType (type de plugin =acct_gather_filesystem)
• AcctGatherProfileType (type de plugin =acct_gather_profile)

Si le plugin respectif pour une option n'est pas chargé, alors cette option sera inconnue de Slurm, ce qui provoquera un arrêt fatal du démon lors de l'initialisation. Si vous décidez de changer les types de plugins dans slurm.conf, assurez-vous également de changer les options liées dans acct_gather.conf.

acct_gather_energy/gpu

Entrée requise dans slurm.conf :

AcctGatherEnergyType=acct_gather_energy/gpu
Ce plugin ne lit aucune option de acct_gather.conf.
Les données fournies par le plugin sont : Énergie.

acct_gather_energy/IPMI

Entrée requise dans slurm.conf :

AcctGatherEnergyType=acct_gather_energy/ipmi

Les options utilisées pour acct_gather_energy/ipmi sont les suivantes :

EnergyIPMIFrequency=<nombre>
Ce paramètre est le nombre de secondes entre les échantillons d'accès au BMC. Idéalement, il devrait être supérieur ou égal à JobAcctGatherFrequency, sinon le plugin JobAcctGather obtiendra des valeurs répétées lors des interrogations successives.
EnergyIPMICalcAdjustment=<oui|non>
S'il est défini sur "oui", la consommation entre le dernier échantillon d'accès au BMC et une mise à jour de la consommation d'une étape est approximée pour obtenir une consommation de tâche plus précise. L'ajustement est effectué au début de l'étape et chaque fois que la consommation est mise à jour, y compris à la fin de l'étape. Les approximations ne sont pas accumulées, seuls le premier et le dernier ajustements sont utilisés pour calculer la consommation. La valeur par défaut est "non".
EnergyIPMIPowerSensors=<clé=valeurs>
Spécifiez facultativement les identifiants des capteurs à utiliser. Plusieurs <clé=valeurs> peuvent être définis avec des séparateurs ";". La clé "Node" est obligatoire et est utilisée pour connaître l'énergie consommée par les nœuds (scontrol show node) et les tâches (sacct). Les autres clés sont facultatives et sont nommées par l'administrateur. Ces clés ne sont utiles que lorsque le profil est activé pour l'énergie afin de stocker la puissance (en watts) de chaque clé. Les <valeurs> sont des entiers sauf lors de l'utilisation de DCMI. Plusieurs valeurs peuvent être définies avec des séparateurs ",". La somme des capteurs listés est utilisée pour chaque clé. EnergyIPMIPowerSensors est facultatif, la valeur par défaut est "Node=<valeur>" où "<valeur>" est l'identifiant du premier capteur de puissance retourné par ipmi-sensors.
c.-à-d.
EnergyIPMIPowerSensors=Node=16,19,23,26;Socket0=16,23;Socket1=19,26;SSUP=23,26;KNC=16,19
EnergyIPMIPowerSensors=Node=29,32;SSUP0=29;SSUP1=32
EnergyIPMIPowerSensors=Node=1280

Interface de gestion de centre de données - acct_gather_energy/ipmi prend en charge la collecte de données de puissance via des commandes d'extension IPMI DCMI. Lorsqu'elle est configurée, le plugin ipmi interrogera le DCMI en utilisant les indicateurs "System Power mode" ou "Enhanced System Power Statistics mode" en fonction de la configuration.

Pour configurer l'un ou l'autre, les valeurs spéciales de capteur DCMI ou DCMI_ENHANCED peuvent être utilisées, par exemple :
EnergyIPMIPowerSensors=Node=DCMI
EnergyIPMIPowerSensors=Node=DCMI_ENHANCED

Les paramètres acct_gather.conf suivants sont définis pour contrôler les valeurs par défaut de la configuration IPMI pour libipmiconsole.

EnergyIPMIUsername=NOMUTILISATEUR
Spécifiez le nom d'utilisateur BMC.
EnergyIPMIPassword=MOTDEPASSE
Spécifiez le mot de passe BMC.
Les données fournies par le plugin portent le nom : <LIBELLE_CAPTEUR_IPMI>Power.

NOTES :

Ce plugin nécessite que les fichiers de développement freeipmi soient installés et liés au moment de la configuration. Le plugin ne sera pas construit sinon. Lors de la construction du RPM, rpmbuild ... --with freeipmi peut être spécifié pour vérifier explicitement ces dépendances.

acct_gather_energy/XCC

Entrée requise dans slurm.conf :

AcctGatherEnergyType=acct_gather_energy/xcc

Les options utilisées pour acct_gather_energy/xcc n'incluent que les communications in-band avec XClarity Controller, donc un ensemble réduit de configurations est pris en charge :

EnergyIPMIFrequency=<nombre>
Ce paramètre est le nombre de secondes entre les échantillons d'accès au XCC. La valeur par défaut est de 30 secondes.
EnergyIPMITimeout=<nombre>
Délai d'attente, en secondes, pour l'initialisation du contexte IPMI XCC pour un nouveau thread de collecte. La valeur par défaut est de 10 secondes.
Les données fournies par le plugin sont : Énergie, CurrPower.

: Ce plugin nécessite que les fichiers de développement de libcurl soient installés et liables au moment de la configuration (configure). Le plugin ne se

construira

pas autrement. Des informations sur la manière d'installer et configurer InfluxDB et de gérer les bases de données, les politiques de rétention, etc. sont

disponibles

sur le site web officiel. Les informations collectées sont écrites depuis chaque nœud de calcul où une tâche s'exécute vers l' instance InfluxDB écoutant sur le ProfileInfluxDBHost. Afin d'éviter de surcharger l' instance InfluxDB avec des requêtes de connexion entrantes, le plugin utilise une mémoire tampon interne qui est remplie d'échantillons. Une fois la mémoire tampon pleine, une requête d'écriture de l'API HTTP est effectuée et la mémoire tampon est vidée pour accueillir les échantillons suivants. Une requête finale est également effectuée lorsqu'une tâche se

termine,

même si la mémoire tampon n'est pas pleine. Les requêtes d'écriture de l'API HTTP qui échouent sont silencieusement jetées. Cela signifie que les informations de profilage collectées dans la mémoire tampon du plugin sont

perdues

si elles ne peuvent pas être écrites dans la base de données InfluxDB pour quelque raison que ce soit. Les messages du plugin sont enregistrés avec les journaux de slurmd dans SlurmdLogFile. Afin de dépanner tout problème, il est recommandé d'augmenter temporairement le niveau de débogage de slurmd à debug3 et d'ajouter Profile aux indicateurs de débogage.
