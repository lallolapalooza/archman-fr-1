ACCEPT(3P) Manuel du programmeur POSIX ACCEPT(3P)

PROLOGUE

Cette page manuelle fait partie du Manuel du programmeur POSIX. L'implémentation Linux de cette interface peut différer (consultez la page manuelle Linux correspondante pour plus de détails sur le comportement de Linux), ou l'interface peut ne pas être implémentée sur Linux.

NOM

accept — accepter une nouvelle connexion sur un socket

SYNOPSIS

#include <sys/socket.h>
int accept(int socket, struct sockaddr *restrict address,
    socklen_t *restrict address_len);

DESCRIPTION

La fonction accept() doit extraire la première connexion de la file des connexions en attente, créer un nouveau socket avec le même type de socket, le même protocole et la même famille d'adresses que le socket spécifié, et allouer un nouveau descripteur de fichier pour ce socket. Le descripteur de fichier doit être alloué comme décrit dans Section 2.14, Allocation des descripteurs de fichier.

La fonction accept() prend les arguments suivants :

socket
Spécifie un socket qui a été créé avec socket(), qui a été lié à une adresse avec bind(), et qui a effectué un appel réussi à listen().
address
Soit un pointeur nul, soit un pointeur vers une structure sockaddr où l'adresse du socket en cours de connexion doit être retournée.
address_len
Soit un pointeur nul, si address est un pointeur nul, soit un pointeur vers un objet socklen_t qui, en entrée, spécifie la longueur de la structure sockaddr fournie, et, en sortie, spécifie la longueur de l'adresse stockée.

Si address n'est pas un pointeur nul, l'adresse du pair pour la connexion acceptée doit être stockée dans la structure sockaddr vers laquelle pointe address, et la longueur de cette adresse doit être stockée dans l'objet vers lequel pointe address_len.

Si la longueur réelle de l'adresse est supérieure à la longueur de la structure sockaddr fournie, l'adresse stockée doit être tronquée.

Si le protocole autorise les connexions par des clients non liés, et que le pair n'est pas lié, alors la valeur stockée dans l'objet vers lequel pointe address est indéterminée.

Si la file d'écoute est vide de demandes de connexion et que O_NONBLOCK n'est pas défini sur le descripteur de fichier du socket, accept() doit se bloquer jusqu'à ce qu'une connexion soit présente. Si la file de listen() est vide de demandes de connexion et que O_NONBLOCK est défini sur le descripteur de fichier du socket, accept() doit échouer et définir errno à [EAGAIN] ou [EWOULDBLOCK].

Le socket accepté ne peut pas lui-même accepter d'autres connexions. Le socket d'origine reste ouvert et peut accepter d'autres connexions.

VALEUR RENVOYÉE

Lors de l'achèvement avec succès, accept() doit renvoyer le descripteur de fichier non négatif du socket accepté. Sinon, -1 doit être renvoyé, errno doit être défini pour indiquer l'erreur, et tout objet vers lequel pointe address_len doit rester inchangé.

ERREURS

La fonction accept() doit échouer si :

EAGAIN ou EWOULDBLOCK

O_NONBLOCK est défini pour le descripteur de fichier du socket et aucune connexion n'est présente pour être acceptée.
EBADF
L'argument socket n'est pas un descripteur de fichier valide.
ECONNABORTED

Une connexion a été interrompue.
EINTR
La fonction accept() a été interrompue par un signal qui a été capté avant l'arrivée d'une connexion valide.
EINVAL
Le socket n'accepte pas de connexions.
EMFILE
Tous les descripteurs de fichier disponibles pour le processus sont actuellement ouverts.
ENFILE
Le nombre maximal de descripteurs de fichier dans le système est déjà ouvert.
ENOBUFS
Aucun espace de tampon n'est disponible.
ENOMEM
La mémoire disponible était insuffisante pour terminer l'opération.
ENOTSOCK
L'argument socket ne fait pas référence à un socket.
EOPNOTSUPP
Le type de socket du socket spécifié ne prend pas en charge l'acceptation de connexions.

La fonction accept() peut échouer si :

EPROTO
Une erreur de protocole s'est produite ; par exemple, la pile de protocoles STREAMS n'a pas été initialisée.

UTILISATION PAR LES APPLICATIONS

Lorsqu'une connexion est disponible, select() indique que le descripteur de fichier du socket est prêt pour la lecture.
