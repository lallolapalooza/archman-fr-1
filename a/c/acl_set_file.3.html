ACL_SET_FILE(3) Manuel des fonctions de bibliothèque ACL_SET_FILE(3)

NOM

acl_set_file — définir un ACL par nom de fichier

BIBLIOTHÈQUE

Bibliothèque Linux des listes de contrôle d'accès (libacl, -lacl).

SYNOPSIS

#include <sys/types.h>
#include <sys/acl.h>

int
acl_set_file(const char *path_p, acl_type_t type, acl_t acl);

DESCRIPTION

La acl_set_file() fonction associe un ACL d'accès à un fichier ou répertoire, ou associe un ACL par défaut à un répertoire. Le chemin d'accès du fichier ou du répertoire est indiqué par l'argument path_p.

L'identifiant utilisateur effectif du processus doit correspondre au propriétaire du fichier ou du répertoire, ou le processus doit posséder la capacité CAP_FOWNER pour que la requête réussisse.

La valeur de l'argument type est utilisée pour indiquer si c'est le ACL d'accès ou le ACL par défaut associé à path_p qui est défini. Si le type paramètre est ACL_TYPE_ACCESS, le ACL d'accès de path_p sera défini. Si le type paramètre est ACL_TYPE_DEFAULT, le ACL par défaut de path_p sera défini. Si l'argument type spécifie un type de ACL qui ne peut pas être associé à path_p, alors la fonction échoue.

Le acl paramètre doit référencer un ACL valide selon les règles décrites sur la page man acl_valid(3) si le type paramètre est ACL_TYPE_ACCESS, et doit soit référencer un ACL valide, soit un ACL avec zéro entrée de ACL si le type paramètre est ACL_TYPE_DEFAULT. Si le acl paramètre référence un ACL vide, alors la fonction acl_set_file() supprime tout ACL par défaut associé au répertoire référencé par le paramètre path_p .

VALEUR RENVOYÉE

La fonction acl_set_file() renvoie la valeur 0 en cas de succès ; sinon la valeur -1 est renvoyée et la variable globale errno est définie pour indiquer l'erreur.

ERREURS

Si l'une des conditions suivantes se produit, la fonction acl_set_file() renvoie -1 et définit errno à la valeur correspondante :

[EACCES]
La permission de recherche est refusée pour un composant du préfixe de chemin ou l'objet existe et le processus ne possède pas les droits d'accès appropriés.

L'argument type spécifie un type de ACL qui ne peut pas être associé à path_p.

[EINVAL]
L'argument acl ne pointe pas vers un ACL valide.

Le ACL a plus d'entrées que le fichier référencé par path_p ne peut en contenir.

Le type paramètre n'est ni ACL_TYPE_ACCESS ni ACL_TYPE_DEFAULT.

Le type paramètre est ACL_TYPE_DEFAULT, mais le fichier référencé par path_p n'est pas un répertoire.

[ENAMETOOLONG]
La longueur de l'argument path_p est trop longue.
[ENOENT]
L'objet nommé n'existe pas ou l'argument path_p pointe vers une chaîne vide.
[ENOSPC]
Le répertoire ou le système de fichiers qui contiendrait le nouveau ACL ne peut pas être étendu ou le système de fichiers est à court de ressources d'allocation de fichiers.
[ENOTDIR]
Un composant du préfixe de chemin n'est pas un répertoire.
[ENOTSUP]
Le fichier identifié par path_p ne peut pas être associé au ACL car le système de fichiers sur lequel le fichier est situé ne le prend pas en charge.
[EPERM]
Le processus ne possède pas le privilège approprié pour effectuer l'opération de définition du ACL.
[EROFS]
Cette fonction nécessite la modification d'un système de fichiers qui est actuellement en lecture seule.

NORMES

IEEE Std 1003.1e brouillon 17 (« POSIX.1e », abandonné)

Le comportement de acl_set_file() lorsque le acl paramètre référence un ACL vide et le type paramètre est ACL_TYPE_DEFAULT est une extension dans l'implémentation Linux, afin que toutes les valeurs renvoyées par acl_get_file() puissent être passées à acl_set_file(). La fonction POSIX.1e pour supprimer un ACL par défaut est acl_delete_def_file().
