NOM

actsync, actsyncd - Synchroniser les groupes de nouvelles

SYNTAXE

actsync [-AkmT] [-b id_hote] [-d id_hote] [-g max] [-i fichier_ignoré] [-I id_hote] [-l id_hote] [-n nom] [-o format] [-p min_inchangé] [-q id_hote] [-s taille] [-t id_hote] [-v verbeux] [-w secondes] [-z secondes] [hote] hote

actsyncd config [niveau_debug [format_debug]]

EN UNE PHRASE

Ces programmes permettent de maintenir synchronisée la liste des groupes de nouvelles gérés par votre serveur de nouvelles avec une source externe.

Par exemple, vous pouvez décider de gérer les mêmes groupes de nouvelles qu'un autre serveur de nouvelles ou qu'une liste dans un fichier provenant d'un site FTP ou web externe, puis de synchroniser avec la source choisie quotidiennement en exécutant actsyncd dans un cron job.

Si vous ne souhaitez qu'un sous-ensemble de groupes de nouvelles de cette source, cela peut être paramétré dans le fichier de configuration actsync.ign dans le répertoire pathetc.

INN est livré avec une configuration par défaut pour récupérer la liste des groupes de nouvelles depuis "downloads.isc.org" (également connu sous le nom de "ftp.isc.org"). Vous pouvez lire les politiques utilisées pour maintenir ce fichier active à https://downloads.isc.org/pub/usenet/CONFIG/README. Assurez-vous simplement que actsync.cfg (le fichier de configuration) et actsync.ign (les règles de synchronisation) conviennent à vos besoins, et exécutez :

actsyncd <pathetc>/actsync.cfg

Vous trouverez des exemples d'utilisation plus détaillés ci-dessous dans cette page de manuel.

DESCRIPTION

actsync permet de synchroniser, comparer ou fusionner deux fichiers active. Avec cet utilitaire, on peut ajouter, modifier ou supprimer des groupes de nouvelles sur le serveur de nouvelles local pour le rendre similaire à la liste des groupes de nouvelles trouvés sur un autre système ou fichier. La synchronisation n'a pas besoin d'être exacte. Des différences locales dans les listes de groupes de nouvelles peuvent être maintenues et préservées. Certaines erreurs de groupes de nouvelles peuvent être détectées et optionnellement corrigées.

Il y a plusieurs raisons de lancer actsync (ou actsyncd) de manière périodique. Parmi ces raisons :

  • Un message de contrôle pour ajouter, modifier ou supprimer un groupe de nouvelles peut ne pas parvenir à votre site.
  • Votre fichier control.ctl peut être obsolète ou incomplet.
  • Les articles de nouvelles pour un nouveau groupe de nouvelles peuvent arriver avant (parfois plusieurs jours avant) le message de contrôle.
  • Les messages de contrôle peuvent être falsifiés, contournant ainsi les restrictions trouvées dans control.ctl à moins que vous n'ayez mis en place une authentification PGP (et même dans ce cas, toutes les hiérarchies n'utilisent pas l'authentification PGP).
  • Votre fichier active peut avoir été corrompu.

Si l'un des arguments hote commence par "." ou "/", il est supposé être le nom d'un fichier contenant des informations au format active(5). Les informations sur les groupes de nouvelles d'un fichier peuvent être traitées comme si elles provenaient d'un hote. Dans cette page de manuel, les arguments hote sur la ligne de commande sont appelés hôtes, même s'il peut s'agir de noms de fichiers.

Si un argument d'hote ne commence pas par "." ou "/", il est supposé être un nom d'hote ou une adresse Internet. Dans ce cas, actsync tentera d'utiliser le protocole NNTP pour obtenir une copie du fichier active du système spécifié. Si l'argument d'hote contient ":", la partie droite sera considérée comme le port à connecter sur le système distant. Si aucun numéro de port n'est spécifié, actsync se connectera au port 119.

Indépendamment de la manière dont les informations du fichier active sont obtenues, les actions de actsync restent les mêmes.

Le premier hote spécifié est considéré comme l'hote local, celui où toutes les modifications seraient apportées. Le second hote spécifié est l'hote distant avec lequel la synchronisation est effectuée. Si un seul hote est spécifié, il est supposé être l'hote distant avec lequel synchroniser, et l'hote local est supposé être le serveur NNTP local par défaut tel que spécifié par la variable d'environnement NNTPSERVER ou par la valeur server trouvée dans inn.conf.

Si l'un des hôtes est spécifié comme "-", le serveur par défaut sera utilisé pour cet hote, déterminé comme décrit ci-dessus.

La synchronisation des groupes de nouvelles, par défaut, concerne tous les groupes de nouvelles trouvés sur les deux hôtes. On peut également synchroniser un sous-ensemble de groupes de nouvelles en demandant à actsync d'ignorer certains groupes de nouvelles des deux systèmes. Seuls les groupes de nouvelles avec des noms valides seront synchronisés. Pour être valide, un nom de groupe de nouvelles doit uniquement contenir des caractères alphanumériques, ".", "+", "-" et "_". On ne peut pas avoir deux caractères "." consécutifs. Le premier caractère doit être alphanumérique, tout comme tout caractère suivant un ".". Le nom ne peut pas se terminer par un caractère ".".

Le démon actsyncd fournit une interface pratique pour configurer et exécuter actsync. Si un hote n'est pas initialement joignable, le démon retentera jusqu'à 9 fois supplémentaires, en attendant 6 minutes avant chaque nouvelle tentative. Ce démon s'exécute en avant-plan, envoyant la sortie vers la sortie standard et l'erreur standard. actsyncd utilise l'utilitaire getlist(1) pour obtenir une copie du fichier active d'un système distant via son serveur NNTP, ou exécute un client FTP ou web (wget ou ncftpget s'ils sont installés et trouvés au moment de la configuration, ou le programme simpleftp(1) fourni avec INN) pour récupérer une liste de groupes de nouvelles à partir d'une archive externe (telle que https://downloads.isc.org/pub/usenet/CONFIG/active ; voir plus d'informations ci-dessous). Il utilise ensuite mod-active(8) pour mettre à jour le fichier active s'il y a des commandes pour ctlinnd dans sa sortie.

Le nom du fichier de configuration pour le démon est donné en argument de ligne de commande, généralement actsync.cfg dans pathetc. Ce fichier peut contenir les options suivantes :

host=<hote>
path=<chemin-vers-active>
protocol=<protocole>
flags=<options-actsync>
ignore_file=<fichier_ignoré>

Les lignes "host=", "flags=" et "ignore_file=" sont obligatoires. Chaque mot-clé doit commencer au début de la ligne, et il ne peut y avoir d'espace blanc avant le caractère "=". Les lignes vides sont ignorées, tout comme les lignes de commentaire qui commencent par "#". Toute autre ligne peut produire des résultats indéfinis.

Le réglage <host> fait référence au second paramètre (distant) hote de actsync. Si <chemin-vers-active> n'est pas fourni, <protocole> est considéré comme "nntp", et <hote> est accédé en tant que serveur NNTP distant. Si <chemin-vers-active> est fourni, <hote> est accédé en tant que serveur FTP ou web selon la valeur de <protocole> ("ftp", "http" ou "https", par défaut "ftp" lorsqu'il n'est pas défini), récupérant le fichier active au chemin absolu <chemin-vers-active>. Si le nom de fichier se termine par ".bz2", ".gz" ou ".Z", il sera automatiquement décompressé après récupération. <options-actsync> contient toutes les autres options que vous souhaitez passer à actsync. <fichier_ignoré> nomme le fichier d'ignoré utilisé par actsync (l'option -i).

Notez qu'il ne faut pas inclure les options -i ou -o dans la ligne "flags=" ; elles sont automatiquement gérées par actsyncd.

On peut obtenir un essai de actsyncd sans modifier quoi que ce soit sur le serveur en fournissant l'argument niveau_debug :

actsyncd <pathetc>/actsync.cfg 2

Le niveau_debug fait exécuter à actsyncd actsync avec une option -v

OPTIONS

actsync accepte les options suivantes.

Dans toutes les options suivantes, le paramètre id-hote prend l'une des valeurs suivantes :

0    aucun serveur
1    serveur local par défaut
2    serveur distant
12   les deux serveurs
21   les deux serveurs

En d'autres termes, 1 fait référence à l'hôte local (le premier argument hote sur la ligne de commande actsync) et 2 fait référence à l'hôte distant (le deuxième argument hote, ou le seul s'il n'y en a qu'un).

-A
actsync tente de s'authentifier en utilisant les informations de nom d'utilisateur et de mot de passe dans passwd.nntp(5) avant d'émettre la commande LIST.
-b id-hote
Ce drapeau amène actsync à ignorer à des fins de synchronisation les groupes de nouvelles avec des noms de style "bork.bork.bork" (groupes de nouvelles dont les 3 derniers composants sont identiques). Par exemple, les groupes de nouvelles suivants ont des noms de style bork : 
alt.helms.dork.dork.dork
alt.auto.accident.sue.sue.sue
alt.election.vote.vote.vote

La valeur par défaut est "-b 0" ; aucun groupe de nouvelles n'est ignoré en raison de noms de style bork.

-d id-hote
Ce drapeau amène actsync à ignorer les groupes de nouvelles qui ont des composants de chemin entièrement numériques. Par exemple, les groupes de nouvelles suivants ont des composants de chemin numériques : 
alt.prime.chongo.23209
391581.times.2.to_the.216193.power.-1
99.bottles.of.treacle.on.the.wall
linfield.class.envio_bio.101.d

Le répertoire des groupes de nouvelles d'un groupe de nouvelles avec un composant entièrement numérique pourrait entrer en conflit avec un article d'un autre groupe s'il est stocké en utilisant la méthode de stockage tradspool ; voir storage.conf(5). Par exemple, le répertoire du premier groupe de nouvelles listé ci-dessus est le même chemin que l'article numéro 23209 du groupe de nouvelles :

alt.prime.chongo

La valeur par défaut est "-d 0" ; tous les groupes de nouvelles numériques des deux hôtes seront traités.

-g max
Ignore tout groupe de nouvelles comportant plus de max niveaux. Par exemple, "-g 6" ignorerait : 
alt.feinstien.votes.to.trash.freedom.of.speech
alt.senator.exon.enemy.of.the.internet
alt.crypto.export.laws.dumb.dumb.dumb

mais n'ignorerait pas :

alt.feinstien.acts.like.a.republican
alt.exon.amendment
alt.crypto.export.laws

Si max est 0, alors la fonctionnalité de niveau max est désactivée.

Par défaut, la fonctionnalité de niveau max est désactivée.

-i fichier-ignoré
Le fichier-ignoré, généralement actsync.ign dans pathetc, permet un contrôle fin sur les groupes de nouvelles à ignorer. Il contient un ensemble de règles qui spécifient quels groupes de nouvelles seront vérifiés et lesquels seront ignorés.

Par défaut, ces règles s'appliquent aux deux hôtes. Ceci peut être modifié en utilisant le drapeau -I.

Les lignes vides et le texte après un "#" sont considérés comme des commentaires et sont ignorés.

Les lignes de règles consistent en des jetons séparés par des espaces. Les lignes de règles peuvent être de l'une des deux formes suivantes :

c <groupe-de-nouvelles> [<type> ...]
i <groupe-de-nouvelles> [<type> ...]

Si la règle commence par un "c", la règle demande que certains groupes de nouvelles soient vérifiés. Si la règle commence par un "i", la règle demande que certains groupes de nouvelles soient ignorés. Le champ <groupe-de-nouvelles> peut être un groupe de nouvelles spécifique, ou un modèle uwildmat.

Si un ou plusieurs <type> sont spécifiés, alors la règle s'applique au groupe de nouvelles uniquement s'il est du type spécifié. Les types se réfèrent au 4ème champ du fichier actif ; c'est-à-dire qu'un type peut être l'un des suivants :

y
n
m
j
x
=nom.de.groupe

Contrairement aux fichiers actif, le "nom.de.groupe" dans un type d'alias peut être un nom de groupe de nouvelles ou un modèle uwildmat. De plus, "=" est équivalent à "=*".

Sur chaque ligne de règle, aucun type de modèle ne peut être répété. Par exemple, il ne peut y avoir qu'un seul type commençant par "=" par ligne. Cependant, on peut obtenir un effet équivalent à l'utilisation de plusieurs types "=" en utilisant plusieurs lignes de règles affectant le même groupe de nouvelles.

Par défaut, tous les groupes de nouvelles sont candidats à la vérification. Si aucun fichier-ignoré n'est spécifié, ou si le fichier ignoré ne contient aucune ligne de règle, tous les groupes de nouvelles seront vérifiés. Si un fichier ignoré est utilisé, chaque groupe de nouvelles est vérifié tour à tour par rapport au fichier ignoré. Si plusieurs lignes correspondent à un groupe de nouvelles donné, la dernière ligne du fichier ignoré est utilisée.

Par exemple, considérons les lignes de fichier ignoré suivantes :

i *.general
c *.general m
i nsa.general

Les groupes de nouvelles ba.general et mod.general seraient synchronisés s'ils sont modérés et ignorés s'ils ne le sont pas. Le groupe de nouvelles nsa.general serait ignoré indépendamment du statut de modération. Tous les groupes de nouvelles ne correspondant pas à *.general seraient synchronisés par défaut.

-I id-hote
Ce drapeau restreint les hôtes affectés par le fichier ignoré. Ce drapeau peut être utile en conjonction avec le drapeau -m. Par exemple : 
actsync -i actsync.ign -I 2 -m host1 host2

gardera tous les groupes de nouvelles actuellement sur host1. Il comparera également uniquement les groupes de host1 avec les groupes de nouvelles non ignorés de host2.

La valeur par défaut est "-I 12" ; les groupes de nouvelles des deux hôtes sont ignorés conformément au fichier spécifié avec -i.

-k
Par défaut, tout groupe de nouvelles sur l'hôte local ayant un nom invalide sera considéré pour suppression. Cela amène actsync à simplement ignorer de tels groupes de nouvelles. Ce drapeau, utilisé en combinaison avec -m, empêchera tout groupe de nouvelles d'être programmé pour suppression.
-l id-hote
Ce drapeau amène les groupes de nouvelles problématiques de type "=" à être considérés comme des erreurs. Les groupes de nouvelles de type "=" sont des entrées actives dont le quatrième champ commence par "=" ; c'est-à-dire les groupes de nouvelles qui sont alias vers d'autres groupes de nouvelles. Un groupe de nouvelles problématique est un groupe pour lequel l'une des conditions suivantes est vraie :
  • Alias à lui-même.
  • Dans une chaîne d'alias qui boucle sur elle-même.
  • Dans une chaîne d'alias de plus de 16 groupes.
  • Alias vers un groupe de nouvelles inexistant.
  • Alias vers un groupe de nouvelles qui présente une erreur quelconque.

Cependant, un groupe de nouvelles équivalent à un groupe de nouvelles ignoré n'est pas un problème.

La valeur par défaut est "-l 12" : les groupes de nouvelles problématiques des deux hôtes sont marqués comme erreurs.

-m
Fusionner les groupes de nouvelles au lieu de synchroniser. Par défaut, si un groupe de nouvelles existe sur l'hôte local mais pas sur l'hôte distant, il sera programmé pour suppression. Ce drapeau désactive ce processus, permettant de conserver les groupes de nouvelles uniques à l'hôte local.
-n nom
Selon -o, la commande ctlinnd(8) peut être utilisée pour créer des groupes de nouvelles si nécessaire. Lorsque cela est fait, le nom du créateur par défaut utilisé est "actsync". Ce drapeau change le nom du créateur en nom.
-o format

a1

ak

aK
Sortie au format active(5), mais utilise les valeurs haute et basse (2ème et 3ème champs actifs) de l'hôte distant pour tous les groupes de nouvelles trouvés sur cet hôte.
a1k
Sortie au format active(5), mais utilise les valeurs haute et basse (2ème et 3ème champs actifs) de l'hôte distant pour tout groupe de nouvelles en cours de création et sort les groupes ignorés non erronés de l'hôte local.
a1K

Les formats de style "a", "a1", "ak", "aK", "a1k", "a1K", "ak1", et "aK1" permettent de formater un nouveau fichier active au lieu de produire des commandes ctlinnd. Ils utilisent les valeurs haute et basse de 0000000000 et 0000000001 respectivement pour les groupes de nouvelles qui sont créés, sauf indication contraire. Les variantes "ak" et "aK" modifient les valeurs haute et basse (2ème et 3ème champs active). Dans le cas de "ak", les groupes de nouvelles créés prennent leurs valeurs haute et basse de l'hôte distant. Dans le cas de "aK", tous les groupes de nouvelles trouvés sur l'hôte distant prennent leurs valeurs haute et basse de celui-ci.

Le format "c" produit des commandes ctlinnd. Aucune action n'est effectuée car actsync se contente d'afficher les commandes ctlinnd sur la sortie standard. Ce format de sortie est utile pour vous permettre de voir comment l'hôte local sera affecté par la synchronisation (ou la fusion) avec l'hôte distant.

La synchronisation (ou la fusion) peut être réalisée directement en utilisant le format "x" ou "xi". Avec ce format, actsync utilise l'appel système execl(2) pour exécuter directement les commandes ctlinnd. La sortie de ces appels d'exécution peut être vue si le niveau de verbosité est d'au moins 2.

L'utilitaire actsync fera une pause de 4 secondes avant chaque commande exécutée si "-o x" est sélectionné. Voir l'option -z ci-dessous pour la discussion de ce délai et comment le personnaliser.

Le format "xi" demande interactivement sur la sortie standard et lit les directives sur l'entrée standard. On peut sélectionner les changements à effectuer avec ce format.

Il faut être prudent lors de la production de la sortie formatée active(5). Il faut vérifier que actsync s'est terminé avec un statut zéro avant d'utiliser une telle sortie. Il faut également savoir qu'une telle sortie ne contiendra pas les lignes ignorées à cause de -i même si "-p 100" est utilisé.

Par défaut, "-o c" est supposé.

-p min-inchangé
Par défaut, l'utilitaire actsync dispose de protections contre l'exécution de changements massifs. Si moins de min-inchangé pour cent des lignes non ignorées de l'hôte local restent inchangées, aucune action (sortie, exécution, etc.) n'est effectuée et actsync se termine avec un statut de sortie non nul. La valeur min-inchangé peut être une valeur flottante comme 66.667.

Un changement est une ligne de groupe de nouvelles locale qui a été supprimée, ajoutée, modifiée, ou qui s'est avérée être en erreur. La modification des 2ème ou 3ème champs active via "-o ak" ou "-o aK" ne sont pas considérées comme des changements par -p.

Pour forcer actsync à accepter n'importe quel montant de changement, utilisez l'option "-p 0". Pour forcer actsync à rejeter tout changement, utilisez l'option "-p 100".

Il faut être prudent lors de la production de la sortie formatée active(5). Il faut vérifier que actsync s'est terminé avec un statut zéro avant d'utiliser une telle sortie. Il faut également savoir qu'une telle sortie ne contiendra pas les lignes ignorées à cause de -i même si "-p 100" est utilisé.

Par défaut, 96% des lignes non ignorées du premier argument host dans la ligne de commande actsync doivent rester inchangées. C'est-à-dire, par défaut, "-p 96" est supposé.

-q hostid
Par défaut, toutes les erreurs de groupes de nouvelles sont rapportées sur la sortie d'erreur standard. Cet indicateur supprime les erreurs provenant de l'identifiant d'hôte hostid spécifié.
-s taille
Si taille est supérieur à 0, alors ignorer les groupes de nouvelles dont le nom est plus long que taille et ignorer les groupes de nouvelles alias (en suivant les chaînes "=") vers des noms plus longs que taille. La vérification de la longueur est effectuée sur les hôtes locaux et distants.

Par défaut, taille est 0 et donc aucune vérification de longueur n'est effectuée.

-t hostid
Ignorer les groupes de nouvelles incorrects constitués uniquement d'un composant de haut niveau de l'identifiant d'hôte hostid spécifié. Les groupes de nouvelles suivants sont considérés comme des groupes de nouvelles corrects malgré leurs noms de haut niveau uniquement et sont donc exemptés de cet indicateur : 
control
general
junk
test
to

Par exemple, les noms de groupes de nouvelles suivants sont incorrects car ils ne contiennent qu'un composant de niveau supérieur :

dole_for_pres
dos
microsoft
windows95

La valeur par défaut est "-t 2" ; c'est-à-dire que tous les groupes de nouvelles incorrects de niveau supérieur uniquement provenant de l'hôte distant sont ignorés.

-T
Cet indicateur fait en sorte que les groupes de nouvelles de l'hôte distant dans de nouvelles hiérarchies soient ignorés. Normalement, un groupe de nouvelles qui n'existe que sur l'hôte distant, chongo.was.here par exemple, est créé sur l'hôte local. Cependant, si cet indicateur est donné et que l'hôte local n'a aucun autre groupe de nouvelles dans la même hiérarchie (chongo.* dans ce cas), le groupe de nouvelles en question sera ignoré et ne sera pas créé sur l'hôte local.
-v verbosité
Par défaut, actsync n'est pas verbeux. Cet indicateur contrôle le niveau de verbosité comme suit :
0
Aucun rapport de débogage ou de statut (par défaut).
1
Afficher un résumé, mais seulement si du travail était nécessaire ou effectué.
2
Afficher les actions, la sortie d'exécution et le résumé, mais seulement si du travail était nécessaire ou effectué.
3
Afficher les actions, la sortie d'exécution et le résumé.
4
Sortie de débogage complète.
-w secondes
Si "-o x" ou "-o xi" est sélectionné, ctlinnd attendra secondes secondes avant de dépasser le délai d'attente. La valeur par défaut est "-w 30".
-z secondes
Si "-o x" est sélectionné, actsync fera une pause de secondes secondes avant chaque commande exécutée. Cela aide à éviter que innd ne soit surchargé si un grand nombre de commandes ctlinnd sont nécessaires. On peut désactiver entièrement cette mise en veille en utilisant "-z 0".

Par défaut, actsync fera une pause de 4 secondes avant chaque commande exécutée si "-o x" est sélectionné.

EXEMPLES

Déterminer la différence (mais sans rien changer) entre votre ensemble de groupes de nouvelles et celui d'un autre serveur de nouvelles :

actsync news.server.com

Identique à ci-dessus, avec des rapports de débogage et de progression complets :

actsync -v 4 news.server.com

Forcer un site à avoir les mêmes groupes de nouvelles qu'un autre site :

actsync -o x master

Cela peut être utile pour synchroniser un site esclave avec son maître, ou pour synchroniser un site interne avec une passerelle.

Comparer votre site avec news.server.com, en ignorant les groupes locaux et certaines différences locales avec celui-ci. Produire un rapport si des différences ont été rencontrées :

actsync -v 2 -i actsync.ign news.server.com

où actsync.ign contient :

# Ne pas comparer les groupes to.* car ils différeront.
#
i       to.*
# Ce sont nos groupes locaux que personne d'autre
# (ne devrait) transporter. Les ignorer donc pour la
# comparaison.
#
i       nsa.*
# Ces groupes sont des favoris locaux, donc les conserver
# même si news.server.com ne les transporte pas.
#
i       ca.dump.bob.dorman
i       ca.keep.bob.dorman
i       alt.tv.dinosaurs.barney.die.die.die
i       alt.tv.dinosaurs.barney.love.love.love
i       alt.sounds.*    =alt.binaries.sounds.*

Pour synchroniser interactivement contre news.server.com, en utilisant le même fichier d'ignorance :

actsync -o xi -v 2 -i actsync.ign news.server.com

En fonction des groupes de nouvelles que vous avez décidé de conserver, on pourrait apporter des modifications au fichier actsync.ign :

# Ne pas comparer les groupes to.* car ils différeront.
#

#

# Ne pas synchroniser les groupes test, sauf ceux qui sont
# modérés ou qui sont sous la hiérarchie gnu.
#
i       *.test
c       *.test m        # vérifier les groupes test modérés
c       gnu.*.test
c       gnu.test        # juste au cas où il existerait

Le traitement automatique peut être configuré en utilisant le fichier actsync.cfg suivant :

# Hôte à partir duquel synchroniser (host2).
host=news.server.com
# Emplacement du fichier d'ignorance.
ignore_file=<pathetc dans inn.conf>/actsync.ign
# Indicateurs actsync(8)
#
# Exécutions automatiques, signaler si quelque chose a été fait,
# sinon ne rien signaler, ne pas signaler les problèmes de fichier
# active de news.server.com, ignorer simplement les entrées concernées.
flags=-o x -v 2 -q 2

et ensuite en exécutant actsyncd avec le chemin vers le fichier de configuration :


pre>actsyncd <pathetc>/actsync.cfg

commande

actsyncd <pathetc>/actsync.cfg 4 >cmd.log 2>dbg.

    instructions de débogage vers dbg.log. (Notez que l'utilisation de debug-level n'est
    prise en charge que lors de la synchronisation avec un autre serveur de
    discussion, et non avec FTP ou HTTP(S).
)
