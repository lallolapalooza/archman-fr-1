DESCRIPTIO

N

Cette page manuelle décrit les listes de contrôle d'accès POSIX

, qui sont utilisées pour définir des droits d'accès discr
étionnaires plus fins pour les fichiers et les répertoires.

TYPES

D'ACL

On peut considérer que chaque objet est associé à une ACL qui régit l'accès discrétionnaire à cet obj

et ; cette ACL est appelée ACL d'accès. De plus, un répertoire peut avoir une ACL associée qui rég
it l'ACL d'accès initiale des objets créés dans ce répertoire ; cette ACL est appelée ACL par défaut.

ENTRÉES

D'ACL

Une ACL se compose d'un ensemble d'entrées d'ACL. Une entrée d'ACL spécifie les permissions d'accès sur l'objet associé pour un utilisateur individuel ou un groupe d'utilisateurs sous la forme d'une combinaison de permissions de lecture, d'écriture et de recherche/exécution

.

Une entrée d'ACL contient un type de balise d'entrée, un qualificateur de balise d'entrée facultatif et un ensemble de permissions. Nous utilisons le terme qualificateur pour désigner le qualificateur de balise d'entrée d'une entrée

d'ACL.

Le qualificateur désigne l'identifiant d'un utilisateur ou d'un groupe, pour les entrées avec les types de balises ACL_USER ou ACL_GROUP, respectivement. Les entrées avec des types de balises autres que ACL_USER ou ACL_GROUP n'ont pas de qualificateurs

définis.

Les types de balises d'entrée suivants sont définis

:
ACL_USER_O
BJ
L'entrée ACL_USER_OBJ désigne les droits d'accès pour le propriétaire du
fichier.
ACL_US
ER
Les entrées ACL_USER désignent les droits d'accès pour les utilisateurs identifiés par le qualificateur de
l'entrée.
ACL_GROUP_O
BJ
L'entrée ACL_GROUP_OBJ désigne les droits d'accès pour le groupe du
fichier.
ACL_GRO
UP
Les entrées ACL_GROUP désignent les droits d'accès pour les groupes identifiés par le qualificateur de
l'entrée.
ACL_MA
SK
L'entrée ACL_MASK désigne les droits d'accès maximums qui peuvent être accordés par les entrées de type ACL_USER, ACL_GROUP_OBJ ou
ACL_GROUP.
ACL_OTH

L'entrée ACL_OTHER désigne les

Lorsqu'une vérification d'accès est effectuée, les entrées ACL_USER_OBJ et ACL_USER sont testées par

rapport à l'identifiant utilisateur effectif. L'identifiant de groupe effectif, ainsi que tous les id
entifiants de groupe supplémentaires, sont testés par rapport aux entrées ACL_GROUP_OBJ et ACL_GROUP.

ACL

VALIDES

Une ACL valide contient exactement une entrée avec chacun des types de balises ACL_USER_OBJ, ACL_GROUP_OBJ et ACL_OTHER. Les entrées avec les balises ACL_USER et ACL_GROUP peuvent apparaître zéro fois ou plus dans une ACL. Une ACL qui contient des entrées de type de balise ACL_USER ou ACL_GROUP doit contenir exactement une entrée du type de balise ACL_MASK. Si une ACL ne contient pas d'entrées de type de balise ACL_USER ou ACL_GROUP, l'entrée ACL_MASK est

facultative.

Tous les qualificateurs d'identifiant utilisateur doivent être uniques parmi toutes les entrées de type de balise ACL_USER, et tous les identifiants de groupe doivent être uniques parmi toutes les entrées de type de balise

ACL_GROUP.


La fonction acl_get_file() renvoie une ACL avec zéro entrée d'ACL comme ACL par défaut d'un répertoire, si le répertoire n'est pas associé à une ACL par défaut. La fonction acl_set_file() accepte également une ACL avec zéro entrée d'ACL comme ACL par défaut valide pour les répertoires, indiquant que le répertoire ne doit pas être associé à une ACL par défaut. Cela équivaut à utiliser la fonction acl_del

ete_def
_file().

CORRESPONDANCE ENTRE LES ENTRÉES D'ACL ET LES BITS DE PERMISSIONS DE

FICHIER

Les permissions définies par les ACL sont un ensemble supérieur aux permissions spécifiées par les bits de permissions de

fichier.

Il existe une correspondance entre les permissions du propriétaire, du groupe et des autres et des entrées d'ACL spécifiques : les permissions du propriétaire correspondent aux permissions de l'entrée ACL_USER_OBJ. Si l'ACL a une entrée ACL_MASK, les permissions du groupe correspondent aux permissions de l'entrée ACL_MASK. Sinon, si l'ACL n'a pas d'entrée ACL_MASK, les permissions du groupe correspondent aux permissions de l'entrée ACL_GROUP_OBJ. Les permissions des autres correspondent aux permissions de l'entrée

ACL_OTHER.

Les permissions du propriétaire, du groupe et des autres du fichier correspondent toujours aux permissions de l'entré

e d'ACL correspondante. La modification des bits de permissions de fichier entraîne la modification des entrées d'AC
L associées, et la modification de ces entrées d'ACL entraîne la modification des bits de permissions de fichier.

FORMES TEXTUELLES DES

ACL

Une forme longue et une forme courte pour représenter les ACL sont définies. Dans les deux formes, les entrées ACL sont représentées comme trois champs séparés par des deux-points : un type de balise d'entrée ACL, un qualificateur d'entrée ACL et les permissions d'accès discrétionnaires. Le premier champ contient l'un des mots-clés de type de balise d'entrée suivants

:
us

Une entrée ACL user spécifie l'accès accordé au propriétaire du fichier (type de balise d'entrée ACL_USER_OBJ) ou à un utilisateur spécifié (type de balise d'entrée ACL_USER). entrée ACL user spécifie l'accès accordé au propriétaire du fichier (type de balise d'entrée ACL_USER_OBJ) ou à un utilisateur spécifié (type de balise d'entrée ACL_USER)

Une entrée ACL group spécifie l'accès accordé au groupe du fichier (type de balise d'entrée ACL_GROUP_OBJ) ou à un groupe spécifié (type de balise d'entrée ACL_GROUP). entrée ACL group spécifie l'accès accordé au groupe du fichier (type de balise d'entrée ACL_GROUP_OBJ) ou à un groupe spécifié (type de balise d'entrée ACL_GROUP)

Une entrée ACL mask spécifie l'accès maximum qui peut être accordé par n'importe quelle entrée ACL à l'exception de l'entrée entrée ACL mask spécifie l'accès maximum qui peut être accordé par n'importe quelle entrée ACL à l'exception de l'entrée user pour le propriétaire du fichier et de l'entrée other (type de balise d'entrée ACL_MASK)

Le deuxième champ contient l'identifiant utilisateur ou groupe de l'utilisateur ou du groupe associé à l'entrée ACL pour les entrées de type de balise d'entrée ACL_USER ou ACL_GROUP, et est vide pour toutes les autres entrées. Un identifiant utilisateur peut être un nom d'utilisateur ou un numéro d'ID utilisateur sous forme décimale. Un identifiant groupe peut être un nom de groupe ou un numéro de groupe ID sous forme

décimale.

Le troisième champ contient les permissions d'accès discrétionnaires. Les permissions de lecture, d'écriture et de recherche/exécution sont représentées par les caractères r, w et x, dans cet ordre. Chacun de ces caractères est remplacé par le caractère - pour indiquer qu'une permission est absente de l'entrée ACL. Lors de la conversion de la forme textuelle vers la représentation interne, les permissions absentes n'ont pas besoin d'être

spécifiées.

Des espaces blancs sont autorisés au début et à la fin de chaque entrée ACL, et immédiatement avant et après un séparateur de champ (le caractère deux-points)

.

FORME

LONGUE

La forme longue contient une entrée ACL par ligne. De plus, un signe dièse (#) peut commencer un commentaire qui s'étend jusqu'à la fin de la ligne. Si une entrée ACL_USER, ACL_GROUP_OBJ ou ACL_GROUP contient des permissions qui ne sont pas également contenues dans l'entrée ACL_MASK, l'entrée est suivie d'un signe dièse, de la chaîne « effective: » et des permissions d'accès effectives définies par cette entrée. Voici un exemple de la forme longue

: 
user::rw-
user:lisa:rw-
#effective:r-- group::r--
group:toolies:rw- #effec
tive:r-- mask::r-- other::r--

FORME

COURTE

La forme courte est une séquence d'entrées ACL séparées par des virgules, et est utilisée pour l'entrée. Les commentaires ne sont pas pris en charge. Les mots-clés de type de balise d'entrée peuvent apparaître soit sous leur forme complète non abrégée, soit sous leur forme abrégée d'une seule lettre. L'abréviation pour user est u, l'abréviation pour group est g, l'abréviation pour mask est m, et l'abréviation pour other est o. Les permissions peuvent contenir au plus un exemplaire de chacun des caractères suivants, dans n'importe quel ordre : r, w, x. Voici des exemples de la forme courte

:

JUSTIFICATIO

N

Le brouillon 17 de l'IEEE 1003.1e définit les listes de contrôle d'accès qui incluent des entrées de type de balise ACL_MASK, et définit un mappage entre les bits de permission de

fichier qui n'est pas constant. Le groupe de travail standard a défini cette interface relativement complexe afin de s'assurer que les applications conformes à l'IEEE 1003.1 (« POS
IX.1 ») fonctionneront toujours comme prévu sur les systèmes avec ACL. Le brouillon 17 de l'IEEE 1003.1e contient la justification du choix de cette interface dans la section B.23.

MODIFICATIONS AUX UTILITAIRES DE

FICHIERS

Sur un système qui prend en charge les ACL, les utilitaires de fichiers ls(1), cp(1) et mv(1) modifient leur comportement de la manière suivante

:
  • Pour les fichiers qui ont une ACL par défaut ou une ACL d'accès qui contient plus que les trois entrées ACL requises, l'utilitaire ls(1) dans la forme longue produite par ls -l affiche un signe plus (+) après la chaîne de
    • permissions.
  • Si l'option -p est spécifiée, l'utilitaire cp(1) préserve également les ACL. Si cela n'est pas possible, un avertissement est
    • produit.

  • L'utilitaire mv(1) préserve toujours les ACL. Si cela n'es
    • t pas possible, un aver

NORME

S

Le document brouillon 17 de l'IEEE 1003.1e (« POSIX.1e ») décrit plusieurs extensions de sécurité à la norme IEEE 1003.1. Bien que le travail sur 1003.1e ait été abandonné, de nombreux systèmes de type UNIX implémentent des parties du brouillon 17 de POSIX.1e, ou de brouillons

antérieurs.

Les listes de contrôle d'accès Linux implémentent l'ensemble complet des fonctions et utilitaires définis pour les listes de contrôle d'accès dans POSIX.1e, et plusieurs extensions. L'implémentation est entièrement conforme au brouillon 17 de POSIX.1e ; les extensions sont marquées comme telles. Les fonctions de manipulation des listes de contrôle d'accès sont définies dans la bibliothèque ACL (libacl, -lacl). Les interfaces conformes à POSIX sont déclarées dans l'en-tête <sys/acl.h>. Les extensions spécifiques à Linux de ces fonctions sont déclarées dans l'en-tête <acl/lib

acl
.h>.
