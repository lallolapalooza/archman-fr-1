ACCESS(5) Manuel des formats de fichiers ACCESS(5)

NOM

access — table d'accès du serveur SMTP Postfix

SYNOPSIS

postmap /etc/postfix/access
postmap -q "chaîne" /etc/postfix/access
postmap -q - /etc/postfix/access <fichier_entrée

DESCRIPTION


Ce document décrit le contrôle d'accès sur les informations des clients SMTP distants : noms d'hôtes, adresses réseau et adresses d'expéditeur ou de destinataire de l'enveloppe ; il est mis en œuvre par le serveur SMTP Postfix. Voir header_checks(5) ou body_checks(5) pour le contrôle d'accès sur le contenu des messages électroniques.

Normalement, la table access(5) est spécifiée sous forme de fichier texte qui sert d'entrée à la commande postmap(1) . Le résultat, un fichier indexé au format dbm ou db , est utilisé pour la recherche rapide par le système de messagerie. Exécutez la commande «postmap /etc/postfix/access» pour reconstruire un fichier indexé après avoir modifié le fichier texte correspondant.

Lorsque la table est fournie par d'autres moyens tels que NIS, LDAP ou SQL, les mêmes recherches sont effectuées que pour les fichiers indexés ordinaires.

Alternativement, la table peut être fournie sous forme de table d'expressions régulières où les motifs sont donnés sous forme d'expressions régulières, ou les recherches peuvent être dirigées vers un serveur basé sur TCP. Dans ces cas, les recherches sont effectuées de manière légèrement différente, comme décrit ci-dessous sous « TABLES D'EXPRESSIONS RÉGULIÈRES » ou « TABLES BASÉES SUR TCP ».

CASSE DES CARACTÈRES

La chaîne de recherche est convertie en minuscules avant la recherche dans la base de données. Depuis Postfix 2.3, la chaîne de recherche n'est pas convertie en minuscules avec les types de bases de données tels que regexp: ou pcre: dont les champs de recherche peuvent correspondre aux majuscules et aux minuscules.

FORMAT DE LA TABLE

Le format d'entrée pour la commande postmap(1) est le suivant :

motif action
Lorsque motif correspond à une adresse de courrier électronique, un domaine ou une adresse d'hôte, effectuez l' actioncorrespondante.
lignes vides et commentaires
Les lignes vides et les lignes ne contenant que des espaces sont ignorées, tout comme les lignes dont le premier caractère non blanc est un « # ».
texte multi-lignes
Une ligne logique commence par du texte non blanc. Une ligne qui commence par des espaces continue une ligne logique.

MOTIFS D'ADRESSES DE COURRIER ÉLECTRONIQUE DANS LES TABLES INDEXÉES

Avec les recherches à partir de fichiers indexés tels que DB ou DBM, ou à partir de tables en réseau telles que NIS, LDAP ou SQL, les motifs sont essayés dans l'ordre listé ci-dessous :

utilisateur@domaine
Correspond à l'adresse de courrier électronique spécifiée.
domaine.tld
Correspond à domaine.tld en tant que partie de domaine d'une adresse de courrier électronique.

Le motif domaine.tld correspond également aux sous-domaines, mais seulement lorsque la chaîne smtpd_access_maps est listée dans le paramètre de configuration Postfix parent_domain_matches_subdomains .

.domaine.tld
Correspond aux sous-domaines de domaine.tld, mais seulement lorsque la chaîne smtpd_access_maps n'est pas listée dans le paramètre de configuration Postfix parent_domain_matches_subdomains .
utilisateur@
Correspond à toutes les adresses de courrier électronique avec la partie utilisateur spécifiée.

Remarque : la recherche de l'adresse d'expéditeur nul n'est pas possible avec certains types de table de recherche. Par défaut, Postfix utilise <> comme clé de recherche pour de telles adresses. La valeur est spécifiée avec le paramètre smtpd_null_access_lookup_key dans le fichier Postfix main.cf .

EXTENSION D'ADRESSE DE COURRIER ÉLECTRONIQUE

Lorsque la partie locale d'une adresse de courrier électronique contient le délimiteur de destinataire facultatif (par exemple, utilisateur+foo@domaine), l'ordre de recherche devient : utilisateur+foo@domaine, utilisateur@domaine, domaine, utilisateur+foo@, et utilisateur@.

MOTIFS DE NOM/ADRESSE D'HÔTE DANS LES TABLES INDEXÉES

Avec les recherches à partir de fichiers indexés tels que DB ou DBM, ou à partir de tables en réseau telles que NIS, LDAP ou SQL, les motifs de recherche suivants sont examinés dans l'ordre listé :

domaine.tld
Correspond à domaine.tld.

Le motif domaine.tld correspond également aux sous-domaines, mais seulement lorsque la chaîne smtpd_access_maps est listée dans le paramètre de configuration Postfix parent_domain_matches_subdomains .

.domaine.tld
Correspond aux sous-domaines de domaine.tld, mais seulement lorsque la chaîne smtpd_access_maps n'est pas listée dans le paramètre de configuration Postfix parent_domain_matches_subdomains .
net.work.addr.ess
net.work.addr
net.work
net
Correspond à une adresse d'hôte IPv4 distante ou à une plage d'adresses réseau. Spécifiez un à quatre octets décimaux séparés par « . ». Ne spécifiez pas « [] », « / », de zéros de tête ou de formes hexadécimales.

Les plages réseau sont correspondues en tronquant à plusieurs reprises le dernier « .octet » d'une chaîne d'adresse d'hôte IPv4 distante, jusqu'à ce qu'une correspondance soit trouvée dans la table d'accès, ou jusqu'à ce qu'une troncature supplémentaire ne soit plus possible.

REMARQUE : utilisez le type de table de recherche cidr pour spécifier des motifs réseau/masque réseau. Voir cidr_table(5) pour les détails.

net:work:addr:ess
net:work:addr
net:work
net
Correspond à une adresse d'hôte IPv6 distante ou à une plage d'adresses réseau. Spécifiez trois à huit paires d'octets hexadécimaux séparées par « : », en utilisant la forme compressée « :: » pour une séquence de paires d'octets de valeur nulle. Ne spécifiez pas « [] », « / », de zéros de tête ou de formes non compressées.

Une plage réseau est correspondue en tronquant à plusieurs reprises la dernière « :pairedoctets » d'une chaîne d'adresse d'hôte IPv6 distante sous forme compressée, jusqu'à ce qu'une correspondance soit trouvée dans la table d'accès, ou jusqu'à ce qu'une troncature supplémentaire ne soit plus possible.

REMARQUE : utilisez le type de table de recherche cidr pour spécifier des motifs réseau/masque réseau. Voir cidr_table(5) pour les détails.

Le support IPv6 est disponible dans Postfix 2.2 et versions ultérieures.

ACTIONS D'ACCEPTATION

OK
Accepte l'adresse etc. qui correspond au motif.
all-numerical
Un résultat entièrement numérique est traité comme OK. Ce format est généré par des schémas d'autorisation de relais basés sur l'adresse tels que pop-before-smtp.

Pour les autres actions d'acceptation, voir « AUTRES ACTIONS » ci-dessous.

ACTIONS DE REJET

Postfix version 2.3 et versions ultérieures prennent en charge les codes de statut améliorés tels que définis dans la RFC 3463. Lorsqu'aucun code n'est spécifié au début du texte ci-dessous, Postfix insère un code de statut amélioré par défaut de « 5.7.1 » dans le cas des actions de rejet, et « 4.7.1 » dans le cas des actions de report. Voir « CODES DE STATUT AMÉLIORÉS » ci-dessous.

4NN texte
5<NN texte
Rejettez l'adresse, etc., qui correspond au modèle, et répondez avec le code numérique à trois chiffres et le texte. 4NN signifie « réessayez plus tard », tandis que 5NN signifie « n'essayez plus ».

Les réponses suivantes ont une signification spéciale pour le serveur SMTP Postfix :

421 texte (Postfix 2.3 et versions ultérieures)
521 texte (Postfix 2.6 et versions ultérieures)
Après avoir répondu avec le code numérique à trois chiffres et le texte, déconnectez-vous immédiatement du client SMTP. Cela libère les ressources du serveur SMTP afin qu'elles puissent être mises à la disposition d'un autre client SMTP.
Remarque : La réponse « 521 » ne doit être utilisée qu'avec les botnets et autres logiciels malveillants pour lesquels l'interopérabilité n'a aucune importance. Le comportement « envoyer 521 et se déconnecter » n'est PAS défini dans la norme SMTP.
REJECT texte facultatif...
Rejette l'adresse, etc., qui correspond au modèle. Répondez avec « $access_map_reject_code texte facultatif... » lorsque le texte facultatif est spécifié, sinon répondez avec un message de réponse d'erreur générique.
DEFER texte facultatif...
Rejette l'adresse, etc., qui correspond au modèle. Répondez avec « $access_map_defer_code texte facultatif... » lorsque le texte facultatif est spécifié, sinon répondez avec un message de réponse d'erreur générique.

Cette fonctionnalité est disponible dans Postfix 2.6 et versions ultérieures.

DEFER_IF_REJECT texte facultatif...
Diffère la requête si une restriction ultérieure entraînerait une action REJET. Répondez avec « $access_map_defer_code 4.7.1 texte facultatif... » lorsque le texte facultatif est spécifié, sinon répondez avec un message de réponse d'erreur générique.

Avant Postfix 2.6, le code de réponse SMTP est 450.

Cette fonctionnalité est disponible dans Postfix 2.1 et versions ultérieures.

DEFER_IF_PERMIT texte facultatif...
Diffère la requête si une restriction ultérieure entraînerait une action PERMET explicite ou implicite. Répondez avec « $access_map_defer_code 4.7.1 texte facultatif... » lorsque le texte facultatif est spécifié, sinon répondez avec un message de réponse d'erreur générique.

Avant Postfix 2.6, le code de réponse SMTP est 450.

Cette fonctionnalité est disponible dans Postfix 2.1 et versions ultérieures.

Pour les autres actions de rejet, voir « AUTRES ACTIONS » ci-dessous.

AUTRES ACTIONS

restriction...
Appliquez la ou les restrictions UCE nommées (permit, reject, reject_unauth_destination, etc.).
BCC utilisateur@domaine
Envoyez une copie du message au destinataire spécifié.

Si plusieurs actions BCC sont spécifiées au cours de la même transaction MAIL SMTP, seule la dernière action sera utilisée avec Postfix 3.0.

Cette fonctionnalité est disponible dans Postfix 3.0 et versions ultérieures.

DISCARD texte facultatif...
Confirmez la livraison réussie et supprimez silencieusement le message. Enregistrez le texte facultatif s'il est spécifié, sinon enregistrez un message générique.

Remarque : cette action affecte actuellement tous les destinataires du message. Pour supprimer un seul destinataire sans supprimer l'intégralité du message, utilisez la table transport(5) pour diriger le courrier vers le service discard(8).

Cette fonctionnalité est disponible dans Postfix 2.0 et versions ultérieures.

DUNNO
Faites comme si la clé de recherche n'avait pas été trouvée. Cela empêche Postfix d'essayer des sous-chaînes de la clé de recherche (comme un nom de sous-domaine ou un sous-réseau d'adresse réseau).

Cette fonctionnalité est disponible dans Postfix 2.0 et versions ultérieures.

FILTER transport:destination
Après la mise en file d'attente du message, envoyez l'intégralité du message via le filtre de contenu externe spécifié. Le nom de transport spécifie le premier champ d'une définition d'agent de livraison de courrier dans master.cf ; la syntaxe de la destination de saut suivant est décrite dans la page de manuel de l'agent de livraison correspondant. Plus d'informations sur les filtres de contenu externes se trouvent dans le fichier FILTER_README de Postfix.

Remarque 1 : n'utilisez pas les substitutions d'expressions régulières $nombre pour transport ou destination à moins de savoir que l'information provient d'une source fiable.

Remarque 2 : cette action remplace le paramètre content_filter de main.cf et affecte tous les destinataires du message. Si plusieurs actions FILTER sont déclenchées, seule la dernière est exécutée.

Remarque 3 : le but de la commande FILTER est de remplacer le routage du message. Pour remplacer le transport du destinataire mais pas la destination de saut suivant, spécifiez une destination de filtre vide (Postfix 2.7 et versions ultérieures), ou spécifiez un transport:destination qui livre via une instance Postfix différente (Postfix 2.6 et versions antérieures). D'autres options consistent à utiliser les fonctionnalités transport_maps dépendantes du destinataire ou sender_dependent_default_transport_maps dépendantes de l'expéditeur.

Cette fonctionnalité est disponible dans Postfix 2.0 et versions ultérieures.

HOLD texte facultatif...
Placez le message dans la file d'attente hold, où il restera jusqu'à ce que quelqu'un le supprime ou le libère pour livraison. Enregistrez le texte facultatif s'il est spécifié, sinon enregistrez un message générique.

Les courriers mis en attente peuvent être examinés avec la commande postcat(1), et peuvent être détruits ou libérés avec la commande postsuper(1).

Remarque : utilisez « postsuper -r » pour libérer les courriers qui ont été maintenus en attente pendant une fraction significative de $maximal_queue_lifetime ou $bounce_queue_lifetime, ou plus longtemps. Utilisez « postsuper -H » uniquement pour les courriers qui n'expireront pas dans les quelques tentatives de livraison.

Remarque : cette action affecte actuellement tous les destinataires du message.

Cette fonctionnalité est disponible dans Postfix 2.0 et versions ultérieures.

PREPEND nom_en_tete: valeur_en_tete
Ajoutez l'en-tête de message spécifié au début du message. Lorsque plusieurs actions PREPEND sont exécutées, le premier en-tête ajouté apparaît avant le deuxième en-tête ajouté, etc.

Remarque : cette action doit s'exécuter avant la réception du contenu du message ; elle ne peut pas s'exécuter dans le contexte de smtpd_end_of_data_restrictions.

Cette fonctionnalité est disponible dans Postfix 2.1 et versions ultérieures.

REDIRECT utilisateur@domaine
Après la mise en file d'attente du message, envoyez le message à l'adresse spécifiée au lieu du ou des destinataires prévus. Lorsque plusieurs actions REDIRECT sont déclenchées, seule la dernière prend effet.

Remarque 1 : cette action remplace l'action FILTER et, actuellement, remplace tous les destinataires du message.

Remarque 2 : une adresse REDIRECT est soumise à la canonicalisation (ajout du domaine manquant) mais N'EST PAS soumise aux mappages d'alias canoniques, de masquage, bcc ou virtuels.

Cette fonctionnalité est disponible dans Postfix 2.1 et versions ultérieures.

INFO texte facultatif...
Enregistrez un enregistrement d'information avec le texte facultatif, ainsi que les informations du client et, si disponibles, les informations helo, expéditeur, destinataire et protocole.

Cette fonctionnalité est disponible dans Postfix 3.0 et versions ultérieures.

WARN texte facultatif...
Enregistrez un avertissement avec le texte facultatif, ainsi que les informations du client et, si disponibles, les informations helo, expéditeur, destinataire et protocole.

Cette fonctionnalité est disponible dans Postfix 2.1 et versions ultérieures.

CODES DE STATUT AMÉLIORÉS

Postfix version 2.3 et ultérieures prend en charge les codes de statut améliorés tels que définis dans la RFC 3463. Lorsqu'un code de statut amélioré est spécifié dans une table d'accès, il est sujet à modification. Les transformations suivantes sont nécessaires lorsque la même table d'accès est utilisée pour les restrictions d'accès client, helo, expéditeur ou destinataire ; elles se produisent indépendamment du fait que Postfix réponde à une commande MAIL FROM, RCPT TO ou une autre commande SMTP.

  • Lorsqu'une adresse d'expéditeur correspond à une action REJET, le serveur SMTP Postfix transformera un statut DSN de destinataire (par exemple, 4.1.1-4.1.6) en statut DSN d'expéditeur correspondant, et vice versa.
  • Lorsque des informations non liées à une adresse correspondent à une action REJET (telles que l'argument de la commande HELO ou le nom d'hôte/adresse du client), le serveur SMTP Postfix transformera un statut DSN d'expéditeur ou de destinataire en un statut DSN générique non lié à une adresse (par exemple, 4.0.0).

TABLES D'EXPRESSIONS RÉGULIÈRES

Cette section décrit comment les recherches dans les tables changent lorsque la table est donnée sous forme d'expressions régulières. Pour une description de la syntaxe des tables de recherche d'expressions régulières, voir regexp_table(5) ou pcre_table(5).

Chaque modèle est une expression régulière qui est appliquée à l'intégralité de la chaîne recherchée. Selon l'application, cette chaîne est un nom d'hôte client complet, une adresse IP client complète ou une adresse électronique complète. Ainsi, aucune recherche de domaine parent ou de réseau parent n'est effectuée, les adresses électroniques utilisateur@domaine ne sont pas décomposées en leurs parties constitutives utilisateur@ et domaine, ni utilisateur+foo décomposé en utilisateur et foo.

Les modèles sont appliqués dans l'ordre spécifié dans la table, jusqu'à ce qu'un modèle soit trouvé qui corresponde à la chaîne de recherche.

Les actions sont les mêmes qu'avec les recherches dans des fichiers indexés, avec la fonctionnalité supplémentaire que les sous-chaînes entre parenthèses du modèle peuvent être interpolées sous forme de $1, $2, etc.

TABLES BASÉES SUR TCP

TABLES BASÉES SUR TCP

Cette section décrit comment les recherches dans les tables changent lorsque les recherches sont dirigées vers un serveur basé sur TCP. Pour une description du protocole de recherche client/serveur TCP, voir tcp_table(5). Cette fonctionnalité n'est pas disponible jusqu'à et y compris la version 2.4 de Postfix.

Chaque opération de recherche utilise l'ensemble de la chaîne de requête une seule fois. Selon l'application, cette chaîne est un nom d'hôte client complet, une adresse IP client complète ou une adresse de courrier complète. Ainsi, aucune recherche de domaine parent ou de réseau parent n'est effectuée, user@domain les adresses de courrier ne sont pas user@ et domain décomposées en leurs parties constituantes user+foo , et user n'est pas non plus décomposé en foo.

Les actions sont les mêmes que pour les recherches dans des fichiers indexés.

EXEMPLE

L'exemple suivant utilise un fichier indexé, de sorte que l'ordre des entrées de la table n'a pas d'importance. L'exemple autorise l'accès par le client à l'adresse 1.2.3.4 mais rejette tous les autres clients dans 1.2.3.0/24. Au lieu de hash tables de recherche, certains systèmes utilisent dbm. Utilisez la commande "postconf -m" pour découvrir quelles tables de recherche Postfix prend en charge sur votre système.

/etc/postfix/main.cf:
    smtpd_client_restrictions =
        check_client_access hash:/etc/postfix/access
/etc/postfix/access:
    1.2.3   REJECT
    1.2.3.4 OK

Exécutez la commande "postmap /etc/postfix/access" après avoir modifié le fichier.

BOGUES


Le format de table ne comprend pas les conventions de guillemets.
