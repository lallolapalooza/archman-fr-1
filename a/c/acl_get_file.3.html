ACL_GET_FILE(3) Manuel des fonctions de bibliothèque ACL_GET_FILE(3)

NOM

acl_get_file — obtenir une ACL par nom de fichier

BIBLIOTHÈQUE

Bibliothèque des listes de contrôle d'accès de Linux (libacl, -lacl).

SYNTAXE

#include <sys/types.h>
#include <sys/acl.h>

acl_t
acl_get_file(const char *path_p, acl_type_t type);

DESCRIPTION

La fonction acl_get_file() récupère l'ACL d'accès associée à un fichier ou un répertoire, ou l'ACL par défaut associée à un répertoire. Le nom de chemin du fichier ou du répertoire est pointé par l'argument path_p. L'ACL est placée dans l'espace de travail et acl_get_file() renvoie un pointeur vers cet espace.

Afin de lire une ACL à partir d'un objet, un processus doit avoir les droits d'accès en lecture aux attributs de l'objet.

La valeur de l'argument type est utilisée pour indiquer si l'ACL d'accès ou l'ACL par défaut associée à path_p est renvoyée. Si type est ACL_TYPE_ACCESS, l'ACL d'accès de path_p est renvoyée. Si type est ACL_TYPE_DEFAULT, l'ACL par défaut de path_p est renvoyée. Si type est ACL_TYPE_DEFAULT et qu'aucune ACL par défaut n'est associée au répertoire path_p, alors une ACL contenant zéro entrée ACL est renvoyée. Si type spécifie un type d'ACL qui ne peut pas être associé à path_p, alors la fonction échoue.

Cette fonction peut allouer de la mémoire. L'appelant doit libérer toute mémoire libérable, lorsque la nouvelle ACL n'est plus requise, en appelant acl_free(3) avec le (void*)acl_t renvoyé par acl_get_file() comme argument.

VALEUR DE RETOUR

En cas de succès, cette fonction renvoie un pointeur vers l'espace de travail. En cas d'erreur, la valeur (acl_t)NULL est renvoyée, et errno est définie de manière appropriée.

ERREURS

Si l'une des conditions suivantes se produit, la fonction acl_get_file() renvoie une valeur de (acl_t)NULL et définit errno en conséquence :

[EACCES]
La permission de recherche est refusée pour un composant du préfixe de chemin ou l'objet existe et le processus n'a pas les droits d'accès appropriés.

L'argument type spécifie un type d'ACL qui ne peut pas être associé à path_p.

[EINVAL]
L'argument type n'est ni ACL_TYPE_ACCESS ni ACL_TYPE_DEFAULT.
[ENAMETOOLONG]
La longueur de l'argument path_p est trop longue.
[ENOENT]
L'objet nommé n'existe pas ou l'argument path_p pointe vers une chaîne vide.
[ENOMEM]
L'espace de travail de l'ACL nécessite plus de mémoire que ce qui est autorisé par les contraintes de gestion de la mémoire imposées par le matériel ou le système.
[ENOTDIR]
Un composant du préfixe de chemin n'est pas un répertoire.
[ENOTSUP]
Le système de fichiers sur lequel se trouve le fichier identifié par path_p ne prend pas en charge les ACL, ou les ACL sont désactivées.

NORMES

IEEE Std 1003.1e draft 17 (“POSIX.1e”, abandonné)
