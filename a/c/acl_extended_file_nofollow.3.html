acl_extended_file_nofollow(3)

Paquet: acl

Licences: LGPL

ACL_EXTENDED_FILE(3) Manuel des fonctions de bibliothèque ACL_EXTENDED_FILE(3)

NOM

acl_extended_file, acl_extended_file_nofollow — teste les informations dans les ACL par nom de fichier

BIBLIOTHÈQUE

Bibliothèque des listes de contrôle d'accès Linux (libacl, -lacl).

SYNOPIS

#include <sys/types.h>
#include <acl/libacl.h>

int
acl_extended_file(const char *path_p);

int
acl_extended_file_nofollow(const char *path_p);

DESCRIPTION

La fonction acl_extended_file() retourne 1 si le fichier ou le répertoire désigné par l'argument path_p est associé à une ACL d'accès étendue, ou si le répertoire désigné par path_p est associé à une ACL par défaut. La fonction retourne 0 si le fichier n'a ni ACL d'accès étendue ni ACL par défaut.

Une ACL étendue est une ACL qui contient des entrées autres que les trois entrées requises des types d'étiquettes ACL_USER_OBJ, ACL_GROUP_OBJ et ACL_OTHER. Si le résultat de la fonction acl_extended_file() pour un objet fichier est 0, alors les ACL ne définissent aucun droit d'accès discrétionnaire autre que ceux déjà définis par les bits de permission traditionnels du fichier.

L'accès à l'objet fichier peut être limité davantage par d'autres mécanismes, tels que les schémas de contrôle d'accès obligatoire. L'appel système access(2) peut être utilisé pour vérifier si un type d'accès donné à un objet fichier serait accordé.

acl_extended_file_nofollow() est identique à acl_extended_file(), sauf dans le cas d'un lien symbolique, où le lien lui-même est interrogé, et non le fichier auquel il se réfère. Puisque les liens symboliques n'ont pas d'ACL eux-mêmes, l'opération est censée échouer sur eux.

VALEUR DE RETOUR

En cas de succès, la fonction acl_extended_file() retourne 1 si l'objet fichier désigné par path_p a une ACL d'accès étendue ou une ACL par défaut, et 0 si l'objet fichier désigné par path_p n'a ni ACL d'accès étendue ni ACL par défaut. Sinon, la valeur -1 est retournée et la variable globale errno est définie pour indiquer l'erreur.

ERREURS

Si l'une des conditions suivantes se produit, la fonction acl_extended_file() retourne -1 et définit errno à la valeur correspondante :

[EACCES]
Le droit de recherche est refusé pour un composant du préfixe du chemin.
[ENAMETOOLONG]
La longueur de l'argument path_p est trop longue.
[ENOENT]
L'objet nommé n'existe pas ou l'argument path_p pointe vers une chaîne vide.
[ENOTDIR]
Un composant du préfixe du chemin n'est pas un répertoire.
[ENOTSUP]
Le système de fichiers sur lequel se trouve le fichier identifié par path_p ne prend pas en charge les ACL, ou les ACL sont désactivées.

NORMES

Il s'agit d'une extension non portable et spécifique à Linux des fonctions de manipulation d'ACL définies dans la version brouillon 17 de IEEE Std 1003.1e (“POSIX.1e”, abandonnée).

VOIR AUSSI

access(2), acl_get_file(3), acl(5)
