Paramètres de contrôle d'exécution :
  -P stratégie  - définir la stratégie de mutation fixe : explore (se concentrer
                  sur une nouvelle couverture), exploit (se concentrer sur le
                  déclenchement de crashes). Vous pouvez également définir un
                  nombre de secondes après lesquelles, sans aucune découverte,
                  il bascule en mode exploit, et inversement sur nouvelle
                  couverture (par défaut : 1000)
  -p planification - les planifications de puissance calculent un score de
                  performance d'une graine : explore (par défaut), fast,
                  exploit, seek, rare, mmopt, coe, lin, quad -- voir
                  docs/FAQ.md pour plus d'informations
  -f fichier    - emplacement lu par le programme fuzzé (par défaut : stdin ou
                  @@)
  -t msec       - délai d'attente pour chaque exécution (auto-ajusté, par
                  défaut 1000 ms). Ajoutez un '+' pour auto-calculer le délai
                  d'attente, la valeur étant le maximum.
  -m megs       - limite mémoire pour le processus enfant (0 Mo, 0 = pas de
                  limite [par défaut])
  -O            - utiliser l'instrumentation binaire uniquement (mode FRIDA)
  -Q            - utiliser l'instrumentation binaire uniquement (mode QEMU)
  -U            - utiliser l'instrumentation basée sur unicorn (mode Unicorn)
  -W            - utiliser l'instrumentation basée sur qemu avec Wine (mode
                  Wine)
  -X            - utiliser le fuzzing de VM (mode NYX - mode autonome)
  -Y            - utiliser le fuzzing de VM (mode NYX - mode instances
                  multiples)
Paramètres du mutateur :
  -a type       - format d'entrée cible, "text" ou "binary" (par défaut :
                  générique)
  -g longmin    - définir la longueur minimale de l'entrée fuzzée générée (par
                  défaut : 1)
  -G longmax    - définir la longueur maximale de l'entrée fuzzée générée (par
                  défaut : 1048576)
  -L minutes    - utiliser le mode MOpt(imize) et définir la limite de temps
                  pour entrer en mode pacemaker (minutes sans nouvelle
                  découverte). 0 = immédiatement, -1 = immédiatement et
                  ensemble avec la mutation normale.
                  Remarque : cette option n'est généralement pas très efficace
  -u            - activer le splice de cas de test
  -c programme  - activer CmpLog en spécifiant un binaire compilé pour cela.
                  Si vous utilisez QEMU/FRIDA ou si la cible de fuzzing est
                  compilée pour CmpLog, utilisez '-c 0'. Pour désactiver CMPLOG
                  utilisez '-c -'.
  -l opts_cmplog - valeurs de configuration de CmpLog (ex. "2ATR") :
                  1=petits fichiers, 2=fichiers plus grands (par défaut),
                  3=tous les fichiers, A=résolution arithmétique,
                  T=résolution transformationnelle, X=résolution de
                  transformation extrême, R=octets de colorisation aléatoires.
Paramètres de comportement du fuzzing :
  -Z            - sélection séquentielle de la file d'attente au lieu d'un
                  aléatoire pondéré
  -N            - ne pas supprimer le fichier d'entrée fuzzé (pour les
                  périphériques, etc.)
  -n            - fuzz sans instrumentation (mode non instrumenté)
  -x dict_fichier - dictionnaire du fuzzer (voir README.md, spécifiable jusqu'à
                  4 fois)
  -w san_binaire - Spécifier les binaires instrumentés par les sanitizers
                   supplémentaires, peut être spécifié plusieurs fois.
                   Lire docs/SAND.md pour les détails.
Paramètres de test :
  -s graine     - utiliser une graine fixe pour le GNA
  -V secondes   - fuzz pendant un temps spécifié puis terminer (temps de fuzz
                  uniquement !)
  -E execs      - fuzz pendant un nombre approx. total d'exécutions puis
                  terminer
                  Remarque : pas précis et peut avoir plusieurs exécutions de
                  plus.
Autres choses :
  -M/-S id      - mode distribué (-M définit -Z et désactive le trimming)
                  voir docs/fuzzing_in_depth.md#c-using-multiple-cores
                  pour des recommandations efficaces pour le fuzzing parallèle.
  -F chemin     - synchroniser avec un répertoire de file d'attente d'un fuzzer
                  tiers (nécessite -M, peut être spécifié jusqu'à 32 fois)
  -z            - ignorer le fuzzing déterministe amélioré
                  (notez que les anciens drapeaux -d et -D sont ignorés.)
  -T texte      - bannière texte à afficher à l'écran
  -I commande   - exécuter cette commande/script lorsqu'un nouveau crash est
                  trouvé
  -C            - mode d'exploration de crash (le truc du lapin péruvien)
  -b cpu_id     - lier le processus de fuzzing au cœur CPU spécifié (0-...)
  -e ext        - extension de fichier pour le fichier d'entrée de test de
                  fuzz (si nécessaire)
Variables d'environnement utilisées :
LD_BIND_LAZY : ne pas définir la variable d'environnement LD_BIND_NOW pour la cible
ASAN_OPTIONS : paramètres personnalisés pour ASAN
               (doit contenir abort_on_error=1 et symbolize=0)
MSAN_OPTIONS : paramètres personnalisés pour MSAN
               (doit contenir exitcode=86 et symbolize=0)
AFL_AUTORESUME : reprendre le fuzzing si le répertoire spécifié par -o existe déjà
AFL_BENCH_JUST_ONE : exécuter la cible juste une fois
AFL_BENCH_UNTIL_CRASH : quitter rapidement dès que la première entrée provoquant un crash a été trouvée
AFL_CMPLOG_ONLY_NEW : ne pas exécuter cmplog sur les cas de test initiaux (utile pour les reprises !)
AFL_CRASH_EXITCODE : code de sortie enfant optionnel à interpréter comme un crash
AFL_CUSTOM_MUTATOR_LIBRARY : lib avec afl_custom_fuzz() pour muter les entrées
AFL_CUSTOM_MUTATOR_ONLY : éviter les mutateurs internes d'AFL++
AFL_CYCLE_SCHEDULES : après avoir complété un cycle, passer à une planification -p différente
AFL_DEBUG : sortie de débogage supplémentaire pour le trimming en mode Python
AFL_DEBUG_CHILD : ne pas supprimer stdout/stderr de la cible
AFL_DISABLE_REDUNDANT : désactiver tout élément de file d'attente qui est redondant
AFL_DISABLE_TRIM : désactiver le trimming des cas de test
AFL_DUMB_FORKSRV : utiliser le fork server sans retour d'information de la cible
AFL_EXIT_WHEN_DONE : quitter lorsque toutes les entrées sont exécutées et qu'aucune nouvelle découverte n'est trouvée
AFL_EXIT_ON_TIME : quitter lorsqu'aucune nouvelle couverture n'est trouvée dans le temps spécifié
AFL_EXIT_ON_SEED_ISSUES : quitter sur tout type de problème de graine
AFL_EXPAND_HAVOC_NOW : activer immédiatement le mode expand havoc (par défaut : après 60 minutes et un cycle sans découvertes)
AFL_FAST_CAL : limiter l'étape de calibration à trois cycles pour accélérer
AFL_FORCE_UI : forcer l'affichage de l'écran de statut (pour les consoles virtuelles)
AFL_FORKSRV_INIT_TMOUT : temps passé à attendre le forkserver pendant le démarrage (en ms)
AFL_HANG_TMOUT : remplacer la valeur du délai d'attente (en millisecondes)
AFL_I_DONT_CARE_ABOUT_MISSING_CRASHES : ne pas avertir des gestionnaires de core dump
AFL_IGNORE_PROBLEMS : ne pas interrompre le fuzzing si une configuration incorrecte est détectée
AFL_IGNORE_PROBLEMS_COVERAGE : si défini en plus de AFL_IGNORE_PROBLEMS - ignorer aussi
                               ces libs pour la couverture
AFL_IGNORE_SEED_PROBLEMS : ignorer les crashes et les timeouts dans les graines au lieu de
                           quitter
AFL_IGNORE_TIMEOUTS : ne pas traiter ni sauvegarder les timeouts
AFL_IGNORE_UNKNOWN_ENVS : ne pas avertir sur les variables d'environnement inconnues
AFL_IMPORT_FIRST : synchroniser et importer les cas de test des autres instances de fuzzer en premier
AFL_INPUT_LEN_MIN/AFL_INPUT_LEN_MAX : comme -g/-G définir la longueur min/max de fuzz produite
AFL_PIZZA_MODE : 1 - forcer le mode pizza, -1 - désactiver pour le 1er avril,
                 0 (par défaut) - activer le 1er avril
AFL_KILL_SIGNAL : ID de signal envoyé aux processus enfants sur timeout, etc.
                  (par défaut : SIGKILL)
AFL_FORK_SERVER_KILL_SIGNAL : Signal d'arrêt pour le fork server à la terminaison
                              (par défaut : SIGTERM). Si non défini et que AFL_KILL_SIGNAL est
                              défini, cette valeur sera utilisée.
AFL_MAP_SIZE : la taille de la mémoire partagée pour cette cible. doit être >= la taille
               pour laquelle la cible a été compilée
AFL_MAX_DET_EXTRAS : si plus d'entrées sont dans la liste du dictionnaire que cette valeur
                     alors elles sont sélectionnées aléatoirement au lieu d'utiliser toutes.
                     Par défaut 200.
AFL_NO_AFFINITY : ne pas vérifier un cœur CPU inutilisé pour le fuzzing
AFL_TRY_AFFINITY : essayer de se lier à un cœur inutilisé, mais ne pas échouer si sans succès
AFL_NO_ARITH : ignorer les mutations arithmétiques dans l'étape déterministe
AFL_NO_AUTODICT : ne pas charger un dictionnaire automatique offert compilé dans une cible
AFL_NO_CPU_RED : éviter la couleur rouge pour montrer une utilisation CPU très élevée
AFL_NO_FORKSRV : exécuter la cible via execve au lieu d'utiliser le forkserver
AFL_NO_SNAPSHOT : ne pas utiliser la fonctionnalité snapshot (si le lkm snapshot est chargé)
AFL_NO_STARTUP_CALIBRATION : pas de calibration initiale de graine, commencer le fuzzing immédiatement
AFL_NO_WARN_INSTABILITY : pas d'avertissement sur les problèmes d'instabilité lors de la calibration au démarrage
AFL_NO_UI : désactiver l'écran de statut
AFL_NYX_AUX_SIZE : taille du tampon auxiliaire Nyx. Doit être un multiple de 4096.
                   Augmentez cette valeur si les rapports de crash sont tronqués.
                   La valeur par défaut est 4096.
AFL_NYX_DISABLE_SNAPSHOT_MODE : désactiver le mode snapshot (doit être supporté par l'agent)
AFL_NYX_LOG : envoyer les messages NYX hprintf vers un autre fichier
AFL_NYX_REUSE_SNAPSHOT : réutiliser un snapshot racine Nyx existant
AFL_PATH : chemin vers les binaires de support d'AFL
AFL_PYTHON_MODULE : muter et trimmer les entrées avec le module Python spécifié
AFL_QUIET : supprimer les messages de statut du forkserver
AFL_POST_PROCESS_KEEP_ORIGINAL : sauvegarder le fichier tel qu'il était avant le post-traitement dans
                                 la file d'attente, mais exécuter celui post-traité
AFL_PRELOAD : paramètres LD_PRELOAD / DYLD_INSERT_LIBRARIES pour la cible
AFL_TARGET_ENV : passer des variables d'environnement supplémentaires à la cible
AFL_SHUFFLE_QUEUE : réordonner la file d'entrée aléatoirement au démarrage
AFL_SKIP_BIN_CHECK : ignorer les vérifications de compatibilité afl, désactive aussi la taille de map auto
AFL_SKIP_CPUFREQ : ne pas avertir de l'horloge CPU variable
AFL_STATSD : active la collecte de métriques StatsD
AFL_STATSD_HOST : changer l'hôte statsd par défaut (par défaut 127.0.0.1)
AFL_STATSD_PORT : changer le port statsd par défaut (par défaut : 8125)
AFL_STATSD_TAGS_FLAVOR : définir le format des tags statsd (par défaut : tags désactivés)
                        formats supportés : dogstatsd, librato, signalfx, influxdb
AFL_NO_FASTRESUME : ne pas lire ni écrire un résumé fichier
AFL_NO_SYNC: désactive toute synchronisation
AFL_SYNC_TIME: temps de synchronisation entre instances de fuzzing (en minutes)
AFL_FINAL_SYNC: synchronise une dernière fois à la sortie (retardera la sortie !)
AFL_NO_CRASH_README: ne crée pas de README dans le répertoire des crashes
AFL_TESTCACHE_SIZE: utilise un cache pour les cas de test, améliore les performances (en Mo)
AFL_TMPDIR: répertoire à utiliser pour la génération des fichiers d'entrée (ramdisk recommandé)
AFL_EARLY_FORKSERVER: force un forkserver précoce dans une cible afl-clang-fast/
                      afl-clang-lto/afl-gcc-fast
AFL_PERSISTENT: force le mode persistant (si __AFL_LOOP est dans une lib partagée)
AFL_DEFER_FORKSRV: force le forkserver différé (__AFL_INIT est dans une lib partagée)
AFL_FUZZER_STATS_UPDATE_INTERVAL: intervalle de mise à jour du fichier fuzzer_stats en
                                  secondes (par défaut : 60, minimum : 1)
Compilé avec le support du module Python 3.13.5, voir docs/custom_mutators.md
Compilé sans support de AFL_PERSISTENT_RECORD.
Compilé avec le support de shmat.
Pour plus d'aide, consultez docs/README.md
