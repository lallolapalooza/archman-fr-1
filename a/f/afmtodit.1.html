Si un glyphe PostScript n'est pas mentionné dans fichier-map,

et qu'un nom de caractère groff ne peut pas être déduit à l'aide de l'Adobe Glyph List (AGL, intégré dans afmtodit), alors afmtodit place le glyphe PostScript dans le fichier de description de police groff en tant que glyphe non nommé qui ne peut être accédé que par la séquence d'échappement « \N » dans un document roff. En particulier, c'est le cas pour les variantes de glyphes nommées sous la forme « foo. bar » ; tous les noms de glyphescontenant un ou plusieurs points sont mappés à des entités non nommées. Sauf si -e est spécifié, l'encodage défini dans le fichier AFM (c'est-à-dire les entrées avec des codes non négatifs) est utilisé. Voir la section « Utilisation des symboles » dans Groff : l'implémentation GNU de troff, le manuel Texinfo de groff, ou groff_char(7) , qui décrivent comment les identifiants de caractères groff sont construits. Diagnostic

s
Le nom AGL 'x' est déjà associé au nom groff 'y' ; nom AGL ignoré 'uniXXX
X'
Vous pouvez ignorer ces messages s'ils sont sous la forme indiquée, où le nom AGL ignoré contient quatre chiffres hexadécimaux XXXX. La liste de glyphes Adobe (AGL) a ses propres noms pour les glyphes ; ils sont souvent différents des noms de caractères spéciaux de groff. afmtodit construit une correspondance à partir des noms de caractères spéciaux de groff vers les noms AGL ; il peut s'agir d'une correspondance un-à-un ou plusieurs-à-un, mais un-à-plusieurs ne fonctionnera pas, donc afmtodit écarte les correspondances superflues. Par exemple, si x est *D, y est Delta, et z est uni0394, afmtodit vous indique que la description de police groff qu'il écrit ne peut pas associer le caractère spécial groff \[*D] aux glyphes AGL Delta et uni0394 en
même
temps.
