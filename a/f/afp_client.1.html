NOM

afp_client - Monter, démonter et contrôler les sessions du protocole de partage de fichiers Apple (AFP) en utilisant l'infrastructure FUSE.

SYNTAXE

afp_client mount|status|unmount|suspend|resume|exit [options]

DESCRIPTION

La commande afp_client vous permet d'effectuer quelques fonctions de base pour accéder aux volumes AFP, telles que monter, démonter, obtenir le statut, suspendre et reprendre.

Ne pas confondre avec afpcmd ; afp_client doit être utilisé uniquement pour le client FUSE, en conjonction avec afpfsd(1). afpcmd est un client de transfert de fichiers en mode batch. Les deux utilisent les bibliothèques afpfs-ng.

afp_mount(1) est normalement un lien symbolique vers afp_client. Il ne gère que les commandes de montage avec une URL AFP entièrement formée.

COMMANDES

mount
Le nom de l'interface. Il s'agit généralement d'un nom de pilote suivi d'un numéro d'unité, par exemple eth0 pour la première interface Ethernet.
mount [options de montage] node
En utilisant les informations d'authentification et de serveur fournies avec les options de montage, monter le système de fichiers distant sur node. Pour plus d'informations, voir les "options de montage" plus loin dans cette page de manuel. Si vous préférez utiliser la syntaxe URL AFP, voir mount_afp(1) pour plus d'informations.
unmount node
Supprimer le montage AFP actuellement connecté à node
status
Afficher les informations de statut de tous les serveurs connectés. Cela fournira des informations sur l'adresse IP des serveurs connectés, les descriptions des serveurs (type de machine, nom de machine, signature, message de connexion) et les volumes disponibles. Il fournit également des statistiques et d'autres détails. Ceci est crucial pour le débogage.
suspend
Suspend, mais ne démonte pas, les connexions actuelles à tous les serveurs actuellement connectés. Actuellement non pris en charge.
resume
Reprend toutes les connexions serveur suspendues. Actuellement non pris en charge. Activer ou désactiver le mode promiscuous de l'interface. Si sélectionné, tous les paquets sur le réseau seront reçus par l'interface.

FLAGS DE MONTAGE

-u, --user <nom_utilisateur>
Se connecter en utilisant <nom_utilisateur>
-p, --pass <mot_de_passe>
Si vous spécifiez un '-' comme mot de passe, il vous sera demandé. Cela vous permet d'utiliser un mot de passe sans avoir à l'exposer sur la ligne de commande.
-o, --port <numéro_de_port>
Utiliser le port TCP num_port au lieu du port par défaut, 548.
-V, --volumepassword <mot_de_passe_volume>
Utiliser ceci si le volume auquel vous accédez utilise un mot de passe de volume (une forme de protection très faible car il est transféré en texte clair). -v, --version <version_afp>
Spécifier la version AFP qui sera utilisée pour un montage. Pour AFP 2.2, utiliser '22', pour 3.2, utiliser '32', etc. Par défaut, afpfs-ng choisira la version AFP la plus élevée partagée entre le client et le serveur. afpfs-ng prend en charge AFP 2.0 jusqu'à 3.2. -a, --uam <uam> Définir la méthode d'authentification, parmi:

No User Authent

Cleartxt Passwrd

Randnum Exchange

2-Way Randnum Exchange

DHCAST128

Client Krb v2

DHX2

Si vous ne spécifiez pas de UAM, le plus sécurisé commun au serveur et au client (afpfs-ng) sera choisi.

-m, --map <uam>
Définir la méthode utilisée pour mapper les UID et GID locaux aux UID et GID du serveur. Les valeurs possibles sont :

Common user directory Ceci devrait être utilisé dans un environnement où l'UID et le GID du client et du serveur sont censés correspondre parfaitement. Un exemple est un serveur NIS ou open directory.

Login ids Utiliser ceci lorsque vous voulez que tous les fichiers apparaissent comme appartenant à l'uid et au gid de l'utilisateur que vous avez utilisé pour vos informations d'authentification.
