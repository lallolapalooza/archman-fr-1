after(n) Commandes intégrées Tcl after(n)

NOM

after - Exécute une commande après un délai

SYNOPIS

after ms

after ms ?script script script ...?

after cancel id

after cancel script script script ...

after idle ?script script script ...?

after info ?id?

DESCRIPTION

Cette commande est utilisée pour retarder l'exécution du programme ou pour exécuter une commande en arrière-plan à un moment donné dans le futur. Elle a plusieurs formes, selon le premier argument de la commande :

after ms
Ms doit être un entier représentant un temps en millisecondes. Un nombre négatif est traité comme 0. La commande se met en veille pendant ms millisecondes puis retourne. Pendant que la commande est en veille, l'application ne répond pas aux événements.
after ms ?script script script ...?
Dans cette forme, la commande retourne immédiatement, mais elle organise l'exécution d'une commande Tcl ms millisecondes plus tard en tant que gestionnaire d'événements. La commande sera exécutée exactement une fois, au moment indiqué. La commande retardée est formée en concaténant tous les arguments script de la même manière que la commande concat. La commande sera exécutée au niveau global (en dehors du contexte d'une procédure Tcl). Si une erreur se produit lors de l'exécution de la commande retardée, l'erreur en arrière-plan sera signalée par la commande enregistrée avec interp bgerror. La commande after retourne un identifiant qui peut être utilisé pour annuler la commande retardée avec after cancel. Une valeur de ms de 0 (ou négative) met en file d'attente l'événement immédiatement avec une priorité supérieure aux autres types d'événements (s'il n'est pas installé avec une procédure d'événement, ce qui attendra le prochain cycle d'événements).
after cancel id
Annule l'exécution d'une commande retardée qui avait été précédemment planifiée. Id indique quelle commande doit être annulée ; il doit s'agir de la valeur de retour d'une commande after précédente. Si la commande donnée par id a déjà été exécutée, la commande after cancel n'a aucun effet.
after cancel script script ...
Cette commande annule également l'exécution d'une commande retardée. Les arguments script sont concaténés avec des séparateurs d'espace (exactement comme dans la commande concat). S'il existe une commande en attente qui correspond à la chaîne, elle est annulée et ne sera jamais exécutée ; si aucune commande de ce type n'est en attente, la commande after cancel n'a aucun effet.
after idle script ?script script ...?
Concatène les arguments script avec des séparateurs d'espace (exactement comme dans la commande concat), et organise l'évaluation du script résultant plus tard en tant que rappel d'inactivité. Le script sera exécuté exactement une fois, la prochaine fois que la boucle d'événements sera entrée et qu'il n'y aura aucun événement à traiter. La commande retourne un identifiant qui peut être utilisé pour annuler la commande retardée en utilisant after cancel. Si une erreur se produit lors de l'exécution du script, l'erreur en arrière-plan sera signalée par la commande enregistrée avec interp bgerror.
after info ?id?
Cette commande retourne des informations sur les gestionnaires d'événements existants. Si aucun argument id n'est fourni, la commande retourne une liste des identifiants de tous les gestionnaires d'événements existants créés par la commande after pour cet interpréteur. Si id est fourni, il spécifie un gestionnaire existant ; id doit avoir été la valeur de retour d'un appel précédent à after et il ne doit pas s'être encore déclenché ni avoir été annulé. Dans ce cas, la commande retourne une liste avec deux éléments. Le premier élément de la liste est le script associé à id, et le second élément est soit idle soit timer pour indiquer le type de gestionnaire d'événements.

Les formes after ms et after idle de la commande supposent que l'application est pilotée par événements : les commandes retardées ne seront pas exécutées à moins que l'application n'entre dans la boucle d'événements. Dans les applications qui ne sont normalement pas pilotées par événements, telles que tclsh, la boucle d'événements peut être entrée avec les commandes vwait et update.

EXEMPLES

Ceci définit une commande pour que Tcl ne fasse rien pendant N secondes :

proc sleep {N} {
    after [expr {int($N * 1000)}]
}

Ceci organise l'exécution de la commande wake_up dans huit heures (à condition que la boucle d'événements soit active à ce moment-là) :

after [expr {1000 * 60 * 60 * 8}] wake_up

La commande suivante peut être utilisée pour effectuer des calculs de longue durée (représentés ici par ::my_calc::one_step, qui est supposé retourner un booléen indiquant si une autre étape doit être effectuée) de manière progressive, bien que le calcul lui-même doive être organisé de manière à pouvoir fonctionner étape par étape. Cette technique est particulièrement prudente pour s'assurer que la boucle d'événements n'est pas bloquée par la replanification des étapes de traitement (en organisant la prochaine étape à faire à l'aide d'un événement de temporisation déjà déclenché uniquement lorsque la file d'attente d'événements a été vidée) et est utile lorsque vous souhaitez vous assurer qu'une interface graphique Tk reste réactive pendant une tâche lente.

proc doOneStep {} {
    if {[::my_calc::one_step]} {
        after idle [list after 0 doOneStep]
    }
}
doOneStep
