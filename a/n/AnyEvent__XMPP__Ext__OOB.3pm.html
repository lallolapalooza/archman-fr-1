NOM

AnyEvent::XMPP::Ext::OOB - Données hors bande XEP-0066

SYNOPIS

my $con = AnyEvent::XMPP::Connection->new (...);
$con->add_extension (my $disco = AnyEvent::XMPP::Ext::Disco->new);
$con->add_extension (my $oob = AnyEvent::XMPP::Ext::OOB->new);
$disco->enable_feature ($oob->disco_feature);
$oob->reg_cb (oob_recv => sub {
   my ($oob, $con, $node, $url) = @_;
   if (got ($url)) {
      $oob->reply_success ($con, $node);
   } else {
      $oob->reply_failure ($con, $node, 'not-found');
   }
});
$oob->send_url (
   $con, 'someonewho@wants.an.url.com', "http://nakedgirls.com/marie_021.jpg",
   "Yaww!!! Hot like SUN!",
   sub {
      my ($error) = @_;
      if ($error) { # alors erreur
      } else { # tout va bien
      }
   }
)

DESCRIPTION

Ce module fournit une abstraction utilitaire pour la gestion des données hors bande comme spécifié dans la XEP-0066.

L'objet généré gère les requêtes de données hors bande, à la fois vers et depuis d'autres entités.

Il existe également quelques fonctions utilitaires pour obtenir, par exemple, les informations oob d'un élément XML :

FONCTIONS

url_from_node ($node)
Cette fonction extrait l'URL et éventuellement un champ de description de l'élément XML dans $node (qui doit être un AnyEvent::XMPP::Node).

$node doit être le nœud XML contenant l'élément <url> et éventuellement l'élément <desc> (qui est, par exemple, un élément <x xmlns='jabber:x:oob'>).

(Cette méthode recherche dans les deux espaces de noms, jabber:x:oob et jabber:iq:oob, les éléments <url> et <desc>).

Elle retourne une référence de hachage qui devrait avoir la structure suivante :

{
   url  => "http://someurl.org/mycoolparty.jpg",
   desc => "That was a party!",
}

Si rien n'est trouvé, cette méthode ne retourne rien (undef).

MÉTHODES

new ()
C'est le constructeur, il ne prend aucun argument supplémentaire.
reply_success ($con, $node)
Cette méthode répond à l'expéditeur de l'oob que l'URL a été récupérée avec succès.

$con et $node sont les arguments $con et $node de l'événement "oob_recv" auquel vous voulez répondre.

reply_failure ($con, $node, $type)
Cette méthode répond à l'expéditeur que le transfert a été rejeté ou qu'il n'a pas été trouvé.

Si le transfert a été rejeté, vous devez définir $type à 'reject', sinon $type doit être 'not-found'.

$con et $node sont les arguments $con et $node de l'événement "oob_recv" auquel vous voulez répondre.

send_url ($con, $jid, $url, $desc, $cb)
Cette méthode envoie une requête de transfert de fichier hors bande à $jid. $url est l'URL que l'autre partie doit télécharger. $desc est une chaîne de description optionnelle (lisible par l'homme) pour le fichier pointé par l'URL et peut être undef si vous ne souhaitez transmettre aucune description.

$cb est un rappel qui sera appelé une fois le transfert réussi.

Le premier argument du rappel sera soit undef en cas de succès, soit 'reject' si l'autre partie a rejeté le fichier, soit 'not-found' si l'autre partie n'a pas pu télécharger le fichier.

ÉVÉNEMENTS

Ces événements peuvent être enregistrés avec "reg_cb" :

oob_recv => $con, $node, $url
Cet événement est généré chaque fois que quelqu'un souhaite vous envoyer un fichier de données hors bande. $url est une référence de hachage similaire à celle retournée par "url_from_node".

$con est la connexion AnyEvent::XMPP::Connection (ou AnyEvent::XMPP::IM::Connection) depuis laquelle les données ont été reçues.

$node est le nœud AnyEvent::XMPP::Node de la requête IQ. Vous pouvez obtenir le JID de l'expéditeur à partir de l'attribut 'from' de celui-ci.

Si vous avez récupéré le fichier avec succès, vous devez appeler "reply_success". Si vous souhaitez rejeter le fichier ou ne pas pouvoir l'obtenir, appelez "reply_failure".
