AnyEvent::Debug::wrap
[$level]
Définit le niveau d'instrumentation/encapsulation de tous les observateurs qui sont créés après cet appel. Si aucun $level n'a été spécifié, il alterne entre 0 et 1.

Le niveau d'encapsulation par défaut est 0, ou la valeur spécifiée par $ENV{PERL_ANYEVENT_DE

BUG_WRAP}.

Un niveau de 0 désactive l'encapsulation, c'est-à-dire qu'AnyEvent fonctionne normalement et dans son mode le plus

efficace.

Un niveau de 1 ou supérieur active l'encapsulation, qui remplace tous les observateurs par des objets AnyEvent::Debug::Wrapped, stocke l'endroit où un observateur a été créé et encapsule le rappel pour journaliser toutes les invocations au niveau de journalisation "trace" si le traçage est activé pour l'observateur. L'état initial du traçage lors de la création d'un observateur est pris à partir de la variable globale $AnyEvent:Debug::TRACE. La valeur par défaut de cette variable est 1, mais il peut être judicieux de la définir à 0 puis de faire "local $AnyEvent::Debug::TRACE = 1" dans un bloc où vous créez des observateurs "intéressants". Le traçage peut aussi être activé et désactivé plus tard en appelant la méthode "trace" de

l'observateur.

L'encapsuleur comptera aussi combien de fois le rappel a été invoqué et enregistrera jusqu'à dix erreurs d'exécution avec les backtraces correspondantes. Il journalisera aussi les erreurs d'exécution au niveau de journalisation

"error".

Pour voir les messages de traçage, vous pouvez invoquer votre programme avec "PERL_ANYEVENT_VERBOSE=9", ou vous pouvez utiliser AnyEvent::Log pour rediriger les messages de traçage comme vous le souhaitez (la section EXEMPLES dans AnyEvent::Log contient quelques exemples)

.

Un niveau de 2 fait tout ce que le niveau 1 fait, mais stocke aussi un backtrace complet de l'endroit où l'observateur a été créé, ce qui ralentit considérablement la création

d'observateurs.

Chaque observateur encapsulé sera lié à %AnyEvent::Debug::Wrapped, avec son adresse comme clé. La commande "wl" dans le shell de débogage peut être utilisée pour lister les

observateurs.

L'instrumentation peut augmenter la taille de chaque observateur de plusieurs fois et, surtout lorsque des backtraces sont impliqués, ralentit aussi beaucoup la création

d'observateurs.

De plus, activer et désactiver l'instrumentation ne récupérera pas les performances complètes que vous aviez avant l'encapsulation (les fonctions AE::xxx resteront plus lentes, par

exemple).

Si vous développez votre programme, env

isagez aussi d'utiliser AnyEvent::Stri
ct pour vérifier les erreurs courantes.

LA CLASSE AnyEvent::Debug::

Wrapped

Tous les observateurs créés pendant que le niveau d'encapsulation est non nul seront encapsulés dans un objet AnyEvent::Debug::Wrapped. L'adresse de l'observateur encapsulé deviendra son ID - chaque observateur sera stocké dans $AnyEvent::Debug::Wra

pped{$id}.

Ces objets encapsuleurs peuvent être convertis en chaîne et ont quelques méthodes définies sur

eux.

Pour le débogage, bien sûr, il peut être utile d'examiner ces objets, c'est pourquoi c'est documenté ici, mais cela pourrait changer à tout moment dans les futures

versions.

Chaque objet est un hash relativement standard avec les membres suivants

: 
type   => nom de la méthode utilisée pour créer l'observateur (par ex. C<io>, C<timer>).
w      => le watcher réel
rfile  => référence vers le nom du fichier dans lequel le watcher a été créé
line   => numéro de ligne où il a été créé
sub    => nom de la fonction (ou une chaîne spéciale) qui a créé le watcher
cur    => si créé à l'intérieur d'un autre callback de watcher, c'est la représentation sous forme de chaîne de l'autre watcher
now    => l'horodatage (AE::now) au moment où le watcher a été créé
arg    => les arguments utilisés pour créer le watcher (sans C<cb>)
cb     => le callback original utilisé pour créer le watcher
called => le nombre de fois où le callback a été
appelé

Chaque objet prend en charge les méthodes suivantes (avertissement : celles-ci ne sont disponibles que pour les watchers enveloppés, elles sont donc mieux adaptées à un usage interactif via le shell de débogage)

.
$w->
id
Retourne l'identifiant numérique du watcher, tel qu'utilisé dans le shell de
débogage.
$w->
verbose
Retourne une description textuelle multiligne du watcher, incluant les dix premières exceptions capturées lors de l'exécution du
callback.
$w->trace
($on)
Active (si $on est vrai) ou désactive (si $on est faux) le traçage sur ce watcher.

Pour obtenir les messages de traçage, les paramètres de journalisation globaux doivent être configurés pour activer les messages de traçage pour le contexte "AnyEvent::Debug" et le traçage doit être activé pour le watcher

enveloppé.

Pour activer les messages de traçage globalement, la méthode la plus simple est de lancer le programme avec "PERL_ANYEVENT_VERBOSE=9" dans

l'environnement.

Le traçage pour chaque watcher individuel est activé par défaut (sauf si $AnyEvent::Debug::

TRACE a
été défin
i à
faux).
