NOM

AnyEvent::XMPP::IM::Connection - Flux « XML » qui implémente la norme XMPP RFC 3921.

SYNOPSIS

use AnyEvent::XMPP::Connection;
my $con = AnyEvent::XMPP::Connection->new;

DESCRIPTION

Ce module représente une connexion de messagerie instantanée XMPP et implémente la RFC 3921.

Ce module est une sous-classe de "AnyEvent::XMPP::Connection" et hérite de toutes les méthodes. Par exemple "reg_cb" et les routines d'envoi de stanzas.

Pour les événements supplémentaires qui peuvent être enregistrés, voir la section ÉVÉNEMENTS ci-dessous.

MÉTHODES

new (%args)
C'est le constructeur. Il prend les mêmes arguments que le constructeur de AnyEvent::XMPP::Connection ainsi que quelques autres :
dont_retrieve_roster => $bool
Définissez ceci à une valeur vraie si aucun roster ne doit être demandé lors de l'établissement de la connexion. Vous pouvez récupérer le roster plus tard si vous le souhaitez avec la "retrieve_roster" méthode.

Le roster interne sera défini même si cette option est active, et même les présences seront stockées dedans, sauf que la "get_contacts" méthode sur l'objet roster ne renverra rien car il n'y a pas d'éléments de roster.

initial_presence => $priority
Ceci définit si la présence initiale doit être envoyée. $priority doit être la priorité de la présence initiale. La valeur par défaut pour la priorité de la présence initiale $priority est 10.

Si vous passez une valeur indéfinie comme $priority aucune présence initiale ne sera envoyée !

retrieve_roster ($cb)
Cette méthode initie une requête de roster. Si vous avez défini "dont_retrieve_roster" lors de la création de cette connexion, aucun roster n'a été récupéré. Vous pouvez le faire avec cette méthode. Le coderef dans $cb sera appelé après que le roster a été récupéré.

Le premier argument du rappel dans $cb sera le roster et le second sera un objet AnyEvent::XMPP::Error::IQ lorsqu'une erreur s'est produite lors de la récupération du roster.

get_roster
Renvoie l'objet roster de type AnyEvent::XMPP::IM::Roster.

ÉVÉNEMENTS

Ces événements supplémentaires peuvent être enregistrés avec "reg_cb":

Dans les événements suivants $roster est l'objet AnyEvent::XMPP::IM::Roster que vous obtenez en appelant "get_roster".

REMARQUE : Le premier argument de chaque rappel est toujours l'objet AnyEvent::XMPP::IM::Connection lui-même. Voir également Object::Event pour plus d'informations sur l'enregistrement des rappels.

session_ready
Cet événement est généré lorsque la session a été entièrement établie et peut être utilisé pour envoyer des messages et d'autres choses.
session_error => $error
Si une erreur s'est produite lors de l'établissement de la session, cet événement sera généré. $error sera un objet d'erreur AnyEvent::XMPP::Error::IQ.
roster_update => $roster, $contacts
Cet événement est émis lorsqu'une mise à jour du roster a été reçue. $contacts est une référence de tableau d'objets AnyEvent::XMPP::IM::Contact qui ont changé. Si un contact a été supprimé, il renverra 'remove' lorsque vous appellerez la "subscription" méthode dessus.

La première fois que cet événement est envoyé, c'est lorsque le roster a été reçu pour la première fois.

roster_error => $error
Si une erreur s'est produite lors de la récupération du roster, cet événement sera généré. $error sera un objet d'erreur AnyEvent::XMPP::Error::IQ.
presence_update => $roster, $contact, $old_presence, $new_presence
Cet événement est émis lorsque la présence d'un contact a changé. $contact est l'objet AnyEvent::XMPP::IM::Contact dont le statut de présence a changé. $old_presence est un objet AnyEvent::XMPP::IM::Presence qui représente la présence avant le changement. $new_presence est un objet AnyEvent::XMPP::IM::Presence qui représente la présence après le changement. La nouvelle présence peut être undef si la nouvelle présence est 'unavailable'.
presence_error => $error
Cet événement est émis lorsqu'une erreur de stanza de présence a été reçue. $error sera un objet d'erreur AnyEvent::XMPP::Error::Presence.
message => $msg
Cet événement est émis lorsqu'un message a été reçu. $msg est un objet AnyEvent::XMPP::IM::Message.
message_error => $error
Cet événement est émis lorsqu'une erreur de stanza de message a été reçue. $error sera un objet d'erreur AnyEvent::XMPP::Error::Message.
contact_request_subscribe => $roster, $contact, $message
Cet événement est généré lorsque $contact souhaite s'abonner à votre présence.

Si vous souhaitez accepter ou refuser la requête, appelez la "send_subscribed" méthode de AnyEvent::XMPP::IM::Contact ou la "send_unsubscribed" méthode de AnyEvent::XMPP::IM::Contact sur $contact.

Si vous souhaitez démarrer une abonnement mutuel, vous devez appeler "send_subscribe" APRÈS avoir accepté ou refusé avec "send_subscribed"/"send_unsubscribed". Appeler dans l'ordre inverse confond certains serveurs !

Si un élément "status" a été transmis avec l'abonnement, son contenu sera dans $message. Ce qui est généralement un texte écrit par celui qui demande l'abonnement.

contact_subscribed => $roster, $contact, $message
Cet événement est généré lorsque $contact vous a abonné à sa présence avec succès.

Si un élément "status" a été transmis avec la présence d'abonnement, son contenu sera dans $message.

contact_did_unsubscribe => $roster, $contact, $message
Cet événement est généré lorsque $contact se désabonne de votre présence.

Si vous souhaitez vous désabonner de lui, appelez la "send_unsubscribe" méthode de AnyEvent::XMPP::IM::Contact sur $contact.

Si un élément "status" a été transmis avec le désabonnement, son contenu sera dans $message. Ce qui est généralement un texte écrit par celui qui se désabonne.

contact_unsubscribed => $roster, $contact, $message
Cet événement est généré lorsque $contact vous a désabonné de sa présence.

Si vous souhaitez le désabonner de votre présence, appelez la "send_unsubscribed" méthode de AnyEvent::XMPP::IM::Contact sur $contact.

Si un "status" a été transmis avec la désabonnement, son contenu sera dans $message.
