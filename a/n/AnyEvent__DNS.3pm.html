DESCRIPTIO

N

Ce module offre un certain nombre de fonctions de commodité DNS ainsi qu'un résolveur stub pure-perl entièrement asynchrone et haute

performance.

Le résolveur stub prend en charge DNS sur IPv4 et IPv6, UDP et TCP, la prise en charge facultative d'EDNS0 pour des datagrammes allant jusqu'à 4kiB et bascule automatiquement en mode circuit virtuel pour les réponses

volumineuses.

$resolver->request ($req, $cb->($res)
)
C'est le principal cheval de trait de bas niveau pour l'envoi de requêtes DNS.

Cette fonction envoie une seule requête (une référence de hachage formatée comme spécifié pour "dns_pack") aux serveurs de noms configurés à tour de rôle jusqu'à ce qu'elle reçoive une réponse. Elle gère les délais d'attente dépassés, les nouvelles tentatives et passe automatiquement en mode circuit virtuel (TCP) lorsqu'elle reçoit une réponse tronquée. Elle ne gère rien d'autre, comme la liste de recherche de domaine ou les noms relatifs - utilisez "->resolve" pour

cela.

Appelle le rappel avec le paquet de réponse dé

codé si une réponse a été reçue, ou san
s arguments si aucun des serveurs n'a répondu.
$resolver->resolve ($qname, $qtype, %options, $cb->(@rr)
)
Interroge le DNS pour le nom de domaine donné $qname de type $qtype.

Un $qtype est soit un type de requête numérique (par ex. 1 pour les enregistrements A) ou un nom en minuscules (vous devez regarder le code source pour voir quels alias sont pris en charge, mais tous les types de la RFC 1035, "aaaa", "srv", "spf" et quelques autres sont connus de ce module). Un $qtype de "*" est pris en charge et signifie "n'importe quel" type

d'enregistrement.

Le rappel sera invoqué avec une liste d'enregistrements de résultats correspondants ou sans rien en cas d'erreur ou si le nom n'a pas pu être

trouvé.

Les chaînes de CNAME (bien qu'illégales) sont suivies jusqu'à une longueur de

10.

Le rappel sera invoqué avec des références de tableau de la forme "[$name, $type, $class, $ttl, @data"], où $name est le nom de domaine, $type une chaîne ou un nombre de type, $class un nom de classe, $ttl est le temps de vie restant et @data sont des données dépendantes de l'enregistrement de ressources, en secondes. Pour les enregistrements "a", ce seront les adresses IPv4 textuelles, pour les enregistrements "ns" ou "cname" ce sera un nom de domaine, pour les enregistrements "txt" ce seront toutes les chaînes et ainsi de

suite.

Tous les types mentionnés dans la RFC 1035, "aaaa", "srv", "naptr" et "spf" sont décodés. Tous les enregistrements de ressources inconnus de ce module auront le champ "rdata" brut comme cinquième élément de

tableau.

Notez que ce résolveur n'est qu'un résolveur stub : il nécessite un serveur de noms prenant en charge les requêtes récursives, ne fera aucune requête récursive lui-même et n'est pas sécurisé lorsqu'il est utilisé avec un serveur de noms non digne de

confiance.

Attendre qu'un emplacement de requête libre soit disponible et appeler le rappel avec l'objet résolveur.

Un emplacement de requête est utilisé chaque fois qu'une requête est effectivement envoyée aux serveurs de noms : il n'y en a jamais plus de "max_outstandin

g".

Bien que vous puissiez soumettre plus de requêtes (elles seront simplement mises en file d'attente jusqu'à ce qu'un emplacement de requête devienne disponible), il est parfois utile, généralement à des fins de limitation de débit, d'attendre un emplacement avant de générer la requête (ou simplement de savoir quand la charge de requêtes est suffisamment faible pour pouvoir en soumettre à

nouveau).

C'est ce que fait cette méthode : le rappel sera appelé lorsqu'une soumission de requête DNS n'entraînera pas la mise en file d'attente de cette requête. Le rappel peut ou non générer des requêtes en

réponse.
