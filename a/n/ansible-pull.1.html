Utilisé pour récupérer une copie distante d'ansible sur chaque nœud géré, chacun étant configuré pour s'exécuter via cron et mettre à jour la source des playbooks via push d'ansible en une pull [[23]], qui
e quasi illimité.

Aucun des outils en ligne de commande n'est conçu pour s'exécuter concurremment avec lui-même ; vous devriez utiliser un planificateur externe et/ou un verrouillage pour vous assurer

qu'il n'y a pas d'opérations conflictuelles.

Le playbook de configuration peut être ajusté pour changer la fréquence cron, les emplacements de journalisation et les paramètres d'ansible-pul

l. Cela est utile à la fois pour une mise à l'échelle extrême et pour une remédiation périodique. L'utilisation du module 'fetch' pour récup
érer les journaux des exécutions d'ansible-pull serait une excellente façon de collecter et d'analyser les journaux distants d'ansible-pull.

ARGUMENTS

playbook.yml

Le nom d'un des fichiers au format YAML à exécuter en tant que playbook Ansible. Il peut s'agir d'un chemin relatif dans le répertoire de travail. Par défaut, Ansible cherchera un playbook basé sur le nom de domaine entièrement qualifié de l'hôte, sur le nom d'hôte de l'hôte et enfin un playbook nommé local.yml.

INVENTAIRE

Ansible stocke les hôtes sur lesquels il peut potentiellement opérer dans un inventaire. Il peut s'agir d'un fichier YAML, d'un fichier de type ini, d'un script, d'un répertoire, d'une liste, etc. Pour des options supplémentaires, voir la documentation sur https://docs.ansible.com/.

ENVIRONNEMENT

Les variables d'environnement suivantes peuvent être spécifiées.

ANSIBLE_INVENTORY -- Remplace les sources d'inventaire ansible par défaut

ANSIBLE_LIBRARY -- Remplace le chemin de la bibliothèque de modules ansible par défaut

ANSIBLE_CONFIG -- Spécifie l'emplacement de remplacement du fichier de configuration d'ansible

Beaucoup plus sont disponibles pour la plupart des options dans ansible.cfg

Pour une liste complète, vérifiez https://docs.ansible.com/. ou utilisez la commande ansible-config .

FICHIERS

/etc/ansible/hosts -- Fichier d'inventaire par défaut

/etc/ansible/ansible.cfg -- Fichier de configuration, utilisé s'il est présent

~/.ansible.cfg -- Fichier de configuration utilisateur, remplace la configuration par défaut si présent

./ansible.cfg -- Fichier de configuration local (dans le répertoire de travail courant) supposé être « spécifique au projet » et remplace le reste s'il est présent.

Comme mentionné ci-dessus, la variable d'environnement ANSIBLE_CONFIG remplace toutes les autres.
