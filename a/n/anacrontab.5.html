ANACRONTAB(5) Formats de fichiers ANACRONTAB(5)

NOM

/etc/anacrontab - fichier de configuration pour Anacron

DESCRIPTION

Le fichier de configuration /etc/anacrontab décrit les tâches contrôlées par anacron(8). Il peut contenir trois types de lignes : lignes de description de tâche, affectations d'environnement ou lignes vides.

Les lignes de description de tâche peuvent avoir le format suivant :


période en jours délai en minutes identifiant_tâche commande

La variable période en jours spécifie la fréquence d'exécution d'une tâche en jours. Cette variable peut être représentée par un entier ou une macro (@daily, @weekly, @monthly), où @daily représente la même valeur que l'entier 1, @weekly la même que 7, et @monthly spécifie que la tâche est exécutée une fois par mois, indépendamment de la durée du mois.

La variable délai en minutes spécifie le nombre de minutes que anacron attend, si nécessaire, avant d'exécuter une tâche. Cette variable est représentée par un entier où 0 signifie aucun délai.

La variable identifiant_tâche spécifie un nom unique pour une tâche utilisé dans les fichiers journaux.

La variable commande spécifie la commande à exécuter. La commande peut être une commande telle que ls /proc >> /tmp/proc ou une commande pour exécuter un script personnalisé.

Les lignes d'affectation d'environnement peuvent avoir le format suivant :


VAR=VALEUR

Tous les espaces autour de VAR sont supprimés. Aucun espace autour de VALEUR n'est autorisé (sauf si vous souhaitez qu'ils fassent partie de la valeur). L'affectation spécifiée prend effet à partir de la ligne suivante jusqu'à la fin du fichier, ou jusqu'à la prochaine affectation de la même variable.

La variable START_HOURS_RANGE définit un intervalle (en heures) pendant lequel les tâches planifiées peuvent être exécutées. Si cet intervalle de temps est manqué, par exemple, en raison d'une coupure de courant, les tâches planifiées ne seront pas exécutées ce jour-là.

La variable RANDOM_DELAY désigne le nombre maximum de minutes qui seront ajoutées au délai en minutes spécifié pour chaque tâche. Un RANDOM_DELAY réglé sur 12 ajouterait donc, de manière aléatoire, entre 0 et 12 minutes au délai en minutes pour chaque tâche dans cet anacrontab particulier. Lorsqu'il est réglé sur 0, aucun délai aléatoire n'est ajouté.

Si MAILTO est défini (et non vide), un e-mail est envoyé à l'adresse spécifiée, sinon, l'utilisateur système est utilisé.

Si MAILFROM est défini (et non vide), il est utilisé comme adresse d'expéditeur de l'enveloppe, sinon, l'utilisateur système est utilisé.

(Note : Les variables MAILFROM et MAILTO sont développées, donc les définir comme dans l'exemple suivant fonctionne comme prévu : MAILFROM=cron-$USER@cron.com ($USER est remplacé par l'utilisateur système) )

Si NO_MAIL_OUTPUT est défini (et non vide), les descripteurs de sortie standard et d'erreur des processus de tâche ne sont pas redirigés et envoyés par e-mail.

Les lignes vides sont soit des lignes blanches, soit des lignes ne contenant que des espaces blancs, soit des lignes avec des espaces blancs suivis d'un '#' suivi d'un commentaire arbitraire.

Vous pouvez continuer une ligne sur la ligne suivante en ajoutant un '\' à la fin de celle-ci.

Si vous souhaitez désactiver Anacron, ajoutez une ligne avec 0anacron qui est le nom du script exécutant Anacron dans le fichier /etc/cron.hourly/jobs.deny.

EXEMPLE

Cet exemple montre comment configurer une tâche Anacron similaire en fonctionnalité à /etc/crontab qui démarre toutes les tâches régulières entre 6h00 et 8h00 uniquement. Un RANDOM_DELAY qui peut être de 30 minutes au maximum est spécifié. Les tâches s'exécuteront sérialisées dans une file d'attente où chaque tâche ne démarre qu'après la fin de la précédente.

# variables d'environnement
SHELL=/bin/sh
PATH=/sbin:/bin:/usr/sbin:/usr/bin
MAILTO=root
RANDOM_DELAY=30
# Les tâches Anacron démarreront entre 6h et 8h.
START_HOURS_RANGE=6-8
# délai sera de 5 minutes + RANDOM_DELAY pour cron.daily
1		5	cron.daily		nice run-parts /etc/cron.daily
7		0	cron.weekly		nice run-parts /etc/cron.weekly
@monthly	0	cron.monthly		nice run-parts /etc/cron.monthly
