Nom

ansible-playbook - Exécute des playbooks Ansible, en exécutant les tâches définies sur les hôtes ciblés.

SYNOPSIS

utilisation : ansible-playbook [-h] [--version] [-v] [--private-key PRIVATE_KEY_FILE]
[-u REMOTE_USER] [-c CONNECTION] [-T TIMEOUT] [--ssh-common-args SSH_COMMON_ARGS] [--sftp-extra-args SFTP_EXTRA_ARGS] [--scp-extra-args SCP_EXTRA_ARGS] [--ssh-extra-args SSH_EXTRA_ARGS] [-k | --connection-password-file CONNECTION_PASSWORD_FILE] [--force-handlers] [-b] [--become-method BECOME_METHOD] [--become-user BECOME_USER] [-K | --become-password-file BECOME_PASSWORD_FILE] [-t TAGS] [--skip-tags SKIP_TAGS] [-C] [-D] [-i INVENTORY] [--list-hosts] [-l SUBSET] [--flush-cache] [-e EXTRA_VARS] [--vault-id VAULT_IDS] [-J | --vault-password-file VAULT_PASSWORD_FILES] [-f FORKS] [-M MODULE_PATH] [--syntax-check] [--list-tasks] [--list-tags] [--step] [--start-at-task START_AT_TASK] playbook [playbook ...]

DESCRIPTION

l'outil pour exécuter des playbooks Ansible, qui sont un système de configuration et de déploiement multi-nœuds. Voir la page d'accueil du projet (https://docs.ansible.com) pour plus d'informations.

OPTIONS COMMUNES

Playbook(s)

--become-method 'BECOME_METHOD'

méthode d'élévation de privilèges à utiliser (par défaut=sudo), utilisez ansible-doc -t become -l pour lister les choix valides.

--become-password-file 'BECOME_PASSWORD_FILE', --become-pass-file 'BECOME_PASSWORD_FILE'

Fichier de mot de passe become

--become-user 'BECOME_USER'

exécuter les opérations en tant que cet utilisateur (par défaut=root)

--connection-password-file 'CONNECTION_PASSWORD_FILE', --conn-pass-file 'CONNECTION_PASSWORD_FILE'

Fichier de mot de passe de connexion

--flush-cache

effacer le cache de faits pour chaque hôte dans l'inventaire

--force-handlers

exécuter les gestionnaires même si une tâche échoue

--list-hosts

affiche une liste des hôtes correspondants ; n'exécute rien d'autre

--list-tags

lister toutes les balises disponibles

--list-tasks

lister toutes les tâches qui seraient exécutées

--private-key 'PRIVATE_KEY_FILE', --key-file 'PRIVATE_KEY_FILE'

utiliser ce fichier pour authentifier la connexion

--scp-extra-args 'SCP_EXTRA_ARGS'

spécifier des arguments supplémentaires à passer uniquement à scp (ex. -l)

--sftp-extra-args 'SFTP_EXTRA_ARGS'

spécifier des arguments supplémentaires à passer uniquement à sftp (ex. -f, -l)

--skip-tags

exécuter uniquement les plays et les tâches dont les balises ne correspondent pas à ces valeurs. Cet argument peut être spécifié plusieurs fois.

--ssh-common-args 'SSH_COMMON_ARGS'

spécifier des arguments communs à passer à sftp/scp/ssh (ex. ProxyCommand)

--ssh-extra-args 'SSH_EXTRA_ARGS'

spécifier des arguments supplémentaires à passer uniquement à ssh (ex. -R)

--start-at-task 'START_AT_TASK'

commencer le playbook à la tâche correspondant à ce nom

--step

étape par étape : confirmer chaque tâche avant de l'exécuter

--syntax-check

effectuer une vérification de la syntaxe du playbook, mais ne pas l'exécuter

--vault-id

l'identité vault à utiliser. Cet argument peut être spécifié plusieurs fois.

--vault-password-file, --vault-pass-file

fichier de mot de passe vault

--version

afficher le numéro de version du programme, l'emplacement du fichier de configuration, le chemin de recherche des modules configuré, l'emplacement des modules, l'emplacement de l'exécutable, puis quitter

-C, --check

ne faire aucun changement ; au lieu de cela, essayer de prédire certains des changements qui pourraient survenir

-D, --diff

lors de la modification de fichiers et de modèles (petits), afficher les différences dans ces fichiers ; fonctionne très bien avec --check

-J, --ask-vault-password, --ask-vault-pass

demander le mot de passe vault

-K, --ask-become-pass

demander le mot de passe d'élévation de privilèges

-M, --module-path

ajouter des chemins séparés par des deux-points devant la bibliothèque de modules (par défaut={{ ANSIBLE_HOME ~ "/plugins/modules:/usr/share/ansible/plugins/modules" }}). Cet argument peut être spécifié plusieurs fois.

-T 'TIMEOUT', --timeout 'TIMEOUT'

remplacer le délai d'attente de connexion en secondes (par défaut dépend de la connexion)

-b, --become

exécuter les opérations avec become (n'implique pas la demande de mot de passe)

-c 'CONNECTION', --connection 'CONNECTION'

type de connexion à utiliser (par défaut=ssh)

-e, --extra-vars

définir des variables supplémentaires sous forme clé=valeur ou YAML/JSON ; pour un nom de fichier, préfixer avec @. Cet argument peut être spécifié plusieurs fois.

-f 'FORKS', --forks 'FORKS'

spécifier le nombre de processus parallèles à utiliser (par défaut=5)

-h, --help

afficher ce message d'aide et quitter

-i, --inventory, --inventory-file

spécifier le chemin du fichier d'inventaire ou une liste d'hôtes séparée par des virgules. Cet argument peut être spécifié plusieurs fois.

-k, --ask-pass

demander le mot de passe de connexion

-l 'SUBSET', --limit 'SUBSET'

limiter davantage les hôtes sélectionnés à un motif supplémentaire

-t, --tags

exécuter uniquement les plays et les tâches étiquetés avec ces valeurs. Cet argument peut être spécifié plusieurs fois.

-u 'REMOTE_USER', --user 'REMOTE_USER'

se connecter en tant que cet utilisateur (par défaut=None)

-v, --verbose

Fait en sorte qu'Ansible affiche plus de messages de débogage. Ajouter plusieurs -v augmentera la verbosité ; les plugins intégrés évaluent actuellement jusqu'à -vvvvvv. Un niveau raisonnable pour commencer est -vvv ; le débogage de connexion pourrait nécessiter -vvvv. Cet argument peut être spécifié plusieurs fois.

INVENTAIRE

Ansible stocke les hôtes sur lesquels il peut potentiellement opérer dans un inventaire. Il peut s'agir d'un fichier YAML, d'un fichier de type ini, d'un script, d'un répertoire, d'une liste, etc. Pour des options supplémentaires, voir la documentation sur https://docs.ansible.com/.

ENVIRONNEMENT

Les variables d'environnement suivantes peuvent être spécifiées.

ANSIBLE_INVENTORY -- Remplacer les sources d'inventaire ansible par défaut

ANSIBLE_LIBRARY -- Remplacer le chemin par défaut de la bibliothèque de modules ansible>

ANSIBLE_CONFIG -- Spécifier l'emplacement de substitution pour le fichier de configuration ansible

Beaucoup d'autres sont disponibles pour la plupart des options dans ansible.cfg

Pour une liste complète, consultez https://docs.ansible.com/. ou utilisez la commande ansible-config.

FICHIERS

/etc/ansible/hosts -- Fichier d'inventaire par défaut

/etc/ansible/ansible.cfg -- Fichier de configuration, utilisé s'il est présent

~/.ansible.cfg -- Fichier de configuration utilisateur, remplace le fichier de configuration par défaut s'il est présent

./ansible.cfg -- Fichier de configuration local (dans le répertoire de travail courant) supposé être 'spécifique au projet' et remplace les autres s'il est présent.

Comme mentionné ci-dessus, la variable d'environnement ANSIBLE_CONFIG remplacera toutes les autres.
