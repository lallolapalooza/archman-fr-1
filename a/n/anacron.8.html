Paquet: cronie

Licences: custom:BSD

ANACRON(8) Administration système ANACRON(8)

NOM

anacron - exécute des commandes périodiquement

SYNTAXE

anacron [-s] [-f] [-n] [-d] [-q] [-t anacrontab] [-S spooldir] [tâche]
anacron [-S spooldir] -u [-t anacrontab] [tâche]
anacron [-V|-h]
anacron -T [-t anacrontab]

DESCRIPTION

Anacron est utilisé pour exécuter des commandes périodiquement, avec une fréquence spécifiée en jours. Contrairement à cron(8), il ne suppose pas que la machine est en marche en continu. Par conséquent, il peut être utilisé sur des machines qui ne fonctionnent pas 24 heures sur 24 pour contrôler des tâches régulières comme les tâches quotidiennes, hebdomadaires et mensuelles.

Anacron lit une liste de tâches depuis le fichier de configuration /etc/anacrontab (voir anacrontab(5)). Ce fichier contient la liste des tâches qu'Anacron contrôle. Chaque entrée de tâche spécifie une période en jours, un délai en minutes, un identifiant de tâche unique et une commande shell.

Pour chaque tâche, Anacron vérifie si cette tâche a été exécutée au cours des n derniers jours, où n est la période spécifiée pour cette tâche. Si une tâche n'a pas été exécutée depuis n jours ou plus, Anacron exécute la commande shell de la tâche, après avoir attendu le nombre de minutes spécifié comme paramètre de délai.

Après la sortie de la commande, Anacron enregistre la date (sans l'heure) dans un fichier d'horodatage spécial pour cette tâche, afin de savoir quand l'exécuter à nouveau.

Lorsqu'il n'y a plus de tâches à exécuter, Anacron se termine.

Anacron ne prend en compte que les tâches dont l'identifiant, tel que spécifié dans anacrontab(5), correspond à l'un des arguments de commande tâche. Les arguments de commande tâche peuvent être représentés par des modèles de caractères génériques shell (assurez-vous de les protéger de votre shell avec une citation adéquate). L'absence d'arguments de commande tâche est équivalente à spécifier "*" (c'est-à-dire que toutes les tâches sont considérées par Anacron).

À moins qu'Anacron ne soit exécuté avec l'option -d (spécifiée ci-dessous), il se dédouble en arrière-plan au démarrage, et tout processus parent se termine immédiatement.

À moins qu'Anacron ne soit exécuté avec les options -s ou -n, il démarre les tâches immédiatement lorsque leur délai est dépassé. L'exécution des différentes tâches est complètement indépendante.

Si une tâche exécutée génère une sortie vers la sortie standard ou l'erreur standard, la sortie est envoyée par courrier à l'utilisateur sous lequel Anacron s'exécute (généralement root), ou à l'adresse spécifiée dans la variable d'environnement MAILTO dans le fichier /etc/anacrontab, si elle existe. Si la variable d'environnement LOGNAME est définie, elle est utilisée dans le champ From: du courrier.

Tous les messages informatifs générés par Anacron sont envoyés à syslogd(8) ou rsyslogd(8) avec la facilité définie à cron et la priorité définie à notice. Tous les messages d'erreur sont envoyés avec la priorité error.

"Actives" tâches (c'est-à-dire les tâches qu'Anacron a déjà décidé d'exécuter et qui attendent maintenant que leur délai passe, et les tâches en cours d'exécution par Anacron), sont "verrouillées", de sorte que d'autres copies d'Anacron ne peuvent pas les exécuter en même temps.

OPTIONS

-f
Force l'exécution de toutes les tâches, en ignorant tous les horodatages.
-u
Met à jour les horodatages de toutes les tâches à la date actuelle, mais n'en exécute aucune.
-s
Sérialise l'exécution des tâches. Anacron ne démarre pas une nouvelle tâche avant que la précédente ne soit terminée.
-n
Exécute les tâches immédiatement et ignore les délais spécifiés dans le fichier /etc/anacrontab. Cette option implique -s.
-d
Ne démarre pas Anacron en arrière-plan. Dans ce mode, Anacron affichera des messages d'information sur la sortie standard, ainsi que dans syslog. La sortie de toute tâche est envoyée par courrier par Anacron.
-q
Supprime tous les messages sur la sortie standard. Applicable uniquement avec -d.
-t un_autre_anacrontab
Utilise l'anacrontab spécifié, plutôt que celui par défaut /etc/anacrontab.
-T
Test de l'anacrontab. Teste la validité du fichier de configuration /etc/anacrontab. S'il y a une erreur dans le fichier, elle est affichée sur la sortie standard et Anacron retourne la valeur 1. Les anacrontabs valides retournent la valeur 0.
-S spooldir
Utilise le répertoire de spooldir spécifié pour stocker les horodatages. Cette option est requise pour les utilisateurs qui souhaitent exécuter anacron eux-mêmes.
-V
Affiche les informations de version et quitte.
-h
Affiche un court message d'utilisation et quitte.

SIGNALS

Après avoir reçu un signal SIGUSR1, Anacron attend que toutes les tâches en cours se terminent, puis se ferme. Ceci peut être utilisé pour arrêter Anacron proprement.

NOTES

Assurez-vous que votre fuseau horaire est correctement réglé avant le démarrage d'Anacron, car le fuseau horaire affecte la date. Ceci est généralement accompli en réglant la variable d'environnement TZ, ou en installant un fichier /usr/lib/zoneinfo/localtime. Voir tzset(3) pour plus d'informations.

Les fichiers d'horodatage sont créés dans le répertoire de spooldir pour chaque tâche spécifiée dans un anacrontab. Ces fichiers ne sont jamais supprimés automatiquement par Anacron, et devraient être supprimés manuellement si une tâche n'est plus planifiée.

FICHIERS

/etc/anacrontab
Contient les spécifications des tâches. Voir anacrontab(5) pour une description complète.
/var/spool/anacron
Ce répertoire est utilisé par Anacron pour stocker les fichiers d'horodatage.

VOIR AUSSI

anacrontab(5), cron(8), tzset(3)

Le fichier README d'Anacron.

BOGUES

Anacron ne supprime jamais les fichiers d'horodatage. Supprimez manuellement les fichiers inutilisés.

Anacron utilise jusqu'à deux descripteurs de fichiers pour chaque tâche active. Il peut manquer de descripteurs s'il y a beaucoup de tâches actives. Voir echo $(($(ulimit -n) / 2)) pour savoir combien de tâches concurrentes anacron peut exécuter.

Envoyez vos commentaires, suggestions et rapports de bogues à Sean 'Shaleh' Perry.
