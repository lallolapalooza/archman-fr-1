NOM

AnyEvent::XMPP - Une implémentation du protocole XMPP

VERSION

Version 0.55

SYNOPSIS

use AnyEvent::XMPP::Connection;

ou :

use AnyEvent::XMPP::IM::Connection;

ou :

use AnyEvent::XMPP::Client;

DESCRIPTION

Ceci est le module principal du framework de protocole client XMPP AnyEvent::XMPP (tel que décrit dans la RFC 3920 et la RFC 3921).

AnyEvent::XMPP::Connection est une implémentation de flux "XML" conforme à la RFC 3920 pour les clients, qui gère la connexion TCP jusqu'à la liaison de ressource. Et fournit un accès de bas niveau aux nœuds XML du flux XML ainsi que quelques méthodes de haut niveau pour envoyer les stanzas XML prédéfinies.

AnyEvent::XMPP::IM::Connection est un module de niveau plus élevé, qui est dérivé de AnyEvent::XMPP::Connection. Il gère toutes les fonctionnalités de client de messagerie instantanée décrites dans la RFC 3921.

AnyEvent::XMPP::Client est une classe de client multi-comptes. Elle gère les connexions à plusieurs comptes XMPP et tente d'offrir une belle interface de haut niveau pour la communication XMPP.

Pour une liste des « extensions prises en charge », voir ci-dessous.

Il y a aussi d'autres modules dans cette distribution, par exemple : AnyEvent::XMPP::Util, AnyEvent::XMPP::Writer, AnyEvent::XMPP::Parser et ceux dont j'ai oublié l'existence :-) Ces modules peuvent être utiles et/ou nécessaires si vous voulez utiliser ce framework pour XMPP.

Voir aussi AnyEvent::XMPP::Writer pour une discussion sur la maladresse du XML dans la spécification XMPP.

Si vous avez des questions ou cherchez de l'aide, regardez ci-dessous dans « SUPPORT ».

PRÉREQUIS

L'un des principaux inconvénients que je vois pour AnyEvent::XMPP est la longue liste de modules requis pour le faire fonctionner.

AnyEvent
Pour les événements d'E/S, les minuteurs, TCP, TLS, DNS et le tamponnage d'E/S.
Object::Event
L'ancien module AnyEvent::XMPP::Event a été externalisé dans le module Object::Event pour fournir une manière plus générique à plus d'autres modules d'enregistrer et d'appeler des rappels d'événements.
XML::Writer
Pour écrire du "XML".
XML::Parser::Expat
Pour analyser des morceaux de "XML" partiels.
MIME::Base64
Pour l'authentification SASL
Authen::SASL
Pour l'authentification SASL
Net::LibIDN
Pour les profils stringprep afin de gérer les JID.
Digest::SHA
Pour l'authentification de composant et l'authentification de style ancien.

Et oui, tout cela est essentiel pour la communication XMPP. Même si « la messagerie instantanée » et la « présence » sont un problème assez simple, XMPP a d'une certaine manière réussi à rendre la tâche suffisamment compliquée pour m'occuper pendant longtemps. Mais tout ce temps n'a pas été consacré uniquement à la technologie nécessaire pour le démarrer, la plupart l'a été pour toutes les bizarreries, les contournements et le "XML" mal appliqué dans le protocole qui ont compliqué la situation.

SUITE DE TESTS

Si vous êtes un développeur et que vous voulez tester soit un serveur, soit peut-être simplement si ce module passe quelques tests de base, vous pourriez vouloir exécuter la suite de tests pour développeurs.

Cette suite de tests n'est pas activée par défaut car elle nécessite une certaine interaction humaine pour être configurée, veuillez voir AnyEvent::XMPP::TestClient pour des indications sur la procédure de configuration de la suite de tests.

J'ai écrit la suite de tests principalement parce que je voulais m'assurer que je n'avais rien cassé d'essentiel avant une version. Les tests ne couvrent pas tout et je n'ai pas l'intention d'écrire un test pour chaque fonction de l'API, cela ralentirait considérablement le développement pour moi. Mais j'espère que certains bogues graves bloquants dans les versions sont évités grâce à cette suite de tests.

Les tests sont aussi utiles si vous voulez tester une implémentation de serveur. Mais il y a peut-être bien sûr des problèmes de conformité avec AnyEvent::XMPP lui-même, donc si vous trouvez quelque chose où AnyEvent::XMPP ne se conforme pas aux RFC ou XEP XMPP, consultez la section BUGS ci-dessous.

Si vous trouvez un serveur qui ne gère pas quelque chose correctement mais que vous devez interagir avec lui, vous êtes libre de mettre en œuvre des solutions de contournement et de m'envoyer un correctif, ou même de me demander si je voudrais examiner le problème (je ne peux rien garantir ici, mais je veux que ce module soit aussi interopérable que possible. Mais si la mise en œuvre d'une solution de contournement pour un logiciel non conforme compliquerait trop le code, je ne vais probablement pas l'implémenter.).

Bien sûr, si vous trouvez un bogue dans une implémentation de serveur, n'oubliez pas de déposer un rapport de bogue à leur attention, un hack de moins dans AnyEvent::XMPP signifie plus de temps pour la correction de bogues, les améliorations et les nouvelles fonctionnalités.

Pourquoi encore un module XMPP ?

La caractéristique principale et distinctive de ce module par rapport aux autres modules XMPP (alias Jabber) disponibles est la prise en charge d'AnyEvent. AnyEvent vous permet d'utiliser ce module avec d'autres programmes et bibliothèques basés sur des événements d'E/S (par ex. Gtk2 ou Event).

Les autres modules pourraient souvent ne peuvent être intégrés dans ces applications ou bibliothèques qu'en utilisant des threads. J'ai décidé d'écrire ce module parce que je pense que CPAN manque d'un module XMPP basé sur les événements. Les threads ne sont malheureusement pas une alternative en Perl pour le moment en raison de la fonctionnalité de threading limitée qu'ils fournissent et de la perte de performance globale. Je pense aussi qu'un simple framework d'E/S basé sur les événements pourrait être un peu plus facile à gérer que les threads.

Une autre raison était que je n'aimais pas les API des autres modules. Dans AnyEvent::XMPP, j'essaie de fournir des modules de bas niveau pour parler XMPP tel que défini dans RFC 3920 et RFC 3921 (voir aussi AnyEvent::XMPP::Connection et AnyEvent::XMPP::IM::Connection). Mais j'essaie aussi de fournir une API de haut niveau pour un usage plus facile pour les tâches de messagerie instantanée et les clients (par ex. AnyEvent::XMPP::Client).

EXEMPLES

Les exemples suivants sont inclus dans cette distribution :

samples/simple_example_1
Ce script d'exemple se connecte simplement à un serveur et envoie un message, et affiche aussi les messages entrants sur stdout.
samples/conference_lister
Voir ci-dessous.
samples/room_lister
Voir ci-dessous.
samples/room_lister_stat
Ces trois scripts implémentent une analyse globale des salons. "conference_lister" prend une liste de serveurs (le fichier est appelé "servers.xml" qui a le même format que le fichier xml à http://www.jabber.org/servers.xml). Il analyse ensuite tous les serveurs à la recherche de services de salons de discussion et les liste dans un fichier "conferences.stor", qui est un dump Storable.

"room_lister" lit ensuite ce fichier et interroge tous les services pour les salons, puis tous les salons pour leurs occupants. Le fichier de sortie est "room_data.stor", également un dump Storable, qui à son tour peut être lu avec "room_lister_stat", qui transforme les structures de données en quelque chose de lisible par un humain.

Ces scripts sont un peu bricolés et assez compliqués, mais ils peuvent peut-être avoir une valeur pour quelqu'un. Vous remarquerez peut-être "EVQ.pm" dans samples, qui est un module qui gère le throttling des requêtes (Vous ne voulez pas flooder le serveur et risquer d'attirer l'attention des administrateurs :).

samples/simple_component
C'est un squelette (basique) pour un composant jabber.
samples/simple_oob_retriever
C'est un simple bot récepteur de transfert de fichiers out of band. Il utilise "curl" pour récupérer les fichiers et a aussi la fonctionnalité d'exemple d'envoyer une url de fichier à quelqu'un qui envoie un message 'send <filename>' au bot.
samples/simple_register_example
C'est un script d'exemple qui vous permet de vous enregistrer, vous désinscrire et changer votre mot de passe pour les comptes. Exécutez-le sans arguments pour plus de détails.
samples/disco_info
C'est un petit outil d'exemple qui vous permet de récupérer la version du logiciel, les informations disco info et disco items à propos d'un JID.
samples/talkbot
C'est un simple bot qui lira les lignes d'un fichier et les récitera quand vous lui enverrez un message. Il vous autorisera aussi automatiquement à vous abonner à lui. Démarrez-le sans arguments de ligne de commande pour être informé de l'utilisation.
samples/retrieve_roster
C'est un simple script d'exemple qui récupérera la liste de contacts d'un compte et l'affichera sur stdout. Vous le démarrez comme ceci : 
samples/# ./retrieve_roster <jid> <password>
samples/display_avatar
C'est juste un petit exemple qui devrait afficher l'avatar du compte auquel vous vous connectez. Il peut être utilisé comme ceci : 
samples/# ./display_avatar <jid> <password>

Pour d'autres, que l'auteur a peut-être oubliés ou n'a pas voulu lister ici, voir le répertoire "samples/" .

Plus d'exemples seront inclus dans les versions ultérieures, n'hésitez pas à contacter l'"AUTEUR" si vous avez des questions sur l'API. Il y a aussi un canal IRC, voir "SUPPORT".

BUGS

Veuillez noter que je suis actuellement (juillet 2007) le seul développeur sur ce projet et que je suis très occupé par mes études en informatique. Si vous voulez alléger ma charge de travail ou voulez des versions régulières, veuillez m'envoyer des patches au lieu de rapports de bugs ou de demandes de fonctionnalités. Je n'oublierai pas les rapports ou les demandes si vous ne pouvez pas ou n'avez pas envoyé de patches, mais je ne peux pas garantir une réponse immédiate. Mais je vais bien sûr essayer de les corriger/implémenter dès que possible !

Essayez aussi d'être aussi précis que possible avec les rapports de bugs, si vous ne pouvez pas envoyer de patch, il serait préférable que vous découvriez quel code ne fonctionne pas et me disiez pourquoi.

Veuillez signaler tout bug ou demande de fonctionnalité à "bug-net-xmpp2 at rt.cpan.org", ou via l'interface web à http://rt.cpan.org/NoAuth/ReportBug.html?Queue=AnyEvent-XMPP. Je serai notifié et ensuite vous serez automatiquement notifié de l'avancement sur votre bug à mesure que j'apporte des changements.
