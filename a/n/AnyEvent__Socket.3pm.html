$sa = AnyEvent::Socket::pack_sockaddr $service, $host
Empaquette la combinaison port/hôte donnée dans une structure sockaddr binaire. Gère les adresses d'hôtes IPv4 et IPv6, ainsi que les sockets de domaine UNIX ($host == "unix/" et $service == chemin absolu).

Exemple :

my $bind = AnyEvent::Socket::pack_sockaddr 43, v195.234.53.120;
bind $socket, $bind
   or die "bind: $!";
($service, $host) = AnyEvent::Socket::unpack_sockaddr $sa
Dépaquette la structure sockaddr binaire donnée (comme utilisée par bind, getpeername etc.) en une combinaison "$service, $host" .

Pour IPv4 et IPv6, $service est le numéro de port et $host l'adresse de l'hôte au format réseau (binaire).

Pour les sockets de domaine UNIX, $service est le chemin absolu et $host est un jeton spécial compris par les autres fonctions de ce module ("format_address" le convertit en "unix/").

AnyEvent::Socket::resolve_sockaddr $node, $service, $proto, $family, $type, $cb->([$family, $type, $proto, $sockaddr], ...)
Tente de résoudre le nom de nœud et le nom de service donnés en familles de protocoles et structures sockaddr utilisables pour se connecter à ce nœud et ce service de manière indépendante du protocole. Cela fonctionne de manière vaguement similaire à la fonction posix getaddrinfo.

Pour les adresses internet, $node est soit une adresse IPv4 ou IPv6, un nom d'hôte internet (nom de domaine DNS ou IDN), et $service est soit un nom de service (nom de port depuis /etc/services) soit un numéro de port numérique. Si à la fois $node et $service sont des noms, alors les enregistrements SRV seront consultés pour trouver le vrai service, sinon ils seront utilisés tels quels. Si vous savez que le nom de service n'est pas dans votre base de données de services, alors vous pouvez spécifier le service dans le format "name=port" (par exemple "http=80").

Si un hôte ne peut pas être trouvé via DNS, alors il sera recherché dans /etc/hosts (ou le fichier spécifié via $ENV{PERL_ANYEVENT_HOSTS}). S'ils sont trouvés, les adresses qui s'y trouvent seront utilisées. L'effet est comme si les entrées de /etc/hosts fournissaient "A" et "AAAA" des enregistrements pour le nom d'hôte sauf si DNS avait déjà des enregistrements pour eux.

Pour les sockets de domaine UNIX, $node doit être la chaîne "unix/" et $service doit être le chemin absolu du socket. Dans ce cas, $proto sera ignoré.

$proto doit être un nom de protocole, actuellement "tcp", "udp" ou "sctp". La valeur par défaut est actuellement "tcp", mais à l'avenir, cette fonction pourrait essayer d'utiliser d'autres protocoles tels que "sctp", selon le type de socket et les éventuels enregistrements SRV qu'elle pourrait trouver.

$family doit être soit 0 (signifiant que n'importe quel protocole convient), 4 (n'utiliser que IPv4) ou 6 (n'utiliser que IPv6). La valeur par défaut est influencée par $ENV{PERL_ANYEVENT_PROTOCOLS}.

$type doit être "SOCK_STREAM", "SOCK_DGRAM" ou "SOCK_SEQPACKET" (ou "undef" auquel cas il sera automatiquement choisi comme "SOCK_STREAM" sauf si $proto est "udp").

Le rappel recevra zéro ou plusieurs références à des tableaux qui contiennent "$family, $type, $proto" pour utilisation dans "socket" et un $sockaddr binaire pour utilisation dans "connect" (ou "bind").

L'application devrait essayer ceux-ci dans l'ordre donné.

Exemple :

resolve_sockaddr "google.com", "http", 0, undef, undef, sub { ... };
$guard = tcp_connect $host, $service, $connect_cb[, $prepare_cb]
C'est une fonction de commodité qui crée un socket TCP et effectue une connexion non-bloquante à 100% vers le $host donné (qui peut être un nom d'hôte DNS/IDN ou une adresse IP textuelle, ou la chaîne "unix/" pour les sockets de domaine UNIX) et $service (qui peut être un numéro de port numérique ou un nom de service, ou une chaîne "servicename=portnumber" , ou le chemin vers un socket de domaine UNIX).

Si à la fois $host et $port sont des noms, alors cette fonction utilisera les enregistrements SRV pour localiser la ou les cibles réelles.

Dans les deux cas, elle créera une liste d'hôtes cibles (par exemple pour les hôtes multihomés ou les hôtes ayant à la fois des adresses IPv4 et IPv6) et essaiera de se connecter à chacun à tour de rôle.

Une fois la connexion établie, alors $connect_cb sera invoqué avec le descripteur de fichier du socket (en mode non-bloquant) comme premier argument, et l'hôte pair (sous forme d'adresse IP textuelle) et le port pair comme deuxième et troisième arguments respectivement. Le quatrième argument est une référence à du code que vous pouvez appeler si, pour une raison quelconque, vous n'aimez pas cette connexion, ce qui fera que "tcp_connect" essaiera la suivante (ou appellera votre rappel sans aucun argument s'il n'y a plus de connexions). Dans la plupart des cas, vous pouvez simplement ignorer cet argument.

$cb->($filehandle, $host, $port, $retry)

Si la connexion échoue, alors $connect_cb sera invoqué sans aucun argument et $! sera défini de manière appropriée (avec "ENXIO" indiquant un échec de résolution DNS).

Le rappel ne sera jamais invoqué avant que "tcp_connect" ne retourne, même si "tcp_connect" a pu se connecter immédiatement (par exemple sur les sockets de domaine unix).

Le descripteur de fichier est parfait pour être branché dans AnyEvent::Handle, mais peut être utilisé comme un descripteur de fichier perl normal également.

Sauf si appelé dans un contexte void, "tcp_connect" retourne un objet garde qui annulera automatiquement la tentative de connexion lorsqu'il sera détruit - auquel cas le rappel ne sera pas invoqué. Le détruire ne fait rien au socket après que la connexion a réussi - vous ne pouvez pas "désappeler" un rappel qui a déjà été invoqué.

Parfois vous devez "préparer" le socket avant de vous connecter, par exemple, pour le "bind" à un certain port, ou vous voulez un délai d'attente de connexion spécifique plus bas que le délai d'attente par défaut de votre noyau. Dans ce cas vous pouvez spécifier un second rappel, $prepare_cb. Il sera appelé avec le descripteur de fichier dans l'état pas-encore-connecté comme unique argument et doit retourner la valeur du délai d'attente de connexion (ou 0, "undef" ou la liste vide pour indiquer que le délai d'attente par défaut doit être utilisé).

Note pour les pauvres utilisateurs de Microsoft Windows : Windows (bien sûr) ne signale pas correctement les erreurs de connexion, donc sauf si votre bibliothèque d'événements contourne cela, les connexions échouées vont simplement bloquer. Les seules bibliothèques d'événements qui gèrent correctement cette condition sont EV et Glib. De plus, AnyEvent contourne ce bogue avec Event et dans son backend pure-perl. Toutes les autres bibliothèques ne peuvent pas gérer correctement cette condition. Pour atténuer l'impact de ce bogue windows, un délai d'attente par défaut de 30 secondes sera imposé sur windows. Cygwin n'est pas affecté.

Exemple simple : se connecter à localhost sur le port 22.

tcp_connect localhost => 22, sub {
   my $fh = shift
      or die "unable to connect: $!";
   # do something
};

Exemple complexe : se connecter à www.google.com sur le port 80 et faire une simple requête GET sans beaucoup de gestion d'erreurs. Aussi limiter le délai d'attente de connexion à 15 secondes.

tcp_connect "www.google.com", "http",
   sub {
      my ($fh) = @_
         or die "unable to connect: $!";
      my $handle; # avoid direct assignment so on_eof has it in scope.
      $handle = new AnyEvent::Handle
         fh     => $fh,
         on_error => sub {
            AE::log error => $_[2];
            $_[0]->destroy;
         },
         on_eof => sub {
            $handle->destroy; # destroy handle
            AE::log info => "Done.";
         };
      $handle->push_write ("GET / HTTP/1.0\015\012\015\012");
      $handle->push_read (line => "\015\012\015\012", sub {
         my ($handle, $line) = @_;
         # print response header
         print "HEADER\n$line\n\nBODY\n";
         $handle->on_read (sub {
            # print response body
            print $_[0]->rbuf;
            $_[0]->rbuf = "";
         });
      });
   }, sub {
      my ($fh) = @_;
      # could call $fh->bind etc. here
      15
   };

$guard = tcp_server $host, $service, $accept_cb[, $prepare_cb]
Crée et lie un socket de flux à l'adresse d'hôte et au port donnés, définit l'indicateur SO_REUSEADDR (si applicable) et appelle "listen". Contrairement à ce que son nom suggère, cette fonction peut également lier des sockets de domaine UNIX.

Pour les sockets internet, $host doit être une adresse IPv4 ou IPv6 (ou "undef", auquel cas elle se lie soit à 0 soit à "::", selon que le protocole préféré soit IPv4 ou IPv6, et peut-être aux deux dans de futures versions, selon le cas).

Pour se lier à l'adresse générique IPv4, utilisez 0, pour se lier à l'adresse générique IPv6, utilisez "::".

Le port est spécifié par $service, qui doit être soit un nom de service soit un numéro de port numérique (ou 0 ou "undef", auquel cas un port éphémère sera utilisé).

Pour les sockets de domaine UNIX, $host doit être "unix/" et $service doit être le chemin absolu du socket. Cette fonction essaiera de "unlink" le socket avant d'essayer de s'y lier, et essaiera de le supprimer après avoir cessé de l'utiliser. Voir CONSIDÉRATIONS DE SÉCURITÉ, ci-dessous.

Pour chaque nouvelle connexion qui pourrait être "accept"ée, appelle le "$accept_cb->($fh, $host, $port)" avec le descripteur de fichier (en mode non bloquant) comme premier argument, et l'hôte et le port du pair comme deuxième et troisième arguments (voir "tcp_connect" pour les détails).

Lance une erreur sur toute erreur qu'il peut détecter avant l'écoute.

Dans un contexte non void, cette fonction renvoie un objet garde dont la durée de vie est liée au serveur TCP : si l'objet est détruit, le serveur sera arrêté et le socket d'écoute sera nettoyé/supprimé (les connexions déjà acceptées ne seront pas affectées).

Lorsqu'elle est appelée dans un contexte void, AnyEvent conservera le socket d'écoute en interne. Dans ce cas, il n'y a aucune garantie que le socket d'écoute sera nettoyé ou supprimé.

Dans tous les cas, lorsque la fonction renvoie au appelant, le socket est lié et en état d'écoute.

Si vous avez besoin de plus de contrôle sur le socket d'écoute, vous pouvez fournir un "$prepare_cb->($fh, $host, $port)", qui est appelé juste avant l'appel "listen ()" , avec le descripteur de fichier d'écoute comme premier argument, et l'adresse IP et le numéro de port de l'extrémité locale du socket comme deuxième et troisième arguments.

Il doit renvoyer la longueur de la file d'attente d'écoute (ou 0 pour la valeur par défaut).

Note pour les utilisateurs IPv6 : le comportement conforme à la RFC pour les sockets IPv6 écoutant sur "::" est de se lier à la fois aux adresses IPv6 et IPv4 par défaut sur les hôtes dual-stack. Malheureusement, seul GNU/Linux semble implémenter cela correctement, donc si vous voulez à la fois des sockets d'écoute IPv4 et IPv6, vous devriez créer le socket IPv6 d'abord et ensuite essayer de se lier sur le socket IPv4, mais ignorer toute erreur "EADDRINUSE" .

Exemple : se lier sur un port TCP sur la machine locale et dire à chaque client de dégager.

tcp_server undef, undef, sub {
   my ($fh, $host, $port) = @_;
   syswrite $fh, "The internet is full, $host:$port. Go away!\015\012";
}, sub {
   my ($fh, $thishost, $thisport) = @_;
   AE::log info => "Bound to $thishost, port $thisport.";
};

$guard = AnyEvent::Socket::tcp_bind $host, $service, $done_cb[, $prepare_cb]
Identique à "tcp_server", sauf qu'il n'appelle pas "accept" dans une boucle pour vous mais passe simplement le socket d'écoute au $done_cb. C'est utile lorsque vous voulez une configuration pratique pour votre socket d'écoute, mais voulez faire l' "accept"ation vous-même, par exemple, dans un autre processus.

En cas d'erreur, "tcp_bind" lance soit une erreur, soit passe "undef" au $done_cb.

Dans un contexte non void, une garde sera renvoyée. Elle nettoiera/supprimera le socket d'écoute lorsqu'elle sera détruite. Dans un contexte void, aucun nettoyage automatique ne sera peut-être effectué.

tcp_nodelay $fh, $enable
Active (ou désactive) l'option de socket "TCP_NODELAY" (aussi connue sous le nom d'algorithme de Nagle). Renvoie faux en cas d'erreur, vrai sinon.
tcp_congestion $fh, $algorithm
Définit l'algorithme d'évitement de congestion TCP (via l'option de socket "TCP_CONGESTION" ). La valeur par défaut dépend du système d'exploitation, mais est généralement "reno". Les autres choix typiques disponibles incluent "cubic", "lp", "bic", "highspeed", "htcp", "hybla", "illinois", "scalable", "vegas", "veno", "westwood" et "yeah".

CONSIDÉRATIONS DE SÉCURITÉ

Ce module est assez puissant, avec ce pouvoir vient la capacité de l'abuser aussi : si vous acceptez des « noms d'hôtes » et des ports provenant de sources non fiables, notez que cela peut être abusé pour supprimer des fichiers (hôte="unix/"). Ce n'est pas vraiment un problème avec ce module, cependant, car accepter aveuglément n'importe quelle adresse et protocole et essayer de lier un serveur ou de s'y connecter est nuisible en général.
