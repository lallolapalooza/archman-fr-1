ANALYZE - collecter

des statistiques sur
une base de données

SYNOPSI

S 
ANALYZE [ ( option [, ...] ) ] [ table_and_columns [, ...] ]
où option peut être l'une des suivantes :
    VERBOSE [ boolean ]
    SKIP_LOCKED [ boolean ]
    BUFFER_USAGE_LIMIT size
et table_and_columns est :
    [ ONLY ] table_name [ * ] [ ( column_name [, ...] )
]

DESCRIPTIO

N

ANALYZE collecte des statistiques sur le contenu des tables dans la base de données et stocke les résultats dans le catalogue système pg_statistic. Par la suite, le planificateur de requêtes utilise ces statistiques pour aider à déterminer les plans d'exécution les plus efficaces pour les

requêtes.

Sans une liste table_and_columns, ANALYZE traite chaque table et vue matérialisée de la base de données actuelle que l'utilisateur courant a le droit d'analyser. Avec une liste, ANALYZE ne traite que ces tables. Il est également possible de fournir une liste de noms de

colonnes pour une table, auquel cas seules les
statistiques de ces colonnes sont collectées.

PARAMÈTRE

S

VERBOS

E
Active l'affichage des messages de progression au niveau
INFO.

SKIP_LOCKE

D
Indique que ANALYZE ne doit pas attendre la libération de verrous conflictuels lorsqu'il commence à travailler sur une relation : si une relation ne peut pas être verrouillée immédiatement sans attendre, la relation est ignorée. Notez que même avec cette option, ANALYZE peut toujours se bloquer lors de l'ouverture des index de la relation ou lors de l'acquisition d'exemples de lignes à partir des partitions, des enfants d'héritage de tables et de certains types de tables étrangères. De plus, alors que ANALYZE traite habituellement toutes les partitions des tables partitionnées spécifiées, cette option fera en sorte que ANALYZE ignore toutes les partitions s'il existe un verrou conflictuel sur la table
partitionnée.

BUFFER_USAGE_LIMI

T
Spécifie la taille du tampon circulaire de la stratégie d'accès aux tampons (Buffer Access Strategy) pour ANALYZE. Cette taille est utilisée pour calculer le nombre de tampons partagés qui seront réutilisés dans le cadre de cette stratégie. 0 désactive l'utilisation d'une stratégie d'accès aux tampons. Lorsque cette option n'est pas spécifiée, ANALYZE utilise la valeur de vacuum_buffer_usage_limit. Des réglages plus élevés peuvent permettre à ANALYZE de s'exécuter plus rapidement, mais un réglage trop élevé peut causer l'éviction de trop de pages utiles des tampons partagés. La valeur minimale est de 128 kB et la valeur maximale est de 16
Go.

boolea

n
Indique si l'option sélectionnée doit être activée ou désactivée. Vous pouvez écrire TRUE, ON ou 1 pour activer l'option, et FALSE, OFF ou 0 pour la désactiver. La valeur boolean peut également être omise, auquel cas TRUE est
supposé.

siz

e
Spécifie une quantité de mémoire en kilooctets. Les tailles peuvent également être spécifiées sous forme de chaîne contenant la taille numérique suivie de l'une des unités mémoire suivantes : B (octets), kB (kilooctets), MB (mégaoctets), GB (gigaoctets) ou TB (téraoctets)
.

table_nam

e
Le nom (éventuellement qualifié par un schéma) d'une table spécifique à analyser. S'il est omis, toutes les tables ordinaires, les tables partitionnées et les vues matérialisées de la base de données actuelle sont analysées (mais pas les tables étrangères). Si ONLY est spécifié avant le nom de la table, seule cette table est analysée. Si ONLY n'est pas spécifié, la table et toutes ses tables enfants d'héritage ou ses partitions (le cas échéant) sont analysées. Il est possible de spécifier * après le nom de la table pour indiquer explicitement que les tables enfants d'héritage (ou les partitions) sont à
analyser.

column_nam

e
Le nom d'une colonne spécif
ique à analyser. Par défau
t, toutes les colonnes.

SORTIE

S

Lorsque VERBOSE est spécifié, ANALYZE émet des messages de progression pour indiquer quelle table est en cour

s de traitement. Diverses statistique
s sur les tables sont également imprimées.

REMARQUE

S

Pour analyser une table, on doit habituellement disposer du privilège MAINTAIN sur la table. Toutefois, les propriétaires de bases de données sont autorisés à analyser toutes les tables de leurs bases de données, à l'exception des catalogues partagés. ANALYZE ignorera toute table que l'utilisateur appelant n'a pas le droit

d'analyser.

Les tables étrangères ne sont analysées que lorsqu'elles sont explicitement sélectionnées. Toutes les enveloppes de données étrangères ne prennent pas en charge ANALYZE. Si l'enveloppe de la table ne prend pas en charge ANALYZE, la commande imprime un avertissement et ne fait

rien.

Dans la configuration par défaut de PostgreSQL, le démon autovacuum (voir la section 24.1.6) se charge de l'analyse automatique des tables lorsqu'elles sont d'abord chargées avec des données, et au fur et à mesure qu'elles changent au cours du fonctionnement régulier. Lorsque autovacuum est désactivé, il est conseillé d'exécuter ANALYZE périodiquement, ou juste après avoir apporté des changements majeurs au contenu d'une table. Des statistiques précises aideront le planificateur à choisir le plan de requête le plus approprié, améliorant ainsi la vitesse du traitement des requêtes. Une stratégie courante pour les bases de données principalement en lecture consiste à exécuter VACUUM et ANALYZE une fois par jour pendant une période de faible utilisation. (Cela ne sera pas suffisant en cas d'activité de mise à jour intensive.

)

Pendant ANALYZE, le search_path est temporairement modifié en pg_catalog,

pg_temp.

ANALYZE ne nécessite qu'un verrou de lecture sur la table cible, il peut donc s'exécuter en parallèle avec d'autres activités non-DDL sur la

table.

Les statistiques collectées par ANALYZE comprennent généralement une liste de certaines des valeurs les plus courantes de chaque colonne et un histogramme montrant la distribution approximative des données dans chaque colonne. L'une ou l'autre de ces informations peuvent être omises si ANALYZE les juge sans intérêt (par exemple, dans une colonne de clé unique, il n'y a pas de valeurs courantes) ou si le type de données de la colonne ne prend pas en charge les opérateurs appropriés. Vous trouverez plus d'informations sur les statistiques au chapitre

24.

Pour les grandes tables, ANALYZE prend un échantillon aléatoire du contenu de la table, plutôt que d'examiner chaque ligne. Cela permet d'analyser même des tables très grandes en peu de temps. Notez toutefois que les statistiques ne sont qu'approximatives et changeront légèrement à chaque fois que ANALYZE est exécuté, même si le contenu réel de la table n'a pas changé. Cela peut entraîner de petits changements dans les coûts estimés par le planificateur affichés par EXPLAIN. Dans de rares situations, ce non-déterminisme fera en sorte que les choix de plans de requête du planificateur changeront après ANALYZE. Pour éviter cela, augmentez la quantité de statistiques collectées par ANALYZE, comme décrit

ci-dessous.

L'étendue de l'analyse peut être contrôlée en ajustant la variable de configuration default_statistics_target, ou colonne par colonne en définissant la cible de statistiques par colonne avec ALTER TABLE ... ALTER COLUMN ... SET STATISTICS. La valeur cible définit le nombre maximal d'entrées dans la liste des valeurs les plus courantes et le nombre maximal de classes dans l'histogramme. La valeur cible par défaut est 100, mais elle peut être ajustée à la hausse ou à la baisse pour faire un compromis entre la précision des estimations du planificateur et le temps pris par ANALYZE et l'espace occupé dans pg_statistic. En particulier, le fait de définir la cible de statistiques à zéro désactive la collecte de statistiques pour cette colonne. Il peut être utile de le faire pour les colonnes qui ne sont jamais utilisées comme partie des clauses WHERE, GROUP BY ou ORDER BY des requêtes, car le planificateur n'aura aucun usage pour les statistiques de telles

colonnes.

La plus grande cible de statistiques parmi les colonnes analysées détermine le nombre de lignes de la table échantillonnées pour préparer les statistiques. L'augmentation de la cible entraîne une augmentation proportionnelle du temps et de l'espace nécessaires pour effectuer ANALYZE

.

L'une des valeurs estimées par ANALYZE est le nombre de valeurs distinctes qui apparaissent dans chaque colonne. Comme seules un sous-ensemble de lignes est examiné, cette estimation peut parfois être assez imprécise, même avec la plus grande cible de statistiques possible. Si cette imprécision entraîne de mauvais plans de requête, une valeur plus précise peut être déterminée manuellement puis installée avec ALTER TABLE ... ALTER COLUMN ... SET (n_distinct = ...)

.

Si la table analysée a des enfants d'héritage, ANALYZE rassemble deux ensembles de statistiques : un sur les lignes de la table parent uniquement, et un second incluant les lignes de la table parent et de tous ses enfants. Ce second ensemble de statistiques est nécessaire lors de la planification de requêtes qui traitent l'arbre d'héritage dans son ensemble. Cependant, le démon autovacuum ne prendra en compte que les insertions ou mises à jour sur la table parent elle-même lorsqu'il décidera de déclencher une analyse automatique pour cette table. Si cette table est rarement insérée ou mise à jour, les statistiques d'héritage ne seront pas à jour.e sauf si vous exécutez ANALYZE manuellement. Par défaut, ANALYZE collectera également récursivement et mettra à jour les statistiques pour chaque table enfant d'héritage. Le mot-clé UNIQUE peut être utilisé pour désactiver

ceci.

Pour les tables partitionnées, ANALYZE collecte les statistiques en échantillonnant des lignes de toutes les partitions. Par défaut, ANALYZE collectera également récursivement et mettra à jour les statistiques pour chaque partition. Le mot-clé UNIQUE peut être utilisé pour désactiver

ceci.

Le démon autovacuum ne traite pas les tables partitionnées, ni les parents d'héritage si seuls les enfants sont modifiés. Il est généralement nécessaire d'exécuter périodiquement un ANALYZE manuel pour maintenir les statistiques de la hiérarchie de tables à

jour.

Si certaines tables enfants ou partitions sont des tables distantes dont les connecteurs de données distantes ne prennent pas en charge ANALYZE, ces tables sont ignorées lors de la collecte des statistiques

d'héritage.

Si la table analysée est complètement vide, ANALYZE n'enregistrera pas de nouvelles statistiques pour cette table. Les statistiques existantes seront

conservées.

Chaque processus serveur exécutant ANALYZE signalera sa progression dans la vue pg_stat_pro

gress_analyze. Voir la section
27.4.1 pour plus de détails.

COMPATIBILIT

É

Il n'existe pas d'instruction ANALYZE dans le standard

SQL.

La syntaxe suivante était utilisée avant la version 11 de PostgreSQL et est toujours prise en charge

: 
ANALYZE [ VERBOSE ] [ table_and_columns [, ...
]
]
