DESCRIPTIO

N

Ce module implémente un "framework" de journalisation relativement simple. Il ne prétend pas être "la" solution de journalisation, ni même "une" solution de journalisation pour AnyEvent - AnyEvent crée simplement des messages de journalisation en interne, et ce module expose plus ou moins ce mécanisme, avec quelques extras pour permettre de l'utiliser depuis d'autres modules

également.

Rappelez-vous que le niveau de verbosité par défaut est 4 ("error"), donc seuls les erreurs et les messages plus importants seront journalisés, sauf si vous définissez "PERL_ANYEVENT_VERBOSE" à un nombre plus élevé avant de lancer votre programme ("AE_VERBOSE=5" est recommandé pendant le développement), ou si vous changez le niveau de journalisation à l'exécution avec quelque chose comme

: 
use AnyEvent::Log;
$AnyEvent::Log::FILTER->level ("info")
;

L'objectif de conception derrière ce module était de le garder simple (et petit), mais de le rendre assez puissant pour être potentiellement utile pour n'importe quel module, et assez étendu pour les tâches les plus courantes, comme la journalisation vers plusieurs cibles, ou la capacité à journaliser dans une base de

données.

Le module est également utilisable avant même l'initialisation d'AnyEvent, auquel cas certaines fonctionnalités peuvent être

réduites.

La quantité de documentation pourrait indiquer le co

ntraire, mais la partie exécution du module est
toujours juste en dessous de 300 lignes de code.

NIVEAUX DE

JOURNALISATION

Les niveaux de journalisation dans ce module vont de 1 (priorité la plus élevée) à 9 (priorité la plus basse). Notez que la valeur numérique la plus basse est la priorité la plus élevée, donc quand ce document dit "priorité plus élevée", cela signifie "valeur numérique plus

basse".

Au lieu de spécifier les niveaux par nom, vous pouvez aussi les spécifier par alias

: 
LVL NAME      SYSLOG   PERL  NOTE
 1  fatal     emerg    exit  system unusable, aborts program!
 2  alert                    failure in primary system
 3  critical  crit           failure in backup system
 4  error     err      die   non-urgent program errors, a bug
 5  warn      warning        possible problem, not necessarily error
 6  note      notice         unusual conditions
 7  info                     normal messages, no action required
 8  debug                    debugging messages for development
 9  trace                    copious tracing
output

Comme vous pouvez le voir, certains niveaux de journalisation ont plusieurs alias - le premier est le nom "officiel", le deuxième le nom "syslog" (s'il diffère) et le troisième le nom "perl", suggérant (seulement !) que vous journalisiez les messages "die" à la priorité "error". La colonne NOTE tente de fournir une justification sur la manière de choisir un niveau de

journalisation.

Comme ligne directrice approximative, les niveaux 1..3 sont principalement destinés aux utilisateurs du programme (administrateurs, personnel), et sont les seuls journalisés sur STDERR par défaut. Les niveaux 4..6 sont destinés aux utilisateurs et aux développeurs, tandis que les niveaux 7..9 sont généralement destinés aux

développeurs.

Vous ne pouvez normalement journaliser un message qu'une seule fois au niveau de priorité le plus élevé (1, "fatal"), car la journalisation d'un message fatal quittera également le programme - utilisez-le donc avec parcimonie :

)

Par exemple, un programme qui trouve une option inconnue sur la ligne de commande pourrait bien utiliser un niveau de journalisation fatal pour en informer les utilisateurs - le "système" dans ce cas serait le programme, ou le

module.

Certaines méthodes offrent également quelques niveaux supplémentaires, tels que 0, "off", "none" ou "all" - ceux-ci ne sont valides que

pour les méthodes
qui les documentent.

Les fonctions suivantes vous permettent de journaliser des messages. Elles utilisent toujours le package de l'appelant comme "contexte de journalisation". De plus, la fonction principale de journalisation, "log", est un alias pour "AnyEvent::log" et "AE::log" lorsque le module "AnyEvent" est

AnyEvent::Log::log $level, $msg[,
@args]
Demande la journalisation du $msg donné avec le niveau de journalisation donné, et renvoie vrai si le message a été journalisé quelque part.

Pour le niveau de journalisation "fatal", le programme

s'arrêtera.

Si seul un $msg est donné, il est journalisé tel quel. Avec des @args supplémentaires, le $msg est interprété comme une chaîne de format

sprintf.

Le $msg ne doit pas se terminer par "\n", mais peut le faire si c'est plus pratique pour vous. De plus, les messages multilignes sont gérés

correctement.

Enfin, $msg peut être une référence de code, auquel cas elle est censée renvoyer le message. Elle ne sera appelée que lorsque le message est effectivement journalisé, ce qui est utile si la création du message est coûteuse en premier

lieu.

Cette fonction prend soin de sauvegarder et de restaurer $! et $@, vous n'avez donc pas à le

faire.

Si le message donné sera journalisé dépend du niveau de journalisation maximal et du package de l'appelant. La valeur de retour peut être utilisée pour s'assurer que les messages ne sont pas "perdus" - par exemple, quand AnyEvent::Debug détecte une erreur d'exécution, il essaie de la journaliser au niveau "die", mais si ce message est perdu, il utilise simplement

warn.

CONTEXTES DE

LOGGING

Ce module associe chaque message de journal à un contexte de logging dit, basé sur le package de l'appelant. Chaque package perl a son propre contexte de

logging.

Un contexte de logging a trois responsabilités principales : filtrer, journaliser et propager le

message.

Pour le premier objectif, le filtrage, chaque contexte a un ensemble de niveaux de logging, appelé le masque de niveau de journal. Les messages qui ne sont pas dans l'ensemble seront ignorés par ce contexte (masqués)

.

Pour le logging, le contexte stocke un rappel de formatage (qui prend l'horodatage, le contexte, le niveau et le message de chaîne et le formate de la manière dont il doit être journalisé) et un rappel de logging (qui est responsable de journaliser réellement le message formaté et de dire à "AnyEvent::Log" s'il a consommé le message, ou s'il doit être propagé)

.

Pour la propagation, un contexte peut avoir un nombre quelconque de contextes esclaves attachés. Tout message qui n'est ni masqué par le masque de logging ni masqué par le rappel de logging retournant vrai sera passé à tous les contextes

esclaves.

Chaque appel à une fonction de logging journalisera le message au plus une fois par contexte, donc cela n'a pas d'importance (beaucoup) s'il y a des cycles ou si le message peut arriver au même contexte via plusieurs

chemins.

DÉFAUT

S

Par défaut, tous les contextes de logging ont un ensemble complet de niveaux de journal ("all"), un rappel de logging désactivé et le rappel de formatage par

défaut.

Les contextes de package ont le nom du package comme titre de logging par

défaut.

Ils ont exactement un esclave - le contexte du package "parent". Le package parent est simplement défini comme le nom du package sans le dernier composant, c'est-à-dire "AnyEvent::Debug::Wrapped" devient "AnyEvent::Debug", et "AnyEvent" devient ... $AnyEvent::Log::COLLECT qui est l'exception de la règle - tout comme le "parent" de tout nom de package à composant unique dans Perl est "main", l'esclave par défaut de tout contexte de package de premier niveau est $AnyEvent::Log::

COLLECT.

Puisque les packages perl ne forment qu'une hiérarchie approximative, ce contexte esclave peut bien sûr être

supprimé.

Tous les autres contextes (anonymes) n'ont pas d'esclaves et un titre vide par

défaut.

Lorsque le module est chargé, il crée le contexte de logging $AnyEvent::Log::LOG qui journalise simplement tout via "warn", sans propager quoi que ce soit nulle part par défaut. Le but de ce contexte est de fournir un endroit pratique pour remplacer la cible de logging globale ou pour attacher des cibles de journal supplémentaires. Il n'est pas destiné au

filtrage.

Il crée ensuite le contexte $AnyEvent::Log::FILTER dont le but est de supprimer tous les messages avec une priorité plus élevée que $ENV{PERL_ANYEVENT_VERBOSE}. Il attache ensuite le contexte $AnyEvent::Log::LOG à celui-ci. Le but du contexte filtre est simplement de fournir un filtrage selon un certain niveau de journal

global.

Enfin, il crée le contexte de package de premier niveau $AnyEvent::Log::COLLECT et attache le contexte $AnyEvent::Log::FILTER à celui-ci, mais laisse par ailleurs la configuration par défaut. Son but est simplement de collecter tous les messages de journal à l'échelle du

système.

La hiérarchie est alors

: 
any package, eventually -> $COLLECT -> $FILTER ->
$LOG

L'effet de tout cela est que les messages de journal, par défaut, remontent jusqu'au contexte $AnyEvent::Log::COLLECT où tous les messages aboutissent normalement, de là au $AnyEvent::Log::FILTER où les messages de journal avec une priorité plus basse que $ENV{PERL_ANYEVENT_VERBOSE} seront filtrés, puis au contexte $AnyEvent::Log::LOG pour être passés à "warn"

.

Cela facilite la définition d'un niveau de logging global (en modifiant $FILTER), mais permet toujours à d'autres contextes d'envoyer, par exemple, leurs messages de débogage et de traçage à la cible $LOG malgré le niveau de logging global, ou d' attacher des cibles de journal supplémentaires qui journalisent les messages, quel que soit le niveau de logging

global.

Cela facilite également la modification du logger warn par défaut ($LOG) en quelque chose qui journalise dans un fichier, ou l'attachement de cibles de logging supplémentaires (telles que le logging dans un fichier) en l'attachant à $FIL

La valeur se compose d'une ou plusieurs spécifications de contexte de journalisation séparées par ":" ou des espaces.
