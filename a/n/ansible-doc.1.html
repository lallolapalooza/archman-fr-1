Nom

ansible-doc - outil de documentation des plugins

Syntaxe

Utilisation : ansible-doc [-h] [--version] [-v] [-M CHEMIN_MODULES]
[--playbook-dir REPERTOIRE_BASE] [-t {become,cache,callback,cliconf,connection,httpapi,inventory,lookup,netconf,shell,vars,module,strategy,test,filter,role,keyword}] [-j] [-r CHEMIN_ROLES] [-e POINT_ENTREE | -s | -F | -l | --metadata-dump] [--no-fail-on-errors] [plugin ...]

DESCRIPTION

affiche des informations sur les modules installés dans les bibliothèques Ansible. Il affiche une liste concise des plugins et de leurs descriptions courtes, fournit un aperçu de leurs chaînes de DOCUMENTATION, et peut créer un court "extrait" qui peut être collé dans un playbook.

OPTIONS COMMUNES

Plugin

--metadata-dump

Pour usage interne uniquement. Affiche les métadonnées json pour toutes les entrées, ignore les autres options.

--no-fail-on-errors

Pour usage interne uniquement. Utilisé uniquement pour --metadata-dump. Ne pas échouer en cas d'erreurs. Rapporter le message d'erreur dans le JSON à la place.

--playbook-dir 'REPERTOIRE_BASE'

Comme cet outil n'utilise pas de playbooks, utilisez ceci comme répertoire de playbook substitut. Ceci définit le chemin relatif pour de nombreuses fonctionnalités, y compris roles/, group_vars/, etc.

--version

affiche le numéro de version du programme, l'emplacement du fichier de configuration, le chemin de recherche des modules configuré, l'emplacement des modules, l'emplacement de l'exécutable et quitte

-F, --list_files

Affiche les noms des plugins et leurs fichiers sources sans résumés (implique --list). Un argument fourni sera utilisé pour le filtrage, peut être un espace de noms ou un nom de collection complet.

-M, --module-path

prépende(z) un ou plusieurs chemins séparés par des deux-points à la bibliothèque de modules (par défaut {{ ANSIBLE_HOME ~ "/plugins/modules:/usr/share/ansible/plugins/modules" }}). Cet argument peut être spécifié plusieurs fois.

-e 'POINT_ENTREE', --entry-point 'POINT_ENTREE'

Sélectionne le point d'entrée pour les rôles.

-h, --help

affiche ce message d'aide et quitte

-j, --json

Change la sortie en format json.

-l, --list

Liste les plugins disponibles. Un argument fourni sera utilisé pour le filtrage, peut être un espace de noms ou un nom de collection complet.

-r, --roles-path

Le chemin vers le répertoire contenant vos rôles. Cet argument peut être spécifié plusieurs fois.

-s, --snippet

Affiche un extrait de playbook pour ces types de plugins : inventory, lookup, module

-t 'TYPE', --type 'TYPE'

Choisit le type de plugin (par défaut "module"). Les types de plugins disponibles sont : ('become', 'cache', 'callback', 'cliconf', 'connection', 'httpapi', 'inventory', 'lookup', 'netconf', 'shell', 'vars', 'module', 'strategy', 'test', 'filter', 'role', 'keyword')

-v, --verbose

Provoque l'affichage de messages de débogage plus détaillés par Ansible. L'ajout de plusieurs -v augmentera la verbosité, les plugins intégrés évaluent actuellement jusqu'à -vvvvvv. Un niveau raisonnable pour commencer est -vvv, le débogage de connexion peut nécessiter -vvvv. Cet argument peut être spécifié plusieurs fois.

ENVIRONNEMENT

Les variables d'environnement suivantes peuvent être spécifiées.

ANSIBLE_LIBRARY -- Remplace le chemin par défaut de la bibliothèque de modules Ansible

ANSIBLE_CONFIG -- Spécifie un emplacement de substitution pour le fichier de configuration Ansible

Beaucoup d'autres sont disponibles pour la plupart des options dans ansible.cfg

Pour une liste complète, consultez https://docs.ansible.com/. ou utilisez la commande ansible-config.

FICHIERS

/etc/ansible/ansible.cfg -- Fichier de configuration, utilisé s'il est présent

~/.ansible.cfg -- Fichier de configuration utilisateur, remplace le fichier de configuration par défaut s'il est présent

./ansible.cfg -- Fichier de configuration local (dans le répertoire de travail actuel) est supposé être 'spécifique au projet' et remplace les autres s'il est présent.

Comme mentionné ci-dessus, la variable d'environnement ANSIBLE_CONFIG remplacera toutes les autres.
