Nom

ansible-console - Console REPL pour exécuter des tâches Ansible.

SYNOPSIS

utilisation : ansible-console [-h] [--version] [-v] [-b]
[--become-method MÉTHODE_DEVIENIR] [--become-user UTILISATEUR_DEVIENIR] [-K | --become-password-file FICHIER_MOT_DE_PASSE_DEVIENIR] [-i INVENTAIRE] [--list-hosts] [-l SOUS_ENSEMBLE] [--flush-cache] [--private-key FICHIER_CLÉ_PRIVÉE] [-u UTILISATEUR_DISTANT] [-c CONNEXION] [-T TEMPS_MORT] [--ssh-common-args ARGUMENTS_ COMMUNS_SSH] [--sftp-extra-args ARGUMENTS_SUPPLÉMENTAIRES_SFTP] [--scp-extra-args ARGUMENTS_SUPPLÉMENTAIRES_SCP] [--ssh-extra-args ARGUMENTS_SUPPLÉMENTAIRES_SSH] [-k | --connection-password-file FICHIER_MOT_DE_PASSE_CONNEXION] [-C] [-D] [--vault-id ID_VAULT] [-J | --vault-password-file FICHIERS_MOT_DE_PASSE_VAULT] [-f FORKS] [-M CHEMIN_MODULE] [--playbook-dir REPERTOIRE_DE_BASE] [-e VARS_SUPPLÉMENTAIRES] [--task-timeout TEMPS_MORT_TÂCHE] [--step] [motif]

DESCRIPTION

Une REPL qui permet d'exécuter des tâches ad hoc sur un inventaire choisi depuis un joli shell avec complétion automatique intégrée (basé sur ansible-shell de dominis).

Elle prend en charge plusieurs commandes, et vous pouvez modifier sa configuration à l'exécution :

  • cd [motif] : changer d'hôte/groupe (vous pouvez utiliser des motifs d'hôtes, par ex. : app*.dc*:!app01*)
  • list : lister les hôtes disponibles dans le chemin courant
  • list groups : lister les groupes inclus dans le chemin courant
  • become : basculer le drapeau 'become'
  • ! : forcer le module shell au lieu du module ansible (!yum update -y)
  • verbosity [num] : définir le niveau de verbosité
  • forks [num] : définir le nombre de forks
  • become_user [utilisateur] : définir l'utilisateur 'become_user'
  • remote_user [utilisateur] : définir l'utilisateur distant
  • become_method [méthode] : définir la méthode d'escalade de privilèges
  • check [bool] : basculer le mode vérification
  • diff [bool] : basculer le mode différences
  • timeout [entier] : définir le temps d'attente des tâches en secondes (0 pour désactiver)
  • help [commande/module] : afficher la documentation pour la commande ou le module
  • exit : quitter ansible-console

OPTIONS COMMUNES

motif d'hôte

--become-method 'MÉTHODE_DEVIENIR'

méthode d'escalade de privilèges à utiliser (par défaut=sudo), utilisez ansible-doc -t become -l pour lister les choix valides.

--become-password-file 'FICHIER_MOT_DE_PASSE_DEVIENIR', --become-pass-file 'FICHIER_MOT_DE_PASSE_DEVIENIR'

Fichier de mot de passe pour 'become'

--become-user 'UTILISATEUR_DEVIENIR'

exécuter les opérations en tant que cet utilisateur (par défaut=root)

--connection-password-file 'FICHIER_MOT_DE_PASSE_CONNEXION', --conn-pass-file 'FICHIER_MOT_DE_PASSE_CONNEXION'

Fichier de mot de passe de connexion

--flush-cache

vider le cache des faits pour chaque hôte de l'inventaire

--list-hosts

affiche une liste des hôtes correspondants ; n'exécute rien d'autre

--playbook-dir 'REPERTOIRE_DE_BASE'

Comme cet outil n'utilise pas de playbooks, utilisez ceci comme répertoire de playbook substitut. Ceci définit le chemin relatif pour de nombreuses fonctionnalités, y compris les rôles/ group_vars/ etc.

--private-key 'FICHIER_CLÉ_PRIVÉE', --key-file 'FICHIER_CLÉ_PRIVÉE'

utilisez ce fichier pour authentifier la connexion

--scp-extra-args 'ARGUMENTS_SUPPLÉMENTAIRES_SCP'

spécifiez des arguments supplémentaires à passer uniquement à scp (par ex. -l)

--sftp-extra-args 'ARGUMENTS_SUPPLÉMENTAIRES_SFTP'

spécifiez des arguments supplémentaires à passer uniquement à sftp (par ex. -f, -l)

--ssh-common-args 'ARGUMENTS_COMMUNS_SSH'

spécifiez des arguments communs à passer à sftp/scp/ssh (par ex. ProxyCommand)

--ssh-extra-args 'ARGUMENTS_SUPPLÉMENTAIRES_SSH'

spécifiez des arguments supplémentaires à passer uniquement à ssh (par ex. -R)

--step

un pas à la fois : confirmer chaque tâche avant l'exécution

--task-timeout 'TEMPS_MORT_TÂCHE'

définir la limite de temps d'attente des tâches en secondes, doit être un entier positif.

--vault-id

l'identité de coffre-fort à utiliser. Cet argument peut être spécifié plusieurs fois.

--vault-password-file, --vault-pass-file

fichier de mot de passe de coffre-fort

--version

affiche le numéro de version du programme, l'emplacement du fichier de configuration, le chemin de recherche des modules configuré, l'emplacement du module, l'emplacement de l'exécutable et quitte

-C, --check

ne faites aucun changement ; essayez plutôt de prédire certains des changements qui pourraient survenir

-D, --diff

lors de la modification de fichiers et de modèles (petits), affichez les différences dans ces fichiers ; fonctionne très bien avec --check

-J, --ask-vault-password, --ask-vault-pass

demander le mot de passe du coffre-fort

-K, --ask-become-pass

demander le mot de passe d'escalade de privilèges

-M, --module-path

prépendez des chemins séparés par des deux-points aux bibliothèques de modules (par défaut={{ ANSIBLE_HOME ~ "/plugins/modules:/usr/share/ansible/plugins/modules" }}). Cet argument peut être spécifié plusieurs fois.

-T 'TEMPS_MORT', --timeout 'TEMPS_MORT'

remplacez le temps d'attente de connexion en secondes (par défaut dépend de la connexion)

-b, --become

exécutez les opérations avec 'become' (n'implique pas l'invite de mot de passe)

-c 'CONNEXION', --connection 'CONNEXION'

type de connexion à utiliser (par défaut=ssh)

-e, --extra-vars

définir des variables supplémentaires sous forme de clé=valeur ou YAML/JSON, si un nom de fichier est préfixé par @. Cet argument peut être spécifié plusieurs fois.

-f 'FORKS', --forks 'FORKS'

spécifiez le nombre de processus parallèles à utiliser (par défaut=5)

-h, --help

montre ce message d'aide et quitte

-i, --inventory, --inventory-file

spécifiez le chemin de l'inventaire des hôtes ou une liste d'hôtes séparée par des virgules. Cet argument peut être spécifié plusieurs fois.

-k, --ask-pass

demander le mot de passe de connexion

-l 'SOUS_ENSEMBLE', --limit 'SOUS_ENSEMBLE'

limitez davantage les hôtes sélectionnés à un motif supplémentaire

-u 'UTILISATEUR_DISTANT', --user 'UTILISATEUR_DISTANT'

connectez-vous en tant que cet utilisateur (par défaut=None)

-v, --verbose

fait qu'Ansible imprime plus de messages de débogage. L'ajout de multiples -v augmentera la verbosité, les plugins intégrés évaluent actuellement jusqu'à -vvvvvv. Un niveau raisonnable pour commencer est -vvv, le débogage de connexion pourrait nécessiter -vvvv. Cet argument peut être spécifié plusieurs fois.

ARGUMENTS

motif-hôte

Un nom de groupe dans l'inventaire, une séquence de caractères de style shell sélectionnant des hôtes dans l'inventaire ou toute combinaison des deux séparés par des virgules.

ENVIRONNEMENT

Les variables d'environnement suivantes peuvent être spécifiées.

ANSIBLE_INVENTORY -- Remplace les sources d'inventaire ansible par défaut

ANSIBLE_LIBRARY -- Remplace le chemin de la bibliothèque de modules ansible par défaut

ANSIBLE_CONFIG -- Spécifie l'emplacement de remplacement du fichier de configuration ansible

Beaucoup d'autres sont disponibles pour la plupart des options dans ansible.cfg

Pour une liste complète, consultez https://docs.ansible.com/. ou utilisez la commande ansible-config .

FICHIERS

/etc/ansible/hosts -- Fichier d'inventaire par défaut

/etc/ansible/ansible.cfg -- Fichier de configuration, utilisé s'il est présent

~/.ansible.cfg -- Fichier de configuration utilisateur, remplace la configuration par défaut s'il est présent

./ansible.cfg -- Fichier de configuration local (dans le répertoire de travail courant) supposé être « spécifique au projet » et remplace le reste s'il est présent.

Comme mentionné ci-dessus, la variable d'environnement ANSIBLE_CONFIG remplace toutes les autres.
