fork_call { CODE } @args, $cb->
(@res)
Exécute le bloc de code donné de manière asynchrone, en forkant. Tout ce que le bloc renvoie sera transféré au processus appelant (en sérialisant et désérialisant via Storable).

S'il y a des erreurs, alors $cb sera appelé sans aucun argument. Dans ce cas, soit $@ contient l'exception (et $! est sans rapport), soit $! contient un numéro d'erreur. Dans tous les autres cas, $@ sera "undef"i

ni.

Le bloc de code ne doit jamais appeler une fonction d'attente d'événements ou utiliser une programmation basée sur les événements qui pourrait faire s'exécuter des rappels enregistrés dans le processus

parent.

Avertissements Win32 : En raison des perls Windows natifs sans fin pourri et cassés (il n'y a aucun moyen de quitter proprement un processus enfant sur cette plate-forme sans tuer également le parent), vous devez vous assurer que votre programme principal ne se termine pas tant que des "fork_calls" sont encore en cours, sinon le programme ne se terminera pas. De plus, sur la plupart des plates-formes Windows, de la mémoire fuira pour chaque invocation. Nous sommes ouverts aux améliorations qui ne nécessitent pas de hackeries

XS.

Notez que le fork peut être coûteux dans les grands programmes (RSS 200 Mo+). Sur Windows, c'est abominablement lent, n'attendez pas plus de 5..20 forks/s sur cette plate-forme pourrie (notez que cela utilise les pseudo-threads de perl, évitez-les donc comme la

peste).

Exemple : E/S disque asynchrone pour les pauvres (mieux vaut utiliser AnyEvent::IO avec

IO::AIO). 
fork_call {
   open my $fh, "</etc/passwd"
      or die "passwd: $!";
   local $/;
   <$fh>
} sub {
   my ($passwd) = @_;
...
};

Cette fonction crée un objet spécial qui, lorsqu'il est détruit, exécutera le bloc de code.

C'est souvent pratique dans le style de passage de continuation pour nettoyer certaines ressources peu importe où vous sortez d'un

Bien que le code soit autorisé à lever des exceptions dans des conditions inhabituelles, il n'est pas défini si cette exception sera signalée (pour l'instant, le module Guard et l'implémentation pure perl d'AnyEvent essaient tous deux de signaler l'erreur et de continuer)

AnyEvent::Util::idn_nameprep $idn[,
$display]
Implémente l'algorithme de normalisation nameprep IDNA. Ou en fait l'algorithme UTS#46. Ou peut-être quelque chose de similaire - la réalité est compliquée entre IDNA2003, UTS#46 et IDNA2008. Si $display est vrai, alors le nom est préparé pour l'affichage, sinon il est préparé pour la recherche (par défaut).

Si vous n'avez aucune idée de ce que cela signifie, regardez plutôt "idn_to_asci

i".

Cette fonction est conçue pour éviter d'utiliser beaucoup de ressources - elle utilise environ 1 Mo

de RAM (la plupart en raison de Unicode::Normalize). De plus, les noms qui sont déjà « simples » ne
seront vérifiés que pour leur validité de base, sans le surcoût du traitement complet de nameprep.
$domainname = AnyEvent::Util::idn_to_ascii
$idn
Convertit la chaîne unicode donnée ($idn, nom de domaine international, par ex. 日本語。ＪＰ) en nom de domaine purement ASCII (c'est généralement appelé la transformation « IDN ToAscii »). Cette transformation est idempotente, ce qui signifie que vous pouvez l'appeler par précaution et qu'elle fera la bonne chose.

Contrairement à certaines autres implémentations de « ToAscii », celle-ci fonctionne sur des noms de domaine complets et ne devrait jamais échouer - si elle ne peut pas convertir le nom, elle le retournera

inchangé.

Cette fonction est un amalgame d'IDNA2003, UTS#46 et IDNA2008 - elle essaie d'être raisonnablement comp

atible avec d'autres implémentations, raisonnablement sécurisée, autant que les IDN peuvent l'être, et
raisonnablement efficace lorsqu'elle est confrontée à des IDN qui sont déjà des noms DNS valides.
