Nom

ansible-galaxy - Effectue diverses opérations liées aux rôles et aux collections.

SYNOPSIS

usage : ansible-galaxy [-h] [--version] [-v] TYPE ...

DESCRIPTION

Commande pour gérer les rôles et les collections Ansible.

Aucun des outils en ligne de commande n'est conçu pour être exécuté concurremment avec lui-même. Utilisez un planificateur externe et/ou un verrouillage pour vous assurer qu'il n'y a pas d'opérations en conflit.

OPTIONS COMMUNES

--version

affiche le numéro de version du programme, l'emplacement du fichier de configuration, le chemin de recherche des modules configuré, l'emplacement des modules, l'emplacement de l'exécutable et quitte

-h, --help

affiche ce message d'aide et quitte

-v, --verbose

Fait afficher à Ansible plus de messages de débogage. Ajouter plusieurs -v augmentera la verbosité, les plugins intégrés évaluent actuellement jusqu'à -vvvvvv. Un niveau raisonnable pour commencer est -vvv, le débogage de la connexion peut nécessiter -vvvv. Cet argument peut être spécifié plusieurs fois.

ACTIONS

collection
Effectue l'action sur une collection Ansible Galaxy. Doit être combiné avec une action supplémentaire comme init/install comme listé ci-dessous.
collection download
Télécharge les collections et leurs dépendances sous forme d'archive tarball pour une installation hors ligne.

--clear-response-cache

Efface le cache de réponse du serveur existant.

--no-cache

N'utilise pas le cache de réponse du serveur.

--pre

Inclut les versions pré-versionnées. Les pré-releases du versionnement sémantique sont ignorées par défaut

--timeout 'TIMEOUT'

Le temps d'attente pour les opérations contre le serveur galaxy, 60s par défaut.

--token 'API_KEY', --api-key 'API_KEY'

La clé API Ansible Galaxy qui peut être trouvée sur https://galaxy.ansible.com/me/preferences.

-c, --ignore-certs

Ignore les erreurs de validation des certificats SSL.

-n, --no-deps

Ne télécharge pas les collection(s) listées comme dépendances.

-p 'DOWNLOAD_PATH', --download-path 'DOWNLOAD_PATH'

Le répertoire dans lequel télécharger les collections.

-r 'REQUIREMENTS', --requirements-file 'REQUIREMENTS'

Un fichier contenant une liste de collections à télécharger.

-s 'API_SERVER', --server 'API_SERVER'

L'URL du serveur API Galaxy
collection init
Crée le squelette de structure d'un rôle ou d'une collection conforme au format de métadonnées Galaxy. Nécessite un nom de rôle ou de collection. Le nom de la collection doit être au format <namespace>.<collection>.

--collection-skeleton 'COLLECTION_SKELETON'

Le chemin vers un squelette de collection sur lequel la nouvelle collection doit être basée.

--init-path 'INIT_PATH'

Le chemin dans lequel la collection squelette sera créée. Le défaut est le répertoire de travail courant.

--timeout 'TIMEOUT'

Le temps d'attente pour les opérations contre le serveur galaxy, 60s par défaut.

--token 'API_KEY', --api-key 'API_KEY'

La clé API Ansible Galaxy qui peut être trouvée sur https://galaxy.ansible.com/me/preferences.

-c, --ignore-certs

Ignore les erreurs de validation des certificats SSL.

-e, --extra-vars

définit des variables supplémentaires sous forme de key=value ou YAML/JSON, si c'est un nom de fichier, préfixez avec @. Cet argument peut être spécifié plusieurs fois.

-f, --force

Force l'écrasement d'un rôle ou d'une collection existant

-s 'API_SERVER', --server 'API_SERVER'

L'URL du serveur API Galaxy

Construit un artefact de collection Ansible Galaxy qui peut être stocké dans un dépôt central comme Ansible Galaxy. Par défaut, cette commande construit depuis le répertoire de travail courant. Vous pouvez éventuellement passer le chemin d'entrée de la collection (où le galaxy.yml fichier est).

--output-path 'OUTPUT_PATH'

Le chemin dans lequel la collection est construite. Le défaut est le répertoire de travail courant.

--timeout 'TIMEOUT'

Le temps d'attente pour les opérations contre le serveur galaxy, 60s par défaut.

FICHIERS

/etc/ansible/ansible.cfg -- Fichier de configuration, utilisé s'il est présent

~/.ansible.cfg -- Fichier de configuration utilisateur, remplace la configuration par défaut s'il est présent

./ansible.cfg -- Fichier de configuration local (dans le répertoire de travail actuel) supposé être 'spécifique au projet' et remplace les autres s'il est présent.

Comme mentionné ci-dessus, la variable d'environnement ANSIBLE_CONFIG remplacera toutes les autres.
