NOM

AnyEvent::XMPP::Ext::VCard - VCards (XEP-0054 & XEP-0084)

SYNOPSIS

use AnyEvent::XMPP::Ext::VCard;
my $vcard = AnyEvent::XMPP::Ext::VCard->new;
$con->reg_cb (
   stream_ready => sub { $vcard->hook_on ($con) }
);
$vcard->retrieve ($con, 'elmex@jabber.org', sub {
   my ($jid, $vcard, $error) = @_;
   if ($error) {
      warn "couldn't get vcard for elmex@jabber.org: " . $error->string . "\n";
   } else {
      print "vCard nick for elmex@jabber.org: ".$vcard->{NICKNAME}."\n";
      print "Avatar hash for elmex@jabber.org: ".$vcard->{_avatar_hash}."\n";
   }
});
$vcard->store ($con, undef, { NICKNAME => 'net-xmpp2' }, sub {
   my ($error) = @_;
   if ($error) {
      warn "upload failed: " . $error->string . "\n";
   } else {
      print "upload successful\n";
   }
});
$disco->enable_feature ($vcard->disco_feature);

DESCRIPTION

Cette extension gère la définition et la récupération du VCard ainsi que les avatars basés sur le VCard.

Par exemple, voir la suite de tests d'AnyEvent::XMPP.

MÉTHODES

new (%args)
Crée une nouvelle extension vcard. Elle peut prendre un "cache" argument, qui doit être un hash lié qui doit être capable de sauvegarder les vcards récupérés. Si aucun "cache" n'est défini, un hash interne sera utilisé et les vcards seront récupérés à chaque redémarrage du programme. Les clés seront les JIDs nus (bare JIDs) stringprepped des personnes dont nous avons récupéré un vcard et la valeur sera une structure de données hash/tableau non cyclique représentant le vcard.

À propos de cette structure de données, voir ci-dessous à STRUCTURE VCARD.

Si vous voulez prendre en charge les avatars correctement, assurez-vous de connecter la connexion via la "hook_on" méthode.

hook_on ($con, $dont_retrieve_vcard)
$con doit être un objet de la classe AnyEvent::XMPP::Connection (ou dérivée). Une fois que l'extension vCard a été connectée à une connexion, elle ajoutera les informations d'avatar à toutes les stanzas de présence sortantes.

IMPORTANT : Vous devez vous connecter à la connexion AVANT qu'elle ne soit connectée. La stanza de présence initiale doit contenir les informations indiquant que nous prenons en charge les avatars. Le vcard sera automatiquement récupéré si la session n'a pas encore été démarrée. Sinon, vous devrez récupérer le vcard manuellement si vous le connectez après que l'événement "session_ready" a été reçu. Vous pouvez empêcher la récupération automatique en donnant une valeur vraie dans $dont_retrieve_vcard. Cependant, assurez-vous simplement de vous connecter à n'importe quelle connexion avant qu'elle ne soit connectée si vous voulez offrir la prise en charge des avatars sur celle-ci.

Le mieux est probablement de le faire comme ceci :

my $vcard = AnyEvent::XMPP::Ext::VCard->new;
$con->reg_cb (
   stream_ready => sub { $vcard->hook_on ($con) }
);
my_vcard ($con)
Cette méthode retourne le vcard pour le compte connecté par $con. Cela ne fonctionne que si le vcard a été (avec succès) récupéré. Si la connexion a été connectée, le vcard a été automatiquement récupéré.

Alternativement $con peut aussi être une chaîne représentant le JID d'un compte.

cache ([$newcache])
Voir aussi "new" à propos du sens des hashes de cache. Si aucun argument n'est donné, le cache actuel est retourné.
store ($con, $vcard, $cb)
Cette méthode stockera votre $vcard sur le serveur connecté. $cb est appelé soit lorsqu'une erreur s'est produite, soit lorsque le stockage a réussi. Si une erreur s'est produite, le premier argument n'est pas indéfini et contient un objet AnyEvent::XMPP::Error::IQ .

$con devrait être un AnyEvent::XMPP::Connection ou un objet d'une classe dérivée.

$vcard a une structure de données comme décrit ci-dessous dans STRUCTURE VCARD.

retrieve ($con, $jid, $cb)
Cette méthode récupérera le vCard pour $jid via la connexion $con. Si $jid est indéfini, le vCard de vous-même est récupéré. Le callback $cb est appelé lorsqu'une erreur s'est produite ou lorsque le vcard a été récupéré. Le premier argument du callback sera le JID auquel le vCard appartient, le deuxième argument est le vCard lui-même (comme décrit dans STRUCTURE VCARD ci-dessous) et le troisième argument est l'erreur, si une erreur s'est produite (undef sinon).

STRUCTURE VCARD

Comme il n'y a actuellement pas de belles implémentations DOM en Perl et que je n'aime pas du tout l'API DOM en général, ce module a une simple structure de données Perl sans cycles pour représenter le vCard.

D'abord un exemple : Un hash vCard récupéré peut ressembler à ceci :

{
  'URL' => ['http://www.ta-sa.org/'],
  'ORG' => [{
             'ORGNAME' => 'nethype GmbH'
           }],
  'N' => [{
           'FAMILY' => 'Redeker'
         }],
  'EMAIL' => ['elmex@ta-sa.org'],
  'BDAY' => ['1984-06-01'],
  'FN' => ['Robin'],
  'ADR' => [
     {
       HOME => undef,
       'COUNTRY' => 'Germany'
     },
     {
        WORK => undef,
        COUNTRY => 'Germany',
        LOCALITY => 'Karlsruhe'
     }
  ],
  'NICKNAME' => ['elmex'],
  'ROLE' => ['Programmer']
}

Les clés représentent l'élément de premier niveau d'un vCard, les valeurs sont toujours des références de tableau contenant une ou plusieurs valeurs pour la clé. Si la valeur est une référence de hash, sa valeur ne sera pas une référence de tableau mais soit undef soit des valeurs simples.

Les valeurs des clés de premier niveau sont toutes des références de tableau car des champs comme "ADR" peuvent apparaître plusieurs fois.

Consultez XEP-0054 pour une explication de ce que ces champs signifient ou contiennent.

Il y a des champs spéciaux dans cette structure pour gérer les avatars : "_avatar" contient les données binaires pour l'image de l'avatar. "_avatar_hash" contient le hash sha1 hexadécimal des données binaires de l'image. "_avatar_type" contient le type mime de l'avatar.

Si vous voulez stocker le vcard, vous n'avez qu'à définir "_avatar" et "_avatar_type" si vous voulez stocker un avatar.

ÉVÉNEMENTS

L'extension vcard émettra ces événements :

retrieve_vcard_error => $iq_error
Lorsqu'une récupération de vCard n'a pas réussi, cet événement est émis. Cela est nécessaire car certaines récupérations peuvent se produire automatiquement.
vcard => $jid, $vcard
Chaque fois qu'un vCard est récupéré, soit automatiquement soit manuellement, cet événement est émis avec le vCard récupéré.
