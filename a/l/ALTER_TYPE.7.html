SYNOPSI

DESCRIPTIO

N

ALTER TYPE modifie la définition d'un type existant. Il existe plusieurs sous-formes

:

OWNE

R
Cette forme modifie le propriétaire du
type.

RENAM

E
Cette forme modifie le nom du
type.

SET

SCHEMA
Cette forme déplace le type vers un autre
schéma.

RENAME

ATTRIBUTE
Cette forme n'est utilisable qu'avec les types composites. Elle modifie le nom d'un attribut individuel du
type.

ADD

ATTRIBUTE
Cette forme ajoute un nouvel attribut à un type composite, en utilisant la même syntaxe que CREATE T
YPE.

DROP ATTRIBUTE [ IF EXISTS

]
Cette forme supprime un attribut d'un type composite. Si IF EXISTS est spécifié et que l'attribut n'existe pas, aucune erreur n'est levée. Dans ce cas, une notification est émise à la
place.

ALTER ATTRIBUTE ... SET DATA

TYPE
Cette forme modifie le type d'un attribut d'un type
composite.

ADD VALUE [ IF NOT EXISTS ] [ BEFORE | AFTER

]
Cette forme ajoute une nouvelle valeur à un type enum. La position de la nouvelle valeur dans l'ordre de l'enum peut être spécifiée comme étant BEFORE ou AFTER l'une des valeurs existantes. Sinon, le nouvel élément est ajouté à la fin de la liste des valeurs.

Si IF EXISTS est spécifié, ce n'est pas une erreur si le type contient déjà la

nouvelle valeur : une notification est émise mais aucune autre action n'est en
treprise. Sinon, une erreur se produira si la nouvelle valeur est déjà présente.

RENAME

VALUE
Cette forme renomme une valeur d'un type enum. La position de la valeur dans l'ordre de l'enum n'est pas affectée. Une erreur se produira si la valeur spécifiée n'est pas présente ou si le nouveau nom est déjà
présent.

SET ( property = value [, ... ]

)
Cette forme n'est applicable qu'aux types de base. Elle permet l'ajustement d'un sous-ensemble des propriétés du type de base qui peuvent être définies dans CREATE TYPE. Plus précisément, les propriétés suivantes peuvent être modifiées :
•RECEIVE peut être défini au nom d'une fonction d'entrée binaire, ou NONE pour supprimer la fonction d'entrée binaire du type. L'utilisation de cette option nécessite le privilège superutilisateur
.
•SEND peut être défini au nom d'une fonction de sortie binaire, ou NONE pour supprimer la fonction de sortie binaire du type. L'utilisation de cette option nécessite le privilège superutilisateur
.
•TYPMOD_IN peut être défini au nom d'une fonction d'entrée de modificateur de type, ou NONE pour supprimer la fonction d'entrée de modificateur de type du type. L'utilisation de cette option nécessite le privilège superutilisateur
.
•TYPMOD_OUT peut être défini au nom d'une fonction de sortie de modificateur de type, ou NONE pour supprimer la fonction de sortie de modificateur de type du type. L'utilisation de cette option nécessite le privilège superutilisateur
.
•ANALYZE peut être défini au nom d'une fonction de collecte de statistiques spécifique au type, ou NONE pour supprimer la fonction de collecte de statistiques du type. L'utilisation de cette option nécessite le privilège superutilisateur
.
•SUBSCRIPT peut être défini au nom d'une fonction de gestion d'indexation spécifique au type, ou NONE pour supprimer la fonction de gestion d'indexation du type. L'utilisation de cette option nécessite le privilège superutilisateur
.
•STORAGE peut être défini à plain, extended, external, ou main (voir la section 66.2 pour plus d'informations sur ce que cela signifie). Cependant, le passage de plain à un autre paramètre nécessite le privilège superutilisateur (car cela nécessite que toutes les fonctions C du type soient prêtes pour TOAST), et le passage à plain depuis un autre paramètre n'est pas du tout autorisé (car le type peut déjà avoir des valeurs TOASTées présentes dans la base de données). Notez que la modification de cette option ne change pas en soi les données stockées, elle définit simplement la stratégie TOAST par défaut à utiliser pour les colonnes de table créées ultérieurement. Voir ALTER TABLE (ALTER_TABLE(7)) pour modifier la stratégie TOAST des colonnes de table
existantes.

Voir CREATE TYPE (CREATE_TYPE(7)) pour plus de détails sur ces propriétés de type. Notez que, le cas échéant, une modificati

on de ces propriétés pour un type de base sera propa
gée automatiquement aux domaines basés sur ce type.

Les actions ADD ATTRIBUTE, DROP ATTRIBUTE et ALTER ATTRIBUTE peuvent être combinées en une liste de plusieurs altérations à appliquer en parallèle. Par exemple, il est possible d'ajouter plusieurs attributs et/ou de modifier le type de plusieurs attributs dans une seule

commande.

Vous devez être propriétaire du type pour utiliser ALTER TYPE. Pour modifier le schéma d'un type, vous devez également avoir le privilège CREATE sur le nouveau schéma. Pour modifier le propriétaire, vous devez pouvoir exécuter SET ROLE vers le nouveau rôle propriétaire, et ce rôle doit avoir le privilège CREATE sur le schéma du type. (Ces restrictions garantissent que la mod

ification du propriétaire ne permet rien que vous ne pourriez faire en supprimant et recréant le type. Cependant, un superutilisateur peut modifier la propriété de
n'importe quel type.) Pour ajouter un attribut ou modifier un type d'attribut, vous devez également avoir le privilège USAGE sur le type de données de l'attribut.

NOTE

S

Si ALTER TYPE ... ADD VALUE (la forme qui ajoute une nouvelle valeur à un type enum) est exécuté à l'intérieur d'un bloc de transaction, la nouvelle valeur ne peut pas être utilisée avant que la transaction ait été

validée.

Les comparaisons impliquant une valeur enum ajoutée seront parfois plus lentes que les comparaisons impliquant uniquement les membres originaux du type enum. Cela se produira généralement seulement si BEFORE ou AFTER est utilisé pour définir la position de tri de la nouvelle valeur ailleurs qu'à la fin de la liste. Cependant, cela se produira parfois même si la nouvelle valeur est ajoutée à la fin (cela se produit si le compteur d'OID « a débordé » depuis la création originale du type enum). Le ralentissement est généralement insignifiant ; mais si cela compte, les performances optimales peuvent être récupérées en supprimant et en recréantg de l'énumération,

ou en vidant et restaur
ant la base de données.
