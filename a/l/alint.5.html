NOM

alint - étiquettes et tags de linting

DESCRIPTION

Une étiquette et un tag sont 2 attributs donnés à chaque test dans alint, une étiquette est composée d'une collection de mots séparés par des tirets et elle est destinée à transmettre l'idée générale de ce que fait le test. Un tag est une chaîne composée de AL suivie d'un entier, ceux-ci étant attribués dans l'ordre croissant à mesure que de nouveaux tests sont créés, mais sans jamais réutiliser les anciens.

les tests peuvent être ignorés en définissant une variable d'environnement composée de SKIP_ + l'étiquette en majuscules avec les tirets remplacés par des underscores, ou en définissant une variable d'environnement composée de SKIP_ + le tag.

Gravité

La gravité est attribuée à chaque tag et indique la gravité de la violation trouvée :

Sérieuse (S)

Causera des problèmes lors de la compilation ou lorsque le paquet est livré aux utilisateurs. Devrait être corrigée immédiatement.

Importante (I)

Peut causer des problèmes lors de la compilation ou lorsque le paquet est livré aux utilisateurs dans certaines situations. Devrait être corrigée bientôt.

Mineure (M)

Ne causera pas directement de problèmes lors de la compilation ou lorsque le paquet est livré aux utilisateurs. Devrait être corrigée quand c'est pratique.

Cela inclut également les problèmes de style qui sont dictés dans le fichier CODINGSTYLE.md.

STYLE (T)

Ne causera aucun problème, il s'agit de problèmes de style spécifiques pertinents pour un développeur ou contributeur concerné. le APKBUILD_STYLE variable peut être définie à une valeur spécifique pour activer un sous-ensemble de vérifications que le développeur ou l'utilisateur spécifique utilise.

Lorsqu'une vérification appartient à cette catégorie, cette page de manuel fournit également des informations sur quels développeurs utilisent une vérification de style spécifique, car les développeurs peuvent parfois vouloir à la fois avoir la même vérification effectuée sur leur propre style.

Les valeurs actuellement valides sont :

•
leo (linting de style pour leo)

Certitude

La certitude est attribuée à chaque tag et indique à quel point un test est certain que la violation trouvée n'est pas un faux positif

Certaine (C)

Le test est certain qu'il ne s'agit pas d'un faux positif

Possible (P)

Le test n'est pas certain qu'il s'agit d'un faux positif, mais il y a de fortes chances que ce ne soit pas le cas

ÉTIQUETTES TAGS (aports-lint)

Les étiquettes et tags suivants sont utilisés par le aports-lint programme.

duplicate-package [AL22]

Le paquet introduit est déjà présent dans un autre dépôt. Résolvez le conflit en :

  • Si le paquet dans le dépôt le plus haut a des modifications plus récentes, fusionnez-les.
  • Puis supprimez le paquet dans le dépôt supérieur.

Les paquets en double se masqueront les uns les autres dans le dépôt et celui avec la version la plus élevée gagnera, cela peut aussi causer la compilation de programmes contre la mauvaise version d'un paquet. Par exemple : si main/foo-1-r0 et testing/foo-2-r0 existent et main/bar est mis à jour vers la version 2 qui requiert foo>=2-r0 alors cela échouera car il ne trouvera trouver main/foo-1-r0 et non testing/foo-2-r0.

Sévérité : Sérieuse, Certitude : Certaine

upper-repo-depends [AL16]

Le paquet dépend d'un paquet d'un dépôt supérieur. Le paquet doit être déplacé vers le dépôt supérieur ou la dépendance doit être déplacée vers le dépôt où se trouve le paquet.

Les paquets ne peuvent pas dépendre d'un paquet d'un dépôt supérieur. Les paquets dans main ne peuvent pas dépendre de paquets d'autres dépôts. Les paquets dans community peuvent dépendre de main et d'eux-mêmes uniquement. Les paquets dans testing peuvent dépendre de main, community et d'eux-mêmes uniquement. Les paquets dans unmaintained peuvent dépendre de paquets de n'importe quel dépôt sauf non-free.

Sévérité : Sérieuse, Certitude : Certaine

duplicate-depends [AL17]

L'APKBUILD a des dépendances dupliquées. L'une d'entre elles doit être supprimée.

Déclarer des dépendances dupliquées est superflu.

Sévérité : Mineure, Certitude : Certaine

upper-repo-makedepends [AL18]

Le paquet a des makedepends sur un paquet d'un dépôt supérieur. Le paquet doit être déplacé vers le dépôt supérieur ou la dépendance doit être déplacée vers le dépôt où se trouve le paquet.

Les paquets ne peuvent pas avoir de makedepends sur un paquet d'un dépôt supérieur. Les paquets dans main ne peuvent pas avoir de makedepends sur des paquets d'autres dépôts. Les paquets dans community ne peuvent dépendre que de main et d'eux-mêmes. Les paquets dans testing ne peuvent avoir de makedepends que sur main, community et eux-mêmes. Les paquets dans unmaintained peuvent avoir de makedepends sur des paquets de n'importe quel dépôt sauf non-free.

Sévérité : Sérieuse, Certitude : Certaine

duplicate-makedepends [AL19]

L'APKBUILD a des makedepends dupliqués. L'un d'entre eux doit être supprimé.

Déclarer des dépendances dupliquées est superflu.

Sévérité : Mineure, Certitude : Certaine

upper-repo-checkdepends [AL20]

Le paquet a des checkdepends sur un paquet d'un dépôt supérieur. Le paquet doit être déplacé vers le dépôt supérieur ou la dépendance doit être déplacée vers le dépôt où se trouve le paquet.

Les paquets ne peuvent pas avoir de checkdepends sur un paquet d'un dépôt supérieur. Les paquets dans main ne peuvent pas avoir de checkdepends sur des paquets d'autres dépôts. Les paquets dans community ne peuvent avoir de checkdepends que sur main et eux-mêmes. Les paquets dans testing ne peuvent avoir de checkdepends que sur main, community et eux-mêmes. Les paquets dans unmaintained peuvent avoir de checkdepends sur des paquets de n'importe quel dépôt sauf non-free.

Sévérité : Sérieuse, Certitude : Certaine

duplicate-checkdepends [AL21]

L'APKBUILD a des checkdepends dupliqués. L'un d'entre eux doit être supprimé.

Déclarer des dépendances dupliquées est superflu.

Sévérité : Mineure, Certitude : Certaine

pkgname-dirname-mismatch [AL23]

La variable pkgname de l'APKBUILD a la valeur foo mais le répertoire dans lequel l'APKBUILD est trouvé n'est pas nommé foo

Sévérité : Importante, Certitude : Certaine

depends-makedepends-checkdepends-overlap [AL24]

Un paquet est présent dans 2 à 3 des 3 types de dépendances suivantes : depends, makedepends et checkdepends. Tous sont installés lors de la création du paquet, veuillez ne le spécifier qu'une seule fois à l'emplacement du dénominateur commun le plus bas.

Sévérité : Importante, Certitude : Certaine

deprecated-packages [AL58]

Un paquet est présent dans depends, makedepends ou checkdepends qui est considéré comme obsolète.

Les paquets obsolètes sont codés en dur dans aports-lint avec la possibilité d'en ajouter des personnalisés via la variable CUSTOM_DEPRECATED_PACKAGES. Ils sont considérés comme ne convenant plus à l'utilisation dans Alpine Linux et doivent être supprimés IMMÉDIATEMENT.

Sévérité : Sérieuse, Certitude : Certaine

missing-patch-description [AL56]

Un patch spécifié dans `$sources` n'a pas de description. La description devrait au minimum expliquer pourquoi le patch est nécessaire.

Sévérité : Mineure, Certitude : Certaine

ÉTIQUETTES TAGS (apkbuild-lint)

Les étiquettes et tags suivants sont utilisés par le programme apkbuild-lint

default-builddir-value [AL1]

La valeur de builddir correspond à la valeur par défaut de $srcdir/$pkgname-$pkgver. La déclaration builddir peut être supprimée.

À partir de la version v2.29.0 (version Alpine 3.3) de abuild la valeur est définie automatiquement.

Certains paquets sont exclus de cela car ils sont construits par abuild lors du bootstrap et sont donc construits avec le pkgname plus le suffixe -bootstrap.

Plus de paquets peuvent être ajoutés aux exceptions en passant une liste séparée par des espaces dans la variable CUSTOM_BOOTSTRAP_PACKAGES.

Sévérité : Mineure, Certitude : Certaine

unnecessary-return-1 [AL2]

L'APKBUILD a des instructions || return 1 . Elles peuvent être supprimées en toute sécurité.

À partir de la version v2.15.0 de abuild le processus de construction est exécuté avec set -e ajoutant effectivement un || return 1 à chaque commande.

Sévérité : Mineure, Certitude : Certaine

pkgname-quoted [AL3]

La variable pkgname de l'APKBUILD est entre guillemets. Elle ne doit pas l'être.

Sévérité : Mineure, Certitude : Certaine

pkgver-quoted [AL4]

La variable pkgver de l'APKBUILD est entre guillemets. Elle ne doit pas l'être.

Sévérité : Mineure, Certitude : Certaine

empty-variable [AL5]

L'APKBUILD a des variables dont la valeur est vide, elles peuvent être supprimées en toute sécurité.

Les variables vides peuvent être supprimées pour rendre l'APKBUILD plus petit et plus concis.

Sévérité : Mineure, Certitude : Certaine

custom-variable [AL6]

L'APKBUILD a des variables personnalisées qui ne sont pas préfixées d'un soulignement. Préfixez les variables d'un soulignement.

Les variables qui n'affectent pas le comportement de abuild devraient être préfixées d'un soulignement pour que les mainteneurs et les contributeurs puissent facilement distinguer leur importance.

Sévérité : Importante, Certitude : Certaine

indent-tabs [AL7]

L'APKBUILD utilise des espaces au lieu de tabulations pour l'indentation. Remplacez les espaces par des tabulations.

Les APKBUILD utilisent des caractères de tabulation (t) et non des espaces pour l'indentation.

Sévérité : Importante, Certitude : Certaine

trailing-whitespace [AL8]

L'APKBUILD a des caractères d'espacement blancs en fin de ligne. Supprimez-les.

L'espacement blanc en fin de ligne est superflu.

Sévérité : Importante, Certitude : Certaine

backticks-usage [AL25]

L'APKBUILD utilise des accents graves pour exécuter une commande shell, utilisez `$()` à la place.

Sévérité : Sérieuse, Certitude : Possible

function-keyword [AL9]

L'APKBUILD utilise le mot-clé function pour déclarer une fonction. Utilisez function() à la place.

le mot-clé function est un bashisme. abuild utilise un shell conforme à Posix avec le mot-clé local .

Sévérité : Sérieuse, Certitude : Certaine

space-before-function-parenthesis [AL10]

L'APKBUILD a un caractère espace entre le nom d'une fonction et la parenthèse qui indique qu'il s'agit d'une fonction. Supprimez l'espace superflu.

Sévérité : Mineure, Certitude : Certaine

space-after-function-parenthesis [AL11]

L'APKBUILD n'a pas d'espace après la parenthèse de la fonction ou en a plus d'un. Utilisez un seul espace après la parenthèse de la fonction.

Sévérité : Mineure, Certitude : Certaine

newline-opening-brace [AL12]

L'APKBUILD a un saut de ligne avant l'accolade ouvrante d'une fonction. Placez l'accolade ouvrante sur la même ligne que la déclaration avec un espace après la parenthèse de la fonction.

Sévérité : Mineure, Certitude : Certaine

superfluous-cd-builddir [AL13]

L'APKBUILD a des instructions cd "$builddir" qui sont superflues. Supprimez-les.

À partir de la version v3.3.0 de abuild les fonctions prepare, build, check et package changent automatiquementtiquement ont leur répertoire de travail défini à la valeur de builddir. Il est également possible qu'il y ait 2 cd "$builddir" instructions l'une après l'autre.

Sévérité : Mineure, Certitude : Possible

pkgname-has-uppercase [AL14]

pkgname contient des caractères majuscules, pkgname ne doit contenir que des caractères minuscules.

D'autres pkgnames peuvent être ajoutés aux exceptions en passant une liste séparée par des espaces dans la variable CUSTOM_UPPERCASE_PKGNAMES.

Sévérité : Sérieuse, Certitude : Certaine

pkgver-has-pkgrel [AL15]

pkgver contient -r suivi d'un nombre, ce qui est réservé pour la version d'un paquet tel que défini par la variable pkgrel .

Sévérité : Sérieuse, Certitude : Certaine

_builddir-is-set [AL26]

_builddir est défini à la place de builddir, qui est une ancienne variable d'avant que builddir n'existe comme concept compris par abuild.

Sévérité : Sérieuse, Certitude : Certaine

literal-integer-is-quoted [AL28]

Une déclaration de variable contenant uniquement des entiers ne devrait pas être entre guillemets.

Sévérité : Mineure, Certitude : Certaine

pkgname-used-in-source [AL29]

"$pkgname" est utilisé dans l'URL source. Cela lie étroitement le pkgname au nom en amont, ce qui rend plus difficile le renommage des paquets ou la création de variantes spécialisées de paquets.

Utilisez plutôt le nom en amont entièrement écrit. Cela ne compte que pour l'URL elle-même, pas pour le préfixe du nom de l'archive locale.

Sévérité : Mineure, Certitude : Certaine

double-underscore-in-variable [AL30]

L'utilisation de doubles underscores dans les variables est interdite, utilisez toujours un seul underscore pour les variables qui ne sont pas utilisées par abuild.

Sévérité : Mineure, Certitude : Certaine

variable-capitalized [AL31]

Les variables ne devraient pas contenir de lettres majuscules

Sévérité : Mineure, Certitude : Certaine

braced-variable [AL32]

La variable a des accolades autour d'elle alors que ce n'est pas requis, supprimez les accolades.

Sévérité : Mineure, Certitude : Possible

cpan-variable [AL35]

Les variables `cpandepends`, `cpanmakedepends` et `cpancheckdepends` ont été créées par le programme apkbuild-cpan mais sont maintenant dépréciées et leur contenu doit être fusionné avec le contenu de leurs variables respectives.

Sévérité : Mineure, Certitude : Certaine

overwrite-xflags [AL36]

Ne pas écraser `CFLAGS`, `GOFLAGS`, `CPPFLAGS`, `CXXFLAGS` et `FFLAGS`. Ces drapeaux sont généralement définis en dehors de l'APKBUILD et ne devraient pas être écrasés car ils contiennent des drapeaux importants qui ne devraient pas être ignorés. Étendez plutôt la variable. Par exemple : `CFLAGS="$CFLAGS .."`

Il est toujours possible de modifier les drapeaux en utilisant la substitution de variable. Par exemple : `CFLAGS="${CFLAGS/-Dflag}"`

Cette liste pourrait être étendue à mesure que d'autres variables sont trouvées qui ne devraient pas être écrasées.

Sévérité : Sérieuse, Certitude : Certaine

invalid-option [AL49]

Une option dans la variable option= a une valeur qui n'est pas utilisée par abuild, bien que cela ne causera probablement aucun problème, il est considéré comme bonne pratique de la supprimer.

La variable VALID_CUSTOM_OPTIONS peut être utilisée pour indiquer d'autres options acceptables, elle prend une liste séparée par des espaces.

Sévérité : Mineure, Certitude : Certaine

missing-default-prepare [AL54]

La fonction prepare() est définie mais un appel à default_prepare (qui applique tous les patchs dans source=) est manquant. Veuillez ajouter default_prepare au bon endroit dans la définition de prepare().

Sévérité : Sérieuse, Certitude : Certaine

invalid-arch [AL57]

La variable 'arch' dans l'APKBUILD a une valeur invalide, les seules options sont le nom des architectures utilisées par Alpine Linux et les chaînes 'noarch' et 'all'.

Les architectures acceptables sont prises depuis /usr/share/abuild/functions.sh car ce sont celles reconnues par abuild et donc par Alpine Linux comme architectures valides, si vous avez d'autres architectures, lisez ci-dessous.

La variable CUSTOM_VALID_ARCHES peut être utilisée pour indiquer d'autres architectures à considérer comme valides, elle prend une liste séparée par des espaces.

Sévérité : Sérieuse, Certitude : Certaine

bad-version [AL61]

Le pkgver correspond à une expression régulière pour une mauvaise version, cela signifie que le pkgver est une version indésirable, comme une branche de test/expérimentale.

La variable CUSTOM_BAD_VERSIONS peut être utilisée pour ajouter plus de combinaisons pkgname@regexes..., séparées par des espaces.

Sévérité : Importante, Certitude : Certaine

volatile-source [AL62]

L'URL donnée est volatile et changera de somme de contrôle en raison de facteurs imprévus.

L'exemple le plus courant est les pull-requests GitHub/demandes de fusion GitLab qui changent au fur et à mesure que l'auteur pousse des commits, un autre est les commits GitHub qui pourraient changer quand GitHub change leur version de Git dans leur infrastructure.

Sévérité : Sérieuse, Certitude : Certaine

LABELS TAGS (initd-lint)

unexpected-shebang-line [AL33]

Les fichiers de service OpenRC doivent utiliser `#!/sbin/openrc-run` pour fonctionner correctement. Voir https://github.com/OpenRC/openrc/blob/master/service-script-guide.md#syntax-of-service-scripts pour plus de détails.

Sévérité : Importante, Certitude : Certaine

custom-start-stop-function [AL34]

Il est déconseillé d'écrire des fonctions de démarrage / arrêt personnalisées pour les fichiers de service. Dans la plupart des cas, il suffit de définir `command`, `command_args` et `pidfile`. Voir https://github.com/OpenRC/openrc/blob/master/service-script-guide.md#dont-write-your-own-startstop-functions pour plus d'informations.

Sévérité : Importante, Certitude : Certaine
