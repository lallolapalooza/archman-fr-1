al_load_bitmap_flags(3) Manuel des fonctions de bibliothèque al_load_bitmap_flags(3)

NOM

al_load_bitmap_flags - API Allegro 5

SYNTAXE

#include <allegro5/allegro.h>
ALLEGRO_BITMAP *al_load_bitmap_flags(const char *filename, int flags)

DESCRIPTION

Charge un fichier image dans un nouvel objet ALLEGRO_BITMAP(3). Le type de fichier est déterminé par al_identify_bitmap(3), en utilisant l'extension comme solution de repli si l'identification n'est pas possible.

Retourne NULL en cas d'erreur.

Le paramètre flags peut être une combinaison des constantes suivantes :

ALLEGRO_NO_PREMULTIPLIED_ALPHA
Par défaut, Allegro pré-multiplie le canal alpha d'une image avec les données de couleur de l'image lors du chargement. Typiquement, cela ressemblerait à ceci :
r = get_float_byte();
g = get_float_byte();
b = get_float_byte();
a = get_float_byte();
r = r * a;
g = g * a;
b = b * a;
set_image_pixel(x, y, r, g, b, a);

La raison de cela peut être vue dans l'exemple Allegro ex_premulalpha, c'est-à-dire que l'utilisation de l'alpha pré-multiplié donne des résultats de couleur plus précis dans certains cas. Pour utiliser le mélange alpha avec des images chargées avec alpha pré-multiplié, vous utiliseriez le mode de mélange par défaut, qui est défini avec al_set_blender(ALLEGRO_ADD, ALLEGRO_ONE, ALLEGRO_INVERSE_ALPHA).

Le drapeau ALLEGRO_NO_PREMULTIPLIED_ALPHA étant défini garantira que les images ne sont pas chargées avec alpha pré-multiplié, mais sont chargées avec des valeurs de couleur directes de l'image. Cela ressemble à ceci :

r = get_float_byte();
g = get_float_byte();
b = get_float_byte();
a = get_float_byte();
set_image_pixel(x, y, r, g, b, a);

Pour dessiner une telle image en utilisant un mélange alpha régulier, vous utiliseriez al_set_blender(ALLEGRO_ADD, ALLEGRO_ALPHA, ALLEGRO_INVERSE_ALPHA) pour définir le mélangeur correct. Cela a quelques mises en garde. Premièrement, comme mentionné ci-dessus, dessiner une telle image peut entraîner un mélange de couleurs moins précis (lorsque l'image est dessinée avec un filtrage linéaire activé, les bords seront plus sombres qu'ils ne devraient l'être). Deuxièmement, le comportement est quelque peu déroutant, ce qui est expliqué dans l'exemple ci-dessous.

// Charger et créer des bitmaps avec un canal alpha
al_set_new_bitmap_format(ALLEGRO_PIXEL_FORMAT_ANY_32_WITH_ALPHA);
// Charger une bitmap avec de l'alpha
bmp = al_load_bitmap("some_alpha_bitmap.png");
// Nous allons dessiner dans ce tampon, puis dessiner ce tampon à l'écran
tmp_buffer = al_create_bitmap(SCREEN_W, SCREEN_H);
// Définir le tampon comme cible et le nettoyer
al_set_target_bitmap(tmp_buffer);
al_clear_to_color(al_map_rgba_f(0, 0, 0, 1));
// Dessiner la bitmap dans le tampon temporaire
al_draw_bitmap(bmp, 0, 0, 0);
// Enfin, dessiner le tampon à l'écran
// La sortie semblera incorrecte (peut nécessiter une inspection approfondie
// selon la bitmap -- elle peut aussi être très évidente)
al_set_target_bitmap(al_get_backbuffer(display));
al_draw_bitmap(tmp_buffer, 0, 0, 0);

Pour expliquer davantage, si vous avez un pixel avec une alpha de 0.5, et que vous utilisez (ALLEGRO_ADD, ALLEGRO_ALPHA, ALLEGRO_INVERSE_ALPHA) pour le mélange, la formule est :

a = da * dst + sa * src

Cela se développe en :

result_a = dst_a * (1-0.5) + 0.5 * 0.5

Ainsi, si vous dessinez l'image dans le tampon temporaire, elle est mélangée une fois, résultant en une alpha de 0.75, puis dessinée à nouveau sur l'écran, mélangée de la même manière, résultant en un pixel ayant une alpha de 0.1875.

ALLEGRO_KEEP_INDEX
Charge les indices de palette des fichiers .bmp et .pcx de 8 bits au lieu des couleurs RVB. Depuis 5.1.0.
ALLEGRO_KEEP_BITMAP_FORMAT
Force le ALLEGRO_BITMAP(3) résultant à utiliser le même format que le fichier.

Ceci n'est pas encore pris en compte.

Note : la bibliothèque Allegro de base ne prend en charge aucun format de fichier image par défaut. Vous devez utiliser le module allegro_image, ou enregistrer votre propre gestionnaire de format.
