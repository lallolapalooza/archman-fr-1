également disposer du privilège USAGE sur le type de données.

Le nom (éventuellement qualifié par le schéma) d'une table distante existante à modifier. Si ONLY est spécifié avant le nom de la table, seule cette table est modifiée. Si ONLY n'est pas spécifié, la table et toutes ses tables descendantes (le cas échéant) sont modifiées. En option, * peut être spécifié après le nom de la table pour indiquer explicitement que les tables descendantes sont
incluses.

CASCADE

Supprime automatiquement les objets qui dépendent de la colonne ou de la contrainte supprimée (par exemple, les vues faisant référence à la colonne), et à leur tour tous les objets qui dépendent de ces objets (voir la Section 5.15).

RESTRICT

Refuse de supprimer la colonne ou la contrainte s'il existe des objets dépendants. C'est le comportement par défaut.

trigger_name

Nom d'un déclencheur unique à désactiver ou à activer.

ALL

Désactive ou active tous les déclencheurs appartenant à la table distante. (Cela nécessite le privilège de superutilisateur si l'un des déclencheurs est un déclencheur généré en interne. Le système principal n'ajoute pas de tels déclencheurs aux tables distantes, mais le code d'extension pourrait le faire.)

USER

Désactive ou active tous les déclencheurs appartenant à la table distante, à l'exception des déclencheurs générés en interne.

parent_table

Une table parente à associer ou à désassocier de cette table distante.

new_owner

Le nom d'utilisateur du nouveau propriétaire de la table.

new_schema

Le nom du schéma vers lequel la table sera déplacée.

NOTES

Le mot-clé COLUMN est superflu et peut être omis.

La cohérence avec le serveur distant n'est pas vérifiée lorsqu'une colonne est ajoutée ou supprimée avec ADD COLUMN ou DROP COLUMN, qu'une contrainte NOT NULL ou CHECK est ajoutée, ou qu'un type de colonne est modifié avec SET DATA TYPE. Il incombe à l'utilisateur de s'assurer que la définition de la table correspond à celle du côté distant.

Voir CREATE FOREIGN TABLE pour une description plus détaillée des paramètres valides.

EXAMPLES

Pour marquer une colonne comme non nulle :

ALTER FOREIGN TABLE distributors ALTER COLUMN street SET NOT NULL;

Pour modifier les options d'une table distante :

ALTER FOREIGN TABLE myschema.distributors OPTIONS (ADD opt1 'value', SET opt2 'value2', DROP opt3);

COMPATIBILITY

Les formes ADD, DROP et SET DATA TYPE sont conformes à la norme SQL. Les autres formes sont des extensions de PostgreSQL à la norme SQL. De plus, la possibilité de spécifier plus d'une manipulation dans une seule commande ALTER FOREIGN TABLE est une extension.

ALTER FOREIGN TABLE DROP COLUMN peut être utilisé pour supprimer la seule colonne d'une table distante, laissant une table à zéro colonne. C'est une extension de SQL, qui interdit les tables distantes à zéro colonne.
