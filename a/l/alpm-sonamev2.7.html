NOM

soname - représentation et utilisation des données soname dans le conditionnement basé sur ALPM.

DESCRIPTION

Les sonames[1] sont un mécanisme pour garantir la compatibilité binaire entre les objets partagés et leurs consommateurs (c'est-à-dire d'autres fichiers ELF[2]). Plus spécifiquement, les données soname[1] sont encodées dans le champ SONAME de la section dynamique des fichiers objet partagé et désignent généralement des informations spécifiques sur la version du fichier objet. Les fichiers ELF[2] peuvent se lier dynamiquement à des versions spécifiques d'objets partagés et déclarer cette dépendance à l'aide du champ NEEDED dans leur section dynamique.

Les chaînes représentant les informations soname peuvent être utilisées dans les relations de paquets alpm de type provision et dépendance à l'exécution pour permettre des configurations de dépendances de paquets strictes basées sur la compatibilité ABI.

Le format alpm-soname existe en plusieurs versions. Les informations contenues dans ce document concernent la version 2, qui est la version actuelle, remplace alpm-sonamev1 et a été introduite avec la sortie de pacman 6.1.0 le 04-03-2024.

FORMAT

La représentation des informations soname a lieu exclusivement dans les formats de fichiers susceptibles de contenir des données dynamiques spécifiques à l'environnement de construction, telles que PKGINFO.

Dans ces fichiers, les données soname sont référencées en utilisant le format suivant, composé de données dérivées de l'emplacement d'un fichier objet partagé, ainsi que des informations qui y sont encodées : une chaîne de caractères préfixe, directement suivie d'un deux-points ‘:’, directement suivie d'un soname (par exemple, lib:libexample.so.1).

Ici, la chaîne de caractères préfixe lib désigne le nom d'utilisation (défini arbitrairement au niveau de la distribution et utilisé par les outils de construction de paquets tels que makepkg) pour un répertoire de recherche (par exemple, /usr/lib) dans lequel le fichier objet partagé est trouvé. Reportez-vous à LIB_DIRS dans makepkg.conf pour comprendre comment fonctionnent les affectations de préfixe dans makepkg.

Le soname représente les données trouvées dans la section dynamique d'un fichier objet partagé (voir readelf pour plus de détails). Selon que les données soname sont utilisées dans une relation de paquet alpm de type provision ou de type dépendance à l'exécution, cela fait référence au champ SONAME ou au champ NEEDED dans la section dynamique, respectivement.

UTILISATION

Un paquet peut dépendre d'un soname spécifique à l'aide d'une relation de paquet alpm de type dépendance à l'exécution, si un autre paquet fournit ce soname exact dans sa relation de paquet alpm de type provision.

Plus précisément, une dépendance soname d'un paquet est basée sur les données soname d'un fichier objet partagé fourni par l'un de ses paquets dépendants.

Un outil de construction de paquets (par exemple, makepkg) dérive automatiquement les informations soname des fichiers ELF[2] dans l'environnement de construction en se basant sur les règles suivantes :

  • Si le paquet en cours de construction fournit un objet partagé dans l'un des répertoires de recherche configurés, la valeur du champ SONAME dans la section dynamique du fichier ELF[2] est extraite. Associée au préfixe attribué au répertoire de recherche donné, cette donnée est ajoutée en tant que provision aux données PKGINFO du paquet (par exemple, provides = lib:libexample.so.1, si le préfixe pour /usr/lib est lib et que le fichier objet partagé encodant le soname libexample.so.1 est présent dans /usr/lib).
  • Si le paquet en cours de construction produit un fichier ELF[2] qui se lie dynamiquement à un objet partagé disponible dans l'environnement de construction, la valeur du champ NEEDED dans la section dynamique du fichier ELF[2] auquel il se lie est extraite. Si un paquet contenant le fichier objet partagé qui encode les données soname est présent dans l'environnement de construction et que les données PKGINFO du paquet exposent ce fait dans une relation de paquet alpm de type provision (c'est-à-dire provides = lib:libexample.so.1), ces données sont utilisées. Associée au préfixe attribué au répertoire de recherche donné du fichier objet partagé qui fournit le soname nécessaire, cette donnée est ajoutée en tant que dépendance à l'exécution aux données PKGINFO du paquet en cours de construction (par exemple, depend = lib:libexample.so.1, si le préfixe pour /usr/lib est lib et que le fichier objet partagé encodant le soname libexample.so.1 est présent dans /usr/lib).

Pour les développeurs, il est fortement suggéré de rendre ce comportement configurable, car la détection de soname peut échouer ou reposer sur des données soname qui ne sont pas conseillées dans certaines conditions. Voir OPTIONS de makepkg.conf pour les détails sur la fonctionnalité autodeps et LIB_DIRS de makepkg.conf pour les détails sur les définitions de préfixe et de répertoire de recherche pour makepkg.

EXEMPLES

Les exemples suivants démontrent comment exposer et utiliser les informations soname dans le conditionnement basé sur ALPM.

Les exemples supposent une compilation avec makepkg avec la fonctionnalité autodeps activée. De plus, le tableau LIB_DIRS dans makepkg.conf est censé préfixer le répertoire de recherche /usr/lib avec lib.

Fournir un soname

Le fichier PKGBUILD suivant pour un paquet nommé example est utilisé pour construire et installer un projet en amont qui contient un objet partagé.

pkgname=example
pkgver=1.0.0
pkgrel=1
pkgdesc="Une bibliothèque d'exemple"
arch=(x86_64)
url="https://example.org/library.html"
license=(MIT)
depends=(glibc)
source=("https://example.org/$pkgname-$pkgver.tar.gz")
sha256sums=(7d865e959b2466918c9863afca942d0fb89d7c9ac0c99bafc3749504ded97730)
build() {
  make -C $pkgname-$pkgver
}
package() {
  make DESTDIR="$pkgdir" install -C $pkgname-$pkgver
}

Cet exemple suppose que le projet installe les fichiers suivants sur le système de fichiers :

/usr/lib/libexample.so -> libexample.so.1
/usr/lib/libexample.so.1 -> libexample.so.1.0.0
/usr/lib/libexample.so.1.0.0

Ici, le fichier /usr/lib/libexample.so.1.0.0 encode le soname libexample.so.1. De plus, cet exemple suppose que le répertoire /usr/lib est associé au préfixe lib.

Après la compilation à partir des sources, le fichier de paquet résultant pour example contient le fichier PKGINFO suivant :

pkgname = example
pkgver = 1.0.0-1
pkgdesc = Une bibliothèque d'exemple
url = https://example.org/library.html
builddate = 1729181726
packager = Votre Nom <votre.nom@example.org>
size = 181849963
arch = x86_64
license = MIT
provides = lib:libexample.so.1
depend = glibc

Dépendre d'un soname

Le fichier PKGBUILD suivant pour un paquet nommé application est utilisé pour construire un projet en amont qui dépend du paquet example de l'exemple précédent. Plus précisément, le paquet résultant dépend de l'objet partagé libexample.so qui est fourni par le paquet example.

pkgname=application
pkgver=1.0.0
pkgrel=1
pkgdesc="Une application d'exemple"
arch=(x86_64)
url="https://example.org/application.html"
license=(MIT)
depends=(
  glibc
  example
)
source=("https://example.org/$pkgname-$pkgver.tar.gz")
sha256sums=(b5bb9d8014a0f9b1d61e21e796d78dccdf1352f23cd32812f4850b878ae4944c)
build() {
  make -C $pkgname-$pkgver
}
package() {
  make DESTDIR="$pkgdir" install -C $pkgname-$pkgver
}

Après la compilation à partir des sources

urce, le fichier de paquet résultant pour application contient le fichier PKGINFO suivant :

pkgname = application
pkgver = 1.0.0-1
pkgdesc = An example application
url = https://example.org/application.html
builddate = 1729181726
packager = Your Name <your@email.com>
size = 181849963
arch = x86_64
license = MIT
depend = glibc
depend = example
depend = lib:libexample.so.1
