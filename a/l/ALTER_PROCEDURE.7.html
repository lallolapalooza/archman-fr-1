ALTER PROCEDURE(7) Documentation PostgreSQL 18.1 ALTER PROCEDURE(7)

NOM

ALTER_PROCEDURE - modifier la définition d'une procédure

SYNOPSISSE

ALTER PROCEDURE nom [ ( [ [ mode_arg ] [ nom_arg ] type_arg [, ...] ] ) ]
    action [ ... ] [ RESTRICT ]
ALTER PROCEDURE nom [ ( [ [ mode_arg ] [ nom_arg ] type_arg [, ...] ] ) ]
    RENAME TO nouveau_nom
ALTER PROCEDURE nom [ ( [ [ mode_arg ] [ nom_arg ] type_arg [, ...] ] ) ]
    OWNER TO { nouveau_propriétaire | CURRENT_ROLE | CURRENT_USER | SESSION_USER }
ALTER PROCEDURE nom [ ( [ [ mode_arg ] [ nom_arg ] type_arg [, ...] ] ) ]
    SET SCHEMA nouveau_schéma
ALTER PROCEDURE nom [ ( [ [ mode_arg ] [ nom_arg ] type_arg [, ...] ] ) ]
    [ NO ] DEPENDS ON EXTENSION nom_extension
où action est l'une des suivantes :
    [ EXTERNAL ] SECURITY INVOKER | [ EXTERNAL ] SECURITY DEFINER
    SET paramètre_configuration { TO | = } { valeur | DEFAULT }
    SET paramètre_configuration FROM CURRENT
    RESET paramètre_configuration
    RESET ALL

DESCRIPTION

ALTER PROCEDURE modifie la définition d'une procédure.

Vous devez être propriétaire de la procédure pour utiliser ALTER PROCEDURE. Pour modifier le schéma d'une procédure, vous devez également disposer du privilège CREATE sur le nouveau schéma. Pour modifier le propriétaire, vous devez pouvoir exécuter SET ROLE vers le nouveau rôle propriétaire, et ce rôle doit disposer du privilège CREATE sur le schéma de la procédure. (Ces restrictions garantissent que la modification du propriétaire ne fait rien que vous ne pourriez pas faire en supprimant et en recréant la procédure. Cependant, un superutilisateur peut modifier la propriété de n'importe quelle procédure de toute façon.)

PARAMÈTRES

nom

Le nom (éventuellement qualifié par le schéma) d'une procédure existante. Si aucune liste d'arguments n'est spécifiée, le nom doit être unique dans son schéma.

mode_arg

Le mode d'un argument : IN, OUT, INOUT, ou VARIADIC. Si omis, la valeur par défaut est IN.

nom_arg

Le nom d'un argument. Notez que ALTER PROCEDURE ne fait en réalité aucune attention aux noms d'arguments, car seuls les types de données des arguments sont utilisés pour déterminer l'identité de la procédure.

type_arg

Le ou les types de données des arguments de la procédure (éventuellement qualifiés par le schéma), le cas échéant. Voir DROP PROCEDURE (DROP_PROCEDURE(7)) pour les détails sur la manière dont la procédure est recherchée à l'aide du ou des types de données des arguments.

nouveau_nom

Le nouveau nom de la procédure.

nouveau_propriétaire

Le nouveau propriétaire de la procédure. Notez que si la procédure est marquée SECURITY DEFINER, elle s'exécutera ensuite en tant que nouveau propriétaire.

nouveau_schéma

Le nouveau schéma pour la procédure.

nom_extension

Cette forme marque la procédure comme dépendant de l'extension, ou plus dépendant de l'extension si NO est spécifié. Une procédure qui est marquée comme dépendant d'une extension est supprimée lorsque l'extension est supprimée, même si cascade n'est pas spécifié. Une procédure peut dépendre de plusieurs extensions, et sera supprimée lorsque l'une de ces extensions est supprimée.

[ EXTERNAL ] SECURITY INVOKER
[ EXTERNAL ] SECURITY DEFINER

Modifie si la procédure est un security definer ou non. Le mot-clé EXTERNAL est ignoré pour la conformité SQL. Voir CREATE PROCEDURE (CREATE_PROCEDURE(7)) pour plus d'informations sur cette fonctionnalité.

paramètre_configuration
valeur

Ajoute ou modifie l'affectation à faire à un paramètre de configuration lorsque la procédure est appelée. Si valeur est DEFAULT ou, de manière équivalente, si RESET est utilisé, le paramètre local à la procédure est supprimé, de sorte que la procédure s'exécute avec la valeur présente dans son environnement. Utilisez RESET ALL pour effacer tous les paramètres locaux à la procédure. SET FROM CURRENT enregistre la valeur du paramètre qui est courante lorsque ALTER PROCEDURE est exécutée comme valeur à appliquer lorsque la procédure est entrée.

Voir SET(7) et le Chapitre 19 pour plus d'informations sur les noms et valeurs de paramètres autorisés.

RESTRICT

Ignoré pour la conformité avec la norme SQL.

EXEMPLES

Pour renommer la procédure insert_data avec deux arguments de type integer en insert_record :

ALTER PROCEDURE insert_data(integer, integer) RENAME TO insert_record;

Pour changer le propriétaire de la procédure insert_data avec deux arguments de type integer en joe :

ALTER PROCEDURE insert_data(integer, integer) OWNER TO joe;

Pour changer le schéma de la procédure insert_data avec deux arguments de type integer en accounting :

ALTER PROCEDURE insert_data(integer, integer) SET SCHEMA accounting;

Pour marquer la procédure insert_data(integer, integer) comme étant dépendante de l'extension myext :

ALTER PROCEDURE insert_data(integer, integer) DEPENDS ON EXTENSION myext;

Pour ajuster le chemin de recherche qui est automatiquement défini pour une procédure :

ALTER PROCEDURE check_password(text) SET search_path = admin, pg_temp;

Pour désactiver la définition automatique de search_path pour une procédure :

ALTER PROCEDURE check_password(text) RESET search_path;

La procédure s'exécutera maintenant avec le chemin de recherche utilisé par son appelant.

COMPATIBILITÉ

Cette instruction est partiellement compatible avec l'instruction ALTER PROCEDURE de la norme SQL. La norme permet de modifier plus de propriétés d'une procédure, mais ne permet pas de renommer une procédure, de faire d'une procédure un security definer, d'attacher des valeurs de paramètres de configuration à une procédure, ou de changer le propriétaire, le schéma, ou la volatilité d'une procédure. La norme exige également le mot-clé RESTRICT, qui est facultatif dans PostgreSQL.
