ALTER AGGREGATE(7) Documentation PostgreSQL 18.1 ALTER AGGREGATE(7)

NOM

ALTER_AGGREGATE - modifier la définition d'une fonction d'agrégation

SYNTAXE

ALTER AGGREGATE nom ( signature_agrégat ) RENOMMER EN nouveau_nom
ALTER AGGREGATE nom ( signature_agrégat )
                PROPRIÉTAIRE EN { nouveau_propriétaire | CURRENT_ROLE | CURRENT_USER | SESSION_USER }
ALTER AGGREGATE nom ( signature_agrégat ) DÉFINIR SCHEMA nouveau_schéma
où signature_agrégat est :
* |
[ mode_arg ] [ nom_arg ] type_arg [ , ... ] |
[ [ mode_arg ] [ nom_arg ] type_arg [ , ... ] ] ORDER BY [ mode_arg ] [ nom_arg ] type_arg [ , ... ]

DESCRIPTION

ALTER AGGREGATE modifie la définition d'une fonction d'agrégation.

Vous devez être propriétaire de la fonction d'agrégation pour utiliser ALTER AGGREGATE. Pour changer le schéma d'une fonction d'agrégation, vous devez également avoir le privilège CREATE sur le nouveau schéma. Pour modifier le propriétaire, vous devez pouvoir utiliser SET ROLE sur le nouveau rôle propriétaire, et ce rôle doit avoir le privilège CREATE sur le schéma de la fonction d'agrégation. (Ces restrictions garantissent que la modification du propriétaire ne fait rien que vous ne pourriez pas faire en supprimant et recréant la fonction d'agrégation. Cependant, un superutilisateur peut modifier le propriétaire de n'importe quelle fonction d'agrégation de toute façon.)

PARAMETRES

nom

Le nom (éventuellement qualifié par un schéma) d'une fonction d'agrégation existante.

mode_arg

Le mode d'un argument : IN ou VARIADIC. S'il est omis, la valeur par défaut est IN.

nom_arg

Le nom d'un argument. Notez que ALTER AGGREGATE ne tient pas compte des noms d'arguments, car seuls les types de données des arguments sont nécessaires pour déterminer l'identité de la fonction d'agrégation.

type_arg

Un type de données d'entrée sur lequel la fonction d'agrégation opère. Pour référencer une fonction d'agrégation à zéro argument, écrivez * à la place de la liste des spécifications d'arguments. Pour référencer une fonction d'agrégation de type ordered-set, écrivez ORDER BY entre les spécifications d'arguments directs et agrégés.

nouveau_nom

Le nouveau nom de la fonction d'agrégation.

nouveau_propriétaire

Le nouveau propriétaire de la fonction d'agrégation.

nouveau_schéma

Le nouveau schéma pour la fonction d'agrégation.

NOTES

La syntaxe recommandée pour référencer une fonction d'agrégation de type ordered-set est d'écrire ORDER BY entre les spécifications d'arguments directs et agrégés, de la même manière que dans CREATE AGGREGATE. Cependant, il fonctionnera également d'omettre ORDER BY et de simplement faire glisser les spécifications d'arguments directs et agrégés dans une seule liste. Dans cette forme abrégée, si VARIADIC "any" a été utilisé dans les listes d'arguments directs et agrégés, écrivez VARIADIC "any" une seule fois.

EXEMPLES

Pour renommer la fonction d'agrégation myavg pour le type integer en my_average :

ALTER AGGREGATE myavg(integer) RENOMMER EN my_average;

Pour changer le propriétaire de la fonction d'agrégation myavg pour le type integer en joe :

ALTER AGGREGATE myavg(integer) PROPRIÉTAIRE EN joe;

Pour déplacer la fonction d'agrégation ordered-set mypercentile avec un argument direct de type float8 et un argument agrégé de type integer dans le schéma myschema :

ALTER AGGREGATE mypercentile(float8 ORDER BY integer) DÉFINIR SCHEMA myschema;

Ceci fonctionnera également :

ALTER AGGREGATE mypercentile(float8, integer) DÉFINIR SCHEMA myschema;

COMPATIBILITÉ

Il n'existe pas d'instruction ALTER AGGREGATE dans la norme SQL.

VOIR AUSSI

CREATE AGGREGATE (CREATE_AGGREGATE(7)), DROP AGGREGATE (DROP_AGGREGATE(7))
