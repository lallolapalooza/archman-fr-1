al_create_bitmap(3) Manuel des fonctions de bibliothèque al_create_bitmap(3)

NOM

al_create_bitmap - API Allegro 5

SYNOPIS

#include <allegro5/allegro.h>
ALLEGRO_BITMAP *al_create_bitmap(int w, int h)

DESCRIPTION

Crée un nouveau bitmap en utilisant le format et les indicateurs de bitmap pour le fil d'exécution actuel. Le transfert entre bitmaps de formats différents, ou le transfert entre bitmaps mémoire et bitmaps d'affichage peut être lent.

Sauf si vous définissez l'indicateur ALLEGRO_MEMORY_BITMAP, le bitmap est créé pour l'affichage actuel. Le transfert vers un autre affichage peut être lent.

Si un bitmap d'affichage est créé, il peut y avoir des limitations sur les dimensions autorisées. Par exemple, un backend DirectX ou OpenGL a généralement une taille de texture maximale - donc si la création de bitmap échoue pour de très grandes dimensions, vous pourriez vouloir réessayer avec un bitmap plus petit. Certaines plateformes dictent également une taille de texture minimale, ce qui est pertinent si vous prévoyez d'utiliser ce bitmap avec le module de primitives. Si vous essayez de créer un bitmap plus petit que cela, cet appel n'échouera pas mais le bitmap retourné sera une section d'un bitmap plus grand avec la taille minimale. La taille minimale qui fonctionnera sur toutes les plateformes est de 32 par 32. Il existe un commutateur expérimental pour désactiver ce remplissage en modifiant la configuration du système (voir la clé min_bitmap_size dans al_get_system_config(3)).

Certaines plateformes ne prennent pas directement en charge les bitmaps d'affichage dont les dimensions ne sont pas des puissances de deux. Allegro gère cela en créant un bitmap plus grand dont les dimensions sont des puissances de deux, puis en retournant une section de ce bitmap avec les dimensions que vous avez demandées. Cela peut être pertinent si vous prévoyez d'utiliser ce bitmap avec le module de primitives mais ne devrait pas poser de problème autrement.

Si vous créez un bitmap sans que ALLEGRO_MEMORY_BITMAP soit défini, mais qu'il n'y a pas d'affichage actuel, un bitmap mémoire temporaire sera créé à la place. Vous pouvez ultérieurement convertir tous ces bitmaps en bitmaps vidéo et les assigner à un affichage en appelant al_convert_memory_bitmaps(3).

Sur certaines plateformes, le contenu des bitmaps vidéo peut être perdu lorsque votre application perd le focus. Allegro dispose d'un mécanisme interne pour restaurer le contenu de ces bitmaps vidéo, mais il n'est pas infailible (parfois le contenu des bitmaps peut être perdu définitivement) et a des implications sur les performances. Si vous utilisez un bitmap comme tampon intermédiaire, ce mécanisme peut être coûteux. Dans ce cas, si vous ne voulez pas qu'Allegro gère le contenu du bitmap pour vous, vous pouvez désactiver ce mécanisme en créant le bitmap avec l'indicateur ALLEGRO_NO_PRESERVE_TEXTURE. Le contenu du bitmap est perdu lorsque vous recevez les événements ALLEGRO_EVENT_DISPLAY_LOST et ALLEGRO_EVENT_DISPLAY_HALT_DRAWING et doit être restauré lorsque vous recevez l'événement ALLEGRO_EVENT_DISPLAY_FOUND et lorsque vous appelez al_acknowledge_drawing_resume(3) (après l'événement ALLEGRO_EVENT_DISPLAY_RESUME_DRAWING). Vous pouvez utiliser ces événements pour implémenter votre propre mécanisme de restauration du contenu du bitmap si celui d'Allegro ne fonctionne pas assez bien pour vous (par exemple, vous pouvez les recharger tous depuis le disque).

Note: Le contenu d'un bitmap nouvellement créé est indéfini - vous devez effacer le bitmap ou vous assurer que tous les pixels sont écrasés avant de le dessiner.

Lorsque vous avez terminé d'utiliser le bitmap, vous devez appeler al_destroy_bitmap(3) dessus pour libérer toutes les ressources qui lui sont attribuées.
