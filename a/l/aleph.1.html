DESCRIPTIO

N

Exécute le composeur Aleph sur fichier, créant généralement fichier.dvi. Si l'argument fichier n'a pas d'extension, « .tex » lui sera ajoutée. Au lieu d'un nom de fichier, un ensemble de commandes Aleph peut être donné, la première devant commencer par une barre oblique inverse. Avec un &argument format, Aleph utilise un ensemble différent de commandes précompilées, contenues dans format.fmt ; il est généralement préférable d'utiliser l'option de format -fmt à la

place.

Aleph est une version du programme TeX modifiée pour la composition multilingue. Il utilise Unicode et possède des primitives supplémentaires pour (entre autres) la composition bidirectionnelle

.

Les options de ligne de commande d'Aleph sont similaires à celles de

TeX.

Aleph n'est plus activement

développé ; voir LuaTeX po
ur l'activité actuelle.

ENVIRONNEMEN

T

Voir la documentation de la bibliothèque Kpathsearch (le nœud « Path specifications ») pour des détails précis sur la manière dont les variables d'environnement sont utilisées. L'utilitaire kpsewhich peut être utilisé pour interroger les valeurs des

variables.

Une mise en garde : Dans la plupart des formats Aleph, vous ne pouvez pas utiliser ~ dans un nom de fichier que vous donnez directement à Aleph, car ~ est un caractère actif et est donc développé, non pris comme partie du nom de fichier. D'autres programmes, tels que Metafont, n'ont pas ce

problème.
TEXMFOUTP
UT
Normalement, Aleph place ses fichiers de sortie dans le répertoire courant. Si un fichier de sortie ne peut pas y être ouvert, il essaie de l'ouvrir dans le répertoire spécifié dans la variable d'environnement TEXMFOUTPUT. Il n'y a pas de valeur par défaut pour cette variable. Par exemple, si vous dites tex paper et que le répertoire courant n'est pas inscriptible, si TEXMFOUTPUT a la valeur /tmp, Aleph tente de créer /tmp/paper.log (et /tmp/paper.dvi, si une sortie est produite.) TEXMFOUTPUT est aussi vérifié pour les fichiers d'entrée, car TeX génère souvent des fichiers qui doivent être lus par la suite ; pour l'entrée, aucun suffixe (comme « .tex ») n'est ajouté par défaut, le nom d'entrée est simplement vérifié tel qu'il est
donné.
TEXINPU
TS
Chemin de recherche pour les fichiers \input et \openin. Cela doit commencer par « . », afin que les fichiers utilisateur soient trouvés avant les fichiers système. Un composant de chemin vide sera remplacé par les chemins définis dans le fichier texmf.cnf. Par exemple, définissez TEXINPUTS à « .:/home/user/tex: » pour ajouter le répertoire courant et « /home/user/tex » en tête du chemin de recherche
standard.
TEXED
IT
Modèle de commande pour basculer vers l'éditeur. La valeur par défaut, généralement vi, est définie
lors de la
compilati
on d'Aleph.

BOGUE

S

Cette version d'Aleph implémente un certain nombre d'extensions optionnelles. En fait, beaucoup de ces extensions entrent en conflit à un degré plus ou moins grand avec la définition d'Aleph. Lorsque de telles extensions sont activées, la bannière affichée au démarrage d'Aleph est modifiée pour afficher Alephk au lieu de Aleph

.

Cette version d'Aleph ne parvient pas à détecter le débordement arithmétique lorsque des dimensions sont ajoutées ou soustraites. Les cas où cela se produit sont rares, mais lorsque c'est le cas, le fichier DVI géné

ré sera i
nvalide.
