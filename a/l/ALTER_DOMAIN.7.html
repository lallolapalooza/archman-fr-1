DESCRIPTIO

N

ALTER DOMAIN modifie la définition d'un domaine existant. Il existe plusieurs sous-formes

:

SET/DROP

DEFAULT
Ces formes définissent ou suppriment la valeur par défaut d'un domaine. Notez que les valeurs par défaut ne s'appliquent qu'aux commandes INSERT suivantes ; elles n'affectent pas les lignes déjà présentes dans une table utilisant le
domaine.

SET/DROP NOT

NULL
Ces formes modifient si un domaine est marqué pour autoriser les valeurs NULL ou pour rejeter les valeurs NULL. Vous ne pouvez exécuter SET NOT NULL que lorsque les colonnes utilisant le domaine ne contiennent aucune valeur
nulle.

ADD domain_constraint [ NOT VALID

]
Cette forme ajoute une nouvelle contrainte à un domaine. Lorsqu'une nouvelle contrainte est ajoutée à un domaine, toutes les colonnes utilisant ce domaine seront vérifiées par rapport à la contrainte nouvellement ajoutée. Ces vérifications peuvent être supprimées en ajoutant la nouvelle contrainte avec l'option NOT VALID ; la contrainte peut ensuite être rendue valide à l'aide de ALTER DOMAIN ... VALIDATE CONSTRAINT. Les lignes nouvellement insérées ou mises à jour sont toujours vérifiées par rapport à toutes les contraintes, même celles marquées NOT VALID. NOT VALID n'est accepté que pour les contraintes
CHECK.

DROP CONSTRAINT [ IF EXISTS

]
Cette forme supprime des contraintes sur un domaine. Si IF EXISTS est spécifié et que la contrainte n'existe pas, aucune erreur n'est levée. Dans ce cas un avis est émis à la
place.

RENAME

CONSTRAINT
Cette forme change le nom d'une contrainte sur un
domaine.

VALIDATE

CONSTRAINT
Cette forme valide une contrainte précédemment ajoutée comme NOT VALID, c'est-à-dire qu'elle vérifie que toutes les valeurs dans les colonnes de table du type domaine satisfont la contrainte
spécifiée.

OWNE

R
Cette forme change le propriétaire du domaine en l'utilisateur
spécifié.

RENAM

E
Cette forme change le nom du
domaine.

SET

SCHEMA
Cette forme change le schéma du domaine. Toutes les contraintes associées au domaine sont déplacées vers le nouveau schéma
également.

Vous devez posséder le domaine pour utiliser ALTER DOMAIN. Pour changer le schéma d'un domaine, vous devez également disposer du privilège CREATE sur le nouveau schéma. Pour modifier le propriétaire, vous devez être en mesure d'exécuter SET ROLE vers le nouveau rôle propriétaire, et ce rôle doit disposer du privilège CREA

TE sur le schéma du domaine. (Ces restrictions garantissent que la modification du propriétaire ne fait rien que vous ne pourriez pas fai
re en supprimant et recréant le domaine. Cependant, un superutilisateur peut modifier la propriété de n'importe quel domaine de toute façon.)

NOTE

S

Bien que ALTER DOMAIN ADD CONSTRAINT tente de vérifier que les données stockées existantes satisfont la nouvelle contrainte, cette vérification n'est pas infaillible, car la commande ne peut pas « voir » les lignes de table nouvellement insérées ou mises à jour et pas encore validées. S'il y a un risque que des opérations concurrentes insèrent de mauvaises données, la manière de procéder est d' ajouter la contrainte avec l'option NOT VALID, de valider cette commande, d'attendre que toutes les transactions commencées avant cette validation soient terminées, puis d'exécuter ALTER DOMAIN VALIDATE CONSTRAINT pour rechercher des données violant la contrainte. Cette méthode est fiable car une fois la contrainte validée, toutes les nouvelles transactions sont garanties de l'appliquer contre les nouvelles valeurs du type

domaine.

Actuellement, ALTER DOMAIN ADD CONSTRAINT, ALTER DOMAIN VALIDATE CONSTRAINT, et ALTER DOMAIN SET NOT NULL échoueront si le domaine nommé ou tout domaine dérivé est utilisé dans une colonne de type conteneur (une colonne composite, de tableau ou d'intervall

e) dans n'importe quelle table de la base de données. Ils devraient éventuellement être a
méliorés pour pouvoir vérifier la nouvelle contrainte pour de telles valeurs imbriquées.

COMPATIBILIT

É

ALTER DOMAIN est conforme à la norme SQL, à l'exception des variantes OWNER, RENAME, SET SCHEMA et VALIDATE CONSTRAINT, qui

sont des extensions PostgreSQL. La clause NOT VALID de la var
iante ADD CONSTRAINT est également une extension PostgreSQL.
