alpm-db-desc - Format de fichier pour la représentation des métadonnées des paquets basés sur ALPM (version

1)

DESCRIPTIO

N

Le format alpm-db-desc est un format textuel qui représente les métadonnées d'un paquet unique. Chaque fichier décrit diverses propriétés d'un paquet, y compris son nom, sa version, ses dépendances, sa taille, ses informations de licence, et plus encore. Pour une liste complète des propriétés, voir sections

.

Un système d'exploitation reposant sur Arch Linux Package Management maintient une base de données libalpm locale avec un fichier alpm-db-desc par paquet, chacun nommé desc et situé dans un répertoire unique, propre à chaque

paquet.

L'accumulation de tous les fichiers alpm-db-desc dans une base de données libalpm décrit l'état actuel du système (c'est-à-dire quels paquets ont été installés quand, dans quelles circonstances). Plus spécifiquement, les logiciels de gestion de paquets tels que pacman et les outils associés utilisent ce format de fichier, par exemple, pour résoudre les dépendances et afficher les informations des

paquets.

Les données dans un fichier alpm-db-desc proviennent d'un alpm-package. Ici, la plupart des métadonnées proviennent des données PKGINFO du

paquet.

Le format de fichier alpm-db-desc ne doit pas être confondu avec le format de fichier alpm-repo-desc, qui est utilisé dans le contexte d'une alpm-repo-db et porte un ensemble différent de métadonnées, mais est généralement aussi nommé desc

.

Le format alpm-db-desc existe en plusieurs versions. Ce document décrit la version 1, qui est une version héritée et est disponible depuis la sortie de pacman 5.1.0 le 2018-05-28. Pour la dernière spécification, voir alpm-db-desc

.

Format

général

Un fichier alpm-db-desc est un fichier encodé en UTF-8, délimité par des sauts de ligne, composé d'une série de sections

.

Chaque section commence par une ligne d'en-tête de section unique. La ligne d'en-tête de section est suivie d'une ou plusieurs lignes contenant chacune une valeur propre à la section. Toutes les valeurs propres à la section doivent se composer de caractères ASCII imprimables[1] sauf indication contraire. Une section se termine lorsqu'une autre ligne d'en-tête de section est rencontrée ou que la fin du fichier est atteinte. Les lignes vides entre les sections sont

ignorées.
