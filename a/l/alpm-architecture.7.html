NOM

architecture - définition d'architecture pour les paquets basés sur ALPM.

DESCRIPTION

Le format architecture est un format de chaîne personnalisé qui contient des architectures de jeux d'instructions CPU[1] et d'autres identifiants, et qui est utilisé pour représenter l'architecture des paquets basés sur ALPM. Ce format est utilisé dans les scripts de construction ou les formats de fichiers pour les métadonnées de paquets (par exemple, dans PKGBUILD, BUILDINFO, PKGINFO) pour décrire l'architecture d'un paquet, ou l'architecture des paquets dépendants.

Le format architecture comprend des valeurs définies par convention. Les valeurs sont des mots-clés personnalisés, dont la plupart sont dérivés directement des architectures de jeux d'instructions CPU[1] ou de microarchitectures spécifiques.

La valeur architecture doit être composée de caractères alphanumériques et de ‘_’.

EXEMPLES

Les valeurs architecture ci-dessous se rapportent toutes à des architectures de jeux d'instructions CPU[1] spécifiques ou à des microarchitectures et peuvent être utilisées pour spécifier une architecture de paquet. Cela signifie généralement que les paquets d'une architecture spécifique ne peuvent être utilisés que dans un contexte particulier.

"any"

Un paquet peut être utilisé sur n'importe quel matériel car son contenu n'est spécifique à aucune architecture.

"x86_64"

Un paquet ne peut être utilisé que sur du matériel compatible avec la version 1 et supérieure du jeu d'instructions x86-64[2] (voir les niveaux de microarchitecture x86-64[3]).

"x86_64_v2"

Un paquet ne peut être utilisé que sur du matériel compatible avec la version 2 et supérieure du jeu d'instructions x86-64[2] (voir les niveaux de microarchitecture x86-64[3]).

"x86_64_v3"

Un paquet ne peut être utilisé que sur du matériel compatible avec la version 3 et supérieure du jeu d'instructions x86-64[2] (voir les niveaux de microarchitecture x86-64[3]).

"x86_64_v4"

Un paquet ne peut être utilisé que sur du matériel compatible avec la version 4 et supérieure du jeu d'instructions x86-64[2] (voir les niveaux de microarchitecture x86-64[3]).

"i686"

Un paquet ne peut être utilisé que sur du matériel compatible avec la version 6 du jeu d'instructions IA-32[4] (également connu sous le nom de P6[5] ou ‘i686’). Cette architecture est considérée comme obsolète.

"i486"

Un paquet ne peut être utilisé que sur du matériel compatible avec la version 4 du jeu d'instructions IA-32[4] (également connu sous le nom de i486[6]). Cette architecture est considérée comme obsolète.

"pentium4"

Un paquet ne peut être utilisé que sur du matériel compatible avec la microarchitecture Pentium 4[7]. Cette architecture est considérée comme obsolète.

"armv7"

Un paquet ne peut être utilisé que sur du matériel compatible avec la famille d'architectures ARMv7[8]. Cette architecture est considérée comme obsolète.

"armv8"

Un paquet ne peut être utilisé que sur du matériel compatible avec la famille d'architectures ARMv8[9].

"aarch64"

Un paquet ne peut être utilisé que sur du matériel compatible avec AArch64[10].

"riscv64"

Un paquet ne peut être utilisé que sur du matériel compatible avec la variante 64 bits de l'architecture de jeu d'instructions RISC-V[12] (ISA[13]).

"loong64"

Un paquet ne peut être utilisé que sur du matériel compatible avec la variante 64 bits de l'architecture de jeu d'instructions LoongArch[14] (ISA[13]).
