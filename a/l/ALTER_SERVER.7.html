NOM

ALTER_SERVER - modifier la définition d'un serveur distant

SYNTAXE

ALTER SERVER nom [ VERSION 'nouvelle_version' ]
    [ OPTIONS ( [ ADD | SET | DROP ] option ['valeur'] [, ... ] ) ]
ALTER SERVER nom OWNER TO { nouveau_proprietaire | CURRENT_ROLE | CURRENT_USER | SESSION_USER }
ALTER SERVER nom RENAME TO nouveau_nom

DESCRIPTION

ALTER SERVER modifie la définition d'un serveur distant. La première forme modifie la chaîne de version du serveur ou les options génériques du serveur (au moins une clause est requise). La deuxième forme modifie le propriétaire du serveur.

Pour modifier le serveur, vous devez en être le propriétaire. De plus, pour modifier le propriétaire, vous devez pouvoir utiliser SET ROLE sur le nouveau rôle propriétaire, et vous devez avoir le privilège USAGE sur la bibliothèque de données étrangères du serveur. (Notez que les superutilisateurs satisfont automatiquement toutes ces conditions.)

PARAMETRES

nom

Le nom d'un serveur existant.

nouvelle_version

Nouvelle version du serveur.

OPTIONS ( [ ADD | SET | DROP ] option ['valeur'] [, ... ] )

Modifie les options pour le serveur. ADD, SET et DROP spécifient l'action à effectuer. ADD est supposé si aucune opération n'est explicitement spécifiée. Les noms d'option doivent être uniques ; les noms et les valeurs sont également validés à l'aide de la bibliothèque de données étrangères du serveur.

nouveau_proprietaire

Le nom d'utilisateur du nouveau propriétaire du serveur distant.

nouveau_nom

Le nouveau nom pour le serveur distant.

EXEMPLES

Modifier le serveur foo, ajouter des options de connexion :

ALTER SERVER foo OPTIONS (host 'foo', dbname 'foodb');

Modifier le serveur foo, changer la version, changer l'option hôte :

ALTER SERVER foo VERSION '8.4' OPTIONS (SET host 'baz');

COMPATIBILITE

ALTER SERVER est conforme à la norme ISO/IEC 9075-9 (SQL/MED). Les formes OWNER TO et RENAME sont des extensions de PostgreSQL.

VOIR AUSSI
