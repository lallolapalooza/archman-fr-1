DESCRIPTIO

N

ALTER ROLE modifie les attributs d'un rôle

PostgreSQL.

La première variante de cette commande listée dans le synopsis peut modifier de nombreux attributs du rôle qui peuvent être spécifiés dans CREATE ROLE. (Tous les attributs possibles sont couverts, à l'exception des options pour ajouter ou supprimer des appartenances ; utilisez GRANT et REVOKE pour cela.) Les attributs non mentionnés dans la commande conservent leurs réglages précédents. Les superutilisateurs de la base de données peuvent modifier n'importe lequel de ces réglages pour n'importe quel rôle, à l'exception de la modification de la propriété SUPERUSER pour le superutilisateur de démarrage. Les rôles non superutilisateurs possédant le privilège CREATEROLE peuvent modifier la plupart de ces propriétés, mais uniquement pour les rôles non superutilisateurs et non réplication pour lesquels ils ont reçu ADMIN OPTION. Les non-superutilisateurs ne peuvent pas modifier la propriété SUPERUSER et peuvent modifier les propriétés CREATEDB, REPLICATION et BYPASSRLS uniquement s'ils possèdent eux-mêmes la propriété correspondante. Les rôles ordinaires ne peuvent modifier que leur propre mot de

passe.

La deuxième variante change le nom du rôle. Les superutilisateurs de la base de données peuvent renommer n'importe quel rôle. Les rôles possédant le privilège CREATEROLE peuvent renommer les rôles non superutilisateurs pour lesquels ils ont reçu ADMIN OPTION. L' utilisateur de session en cours ne peut pas être renommé. (Connectez-vous en tant qu'utilisateur différent si vous devez le faire.) Étant donné que les mots de passe chiffrés MD5 utilisent le nom du rôle comme sel cryptographique, renommer un rôle efface son mot de passe si le mot de passe est chiffré

MD5.

Les variantes restantes modifient la valeur par défaut de session d'un rôle pour une variable de configuration, soit pour toutes les bases de données, soit, lorsque la clause IN DATABASE est spécifiée, uniquement pour les sessions dans la base de données nommée. Si ALL est spécifié à la place d'un nom de rôle, cela modifie le réglage pour tous les rôles. L'utilisation de ALL avec IN DATABASE est essentiellement la même que l'utilisation de la commande ALTER DATABASE ... SET ...

.

Chaque fois que le rôle démarre ensuite une nouvelle session, la valeur spécifiée devient la valeur par défaut de la session, remplaçant le réglage présent dans postgresql.conf ou reçu depuis la ligne de commande postgres. Cela ne se produit qu'à la connexion ; exécuter SET ROLE ou SET SESSION AUTHORIZATION ne provoque pas la définition de nouvelles valeurs de configuration. Les réglages définis pour toutes les bases de données sont remplacés par les réglages spécifiques à la base de données attachés à un rôle. Les réglages pour des bases de données spécifiques ou des rôles spécifiques remplacent les réglages pour tous les

rôles.

Les superutilisateurs peuvent modifier les valeurs par défaut de session de n'importe qui. Les rôles possédant le privilège CREATEROLE peuvent modifier les valeurs par défaut pour les rôles non superutil

isateurs pour lesquels ils ont reçu ADMIN OPTION. Les rôles ordinaires ne peuvent définir des valeurs par défaut que pour eux-mêmes. Certaines variables de configuration ne peuvent pas être définies d
e cette manière, ou ne peuvent être définies que si un superutilisateur émet la commande. Seuls les superutilisateurs peuvent modifier un réglage pour tous les rôles dans toutes les bases de données.

NOTE

S

Utilisez CREATE ROLE pour ajouter de nouveaux rôles, et DROP ROLE pour supprimer un

rôle.

ALTER ROLE ne peut pas modifier les appartenances d'un rôle. Utilisez GRANT et REVOKE pour

cela.

Une prudence doit être exercée lors de la spécification d'un mot de passe non chiffré avec cette commande. Le mot de passe sera transmis au serveur en clair, et il pourrait aussi être journalisé dans l'historique des commandes du client ou le journal du serveur. psql(1) contient une commande \password qui peut être utilisée pour modifier le mot de passe d'un rôle sans exposer le mot de passe en

clair.

Il est également possible de lier une valeur par défaut de session à une base de données spécifique plutôt qu'à un rôle ; consultez ALTER DATABASE (ALTER_DATABASE(7)). En cas de conflit, les réglages spécifiques à la base de données et au rôle remplacent

les réglages spécifiques au rôle, qui à leur tour rempl
acent les réglages spécifiques à la base de données.
