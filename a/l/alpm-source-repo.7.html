NOM

alpm-source-repo - un dépôt contenant les sources pour construire un ou plusieurs paquets basés sur la gestion de paquets Arch Linux Package Management (ALPM).

DESCRIPTION

Les paquets basés sur ALPM (voir alpm-package) sont créés à partir de sources de paquets à l'aide de logiciels de construction de paquets, tels que makepkg. Consultez la section contenu pour un aperçu des fichiers requis et optionnels dans un alpm-source-repo. Pour les logiciels de construction de paquets spécifiques à Arch Linux, consultez devtools et pkgctl.

Contenu

Les sources de paquets sont représentées par un seul PKGBUILD par alpm-source-repo, qui peut définir et/ou requérir des fichiers supplémentaires, tels qu'un alpm-install-scriptlet, des fichiers sources locaux personnalisés arbitraires pour le processus de construction du paquet et des fichiers pour les outils (par ex. fichiers de configuration, etc.). Le script PKGBUILD peut être accompagné d'un fichier SRCINFO qui représente un format de données analysable exposant les métadonnées pertinentes définies par le PKGBUILD.

Fichiers requis

•
PKGBUILD: Le script de construction du paquet.

Fichiers optionnels

  • .SRCINFO: La représentation des données des métadonnées du script de construction du paquet (voir SRCINFO).
  • .nvchecker.toml: Un fichier de configuration minimal pour nvchecker (pris en charge par pkgctl) permettant la détection de nouvelles versions en amont.
  • LICENSES/: Un répertoire contenant les fichiers de licence utilisés par reuse (voir RFC 0040[1] et RFC 0052[2]).
  • REUSE.toml: Un fichier de configuration pour reuse qui couvre les informations de licence de tous les fichiers dans le alpm-source-repo (voir RFC 0040[1] et RFC 0052[2]).
  • alpm-install-scriptlet: Un scriptlet d'installation qui est ajouté à un alpm-package résultant (doit être spécifié dans le PKGBUILD).
  • keys/pgp/: Un répertoire contenant des certificats OpenPGP[4] en armure ASCII[3] qui représentent des vérificateurs pour les signatures OpenPGP[5] créées par les projets en amont pour leurs artefacts de publication.

En plus des fichiers spécifiques ci-dessus, un alpm-source-repo peut contenir une liste de fichiers sources personnalisés arbitraires qui sont utilisés avec le PKGBUILD lors de la construction de fichiers de paquets avec un logiciel de construction de paquets. Des exemples courants de ces fichiers sont les correctifs, systemd.service, systemd.socket, sysusers.d, tmpfiles.d ou d'autres fichiers de configuration.

Contrôle de version

Il est conseillé de conserver le contenu d'un alpm-source-repo dans un système de contrôle de version tel que git. Ce faisant, la relation entre un PKGBUILD et sa liste résultante de fichiers alpm-package peut être établie, en associant un hash de commit git (de préférence signé) au paquet. Cela est important pour les compilations reproductibles[6].

Les sources en amont et les artefacts de compilation (par ex. journaux de compilation, ou fichiers de paquets) ne doivent pas être inclus dans le dépôt git . Ils peuvent être ignorés à l'aide d'un fichier gitignore . Alternativement, makepkg.conf peut être utilisé pour indiquer à l'outil de construction de paquets makepkg de stocker les artefacts ailleurs.

Bonnes pratiques

Bien qu'une configuration de base ne requise techniquement qu'un PKGBUILD , d'autres composants sont considérés comme des bonnes pratiques.

  • .SRCINFO: Créer ce fichier (voir SRCINFO pour la description du format) et le maintenir en phase avec le fichier PKGBUILD permet aux consommateurs du alpm-source-repo d'extraire les métadonnées du PKGBUILD sans nécessiter bash.
  • .nvchecker.toml: Utiliser nvchecker (par ex. à travers pkgctl) permet aux utilisateurs de vérifier les nouvelles versions d'un projet en amont.
  • LICENSES/ et REUSE.toml: Une configuration reuse garantit que la licence est clairement définie pour tous les fichiers dans le alpm-source-repo ce qui permet à d'autres de l'utiliser et de l'adapter.
  • keys/pgp/: Si le PKGBUILD définit une alpm-package-source avec une vérification de signature OpenPGP[7], le stockage des versions actuelles des certificats OpenPGP[4] en armure ASCII[3] permet aux utilisateurs du alpm-source-repo d'authentifier les artefacts en amont à l'aide de signatures OpenPGP[5].
