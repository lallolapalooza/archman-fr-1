al_set_new_bitmap_flags(3) Manuel des fonctions de bibliothèque al_set_new_bitmap_flags(3)

NOM

al_set_new_bitmap_flags - API Allegro 5

SYNTAXE

#include <allegro5/allegro.h>
void al_set_new_bitmap_flags(int flags)

DESCRIPTION

Définit les indicateurs à utiliser pour les bitmaps nouvellement créés. Les indicateurs valides sont :

ALLEGRO_MEMORY_BITMAP
Crée une bitmap résidant en mémoire système. Les opérations sur et avec les bitmaps mémoire ne seront pas accélérées matériellement. Cependant, l'accès direct aux pixels peut être relativement rapide par rapport aux bitmaps vidéo, qui dépendent du pilote d'affichage utilisé.

Note : Les routines de rendu logiciel d'Allegro sont actuellement un peu sous-optimisées.

Note : La combinaison des indicateurs ALLEGRO_VIDEO_BITMAP et ALLEGRO_MEMORY_BITMAP est invalide.

ALLEGRO_VIDEO_BITMAP
Crée une bitmap résidant dans la mémoire de la carte vidéo. Ces types de bitmaps bénéficient le plus de l'accélération matérielle.

Note : La création d'une bitmap vidéo échouera s'il n'y a pas d'écran actif ou si le pilote d'affichage actuel ne peut pas créer la bitmap. Ce dernier cas se produira si, par exemple, le format ou les dimensions ne sont pas pris en charge.

Note : Les bitmaps créées avec cet indicateur seront converties en bitmaps mémoire lorsque le dernier écran sera détruit. Dans la plupart des cas, il est donc plus facile d'utiliser plutôt l'indicateur ALLEGRO_CONVERT_BITMAP.

Note : La combinaison des indicateurs ALLEGRO_VIDEO_BITMAP et ALLEGRO_MEMORY_BITMAP est invalide.

ALLEGRO_CONVERT_BITMAP
C'est la valeur par défaut. Il tentera de créer une bitmap vidéo et, en cas d'échec, créera une bitmap mémoire. Les bitmaps créées avec cet indicateur lorsqu'il n'y a pas d'écran actif seront converties en bitmaps vidéo lors de la prochaine création d'un écran. Elles resteront également des bitmaps vidéo si le dernier écran est détruit puis qu'un autre est recréé. Depuis 5.1.0.

Note : Vous pouvez combiner cet indicateur avec ALLEGRO_MEMORY_BITMAP ou ALLEGRO_VIDEO_BITMAP pour forcer le type initial (et échouer dans le second cas si aucune bitmap vidéo ne peut être créée) - mais généralement, aucune de ces combinaisons n'est très utile.

Vous pouvez utiliser l'option d'affichage ALLEGRO_AUTO_CONVERT_BITMAPS pour contrôler quels écrans tenteront de convertir automatiquement les bitmaps.

ALLEGRO_FORCE_LOCKING
Ne fait rien depuis 5.1.8. Conservé uniquement pour la compatibilité ascendante.
ALLEGRO_NO_PRESERVE_TEXTURE
Normalement, tout est fait pour préserver le contenu des bitmaps, car certaines plateformes peuvent les oublier. Cela peut prendre du temps de traitement supplémentaire. Si vous savez qu'il n'est pas important que la bitmap conserve ses données pixelisées, par exemple lorsqu'il s'agit d'un tampon temporaire, utilisez cet indicateur pour indiquer à Allegro de ne pas tenter de préserver son contenu.
ALLEGRO_ALPHA_TEST
Ceci est uniquement un indice pour le pilote. Il indique au pilote graphique d'effectuer un test alpha au lieu d'un mélange alpha sur les bitmaps créées avec cet indicateur. Le test alpha est généralement plus rapide et préférable si vos bitmaps n'ont qu'un seul niveau d'alpha (0). Cet indicateur n'est actuellement pas largement implémenté (c'est-à-dire uniquement pour les bitmaps mémoire).
ALLEGRO_MIN_LINEAR
Lors du dessin d'une version réduite de la bitmap, utilisez le filtrage linéaire. Cela a généralement une meilleure apparence. Vous pouvez également le combiner avec l'indicateur MIPMAP pour une qualité encore meilleure.
ALLEGRO_MAG_LINEAR
Lors du dessin d'une version agrandie d'une bitmap, utilisez le filtrage linéaire. Cela rendra l'image floue au lieu de créer un grand rectangle pour chaque pixel. Il dépend de l'apparence souhaitée pour savoir si vous voulez l'utiliser ou non.
ALLEGRO_MIPMAP
Ceci ne peut être utilisé que pour les bitmaps dont la largeur et la hauteur sont une puissance de deux. Dans ce cas, il générera des mipmaps et les utilisera lors du dessin de versions réduites. Par exemple, si la bitmap est de 64x64, des bitmaps supplémentaires de tailles 32x32, 16x16, 8x8, 4x4, 2x2 et 1x1 seront créées, contenant toujours une version réduite de l'original.
