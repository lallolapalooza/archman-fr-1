alpm-repo-desc - Format de fichier pour la représentation des métadonnées des paquets basés sur ALPM dans les

dépôts de paquets (version 1).

DESC

RIP
TION

L

e

format alpm-repo-desc est un format textuel qui représente les métadonnées d'un paquet unique dans une version spécifique d'un dépôt. Chaque fichier décrit diverses propriétés d'un fichier alpm-package, y compris son nom, sa version, ses dépendances, sa taille, ses informations de licence, et plus encore. Pour une liste complète des propriétés, voir ses sections. L'accumulation de tous

les fichiers

alpm-repo-desc dans une alpm-repo-db décrit l'état actuel du dépôt (c'est-à-dire quels paquets sont disponibles et dans quelle version). Un système d'exploitation s'appuyant sur

la

gestion des paquets d'Arch Linux maintient un ou plusieurs fichiers alpm-repo-db qui contiennent chacun un fichier alpm-repo-desc par paquet, chacun nommé desc et situé dans un répertoire unique pour chaque paquet. Plus précisément, les logiciels de gestion de paquets tels que pacman et les outils associés utilisent ce format de fichier, par exemple pour résoudre les dépendances et pour afficher les informations des paquets des fichiers alpm-package dans les dépôts. Les données dans un

fichier

alpm-repo-desc proviennent d'un alpm-package. Une grande partie de ses métadonnées provient des données PKGINFO du paquet. Un fichier alpm-repo-desc est généralement créé par un logiciel gérant un alpm-repo, tel que repo-add. Le format de fichier décrit dans ce document ne doit pas être confondu avec le format

de fichier

alpm-db-desc, qui est utilisé dans le contexte d'une base de données libalpm et porte un ensemble différent de métadonnées, mais est généralement aussi nommé desc. Le for

mat

alpm-repo-desc existe en plusieurs versions. Ce document décrit la version 1, qui est une version héritée et est disponible depuis la sortie de pacman 5.1.0 le 2018-05-28. Pour la dernière spécification, voir alpm-repo-desc. Format gé

néral

Un

fichier

alpm-repo-desc est un fichier encodé en UTF-8, délimité par des sauts de ligne, composé d'une série de sections. Chaque section commence par une ligne d'en-tête de section unique. La ligne d'en-tête de section est suivie d'une ou plusieurs lignes contenant

chacune une

valeur spécifique à la section. Toutes les valeurs spécifiques à la section doivent être composées de caractères ASCII imprimables[1] sauf indication contraire. Une section se termine lorsqu'une autre ligne d'en-tête de section est rencontrée ou que la fin du fichier est atteinte. Les lignes vides entre les sections sont ignorées. Section

s

Ch

aq
ue

ligne d'en-tête de section contient

le

nom de la section en majuscules, entouré de signes pourcent (par exemple %NAME%). Les noms de sections servent de clé pour chaque valeur spécifique à la section. Chaque section permet une seule valeur spécifique à la secti

on, suivant la

ligne d'en-tête de section. Comme exception à cette règle, les sections %LICENSE%, %GROUPS%, %CHECKDEPENDS%, %DEPENDS%, %OPTDEPENDS%, %REPLACES%, %CONFLICTS% et %PROVIDES% peuvent avoir plus d'une valeur spécifique à la section. %FILENAME% Le nom de

fichi

alpm-package (par

exemple

example-1.2.3-any.pkg.tar.zst). %NAME% U

n

alpm-package-name, qui représente le nom d'un paquet (par

exemple

example). %BASE% U

n

alpm-package-base qui représente la base du paquet d'où provient un paquet. Si un paquet

n'est pas un

alpm-split-package, la valeur est la même que celle de la section %NAME%. Si un paquet est un alpm-split-package, la valeur peut être différente de celle de la section %NAME%. %VERSION% Un

alpm-package-version

(par exemple

Un ensemble facultatif d'identifiants de licence qui s'appliquent au paquet. Une ou plusieurs valeurs peuvent être présentes. S'il n'y a pas d'identifiant de licence, la

La date à laquelle la construction du paquet a commencé. La valeur doit être numérique et représenter les secondes depuis l'Epoch, aussi appelé « Unix time » (par exemple 172918

172

%PACKAGER

% alpm-repo-descv1.5

DESCRIPTION

Le champ PACKAGER contient l'identifiant utilisateur de l'entité qui a construit le paquet. La valeur est destinée aux recherches d'identité et représente un OpenPGP User ID[7]. À ce titre, la valeur est une chaîne encodée en UTF-8, qui est classiquement composée d'un nom et d'une adresse e-mail, conformément au format décrit dans la RFC 28228.

%REPLACES%

Un autre composant virtuel ou paquet que le paquet remplace lors de l'installation. Une ou plusieurs valeurs peuvent être présentes. Si le paquet ne remplace rien, la section est omise. La valeur est une alpm-package-relation de type replacement (par exemple, example ou example=1.0.0).

%CONFLICTS%

Un autre composant virtuel ou paquet avec lequel le paquet est en conflit. Une ou plusieurs valeurs peuvent être présentes. Si le paquet n'est en conflit avec rien, la section est omise. La valeur est une alpm-package-relation de type conflict (par exemple, example ou example=1.0.0).

%PROVIDES%

Un autre composant virtuel ou paquet que le paquet fournit. Une ou plusieurs valeurs peuvent être présentes. Si le paquet ne fournit rien, la section est omise. La valeur est une alpm-package-relation de type provision (par exemple, example ou example=1.0.0).

%DEPENDS%

Une dépendance d'exécution du paquet (composant virtuel ou paquet). Une ou plusieurs valeurs peuvent être présentes. Si le paquet n'a pas de dépendance d'exécution, la section est omise. La valeur est une alpm-package-relation de type run-time dependency (par exemple, example ou example=1.0.0).

%OPTDEPENDS%

Une dépendance optionnelle du paquet (composant virtuel ou paquet). Une ou plusieurs valeurs peuvent être présentes. Si le paquet n'a pas de dépendance optionnelle, la section est omise. La valeur est une alpm-package-relation de type optional dependency (par exemple, example ou example: ceci est une description).

%MAKEDEPENDS%

Une dépendance pour la construction du logiciel amont du paquet. Une ou plusieurs valeurs peuvent être présentes. Si le paquet n'a pas de dépendance de construction, la section est omise. La valeur est une alpm-package-relation de type build dependency (par exemple, example ou example=1.0.0).

%CHECKDEPENDS%

Une dépendance pour l'exécution des tests du projet amont du paquet. Une ou plusieurs valeurs peuvent être présentes. Si le paquet n'a pas de dépendance de test, la section est omise. La valeur est une alpm-package-relation de type test dependency (par exemple, example ou example=1.0.0).
