NOM

alpm-repo-files - Format de fichier pour la liste des fichiers et répertoires contenus dans un alpm-package.

DESCRIPTION

Le format alpm-repo-files est un format textuel qui liste les répertoires et fichiers contenus dans un seul alpm-package.

Ces fichiers sont nommés files et se trouvent dans les fichiers alpm-repo-db ainsi que dans les structures de bases de données de libalpm. Ils sont créés par les logiciels de gestion de dépôts de paquets (comme dbscripts [1]). Les logiciels de gestion de paquets (par exemple pacman) les utilisent pour lister et interroger les chemins des répertoires et fichiers contenus dans un fichier paquet.

Format général

Un fichier alpm-repo-files est un fichier encodé en UTF-8, délimité par des sauts de ligne. Il existe en deux styles différents (un pour alpm-db et un pour alpm-repo-db), qui varient légèrement.

Le fichier contient généralement un seul en-tête de section et zéro ou plusieurs entrées de section. Les lignes vides sont ignorées. Les commentaires ne sont pas pris en charge.

La première ligne doit être la chaîne littérale %FILES%, qui représente l'en-tête de section. Notez que, lorsqu'il est utilisé dans le contexte d'une alpm-db, le fichier peut être entièrement vide, s'il ne suit aucun chemin. Cela peut être le cas, par exemple, lors du ciblage d'un alpm-meta-package.

Toutes les lignes suivantes sont interprétées comme des entrées de section, une par ligne, triées par ordre lexical. Chaque entrée de section représente soit un seul chemin de fichier, soit un chemin de répertoire. Les règles de mise en forme suivantes s'appliquent aux chemins :

  • Les répertoires sont toujours listés avec une barre oblique finale (/).
  • Tous les chemins sont relatifs à la racine du système (c'est-à-dire que /usr/bin/foo est représenté par usr/bin/foo).

Notez que, lorsqu'il est utilisé dans le contexte d'une alpm-db, le fichier contient généralement une ligne vide finale, s'il suit au moins un chemin.

EXEMPLES

L'exemple suivant est un fichier alpm-repo-files pour un paquet nommé foo :

%FILES%
usr/
usr/bin/
usr/bin/foo
usr/share/
usr/share/bash-completion/
usr/share/bash-completion/completions/
usr/share/bash-completion/completions/foo
usr/share/doc/
usr/share/doc/foo/
usr/share/doc/foo/README.md
usr/share/fish/
usr/share/fish/vendor_completions.d/
usr/share/fish/vendor_completions.d/foo.fish
usr/share/licenses/
usr/share/licenses/foo/
usr/share/licenses/foo/LICENSE-MIT
usr/share/zsh/
usr/share/zsh/site-functions/
usr/share/zsh/site-functions/_foo

Le paquet installé contiendra un binaire (usr/bin/foo), un fichier README (usr/share/doc/foo/README.md), et un fichier de licence (usr/share/licenses/foo/LICENSE-MIT), parmi d'autres fichiers tels que des scripts d'achèvement pour divers shells.
