DESCRIPTION
ALTER DEFAULT PRIVILEGES permet de définir les privilèges
    qui seront appliqués aux objets créés à l'avenir. (Cela n'affecte pas
    les privilèges attribu
és aux objets d
éjà existants.)

Les

privilèges

peuvent être définis globalement (c'est-à-dire pour tous les objets créés dans la base de données actuelle), ou uniquement pour les objets créés dans des schémas spécifiés. Bien que vous puissiez modifier vos propres privilèges par défaut et ceux des rôles dont vous êtes membre, au moment de la création d'un objet, les nouvelles

permissions

de l'objet ne sont affectées que par les privilèges par défaut du rôle actuel, et ne sont pas héritées des rôles dont le rôle actuel est membre. Comme expliqué à la section 5.8, les privilèges par défaut pour tout type d'objet accordent normalement toutes les permissions accordables au propriétaire de

l'objet,

et peuvent également accorder certains privilèges à PUBLIC. Cependant, ce comportement peut être modifié en altérant les privilèges globaux par défaut avec ALTER DEFAULT PRIVILEGES. Actuellement, seuls les privilèges pour les schémas, les tables (y compris les vues et les tables étrangères), les séqu

ences, les

fonctions, les types (y compris les domaines) et les objets volumineux peuvent être modifiés. Pour cette commande, les fonctions incluent les agrégats et les procédures. Les mots FUNCTIONS et ROUTINES sont équivalents dans cette commande. (ROUTINES est préféré à l'avenir comme terme standard pour désigner les fonctions et les procédures ensemble. Dans les versions antérieures de PostgreSQL, seul le mot FUNCTIONS était autorisé. Il n'est pas possible de définir des privilèges par défaut pour les fonctions et les procédures séparément.) Les privilèges par défaut spécifiés par schéma sont ajoutés

à

ceux qui sont les privilèges globaux par défaut pour le type d'objet particulier. Cela signifie que vous ne pouvez pas révoquer des privilèges par schéma s'ils sont accordés globalement (soit par défaut, soit selon une commande ALTER DEFAULT PRIVILEGES précédente qui ne spécifiait pas de schéma). Un REVOKE par schéma n'est utile que pour annuler les effets d'un GRANT par schéma précédent. Paramètres target_role Modifier les privilèges par
