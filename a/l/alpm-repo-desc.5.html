alpm-repo-desc - Format de fichier pour la représentation des métadonnées des paquets basés sur ALPM dans les dépôts de paquets (version

2)
.

DESCRIPTIO

N

Le format alpm-repo-desc est un format textuel qui représente les métadonnées d'un paquet unique dans une version spécifique d'un dépôt. Chaque fichier décrit diverses propriétés d'un fichier alpm-package, y compris son nom, sa version, ses dépendances, sa taille, ses informations de licence, et plus encore. Pour une liste complète des propriétés, voir ses sections

.

L'ensemble de tous les fichiers alpm-repo-desc dans une alpm-repo-db décrit l'état actuel du dépôt (c'est-à-dire quels paquets sont disponibles dans quelle version)

.

Un système d'exploitation reposant sur la gestion des paquets d'Arch Linux maintient un ou plusieurs fichiers alpm-repo-db qui contiennent chacun un fichier alpm-repo-desc par paquet, chacun nommé desc et situé dans un répertoire unique pour chaque paquet. Plus précisément, des logiciels de gestion de paquets tels que pacman et les outils associés utilisent ce format de fichier, par exemple, pour résoudre les dépendances et afficher les informations des paquets des

fichiers

alpm-package dans les dépôts. Les données dans un fichier alpm-repo-desc proviennent d'un alpm-package. Une grande partie de ses métadonnées provient des données PKGINFO du paquet. Un fichier alpm-repo-desc est généralement créé par un logiciel gérant un alpm-repo, t

el que

repo-add. Le format de fichier décrit dans ce document ne doit pas être confondu avec le format de fichier alpm-db-desc, qui est utilisé dans le contexte d'une base de données libalpm et porte un ensemble différent de métadonnées, mais qui est généralement

aussi nommé

desc. Le format alpm-repo-desc existe en plusieurs versions. Les informations de ce document concernent la version 2, qui est la version actuelle et a été introduite avec la sortie de pacman 6.1.0 le

2024-03-04.

Format

général

Un fichier alpm-repo-desc est un fichier encodé en UTF-8, délimité par des sauts de ligne, composé d'une série de sections

.

Chaque section commence par une ligne d'en-tête de section unique. La ligne d'en-tête de section est suivie d'une ou plusieurs lignes contenant chacune une valeur spécifique à la section. Toutes les valeurs spécifiques à la section doivent se composer de caractères ASCII imprimables[1] sauf indication contraire. Une section se termine lorsqu'une autre ligne d'en-tête de section est rencontrée ou que la fin du fichier est atteinte. Les lignes vides entre les sections sont

ignorées.

%LICENSE

Un ensemble facultatif d'identifiants de licence qui s'appliquent au paquet. Une ou plusieurs valeurs peuvent être présentes. S'il n'y a pas d'identifiant de licence, la section est

omise.

Chaque valeur représente un identifiant de licence, qui est une chaîne de longueur non nulle (par exemple GPL). Bien qu'aucune restriction spécifique ne soit imposée à la valeur en dehors de sa longueur, il est fortement recommandé de s'appuyer sur les expressions de licence SPDX (par exemple GPL-3.0-or-later ou Apache-2.0 OR MIT). Voir la liste des licences SPDX[6]

pour plus d'

%

L'architecture du paquet (voir alpm-architecture pour plus d'informations). La valeur doit être couverte par l'ensemble des caractères alphanumériques et « _ » (par exemple x86_64 ou an

y)
.

%BUILDDATE

%

La date à laquelle la construction du paquet a commencé. La valeur doit être numérique et représenter les secondes depuis l'Epoch, aussi appelé « Unix time » (par exemple 1729181726).p

>

%PACKAGER

%

L'identifiant utilisateur (User ID) de l'entité qui a construit le paquet. La valeur est destinée à être utilisée pour la recherche d'identité et représente un identifiant utilisateur OpenPGP[7]. En tant que tel, la valeur est une chaîne encodée en UTF-8, qui est conventionnellement composée d'un nom et d'une adresse e-mail, ce qui correspond au format décrit dans RFC 28228

.

%REPLACES

%

Un autre composant virtuel ou paquet, que le paquet remplace lors de l'installation. Une ou plusieurs valeurs peuvent être présentes. Si le paquet ne remplace rien, la section est omise. La valeur est une alpm-package-relation de type remplacement (par exemple example ou example=1.0.

0)
.

%CONFLICTS

%

Un autre composant virtuel ou paquet, avec lequel le paquet entre en conflit. Une ou plusieurs valeurs peuvent être présentes. Si le paquet n'entre en conflit avec rien, la section est omise. La valeur est une alpm-package-relation de type conflit (par exemple example ou example=1.0.

0)
.

%PROVIDES

%

Un autre composant virtuel ou paquet, que le paquet fournit. Une ou plusieurs valeurs peuvent être présentes. Si le paquet ne fournit rien, la section est omise. La valeur est une alpm-package-relation de type fourniture (par exemple example ou example=1.0.

0)
.

%DEPENDS

%

Une dépendance d'exécution du paquet (composant virtuel ou paquet). Une ou plusieurs valeurs peuvent être présentes. Si le paquet n'a pas de dépendance d'exécution, la section est omise. La valeur est une alpm-package-relation de type dépendance d'exécution (par exemple example ou example=1.0.

0)
.

%OPTDEPENDS

%

Une dépendance optionnelle du paquet (composant virtuel ou paquet). Une ou plusieurs valeurs peuvent être présentes. Si le paquet n'a pas de dépendance optionnelle, la section est omise. La valeur est une alpm-package-relation de type dépendance optionnelle (par exemple example ou example: ceci est

une desc
ription).

%MAKEDEPENDS

%

Une dépendance pour construire le logiciel en amont du paquet. Une ou plusieurs valeurs peuvent être présentes. Si le paquet n'a pas de dépendance de compilation, la section est omise. La valeur est une alpm-package-relation de type dépendance de compilation (par exemple example ou example=1.0.

0)
.

%CHECKDEPENDS

%

Une dépendance pour exécuter les tests du projet en amont du paquet. Une ou plusieurs valeurs peuvent être présentes. Si le paquet n'a pas de dépendance de test, la section est omise. La valeur est une alpm-package-relation de type dépendance de test (par exemple example ou exampl

e=1
