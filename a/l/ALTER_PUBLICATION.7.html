ALTER PUBLICATION(7) Documentation PostgreSQL 18.1 ALTER PUBLICATION(7)

NOM

ALTER_PUBLICATION - modifie la définition d'une publication

SYNOPSIS

ALTER PUBLICATION name ADD publication_object [, ...]
ALTER PUBLICATION name SET publication_object [, ...]
ALTER PUBLICATION name DROP publication_object [, ...]
ALTER PUBLICATION name SET ( publication_parameter [= value] [, ... ] )
ALTER PUBLICATION name OWNER TO { new_owner | CURRENT_ROLE | CURRENT_USER | SESSION_USER }
ALTER PUBLICATION name RENAME TO new_name
où publication_object est l'une des suivantes :
    TABLE [ ONLY ] table_name [ * ] [ ( column_name [, ... ] ) ] [ WHERE ( expression ) ] [, ... ]
    TABLES IN SCHEMA { schema_name | CURRENT_SCHEMA } [, ... ]

DESCRIPTION

La commande ALTER PUBLICATION peut modifier les attributs d'une publication.

Les trois premières variantes modifient les tables/schémas qui font partie de la publication. La clause SET remplace la liste des tables/schémas de la publication par la liste spécifiée ; les tables/schémas existants présents dans la publication seront supprimés. Les clauses ADD et DROP ajoutent et suppriment une ou plusieurs tables/schémas de la publication. Notez que l'ajout de tables/schémas à une publication déjà souscrite nécessitera une action ALTER SUBSCRIPTION ... REFRESH PUBLICATION du côté abonné afin de prendre effet. Notez également que DROP TABLES IN SCHEMA ne supprimera aucune table de schéma spécifiée à l'aide de FOR TABLE/ ADD TABLE, et que la combinaison de DROP avec une clause WHERE n'est pas autorisée.

La quatrième variante de cette commande listée dans le synopsis peut modifier toutes les propriétés de publication spécifiées dans CREATE PUBLICATION (CREATE_PUBLICATION(7)). Les propriétés non mentionnées dans la commande conservent leurs paramètres précédents.

Les variantes restantes modifient le propriétaire et le nom de la publication.

Vous devez être propriétaire de la publication pour utiliser ALTER PUBLICATION. L'ajout d'une table à une publication nécessite également d'être propriétaire de cette table. L'ajout de ADD TABLES IN SCHEMA et SET TABLES IN SCHEMA à une publication nécessite que l'utilisateur appelant soit un superutilisateur. Pour modifier le propriétaire, vous devez pouvoir exécuter SET ROLE vers le nouveau rôle propriétaire, et ce rôle doit avoir le privilège CREATE sur la base de données. De plus, le nouveau propriétaire d'une publication FOR ALL TABLES ou FOR TABLES IN SCHEMA doit être un superutilisateur. Cependant, un superutilisateur peut changer la propriété d'une publication indépendamment de ces restrictions.

L'ajout/définition de n'importe quel schéma lorsque la publication publie également une table avec une liste de colonnes, et inversement, n'est pas pris en charge.

PARAMÈTRES

name

Le nom d'une publication existante dont la définition doit être modifiée.

table_name

Nom d'une table existante. Si ONLY est spécifié avant le nom de la table, seule cette table est affectée. Si ONLY n'est pas spécifié, la table et toutes ses tables descendantes (le cas échéant) sont affectées. En option, * peut être spécifié après le nom de la table pour indiquer explicitement que les tables descendantes sont incluses.

En option, une liste de colonnes peut être spécifiée. Voir CREATE PUBLICATION (CREATE_PUBLICATION(7)) pour plus de détails. Notez qu'un abonnement ayant plusieurs publications dans lesquelles la même table a été publiée avec différentes listes de colonnes n'est pas pris en charge. Voir Avertissement : Combinaison de listes de colonnes à partir de plusieurs publications pour les détails des problèmes potentiels lors de la modification des listes de colonnes.

Si la clause WHERE facultative est spécifiée, les lignes pour lesquelles le expression évalue à faux ou null ne seront pas publiées. Notez que des parenthèses sont requises autour de l'expression. Le expression est évalué avec le rôle utilisé pour la connexion de réplication.

schema_name

Nom d'un schéma existant.

SET ( publication_parameter [= value] [, ... ] )

Cette clause modifie les paramètres de publication initialement définis par CREATE PUBLICATION (CREATE_PUBLICATION(7)). Voir là-bas pour plus d'informations.

Attention
La modification du paramètre publish_via_partition_root peut entraîner une perte ou une duplication de données chez l'abonné car elle change l'identité et le schéma des tables publiées. Notez que cela ne se produit que lorsqu'une table racine de partition est spécifiée comme cible de réplication.

Ce problème peut être évité en s'abstenant de modifier les tables de partition feuilles après le ALTER PUBLICATION ... SET jusqu'à ce que le ALTER SUBSCRIPTION ... REFRESH PUBLICATION soit exécuté et en ne rafraîchissant qu'avec l'option copy_data = off.

new_owner

Le nom d'utilisateur du nouveau propriétaire de la publication.

new_name

Le nouveau nom de la publication.

EXEMPLES

Modifier la publication pour ne publier que les suppressions et les mises à jour :

ALTER PUBLICATION noinsert SET (publish = 'update, delete');

Ajouter quelques tables à la publication :

ALTER PUBLICATION mypublication ADD TABLE users (user_id, firstname), departments;

Modifier l'ensemble des colonnes publiées pour une table :

ALTER PUBLICATION mypublication SET TABLE users (user_id, firstname, lastname), TABLE departments;

Ajouter les schémas marketing et sales à la publication sales_publication :

ALTER PUBLICATION sales_publication ADD TABLES IN SCHEMA marketing, sales;

Ajouter les tables users, departments et le schéma production à la publication production_publication :

ALTER PUBLICATION production_publication ADD TABLE users, departments, TABLES IN SCHEMA production;

COMPATIBILITÉ

ALTER PUBLICATION est une extension PostgreSQL.

VOIR AUSSI
