NOM

Algorithm::Diff - Calcule les différences « intelligentes » entre deux fichiers / listes

SYNOPSIS

require Algorithm::Diff;
# Cet exemple produit une sortie 'diff' traditionnelle :
my $diff = Algorithm::Diff->new( \@seq1, \@seq2 );
$diff->Base( 1 );   # Retourne les numéros de ligne, pas les indices
while(  $diff->Next()  ) {
    next   if  $diff->Same();
    my $sep = '';
    if(  ! $diff->Items(2)  ) {
        printf "%d,%dd%d\n",
            $diff->Get(qw( Min1 Max1 Max2 ));
    } elsif(  ! $diff->Items(1)  ) {
        printf "%da%d,%d\n",
            $diff->Get(qw( Max1 Min2 Max2 ));
    } else {
        $sep = "---\n";
        printf "%d,%dc%d,%d\n",
            $diff->Get(qw( Min1 Max1 Min2 Max2 ));
    }
    print "< $_"   for  $diff->Items(1);
    print $sep;
    print "> $_"   for  $diff->Items(2);
}
# Interfaces alternatives :
use Algorithm::Diff qw(
    LCS LCS_length LCSidx
    diff sdiff compact_diff
    traverse_sequences traverse_balanced );
@lcs    = LCS( \@seq1, \@seq2 );
$lcsref = LCS( \@seq1, \@seq2 );
$count  = LCS_length( \@seq1, \@seq2 );
( $seq1idxref, $seq2idxref ) = LCSidx( \@seq1, \@seq2 );
# Interfaces compliquées :
@diffs  = diff( \@seq1, \@seq2 );
@sdiffs = sdiff( \@seq1, \@seq2 );
@cdiffs = compact_diff( \@seq1, \@seq2 );
traverse_sequences(
    \@seq1,
    \@seq2,
    {   MATCH     => \&callback1,
        DISCARD_A => \&callback2,
        DISCARD_B => \&callback3,
    },
    \&key_generator,
    @extra_args,
);
traverse_balanced(
    \@seq1,
    \@seq2,
    {   MATCH     => \&callback1,
        DISCARD_A => \&callback2,
        DISCARD_B => \&callback3,
        CHANGE    => \&callback4,
    },
    \&key_generator,
    @extra_args,
);

INTRODUCTION

(par Mark-Jason Dominus)

J'ai lu un jour un article écrit par les auteurs de "diff"; ils disaient qu'ils avaient travaillé très dur sur l'algorithme jusqu'à ce qu'ils trouvent le bon.

Je pense que ce qu'ils ont fini par utiliser (et j'espère que quelqu'un me corrigera, car je ne suis pas très sûr de cela) était la méthode de la « plus longue sous-séquence commune ». Dans le problème de la LCS, vous avez deux séquences d'éléments :

a b c d f g h j q z
a b c d e f g i j k r x y z

et vous voulez trouver la plus longue séquence d'éléments présente dans les deux séquences d'origine dans le même ordre. C'est-à-dire, vous voulez trouver une nouvelle séquence S qui peut être obtenue à partir de la première séquence en supprimant certains éléments, et à partir de la deuxième séquence en supprimant d'autres éléments. Vous voulez aussi que S soit aussi longue que possible. Dans ce cas, S est

a b c d f g j z

De là, il ne manque qu'un petit pas pour obtenir une sortie de type diff :

e   h i   k   q r x y
+   - +   +   - + + +

Ce module résout le problème de la LCS. Il inclut également une fonction toute faite pour générer une sortie de type "diff".

D'après l'exemple ci-dessus, il pourrait sembler que la LCS de deux séquences est toujours assez évidente, mais ce n'est pas toujours le cas, surtout lorsque les deux séquences ont de nombreux éléments répétés. Par exemple, considérez

a x b y c z p d q
a b c a x b y c z

Une approche naïve pourrait commencer par appairer le "a" et le "b" qui apparaissent au début de chaque séquence, comme ceci :

a x b y c         z p d q
a   b   c a b y c z

Cela trouve la sous-séquence commune "a b c z". Mais en fait, la LCS est "a x b y c z":

      a x b y c z p d q
a b c a x b y c z

ou

a       x b y c z p d q
a b c a x b y c z

UTILISATION

(Voir aussi le fichier README et plusieurs scripts d'exemple inclus avec ce module.)

Ce module fournit maintenant une interface orientée objet qui utilise moins de mémoire et est plus facile à utiliser que la plupart des interfaces procédurales précédentes. Il fournit toujours plusieurs fonctions exportables. Nous les aborderons par ordre croissant de difficulté : "LCS", "LCS_length", "LCSidx", interface OO, "prepare", "diff", "sdiff", "traverse_sequences", et "traverse_balanced".

"LCS"

Étant donné des références à deux listes d'éléments, LCS retourne un tableau contenant leur plus longue sous-séquence commune. En contexte scalaire, elle retourne une référence à une telle liste.

@lcs    = LCS( \@seq1, \@seq2 );
$lcsref = LCS( \@seq1, \@seq2 );

"LCS" peut recevoir un troisième paramètre optionnel ; c'est une référence CODE à une fonction de génération de clé. Voir "FONCTIONS DE GÉNÉRATION DE CLÉS".

@lcs    = LCS( \@seq1, \@seq2, \&keyGen, @args );
$lcsref = LCS( \@seq1, \@seq2, \&keyGen, @args );

Les paramètres supplémentaires, s'il y en a, seront passés à la routine de génération de clés.

"LCS_length"

C'est exactement comme "LCS" sauf qu'elle ne retourne que la longueur de la plus longue sous-séquence commune. Cela offre un gain de performance d'environ 9 % par rapport à "LCS".

"LCSidx"

Comme "LCS" sauf qu'elle retourne des références à deux tableaux. Le premier tableau contient les indices dans @seq1 où se trouvent les éléments de la LCS. Le deuxième tableau contient les indices dans @seq2 où se trouvent les éléments de la LCS.

Par conséquent, les trois listes suivantes contiendront les mêmes valeurs :

my( $idx1, $idx2 ) = LCSidx( \@seq1, \@seq2 );
my @list1 = @seq1[ @$idx1 ];
my @list2 = @seq2[ @$idx2 ];
my @list3 = LCS( \@seq1, \@seq2 );

"new"

$diff = Algorithm::Diff->new( \@seq1, \@seq2 );
$diff = Algorithm::Diff->new( \@seq1, \@seq2, \%opts );

"new" calcule le plus petit ensemble d'ajouts et de suppressions nécessaire pour transformer la première séquence en la deuxième et les enregistre de manière compacte dans l'objet.

Vous utilisez l'objet pour itérer sur les blocs, où chaque bloc représente une section contiguë d'éléments qui doivent être ajoutés, supprimés, remplacés ou laissés inchangés.

Le résumé suivant de toutes les méthodes ressemble beaucoup à du code Perl mais certains symboles ont des significations différentes :

[ ]     Enveloppe des arguments optionnels
:       Est suivi de la valeur par défaut d'un argument optionnel
|       Sépare les résultats de retour alternatifs

Résumé des méthodes :

$obj        = Algorithm::Diff->new( \@seq1, \@seq2, [ \%opts ] );
$pos        = $obj->Next(  [ $count : 1 ] );
$revPos     = $obj->Prev(  [ $count : 1 ] );
$obj        = $obj->Reset( [ $pos : 0 ] );
$copy       = $obj->Copy(  [ $pos, [ $newBase ] ] );
$oldBase    = $obj->Base(  [ $newBase ] );

Notez que toutes les méthodes suivantes "die" si elles sont utilisées sur un objet qui est "réinitialisé" (ne pointant actuellement vers aucun bloc).

$bits       = $obj->Diff(  );
@items|$cnt = $obj->Same(  );
@items|$cnt = $obj->Items( $seqNum );
@idxs |$cnt = $obj->Range( $seqNum, [ $base ] );
$minIdx     = $obj->Min(   $seqNum, [ $base ] );
$maxIdx     = $obj->Max(   $seqNum, [ $base ] );
@values     = $obj->Get(   @names );

Passer "undef" pour un argument optionnel est toujours traité de la même manière que si aucun argument n'était passé.

"Next"
$pos = $diff->Next();    # Avance d'un bloc
$pos = $diff->Next( 2 ); # Avance de deux blocs
$pos = $diff->Next(-5);  # Recule de cinq blocs

"Next" déplace l'objet pour qu'il pointe vers le suivant. L'objet commence dans un état "réinitialisé", ce qui signifie qu'il ne pointe vers aucun bloc. Si l'objet est réinitialisé, alors Next() se déplace vers le premier bloc.

"Next" retourne une valeur vraie si le déplacement n'est pas allé au-delà du dernier bloc. Ainsi Next(0) renverra une valeur vraie si l'objet n'est pas réinitialisé.

En fait, "Next" renvoie la nouvelle position de l'objet, qui est un nombre compris entre 1 et le nombre de blocs (inclus), ou renvoie une valeur fausse.

"Prev"
Prev($N) est presque identique à Next(-$N); il se déplace vers le $Nième bloc précédent. Sur un objet 'réinitialisé', Prev() [et Next(-1)] se déplacent vers le dernier bloc.

La position renvoyée par "Prev" est relative à la fin des blocs ; -1 pour le dernier bloc, -2 pour l'avant-dernier, etc.

"Reset"
$diff->Reset();     # Réinitialise la position de l'objet
$diff->Reset($pos); # Se déplace vers le bloc spécifié
$diff->Reset(1);    # Se déplace vers le premier bloc
$diff->Reset(-1);   # Se déplace vers le dernier bloc

"Reset" renvoie l'objet, donc, par exemple, vous pourriez utiliser "$diff->Reset()->Next(-1)" pour obtenir le nombre de blocs.

"Copy"
$copy = $diff->Copy( $newPos, $newBase );

"Copy" renvoie une copie de l'objet. La copie et l'objet original partagent la plupart de leurs données, donc faire des copies prend très peu de mémoire. La copie maintient sa propre position (séparée de celle de l'original), ce qui est le but principal des copies. Elle maintient également sa propre base.

Par défaut, la position de la copie est initialement la même que celle de l'objet original. Mais "Copy" accepte un premier argument optionnel pour définir la nouvelle position, donc les trois extraits suivants sont équivalents :

$copy = $diff->Copy($pos);
$copy = $diff->Copy();
$copy->Reset($pos);
$copy = $diff->Copy()->Reset($pos);

"Copy" accepte un deuxième argument optionnel pour définir la base de la copie. Si vous souhaitez changer la base de la copie mais laisser la position identique à celle de l'original, voici deux manières équivalentes :

$copy = $diff->Copy();
$copy->Base( 0 );
$copy = $diff->Copy(undef,0);

Voici deux manières équivalentes d'obtenir une copie "réinitialisée" :

$copy = $diff->Copy(0);
$copy = $diff->Copy()->Reset();
"Diff"
$bits = $obj->Diff();

"Diff" renvoie une valeur vraie si et seulement si le bloc courant contient des éléments qui sont différents entre les deux séquences. Il renvoie en réalité l'une des 4 valeurs suivantes :

3
"3==(1|2)". Ce bloc contient des éléments de @seq1 et les éléments de @seq2 qui doivent les remplacer. Les séquences 1 et 2 contiennent toutes deux des éléments modifiés, donc les bits 1 et 2 sont définis.
2
Ce bloc ne contient que des éléments de @seq2 qui doivent être insérés (et non des éléments de @seq1). Seule la séquence 2 contient des éléments modifiés, donc seul le bit 2 est défini.
1
Ce bloc ne contient que des éléments de @seq1 qui doivent être supprimés (et non des éléments de @seq2). Seule la séquence 1 contient des éléments modifiés, donc seul le bit 1 est défini.
0
Cela signifie que les éléments de ce bloc sont identiques dans les deux séquences. Ni la séquence 1 ni la séquence 2 ne contiennent d'éléments modifiés, donc ni le bit 1 ni le bit 2 ne sont définis.
"Same"
"Same" renvoie une valeur vraie si et seulement si le bloc courant contient des éléments qui sont identiques dans les deux séquences. Il renvoie en réalité la liste des éléments s'ils sont identiques, ou une liste vide s'ils ne le sont pas. Dans un contexte scalaire, il renvoie la taille de la liste.
"Items"
$count = $diff->Items(2);
@items = $diff->Items($seqNum);

"Items" renvoie les éléments (ou le nombre d'éléments) de la séquence spécifiée qui font partie du bloc courant.

Si le bloc courant ne contient que des insertions, alors "$diff->Items(1)" renverra une liste vide (0 dans un contexte scalaire). Si le bloc courant ne contient que des suppressions, alors "$diff->Items(2)" renverra une liste vide (0 dans un contexte scalaire).

Si le bloc contient des remplacements, alors à la fois "$diff->Items(1)" et "$diff->Items(2)" renverront des listes différentes et non vides.

Sinon, le bloc contient des éléments identiques et tout ce qui suit renverra les mêmes listes :

@items = $diff->Items(1);
@items = $diff->Items(2);
@items = $diff->Same();
"Range"
$count = $diff->Range( $seqNum );
@indices = $diff->Range( $seqNum );
@indices = $diff->Range( $seqNum, $base );

"Range" est comme "Items" sauf qu'il renvoie une liste d' indices vers les éléments plutôt que les éléments eux-mêmes. Par défaut, l'index du premier élément (dans chaque séquence) est 0 mais cela peut être changé en appelant la méthode "Base" . Ainsi, par défaut, les deux extraits suivants renvoient les mêmes listes :

@list = $diff->Items(2);
@list = @seq2[ $diff->Range(2) ];

Vous pouvez également spécifier la base à utiliser comme deuxième argument. Ainsi les deux extraits suivants toujours renvoient les mêmes listes :

@list = $diff->Items(1);
@list = @seq1[ $diff->Range(1,0) ];
"Base"
$curBase = $diff->Base();
$oldBase = $diff->Base($newBase);

"Base" définit et/ou renvoie la base courante (généralement 0 ou 1) qui est utilisée lorsque vous demandez des informations de plage. La base vaut par défaut 0 afin que les informations de plage soient renvoyées sous forme d'indices de tableau. Vous pouvez définir la base à 1 si vous préférez rapporter des numéros de ligne traditionnels.

"Min"
$min1 = $diff->Min(1);
$min = $diff->Min( $seqNum, $base );

"Min" renvoie la première valeur que "Range" renverrait (avec les mêmes arguments) ou renvoie "undef" si "Range" renverrait une liste vide.

"Max"
"Max" renvoie la dernière valeur que "Range" renverrait ou "undef".
"Get"
( $n, $x, $r ) = $diff->Get(qw( min1 max1 range1 ));
@values = $diff->Get(qw( 0min2 1max2 range2 same base ));

"Get" renvoie une ou plusieurs valeurs scalaires. Vous passez une liste des noms des valeurs que vous souhaitez voir renvoyées. Chaque nom doit correspondre à l'une des expressions régulières suivantes :

/^(-?\d+)?(min|max)[12]$/i
/^(range[12]|same|diff|base)$/i

Le 1 ou 2 après un nom indique pour quelle séquence vous voulez les informations (et, lorsque c'est autorisé, il est requis). Le nombre optionnel avant "min" ou "max" est la base à utiliser. Ainsi, les égalités suivantes sont valables :

$diff->Get('min1') == $diff->Min(1)
$diff->Get('0min2') == $diff->Min(2,0)

Utiliser "Get" dans un contexte scalaire lorsque vous avez passé plus d'un nom est une erreur fatale ("die" est appelé).

"prepare"

Étant donné une référence à une liste d'éléments, "prepare" renvoie une référence à un hachage qui peut être utilisé pour comparer cette séquence à d'autres séquences avec "LCS" ou "LCS_length".

$prep = prepare( \@seq1 );
for $i ( 0 .. 10_000 )
{
    @lcs = LCS( $prep, $seq[$i] );
    # faire quelque chose d'utile avec @lcs
}

"prepare" peut recevoir un troisième paramètre optionnel ; c'est une référence CODE à une fonction de génération de clés. Voir "KEY GENERATION FUNCTIONS".

$prep = prepare( \@seq1, \&keyGen );
for $i ( 0 .. 10_000 )
{
    @lcs = LCS( $seq[$i], $prep, \&keyGen );
    # faire quelque chose d'utile avec @lcs
}

Utiliser "prepare" procure un gain de performance d'environ 50% lors de nombreux appels à LCS par rapport à l'absence de préparation.

"diff"

@diffs     = diff( \@seq1, \@seq2 );
$diffs_ref = diff( \@seq1, \@seq2 );

"diff" calcule le plus petit ensemble d'ajouts et de suppressions nécessaire pour transformer la première séquence en la seconde, et renvoie une description de ces changements. La description est une liste de blocs; chaque bloc représente une section contiguë d'éléments qui doivent être ajoutés, supprimés ou remplacés. (Les blocs contenant des éléments inchangés ne sont pas inclus.)

La valeur de retour de "diff" est une liste de blocs, ou, dans un contexte scalaire, une référence à une telle liste. S'il n'y a pas de différences, la liste sera vide.

Voici un exemple. Appeler "diff" pour les deux séquences suivantes :

a b c e h j l m n p
b c d e f j k l m r s t

produirait la liste suivante :

(
  [ [ '-', 0, 'a' ] ],
  [ [ '+', 2, 'd' ] ],
  [ [ '-', 4, 'h' ],
    [ '+', 4, 'f' ] ],
  [ [ '+', 6, 'k' ] ],
  [ [ '-',  8, 'n' ],
    [ '-',  9, 'p' ],
    [ '+',  9, 'r' ],
    [ '+', 10, 's' ],
    [ '+', 11, 't' ] ],
)

Il y a cinq blocs ici. Le premier bloc indique que le "a" à la position 0 de la première séquence doit être supprimé ("-"). Le deuxième bloc indique que le "d" à la position 2 de la deuxième séquence doit être inséré ("+"). Le troisième bloc indique que le "h" à la position 4 de la première séquence doit être retiré et remplacé par le "f" de la position 4 de la deuxième séquence. Et ainsi de suite.

"diff" peut recevoir un troisième paramètre optionnel ; il s'agit d'une référence CODE vers une fonction de génération de clé. Voir "KEY GENERATION FUNCTIONS".

Les paramètres supplémentaires, s'il y en a, seront passés à la routine de génération de clé.

"sdiff"

@sdiffs     = sdiff( \@seq1, \@seq2 );
$sdiffs_ref = sdiff( \@seq1, \@seq2 );

"sdiff" calcule tous les composants nécessaires pour afficher deux séquences et leurs différences minimisées côte à côte, tout comme l'utilitaire Unix sdiff le fait :

same             same
before     |     after
old        <     -
-          >     new

Elle retourne une liste de références de tableaux, chacune pointant vers un tableau d'instructions d'affichage. En contexte scalaire, elle retourne une référence vers une telle liste. S'il n'y a pas de différences, la liste contiendra une entrée pour chaque élément, chacune indiquant que l'élément n'a pas été modifié.

Les instructions d'affichage se composent de trois éléments : un indicateur de modificateur ("+": élément ajouté, "-": élément supprimé, "u": élément non modifié, "c": élément modifié) et les valeurs des éléments ancien et nouveau, à afficher côte à côte.

Un "sdiff" des deux séquences suivantes :

a b c e h j l m n p
b c d e f j k l m r s t

donne

( [ '-', 'a', ''  ],
  [ 'u', 'b', 'b' ],
  [ 'u', 'c', 'c' ],
  [ '+', '',  'd' ],
  [ 'u', 'e', 'e' ],
  [ 'c', 'h', 'f' ],
  [ 'u', 'j', 'j' ],
  [ '+', '',  'k' ],
  [ 'u', 'l', 'l' ],
  [ 'u', 'm', 'm' ],
  [ 'c', 'n', 'r' ],
  [ 'c', 'p', 's' ],
  [ '+', '',  't' ],
)

"sdiff" peut recevoir un troisième paramètre optionnel ; il s'agit d'une référence CODE vers une fonction de génération de clé. Voir "KEY GENERATION FUNCTIONS".

Les paramètres supplémentaires, s'il y en a, seront passés à la routine de génération de clé.

"compact_diff"

"compact_diff" est très similaire à "sdiff" sauf qu'elle retourne une description beaucoup plus compacte consistant en une seule liste plate d'indices. Un exemple aide à expliquer le format :

my @a = qw( a b c   e  h j   l m n p      );
my @b = qw(   b c d e f  j k l m    r s t );
@cdiff = compact_diff( \@a, \@b );
# Returns:
#   @a      @b       @a       @b
#  start   start   values   values
(    0,      0,   #       =
     0,      0,   #    a  !
     1,      0,   #  b c  =  b c
     3,      2,   #       !  d
     3,      3,   #    e  =  e
     4,      4,   #    f  !  h
     5,      5,   #    j  =  j
     6,      6,   #       !  k
     6,      7,   #  l m  =  l m
     8,      9,   #  n p  !  r s t
    10,     12,   #
);

Les entrées 0, 2, 4, etc. sont toutes des indices dans @seq1 (@a dans l'exemple ci-dessus) indiquant où un bloc commence. Les entrées 1, 3, 5, etc. sont toutes des indices dans @seq2 (@b dans l'exemple ci-dessus) indiquant où le même bloc commence.

Ainsi, chaque paire d'indices (sauf la dernière paire) décrit où un bloc commence (dans chaque séquence). Puisque chaque bloc doit se terminer à l'élément juste avant celui qui commence le bloc suivant, la paire d'indices suivante peut être utilisée pour déterminer où le bloc se termine.

Ainsi, les 4 premières entrées (0..3) décrivent le premier bloc. Les entrées 0 et 1 décrivent où le premier bloc commence (et sont donc toujours toutes les deux à 0). Les entrées 2 et 3 décrivent où le bloc suivant commence, donc en soustrayant 1 de chacune, nous savons où le premier bloc se termine. C'est-à-dire que le premier bloc contient les éléments $diff[0] à "$diff[2] - 1" de la première séquence et contient les éléments $diff[1] à "$diff[3] - 1" de la deuxième séquence.

En d'autres termes, le premier bloc se compose des deux listes suivantes d'éléments :

           #  1st pair     2nd pair
           # of indices   of indices
@list1 = @a[ $cdiff[0] .. $cdiff[2]-1 ];
@list2 = @b[ $cdiff[1] .. $cdiff[3]-1 ];
           # Hunk start   Hunk end

Notez que les blocs alterneront toujours entre ceux qui font partie de la LCS (ceux qui contiennent des éléments inchangés) et ceux qui contiennent des changements. Cela signifie que tout ce dont nous avons besoin est de savoir si le premier bloc est un bloc 'same' ou 'diff', et nous pouvons déterminer lesquels des autres blocs contiennent des éléments 'same' ou 'diff'.

Par convention, nous faisons toujours en sorte que le premier bloc contienne des éléments inchangés. Ainsi, les blocs 1, 3, 5, etc. (tous les blocs de numéro impair si vous commencez à compter à partir de 1) contiennent tous des éléments inchangés. Et les blocs 2, 4, 6, etc. (tous les blocs de numéro pair si vous commencez à compter à partir de 1) contiennent tous des éléments modifiés.

Puisque @a et @b ne commencent pas par la même valeur, le premier bloc dans notre exemple est vide (sinon nous violerions la convention ci-dessus). Notez que les 4 premières valeurs d'indices dans notre exemple sont toutes à zéro. Insérez ces valeurs dans notre bloc de code précédent et nous obtenons :

@hunk1a = @a[ 0 .. 0-1 ];
@hunk1b = @b[ 0 .. 0-1 ];

Et "0..-1" retourne la liste vide.

Descendez d'une paire d'indices (2..5) et nous obtenons les plages d'offsets pour le deuxième bloc, qui contient des éléments modifiés.

Puisque @diff[2..5] contient (0,0,1,0) dans notre exemple, le deuxième bloc se compose de ces deux listes d'éléments :

    @hunk2a = @a[ $cdiff[2] .. $cdiff[4]-1 ];
    @hunk2b = @b[ $cdiff[3] .. $cdiff[5]-1 ];
# or
    @hunk2a = @a[ 0 .. 1-1 ];
    @hunk2b = @b[ 0 .. 0-1 ];
# or
    @hunk2a = @a[ 0 .. 0 ];
    @hunk2b = @b[ 0 .. -1 ];
# or
    @hunk2a = ( 'a' );
    @hunk2b = ( );

C'est-à-dire que nous supprimerions l'élément 0 ('a') de @a.

Puisque @diff[4..7] contient (1,0,3,2) dans notre exemple, le troisième bloc se compose de ces deux listes d'éléments :

    @hunk3a = @a[ $cdiff[4] .. $cdiff[6]-1 ];
    @hunk3a = @b[ $cdiff[5] .. $cdiff[7]-1 ];
# or
    @hunk3a = @a[ 1 .. 3-1 ];
    @hunk3a = @b[ 0 .. 2-1 ];
# or
    @hunk3a = @a[ 1 .. 2 ];
    @hunk3a = @b[ 0 .. 1 ];
# or
    @hunk3a = qw( b c );
    @hunk3a = qw( b c );

Notez que ce troisième bloc contient des éléments inchangés comme l'exige notre convention.

Vous pouvez continuer ce processus jusqu'à ce que vous atteigniez les deux derniers indices, qui seront toujours le nombre d'éléments dans chaque séquence. Cela est nécessaire pour que la soustraction de 1 à chacun vous donne les indices des derniers éléments de chaque séquence.

"traverse_sequences"

"traverse_sequences" était la fonctionnalité la plus générale fournie par ce module (la nouvelle interface OO est plus puissante et beaucoup plus facile à utiliser).

Imaginez qu'il y ait deux flèches. La flèche A pointe vers un élément de la séquence A, et la flèche B pointe vers un élément de la séquence B. Initialement, les flèches pointent vers les premiers éléments des séquences respectives. "traverse_sequences" fera avancer les flèches à travers les séquences un élément à la fois, en appelant une fonction de rappel appropriée spécifiée par l'utilisateur avant chaque avancement. Elle fera avancer les flèches de telle manière que s'il y a des éléments égaux $A[$i] et $B[$j] qui sont égaux et qui font partie de la LCS, il y aura un moment pendant l'exécution de "traverse_sequences" où la flèche A pointe vers $A[$i] et la flèche B pointe vers $B[$j]. Quand cela se produit, "traverse_sequences" appellera la fonction de rappel "MATCH" puis fera avancer les deux flèches.

Sinon, l'une des flèches pointe vers un élément de sa séquence qui ne fait pas partie de la LCS. "traverse_sequences" fera avancer cette flèche et appellera le rappel "DISCARD_A" ou "DISCARD_B" , selon la flèche qu'elle a fait avancer. Si les deux flèches pointent vers des éléments qui ne font pas partie de la LCS, alors "traverse_sequences" en fera avancer une et appellera le rappel approprié, mais il n'est pas spécifié lequel elle appellera.

Les arguments de "traverse_sequences" sont les deux séquences à parcourir, et un hash qui spécifie les fonctions de rappel, comme ceci :

traverse_sequences(
    \@seq1, \@seq2,
    {   MATCH => $callback_1,
        DISCARD_A => $callback_2,
        DISCARD_B => $callback_3,
    }
);

Les rappels pour MATCH, DISCARD_A et DISCARD_B sont invoqués avec au moins les indices des deux flèches comme arguments. On ne s'attend pas à ce qu'ils retournent des valeurs. Si un rappel est omis de la table, il n'est pas appelé.

Les rappels pour A_FINISHED et B_FINISHED sont invoqués avec au moins l'indice correspondant dans A ou B.

Si la flèche A atteint la fin de sa séquence avant que la flèche B ne le fasse, "traverse_sequences" appellera le rappel "A_FINISHED" quand elle fera avancer la flèche B, s'il y a une telle fonction ; sinon elle appellera "DISCARD_B" à la place. De même si la flèche B se termine la première. "traverse_sequences" se termine lorsque les deux flèches sont aux extrémités de leurs séquences respectives. Elle retourne vrai en cas de succès et faux en cas d'échec. Actuellement, il n'y a aucun moyen d'échouer.

"traverse_sequences" peut recevoir un quatrième paramètre optionnel ; il s'agit d'une référence CODE vers une fonction de génération de clé. Voir "KEY GENERATION FUNCTIONS".

Les paramètres supplémentaires, s'il y en a, seront passés à la fonction de génération de clé.

Si vous voulez passer des paramètres supplémentaires à vos rappels, mais que vous n'avez pas besoin d'une fonction de génération de clé personnalisée, vous pouvez obtenir la valeur par défaut en passant undef :

traverse_sequences(
    \@seq1, \@seq2,
    {   MATCH => $callback_1,
        DISCARD_A => $callback_2,
        DISCARD_B => $callback_3,
    },
    undef,     # default key-gen
    $myArgument1,
    $myArgument2,
    $myArgument3,
);

"traverse_sequences" n'a pas de valeur de retour utile ; on s'attend à ce que vous insériez le comportement approprié avec les fonctions de rappel.

"traverse_balanced" est une alternative à "traverse_sequences". Elle utilise un algorithme différent pour parcourir les entrées dans le LCS calculé. Au lieu de rester d'un seul côté et de montrer les changements d'éléments uniquement comme des insertions et des suppressions, elle sautera d'avant en arrière entre les deux séquences et signalera les changements survenant comme des suppressions d'un côté suivies immédiatement par une insertion de l'autre.

En plus des "DISCARD_A", "DISCARD_B", et "MATCH" rappels (callbacks) pris en charge par "traverse_sequences", "traverse_balanced" prend en charge un rappel "CHANGE" indiquant qu'un élément a été "remplacé" par un autre :

traverse_balanced(
    \@seq1, \@seq2,
    {   MATCH => $callback_1,
        DISCARD_A => $callback_2,
        DISCARD_B => $callback_3,
        CHANGE    => $callback_4,
    }
);

Si aucun rappel "CHANGE" n'est spécifié, "traverse_balanced" fera correspondre les événements "CHANGE" aux actions "DISCARD_A" et "DISCARD_B" , résultant donc en un comportement similaire à celui de "traverse_sequences" avec un ordre d'événements différent.

"traverse_balanced" peut être un peu plus lent que "traverse_sequences", perceptible uniquement lors du traitement de quantités massives de données.

La fonction "sdiff" de ce module est implémentée comme un appel à "traverse_balanced".

"traverse_balanced" n'a pas de valeur de retour utile ; vous êtes censé fournir le comportement approprié avec les fonctions de rappel.

FONCTIONS DE GÉNÉRATION DE CLÉS

La plupart des fonctions acceptent un paramètre supplémentaire facultatif. C'est une référence CODE à une fonction de génération de clés (hachage) qui doit retourner une chaîne identifiant de manière unique un élément donné. Il doit être le cas que si deux éléments doivent être considérés comme égaux, leurs clés doivent être les mêmes (et vice versa). Si aucune fonction de génération de clés n'est fournie, la clé sera l'élément sous forme de chaîne.

Par défaut, les comparaisons utiliseront "eq" et les éléments seront convertis en clés en utilisant l'opérateur de conversion en chaîne par défaut '""'.

Cela est important lorsque vous comparez autre chose que des chaînes. S'il arrive que vous ayez plusieurs objets différents qui doivent être considérés comme égaux, vous devez fournir une fonction de génération de clés. Sinon, vous devez vous assurer que vos tableaux contiennent des références uniques.

Par exemple, considérez cet exemple :

package Person;
sub new
{
    my $package = shift;
    return bless { name => '', ssn => '', @_ }, $package;
}
sub clone
{
    my $old = shift;
    my $new = bless { %$old }, ref($old);
}
sub hash
{
    return shift()->{'ssn'};
}
my $person1 = Person->new( name => 'Joe', ssn => '123-45-6789' );
my $person2 = Person->new( name => 'Mary', ssn => '123-47-0000' );
my $person3 = Person->new( name => 'Pete', ssn => '999-45-2222' );
my $person4 = Person->new( name => 'Peggy', ssn => '123-45-9999' );
my $person5 = Person->new( name => 'Frank', ssn => '000-45-9999' );

Si vous faisiez ceci :

my $array1 = [ $person1, $person2, $person4 ];
my $array2 = [ $person1, $person3, $person4, $person5 ];
Algorithm::Diff::diff( $array1, $array2 );

tout fonctionnerait correctement (chaque objet serait converti en une chaîne comme "Person=HASH(0x82425b0)" pour la comparaison).

Mais si vous faisiez ceci :

my $array1 = [ $person1, $person2, $person4 ];
my $array2 = [ $person1, $person3, $person4->clone(), $person5 ];
Algorithm::Diff::diff( $array1, $array2 );

$person4 et $person4->clone() (qui ont le même nom et le même numéro de sécurité sociale) seraient vus comme des objets différents. Si vous vouliez qu'ils soient considérés comme équivalents, vous devriez passer une fonction de génération de clés :

my $array1 = [ $person1, $person2, $person4 ];
my $array2 = [ $person1, $person3, $person4->clone(), $person5 ];
Algorithm::Diff::diff( $array1, $array2, \&Person::hash );

Cela utiliserait le champ 'ssn' de chaque Person comme clé de comparaison, et considérerait donc $person4 et $person4->clone() comme égaux.

Vous pouvez également passer des paramètres supplémentaires à la fonction de génération de clés si vous le souhaitez.
