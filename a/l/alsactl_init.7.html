NOM

alsactl_init - gestion des commandes alsa - initialisation

DESCRIPTION

« alsactl init » fournit une initialisation spécifique à la carte son.

CONFIGURATION

Tous les fichiers de configuration de « alsactl init » sont placés dans le répertoire /usr/share/alsa/init/. Le fichier de configuration de premier niveau est /usr/share/alsa/init/00main. Le fichier de premier niveau par défaut peut également être spécifié à l'aide du paramètre -i ou --initfile de l'outil alsactl. Chaque fichier se compose d'un ensemble de lignes de texte. Toutes les lignes vides ou commençant par '#' seront ignorées.

Fichiers de règles

Les règles de « alsactl init » sont lues depuis les fichiers situés dans /usr/share/alsa/init/*. Le fichier de configuration de premier niveau est /usr/share/alsa/init/00main. Chaque ligne du fichier de règles contient au moins une paire clé-valeur. Il existe deux types de clés : les clés de correspondance (match) et les clés d'affectation (assignment). Si toutes les clés de correspondance correspondent à leur valeur, la règle est appliquée et les clés d'affectation se voient attribuer la valeur spécifiée.

Une règle peut se composer d'une liste d'une ou plusieurs paires clé-valeur séparées par une virgule. Chaque clé a une opération distincte, selon l'opérateur utilisé. Les opérateurs valides sont :

==

Comparer pour l'égalité.

!=

Comparer pour l'inégalité.

=

Affecter une valeur à une clé. Les clés représentant une liste sont réinitialisées et seule cette valeur unique est affectée.

+=

Ajouter la valeur à une clé contenant une liste d'entrées.

:=

Affecter définitivement une valeur à une clé ; interdire toute modification ultérieure, ce qui peut être utilisé pour empêcher les modifications par des règles ultérieures.

Les noms de clés suivants peuvent être utilisés pour correspondre aux propriétés du périphérique :

CARDINDEX

Correspond à l'index de la carte du pilote ALSA.

CTL{attribut}

Définir ou tester un attribut de commande universel. Attributs possibles :

numid

Identification numérique de la commande.

iface, interface

Nom de l'interface de commande (CARD, HWEDEP, MIXER, PCM, RAWMIDI, TIMER, SEQUENCER)

subdev, subdevice

Numéro de sous-périphérique.

name

Nom de la commande

index

Index de la commande

type

Type de commande (BOOLEAN, INTEGER, INTEGER64, ENUMERATED, BYTES, IEC958)

attr, attribute

Attributs (stockés dans une chaîne - utiliser les caractères de correspondance * et ?) :

r

la commande est lisible

w

la commande est inscriptible

v

la commande est volatile

i

la commande est inactive

l

la commande est verrouillée

R

la commande est TLV lisible

W

la commande est TLV inscriptible

C

la commande est TLV commandable

o

le processus est le propriétaire de cette commande

u

commande créée dans l'espace utilisateur

owner

Numéro de PID du processus propriétaire de la commande

count

Nombre de valeurs de la commande

min

Plage de valeurs - valeur minimale

max

Plage de valeurs - valeur maximale

step

Plage de valeurs - valeur de pas

dBmin

Plage de valeurs - valeur dB minimale

dBmax

Plage de valeurs - valeur dB maximale

items

Valeur énumérée - nombre d'éléments de texte

enums

Valeur énumérée - liste de noms de texte stockés entre les caractères '|'

value

Valeur de la commande stockée dans une chaîne délimitée par une virgule (,).

do_search

Rechercher une commande. La valeur "1" est retournée si une commande a été trouvée. La clé CTL{name} peut contenir les caractères de correspondance * et ?. Un index de commande peut être spécifié comme premier argument à partir de zéro (par ex. CTL{do_search 2}="1").

do_count

Rechercher des commandes et retourner le nombre total de correspondances. La clé CTL{name} peut contenir les caractères de correspondance * et ?.

CONFIG{sysfs_device}

Le chemin relatif vers le sous-système sysfs spécifiant le répertoire racine d'un périphérique de carte son. En général, il devrait être défini sur "/class/sound/card$cardinfo{card}/device".

ATTR{nom_de_fichier}

Correspondre aux valeurs d'attribut sysfs du périphérique de carte son. Le chemin relatif vers l'arborescence sysfs doit être défini par la clé CONFIG{sysfs_device}. Les espaces de fin dans les valeurs d'attribut sont ignorés, si la valeur de correspondance spécifiée ne contient pas elle-même d'espace de fin. Selon le type d'opérateur, cette clé est également utilisée pour définir la valeur d'un attribut sysfs.

ENV{clé}

Correspondre à la valeur d'une variable d'environnement. Jusqu'à cinq ENV clés peuvent être spécifiées par règle. Selon le type d'opérateur, cette clé est également utilisée pour exporter une variable vers l'environnement.

PROGRAM

Exécuter un programme externe. La clé est vraie si le programme se termine avec un code de sortie zéro. Tout l'environnement de l'événement est disponible pour le programme exécuté. La sortie du programme imprimée sur stdout est disponible pour la clé RESULT.

Plusieurs commandes intégrées sont disponibles :

__ctl_search

Rechercher une commande. La clé CTL{name} peut contenir les caractères de correspondance * et ?. Un index de commande peut être spécifié comme premier argument à partir de zéro (par ex. PROGRAM="__ctl_search 2").

__ctl_count

Rechercher des commandes et retourner le nombre total de correspondances. La clé CTL{name} peut contenir les caractères de correspondance * et ?.

RESULT

Correspondre à la chaîne retournée par le dernier appel à PROGRAM. Cette clé peut être utilisée dans la même règle ou dans toute règle ultérieure après un appel à PROGRAM.

La plupart des champs prennent en charge la correspondance de motifs de style shell. Les caractères de motif suivants sont pris en charge :

*

Correspond à zéro, ou à un nombre quelconque de caractères.

?

Correspond à n'importe quel caractère unique.

[]

Correspond à n'importe quel caractère unique spécifié entre crochets. Par exemple, la chaîne de motif 'tty[SR]' correspondrait à 'ttyS' ou 'ttyR'. Les plages sont également prises en charge dans cette correspondance avec le caractère '-'. Par exemple, pour correspondre à la plage de tous les chiffres, le motif [0-9] serait utilisé. Si le premier caractère suivant '[' est un '!', tous les caractères non inclus sont correspondus.

Les clés suivantes peuvent recevoir des valeurs affectées :

CTL{numid}, CTL{iface}, CTL{device}, CTL{subdev}, CTL{name}, CTL{index},

Sélectionner un élément de commande universel.

CTL{value}

La valeur est définie (écrite) également sur le périphérique de commande de la carte son et la clé RESULT est définie sur le code errno. Le résultat de l'opération de définition est toujours vrai (ce qui signifie continuer avec la clé suivante sur la ligne).

CTL{values}

La valeur est définie (écrite) également sur le périphérique de commande de la carte son (toutes les valeurs de commande sont définies à la valeur spécifiée) et la clé RESULT est définie sur le code errno. Le résultat de l'opération de définition est toujours vrai (ce qui signifie continuer avec la clé suivante sur la ligne).

CTL{write}

La valeur est définie (écrite) également sur le périphérique de commande de la carte son (toutes les valeurs de commande sont définies à la valeur spécifiée). Le résultat de l'opération de définition est vrai lorsque l'opération réussit (ce qui signifie continuer avec la clé suivante sur la ligne).

ENV{clé}

Exporter une variable vers l'environnement. Selon le type d'opérateur, cette clé est également utilisée pour correspondre à une variable d'environnement.

RESULT

Définir la variable RESULT. Notez que PROGRAM définit également cette variable. alsactl_init(7) — alsactl

NAME

alsactl_init — Init script configuration for alsactl

DESCRIPTION

The alsactl_init script is used to initialize the Sound Card state when the system boots up. The script reads a configuration file that contains a list of commands to be executed. These commands are used to set various parameters of the sound card.

The configuration file has a simple syntax:

  • Lines starting with a '#' character are comments.
  • Empty lines are ignored.
  • Other lines are processed as commands.

The following commands are supported:

PROGRAM
Execute external program and assign its output to variable. If the program returns non-zero exit code, the script stops processing. The program output is assigned to the variable $result.
CTL
Control sound card state. The syntax is CTL{attribute=value}. The value can be substituted using variables like $cardinfo or $result.
CARDINFO
Get information about sound card. The syntax is CARDINFO{attribute}. The following attributes are supported:
card
Index of the sound card.
id
Sound card ID string.
name
Sound card name string.
driver
Sound card driver name.
device
Sound card device name.
longname
Sound card long name string.
driver_version
Sound card driver version.
date
Sound card driver date.
config
Configuration string.
mixer
Mixer name.
The information is stored in the variable $cardinfo{attribute}. This variable can be later used for substitutions.
CONFIG
Set or get configuration variables. The syntax is CONFIG{key} or CONFIG{key=value}. If no value is specified, the current value of the variable is returned. The value can be substituted using variables like $cardinfo or $result.
LABEL
Named label where a GOTO can jump to.
GOTO
Jumps to the next LABEL with a matching name. The goto cannot jump backward.
INCLUDE
Include the specified filename or files in specified directory.

When a directory is specified, only the files with the extension ".conf" are read. Also they are read in the alphabetical order. Thus it's highly recommended to use some number prefix (e.g. "01-something.conf") to assure the order of execucions.

ACCESS
Check if specified file or directory exists
CONFIG{sysfs_device}
The relative path to sysfs subsystem specifying the root directory of a soundcard device. Usually, it should be set to "/class/sound/card$cardinfo{card}/device".
PRINT
PRINT value to stdout.
ERROR
PRINT value to stderr.
EXIT
Exit immediately and set program exit code to value (should be integer). If value is "return" string, parser leaves current included file and returns to parent configuration file.

The PROGRAM, RESULT, CTL{value}, PRINT, ERROR, EXIT, CONFIG{} fields support simple printf-like string substitutions. It allows the use of the complete environment set by earlier matching rules. For all other fields, substitutions are applied while the individual rule is being processed. The available substitutions are:

$cardinfo{attribute}, %i{attribute}

See CARDINFO{} for more details.

$ctl{attribute}, %C{attribute}

See CTL{} for more details.

$attr{file}, %s{file}

The value of a sysfs attribute found at the device, where all keys of the rule have matched. If the attribute is a symlink, the last element of the symlink target is returned as the value.

$env{key}, %E{key}

The value of an environment variable.

$result, %c

The string returned by the external program requested with PROGRAM. A single part of the string, separated by a space character may be selected by specifying the part number as an attribute: %c{N}. If the number is followed by the '+' char this part plus all remaining parts of the result string are substituted: %c{N+}

$sysfsroot, %r

Root directory where sysfs file-system is mounted. Ususally, this value is just "/sys".

$config{key}, %g{key}

The value of a configuration variable. See CONFIG{} for more details.

%%

The '%' character itself.

$$

The '$' character itself.

The count of characters to be substituted may be limited by specifying the format length value. For example, '%3s{file}' will only insert the first three characters of the sysfs attribute
