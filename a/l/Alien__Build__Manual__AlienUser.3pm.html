DESCRIPTIO

N

Ce document est destiné à l'utilisateur d'un module Alien basé sur Alien::Base. Bien qu'il soit spécifiquement conçu pour les sous-classes d'Alien::Base, il peut contenir des indications utiles pour Alien en

général.

Des exemples complets et fonctionnels d'utilisation d'un module Alien sont également fournis avec Alien::Build dans le répertoire "example/user" de la distribution. Ces exemples utilisent Alien::xz, qui utilise alienfile + Alien::Build + Alien::

Base.

La documentation suivante suppose que vous essayez d'utiliser un Alien appelé "Alien::Foo" qui fournit la bibliothèque "libfoo" et l'outil en ligne de commande "foo". Beaucoup d'Aliens ne fournissent que l'un ou

l'autre.

La meilleure interface pour utiliser les Aliens basés sur Alien::Base est Alien::Base::Wrapper. Cela vous permet de combiner plusieurs Aliens ensemble et gère un certain nombre de cas particuliers obscurs que l'utilisation directe des Aliens ne gère pas. De plus, depuis la version 0.64, Alien::Base::Wrapper est fourni avec Alien::Build et Alien::Base, il ne s'agit donc pas d'une dépendance

supplémentaire.

Voici les principaux cas

d'utilisation.

ExtUtils::

MakeMaker 
use ExtUtils::MakeMaker;
use Alien::Base::Wrapper ();

WriteMakefile(
  Alien::Base::Wrapper->new('Alien::Foo')->mm_args2(
    NAME => 'FOO::XS',
    ...
  ),
)
;

Alien::Base::Wrapper prendra un hash d'arguments "WriteMakefile" et insérera les drapeaux de compilation et de liaison appropriés pour vous. Cela est recommandé plutôt que de le faire vous-même, car l'incantation exacte pour faire fonctionner EUMM est difficile à obtenir

correctement.

La méthode "mm_args2" définira également votre "CONFIGURE_REQUIRES" pour Alien::Base::Wrapper, ExtU

tils::MakeMaker et tous les
Aliens que vous spécifiez.

Module::

Build 
use Module::Build;
use Alien::Base::Wrapper qw( Alien::Foo !export );
use Alien::Foo;

my $build = Module::Build->new(
  ...
  configure_requires => {
    'Alien::Base::Wrapper' => '0',
    'Alien::Foo'           => '0',
    ...
  },
  Alien::Base::Wrapper->mb_args,
  ...
);

$build->create_build_script
;

Pour Module::Build, vous pouvez également utiliser Alien::Base::Wrapper, mais vous devrez spécifier "configure_requi

res" vo
us-même.

FFI::

Platypus

Requiert "Alien::Foo" toujours

: 
use FFI::Platypus;
use Alien::Foo;

my $ffi = FFI::Platypus->new(
  lib => [ Alien::Foo->dynamic_libs ],
)
;

Utilise "Alien::Foo" en mode de repli

: 
use FFI::Platypus;
use FFI::CheckLib 0.28 qw( find_lib_or_die );
use Alien::Foo;

my $ffi = FFI::Platypus->new(
  lib => [ find_lib_or_die lib => 'foo', alien => ['Alien::Foo'] ],
)
;

Si vous allez toujours exiger un Alien, vous pouvez simplement appeler "dynamic_libs" et le passer à la méthode lib de FFI::Platypus. Vous devriez envisager d'utiliser FFI::CheckLib pour utiliser l'Alien en mode de repli à la place. De cette façon, vous n'avez besoin d'installer l'Alien que si le système ne le fournit

pas.

Pour que le mode de repli fonctionne cor

rectement, vous devez utiliser FFI::
CheckLib 0.28 ou une version supérieure.

ENVIRONNEMEN

T
ALIEN_INSTALL_T
YPE
Bien que la manière recommandée pour un consommateur d'utiliser un Alien basé sur Alien::Base soit de le déclarer comme une dépendance statique de configuration et de compilation, certains consommateurs peuvent préférer n'utiliser un Alien qu'en mode de repli lorsque le consommateur lui-même ne peut pas détecter le paquet nécessaire. Dans certains cas, le consommateur peut vouloir que l'utilisateur choisisse explicitement d'utiliser un Alien avant de l'exiger.

Pour garder l'interface cohérente entre les Aliens, le consommateur de l'Alien de repli par opt-in peut utiliser l'Alien en mode de repli si la variable d'environnement "ALIEN_INSTALL_TYPE" est définie à n'importe quelle valeur. La raison est qu'en définissant cette variable d'environnement, l'utilisateur est conscient que des modules Alien peuvent être installés et a indiqué son consentement. L'implémentation réelle de cela, par sa nature, devrait être dans le module CPAN

consommateur.

Ce comportement devrait être documenté dans le POD du

consommateur.

Voir "ENVIRONMENT" dans

Alien::Build pour plus
de détails sur l
'utilisation de cette v
ariable d'environnement.
