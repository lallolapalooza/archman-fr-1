ALTER VIEW(7) Documentation PostgreSQL 18.1 ALTER VIEW(7)

NOM

ALTER_VIEW - modifier la définition d'une vue

SYNTAXE

ALTER VIEW [ IF EXISTS ] nom ALTER [ COLUMN ] nom_colonne SET DEFAULT expression
ALTER VIEW [ IF EXISTS ] nom ALTER [ COLUMN ] nom_colonne DROP DEFAULT
ALTER VIEW [ IF EXISTS ] nom OWNER TO { nouvel_proprietaire | CURRENT_ROLE | CURRENT_USER | SESSION_USER }
ALTER VIEW [ IF EXISTS ] nom RENAME [ COLUMN ] nom_colonne TO nouveau_nom_colonne
ALTER VIEW [ IF EXISTS ] nom RENAME TO nouveau_nom
ALTER VIEW [ IF EXISTS ] nom SET SCHEMA nouveau_schema
ALTER VIEW [ IF EXISTS ] nom SET ( nom_option_vue [= valeur_option_vue] [, ... ] )
ALTER VIEW [ IF EXISTS ] nom RESET ( nom_option_vue [, ... ] )

DESCRIPTION

ALTER VIEW modifie diverses propriétés auxiliaires d'une vue. (Si vous souhaitez modifier la requête définissant la vue, utilisez CREATE OR REPLACE VIEW.)

Vous devez être propriétaire de la vue pour utiliser ALTER VIEW. Pour changer le schéma d'une vue, vous devez également avoir le privilège CREATE sur le nouveau schéma. Pour modifier le propriétaire, vous devez pouvoir exécuter SET ROLE sur le nouveau rôle propriétaire, et ce rôle doit avoir le privilège CREATE sur le schéma de la vue. (Ces restrictions garantissent que la modification du propriétaire ne fait rien que vous ne puissiez faire en supprimant et recréant la vue. Cependant, un superutilisateur peut modifier le propriétaire de n'importe quelle vue.)

PARAMÈTRES

nom

Le nom (éventuellement qualifié par un schéma) d'une vue existante.

nom_colonne

Nom d'une colonne existante.

nouveau_nom_colonne

Nouveau nom pour une colonne existante.

IF EXISTS

Ne pas générer d'erreur si la vue n'existe pas. Une notification est émise dans ce cas.

SET/DROP DEFAULT

Ces formes définissent ou suppriment la valeur par défaut d'une colonne. La valeur par défaut d'une colonne de vue est substituée dans toute commande INSERT ou UPDATE dont la cible est la vue, avant l'application de règles ou de déclencheurs pour la vue. La valeur par défaut de la vue prévaudra donc sur les valeurs par défaut des relations sous-jacentes.

nouvel_proprietaire

Le nom de l'utilisateur du nouveau propriétaire de la vue.

nouveau_nom

Le nouveau nom de la vue.

nouveau_schema

Le nouveau schéma pour la vue.

SET ( nom_option_vue [= valeur_option_vue] [, ... ] )
RESET ( nom_option_vue [, ... ] )

Définit ou réinitialise une option de vue. Les options actuellement supportées sont :

check_option (enum)

Modifie l'option de vérification de la vue. La valeur doit être local ou cascaded.

security_barrier (boolean)

Modifie la propriété security-barrier de la vue. La valeur doit être une valeur booléenne, comme true ou false.

security_invoker (boolean)

Modifie la propriété security-invoker de la vue. La valeur doit être une valeur booléenne, comme true ou false.

NOTES

Pour des raisons historiques, ALTER TABLE peut également être utilisé avec des vues ; mais les seules variantes de ALTER TABLE autorisées avec des vues sont équivalentes à celles présentées ci-dessus.

EXEMPLES

Pour renommer la vue foo en bar :

ALTER VIEW foo RENAME TO bar;

Pour attacher une valeur de colonne par défaut à une vue modifiable :

CREATE TABLE base_table (id int, ts timestamptz);
CREATE VIEW a_view AS SELECT * FROM base_table;
ALTER VIEW a_view ALTER COLUMN ts SET DEFAULT now();
INSERT INTO base_table(id) VALUES(1);  -- ts recevra une valeur NULL
INSERT INTO a_view(id) VALUES(2);  -- ts recevra l'heure actuelle

COMPATIBILITÉ

ALTER VIEW est une extension PostgreSQL de la norme SQL.

VOIR AUSSI

CREATE VIEW (CREATE_VIEW(7)), DROP VIEW (DROP_VIEW(7))
