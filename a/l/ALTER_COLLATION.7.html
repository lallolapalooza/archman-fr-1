ALTER_COLLATION(7)

Paquet: postgresql

Licences: PostgreSQL

ALTER COLLATION(7) Documentation PostgreSQL 18.1 ALTER COLLATION(7)

NOM

ALTER_COLLATION - modifier la définition d'une collation

SYNOPSIS

ALTER COLLATION name REFRESH VERSION
ALTER COLLATION name RENAME TO new_name
ALTER COLLATION name OWNER TO { new_owner | CURRENT_ROLE | CURRENT_USER | SESSION_USER }
ALTER COLLATION name SET SCHEMA new_schema

DESCRIPTION

ALTER COLLATION modifie la définition d'une collation.

Vous devez posséder la collation pour utiliser ALTER COLLATION. Pour modifier le propriétaire, vous devez pouvoir définir le rôle sur le nouveau rôle propriétaire, et ce rôle doit avoir le privilège CREATE sur le schéma de la collation. (Ces restrictions garantissent que la modification du propriétaire n'entraîne rien que vous ne pourriez faire en supprimant et recréant la collation. Cependant, un superutilisateur peut modifier la propriété de n'importe quelle collation.)

PARAMETRES

name

Le nom (éventuellement qualifié par un schéma) d'une collation existante.

new_name

Le nouveau nom de la collation.

new_owner

Le nouveau propriétaire de la collation.

new_schema

Le nouveau schéma pour la collation.

REFRESH VERSION

Mettre à jour la version de la collation. Voir Notes ci-dessous.

NOTES

Lorsqu'un objet collation est créé, la version spécifique du fournisseur de la collation est enregistrée dans le catalogue système. Lorsque la collation est utilisée, la version actuelle est comparée à la version enregistrée, et un avertissement est émis en cas de discordance, par exemple :

AVERTISSEMENT : la collation « xx-x-icu » a une version incohérente
DÉTAIL : La collation dans la base de données a été créée en utilisant la version 1.2.3.4, mais le système d'exploitation fournit la version 2.3.4.5.
INDICE : Reconstruisez tous les objets affectés par cette collation et exécutez ALTER COLLATION pg_catalog.« xx-x-icu » REFRESH VERSION, ou compilez PostgreSQL avec la bonne version de la bibliothèque.

Une modification des définitions de collation peut entraîner la corruption d'index et d'autres problèmes, car le système de base de données s'appuie sur le fait que les objets stockés ont un ordre de tri spécifique. En général, cela doit être évité, mais cela peut se produire dans des circonstances légitimes, telles que la mise à niveau du système d'exploitation vers une nouvelle version majeure ou lors de l'utilisation de pg_upgrade pour passer à des binaires serveur liés à une version plus récente d'ICU. Lorsque cela se produit, tous les objets dépendant de la collation doivent être reconstruits, par exemple, en utilisant REINDEX. Une fois cela fait, la version de la collation peut être rafraîchie à l'aide de la commande ALTER COLLATION ... REFRESH VERSION. Cela mettra à jour le catalogue système pour enregistrer la version actuelle de la collation et fera disparaître l'avertissement. Notez que cela ne vérifie pas si tous les objets affectés ont été correctement reconstruits.

Lors de l'utilisation de collations fournies par libc, les informations de version sont enregistrées sur les systèmes utilisant la bibliothèque GNU C (la plupart des systèmes Linux), FreeBSD et Windows. Lors de l'utilisation de collations fournies par ICU, les informations de version sont fournies par la bibliothèque ICU et sont disponibles sur toutes les plateformes.


Note

Lors de l'utilisation de la bibliothèque GNU C pour les collations, la version de la bibliothèque C est utilisée comme proxy pour la version de la collation. De nombreuses distributions Linux modifient les définitions de collation uniquement lors de la mise à niveau de la bibliothèque C, mais cette approche est imparfaite car les mainteneurs sont libres de porter rétroactivement des définitions de collation plus récentes vers des versions antérieures de la bibliothèque C.

Lors de l'utilisation de Windows pour les collations, les informations de version ne sont disponibles que pour les collations définies avec des balises de langue BCP 47 telles que en-US.

Pour la collation par défaut de la base de données, il existe une commande analogue ALTER DATABASE ... REFRESH COLLATION VERSION.

La requête suivante peut être utilisée pour identifier toutes les collations de la base de données actuelle qui doivent être rafraîchies et les objets qui en dépendent :

SELECT pg_describe_object(refclassid, refobjid, refobjsubid) AS "Collation",
       pg_describe_object(classid, objid, objsubid) AS "Objet"
  FROM pg_depend d JOIN pg_collation c
       ON refclassid = 'pg_collation'::regclass AND refobjid = c.oid
  WHERE c.collversion <> pg_collation_actual_version(c.oid)
  ORDER BY 1, 2;

EXEMPLES

Pour renommer la collation de_DE en german :

ALTER COLLATION "de_DE" RENAME TO german;

Pour changer le propriétaire de la collation en_US en joe :

ALTER COLLATION "en_US" OWNER TO joe;

COMPATIBILITÉ

Il n'existe pas d'instruction ALTER COLLATION dans la norme SQL.

VOIR AUSSI

CREATE COLLATION (CREATE_COLLATION(7)), DROPCOLLATION (DROP_COLLATION(7))
