DESCRIPTIO

N

libalpm permet de spécifier des crochets à exécuter avant ou après les transactions en fonction des paquets et/ou des fichiers modifiés. Les crochets se composent d'une seule section [Action] décrivant l'action à exécuter et d'une ou plusieurs sections [Trigger] décrivant les transactions pour lesquelles elles doivent être

exécutées.

Les crochets sont lus à partir de fichiers situés dans le répertoire des crochets du système /usr/share/libalpm/hooks, et des répertoires personnalisés supplémentaires spécifiés dans pacman.conf(5) (par défaut /etc/pacman.d/hooks). Les noms de fichiers doivent avoir le suffixe « .hook ». Le

s crochets sont exécutés dans l'ordre alphabétique d
e leur nom de fichier, où l'ordre ignore le suffixe.

DÉCLENCHEUR

S

Les crochets doivent contenir au moins une section [Trigger] qui détermine quelles transactions provoqueront l'exécution du crochet. Si plusieurs sections de déclencheur sont définies, le crochet s'exécutera si la transaction correspond à l'un des

déclencheurs.

Operation = Install|Upgrade|Remov

e
Sélectionne le type d'opération pour faire correspondre les cibles. Peut être spécifié plusieurs fois. Les installations sont considérées comme une mise à jour si le paquet ou le fichier est déjà présent sur le système, que la nouvelle version du paquet soit réellement supérieure ou non à la version actuellement installée. Pour les déclencheurs de type Path, c'est le cas même si le fichier change de propriétaire d'un paquet à un autre.
Requis.

Type =

Path|Package
Sélectionne si les cibles sont comparées aux paquets ou aux fichiers de la transaction. Voir AVERTISSEMENTS pour des notes spéciales concernant les déclencheurs Path. File est un alias obsolète pour Path et sera supprimé dans une version future.
Requis.

Target =

<path|package>
Le chemin ou le nom du paquet à comparer à la transaction active. Les chemins font référence aux fichiers dans l'archive du paquet ; la racine d'installation ne doit pas être incluse dans le chemin. Les motifs glob de type shell sont autorisés. Il est possible d'inverser les
correspondances en préfixant une cible avec un point d
'exclamation. Peut être spécifié plusieurs fois. Requis.

S

.

utilisateur.

Exec =

<command>
Commande à exécuter. Les arguments de la commande sont séparés par des espaces. Les valeurs contenant des espaces doivent être entourées de guillemets.
Requis.

When = PreTransaction|PostTransactio

n
Quand exécuter le crochet.
Requis.

Depends =

<package>
Paquets qui doivent être installés pour que le crochet s'exécute. Peut être spécifié plusieurs
fois.

l
Provoque l'abandon de la transaction si le crochet se termine avec un code non nul. Ne s'applique qu'aux crochets
PreTransaction.

s

AVERTISSEMEN

TS

Il existe des situations où les déclencheurs de chemin peuvent se comporter de manière inattendue. Les crochets sont déclenchés à l'aide de la liste de fichiers du paquet installé, mis à jour ou supprimé. Lors de l'installation ou de la mise à jour d'un fichier extrait avec une extension .pacnew, le nom de fichier original est utilisé pour déclencher le crochet. Lors de la suppression d'un paquet, tous les fichiers appartenant à ce paquet peuvent déclencher un crochet, qu'ils soient réellement présents sur le système de fichiers avant la suppression du paquet ou

non.

Les crochets PostTransaction ne s'exécuteront pas si la transaction échoue à se terminer pour quelque raison que ce

soit.

Voir le site web de pacman à l'adresse https://archlinux.org/pacman/ pour des informa

tions actuelles sur pacma
n et ses outils associés.
