DESCRIPTIO

N

Ce module fournit des outils pour construire des dépendances externes (non-CPAN) pour CPAN. Il est principalement conçu pour être utilisé au moment de l'installation d'un client CPAN, et fonctionne en étroite collaboration avec Alien::Base qui est utilisé à

l'exécution.

Ceci est la documentation détaillée pour la classe Alien::Build. Si vous débutez, vous voudrez probablement commencer par l'un de ces documents

:

Alien

écosystème.

Pour les utilisateurs d'un "Alien::libfoo" qui est implémenté en utilisant Alien::Base. (Le développeur de "Alien::libfoo" devrait fournir la documentation nécessaire, mais si ce n'est pas le cas, c'est ici qu'il faut commencer)
.

construction".

Ceci est pour les âmes courageuses qui veulent écrire des plugins qui fonctionneront avec Alien::Build +
alienfile.

Security
Si vous êtes préoccupé par le fait que les Aliens pourraient télécharger des tarballs depuis internet
, alors c'est ici qu'il faut aller. Cela discutera de certains des risques liés au téléchargement (vr
aiment n'importe quel) logiciel depuis internet et vous donnera des outils pour atténuer ces risques.

Notez que vous ne créerez généralement pas directement une instance Alien::Build, mais utiliserez plutôt une fine

couche d'installation, comme Alien::Build::MM (pour utilisation avec ExtUtils::MakeMaker) ou Alien::Build::MB (pour
utilisation avec Module::Build). L'un des objectifs de ce projet est de rester indépendant de l'installateur.

PROPRIÉTÉ

S

Il y a trois propriétés principales pour Alien::Build. Il y a un certain nombre de propriétés documentées ici avec une utilisation spécifique. Notez que ces propriétés peuvent avoir besoin d'être sérialisées en quelque chose de primitif comme JSON qui ne supporte pas : les expressions rationnelles, les références de code d'objets

bénis.

Si vous écrivez un plugin (Alien::Build::Plugin), vous devriez utiliser un préfixe comme "plugin_name" (où name est le nom de votre plugin) afin qu'il n'interfère pas avec d'autres plugins ou de futures versions d'Alien::Build. Par exemple, si vous écriviez "Alien::Build::Plugin::Fetch::NewProtocol", veuillez utiliser le préfixe "plugin_fetch_newpr

otocol" : 
sub init
{
  my($self, $meta) = @_;

  $meta->prop( plugin_fetch_newprotocol_foo => 'some value' );

  $meta->register_hook(
    some_hook => sub {
      my($build) = @_;
      $build->install_prop->{plugin_fetch_newprotocol_bar} = 'some other value';
      $build->runtime_prop->{plugin_fetch_newprotocol_baz} = 'and another value';
    }
  );
}

Si vous écrivez une recette alienfile, veuillez utiliser le préfixe "my_"

: 
use alienfile;

meta_prop->{my_foo} = 'some value';

probe sub {
  my($build) = @_;
  $build->install_prop->{my_bar} = 'some other value';
  $build->install_prop->{my_baz} = 'and another value';
}
;

Toute propriété peut être utilisée depuis une commande

: 
probe [ 'some command %{.meta.plugin_fetch_newprotocol_foo}' ];
probe [ 'some command %{.install.plugin_fetch_newprotocol_bar}' ];
probe [ 'some command %{.runtime.plugin_fetch_newprotocol_baz}' ];
probe [ 'some command %{.meta.my_foo}' ];
probe [ 'some command %{.install.my_bar}' ];
probe [ 'some command %{.runtime.my_baz}' ]
;
