al_get_standard_path(3) Manuel des fonctions de bibliothèque al_get_standard_path(3)

NOM

al_get_standard_path - API Allegro 5

SYNTAXE

#include <allegro5/allegro.h>
ALLEGRO_PATH *al_get_standard_path(int id)

DESCRIPTION

Récupère un chemin système, en fonction du paramètre id. Certains de ces chemins peuvent être affectés par le nom de l'organisation et de l'application, assurez-vous donc de les définir avant d'appeler cette fonction.

Les chemins ne sont pas garantis d'être uniques (par exemple, SETTINGS et DATA peuvent être identiques sur certaines plateformes), vous devez donc vous assurer que vos noms de fichiers sont uniques si vous souhaitez éviter les collisions de noms. De plus, un chemin retourné peut ne pas exister réellement sur le système de fichiers.

ALLEGRO_RESOURCES_PATH
Si vous incluez des données dans un emplacement relatif à votre exécutable, vous devez utiliser ce chemin pour localiser ces données. Sur la plupart des plateformes, il s'agit du répertoire contenant le fichier exécutable.

Si appelé depuis un bundle d'applications OS X, il pointera vers le répertoire des ressources internes (<bundle.app>/Contents/Resources). Pour maintenir la cohérence, si vous placez vos ressources dans un répertoire appelé « data » sous l'exécutable sur une autre plateforme (comme Windows), vous devez également créer un répertoire appelé « data » sous le dossier des ressources du bundle d'applications OS X.

Vous ne devez pas essayer d'écrire dans ce chemin, car il est très probablement en lecture seule.

Si vous installez vos ressources dans un autre répertoire système (par exemple, dans /usr/share ou C:\ProgramData), vous êtes responsable de votre propre suivi.

ALLEGRO_TEMP_PATH
Chemin vers le répertoire des fichiers temporaires.
ALLEGRO_USER_HOME_PATH
Ceci est le répertoire personnel de l'utilisateur. Vous ne devriez normalement pas écrire de fichiers directement dans ce répertoire, ni y créer de sous-dossiers, sans la permission explicite de l'utilisateur. Une application pratique de ce chemin serait de l'utiliser comme point de départ d'un sélecteur de fichiers dans une interface graphique.
ALLEGRO_USER_DOCUMENTS_PATH
Cet emplacement est facilement accessible par l'utilisateur et est l'endroit où stocker les documents et fichiers que l'utilisateur pourrait vouloir ouvrir ultérieurement avec un programme externe ou transférer ailleurs.

Vous ne devriez pas y enregistrer de fichiers, sauf si l'utilisateur s'y attend, généralement avec sa permission explicite.

ALLEGRO_USER_DATA_PATH
Si votre programme enregistre des données auxquelles l'utilisateur n'a pas besoin d'accéder de l'extérieur, vous devriez les placer ici. C'est généralement l'endroit le moins intrusif pour stocker des données. Ce chemin ne sera généralement pas présent sur le système de fichiers, assurez-vous donc de le créer avant d'y écrire.
ALLEGRO_USER_SETTINGS_PATH
Si vous enregistrez des fichiers de configuration (surtout si l'utilisateur souhaite les modifier en dehors de votre programme), vous devriez les placer ici. Ce chemin ne sera généralement pas présent sur le système de fichiers, assurez-vous donc de le créer avant d'y écrire.
ALLEGRO_EXENAME_PATH
Le chemin complet vers l'exécutable.

Retourne NULL en cas d'échec. Le chemin retourné doit être libéré avec al_destroy_path(3).
