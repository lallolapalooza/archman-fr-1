REMARQUE : Veuillez envisager, pour le développement de nouveaux Aliens, d'utiliser Alien::Build et alienfile à la place. Comme Alien::Base::ModuleBuild, ils fonctionnent avec Alien::Base. Contrairement à Alien::Base::ModuleBuild, ils sont plus facilement personnalisables et gèrent un certain nombre de cas particuliers de manière plus efficace. Pour un bon point de départ, veuillez consulter Alien::Base::ModuleBuild::API. Bien que l'équipe Alien-Base / Alien-Build continue de maintenir ce module, (nous continuerons à corriger les bogues là où c'est approprié), nous n'ajoutons aucune nouvelle fonctionnalité à ce

module.

Ce document sert à répondre aux questions les plus fréquemment posées par les auteurs d'Alien::

Base.

Qu'est-ce qu'Alien et Alien::Base

?

Alien est un espace de noms Perl pour définir des dépendances dans CPAN pour des bibliothèques et des outils qui ne sont pas « natifs » à CPAN. Pour une

description de style manifeste du Pourquoi et du Comment, voir Alien. Alien::Base est une classe de base et un cadre pour créer des distributions Alien.
L'idée est de traiter autant que possible les défis communs au développement de modules Alien dans la classe de base afin de simplifier le processus.

Comment spécifier une version minimale ou exacte requise pour les paquets qui utilisent pkg-config

?

L'attribut "alien_version_check" d'Alien::Base::ModuleBuild sera exécuté pour déterminer si la bibliothèque est fournie par le système d'exploitation. La valeur par défaut est "%{pkg_config} --modversion %n" qui vérifie simplement si une version de ce paquet est disponible et imprime le numéro de version. Vous pouvez utiliser les options "--atleast-version", "--exact-version" pour exiger une plage spécifique de versions, mais ces indicateurs ne fonctionnent pas avec l'indicateur "--modversion", alors assurez-vous de les invoquer

séparément. 
use Alien::Base::ModuleBuild;
Alien::Base::ModuleBuild->new(
  dist_name           => 'Alien::Foo',
  alien_name          => 'foo',
  configure_requires  => { 'Alien::Base::ModuleBuild' => '0.022' }, # requis pour %{pkg_config}
  alien_version_check => '%{pkg_config} --atleast-version 1.2.3 %n && %{pkg_config} --modversion %n',
  ...
)->create_build_script
;

Il est préférable d'utiliser l'assistant intégré "%{pkg_config}" car il utilisera le pkg-config fourni par le système s'il est disponible et utilisera en secours le PkgConfig en Perl pur si ce n'est pas le

cas.

Vous pouvez également utiliser "--exact-version" pour spéci

fier une versi
on exacte.

Comment créer un module Alien pour les paquets qui ne prennent pas en charge pkg-config

?

Bien qu'Alien::Base et Alien::Base::ModuleBuild supposent que les paquets sont livrés avec un fichier "pkg-config" ".pc" pour déterminer les drapeaux du compilateur et de l'éditeur de liens par défaut, vous pouvez implémenter un module Alien pour les paquets qui n'utilisent pas "pkg-config" en suivant ces tâches

:
sous-classer Alien::Base::ModuleBuild et implémenter "alien_check_installed_versi
on"
Créez une sous-classe d'Alien::Base::ModuleBuild et placez-la dans le répertoire "inc" de votre distribution afin qu'elle puisse être utilisée lors de l'installation mais ne sera pas installée. 
# inc/My/ModuleBuild.pm
package My::ModuleBuild;

use parent 'Alien::Base::ModuleBuild';

sub alien_check_installed_version {
  my($class) = @_;

  # déterminez si votre bibliothèque est déjà fournie par le système
  my $version = ...;

  # retournez faux si la bibliothèque n'est PAS fournie par le système
  return unless defined $version;

  # sinon retournez la version détectée
  # (si vous ne pouvez pas déterminer la version, il
  #  est généralement suffisant de retourner une valeur vraie)
  return $version;
}

Il existe de nombreuses méthodes que vous pouvez utiliser pour déterminer si le système fournit votre bibliothèque. Parmi les méthodes Perl, on trouve Devel::CheckLib, ExtUtils::CBuilder, ExtUtils::CChecker, Config::AutoConf, FFI::CheckLib, entre autres. Il est également souvent possible de déterminer si une bibliothèque est installée à l'aide d'un programme avec le suffixe "-config". Par exemple "libxml2" est livré avec xml2-config qui fournit l'existence, les drapeaux du compilateur et de l'éditeur de liens dont il a besoin. D'après mon expérience, cependant, la plupart des paquets qui fournissent un programme avec le suffixe "-config" fournissent également une interface "pkg-config

"

Comment tester mon paquet une fois qu'il est construit (avant qu'il ne soit installé)

?

Il existe de nombreuses façons de tester les modules Alien avant (ou après) qu'ils soient installés, mais au lieu de développer votre propre solution, envisagez d'utiliser Test::Alien qui est léger en dépendances et testera votre module très fidèlement à la façon dont il sera réellement utilisé. C'est-à-dire en construisant une mini-extension XS ou FFI et en l'utilisant. Il a même des tests pour les distributions Alien orientées outils (comme Alien::gmake et Alien::patch). Voici un court exemple, il y en a beaucoup d'autres inclus avec la documentation de Test::Alien

Comment patcher les paquets qui nécessitent des modifications mineures (ou majeures)

?

Une approche consiste à créer un diff unifié pour les patchs que vous souhaitez appliquer et simplement exécuter patch dessus. Alien::patch et le pan class="Li">"%{patch}" peut être utilisé comme ceci :

# 
Build.PL
use Alien::Base::ModuleBuild;

Alien::Base::ModuleBuild->new(
  ...
  alien_bin_requires => {
    'Alien::patch' => 0.06, # nécessaire pour l'assistant %{patch}
  },
  alien_build_commands => [
    '%{patch} -p1 < ../../patch/mypackage.patch',
    ...
  ],
  ...
)->create_build_script;

Alien::Base::ModuleBuild est agressif dans l'utilisation de l'option "--with-pic" parce que lorsqu'elle est prise en charge par autoconf, elle produit du code indépendant de la position (important pour construire de manière fiable les extensions XS), et lorsqu'elle n'est pas prise en charge, autoconf ignore simplement l'option. package My::ModuleBuild;

use strict;
use warnings;
use parent 'Alien::Base::ModuleBuild';
use Capture::Tiny qw( capture );

sub alien_check_installed_version
{
  # voir Alien::Base::ModuleBuild#alien_check_installed_version pour les détails

  my($self) = @_;
  my($stdout, $stderr) = capture { system 'mytool', '--version' };

  # retourne une liste vide si l'outil n'est pas disponible sur le système,
  # ou s'il est inacceptable.
  return if $! || ...;

  # analyse depuis stdout ou stderr
  my $version = ...;
  return $version;
}

sub alien_check_built_version
{
  # voir Alien::Base::ModuleBuild#alien_check_built_version pour les détails

  # retourne une liste vide si la version de l'outil ne peut pas être trouvée, ou si elle
  # est inacceptable. Notez que cela causera un échec, donc "unknown"
  # peut être raisonnable si la version de l'outil ne peut pas être déterminée.
  return if ...;

  # détermine à partir de l'outil lui-même, ou du répertoire courant.
  my $version = ...;
  return $version;
}

Comme
d'habitude,

votre classe "Alien::MyTool" sera simplement une sous-classe de Alien::Base. Si votre outil est installé dans un répertoire "bin", vous avez terminé, l'implémentation par défaut de "bin_dir" devrait fonctionner pour vous. Sinon, vous devrez peut-être fournir une implémentation alternative

package Alien::MyTool;

use strict;
use warnings;
use parent 'Alien::Base';

sub bin_dir
{
  # voir Alien::Base#bin_dir pour les détails
  # Vous n'avez besoin de remplacer l'implémentation par défaut que si votre outil
  # ne s'installe pas dans le répertoire "bin" standard.

  my($class) = @_;

  # normalement pour les installations système, l'outil devrait déjà être dans votre
  # PATH, donc retournez une liste vide.
  return if $class->install_type eq 'system';

  # install_type = share
  my $dist_dir = $class->dist_dir;
  return ("$dist_dir/some/bin", "$dist_dir/some/other/bin");
}

1;

vérifier la version construite si ma bibliothèque ne fournit pas de fichier ".

pc".

L'implémentation par défaut de "alien_check_built_version" utilise plusieurs heuristiques, mais s'appuie fortement sur les fichiers de style "pkg-config" ".pc", donc si votre bibliothèque ou outil ne fournit pas de ".pc", la version peut ne pas être détectée et votre compilation peut

échouer.

Beaucoup de bibliothèques sont distribuées sous forme de tarballs avec la version dans le nom du répertoire dans lequel elles sont extraites, et le répertoire courant lorsque "alien_check_built_version" est appelé est la racine de la compilation, vous pouvez donc utiliser "File::chdir" comme moyen simple de déterminer le numéro de version

: 
package My::ModuleBuild;

use strict;
use warnings;
use parent 'Alien::Base::ModuleBuild';
use File::chdir; # fournit @CWD

sub alien_check_built_version
{
  my $dir_name = $CWD[-1];

  if($dir_name =~ /^libfoo-([0-9\.]+)$/) {
    return $1;
  } else {
    # Notez que cela déclenchera un échec de compilation
    return;
  }
}
1;

Utiliser File::chdir et @CWD est un idiome courant dans Alien::Base, car File::chdir est déjà une dépendance de Alien::Base. Pour les paquets

qui ne fournissent pas de numéro de version dans le répert
oire extrait, vous devrez peut-être faire preuve de créativité.
