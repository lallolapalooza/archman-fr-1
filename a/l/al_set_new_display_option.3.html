DESCRIPTIO

N

Définit une option d'affichage supplémentaire, à utiliser lors de la création de nouveaux affichages sur le thread appelant. Les options d'affichage diffèrent des indicateurs d'affichage (display flags) et spécifient certains détails du contexte à créer à l'intérieur de la fenêtre elle-même. Celles-ci n'ont principalement aucun effet sur Allegro lui-même, mais vous pouvez vouloir les spécifier, par exemple si vous souhaitez utiliser le

multisampling.

Le paramètre `importance' peut être l'un des suivants

:
•
ALLEGRO_REQUIRE - L'affichage ne sera pas créé si le paramètre ne peut pas être
satisfait.
•
ALLEGRO_SUGGEST - Si le paramètre n'est pas disponible, l'affichage sera quand même créé avec un paramètre aussi proche que possible de celui demandé. Vous pouvez interroger la valeur réelle utilisée dans ce cas en appelant al_get_display_option(3) après la création de
l'affichage.
•
ALLEGRO_DONTCARE - Si vous avez ajouté une option d'affichage
avec l'un des deux paramètres ci-dessus auparavant, e
lle sera à nouveau supprimée. Sinon, cela ne fait rien.

Les options prises en charge sont

:
ALLEGRO_COLOR_S
IZE
Cela peut être utilisé pour demander une profondeur de bits spécifique. Par exemple, pour forcer un framebuffer de 16 bits, définissez ceci
à 16.
ALLEGRO_RED_SIZE, ALLEGRO_GREEN_SIZE, ALLEGRO_BLUE_SIZE, ALLEGRO_ALPHA_S
IZE
Taille individuelle du composant de couleur en
bits.
ALLEGRO_RED_SHIFT, ALLEGRO_GREEN_SHIFT, ALLEGRO_BLUE_SHIFT, ALLEGRO_ALPHA_SH
IFT
En combinaison avec les paramètres précédents, ceux-ci peuvent être utilisés pour spécifier la disposition exacte des pixels que l'affichage doit utiliser. Normalement, il n'y a aucune raison d'utiliser
ceux-ci.
ALLEGRO_ACC_RED_SIZE, ALLEGRO_ACC_GREEN_SIZE, ALLEGRO_ACC_BLUE_SIZE, ALLEGRO_ACC_ALPHA_S
IZE
Cela peut être utilisé pour définir la taille requise du tampon
d'accumulation.
ALLEGRO_STER
EO
Indique si l'affichage est un affichage
stéréoscopique.
ALLEGRO_AUX_BUFF
ERS
Nombre de tampons auxiliaires que l'affichage doit
avoir.
ALLEGRO_DEPTH_S
IZE
Nombre de bits du tampon de profondeur (z-buffer) à
utiliser.
ALLEGRO_STENCIL_S
IZE
Nombre de bits à utiliser pour le tampon de
stencil.
ALLEGRO_SAMPLE_BUFF
ERS
Indique s'il faut utiliser le multisampling (1) ou non
(0).
ALLEGRO_SAMP
LES
Si ce qui précède est 1, le nombre d'échantillons à utiliser par pixel. Sinon
0.
ALLEGRO_RENDER_METH
OD:
0 si l'accélération matérielle n'est pas utilisée avec cet
affichage.
ALLEGRO_FLOAT_CO
LOR
Indique s'il faut utiliser des composants de couleur en virgule
flottante.
ALLEGRO_FLOAT_DE
PTH
Indique s'il faut utiliser un tampon de profondeur en virgule
flottante.
ALLEGRO_SINGLE_BUF
FER
Indique si l'affichage utilise un tampon unique (1) ou une autre méthode de mise à jour
(0).
ALLEGRO_SWAP_MET
HOD
Si ce qui précède est 0, ceci est défini à 1 pour indiquer que l'affichage utilise une méthode de copie pour rendre le prochain tampon de la chaîne de basculement disponible, ou à 2 pour indiquer un basculement ou une autre
méthode.
ALLEGRO_COMPATIBLE_DISP
LAY
Indique si les fonctions graphiques d'Allegro peuvent utiliser cet affichage. Si vous demandez un affichage non utilisable par Allegro, vous pouvez toujours utiliser par exemple OpenGL pour dessiner des
graphiques.
ALLEGRO_UPDATE_DISPLAY_REG
ION
Défini à 1 si l'affichage est capable de mettre à jour seulement une région, et à 0 si appeler al_update_display_region(3) est équivalent à al_flip_display(3)
.
ALLEGRO_VSY
NC
Défini à 1 pour indiquer au pilote d'attendre le vsync dans al_flip_display(3), ou à 2 pour forcer le vsync désactivé. La valeur par défaut 0 signifie qu'Allegro n'essaie pas de modifier le comportement du vsync, il peut donc être activé ou désactivé. Notez que même dans le cas de 1 ou 2, il est possible de remplacer le comportement du vsync dans le pilote graphique, vous ne devez donc pas compter
dessus.
ALLEGRO_MAX_BITMAP_S
IZE
Lorsqu'il est interrogé, cela renvoie la taille maximale (largeur ainsi que hauteur) qu'une bitmap peut avoir pour cet affichage. Les appels à al_create_bitmap(3) ou al_load_bitmap(3) pour des bitmaps plus grandes que cette taille échoueront. Cela ne s'applique pas aux bitmaps en mémoire qui peuvent toujours avoir une taille arbitraire (mais sont lentes pour le dessin)
.
ALLEGRO_SUPPORT_NPOT_BIT
MAP
Défini à 1 si les textures utilisées pour les bitmaps sur cet affichage peuvent avoir une taille qui n'est pas une puissance de deux. C'est principalement utile si vous utilisez Allegro pour charger des textures, car sinon seules des textures de puissance de deux seront utilisées en interne comme stockage de
bitmap.
ALLEGRO_CAN_DRAW_INTO_BIT
MAP
Défini à 1 si vous pouvez utiliser al_set_target_bitmap(3) sur les bitmaps de cet affichage pour dessiner à l'intérieur. Si ce n'est pas le cas, une émulation logicielle sera utilisée lors du dessin dans les bitmaps d'affichage (ce qui peut être très
lent).
ALLEGRO_SUPPORT_SEPARATE_AL
PHA
Ceci est défini à 1 si la fonction al_set_separate_blender(3) est prise en charge. Sinon, les paramètres alpha seront
ignorés.
ALLEGRO_AUTO_CONVERT_BITM
APS
C'est activé par défaut. Cela provoque la conversion de toute bitmap en
mémoire existante avec l'indicateur ALLEGRO_CONVERT_BITMAP en bitmap
d'affichage de l'affichage nouvellement créé avec l'option définie.

PORTRAIT signifie que seules les deux orientations portrait sont prises en charge, LANDSCAPE signifie que seules les deux orientations paysage le sont, et ALL permet les quatre orientations. Lorsque l'orientation change entre une orientation portrait et une orientation paysage, l'affichage doit être redimensionné.
