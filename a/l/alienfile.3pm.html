RÉSUM

É

Approche faites-le-vous-même

: 
use alienfile;

probe [ 'pkg-config --exists libarchive' ];

share {

  start_url 'http://libarchive.org/downloads/libarchive-3.2.2.tar.gz';

  # le premier qui réussit sera utilisé
  download [ 'wget %{.meta.start_url}' ];
  download [ 'curl -o %{.meta.start_url}' ];

  extract [ 'tar xf %{.install.download}' ];

  build [
    # Remarque : ne fonctionnera pas sur Windows, mieux vaut utiliser le plugin Build::Autoconf
    # si vous avez besoin de la prise en charge de Windows
    './configure --prefix=%{.install.prefix} --disable-shared',
    '%{make}',
    '%{make} install',
  ];
}

gather [
  [ 'pkg-config', '--modversion', 'libarchive', \'%{.runtime.version}' ],
  [ 'pkg-config', '--cflags',     'libarchive', \'%{.runtime.cflags}'  ],
  [ 'pkg-config', '--libs',       'libarchive', \'%{.runtime.libs}'    ],
]
;

Avec des plugins (mieux)

: 
use alienfile;

plugin 'PkgConfig' => 'libarchive';

share {
  start_url 'http://libarchive.org/downloads/';
  plugin Download => (
    filter => qr/^libarchive-.*\.tar\.gz$/,
    version => qr/([0-9\.]+)/,
  );
  plugin Extract => 'tar.gz';
  plugin 'Build::Autoconf';
  plugin 'Gather::IsolateDynamic';
  build [
    '%{configure}',
    '%{make}',
    '%{make} install',
  ];
}
;

DESCRIPTIO

N

Un alienfile est une recette utilisée par Alien::Build pour rechercher des bibliothèques système ou télécharger depuis Internet, et compiler le code source de ces bibliothèques. Ce document sert de référence pour le système alienfile, mais si vous commencez à écrire votre propre Alien, vous devriez lire Alien::Build::Manual::AlienAuthor, qui vous apprendra comment écrire votre propre Alien complet en utilisant alienfile + Alien::Build + ExtUtils::MakeMaker. Une attention particulière doit être portée à la section « a note about dynamic vs. static libraries

»
.

plugi

n 
plugin $name => (%args);
plugin $name =>
$arg;

Charge le plugin donné. Si vous préfixez le nom du plugin avec un signe « = », il sera considéré comme un chemin de fichier entièrement qualifié. Sinon, le plugin sera supposé se trouver dans l'espace de noms « Alien::Build::Plugin ». S'il existe un plugin de négociation approprié, celui-ci sera chargé. Exemples

: 
# Charge Alien::Build::Plugin::Fetch::Negotiate
# qui choisira le meilleur plugin Alien::Build::Plugin::Fetch
# en fonction de l'URL et de la configuration du système
plugin 'Fetch' => 'http://ftp.gnu.org/gnu/gcc';

# charge le plugin avec la classe mal nommée !
plugin '=Badly::Named::Plugin::Not::In::Alien::Build::Namespace';

# charge explicitement Alien::Build::Plugin::Prefer::SortVersions
plugin 'Prefer::SortVersions' => (
  filter => qr/^gcc-.*\.tar\.gz$/,
  version => qr/([0-9\.]+)/,
)
;

Instructions pour l'étape de regroupement. Peut être soit une référence de code, soit une liste de commandes. Dans le bloc racine du fichier alien, cela se déclenchera à la fois pour la compilation partagée et système. Dans le bloc partagé ou système, cela ne se déclenchera que dans la compilation correspondante.

before

before $stage => \&code;

Exécute le code donné avant l'étape spécifiée. L'étape doit être l'une de "probe", "download", "fetch", "decode", "prefer", "extract", "patch", "build", "test", et "gather".

La directive before n'est légale que dans les mêmes blocs que ceux où l'étape serait normalement légale. Par exemple, vous ne pouvez pas faire ceci :

use alienfile;

sys {
  before 'build' => sub {
    ...
  };
};

Car un "build" ne serait pas légal dans un bloc "sys".

after

after $stage => \&code;

Exécute le code donné après l'étape spécifiée. L'étape doit être l'une de "probe", "download", "fetch", "decode", "prefer", "extract", "patch", "build", "test", et "gather".

La directive after n'est légale que dans les mêmes blocs que ceux où l'étape serait normalement légale. Par exemple, vous ne pouvez pas faire ceci :

use alienfile;

sys {
  after 'build' => sub {
    ...
  };
};

Car un "build" ne serait pas légal dans un bloc "sys".
