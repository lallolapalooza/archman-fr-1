NOM

package - un paquet basé sur les concepts de gestion de paquets d'Arch Linux Package Management (ALPM).

DESCRIPTION

Les paquets basés sur ALPM font référence à des archives tar (optionnellement compressées) qui contiennent des fichiers de paquet. Les fichiers de paquet englobent des fichiers de métadonnées obligatoires ainsi que des scripts et des fichiers de données optionnels.

Les fichiers de paquet sont créés à partir des sources du paquet (c'est-à-dire PKGBUILD) à l'aide d'un logiciel de construction de paquet (par exemple, makepkg). Pour le logiciel de construction de paquets spécifique à Arch Linux, référez-vous à devtools et pkgctl.

Le logiciel de gestion de paquets (par exemple, pacman) s'appuie sur les fichiers de métadonnées et les scripts aux fins de résolution des dépendances et d'installation. Les fichiers de données peuvent être installés sur des systèmes cibles compatibles en utilisant le logiciel de gestion de paquets.

FORMAT

Les fichiers de paquet ALPM *non compressés* suivent le schéma de nommage suivant :

Un nom-paquet-alpm directement suivi d'un signe ‘-’, directement suivi d'un version-paquet-alpm (sous la forme *complète* ou *complète avec epoch*), directement suivi d'un signe ‘-’, directement suivi d'une architecture-alpm, directement suivi de la chaîne ‘.pkg.tar’, par exemple :

  • example-1.0.0-1-any.pkg.tar
  • example-1.0.0-1-x86_64.pkg.tar

Compression

Les paquets basés sur ALPM peuvent éventuellement être compressés en utilisant une seule technologie de compression prise en charge. Si un paquet est compressé, un suffixe spécifique à la technologie est ajouté au nom de fichier :

  • .Z pour la compression basée sur le codage Lempel-Ziv adaptatif (par exemple, example-1.0.0-1-x86_64.pkg.tar.Z), voir la commande compress
  • .bz2 pour la compression bzip2 (par exemple, example-1.0.0-1-x86_64.pkg.tar.bz2)
  • .gz pour la compression gzip (par exemple, example-1.0.0-1-x86_64.pkg.tar.gz)
  • .lrz pour la compression lrzip (par exemple, example-1.0.0-1-x86_64.pkg.tar.lrz)
  • .lz4 pour la compression lz4 (par exemple, example-1.0.0-1-x86_64.pkg.tar.lz4)
  • .lz pour la compression lzip (par exemple, example-1.0.0-1-x86_64.pkg.tar.lz)
  • .lzo pour la compression lzop (par exemple, example-1.0.0-1-x86_64.pkg.tar.lzo)
  • .xz pour la compression xz (par exemple, example-1.0.0-1-x86_64.pkg.tar.xz)
  • .zst pour la compression zstd (par exemple, example-1.0.0-1-x86_64.pkg.tar.zst)

La gestion des technologies de compression est spécifique à l'outil de construction de paquets. Référez-vous à COMPRESSBZ2, COMPRESSGZ, COMPRESSLRZ, COMPRESSLZ, COMPRESSLZ4, COMPRESSLZO, COMPRESSXZ, COMPRESSZ, COMPRESSZST et PKGEXT dans makepkg.conf pour les options de compression et les extensions de paquets utilisées dans makepkg.

Signatures numériques

Des signatures numériques peuvent être créées pour les fichiers de paquet.

Actuellement, seules les signatures détachées OpenPGP sur le fichier de paquet sont prises en charge. Les signatures détachées portent le même nom que le fichier de paquet pour lequel elles sont créées, avec un suffixe supplémentaire .sig (par exemple, example-1.0.0-1-x86_64.pkg.tar.zst.sig est la signature numérique d'un fichier de paquet example-1.0.0-1-x86_64.pkg.tar.zst).

CONTENU

Le contenu d'un paquet basé sur ALPM est distingué entre les fichiers de métadonnées, les scripts et les données.

Métadonnées

Les fichiers suivants doivent être présents à la racine d'un paquet basé sur ALPM :

  • .BUILDINFO : un fichier BUILDINFO
  • .MTREE : un fichier ALPM-MTREE
  • .PKGINFO : un fichier PKGINFO

Les fichiers ci-dessus fournissent les métadonnées pertinentes pour l'installation, la mise à niveau et la désinstallation des paquets sur un système cible (voir alpm-package-relation pour plus de détails sur la résolution des dépendances), ainsi que pour la construction reproductible d'un paquet bit par bit identique à partir des mêmes sources (voir constructions reproductibles[2]).

Scripts

Optionnellement, un script d'installation alpm nommé .INSTALL peut être présent à la racine d'un paquet basé sur ALPM.

Données

Zéro ou plusieurs fichiers de données peuvent être présents dans un paquet basé sur ALPM (voir alpm-meta-package pour plus de détails sur pourquoi les paquets peuvent ne pas contenir de fichiers de données).

Tous les fichiers de données existants d'un paquet sont extraits dans le répertoire racine[3] d'un système cible lors de l'installation du paquet.

Il n'existe pas de règles spécifiques concernant les fichiers (et répertoires) de données autorisés dans le contenu d'un paquet, mais il est conseillé de respecter les normes communes telles que les Exigences de hiérarchie de fichiers systemd[4] et/ou le Filesystem Hierarchy Standard[5] et, par défaut, que tous les fichiers et répertoires appartiennent à root. En conclusion, il est préférable de ne jamais empaqueter de fichiers dans des répertoires contenant des données utilisateur (par exemple, sous /home).

Des directives plus spécifiques concernant la validation des fichiers de données dans les paquets sont laissées à la discrétion de l'implémenteur (par exemple, une distribution utilisant ALPM).

EXEMPLES

L'exemple de PKGBUILD suivant définit le paquet example qui ne crée qu'un seul fichier de données (plus les répertoires dans lesquels il se trouve) :

pkgname=example
pkgver=1.0.0
pkgrel=1
pkgdesc="Un exemple de paquet simple"
arch=(any)
url="https://example.org"
license=(GPL-3.0-or-later)
package() {
  install -vdm 755 "$pkgdir/usr/share/$pkgname/"
  echo "data" > "$pkgdir/usr/share/$pkgname/data.txt"
}

En supposant que makepkg soit utilisé pour construire un paquet à partir du PKGBUILD ci-dessus et qu'il soit configuré pour utiliser zstd pour la compression, le fichier de paquet résultant est nommé example-1.0.0-1-any.pkg.tar.zst.

Le contenu du fichier de paquet peut être examiné comme suit :

$ tar -tf example-1.0.0-1-any.pkg.tar.zst
.BUILDINFO
.MTREE
.PKGINFO
usr/
usr/share/
usr/share/example/
usr/share/example/data.txt
