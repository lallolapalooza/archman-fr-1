ALTER_DATABASE(7)

Paquet: postgresql

Licences: PostgreSQL

ALTER DATABASE(7) Documentation PostgreSQL 18.1 ALTER DATABASE(7)

NOM

ALTER_DATABASE - modifier une base de données

SYNTAXE

ALTER DATABASE nom [ [ WITH ] option [ ... ] ]
où option peut être :
    ALLOW_CONNECTIONS allowconn
    CONNECTION LIMIT connlimit
    IS_TEMPLATE istemplate
ALTER DATABASE nom RENAME TO nouveau_nom
ALTER DATABASE nom OWNER TO { nouveau_proprietaire | CURRENT_ROLE | CURRENT_USER | SESSION_USER }
ALTER DATABASE nom SET TABLESPACE nouveau_tablespace
ALTER DATABASE nom REFRESH COLLATION VERSION
ALTER DATABASE nom SET parametre_configuration { TO | = } { valeur | DEFAULT }
ALTER DATABASE nom SET parametre_configuration FROM CURRENT
ALTER DATABASE nom RESET parametre_configuration
ALTER DATABASE nom RESET ALL

DESCRIPTION

ALTER DATABASE modifie les attributs d'une base de données.

La première forme modifie certains paramètres par base de données. (Voir ci-dessous pour les détails.) Seul le propriétaire de la base de données ou un superutilisateur peut modifier ces paramètres.

La deuxième forme modifie le nom de la base de données. Seul le propriétaire de la base de données ou un superutilisateur peut renommer une base de données ; les propriétaires non-superutilisateurs doivent également avoir le privilège CREATEDB. La base de données actuelle ne peut pas être renommée. (Connectez-vous à une autre base de données si vous devez le faire.)

La troisième forme modifie le propriétaire de la base de données. Pour modifier le propriétaire, vous devez pouvoir exécuter SET ROLE sur le nouveau rôle propriétaire, et vous devez avoir le privilège CREATEDB. (Notez que les superutilisateurs ont automatiquement tous ces privilèges.)

La quatrième forme modifie l'espace de table par défaut de la base de données. Seul le propriétaire de la base de données ou un superutilisateur peut le faire ; vous devez également avoir le privilège create pour le nouvel espace de table. Cette commande déplace physiquement toutes les tables ou index de l'ancien espace de table par défaut de la base de données vers le nouvel espace de table. Le nouvel espace de table par défaut doit être vide pour cette base de données, et personne ne doit être connecté à la base de données. Les tables et les index dans des espaces de table non-par défaut ne sont pas affectés. La méthode utilisée pour copier les fichiers vers le nouvel espace de table est affectée par le paramètre file_copy_method.

Les formes restantes modifient la valeur par défaut de session pour une variable de configuration d'exécution pour une base de données PostgreSQL. Chaque fois qu'une nouvelle session démarre ultérieurement dans cette base de données, la valeur spécifiée devient la valeur par défaut de session. Le défaut spécifique à la base de données remplace tout réglage présent dans postgresql.conf ou reçu de la ligne de commande postgres. Seul le propriétaire de la base de données ou un superutilisateur peut modifier les valeurs par défaut de session d'une base de données. Certains paramètres ne peuvent pas être définis de cette manière, ou ne peuvent être définis que par un superutilisateur.

PARAMETRES

nom

Le nom de la base de données dont les attributs doivent être modifiés.

allowconn

Si false, personne ne peut se connecter à cette base de données.

connlimit

Combien de connexions simultanées peuvent être établies à cette base de données. -1 signifie aucune limite.

istemplate

Si true, alors cette base de données peut être clonée par tout utilisateur ayant les privilèges CREATEDB ; si false, alors seuls les superutilisateurs ou le propriétaire de la base de données peuvent la cloner.

nouveau_nom

Le nouveau nom de la base de données.

nouveau_proprietaire

Le nouveau propriétaire de la base de données.

nouveau_tablespace

L'espace de table par défaut de la base de données.

Cette forme de la commande ne peut pas être exécutée à l'intérieur d'un bloc de transaction.

REFRESH COLLATION VERSION

Met à jour la version de collation de la base de données. Voir Notes pour le contexte.

parametre_configuration
valeur

Définit la valeur par défaut de session de cette base de données pour le paramètre de configuration spécifié. Si valeur est DEFAULT ou, de manière équivalente, RESET est utilisé, le réglage spécifique à la base de données est supprimé, de sorte que le réglage par défaut du système sera hérité dans les nouvelles sessions. Utilisez RESET ALL pour effacer tous les réglages spécifiques à la base de données. SET FROM CURRENT sauvegarde la valeur actuelle du paramètre de la session comme valeur spécifique à la base de données.

Voir SET(7) et le Chapitre 19 pour plus d'informations sur les noms de paramètres et les valeurs autorisés.

NOTES

Il est également possible de lier une valeur par défaut de session à un rôle spécifique plutôt qu'à une base de données ; voir ALTER ROLE (ALTER_ROLE(7)). Les réglages spécifiques au rôle remplacent ceux spécifiques à la base de données en cas de conflit.

EXEMPLES

Pour désactiver les scans d'index par défaut dans la base de données test :

ALTER DATABASE test SET enable_indexscan TO off;

COMPATIBILITE

L'instruction ALTER DATABASE est une extension PostgreSQL.

VOIR AUSSI
