DESCRIPTIO

N

Les relations de paquets décrivent les relations entre les paquets basés sur ALPM pour divers scénarios. Elles sont utilisées dans les scripts de construction ou les formats de fichier pour les métadonnées des paquets (par exemple dans PKGBUILD, PKGINFO ou SRCINFO) pour décrire les relations des paquets avec d'autres paquets. Des logiciels tels que les gestionnaires de paquets ou les logiciels de construction de paquets s'appuient sur les relations de paquets pour résoudre les graphes de dépendances, par exemple lors de l'installation ou de la désinstallation de

paquets.

Paquets et composants

virtuels

Toute relation de paquet peut contenir un nom-de-paquet-alpm, qui peut être utilisé pour faire référence à un paquet existant ou à un composant virtuel. Les composants virtuels ne représentent pas les noms de paquets existants, mais plutôt un composant qui est implicitement défini par les métadonnées du paquet. À l'aide des relations de paquets, les composants virtuels sont définis et utilisés de manière similaire aux noms de paquets existants (voir EXEMPLES pour plus

d'infor
mations).

Soname

s

Une relation de paquet de type fourniture ou dépendance d'exécution peut contenir un soname-alpm qui représente une dépendance stricte basée sur un objet partagé spécifique dans un paquet. Elles sont utilisées pour encoder les garanties de compatibilité entre les fichiers ELF[1] et les objets partagés à l'aide des données soname[2] (voir EXEMPLES pour plus

d'infor
mations).

l'architecture

Provisions en tant que composants

virtuels

Les serveurs de courrier fonctionnant avec le protocole SMTP peuvent généralement être utilisés dans plusieurs scénarios (p. ex. en tant que relais SMTP ou serveur). Il est courant d'avoir des paquets qui ne nécessitent qu'un seul de ces scénarios. En considérant le paquet de serveur de courrier my-mailserver, qui représente une solution complète de serveur de courrier, il est donc utile de définir des provisions pour lui (p. ex. en introduisant les composants virtuels smtp-forwarder et smtp-server). Un autre paquet de serveur de courrier - minimal-mailserver - ne peut être utilisé qu'en tant que relais SMTP, il est donc possible de définir une seule provision (c.-à-d. en introduisant le composant virtuel smtp-forwar

der).

D'autres paquets peuvent maintenant dépendre de ces composants virtuels, au lieu d'un serveur de courrier spécifique : en considérant le paquet de supervision my-monitoring, qui permet d'envoyer des courriels de supervision en utilisant un relais SMTP local, une dépendance d'exécution peut être définie pour qu'il dépende du composant virtuel smtp-forwarder

.

Ce scénario permet à un gestionnaire de paquets d'offrir à l'utilisateur le choix de s'appuyer sur l'un des fournisseurs de smtp-forwarder (c.-à-d. my-mailserver ou minimal-ma

ilser
ver).

sonames

Certains paquets fournissent des fichiers d'objet partagé auxquels les fichiers ELF[1] d'autres paquets peuvent se lier

dynamiquement.

Par exemple, le paquet example peut contenir les fichiers suivants

/usr/lib/libexample.so.1 -> libexample.so.1.0.0
/usr/lib/libexample.so.1.0.

Ici, le fichier d'objet partagé /usr/lib/libexample.so.1.0.0 encode le soname[2] libexample.

so.1.

En suivant la spécification alpm-soname, lib:libexample.so.1 peut être ajouté en tant que fourniture au fichier PKGINFO du paquet example, si le répertoire de recherche de bibliothèques /usr/lib est représenté par le préfixe lib

.

Ensuite, un autre paquet example appelé application peut contenir le fichier ELF[1] /usr/bin/application, qui se lie dynamiquement à l' objet partagé /usr/lib/libexample.so.1 contenu dans le paquet example. Le fichier ELF[1] encode cette exigence en s'appuyant sur le soname[2] libexample.

so.1.

En suivant la spécification alpm-soname, lib:libexample.so.1 peut être ajouté en tant que dépendance d'exécution au fichier PKGINFO du paquet application, si le répertoire de recherche de bibliothèques /usr/lib est représenté par le préfixe lib et que l' objet partagé encodant le soname libexample.so.12 est présent dans le répertoire de re

cherche.

NOM

alpm-package-relation - Relations entre paquets ALPM

DESCRIPTION

ALPM (Arch Linux Package Management) gère les relations entre paquets en utilisant une syntaxe simple.

Les relations courantes incluent :

  • depname : Le paquet depname est une dépendance de ce paquet.
  • >depname : Le paquet depname doit être une version supérieure.
  • <depname : Le paquet depname doit être une version inférieure.
  • =depname : Le paquet depname doit être de cette version exacte.
  • nom:option : La dépendance nom est optionnelle, déclenchée par option.
  • nom&autre : Le paquet doit avoir nom ET autre installés.
  • nom|autre : Le paquet doit avoir nom OU autre installé.

Ces relations sont utilisées dans les champs Depends On, Optional Deps, Conflicts With, Provides, et Replaces des fichiers PKGBUILD.

EXEMPLES

Pour déclarer qu'un paquet dépend de glibc version 2.28 ou supérieure, et optionnellement de bash qui fournit la fonctionnalité shell :

depends=('glibc>=2.28')
optional_depends=('bash: shell')

PKGBUILD(5), Documentation ALPM

NOTES

La gestion des relations est un aspect crucial pour maintenir l'intégrité et la stabilité du système Arch Linux.
