Pourquoi mon fichier zip est-il si gros

?

Q : Mon fichier zip est en fait plus grand que ce que j'y ai stocké ! Pourquoi

?

R : Quelques points à vérifier

:
Assurez-vous que vous demandez COMPRESSION_DEFLATED si vous stockez des chaînes de
caractères.
$member->desiredCompressionMethod( COMPRESSION_DEFLATED
);
N'essayez pas de créer beaucoup de petits fichiers si vous pouvez
l'éviter.
Puisque zip calcule les tables de compression pour chaque membre, les petits membres sans beaucoup d'entropie ne seront pas bien compressés. À la place, si vous avez beaucoup de chaînes répétées dans vos données, essayez de les combiner en un seul gros
membre.
Assurez-vous que vous demandez COMPRESSION_STORED si vous stockez des choses déjà
compressées.
Si vous stockez un .zip, .jpg, .mp3
ou autre fichier compressé dans un
zip, ne les compressez pas à
nouveau. Ils deviendront plus gros.

Impossible de lire/modifier/écrire le même fichier

Zip

Q : Pourquoi ne puis-je pas ouvrir un fichier Zip, ajouter un membre et le réécrire ? J'obtiens un message d'erreur quand

j'essaie.

R : Parce qu'Archive::Zip ne lit pas (et ne peut généralement pas lire) le contenu des fichiers en mémoire, le fichier Zip original doit rester disponible jusqu'à ce que l'écriture du nouveau fichier soit

terminée.

La meilleure façon de faire est d'écrire le Zip dans un fichier temporaire puis de renommer le fichier temporaire pour qu'il porte l'ancien nom (éventuellement après avoir supprimé l'ancien)

.

Archive::Zip v1.02 a ajouté les méthodes d'archive overwrite() et overwriteAs() pour faire cela simplement et

soigneusement.

Voir "examples/updateZip.pl" pour

un exemple de
cette technique.

Heure de création du fichier non

définie

Q : Lors de l'extraction des fichiers, je constate que leur heure de modification (et d'accès) est définie à l'heure indiquée dans l'archive Zip. Cependant, leur heure de création n'est pas définie à la même heure. Pourquoi

?

R : Principalement parce que Perl ne fournit pas d'accès multiplateforme à l'heure de création. En effet, de nombreux systèmes (comme Unix) ne prennent pas en charge un tel concept. Cependant, si le vôtre le fait, vous pouvez facilement la définir. Récupérez l'heure de modification du membre avec lastMod

Tim
e().

Impossible d'utiliser Archive::Zip sur des fichiers

gzip

Q : Puis-je utiliser Archive::Zip pour extraire des fichiers gzip Unix

?

R :

Non.

Il y a une distinction entre les fichiers gzip Unix et les archives Zip qui peuvent aussi utiliser la compression

gzip.

Selon le format du fichier gzip, vous pouvez utiliser Compress::Raw::Zlib ou Archive::Tar pour le décompresser (et le désarchiver dans le cas des fichiers Tar)

.

Vous pouvez décompresser les archives PKZIP/WinZip/etc/ avec

Archive::Zip (c'est à cela qu'il sert) tant que tous les
membres compressés le sont avec la compression Deflate.

Ajouter un répertoire/arborescence à un

Zip

Q : Comment puis-je ajouter un répertoire (ou une arborescence) rempli de fichiers à un Zip

?

R : Vous pouvez utiliser les méthodes Archive::Zip::addTree*()

: 
use Archive::Zip;
my $zip = Archive::Zip->new();
# ajoute tous les fichiers et répertoires lisibles sous . comme xyz/*
$zip->addTree( '.', 'xyz' );
# ajoute tous les fichiers simples lisibles sous /abc comme def/*
$zip->addTree( '/abc', 'def', sub { -f && -r } );
# ajoute tous les fichiers .c sous /tmp comme stuff/*
$zip->addTreeMatching( '/tmp', 'stuff', '\.c$' );
# ajoute tous les fichiers .o sous /tmp comme stuff/* s'ils ne sont pas inscriptibles
$zip->addTreeMatching( '/tmp', 'stuff', '\.o$', sub { ! -w } );
# ajoute tous les fichiers .so sous /tmp qui font moins de 200 octets comme stuff/*
$zip->addTreeMa
tching( '/tmp', 'stuff', '\.o$', sub { -s < 200 } ); # et l
es écrire dans un fichier $zip->writeToFileNamed('xxx.zip');

Impossible d'extraire les fichiers

Shrunk

Q : J'essaie d'extraire un fichier d'un Zip produit par PKZIP, et je reçois constamment ce message d'erreur

: 
error: Unsupported compression combination: read 6, write
0

R : Vous ne pouvez pas décompresser ce membre d'archive. Archive::Zip ne prend en charge que les membres non compressés, et les membres compressés avec la compression prise en charge par Compress::Raw::Zlib. Cela signifie uniquement les membres Deflated et

Stored.

Votre fichier est compressé avec le format Shrink, qui n'est pas pris en charge par Compress::Raw::

Zlib.

Vous pourriez peut-être utiliser un prog

ramme UnZip en ligne de commande (comme
celui d'Info-Zip) pour extraire cela.

?

vous
-même).

Comment tester l'intégrité des fichiers

?

Q : Comment Archive::Zip peut-il tester la validité d'un fichier Zip

?

R : Si vous essayez de décompresser le fichier, les flux gzip signaleront des erreurs si vous avez des données parasites. La plupart du

temps.

Si vous essayez d'ouvrir le fichier et qu'une structure de répertoire central ne peut pas être trouvée, une erreur sera

signalée.

Lorsqu'un fichier est lu, si nous ne pouvons pas trouver une signature PK.. appropriée aux bons endroits, nous signalons une erreur de

format.

S'il y a des données parasites ajoutées au début d'un fichier Zip (comme insérées par certains virus), vous pouvez le découvrir, mais Archive::Zip les ignorera, et vous pourrez toujours utiliser l'archive. Lorsqu'elle sera réécrite, les données ajoutées auront

disparu.

Il y a deux utilitaires prêts à l'emploi dans le répertoire examples qui peuvent être utilisés pour tester l'intégrité des fichiers, ou que vous pouvez utiliser comme exemples pour votre propre code

:
examples/zipcheck.pl montre comment utiliser une tentative d'extraction pour tester un
fichier.
examples/ziptest.pl montre comment tester les CRC dans un
fichier.

?

Q : Archive::Zip m'a laissé mettre le même fichier dans mon Zip deux fois ! Pourquoi n'empêchez-vous pas cela

?

R : Autant que je sache, cela n'est pas interdit par la spécification Zip. Si vous pensez que c'est une mauvaise idée, vérifiez-le vous-même

: 
$zip->addFile($someFile, $someName) unless $zip->memberNamed($someName)

a pourrait être utile (par exemple,
plusieurs versions de fichiers).
