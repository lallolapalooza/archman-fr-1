arch_prctl(2) Manuel des appels système arch_prctl(2)

NOM

arch_prctl - définir l'état du fil d'exécution spécifique à l'architecture

BIBLIOTHÈQUE

Bibliothèque C standard (libc,-lc)

SYNOPSIS

#include <asm/prctl.h>        /* Définition des constantes ARCH_* */
#include <sys/syscall.h>      /* Définition des constantes SYS_* */
#include <unistd.h>
int syscall(SYS_arch_prctl, int op, unsigned long addr);
int syscall(SYS_arch_prctl, int op, unsigned long *addr);

Note: glibc ne fournit pas de fonction enveloppe pour arch_prctl(), ce qui nécessite l'utilisation de syscall(2).

DESCRIPTION

arch_prctl() définit l'état du processus ou du fil d'exécution spécifique à l'architecture. op sélectionne une opération et lui passe l'argument addr ; addr est interprété soit comme un unsigned long pour les opérations « set », soit comme un unsigned long *, pour les opérations « get ».

Les sous-fonctions pour x86 et x86-64 sont :

ARCH_SET_CPUID (depuis Linux 4.12)
Active (addr != 0) ou désactive (addr == 0) l'instruction cpuid pour le fil d'exécution appelant. L'instruction est activée par défaut. Si elle est désactivée, toute exécution d'une instruction cpuid génère à la place un signal SIGSEGV . Cette fonctionnalité peut être utilisée pour émuler des résultats cpuid différents de ceux que le matériel sous-jacent aurait produits (par exemple dans un environnement de paravirtualisation).
Le paramètre ARCH_SET_CPUID est conservé à travers fork(2) et clone(2) mais est réinitialisé à la valeur par défaut (c'est-à-dire cpuid activé) lors d'un execve(2).
ARCH_GET_CPUID (depuis Linux 4.12)
Renvoie la valeur du drapeau manipulé par ARCH_SET_CPUID comme résultat de l'appel système (1 si activé, 0 si désactivé). addr est ignoré.
Les sous-fonctions exclusives à x86-64 sont :
ARCH_SET_FS
Définit la base 64 bits du registre FS à addr.
ARCH_GET_FS
Renvoie la valeur de base 64 bits du registre FS du fil d'exécution appelant dans le unsigned long pointé par addr.
ARCH_SET_GS
Définit la base 64 bits du registre GS à addr.
ARCH_GET_GS
Renvoie la valeur de base 64 bits du registre GS du fil d'exécution appelant dans le unsigned long pointé par addr.

VALEUR RENVOYÉE

En cas de succès, arch_prctl() renvoie 0 ; en cas d'erreur, -1 est renvoyé et errno est défini pour indiquer l'erreur.

ERREURS

EFAULT
addr pointe vers une adresse non mappée ou se trouve en dehors de l'espace d'adressage du processus.
EINVAL
op n'est pas une opération valide.
ENODEV
ARCH_SET_CPUID a été demandé, mais le matériel sous-jacent ne prend pas en charge la détection de fautes CPUID.
EPERM
addr se trouve en dehors de l'espace d'adressage du processus.

NORMES

Linux/x86-64.

NOTES

arch_prctl() n'est actuellement pris en charge que sur Linux/x86-64 pour les programmes 64 bits.

La base 64 bits change lorsqu'un nouveau sélecteur de segment 32 bits est chargé.

ARCH_SET_GS est désactivé dans certains noyaux.

Les changements de contexte pour les bases de segment 64 bits sont plutôt coûteux. En guise d'optimisation, si une adresse de base TLS 32 bits est utilisée, arch_prctl() peut utiliser une entrée TLS réelle comme si set_thread_area(2) avait été appelé, au lieu de manipuler directement le registre de base de segment. De la mémoire dans les 2 premiers Go de l'espace d'adressage peut être allouée en utilisant mmap(2) avec le drapeau MAP_32BIT .

En raison de l'optimisation susmentionnée, l'utilisation de arch_prctl() et set_thread_area(2) dans le même fil d'exécution est dangereuse, car ils peuvent écraser mutuellement leurs entrées TLS.

FS peut déjà être utilisé par la bibliothèque de gestion des fils d'exécution. Les programmes qui utilisent ARCH_SET_FS directement sont très susceptibles de planter.

VOIR AUSSI

mmap(2), modify_ldt(2), prctl(2), set_thread_area(2)
