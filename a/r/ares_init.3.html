ARES_INIT_OPTIONS(3) Manuel des fonctions de bibliothèque ARES_INIT_OPTIONS(3)

NOM

ares_init_options, ares_init - Initialiser un canal de résolution

SYNOPSIS

#include <ares.h>
struct ares_server_failover_options {
  unsigned short retry_chance;
  size_t retry_delay;
};
struct ares_options {
  int flags;
  int timeout; /* en secondes ou millisecondes, selon les options */
  int tries;
  int ndots;
  unsigned short udp_port;
  unsigned short tcp_port;
  int socket_send_buffer_size;
  int socket_receive_buffer_size;
  struct in_addr *servers;
  int nservers;
  char **domains;
  int ndomains;
  char *lookups;
  ares_sock_state_cb sock_state_cb;
  void *sock_state_cb_data;
  struct apattern *sortlist;
  int nsort;
  int ednspsz;
  char *resolvconf_path;
  char *hosts_path;
  int udp_max_queries;
  int maxtimeout; /* en millisecondes */
  unsigned int qcache_max_ttl; /* en secondes */
  ares_evsys_t evsys;
  struct ares_server_failover_options server_failover_opts;
};
int ares_init_options(ares_channel_t **channelptr,
                      const struct ares_options *options,
                      int optmask);
int ares_init(ares_channel_t **channelptr);

DESCRIPTION

La fonction ares_init(3) est équivalente à un appel à ares_init_options(channelptr, NULL, 0). Il est recommandé d'utiliser plutôt ares_init_options(3) et de définir ou de rendre configurables les options appropriées pour votre application.

La fonction ares_init_options(3) initialise un canal de communication pour les recherches de services de noms. Si elle renvoie un succès, ares_init_options(3) définira la variable pointée par channelptr vers un handle utilisé pour identifier le canal de services de noms. L'appelant doit invoquer ares_destroy(3) sur le handle lorsque le canal n'est plus nécessaire.

Il est recommandé pour une application de n'avoir qu'un seul canal ares et de l'utiliser pour toutes les requêtes DNS pendant la durée de vie de l'application. Lorsque la configuration système change, ares_reinit(3) peut être appelée pour recharger la configuration si nécessaire. La limite recommandée de requêtes concurrentes est d'environ 32k requêtes, mais il faut se rappeler que lors de la spécification de AF_UNSPEC pour ares_getaddrinfo(3) ou ares_gethostbyname(3), elles peuvent générer 2 requêtes en interne. La raison de la limite est que c-ares ne permet pas que des identifiants de requête DNS dupliqués (qui ont un maximum de 64k) soient en attente à un moment donné, et il doit rechercher aléatoirement un identifiant disponible, donc 32k limitera le nombre de recherches. Cette limitation ne devrait pas être un problème pour la plupart des implémentations et c-ares pourrait implémenter une mise en file d'attente dans les futures versions pour lever cette limitation.

Le paramètre optmask spécifie généralement quels champs de la structure pointée par options sont définis, comme suit :

ARES_OPT_FLAGS
int flags;
Indicateurs contrôlant le comportement du résolveur :
ARES_FLAG_USEVC
Utiliser toujours les requêtes TCP (le « circuit virtuel ») au lieu des requêtes UDP. Normalement, le TCP n'est utilisé que si une requête UDP donne un résultat tronqué.
ARES_FLAG_PRIMARY
Interroger uniquement le premier serveur dans la liste des serveurs à interroger.
ARES_FLAG_IGNTC
Si une réponse tronquée à une requête UDP est reçue, ne pas revenir au TCP ; continuer simplement avec la réponse tronquée.
ARES_FLAG_NORECURSE
Ne pas définir le bit « récursion désirée » sur les requêtes sortantes, de sorte que le serveur de noms contacté n'essaie pas d'obtenir la réponse d'autres serveurs s'il ne connaît pas la réponse localement. Soyez conscient que ares ne fera pas la récursion pour vous. La récursion doit être gérée par l'application appelant ares si ARES_FLAG_NORECURSE est défini.
ARES_FLAG_STAYOPEN
Ne pas fermer les sockets de communication lorsque le nombre de requêtes actives tombe à zéro.
ARES_FLAG_NOSEARCH
Ne pas utiliser les domaines de recherche par défaut ; interroger uniquement les noms d'hôte tels quels ou comme alias.
ARES_FLAG_NOALIASES
Ne pas tenir compte de la variable d'environnement HOSTALIASES, qui spécifie normalement un fichier de traductions de noms d'hôte.
ARES_FLAG_NOCHECKRESP
Ne pas rejeter les réponses avec le code de réponse SERVFAIL, NOTIMP ou REFUSED ou les réponses dont les questions ne correspondent pas aux questions de la requête. Principalement utile pour écrire des clients qui pourraient être utilisés pour tester ou déboguer des serveurs de noms.
ARES_FLAG_EDNS
Inclure un enregistrement pseudo-ressource EDNS (RFC 2671) dans les requêtes générées. À partir de la v1.22, c'est activé par défaut si les indicateurs ne sont pas définis autrement.
ARES_FLAG_NO_DFLT_SVR
Ne pas tenter d'ajouter un serveur local par défaut s'il n'y a pas d'autres serveurs disponibles. Au lieu de cela, échouer l'initialisation avec ARES_ENOSERVER.
ARES_FLAG_DNS0x20
Activer le support de DNS 0x20 conformément à https://datatracker.ietf.org/doc/html/draft-vixie-dnsext-dns0x20-00 qui ajoute une entropie supplémentaire à la requête en randomisant la casse du nom de la requête. Les intégrateurs doivent s'assurer qu'ils traitent les réponses de noms DNS comme étant insensibles à la casse. Dans de rares cas, cela peut entraîner l'impossibilité de rechercher certains domaines si le serveur en amont ou le serveur faisant autorité pour le domaine n'est pas conforme.
ARES_OPT_TIMEOUT
int timeout;
Le nombre de secondes accordé à chaque serveur de noms pour répondre à une requête lors de la première tentative. Voir ARES_OPT_TIMEOUTMS dans lequel cette valeur est convertie.
ARES_OPT_TIMEOUTMS
int timeout;
Le nombre de millisecondes accordé à chaque serveur de noms pour répondre à une requête lors de la première tentative de connexion à un serveur donné. La valeur par défaut est de deux secondes, cependant toute valeur inférieure à 250 ms sera automatiquement définie à 250 ms (environ le RTT à mi-chemin autour du monde). Notez que cette option est spécifiée avec le même champ de structure que l'ancien ARES_OPT_TIMEOUT, c'est mais les bits d'option qui indiquent à c-ares comment interpréter le nombre. Cette option a été ajoutée dans c-ares 1.5.2.

À partir de c-ares 1.32.0, cette option n'est honorée que lors de la première requête réussie vers un serveur donné, après quoi le délai d'attente est automatiquement calculé en fonction de l'historique des requêtes précédentes.

ARES_OPT_TRIES
int tries;
Le nombre de tentatives que le résolveur tentera de contacter chaque serveur de noms avant d'abandonner. La valeur par défaut est de trois tentatives.
ARES_OPT_NDOTS
int ndots;
Le nombre de points qui doivent être présents dans un nom de domaine pour qu'il soit interrogé « tel quel » avant d'être interrogé avec les extensions de domaine par défaut ajoutées. La valeur par défaut est 1, sauf si elle est définie autrement par resolv.conf ou la variable d'environnement RES_OPTIONS. La plage valide est 0-15.
ARES_OPT_MAXTIMEOUTMS
int maxtimeout;
La limite supérieure pour le délai entre les tentatives de nouvelle requête séquentielles. Lors de la nouvelle tentative des requêtes, le délai est augmenté par rapport au paramètre de délai demandé, ceci limite la valeur.
ARES_OPT_UDP_PORT
unsigned short udp_port;
Le port à utiliser pour les requêtes sur UDP, en ordre d'octets hôte. La valeur par défaut est 53, le port standard des services de noms.
ARES_OPT_TCP_PORT
unsigned short tcp_port;
Le port à utiliser pour les requêtes sur TCP, en ordre d'octets hôte. La valeur par défaut est 53.
ARES_OPT_SOCKET_SEND_BUFFER_SIZE
int socket_send_buffer_size;
La taille du tampon d'envoi du socket. La valeur par défaut est la taille par défaut du système.
ARES_OPT_SOCKET_RECV_BUFFER_SIZE
int socket_receive_buffer_size;
La taille du tampon de réception du socket. La valeur par défaut est la taille par défaut du système.
ARES_OPT_SERVERS
struct in_addr *servers;
int nservers;
Un tableau d'adresses IP de serveurs de noms à interroger. La valeur de servers est copiée par ares. La valeur de nservers est le nombre d'entrées dans le tableau servers. Si servers est NULL, alors ares essaiera de lire la liste des serveurs à partir de /etc/resolv.conf.
ARES_OPT_DOMAINS
char **domains;
int ndomains;
Un tableau de chaînes de caractères spécifiant les domaines de recherche. La valeur de domains est copiée par ares. La valeur de ndomains est le nombre d'entrées dans le tableau domains. Si domains est NULL, alors ares essaiera de lire la liste des domaines à partir de /etc/resolv.conf.
ARES_OPT_LOOKUPS
char *lookups;
Une chaîne de caractères spécifiant la liste des services de recherche à utiliser, par exemple "b hosts files". Si cette chaîne est NULL, alors ares utilisera "b files" par défaut.
ARES_OPT_SOCK_STATE_CB
ares_sock_state_cb sock_state_cb;
void *sock_state_cb_data;
Une fonction de rappel qui sera appelée lorsque l'état d'un socket change (par exemple, lorsqu'un socket devient prêt pour la lecture ou l'écriture). Le deuxième paramètre est un pointeur de données fourni par l'application qui sera passé à la fonction de rappel. Cette option est utile pour intégrer ares dans une boucle d'événements.
ARES_OPT_SORTLIST
struct apattern *sortlist;
int nsort;
Un tableau d'adresses et de masques de réseau qui spécifie l'ordre dans lequel les adresses IP doivent être retournées pour un nom d'hôte donné. Ceci est utilisé pour trier les résultats de ares_getaddrinfo(3). La valeur de sortlist est copiée par ares. La valeur de nsort est le nombre d'entrées dans le tableau sortlist. Si sortlist est NULL, alors ares essaiera de lire la liste de tri à partir de /etc/gai.conf.
ARES_OPT_EDNSPSZ
int ednspsz;
La taille du tampon EDNS (Extension Mechanisms for DNS) à utiliser pour les requêtes DNS. La valeur 0 désactive EDNS. La valeur par défaut est 0.
ARES_OPT_RESOLVCONF_PATH
char *resolvconf_path;
Le chemin du fichier de configuration du résolveur à lire (par exemple, /etc/resolv.conf). Si NULL, alors ares utilisera le chemin par défaut.
ARES_OPT_HOSTS_PATH
char *hosts_path;
Le chemin du fichier hosts à lire (par exemple, /etc/hosts). Si NULL, alors ares utilisera le chemin par défaut.
ARES_OPT_UDP_MAX_QUERIES
int udp_max_queries;
Le nombre maximum de requêtes UDP qui peuvent être envoyées à un serveur de noms donné avant que les requêtes suivantes ne soient envoyées sur TCP. La valeur par défaut est de 20.
ARES_OPT_MAXTIMEOUTMS
int maxtimeout;
La limite supérieure pour le délai entre les tentatives de nouvelle requête séquentielles. Lorsque l'on re-tente des requêtes, le délai augmente par rapport au paramètre de délai demandé, ceci limite la valeur.
ARES_OPT_CACHETTL
unsigned int qcache_max_ttl;
La durée de vie maximale (TTL) des enregistrements mis en cache. Les enregistrements mis en cache avec une TTL supérieure à cette valeur seront tronqués à cette valeur. La valeur par défaut est de 1 heure.
ARES_OPT_EV_SYS
ares_evsys_t evsys;
Le système d'événements à utiliser. Les valeurs possibles sont ARES_ETIMER_FD, ARES_ETIMER_ONLY, ARES_EPOLL, ARES_KQUEUE, ARES_POLL, ARES_SELECT. Si cette option n'est pas définie, ares essaiera de deviner le meilleur système d'événements disponible.
ARES_OPT_SERVER_FAILOVER
struct ares_server_failover_options server_failover_opts;
Options pour la bascule de serveur. Lorsque le serveur principal échoue, c-ares peut basculer vers des serveurs secondaires. La bascule se fait avec une certaine probabilité et un délai.

La valeur de optmask est un masque de bits indiquant quels champs dans la structure options sont définis. Par exemple, si vous souhaitez définir les indicateurs et le délai d'attente, vous utiliseriez |ARES_OPT_FLAGS |ARES_OPT_TIMEOUT.

Si options est NULL, alors ares essaiera de lire la configuration à partir de /etc/resolv.conf.

La fonction ares_init_options(3) renvoie ARES_SUCCESS en cas de succès, ou un code d'erreur c-ares en cas d'échec.

unsigned int qcache_max_ttl;
Depuis c-ares 1.31.0, le cache de requêtes est activé par défaut avec un TTL de 1 heure. Pour désactiver le cache de requêtes, spécifiez cette option avec un TTL de 0. Le cache de requêtes est basé sur le TTL retourné dans le message DNS. Seuls les résultats de requêtes entièrement réussis et NXDOMAIN seront mis en cache. Remplissez qcache_max_ttl avec le nombre maximal de secondes pendant lesquelles un résultat de requête peut être mis en cache, ce qui remplacera un TTL plus grand dans le message de réponse. Cela doit être une valeur non nulle, sinon le cache sera désactivé. Choisissez une valeur raisonnable pour votre application, comme 300 (5 minutes) ou 3600 (1 heure). Le cache de requêtes est automatiquement vidé si une modification de la configuration des serveurs est effectuée.

ARES_OPT_SERVER_FAILO
VER
struct ares_server_failover_options server_failover_opts;
Configure le comportement de nouvelle tentative en cas de basculement de serveur. Lorsqu'un serveur DNS ne répond pas à une requête, c-ares dépriorisera le serveur. Lors des requêtes suivantes, les serveurs avec moins d'échecs consécutifs seront sélectionnés de préférence. Cependant, afin de détecter quand un tel serveur s'est rétabli, c-ares retentera occasionnellement les serveurs en échec en envoyant une copie de la requête, sans affecter la latence de la requête réellement demandée. La structure ares_server_failover_options contient des options pour contrôler ce comportement. Le champ retry_chance donne la probabilité (1/N) de réessayer un serveur en échec sur une requête donnée. Le définir à 0 désactive les nouvelles tentatives. Le champ retry_delay donne le délai minimum en millisecondes que c-ares attendra avant de réessayer un serveur en échec spécifique. Si cette option n'est pas spécifiée, c-ares utilisera une probabilité de 10 % et un délai minimum de 5 secondes.

Le paramètre optmask inclut également des options sans champ correspondant dans la structure ares_options, comme suit

:

résolution.
ARES_OPT_NOROT

Lors de l'initialisation à partir de /etc/resolv.conf (ou, alternativement lorsqu'il est spécifié par l'emplacement du chemin resolvconf_path), ares_init_options(3) et ares_init(3) lisent les directives domain et search pour permettre la recherche de noms courts relatifs aux domaines spécifiés. Les directives domain et search se remplacent l'une l'autre. Si plus d'une instance de l'une ou l'autre des directives domain ou search est spécifiée, la dernière occurrence l'emporte.
