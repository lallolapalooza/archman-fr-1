DESCRIPTIO

N

Argtable est une bibliothèque ANSI C pour l'analyse des arguments de ligne de commande de style GNU avec un minimum de tracas. Elle permet au programmeur de définir la syntaxe des arguments de son programme directement dans le code source sous forme d'un tableau de structures. La ligne de commande est ensuite analysée selon cette spécification et les valeurs résultantes sont stockées directement dans des variables de programme définies par l'utilisateur, où elles sont accessibles au programme

principal.

Cette page manuelle sert uniquement de référence. La documentation d'introduction et le code source d'exemple sont généralement installés sous /usr/share/doc/argtable2/ et sont également disponibles sur la page d'accueil d'argtable à http://argtable.sourc

eforge.net.

Construction d'une structure de données

arg_<xxx>

Chaque structure arg_<xxx> possède son propre ensemble unique de fonctions constructrices (définies ci-dessus) qui sont généralement de la forme

: 
struct arg_int* arg_int0("f", "foo", "<int>", "the foo factor")
struct arg_int* arg_int1("f", "foo", "<int>", "the foo factor")
struct arg_int* arg_intn("f", "foo", "<int>", 2, 4, "the foo
factor")

où arg_int0() et arg_int1() sont simplement des formes abrégées de arg_intn(). Elles sont fournies par commodité lors de la définition d'options de ligne de commande ayant soit zéro ou une occurrence (mincount=0,maxcount=1) soit exactement une occurrence (mincount=1,maxcount=1)

respectivement.

Le paramètre shortopts="f" définit l'étiquette de forme courte de l'option (par ex. -f). Plusieurs étiquettes alternatives peuvent être définies en les concaténant (par ex. shortopts="abc" définit les options -a, -b et -c comme équivalentes). Spécifiez shortopts=NULL lorsqu'aucune option courte n'est

requise.

Le paramètre longopts="foo" définit l'étiquette de forme longue de l'option (par ex. --foo). Plusieurs étiquettes alternatives de forme longue peuvent être séparées par des virgules (par ex. longopts="size,limit" définit --size et --limit). N'incluez aucun espace blanc dans la chaîne longopts. Spécifiez longopts=NULL lorsqu'aucune option longue n'est

requise.

Si shortopts et longopts sont tous deux NULL, alors l'option est un argument sans

étiquette.

Le paramètre datatype="<int>" est une chaîne descriptive qui désigne le type de données de l'argument dans les messages d'erreur, comme dans --foo=<int>. Spécifier datatype=NULL indique que le type de données par défaut doit être utilisé. Spécifier datatype="" désactive effectivement l'affichage du type de

données.

Les paramètres mincount=2 et maxcount=3 spécifient le nombre minimum et maximum d'occurrences de l'option sur la ligne de commande. Si l'option de ligne de commande n'apparaît pas le nombre de fois requis, alors l'analyseur signale une erreur de

syntaxe.

Le paramètre glossary="the foo factor" est une autre chaîne descriptive. Elle n'apparaît que dans la table du glossaire qui est générée automatiquement par la fonction arg_print_glossary (décrite plus tard)

.
-f, --foo=<int> the foo factor

Spécifier une chaîne glossary

NULL fait omettre cette option
de la table du glossaire.

à la con

OPTIONS DE LIGNE DE COMMANDE

ENTIÈRES

-x2, -z 32MB, --size=734kb, --hex 0x7, --binary 0b10011010, --octal

0o123

Argtable accepte les entiers de ligne de commande en décimal (par ex. 123), hexadécimal (par ex. 0xFF12), octal (par ex. 0o123) et binaire (par ex. 0b0101110) formats. Elle accepte également les entiers suffixés par "KB" (x1024), "MB" (x1048576) ou "GB" (x1073741824). Tous les caractères sont insensibles à la

casse 
struct arg_int
   {
   struct arg_hdr hdr;  /* en-tête argtable interne */
   int count;           /* nombre de valeurs retournées dans ival[] */
   int *ival;           /* tableau des valeurs entières analysées */
   }
;

Après une analyse réussie, count est garanti d'être dans les limites de mincount et maxcount définies pour l'option à la construction avec les valeurs appropriées stockées dans le tableau ival. L'analyseur n'acceptera aucune valeur au-delà dehat

limit.

Astuce : il est légal de définir des valeurs par défaut dans le tableau ival avant d'appeler la fonction arg_parse. Argtable ne modifiera pas les entrées ival pour lesquelles aucun argument de ligne de commande n'est

reçu.

Astuce : Les arguments numériques non étiquetés ne sont pas recommandés car GNU getopt confond les valeurs négatives (par ex. -123) avec des options étiquetées (par ex. -1 -2 -3). Les arguments étiquetés (par ex. -x -123, --t

ag=-123) ne souffrent p
as de ce problème.

struct arg_str
   {
   struct arg_hdr hdr;  /* en-tête interne d'argtable */
   int count;           /* nombre de chaînes retournées dans sval[] */
   const char **sval;   /* tableau de pointeurs vers les chaînes d'arguments analysées */
   }
;

Identique à arg_int sauf que les pointeurs vers les chaînes analysées sont retournés dans sval plutôt qu'une copie distincte de la chaîne. En effet, ces pointeurs référencent en réalité les tampons de chaînes d'origine stockés dans argv[], leur contenu ne doit donc pas être modifié. Cependant, il est légal d'initialiser les pointeurs de chaînes dans le tableau sval pour qu'ils référencent des chaînes par défaut fournies par l'utilisateur avant d'appeler arg_parse. Argtable ne modifiera le contenu de sval que lorsqu'il détecte des argumen

ts de ligne de comma
nde correspondants.

OPTIONS DE LIGNE DE COMMANDE D'EXPRESSIONS

RÉGULIÈRES

commit, update, --command=commit, --command=updat

e 
struct arg_rex
   {
   struct arg_hdr hdr;  /* en-tête interne d'argtable */
   int count;           /* nombre de chaînes retournées dans sval[] */
   const char **sval;   /* tableau de pointeurs vers les chaînes d'arguments analysées */
   }
;

Similaire à arg_str sauf que les valeurs d'arguments de chaîne ne sont acceptées que si elles correspondent à une expression régulière prédéfinie. Les expressions régulières sont utiles pour faire correspondre des mots-clés de ligne de commande, en particulier si des chaînes insensibles à la casse ou des motifs sont requis. L'expression régulière est définie par le paramètre pattern passé au constructeur arg_rex et évaluée à l'aide de regex. Son comportement peut être contrôlé via les drapeaux de bits standard de regex. Ceux-ci sont passés à argtable via le paramètre flags dans le constructeur arg_rex. Cependant, seuls deux des drapeaux de regex standard sont pertinents pour argtable, à savoir REG_EXTENDED (utiliser les expressions régulières étendues plutôt que les basiques) et REG_ICASE (ignorer la casse). Ces drapeaux peuvent être combinés par un OU logique si souhaité. Voir regex(3) pour plus de détails sur la correspondance d'expressions

régulières.

Restrictions : Argtable ne prend pas en charge la fonctionnalité arg_rex sous les plateformes Microsoft Windows car les compilateurs Microsoft n'incluent pas le support de regex néc

essaire p
ar défaut.

OPTIONS DE LIGNE DE COMMANDE DE NOM DE

FICHIER

-o myfile, -Ihome/foo/bar, --input=~/doc/letter.txt, --name a.

out 
struct arg_file
   {
   struct arg_hdr hdr;      /* en-tête interne d'argtable */
   int count;               /* nombre de chaînes de noms de fichiers retournées */
   const char **filename;   /* pointeur vers la chaîne du nom de fichier complet */
   const char **basename;   /* pointeur vers le nom de fichier sans le chemin initial */
   const char **extension;  /* pointeur vers l'extension du nom de fichier */
   }
;

Similaire à arg_str mais on suppose que les chaînes d'arguments se réfèrent à des noms de fichiers ; un analyse supplémentaire est donc effectuée pour séparer le nom de base et l'extension du nom de fichier (s'ils existent). Les trois tableaux filename[], basename[], extension[] stockent chacun jusqu'à maxcount entrées, et la ième entrée de chacun de ces tableaux se réfère à des composants différents du même tampon de

chaîne.

Par exemple, -o /home/heitmann/mydir/foo.txt serait analysé comme : 

filename[i]  = "/home/heitmann/mydir/foo.txt"
basename[i]  =                      "foo.txt"
extension[i] =                         ".
txt"

Si le nom de fichier n'a pas de chemin initial, le nom de base est le même que le nom de fichier. Si aucune extension n'a pu être identifiée, elle est donnée comme NULL. Les extensions sont considérées comme tout le texte à partir du dernier point dans le nom de

fichier.

Astuce : Argtable ne traite les noms de fichiers que comme de

s chaînes et n'essaie jamais de les ouvrir en tant que f
ichiers ni d'effectuer des recherches de répertoires sur eux.

struct arg_date
   {
   struct arg_hdr hdr;  /* en-tête interne d'argtable */
   const char *format;  /* chaîne de format de date fournie par l'utilisateur et passée au constructeur */
   int count;           /* nombre d'horodatages retournés dans tmval[] */
   struct tm *tmval;    /* tableau d'horodatages */
   }
;

Accepte une chaîne d'horodatage depuis la ligne de commande et la convertit au format struct tm à l'aide de la fonction système strptime. Le format de l'heure est défini par la chaîne de format passée au constructeur arg_date et est passée directement à strptime. Voir strptime(3) pour plus de détails sur la chaîne de

format.

Restrictions : Argtable ne prend pas en charge la fonctionnalité arg_date sous Microsoft Windows car les compilateurs Microsoft n'incluent pas le support de strptime n

écessaire p
ar défaut.

OPTIONS DE

REMARQUE 
struct arg_rem
   {
   struct arg_hdr hdr;  /* en-tête interne d'argtable */
   }
;

La struct arg_rem est une structure factice en ce sens qu'elle ne représente pas une option de ligne de commande à analyser. Elle fournit plutôt un moyen d'inclure des chaînes de type de données et de glossaire dans la sortie des fonctions arg_print_syntax, arg_print_syntaxv et arg_print_glossary. En tant que telles, les structures arg_rem peuvent être utilisées dans la table d'arguments pour insérer des lignes de texte supplémentaires dans

les descriptions du glossaire ou pour insérer des champs d
e texte supplémentaires dans la description de la syntaxe.

OPTION DE FIN DE

TABLE 
struct arg_end
   {
   struct arg_hdr hdr;  /* en-tête interne d'argtable */
   int count;           /* nombre d'erreurs retournées */
   int *error;          /* tableau des codes d'erreur */
   void **parent;       /* pointeurs vers les options de ligne de commande erronées */
   const char **argval; /* pointeurs vers les valeurs d'arguments de ligne de commande erronées */
   }
; 
Chaque table d'arguments doit avoir une structure arg_end comme dernière entrée.
Elle marque la fin d'une table d'arguments et stocke les codes d'erreur générés
par l'analyseur lors du traitement de la table d'arguments.
Le paramètre maxerrors passé au constructeur arg_end
spécifie le nombre maximal d'erreurs que la structure peut stocker.
Toute erreur supplémentaire est ignorée et remplacée par le seul code d'erreur
ARG_ELIMIT qui est ensuite signalé à l'utilisateur par le message "too many errors".
Une limite maxerrors de 20 est tout à fait
raisonnable. 
La fonction arg_print_errors imprimera les erreurs stockées dans la struct arg_end dans le même ordre que leur survenue,
il n'est donc pas nécessaire de comprendre les détails internes de la struct
ar
g_e
nd.

int arg_nullcheck (void

**argtable)

Retourne une valeur non nulle si le tableau argtable[] contient des entrées NULL jusqu'à l'entrée terminatrice arg_end*. Retourn

e zéro
sinon.

int arg_parse (int argc, char **argv, void

**argtable)

Analyse les arguments de la ligne de commande dans argv[] en utilisant la syntaxe de ligne de commande spécifiée dans argtable[], en retournant le nombre d'erreurs rencontrées. Les détails des erreurs sont enregistrés dans la structure arg_end de la table d'arguments, d'où ils peuvent être affichés plus tard avec la fonction arg_print_errors. Lors d'une analyse réussie, les structures arg_xxx référencées dans argtable[] contiendront les valeurs d'a

rguments extraites de
la ligne de commande.

void arg_print_option (FILE *fp, const char *shortopts, const char *longopts, const char *datatype, const char

*suffix)

Cette fonction imprime la syntaxe d'une option, comme dans -K|--scalar=<int>, où les options courtes, les options longues et le type de données sont tous donnés en paramètres de cette fonction. Elle est principalement utilisée dans les fonctions errorfn des structures arg_xxx comme moyen d'afficher la syntaxe d'une option à l'intérieur des messages d'erreur. Cependant, elle peut aussi être utilisée dans le code de l'utilisateur si souhaité. La chaîne suffix est fournie pour faciliter l'ajout de retours à la ligne et ainsi de

suite à la fin de l'affichage et peut être
donnée comme NULL si elle n'est pas requise.

void arg_print_syntax (FILE *fp, void **argtable, const char

*suffix)

Imprime la syntaxe de ligne de commande de style GNU pour la table d'arguments donnée, comme suit : [-abcv] [--scalar=<n>] [-o myfile] <file> [<file>]
La chaîne suffix est fournie pour faciliter l'ajout de retours à la ligne et ainsi de

suite à la fin de l'affichage et peut être
donnée comme NULL si elle n'est pas requise.

void arg_print_syntax_hint (FILE *fp, void **argtable)

Prints a brief, human-readable description of the command line syntax for the given argument table, as in: [-a] [-b] [-c] [--scalar=<n>] [-o myfile] [-v|--verbose] <file> [<file>]

void arg_print_syntax_hint_arg (FILE *fp, void **argtable)

Similar to arg_print_syntax_hint() but includes explicit argument names where appropriate, such as: [-a NAME] [-b] [-c] [--scalar=<n>] [-o FILE] [-v|--verbose] <file> [<file>]

void arg_print_syntax_hint_gnu (FILE *fp, void **argtable)

Similar to arg_print_syntax_hint() but uses GNU formatting conventions, aligning long options in a second column and wrapping lines at 80 characters.

void arg_print_syntaxv (FILE *fp, void **argtable, const char *suffix)

Prints the verbose form of the command line syntax for the given argument table, as in: [-a] [-b] [-c] [--scalar=<n>] [-o myfile] [-v|--verbose] <file> [<file>]
The suffix string is provided as a convenience for appending newlines and so forth to the end of the display and can be given as NULL if not required.

void arg_print_glossary (FILE *fp, void **argtable, const char *format)

Prints a glossary table describing each option in the given argument table. The format string is passed to printf to control the formatting of each entry in the the glossary. It must have exactly two " %s" format parameters as in " %-25s %s\n", the first is for the option's syntax and the second for its glossary string. If an option's glossary string is NULL then that option in omitted from the glossary display.

void arg_print_glossary_gnu (FILE *fp, void **argtable)

An alternate form of arg_print_glossary() that prints the glossary using strict GNU formatting conventions wherein long options are vertically aligned in a second column, and lines are wrapped at 80 characters.

void arg_print_errors (FILE *fp, struct arg_end *end, const char *progname)

Prints the details of all errors stored in the end data structure. The progname string is prepended to each error message.

void arg_freetable (void ** argtable, size_t n)

Deallocates the memory used by each arg_xxx struct referenced by argtable[]. It does this by calling free for each of the n pointers in the argtable array and then nulling them for safety.
