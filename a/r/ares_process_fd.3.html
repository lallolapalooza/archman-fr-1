ares_process_fd(3)

Paquet: c-ares

Licences: MIT

ARES_PROCESS(3) Manuel des fonctions de bibliothèque ARES_PROCESS(3)

NOM

ares_process_fds, ares_process_fd, ares_process - Traiter les événements de résolution de noms

SYNOPSIS

#include <ares.h>
/*! Événements utilisés par ares_fd_events_t */
typedef enum {
  ARES_FD_EVENT_NONE  = 0,      /*!< Aucun événement */
  ARES_FD_EVENT_READ  = 1 << 0, /*!< Événement de lecture (y compris déconnexion/erreur) */
  ARES_FD_EVENT_WRITE = 1 << 1  /*!< Événement d'écriture */
} ares_fd_eventflag_t;
/*! Type contenant un descripteur de fichier et un masque d'événements, utilisé par
 *  ares_process_fds() */
typedef struct {
  ares_socket_t fd;     /*!< Descripteur de fichier */
  unsigned int  events; /*!< Masque de ares_fd_event_t */
} ares_fd_events_t;
typedef enum {
  ARES_PROCESS_FLAG_NONE        = 0,
  ARES_PROCESS_FLAG_SKIP_NON_FD = 1 << 0
} ares_process_flag_t;
ares_status_t ares_process_fds(ares_channel_t         *channel,
                               const ares_fd_events_t *events,
                               size_t                  nevents,
                               unsigned int            flags)
void ares_process_fd(ares_channel_t *channel,
                     ares_socket_t read_fd,
                     ares_socket_t write_fd)
void ares_process(ares_channel_t *channel,
                  fd_set *read_fds,
                  fd_set *write_fds)

DESCRIPTION

Ces fonctions doivent être utilisées par les intégrateurs qui choisissent de ne pas utiliser l'EventThread activé via ARES_OPT_EVENT_THREAD passé à ares_init_options. Cela suppose que les intégrateurs ont déjà leur propre boucle d'événements gérant les notifications d'événements pour divers descripteurs de fichiers et souhaitent faire de même avec leur intégration de c-ares.

La fonction ares_process_fds(3) gère les événements d'entrée/sortie sur les descripteurs de fichiers et les délais d'attente associés aux requêtes en attente sur le canal identifié par channel. Les descripteurs de fichiers à traiter sont passés dans un tableau de structures de données ares_fd_events_t dans le membre fd, et les événements sont un masque binaire de ares_fd_eventflag_t dans le membre event. Cette fonction peut également être utilisée pour traiter les délais d'attente en passant NULL au tableau events avec une valeur nevents de 0. Des drapeaux peuvent également être spécifiés dans le champ flags et sont définis dans ares_process_flag_t.

ARES_PROCESS_FLAG_SKIP_NON_FD peut être spécifié pour ignorer spécifiquement tout traitement non lié aux événements de descripteurs de fichiers passés, par exemple le traitement des délais d'attente et la gestion du nettoyage. Ceci est utile si un intégrateur sait qu'il enverra plusieurs requêtes ares_process_fds(3) et souhaite ignorer ce traitement supplémentaire. Cependant, l'intégrateur doit envoyer la requête finale avec le drapeau afin que le délai d'attente et d'autres traitements soient effectués avant que sa boucle d'événements n'attende d'autres événements.

Il est acceptable d'utiliser une ares_fd_events_t avec le membre events ayant la valeur ARES_FD_EVENT_NONE (0) s'il n'y a pas d'événements pour un descripteur de fichier donné si un intégrateur souhaite simplement maintenir un tableau avec tous les descripteurs de fichiers possibles et mettre à jour la disponibilité via le membre event.

Cette fonction retournera ARES_ENOMEM en cas de manque de mémoire, sinon elle retournera ARES_SUCCESS.

Cette fonction est recommandée par rapport à ares_process_fd(3) car elle peut traiter plusieurs descripteurs de fichiers à la fois, évitant ainsi de répéter une logique supplémentaire telle que le traitement des délais d'attente qui serait nécessaire si on appelait ares_process_fd(3) pour plusieurs descripteurs de fichiers notifiés en même temps.

Cette fonction est généralement utilisée avec l'option ARES_OPT_SOCK_STATE_CB.

ares_timeout(3) doit être utilisé pour récupérer le délai d'attente souhaité, et lorsque le délai d'attente expire, l'intégrateur doit appeler ares_process_fds(3) avec un tableau events NULL. (ou ares_process_fd(3) avec les deux sockets définis sur ARES_SOCKET_BAD). Il n'est pas nécessaire de le faire si des événements sont également livrés pour des descripteurs de fichiers, car le traitement des délais d'attente sera automatiquement géré par tout appel à ares_process_fds(3) ou ares_process_fd(3).

La fonction ares_process_fd(3) est la même que ares_process_fds(3) sauf qu'elle ne peut traiter qu'un seul descripteur de fichier de lecture et un seul de lecture à la fois. Les nouveaux intégrateurs devraient utiliser ares_process_fds(3) si possible.

La fonction ares_process(3) fonctionne de la même manière, sauf qu'elle opère sur des fd_sets comme utilisé par select(3) et récupéré par ares_fds(3). Cette méthode est dépréciée et ne devrait pas être utilisée dans les applications modernes en raison des limitations connues de l'implémentation de select(3).

DISPONIBILITÉ

ares_process_fds(3) a été introduit dans c-ares 1.34.0.

VOIR AUSSI

ares_fds(3), ares_timeout(3), ares_init_options(3) avec ARES_OPT_EVENT_THREAD ou ARES_OPT_SOCK_STATE_CB
