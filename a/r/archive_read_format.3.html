DESCRIPTION

archive_read_support_format_7zip(), archive_read_support_format_ar(), archive_read_support_format_cab(), archive_read_support_format_cpio(), archive_read_support_format_iso9660(), archive_read_support_format_lha(), archive_read_support_format_mtree(), archive_read_support_format_rar(), archive_read_support_format_rar5(), archive_read_support_format_raw(), archive_read_support_format_tar(), archive_read_support_format_warc(), archive_read_support_format_xar(), archive_read_support_format_zip()
Active le support — y compris le code de détection automatique — pour le format d'archive spécifié. Par exemple, archive_read_support_format_tar() active le support pour une variété de formats tar standards, le format tar ancien, ustar, le format d'échange pax, et de nombreux variants courants. archive_read_support_format_zip() active le support pour les lecteurs zip en flux et ceux qui permettent la recherche, qui peuvent être activés séparément respectivement par archive_read_support_format_zip_streamable() et archive_read_support_format_zip_seekable()
archive_read_support_format_all()
Active le support pour tous les formats disponibles à l'exception du format « brut » (voir ci-dessous).
archive_read_support_format_by_code()
Active un seul format spécifié par son code. Ceci peut être utile lors de la lecture d'une archive unique à deux reprises ; utilisez archive_format() après la première lecture et passez le code résultant à cette fonction pour activer sélectivement uniquement le support du format nécessaire. Remarque : Dans les exécutables liés statiquement, cela entraînera l'inclusion dans votre programme du support de chaque format. Si la taille de l'exécutable est une préoccupation, vous pourriez souhaiter éviter d'utiliser cette fonction.
archive_read_support_format_empty()
Active le support pour traiter les fichiers vides comme des archives vides. Parce que les fichiers vides sont valides pour plusieurs formats différents, il n'est pas possible de déterminer avec précision un format pour un fichier vide basé uniquement sur son contenu. Ainsi, les fichiers vides sont traités par libarchive comme un format distinct.

archive_read_format(3) — libarchive — The C library for extracting and creating various archive formats

NAME

archive_read_format, archive_read_support_format_raw

LIBRARY

libarchive library

SYNOPSIS

#include <archive.h>
int archive_read_support_format_raw(struct archive *);

DESCRIPTION

The archive_read_support_format_raw() function enables support for reading data in the raw, uncompressed, unarchived format. This is equivalent to treating the entire input stream as a single file. This handler is not enabled by default with archive_read_support_format_all() in order to avoid erroneous handling of damaged archives.

The raw handler can be useful for handling data streams that are not archives at all, or for debugging purposes.

This function enables the raw handler for the archive object pointed to by a. Once enabled, if no other format handler successfully identifies the archive content, the raw handler will be used.

The raw handler allows libarchive to be used to read arbitrary data. It treats any data stream as an archive with a single entry. The pathname of this entry is “data”; all other entry fields are unset. This is not enabled by archive_read_support_format_all() in order to avoid erroneous handling of damaged archives.

RETURN VALUES

These functions return ARCHIVE_OK on success, or ARCHIVE_FATAL.

ERRORS

Detailed error codes and textual descriptions are available from the archive_errno() and archive_error_string() functions.

SEE ALSO

tar(1), archive_read_data(3), archive_read_filter(3), archive_read_set_options(3), archive_util(3), libarchive(3), tar(5)

BUGS

Many traditional archiver programs treat empty files as valid empty archives. For example, many implementations of tar(1) allow you to append entries to an empty file. Of course, it is impossible to determine the format of an empty file by inspecting the contents, so this library treats empty files as having a special “empty” format.

Using the “raw” handler together with any other handler will often work but can produce surprising results.
