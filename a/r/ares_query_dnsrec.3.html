ares_query_dnsrec(3)

Paquet: c-ares

Licences: MIT

ARES_QUERY(3) Manuel des fonctions de bibliothèque ARES_QUERY(3)

NOM

ares_query - Initier une requête DNS à question unique

SYNTAXE

#include <ares.h>
typedef void (*ares_callback_dnsrec)(void *arg, ares_status_t status,
                                     size_t timeouts,
                                     const ares_dns_record_t *dnsrec);
ares_status_t ares_query_dnsrec(ares_channel_t      *channel,
                                const char          *name,
                                ares_dns_class_t     dnsclass,
                                ares_dns_rec_type_t  type,
                                ares_callback_dnsrec callback,
                                void                *arg,
                                unsigned short      *qid);
typedef void (*ares_callback)(void *arg, int status,
                              int timeouts, unsigned char *abuf,
                              int alen);
void ares_query(ares_channel_t *channel, const char *name,
                int dnsclass, int type,
                ares_callback callback, void *arg);

DESCRIPTION

Les fonctions ares_query_dnsrec(3) et ares_query(3) initient une requête DNS à question unique sur le canal du service de noms identifié par channel. Le paramètre name donne le nom de la requête sous forme d'une chaîne C terminée par un octet nul, avec des labels séparés par des points, éventuellement terminés par un point ; les points et les antislashs dans un label doivent être échappés avec un antislash.

ares_query_dnsrec(3) utilise les types de données définis par ares ares_dns_class_t et ares_dns_rec_type_t. Cependant, ares_query(3) utilise les valeurs définies dans <arpa/nameser.h>.

Lorsque la requête est terminée ou a échoué, la bibliothèque ares appellera callback. L'achèvement ou l'échec de la requête peut se produire immédiatement (même avant le retour de l'appel de fonction), ou peut se produire lors d'un appel ultérieur à ares_process(3) ou ares_destroy(3).

Si cet appel est effectué depuis un thread autre que celui où la boucle d'événements principale du programme s'exécute, il faut veiller à ce que les listes de descripteurs de fichiers soient immédiatement mises à jour dans la boucle d'événements. Lorsque le rappel associé est appelé, il est appelé avec un verrouillage de canal, il faut donc veiller à ce que tout traitement soit minimal pour éviter les blocages du canal DNS.

L'argument de rappel arg est copié depuis l'argument arg de ares_query_dnsrec(3) ou ares_query(3). L'argument de rappel status indique si la requête a réussi et, sinon, pourquoi elle a échoué. Il peut prendre l'une des valeurs suivantes :

ARES_SUCCESS
La requête s'est terminée avec succès.
ARES_ENODATA
La requête s'est terminée mais ne contient aucune réponse.
ARES_EFORMERR
La requête s'est terminée mais le serveur prétend que la requête était mal formatée.
ARES_ESERVFAIL
La requête s'est terminée mais le serveur prétend avoir rencontré une erreur. (Ce code ne peut survenir que si le drapeau ARES_FLAG_NOCHECKRESP a été spécifié lors de l'initialisation du canal ; sinon, de telles réponses sont ignorées au niveau de ares_send_dnsrec(3).)
ARES_ENOTFOUND
La requête s'est terminée mais le nom de domaine recherché n'a pas été trouvé.
ARES_ENOTIMP
La requête s'est terminée mais le serveur n'implémente pas l'opération demandée par la requête. (Ce code ne peut survenir que si le drapeau ARES_FLAG_NOCHECKRESP a été spécifié lors de l'initialisation du canal ; sinon, de telles réponses sont ignorées au niveau de ares_send_dnsrec(3).)
ARES_EREFUSED
La requête s'est terminée mais le serveur a refusé la requête. (Ce code ne peut survenir que si le drapeau ARES_FLAG_NOCHECKRESP a été spécifié lors de l'initialisation du canal ; sinon, de telles réponses sont ignorées au niveau de ares_send_dnsrec(3).)
ARES_EBADNAME
Le nom de requête name n'a pas pu être encodé en tant que nom de domaine, soit parce qu'il contenait un label de longueur nulle, soit parce qu'il contenait un label de plus de 63 caractères.
ARES_ETIMEOUT
Aucun serveur de noms n'a répondu dans le délai imparti.
ARES_ECONNREFUSED
Aucun serveur de noms n'a pu être contacté.
ARES_ENOMEM
La mémoire a été épuisée.
ARES_ECANCELLED
La requête a été annulée.
ARES_EDESTRUCTION
Le canal du service de noms channel est en cours de destruction ; la requête ne sera pas complétée.
ARES_ENOSERVER
La requête ne sera pas complétée car aucun serveur DNS n'a été configuré sur le canal.

L'argument de rappel timeouts indique combien de fois une requête a expiré pendant l'exécution de la requête donnée.

Si la requête s'est terminée (même s'il y avait quelque chose qui n'allait pas, comme indiqué par certains des codes d'erreur ci-dessus), l'argument de rappel dnsrec ou abuf sera non NULL, sinon ils seront NULL.

DISPONIBILITÉ

ares_query_dnsrec(3) a été introduit dans c-ares 1.28.0.
