AR(1P) Manuel du programmeur POSIX AR(1P)

PROLOGUE

Cette page de manuel fait partie du Manuel du programmeur POSIX. L'implémentation Linux de cette interface peut différer (consultez la page de manuel Linux correspondante pour les détails du comportement Linux), ou l'interface peut ne pas être implémentée sous Linux.

NOM

ar — créer et maintenir des bibliothèques d'archives

SYNTAXE

ar -d [-v] archive fichier...
ar -m [-v] archive fichier...
ar -m -a [-v] posname archive fichier...
ar -m -b [-v] posname archive fichier...
ar -m -i [-v] posname archive fichier...
ar -p [-v] [-s] archive [fichier...]
ar -q [-cv] archive fichier...
ar -r [-cuv] archive fichier...
ar -r -a [-cuv] posname archive fichier...
ar -r -b [-cuv] posname archive fichier...
ar -r -i [-cuv] posname archive fichier...
ar -t [-v] [-s] archive [fichier...]
ar -x [-v] [-sCT] archive [fichier...]

DESCRIPTION

L'utilitaire ar fait partie de l'option Utilitaires de développement logiciel.

L'utilitaire ar peut être utilisé pour créer et maintenir des groupes de fichiers combinés dans une archive. Une fois qu'une archive a été créée, de nouveaux fichiers peuvent être ajoutés, et des fichiers existants dans une archive peuvent être extraits, supprimés ou remplacés. Lorsque une archive est entièrement composée de fichiers objets valides, l'implémentation doit formater l'archive de manière à ce qu'elle soit utilisable comme bibliothèque pour l'édition de liens (voir c99 et fort77). Lorsque certains des fichiers archivés ne sont pas des fichiers objets valides, l'aptitude de l'archive à être utilisée comme bibliothèque n'est pas définie. Si une archive est entièrement composée de fichiers imprimables, l'archive entière doit être imprimable.

Lorsque ar crée une archive, il crée des informations administratives indiquant si une table des symboles est présente dans l'archive. Lorsqu'il y a au moins un fichier objet que ar reconnaît comme tel dans l'archive, une table des symboles d'archive doit être créée dans l'archive et maintenue par ar ; elle est utilisée par l'éditeur de liens pour rechercher dans l'archive. Chaque fois que l'utilitaire ar est utilisé pour créer ou mettre à jour le contenu d'une telle archive, la table des symboles doit être reconstruite. L'option -s force la reconstruction de la table des symboles.

Tous les opérandes fichier peuvent être des chemins. Cependant, les fichiers dans les archives sont nommés par un nom de fichier, qui est la dernière composante du chemin utilisé lorsque le fichier a été entré dans l'archive. La comparaison des opérandes fichier avec les noms des fichiers dans les archives doit être effectuée en comparant la dernière composante de l'opérande au nom du fichier dans l'archive.

Il n'est pas spécifié si plusieurs fichiers dans l'archive peuvent avoir des noms identiques. Dans le cas de tels fichiers, cependant, chaque opérande fichier et posname ne doit correspondre qu'au premier fichier de l'archive portant un nom identique à la dernière composante de l'opérande.

OPTIONS

L'utilitaire ar doit être conforme au volume Définitions de base de POSIX.1‐2017, Section 12.2, Directives de syntaxe utilitaire, à l'exception de la Directive 9.

Les options suivantes doivent être prises en charge :

-a
Positionner les nouveaux fichiers dans l'archive après le fichier nommé par l'opérande posname.
-b
Positionner les nouveaux fichiers dans l'archive avant le fichier nommé par l'opérande posname.
-c
Supprimer le message de diagnostic qui est écrit sur la sortie standard d'erreur par défaut lorsque l'archive archive est créée.
-C
Empêcher les fichiers extraits de remplacer des fichiers portant le même nom dans le système de fichiers. Cette option est utile lorsque -T est également utilisé, pour empêcher que les noms de fichiers tronqués ne remplacent des fichiers portant le même préfixe.
-d
Supprimer un ou plusieurs fichiers de archive.
-i
Positionner les nouveaux fichiers dans l'archive avant le fichier de l'archive nommé par l'opérande posname (équivalent à -b).
-m
Déplacer les fichiers nommés dans l'archive. Les options -a, -b ou -i avec l'opérande posname indiquent la position ; sinon, déplacer les fichiers nommés dans l'archive à la fin de l'archive.
-p
Écrire le contenu des fichiers dans l'archive nommés par les opérandes file à partir de archive sur la sortie standard. Si aucun opérande fichier n'est spécifié, le contenu de tous les fichiers de l'archive doit être écrit dans l'ordre de l'archive.
-q
Ajouter les fichiers nommés à la fin de l'archive. Dans ce cas, ar ne vérifie pas si les fichiers ajoutés sont déjà dans l'archive. Ceci est utile pour contourner la recherche effectuée lors de la création d'une grande archive par morceaux.
-r
Remplacer ou ajouter des fichiers à archive. Si l'archive nommée par archive n'existe pas, une nouvelle archive sera créée et un message de diagnostic sera écrit sur la sortie standard d'erreur (sauf si l'option -c est spécifiée). Si aucun fichier n'est spécifié et que l'archive existe, les résultats ne sont pas définis. Les fichiers qui remplacent des fichiers existants dans l'archive ne doivent pas modifier l'ordre de l'archive. Les fichiers qui ne remplacent pas de fichiers existants dans l'archive seront ajoutés à l'archive à moins qu'une option -a, -b ou -i ne spécifie une autre position.
-s
Forcer la régénération de la table des symboles de l'archive, même si ar n'est pas invoqué avec une option qui modifie le contenu de l'archive. Cette option est utile pour restaurer la table des symboles de l'archive après qu'elle a été dépouillée ; voir strip.
-t
Écrire une table des matières de archive sur la sortie standard. Seuls les fichiers spécifiés par les opérandes fichier doivent être inclus dans la liste écrite. Si aucun opérande fichier n'est spécifié, tous les fichiers de l'archive doivent être inclus dans l'ordre de l'archive.
-T
Permettre la troncature des noms de fichiers pour les fichiers extraits dont les noms d'archive sont plus longs que ce que le système de fichiers peut supporter. Par défaut, l'extraction d'un fichier dont le nom est trop long doit être une erreur ; un message de diagnostic sera écrit et le fichier ne sera pas extrait.
-u
Mettre à jour les anciens fichiers dans l'archive. Lorsqu'elle est utilisée avec l'option -r, les fichiers dans l'archive ne seront remplacés que si le fichier correspondant a une heure de modification au moins aussi récente que l'heure de modification du fichier dans l'archive.
-v
Donner une sortie détaillée. Lorsqu'elle est utilisée avec les caractères d'option -d, -r ou -x, écrire une description détaillée fichier par fichier de l'activité de création et de maintenance de l'archive, comme décrit dans la section STDOUT.

Lorsqu'elle est utilisée avec -p, écrire le nom du fichier dans l'archive sur la sortie standard avant d'écrire le fichier de l'archive lui-même sur la sortie standard, comme décrit dans la section STDOUT.

Lorsqu'elle est utilisée avec -t, inclure une liste détaillée d'informations sur les fichiers de l'archive, comme décrit dans la section STDOUT.

-x
Extraire les fichiers dans l'archive nommés par les opérandes fichier à partir de archive. Le contenu de l'archive ne doit pas être modifié. Si aucun opérande fichier n'est donné, tous les fichiers de l'archive doivent être extraits. L'heure de modification de chaque fichier extrait doit être définie à l'heure à laquelle le fichier est extrait de l'archive.

OPÉRANDES

Les opérandes suivants doivent être pris en charge :

archive
Un chemin de l'archive.
file
Le nom d'un fichier à ajouter, à supprimer ou à extraire.
posname
Un nom de fichier existant dans l'archive. Utilisé avec les options -a, -b et -i pour indiquer la position à laquelle les nouveaux fichiers doivent être insérés.

où filename est le nom du fichier traité.

Lorsque l'option -p est spécifiée, la sortie suivante est écrite sur la sortie standard :

Si l'option -v n'est pas spécifiée, le contenu de chaque fichier spécifié par l'opérande file (ou tous les fichiers de l'archive si aucun opérande file n'est spécifié) est écrit sur la sortie standard. L'ordre d'écriture est celui des fichiers dans l'archive.

Si l'option -v est spécifiée, le nom du fichier est écrit sur la sortie standard, suivi d'un caractère de nouvelle ligne, puis le contenu du fichier est écrit sur la sortie standard. L'ordre est le même que lorsque -v n'est pas spécifié.

Lorsque l'option -t est spécifiée, la sortie suivante est écrite sur la sortie standard :

Si l'option -v n'est pas spécifiée, la liste des noms de fichiers de l'archive est écrite, un par ligne. L'ordre est celui des fichiers dans l'archive. Si des opérandes file sont spécifiés, seuls les fichiers correspondants sont inclus dans la liste.

Si l'option -v est spécifiée, la sortie est un listing détaillé similaire à celui produit par ls -l, avec le nom de fichier de l'archive en premier, suivi des champs de permission, du propriétaire, du groupe, de la taille, de la date de dernière modification et du nom de fichier.

Si aucune des options -d, -m, -p, -r, -t ou -x n'est spécifiée, l'effet est le même que si l'option -t avait été spécifiée.

La utilité ar est néanmoins incluse pour permettre la création d'archives destinées à être utilisées uniquement sur une seule machine. L'archive est spécifiée en tant que fichier, et elle peut être déplacée en tant que fichier. Cela permet donc de déplacer une archive d'une machine à une autre qui utilise la même implémentation de ar. Des utilitaires tels que pax (e

t

ses prédécesseurs tar et cpio) fournissent également des « archives » portables. Il ne s'agit pas d'une duplication ; l'utilité ar est incluse pour fournir une interface principalement pour make et les compilateurs, basée sur un modèle historique. Dans les

implémentations

historiques, l'option -q (disponible sur les systèmes conformes à XSI) est connue pour s'exécuter rapidement car ar ne vérifie pas si les membres ajoutés sont déjà dans l'archive. Cela est utile pour contourner la recherche autrement effectuée lors de la création d'une grande archive pièce par pièce. Ces remarques peuvent mais ne doivent pas nécessairement rester vraies pour une toute nouvelle implémentation de cette utilité ; par conséquent, ces remarques ont été déplacées dans

la

section JUSTIFICATION. Les implémentations BSD exigeaient historiquement que les applications fournissent l'option -s chaque fois que l'archive devait contenir une table de symboles. Comme dans ce volume de POSIX.1‐2017, System V crée ou met à jour historiquement une table de symboles d'archive chaque fois qu'un fichier objet est retiré de, ajouté à, ou

mis

à jour dans l'archive. La section OPÉRANDES exige ce qui pourrait sembler vrai sans le spécifier : l'archive ne peut pas tronquer les noms de fichiers en dessous de {NAME_MAX}. Certaines implémentations historiques le font cependant, causant des résultats inattendus pour l'application. Par conséquent, ce volume de POSIX.1‐2017 rend l'exigence explicite pour

éviter

les malentendus. Selon la documentation System V, les options -dmpqrtx ne sont pas tenues de commencer par un <hyphen-minus>( '-'). Ce volume de POSIX.1‐2017 exige qu'une application conforme utilise le <hyphen-minus>

initial.

Le format d'archive utilisé par l'implémentation 4.4 BSD est documenté dans cette section RATIONALE à titre d'exemple

:
Un fichier créé par ar commence par la chaîne « magique » "!<arch>\n". Le reste de l'archive est composé d'objets, chacun étant constitué d'un en-tête pour un fichier, d'un nom de fichier éventuel et du contenu du fichier. L'en-tête est portable entre les architectures machines et, si le contenu du fichier est imprimable, l'archive elle-même est imprimable.

L'en-tête est composé de six champs ASCII, suivis d'un en-tête de fin de deux caractères. Les champs sont le nom de l'objet (16 caractères), l'heure de dernière modification du fichier (12 caractères), les identifiants utilisateur et groupe (6 caractères chacun), le mode du fichier (8 caractères) et la taille du fichier (10 caractères). Tous les champs numériques sont en décimal, à l'exception du mode du fichier, qui est en

octal.

L'heure de modification est le champ st_mtime du fichier. Les identifiants utilisateur et groupe sont les champs st_uid et st_gid du fichier. Le mode du fichier est le champ st_mode du fichier. La taille du fichier est le champ st_size du fichier. L'en-tête de fin de deux octets est la chaîne "`<newlin

e>".

Seul le champ nom prévoit un débordement. Si un nom de fichier dépasse 16 caractères ou contient un espace incorporé, la chaîne "#1/" suivie de la longueur ASCII du nom est écrite dans le champ nom. La taille du fichier (stockée dans l'en-tête de l'archive) est incrémentée de la longueur du nom. Le nom est ensuite écrit immédiatement après l'en-tête de

l'archive.

Tous les caractères inutilisés dans chacun de ces champs sont écrits comme caractères <space>. Si certains champs atteignent leur nombre maximal de caractères, il n'y a aucune séparation entre les

champs.

Les objets dans l'archive ont toujours un nombre pair d'octets de long

; les fichiers ayant un nombre impair d'octets de long sont complétés p
ar un <newline>, bien que la taille dans l'en-tête ne reflète pas cela.

La description de l'utilitaire ar exige que (lorsque tous ses membres sont des fichiers objet valides) ar produise une bibliothèque de code objet, que l'éditeur de liaison peut utiliser pour extraire des modules objet. Si l'éditeur de liaison a besoin d'une table de symboles pour permettre l'accès aléatoire à l'archive, ar doit la fournir ; cependant, ar ne requiert pas de table de

symboles.

L'option BSD -o a été omise. Il est rare qu'une application conforme utilise ar pour extraire du code objet d'une bibliothèque en se souciant de son heure de modification, car cela ne peut avoir d'importance que pour make. Par conséquent, puisque cette fonctionnalité n'est pas considérée comme importante pour la portabilité des applications, l'heure de modification des fichiers extraits est réglée sur l'heure

courante.

Il existe au moins une implémentation connue (pour un petit ordinateur) qui ne peut accueillir que des fichiers objet pour ce système, n'autorisant pas de fichiers objets et autres fichiers mélangés. La capacité de gérer tout type de fichier n'est pas seulement une pratique historique pour la plupart des implémentations, mais aussi une attente

raisonnable.

La possibilité de changer le format de sortie de ar -tv au même format que la sortie de ls -l a été envisagée. Cela aurait rendu l'analyse de la sortie de ar identique à celle de ls. Cela a été rejeté en partie parce que le format actuel de ar est couramment utilisé et que des changements casseraient l'usage historique. Deuxièmement, ar donne l'identifiant utilisateur et l'identifiant groupe sous forme numérique séparés par un <slash>. Changer cela pour le nom d'utilisateur et le nom de groupe ne serait pas correct si l'archive était déplacée vers une machine contenant une base de données d'utilisateurs différente. Puisque ar ne peut pas savoir si l'archive a été générée sur la même machine, il ne peut pas dire quoi

rapporter.

Le texte concernant la combinaison d'options -ur est une pratique historique — puisqu'un nom de fichier peut facilement représenter deux fichiers différents (par exemple, /a/f

oo
et

/b/foo), il est raisonnable de remplacer le fichier dans l'archive même lorsque l'heure de modification dans l'archive est identique à celle dans le système de

fichiers.
