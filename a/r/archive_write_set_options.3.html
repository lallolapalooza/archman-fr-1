archive_write_set_options(3)

Paquet: libarchive

Licences: BSD-2-Clause

ARCHIVE_WRITE_OPTIONS(3) Manuel des fonctions de bibliothèque ARCHIVE_WRITE_OPTIONS(3)

NOM

archive_write_set_filter_option, archive_write_set_format_option, archive_write_set_option, archive_write_set_options — fonctions contrôlant les options pour l'écriture d'archives

BIBLIOTHEQUE

Bibliothèque d'archives en flux (libarchive, -larchive)

SYNTAXE

int
archive_write_set_filter_option(struct archive *, const char *module, const char *option, const char *value);

int
archive_write_set_format_option(struct archive *, const char *module, const char *option, const char *value);

int
archive_write_set_option(struct archive *, const char *module, const char *option, const char *value);

int
archive_write_set_options(struct archive *, const char *options);

DESCRIPTION

Ces fonctions fournissent un moyen aux clients de libarchive de configurer des modules d'écriture spécifiques.

archive_write_set_filter_option(), archive_write_set_format_option()
Spécifie une option qui sera transmise aux filtres (y compris les filtres de décompression) ou aux lecteurs de format actuellement enregistrés.

Si option et value sont tous deux NULL, ces fonctions ne feront rien et ARCHIVE_OK sera retourné. Si option est NULL mais value ne l'est pas, ces fonctions ne feront rien et ARCHIVE_FAILED sera retourné.

Si module n'est pas NULL, option et value seront fournis au filtre ou au lecteur nommé module. La valeur de retour sera soit ARCHIVE_OK si l'option a été gérée avec succès, soit ARCHIVE_WARN si l'option n'a pas été reconnue par le module ou n'a pas pu être gérée. S'il n'existe pas de tel module, ARCHIVE_FAILED sera retourné.

Si module est NULL, option et value seront fournis à chaque module enregistré. Si un module retourne ARCHIVE_FATAL, cette valeur sera retournée immédiatement. Sinon, ARCHIVE_OK sera retourné si au moins un module accepte l'option, et ARCHIVE_FAILED dans tous les autres cas.

archive_write_set_option()
Appelle archive_write_set_format_option(), puis archive_write_set_filter_option(). Si l'une des fonctions retourne ARCHIVE_FATAL, ARCHIVE_FATAL sera retourné immédiatement. Sinon, la plus grande des deux valeurs sera retournée.
archive_write_set_options()
options est une liste d'options séparées par des virgules. Si options est NULL ou vide, ARCHIVE_OK sera retourné immédiatement.

Les options individuelles ont l'une des formes suivantes :

option=valeur
La paire option/valeur sera fournie à chaque module. Les modules qui n'acceptent pas une option de ce nom l'ignoreront.
option
L'option sera fournie à chaque module avec la valeur « 1 ».
!option
L'option sera fournie à chaque module avec une valeur NULL.
module:option=valeur, module:option, module:!option
Comme ci-dessus, mais l'option et la valeur correspondantes ne seront fournies qu'aux modules dont le nom correspond à module.

OPTIONS

Filtre b64encode
mode
La valeur est interprétée comme des chiffres octaux spécifiant le mode du fichier.
nom
La valeur spécifie le nom du fichier.
Filtre bzip2
niveau-de-compression
La valeur est interprétée comme un entier décimal spécifiant le niveau de compression bzip2. Les valeurs prises en charge vont de 1 à 9.
Filtre gzip
niveau-de-compression
La valeur est interprétée comme un entier décimal spécifiant le niveau de compression gzip. Les valeurs prises en charge vont de 0 à 9.
horodatage
Enregistrer l'horodatage. Ceci est activé par défaut.
Filtre lrzip
compression=type
Utiliser type comme méthode de compression. Les valeurs prises en charge sont « bzip2 », « gzipi », « lzo » (ultra rapide), et « zpaq » (meilleur, extrêmement lent).
niveau-de-compression
La valeur est interprétée comme un entier décimal spécifiant le niveau de compression lrzip. Les valeurs prises en charge vont de 1 à 9.
Filtre lz4
niveau-de-compression
La valeur est interprétée comme un entier décimal spécifiant le niveau de compression lz4. Les valeurs prises en charge vont de 0 à 9.
controle-de-flux
Activer le contrôle de flux. Ceci est activé par défaut.
controle-de-bloc
Activer le contrôle de bloc. Ceci est désactivé par défaut.
taille-de-bloc
La valeur est interprétée comme un entier décimal spécifiant la taille de bloc de compression lz4. Les valeurs prises en charge vont de 4 à 7 (par défaut).
dependance-de-bloc
Utiliser le bloc précédent du bloc en cours de compression comme dictionnaire de compression pour améliorer le rapport de compression. Ceci est désactivé par défaut.
Filtre lzop
niveau-de-compression
La valeur est interprétée comme un entier décimal spécifiant le niveau de compression lzop. Les valeurs prises en charge vont de 1 à 9.
Filtre uuencode
mode
La valeur est interprétée comme des chiffres octaux spécifiant le mode du fichier.
name
La valeur spécifie le nom du fichier.
Filtre xz
compression-level
La valeur est interprétée comme un entier décimal spécifiant le niveau de compression. Les valeurs prises en charge vont de 0 à 9.
threads
La valeur est interprétée comme un entier décimal spécifiant le nombre de threads pour la compression lzma multi-threadée. Si pris en charge, la valeur par défaut est lue depuis lzma_cputhreads().
Filtre zstd
compression-level
La valeur est interprétée comme un entier décimal spécifiant le niveau de compression. Les valeurs prises en charge dépendent de la version de la bibliothèque ; les valeurs courantes vont de 1 à 22.
long
Active la correspondance à longue distance. La valeur est interprétée comme un entier décimal spécifiant la taille de la fenêtre log2 en octets. Les valeurs de 10 à 30 pour 32 bits, ou 31 pour 64 bits, sont prises en charge.
threads
La valeur est interprétée comme un entier décimal spécifiant le nombre de threads pour la compression zstd multi-threadée. Si défini à 0, zstd essaiera de détecter et d'utiliser le nombre de cœurs physiques de CPU actifs.
Format 7zip
compression
La valeur est l'une des suivantes : « store », « copy », « deflate », « bzip2 », « lzma1 », « lzma2 », « ppmd » ou « zstd » pour indiquer comment les entrées suivantes doivent être compressées. Les valeurs « store » et « copy » sont des synonymes. Notez que ce paramètre est ignoré pour les répertoires, les liens symboliques et les autres entrées spéciales.
compression-level
La valeur est interprétée comme un entier décimal spécifiant le niveau de compression. Les valeurs entre 0 et 9 sont prises en charge, à l'exception de bzip2 qui ne prend en charge que les valeurs entre 1 et 9, et zstd qui peut prendre en charge des valeurs négatives selon la version de la bibliothèque et les valeurs couramment utilisées de 1 à 22. L'interprétation du niveau de compression dépend de la méthode de compression choisie.
threads
La valeur est interprétée comme un entier décimal spécifiant le nombre de threads pour la compression multi-threadée (pour des compresseurs comme zstd qui la prennent en charge). Si défini à 0, une tentative sera faite pour découvrir le nombre de cœurs de CPU.
Format bin
hdrcharset
La valeur est utilisée comme nom de jeu de caractères qui sera utilisé lors de la traduction des noms de fichiers.
Format gnutar
hdrcharset
La valeur est utilisée comme nom de jeu de caractères qui sera utilisé lors de la traduction des noms de fichiers, de groupes et d'utilisateurs.
Format iso9660 - métadonnées du volume
Ces options sont utilisées pour définir les métadonnées ISO9660 standard.
abstract-file=filename
Le fichier portant le nom spécifié sera identifié dans les métadonnées ISO9660 comme contenant le résumé de ce volume. Par défaut : aucun.
application-id=filename
Le fichier portant le nom spécifié sera identifié dans les métadonnées ISO9660 comme contenant l'identifiant d'application de ce volume. Par défaut : aucun.
biblio-file=filename
Le fichier portant le nom spécifié sera identifié dans les métadonnées ISO9660 comme contenant la bibliographie de ce volume. Par défaut : aucune.
copyright-file=filename
Le fichier portant le nom spécifié sera identifié dans les métadonnées ISO9660 comme contenant le copyright de ce volume. Par défaut : aucun.
publisher=filename
Le fichier portant le nom spécifié sera identifié dans les métadonnées ISO9660 comme contenant les informations de l'éditeur de ce volume. Par défaut : aucun.
volume-id=string
La chaîne spécifiée sera utilisée comme identifiant de volume dans les métadonnées ISO9660. Elle est limitée à 32 octets. Par défaut : aucun.
Format iso9660 - prise en charge du démarrage
Ces options sont utilisées pour créer une image ISO9660 pouvant être démarrée directement sur divers systèmes.
boot=filename
Le fichier correspondant à ce nom sera utilisé comme fichier image de démarrage El Torito.
boot-catalog=name
Le nom qui sera utilisé pour le catalogue de démarrage El Torito. Par défaut : boot.catalog
boot-info-table
Le fichier image de démarrage fourni par l'option boot=filename sera modifié avec les informations de démarrage appropriées dans les octets 8 à 64. Par défaut : désactivé
boot-load-seg=hexadecimal-number
Le segment de chargement pour une image de démarrage sans émulation.
boot-load-size=decimal-number
Le nombre de secteurs « virtuels » de 512 octets à charger depuis une image de démarrage sans émulation. Certains BIOS très anciens ne peuvent charger que de très petites images ; définir cette valeur à 4 permettra souvent à de tels BIOS de charger la première partie de l'image de démarrage (qui devra alors être suffisamment intelligente pour charger le reste d'elle-même). Cela ne devrait pas être nécessaire sauf si vous essayez de prendre en charge des systèmes avec des BIOS très anciens. La valeur par défaut est la taille complète de l'image.
boot-type=value
Spécifie la sémantique de démarrage utilisée par l'image de démarrage El Torito : si le value est fd, l'image de démarrage est supposée être une image de disquette amorçable. Si le value est hd, l'image de démarrage est supposée être une image de disque dur amorçable. Si le value est no-emulation, l'image de démarrage est utilisée sans émulation de disquette ou de disque dur. Si l'image de démarrage fait exactement 1,2 Mo, 1,44 Mo ou 2,88 Mo, alors la valeur par défaut est fd, sinon la valeur par défaut est no-emulation.
Format iso9660 - extensions de nom de fichier et de taille
Diverses extensions au format ISO9660 de base.
allow-ldots
Si activé, permet aux noms de fichiers de commencer par un point initial. Si désactivé, les noms de fichiers commençant par un point initial auront ce point remplacé par un caractère de soulignement dans l'espace de noms ISO9660 standard. Cela n'affecte pas les noms stockés dans les zones d'extension Rockridge ou Joliet. Par défaut : désactivé.
allow-lowercase
Si activé, permet aux noms de fichiers de contenir des caractères minuscules. Si désactivé, les noms de fichiers seront forcés en majuscules. Cela n'affecte pas les noms stockés dans les zones d'extension Rockridge ou Joliet. Par défaut : désactivé.
allow-multidot
Si activé, permet aux noms de fichiers de contenir plusieurs caractères de point, en violation de la spécification ISO9660. Si désactivé, les points supplémentaires seront convertis en caractères de soulignement. Cela n'affecte pas les noms stockés dans les zones d'extension Rockridge ou Joliet. Par défaut : désactivé.
allow-period
Si activé, permet aux noms de fichiers de contenir des caractères de point finaux, en violation de la spécification ISO9660. Si désactivé, les points finaux seront convertis en caractères de soulignement. Cela n'affecte pas les noms stockés dans les zones d'extension Rockridge ou Joliet. Par défaut : désactivé.
allow-pvd-lowercase
Si activé, le Descripteur de Volume Principal peut contenir des caractères ASCII minuscules, en violation de la spécification ISO9660. Si désactivé, les caractères seront convertis en ASCII majuscules. Par défaut : désactivé.
allow-sharp-tilde
Si activé, les caractères dièse et tilde seront autorisés dans les noms de fichiers, en violation de la spécification ISO9660. Si désactivé, de tels caractères seront convertis en caractères de soulignement. Par défaut : désactivé.
allow-vernum
Si activé, les numéros de version seront inclus avec les fichiers. Si désactivé, les numéros de version seront supprimés, en violation de la norme ISO9660. Cela n'affecte pas les noms stockés dans les extensions Rockridge ou Joliet. Par défaut : activé.
iso-level
Cela active la prise en charge de la taille des fichiers et des extensions de noms de fichiers dans la zone principale ISO9660. Les extensions de noms spécifiées ici n'affectent pas les noms stockés dans les extensions Rockridge ou Joliet.
iso-level=1
La forme la plus conforme de l'image ISO9660. Les noms de fichiers sont limités au format 8.3 en majuscules, les noms de répertoires sont limités à 8 caractères en majuscules, les fichiers sont limités à 4 Gio, l'image ISO9660 complète ne peut pas dépasser 4 Gio.
iso-level=2
Les noms de fichiers sont limités à 30 caractères en majuscules avec une extension de 30 caractères, les noms de répertoires sont limités à 30 caractères, les fichiers sont limités à 4 Gio.
iso-level=3
Comme avec iso-level=2, sauf que les fichiers peuvent dépasser 4 Gio.
iso-level=4
Comme avec iso-level=3, sauf que les noms de fichiers peuvent comporter jusqu'à 193 caractères et peuvent inclure des caractères arbitraires sur 8 bits.
joliet
Les extensions Joliet de Microsoft stockent un ensemble complètement séparé d'informations de répertoire pour chaque fichier. En particulier, ces informations incluent des noms de fichiers Unicode de jusqu'à 255 caractères. Par défaut : activé.
limit-depth
Si activé, libarchive utilisera des enregistrements de relocalisation de répertoire pour garantir qu'aucun chemin ne dépasse la limite ISO9660 de 8 niveaux de répertoires. Si désactivé, aucune relocalisation n'aura lieu. Par défaut : activé.
limit-dirs
Si activé, libarchive provoquera une erreur s'il y a plus de 65536 répertoires. Si désactivé, il n'y a pas de limite sur le nombre de répertoires. Par défaut : activé
pad
Si activé, 300 kio d'octets nuls seront ajoutés à la fin de l'archive. Par défaut : activé
relaxed-filenames
Si activé, tous les caractères ASCII 7 bits sont autorisés dans les noms de fichiers (sauf les caractères minuscules, sauf si allow-lowercase est également spécifié). Cela viole les normes ISO9660. Cela n'affecte pas les noms stockés dans les extensions Rockridge ou Joliet. Par défaut : désactivé.
rockridge
Les extensions Rockridge stockent un ensemble supplémentaire d'informations de fichier de style POSIX avec chaque fichier, incluant mtime, atime, ctime, les permissions et les noms de fichiers longs avec des caractères arbitraires sur 8 bits. Ces extensions prennent également en charge les liens symboliques et d'autres types de fichiers POSIX. Par défaut : activé.
Format iso9660 - prise en charge de zisofs
Les extensions zisofs permettent à chaque fichier d'être compressé indépendamment en utilisant une compression compatible gzip. Cela peut offrir des économies de taille significatives, mais nécessite que le système de lecture prenne en charge ces extensions. Ces extensions sont désactivées par défaut.
compression-level=nombre
Le niveau de compression utilisé par le compresseur deflate. Va de 0 (moins d'effort) à 9 (le plus d'effort). Par défaut : 6
zisofs
Synonyme pour zisofs=direct.
zisofs=direct
Compresse chaque fichier dans l'archive. Contrairement à zisofs=indirect, cela est entièrement géré dans libarchive et ne nécessite pas d'utilitaire séparé. Pour de meilleurs résultats, libarchive teste chaque fichier et stockera le fichier non compressé si la compression ne fait réellement gagner aucun espace. En particulier, les fichiers de moins de 2k ne seront jamais compressés. Notez que les fichiers d'image de démarrage ne sont jamais compressés.
zisofs=indirect
Reconnaît les fichiers qui ont déjà été compressés avec l'utilitaire mkzftree et configure les métadonnées de fichier nécessaires afin que les lecteurs identifient correctement ces fichiers comme compressés avec zisofs.
zisofs-exclude=nom-de-fichier
Spécifie un nom de fichier qui ne doit pas être compressé lors de l'utilisation de zisofs=direct. Cette option peut être fournie plusieurs fois pour supprimer la compression de nombreux fichiers.
Format mtree
cksum, device, flags, gid, gname, indent, link, md5, mode, nlink, rmd160, sha1, sha256, sha384, sha512, size, time, uid, uname
Active un mot-clé particulier dans la sortie mtree. Préfixez avec un point d'exclamation pour désactiver le mot-clé correspondant. La valeur par défaut est équivalente à « device, flags, gid, gname, link, mode, nlink, size, time, type, uid, uname ».
all
Active tous les mots-clés ci-dessus.
use-set
Active la génération de lignes /set qui spécifient des valeurs par défaut pour les fichiers et/ou répertoires suivants.
indent
XXX besoin d'explication XXX
Format newc
hdrcharset
La valeur est utilisée comme nom de jeu de caractères qui sera utilisé lors de la traduction des noms de fichiers.
Format odc
hdrcharset
La valeur est utilisée comme nom de jeu de caractères qui sera utilisé lors de la traduction des noms de fichiers.
Format pwb
hdrcharset
La valeur est utilisée comme nom de jeu de caractères qui sera utilisé lors de la traduction des noms de fichiers.
Format pax
hdrcharset
La valeur est utilisée comme nom de jeu de caractères qui sera utilisé lors de la traduction des noms de fichiers, de groupes et d'utilisateurs. La valeur est soit « BINARY » soit « UTF-8 ». Avec « BINARY », il n'y a pas de conversion de caractères, avec « UTF-8 », les noms sont convertis en UTF-8.
xattrheader
Lors du stockage des attributs étendus, cette option configure quels en-têtes doivent être écrits. La valeur est soit « all », « LIBARCHIVE », ou « SCHILY ». Par défaut, les en-têtes « LIBARCHIVE.xattr » et « SCHILY.xattr » sont écrits.
Format ustar
hdrcharset
La valeur est utilisée comme nom de jeu de caractères qui sera utilisé lors de la traduction des noms de fichiers, de groupes et d'utilisateurs.
Format v7tar
hdrcharset
La valeur est utilisée comme nom de jeu de caractères qui sera utilisé lors de la traduction des noms de fichiers, de groupes et d'utilisateurs.
Format warc
omit-warcinfo
Définissez à « true » pour désactiver la sortie de l'enregistrement warcinfo.
Format xar
checksum=type
Utilise type comme méthode de somme de contrôle de fichier. Les valeurs prises en charge sont « none », « md5 », et « sha1 » (par défaut).
compression=type
Utilise type comme méthode de compression. Les valeurs prises en charge sont « none », « bzip2 », « gzip » (par défaut), « lzma » et «xz ».
compression_level
La valeur est un entier décimal de 1 à 9 spécifiant le niveau de compression.
toc-checksum=type
Utilise type comme méthode de somme de contrôle de la table des matières. Les valeurs prises en charge sont « none », « md5 » et « sha1 » (par défaut).
Format zip
compression
La valeur est soit « store », « deflate », « bzip2 », « lzma », « xz », ou « zstd » pour indiquer comment les entrées suivantes doivent être compressées. Notez que ce réglage est ignoré pour les répertoires, les liens symboliques et les autres entrées spéciales.
compression-level
La valeur est interprétée comme un entier décimal spécifiant le niveau de compression. Les valeurs comprises entre 0 et 9 sont prises en charge. Un niveau de compression de 0 bascule la méthode de compression vers « store », les autres valeurs activeront la compression « deflate », « bzip2 », « lzma », ou « zstd » (par ordre de priorité, selon les bibliothèques liées) avec le niveau donné.
threads
La valeur est interprétée comme un entier décimal spécifiant le nombre de threads à utiliser pour la compression. Elle n'est prise en charge que pour la compression « xz » ou « zstd » et est ignorée pour toute autre. Une valeur de threads de 0 est une valeur spéciale demandant de détecter et d'utiliser autant de threads que le nombre de cœurs physiques de CPU actifs.
encryption
Active le chiffrement en utilisant le chiffrement zip traditionnel.
encryption=type
Utilise type comme type de chiffrement. Les valeurs prises en charge sont « zipcrypt » (chiffrement zip traditionnel), « aes128 » (chiffrement WinZip AES-128) et « aes256 » (chiffrement WinZip AES-256).
experimental
Cette option booléenne active ou désactive les fonctionnalités expérimentales de Zip qui peuvent ne pas être compatibles avec d'autres implémentations de Zip.
fakecrc32
Cette option booléenne désactive les calculs de CRC. Tous les champs CRC sont mis à zéro. Elle ne devrait pas être utilisée à des fins autres que les tests.
hdrcharset
La valeur est utilisée comme nom de jeu de caractères qui sera utilisé lors de la traduction des noms de fichiers.
zip64
Les extensions Zip64 fournissent des informations de taille de fichier supplémentaires pour les entrées plus grandes que 4 Gio. Elles fournissent également des informations étendues sur le décalage de fichier et la taille de l'archive lorsque les archives dépassent 4 Gio. Par défaut, l'écrivain Zip active sélectivement ces extensions uniquement selon les besoins. En particulier, si la taille du fichier est inconnue, l'écrivain Zip inclura les extensions Zip64 pour se prémunir contre la possibilité que le fichier soit plus grand que 4 Gio.

Régler cette option booléenne forcera l'écrivain à utiliser les extensions Zip64 même pour de petits fichiers qui ne les nécessiteraient pas autrement. C'est principalement utile pour les tests.

Désactiver cette option avec !zip64 forcera l'écrivain Zip à éviter les extensions Zip64 : il rejettera les fichiers dont la taille est supérieure à 4 Gio, il rejettera toute nouvelle entrée une fois que la taille totale de l'archive atteint 4 Gio, et il n'utilisera pas les extensions Zip64 pour les fichiers de taille inconnue. En particulier, cela peut améliorer la compatibilité lors de la génération d'archives dont les tailles des entrées ne sont pas connues à l'avance.

EXEMPLES

L'exemple suivant crée une poignée d'écriture d'archive pour créer une image au format ISO9660 compressée avec gzip. Les deux options ici spécifient que l'archive ISO9660 utilisera kernel.img comme image d'amorçage pour le démarrage El Torito, et que le compresseur gzip devrait utiliser le niveau de compression maximal.

a = archive_write_new();
archive_write_add_filter_gzip(a);
archive_write_set_format_iso9660(a);
archive_write_set_options(a, "boot=kernel.img,compression=9");
archive_write_open_filename(a, filename, blocksize);
