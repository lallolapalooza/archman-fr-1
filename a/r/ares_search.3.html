DESCRIPTIO

N

La fonction ares_search initie une série de requêtes DNS à question unique sur le canal de service de noms identifié par channel, en utilisant les domaines de recherche du canal ainsi qu'un fichier d'alias d'hôte fourni par la variable d'environnement HOSTALIAS. Le paramètre name donne le nom d'alias ou la base du nom de requête sous forme de chaîne C terminée par NUL, composée d'étiquettes séparées par des points ; s'il se termine par un point, les domaines de recherche du canal ne seront pas utilisés. Les points et les barres obliques inverses à l'intérieur d'une étiquette doivent être échappés par une barre oblique inverse. Les paramètres dnsclass et type donnent la classe et le type de la requête en utilisant les valeurs définies dans <arpa/nameser.h>. Lorsque la séquence de requêtes est terminée ou a échoué, la bibliothèque ares invoquera callback. L'achèvement ou l'échec de la séquence de requêtes peut se produire immédiatement, ou se produire lors d'un appel ultérieur à ares_process(3) ou ares_destro

y(3).

Si ceci est appelé depuis un autre fil d'exécution que celui dans lequel la boucle d'événements du programme principal s'exécute, il faut veiller à ce que les listes de descripteurs de fichiers soient mises à jour immédiatement dans la boucle d'événements. Lorsque le callback associé est appelé, il est appelé avec le verrou du canal, il faut donc veiller à ce que tout traitement soit minimal afin d'éviter les blocages du canal

DNS.

L'argument de callback arg est copié à partir de l'argument ares_search arg. L'argument de callback status indique si la séquence de requêtes s'est terminée par une requête réussie et, si ce n'est pas le cas, comment la séquence de requêtes a échoué. Il peut avoir l'une des valeurs suivantes

L'argument de callback timeouts indique combien de fois une requête a expiré pendant l'exécution de la requête donnée. Si une requête s'est terminée avec succès, l'argument de callback abuf pointe vers un tampon de résultat de longueur alen. Si la requête ne s'est pas terminée avec succès, abuf sera généraleme

nt NULL et

alen sera généralement 0, mais dans certains cas un résultat de requête infructueux peut être placé dans abuf. La fonction ares_search_dnsrec(3) se comporte de manière identique à ares_search(3), mais prend un objet d'enregistrement DNS initialisé et rempli à utiliser pour les requêtes comme deuxième argument dnsrec au lieu d'un nom, d'une classe et d'un type. Cet objet est utilisé comme base pour les requêtes et doit lui-même représenter une requête valide pour un seul nom. Notez que les domaines de recherche ne seront ajoutés qu'au nom dans la section question ; les RR sur l'objet d'enregistrement DNS ne seront pas affectés. De plus, l'argument callback est de type ares_callback_dnsrec. Ce callback se comporte de manière identique

à

ares_callback, mais est invoqué avec un objet d'enregistrement DNS analysé dnsrec plutôt qu'un tampon brut avec longueur. Notez que cet objet est en lecture seule. La fon

ct
ion

ares_search_dnsrec(3) renvoie un code de réponse ares_status_t. Cela peut être utile pour savoir que la requête a été mise en file d'attente correctement. Le code de réponse ne reflète pas le résultat de la requête, seulement le résultat de la mise en file

d'attente de la requête.
