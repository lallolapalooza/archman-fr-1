tclvars(n) Commandes intégrées Tcl tclvars(n)

NOM

argc, argv, argv0, auto_path, env, errorCode, errorInfo, tcl_interactive, tcl_library, tcl_nonwordchars, tcl_patchLevel, tcl_pkgPath, tcl_platform, tcl_precision, tcl_rcFileName, tcl_traceCompile, tcl_traceExec, tcl_wordchars, tcl_version - Variables utilisées par Tcl

DESCRIPTION

Les variables globales suivantes sont créées et gérées automatiquement par la bibliothèque Tcl. Sauf indication contraire ci-dessous, ces variables doivent normalement être considérées comme en lecture seule par le code spécifique à l'application et par les utilisateurs.

auto_path
Si définie, elle doit contenir une liste Tcl valide indiquant les répertoires à rechercher lors des opérations de chargement automatique (y compris les fichiers d'index de paquets lors de l'utilisation du gestionnaire par défaut package unknown). Cette variable est initialisée au démarrage pour contenir, dans l'ordre : les répertoires listés dans la variable d'environnement TCLLIBPATH, le répertoire nommé par la variable globale tcl_library, le répertoire parent de tcl_library, [file dirname [file dirname [info nameofexecutable]]]/lib, les répertoires listés dans la variable tcl_pkgPath. D'autres emplacements pour rechercher des fichiers et des index de paquets devraient normalement être ajoutés à cette variable en utilisant lappend.

D'autres variables relatives à la gestion des paquets existent. Plus de détails sont listés dans la section VARIABLES de la page de manuel de library.

env
Cette variable est maintenue par Tcl comme un tableau dont les éléments sont les variables d'environnement du processus. La lecture d'un élément retournera la valeur de la variable d'environnement correspondante. La définition d'un élément du tableau modifiera la variable d'environnement correspondante ou en créera une nouvelle si elle n'existe pas déjà. La suppression d'un élément de env supprimera la variable d'environnement correspondante. Les modifications apportées au tableau env affecteront l'environnement transmis aux enfants par des commandes telles que exec. Si l'intégralité du tableau env est supprimée, Tcl cessera de surveiller les accès à env et ne mettra pas à jour les variables d'environnement.

Sous Windows, les variables d'environnement PATH et COMSPEC, quelle que soit leur capitalisation, sont automatiquement converties en majuscules. Par exemple, la variable PATH peut être exportée par le système d'exploitation sous les formes “path”, “Path”, “PaTh”, etc., obligeant le code Tcl, par ailleurs simple, à prendre en charge de nombreux cas particuliers. Toutes les autres variables d'environnement héritées par Tcl restent inchangées. Définir une variable du tableau env à une chaîne vide équivaut à la supprimer, car tel est le comportement du système d'exploitation Windows sous-jacent. Il convient de noter que s'appuyer sur une variable d'environnement existante et vide ne fonctionnera pas sous Windows et est déconseillé pour une utilisation multiplateforme.

Les éléments suivants de env sont spéciaux pour Tcl :

env(HOME)
Cette variable d'environnement, si elle est définie, indique l'emplacement du répertoire considéré comme le répertoire personnel de l'utilisateur courant, et vers lequel un appel à cd sans argument ou avec seulement “~” comme argument se déplacera. La plupart des plates-formes définissent cela correctement par défaut ; il n'est normalement pas nécessaire de le définir par du code utilisateur.
env(TCL_LIBRARY)
Si elle est définie, elle spécifie l'emplacement du répertoire contenant les scripts de bibliothèque (la valeur de cette variable sera assignée à la variable tcl_library et retournée par conséquent par la commande info library). Si cette variable n'est pas définie, une valeur par défaut est utilisée.

Notez que cette variable d'environnement ne devrait *pas* normalement être définie.

env(TCLLIBPATH)
Si elle est définie, elle doit contenir une liste Tcl valide indiquant les répertoires à rechercher lors des opérations de chargement automatique. Les répertoires doivent être spécifiés au format Tcl, en utilisant “/” comme séparateur de chemin, quelle que soit la plateforme. Cette variable n'est utilisée que lors de l'initialisation de la variable auto_path.
env(TCL_TZ), env(TZ)
Ces variables spécifient le fuseau horaire par défaut utilisé pour l'analyse et le formatage des heures et des dates dans la commande clock. Sur de nombreuses plateformes, la variable d'environnement TZ est configurée par le système d'exploitation.
env(LC_ALL), env(LC_MESSAGES), env(LANG)
Ces variables d'environnement sont utilisées par le paquet msgcat pour déterminer quelle locale utiliser pour formater les messages.
env(TCL_INTERP_DEBUG_FRAME)
Si elle existe, elle a le même effet que l'exécution de interp debug {} -frame 1 comme toute première commande de chaque nouvel interpréteur Tcl.
errorCode
Cette variable contient la valeur de l'option de retour -errorcode définie par la plus récente erreur survenue dans cet interpréteur. Cette valeur de liste représente des informations supplémentaires sur l'erreur sous une forme facile à traiter par les programmes. Le premier élément de la liste identifie une classe générale d'erreurs et détermine le format du reste de la liste. Les formats suivants pour les options de retour -errorcode sont utilisés par le noyau Tcl ; les applications individuelles peuvent définir des formats supplémentaires.
ARITH code msg
Ce format est utilisé lorsqu'une erreur arithmétique survient (par exemple, une tentative de division par zéro dans la commande expr). Code identifie l'erreur précise et msg fournit une description lisible par l'homme de l'erreur. Code sera soit DIVZERO (pour une tentative de division par zéro), DOMAIN (si un argument est en dehors du domaine d'une fonction, comme acos(-3)), IOVERFLOW (pour un dépassement de capacité entier), OVERFLOW (pour un dépassement de capacité en virgule flottante), soit UNKNOWN (si la cause de l'erreur ne peut être déterminée).

La détection de ces erreurs dépend en partie du matériel sous-jacent et des bibliothèques système.

CHILDKILLED pid sigName msg
Ce format est utilisé lorsqu'un processus enfant a été tué à cause d'un signal. L'élément pid sera l'identifiant du processus (en décimal). L'élément sigName sera le nom symbolique du signal qui a provoqué la terminaison du processus ; ce sera l'un des noms du fichier d'inclusion signal.h, tel que SIGPIPE. L'élément msg sera un court message lisible par l'homme décrivant le signal, tel que “écriture sur un tuyau sans lecteur” pour SIGPIPE.
CHILDSTATUS pid code
Ce format est utilisé lorsqu'un processus enfant s'est terminé avec un code de retour non nul. L'élément pid sera l'identifiant du processus (en décimal) et l'élément code sera le code de sortie retourné par le processus (également en décimal).
CHILDSUSP pid sigName msg
Ce format est utilisé lorsqu'un processus enfant a été suspendu à cause d'un signal. L'élément pid sera l'identifiant du processus, en décimal. L'élément sigName sera le nom symbolique du signal qui a provoqué la suspension du processus ; ce sera l'un des noms du fichier d'inclusion signal.h, tel que SIGTTIN. L'élément msg sera un court message lisible par l'homme décrivant le signal, tel que “lecture de tty en arrière-plan” pour SIGTTIN.
NONE
Ce format est utilisé pour les erreurs pour lesquelles aucune information supplémentaire n'est disponible hormis le message retourné avec l'erreur. Dans ces cas, l'option de retour -errorcode consistera en une liste contenant un seul élément dont le contenu est NONE.

tcl_precisi
on
Cette variable contrôle le nombre de chiffres à générer lors de la conversion des valeurs en virgule flottante en chaînes. Sa valeur par défaut est 0. Les applications ne devraient pas changer cette valeur ; e
lle est fournie pour la compatib
ilité avec le code hérité.
La valeur par défaut 0 est spéciale, signifiant que Tcl devrait convertir les nombres en utilisant aussi peu de chiffres que possible tout en distinguant toujours tout nombre en virgule flottante de ses voisins les plus proches. Elle diffère de l'utilisation d'une valeur arbitrairement élevée pour tcl_precision en ce que un nombre inexact comme 1.4 sera converti en 1.4 plutôt qu'en 1.3999999999999999 même si ce dernier est plus proche de la valeur exacte du nombre
binaire.
Si tcl_precision n'est pas zéro, alors lorsque Tcl convertit un nombre en virgule flottante, il crée une représentation décimale d'au plus tcl_precision chiffres significatifs ; le résultat peut être plus court si le résultat plus court représente le nombre original exactement. Si aucun résultat d'au plus tcl_precision chiffres n'est une représentation exacte du nombre original, celui qui est le plus proche du nombre original est choisi. Si le nombre original se trouve précisément entre deux représentations décimales également précises, alors celui dont la valeur du chiffre le moins significatif est paire est choisi ; par exemple, si tcl_precision vaut 3, alors 0.3125 sera converti en 0.312, pas 0.313, tandis que 0.6875 sera converti en 0.688, pas 0.687. Toute chaîne de zéros finaux restante est
supprimée.
Une valeur de tcl_precision de 17 chiffres est « parfaite » pour les flottants IEEE en ce qu'elle permet aux valeurs en double précision d'être converties en chaînes puis en binaire sans perte d'information. Pour cette raison, vous le verrez souvent comme une valeur dans du code hérité qui doit s'exécuter sur des versions de Tcl antérieures à 8.5. Elle n'est plus recommandée ; comme noté ci-dessus, une valeur zéro est la méthode
préférée.
Tous les interpréteurs dans un thread partagent une seule valeur de tcl_precision : la changer dans un interpréteur affectera tous les autres interpréteurs également. Les interpréteurs sûrs ne sont pas autorisés à modifier la
variable.
Les valeurs valides pour tcl_precision vont de 0 à
17.

tclvars(3) — Tcl variables

NAME

tclvars — Tcl variables

DESCRIPTION

The Tcl library exports a number of global variables. These are documented below.

auto_path
This is a Tcl list containing a sequence of directories that the Tcl auto-load facility will search for packages. It is initialized with default directories, but it can be modified by scripts to add new directories. For example, to add the directory /usr/local/lib/tcl8.0 to the list, you could use the command:
lappend auto_path /usr/local/lib/tcl8.0
auto_path is also the variable that the package require command searches for packages. The script init.tcl may also initialize the auto_path variable.
auto_index
This variable is used internally by the Tcl auto-load facility. It maps package names to procedures that can be auto-loaded. You should not normally need to modify it.
tcl_CompilerSpecialVar
This variable is used internally by the Tcl compiler. It is currently unused, but may be used in future versions of Tcl.
tcl_traceExec
The value of this variable can be set to control how much tracing information is displayed during bytecode execution. By default, tcl_traceExec is zero and no information is displayed. Setting tcl_traceExec to 1 generates a one-line trace in stdout on each call to a Tcl procedure. Setting it to 2 generates a line of output whenever any Tcl command is invoked that contains the name of the command and its arguments. Setting it to 3 produces a detailed trace showing the result of executing each bytecode instruction. Note that when tcl_traceExec is 2 or 3, commands such as set and incr that have been entirely replaced by a sequence of bytecode instructions are not shown. Setting this variable is useful in tracking down suspected problems with the bytecode compiler and interpreter.
This variable and functionality only exist if TCL_COMPILE_DEBUG was defined during Tcl's compilation.
tcl_wordchars
The value of this variable is a regular expression that can be set to control what are considered “word” characters, for instances like selecting a word by double-clicking in text in Tk. It is platform dependent. On Windows, it defaults to \S, meaning anything but a Unicode space character. Otherwise it defaults to \w, which is any Unicode word character (number, letter, or underscore).
tcl_nonwordchars
The value of this variable is a regular expression that can be set to control what are considered “non-word” characters, for instances like selecting a word by double-clicking in text in Tk. It is platform dependent. On Windows, it defaults to \s, meaning any Unicode space character. Otherwise it defaults to \W, which is anything but a Unicode word character (number, letter, or underscore).
tcl_version
When an interpreter is created Tcl initializes this variable to hold the version number for this version of Tcl in the form x.y. Changes to x represent major changes with probable incompatibilities and changes to y represent small enhancements and bug fixes that retain backward compatibility. The value of this variable is returned by the info tclversion command.

OTHER GLOBAL VARIABLES

The following variables are only guaranteed to exist in tclsh and wish executables; the Tcl library does not define them itself but many Tcl environments do.

argc
The number of arguments to tclsh or wish.
argv
Tcl list of arguments to tclsh or wish.
argv0
The script that tclsh or wish started executing (if it was specified) or otherwise the name by which tclsh or wish was invoked.
tcl_interactive
Contains 1 if tclsh or wish is running interactively (no script was specified and standard input is a terminal-like device), 0 otherwise.

EXAMPLES

To add a directory to the collection of locations searched by package require, e.g., because of some application-specific packages that are used, the auto_path variable needs to be updated:

lappend ::auto_path [file join [pwd] "theLibDir"]

A simple though not very robust way to handle command line arguments of the form “-foo 1 -bar 2” is to load them into an array having first loaded in the default settings:

array set arguments {-foo 0 -bar 0 -grill 0}
array set arguments $::argv
puts "foo is $arguments(-foo)"
puts "bar is $arguments(-bar)"
puts "grill is $arguments(-grill)"

The argv0 global variable can be used (in conjunction with the info script command) to determine whether the current script is being executed as the main script or loaded as a library. This is useful because it allows a single script to be used as both a library and a demonstration of that library:

if {$::argv0 eq [info script]} {
    # running as: tclsh example.tcl
} else {
    package provide Example 1.0
}
