NOM

Archive::Zip - Fournit une interface aux fichiers d'archive ZIP.

SYNOPSIS

# Create a Zip file
use Archive::Zip qw( :ERROR_CODES :CONSTANTS );
my $zip = Archive::Zip->new();
# Add a directory
my $dir_member = $zip->addDirectory( 'dirname/' );
# Add a file from a string with compression
my $string_member = $zip->addString( 'This is a test', 'stringMember.txt' );
$string_member->desiredCompressionMethod( COMPRESSION_DEFLATED );
# Add a file from disk
my $file_member = $zip->addFile( 'xyz.pl', 'AnotherName.pl' );
# Save the Zip file
unless ( $zip->writeToFileNamed('someZip.zip') == AZ_OK ) {
    die 'write error';
}
# Read a Zip file
my $somezip = Archive::Zip->new();
unless ( $somezip->read( 'someZip.zip' ) == AZ_OK ) {
    die 'read error';
}
# Change the compression type for a file in the Zip
my $member = $somezip->memberNamed( 'stringMember.txt' );
$member->desiredCompressionMethod( COMPRESSION_STORED );
unless ( $zip->writeToFileNamed( 'someOtherZip.zip' ) == AZ_OK ) {
    die 'write error';
}

DESCRIPTION

Le module Archive::Zip permet à un programme Perl de créer, manipuler, lire et écrire des fichiers d'archive Zip.

Des archives Zip peuvent être créées, ou vous pouvez lire depuis des fichiers zip existants.

Une fois créées, elles peuvent être écrites dans des fichiers, des flux ou des chaînes de caractères. Des membres peuvent être ajoutés, supprimés, extraits, remplacés, réorganisés et énumérés. Ils peuvent également être renommés, ou leurs dates, commentaires ou autres attributs peuvent être interrogés ou modifiés. Leurs données peuvent être compressées ou décompressées selon les besoins.

Des membres peuvent être créés à partir de membres dans des fichiers Zip existants, ou à partir de répertoires, de fichiers ou de chaînes de caractères existants.

Ce module utilise la bibliothèque Compress::Raw::Zlib pour lire et écrire les flux compressés à l'intérieur des fichiers.

On peut utiliser Archive::Zip::MemberRead pour lire les membres de l'archive de fichier zip comme s'il s'agissait de fichiers.

Nommage des fichiers

Quel que soit le système de fichiers local que vous utilisez pour le nommage des fichiers, les noms dans un fichier Zip sont au format Unix (barres obliques avant (/) séparant les noms de répertoires, etc.).

"Archive::Zip" essaie d'être cohérent avec les conventions de nommage de fichiers, et traduira dans les deux sens entre les noms de fichiers natifs et Zip.

Cependant, il ne peut pas deviner dans quel format se trouvent les noms. Deux règles contrôlent donc le type de nom de fichier que vous devez passer à diverses routines :

Les noms de fichiers sont au format local.
"File::Spec" et "File::Basename" sont utilisés pour diverses opérations sur les fichiers. Lorsque vous faites référence à un fichier sur votre système, utilisez ses conventions de nommage de fichiers.
Les noms des membres d'archive sont au format Unix.
Cela s'applique à chaque méthode qui fait référence à un membre d'archive, ou qui fournit un nom pour de nouveaux membres d'archive. Les méthodes extract() qui peuvent prendre un ou deux noms convertiront du format local vers le format zip si vous les appelez avec un seul nom.

Modèle d'objet Archive::Zip

Aperçu

Les objets Archive::Zip::Archive sont ceux avec lesquels vous traitez habituellement. Ils maintiennent la structure d'un fichier zip, sans nécessairement contenir de données. Lorsqu'un zip est lu depuis un fichier sur disque, les données (éventuellement compressées) restent dans le fichier, pas en mémoire. Les membres d'archive contiennent des informations sur les membres individuels, mais pas (généralement) les données réelles du membre. Lorsque le zip est écrit dans un fichier (différent), les données du membre sont compressées ou copiées selon les besoins. Il est possible de créer des membres d'archive dont les données sont conservées dans une chaîne en mémoire, mais cela n'est pas fait lorsqu'un fichier zip est lu. Les membres de répertoire n'ont aucune donnée.

CODES D'ERREUR

Beaucoup des méthodes dans Archive::Zip retournent des codes d'erreur. Ceux-ci sont implémentés comme des sous-routines en ligne, utilisant la "use constant" pragme. Ils peuvent être importés dans votre espace de noms en utilisant le marqueur ":ERROR_CODES" :

use Archive::Zip qw( :ERROR_CODES );
...
unless ( $zip->read( 'myfile.zip' ) == AZ_OK ) {
    die "whoops!";
}
AZ_OK (0)
Tout va bien.
AZ_STREAM_END (1)
Le flux de lecture (ou le répertoire central) s'est terminé normalement.
AZ_ERROR (2)
Il y a eu une erreur de type générique.
AZ_FORMAT_ERROR (3)
Il y a une erreur de format dans un fichier ZIP en cours de lecture.
AZ_IO_ERROR (4)
Il y a eu une erreur d'E/S.

Compression

Archive::Zip permet à chaque membre d'un fichier ZIP d'être compressé (à l'aide de l'algorithme Deflate) ou non compressé.

Les autres algorithmes de compression que certaines versions de ZIP ont été capables de produire ne sont pas pris en charge. Chaque membre a deux méthodes de compression : celle sous laquelle il est stocké (c'est toujours COMPRESSION_STORED pour les membres issus de chaînes de caractères et de fichiers externes), et celle que vous désirez pour le membre dans le fichier zip.

Celles-ci peuvent bien sûr différer, vous pouvez donc créer un membre zip non compressé à partir d'un membre compressé, et vice versa.

Vous pouvez interroger la compression actuelle et définir la méthode de compression souhaitée :

my $member = $zip->memberNamed( 'xyz.txt' );
$member->compressionMethod();    # return current compression
# set to read uncompressed
$member->desiredCompressionMethod( COMPRESSION_STORED );
# set to read compressed
$member->desiredCompressionMethod( COMPRESSION_DEFLATED );

Il y a deux méthodes de compression différentes :

COMPRESSION_STORED
Le fichier est stocké (pas de compression)
COMPRESSION_DEFLATED
Le fichier est Deflate

Niveau de compressions

Si la méthode de compression souhaitée d'un membre (desiredCompressionMethod) est COMPRESSION_DEFLATED, vous pouvez choisir différents niveaux de compression. Ce choix peut affecter la vitesse de compression et de décompression, ainsi que la taille des données du membre compressé.

$member->desiredCompressionLevel( 9 );

Les niveaux possibles sont :

  • 0 ou COMPRESSION_LEVEL_NONE

    Cela revient à dire

    $member->desiredCompressionMethod( COMPRESSION_STORED );
  • 1 .. 9

    1 donne la meilleure vitesse et la pire compression, et 9 donne la meilleure compression et la pire vitesse.

  • COMPRESSION_LEVEL_FASTEST

    C'est un synonyme pour le niveau 1.

  • COMPRESSION_LEVEL_BEST_COMPRESSION

    C'est un synonyme pour le niveau 9.

  • COMPRESSION_LEVEL_DEFAULT

    Cela donne un bon compromis entre vitesse et compression, et est actuellement équivalent à 6 (c'est dans le code zlib). C'est le niveau qui sera utilisé s'il n'est pas spécifié.

Archive::Zip Méthodes

La classe Archive::Zip (et sa sous-classe invisible Archive::Zip::Archive) implémente les fonctionnalités génériques des fichiers zip. Créer un nouvel objet Archive::Zip crée en fait un objet Archive::Zip::Archive, mais vous n'avez pas à vous en préoccuper sauf si vous créez une sous-classe.

Constructeur

new( [$fileName] )
new( { filename => $fileName } )
Crée une nouvelle archive zip vide. 
my $zip = Archive::Zip->new();

Si un argument supplémentaire est passé, new() appellera read() pour lire le contenu d'une archive :

my $zip = Archive::Zip->new( 'xyz.zip' );

Si un argument de nom de fichier est passé et que la lecture échoue pour quelque raison que ce soit, new renverra undef. Pour cette raison, il peut être préférable d'appeler read séparément.

Zip Méthodes utilitaires de l'archive

Ces méthodes d'Archive::Zip peuvent être appelées comme fonctions ou comme méthodes d'objet. Ne les appelez pas comme méthodes de classe :

$zip = Archive::Zip->new();
$crc = Archive::Zip::computeCRC32( 'ghijkl' );    # OK
$crc = $zip->computeCRC32( 'ghijkl' );            # also OK
$crc = Archive::Zip->computeCRC32( 'ghijkl' );    # NOT OK
Archive::Zip::computeCRC32( $string [, $crc] )
Archive::Zip::computeCRC32( { string => $string [, checksum => $crc ] } )
C'est une fonction utilitaire qui utilise la routine CRC de Compress::Raw::Zlib pour calculer un CRC-32. Vous pouvez obtenir le CRC d'une chaîne : 
$crc = Archive::Zip::computeCRC32( $string );

Ou vous pouvez calculer le CRC courant :

$crc = 0;
$crc = Archive::Zip::computeCRC32( 'abcdef', $crc );
$crc = Archive::Zip::computeCRC32( 'ghijkl', $crc );
Archive::Zip::setChunkSize( $number )
Archive::Zip::setChunkSize( { chunkSize => $number } )
Signale ou change la taille de bloc utilisée pour la lecture et l'écriture. Cela peut faire de grandes différences lors du traitement de fichiers volumineux. Actuellement, la valeur par défaut est de 32K. Cela change aussi la taille de bloc utilisée pour Compress::Raw::Zlib. Vous devez appeler setChunkSize() avant de lire ou d'écrire. Ceci n'est pas exportable, vous devez donc l'appeler comme ceci : 
Archive::Zip::setChunkSize( 4096 );

ou comme méthode sur un zip (bien que ce soit un réglage global). Renvoie l'ancienne taille de bloc.

Archive::Zip::chunkSize()
Renvoie la taille de bloc courante : 
my $chunkSize = Archive::Zip::chunkSize();
Archive::Zip::setErrorHandler( \&subroutine )
Archive::Zip::setErrorHandler( { subroutine => \&subroutine } )
Change la sous-routine appelée avec les chaînes d'erreur. La valeur par défaut est \&Carp::carp, mais vous voudrez peut-être la changer pour récupérer les chaînes d'erreur. Ceci n'est pas exportable, vous devez donc l'appeler comme ceci : 
Archive::Zip::setErrorHandler( \&myErrorHandler );

Si myErrorHandler est undef, réinitialise le gestionnaire à la valeur par défaut. Renvoie l'ancien gestionnaire d'erreur. Notez que si vous appelez Carp::carp ou une routine similaire, ou si vous déléguez au gestionnaire d'erreur par défaut depuis votre gestionnaire d'erreur, vous voudrez peut-être incrémenter le nombre de niveaux d'appelant qui sont ignorés (ne le réglez pas simplement sur un nombre) :

$Carp::CarpLevel++;
Archive::Zip::tempFile( [ $tmpdir ] )
Archive::Zip::tempFile( { tempDir => $tmpdir } )
Crée un fichier temporaire avec un nom unique. Il sera renvoyé ouvert en lecture/écriture. Si $tmpdir est fourni, il est utilisé comme le nom du répertoire dans lequel créer le fichier. S'il n'est pas fourni, crée le fichier en utilisant File::Spec::tmpdir(). Généralement, vous pouvez annuler ce choix en utilisant la variable d'environnement 
$ENV{TMPDIR}

. Mais consultez la documentation de File::Spec pour votre système. Notez que sur de nombreux systèmes, si vous exécutez en mode taint, vous devez vous assurer que $ENV{TMPDIR} est non contaminé (untainted) pour qu'il soit utilisé. Ne PAS créer $tmpdir s'il n'existe pas (c'est un changement par rapport aux versions précédentes !). Renvoie le descripteur de fichier et le nom :

my ($fh, $name) = Archive::Zip::tempFile();
my ($fh, $name) = Archive::Zip::tempFile('myTempDir');
my $fh = Archive::Zip::tempFile();  # if you don't need the name

my @members = $zip->members();

Renvoie une liste des noms de fichiers (internes) des membres du zip

Renvoie une référence au membre dont le nom de fichier est égal au nom de fichier donné, ou undef. $string doit être au format de nom de fichier Zip (Unix).

Renvoie un tableau des membres dont les noms de fichiers correspondent à l'expression rationnelle donnée en contexte liste. Renvoie le nombre de membres correspondants en contexte scalaire. 
my @textFileMembers = $zip->membersMatching( '.*\.txt' );
# or
my $numberOfTextFiles = $zip->membersMatching( '.*\.txt' );
zip64()
Indique si la lecture ou l'écriture précédente de l'archive a été faite au format zip64.
desiredZip64Mode()
Obtient ou définit quelles parties de l'archive doivent être écrites au format zip64 : toutes les parties au besoin (ZIP64_AS_NEEDED), la valeur par défaut, force l'écriture de l'enregistrement de fin du répertoire central zip64 (ZIP64_EOCD), force l'écriture de l'enregistrement zip64 EOCD et de tous les en-têtes au format zip64 (ZIP64_HEADERS).

Obtient les champs de l'enregistrement de fin du répertoire central zip64. Ceux-ci sont toujours à 0 si l'archive n'est pas au format zip64.

Renvoie le disque sur lequel je commence. Non utilisé pour l'écriture des zips, mais pourrait être intéressant si vous lisez un zip. Cela devrait être 0, car Archive::Zip ne gère pas les archives multi-volumes.
diskNumberWithStartOfCentralDirectory()
Renvoie le numéro de disque qui contient le début du répertoire central. Non utilisé pour l'écriture des zips, mais pourrait être intéressant si vous lisez un zip. Cela devrait être 0, car Archive::Zip ne gère pas les archives multi-volumes.
numberOfCentralDirectoriesOnThisDisk()
Renvoie le nombre de structures CD dans le fichier zip lu en dernier. Non utilisé pour l'écriture des zips, mais pourrait être intéressant si vous lisez un zip.
numberOfCentralDirectories()
Renvoie le nombre de structures CD dans le fichier zip lu en dernier. Non utilisé pour l'écriture des zips, mais pourrait être intéressant si vous lisez un zip.
centralDirectorySize()
Renvoie la taille du répertoire central, telle que lue depuis un fichier zip externe. Non utilisé pour l'écriture des zips, mais pourrait être intéressant si vous lisez un zip.
centralDirectoryOffsetWRTStartingDiskNumber()
Renvoie le décalage dans le fichier zip où commence le CD. Non utilisé pour l'écriture des zips, mais pourrait être intéressant si vous lisez un zip.
zipfileComment( [ $string ] )
Récupère ou définit le commentaire du fichier zip. Retourne l'ancien commentaire. 
print $zip->zipfileComment();
$zip->zipfileComment( 'New Comment' );
eocdOffset()
Retourne le nombre (inattendu) d'octets entre l'endroit où l'EOCD a été trouvé et l'endroit où il était censé se trouver. Cela vaut normalement 0, mais serait positif si quelque chose (un virus, peut-être) avait ajouté des octets quelque part avant l'EOCD. Non utilisé pour l'écriture des zips, mais pourrait être intéressant si vous lisez un zip. Voici un exemple de la manière dont vous pouvez diagnostiquer cela : 
my $zip = Archive::Zip->new('somefile.zip');
if ($zip->eocdOffset())
{
  warn "A virus has added ", $zip->eocdOffset, " bytes of garbage\n";
}

Le eocdOffset() est utilisé pour ajuster la position de départ des en-têtes des membres, si nécessaire.

fileName()
Retourne le nom du dernier fichier lu. Si rien n'a encore été lu, retourne une chaîne vide ; si lu depuis un descripteur de fichier, retourne le descripteur sous forme de chaîne.

Zip Opérations sur les membres d'archive

Diverses opérations sur un fichier zip modifient des membres. Lorsqu'un membre est passé en argument, vous pouvez soit utiliser une référence au membre lui-même, soit le nom d'un membre. Bien sûr, utiliser le nom nécessite que les noms soient uniques au sein d'un zip (ce qui n'est pas imposé).

removeMember( $memberOrName )
removeMember( { memberOrZipName => $memberOrName } )
Supprime et retourne le membre donné, ou recherche son nom et le supprime. Retourne undef si le membre ou le nom n'existe pas dans ce Zip. Ne fait rien si le membre n'appartient pas à ce zip.
replaceMember( $memberOrName, $newMember )
replaceMember( { memberOrZipName => $memberOrName, newMember => $newMember } )
Supprime et retourne le membre donné, ou recherche son nom et le supprime. Remplace par le nouveau membre. Retourne undef si le membre ou le nom n'existe pas dans ce Zip, ou si $newMember est indéfini.

C'est une erreur (non diagnostiquée) de fournir un $newMember qui est un membre du zip en cours de modification.

my $member1 = $zip->removeMember( 'xyz' );
my $member2 = $zip->replaceMember( 'abc', $member1 );
# now, $member2 (named 'abc') is not in $zip,
# and $member1 (named 'xyz') is, having taken $member2's place.
extractMember( $memberOrName [, $extractedName ] )
extractMember( { memberOrZipName => $memberOrName [, name => $extractedName ] } )
Extrait le membre donné, ou recherche son nom et l'extrait. Retourne undef si le membre n'existe pas dans ce Zip. Si le deuxième argument optionnel est fourni, utilisez-le comme nom du membre extrait. Sinon, le nom de fichier interne du membre est utilisé comme nom du fichier ou du répertoire extrait. Si vous passez $extractedName, il doit être dans le format du système de fichiers local. Si vous ne passez pas $extractedName et que le nom de fichier interne traverse un répertoire parent ou un lien symbolique, l'extraction sera interrompue avec "AC_ERROR" pour des raisons de sécurité. Tous les répertoires nécessaires seront créés. Retourne "AZ_OK" en cas de succès.
extractMemberWithoutPaths( $memberOrName [, $extractedName ] )
extractMemberWithoutPaths( { memberOrZipName => $memberOrName [, name => $extractedName ] } )
Extrait le membre donné, ou recherche son nom et l'extrait. N'utilise pas les informations de chemin (extrait dans le répertoire courant). Retourne undef si le membre n'existe pas dans ce Zip. Si le deuxième argument optionnel est fourni, utilisez-le comme nom du membre extrait (ses chemins seront également supprimés). Sinon, le nom de fichier interne du membre (sans les chemins) est utilisé comme nom du fichier ou du répertoire extrait. Retourne "AZ_OK" en cas de succès. Si vous ne passez pas $extractedName et que le nom de fichier interne est égal à un lien symbolique local, l'extraction sera interrompue avec "AC_ERROR" pour des raisons de sécurité.
addMember( $member )
addMember( { member => $member } )
Ajoute un membre (éventuellement provenant d'un autre fichier zip) au fichier zip. Retourne le nouveau membre. En général, vous utiliserez addFile(), addDirectory(), addFileOrDirectory(), addString(), ou read() pour ajouter des membres. 
# Move member named 'abc' to end of zip:
my $member = $zip->removeMember( 'abc' );
$zip->addMember( $member );
updateMember( $memberOrName, $fileName )
updateMember( { memberOrZipName => $memberOrName, name => $fileName } )
Met à jour un seul membre à partir du fichier ou du répertoire nommé $fileName. Retourne le membre (éventuellement ajouté ou mis à jour), le cas échéant ; "undef" en cas d'erreur. La comparaison est basée sur lastModTime() et (dans le cas d'un non-répertoire) la taille du fichier.
addFile( $fileName [, $newName, $compressionLevel ] )
addFile( { filename => $fileName [, zipName => $newName, compressionLevel => $compressionLevel } ] )
Ajoute un membre dont les données proviennent d'un fichier externe, en retournant le membre ou undef. Le membre aura son nom de fichier défini sur le nom du fichier externe, et sa desiredCompressionMethod définie sur COMPRESSION_DEFLATED. Les attributs du fichier et l'heure de dernière modification seront définis à partir du fichier. Si le nom donné ne représente pas un fichier ordinaire lisible ou un lien symbolique, undef sera retourné. $fileName doit être dans le format requis pour le système de fichiers local. L'argument optionnel $newName définit le nom de fichier interne sur quelque chose de différent du $fileNamedonné. $newName, s'il est fourni, doit être au format de nom Zip (c'est-à-dire Unix). Le bit de mode texte sera défini si le contenu semble être du texte (comme retourné par l' opérateur perl "-T" ).

NOTE : vous ne devriez pas (en général) utiliser de noms de chemin absolus dans les noms des membres zip, car cela causera des problèmes avec certains outils zip ainsi qu'introduire une faille de sécurité et rendre le zip plus difficile à utiliser.

addDirectory( $directoryName [, $fileName ] )
addDirectory( { directoryName => $directoryName [, zipName => $fileName ] } )
Ajoute un membre créé à partir du nom de répertoire donné. Le nom du répertoire n'a pas besoin de désigner un répertoire existant. Si le répertoire nommé existe, l'heure de modification du fichier et les permissions sont définies à partir du répertoire existant, sinon elles sont définies à maintenant et à des permissions par défaut permissives. $directoryName doit être au format du système de fichiers local. Le deuxième argument optionnel définit le nom du membre de l'archive (qui vaut par défaut $directoryName). S'il est fourni, il doit être au format Zip (Unix). Retourne le nouveau membre.
addFileOrDirectory( $name [, $newName, $compressionLevel ] )
addFileOrDirectory( { name => $name [, zipName => $newName, compressionLevel => $compressionLevel ] } )
Ajoute un membre à partir du fichier ou du répertoire nommé $name. Si $newName est fourni, utilisez-le comme nom du nouveau membre. Ajoutera ou supprimera les barres obliques finales de $newName selon les besoins. $name doit être au format du système de fichiers local. Le deuxième argument optionnel définit le nom du membre de l'archive (qui vaut par défaut $name). S'il est fourni, il doit être au format Zip (Unix).
addString( $stringOrStringRef, $name, [$compressionLevel] )
addString( { string => $stringOrStringRef [, zipName => $name, compressionLevel => $compressionLevel ] } )
Ajoute un membre créé à partir de la chaîne ou de la référence de chaîne donnée. Le nom est donné par le deuxième argument. Retourne le nouveau membre. L'heure de dernière modification sera définie à maintenant, et les attributs du fichier seront définis à des valeurs par défaut permissives. 
my $member = $zip->addString( 'This is a test', 'test.txt' );
contents( $memberOrMemberName [, $newContents ] )
contents( { memberOrZipName => $memberOrMemberName [, contents => $newContents ] } )
Retourne les données non compressées d'un membre particulier, ou undef. 
print "xyz.txt contains " . $zip->contents( 'xyz.txt' );

Peut aussi changer le contenu d'un membre :

$zip->contents( 'xyz.txt', 'This is the new contents' );

Si l'appel attend un tableau comme valeur de retour, il inclura le statut comme deuxième valeur du tableau.

($content, $status) = $zip->contents( 'xyz.txt');

Zip Opérations d'E/S sur les archives

Une archive Zip peut être écrite dans un fichier ou un descripteur de fichier, ou lue depuis l'un d'eux.

writeToFileNamed( { fileName => $fileName } )
Écrit une archive zip dans un fichier nommé. Retourne "AZ_OK" en cas de succès. 
my $status = $zip->writeToFileNamed( 'xx.zip' );
die "error somewhere" if $status != AZ_OK;

Notez que si vous utilisez le même nom qu'un fichier zip existant que vous avez lu, vous écraserez les ZipFileMembers. Écrivez plutôt dans un nom de fichier différent, puis supprimez l'original. Si vous utilisez les overwrite() ou overwriteAs() méthodes, vous pouvez réécrire le zip original de cette manière. $fileName doit être un nom de fichier valide sur votre système.

writeToFileHandle( $fileHandle [, $seekable] )
Écrit une archive zip dans un fichier handle. Retourne AZ_OK en cas de succès. Le deuxième argument optionnel indique s'il faut ou non tenter de se déplacer en arrière pour réécrire les en-têtes. S'il n'est pas fourni, il est défini si le test Perl "-f" renvoie vrai. Cela pourrait échouer sur certains systèmes d'exploitation, cependant. 
my $fh = IO::File->new( 'someFile.zip', 'w' );
unless ( $zip->writeToFileHandle( $fh ) == AZ_OK ) {
    # error handling
}

Si vous passez un fichier handle non déplaçable (comme si vous écrivez dans un pipe ou un socket), passez un deuxième argument faux :

my $fh = IO::File->new( '| cat > somefile.zip', 'w' );
$zip->writeToFileHandle( $fh, 0 );   # fh is not seekable

Si cette méthode échoue lors de l'écriture d'un membre, ce membre et tous ceux qui le suivent renverront faux depuis wasWritten(). Voir writeCentralDirectory() pour une façon de gérer cela. Si vous le souhaitez, vous pouvez écrire des données dans le fichier handle avant de le passer à writeToFileHandle(); cela pourrait être utilisé (par exemple) pour créer des archives auto-extractibles. Cependant, cela ne fonctionne de manière fiable que lors de l'écriture dans un vrai fichier (par opposition à STDOUT ou à d'autres possibles non-fichiers).

Voir examples/selfex.pl pour savoir comment écrire une archive auto-extractible.

writeCentralDirectory( $fileHandle [, $offset ] )
writeCentralDirectory( { fileHandle => $fileHandle [, offset => $offset ] } )
Écrit la structure du répertoire central dans le fichier handle donné.

Retourne AZ_OK en cas de succès. Si on lui donne un $offset, il se déplacera à ce point avant d'écrire. Cela peut être utilisé pour la récupération dans les cas où writeToFileHandle ou writeToFileNamed renvoient une erreur IO due à un manque d'espace sur le fichier de destination.

Vous pouvez tronquer le zip en se déplaçant en arrière puis en écrivant le répertoire :

my $fh = IO::File->new( 'someFile.zip', 'w' );
    my $retval = $zip->writeToFileHandle( $fh );
if ( $retval == AZ_IO_ERROR ) {
    my @unwritten = grep { not $_->wasWritten() } $zip->members();
    if (@unwritten) {
        $zip->removeMember( $member ) foreach my $member ( @unwritten );
        $zip->writeCentralDirectory( $fh,
        $unwritten[0]->writeLocalHeaderRelativeOffset());
    }
}
overwriteAs( $newName )
overwriteAs( { filename => $newName } )
Écrit le zip dans le fichier spécifié, aussi sûrement que possible. Cela est fait en écrivant d'abord dans un fichier temporaire, puis en renommant l'original s'il existe, puis en renommant le fichier temporaire, puis en supprimant l'original renommé s'il existe. Retourne AZ_OK si réussi.
overwrite()
Réécrit dans le fichier zip original. Voir overwriteAs() ci-dessus. Si le zip n'a jamais été lu depuis un fichier, cela génère une erreur.
read( $fileName )
read( { filename => $fileName } )
Lit les en-têtes du fichier zip depuis un fichier zip, en ajoutant de nouveaux membres. Retourne "AZ_OK" ou un code d'erreur. 
my $zipFile = Archive::Zip->new();
my $status = $zipFile->read( '/some/FileName.zip' );
readFromFileHandle( $fileHandle, $filename )
readFromFileHandle( { fileHandle => $fileHandle, filename => $filename } )
Lit les en-têtes du fichier zip depuis un fichier handle déjà ouvert, en ajoutant de nouveaux membres. Ne ferme pas le fichier handle. Retourne "AZ_OK" ou un code d'erreur. Notez que cela nécessite un fichier handle déplaçable ; la lecture depuis un flux n'est pas encore supportée, mais l'utilisation de données en mémoire l'est. 
my $fh = IO::File->new( '/some/FileName.zip', 'r' );
my $zip1 = Archive::Zip->new();
my $status = $zip1->readFromFileHandle( $fh );
my $zip2 = Archive::Zip->new();
$status = $zip2->readFromFileHandle( $fh );

Lire le zip en utilisant des données en mémoire (récursable) :

open my $fh, "<", "archive.zip" or die $!;
my $zip_data = do { local $.; <$fh> };
my $zip = Archive::Zip->new;
open my $dh, "+<", \$zip_data;
$zip->readFromFileHandle ($dh);

Opérations sur l'arborescence Zip

Elles se trouvaient autrefois dans Archive::Zip::Tree mais ont été déplacées dans Archive::Zip. Elles permettent d'opérer sur une arborescence entière de membres ou de fichiers. Un exemple d'utilisation :

use Archive::Zip;
my $zip = Archive::Zip->new();
# add all readable files and directories below . as xyz/*
$zip->addTree( '.', 'xyz' );
# add all readable plain files below /abc as def/*
$zip->addTree( '/abc', 'def', sub { -f && -r } );
# add all .c files below /tmp as stuff/*
$zip->addTreeMatching( '/tmp', 'stuff', '\.c$' );
# add all .o files below /tmp as stuff/* if they aren't writable
$zip->addTreeMatching( '/tmp', 'stuff', '\.o$', sub { ! -w } );
# add all .so files below /tmp that are smaller than 200 bytes as stuff/*
$zip->addTreeMatching( '/tmp', 'stuff', '\.o$', sub { -s < 200 } );
# and write them into a file
$zip->writeToFileNamed('xxx.zip');
# now extract the same files into /tmpx
$zip->extractTree( 'stuff', '/tmpx' );
$zip->addTree( $root, $dest [, $pred, $compressionLevel ] ) -- Ajoute une arborescence de fichiers à un zip
$zip->addTree( { root => $root, zipName => $dest [, select => $pred, compressionLevel => $compressionLevel ] )
$root est la racine de l'arborescence de fichiers et de répertoires à ajouter. C'est un nom de répertoire valide sur votre système. $dest est le nom pour la racine dans le fichier zip (undef ou vide signifie utiliser les chemins relatifs). C'est un nom de répertoire ZIP valide (c'est-à-dire qu'il utilise des barres obliques (/) pour séparer les composants de répertoire). $pred est une référence de sous-programme optionnelle pour sélectionner des fichiers : on lui passe le nom du fichier ou du répertoire potentiel en utilisant $_, et s'il renvoie vrai, le fichier ou le répertoire sera inclus. Par défaut, on ajoute tous les fichiers et répertoires lisibles. Par exemple, utiliser 
my $pred = sub { /\.txt/ };
$zip->addTree( '.', '', $pred );

ajoutera tous les fichiers .txt dans et sous le répertoire courant, en utilisant des noms relatifs, et en rendant les noms identiques dans le fichier zip :

nom original           nom du membre zip
./xyz                   xyz
./a/                    a/
./a/b                   a/b

Pour traduire les chemins absolus en chemins relatifs, passez-les simplement : $zip->addTree( '/c/d', 'a' );

nom original           nom du membre zip
/c/d/xyz                a/xyz
/c/d/a/                 a/a/
/c/d/a/b                a/a/b

Retourne AZ_OK en cas de succès. Notez que cela ne suivra pas les liens symboliques vers des répertoires. Notez également que cela ne vérifie pas la validité des noms de fichiers.

Notez que généralement vous ne voulez pas rendre les noms des membres d'archive zip absolus.

$zip->addTreeMatching( $root, $dest, $pattern [, $pred, $compressionLevel ] )
$zip->addTreeMatching( { root => $root, zipName => $dest, pattern => $pattern [, select => $pred, compressionLevel => $compressionLevel ] } )
$root est la racine de l'arborescence de fichiers et de répertoires à ajouter $dest est le nom pour la racine dans le fichier zip (undef signifie utiliser les chemins relatifs) $pattern est une expression régulière (non ancrée) pour les noms de fichiers à faire correspondre $pred est une référence de sous-programme optionnelle pour sélectionner des fichiers : on lui passe le nom du fichier ou du répertoire potentiel dans $_, et s'il renvoie vrai, le fichier ou le répertoire sera inclus. Par défaut, on ajoute tous les fichiers et répertoires lisibles. Pour ajouter tous les fichiers dans et sous le répertoire courant dont les noms se terminent par ".pl", et les faire extraire dans un sous-répertoire nommé "xyz", faites ceci : 
$zip->addTreeMatching( '.', 'xyz', '\.pl$' )

Pour ajouter tous les fichiers modifiables dans et sous le répertoire nommé "/abc" dont les noms se terminent par ".pl", et les faire extraire dans un sous-répertoire nommé "xyz", faites ceci :

$zip->addTreeMatching( '/abc', 'xyz', '\.pl$', sub { -w } )

Retourne AZ_OK en cas de succès. Notez que cela ne suivra pas les liens symboliques vers des répertoires.

$zip->updateTree( $root [, $dest , $pred , $mirror, $compressionLevel ] );
$zip->updateTree( { root => $root [, zipName => $dest, select => $pred, mirror => $mirror, compressionLevel => $compressionLevel ] } );
Met à jour un fichier zip à partir d'une arborescence de répertoires.

updateTree() prend les mêmes arguments que addTree(), mais vérifie d'abord si le fichier ou le répertoire existe déjà dans le fichier zip, et s'il a été modifié.

Si le quatrième argument $mirror est vrai, alors supprimez tous mes membres si les fichiers correspondants n'ont pas été trouvés.

Retourne un code d'erreur ou AZ_OK si tout va bien.

$zip->extractTree( [ $root, $dest, $volume } ] )
$zip->extractTree( [ { root => $root, zipName => $dest, volume => $volume } ] )
Si vous ne fournissez aucun argument, tous les fichiers du zip seront extraits avec leurs noms d'origine.

Si vous fournissez un argument pour $root, "extractTree" extraira tous les membres dont les noms commencent par $root dans le répertoire courant, en supprimant d'abord $root . $root est au format Zip (Unix). Par exemple,

$zip->extractTree( 'a' );

appliqué à un zip contenant les fichiers : a/x a/b/c ax/d/e d/e extraira :

a/x en ./x

a/b/c en ./b/c

Si vous donnez deux arguments, "extractTree" extrait tous les membres dont les noms commencent par $root. Il traduira $root en $dest pour construire le nom du fichier de destination. $root et $dest sont au format Zip (Unix). Par exemple,

$zip->extractTree( 'a', 'd/e' );

appliqué à un zip contenant les fichiers : a/x a/b/c ax/d/e d/e extraira :

a/x vers d/e/x

a/b/c vers d/e/b/c et ignorera ax/d/e et d/e

Si vous donnez trois arguments, "extractTree" extrait tous les membres dont les noms commencent par $root. Il traduira $root en $dest pour construire le nom du fichier de destination, puis convertira au format du système de fichiers local, en utilisant $volume comme nom du volume de destination.

$root et $dest sont au format Zip (Unix).

$volume est au format du système de fichiers local.

Par exemple, sous Windows,

$zip->extractTree( 'a', 'd/e', 'f:' );

appliqué à un zip contenant les fichiers : a/x a/b/c ax/d/e d/e extraira :

a/x vers f:d/e/x

a/b/c vers f:d/e/b/c et ignorera ax/d/e et d/e

Si vous voulez des chemins absolus (l'exemple précédent utilisait des chemins relatifs au répertoire courant sur le volume de destination), vous pouvez les spécifier dans $dest:

$zip->extractTree( 'a', '/d/e', 'f:' );

appliqué à un zip contenant les fichiers : a/x a/b/c ax/d/e d/e extraira :

a/x vers f:\d\e\x

a/b/c vers f:\d\e\b\c et ignorera ax/d/e et d/e

Si le chemin du fichier extrait traverse un répertoire parent ou un lien symbolique, l'extraction sera interrompue avec "AC_ERROR" pour des raisons de sécurité. Retourne un code d'erreur ou AZ_OK si tout s'est bien passé.

Archive::Zip Variables Globales

$Archive::Zip::UNICODE
Cette variable contrôle la manière dont les noms de fichiers et de répertoires Unicode sont ajoutés à ou extraits d'une archive. Si définie, les noms de fichiers et de répertoires sont considérés comme étant encodés en UTF-8. C'est EXPÉRIMENTAL ET BUGUÉ (il y a certains cas limites sur Win32). Veuillez signaler les problèmes. 
{
    local $Archive::Zip::UNICODE = 1;
    $zip->addFile('Déjà vu.txt');
}

OPÉRATIONS SUR LES MEMBRES

Méthodes de Classe des Membres

Plusieurs constructeurs vous permettent de construire des membres sans les ajouter à une archive zip. Ils fonctionnent de la même manière que les addFile(), addDirectory(), et addString() méthodes d'instance zip décrites ci-dessus, mais ils n'ajoutent pas les nouveaux membres à un zip.

Archive::Zip::Member->newFromString( $stringOrStringRef [, $fileName ] )
Archive::Zip::Member->newFromString( { string => $stringOrStringRef [, zipName => $fileName ] )
Construit un nouveau membre à partir de la chaîne donnée. Retourne undef en cas d'erreur. 
my $member = Archive::Zip::Member->newFromString( 'This is a test' );
my $member = Archive::Zip::Member->newFromString( 'This is a test', 'test.txt' );
my $member = Archive::Zip::Member->newFromString( { string => 'This is a test', zipName => 'test.txt' } );
newFromFile( $fileName [, $zipName ] )
newFromFile( { filename => $fileName [, zipName => $zipName ] } )
Construit un nouveau membre à partir du fichier donné. Retourne undef en cas d'erreur. 
my $member = Archive::Zip::Member->newFromFile( 'xyz.txt' );
newDirectoryNamed( $directoryName [, $zipname ] )
newDirectoryNamed( { directoryName => $directoryName [, zipName => $zipname ] } )
Construit un nouveau membre à partir du répertoire donné. $directoryName doit être un nom valide sur votre système de fichiers ; il n'a pas besoin d'exister.

Si fourni, $zipname sera le nom du membre zip ; il doit être un nom Zip (Unix) valide. S'il n'est pas fourni, il sera converti à partir de $directoryName.

Retourne undef en cas d'erreur.

my $member = Archive::Zip::Member->newDirectoryNamed( 'CVS/' );

Lecture des données de membre de bas niveau

Il est possible d'utiliser des routines de plus bas niveau pour accéder aux flux de données des membres, plutôt que les méthodes extract* et contents(). Par exemple, voici comment imprimer le contenu décompressé d'un membre par morceaux en utilisant ces méthodes :

my ( $member, $status, $bufferRef );
$member = $zip->memberNamed( 'xyz.txt' );
$member->desiredCompressionMethod( COMPRESSION_STORED );
$status = $member->rewindData();
die "error $status" unless $status == AZ_OK;
while ( ! $member->readIsDone() )
{
( $bufferRef, $status ) = $member->readChunk();
die "error $status"
            if $status != AZ_OK && $status != AZ_STREAM_END;
# faire quelque chose avec $bufferRef :
print $$bufferRef;
}
$member->endRead();
readChunk( [ $chunkSize ] )
readChunk( [ { chunkSize => $chunkSize } ] )
Ceci lit le prochain morceau de la taille donnée depuis le flux de données du membre et le compresse ou le décompresse si nécessaire, retournant une référence aux octets lus et un statut. Si l'argument de taille n'est pas donné, la valeur par défaut est celle définie globalement par Archive::Zip::setChunkSize. Le statut est AZ_OK en cas de succès jusqu'au dernier morceau, où il retourne AZ_STREAM_END. Retourne "( \$bytes, $status)". 
my ( $outRef, $status ) = $self->readChunk();
print $$outRef if $status != AZ_OK && $status != AZ_STREAM_END;
rewindData()
Rembobine les données et prépare la lecture des flux de données ou l'écriture des fichiers zip. Peut prendre des options pour inflateInit() ou deflateInit(), mais cela n'est probablement pas nécessaire. Les redéfinitions dans les sous-classes devraient appeler cette méthode. Retourne "AZ_OK" en cas de succès.
endRead()
Réinitialise les variables de lecture et libère le décompresseur ou le compresseur. Doit être appelé pour fermer les fichiers, etc. Retourne AZ_OK en cas de succès.
readIsDone()
Retourne vrai si la lecture a épuisé les données ou a rencontré une erreur.
contents()
Retourne toutes les données décompressées du membre ou undef en contexte scalaire. Lorsqu'elle est appelée en contexte tableau, elle retourne "( $string, $status )"; le statut sera AZ_OK en cas de succès : 
my $string = $member->contents();
# ou
my ( $string, $status ) = $member->contents();
die "error $status" unless $status == AZ_OK;

Peut aussi être utilisée pour définir le contenu d'un membre (cela peut changer la classe du membre) :

$member->contents( "voici mon nouveau contenu" );
extractToFileHandle( $fh )
extractToFileHandle( { fileHandle => $fh } )
Extrait (et décompresse, si nécessaire) le contenu du membre vers la poignée de fichier donnée. Retourne AZ_OK en cas de succès.

Pour les membres représentant des liens symboliques, passez le nom du lien symbolique comme poignée de fichier. Assurez-vous que tous les répertoires dans le chemin vers le lien symbolique existent déjà.

La classe Archive::Zip::FileMember étend Archive::Zip::Member. C'est la classe de base des classes ZipFileMember et NewFileMember. Cette classe ajoute un "externalFileName" et un "fh" membre pour garder la trace du fichier externe.

externalFileName()
Retourne le nom de fichier externe du membre.
fh()
Retourne le descripteur de fichier de lecture du membre. Ouvre automatiquement le fichier si nécessaire.

Archive::Zip::ZipFileMember méthodes

La classe Archive::Zip::ZipFileMember représente les membres qui ont été lus depuis des fichiers zip externes.

diskNumberStart()
Retourne le numéro de disque où se trouve l'en-tête local du membre. Devrait être 0.
localHeaderRelativeOffset()
Retourne le décalage dans le fichier zip où se trouve l'en-tête local du membre.
dataOffset()
Retourne le décalage depuis le début du fichier zip jusqu'aux données du membre.

BUGS ET RÉSERVES

Quand ne pas utiliser Archive::Zip

Si vous ne faites qu'extraire des fichiers zip (et/ou d'autres archives), il est recommandé d'utiliser Archive::Extract à la place, car il est beaucoup plus facile à utiliser et isole les fonctionnalités spécifiques aux archives.

Prise en charge du format Zip64

Depuis la version 1.66, Archive::Zip prend en charge le format dit zip64, qui surmonte diverses limitations du format de fichier zip original. Sur certains interpréteurs Perl, cependant, même la version 1.11 et plus récente d'Archive::Zip ne peut pas prendre en charge le format zip64. Parmi ceux-ci figurent tous les interpréteurs Perl dépourvus de prise en charge 64 bits et ceux antérieurs à la version 5.10.0.

Constante "ZIP64_SUPPORTED", exportée avec le tag :CONSTANTS, est vraie si Archive::Zip sur l'interpréteur Perl actuel prend en charge le format zip64. S'il ne le prend pas et que vous essayez quand même de lire ou d'écrire une archive au format zip64, Archive::Zip renvoie une erreur "AZ_ERROR" et signale un message d'erreur du type « zip64 format not supported on this Perl interpreter ».

"versionMadeBy" et "versionNeededToExtract"

Le format zip64 et le format de fichier zip en général spécifient quelles valeurs utiliser pour les champs "versionMadeBy" et "versionNeededToExtract" dans l'en-tête de fichier local, l'en-tête de fichier du répertoire central et l'enregistrement EOCD zip64. En pratique, cependant, ces champs semblent être utilisés plus ou moins aléatoirement par diverses implémentations d'archivers.

Pour trouver un compromis entre la rétrocompatibilité et la conformité (quelconque) aux normes, Archive::Zip les gère comme suit :

  • Pour le champ "versionMadeBy", Archive::Zip utilise la valeur par défaut 20 (45 pour l'enregistrement EOCD zip64) ou toute valeur lue précédemment. Il ne change jamais cette valeur lors de l'écriture d'un en-tête, même s'il est écrit au format zip64, ni lors de l'écriture de l'enregistrement EOCD zip64.
  • De même pour le champ "versionNeededToExtract", mais ici Archive::Zip force une valeur minimale de 45 lors de l'écriture d'un en-tête au format zip64 ou de l'enregistrement EOCD zip64.
  • Enfin, Archive::Zip ne dépend jamais des valeurs de ces champs d'aucune manière lors de la lecture d'une archive depuis un fichier ou un descripteur de fichier.

Essayer d'éviter IO::Scalar

L'une des façons les plus courantes d'utiliser Archive::Zip est de générer des fichiers Zip en mémoire. La plupart des gens utilisent IO::Scalar à cette fin.

Malheureusement, à partir de la version 1.11, ce module ne fonctionne plus avec IO::Scalar car il implémente incorrectement le positionnement (seeking).

Toute personne utilisant IO::Scalar devrait envisager de migrer vers IO::String, qui est plus petit, plus léger et est implémenté pour être parfaitement compatible avec les descripteurs de fichier positionnables ordinaires.

La prise en charge de IO::Scalar ne sera très probablement pas rétablie à l'avenir, car IO::Scalar lui-même ne peut pas changer sa façon d'être implémenté en raison de problèmes de rétrocompatibilité.

Mot de passe incorrect pour les membres chiffrés

Lorsqu'un membre chiffré est lu avec le mauvais mot de passe, vous devez actuellement relire l'archive entière pour réessayer avec le bon mot de passe.
