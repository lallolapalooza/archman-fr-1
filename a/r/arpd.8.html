ARPD(8) Manuel de l'administrateur système ARPD(8)

NOM

arpd - démon userspace pour ARP.

SYNTAXE

Usage : arpd [ -lkh? ] [ -a N ] [ -b dbase ] [ -B nombre ] [ -f fichier ] [-p intervalle ] [ -n temps ] [ -R taux ] [ <INTERFACES> ]

DESCRIPTION

Le démon arpd collecte les informations ARP gratuites, les sauvegarde sur le disque local et les fournit au noyau sur demande pour éviter des diffusions redondantes dues à la taille limitée du cache ARP du noyau.

OPTIONS

-h -?
Afficher l'aide
-l
Extraire la base de données arpd sur la sortie standard et quitter. La sortie consiste en trois colonnes : l'index de l'interface, l'adresse IP de l'interface et l'adresse MAC de l'interface. Les entrées négatives pour les hôtes inactifs sont également affichées, dans ce cas l'adresse MAC est remplacée par le mot FAILED suivi d'un deux-points et du dernier moment où le fait que l'hôte est inactif a été prouvé.
-f <FICHIER>
Lire et charger une base de données arpd depuis FICHIER dans un format texte similaire à celui extrait par l'option -l. Quitter après le chargement, en affichant éventuellement la base de données résultante, si l'option -l est également donnée. Si FICHIER est -, stdin est lu pour obtenir la table ARP.
-b <BASE_DE_DONNEES>
l'emplacement du fichier de base de données. L'emplacement par défaut est /var/lib/arpd/arpd.db
-a <NOMBRE>
Avec cette option, arpd n'écoute pas seulement passivement les paquets ARP sur l'interface, mais envoie également des requêtes de diffusion lui-même. NOMBRE est le nombre de ces requêtes à effectuer avant qu'une destination ne soit considérée comme morte. Lorsque arpd est démarré comme assistant du noyau (c'est-à-dire avec app_solicit activé dans sysctl ou même avec l'option -k) sans cette option et n'a pas encore appris suffisamment d'informations, vous pouvez observer des interruptions de service de 1 seconde. Non fatal, mais pas idéal.
-k
Supprimer l'envoi de requêtes de diffusion par le noyau. Cette option n'a de sens qu'avec l'option -a.
-n <TEMPS>
Spécifie le délai d'expiration du cache négatif. En cas d'échec de résolution, arpd supprime les tentatives ultérieures de résolution pendant cette période. Cette option n'a de sens qu'avec l'option '-k'. Ce délai ne doit pas être beaucoup plus long que le temps de démarrage d'un hôte typique ne prenant pas en charge l'ARP gratuit. La valeur par défaut est de 60 secondes.
-p <TEMPS>
Le temps d'attente en secondes entre les tentatives de scrutation de la table ARP du noyau. TEMPS peut être un nombre à virgule flottante. La valeur par défaut est 30.
-R <TAUX>
Taux de base maximal des diffusions envoyées par arpd en paquets par seconde. La valeur par défaut est 1.
-B <NOMBRE>
Le nombre de diffusions envoyées par arpd les unes à la suite des autres. La valeur par défaut est 3. Avec l'option -R, cette option garantit que le nombre de requêtes ARP qui sont diffusées ne dépasse pas B+R*T sur n'importe quel intervalle de temps T.

<INTERFACES> est une liste de noms d'interfaces réseau à surveiller. Si aucune interface n'est donnée, arpd surveille toutes les interfaces. Dans ce cas, arpd n'ajuste pas les paramètres sysctl, il est supposé que l'utilisateur le fait lui-même après le démarrage d'arpd.

SIGNaux

Lorsque arpd reçoit un signal SIGINT ou SIGTERM, il se termine gracieusement, synchronisant la base de données et restaurant les paramètres sysctl ajustés. Avec SIGHUP il synchronise la base de données sur le disque. Avec SIGUSR1 il envoie des statistiques à syslog. L'effet de tout autre signal est indéfini. En particulier, ils peuvent corrompre la base de données et laisser les paramètres sysctl dans un état imprévisible.

NOTE

Pour que arpd puisse servir de résolveur ARP, le noyau doit être compilé avec l'option CONFIG_ARPD et, dans le cas où la liste des interfaces n'est pas donnée sur la ligne de commande, la variable app_solicit sur les interfaces d'intérêt devrait se trouver dans /proc/sys/net/ipv4/neigh/*. Si ce n'est pas fait, arpd collecte toujours les informations ARP gratuites dans sa base de données.

EXEMPLES

arpd -b /var/tmp/arpd.db
Démarrer arpd pour collecter les ARP gratuits, sans interférer avec les fonctionnalités du noyau.
killall arpd ; arpd -l -b /var/tmp/arpd.db
Examiner le résultat après un certain temps.
arpd -b /var/tmp/arpd.db -a 1 eth0 eth1
Activer l'assistant du noyau, laissant le rôle principal au noyau.
arpd -b /var/tmp/arpd.db -a 3 -k eth0 eth1
Remplacer complètement la résolution du noyau sur les interfaces eth0 et eth1. Dans ce cas, le noyau effectue toujours des sondes unicast pour valider les entrées, mais toute l'activité de diffusion est supprimée et gérée par arpd.

C'est le mode dans lequel arpd est normalement censé fonctionner. Ce n'est pas le défaut afin d'éviter l'activation occasionnelle d'un mode trop agressif.
