val length : 'a array ->

int

Renvoie la longueur (le nombre d'éléments) du tableau

donné.

val get : 'a array -> int ->

'a

get a n renvoie l'élément numéro n du tableau a . Le premier élément porte le numéro 0. Le dernier élément porte le numéro length a - 1 . Vous pouvez aussi écrire a.(n) au lieu de get a n

.

Lève Invalid_argument si n est en dehors de l'intervalle 0 à (length a - 1)

.

val set : 'a array -> int -> 'a ->

unit

set a n x modifie le tableau a sur place, en remplaçant l'élément numéro n par x . Vous pouvez aussi écrire a.(n) <- x au lieu de set a n x

.

Lève Invalid_argument si n est en dehors de l'intervalle 0 à length a - 1

.

val make : int -> 'a -> 'a

array

make n x renvoie un nouveau tableau de longueur n , initialisé avec x . Tous les éléments de ce nouveau tableau sont initialement physiquement égaux à x (au sens du prédicat ==). Par conséquent, si x est mutable, il est partagé entre tous les éléments du tableau, et modifier x à travers l'une des entrées du tableau modifiera toutes les autres entrées en même

temps.

Lève Invalid_argument si n < 0 ou n > Sys.max_array_length . Si la valeur de x est un nombre à virgule flottante, alors la taille maximale n'est que de Sys.max_array_length / 2

.

val create_float : int -> float

array

create_float n renvoie un nouveau tableau de flottants de longueur n , avec des données non

initialisées.

val init : int -> f:(int -> 'a) -> 'a

array

init n ~f renvoie un nouveau tableau de longueur n , où l'élément numéro i est initialisé au résultat de f i . En d'autres termes, init n ~f tabule les résultats de f appliquée dans l'ordre aux entiers 0 à n-1

.

Lève Invalid_argument si n < 0 ou n > Sys.max_array_length . Si le type de retour de f est float , alors la taille maximale n'est que de Sys.max_array_length / 2

.

val make_matrix : dimx:int -> dimy:int -> 'a -> 'a array

array

make_matrix ~dimx ~dimy e renvoie un tableau à deux dimensions (un tableau de tableaux) avec pour première dimension dimx et pour seconde dimension dimy . Tous les éléments de cette nouvelle matrice sont initialement physiquement égaux à e . L'élément ( x,y ) d'une matrice m est accessible avec la notation m.(x).(y)

.

Lève Invalid_argument si dimx ou dimy est négatif ou supérieur à Sys.max_array_length . Si la valeur de e est un nombre à virgule flottante, alors la taille maximale n'est que de Sys.max_array_length / 2

.

val sub : 'a array -> pos:int -> len:int -> 'a

array

sub a ~pos ~len renvoie un nouveau tableau de longueur len , contenant les éléments numéros pos à pos + len - 1 du tableau a

.

Lève Invalid_argument si pos et len ne désignent pas un sous-tableau valide de a ; c'est-à-dire si pos < 0 , ou len < 0 , ou pos + len > length a

.

val copy : 'a array -> 'a

array

copy a renvoie une copie de a , c'est-à-dire un nouveau tableau contenant les mêmes éléments que a

.

val fill : 'a array -> pos:int -> len:int -> 'a ->

unit

fill a ~pos ~len x modifie le tableau a sur place, en stockant x dans les éléments numéros pos à pos + len - 1

.

Lève Invalid_argument si pos et len ne désignent pas un sous-tableau valide de a

.

val blit : src:'a array -> src_pos:int -> dst:'a array -> dst_pos:int -> len:int ->

unit

blit ~src ~src_pos ~dst ~dst_pos ~len copie len éléments depuis le tableau src , en commençant à l'élément numéro src_pos , vers le tableau dst , en commençant à l'élément numéro dst_pos . Cela fonctionne correctement même si src et dst sont le même tableau, et que les portions source et destination se

chevauchent.

Lève Invalid_argument si src_pos et len ne désignent pas un sous-tableau valide de src , ou si dst_pos et len ne désignent pas un sous-tableau valide de dst

.

val of_list : 'a list -> 'a

array

of_list l renvoie un nouveau tableau contenant les éléments de l

iter ~f a applique la fonction f tour à tour à tous les éléments de a . C'est équivalent à f a.(0); f a.(1); ...; f a.(length a - 1); ()

val sort : cmp:('a -> 'a -> int) -> 'a array ->

unit

Trie un tableau dans l'ordre croissant selon une fonction de comparaison. La fonction de comparaison doit renvoyer 0 si ses arguments sont égaux, un entier positif si le premier est plus grand, et un entier négatif si le premier est plus petit (voir ci-dessous pour une spécification complète). Par exemple, compare est une fonction de comparaison appropriée. Après avoir appelé sort , le tableau est trié sur place dans l'ordre croissant. sort est garanti de s'exécuter en espace de tas constant et en espace de pile (au plus)

logarithmique.

L'implémentation actuelle utilise le tri par tas. Elle s'exécute en espace de pile

constant.

Tableaux et sécurité de

concurrence

Il faut faire attention lors de l'accès concurrent à des tableaux depuis plusieurs dom

aines : l'accès à un tableau ne fera jamais planter un programme, mais des accès non s
ynchronisés peuvent donner des résultats surprenants (non séquentiellement cohérents).

Atomicit

é

Toute opération sur un tableau qui accède à plus d'un élément du tableau n'est pas atomique. Cela inclut l'itération, la recherche, le tri, la séparation et la combinaison de

tableaux.

Par exemple, considérez le programme suivant

: 
let size = 100_000_000
let a = ArrayLabels.make size 1
let d1 = Domain.spawn (fun () ->
   ArrayLabels.iteri ~f:(fun i x -> a.(i) <- x + 1) a
)
let d2 = Domain.spawn (fun () ->
  ArrayLabels.iteri ~f:(fun i x -> a.(i) <- 2 * x + 1) a
)
let () = Domain.join d1; Domain.join d2

Après l'exécution de ce code, chaque champ du tableau a est soit 2 , 3 , 4 ou 5 . Si l'atomicité est requise, l'utilisateur doit alors implémenter sa propre synchronisation (par exemple, en utilisant Mutex.t

)
.

Conditions de concurrence (data

races)

Si deux domaines n'accèdent qu'à des parties disjointes du tableau, alors le comportement observé est équivalent à une certaine imbrication séquentielle des opérations des deux

domaines.

Un une condition de course (data race) est dite survenir lorsque deux domaines accèdent au même élément de tableau sans synchronisation et qu'au moins un des accès est une écriture. En l'absence de conditions de course, le comportement observé est équivalent à un entrelacement séquentiel des opérations provenant de différents

domaines.

Chaque fois que possible, les conditions de course devraient être évitées en utilisant la synchronisation pour médiatiser les accès aux éléments du

tableau.

En effet, en présence de conditions de course, les programmes ne planteront pas mais le comportement observé peut ne pas être équivalent à un

quelconque entrelacement séquentiel d'opérations provenant de différents domaines. Néanmoins, même en présence de conditions de course, une o
pération de lecture renverra la valeur d'une écriture antérieure à cet emplacement (avec quelques exceptions pour les tableaux de flottants).

Tableaux de

flottants

Les tableaux de flottants présentent deux avertissements supplémentaires en présence de conditions de

course.

Tout d'abord, l'opération blit peut copier un tableau octet par octet. Des conditions de course entre une telle opération blit et une autre opération peuvent produire des valeurs surprenantes en raison du déchirement (tearing) : des écritures partielles entrelacées avec d'autres opérations peuvent créer des valeurs de flottants qui n'existeraient pas avec une exécution

séquentielle.

Par exemple, à la fin

de 
let zeros = Array.make size 0.
let max_floats = Array.make size Float.max_float
let res = Array.copy zeros
let d1 = Domain.spawn (fun () -> Array.blit zeros 0 res 0 size)
let d2 = Domain.spawn (fun () -> Array.blit max_floats 0 res 0 size)
let () = Domain.join d1; Domain.join d2
le tableau res pourrait contenir des valeurs qui ne sont ni 0. ni max_float .
