val length : 'a array ->

int

Renvoie la longueur (nombre d'éléments) du tableau

donné.

val get : 'a array -> int ->

'a

get a n renvoie l'élément numéro n du tableau a . Le premier élément porte le numéro 0. Le dernier élément porte le numéro length a - 1 . Vous pouvez aussi écrire a.(n) au lieu de get a n

.

Lève Invalid_argument si n est en dehors de l'intervalle 0 à (length a - 1)

.

val set : 'a array -> int -> 'a ->

unit

set a n x modifie le tableau a sur place, en remplaçant l'élément numéro n par x . Vous pouvez aussi écrire a.(n) <- x au lieu de set a n x

.

Lève Invalid_argument si n est en dehors de l'intervalle 0 à length a - 1

.

val make : int -> 'a -> 'a

array

make n x renvoie un nouveau tableau de longueur n , initialisé avec x . Tous les éléments de ce nouveau tableau sont initialement physiquement égaux à x (au sens du prédicat ==). Par conséquent, si x est mutable, il est partagé entre tous les éléments du tableau, et modifier x à travers l'une des entrées du tableau modifiera toutes les autres entrées en même

temps.

Lève Invalid_argument si n < 0 ou n > Sys.max_array_length . Si la valeur de x est un nombre à virgule flottante, alors la taille maximale est seulement Sys.max_array_length / 2

.

val create_float : int -> float

array

create_float n renvoie un nouveau tableau de flottants de longueur n , avec des données non

initialisées.

val init : int -> (int -> 'a) -> 'a

array

init n f renvoie un nouveau tableau de longueur n , où l'élément numéro i est initialisé avec le résultat de f i . En d'autres termes, init n f tabule les résultats de f appliqué dans l'ordre aux entiers 0 à n-1

.

Lève Invalid_argument si n < 0 ou n > Sys.max_array_length . Si le type de retour de f est float , alors la taille maximale est seulement Sys.max_array_length / 2

.

val make_matrix : int -> int -> 'a -> 'a array

array

make_matrix dimx dimy e renvoie un tableau bidimensionnel (un tableau de tableaux) avec la première dimension dimx et la deuxième dimension dimy . Tous les éléments de cette nouvelle matrice sont initialement physiquement égaux à e . L'élément ( x,y ) d'une matrice m est accessible avec la notation m.(x).(y)

.

Lève Invalid_argument si dimx ou dimy est négatif ou supérieur à Sys.max_array_length . Si la valeur de e est un nombre à virgule flottante, alors la taille maximale est seulement Sys.max_array_length / 2

.

val init_matrix : int -> int -> (int -> int -> 'a) -> 'a array

array

init_matrix dimx dimy f renvoie un tableau bidimensionnel (un tableau de tableaux) avec la première dimension dimx et la deuxième dimension dimy , où l'élément à l'indice ( x,y ) est initialisé avec f x y . L'élément ( x,y ) d'une matrice m est accessible avec la notation m.(x).(y)

.

val sub : 'a array -> int -> int -> 'a

array

sub a pos len renvoie un nouveau tableau de longueur len , contenant les éléments numéro pos à pos + len - 1 du tableau a

.

Lève Invalid_argument si pos et len ne désignent pas un sous-tableau valide de a ; c'est-à-dire, si pos < 0 , ou len < 0 , ou pos + len > length a

.

val copy : 'a array -> 'a

array

copy a renvoie une copie de a , c'est-à-dire, un nouveau tableau contenant les mêmes éléments que a

.

val fill : 'a array -> int -> int -> 'a ->

unit

fill a pos len x modifie le tableau a sur place, en stockant x dans les éléments numéro pos à pos + len - 1

.

Lève Invalid_argument si pos et len ne désignent pas un sous-tableau valide de a

.

val blit : 'a array -> int -> 'a array -> int -> int ->

unit

blit src src_pos dst dst_pos len copie len éléments du tableau src , à partir de l'élément numéro src_pos , vers le tableau dst , à partir de l'élément numéro dst_pos . Cela fonctionne correctement même si src et dst sont le même tableau, et que les morceaux source et destination se

chevauchent.

Lève Invalid_argument si src_pos et len ne désignent pas un sous-tableau valide de src , ou si dst_pos et len ne désignent pas un sous-tableau valide de dst

.

val to_list : 'a array -> 'a

list

to_list a renvoie la liste de tous les éléments de a

.

val of_list : 'a list -> 'a

array

of_list l renvoie un nouveau tableau contenant les éléments de l

.

Lève Invalid_argument si la longueur de l est supérieure à Sys.max_array_l

val iter : ('a -> unit) -> 'a array ->

unit

iter f a applique la fonction f à tour de rôle à tous les éléments de a . C'est équivalent à f a.(0); f a.(1); ...; f a.(length a - 1); ()

.

val iteri : (int -> 'a -> unit) -> 'a array ->

Identique à Array.iter , mais la fonction est appliquée à l'indice de l'élément comme premier argument, et à l'élément lui-même comme deuxième

map f a applique la fonction f à tous les éléments de a , et construit un tableau avec les résultats renvoyés par f : [| f a.(0); f a.(1); ...; f a.(length a - 1) |]

.

val sort : ('a -> 'a -> int) -> 'a array ->

unit

Trie un tableau dans l'ordre croissant selon une fonction de comparaison. La fonction de comparaison doit retourner 0 si ses arguments sont égaux, un entier positif si le premier est plus grand, et un entier négatif si le premier est plus petit (voir ci-dessous pour une spécification complète). Par exemple, compare est une fonction de comparaison appropriée. Après avoir appelé sort , le tableau est trié sur place dans l'ordre croissant. sort est garanti de s'exécuter en espace de tas constant et en espace de pile (au plus)

logarithmique.

L'implémentation actuelle utilise le tri par tas. Elle s'exécute en espace de pile

constant.

Spécification de la fonction de comparaison : Soit a le tableau et cmp la fonction de comparaison. Les conditions suivantes doivent être vraies pour tous x , y , z dans a

:

- cmp x y > 0 si et seulement si cmp y x <

0

- si cmp x y >= 0 et cmp y z >= 0 alors cmp x z >=

0

Quand sort retourne, a contient les mêmes éléments qu'avant, réordonnés de telle manière que pour tout i et j indices valides de a

:

- cmp a.(i) a.(j) >= 0 si i >=

j

val stable_sort : ('a -> 'a -> int) -> 'a array ->

unit

Identique à Array.sort , mais l'algorithme de tri est stable (c'est-à-dire que les éléments qui sont égaux sont conservés dans leur ordre d'origine) et n'est pas garanti de s'exécuter en espace de tas

constant.

L'implémentation actuelle utilise le tri fusion. Elle utilise un tableau temporaire de longueur n/2 , où n est la longueur du tableau. Elle est généralement plus rapide que l'implémentation actuelle de Array.so

rt .

val fast_sort : ('a -> 'a -> int) -> 'a array ->

unit

Identique à Array.sort ou Array.stable_sort , selon ce qui est le plus rapide sur des entrées

typiques.

val shuffle : rand:(int -> int) -> 'a array ->

unit

shuffle rand permute aléatoirement les éléments de a en utilisant rand pour la randomisation. La distribution des permutations est

uniforme.

rand doit être tel qu'un appel à rand n retourne un nombre aléatoire distribué uniformément dans l'intervalle [ 0 ; n-1 ]. Random.int peut être utilisé pour cela (n'oubliez pas de Random.self_init le générateur)

.

Tableaux et sécurité de

concurrence

Il faut faire attention lors de l'accès concurrent à des tableaux depuis plusieurs do

maines : l'accès à un tableau ne fera jamais planter un programme, mais des accès no
n synchronisés peuvent donner des résultats surprenants (non séquentiellement cohérents).

Atomicit

é

Toute opération sur un tableau qui accède à plus d'un élément du tableau n'est pas atomique. Cela inclut l'itération, la recherche, le tri, la séparation et la combinaison de

tableaux.

Par exemple, considérez le programme suivant

: 
let size = 100_000_000
let a = Array.make size 1
let d1 = Domain.spawn (fun () ->
   Array.iteri (fun i x -> a.(i) <- x + 1) a
)
let d2 = Domain.spawn (fun () ->
  Array.iteri (fun i x -> a.(i) <- 2 * x + 1) a
)
let () = Domain.join d1; Domain.join d2

Après l'exécution de ce code, chaque champ du tableau a est soit 2 , 3 , 4 ou 5 . Si l'atomicité est requise, l'utilisateur doit implémenter sa propre synchronisation (par exemple, en utilisant Mutex.t

)
.

Conditions de concurrence (data

races)

Si deux domaines n'accèdent qu'à des parties disjointes du tableau, alors le comportement observé est équivalent à un entrelacement séquentiel des opérations des deux

domaines.

Une condition de concurrence (data race) se produit lorsque deux domaines accèdent au même élément de tableau sans synchronisation et qu'au moins un des accès est une écriture. En l'absence de conditions de concurrence, le comportement observé est équivalent à un entrelacement séquentiel des opérations de différentst

domaines.

Dans la mesure du possible, les conditions de course (data races) doivent être évitées en utilisant la synchronisation pour arbitrer les accès aux éléments du

tableau.

En effet, en présence de conditions de course, les programmes ne planteront pas mais le comportement observé peut ne correspondre à aucun

entrelacement séquentiel des opérations issues de domaines différents. Néanmoins, même en présence de conditions de course, une opéra
tion de lecture renverra la valeur d'une écriture antérieure à cet emplacement (avec quelques exceptions pour les tableaux de flottants).

Tableaux de

flottants

Les tableaux de flottants présentent deux avertissements supplémentaires en présence de conditions de

course.

Tout d'abord, l'opération blit peut copier un tableau octet par octet. Des conditions de course entre une telle opération blit et une autre opération peuvent produire des valeurs surprenantes en raison de la déchirure (tearing) : des écritures partielles entrelacées avec d'autres opérations peuvent créer des valeurs flottantes qui n'existeraient pas avec une exécution

séquentielle.

Par exemple, à la fin

de 
let zeros = Array.make size 0.
let max_floats = Array.make size Float.max_float
let res = Array.copy zeros
let d1 = Domain.spawn (fun () -> Array.blit zeros 0 res 0 size)
let d2 = Domain.spawn (fun () -> Array.blit max_floats 0 res 0 size)
let () = Domain.join d1; Domain.join d2
le tableau res peut contenir des valeurs qui ne sont ni 0. ni max_float .
