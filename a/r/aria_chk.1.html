ARIA_CHK(1) Commandes utilisateur ARIA_CHK(1)

NOM

aria_chk - Utilitaire de maintenance des tables Aria

SYNTAXE

aria_chk [OPTIONS] tables[.MAI]

DESCRIPTION

Description, vérification et réparation des tables Aria. Utilisé sans options, toutes les tables spécifiées seront vérifiées pour détecter les erreurs.

Options globales

-#, --debug=...
Sortie du journal de débogage. Souvent de la forme 'd:t:o,nom_fichier'.
-H, --HELP
Imprime toutes les options d'arguments triées par ordre alphabétique.
-?, --help
Imprime toutes les options par groupes.
--datadir=chemin
Chemin du fichier de contrôle (et des journaux si --logdir n'est pas utilisé).
--logdir=chemin
Chemin des fichiers journaux.
--ignore-control-file
Ne pas ouvrir le fichier de contrôle. Utilisez cette option uniquement si vous êtes sûr que les tables ne sont pas utilisées par un autre programme !
--require-control-file
Arrêter si le fichier maria_log_control n'est pas trouvé/lu.
-s, --silent
N'imprime que les erreurs. On peut utiliser deux -s pour rendre maria_chk très silencieux.
-t, --tmpdir=chemin
Chemin des fichiers temporaires. Plusieurs chemins peuvent être spécifiés, séparés par deux points (:), ils seront utilisés en alternance.
-v, --verbose
Imprime plus d'informations. Peut être utilisé avec --description et --check. Utilisez plusieurs -v pour plus de verbosité.
-V, --version
Imprime la version et quitte.
-w, --wait
Attend si la table est verrouillée.

Options de vérification (la vérification est l'action par défaut pour aria_chk)

-c, --check
Vérifie la table pour détecter les erreurs.
-e, --extend-check
Vérifie la table TRÈS minutieusement. N'utilisez cette option que dans des cas extrêmes, car aria_chk devrait normalement pouvoir déterminer si la table est correcte même sans ce commutateur.
-F, --fast
Ne vérifie que les tables qui n'ont pas été fermées correctement.
-C, --check-only-changed
Ne vérifie que les tables qui ont changé depuis la dernière vérification.
-f, --force
Redémarre avec '-r' s'il y a des erreurs dans la table. Les états seront mis à jour comme avec '--update-state'.
-i, --information
Imprime des informations statistiques sur la table vérifiée.
-m, --medium-check
Plus rapide que extend-check, mais ne trouve que 99,99 % de toutes les erreurs. Devrait être suffisant dans la plupart des cas.
-T, --read-only
Ne marque pas la table comme vérifiée.
-U, --update-state
Marque les tables comme corrompues si des erreurs sont trouvées et nettes si la vérification n'a trouvé aucune erreur mais que la table était marquée comme 'non nette' auparavant. Cela permet de se débarrasser des avertissements tels que 'table not properly closed'. Si la table a été mise à jour, mettez également à jour l'horodatage de la vérification. Cette option est activée par défaut ! Utilisez --skip-update-state pour la désactiver.

--warning-for-wrong-transaction-id

Donne un avertissement si un identifiant de transaction est trouvé dans la table et qu'il est supérieur à celui présent dans le fichier de contrôle. Utilisez --skip-... pour désactiver l'avertissement.

Récupération (réparation)/ options (Lors de l'utilisation de '--recover' ou '--safe-recover')

-B, --backup
Crée une sauvegarde du fichier .MAD sous forme de 'nom_fichier-horodatage.BAK'.
--correct-checksum
Corrige les informations de checksum pour la table.
-D, --data-file-length=#
Longueur maximale du fichier de données (lors de la recréation du fichier de données lorsqu'il est plein).
-e, --extend-check
Tente de récupérer toutes les lignes possibles du fichier de données. Normalement, cela trouvera également beaucoup de lignes inutiles ; N'utilisez pas cette option si vous n'êtes pas totalement désespéré.
-f, --force
Écrase les anciens fichiers temporaires.
-k, --keys-used=#
Indique à Aria de n'utiliser que certaines clés spécifiques. # est un masque de bits indiquant les clés à utiliser. Ceci peut être utilisé pour accélérer les insertions.
--max-record-length=#
Ignore les lignes plus grandes que cette valeur si aria_chk ne peut pas allouer de mémoire pour les contenir.
-r, --recover
Peut réparer presque tout sauf les clés uniques qui ne sont pas uniques.
-n, --sort-recover
Force la récupération par tri, même si le fichier temporaire serait très grand.
-p, --parallel-recover
Utilise la même technique que '-r' et '-n', mais crée toutes les clés en parallèle, dans des threads différents.
-o, --safe-recover
Utilise l'ancienne méthode de récupération ; Plus lente que '-r' mais peut gérer quelques cas où '-r' signale qu'il ne peut pas réparer le fichier de données.
--transaction-log
Journalise la commande de réparation dans le journal des transactions. Ceci est nécessaire si l'on souhaite utiliser aria_read_log pour répéter la réparation.
--character-sets-dir=...
Répertoire où se trouvent les jeux de caractères.
--set-collation=nom
Change la collation utilisée par l'index.
-q, --quick
Récupération plus rapide en ne modifiant pas le fichier de données. On peut donner un deuxième '-q' pour forcer aria_chk à modifier le fichier de données d'origine en cas de clés dupliquées. NOTE : Les tables dont le fichier de données est corrompu ne peuvent pas être réparées avec cette option.
-u, --unpack
Décompresse un fichier compressé avec ariapack.

Autres actions

-a, --analyze
Analyse la distribution des clés. Cela rendra certaines jointures dans MariaDB plus rapides. Vous pouvez vérifier la distribution calculée en utilisant '--description --verbose nom_table'.
--stats_method=nom
Spécifie comment le code de collecte des statistiques d'index doit traiter les NULL. Les valeurs possibles de nom sont "nulls_unequal" (par défaut pour 4.1/5.0), "nulls_equal" (émuler 4.0) et "nulls_ignored".
-d, --description
Imprime des informations sur la table.
-A, --set-auto-increment[=valeur]
Force auto_increment à démarrer à cette valeur ou à une valeur supérieure. Si aucune valeur n'est donnée, la prochaine valeur de auto_increment est définie sur la valeur la plus élevée utilisée pour la clé auto + 1.
-S, --sort-index
Trie les blocs d'index. Cela accélère la 'lecture suivante' dans les applications.
-R, --sort-records=#

Ce site n'est en aucun cas associé à Arch Linux ni affilié à ce projet. Le contenu est uniquement une traduction des pages de manuel d'Arch publiées sur man.archlinux.org.

>
Trier les enregistrements selon un index. Cela rend vos données beaucoup plus localisées et peut accélérer les opérations (un premier tri peut être TRÈS lent !).
-b, --block-search=#
Trouver l'enregistrement auquel appartient un bloc à l'offset donné.
-z, --zerofill
Remplir l'espace libre dans les fichiers de données et d'index avec des zéros. Cela rend le fichier de données déplaçable entre différents serveurs.
--zerofill-keep-lsn
Comme --zerofill mais ne met pas à zéro le LSN des pages de données/index.

Variables

--page_buffer_size=#
Taille du tampon de pages. Utilisé par --safe-repair
--read_buffer_size=#
Taille du tampon de lecture pour les lectures séquentielles lors de l'analyse
--sort_buffer_size=#
Taille du tampon de tri. Utilisé par --recover
--sort_key_blocks=#
Tampon interne pour le tri des clés ; Ne pas toucher.
--write_buffer_size=#
Taille du tampon d'écriture pour les écritures séquentielles lors de la réparation

Les options par défaut sont lues depuis les fichiers suivants dans l'ordre donné : /etc/my.cnf /etc/mysql/my.cnf ~/.my.cnf

Les groupes suivants sont lus : aria_chk

Les options suivantes peuvent être données comme premier argument :

--print-defaults
Afficher la liste des arguments du programme et quitter.
--no-defaults
Ne pas lire les options par défaut depuis aucun fichier d'options.
--defaults-file=#
Lire uniquement les options par défaut depuis le fichier # donné.
--defaults-extra-file=#
Lire ce fichier après la lecture des fichiers globaux.
