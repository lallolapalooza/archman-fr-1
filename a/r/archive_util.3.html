DESCRIPTION

Ces fonctions donnent accès à diverses informations concernant l'objet struct archive utilisé dans la bibliothèque libarchive(3) .

archive_clear_error()
Efface toute information d'erreur laissée par un appel précédent. Généralement pas utilisé dans le code client.
archive_compression()
Synonyme de archive_filter_code(a, 0).
archive_compression_name()
Synonyme de archive_filter_name(a, 0).
archive_copy_error()
Copie les informations d'erreur d'une archive vers une autre.
archive_errno()
Renvoie un code d'erreur numérique (voir errno(2)) indiquant la raison du dernier retour d'erreur. Notez que cela ne peut pas être utilisé de manière fiable pour détecter si une erreur s'est produite. Cela ne doit être utilisé qu'après qu'une autre fonction de libarchive ait renvoyé un statut d'erreur.
archive_error_string()
Renvoie un message d'erreur textuel adapté à l'affichage. Le message d'erreur ici est généralement plus précis que celui obtenu en passant le résultat de archive_errno() à strerror(3).
archive_file_count()
Renvoie le nombre de fichiers traités par cet objet archive. Le compteur est incrémenté par les appels à archive_write_header(3) ou archive_read_next_header(3).
archive_filter_code()
Renvoie un code numérique identifiant le filtre indiqué. Voir archive_filter_count() pour les détails de la numérotation.
archive_filter_count()
Renvoie le nombre de filtres dans le pipeline courant. Pour les poignées d'archives en lecture, ces filtres sont ajoutés automatiquement par la détection automatique du format. Pour les poignées d'archives en écriture, ces filtres sont ajoutés par des appels aux diverses fonctions archive_write_add_filter_XXX() . Les filtres dans le pipeline résultant sont numérotés de sorte que le filtre 0 est le filtre le plus proche du gestionnaire de format. Par commodité, les fonctions qui attendent un numéro de filtre accepteront -1 comme synonyme du filtre au numéro le plus élevé.

Par exemple, lors de la lecture d'une archive tar compressée avec gzip et encodée en uu, il y a trois filtres : le filtre 0 est le filtre gunzip, le filtre 1 est le filtre uudecode, et le filtre 2 est le pseudo-filtre qui enveloppe les fonctions de lecture d'archives. Dans ce cas, demander archive_position(a, -1) serait un synonyme de archive_position(a, 2) qui renverrait le nombre d'octets actuellement lus depuis l'archive, tandis que archive_position(a, 1) renverrait le nombre d'octets après le décodage uu, et archive_position(a, 0) renverrait le nombre d'octets après la décompression.

archive_filter_name()
Renvoie un nom textuel identifiant le filtre indiqué. Voir archive_filter_count() pour les détails de la numérotation.
archive_format()
Renvoie un code numérique indiquant le format de l'entrée d'archive courante. Cette valeur est définie par un appel réussi à archive_read_next_header(). Notez qu'il est courant que cette valeur change d'une entrée à l'autre. Par exemple, une archive tar peut avoir plusieurs entrées utilisant les extensions GNU tar et plusieurs entrées qui ne les utilisent pas. Ces entrées auronterent format codes.
archive_format_name()
Une description textuelle du format de l'entrée courante.
archive_position()
Renvoie le nombre d'octets lus ou écrits dans le filtre indiqué. En particulier, archive_position(a, 0) renvoie le nombre d'octets lus ou écrits par le gestionnaire de format, tandis que archive_position(a, -1) renvoie le nombre d'octets lus ou écrits dans l'archive. Voir archive_filter_count() pour les détails concernant la numérotation ici.
archive_set_error()
Définit le code d'erreur numérique et la description d'erreur qui seront renvoyés par archive_errno() et archive_error_string(). Cette fonction doit être utilisée dans les rappels d'E/S pour définir les codes d'erreur et les descriptions d'erreur spécifiques au système. Cette fonction accepte une chaîne de format de type printf et des arguments. Cependant, vous devez faire attention à utiliser uniquement les spécificateurs de format printf suivants : « %c », « %d », « %jd », « %jo », « %ju », « %jx », « %ld », « %lo », « %lu », « %lx », « %o », « %u », « %s », « %x », « %% ». Les spécificateurs de largeur de champ et les autres fonctionnalités de printf ne sont pas pris en charge de manière uniforme et ne doivent pas être utilisés.
