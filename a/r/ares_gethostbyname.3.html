NOM

ares_gethostbyname - Initier une requête de nom d'hôte par son nom

SYNOPSIS

#include <ares.h>
typedef void (*ares_host_callback)(void *arg, int status,
                                   int timeouts,
                                   struct hostent *hostent)
void ares_gethostbyname(ares_channel_t *channel, const char *name,
                        int family, ares_host_callback callback,
                        void *arg)

DESCRIPTION

La fonction ares_gethostbyname initie une requête de nom d'hôte sur le canal de service de noms identifié par channel. Le paramètre name donne le nom d'hôte sous forme de chaîne C terminée par NUL, et family donne le type d'adresse désiré pour l'entrée d'hôte résultante. Lorsque la requête est terminée ou a échoué, la bibliothèque ares appellera callback. L'achèvement ou l'échec de la requête peut se produire immédiatement, ou peut se produire lors d'un appel ultérieur à ares_process(3), ares_destroy(3) ou ares_cancel(3).

L'argument de rappel arg est copié depuis l'argument ares_gethostbyname arg. L'argument de rappel status indique si la requête a réussi et, sinon, comment elle a échoué. Il peut avoir l'une des valeurs suivantes:

ARES_SUCCESS
La résolution du nom d'hôte s'est terminée avec succès.
ARES_ENOTIMP
La bibliothèque ares ne sait pas comment trouver des adresses de type family.
ARES_EBADNAME
Le nom d'hôte name est composé uniquement de chiffres et de points, mais n'est pas une représentation valide d'une adresse Internet.
ARES_ENODATA
Aucune donnée n'a été retournée pour en extraire un résultat.
ARES_ENOTFOUND
Le nom name n'a pas été trouvé.
ARES_ENOMEM
Mémoire épuisée.
ARES_ECANCELLED
La requête a été annulée.
ARES_EDESTRUCTION
Le canal de service de noms channel est en cours de destruction ; la requête ne sera pas terminée.

L'argument de rappel timeouts rapporte combien de fois une requête a expiré pendant l'exécution de la requête donnée.

En cas de succès de la requête, l'argument de rappel hostent pointe vers une struct hostent contenant le nom d'hôte retourné par la requête. Le rappel n'a pas besoin et ne doit pas tenter de libérer la mémoire pointée par hostent ; la bibliothèque ares la libérera au retour du rappel. Si la requête n'a pas abouti, hostent sera NULL.

Lorsque le rappel associé est appelé, il l'est avec un verrou de canal, il faut donc veiller à ce que tout traitement soit minimal pour éviter les blocages du canal DNS.

Le rappel peut être déclenché à partir d'un thread différent de celui qui a appelé ares_gethostbyname(3).

Pour les intégrateurs qui exécutent leurs propres boucles d'événements et n'utilisent pas ARES_OPT_EVENT_THREAD, il faut veiller à ce que toutes les listes de descripteurs de fichiers soient immédiatement mises à jour dans la boucle d'événements lors de la notification.
