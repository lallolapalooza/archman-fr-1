ares_search_dnsrec(3)

Paquet: c-ares

Licences: MIT

ARES_SEARCH(3) Manuel des fonctions de librairie ARES_SEARCH(3)

NOM

ares_search - Lance une requête DNS avec recherche de domaine

SYNTAXE

#include <ares.h>
typedef void (*ares_callback_dnsrec)(void *arg,
                                     ares_status_t status,
                                     size_t timeouts,
                                     const ares_dns_record_t *dnsrec);
void ares_search_dnsrec(ares_channel_t *channel,
                        const ares_dns_record_t *dnsrec,
                        ares_callback_dnsrec callback, void *arg);
typedef void (*ares_callback)(void *arg, int status,
                              int timeouts, unsigned char *abuf,
                              int alen);
void ares_search(ares_channel_t *channel, const char *name,
                 int dnsclass, int type,
                 ares_callback callback, void *arg);

DESCRIPTION

La fonction ares_search lance une série de requêtes DNS à question unique sur le canal de service de noms identifié par channel, en utilisant les domaines de recherche du canal ainsi qu'un fichier d'alias d'hôtes donné par la variable d'environnement HOSTALIAS. Le paramètre name donne l'alias ou la base du nom de requête sous forme d'une chaîne C terminée par NUL de labels séparés par des points ; s'il se termine par un point, les domaines de recherche du canal ne seront pas utilisés. Les points et les antislashs à l'intérieur d'un label doivent être échappés avec un antislash. Les paramètres dnsclass et type donnent la classe et le type de la requête en utilisant les valeurs définies dans <arpa/nameser.h>. Lorsque la séquence de requêtes est complète ou a échoué, la librairie ares appellera callback. L'achèvement ou l'échec de la séquence de requêtes peut se produire immédiatement, ou lors d'un appel ultérieur à ares_process(3) ou ares_destroy(3).

Si ceci est appelé depuis un thread autre que celui où la boucle d'événements du programme principal est en cours d'exécution, des précautions doivent être prises pour s'assurer que les listes de descripteurs de fichiers sont immédiatement mises à jour dans la boucle d'événements. Lorsque le callback associé est appelé, il est appelé avec un verrou de canal, donc il faut s'assurer que tout traitement est minimal pour éviter des blocages du canal DNS.

L'argument de rappel arg est copié depuis l'argument ares_search arg. L'argument de rappel status indique si la séquence de requêtes s'est terminée par une requête réussie et, sinon, comment la séquence de requêtes a échoué. Il peut prendre l'une des valeurs suivantes :

ARES_SUCCESS
Une requête s'est terminée avec succès.
ARES_ENODATA
Aucune requête ne s'est terminée avec succès ; lorsque la requête a été tentée sans domaine de recherche ajouté, une réponse a été retournée sans aucune réponse.
ARES_EFORMERR
Une requête s'est terminée mais le serveur a affirmé que la requête était malformée.
ARES_ESERVFAIL
Aucune requête ne s'est terminée avec succès ; lorsque la requête a été tentée sans domaine de recherche ajouté, le serveur a affirmé avoir rencontré un échec. (Ce code ne peut apparaître que si le drapeau ARES_FLAG_NOCHECKRESP a été spécifié lors de l'initialisation du canal ; sinon, de telles réponses sont ignorées au niveau de ares_send(3).)
ARES_ENOTFOUND
Aucune requête ne s'est terminée avec succès ; lorsque la requête a été tentée sans domaine de recherche ajouté, le serveur a rapporté que le nom de domaine recherché n'a pas été trouvé.
ARES_ENOTIMP
Une requête s'est terminée mais le serveur n'implémente pas l'opération demandée par la requête. (Ce code ne peut apparaître que si le drapeau ARES_FLAG_NOCHECKRESP a été spécifié lors de l'initialisation du canal ; sinon, de telles réponses sont ignorées au niveau de ares_send(3).)
ARES_EREFUSED
Une requête s'est terminée mais le serveur a refusé la requête. (Ce code ne peut être retourné que si le drapeau ARES_FLAG_NOCHECKRESP a été spécifié lors de l'initialisation du canal ; sinon, de telles réponses sont ignorées au niveau de ares_send(3).)
ARES_TIMEOUT
Aucun serveur de noms n'a répondu à une requête dans le délai imparti.
ARES_ECONNREFUSED
Aucun serveur de noms n'a pu être contacté.
ARES_ENOMEM
La mémoire a été épuisée.
ARES_ECANCELLED
La requête a été annulée.
ARES_EDESTRUCTION
Le canal de service de noms channel est en cours de destruction ; la requête ne sera pas complétée.
ARES_ENOSERVER
Aucune requête ne s'est terminée avec succès ; aucun serveur DNS n'a été configuré sur le canal.

L'argument de rappel timeouts indique combien de fois une requête a expiré pendant l'exécution de la requête donnée.

Si une requête s'est terminée avec succès, l'argument de rappel abuf pointe vers un tampon de résultat de longueur alen. Si la requête ne s'est pas terminée avec succès, abuf sera généralement NULL et alen sera généralement 0, mais dans certains cas, un résultat de requête non réussi peut être placé dans abuf.

La fonction ares_search_dnsrec(3) se comporte de manière identique à ares_search(3), mais prend un objet d'enregistrement DNS initialisé et rempli pour être utilisé dans les requêtes comme deuxième argument dnsrec au lieu d'un nom, d'une classe et d'un type. Cet objet est utilisé comme base pour les requêtes et doit lui-même représenter une requête valide pour un nom unique. Notez que les domaines de recherche ne seront ajoutés qu'au nom dans la section question ; les RR de l'objet d'enregistrement DNS ne seront pas affectés. De plus, l'argument callback est de type ares_callback_dnsrec. Ce callback se comporte de manière identique à ares_callback, mais est appelé avec un objet d'enregistrement DNS analysé dnsrec plutôt qu'avec un tampon brut avec sa longueur. Notez que cet objet est en lecture seule.

La fonction ares_search_dnsrec(3) retourne un code de réponse ares_status_t. Cela peut être utile pour savoir que la requête a été mise en file d'attente correctement. Le code de réponse ne reflète pas le résultat de la requête, seulement le résultat de la mise en file d'attente de la requête.

DISPONIBILITÉ

ares_search_dnsrec(3) a été introduit dans c-ares 1.28.0.
