archinstall - Documentation

d'archinstall

archinstall est une bibliothèque qui peut être utilisée pour installer Arch Linux. La bibliothèque est livrée avec différents installateurs pré-configurés, tels que l'installateur Guidé par défaut <#guided>

.

Certaines des fonctionnalités d'Archinstall sont

:
  • Compatible avec le contexte. La bibliothèque exécute toujours les appels dans l'ordre séquentiel pour s'assurer que les étapes d'installation ne se chevauchent pas et ne s'exécutent pas dans le mauvais ordre. Elle prend également en charge (et utilise) des enveloppes de contexte pour s'assurer que le nettoyage et les tâches finales telles que mkinitcpio sont appelés lorsque c'est
    • nécessaire.
  • Transparence totale Les journaux et les informations peuvent être trouvés dans /var/log/archinstall, à la fois dans l'ISO live et partiellement sur le système
    • installé.
  • Accessible Archinstall fonctionne avec espeakup et d'autres
    • outils d'acces
sibilité grâce

OPTIONS

archinstall can be run with a few different CLI options.

--advanced

This option forces the TUI to load in advanced mode. This exposes more options for the user to modify during the installation process. Please note that this option will be deprecated in the next release. For further information, see the advanced installation guide.

--disk_layout

A JSON file describing the disk layout. See the example disk_layout.json.

--creds

A JSON file detailing credentials, like passwords for the root user and for regular user accounts.

--profile

Specifies a profile to use for the installation. Profiles are pre-configured sets of options that define the system's configuration. You can find default profiles in the profiles directory. The following profiles are available:

  • guided https://github.com/archlinux/archinstall/blob/master/archinstall/scripts/guided.py (default)
  • minimal https://github.com/archlinux/archinstall/blob/master/archinstall/scripts/minimal.py
  • only_hdd https://github.com/archlinux/archinstall/blob/master/archinstall/scripts/only_hdd.py

When used to autorun an installation, this sets which script to autorun.

--silent

Disables or enables user questions using the TUI.

--swap

Enables or disables swap.

--timezone

Sets a timezone for the installed system. For a list of available timezones, refer to the Arch Wiki.

Note:

If no entries are found in disk_config, the archinstall guided installation will use whatever is currently mounted under /mnt/archinstall without performing any disk operations.

Options for --creds

Creds is a separate configuration file to separate normal options from more sensitive data like passwords. Below is an example of how to set the root password and below that are descriptions of other values that can be set.

{
    "root_enc_password" : "SecretSanta2022"

KNOWN ISSUES

Some issues are out of the archinstall archinstall projects scope, and the ones we know of are listed below.

Waiting for time sync #2144 <https://github.com/archlinux/archinstall/issues/2144>

The usual root cause of this is the network topology. More specifically timedatectl show https://github.com/archlinux/archinstall/blob/e6344f93f7e476d05bbcd642f2ed91fdde545870/archinstall/lib/installer.py#L136 cannot perform a proper time sync against the default servers.

Restarting systemd-timesyncd.service might work but most often you need to configure /etc/systemd/timesyncd.conf to match your network design.

Note:

If you know your time is correct on the machine, you can run archinstall --skip-ntp to ignore time sync.

Waiting for Arch Linux keyring sync (archlinux-keyring-wkd-sync) to complete. #2679 <https://github.com/archlinux/archinstall/issues/2679>

The archlinux-keyring-wkd-sync.service or archlinux-keyring-wkd-sync.timer can hang "indefinitely" some times. This is usually due to an inability to reach the key servers, or a slow connection towards key servers.

The script /usr/bin/archlinux-keyring-wkd-sync can be run manually, to verify if it's executing slowly or not.

If systemctl show --property=ActiveEnterTimestamp --no-pager archlinux-keyring-wkd-sync.timer shows nothing, it means the built-in sync never finished. Likewise systemctl show --no-pager -p SubState --value archlinux-keyring-wkd-sync.service most likely shows dead, which means the service never completed.

To fix this, try the following:

# killall gpg-agent
# rm -rf /etc/pacman.d/gnupg
# pacman-key --init
# pacman-key --populate
# pacman -Sy archlinux-keyring
# systemctl restart archlinux-keyring-wkd-sync.timer

Note:

If you know the ISO is the latest, and that you have valid GPG keys, try archinstall --skip-wkd to ignore waiting for the sync.

If you skip WKD sync, you might end up with:

> error: archinstall: signature from "Anton Hvornum (Torxed) <torxed@archlinux.org>" is unknown trust
> :: File /var/cache/pacman/pkg/archinstall-1.2.3-4-x86_64.pkg.tar.xz is corrupted (invalid or corrupted package (PGP signature)).
> Do you want to delete it? [Y/n]

Missing Nvidia Proprietary Driver #2002 <https://github.com/archlinux/archinstall/issues/2002>

In some instances, the nvidia driver might not have all the necessary packages installed. This is due to the kernel selection and/or hardware setups requiring additional packages to work properly.

A common workaround is to install the package linux-headers https://archlinux.org/packages/core/x86_64/linux-headers/ and nvidia-dkms https://archlinux.org/packages/extra/x86_64/nvidia-dkms/

ARM, 32bit and other CPU types error out #1686 <https://github.com/archlinux/archinstall/issues/1686>, #2185 <https://github.com/archlinux/archinstall/issues/2185>

This is a bit of a catch-all known issue. Officially x86_64 <https://wiki.archlinux.org/title/Frequently_asked_questions#What_architectures_does_Arch_support?> is only supported by Arch Linux. Hence little effort have been put into supporting other platforms.

In theory, other architectures should work but small quirks might arise.

PR's are welcome but please be respectful of the delays in merging. Other fixes, issues or features will be prioritized for the above reasons.

Keyring is out of date #2213 <https://github.com/archlinux/archinstall/issues/2213>

Missing key-issues tend to be that the archlinux-keyring https://archlinux.org/packages/core/any/archlinux-keyring/ package is out of date, usually as a result of an outdated ISO. There is an attempt from upstream to fix this issue, and it's the archlinux-keyring-wkd-sync.service https://gitlab.archlinux.org/archlinux/archlinux-keyring/-/blob/7e672dad10652a80d1cc575d75cdb46442cd7f96/wkd_sync/archlinux-keyring-wkd-sync.service.in

The service starts almost immediately during boot, and if network is not configured in time — the service will fail. Subsequently the archinstall run might operate on a old keyring despite there being an update service for this.

There is really no way to reliably over time work around this issue in archinstall. Instead, efforts to the upstream service should be considered the way forward. And/or keys not expiring between a sane amount of ISO's.

Note:

If you know the ISO is the latest, and that you have valid GPG keys, try archinstall --skip-wkd to ignore waiting for the sync.

If you skip WKD sync, you might end up with:

> error: archinstall: signature from "Anton Hvornum (Torxed) <torxed@archlinux.org>" is unknown trust
> :: File /var/cache/pacman/pkg/archinstall-1.2.3-4-x86_64.pkg.tar.xz is corrupted (invalid or corrupted package (PGP signature)).

PLUGINS

archinstall prend en charge les plugins via deux

méthodes.

La première méthode est directement via le --plugin parameter lors de l'exécution en tant qu'outil CLI. Cela chargera un plugin spécifique localement ou à distance via un

chemin.

La deuxième méthode est via la découverte intégrée des plugins de Python https://packaging.python.org/en/latest/specifications/entry-points/ en utilisant les points d'entrée https://docs.python.org/3/library/importlib.metadata.html#entry-points classifiés comme archinstall.p

lugin.

--plugin par

ameter

Le paramètre a l'avantage d'être stocké dans l'état --conf , ce qui signifie que lors de la réexécution d'une installation — le plugin sera automatiquement ch

argé. Sa limitation est qu'il nécessite qu'un chemin in
itial soit connu et écrit, ce qui peut être fastidieux.

Plugin

Discovery

Cette méthode permet de charger plusieurs plugins, mais l'inconvénient est qu'ils doivent être installés au préalable sur le système exécutant archinstall. Cela vise principalement ceux qui construisent leurs propre

s ISO et empaquetent des configurati
ons spécifiques selon leurs besoins.

Les plugins archinstall utilisent une approche pilotée par la découverte où les plugins sont interrogés pour certaines fonctions. Par exemple, si un plugin a la fonction suivante
