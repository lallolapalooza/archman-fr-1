archive_write_ope
n()
Figer les paramètres, ouvrir l'archive et préparer l'écriture des entrées. C'est la forme la plus générique de cette fonction, qui accepte des pointeurs vers trois fonctions de rappel qui seront invoquées par la couche de compression pour écrire l'archive construite. Cela n'altère pas le remplissage (padding) par défaut de
l'archive.

open().

d()
Une forme de commodité de archive_write_open() qui accepte un descripteur de fichier. La fonction archive_write_open_fd() est sûre pour une utilisation avec des lecteurs de bande ou d'autres dispositifs orientés
blocs.

E()
Une forme de commodité de archive_write_open() qui accepte un FILE *. Notez que archive_write_open_FILE() n'est pas sûr pour écrire vers des lecteurs de bande ou d'autres dispositifs nécessitant un blocage
correct.

Un synonyme déprécié pour archive_write_open_f
ilename().
archive_write_open_filenam
e()
Une forme de commodité de archive_write_open() qui accepte un nom de fichier. Un argument NULL indique que la sortie doit être écrite sur la sortie standard ; un argument de « - » ouvrira un fichier portant ce nom. Si vous n'avez pas invoqué archive_write_set_bytes_in_last_block(), alors archive_write_open_filename() ajustera le remplissage du dernier bloc en fonction du fichier : il activera le remplissage lors de l'écriture sur la sortie standard ou sur un nœud de dispositif caractère ou bloc, et le désactivera dans les autres cas. Vous pouvez outrepasser cela en invoquant manuellement archive_write_set_bytes_in_last_block() avant d'appeler archive_write_open2(). La fonction archive_write_open_filename() est sûre pour une utilisation avec des lecteurs de bande ou d'autres dispositifs orientés
blocs.
archive_write_open_memor
y()
Une forme de commodité de archive_write_open2() qui accepte un pointeur vers un bloc de mémoire qui recevra l'archive. Le dernier size_t * argument pointe vers une variable qui sera mise à jour après chaque écriture pour refléter la quantité du tampon actuellement utilisée. Vous devez veiller à ce q
ue cette variable reste allouée jusqu'à ce que l'archive soit fermée. Cette fonction
désactivera le remplissage sauf si vous avez spécifiquement défini la taille de bloc.

Plus d'informations sur l'objet struct archive et la conception générale de la bibliothèque peuvent être trouvées dans l'aperçu libarchive(3)

Notez que les formes de commodité ci-dessus varient dans la manière dont elles effectuent le blocage de la sortie. Voir archive_write_blocksize(3) si vous devez contrôler la taille de bloc utili

RAPPELS

CLIENT

Pour utiliser cette bibliothèque, vous devrez définir et enregistrer des fonctions de rappel qui seront invoquées pour écrire des données vers l'archive résultante. Ces fonctions sont enregistrées en appelant archive_write_open2()

:

ata)

Le rappel d'ouverture est invoqué par archive_write_open(). Il doit retourner ARCHIVE_OK si le fichier sous-jacent ou la source de données est ouvert avec succès. Si l'ouverture échoue, il doit appeler archive_set_error() pour enregistrer un code d'erreur et un message, puis retourner ARCHIVE_FATAL. Veuillez noter que si l'ouverture échoue, la fermeture n'est pas appelée et les ressources doivent être libérées à l'intérieur du rappel d'ouverture ou avec le rappel de

libération.

Le rappel d'écriture est invoqué chaque fois que la bibliothèque a besoin d'écrire des octets bruts vers l'archive. Pour un blocage correct, chaque appel à la fonction de rappel d'écriture doit se traduire par un seul appel système write(2). C'est particulièrement critique lors de l'écriture d'archives sur des lecteurs de bande. En cas de succès, le rappel d'écriture doit retourner le nombre d'octets réellement écrits. En cas d'erreur, le rappel doit invoquer archive_set_error() pour enregistrer un code d'erreur et un message, puis retourner

-1.

Le rappel de fermeture est invoqué par archive_close lorsque l'archive est terminé. Si le rappel d'ouverture échoue, le rappel de fermeture n'est pas invoqué. Le rappel doit retourner ARCHIVE_OK en cas de succès. En cas d'échec, le rappel doit invoquer archive_set_error() pour enregistrer un code d'erreur et un message, puis retourner ARCHIVE_FATAL

.

Le rappel de libération est toujours invoqué lors de archive_free. Le code de retour de ce rappel n'est pas

traité.

Notez que si la fonction de rappel d'écriture fournie par le client retourne une valeur non nulle, cet erreur sera propagée au appelant à travers la fonction API qui a entraîné cet appel, ce qui peut inclure archive_write_header(), archive_write_data(), archive_write_close(), archive_write_finish(), ou archive_write_free(). Le rappel client peut appeler archive_set_error() pour fournir des valeurs qui peuvent ensuite être récupérées par archive_errno() et archive_erro
