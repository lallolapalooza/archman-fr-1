ares_send(3)

Paquet: c-ares

Licences: MIT

ARES_SEND(3) Manuel des fonctions de bibliothèque ARES_SEND(3)

NOM

ares_send - Lancer une requête DNS

SYNTAXE

#include <ares.h>
typedef void (*ares_callback_dnsrec)(void *arg, ares_status_t status,
                                     size_t timeouts,
                                     const ares_dns_record_t *dnsrec);
ares_status_t ares_send_dnsrec(ares_channel_t *channel,
                               const ares_dns_record_t *dnsrec,
                               ares_callback_dnsrec callback,
                               void *arg, unsigned short *qid);
typedef void (*ares_callback)(void *arg, int status,
                              int timeouts, unsigned char *abuf,
                              int alen);
void ares_send(ares_channel_t *channel, const unsigned char *qbuf,
               int qlen, ares_callback callback, void *arg);

DESCRIPTION

La fonction ares_send_dnsrec(3) lance une requête DNS formatée à l'aide de la structure de données ares_dns_record_t * créée via ares_dns_record_create(3) dans le paramètre dnsrec. Le callback fourni dans le paramètre callback renvoie également la réponse en utilisant une structure de données ares_dns_record_t *.

La fonction ares_send(3) lance de manière similaire une requête DNS, mais utilise plutôt des tampons binaires bruts avec des messages DNS entièrement formatés passés dans la requête via les paramètres qbuf et qlen. Le callback fourni dans le paramètre callback renvoie également la réponse DNS binaire brute dans les paramètres abuf et alen. Cette méthode doit être considérée comme obsolète au profit de ares_send_dnsrec(3).

Les deux fonctions prennent un canal ares initialisé identifié par channel.

La fonction ares_send_dnsrec(3) peut également se voir attribuer un paramètre de sortie optionnel qid pour remplir l'identifiant de la requête tel qu'il a été placé sur le réseau.

La fonction ares_send_dnsrec(3) renvoie un code de réponse ares_status_t. Cela peut être utile pour savoir que la requête a été correctement mise en file d'attente. Le code de réponse ne reflète pas le résultat de la requête, seulement le résultat de la mise en file d'attente de la requête.

L'achèvement ou l'échec de la requête peut se produire immédiatement (même avant le retour de la fonction), ou peut se produire plus tard lorsque les événements réseau sont traités.

Lorsque le callback associé est appelé, il est appelé avec un verrou de canal, il faut donc veiller à ce que tout traitement soit minimal pour éviter les blocages du canal DNS.

Le callback peut être déclenché par un thread différent de celui qui a appelé ares_send_dnsrec(3) ou ares_send(3).

Pour les intégrateurs exécutant leurs propres boucles d'événements et n'utilisant pas ARES_OPT_EVENT_THREAD, il faut veiller à ce que toutes les listes de descripteurs de fichiers soient mises à jour immédiatement dans la boucle d'événements lorsqu'elles sont notifiées.

L'argument de callback arg est copié à partir du paramètre arg de ares_send_dnsrec(3) ou ares_send(3).

L'argument de callback status indique si la requête a réussi et, si ce n'est pas le cas, comment elle a échoué. Il peut avoir l'une des valeurs suivantes :

ARES_SUCCESS
La requête s'est terminée.
ARES_EBADQUERY
Le tampon de requête était mal formé (n'était pas assez long pour un en-tête DNS ou était trop long pour la transmission TCP).
ARES_ETIMEOUT
Aucun serveur de noms n'a répondu dans le délai imparti.
ARES_ECONNREFUSED
Aucun serveur de noms n'a pu être contacté.
ARES_ENOMEM
La mémoire a été épuisée.
ARES_ECANCELLED
La requête a été annulée.
ARES_EDESTRUCTION
Le canal de service de noms channel est en cours de destruction ; la requête ne sera pas terminée.
ARES_ENOSERVER
La requête ne sera pas terminée car aucun serveur DNS n'a été configuré sur le canal.
ARES_EBADQUERY
Requête DNS mal formatée.

L'argument de callback timeouts indique combien de fois une requête a expiré pendant l'exécution de la demande donnée.

Si la requête s'est terminée, l'argument de callback dnsrec pour ares_send_dnsrec(3) ou abuf et alen pour ares_send(3) sera non NULL.

À moins que le drapeau ARES_FLAG_NOCHECKRESP n'ait été défini lors de l'initialisation du canal, ares_send_dnsrec(3) et ares_send(3) ignoreront normalement les réponses dont les questions ne correspondent pas aux questions fournies, ainsi que les réponses avec des codes d'erreur SERVFAIL, NOTIMP et REFUSED. Cependant, contrairement aux autres fonctions de requête de la bibliothèque ares, ares_send_dnsrec(3) et ares_send(3) n'inspectent pas l'en-tête du paquet de réponse pour déterminer le statut d'erreur, de sorte qu'un statut de callback ARES_SUCCESS ne reflète pas autant la réponse que pour d'autres fonctions de requête.

DISPONIBILITÉ

ares_send_dnsrec(3) a été introduit dans c-ares 1.28.0.
