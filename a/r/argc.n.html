Les variables globales suivantes sont créées et gérées automatiquement par la bibliothèque Tcl. Sauf indication contraire ci-dessous, ces variables doivent normalement être considérées comme en lecture seule par le code spécifique à l'application et par les

Cette variable est initialisée au démarrage pour contenir, dans l'ordre : les répertoires listés dans la variable d'environnement TCLLIBPATH, le répertoire nommé par la variable globale tcl_library, le répertoire parent de tcl_library, [file dirname [file dirname [info nameofexecutable]]]/lib, les répertoires listés dans la variable tcl_pkgPath. en
v
Cette variable est maintenue par Tcl sous forme de tableau dont les éléments sont les variables d'environnement du processus. La lecture d'un élément renverra la valeur de la variable d'environnement correspondante. La définition d'un élément du tableau modifiera la variable d'environnement correspondante ou en créera une nouvelle si elle n'existe pas déjà. La suppression d'un élément de env supprimera la variable d'environnement correspondante. Les modifications apportées au tableau env affecteront l'environnement transmis aux processus enfants par des commandes comme exec. Si l'ensemble du tableau env est supprimé, Tcl cessera de surveiller les accès à env et ne mettra pas à jour les variables
d'environnement

Sous Windows, les variables d'environnement PATH et COMSPEC, quelle que soit leur casse, sont automatiquement converties en majuscules. Par exemple, la variable PATH peut être exportée par le système d'exploitation sous la forme « path », « Path », « PaTh », etc., obligeant autrement un code Tcl simple à prendre en charge de nombreux cas particuliers. Toutes les autres variables d'environnement héritées par Tcl restent inchangées. Définir une variable de tableau env à vide revient à la supprimer, car c'est le comportement du système d'exploitation Windows sous-jacent. Il convient de noter que s'appuyer sur une variable d'environnement existante et vide ne fonctionnera pas sous Windows et est déconseillé pour une utilisation multiplateforme

.

Cette variable contient une liste de répertoires indiquant où les paquets sont normalement installés. Elle n'est pas utilisée sur Windows. on
Cette variable contrôle le nombre de chiffres à générer lors de la conversion des valeurs en virgule flottante en chaînes. Sa valeur par défaut est 0. Les applications ne devraient pas changer cette valeur ; e
lle est fournie pour la compatib
ilité avec le code hérité.
La valeur par défaut 0 est spéciale, signifiant que Tcl devrait convertir les nombres en utilisant aussi peu de chiffres que possible tout en distinguant toujours tout nombre en virgule flottante de ses voisins les plus proches. Elle diffère de l'utilisation d'une valeur arbitrairement élevée pour tcl_precision en ce que un nombre inexact comme 1.4 sera converti en 1.4 plutôt qu'en 1.3999999999999999 même si ce dernier est plus proche de la valeur exacte du nombre
binaire.
Si tcl_precision n'est pas zéro, alors lorsque Tcl convertit un nombre en virgule flottante, il crée une représentation décimale d'au plus tcl_precision chiffres significatifs ; le résultat peut être plus court si le résultat plus court représente le nombre original exactement. Si aucun résultat d'au plus tcl_precision chiffres n'est une représentation exacte du nombre original, celui qui est le plus proche du nombre original est choisi. Si le nombre original se trouve précisément entre deux représentations décimales également précises, alors celui dont la valeur du chiffre le moins significatif est paire est choisi ; par exemple, si tcl_precision vaut 3, alors 0.3125 sera converti en 0.312, et non 0.313, tandis que 0.6875 sera converti en 0.688, et non 0.687. Toute chaîne de zéros finaux restante est
supprimée.
a une valeur de tcl_precision de 17 chiffres est « parfaite » pour les nombres en virgule flottante IEEE en ce qu'elle permet aux valeurs en double précision d'être converties en chaînes et en retour en binaire sans perte d'information. Pour cette raison, vous le verrez souvent comme une valeur dans du code hérité qui doit s'exécuter sur des versions de Tcl antérieures à 8.5. Elle n'est plus recommandée ; comme noté ci-dessus, une valeur zéro est la méthode
préférée.
Tous les interpréteurs dans un thread partagent une seule valeur de tcl_precision : la changer dans un interpréteur affectera tous les autres interpréteurs également. Les interpréteurs sûrs ne sont pas autorisés à modifier la
variable.
Les valeurs valides pour tcl_precision vont de 0 à
17.

tcl_traceEx

La valeur de cette variable peut être définie pour contrôler la quantité d'informations de traçage affichée lors de l'exécution du code intermédiaire (bytecode). Par défaut, tcl_traceExec vaut zéro et aucune information n'est affichée. En définissant tcl_traceExec à 1, une trace d'une ligne est générée dans stdout à chaque appel à une procédure Tcl. En la définissant à 2, une ligne de sortie est générée chaque fois qu'une commande Tcl est invoquée, contenant le nom de la commande et ses arguments. En la définissant à 3, une trace détaillée est produite montrant le résultat de l'exécution de chaque instruction de code intermédiaire. Notez que lorsque tcl_traceExec vaut 2 ou 3, des commandes telles que set et incr, qui ont été entièrement remplacées par une séquence d'instructions de code intermédiaire, ne sont pas affichées.
