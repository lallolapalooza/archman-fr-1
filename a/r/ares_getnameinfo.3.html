ARES_GETNAMEINFO(3) Manuel des fonctions de bibliothèque ARES_GETNAMEINFO(3)

NOM

ares_getnameinfo - Traduction adresse-nom d'hôte de manière indépendante du protocole

SYNTAXE

#include <ares.h>
typedef void (*ares_nameinfo_callback)(void *arg, int status,
                                       int timeouts, char *node,
                                       char *service)
void ares_getnameinfo(ares_channel_t *channel, const struct sockaddr *sa,
                      ares_socklen_t salen, int flags,
                      ares_nameinfo_callback callback, void *arg)

DESCRIPTION

La fonction ares_getnameinfo est définie pour la traduction d'adresses indépendante du protocole. La fonction est une combinaison de ares_gethostbyaddr(3) et getservbyport(3). La fonction traduira l'adresse soit en exécutant une requête d'hôte sur le canal de service de noms identifié par channel, soit elle tentera de la résoudre localement si possible. Les paramètres sa et len fournissent l'adresse sous forme de structure sockaddr, et flags fournit les options que la fonction utilisera. Les indicateurs valides sont listés ci-dessous :

ARES_NI_NOFQDN
Seule la partie nom d'hôte du FQDN est retournée pour les hôtes locaux.
ARES_NI_NUMERICHOST
La forme numérique du nom d'hôte est retournée plutôt que le nom.
ARES_NI_NAMEREQD
Une erreur est retournée si le nom d'hôte ne peut pas être trouvé dans le DNS.
ARES_NI_NUMERICSERV
La forme numérique du service est retournée plutôt que le nom.
ARES_NI_TCP
Le nom du service doit être recherché pour le protocole TCP.
ARES_NI_UDP
Le nom du service doit être recherché pour le protocole UDP.
ARES_NI_SCTP
Le nom du service doit être recherché pour le protocole SCTP.
ARES_NI_DCCP
Le nom du service doit être recherché pour le protocole DCCP.
ARES_NI_NUMERICSCOPE
La forme numérique de l'ID de portée est retournée plutôt que le nom.
ARES_NI_LOOKUPHOST
Une recherche de nom d'hôte est demandée.
ARES_NI_LOOKUPSERVICE
Une recherche de nom de service est demandée.

Lorsque la requête est terminée ou a échoué, la bibliothèque ares appellera callback. L'achèvement ou l'échec de la requête peut se produire immédiatement, ou peut se produire lors d'un appel ultérieur à ares_process(3), ares_destroy(3) ou ares_cancel(3).

Lorsque le rappel associé est appelé, il est appelé avec un verrou de canal, donc des précautions doivent être prises pour s'assurer que tout traitement est minimal afin d'éviter les blocages du canal DNS.

Le rappel peut être déclenché à partir d'un thread différent de celui qui a appelé ares_getnameinfo(3).

Pour les intégrateurs exécutant leurs propres boucles d'événements et n'utilisant pas ARES_OPT_EVENT_THREAD, des précautions doivent être prises pour s'assurer que les listes de descripteurs de fichiers sont mises à jour immédiatement dans la boucle d'événements lorsqu'elles sont notifiées.

L'argument de rappel arg est copié de l'argument arg de ares_getnameinfo. L'argument de rappel status indique si la requête a réussi et, sinon, comment elle a échoué. Il peut avoir l'une des valeurs suivantes :

ARES_SUCCESS
La recherche d'hôte s'est terminée avec succès.
ARES_ENOTIMP
La bibliothèque ares ne sait pas comment rechercher les adresses de type family.
ARES_ENOTFOUND
L'adresse addr n'a pas été trouvée.
ARES_ENOMEM
La mémoire a été épuisée.
ARES_ECANCELLED
La requête a été annulée.
ARES_EDESTRUCTION
Le canal de service de noms channel est en cours de destruction ; la requête ne sera pas terminée.
ARES_EBADFLAGS
Le paramètre flags contient une valeur illégale.

L'argument de rappel timeouts rapporte combien de fois une requête a expiré pendant l'exécution de la demande donnée.

En cas de succès de la requête, l'argument de rappel node contient une chaîne représentant le nom d'hôte (en supposant que ARES_NI_LOOKUPHOST a été spécifié). De plus, service contient une chaîne représentant le nom du service (en supposant que ARES_NI_LOOKUPSERVICE a été spécifié). Si la requête n'a pas abouti, ou si l'une des valeurs n'a pas été demandée, node ou service sera NULL.
