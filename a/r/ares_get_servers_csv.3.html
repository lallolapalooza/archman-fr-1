ares_get_servers_csv(3)

Paquet: c-ares

Licences: MIT

ARES_SET_SERVERS_CSV(3) Manuel des fonctions de bibliothèque ARES_SET_SERVERS_CSV(3)

NOM

ares_set_servers_csv, ares_set_servers_ports_csv, ares_get_servers_csv - Définir ou obtenir une liste de serveurs DNS pour les requêtes.

SYNTAXE

#include <ares.h>
int ares_set_servers_csv(ares_channel_t *channel, const char* servers)
int ares_set_servers_ports_csv(ares_channel_t *channel, const char* servers)
char *ares_get_servers_csv(const ares_channel_t *channel)

DESCRIPTION

Les fonctions ares_set_servers_csv et ares_set_servers_ports_csv définissent la liste des serveurs DNS que c-ares interrogera. Depuis la version 1.22.0, cette fonction peut être appelée sur un canal actif avec des requêtes en cours, alors qu'auparavant elle retournait ARES_ENOTIMP.

Bien que déconseillé, passer NULL pour les serveurs effacera tous les serveurs configurés et rendra le canal inopérant, ce qui peut être avantageux pour la simulation de tests mais peu probable d'être utile en production.

La fonction ares_get_servers_csv récupère la liste des serveurs au format délimité par des virgules.

Le format d'entrée et de sortie est une liste de serveurs séparés par des virgules. Deux formats sont disponibles, le format typique de nameserver de resolv.conf(5), ainsi qu'un format URI. Les deux formats peuvent être utilisés en même temps dans la chaîne CSV fournie.

Le format nameserver est :

ip[:port][%iface]
L'ip peut être encapsulée entre crochets ([ ]), et doit l'être si vous utilisez IPv6 et spécifiez également un port.

Le port est optionnel, et vaut par défaut 53 ou la valeur spécifiée dans ares_init_options(3).

L'iface est spécifique aux serveurs locaux de lien IPv6 (fe80::/10) et ne doit pas être utilisée autrement.

Exemples de format nameserver :

192.168.1.100
192.168.1.101:53
[1:2:3::4]:53
[fe80::1]:53%eth0

Le format URI est composé des schémas définis suivants :

dns:// - Serveur DNS normal (UDP + TCP). Nous devons faire attention à ne pas entrer en conflit avec les paramètres de requête définis dans la RFC4501 car nous étendrions techniquement ce schéma URI. Le port vaut par défaut 53.

dns+tls:// - DNS sur TLS. Le port vaut par défaut 853.

dns+https:// - DNS sur HTTPS. Le port vaut par défaut 443.

Les paramètres de requête sont définis comme suit. Des paramètres supplémentaires pourront être définis à l'avenir.

tcpport - Port TCP à utiliser, uniquement pour le schéma dns://. Le port spécifié comme faisant partie du composant d'autorité de l'URI sera utilisé par défaut pour UDP et TCP, cette option remplacera le port TCP.

ipaddr - Uniquement pour dns+tls:// et dns+https://. Si le composant d'autorité de l'URI contient un nom d'hôte, ceci est utilisé pour spécifier l'adresse IP de ce nom d'hôte. Si non spécifié, il faudra utiliser un serveur non sécurisé pour effectuer une recherche DNS afin de récupérer cette information. Il est toujours recommandé d'avoir spécifiés à la fois l'adresse IP et le nom de domaine entièrement qualifié.

hostname - Uniquement pour dns+tls:// et dns+https://. Si le composant d'autorité de l'URI contient une adresse IP, ceci est utilisé pour spécifier le nom de domaine entièrement qualifié du serveur. Si non spécifié, il faudra utiliser un serveur non sécurisé pour effectuer une recherche DNS inversée afin de récupérer cette information. Il est toujours recommandé d'avoir spécifiés à la fois l'adresse IP et le nom de domaine entièrement qualifié.

domain - Si spécifié, ce serveur est un serveur spécifique au domaine. Toute requête pour ce domaine sera acheminée vers ce serveur. Plusieurs serveurs peuvent être tagués avec le même domaine.

Exemples de format URI :

dns://8.8.8.8
dns://[2001:4860:4860::8888]
dns://[fe80::b542:84df:1719:65e3%en0]
dns://192.168.1.1:55
dns://192.168.1.1?tcpport=1153
dns://10.0.1.1?domain=myvpn.com
dns+tls://8.8.8.8?hostname=dns.google
dns+tls://one.one.one.one?ipaddr=1.1.1.1

NOTE : Bien que nous définissions le schéma pour des choses comme les serveurs spécifiques au domaine, DNS sur TLS et DNS sur HTTPS, les implémentations sous-jacentes pour ces fonctionnalités n'existent pas encore et entraîneront donc des erreurs si l'on tente de les utiliser.

Depuis c-ares 1.24.0, ares_set_servers_csv et ares_set_servers_ports_csv sont identiques. Les versions antérieures omettaient simplement les ports dans ares_set_servers_csv mais en raison de l'ajout du support des interfaces locales, cette différence a été supprimée.

EXEMPLE

192.168.1.100,[fe80::1]:53%eth0,dns://192.168.1.1?tcpport=1153

VALEURS DE RETOUR

Les fonctions ares_set_servers_csv(3) et ares_set_servers_ports_csv(3) peuvent retourner l'une des valeurs suivantes :

ARES_SUCCESS
La configuration des serveurs de noms a été initialisée avec succès.
ARES_ENOMEM
La mémoire disponible du processus a été épuisée.
ARES_ENODATA
Les données du canal identifiées par channel étaient invalides.
ARES_ENOTINITIALIZED
L'initialisation de la bibliothèque c-ares n'a pas encore été effectuée.

La fonction ares_get_servers_csv(3) retourne une chaîne représentant les serveurs configurés qui doit être libérée avec ares_free_string(3). Si elle retourne NULL, il s'agit d'une condition de manque de mémoire.
