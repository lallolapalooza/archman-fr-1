DESCRIPTION

Ces fonctions fournissent une API pour lire des informations sur les objets sur le disque. En particulier, elles fournissent une interface pour peupler des objets struct archive_entry.

archive_read_disk_new()
Alloue et initialise un objet struct archive adapté à la lecture des informations d'objet depuis le disque.
archive_read_disk_open()
Ouvre le fichier ou le répertoire à partir du chemin donné et prépare le struct archive pour le lire depuis le disque.
archive_read_disk_open_w()
Ouvre le fichier ou le répertoire à partir du chemin donné sous forme de chaîne de caractères larges et prépare le struct archive pour le lire depuis le disque.
archive_read_disk_set_behavior()
Configure diverses options de comportement lors de la lecture des entrées depuis le disque. Le champ flags est constitué d'un OU bit à bit d'une ou plusieurs des valeurs suivantes :
ARCHIVE_READDISK_HONOR_NODUMP
Ignorer les fichiers et répertoires ayant l'attribut de fichier nodump (file flag) défini. Par défaut, l'attribut de fichier nodump est ignoré.
ARCHIVE_READDISK_MAC_COPYFILE
Spécifique à Mac OS X. Lire les métadonnées (ACL et attributs étendus) avec copyfile(3). Par défaut, les métadonnées sont lues en utilisant copyfile(3).
ARCHIVE_READDISK_NO_ACL
Ne pas lire les listes de contrôle d'accès (ACL). Par défaut, les ACL sont lues depuis le disque.
ARCHIVE_READDISK_NO_FFLAGS
Ne pas lire les attributs de fichier (file flags). Par défaut, les attributs de fichier sont lus depuis le disque. Voir chattr(1) (Linux) ou chflags(1) (FreeBSD, Mac OS X) pour plus d'informations sur les attributs de fichier.
ARCHIVE_READDISK_NO_TRAVERSE_MOUNTS
Ne pas traverser les points de montage. Par défaut, les points de montage sont traversés.
ARCHIVE_READDISK_NO_XATTRe>
Ne pas lire les attributs étendus de fichier (xattrs). Par défaut, les attributs étendus de fichier sont lus depuis le disque. Voir xattr(7) (Linux), xattr(2) (Mac OS X), ou getextattr(8) (FreeBSD) pour plus d'informations sur les attributs étendus de fichier.
ARCHIVE_READDISK_RESTORE_ATIME
Restaurer l'heure d'accès des fichiers parcourus. Par défaut, l'heure d'accès des fichiers parcourus n'est pas restaurée.
ARCHIVE_READDISK_NO_SPARSE
Ne pas lire les informations sur les fichiers épars. Par défaut, les informations sur les fichiers épars sont lues depuis le disque.
archive_read_disk_set_symlink_logical(), archive_read_disk_set_symlink_physical(), archive_read_disk_set_symlink_hybrid()
Ceci définit le mode utilisé pour gérer les liens symboliques. Le mode « logique » suit tous les liens symboliques. Le mode « physique » ne suit aucun lien symbolique. Le mode « hybride » se comporte actuellement de manière identique au mode « logique ».
archive_read_disk_gname(), archive_read_disk_uname()
Retourne un nom d'utilisateur ou de groupe étant donné une valeur gid ou uid. Par défaut, ceux-ci retournent toujours une chaîne NULL.
archive_read_disk_set_gname_lookup(), archive_read_disk_set_uname_lookup()
Ceux-ci vous permettent de remplacer les fonctions utilisées pour la recherche des noms d'utilisateur et de groupe. Vous pouvez également fournir un pointeur void * vers une structure de données privée et une fonction de nettoyage pour ces données. La fonction de nettoyage sera appelée lorsque l'objet archive sera détruit ou lorsque de nouvelles fonctions de recherche seront enregistrées.
archive_read_disk_set_standard_lookup()
Cette fonction de commodité installe un ensemble standard de fonctions de recherche des noms d'utilisateur et de groupe. Ces fonctions utilisent getpwuid(3) et getgrgid(3) pour convertir les ID en noms, retournant NULL par défaut si les noms ne peuvent pas être trouvés. Ces fonctions implémentent également un cache mémoire simple pour réduire le nombre d'appels à getpwuid(3) et getgrgid(3).
archive_read_disk_entry_from_file()
Remplit un objet struct archive_entry avec les informations d'un fichier particulier. L'objet archive_entry doit déjà avoir été créé avec archive_entry_new(3) et au moins un des champs chemin source ou chemin doit déjà être défini. (Si les deux sont définis, le chemin source sera utilisé.)

Les informations sont lues depuis le disque en utilisant le nom de chemin de l'objet struct archive_entry. Si un descripteur de fichier est fourni, certaines informations seront obtenues en utilisant ce descripteur de fichier, sur les plateformes qui supportent les appels système appropriés.

Si un pointeur vers une struct stat est fourni, les informations de cette structure seront utilisées au lieu de lire le disque lorsque cela est approprié. Cela peut apporter des avantages en termes de performance dans des scénarios où les informations de la struct stat ont déjà été lues depuis le disque comme effet secondaire d'une autre opération. (Par exemple, les bibliothèques de parcours de répertoire fournissent souvent ces informations.)

Lorsque nécessaire, les ID utilisateur et groupe sont convertis en noms d'utilisateur et de groupe en utilisant les fonctions de recherche actuellement enregistrées ci-dessus. Cela affecte les champs de propriété du fichier et les valeurs ACL dans l'objet struct archive_entry.

archive_read_disk_descend()
Si l'entrée actuelle peut être descendue, cette fonction marquera le répertoire comme la prochaine entrée pour que archive_read_header(3) la visite.
archive_read_disk_can_descend()
Retourne 1 si l'entrée actuelle est un répertoire non visité et 0 sinon.
archive_read_disk_current_filesystem()
Retourne l'index de la dernière entrée de système de fichiers qui a été visitée via archive_read_disk
archive_read_disk_current_filesystem_is_synthetic()
Retourne 1 si le système de fichiers actuel est un système de fichiers virtuel. Retourne 0 si le système de fichiers actuel n'est pas un système de fichiers virtuel. Retourne -1 s'il est inconnu.
archive_read_disk_current_filesystem_is_remote()
Retourne 1 si le système de fichiers actuel est un système de fichiers distant. Retourne 0 si le système de fichiers actuel n'est pas un système de fichiers distant. Retourne -1 s'il est inconnu.
archive_read_disk_set_matching()
Permet à l'appelant de définir struct archive *_ma pour comparer chaque entrée lors des appels à archive_read_header(3). Si une correspondance est trouvée sur la base des appels à archive_match_path_excluded, archive_match_time_excluded, ou archive_match_owner_excluded, alors la fonction de rappel spécifiée par le paramètre _excluded_func sera exécutée. Cette fonction recevra les données fournies au quatrième paramètre, void *_client_data.
archive_read_disk_set_metadata_filter_callback()
Permet à l'appelant de définir une fonction de rappel lors des appels à archive_read_header(3) pour filtrer les métadonnées de chaque entrée. La fonction de rappel reçoit l'objet struct archive, les données de filtre personnalisées void* et la struct archive_entry. Si la fonction de rappel retourne une erreur, ARCHIVE_RETRY sera retourné et l'entrée ne sera pas traitée davantage.
Plus d'informations sur l'objet struct archive et la conception globale de la bibliothèque peuvent être trouvées dans la vue d'ensemble de libarchive(3).

EXEMPLES

L'exemple suivant illustre une utilisation basique de la bibliothèque en montrant comment l'utiliser pour copier un élément sur disque dans une archive.

void
file_to_archive(struct archive *a, const char *name)
{
  char buff[8192];
  size_t bytes_read;
  struct archive *ard;
  struct archive_entry *entry;
  int fd;

  ard = archive_read_disk_new();
  archive_read_disk_set_standard_lookup(ard);
  entry = archive_entry_new();
  fd = open(name, O_RDONLY);
  if (fd < 0)
     return;
  archive_entry_copy_pathname(entry, name);
  archive_read_disk_entry_from_file(ard, entry, fd, NULL);
  archive_write_header(a, entry);
  while ((bytes_read = read(fd, buff, sizeof(buff))) > 0)
    archive_write_data(a, buff, bytes_read);
  archive_write_finish_entry(a);
  archive_read_free(ard);
  archive_entry_free(entry);
}

VALEURS DE RETOUR

La plupart des fonctions retournent ARCHIVE_OK (zéro) en cas de succès, ou l'un des plusieurs codes d'erreur négatifs en cas d'erreur. Les codes d'erreur spécifiques incluent : ARCHIVE_RETRY pour les opérations qui pourraient réussir si elles étaient retentées, ARCHIVE_WARN pour les conditions inhabituelles qui n'empêchent pas les opérations ultérieures, et ARCHIVE_FATAL pour les erreurs graves qui rendent les opérations restantes impossibles.

archive_read_disk_new() retourne un pointeur vers un objet struct archive nouvellement alloué ou NULL si l'allocation a échoué pour une raison quelconque.

archive_read_disk_gname() et archive_read_disk_uname() retournent des pointeurs const char * vers le nom textuel ou NULL si la recherche a échoué pour une raison quelconque. Le pointeur retourné pointe vers un stockage interne qui peut être réutilisé lors du prochain appel à l'une de ces fonctions ; les appelants doivent copier la chaîne s'ils ont besoin de continuer à y accéder.

ERREURS

Des codes d'erreur détaillés et des descriptions textuelles sont disponibles via les fonctions archive_errno() et archive_error_string().

BUGS

Les fonctions de recherche de noms d'utilisateur et de groupe «standard» ne sont pas les valeurs par défaut car getgrgid(3) et getpwuid(3) sont parfois trop volumineuses pour des applications particulières. La conception actuelle permet à l'auteur de l'application d'utiliser une implémentation plus compacte lorsque cela est approprié.

La liste complète des métadonnées lues à partir du disque par archive_read_disk_entry_from_file() dépend nécessairement du système.

La fonction archive_read_disk_entry_from_file() lit autant d'informations que possible à partir du disque. Une méthode devrait être fournie pour limiter cela afin que les clients qui n'ont pas besoin des ACL, par exemple, puissent éviter le travail supplémentaire nécessaire pour rechercher de telles informations.

Cette API devrait fournir un ensemble de méthodes pour parcourir une arborescence de répertoires. Cela en ferait un parallèle direct de l'API archive_read(3). Lorsque de telles méthodes seront implémentées, le mode «hybride» de lien symbolique aura un sens.
