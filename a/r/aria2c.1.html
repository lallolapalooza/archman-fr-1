-k, --min-split-size=<TAILLE>
aria2 ne divise pas les plages de moins de 2*TAILLE octets. Par exemple, considérons le téléchargement d'un fichier de 20 Mio. Si TAILLE est de 10M, aria2 peut diviser le fichier en 2 plages [0-10 Mio) et [10 Mio-20 Mio) et le télécharger en utilisant 2 sources (si --split >= 2, bien sûr). Si TAILLE est de 15M, car 2*15M > 20 Mio, aria2 ne divise pas le fichier et le télécharge en utilisant 1 source. Vous pouvez ajouter K ou M (1K = 1024, 1M = 1024K). --stream-piece-selector=<SELECTEUR>
Spécifie l'algorithme de sélection de morceaux utilisé dans le téléchargement HTTP/FTP. Un morceau est un segment de longueur fixe qui est téléchargé en parallèle dans un téléchargement segmenté. Par défaut : default.
default
Sélectionne un morceau pour réduire le nombre de connexions établies. C'est un comportement par défaut raisonnable car l'établissement d'une connexion est une opération coûteuse.
inorder
Sélectionne un morceau proche du début du fichier. Ceci est utile pour regarder des films pendant le téléchargement. L'option --enable-http-pipelining peut être utile pour réduire la surcharge de reconnexion. Notez qu'aria2 respecte l'option --min-split-size, il sera donc nécessaire de spécifier une valeur raisonnable à cette option.
random
Sélectionne un morceau au hasard. Comme inorder, l'option --min-split-size est respectée.
geom
Au démarrage du téléchargement d'un fichier, sélectionne un morceau proche du début du fichier comme inorder, puis augmente exponentiellement l'espace entre les morceaux. Cela réduit le nombre de connexions établies, tout en téléchargeant d'abord la partie début du fichier. C'est utile pour regarder des films pendant le téléchargement.
-t, --timeout=<SEC>

--uri-selector=<SELECTEUR>
Spécifie l'algorithme de sélection d'URI. Les valeurs possibles sont inorder, feedback et adaptive. Si inorder est donné, l'URI est essayée dans l'ordre où elle apparaît dans la liste d'URI. Si feedback est donné, aria2 utilise la vitesse de téléchargement observée lors des téléchargements précédents et choisit le serveur le plus rapide dans la liste d'URI. Cela permet également de sauter efficacement les miroirs morts. La vitesse de téléchargement observée fait partie du profil de performance des serveurs mentionnés dans les options --server-stat-of et --server-stat-if. Si adaptive est donné, il sélectionne l'un des meilleurs miroirs pour les connexions principales et réservées. Pour les connexions supplémentaires, il retourne les miroirs qui n'ont pas encore été testés, et si chacun d'eux a déjà été testé, il retourne les miroirs qui doivent être retester. Sinon, il ne sélectionne plus de miroirs. Comme feedback, il utilise un profil de performance des serveurs. Par défaut : feedback

aria2 utilise un fichier de contrôle pour suivre la progression d'un téléchargement. INTERFACE

RPC

aria2 fournit des interfaces JSON-RPC sur HTTP et XML-RPC sur HTTP qui offrent fondamentalement les mêmes fonctionnalités. aria2 fournit également JSON-RPC sur WebSocket. JSON-RPC sur WebSocket utilise les mêmes signatures de méthode et le même format de réponse que JSON-RPC sur HTTP, mais fournit en plus des notifications initiées par le serveur. Voir la section JSON-RPC sur WebSocket pour plus

d'informations.

Le chemin de requête de l'interface JSON-RPC (à la fois sur HTTP et sur WebSocket) est /jsonrpc. Le chemin de requête de l'interface XML-RPC est /rpc

.

L'URI WebSocket pour JSON-RPC sur WebSocket est ws://HOST:PORT/jsonrpc. Si vous avez activé le chiffrement SSL/TLS, utilisez plutôt wss://HOST:PORT/

jsonrpc.

Le JSON-RPC implémenté est basé sur JSON-RPC 2.0 http://jsonrpc.org/specification et supporte HTTP POST et GET (JSONP). Le transport WebSocket est une extension

aria2.

L'interface JSON-RPC ne supporte pas les notifications sur HTTP, mais le serveur RPC enverra des notifications sur WebSocket. Elle ne supporte pas non plus les nombres à virgule flottante. L'encodage des caractères doit être

UTF-8.

Lors de la lecture de la documentation suivante pour JSON-RPC, interprétez les structs comme des objets

JSON.

Terminologi

e

GI

D
Le GID (ou gid) est une clé pour gérer chaque téléchargement. Chaque téléchargement se verra attribuer un GID unique. Le GID est stocké comme une valeur binaire de 64 bits dans aria2. Pour l'accès RPC, il est représenté comme une chaîne hexadécimale de 16 caractères (par ex., 2089b05ecca3d829). Normalement, aria2 génère ce GID pour chaque téléchargement, mais l'utilisateur peut spécifier des GID manuellement en utilisant l'option --gid. Lors de l'interrogation des téléchargements par GID, v
