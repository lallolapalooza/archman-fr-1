archive_entry_linkify(3)

Paquet: libarchive

Licences: BSD-2-Clause

ARCHIVE_ENTRY_LINKIFY(3) Manuel des fonctions de bibliothèque ARCHIVE_ENTRY_LINKIFY(3)

NOM

archive_entry_linkresolver, archive_entry_linkresolver_new, archive_entry_linkresolver_set_strategy, archive_entry_linkresolver_free, archive_entry_linkify — fonctions de résolution de liens physiques

BIBLIOTHÈQUE

Bibliothèque d'archives en flux (libarchive, -larchive)

SYNOPSIS

#include <archive_entry.h>

struct archive_entry_linkresolver *
archive_entry_linkresolver_new(void);

void
archive_entry_linkresolver_set_strategy(struct archive_entry_linkresolver *resolver, int format);

void
archive_entry_linkresolver_free(struct archive_entry_linkresolver *resolver);

void
archive_entry_linkify(struct archive_entry_linkresolver *resolver, struct archive_entry **entry, struct archive_entry **sparse);

DESCRIPTION

Les programmes qui veulent créer des archives doivent gérer les liens physiques. Les liens physiques sont gérés de différentes manières par les formats d'archives. Les stratégies de base sont :

  1. Ignorer les liens physiques et stocker le corps pour chaque référence (ancien cpio, zip).
  2. Stocker le corps la première fois qu'un inode est vu (ustar, pax).
  3. Stocker le corps la dernière fois qu'un inode est vu (nouveau cpio).

Les fonctions archive_entry_linkresolver aident en fournissant une interface unifiée et en gérant la complexité en coulisse.

Les fonctions archive_entry_linkresolver supposent que les instances archive_entry ont des valeurs nlinks, inode et device valides. La valeur de l'inode et du device est utilisée pour faire correspondre les entrées. La valeur nlinks est utilisée pour déterminer si toutes les références ont été trouvées et si les références internes peuvent être recyclées.

La fonction archive_entry_linkresolver_new() alloue un nouveau résolveur de liens. L'instance peut être libérée en utilisant archive_entry_linkresolver_free(). Toutes les entrées différées sont vidées et le stockage interne est libéré.

La fonction archive_entry_linkresolver_set_strategy() sélectionne la stratégie de lien physique optimale pour le format donné. Le code de format peut être obtenu à partir de archive_format(3). La fonction peut être appelée plus d'une fois, mais il est recommandé de vider d'abord toutes les entrées différées.

La fonction archive_entry_linkify() est le cœur de archive_entry_linkresolver. L'argument entry() pointe vers le archive_entry qui doit être écrit. Selon la stratégie, l'une des actions suivantes est effectuée :

  1. Pour les formats d'archives simples, *entry est laissé inmodifié et *sparse est défini sur NULL.
  2. Pour les formats d'archives de type tar, *sparse est défini sur NULL. Si *entry est NULL, aucune action n'est effectuée. Si le nombre de liens de *entry est supérieur à 1 et que le type de fichier est un fichier régulier ou un lien symbolique, la liste interne est recherchée pour un inode correspondant. S'il est trouvé, le nombre de liens est décrémenté et la taille du fichier de *entry est mise à 0 pour notifier qu'aucun corps ne doit être écrit. Si aucun inode correspondant n'est trouvé, une copie de l'entrée est ajoutée au cache interne avec un nombre de liens réduit d'un.
  3. Pour les formats d'archives de type nouveau cpio, une valeur pour *entry de NULL est utilisée pour vider les entrées différées. Dans ce cas, *entry est défini sur une entrée différée arbitraire et l'entrée elle-même est retirée de la liste interne. Si la liste interne est vide, *entry est défini sur NULL. Dans les deux cas, *sparse est défini sur NULL et la fonction retourne. Si le nombre de liens de *entry est un ou si le type de fichier est un répertoire ou un périphérique, *sparse est défini sur NULL et aucune autre action n'est effectuée. Sinon, la liste interne est recherchée pour un inode correspondant. Si aucun inode correspondant n'est trouvé, l'entrée est ajoutée à la liste interne, *entry et *sparse sont définis sur NULL et la fonction retourne. Si un inode correspondant est trouvé, le nombre de liens est décrémenté. S'il reste supérieur à un, l'entrée existante dans la liste interne est échangée avec *entry après avoir conservé le nombre de liens. L'entrée existante est retournée dans *entry. Si le nombre de liens atteint un, la nouvelle entrée est également retirée de la liste interne et retournée dans *sparse. Sinon, *sparse est défini sur NULL.

L'utilisation générale est donc :

  1. Pour chaque nouvelle entrée d'archive, appelez archive_entry_linkify().
  2. Gardez à l'esprit que les entrées retournées peuvent maintenant avoir une taille de 0.
  3. Si *entry n'est pas NULL, archivez-le.
  4. Si *sparse n'est pas NULL, archivez-le.
  5. Après que toutes les entrées aient été écrites sur disque, appelez archive_entry_linkify() avec *entry défini sur NULL et archivez l'entrée retournée tant qu'elle n'est pas NULL.

VALEURS DE RETOUR

archive_entry_linkresolver_new() retourne NULL en cas d'échec de malloc(3).
