ARCHIVE_READ(3) Manuel des fonctions de bibliothèque ARCHIVE_READ(3)

NOM

archive_read — fonctions pour la lecture d'archives en flux

BIBLIOTHÈQUE

Bibliothèque d'archives en flux (libarchive, -larchive)

SYNOPSIS

#include <archive.h>

DESCRIPTION

Ces fonctions fournissent une API complète pour la lecture d'archives en flux. Le processus général consiste à créer d'abord l'objet struct archive, définir les options, initialiser le lecteur, parcourir les en-têtes de l'archive et les données associées, puis fermer l'archive et libérer toutes les ressources.

Créer l'objet archive

Voir archive_read_new(3).

Pour lire une archive, vous devez d'abord obtenir un objet struct archive initialisé à partir de archive_read_new().

Activer les filtres et les formats

Voir archive_read_filter(3) et archive_read_format(3).

Vous pouvez ensuite modifier cet objet pour les opérations souhaitées à l'aide des diverses fonctions archive_read_set_XXX() et archive_read_support_XXX() . En particulier, vous devrez invoquer les fonctions archive_read_support_XXX() appropriées pour activer la prise en charge de la compression et du format correspondants. Notez que ces dernières fonctions effectuent deux opérations distinctes : elles font en sorte que le code de prise en charge correspondant soit lié à votre programme, et elles activent le code de détection automatique correspondant. Sauf si vous avez des contraintes spécifiques, vous voudrez généralement invoquer archive_read_support_filter_all() et archive_read_support_format_all() pour activer la détection automatique pour tous les formats et types de compression actuellement pris en charge par la bibliothèque.

Définir les options

Voir archive_read_set_options(3).

Ouvrir l'archive

Voir archive_read_open(3).

Une fois que vous avez préparé l'objet struct archive, vous appelez archive_read_open() pour ouvrir réellement l'archive et la préparer pour la lecture. Il existe plusieurs variantes de cette fonction ; la plus basique attend que vous fournissiez des pointeurs vers plusieurs fonctions capables de fournir des blocs d'octets à partir de l'archive. Il existe des formes pratiques qui vous permettent de spécifier un nom de fichier, un descripteur de fichier, FILE * un objet, ou un bloc de mémoire à partir duquel lire les données de l'archive. Notez que la bibliothèque principale ne fait aucune hypothèse sur la taille des blocs lus ; les fonctions de rappel sont libres de lire la taille de bloc qui convient le mieux au support.

Consommer l'archive

Voir archive_read_header(3), archive_read_data(3) et archive_read_extract(3).

Chaque entrée d'archive se compose d'un en-tête suivi d'une certaine quantité de données. Vous pouvez obtenir l'en-tête suivant avec archive_read_next_header(), qui renvoie un pointeur vers une structure struct archive_entry avec des informations sur l'élément d'archive courant. Si l'entrée est un fichier régulier, l'en-tête sera suivi des données du fichier. Vous pouvez utiliser archive_read_data() (qui fonctionne de manière très similaire à l'appel système read(2) ) pour lire ces données à partir de l'archive, ou archive_read_data_block() qui fournit une interface légèrement plus efficace. Vous préférerez peut-être utiliser le niveau supérieur archive_read_data_skip(), qui lit et ignore les données de cette entrée, archive_read_data_into_fd(), qui copie les données vers le descripteur de fichier fourni, ou archive_read_extract(), qui recrée l'entrée spécifiée sur le disque et copie les données à partir de l'archive. En particulier, notez que archive_read_extract() utilise la structure struct archive_entry que vous lui fournissez, qui peut différer de l'entrée tout juste lue à partir de l'archive. En particulier, de nombreuses applications voudront remplacer le chemin d'accès, les permissions de fichier ou la propriété.

Libérer les ressources

Voir archive_read_free(3).

Une fois que vous avez terminé de lire les données à partir de l'archive, vous devriez appeler archive_read_close() pour fermer l'archive, puis appeler archive_read_free() pour libérer toutes les ressources, y compris toute la mémoire allouée par la bibliothèque.

EXEMPLES

Ce qui suit illustre l'utilisation de base de la bibliothèque. Dans cet exemple, les fonctions de rappel sont simplement des enveloppes autour des appels système open(2), read(2)et close(2) .

void
list_archive(const char *name)
{
  struct mydata *mydata;
  struct archive *a;
  struct archive_entry *entry;

  mydata = malloc(sizeof(struct mydata));
  a = archive_read_new();
  mydata->name = name;
  archive_read_support_filter_all(a);
  archive_read_support_format_all(a);
  archive_read_open(a, mydata, myopen, myread, myclose);
  while (archive_read_next_header(a, &entry) == ARCHIVE_OK) {
    printf("%s\n",archive_entry_pathname(entry));
    archive_read_data_skip(a);
  }
  archive_read_free(a);
  free(mydata);
}

la_ssize_t
myread(struct archive *a, void *client_data, const void **buff)
{
  struct mydata *mydata = client_data;

  *buff = mydata->buff;
  return (read(mydata->fd, mydata->buff, 10240));
}

int
myopen(struct archive *a, void *client_data)
{
  struct mydata *mydata = client_data;

  mydata->fd = open(mydata->name, O_RDONLY);
  return (mydata->fd >= 0 ? ARCHIVE_OK : ARCHIVE_FATAL);
}

int
myclose(struct archive *a, void *client_data)
{
  struct mydata *mydata = client_data;

  if (mydata->fd > 0)
    close(mydata->fd);
  return (ARCHIVE_OK);
}

BUGS

De nombreux programmes d'archivage traditionnels traitent les fichiers vides comme des archives vides valides. Par exemple, de nombreuses implémentations de tar(1) vous permettent d'ajouter des entrées à un fichier vide. Bien sûr, il est impossible de déterminer le format d'un fichier vide en inspectant son contenu, c'est pourquoi cette bibliothèque traite les fichiers vides comme ayant un format spécial « vide ».
