DESCRIPTION

GNU as est en réalité une famille d'assembleurs. Si vous utilisez (ou avez utilisé) l'assembleur GNU sur une architecture, vous devriez trouver un environnement assez similaire lorsque vous l'utilisez sur une autre architecture. Chaque version a beaucoup en commun avec les autres, y compris les formats de fichiers objet, la plupart des directives de l'assembleur (souvent appelées pseudo-ops) et la syntaxe de l'assembleur.

as est principalement destiné à assembler la sortie du compilateur C GNU "gcc" pour une utilisation par l'éditeur de liens "ld". Néanmoins, nous avons essayé de faire en sorte que as assemble correctement tout ce que les autres assembleurs pour la même machine assembleraient. Toute exception est documentée explicitement. Cela ne signifie pas que as utilise toujours la même syntaxe qu'un autre assembleur pour la même architecture ; par exemple, nous connaissons plusieurs versions incompatibles de la syntaxe du langage d'assemblage 680x0.

Chaque fois que vous exécutez as, il assemble exactement un programme source. Le programme source est composé d'un ou plusieurs fichiers. (L'entrée standard est également un fichier.)

Vous donnez à as une ligne de commande qui contient zéro ou plusieurs noms de fichiers d'entrée. Les fichiers d'entrée sont lus (du premier nom de fichier au dernier). Un argument de ligne de commande (dans n'importe quelle position) qui n'a pas de signification spéciale est considéré comme un nom de fichier d'entrée.

Si vous ne donnez aucun nom de fichier à as, il tente de lire un fichier d'entrée à partir de l'entrée standard de as, qui est normalement votre terminal. Vous devrez peut-être taper ctl-D pour indiquer à as qu'il n'y a plus de programme à assembler.

Utilisez -- si vous devez explicitement nommer le fichier d'entrée standard dans votre ligne de commande.

Si la source est vide, as produit un petit fichier objet vide.

as peut écrire des avertissements et des messages d'erreur dans le fichier d'erreur standard (généralement votre terminal). Cela ne devrait pas se produire lorsqu'un compilateur exécute as automatiquement. Les avertissements signalent une hypothèse faite pour que as puisse continuer à assembler un programme défectueux ; les erreurs signalent un problème grave qui interrompt l'assemblage.

Si vous invoquez as via le compilateur C GNU, vous pouvez utiliser l'option -Wa pour passer des arguments à l'assembleur. Les arguments de l'assembleur doivent être séparés les uns des autres (et de -Wa) par des virgules. Par exemple :

gcc -c -g -O -Wa,-alh,-L fichier.c

Ceci passe deux options à l'assembleur : -alh (générer une liste sur la sortie standard avec le code source de haut niveau et le code d'assemblage) et -L (conserver les symboles locaux dans la table des symboles).

Habituellement, vous n'avez pas besoin d'utiliser ce mécanisme -Wa, car de nombreuses options de ligne de commande du compilateur sont automatiquement transmises à l'assembleur par le compilateur. (Vous pouvez appeler le pilote du compilateur GNU avec l'option -v pour voir précisément quelles options il transmet à chaque passe de compilation, y compris l'assembleur.)

OPTIONS

@fichier
Lire les options de ligne de commande depuis fichier. Les options lues sont insérées à la place de l'option @fichier d'origine. Si fichier n'existe pas ou ne peut pas être lu, alors l'option sera traitée littéralement, et non supprimée.

Les options dans fichier sont séparées par des espaces blancs. Un caractère d'espace blanc peut être inclus dans une option en entourant l'option entière de guillemets simples ou doubles. Tout caractère (y compris une barre oblique inverse) peut être inclus en précédant le caractère à inclure avec une barre oblique inverse. Le fichier peut lui-même contenir des options @fichier supplémentaires ; toutes ces options seront traitées récursivement.

-a[cdghilmns]
Activer les listages, de différentes manières :
-ac
omettre les conditionnels faux
-ad
omettre les directives de débogage
-ag
inclure des informations générales, telles que la version et les options passées
-ah
inclure le code source de haut niveau
-al
inclure l'assembleur
-ali
inclure l'assembleur avec ginsn
-am
inclure les expansions de macros
-an
omettre le traitement des formulaires
-as
inclure les symboles
=fichier
définir le nom du fichier de liste

Vous pouvez combiner ces options ; par exemple, utilisez -aln pour une liste d'assemblage sans traitement des formulaires. L'option =fichier, si utilisée, doit être la dernière. En soi, -a est équivalent à -ahls.

--alternate
Commencer en mode macro alternatif.
--compress-debug-sections
Compresser les sections de débogage DWARF à l'aide de zlib avec SHF_COMPRESSED de l'ABI ELF. Le fichier objet résultant peut ne pas être compatible avec les anciens linkers et utilitaires de fichiers objets. Notez que si la compression rendait une section donnée plus grande, elle n'est pas compressée.
--compress-debug-sections=none
--compress-debug-sections=zlib
--compress-debug-sections=zlib-gnu
--compress-debug-sections=zlib-gabi
--compress-debug-sections=zstd
Ces options contrôlent la compression des sections de débogage DWARF. --compress-debug-sections=none est équivalent à --nocompress-debug-sections. --compress-debug-sections=zlib et --compress-debug-sections=zlib-gabi sont équivalents à --compress-debug-sections. --compress-debug-sections=zlib-gnu compresse les sections de débogage DWARF en utilisant le format obsolète zlib-gnu. Les sections de débogage sont renommées pour commencer par .zdebug. --compress-debug-sections=zstd compresse les sections de débogage DWARF à l'aide de zstd. Notez : si la compression rendait une section plus grande, elle n'est ni compressée ni renommée.
--nocompress-debug-sections
Ne pas compresser les sections de débogage DWARF. C'est généralement le comportement par défaut pour toutes les cibles sauf x86/x86_64, mais une option de configuration peut être utilisée pour remplacer cela.
-D
Activer le débogage dans les backends spécifiques à la cible, si pris en charge. Sinon, ignoré. Même si ignoré, cette option est acceptée pour la compatibilité des scripts avec les appels à d'autres assembleurs.
--debug-prefix-map ancien=nouveau
Lors de l'assemblage de fichiers dans le répertoire ancien, enregistrer les informations de débogage les décrivant comme se trouvant dans nouveau à la place.
--defsym sym=valeur
Définir le symbole sym à la valeur valeur avant d'assembler le fichier d'entrée. valeur doit être une constante entière. Comme en C, un préfixe 0x indique une valeur hexadécimale, et un préfixe 0 indique une valeur octale. La valeur du symbole peut être remplacée à l'intérieur d'un fichier source via l'utilisation de la pseudo-instruction ".set".
--dump-config
Affiche la configuration de l'assembleur, puis se termine.
--elf-stt-common=no
--elf-stt-common=yes
Ces options contrôlent si l'assembleur ELF doit générer des symboles communs avec le type "STT_COMMON". Le comportement par défaut peut être contrôlé par une option de configuration --enable-elf-stt-common.
--emulation=nom
Si l'assembleur est configuré pour prendre en charge plusieurs configurations cibles différentes, alors cette option peut être utilisée pour sélectionner la forme souhaitée.
-f
"rapide"---ignore le prétraitement des espaces blancs et des commentaires (suppose que la source est une sortie de compilateur).
-g
--gen-debug
Génère des informations de débogage pour chaque ligne source de l'assembleur en utilisant le format de débogage préféré par la cible. Cela signifie actuellement soit STABS, ECOFF ou DWARF2. Lorsque le format de débogage est DWARF, une section ".debug_info" et ".debug_line" n'est émise que lorsque le fichier d'assemblage n'en génère pas une lui-même.
--gstabs
Génère des informations de débogage stabs pour chaque ligne d'assembleur. Cela peut aider au débogage du code assembleur, si le débogueur peut le gérer.
--gstabs+
Génère des informations de débogage stabs pour chaque ligne d'assembleur, avec des extensions GNU que probablement seul gdb peut gérer, et qui pourraient faire planter ou refuser de lire votre programme à d'autres débogueurs. Cela peut aider au débogage du code assembleur. Actuellement, la seule extension GNU est l'emplacement du répertoire de travail courant au moment de l'assemblage.
--gdwarf-2
Génère des informations de débogage DWARF2 pour chaque ligne d'assembleur. Cela peut aider au débogage du code assembleur, si le débogueur peut le gérer. Notez que cette option n'est prise en charge que par certaines cibles, pas par toutes.
--gdwarf-3
Cette option est identique à l'option --gdwarf-2, sauf qu'elle permet la possibilité de générer des informations de débogage supplémentaires selon la version 3 de la spécification DWARF. Notez que l'activation de cette option ne garantit pas la génération d'informations supplémentaires, le choix de le faire dépend de la cible.
--gdwarf-4
Cette option est identique à l'option --gdwarf-2, sauf qu'elle permet la possibilité de générer des informations de débogage supplémentaires selon la version 4 de la spécification DWARF. Notez que l'activation de cette option ne garantit pas la génération d'informations supplémentaires, le choix de le faire dépend de la cible.
--gdwarf-5
Cette option est identique à l'option --gdwarf-2, sauf qu'elle permet la possibilité de générer des informations de débogage supplémentaires selon la version 5 de la spécification DWARF. Notez que l'activation de cette option ne garantit pas la génération d'informations supplémentaires, le choix de le faire dépend de la cible.
--gdwarf-sections
Au lieu de créer une section .debug_line, crée une série de sections .debug_line.foo où foo est le nom de la section de code correspondante. Par exemple, une section de code appelée .text.func aura ses informations de numéro de ligne dwarf placées dans une section appelée .debug_line.text.func. Si la section de code s'appelle simplement .text, la section de ligne de débogage s'appellera toujours simplement .debug_line sans suffixe.
--gdwarf-cie-version=version
Contrôle quelle version des entrées d'information commune DWARF (CIE) est produite. Lorsque ce drapeau n'est pas spécifié, la valeur par défaut est la version 1, bien que certaines cibles puissent modifier ce défaut. D'autres valeurs possibles pour version sont 3 ou 4.
--generate-missing-build-notes=yes
--generate-missing-build-notes=no
Ces options contrôlent si l'assembleur ELF doit générer des notes d'attributs GNU Build s'il n'y en a pas dans les sources d'entrée. Le comportement par défaut peut être contrôlé par l'option de configuration --enable-generate-build-notes.
--gsframe
--gsframe
Crée la section .sframe à partir des directives CFI.
--hash-size N
Ignoré. Supporté pour la compatibilité de la ligne de commande avec d'autres assembleurs.
--help
Imprime un résumé des options de ligne de commande et quitte.
--target-help
Imprime un résumé de toutes les options spécifiques à la cible et quitte.
-I dir
Ajoute le répertoire dir à la liste de recherche pour les directives ".include".
-J
