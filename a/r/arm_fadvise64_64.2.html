DESCRIPTIO

N

Les programmes peuvent utiliser posix_fadvise() pour annoncer l'intention d'accéder aux données d'un fichier selon un motif spécifique à l'avenir, permettant ainsi au noyau d'effectuer les optimisations

appropriées.

Le conseil s'applique à une région (pas nécessairement existante) commençant à offset et s'étendant sur size octets (ou jusqu'à la fin du fichier si size vaut 0) dans le fichier référencé par fd. Le conseil n'est pas contraignant ; il constitue simplement une attente de la part de

l'application.

Les valeurs autorisées pour advice sont

:
POSIX_FADV_NOR
MAL
Indique que l'application n'a aucun conseil à donner concernant son motif d'accès pour les données spécifiées. Si aucun conseil n'est donné pour un fichier ouvert, c'est l'hypothèse par
défaut.
POSIX_FADV_SEQUENT
IAL
L'application s'attend à accéder aux données spécifiées séquentiellement (avec les offsets inférieurs lus avant les supérieurs)
.
POSIX_FADV_RAN
DOM
Les données spécifiées seront accessibles dans un ordre
aléatoire.
POSIX_FADV_NORE
USE
Les données spécifiée
s ne seront accessibl
es qu'une seule fois.
Avant Linux 2.6.18, POSIX_FADV_NOREUSE avait la même sémantique que POSIX_FADV_WILLNEED. C'était probablement un bogue ; de Linux 2.6.18 jusqu'à Linux 6.2, ce drapeau était sans effet. Depuis Linux 6.3, POSIX_FADV_NOREUSE indique que l'algorithme de remplacement de pages du noyau peut ignorer l'accès aux pag
es de cache mappées marquées par ce drapeau. C'est
utile, par exemple, lors du streaming de gros fichiers.

POSIX_FADV_WILLNEED initie une lecture non bloquante de la région spécifiée dans le cache de pages. La quantité de données lue peut être réduite par
le noyau en fonction de la charge de la mémoire virtuelle. (Quelques mégaoctet

EED
Les données spécifiées n

POSIX_FADV_DONTNEED tente de libérer les pages en cache associées à la région spécifiée. C'est utile, par exemple, lors du streaming de gros fichiers. Un programme peut périodiquement demander au noyau de libérer des données en cache déjà utilisées, afin que des pages en cache plus utiles ne soient pas jetées à la
place.
Les demandes de suppression de pages partielles sont ignorées. Il est préférable de préserver les données nécessaires que de jeter les données inutiles. Si l'application exige que des données soient prises en compte pour la suppression, alors offset et size doivent être alignés sur une
page.
L'implémentation peut tenter d'écrire sur disque les pages modifiées dans la région spécifiée, mais cela n'est pas garanti. Toute page modifiée non écrite ne sera pas libérée. Si l'application souhaite s'assurer que les pages modifiées seront libérées, elle devrait appeler fsync(2) ou fdatasync(2

VERSION

S

Sous Linux, POSIX_FADV_NORMAL définit la fenêtre de prélecture à la taille par défaut pour le périphérique de stockage ; POSIX_FADV_SEQUENTIAL double cette taille, et POSIX_FADV_RANDOM désactive complètement la prélecture de fichier. POSIX_FADV_NOREUSE ne modifie pas la taille de la fenêtre de prélecture. Ces changements affectent l'ensemble du fichier, pas seulement la région spécifiée (mais les autres descripteurs de fichier ouverts sur le même fichier ne sont pas affectés)

.

Différences bibliothèque

C/noyau

Le nom de la fonction d'enveloppe dans la bibliothèque C est posix_fadvise(). L'appel système sous-jacent est appelé fadvise64() (ou, sur certaines architectures, fadvise64_64()) ; la différence entre les deux est que le premier appel système suppose que le type de l'argument size est size_t, alors que le second attend loff_t à c

et end
roit.

Variantes spécifiques à

l'architecture

Certaines architectures exigent que les arguments 64 bits soient alignés dans une paire de registres appropriée (voir syscall(2) pour plus de détails). Sur de telles architectures, la signature d'appel de posix_fadvise() montrée dans le SYNOPSIS forcerait un registre à être gaspillé comme remplissage entre les fd et offset arguments. Par conséquent, ces architectures définissent une version de l'appel système qui ordonne les arguments de manière appropriée, mais est sinon exactement la même que posix_fadvi

se().

Par exemple, depuis Linux 2.6.14, ARM a l'appel système suivant

: 


long arm_fadvise64_64(int fd, int advice,
                      loff_t offset, loff_t size)
;

Ces détails spécifiques à l'architecture sont généralement masqués aux applications par la fonction d'enveloppe glibc posix_fadvise(), qui invoque l'

appel système spé
cifique approprié
à l'architecture.
