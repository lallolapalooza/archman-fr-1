NOM

argomail2dlf - convertit les fichiers journaux du serveur de messagerie ArGoSoft au format DLF d'email

SYNTAXE

argomail2dlf

DESCRIPTION

argomail2dlf convertit un fichier journal du serveur de messagerie ArGoSoft au format DLF d'email. Des informations sur le serveur de messagerie ArGoSoft peuvent être trouvées sur http://www.argosoft.com/applications/mailserver/. Le format générique DLF d'email est décrit dans email.xml.

Ce convertisseur DLF a été développé et testé avec ArGoSoft Mail Server Pro. Il pourrait fonctionner avec les versions Free et Plus, mais il n'a pas été testé.

CONFIGURATION DE LA JOURNALISATION

Pour fonctionner correctement avec Lire, vous devez vous assurer que les fonctionnalités de journalisation suivantes sont activées :

- Journaliser les commandes SMTP.
- Journaliser les conversations SMTP.
- Journaliser dans un fichier.

Les deux autres options (Journaliser les commandes POP et Journaliser les commandes Web) ne sont pas nécessaires et peuvent être laissées décochées.

LIMITATIONS

En raison des limitations du système de journalisation d'ArGoSoft Mail Server, les informations suivantes ne sont pas disponibles :

- taille des messages
- ID des messages

De plus, comme ArGoSoft ne journalise pas "l'identifiant de file d'attente" (c'est-à-dire un identifiant qui peut être utilisé pour suivre la livraison d'un message entre les différents composants), nous devons nous fier à des heuristiques et à des invariants supposés pour suivre les messages. Nous utilisons les adresses de l'expéditeur et du destinataire pour suivre les messages.

Livraison en ordre
Nous supposons que le serveur de messagerie ArGoSoft livrera ses messages dans l'ordre où il les a reçus.
Livraison à un seul destinataire
Nous supposons que le serveur de messagerie ArGoSoft ne livrera qu'à un seul destinataire à la fois. C'est-à-dire que si un message était adressé à deux destinataires du même domaine distant, il utiliserait deux connexions pour livrer ce message.
La livraison locale est immédiate
Nous supposons que la livraison locale (et le transfert) se produira juste après le code de statut 354 ou 250. Nous devons nous fier à cela, car les messages journaux liés au transfert ne mentionnent pas l'expéditeur.
Les messages inconnus ont été livrés via le web
Les messages livrés mais qui n'ont pas été envoyés via SMTP sont censés provenir du relais webmail (envoyés via l'interface web). Ils pourraient également avoir été envoyés avant le début du fichier journal.

EXEMPLES

Pour traiter un journal tel que produit par argomail

$ argomail2dlf < mail.log

argomail2dlf sera rarement utilisé seul, mais il sera plus probablement appelé par lr_log2report :

$ lr_log2report argomail < /var/log/mail.log
