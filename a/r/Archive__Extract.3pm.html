DESCRIPTIO

N

Archive::Extract est un mécanisme générique d'extraction

d'archives.

Il vous permet d'extraire n'importe quel fichier d'archive de type .tar, .tar.gz, .gz, .Z, tar.bz2, .tbz, .bz2, .zip, .xz,, .txz, .tar.xz ou .lzma sans avoir à vous soucier de la manière dont il le fait, ou d'utiliser des interfaces différentes pour chaque type en utilisant soit des modules perl, soit des outils en ligne de commande sur votre

système.

Voir la section « COMMENT ÇA MARCHE »

plus bas pour
plus de détails.

MÉTHODE

$ae = Archive::Extract->new(archive => '/path/to/archive',[type => TYPE]

Les valeurs valides pour "type" sont

Renvoie un objet "Archive::Extract" en cas de

succès, ou faux

$ae->extract( [to => '/output/path']

)

Extrait l'archive représentée par l'objet "Archive::Extract" vers le chemin de votre choix tel que spécifié par l'argument "to". Par défaut, c'est cwd(

).

Étant donné que les fichiers ".gz" ne contiennent jamais un répertoire, mais seulement un seul fichier ; si l'argument "to" est un répertoire existant, le fichier y est extrait, avec son suffixe ".gz" supprimé. Si l'argument "to" n'est pas un répertoire existant, l'argument "to" est compris comme étant un nom de fichier, si le type d'archive est "gz". Dans le cas où vous n'avez pas spécifié d'argument "to", le fichier de sortie sera le nom du fichier d'archive, privé de son suffixe ".gz", dans le répertoire de travail

courant.

"extract" essaiera d'abord une solution pure perl, puis retombera sur les outils en ligne de commande s'ils sont disponibles. Voir la section « VARIABLES GLOBALES » ci-dessous pour savoir comment modifier ce

comportement.

Elle renverra vrai en cas de succès, et faux en cas

d'échec.

En cas de succès, elle définira également les attributs suivants dans l'objet

:
$ae->
extract_path
C'est le répertoire vers lequel les fichiers ont été
extraits.
$ae->
files
C'est une référence de tableau contenant les chemins de tous les fichiers de l'archive, relatifs à l'argument "to" que vous avez spécifié. Pour obtenir le chemin complet d'un fichier extrait, vous utiliseriez : 
File::Spec->catfile( $to, $ae->files->[0]
);

Notez que tous les

fichiers d'une arch
ive tar seront au
format unix,
conformément à la

FONCTION

UTILITAIRE

type_for($archive

)

Étant donné un nom de fichier d'archive, elle détermine le type en analysant l'extension du nom de fichier. Utilisée par new() lorsque le paramètre "type" n'est pas passé. Également utile lorsque le fichier d'archive n'inclut pas de suffixe mais que le nom de fichier est autrement connu, par exemple lorsqu'un fichier est téléversé sur un serveur web et stocké avec un nom temporaire différent du nom original, et que vous voulez utiliser le même motif de détection que Archive::Extract. Exemple

: 
my $ae = Archive::Extract->new(
    archive => '/tmp/02af6s',
    type    => Archive::Extract::type_for('archive.zip'),
)
;

COMMENT ÇA

MARCHE

"Archive::Extract" essaie d'abord de déterminer quel type d'archive vous lui transmettez, en inspectant son suffixe. Elle ne le fait pas en utilisant Mime magic, ou quelque chose de lié. Voir "AVERTISSEMENTS" ci

-dessous.

Une fois qu'elle a déterminé le type de fichier, elle sait quelles méthodes d'extraction elle peut utiliser sur l'archive. Elle essaiera d'abord une solution en perl, puis retombera sur un outil en ligne de commandes si cela échoue. Si cela échoue également, elle renverra faux, indiquant qu'elle n'a pas pu extraire l'archive. Voir la section sur "VARIABLES GLOBALES" pour voir

comment mod
ifier cet ordre.

AVERTISSEMEN

TS

Extensions de

fichiers

"Archive::Extract" se fie à l'extension de l'archive pour déterminer de quel type il s'agit, et quelles méthodes d'extraction peuvent donc être utilisées. Si vos archives n'ont aucune des extensions décrites dans la méthode new(), vous devrez spécifier le type explicitement, ou "Archive::Extract" ne pourra pas

extraire l'ar
chive pour vous.

Prise en charge de fichiers très

volumineux

"Archive::Extract" peut utiliser soit des modules perl purs, soit des programmes en ligne de commandes en interne. Certains des modules perl purs (comme "Archive::Tar" et Compress::unLZMA) chargent l'intégralité du contenu de l'archive en mémoire, ce qui peut ne pas être faisable sur votre système. Envisagez de définir la variable globale $Archive::Extract::PREFER_BIN à 1, ce qui privilégiera l'utilisation des programmes en ligne de commandes et ne consommera pas autant de

mémoire.

Voir la section "VARIABLES GLOBALES"

ci-dessous pour
plus de détails.

Prise en charge par Bunzip2 d'extensions

arbitraires.

Les anciennes versions de "/bin/bunzip2" ne prennent pas en charge les extensions de fichiers arbitraires et insistent sur un suffixe ".bz2". Bien que nous fassions de notre mieux pour nous prémunir contre cela, si vous rencontrez une erreur bunzip2, elle peut être liée à ceci. Pour plus de détails, veuillez voir la méthode "have_old_bunzip2". "have_old_bunzip2" method.
