NOM

atmsigd.conf - fichier de configuration du démon de signalisation ATM

SYNOPIS

/etc/atmsigd.conf

DESCRIPTION

atmsigd.conf contient les données de configuration pour atmsigd. atmsigd lit atmsigd.conf après l'analyse des options de ligne de commande, avant de se connecter au réseau ATM.

Les paramètres de configuration sont organisés en groupes fonctionnels. Afin de définir un paramètre, le nom du groupe, le nom du paramètre et la ou les valeurs du paramètre doivent être spécifiés, par exemple :

     sig level debug
diminue le seuil de journalisation pour les messages liés à la signalisation au niveau debug. Les options suivantes sont reconnues :
debug dump chemin
Spécifie le répertoire dans lequel atmsigd écrira les vidages d'état et de trace. Si le traçage n'est pas encore activé, la taille de la trace est automatiquement définie à une valeur par défaut (petite).
debug level niveau
Définit le niveau de débogage par défaut à niveau. niveau peut être l'un des suivants : debug, info, warn, error et fatal. Seuls les messages ayant une priorité égale ou supérieure au niveau de débogage sont affichés. Notez que l'option de ligne de commande -d génère encore plus de sorties (par exemple, des vidages hexadécimaux de tous les paquets passant entre atmsigd et le réseau) que debug level debug.
debug log chemin
Spécifie le fichier dans lequel atmsigd écrit les messages de journalisation. En utilisant le nom de fichier spécial syslog, les messages sont envoyés au journal système à la place. Les messages de journal sont écrits sur la sortie standard si aucun fichier de journal n'est spécifié. L'écriture sur la sortie standard peut également être explicitement demandée en utilisant le nom de fichier spécial stderr.
debug trace [nombre]
Active le traçage et définit éventuellement le nombre d'entrées à conserver dans le tampon de trace. Une valeur par défaut (petite) est utilisée si le nombre est omis.
io level niveau
Définit le niveau de débogage pour les messages liés aux E/S à niveau.
io max_rate taux
Définit le taux à signaler si une application demande le « maximum ». Voir qos(7) pour la syntaxe à utiliser pour exprimer le taux. Le taux maximum par défaut est de 353207 cellules/seconde (OC3). (Notez que la valeur de max_rate ne limite pas les taux qu'une application peut demander explicitement.)
io qos qos
Configure le VC de signalisation pour utiliser le QOS spécifié (voir qos(7) pour la syntaxe). Par défaut, UBR à la vitesse de la liaison est utilisé sur le VC de signalisation.
io vc [itf.]vpi.vci
Utilise le VC spécifié pour les messages de signalisation au lieu du 0.0.5 habituel.
saal level niveau
Définit le niveau de débogage pour les messages liés à SAAL (c'est-à-dire SSCF et SSCOP) à niveau.
sig level niveau
Définit le niveau de débogage pour les messages liés à la signalisation (Q.2931 ou ISP) à niveau.
sig mode mode
Définit le mode de fonctionnement. Les modes suivants sont disponibles : user pour le côté utilisateur, network pour le côté réseau, et switch pour le fonctionnement dans un commutateur. Le comportement par défaut est user.
sig uni30
Utilise la signalisation UNI 3.0. Si elle est spécifiée avec sig uni31, cette option définit la signalisation UNI 3.1 avec quelques extensions de rétrocompatibilité.
sig uni31
Utilise la signalisation UNI 3.1. Cette option peut être combinée avec sig uni30 (voir ci-dessus).
sig uni40
Utilise la signalisation UNI 4.0. Cette option peut être combinée avec sig q.2963.1 (voir ci-dessous).
sig q.2963.1
Active la renégociation du débit de cellules de pointe. Cette option n'est disponible qu'avec la signalisation UNI 4.0.
sig vpci vpci itf itf
Configure un type de routage très simpliste. Tous les appels avec des valeurs VPCI égales ou supérieures à vpci seront routés vers itf, et leurs valeurs VPI seront définies comme le VPCI signalé moins vpci. Plusieurs entrées sig vpci peuvent être utilisées pour supporter un nombre arbitraire d'interfaces. Exemple : avec sig vpci 4 itf 1, un appel signalé pour VPCI/VCI 0.x est routé vers 0.0.x, un appel signalé pour 6.y est routé vers 1.2.y, etc.
policy level niveau
Définit le niveau de débogage pour les messages liés aux décisions de politique à niveau.
policy decision direction address
Prend la decision spécifiée pour les appels provenant de ou vers l'address. decision peut être allow ou reject. direction est soit from soit to. L'address peut être wildcardée en la précédant d'une barre oblique et du nombre de bits significatifs (NSAP) ou de chiffres (E.164). Les règles sont recherchées dans l'ordre où elles apparaissent dans atmsigd.conf jusqu'à la première correspondance. Si aucune règle ne correspond, l'appel est autorisé.
entity [itf.]vpi.vci { options ... }
Active une entité de signalisation sur ce VC spécifique. Plusieurs clauses entity peuvent apparaître dans la même configuration. Lors de l'utilisation de entity, l'option io vc n'est pas disponible. entity est facultativement suivi des options suivantes, entre accolades : vpci (correspond à sig vpci), mode (correspond à sig mode), qos (correspond à vc qos), route, et default. Les deux dernières options déterminent comment les appels sortants sont routés. L'option route est suivie d'une adresse au format utilisé pour les adresses dans policy. Si aucune entrée de route ne correspond au numéro de téléphone de destination d'un appel sortant, l'entrée marquée avec default est sélectionnée.

Lors de la définition de plusieurs paramètres dans le même groupe, le nom du groupe n'a pas besoin d'être répété s'il est suivi des paramètres entre accolades. Exemple :

    debug {
        level warn
        dump /var/tmp
        log syslog
        trace 100
    }

Les sauts de ligne peuvent être insérés dans atmsigd.conf partout où des espaces ou des tabulations sont autorisés. Tout ce qui se trouve entre un `#` et la fin de la ligne est considéré comme un commentaire. Le caractère `#` ne peut pas être échappé.

Si une option est spécifiée dans atmsigd.conf et sur la ligne de commande, la ligne de commande a la priorité.

COMPATIBILITÉ

Certaines options utilisées par les versions précédentes d'atmsigd mais qui ne sont plus documentées dans la page de manuel sont toujours reconnues et prises en charge, mais elles génèrent également un message d'avertissement. Les futures versions d'atmsigd ne reconnaîtront pas ces options.
