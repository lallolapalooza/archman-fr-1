Module Atomic

Références atomiques.

Voir Atomic.examples ci-dessous. Voir le chapitre 'Modèle mémoire : les bits difficiles' du manuel.

Depuis 4.12

type !'a t

Une référence atomique (mutable) vers une valeur de type 'a .

val make : 'a -> 'a t

Crée une référence atomique.

val make_contended : 'a -> 'a t

Crée une référence atomique qui est seule sur une ligne de cache. Elle occupe 4 à 16 fois plus de mémoire qu'une allouée avec make v .

Le but principal est d'éviter le partage de faux et la dégradation des performances qui en résulte. Lorsqu'un CPU effectue une opération atomique, il prend temporairement possession d'une ligne de cache entière contenant la référence atomique. Si plusieurs références atomiques partagent la même ligne de cache, il devient impossible de modifier simultanément ces régions mémoire disjointes, ce qui peut créer un goulot d'étranglement. Ainsi, en règle générale, si une référence atomique connaît des contentions, lui attribuer sa propre ligne de cache peut améliorer les performances.

val get : 'a t -> 'a

Obtient la valeur actuelle de la référence atomique.

val set : 'a t -> 'a -> unit

Définit une nouvelle valeur pour la référence atomique.

val exchange : 'a t -> 'a -> 'a

Définit une nouvelle valeur pour la référence atomique et renvoie la valeur actuelle.

val compare_and_set : 'a t -> 'a -> 'a -> bool

compare_and_set r vu v définit la nouvelle valeur de r à v uniquement si sa valeur actuelle est physiquement égale à vu -- la comparaison et la définition se font atomiquement. Renvoie true si la comparaison a réussi (donc la définition a eu lieu) et false sinon.

val fetch_and_add : int t -> int -> int

fetch_and_add r n incrémente atomiquement la valeur de r de n et renvoie la valeur actuelle (avant l'incrémentation).

val incr : int t -> unit

incr r incrémente atomiquement la valeur de r de 1 .

val decr : int t -> unit

decr r décrémente atomiquement la valeur de r de 1 .

module Loc : sig end

"Emplacements" atomiques, tels que les champs d'enregistrement.

Exemples

Coordination de Threads de Base

Un cas d'utilisation basique est d'avoir des compteurs globaux mis à jour de manière thread-safe, par exemple pour conserver des métriques sur les IO effectuées par le programme. Un autre cas d'utilisation basique est de coordonner la terminaison de threads dans un programme donné, par exemple lorsqu'un thread trouve une réponse, ou lorsque le programme est arrêté par l'utilisateur.

Ici, par exemple, nous allons essayer de trouver un nombre dont le hash satisfait une propriété basique. Pour ce faire, nous allons exécuter plusieurs threads qui essaieront des nombres aléatoires jusqu'à en trouver un qui fonctionne.

Bien entendu, la sortie ci-dessous est un exemple d'exécution et changera à chaque fois que le programme sera exécuté.

    (* utiliser pour la terminaison *)
    let stop_all_threads = Atomic.make false
    (* nombre total de tentatives individuelles pour trouver un nombre *)
    let num_attempts = Atomic.make 0
    (* trouver un nombre tel que [p] soit vrai, en... essayant des nombres aléatoires
       jusqu'à ce qu'un corresponde. *)
    let find_number_where (p:int -> bool) =
      let rand = Random.State.make_self_init() in
      while not (Atomic.get stop_all_threads) do
        let n = Random.State.full_int rand max_int in
        ignore (Atomic.fetch_and_add num_attempts 1 : int);
        if p (Hashtbl.hash n) then (
          Printf.printf "trouvé %d (hash=%d)\n%!" n (Hashtbl.hash n);
          Atomic.set stop_all_threads true; (* signaler à tous les threads de s'arrêter *)
        )
      done;;
    (* exécuter plusieurs domaines pour rechercher un [n] tel que [hash n <= 100] *)
    let () =
      let criterion n = n <= 100 in
      let threads =
        Array.init 8
          (fun _ -> Domain.spawn (fun () -> find_number_where criterion))
      in
      Array.iter Domain.join threads;
      Printf.printf "nombre total de tentatives : %d\n%!"
        (Atomic.get num_attempts) ;;
    - : unit = ()
    trouvé 1651745641680046833 (hash=33)
    nombre total de tentatives : 30230350

Pile de Treiber

Un autre exemple est une pile de Treiber basique (une pile thread-safe) qui peut être partagée en toute sécurité entre les threads.

Notez comment à la fois push et pop sont récursifs, car ils tentent d'échanger la nouvelle pile (avec un élément de plus ou de moins) avec l'ancienne pile. C'est une concurrence optimiste : chaque itération de, par exemple, push stack x récupère l'ancienne pile l , et espère qu'au moment où elle essaiera de remplacer l par x::l , personne d'autre n'a eu le temps de modifier la liste. Si le compare_and_set échoue, cela signifie que nous étions trop optimistes et devons réessayer.

    type 'a stack = 'a list Atomic.t
    let rec push (stack: _ stack) elt : unit =
      let cur = Atomic.get stack in
      let success = Atomic.compare_and_set stack cur (elt :: cur) in
      if not success then
        push stack elt
    let rec pop (stack: _ stack) : _ option =
      let cur = Atomic.get stack in
      match cur with
      | [] -> None
      | x :: tail ->
        let success = Atomic.compare_and_set stack cur tail in
        if success then Some x
        else pop stack
    # let st = Atomic.make []
    # push st 1
    - : unit = ()
    # push st 2
    - : unit = ()
    # pop st
    - : int option = Some 2
    # pop st
    - : int option = Some 1
    # pop st
    - : int option = None
