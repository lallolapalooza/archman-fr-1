NOM

atopacctd - démon de comptabilité des processus

SYNTAXE

atopacctd [-v | répertoire_racine]

DESCRIPTION

Le démon atopacctd active la fonctionnalité de comptabilité des processus dans le noyau et laisse les enregistrements de comptabilité des processus être écrits dans un fichier, appelé fichier source à partir de maintenant. Après l'activation de la comptabilité des processus, le démon atopacctd transfère chaque enregistrement de comptabilité des processus disponible dans le fichier source vers un fichier miroir. Les processus clients (comme les processus atop) liront les fichiers miroirs au lieu du fichier source de comptabilité des processus.
De cette façon, le démon atopacctd opère comme une « couche » entre le fichier de comptabilité des processus écrit par le noyau et les fichiers de comptabilité miroirs lus par les processus atop.

Cette approche présente les avantages suivants :

o
Le démon atopacctd veille à ce que le fichier source soit maintenu à une taille limitée. Dès que sa taille maximale est atteinte, il est tronqué à une taille de zéro à nouveau (cela n'est pas remarqué par les processus atop).
o
Le démon atopacct veille à ce que le fichier miroir soit maintenu à une taille limitée. Dès que le fichier miroir actuel atteint cette taille maximale, le démon atopacctd crée un nouveau fichier miroir (subséquent). Tant que les processus clients ont encore la possibilité de lire les fichiers miroirs précédents, le démon atopacctd continue d'écrire les enregistrements de comptabilité dans le fichier miroir le plus récent (actuel). Pour cette raison, le nom d'un fichier miroir se compose d'un numéro de séquence à 10 chiffres suivi de l'extension '.paf' (fichier de comptabilité des processus). Les anciens fichiers miroirs qui ne sont plus utilisés par les processus clients sont automatiquement supprimés par le collecteur de déchets dans le démon atopacctd.
o
Lorsque aucun processus client n'est actif (ou ne l'est plus), tous les fichiers miroirs seront supprimés et aucun enregistrement ne sera transféré vers un fichier miroir. Dès qu'au moins un client est actif à nouveau, le démon atopacctd continue d'écrire des fichiers miroirs.

Le répertoire /var/run est utilisé comme répertoire racine par défaut. Sous ce répertoire racine, le fichier source pacct_source est créé auquel le noyau écrit les enregistrements de comptabilité des processus.
De plus, le sous-répertoire pacct_shadow.d est créé comme « conteneur » pour les fichiers miroirs. Outre les fichiers miroirs, le fichier current est également maintenu dans ce sous-répertoire, contenant le numéro de séquence du fichier miroir actuel et le nombre maximum d'enregistrements qui seront écrits dans chaque fichier miroir.

Un répertoire racine alternatif peut être spécifié comme argument de ligne de commande. Lorsqu'un répertoire racine alternatif est défini, modifiez également le fichier de configuration /etc/atoprc pour informer les clients atop de cet emplacement alternatif (voir la page de manuel atoprc). Un tel répertoire racine alternatif doit appartenir à root et ne doit pas être accessible en écriture pour le groupe ou les autres (raisons de sécurité).

Notez que le noyau suspend l'écriture des enregistrements de comptabilité des processus lorsque l'espace libre du système de fichiers sur lequel réside le fichier de comptabilité des processus tombe en dessous de 2%. L'écriture reprend lorsque l'espace libre est de 4% ou plus. Ces pourcentages de seuil bas et haut peuvent être configurés via le pseudo-fichier /proc/sys/kernel/acct.
Le démon atopacctd suspend le transfert des enregistrements de comptabilité des processus vers les fichiers miroirs lorsque l'espace libre du système de fichiers sur lequel réside le fichier de comptabilité des processus tombe en dessous de 5%. Le transfert reprend lorsque l'espace libre est de 5% ou plus. Des messages de journal sont générés via syslog lorsque l'écriture dans le fichier miroir actuel est suspendue ou reprise.

L'option -v peut être utilisée pour vérifier la version du démon atopacctd.

FICHIERS

/var/run/pacct_source
Fichier régulier dans lequel le noyau écrit les enregistrements de comptabilité des processus. Ce fichier sera régulièrement tronqué.
/var/run/pacct_shadow.d/current
Fichier régulier contenant le numéro de séquence du fichier miroir actuel et le nombre maximum d'enregistrements par fichier miroir.
/var/run/pacct_shadow.d/N.paf
Fichiers réguliers contenant les enregistrements de comptabilité des processus qui ont été copiés de manière transparente depuis le fichier source (N représente un numéro de séquence à 10 chiffres).
