NOM

atmsigd - démon de signalisation ATM

SYNTAXE

atmsigd [-b] [-c fichier_config] [-d] [-D repertoire_dump] [-l fichier_journal] [-m mode] [-n] [-q qos] [-t longueur_trace] [-u version_uni] [[interface.]vpi.vci [entree sortie]]
atmsigd -V

DESCRIPTION

atmsigd implémente le protocole de signalisation ATM UNI. Les requêtes d'établissement, d'acceptation ou de fermeture de Connexions Virtuelles Temporaires (SVC) sont envoyées depuis le noyau (à l'aide d'un protocole relativement simple) au démon de signalisation, qui effectue ensuite le dialogue avec le réseau.

Notez que atmsigd ne peut pas accepter ou établir de connexions tant que l'adresse ATM locale de l'interface n'est pas configurée par ilmid ou manuellement à l'aide de atmaddr.

La VC de signalisation par défaut (interface 0, VPI 0, VCI 5) peut être remplacée en ligne de commande en spécifiant une adresse de PVC différente.

Lors du remplacement de la VC par défaut, une paire de tubes nommés peut optionnellement être spécifiée pour communiquer avec l'utilisateur de la signalisation. Normalement, le noyau est l'utilisateur de la signalisation et atmsigd ouvre un socket spécial pour communiquer avec lui.

Si atmsigd est arrêté, tous les appels système nécessitant une interaction avec lui retourneront une erreur et régleront errno à EUNATCH.

OPTIONS

-b
Exécuter en arrière-plan (c'est-à-dire dans un processus enfant forké) après initialisation.
-c fichier_config
Utiliser le fichier de configuration spécifié au lieu de /etc/atmsigd.conf. Si une option est spécifiée dans le fichier de configuration et sur la ligne de commande, la ligne de commande a la priorité.
-d
Active (beaucoup de) sortie de débogage. Par défaut, atmsigd est relativement silencieux.
-D repertoire_dump
Spécifie le répertoire dans lequel atmsigd écrira les dumps d'état et de trace. Si -D n'est pas spécifié, les dumps sont écrits dans /var/tmp.
-l fichier_journal
Écrire les messages de diagnostic dans le fichier spécifié. Le nom spécial syslog est utilisé pour envoyer les diagnostics au syslog du système, stderr est utilisé pour envoyer les diagnostics sur la sortie d'erreur standard. Si -l est absent, le réglage dans atmsigd.conf est utilisé. Si atmsigd ne spécifie pas de destination non plus, les messages sont écrits sur la sortie d'erreur standard.
-m mode
Définit le mode de fonctionnement. Les modes suivants sont disponibles : user pour le côté utilisateur (par défaut), network pour le côté réseau (utile si vous avez deux PC mais pas de switch), et switch pour le fonctionnement avec un relais de signalisation dans un switch.
-n
Affiche les adresses uniquement en format numérique, c'est-à-dire qu'aucune traduction d'adresse en nom n'est tentée.
-q qos
Configure la VC de signalisation pour utiliser la qualité de service spécifiée (voir qos(7) pour la syntaxe). Par défaut, UBR à la vitesse de liaison est utilisé sur la VC de signalisation.
-t longueur_trace
Définit le nombre d'entrées qui doivent être conservées dans le tampon de trace. -t 0 désactive le traçage. Si -t n'est pas spécifié, atmsigd utilise une valeur par défaut de 20 entrées de trace.
-u version_uni
Définit le mode de signalisation. Les modes suivants sont supportés : uni30 pour UNI 3.0, uni31 pour UNI 3.1, uni31+uni30 pour UNI 3.1 avec compatibilité 3.0, uni40 pour UNI 4.0, et uni40+q.2963.1 pour UNI 4.0 avec renégociation du débit de cellules maximal Q.2963.1.
-V
Affiche le numéro de version de atmsigd sur la sortie standard et quitte.

FICHIERS

/etc/atmsigd.conf
fichier de configuration par défaut
/var/tmp/atmsigd.pid.status.version
emplacement par défaut des dumps d'état
/var/tmp/atmsigd.pid.trace.version
emplacement par défaut des dumps de trace de signalisation

DÉBOGAGE

Lors de la réception d'un signal SIGUSR1, atmsigd dump la liste de tous les descripteurs de sockets internes. Avec SIGUSR2, il dump le contenu du tampon de trace. Si un répertoire de dumps a été défini, les dumps sont écrits dans des fichiers nommés atmsigd.pid.status.nombre et atmsigd.pid.trace.nombre, respectivement, avec nombre commençant à zéro et étant incrémenté pour chaque dump. Si aucun répertoire de dumps n'est défini, les dumps sont écrits sur la sortie d'erreur standard.

Des dumps sont également générés chaque fois que atmsigd détecte une erreur fatale et se termine. Aucune tentative n'est faite pour intercepter des signaux comme SIGSEGV.

BOGUES

La génération de traces est un processus relativement lent qui peut déjà prendre plusieurs secondes pour seulement 100 entrées de trace. Pour générer un dump de trace, atmsigd fork donc un processus enfant qui s'exécute en parallèle du démon de signalisation.
