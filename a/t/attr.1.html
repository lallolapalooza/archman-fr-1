ATTR(1) API de compatibilité XFS ATTR(1)

NOM

attr - attributs étendus sur les objets du système de fichiers XFS

SYNTAXE

attr [ -LRSq ] -s nom_attribut [ -V valeur_attribut ] 
chemin_fichier

attr [ -LRSq ] -g nom_attribut chemin_fichier

attr [ -LRSq ] -r nom_attribut chemin_fichier

attr [ -LRSq ] -l chemin_fichier

APERÇU

Les attributs étendus implémentent la capacité pour un utilisateur de joindre des paires nom:valeur à des objets au sein du système de fichiers XFS.

Ce document décrit la commande attr, qui est largement compatible avec la commande du même nom d'IRIX. Elle s'adresse donc spécifiquement aux utilisateurs du système de fichiers XFS - pour la manipulation d'attributs étendus indépendants du système de fichiers, consultez la documentation de getfattr(1) et setfattr(1).

Les attributs étendus peuvent être utilisés pour stocker des méta-informations sur le fichier. Par exemple, « character-set=kanji » pourrait indiquer à un navigateur de documents d'utiliser le jeu de caractères Kanji lors de l'affichage de ce document et « thumbnail=... » pourrait fournir un aperçu en résolution réduite d'une image graphique haute résolution.

Dans le système de fichiers XFS, les noms peuvent avoir jusqu'à 256 octets de longueur, terminés par le premier octet 0. L'intention est qu'ils soient des noms d'attributs imprimables en ASCII (ou dans un autre jeu de caractères). Les valeurs peuvent contenir jusqu'à 64 Ko de données binaires arbitraires.

Les attributs peuvent être attachés à tous les types d'inodes XFS : fichiers réguliers, répertoires, liens symboliques, nœuds de périphériques, etc.

XFS utilise 2 espaces d'adressage d'attributs disjoints associés à chaque objet du système de fichiers. Ce sont les espaces d'adressage root et user. L'espace d'adressage root n'est accessible qu'au superutilisateur, et uniquement en spécifiant un argument drapeau à l'appel de fonction. Les autres utilisateurs ne verront pas et ne pourront pas modifier les attributs dans l'espace d'adressage root. L'espace d'adressage user est protégé par le mécanisme de permissions de fichiers normal, de sorte que le propriétaire du fichier puisse décider qui est capable de voir et/ou de modifier la valeur des attributs sur un fichier particulier.

DESCRIPTION

L'utilitaire attr permet la manipulation des attributs étendus associés aux objets du système de fichiers depuis l'intérieur des scripts shell.

Il existe quatre opérations principales que attr peut effectuer :

GET
L'option -g nom_attribut indique à attr de rechercher l'objet nommé et d'imprimer (vers stdout) la valeur associée à ce nom d'attribut. Avec le drapeau -q, stdout sera exactement et uniquement la valeur de l'attribut, appropriée pour un stockage direct dans un fichier ou un traitement via une commande passée en pipeline.
LIST
L'option -l indique à attr de lister les noms de tous les attributs associés à l'objet, et le nombre d'octets dans la valeur de chacun de ces attributs. Avec le drapeau -q, stdout sera une simple liste des noms d'attributs, un par ligne, appropriée pour l'entrée dans un script.
SUPPRIMER
L'option -r nom_attribut indique à attr de supprimer un attribut avec le nom donné de l'objet s'il existe. Il n'y a pas de sortie en cas de succès.
DEFINIR/CREER
L'option -s nom_attribut indique à attr de définir l'attribut nommé de l'objet avec la valeur lue depuis stdin. Si un attribut de ce nom existe déjà, sa valeur sera remplacée par celle-ci. Si un attribut de ce nom n'existe pas encore, un sera créé avec cette valeur. Avec le drapeau -V valeur_attribut, l'attribut sera défini avec la valeur valeur_attribut et stdin ne sera pas lu. Avec le drapeau -q, stdout ne sera pas utilisé. Sans le drapeau -q, un message indiquant le nom de l'attribut et la valeur entière sera imprimé.

Lorsque l'option -L est donnée et que l'objet nommé est un lien symbolique, opérer sur les attributs de l'objet référencé par le lien symbolique. Sans cette option, opérer sur les attributs du lien symbolique lui-même.

Lorsque l'option -R est donnée et que le processus a les privilèges appropriés, opérer dans l'espace de noms d'attributs root plutôt que dans l'espace de noms d'attributs USER.

L'option -S est similaire, sauf qu'elle spécifie l'utilisation de l'espace de noms d'attributs security.

Lorsque l'option -q est donnée, attr essaiera de rester silencieux. Il affichera des messages d'erreur (sur stderr) mais n'affichera pas de messages d'état (sur stdout).

NOTES

Les programmes standards d'échange/archivage de fichiers tar(1) et cpio(1) n'archiveront ni ne restaureront les attributs étendus, tandis que le programme xfsdump(8) le fera.

AVERTISSEMENTS

L'option list présente dans la version IRIX de cette commande n'est pas supportée. getfattr fournit un mécanisme pour récupérer tous les noms d'attributs.
