attr_list(3)

Paquet: attr

Licences: LGPL

ATTR_LIST(3) API de compatibilité XFS ATTR_LIST(3)

NOM

attr_list, attr_listf - lister les noms des attributs utilisateur d'un objet du système de fichiers

SYNTAXE C

#include <attr/attributes.h>

int attr_list (const char ∗path, char ∗buffer, 
               const int buffersize, int flags,
               attrlist_cursor_t ∗cursor);
int attr_listf (int fd, char ∗buffer, 
                const int buffersize, int flags,
                attrlist_cursor_t ∗cursor);

DESCRIPTION

Les fonctions attr_list et attr_listf fournissent un moyen de lister les attributs existants d'un objet du système de fichiers.

Path pointe vers un nom de chemin pour un objet du système de fichiers, et fd fait référence au descripteur de fichier associé à un fichier. Le buffer sera rempli avec une structure décrivant au moins une partie des attributs associés à l'objet du système de fichiers donné. Buffer sera écrasé avec une structure attrlist_t contenant une liste des attributs associés à cet objet du système de fichiers, jusqu'à un maximum de buffersize octets. Le buffer doit être suffisamment grand pour contenir les structures de données appropriées plus au moins un nom d'attribut de taille maximale, mais ne peut pas dépasser (actuellement 64 Ko) octets de longueur.

Le contenu d'une structure attrlist_t inclut les membres suivants :

int32_t al_count; /∗ nombre d'entrées dans attrlist ∗/
int32_t al_more; /∗ V/F: plus d'attributs (refaire l'appel système) ∗/
int32_t al_offset[1]; /∗ décalages en octets des attributs [taille variable] ∗/

Le champ al_count indique le nombre d'attributs représentés dans ce tampon, ce qui correspond également au nombre d'éléments dans le tableau al_offset. Le champ al_more sera non nul s'il faut un autre appel attr_list pour obtenir plus d'attributs. Le tableau al_offset contient le décalage en octets dans le buffer de la structure décrivant chacun des attributs, une structure attrlist_ent_t. La macro ATTR_ENTRY(buffer, index) aidera au décodage de la liste. Elle prend un pointeur vers le buffer et un index dans le tableau al_offset et retourne un pointeur vers la structure attrlist_ent_t correspondante.

Le contenu d'une structure attrlist_ent_t inclut les membres suivants :

uint32_t a_valuelen; /∗ nombre d'octets dans la valeur de l'attribut ∗/
char a_name[]; /∗ nom de l'attribut (terminé par NULL) ∗/

Le champ a_valuelen indique la taille en octets de la valeur associée à l'attribut dont le nom est stocké dans le champ a_name. Le nom est une chaîne terminée par NULL.

Notez que la valeur de l'attribut ne peut pas être obtenue via cette interface, l'appel attr_get doit être utilisé pour obtenir la valeur. L'interface attr_list indique au processus appelant la taille du tampon nécessaire pour obtenir la valeur de l'attribut.

Le paramètre flags peut contenir les symboles suivants combinés par un OU bit à bit :

ATTR_ROOT
Lister les attributs qui se trouvent dans l'espace d'adressage root, pas dans l'espace d'adressage user. (utilisation limitée au super-utilisateur uniquement)
ATTR_DONTFOLLOW
Ne pas suivre les liens symboliques lors de la résolution d'un path lors d'un appel de fonction attr_list. Le comportement par défaut est de suivre les liens symboliques.

Le paramètre cursor est un pointeur vers une structure de données opaque que le noyau utilise pour suivre la position du processus appelant dans la liste des attributs. Les seules opérations valides sur un cursor sont de le passer à un appel de fonction attr_list ou de le mettre à zéro. Il doit être mis à zéro avant le premier appel attr_list. Notez que les applications multi-threadées peuvent conserver plus d'un cursor afin de servir plusieurs contextes, c'est-à-dire que l'appel attr_list est "thread-safe".

attr_list échouera si l'une des conditions suivantes est vraie :

[ENOENT]
Le fichier nommé n'existe pas.
[EPERM]
L'ID utilisateur effectif ne correspond pas au propriétaire du fichier et l'ID utilisateur effectif n'est pas super-utilisateur.
[ENOTDIR]
Un composant du préfixe du chemin n'est pas un répertoire.
[EACCES]
L'autorisation de recherche est refusée sur un composant du préfixe du chemin.
[EINVAL]
Un bit a été défini dans le paramètre flag qui n'est pas défini pour cet appel système, ou le tampon était trop petit ou trop grand.
[EFAULT]
Soit Path soit buffer pointe en dehors de l'espace d'adressage alloué au processus, soit buffer ou bufsize ne sont pas alignés sur 32 bits.
[ELOOP]
Une recherche de nom de chemin a impliqué trop de liens symboliques.
[ENAMETOOLONG]
La longueur de path dépasse {MAXPATHLEN}, ou un composant de nom de chemin est plus long que {MAXNAMELEN}.
[ENOATTR]
attribute n'existe pas pour ce fichier.

attr_listf échouera si :

[EINVAL]
Un bit a été défini dans le paramètre flag qui n'est pas défini pour cet appel système, ou fd fait référence à une socket, et non à un fichier, ou le tampon était trop petit ou trop grand.
[EFAULT]
Soit Path soit buffer pointe en dehors de l'espace d'adressage alloué au processus, soit buffer ou bufsize ne sont pas alignés sur 32 bits.
[EBADF]
Fd ne fait pas référence à un descripteur valide.

DIAGNOSTICS

En cas de succès, la valeur 0 est retournée. Sinon, une valeur de -1 est retournée et errno est définie pour indiquer l'erreur.
