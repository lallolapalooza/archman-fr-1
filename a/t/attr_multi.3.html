SYNOPSIS 
#include <attr/attributes.h>

int attr_multi (const char *path, attr_multiop_t *oplist,
                int count, int flags)
;

;

DESCRIPTIO

N

Les fonctions attr_multi et attr_multif fournissent un moyen d'opérer sur plusieurs attributs d'un objet de système de fichiers à la

fois.

path pointe vers un nom de chemin pour un objet de système de fichiers, et fd fait référence au descripteur de fichier associé à un fichier. Le oplist est un tableau de structures attr_multiop_t. Chaque élément de ce tableau décrit une seule opération sur un attribut et fournit toutes les informations nécessaires pour effectuer cette opération et vérifier son succès ou son échec. count indique combien d'éléments se trouvent dans le tableau op

list.

Le contenu d'une structure attr_multiop_t comprend les membres suivants

: 
int am_opcode; /* quelle opération effectuer (voir ci-dessous) */
int am_error; /* [arg de sortie] résultat de cette sous-op (un errno) */

ts) */ int am_length; /* [arg entrée/sortie] longueur de la valeur */ int am_flags; /* indicateurs (OU bit à bit des #defines ci-dessous) */

Le champ am_opcode définit comment les champs restants doivent être interprétés et peut prendre l'une des valeurs suivantes

: 
ATTR_OP_GET /* retourner la valeur de l'attribut indiqué *
/ ATTR_OP_SET /* définir/créer la paire attribut/valeur ind

Le champ am_error contiendra le code de résultat d'erreur approprié si cette sous-opération échoue. Les codes de résultat pour une sous-opération donnée sont un sous-ensemble des codes de résultat possibles à partir de l'appel de fonction correspondant à attribut unique. Par exemple, le code de résultat possible à partir d'une sous-opération ATTR_OP_GET est un sous-ensemble de ceux qui peuvent être retournés par un appel de fonction attr_get

.

Le champ am_attrname est un pointeur vers une chaîne terminée par NULL donnant le nom de l'attribut sur lequel la sous-opération doit

opérer.

Les champs am_attrvalue, am_length et am_flags sont utilisés pour stocker la valeur de l'attribut nommé et certains indicateurs de contrôle pour cette sous-opération, respectivement. Leur utilisation varie en fonction de la valeur du champ am_op

code.
ATTR_OP_G
ET
Le champ am_attrvalue est un pointeur vers un tampon vide qui sera écrasé avec la valeur de l'attribut nommé. Le champ am_length est initialement la taille totale du tampon mémoire que le champ am_attrvalue pointe. Après l'opération, le champ am_length contient la taille réelle de la valeur de l'attribut. Le champ am_flags peut être défini à l'indicateur ATTR_ROOT. Si le processus a les privilèges appropriés, l'espace de noms ROOT sera recherché pour l'attribut nommé, sinon l'espace de noms USER sera
recherché.
ATTR_OP_S
ET
Les champs am_attrvalue et am_length contiennent la nouvelle valeur pour le nom d'attribut donné et sa longueur. L'indicateur ATTR_ROOT peut être défini dans le champ am_flags. Si le processus a les privilèges appropriés, l'espace de noms ROOT sera recherché pour l'attribut nommé, sinon l'espace de noms USER sera recherché. Les indicateurs ATTR_CREATE et ATTR_REPLACE peuvent également être définis dans le champ am_flags (mais pas simultanément). Si l'indicateur ATTR_CREATE est défini, la sous-opération définira le champ am_error à EEXIST si l'attribut nommé existe déjà. Si l'indicateur ATTR_REPLACE est défini, la sous-opération définira le champ am_error à ENOATTR si l'attribut nommé n'existe pas déjà. Si aucun de ces deux indicateurs n'est défini et que l'attribut n'existe pas, l'attribut sera créé avec la valeur donnée. Si aucun de ces deux indicateurs n'est défini et que l'attribut existe déjà, la valeur sera remplacée par la valeur
donnée.
ATTR_OP_REMO
VE
Les champs am_attrvalue et am_length ne sont pas utilisés et sont ignorés. Le champ am_flags peut être défini à l'indicateur ATTR_ROOT. Si le processus a les privilèges appropriés, l'espace de noms ROOT se
ra recherché pour l'attribut nommé, sinon
l'espace de noms USER sera recherché.

L'argument flags de l'appel attr_multi est utilisé pour contrôler le suivi des liens symboliques dans l'argument path. Par défaut, les liens symboliques sont suivis, flags doit être défini à ATTR_DONTFOLLOW pour ne pas suivre les liens

symboliques.

DIAGNOSTIC

S

En cas de succès, zéro est retourné. En cas d'erreur, -1 est retourné, et errno est défini de manière appropriée. Notez que les opérations individuelles listées dans le tableau oplist ont chacune leurs propres champs de retour d'erreur. La variable errno ne fait que consigner le résultat de l'appel attr_multi lui-même, pas le résultat des

sous-opérations
.
