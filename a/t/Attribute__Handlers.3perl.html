DESCRIPTIO

N

Ce module, lorsqu'il est hérité par un paquet, permet à la classe de ce paquet de définir des sous-routines de gestion d'attributs pour des attributs spécifiques. Les variables et sous-routines définies ultérieurement dans ce paquet, ou dans des paquets dérivés de celui-ci, peuvent recevoir des attributs portant les mêmes noms que les sous-routines de gestion d'attributs, qui seront alors appelées dans l'une des phases de compilation (c'est-à-dire dans un "BEGIN", "CHECK", "INIT" ou "END"). (Les blocs "UNITCHECK" ne correspondent pas à une phase de compilation globale, ils ne peuvent donc pas être spécifiés ici.

)

Pour créer un gestionnaire, définissez-le comme une sous-routine portant le même nom que l'attribut souhaité, et déclarez la sous-routine elle-même avec l'attribut ":ATTR". Par exemple

: 
package LoudDecl;
use Attribute::Handlers;
sub Loud :ATTR {
    my ($package, $symbol, $referent, $attr, $data, $phase,
        $filename, $linenum) = @_;
    print STDERR
        ref($referent), " ",
        *{$symbol}{NAME}, " ",
        "($referent) ", "was just declared ",
        "and ascribed the ${attr} attribute ",
        "with data ($data)\n",
        "in phase $phase\n",
        "in file $filename at line $linenum\n";
}

Cela crée un gestionnaire pour l'attribut ":Loud" dans la classe LoudDecl. Par la suite, toute sous-routine déclarée avec un ":Loud" attribut dans la classe LoudDecl

: 
package LoudDecl;
sub foo: Loud {...
}

provoque l'appel du gestionnaire ci-dessus, auquel on transmet

:
[0
]
le nom du paquet dans lequel il a été déclaré
;
[1
]
une référence à l'entrée de la table des symboles (typeglob) contenant la sous-routine
;
[2
]
une référence à la sous-routine
;
[3
]
le nom de l'attribut
;
[4
]
toute donnée associée à cet attribut
;
[5
]
le nom de la phase dans laquelle le gestionnaire est appelé
;
[6
]
le nom du fichier dans lequel le gestionnaire est appelé
;
[7
]
le numéro de
ligne dans
ce fichier.

De même, déclarer des variables avec l'attribut ":Loud" à l'intérieur du paquet

: 
package LoudDecl;
my $foo :Loud;
my @foo :Loud;
my %foo :
Loud;

provoquera l'appel du gestionnaire avec une liste d'arguments similaire (sauf, bien sûr, que $_[2] sera une référence à la variable)

.

L'argument du nom de paquet sera généralement le nom de la classe dans laquelle la sous-routine a été déclarée, mais il peut aussi être le nom d'une classe dérivée (puisque les gestionnaires sont hérités)

.

Si une variable lexicale reçoit un attribut, il n'y a pas de table des symboles à laquelle elle appartient, l'argument de la table des symboles ($_[1]) est donc défini à la chaîne 'LEXICAL' dans ce cas. De même, attribuer un attribut à une sous-routine anonyme donne un argument de table des symboles de 'ANON'

.

L'argument de données transmet la valeur (le cas échéant) associée à l'attribut. Par exemple, si &foo avait été déclarée

: 
sub foo :Loud("turn it up to 11, man!") {...
}

alors une référence à un tableau contenant la chaîne "turn it up to 11, man!" serait transmise en dernier

argument.

Attribute::Handlers s'efforce de convertir l'argument de données ($_[4]) en une forme utilisable avant de le transmettre au gestionnaire (mais voir « Gestionnaires d'attributs non interprétatifs »). Si ces efforts aboutissent, les données interprétées sont transmises dans une référence de tableau ; s'ils échouent, les données brutes sont transmises sous forme de chaîne. Par exemple, toutes celles-ci

: 
sub foo :Loud(till=>ears=>are=>bleeding) {...}
sub foo :Loud(qw/till ears are bleeding/) {...}
sub foo :Loud(qw/till, ears, are, bleeding/) {...}
sub foo :Loud(till,ears,are,bleeding) {...
}

provoquent le passage de "['till','ears','are','bleeding']" comme argument de données du gestionnaire. Alors que

: 
sub foo :Loud(['till','ears','are','bleeding']) {...
}

provoque le passage de "[ ['till','ears','are','bleeding'] ]" ; la référence de tableau spécifiée dans les données étant transmise à l'intérieur de la référence de tableau standard indiquant une interprétation

réussie.

Cependant, si les données ne peuvent pas être analysées en Perl valide, elles sont transmises sous forme de chaîne non interprétée. Par exemple

: 
sub foo :Loud(my,ears,are,bleeding) {...}
sub foo :Loud(qw/my ears are bleeding) {...
}

provoquent le passage des chaînes 'my,ears,are,bleeding' et 'qw/my ears are bleeding' respectivement comme argument de

données.

Si aucune valeur n'est associée à l'attribut, "undef" est

transmis.

Lexicales

typées

Quel que soit le paquet dans lequel elle est déclarée, si une variable lexicale reçoit un attribut, le gestionnaire qui est appelé est celui appartenant au paquet auquel elle est typée. Par exemple, les déclarations suivantes

: 
package OtherClass;
my LoudDecl $loudobj : Loud;
my LoudDecl @loudobjs : Loud;
my LoudDecl %loudobjex :
Loud;

provoquent l'appel du gestionnaire LoudDecl::Loud (même si OtherClass définit aussi un gestionnaire pour les attributs ":Lo

ud"
).

Gestionnaires d'attributs spécifiques au

type

Si un gestionnaire d'attributs est déclaré et que le spécificateur ":ATTR" reçoit le nom d'un type intégré ("SCALAR", "ARRAY", "HASH" ou "CODE"), le gestionnaire n'est appliqué qu'aux déclarations de ce type. Par exemple, la définition suivante

: 
package LoudDecl;
sub RealLoud :ATTR(SCALAR) { print "Yeeeeow!"
}

crée un gestionnaire d'attributs qui ne s'applique qu'aux scalaires

: 
package Painful;
use base LoudDecl;
my $metal : RealLoud;           # appelle &LoudDecl::RealLoud
my @metal : RealLoud;           # erreur : attribut inconnu
my %metal : RealLoud;           # erreur : attribut inconnu
sub metal : RealLoud {...}      # erreur : attribut
inconnu

Vous pouvez, bien sûr, déclarer des gestionnaires séparés pour ces types également (mais vous devrez spécifier "no warnings 'redefine'" pour le faire sans avertissement)

: 
package LoudDecl;
use Attribute::Handlers;
no warnings 'redefine';
sub RealLoud :ATTR(SCALAR) { print "Yeeeeow!" }

sub RealLoud :ATTR(ARRAY) { print "Urrrrrrrrrr!" }
sub RealLoud :ATTR(HASH) { print "Arrrrrgggghhhhhh!" }
sub RealLoud :ATTR(CODE) { croak "Real loud sub torpedoed"
}

Vous pouvez aussi indiquer explicitement qu'un seul gestionnaire est destiné à être utilisé pour tous les types de référents comme suit

: 
package LoudDecl;
use Attribute::Handlers;
sub SeriousLoud :ATTR(ANY) { warn "Hearing loss imminent"
}

(C'est-à-dire ATTR(ANY) est un synonyme pour ":AT

TR"
).

Gestionnaires d'attributs non-interprétatif

s

Parfois, les efforts soutenus qu'Attribute::Handlers déploie pour convertir l'argument de données ($_[4]) en une forme utilisable avant de le passer au gestionnaire se mettent en

travers.

Vous pouvez désactiver cette envie d'aider en déclarant un gestionnaire d'attributs avec le mot-clé "RAWDATA". Par exemple

: 
sub Raw          : ATTR(RAWDATA) {...}
sub Nekkid       : ATTR(SCALAR,RAWDATA) {...}
sub Au::Naturale : ATTR(RAWDATA,ANY) {...
}

Le gestionnaire ne fait alors absolument aucune tentative d'interpréter les données qu'il reçoit et les passe simplement sous forme de chaîne

: 
my $power : Raw(1..100
); # le gestio
nnaire reçoit "1..100"

Gestionnaires d'attributs spécifiques à une

phase

Par défaut, les gestionnaires d'attributs sont appelés à la fin de la phase de compilation (dans un bloc "CHECK"). Cela semble optimal dans la plupart des cas car la plupart des choses qui peuvent être définies le sont à ce stade, mais rien n'a encore été

exécuté.

Cependant, il est possible de configurer des gestionnaires d'attributs qui sont appelés à d'autres moments de la compilation ou de l'exécution du programme, en indiquant explicitement la phase (ou les phases) dans lesquelles vous souhaitez que le gestionnaire d'attributs soit appelé. Par exemple

: 
sub Early    :ATTR(SCALAR,BEGIN) {...}
sub Normal   :ATTR(SCALAR,CHECK) {...}
sub Late     :ATTR(SCALAR,INIT) {...}
sub Final    :ATTR(SCALAR,END) {...}
sub Bookends :ATTR(SCALAR,BEGIN,END) {...
}

Comme l'indique le dernier exemple, un gestionnaire peut être configuré pour être (re)appelé dans deux phases ou plus. Le nom de la phase est passé comme dernier argument du

gestionnaire.

Notez que les gestionnaires d'attributs planifiés pour la phase "BEGIN" sont traités dès que l'attribut est détecté (c'est-à-dire avant l'exécution de tout bloc "BEGIN" défini u

ltérieu
rement).

Les attributs comme interfaces

"tie"

Les attributs constituent une interface excellente et intuitive à travers laquelle lier des variables. Par exemple

: 
use Attribute::Handlers;
use Tie::Cycle;
sub UNIVERSAL::Cycle : ATTR(SCALAR) {
    my ($package, $symbol, $referent, $attr, $data, $phase) = @_;
    $data = [ $data ] unless ref $data eq 'ARRAY';
    tie $$referent, 'Tie::Cycle', $data;
}
# et par la suite...
package main;
my $next : Cycle('A'..'Z');     # $next est maintenant une variable liée
while (<>) {
    print $next;
}

Notez que, parce que l'attribut "Cycle" reçoit ses arguments dans la variable $data , si l'attribut reçoit une liste d'arguments, $data consistera en une seule référence de tableau ; sinon, il consistera directement en l'argument unique. Puisque Tie::Cycle exige que ses valeurs cycliques soient passées comme une référence de tableau, cela signifie que nous devons envelopper les arguments qui ne sont pas des références de tableau dans un constructeur de tableau

: 
$data = [ $data ] unless ref $data eq
'ARRAY';

Typiquement, cependant, les choses sont à l'inverse : la classe liable attend ses arguments sous forme de liste aplatie, de sorte que l'attribut ressemble à

: 
sub UNIVERSAL::Cycle : ATTR(SCALAR) {
    my ($package, $symbol, $referent, $attr, $data, $phase) = @_;
    my @data = ref $data eq 'ARRAY' ? @$data : $data;
    tie $$referent, 'Tie::Whatever', @data;
}

Ce motif logiciel est si largement applicable qu' Attribute::Handlers fournit un moyen de l'automatiser : en spécifiant 'autotie' dans l'instruction "use Attribute::Handlers". Ainsi, l'exemple cyclique pourrait aussi s'écrire

: 
use Attribute::Handlers autotie => { Cycle => 'Tie::Cycle' };
# et par la suite...
package main;
my $next : Cycle(['A'..'Z']);     # $next est maintenant une variable liée
while (<>) {
    print $next;
}

Notez que nous devons maintenant passer les valeurs cycliques comme une référence de tableau, puisque le mécanisme "autotie" passe à "tie" une liste d'arguments sous forme de liste (comme dans l'exemple Tie::Whatever), et non sous forme de référence de tableau (comme dans l'exemple Tie::Cycle original au début de cette section)

.

L'argument après 'autotie' est une référence vers un hash dont chaque clé est le nom d'un attribut à créer, et chaque valeur est la classe à laquelle les variables portant cet attribut doivent être

liées.

Notez qu'il n'est plus nécessaire d'importer le module Tie::Cycle -- Attribute::Handlers s'en charge automatiquement. Vous pouvez même passer des arguments à la sous-routine "import" du module, en les ajoutant au nom de la classe. Par exemple

: 
use Attribute::Handlers
     autotie => { Dir => 'Tie::Dir qw(DIR_UNLINK)' }
;

Si le nom de l'attribut n'est pas qualifié, l'attribut est installé dans le paquet courant. Sinon, il est installé dans le paquet du qualificateur

: 
package Here;
use Attribute::Handlers autotie => {
     Other::Good => Tie::SecureHash, # attribut tie installé dans Other::
             Bad => Tie::Taxes,      # attribut tie installé dans Here::
 UNIVERSAL::Ugly => Software::Patent # attribut tie installé partout
}
;

Les autoties sont le plus souvent utilisées dans le module auquel elles se lient réellement, et doivent exporter leurs attributs à tout module qui les appelle. Pour faciliter cela, Attribute::Handlers reconnaît une "pseudo-classe" spéciale -- "__CALLER__", qui peut être spécifiée comme qualificateur d'un attribut

: 
package Tie::Me::Kangaroo::Down::Sport;
use Attribute::Handlers autotie =>
     { '__CALLER__::Roo' => __PACKAGE__ }
;

Cela fait qu'Attribute::Handlers définit l'attribut "Roo" dans le paquet qui importe le module Tie::Me::Kangaroo::Down::

Sport.

Notez qu'il est important de mettre l'identifiant __CALLER__::Roo entre guillemets car un bogue dans perl 5.8 refusera de l'analyser et provoquera une erreur

inconnue.

Passer l'objet lié à "tie

"

Parfois, il est important de passer une référence à l'objet qui est lié à TIESCALAR, TIEHASH, etc. qui le

lie.

Le mécanisme "autotie" prend également en charge cela. Le code suivant

: 
use Attribute::Handlers autotieref => { Selfish => Tie::Selfish };
my $var : Selfish(@args)
;

a le même effet que

: 
tie my $var, 'Tie::Selfish',
@args;

Mais quand "autotieref" est utilisé au lieu de "autoti

e" : 
use Attribute::Handlers autotieref => { Selfish => Tie::Selfish };
my $var : Selfish(@args)
;

l'effet est de passer à l'appel "tie" une référence supplémentaire vers la variable qui est liée

: 
tie my $va
r, 'Tie::Se
lfish', \$v
ar, @args;

Installer des gestionnaires dans UNIVERSAL les rend...err..universels. Par exemple

UTILITAIRES

Ce module propose une seule fonction utilitaire, findsym

().
finds
ym 
my $symbol = Attribute::Handlers::findsym($package, $referent)
;

La fonction cherche dans la table des symboles de $package le typeglob pour $referent, qui est une référence à une variable ou à une sous-routine (SCALAR, ARRAY, HASH ou CODE). Si elle trouve le typeglob, elle le renvoie. Sinon, elle renvoie undef. Notez que "findsym" met en mémoire les typeglobs qu'elle a précédem

ment trouvés avec succès, de sort
e que les appels ultérieurs avec
les mêmes arguments devr
aient être beaucoup plus rapides.

DIAGNOSTIC

S
"Bad attribute type: ATTR(%s)
"
Un gestionnaire d'attribut a été spécifié avec une :ATTR(ref_type), mais le type de référent qu'il était défini pour gérer n'en faisait pas partie des cinq autorisés : "SCALAR", "ARRAY", "HASH", "CODE" ou "ANY
".
"Attribute handler %s doesn't handle %s
attributes"
Un gestionnaire pour les attributs du nom spécifié a été défini, mais pas pour le type de déclaration spécifié. On rencontre généralement ce cas lorsqu'on essaie d'appliquer un gestionnaire d'attribut "VAR" à une sous-routine, ou un gestionnaire d'attribut "SCALAR" à un autre type de
variable.
"Declaration of %s attribute in package %s may clash with future reserved
word"
Un gestionnaire pour un attribut dont le nom est entièrement en minuscules a été déclaré. Un attribut dont le nom est entièrement en minuscules pourrait un jour avoir une signification pour Perl lui-même, même si la plupart n'en ont pas encore. Utilisez plutôt un nom d'attribut en casse
mixte.
"Can't have two ATTR specifiers on one
subroutine"
Vous ne pouvez tout simplement pas, d'accord ? À la place, mettez toutes les spécifications ensemble, séparées par des virgules, dans une seule ATTR(spécification)
.
"Can't autotie a
%s"
Vous ne pouvez déclarer des autoties que pour les types "SCALAR", "ARRAY" et "HASH". Ce sont les seules choses (à part les typeglobs -- qui ne sont pas déclarables) que Perl peut
lier.
"Internal error: %s symbol went
missing"
Quelque chose de pourri se passe dans l'état du programme. Une sous-routine attribuée a cessé d'exister entre le moment où elle a été déclarée et le moment où son(ses) gestionnaire(s) d'attribut auraient dû être
appelés.
"Won't be able to apply END
handler"
Vous avez défini un gestionnaire END pour un att
ribut qui est appliqué à une variable lexi
cale. Comme la variable peut ne pas être dispon
ible pendant END, cela ne se produira pas.
