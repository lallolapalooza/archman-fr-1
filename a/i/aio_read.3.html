aio_read(3) Manuel des fonctions de bibliothèque aio_read(3)

NOM

aio_read - lecture asynchrone

BIBLIOTHÈQUE

Bibliothèque temps réel (librt, -lrt)

SYNTAXE

#include <aio.h>
int aio_read(struct aiocb *aiocbp);

DESCRIPTION

La fonction aio_read() met en file d'attente la requête d'E/S décrite par le tampon pointé par aiocbp. Cette fonction est l'analogue asynchrone de read(2). Les arguments de l'appel


read(fd, buf, count)

correspondent (dans l'ordre) aux champs aio_fildes, aio_buf, et aio_nbytes de la structure pointée par aiocbp. (Voir aio(7) pour une description de la structure aiocb.)

Les données sont lues à partir de la position absolue aiocbp->aio_offset, quel que soit le décalage du fichier. Après l'appel, la valeur du décalage du fichier est non spécifiée.

« Asynchrone » signifie que cet appel retourne dès que la requête a été mise en file d'attente ; la lecture peut ou peut ne pas être terminée lorsque l'appel retourne. On teste l'achèvement en utilisant aio_error(3). Le statut de retour d'une opération d'E/S terminée peut être obtenu par aio_return(3). Une notification asynchrone de l'achèvement des E/S peut être obtenue en configurant aiocbp->aio_sigevent de manière appropriée ; voir sigevent(3type) pour plus de détails.

Si _POSIX_PRIORITIZED_IO est défini, et si ce fichier le supporte, alors l'opération asynchrone est soumise à une priorité égale à celle du processus appelant moins aiocbp->aio_reqprio.

Le champ aiocbp->aio_lio_opcode est ignoré.

Aucune donnée n'est lue à partir d'un fichier régulier au-delà de son décalage maximal.

VALEUR DE RETOUR

En cas de succès, 0 est retourné. En cas d'erreur, la requête n'est pas mise en file d'attente, -1 est retourné et errno est défini pour indiquer l'erreur. Si une erreur n'est détectée que plus tard, elle sera rapportée via aio_return(3) (retourne le statut -1) et aio_error(3) (statut d'erreur — ce que l'on aurait obtenu dans errno, tel que EBADF).

ERREURS

EAGAIN
Manque de ressources.
EBADF
aio_fildes n'est pas un descripteur de fichier valide ouvert en lecture.
EINVAL
Un ou plusieurs des champs aio_offset, aio_reqprio, ou aio_nbytes sont invalides.
ENOSYS
aio_read() n'est pas implémenté.
EOVERFLOW
Le fichier est un fichier régulier, nous commençons la lecture avant la fin du fichier et voulons au moins un octet, mais la position de départ est au-delà du décalage maximal pour ce fichier.

ATTRIBUTS

Pour une explication des termes utilisés dans cette section, voir attributes(7).

Interface Attribut Valeur
aio_read () Sécurité des threads MT-Safe

NORMES

POSIX.1-2008.

HISTORIQUE

glibc 2.1. POSIX.1-2001.

NOTES

Il est conseillé de mettre à zéro le bloc de contrôle avant son utilisation. Le bloc de contrôle ne doit pas être modifié pendant que l'opération de lecture est en cours. La zone tampon dans laquelle les données sont lues ne doit pas être accédée pendant l'opération, sinon des résultats indéfinis peuvent survenir. Les zones mémoire impliquées doivent rester valides.

Les opérations d'E/S simultanées spécifiant la même structure aiocb produisent des résultats indéfinis.
