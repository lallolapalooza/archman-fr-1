DESCRIPTIO

N

La fonction aio_write() doit écrire aiocbp->aio_nbytes dans le fichier associé à aiocbp->aio_fildes depuis le tampon pointé par aiocbp->aio_buf. La fonction doit retourner lorsque la demande d'écriture a été initiée ou, au minimum, mise en file d'attente vers le fichier ou le

périphérique.

Si l'E/S priorisée est prise en charge pour ce fichier, alors l'opération asynchrone doit être soumise à une priorité égale à une priorité de planification de base moins aiocbp->aio_reqprio. Si l'ordonnancement d'exécution des threads n'est pas pris en charge, alors la priorité de planification de base est celle du processus appelant ;
sinon, la priorité de planification de base est celle du thread

appelant.

L'argument aiocbp peut être utilisé comme argument à aio_error() et aio_return() afin de déterminer respectivement le statut d'erreur et le statut de retour de l'opération asynchrone pendant son

déroulement.

L'argument aiocbp pointe vers une structure aiocb. Si le tampon pointé par aiocbp->aio_buf ou le bloc de contrôle pointé par aiocbp devient une adresse illégale avant l'achèvement de l'E/S asynchrone, alors le comportement est

indéfini.

Si O_APPEND n'est pas défini pour le descripteur de fichier aio_fildes, alors l'opération demandée doit avoir lieu à la position absolue dans le fichier telle que donnée par aio_offset, comme si lseek() était appelé immédiatement avant l'opération avec un décalage égal à aio_offset et un whence égal à SEEK_SET. Si O_APPEND est défini pour le descripteur de fichier, ou si aio_fildes est associé à un périphérique incapable de se déplacer, les opérations d'écriture s'ajoutent au fichier dans le même ordre que les appels ont été faits, sauf dans les circonstances décrites dans Section 2.8.2, E/S asynchrone. Après un appel réussi pour mettre en file une opération d'E/S asynchrone, la valeur du décalage de fichier pour le fichier est

indéterminée.

Le membre aio_sigevent spécifie la notification qui se produit lorsque la demande est

terminée.

Le champ aiocbp->aio_lio_opcode doit être ignoré par aio_writ

e().

Des opérations asynchrones simultanées utilisant le même aiocbp produisent des résultats

indéfinis.

Si l'E/S synchronisée est activée sur le fichier associé à aiocbp->aio_fildes, le comportement de cette fonction doit être selon les définitions de l'achèvement d'intégrité des données d'E/S synchronisée et de l'achèvement d'intégrité de fichier d'E/S

synchronisée.

Pour toute action système qui modifie l'espace mémoire du processus pendant qu'une E/S asynchrone est en attente vers la plage d'adresses étant modifiée, le résultat de cette action est

indéfini.

Pour les fichiers réguliers, aucun transfert de données ne doit se produire au-delà du décalage maximum établi dans la description de fichier ouverte associée à aiocbp->aio_filde

s
.
