NOM

airodump-ng - outil de capture de paquets sans fil pour aircrack-ng

SYNOPSIS

airodump-ng [options] <nom de l'interface>

DESCRIPTION

airodump-ng est utilisé pour capturer des trames 802.11 brutes dans le but de les utiliser avec aircrack-ng. Si vous avez un récepteur GPS connecté à l'ordinateur, airodump-ng est capable d'enregistrer les coordonnées des points d'accès trouvés. De plus, airodump-ng écrit un fichier texte contenant les détails de tous les points d'accès et clients vus.

OPTIONS

-H, --help
Affiche l'écran d'aide.
-i, --ivs
Enregistre uniquement les IV (uniquement utile pour le craquage). Si cette option est spécifiée, vous devez fournir un préfixe de dump (option --write)
-g, --gpsd
Indique qu'airodump-ng doit essayer d'utiliser GPSd pour obtenir les coordonnées.
-w <préfixe>, --write <préfixe>
Est le préfixe du fichier de dump à utiliser. Si cette option n'est pas donnée, les données seront seulement affichées à l'écran. En plus de ce fichier, un fichier CSV avec le même nom que la capture sera créé.
-e, --beacons
Enregistrera tous les beacons dans le fichier cap. Par défaut, il n'enregistre qu'un beacon pour chaque réseau.
-u <secs>, --update <secs>
Délai de <secs> secondes entre les mises à jour de l'affichage (par défaut : 1 seconde). Utile pour les CPU lents.
--showack
Affiche les statistiques ACK/CTS/RTS. Aide au débogage et à l'optimisation générale de l'injection. C'est une indication si vous injectez, injectez trop vite, atteignez le PA, si les trames sont des trames chiffrées valides. Permet de détecter les stations "cachées", qui sont trop éloignées pour capturer des trames à haut débit, car les trames ACK sont envoyées à 1Mbps.
-h
Masque les stations connues pour --showack.
--berlin <secs>
Temps avant de retirer le PA/client de l'écran quand aucune trame n'est plus reçue (Par défaut : 120 secondes). Voir le code source d'airodump-ng pour l'histoire derrière cette option ;).
-c <canal>[,<canal>[,...]], --channel <canal>[,<canal>[,...]]
Indique le(s) canal(aux) sur lesquels écouter. Par défaut, airodump-ng saute sur tous les canaux 2.4GHz.
-C <fréq>[,<fréq>[,...]]
Indique les fréquences sur lesquelles écouter. Par défaut, airodump-ng saute sur tous les canaux 2.4GHz.
-b <abg>, --band <abg>
Indique la bande sur laquelle airodump-ng doit sauter. Cela peut être une combinaison des lettres 'a', 'b' et 'g' ('b' et 'g' utilisent 2.4GHz et 'a' utilise 5GHz). Incompatible avec l'option --channel.
-s <méthode>, --cswitch <méthode>
Définit la manière dont airodump-ng définit les canaux lorsqu'il utilise plus d'une carte. Valeurs valides : 0 (FIFO, valeur par défaut), 1 (Round Robin) ou 2 (Hop on last).
-2, --ht20
Définit le canal pour être en HT20 (802.11n).
-3, --ht40+
Définit le canal pour être en HT40+ (802.11n). Cela nécessite que la fréquence 20MHz au-dessus soit disponible (4 canaux au-dessus) et donc certains canaux ne sont pas utilisables en HT40+. Seuls les canaux jusqu'à 7 sont disponibles en HT40+ aux États-Unis (et 9 dans la plupart de l'Europe).
-5, --ht40-
Définit le canal pour être en HT40- (802.11n). Cela nécessite que la fréquence 20MHz en dessous soit disponible (4 canaux en dessous) et donc certains canaux ne sont pas utilisables en HT40-. En 2.4GHz, les canaux HT40- commencent au canal 5.
-r <fichier>
Lit les paquets depuis un fichier.
-T, --real-time
Pendant la lecture des trames depuis un fichier spécifié avec '-r <fichier>', simule leur taux d'arrivée, comme si elles étaient "en direct".
-x <msecs>
Simulation de balayage actif (envoi de requêtes de sonde et analyse des réponses de sonde).
-M, --manufacturer
Affiche une colonne fabricant avec les informations obtenues à partir de la liste IEEE OUI. Voir airodump-ng-oui-update(8)
-U, --uptime
Affiche le temps de fonctionnement des PA obtenu à partir de l'horodatage de leur beacon.
-W, --wps
Affiche une colonne WPS avec la version WPS, la/des méthode(s) de configuration, et l'état AP Setup Locked obtenu à partir du beacon ou de la réponse de sonde du PA (s'il y en a).
--output-format <formats>
Définit les formats à utiliser (séparés par une virgule). Les valeurs possibles sont : pcap, ivs, csv, gps, kismet, netxml. Les valeurs par défaut sont : pcap, csv, kismet, kismet-newcore. 'pcap' est pour enregistrer une capture au format pcap, 'ivs' est pour le format ivs (c'est un raccourci pour --ivs). 'csv' créera un fichier CSV airodump-ng, 'kismet' créera un fichier csv kismet et 'kismet-newcore' créera le fichier netxml kismet. 'gps' est un raccourci pour --gps.
Ces valeurs peuvent être combinées à l'exception de ivs et pcap.
-I <secondes>, --write-interval <secondes>
Intervalle d'écriture du/des fichier(s) de sortie pour CSV, Kismet CSV et Kismet NetXML en secondes (minimum : 1 seconde). Par défaut : 5 secondes. Notez qu'un intervalle trop court peut ralentir airodump-ng.
-K <activer>, --background <activer>
Remplace la détection automatique de l'arrière-plan. Utilisez "0" pour forcer les paramètres de premier plan et "1" pour forcer les paramètres d'arrière-plan. Cela ne fera pas fonctionner airodump-ng comme un démon, il sautera l'autodétection de l'arrière-plan et forcera l'activation/désactivation du mode interactif et des mises à jour de l'affichage.
--ignore-negative-one
Supprime le message qui dit 'fixed channel <interface>: -1'.

Options de filtrage :

-t <OPN|WEP|WPA|WPA1|WPA2|WPA3|OWE>, --encrypt <OPN|WEP|WPA|WPA1|WPA2|WPA3|OWE>
N'affichera que les réseaux correspondant au chiffrement donné. Notez que WPA est un raccourci pour WPA1, WPA2 et WPA3. Peut être spécifié plus d'une fois : '-t OPN -t WPA2'
-d <bssid>, --bssid <bssid>
N'affichera que les réseaux correspondant au bssid donné.
-m <masque>, --netmask <masque>
N'affichera que les réseaux correspondant à la combinaison bssid ^ masque donnée. Nécessite que --bssid (ou -d) soit spécifié.
-a
N'affichera que les clients associés.
-n <int>, --min-packets <int>
Le nombre minimum de paquets reçus par un PA avant de l'afficher.
-N, --essid
Filtre les PA par ESSID. Peut être utilisé plusieurs fois pour correspondre à un ensemble d'ESSID.
-R, --essid-regex
Filtre les PA par ESSID en utilisant une expression régulière.

BSS
ID
Adresse MAC du point d'accès. Dans la section Client, un BSSID de "(not associated)" signifie que le client n'est associé à aucun PA. Dans cet état non associé, il recherche un PA auquel se
connecter.
PWR Niveau de signal rapporté par l'adaptateur Wi-Fi. Sa signification dépend du pilote, mais plus vous
vous approchez du PA ou de la station, plus le signal est élevé. C'est généralement le RSSI (
https://en.wikipedia.org/wiki/Received_signal_strength_indication). Si le BSSID PWR est -1, alors le pilote ne supporte pas le rapport du niveau de signal. Si PWR est -1 pour certains points d'accès, cela signifie que le point d'accès est hors de portée, cependant airodump-ng a reçu au moins une trame lui étant destinée. Si le PWR est -1 pour un nombre limité de stations, cela est dû à un paquet provenant du PA vers le client mais les transmissions du client sont hors de portée pour votre adaptateur Wi-Fi. Cela signifie que vous n'entendez que 1/2 de la communication. Si tous les clients ont PWR à -1, il est probable que le pilote ne supporte pas le rapport du niveau de signal. Un signal fort est autour de -40. Un signal moyen est autour de -55, et un signal faible commence autour de -70. La limite basse des adaptateurs Wi-Fi (sensibilité de réception) est souvent autour de
-80/-90.
RX
Q
Affiché uniquement lorsque sur un canal fixe. Qualité de Réception (Receive Quality) mesurée par le pourcentage de trames (trames de gestion et trames de données) reçues avec succès au cours des 10 dernières secondes. Elle est mesurée sur toutes les trames de gestion et de données. C'est l'indice, cela vous permet de tirer plus d'informations de cette valeur. Disons que vous avez 100 pour cent de RXQ et que les 10 (ou quel que soit le débit) beacons par seconde arrivent. Soudainement, le RXQ chute en dessous de 90, mais vous capturez toujours tous les beacons envoyés. Ainsi, vous savez que le PA envoie des trames à un client mais vous ne pouvez entendre ni le client ni le PA envoyant au client (il faut vous rapprocher). Une autre chose serait que vous ayez une carte 11MB pour surveiller et capturer les trames (disons un prism2.5) et que vous ayez une très bonne position par rapport au PA. Le PA est réglé sur 54MBit et de nouveau le RXQ chute, vous savez donc qu'il y a au moins un client 54MBit connecté au
PA.
Beaco
ns
Nombre de beacons envoyés par le PA. Chaque point d'accès envoie environ dix beacons par seconde au débit le plus bas (1M), ils peuvent donc généralement être captés de très
loin.
#Da
ta
Nombre de paquets de données capturés (si WEP, nombre d'IV uniques), incluant les paquets de diffusion de
données.
#/
s
Nombre de paquets de données par seconde mesuré sur les 10 dernières
secondes.
C
H
Numéro de canal (issu des trames de beacon). Note : parfois des trames d'autres canaux sont capturées même si airodump-ng ne fait pas de saut de canal, à cause d'interférences
radio.
M
B
Vitesse maximale supportée par le PA. Si MB = 11, c'est 802.11b, si MB = 22 c'est 802.11b+ et les débits supérieurs sont 802.11g. Le point (après 54 ci-dessus) indique que le préambule court est supporté. 'e' indique que le réseau a le QoS (802.11e)
activé.
EN
C
Algorithme de chiffrement utilisé. OPN = pas de chiffrement, "WEP?" = WEP ou supérieur (pas assez de données pour choisir entre WEP et WPA/WPA2), WEP (sans le point d'interrogation) indique WEP statique ou dynamique, et WPA ou WPA2 si TKIP ou CCMP ou MGT est
présent.
CIPH
ER
Le chiffrement détecté. L'un de CCMP, WRAP, TKIP, WEP, WEP40, ou WEP104. Non obligatoire, mais TKIP est typiquement utilisé avec WPA et CCMP est typiquement utilisé avec WPA2. WEP40 est affiché lorsque l'index de clé est supérieur à 0. La norme indique que l'index peut être 0-3 pour 40 bits et devrait être 0 pour 104
bits.
AU
TH
Le protocole d'authentification utilisé. L'un de MGT (WPA/WPA2 utilisant un serveur d'authentification séparé), SKA (clé partagée pour WEP), PSK (clé pré-partagée pour WPA/WPA2), ou OPN (ouvert pour
WEP).
WP
S
Ceci n'est affiché que lorsque --wps (ou -W) est spécifié. Si le PA supporte WPS, le premier champ de la colonne indique la version supportée. Le second champ indique les méthodes de configuration WPS (peut y avoir plus d'une méthode, séparées par une virgule) : USB = méthode USB, ETHER = Ethernet, LAB = Étiquette, DISP = Affichage, EXTNFC = NFC Externe, INTNFC = NFC Interne, NFCINTF = Interface NFC, PBC = Bouton Poussoir, KPAD = Clavier. Locked est affiché lorsque la configuration du PA est
verrouillée.
ESS
ID
Le "SSID" en question, qui peut être vide si le masquage du SSID est activé. Dans ce cas, airodump-ng essaiera de récupérer le SSID à partir des réponses de sonde et des requêtes
d'association.
STATI
ON
Adresse MAC de chaque station associée ou des stations recherchant un PA auquel se connecter. Les clients actuellement non associés à un PA ont un BSSID de "(not associated)
".
Ra
te
Ceci n'est affiché que lors de l'utilisation d'un canal unique. Le premier nombre est le dernier débit de données du PA (BSSID) vers le Client (STATION). Le second nombre est le dernier débit de données du Client (STATION) vers le PA (BSSID)
.
Lo
st
Cela signifie les trames perdues en provenance du client. Pour déterminer le nombre de trames perdues, il y a un champ de séquence sur chaque trame non de contrôle, vous pouvez donc soustraire le numéro de séquence avant-dernier du dernier numéro de séquence et vous saurez combien de trames vous avez
perdues.
Not
es
Informations supplémentaires sur le client, telles que EAPOL ou PMKID
capturés.
Fram
es
Le nombre de paquets de données envoyés par le
client.
Prob
es
Les ESSID sondés par le client. Ce sont les
réseaux auxquels le client essaie de se con
necter s'il n'est pas actuellement connecté.

La première partie est les points d'accès détectés. La seconde partie est une li

ste des clients sans fil détectés, les stations. En se basant sur la puissance
du signal, on peut même localiser physiquement la position d'une station donnée.
