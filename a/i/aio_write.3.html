aio_write(3) Manuel des fonctions de bibliothèque aio_write(3)

NOM

aio_write - écriture asynchrone

BIBLIOTHÈQUE

Bibliothèque temps réel (librt, -lrt)

SYNTAXE

#include <aio.h>
int aio_write(struct aiocb *aiocbp);

DESCRIPTION

La fonction aio_write() met en file d'attente la requête d'E/S décrite par le tampon pointé par aiocbp. Cette fonction est l'analogue asynchrone de write(2). Les arguments de l'appel


write(fd, buf, count)

correspondent (dans l'ordre) aux champs aio_fildes, aio_buf et aio_nbytes de la structure pointée par aiocbp. (Voir aio(7) pour une description de la structure aiocb.)

Si O_APPEND n'est pas défini, les données sont écrites en commençant à la position absolue aiocbp->aio_offset, indépendamment du décalage de fichier. Si O_APPEND est défini, les données sont écrites à la fin du fichier dans le même ordre que les appels aio_write(). Après l'appel, la valeur du décalage de fichier est non spécifiée.

« Asynchrone » signifie que cet appel retourne dès que la requête a été mise en file d'attente ; l'écriture peut être terminée ou non lorsque l'appel retourne. On teste l'achèvement avec aio_error(3). Le statut de retour d'une opération d'E/S terminée peut être obtenu avec aio_return(3). Une notification asynchrone de l'achèvement des E/S peut être obtenue en configurant aiocbp->aio_sigevent de manière appropriée ; voir sigevent(3type) pour les détails.

Si _POSIX_PRIORITIZED_IO est défini, et que ce fichier le prend en charge, alors l'opération asynchrone est soumise avec une priorité égale à celle du processus appelant moins aiocbp->aio_reqprio.

Le champ aiocbp->aio_lio_opcode est ignoré.

Aucune donnée n'est écrite dans un fichier régulier au-delà de son décalage maximum.

VALEUR DE RETOUR

En cas de succès, 0 est retourné. En cas d'erreur, la requête n'est pas mise en file d'attente, -1 est retourné, et errno est défini pour indiquer l'erreur. Si une erreur n'est détectée que plus tard, elle sera signalée via aio_return(3) (retourne le statut -1) et aio_error(3) (statut d'erreur — ce qui aurait été obtenu dans errno, tel que EBADF).

ERREURS

EAGAIN
Ressources insuffisantes.
EBADF
aio_fildes n'est pas un descripteur de fichier valide ouvert en écriture.
EFBIG
Le fichier est un fichier régulier, nous voulons écrire au moins un octet, mais la position de départ est au niveau ou au-delà du décalage maximum pour ce fichier.
EINVAL
Un ou plusieurs des champs aio_offset, aio_reqprio, aio_nbytes sont invalides.
ENOSYS
aio_write() n'est pas implémenté.

ATTRIBUTS

Pour une explication des termes utilisés dans cette section, voir attributes(7).

Interface Attribut Valeur
aio_write () Sécurité des threads MT-Safe

NORMES

POSIX.1-2008.

HISTORIQUE

glibc 2.1. POSIX.1-2001.

NOTES

Il est conseillé de remettre à zéro le bloc de contrôle avant utilisation. Le bloc de contrôle ne doit pas être modifié pendant que l'opération d'écriture est en cours. La zone tampon utilisée doit rester valide et ne pas être accédée pendant l'opération, sinon des résultats indéfinis peuvent survenir.

Les opérations d'E/S simultanées spécifiant la même structure aiocb produisent des résultats indéfinis.
