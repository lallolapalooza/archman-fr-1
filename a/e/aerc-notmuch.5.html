NOM

aerc-notmuch - Configuration notmuch pour aerc(1)

SYNTAXE

aerc prend en charge l'utilisation du système de messagerie notmuch comme backend, pour une indexation et une recherche rapides.

Pour que cela soit activé, aerc doit être compilé avec le support de notmuch. Référez-vous aux instructions d'installation pour plus de détails.

CONFIGURATION

La configuration de base de Notmuch peut être effectuée de manière interactive avec la commande :new-account.

Dans accounts.conf (voir aerc-accounts(5)), les options spécifiques à notmuch suivantes sont disponibles :

check-mail-cmd = <commande>

Commande à exécuter en conjonction avec l'option check-mail.

Exemple :

check-mail-cmd = mbsync -a

check-mail-timeout = <durée>

Délai d'attente pour check-mail-cmd. La commande sera arrêtée si elle ne se termine pas dans cet intervalle et une erreur sera affichée. Augmentez la valeur par défaut si des erreurs répétées se produisent.

Par défaut : 10s

source = notmuch://<chemin>

La source indique le chemin du répertoire contenant votre base de données notmuch (généralement un dossier .notmuch/).

La partie chemin de l'URL après notmuch:// doit être soit un chemin absolu préfixé par /, soit un chemin relatif à votre répertoire personnel préfixé par ~. Par exemple :

source = notmuch:///home/moi/mail

source = notmuch://~/mail

query-map = <fichier>

Chemin vers un fichier contenant une correspondance entre un nom d'affichage et une requête notmuch sous la forme <NOM>=<REQUÊTE>.

Plusieurs entrées peuvent être spécifiées, une par ligne. Les lignes commençant par # sont ignorées et servent de commentaires.

par ex. inbox=tag:inbox and not tag:archived

exclude-tags = <tag1,tag2,tag3...>

Liste séparée par des virgules de tags qui seront exclus des résultats de requête, sauf s'ils sont explicitement mentionnés dans la requête.

Cela peut par exemple être utile si vous utilisez un tag archive ou spam.

maildir-store = <chemin>

Chemin vers le répertoire maildir contenant les fichiers de messages qui sous-tendent la base de données notmuch. C'est souvent le même chemin que celui de la base de données notmuch. Si spécifié, cette option sera utilisée par aerc pour lister les dossiers disponibles et activer des commandes telles que :delete et :archive.

N.B. : aerc affichera toujours les messages et non les fichiers (sous notmuch, un seul message peut être représenté par plusieurs fichiers), ce qui rend les sémantiques de certaines commandes comme move ambiguës. Utilisez multi-file-strategy pour indiquer à aerc comment résoudre ces ambiguïtés.

maildir-account-path = <chemin>

Chemin du compte maildir relatif au maildir-store.

Ceci pourrait être utilisé pour obtenir le comportement traditionnel de maildir avec un onglet par compte. La note concernant maildir-store s'applique également à cette option.

multi-file-strategy = <stratégie>

Stratégie pour les opérations sur les fichiers (par exemple, déplacer, copier, supprimer) sur les messages qui sont sous-tendus par plusieurs fichiers. Valeurs possibles :
  • refuse (par défaut) : Refuser d'agir.
  • act-all : Agir sur tous les fichiers.
  • act-one : Agir sur un des fichiers, choisi arbitrairement, et ignorer les
restants.
  • act-one-delete-rest : Comme act-one, mais supprimer les fichiers restants.
  • act-dir : Agir sur tous les fichiers dans le dossier courant et ignorer les
restants.
Notez que cette stratégie ne fonctionne qu'à l'intérieur des répertoires maildir ; dans d'autres
répertoires, elle se comporte comme refuse.
•
act-dir-delete-rest : Comme act-dir, mais supprimer les fichiers restants.

Notez que la stratégie n'a aucun effet sur les opérations entre comptes. Copier un message entre comptes copiera toujours un seul fichier, choisi arbitrairement. Déplacer un message entre comptes copiera toujours un seul fichier, choisi arbitrairement, et refusera de supprimer plusieurs fichiers du compte source.

UTILISATION

Notmuch présente un comportement légèrement différent par rapport à imap par exemple. Certaines commandes ont des sémantiques légèrement différentes et sont mentionnées ci-dessous :

cf <requête notmuch>

La commande de changement de dossier permet des requêtes notmuch arbitraires. L'exécution d'une commande :cf effectuera une nouvelle requête notmuch de niveau supérieur.

filter <requête notmuch>

La commande de filtre pour les backends notmuch accepte des requêtes notmuch arbitraires. Elle applique la requête à l'ensemble des messages affichés dans la liste des messages. Cela peut être utilisé pour effectuer des filtres/requêtes successifs. C'est équivalent à effectuer un ensemble de requêtes concaténées par "and".
