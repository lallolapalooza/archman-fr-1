aerc-patch - gestion locale des correctifs pour aerc(

1
)

SYNOPSI

S

aerc prend en charge la gestion de jeux de correctifs locaux. Dans un flux de travail de développement logiciel basé sur le courrier électronique, il y a généralement de nombreuses séries de correctifs différentes appliquées localement pour les tests et les revues. La gestion du dépôt local peut donc être difficile. Avec le système de gestion locale des correctifs, aerc facilite ce processus de tenue de

registre.

Lors de l'application d'un jeu de correctifs, aerc crée une étiquette pour ces commits. Avec cette étiquette, le jeu de correctifs peut être suivi et plus tard abandonné si nécessaire. Les correctifs sont stockés dans une structu

re de données de projet qui conserve également la trace du répertoire où se trouve le dépôt
. Plusieurs bases de code peuvent être suivies en définissant un projet séparé pour chacune.

S

t>]
Crée un nouveau projet <projet>. Si <projet> n'est pas défini, aerc utilisera le dernier élément du chemin du répertoire courant. Il effectue également une recherche d'un dépôt pris en charge dans le répertoire courant.

-f : Écrase un p

:patch apply [-c <cmd>] [-w <commit-ish>] <tag

>
Applique le ou les messages sélectionnés au dépôt du projet courant. Il utilise pour cela la commande :pipe et garde la trace du correctif appliqué.

Des complétions pour le <tag> sont disponibles en fonction des lignes d'objet des messages sélectionnés ou

marqués.

-c <cmd> : Applique les correctifs avec la commande <cmd> fournie. Toute occurrence de '%r' dans la chaîne de commande sera remplacée par le répertoire racine du projet courant. Notez que cette approche n'est généralement pas recommandée et ne devrait être utilisée que pour des objectifs très spécifiques, c'est-à-dire lorsqu'un mainteneur applique un jeu de correctifs via un script séparé pour gérer les trailers

git.

aerc proposera des complétions pour le <tag> en fonction des lignes d'objet des messages sélectionnés ou

marqués.

Exemple

: 
:patch apply
-c "git -C %r
am -3" fix_v2

-w <commit-ish> : Crée un arbre de travail lié pour le projet courant à <commit-ish> et applique les correctifs à l'arbre de travail lié. Un nouveau projet est créé pour stocker les informations de l'arbre de travail. Lorsque ce projet est supprimé, l'arbre de travail le sera

également.

POUR

COMMENCER

Assurez-vous d'avoir un projet initialisé (voir :patch

init).

Maintenant, il y a deux façons de mettre les correctifs sous le système de gestion locale des correctifs

:
•
Appliquer les correctifs avec la commande :patch apply. Cela créera automatiqueme
nt une nouvelle étiquette
pour les commits appliqués.
•
Utiliser :patch rebase. S'il existe des correctifs locaux dans l'historique des commits qui devraient être gérés par aerc, vous pouvez exécuter :patch rebase <commit-ish> et définir <commit-ish> sur le commit précédant le premier correctif que vous voulez inclure. Pour un dépôt git qui a un amont appelé origin, vous exécuteriez :patch reba
se ori
gin/m
aster.

EXEMPL

E

L'exemple suivant montre comment gérer les jeux de correctifs

locaux.

D'abord, un projet doit être initialisé. Cela se fait en changeant de répertoire vers le répertoire de travail où se trouve le dépôt du projet. Pour cet exemple, supposons que nous avons un projet appelé bar dans le répertoire /home/user/foo/bar

. 
:cd /home/user/foo/b
a
r

puis en créant un nouveau projet

avec 
:pat
ch
init

Si aucun nom n'est fourni à :patch init, aerc utilisera le dernier élément du chemin du répertoire de travail (ici : bar

).

Le suivi des correctifs est maintenant prêt à l'action. Allez dans la liste des messages, marquez une série de correctifs et appliquez-la

: 
:patch
apply
fix_v2

Cela appliquera le jeu de correctifs sélectionné et assignera l'étiquette fix_v2 à ces commits. L'étiquette aide à garder les commits groupés ensemble, et sera utile lorsque nous voudrons abandonner ce jeu de correctifs exact à un moment

ultérieur.

Avec :patch list, vous pouvez vérifier que le jeu de correctifs a été correctement

appliqué.

S'il y a un changement dans le dépôt sous-jacent (par exemple en réappliquant sur l'amont), les hachages des commits locaux appliqués peuvent changer. :patch list peut détecter un tel changement et proposera alors de réappliquer les données internes. Pour ce faire,

exécutez 
:pat
ch re
base

Cela ouvrira un éditeur où vous pourrez réajuster les étiquettes correctes. Vous pourriez aussi changer le point de réapplication en fournissant un argument optionnel (par exemple un hachage de commit, ou même HEAD~3 ou origin/master, etc.)

.

Pour abandonner un jeu de correctifs, utilisez l'étiquette qui a été assignée lors de l'application

: 
:patch
drop
fix_v2

Et pour supprimer les données du projet dans aerc

: 
:pat
ch u
nlink
bar
