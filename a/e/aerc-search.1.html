NOM

aerc-search - recherche et filtres de motifs et d'options pour aerc(1)

SYNTAXE

Cette syntaxe est commune à tous les backends.

:filter [-rubae] [-x <flag>] [-X <flag>] [-H <en-tête>:[<valeur>]] [-f <de>] [-t <à>] [-c <cc>] [-d <début[..fin]>] [<termes>...]
:search [-rubae] [-x <flag>] [-X <flag>] [-H <en-tête>:[<valeur>]] [-f <de>] [-t <à>] [-c <cc>] [-d <début[..fin]>] [<termes>...]

Recherche dans le dossier courant les messages correspondant à l'ensemble des conditions données.

:filter restreint les messages affichés aux seuls résultats de la recherche.

Chaque terme séparé par un espace de <termes>, s'il est fourni, est recherché sans distinction de casse dans les lignes d'objet, sauf si -b ou -a sont fournis.

-r : Rechercher les messages lus

-u : Rechercher les messages non lus

-x <flag>, -X <flag> : Restreindre la recherche aux messages avec ou sans <flag>

Utilisez -x pour rechercher les messages avec le flag défini. Utilisez -X pour rechercher les messages sans le flag défini.

Les valeurs possibles sont :

seen
Messages lus
answered
Messages répondus
forwarded
Messages transférés
flagged
Messages marqués
draft
Messages brouillons

-H <en-tête>:[<valeur>] :

Recherche dans les en-têtes des messages un <en-tête> spécifique qui correspond à <valeur>. <valeur> peut être omis pour ne rechercher qu'un <en-tête>. Si l'<en-tête> ou la <valeur> contiennent un espace, l'argument entier doit être échappé avec des guillemets. Note : les espaces autour de <valeur> sont supprimés.

-b : Rechercher dans le corps des messages

-a : Rechercher dans le texte entier des messages

-e : Demande au backend d'utiliser une extension de recherche personnalisée

(comme X-GM-EXT-1 si disponible). Les termes de recherche sont attendus dans <termes> ; les autres drapeaux seront ignorés.

-f <de> : Rechercher les messages de <de>

-t <à> : Rechercher les messages adressés à <à>

-c <cc> : Rechercher les messages en copie carbone à <cc>

-d <depuis[..jusqu’à]> :

Rechercher les messages dans une plage de dates spécifique entre depuis et jusqu’à, en excluant ce dernier (en notation mathématique : rechercher les messages dans l'intervalle [depuis, jusqu’à)). jusqu’à peut être omis pour ne rechercher que à partir de <depuis> jusqu'à présent.

Les espaces et les traits de soulignement sont autorisés dans les dates relatives pour améliorer la lisibilité.

AAAA-MM-JJ

aujourd'hui, hier

(cette|dernière) (année|mois|semaine)

Jours_de_la_semaine, Mois

Peuvent également être abrégés, ainsi Lundi..Mardi peut s'écrire Lun..Mar et Février..Mars peut s'écrire Fév..Mar.

<N> (a[nnée]|m[ois]|s[emaine]|j[our])

<N> est un entier positif représentant le nombre d'unités de temps dans le passé. Plusieurs termes relatifs peuvent être accumulés. Les unités peuvent également être abrégées par une seule lettre, ainsi hier correspondrait à 1j (équivalent à 1 jour ou 1_jour) et il y a 8 jours serait soit 1s1j soit 8j.

EXTENSIONS IMAP PERSONNALISÉES

L'extension IMAP de Gmail (X-GM-EXT-1) peut être utilisée pour la recherche et le filtrage. Pour utiliser cette extension personnalisée, assurez-vous qu'elle est activée (voir aerc-imap(5)) et utilisez l'option d'extension -e dans vos commandes :filter ou :search.

Exemple :
:filter -e nom-de-fichier:pdf de:bob :filter -e a:pièce_jointe plus_récent_que:2j

:search -e est:lu est:favori :search -e liste:~rjarry/aerc-devel@lists.sr.ht

NOTMUCH

Pour notmuch, il est possible d'éviter d'utiliser les options ci-dessus et de s'appuyer uniquement sur la syntaxe de recherche notmuch.

:filter requête...
:search requête...

Vous pouvez utiliser le langage de requête complet de notmuch tel que décrit dans notmuch-search-terms(7).

La requête ne s'appliquera qu'au-dessus de la requête de dossier active.

Exemple, sauter au prochain message non lu :

:search tag:nonlu
