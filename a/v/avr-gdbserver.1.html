DESCRIPTIO

N

gdbserver est un programme qui vous permet d'exécuter GDB sur une machine différente de celle qui exécute le programme en cours de

débogage.

Utilisation (côté serveur (cible))

:

Tout d'abord, vous devez placer une copie du programme que vous souhaitez déboguer sur le système cible. Le programme peut être dépouillé de ses symboles pour économiser de l'espace si nécessaire, car gdbserver ne se soucie pas des symboles. Toute la gestion des symboles est prise en charge par GDB exécuté sur le système

hôte.

Pour utiliser le serveur, vous vous connectez au système cible et exécutez le programme gdbserver. Vous devez lui indiquer (a) comment communiquer avec GDB, (b) le nom de votre programme et (c) ses arguments. La syntaxe générale est

: 
target> gdbserver <comm> <program> [<args> ...
]

Par exemple, en utilisant un port série, vous pourriez dire

: 
target> gdbserver /dev/com1 emacs foo.
txt

Cela indique à gdbserver de déboguer emacs avec l'argument foo.txt et de communiquer avec GDB via /dev/com1. gdbserver attend maintenant patiemment que le GDB hôte communique avec

lui.

Pour utiliser une connexion TCP, vous pourriez dire

: 
target> gdbserver host:2345 emacs foo.
txt

Cela dit essentiellement la même chose que l'exemple précédent, sauf que nous allons communiquer avec le GDB "host" via TCP. L'argument "host:2345" signifie que nous nous attendons à voir une connexion TCP en provenance de "host" vers le port TCP local 2345. (Actuellement, la partie "host" est ignorée.) Vous pouvez choisir le numéro de port de votre choix à condition qu'il n'entre pas en conflit avec les ports TCP existants sur le système cible. Ce même numéro de port doit être utilisé dans la commande "target remote" du GDB hôte, qui sera décrite brièvement. Notez que si vous choisissez un numéro de port qui entre en conflit avec un autre service, gdbserver affichera un message d'erreur et se

terminera.

gdbserver peut aussi s'attacher à des programmes en cours d'exécution. Cela est accompli via l'argument --attach. La syntaxe est

: 
target> gdbserver --attach <comm>
<pid>

pid est l'identifiant de processus d'un processus en cours d'exécution. Il n'est pas nécessaire d'indiquer à gdbserver le binaire du processus en cours

d'exécution.

Pour démarrer "gdbserver" sans fournir de commande initiale à exécuter ni d'identifiant de processus à attacher, utilisez l'option de ligne de commande --multi. Dans ce cas, vous devez vous connecter en utilisant "target extended-remote" pour démarrer le programme que vous souhaitez

déboguer. 
target> gdbserver --multi
<comm>

Utilisation (côté hôte)

:

Vous avez besoin d'une copie non dépouillée du programme cible sur votre système hôte, car GDB doit examiner ses tables de symboles et autres. Démarrez GDB comme vous le feriez normalement, avec le programme cible comme premier argument. (Vous devrez peut-être utiliser l'option --baud si la ligne série fonctionne à un débit autre que 9600 bauds.) C'est-à-dire "gdb TARGET-PROG", ou "gdb --baud BAUD TARGET-PROG". Après cela, la seule nouvelle commande que vous devez connaître est "target remote" (ou "target extended-remote"). Son argument est soit un nom de périphérique (généralement un périphérique série, comme /dev/ttyb), soit un descripteur "HOST:PORT". Par exemple

: 
(gdb) target remote
/dev/ttyb

communique avec le serveur via la ligne série /dev/ttyb, et

: 
(gdb) target remote the-target:
2345

communique via une connexion TCP vers le port 2345 sur l'hôte `the-target', où vous avez précédemment démarré gdbserver avec le même numéro de port. Notez que pour les connexions TCP, vous devez démarrer gdbserver avant d'utiliser la commande `target remote', sinon vous pourriez obtenir une erreur ressemblant à `Connection

refused'.

gdbserver peut aussi déboguer plusieurs inférieurs à la fois, comme décrit dans le manuel GDB au nœud "Inferiors Connections and Programs" -- commande shell "info -f gdb -n 'Inferiors Connections and Programs'". Dans ce cas, utilisez la variante de commande GDB "extended-rem

ote" : 
(gdb) target extended-remote the-target:
2345

L'option gdbserver --multi peut être utilisé

e ou non
dans ce cas.
