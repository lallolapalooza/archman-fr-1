Le préprocesseur C, souvent connu sous le

nom de

cpp est un processeur de macros utilisé automatiquement par le compilateur C pour transformer votre programme avant la compilation. On l'appelle processeur de macros car il vous permet de définir des macros qui sont de brèves abréviations pour des constructions plus longues. Le préprocesseur C est destiné à être utilisé uniquement avec du code source C, C++ et Objective-C. Par le passé, il a été détourné comme processeur de texte général. Il échouera sur une entrée qui ne respecte pas les règles lexicales du C. Par exemple, les apostrophes seront interprétées comme le début de constantes de caractères et provoqueront des erreurs. De plus, vous ne pouvez pas compter sur lui pour préserver les caractéristiques de l'entrée qui ne sont pas significatives pour les langages de la famille C. Si un Makefile est prétraité, toutes les tabulations seront supprimées et le Makefile ne fonctionnera

pas.

Cela dit, vous pouvez souvent utiliser cpp sur des choses qui ne sont pas du C. D'autres langages de programmation de type Algol sont souvent sûrs (Ada, etc.). L'assembleur aussi, avec

prudence.

Le mode -traditional-cpp préserve plus d'espaces blancs et est par ailleurs plus permissif. Beaucoup de problèmes peuvent être évités en écrivant des commentaires de style C ou C++ au lieu de commentaires natifs et en gardant les macros simples. Dans la mesure du possible, vous devriez utiliser un préprocesseur adapté au langage dans lequel vous écrivez. Les versions modernes de l'assembleur GNU disposent de fonctionnalités de macro. La plupart des langages de programmation de haut niveau ont leur propre mécanisme de compilation conditionnelle et d'inclusion. Si tout le reste échoue, essayez un vrai processeur de texte général, comme GNU

M4.

Les préprocesseurs C varient dans certains détails. Ce manuel discute du préprocesseur C GNU, qui fourit un petit sur-ensemble des caractéristiques du C standard ISO. Dans son mode par défaut, le préprocesseur C GNU ne fait pas quelques choses requises par la norme. Ce sont des caractéristiques rarement, voire jamais utilisées, et qui peuvent provoquer des changements surprenants dans la signification d'un programme qui ne s'y attend pas. Pour obtenir le C standard ISO strict, vous devriez utiliser les

options

-std=c90, -std=c99, -std=c11 ou -std=c17 selon la version de la norme que vous souhaitez. Pour obtenir tous les diagnostics obligatoires, vous devez également utiliser -pedantic. Ce manuel décrit le comportement du préprocesseur ISO. Pour minimiser les différences arbitraires, là où le comportement du préprocesseur ISO n'est pas en conflit avec la sémantique traditionnelle, le préprocesseur traditionnel devrait se comporter de la même manière. Les différentes différences qui existent

sont détaillées dans la section

Mode traditionnel. Pour plus de clarté, sauf indication contraire, les

références à

CPP dans ce manuel se réfèrent à GNU CPP. OPTI

Au lieu de produire le résultat du prétraitement, produit une règle adaptée à make décrivant les dépendances du fichier source principal. Le préprocesseur produit une règle make contenant le nom du fichier objet pour ce fichier source, un deux-points, et les noms de tous les fichiers inclus, y compris ceux provenant des options de ligne de commande -include ou -imacros.

Sauf indication explicite (avec -MT ou -MQ), le nom du fichier objet se compose du nom du fichier source avec tout suffixe remplacé par le suffixe de fichier objet et avec toute partie de répertoire initiale supprimée. S'il y a beaucoup de fichiers inclus, la règle est divisée en plusieurs lignes en utilisant \-nouvelle-ligne. La règle n'a pas de

commandes.

Cette option ne supprime pas la sortie de débogage du préprocesseur, telle que -dM. Pour éviter de mélanger cette sortie de débogage avec les règles de dépendance, vous devriez spécifier explicitement le fichier de sortie des dépendances avec -MF, ou utiliser une variable d'environnement comme DEPENDENCIES_OUTPUT. La sortie de débogage est toujours envoyée au flux de sortie régulier comme d'habitude.

Passer -M au pilote implique -E et supprime les avertissements avec un -w implicite.

-MM
Comme -M, mais ne mentionne pas les fichiers d'en-tête trouvés dans les répertoires d'en-têtes système, ni les fichiers d'en-tête qui sont inclus, directement ou indirectement, à partir d'un tel en-tête.

Cela implique que le choix des crochets d'angle ou des guillemets doubles dans une directive #include ne détermine pas en soi si cet en-tête apparaît dans la sortie de dépendances -MM.

-MF fichier
Lorsqu'il est utilisé avec -M ou -MM, spécifie un fichier dans lequel écrire les dépendances. Si aucun commutateur -MF n'est donné, le préprocesseur envoie les règles au même endroit où il enverrait la sortie préprocessée.

Lorsqu'il est utilisé avec les options du pilote -MD ou -MMD, -MF remplace le fichier de sortie de dépendances par défaut.

Si fichier est -, les dépendances sont écrites sur stdout.

-MG
En conjonction avec une option telle que -M demandant la génération de dépendances, -MG suppose que les fichiers d'en-tête manquants sont des fichiers générés et les ajoute à la liste de dépendances sans lever d'erreur. Le nom de fichier de dépendance est pris directement de la directive "#include" sans préfixer de chemin. -MG supprime également la sortie préprocessée, car un fichier d'en-tête manquant rend cela inutile.

Cette fonctionnalité est utilisée dans la mise à jour automatique des makefiles.

-Mno-modules
Désactive la génération de dépendances pour les interfaces de modules compilées.
-MP
Cette option demande à CPP d'ajouter une cible factice (phony target) pour chaque dépendance autre que le fichier principal, faisant en sorte que chacune dépend de rien. Ces règles factices contournent les erreurs que make donne si vous supprimez des fichiers d'en-tête sans mettre à jour le Makefile pour qu'il corresponde.

Voici une sortie typique :

test.o: test.c test.h

test.h:
-MT cible
Modifie la cible de la règle générée par la génération de dépendances. Par défaut, CPP prend le nom du fichier d'entrée principal, supprime tout composant de répertoire et toute extension de fichier telle que .c, et ajoute le suffixe d'objet habituel de la plateforme. Le résultat est la cible.

Une option -MT définit la cible comme étant exactement la chaîne que vous spécifiez. Si vous voulez plusieurs cibles, vous pouvez les spécifier comme un seul argument à -MT, ou utiliser plusieurs options -MT.

Par exemple, -MT '$(objpfx)foo.o' pourrait donner

$(objpfx)foo.o: foo.c
-MQ cible
Identique à -MT, mais met entre guillemets les caractères qui sont spéciaux pour Make. -MQ '$(objpfx)foo.o' donne 
$$(objpfx)foo.o: foo.c

La cible par défaut est automatiquement mise entre guillemets, comme si elle était donnée avec -MQ.

-MD
-MD est équivalent à -M -MF fichier, sauf que -E n'est pas implicite. Le pilote détermine le fichier en fonction de la présence ou non d'une option -o. Si c'est le cas, le pilote utilise son argument mais avec un suffixe .d, sinon il prend le nom du fichier d'entrée, supprime les composants de répertoire et l'extension, et applique un suffixe .d.

Si -MD est utilisé conjointement avec -E, tout commutateur -o est interprété comme spécifiant le fichier de sortie de dépendances, mais s'il est utilisé sans -E, chaque -o est interprété comme spécifiant un fichier objet cible.

Puisque -E n'est pas implicite, -MD peut être utilisé pour générer un fichier de sortie de dépendances comme effet secondaire du processus de compilation.

-MMD
Comme -MD, mais ne mentionne que les fichiers d'en-tête utilisateur, pas les fichiers d'en-tête système.
-fpreprocessed
Indique au préprocesseur que le fichier d'entrée a déjà été préprocessé. Cela supprime des éléments tels que l'expansion de macros, la conversion de trigraphes, le collage de sauts de ligne échappés et le traitement de la plupart des directives. Le préprocesseur reconnaît et supprime toujours les commentaires, de sorte que vous pouvez passer un fichier préprocessé avec -C au compilateur sans problème. Dans ce mode, le préprocesseur intégré n'est guère plus qu'un analyseur lexical pour les front ends.

-fpreprocessed est implicite si le fichier d'entrée a une des extensions .i, .ii ou .mi. Ce sont les extensions que GCC utilise pour les fichiers préprocessés créés par -save-temps.

-fdirectives-only
Lors du pré-traitement, traite les directives, mais n'étend pas les macros.

Le comportement de l'option dépend des options -E et -fpreprocessed.

Avec -E, le pré-traitement est limité au traitement des directives telles que "#define", "#ifdef" et "#error". D'autres opérations de préprocesseur, telles que l'expansion de macros et la conversion de trigraphes, ne sont pas effectuées. De plus, l'option -dD est implicitement activée.

Avec -fpreprocessed, la pré-définition des macros de ligne de commande et la plupart des macros intégrées sont désactivées. Les macros telles que "__LINE__", qui sont contextuellement dépendantes, sont traitées normalement. Cela permet la compilation de fichiers précédemment pré-traités avec "-E -fdirectives-only".

Avec -E et -fpreprocessed, les règles pour -fpreprocessed ont la priorité. Cela permet un pré-traitement complet des fichiers précédemment pré-traités avec "-E -fdirectives-only".

-fdollars-in-identifiers
Accepte $ dans les identificateurs.
-fextended-identifiers
Accepte les noms de caractères universels et les caractères étendus dans les identificateurs. Cette option est activée par défaut pour C99 (et les versions ultérieures de la norme C) et C++.
-fno-canonical-system-headers
Lors du pré-traitement, ne raccourcit pas les chemins des en-têtes système par canonicalisation.
-fmax-include-depth=profondeur
Définit la profondeur maximale des #include imbriqués. La valeur par défaut est 200.
-fsearch-include-path[=type]
Recherche les fichiers d'entrée dans le chemin #include, pas seulement dans le répertoire courant. Ceci est particulièrement utile avec les modules C++20, pour lesquels les unités d'en-tête et les unités d'interface de module doivent être compilées directement : 
g++ -c -std=c++20 -fmodules -fsearch-include-path bits/stdc++.h bits/std.cc

type vaut par défaut user, ce qui recherche dans le chemin de recherche "#include "..."" ; vous pouvez également spécifier explicitement system pour le chemin de recherche "#include <...>".

-ftabstop=largeur
Définit la distance entre les tabulations. Cela aide le préprocesseur à rapporter des numéros de colonne corrects dans les avertissements ou les erreurs, même si des tabulations apparaissent sur la ligne. Si la valeur est inférieure à 1 ou supérieure à 100, l'option est ignorée. La valeur par défaut est 8.
-ftrack-macro-expansion[=niveau]
Suivi des emplacements des jetons à travers les expansions de macros. Cela permet au compilateur d'émettre des diagnostics sur la pile d'expansion de macros actuelle lorsqu'une erreur de compilation survient dans une expansion de macro. L'utilisation de cette option rend le préprocesseur et le compilateur plus gourmands en mémoire. Le paramètre niveau peut être utilisé pour choisir le niveau de précision du suivi des emplacements de jetons, diminuant ainsi la consommation de mémoire si nécessaire. La valeur 0 de niveau désactive cette option. La valeur 1 suit les emplacements des jetons dans un mode dégradé pour une surcharge mémoire minimale. Dans ce mode, tous les jetons résultant de l'expansion d'un argument d'une macro de type fonction ont le même emplacement. La valeur 2 suit complètement les emplacements des jetons. Cette valeur est la plus gourmande en mémoire. Lorsque cette option est donnée sans argument, la valeur par défaut du paramètre est 2.

Notez que "-ftrack-macro-expansion=2" est activé par défaut.

-fmacro-prefix-map=ancien=nouveau
Lors du pré-traitement de fichiers résidant dans le répertoire ancien, développe les macros "__FILE__" et "__BASE_FILE__" comme si les fichiers résidaient dans le répertoire nouveau à la place. Cela peut être utilisé pour changer un chemin absolu en un chemin relatif en utilisant . pour nouveau, ce qui peut aboutir à des builds plus reproductibles et indépendants de l'emplacement. Cette option affecte également "__builtin_FILE()" lors de la compilation. Voir aussi -ffile-prefix-map et -fcanon-prefix-map.
-fexec-charset=jeu_de_caracteres
Définit le jeu de caractères d'exécution, utilisé pour les constantes de chaînes et de caractères. La valeur par défaut est UTF-8. jeu_de_caracteres peut être n'importe quel encodage pris en charge par la fonction "iconv" de la bibliothèque système.
-fwide-exec-charset=jeu_de_caracteres
Définit le jeu de caractères d'exécution large, utilisé pour les constantes de chaînes et de caractères larges. La valeur par défaut est l'un de UTF-32BE, UTF-32LE, UTF-16BE ou UTF-16LE, celui qui correspond à la largeur de "wchar_t" et à l'ordre des octets big-endian ou little-endian utilisé pour la génération de code. Comme avec -fexec-charset, jeu_de_caracteres peut être n'importe quel encodage pris en charge par la fonction "iconv" de la bibliothèque système ; cependant, vous rencontrerez des problèmes avec les encodages qui ne correspondent pas exactement à "wchar_t".
-finput-charset=jeu_de_caracteres
Définit le jeu de caractères d'entrée, utilisé pour la traduction du jeu de caractères du fichier d'entrée vers le jeu de caractères source utilisé par G
CC. Si la locale ne le spécifie pas, ou si GCC ne peut pas obtenir cette information de la locale, la valeur par défaut est UTF-8. Ceci peut être remplacé par la locale ou par cette option de ligne de commande. Actuellement, l'option de ligne de commande a la priorité en cas de conflit. charset peut être n'importe quel encodage pris en charge par la routine de la bibliothèque "iconv" du système.
-fworking-directory
Active la génération de marqueurs de ligne dans la sortie du préprocesseur qui indiquent au compilateur le répertoire de travail courant au moment du prétraitement. Lorsque cette option est activée, le préprocesseur émet, après le marqueur de ligne initial, un second marqueur de ligne avec le répertoire de travail courant suivi de deux barres obliques. GCC utilise ce répertoire, lorsqu'il est présent dans l'entrée prétraitée, comme répertoire émis comme répertoire de travail courant dans certains formats d'informations de débogage. Cette option est implicitement activée si les informations de débogage sont activées, mais cela peut être empêché avec la forme niée -fno-working-directory. Si le drapeau -P est présent dans la ligne de commande, cette option n'a aucun effet, car aucune directive "#line" n'est émise du tout.
-A prédicat=réponse
Fait une assertion avec le prédicat prédicat et la réponse réponse. Cette forme est préférée à l'ancienne forme -A prédicat(réponse), qui est toujours prise en charge, car elle n'utilise pas de caractères spéciaux du shell.
-A -prédicat=réponse
Annule une assertion avec le prédicat prédicat et la réponse réponse.
-C
Ne pas supprimer les commentaires. Tous les commentaires sont transmis au fichier de sortie, à l'exception des commentaires dans les directives traitées, qui sont supprimés avec la directive.

Vous devez être préparé aux effets secondaires lorsque vous utilisez -C ; cela fait que le préprocesseur traite les commentaires comme des jetons à part entière. Par exemple, les commentaires apparaissant au début de ce qui serait une ligne de directive ont pour effet de transformer cette ligne en une ligne source ordinaire, car le premier jeton de la ligne n'est plus un #.

-CC
Ne pas supprimer les commentaires, y compris pendant l'expansion des macros. Ceci est similaire à -C, sauf que les commentaires contenus dans les macros sont également transmis au fichier de sortie où la macro est développée.

En plus des effets secondaires de l'option -C, l'option -CC convertit tous les commentaires de style C++ à l'intérieur d'une macro en commentaires de style C. Ceci afin d'éviter que l'utilisation ultérieure de cette macro ne commente par inadvertance le reste de la ligne source.

L'option -CC est généralement utilisée pour prendre en charge les commentaires lint.

-P
Empêche la génération de marqueurs de ligne dans la sortie du préprocesseur. Ceci peut être utile lors de l'exécution du préprocesseur sur quelque chose qui n'est pas du code C, et qui sera envoyé à un programme qui pourrait être confus par les marqueurs de ligne.
-traditional
-traditional-cpp
Essayer d'imiter le comportement des préprocesseurs C pré-standard, par opposition aux préprocesseurs C ISO.

Notez que GCC n'essaie pas autrement d'émuler un compilateur C pré-standard, et ces options ne sont prises en charge qu'avec le commutateur -E, ou lors de l'invocation explicite de CPP.

-trigraphs
Prend en charge les trigraphes C ISO. Ce sont des séquences de trois caractères, commençant toutes par ??, qui sont définies par C ISO pour représenter des caractères uniques. Par exemple, ??/ représente \, donc '??/n' est une constante de caractère pour une nouvelle ligne.

Par défaut, GCC ignore les trigraphes, mais dans les modes conformes aux normes, il les convertit. Voir les options -std et -ansi.

-remap
Active un code spécial pour contourner les systèmes de fichiers qui n'autorisent que des noms de fichiers très courts, comme MS-DOS.
-H
Imprime le nom de chaque fichier d'en-tête utilisé, en plus des autres activités normales. Chaque nom est indenté pour montrer à quel point il est profond dans la pile #include. Les fichiers d'en-tête précompilés sont également imprimés, même s'ils s'avèrent invalides ; un fichier d'en-tête précompilé invalide est imprimé avec ...x et un fichier valide avec ...! .
-dlettres
Indique de faire des dumps de débogage pendant la compilation comme spécifié par lettres. Les indicateurs documentés ici sont ceux pertinents pour le préprocesseur. D'autres lettres sont interprétées par le compilateur lui-même, ou réservées pour les futures versions de GCC, et sont donc silencieusement ignorées. Si vous spécifiez des lettres dont le comportement est conflictuel, le résultat est indéfini.
-dM
Au lieu de la sortie normale, génère une liste de directives #define pour toutes les macros définies pendant l'exécution du préprocesseur, y compris les macros prédéfinies. Cela vous permet de savoir ce qui est prédéfini dans votre version du préprocesseur. En supposant que vous n'avez pas de fichier foo.h, la commande 
touch foo.h; cpp -dM foo.h

affiche toutes les macros prédéfinies.

-dD
Semblable à -dM, sauf qu'il émet *à la fois* les directives #define et le résultat du prétraitement. Les deux types de sortie vont vers le fichier de sortie standard.
-dN
Semblable à -dD, mais n'émet que les noms des macros, pas leurs expansions.
-dI
Émet les directives #include en plus du résultat du prétraitement.
-dU
Semblable à -dD, sauf que seules les macros qui sont développées, ou dont la définission est testée dans les directives du préprocesseur, sont affichées ; la sortie est retardée jusqu'à l'utilisation ou le test de la macro ; et les directives #undef sont également affichées pour les macros testées mais non définies à ce moment-là.
-fdebug-cpp
Cette option n'est utile que pour le débogage de GCC. Lorsqu'elle est utilisée depuis CPP ou avec -E, elle affiche des informations de débogage sur les cartes d'emplacement. Chaque jeton dans la sortie est précédé du dump de la carte à laquelle son emplacement appartient.

Lorsqu'elle est utilisée depuis GCC sans -E, cette option n'a aucun effet.

-I rép
-iquote rép
-isystem rép
-idirafter rép
Ajoute le répertoire rép à la liste des répertoires à rechercher pour les fichiers d'en-tête pendant le prétraitement.

Si rép commence par = ou $SYSROOT, alors le = ou $SYSROOT est remplacé par le préfixe sysroot ; voir --sysroot et -isysroot.

Les répertoires spécifiés avec -iquote s'appliquent uniquement à la forme entre guillemets de la directive, "#include "fichier"". Les répertoires spécifiés avec -I, -isystem, ou -idirafter s'appliquent à la recherche des directives "#include "fichier"" et "#include <fichier>".

Vous pouvez spécifier n'importe quel nombre ou combinaison de ces options dans la ligne de commande pour rechercher des fichiers d'en-tête dans plusieurs répertoires. L'ordre de recherche est le suivant :

1.
Pour la forme entre guillemets de la directive include, le répertoire du fichier courant est recherché en premier.
2.
Pour la forme entre guillemets de la directive include, les répertoires spécifiés par les options -iquote sont recherchés dans l'ordre de gauche à droite, tels qu'ils apparaissent dans la ligne de commande.
3.
Les répertoires spécifiés par les options -I sont parcourus dans l'ordre de gauche à droite.
4.
Les répertoires spécifiés par les options -isystem sont parcourus dans l'ordre de gauche à droite.
5.
Les répertoires système standard sont parcourus.
6.
Les répertoires spécifiés par les options -idirafter sont parcourus dans l'ordre de gauche à droite.

Vous pouvez utiliser -I pour remplacer un fichier d'en-tête système, en lui substituant votre propre version, car ces répertoires sont recherchés avant les répertoires de fichiers d'en-tête système standard. Cependant, vous ne devez pas utiliser cette option pour ajouter des répertoires contenant des fichiers d'en-tête système fournis par le fournisseur ; utilisez -isystem pour cela.

Les options -isystem et -idirafter marquent également le répertoire comme un répertoire système, de sorte qu'il reçoive le même traitement spécial qui est appliqué aux répertoires système standard.

Si un répertoire d'inclusion système standard, ou un répertoire spécifié avec -isystem, est également spécifié avec -I, l'option -I est ignorée. Le répertoire est toujours recherché mais en tant que répertoire système à sa position normale dans la chaîne d'inclusion système. Ceci est fait pour garantir que la procédure de GCC pour corriger les fichiers d'en-tête système bogués et l'ordre pour la directive "#include_next" ne soient pas involontairement modifiés. Si vous avez vraiment besoin de changer l'ordre de recherche pour les répertoires système, utilisez les options -nostdinc et/ou -isystem.
