STRINGS(1) Outils de développement GNU STRINGS(1)

NOM

strings - affiche les séquences de caractères imprimables dans les fichiers

SYNOPSIS

strings [-afovV] [-longueur-min]
[-n longueur-min] [--bytes=longueur-min]
[-t base] [--radix=base]
[-e encodage] [--encoding=encodage]
[-U méthode] [--unicode=méthode]
[-] [--all] [--print-file-name]
[-T bfdname] [--target=bfdname]
[-w] [--include-all-whitespace]
[-s] [--output-separator sep_string]
[--help] [--version] fichier...

DESCRIPTION

Pour chaque fichier fourni, GNU strings affiche les séquences de caractères imprimables d'au moins 4 caractères de long (ou du nombre indiqué avec les options ci-dessous) et suivies d'un caractère non imprimable.

Selon la configuration du programme strings, il affichera par défaut soit toutes les séquences imprimables qu'il peut trouver dans chaque fichier, soit uniquement celles qui se trouvent dans des sections de données initialisées et chargeables. Si le type de fichier n'est pas reconnu, ou si strings lit depuis l'entrée standard, il affichera toujours toutes les séquences imprimables qu'il peut trouver.

Par compatibilité ascendante, tout fichier qui apparaît après une option de ligne de commande constituée uniquement de - sera également analysé intégralement, quelle que soit la présence de l'option -d .

strings est principalement utile pour déterminer le contenu des fichiers non textuels.

OPTIONS

-a
--all
-
Analyser le fichier entier, quelles que soient les sections qu'il contient et que ces sections soient chargées ou initialisées. Normalement, c'est le comportement par défaut, mais strings peut être configuré pour que -d soit le comportement par défaut à la place.

L'option - dépend de la position et force strings à effectuer des analyses complètes de tout fichier mentionné après le - sur la ligne de commande, même si l'option -d a été spécifiée.

-d
--data
Afficher uniquement les chaînes issues des sections de données initialisées et chargées du fichier. Cela peut réduire la quantité de données parasites dans la sortie, mais expose également le programme strings à toutes les failles de sécurité qui peuvent exister dans la bibliothèque BFD utilisée pour analyser et charger les sections. Strings peut être configuré pour que cette option soit le comportement par défaut. Dans ce cas, l'option -a peut être utilisée pour éviter d'utiliser la bibliothèque BFD et afficher à la place toutes les chaînes trouvées dans le fichier.
-f
--print-file-name
Afficher le nom du fichier avant chaque chaîne.
--help
Afficher un résumé de l'utilisation du programme sur la sortie standard et quitter.
-longueur-min
-n longueur-min
--bytes=longueur-min
Afficher les séquences de caractères affichables d'au moins longueur-min caractères de long. Si ce n'est pas spécifié, une longueur minimale par défaut de 4 est utilisée. La distinction entre caractères affichables et non affichables dépend du paramétrage des options -e et -U . Les séquences sont toujours terminées par des caractères de contrôle tels que le changement de ligne et le retour chariot, mais pas par le caractère de tabulation.
-o
Comme -t o. Certaines autres versions de strings font que -o se comporte comme -t d à la place. Puisque nous ne pouvons pas être compatibles avec les deux approches, nous en avons simplement choisi une.
-t base
--radix=base
Afficher le décalage dans le fichier avant chaque chaîne. L'argument d'un seul caractère spécifie la base du décalage---o pour l'octal, x pour l'hexadécimal, ou d pour le décimal.
-e encodage
--encoding=encodage
Sélectionner l'encodage des caractères des chaînes à trouver. Les valeurs possibles pour encodage sont : s = caractères sur un seul octet de 7 bits (par défaut), S = caractères sur un seul octet de 8 bits, b = 16 bits big-endian, l = 16 bits little-endian, B = 32 bits big-endian, L = 32 bits little-endian. Utile pour trouver des chaînes de caractères larges. (l et b s'appliquent, par exemple, aux encodages Unicode UTF-16/UCS-2).
-U [d|i|l|e|x|h]
--unicode=[default|invalid|locale|escape|hex|highlight]
Contrôle l'affichage des caractères multioctets encodés en UTF-8 dans les chaînes. Par défaut (--unicode=default), ils ne reçoivent aucun traitement particulier, et dépendent plutôt du paramétrage de l'option --encoding . Les autres valeurs pour cette option activent automatiquement --encoding=S.

L'option --unicode=invalid les traite comme des caractères non graphiques et donc non faisant partie d'une chaîne valide. Toutes les autres options les traitent comme des caractères de chaîne valides.

L'option --unicode=locale les affiche dans la locale courante, qui peut ou non prendre en charge l'encodage UTF-8. L'option --unicode=hex les affiche sous forme de séquences d'octets hexadécimaux encadrées par les caractères <> . L'option --unicode=escape les affiche sous forme de séquences d'échappement (\uxxxx) et l'option --unicode=highlight les affiche sous forme de séquences d'échappement surlignées en rouge (si pris en charge par le périphérique de sortie). La coloration vise à attirer l'attention sur la présence de séquences unicode là où on ne s'y attendrait pas.

-T bfdname
--target=bfdname
Spécifier un format de code objet autre que le format par défaut de votre système.
-v
-V
--version
Afficher le numéro de version du programme sur la sortie standard et quitter.
-w
--include-all-whitespace
Par défaut, les caractères de tabulation et d'espace sont inclus dans les chaînes affichées, mais les autres caractères d'espacement, tels que les changements de ligne et les retours chariot, ne le sont pas. L'option -w modifie cela pour que tous les caractères d'espacement soient considérés comme faisant partie d'une chaîne.
-s
--output-separator
Par défaut, les chaînes de sortie sont délimitées par un changement de ligne. Cette option permet de fournir une chaîne quelconque à utiliser comme séparateur d'enregistrement de sortie. Utile avec --include-all-whitespace où les chaînes peuvent contenir des changements de ligne en interne.
@fichier
Lire les options de ligne de commande à partir de fichier. Les options lues sont insérées à la place de l'option originale @fichier . Si fichier n'existe pas ou ne peut pas être lu, l'option sera traitée littéralement et ne sera pas supprimée.

Les options dans fichier sont séparées par des caractères d'espacement. Un caractère d'espacement peut être inclus dans une option en entourant l'option entière de guillemets simples ou doubles. Tout caractère (y compris une barre oblique inverse) peut être inclus en préfixant le caractère à inclure d'une barre oblique inverse. Le fichier peut lui-même contenir des options @fichier supplémentaires ; toutes ces options seront traitées récursivement.
