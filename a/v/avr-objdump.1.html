DESCRIPTION

objdump affiche des informations sur un ou plusieurs fichiers objet. Les options permettent de contrôler quelles informations particulières afficher. Ces informations sont principalement utiles aux programmeurs qui travaillent sur les outils de compilation, par opposition aux programmeurs qui veulent simplement que leur programme compile et fonctionne.

objfile... sont les fichiers objet à examiner. Lorsque vous spécifiez des archives, objdump affiche des informations sur chacun des fichiers membres de l'archive.

OPTIONS

Les formes longues et courtes des options, présentées ici comme alternatives, sont équivalentes. Au moins une option de la liste -a,-d,-D,-e,-f,-g,-G,-h,-H,-p,-P,-r,-R,-s,-S,-t,-T,-V,-x doit être fournie.

-a
--archive-header
Si l'un des fichiers objfile est une archive, affiche les informations de l'en-tête de l'archive (d'un format similaire à ls -l). En plus des informations que vous pourriez lister avec ar tv, objdump -a affiche le format du fichier objet de chaque membre de l'archive.
--adjust-vma=offset
Lors de l'affichage des informations, ajoutez d'abord offset à toutes les adresses de section. C'est utile si les adresses de section ne correspondent pas à la table des symboles, ce qui peut arriver lorsqu'on place des sections à des adresses particulières en utilisant un format qui ne peut pas représenter les adresses de section, comme a.out.
-b bfdname
--target=bfdname
Spécifie que le format de code objet des fichiers objet est bfdname. Cette option peut ne pas être nécessaire ; objdump peut reconnaître automatiquement de nombreux formats.

Par exemple,

objdump -b oasys -m vax -h fu.o

affiche les informations résumées des en-têtes de section (-h) de fu.o, qui est explicitement identifié (-m) comme un fichier objet VAX au format produit par les compilateurs Oasys. Vous pouvez lister les formats disponibles avec l'option -i .

-C
--demangle[=style]
Décode (demangle) les noms de symboles de bas niveau en noms de haut niveau. En plus de supprimer tout underscore initial préfixé par le système, cela rend les noms de fonctions C++ lisibles. Les différents compilateurs ont différents styles de mangle. L'argument optionnel de style de dé-mangle peut être utilisé pour choisir un style de dé-mangle approprié pour votre compilateur.
--recurse-limit
--no-recurse-limit
--recursion-limit
--no-recursion-limit
Active ou désactive une limite sur la quantité de récursion effectuée lors du dé-mangle des chaînes. Comme les formats de mangle de noms permettent un niveau de récursion infini, il est possible de créer des chaînes dont le décodage épuisera l'espace de pile disponible sur la machine hôte, provoquant une faute de mémoire. La limite tente d'empêcher cela en restreignant la récursion à 2048 niveaux d'imbrication.

Par défaut, cette limite est activée, mais la désactiver peut être nécessaire pour dé-mangle des noms véritablement compliqués. Notez cependant que si la limite de récursion est désactivée, une épuisement de la pile est possible et tout rapport de bogue concernant un tel événement sera rejeté.

-g
--debugging
Affiche les informations de débogage. Cela tente d'analyser les informations de format de débogage STABS stockées dans le fichier et de les imprimer en utilisant une syntaxe semblable au C. Si aucun débogage STABS n'a été trouvé, cette option utilise l'option -W pour imprimer toute information DWARF dans le fichier.
-e
--debugging-tags
Comme -g, mais les informations sont générées dans un format compatible avec l'outil ctags.
-d
--disassemble
--disassemble=symbol
Affiche les mnémoniques assembleur pour les instructions machine du fichier d'entrée. Cette option ne désassemble que les sections censées contenir des instructions. Si l'argument optionnel symbol est fourni, alors affiche les mnémoniques assembleur à partir de symbol. Si symbol est un nom de fonction, alors la désassemblage s'arrêtera à la fin de la fonction, sinon il s'arrêtera lorsqu'un autre symbole est rencontré. S'il n'y a pas de correspondance pour symbol , alors rien ne sera affiché.

Notez que si l'option --dwarf=follow-links est activée, alors tous les symboles dans les fichiers d'informations de débogage liés seront lus et utilisés lors de la désassemblage.

-D
--disassemble-all
Comme -d, mais désassembleble le contenu de toutes les sections non vides non bss, et pas seulement celles censées contenir des instructions. -j peut être utilisé pour sélectionner des sections spécifiques. Cette option a également un effet subtil sur le désassemblage des instructions dans les sections de code. Lorsque l'option -d

est active, objdump supposera que tous les symboles présents dans une section de code se trouvent à la frontière entre les instructions et refusera de désassembler à travers une telle frontière. Lorsque l'option -D est active, cependant, cette hypothèse est supprimée. Cela signifie qu'il est possible que la sortie de -d et -

D

code.

Si la cible est une architecture ARM, ce commutateur a également l'effet de forcer le désassembleur à décoder des morceaux de données trouvés dans les sections de code comme s'il s'agissait d'instructions. Notez que si l'option --dwarf=follow-lin

Active ou désactive l'utilisation de la coloration syntaxique dans le désassemblage sortie. Le comportement par défaut est déterminé par une option de configuration. Notez que toutes les architectures ne prennent pas en charge la coloration syntaxique, et selon le terminal utilisé, la sortie colorée peut ne pas être lisible.

L'argument on ajoute des couleurs à l'aide de couleurs de terminal simples.

L'argument terminal fait de même, mais uniquement si le périphérique de sortie est un terminal.

L'argument off désactive le désassemblage coloré.

--dwarf-depth=n
Limite le déversement de la section .debug_info à n enfants. Ceci n'est utile qu'avec --debug-dump=info. La valeur par défaut est d'afficher toutes les DIE ; la valeur spéciale 0 pour n aura également cet effet.

Avec une valeur non nulle pour n, les DIE à ou en dessous du niveau n ne seront pas affichés. La plage pour n est basée sur zéro.

--dwarf-start=n
Affiche uniquement les DIE en commençant par le DIE numéroté n. Ceci n'est utile qu'avec --debug-dump=info.

Si cette option est spécifiée, elle supprimera l'affichage de toute information d'en-tête et de tous les DIE avant le DIE numéroté n. Seuls les frères et sœurs et les enfants du DIE spécifié seront affichés.

Cela peut être utilisé en conjonction avec --dwarf-depth.

--ctf-parent=member
Si la section CTF contient des types définis de manière ambiguë, elle sera constituée d'une archive de nombreux dictionnaires CTF, tous héritant d'un dictionnaire contenant les types non ambigus. Lors de l'examen des archives CTF créées par un éditeur de liens qui utilise le changeur de nom pour renommer le membre parent, --ctf-parent peut être utilisé pour spécifier le nom utilisé pour le parent.
--ctf-parent-section=section
Cette option vous permet de choisir une section complètement différente pour le dictionnaire parent CTF contenant les types non ambigus que pour les dictionnaires enfants contenant le reste ambigu. L'éditeur de liens n'émet pas d'objets ELF structurés de cette manière, mais certains éditeurs de liens tiers peuvent le faire. Il est également pratique d'inspecter le CTF écrit sous forme de plusieurs fichiers bruts pour les composer avec objcopy, qui peut les placer dans différentes sections ELF mais pas dans différents membres d'un même dictionnaire CTF.
