DESCRIPTION

L'utilitaire GNU objcopy copie le contenu d'un fichier objet vers un autre. objcopy utilise la bibliothèque GNU BFD pour lire et écrire les fichiers objet. Il peut écrire le fichier objet de destination dans un format différent de celui du fichier objet source. Le comportement exact de objcopy est contrôlé par les options de la ligne de commande. Notez que objcopy devrait pouvoir copier un fichier entièrement lié entre deux formats quelconques. Cependant, copier un fichier objet relocalisable entre deux formats quelconques peut ne pas fonctionner comme prévu.

objcopy crée des fichiers temporaires pour effectuer ses conversions et les supprime ensuite. objcopy utilise BFD pour effectuer tout son travail de conversion ; il a accès à tous les formats décrits dans BFD et est donc capable de reconnaître la plupart des formats sans qu'on le lui indique explicitement.

objcopy peut être utilisé pour générer des enregistrements S en utilisant une cible de sortie srec (par exemple, utilisez -O srec).

objcopy peut être utilisé pour générer un fichier binaire brut en utilisant une cible de sortie binary (par exemple, utilisez -O binary). Quand objcopy génère un fichier binaire brut, il produit essentiellement un dump mémoire du contenu du fichier objet d'entrée. Tous les symboles et les informations de relocalisation seront supprimés. Le dump mémoire commencera à l'adresse de chargement de la section la plus basse copiée dans le fichier de sortie.

Lors de la génération d'un enregistrement S ou d'un fichier binaire brut, il peut être utile d'utiliser -S pour supprimer les sections contenant des informations de débogage. Dans certains cas, -R sera utile pour supprimer les sections qui contiennent des informations dont le fichier binaire n'a pas besoin.

Note---objcopy n'est pas capable de changer l'endianness de ses fichiers d'entrée. Si le format d'entrée a une endianness (certains formats n'en ont pas), objcopy ne peut copier les entrées que vers des formats de fichier ayant la même endianness ou n'ayant pas d'endianness (par exemple, srec). (Cependant, voir l'option --reverse-bytes .)

OPTIONS

infile
outfile
Les fichiers d'entrée et de sortie, respectivement. Si vous ne spécifiez pas outfile, objcopy crée un fichier temporaire et renomme de manière destructive le résultat avec le nom de infile.
-I bfdname
--input-target=bfdname
Considérer le format objet du fichier source comme étant bfdname, au lieu d'essayer de le déduire.
-O bfdname
--output-target=bfdname
Écrire le fichier de sortie en utilisant le format objet bfdname.
-F bfdname
--target=bfdname
Utiliser bfdname comme format objet à la fois pour le fichier d'entrée et de sortie ; c'est-à-dire simplement transférer les données de la source vers la destination sans conversion.
-B bfdarch
--binary-architecture=bfdarch
Utile lors de la transformation d'un fichier d'entrée sans architecture en fichier objet. Dans ce cas, l'architecture de sortie peut être définie à bfdarch. Cette option sera ignorée si le fichier d'entrée a une bfdarchconnue. Vous pouvez accéder à ces données binaires à l'intérieur d'un programme en référençant les symboles spéciaux créés par le processus de conversion. Ces symboles sont appelés _binary_objfile_start, _binary_objfile_end et_binary__size. Par exemple, vous pouvez trantransformer un fichier image en fichier objet puis y accéder dans votre code à l'aide de ces symboles.
-j motif_de_section
--only-section=motif_de_section
Copier uniquement les sections indiquées du fichier d'entrée vers le fichier de sortie. Cette option peut être donnée plusieurs fois. Notez que l'utilisation inappropriée de cette option peut rendre le fichier de sortie inutilisable. Les caractères génériques sont acceptés dans motif_de_section.

Si le premier caractère de motif_de_section est le point d'exclamation (!), alors les sections correspondantes ne seront pas copiées, même si une utilisation antérieure de --only-section sur la même ligne de commande les aurait autrement copiées. Par exemple :

--only-section=.text.* --only-section=!.text.foo

copiera toutes les sections correspondant à '.text.*' mais pas la section '.text.foo'.

-R motif_de_section
--remove-section=motif_de_section
Supprimer toute section correspondant à motif_de_section du fichier de sortie. Cette option peut être donnée plusieurs fois. Notez que l'utilisation inappropriée de cette option peut rendre le fichier de sortie inutilisable. Les caractères génériques sont acceptés dans motif_de_section. L'utilisation combinée des options -j et -R entraîne un comportement indéfini.

Si le premier caractère de motif_de_section est le point d'exclamation (!), alors les sections correspondantes ne seront pas supprimées, même si une utilisation antérieure de --remove-section sur la même ligne de commande les aurait autrement supprimées. Par exemple :

--remove-section=.text.* --remove-section=!.text.foo

supprimera toutes les sections correspondant au motif '.text.*', mais ne supprimera pas la section '.text.foo'.

--keep-section=motif_de_section
Lors de la suppression de sections du fichier de sortie, conserver les sections qui correspondent à motif_de_section.
--remove-relocations=motif_de_section
Supprimer les rélocations non dynamiques du fichier de sortie pour toute section correspondant à motif_de_section. Cette option peut être donnée plusieurs fois. Notez que l'utilisation inappropriée de cette option peut rendre le fichier de sortie inutilisable, et qu'essayer de supprimer une section de rélocations dynamiques telle que .rela.plt d'un exécutable ou d'une bibliothèque partagée avec --remove-relocations=.plt ne fonctionnera pas. Les caractères génériques sont acceptés dans motif_de_section. Par exemple : 
--remove-relocations=.text.*

supprimera les rélocations de toutes les sections correspondant au motif '.text.*'.

Si le premier caractère de motif_de_section est le point d'exclamation (!), alors les sections correspondantes n'auront pas leurs rélocations supprimées, même si une utilisation antérieure de --remove-relocations sur la même ligne de commande aurait autrement causé la suppression des rélocations. Par exemple :

--remove-relocations=.text.* --remove-relocations=!.text.foo

supprimera toutes les rélocations des sections correspondant au motif '.text.*', mais ne supprimera pas les rélocations de la section '.text.foo'.

--strip-section-headers
Supprimer les en-têtes de section. Cette option est spécifique aux fichiers ELF. Implique --strip-all et --merge-notes.
-S
--strip-all
Ne pas copier les informations de rélocation et de symboles depuis le fichier source. Supprime également les sections de débogage.
-g
--strip-debug
Ne pas copier les symboles ou les sections de débogage depuis le fichier source.
--strip-unneeded
Supprimer tous les symboles qui ne sont pas nécessaires au traitement des rélocations, en plus des symboles et sections de débogage supprimés par --strip-debug.
-K nom_de_symbole
--keep-symbol=nom_de_symbole
Lors de la suppression des symboles, conserver le symbole nom_de_symbole même s'il serait normalement supprimé. Cette option peut être donnée plusieurs fois.
-N nom_de_symbole
--strip-symbol=nom_de_symbole
Ne pas copier le symbole nom_de_symbole depuis le fichier source. Cette option peut être donnée plusieurs fois.
--strip-unneeded-symbol=nom_de_symbole
Ne pas copier le symbole nom_de_symbole depuis le fichier source à moins qu'il ne soit nécessaire pour une rélocation. Cette option peut être donnée plusieurs fois.
-G nom_de_symbole
--keep-global-symbol=nom_de_symbole
Ne garder comme global que le symbole nom_de_symbole . Rendre tous les autres symboles locaux au fichier, afin qu'ils ne soient pas visibles de l'extérieur. Cette option peut être donnée plusieurs fois. Note : cette option ne peut pas être utilisée en conjonction avec les options --globalize-symbol ou --globalize-symbols .
--localize-hidden
Dans un objet ELF, marquer comme locaux tous les symboles ayant une visibilité cachée ou interne. Cette option s'applique en plus des options de localisation spécifiques aux symboles telles que -L.
-L nom_de_symbole
--localize-symbol=nom_de_symbole
Convertir un symbole global ou faible appelé nom_de_symbole en symbole local, afin qu'il ne soit pas visible de l'extérieur. Cette option peut être donnée plusieurs fois. Note : les symboles uniques ne sont pas convertis.
-W nom_de_symbole
--weaken-symbol=nom_de_symbole
Rendre le symbole nom_de_symbole faible. Cette option peut être donnée plus d'une fois.
--globalize-symbol=nom_de_symbole
Donner au symbole nom_de_symbole une portabilité globale afin qu'il soit visible en dehors du fichier dans lequel il est défini. Cette option peut être donnée plus d'une fois. Note : cette option ne peut pas être utilisée en conjonction avec les options -G ou --keep-global-symbol .
-w
--wildcard
Autoriser les expressions rationnelles dans les nom_de_symboles utilisés dans les autres options de ligne de commande. Les opérateurs point d'interrogation (?), astérisque (*), antislash (\) et crochets ([]) peuvent être utilisés n'importe où dans le nom du symbole. Si le premier caractère du nom du symbole est le point d'exclamation (!), alors le sens de l'option est inversé pour ce symbole. Par exemple : 
-w -W !foo -W fo*

ferait que objcopy rendrait faibles tous les symboles commençant par "fo" sauf le symbole "foo".

-x
--discard-all
Ne pas copier les symboles non globaux depuis le fichier source.
-X
--discard-locals
Ne pas copier les symboles locaux générés par le compilateur. (Ceux-ci commencent généralement par L ou ..)
-b octet
--byte=octet
Si l'entrelacement a été activé via l'option --interleave alors commencer la plage d'octets à conserver à partir du octetième octet. octet peut être dans la plage de 0 à largeur-1, où largeur est la valeur donnée par l'option --interleave .
-i [largeur]
--interleave[=largeur]
Copier uniquement une plage sur chaque largeur octets. (Les données d'en-tête ne sont pas affectées). Sélectionner quel octet dans la plage commence la copie avec l'option --byte . Sélectionner la largeur de la plage avec l'option --interleave-width .

Cette option est utile pour créer des fichiers à programmer dans une ROM. Elle est généralement utilisée avec une cible de sortie "srec" . Notez que objcopy se plaindra si vous ne spécifiez pas également l'option --byte .

La largeur d'entrelacement par défaut est 4, donc avec --byte défini à 0, objcopy copierait le premier octet sur quatre de l'entrée vers la sortie.

--interleave-width=largeur
Lorsqu'elle est utilisée avec l'option --interleave , copier largeur octets à la fois. Le début de la plage d'octets à copier est défini par l'option --byte , et l'étendue de la plage est définie avec l'option --interleave .

La valeur par défaut de cette option est 1. La valeur de largeur plus la valeur de octet définie par l'option --byte ne doit pas dépasser la largeur d'entrelacement définie par l'option --interleave .

Cette option peut être utilisée pour créer des images pour deux mémoires flash 16 bits entrelacées sur un bus 32 bits en passant -b 0 -i 4 --interleave-width=2 et -b 2 -i 4 --interleave-width=2 à deux objcopy commandes. Si l'entrée était '12345678', alors les sorties seraient respectivement '1256' et '3478'.

-p
--preserve-dates
Définir les dates d'accès et de modification du fichier de sortie pour qu'elles soient les mêmes que celles du fichier d'entrée.

Cette option copie également la date stockée dans l'en-tête d'un fichier au format PE, sauf si la variable d'environnement SOURCE_DATE_EPOCH est définie. Si elle est définie, alors cette variable sera utilisée comme date stockée dans l'en-tête, interprétée comme le nombre de secondes depuis l'époque Unix.

-D
--enable-deterministic-archives
Opérer en mode déterministe . Lors de la copie des membres d'archive et de l'écriture de l'index d'archive, utiliser zéro pour les UID, GID, horodatages et utiliser des modes de fichier cohérents pour tous les fichiers.

Si binutils a été configuré avec --enable-deterministic-archives, alors ce mode est activé par défaut. Il peut être désactivé avec l'option -U, ci-dessous.

-U
--disable-deterministic-archives
Ne pas fonctionner en mode déterministe. Ceci est l'inverse de l'option -D, ci-dessus : lors de la copie des membres d'archive et de l'écriture de l'index de l'archive, utiliser leurs valeurs réelles d'UID, GID, horodatage et mode de fichier.

Ceci est le comportement par défaut, sauf si binutils a été configuré avec --enable-deterministic-archives.

--debugging
Convertir les informations de débogage, si possible. Ce n'est pas le comportement par défaut car seuls certains formats de débogage sont pris en charge, et le processus de conversion peut être long.
--gap-fill val
Remplir les espaces entre les sections avec val. Cette opération s'applique à l'adresse de chargement (LMA) des sections. Cela se fait en augmentant la taille de la section avec l'adresse la plus basse, et en remplissant l'espace supplémentaire créé avec val.
--pad-to adresse
Rembourrer le fichier de sortie jusqu'à l'adresse de chargement adresse. Ceci est fait en augmentant la taille de la dernière section. L'espace supplémentaire est rempli avec la valeur spécifiée par --gap-fill (zéro par défaut).
--set-start val
Définir l'adresse de départ (également appelée adresse d'entrée) du nouveau fichier à val. Tous les formats de fichiers objets ne prennent pas en charge la définition de l'adresse de départ.
--change-start incr
--adjust-start incr
Modifier l'adresse de départ (également appelée adresse d'entrée) en ajoutant incr. Tous les formats de fichiers objets ne prennent pas en charge la définition de l'adresse de départ.
--change-addresses incr
--adjust-vma incr
Modifier les adresses VMA et LMA de toutes les sections, ainsi que l'adresse de départ, en ajoutant incr. Certains formats de fichiers objets ne permettent pas de modifier arbitrairement les adresses des sections. Notez que cela ne déplace pas les sections ; si le programme s'attend à ce que les sections soient chargées à une certaine adresse, et que cette option est utilisée pour modifier les sections de manière à ce qu'elles soient chargées à une adresse différente, le programme peut échouer.
--change-section-address sectionpattern{=,+,-}val
--adjust-section-vma sectionpattern{=,+,-}val
Définir ou modifier l'adresse VMA et l'adresse LMA de toute section correspondant à sectionpattern. Si = est utilisé, l'adresse de la section est définie à val. Sinon, val est ajouté ou soustrait de l'adresse de la section. Voir les commentaires sous --change-addresses, ci-dessus. Si sectionpattern ne correspond à aucune section dans le fichier d'entrée, un avertissement sera émis, sauf si --no-change-warnings est utilisé.
--change-section-lma sectionpattern{=,+,-}val
Définir ou modifier l'adresse LMA de toute section correspondant à sectionpattern. L'adresse LMA est l'adresse à laquelle la section sera chargée en mémoire lors du chargement du programme. Normalement, c'est la même que l'adresse VMA, qui est l'adresse de la section au moment de l'exécution du programme, mais sur certains systèmes, en particulier ceux où un programme est stocké dans une ROM, les deux peuvent être différentes. Si = est utilisé, l'adresse de la section est définie à val. Sinon, val est ajouté ou soustrait de l'adresse de la section. Voir les commentaires sous --change-addresses, ci-dessus. Si sectionpattern ne correspond à aucune section dans le fichier d'entrée, un avertissement sera émis, sauf si --no-change-warnings est utilisé.
--change-section-vma sectionpattern{=,+,-}val
Définir ou modifier l'adresse VMA de toute section correspondant à sectionpattern. L'adresse VMA est l'adresse à laquelle la section sera située une fois que le programme aura commencé à s'exécuter. Normalement, c'est la même que l'adresse LMA, qui est l'adresse à laquelle la section sera chargée en mémoire, mais sur certains systèmes, en particulier ceux où un programme est stocké dans une ROM, les deux peuvent être différentes. Si = est utilisé, l'adresse de la section est définie à val. Sinon, val est ajouté ou soustrait de l'adresse de la section. Voir les commentaires sous --change-addresses, ci-dessus. Si sectionpattern ne correspond à aucune section dans le fichier d'entrée, un avertissement sera émis, sauf si --no-change-warnings est utilisé.

Note - modifier la VMA des sections dans un binaire entièrement lié peut être dangereux car il peut y avoir du code qui s'attend à ce que les sections soient situées à leur ancienne adresse.

--change-warnings
--adjust-warnings
Si --change-section-address ou --change-section-lma ou --change-section-vma est utilisé, et que le modèle de section ne correspond à aucune section, émettre un avertissement. C'est le comportement par défaut.
--no-change-warnings
--no-adjust-warnings
Ne pas émettre d'avertissement si --change-section-address ou --adjust-section-lma ou --adjust-section-vma est utilisé, même si le modèle de section ne correspond à aucune section.
--set-section-flags sectionpattern=flags
Définir les drapeaux pour toute section correspondant à sectionpattern. L'argument flags est une chaîne de noms de drapeaux séparés par des virgules. Les noms reconnus sont alloc, contents, load, noload, readonly, code, data, rom, exclude, share, debug et large. Vous pouvez définir le drapeau contents pour une section qui n'a pas de contenu, mais il n'est pas pertinent de désactiver le drapeau contents d'une section qui a du contenu ; supprimez simplement la section à la place. Tous les drapeaux ne sont pas pertinents pour tous les formats de fichiers objets. En particulier, le drapeau share n'est pertinent que pour les fichiers au format COFF et pas pour les fichiers au format ELF. Le drapeau spécifique à ELF x86-64 large correspond à SHF_X86_64_LARGE.
--set-section-alignment sectionpattern=align
Définir l'alignement pour toute section correspondant à sectionpattern. align spécifie l'alignement en octets et doit être une puissance de deux, c'est-à-dire 1, 2, 4, 8....

Note - définir l'alignement d'une section n'alignera pas automatiquement ses adresses LMA ou VMA. Si celles-ci doivent également être modifiées, les options --change-section-lma et/ou --change-section-vma devraient être utilisées. Notez également que la modification des VMA peut poser des problèmes dans les binaires entièrement liés où il peut y avoir du code qui s'attend à ce que le contenu des sections soit situé à leur ancienne adresse.

--add-section sectionname=filename
Ajouter une nouvelle section nommée sectionname lors de la copie du fichier. Le contenu de la nouvelle section provient du fichier filename. La taille de la section sera la taille du fichier. Cette option ne fonctionne que sur les formats de fichiers qui peuvent prendre en charge des sections avec des noms arbitraires. Notez - il peut être nécessaire d'utiliser l'option --set-section-flags pour définir les attributs de la section nouvellement créée.
--dump-section sectionname=filename
Placer le contenu de la section nommée sectionname dans le fichier filename, en écrasant tout contenu qui aurait pu s'y trouver précédemment. Cette option est l'inverse de --add-section. Cette option est similaire à l'option --only-section sauf qu'elle ne crée pas de fichier formaté, elle déverse simplement le contenu sous forme de données binaires brutes, sans appliquer de relocations. L'option peut être spécifiée plusieurs fois.
--update-section sectionname=filename
Remplacer le contenu existant d'une section nommée sectionname par le contenu du fichier filename. La taille de la section sera ajustée à la taille du fichier. Les drapeaux de section pour sectionname resteront inchangés. Pour les fichiers au format ELF, le mappage section-segment restera également inchangé, ce qui n'est pas possible en utilisant --remove-section suivi de --add-section. L'option peut être spécifiée plusieurs fois.

Note - il est possible d'utiliser --rename-section et --update-section pour mettre à jour et renommer une section à partir d'une seule ligne de commande. Dans ce cas, passez le nom de section d'origine à --update-section, et les noms de section d'origine et nouveaux à --rename-section.

--add-symbol name=[section:]value[,flags]
Ajouter un nouveau symbole nommé name lors de la copie du fichier. Cette option peut être spécifiée plusieurs fois. Si la section est donnée, le symbole sera associé et relatif à cette section, sinon ce sera un symbole ABS. La spécification d'une section indéfinie entraînera une erreur fatale. Il n'y a pas de vérification de la valeur, elle sera prise telle que spécifiée. Les drapeaux de symbole peuvent être spécifiés et tous les drapeaux ne seront pas pertinents pour tous les formats de fichiers objets. Par défaut, le symbole sera global. Le drapeau spécial 'before=othersym' insérera le nouveau symbole avant le othersym spécifié, sinon le(s) symbole(s) sera(ont) ajouté(s) à la fin de la table des symboles dans l'ordre où ils apparaissent.
--rename-section oldname=newname[,flags]
Renommer une section de oldname à newname, en modifiant éventuellement les drapeaux de la section à flags dans le processus. Ceci présente l'avantage par rapport à l'utilisation d'un script linker pour effectuer le renommage par le fait que le ou
tput reste un fichier objet et ne devient pas un exécutable lié. Cette option accepte le même ensemble de drapeaux que l' --set-section-flags option. Cette option est particulièrement utile lorsque le format d'entrée est binaire, car cela créera toujours une section appelée .data. Si par exemple, vous vouliez plutôt créer une section appelée .rodata contenant des données binaires, vous pourriez utiliser la ligne de commande suivante pour y parvenir : objcopy -I binary -O <output_format> -B <architecture> \ --rename-section .data=.rodata,alloc,load,readonly,data,contents \ <input_binary_file> <output_object_file> --long-section-names {enable,disable,keep} Contrôle le traitement des noms de sections longs lors du traitement des "COFF" et

"PE-COFF

" 
formats d'objets. Le
comportement par défaut, [[11]] keep

--keep-section-symbols
Lors du dédouanage d'un fichier, peut-être avec --strip-debug ou --strip-unneeded, conserver tous les symboles spécifiant des noms de sections, qui seraient autrement supprimés.
--keep-file-symbols
Lors du dédouanage d'un fichier, peut-être avec --strip-debug ou --strip-unneeded, conserver tous les symboles spécifiant des noms de fichiers source, qui seraient autrement supprimés.
--only-keep-debug
Dédouaner un fichier, en supprimant le contenu des sections qui ne seraient pas dédouanées par --strip-debug et en laissant les sections de débogage intactes. Dans les fichiers ELF, cela préserve toutes les sections de notes dans la sortie.

Remarque - les en-têtes des sections dédouanées sont préservés, y compris leurs tailles, mais le contenu de la section est rejeté. Les en-têtes de section sont préservés afin que d'autres outils puissent faire correspondre le fichier debuginfo avec l'exécutable réel, même si cet exécutable a été relocalisé dans un espace d'adressage différent.

L'intention est que cette option soit utilisée en conjonction avec --add-gnu-debuglink pour créer un exécutable en deux parties. Un binaire dédouané qui occupera moins d'espace en RAM et dans une distribution, et deuxièmement un fichier d'informations de débogage qui n'est nécessaire que si des capacités de débogage sont requises. La procédure suggérée pour créer ces fichiers est la suivante :

1.<Liez l'exécutable normalement. En supposant qu'il est appelé>
"foo" alors...
1.<Exécutez "objcopy --only-keep-debug foo foo.dbg" pour>
créer un fichier contenant les informations de débogage.
1.<Exécutez "objcopy --strip-debug foo" pour créer un>
exécutable dédouané.
1.<Exécutez "objcopy --add-gnu-debuglink=foo.dbg foo">
pour ajouter un lien vers les informations de débogage dans l'exécutable dédouané.

Remarque---le choix de ".dbg" comme extension pour le fichier d'informations de débogage est arbitraire. De plus, l'étape "--only-keep-debug" est facultative. Vous pourriez plutôt faire ceci :

1.<Liez l'exécutable normalement.>
1.<Copiez "foo" vers "foo.full">
1.<Exécutez "objcopy --strip-debug foo">
1.<Exécutez "objcopy --add-gnu-debuglink=foo.full foo">

c.-à-d., le fichier vers lequel pointe --add-gnu-debuglink peut être l'exécutable complet. Il n'a pas besoin d'être un fichier créé par le --only-keep-debug commutateur.

Remarque---ce commutateur n'est destiné qu'à être utilisé sur des fichiers entièrement liés. Cela n'a pas de sens de l'utiliser sur des fichiers objets où les informations de débogage peuvent être incomplètes. De plus, la fonctionnalité gnu_debuglink actuellement ne prend en charge que la présence d'un nom de fichier contenant des informations de débogage, et non plusieurs noms de fichier, un par fichier objet.
