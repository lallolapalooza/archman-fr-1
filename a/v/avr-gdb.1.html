NAME

avr-gdb - The GNU Project Debugger

SYNOPSIS

gdb [options] [program [args ...]]
gdb [options] [program core]
gdb [options] --pid=pid
gdb [options] --attach=pid [progargs ...]
gdb [options] --pid=pid --program-args progargs [progargs ...]

DESCRIPTION

This manual describes how to use gdb, the GNU Source-Level Debugger.

The purpose of a source-level debugger is to allow you to see what is happening inside your program while it executes or what the state of your program was when, for example, it terminated abnormally.

gdb can do four things:

  • Start your program, specifying anything that might affect its behavior
  • Allow you to examine what happened, when your program has finished running because of some event
  • Allow you to examine the state of the program while it is running under the control of gdb
  • Allow you to change your program to overcome the effects of some buggy section and then continue running to test a fix.

To do these things, gdb needs to know about your program's source code.

OPTIONS

--batch
Run in batch mode. GDB will process commands from a script file (or standard input if none is specified) and then exit. This is useful for automated debugging, error checking, or regression tests. When running in batch mode, GDB does not try to initialize the debugger's screen modes, nor does it try to read commands from the user's terminal. If you specify a command file, gdb will exit after executing all commands in the file. If you do not specify a command file, gdb will continue to read commands from standard input until it sees an EOF character.

The message Program exited normally. (which is ordinarily issued whenever a program running under GDB control terminates) is not issued when running in batch mode.

--batch-silent
Run in batch mode, just like --batch, but totally silent. All GDB output is suppressed (stderr is unaffected). This is much quieter than --silent and would be useless for an interactive session.

This is particularly useful when using targets that give Loading section messages, for example.

Note that targets that give their output via GDB, as opposed to writing directly to "stdout", will also be made silent.

--args prog [arglist]
Change interpretation of command line so that arguments following this option are passed as arguments to the inferior. As an example, take the following command: 
gdb ./a.out -q
It would start GDB with -q, not printing the introductory message. On the other hand, using: 
gdb --args ./a.out -q
starts GDB with the introductory message, and passes the option to the inferior.
--pid=pid
Attach GDB to an already running program, with the PID pid.
--tui
Open the terminal user interface.
--readnow
Read all symbols from the given symfile on the first access.
--readnever
Do not read symbol files.
--return-child-result
GDB's exit code will be the same as the child's exit code.
--configuration
Print details about GDB configuration and then exit.
--version
Print version information and then exit.
--cd=directory
Run GDB using directory as its working directory, instead of the current directory.
--data-directory=directory
-D
Run GDB using directory as its data directory. The data directory is where GDB searches for its auxiliary files.
--fullname
-f
Emacs sets this option when it runs GDB as a subprocess. It tells GDB to output the full file name and line number in a standard, recognizable fashion each time a stack frame is displayed (which includes each time the program stops). This recognizable format looks like two \032 characters, followed by the file name, line number and character position separated by colons, and a newline. The Emacs-to-GDB interface program uses the two \032 characters as a signal to display the source code for the frame.
-b baudrate
Set the line speed (baud rate or bits per second) of any serial interface used by GDB for remote debugging.
-l timeout
Set timeout, in seconds, for remote debugging.
--tty=device
Run using device for your program's standard input and output.

ENVIRONMENT

SEE ALSO

The full documentation for GDB is maintained as a Texinfo manual. If the "info" and "gdb" programs and GDB's Texinfo documentation are properly installed at your site, the command

info gdb

should give you access to the complete manual.

Using GDB: A Guide to the GNU Source-Level Debugger, Richard M. Stallman and Roland H. Pesch, July 1991.

NOM

avr-gdb - Le débogueur du projet GNU

SYNTAXE

gdb [options] [programme [args ...]]
gdb [options] [programme core]
gdb [options] --pid=pid
gdb [options] --attach=pid [progargs ...]
gdb [options] --pid=pid --program-args progargs [progargs ...]

DESCRIPTION

Ce manuel décrit comment utiliser gdb, le débogueur de niveau source du projet GNU.

Le but d'un débogueur de niveau source est de vous permettre de voir ce qui se passe à l'intérieur de votre programme pendant son exécution ou quel était l'état de votre programme lorsque, par exemple, il s'est terminé anormalement.

gdb peut faire quatre choses :

  • Démarrer votre programme, en spécifiant tout ce qui pourrait affecter son comportement
  • Vous permettre d'examiner ce qui s'est passé, une fois que votre programme a terminé son exécution à cause d'un événement
  • Vous permettre d'examiner l'état du programme pendant qu'il s'exécute sous le contrôle de gdb
  • Vous permettre de modifier votre programme pour surmonter les effets d'une section défectueuse et continuer ensuite l'exécution pour tester une correction.

Pour faire ces choses, gdb a besoin de connaître le code source de votre programme.

OPTIONS

--batch
Exécuter en mode batch. GDB traitera les commandes d'un fichier script (ou de l'entrée standard si aucun n'est spécifié) puis se terminera. Ceci est utile pour le débogage automatisé, la vérification d'erreurs ou les tests de régression. En mode batch, GDB n'essaie pas d'initialiser les modes d'écran du débogueur, ni de lire les commandes depuis le terminal de l'utilisateur. Si vous spécifiez un fichier de commandes, gdb se terminera après avoir exécuté toutes les commandes du fichier. Si vous ne spécifiez pas de fichier de commandes, gdb continuera à lire les commandes depuis l'entrée standard jusqu'à ce qu'il rencontre un caractère EOF.

Le message Program exited normally. (qui est normalement émis chaque fois qu'un programme exécuté sous le contrôle de GDB se termine) n'est pas émis lors de l'exécution en mode batch.

--batch-silent
Exécuter en mode batch, tout comme --batch, mais totalement silencieux. Toute sortie de GDB est supprimée (stderr n'est pas affecté). Ceci est beaucoup plus discret que --silent et serait inutile pour une session interactive.

Ceci est particulièrement utile lorsque vous utilisez des cibles qui affichent des messages du type Loading section, par exemple.

Notez que les cibles qui donnent leur sortie via GDB, par opposition à l'écriture directe sur "stdout", seront également rendues silencieuses.

--args prog [arglist]
Modifier l'interprétation de la ligne de commande de sorte que les arguments suivant cette option soient passés comme arguments à l'inférieur. Par exemple, prenez la commande suivante : 
gdb ./a.out -q
Elle démarrerait GDB avec -q, sans afficher le message d'introduction. D'un autre côté, en utilisant : 
gdb --args ./a.out -q
démarrerait GDB avec le message d'introduction, et passerait l'option à l'inférieur.
--pid=pid
Attacher GDB à un programme déjà en cours d'exécution, avec le PID pid.
--tui
Ouvrir l'interface utilisateur du terminal.
--readnow
Lire tous les symboles du fichier de symboles donné lors du premier accès.
--readnever
Ne pas lire les fichiers de symboles.
--return-child-result
Le code de sortie de GDB sera le même que le code de sortie de l'enfant.
--configuration
Afficher les détails sur la configuration de GDB puis quitter.
--version
Afficher les informations de version puis quitter.
--cd=directory
Exécuter GDB en utilisant directory comme répertoire de travail, au lieu du répertoire courant.
--data-directory=directory
-D
Exécuter GDB en utilisant directory comme répertoire de données. Le répertoire de données est l'endroit où GDB recherche ses fichiers auxiliaires.
--fullname
-f
Emacs définit cette option lorsqu'il exécute GDB en tant que sous-processus. Elle indique à GDB de sortir le nom de fichier complet et le numéro de ligne dans un format standard reconnaissable chaque fois qu'un cadre de pile est affiché (ce qui inclut chaque arrêt du programme). Ce format reconnaissable ressemble à deux caractères \032, suivis du nom du fichier, du numéro de ligne et de la position du caractère séparés par des deux-points, et une nouvelle ligne. Le programme d'interface Emacs vers GDB utilise les deux caractères \032 comme signal pour afficher le code source du cadre.
-b baudrate
Définir la vitesse de ligne (débit en bauds ou bits par seconde) de toute interface série utilisée par GDB pour le débogage à distance.
-l timeout
Définir le délai d'attente, en secondes, pour le débogage à distance.
--tty=device
Exécuter en utilisant device pour l'entrée et la sortie standard de votre programme.
