NOM

avahi-daemon - Le démon mDNS/DNS-SD d'Avahi

SYNTAXE

avahi-daemon [options]

avahi-daemon --kill

avahi-daemon --reload

avahi-daemon --check

DESCRIPTION

Le démon mDNS/DNS-SD d'Avahi implémente l'architecture Zeroconf d'Apple (également connue sous le nom de "Rendezvous" ou "Bonjour"). Le démon enregistre les adresses IP locales et les services statiques en utilisant mDNS/DNS-SD et fournit deux API IPC (communication inter-processus) pour que les programmes locaux utilisent le cache d'enregistrements mDNS maintenu par avahi-daemon. Premièrement, il y a le soi-disant "protocole simple" qui est utilisé exclusivement par avahi-dnsconfd (un démon qui configure les serveurs DNS unicast en utilisant les informations de serveur publiées via mDNS) et nss-mdns (un plugin libc NSS, fournissant la résolution de noms via mDNS). Enfin, il y a l'interface D-Bus qui fournit une interface orientée objet riche aux applications compatibles D-Bus.

Au démarrage, avahi-daemon interprète son fichier de configuration /etc/avahi/avahi-daemon.conf et lit des fragments XML à partir de /etc/avahi/services/*.service qui peuvent définir des services DNS-SD statiques. Si vous activez publish-resolv-conf-dns-servers dans avahi-daemon.conf, le fichier /etc/resolv.conf sera également lu.

OPTIONS

-f | --file= FICHIER
Spécifie le fichier de configuration à lire. (par défaut : /etc/avahi/avahi-daemon.conf)
-D | --daemonize
Démonise après le démarrage. Implique --syslog.
-s | --syslog
Journalise dans syslog au lieu de STDERR. Impliqué par --daemonize.
--debug
Augmente la verbosité au niveau de débogage.
--no-rlimits
Ne pas appliquer les limites de ressources spécifiées dans le fichier de configuration. (Voir setrlimit(2) pour plus d'informations)
--no-drop-root
Ne pas abandonner les privilèges root après le démarrage et ne pas exiger que le démon soit démarré en tant que root. Nous recommandons de ne pas utiliser cette option.
--no-chroot
Ne pas chroot(2) le démon. Cette option n'est disponible que si le support chroot() est activé à la compilation.
--no-proc-title
Ne pas modifier le nom du processus pendant son exécution. Sauf si cette option est spécifiée, avahi-daemon reflétera son état actuel et le nom d'hôte sélectionné dans le titre du processus.
-k | --kill
Tuer un avahi-daemon déjà en cours d'exécution. (équivalent à envoyer un SIGTERM)
-r | --reload
Demander à un avahi-daemon déjà en cours d'exécution de relire /etc/resolv.conf (si vous avez activé publish-resolv-conf-dns-servers dans avahi-daemon.conf) et les fichiers de /etc/avahi/services/. Veuillez noter que cela ne rechargera pas /etc/avahi/avahi-daemon.conf. (équivalent à envoyer un SIGHUP)
-c | --check
Retourne 0 comme code de retour si avahi-daemon est déjà en cours d'exécution.
-h | --help
Afficher l'aide
-v | --version
Afficher les informations de version

FICHIERS

/etc/avahi/avahi-daemon.conf : le fichier de configuration par défaut pour avahi-daemon, voir avahi-daemon.conf(5) pour plus d'informations.

/etc/avahi/hosts : mappages de noms d'hôtes statiques supplémentaires à publier en mDNS, voir avahi.hosts(5) pour plus d'informations.

/etc/avahi/services/*.service : définitions de services statiques, voir avahi.service(5) pour plus d'informations.

SIGNaux

SIGINT, SIGTERM : avahi-daemon s'arrêtera. (Même que --kill).

SIGHUP : avahi-daemon relira les données des serveurs DNS unicast à partir de /etc/resolv.conf et les définitions de services statiques à partir de /etc/avahi/services/. (Même que --reload)

SIGUSR1 : avahi-daemon exportera les données des enregistrements de ressources locales et distantes mises en cache vers syslog.
