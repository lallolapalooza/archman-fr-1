NOM

ab - Outil de mesure de performance du serveur HTTP Apache

SYNOPSIS

ab [ -A auth-username:password ] [ -b windowsize ] [ -B local-address ] [ -c concurrency ] [ -C cookie-name=value ] [ -d ] [ -e csv-file ] [ -E client-certificate file ] [ -f protocol ] [ -g gnuplot-file ] [ -h ] [ -H custom-header ] [ -i ] [ -k ] [ -l ] [ -m HTTP-method ] [ -n requests ] [ -p POST-file ] [ -P proxy-auth-username:password ] [ -q ] [ -r ] [ -s timeout ] [ -S ] [ -t timelimit ] [ -T content-type ] [ -u PUT-file ] [ -v verbosity] [ -V ] [ -w ] [ -x <table>-attributes ] [ -X proxy[:port] ] [ -y <tr>-attributes ] [ -z <td>-attributes ] [ -Z ciphersuite ] [http[s]://]hostname[:port]/path

RÉSUMÉ

ab est un outil pour mesurer les performances de votre serveur Apache Hypertext Transfer Protocol (HTTP). Il est conçu pour vous donner une impression de la performance de votre installation Apache actuelle. Il vous montre en particulier combien de requêtes par seconde votre installation Apache est capable de servir.

OPTIONS

-A auth-username:password
Fournit des identifiants d'authentification BASIC au serveur. Le nom d'utilisateur et le mot de passe sont séparés par un seul : et envoyés sur le réseau encodés en base64. La chaîne est envoyée que le serveur en ait besoin ou non (c.-à-d., a envoyé un 401 authentification requise).
-b windowsize
Taille du tampon d'envoi/réception TCP, en octets.
-B local-address
Adresse à lier lors des connexions sortantes.
-c concurrency
Nombre de requêtes multiples à effectuer à la fois. Par défaut, une seule requête à la fois.
-C cookie-name=value
Ajoute une ligne Cookie: à la requête. L'argument est généralement sous la forme d'une paire name=value . Ce champ est répétable.
-d
N'affiche pas le « tableau des pourcentages servis dans XX [ms] ». (support hérité).
-e csv-file
Écrit un fichier de valeurs séparées par des virgules (CSV) qui contient pour chaque pourcentage (de 1 % à 100 %) le temps (en millisecondes) qu'il a fallu pour servir ce pourcentage des requêtes. C'est généralement plus utile que le fichier « gnuplot » ; car les résultats sont déjà « regroupés en classes ».
-E client-certificate-file
Lors de la connexion à un site SSL, utilise le certificat client fourni au format PEM pour s'authentifier auprès du serveur. Le fichier doit contenir le certificat client, suivi des certificats intermédiaires, suivi de la clé privée. Disponible dans 2.4.36 et versions ultérieures.
-f protocol
Spécifie le protocole SSL/TLS (SSL2, SSL3, TLS1, TLS1.1, TLS1.2 ou ALL). La prise en charge de TLS1.1 et TLS1.2 est disponible dans 2.4.4 et versions ultérieures.
-g gnuplot-file
Écrit toutes les valeurs mesurées dans un fichier « gnuplot » ou TSV (valeurs séparées par des tabulations). Ce fichier peut facilement être importé dans des logiciels comme Gnuplot, IDL, Mathematica, Igor ou même Excel. Les libellés se trouvent sur la première ligne du fichier.
-h
Affiche les informations d'utilisation.
-H custom-header
Ajoute des en-têtes supplémentaires à la requête. L'argument est généralement sous la forme d'une ligne d'en-tête valide, contenant une paire champ-valeur séparée par deux-points (c.-à-d., "Accept-Encoding: zip/zop;8bit").
-i
Effectue des requêtes HEAD au lieu de GET.
-k
Active la fonctionnalité HTTP KeepAlive, c.-à-d.effectue plusieurs requêtes au sein d'une même session HTTP. Par défaut, KeepAlive est désactivé.
-l
Ne signale pas d'erreurs si la longueur des réponses n'est pas constante. Cela peut être utile pour les pages dynamiques. Disponible dans 2.4.7 et versions ultérieures.
-m HTTP-method
Méthode HTTP personnalisée pour les requêtes. Disponible dans 2.4.10 et versions ultérieures.
-n requests
Nombre de requêtes à effectuer pour la session de mesure. Par défaut, une seule requête est effectuée, ce qui donne généralement des résultats de mesure non représentatifs.
-p POST-file
Fichier contenant les données à envoyer en POST. N'oubliez pas de définir également -T.
-P proxy-auth-username:password
Fournit des identifiants d'authentification BASIC à un proxy sur le chemin. Le nom d'utilisateur et le mot de passe sont séparés par un seul : et envoyés sur le réseau encodés en base64. La chaîne est envoyée que le proxy en ait besoin ou non (c.-à-d., a envoyé un 407 authentification proxy requise).
-q
Lors du traitement de plus de 150 requêtes, ab affiche un compteur de progression sur stderr environ tous les 10 % ou 100 requêtes. L'indicateur -q supprime ces messages.
-r
Ne pas quitter en cas d'erreurs de réception sur le socket.
-s timeout
Nombre maximal de secondes à attendre avant l'expiration du socket. Par défaut, 30 secondes. Disponible dans 2.4.4 et versions ultérieures.
-S
N'affiche pas les valeurs de médiane et d'écart type, et n'affiche pas les messages d'avertissement/erreur lorsque la moyenne et la médiane diffèrent d'un ou deux écarts types. Et affiche par défaut les valeurs min/avg/max. (support hérité).
-t timelimit
Nombre maximal de secondes à consacrer à la mesure. Cela implique un -n 50000 en interne. Utilisez ceci pour mesurer le serveur dans un temps total fixe. Par défaut, il n'y a pas de limite de temps.
-T content-type
En-tête content-type à utiliser pour les données POST/PUT, par ex. application/x-www-form-urlencoded. Par défaut, text/plain.
-u PUT-file
Fichier contenant les données à envoyer en PUT. N'oubliez pas de définir également -T.
-v verbosity
Définit le niveau de verbosité - 4 et supérieur affiche des informations sur les en-têtes, 3 et supérieur affiche les codes de réponse (404, 200, etc.), 2 et supérieur affiche les avertissements et les informations.
-V
Affiche le numéro de version et quitte.
-w
Affiche les résultats dans des tableaux HTML. Le tableau par défaut a deux colonnes de large, avec un fond blanc.
-x <table>-attributes
Chaîne à utiliser comme attributs pour <table>. Les attributs sont insérés <table ici >.
-X proxy[:port]
Utilise un serveur proxy pour les requêtes.
-y <tr>-attributes
Chaîne à utiliser comme attributs pour <tr>.
-z <td>-attributes
Chaîne à utiliser comme attributs pour <td>.
-Z ciphersuite
Spécifie la suite de chiffrement SSL/TLS (voir openssl ciphers)

SORTIE

La liste suivante décritles valeurs renvoyées par ab:

Logiciel du serveur
La valeur, le cas échéant, renvoyée dans l'en-tête server de la première réponse réussie. Cela inclut tous les caractères de l'en-tête à partir du début jusqu'au point où un caractère de valeur décimale 32 est détecté (notamment : une espace ou un CR/LF).
Nom d'hôte du serveur
Le nom DNS ou l'adresse IP indiqué sur la ligne de commande
Port du serveur
Le port auquel ab se connecte. Si aucun port n'est indiqué sur la ligne de commande, la valeur par défaut sera 80 pour http et 443 pour https.
Protocole SSL/TLS
Les paramètres de protocole négociés entre le client et le serveur. Cela ne sera affiché que si SSL est utilisé.
Chemin du document
L'URI de la requête analysé à partir de la chaîne de la ligne de commande.
Longueur du document
Il s'agit de la taille en octets du premier document renvoyé avec succès. Si la longueur du document change pendant le test, la réponse est considérée comme une erreur.
Niveau de concurrence
Le nombre de clients simultanés utilisés pendant le test
Temps écoulé pour les tests
Il s'agit du temps écoulé depuis le moment où la première connexion de socket est créée jusqu'au moment où la dernière réponse est reçue
Requêtes terminées
Le nombre de réponses réussies reçues
Requêtes échouées
Le nombre de requêtes considérées comme échouées. Si ce nombre est supérieur à zéro, une autre ligne sera affichée indiquant le nombre de requêtes ayant échoué en raison de la connexion, de la lecture, d'une longueur de contenu incorrecte ou d'exceptions.
Erreurs d'écriture
Le nombre d'erreurs survenues lors de l'écriture (pipe brisé).
Réponses non-2xx
Le nombre de réponses qui n'étaient pas dans la série 200 des codes de réponse. Si toutes les réponses étaient 200, ce champ n'est pas affiché.
Requêtes Keep-Alive
Le nombre de connexions ayant entraîné des requêtes Keep-Alive
Corps total envoyé
Si la configuration envoie des données dans le cadre du test, il s'agit du nombre total d'octets envoyés pendant les tests. Ce champ est omis si le test n'a pas inclus de corps à envoyer.
Total transféré
Le nombre total d'octets reçus du serveur. Ce nombre est essentiellement le nombre d'octets envoyés sur le réseau.
HTML transféré
Le nombre total d'octets de document reçus du serveur. Ce nombre exclut les octets reçus dans les en-têtes HTTP
Requêtes par seconde
Il s'agit du nombre de requêtes par seconde. Cette valeur est le résultat de la division du nombre de requêtes par le temps total écoulé
Temps par requête
Le temps moyen passé par requête. La première valeur est calculée avec la formule concurrency * timetaken * 1000 / done tandis que la seconde valeur est calculée avec la formule timetaken * 1000 / done
Débit de transfert
Le débit de transfert tel que calculé par la formule totalread / 1024 / timetaken

BOGUES

Il existe diverses buffers déclarées statiquement de longueur fixe. Combiné à l'analyse paresseuse des arguments de la ligne de commande, des en-têtes de réponse du serveur et d'autres entrées externes, cela pourrait vous poser problème.

Il n'implémente pas complètement HTTP/1.x ; n'accepte que certaines formes « attendues » de réponses. L'utilisation plutôt intensive de strstr(3) apparaît en tête du profil, ce qui pourrait indiquer un problème de performance ; c.-à-d., vous mesurerez les performances de ab plutôt que celles du serveur.
