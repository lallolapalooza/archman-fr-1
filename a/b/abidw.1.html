NOM

abidw - sérialiser l'ABI d'un fichier ELF

Cet outil utilise la bibliothèque libabigail pour analyser le binaire ainsi que ses informations de débogage associées. Voici son mode de fonctionnement général.

Libabigail dispose alors de capacités pour générer des représentations textuelles des corpus ABI, les comparer, analyser leurs changements et en rendre compte.

INVOCATION

abidw [options] [<chemin-vers-fichier-elf>]

OPTIONS

•
--abidiff
Charge l'ABI du binaire ELF donné en argument, la sauvegarde dans le format XML de libabigail dans un fichier temporaire ; lit l'ABI depuis le fichier XML temporaire et compare l'ABI qui a été lue avec l'ABI du binaire ELF donné en argument. Les ABI devraient être identiques. Si ce n'est pas le cas, le programme émet un diagnostic et se termine avec un code non nul.

Ceci est une option de débogage et de vérification de cohérence.

  • --abixml-version

    Affiche la version du format ABIXML émis par ce programme et quitte.

  • --add-binaries <bin1,bin2,...>

    Pour chacun des binaires séparés par des virgules donnés en argument à cette option, si le binaire est trouvé dans le répertoire spécifié par l'option --added-binaries-dir, alors charge le corpus ABI du binaire et l'ajoute à un ensemble de corpus ABI (appelé Groupe de Corpus ABI) composé du binaire désigné par l'Argument de abidw. Ce groupe de corpus est ensuite sérialisé.

  • --added-binaries-dir | --abd <chemin-répertoire>

    Cette option doit être utilisée conjointement avec l'option --add-binaries, l'option --follow-dependencies ou l'option --list-dependencies. Les binaires listés comme arguments de l'option --add-binaries ou étant des dépendances du binaire d'entrée dans le cas de l'option --follow-dependencies et trouvés dans le répertoire <chemin-répertoire> seront chargés comme corpus ABI et ajoutés à l'ensemble de corpus ABI (appelé groupe de corpus ABI) construit et sérialisé.

  • --allow-non-exported-interfaces

    En présence d'un binaire de taille "moyenne", cependant, on peut se permettre d'avoir libabigail analysant toutes les interfaces visibles en dehors de leur unité de traduction, en utilisant cette option.

  • --annotate
Commente la sortie ABIXML avec des commentaires au-dessus de la plupart des éléments. Les commentaires sont constitués de la forme imprimée des types, de la déclaration ou même des symboles ELF. Le but est de rendre la sortie ABIXML plus lisible par l'homme à des fins de débogage ou de documentation.
  • --btf
  • --check-alternate-debug-info <chemin-elf>

    Si les informations de débogage pour le fichier chemin-elf contiennent une référence à un fichier d'informations de débogage alternatives, abidw vérifie qu'il peut trouver ce fichier d'informations de débogage alternatives. Dans ce cas, il émet un message de succès significatif mentionnant le chemin complet vers le fichier d'informations de débogage alternatives trouvé. Sinon, il émet un code d'erreur.

  • --check-alternate-debug-info-base-name <chemin-elf>

    Comme --check-alternate-debug-info, mais dans le message de succès, ne mentionne que le nom de base du fichier d'informations de débogage ; pas son chemin complet.

  • --debug-abidiff
Identique à --abidiff mais en mode débogage. Dans ce mode, des messages d'erreur sont émis pour les types qui échouent à la canonisation des types.

Ceci est une option de débogage et de vérification de cohérence facultative. Pour l'activer, le paquet libabigail doit être configuré avec l'option --enable-debug-self-comparison.

  • --ctf
  • --debug-info-dir | -d <chemin-répertoire>

    Dans les cas où les informations de débogage pour chemin-vers-fichier-elf se trouvent dans un fichier séparé situé dans un endroit non standard, cela indique à abidw où rechercher ce fichier d'informations de débogage.

    Notez que chemin-répertoire doit pointer vers le répertoire racine sous lequel les informations de débogage sont organisées de manière arborescente. Sur les systèmes basés sur Red Hat, ce répertoire est généralement <racine>/usr/lib/debug.
