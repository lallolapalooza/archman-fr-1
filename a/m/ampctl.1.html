NOM

ampctl - contrôle les amplificateurs radio

SYNTAXE

ampctl [-hiIlLuV] [-m id] [-r périphérique] [-s débit] [-t char] [-C parm=val] [-v[-Z]] [commande|-]

DESCRIPTION

Contrôle les amplificateurs radio. ampctl accepte des commandes depuis la ligne de commande ainsi qu'en mode interactif si aucune n'est fournie en ligne de commande.

Gardez à l'esprit que Hamlib est un logiciel de niveau BÊTA. Bien que de nombreuses bibliothèques backend manquent de support complet des amplificateurs, les fonctions de base sont généralement bien prises en charge.

Veuillez signaler les bugs et fournir vos commentaires à l'adresse e-mail indiquée dans la section BUGS ci-dessous. Les correctifs et les améliorations de code envoyés à la même adresse sont les bienvenus.

OPTIONS

Ce programme suit la syntaxe habituelle des lignes de commande GNU. Les options courtes qui prennent un argument peuvent avoir la valeur qui suit immédiatement ou être séparées par un espace. Les options longues commençant par deux tirets (“-”) nécessitent un “=” entre l'option et tout argument.

Voici un résumé des options prises en charge :

-m, --model=id
Sélectionne le numéro de modèle de l'amplificateur.
Voir la liste des modèles (utilisez “ampctl -l”).
Note : ampctl (ou un logiciel tiers utilisant l'API C) utilisera le modèle d'amplificateur 2 pour NET ampctl (communication avec ampctld).
-r, --amp-file=périphérique
Utilise périphérique comme nom de fichier du port connecté à l'amplificateur.
Souvent un port série, mais peut être un adaptateur USB vers série. Typiquement /dev/ttyS0, /dev/ttyS1, /dev/ttyUSB0, etc. sous Linux, COM1, COM2, etc. sous MS Windows. Les versions BSD et Mac OS/X ont leurs propres désignations. Consultez la documentation de votre système.
-s, --serial-speed=débit
Définit la vitesse série à débit bauds.
Utilise la vitesse série maximale des capacités du backend d'amplificateur (définie par -m ci-dessus) comme défaut.
-t, --send-cmd-term=char
Change le caractère de terminaison pour le protocole texte lors de l'utilisation de la commande send_cmd.
La valeur par défaut est ASCII CR (‘0x0D’). Les caractères non imprimables ASCII peuvent être donnés comme le numéro ASCII au format hexadécimal précédé de “0x”. Vous pouvez passer une chaîne vide pour aucun caractère de terminaison. La chaîne “-1” indique à ampctl de passer au protocole binaire.
Par exemple, pour spécifier un terminateur de commande pour les commandes texte de style Kenwood, passez “-t ';'” à ampctl. Voir EXEMPLE ci-dessous.
-L, --show-conf
Liste tous les paramètres de configuration pour l'amplificateur défini avec -m ci-dessus.
-C, --set-conf=parm=val[,parm=val]
Définit un ou plusieurs paramètres de configuration de l'amplificateur, par exemple stop_bits=2.
Utilisez l'option -L ci-dessus pour obtenir une liste des paramètres de configuration pour un numéro de modèle donné.
-u, --dump-caps
Affiche les capacités de l'amplificateur défini avec -m ci-dessus et quitte.
-l, --list
Liste tous les numéros de modèles d'amplificateurs définis dans Hamlib et quitte.
La liste est triée par numéro de modèle.
Note : Sous Linux, la liste peut être parcourue en utilisant Shift-PageUp/Shift-PageDown, ou en utilisant les barres de défilement d'un terminal virtuel sous X ou la fenêtre de commande sous Windows. La sortie peut être redirigée vers more(1) ou less(1), par exemple “ampctl -l | more”.
-i, --read-history
Lit l'historique des commandes et arguments précédemment enregistré à partir d'un fichier (par défaut $HOME/.ampctl_history) pour la session en cours.
Disponible lorsque ampctl est compilé avec le support Readline (voir READLINE ci-dessous).
Note : Pour lire un fichier d'historique stocké dans un autre répertoire, définissez la variable d'environnement AMPCTL_HIST_DIR, par exemple “AMPCTL_HIST_DIR=~/tmp ampctl -i”. Lorsque AMPCTL_HIST_DIR n'est pas défini, la valeur de HOME est utilisée.
-I, --save-history
Écrit l'historique des commandes et arguments de la session actuelle (et des sessions précédentes, si l'option -i est donnée) dans un fichier (par défaut $HOME/.ampctl_history) à la fin de la session en cours.
Les commandes complètes avec leurs arguments sont enregistrées sur une seule ligne pour être rappelées et utilisées ou modifiées. Disponible lorsque ampctl est compilé avec le support Readline (voir READLINE ci-dessous).
Note : Pour écrire un fichier d'historique dans un autre répertoire, définissez la variable d'environnement AMPCTL_HIST_DIR, par exemple “AMPCTL_HIST_DIR=~/tmp ampctl -IRq. Lorsque AMPCTL_HIST_DIR n'est pas défini, la valeur de HOME est utilisée.
-v, --verbose
Définit le mode verbeux, cumulatif (voir DIAGNOSTICS ci-dessous).
-Z, --debug-time-stamps
Active les horodatages pour les messages de débogage.
À utiliser uniquement en combinaison avec l'option -v car elle ne génère aucune sortie seule.
-h, --help
Affiche un résumé de ces options et quitte.
-V, --version
Affiche la version de ampctl et quitte.
-
Arrête le traitement des options et lit les commandes depuis l'entrée standard.
Voir Entrée Standard ci-dessous.

Note : Certaines options peuvent ne pas être implémentées par un backend donné et renverront une erreur. Cela se produit très probablement avec les options --set-conf et --show-conf.

Veuillez noter que le backend pour l'amplificateur à contrôler, ou l'amplificateur lui-même, peut ne pas supporter certaines commandes. Dans ce cas, l'opération échouera avec un code d'erreur Hamlib.

COMMANDES

Les commandes peuvent être saisies soit sous forme de caractère unique, soit sous forme de nom de commande long. Les commandes ne sont pas précédées d'un tiret comme les options. Elles peuvent être tapées en mode interactif ou fournies comme argument(s) en mode interface ligne de commande. En mode interactif, les commandes et leurs arguments peuvent être saisis sur une seule ligne :


F 14250000

Comme la plupart des opérations Hamlib ont une méthode set (définir) et une méthode get (obtenir), une lettre majuscule sera souvent utilisée pour une méthode set tandis que la lettre minuscule correspondante fera référence à la méthode get. Chaque opération a également un nom long ; en mode interactif, préfixez une barre oblique inverse, ‘\’, pour entrer un nom de commande long.

Exemple : Utilisez “\dump_caps” pour voir quelles capacités cet amplificateur et ce backend supportent.

Note : Le backend de l'amplificateur à contrôler, ou l'amplificateur lui-même, peut ne pas supporter certaines commandes. Dans ce cas, l'opération échouera avec un message d'erreur Hamlib.

Un exemple simple utilisant des commandes enregistrées dans un fichier (le texte tapé est affiché en gras) :


$ cat <<.EOF. >cmds.txt
> # Fichier de commandes
> F 14
250000 > f > l PWRINPUT > l PWRFORWARD > l SWR > \dump_caps > .EOF. $ ampctl -m1 - <cmds.txt Amplifier command: # File of commands Amplifier command: F 14250000 Amplifier command: f Frequency(Hz): 14250000 Amplifier command: l PWRINPUT Level Value: 0 Amplifier command: l PWRFORWARD Level Value: 1499 Amplifier command: l SWR Level Value: 1.000000 Amplifier command: \dump_caps Caps dump for model: 1 Model name: Dummy Mfg name: Hamlib Backend version: 0.1 Backend copyright: LGPL Backend status: Alpha Amp type: Other Port type: None Write delay: 0mS, timeout 0mS, 0 retries Post Write delay: 0mS Has priv data: N Get level: SWR NH PF PWRINPUT PWRFORWARD PWRREFLECTED PWRPEAK FAULT Has Init: Y Has Cleanup: Y Has Open: Y Has Close: Y Can set Conf: N Can get Conf: N Can Reset: Y Can get Info: Y Overall backend warnings: 0 Amplifier command: $

ampctl Commandes

Un résumé des commandes est inclus ci-dessous (Dans le cas des commandes set, la chaîne de caractères en italique entre guillemets est remplacée par la valeur décrite. Dans le cas des commandes get, la chaîne de caractères en italique entre guillemets est le nom de la clé de la valeur retournée) :

Q|q, exit ampctl
Quitte ampctl en mode interactif.
Lorsque ampctl contrôle directement l'amplificateur, il ferme le backend de l'amplificateur et le port. Lorsque ampctl est connecté à ampctld (modèle d'amplificateur 2), la connexion TCP/IP à ampctld est fermée et ampctld reste en cours d'exécution, disponible pour une autre connexion réseau TCP/IP.
F, set_freq 'Fréquence'
Définit la 'Fréquence', en Hz.
La fréquence peut être une valeur flottante ou entière.
f, get_freq
Obtient la 'Fréquence', en Hz.
Retourne une valeur entière.
l, get_level 'Niveau'
Obtient la 'Valeur du niveau'.
Retourne la Valeur du niveau sous forme de flottant ou d'entier pour le jeton de Niveau donné.
Note : Passer un ‘?’ (requête) comme premier argument au lieu d'un jeton de Niveau retournera une liste d'espaces séparés des jetons de niveau get pris en charge par le backend de l'amplificateur. Utilisez ceci pour déterminer les niveaux pris en charge d'un backend d'amplificateur donné.
w, send_cmd 'Cmd'
Envoie une chaîne de commande brute à l'amplificateur.
Ceci est utile pour tester et déboguer les commandes et les réponses de l'amplificateur lors du développement d'un backend.
Pour les protocoles binaires, entrez les valeurs sous la forme \0xAA\0xBB. Attendez une 'Réponse' de l'amplificateur qui sera probablement un bloc binaire ou une chaîne ASCII en fonction du protocole de l'amplificateur (voir la documentation de contrôle informatique de votre amplificateur).
Le terminateur de commande, défini par l'option send-cmd-term ci-dessus, terminera chaque chaîne de commande envoyée à l'amplificateur. Ce caractère ne doit pas faire partie de la chaîne d'entrée.
dump_state
Retourne certaines informations d'état sur le backend de l'amplificateur.
1, dump_caps
Pas une vraie commande d'amplificateur à distance, elle se contente de vider les capacités, c'est-à-dire ce que le backend sait de ce modèle et ce qu'il peut faire.
TODO : Assurez-vous que ceci est dans un format cohérent afin qu'il puisse être lu dans un hash, un dictionnaire, etc. Rapports de bugs demandés.
Note : Cette commande produira de nombreuses lignes de sortie, alors soyez très prudent si vous utilisez un tableau de longueur fixe ! Par exemple, l'exécution de cette commande sur le backend Dummy génère un certain nombre de lignes de sortie texte.
_, get_info
Retourne des informations du backend de l'amplificateur.
R, reset 'Reset'
Effectue le 'Reset' de l'amplificateur.
Reset est une valeur entière : ‘0’ = Aucun, ‘1’ = Reset mémoire, ‘2’ = Reset défaut, ‘3’ = Reset amplificateur.
set_powerstat 'État de l'alimentation'
Définit l''État de l'alimentation'.
État de l'alimentation est une valeur entière : ‘0’ = Alimentation coupée, ‘1’ = Alimentation allumée, ‘2’ = Veille (entrer en veille), ‘4’ = Fonctionnement (sortir de veille).
get_powerstat
Obtient l''État de l'alimentation' comme dans set_powerstat ci-dessus.
Y, set_ant 'Antenne' 'Option'
Définit l''Antenne' et l''Option'.
Le numéro est le numéro d'antenne basé sur 1 (‘1’, ‘2’, ‘3’, ...).

1 = A/1
2 = B/2
3 = C/3

READLINE

Si les fichiers de développement de la bibliothèque Readline sont trouvés au moment de la configuration, ampctl sera construit conditionnellement avec le support Readline pour la saisie des commandes et des arguments. Les raccourcis clavier de Readline sont aux valeurs par défaut telles que décrites dans le manuel de Readline. ampctl définit le nom “ampctl” qui peut être utilisé dans les constructions d'initialisation conditionnelles dans le fichier d'initialisation de Readline ($HOME/.inputrc par défaut) pour des raccourcis clavier personnalisés uniques à ampctl.

L'historique des commandes est disponible avec le support Readline tel que décrit dans le manuel de l'historique Readline. Les chaînes de commande et d'arguments sont stockées sur une seule ligne, même lorsque les arguments sont demandés individuellement. Les commandes et les arguments ne sont pas validés et sont stockés tels qu'ils sont tapés, avec les valeurs séparées par un seul espace.

Normalement, l'historique de session n'est pas sauvegardé, cependant, l'utilisation des options -i/--read-history ou -I/--save-history au démarrage de ampctl entraînera la lecture de tout historique précédemment sauvegardé et/ou l'écriture de l'historique de la session actuelle et de toute session précédente (en supposant que les options -i et -I sont données ensemble) à la fermeture de ampctl. Chaque option est mutuellement exclusive, c'est-à-dire qu'elle peut être donnée séparément ou en combinaison. Ceci est utile pour sauvegarder un ensemble de commandes puis les lire plus tard, mais sans écrire l'historique modifié pour un ensemble cohérent de commandes de test en mode interactif, par exemple.

L'historique est stocké dans $HOME/.ampctl_history par défaut, bien que le répertoire de destination puisse être modifié en définissant la variable d'environnement AMPCTL_HIST_DIR. Lorsque AMPCTL_HIST_DIR est désactivée, la valeur de la variable d'environnement HOME est utilisée à la place. Seul le répertoire de destination peut être modifié pour le moment.

Si le support Readline n'est pas trouvé au moment de la configuration, le gestionnaire de commandes interne d'origine est utilisé. Readline n'est pas utilisé pour les commandes ampctl entrées sur la ligne de commande, que le support Readline soit intégré ou non.

Note : Le support Readline n'est pas inclus dans les versions binaires 32 ou 64 bits pour MS Windows fournies par le projet Hamlib. L'exécution de ampctl sous MS Windows dans l'interpréteur de commandes ‘cmd’ offre un historique des commandes de session, cependant, il n'est pas sauvegardé sur disque entre les sessions.

DIAGNOSTICS

L'option -v, --verbose permet différents niveaux de diagnostics à afficher sur stderr et correspondent à -v pour BUG, -vv pour ERR, -vvv pour WARN, -vvvv pour VERBOSE, ou -vvvvv pour TRACE.

Un niveau de verbosité donné est utile pour fournir les informations de débogage nécessaires à l'adresse e-mail ci-dessous. Par exemple, la sortie TRACE montre toutes les valeurs envoyées et reçues de l'amplificateur, ce qui est très utile pour le développement de bibliothèques de backend d'amplificateurs et peut être demandé par les développeurs.

STATUT DE SORTIE

ampctl se termine avec :

0
si toutes les opérations se sont déroulées normalement ;
1
s'il y a eu une option ou un argument de ligne de commande invalide ;
2
si une erreur a été retournée par Hamlib.

EXEMPLES

Démarrez ampctl pour un Elecraft KPA-1500 en utilisant un adaptateur USB vers série sous Linux en mode interactif :


$ ampctl -m 201 -r /dev/ttyUSB1

Démarrez ampctl pour un Elecraft KPA-1500 en utilisant COM1 sous MS Windows tout en générant une sortie TRACE vers stderr :


> ampctl -m 201 -r COM1 -vvvvv

Connectez-vous à un ampctld en cours d'exécution avec le modèle d'amplificateur 2 (“NET ampctl”) sur l'hôte local et spécifiez le port TCP, en réglant la fréquence et le mode :


$ ampctl -m 2 -r localhost:4531 F 7253500
