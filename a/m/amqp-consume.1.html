NOM

amqp-consume - Consommer des messages d'une file d'attente sur un serveur AMQP

SYNTAXE

amqp-consume [OPTION...] {commande} [args...]

DESCRIPTION

amqp-consume consomme des messages d'une file d'attente sur un serveur AMQP. Pour chaque message qui arrive, une commande de réception est exécutée, avec le corps du message fourni à celle-ci sur l'entrée standard.

amqp-consume peut consommer à partir d'une file d'attente existante, ou il peut en créer une nouvelle. Il peut éventuellement lier la file d'attente à un échange existant.

Par défaut, les messages seront consommés avec des acquittements explicites. Un message ne sera acquitté que si la commande de réception se termine avec succès (c'est-à-dire avec un code de sortie de zéro). Le mode AMQP « no ack » (alias mode auto-ack) peut être activé avec l'option -A.

OPTIONS

-q, --queue=nom de la file

Le nom de la file d'attente à partir de laquelle consommer les messages.

Si l'option --queue est omise, le serveur AMQP assignera un nom unique à la file d'attente, et ce nom assigné par le serveur sera affiché sur stderr ; ce cas implique qu'une file d'attente exclusive devrait être déclarée.

-e, --exchange=nom de l'échange

Spécifie qu'une file d'attente exclusive doit être déclarée et liée à l'échange donné. L'échange spécifié devrait déjà exister à moins que l'option --exchange-type ne soit utilisée pour demander la création d'un échange.

-r, --routing-key=clé de routage

La clé de routage pour la liaison. Si omise, une clé de routage vide est supposée.

-d, --declare

Force la déclaration d'une file d'attente exclusive, même si elle ne le serait pas autrement. C'est-à-dire, lorsqu'un nom de file d'attente est spécifié avec l'option --queue, mais qu'aucune liaison à un échange n'est demandée avec l'option --exchange. Note : cette option est obsolète et pourrait être supprimée dans une future version, utilisez l'option --exclusive pour déclarer explicitement une file d'attente exclusive.

-x, --exclusive

Les files d'attente déclarées sont non-exclusives par défaut, cette option force la déclaration de files d'attente exclusives.

-A, --no-ack=clé de routage

Active le mode « no ack » : le serveur AMQP acquittera inconditionnellement chaque message qui est délivré, indépendamment du fait que la commande cible se termine avec succès ou non.

-c, --count=limite

Arrête la consommation après que le nombre donné de messages ait été reçu.

-p, --prefetch-count=limite

Demande au serveur de n'envoyer que limite messages à la fois.

Si une valeur a été passée à --count, la valeur passée à --prefetch-count devrait être plus petite que celle-ci, sinon elle sera ignorée.

Si -A/--no-ack est passé, cette option n'a aucun effet.

EXEMPLES

Consommer des messages de la file d'attente existante « myqueue », et afficher les corps des messages sur la sortie standard via cat :

$ amqp-consume -q myqueue cat

Lier une nouvelle file d'attente exclusive à un échange « myexch », et envoyer chaque corps de message au script myscript, en les acquittant automatiquement sur le serveur :

$ amqp-consume -A -e myexch ./myscript
