NOM

amavisd-milter - milter sendmail pour amavis

SYNTAXE

amavisd-milter [-Bfhv] [-d niveau-debug] [-D transfert-par-procuration] [-m max-connexions] [-M max-attente] [-p fichier-pid] [-P] [-q file-dattente] [-s socket] [-t delai] [-S socket] [-T delai] [-w repertoire]

DESCRIPTION

Le amavisd-milter est un milter (filtre de courrier) sendmail pour amavis 2.4.3 et supérieur, et sendmail 8.13 et supérieur.

Avec le amavisd-milter, une fonctionnalité complète d'amavis est disponible, incluant l'ajout de champs d'en-tête d'information spam et virus, la modification de l'objet, l'ajout d'extensions d'adresse et la suppression de certains destinataires de la livraison, tout en livrant le même message au reste.

Pour plus d'informations, vous pouvez visiter le site web d'amavisd-milter :

https://github.com/prehor/amavisd-milter

Options

Les options sont les suivantes :

-B
Utilise la macro milter {daemon_name} comme nom de banque de politiques (voir BANQUES DE POLITIQUES ci-dessous).
-d niveau-debug
Définit le niveau de débogage. Les traces de débogage deviennent plus détaillées à mesure que le niveau de débogage augmente. Le maximum est 9.
-D transfert-par-procuration
Définit l'attribut de requête AM.PDP delivery_care_of à client (par défaut) ou server.

Lorsque la méthode client est utilisée, amavisd-milter est responsable de transférer le message aux destinataires. Cette méthode ne permet pas de modification personnalisée des en-têtes ou du corps.

Lorsque la méthode server est utilisée, amavis est responsable de transférer le message aux destinataires et peut personnaliser les en-têtes et le corps des messages. La variable $forward_method dans amavisd.conf doit pointer vers un endroit disposé à accepter le message sans vérification supplémentaire dans amavis.

-f
Exécute amavisd-milter au premier plan (c'est-à-dire qu'il ne se détache pas). Affiche les messages de débogage dans le terminal.
-h
Affiche la page d'aide et quitte.
-m max-connexions
Nombre maximum de connexions amavis simultanées (par défaut 0 = nombre illimité de connexions). Il doit être identique à la variable $max_servers dans amavisd.conf.
-M delai
Délai de traitement des messages en secondes (par défaut 300 secondes = 5 minutes). Doit être inférieur au délai de réponse au “.” qui termine un message sur le MTA d'envoi. Sendmail utilise une valeur par défaut d'1 heure, postfix 10 minutes et qmail 20 minutes. La valeur recommandée est inférieure à 10 minutes.

Si vous utilisez d'autres milters (surtout chronophages), le délai doit être suffisant pour traiter le message dans tous les milters.

-p fichier-pid
Utilise ce fichier pid.
-P
En cas d'échec d'amavis, le message sera transmis sans vérification.
-q file-dattente
Définit la file d'attente des sockets entrants utilisée par listen(2). Si elle n'est pas définie ou définie à zéro, la valeur par défaut du système d'exploitation est utilisée.
-s socket
Socket de communication entre sendmail et amavisd-milter. Le protocole utilisé sur ce socket est MILTER (Mail FILTER). Il doit avoir la même valeur que la macro INPUT_MAIL_FILTER dans sendmail.mc.

Le socket doit être au format proto:adresse :

•
{unix|local}:/chemin/vers/fichier - Un tube nommé.
•
inet:port@{hôte|adresse-ip} - Un socket IPV4.
•
inet6:port@{hôte|adresse-ip} - Un socket IPV6.
-S socket
Socket de communication entre amavisd-milter et amavis. Le protocole utilisé sur ce socket est AM.PDP (AMavis Policy Delegation Protocol). Il doit avoir la même valeur que la variable $unix_socketname dans amavisd.conf.

Le socket doit être au format proto:adresse :

•
{unix|local}:/chemin/vers/fichier - Un tube nommé.
•
inet:port@{hôte|adresse-ip} - Un socket IPV4.
•
inet6:port@{hôte|adresse-ip} - Un socket IPV6.
-t delai
Délai de connexion sendmail en secondes (par défaut 600 = 10 minutes). Il doit avoir la même valeur que la macro INPUT_MAIL_FILTER dans sendmail.mc et doit être supérieur ou égal au délai de connexion amavis.

Si vous utilisez d'autres milters (surtout chronophages), le délai doit être suffisant pour traiter le message dans tous les milters.

-T delai
Délai de connexion Amavis en secondes (par défaut 600 = 10 minutes). Doit être suffisant pour traiter le message dans amavis. Habituellement, il est conseillé de les définir à la même valeur que le délai de connexion sendmail.
-v
Affiche le numéro de version et quitte.
-w repertoire
Définit le répertoire de travail.

BANQUES DE POLITIQUES

Si l'option -B est activée, amavisd-milter utilise la valeur de la macro milter {daemon_name} comme nom de la banque de politiques amavis. Généralement, cette macro milter est définie avec le nom du MTA.

Lorsqu'un client distant est authentifié, amavisd-milter utilise les informations d'authentification comme nom des banques de politiques amavis :

SMTP_AUTH
Le client distant a été authentifié.
SMTP_AUTH_<MECH>
Le mécanisme d'authentification du client distant.
SMTP_AUTH_<MECH>_<BITS>
Le nombre de bits utilisés pour la clé du chiffrement symétrique lorsque le mécanisme d'authentification l'utilise.

EXEMPLES

Configuration d'amavis

Dans le fichier amavisd.conf, définissez le protocole et le socket amavis sur :

$protocol = "AM.PDP";                      # Utiliser le protocole AM.PDP
$unix_socketname = "$MYHOME/amavisd.sock"; # Écouter sur le socket Unix
### $inet_socket_port = 10024;             # Ne pas écouter sur le port TCP

Ensuite, redémarrez le démon amavisd.

Configuration de Postfix

Ajoutez les entrées suivantes à Postfix main.cf* :

smtpd_milters = local:<AMAVISD_MILTER.SOCK>
milter_connect_macros = j {client_name} {daemon_name} v
milter_protocol = 6

Ensuite, redémarrez le démon Postfix.

Configuration de sendmail

Ajoutez les entrées suivantes au fichier sendmail.mc :

define(`confMILTER_MACROS_CONNECT',
  confMILTER_MACROS_CONNECT`, {client_resolve}')
define(`confMILTER_MACROS_ENVFROM',
  confMILTER_MACROS_ENVFROM`, r, b')
INPUT_MAIL_FILTER(`amavisd-milter',
  `S=local:<AMAVISD_MILTER.SOCK>, F=T, T=S:10m;R:10m;E:10m')

Ensuite, reconstruisez le fichier sendmail.cf, installez-le et redémarrez le démon sendmail.

Exécution de amavisd-milter

Cet exemple suppose que amavis s'exécute en tant qu'utilisateur vscan. Le nom réel est indiqué dans la variable $daemon_user dans amavisd.conf.

Limiter le nombre maximal de connexions simultanées à amavisd

Pour limiter le nombre maximal de connexions simultanées à amavis, exécutez amavisd-milter avec les options suivantes :

su - vscan -c "amavisd-milter -m 4"

Dépannage

Pour le dépannage, exécutez amavisd-milter au premier plan et définissez le niveau de débogage à la valeur appropriée :

su - vscan -c "amavisd-milter -f -d 4"

Les niveaux de débogage sont :

•
1 - Pas des erreurs, mais des états inattendus (interruption de connexion, etc.).
•
2 - États principaux du traitement des messages.
•
3 - Tous les messages de débogage de amavisd-milter.
•
4-9 - Débogage de la communication milter (définir smfi_setdbg à 1-6).
