APERÇ

U

AppConfig::State est un module Perl5 pour gérer les variables de configuration globales des programmes Perl. Il maintient l'état d'un nombre quelconque de variables, gérant les valeurs par défaut, les alias, la validation, les rappels de mise à jour et les arguments d'option pour être utilisé par d'autres modules AppConfig::

*.

istribué dans le cadre
du paquet AppConfig.

UTILISATION DU MODULE AppConfig::

State

Pour importer et utiliser le module AppConfig::State, la ligne suivante doit apparaître dans votre script Perl

: 
use AppConfig::
State;

Le module AppConfig::State est chargé automatiquement par le constructeur new() du module

AppConfig.

AppConfig::State est implémenté à l'aide de méthodes orientées objet. Un nouvel objet AppConfig::State est créé et initialisé à l'aide de la méthode new(). Celle-ci renvoie une référence à un nouvel objet AppConfig::

State. 
my $state = AppConfig::State->new()
;

Cela créera une référence à un nouvel AppConfig::State avec toutes les options de configuration définies à leurs valeurs par défaut. Vous pouvez initialiser l'objet en passant une référence à un tableau associatif contenant les options de configuration

: 
$state = AppConfig::State->new( {
    CASE      => 1,
    ERROR     => \&my_error,
} )
;

Le constructeur new() du module AppConfig transmet automatiquement tous les paramètres au constructeur new() de AppConfig::State. Ainsi, toutes les valeurs de configuration globales et les définitions de variables pour AppConfig::State sont également applicables à

AppConfig.

Les options de configuration suivantes peuvent être

spécifiées.
CA
SE
Détermine si les noms de variables sont traités de manière sensible à la casse. Toute valeur non nulle rend la casse significative lors de la nommage des variables. Par défaut, CASE est défini à 0 et donc « Variable », « VARIABLE » et « VaRiAbLe » sont tous traités comme « variable
».
CREA
TE
Par défaut, CREATE est désactivé, ce qui signifie que toutes les variables accessibles via set() (ce qui inclut l'accès via des raccourcis tels que "$state->variable($value)" qui délègue à set()) doivent avoir été préalablement définies via define(). Lorsque CREATE est défini à 1, l'appel à set($variable, $value) sur une variable qui n'existe pas la fera créer automatiquement.

Lorsque CREATE est défini à toute autre valeur non nulle, on suppose qu'il s'agit d'un motif d'expression régulière. Si le nom de la variable correspond à l'expression régulière, la variable est créée. Cela peut être utilisé pour spécifier des blocs de fichier de configuration dans lesquels les variables doivent être créées,

par exemple : 
$state = AppConfig::State->new( {
    CREATE => '^define_',
} );

Dans un fichier de

configuration : 
[define]
name = fred           # define_name gets created automatically
[other]
name = john           # other_name doesn't - warning
raised

Notez qu'un motif d'expression régulière spécifié dans CREATE

est appliqué au vrai nom de la variable plutôt qu'à
un alias par lequel la variable peut être accessible.
PEDANT
IC
L'option PEDANTIC détermine l'action que le fichier de configuration (AppConfig::File) ou l'analyseur d'arguments (AppConfig::Args) doit entreprendre lorsqu'il rencontre une condition d'avertissement (généralement causée lors de la tentative de définir une variable non déclarée). Si PEDANTIC est défini à une valeur vraie, les méthodes d'analyse renverront immédiatement une valeur de 0 lorsqu'elles rencontreront une telle condition. Si PEDANTIC n'est pas défini, la méthode continuera d'analyser le reste du/des fichier(s) ou des arguments actuels, en renvoyant 0 une fois terminé.

Si aucun avertissement ou erreur n'est rencontré, la méthode renvoie

1.

Dans le cas d'une erreur système (par ex. impossible d

'ouvrir un fichier), la méthode renvoie immédia
tement undef, quelle que soit l'option PEDANTIC.
ERR
OR
Spécifie une routine de gestion d'erreurs définie par l'utilisateur. Lorsque le gestionnaire est appelé, une chaîne de format est passée en premier paramètre, suivie de toutes les valeurs supplémentaires, comme pour printf(3C)
.
DEB
UG
Active ou désactive le débogage lorsqu'il est défini à 1 ou 0 respectivement. Le débogage peut également être activé en appelant _debug() comme méthode d'objet ("$state->_debug(1)") ou comme fonction de paquet (AppConfig::State::_debug(1)), en passant une valeur vraie/fausse pour définir l'état du débogage en conséquence. La variable de paquet $AppConfig::State::DEBUG peut également être définie directement.

La méthode _debug() renvoie la valeur de débogage actuelle. Si une nouvelle valeur est passée, la valeur interne est mise à jour, mais la valeur précédente est

renvoyée.

Notez que tout objet AppConfig::File ou App::Config::Args instancié avec une référence à un Ap

p::State héritera des valeurs DEBUG (et aussi PEDANTIC) de l'état à ce moment-là. Les modifica
tions ultérieures de la valeur de débogage de AppConfig::State ne les affecteront pas.

AL
L'option GLOBAL permet de définir des valeurs par défaut pour les options DEFAULT, ARGCOUNT, EXPAND, VALIDATE et ACTION pour toutes les variables définies ultérieurement. 
$state = AppConfig::State->new({
    GLOBAL => {
        DEFAULT  => '<undef>',     # default value for new vars
        ARGCOUNT => 1,             # vars expect an argument
        ACTION   => \&my_set_var,  # callback when vars get set
} });

Tous les attributs spécifiés explicitement lors de la définition d'une variable remplaceront toutes les valeurs

VARIABLES

La fonction define() est utilisée pour pré-déclarer une variable et spécifier sa

configuration. 
$state->define("foo")
;

Dans l'exemple simple ci-dessus, une nouvelle variable appelée « foo » est définie. Une référence à un tableau associatif peut également être passée pour spécifier les informations de configuration de la variable

$state->define("foo", {
        DEFAULT   => 99,
        ALIAS     => 'metavar1',
    })
;

Toutes les valeurs GLOBAL s'appliquant à l'ensemble des variables passées au constructeur new() dans le hachage de configuration seront également appliquées. Les valeurs explicitement spécifiées dans la configuration define() d'une variable remplaceront les valeurs GLOBAL

respectives.

VALIDA
TE
Chaque variable peut avoir une sous-routine ou une expression régulière définie qui est utilisée pour valider la valeur prévue pour une variable avant qu'elle ne soit définie.

Si VALIDATE est défini comme une expression régulière, il est appliqué à la valeur et est considéré comme valide si le motif correspond. Dans ce cas, la variable est ensuite définie à la nouvelle valeur. Un message d'avertissement est généré si la correspondance du motif

échoue.

VALIDATE peut également être défini comme une référence à une sous-routine qui prend comme arguments le nom de la variable et sa valeur prévue. La sous-routine doit retourner 1 ou 0 pour indiquer que la valeur est valide ou invalide, respectivement. Une valeur invalide causera la génération d'un message

d'avertissement.

Si la variable VALIDATE GLOBALE est définie (voir GLOBAL dans DESCRIPTION ci-dessus) alors cette valeur sera utilisée comme VALIDATE par défaut pour chaque variable sauf indication

contraire. 
$state->define("age", {
        VALIDATE => '\d+',
    });
$state->define("pin", {
        VALIDATE => \&check_pin,
});
ACTI
ON
L'option ACTION permet de lier une sous-routine à une variable en tant que rappel qui est exécuté chaque fois que la variable est définie. L'ACTION reçoit une référence à l'objet AppConfig::State, le nom de la variable et la valeur de la variable.

La routine ACTION peut être utilisée, par exemple, pour post-traiter les données de la variable, mettre à jour la valeur d'une autre variable dépendante, générer un message d'avertissement,

etc.

Exemple

: 
$state->define("foo", { ACTION => \&my_notify });
sub my_notify {
    my $state = shift;
    my $var   = shift;
    my $val   = shift;
    print "$variable set to $value";
}
$state->foo(42);        # prints "foo set
to 42"

Soyez conscient que l'appel à "$state->set()" pour mettre à jour la même variable

depuis la fonction ACTION ca
usera une boucle récursive car
la fonction ACTION es
t appelée de manière répétée.

DÉFINITION DES VARIABLES UTILISANT LE FORMAT

COMPACT

Les variables peuvent être définies dans un format compact qui permet à n'importe quels valeurs ALIAS et ARGS d'être spécifiées comme partie du nom de la variable. Ceci est conçu pour imiter le comportement du module Getopt::Long de Johan

Vromans.

Les alias pour une variable doivent être spécifiés après le nom de la variable, séparés par des barres verticales, '|'. Tout paramètre ARGS doit être ajouté après le(s) nom(s) de variable et/ou les

alias.

Les exemples suivants sont équivalents

: 
$state->define("foo", { 
        ALIAS =>
[ 'bar', 'baz' ], ARGS => '=i',
}); $state->define("foo|bar|baz=i");

LECTURE ET MODIFICATION DES VALEURS DES

VARIABLES

AppConfig::State définit deux méthodes pour manipuler les valeurs des variables

: 
set($variable, $value);
get($variable)
;

Les deux fonctions prennent le nom de la variable comme premier paramètre et set() prend un paramètre supplémentaire qui est la nouvelle valeur pour la variable. set() retourne 1 ou 0 pour indiquer une mise à jour réussie ou non de la valeur de la variable. S'il y a une routine ACTION associée à la variable nommée, la valeur retournée sera passée depuis set(). La fonction get() retourne la valeur actuelle de la

variable.

Une fois définies, les variables peuvent être accédées directement en tant que méthodes d'objet où le nom de la méthode est le même que le nom de la variable.

c'est-à-dire 
$state->set("verbose", 1)
;

est équivalent

à 
$state->verbose(1)
;

Sans paramètres, la valeur actuelle de la variable est retournée. Si un paramètre est spécifié, la variable est définie à cette valeur et le résultat de l'opération set() est

retourné. 
$state->age(29);
# sets 'age' to
29, returns 1 (ok)

VARLIS

T

La méthode varlist() peut être utilisée pour extraire un certain nombre de variables dans un hash. Le premier paramètre doit être une expression régulière utilisée pour la correspondance avec les noms de

variables. 
my %vars = $state->varlist("^file");   # all "file*"
variables

Un second paramètre peut être spécifié (n'importe quelle valeur vraie) pour indiquer que la partie du nom de la variable correspondant à l'expression régulière doit être supprimée lorsque copiée dans le hash

cible. 
$state->file_name("/tmp/file");
$state->file_path("/foo:/
bar:/baz"); my %vars = $state->varlist("^file_", 1); # %v
ars: # name => /tmp/file # path => "/foo:/bar:/baz"

MÉTHODES

INTERNES

Les méthodes internes (privées) de la classe AppConfig::State sont listées

ci-dessous.

Elles ne sont pas destinées à un usage régulier et les utilisateurs potentiels doivent considérer le fait que rien sur l'implémentation interne n'est garanti de rester le même. Cela dit, la classe AppConfig::State est destinée à coexister et à fonctionner avec un certain nombre d'autres modules et ceux-ci sont considérés comme des classes "amies". Ces méthodes sont fournies, en partie, comme services pour elles. Avec cette coopération reconnue à l'esprit, il est sûr de supposer une certaine stabilité dans cette interface de

base.

La méthode _varname() peut être utilisée pour déterminer le vrai nom d'une variable à partir d'un alias

: 
$varname->_varname($alias)
;

Notez que toutes les méthodes qui prennent un nom de variable, y compris celles listées ci-dessous, peuvent accepter un alias et le résoudre automatiquement en nom de variable correct. Il n'est pas nécessaire d'appeler _varname() explicitement pour faire l'expansion d'alias. La méthode _varname() mettra tous les noms de variables en minuscules sauf si la sensibilité à la casse (CASE) est

définie.

La méthode _exists() peut être utilisée pour vérifier si une variable a été définie

: 
$state->_exists($varname);re>

La méthode _default() peut être utilisée pour réinitialiser une variable à
    sa valeur par défaut 
:

$state->_default($varname)
;

La méthode _expand() peut être utilisée pour déterminer la valeur EXPAND
    d'une variable 
:

print "$varname EXPAND: ", $state->_expand($varname), 
"\n";

La méthode _argcount() renvoie la valeur de l'attribut ARGCOUNT
    d'une variable 
:

print "$varname ARGCOUNT: ", $state->_argcount($varname), 
"\n";

La méthode _validate() peut être utilisée pour déterminer si une nouvelle
    valeur pour une variable satisfait les critères de validation spécifiés pour celle-ci. Le
    nom de la variable et la valeur prévue doivent être passés. La méthode renvoie une
    valeur vrai/faux selon que la validation a réussi ou non 
:

print "OK\n" if $state->_validate($varname, $value)
;

La méthode _pedantic() peut être appelée pour déterminer la
    valeur actuelle de l'option 
PEDANTIC.

print "pedantic mode is ", $state->_pedantic() ? "on" ; "off", 
"\n";

La méthode _debug() peut être utilisée pour activer ou désactiver le débogage

    en renvoyant la valeur interne actuelle de
    $AppConfig::State::DEBUG. Si une nouvelle valeur de débogage est
    fournie, l'état du débogage est mis à jour et l'état précédent est 
renvoyé.
