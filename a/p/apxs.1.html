RÉSUM

É

apxs est un outil pour construire et installer des modules d'extension pour le serveur Apache HyperText Transfer Protocol (HTTP). Cela est réalisé en construisant un objet partagé dynamique (DSO) à partir d'un ou plusieurs fichiers source ou fichiers objet qui peuvent ensuite être chargés dans le serveur Apache à l'exécution via la directive LoadModule de

mod_so.

Ainsi, pour utiliser ce mécanisme d'extension, votre plateforme doit prendre en charge la fonctionnalité DSO et votre binaire Apache httpd doit être compilé avec le module mod_so. Le outil apxs signale automatiquement si ce n'est pas le cas. Vous pouvez le vérifier vous-même en exécutant manuellement la

commande 
      $ httpd
-l

Le module mod_so devrait faire partie de la liste affichée. Si ces conditions sont remplies, vous pouvez facilement étendre les fonctionnalités de votre serveur Apache en installant vos propres modules avec le mécanisme DSO à l'aide de cet outil apxs

: 
      $ apxs -i -a -c mod_foo.c
      gcc -fpic -DSHARED_MODULE -I/path/to/apache/include -c mod_foo.c
      ld -Bshareable -o mod_foo.so mod_foo.o
      cp mod_foo.so /path/to/apache/modules/mod_foo.so
      chmod 755 /path/to/apache/modules/mod_foo.so
      [activating module `foo' in /path/to/apache/etc/httpd.conf]
      $ apachectl restart
      /path/to/apache/sbin/apachectl restart: httpd not running, trying to start
      [Tue Mar 31 11:27:55 1998] [debug] mod_so.c(303): loaded module foo_module
      /path/to/apache/sbin/apachectl restart: httpd started
      $
_

Les arguments fichiers peuvent être n'importe quel fichier source C (.c), un fichier objet (.o) ou même une archive de bibliothèque (.a). L' outil apxs reconnaît automatiquement ces extensions et utilise automatiquement les fichiers source C pour la compilation tout en utilisant simplement les fichiers objet et archive pour la phase d'édition de liens. Mais lors de l'utilisation d'objets pré-compilés, assurez-vous qu'ils sont compilés en code indépendant de la position (PIC) pour pouvoir les utiliser pour un objet partagé chargé dynamiquement. Par exemple, avec GCC, vous devez toujours simplement utiliser -fpic. Pour d'autres compilateurs C, consultez leur page manuel ou surveillez les drapeaux qu'apxs utilise pour compiler les fichiers

objet.

Pour plus de détails sur la prise en charge DSO dans Apache, lisez la documentation de mod_so ou peut-être même lisez le fichier source src/mod

ules/standar
d/mod_so.c.

EXEMPLE

S

Supposons que vous ayez un module Apache nommé mod_foo.c disponible qui devrait étendre les fonctionnalités du serveur d'Apache. Pour ce faire, vous devez d'abord compiler la source C en un objet partagé adapté au chargement dans le serveur Apache à l'exécution via la commande suivante

: 
      $ apxs -c mod_foo.c
      /path/to/libtool --mode=compile gcc ... -c mod_foo.c
      /path/to/libtool --mode=link gcc ... -o mod_foo.la mod_foo.slo
      $
_

Ensuite, vous devez mettre à jour la configuration d'Apache en vous assurant qu'une directive LoadModule est présente pour charger cet objet partagé. Pour simplifier cette étape apxs fournit un moyen automatique d'installer l'objet partagé dans son répertoire « modules » et de mettre à jour le fichier httpd.conf en conséquence. Cela peut être réalisé en exécutant

: 
      $ apxs -i -a mod_foo.la
      /path/to/instdso.sh mod_foo.la /path/to/apache/modules
      /path/to/libtool --mode=install cp mod_foo.la /path/to/apache/modules
      ...
      chmod 755 /path/to/apache/modules/mod_foo.so
      [activating module `foo' in /path/to/apache/conf/httpd.conf]
      $
_

De cette façon, une ligne

nommée 
      LoadModule foo_module modules/mod_foo.
so

est ajoutée au fichier de configuration si elle n'est pas encore présente. Si vous souhaitez que cela soit désactivé par défaut, utilisez l'option -A, c'est-à-di

re 
      $ apxs -i -A mod_foo.
c

Pour un test rapide du mécanisme apxs, vous pouvez créer un modèle d'exemple de module Apache ainsi qu'un Makefile correspondant via

: 
      $ apxs -g -n foo
      Creating [DIR]  foo
      Creating [FILE] foo/Makefile
      Creating [FILE] foo/modules.mk
      Creating [FILE] foo/mod_foo.c
      Creating [FILE] foo/.deps
      $
_

Vous pouvez ensuite compiler immédiatement ce module d'exemple en un objet partagé et le charger dans le serveur Apache

: 
      $ cd foo
      $ make all reload
      apxs -c mod_foo.c
      /path/to/libtool --mode=compile gcc ... -c mod_foo.c
      /path/to/libtool --mode=link gcc ... -o mod_foo.la mod_foo.slo
