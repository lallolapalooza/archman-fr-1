apk-mkndx(8) Manuel du gestionnaire système apk-mkndx(8)

NOM

apk mkndx - crée un fichier d'index de dépôt apkv3 à partir de paquets

SYNTAXE

apk mkndx [<options>...] paquets...

DESCRIPTION

apk mkndx crée un index de dépôt à partir d'une liste de fichiers de paquets. Voir apk-repositories(5) pour plus d'informations sur les index de dépôts.

OPTIONS

--description, -d TEXTE

Ajoute une description à l'index. En amont (upstream), ceci est utilisé pour ajouter des informations de version basées sur le SHA du commit git de HEAD aports au moment de la génération de l'index.

--filter-spec PKGNAME_SPEC

Filtre l'index précédent uniquement. Chaque argument doit être un nom de paquet au format PKGNAME_SPEC à inclure dans l'index. Ceci peut être utilisé pour créer un sous-ensemble d'un index existant.

--hash HASH

Utilise HASH comme algorithme pour l'intégrité apk v3. Actuellement supportés :
  • sha256 (par défaut)
  • sha256-160

Le sha256-160 est autorisé pour générer un index compatible avec les anciennes versions préliminaires (prereleases) d'apkv3 qui ne gèrent pas correctement les hashs plus longs.

--index, -x INDEX

Lit un index existant depuis INDEX pour accélérer la création du nouvel index en réutilisant les données lorsque c'est possible.

--output, -o FICHIER

Écrit l'index généré dans FICHIER.

--pkgname-spec PKGNAME_SPEC

Spécifie la spécification du nom de paquet pour le téléchargement des paquets. APK construira l'URL de téléchargement par rapport au fichier d'index en développant cette spécification avec des valeurs spécifiques au paquet.

Si la spécification contient ://, elle est considérée comme une URL absolue au lieu d'une URL relative. Ceci n'est pas recommandé pour les dépôts publics car l'utilisation d'une spécification de nom de paquet absolue empêcherait la mise en miroir (mirroring). Cependant, c'est utile dans l'environnement de construction pour créer un sous-ensemble d'un index et le faire pointer vers des paquets dans un autre dépôt.

Si non spécifié, la valeur par défaut sera déterminée par apk à l'exécution en fonction de la manière dont le dépôt est référencé :

  • ${arch}/${name}-${version}.apk si référencé par l'URL de base du dépôt
  • ${name}-${version}.apk si référencé par l'URL du fichier d'index du dépôt

Les variables de substitution actuellement supportées sont :

  • name
  • version
  • arch
  • hash

De plus, un préfixe de la variable peut être utilisé avec la syntaxe : ${name:4}. Ceci tronque la substitution à un maximum de 4 caractères.

Le rédacteur de la spécification doit s'assurer que le dépôt ne contient pas plusieurs paquets qui se développeraient en un même nom de fichier de paquet.
