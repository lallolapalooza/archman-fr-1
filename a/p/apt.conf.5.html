DESCRIPTIO

N

/etc/apt/apt.conf est le fichier de configuration principal partagé par tous les outils de la suite d'outils APT, bien qu'il ne soit en aucun cas le seul endroit où les options peuvent être définies. La suite partage également un analyseur de ligne de commande commun pour fournir un environnement

uniforme.

Lorsqu'un outil APT démarre, il lira les fichiers de configuration dans l'ordre suivant

:
1.le fichier spécifié par la variable d'environnement APT_CONFIG (le cas
échéant)
2.tous les fichiers dans Dir::Etc::Parts en ordre alphanumérique croissant qui n'ont soit aucune extension de nom de fichier, soit l'extension "conf", et qui ne contiennent que des caractères alphanumériques, des tirets (-), des traits de soulignement (_) et des points (.). Sinon, APT affichera un avis indiquant qu'il a ignoré un fichier, sauf si ce fichier correspond à un motif dans la liste de configuration Dir::Ignore-Files-Silently - auquel cas il sera ignoré silencieusement
.
3.le fichier de configuration principal spécifié par Dir::Etc::
main
4.toutes les options définies dans le sous-arbre de configuration spécifique au binaire sont déplacées à la racine de
l'arbre.
5.les options de ligne de commande sont appliquées p
our remplacer les directives de configuration ou po
ur charger encore plus de fichiers de configuration.

SYNTAX

E

Le fichier de configuration est organisé en un arbre avec des options organisées en groupes fonctionnels. La spécification d'une option est donnée avec une notation à double deux-points ; par exemple, APT::Get::Assume-Yes est une option au sein du groupe d'outils APT, pour l'outil Get. Les options n'héritent pas de leurs groupes

parents.

Syntaxiquement, le langage de configuration est modélisé sur celui utilisé par les outils ISC tels que bind et dhcp. Les lignes commençant par // sont traitées comme des commentaires (ignorées), ainsi que tout le texte entre /* et */, tout comme les commentaires C/C++. Les lignes commençant par # sont également traitées comme des commentaires. Chaque ligne est de la forme APT::Get::Assume-Yes "true";. Les guillemets et le point-virgule final sont requis. La valeur doit être sur une seule ligne, et il n'y a aucun type de concaténation de chaînes. Les valeurs ne doivent pas inclure de barres obliques inverses ou de guillemets supplémentaires. Les noms d'options sont composés de caractères alphanumériques et des caractères "/-:._+". Un nouveau portée peut être ouverte avec des accolades, comme ceci

: 
APT {
  Get {
    Assume-Yes "true";
    Fix-Broken "true";
  };
}
;

avec des sauts de ligne placés pour le rendre plus lisible. Des listes peuvent être créées en ouvrant une portée et en incluant une chaîne unique entourée de guillemets suivie d'un point-virgule. Plusieurs entrées peuvent être incluses, séparées par un

point-virgule. 
DPkg::Pre-Install-Pkgs {"/usr/sbin/dpkg-preconfigure --apt";
}
;

En général, le fichier de configuration d'exemple /usr/share/doc/apt/examples/configure-index est un bon guide pour savoir à quoi il devrait

ressembler.

La casse n'est pas significative dans les noms des éléments de configuration, de sorte que dans l'exemple précédent, vous pourriez utiliser dpkg::pre-install-pkgs

.

Les noms des éléments de configuration sont facultatifs si une liste est définie, comme on peut le voir dans l'exemple DPkg::Pre-Install-Pkgs ci-dessus. Si vous ne spécifiez pas de nom, une nouvelle entrée ajoutera simplement une nouvelle option à la liste. Si vous spécifiez un nom, vous pouvez remplacer l'option de la même manière que n'importe quelle autre option en réassignant une nouvelle valeur à

l'option.

Deux commandes spéciales sont définies : #include (qui est obsolète et non prise en charge par les implémentations alternatives) et #clear. #include inclura le fichier donné, sauf si le nom de fichier se termine par une barre oblique, auquel cas l'ensemble du répertoire est inclus. #clear est utilisé pour effacer une partie de l'arbre de configuration. L'élément spécifié et tous ses descendants sont effacés. (Notez que ces lignes doivent également se terminer par un point-virgule.

)

La commande #clear est le seul moyen de supprimer une liste ou une portée complète. Rouvrir une portée (ou utiliser la syntaxe décrite ci-dessous avec un :: ajouté) ne remplacera pas les entrées écrites précédemment. Les options ne peuvent être remplacées que par l'assignation d'une nouvelle valeur - les listes et les portées ne peuvent pas être remplacées, seulement

effacées.

Tous les outils APT prennent une option -o qui permet de spécifier une directive de configuration arbitraire sur la ligne de commande. La syntaxe est un nom d'option complet (APT::Get::Assume-Yes par exemple) suivi d'un signe égal puis de la nouvelle valeur de l'option. Pour ajouter un nouvel élément à une liste, ajoutez un :: final au nom de la liste. (Comme vous pouvez le soupçonner, la syntaxe de portée ne peut pas être utilisée sur la ligne de commande.

)

Notez que l'ajout d'éléments à une liste avec :: ne fonctionne que pour un élément par ligne, et que vous ne devriez pas l'utiliser en combinaison avec la syntaxe de portée (qui ajoute :: implicitement). L'utilisation des deux syntaxes ensemble déclenchera un bogue dont certains utilisateurs dépendent malheureusement : une option avec le nom inhabituel "::" qui se comporte comme toutes les autres options avec un nom. Cela introduit de nombreux problèmes ; par exemple, les utilisateurs qui écrivent plusieurs lignes dans cette mauvaise syntaxe dans l'espoir d'ajouter à une liste obtiendront le contraire, car seule la dernière affectation pour cette option "::" sera utilisée. Les futures versions d'APT lèveront d

es erreurs et cesseront de fonctionner si elles rencontrent cet usage incorrect, alors veuille
z corriger de telles déclarations maintenant, alors qu'APT ne se plaint pas explicitement d'elles.

LE GROUPE

APT

Ce groupe d'options contrôle le comportement général d'APT ainsi que contient les options pour tous les

outils.

Architectur

e
Architecture du système ; définit l'architecture à utiliser lors de la récupération de fichiers et de l'analyse des listes de paquets. La valeur interne par défaut est l'architecture pour laquelle apt a été
compilé.

Architecture

s
Toutes les architectures prises en charge par le système. Par exemple, les processeurs implémentant l'ensemble d'instructions amd64 (également appelé x86-64) sont également capables d'exécuter des binaires compilés pour l'ensemble d'instructions i386 (x86). Cette liste est utilisée lors de la récupération de fichiers et de l'analyse des listes de paquets. La valeur initiale par défaut est toujours l'architecture native du système (APT::Architecture), et les architectures étrangères sont ajoutées à la liste par défaut lorsqu'elles sont enregistrées via dpkg --add-architecture
.

Colo

r
Cette portée définit les couleurs et les styles. Les couleurs de base prises en charge sont rouge, vert, jaune, bleu, magenta, cyan, et blanc.

Le sous-portée action définit les couleurs pour les listes de paquets dans install et les commandes similaires. Les options suivantes peuvent être définies : APT::Color::Action::Upgrade, APT::Color::Action::Install, APT::Color::Action::Install-Dependencies, APT::Color::Action::Downgrade, APT::Color::Action::Remove; correspondant à leurs listes dans la sortie apt(8

).

Chaque couleur peut référencer une ou plusieurs autres options de couleur par nom, par rapport à APT::Color. Leurs séquences d'échappement seront

combinées. 
APT::Color::Bold "\x1B[1m";
APT::Color::Action::Install "cyan";
A
PT::Color::Action::Upgrade "bold action::install"; Les couleurs
peuvent être activées ou désactivées complètement en définissant APT::Color à yes ou no, en utilisant les variables d'environnement NO_COLOR ou APT_NO_COLOR ou en utilisant les options de ligne de commande --color, --no-color
.

Compresso

r
Cette portée définit quels formats de compression sont pris en charge, comment la compression et la décompression peuvent être effectuées si la prise en charge de ce format n'est pas intégrée directement dans apt, et une valeur de coût indiquant combien il est coûteux de compresser quelque chose dans ce format. À titre d'exemple, le bloc de configuration suivant permettrait à apt de télécharger et décompresser ainsi que de créer et stocker des fichiers avec l'extension de fichier à faible coût .reversed qu'il transmettra à la commande rev sans paramètres de ligne de commande supplémentaires pour la compression et la décompression : 
APT::Compressor::rev {
	Name "rev";
	Extension ".reversed";
	Binary "rev";
	CompressArg {};
	UncompressArg {};
	Cost "10";
}
;

Build-Profile

s
Liste de tous les profils de construction activés pour la résolution des dépendances de construction, sans le préfixe d'espace de noms "profile.". Par défaut, cette liste est vide. La variable DEB_BUILD_PROFILES telle qu'utilisée par /dpkg-buildpackage.1.en'>dpkg-buildpackage(1) remplace la notation par
liste.

Default-Releas

e
Release par défaut à partir de laquelle installer les paquets si plusieurs versions sont disponibles. Contient le nom de la release, le nom de code ou la version de la release. Exemples : 'stable', 'testing', 'unstable', 'trixie', 'forky', '4.0', '5.0*'. Voir aussi apt_preferenc
es(5).

Snapsho

t
Instantané (snapshot) à utiliser pour tous les dépôts configurés avec Snapshot: yes. Voir aussi sources.list(5), l' option --snapshot qui définit cette valeur, et Acquire::Snapshots::URI
ci-dessous.

Ignore-Hol

d
Ignore les paquets retenus ; cette option globale indique au résolveur de problèmes d'ignorer les paquets retenus dans sa prise de
décision.

Clean-Installe

d
Activée par défaut. Lorsqu'elle est activée, la fonction d'autonettoyage supprimera du cache tous les paquets qui ne peuvent plus être téléchargés. Si elle est désactivée, les paquets installés localement sont également exclus du nettoyage - mais notez qu'APT ne fournit aucun moyen direct de les
réinstaller.

Immediate-Configur

e
Activée par défaut, ce qui amènera APT à installer les paquets essentiels et importants dès que possible lors d'une opération d'installation/mise à jour, afin de limiter l'effet d'un échec d'un appel à dpkg(1). Si cette option est désactivée, APT traite un paquet important de la même manière qu'un paquet supplémentaire : entre le dépaquetage du paquet A et sa configuration, il peut y avoir de nombreux autres appels de dépaquetage ou de configuration pour d'autres paquets non liés B, C, etc. Si ceux-ci provoquent l'échec de l'appel à dpkg(1) (par exemple parce que les scripts de mainteneur du paquet B génèrent une erreur), cela résulte en un état du système où le paquet A est dépaqueté mais non configuré - ainsi tout paquet dépendant de A n'est plus garanti de fonctionner, car sa dépendance à A n'est plus satisfaite.

La marque de configuration immédiate est également appliquée dans le cas potentiellement problématique des dépendances circulaires, puisqu'une dépendance avec le marqueur immédiat est équivalente à une Pré-Dépendance. En théorie, cela permet à APT de reconnaître une situation où il est incapable d'effectuer la configuration immédiate, d'interrompre, et de suggérer à l'utilisateur que l'option devrait être temporairement désactivée pour permettre à l'opération de se poursuivre. Notez l'utilisation du mot « théorie » ici ; dans le monde réel ce problème a rarement été rencontré, dans des versions de distribution non stables, et était causé par des dépendances incorrectes du paquet en question ou par un système déjà dans un état cassé ; vous ne devriez donc pas désactiver aveuglément cette option, car le scénario mentionné ci-dessus n'est pas le seul problème qu'elle peut aider à prévenir à la

base.

Avant qu'une grande opération comme dist-upgrade ne soit exécutée avec cette option désactivée, vous devriez essayer d'installer explicitement l

e paquet qu'APT est incapable de configurer immédiatement ; mais assurez-vous également de signaler votre problème à votre distribution et à
l'équipe APT avec le lien de bogue ci-dessous, afin qu'ils puissent travailler à l'amélioration ou à la correction du processus de mise à jour.

Force-LoopBrea

k
N'activez jamais cette option à moins que vous ne sachiez vraiment ce que vous faites. Elle permet à APT de supprimer temporairement un paquet essentiel pour rompre une boucle Conflits/Conflits ou Conflits/Pré-Dépendances entre deux paquets essentiels. Une telle boucle ne devrait jamais exister et est un bogue grave. Cette option fonctionnera si les paquets essentiels ne sont pas tar, gzip, libc, dpkg, dash ou tout ce dont ces paquets
dépendent.

Cache-Start, Cache-Grow, Cache-Limi

t
APT utilise depuis la version 0.7.26 un fichier cache mappé en mémoire redimensionnable pour stocker les informations disponibles. Cache-Start agit comme un indice de la taille à laquelle le cache va croître, et est donc la quantité de mémoire qu'APT demandera au démarrage. La valeur par défaut est 20971520 octets (~20 Mo). Notez que cette quantité d'espace doit être disponible pour APT ; sinon il échouera probablement de manière non gracieuse, donc pour les appareils à mémoire restreinte cette valeur devrait être abaissée, tandis que sur les systèmes avec beaucoup de sources configurées elle devrait être augmentée. Cache-Grow définit en octets, avec une valeur par défaut de 1048576 (~1 Mo), de combien la taille du cache sera augmentée si l'espace défini par Cache-Start n'est pas suffisant. Cette valeur sera appliquée encore et encore jusqu'à ce que le cache soit assez grand pour stocker toutes les informations ou que la taille du cache atteigne la Cache-Limit. La valeur par défaut de Cache-Limit est 0, ce qui signifie aucune limite. Si Cache-Grow est défini à 0, la croissance automatique du cache est
désactivée.

l
Définit quels paquets sont considérés comme des dépendances de construction
essentielles.

t
La sous-section Get contrôle l' outil apt-get(8) ; veuillez consulter sa documentation pour plus d'informations sur les options
ici.

Cach

e
La sous-section Cache contrôle l' outil apt-cache(8) ; veuillez consulter sa documentation pour plus d'informations sur les options
ici.

CDRO

M
La sous-section CDROM contrôle l' outil apt-cdrom(8) ; veuillez consulter sa documentation pour plus d'informations sur les options
ici.

NeverAutoRemov

e
Ne jamais supprimer automatiquement les paquets qui correspondent à la ou aux expressions
rationnelles.

Protect-Kernel

s
Cette option indique à apt autoremove que les noyaux sont protégés et vaut true par défaut. Si les noyaux ne sont pas protégés, ils sont traités comme n'importe quel autre
paquet.

VersionedKernelPackage

s
Définit la ou les expressions rationnelles pour les paquets de noyau versionnés. Sur la base de ces expressions, un ensemble de règles est injecté dans apt similaire aux expressions rationnelles de APT::NeverAutoRemove
.

NeverAutoRemove::

KernelCount
Conserve un nombre personnalisé de noyaux lors de la suppression automatique et vaut 2 par défaut, ce qui signifie que deux noyaux sont conservés. Apt conservera to
ujours le noyau en cours d'exécution et le plus récent. Si le noyau le plus récent est le même que le noyau en cours d'exécution, l'avant-dernier noyau est conser
vé. En raison de cela, toute valeur inférieure à 2 sera ignorée. Si vous ne voulez que le noyau le plus récent, vous devriez définir APT::Protect-Kernels à false.

LE GROUPE

ACQUIRE

Le groupe d'options Acquire contrôle le téléchargement des paquets ainsi que les diverses « méthodes d'acquisition » responsables du téléchargement lui-même (voir aussi sources.list(5))

.

Check-Dat

e
Option liée à la sécurité valant true par défaut, activant les vérifications liées au temps. La désactiver signifie que l'horloge de la machine ne peut pas être considérée comme fiable, et APT désactivera donc toutes les vérifications liées au temps, telles que Check-Valid-Until et la vérification que le champ Date d'un fichier Release n'est pas dans le
futur.

Max-FutureTim

e
Durée maximale (en secondes) avant sa création (comme indiqué par l'en-tête Date) pendant laquelle le fichier Release doit être considéré comme valide. La valeur par défaut est 10. Des réglages spécifiques à l'archive peuvent être faits en ajoutant le label de l'archive au nom de l'option. De préférence, la même chose peut être obtenue pour des entrées sources.list(5) spécifiques en utilisant l' option Date-Max-Future
là-bas.

Check-Valid-Unti

l
Option liée à la sécurité valant true par défaut, car donner une date d'expiration à la validation d'un fichier Release empêche les attiques par rejeu sur une longue période, et peut aussi par exemple aider les utilisateurs à identifier des miroirs qui ne sont plus mis à jour - mais la fonctionnalité dépend de la justesse de l'horloge sur le système utilisateur. Les mainteneurs d'archives sont encouragés à créer des fichiers Release avec l'en-tête Valid-Until, mais s'ils ne le font pas ou si une valeur plus stricte est souhaitée, l'option Max-ValidTime ci-dessous peut être utilisée. L' option Check-Valid-Until des entrées sources.list(5) devrait être préférée pour désactiver la vérification de manière sélective plutôt que d'utiliser ce remplacement
global.

Max-ValidTim

e
Durée maximale (en secondes) après sa création (comme indiqué par l'en-tête Date) pendant laquelle le fichier Release doit être considéré comme valide. Si le fichier Release lui-même inclut un en-tête Valid-Until, la date la plus proche des deux est utilisée comme date d'expiration. La valeur par défaut est 0, ce qui signifie « valide pour toujours ». Des réglages spécifiques à l'archive peuvent être faits en ajoutant le label de l'archive au nom de l'option. De préférence, la même chose peut être obtenue pour des entrées sources.list(5) spécifiques en utilisant l' option Valid-Until-Max
là-bas.

Min-ValidTim

e
Durée minimale (en secondes) après sa création (comme indiqué par l'en-tête Date) pendant laquelle le fichier Release doit être considéré comme valide. Utilisez ceci si vous devez utiliser un miroir (local) mis à jour rarement d'une archive mise à jour plus fréquemment avec un en-tête Valid-Until au lieu de désactiver complètement la vérification de la date d'expiration. Des réglages spécifiques à l'archive peuvent et devraient être utilisés en ajoutant le label de l'archive au nom de l'option. De préférence, la même chose peut être obtenue pour des entrées sources.list(5) spécifiques en utilisant l' option Valid-Until-Min
là-bas.

AllowTL

S
Autorise l'utilisation du support TLS interne dans la méthode http. Si défini à false, cela désactive complètement le support pour TLS dans les méthodes propres d'apt (à l'exclusion de la méthode https basée sur curl). Aucune fonction liée à TLS ne sera plus
appelée.

PDiff

s
Essayer de télécharger des deltas appelés PDiffs pour les index (comme les fichiers Packages) au lieu d'en télécharger des entiers. Vrai par défaut. De préférence, ceci peut être défini pour des entrées sources.list(5) spécifiques ou des fichiers d'index en utilisant l' option PDiffs là-bas.

Deux sous-options pour limiter l'utilisation de PDiffs sont également disponibles : FileLimit peut être utilisé pour spécifier un nombre maximal de fich

iers PDiff qui doivent être téléchargés pour mettre à jour un fichier. SizeLimit, quant à elle, est le pourcentage maximal de la taille de tous les
correctifs par rapport à la taille du fichier ciblé. Si l'une de ces limites est dépassée, le fichier complet est téléchargé au lieu des correctifs.

By-Has

h
Essayer de télécharger les index via une URI construite à partir d'une somme de hachage du fichier attendu plutôt que via un nom de fichier stable bien connu. Vrai par défaut, mais automatiquement désactivé si la source indique ne pas le supporter. L'utilisation peut être forcée avec la valeur spéciale « force ». De préférence, ceci peut être défini pour des entrées sources.list(5) spécifiques ou des fichiers d'index en utilisant l' option By-Hash
là-bas.

Queue-Mod

e
Mode de mise en file d'attente ; Queue-Mode peut être host ou access, ce qui détermine comment APT parallélise les connexions sortantes. host signifie qu'une connexion par cibleet host sera ouvert, access signifie qu'une connexion par type d'URI sera
ouverte.

Retrie

s
Nombre de nouvelles tentatives à effectuer. Si cette valeur est non nulle, APT réessaiera les fichiers en échec le nombre de fois
indiqué.

Source-Symlink

s
Utiliser des liens symboliques pour les archives sources. Si défini à true, les archives sources seront liées par des liens symboliques lorsque c'est possible au lieu d'être copiées. True est la valeur par
défaut.

http http

s
Les options dans ces portées configurent les transports d'acquisition d'APT pour les protocoles HTTP et HTTPS et sont documentées dans les pages de man apt-transport-http(1) et apt-transport-https(1)
respectivement.

Il est possible de fournir des commandes de montage et de démontage alternatives si votre point de montage ne peut pas être listé dans le fstab. La syntaxe consiste à mettre

Pour les URIs GPGV, la seule option configurable est gpgv::Options, qui transmet des paramètres supplémentaires à

CompressionType

s
Liste des types de compression compris par les méthodes d'acquisition. Des fichiers comme Packages peuvent être disponibles dans différents formats de compression. Par défaut, les méthodes d'acquisition peuvent décompresser et recomprimer de nombreux formats courants comme xz et gzip ; avec cette portée, les formats pris en charge peuvent être interrogés, modifiés et le support de formats supplémentaires ajouté (voir aussi APT::Compressor). La syntaxe est la suivante : 
Acquire::CompressionTypes::FileExtension "Methodname
"
;

De plus, le sous-groupe Order peut être utilisé pour définir dans quel ordre le système d'acquisition essaiera de télécharger les fichiers compressés. Le système d'acquisition essaiera le premier et passera au type de compression suivant de cette liste en cas d'erreur ; pour préférer un type à un autre, ajoutez simplement le type préféré en premier - les types non déjà ajoutés seront implicitement ajoutés à la fin de la liste, par

exemple 
Acquire::Comp
ressionTypes::
Order:: "gz";

peut être utilisé pour préférer les fichiers compressés avec gzip à tous les autres formats de compression. Si xz doit être préféré à gzip et bzip2, le paramètre de configuration doit ressembler à ceci

: 
Acquire::CompressionTypes::Order { "xz"; "gz";
}
;

Il n'est pas nécessaire d'ajouter bz2 à la liste explicitement car il sera ajouté automatiquement

.

Notez que le Dir::Bin::Methodname sera vérifié à l'exécution. Si cette option a été définie et que le support de ce format n'est pas directement intégré à apt, la méthode ne sera utilisée que si ce fichier existe ; par exemple, pour la méthode bzip2 (intégrée), le paramètre est

: 
Dir::Bin::
bzip2 "/b
in/bzip2";

Notez également que les entrées de liste spécifiées en ligne de commande seront ajoutées à la fin de la liste spécifiée dans les fichiers de configuration, mais avant les entrées par défaut. Pour préférer un type dans ce cas à ceux spécifiés dans les fichiers de configuration, vous pouvez définir l'option directement - pas sous forme de liste. Cela n'écrasera pas la liste définie ; cela ne fera que préfixer la liste avec ce

type.

Le type spécial uncompressed peut être utilisé pour donner une préférence aux fichiers

non compressés, mais notez que la plupart des dépôts ne fournissent pas de fichiers
non compressés, donc cela n'est principalement utilisable que pour les miroirs locaux.

GzipIndexe

s
Lors du téléchargement d'index compressés avec gzip (Packages, Sources, ou Translations), les conserver compressés localement avec gzip au lieu de les décompresser. Cela économise pas mal d'espace disque au prix de besoins CPU plus importants lors de la construction des caches de paquets locaux. Faux par
défaut.

Language

s
La sous-section Languages contrôle quels fichiers Translation sont téléchargés et dans quel ordre APT essaie d'afficher les traductions de descriptions. APT essaiera d'afficher la première description disponible dans la langue listée en premier. Les langues peuvent être définies avec leurs codes de langue courts ou longs. Notez que tous les dépôts ne fournissent pas de fichiers Translation pour chaque langue - les codes de langue longs sont particulièrement rares.

La liste par défaut inclut "environment" et "en". "environment" a une signification particulière ici : il sera remplacé à l'exécution par les codes de langue extraits de la variable d'environnement LC_MESSAGES. Il s'assurera également que ces codes ne sont pas inclus deux fois dans la liste. Si LC_MESSAGES est défini à "C", seul le fichier Translation-en (s'il est disponible) sera utilisé. Pour forcer APT à n'utiliser aucun fichier Translation, utilisez le paramètre Acquire::Languages=none. "none" est un autre code à signification particulière qui arrêtera la recherche d'un fichier Translation approprié. Cela indique à APT de télécharger ces traductions également, sans les utiliser réellement sauf si l'environnement spécifie les langues. Ainsi, l'exemple de configuration suivant résultera dans l'ordre "en, de" dans un locale anglais ou "de, en" dans un locale allemand. Notez que "fr" est téléchargé, mais non utilisé sauf si APT est utilisé dans un locale français (où l'ordre serait "fr, de, en")

. 
Acquire::Languages { "environment"; "de"; "en"; "none"; "fr";
}
;

Note : Pour éviter les problèmes résultant de l'exécution d'APT dans différents environnements (par

exemple par différents utilisateurs ou par d'autres programmes), tous les fichiers Translation tr
ouvés dans /var/lib/apt/lists/ seront ajoutés à la fin de la liste (après un "none" implicite).

Pre-Install-Pkg

Il s'agit d'une liste de commandes shell à exécuter avant d'invoquer dpkg(1). Comme options, cela doit être spécifié en notation de liste. Les commandes sont invoquées dans l'ordre en utilisant /bin/sh ; si l'une d'elles échoue, APT s'interrompra. APT transmettra les noms de fichiers de tous les fichiers .deb qu'il va installer aux commandes, un par ligne sur le descripteur de fichier demandé, par défaut l'entrée standard.

La version 2 de ce protocole envoie plus d'informations à travers le descripteur de fichier demandé : une ligne avec le texte VERSION 2, l'espace de configuration APT, et une liste d'actions de paquets avec les informations de nom de fichier et de

version.

Chaque ligne de directive de configuration a la forme clé=valeur. Les caractères spéciaux (signes égal, sauts de ligne, caractères non imprimables, guillemets, et signes pourcents dans la clé et sauts de ligne, caractères non imprimables, et signes pourcents dans la valeur) sont encodés en %. Les listes sont représentées par plusieurs lignes clé::=valeur avec la même clé. La section de configuration se termine par une ligne

vide.

Les lignes d'action de paquets consistent en cinq champs en version 2 : nom du paquet (sans qualification d'architecture même si étranger), ancienne version, direction du changement de version (< pour les mises à niveau, > pour les rétrogradations, = pour aucun changement), nouvelle version, action. Les champs de version sont "-" pour aucune version du tout (par exemple lors de l'installation d'un paquet pour la première fois ; aucune version est considérée comme antérieure à toute version réelle, donc c'est une mise à niveau, indiquée comme - < 1.23.4). Le champ d'action est "**CONFIGURE**" si le paquet est en cours de configuration, "**REMOVE**" s'il est en cours de suppression, ou le nom de fichier d'un fichier .deb s'il est en cours de

dépaquetage.

En version 3, après chaque champ de version suit l'architecture de cette version, qui est "-" s'il n'y a pas de version, et un champ montrant le type MultiArch "same", "foreign", "allowed" ou "none". Notez que "none" est un nom de type incorrect qui est simplement conservé pour rester compatible, il doit être lu comme "no" et les utilisateurs sont encouragés à prendre en charge les

deux.

La version du protocole à utiliser pour la commande cmd peut être choisie en définissant DPkg::Tools::options::cmd::Version en conséquence, la version par défaut étant la version 1. Si APT ne prend pas en charge la version demandée, il enverra les informations dans la version la plus élevée qu'il prend en charge à la

place.

La prise en charge de l'option peut être détectée en cherchant la variable d'environnement APT_HOOK_INFO_FD qui contient le numéro du descr
