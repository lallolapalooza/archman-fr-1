L'installation sur disque dur entraînera probablement la suppression inattendue de certains paquets. En cas de doute, utilisez avec --interactive ou --simulate d'abord.

--force-missing-repositories

Continue même si certains index de dépôts ne sont pas disponibles.

--force-no-chroot

Désactive le chroot pour les scripts. Ceci peut être utilisé pour la création de rootfs lorsque le chroot n'est pas disponible. Les scripts exécutés en dehors d'un environnement chroot peuvent modifier et endommager le système hôte.

--force-non-repository

Continue même si des paquets risquent d'être perdus au redémarrage. Cela peut se produire lors de l'exécution en mode run-from-tmpfs et de l'installation d'un paquet non référencé.

--force-old-apk

Continue même si les paquets utilisent des fonctionnalités non prises en charge.

--force-overwrite

Écrase les fichiers d'autres paquets.

--force-refresh

N'utilise pas les fichiers mis en cache (locaux ou provenant d'un proxy).

--help, -h

Affiche la liste de toutes les commandes avec leurs descriptions.

--interactive[=AUTO]

Détermine si des questions peuvent être posées avant d'effectuer certaines opérations. En mode auto, le mode interactif est activé si l'on s'exécute sur un tty. Par défaut, il est réglé sur no, ou sur auto si /etc/apk/interactive existe.

--keys-dir KEYSDIR

Remplace les répertoires par défaut des clés de confiance du système. Si spécifié, seul ce répertoire est traité. Le KEYSDIR est traité par rapport au ROOT.

--legacy-info[=BOOL]

Affiche la sortie de l'applet "info" dans le format hérité ou dans le nouveau format "query". Par défaut, la valeur est actuellement no, mais cette valeur par défaut est susceptible d'être modifiée à yes dans une future version.

--logfile[=BOOL]

Si désactivé, désactive l'écriture du fichier journal.

--network[=BOOL]

Si désactivé, n'utilise pas le réseau. Les paquets provenant des dépôts réseau dans le cache sont utilisés.

--preserve-env[=BOOL]

Permet de transmettre l'environnement utilisateur aux scripts (à l'exclusion des variables commençant par APK_ qui sont réservées).

--pretty-print[=AUTO]

Détermine si la sortie doit être stylisée pour être lisible par l'homme. Par défaut, la valeur est auto, ce qui se résout en yes si l'on s'exécute sur un tty.

--preupgrade-depends DEPS

Ajoute ou modifie les dépendances de pré-mise à niveau. Les dépendances de pré-mise à niveau sont utilisées pour faire correspondre les paquets installés éligibles à la pré-mise à niveau. Par exemple, 'apk-tools' pré-mettra toujours à niveau le paquet 'apk-tools', mais 'baselayout<2' pré-mettra à niveau 'baselayout' uniquement si la version installée de baselayout est inférieure à 2 et qu'une mise à niveau est disponible. Voir également apk-upgrade(8).

--print-arch

Affiche l'architecture par défaut et quitte.

--progress[=AUTO]

Active ou désactive la barre de progression. Par défaut, la valeur est auto, ce qui se résout en yes si l'on s'exécute sur un tty.

--progress-fd FD

Écrit la progression vers le descripteur de fichier spécifié.

--purge[=BOOL]

Supprime les fichiers de configuration modifiés et les paquets mis en cache. Permet la suppression des fichiers de configuration modifiés lors de la suppression de paquets. Lors de l'action de nettoyage du cache, cela permet la suppression des paquets mis en cache non nécessaires (paquets désinstallés sur les installations tmpfs ou tous les paquets sur les installations sur disque).

--quiet, -q

Affiche moins d'informations.

--repositories-file REPOFILE

Remplace les dépôts système, voir apk-repositories(5). La spécification de cette option remplace le traitement normal du fichier de dépôts et du répertoire repositories.d. Le REPOFILE donné est relatif au répertoire de démarrage depuis apk 2.12.0_rc2.

--repository, -X REPO

Spécifie un dépôt de paquets supplémentaire. Les commandes spécifiées dans apk-repositories(5) ne sont pas analysées (utilisez --repository-config pour cela). De plus, les chemins relatifs sont acceptés et interprétés par rapport au répertoire de démarrage.

--repository-config REPOCONFIG

Spécifie une configuration de dépôt de paquets supplémentaire. Le REPOCONFIG est analysé exactement de la même manière que s'il était lu à partir d'un fichier .list spécifié dans apk-repositories(5).

--root, -p ROOT

Gère le système de fichiers dans ROOT.

--root-tmpfs[=AUTO]

Spécifie si le ROOT est un système de fichiers temporaire. Par défaut, la valeur est auto, qui détermine automatiquement le type de système de fichiers.

Ceci affecte :

  • la lecture et la création de l'index 'installed' dans le cache
  • la suppression des paquets dans le cache
  • les vérifications de sécurité pour ne pas installer de paquets non référencés

--sync[=AUTO]

Détermine si les caches de système de fichiers doivent être validés sur le disque. Par défaut, la valeur est auto, ce qui se résout en yes si --root n'est pas spécifié, si la base de données n'est pas en mode utilisateur et si l'on s'exécute sur l'espace de noms pid racine (pas dans un conteneur).

--timeout TIME

Définit un délai d'attente pour les connexions réseau si aucun progrès n'est réalisé pendant TIME secondes. Le délai par défaut est de 60 secondes.

--update-cache, -U

Alias de '--cache-max-age 0'.

--uvol-manager UVOL

Spécifie l'emplacement de l'exécutable du gestionnaire de volumes OpenWRT uvol.

--verbose, -v

Affiche plus d'informations (peut être spécifié deux fois).

--version, -V

Affiche la version du programme et quitte.

--wait TIME

Attend TIME secondes pour obtenir un verrou exclusif sur le dépôt avant d'échouer.

OPTIONS DE COMMIT

Les options suivantes sont disponibles pour toutes les commandes qui valident la base de données.

--clean-protected[=BOOL]

Si désactivé, empêche la création de fichiers .apk-new dans les répertoires de configuration.

--commit-hooks[=BOOL]

Si désactivé, ignore les scripts de hook pré/post (mais pas les autres scripts).

--initramfs-diskless-boot

Utilisé par initramfs lors de la recréation de root tmpfs. Cela active certaines options de force pour minimiser les échecs, désactive les hooks de commit, entre autres fonctionnalités.

--overlay-from-stdin

Lit la liste des fichiers overlay depuis stdin. Normalement, ceci est utilisé uniquement pendant initramfs lors du démarrage d'une installation run-from-tmpfs.

--scripts[=BOOL]

Si désactivé, empêche l'exécution de tous les scripts. Utile pour extraire une image système pour une architecture différente sur un ROOT alternatif.

--simulate[=BOOL], -s

Simule l'opération demandée sans apporter de modifications. La base de données est ouverte en mode lecture seule, et la mise à jour automatique des index est désactivée. Vous pourriez vouloir exécuter "apk update" avant de lancer une simulation pour vous assurer qu'elle est effectuée avec des index de dépôts à jour.

OPTIONS DE GÉNÉRATION

Les options suivantes sont disponibles pour toutes les commandes qui génèrent des fichiers APKv3.

--compression, -C ALGORITHME[:NIVEAU]

Compresse le fichier avec l'ALGORITHME et le NIVEAU donnés. Algorithmes pris en charge :
  • none
  • deflate (niveau 1-9)
  • zstd (niveau 1-22)

--sign-key KEYFILE

Signe le fichier avec une clé privée dans le KEYFILE spécifié.

Une adresse IP locale à laquelle libfetch liera tous les sockets qu'il crée. Peut être utile pour le routage source.

Spécifie le fichier .netrc à lire pour les secrets d'authentification. S'il n'est pas défini, la valeur par défaut est $HOME/.netrc.

HTTP_AUTH

Spécifie un en-tête Authorization, Referer ou User-Agent HTTP personnalisé.

HTTP_PROXY, http_proxy
HTTPS_PROXY, https_proxy
Si elles sont définies, ces variables doivent contenir l'URL du proxy pour les connexions http

et https respectivement.

HTTP_PROXY_AUTH

Spécifie un en-tête HTTP Proxy-Authorization. Utilisé uniquement si la connexion est établie via un proxy HTTP configuré.

NO_PROXY, no_proxy

Liste séparée par des virgules d'extensions de domaine ou d'adresses IP en notation CIDR pour lesquelles un proxy ne doit pas être utilisé. Ceci est utilisé explicitement pour tester uniquement la partie nom d'hôte de l'URL. C'est-à-dire que la spécification d'une adresse IP ou d'un bloc CIDR ne correspondra pas à un nom DNS qui résout cette adresse IP.

SSL_CLIENT_CERT_FILE
SSL_CLIENT_KEY_FILE

Remplace le nom de fichier par défaut du certificat client SSL et de la clé privée correspondante.

SSL_NO_VERIFY_HOSTNAME

Si défini sur n'importe quoi, désactive la vérification du nom du certificat serveur.
