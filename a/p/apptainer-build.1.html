DESCRIPTIO

N

CHEMIN DE L'IMAGE

:

Lorsqu'Apptainer construit le conteneur, la sortie peut être l'une des quelques formats

: 
  default :    Le format d'image Apptainer compressé en lecture seule (par défaut)
  sandbox :    Il s'agit d'un conteneur en lecture-écriture au sein d'une structure de
répertoires

note : Il est courant d'utiliser le mode "sandbox" pour le développement du
conteneur, puis de le construire en tant qu'image Apptainer par défaut pour la production
Le format par défaut est

immuable.

SPÉCIFICATION DE CONSTRUCTION

:

La cible de spécification de construction est un fichier de définition (def), une image locale ou une URI qui peut
être utilisée pour créer un conteneur Apptainer. Plusieurs formats de cibles locales
différents existent

: 
  fichier def : Il s'agit d'une recette pour construire un conteneur (exemples ci-dessous)
  répertoire :  Une structure de répertoires contenant un système de fichiers (ch)root
  image :       Une image locale sur votre machine (sera convertie en sif si
                c'est un format
hérité)

Les cibles peuvent également être distantes et définies par une URI des formats suivants

: 
  library://  une bibliothèque d'images (aucune par défaut)
  docker://   un registre Docker/OCI (Docker Hub par défaut)
  shub://     un registre Apptainer (Singularity Hub par défaut)
  oras://     un registre OCI qui contient des fichiers SIF utilisant
ORAS

Fichiers temporaires

:

L'emplacement utilisé pour les répertoires temporaires est '/tmp' par défaut mais
peut être remplacé par la variable d'environnement TMPDIR, et celle-ci peut être
remplacée par la variable d'environnement APPTAINER_TMPDIR. Le
répertoire temporaire utilisé pendant une construction doit se trouver sur un système de fichiers qui
dispose d'un espace suffisant pour contenir l'intégralité de l'image du conteneur, non compressée,
y compris tous les fichiers temporaires qui sont créés puis supprimés
pendant la construction. Vous devrez peut-être définir APPTAINER_TMPDIR ou TMPDIR lors de la
construction d'un grand conten

eur sur un système ayant un p
etit système de fichiers /tmp.

OPTION

S

--arch="amd64" architecture pour laquelle

construire

--arch-variant="" variante d'architecture pour laquelle

construire

--authfile="" fichier d'authentification de style Docker à utiliser pour écrire/lire les identifiants de registre

OCI

-B, --bind=[] spécification de chemin de liaison utilisateur. La spécification a le format src[:dest[:opts]], où src et dest sont les chemins extérieur et intérieur. Si dest n'est pas indiqué, il est défini égal à src. Les options de montage ('opts') peuvent être spécifiées comme 'ro' (lecture seule) ou 'rw' (lecture/écriture, qui est la valeur par défaut).Plusieurs chemins de liaison peuvent être donnés sous forme de liste séparée par des

virgules.

--build-arg=[] définit variable=value pour remplacer les entrées {{ variable }} dans le fichier de définition de

construction

--build-arg-file="" spécifie un fichier contenant des lignes variable=value pour remplacer '{{ variable }}' par value dans les fichiers de définition de

construction

--disable-cache[=false] ne pas utiliser le cache ni créer de

cache

--docker-host="" spécifier un hôte de démon Docker

personnalisé

--docker-login[=false] se connecter de manière interactive à un dépôt

Docker

-e, --encrypt[=false] construire une image avec un système de fichiers

chiffré

-f, --fakeroot[=false] construire en ayant l'apparence de l'exécution en tant que root (par défaut lors de la construction à partir d'un fichier de définition non

privilégié)

--fix-perms[=false] s'assurer que le propriétaire dispose des permissions rwX sur tout le contenu du conteneur pour les sources

oci/docker

-F, --force[=false] écraser un fichier image s'il

existe

-h, --help[=false] aide pour

build

--json[=false] interpréter la définition de construction comme

JSON

--library="" URL de la bibliothèque de

conteneurs

--mksquashfs-args="" arguments supplémentaires à passer à mksquashfs lors de la création de fichiers

SIF

--mount=[] spécification de montage, par ex. 'type=bind,source=/opt,destination=/hostopt'

.

--no-cleanup[=false] NE PAS nettoyer le bundle après un échec de construction, peut être utile pour le

débogage

--no-https[=false] utiliser http au lieu de https pour les URI docker:// oras:// et library:///..

.

-T, --notest[=false] construire sans exécuter les tests dans la section

%test

--nv[=false] injecter les bibliothèques Nvidia de l'hôte pendant la construction pour les sections post et

test

--nvccli[=false] utiliser nvidia-container-cli pour la configuration GPU

(expérimental)

--passphrase[=false] demander une phrase secrète de

chiffrement

--pem-path="" indiquer un chemin vers une clé RSA au format PEM pour un conteneur

chiffré

--rocm[=false] injecter les bibliothèques Rocm de l'hôte pendant la construction pour les sections post et

test

-s, --sandbox[=false] construire l'image au format sandbox (structure de répertoires

chroot)

--section=[all] exécuter uniquement des sections spécifiques du deffile (setup, post, files, environment, test, labels,

none)

-u, --update[=false] exécuter la définition sur un conteneur existant (ignore

l'en-tête)

--userns[=false] construire sans utiliser setuid même si

disponible

--warn-unused-build-args[=false] affiche un avertissement au lieu d'un message fatal lorsque les arguments de construction ne correspondent pas

exactement

--writable-tmpfs[=false] pendant la section %test, rend le système de fichiers accessible en le

cture-écriture avec des données non persistantes
(avec prise en charge de l'overlay uniquement)

EXEMPL

E 
  FICHIER DEF OS DE BASE :
      Library :
          Bootstrap : library
          From : debian:9
      Docker :
          Bootstrap : docker
          From : tensorflow/tensorflow:latest
          IncludeCmd : yes # Utiliser le CMD comme runscript au lieu de ENTRYPOINT
      Singularity Hub :
          Bootstrap : shub
          From : singularityhub/centos
      YUM/RHEL :
          Bootstrap : yum
          OSVersion : 7
          MirrorURL : http://mirror.centos.org/centos-%{OSVERSION}/%{OSVERSION}/os/x86_64/
          Include : yum
      SUSE :
          Bootstrap : zypper # sur un système SLE, l'enregistrement de l'hôte de construction est utilisé
          Include : zypper
      openSUSE :
          Bootstrap : zypper
          MirrorURL : http://download.opensuse.org/distribution/openSUSE-stable/repo/oss
          Include : zypper
      Debian/Ubuntu :
          Bootstrap : debootstrap
          OSVersion : trusty
          MirrorURL : http://us.archive.ubuntu.com/ubuntu/
      Image locale :
          Bootstrap : localimage
          From : /home/dave/starter.img
      Scratch :
          Bootstrap : scratch # Remplir le conteneur avec un rootfs minimal dans %setup
  SECTIONS DU DEFFILE :
  Les sections suivantes sont présentées dans l'ordre de traitement, à l'exception
  que labels et environment peuvent également être manipulés dans %post.
      %pre
          echo "Ceci est un scriptlet qui sera exécuté sur l'hôte, en tant que root, avant"
          echo "que le conteneur ait été amorcé. Cette section n'est pas couramment utilisée."
      %setup
          echo "Ceci est un scriptlet qui sera exécuté sur l'hôte, en tant que root, après"
          echo "que le conteneur ait été amorcé. Pour installer des choses dans le conteneur,"
          echo "référencez l'emplacement du système de fichiers avec $APPTAINER_ROOTFS."
      %files
          /path/on/host/file.txt /path/on/container/file.txt
          relative_file.txt /path/on/container/relative_file.txt
      %post
          echo "Cette section de scriptlet sera exécutée depuis l'intérieur du conteneur après"
          echo "que la base d'amorçage ait été créée et configurée."
      %environment
          LUKE=goodguy
          VADER=badguy
          HAN=someguy
          export HAN VADER LUKE
      %test
          echo "Définissez toutes les commandes de test qui doivent être exécutées après que le conteneur ait été"
          echo "construit. Ce scriptlet sera exécuté depuis l'intérieur du conteneur en cours d'exécution"
          echo "en tant qu'utilisateur root. Faites attention à la valeur de sortie/retour de ce scriptlet"
          echo "car tout code de sortie non nul sera considéré comme un échec."
          exit 0
      %runscript
          echo "Définissez les actions que le conteneur doit exécuter avec la commande run ou"
          echo "lorsque le conteneur est exécuté."
      %startscript
          echo "Définissez les actions que le conteneur doit effectuer lorsqu'il est démarré en tant qu'instance."
      %labels
          HELLO MOTO
          KEY VALUE
      %help
          Ceci est un fichier texte à afficher avec la commande run-help.
  COMMANDES :
      Construire un fichier sif à partir d'un fichier recette Apptainer :
          $ apptainer build /tmp/debian0.sif /path/to/debian.def
      Construire une image sif à partir de la bibliothèque :
          $ apptainer build /tmp/debian1.sif library://debian:latest
      Construire une sandbox de base à partir de DockerHub, y apporter des
modifications, puis construire un sif $ apptainer build --sandbox /tmp/debian docker://debian:latest
$ apptainer exec --writable /tmp/debian apt-get install python $ apptainer build /tmp/debian2.sif /tmp/debian
