et sémantique des mot
ifs de recherche d'apt

DESCRIPTIO

N

À partir de la version 2.0, APT prend en charge les motifs, qui peuvent être utilisés pour interroger le cache d'apt à la recherche de paquets. APT fournit un support pour les motifs, qui peuvent être uti

lisés pour interroger le cache
d'apt à la recherche de paquets.

MOTIFS

LOGIQUES

Ces motifs fournissent les moyens de base pour combiner d'autres motifs en expressions plus complexes, ainsi que les motifs ?true et ?

false.

?and(MOTIF, MOTIF, ...), MOTIF MOTIF ..

.
Sélectionne les objets où tous les motifs spécifiés
correspondent.

?false,

~F
Ne sélectionne
rien.

?not(MOTIF), !

MOTIF
Sélectionne les objets où MOTIF ne correspond
pas.

?or(MOTIF, MOTIF, ...), MOTIF | MOTIF | ..

.
Sélectionne les objets où au moins un des motifs spécifiés
correspond.

?true,

~T
Sélectionne tous les
objets.

(MOTIF

)
Sélectionne la même chose que MOTIF, peu
t être utilisé pour contourner la prio
rité, par exemple, (~ramd64|~ri386)~nfoo

MOTIFS DE

RESTRECTION

?all-versions(MOTIF

)
Sélectionne les paquets où toutes les versions correspondent à MOTIF. Lorsqu'on fait correspondre des versions, c'est la même chose que
MOTIF.

?any-version(MOTIF

)
Sélectionne n'importe quelle version où le motif correspond sur la version.

Par exemple, alors que ?and(?version(1),?version(2)) correspond à un paquet

qui a une version contenant 1 et une version contenant 2, ?any-version(?a
nd(?version(1),?version(2))) restreint le ?and à agir sur la même version.

?narrow(MOTIF...

)
Sélectionne n'importe quelle version correspondant à tous les MOTIFs, abréviation de ?any-version(?and(MOTIF...
))
.

MOTIFS DE

PAQUET

Ces motifs sélectionnent des paquets

spécifiques.

?architecture(GLOBO),

~rGLOBO
Sélectionne les paquets correspondant à l'architecture spécifiée, qui peut contenir des globules utilisant
any.

?automatic,

~M
Sélectionne les paquets qui ont été installés automatiquement
.

?broken,

~b
Sélectionne les paquets qui ont des dépendances
cassées.

?config-files,

~c
Sélectionne les paquets qui ne sont pas entièrement installés, mais ont uniquement des fichiers de configuration
résiduels.

?essential,

~E
Sélectionne les paquets qui ont Essential: yes défini dans leur fichier de
contrôle.

?

exact-name(NOM)
Sélectionne les paquets avec le nom exact
spécifié.

?garbage,

~g
Sélectionne les paquets qui peuvent être supprimés automatiquement
.

?installed,

~i
Sélectionne les paquets qui sont actuellement installés. Depuis la version 2.5.4, restreindre ce motif (voir les motifs de restriction ci-dessus) le fait uniquement correspondre aux versions installées (voir les motifs de version ci-dessous)
.

?name(REGEX),

~nREGEX
Sélectionne les paquets où le nom correspond à l'expression régulière
donnée.

?obsolete,

~o
Sélectionne les paquets qui n'existent plus dans les
dépôts.

?

phasing
Sélectionne les paquets qui seront maintenus en attente lors des mises à jour en raison du
phasing.

?upgradable,

~U
Sélectionne les paquets qui peuvent être mis à jour (ont un candidat plus récent)
.

?virtual,

~v
Sélectionne tous les paquets virtuels ; c'est-à-dire les paquets sans
version. Ceux-ci existent lorsqu'ils sont référencés quelque part d
ans l'archive, par exemple parce que quelque chose dépend de ce nom.

MOTIFS DE

VERSION

Ces motifs sélectionnent des versions spécifiques d'un

paquet.

?archive(REGEX),

~AREGEX
Sélectionne les versions qui proviennent de l'archive qui correspond à l'expression régulière spécifiée. Archive, ici, signifie les valeurs après a= dans apt-cache p
olicy.

?

codename(REGEX)
Sélectionne les versions qui proviennent du codename qui correspond à l'expression régulière spécifiée. Codename, ici, signifie les valeurs après n= dans apt-cache p
olicy.

?installed,

~i
Sélectionne les versions de paquets qui sont actuellement installées. Les versions antérieures à 2.5.4 ne correspondaient qu'au niveau du paquet, d'où ?any-version(?installed?version(2.0)) correspondait même si 2.0 n'était pas installé, mais qu'une autre version
l'était.

?origin(REGEX),

~OREGEX
Sélectionne les versions qui proviennent de l'origine qui correspond à l'expression régulière spécifiée. Origine, ici, signifie les valeurs après o= dans apt-cache p
olicy.

?section(REGEX),

~sREGEX
Sélectionne les versions où la section correspond à l'expression régulière
spécifiée.

?source-package(REGEX),

~eREGEX
Sélectionne les versions où le nom du paquet source correspond à l'expression régulière
spécifiée.

?source-version(REGEX

)
Sélectionne les versions où la version du paquet source correspond à l'expression régulière
spécifiée.

?version(REGEX),

~VREGEX
Sélectionne les versions où la chaîne de version correspond à l'expression régulière
spécifiée.

?priority(NOM),

~pNOM
Sélectionne les versions où la chaîne Priority est égale au nom
donné.

?

security
Sélectionne les paquets qui sont une
mise à jour de sécurité ou qui succè
dent à une mise à jour de sécurité.

MOTIFS DE RELATION DE

PAQUET

Ces motifs correspondent à des versions de paquets spécifiques qui dépendent/entrent en conflit avec d'autres

paquets.

?depends(MOTIF), ~DMOTIF, ?pre-depends(MOTIF), ~DPre-Depends:MOTIF, ?suggests(MOTIF), ~DSuggests:MOTIF, ?recommends(MOTIF), ~DRecommends:MOTIF, ?conflicts(MOTIF), ~DConflicts:MOTIF, ?replaces(MOTIF), ~DReplaces:MOTIF, ?obsoletes(MOTIF), ~DObsoletes:MOTIF, ?breaks(MOTIF), ~DBreaks:MOTIF, ?enhances(MOTIF), ~DEnhances:

MOTIF
Sélectionne les versions dépendant/pré-dépendant/suggérant/recommandant/entrant en conflit/etc avec des paquets correspondant à
MOTIF.

?reverse-depType(MOTIF), ~RDepType:M

OTIF
L'opposé de ?depends et compagnie - sélectionne tous les paquets qui ont des dépendances inverses (versions) correspondant à MOTIF.

depType est l'un des types de dépendances tels que depend

s, afin que nous n'ayons
pas à répéter toute la liste
du premier paragrappe ici.

MIGRATION DEPUIS

APTITUDE

Les motifs dans apt sont fortement inspirés des motifs dans aptitude, mais avec quelques ajustements

:
•La syntaxe est uniforme : S'il y a une parenthèse ouvrante après un terme, elle est toujours supposée être le début d'une liste d'arguments.

Dans aptitude, une forme syntaxique "?foo(bar)" pouva

it signifier "?and(?foo,bar)" si foo ne prend pas
d'argument. Dans APT, cela provoquera une erreur.
•Tous les motifs ne sont pas pris en
charge.
•Certains motifs supplémentaires sont disponibles, par exemple, pour trouver les codecs
gstreamer.
•L'échappement des termes avec ~ n'est pas pris en
charge.
•Une virgule finale est autorisée dans les listes
d'arguments
?narrow accepte un nombre infini
d'arguments
foo ne peut pas être utilisé comme forme abrégée de ?name(foo), car tCela peut faire passer des fautes de frappe inaperçues : considérez ?and(...,~poptional) : cela exige que le paquet ait la priorité requise, mais si vous n'entrez pas le ~, cela exigerait que le nom du paquet contienne
poptional.
•Les types de dépendances pour ~D et
les opérateurs associés doivent êt
re spécifiés dans la casse canonique.
