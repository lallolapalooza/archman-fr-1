apk-add(8) Manuel de l'administrateur système apk-add(8)

NOM

apk add - ajouter ou mettre à jour des contraintes dans le world et valider les modifications

SYNTAXE

apk add [<options>...] contraintes...

DESCRIPTION

apk add ajoute ou met à jour les contraintes données dans le world (voir apk-world(5)) et valide les modifications sur le disque. Cela implique généralement l'installation de nouveaux paquets, mais peut également entraîner d'autres modifications des paquets installés.

Pour mettre à jour des paquets individuels sans modifier le world, utilisez apk-fix(8).

Par défaut, apk essaie de sélectionner un ensemble de paquets de manière à satisfaire toutes les contraintes. Cela signifie que certains paquets peuvent être retenus dans une version plus ancienne s'il existe des dépendances directes ou implicites à la version plus ancienne.

OPTIONS

apk add prend en charge les options de validation décrites dans apk(8), ainsi que les options suivantes :

--initdb

Initialise une nouvelle base de données de paquets.

--latest, -l

Choisit toujours le paquet le plus récent en termes de version. Cependant, les versions considérées sont basées sur l'épinglage des paquets. Principalement, cela remplace l'heuristique par défaut et provoquera l'affichage d'une erreur si toutes les dépendances ne peuvent pas être satisfaites.

--no-chown

Alias obsolète pour --usermode.

--upgrade, -u

Met à jour les paquets et leurs dépendances. Normalement, apk add évite de modifier les paquets installés sauf s'ils sont requis par les nouveaux paquets ajoutés ou leurs dépendances. Ceci change la préférence par défaut de mise à niveau du paquet vers la dernière version installable.

--usermode

Crée une base de données utilisateur avec --initdb. En mode utilisateur, apk fonctionnera de manière à ne pas nécessiter les privilèges root. Actuellement, cela implique :
  • la vérification que nous ne nous exécutons pas en tant que non-root
  • ne pas changer le propriétaire ou le groupe de fichier
  • ne pas définir d'attributs étendus système

Cela implique que l'installation pourrait ne pas être entièrement fonctionnelle. Cependant, ce mode est utile à des fins de test ou pour créer un chroot où certaines applications spécifiques peuvent s'exécuter en tant que non-root.

--virtual, -t NOM

Crée un paquet virtuel nommé NOM avec les dépendances spécifiées. Ce nouveau paquet obtiendra les paquets comme dépendances au lieu du world. Finalement, le NOM est ajouté au world. Un spécificateur de version optionnel pour le paquet virtuel peut être donné via la syntaxe NOM=VERSION. La version est par défaut une version synthétisée basée sur l'heure.

On peut l'utiliser pour s'assurer qu'un ensemble sélectionné de paquets est installé, et plus tard que la modification temporaire peut être annulée avec apk-del(8) NOM sans supprimer les paquets qui ont été installés précédemment.
