DESCRIPTIO

N

apt-get est l'outil en ligne de commande pour la gestion des paquets, et peut être considéré comme le « back-end » de l'utilisateur pour d'autres outils utilisant la bibliothèque APT. Plusieurs interfaces « front-end » existent, telles que aptitude(8), synaptic(8) et wajig(

1).

À moins que l'option -h, ou --help soit donnée, l'une des commandes suivantes doit être

présente.

updat

e
update est utilisé pour resynchroniser les fichiers d'index des paquets à partir de leurs sources. Les index des paquets disponibles sont récupérés depuis les emplacements spécifiés dans /etc/apt/sources.list. Par exemple, lors de l'utilisation d'une archive Debian, cette commande récupère et analyse les fichiers Packages.gz, afin que les informations sur les nouveaux paquets et les paquets mis à jour soient disponibles. Une mise à jour doit toujours être effectuée avant une mise à niveau (upgrade) ou une mise à niveau de la distribution (dist-upgrade). Veuillez noter que la jauge de progression globale sera incorrecte car la taille des fichiers de paquets ne peut pas être connue à
l'avance.

upgrad

e
upgrade est utilisé pour installer les versions les plus récentes de tous les paquets actuellement installés sur le système à partir des sources énumérées dans /etc/apt/sources.list. Les paquets actuellement installés pour lesquels de nouvelles versions sont disponibles sont récupérés et mis à niveau ; en aucun cas les paquets actuellement installés ne sont supprimés, ni les paquets non déjà installés récupérés et installés. Les nouvelles versions des paquets actuellement installés qui ne peuvent pas être mises à niveau sans changer l'état d'installation d'un autre paquet resteront à leur version actuelle. Une mise à jour doit d'abord être effectuée pour que apt-get sache que de nouvelles versions de paquets sont disponibles.

Lorsqu'un paquet est fourni en arg

ument, le paquet sera install
é avant l'action de mise à niveau.

dist-upgrad

e
dist-upgrade, en plus de réaliser la fonction de upgrade, gère également de manière intelligente le changement des dépendances avec les nouvelles versions des paquets ; apt-get dispose d'un système « intelligent » de résolution des conflits, et essaiera de mettre à niveau les paquets les plus importants au détriment des moins importants si nécessaire. La commande dist-upgrade peut donc supprimer certains paquets. Le fichier /etc/apt/sources.list contient une liste d'endroits à partir desquels récupérer les fichiers de paquets souhaités. Voir aussi apt_preferences(5) pour un mécanisme permettant de remplacer les paramètres généraux pour des paquets individuels.

Lorsqu'un paquet est fourni en arg

ument, le paquet sera install
é avant l'action de mise à niveau.

dselect-upgrad

e
dselect-upgrade est utilisé en conjonction avec le front-end traditionnel de packaging Debian, dselect(1). dselect-upgrade suit les modifications effectuées par dselect(1) sur le champ Status des paquets disponibles, et effectue les actions nécessaires pour réaliser cet état (par exemple, la suppression des anciens et l'installation des nouveaux paquets)
.

instal

l
install est suivi d'un ou plusieurs paquets souhaités pour l'installation ou la mise à niveau. Chaque paquet est un nom de paquet, et non un nom de fichier entièrement qualifié (par exemple, dans un système Debian, apt-utils serait l'argument fourni, et non apt-utils_3.1.12_amd64.deb). Tous les paquets requis par le ou les paquets spécifiés pour l'installation seront également récupérés et installés. Le fichier /etc/apt/sources.list est utilisé pour localiser les paquets souhaités. Si un tiret est ajouté au nom du paquet (sans espace intermédiaire), le paquet identifié sera supprimé s'il est installé. De même, un signe plus peut être utilisé pour désigner un paquet à installer. Ces dernières fonctionnalités peuvent être utilisées pour remplacer les décisions prises par le système de résolution des conflits d'apt-get.

Une version spécifique d'un paquet peut être sélectionnée pour l'installation en suivant le nom du paquet par un signe égal et la version du paquet à sélectionner. Cela aura pour effet de localiser et de sélectionner cette version pour l'installation. Alternativement, une distribution spécifique peut être sélectionnée en suivant le nom du paquet par une barre oblique et la version de la distribution ou le nom de l'archive (stable, testing, unstable)

.

Les deux mécanismes de sélection de version peuvent rétrograder des paquets et doivent être utilisés avec

prudence.

C'est également la cible à utiliser si vous souhaitez mettre à niveau un ou plusieurs paquets déjà installés sans mettre à niveau chaque paquet que vous avez sur votre système. Contrairement à la cible « upgrade », qui installe la version la plus récente de tous les paquets actuellement installés, « install » n'installera que la version la plus récente du ou des paquets spécifiés. Il suffit de fournir le nom du ou des paquets que vous souhaitez mettre à niveau, et si une version plus récente est disponible, celle-ci (et ses dépendances, comme décrit ci-dessus) sera téléchargée et

installée.

Enfin, le mécanisme apt_preferences(5) vous permet de créer une politique d'alternative d'installation pour des paquets

individuels.

Si aucun paquet ne correspond à l'expression donnée et que l'expression contient l'un de '.', '?' ou '*', elle est supposée être une expression rationnelle POSIX, et elle est appliquée à tous les noms de paquets dans la base de données. Toutes les correspondances sont alors installées (ou supprimées). Notez que la correspondance se fait par sous-chaîne, donc 'lo.*' correspond à 'how-lo' et 'lowest'. Si cela est indésirable, ancrez l'expression rationnelle avec un caractère '^' ou '$', ou créez une expression rationnelle plus

spécifique.

Le recours aux expressions rationnelles est déprécié dans APT 2.0, a été supprimé dans apt(8), sauf pour les expressions ancrées, et sera supprimé de apt-get(8) dans une version future. Utilisez apt-patterns(7

) à la
place.

reinstal

l
reinstall est un alias pour install
--reinstall.

remov

e
remove est identique à install sauf que les paquets sont supprimés au lieu d'être installés. Notez que la suppression d'un paquet laisse ses fichiers de configuration sur le système. Si un signe plus est ajouté au nom du paquet (sans espace intermédiaire), le paquet identifié sera installé au lieu d'être
supprimé.

purg

e
purge est identique à remove sauf que les paquets sont supprimés et purgés (tous les fichiers de configuration sont également supprimés)
.

sourc

e
source fait apt-get récupérer les paquets source. APT examinera les paquets disponibles pour décider quel paquet source récupérer. Il trouvera ensuite et téléchargera dans le répertoire courant la version la plus récente disponible de ce paquet source tout en respectant la version par défaut, définie avec l'option APT::Default-Release, l'option -t ou par paquet avec la syntaxe paquet/version, si possible.

Les arguments sont interprétés comme des noms de paquets binaires et source. Voir l'option --only-source si vous souhaitez changer

cela.

Les paquets source sont suivis séparément des paquets binaires via des lignes deb-src dans le fichier sources.list(5). Cela signifie que vous devrez ajouter une telle ligne pour chaque dépôt à partir duquel vous voulez obtenir les sources ; sinon, vous obtiendrez probablement soit les mauvaises versions source (trop anciennes/trop récentes), soit

aucune.

Si l'option --compile est spécifiée, le paquet sera compilé en un binaire .deb en utilisant dpkg-buildpackage pour l'architecture définie par l'option --host-architecture. Si --download-only est spécifié, le paquet source ne sera pas

décompressé.

Une version source spécifique peut être récupérée en postfixant le nom source par un signe égals puis la version à récupérer, similaire au mécanisme utilisé pour les fichiers de paquets. Cela permet une correspondance exacte du nom et de la version du paquet source, activant implicitement l'option APT::Get::

Only-Source.

Notez que les paquets sources ne sont pas installés et suivis dans la base de données dpkg comme les paquets binaires ; ils sont simplement téléch

argés dans le répertoire couran
t, comme les archives sources.

build-de

p
build-dep fait en sorte qu'apt-get installe/supprime des paquets pour satisfaire les dépendances de compilation d'un paquet source. Par défaut, les dépendances sont satisfaites pour compiler le paquet nativement. Si vous le souhaitez, une architecture hôte peut être spécifiée avec l' --host-architecture à la place.

Les arguments sont interprétés comme des noms de paquets binaires ou sources. Voir l' --only-source si vous

souhaitez ch
anger cela.

satisf

y
satisfy fait en sorte qu'apt-get satisfasse les chaînes de dépendances données. Les chaînes de dépendances peuvent avoir des profils de compilation et des listes de restrictions d'architecture comme dans les dépendances de compilation. Elles peuvent éventuellement être préfixées par "Conflicts: " pour ne pas satisfaire la chaîne de dépendance. Plusieurs chaînes du même type peuvent être spécifiées.

Exemple : apt-get satisfy "foo" "Conflicts: bar" "baz (>> 1.0) | bar (= 2.0),

moo"

L'opérateur hérité '</>' n

'est pas supporté, utilis
ez '<=/>=' à la place.

chec

k
check est un outil de diagnostic ; il met à jour le cache des paquets et vérifie les dépendances
cassées.

downloa

d
download téléchargera le paquet binaire donné dans le répertoire courant. L'authenticité des données du paquet est assurée comme
d'habitude.

clea

n
clean vide le dépôt local des fichiers de paquets récupérés. Il supprime tout sauf le fichier de verrouillage de /var/cache/apt/archives/ et /var/cache/apt/archives/partial/
.

autoclean (et l'alias auto-clean depuis la version 1.

1)
Comme clean, autoclean vide le dépôt local des fichiers de paquets récupérés. La différence est qu'il ne supprime que les fichiers de paquets qui ne peuvent plus être téléchargés et sont largement inutiles. Cela permet de maintenir un cache sur une longue période sans qu'il ne dégénère. L'option de configuration APT::Clean-Installed empêchera l'effacement des paquets installés si elle est définie à
off.

distclean (et l'alias dist-clean

)
distclean supprime tous les fichiers sous /var/lib/apt/lists sauf Release, Release.gpg et InRelease. Il peut être utilisé par exemple lors de la finalisation d'images distribuées aux utilisateurs. Les fichiers de version sont conservés pour des raisons de sécurité, afin de prévenir divers types
d'attaques.

autoremove (et l'alias auto-remove depuis la version 1.

1)
autoremove est utilisé pour supprimer les paquets qui ont été installés automatiquement pour satisfaire les dépendances d'autres paquets et qui ne sont plus
nécessaires.

autopurg

e
Comme autoremove, mais autopurge supprime aussi les fichiers de configuration. C'est un raccourci pour autoremove
--purge.

changelo

g
changelog essaie de télécharger le journal des modifications d'un paquet et l'affiche à travers sensible-pager. Par défaut, il affiche le journal des modifications de la version installée. Cependant, vous pouvez spécifier les mêmes options que pour la commande in
stall.

indextarget

s
Affiche par défaut une liste au format deb822 des informations sur tous les fichiers de données (aussi appelés cibles d'index) que apt-get update téléchargerait. Supporte une --format pour modifier le format de sortie ainsi qu'accepte des lignes de la sortie par défaut pour filtrer les enregistrements. La commande est principalement utilisée comme interface pour les outils externes travaillant avec APT pour obtenir des informations ainsi que les noms
de fichiers des fichiers téléchargés afin qu'ils puissent les utiliser au lieu de les retélécharger eux-mêmes. La documentation détaillée e
st omise ici et peut être trouvée à la place dans le fichier /usr/share/doc/apt/acquire-additional-files.md.gz fourni par le paquet apt-doc.

OPTION

S

Toutes les options de ligne de commande peuvent être définies en utilisant le fichier de configuration ; les descriptions indiquent l'option de configuration à définir. Pour les options booléennes, vous pouvez outrepasser le fichier de configuration en utilisant quelque chose comme -f-,--no-f, -f=no ou plusieurs autres

variations.

--no-install-recommend

s
Ne pas considérer les paquets recommandés comme une dépendance pour l'installation. Élément de configuration : APT::Install-Recommends
.

--install-suggest

s
Considérer les paquets suggérés comme une dépendance pour l'installation. Élément de configuration : APT::Install-Suggests
.

-d, --download-onl

y
Télécharger uniquement ; les fichiers de paquets sont seulement récupérés, pas dépaquetés ou installés. Élément de configuration : APT::Get::
Download-Only.

-f, --fix-broke

n
Réparer ; tenter de corriger un système avec des dépendances cassées sur place. Cette option, lorsqu'elle est utilisée avec install/remove, peut omettre certains paquets pour permettre à APT de déduire une solution probable. Si des paquets sont spécifiés, ceux-ci doivent corriger complètement le problème. L'option est parfois nécessaire lors de la première exécution d'APT ; APT lui-même ne permet pas l'existence de dépendances de paquets cassées sur un système. Il est possible que la structure des dépendances d'un système soit si corrompue qu'elle nécessite une intervention manuelle (ce qui signifie généralement d'utiliser dpkg --remove pour éliminer certains des paquets problématiques). L'utilisation de cette option avec -m peut produire une erreur dans certaines situations. Élément de configuration : APT::Get::
Fix-Broken.

-m, --ignore-missing, --fix-missin

g
Ignorer les paquets manquants ; si des paquets ne peuvent pas être récupérés ou échouent au test d'intégrité après la récupération (fichiers de paquets corrompus), mettre ces paquets en attente et gérer le résultat. L'utilisation de cette option avec -f peut produire une erreur dans certaines situations. Si un paquet est sélectionné pour l'installation (particulièrement s'il est mentionné sur la ligne de commande) et qu'il n'a pas pu être téléchargé, il sera silencieusement mis en attente. Élément de configuration : APT::Get::
Fix-Missing.

--no-downloa

d
Désactive le téléchargement des paquets. C'est mieux utilisé avec --ignore-missing pour forcer APT à utiliser uniquement les .debs qu'il a déjà téléchargés. Élément de configuration : APT::Get::
Download.

-q, --quie

t
Silencieux ; produit une sortie adaptée à la journalisation, omettant les indicateurs de progression. Plus de q produira plus de silence jusqu'à un maximum de 2. Vous pouvez aussi utiliser -q=# pour définir le niveau de silence, en outrepassant le fichier de configuration. Notez que le niveau de silence 2 implique -y ; vous ne devriez jamais utiliser -qq sans un modificateur d'absence d'action tel que -d, --print-uris ou -s car APT pourrait décider de faire quelque chose que vous n'attendiez pas. Élément de configuration :
quiet.

-s, --simulate, --just-print, --dry-run, --recon, --no-ac

t
Aucune action ; effectue une simulation des événements qui se produiraient sur la base de l'état actuel du système mais ne change pas réellement le système. Le verrouillage sera désactivé (Debug::NoLocking) donc l'état du système pourrait changer pendant l'exécution d'apt-get. Les simulations peuvent aussi être exécutées par des utilisateurs non-root qui pourraient ne pas avoir d'accès en lecture à toute la configuration d'apt, faussant la simulation. Un avis exprimant cet avertissement est aussi affiché par défaut pour les utilisateurs non-root (APT::Get::Show-User-Simulation-Note). Élément de configuration : APT::Get::Simulate.

Les exécutions simulées affichent une série de lignes, chacune représentant une opération dpkg : configurer (Conf), supprimer (Remv) ou dépaqueter (Inst). Les crochets indi

quent les paquets cassés, et les crochets vides
indiquent des ruptures sans conséquence (rare).

-y, --yes, --assume-ye

s
Réponse "oui" automatique aux invites ; suppose "oui" comme réponse à toutes les invites et s'exécute de manière non interactive. Si une situation indésirable survient, comme changer un paquet en attente, essayer d'installer un paquet non authentifié ou supprimer un paquet essentiel, apt-get interrompra son exécution. Élément de configuration : APT::Get::
Assume-Yes.

--assume-n

o
Réponse "non" automatique à toutes les invites. Élément de configuration : APT::Get::
Assume-No.

--no-show-upgrade

d
Ne pas afficher la liste de tous les paquets qui doivent être mis à niveau. Élément de configuration : APT::Get::
Show-Upgraded.

-V, --verbose-version

s
Afficher les versions complètes pour les paquets mis à niveau et installés. Élément de configuration : APT::Get::
Show-Versions.

--no-list-column

s
Afficher les listes de paquets sans les organiser en colonnes. Par défaut, les listes de paquets sont imprimées dans le style de la commande "ls". Élément de configuration : APT::Get::
List-Columns.

--commen

t
Ajouter la valeur donnée au champ Comment: dans history.log. Élément de configuration : APT::History::
Comment.

-a, --host-architectur

e
Cette option contrôle l'architecture pour laquelle les paquets sont construits par apt-get source --compile et comment les dépendances de compilation croisée sont satisfaites. Par défaut, elle n'est pas définie, ce qui signifie que l'architecture hôte est la même que l'architecture de compilation (qui est définie par APT::Architecture). Élément de configuration : APT::Get::Host-Architecture
.

-P, --build-profile

s
Cette option contrôle les profils de compilation activés pour lesquels un paquet source est construit par apt-get source --compile et comment les dépendances de compilation sont satisfaites. Par défaut, aucun profil de compilation n'est actif. Plus d'un profil de compilation peut être activé à la fois en les concaténant avec une virgule. Élément de configuration : APT::
Build-Profiles.

-b, --compile, --buil

d
Compiler les paquets sources après leur téléchargement. Élément de configuration : APT::Get::
Compile.

--ignore-hol

d
Ignorer les mises en attente de paquets ; cela fait en sorte qu' apt-get ignore une mise en attente placée sur un paquet. Cela peut être utile en conjonction avec dist-upgrade pour outrepasser un grand nombre de mises en attente indésirables. Élément de configuration : APT::
Ignore-Hold.

--with-new-pkg

s
Permettre l'installation de nouveaux paquets lorsqu'il est utilisé en conjonction avec upgrade. C'est utile si la mise à jour d'un paquet installé nécessite l'installation de nouvelles dépendances. Au lieu de mettre le paquet en attente, upgrade mettra à niveau le paquet et installera les nouvelles dépendances. Notez que upgrade avec cette option ne supprimera jamais de paquets, seulement permettra d'en ajouter de nouveaux. Élément de configuration : APT::Get::Upgrade-Allow-New
.

--no-upgrad

e
Ne pas mettre à niveau les paquets ; lorsqu'il est utilisé en conjonction avec install, no-upgrade empêchera les paquets sur la ligne de commande d'être mis à niveau s'ils sont déjàdéjà installé. Élément de configuration : APT::Get::
Upgrade.

--only-upgrad

e
Ne pas installer de nouveaux paquets ; lorsqu'il est utilisé en conjonction avec install, only-upgrade n'installera que les mises à jour de paquets déjà installés et ignorera les demandes d'installation de nouveaux paquets. Élément de configuration : APT::Get::
Only-Upgrade.

--allow-downgrade

s
Ceci est une option dangereuse qui fera continuer apt sans demander confirmation s'il effectue des rétrogradations. Elle ne devrait pas être utilisée sauf dans des situations très particulières. Son utilisation peut potentiellement détruire votre système ! Élément de configuration : APT::Get::allow-downgrades. Introduite dans APT 1.
1.

--allow-remove-essentia

l
Force yes ; ceci est une option dangereuse qui fera continuer apt sans demander confirmation s'il supprime des éléments essentiels. Elle ne devrait pas être utilisée sauf dans des situations très particulières. Son utilisation peut potentiellement détruire votre système ! Élément de configuration : APT::Get::allow-remove-essential. Introduite dans APT 1.
1.

--allow-change-held-package

s
Force yes ; ceci est une option dangereuse qui fera continuer apt sans demander confirmation s'il modifie des paquets retenus. Elle ne devrait pas être utilisée sauf dans des situations très particulières. Son utilisation peut potentiellement détruire votre système ! Élément de configuration : APT::Get::allow-change-held-packages. Introduite dans APT 1.
1.

--force-ye

s
Force yes ; ceci est une option dangereuse qui fera continuer apt sans demander confirmation s'il effectue une action potentiellement nuisible. Elle ne devrait pas être utilisée sauf dans des situations très particulières. L'utilisation de force-yes peut potentiellement détruire votre système ! Élément de configuration : APT::Get::force-yes. Cette option est obsolète et remplacée par --allow-unauthenticated , --allow-downgrades , --allow-remove-essential , --allow-change-held-packages dans la version 1.
1.

--print-uri

s
Au lieu de récupérer les fichiers, leurs URI sont affichés. Chaque URI contiendra le chemin, le nom du fichier de destination, la taille et l'empreinte MD5 attendue. Notez que le nom du fichier à écrire ne correspondra pas toujours au nom du fichier sur le site distant ! Cela fonctionne aussi avec les commandes source et update. Lorsqu'il est utilisé avec la commande update, l'empreinte MD5 et la taille ne sont pas incluses, et il appartient à l'utilisateur de décompresser les fichiers compressés. Élément de configuration : APT::Get::
Print-URIs.

--purg

e
Utiliser purge au lieu de remove pour tout ce qui serait supprimé. Un astérisque (« * ») sera affiché à côté des paquets qui sont programmés pour être purgés. remove --purge est équivalent à la commande purge. Élément de configuration : APT::Get::
Purge.

--reinstal

l
Réinstaller les paquets déjà installés et à la version la plus récente. Élément de configuration : APT::Get::
ReInstall.

--list-cleanu

p
Cette option est activée par défaut ; utilisez --no-list-cleanup pour la désactiver. Lorsqu'elle est activée, apt-get gérera automatiquement le contenu de /var/lib/apt/lists pour s'assurer que les fichiers obsolètes sont effacés. La seule raison de la désactiver est si vous modifiez fréquemment votre liste de sources. Élément de configuration : APT::Get::
List-Cleanup.

-S, --snapsho

t
Cette option contrôle l'instantané choisi pour les archives avec Snapshot: enable dans l'entrée de source. Par exemple, -S 20220102T030405Z sélectionne un instantané du 2 janvier 2022 à 03:04:05 UTC. Élément de configuration : APT::Snapshot ; voir aussi la page de manuel sources.list(5)
.

-t, --target-release, --default-releas

e
Cette option contrôle l'entrée par défaut du moteur de politique ; elle crée un épinglage par défaut à la priorité 990 en utilisant la chaîne de version spécifiée. Cela remplace les paramètres généraux dans /etc/apt/preferences. Les paquets épinglés spécifiquement ne sont pas affectés par la valeur de cette option. En résumé, cette option vous permet d'avoir un contrôle simple sur la distribution à partir de laquelle les paquets seront récupérés. Quelques exemples courants pourraient être -t '2.1*', -t unstable ou -t sid. Élément de configuration : APT::Default-Release ; voir aussi la page de manuel apt_preferenc
es(5).

--trivial-onl

y
N'effectuer que les opérations qui sont « triviales ». Logiquement, cela peut être considéré comme lié à --assume-yes ; là où --assume-yes répondra oui à toute demande de confirmation, --trivial-only répondra non. Élément de configuration : APT::Get::
Trivial-Only.

--mark-aut

o
Après une installation réussie, marquer tous les paquets nouvellement installés comme installés automatiquement, ce qui fera en sorte que chacun de ces paquets sera supprimé lorsque plus aucun paquet installé manuellement ne dépendra de lui. Cela revient à exécuter apt-mark auto pour tous les paquets installés. Élément de configuration : APT::Get::
Mark-Auto.

--no-remov

e
Si des paquets doivent être supprimés, apt-get annule immédiatement sans demander confirmation. Élément de configuration : APT::Get::
Remove.

--auto-remove, --autoremov

e

--allow-unauthenticate

d

Cela peut être utile lors du travail avec des dépôts locaux, mais représente un énorme risque de sécurité si l'authenticité des données n'est pas assurée d'une autre manière par l'utilisateur lui-même. L'utilisation de l'option Trusted pour les entrées sources.list(5) devrait généralement être préférée à ce contournement global. Élément de configuration : APT::Get::AllowUnauthenticated

--allow-insecure-repositorie

s
Autoriser la commande update à acquérir des données non vérifiables à partir des sources configurées. APT échouera sinon à la commande update pour les dépôts sans signatures cryptographiques valides. Voir aussi apt-secure(8) pour des détails sur le concept et ses implications. Élément de configuration : Acquire::AllowInsecureRepositories
.

--allow-releaseinfo-chang

e
Autoriser la commande update à continuer le téléchargement des données depuis un dépôt qui a modifié ses informations sur la version qu'il contient, indiquant par exemple une nouvelle version majeure. APT échouera à la commande update pour de tels dépôts jusqu'à ce que le changement soit confirmé, afin de s'assurer que l'utilisateur est préparé au changement. Voir aussi apt-secure(8) pour des détails sur le concept et la configuration.

Des options spécialisées (--allow-releaseinfo-change-field) existent pour autoriser les changements uniquement pour certains champs comme origin, label, codename, suite, version et defaultpin. Voir aussi apt_preferences(5). Élément de configuration : Acquire::AllowReleaseInfoChang

e
.

-U, --updat

Cela est pris en charge pour les commandes qui installent, suppriment ou mettent à jour des paquets comme install, remove, safe-upgrade, full-upgrade. Cela peut être utile pour s'assurer qu'une commande installe toujours les dernières versions, ou, en combinaison avec l'option --snapshot pour s'assurer que l'instantané est présent lorsque install est exécuté.

--cli-versio

n
Demande une version CLI spécifique. Il s'agit d'un motif qui prend une version MAJEURE.MINEURE. Vous pouvez omettre la version MINEURE, auquel cas le niveau mineur le plus récent pris en charge sera utilisé.

Les pistes de version sont présentées comme suit : La version 3.2 a des versions équivalentes 0.32, 1.22 et 2.12, implémentant de nouvelles fonctionnalités pour leurs versions majeures

respectives.

Un cas particulier est le motif de version X.9 : une version comme 2.9 est suivie de 3.0, mais 2.10 suit directement 2.8 ; étant donné que nous utilisons les numéros de version impairs comme séries de développement (2.9 est la série de développement 3.0)

.

Cette fonctionnalité a étéen introduite dans APT 3.1.10, et remplace la configuration spécifique au binaire. Vous pouvez utiliser APT::Version pour un effet similaire sur les anciens binaires, par exemple, utilisez -o APT::Version=2 pour faire en sorte que apt(8) se comporte comme la série 2.

x.

La valeur par défaut est la version actuelle d'APT pour apt(8) et 0.(10 * majeur + mineur) pour les commandes classiques. La série 0.X est o

bsolète (soft-deprecated) et les autres command
es passeront à la série 2.x dans le futur.
