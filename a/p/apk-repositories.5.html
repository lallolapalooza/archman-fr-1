apk-repositories(5) Manuel des formats de fichiers apk-repositories(5)

NOM

/etc/apk/repositories
/etc/apk/repositories.d/*.list
/lib/apk/repositories.d/*.list
liste des dépôts de paquets

DESCRIPTION

apk(8) charge les définitions de dépôts à partir des fichiers mentionnés ci-dessus.

Le fichier repositories est chargé en premier. Les chemins repositories.d sont ensuite traités si l'option --repositories-file n'a pas été utilisée. Les répertoires sont énumérés dans l'ordre mentionné ci-dessus. Une fois qu'un fichier .list du nom donné est rencontré, tout fichier du même nom dans les répertoires suivants est ignoré.

FORMAT DE FICHIER

Chaque ligne suit l'une des syntaxes suivantes :

# commentaire

Une ligne de commentaire qui est ignorée.

set [-default] clé=valeur

Définit la variable nommée clé à la valeur donnée.

La clé est limitée aux lettres, chiffres et au caractère underscore (_), et doit commencer par une lettre. Les noms de variables préfixés par APK_ sont réservés aux variables intégrées et ne peuvent pas être définis par l'utilisateur.

Une expansion de variable est effectuée sur la valeur avant l'affectation.

Si l'option -default est spécifiée, la valeur de la clé n'est pas modifiée si elle existe déjà.

Actuellement, les variables suivantes sont définies :

•
APK_ARCH, l'architecture principale de la base de données

ndx [@tag] url
[v2|v3] [@tag] url [composant...]

Si une déclaration de dépôt omet le champ type, elle prend par défaut le type défini dans la dernière commande default, ou si absent, v2 (ou ndx si url se termine par .adb ou .tar.gz). Si le format est v3 ou si le nom de fichier ndx se termine par .adb, un fichier d'index au format v3 est requis.

Le @tag optionnel peut être présent pour indiquer que le dépôt ne doit pas être utilisé par défaut. Reportez-vous à apk-world(5) sur comment activer l'installation de paquets à partir de dépôts étiquetés.

Une expansion de variable est effectuée sur les parties url et composant individuellement au moment de l'analyse de la ligne.

L'url fait référence à un fichier d'index ou à un chemin de dépôt. Les schémas actuellement pris en charge sont :

  • http://
  • https://
  • file://
  • chemin d'accès absolu au système de fichiers (doit commencer par `/`)

La liste des composants spécifie une liste de composants de dépôt. Si spécifié, la ligne est étendue à plusieurs URLs : une pour chaque composant, et le composant est ajouté à l'url. La spécification d'un composant avec le type ndx n'est pas valide.

EXEMPLES

Pour définir une liste de dépôts fournie par la distribution, la distribution peut expédier par exemple /lib/apk/repositories.d/distribution.list avec le contenu suivant :

set -default distro_mirror=https://example.com/distro
v3 ${distro_mirror} main community

Dans /etc/apk/repositories.d/00-vars.list, le miroir peut être remplacé par :

set distro_mirror=https://mirror.example.com/distro

DISPOSITION DU DÉPÔT

Si le type est ndx, la disposition et la résolution de chemin sont les suivantes :

  • url est une URL vers le fichier d'index
  • base_url est url avec le dernier composant supprimé
  • chemin par défaut du paquet : $base_url/$nom-$version.apk

Sinon, le type est l'un des types de dépôts, et la résolution de chemin fonctionne comme suit :

  • url est le base_url du dépôt
  • index (v3) se trouve à $base_url/$arch/Packages.adb
  • index (v2) se trouve à $base_url/$arch/APKINDEX.tar.gz
  • chemin par défaut du paquet : $base_url/$arch/$nom-$version.apk

Si le fichier d'index a un pkgname-spec défini, il est utilisé pour construire le chemin du paquet. Sinon, le chemin par défaut du paquet basé sur les règles ci-dessus est utilisé.

CRÉATION DES INDEX ET DES DÉPÔTS

Voir apk-mkndx(8) sur comment créer des fichiers d'index et apk-adbsign(8) sur comment modifier les signatures.

Pour le format d'index hérité, référez-vous à apk-index(8) pour les fichiers d'index, abuild-keygen(1) pour des informations sur la génération de clés, abuild-sign(1) pour des informations sur l'utilisation de ces clés pour signer des fichiers.

apk-verify(8) peut vérifier les fichiers d'index et de paquets de style nouveau et ancien.

MISE À JOUR DE L'INDEX CLIENT

apk(8) télécharge et stocke l'index de chaque dépôt dans un cache local dans /etc/apk/cache ou /var/cache/apk. Référez-vous à apk-cache(5) pour plus de détails.

Reportez-vous à apk-keys(5) sur comment le client doit être configuré pour vérifier les signatures d'index.
