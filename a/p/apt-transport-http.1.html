NOM

apt-transport-http - transport APT pour le téléchargement via le protocole Hypertext Transfer Protocol (HTTP)

DESCRIPTION

Ce transport APT permet l'utilisation de dépôts accessibles via le protocole Hypertext Transfer Protocol (HTTP). Il est disponible par défaut et probablement le plus utilisé de tous les transports. Notez qu'un transport n'est jamais appelé directement par un utilisateur, mais utilisé par les outils APT en fonction de la configuration de l'utilisateur.

HTTP est un protocole de transport non chiffré, ce qui signifie que toute la communication avec le serveur distant (ou le proxy) peut être observée par un attaquant suffisamment capable, communément appelé un « man in the middle » (MITM). Cependant, un tel attaquant ne peut *pas* modifier la communication pour compromettre la sécurité de votre système, car le modèle de sécurité des données d'APT est indépendant de la méthode de transport choisie. Ceci est expliqué en détail dans apt-secure(8). Un aperçu des méthodes de transport disponibles est donné dans sources.list(5).

OPTIONS

Diverses options peuvent être définies dans un fichier apt.conf(5) pour modifier son comportement, allant de la configuration du proxy aux solutions de contournement pour des limitations spécifiques du serveur.

Configuration du proxy

La variable d'environnement http_proxy est prise en charge pour la configuration à l'échelle du système. Les proxies spécifiques à APT peuvent être configurés via l'option Acquire::http::Proxy. Les proxies qui ne doivent être utilisés que pour certains hôtes peuvent être spécifiés via Acquire::http::Proxy::hôte. Un contrôle encore plus précis peut être réalisé via la détection automatique de proxy, détaillée ci-dessous. Toutes ces options utilisent le format d'URI schéma://[[utilisateur][:mot_de_passe]@]hôte[:port]/. Les schémas d'URI pris en charge sont socks5h (SOCKS5 avec résolution DNS à distance), http et https. Les informations d'authentification peuvent être fournies via apt_auth.conf(5) au lieu de les inclure directement dans l'URI.

Les différentes options de configuration APT prennent en charge la valeur spéciale DIRECT, signifiant qu'aucun proxy ne doit être utilisé. La variable d'environnement no_proxy est également prise en charge dans le même but.

En outre, trois paramètres sont fournis pour le contrôle du cache avec des caches proxy conformes à HTTP/1.1 : Acquire::http::No-Cache indique au proxy de ne pas utiliser sa réponse mise en cache en aucun cas. Acquire::http::Max-Age définit l'âge maximum autorisé (en secondes) d'un fichier d'index dans le cache du proxy. Acquire::http::No-Store spécifie que le proxy ne doit pas stocker les fichiers d'archive demandés dans son cache, ce qui peut être utilisé pour empêcher le proxy de polluer son cache avec (gros) fichiers .deb.

Configuration automatique du proxy

Acquire::http::Proxy-Auto-Detect peut être utilisé pour spécifier une commande externe pour découvrir le proxy HTTP à utiliser. Le premier et unique paramètre est une URI désignant l'hôte à contacter, pour permettre une configuration spécifique à l'hôte. APT s'attend à ce que la commande affiche le proxy sur stdout sous forme d'une seule ligne au format URI spécifié précédemment, ou le mot DIRECT si aucun proxy ne doit être utilisé. Aucune sortie n'indique que les paramètres de proxy génériques doivent être utilisés.

Notez que la détection automatique ne sera pas utilisée pour un hôte si une configuration de proxy spécifique à l'hôte est déjà définie via Acquire::http::Proxy::hôte.

Voir les paquets squid-deb-proxy-client(1) et auto-apt-proxy(1) pour des exemples d'implémentation.

Cette option a priorité sur le nom d'option hérité Acquire::http::ProxyAutoDetect.

Configuration de la connexion

L'option Acquire::http::Timeout définit le minuteur de délai d'attente utilisé par la méthode ; cette valeur s'applique à la fois au délai de connexion et au délai des données.

La bande passante utilisée peut être limitée avec Acquire::http::Dl-Limit, qui accepte des valeurs entières en kilooctets par seconde. La valeur par défaut est 0, ce qui désactive la limite et tente d'utiliser toute la bande passante disponible. Notez que cette option désactive implicitement le téléchargement à partir de plusieurs serveurs en même temps.

Le réglage Acquire::http::Pipeline-Depth peut être utilisé pour activer le pipelining HTTP (RFC 2616 section 8.1.2.2) qui peut être bénéfique par exemple sur des connexions à latence élevée. Il spécifie combien de requêtes sont envoyées dans un pipeline. APT tente de détecter et de contourner les serveurs web et les proxies mal configurés à l'exécution, mais si vous savez que le vôtre n'est pas conforme à la spécification HTTP/1.1, le pipelining peut être désactivé en définissant la valeur à 0. Il est activé par défaut avec la valeur 10.

Acquire::http::AllowRedirect contrôle si APT suivra les redirections, ce qui est activé par défaut.

Acquire::http::User-Agent peut être utilisé pour définir un User-Agent différent pour la méthode de téléchargement http, car certains proxies n'autorisent l'accès aux clients que si le client utilise un identifiant connu.

Acquire::http::SendAccept est activé par défaut et envoie un champ d'en-tête Accept: text/* au serveur pour les requêtes sans extensions de fichier, afin d'empêcher le serveur de tenter une négociation de contenu.

EXEMPLES

Acquire::http {
	Proxy::example.org "DIRECT";
	Proxy "socks5h://apt:pass@127.0.0.1:9050";
	Proxy-Auto-Detect "/usr/local/bin/apt-http-proxy-auto-detect";
	No-Cache "true";
	Max-Age "3600";
	No-Store "true";
	Timeout "10";
	Dl-Limit "42";
	Pipeline-Depth "0";
	AllowRedirect "false";
	User-Agent "Mon APT-HTTP";
	SendAccept "false";
};
