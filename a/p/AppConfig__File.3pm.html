D'ENSEMBLE

AppConfig::File est un module Perl5 qui lit les fichiers de configuration et utilise leur contenu pour mettre à jour les valeurs des variables dans un objet AppConfig::

State.

AppConfig::File est di

stribué dans le cadre
du paquet AppConfig.

DESCRIPTIO

N

UTILISATION DU MODULE AppConfig::

File

Pour importer et utiliser le module AppConfig::File, la ligne suivante doit apparaître dans votre script Perl

: 
use AppConfig::
File;

AppConfig::File est utilisé automatiquement si vous utilisez le module AppConfig et créez un objet AppConfig::File via la file()

méthode.

AppConfig::File est implémenté à l'aide de méthodes orientées objet. Un nouvel objet AppConfig::File est créé et initialisé en utilisant la méthode AppConfig::File->new(). Cela renvoie une référence à un nouvel objet AppConfig::File. Une référence à un objet AppConfig::State doit être passée en premier paramètre

: 
my $state   = AppConfig::State->new();
my $cfgfile = AppConfig::File->new($state)
;

Cela créera et renverra u

ne référence à un nouvel o
bjet AppConfig::File.

LECTURE DES FICHIERS DE

CONFIGURATION

La méthode parse() est utilisée pour lire un fichier de configuration et faire mettre à jour l'État (STATE) en

conséquence. 
$cfgfile->parse($file)
;

Plusieurs fichiers peuvent être spécifiés et seront lus à tour de

rôle. 
$cfgfile->parse($file1, $file2, $file3)
;

La méthode renverra une valeur undef si elle rencontre des erreurs lors de l'ouverture des fichiers. Elle s'arrêtera immédiatement sans traiter les fichiers suivants. Par défaut, l'option PEDANTIC dans l'objet AppConfig::State, $self->{ STATE }, est désactivée et toutes les erreurs d'analyse (variables invalides, valeurs non validées, etc.) généreront des avertissements, mais ne feront pas retourner la méthode. Une fois tous les fichiers traités, la méthode renverra 1 si tous les fichiers ont été traités sans avertissement, ou 0 si un ou plusieurs avertissements ont été levés. Lorsque l'option PEDANTIC est activée, la méthode génère un avertissement et renvoie immédiatement une valeur de 0 dès qu'elle rencontre une erreur

d'analyse.

Les valeurs des variables dans les fichiers de configuration peuvent être développées e

n fonction de la valeur de leur option EXPAND, telle que déterminée par l'objet App::St
ate. Voir AppConfig::State pour plus d'informations sur le développement des variables.

FORMAT DU FICHIER DE

CONFIGURATION

Un fichier de configuration peut contenir des lignes vides et des commentaires qui sont ignorés. Les commentaires commencent par un '#' comme premier caractère d'une ligne ou après un ou plusieurs espaces, et se poursuivent jusqu'à la fin de la

ligne. 
# ceci est un commentairer
foo = bar               # celui-ci aussi
url = index.html#hello  # celui-ci aussi, mais pas le
'#welcome'

Remarquez comment la partie '#welcome' de l'URL n'est pas traitée comme un commentaire parce qu'un espace ne la précède

pas.

Les longues lignes peuvent être poursuivies sur la ligne suivante en terminant la première ligne par un

'\'. 
callsign = alpha bravo camel delta echo foxtrot golf hipowls \
           india juliet kilo llama mike november oscar papa  \
           quebec romeo sierra tango umbrella victor whiskey \
           x-ray yankee
zebra

Les variables qui sont de simples indicateurs et ne s'attendent pas à un argument (ARGCOUNT = ARGCOUNT_NONE) peuvent être spécifiées sans aucune valeur. Elles seront définies avec la valeur 1, toute valeur explicitement spécifiée (sauf "0" et "off") étant ignorée. La variable peut également être spécifiée avec un préfixe "no" pour définir implicitement la variable à

0. 
verbose                              # activé (1)
verbose = 1                          # activé (1)
verbose = 0                          # désactivé (0)
verbose off                          # désactivé (0)
verbose on                           # activé (1)
verbose mumble                       # activé (1)
noverbose                            # désactivé
(0)

Les variables qui s'attendent à un argument (ARGCOUNT = ARGCOUNT_ONE) seront définies avec ce qui suit le nom de la variable, jusqu'à la fin de la ligne courante. Un signe égal peut être inséré entre la variable et la valeur pour plus de

clarté. 
room = /home/kitchen     
room
/home/bedroom

Chaque redéfinition ultérieure de la valeur de la variable écrase la valeur

précédente. 
print $config->room();               # affiche
"/home/bedroom"

Les variables peuvent être définies pour accepter plusieurs valeurs (ARGCOUNT = ARGCOUNT_LIST). Chaque définition ultérieure de la variable ajoute la valeur à la liste des valeurs précédemment définies pour la

variable. 
drink = coffee
drink =
tea

Une référence à une liste de valeurs est renvoyée lorsque la variable est

demandée. 
my $beverages = $config->drinks();
print join(", ", @$beverages);      # affiche "coffee,
tea"

Les variables peuvent également être définies comme des listes de hachage (ARGCOUNT = ARGCOUNT_HASH). Chaque définition ultérieure crée une nouvelle clé et valeur dans le tableau

associatif. 
alias l="ls -CF"
alias
h="history"

Une référence au hachage est renvoyée lorsque la variable est

demandée. 
my $aliases = $config->alias();
foreach my $k (keys %$aliases) {
    print "$k => $aliases->{ $k }\n";
}

Un grand bloc de texte peut être défini en utilisant le style de guillemetage "heredoc" de

Perl. 
scalar = <<BOUNDARY_STRING
line 1
line 2: Space/linebreaks within a HERE document are kept.
line 3: The last linebreak (\n) is stripped.
BOUNDARY_STRING
hash   key1 = <<'FOO'
  * Quotes (['"]) around the boundary string are simply ignored.
  * Whether the variables in HERE document are expanded depends on
    the EXPAND option of the variable or global setting.
FOO
hash = key2 = <<"_bar_"
Text within HERE document are kept as is.
# comments are treated as a normal text.
The same applies to line continuation. \
_bar_

Notez que vous ne pouvez pas utiliser un document HERE comme clé dans un hachage ou comme nom de

variable.

Le préfixe '-' peut être utilisé pour réinitialiser une variable à sa valeur par défaut et le préfixe '+' peut être utilisé pour la définir à

1 
-verbose
+debug

Développement des variables, des variables d'environnement et du tilde (répertoire personnel) Les valeurs des variables peuvent contenir des références à d'autres variables AppConfig, des variables d'environnement et/ou les répertoires personnels des utilisateurs. Celles-ci seront développées en fonction de la valeur EXPAND pour chaque variable ou de la valeur GLOBAL

EXPAND.

Trois types de développement différents peuvent être appliqués

: 
bin = ~/bin          # développer '~' vers le répertoire personnel si EXPAND_UID
tmp = ~abw/tmp       # comme ci-dessus, mais répertoire personnel de l'utilisateur 'abw'
perl = $bin/perl     # développer la valeur de la variable 'bin' si EXPAND_VAR
ripl = $(bin)/ripl   # comme ci-dessus avec parenthèses explicites
home = ${HOME}       # développer la variable d'environnement HOME si
EXPAND_ENV

Voir AppConfig::State pour plus d'informations sur le développement des valeurs des

variables.

Les fichiers de configuration peuvent avoir des variables organisées en blocs. Un en-tête de bloc, constitué du nom du bloc entre crochets, introduit un bloc de configuration. Le nom du bloc et un tiret bas sont ensuite préfixés aux noms de toutes les variables ultérieurement référencées dans ce bloc. Le bloc se poursuit jusqu'à la définition du bloc suivant ou jusqu'à la fin du fichier

courant. 
[block1]
foo = 10
# block1_foo = 10
[block2] foo = 20
# block2_foo = 20
