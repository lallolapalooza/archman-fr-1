DESCRIPTIO

N

apt-ftparchive est l'outil en ligne de commande qui génère les fichiers d'index utilisés par APT pour accéder à une source de distribution. Les fichiers d'index doivent être générés sur le site d'origine en fonction du contenu de ce

site.

apt-ftparchive est une version étendue du programme dpkg-scanpackages(1), incorporant l'intégralité de ses fonctionnalités via la commande packages. Il contient également un générateur de fichier contents, contents, ainsi qu'un moyen élaboré de « scripter » le processus de génération pour une archive

complète.

En interne apt-ftparchive peut utiliser des bases de données binaires pour mettre en cache le contenu d'un fichier .deb et ne dépend d'aucun programme externe en dehors de gzip(1). Lors d'une génération complète, il effectue automatiquement des vérifications de modification des fichiers et construit les fichiers compressés de sortie

souhaités.

Sauf si l'option -h ou --help est spécifiée, l'une des commandes suivantes doit être

présente.

package

s
La commande packages génère un fichier de paquets à partir d'une arborescence de répertoires. Elle prend le répertoire donné et le recherche récursivement à la recherche de fichiers .deb, émettant un enregistrement de paquet sur stdout pour chacun. Cette commande est approximativement équivalente à dpkg-scanpackages(1).

L'option --db peut être utilisée pour spécifier une b

ase de données de
mise en cache binaire.

s
La commande sources génère un fichier d'index des sources à partir d'une arborescence de répertoires. Elle prend le répertoire donné et le recherche récursivement à la recherche de fichiers .dsc, émettant un enregistrement de source sur stdout pour chacun. Cette commande est approximativement équivalente à dpkg-scansources(1).

Si un fichier override est spécifié, un fichier override de source ave

Elle prend le répertoire donné et le recherche récursivement à la recherche de fichiers .deb, et lit la liste de fichiers de chaque fichier. Elle trie ensuite et écrit sur stdout la liste des fichiers associés aux paquets. Les répertoires ne sont pas écrits dans la sortie. Si plusieurs paquets possèdent le même fichier, chaque paquet est séparé par une virgule dans la sortie.

releas

e
La commande release génère un fichier Release à partir d'une arborescence de répertoires. Elle recherche récursivement dans le répertoire donné les fichiers Packages, Sources, Contents, Components et icônes non compressés et compressés, ainsi que les fichiers Release, Index et md5sum.txt par défaut (APT::FTPArchive::Release::Default-Patterns). Des motifs de nom de fichier supplémentaires peuvent être ajoutés en les listant dans APT::FTPArchive::Release::Patterns. Elle écrit ensuite sur stdout un fichier Release contenant (par défaut) un résumé MD5, SHA1, SHA256 et SHA512 pour chaque fichier.

Les valeurs des champs de métadonnées supplémentaires dans le fichier Release sont prises des variables correspondantes sous APT::

FTPArchive::Release, par ex. APT::FTPArchive::Release::Origin. Les champs pris en charge sont Origin, Label, Suite, Version, Code
name, Date, NotAutomatic, ButAutomaticUpgrades, Acquire-By-Hash, Valid-Until, Signed-By, Architectures, Components et Description.

Le langage de configuration fournit un moyen flexible de spécifier quels fichiers d'index sont construits à partir de quels répertoires, ainsi qu'un moyen simple de maintenir les paramètres

NAME

apt-ftparchive - Crée les fichiers d'archive FTP des dépôts APT

SYNOPSIS

apt-ftparchive [options] commande [arguments ...]

DESCRIPTION

apt-ftparchive est un outil utilisé pour créer les fichiers d'index d'un dépôt APT. Il est généralement utilisé à la racine d'une arborescence de dépôt, par exemple une arborescence construite avec dpkg-scanpackages(1).

apt-ftparchive prend en entrée une ou plusieurs arborescences de paquets binaires et génère les fichiers Packages, Sources et Contents.

THE GENERATE CONFIGURATION

apt-ftparchive peut être configuré à l'aide de fichiers apt.conf(5). Les options de configuration pertinentes sont les suivantes :

APT::FTPArchive::Build-Depends-Indep
Si défini à true, les dépendances indépendantes de l'architecture seront calculées et affichées dans le champ Build-Depends-Indep du fichier Sources. (Par défaut : false)
APT::FTPArchive::Build-Depends-Arch
Si défini à true, les dépendances dépendantes de l'architecture seront calculées et affichées dans le champ Build-Depends-Arch du fichier Sources. (Par défaut : false)
APT::FTPArchive::Contents
Si défini à true, le fichier Contents sera généré. Il permet la recherche de fichiers dans les paquets. (Par défaut : false)
APT::FTPArchive::Prereq
Si défini à true, le champ Prereq sera ajouté au fichier Sources. Il contient les dépendances indépendantes de l'architecture qui sont également indépendantes de la version. (Par défaut : false)
APT::FTPArchive::Package-List
Si défini à true, le fichier Packages sera généré. (Par défaut : true)
APT::FTPArchive::Source-List
Si défini à true, le fichier Sources sera généré. (Par défaut : true)
APT::FTPArchive::Meta-List
Si défini à true, le fichier Meta sera généré. Ce fichier contient une liste des fichiers d'index présents dans le dépôt. (Par défaut : false)
APT::FTPArchive::Release
Si défini à true, le fichier Release sera généré. Ce fichier contient des métadonnées sur le dépôt, comme sa taille et les sommes de contrôle des autres fichiers d'index. (Par défaut : true)
APT::FTPArchive::Use-Index-Files
Si défini à true, les fichiers d'index existants (Packages, Sources, Contents) seront utilisés comme base pour les nouvelles générations, plutôt que de scanner à nouveau tous les paquets. Ceci accélère considérablement le processus, mais peut entraîner des incohérences si des paquets ont été modifiés sans que le fichier d'index ne soit mis à jour. (Par défaut : false)
APT::FTPArchive::Use-Fast-Hash
Si défini à true, les sommes de contrôle SHA256 et SHA512 seront calculées en utilisant une méthode plus rapide mais moins sécurisée. Ceci peut être utile pour de très grands dépôts où la performance est critique. (Par défaut : false)

THE BINARY OVERRIDE FILE

Le fichier override binaire peut être utilisé pour ajouter ou modifier des champs dans les paquets binaires avant qu'ils ne soient traités par apt-ftparchive. La syntaxe du fichier est la suivante :

NomDuPaquet [Champ=Valeur ...]

Par exemple, pour ajouter la section "contrib" au paquet "monpaquet" :

monpaquet Section=contrib

Ou pour définir le champ "Description-md5" :

monpaquet Description-md5=d41d8cd98f00b204e9800998ecf8427e

THE SOURCE OVERRIDE FILE

Le fichier override source peut être utilisé pour ajouter ou modifier des champs dans les paquets source avant qu'ils ne soient traités par apt-ftparchive. La syntaxe est la même que pour le fichier override binaire.

THE EXTRA OVERRIDE FILE

Le fichier override extra peut être utilisé pour ajouter des champs personnalisés qui ne sont ni binaires ni sources. La syntaxe est la même que pour les autres fichiers override.

APT::FTPArchive::Override::Binary

Chemin vers le fichier override binaire.

APT::FTPArchive::Override::Source

Chemin vers le fichier override source.

APT::FTPArchive::Override::Extra

Chemin vers le fichier override extra.

APT::FTPArchive::Cache-Changed-Detect

Par défaut, ce paramètre est défini sur "true". Il vérifie si un fichier a été modifié avant d'être mis en cache. Si un fichier est recompilé et/ou republié avec la même version à nouveau, cela entraînera des problèmes car les métadonnées mises en cache obsolètes comme la taille et les sommes de contrôle seront utilisées. Avec cette option activée, cela ne se produira plus car il sera vérifié si le fichier a été modifié. Notez que cette option est définie sur "false" par défaut car il n'est pas recommandé de télécharger plusieurs versions/builds d'un paquet avec le même numéro de version, donc en théorie personne n'aura ces problèmes et donc tous ces contrôles supplémentaires sont inutiles.

APT::FTPArchive::LongDescription

Cette option de configuration est définie par défaut sur "true" et ne doit être définie sur "false" que si l'archive générée avec apt-ftparchive(1) fournit également des fichiers de traduction. Notez que le fichier maître Translation-en ne peut être créé que dans la commande generate.

--cli-version

Demande une version CLI spécifique. C'est un modèle qui prend une version MAJEURE.MINEURE. Vous pouvez omettre la version MINEURE, auquel cas le dernier niveau mineur pris en charge sera utilisé.

Les pistes de version sont présentées comme suit : La version 3.2 a des versions équivalentes 0.32, 1.22 et 2.12, implémentant de nouvelles fonctionnalités pour leurs versions majeures spécifiées.

Un cas spécial est le modèle de version X.9 : Une version comme 2.9 est suivie de 3.0, mais 2.10 suit directement 2.8 ; étant donné que nous utilisons des numéros de version impairs comme séries de développement (2.9 est la série de développement 3.0).

Cette fonctionnalité a été introduite dans APT 3.1.10 et remplace la configuration spécifique au binaire. Vous pouvez utiliser APT::Version à des fins similaires sur des binaires plus anciens, par exemple, utilisez -o APT::Version=2 pour que apt(8) se comporte comme la série 2.x.

La valeur par défaut est la version APT actuelle pour apt(8) et 0.(10 * majeur + mineur) pour les commandes classiques. La série 0.X est dépréciée et les autres commandes basculeront vers la série 2.x à l'avenir.

--no-color, --color

Active ou désactive les couleurs. Les couleurs sont activées par défaut sur les terminaux pris en charge pour apt(8) et peuvent également être désactivées en utilisant les variables d'environnement NO_COLOR ou APT_NO_COLOR, ou configurées davantage par l'option de configuration APT::Color et son portée, voir apt.conf(5) pour des informations à ce sujet.

EXAMPLES

Pour créer un fichier Packages compressé pour un répertoire contenant des paquets binaires (.deb) :

apt-ftparchive packages directory | gzip > Packages.gz

apt.conf(5)

DIAGNOSTICS

apt-ftparchive retourne zéro en cas de fonctionnement normal, dix sur une erreur.
