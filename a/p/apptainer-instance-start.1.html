NOM

apptainer-instance-start - Démarre une instance nommée de l'image de conteneur donnée

SYNTAXE

apptainer instance start [options de démarrage...] [arguments du script de démarrage...]

DESCRIPTION

La commande d'instance start permet de créer une nouvelle instance nommée à partir d'une
image de conteneur existante qui sera lancée en arrière-plan. Si un
script de démarrage est défini dans les métadonnées du conteneur, les commandes de ce script
seront également exécutées avec la commande de démarrage de l'instance. Vous pouvez facultativement
passer des arguments au script de démarrage.

apptainer instance start accepte les formats de conteneur suivants :

*.sif Format d'image de conteneur Singularity (SIF). Natif pour Singularity
(3.0+) et Apptainer (v1.0.0+)

*.sqsh Format SquashFS. Natif pour Singularity 2.4+

*.img Format ext3. Natif pour les versions de Singularity < 2.4.

répertoire/ format sandbox. Répertoire contenant un système de fichiers racine valide
et éventuellement des métadonnées Apptainer.

instance://* Une instance locale en cours d'exécution d'un conteneur. (Voir le groupe de commandes
instance.)

library://* Un conteneur SIF hébergé sur une Bibliothèque (aucune par défaut)

docker://* Un conteneur Docker/OCI hébergé sur Docker Hub ou un autre
registre OCI.

shub://* Un conteneur hébergé sur Singularity Hub.

oras://* Un conteneur SIF hébergé sur un registre OCI qui prend en charge
la spécification OCI Registry As Storage (ORAS).

OPTIONS

--add-caps="" une liste de capacités séparées par des virgules à ajouter

--allow-setuid[=false] autoriser les binaires setuid dans le conteneur (root uniquement)

--app="" définir une application à exécuter dans un conteneur

--apply-cgroups="" appliquer des cgroups à partir d'un fichier pour les processus du conteneur (root uniquement)

--authfile="" fichier d'authentification de type Docker à utiliser pour lire/écrire les identifiants du registre OCI

-B, --bind=[] une spécification de chemin de montage utilisateur. spec a le format src[:dest[:opts]], où src et dest sont les chemins extérieurs et intérieurs. Si dest n'est pas donné, il est égal à src. Les options de montage ('opts') peuvent être spécifiées comme 'ro' (lecture seule) ou 'rw' (lecture/écriture, ce qui est la valeur par défaut). Plusieurs chemins de montage peuvent être donnés sous forme de liste séparée par des virgules.

--blkio-weight=0 poids relatif de l'IO bloc dans la plage 10-1000, 0 pour désactiver

--blkio-weight-device=[] poids relatif de l'IO bloc spécifique à un périphérique

--boot[=false] exécuter /sbin/init pour démarrer le conteneur (root uniquement)

-e, --cleanenv[=false] nettoyer l'environnement avant d'exécuter le conteneur

--compat[=false] appliquer les paramètres pour une compatibilité OCI/Docker accrue. Déduit --containall, --no-init, --no-umask, --no-eval, --writable-tmpfs.

-c, --contain[=false] utiliser un système de fichiers /dev minimal et vider d'autres répertoires (par exemple /tmp et $HOME) au lieu de partager les systèmes de fichiers de votre hôte

-C, --containall[=false] isoler non seulement les systèmes de fichiers, mais aussi les processus PID, IPC et l'environnement

--cpu-shares=-1 parts CPU pour le conteneur

--cpus="" Nombre de CPUs disponibles pour le conteneur

--cpuset-cpus="" Liste des CPUs hôtes disponibles pour le conteneur

--cpuset-mems="" Liste des nœuds mémoire hôtes disponibles pour le conteneur

--disable-cache[=false] ne pas utiliser ou créer de cache

--dmtcp-launch="" point de contrôle pour que dmtcp sauvegarde l'état du processus du conteneur (expérimental)

--dmtcp-restart="" point de contrôle pour que dmtcp redémarre le processus du conteneur (expérimental)

--dns="" liste de serveurs DNS séparés par des virgules à ajouter dans resolv.conf

--docker-host="" spécifier un hôte démon Docker personnalisé

--docker-login[=false] se connecter à un dépôt Docker interactivement

--drop-caps="" une liste de capacités séparées par des virgules à supprimer

--env=[] transmettre une variable d'environnement au processus contenu

--env-file=[] transmettre des variables d'environnement depuis un fichier au processus contenu

-f, --fakeroot[=false] exécuter le conteneur avec l'apparence d'une exécution en tant que root

--fusemount=[] une spécification de montage de système de fichiers FUSE de la forme :
- où est 'container' ou 'host', spécifiant où le montage sera effectué ('container-daemon' ou 'host-daemon' exécutera le processus FUSE détaché). est le chemin vers l'exécutable FUSE, plus les options pour le montage. est l'emplacement dans le conteneur où le montage FUSE sera attaché. Par exemple : 'container:sshfs 10.0.0.1:/ /sshfs'. Implique --pid.

-h, --help[=false] aide pour start

-H, --home="/build" une spécification de répertoire personnel. spec peut être soit un chemin src, soit une paire src:dest. src est le chemin source du répertoire personnel à l'extérieur du conteneur et dest remplace le répertoire personnel à l'intérieur du conteneur.

--hostname="" définir le nom d'hôte du conteneur

-i, --ipc[=false] exécuter le conteneur dans un nouvel espace de noms IPC

--keep-privs[=false] laisser l'utilisateur root conserver ses privilèges dans le conteneur (root uniquement)

--memory="" limite de mémoire en octets

--memory-reservation="" limite souple de mémoire en octets

--memory-swap="" limite de swap, utiliser -1 pour un swap illimité

--mount=[] une spécification de montage par exemple 'type=bind,source=/opt,destination=/hostopt'.

-n, --net[=false] exécuter le conteneur dans un nouvel espace de noms réseau (met en place une interface réseau bridge par défaut)

--netns-path="" rejoindre l'espace de noms réseau au chemin spécifié (en tant que root, ou si autorisé dans apptainer.conf)

--network="" spécifier le type de réseau souhaité séparé par des virgules, chaque réseau mettra en place une interface dédiée à l'intérieur du conteneur

--network-args=[] spécifier les arguments réseau à passer aux plugins CNI

--no-eval[=false] ne pas évaluer shell les variables d'environnement ou les commandes CMD/ENTRYPOINT/ARGS du conteneur OCI

--no-home[=false] NE PAS monter le répertoire personnel de l'utilisateur si /home n'est pas le répertoire de travail actuel

--no-https[=false] utiliser http au lieu de https pour les URI docker://, oras:// et library:///...

--no-init[=false] ne PAS démarrer le processus shim avec --pid

--no-mount=[] désactiver une ou plusieurs options 'mount xxx' définies dans apptainer.conf et/ou spécifier un chemin de destination absolu pour désactiver une entrée de chemin de montage, ou 'bind-paths' pour désactiver toutes les entrées de chemin de montage.

--no-privs[=false] supprimer tous les privilèges de l'utilisateur root dans le conteneur)

--no-umask[=false] ne pas propager le umask au conteneur, définir un umask par défaut de 0022

--nv[=false] activer le support Nvidia

--nvccli[=false] utiliser nvidia-container-cli pour la configuration GPU (expérimental)

--oom-kill-disable[=false] Désactiver le tueur OOM

-o, --overlay=[] utiliser une image overlayFS pour le stockage de données persistantes ou comme couche en lecture seule du conteneur

--passphrase[=false] demander une phrase secrète de chiffrement

--pem-path="" entrer un chemin vers une clé RSA au format PEM pour un conteneur chiffré

--pid-file="" écrire le PID de l'instance dans le fichier avec le nom donné

--pids-limit=0 limiter le nombre de PIDs du conteneur, utiliser -1 pour illimité

--rocm[=false] activer le support Rocm expérimental

-S, --scratch=[] inclure un répertoire scratch dans le conteneur qui est lié à un répertoire temporaire (utiliser -W pour forcer l'emplacement)

--security=[] activer les fonctionnalités de sécurité (SELinux, Apparmor, Seccomp)

--unsquash[=false] convertir le fichier SIF en sandbox temporaire avant l'exécution

-u, --userns[=false] exécuter le conteneur dans un nouvel espace de noms utilisateur

--uts[=false] exécuter le conteneur dans un nouvel espace de noms UTS

-W, --workdir="" répertoire de travail à utiliser pour /tmp, /var/tmp et $HOME (si -c/--contain a également été utilisé)

-w, --writable[=false] par défaut, tous les conteneurs Apptainer sont accessibles en lecture seule. Cette option rend le système de fichiers accessible

en lecture/écriture.

--writable-tmpfs[=false] rend le système de fichiers accessible en lecture/écriture avec des données non persistantes (uniquement avec le support de l'overlay)

EXEMPLE

  $ apptainer instance start /tmp/my-sql.sif mysql
  $ apptainer shell instance://mysql
  Apptainer my-sql.sif> pwd
  /home/mibauer/mysql
  Apptainer my-sql.sif> ps
  PID TTY          TIME CMD
    1 pts/0    00:00:00 appinit
    2 pts/0    00:00:00 bash
    3 pts/0    00:00:00 ps
  Apptainer my-sql.sif>
  $ apptainer instance stop /tmp/my-sql.sif mysql
  Stopping /tmp/my-sql.sif mysql
