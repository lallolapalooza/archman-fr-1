NOM

apt-cache - interroger le cache d'APT

SYNOPSIS

apt-cache [-agipns] [-o=config_string] [-c=config_file] {gencaches | showpkgpkg... | showsrcpkg... | stats | dump | dumpavail | unmet | searchregex... | showpkg[{=pkg_version_number| /target_release}]... | dependspkg[{=pkg_version_number| /target_release}]... | rdependspkg[{=pkg_version_number| /target_release}]... | pkgnames [prefix] | dottypkg[{=pkg_version_number| /target_release}]... | xvcgpkg[{=pkg_version_number| /target_release}]... | policy [pkg...] | madisonpkg... | {-v | --version} | {-h | --help}}

DESCRIPTION

apt-cache effectue diverses opérations sur le cache de paquets d'APT. apt-cache ne manipule pas l'état du système mais fournit des opérations pour rechercher et générer des sorties intéressantes à partir des métadonnées des paquets. Les métadonnées sont acquises et mises à jour via la commande 'update' de, par exemple, apt-get, de sorte qu'elles peuvent être obsolètes si la dernière mise à jour remonte à longtemps, mais en contrepartie apt-cache fonctionne indépendamment de la disponibilité des sources configurées (par ex. hors ligne).

Sauf si l'option -h, ou --help est donnée, l'une des commandes suivantes doit être présente.

gencaches

gencaches crée le cache de paquets d'APT. Cela est fait implicitement par toutes les commandes nécessitant ce cache s'il est manquant ou obsolète.

showpkg pkg...

showpkg affiche des informations sur les paquets listés sur la ligne de commande. Les arguments restants sont des noms de paquets. Les versions disponibles et les dépendances inverses de chaque paquet listé sont affichées, ainsi que les dépendances directes pour chaque version. Les dépendances directes (normales) sont les paquets dont le paquet en question dépend ; les dépendances inverses sont les paquets qui dépendent du paquet en question. Ainsi, les dépendances directes doivent être satisfaites pour un paquet, mais les dépendances inverses ne le doivent pas. Par exemple, apt-cache showpkg libreadline2 produirait une sortie similaire à ce qui suit : 
Package: libreadline2
Versions: 2.1-12(/var/state/apt/lists/foo_Packages),
Reverse Depends: 
  libreadlineg2,libreadline2
  libreadline2-altdev,libreadline2
Dependencies:
2.1-12 - libc5 (2 5.4.0-0) ncurses3.0 (0 (null))
Provides:
2.1-12 - 
Reverse Provides:
On peut ainsi voir que libreadline2, version 2.1-12, dépend de libc5 et ncurses3.0 qui doivent être installés pour que libreadline2 fonctionne. À son tour, libreadlineg2 et libreadline2-altdev dépendent de libreadline2. Si libreadline2 est installé, libc5 et ncurses3.0 (et ldso) doivent également être installés ; libreadlineg2 et libreadline2-altdev n'ont pas besoin d'être installés. Pour le sens précis du reste de la sortie, il est préférable de consulter le code source d'apt.

stats

stats affiche quelques statistiques sur le cache. Aucun argument supplémentaire n'est attendu. Les statistiques rapportées sont :
•Total package names est le nombre de noms de paquets trouvés dans le cache.
•Normal packages est le nombre de noms de paquets réguliers et ordinaires ; ce sont des paquets qui ont une correspondance un-à-un entre leurs noms et les noms utilisés par d'autres paquets pour les désigner dans les dépendances. La majorité des paquets appartiennent à cette catégorie.
•Pure virtual packages est le nombre de paquets qui n'existent qu'en tant que nom de paquet virtuel ; c'est-à-dire que les paquets ne « fournissent » que le nom du paquet virtuel, et qu'aucun paquet n'utilise réellement ce nom. Par exemple, « mail-transport-agent » dans le système Debian est un paquet virtuel pur ; plusieurs paquets fournissent « mail-transport-agent », mais aucun paquet nommé « mail-transport-agent » n'existe.
•Single virtual packages est le nombre de paquets pour lesquels un seul paquet fournit un paquet virtuel particulier. Par exemple, dans le système Debian, « X11-text-viewer » est un paquet virtuel, mais un seul paquet, xless, fournit « X11-text-viewer ».
•Mixed virtual packages est le nombre de paquets qui fournissent soit un paquet virtuel particulier, soit ont le nom du paquet virtuel comme nom de paquet. Par exemple, dans le système Debian, « debconf » est à la fois un paquet réel et fourni par le paquet debconf-tiny.
•Missing est le nombre de noms de paquets qui ont été référencés dans une dépendance mais qui n'ont été fournis par aucun paquet. Les paquets manquants peuvent être un signe qu'une distribution complète n'est pas accessible, ou qu'un paquet (réel ou virtuel) a été retiré de la distribution. Habituellement, ils sont référencés à partir d'instructions Conflicts ou Breaks.
•Total distinct versions est le nombre de versions de paquets trouvées dans le cache. Si plus d'une distribution est accessible (par exemple, « stable » et « unstable »), cette valeur peut être considérablement plus grande que le nombre total de noms de paquets.
•Total dependencies est le nombre de relations de dépendance revendiquées par tous les paquets du cache.

showsrc pkg...

showsrc affiche tous les enregistrements de paquets source qui correspondent aux noms de paquets donnés. Toutes les versions sont affichées, ainsi que tous les enregistrements qui déclarent le nom comme étant un paquet binaire. Utilisez --only-source pour afficher uniquement les noms de paquets source.

dump

dump affiche une liste courte de chaque paquet dans le cache. C'est principalement pour le débogage.

dumpavail

dumpavail imprime une liste des paquets disponibles sur la sortie standard. Cela convient à l'utilisation avec dpkg(1) et est utilisé par la méthode dselect(1) .

unmet

unmet affiche un résumé de toutes les dépendances non satisfaites dans le cache de paquets.

show pkg...

show effectue une fonction similaire à dpkg --print-avail; il affiche les enregistrements des paquets pour les paquets nommés.

search regex...

search effectue une recherche en texte intégral sur toutes les listes de paquets disponibles pour le motif regex POSIX donné, voir regex(7). Il recherche les noms de paquets et les descriptions pour une occurrence de l'expression régulière et imprime le nom du paquet et la description courte, y compris les noms de paquets virtuels. Si --full est donné, une sortie identique à show est produite pour chaque paquet correspondant, et si --names-only est donné, la description longue n'est pas recherchée, seuls le nom du paquet et les paquets fournis le sont.

Des arguments séparés peuvent être utilisés pour spécifier plusieurs motifs de recherche qui sont combinés par une opération ET.

depends pkg...

depends affiche une liste de chaque dépendance qu'a un paquet et tous les autres paquets possibles qui peuvent satisfaire cette dépendance.

rdepends pkg...

rdepends affiche une liste de chaque dépendance inverse qu'a un paquet.

pkgnames [prefix]

Cette commande imprime le nom de chaque paquet connu d'APT. L'argument facultatif est une correspondance de préfixe pour filtrer la liste des noms. La sortie convient à l'utilisation dans une fonction de complétion de tabulation de shell et la sortie est générée extrêmement rapidement. Cette commande est mieux utilisée avec l'option --generate .

Notez qu'un paquet connu d'APT n'est pas nécessairement disponible au téléchargement, installable ou installé, par ex. les paquets virtuels sont également listés dans la liste générée.

dotty pkg...

dotty prend une liste de paquets sur la ligne de commande et génère une sortie adaptée à l'utilisation par dotty à partir de GraphViz[1] paquet. Le résultat sera un ensemble de nœuds et d'arêtes représentant les relations entre les paquets. Par défaut, les paquets donnés traceront tous les paquets dépendants ; cela peut produire un graphe très volumineux. Pour limiter la sortie aux seuls paquets listés en ligne de commande, définissez l'option APT::Cache::GivenOnly.

Les nœuds résultants auront plusieurs formes ; les paquets normaux sont des boîtes, les paquets purement virtuels sont des triangles, les paquets virtuels mixtes sont des diamants, les paquets manquants sont des hexagones. Les boîtes orange signifient que la récursion a été arrêtée (paquets feuilles), les lignes bleues sont les pré-dépendances, les lignes vertes sont les

conflits.

Vous pouvez omettre la version mineure, auquel cas le niveau mineur le plus récent pris en charge sera utilisé.
