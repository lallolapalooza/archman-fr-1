APERÇ

U

AppConfig est un module Perl5 pour gérer les informations de configuration d'une application. Il maintient l'état d'un nombre quelconque de variables et fournit des méthodes pour analyser les fichiers de configuration, les arguments de la ligne de commande et les paramètres des scripts

CGI.

Les valeurs des variables peuvent être définies via des fichiers de configuration. Les variables peuvent être des drapeaux (Activé/Désactivé), prendre une seule valeur, ou prendre plusieurs valeurs stockées sous forme de liste ou de table de hachage. Le nombre d'arguments qu'une variable attend est déterminé par sa configuration lors de sa

définition. 
# drapeaux
verbose 
nohelp
debug = On
# valeur unique
home  = /home/abw/
# plusieurs valeurs en liste
file = /tmp/file1
file = /tmp/file2
# plusieurs valeurs en table de hachage
book  camel = Programming Perl
book  llama = Learning
Perl

Le préfixe '-' peut être utilisé pour réinitialiser une variable à sa valeur par défaut et le préfixe '+' peut être utilisé pour la définir à

1 
-verbose
+debug

Les expansions de variable, de variable d'environnement et de tilde (répertoire personnel) peuvent être appliquées (de manière sélective, si nécessaire) aux valeurs lues depuis les fichiers de configuration

: 
home = ~                    # répertoire personnel
nntp = ${NNTPSERVER}        # variable d'environnement
html = $home/html           # variables internes
img  =
$html/images

Les fichiers de configuration peuvent être organisés en blocs selon le style des fichiers "INI"

Win32. 
[file]
site = kfs
src  = ~/websrc/docs/$site
lib  = ~/websrc/lib
dest = ~/public_html/$site
[page]
header = $lib/header
footer =
$lib/footer

Vous pouvez également utiliser la syntaxe "heredoc" de Perl pour définir un grand bloc de texte dans un fichier de

configuration. 
multiline = <<FOOBAR
line 1
line 2
FOOBAR
paths  exe  = "${PATH}:${HOME}/.bin"
paths  link = <<'FOO'
${LD_LIBARRAY_PATH}:${HOME}/lib
FOO

Les variables peuvent également être définies en analysant les arguments de la ligne de

commande. 
myapp -verbose -site kfs -file f1 -file
f2

AppConfig fournit une méthode simple (args()) pour analyser les arguments de la ligne de commande. Une seconde méthode (getopt()) permet un traitement plus complexe des arguments par délégation au module Getopt::Long de Johan

Vroman.

AppConfig permet également de définir des variables via les paramètres passés à un script CGI par l'URL (méthode GET)

. 
http://www.nowhere.com/cgi-bin/myapp?
verbose&site=kf
s

UTILISATION DU MODULE

AppConfig

Pour importer et utiliser le module AppConfig, la ligne suivante devrait apparaître dans votre script Perl

: 
use
AppConfig;

Pour importer les constantes définies par le module AppConfig, spécifiez le nom d'un ou plusieurs des ensembles de constantes ou de tags en tant que paramètres à "use"

: 
use AppConfig qw(:expand :argcount)
;

Voir "DÉFINITION DES CONSTANTES" ci-dessous pour plus d'informations sur les ensembles de tags de constantes définis par

AppConfig.

AppConfig est implémenté à l'aide de méthodes orientées objet. Un nouvel objet AppConfig est créé et initialisé à l'aide de la méthode new(). Celle-ci renvoie une référence à un nouvel objet

AppConfig. 
my $config = AppConfig->new()
;

Cela créera et renverra une référence à un nouvel objet

AppConfig.

Ce faisant, l'objet AppConfig crée également une référence interne à un objet AppConfig::State dans lequel stocker l'état des variables. Tous les arguments passés au constructeur AppConfig sont transmis directement au constructeur AppConfig::

State.

Le premier paramètre (optionnel) peut être une référence à une table de hachage contenant des informations de

configuration. 
my $config = AppConfig->new( {
        CASE   => 1,
        ERROR  => \&my_error,
        GLOBAL => { 
                DEFAULT  => "<unset>", 
                ARGCOUNT => ARGCOUNT_ONE,
            },
    } )
;

DÉFINITION DES

VARIABLES

La méthode define() (déléguée à AppConfig::State) est utilisée pour pré-déclarer une variable et spécifier sa

configuration. 
$config->define("foo")
;

Les variables peuvent également être définies directement depuis le constructeur new()

d'AppConfig. 
my $config = AppConfig->new("foo")
;

Dans les deux exemples simples ci-dessus, une nouvelle variable nommée "foo" est définie. Une référence à un tableau associatif peut également être passée pour spécifier les informations de configuration de la variable

: 
$config->define("foo", {
        DEFAULT   => 99,
        ALIAS     => 'metavar1',
    })
;

Les éléments de configuration spécifiés dans l'option GLOBAL du constructeur du module sont appliqués par défaut lorsque les variables sont créées. p.

ex. 
my $config = AppConfig->new( { 
    GLOBAL => {
        DEFAULT  => "<undef>",
        ARGCOUNT => ARGCOUNT_ONE,
    }
} );
$config->define("foo");
$config->define("bar", { ARGCOUNT => ARGCOUNT_NONE } )
;

est équivalent à

: 
my $config = AppConfig->new();
$config->define( "foo", {
    DEFAULT  => "<undef>",
    ARGCOUNT => ARGCOUNT_ONE,
} );
$config->define( "bar", 
    DEFAULT  => "<undef>",
    ARGCOUNT => ARGCOUNT_NONE,
} )
;

Plusieurs variables peuvent être définies dans le même appel à define(). Les hachages de configuration des variables peuvent être

omis. 
$config->define("foo", "bar" => { ALIAS = "boozer" }, "baz")
;

DÉFINITION DE FORMAT

COMPACT

Les variables peuvent être spécifiées en utilisant un format compact. C'est identique au format de spécification de Getopt::Long et est de la forme

: 
"name|alias|alias<argopts>
"

Le premier élément indique le nom de la variable et les valeurs ALIAS suivantes peuvent être ajoutées, chacune séparée par une barre verticale

'|'.

L'élément <argopts> indique la valeur ARGCOUNT et peut être l'une des suivantes

; 
!                  ARGCOUNT_NONE
=s                 ARGCOUNT_ONE
=s@                ARGCOUNT_LIST
=s%
ARGCOUNT_HASH

Les constructions supplémentaires prises en charge par Getopt::Long peuvent être spécifiées à la place de l'élément "=s" (p. ex. "=f"). L'élément <argopts> entier est stocké dans le paramètre ARGS de la variable et est passé intact à Getopt::Long lorsque la méthode getopt() est

appelée.

Les exemples suivants démontrent l'utilisation du format compact, avec leurs spécifications complètes équivalentes

: 
$config->define("foo|bar|baz!");
$config->define(
        "foo" => { 
            ALIAS    => "bar|baz", 
            ARGCOUNT => ARGCOUNT_NONE,
        });
$config->define("name=s");
$config->define(
        "name" => { 
            ARGCOUNT => ARGCOUNT_ONE,
        });
$config->define("file|filelist|f=s@");
$config->define(
        "file" => { 
            ALIAS    => "filelist|f", 
            ARGCOUNT => ARGCOUNT_LIST,
        });
$config->define("user|u=s%");
$config->define(
        "user" => { 
            ALIAS    => "u", 
            ARGCOUNT => ARGCOUNT_HASH,
        })
;

Des options de configuration supplémentaires peuvent être spécifiées par référence de hachage, comme d'habitude. Le format de définition compact remplacera toute valeur de configuration fournie pour ARGS et

ARGCOUNT. 
$config->define("file|filelist|f=s@", { VALIDATE => \&check_file }
)
;

LECTURE ET MODIFICATION DES VALEURS DES

VARIABLES

AppConfig définit deux méthodes (via AppConfig::State) pour manipuler les valeurs des

variables 
set($variable, $value);
get($variable)
;

Une fois définies, les variables peuvent être accédées directement en tant que méthodes d'objet où le nom de la méthode est le même que le nom de la variable. c.

-à-d. 
$config->set("verbose", 1)
;

est équivalent

à 
$config->verbose(1)
;

Notez qu'AppConfig définit les méthodes suivantes

: 
new();
file();
args();
getopt()
;

Et aussi, par délégation à AppConfig::State

: 
define()
get()
set()
varlist()

Si vous définissez une variable avec l'un des noms ci-dessus, vous ne pourrez pas y accéder directement en tant que méthode d'objet. c.

-à-d. 
$config->file()
;

Cela appellera la méthode file(), au lieu de retourner la valeur de la variable 'file'. Vous pouvez contourner cela en appelant explicitement get() et set() sur une variable dont le nom entre en conflit

: 
$config->get('file')
;

ou en définissant un alias "sûr" par lequel la variable peut être accédée

: 
    $config->define("file", { ALIAS => "fileopt" });
or
    $config->define("file|fileopt");
    ...
    $config->fileopt()
;

Sans paramètres, la valeur actuelle de la variable est retournée. Si un paramètre est spécifié, la variable est définie à cette valeur et le résultat de l'opération set() est

retourné. 
$config->age(29);        # sets 'age' to 29, returns 1 (ok)
print $config->age();    # prints
"29"

La méthode varlist() peut être utilisée pour extraire un certain nombre de variables dans un tableau associatif. Le premier paramètre doit être une expression régulière utilisée pour la correspondance avec les noms de

variables. 
my %vars = $config->varlist("^file");   # all "file*"
variables

Un second paramètre peut être spécifié (n'importe quelle valeur vraie) pour indiquer que la partie du nom de la variable correspondant à l'expression régulière doit être supprimée lorsqu'elle est copiée dans le hachage

cible. 
$config->file_name("/tmp/file");
$config->file_path("/foo:
/bar:/baz"); my %vars = $config->varlist("^file_", 1); # %
vars: # name => /tmp/file # path => "/foo:/bar:/baz"

LECTURE DES FICHIERS DE

CONFIGURATION

Le module AppConfig fournit une interface simplifiée pour lire les fichiers de configuration avec le module AppConfig::File. La méthode file() charge automatiquement le module AppConfig::File et crée un objet pour traiter le fichier ou les fichiers de configuration. Les variables stockées dans l'AppConfig::State interne sont automatiquement mises à jour avec les valeurs spécifiées dans le fichier de

configuration. 
$config->file($filename)
;

Plusieurs fichiers peuvent être passés à file() et doivent indiquer le nom du fichier ou être une référence à un descripteur de fichier ouvert ou un

glob. 
$config->file($filename, $filehandle, \*STDIN, ...)
;

Le fichier peut contenir des lignes vides et des commentaires (préfixés par '#') qui sont ignorés. Les lignes de continuation peuvent être marquées en terminant la ligne avec un

'\'. 
# this is a comment
callsign = alpha bravo camel delta echo foxtrot golf hipowls \
           india juliet kilo llama mike november oscar papa  \
           quebec romeo sierra tango umbrella victor whiskey \
           x-ray yankee
zebra

Les variables qui sont de simples indicateurs et n'attendent pas d'argument (ARGCOUNT = ARGCOUNT_NONE) peuvent être spécifiées sans aucune valeur. Elles seront définies avec la valeur 1, toute valeur explicitement spécifiée (sauf "0" et "off") étant ignorée. La variable peut également être spécifiée avec un préfixe "no" pour définir implicitement la variable à

0. 
verbose                              # on  (1)
verbose = 1                          # on  (1)
verbose = 0                          # off (0)
verbose off                          # off (0)
verbose on                           # on  (1)
verbose mumble                       # on  (1)
noverbose                            # off
(0)

Les variables qui attendent un argument (ARGCOUNT = ARGCOUNT_ONE) seront définies avec ce qui suit le nom de la variable, jusqu'à la fin de la ligne actuelle (y compris toute ligne de continuation). Un signe égal facultatif peut être inséré entre la variable et la valeur pour clarté

. 
room = /home/kitchen     
room
/home/bedroom

Chaque redéfinition ultérieure de la valeur de la variable écrase la valeur

précédente. 
print $config->room();               # affiche
"/home/bedroom"

Les variables peuvent être définies pour accepter plusieurs valeurs (ARGCOUNT = ARGCOUNT_LIST). Chaque définition ultérieure de la variable ajoute la valeur à la liste des valeurs précédemment définies pour la

variable. 
drink = coffee
drink =
tea

Une référence à une liste de valeurs est retournée lorsque la variable est

demandée. 
my $beverages = $config->drink();
print join(", ", @$beverages);      # affiche "coffee,
tea"

Les variables peuvent également être définies en tant que listes de hachage (ARGCOUNT = ARGCOUNT_HASH). Chaque définition ultérieure crée une nouvelle clé et valeur dans le tableau de

hachage. 
alias l="ls -CF"
alias
e="emacs"

Une référence au hachage est retournée lorsque la variable est

demandée. 
my $aliases = $config->alias();
foreach my $k (keys %$aliases) {
    print "$k => $aliases->{ $k }\n";
}

Le préfixe '-' peut être utilisé pour réinitialiser une variable à sa valeur par défaut et le préfixe '+' peut être utilisé pour la définir à

1 
-verb
ose +
debug

VARIABLE

EXPANSION

Les valeurs des variables peuvent contenir des références à d'autres variables AppConfig, des variables d'environnement et/ou les répertoires personnels des utilisateurs. Celles-ci seront développées en fonction de la valeur EXPAND pour chaque variable ou de la valeur globale

EXPAND.

Trois types d'expansion différents peuvent être appliqués

: 
bin = ~/bin          # développe '~' vers le répertoire personnel si EXPAND_UID
tmp = ~abw/tmp       # comme ci-dessus, mais répertoire personnel de l'utilisateur 'abw'
perl = $bin/perl     # développe la valeur de la variable 'bin' si EXPAND_VAR
ripl = $(bin)/ripl   # comme ci-dessus avec parenthèses explicites
home = ${HOME}       # développe la variable d'environnement HOME si
EXPAND_ENV

Voir AppConfig::State pour plus d'informations sur le développement des valeurs des

variables.

Les fichiers de configuration peuvent avoir des variables organisées en blocs. Un en-tête de bloc, composé du nom du bloc entre crochets, introduit un bloc de configuration. Le nom du bloc et un tiret bas sont ensuite préfixés aux noms de toutes les variables référencées ultérieurement dans ce bloc. Le bloc continue jusqu'à la définition du bloc suivant ou jusqu'à la fin du fichier

courant. 
[block1]
foo = 10             #
block1_foo = 10 [block2] foo =
20 # block2_foo = 20

PARSING OPTIONS DE LIGNE DE

COMMANDE

Il existe deux méthodes pour traiter les options de ligne de commande. La première, args(), est une implémentation petite et efficace qui offre des fonctionnalités de base. La seconde, getopt(), offre une fonctionnalité plus puissante et complète en déléguant la tâche au module Getopt::Long de Johan Vroman. Le compromis entre args() et getopt() est essentiellement une question de vitesse/taille contre flexibilité. Utilisez selon les besoins. Les deux implémentent le chargement à la demande des modules et n'entraînent aucune surcharge tant qu'elles ne sont pas

utilisées.

La méthode args() est utilisée pour analyser des options simples de ligne de commande. Elle charge automatiquement le module AppConfig::Args et crée un objet pour traiter les arguments de la ligne de commande. Les variables stockées dans l'AppConfig::State interne sont automatiquement mises à jour avec les valeurs spécifiées dans les

arguments.

La méthode doit recevoir une référence à une liste d'arguments à analyser. Le tableau @ARGV est utilisé si args() est appelée sans

paramètres. 
$config->args(\@myargs);
$config->args();               # utilise
@ARGV

Les arguments sont lus et décalés du tableau jusqu'à ce que le premier soit rencontré qui n'est pas préfixé par '-' ou '--'. À ce moment-là, la méthode renvoie 1 pour indiquer le succès, laissant tout argument non traité restant dans la

liste.

Chaque argument doit être le nom ou l'alias d'une variable préfixé par '-' ou '--'. Les arguments qui ne sont pas préfixés ainsi (et ne sont pas un paramètre supplémentaire à un argument précédent) provoqueront l'émission d'un avertissement. Si l'option PEDANTIC est définie, la méthode renverra immédiatement 0. Avec PEDANTIC non défini (par défaut), la méthode continuera à analyser le reste des arguments, renvoyant 0 une fois

terminé.

Si la variable est un simple drapeau (ARGCOUNT = ARGCOUNT_NONE), elle est définie à la valeur 1. La variable peut être préfixée par "no" pour définir sa valeur à

0. 
myprog -verbose --debug -notaste     # $config->verbose(1)
                                     # $config->debug(1)
                                     # $config->
taste(0)

Les variables qui attendent un argument supplémentaire (ARGCOUNT != 0) seront définies à la valeur de l'argument qui les

suit. 
myprog -f /tmp/myfile                # $config->file('/tmp/file')
;

Les variables qui attendent plusieurs valeurs (ARGCOUNT = ARGCOUNT_LIST ou ARGCOUNT_HASH) auront des valeurs successives ajoutées chaque fois que l'option est

rencontrée. 
myprog -file /tmp/foo -file /tmp/bar # $config->file('/tmp/foo')
                                     # $config->file('/tmp/bar')
# file => [ '/tmp/foo', '/tmp/bar' ]
myprog -door "jim=Jim Morrison" -door "ray=Ray Manzarek"
                                # $config->door("jim=Jim Morrison");
                                # $config->door("ray=Ray Manzarek");
# door => { 'jim' => 'Jim Morrison', 'ray' => 'Ray Manzarek'
}

Voir AppConfig::Args pour plus de détails sur l'analyse des arguments de ligne de

commande.

La méthode getopt() fournit un moyen d'utiliser la puissance et la flexibilité du module Getopt::Long pour analyser les arguments de ligne de commande et faire en sorte que les valeurs internes de l'objet AppConfig soient mises à jour automatiquement

.

Les premiers paramètres (non références de liste) peuvent contenir un certain nombre de chaînes de configuration à passer à Getopt::Long::Configure. Une référence à une liste d'arguments peut également être passée ou @ARGV est utilisé par

défaut. 
$config->getopt();                       # utilise @ARGV
$config->getopt(\@myargs);
$config->getopt(qw(auto_abbrev debug));  # utilise @ARGV
$config->getopt(qw(debug), \@myargs)
;

Voir Getopt::Long pour les détails des options de configuration

disponibles.

La méthode getopt() construit une chaîne de spécification pour chaque variable interne et initialise ensuite Getopt::Long avec ces valeurs. La chaîne de spécification est construite à partir du nom, de tous les alias (délimités par une barre verticale '|') et de la valeur du paramètre

ARGS. 
$config->define("foo", {
    ARGS  => "=i",
    ALIAS => "bar|baz",
});
# Spécification Getopt::Long :
"foo|bar|baz=i"

Les erreurs et avertissements générés par le module Getopt::Long sont interceptés et traités par le gestionnaire d'erreurs AppConfig. Il peut s'agir d'une routine définie par l'utilisateur installée avec l'option de configuration

ERROR.

Veuillez noter que l'interface AppConfig::Getopt est encore expérimentale

et peut ne pas être opérationnelle à 100 %. Cela est presque indubitableme
nt dû à des problèmes dans AppConfig::Getopt plutôt que dans Getopt::Long.

PARSING PARAMÈTRES

CGI

La méthode cgi() fournit une interface au module AppConfig::CGI pour mettre à jour les valeurs des variables en fonction des paramètres ajoutés à l'URL pour un script CGI. C'est communément appelé la méthode "GET" du CGI. La méthode "POST" du CGI n'est actuellement pas prise en

charge.

Les définitions de paramètres sont séparées du nom du script CGI par un point d'interrogation et les unes des autres par des esperluettes. Lorsque les variables ont des valeurs spécifiques, celles-ci sont ajoutées à la variable avec un signe égal

: 
http://www.here.com/cgi-bin/myscript?foo=bar&baz=qux&verbose
    # $config->foo('bar');
    # $config->baz('qux');
    # $config->verbose(1)
;

Certaines valeurs spécifiées dans une URL doivent être échappées de la manière appropriée (voir les spécifications CGI à http://www.w3c.org/ pour les détails complets). Le module AppConfig::CGI déséchappe automatiquement la chaîne de requête CGI pour restaurer les paramètres à leurs valeurs

prévues. 
http://where.com/mycgi?title=%22The+Wrong+Trousers%22
# $config->title('"The Wrong Trousers"')
;

Veuillez tenir compte des implications en matière de sécurité de la fourniture d'un accès en écriture aux variables de script via

CGI. 
http://rebel.alliance.com/cgi-bin/...
    .../send_report?file=%2Fetc%2Fpasswd&email=darth%40empire.
com

Pour éviter tout changement accidentel ou malveillant de variables "privées", ne définissez que les variables "publiques" avant d'appeler la méthode cgi() (ou toute autre). D'autres variables peuvent ensuite être définies et ne peuvent pas être influencées par les paramètres

CGI. 
$config->define('verbose', 'debug')
$config->cgi();
# ne peut définir que verbose et debug $
config->define('email', 'file'); $config->file($cfgf
ile); # peut définir verbose, debug, email + file
