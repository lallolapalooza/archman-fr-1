NOM

apt - interface en ligne de commande

SYNOPSIS

apt [-h] [-o=chaîne_de_configuration] [-c=fichier_de_configuration] [-t=version_cible] [-a=architecture] {list | search | show | update | installpaquet[{=numéro_de_version_du_paquet| /version_cible}]... | removepaquet... | upgrade | full-upgrade | edit-sources | {-v | --version} | {-h | --help}}

DESCRIPTION

apt fournit une interface en ligne de commande de haut niveau pour le système de gestion de paquets. Elle est destinée à être une interface pour l'utilisateur final et permet certaines options mieux adaptées à un usage interactif par défaut, par rapport à des outils APT plus spécialisés comme apt-get(8) et apt-cache(8).

Tout comme apt lui-même, sa page manuelle est destinée à être une interface pour l'utilisateur final et mentionne donc uniquement les commandes et options les plus utilisées, en partie pour ne pas dupliquer les informations à plusieurs endroits et en partie pour ne pas submerger les lecteurs d'une pléthore d'options et de détails.

update (apt-get(8))

update est utilisé pour télécharger les informations sur les paquets depuis toutes les sources configurées. Les autres commandes opèrent sur ces données pour, par exemple, effectuer des mises à niveau de paquets ou rechercher et afficher des détails sur tous les paquets disponibles à l'installation.

upgrade (apt-get(8))

upgrade est utilisé pour installer les mises à niveau disponibles de tous les paquets actuellement installés sur le système depuis les sources configurées via sources.list(5). De nouveaux paquets seront installés si nécessaire pour satisfaire les dépendances, mais les paquets existants ne seront jamais supprimés. Si la mise à niveau d'un paquet nécessite la suppression d'un paquet installé, la mise à niveau de ce paquet n'est pas effectuée.

Lorsqu'un paquet est fourni en argument, il sera installé avant l'action de mise à niveau.

full-upgrade (apt-get(8))

full-upgrade effectue la fonction de upgrade mais supprimera les paquets actuellement installés si cela est nécessaire pour mettre à niveau le système dans son ensemble.

Lorsqu'un paquet est fourni en argument, il sera installé avant l'action de mise à niveau.

install, reinstall, remove, purge (apt-get(8))

Effectue l'action demandée sur un ou plusieurs paquets spécifiés via regex(7), glob(7) ou une correspondance exacte. L'action demandée peut être remplacée pour des paquets spécifiques en ajoutant un plus (+) au nom du paquet pour l'installer ou un moins (-) pour le supprimer.

Une version spécifique d'un paquet peut être sélectionnée pour l'installation en suivant le nom du paquet par un égal (=) et la version du paquet à sélectionner. Alternativement, la version d'une publication spécifique peut être sélectionnée en suivant le nom du paquet par une barre oblique (/) et le nom de code (trixie, forky, sid ...) ou le nom de la suite (stable, testing, unstable). Cela sélectionnera également les versions de cette publication pour les dépendances de ce paquet si nécessaire pour satisfaire la demande.

La suppression d'un paquet supprime toutes les données empaquetées, mais laisse généralement de petits fichiers de configuration utilisateur (modifiés) derrière, au cas où la suppression serait accidentelle. Il suffit de demander l'installation du paquet supprimé par accident pour restaurer son fonctionnement comme avant dans ce cas. D'autre part, vous pouvez vous débarrasser de ces restes en appelant purge même sur des paquets déjà supprimés. Notez que cela n'affecte aucune donnée ni configuration stockée dans votre répertoire personnel.

autoremove (apt-get(8))

autoremove est utilisé pour supprimer les paquets qui ont été installés automatiquement pour satisfaire les dépendances d'autres paquets et qui ne sont plus nécessaires car les dépendances ont changé ou les paquets qui les nécessitaient ont été supprimés entre-temps.

Vous devriez vérifier que la liste n'inclut pas des applications que vous avez apprécier alors même qu'elles ont été installées uniquement comme dépendance d'un autre paquet. Vous pouvez marquer un tel paquet comme installé manuellement en utilisant apt-mark(8). Les paquets que vous avez installés explicitement via install ne sont jamais proposés pour une suppression automatique.

satisfy (apt-get(8))

satisfy satisfait les chaînes de dépendances, comme celles utilisées dans Build-Depends. Il gère aussi les conflits, en préfixant un argument avec "Conflicts: ".

Exemple : apt satisfy "foo, bar (>= 1.0)" "Conflicts: baz, fuzz"

why, why-not

Ces commandes affichent le chemin de raisonnement du solveur. Elles sont similaires aux commandes aptitude équivalentes pour de nombreux cas d'utilisation, mais diffèrent en ce qu'elles affichent la raison réelle pour laquelle le solveur a fait son choix plutôt que le chemin le plus fort potentiel.

La why commande détermine pourquoi un paquet installé est installé. Cela fournit un retour raisonnable sur la raison pour laquelle un paquet installé automatiquement est installé ; pour un paquet installé manuellement, aucune autre raison n'est donnée. Si le paquet n'est pas installé, aucune raison ne peut être déterminée.

La why-not commande détermine pourquoi un paquet a été déterminé comme non installable. Cela peut ne pas toujours donner un résultat, même si un paquet est désinstallable.

Les deux commandes prennent un seul argument, le nom d'un paquet.

search (apt-cache(8))

search peut être utilisé pour rechercher le ou les termes regex(7) donnés dans la liste des paquets disponibles et afficher les correspondances. Cela peut être utile, par exemple, si vous cherchez des paquets ayant une fonctionnalité spécifique. Si vous cherchez un paquet incluant un fichier spécifique, essayez apt-file(1).

show (apt-cache(8))

Affiche des informations sur le ou les paquets donnés, y compris ses dépendances, la taille d'installation et de téléchargement, les sources depuis lesquelles le paquet est disponible, la description du contenu du paquet et bien plus encore. Cela peut être utile pour consulter ces informations avant de permettre à apt(8) de supprimer un paquet ou lors de la recherche de nouveaux paquets à installer.

list

list est quelque peu similaire à dpkg-query --list en ce qu'il peut afficher une liste de paquets satisfaisant certains critères. Il prend en charge les motifs glob(7) pour la correspondance des noms de paquets, apt-patterns(7), ainsi que des options pour lister les versions installées (--installed), pouvant être mises à niveau (--upgradeable) ou toutes les versions disponibles (--all-versions).

edit-sources (en cours de développement)

edit-sources vous permet de modifier vos sources.list(5) fichiers dans votre éditeur de texte préféré tout en fournissant des vérifications de cohérence de base.

showsrc, depends, rdepends, policy (résumé dans apt-cache(8))

source, build-dep, download, changelog, clean, distclean, autoclean (résumé dans apt-get(8))

UTILISATION EN SCRIPT ET DIFFÉRENCES AVEC LES AUTRES OUTILS APT

La apt(8) ligne de commande est conçue comme un outil pour l'utilisateur final et son comportement peut changer entre les versions. Bien qu'elle essaie de ne pas casser la rétrocompatibilité, cela n'est pas non plus garanti si un changement semble bénéfique pour un usage interactif.

Toutes les fonctionnalités de apt(8) sont disponibles dans les outils APT dédiés comme apt-get(8) et apt-cache(8) ainsi. apt(8) change simplement la valeur par défaut de certaines options (voir apt.conf(5) et spécifiquement la portée Binary). Vous devriez donc préférer utiliser ces commandes (potentiellement avec quelques options supplémentaires activées) dans vos scripts car elles conservent la rétrocompatibilité autant que possible.

Toutes les options de ligne de commande peuvent être définies via le fichier de configuration, les descriptions indiquent l'option de configuration à définir. Pour les options booléennes, vous pouvez écraser le fichier de configuration en utilisant quelque chose comme -f-,--no-f, -f=no ou plusieurs autres variations.

-h, --help

Affiche un court résumé de l'utilisation.

-v, --version

Affiche la version du programme.

--audit

Affiche les messages d'audit (et de notification). Cela écrase l'option quiet, mais seulement pour les messages de notification, pas pour ceux de progression.

-c, --config-file

Fichier de configuration ; Spécifie un fichier de configuration à utiliser. Le programme lira le fichier de configuration par défaut puis ce fichier de configuration. Si des paramètres de configuration doivent être définis avant l'analyse des fichiers de configuration par défaut, spécifiez un fichier avec la APT_CONFIG variable d'environnement. Voir apt.conf(5) pour les informations de syntaxe.

-o, --option

Définit une option de configuration ; Cela définira une option de configuration arbitraire. La syntaxe est -o Foo::Bar=bar. -o et --option peuvent être utilisés plusieurs fois pour définir différentes options.

--cli-version

Demande une version CLI spécifique. C'est un motif qui prend une version MAJEURE.MINEURE. Vous pouvez omettre la version mineure, auquel cas le niveau mineur le plus récent pris en charge sera utilisé.

Les pistes de version sont présentées comme suit : La version 3.2 a des versions équivalentes 0.32, 1.22 et 2.12, implémentant de nouvelles fonctionnalités pour leurs versions majeures spécifiées.

Un cas particulier est le motif de version X.9 : Une version comme 2.9 est suivie de 3.0, mais 2.10 suit directement 2.8 ; étant donné que nous utilisons les numéros de version impairs comme séries de développement (2.9 est la série de développement 3.0).

Cette fonctionnalité a été introduite dans APT 3.1.10 et remplace la configuration spécifique au binaire. Vous pouvez utiliser la APT::Version pour un effet similaire sur les anciens binaires, par exemple, utilisez -o APT::Version=2 pour faire apt(8) se comporter comme la série 2.x.

La valeur par défaut est la version APT actuelle pour apt(8) et 0.(10 * majeure + mineure) pour les commandes classiques. La série 0.X est obsolète de manière douce et les autres commandes passeront à la série 2.x à l'avenir.

--no-color, --color

Active ou désactive les couleurs. Les couleurs sont activées par défaut sur les terminaux pris en charge pour apt(8) et peuvent également être désactivées à l'aide des variables d'environnement NO_COLOR ou APT_NO_COLOR , ou encore configurées par l'option et la portée de configuration APT::Color , voir apt.conf(5) pour des informations à ce sujet.

VOIR AUSSI

apt-get(8), apt-cache(8), sources.list(5), apt.conf(5), apt-config(8), apt-patterns(7), Le guide de l'utilisateur APT dans /usr/share/doc/apt-doc/, apt_preferences(5), le Howto APT.

DIAGNOSTICS

apt renvoie zéro lors d'un fonctionnement normal, 100 en décimal en cas d'erreur.
