appstreamcli-compose - Compose un c

atalogue de métadonnées AppStream à
partir d'arbres de répertoires

SYNOPSI

S

appstreamcli compose [COMMAND

E
]

DESCRIPTIO

N

Cette page de manuel documente brièvement la commande appstreamc

li compose.

L'outil appstreamcli compose est utilisé pour construire des catalogues de métadonnées AppStream à partir d'arbres de répertoires. L'outil effectuera également de nombreuses actions de génération de métadonnées connexes, telles que le redimensionnement des icônes et des captures d'écran, ainsi que la fusion de données issues de fichiers d'entrée de bureau référencés et d'informations sur l'état de traduction. Par conséquent, l'outil fournit un moyen rapide de tester à quoi peuvent ressembler les métadonnées finales traitées d'une application qui est livrée aux utilisateurs. Il fournit également un moyen de générer facilement des données AppStream pour des projets qui n'ont pas besoin d'un générateur de données plus complexe comme appstream-generator

.

Afin que la commande appstreamcli compose soit disponible, vous devrez peut-être d'abord installer le module compose optionnel pour appstreamcli

.

Pour plus d'informations sur le projet AppStream et les autres composants qui en font partie, consultez les pages AppStream sur Freedeskto

p.or
g[1].

OPTION

S

RÉPERTOIRES-SOURCE

S
Une liste de répertoires à traiter doit être fournie sous la forme de paramètres positionnels. Les données de tous les répertoires seront combinées dans un seul espace de noms de
sortie.

--origin NO

M
Définit l'identifiant d'origine des données AppStream. Il peut s'agir d'une valeur comme "debian-unstable-main" ou
"flathub".

--result-root RÉ

P
Définit le répertoire dans lequel toutes les données générées déployées sur la machine d'un utilisateur sont exportées. Si ce paramètre n'est pas défini et que nous n'avons qu'un seul répertoire à traiter, nous utilisons ce répertoire comme chemin de sortie par défaut.

Si à la fois --data-dir et --icons-dir sont définis, --result-root n'est pas nécessaire et aucune

donnée ne sera écri
te dans ce répertoire.

--data-dir RÉ

P
Remplace le répertoire dans lequel le catalogue de métadonnées AppStream généré sera écrit. Les données seront écrites directement dans ce répertoire, et aucun sous-répertoire ne sera créé (contrairement à l'utilisation de --result-root pour définir un emplacement de sortie)
.

--icons-dir RÉ

P
Remplace le répertoire dans lequel les icônes en cache sont
exportées.

--hints-dir RÉ

P
Définit un répertoire dans lequel les rapports d'indices générés lors du traitement des métadonnées sont enregistrés. Si ce paramètre n'est pas défini, aucun rapport d'indices HTML/YAML ne sera
enregistré.

--media-dir RÉ

P
S'il est défini, crée un répertoire avec du contenu multimédia (icônes, captures d'écran, ...) qui peut être servi via un serveur web. Les métadonnées seront étendues pour inclure des informations sur ces médias
distants.

--media-baseurl UR

L
L'URL sous laquelle le contenu d'un répertoire défini via --media-dir sera servi. Cette valeur doit être définie si un répertoire multimédia est
créé.

--prefix RÉ

P
Définit le préfixe par défaut utilisé dans les répertoires traités. Si aucun n'est défini explicitement, /usr est
supposé.

--print-report MOD

E
Affiche le rapport d'indices de problèmes (qui est exporté en tant que document HTML et YAML lorsque --hints-dir était défini) sur la console sous forme de texte.

Divers modes d'affichage sont pris en charge : on-error n'affiche un rapport court que si l'exécution a échoué (par défaut), short génère un rapport abrégé qui est toujours affiché et full entraîne l'affichage

d'un rapp
ort détaillé.

--no-partial-url

s
S'il est défini, toutes les URL dans les données générées seront absolues et media_baseurl ne sera pas utilisé. Cela rend le changement de miroir multimédia plus difficile sans régénérer toutes les données et n'est généralement pas recommandé, afin d'augmenter la
flexibilité.

--icon-policy CHAÎNE-POLITIQU

E
Remplace la politique d'icônes existante par une personnalisée. La politique d'icônes définit comment les icônes de différentes tailles doivent être traitées. Elles peuvent être uniquement dans le cache d'icônes, être une icône distante dans l'emplacement multimédia, ou être à la fois en cache et disponibles dans l'emplacement distant.

La chaîne icon-policy est composée d'instructions %{size}x%{size}@%{scale}=%{state} séparées par des virgules. La taille et l'échelle sont celles de l'icône respective, l'échelle pouvant être omise si elle est 1. L'état peut être l'un des suivants : remote, cached ou

cached-remote.

Par défaut, la politique 48x48=cached,48x48@2=c

ached,64x64=cached,64x64@2=cached,128x128=cached-r
emote,128x128@2=cached-remote est sélectionnée.

--allow-custom NOMS-DE-CLES-PERSONNALISÉ

ES
Par défaut, toutes les entrées personnalisées définies dans les données d'entrée MetaInfo sont supprimées. Ce drapeau permet de mettre les clés personnalisées sur liste blanche pour qu'elles soient propagées aux données de sortie du catalogue final. Les noms des clés personnalisées doivent être fournis sous forme de liste séparée par des
virgules.

--components ID-COMPOSANT

S
Définit une liste d'ID de composants AppStream séparés par des virgules qui doivent être pris en compte pour les métadonnées générées. Tous les composants qui existent dans les données d'entrée mais qui ne sont pas mentionnés dans cette liste seront ignorés pour la sortie
générée.

--no-colo

r
N'affiche pas de sortie
colorée.

--verbos

e
Affiche des informations de débogage
supplémentaires

--versio

n
Affiche le numéro
de version de app
streamcli compose
