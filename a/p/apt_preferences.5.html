DESCRIPTIO

N

Le fichier de préférences APT /etc/apt/preferences et les fichiers fragments dans le dossier /etc/apt/preferences.d/ peuvent être utilisés pour contrôler quelles versions de paquets seront sélectionnées pour

l'installation.

Plusieurs versions d'un paquet peuvent être disponibles pour l'installation lorsque le fichier sources.list(5) contient des références à plus d'une distribution (par exemple, stable et testing). APT attribue une priorité à chaque version disponible. Sous réserve des contraintes de dépendances, apt-get sélectionne la version ayant la priorité la plus élevée pour l'installation. Les préférences APT remplacent les priorités qu'APT attribue par défaut aux versions de paquets, donnant ainsi à l'utilisateur le contrôle sur celle qui est sélectionnée pour

l'installation.

Plusieurs instances de la même version d'un paquet peuvent être disponibles lorsque le fichier sources.list(5) contient des références à plus d'une source. Dans ce cas, apt-get télécharge l'instance listée en premier dans le fichier sources.list(5). Les préférences APT n'affectent pas le choix de l'instance, seulement le choix de la

version.

Les préférences sont un pouvoir considérable entre les mains d'un administrateur système mais elles peuvent aussi devenir leur pire cauchemar si elles sont utilisées sans précaution ! APT ne remettra pas en question les préférences, de sorte que de mauvais réglages peuvent conduire à des paquets non installables ou à de mauvaises décisions lors de la mise à niveau des paquets. Encore plus de problèmes surgiront si plusieurs versions de distribution sont mélangées sans une bonne compréhension des paragraphes suivants. Les paquets inclus dans une version spécifique ne sont pas testés dans (et ne fonctionnent donc pas toujours comme prévu dans) les versions plus anciennes ou plus récentes, ou ensemble avec d'autres paquets de versions différentes. Vous avez été

averti.

Notez que les fichiers dans le répertoire /etc/apt/preferences.d doivent respecter la convention de nommage suivante : les fichiers n'ont soit aucune extension de nom de fichier, soit "pref" comme extension, et ne contiennent que des caractères alphanumériques, hyphen (-), souligné (_) et point (.). Sinon APT affichera un avis indiquant qu'il a ignoré un fichier, sauf si ce fichier correspond à un motif dans la liste de configuration Dir::Ignore-Files-Silently - auquel cas il sera ignoré en

silence.

/etc/apt/preferences est analysé en premier, suivi des fichiers dans /etc/apt/preferences.d dans l'ordre lexicographique. Par exemple, /etc/apt/preferences.d/00-high-priority.pref, /etc/apt/preferences.d/50-mid-priority et /etc/apt/preferences.d/z-low-priority.pref seraient analysés dans cet

ordre.

Attribution des priorités par défaut

d'APT

S'il n'y a pas de fichier de préférences ou s'il n'y a pas d'entrée dans le fichier qui s'applique à une version particulière, alors la priorité attribuée à cette version est la priorité de la distribution à laquelle cette version appartient. Il est possible de distinguer une distribution, « la version cible », qui reçoit une priorité plus élevée que les autres distributions par défaut. La version cible peut être définie sur la ligne de commande apt-get ou dans le fichier de configuration APT /etc/apt/apt.conf. Notez que cela a la priorité sur toute priorité générale que vous définissez dans le fichier /etc/apt/preferences décrit plus tard, mais pas sur les paquets épinglés spécifiquement. Par

exemple,

exécuté.

Plus rarement, la version installée d'un paquet est plus récente que toutes les autres versions disponibles. Le paquet ne sera pas rétrogradé lorsque apt-get install some-package ou apt-get upgrade est

exécuté.

Parfois, la version installée d'un paquet est plus récente que la version appartenant à la version cible, mais pas aussi récente qu'une version appartenant à une autre distribution. Un tel paquet sera en effet mis à niveau lorsque apt-get install some-package ou apt-get upgrade est exécuté, parce qu'au moins une des versions disponibles a une priorit

é plus élevée que

Mises à niveau

phasées

APT comprend un champ appelé Phased-Update-Percentage qui peut être utilisé pour contrôler le déploiement d'une nouvelle version. C'est un entier entre 0 et

100.

L'éligibilité d'un système à une mise à niveau phasée est déterminée en initialissant le générateur de nombres aléatoires avec le nom de la source du paquet, le numéro de version et /etc/machine-id, puis en calculant un entier dans l'intervalle [0, 100]. Si cet entier est supérieur à Phased-Update-Percentage, la version est épinglée à 1, et donc retenue. Sinon, les règles de politique normales

s'appliquent.

Si vous avez plusieurs systèmes qui doivent recevoir le même ensemble de mises à niveau, vous pouvez définir APT::Machine-ID

sur un UUID de sorte qu'ils soient tous phasés de la même manière, ou définir APT::Get::Never-Include-Phased-Updates o
u APT::Get::Always-Include-Phased-Updates sur true de sorte qu'APT n'inclura jamais/toujours les mises à niveau phasées.

L'effet des préférences

APT

Le fichier de préférences APT permet à l'administrateur système de contrôler l'attribution des priorités. Le fichier se compose d'une ou plusieurs entrées multi-lignesecords séparées par des lignes vides. Les enregistrements peuvent prendre l'une des deux formes suivantes, une forme spécifique et une forme

générale.
•La forme spécifique attribue une priorité (une « Pin-Priority ») à un ou plusieurs paquets spécifiés avec une version ou une plage de versions spécifiée. Par exemple, l'enregistrement suivant attribue une priorité élevée à toutes les versions du paquet perl dont le numéro de version commence par « 5.32 ». Cette entrée de forme générale dans le fichier de préférences APT ne s'applique qu'à des groupes de paquets. Par exemple, l'enregistrement suivant attribue une priorité élevée à toutes les versions de paquets disponibles depuis le site

Correspondance des paquets dans le champ

Package

Le champ Package spécifie le paquet auquel une priorité d'épinglage est appliquée. Le champ peut contenir soit un nom de paquet binaire, soit un nom de paquet source (préfixé par « src: »), soit une expression glob(7) ou une expression rationnelle (entourée de barres obliques). Plusieurs noms de paquets, expressions glob(7) et expressions rationnelles peuvent être listés séparés par des espaces, auquel cas l'enregistrement correspondra à n'importe lequel des paquets

correspondants.

Par défaut, seuls les paquets de l'architecture native correspondent. Pour faire correspondre les paquets binaires de n'importe quelle architecture, ajoutez le suffixe :any au nom du paquet. Vous pouvez également limiter la correspondance à une architecture spécifique en ajoutant le nom de l'architecture au nom du paquet, séparé par un caractère

deux-points.

Par exemple, l'exemple suivant utilise une expression glob et une expression rationnelle pour attribuer la priorité 500 à tous les paquets de experimental où le nom commence par gnome (comme une expression de type glob(7)) ou contient le mot kde (comme une expression rationnelle étendue POSIX entourée de barres obliques)

. 
Package: gnome* /kde/
Pin: release a=experime
ntal Pin-Priority: 500

La règle pour ces expressions est qu'elles peuvent apparaître partout où une chaîne peut apparaître. Ainsi, l'épinglage suivant attribue la priorité 990 à tous les paquets d'une version commençant par

plucky. 
Package: *
Pin: r
elease n=plucky*
Pin-Priority: 990

Si une expression rationnelle apparaît dans un champ Package, le comportement est le même que si cette expression rationnelle était remplacée par une liste de tous les noms de paquets qu'elle correspond. Il n'est pas décidé si cela changera à l'avenir ; vous devriez donc toujours lister les épinglages génériques en premier, afin que les épinglages spécifiques ultérieurs les remplacent. Le motif « * » dans un champ Package n'est pas considéré comme une expression glob(7) en

soi.

Pour épingler tous les binaires produits par le paquet source apt de cette version d'APT à 990, vous pouvez faire

: 
Package: src:apt
P
in: version 3.1.12
Pin-Priority: 990

L'épinglage de paquets source peut être combiné avec des expressions rationnelles et des motifs glob, et peut également prendre une architecture

binaire.

Par exemple, épinglons tous les binaires pour toutes les architectures produits par n'importe quel paquet source contenant apt dans son nom à 990

: 
Package: src:*apt*
:any Pin: version *
Pin-Priority: 990

Le suffixe :any garantit la sélection de paquets binaires de n'importe qu

elle architecture. Sans ce suffixe, apt suppose implicitement le suffixe
:native qui ne sélectionnerait que les paquets de l'architecture native.

Le premier enregistrement de forme spécifique correspondant à une version de paquet disponible détermine la priorité de la version du paquet.
