AppConfig::Args(3) Documentation Perl fournie par l'utilisateur AppConfig::Args(3)

NOM

AppConfig::Args - module Perl5 pour lire les arguments de la ligne de commande.

SYNOPSIS

use AppConfig::Args;
my $state   = AppConfig::State->new(\%cfg);
my $cfgargs = AppConfig::Args->new($state);
$cfgargs->parse(\@args);            # lire les arguments

APERÇU

AppConfig::Args est un module Perl5 qui lit les arguments de la ligne de commande et utilise les options qu'ils contiennent pour mettre à jour les valeurs des variables dans un objet AppConfig::State.

AppConfig::File est distribué dans le cadre du bundle AppConfig.

DESCRIPTION

UTILISATION DU MODULE AppConfig::Args

Pour importer et utiliser le module AppConfig::Args, la ligne suivante doit apparaître dans votre script Perl :

use AppConfig::Args;

AppConfig::Args est utilisé automatiquement si vous utilisez le module AppConfig et créez un objet AppConfig::Args via la méthode parse().

AppConfig::File est implémenté en utilisant des méthodes orientées objet. Un nouvel objet AppConfig::Args est créé et initialisé à l'aide de la méthode new(). Celle-ci renvoie une référence vers un nouvel objet AppConfig::File. Une référence vers un objet AppConfig::State doit être passée comme premier paramètre :

my $state   = AppConfig::State->new();
my $cfgargs = AppConfig::Args->new($state);

Ceci créera et retournera une référence vers un nouvel objet AppConfig::Args.

ANALYSE DES ARGUMENTS DE LA LIGNE DE COMMANDE

La méthode parse() est utilisée pour lire une liste d'arguments de la ligne de commande et mettre à jour l'état en conséquence. Une référence vers la liste d'arguments doit être passée.

$cfgargs->parse(\@ARGV);

Si la méthode est appelée sans référence à une liste d'arguments, elle examinera et manipulera @ARGV.

Si l'option PEDANTIC est désactivée dans l'objet AppConfig::State, toutes les erreurs d'analyse (variables invalides, valeurs non validées, etc.) généreront des avertissements, mais ne provoqueront pas le retour de la méthode. Après avoir traité tous les arguments, la méthode retournera 1 en cas de traitement sans avertissement ou 0 si un ou plusieurs avertissements ont été émis. Lorsque l'option PEDANTIC est activée, la méthode génère un avertissement et retourne immédiatement une valeur de 0 dès qu'elle rencontre une erreur d'analyse.

La méthode continue l'analyse des arguments jusqu'à ce qu'elle détecte le premier qui ne commence pas par un tiret, '-'. Les arguments qui constituent des valeurs pour d'autres options ne sont pas examinés de cette manière.

DÉVELOPPEMENT FUTUR

Ce module a été développé pour fournir une compatibilité ascendante (dans une certaine mesure) avec le module App::Config précédent. L'analyse des arguments qu'il fournit est basique mais offre une solution rapide et efficace pour les moments où seule une gestion simple des options est requise.

Si vous avez besoin de plus de flexibilité dans l'analyse des arguments de la ligne de commande, vous devriez envisager d'utiliser le module AppConfig::Getopt. Celui-ci est chargé et utilisé automatiquement en appelant la méthode getopt() d'AppConfig.

Le module AppConfig::Getopt fournit des fonctionnalités considérablement étendues par rapport au module AppConfig::Args en déléguant la tâche d'analyse des arguments au module Getopt::Long de Johan Vromans. Pour une analyse avancée de la ligne de commande, ce module (soit Getopt::Long seul, soit en conjonction avec AppConfig::Getopt) est fortement recommandé.
