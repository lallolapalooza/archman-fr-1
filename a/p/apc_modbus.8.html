MATÉRIEL PRIS EN

CHARGE

En général, ce pilote devrait fonctionner avec tous les appareils d'onduleur APC utilisant Modbus. Certains appareils peuvent exposer plus de fonctionnalités que ce qui est actuellement pris en charge, comme plusieurs phases. Une règle empirique générale est que les appareils APC (ou les versions de micrologiciel) sortis après 2010 sont plus susceptibles de prendre en charge Modbus que la norme USB

HID.

Testé avec le matériel suivant

:
•SMT1500 (Smart-UPS 1500, micrologiciel 9.
6)
•SMX750 (Smart-UPS X 750, micrologiciel 10.
1)
•SMX1500 (Smart-UPS X 1500, micrologiciel 15.
0)
•SMX2200 (Smart-UPS X 2200, micrologiciel 15.
0)

Notez que vous devrez activer la communication Modbus. Dans le panneau avant de l'onduleur, passez en mode Menu Avancé, sous Configuration, et activez

Modbus.

Note

Ce pilote a été testé avec les interfaces Modbus Série, TCP et USB. Notamment, les ports série ne sont pas disponibles sur tous les appareils de nos jours ; la prise en charge TCP peut nécessiter l'achat d'une carte de gestion réseau supplémentaire ; et la prise en charge USB nécessite actuellement une compilation non standard de libmodbus (une demande d'intégration à la bibliothèque amont est en attente, au moment de cette publication) comme prérequis pour

compiler NUT avec cette partie de la prise en charge. Pour plus de détails (y compris comme
nt compiler la bibliothèque personnalisée et NUT avec elle), veuillez consulter NUT PR #2063

Note

Tel que publié actuellement, ce pilote prend en charge la lecture des informations depuis l'onduleur. L'implémentation de la prise en charge de

l'écriture (définition de variables modifiables ou envoi de commandes) est prévue pour une version ultérieure. Cela peut en particulier impact
er les procédures d'arrêt de l'hôte (impossibilité d'indiquer activement à l'onduleur de s'éteindre ou de redémarrer à la fin). En contournement
, vous pouvez essayer d'intégrer apctest (du projet "apcupsd") avec un "Test to kill power" dans votre procédure d'arrêt tardif, si nécessaire.

x
FACULTATIF, NON RECOMMANDÉ.

Sélectionne un onduleur sur un bus USB spécifique ou un groupe de bus. L'argument est une expression régulière qui doit correspondre au nom du bus auquel l'onduleur est connecté (par ex. bus="002" ou bus="00[2-3]") comme vu sur Linux dans /sys/bus/usb/devices ou lsusb(8) ; y compris les zéros de

Prise en charge RTU

USB

Ce pilote s'appuie sur des fonctionnalités avancées de libmodbus pour parler le protocole Modbus sur USB spécifiquement (Série et TCP font partie de la bibliothèque commune). Au moment de la rédaction de ce document, le projet de bibliothèque commune attend simplement la fusion de la pull request avec cette

capacité.

Pour l'instant, si votre distribution OS ne fournit pas le jeu de fonctionnalités requis, vous devrez peut-être construire votre propre libmodbus et ensuite (re-)construire NUT contre cette bibliothèque, comme détaillé dans le Wiki GitHub NUT à https://github.com/networkupstools/nut/wiki/APC-UPS-with-Modbus-protoco

l

La séquence courte peut être la suivante

: 
cd ~/
git clone -b rtu_usb https://github.com/networkup
stools/libmodbus cd libmodbus ./autogen.sh ./configure -
-with-libusb --prefix=/chemin/vers/prefixe make install

•vous devrez peut-être « make && sudo make install » si vous souhaitez placer la variante de ces fichiers de bibliothèque dans un chemin système (comme --prefix=/usr/local/ups pour correspondre aux valeurs par défaut de NUT — cette activité nécessiterait une élévation de privilèges via sudo), et non dans votre répertoire personnel ou un emplacement
/tmp.
•à l'inverse, vous pouvez vouloir ./configure --with-libusb --enable-static --disable-shared --prefix=/chemin/vers/prefixe et uniquement construire et installer une libmod

Utilisation de noms d'hôtes pour la NMC de

l'onduleur

Une carte de gestion réseau d'onduleur peut se voir attribuer une adresse IP fixe/statique ou dynamique (par ex. par DHCP) dans votre réseau. En raison de cela, vous pouvez vouloir ou devoir utiliser un service de noms dynamique pour accéder à l'onduleur. Notez que cela peut devenir un problème spécifiquement lors de grandes coupures et arrêts, lorsque votre serveur DHCP/DNS pourrait déjà être hors service alors que le pilote doit résoudre le nom concerné (surtout lors des crochets d'arrêt tardif, lorsqu'une nouvelle instance du programme pilote pourrait démarrer juste pour dire à l'onduleur de s'éteindre ou de redémarrer)

.

Il peut être judicieux de vous assurer que votre client de service de noms OS pe

ut mettre en cache le nom de l'onduleur suffisamment longtemps, ou d'utilise
r une adressage IP fixe (et une entrée dans /etc/hosts par mesure de précaut
ion, afin que vous n'ayez qu'un seul endroit à reconfigurer éventuellement).
