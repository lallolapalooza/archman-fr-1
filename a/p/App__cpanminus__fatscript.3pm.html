NOM

cpanm - récupérer, décompresser, compiler et installer des modules depuis CPAN

SYNOPSIS

cpanm Test::More                                 # installer Test::More
cpanm MIYAGAWA/Plack-0.99_05.tar.gz              # chemin complet de la distribution
cpanm http://example.org/LDS/CGI.pm-3.20.tar.gz  # installer depuis une URL
cpanm ~/dists/MyCompany-Enterprise-1.00.tar.gz   # installer depuis un fichier local
cpanm --interactive Task::Kensho                 # Configurer de manière interactive
cpanm .                                          # installer depuis un répertoire local
cpanm --installdeps .                            # installer toutes les dépendances du répertoire courant
cpanm -L extlib Plack                            # installer Plack et toutes les dépendances non-core dans extlib
cpanm --mirror http://cpan.cpantesters.org/ DBI  # utiliser le miroir à synchronisation rapide
cpanm --from https://cpan.metacpan.org/ Plack    # utiliser uniquement le miroir HTTPS

COMMANDES

(arguments)
Les arguments de la ligne de commande peuvent être un nom de module, un fichier de distribution, un chemin de fichier local, une URL HTTP ou une URL de dépôt git. Les commandes suivantes fonctionneront toutes comme vous l'attendez. 
cpanm Plack
cpanm Plack/Request.pm
cpanm MIYAGAWA/Plack-1.0000.tar.gz
cpanm /path/to/Plack-1.0000.tar.gz
cpanm http://cpan.metacpan.org/authors/id/M/MI/MIYAGAWA/Plack-0.9990.tar.gz
cpanm git://github.com/plack/Plack.git

De plus, vous pouvez utiliser la notation avec "~" et "@" pour spécifier la version d'un module donné. "~" spécifie l'exigence de version au format CPAN::Meta::Spec, tandis que "@" fixe la version exacte, et est un raccourci pour "~"== VERSION"".

cpanm Plack~1.0000                 # 1.0000 ou plus récent
cpanm Plack~">= 1.0000, < 2.0000"  # le plus récent des 1.xxxx
cpanm Plack@0.9990                 # version spécifique. identique à Plack~"== 0.9990"

La requête de version incluant une version ou une plage spécifique sera envoyée à MetaCPAN pour rechercher des versions précédentes. La requête cherchera dans les archives BackPAN par défaut, sauf si vous spécifiez l'option "--dev" , auquel cas, les versions archivées seront filtrées.

Pour un dépôt git, vous pouvez spécifier une branche, une étiquette ou un SHA de commit à compiler. La valeur par défaut est "master"

cpanm git://github.com/plack/Plack.git@1.0000        # étiquette
cpanm git://github.com/plack/Plack.git@devel         # branche
-i, --install
Installe les modules. C'est le comportement par défaut et c'est juste une option de compatibilité pour qu'il fonctionne comme cpan ou cpanp.
--self-upgrade
Se met à jour lui-même. C'est juste un alias pour : 
cpanm App::cpanminus
--info
Affiche les informations de la distribution au format "AUTEUR/Nom-Dist-ver.tar.gz" sur la sortie standard.
--installdeps
Installe les dépendances de la distribution cible mais ne la compile pas elle-même. Pratique si vous voulez essayer l'application depuis un dépôt sous contrôle de version tel que git. 
cpanm --installdeps .
--look
Télécharge et décompresse la distribution puis ouvre le répertoire avec votre shell. Pratique pour explorer le code source ou effectuer des tests manuels.
-h, --help
Affiche le message d'aide.
-V, --version
Affiche le numéro de version.

OPTIONS

Vous pouvez spécifier les options par défaut dans la variable d'environnement "PERL_CPANM_OPT" .

-f, --force
Force l'installation des modules même si les tests ont échoué.
-n, --notest
Ignore les tests des modules. Utilisez ceci seulement quand vous voulez simplement gagner du temps en installant des centaines de distributions sur le même perl et la même architecture que vous avez déjà testés pour vous assurer qu'ils se compilent correctement.

Par défaut à faux, et vous pouvez dire "--no-notest" pour annuler quand c'est défini dans les options par défaut dans "PERL_CPANM_OPT".

--test-only
Exécute uniquement les tests, et n'installe pas le module ou les distributions spécifiés. Pratique si vous voulez vérifier que les nouvelles (ou même anciennes) versions passent leurs tests unitaires sans installer le module.

Notez que si vous spécifiez cette option avec un module ou une distribution qui a des dépendances, ces dépendances seront installées si vous ne les avez pas actuellement.

-S, --sudo
Passe à l'utilisateur root avec "sudo" lors de l'installation des modules. Utilisez ceci si vous voulez installer des modules dans le chemin d'inclusion du perl système.

Par défaut à faux, et vous pouvez dire "--no-sudo" pour annuler quand c'est défini dans les options par défaut dans "PERL_CPANM_OPT".

-v, --verbose
Rend la sortie verbeuse. Cela active aussi la configuration interactive. (Voir --interactive)
-q, --quiet
Rend la sortie encore plus silencieuse que par défaut. Elle n'affiche que les dépendances réussies/échouées dans la sortie.
-l, --local-lib
Définit le chemin compatible local::lib où installer les modules. Vous n'avez pas besoin de définir ceci si vous configurez déjà les variables d'environnement du shell avec local::lib, mais cela peut aussi être utilisé pour annuler cela.
-L, --local-lib-contained
Identique à "--local-lib" mais avec --self-contained défini. Toutes les dépendances non-core seront installées même si elles sont déjà installées.

Par exemple,

cpanm -L extlib Plack

installerait Plack et toutes ses dépendances non-core dans le répertoire "extlib", qui peut être chargé depuis votre application avec :

use local::lib '/path/to/extlib';

Notez que cette option ne fonctionne PAS de manière fiable avec les installations de perl fournies par les distributeurs du système d'exploitation qui suppriment les modules standard de perl, tels que RHEL, Fedora et CentOS, SAUF SI vous installez aussi les paquets fournissant tous les modules qui ont été supprimés. Pour ces systèmes, vous voudrez probablement installer le méta-paquet "perl-core" qui fait exactement cela.

--self-contained
Lors de l'examen des dépendances, suppose qu'aucun module non-core n'est installé sur le système. Pratique si vous voulez regrouper les dépendances de l'application dans un seul répertoire pour pouvoir les distribuer à d'autres machines.
--exclude-vendor
N'inclut pas les modules installés sous les chemins 'vendor' lors de la recherche de modules core quand l'indicateur "--self-contained" est actif. Cela restaure le comportement d'avant la version 1.7023
--mirror
Spécifie l'URL de base du miroir CPAN à utiliser, tel que "http://cpan.cpantesters.org/" (vous pouvez omettre la barre oblique finale). Vous pouvez spécifier plusieurs URL de miroir en répétant l'option de ligne de commande.

Vous pouvez utiliser un répertoire local qui a une structure de miroir CPAN (créé par des outils tels qu'OrePAN ou Pinto) en utilisant un schéma d'URL spécial "file://". Si l'URL donnée commence par `/` (sans aucun schéma), elle est considérée comme un schéma fichier également.

cpanm --mirror file:///path/to/mirror
cpanm --mirror ~/minicpan      # Parce que le shell développe ~ en /home/user

Par défaut à "http://www.cpan.org/".

--mirror-only
Télécharge l'index 02packages.details.txt.gz du miroir fichier au lieu d'interroger la base de données CPAN Meta. Cela aura également pour effet d'opter pour ne pas envoyer vos versions de perl locales aux serveurs de bases de données tels que CPAN Meta DB et MetaCPAN.

Sélectionnez cette option si vous utilisez un miroir local de CPAN, comme minicpan lorsque vous êtes hors ligne, ou votre propre index CPAN (aussi appelé darkpan).

--from, -M
cpanm -M https://cpan.metacpan.org/
cpanm --from https://cpan.metacpan.org/

Utilise l'URL du miroir donnée et son index comme seule source pour rechercher et télécharger des modules.

Cela fonctionne de manière similaire à "--mirror" et "--mirror-only" combinés, avec une petite différence : contrairement à "--mirror" qui ajoute l'URL à la liste des miroirs, "--from" (ou "-M" en abrégé) utilise l'URL spécifiée comme seule source pour télécharger l'index et les modules. Cela fait que l'option remplace toujours le miroir par défaut, qui aurait pu être défini via des options globales comme celle définie par la variable d' environnement "PERL_CPANM_OPT".

Astuce : Il peut être utile de nommer ces options avec des alias de votre shell, comme :

alias minicpanm='cpanm --from ~/minicpan'
alias darkpan='cpanm --from http://mycompany.example.com/DPAN'
--mirror-index
EXPÉRIMENTAL: Spécifie le chemin du fichier vers "02packages.details.txt" pour l'index de recherche des modules.
--cpanmetadb
EXPÉRIMENTAL: Spécifie une URI alternative pour les recherches dans l'index CPAN MetaDB.
--metacpan
Préfère l'API MetaCPAN à CPAN MetaDB.
--cpanfile
EXPÉRIMENTAL: Spécifie un chemin alternatif pour rechercher le cpanfile, lorsque la commande "--installdeps" est utilisée. Par défaut, c'est "cpanfile".
--prompt
Invite à l'utilisateur lorsqu'un test échoue afin que vous puissiez passer, forcer l'installation, réessayer ou regarder dans le shell pour voir ce qui ne va pas. Cela invite également lorsque l'une des dépendances a échoué, si vous voulez poursuivre l'installation.

Par défaut, c'est faux, et vous pouvez dire "--no-prompt" pour écraser cette valeur si elle est définie dans les options par défaut dans "PERL_CPANM_OPT".

--dev
EXPÉRIMENTAL: recherche également une version de développement plus récente. Par défaut, c'est faux.
--reinstall
cpanm, lorsqu'un nom de module est donné sur la ligne de commande (c'est-à-dire "cpanm Plack"), vérifie d'abord la version installée localement et passe à la suivante si elle est déjà installée. Cette option fait qu'il saute cette vérification, ainsi : 
cpanm --reinstall Plack

réinstallerait Plack même si votre version installée localement est la plus récente, ou même plus récente (ce qui arriverait si vous installez une version de développement depuis des dépôts de contrôle de version).

Par défaut, c'est faux.

--interactive
Rend la configuration (comme "Makefile.PL" et "Build.PL") interactive, afin que vous puissiez répondre aux questions dans la distribution qui nécessite une configuration personnalisée ou les distributions Task::.

Par défaut, c'est faux, et vous pouvez dire "--no-interactive" pour écraser cette valeur lorsqu'elle est définie dans les options par défaut dans "PERL_CPANM_OPT".

--pp, --pureperl
Préfère la construction Pure perl des modules en définissant "PUREPERL_ONLY=1" pour MakeMaker et "--pureperl-only" pour les distributions basées sur Build.PL. Notez que tous les modules de CPAN ne supportent pas encore cette convention.
--with-recommends, --with-suggests
EXPÉRIMENTAL: Installe les dépendances déclarées comme "recommends" et "suggests" respectivement, selon la spécification META. Lorsque ces dépendances échouent à s'installer, cpanm continue l'installation, car ce ne sont que des recommandations/suggestions.

Activer cela pourrait potentiellement créer une dépendance circulaire pour quelques modules sur CPAN, lorsque "recommends" ajoute un module qui "recommends" en retour le module d'origine.

Il y a aussi "--without-recommend" et "--without-suggests" pour écraser la décision par défaut prise plus tôt dans "PERL_CPANM_OPT".

Par défaut, c'est faux pour les deux.

--with-develop
EXPÉRIMENTAL: Installe les dépendances de phase de développement dans les fichiers META ou le "cpanfile" lorsqu'il est utilisé avec "--installdeps". Par défaut, c'est faux.
--with-configure
EXPÉRIMENTAL: Installe les dépendances de phase de configuration dans le "cpanfile" lorsqu'il est utilisé avec "--installdeps". Par défaut, c'est faux.
--with-feature, --without-feature, --with-all-features
EXPÉRIMENTAL: Spécifie la fonctionnalité à activer, si un module supporte des fonctionnalités optionnelles selon la spécification META 2.0. 
cpanm --with-feature=opt_csv Spreadsheet::Read

les fonctionnalités peuvent aussi être choisies de manière interactive lorsque l'option "--interactive" est activée.

"--with-all-features" active toutes les fonctionnalités optionnelles, et "--without-feature" peut sélectionner une fonctionnalité à désactiver.

--configure-timeout, --build-timeout, --test-timeout
Spécifie la durée du délai d'attente (en secondes) pour les processus de configuration, de construction et de test. Les valeurs par défaut actuelles sont : 60 pour la configuration, 3600 pour la construction et 1800 pour le test.
--configure-args, --build-args, --test-args, --install-args
EXPÉRIMENTAL: Passe des arguments aux commandes de configuration/construction/test/installation respectivement, pour un module donné à installer. 
cpanm DBD::mysql --configure-args="--cflags=... --libs=..."

L'argument n'est activé que pour le module passé comme argument de ligne de commande, pas pour les dépendances.

--scandeps
OBSOLÈTE: Analyse les dépendances des modules donnés et affiche l'arbre dans un format texte. (Voir "--format" ci-dessous pour plus d'options)

Parce que cette commande n'installe en fait aucune distribution, il sera utile de taper :

cpanm --scandeps Catalyst::Runtime

vous pouvez vérifier quels modules seront installés.

Cette commande prend en compte les modules que vous avez déjà installés sur votre système. Si vous voulez voir quels modules seront installés sur une installation perl vierge, vous pourriez vouloir la combiner avec l'option "-L" .

--format
OBSOLÈTE: Détermine le format d'affichage de l'arbre de dépendances analysé. Les options disponibles sont "tree", "json", "yaml" et "dists".
tree
Affiche l'arbre dans un format texte simple. C'est la valeur par défaut.
json, yaml
Affiche l'arbre dans un format JSON ou YAML. Les modules JSON et YAML doivent être installés respectivement. L'arbre de sortie est représenté comme un tuple récursif de : 
[ distribution, dépendances ]

et le conteneur est un tableau contenant les éléments racines. Notez qu'il peut y avoir plusieurs nœuds racines, car vous pouvez donner plusieurs modules à la commande "--scandeps" .

dists
"dists" est un format de sortie spécial, où il affiche le nom de fichier de la distribution dans l' ordre de parcours en profondeur après la résolution des dépendances, comme : 
GAAS/MIME-Base64-3.13.tar.gz
GAAS/URI-1.58.tar.gz
PETDANCE/HTML-Tagset-3.20.tar.gz
GAAS/HTML-Parser-3.68.tar.gz
GAAS/libwww-perl-5.837.tar.gz

ce qui signifie que vous pouvez installer ces distributions dans cet ordre sans dépendances supplémentaires. Lorsqu'il est combiné avec l'option "-L" , il sera utile pour rejouer des installations sur d'autres machines.

--save-dists
Spécifie le chemin de répertoire optionnel où copier les tarballs téléchargés dans la structure de répertoire compatible avec le miroir CPAN, c'est-à-dire authors/id/A/AU/AUTHORS/Foo-Bar-version.tar.gz

Si le tarball de la distribution ne vient pas de CPAN, par exemple depuis un fichier local ou depuis GitHub, alors il sera enregistré sous vendor/Foo-Bar-version.tar.gz.

--uninst-shadows
Désinstalle les fichiers fantômes (shadow) de la distribution que vous êtes en train d'installer. Cela élimine la confusion si vous essayez d'installer des modules core (double vie) depuis CPAN sur perl 5.10 ou plus ancien, ou des modules qui étaient basés sur XS mais qui sont passés à pure perl à une certaine version.

Si vous exécutez cpanm en tant que root et utilisez "INSTALL_BASE" ou l'équivalent pour spécifier un chemin d'installation personnalisé, vous DEVRIREZ désactiver cette option pour que vous ne désinstalliez pas accidentellement des modules double vie depuis le chemin d'inclusion core.

Par défaut, c'est vrai si votre version de perl est inférieure à 5.12, et vous pouvez désactiver cela avec "--no-uninst-shadows".

NOTE>: Depuis la version 1.3000, cette option est désactivée par défaut pour perl plus récent que 5.12, car avec 5.12 @INC contient le répertoire site_perl av
