DESCRIPTIO

N

bmake est un programme conçu pour simplifier la maintenance d'autres programmes. Son entrée est une liste de spécifications indiquant les fichiers dont dépendent les programmes et les autres fichiers. Si l'option -f makefile n'est pas donnée, bmake recherche les makefiles listés dans .MAKE.MAKEFILE_PREFERENCE (par défaut «makefile », «Makefile ») afin de trouver les spécifications. Si le fichier «.depend » existe, il est lu, voir mkdep(

1).

Cette page de manuel est destinée à servir uniquement de document de référence. Pour une description plus approfondie de bmake et des makefiles, veuillez consulter PMake - A Tutorial (de 1993)

.

bmake préfixe le contenu de la variable d'environnement MAKEFLAGS aux arguments de la ligne de commande avant de les

analyser.

SPÉCIFICATIONS DE DÉPENDANCES DE

FICHIER

Les lignes de dépendance se composent d'une ou plusieurs cibles, d'un opérateur et de zéro ou plusieurs sources. Cela crée une relation où les cibles « dépendent » des sources et sont habituellement créées à partir de celles-ci. Une cible est considérée comme périmée si elle n'existe pas, ou si son temps de modification is moins grand que celui de n'importe laquelle de ses sources. Une cible obsolète est recréée, mais pas avant que toutes les sources aient été examinées et elles-mêmes recréées si nécessaire. Trois opérateurs peuvent être utilisés

:
De nombreuses lignes de dépendance peuvent nommer cette cible mais une seule peut avoir des commandes shell associées. Toutes les sources nommées dans toutes les lignes de dépendance sont considérées ensemble, et si nécessaire, les commandes shell associées sont exécutées pour créer ou recréer la cible. Si bmake est interrompu, la cible est
supprimée.
!
Idem, mais la cible est toujours recréée, qu'elle soit obsolète ou
non.

:

Ainsi, différents groupes de commandes shell associées peuvent être exécutés selon les circonstances. De plus, contrairement à :, pour les lignes de dépendance sans sources, les commandes shell associées sont toujours exécutées. Aussi contrairement à :, la cible n'est pas supprimée si bmake est

Les caractères ‘?’, ‘*’, et ‘[]’ ne peuvent être utilisés que comme partie du dernier composant de la cible ou de la source, et ne correspondent qu'aux fichiers existants. COMMANDES

Chaque cible peut avoir associée une ou plusieurs lignes de commandes shell, normalement utilisées pour créer la cible. Chacune des lignes dans ce script doit être précédée d'une tabulation. (Pour des raisons historiques, les espaces ne sont pas acceptés.) Si l'opérateur ‘::’ est utilisé, cependant, toutes les règles peuvent inclure des scripts, et les scripts respectifs sont exécutés dans l'ordre où ils sont

trouvés.

Chaque ligne est traitée comme une commande shell distincte, sauf si la fin de ligne est échappée avec une barre oblique inverse ‘\’, auquel cas cette ligne et la suivante sont combinées. Quand bmake est exécuté en mode jobs avec -j max_jobs, le script entier de la cible est fourni à une seule instance du shell. En mode de compatibilité (non jobs), chaque commande est exécutée dans un processus séparé. Si la commande contient des métacaractères de shell (‘#=|^(){};&<>*?[]:$`\\n’), elle est passée au shell ; sinon bmake tente l'exécution directe. Si une ligne commence par ‘-’ et que le shell a ErrCtl activé, l'échec de la ligne de commande est ignoré comme en mode de compatibilité. Sinon ‘-’ affecte l'ensemble de la tâche ; le script s'arrête à la première ligne de commande qui échoue, mais la cible n'est pas considérée comme ayant

Boucles For

Les boucles for sont généralement utilisées pour appliquer un ensemble de règles à une liste de fichiers. La syntaxe d'une boucle for est :

.for variable [variable ...] in expression
 
⟨lignes-make⟩
 
.endfor
 

L'expression est développée puis divisée en mots. À chaque itération de la boucle, un mot est pris et assigné à chaque variable, dans l'ordre, et ces variables sont substituidas dans les lignes-make à l'intérieur du corps de la boucle for. Le nombre de mots doit être pair ; c'est-à-dire, s'il y a trois variables d'itération, le nombre de mots fournis doit être un multiple de trois.

Si ‘.break’ est rencontré dans une boucle .for, cela provoque une terminaison anticipée de la boucle, sinon une erreur d'analyse.
