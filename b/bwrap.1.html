NOM

bwrap - utilitaire de configuration de bac à sable

SYNTAXE

bwrap [OPTION...] [COMMANDE]

DESCRIPTION

bwrap est un outil de bac à sable de bas niveau sans privilèges (optionnellement setuid sur les distributions plus anciennes). Vous ne l'utiliserez probablement pas directement en ligne de commande, bien que cela soit possible.

Il fonctionne en créant un nouvel espace de noms de système de fichiers, complètement vide, où la racine est sur un tmpfs qui est invisible depuis l'hôte, et qui sera automatiquement nettoyé lorsque le dernier processus se terminera. Vous pouvez ensuite utiliser les options de la ligne de commande pour construire le système de fichiers racine et l'environnement de processus pour la commande à exécuter dans l'espace de noms.

Par défaut, bwrap crée un nouvel espace de noms de montage pour le bac à sable. Optionnellement, il configure également de nouveaux espaces de noms utilisateur, ipc, pid, réseau et uts (mais notez que l'espace de noms utilisateur est requis si bwrap n'est pas installé en tant que setuid root).

Si nécessaire (par exemple, lors de l'utilisation d'un espace de noms PID), bwrap exécute un processus minimal pid 1 dans le bac à sable, responsable de la récupération des zombies. Il détecte également la mort du processus applicatif initial (pid 2) et renvoie son statut de sortie à l'appelant d'origine. Le processus pid 1 se termine pour nettoyer le bac à sable lorsqu'il n'y a plus d'autres processus dans le bac à sable.

OPTIONS

Lorsque les options sont utilisées plusieurs fois, la dernière option l'emporte, sauf indication contraire.

Options générales :

--help

Affiche l'aide et quitte

--version

Affiche la version

--args FD

Analyse les arguments séparés par NUL à partir du descripteur de fichier donné. Cette option peut être utilisée plusieurs fois pour analyser des options à partir de plusieurs sources.

--argv0 VALEUR

Définit argv[0] à la valeur VALEUR avant d'exécuter le programme

--level-prefix

Précède chaque ligne de sortie diagnostique d'un niveau de gravité numérique entre crochets angulaires. Les niveaux de gravité utilisés sont basés sur les constantes utilisées par syslog(3) : par exemple, <4> indique un avertissement, car LOG_WARNING a la valeur numérique 4. Les nombres inférieurs à 4 indiquent des erreurs fatales, et les nombres supérieurs à 4 indiquent des messages informatifs. Ces préfixes peuvent être analysés par des outils compatibles avec logger --prio-prefix (voir logger(1)) ou systemd-cat --level-prefix=1 (voir systemd-cat(1)).

Options relatives aux espaces de noms du noyau :

--unshare-user

Crée un nouvel espace de noms utilisateur

--unshare-user-try

Crée un nouvel espace de noms utilisateur si possible, sinon l'ignore

--unshare-ipc

Crée un nouvel espace de noms ipc

--unshare-pid

Crée un nouvel espace de noms pid

--unshare-net

Crée un nouvel espace de noms réseau

--unshare-uts

Crée un nouvel espace de noms uts

--unshare-cgroup

Crée un nouvel espace de noms cgroup

--unshare-cgroup-try

Crée un nouvel espace de noms cgroup si possible, sinon l'ignore

--unshare-all

Crée de nouveaux tous les espaces de noms possibles. Actuellement équivalent à : --unshare-user-try --unshare-ipc --unshare-pid --unshare-net --unshare-uts --unshare-cgroup-try

--share-net

Conserve l'espace de noms réseau, remplaçant un --unshare-all ou --unshare-net précédent

--userns FD

Utilise un espace de noms utilisateur existant au lieu d'en créer un nouveau. L'espace de noms doit satisfaire les exigences d'autorisation pour setns(), ce qui signifie généralement qu'il doit être un descendant de l'espace de noms utilisateur actuellement actif, appartenant au même utilisateur.

Ceci est incompatible avec --unshare-user et ne fonctionne pas dans la version setuid de bubblewrap.

--userns2 FD

Après avoir configuré le nouvel espace de noms, bascule vers l'espace de noms spécifié. Pour que cela fonctionne, l'espace de noms spécifié doit être un descendant de l'espace de noms utilisateur utilisé pour la configuration, donc ceci n'est utile qu'en combinaison avec --userns.

Ceci est utile car bubblewrap crée parfois des espaces de noms utilisateur imbriqués (pour contourner certains problèmes du noyau) et --userns2 peut être utilisé pour entrer dans ces espaces.

--disable-userns

Empêche le processus dans le bac à sable de créer d'autres espaces de noms utilisateur, afin qu'il ne puisse pas réorganiser l'espace de noms du système de fichiers ou effectuer d'autres modifications complexes d'espace de noms. Ceci est actuellement implémenté en réglant le sysctl user.max_user_namespaces à 1, puis en entrant dans un espace de noms utilisateur imbriqué qui ne peut pas augmenter cette limite dans l'espace de noms externe. Cette option nécessite --unshare-user et ne fonctionne pas dans la version setuid de bubblewrap.

--assert-userns-disabled

Confirme que le processus dans le bac à sable a été empêché de créer d'autres espaces de noms utilisateur, sans prendre de mesure particulière pour l'empêcher. Par exemple, cela peut être combiné avec --userns pour vérifier que l'espace de noms utilisateur donné a déjà été configuré pour empêcher la création d'espaces de noms utilisateur supplémentaires.

--pidns FD

Utilise un espace de noms pid existant au lieu d'en créer un. Ceci est souvent utilisé avec --userns, car l'espace de noms pid doit appartenir au même espace de noms utilisateur que celui utilisé par bwrap.

Notez que cela peut être combiné avec --unshare-pid, et dans ce cas, cela signifie que le bac à sable sera dans son propre espace de noms pid, qui est un enfant de celui fourni.

--uid UID

Utilise un identifiant utilisateur personnalisé dans le bac à sable (nécessite --unshare-user)

--gid GID

Utilise un identifiant de groupe personnalisé dans le bac à sable (nécessite --unshare-user)

--hostname NOMHOTE

Utilise un nom d'hôte personnalisé dans le bac à sable (nécessite --unshare-uts)

Options de configuration de l'environnement :

--chdir DIR

Change le répertoire courant vers DIR

--setenv VAR VALEUR

Définit une variable d'environnement

--unsetenv VAR

Supprime une variable d'environnement

--clearenv

Supprime toutes les variables d'environnement, à l'exception de PWD et de celles qui sont ensuite définies par --setenv

Options pour surveiller le bac à sable de l'extérieur :

--lock-file DEST

Prend un verrou sur DEST pendant que le bac à sable fonctionne. Cette option peut être utilisée plusieurs fois pour prendre des verrous sur plusieurs fichiers.

--sync-fd FD

Garde ce descripteur de fichier ouvert pendant que le bac à sable fonctionne

Options relatives au système de fichiers. Ce sont toutes des opérations qui modifient directement le système de fichiers, ou qui montent des éléments dans le système de fichiers. Elles sont appliquées dans l'ordre où elles apparaissent en tant qu'arguments.

Tous les répertoires parents manquants nécessaires à la création d'une destination spécifiée sont automatiquement créés. Leurs permissions sont normalement définies à 0755 (rwxr-xr-x). Cependant, si une option --perms est en vigueur et qu'elle définit les permissions pour le groupe ou les autres à zéro, alors les répertoires parents nouvellement créés auront également leurs permissions correspondantes définies à zéro. --size modifie la taille du montage créé lorsqu'il précède une action --tmpfs ; --perms et --size peuvent être combinés.

--perms OCTAL

Cette option ne fait rien par elle-même et doit être suivie par l'une des options qu'elle affecte. Elle définit les permissions pour la prochaine opération à OCTAL. Les opérations suivantes ne sont pas affectées : par exemple, --perms 0700 --tmpfs /a --tmpfs /b montera /a avec les permissions 0700, puis reviendra aux permissions par défaut pour /b. Notez que --perms et --size peuvent être combinés : --perms 0700 --size 10485760 --tmpfs /s appliquera les permissions ainsi qu'une taille maximale au tmpfs créé.

--size OCTETS

OPTIONS

--tmpfs DEST

Montez un nouveau tmpfs sur DEST. Si l'option précédente était --perms, elle définit le mode du tmpfs. Sinon, le tmpfs a le mode 0755. Si l'option précédente était --size, elle définit la taille en octets du tmpfs. Sinon, le tmpfs a la taille par défaut.

--size OCTAL

Définit la taille de l'option --tmpfs suivante en octets.

--perms OCTAL

Définit le mode de l'option --tmpfs ou --dir ou --file ou --bind-data ou --ro-bind-data suivante.

Par exemple, --size 10485760 --perms 0700 --tmpfs /tmp montera un tmpfs sur /tmp d'une taille de 10MiB. Les opérations suivantes ne sont pas affectées : par exemple, --size 10485760 --tmpfs /a --tmpfs /b montera /a avec une taille de 10MiB, puis reviendra à la taille par défaut pour /b. Notez que --perms et --size peuvent être combinés : --size 10485760 --perms 0700 --tmpfs /s appliquera les permissions ainsi qu'une taille maximale au tmpfs créé.

--bind SRC DEST

Montez le chemin hôte SRC sur DEST en mode bind.

--bind-try SRC DEST

Égal à --bind mais ignore les SRC inexistants.

--dev-bind SRC DEST

Montez le chemin hôte SRC sur DEST en mode bind, autorisant l'accès aux périphériques.

--dev-bind-try SRC DEST

Égal à --dev-bind mais ignore les SRC inexistants.

--ro-bind SRC DEST

Montez le chemin hôte SRC sur DEST en mode bind en lecture seule.

--ro-bind-try SRC DEST

Égal à --ro-bind mais ignore les SRC inexistants.

--remount-ro DEST

Remonte le chemin DEST en lecture seule. Cela ne fonctionne que sur le point de montage spécifié, sans modifier aucun autre point de montage sous le chemin spécifié.

--overlay-src SRC

Cette option ne fait rien par elle-même et doit être suivie par l'une des autres options d'overlay. Elle spécifie un chemin hôte à partir duquel les fichiers doivent être lus s'ils ne sont pas présents dans une couche supérieure.

Cette option peut être utilisée plusieurs fois pour fournir plusieurs sources. Les sources sont superposées dans l'ordre donné, la première source de la ligne de commande étant en bas de la pile : si un chemin donné à lire existe dans plus d'une source, le fichier est lu à partir de la dernière source spécifiée.

(Pour les lecteurs familiers avec overlayfs, notez que c'est l'inverse de l'ordre utilisé par l'option de montage lowerdir du noyau.)

--overlay RWSRC WORKDIR DEST

--tmp-overlay DEST

--ro-overlay DEST

Utilise overlayfs pour monter les chemins hôtes spécifiés par RWSRC et tous les --overlay-src immédiatement précédents sur DEST. DEST contiendra l'union de tous les fichiers de toutes les couches.

Avec --overlay, toutes les écritures iront dans RWSRC. Les lectures proviendront préférentiellement de RWSRC, puis de tous les chemins --overlay-src. WORKDIR doit être un répertoire vide sur le même système de fichiers que RWSRC et est utilisé en interne par le noyau.

Avec --tmp-overlay, toutes les écritures iront dans le tmpfs qui héberge la racine du sandbox, dans un emplacement non accessible depuis l'hôte ou le processus enfant. Les écritures ne seront donc pas persistantes entre plusieurs exécutions.

Avec --ro-overlay, le système de fichiers sera monté en lecture seule. Cette option nécessite au moins deux --overlay-src pour la précéder.

Aucune de ces options n'est disponible dans la version setuid de bubblewrap. L'utilisation de --ro-overlay ou la fourniture de plus d'un --overlay-src nécessite un noyau Linux version 4.0 ou ultérieure.

En raison des limitations d'overlayfs, aucun répertoire hôte donné via --overlay-src ou --overlay ne peut être un ancêtre d'un autre, après résolution des liens symboliques. Selon la version, le noyau Linux peut ou non appliquer cette règle, mais sinon, le comportement d'overlayfs est indéfini.

Pour plus d'informations, consultez la documentation du système de fichiers Overlay dans le noyau Linux à l'adresse https://www.kernel.org/doc/Documentation/filesystems/overlayfs.txt

--proc DEST

Montez procfs sur DEST.

--dev DEST

Montez nouveau devtmpfs sur DEST.

--tmpfs DEST

Montez nouveau tmpfs sur DEST. Si l'option précédente était --perms, elle définit le mode du tmpfs. Sinon, le tmpfs a le mode 0755. Si l'option précédente était --size, elle définit la taille en octets du tmpfs. Sinon, le tmpfs a la taille par défaut.

--mqueue DEST

Montez nouveau mqueue sur DEST.

--dir DEST

Crée un répertoire sur DEST. Si le répertoire existe déjà, ses permissions ne sont pas modifiées, ignorant --perms (utilisez --chmod si les permissions d'un répertoire existant doivent être modifiées). Si le répertoire est nouvellement créé et que l'option précédente était --perms, elle définit le mode du répertoire. Sinon, les répertoires nouvellement créés ont le mode 0755.

--file FD DEST

Copie depuis le descripteur de fichier FD vers DEST. Si l'option précédente était --perms, elle définit le mode du nouveau fichier. Sinon, le fichier a le mode 0666 (notez que ce n'est pas pareil que --bind-data).

--bind-data FD DEST

Copie depuis le descripteur de fichier FD vers un fichier qui est bind-monté sur DEST. Si l'option précédente était --perms, elle définit le mode du nouveau fichier. Sinon, le fichier a le mode 0600 (notez que ce n'est pas pareil que --file).

--ro-bind-data FD DEST

Copie depuis le descripteur de fichier FD vers un fichier qui est bind-monté en lecture seule sur DEST. Si l'option précédente était --perms, elle définit le mode du nouveau fichier. Sinon, le fichier a le mode 0600 (notez que ce n'est pas pareil que --file).

--symlink SRC DEST

Crée un lien symbolique sur DEST avec la cible SRC.

Depuis la version 0.9.0, ce n'est pas considéré comme une erreur si DEST existe déjà comme un lien symbolique et que sa cible est exactement SRC.

Avant la version 0.9.0, si DEST existait déjà, cela était traité comme une erreur (même si sa cible était identique à SRC).

--chmod OCTAL PATH

Définit les permissions de PATH, qui doit déjà exister, à OCTAL.

Options de lockdown :

--seccomp FD

Charge et utilise les règles seccomp depuis FD. Les règles doivent être sous la forme d'un programme cBPF compilé, tel que généré par seccomp_export_bpf. Si cette option est donnée plus d'une fois, seule la dernière est utilisée. Utilisez --add-seccomp-fd si plusieurs programmes seccomp sont nécessaires.

--add-seccomp-fd FD

Charge et utilise les règles seccomp depuis FD. Les règles doivent être sous la forme d'un programme cBPF compilé, tel que généré par seccomp_export_bpf. Cette option peut être répétée, auquel cas tous les programmes seccomp seront chargés dans l'ordre donné (notez que le noyau les évaluera dans l'ordre inverse, donc le dernier programme de la ligne de commande bwrap est évalué en premier). Tous, sauf potentiellement le dernier, doivent autoriser l'utilisation du prctl PR_SET_SECCOMP. Cette option ne peut pas être combinée avec --seccomp.

--exec-label LABEL

Label d'exécution du sandbox. Sur un système SELinux, vous pouvez spécifier le contexte SELinux pour le(s) processus du sandbox.

--file-label LABEL

Label de fichier pour le contenu temporaire du sandbox. Sur un système SELinux, vous pouvez spécifier le contexte SELinux pour le contenu du sandbox.

--block-fd FD

Bloque le sandbox à la lecture de FD jusqu'à ce que des données soient disponibles.

--userns-block-fd FD

N'initialise pas l'espace utilisateur mais attend sur FD jusqu'à ce qu'il soit prêt. Cela permet à des processus externes (comme newuidmap/newgidmap) de configurer l'espace utilisateur avant qu'il ne soit utilisé par le processus du sandbox.

--info-fd FD

Écrit des informations au format JSON sur le sandbox dans FD.

--json-status-fd FD

Plusieurs documents JSON sont écrits dans FD, un par ligne (format **"lignes JSON"**[1]). Chaque ligne est un seul objet JSON. Après que bwrap ait démarré le processus enfant dans le sandbox, il écrit un objet avec un membre child-pid dans --json-status-fd (cela duplique l'ancien --info-fd). La valeur correspondante est l'ID du processus enfant dans l'espace de noms PID à partir duquel bwrap a été exécuté. Si disponibles, les identifiants d'espace de noms sont également inclus dans l'objet avec le child-pid ; cela duplique également l'ancien --info-fd. Lorsque le processus enfant à l'intérieur du sandbox se termine, bwrap écrit un objet avec un membre exit-code, puis ferme le --json-status-fd. La valeur correspondant à exit-code est le statut de sortie de l'enfant, dans l'encodage shell habituel (n s'il s'est terminé normalement avec le statut n, ou 128+n s'il a été tué par le signal n). D'autres membres peuvent être ajoutés à ces objets dans les futures versions de bwrap, et d'autres objets JSON peuvent être ajoutés avant ou après les objets actuels, donc les lecteurs doivent ignorer les membres et les objets qu'ils ne comprennent pas.

--new-session

Crée une nouvelle session de terminal pour le sandbox (appelle setsid()). Cela déconnecte le sandbox du terminal de contrôle, ce qui signifie que le sandbox ne peut pas, par exemple, injecter d'entrées dans le terminal.

Note : Dans un sandbox général, si vous n'utilisez pas --new-session, il est recommandé d'utiliser seccomp pour interdire l'ioctl TIOCSTI, sinon l'application peut injecter des entrées clavier dans le terminal, ce qui peut par exemple conduire à une exécution de commande hors sandbox (voir CVE-2017-5226).

--die-with-parent

Assure que le processus enfant (COMMAND) meurt lorsque le parent de bwrap meurt. Tue (SIGKILL) tous les processus du sandbox bwrap en séquence du parent à l'enfant, y compris le processus COMMAND, lorsque bwrap ou le parent de bwrap meurt. Voir prctl, PR_SET_PDEATHSIG.

--as-pid-1

Ne crée pas de processus avec PID=1 dans le sandbox pour récupérer les processus enfants.

--cap-add CAP

Ajoute la capacité spécifiée CAP, par exemple CAP_DAC_READ_SEARCH, lorsqu'il est exécuté en tant qu'utilisateur privilégié. Il accepte la valeur spéciale ALL pour ajouter toutes les capacités autorisées.

--cap-drop CAP

Supprime la capacité spécifiée lorsqu'il est exécuté en tant qu'utilisateur privilégié. Il accepte la valeur spéciale ALL pour supprimer toutes les capacités. Par défaut, aucune capacité n'est laissée dans le processus sandboxed. Les options --cap-add et --cap-drop sont traitées dans l'ordre où elles sont spécifiées sur la ligne de commande. Soyez attentif à l'ordre dans lequel elles sont spécifiées.

ENVIRONNEMENT

HOME

Utilisé comme répertoire de travail courant (cwd) dans le sandbox si --chdir n'a pas été explicitement spécifié et si le cwd actuel n'est pas présent à l'intérieur du sandbox. L'option --setenv peut être utilisée pour remplacer la valeur utilisée ici.
