NOM

basic_ldap_auth - Assistant d'authentification LDAP pour Squid

SYNOPSIS

basic_ldap_auth -b " DN de base " [-u attribut ] [ options ] [ nom du serveur LDAP [: port ]| URI ]...
basic_ldap_auth -b " DN de base " -f " filtre de recherche LDAP " [ options ] [ nom du serveur LDAP [: port ]| URI ]...

DESCRIPTION

basic_ldap_auth permet à Squid de se connecter à un annuaire LDAP pour valider le nom d'utilisateur et le mot de passe de l'authentification HTTP Basic. Les options LDAP sont spécifiées en tant que paramètres sur la ligne de commande, tandis que le(s) nom(s) d'utilisateur et le(s) mot(s) de passe à vérifier par rapport à l'annuaire LDAP sont spécifiés sur les lignes suivantes d'entrée pour l'assistant, un couple nom d'utilisateur/mot de passe par ligne séparé par un espace.

Comme attendu par le mécanisme d'authentification Basic de Squid, après avoir spécifié un nom d'utilisateur et un mot de passe suivis d'un retour à la ligne, cet assistant produira soit OK soit ERR sur la ligne suivante pour indiquer si les identifiants spécifiés sont corrects selon l'annuaire LDAP.

Le programme possède deux principaux modes de fonctionnement. Dans le mode de fonctionnement par défaut, le DN de l'utilisateur est construit à l'aide du DN de base et de l'attribut utilisateur. Dans l'autre mode de fonctionnement, un filtre de recherche est utilisé pour localiser les DN d'utilisateurs valides sous le DN de base.

OPTIONS

-b basedn
REQUIS. Spécifie le DN de base sous lequel les utilisateurs sont localisés.
-f filter
Filtre de recherche LDAP pour localiser le DN de l'utilisateur. Requis si les utilisateurs se trouvent dans une hiérarchie sous le DN de base, ou si le nom de connexion ne constitue pas la partie spécifique à l'utilisateur du DN de l'utilisateur.
Le filtre de recherche peut contenir jusqu'à 15 occurrences de %s qui seront remplacées par le nom d'utilisateur, comme dans "uid=%s" pour les annuaires RFC2037. Pour une description détaillée de la syntaxe des filtres de recherche LDAP, voir la RFC2254.
Le programme plantera si d'autres valeurs % que %s sont utilisées, ou si plus de 15 %s
sont utilisés.
-u userattr Spécifie le nom de l'attribut DN qui contient le nom d'utilisateur/connexion. Combiné avec le DN de base pour construire le DN de l'utilisateur lorsqu'aucun filtre de recherche n'est spécifié (option -f ). Par défaut à
uid Remarque : Cela ne peut être fait que si tous vos utilisateurs sont localisés directement sous le même emplacement dans l'arborescence LDAP et que le nom de connexion est utilisé pour nommer chaque objet utilisateur. Si votre arborescence LDAP ne correspond pas à ces critères, ou si vous souhaitez filtrer qui sont des utilisateurs valides, vous devez utiliser un filtre de recherche pour rechercher le DN de vos utilisateurs (option -f
).
-U passwordattr Utilise ldap_compare au lieu de ldap_simple_bind pour vérifier le mot de passe de l'utilisateur. passwordattr
est l'attribut LDAP stockant le mot de passe de l'utilisateur.
-s base|one|sub Portée de recherche lors de l'exécution des recherches de DN d'utilisateur spécifiées par l'option -f . Par défaut à
sub objet de base uniquement,
one un niveau sous l'objet de base ou
subl'arborescence sous l'objet de base
-D binddn -w password
Le DN et le mot de passe à utiliser pour la liaison lors des recherches. Requis par l'indicateur -f si l'annuaire n'autorise pas les recherches anonymes.
Comme le mot de passe doit être imprimé en clair dans votre configuration Squid, il est fortement recommandé d'utiliser un compte avec des privilèges minimaux associés. Cela afin de limiter les dégâts en cas où quelqu'un pourrait obtenir une copie de votre fichier de configuration Squid.
-D binddn -W secretfile
Le DN et le nom d'un fichier contenant le mot de passe à utiliser pour la liaison lors des recherches.
Version moins non sécurisée de la paire de paramètres précédente avec deux avantages : le mot de passe n'apparaît pas dans la liste des processus, et le mot de passe n'est pas compromis si quelqu'un obtient le fichier de configuration squid sans obtenir le fichier secret.
-P
Utilise une connexion LDAP persistante. Normalement, la connexion LDAP n'est ouverte que lors de la validation d'un nom d'utilisateur afin de préserver les ressources sur le serveur LDAP. Cette option permet de maintenir la connexion LDAP ouverte, permettant ainsi sa réutilisation pour d'autres validations d'utilisateurs. Recommandé pour les installations plus importantes.
-O
N'effectuer la liaison qu'une seule fois par connexion LDAP. Certains serveurs LDAP n'autorisent pas la re-liaison en tant qu'autre utilisateur après un ldap_bind réussi. L'utilisation de cette option ouvre toujours une nouvelle connexion pour chaque tentative de connexion. Si combinée avec l'option -P pour une connexion LDAP persistante, la connexion utilisée pour rechercher le DN de l'utilisateur reste persistante mais une nouvelle connexion est ouverte pour vérifier le mot de passe de chaque utilisateur une fois le DN trouvé.
-R
Ne pas suivre les renvois
-a never|always|search|find
quand désérialiser les alias. Par défaut à never
never ne jamais désérialiser les alias (par défaut), always désérialiser les alias, seulement lors d'une search ou seulement pour find l'objet de base.
-H ldap_uri
Spécifie le serveur LDAP auquel se connecter par URI LDAP (requiert les bibliothèques OpenLDAP). Les serveurs peuvent également être spécifiés en dernier sur la ligne de commande.
-h ldap_server
Spécifie le serveur LDAP auquel se connecter. Les serveurs peuvent également être spécifiés en dernier sur la ligne de commande.
-p ldap_port
Spécifie un port TCP alternatif sur lequel le serveur LDAP écoute s'il est différent du port LDAP par défaut 389. Peut également être spécifié dans la spécification du serveur en utilisant la syntaxe nomduserveur:port.
-v 2|3
Version du protocole LDAP. Par défaut à 3 si non spécifié.
-Z
Utiliser le chiffrement TLS
-S certpath
Activer LDAP sur SSL (requiert les bibliothèques de l'API LDAP Netscape)
-c connect_timeout
Spécifie le délai d'expiration utilisé lors de la connexion aux serveurs LDAP (requiert les bibliothèques de l'API LDAP Netscape)
-t search_timeout
Spécifie une limite de temps pour les opérations de recherche LDAP
-d
Mode de débogage où chaque étape effectuée sera rapportée en détail. Utile pour comprendre ce qui se passe mal si les résultats ne sont pas ceux qui sont attendus.

CONFIGURATION

Pour les annuaires utilisant la disposition RFC2307 avec un domaine unique, tout ce que vous devez spécifier est généralement le DN de base sous lequel vos utilisateurs sont localisés et le nom du serveur :

basic_ldap_auth -b ou=people,dc=your,dc=domain ldapserver

Si vous avez des sous-domaines, vous devez utiliser une approche par filtre de recherche pour localiser vos DN d'utilisateurs car ils ne peuvent plus être construits directement à partir du DN de base et du nom de connexion seul :

basic_ldap_auth -b dc=your,dc=domain -f uid=%s ldapserver

De même, si vous ne souhaitez autoriser l'accès qu'aux utilisateurs ayant un attribut spécifique

basic_ldap_auth -b dc=your,dc=domain -f (&(uid=%s)(specialattribute=value)) ldapserver

Ou si l'attribut utilisateur du DN de l'utilisateur est cn au lieu de uid et que vous ne voulez pas avoir à rechercher les utilisateurs, vous pourriez utiliser quelque chose comme l'exemple suivant pour Active Directory :

basic_ldap_auth -u cn -b cn=Users,dc=your,dc=domain ldapserver

Si vous souhaitez rechercher le DN de l'utilisateur et que votre annuaire n'autorise pas les recherches anonymes, vous devez également utiliser les indicateurs -D et -w pour spécifier un DN d'utilisateur et un mot de passe pour se connecter afin d'effectuer les recherches, comme dans le complexe exemple suivant pour Active Directory example

basic_ldap_auth -P -R -b dc=your,dc=domain -D cn=squid,cn=users,dc=your,dc=domain -w secretsquidpassword -f (&(userPrincipalName=%s)(objectClass=Person)) activedirectoryserver

NOTE: Lors de la construction de filtres de recherche, il est fortement recommandé de tester le filtre en utilisant ldapsearch avant d'essayer de l'utiliser avec basic_ldap_auth. Cela permet de vérifier que le filtre correspond à ce que vous attendez.
