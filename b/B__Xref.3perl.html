B::Xref(3perl) Guide du programmeur Perl B::Xref(3perl)

NOM

B::Xref - Génère des rapports de référence croisée pour les programmes Perl

SYNTAXE

perl -MO=Xref[,OPTIONS] foo.pl

DESCRIPTION

Le module B::Xref est utilisé pour générer une liste de référence croisée de toutes les définitions et utilisations de variables, sous-routines et formats dans un programme Perl. Il est implémenté en tant que backend pour le compilateur Perl.

Le rapport généré est au format suivant :

Fichier nom_fichier1
  Sous-routine nom_routine1
    Paquet paquet1
      objet1        numéros de ligne
      objet2        numéros de ligne
      ...
    Paquet paquet2
    ...

Chaque section Fichier fait rapport sur un seul fichier. Chaque section Sous-routine fait rapport sur une seule sous-routine, à l'exception des cas spéciaux « (definitions) » et « (main) ». Ceux-ci font rapport, respectivement, sur les définitions de sous-routines trouvées par la balayage initial de la table des symboles et sur la partie principale du programme ou du module externe à toutes les sous-routines.

Le rapport est ensuite regroupé par le Paquet de chaque variable, sous-routine ou format avec le cas spécial « (lexicals) » signifiant variables lexicales. Chaque nom d'objet (implicitement qualifié par son Paquet contenant) inclut ses caractères de type au début lorsque possible. Les variables lexicales sont plus faciles à suivre et incluent même des informations de déréférencement lorsque possible.

Les "numéros de ligne" sont une liste séparée par des virgules de numéros de ligne (certains précédés de lettres de code) où cet objet est utilisé d'une manière ou d'une autre. Les utilisations simples ne sont pas précédées d'une lettre de code. Les introductions (comme lorsqu'une lexicale est définie pour la première fois avec "my") sont indiquées par la lettre « i ». Les appels de sous-routines et de méthodes sont indiqués par le caractère « & ». Les définitions de sous-routines sont indiquées par « s » et les définitions de formats par « f ».

Par exemple, voici une partie du rapport du programme pod2man fourni avec Perl :

Sous-routine clear_noremap
  Paquet (lexical)
    $ready_to_print   i1069, 1079
  Paquet main
    $&                1086
    $.                1086
    $0                1086
    $1                1087
    $2                1085, 1085
    $3                1085, 1085
    $ARGV             1086
    %HTML_Escapes     1085, 1085

Ceci montre les variables utilisées dans la sous-routine "clear_noremap". La variable $ready_to_print est une variable my() (lexicale), introduite (déclarée pour la première fois avec my()) à la ligne 1069, et utilisée à la ligne 1079. La variable $& du paquet principal est utilisée à la ligne 1086, et ainsi de suite.

Un numéro de ligne peut être précédé d'une seule lettre :

i
Variable lexicale introduite (déclarée avec my()) pour la première fois.
&
Appel de sous-routine ou de méthode.
s
Sous-routine définie.
r
Format défini.

L'option la plus utile du générateur de références croisées est de sauvegarder le rapport dans un fichier séparé. Par exemple, pour sauvegarder le rapport sur myperlprogram dans le fichier report :

$ perl -MO=Xref,-oreport myperlprogram

OPTIONS

Les mots d'option sont séparés par des virgules (et non par des espaces) et suivent les conventions habituelles des options de backend du compilateur.

"-oNOMFICHIER"
Dirige la sortie vers "NOMFICHIER" au lieu de la sortie standard.
"-r"
Sortie brute. Au lieu de produire un rapport lisible par l'homme, génère une ligne sous forme lisible par machine pour chaque définition/utilisation d'une variable/sous-routine/format.
"-d"
Ne pas afficher les sections « (definitions) ».
"-D[tO]"
(Interne) options de débogage, probablement utiles uniquement si "-r" est inclus. L'option "t" affiche l'objet au sommet de la pile lorsqu'il est suivi. L'option "O" affiche chaque opérateur lorsqu'il est traité dans l'ordre d'exécution du programme.

BOGUES

Les variables non lexicales sont assez difficiles à suivre dans un programme. Parfois, le type d'utilisation d'une variable non lexicale est impossible à déterminer. Les introductions de non-lexicales non-scalaires ne semblent pas être rapportées correctement.
