DESCRIPTIO

N
bpftool btf { show | list } [id BTF_I
D]
Afficher des informations sur les objets BTF chargés. Si un ID BTF est spécifié, afficher uniquement les informations sur l'objet BTF donné, sinon lister tous les objets BTF actuellement chargés sur le système.

Depuis Linux 5.8, bpftool est capable de découvrir des informations sur les proc

essus qui détiennent des descripteurs de fichiers ouverts (FD) sur des objets BTF. Sur
de tels noyaux, bpftool émettra automatiquement cette information également.
bpftool btf dump BTF_SRC [format FORMAT] [root_id ROOT_I
D]
Vider les entrées BTF à partir d'un BTF_SRC donné.

Quand id est spécifié, l'objet BTF avec cet ID sera chargé et tous ses types BTF seront

émis.

Quand map est fourni, on s'attend à ce que la map ait un objet BTF associé avec des types BTF décrivant la clé et la valeur. Il est possible de sélectionner si on ne veut vider que le(s) type(s) BTF associé(s) à la clé (key), à la valeur (value), à la fois à la clé et à la valeur (kv), ou tous les types BTF présents dans l'objet BTF associé (all). Si non spécifié, kv est

supposé.

Quand prog est fourni, on s'attend à ce que le programme ait un objet BTF associé avec des types

BTF.

En spécifiant FILE, un fichier ELF est attendu, contenant une section .BTF avec des données au format binaire BTF bien défini, généralement produites par clang ou

pahole.

L'option format peut être utilisée pour remplacer le format de sortie par défaut (raw). Les formats de sortie brut (raw) ou en syntaxe C (c) sont supportés. Avec le formatage de style C, la sortie est triée par défaut. Utilisez l'option unsorted pour éviter de trier la

sortie.

L'option root_id peut être utilisée pour filtrer un dump à un seul type et tous ses types dépendants. Elle ne peut pas être utilisée avec d'autres types de

filtrage (comme les arguments "key", "value", ou "kv" lors du dump du BTF po
ur une map). Elle peut être passée plusieurs fois pour dumper plusieurs types.

OPTION

S
-h, --hel
p
Afficher un court message d'aide (similaire à bpftool help)
.
-V, --versi
on
Afficher le numéro de version de bpftool (similaire à bpftool version), le numéro de la version de libbpf utilisée, et les fonctionnalités optionnelles qui ont été incluses lorsque bpftool a été compilé. Les fonctionnalités optionnelles incluent le lien avec LLVM ou libbfd pour fournir le désassembleur pour les programmes JIT (bpftool prog dump jited) et l'utilisation des squelettes BPF (certaines fonctionnalités comme bpftool prog profile ou l'affichage des pids associés aux objets BPF peuvent en dépendre)
.
-j, --jso
n
Générer une sortie JSON. Pour les commandes qui ne peuvent pas produire de JSON, cette option n'a aucun
effet.
-p, --pret
ty
Générer une sortie JSON lisible par l'humain. Implique -j
.
-d, --debu
g
Afficher tous les journaux disponibles, y compris les
informations de niveau debug. Cela inclut les journa
ux de libbpf ainsi que ceux du vérificateur, lo
rs de la tentative de chargement de programmes.
-B, --base-btf FI
LE
Passer un objet BTF de base. Les objets BTF de base sont typiquement utilisés avec les objets BTF pour les modules du noyau. Pour éviter de dupliquer tous les symboles du noyau requis par les modules, les objets BTF pour les modules sont "divisés", ils sont construits de manière incrémentale au-dessus de l'objet BTF du noyau (vmlinux). Ainsi la référence BTF de base devrait généralement pointer vers le BTF du noyau.

Quand l'objet BTF principal à traiter (par exemple, le BTF du module à dumper) est passé en tant que FILE, bpftool tente de détecter automatiquement le chemin p

our l'objet de base, et passer cet
te option est facultatif. Quand
l'objet BTF principal est p
assé via d'autres handles, cette
option devient nécessaire.
