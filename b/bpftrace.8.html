NAME

bpftrace - High-level tracing language for Linux

SYNOPSIS

bpftrace [-e 'program'] [-f format] [-d] [-p] [-I path] [-L] [-v] [-h] [filename]

DESCRIPTION

bpftrace is a powerful tracing tool for Linux that uses the kernel's extended Berkeley Packet Filter (eBPF) infrastructure. It leverages an expressive, high-level tracing language that simplifies the creation of eBPF programs. bpftrace allows users to write short, simple tracing scripts in a language similar to awk and C, and have them compiled and executed as eBPF bytecode within the kernel.

bpftrace offers a flexible and efficient way to perform system and application tracing, offering insights into performance bottlenecks, debugging issues, and understanding system behavior without modifying existing code or kernel modules.

EXAMPLES

Trace all function calls to a specific kernel function:

# bpftrace -e 'kprobe:__x64_sys_clone { printf("Clone called by %s\n", comm); }'

Trace all user-level function calls to malloc:

# bpftrace -e 'uprobe:/usr/include/stdlib.h:malloc { printf("malloc called by %s\n", comm); }'

Trace process execution tracing (PET) on execve:

# bpftrace -e 'tracepoint:syscalls:sys_enter_execve { printf("execve by %s\n", comm); }'

Count calls to a specific function:

# bpftrace -e 'kprobe:my_kernel_func { @[comm] = count(); }'

OPTIONS

-e 'program'
Execute the given bpftrace program string.
-f format
Specify output format. Supported formats: text (default), json.
-d
Dump BPF bytecode.
-p
Print map values.
-I path
Add path to include search path for BPF Type Format (BTF) information.
-L
List available probes.
-v
Verbose output.
-h
Print help message.

THE LANGUAGE

The bpftrace language is a high-level tracing language inspired by awk and C. It allows users to define probes and associated actions. A bpftrace program consists of one or more probe definitions.

A probe definition has the following structure:

probe_type:probe_name {
  actions
}

probe_type can be one of:

kprobe
Kernel function entry point.
kretprobe
Kernel function return.
uprobe
User-level function entry point.
uretprobe
User-level function return.
tracepoint
Kernel tracepoint.
profile
Periodic sampling.
interval
Periodic execution.
syscall
System call entry point.
sysret
System call return.
BEGIN
Action executed once at the beginning.
END
Action executed once at the end.

probe_name specifies the function, tracepoint, or other event to probe.

actions is a block of code that is executed when the probe fires. It can include built-in functions, variable assignments, and map operations.

PROBES

bpftrace supports various types of probes, including:

kprobes
Kernel probes, used to instrument kernel functions.
uprobes
User-level probes, used to instrument user-space functions.
tracepoints
Kernel tracepoints, which are statically defined instrumentation points within the kernel.
USDT (User Statically-Defined Tracing)
Statically defined tracing points within user-space applications.
profile
Periodic sampling of CPU activity.
interval
Periodic execution of actions.
syscall
Tracing system calls.

CONFIGURATION

bpftrace relies on kernel features like eBPF, kprobes, uprobes, and tracepoints. For full functionality, ensure your kernel is compiled with the necessary options enabled (e.g., CONFIG_BPF, CONFIG_KPROBES, CONFIG_UPROBES, CONFIG_TRACEPOINTS).

BPF Type Format (BTF) information can significantly enhance bpftrace's capabilities, especially for type information. Ensure your kernel has BTF enabled and that BPF debug information is available for the targets you are tracing.

OPTIONS EXPANDED

This section expands on some of the options mentioned in the SYNOPSIS.

-e 'program'
Allows you to directly provide a bpftrace script as a command-line argument. The program string should be enclosed in single quotes to prevent shell interpretation.
-f format
Controls the output format. 'text' provides human-readable output, while 'json' outputs structured data suitable for programmatic processing.
-d
Useful for debugging bpftrace scripts. When used, it dumps the generated eBPF bytecode, which can be inspected using tools like bp تحليل (if available) or other BPF analysis tools.
-p
Prints the current values of all maps. This is typically used at the end of a tracing session to display aggregated results.
-I path
Specifies directories to search for BTF (BPF Type Format) information. BTF provides type and debug information for BPF programs and maps, allowing bpftrace to understand complex data structures. This is crucial for tracing programs that interact with kernel data structures.
-L
Lists all available probes on the system. This is invaluable for discovering what can be traced. It shows probe types (kprobe, uprobe, tracepoint, etc.) and their names.
-v
Verbose mode. Increases the level of detail in the output, which can be helpful for understanding the execution flow and debugging issues.
-h
Displays a help message summarizing all available options and their usage.
filename
If no -e option is provided, bpftrace reads the program from the specified file. It's conventional to use the .bt extension for bpftrace script files.

TERMINOLOGY

BPF Berkeley Packet Filter: a virtual machine technology originally developed for optimizing the processing of packet filters (eg, tcpdump expressions).
BPF map A BPF memory object, which is used by bpftrace to create many higher-level objects.
BTF BPF Type Format: the metadata format which encodes the debug info related to BPF program/map.
dynamic tracing Also known as dynamic instrumentation, this is a technology that can instrument any software event, such as function calls and returns, by live modification of instruction text. Target software usually does not need special capabilities to support dynamic tracing, other than a symbol table that bpftrace can read. Since this instruments all software text, it is not considered a stable API, and the target functions may not be documented outside of their source code.
eBPF Enhanced BPF: a kernel technology that extends BPF so that it can execute more generic programs on any events, such as the bpftrace programs listed below. It makes use of the BPF sandboxed virtual machine environment. Also note that eBPF is often just referred to as BPF.
kprobes A Linux kernel technology for providing dynamic tracing of kernel functions.
probe An instrumentation point in software or hardware, that generates events that can execute bpftrace programs.
static tracing Hard-coded instrumentation points in code. Since these are fixed, they may be provided as part of a stable API, and documented.
tracepoints A Linux kernel technology for providing static tracing.
uprobes A Linux kernel technology for providing dynamic tracing of user-level functions.
USDT User Statically-Defined Tracing: static tracing points for user-level software. Some applications support USDT.

PROGRAM FILES

Programs saved as files are often called scripts and can be executed by specifying their file name. It is convention to use the .bt file extension but it is not required.

For example, listing the sleepers.bt file using cat:

# cat sleepers.bt
tracepoint:syscalls:sys_enter_nanosleep {
  printf("%s is sleeping.\n", comm);
}

And then calling it:

# bpftrace sleepers.bt
Attached 1 probe
iscsid is sleeping.
iscsid is sleeping.

It can also be made executable to run stand-alone. Start by adding an interpreter line at the top (#!) with either the path to your installed bpftrace (/usr/local/bin is the default) or the path to env (usually just /usr/bin/env) followed by bpftrace (so it will find bpftrace in your $PATH):

#!/usr/local/bin/bpftrace
tracepoint:syscalls:sys_enter_nanosleep {
  printf("%s is sleeping.\n", comm);
}

Then make it executable:

# chmod 755 sleepers.bt
# ./sleepers.bt
Attached 1 probe
iscsid is sleeping.
iscsid is sleeping.
