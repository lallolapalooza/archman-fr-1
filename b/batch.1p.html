DESCRIPTIO

N

L'utilitaire batch lit des commandes depuis l'entrée standard et les planifie pour exécution dans une file d'attente batch. Il est l'équivalent de la commande

: 
at -q
b -
m now

où la file b est une file at spéciale, destinée spécifiquement aux travaux batch. Les travaux batch sont soumis à la file batch sans contrainte de temps et sont exécutés par le système à l'aide d'algorithmes, basés sur des facteurs non spécifiés, qui peuvent varier à chaque invocation de batch

.

Les utilisateurs sont autorisés à utiliser batch si leur nom apparaît dans le fichier at.allow, qui est situé dans un répertoire défini par l'implémentation. Si ce fichier n'existe pas, le fichier at.deny, situé dans un répertoire défini par l'implémentation, est vérifié pour déterminer si l'utilisateur doit se voir refuser l'accès à batch. Si aucun des deux fichiers n'existe, seul un processus disposant des privilèges appropriés est autorisé à soumettre un travail. Si seul at.deny existe et est vide, l'utilisation globale est autorisée. Les fichiers at.allow et at.deny doivent contenir un

nom d'utilisat
eur par ligne.

JUSTIFICATIO

N

Les premières propositions décrivaient batch d'une manière totalement séparée de at, même si le modèle historique le traitait presque comme un synonyme pour at -qb. Un certain nombre de fonctionnalités ont été ajoutées pour lister et contrôler le travail batch séparément de celles de at. Après réflexion, il a été décidé que le bénéfice de cela ne justifiait pas le changement de l'interface

historique.

L'option -m a été incluse dans la commande at équivalente car il est pratique historique d'envoyer les résultats par courrier au soumetteur, même si toute la sortie produite par le travail est redirigée. Comme expliqué dans la RATIONALE pour at, le mot-clé now soumet le travail pour une exécution immédiate (après les délais de planification), contrairement à certains systèmes historiques où at now aurait été consid

éré comme u
ne erreur.
