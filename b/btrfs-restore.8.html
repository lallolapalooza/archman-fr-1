NOM

btrfs-restore - tente de restaurer des fichiers à partir d'une image de système de fichiers endommagée

SYNTAXE

btrfs restore [options] <périphérique> <chemin> | -l <périphérique>

DESCRIPTION

btrfs restore est utilisé pour tenter de récupérer des fichiers à partir d'un système de fichiers endommagé et les restaurer dans chemin ou simplement lister les racines des sous-volumes. L'image du système de fichiers n'est pas modifiée.

Si le système de fichiers est endommagé et ne peut pas être réparé par les autres outils (btrfs-check(8) <> ou btrfs-rescue(8) <>), btrfs restore peut être utilisé pour récupérer les données des fichiers, dans la mesure où les métadonnées sont lisibles. Les vérifications effectuées par restore sont moins strictes et le processus est généralement capable d'aller assez loin pour récupérer les données de l'ensemble du système de fichiers. Cela a pour conséquence que certaines données peuvent être incomplètes ou provenir de versions antérieures si elles sont disponibles.

Il existe plusieurs options pour tenter de restaurer divers types de métadonnées de fichiers. Vous pouvez d'abord essayer une simulation à sec pour voir comment le processus se déroule et utiliser d'autres options pour étendre l'ensemble des métadonnées restaurées.

Pour les images dont les structures d'arbre sont endommagées, il existe plusieurs options pour indiquer au processus une copie de secours.

OPTIONS

-s|--snapshots
récupérer également les snapshots qui sont ignorés par défaut
-x|--xattr
récupérer les attributs étendus
-m|--metadata
restaurer le propriétaire, les permissions et les horodatages pour les fichiers et répertoires
-S|--symlinks
restaurer les liens symboliques ainsi que les fichiers normaux
-i|--ignore-errors
ignorer les erreurs pendant la restauration et continuer
-o|--overwrite
écraser les répertoires/fichiers dans chemin, par exemple pour des exécutions répétées
-t <no_octet>
utiliser no_octet pour lire l'arbre racine
-f <no_octet>
restaurer uniquement les fichiers situés sous la racine du sous-volume spécifiée par no_octet
-u|--super <miroir>
utiliser le miroir du superbloc donné identifié par <miroir>, il peut être 0, 1 ou 2
-r|--root <id_racine>
restaurer uniquement les fichiers situés sous un sous-volume spécifié dont l'identifiant d'objet est id_racine
-d
trouver le répertoire
-l|--list-roots
lister les racines des sous-volumes, peut être utilisé comme argument pour -r
-D|--dry-run
simulation à sec (lister uniquement les fichiers qui seraient récupérés)
--path-regex <regex>
restaurer uniquement les noms de fichiers correspondant à une expression régulière (regex(7) https://man7.org/linux/man-pages/man7/regex.7.html) avec un format obligatoire

^/(|home(|/username(|/Desktop(|/.*))))$

Le format n'est pas très pratique et restaure tous les fichiers des répertoires dans tout le chemin, donc ce n'est pas utile pour restaurer un fichier unique dans une hiérarchie profonde.

-c
ignorer la casse (uniquement pour --path-regex)
-v|--verbose
(déprécié) alias pour l'option globale -v

Options globales

-v|--verbose
soyez verbeux et affichez ce qui est en cours de restauration

STATUT DE SORTIE

btrfs restore renvoie un statut de sortie zéro en cas de succès. Un code non nul est renvoyé en cas d'échec.

DISPONIBILITÉ

btrfs fait partie de btrfs-progs. Veuillez vous référer à la documentation sur https://btrfs.readthedocs.io.

VOIR AUSSI
