EQUÊTE

Retire de la musique de votre

bibliothèque.

Cette commanded utilise la même syntaxe de query que la commande list. Par défaut, il supprime simplement les entrées de la base de données de la bibliothèque ; il ne touche pas aux fichiers sur disque. Pour supprimer réellement les fichiers, utilisez l'indicateur -d. Lorsque l'indicateur -a est donné, la commande opère sur les albums au lieu des pistes individuelles.

Lorsque vous exécutez la commande remove, elle imprime une liste de tous les éléments affectés dans la bibliothèque et demande votre permission avant de les supprimer. Vous pouvez alors choisir d'interrompre (tapez n), de confirmer (y) ou de choisir interactivement certains éléments (s). Dans ce dernier cas, la commande vous demandera pour chaque élément ou album correspondant et vous invitera à taper y pour supprimer l'élément/album, n pour le conserver ou q pour quitter et ne supprimer que les éléments/albums sélectionnés jusqu'à ce point. Cette option vous permet de choisir précisément quelles pistes/albums supprimer sans passer trop de temps à créer soigneusement une requête. Si vous ne voulez pas être invité du tout, utilisez l'option -f.

modify

beet modify [-IMWay] [-f FORMAT] QUERY [FIELD=VALUE...] [FIELD!...]

Change les métadonnées des éléments ou des albums dans la base de données.

Fournissez une query correspondant aux éléments que vous souhaitez modifier et une série de paires field=value. Par exemple, beet modify genius of love artist="Tom Tom Club" modifiera l'artiste de la piste "Genius of Love". Pour supprimer des champs (ce qui n'est possible que pour les attributs flexibles), faites suivre un nom de champ d'un point d'exclamation : field!.

Les valeurs peuvent également être des templates, en utilisant la même syntaxe que les path formats. Par exemple, beet modify artist='$artist_sort' copiera le nom de tri de l'artiste dans le champ artiste pour toutes vos pistes, et beet modify title='$track $title' ajoutera les numéros de piste à leurs métadonnées de titre.

L'option -a passe à l'interrogation des champs d'album au lieu des champs de piste et permet également d'opérer sur les albums en plus des pistes individuelles. Sans cet indicateur, la commande ne modifiera que les données au niveau de la piste, même si toutes les pistes appartiennent au même album. Si vous souhaitez modifier un champ au niveau de l'album, tel que year ou albumartist, vous voudrez utiliser l'indicateur -a pour éviter une situation confuse où les données des pistes individuelles entrent en conflit avec les données de l'album entier.

Les modifications effectuées à l'aide de -a se propagent par défaut aux pistes individuelles. Pour empêcher ce comportement, utilisez -I/--noinherit.

Les éléments seront automatiquement déplacés si nécessaire s'ils se trouvent dans le répertoire de votre bibliothèque, mais vous pouvez désactiver cela avec -M. Les tags seront écrits dans les fichiers selon les paramètres que vous avez pour les importations, mais ceux-ci peuvent être remplacés par -w (écrire les tags, par défaut) et -W (ne pas écrire les tags).

Lorsque vous exécutez la commande modify, elle imprime une liste de tous les éléments affectés dans la bibliothèque et demande votre permission avant d'apporter des modifications. Vous pouvez alors choisir d'interrompre la modification (tapez n), de confirmer (y), ou de choisir interactivement certains éléments (s). Dans ce dernier cas, la commande vous demandera pour chaque élément ou album correspondant et vous invitera à taper y pour appliquer les modifications, n pour les rejeter ou q pour quitter et appliquer les modifications sélectionnées. Cette option vous permet de choisir précisément quelles données modifier sans passer trop de temps à créer soigneusement une requête. Pour sauter les invites entièrement, utilisez l'option -y.

move

beet move [-capt] [-d DIR] QUERY

Déplace ou copie des éléments dans votre bibliothèque.

Cette commande, par défaut, agit comme un consolidateur de bibliothèque : les éléments correspondant à la requête sont renommés dans la structure de répertoires de votre bibliothèque. En spécifiant manuellement un répertoire de destination avec -d, vous pouvez déplacer les éléments correspondant à une requête n'importe où sur votre système de fichiers. L'option -c copie les fichiers au lieu de les déplacer. Comme avec les autres commandes, l'option -a correspond aux albums au lieu des éléments. L'indicateur -e (pour "export") copie les fichiers sans modifier la base de données.

Pour effectuer un "dry run" (simulation), utilisez simplement l'indicateur -p (pour "pretend"). Cela vous montrera une liste des fichiers qui seraient déplacés mais ne changera rien sur le disque. L'option -t active le mode timide qui demandera à nouveau avant de déplacer ou copier réellement les fichiers.

update

beet update [-F] FIELD [-e] EXCLUDE_FIELD [-aM] QUERY

Met à jour la bibliothèque (et, par défaut, déplace les fichiers) pour refléter les changements de métadonnées hors bande et les suppressions de fichiers.

Cela analysera tous les fichiers correspondants et lira leurs tags, remplissant la base de données avec les nouvelles valeurs. Par défaut, les fichiers seront renommés conformément à leurs nouvelles métadonnées ; désactivez cela avec -M. Beets ignorera les fichiers si leurs temps de modification n'ont pas changé, donc tout changement de métadonnées hors bande doit également les mettre à jour pour que beet update reconnaisse que les fichiers ont été modifiés.

Pour effectuer une "dry run" (simulation) d'une mise à jour, utilisez simplement l'indicateur -p (pour "pretend"). Cela vous montrera tous les changements proposés mais ne modifiera rien sur le disque.

Par défaut, toutes les métadonnées modifiées seront renvoyées dans la base de données. Si vous ne souhaitez que certains champs soient écrits, spécifiez-les avec les indicateurs `-F` (qui peuvent être utilisés plusieurs fois). Alternativement, spécifiez les champs à ne pas écrire avec les indicateurs `-e` (qui peuvent être utilisés plusieurs fois). Pour la liste des champs pris en charge, veuillez consulter `beet fields`.

Lorsqu'une piste mise à jour fait partie d'un album, les champs de niveau album de toutes les pistes de l'album sont également mis à jour. (Plus précisément, la commande copie les données de niveau album de la première piste de l'album et les applique aux autres pistes.) Cela signifie que, si les champs de niveau album ne sont pas identiques au sein d'un album, certains changements affichés par la commande update peuvent être remplacés par des données d'autres pistes du même album. Cela signifie que l'exécution de la commande update plusieurs fois peut montrer les mêmes changements appliqués.

write

beet write [-pf] [QUERY]

Écrit les métadonnées de la base de données dans les tags des fichiers.

Lorsque vous apportez des modifications aux métadonnées stockées dans la base de données de la bibliothèque de beets (lors de l'importation ou avec la commande modify, par exemple), vous avez souvent la possibilité de stocker les modifications uniquement dans la base de données, en laissant vos fichiers intacts. La commande write vous permet plus tard de changer d'avis et d'écrire le contenu de la base de données dans les fichiers. Par défaut, cela écrit les modifications uniquement s'il y a une différence entre la base de données et les tags dans le fichier.

Vous pouvez considérer cette commande comme l'inverse de update.

L'option -p prévisualise les modifications de métadonnées sans les appliquer réellement.

L'option -f force l'écriture dans le fichier, même si les tags du fichier correspondent à la base de données. Ceci est utile pour s'assurer que les plugins activés qui s'exécutent à l'écriture (par exemple, les plugins Scrub et Zero) sont exécutés sur le fichier.

stats

beet stats [-e] [QUERY]

Affiche des statistiques sur votre bibliothèque entière (si vous ne fournissez pas de query) ou sur les éléments correspondants (si vous en fournissez une).

Par défaut, la commande calcule la taille des fichiers en utilisant leur débit binaire et leur durée. L'option -e (--exact) lit les tailles exactes de chaque fichier (mais est plus lente). Le mode exact affiche également la durée exacte en secondes.

fields

beet fields

Affiche les champs de métadonnées d'éléments et d'albums disponibles pour utilisation dans les Queries et les Path Formats. La liste comprend tous les champs de template fournis par les plugins et tous les attributs flexibles que vous avez attribués manuellement à vos éléments et albums.

config

beet config [-pdc]
beet config -e

Affiche ou modifie la configuration utilisateur. Cette commande fait l'une des trois choses suivantes :

  • Sans aucune option, imprime une représentation YAML de la configuration utilisateur actuelle. Avec l'option --default, les options par défaut de beets sont également incluses dans le dump.
  • L'option --path affiche plutôt le chemin vers votre fichier de configuration. Cela peut être combiné avec l'indicateur --default pour montrer où beets conserve ses valeurs par défaut internes.
  • Par défaut, les informations sensibles comme les mots de passe sont supprimées lors de l'affichage de la configuration. L'option --clear inclut ces données sensibles.
  • Avec l'option --edit, beets tente d'ouvrir votre fichier de configuration pour édition. Il essaie d'abord la variable d'environnement $EDITOR, suivie de $EDITOR puis d'une option de repli en fonction de votre plateforme : open sur OS X, xdg-open sur Unix, et invocation directe sous Windows.

FLAGS GLOBAUX

Beets dispose de quelques indicateurs "globaux" qui affectent toutes les commandes. Ceux-ci doivent apparaître entre le nom de l'exécutable (beet) et la commande --- par exemple, beet -v import ....

  • -l LIBPATH : spécifie le fichier de base de données de la bibliothèque à utiliser.
  • -d DIRECTORY : spécifie le répertoire racine de la bibliothèque.
  • -v : mode verbeux ; imprime une débauche d'informations de débogage. Veuillez utiliser cet indicateur lors du signalement de bugs. Vous pouvez l'utiliser deux fois, comme dans -vv, pour rendre beets encore plus verbeux.
  • -c FILE : lit un fichier de configuration YAML spécifié. Cette configuration fonctionne comme une superposition : plutôt que de remplacer entièrement vos options de configuration normales, les deux sont fusionnées. Toutes les options individuelles définies dans ce fichier de configuration outrepasseront les paramètres correspondants de votre configuration de base.
  • -p plugins : spécifie une liste de plugins séparés par des virgules à activer. Si spécifié, la liste des plugins dans votre configuration est ignorée. La forme longue de cet argument permet également de spécifier aucun plugin, désactivant ainsi tous les plugins : --plugins=.
  • -P plugins : spécifie
ficier une liste de plugins séparés par des virgules à désactiver lors d'une exécution spécifique de beets. Cela écrasera -p s'il est utilisé avec celui-ci. Pour désactiver tous les plugins, utilisez --plugins= à la place.

Beets utilise également la variable d'environnement BEETSDIR pour rechercher la configuration et les données.

COMPLÉTION DE SHELL

eval "$(beet completion)"

Ou, pour éviter de ralentir le démarrage de votre shell, vous pouvez rediriger la sortie de beet completion vers un fichier et le charger à la place.

Le script de complétion suggère les noms des sous-commandes et (après avoir tapé -) les options de la commande donnée. Si vous utilisez une commande qui accepte une requête, le script complétera également les noms de champs.

beet list ar[TAB]
# artist:  artist_credit:  artist_sort:  artpath:
beet list artp[TAB]
beet list artpath\:

(Ne vous inquiétez pas du slash devant les deux-points : c'est une séquence d'échappement pour le shell et ne sera pas vue par beets.)

La complétion des commandes de plugins ne fonctionne que pour les plugins qui étaient activés lors de l'exécution de beet completion. Si vous ajoutez un plugin plus tard, vous devrez régénérer le script.

zsh

Une autre approche consiste à utiliser la compatibilité de complétion bash de zsh. Ce fragment de code définit quelques fonctions spécifiques à bash pour que cela fonctionne sans erreurs :

autoload bashcompinit
bashcompinit
_get_comp_words_by_ref() { :; }
compopt() { :; }
_filedir() { :; }
eval "$(beet completion)"
