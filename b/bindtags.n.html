bindtags(n) Commandes intégrées Tk bindtags(n)

NOM

bindtags - Déterminer quelles liaisons s'appliquent à une fenêtre et leur ordre d'évaluation

SYNTAXE

bindtags fenêtre ?listeDeTags?

DESCRIPTION

Lorsqu'une liaison est créée avec la commande bind, elle est associée soit à une fenêtre particulière comme .a.b.c, un nom de classe comme Button, le mot-clé all, ou toute autre chaîne. Toutes ces formes sont appelées tags de liaison. Chaque fenêtre contient une liste de tags de liaison qui déterminent comment les événements sont traités pour la fenêtre. Lorsqu'un événement se produit dans une fenêtre, il est appliqué à chacun des tags de la fenêtre dans l'ordre : pour chaque tag, la liaison la plus spécifique qui correspond au tag et à l'événement donnés est exécutée. Voir la commande bind pour plus d'informations sur le processus de correspondance.

Par défaut, chaque fenêtre possède quatre tags de liaison constitués du nom de la fenêtre, du nom de classe de la fenêtre, du nom de l'ancêtre de niveau supérieur le plus proche de la fenêtre, et de all, dans cet ordre. Les fenêtres de niveau supérieur n'ont que trois tags par défaut, car le nom de niveau supérieur est identique à celui de la fenêtre. La commande bindtags permet de lire et de modifier les tags de liaison d'une fenêtre.

Si bindtags est appelée avec un seul argument, l'ensemble actuel des tags de liaison pour fenêtre est renvoyé sous forme de liste. Si l'argument listeDeTags est spécifié à bindtags, il doit s'agir d'une liste valide ; les tags pour fenêtre sont changés pour les éléments de la liste. Les éléments de listeDeTags peuvent être des chaînes arbitraires ; cependant, tout tag commençant par un point est traité comme le nom d'une fenêtre ; si aucune fenêtre de ce nom n'existe au moment où un événement est traité, alors le tag est ignoré pour cet événement. L'ordre des éléments dans listeDeTags détermine l'ordre dans lequel les scripts de liaison sont exécutés en réponse aux événements. Par exemple, la commande

bindtags .b {all . Button .b}
inverse l'ordre dans lequel les scripts de liaison seront évalués pour un bouton nommé .b, de sorte que les liaisons all soient invoquées en premier, suivies des liaisons pour le niveau supérieur de .b (“.”), suivies des liaisons de classe, suivies des liaisons pour .b. Si listeDeTags est une liste vide, alors les tags de liaison pour fenêtre reviennent à l'état par défaut décrit ci-dessus.

La commande bindtags peut être utilisée pour introduire des tags de liaison supplémentaires arbitraires pour une fenêtre, ou pour supprimer des tags standard. Par exemple, la commande

bindtags .b {.b TrickyButton . all}
remplace le tag Button pour .b par TrickyButton. Cela signifie que les liaisons de widgets par défaut, qui sont associées au tag Button, ne s'appliqueront plus à .b, mais toute liaison associée à TrickyButton (peut-être un nouveau comportement de bouton) s'appliquera.

EXEMPLE

Si vous avez un ensemble de widgets frame imbriqués et que vous souhaitez que les événements envoyés à un widget button soient également livrés à tous les widgets jusqu'au toplevel actuel (contrairement au comportement par défaut de Tk, où les événements ne sont pas livrés à ces fenêtres intermédiaires) pour faciliter la mise en place d'accélérateurs qui ne sont actifs que pour une partie d'une fenêtre, vous pourriez utiliser une procédure d'aide comme celle-ci pour aider à la configuration :

proc setupBindtagsForTreeDelivery {widget} {
    set tags [list $widget [winfo class $widget]]
    set w $widget
    set t [winfo toplevel $w]
    while {$w ne $t} {
        set w [winfo parent $w]
        lappend tags $w
    }
    lappend tags all
    bindtags $widget $tags
}
