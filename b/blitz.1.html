BLITZ(1) Manuel des commandes générales BLITZ(1)

NOM

blitz — Transférez des fichiers de manière sécurisée entre deux postes de travail via NAT/Pare-feu.

SYNTAXE

blitz [-lT] [-s secret] [-k fichier-clé] [-f liste] [-o RSOPT=] [fichiers ...]

DESCRIPTION

L'utilitaire blitz est un script enveloppant pour gs-netcat et rsync. Il permet d'envoyer des fichiers d'un poste de travail à un autre via le réseau de relais global de sockets (GSRN).

Un cas d'utilisation typique est lorsque les deux postes de travail sont séparés par un pare-feu ou un NAT et ne peuvent pas établir de connexion directe entre eux.

OPTIONS

-l
Mode serveur. Le mode par défaut est client.
-s secret
Un mot de passe choisi par l'utilisateur. Les deux utilisateurs doivent utiliser le même mot de passe pour se connecter.
-k FICHIER
Un fichier contenant le mot de passe.
-f FICHIER
Lire la liste des noms de fichiers depuis FICHIER. Si FICHIER est -, la liste sera lue depuis l'entrée standard.
-o RSOPT=
Options passées à rsync. Voir rsync(1) pour les options disponibles.
-T
Utiliser TOR. L'outil blitz se connectera via TOR au GSRN. Cela nécessite que TOR soit installé et en cours d'exécution. L'IP et le PORT du serveur TOR peuvent être définis en utilisant des variables d'environnement.

Voir gs-netcat(1) pour plus d'options.

EXEMPLES

Écouter les clients avec le mot de passe 'MonSecret':

$ mkdir /tmp/foo && cd /tmp/foo
$ blitz -s MonSecret -l

Copier 'fichier.dat' vers /tmp/foo/fichier.dat sur le serveur:

$ blitz -s MonSecret fichier.dat

Copier '/etc/ssh/ssh*config' vers /tmp/foo/etc/ssh/ sur le serveur:

$ blitz -s MonSecret /etc/ssh/ssh*config

Il est également possible de limiter la quantité d'informations de chemin qui sont envoyées comme répertoires implicites pour chaque chemin que vous spécifiez. Vous pouvez insérer un point et une barre oblique dans le chemin source, comme ceci:

$ blitz -s MonSecret /etc/./ssh/ssh*config
Les fichiers reçus seront stockés dans /tmp/foo/ssh/ au lieu de /tmp/foo/etc/ssh.

Copier récursivement et limiter la bande passante à 10 Ko/sec:

$ blitz -s MonSecret -o 'RSOPT=--bwlimit=10' /usr/./share

Copier tout le système de fichiers racine:

$ blitz -s MonSecret -o 'RSOPT=-x' /

Copier des fichiers spécifiques lus depuis l'entrée standard:

$ find . -name '*.conf' | blitz -s MonSecret -f -

Exécuter un serveur permanent (démon) via TOR:

$ blitz -s MonSecret -l -D -T

ENVIRONNEMENT

Voir gs-netcat(1) pour une liste des variables d'environnement prises en charge.

VOIR AUSSI

gsocket(1), gs-netcat(1), gs-sftp(1), gs-mount(1), rsync(1)

BOGUES

Des efforts ont été faits pour que blitz "fasse ce qu'il faut" dans tous ses différents modes. Si vous pensez qu'il fait la mauvaise chose dans certaines circonstances, veuillez m'en informer (skyper@thc.org) et me dire comment vous pensez qu'il devrait se comporter.
