NOM

borgfs - Monter une archive ou un dépôt entier en tant que système de fichiers FUSE

SYNTAXE

borgfs [options] DÉPÔT_OU_ARCHIVE POINT_DE_MONTAGE [CHEMIN...]

DESCRIPTION

Cette commande monte un dépôt ou une archive en tant que système de fichiers FUSE. Ceci peut être utile pour parcourir ou restaurer des fichiers individuels.

Lors de la restauration, prenez en compte que l'implémentation FUSE actuelle ne prend pas en charge les drapeaux spéciaux de système de fichiers et les ACL.

Lors du montage d'un dépôt, les répertoires de niveau supérieur seront nommés comme les archives et la structure de répertoires en dessous sera chargée à la demande depuis le dépôt lors de l'entrée dans ces répertoires, attendez-vous donc à un certain délai.

Sauf si l'option --foreground est donnée, la commande s'exécutera en arrière-plan jusqu'à ce que le système de fichiers soit démonté.

Conseils de performance :

  • lors d'un montage de "dépôt entier" : n'entrez pas dans les répertoires d'archives si ce n'est pas nécessaire ; cela évite le chargement à la demande.
  • ne montez qu'une archive spécifique, pas le dépôt entier.
  • ne montez que des chemins spécifiques dans une archive spécifique, pas l'archive complète.

La commande borgfs fournit un wrapper pour borg mount. Celle-ci peut également être utilisée dans les entrées fstab : /chemin/vers/depot /point/de/montage fuse.borgfs defaut,sansauto 0 0

Pour permettre à un utilisateur ordinaire d'utiliser les entrées fstab, ajoutez l'option user : /chemin/vers/depot /point/de/montage fuse.borgfs defaut,sansauto,user 0 0

Pour la configuration FUSE et les options de montage, consultez la page de manuel de mount.fuse(8).

Le comportement par défaut de Borg est d'utiliser les noms d'utilisateur et de groupe archivés de chaque fichier et de les mapper aux identifiants d'utilisateur et de groupe respectifs du système. Alternativement, l'utilisation de numeric-ids utilisera plutôt les identifiants d'utilisateur et de groupe archivés sans aucun mappage.

Les options de montage uid et gid (implémentées par Borg) peuvent être utilisées pour remplacer les identifiants d'utilisateur et de groupe de tous les fichiers (c'est-à-dire, borg mount -o uid=1000,gid=1000).

La page de manuel fait référence aux options de montage user_id et group_id (implémentées par FUSE) qui spécifient l'identifiant d'utilisateur et de groupe du propriétaire du montage (alias, l'utilisateur qui effectue le montage). Elle est définie automatiquement par libfuse (ou le système de fichiers si libfuse n'est pas utilisé). Cependant, vous ne devez pas les spécifier manuellement. Contrairement aux options de montage uid et gid qui affectent tous les fichiers, user_id et group_id affectent l'identifiant d'utilisateur et de groupe du répertoire (de base) monté.

Options de montage supplémentaires prises en charge par borg :

  • versions : lorsqu'elle est utilisée avec un montage de dépôt, cela donne une vue fusionnée et versionnée des fichiers dans les archives. EXPÉRIMENTAL ; la disposition peut changer à l'avenir.
  • allow_damaged_files : par défaut, les fichiers endommagés (où les chunks manquants ont été remplacés par des séries de zéros par borg check --repair) ne sont pas lisibles et retournent EIO (Erreur d'entrée/sortie). Définissez cette option pour lire de tels fichiers.
  • ignore_permissions : pour des raisons de sécurité, l'option de montage default_permissions est appliquée en interne par borg. ignore_permissions peut être fournie pour ne pas appliquer default_permissions.

La variable d'environnement BORG_MOUNT_DATA_CACHE_ENTRIES est destinée aux utilisateurs avancés pour ajuster les performances. Elle définit le nombre de chunks de données mis en cache ; l'utilisation de mémoire supplémentaire peut atteindre environ 8 MiB par ce nombre. La valeur par défaut est le nombre de cœurs CPU.

Lorsque le processus daemonisé reçoit un signal ou plante, il ne démonte pas. Le démontage dans ces cas pourrait entraîner la suppression involontaire de données par un processus rsync actif ou similaire.

Lors de l'exécution au premier plan, ^C/SIGINT démonte proprement le système de fichiers, mais d'autres signaux ou plantages ne le font pas.

Débogage :

borg mount daemonise généralement et le processus daemon envoie stdout/stderr à /dev/null. Ainsi, vous devez soit utiliser -f / --foreground pour le maintenir au premier plan et ne pas daemoniser, soit utiliser BORG_LOGGING_CONF pour reconfigurer le logger afin qu'il écrive dans un fichier.

OPTIONS

Voir borg-common(1) pour les options communes des commandes Borg.

arguments

DÉPÔT_OU_ARCHIVE
dépôt ou archive à monter
POINT_DE_MONTAGE
où monter le système de fichiers
CHEMIN
chemins à extraire ; les motifs sont pris en charge

options

-V, --version
afficher le numéro de version et quitter
--consider-checkpoints
Afficher les archives de points de contrôle dans la liste du contenu du dépôt (par défaut : masqué).
-f, --foreground
rester au premier plan, ne pas daemoniser
-o
Options de montage supplémentaires
--numeric-owner
obsolète, utiliser --numeric-ids à la place
--numeric-ids
utiliser les identifiants numériques d'utilisateur et de groupe de l'archive (ou des archives)

Filtres d'archives

-P PRÉFIXE, --prefix PRÉFIXE
ne considérer que les noms d'archive commençant par ce préfixe. (obsolète)
-a GLOB, --glob-archives GLOB
ne considérer que les noms d'archive correspondant au glob. Les règles sh s'appliquent (sans utiliser réellement le préfixe sh:), voir "borg help patterns".
--sort-by CLÉS
Liste séparée par des virgules de clés de tri ; les clés valides sont : timestamp, archive, name, id ; la valeur par défaut est : timestamp
--first N
considérer les N premières archives après l'application d'autres filtres
--last N
considérer les N dernières archives après l'application d'autres filtres

Options Inclure/Exclure

-e MOTIF, --exclude MOTIF
exclure les chemins correspondant au MOTIF
--exclude-from FICHIEREXCLUSION
lire les motifs d'exclusion depuis FICHIEREXCLUSION, un par ligne
--pattern MOTIF
inclure/exclure les chemins correspondant au MOTIF
--patterns-from FICHIERMOTIF
lire les motifs d'inclusion/exclusion depuis FICHIERMOTIF, un par ligne
--strip-components NOMBRE
Supprimez le nombre spécifié d'éléments de chemin initiaux. Les chemins avec moins d'éléments seront silencieusement ignorés.
