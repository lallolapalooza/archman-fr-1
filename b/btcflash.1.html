dev= fait référence au scsibus/cible/ lun de l'enregistreur CD/DVD/BluRay. La communication sur SunOS se fait avec le pilote général SCSI scg. Les autres systèmes d'exploitation utilisent une simulation logicielle de ce pilote. La syntaxe possible est : dev=scsibus, cible, lun ou

dev= cible,
lun. Dans ce dernier cas, l'enregistreur CD/DVD/BluRay doit être connecté au bus SCSI par défaut de la machine. Scsibus, cible etlun sont des nombres entiers. Certainssystèmes d'exploitation ou implémentations de transport SCSI peuvent nécessiter de spécifier un nom de fichier en plus. Dans ce cas, la syntaxe correcte pour le périphérique est : dev= nombrepériphérique:scsibus,cible, lun ou dev= nombrepériphérique:cible, lun. Si le nom du nœud de périphérique spécifié sur un tel système fait référence à exactement un périphérique SCSI, un raccourci de la forme dev= nombrepériphérique: @ ou dev=nombrepériphérique:@,lun peut être utilisé à la place de dev= nombrepériphérique:scsibus,cible, lun. Transports SCSI alternatifs Les lecteurs ATAPI sont simplementdes lecteurs SCSI qui utilisent intrinsèquement l'interface de paquets ATA commecouche de transport de commandes SCSI intégrée dans le transport IDE (ATA). Le délai d'attente par défaut des commandes SCSI est le délai d'attente minimum utilisé pour l'envoi des commandes SCSI. Si une commande SCSI échoue en raison d'un délai d'attente dépassé, vous pouvez essayer d'augmenter le délai d'attente par défaut des commandes SCSI au-dessus de la valeur du délai d'attente de la commande qui a échoué. Si la variable d'environnement RSH est présente, la connexion distante ne sera pas créée via rcmd(3) mais en appelant le programme auquel pointe RSH. Utilisez par exemple RSH=/usr/bin/ssh pour créer une connexion shell sécurisée.

Notez que cela force cdrecord à créer un pipe vers le programme rsh(1) et empêche cdrecord d'accéder directement au socket réseau vers le serveur distant. Cela rend impossible la configuration des paramètres de performance et ralentit la connexion par rapport à une connexion rcmd(3) initiée

par r
oot.

S

Un message d'erreur typique pour une commande SCSI ressemble à

: 
btcflash: I/O error. test unit ready: scsi sendcmd: no error
CDB:  00 20 00 00 00 00
status: 0x2 (CHECK CONDITION)
Sense Bytes: 70 00 05 00 00 00 00 0A 00 00 00 00 25 00 00 00 00 00
Sense Key: 0x5 Illegal Request, Segment 0
Sense Code: 0x25 Qual 0x00 (logical unit not supported) Fru 0x0
Sense flags: Blk 0 (not valid)
cmd finished after 0.002s timeout 40s

La
première
ligne donne des informations sur le transport de la commande. Le texte après le premier deux-points donne le texte d'erreur pour l'appel système du point de vue du noyau. C'est généralement : I/O error sauf si d'autres problèmes surviennent. Les mots suivants contiennent une brève description de la commande SCSI qui échoue. Le reste de la ligne indique s'il y a eu des problèmes pour le transport de la commande sur le bus SCSI. fatal error signifie qu'il n'a pas été possible de transporter la commande (c'est-à-dire aucun appareil présent à l'adresse SCSI demandée).

La deuxième ligne affiche le bloc des descripteurs de commande SCSI pour la commande

échouée.

La troisième ligne donne des informations sur le code de statut SCSI renvoyé par la commande, si le transport de la commande réussit. Il s'agit d'informations d'erreur provenant de l'appareil

SCSI.

La quatrième ligne est un dump hexadécimal des informations de sens auto-demandées pour la

commande.

La cinquième ligne est le texte d'erreur pour la clé de sens si disponible, suivi du numéro de segment qui n'est valide que si la commande était une commande de copie. Si le message d'erreur n'est pas directement lié à la commande actuelle, le texte deferred error est

ajouté.

La sixième ligne est le texte d'erreur pour le code de sens et le qualificateur de sens si disponibles. Si le type d'appareil est connu, les données de sens sont décodées à partir des tableaux dans scsierrs.c . Le texte est suivi de la valeur d'erreur pour une unité remplaçable sur le

terrain.

La septième ligne affiche le numéro de bloc lié à la commande échouée et le texte pour plusieurs indicateurs d'erreur. Le numéro de bloc peut ne pas être

valide.

La huitième ligne indique le délai d'attente c

onfiguré pour cette commande et le temps que l
a commande a réellement pris pour se terminer.
