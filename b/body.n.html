NOM

itcl::body - modifier le corps d'une méthode/procédure de classe

SYNOPSIS

itcl::body nomClasse::fonction arguments corps

DESCRIPTION

La commande body est utilisée en dehors d'une définition de classe [incr Tcl] pour définir ou redéfinir le corps d'une méthode ou d'une procédure de classe. Cette fonctionnalité permet à une définition de classe d'avoir des parties distinctes d'"interface" et d'"implémentation". La partie "interface" est une commande class avec les déclarations pour les méthodes, les procédures, les variables d'instance et les variables communes. La partie "implémentation" est une série de commandes body et configbody. Si la partie "implémentation" est conservée dans un fichier séparé, elle peut être sourcée encore et encore au fur et à mesure que les bugs sont corrigés, pour supporter le développement interactif. Lorsque le mode "tcl" est utilisé dans l'éditeur emacs, les parties "interface" et "implémentation" peuvent être conservées dans le même fichier ; au fur et à mesure que les bugs sont corrigés, les corps individuels peuvent être mis en surbrillance et envoyés à l'application de test.

Le nom "nomClasse::fonction" identifie la méthode/procédure en cours de modification.

Si une liste d> arguments a été spécifiée lorsque la fonction a été définie dans la définition de classe, la liste des arguments pour la commande body doit correspondre en sens. Les noms de variables peuvent changer, mais les listes d'arguments doivent avoir les mêmes arguments requis et les mêmes valeurs par défaut pour les arguments optionnels. L'argument spécial args agit comme un caractère générique lorsqu'il est inclus dans la liste des arguments dans la définition de classe ; il correspondra à zéro ou plusieurs arguments de tout type lors de la redéfinition du corps.

Si la chaîne corps commence par "@", elle est traitée comme le nom symbolique d'une procédure C. La liste des arguments a peu de signification pour la procédure C, sauf pour documenter l'utilisation attendue. (La procédure C n'est pas garantie d'utiliser les arguments de cette manière.) Si corps ne commence pas par "@", elle est traitée comme un script de commande Tcl. Lorsque la fonction est invoquée, les arguments de la ligne de commande sont mis en correspondance avec la liste des arguments, et des variables locales sont créées pour représenter chaque argument. C'est le comportement habituel pour une procédure de style Tcl.

Les noms symboliques pour les procédures C sont établis en enregistrant les procédures via Itcl_RegisterC(). Ceci est généralement fait dans la procédure Tcl_AppInit(), qui est automatiquement appelée au démarrage de l'interpréteur. Dans l'exemple suivant, la procédure My_FooCmd() est enregistrée avec le nom symbolique "foo". Cette procédure peut être référencée dans la commande body comme "@foo".

int
Tcl_AppInit(interp)
    Tcl_Interp *interp;     /* Interpréteur pour l'application. */
{
    if (Itcl_Init(interp) == TCL_ERROR) {
        return TCL_ERROR;
    }
    if (Itcl_RegisterC(interp, "foo", My_FooCmd) != TCL_OK) {
        return TCL_ERROR;
    }
}

EXEMPLE

Dans l'exemple suivant, une classe "File" est définie pour représenter des fichiers ouverts. Les corps des méthodes sont inclus ci-dessous la définition de classe via la commande body. Notez que les corps du constructeur/destructeur doivent être inclus dans la définition de classe, mais ils peuvent également être redéfinis via la commande body.

itcl::class File {
    private variable fid ""
    constructor {name access} {
        set fid [open $name $access]
    }
    destructor {
        close $fid
    }
    method get {}
    method put {line}
    method eof {}
}
itcl::body File::get {} {
    return [gets $fid]
}
itcl::body File::put {line} {
    puts $fid $line
}
itcl::body File::eof {} {
    return [::eof $fid]
}
#
# Voir la classe File en action :
#
File x /etc/passwd "r"
while {![x eof]} {
    puts "=> [x get]"
}
itcl::delete object x
