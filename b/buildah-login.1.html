NOM

buildah-login - Se connecter à un registre de conteneurs

SYNOPSIS

buildah login [options] registry

DESCRIPTION

buildah login se connecte à un serveur de registre spécifié avec le nom d'utilisateur et le mot de passe corrects. buildah login lit le nom d'utilisateur et le mot de passe depuis STDIN. Le nom d'utilisateur et le mot de passe peuvent également être définis à l'aide des options username et password. Le chemin du fichier d'authentification peut être spécifié par l'utilisateur en définissant l'option authfile. Le chemin par défaut utilisé est ${XDG_RUNTIME_DIR}/containers/auth.json. Si XDG_RUNTIME_DIR n'est pas défini, le chemin par défaut est /run/user/$UID/containers/auth.json.

buildah [OPTIONS GLOBALES]

buildah login [OPTIONS GLOBALES]

buildah login [OPTIONS] REGISTRY [OPTIONS GLOBALES]

OPTIONS

--authfile

Chemin du fichier d'authentification. Par défaut : ${XDG_RUNTIME_DIR}/containers/auth.json. Voir containers-auth.json(5) pour plus d'informations. Ce fichier est créé en utilisant buildah login.

Remarque : Vous pouvez également remplacer le chemin par défaut du fichier d'authentification en définissant la variable d'environnement REGISTRY_AUTH_FILE. export REGISTRY_AUTH_FILE=chemin

--cert-dir chemin

Utilise les certificats dans chemin (*.crt, *.cert, *.key) pour se connecter au registre. Le répertoire de certificats par défaut est /etc/containers/certs.d.

--compat-auth-file=chemin

Au lieu de mettre à jour le fichier d'identifiants par défaut, mettez à jour celui situé dans chemin et utilisez un format compatible avec Docker.

--get-login

Retourne l'utilisateur connecté pour le registre. Retourne une erreur si aucune connexion n'est trouvée.

--help, -h

Affiche le message d'utilisation

--password, -p

Mot de passe pour le registre

--password-stdin

Prend le mot de passe depuis stdin

--tls-verify

Exige HTTPS et la vérification des certificats lors de la communication avec les registres de conteneurs (par défaut : true). S'il est explicitement défini à true, la vérification TLS sera utilisée. S'il est défini à false, la vérification TLS ne sera pas utilisée. Si non spécifié, la vérification TLS sera utilisée à moins que le registre cible ne soit listé comme un registre non sécurisé dans registries.conf. La vérification TLS ne peut pas être utilisée lors de la communication avec un registre non sécurisé.

--username, -u

Nom d'utilisateur pour le registre

--verbose, -v

Affiche des informations détaillées sur le magasin d'identifiants

EXEMPLES

$ buildah login quay.io
Username: qiwanredhat
Password:
Login Succeeded!
$ buildah login -u testuser -p testpassword localhost:5000
Login Succeeded!
$ buildah login --authfile ./auth.json quay.io
Username: qiwanredhat
Password:
Login Succeeded!
$ buildah login --tls-verify=false -u test -p test localhost:5000
Login Succeeded!
$ buildah login --cert-dir /etc/containers/certs.d/ -u foo -p bar localhost:5000
Login Succeeded!
$ buildah login -u testuser  --password-stdin < pw.txt quay.io
Login Succeeded!
$ echo $testpassword | buildah login -u testuser --password-stdin quay.io
Login Succeeded!
