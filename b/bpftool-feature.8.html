BPFTOOL-FEATURE(8) Manuel de l'administrateur système BPFTOOL-FEATURE(8)

NOM

bpftool-feature - outil d'inspection des paramètres liés à eBPF pour le noyau Linux ou les périphériques réseau

SYNTAXE

bpftool [OPTIONS] feature COMMANDE

OPTIONS := { { -j | --json } [{ -p | --pretty }] | { -d | --debug } }

COMMANDES := { probe | help }

COMMANDES FEATURE

bpftool feature probe [COMPOSANT] [full] [unprivileged] [macros [prefix PREFIXE]]
bpftool feature list_builtins GROUPE
bpftool feature help
COMPOSANT := { kernel | dev NOM }
GROUPE := { prog_types | map_types | attach_types | link_types | helpers }

DESCRIPTION

bpftool feature probe [kernel] [full] [macros [prefix PREFIXE]]
Sonde le noyau en cours d'exécution et affiche un certain nombre de paramètres liés à eBPF, tels que la disponibilité de l'appel système bpf(), l'état JIT, la disponibilité des types de programmes eBPF, la disponibilité des fonctions d'aide eBPF, et plus encore.

Par défaut, bpftool ne lance pas de sondes pour les fonctions auxiliaires bpf_probe_write_user() et bpf_trace_printk() qui affichent des avertissements dans les journaux du noyau. Pour les activer et lancer toutes les sondes, le mot-clé full doit être utilisé.

Si le mot-clé macros (mais pas l'option -j) est passé, un sous-ensemble de la sortie est affiché sous forme d'une liste de macros #define prêtes à être incluses dans un fichier d'en-tête C, par exemple. Si, en outre, prefix est utilisé pour définir un PREFIXE, la chaîne fournie sera utilisée comme préfixe pour les noms des macros : cela peut être utilisé pour éviter les conflits de noms de macros lors de l'inclusion de la sortie de cette commande en tant que fichier d'en-tête.

Le mot-clé kernel peut être omis. Si aucune cible de sonde n'est spécifiée, la sonde du noyau est le comportement par défaut.

Lorsque le mot-clé unprivileged est utilisé, bpftool n'affichera que les fonctionnalités disponibles pour un utilisateur qui ne possède pas la capacité CAP_SYS_ADMIN définie. Les fonctionnalités disponibles dans ce cas représentent généralement un petit sous-ensemble des paramètres pris en charge par le système. Les utilisateurs sans privilèges DOIVENT utiliser le mot-clé unprivileged : ceci afin d'éviter une mauvaise détection si bpftool est involontairement exécuté en tant que non-root, par exemple. Ce mot-clé n'est pas disponible si bpftool a été compilé sans libcap.

bpftool feature probe dev NOM [full] [macros [prefix PREFIXE]]
Sonde le périphérique réseau pour les fonctionnalités eBPF prises en charge et affiche les résultats sur la console.

Les mots-clés full, macros et prefix ont le même rôle que lors de la sonde du noyau.

bpftool feature list_builtins GROUPE
Liste les éléments connus de bpftool. Il peut s'agir de types de programmes BPF (prog_types), de types de cartes BPF (map_types), de types d'attachement (attach_types), de types de liens (link_types), ou de fonctions d'aide BPF (helpers). La commande ne sonde pas le système, mais liste simplement les éléments que bpftool connaît à partir du moment de la compilation, tels que fournis par libbpf (pour tous les types d'objets) ou à partir de l'en-tête UAPI BPF (liste des fonctions d'aide). Cela peut être utilisé dans les scripts pour itérer sur les types ou les fonctions d'aide BPF.
bpftool feature help
Affiche un bref message d'aide.

OPTIONS

-h, --help
Affiche un bref message d'aide (similaire à bpftool help).
-V, --version
Affiche le numéro de version de bpftool (similaire à bpftool version), le numéro de la version de libbpf utilisée, et les fonctionnalités optionnelles qui ont été incluses lors de la compilation de bpftool. Les fonctionnalités optionnelles incluent la liaison avec LLVM ou libbfd pour fournir le désassembleur pour les programmes JITtés (bpftool prog dump jited) et l'utilisation de squelettes BPF (certaines fonctionnalités comme bpftool prog profile ou l'affichage des PID associés aux objets BPF peuvent en dépendre).
-j, --json
Génère une sortie JSON. Pour les commandes qui ne peuvent pas produire de JSON, cette option n'a aucun effet.
-p, --pretty
Génère une sortie JSON lisible par l'homme. Implique -j.
-d, --debug
Affiche toutes les journaux disponibles, y compris les informations de niveau débogage. Cela inclut les journaux de libbpf ainsi que ceux du vérificateur, lorsqu'il tente de charger des programmes.
