NOM

Bear - un outil pour générer une base de données de compilation pour les outils Clang.

SYNTAXE

bear [options] -- [commande de compilation]

DESCRIPTION

La base de données de compilation JSON http://clang.llvm.org/docs/JSONCompilationDatabase.html est utilisée dans le projet Clang pour fournir des informations sur la manière dont une unité de compilation unique a été traitée. Lorsqu'elle est disponible, il est facile de relancer la compilation avec différents programmes.

Bear exécute la commande de compilation d'origine et intercepte les appels de commandes émis par l'outil de compilation. À partir du journal des exécutions de commandes, il tente d'identifier les appels du compilateur et crée la base de données de compilation finale.

OPTIONS

--version
Affiche le numéro de version.
--help
Affiche le message d'aide.
--verbose
Active la journalisation détaillée.
--output fichier
Spécifie le fichier de sortie. (Nom de fichier par défaut fourni.) La sortie est une base de données de compilation JSON.
--append
Utilise le fichier de sortie généré précédemment et y ajoute les nouvelles entrées. Vous pouvez ainsi exécuter Bear en continu pendant le travail, et il maintient la base de données de compilation à jour. La suppression et l'ajout de fichiers sont tous deux pris en compte. Cependant, un changement dans le processus de compilation (changement des indicateurs du compilateur) peut entraîner des doublons.
--config fichier
Spécifie un fichier de configuration. Le fichier de configuration indique comment le format de la sortie doit être et quelles entrées elle doit contenir.
--force-preload
Force l'utilisation de la méthode du lieur dynamique pour intercepter les commandes.
--force-wrapper
Force l'utilisation de la méthode de l'enveloppe du compilateur pour intercepter les commandes.

COMMANDES

bear-intercept(1)
Intercepte les événements qui se sont produits pendant l'exécution de la commande de compilation.
bear-citnames(1)
Déduit la sémantique des commandes capturées par bear-intercept(1).

SORTIE

La définition de la base de données de compilation JSON a évolué au fil du temps. La version actuelle de Bear génère des entrées où :

directory
est un chemin absolu.
file
est un chemin absolu.
output
est un chemin absolu.
arguments
est utilisé à la place de la commande pour éviter les problèmes d'échappement du shell. (La configuration peut forcer l'émission du champ commande.) Le compilateur comme premier argument a un chemin absolu. Certains indicateurs non liés à la compilation sont filtrés de la sortie finale.

FICHIER DE CONFIGURATION

Lisez la page de manuel de bear-citnames(1) pour connaître le contenu de ce fichier. bear ne lit pas le contenu de ce fichier, mais passe le nom du fichier à la commande bear citnames.

STATUT DE SORTIE

Le statut de sortie du programme est le statut de sortie de la commande de compilation. Sauf si le programme lui-même plante, auquel cas il est défini à non nul.

DÉPANNAGE

Les problèmes potentiels que vous pourriez rencontrer sont : la compilation avec et sans Bear se comporte différemment, ou la sortie est vide.

La cause la plus fréquente de sorties vides est que la commande de compilation n'a exécuté aucune commande. La raison pourrait être que les compilations incrémentielles n'exécutent pas les compilateurs si tout est à jour. N'oubliez pas que Bear ne comprend pas le fichier de construction (par exemple : makefile), mais intercepte les commandes exécutées.

L'autre cause fréquente de sortie vide est que la compilation a une étape de « configure », qui capture le compilateur pour construire le projet. Dans le cas où Bear utilise le mode « wrapper » (voir la page de manuel bear-intercept(1)), il doit également exécuter l'étape de configuration avec Bear (et ignorer cette sortie) avant de lancer la compilation avec Bear.

Il peut y avoir de nombreuses raisons à ces échecs. Il est préférable de consulter la page wiki du projet pour connaître les problèmes connus avant d'ouvrir un rapport de bug.
