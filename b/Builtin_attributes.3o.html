type current_phase =
| Parser
|

Invariant_check

register_attr doit être appelé sur les emplacements de tous les attributs qui doivent être suivis afin d'émettre les avertissements d'attribut mal placé. En particulier, il doit être appelé sur tous les attributs présents dans le programme source, à l'exception de ceux qui sont contenus dans le chargeur d'une autre attribut (car ceux-ci peuvent être laissés par un ppx et intentionnellement ignorés par le compilateur)

.

L'argument current_phase indique quand cette fonction est

appelée

-soit lorsqu'un attribut est créé dans l'analyseur syntaxique, soit lorsque nous voyons un attribut pendant l'exécution du contrôle dans le module Ast_invariants. Cela sert à garantir que nous ne suivons que les attributs de la version finale de l'arbre d'analyse : nous n'ajoutons pas les attributs vus au moment de l'analyse si nous pouvons voir qu'un ppx sera exécuté plus tard, car le contrôle Ast_invariants est toujours exécuté sur le résultat d'un

ppx.

Notez que le contrôle Ast_invariants est également exécuté sur les arbres d'analyse créés à partir de fichiers ast marshalisés si aucun ppx n'est utilisé, ce qui garantit que nous ne manquons pas d'attributs dans ce

cas.

Aides pour l'avertissement 53 des attributs

d'environnement

Certains attributs, comme les marqueurs de dépréciation, n'affectent pas la compilation de la définition sur laquelle ils apparaissent, mais entraînent plutôt des avertissements lors des utilisations futures de cette définition. Cela est implémenté en déplaçant les attributs bruts dans l'environnement, où ils seront remarqués lors des accès

futurs.

Pour que les avertissements d'attribut mal placé fonctionnent correctement pour ces attributs, nous les marquons comme « utilisés » lorsqu'ils sont déplacés dans l'environnement. Cela est fait avec les fonctions utilitaires de cette

section.

val mark_alert_used : Parsetree.attribute ->

unit

Marque l'attribut comme utilisé aux fins des avertissements d'attribut mal placé s'il s'agit d'une alerte. Appelez cette fonction lors du déplacement dans l'environnement des éléments autorisés à avoir des attributs

d'alerte.

val mark_alerts_used : Parsetree.attributes ->

unit

Identique à List.iter mark_ale

rt_used .

val mark_warn_on_literal_pattern_used : Parsetree.attributes ->

unit

Marque les attributs « warn_on_literal_pattern » comme utilisés aux fins des avertissements d'attribut mal placé. Appelez cette fonction lors du déplacement des constructeurs dans l'environnement

.

val mark_deprecated_mutable_used : Parsetree.attributes ->

unit

Marque les attributs « deprecated_mutable » comme utilisés aux fins des avertissements d'attribut mal placé. Appelez cette fonction lors du déplacement des étiquettes de champs mutables dans

l'environnement
.

val warning_attribute : ?ppwarning:bool -> Parsetree.attribute ->

unit

Applique les paramètres d'avertissement provenant de l'attribut spécifié. « ocaml.warning »/« ocaml.warnerror » (et les variantes sans le préfixe) sont traités et marqués comme utilisés pour l'avertissement 53. Les autres attributs sont

ignorés.

Implémente également ocaml.ppwarning (sauf si ~ppwarning:false est passé)

.

val warning_scope : ?ppwarning:bool -> Parsetree.attributes -> (unit -> 'a) ->

'a

Exécute une fonction dans une nouvelle portée pour les paramètres d'avertissement. Cela signifie que l'effet de tout appel à warning_attribute pendant l'exécution de cette fonction sera annulé après

l'exécution.

La fonction prend également une liste d'attributs qui sont traités avec warning_attribute dans la nouvelle portée

avant que la fonction
ne soit exécutée.

val has_attribute : string -> Parsetree.attributes ->

bool

has_attribute name attrs vaut true si un attribut dont le nom est name ou "ocaml." ^ name est présent dans attrs . Il marque cet attribut comme utilisé aux fins des avertissements d'attribut mal

placé.

type attr_action =
| Mark_used_only
|

Return

select_attributes actions attrs trouve les éléments de attrs qui apparaissent dans actions et les retourne ou se contente de les marquer comme utilisés, selon l' attr_action corre

spondant.

Chaque élément (nm, action) de la liste actions est un attribut accompagné d'une attr_action spécifiant quoi faire de cet attribut. L'action sert à prendre en charge différentes configurations du compilateur. Si un attribut n'est utilisé que dans certaines configurations du compilateur, il est important que nous cherchions quand même et le marquions comme utilisé lors de la compilation avec d'autres configurations. Sinon, nous émettrions des avertissements d'attribut mal placé

erronés.

val select_attributes : (string * attr_action) list -> Parsetree.attributes -> Parsetree.

attributes

val attr_equals_builtin : Parsetree.attribute -> string ->

bool

attr_equals_builtin attr s vaut true si le nom de l'attribut est s ou "ocaml." ^ s . Cela est utile pour inspecter manuellement les noms d'attributs, mais notez que le faire ne permet pas de marquer l'attribut comme utilisé aux fins de l'avertissement 53, il est donc généralement préférablerable à utiliser has_attribute ou select_attributes

.
