de la

plateforme.

À l'aide des BIO de connexion, des connexions TCP/IP peuvent être établies et des données transférées en utilisant

uniquement

les routines BIO. De cette manière, les opérations spécifiques à la plateforme sont masquées par l'abstraction BIO. Les opérations de lecture et d'écriture sur un BIO de connexion

effectueront

des E/S sur la connexion sous-jacente. Si aucune connexion n'est établie et que le port et le nom d'hôte (voir ci-dessous) sont configurés correctement, une connexion est d'abord établie. Les BIO de connexion prennent en charge

BIO_puts()

et BIO_gets(). Si l'indicateur de fermeture

est

défini sur un BIO de connexion, toute connexion active est arrêtée et le socket est fermé lorsque le BIO est libéré. Appeler

BIO_reset()

sur un BIO de connexion fermera toute connexion active et réinitialisera le BIO dans un état où il peut se reconnecter au même hôte. BIO_new_connect()

combine

BIO_new() et BIO_set_conn_hostname() en un seul appel : il crée un nouveau BIO de connexion avec le nom d'hôte name. BIO_set_conn_hostname() utilise la cha

îne

name pour définir le nom d'hôte. Le nom d'hôte peut être une adresse IP ; si l'adresse est une adresse IPv6, elle doit être entourée de crochets "[" et "]". Le nom d'hôte peut également inclure le port sous la forme nomhôte:port ; voir BIO_parse_hostserv(3) et BIO_set_conn_port() pour plus de détails. BIO_set_conn_port() définit

le

port sur port. port peut être la forme numérique ou une chaîne de service telle que "http", qui sera mappée à un numéro de port à l'aide de la fonction système getservbyname(). BIO_set_conn_address() définit

les

informations d'adresse et de port à l'aide d'un BIO_ADDR(3ssl). BIO_set_conn_ip_family() défin

it

la famille IP. BIO_get_conn_hostname()

renvoie

le nom d'hôte du BIO de connexion ou NULL si le BIO est initialisé mais qu'aucun nom d'hôte n'est défini. Cette valeur de retour est un pointeur interne qui ne doit pas être modifié. BIO_get_conn_port(

)

renvoie le port sous forme de chaîne. Cette valeur de retour est un pointeur interne qui ne doit pas être modifié. BIO_get_conn_address(

)

renvoie les informations d'adresse sous forme de BIO_ADDR. Cette valeur de retour est un pointeur interne qui ne doit pas être modifié. BIO_get_conn_ip_family(

)

renvoie la famille IP du BIO de connexion. BIO_set_nbio()

définit

l'indicateur d'E/S non bloquantes à n. Si n est zéro, les E/S bloquantes sont définies. Si n est 1, les E/S non bloquantes sont définies. Les E/S bloquantes sont la valeur par défaut. L'appel à BIO_set_nbio() doit être effectué avant l'établissement de la connexion car les E/S non bloquantes sont définies pendant le

processus

de connexion. BIO_do_connect() tente de connecter le BIO fourni. Cela effectue une poignée de main SSL/TLS dans la mesure où elle est prise en charge par le BIO. Pour les BIO non SSL, la connexion se fait généralement au niveau TCP. Si la résolution de nom de domaine renvoie plusieurs adresses IP, toutes sont essayées après les échecs de connect(). La fonction renvoie 1 si la connexion a été établie avec succès. Une valeur nulle ou négative est renvoyée si la connexion n'a pas pu être établie. L'appel BIO_should_retry() doit être utilisé pour les BIO de connexion non bloquants afin de déterminer si l'appel doit être réessayé. Si une connexion a déjà été établie, cet

appel

n'a aucun effet. BIO_set_sock_type() peut être utilisé pour définir une valeur de type de socket telle que celle qui serait passée dans un appel à socket(2) . Les seules valeurs actuellement prises en charge sont SOCK_STREAM (par défaut) et SOCK_DGRAM. Si SOCK_DGRAM est configuré, la connexion créée est un socket datagramme UDP géré via BIO_s_datagram(3). Les appels d'E/S tels que BIO_read(3) et BIO_write(3) sont transmis de manière transparente à une instance interne BIO_s_datagram(3). L'instance BIO_s_datagram(3) créée peut être récupérée à l'aide de BIO_get0_dgram_bio() si désiré, qui écrit un pointeur vers l'instance BIO_s_datagram(3) dans *dgram_bio. La durée de vie de l'instance interne BIO_s_datagram(3) est gérée par BIO_s_connect() et n'a pas besoin

d'être

libérée par l'appelant. BIO_get_sock_type() récupère la valeur définie à

l'ai
de de

B

IO_set_sock_type(). NOTES Si les E/S bloquantes sont définies, une valeur de retour non positive de n'importe quel appel d'E/S est causée par une condition d'erreur, bien qu'un retour de zéro

signifie

généralement que la connexion a été fermée. Si le nom du port est fourni dans le nom d'hôte, cela remplacera toute valeur définie avec BIO_set_conn_port(). Cela peut être indésirable si l'application ne souhaite pas autoriser la connexion à des ports arbitraires. Cela peut être évité en vérifiant la présence du caractère ':' dans le nom d'hôte passé et en indiquant une erreur ou en tronquant la chaîne à ce

point.

Les valeurs renvoyées par BIO_get_conn_hostname(), BIO_get_conn_address() et BIO_get_conn_port() sont mises à jour lors d'une tentative de connexion. Avant toute tentative de connexion, les valeurs renvoyées sont celles définies par l'application

elle-même.

Les applications n'ont pas besoin d'appeler BIO_do_connect() mais peuvent souhaiter le faire pour séparer le processus de connexion du

traitement

des autres E/S. Si les E/S non bloquantes sont définies, des nouvelles

tentatives

seront demandées selon les besoins. En plus de BIO_should_read() et BIO_should_write(), il est également possible que BIO_should_io_special() soit vrai pendant le processus de connexion initial avec la raison BIO_RR_CONNECT. Si cela est renvoyé, cela indique qu'une tentative de connexion serait bloquante ; l'application devrait alors prendre les mesures appropriées pour attendre que le socket sous-jacent soit connecté

et

réessayer l'appel. BIO_set_conn_hostname(), BIO_set_conn_port() , BIO_get_conn_hostname() , BIO_set_conn_address() , BIO_get_conn_port(), BIO_get_conn_address(), BIO_set_conn_ip_family(), BIO_get_conn_ip_family(), BIO_set_nbio() et BIO_do_connect() sont des macros.

S

Cet exemple se connecte à un serveur web sur l'hôte local et tente de récupérer une page et de copier le résultat sur la sortie

standard. 
BIO *cbio, *out;
int len;
char tmpbuf[1024];
cbio = BIO_new_connect("localhost:http");
out = BIO_new_fp(stdout, BIO_NOCLOSE);
if (BIO_do_connect(cbio
) <= 0) { fprintf(stderr, "Error connecting to server\n"); ERR_print_errors_fp(stderr); exit(1); } BIO_puts(cbio, "GET / HTTP/1.0\n\n");
for (;;) { len = BIO_read(cbio, tmpbuf, 1024); if (len <= 0) break; BIO_write(out, tmpbuf, len); } BIO_free(cbio); BIO_free(out);
