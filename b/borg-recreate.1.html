DESCRIPTIO

N

Recréer le contenu d'archives

existantes.

Recreate est une opération potentiellement dangereuse et peut entraîner une perte de données (si elle est utilisée à tort). SOYEZ TRÈS PRUDENT

!

Important : l'espace disque du dépôt n'est pas libéré tant que vous n'exécutez pas borg comp

act.

--exclude, --exclude-from, --exclude-if-present, --keep-exclude-tags et CHEMIN ont la sémantique exactement identique à celle de "borg create", mais ils ne vérifient que les fichiers présents dans les archives et non dans le système de fichiers local. Si des CHEMINs sont spécifiés, les archives résultantes ne contiendront que les fichiers provenant de ces

CHEMINs.

Notez que tous les chemins dans une archive sont relatifs, par conséquent les motifs/chemins absolus ne correspondront pas (--exclude, --exclude-from, CHEMINs)

.

--recompress permet de modifier la compression des données existantes dans les archives. En raison de la manière dont Borg stocke les informations de taille compressée, cela peut afficher des informations incorrectes pour les archives qui n'ont pas été recréées en même temps. Il n'y a aucun risque de perte de données à cet

égard.

--chunker-params re-découpera tous les fichiers de l'archive ; cela peut être utilisé pour faire en sorte que les archives Borg 0.xx ou Attic mises à niveau soient dédupliquées avec les archives Borg 1.

x.

UTILISEZ AVEC PRUDENCE. Selon les CHEMINs et motifs fournis, recreate peut être utilisé pour supprimer définitivement des fichiers des archives. En cas de doute, utilisez --dry-run --verbose --list pour voir comment les motifs/CHEMINs sont interprétés. Voir list_item_flags dans borg create pour plus de

détails.

L'archive en cours de recréation n'est supprimée qu'une fois l'opération terminée. L'archive qui est construite pendant l'opération existe simultanément sous "<ARCHIVE>.recreate". La nouvelle archive aura un ID d'archive

différent.

Avec --target, l'archive d'origine n'est pas remplacée ; à la place, une nouvelle archive est

créée.

Lors d'une re-découpage (ou recompression), l'utilisation d'espace peut être considérable - attendez-vous à au moins la taille dédupliquée complète des archives utilisant les paramètres de découpage (ou de compression)

précédents.

Si vous avez récemment exécuté borg check --repair et qu'il a dû réparer des fragments perdus avec des fragments de remplacement entièrement à zéro, veuillez d'abord exécuter une autre sauvegarde pour les mêmes données et ré-exécuter borg check --repair par la suite pour guérir les archives qui avaient perdu des fragments mais qui sont toujours générées à partir des données

d'entrée.

Important : exécuter borg recreate pour re-découper supprimera les métadonnées chunks_healthy de tous les éléments ayant des fragments de remplacement, de sorte que la guérison ne sera plus possible après le re-découpage (il est également peu probable que cela fonc

tionne jamais : en raison du changement des paramètres de découpage, le fragment manquant
ne sera probablement jamais revu même si vous avez toujours les données qui l'ont produit).

EXEMPLE

S 
# Faire en sorte que les anciennes archives (Attic/Borg 0.xx) soient
# dédupliquées avec les archives Borg 1.x.
# Les archives créées avec Borg 1.1+ et les paramètres de découpage par défaut
# sont ignorées (l'ID d'archive reste le même).
$ borg recreate /mnt/backup --chunker-params default --progress
# Créer une sauvegarde avec une compression faible mais rapide.
$ borg create /mnt/backup::archive /some/files --compression lz4
# Puis la compresser — cela peut prendre plus de temps, mais la sauvegarde est
# déjà terminée, donc pas d'incohérences d'un travail de sauvegarde de longue
# durée.
$ borg recreate /mnt/backup::archive --recompress --compression zlib,9
# Supprimer les fichiers indésirables de toutes les archives d'un dépôt.
# Notez le chemin relatif pour l'option --exclude — les archives neain chemins relatifs.
$ borg recreate /mnt/backup --exclude home/icke/Pictures/drunk_photos
