NOM

btrfs-send - générer un flux de modifications entre deux clichés de sous-volumes

SYNTAXE

btrfs send [-ve] [-p <parent>] [-c <clone-src>] [-f <fichier_sortie>] <sous-vol> [<sous-vol>...]

DESCRIPTION

Cette commande génère un flux d'instructions qui décrivent les modifications entre deux clichés de sous-volumes. Le flux peut être consommé par la commande btrfs receive pour répliquer le cliché envoyé sur un système de fichiers différent. La commande fonctionne en deux modes : complet et incrémental.

Tous les clichés impliqués dans une commande d'envoi doivent être en lecture seule, et ce statut ne peut être modifié tant qu'une opération d'envoi en cours utilise le cliché. Le montage en lecture seule du sous-volume n'est pas suffisant, il n'y a aucun moyen de garantir qu'il n'y aura pas un autre montage en écriture du même sous-volume qui pourrait écrire pendant l'exécution de l'envoi.

En mode complet, les données et métadonnées du cliché entier seront incluses dans le flux.

En mode incrémental (options -p et -c), les clichés précédemment envoyés et disponibles à la fois du côté de l'expéditeur et du récepteur peuvent être utilisés pour réduire la quantité d'informations à envoyer afin de reconstruire le cliché envoyé sur un autre système de fichiers.

L'option -p <parent> peut être omise lorsque les options -c <clone-src> sont fournies, auquel cas btrfs send déterminera un parent approprié parmi les sources de clonage.

Vous ne devez pas spécifier de sources de clonage à moins de garantir que ces clichés sont exactement dans le même état des deux côtés – tant pour l'expéditeur que pour le récepteur. Pour les implications d'un changement de statut lecture-écriture d'un cliché reçu, veuillez consulter la section FLAGS DE SOUS-VOLUME dans btrfs-subvolume(8) <>.

Options

-e
si plusieurs sous-volumes sont envoyés à la fois, utiliser le nouveau format et omettre le marqueur end cmd dans le flux séparant les sous-volumes
-p <parent>
envoyer un flux incrémental de parent à sous-vol
-c <clone-src>
utiliser ce cliché comme source de clonage pour un envoi incrémental (plusieurs possibles)
-f <fichier_sortie>
la sortie est normalement écrite sur la sortie standard afin de pouvoir être, par exemple, redirigée vers btrfs receive. Utiliser cette option pour l'écrire dans un fichier à la place.
--no-data
envoyer en mode NO_FILE_DATA

Le flux de sortie ne contient aucune donnée de fichier et ne peut donc pas être utilisé pour transférer des modifications. Ce mode est plus rapide et utile pour montrer les différences dans les métadonnées.

--proto <N>
utiliser le protocole d'envoi version N

La version par défaut est 1, qui était la version originale du protocole. La version 2 encode les données de fichier de manière légèrement plus efficace ; elle est également nécessaire pour envoyer directement des données compressées (voir --compressed-data). La version 2 nécessite au moins btrfs-progs 6.0 sur l'expéditeur et le récepteur, et au moins Linux 6.0 sur l'expéditeur. Passer 0 signifie utiliser la version la plus élevée supportée par le noyau en cours d'exécution.

--compressed-data
envoyer directement les données compressées sur le système de fichiers sans les décompresser

Si le récepteur prend en charge l'ioctl BTRFS_IOC_ENCODED_WRITE (ajouté dans Linux 6.0), il peut également l'écrire directement sans la décompresser. Sinon, le récepteur se rabattra sur la décompression et l'écriture normale.

Ceci nécessite le protocole version 2 ou supérieur. Si --proto n'a pas été utilisé, alors --compressed-data implique --proto 2.

-q|--quiet
(déprécié) alias pour l'option globale -q
-v|--verbose
(déprécié) alias pour l'option globale -v

Options globales

-q|--quiet
supprimer tous les messages sauf les erreurs
-v|--verbose
augmenter la verbosité de la sortie, afficher les commandes générées de manière lisible

STATUT DE SORTIE

btrfs send retourne un statut de sortie nul en cas de succès. Une valeur non nulle est retournée en cas d'échec.

DISPONIBILITÉ

btrfs fait partie de btrfs-progs. Veuillez vous référer à la documentation sur https://btrfs.readthedocs.io.
