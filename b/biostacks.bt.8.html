NOM

biostacks - Afficher la latence des E/S disque avec des piles d'initialisation. Utilise bpftrace/eBPF.

SYNTAXE

biostacks

DESCRIPTION

Cet outil affiche des histogrammes de latence des E/S disque pour chaque chemin d'initialisation des E/S bloc. Cela peut aider à révéler la raison des différentes latences, certaines pouvant être créées par la vidange de journal, d'autres par des lectures d'application, etc.

Cela fonctionne en s'attachant aux points de trace block_io_start et block_rq_issue.

Comme cela utilise BPF, seul l'utilisateur root peut utiliser cet outil.

PRÉREQUIS

CONFIG_BPF et bpftrace.

EXEMPLES

Tracer la latence des E/S disque avec les piles d'initialisation :
# biostacks.bt

CHAMPS

0e
Une trace de pile noyau d'initialisation (affichée entre guillemets {@code @[...]}) est imprimée avant chaque histogramme d'E/S.
1er, 2e
Il s'agit d'une plage de latence d'E/S, en microsecondes (affichée entre crochets {@code [...]}).
3e
Une colonne indiquant le nombre d'E/S dans cette plage.
4e
Il s'agit d'un histogramme ASCII représentant la colonne de comptage.

SURCHARGE

Le taux de biostacks devrait être faible (limité par le nombre d'IOPS du périphérique), de sorte que la surcharge de cet outil devrait être négligeable.

SOURCE

Cet outil est issu du livre « BPF Performance Tools », publié par Addison Wesley (2019) :

http://www.brendangregg.com/bpf-performance-tools-book.html

Consultez le livre pour plus de documentation sur cet outil.

Cette version se trouve dans le dépôt bpftrace :

https://github.com/bpftrace/bpftrace

Recherchez également dans la distribution bpftrace un fichier _examples.txt compagnon contenant des exemples d'utilisation, de sortie et des commentaires pour cet outil.
