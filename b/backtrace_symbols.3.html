backtrace(3) Manuel des fonctions de bibliothèque backtrace(3)

NOM

backtrace, backtrace_symbols, backtrace_symbols_fd - support pour le débogage par l'application elle-même

BIBLIOTHÈQUE

Bibliothèque C standard (libc, -lc)

SYNTAXE

#include <execinfo.h>
int backtrace(int size;
              void *buffer[size], int size);
char **backtrace_symbols(int size;
              void *const buffer[size], int size);
void backtrace_symbols_fd(int size;
              void *const buffer[size], int size, int fd);

DESCRIPTION

backtrace() renvoie une trace d'appels pour le programme appelant, dans le tableau pointé par buffer. Une trace d'appels est la série des appels de fonction actuellement actifs pour le programme. Chaque élément du tableau pointé par buffer est de type void *, et est l'adresse de retour du cadre de pile correspondant. L'argument size spécifie le nombre maximal d'adresses pouvant être stockées dans buffer. Si la trace d'appels est plus grande que size, alors les adresses correspondant aux size appels de fonction les plus récents sont renvoyées ; pour obtenir la trace d'appels complète, assurez-vous que buffer et size sont suffisamment grands.

Étant donné l'ensemble d'adresses renvoyées par backtrace() dans buffer, backtrace_symbols() traduit les adresses en un tableau de chaînes de caractères décrivant symboliquement les adresses. L'argument size spécifie le nombre d'adresses dans buffer. La représentation symbolique de chaque adresse se compose du nom de la fonction (si cela peut être déterminé), d'un décalage hexadécimal dans la fonction, et de l'adresse de retour réelle (en hexadécimal). L'adresse du tableau de pointeurs de chaînes de caractères est renvoyée comme résultat de la fonction backtrace_symbols(). Ce tableau est alloué par backtrace_symbols() via malloc(3), et doit être libéré par l'appelant. (Les chaînes de caractères pointées par le tableau de pointeurs n'ont pas besoin et ne doivent pas être libérées.)

backtrace_symbols_fd() prend les mêmes arguments buffer et size que backtrace_symbols(), mais au lieu de renvoyer un tableau de chaînes de caractères à l'appelant, elle écrit les chaînes, une par ligne, dans le descripteur de fichier fd. backtrace_symbols_fd() n'appelle pas malloc(3), et peut donc être utilisée dans des situations où cette dernière fonction pourrait échouer, mais voir la section NOTES.

VALEUR RENVOYÉE

backtrace() renvoie le nombre d'adresses renvoyées dans buffer, qui n'est pas supérieur à size. Si la valeur de retour est inférieure à size, alors la trace d'appels complète a été stockée ; si elle est égale à size, alors elle a pu être tronquée, auquel cas, les adresses des cadres de pile les plus anciens ne sont pas renvoyées.

En cas de succès, backtrace_symbols() renvoie un pointeur vers le tableau alloué par malloc(3) lors de l'appel ; en cas d'erreur, NULL est renvoyé.

NORMES

GNU.

HISTORIQUE

glibc 2.1.

NOTES

Ces fonctions font certaines suppositions sur la manière dont l'adresse de retour d'une fonction est stockée sur la pile. Notez les points suivants :

•
L'omission des pointeurs de cadre (comme le suggèrent les niveaux d'optimisation non nuls de gcc(1)) peut entraîner la violation de ces suppositions.
•
Les fonctions inline n'ont pas de cadres de pile.
•
L'optimisation par appel final provoque le remplacement d'un cadre de pile par un autre.
•
backtrace() et backtrace_symbols_fd() n'appellent pas explicitement malloc(), mais elles font partie de libgcc, qui est chargée dynamiquement lors de sa première utilisation. Le chargement dynamique déclenche généralement un appel à malloc(3). Si vous avez besoin que certains appels à ces deux fonctions n'allouent pas de mémoire (dans les gestionnaires de signaux, par exemple), vous devez vous assurer que libgcc est chargée au préalable.

Les noms des symboles peuvent être indisponibles sans l'utilisation d'options d'édition de liens spéciales. Pour les systèmes utilisant l'éditeur de liens GNU, il est nécessaire d'utiliser l'option -rdynamic de l'éditeur de liens. Notez que les noms des fonctions "statiques" ne sont pas exposés et ne seront pas disponibles dans la trace d'appels.

EXEMPLES

Le programme ci-dessous démontre l'utilisation de backtrace() et backtrace_symbols(). La session shell suivante montre ce que nous pourrions voir en exécutant le programme :


$ cc -rdynamic prog.c -o prog
$ ./prog 3
backtrace() returned 8 addresses
./prog(myfunc3+0x5c) [0x80487f0]
./prog [0x8048711]
./prog(myfunc+0x21) [0x8048894]
./prog(myfunc+0x1a) [0x804888d]
./prog(myfunc+0x1a) [0x804888d]
./prog(main+0x65) [0x80488fb]
/lib/libc.so.6(__libc_start_main+0xdc) [0xb7e38f9c]
./prog [0x8048711]

Source du programme

#include <execinfo.h>
#include <stdio.h>
#include <stdlib.h>
#include <unistd.h>
#define BT_BUF_SIZE 100
void
myfunc3(void)
{
    int nptrs;
    void *buffer[BT_BUF_SIZE];
    char **strings;
    nptrs = backtrace(buffer, BT_BUF_SIZE);
    printf("backtrace() returned %d addresses\n", nptrs);
    /* L'appel backtrace_symbols_fd(buffer, nptrs, STDOUT_FILENO)
       produirait une sortie similaire à celle qui suit : */
    strings = backtrace_symbols(buffer, nptrs);
    if (strings == NULL) {
        perror("backtrace_symbols");
        exit(EXIT_FAILURE);
    }
    for (size_t j = 0; j < nptrs; j++)
        printf("%s\n", strings[j]);
    free(strings);
}
static void   /* "static" signifie ne pas exporter le symbole.  */
myfunc2(void)
{
    myfunc3();
}
void
myfunc(int ncalls)
{
    if (ncalls > 1)
        myfunc(ncalls - 1);
    else
        myfunc2();
}
int
main(int argc, char *argv[])
{
    if (argc != 2) {
        fprintf(stderr, "%s num-appels\n", argv[0]);
        exit(EXIT_FAILURE);
    }
    myfunc(atoi(argv[1]));
    exit(EXIT_SUCCESS);
}
