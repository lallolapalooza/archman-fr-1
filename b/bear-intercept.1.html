NOM

bear-intercept - intercepte les exécutions de commandes dans l'espace utilisateur.

SYNTAXE

bear intercept [options] -- [commande de compilation]

DESCRIPTION

La commande exécute la commande de compilation donnée et génère un fichier de sortie qui contient tous les événements liés à l'exécution des processus qui se sont produits pendant la compilation.

Les événements d'exécution de processus sont : démarrage, signal, terminaison. La sortie ne contiendra que les processus enfants. Selon le mode d'interception, la sortie pourrait ne contenir qu'un sous-ensemble des commandes exécutées. Les modes d'interception sont :

•
preload utilise les mécanismes LD_PRELOAD ou DYLD_INSERT_LIBRARIES fournis par l'éditeur de liens dynamique. La bibliothèque pré-chargée détourne les appels d'exécution de processus et exécute un processus superviseur qui rapporte l'exécution. La méthode échoue lorsque l'exécutable est lié statiquement ou lorsqu'une protection de sécurité désactive l'éditeur de liens dynamique.
•
Le mode wrapper interpose un programme wrapper à la compilation. Le wrapper envoie un rapport d'exécution et appelle le programme original. La méthode échoue lorsque le système de compilation n'est pas assez flexible pour interposer les outils de compilation.

Les rapports sont collectés par l'intercepteur via une interface gRPC et écrits dans un fichier de sortie.

OPTIONS

--version
Affiche le numéro de version.
--help
Affiche le message d'aide.
--verbose
Active la journalisation détaillée.
--output fichier
Spécifie le fichier de sortie. (Nom de fichier par défaut fourni.) La sortie est une liste d'exécutions de commandes, avec quelques informations supplémentaires. La syntaxe est détaillée dans une section séparée.
--force-preload
Force l'utilisation de la méthode preload pour intercepter les processus enfants.
--force-wrapper
Force l'utilisation de la méthode wrapper pour intercepter les processus enfants.

STATUT DE SORTIE

Le statut de sortie du programme est le statut de sortie de la commande de compilation. Sauf si le programme lui-même plante, auquel cas il est défini sur une valeur non nulle.

FICHIER DE SORTIE

Le fichier de sortie est au format JSON Lines (https://jsonlines.org/), où chaque ligne est terminée par un séparateur de ligne \n et chaque ligne est un objet JSON.

Les objets JSON sont des événements d'exécution de processus : début de processus, processus ayant reçu un signal, processus terminé. (Pour le schéma de ces événements, veuillez consulter le code source de ce projet.)

DÉPANNAGE

Les problèmes potentiels que vous pourriez rencontrer sont : la compilation avec et sans l'interception se comporte différemment (par exemple, la compilation plante avec l'outil d'interception, mais réussit autrement). La sortie est vide, et l'interception de l'exécution des processus enfants par la commande de compilation a échoué.

La cause la plus fréquente des sorties vides est que la commande de compilation n'a exécuté aucune commande. La raison pourrait être que les compilations incrémentielles n'exécutent pas les compilateurs si tout est à jour. Rappelez-vous que ce programme ne comprend pas le fichier de compilation (par exemple, le makefile), mais intercepte les commandes exécutées.

Il peut y avoir de nombreuses raisons à l'un de ces échecs. Il est préférable de consulter la page wiki du projet pour les problèmes connus avant d'ouvrir un rapport de bug.
