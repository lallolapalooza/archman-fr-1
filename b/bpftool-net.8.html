NOM

bpftool-net - outil d'inspection des programmes bpf liés au réseau

SYNTAXE

bpftool [OPTIONS] net COMMANDE

OPTIONS := { { -j | --json } [{ -p | --pretty }] | { -d | --debug } }

COMMANDES := { show | list | attach | detach | help }

COMMANDES NET

bpftool net { show | list } [ dev NOM ]
bpftool net attach TYPE_ATTACHEMENT PROG dev NOM [ overwrite ]
bpftool net detach TYPE_ATTACHEMENT dev NOM
bpftool net help
PROG := { id ID_PROG | pinned FICHIER | tag TAG_PROG | name NOM_PROG }
TYPE_ATTACHEMENT := { xdp | xdpgeneric | xdpdrv | xdpoffload | tcx_ingress | tcx_egress }

DESCRIPTION

bpftool net { show | list } [ dev NOM ]
Liste les attaches de programmes bpf dans le sous-système réseau du noyau.

Actuellement, les attaches xdp du pilote, les attaches tc, netkit et les anciennes attaches de classificateur/action tc, flow_dissector ainsi que les attaches netfilter sont implémentées, c'est-à-dire pour les types de programmes BPF_PROG_TYPE_XDP, BPF_PROG_TYPE_SCHED_CLS, BPF_PROG_TYPE_SCHED_ACT, BPF_PROG_TYPE_FLOW_DISSECTOR, BPF_PROG_TYPE_NETFILTER.

Pour les programmes attachés à un cgroup particulier, par exemple BPF_PROG_TYPE_CGROUP_SKB, BPF_PROG_TYPE_CGROUP_SOCK, BPF_PROG_TYPE_SOCK_OPS et BPF_PROG_TYPE_CGROUP_SOCK_ADDR, les utilisateurs peuvent utiliser bpftool cgroup pour afficher les attaches cgroup. Pour les programmes bpf sk_{filter, skb, msg, reuseport} et lwt/seg6, les utilisateurs doivent consulter d'autres outils, par exemple iproute2.

La sortie actuelle commencera par toutes les attaches de programmes xdp, suivies de toutes les attaches tc, netkit, puis des programmes bpf de classe/qdisc tc, puis flow_dissector et enfin des programmes netfilter. Les programmes xdp et les programmes tcx/netkit/tc sont ordonnés en fonction du numéro d'ifindex. Si plusieurs programmes bpf sont attachés au même périphérique réseau via tc, l'ordre sera d'abord tous les programmes bpf attachés à tcx, netkit, puis les classes tc, puis tous les programmes bpf attachés aux qdiscs non-clsact, et enfin tous les programmes bpf attachés au qdisc root et clsact.

bpftool net attach TYPE_ATTACHEMENT PROG dev NOM [ overwrite ]
Attache le programme bpf PROG à l'interface réseau NOM avec le type spécifié par TYPE_ATTACHEMENT. Un programme bpf attaché précédemment peut être remplacé par la commande utilisée avec l'option overwrite. Actuellement, seuls les modes liés à XDP sont pris en charge pour TYPE_ATTACHEMENT.

TYPE_ATTACHEMENT peut être : xdp - essaie XDP natif et se rabat sur XDP générique si le pilote NIC ne le prend pas en charge ; xdpgeneric - XDP générique. S'exécute au niveau du hook XDP générique lorsque le paquet entre dans le chemin de réception en tant que skb ; xdpdrv - XDP natif. S'exécute au point le plus précoce du chemin de réception du pilote ; xdpoffload - Offload XDP. S'exécute directement sur la carte réseau à la réception de chaque paquet ; tcx_ingress - TCX entrant. S'exécute sur le trafic réseau entrant ; tcx_egress - TCX sortant. S'exécute sur le trafic réseau sortant ;

bpftool net detach TYPE_ATTACHEMENT dev NOM
Détache le programme bpf attaché à l'interface réseau NOM avec le type spécifié par TYPE_ATTACHEMENT. Pour détacher un programme bpf, le même TYPE_ATTACHEMENT utilisé précédemment pour l'attachement doit être spécifié. Actuellement, seuls les modes liés à XDP sont pris en charge pour TYPE_ATTACHEMENT.
bpftool net help
Affiche un court message d'aide.

OPTIONS

-h, --help
Affiche un court message d'aide (similaire à bpftool help).
-V, --version
Affiche le numéro de version de bpftool (similaire à bpftool version), le numéro de la version de libbpf utilisée et les fonctionnalités optionnelles qui étaient incluses lors de la compilation de bpftool. Les fonctionnalités optionnelles incluent la liaison avec LLVM ou libbfd pour fournir le désassembleur pour les programmes JIT-ted (bpftool prog dump jited) et l'utilisation de squelettes BPF (certaines fonctionnalités comme bpftool prog profile ou l'affichage des pids associés aux objets BPF peuvent en dépendre).
-j, --json
Génère une sortie JSON. Pour les commandes qui ne peuvent pas produire de JSON, cette option n'a aucun effet.
-p, --pretty
Génère une sortie JSON lisible par l'homme. Implique -j.
-d, --debug
Affiche tous les logs disponibles, y compris les informations de niveau débogage. Cela inclut les logs de libbpf ainsi que ceux du vérificateur, lorsqu'il tente de charger des programmes.
