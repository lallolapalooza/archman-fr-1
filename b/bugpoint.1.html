DESCRIPTIO

N

bugpoint permet d'identifier la source des problèmes dans les outils et passes LLVM. Il peut être utilisé pour déboguer trois types de pannes : plantages de l'optimiseur, compilations incorrectes par les optimiseurs, ou mauvaise génération de code natif (y compris les problèmes des compilateurs statique et JIT). Il vise à réduire de grands cas de test en de petits cas utiles. Pour plus d'informations sur la conception et le fonctionnement interne de bugpoint, ainsi que des conseils pour utiliser bugpoint, voir L

LVM bugpoint tool: design and usa
ge <> dans la distribution LLVM.

Chaque fois que le programme de test est compilé, bugpoint doit générer du code pour lui en utilisant le générateur de code spécifié. --safe-{llc,

Lors du débogage d'un générateur de code, bugpoint doit utiliser le générateur de code spécifié comme générateur de code « safe ». Il s'agit d'un générateur de code connu pour être bon, utilisé pour générer la « sortie de référence » si elle n'a pas été fournie, et pour compiler les parties du programme qui en sont exclues du cas de test. Ces options vous permettent de choisir respectivement le compilateur de code natif statique, ou une commande personnalisée (voir --exec-command). Les backends interpréteur et JIT ne peuvent actuellement pas être utilisés comme backends « safe

--compile-command command

e
Cette option définit la commande à utiliser avec l'option --compile-custom pour compiler le cas de test en bitcode. La commande doit se terminer avec un code de sortie d'échec si le fichier est « interesting » et doit se terminer avec un code de sortie de succès (c'est-à-dire 0) sinon (c'est la même chose que si elle plantait sur des entrées « interesting »).

Cela peut être utile pour tester la sortie d'un compilateur sans exécuter d'étapes de liaison ou d'exécution. Pour générer un test unitaire réduit, vous pouvez ajouter des directives CHECK au cas de test et passer le nom d'un script compile-command exécutable sous cette forme

minimal qui passe FileCheck.

--verbose-errors={true,

false}
Le comportement par défaut de bugpoint est d'afficher « <crash> » lorsqu'il trouve un test réd

et non d'une erreur différente qui fait également planter le compilateur. Par défaut : false.
