Les 
configurations peuvent être
liées

entre elles pour permettre à un paquet d'être construit dans une configuration tout en construisant ses dépendances dans une ou plusieurs configurations liées. Cela peut être utilisé pour créer une configuration « de base » avec des dépendances communes partagées entre plusieurs configurations. Ce mécanisme est également utilisé pour fournir une configuration hôte utilisée pour construire les dépendances au moment de la

construction.

Chaque configuration se voit attribuer un UUID généré automatiquement sauf si un est spécifié avec l'option --uuid. Cet UUID est utilisé pour vérifier l'intégrité des liens de configuration. Pour faciliter la référence aux configurations liées, une configuration peut également se voir attribuer un nom avec l'option --name.

Une

configuration a également un type spécifié avec l'option --type. Trois types prédéfinis sont : target, host et build2. Si le type n'est pas spécifié explicitement, alors target est supposé. Lors de la satisfaction d'une dépendance d'un paquet sur un autre, une configuration liée ne sera considérée que si (1) elle a le même type que l'autre configuration pour les dépendances d'exécution, (2) elle a le type host pour les dépendances de construction régulières, et (3) elle a le type build2 pour les dépendances de construction des modules du système de construction. Notez qu'une configuration hôte est une configuration cible pour la machine hôte. Ainsi, pour créer une configuration auto-hébergée, utilisez le type host. P

our

lier une configuration, nous utilisons la commande bpkg-cfg-link(1). En raccourci, les configurations hôte et les configurations de modules du système de construction peuvent également être liées lors de la création de la configuration avec les options --host-config et --build2-config respectivement.
