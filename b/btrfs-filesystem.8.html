NAME

btrfs-filesystem — manipulate btrfs filesystem

SYNOPSIS

btrfs filesystem subcommand [options] [args]

DESCRIPTION

The btrfs filesystem command is used to manage various aspects of a btrfs filesystem, including defragmentation, resizing, and obtaining usage information. It supports several subcommands, each targeting a specific operation.

SUBCOMMAND

defrag [-r] [-v] [-f] [-c [compress_type]] [-t [[no]io|allocsize]] [-d [[no]io|allocsize]] [-s [[no]io|allocsize]] [-m [[no]io|allocsize]] [-k [[no]io|allocsize]] [-p [[no]io|allocsize]] <path> [...]
Defragment the file(s) specified by path. If a directory is specified, recursively operate on the directory contents.

Options:

  • -r: Recurse into directories.
  • -v: Be verbose. Print files as they are processed.
  • -f: Force. Flush data to disk before processing the next file.
  • -c compress_type: Compress file content during defragmentation. Supported types are `lzo` and `zstd`. If no type is specified, `zstd` is used by default.
  • -t [[no]io|allocsize]: Target extent size. Try to merge extents to a target size for data blocks. The default is `allocsize`. Use `nio` to disable.
  • -d [[no]io|allocsize]: Target extent size for data.
  • -s [[no]io|allocsize]: Target extent size for system data.
  • -m [[no]io|allocsize]: Target extent size for metadata.
  • -k [[no]io|allocsize]: Target extent size for duplicated data.
  • -p [[no]io|allocsize]: Target extent size for duplicated metadata.

Note: The extent size is a hint and the final result may vary based on filesystem fragmentation and available space.

resize [-s [[+|-]size[unit]] | max] [-r] [<devid>:]path [...]
Resize the filesystem. Can be used to grow or shrink the filesystem.

Options:

  • -s [[+|-]size[unit]]: Specify the new size. Prefixes `+` or `-` can be used for relative resizing. Units are `K`, `M`, `G`, `T`, `P`, `E` (powers of 1024) or `KiB`, `MiB`, `GiB`, etc.
  • max: Resize the filesystem to the maximum possible size on the device.
  • -r: Enable read-only filesystem resize. This allows shrinking on a read-only mounted filesystem.
  • <devid>:: Optional device ID to specify which device to resize in a multi-device filesystem.

The path argument is the mount point of the filesystem. Multiple paths can be specified for multi-device filesystems.

usage [-b] [-h] [-H] [--iec] [--si] [-k] [-m] [-g] [-t] [-T] <path> [<path>...]
Show detailed information about filesystem usage. This command aims to replace btrfs filesystem df. The level of detail may differ based on user privileges (root vs. regular user).

Options:

  • -b, --raw: Display numbers in bytes without suffixes.
  • -h, --human-readable: Display numbers in a human-friendly format (base 1024, powers of 2). This is the default.
  • -H: Display numbers in a human-friendly format (base 1000, powers of 10).
  • --iec: Use IEC standard (powers of 1024) for human-readable output.
  • --si: Use SI standard (powers of 1000) for human-readable output.
  • -k, --kbytes: Display sizes in Kibibytes (KiB) or Kilobytes (kB with --si).
  • -m, --mbytes: Display sizes in Mebibytes (MiB) or Megabytes (MB with --si).
  • -g, --gbytes: Display sizes in Gibibytes (GiB) or Gigabytes (GB with --si).
  • -t, --tbytes: Display sizes in Tebibytes (TiB) or Terabytes (TB with --si).
  • -T: Display data in a tabular format.

If conflicting options are provided, the last one takes precedence.

sync <path>
Force a synchronous write of all cached data to the underlying storage for the filesystem specified by path. This is similar to the sync(1) command. Additionally, it triggers the cleaning of deleted subvolumes. To wait for subvolume deletion to complete, use the btrfs subvolume sync command.

Note: The btrfs filesystem defrag command requires root privileges to operate on directories or files owned by other users. btrfs filesystem usage may provide more detailed information when run as root.

EXAMPLES

$ btrfs filesystem defrag -v -r dir/

Recursively defragment files under dir/, printing files as they are processed. The system's memory throttling may slow down the defragmentation, and it can still cause significant I/O load.

$ btrfs filesystem defrag -v -r -f dir/

Recursively defragment files under dir/, be verbose, and flush data to disk before processing the next file. This results in slower progress but lower peak I/O load.

$ btrfs filesystem defrag -v -r -c lzo dir/

Recursively defragment files under dir/, be verbose, and compress file content using LZO during defragmentation.

$ btrfs filesystem defrag -v -r -t 64M dir/

Recursively defragment files under dir/, be verbose, and attempt to merge extents to approximately 64 MiB for data blocks. Success depends on filesystem fragmentation and available space.

$ btrfs filesystem resize -1G /path

Shrink the filesystem mounted at /path by 1 GiB.

$ btrfs filesystem resize 1:-1G /path

Shrink the device with ID 1 within the filesystem mounted at /path by 1 GiB. This syntax is more explicit for multi-device filesystems.

$ btrfs filesystem resize max /path

Grow the filesystem mounted at /path to occupy the maximum available space on its underlying device(s).

$ btrfs filesystem usage /path

Display detailed usage statistics for the filesystem mounted at /path.

$ btrfs filesystem sync /path

Ensure all cached data for the filesystem at /path is written to disk.

EXIT STATUS

Zero exit status is returned on success. Non-zero exit status is returned in case of failure.

AVAILABILITY

The btrfs filesystem command is part of the btrfs-progs package. More information can be found at https://btrfs.readthedocs.io.
