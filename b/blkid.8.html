DESCRIPTIO

N

Le programme blkid est l'interface en ligne de commande pour travailler avec la bibliothèque libblkid(3). Il peut déterminer le type de contenu (par ex. système de fichiers ou swap) qu'un périphérique de bloc contient, ainsi que les attributs (jetons, paires NOM=valeur) provenant des métadonnées du contenu (par ex. les champs LABEL ou UUID)

.

Il est recommandé d'utiliser la commande lsblk(8) pour obtenir des informations sur les périphériques de bloc, ou lsblk --fs pour obtenir un aperçu des systèmes de fichiers, ou findmnt(8) pour rechercher dans les systèmes de fichiers déjà

montés.

lsblk(8) fournit plus d'informations, un meilleur contrôle sur le formatage de la sortie, est facile à utiliser dans des scripts et ne nécessite pas les permissions root pour obtenir les informations réelles. blkid lit les informations directement depuis les périphériques et pour les utilisateurs non-root, il renvoie des informations mises en cache et non vérifiées. blkid est principalement conçu pour les services système et pour tester la fonctionnalité de libblkid(3).

Quand un périphérique est spécifié, les jetons de ce seul périphérique sont affichés. Il est possible de spécifier plusieurs arguments périphérique sur la ligne de commande. Si aucun n'est donné, toutes les partitions ou périphériques non partitionnés qui apparaissent dans /proc/partitions sont affichés, s'ils sont

reconnus.

blkid a deux formes principales de fonctionnement : soit rechercher un périphérique avec une paire NOM=valeur spécifique, soit afficher les paires NOM=valeur pour un ou plusieurs périphériques

spécifiés.

Pour des raisons de sécurité, blkid ignore silencieusement tous les périphériques dont le résultat de la sonde est ambivalent (plusieurs systèmes de fichiers en conflit sont détectés). Le mode de sonde de bas niveau (-p) fournit plus d'informations et un code de sortie supplémentaire dans ce cas. Il est recommandé d'utiliser wipefs(8) pour obtenir un aperçu détaillé et effacer les é

léments obsolètes (chaîn
es magiques) du périphérique.

OPTION

S

Les arguments size et offset peuvent être suivis par des suffixes multiplicatifs tels que KiB (=1024), MiB (=1024*1024), et ainsi de suite pour GiB, TiB, PiB, EiB, ZiB et YiB (le « iB » est facultatif, par ex. « K » a la même signification que « KiB »), ou les suffixes KB (=1000), MB (=1000*1000), et ainsi de suite pour GB, TB, PB, EB, ZB et

YB.

-c, --cache-file fichier_cach

e
Lire depuis fichier_cache au lieu de lire depuis le fichier cache par défaut (voir la section FICHIER DE CONFIGURATION pour plus de détails). Si vous souhaitez démarrer avec un cache vierge (c.-à-d. ne pas signaler les périphériques précédemment scannés mais pas nécessairement disponibles en ce moment), spécifiez /dev/null

Ne pas encoder les caractères non imprimables. Les caractères non imprimables sont encodés par défaut avec la notation ^ et M-. Notez que le format de sortie udev de --output utilise un encodage différent qui ne peut pas être

-l, --list-on

e
Rechercher un seul périphérique qui correspond au paramètre de recherche spécifié avec l'option --match-token. S'il y a plusieurs périphériques qui correspondent au paramètre de recherche spécifié, alors le périphérique avec la priorité la plus élevée est renvoyé, et/ou le premier périphérique trouvé à une priorité donnée (mais voir la note ci-dessous à propos de udev). Les types de périphériques par ordre de priorité décroissante sont : Device Mapper, EVMS, LVM, MD, et enfin les périphériques de bloc ordinaires. Si cette option n'est pas spécifiée, blkid affichera tous les périphériques qui correspondent au paramètre de recherche.

Cette option force blkid à utiliser udev lorsqu'elle est utilisée pour les jetons LABEL ou UUID dans --match-token. Le but est de fournir une sortie cohérente avec d'autres utilitaires (comme mount(8), etc.) sur les systèmes où la même

balise est utilisée pour
plusieurs périphériques.

-L, --label étiquett

e
Rechercher le périphérique qui utilise cette étiquette de système de fichiers ; cela équivaut à --list-one --output device --match-token LABEL=étiquette. Cette méthode de recherche est capable d'utiliser de manière fiable les liens symboliques udev /dev/disk/by-label (selon un paramètre dans /etc/blkid.conf). Évitez d'utiliser les liens symboliques directement ; il n'est pas fiable d'utiliser les liens symboliques sans vérification. L'option --label fonctionne sur les systèmes avec et sans udev.

Malheureusement, le blkid(8) original d'e2fsprogs utilise l' option -L comme synonyme pour -o list. Pour une meilleure portabilité, utilisez -l -o device -t LABEL=étiquette et -o list dans vos scripts plutôt que l' optio

n -
L.

-O, --offset offse

Sonde à l' offset donné (utile uniquement avec --probe). Cette option peut être utilisée avec l'option --info

-p, --prob

e
Passe en mode de sonde de superblock bas niveau (en contournant le cache).

Notez que la sonde bas niveau renvoie également des informations sur le type de table de partition (balise PTTYPE) et les partitions (balises PART_ENTRY_*). Les noms de balises produits par la sonde bas niveau sont basés sur les noms utilisés en interne par libblkid et peuvent différer de ceux obtenus sans --probe (par exemple PART_ENTRY_UUID= vs PARTUUID=). Voir aussi --no-part-detail

-s, --match-tag ta

g
Pour chaque périphérique (spécifié), affiche uniquement les balises qui correspondent à tag. Il est possible de spécifier plusieurs options --match-tag . Si aucune balise n'est spécifiée, alors tous les jetons sont affichés pour tous les périphériques (spécifiés). Afin de simplement rafraîchir le cache sans afficher de jetons, utilisez --match-tag none sans aucune autre
option.

-S, --size siz

e
Remplace la taille du périphérique/fichier (utile uniquement avec --prob

-t, --match-token NOM=valeu

r
Recherche des périphériques bloc avec des jetons nommés NOM ayant la valeur valeur, et affiche tous les périphériques trouvés. Les valeurs courantes pour NOM incluent TYPE, LABEL, et UUID. Si aucun périphérique n'est spécifié sur la ligne de commande, tous les périphériques bloc seront recherchés ; sinon, seuls les périphériques spécifiés sont
recherchés.

-u, --usages list

e
Restreint les fonctions de sonde aux types d' « usage » spécifiés (séparés par des virgules). Les types d'usage pris en charge sont : filesystem, raid, crypto et other. Les éléments de la liste peuvent être préfixés par « no » pour spécifier les types d'usage qui doivent être ignorés. Par exemple :

blkid --probe --usages filesystem,other

/dev/sda1

sonde tous les formats de système de fichiers et autres (par ex., swap),

et

blkid --probe --usages noraid

/dev/sda1

sonde tous les formats pris en charge sauf les RAIDs. Cette option n'est utile qu'avec --pr

CODE DE

RETOUR

Si le périphérique spécifié ou le périphérique adressé par le jeton spécifié (option --match-token) a été trouvé et qu'il est possible de recueillir des informations à son sujet, un code de retour 0 est renvoyé. Notez que l'option --match-tag filtre les balises de sortie, mais n'affecte pas le code de

retour.

Si le jeton spécifié n'a pas été trouvé, ou si aucun périphérique (spécifié) n'a pu être identifié, ou s'il est impossible de recueillir des informations sur les identifiants du périphérique ou son contenu, un code de retour de 2 est

renvoyé.

En cas d'erreur d'utilisation ou d'autres erreurs, un code de retour de 4 est

renvoyé.

Si un résultat de sonde ambigu a été détecté par le mode de sonde bas niveau (-p), un code de reto

ur de 8 es
t renvoyé.

FICHIER DE

CONFIGURATION

L'emplacement standard du fichier de configuration /etc/blkid.conf peut être remplacé par la variable d'environnement BLKID_CONF. Les options suivantes contrôlent la bibliothèque libblkid

:

SEND_UEVENT=<yes|not

>
Envoie un uevent lorsque le lien symbolique /dev/disk/by-{label,uuid,partuuid,partlabel}/ ne correspond pas au LABEL, UUID, PARTUUID ou PARTLABEL du périphérique. La valeur par défaut est « yes »
.

CACHE_FILE=<chemin

>
Remplace l'emplacement standard du fichier de cache. Ce paramètre peut être remplacé par la variable d'environnement BLKID_FILE. La valeur par défaut est /run/blkid/blkid.tab, ou /etc/blkid.tab sur les systèmes sans répertoire /run
.

EVALUATE=<méthodes

>
Définit la ou les méthodes d'évaluation de LABEL et UUID. Actuellement, la bibliothèque libblkid prend en charge les méthodes « udev » et « scan ». Plusieurs méthodes peuvent être spécifiées dans une liste séparée par des virgules. La valeur par défaut est « udev,scan ». La méthode « udev » utilise les liens symboliques /dev/disk/by-* d'udev et la méthode « scan » scanne tous les périphériques bloc à partir du fichier /proc/partition
s
.
