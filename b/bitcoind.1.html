-i2pacceptincoming

Accepter les connexions I2P entrantes (par défaut : 1). Ignoré si -i2psam n'est pas défini. L'écoute des connexions I2P entrantes se fait via le proxy SAM, pas en se liant à une adresse et un port locaux.

-i2psam=<ip:port>

Proxy SAM I2P pour atteindre les pairs I2P et accepter les connexions I2P (par défaut : aucun)

-listen

Accepter les connexions de l'extérieur (par défaut : 1 si pas de -proxy, -connect ou -maxconnections=0)

-listenonion

Créer automatiquement un service onion Tor (par défaut : 1)

-maxconnections=<n>

Maintenir au maximum <n> connexions automatiques avec les pairs (par défaut : 125). Cette limite ne s'applique pas aux connexions ajoutées manuellement via -addnode ou la RPC addnode, qui ont une limite séparée de 8.

-maxreceivebuffer=<n>

Tampon de réception maximal par connexion, <n>*1000 octets (par défaut : 5000)

-maxsendbuffer=<n>

Utilisation mémoire maximale du tampon d'envoi par connexion, <n>*1000 octets (par défaut : 1000)

-maxuploadtarget=<n>

Essaie de maintenir le trafic sortant sous la cible donnée par période de 24h. La limite ne s'applique pas aux pairs ayant la permission 'download' ou aux blocs créés la semaine précédente. 0 = pas de limite (par défaut : 0M). Unités suffixées optionnelles [k|K|m|M|g|G|t|T] (par défaut : M). Les minuscules sont basées sur 1000 tandis que les majuscules sont basées sur 1024.

-natpmp

Utiliser NAT-PMP pour mapper le port d'écoute (par défaut : 0)

-networkactive

Activer toute l'activité réseau P2P (par défaut : 1). Peut être modifié par la commande RPC setnetworkactive.

-onion=<ip:port|chemin>

Utiliser un proxy SOCKS5 séparé pour atteindre les pairs via les services onion Tor, définir -noonion pour désactiver (par défaut : -proxy). Peut être un chemin de fichier local préfixé par 'unix:'.

-onlynet=<net>

Effectuer les connexions sortantes automatiques uniquement vers le réseau <net> (ipv4, ipv6, onion, i2p, cjdns). Les connexions entrantes et manuelles ne sont pas affectées par cette option. Elle peut être spécifiée plusieurs fois pour autoriser plusieurs réseaux.

-peerblockfilters

Servir des filtres de blocs compacts aux pairs conformément à BIP 157 (par défaut : 0)

-peerbloomfilters

Prendre en charge le filtrage des blocs et des transactions avec des filtres bloom (par défaut : 0)

-port=<port>

Écouter les connexions sur <port> (par défaut : 8333, testnet3 : 18333, testnet4 : 48333, signet : 38333, regtest : 18444). Non pertinent pour I2P (voir doc/i2p.md). Si défini sur une valeur x, le port d'écoute onion par défaut sera défini sur x+1.

-proxy=<ip:port|chemin>

Se connecter via un proxy SOCKS5, définir -noproxy pour désactiver (par défaut : désactivé). Peut être un chemin de fichier local préfixé par 'unix:' si le proxy le supporte.

-proxyrandomize

Randomiser les identifiants pour chaque connexion proxy. Ceci active l'isolement des flux Tor (par défaut : 1)

-seednode=<ip>

Se connecter à un nœud pour récupérer les adresses des pairs, puis se déconnecter. Cette option peut être spécifiée plusieurs fois pour se connecter à plusieurs nœuds. Au démarrage, les seednodes seront essayés avant les dnsseeds.

-timeout=<n>

Spécifier le délai d'attente de connexion socket en millisecondes. Si une tentative initiale de connexion échoue après ce laps de temps, elle est abandonnée (minimum : 1, par défaut : 5000)

-torcontrol=<ip>:<port>

Hôte et port de contrôle Tor à utiliser si l'écoute onion est activée (par défaut : 127.0.0.1:9051). Si aucun port n'est spécifié, le port par défaut de 9051 sera utilisé.

-torpassword=<pass>

Mot de passe du port de contrôle Tor (par défaut : vide)

-upnp

Utiliser UPnP pour mapper le port d'écoute (par défaut : 0)

-v2transport

Prendre en charge le transport v2 (par défaut : 1)

-whitebind=<[permissions@]addr>

Se lier à l'adresse donnée et ajouter des drapeaux de permission aux pairs qui s'y connectent. Utiliser la notation [hôte]:port pour IPv6. Permissions autorisées : bloomfilter (autoriser la demande de blocs et transactions filtrés par BIP37), noban (ne pas bannir en cas de mauvais comportement ; implique download), forcerelay (relayer les transactions déjà dans le mempool ; implique relay), relay (relayer même en mode -blocksonly, et annonces de transactions illimitées), mempool (autoriser la demande des contenus du mempool BIP35), download (autoriser getheaders pendant l'IBD, pas de déconnexion après la limite maxuploadtarget), addr (les réponses à GETADDR évitent le cache et contiennent des enregistrements aléatoires avec les informations les plus à jour). Spécifier plusieurs permissions séparées par des virgules (par défaut : download,noban,mempool,relay). Peut être spécifié plusieurs fois.

-whitelist=<[permissions@]IP address or network>

Ajouter des drapeaux de permission aux pairs utilisant l'adresse IP donnée (par exemple 1.2.3.4) ou le réseau noté en CIDR (par exemple 1.2.3.0/24). Utilise les mêmes permissions que -whitebind. Les drapeaux supplémentaires "in" et "out" contrôlent si les permissions s'appliquent aux connexions entrantes et/ou manuelles (par défaut : uniquement entrantes). Peut être spécifié plusieurs fois.

Options du portefeuille :

-addresstype

Quel type d'adresses utiliser ("legacy", "p2sh-segwit", "bech32", ou "bech32m", par défaut : "bech32")

-avoidpartialspends

Grouper les sorties par adresse, en sélectionnant plusieurs (potentiellement toutes) ou aucune, au lieu de sélectionner par sortie. La confidentialité est améliorée car les adresses sont balayées avec moins de transactions et les sorties sont agrégées dans des adresses de monnaie propres. Cela peut entraîner des frais plus élevés en raison d'une sélection de pièces moins optimale due à cette limitation supplémentaire et potentiellement un nombre d'entrées plus grand que nécessaire. Toujours activé pour les portefeuilles avec "avoid_reuse" activé, sinon par défaut : 0.

-changetype

Quel type de monnaie utiliser ("legacy", "p2sh-segwit", "bech32", ou "bech32m"). Par défaut, c'est "legacy" lorsque -addresstype=legacy, sinon c'est un détail d'implémentation.

-consolidatefeerate=<amt>

Le taux de frais maximum (en BTC/kvB) auquel la construction de transaction peut utiliser plus d'entrées que strictement nécessaire afin que le pool d'UTXO du portefeuille puisse être réduit (par défaut : 0.0001).

-disablewallet

Ne pas charger le portefeuille et désactiver les appels RPC du portefeuille

-discardfee=<amt>

Le taux de frais (en BTC/kvB) qui indique votre tolérance à l'abandon de la monnaie en l'ajoutant aux frais (par défaut : 0.0001). Remarque : une sortie est abandonnée si elle est de la poussière à ce taux, mais nous abandonnerons toujours jusqu'aux frais de relais de poussière et des frais d'abandon supérieurs à cela seront limités par l'estimation des frais pour la cible la plus longue.

-fallbackfee=<amt>

Un taux de frais (en BTC/kvB) qui sera utilisé lorsque l'estimation des frais manque de données. 0 pour désactiver complètement la fonction fallbackfee. (par défaut : 0.00)

-keypool=<n>

Définir la taille du pool de clés à <n> (par défaut : 1000). Attention : des tailles plus petites peuvent augmenter le risque de perdre des fonds lors de la restauration à partir d'une ancienne sauvegarde, si aucune des adresses du pool de clés d'origine n'a été utilisée.

-maxapsfee=<n>

Dépenser jusqu'à ce montant en frais supplémentaires (absolus) (en BTC) si cela permet d'éviter les dépenses partielles (par défaut : 0.00)

-mintxfee=<amt>

Les taux de frais (en BTC/kvB) inférieurs à ce montant sont considérés comme des frais nuls pour la création de transactions (défaut : 0.00001)

-paytxfee=<amt>

Taux de frais (en BTC/kvB) à ajouter aux transactions que vous envoyez (défaut : 0.00)

-signer=<cmd>

Outil de signature externe, voir doc/external-signer.md

-spendzeroconfchange

Dépenser le rendu non confirmé lors de l'envoi de transactions (défaut : 1)

-txconfirmtarget=<n>

Si paytxfee n'est pas défini, inclure suffisamment de frais pour que les transactions commencent à être confirmées en moyenne dans les n blocs (défaut : 6)

-wallet=<path>

Spécifier le chemin du portefeuille à charger au démarrage. Peut être utilisé plusieurs fois pour charger plusieurs portefeuilles. Le chemin mène à un répertoire contenant les données du portefeuille et les fichiers journaux. Si le chemin n'est pas absolu, il est interprété par rapport à <walletdir>. Ceci ne charge que les portefeuilles existants et n'en crée pas de nouveaux. Pour des raisons de compatibilité ascendante, accepte également les noms de fichiers de données de niveau supérieur existants dans <walletdir>.

-walletbroadcast

Faire diffuser les transactions par le portefeuille (défaut : 1)

-walletdir=<dir>

Spécifier le répertoire pour contenir les portefeuilles (défaut : <datadir>/wallets s'il existe, sinon <datadir>)

-walletnotify=<cmd>

Exécuter une commande lorsqu'une transaction du portefeuille change. %s dans cmd est remplacé par l'ID de la transaction, %w par le nom du portefeuille, %b par le hachage du bloc incluant la transaction (mis à 'unconfirmed' si la transaction n'est pas incluse) et %h par la hauteur du bloc (-1 si non incluse). %w n'est actuellement pas implémenté sous Windows. Sur les systèmes où %w est pris en charge, il ne doit PAS être mis entre guillemets car cela briserait l'échappement shell utilisé pour invoquer la commande.

-walletrbf

Envoyer des transactions avec l'option full-RBF activée (RPC uniquement, défaut : 1)

Options de débogage/test :

-debug=<category>

Sortie des journaux de débogage et de trace (défaut : -nodebug, la fourniture de <category> est facultative). Si <category> n'est pas fournie ou si <category> est 1 ou "all", toutes les sorties de débogage sont affichées. Si <category> est 0 ou "none", les autres catégories sont ignorées. Les autres valeurs valides pour <category> sont : addrman, bench, blockstorage, cmpctblock, coindb, estimatefee, http, i2p, ipc, leveldb, libevent, mempool, mempoolrej, net, proxy, prune, qt, rand, reindex, rpc, scan, selectcoins, tor, txpackages, txreconciliation, validation, walletdb, zmq. Cette option peut être spécifiée plusieurs fois pour sortir plusieurs catégories.

-debugexclude=<category>

Exclure les journaux de débogage et de trace d'une catégorie. Peut être utilisé en conjonction avec -debug=1 pour afficher les journaux de débogage et de trace pour toutes les catégories sauf celle spécifiée. Cette option peut être spécifiée plusieurs fois pour exclure plusieurs catégories. Elle a priorité sur "-debug".

-help-debug

Afficher le message d'aide avec les options de débogage et quitter

-logips

Inclure les adresses IP dans la sortie de débogage (défaut : 0)

-loglevelalways

Ajouter toujours une catégorie et un niveau au début (défaut : 0)

-logsourcelocations

Ajouter le nom de l'emplacement source d'origine (fichier source, numéro de ligne et nom de fonction) au début de la sortie de débogage (défaut : 0)

-logthreadnames

Ajouter le nom du thread d'origine au début de la sortie de débogage (défaut : 0)

-logtimestamps

Ajouter un horodatage au début de la sortie de débogage (défaut : 1)

-maxtxfee=<amt>

Frais totaux maximum (en BTC) à utiliser dans une seule transaction du portefeuille ; régler ceci trop bas peut interrompre les grosses transactions (défaut : 0.10)

-printtoconsole

Envoyer les informations de trace/débogage à la console (défaut : 1 lorsqu'aucun -daemon n'est spécifié. Pour désactiver la journalisation dans le fichier, définir -nodebuglogfile)

-shrinkdebugfile

Réduire le fichier debug.log au démarrage du client (défaut : 1 lorsqu'aucun -debug n'est spécifié)

-uacomment=<cmt>

Options de sélection de chaîne :

-chain=<chain>

Utiliser la chaîne <chain> (défaut : main). Valeurs autorisées : main, test, testnet4, signet, regtest

-signet

Utiliser la chaîne signet. Équivalent à -chain=signet. Notez que le réseau est défini par le paramètre -signetchallenge.

-signetchallenge

Les blocs doivent satisfaire le script donné pour être considérés comme valides (uniquement pour les réseaux signet ; par défaut, le défi global par défaut du réseau de test signet)

-signetseednode

Spécifier un nœud de départ pour le réseau signet, au format hostname[:port], par exemple sig.net:1234 (peut être utilisé plusieurs fois pour spécifier plusieurs nœuds de départ ; par défaut, le(s) nœud(s) de départ global(aux) par défaut du réseau de test signet)

-testnet
