DESCRIPTIO

N

buildrealms aide à la configuration d'un environnement realms destiné à être utilisé par dtrealms. buildrealms crée les hiérarchies de fichiers requises pour chaque realm, déplace les fichiers d'un realm vers leur emplacement approprié dans la hiérarchie, et met à jour plusieurs fichiers pour leur destination

finale.

Les hiérarchies des realms sont construites dans une zone de préparation, qui contiendra les fichiers de tous les realms. Ce sont les fichiers rollrec, fichiers keyrec, fichiers de clés, fichiers de configuration, fichiers de journal, et tout autre élément nécessaire à DNSSEC-Tools pour gérer le renouvellement des clés. Après que buildrealms a créé ces fichiers, l'utilisateur doit vérifier les fichiers pour s'assurer qu'ils sont corrects. Les fichiers et répertoires de la zone de préparation doivent ensuite être déplacés manuellement vers le répertoire final. C'est depuis ce répertoire que dtrealms gérera les différents realms. Si le répertoire final n'est pas spécifié (via une option), alors le répertoire dans lequel buildrealms a été exécuté sera le répertoire

final.

buildrealms utilise un fichier realms pour contrôler la manière dont il construit l'environnement realms. Les entrées de realm dans ce fichier ont un champ hoard, qui n'est utilisé que par buildrealms. Pour chaque realm, la valeur de ce champ est un répertoire qui contient les fichiers nécessaires à ce realm particulier. Après avoir construit ce realm, buildrealms supprime l' entrée hoard de cet enregistrement de realm. Après que tous les realms ont été construits, une copie de ce fichier realms est déplacée dans la zone de

préparation.

Il existe deux opérations que buildrealms fournit actuellement. Ces opérations servent à créer et à maintenir un environnement realms de DNSSEC-Tools. Cette documentation décrit les opérations individuellement

.

Après que buildrealms a créé ces fichiers, l'utilisateur doit vérifier les fichiers pour s'assurer qu'ils sont corrects. Les fichiers et répertoires de la zone de préparation doivent ensuite être déplacés manuellement vers le répertoire final. Si le répertoire final n'est pas spécifié (via une option), alors le répertoire dans lequel buildrealms a été exécuté sera le répertoire

final.

L'EXÉCUTION

Dans la préparation d'un fichier realms et des hoards de realms pour buildrealms, plusieurs choses doivent être gardées à

l'esprit.
  • Utilisez des chemins relatifs pour le fichier rollrec et les trois répertoires dans le fichier re
    • alms.
  • Tous les fichiers d'un realm doivent être stockés dans son hoard. Ils n'ont pas besoin d'être à un endroit particulier du répertoire, tant que les fichiers rollrec et keyrec sont
    • exacts.
  • À la fin du processus de création, le fichier realms sera copié au niveau supérieur de la zone de
    • préparation.
  • Après que des fichiers spécifiques (par exemple, rollrecs, keyrecs, etc.) ont été déplacés dans la partie du realm de la zone de préparation, les fichiers restants du hoard seront déplacés dans la partie realmdir du realm de la zone de préparation. L'organisation hiérarchique des fichiers restants du hoard sera
    • préservée.
  • Le contenu du répertoire d'archive d'un keyrec dans le hoard du realm, tel que défini par le champ archivedir, sera déplacé vers <statedir>/key-archive dans la zone de
    • préparation.
  • Le fichier de configuration d'un realm sera placé dans <configdir>/dnssec-tools/<conffile> dans la zone de préparation. Le nom réel du fichier de configuration (donné ici comme <conffile>) dépendra de la manière dont le fichier de configuration est trouvé. Si le fichier DNSSEC-Tools du système est utilisé, alors le nom sera dnssec-tools.conf. Si l'option -config est utilisée, alors le nom utilisé avec l'option sera utilisé. Si un fichier .conf est trouvé dans le hoard du
    • realm, alors le no
m de fichier comp
let sera utilisé.

AVERTISSEMEN

TS

root n'est pas autorisé à exécuter buildrealms. Certaines des actions entreprises par buildrealms peuvent être dévastatrices si un fichier de realm mal configuré (ou construit de manière malveillante) est utilisé pour contrôler la

construction.

buildrealms n'est pas clairvoyant. Il fait de son mieux, mais c'est un outil général. Les realms résultants doivent être vérifiés pour s'assurer qu'ils sont configurés comme souhaité. En particulier, vous devriez vérifier le fichier realm, les fichiers rollrec, les fichiers keyrec et le fichier de

configuration.

Aucune fonctionnalité inverse n'a été implémentée, donc une fois exécuté, les fichiers sont modifiés, déplacés et copiés. Ce ne serait pas une mauvaise idée de sauvegarder vos fichiers avant d'exécuter buildrealms, au cas où.

.
