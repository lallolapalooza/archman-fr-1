BUNDLE-GEM(1) Manuel des commandes générales BUNDLE-GEM(1)

NOM

bundle-gem - Générer un squelette de projet pour la création d'une gem rubygem

SYNTAXE

bundle gem NOM_DE_LA_GEM OPTIONS

DESCRIPTION

Génère un répertoire nommé NOM_DE_LA_GEM avec un Rakefile, un NOM_DE_LA_GEM.gemspec, et d'autres fichiers et répertoires de support qui peuvent être utilisés pour développer une gem rubygem de ce nom.

Exécutez rake -T dans le projet résultant pour obtenir la liste des tâches Rake qui peuvent être utilisées pour tester et publier la gem sur rubygems.org.

Le squelette de projet généré peut être personnalisé avec des OPTIONS, comme expliqué ci-dessous. Notez que ces options peuvent également être spécifiées via le fichier de configuration global de Bundler en utilisant les noms suivants :

  • gem.coc
  • gem.mit
  • gem.test

OPTIONS

--exe, --bin, -b
Spécifie que Bundler doit créer un exécutable binaire (sous la forme exe/NOM_DE_LA_GEM) dans le projet de gem rubygem généré. Cet exécutable sera également ajouté au manifeste NOM_DE_LA_GEM.gemspec. Ce comportement est désactivé par défaut.
--no-exe
Ne pas créer d'exécutable (annule --exe spécifié dans la config globale).
--coc
Ajoute un fichier CODE_OF_CONDUCT.md à la racine du projet généré. Si cette option n'est pas spécifiée, une invite interactive sera affichée et la réponse sera sauvegardée dans la config globale de Bundler pour une utilisation future de bundle gem.
--no-coc
Ne pas créer de fichier CODE_OF_CONDUCT.md (annule --coc spécifié dans la config globale).
--changelog
Ajoute un fichier CHANGELOG.md à la racine du projet généré. Si cette option n'est pas spécifiée, une invite interactive sera affichée et la réponse sera sauvegardée dans la config globale de Bundler pour une utilisation future de bundle gem. Mettez à jour la valeur par défaut avec bundle config set --global gem.changelog <vrai|faux>.
--no-changelog
Ne pas créer de fichier CHANGELOG.md (annule --changelog spécifié dans la config globale).
--ext=c, --ext=rust
Ajoute un code d'initialisation pour les extensions C ou Rust (actuellement basé sur magnus https://docs.rs/magnus) au projet généré. Ce comportement est désactivé par défaut.
--no-ext
Ne pas ajouter de code d'extension (annule --ext spécifié dans la config globale).
--git
Initialiser un dépôt git dans votre bibliothèque.
--github-username=NOM_UTILISATEUR_GITHUB
Remplit le nom d'utilisateur GitHub dans le README afin que vous n'ayez pas à le faire manuellement. Définissez une valeur par défaut avec bundle config set --global gem.github_username <votre_nom_utilisateur>.
--mit
Ajoute une licence MIT dans un fichier LICENSE.txt à la racine du projet généré. Votre nom, issu de la configuration git globale, est utilisé pour la mention de copyright. Si cette option n'est pas spécifiée, une invite interactive sera affichée et la réponse sera sauvegardée dans la config globale de Bundler pour une utilisation future de bundle gem.
--no-mit
Ne pas créer de fichier LICENSE.txt (annule --mit spécifié dans la config globale).
-t, --test=minitest, --test=rspec, --test=test-unit
Spécifie le framework de test que Bundler doit utiliser lors de la génération du projet. Les valeurs acceptables sont minitest, rspec et test-unit. Le fichier NOM_DE_LA_GEM.gemspec sera configuré et un répertoire squelette de tests/spécifications sera créé en fonction de cette option. Si aucune option n'est spécifiée :
Lorsque Bundler est configuré pour générer des tests, la valeur par défaut est le paramètre de configuration global de Bundler gem.test.
Lorsque Bundler est configuré pour ne pas générer de tests, une invite interactive sera affichée et la réponse sera utilisée pour le projet de gem rubygem actuel.
Lorsque Bundler n'est pas configuré, une invite interactive sera affichée et la réponse sera sauvegardée dans la config globale de Bundler pour une utilisation future de bundle gem.
--no-test
Ne pas utiliser de framework de test (annule --test spécifié dans la config globale).
--ci, --ci=circle, --ci=github, --ci=gitlab
Spécifie le service d'intégration continue que Bundler doit utiliser lors de la génération du projet. Les valeurs acceptables sont github, gitlab et circle. Un fichier de configuration sera généré dans le répertoire du projet. Si aucune option n'est spécifiée :
Lorsque Bundler est configuré pour générer des fichiers CI, la valeur par défaut est le paramètre de configuration global de Bundler gem.ci.
Lorsque Bundler est configuré pour ne pas générer de fichiers CI, une invite interactive sera affichée et la réponse sera utilisée pour le projet de gem rubygem actuel.
Lorsque Bundler n'est pas configuré, une invite interactive sera affichée et la réponse sera sauvegardée dans la config globale de Bundler pour une utilisation future de bundle gem.
--no-ci
Ne pas utiliser de service d'intégration continue (annule --ci spécifié dans la config globale).
--linter, --linter=rubocop, --linter=standard
Spécifie le linter et le formateur de code que Bundler doit ajouter aux dépendances de développement du projet. Les valeurs acceptables sont rubocop et standard. Un fichier de configuration sera généré dans le répertoire du projet. Si aucune option n'est spécifiée :
Lorsque Bundler est configuré pour ajouter un linter, la valeur par défaut est le paramètre de configuration global de Bundler gem.linter.
Lorsque Bundler est configuré pour ne pas ajouter de linter, une invite interactive sera affichée et la réponse sera utilisée pour le projet de gem rubygem actuel.
Lorsque Bundler n'est pas configuré, une invite interactive sera affichée et la réponse sera sauvegardée dans la config globale de Bundler pour une utilisation future de bundle gem.
--no-linter
Ne pas ajouter de linter (annule --linter spécifié dans la config globale).
--rubocop
Ajoute rubocop au Rakefile et gemspec générés. Définissez une valeur par défaut avec bundle config set --global gem.rubocop true.
--edit=EDIT, -e=EDIT
Ouvre le fichier NOM_DE_LA_GEM.gemspec résultant dans EDIT, ou dans l'éditeur par défaut s'il n'est pas spécifié. La valeur par défaut est $BUNDLER_EDITOR, $VISUAL, ou $EDITOR.
--bundle
Exécute bundle install après la création de la gem.
--no-bundle
Ne pas exécuter bundle install après la création de la gem.
