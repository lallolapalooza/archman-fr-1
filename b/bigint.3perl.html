DESCRIPTIO

N

Tous les littéraux numériques dans la portée donnée sont convertis en objets Math::BigInt. Les littéraux numériques représentant des non-entiers sont tronqués en entiers. Tous les résultats des expressions sont également tronqués en

entiers.

Tous les opérateurs (y compris les opérations mathématiques de base) sauf l'opérateur de plage ".." sont

surchargés.

Contrairement à la pragma "integer", la pragma "bigint" crée des entiers dont la taille est uniquement limitée par la mémoire

disponible.

Ainsi, ce qui suit

: 
use bigint;
$x =
1234;

crée un Math::BigInt et stocke une référence vers celui-ci dans $x. Cela se produit de manière transparente et en arrière-plan, pour ainsi

dire.

Vous pouvez le voir avec ce qui suit

: 
perl -Mbigint -le 'print ref(1234)
'

Puisque les nombres sont en réalité des objets, vous pouvez appeler toutes les méthodes habituelles de Math::BigFloat sur eux. Cela fonctionne même dans une certaine mesure sur les expressions

: 
perl -Mbigint -le '$x = 1234; print $x->bdec()'
perl -Mbigint -le 'print 1234->copy()->binc();'
perl -Mbigint -le 'print 1234->copy()->binc->badd(6);'
perl -Mbigint -le 'print +(1234)->copy()->binc()
'

(Notez que print ne fait pas ce que vous attendez si l'expression commence par '(' d'où le "+"

)

Vous pouvez même enchaîner les opérations comme d'habitude

: 
perl -Mbigint -le 'print 1234->copy()->binc->badd(6);'
1241

Veuillez noter que ce qui suit ne fonctionne pas comme prévu (n'affiche rien), car la surcharge de '..' n'est pas encore possible dans Perl (jusqu'à la v5.8.0)

: 
perl -Mbigint -le 'for (1..2) { print ref($_); }
'

use integer vs. use

bigint

Il existe certaines différences entre "use integer" et "use bigi

nt".

Alors que "use integer" est limité à ce qui peut être traité comme un scalaire Perl, "use bigint" peut traiter des entiers arbitrairement

grands.

De plus, "use integer" affecte les affectations aux variables et la valeur de retour de certaines fonctions. "use bigint" tronque ces résultats en entiers

: 
# perl -Minteger -wle 'print 3.2'
3.2
# perl -Minteger -wle 'print 3.2 + 0'
3
# perl -Mbigint -wle 'print 3.2'
3
# perl -Mbigint -wle 'print 3.2 + 0'
3
# perl -Mbigint -wle 'print exp(1) + 0'
2
# perl -Mbigint -wle 'print exp(1)'
2
# perl -Minteger -wle 'print exp(1)'
2.71828182845905
# perl -Minteger -wle 'print exp(1) + 0'
2

En pratique, cela fait rarement une différence pour les petits entiers car les parties et les résultats des expressions sont de toute façon tronqués, mais cela peut, par exemple, affecter la valeur de retour des sous-routines

: 
sub three_integer { use integer; return 3.2; }
sub thr
ee_bigint { use bigint; return 3.2; } print three_int
eger(), " ", three_bigint(),"\n"; # affiche "3.2 3"

Bibliothèque

Math

Les calculs avec les nombres sont effectués (par défaut) par un module de bibliothèque de backend appelé Math::BigInt::Calc. La valeur par défaut est équivalente à dire

: 
use bigint lib =>
'Calc';

vous pouvez changer cela en utilisant

: 
use bigint lib =>
'GMP';

Ce qui suit tenterait d'abord de trouver Math::BigInt::Foo, puis Math::BigInt::Bar, et si cela échoue également, reviendrait à Math::BigInt::Calc

: 
use bigint lib => 'Foo,Math::BigInt::
Bar';

L'utilisation de c<lib> avertit si aucune des bibliothèques spécifiées ne peut être trouvée et que Math::BigInt est revenu à l'une des bibliothèques par défaut. Pour supprimer cet avertissement, utilisez plutôt c<try>

: 
use bigint try =>
'GMP';

Si vous voulez que le code meure au lieu de revenir en arrière, utilisez "only" à la place

: 
use bigint only =>
'GMP';

Veuillez consulter la docum

entation respective du modul
e pour plus de détails.

Appels de

méthodes

Puisque tous les nombres sont maintenant des objets, vous pouvez utiliser toutes les méthodes qui font partie de l'API Math::

BigInt.

Mais un avertissement s'impose. Lors de l'utilisation de ce qui suit pour faire une copie d'un nombre, seule une copie superficielle sera

effectuée. 
$x = 9; $y = $x;
$x = $y =
7;

Utiliser la copie ou l'original avec des mathématiques surchargées est acceptable, par exemple, ce qui suit fonctionne

: 
$x = 9; $y = $x;
print $x + 1, " ", $y,"\n";     # affiche 10
9

mais appeler une méthode qui modifie directement le nombre entraînera la destruction à la fois de l'original et de la copie

: 
$x = 9; $y = $x;
print $x->badd(1), " ", $y,"\n";        # affiche 10 10
$x = 9; $y = $x;
print $x->binc(1), " ", $y,"\n";        # affiche 10 10
$x = 9; $y = $x;
print $x->bmul(2), " ", $y,"\n";        # affiche 18
18

L'utilisation de méthodes qui ne modifient pas, mais testent le contenu fonctionne

: 
$x = 9; $y = $x;
$z = 9 if $x->is_zero();                # fonctionne
bien

Voir la documentation concernant le constructeur de copie et "=" dans overload, ainsi que la documentation dans Math::BigInt pour plus de détails.l

AVERTISSEMEN

TS
Littéraux flottants hexadécimaux, octaux et
binaires
Perl (et ce module) accepte les littéraux flottants hexadécimaux, octaux et binaires, mais utilisez-les avec prudence avec les versions de Perl antérieures à v5.32.0, car certaines versions de Perl donnent silencieusement un résultat
incorrect.
Surchargement des opérateurs vs
littéraux
"bigint" fonctionne en surchargeant le traitement des littéraux entiers et flottants, les convertissant en objets Math::BigInt.

Cela signifie que l'arithmétique impliquant uniquement des valeurs chaînes ou des littéraux chaînes est effectuée à l'aide des opérateurs intégrés de

Perl.

Par

exemple : 
use bigint;
my $x = "900000000000000009";
my $y = "900000000000000007";
print $x
- $y;

affiche 0 sur les compilations 32 bits par défaut, car "bigint" ne voit jamais les littéraux chaînes. Pour vous assurer que l'expression est entièrement traitée comme des objets "Math::BigInt", utilisez un littéral numérique dans

l'expression : 
print +(0+$x)
-
$y;

for my $i (12..13) {
  for my $j (20..21) {
    say $i ** $j;  # produit un nombre en virgule flottante,
                   # pas un objet
} }
