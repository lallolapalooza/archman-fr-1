DESCRIPTIO

N

Cette commande trouve les différences (contenu des fichiers, utilisateur/groupe/mode) entre des

archives.

Un emplacement de dépôt et un nom d'archive doivent être spécifiés pour REPO::ARCHIVE1. ARCHIVE2 est simplement un autre nom d'archive dans le même dépôt (aucun emplacement de dépôt n'est autorisé)

.

Ce qui est

comparé

Pour chaque élément correspondant dans les deux archives, Borg rapporte

:
  • Modifications de contenu : octets ajoutés/supprimés au total dans les fichiers. Si les paramètres du chunker sont comparables, Borg compare rapidement les ID de chunks ; sinon, il compare le
    • contenu.
  • Modifications de métadonnées : utilisateur, groupe, mode et autres métadonnées affichées en ligne comme "[ancien_mode -> nouveau_mode]" pour les modifications de mode. Utilisez --content-only pour supprimer les modifications de
    • métadonnées.
  • Éléments ajoutés/sup
    • primés : affichés co
mme "added TAILLE c
hemin" ou "rem
oved TAILLE chemin".

Formats de

sortie

La sortie par défaut (texte) affiche une ligne par chemin modifié, par ex.

: 
+135 B    -252 B [ -rw-r--r-- -> -rwxr-xr-x ] chemin/vers/fich
i
e
r

La sortie JSON Lines (--json-lines) imprime un objet JSON par chemin modifié, par ex.

: 
{"path": "CHEMIN", "changes": [
    {"type": "modified", "added": OCTETS, "removed": OCTETS},
    {"type": "mode", "old_mode": "-rw-r--r--", "new_mode": "-rwxr-xr-x"},
    {"type": "added", "size": TAILLE},
    {"type": "removed", "size": TAILLE}
]
}

Seules les modifications réelles sont incluses d

ans la liste "changes". Par exemple, une entr
ée modifiée avec added=0 et removed=0 est omise.

Tr

i

Utilisez --sort-by CHAMPS où CHAMPS est une liste de champs séparés par des virgules. Les tris sont appliqués de manière stable du dernier au premier dans la liste donnée. Préfixez par ">" pour un ordre décroissant, "<" (ou aucun préfixe) pour un ordre croissant, par exemple --sort-by=">size_added,path". Les champs pris en charge incluent

:
  • path : le chemin de
    • l'élément
  • size_added : octets ajoutés au total pour le contenu de
    • l'élément
  • size_removed : octets supprimés au total pour le contenu de
    • l'élément
  • size_diff : size_added - size_removed (changement net de
    • contenu)
  • size : taille de l'élément tel qu'il est stocké dans ARCHIVE2 (0 pour les éléments
    • supprimés)
  • user, group, uid, gid, ctime, mtime : pris depuis l'état de l'élément dans ARCHIVE2 lorsqu'il est
    • présent
  • ctime_diff, mtime_
    • diff : différence
d'horodatage (ar
chive2 - archive1)

L'option --sort est obsolète et

ne trie que
par chemin.

Considérations de

performance

Pour les archives créées avec Borg 1.1 ou plus récent, diff détecte automatiquement si les archives ont été créées avec les mêmes paramètres de chunker. Si c'est le cas, seuls les ID de chunks sont comparés, ce qui est très

rapide.

Pour les archives antérieures à Borg 1.1, le contenu des chunks est comparé par défaut. Si vous n'avez pas créé les archives avec des paramètres de chunker différents, passez --same-chunker-params. Notez que les paramètres du chunker ont changé de Borg 0.xx à 1.

0.
