SYNOPSI

S

Mettre des données dans un dépôt

bupstash.

bupstash put [OPTIONS] [TAG=VAL...] [::] PATHS...
bupstash put --exec [OPTIONS] [TAG=VAL...] [::] COMMAND

DESCRIPTIO

N

bupstash put chiffre des fichiers, des répertoires ou la sortie d'une commande et les stocke dans un dépôt bupstash de telle sorte que seule la clé de déchiffrement peut les

déchiffrer.

Pour un fichier unique, le contenu est enregistré directement ; pour plusieurs fichiers, les données sont enregistrées de manière à pouvoir être récupérées sous forme d'archive tar, et pour les commandes, la commande est exécutée et stdout est envoyée vers le

dépôt.

Les données stockées dans un dépôt bupstash sont automatiquement dédupliquées de sorte que des instantanés identiques ou similaires occupent un espace disque supplémentaire minimal. Pour un fonctionnement incrémentiel efficace, utilisez l'option --send-log décrite dans la section notes

d'utilisation.

Toutes les opérations put peuvent être associées à un ensemble de balises de métadonnées arbitraires chiffrées, qui peuvent être interrogées à l'aide de bupstash-list(1). Les balises sont spécifiées dans un format simple CLÉ=VALEUR sur la ligne de commande. Les clés de balises valides doivent correspondre à l'expression régulière ^([a-zA-Z0-9\\-_]+)=(.+)$, ce qui signifie que les clés de balises doivent être alphanumériques avec l'ajout de - et _. Le traitement des balises se termine au premier argument qui ne correspond pas au

motif.

Le marqueur spécial :: peut être utilisé pour forcer la fin de l'analyse des balises, mais n'est généralement pas

nécessaire.

Notez que des téléversements multiples et concurrents vers le même dépôt sont sûrs et pris en charge à condition que tous les clients accèdent au dépôt depuis le même serveur et respectent donc les verrous de fichiers du dépôt. Certains systèmes de fichiers réseau (comme NFS et sshfs) ne respectent pas toujours les verrous de fichiers distants et ne sont donc pas pris en charge. Préférez toujours vous connecter à un dépôt distant via une URL de style ssh:// ou une instance de bupstash

s
erve.

NOTES

D'UTILISATION

Put

incrémentiel

Lors de l'envoi de données, bupstash enregistre des métadonnées sur ce qui a été envoyé lors de l'opération ´put´ précédente dans un fichier connu sous le nom de journal d'envoi (send log)

.

Le journal d'envoi sert deux objectifs principaux

:
○
il se souvient des identifiants des morceaux de données qui ont été envoyés au dépôt lors du dernier ´put´, permettant à bupstash d'éviter de renvoyer ces morceaux sur le réseau à plusieurs
reprises.
○
Il stocke une correspondance entre les chemins de fichiers et les données déjà envoyées, permettant à bupstash d'éviter le traitement des fichiers lors de la création d'instantanés du même répertoire de nombreuses fois de
suite.

Le journal d'envoi ne se souvient que des données précédemment envoyées ; pour une utilisation efficace de ´put´, donnez à chaque tâche de sauvegarde un fichier de journal d'envoi unique. Par exemple, si vous avez un script de sauvegarde qui enregistre un répertoire en tant que tâche cron, il est préférable de donner à ce script son propre journal d'envoi afin que toutes les exécutions ultérieures avec des données d'entrée similaires partagent le même journal

d'envoi.

Exemple

:

$ bupstash put --send-log /root/bupstash-backups.sendlog /home/ # La de

uxième sauvegarde est incrémentielle et rapide car elle utilise le journal d
'envoi. $ bupstash put --send-log /root/bupstash-backups.sendlog /home/

Modification concurrente du système de

fichiers

Bupstash prend en charge le téléversement d'un système de fichiers qui est simultanément modifié, avec la réserve que bupstash ne peut pas garantir que le système de fichiers est dans un état cohérent. Si bupstash lit un fichier ou un répertoire alors qu'il est simultanément modifié par une application, il est possible que l'instantané bupstash contienne des données de plusieurs points dans le temps, la combinaison étant potentiellement invalide et/ou

corrompue.

Le seul moyen sûr d'assurer la cohérence des données est d'utiliser un système de fichiers doté de fonctionnalités d'instantané. En utilisant des instantanés de système de fichiers, vous pouvez créer une vue cohérente du système de fichiers puis effectuer une sauvegarde bupstash sur cet instantané. Sur Linux, certaines options pour effectuer des instantanés cohérents incluent ZFS, BTRFS et également les instantanés

LVM

Une autre option consiste à effectuer une opération put à un moment où les fichiers sont moins susceptibles d'être modifiés ; cela fournira des sauvegardes suffisantes pour de nombreuses personnes sans complications

supplémentaires
.

ASTUCE

S
○
bupstash put déduplique et compresse les données automatiquement, évitez donc de mettre des données déjà compressées ou chiffrées si vous souhaitez une déduplication et une compression
optimales.
○
Combinez bupstash serve --allow-put avec des commandes force ssh pour créer des clés ssh restreintes qui ne peuvent que ajouter de nouvelles sauvegardes mais pas lister ou supprimer les
anciennes.
○
La différence entre le fait de rediriger la sortie de la commande tar vers bupstash put, et l'utilisation directe de bupstash put sur un répertoire, est que cette dernière peut utiliser un journal d'envoi et éviter de lire les fichiers déjà envoyés au serveur, et peut créer une liste d'instantanés pour d'autres commandes comme bupstash-list-contents(1)
.

COMMAND est une commande à exécuter, dont stdout est enregistré comme une entrée dans le dépôt bupstash. L'entrée n'est créée que si la commande s'est terminée avec un code de statut de

PATTERN
Ajoute un motif glob d'exclusion pour filtrer les entrées du tarball résultant. Cette option peut être passée plusieurs fois et est ignorée si l'on ne téléverse pas un instantané de répertoire. Le glob est comparé aux chemins absolus et ne doit pas se terminer par un /. Les globs sans / initial ou **/ sont traités comme des correspondances de nom de fichier, c'est-à-dire qu'ils sont automatiquement préfixés par **/. Les règles de globbing habituelles s'appliquent : * correspond à tout sur un niveau, ** correspond à un nombre quelconque de niveaux, ? correspond à un seul caractère, […] correspond à un seul caractère d'un jeu de caractères donné (et peut aussi être utilisé pour échapper les autres caractères spéciaux : [?]

NAME
Compute file metadata and then hash and encrypt data. The put subcommand is used to write files and directories to the repository. It supports incremental backups and deduplication.
OPTIONS

When saving a directory, save it as a directory entry. This is the default behaviour.

DESCRIPTION

The bupstash put command writes the specified FILEs and directories to the bupstash repository. If a FILE is a directory, bupstash will recursively walk the directory and store its contents. If the FILE is a regular file, bupstash will compute its metadata, hash, and encrypt the data before writing it to the repository. Bupstash uses deduplication to reduce storage space by only storing unique chunks of data.

The bupstash put command supports incremental backups using a send log. A send log tracks previously sent files and allows bupstash to only send new or modified files. This is enabled by default when a send log path is configured or specified using the --send-log option.

The --exec option allows snapshotting the output of commands. This is useful for backing up databases or other dynamic data sources.

USAGE NOTES

When using the --exec option, bupstash will execute the specified command and capture its standard output. The output will be saved as a file in the repository with the specified NAME. Ensure that the command produces the desired output and that the NAME is a valid filename.

The --exclude option is useful for excluding specific files or directories from backups. This can be used to exclude cache directories, temporary files, or other non-essential data.

Incremental backups are enabled by default if a send log is configured. To disable incremental backups and force all data to be sent, use the --no-send-log option. This will also disable stat caching.

ENVIRONMENT

BUPSTASH_REPOSITORY
The repository to connect to. May be of the form ssh://$SERVER/$PATH for remote repositories if ssh access is configured.
BUPSTASH_REPOSITORY_COMMAND
A command to run to connect to an instance of bupstash-serve(1). This allows more complex connections to the repository for less common use cases.
BUPSTASH_KEY
Path to the key that will be used to encrypt the data. Only the associated primary key will be able to decrypt the data once sent.
BUPSTASH_KEY_COMMAND
A command to run that must print the key data, can be used instead of BUPSTASH_KEY to fetch the key from arbitrary locations such as the network or other secret storage.
BUPSTASH_SEND_LOG
Path to the send log, overridden by --send-log. See the section ´Incremental backups´ for a description of how to use send logging for efficient incremental uploads.
BUPSTASH_CHECKPOINT_SECONDS
When send logging is enabled, bupstash will checkpoint approximately every BUPSTASH_CHECKPOINT_SECONDS. If an upload is interrupted after a successful checkpoint, data will not need to be resent over the network. The default value of this option is 600, which is 10 minutes.

EXAMPLES

Snapshot a directory

The builtin directory put creates a tarball from a directory, while deduplicating repeated files.

# Snapshot a directory. $ ID="$(bupstash put ./data)" # List snapshot contents. $ bupstash list-contents id="$ID" # Fetch the snapshot. $ bupstash get id="$ID" | tar -xf -

Save files or directory to a repository over ssh

``` export BUPSTASH_KEY="/backups/backups-secret.key" export BUPSTASH_REPOSITORY="ssh://$SERVER/home/me/bupstash-repository"

$ bupstash put ./data.file $ bupstash put ./directory $ bupstash put ./multiple-files.txt ./directory

```

Snapshot the output of a command

# Snapshot a postgres database with pgdump $ bupstash put --exec name=dbdump.sql pgdump mydb

Connecting to an ssh server with a specific ssh config.

$ export BUPSTASH_REPOSITORY_COMMAND="ssh -F ./my-ssh-config me@$SERVER bupstash serve /my/repo" $ bupstash put ./files
