BOUNCE(5) Manuel des formats de fichiers BOUNCE(5)

NOM

bounce - format du modèle de message de rebond de Postfix

SYNOPSIS

bounce_template_file = /etc/postfix/bounce.cf
postconf -b [template_file]

DESCRIPTION


Le serveur bounce(8) de Postfix produit des messages de notification d'état de livraison (DSN) pour le courrier non livrable, le courrier retardé, la livraison réussie ou les requêtes de vérification d'adresse.

Par défaut, ces notifications sont générées à partir de modèles intégrés avec des en-têtes de message et un texte de message. Les sites peuvent remplacer les informations intégrées en spécifiant un fichier de modèle de bounce avec le paramètre de configuration bounce_template_file .

Ce document décrit la procédure générale pour créer un fichier de modèle de bounce, suivie des détails spécifiques des formats de modèle de bounce.

PROCÉDURE GÉNÉRALE

Pour créer un fichier de modèle de bounce personnalisé, créez une copie temporaire du fichier /etc/postfix/bounce.cf.default et modifiez le fichier temporaire.

Pour prévisualiser les résultats des expansions $name dans le texte du modèle, utilisez la commande

    postconf -b temporary_file

Les erreurs dans le modèle seront rapportées au flux d'erreur standard et au démon syslog.

Lors de la prévisualisation du texte, assurez-vous de porter une attention particulière à l'expansion des paramètres de valeur temporelle qui apparaissent dans le texte de notification de courrier retardé.

Une fois le résultat satisfaisant, copiez le modèle dans le répertoire de configuration de Postfix et spécifiez dans main.cf quelque chose comme :

/etc/postfix/main.cf :
    bounce_template_file = /etc/postfix/bounce.cf

FORMAT DU FICHIER MODÈLE

Le fichier de modèle peut spécifier des modèles pour le courrier échoué, le courrier retardé, la livraison réussie ou pour la vérification d'adresse. Ces modèles sont nommés failure_template, delay_template, success_template et verify_template, respectivement. Vous pouvez, mais n'êtes pas obligé de, spécifier les quatre modèles dans un fichier de modèle de bounce.

Chaque modèle commence par "template_name = <<EOF" et se termine par une ligne contenant uniquement le motEOF". Vous pouvez changer le mot EOF, mais vous ne pouvez pas le mettre entre guillemets comme avec le shell ou avec Perl( template_name= <<'EOF'

L'utilisation et la spécification des modèles de bounce sont soumises aux restrictions suivantes :

  • Aucun sens spécial n'est donné au caractère backslash ou aux espaces en début de ligne ; ils sont toujours pris littéralement.
  • Dans le contexte <<, le caractère "$" est spécial. Pour produire un caractère "$" en sortie, spécifiez "$$".
  • En dehors du contexte <<, les lignes commençant par "#" sont ignorées, tout comme les lignes vides et les lignes composées uniquement d'espaces.

Des exemples de tous les modèles peuvent être trouvés dans le fichier bounce.cf.default dans le répertoire de configuration de Postfix.

FORMAT DES EN-TÊTES DU MODÈLE

La première partie d'un modèle de bounce se compose d'en-têtes de modèle facultatifs. Certains deviennent des en-têtes de message dans la notification d'état de livraison ; d'autres contrôlent le formatage de cette notification. Les en-têtes non spécifiés dans un modèle resteront à leur valeur par défaut.

Les en-têtes suivants sont pris en charge :

Charset :
Le jeu de caractères MIME du texte du message du modèle. Voir la description "FORMAT DU TEXTE DU MESSAGE DU MODÈLE" ci-dessous.
From :
L'adresse de l'expéditeur dans l'en-tête de message de la notification d'état de livraison.
Subject :
L'objet dans l'en-tête de message de la notification d'état de livraison qui est retournée à l'expéditeur.
Postmaster-Subject :
L'objet qui sera utilisé dans les copies Postmaster des notifications de courrier non livrable ou retardé. Ces copies sont envoyées sous le contrôle du paramètre de configuration notify_classes.

L'utilisation et la spécification des en-têtes de message du modèle sont soumises aux restrictions suivantes :

  • Les noms des en-têtes de message du modèle peuvent être spécifiés en majuscules, en minuscules ou en casse mixte. Postfix produit toujours des étiquettes d'en-tête de message de bounce sous la forme "From :" et "Subject :".
  • Les en-têtes de message du modèle ne doivent pas s'étendre sur plusieurs lignes.
  • Les en-têtes de message du modèle ne prennent pas en charge les expansions $parameter.
  • Les en-têtes de message du modèle ne doivent contenir que des caractères ASCII et ne doivent pas contenir de caractères nuls ASCII.

FORMAT DU TEXTE DU MESSAGE DU MODÈLE

La deuxième partie d'un modèle de bounce se compose du texte du message. Comme le montre l'exemple ci-dessus, le texte du message du modèle peut contenir des $parameters de main.cf. En plus des paramètres définis dans main.cf, les paramètres suivants sont traités spécifiquement en fonction du suffixe qui est ajouté à leur nom.

delay_warning_time_suffix
S'expande en la valeur du paramètre delay_warning_time , exprimée dans l'unité de temps spécifiée par suffix, qui est l'un de seconds, minutes, hours, days, ou weeks.
maximal_queue_lifetime_suffix
S'expande en la valeur du paramètre maximal_queue_lifetime , exprimée dans l'unité de temps spécifiée par suffix. Voir ci-dessus sous delay_warning_time pour les valeurs possibles de suffix .
mydomain
S'expande en la valeur du paramètre mydomain . Avec "smtputf8_enable = yes", cela remplace les étiquettes ACE (xn--mumble) par leur équivalent UTF-8.

Cette fonctionnalité est disponible dans Postfix 3.0.

myhostname
S'expande en la valeur du paramètre myhostname . Avec "smtputf8_enable = yes", cela remplace les étiquettes ACE (xn--mumble) par leur équivalent UTF-8.

Cette fonctionnalité est disponible dans Postfix 3.0.

L'utilisation et la spécification du texte du message du modèle sont soumises aux restrictions suivantes :

  • Le texte du message du modèle n'est pas envoyé dans les copies Postmaster des notifications d'état de livraison.
  • Si le texte du message du modèle contient des caractères non ASCII, Postfix exige que l'en-tête de modèle Charset : soit mis à jour. Spécifiez un sur-ensemble approprié de US-ASCII. Un sur-ensemble est nécessaire car Postfix ajoute du texte ASCII après le modèle de message lorsqu'il envoie une notification d'état de livraison.
