DESCRIPTIO

N

Ce backend de compilation affiche les OPs internes de l'arbre de syntaxe d'un programme Perl dans l'un de plusieurs formats de texte économiques en espace, adaptés au débogage du fonctionnement interne de perl ou d'autres backends de compilation. Il peut afficher les OPs dans l'ordre où ils apparaissent dans l'arbre OP, dans l'ordre où ils seront exécutés, ou dans une approximation textuelle de leur structure d'arbre, et le format des informations affichées est personnalisable. Sa fonction est similaire à celle du -Dx de débogage de perl ou du module B::Terse, mais il est

plus sophistiqu
é et flexible.

EXEMPL

E

Voici deux sorties (ou « rendus »), utilisant les conventions de mise en forme -exec et -basic (c'est-à-dire par défaut) sur le même extrait de

code. 
   % perl -MO=Concise,-exec -e '$a = $b + 42'
   1  <0> enter
   2  <;> nextstate(main 1 -e:1) v
   3  <#> gvsv[*b] s
   4  <$> const[IV 42] s
*  5  <2> add[t3] sK/2
   6  <#> gvsv[*a] s
   7  <2> sassign vKS/2
   8  <@> leave[1 ref]
vKP/REFC

Dans ce rendu -exec, chaque opcode est exécuté dans l'ordre indiqué. L'opcode add, marqué avec '*', est discuté plus en

détail.

La 1re colonne est le numéro de séquence de l'op, commençant à 1, et est affiché en base 36 par défaut. Ici, ils sont purement linéaires ; les séquences sont très utiles lorsqu'on examine du code avec des boucles et des

branches.

Le symbole entre crochets angulaires indique le type de l'op, par exemple ; <2> est un BINOP, <@> un LISTOP, et <#> est un PADOP, utilisé dans les perls à threads. (voir « OP class abbreviations »)

.

Le nom de l'op, comme dans 'add[t1]', peut être suivi d'informations spécifiques à l'op entre parenthèses ou crochets (ex '[t1]')

.

Les drapeaux de l'op (ex 'sK/2') sont décrits dans ("OP flags abbreviations")

. 
   % perl -MO=Concise -e '$a = $b + 42'
   8  <@> leave[1 ref] vKP/REFC ->(end)
   1     <0> enter ->2
   2     <;> nextstate(main 1 -e:1) v ->3
   7     <2> sassign vKS/2 ->8
*  5        <2> add[t1] sK/2 ->6
   -           <1> ex-rv2sv sK/1 ->4
   3              <$> gvsv(*b) s ->4
   4           <$> const(IV 42) s ->5
   -        <1> ex-rv2sv sKRM*/1 ->7
   6           <$> gvsv(*a) s ->
7

Le rendu par défaut est de haut en bas, donc ils ne sont pas dans l'ordre d'exécution. Cette forme reflète la manière dont la pile est utilisée pour analyser et évaluer les expressions ; l'add opère sur les deux termes situés en dessous de lui dans

l'arbre.

Les Nullops apparaissent comme "ex-opname", où opname est un op qui a été optimisé par perl. Ils sont affichés avec un numéro de séquence de '-', car ils ne sont pas exécutés (ils n'apparaissent pas dans l'exemple précédent), ils sont imprimés ici car ils reflètent l'analyse

syntaxique.

La flèche pointe vers le numéro de séquence de l'op suivant ; ils ne sont pas affichés en mode -exec, pour des raisons

évidentes.

Notez que parce que ce rendu a été fait sur un perl sans threads, les PADOPs des exemples précédents sont maintenan

t des SVOPs, et certains (mais pas tous) des crochets droits ont été remplacés par des parenthèses. Il s'agit d'un
e fonctionnalité subtile pour fournir une distinction visuelle entre les rendus sur des perls avec et sans threads.

OPTION

S

Les arguments qui ne commencent pas par un tiret sont considérés comme les noms de sous-routines ou de formats à rendre ; si aucune de ces fonctions n'est spécifiée, le corps principal du programme (hors de toute sous-routine, et n'incluant pas les fichiers use'd ou require'd) est rendu. Passer "BEGIN", "UNITCHECK", "CHECK", "INIT", ou "END" fera imprimer tous les blocs spéciaux correspondants. Les arguments doivent suivre les

options.

Les options affectent la manière dont les choses sont rendues (c'est-à-dire imprimées). Elles sont présentées ici par leur effet visuel, la 1re étant la plus forte. Elles sont regroupées selon leur interrelation ; au sein de chaque groupe, les options sont mutuellement exclusives (sauf indication contraire)

.

Utiliser B::Concise en dehors du cadre

O

L'utilisation commune (et originale) de B::Concise était pour des rendus en ligne de commande de code simple, comme donné dans EXEMPLE. Mais vous pouvez aussi utiliser B::Concise depuis votre code, et appeler compile() directement, et de manière répétée. Ce faisant, vous pouvez éviter l'opération de compilation uniquement de O.pm, et même utiliser le débogueur pour suivre B::Concise::compile()

lui-même.

add_callback

()

Si vos styles nouvellement créés font référence à de nouvelles #variables, vous devrez définir une sous-routine de rappel qui peuplera (ou modifiera) ces variables. Elles sont ensuite disponibles pour utilisation dans le style que vous avez

Les rappels sont appelés pour chaque opcode visité par Concise, dans le même ordre que celui où ils sont ajoutés. Chaque sous-routine reçoit cinq

2. l'op, en tant qu'objet B<B::OP>
3. une référence à la chaîne de format
4. le niveau de formatage (indentation)
5. le nom de style
sélectionné

Pour définir vos propres variables, ajoutez-les simplement au hash, ou modifiez les valeurs e

Exécuter B::Concise::

compile()

compile accepte les options décrites ci-dessus dans "OPTIONS", et les arguments, qui sont soit des coderefs, soit des noms de

sous-routines.

Il construit et retourne un $treewalker coderef, qui, lorsqu'il est invoqué, traverse, ou parcourt, et rend les optrees des arguments donnés vers STDOUT. Vous pouvez réutiliser cela, et changer le style de rendu utilisé à chaque fois ; ensuite, le coderef rend dans le nouveau

style.

walk_output vous permet de changer la destination d'impression depuis STDOUT vers un autre filehandle ouvert, ou vers une chaîne passée en tant que ref (sauf si vous avez compilé perl avec -Uuseperlio)

. 
my $walker = B::Concise::compile('-terse','aFuncName', \&aSubRef); # 1
walk_output(\my $buf);
$walker->();                          # 1 rend -terse
set_style_standard('concise');        # 2
$walker->();                          # 2 rend -concise
$walker->(@new);                      # 3 rend ce que que
print "3 different renderings: terse, concise, and @new:
$buf\n";

Quand $walker est appelé, il traverse les sous-routines fournies lorsqu'il a été créé, et les rend en utilisant le style actuel. Vous pouvez changer le style ensuite de plusieurs manières différentes

: 
1. appeler C<compile>, en altérant le style ou le mode/l'ordre
2. appeler C<set_style_standard>
3. appeler $walker, en passant les options
@new

Passer de nouvelles options au $walker est la façon la plus simple de basculer parmi n'importe quels styles prédéfinis (ceux que vous ajoutez sont automatiquement reconnus comme options), et c'est la seule façon d'altérer l'ordre de rendu sans rappeler compile. Notez cependant que l'état de rendu est toujours partagé entre plusieurs objets $walker, donc ils doivent touj

ours être utilisés de
manière coordonnée.

Sans la réinitialisation, B::Concise, voyant qu'elles sont séparéesarate optrees, génère
