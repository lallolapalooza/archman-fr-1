NOM

borg-benchmark-crud - Benchmarking des opérations CRUD (Créer, Lire, Mettre à jour, Supprimer) pour les archives.

SYNOPSIS

borg [options communes] benchmark crud [options] REPOSITORIUM CHEMIN

DESCRIPTION

Cette commande effectue des benchmarks des opérations CRUD (créer, lire, mettre à jour, supprimer) de borg.

Elle crée des données d'entrée sous le CHEMIN spécifié et sauvegarde ces données dans le REPOSITORIUM donné. Le REPOSITORIUM doit déjà exister (il peut s'agir d'un dépôt frais et vide ou d'un dépôt existant, la commande créera/lira/mettra à jour/supprimera certaines archives nommées borg-benchmark-crud*). Il faut s'assurer d'avoir suffisamment d'espace libre, environ 1 Go par benchmark (+ surcoût).

Si votre dépôt est chiffré et que borg nécessite un mot de passe pour déverrouiller la clé, utilisez :

BORG_PASSPHRASE=monsecret borg benchmark crud REPO CHEMIN

Les mesures sont effectuées avec différentes tailles et nombres de fichiers d'entrée. Le contenu des fichiers est très artificiel (soit tout zéro, soit aléatoire), par conséquent les résultats des mesures ne reflètent pas nécessairement les performances avec des données réelles. De plus, en raison du type de contenu utilisé, aucune compression n'est utilisée dans ces benchmarks.

C- == borg create (1ère création d'archive, sans compression, n'utilise pas le cache des fichiers)
C-Z- == fichiers tout zéro. Déduplication complète ; cela mesure principalement le lecteur/chunker/hachage. C-R- == fichiers aléatoires. Pas de déduplication, mesure du débit à travers toutes les étapes de traitement.
R- == borg extract (extraction d'archive, simulation, fait tout, mais n'écrit pas les fichiers sur le disque)
R-Z- == fichiers tout zéro. Mesure des fichiers fortement dédupliqués. R-R- == fichiers aléatoires. Aucune déduplication ici, mesure du débit à travers toutes les étapes de traitement, sauf l'écriture sur disque.
U- == borg create (2ème création d'archive avec des fichiers d'entrée inchangés, mesure la vitesse du cache des fichiers)
La valeur de débit est quelque peu virtuelle ici, elle ne lit pas réellement le fichier. U-Z- == doit vérifier l'existence des deux morceaux tout zéro dans le dépôt. U-R- == doit vérifier l'existence d'un grand nombre de morceaux différents dans le dépôt.
D- == borg delete archive (supprime la dernière archive restante, mesure la suppression + la compaction)
D-Z- == peu de morceaux à supprimer / peu de segments à compacter/supprimer. D-R- == beaucoup de morceaux à supprimer / beaucoup de segments à compacter/supprimer.

Veuillez noter qu'il peut y avoir une assez grande variance dans ces mesures. Essayez plusieurs mesures et utilisez une machine autrement inactive (et un réseau, si vous l'utilisez).

OPTIONS

Voir borg-common(1) pour les options communes des commandes Borg.

arguments

REPOSITORIUM
dépôt à utiliser pour le benchmark (doit exister)
CHEMIN
chemin où créer les données d'entrée du benchmark
