--options-file fich
ier
Lit des options supplémentaires à partir du fichier. Chaque option doit apparaître sur une ligne séparée, éventuellement suivie d'un espace ou d'un signe égal (=) et d'une valeur d'option. Les lignes vides et les lignes commençant par # sont ignorées. Les valeurs d'option peuvent être entourées de guillemets doubles (") ou simples (') pour préserver les espaces en début et en fin de chaîne ainsi que pour spécifier des valeurs vides. Si la valeur elle-même contient des guillemets en début ou en fin, entourez-la d'une paire de guillemets supplémentaire, par exemple '"x"'. Les guillemets qui ne sont ni en début ni en fin sont interprétés comme faisant partie de la valeur de l'option.

La sémantique de la fourniture d'options dans un fichier est équivalente à la fourniture du même ensemble d'options dans le même ordre sur la ligne de commande à l'endroit où l'option --options-file est spécifiée, sauf que l'échappement et le guillemetage du shell ne s

ont pas nécessaires. Répétez cette option
pour spécifier plus d'un fichier d'options.

SORTIE

JSON

Les commandes qui prennent en charge la sortie JSON spécifient leurs formats comme une représentation sérialisée d'une struct C++ ou d'un tableau de celles-ci. Par exemple

: 
struct package
{
  string name;
};
struct configuration
{
  uint64_t         id;
  string           path;
  optional<string> name;
  bool             default;
  vector<package>  packages;
}
;

Exemple de représentation JSON sérialisée de struct configurat

ion : 
{
  "id": 1,
  "path": "/tmp/hello-gcc",
  "name": "gcc",
  "default": true,
  "packages": [
    {
      "name": "hello"
    }
  ]
}

Cette section fournit des détails sur les propriétés générales de tels formats et la sémantique de la sérialisation de

struct.

L'ordre des membres dans un objet JSON est fixe, tel que spécifié dans le struct correspondant. Bien que de nouveaux membres puissent être ajoutés à l'avenir (et devraient être ignorés par les consommateurs plus anciens), la sémantique des membres existants (y compris le fait que l'entrée de premier niveau est un objet ou un tableau) ne peut pas

changer.

Un membre d'objet est requis, à moins que son type ne soit optional<>, bool, ou vector<> (tableau). Pour bool, un membre absent signifie false. Pour vector<>, un membre absent signifie vide. Un tableau de premier niveau vide est toujours

présent.

Par exemple, le texte JSON suivant est une sérialisation possible de la configuration struct ci-dess

us : 
{
  "id": 1,
"path": "/tm
p/hello-gcc" }
