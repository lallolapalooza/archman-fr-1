NOM

bfort - programme pour extraire des définitions courtes pour une interface Fortran vers C

ENTRÉE

fichiers
- Noms des fichiers à partir desquels les définitions de lint doivent être extraites
-nomsgs
- Ne pas générer de messages pour les routines qui ne peuvent pas être converties en Fortran.
-nofort
- Générer des messages pour toutes les routines/macros sans leur équivalent Fortran.
-rep nom
- Répertoire pour le fichier de sortie
-I nom
- fichier contenant les includes communs
-mapptr
- traduire les pointeurs en indices entiers
-pref_ptr
- préfixe pour les noms des fonctions pour convertir vers/depuis des pointeurs (par défaut est __). La macro qui sélectionne la forme basée sur la taille du pointeur peut être changée avec -ptr64.
-toutnom
- Générer un seul wrapper Fortran qui fonctionne pour presque tous les systèmes, en ajoutant des noms de préprocesseur C (voir ci-dessous). Ces noms peuvent être changés avec -fcaps, -fuscore, et -fduscore.
-ferr
- Les versions Fortran renvoient la valeur de la routine comme dernier argument (un entier). Ceci est utilisé dans MPI et est une approche courante pour gérer les retours d'erreur.
-nom_arg_court
- Utiliser des noms d'arguments courts (une seule lettre) au lieu du nom dans la définition C.
-fstring
- Activer la gestion des paramètres de caractères Fortran, en utilisant l'interface d'appel la plus courante. Ceci est le comportement par défaut à moins que la variable d'environnement BFORT_STRINGHANDLING ne soit définie sur IGNORE.
-fnostring
- Désactiver la gestion des paramètres de caractères Fortran. Les routines avec des arguments de type char en C n'auront pas de routines d'interface générées pour elles.
-fstring
- tel quel - Aucun traitement spécial pour les arguments de chaîne. Fourni pour la compatibilité descendante avec les versions plus anciennes de bfort qui ne géraient pas les chaînes.
-mpi
- Gérer les types MPI (certaines choses sont des pointeurs par définition)
-no_pmpi
- Ne pas générer de noms PMPI
-pmpi nom
- Changer la macro utilisée pour sélectionner la version de profilage MPI
-sans_profilage
- Désactiver la génération de la version de profilage
-mnative
- Les indirects multiples sont des types de données natifs (pas de coercition)
-voidisptr
- Considérer "void *" comme un pointeur vers une structure.
-nodebug
- Ne pas ajouter 
#ifndef DEBUG_ALL
#define DEBUG_ALL
#endif

au fichier wrapper.

-toutnom
- Générer un seul wrapper qui peut gérer les trois cas les plus courants : underscore final, pas d'underscore, et tout en majuscules. Le choix est basé sur la définition de 
FORTRANCAPS:       Les noms sont en majuscules, pas d'underscore final
FORTRANUNDERSCORE: Les noms sont en minuscules, avec un underscore final
sont définis.
FORTRANDOUBLEUNDERSCORE: Les noms sont en minuscules, avec DEUX underscores

finaux. Ceci est nécessaire lorsque certaines versions de "f2c" sont utilisées pour générer du C pour des routines Fortran. Notez que f2c n'utilise deux underscores que lorsque le nom contient déjà un underscore (du moins sur le système FreeBSD que j'utilise qui utilise f2c). Pour gérer ce cas, le code généré ne contient le deuxième underscore que lorsque le nom en contient déjà un.

Si -mapptr est également choisi, alors

POINTER_64_BITS

sera également utilisé pour déterminer si les pointeurs sont trop longs pour tenir dans un entier Fortran 32 bits. Les routines qui détruisent un pointeur devront insérer manuellement un appel à __RmPointer. Les routines pour gérer les pointeurs se trouvent dans ptrcvt.c

De plus, si -mpi est utilisé et -no_pmpi n'est pas utilisé, les noms de profilage MPI sont également générés, entourés de MPI_BUILD_PROFILING.

NOTE

Nous avons vraiment besoin d'un moyen de spécifier un type général comme pointeur, afin qu'il soit traité comme un pointeur. L'option -mpi est un pis-aller pour un besoin urgent. À terme, il faudrait fournir une option "-ptr nom" et la conserver dans un espace de recherche lors de la recherche de types connus.
