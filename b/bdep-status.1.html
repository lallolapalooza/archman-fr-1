affiche l'état des paquets d'un projet et/ou de leurs dépendances dans une ou plusieurs configurations de compilation. Si aucun répertoire de projet ou de paquet n'est spécifié, le répertoire de travail courant est supposé. Si aucune configuration n'est spécifiée, les configurations par défaut sont supposées. Voirbdep-projects-configs(1)pour des détails sur la spécification des projets et des configurations. Si aucun argument dep-spec n'est spécifié, status
affiche l'état des paquets du projet. Sinon, l'état des paquets de dépendance spécifiés est affiché. De plus, l'état des dépendances immédiates ou de toutes les dépendances des paquets ci-dessus peut être affiché en spécifiant respectivement les options --immediate| -i o

u

--recursive

|

-r .

Dans le format de sortie par défaut (voir l'option commune --stdout-forma

t

), l'état de chaque paquet est affiché sur une ligne séparée. Notez que l'état est écrit sur stdout , et non stderr. La sémantique de dep-spec et le format de la ligne d'état sont décrits dansbpkg-pkg-status(1

)

. Si le format de sortie est json , alors la sortie est un tableau JSON d'objets qui sont la représentation sérialisée du C++ struct configuration_package_status suivan

struct configuration { uint64_t id; string path; optional<string> name; }; struct configuration_package_status { configuration configuration; vector<package_status> packages; }; Par exemple : [ { "configuration": { "id": 1, "path": "/tmp/hello-gcc", "name": "gcc" }, "packages": [ { "name": "hello", "status": "configured", "version": "1.0.0", "hold_package": true, "available_versions": [ { "version": "1.0.1" }, { "version": "2.0.0" } ], "dependencies": [ { "name": "libhello", "status": "configured", "version": "1.0.2" } ] } ] } ] Voir la section JSON

Notez également que dans le format de sortie json certaines conditions (pas de configurations associées, aucun paquet initialisé, etc.) ne sont pas traitées comme des erreurs mais résultent en une sortie valide.
