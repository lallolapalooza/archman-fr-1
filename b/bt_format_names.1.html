NOM

bt_format_names - mise en forme des noms BibTeX pour une sortie cohérente

DESCRIPTION

Après avoir divisé un nom en ses composantes (représentées par une "bt_name" structure), vous voulez souvent le réassembler en une chaîne unique de manière cohérente. btparse fournit une méthode très flexible pour ce faire, généralement en deux étapes : d'abord, vous créez un « format de nom » qui décrit comment réassembler les jetons et les parties de n'importe quel nom, puis vous appliquez ce format à un nom particulier.

Le « format de nom » est encapsulé dans une "bt_name_format" structure, qui est créée avec bt_create_name_format(). Cette fonction inclut une astuce maline qui signifie que vous pouvez généralement vous contenter de l'appeler seule, sans avoir besoin de personnaliser le format. Si vous devez toutefois personnaliser le format, bt_set_format_text() et bt_set_format_options() offrent cette capacité.

Le format contrôle les éléments suivants :

  • quelles parties du nom sont imprimées, et dans quel ordre (par ex. « first von last jr », ou « von last jr first »)
  • le texte qui précède et suit chaque partie (par ex. si le prénom suit le nom de famille, vous voudrez probablement une virgule avant la partie `first' : « Smith, John » plutôt que « Smith John »)
  • le texte qui précède et suit chaque jeton (par ex. si le prénom est abrégé, vous voudrez peut-être un point après chaque jeton : « J. R. Smith » plutôt que « J R Smith »)
  • la méthode utilisée pour joindre les jetons de chaque partie
  • la méthode utilisée pour joindre chaque partie à la partie suivante

Tous ces éléments, sauf la liste des parties à mettre en forme, sont conservés dans des tableaux indexés par partie du nom : par exemple, la structure a un champ

char * post_token[BT_MAX_NAMEPARTS]

et "post_token[BTN_FIRST]" ("BTN_FIRST" provient de "bt_namepart" "enum") est la chaîne à ajouter après chaque jeton dans le prénom---par exemple, "." si le prénom doit être abrégé de la manière conventionnelle.

Encore un autre "enum", "bt_joinmethod", décrit les méthodes disponibles pour joindre les jetons. Notez qu'il y a deux ensembles de méthodes de jonction dans un format de nom : entre les jetons au sein d'une même partie, et entre les jetons de deux parties différentes. La première vous permet, par exemple, de changer "J R Smith" (prénom abrégé sans texte post-jeton mais avec les jetons séparés par un espace) en "JR Smith" (le même, mais avec les jetons du prénom collés ensemble). La seconde sert principalement à s'assurer que les parties du nom « von » et « last » peuvent être jointes par un lien : "de~Roche" plutôt que "de Roche".

Les méthodes de jonction des jetons sont :

BTJ_MAYTIE
Insère un « lien discrétionnaire » entre les jetons. C'est-à-dire, soit un espace, soit un « lien » est inséré, selon le contexte. (Un « lien », aussi connu comme espace insécable, est actuellement codé en dur comme "~"---de TeX.)

Le format est ensuite appliqué à un nom particulier par bt_format_name(), qui retourne une nouvelle chaîne.

BTJ_SPACE
Insère toujours un espace entre les jetons.
BTJ_FORCETIE
Insère toujours un « lien » ("~") entre les jetons.
BTJ_NOTHING
N'insère rien entre les jetons---simplement les colle ensemble.

Les jetons sont joints ensemble, et ainsi le choix d'insérer un « lien discrétionnaire » est fait, à deux endroits : au sein d'une partie et entre deux parties. Naturellement, cela ne s'applique que lorsque "BTJ_MAYTIE" a été fourni comme méthode de jonction des jetons ; "BTJ_SPACE" et "BTJ_FORCETIE" insèrent toujours soit un espace, soit un lien, et "BTJ_NOTHING" n'ajoute toujours rien entre les jetons. Au sein d'une partie, les liens sont ajoutés après le premier jeton s'il fait moins de trois caractères, et avant le dernier jeton. Entre les parties, un lien n'est ajouté que si la partie précédente consistait en un seul jeton de moins de trois caractères. Dans tous les autres cas, des espaces sont insérés. (Cette implémentation suit servilement BibTeX.)

FONCTIONS

bt_create_name_format()
bt_name_format * bt_create_name_format (char * parts,
                                        boolean abbrev_first)

Crée un format de nom pour un ensemble donné de parties, avec des variations pour les formes de personnalisation les plus courantes---l'ordre des parties et la question de savoir s'il faut abréger le prénom.

Le "parts" paramètre spécifie quelles parties inclure dans un nom mis en forme, ainsi que l'ordre dans lequel les mettre en forme. "parts" doit être une chaîne de quatre caractères au maximum, chacun désignant l'une des quatre parties du nom : par exemple, "vljf" signifie mettre en forme les quatre parties dans l'ordre « von last jr first ». Aucun caractère en dehors de l'ensemble "fvlj" n'est autorisé, et aucun caractère ne peut être répété. "abbrev_first" contrôle si la partie `first' sera abrégée (c'est-à-dire, seule la première lettre de chaque jeton sera imprimée).

En plus de simplement définir la liste des parties à mettre en forme et le drapeau « abréger » pour le prénom, bt_create_name_format() initialise toute la structure de format afin de minimiser le besoin de personnalisations supplémentaires :

  • La « méthode de jonction des jetons »---ce qu'il faut insérer entre les jetons de la même partie---est définie à "BTJ_MAYTIE" (lien discrétionnaire) pour toutes les parties
  • La « méthode de jonction des parties »---ce qu'il faut insérer après le jeton final d'une partie particulière, en supposant qu'il reste d'autres parties---est définie à "BTJ_SPACE" pour les parties `first', `last' et `jr'. Si la partie `von' est présente et précède immédiatement la partie `last' (ce qui sera presque toujours le cas), "BTJ_MAYTIE" est utilisé pour joindre `von' à `last' ; sinon, `von' reçoit aussi "BTJ_SPACE" comme méthode de jonction inter-parties.
  • Le drapeau d'abréviation est défini à "FALSE" pour les parties `von', `last' et `jr' ; pour `first', le drapeau d'abréviation est défini à ce que vous passez comme "abbrev_first".
  • Initialement, tout le « texte environnant » (pré-partie, post-partie, pré-jeton et post-jeton) pour toutes les parties est défini à la chaîne vide. Ensuite, quelques ajustements sont faits, dépendant du "abbrev_first" drapeau et de l'ordre des jetons. D'abord, si "abbrev_first" est "TRUE", le texte post-jeton pour le prénom est défini à "."---cela change "J R S bt_format_names(1) — btparse, version 0.91

    NAME

    bt_format_names — formatting name parts

    SYNOPSIS

    #include <btparse.h>

bt_set_format_options (bt_name_format * format,

    DESCRIPTION

    These functions allow you to control the way that names are formatted by bt_format_name(). The library supports a number of pre-defined formats, but you can also customize them.

    The default format supports the following parts:

    • BTN_FIRST: first name(s)
    • BTN_LAST: last name(s)
    • BTN_JR: suffix (Jr., Sr., III, etc.)
    • BTN_MIDDLE: middle name(s)
    • BTN_TITLE: title (Dr., Mr., Mrs., etc.)

    The parts are arranged in the order specified by the string argument to bt_create_name_format(). The string is composed of characters, each of which represents one of the name parts listed above. The default order is "fvlj" (first, last, Jr., middle, title), which is suitable for U.S. style names. Other common orders include "vljf" (last, Jr., first, middle, title).

    The force_abbrev flag in bt_create_name_format() controls whether first names and middle names are abbreviated by default. If TRUE, they will be.

    The default formatting rules attempt to produce sensible output. For instance, an abbreviated first name like "J" will be printed as "J.". A suffix like "Jr" will be printed as ", Jr". These rules are complex, and are controlled by the functions described below.

    bt_create_name_format()
    bt_name_format * bt_create_name_format (char *order, boolean force_abbrev)

    Creates and returns a new name format structure. The order string specifies the order in which name parts should be printed. The force_abbrev flag controls whether first and middle names are abbreviated by default.

    The returned structure should be freed with bt_free_name_format() when it is no longer needed.

    The default formatting rules are as follows:

    • A title, if present, is printed first, followed by a space.
    • First and middle names are abbreviated (unless force_abbrev is false), and printed with a period after each token. The default inter-token join method is "BTJ_SPACE".
    • The last name is printed next.
    • A suffix (like Jr., III, etc.), if present, is printed after the last name, preceded by a comma and a space.
    • The default joining method between parts is "BTJ_SPACE".

    The following examples illustrate how the default rules work, and how they can be overridden.

    Given the name "John Fitzgerald Kennedy Jr.", and the default format "fvlj":

    • The first name part (BTN_FIRST) is "John Fitzgerald". Since force_abbrev is true, this becomes "J. F.".
    • The last name part (BTN_LAST) is "Kennedy".
    • The Jr. part (BTN_JR) is "Jr". This is printed as ", Jr".

    The result is "J. F. Kennedy, Jr.".

    Now consider the name "Winston S. Churchill". If the format is "fv" (first, last):

    • First name: "Winston S."
    • Last name: "Churchill"

    Result: "Winston S. Churchill".

    What if you want the suffix "Jr" to be printed without a preceding comma, as in "John Smith Jr" rather than "John Smith, Jr"? You can achieve this using bt_set_format_text() and bt_set_format_options(). The trick is to associate the comma with the BTN_JR part, rather than with the BTN_LAST part.

    Start by creating the format:

        bt_name_format *format;
    format = bt_create_name_format ("fvlj", TRUE);

    By default, the BTN_LAST part will have "BTJ_SPACE" as its inter-part join method. This means that a space will be printed after the last name. We want to change that to "BTJ_NOTHING", and associate the ", " text with the BTN_JR part.

    • First, change the inter-token join method for the last name part to "BTJ_NOTHING". This ensures that no space is printed between the last name and the suffix, assuming the suffix is associated with the last name part. (We'll fix this association later.) We also need to tell bt_set_format_options() what the values are for the other arguments, even if we don't want to change them. We assume that the default abbreviation flag for last names is FALSE, and the default post-token join method is "BTJ_SPACE" (a space after the last name).
        bt_set_format_options (format, BTN_LAST,
                           FALSE,        /* abbrev flag */
                           BTJ_NOTHING,  /* join tokens within part */
                           BTJ_SPACE);   /* join part to next part */

    Now, set the pre-part text for the BTN_JR part to ", ". This will automatically cause the post-token text for the BTN_LAST part to be changed from " " to "", and the inter-part join method for BTN_LAST to be changed from "BTJ_SPACE" to "BTJ_NOTHING".

        bt_set_format_text (format, BTN_JR, ", ", NULL, NULL, NULL);

    This changes "John Smith" to "John Smith". Then, when the BTN_JR part is processed, ", Jr" is appended, resulting in "John Smith, Jr".

    A similar trick can be used to control the punctuation after abbreviated first names. By default, abbreviated first names (like "J") are printed with a period, e.g., "J.". If you don't want the periods, you can use bt_set_format_text() to set the post-token text for the BTN_FIRST part to an empty string:

        bt_set_format_text (format, BTN_FIRST, NULL, NULL, NULL, "");

    This changes "John R. Smith" (where "R." comes from the default formatting of the middle name part) to "John R Smith".

    If you want to modify the formatting of the Jr. part even further, you might want to print it like "J. R. Smith". To do this, you'd use bt_set_format_text() to set the post-token text for the BTN_JR part to " mith" to "J. R. Smith", which is usually the desired form. (If you don't want the periods, you'll have to set the post-token text yourself with bt_set_format_text().)

    Then, if `jr' is present and immediately after `last' (almost always the case), the pre-part text for `jr' is set to ", ", and the inter-part join method for `last' is set to "BTJ_NOTHING". This changes "John Smith Jr" (where the space following "Smith" comes from formatting the last name with a "BTJ_SPACE" inter-part join method) to "John Smith, Jr" (where the ", " is now associated with "Jr"---that way, if there is no `jr' part, the ", " will not be printed.)

    Finally, if `first' is present and immediately follows either `jr' or `last' (which will usually be the case in "last-name first" formats), the same sort of trickery is applied: the pre-part text for `first' is set to ", ", and the part join method for the preceding part (either `jr' or `last') is set to "BTJ_NOTHING".

    While all these rules are rather complicated, they mean that you are usually freed from having to do any customization of the name format. Certainly this is the case if you only need "fvlj" and "vljf" part orders, only want to abbreviate the first name, want periods after abbreviated tokens, non-breaking spaces in the "right" places, and commas in the conventional places.

    If you want something out of the ordinary---for instance, abbreviated tokens jammed together with no puncuation, or abbreviated last names---you'll need to customize the name format a bit with bt_set_format_text() and bt_set_format_options().

    bt_free_name_format()
    void bt_free_name_format (bt_name_format * format)

    Frees a name format created by bt_create_name_format().

    bt_set_format_text()
    void bt_set_format_text (bt_name_format * format, 
                         bt_namepart part,
                         char * pre_part,
                         char * post_part,
                         char * pre_token,
                         char * post_token)

    Allows you to customize some or all of the surrounding text for a single name part. Supply "NULL" for any chunk of text that you don't want to change.

    For instance, say you want a name format that will abbreviate first names, but without any punctuation after the abbreviated tokens. You could create and customize the format as follows:

    format = bt_create_name_format ("fvlj", TRUE);
bt_set_format_text (format, 
                    BTN_FIRST,       /* name-part to customize */
                    NULL, NULL,      /* pre- and post- part text */
                    NULL, "");       /* empty string for post-token */

    Without the bt_set_format_text() call, "format" would result in names formatted like "J. R. Smith". After setting the post-token text for first names to "", this name would become "J R Smith".

    bt_set_format_options()
    void bt_set_format_options (bt_name_format * format, 
                            bt_namepart part,
                            boolean abbrev,
                            bt_joinmethod join_tokens,
                            bt_joinmethod join_part)

    Allows further customization of a name format: you can set the abbreviation flag and the two token-join methods. Alas, there is no mechanism for leaving a value unchanged; you must set everything with bt_set_format_options().

    For example, let's say that just dropping periods from abbreviated tokens in the first name isn't enough; you really want to save space by jamming the abbreviated tokens together: "JR Smith" rather than "J R Smith" Assuming the two calls in the above example have been done, the following will finish the job:

    bt_set_format_options (format, BTN_FIRST,
                       TRUE,         /* keep same value for abbrev flag */
                       BTJ_NOTHING,  /* jam tokens together */
                       BTJ_SPACE);   /* space after final token of part */

    Note that we unfortunately had to know (and supply) the current values for the abbreviation flag and post-part join method, even though we were only setting the intra-part join method.

    bt_format_name()
    char * bt_format_name (bt_name * name, bt_name_format * format)

    Once a name format has been created and customized to your heart's content, you can use it to format any number of names that have been split with "bt_split_name" (see bt_split_names). Simply pass the name structure and name format structure, and a newly-allocated string containing the formatted name will be returned to you. It is your responsibility to free() this string.
