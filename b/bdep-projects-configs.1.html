NOM

bdep-projects-configs - spécification des projets et des configurations

SYNOPSIS

bdep commande [spéc-paquet] [spéc-config] ...

spéc-config = (@nom-cfg | --config|-c rép-cfg)... | --all|-a
spéc-paquet = (--directory|-d rép-paquet)... | spéc-projet
spéc-projet = --directory|-d rép-projet

DESCRIPTION

La plupart des commandes bdep opèrent sur un projet ou sur certains de ses paquets ainsi que sur ses configurations de construction. Par exemple, status (bdep-status(1)) affiche l'état d'un ou plusieurs paquets du projet dans une ou plusieurs configurations de construction. Tandis que fetch (bdep-fetch(1)) récupère la liste des paquets de dépendance disponibles pour le projet, à nouveau, dans une ou plusieurs configurations de construction.

Sans aucune option --directory|-d spécifiée, le répertoire de travail courant est supposé être soit le répertoire racine du projet, soit le répertoire racine d'un paquet, soit l'un des sous-répertoires d'un paquet. C'est le mode d'utilisation courant de bdep où vous l'exécutez depuis les répertoires de code source de votre projet, similaire aux outils de contrôle de version tels que git(1).

Alternativement, le projet ou (plusieurs) répertoires de paquets peuvent être spécifiés avec les options --directory|-d. Notez que bdep opère sur un seul projet mais potentiellement sur plusieurs paquets appartenant audit projet à la fois.

Certaines commandes bdep, comme fetch, opèrent sur le projet entier. Si une telle commande reçoit un répertoire de paquet (soit comme répertoire de travail, soit avec --directory|-d), alors elle détermine automatiquement son répertoire de projet et l'utilise.

D'autres commandes, comme status, opèrent sur un ou plusieurs paquets. Si une telle commande reçoit un répertoire de projet, alors elle détermine automatiquement la liste des paquets appartenant à ce projet et l'utilise. Notez que ce que signifie exactement *appartenir* est spécifique à la commande. Pour la plupart des commandes, cela signifie tous les paquets initialisés dans une configuration de construction donnée. Pour init (bdep-init(1)), cependant, cela signifie tous les paquets disponibles dans le projet (par exemple, tels que listés dans packages.manifest).

Un projet géré par bdep a une ou plusieurs configurations de construction associées (voir bdep-config(1) pour les détails). Certaines de ces configurations, une par type de configuration, peuvent être désignées comme par défaut et utilisées si aucune configuration n'est spécifiée explicitement. Ainsi, par exemple, exécuter status sans arguments dans le répertoire du projet affichera l'état de tous les paquets du projet initialisés dans les configurations par défaut.

Une configuration de construction associée peut se voir attribuer un nom, auquel cas nous pouvons la spécifier en utilisant la notation @nom-cfg. Par exemple :

$ bdep status @gcc @clang

Note aux utilisateurs de Windows : un argument de ligne de commande commençant par @ a une signification spéciale dans PowerShell. Pour contourner cela, vous pouvez utiliser la syntaxe alternative -@gcc ou l'option -n gcc.

Une configuration sans nom peut être spécifiée comme répertoire en utilisant l'option --config|-c. Les spécifications de nom et de répertoire peuvent être mélangées. Par exemple :

$ bdep status @gcc -c ../builds/clang

Enfin, nous pouvons utiliser l'option --all|-a pour spécifier toutes les configurations de construction associées au projet.
