NOM

barrier - synchronise l'exécution de multiples invocations de shader

DÉCLARATION

void barrier(void);

DESCRIPTION

Disponible uniquement dans les Shaders de contrôle de tessellation et les Shaders de calcul, barrier fournit un ordre d'exécution partiellement défini entre les invocations de shader. Pour toute instance statique donnée de barrier, dans un shader de contrôle de tessellation, toutes les invocations pour une seule primitive d'entrée doivent y entrer avant que l'une d'elles soit autorisée à continuer au-delà. Pour toute instance statique donnée de barrier dans un shader de calcul, toutes les invocations au sein d'un même groupe de travail doivent y entrer avant que l'une d'elles soit autorisée à continuer au-delà. Cela garantit que les valeurs écrites par une invocation avant une instance statique donnée de barrier peuvent être lues en toute sécurité par d'autres invocations après leur appel à la même instance statique de barrier. Comme les invocations peuvent s'exécuter dans un ordre indéfini entre ces appels à barrier, les valeurs d'une variable de sortie par sommet ou par primitive, ou toute variable partagée seront indéfinies dans un certain nombre de cas.

barrier ne peut être placé qu'à l'intérieur de la fonction main() du shader de contrôle de tessellation, mais peut être placé n'importe où dans un shader de calcul. Les appels à barrier ne peuvent pas être placés dans un flux de contrôle. Les barrières sont également interdites après une instruction return dans la fonction main().
