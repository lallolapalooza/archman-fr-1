NOM

binfmt.d - Configurer des formats binaires supplémentaires pour les exécutables au démarrage

SYNTAXE

/etc/binfmt.d/*.conf
/run/binfmt.d/*.conf
/usr/local/lib/binfmt.d/*.conf
/usr/lib/binfmt.d/*.conf

DESCRIPTION

Au démarrage, systemd-binfmt.service(8) lit les fichiers de configuration provenant des répertoires ci-dessus pour enregistrer dans le noyau des formats binaires supplémentaires pour les exécutables.

FORMAT DE CONFIGURATION

Chaque fichier contient une liste de règles de format binaire binfmt_misc du noyau. Consultez la documentation du noyau Kernel Support for miscellaneous Binary Formats (binfmt_misc)[1] pour plus d'informations sur l'enregistrement de formats binaires supplémentaires et la rédaction des règles.

Les lignes vides et les lignes commençant par ";" et "#" sont ignorées. Notez que cela signifie que vous ne pouvez pas utiliser ces symboles comme délimiteurs dans les règles de format binaire.

RÉPERTOIRES DE CONFIGURATION ET PRÉÉDENCE

Les fichiers de configuration sont lus à partir des répertoires /etc/, /run/, /usr/local/lib/, et /usr/lib/, dans l'ordre de précédence, tel qu'indiqué dans la section SYNTAXE ci-dessus. Les fichiers doivent avoir l'extension ".conf". Les fichiers dans /etc/ remplacent les fichiers portant le même nom dans /run/, /usr/local/lib/, et /usr/lib/. Les fichiers dans /run/ remplacent les fichiers portant le même nom sous /usr/.

Tous les fichiers de configuration sont triés par leur nom de fichier dans l'ordre lexicographique, quel que soit le répertoire dans lequel ils résident. Si plusieurs fichiers spécifient la même option, l'entrée dans le fichier portant le nom le plus tardif lexicographiquement prendra le dessus. Ainsi, la configuration dans un certain fichier peut soit être complètement remplacée (en plaçant un fichier portant le même nom dans un répertoire de priorité supérieure), soit les paramètres individuels peuvent être modifiés (en spécifiant des paramètres supplémentaires dans un fichier portant un nom différent et ordonné plus tard).

Les paquets doivent installer leurs fichiers de configuration dans /usr/lib/ (paquets de distribution) ou /usr/local/lib/ (installations locales) [2]. Les fichiers dans /etc/ sont réservés à l'administrateur local, qui peut utiliser cette logique pour remplacer les fichiers de configuration installés par les paquets du fournisseur.

Il est recommandé de préfixer tous les noms de fichiers par un chiffre à deux chiffres et un tiret pour simplifier l'ordre. Il est recommandé d'utiliser la plage 10-40 pour les fichiers de configuration dans /usr/ et la plage 60-90 pour les fichiers de configuration dans /etc/ et /run/, afin de s'assurer que les fichiers de configuration locaux et transitoires auront toujours la priorité sur les fichiers de configuration fournis par le vendeur de l'OS.

Si l'administrateur souhaite désactiver un fichier de configuration fourni par le vendeur, la méthode recommandée est de placer un lien symbolique vers /dev/null dans le répertoire de configuration de /etc/, avec le même nom de fichier que le fichier de configuration du vendeur. Si le fichier de configuration du vendeur est inclus dans l'image initrd, l'image doit être régénérée.

EXEMPLE

Exemple 1. Exemple de /etc/binfmt.d/wine.conf :

# Démarre WINE sur les exécutables Windows
:DOSWin:M::MZ::/usr/bin/wine:
