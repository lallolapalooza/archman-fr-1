NOM

bup-midx - créer un fichier multi-index (.midx) à partir de plusieurs fichiers .idx

SYNTAXE

bup midx [-o fichier_sortie] <-a|-f|noms_idx...>

DESCRIPTION

bup midx crée un fichier multi-index (.midx) à partir d'un ou plusieurs fichiers d'index de pack git (.idx).

Remarque : vous ne devriez plus avoir besoin d'exécuter cette commande manuellement. Elle est exécutée automatiquement par bup-save(1) et des commandes similaires.

OPTIONS

-o, --output=nom_fichier.midx
utiliser le nom de fichier de sortie donné pour le fichier .midx. Par défaut, il est généré automatiquement.
-a, --auto
générer automatiquement de nouveaux fichiers .midx pour tous les fichiers .idx pour lesquels cela est approprié.
-f, --force
forcer la génération d'un nouveau fichier .midx unique contenant tous vos fichiers .idx, même si d'autres fichiers .midx existent déjà. Cela résultera en des performances de sauvegarde les plus rapides, mais peut prendre beaucoup de temps.
--dir=rép_pack
spécifier le répertoire contenant les fichiers .idx/.midx avec lesquels travailler. Le répertoire par défaut est $BUP_DIR/objects/pack.
--max-files
nombre maximum de fichiers .idx à ouvrir simultanément. Vous pouvez l'utiliser si vous avez un nombre particulièrement faible de descripteurs de fichiers disponibles, afin que midx puisse se terminer (bien que potentiellement de manière sous-optimale) même s'il ne peut pas ouvrir tous vos fichiers .idx en même temps. La valeur par défaut de cette option devrait convenir à la plupart des utilisateurs.
--check
valider un fichier .midx en s'assurant que tous les objets de ses fichiers .idx contenus existent dans le .midx. Peut être utile pour le débogage.

EXEMPLES

$ bup midx -a
Fusion de 21 index (2278559 objets).
Taille de la table : 524288 (17 bits)
Lecture des index : 100.00% (2278559/2278559), terminé.
midx-b66d7c9afc4396187218f2936a87b865cf342672.midx

DISCUSSION

Par défaut, bup utilise des fichiers de pack au format git, qui se composent d'un fichier de pack (contenant les objets) et d'un fichier idx (contenant une liste triée des noms d'objets et de leurs offsets dans le fichier .pack).

Les fichiers idx normaux sont pratiques car ils permettent d'utiliser git(1) pour accéder à vos jeux de données de sauvegarde. Cependant, les fichiers idx peuvent devenir lents lorsque vous avez un grand nombre de très gros packs (ce que git n'a généralement pas, mais bup a souvent).

Les fichiers .midx de bup consistent en une liste triée unique de tous les objets contenus dans tous les fichiers .pack auxquels il fait référence. Cette liste peut être recherchée par recherche binaire en environ log2(m) étapes, où m est le nombre total d'objets.

Pour accélérer davantage la recherche, les fichiers midx ont également une table de ventilation de taille variable qui réduit les n premières étapes de la recherche binaire. Avec l'aide de cette table de ventilation, bup peut déterminer dans quelle page du fichier midx un identifiant d'objet donné se trouverait (s'il existe) avec une seule consultation. Ainsi, les recherches typiques n'auront besoin d'échanger que deux pages : une pour la table de ventilation et une pour l'identifiant de l'objet.

Les fichiers midx sont les plus utiles lors de la création de nouvelles sauvegardes, car la recherche d'un objet inexistant dans le référentiel nécessite nécessairement de parcourir tous les fichiers d'index pour s'assurer qu'il n'existe pas. (La recherche d'objets qui existent peut être optimisée ; par exemple, les objets consécutifs sont souvent stockés dans le même pack, nous pouvons donc rechercher celui-ci en premier en utilisant un algorithme MRU.)
