BCOMPS(1) Manuel des commandes générales BCOMPS(1)

NOM

bcomps - filtre de composantes biconnectées pour les graphes

SYNTAXE

bcomps [ -stvx? ] [ -ofichier_sortie ] [ fichiers ]

DESCRIPTION

bcomps décompose les graphes en leurs composantes biconnectées, imprimant les composantes sur la sortie standard.

OPTIONS

Les options suivantes sont supportées :

-s
Aucun graphe de sortie n'est imprimé. Implique l'option -v.
-t
Imprime l'arbre blocs-articulations sous-jacent.
-x
Chaque composante biconnectée est imprimée comme un graphe racine distinct.
-v
Imprime le nombre de blocs et d'articulations.
-o fichier_sortie
Si spécifié, chaque graphe racine sera écrit dans un fichier différent avec des noms dérivés de fichier_sortie. En particulier, si les options -o et -x sont utilisées, alors chaque bloc est écrit dans un fichier différent. Si fichier_sortie n'a pas de suffixe, le nième bloc du ième graphe est écrit dans fichier_sortie_n_i. Cependant, le 0ème bloc du 0ème graphe est écrit dans fichier_sortie.

Si fichier_sortie a un suffixe, c'est-à-dire a la forme base.sfx, alors les fichiers auront le même nom que ci-dessus, sauf avec l'ajout de .sfx.

L'arbre blocs-articulations du ième graphe est écrit dans fichier_sortie_n_T, avec un suffixe ajouté si spécifié.

Par défaut, chaque graphe d'entrée est imprimé, chaque bloc étant donné comme un sous-graphe dont le nom est une concaténation du nom du graphe d'entrée, de la chaîne "_bcc_" et du numéro du bloc.

OPÉRANDES

L'opérande suivant est supporté :

fichiers
Noms des fichiers contenant 1 ou plusieurs graphes au format dot. Si aucun opérande fichiers n'est spécifié, l'entrée standard sera utilisée.

CODES DE RETOUR

bcomps retourne 0 si tous les graphes d'entrée sont biconnectés ; et non-zéro si un graphe a plusieurs blocs, ou si une erreur s'est produite.

BOGUES

Il est possible, bien qu'improbable, que les noms utilisés pour les composantes connexes et leurs sous-graphes entrent en conflit avec des noms de sous-graphes existants.
