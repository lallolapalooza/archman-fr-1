NOM

buffchan - Mécanisme d'écriture tamponnée de fichiers pour INN

SYNOPSIS

buffchan [-bru] [-c lignes] [-C secondes] [-d répertoire] [-f nb-champs] [-l lignes] [-L secondes] [-m table] [-p fichier-pid] [-s format]

DESCRIPTION

buffchan lit des lignes depuis l'entrée standard et copie les champs initiaux de chaque ligne vers les fichiers nommés par les champs restants de la ligne. buffchan est destiné à être appelé par innd en tant que flux explodeur.

L'entrée est interprétée comme une séquence de lignes. Chaque ligne contient un nombre fixe de champs initiaux, suivis d'un nombre variable de champs de nom de fichier. Tous les champs d'une ligne sont séparés par des espaces et ne contiennent aucun espace. Le nombre par défaut de champs initiaux est un.

Pour chaque ligne d'entrée, buffchan écrit les champs initiaux, séparés par un espace et suivis d'un retour à la ligne, vers chacun des fichiers nommés dans les champs de nom de fichier. Les fichiers de sortie restent ouverts et ne sont vidés ou fermés que selon la planification donnée par les -c, -C, -let -L options.

En tant que flux explodeur (voir newsfeeds(5) pour une explication), buffchan interprète les lignes commençant par un point d'exclamation comme des commandes. En plus de "!begin" (qui ne fait que marquer le début du flux), trois commandes sont prises en charge :

!flush [site]
La commande flush ferme et rouvre tous les fichiers ouverts. Un site optionnel peut être spécifié, auquel cas buffchan ne vide que ce fichier. Cette commande est analogue à la "ctlinnd flush" commande. Cette commande peut être envoyée via innd en utilisant "ctlinnd send buffchan-site 'flush site'".

Les applications peuvent savoir que le flush est terminé en renommant le fichier avant d'émettre la commande. Lorsque le nom de fichier d'origine réapparaît, le flush est terminé. Si fchmod(3) est disponible, buffchan change également le fichier en lecture seule pendant qu'il écrit activement dessus et le remet en lecture/écriture une fois fermé. Il ne remettra le mode en lecture seule que s'il rouvre le même fichier.

!drop [site]
La commande drop est similaire à la commande flush, sauf qu'aucun fichier n'est rouvert. Si un argument est donné, seul le site spécifié est abandonné ; sinon, tous les sites sont abandonnés. (Notez qu'un site sera redémarré si le flux d'entrée mentionne à nouveau le site.)

Lorsqu'une "ctlinnd drop site" commande est envoyée, innd transmettra automatiquement la commande à buffchan si le site est listé comme un entonnoir alimentant l'explodeur buffchan . Pour abandonner tous les sites, utilisez "ctlinnd send buffchan-site drop".

!readmap
Le fichier de table spécifié avec l'option -m , si fourni, sera rechargé.

Une fois buffchan ouvre un fichier, il le garde ouvert (en l'absence d'une commande drop). L'entrée ne doit donc jamais spécifier plus de fichiers que le nombre maximal de fichiers qu'un processus peut ouvrir.

OPTIONS

-b
Force la sortie à être tamponnée. (C'est généralement le comportement par défaut, mais cela peut dépendre du système d'exploitation.) Si -b est donné, une taille de tampon de BUFSIZ (une constante de la bibliothèque d'E/S standard du système) est utilisée.
-c lignes
Si l'indicateur -c est donné, buffchan fermera et rouvrira un fichier après que lignes lignes ont été écrites dans le fichier.
-C secondes
Si l'indicateur -C est donné, buffchan fermera et rouvrira un fichier s'il a été ouvert pendant plus de secondes secondes.
-d répertoire
Par défaut, buffchan écrit sa sortie dans le répertoire pathoutgoing . Cet indicateur peut être utilisé pour spécifier un répertoire vers lequel le programme doit se rendre avant de démarrer. Si cet indicateur est utilisé, la valeur par défaut de l'indicateur -s (voir ci-dessous) est modifiée pour être un simple %s (en d'autres termes, les fichiers de sortie sont considérés comme relatifs au répertoire).
-f nb-champs
Par défaut, chaque ligne est censée contenir un champ fixe suivi de plusieurs champs de nom de fichier. Si cet indicateur est donné, nb-champs sera utilisé comme nombre de champs fixes initiaux.
-l lignes
Si l'indicateur -l est donné, buffchan videra la sortie après que lignes lignes ont été écrites dans un fichier.
-L secondes
Si l'indicateur -L est donné, buffchan videra chaque fichier de sortie toutes les secondes secondes.
-m table
Les fichiers de table traduisent les noms dans les champs de nom de fichier de chaque ligne en noms de fichiers qui devraient être utilisés à la place. Il est utilisé principalement lorsque des noms courts sont utilisés dans newsfeeds, mais que les fichiers de sortie devraient utiliser les noms de domaine complets des pairs distants.

Dans le fichier de table, les lignes vides et les lignes commençant par un signe dièse ("#") sont ignorées. Toutes les autres lignes doivent avoir deux noms d'hôte séparés par deux-points. Le premier champ est le nom qui peut apparaître dans le flux d'entrée ; le second champ nomme le fichier à utiliser lorsque le nom du premier champ apparaît.

Par exemple, le fichier de table suivant peut être utilisé pour faire correspondre les noms courts utilisés dans l'exemple ci-dessous aux noms de domaine complets :

# Ceci est un commentaire
uunet:news.uu.net
foo:foo.com
munnari:munnari.oz.au
-p fichier-pid
Si l'option -p est donnée, buffchan écrira une ligne contenant son ID de processus (en texte) dans le fichier spécifié lorsqu'il démarre.
-r
Par défaut, buffchan envoie ses messages d'erreur vers pathlog/errlog. Pour supprimer cette redirection et envoyer les messages d'erreur vers la sortie d'erreur standard, utilisez l'indicateur -r .
-s
L'indicateur -s peut être utilisé pour spécifier un format qui fait correspondre un nom de fichier des champs de nom de fichier à la fin de chaque ligne à un nom de fichier réel. Il s'agit d'une chaîne de format sprintf(3) qui doit contenir une seule instance de %s, qui sera remplacée par la valeur du champ de nom de fichier (éventuellement après correspondance avec le fichier de table de -m). La valeur par défaut est pathoutgoing/%s.
-u
Si l'indicateur -u est utilisé, la sortie sera non tamponnée.

EXEMPLES

Si buffchan est invoqué avec "-f 2" et reçoit l'entrée suivante :

news.software.nntp <1643@munnari.oz.au> foo uunet
news.software.nntp <102060@litchi.foo.com> uunet munnari
comp.sources.unix <999@news.foo.com> foo uunet munnari

alors le fichier foo dans pathoutgoing contiendra ces lignes :

news.software.nntp <1643@munnari.oz.au>
comp.sources.unix <999@news.foo.com>

le fichier munnari dans pathoutgoing contiendra ces lignes :

news.software.nntp <102060@litchi.foo.com>
comp.sources.unix <999@news.foo.com>

et le fichier uunet dans pathoutgoing contiendra ces lignes :

news.software.nntp <1643@munnari.oz.au>
news.software.nntp <102060@litchi.foo.com>
comp.sources.unix <999@news.foo.com>

Utiliser buffchan de cette manière peut être fait dans newsfeeds avec par exemple :

foo:*,@misc.*:Ap,Tm:buffchan!
munnari:*,@rec.*:Ap,Tm:buffchan!
uunet:*:Ap,Tm:buffchan!
buffchan!:*:Tx,WGm*:<pathbin>/buffchan -f 2

Cela générera les exemples ci-dessus. Voir la &quot;W" drapeau dans newsfeeds(5) pour savoir comment paramétrer la sortie.
