NOM

borg-compression - Détails sur la compression

DESCRIPTION

Il n'y a pas de problème à mélanger différentes méthodes de compression dans un même dépôt, la déduplication se fait sur les blocs de données sources (pas sur les données compressées ou chiffrées).

Si un bloc spécifique a été une fois compressé et stocké dans le dépôt, la création d'une autre sauvegarde qui utilise également ce bloc ne modifiera pas le bloc stocké. Donc si vous utilisez des spécifications de compression différentes pour les sauvegardes, celui qui stocke un bloc en premier détermine sa compression. Voir aussi borg recreate.

La compression est lz4 par défaut. Si vous voulez autre chose, vous devez spécifier ce que vous voulez.

Les spécificateurs de compression valides sont :

none
Ne pas compresser.
lz4
Utiliser la compression lz4. Très haute vitesse, très faible compression. (défaut)
zstd[,N]
Utiliser la compression zstd (« zstandard »), un algorithme moderne à large plage. Si vous ne donnez pas explicitement le niveau de compression N (allant de 1 à 22), il utilisera le niveau 3. Les archives compressées avec zstd ne sont pas compatibles avec borg < 1.1.4.
zlib[,N]
Utiliser la compression zlib (« gz »). Vitesse moyenne, compression moyenne. Si vous ne donnez pas explicitement le niveau de compression N (allant de 0 à 9), il utilisera le niveau 6. Donner le niveau 0 (signifie « aucune compression », mais il y a toujours une surcharge de protocole zlib) est généralement inutile, vous feriez mieux d'utiliser la compression « none ».
lzma[,N]
Utiliser la compression lzma (« xz »). Faible vitesse, haute compression. Si vous ne donnez pas explicitement le niveau de compression N (allant de 0 à 9), il utilisera le niveau 6. Donner des niveaux supérieurs à 6 est inutile et contre-productif car cela ne compresse pas mieux en raison de la taille du tampon utilisée par borg - mais cela gaspille beaucoup de cycles CPU et de RAM.
auto,C[,N]
Utiliser une heuristique intégrée pour décider par bloc s'il faut compresser ou non. L'heuristique essaie avec lz4 si les données sont compressibles. Pour les données incompressibles, elle n'utilisera pas de compression (utilise « none »). Pour les données compressibles, elle utilise la compression donnée C[,N] - C[,N] étant un spécificateur de compression valide. Cela peut être utile pour les fichiers multimédias qui ne peuvent souvent pas être beaucoup plus compressés.
obfuscate,SPEC,C[,N]
Utiliser l'obfuscation de taille compressée pour rendre les attaques par empreinte basées sur la taille observable des blocs stockés plus difficiles. Note :
  • Vous devez combiner ceci avec le chiffrement, sinon cela n'aura aucun sens.
  • La taille de votre dépôt sera plus grande, bien sûr.
  • Un bloc est limité par la constante MAX_DATA_SIZE (actuellement ~20MiB).

La valeur SPEC détermine comment fonctionne l'obfuscation de taille :

Variation aléatoire réciproque de taille relative (multiplicative)

La taille augmentera d'un facteur, relatif à la taille des données compressées. Des facteurs plus petits sont utilisés souvent, des facteurs plus grands rarement.

Facteurs disponibles :

1:     0.01 ..        100
2:     0.1  ..      1,000
3:     1    ..     10,000
4:    10    ..    100,000
5:   100    ..  1,000,000
6: 1,000    .. 10,000,000

Exemples de probabilités pour SPEC 1 :

90   %  0.01 ..   0.1
 9   %  0.1  ..   1
 0.9 %  1    ..  10
 0.09% 10    .. 100

Rembourrage aléatoire de taille jusqu'à la taille donnée (additif)

110: 1kiB (2 ^ (SPEC - 100))
...
120: 1MiB
...
123: 8MiB (max.)

Rembourrage Padmé (déterministe)

250: remplit jusqu'à des sommes de puissances de 2, surcharge max 12 %

Utilise l'algorithme Padmé pour remplir de manière déterministe la taille compressée en une somme de puissances de 2, limitant la surcharge à 12 %. Voir https://lbarman.ch/blog/padme/ pour les détails.

Exemples :

borg create --compression lz4 REPO::ARCHIVE data
borg create --compression zstd REPO::ARCHIVE data
borg create --compression zstd,10 REPO::ARCHIVE data
borg create --compression zlib REPO::ARCHIVE data
borg create --compression zlib,1 REPO::ARCHIVE data
borg create --compression auto,lzma,6 REPO::ARCHIVE data
borg create --compression auto,lzma ...
borg create --compression obfuscate,110,none ...
borg create --compression obfuscate,3,auto,zstd,10 ...
borg create --compression obfuscate,2,zstd,6 ...
borg create --compression obfuscate,250,zstd,3 ...
