--sha256 chemin
Le programme sha256 à utiliser pour calculer les sommes SHA256. Actuellement, bpkg reconnaît sha256, sha256sum et shasum. Notez que la dernière composante de chemin doit contenir l'un de ces noms comme sous-chaîne pour que bpkg reconnaisse le programme utilisé. Vous pouvez également spécifier des options supplémentaires à passer au programme sha256 avec --sha256-option.

Si le programme sha256 n'est pas spécifié, alors bpkg essaiera de découvrir si l'un des programmes ci-dessus est disponible et l'utilisera. Actuellement, bpkg a l'ordre de préférence suivant : sha256, sha256sum et shasum.

--sha256-option opt
Option supplémentaire à passer au programme sha256. Voir --sha256 pour plus d'informations sur le programme sha256. Répétez cette option pour spécifier plusieurs options sha256.
--tar chemin
Le programme tar à utiliser pour extraire les archives de paquets. Par exemple, gtar ou bsdtar. Vous pouvez également spécifier des options supplémentaires à passer au programme tar avec --tar-option. Si le programme tar n'est pas explicitement spécifié, alors bpkg utilisera tar par défaut.
--tar-option opt
Option supplémentaire à passer au programme tar. Voir --tar pour plus d'informations sur le programme tar. Répétez cette option pour spécifier plusieurs options tar.
--openssl chemin
Le programme openssl à utiliser pour les opérations cryptographiques. Vous pouvez également spécifier des options supplémentaires à passer au programme openssl avec --openssl-option. Si le programme openssl n'est pas explicitement spécifié, alors bpkg utilisera openssl par défaut.

Les valeurs --openssl* peuvent être qualifiées de manière facultative avec la commande openssl sous la forme commande:valeur. Cela rend la valeur applicable uniquement à la commande spécifique, par exemple :

bpkg rep-create                      \
  --openssl pkeyutl:/chemin/vers/openssl \
  --openssl-option pkeyutl:-engine   \
  --openssl-option pkeyutl:pkcs11    \
  ...

Notez que pour les versions d'openssl antérieures à 3.0.0, bpkg utilise la commande rsautl au lieu de pkeyutl pour les opérations de signature et de récupération de données.

Une valeur non qualifiée contenant un deux-points peut être spécifiée comme qualifiée avec une commande vide, par exemple, --openssl :C:\bin\openssl. Pour voir les commandes openssl exécutées par bpkg, utilisez le mode verbeux (option -v).

--openssl-option opt
Option supplémentaire à passer au programme openssl. Voir --openssl pour plus d'informations sur le programme openssl. Les valeurs peuvent être qualifiées de manière facultative par la commande openssl, comme discuté dans --openssl. Répétez cette option pour spécifier plusieurs options openssl.
--auth type
Types de dépôts à authentifier. Les valeurs valides pour cette option sont none, remote, all. Par défaut, seuls les dépôts distants sont authentifiés. Vous pouvez demander l'authentification des dépôts locaux en passant all ou désactiver complètement l'authentification en passant none.
--trust empreinte
Faire confiance au certificat du dépôt avec une empreinte SHA256. Un tel certificat est automatiquement approuvé, sans demander de confirmation à l'utilisateur. Répétez cette option pour faire confiance à plusieurs certificats.

Notez que par défaut openssl affiche une empreinte SHA1 et pour obtenir une empreinte SHA256, vous devrez passer l'option -sha256, par exemple :

openssl x509 -sha256 -fingerprint -noout -in cert.pem
--trust-yes
Supposez que la réponse à toutes les invites d'authentification est oui.
--trust-no
Supposez que la réponse à toutes les invites d'authentification est non.
--git-capabilities up=pc
Capacités de protocole (pc) pour un préfixe d'URL de dépôt git (up). Les valeurs valides pour les capacités sont dumb (pas de support de clone peu profond), smart (support de clone peu profond, mais pas pour la récupération de commits non annoncés), unadv (support de clone peu profond et pour la récupération de commits non annoncés). Par exemple : 
bpkg build https://example.org/foo.git#master \
  --git-capabilities https://example.org=smart

Voir bpkg-repository-types(1) pour les détails sur les capacités du protocole git.

--pager chemin
Le programme paginateur à utiliser pour afficher du texte long. Les programmes paginateurs couramment utilisés sont less et more. Vous pouvez également spécifier des options supplémentaires à passer au programme paginateur avec --pager-option. Si une chaîne vide est spécifiée comme programme paginateur, aucun paginateur ne sera utilisé. Si le programme paginateur n'est pas explicitement spécifié, alors bpkg essaiera d'utiliser less. S'il n'est pas disponible, aucun paginateur ne sera utilisé.
--pager-option opt
Option supplémentaire à passer au programme paginateur. Voir --pager pour plus d'informations sur le programme paginateur. Répétez cette option pour spécifier plusieurs options de paginateur.
--options-file fichier
Lire les options supplémentaires à partir du fichier. Chaque option doit apparaître sur une ligne distincte, suivie éventuellement d'un espace ou d'un signe égal (=) et d'une valeur d'option. Les lignes vides et les lignes commençant par # sont ignorées. Les valeurs d'option peuvent être entourées de guillemets doubles (") ou simples (') pour conserver les espaces blancs en tête et en fin, ainsi que pour spécifier des valeurs vides. Si la valeur contient elle-même des guillemets de fin ou de début, entourez-la d'une paire de guillemets supplémentaire, par exemple '"x"'. Les guillemets qui ne sont ni en tête ni en fin sont interprétés comme faisant partie de la valeur de l'option.

La sémantique de la fourniture d'options dans un fichier est équivalente à la fourniture du même ensemble d'options dans le même ordre sur la ligne de commande à l'endroit où l'option --options-file est spécifiée, sauf que l'échappement et le guillemet du shell ne sont pas requis. Répétez cette option pour spécifier plus d'un fichier d'options.

--default-options rép
Le répertoire à partir duquel charger les fichiers d'options par défaut supplémentaires.
--no-default-options
Ne pas charger les fichiers d'options par défaut.
--keep-tmp
Ne pas supprimer le répertoire temporaire de bpkg à la fin de l'exécution de la commande et afficher son chemin au niveau de verbosité 2 ou supérieur. Cette option est principalement utile pour le dépannage.

SORTIE JSON

Les commandes qui prennent en charge la sortie JSON spécifient leurs formats comme une représentation sérialisée d'une struct C++ ou d'un tableau de celles-ci. Par exemple :

struct package
{
  string name;
};
struct configuration
{
  uint64_t         id;
  string           path;
  optional<string> name;
  bool             default;
  vector<package>  packages;
};

Un exemple de la représentation JSON sérialisée de la struct configuration :

{
  "id": 1,
  "path": "/tmp/hello-gcc",
  "name": "gcc",
  "default": true,
  "packages": [
    {
      "name": "hello"
    }
  ]
}

Cette section fournit des détails sur les propriétés globales de tels formats et la sémantique de la sérialisation de struct.

L'ordre des membres dans un objet JSON est fixe comme spécifié dans la struct correspondante. Bien que de nouveaux membres puissent être ajoutés à l'avenir (et devraient être ignorés par les anciens consommateurs), la sémantique des membres existants (y compris si l'entrée de niveau supérieur est un objet ou un tableau) ne peut pas changer.

Un membre d'objet est requis sauf si son type est optional<>, bool, ou vector<> (tableau). Pour les membres bool, l'absence signifie false. Pour les membres vector<>, l'absence signifie vide. Un tableau de niveau supérieur vide est toujours présent.

Par exemple, le texte JSON suivant est une sérialisation possible de la struct configuration ci-dessus :

{
  "id": 1,
  "path": "/tmp/hello-gcc"
}
