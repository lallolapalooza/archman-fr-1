BUNDLE-CACHE(1) Manuel des commandes générales BUNDLE-CACHE(1)

NOM

bundle-cache - Empaquete vos fichiers .gem nécessaires dans votre application

SYNOPIS

bundle cache [OPTIONS]

alias : package, pack

DESCRIPTION

Copie tous les fichiers .gem nécessaires pour exécuter l'application dans le répertoire vendor/cache. À l'avenir, lors de l'exécution de bundle install(1) bundle-install.1.html, utilisez les gems du cache de préférence à celles de rubygems.org.

OPTIONS

--all
Inclure toutes les sources (y compris les chemins et git).
--all-platforms
Inclure les gems pour toutes les plateformes présentes dans le fichier de verrouillage, pas seulement celle actuelle.
--cache-path=CHEMIN-CACHE
Spécifier un chemin de cache différent de celui par défaut (vendor/cache).
--gemfile=GEMFILE
Utiliser le gemfile spécifié au lieu de Gemfile.
--no-install
Ne pas installer les gems, seulement mettre à jour le cache.
--no-prune
Ne pas supprimer les gems obsolètes du cache.
--path=CHEMIN
Spécifier un chemin différent de celui par défaut du système ($BUNDLE_PATH ou $GEM_HOME).
--quiet
N'afficher que les avertissements et les erreurs.
--frozen
Ne pas autoriser la mise à jour du Gemfile.lock après l'installation de cette opération de cache de bundle.

GEMS GIT ET CHEMINS

La commande bundle cache peut également empaqueter des dépendances :git et :path en plus des fichiers .gem. Cela doit être explicitement activé via l'option --all. Une fois utilisée, l'option --all sera mémorisée.

SUPPORT PLATEFORMES MULTIPLES

Lors de l'utilisation de gems qui ont des paquets différents pour des plateformes différentes, Bundler prend en charge la mise en cache des gems pour d'autres plateformes où le Gemfile a été résolu (c'est-à-dire présentes dans le fichier de verrouillage) dans vendor/cache. Cela doit être activé via l'option --all-platforms. Ce paramètre sera mémorisé dans votre configuration locale de bundler.

RECUPÉRATION DISTANTE

Par défaut, si vous exécutez bundle install(1) bundle-install.1.html après avoir exécuté bundle cache(1) bundle-cache.1.html, bundler se connectera toujours à rubygems.org pour vérifier si un gem spécifique à la plateforme existe pour l'un des gems dans vendor/cache.

Par exemple, considérez ce Gemfile(5) :

source "https://rubygems.org"
gem "nokogiri"

Si vous exécutez bundle cache sous C Ruby, bundler récupérera la version de nokogiri pour la plateforme "ruby". Si vous déployez sur JRuby et exécutez bundle install, bundler est obligé de vérifier si un nokogiri de plateforme "java" existe.

Même si le gem nokogiri pour la plateforme Ruby est *techniquement* acceptable sur JRuby, il possède une extension C qui ne s'exécute pas sur JRuby. En conséquence, bundler, par défaut, se connectera toujours à rubygems.org pour vérifier s'il existe une version d'un de vos gems plus spécifique à votre plateforme.

Ce problème ne se limite pas non plus à la plateforme "java". Un problème similaire (courant) peut survenir lors du développement sous Windows et du déploiement sous Linux, ou même lors du développement sous OSX et du déploiement sous Linux.

Si vous êtes absolument certain que les gems empaquetés dans vendor/cache conviennent à la plateforme sur laquelle vous vous trouvez, vous pouvez exécuter bundle install --local pour éviter de vérifier les gems plus appropriés et utiliser ceux de vendor/cache.

Une façon de s'assurer que vous avez les bonnes versions de tous vos gems pour la plateforme est d'exécuter bundle cache sur une machine identique et de vérifier les gems. Par exemple, vous pouvez exécuter bundle cache sur un environnement de staging identique pendant votre processus de staging, et vérifier le répertoire vendor/cache avant de déployer en production.

Par défaut, bundle cache(1) bundle-cache.1.html récupère et installe également les gems à l'emplacement par défaut. Pour empaqueter les dépendances dans vendor/cache sans les installer à l'emplacement d'installation local, vous pouvez exécuter bundle cache --no-install.

HISTORIQUE

Dans Bundler 2.1, cache a repris les fonctionnalités de package et maintenant package et pack sont des alias de cache.
