GEMS

Si vous exécutez bundle update --all, bundler ignorera toutes les gems précédemment installées et résoudra à nouveau toutes les dépendances en se basant sur les versions les plus récentes de toutes les gems disponibles dans les

sources.

Comme vous pouvez le voir, même si vous avez deux gems dans le Gemfile(5), votre application a besoin de 26 gems différentes pour fonctionner. Bundler se souvient des versions exactes qu'il a installées dans le Gemfile.lock. La prochaine fois que vous exécuterez bundle install(1) bundle-install.1.html, bundler sautera la résolution des dépendances et installera les mêmes gems que la dernière

fois.

Après avoir mis le Gemfile.lock sous contrôle de version et l'avoir cloné sur une autre machine, l'exécution de bundle install(1) bundle-install.1.html installera toujours les gems que vous avez installées la dernière fois. Vous n'avez pas à vous inquiéter qu'une nouvelle version de erubis ou mail change les gems que vous

utilisez.

Cependant, de temps en temps, vous pourriez vouloir mettre à jour les gems que vous utilisez vers les versions les plus récentes qui correspondent toujours aux gems de votre Gemfile(5)

.

Pour ce faire, exécutez bundle update --all, qui ignorera le Gemfile.lock et résoudra à nouveau toutes les dépendances. Gardez à l'esprit que ce processus peut résulter en un ensemble de 25 gems sensiblement différent, basé sur les exigences des nouvelles gems que les auteurs de gems ont publiées depuis la dernière fois que vous avez exécuté bundle upd

ate -
-all.
