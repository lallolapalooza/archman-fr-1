bootparam - introduction

aux paramètres de déma
rrage du noyau Linux

DESCRIPTIO

N

Le noyau Linux accepte certaines « options de ligne de commande » ou « paramètres de démarrage » au moment où il est démarré. En général, cela sert à fournir au noyau des informations sur des paramètres matériels que le noyau ne pourrait pas déterminer par lui-même, ou pour éviter/annuler les valeurs que le noyau détecterait

autrement.

Lorsque le noyau est démarré directement par le BIOS, vous n'avez aucune occasion de spécifier des paramètres. Afin de profiter de cette possibilité, vous devez utiliser un chargeur de démarrage capable de passer des paramètres, comme

GRUB.

La liste

d'arguments

La ligne de commande du noyau est analysée en une liste de chaînes (arguments de démarrage) séparées par des espaces. La plupart des arguments de démarrage ont la forme

: 


nom[=valeur_1][,valeur_2]...[,
valeur_10]

où « nom » est un mot-clé unique utilisé pour identifier à quelle partie du noyau les valeurs associées (le cas échéant) doivent être transmises. Notez que la limite de 10 est réelle, car le code actuel ne traite que 10 paramètres séparés par des virgules par mot-clé. (Cependant, vous pouvez réutiliser le même mot-clé avec jusqu'à 10 paramètres supplémentaires dans des situations inhabituellement complexes, en supposant que la fonction de configuration le supporte.

)

La plupart du tri est codé dans le fichier source du noyau init/main.c. D'abord, le noyau vérifie si l'argument est l'un des arguments spéciaux « root= », « nfsroot= », « nfsaddrs= », « ro », « rw », « debug » ou « init ». Le sens de ces arguments spéciaux est décrit

ci-dessous.

Ensuite, il parcourt une liste de fonctions de configuration pour voir si la chaîne d'argument spécifiée (comme « foo ») a été associée à une fonction de configuration (« foo_setup() ») pour un périphérique ou une partie particulière du noyau. Si vous avez passé au noyau la ligne foo=3,4,5,6, le noyau chercherait dans le tableau bootsetups pour voir si « foo » a été enregistré. Si c'était le cas, il appellerait la fonction de configuration associée à « foo » (foo_setup()) et lui transmettrait les arguments 3, 4, 5 et 6 tels que donnés sur la ligne de commande du

noyau.

Tout ce qui a la forme « foo=bar » et qui n'est pas accepté comme fonction de configuration comme décrit ci-dessus est ensuite interprété comme une variable d'environnement à définir. Un exemple (inutile ?) serait d'utiliser « TERM=vt100 » comme argument de

démarrage.

Tous les arguments restants qui n'ont pas été pris en charge par le noyau et qui n'ont pas été interprétés comme des variables d'environnement sont ensuite transmis au PID 1, qui est généralement le programme init(1). L'argument le plus courant qui est passé au processus init est le mot « single », qui lui indique de démarrer l'ordinateur en mode utilisateur unique et de ne pas lancer tous les démons habituels. Consultez la page de manuel de la version d' init(1) installée sur votre système pour

voir quels arg
uments elle accepte.

Cet argument indique au noyau quel périphérique doit être utilisé comme système de fichiers racine pendant le démarrage. Arguments de démarrage destinés aux développeurs du

noyau
'debu
g'
Les messages du noyau sont transmis à un démon (par ex. klogd(8) ou similaire) afin qu'ils puissent être enregistrés sur disque. Les messages ayant une priorité supérieure à console_loglevel sont également imprimés sur la console. (Pour une discussion sur les niveaux de journalisation, voir syslog(2).) Par défaut, console_loglevel est défini pour journaliser les messages aux niveaux supérieurs à KERN_DEBUG. Cet argument de démarrage fera en sorte que le noyau imprime également les messages journalisés au niveau KERN_DEBUG. Le niveau de journalisation de la console peut également être défini sur un système déjà démarré via le fichier /proc/sys/kernel/printk (décrit dans syslog(2)), l'opération syslog(2) SYSLOG_ACTION_CONSOLE_LEVEL, ou dmesg(
8).

N'

Le profilage est activé en définissant la variable prof_shift à une valeur non nulle. Cela se fait soit en spécifiant CONFIG_PROFILE à la compilation, soit en donnant l'option 'profile='. Maintenant, la valeur que prof_shift prendra sera N, si elle e

Arguments de démarrage pour l'utilisation du ramdisk (Uniquement si le noyau a été compilé

avec
CONFIG_BLK_DEV_RAM.) En général, c'est une mauvaise idée d'utiliser un ramdisk sous Linux — le système utilisera la mémoire disponible de manière plus efficace lui-même. Mais lors du démarrage, il est souvent utile de charger le contenu de la disquette dans un ramdisk. On peut aussi avoir un système où certains modules (pour le système de fichiers ou le matériel) doivent d'abord être chargés avant que le disque principal ne puisse être accessible. Dans Linux 1.3.48, la gestion des ramdisks a été radicalement modifiée. Auparavant, la mémoire était allouée statiquement, et il existait un paramètre 'ramdisk=N' pour indiquer sa taille. (Cela pouvait aussi être défini dans l'image du noyau à la compilation.) De nos jours, les ramdisks utilisent le cache de tampons et grandissent dynamiquement. Pour beaucoup d'informations sur la configuration actuelle des ramdisks, voir le fichier source du noyauDocumentation/blockdev/ramdisk.txt
(

'prompt_ramdisk=N' Si N=1, demande l'insertion de la disquette. (C'est le défaut.) Si N=0, ne demande rien. (Ainsi, ce paramètre n'est jamais nécessaire.

'ramdisk_size=N' ou (obsolète) 'ramdisk=

'ramdisk_start

Définit le numéro de bloc de départ (le décalage sur la disquette où le ramdisk commence) à N. C'est nécessaire si le ramdisk suit une image de

Lorsque cette fonctionnalité est activée, le processus de démarrage chargera le noyau et un ramdisk initial ; puis le noyau convertit initrd en un ramdisk « normal », qui est monté en lecture- écriture comme périphérique racine ; puis /linuxrc est exécuté ; ensuite le système de fichiers racine « réel » est monté, et le système de fichiers initrd est déplacé vers /initrd ; enfin, la séquence de démarrage habituelle (par ex. l'invocation de /sbin/init) e

Arguments de démarrage pour les périphériques

SCSI

Notation générale pour cette section

:

iobase -- le premier port d'E/S occupé par l'hôte SCSI. Ceux-ci sont spécifiés en notation hexadécimale, et se situent généralement dans la plage de 0x200 à

0x3ff.

irq -- l'interruption matérielle configurée pour être utilisée par la carte. Les valeurs valides dépendront de la carte en question, mais seront généralement 5, 7, 9, 10, 11, 12 et 15. Les autres valeurs sont généralement utilisées pour des périphériques courants comme les disques durs IDE, les disquettes, les ports série,

etc.

scsi-id -- l'ID que l'adaptateur hôte utilise pour s'identifier sur le bus SCSI. Seuls certains adaptateurs hôte vous permettent de changer cette valeur, car la plupart l'ont spécifiée de manière permanente en interne. La valeur par défaut habituelle est 7, mais les cartes Seagate et Future Domain TMC-950 utilisent

6.

parity -- si l'adaptateur hôte SCSI attend que les périphériques connectés fournissent une valeur de parité avec tous les échanges d'informations. Spécifier un un indique que la vérification de parité est activée, et un zéro la désactive. Encore une fois, tous les adaptateurs ne supporteront pas la sélection du comportement de parité en argument de

démarrage.
'max_scsi_luns=.
..'
Un périphérique SCSI peut contenir un certain nombre de « sous- périphériques ». L'exemple le plus courant est celui des nouveaux CD-ROM SCSI q
ui gèrent plus d'un disque à la fois. Chaque CD est adressé comme un « Logical Unit Number » (LUN) de ce périphérique particulier. Mais la plup
art des périphériques, tels que les disques durs, les lecteurs de bandes, etc., ne sont qu'un seul périphérique et seront assignés au LUN zéro.
Certains périphériques SCSI mal conçus ne peuvent pas gérer le fait d'être interrogés pour des LUN différents de zéro. Par conséquent, si le drapeau de compilation CONFIG_SCSI_MULTI_LUN n'est pas défini, les noyaux plus récents interrogeront par défaut uniquement le LUN
zéro.
Pour spécifier le nombre de LUN interrogés au démarrage, on entre 'max_scsi_luns=n' comme ar
gument de démarrage, où n est un nombre compris entre un et huit. Pour éviter les problèmes d
écrits ci-dessus, on utiliserait n=1 pour ne pas perturber de tels périphériques défectueux.

Paramètres du pilote de disque/CD-ROM
IDE
Le pilote IDE accepte un certain nombre de paramètres, allant des spécifications
de géométrie du disque au support de puces de contrôleur défectueuses. Les option
s spécifiques au lecteur sont spécifiées en utilisant 'hdX=' avec X dans 'a'–'h'.
Les options non spécifiques au lecteur sont spécifiées avec le préfixe 'hd='. Notez que l'utilisation d'un préfixe spécifique au lecteur pour une option non spécifique au lecteur fonctionnera toujours, et l'option sera simplement appliquée comme
prévu.
Notez également que 'hd=' peut être utilisé pour faire référence au prochain lecteur non spécifié de la séquence (a, ..., h). Pour les discussions suivantes, l'option 'hd=' sera citée par brièveté. Voir le fichier Documentation/ide/ide.txt (ou Documentation/ide.txt dans les noyaux plus anciens, ou drivers/block/README.ide dans les noyaux anciens) dans
les sources du noyau
Linux pour plus de détails.
Les options 'hd=cyls,heads,sects[,wpcom[,irq]
]'
Ces options sont utilisées pour spécifier la géométrie physique du disque. Seules les trois premières valeurs sont requises. Les valeurs cylindres/têtes/secteurs seront celles utilisées par fdisk. La valeur de précompensation d'écriture est ignorée pour les disques IDE. La valeur IRQ spécifiée sera l'IRQ utilisée pour l'interface sur laquelle se trouve le lecteur, et n'est pas vraiment un paramètre spécifique au
lecteur.
L'option
'hd=serialize'
La puce d'interface IDE double CMD-640 est défectueuse par conception de telle sorte que lorsque des lecteurs sur l'interface secondaire sont utilisés en même temps que des lecteurs sur l'interface primaire, elle corrompra vos données. L'utilisation de cette option indique au pilote de s'assurer que les deux interfaces ne sont jamais utilisées en même
temps.
L'option
'hd=noprobe'
Ne pas interro
ger ce lecteur
. Par exemple,

désactiverait l'interrogation, mais spécifierait toujours la géométrie du lecteur afinat it would be registered as a valid block device, and hence usable.
L'option 'hd=nowerr'
Certains disques ont apparemment le bit WRERR_STAT bloqué en permanence. Ceci active une solution de contournement pour ces périphériques défectueux.
L'option 'hd=cdrom'
Ceci indique au pilote IDE qu'un CD-ROM compatible ATAPI est connecté à la place d'un disque dur IDE normal. Dans la plupart des cas, le CD-ROM est identifié automatiquement, mais si ce n'est pas le cas, ceci peut aider.
Options du pilote de disque ST-506 standard ('hd=')
Le pilote de disque standard peut accepter des arguments de géométrie pour les disques, similaires au pilote IDE. Notez cependant qu'il n'attend que trois valeurs (C/H/S) ; toute autre quantité sera ignorée silencieusement. De plus, il n'accepte que 'hd=' comme argument, c'est-à-dire que 'hda=' et ainsi de suite ne sont pas valides ici. Le format est le suivant :

S'il y a deux disques installés, ce qui précède est répété avec les paramètres de géométrie du second disque.

Périphériques Ethernet

Les différents pilotes utilisent des paramètres différents, mais ils partagent tous au moins une IRQ, une valeur de base du port d'E/S et un nom. Dans sa forme la plus générique, cela ressemble à ceci :


ether=irq,iobase[,param_1[,...param_8]],name

Le premier argument non numérique est considéré comme le nom. Les valeurs param_n (si applicables) ont généralement des significations différentes pour chaque carte/pilote différent. Les valeurs param_n typiques sont utilisées pour spécifier des choses comme l'adresse de la mémoire partagée, la sélection de l'interface, le canal DMA, etc.

L'utilisation la plus courante de ce paramètre est de forcer la recherche d'une deuxième carte réseau, car la valeur par défaut est de n'en rechercher qu'une. Ceci peut être accompli avec un simple :


ether=0,0,eth1

Notez que les valeurs zéro pour l'IRQ et la base d'E/S dans l'exemple ci-dessus indiquent au(x) pilote(s) d'effectuer une recherche automatique.

Le guide Ethernet (Ethernet-HowTo) contient une documentation complète sur l'utilisation de plusieurs cartes et sur l'implémentation spécifique à la carte/au pilote des valeurs param_n lorsqu'elles sont utilisées. Les lecteurs intéressés devraient se référer à la section de ce document concernant leur carte particulière.

Le pilote de disquette

Il existe de nombreuses options pour le pilote de disquette, et elles sont toutes listées dans Documentation/blockdev/floppy.txt (ou Documentation/floppy.txt dans les anciens noyaux, ou drivers/block/README.fd pour les noyaux très anciens) dans le code source du noyau Linux. Voir ce fichier pour les détails.

Le pilote sonore

Le pilote sonore peut également accepter des arguments de démarrage pour remplacer les valeurs compilées. Ceci n'est pas recommandé, car c'est assez complexe. C'est décrit dans le fichier du code source du noyau Linux Documentation/sound/oss/README.OSS (drivers/sound/Readme.linux dans les anciennes versions du noyau). Il accepte un argument de démarrage de la forme :


sound=device1[,device2[,device3...[,device10]]]

où chaque valeur deviceN est du format suivant 0xTaaaId et les octets sont utilisés comme suit :

T - type de périphérique : 1=FM, 2=SB, 3=PAS, 4=GUS, 5=MPU401, 6=SB16, 7=SB16-MPU401

aaa - adresse d'E/S en hexadécimal.

I - ligne d'interruption en hexadécimal (c'est-à-dire, 10=a, 11=b, ...)

d - canal DMA.

Comme vous pouvez le constater, cela devient assez compliqué, et il est préférable de compiler vos propres valeurs personnelles comme recommandé. L'utilisation d'un argument de démarrage 'sound=0' désactivera entièrement le pilote sonore.

Le pilote d'imprimante ligne

'lp='

Syntaxe :

lp=0
lp=auto
lp=reset
lp=port[,port...]

Vous pouvez indiquer au pilote d'imprimante quels ports utiliser et lesquels ne pas utiliser. Ce dernier est utile si vous ne voulez pas que le pilote d'imprimante réclame tous les ports parallèles disponibles, afin que d'autres pilotes (par exemple, PLIP, PPA) puissent les utiliser à la place.
Le format de l'argument est une liste de noms de ports. Par exemple, lp=none,parport0 utilisera le premier port parallèle pour lp1, et désactivera lp0. Pour désactiver entièrement le pilote d'imprimante, on peut utiliser lp=0.
