NOM

bup-save - créer un nouvel ensemble de sauvegarde bup

SYNOPSIS

bup save [-r host:path] <-t|-c|-n name> [-#] [-f indexfile] [-v] [-q] [--smaller=maxsize] <chemins...>;

DESCRIPTION

bup save enregistre le contenu des fichiers ou chemins donnés dans un nouvel ensemble de sauvegarde et nomme éventuellement cet ensemble de sauvegarde.

Notez que pour pouvoir faire référence à votre ensemble de sauvegarde ultérieurement (c'est-à-dire pour la restauration), vous devez soit spécifier --name (le cas normal), soit noter l'identifiant de l'arbre ou du commit affiché par --tree ou --commit.

Avant d'essayer d'enregistrer des fichiers avec bup save, vous devez d'abord mettre à jour l'index en utilisant bup index. Les raisons de la séparation des deux étapes sont décrites dans la page man de bup-index(1).

Par défaut, les métadonnées seront enregistrées pour chaque chemin, et les métadonnées de tout répertoire parent non indexé des chemins indexés seront prises directement depuis le système de fichiers. Cependant, si --strip, --strip-path, ou --graft est spécifié, les métadonnées ne seront pas enregistrées pour le répertoire racine (/). Voir bup-restore(1) pour plus d'informations sur le traitement des métadonnées.

OPTIONS

-r, --remote=host:path
enregistrer l'ensemble de sauvegarde sur le serveur distant donné. Si path est omis, utilise le chemin par défaut sur le serveur distant (vous devez toujours inclure le « : »). La connexion au serveur distant est établie avec SSH. Si vous souhaitez spécifier le port, l'utilisateur ou la clé privée à utiliser pour la connexion SSH, nous vous recommandons d'utiliser le fichier ~/.ssh/config .
-t, --tree
après la création de l'ensemble de sauvegarde, affiche l'identifiant git tree de la sauvegarde résultante.
-c, --commit
après la création de l'ensemble de sauvegarde, affiche l'identifiant git commit de la sauvegarde résultante.
-n, --name=name
après la création de l'ensemble de sauvegarde, crée une branche git nommée name afin que la sauvegarde puisse être accessible en utilisant ce nom. Si name existe déjà, la nouvelle sauvegarde sera considérée comme un descendant de l'ancienne name. (Ainsi, vous pouvez créer continuellement de nouveaux ensembles de sauvegarde avec le même nom, et plus tard consulter l'historique de cet ensemble de sauvegarde pour voir comment les fichiers ont changé au fil du temps.)
-d, --date=date
spécifier la date de la sauvegarde, en secondes depuis l'époque, au lieu de l'heure actuelle.
-f, --indexfile=indexfile
utiliser un nom de fichier d'index différent au lieu de $BUP_DIR/bupindex.
-v, --verbose
augmenter le niveau de verbosité (peut être utilisé plus d'une fois). Avec un -v, affiche chaque nom de répertoire au fur et à mesure qu'il est sauvegardé. Avec deux -v, affiche également chaque nom de fichier.
-q, --quiet
désactiver les messages de progression.
--smaller=maxsize
ne pas sauvegarder les fichiers >= maxsize octets. Vous pouvez utiliser cette option pour exécuter des sauvegardes incrémentales fréquentes de vos petits fichiers, qui peuvent généralement être sauvegardés rapidement, et ignorer les gros fichiers (comme les images de machine virtuelle) qui prennent plus de temps. Vous pouvez ensuite sauvegarder les gros fichiers moins fréquemment. Utilisez un suffixe comme k, M, ou G pour spécifier des multiples de 1024, 1024*1024, 1024*1024*1024 respectivement.
--bwlimit=bytes/sec
ne pas transmettre plus de bytes/sec octets par seconde au serveur. C'est utile pour éviter que vos sauvegardes n'absorbent toute la bande passante de votre réseau. Utilisez un suffixe comme k, M, ou G pour spécifier des multiples de 1024, 1024*1024, 1024*1024*1024 respectivement.
--strip
supprime le chemin donné de tous les fichiers et répertoires.

Un répertoire /root/chroot/etc sauvegardé avec « bup save -n chroot --strip /root/chroot » serait sauvegardé comme /etc. Notez que actuellement, les métadonnées ne seront pas enregistrées pour le répertoire racine (/) lorsque cette option est spécifiée.

--strip-path=path-prefix
supprime le préfixe de chemin donné path-prefix de tous les fichiers et répertoires.

Un répertoire /root/chroot/webserver/etc sauvegardé avec « bup save -n webserver --strip-path=/root/chroot /root/chroot/webserver/etc » serait sauvegardé comme /webserver/etc. Notez que actuellement, les métadonnées ne seront pas enregistrées pour le répertoire racine (/) lorsque cette option est spécifiée.

--graft=old_path=new_path
un point de greffage old_path=new_path (peut être utilisé plus d'une fois).

Un répertoire /root/chroot/a/etc sauvegardé avec « bup save -n chroot --graft /root/chroot/a=/chroot/a » serait sauvegardé comme /chroot/a/etc. Notez que actuellement, les métadonnées ne seront pas enregistrées pour le répertoire racine (/) lorsque cette option est spécifiée.

-#, --compress=#
définir le niveau de compression à # (une valeur de 0-9, où 9 est le plus élevé et 0 est sans compression). La valeur par défaut est 1 (compression rapide et légère)

EXEMPLES

$ bup index -ux /etc
Indexing: 1981, done.
$ bup save -r myserver: -n my-pc-backup --bwlimit=50k /etc
Reading index: 1981, done.
Saving: 100.00% (998/998k, 1981/1981 files), done.
$ ls /home/joe/chroot/httpd
bin var
$ bup index -ux /home/joe/chroot/httpd
Indexing: 1337, done.
$ bup save --strip -n joes-httpd-chroot /home/joe/chroot/httpd
Reading index: 1337, done.
Saving: 100.00% (998/998k, 1337/1337 files), done.
$ bup ls joes-httpd-chroot/latest/
bin/
var/
$ bup save --strip-path=/home/joe/chroot -n joes-chroot \
     /home/joe/chroot/httpd
Reading index: 1337, done.
Saving: 100.00% (998/998k, 1337/1337 files), done.
$ bup ls joes-chroot/latest/
httpd/
$ bup save --graft /home/joe/chroot/httpd=/http-chroot \
     -n joe
     /home/joe/chroot/httpd
Reading index: 1337, done.
Saving: 100.00% (998/998k, 1337/1337 files), done.
$ bup ls joe/latest/
http-chroot/
