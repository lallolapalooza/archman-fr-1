String donne les octets d'entrée à analyser (un octet par caractère, et les caractères non représentables comme un octet ont leurs bits de poids fort tranchés) et formatString indique comment l'analyser. Chaque spécificateur de champ est un caractère de type unique suivi d'un caractère de drapeau optionnel suivi d'un count numérique optionnel. La plupart des spécificateurs de champ consomment un argument pour obtenir la variable dans laquelle les valeurs analysées doivent être placées. S'il n'y a pas assez d'octets restants après la position actuelle du curseur pour satisfaire le spécificateur de champ actuel, alors la variable correspondante est laissée intacte

Tous les bits supplémentaires dans le dernier octet sont ignorés. Si count est *, alors tous les bits restants dans string seront analysés. Si count est omis, alors un bit
sera analysé
. Par exemple, 
binary scan \x07\x87\x05 b
5b* var1 var
2 retournera 2 avec 11100 stocké dans var1 et 1110000110100000 stocké dans var2
.
B
Cette forme est la même que b, sauf que les bits sont pris dans l'ordre de h
aut en bas à l'intérieur de
chaque octet. Par exemple, 
binary scan \x70\x87\x05 B
5B* var1 var
2 retournera 2 avec 01110 stocké dans var1 et 1000011100000101 stocké dans var2
.
H
Les données sont transformées en une chaîne de count chiffres hexadécimaux dans l'ordre de haut en bas représentés comme une séquence de caractères de l'ensemble « 0123456789abcdef ». Les octets de données sont analysés du premier au dernier avec les chiffres hexadécimaux pris dans l'ordre de haut en bas à l'intérieur de chaque octet. Tous les bits supplémentaires dans le dernier octet sont ignorés. Si count est *, alors tous les chiffres hexadécimaux restants dans string seront analysés. Si count est omis, alors un chiffre hexad
écimal sera analysé.
Par exemple, 
binary scan \x07\xC6\x05\x1f\x34 H3H* var1
var2
retournera 2 avec 07c stocké dans var1 et 051f34 stocké dans var2
.
h
Cette forme est la même que H, sauf que les chiffres sont pris dans l'ordre inverse
(de bas en haut) à l'intérieur
de chaque octet. Par exemple, 
binary scan \x07\x86\x05\x12\x34 h3h* var1
var2
retournera 2 avec 706 stocké dans var1 et 502143 stocké dans var2.

Notez que la plupart du code qui souhaite analyser les chiffres hexadécimaux à partir de plusieurs octets dans l'ordre devrait utiliser le form

c
Les données sont transformées en count entiers signés sur 8 bits et stockés dans la variable correspondante sous forme de liste. Si count est *, alors tous les octets restants dans string seront analysés. Si count est omis, alors un entier sur 8
bits sera analysé.
Par exemple, 
binary scan \x07\x86\x05 c
2c* var1 var
2 retournera 2 avec 7 -122 stocké dans var1 et 5 stocké dans var2. Notez que les entiers retournés sont signés, mais ils peuvent être convertis en quantités non signées sur 8 bits en utilisant une expression comme : 
set num
[expr {
$num &
0xFF }]
s
Les données sont interprétées comme count entiers signés sur 16 bits représentés dans l'ordre d'octets little-endian. Les entiers sont stockés dans la variable correspondante sous forme de liste. Si count est *, alors tous les octets restants dans string seront analysés. Si count est omis, alors un entier sur 16 bit entier sera lu. Par exemple, 
binary scan \x05\x00\x07\x00\xf0\xff s2s* var1 var2
renverra 2 avec 5 7 stockés dans var1 et -16 stocké dans var2. Notez que les entiers retournés sont signés, mais ils peuvent être convertis en quantités non signées de 16 bits en utilisant une expression comme : 
set num [expr { $num & 0xFFFF }]
S
Cette forme est identique à s sauf que les données sont interprétées comme count entiers signés de 16 bits représentés en ordre d'octets big-endian. Par exemple, 
binary scan \x00\x05\x00\x07\xff\xf0 S2S* var1 var2
renverra 2 avec 5 7 stockés dans var1 et -16 stocké dans var2.
t
Les données sont interprétées comme count entiers signés de 16 bits représentés dans l'ordre d'octets natif de la machine exécutant le script Tcl. C'est sinon identique à s et S. Pour déterminer quel est l'ordre d'octets natif de la machine, référez-vous à l'élément byteOrder du tableau tcl_platform.
i
Les données sont interprétées comme count entiers signés de 32 bits représentés en ordre d'octets little-endian. Les entiers sont stockés dans la variable correspondante sous forme de liste. Si count est *, alors tous les octets restants dans string seront lus. Si count est omis, alors un entier de 32 bits sera lu. Par exemple, 
set str \x05\x00\x00\x00\x07\x00\x00\x00\xf0\xff\xff\xff
binary scan $str i2i* var1 var2
renverra 2 avec 5 7 stockés dans var1 et -16 stocké dans var2. Notez que les entiers retournés sont signés, mais ils peuvent être convertis en quantités non signées de 32 bits en utilisant une expression comme : 
set num [expr { $num & 0xFFFFFFFF }]
I
Cette forme est identique à I sauf que les données sont interprétées comme count entiers signés de 32 bits représentés en ordre d'octets big-endian. Par exemple, 
set str \x00\x00\x00\x05\x00\x00\x00\x07\xff\xff\xff\xf0
binary scan $str I2I* var1 var2
renverra 2 avec 5 7 stockés dans var1 et -16 stocké dans var2.
n
Les données sont interprétées comme count entiers signés de 32 bits représentés dans l'ordre d'octets natif de la machine exécutant le script Tcl. C'est sinon identique à i et I. Pour déterminer quel est l'ordre d'octets natif de la machine, référez-vous à l'élément byteOrder du tableau tcl_platform.
w
Les données sont interprétées comme count entiers signés de 64 bits représentés en ordre d'octets little-endian. Les entiers sont stockés dans la variable correspondante sous forme de liste. Si count est *, alors tous les octets restants dans string seront lus. Si count est omis, alors un entier de 64 bits sera lu. Par exemple, 
set str \x05\x00\x00\x00\x07\x00\x00\x00\xf0\xff\xff\xff
binary scan $str wi* var1 var2
renverra 2 avec 30064771077 stockés dans var1 et -16 stocké dans var2. Notez que les entiers retournés sont signés et ne peuvent pas être représentés par Tcl sous forme de valeurs non signées.
W
Cette forme est identique à w sauf que les données sont interprétées comme count entiers signés de 64 bits représentés en ordre d'octets big-endian. Par exemple, 
set str \x00\x00\x00\x05\x00\x00\x00\x07\xff\xff\xff\xf0
binary scan $str WI* var1 var2
renverra 2 avec 21474836487 stockés dans var1 et -16 stocké dans var2.
m
Les données sont interprétées comme count entiers signés de 64 bits représentés dans l'ordre d'octets natif de la machine exécutant le script Tcl. C'est sinon identique à w et W. Pour déterminer quel est l'ordre d'octets natif de la machine, référez-vous à l'élément byteOrder du tableau tcl_platform.
f
Les données sont interprétées comme count nombres à virgule flottante de précision simple dans la représentation native de la machine. Les nombres à virgule flottante sont stockés dans la variable correspondante sous forme de liste. Si count est *, alors tous les octets restants dans string seront lus. Si count est omis, alors un nombre à virgule flottante de précision simple sera lu. La taille d'un nombre à virgule flottante peut varier selon les architectures, donc le nombre d'octets lus peut varier. Si les données ne représentent pas un nombre à virgule flottante valide, la valeur résultante est indéfinie et dépend du compilateur. Par exemple, sur un système Windows exécutant un processeur Intel Pentium, 
binary scan \x3f\xcc\xcc\xcd f var1
renverra 1 avec 1.6000000238418579 stocké dans var1.
r
Cette forme est identique à f sauf que les données sont interprétées comme count nombres à virgule flottante de précision simple en ordre little-endian. Cette conversion n'est pas portable vers la minorité de systèmes n'utilisant pas les représentations en virgule flottante IEEE.
R
Cette forme est identique à f sauf que les données sont interprétées comme count nombres à virgule flottante de précision simple en ordre big-endian. Cette conversion n'est pas portable vers la minorité de systèmes n'utilisant pas les représentations en virgule flottante IEEE.
d
Cette forme est identique à f sauf que les données sont interprétées comme count nombres à virgule flottante de double précision dans la représentation native de la machine. Par exemple, sur un système Windows exécutant un processeur Intel Pentium, 
binary scan \x9a\x99\x99\x99\x99\x99\xf9\x3f d var1
renverra 1 avec 1.6000000000000001 stocké dans var1.
q
Cette forme est identique à d sauf que les données sont interprétées comme count nombres à virgule flottante de double précision en ordre little-endian. Cette conversion n'est pas portable vers la minorité de systèmes n'utilisant pas les représentations en virgule flottante IEEE.
Q
Cette forme est identique à d sauf que les données sont interprétées comme count nombres à virgule flottante de double précision en ordre big-endian. Cette conversion n'est pas portable vers la minorité de systèmes n'utilisant pas les représentations en virgule flottante IEEE.
x
Déplace le curseur de count octets en avant dans string. Si count est * ou est supérieur au nombre d'octets après la position actuelle du curseur, alors le curseur est positionné après le dernier octet de string. Si count est omis, alors le curseur est déplacé d'un octet en avant. Notez que ce type ne consomme pas d'argument. Par exemple, 
binary scan \x01\x02\x03\x04 x2H* var1
renverra 1 avec 0304 stocké dans var1.
X
Déplace le curseur de count octets en arrière dans string. Si count est * ou est supérieur à la position actuelle du curseur, alors le curseur est positionné à l'emplacement 0 de sorte que le prochain octet lu soit le premier octet de string. Si count est omis, alors le curseur est déplacé d'un octet en arrière. Notez que ce type ne consomme pas d'argument. Par exemple, 
binary scan \x01\x02\x03\x04 c2XH* var1 var2
renverra 2 avec 1 2 stockés dans var1 et 020304 stockés dans var2.
@
Déplace le curseur à l'emplacement absolu dans la chaîne de données spécifié par count. Notez que la position 0 fait référence au premier octet de string. Si count fait référence à une position au-delà de la fin de string, alors le curseur est positionné après le dernier octet. Si count est omis, alors une erreur sera générée. Par exemple, 
binary scan \x01\x02\x03\x04 c2@1H* var1 var2
renverra 2 avec 1 2 stockés dans var1 et 020304 stockés dans var2.

PROBLÈMES DE PORTABILITÉ

Les conversions r, R, q et Q ne fonctionneront de manière fiable que pour le transfert de données entre ordinateurs qui utilisent tous des représentations en virgule flottante IEEE. Ceci est très courant, mais pas universel. Pour transférer des nombres à virgule flottante de manière portable entre toutes les architectures, utilisez plutôt leur représentation textuelle (telle que produite par format).

EXEMPLES

Voici une procédure pour écrire une chaîne Tcl dans un canal codé en binaire en tant que données UTF-8 précédées d'un mot de longueur :

proc writeString {channel string} {
    set data [encoding convertto utf-8 $string]
    puts -nonewline [binary format Ia* \
            [string length $data] $data]
}

Cette procédure lit une chaîne depuis un canal qui a été écrit par la procédure writeString précédemment présentée :

proc readString {channel} {
    if {![binary scan [read $channel 4] I length]} {
        error "longueur manquante"
    }
    set data [read $channel $length]
    return [encoding convertfrom utf-8 $data]
}

Ceci convertit le contenu d'un fichier (nommé dans la variable filename) en base64 et l'affiche :

set f [open $filename rb]
set data [read $f]
close $f
puts [binary encode base64 -maxlen 64 $data]
