btparse maintient une seule table de toutes les macros (abréviations) rencontrées lors de l'analyse des entrées BibTeX. Il met à jour cette table chaque fois qu'il rencontre une « définition

de macro » (

@string), et s'y réfère chaque fois qu'une macro est utilisée dans une entrée et doit être développée. (Les macros ne sont pas nécessairement développées à l'entrée, bien que ce soit le comportement par défaut. Voir bt_postprocess.) Les définitions de macro ne sont effacées que lorsquela fonction de nettoyage globale de btparse, bt_cleanup(), est appelée. Ainsi, sauf si vous appelez explicitement bt_delete_macro() ou bt_delete_all_macros(), les définitions de macro persistent aussi longtemps que vous utilisez la bibliothèque---généralement, pour la durée de vie de votre processus. Vous pouvez utiliser les fonctions suivantes pour ajouter des macros, les supprimer, et interroger leurs valeurs---interférant

ainsi avec

le fonctionnement normal de btparse à la volée. bt_add_macro_text

()
void bt_add_macro_text (char * macro, char * text, char * filename,
int line); 
Définit une nouvelle macro, ou redéfinit une
ancienne.

« macro » est le nom de la macro, et « text » est le texte vers lequel elle doit se développer. « filename » et « line » sont utilisés uniquement pour générer les avertissements concernant la définition de la macro ; s'ils ne s'appliquent pas, spécifiez « NULL » pour « filename » et 0 pour « line ». Le seul avertissement de ce type se produit lorsque vous redéfinissez une ancienne macro : sa valeur est écrasée, et bt_add_macro_text() émet un avertissement le signalant. Par exemple, lors de l'analyse de cette entrée de définition de

macro :

@string{fubar = "Fouled Up Beyond All

Recognition"} 
la bibliothèque (en particulier, le code de post-traitement appelé
        après qu'une entrée a été analysée avec succès) finira par
faire ceci :

bt_add_macro_text ("fubar", "Fouled Up Beyond All Recognition", filename,

line); 
Cela entraînera à son tour le développement approprié de la
macro

« fubar » chaque fois que le code de post-traitement la verra dans de futures entrées. bt_add_macro

_value
()
void bt_add_macro_value (AST * assignment, btshort
options); 
Cette fonction est principalement destinée à un usage interne par la bibliothèque, mais
        elle est disponible pour vous si vous vous retrouvez un jour avec un petit AST
        représentant une définition de macro, et que vous voulez définir la macro vous-même
        (plutôt que de laisser le code de post-traitement de la bibliothèque s'en charger
pour vous).

« assignment » doit être un nœud AST tel que renvoyé par bt_next_field(). Contrairement à la plupart des autres fonctions de btparse qui prennent un argument « options », ici « options » indique comment la valeur dans « assignment » a été post-traitée. Cela est nécessaire car les valeurs de macro doivent être traitées d'une manière spéciale pour être valides dans de futurs développements ; si celle-ci n'a pas été traitée de cette façon, bt_add_macro_value() le fera pour vous. Si vous ne savez pas comment la valeur a été post-traitée, fournissez simplement 0 pour « options »---c'est garanti pour décrire quelque chose de différent de « la bonne façon » pour les macros, de sorte que le post-traitement sera effectué

correctement.

Le traitement effectué sur les valeurs de macro vise principalement à garantir que nous pouvons nous contenter de stocker une simple chaîne dans la table des macros : les macros invoquées par la macro sont elles-mêmes développées, et toutes les sous-chaînes sont concaténées. Par exemple, si btparse analyse ces

entrées : 
@string{and = " and "}
@string{jim_n_bob = "James Smith" # and # "Bob
Jones"}

alors la valeur stockée pour « jim_n_bob » devrait évidemment être la chaîne « James Smith and Bob Jones ». Pour garantir cela, btparse doit traiter la valeur de « and » différemment de la plupart des chaînes BibTeX : en particulier, les espaces ne sont pas réduits avant que la chaîne soit stockée. De cette façon, la valeur correcte, « and », est interpolée dans la valeur de « jim_n_bob ». Ainsi, toutes les valeurs de macro ont les sous-macros développées et les chaînes concaténées avant d'être stockées, mais les espaces ne sont pas réduits tant que la macro n'est pas utilisée dans une entrée

régulière.

Cette fonction appelle bt_add_macro_text(), donc la même réserve concernant la redéfinition des anciennes

macros s'applique---un avertissement sera ém
is, et l'ancienne valeur sera perdue.
