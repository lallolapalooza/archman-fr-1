DESCRIPTIO

N

BN_generate_prime_ex2() génère un nombre premier pseudo-aléatoire d'une longueur en bits d'au moins bits en utilisant le BN_CTX fourni dans ctx. La valeur de ctx ne doit pas être

NULL.

Le nombre retourné est probablement premier avec une erreur négligeable. Le taux d'erreur maximal est de 2^-128. Il est de 2^-287 pour un premier de 512 bits, 2^-435 pour un premier de 1024 bits, 2^-648 pour un premier de 2048 bits, et inférieur à 2^-882 pour les premiers de plus de 2048

bits.

Si add est NULL, le nombre premier retourné aura une longueur en bits exacte de bits avec les deux bits de poids fort

définis.

Si ret n'est pas NULL, il sera utilisé pour stocker le

nombre.

Si cb n'est pas NULL, il est utilisé comme suit

:
  • BN_GENCB_call(cb, 0, i) est appelé après la génération du i-ème nombre premier
    • potentiel.
  • Pendant que le nombre est testé pour sa primalité, BN_GENCB_call(cb, 1, j) est appelé comme décrit
    • ci-dessous.
  • Quand un premier a été trouvé, BN_GENCB_call(cb, 2, i) est
    • appelé.
  • Les appelants de BN_generate_prime_ex() peuvent appeler BN_GENCB_call(cb, i, j) avec d'autres valeurs comme décrit dans leurs pages manuelles respectives ; voir « VOIR AUSSI
    • »
.

Le premier peut devoir satisfaire des exigences supplémentaires pour être utilisé dans l'échange de clés Diffie-Hellman

:

Si add n'est pas NULL, le premier satisfera la condition p % add == rem (p % add == 1 si rem == NULL) afin de convenir à un générateur

donné.

Si safe est vrai, ce sera un premier sûr (c'est-à-dire un premier p tel que (p-1)/2 est aussi premier). Si safe est vrai, et rem == NULL, la condition sera p % add == 3. Il est recommandé que add soit un multiple de

4.

Le générateur aléatoire doit être initialisé avant d'appeler BN_generate_prime_ex(). Si l'initialisation automatique ou la réinitialisation du CSPRNG d'OpenSSL échoue en raison de circonstances externes (voir RAND(7)), l'opération échouera. Le générateur de nombres aléatoires configuré pour le OSSL_LIB_CTX associé à ctx sera

utilisé.

BN_generate_prime_ex() est identique à BN_generate_prime_ex2() sauf qu'aucun paramètre ctx n'est passé. Dans ce cas, le générateur de nombres aléatoires associé au OSSL_LIB_CTX par défaut sera

utilisé.

BN_check_prime(), BN_is_prime_ex(), BN_is_prime_fasttest_ex(), BN_is_prime() et BN_is_prime_fasttest() testent si le nombre p est premier. Les fonctions effectuent les tests jusqu'à ce que l'un des tests montre que p est composé, ou que tous les tests sont passés. Si p passe tous ces tests, il est considéré comme un premier

probable.

Les tests effectués sur p sont la division d'essai par un certain nombre de petits premiers et des tours du test de primalité probabiliste de

Miller-Rabin.

Les fonctions effectuent au moins 64 tours du test de Miller-Rabin donnant un taux de faux positif maximal de 2^-128. Si la taille de p est supérieure à 2048 bits, elles effectuent au moins 128 tours donnant un taux de faux positif maximal de

2^-256.

Si nchecks est supérieur au minimum ci-dessus (64 ou 128), nchecks tours du test de Miller-Rabin seront

effectués.

Si do_trial_division est défini à 0, la division d'essai sera ignorée. BN_is_prime_ex() et BN_is_prime() ignorent toujours la division

d'essai.

BN_is_prime_ex(), BN_is_prime_fasttest_ex(), BN_is_prime() et BN_is_prime_fasttest() sont

obsolètes.

BN_is_prime_fasttest() et BN_is_prime() se comportent exactement comme BN_is_prime_fasttest_ex() et BN_is_prime_ex() respectivement, mais avec un rappel à l'ancien

style.

ctx est un BN_CTX pré-alloué (pour économiser le surcoût d'allocation et de libération de la structure dans une boucle), ou NULL

.

Si la division d'essai est effectuée, et qu'aucun diviseur n'est trouvé et cb n'est pas NULL, BN_GENCB_call(cb, 1, -1) est

appelé.

Après chaque tour du test de primalité probabiliste de Miller-Rabin, si cb n'est pas NULL, BN_GENCB_call(cb, 1, j) est appelé avec j l'itération (j = 0, 1, ...)

.

BN_GENCB_call() appelle la fonction de rappel contenue dans la structure BN_GENCB et passe les entiers a et b en tant qu' arguments. Il existe deux types de structures BN_GENCB qui sont supportés : le style « nouveau » et le style « ancien ». Les nouveaux programmes devraient préférer le style « nouveau », tandis que le style « ancien » est fourni à des fins de compatibilité

ascendante.

Une structure BN_GENCB devrait être créée par un appel à BN_GENCB_new(), et libérée par un appel à BN_GENCB_free(). Si l'argument est NULL, rien n'est

fait.

Pour les rappels de style « nouveau », une structure BN_GENCB devrait être initialisée par un appel à BN_GENCB_set(), où gencb est un BN_GENCB *, callback est de type int (*callback)(int, int, BN_GENCB *) et cb_arg est un void *. Les rappels de style « ancien » sont les mêmes sauf qu'ils sont initialisés par un appel à BN_GENCB_set_old() et callback est de type void (*callback)(int, int, void *)

.

Un rappel est invoqué par un appel à BN_GENCB_call. Cela vérifiera le type du rappel et invoquera callback(a, b, gencb) pour les rappels de style nouveau ou callback(a, b, cb_arg) pour le style

ancien.

Il est possible d'obtenir l'argument associé à une structure BN_GENCB (défini via un appel à BN_GENCB_set ou BN_GENCB_set_old) en utilisant BN_GENCB_get_arg

.

BN_generate_prime() (obsolète) fonctionne de la même manière que BN_generate_prime_ex() mais attend une fonction de rappel à l'ancien style directement dans le paramètre callback, et un argument à lui passer dans le cb_arg. BN_is_prime() et BN_is_prime_fasttest() peuvent de même être comparés à BN_is_prime_ex() et BN_is_prime_fasttest_

ex(), respe
ctivement.

VALEURS

RETOURNÉES

BN_generate_prime_ex() retourne 1 en cas de succès ou 0 en cas

d'erreur.

BN_is_prime_ex(), BN_is_prime_fasttest_ex(), BN_is_prime(), BN_is_prime_fasttest() et BN_check_prime retournent 0 si le nombre est composé, 1 s'il est premier avec une probabilité d'erreur inférieure à 0.25^nchecks, et -1 en cas

d'erreur.

BN_generate_prime() retourne le nombre premier en cas de succès, NULL si

non.

BN_GENCB_new renvoie un pointeur vers une structure BN_GENCB en cas de succès, ou NULL si

non.

BN_GENCB_get_arg renvoie l'argument précédemment associé à une structure

BN_GENCB.

Les fonctions de rappel doivent renvoyer 1 en cas de succès ou 0 en cas

d'erreur.

Les codes d'erreur peuvent être obtenus par ERR_get_

error
(3).
