bpf(2) Manuel des appels système bpf(2)

NOM

bpf - effectuer une commande sur une carte ou un programme eBPF étendu

SYNTAXE

#include <linux/bpf.h>
int bpf(int cmd, union bpf_attr *attr, unsigned int size);

DESCRIPTION

L'appel système bpf() effectue une gamme d'opérations liées aux filtres Berkeley Packet Filters étendus. Le Extended Berkeley Packet Filter (eBPF) est similaire au BPF original ("classique") (cBPF) utilisé pour filtrer les paquets réseau. Pour les programmes cBPF et eBPF, le noyau analyse statiquement les programmes avant de les charger, afin de s'assurer qu'ils ne peuvent pas nuire au système en cours d'exécution.

eBPF étend cBPF de plusieurs manières, notamment la capacité d'appeler un ensemble fixe de fonctions d'aide internes au noyau (via l'extension d'opcode BPF_CALL fournie par eBPF) et d'accéder à des structures de données partagées telles que les cartes eBPF.

Conception/Architecture eBPF étendu

Les cartes eBPF sont une structure de données générique pour le stockage de différents types de données. Les types de données sont généralement traités comme des blobs binaires, de sorte qu'un utilisateur spécifie simplement la taille de la clé et la taille de la valeur au moment de la création de la carte. En d'autres termes, une clé/valeur pour une carte donnée peut avoir une structure arbitraire.

Un processus utilisateur peut créer plusieurs cartes (avec des paires clé/valeur étant des octets de données opaques) et y accéder via des descripteurs de fichiers. Différents programmes eBPF peuvent accéder aux mêmes cartes en parallèle. Il appartient au processus utilisateur et au programme eBPF de décider de ce qu'ils stockent dans les cartes.

Il existe un type de carte spécial, appelé tableau de programmes. Ce type de carte stocke des descripteurs de fichiers faisant référence à d'autres programmes eBPF. Lorsqu'une recherche dans la carte est effectuée, le flux du programme est redirigé sur place vers le début d'un autre programme eBPF et ne revient pas au programme appelant. Le niveau d'imbrication a une limite fixe de 32, de sorte que des boucles infinies ne peuvent pas être créées. Au moment de l'exécution, les descripteurs de fichiers de programme stockés dans la carte peuvent être modifiés, de sorte que la fonctionnalité du programme peut être altérée en fonction des exigences spécifiques. Tous les programmes référencés dans une carte de tableau de programmes doivent avoir été préalablement chargés dans le noyau via bpf(). Si une recherche de carte échoue, le programme en cours continue son exécution. Voir BPF_MAP_TYPE_PROG_ARRAY ci-dessous pour plus de détails.

Généralement, les programmes eBPF sont chargés par le processus utilisateur et automatiquement déchargés lorsque le processus se termine. Dans certains cas, par exemple, tc-bpf(8), le programme continue de rester actif dans le noyau même après la sortie du processus qui a chargé le programme. Dans ce cas, le sous-système tc conserve une référence au programme eBPF après que le descripteur de fichier a été fermé par le programme user-space. Ainsi, qu'un programme spécifique continue de vivre dans le noyau dépend de la manière dont il est attaché à un sous-système du noyau donné après avoir été chargé via bpf().

Chaque programme eBPF est un ensemble d'instructions dont l'exécution est sûre jusqu'à son achèvement. Un vérificateur interne au noyau détermine statiquement que le programme eBPF se termine et est sûr à exécuter. Pendant la vérification, le noyau incrémente les compteurs de références pour chacune des cartes que le programme eBPF utilise, de sorte que les cartes attachées ne peuvent pas être supprimées tant que le programme n'est pas déchargé.

Les programmes eBPF peuvent être attachés à différents événements. Ces événements peuvent être l'arrivée de paquets réseau, des événements de traçage, des événements de classification par les files d'attente de mise en réseau (pour les programmes eBPF attachés à un classificateur tc(8)), et d'autres types qui pourraient être ajoutés à l'avenir. Un nouvel événement déclenche l'exécution du programme eBPF, qui peut stocker des informations sur l'événement dans des cartes eBPF. Au-delà du stockage de données, les programmes eBPF peuvent appeler un ensemble fixe de fonctions d'aide internes au noyau.

Le même programme eBPF peut être attaché à plusieurs événements et différents programmes eBPF peuvent accéder à la même carte :

Arguments

L'opération à effectuer par l'appel système bpf() est déterminée par l'argument cmd. Chaque opération prend un argument correspondant, fourni via attr, qui est un pointeur vers une union de type bpf_attr (voir ci-dessous). Les champs inutilisés et le remplissage doivent être mis à zéro avant l'appel. L'argument size est la taille de l'union pointée par attr.

La valeur fournie dans cmd est l'une des suivantes :

BPF_MAP_CREATE
Crée une carte et renvoie un descripteur de fichier faisant référence à la carte. L'indicateur de fichier close-on-exec (voir fcntl(2)) est automatiquement activé pour le nouveau descripteur de fichier.
BPF_MAP_LOOKUP_ELEM
Recherche un élément par sa clé dans une carte spécifiée et renvoie sa valeur.
BPF_MAP_UPDATE_ELEM
Crée ou met à jour un élément (paire clé/valeur) dans une carte spécifiée.
BPF_MAP_DELETE_ELEM
Recherche et supprime un élément par sa clé dans une carte spécifiée.
BPF_MAP_GET_NEXT_KEY
Recherche un élément par sa clé dans une carte spécifiée et renvoie la clé de l'élément suivant.
BPF_PROG_LOAD
Vérifie et charge un programme eBPF, renvoyant un nouveau descripteur de fichier associé au programme. L'indicateur de fichier close-on-exec (voir fcntl(2)) est automatiquement activé pour le nouveau descripteur de fichier.
L'union bpf_attr se compose de diverses structures anonymes qui sont utilisées par différentes commandes bpf() :


union bpf_attr {
    struct {    /* Utilisé par BPF_MAP_CREATE */
        __u32         map_type;
        __u32         key_size;    /* taille de la clé en octets */
        __u32         value_size;  /* taille de la valeur en octets */
        __u32         max_entries; /* nombre maximum d'entrées
                                      dans une carte */
    };
    struct {    /* Utilisé par les commandes BPF_MAP_*_ELEM et BPF_MAP_GET_NEXT_KEY
                   */
        __u32         map_fd;
        __aligned_u64 key;
        union {
            __aligned_u64 value;
            __aligned_u64 next_key;
        };
        __u64         flags;
    };
    struct {    /* Utilisé par BPF_PROG_LOAD */
        __u32         prog_type;
        __u32         insn_cnt;
        __aligned_u64 insns;      /* 'const struct bpf_insn *' */
        __aligned_u64 license;    /* 'const char *' */
        __u32         log_level;  /* niveau de verbosité du vérificateur */
        __u32         log_size;   /* taille du tampon utilisateur */
        __aligned_u64 log_buf;    /* tampon 'char *' fourni par l'utilisateur
                                     */
        __u32         kern_version;
                                  /* vérifié lorsque prog_type=kprobe
                                     (depuis Linux 4.1) */
    };
} __attribute__((aligned(8)));

Cartes eBPF

Les cartes sont une structure de données générique pour le stockage de différents types de données. Elles permettent le partage de données entre les programmes eBPF du noyau, et aussi entre le noyau et les applications user-space.

Chaque type de carte a les attributs suivants :

•
type
•
nombre maximum d'éléments
•
taille de la clé en octets
•
taille de la valeur en octets

Les fonctions d'encapsulation suivantes montrent comment diverses commandes bpf() peuvent être utilisées pour accéder aux cartes. Les fonctions utilisent l'argument cmd pour invoquer différentes opérations.

BPF_MAP_CREATE
Crée une nouvelle carte, puis renvoie un descripteur de fichier pour celle-ci.
BPF_MAP_LOOKUP_ELEM
Recherche un élément dans une carte donnée par sa clé.
BPF_MAP_UPDATE_ELEM
Ajoute ou met à jour une paire clé/valeur dans une carte donnée.
BPF_MAP_DELETE_ELEM
Supprime un élément d'une carte donnée par sa clé.
BPF_PROG_LOAD
Charge un programme eBPF donné dans le noyau.
BPF_OBJ_PIN
Permet de "épingler" un objet eBPF (programme ou carte) dans le système de fichiers bpffs, afin qu'il ne soit pas déchargé lorsque le dernier descripteur de fichier est fermé. L'objet peut ensuite être rechargé via BPF_OBJ_GET.
BPF_OBJ_GET
Récupère un objet eBPF précédemment épinglé via BPF_OBJ_PIN.
BPF_PROG_TEST_RUN
Exécute un programme eBPF dans un environnement isolé pour des tests.

Erreurs

Les erreurs courantes incluent :

EINVAL
Commande ou type de carte/programme invalide, ou arguments invalides.
EPERM
Permissions insuffisantes pour effectuer l'opération.
ENOMEM
Pas assez de mémoire pour allouer la carte ou charger le programme.
EEXIST
La carte ou le programme existe déjà.
ENOENT
La clé n'a pas été trouvée dans la carte.

EXEMPLE

L'exemple suivant montre comment créer une carte HASH, y mettre à jour un élément, puis le rechercher.

#include <stdio.h>
#include <stdlib.h>
#include <string.h>
#include <unistd.h>
#include <linux/bpf.h>
#include "bpf_helpers.h" // Fonctions d'aide pour les opérations BPF

// Structure pour les attributs de création de carte
struct bpf_map_create_attr {
    __u32 map_type;
    __u32 key_size;
    __u32 value_size;
    __u32 max_entries;
};

// Structure pour les attributs de mise à jour/recherche d'élément
struct bpf_map_update_attr {
    __u32 map_fd;
    __aligned_u64 key;
    __aligned_u64 value;
    __u64 flags;
};

// Structure pour les attributs de recherche d'élément
struct bpf_map_lookup_attr {
    __u32 map_fd;
    __aligned_u64 key;
    __aligned_u64 value;
};

int main() {
    int map_fd;
    long ret;
    
    // Créer une carte HASH
    struct bpf_map_create_attr map_create_opts = {
        .map_type = BPF_MAP_TYPE_HASH,
        .key_size = sizeof(int),
        .value_size = sizeof(int),
        .max_entries = 1,
    };

    // Utiliser le wrapper bpf_map_create (supposons qu'il existe dans bpf_helpers.h)
    // Sinon, utiliser directement l'appel système bpf()
    map_fd = bpf(BPF_MAP_CREATE, &map_create_opts, sizeof(map_create_opts));
    if (map_fd < 0) {
        perror("BPF_MAP_CREATE failed");
        return 1;
    }

    // Mettre à jour un élément
    int key = 1;
    int value = 10;
    struct bpf_map_update_attr map_update_opts = {
        .map_fd = map_fd,
        .key = (__aligned_u64)&key,
        .value = (__aligned_u64)&value,
        .flags = 0, // BPF_ANY pour écraser, BPF_NOEXIST pour ne pas écraser
    };

    ret = bpf(BPF_MAP_UPDATE_ELEM, &map_update_opts, sizeof(map_update_opts));
    if (ret < 0) {
        perror("BPF_MAP_UPDATE_ELEM failed");
        close(map_fd);
        return 1;
    }

    // Rechercher l'élément
    int found_value;
    struct bpf_map_lookup_attr map_lookup_opts = {
        .map_fd = map_fd,
        .key = (__aligned_u64)&key,
        .value = (__aligned_u64)&found_value, // Pointeur vers où stocker la valeur
    };

    ret = bpf(BPF_MAP_LOOKUP_ELEM, &map_lookup_opts, sizeof(map_lookup_opts));
    if (ret < 0) {
        perror("BPF_MAP_LOOKUP_ELEM failed");
        close(map_fd);
        return 1;
    }

    printf("Key: %d, Found Value: %d\n", key, found_value);

    close(map_fd);
    return 0;
}

Une carte de tableau de programmes est un type spécial de carte de tableau dont les valeurs ne contiennent que des descripteurs de fichier faisant référence à d'autres programmes eBPF. Cela signifie qu'un programme eBPF auquel est attachée une carte de tableau de programmes peut appeler depuis le côté

                   unsigned int

et ainsi remplacer son propre flux d'exécution par celui du programme situé à l'emplacement de tableau de programmes donné, s'il existe. Cela peut être considéré comme une sorte de table de saut vers un autre programme eBPF. Le programme invoqué réutilisera alors la même pile. Une fois le saut vers le nouveau programme effectué, il ne retournera plus à l'ancien
programme.
Si aucun programme eBPF n'est trouvé à l'index donné du tableau de programmes (parce que l'emplacement de la carte ne contient pas un descripteur de fichier de programme valide, l'index/clé de recherche spécifié est hors limites, ou la limite de 32 appels imbriqués a été dépassée), l'exécution se poursuit avec le programme eBPF courant. Cela peut être utilisé comme une exécution par défaut pour les cas par

Une carte de tableau de programmes est utile, par exemple, pour le traçage ou le réseau, afin de gérer des appels système ou des protocoles individuels dans leurs propres sous-

Les cartes sont accessibles depuis les programmes eBPF et sont utilisées pour échanger des données entre les programmes eBPF et entre les programmes eBPF et les programmes en espace utilisateur. Par exemple, les programmes eBPF

peuvent traiter divers événements (comme kprobe, paquets) et stocker leurs données dans une carte, et les programmes en espace utilisateur peuvent ensuite récupérer les données de la carte. Inversement, les programmes en
espace utilisateur peuvent utiliser une carte comme mécanisme de configuration, en remplissant la carte avec des valeurs vérifiées par le programme eBPF, qui modifie alors son comportement à la volée en fonction de ces valeurs.

types de programmes

eBPF

Le type de programme eBPF (prog_type) détermine le sous-ensemble de fonctions d'assistance du noyau que le programme peut appeler. Le type de programme détermine également l'entrée du programme (contexte)—le format de struct bpf_context (qui est le bloc de données passé au programme eBPF en tant que premier argument)

.

Par exemple, un programme de traçage n'a pas exactement le même sous-ensemble de fonctions d'assistance qu'un programme de filtre de socket (bien qu'ils puissent avoir certaines fonctions d'assistance en commun). De même, l'entrée (contexte) pour un programme de traçage est un ensemble de valeurs de registres, tandis que pour un filtre de socket c'est un paquet

réseau.

l'avenir.

 *    map[r0]++

main(int argc, char *argv[])
{
    int sock, map_fd, prog_fd, key;
    long long value = 0, tcp_cnt, udp_cnt;
    map_fd = bpf_create_map(BPF_MAP_TYPE_ARRAY, sizeof(key),
                            sizeof(value), 256);
    if (map_fd < 0) {
        printf("échec de la création de la carte '%s'\n", strerror(errno));
        /* probablement pas exécuté en tant que root */
        return 1;
    }

        BPF_MOV64_REG(BPF_REG_6, BPF_REG_1),        /* r6 = r1 */

                                /* r0 = ip->proto */
        BPF_STX_MEM(BPF_W, BPF_REG_10, BPF_REG_0, -4),
                                /* *(u32 *) (fp - 4) = r0 */

        BPF_MOV64_IMM(BPF_REG_0, 0),                /* r0 = 0 */
        BPF_EXIT_INSN(),                            /* return r0 */
    };
    prog_fd = bpf_prog_load(BPF_PROG_TYPE_SOCKET_FILTER, prog,
                            NITEMS(prog), "GPL")
