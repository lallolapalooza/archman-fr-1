DESCRIPTIO

N

BIO_f_ssl() renvoie la méthode BIO SSL. Il s'agit d'un BIO filtre qui est un enveloppement des routines SSL d'OpenSSL ajoutant une « saveur » BIO aux E/S

SSL.

Les E/S effectuées sur un BIO SSL communiquent en utilisant le protocole SSL avec les BIO de lecture et d'écriture SSL. Si une connexion SSL n'est pas établie, une tentative est faite pour en établir une lors du premier appel

d'E/S.

Si un BIO est ajouté à un BIO SSL en utilisant BIO_push(), il est automatiquement utilisé comme les BIO de lecture et d'écriture du BIO

SSL.

Appeler BIO_reset() sur un BIO SSL ferme toute connexion SSL en cours en appelant SSL_shutdown(). BIO_reset() est ensuite envoyé au BIO suivant dans la chaîne : cela déconnectera généralement le transport sous-jacent. Le BIO SSL est ensuite réinitialisé à l'état initial d'acceptation ou de

connexion.

Si l'indicateur de fermeture est défini lorsqu'un BIO SSL est libéré, la structure SSL interne est également libérée en utilisant SSL_fre

e().

BIO_set_ssl() définit le pointeur SSL interne du BIO SSL b à ssl en utilisant l'indicateur de fermeture c

.

BIO_get_ssl() récupère le pointeur SSL du BIO SSL b, qui peut ensuite être manipulé en utilisant les fonctions standard de la bibliothèque

SSL.

BIO_set_ssl_mode() définit le mode du BIO SSL à client. Si client vaut 1, le mode client est défini. Si client vaut 0, le mode serveur est

défini.

BIO_set_ssl_renegotiate_bytes() définit le nombre d'octets de renégociation du BIO SSL b à num. Une fois défini, après chaque num octets d'E/S (lecture et écriture), la session SSL est automatiquement renégociée. num doit être d'au moins 512

octets.

BIO_set_ssl_renegotiate_timeout() définit le délai d'attente de renégociation du BIO SSL b à seconds. Lorsque le délai de renégociation expire, la session est automatiquement

renégociée.

BIO_get_num_renegotiates() renvoie le nombre total de renégociations de session dues aux E/S ou au délai d'attente du BIO SSL b

.

BIO_new_ssl() alloue un BIO SSL en utilisant SSL_CTX ctx et en utilisant le mode client si client est non

nul.

BIO_new_ssl_connect() crée une nouvelle chaîne BIO composée d'un BIO SSL (utilisant ctx) suivi d'un BIO de

connexion.

BIO_new_buffer_ssl_connect() crée une nouvelle chaîne BIO composée d'un BIO avec tampon, d'un BIO SSL (utilisant ctx) et d'un BIO de

connexion.

BIO_ssl_copy_session_id() copie un identifiant de session SSL entre les chaînes BIO from et to. Il le fait en localisant les BIO SSL dans chaque chaîne et en appelant SSL_copy_session_id() sur le pointeur SSL

interne.

BIO_ssl_shutdown() ferme une connexion SSL sur la chaîne BIO bio. Il le fait en localisant le BIO SSL dans la chaîne et en appelant SSL_shutdown() sur son pointeur SSL

interne.

BIO_do_handshake() tente de compléter une poignée de main SSL sur le BIO fourni et d'établir la connexion SSL. Pour les BIO non SSL, la connexion se fait généralement au niveau TCP. Si la résolution de nom de domaine renvoie plusieurs adresses IP, toutes sont essayées après des échecs de connect(). La fonction renvoie 1 si la connexion a été établie avec succès. Une valeur nulle ou négative est renvoyée si la connexion n'a pas pu être établie. L'appel BIO_should_retry() doit être utilisé pour les BIO de connexion non bloquants afin de déterminer

si l'appel doit être réessayé. Si une connex
ion a déjà été établie, cet appel n'a aucun effet.

NOTE

S

Les BIO SSL sont exceptionnels en ce sens que si le transport sous-jacent est non bloquant, ils peuvent toujours demander une nouvelle tentative dans des circonstances exceptionnelles. Plus précisément, cela se produit si une renégociation de session a lieu pendant une opération BIO_read_ex(), un cas où cela se produit est lors d'une montée en gamme (step up)

.

Le drapeau SSL SSL_AUTO_RETRY peut être défini pour désactiver ce comportement. C'est-à-dire que lorsque ce drapeau est défini, un BIO SSL utilisant un transport bloquant ne demandera jamais de nouvelle

tentative.

Étant donné que les opérations BIO_ctrl() inconnues sont envoyées à travers les BIO filtres, le nom et le port du serveur peuvent être définis en utilisant BIO_set_host() sur le BIO renvoyé par BIO_new_ssl_connect() sans avoir à localiser le BIO de connexion au

préalable.

Les applications n'ont pas besoin d'appeler BIO_do_handshake() mais peuvent souhaiter le faire pour séparer le processus de poignée de main du reste du traitement des

E/S.

BIO_set_ssl(), BIO_get_ssl(), BIO_set_ssl_mode(), BIO_set_ssl_renegotiate_bytes(), BIO_set_ssl_renegotiate_timeout(), BIO_get_num_renegotiates(), et BIO_do_handshake() sont implémentés en tant que

macros.

BIO_ssl_copy_session_id() n'est actuellement pas pris en charge sur

les objets SSL QUIC et échoue
s'il est appelé sur un tel objet.

VALEURS

RENVOYÉES

BIO_f_ssl() renvoie la structure BIO_METHOD

SSL.

BIO_set_ssl(), BIO_get_ssl(), BIO_set_ssl_mode(), BIO_set_ssl_renegotiate_bytes(), BIO_set_ssl_renegotiate_timeout() et BIO_get_num_renegotiates() renvoient 1 en cas de succès ou une valeur inférieure ou égale à 0 si une erreur s'est

produite.

QUIC.

BIO_do_handshake() renvoie 1 si la connexion a été établie avec succès. Une v

aleur nulle ou négative est renvoyée si l
a connexion n'a pas pu être établie.

EXEMPLE

S

Cet exemple de client SSL/TLS tente de récupérer une page d'un serveur web SSL/TLS. Les routines d'E/S sont identiques à celles de l'exemple non chiffré dans BIO_s_conne

ct(3). 
BIO *sbio, *out;
int len;
char tmpbuf[1024];
SSL_CTX *ctx;
SSL *ssl;
/* XXX Seed the PRNG if needed. */
ctx = SSL_CTX_new(TLS_client_method());
/* XXX Set verify paths and mode here. */
sbio = BIO_new_ssl_connect(ctx);
BIO_get_ssl(sbio, &ssl);
if (ssl == NULL) {
    fprintf(stderr, "Can't locate SSL pointer\n");
    ERR_print_errors_fp(stderr);
    exit(1);
}
/* XXX We might want to do other things with ssl here */
/* An empty host part means the loopback address */
BIO_set_conn_hostname(sbio, ":https");
out = BIO_new_fp(stdout, BIO_NOCLOSE);
if (BIO_do_connect(sbio) <= 0) {
    fprintf(stderr, "Error connecting to server\n");
    ERR_print_errors_fp(stderr);
    exit(1);
}
/* XXX Could examine ssl here to get connection info */
BIO_puts(sbio, "GET / HTTP/1.0\n\n");
for (;;) {
    len = BIO_read(sbio, tmpbuf, 1024);
    if (len <= 0)
        break;
    BIO_write(out, tmpbuf, len);
}
BIO_free_all(sbio);
BIO_free(out)
;

Voici un exemple de serveur simple. Il utilise un BIO avec tampon pour permettre la lecture de lignes depuis le BIO SSL en utilisant BIO_gets. Il crée une pseudo-page web contenant la requête réelle d'un client et renvoie également la requête vers la sortie

standard. 
BIO *sbio, *bbio, *acpt, *out;
int len;
char tmpbuf[1024];
SSL_CTX *ctx;
SSL *ssl;
/* XXX Seed the PRNG if needed. */
ctx = SSL_CTX_new(TLS_server_method());
if (!SSL_CTX_use_certificate_file(ctx, "server.pem", SSL_FILETYPE_PEM)
        || !SSL_CTX_use_PrivateKey_file(ctx, "server.pem", SSL_FILETYPE_PEM)
        || !SSL_CTX_check_private_key(ctx)) {
    fprintf(stderr, "Error setting up SSL_CTX\n");
    ERR_print_errors_fp(stderr);
    exit(1);
}
/* XXX Other things like set verify locations, EDH temp callbacks. */
/* New SSL BIO setup as server */
sbio = BIO_new_ssl(ctx, 0);
BIO_get_ssl(sbio, &ssl);
if (ssl == NULL) {
    fprintf(stderr, "Can't locate SSL pointer\n");
    ERR_print_errors_fp(stderr);
    exit(1);
}
bbio = BIO_new(BIO_f_buffer());
sbio = BIO_push(bbio, sbio);
acpt = BIO_new_accept("4433");
/*
 * De cette façon, lorsqu'une nouvelle connexion est établie,
 * sbio est automatiquement inséré dans celle-ci. La
 * chaîne BIO est désormais « avalée » par le BIO accept et
 * sera libéré lorsque le BIO accept sera libéré.
 */
BIO_set_accept_bios(acpt, sbio);
out = BIO_new_fp(stdout, BIO_NOCLOSE);
/* Le premier appel à BIO_do_accept() configure le BIO accept */
if (BIO_do_accept(acpt) <= 0) {
    fprintf(stderr, "Error setting up accept BIO\n");
    ERR_print_errors_fp(stderr);
    exit(1);
}

/* Le deuxième appel à BIO_do_accept() attend une connexion entrante */
if (BIO_do_accept(acpt) <= 0) {
fprintf(stderr, "Error accepting connection\n");
ERR_print_errors_fp(stderr);
exit(1);

} 
/* Nous ne voulons qu'une seule connexion, donc nous retirons et libérons le BIO accept */
sbio = BIO_pop(acpt);
BIO_free_all(acpt);
if (BIO_do_handshake(sbio) <= 0) {
    fprintf(stderr, "Error in SSL handshake\n");
    ERR_print_errors_fp(stderr);
    exit(1);
}
BIO_puts(sbio, "HTTP/1.0 200 OK\r\
nContent-type: text/plain\r\n\r\n"); BIO_puts(sbio, "\r\nConnection Established\r\nRequest headers:\r\n"); BIO_puts(sbio, "--------------------------------------------------\r\n"); for (;;) { len = BIO_gets(sbio, tmpbuf, 1024); if (len <= 0) break; BIO_write(sbio, tmpbuf, len);
BIO_write(out, tmpbuf, len); /* Recherche d'une ligne vide indiquant la fin des en-têtes */ if (tmpbuf[0] == '\r' || tmpbuf[0] == '\n') break; } BIO_puts(sbio, "--------------------------------------------------\r\n"); BIO_puts(sbio, "\r\n"); BIO_flush(sbio); BIO_free_all(sbio);

HISTORIQU

E

Dans OpenSSL avant la version 1.0.0, l'appel BIO_pop() était géré de manière incorrecte, le compteur de références du BIO d'E/S était incrémenté par erreur (au lieu d'être décrémenté) et dissocié du BIO SSL même si le BIO SSL n'était pas explicitement retiré (par exemple, un retrait plus ha

ut dans la chaîne). Les applications qui incluaient des contournements pour ce bogue (par exemple, libérer les BIO plus d'u
ne fois) doivent être modifiées pour prendre en charge cette correction, sinon elles pourraient libérer un BIO déjà libéré.
