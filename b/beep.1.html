NOM

beep - faire biper le haut-parleur du PC de différentes manières

SYNTAXE

beep [GLOBALS] [-f FREQ] [-l LEN] [-r REPEATS] [<-d|-D> DELAY] [-s] [-c]
beep [GLOBALS] <TONE_OPTIONS> [-n|--new] <TONE_OPTIONS>
beep <-h|--help>
beep <-v|-V|--version>

DESCRIPTION

beep permet à l'utilisateur de contrôler le haut-parleur du PC avec précision, permettant différents sons pour indiquer différents événements. Bien que beep puisse être utilisé directement en ligne de commande, son utilisation prévue est dans des scripts shell/perl, informant l'utilisateur lorsque quelque chose d'intéressant se produit. Bien sûr, il n'a aucune idée de ce qui EST intéressant, mais il est doué pour la partie notification.

Toutes les options ont des valeurs par défaut, ce qui signifie que simplement taper 'beep' fonctionnera. Si une option est spécifiée plus d'une fois sur la ligne de commande, les options ultérieures remplacent les précédentes. Ainsi 'beep -f 200 -f 300' fera biper à 300Hz.

Toutes les durées sont données en unités de millisecondes, les fréquences en Hertz, et le nombre de répétitions est un nombre sans dimension.

OPTIONS

Options globales

-e APPAREIL, --device=APPAREIL
Définit explicitement l'appareil que beep doit utiliser pour générer les tonalités. Lorsqu'aucun appareil n'est spécifié explicitement, beep parcourt une liste interne d'appareils jusqu'à ce que l'un d'eux fonctionne.
--debug, --verbose
Rend le programme beep plus verbeux.

Options de tonalité

-f FREQ
Faire biper avec une fréquence de tonalité de FREQ Hz, où 0 < FREQ < 20000. En gros, le bip sonore du terminal habituel est d'environ 750Hz. Pour la compatibilité ascendante, vous pouvez donner FREQ comme un nombre à virgule flottante, mais beep l'arrondira à des valeurs entières car les API du noyau s'attendent à cela. Valeur par défaut : 440 Hz.
-l LEN
Faire biper pendant une durée de tonalité de LEN millisecondes. Valeur par défaut : 200 ms.
-r REPETITIONS
Répéter la tonalité, y compris les délais, REPETITIONS fois. Valeur par défaut : 1 tonalité, non répétée.
-d DELAI | -D DELAI
Spécifier un délai de DELAI millisecondes entre les répétitions. La lettre minuscule -d spécifie que ce délai ne doit se produire qu'entre les bips, c'est-à-dire qu'il ne doit pas se produire après la dernière répétition. La lettre majuscule -D spécifie que le délai doit se produire après chaque répétition, y compris après la dernière. Normalement, -d est ce que vous voulez, mais si, par exemple, vous enchaînez plusieurs commandes beep pour jouer l'hymne de la guerre des étoiles, vous pourriez vouloir contrôler chaque délai. Valeur par défaut : délai de 100 ms entre les bips, sans délai après le dernier bip.
-n, --new
L'option --new vous permet d'enchaîner plusieurs bips sur une seule ligne de commande. Chaque fois que --new est utilisé, beep commence à traiter tous les arguments suivants comme s'ils étaient pour un nouveau bip. Ainsi, par exemple :


beep -f 1000 -n -f 2000 -n -f 1500

produirait une séquence de trois bips, le premier avec une fréquence de 1000Hz (et sinon des valeurs par défaut), puis un second bip avec une fréquence de 2000Hz (là encore, avec des éléments comme le délai et les répétitions réglés sur leurs valeurs par défaut), puis un troisième bip, à 1500Hz. Ceci est différent de la spécification d'une valeur -r, car -r répète le même bip plusieurs fois, alors que --new permet de spécifier différents bips. Après un --new, le nouveau bip est créé avec toutes les valeurs par défaut, et chacune d'elles peut être spécifiée sans modifier les valeurs des bips précédents (ou suivants). Voir la section EXEMPLES si cela a réussi à vous embrouiller.

-s, -c
Les options -s et -c placent beep en mode de traitement d'entrée, lisant depuis stdin et copiant toutes les données reçues vers stdout. Cela permet d'intégrer facilement beep dans un pipeline de traitement de texte pour surveiller acoustiquement le flux de données dans ce pipeline. Voir la section EXEMPLES.
-c
Faire biper après chaque caractère reçu.
-s
Faire biper après chaque ensemble de données reçu. Habituellement, cela signifie après les retours à la ligne dans les pipelines de traitement de texte.

Dans une séquence de notes spécifiées avec une ou plusieurs occurrences de -n ou --new, il est seulement logique d'avoir une seule note marquée avec -s ou -c. Ensuite, beep jouera toutes les notes jusqu'à atteindre la note marquée, puis répétera la note marquée en fonction de l'entrée reçue, et une fois que l'entrée aura atteint EOF, beep continuera avec le reste de la séquence de notes.

Le comportement de beep avec plus d'une note marquée avec -s ou -c est indéfini.

Autres actions

-h, --help Affiche les informations d'utilisation de beep et quitte.

-v, -V, --version
Affiche les informations de version de beep et quitte.

STATUT DE SORTIE

En cas de succès, beep retourne avec le code de sortie 0.

Tout code de sortie non nul signifie que beep a rencontré une erreur et s'est arrêté.

ENVIRONNEMENT

BEEP_LOG_LEVEL
Lorsqu'il est défini sur un nombre entre -999 et 999, BEEP_LOG_LEVEL sera utilisé comme niveau de journalisation par défaut jusqu'à ce qu'il soit remplacé par un paramètre de ligne de commande.

FICHIERS

Les fichiers d'appareils que beep utilise par défaut sont les suivants :
/dev/input/by-path/platform-pcspkr-event-spkr
/dev/tty0
/dev/vc/0

NOTES

Appareils et Permissions

Lorsque vous exécutez beep sans spécifier explicitement d'appareil à utiliser, beep essaie d'ouvrir les appareils suivants en séquence jusqu'à ce que l'un d'eux réussisse :

/dev/input/by-path/platform-pcspkr-event-spkr
Utilise l'API evdev, et l'administrateur système peut accorder l'accès à un ensemble quelconque d'utilisateurs et de groupes en utilisant les permissions de fichier normales.
/dev/tty0
Utilise l'API de console, et le noyau insiste pour que vous soyez root ou que vous possédiez le TTY.
/dev/vc/0
Utilise l'API de console, et le noyau insiste pour que vous soyez root ou que vous possédiez le TTY.

beep ne prend pas en charge l'exécution en tant que setuid root ou via sudo(1).

Pour les utilisations non root, l'administrateur système peut configurer une règle udev(7) pour autoriser l'accès en écriture à /dev/input/by-path/platform-pcspkr-event-spkr pour certains utilisateurs et/ou groupes d'utilisateurs. Pour plus de détails, consultez le fichier /usr/share/doc/beep/PERMISSIONS.md de beep.

NAME

beep — play a tunable sound on the PC speaker

SYNOPSIS

beep [-e|--device device] [-f|--frequency frequency] [-l|--length length] [-r|--repetitions repetitions] [-d|--delay delay] [-D|--delay-between-repetitions delay] [-s|--sync] [-n|--new] [-c|--compose] [-w|--wait msec] [-v|--verbose] [-?|--help] [--usage]

DESCRIPTION

The beep command generates a tone on the PC speaker. The tone can be specified by frequency, duration, and number of repetitions. It has several modes of operation, controlling how it interacts with other programs and how the sound is generated.

OPTIONS

-e device, --device device
Use the specified device file instead of the default /dev/input/by-path/platform-pcspkr-event-spkr. This is useful if you want to use a different event device or if the default is not available. See also FILES.
-f frequency, --frequency frequency
Set the frequency of the tone in Hertz (Hz). The default is 1000 Hz.
-l length, --length length
Set the length of the beep in milliseconds (ms). The default is 200 ms.
-r repetitions, --repetitions repetitions
Set the number of repetitions of the beep. The default is 1.
-d delay, --delay delay
Set the delay between repetitions in milliseconds (ms). The default is the same as the length of the beep (see -l).
-D delay, --delay-between-repetitions delay
Set the delay between repetitions in milliseconds (ms). This option overrides -d if both are given. The default is the same as the length of the beep (see -l).
-s, --sync
Wait for the beep to finish before returning. This is useful for creating sequences of beeps or for synchronizing with other processes.
-n, --new
Start a new beep sequence. This is useful for creating complex sound patterns by chaining multiple beep commands together. See also EXAMPLES.
-c, --compose
Enable compose mode. In this mode, beep will generate a short beep for each character typed, useful for an audible feedback when typing.
-w msec, --wait msec
Wait for the specified number of milliseconds before starting the beep. This is often used in conjunction with -n to create pauses within a sequence.
-v, --verbose
Print verbose output about the beep's actions. Useful for debugging.
-?, --help
Print a help message and exit.
--usage
Print a short usage message and exit.

EXIT STATUS

A zero exit status indicates success. A non-zero exit status indicates an error.

ENVIRONMENT

No environment variables are used.

FILES

/dev/input/by-path/platform-pcspkr-event-spkr
The default device file used by beep to interact with the PC speaker. The permissions of this file can be adjusted to allow non-root users to run beep.
console
This section describes an alternative method using the older console API, which involves using the KIOCSOUND ioctl(2) on a TTY device like /dev/tty0 or /dev/vc/0.
This method typically requires root privileges, unless the user is directly logged into the virtual console they are trying to use. This makes it unsuitable for users logged in via SSH or graphical environments like X11 or Wayland. It is recommended to use the evdev API instead.

Concurrent Invocations

Concurrent invocations of beep are not supported. The PC hardware has only one tone generator, and beep does not manage access to this shared resource. If multiple beep processes are run simultaneously, the behavior can be unpredictable, with later beeps potentially interrupting or overriding earlier ones. It is recommended to use a single beep command with multiple notes or sequences if complex sounds are required.

Sound Volume

The PC speaker hardware does not provide a way to explicitly set the volume. For standalone PCs with a piezo beeper, the volume can be influenced by selecting a frequency close to the beeper's resonance frequency (typically around 2000Hz). For PC laptops, the pcspkr output is often routed through the sound card mixer, allowing volume control via a sound card mixer application.

EXAMPLES

At its simplest (yet still effective)


beep

A more interesting standalone setup


beep -f 300.7 -r 2 -d 100 -l 400

As part of a log watching pipeline


tail -f /var/log/xferlog | grep 'passwd' | beep -f 1000 -r 5 -s

When using -c mode, I recommend using a short -D, and a shorter -l, so that the beeps do not blur together. Something like this will get you a cheesy 1970's style beep-as-you-type-each-letter effect


cat file | beep -c -f 400 -D 50 -l 10

A highly contrived example of -n/--new usage


beep -f 1000 -r 2 -n -r 5 -l 10 --new

will produce first two 1000Hz beeps, then 5 beeps at the default tone, but only 10ms long each, followed by a third beep using all the default settings (since none are specified).
