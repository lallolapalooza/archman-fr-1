NOM

buildah-config - Met à jour les paramètres de configuration de l'image.

SYNOPSIS

buildah config [options] container

DESCRIPTION

Met à jour un ou plusieurs des paramètres conservés pour un conteneur.

OPTIONS

--add-history

Ajoute une entrée à l'historique de l'image qui notera les modifications des paramètres pour --cmd, --entrypoint, --env, --healthcheck, --label, --onbuild, --port, --shell, --stop-signal, --user, --volume, et --workingdir. Par défaut à false.

Remarque : vous pouvez aussi remplacer la valeur par défaut de --add-history en définissant la variable d'environnement BUILDAH_HISTORY. export BUILDAH_HISTORY=true

--annotation, -a annotation=annotation

Ajoute une annotation d'image (par exemple annotation=annotation) au manifeste d'image de toutes les images qui seront construites à l'aide du conteneur spécifié. Peut être utilisé plusieurs fois. Si annotation se termine par un -, alors l' annotation est supprimée de la configuration. Si l' annotation est définie sur « - », alors toutes les annotations sont supprimées de la configuration.

--arch architecture

Définit l' architecture cible pour toutes les images qui seront construites à l'aide du conteneur spécifié. Par défaut, si le conteneur était basé sur une image, l'architecture cible de cette image est conservée, sinon l'architecture de l'hôte est enregistrée.

--author author

Définit les informations de contact pour l' auteur de toutes les images qui seront construites à l'aide du conteneur spécifié.

--cmd command

Définit la commande par défaut à exécuter pour les conteneurs basés sur toutes les images qui seront construites à l'aide du conteneur spécifié. Lorsqu'il est utilisé en combinaison avec un point d'entrée, cela spécifie les paramètres par défaut pour lepoint d'entrée

--comment comment

Définit le commentaire au niveau de l'image pour toutes les images qui seront construites à l'aide du conteneur spécifié.

Remarque : ce paramètre n'est pas présent dans le format d'image OCIv1, il est donc ignoré lors de l'écriture d'images à l'aide des formats OCIv1.

--created-by created

Définit la description de la manière dont la couche supérieure a été créée pour toutes les images qui seront créées à l'aide du conteneur spécifié.

--domainname domain

Définit le nom de domaine à définir lors de l'exécution de conteneurs basés sur toutes les images construites à l'aide du conteneur spécifié.

Remarque : ce paramètre n'est pas présent dans le format d'image OCIv1, il est donc ignoré lors de l'écriture d'images à l'aide des formats OCIv1.

--entrypoint "command" | '["command", "arg1", ...]'

Définit le point d'entrée pour les conteneurs basés sur toutes les images qui seront construites à l'aide du conteneur spécifié. buildah prend en charge deux formats pour le point d'entrée. Il peut être spécifié sous forme de chaîne simple ou sous forme de tableau de commandes.

Remarque : lorsque le point d'entrée est spécifié sous forme de chaîne, les runtimes de conteneurs ignoreront la valeur cmd de l'image du conteneur. Cependant, si vous utilisez la forme tableau, la commande cmd sera ajoutée à la fin de la commande du point d'entrée et sera exécutée avec elle.

Remarque : la forme chaîne est ajoutée à la commande sh -c en tant que point d'entrée. La forme tableau remplace entièrement le point d'entrée.

Format chaîne :

$ buildah from scratch
$ buildah config --entrypoint "/usr/bin/notashell" working-container
$ buildah inspect --format '{{ .OCIv1.Config.Entrypoint }}' working-container
[/bin/sh -c /usr/bin/notshell]
$ buildah inspect --format '{{ .Docker.Config.Entrypoint }}' working-container
[/bin/sh -c /usr/bin/notshell]

Format tableau :

$ buildah config --entrypoint '["/usr/bin/notashell"]' working-container
$ buildah inspect --format '{{ .OCIv1.Config.Entrypoint }}' working-container
[/usr/bin/notashell]
$ buildah inspect --format '{{ .Docker.Config.Entrypoint }}' working-container
[/usr/bin/notashell]

--env, -e env[=value]

Ajoute une valeur (par exemple env=value) à l'environnement pour les conteneurs basés sur toutes les images qui seront construites à l'aide du conteneur spécifié. Peut être utilisé plusieurs fois. Si env est nommé mais que ni = ni une value ne sont spécifiés, alors la valeur sera prise depuis l'environnement du processus actuel. Si env se termine par un -, alors l' env est supprimée de la configuration. Si env est définie sur « - », alors toutes les variables d'environnement sont supprimées de la configuration.

--healthcheck command

Spécifie une commande qui doit être exécutée pour vérifier si un conteneur fonctionne correctement.

Les valeurs peuvent être NONE, «CMD ... » (exécuter la commande spécifiée directement), ou «CMD-SHELL ... » (exécuter la commande spécifiée à l'aide du shell du système), ou la valeur vide (supprimer une valeur définie précédemment et les paramètres associés).

Remarque : ce paramètre n'est pas présent dans le format d'image OCIv1, il est donc ignoré lors de l'écriture d'images à l'aide des formats OCIv1.

--healthcheck-interval interval

Spécifie la fréquence à laquelle la commande spécifiée à l'aide de l'option --healthcheck doit être exécutée.

Remarque : ce paramètre n'est pas présent dans le format d'image OCIv1, il est donc ignoré lors de l'écriture d'images à l'aide des formats OCIv1.

--healthcheck-retries count

Spécifie le nombre de fois où la commande spécifiée à l'aide de l'option --healthcheck peut échouer avant que le conteneur ne soit considéré comme défaillant.

Remarque : ce paramètre n'est pas présent dans le format d'image OCIv1, il est donc ignoré lors de l'écriture d'images à l'aide des formats OCIv1.

--healthcheck-start-interval interval

Spécifie le temps entre les vérifications d'état de santé pendant la période de démarrage.

Remarque : ce paramètre n'est pas présent dans le format d'image OCIv1, il est donc ignoré lors de l'écriture d'images à l'aide des formats OCIv1.

--healthcheck-start-period interval

Spécifie le temps qui peut s'écouler après le démarrage d'un conteneur avant qu'un échec d'exécution de la commande spécifiée à l'aide de l'option --healthcheck ne soit considéré comme une indication que le conteneur est défaillant. Pendant cette période, les échecs seront attribués au fait que le conteneur n'a pas encore entièrement démarré et ne seront pas comptés comme des erreurs. Après le succès de la commande, ou une fois la période écoulée, les échecs seront comptés comme des erreurs.

Remarque : ce paramètre n'est pas présent dans le format d'image OCIv1, il est donc ignoré lors de l'écriture d'images à l'aide des formats OCIv1.

--healthcheck-timeout interval

Spécifie le temps d'attente après le démarrage de la commande spécifiée à l'aide de l'option --healthcheck pour attendre que la commande retourne son code de sortie. Si la commande n'est pas retournée dans ce délai, elle doit être considérée comme ayant échoué.

Remarque : ce paramètre n'est pas présent dans le format d'image OCIv1, il est donc ignoré lors de l'écriture d'images à l'aide des formats OCIv1.

--history-comment comment

Définit un commentaire sur la couche supérieure de toutes les images qui seront créées à l'aide du conteneur spécifié.

--hostname host

Définit le nom d'hôte à définir lors de l'exécution de conteneurs basés sur toutes les images construites à l'aide du conteneur spécifié.

Remarque : ce paramètre n'est pas présent dans le format d'image OCIv1, il est donc ignoré lors de l'écriture d'images à l'aide des formats OCIv1.

--label, -l label=value

Ajoute une label d'image (par exemple label=value) à la configuration d'image de toutes les images qui seront construites à l'aide du conteneur spécifié. Peut être utilisé plusieurs fois. Si label se termine par un -, alors la label est supprimée de la configuration. Si la label est définie sur « - », alors toutes les étiquettes sont supprimées de la configuration.

--onbuild onbuild command

Ajoute une commande ONBUILD à l'image. Les commandes ONBUILD sont automatiquement exécutées lorsque des images sont construites à partir de l'image que vous créez.

Remarque : ce paramètre n'est pas présent dans le format d'image OCIv1, il est donc ignoré lors de l'écriture d'images à l'aide des formats OCIv1.

--os operating system

Définit le système d'exploitation cible pour toutes les images qui seront construites à l'aide du conteneur spécifié. Par défaut, si le conteneur était basé sur une image, son système d'exploitation est conservé, sinon le nom du système d'exploitation de l'hôte est enregistré.

--os-feature feature

Définir le nom d'une fonctionnalité requise du système d'exploitation feature pour toute image qui sera construite à l'aide du conteneur spécifié. Par défaut, si le conteneur était basé sur une image, la liste des fonctionnalités OS requises de l'image de base est conservée, si elle en spécifiait. Cette option n'est généralement significative que lorsque l'OS de l'image est Windows.

Si feature se termine par -, alors la feature est retirée de l'ensemble des fonctionnalités requises qui seront listées dans l'image. Si la feature est définie sur "-", la liste complète des fonctionnalités est retirée de la configuration.

--os-version version

Définir la version exacte requise du système d'exploitation version pour toute image qui sera construite à l'aide du conteneur spécifié. Par défaut, si le conteneur était basé sur une image, la version OS requise de l'image de base est conservée, si elle en spécifiait. Cette option n'est généralement significative que lorsque l'OS de l'image est Windows, et est généralement définie dans les images de base Windows ; son utilisation est donc généralement inutile.

--port, -p port/protocole

Ajouter un port à exposer lors de l'exécution de conteneurs basés sur toute image qui sera construite à l'aide du conteneur spécifié. Peut être utilisé plusieurs fois. Pour spécifier si le port écoute en TCP ou en UDP, utilisez "port/protocole". Le protocole par défaut est TCP s'il n'est pas spécifié. Pour exposer le port à la fois en TCP et en UDP, spécifiez l'option port plusieurs fois. Si port se termine par - et est déjà défini, alors le port est retiré de la configuration. Si le port est défini sur - alors tous les paramètres de ports exposés sont retirés de la configuration.

--shell shell

Définir le shell par défaut à exécuter à l'intérieur de l'image du conteneur. L'instruction shell permet de remplacer le shell par défaut utilisé pour la forme shell des commandes. Le shell par défaut pour les conteneurs Linux est "/bin/sh -c".

Remarque : ce paramètre n'est pas présent dans le format d'image OCIv1 ; il est donc ignoré lors de l'écriture d'images avec les formats OCIv1.

--stop-signal signal

Définir le signal d'arrêt par défaut pour le conteneur. Ce signal sera envoyé lorsque le conteneur sera arrêté ; la valeur par défaut est SIGINT.

--unsetannotation annotation

Annuler l'annotation de l'image, ce qui fait que l'annotation n'est pas héritée de l'image de base.

--unsetlabel label

Annuler l'étiquette de l'image, ce qui fait que l'étiquette n'est pas héritée de l'image de base.

--user, -u user[:group]

Définir l' utilisateur par défaut à utiliser lors de l'exécution de conteneurs basés sur cette image. L'utilisateur peut être spécifié sous forme de nom d'utilisateur ou d'UID, éventuellement suivi d'un nom de groupe ou d'un GID, séparés par un deux-points (':'). Si des noms sont utilisés, le conteneur doit inclure des entrées pour ces noms dans ses fichiers /etc/passwd et /etc/group .

--variant variant

Définir la variante de l'architecture cible pour toute image qui sera construite à l'aide du conteneur spécifié. Par défaut, si le conteneur était basé sur une image, les informations d'architecture et de variante cibles de cette image sont conservées ; sinon, l'architecture et la variante de l'hôte sont enregistrées.

--volume, -v volume

Ajouter un emplacement dans l'arborescence des répertoires qui doit être marqué comme un volume dans toute image qui sera construite à l'aide du conteneur spécifié. Peut être utilisé plusieurs fois. Si volume se termine par -, et est déjà défini, alors le volume est retiré de la configuration. Si le volume est défini sur "-" alors tous les volumes sont retirés de la configuration.

--workingdir directory

Définir le répertoire de travail directory initial pour les conteneurs basés sur des images qui seront construites à l'aide du conteneur spécifié.

EXEMPLE

buildah config --author='Jane Austen' --workingdir='/etc/mycontainers' containerID

buildah config --entrypoint /entrypoint.sh containerID

buildah config --entrypoint '[ "/entrypoint.sh", "dev" ]' containerID

buildah config --env foo=bar --env PATH=$PATH containerID

buildah config --env foo- containerID

buildah config --label Name=Mycontainer --label Version=1.0 containerID

buildah config --label Name- containerID

buildah config --annotation note=myNote containerID

buildah config --annotation note-

buildah config --volume /usr/myvol containerID

buildah config --volume /usr/myvol- containerID

buildah config --port 1234 --port 8080 containerID

buildah config --port 514/tcp --port 514/udp containerID

buildah config --env 1234=5678 containerID

buildah config --env 1234- containerID

buildah config --os-version 10.0.19042.1645 containerID

buildah config --os-feature win32k containerID

buildah config --os-feature win32k- containerID
