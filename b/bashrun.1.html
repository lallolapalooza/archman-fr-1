EXÉCUTION DE

COMMANDES

Exécuter des commandes simples est direct. Le shell effectuera les expansions habituelles et la commande résultante sera traitée et lancée selon l'action et les préférences demandées par l'utilisateur. Plusieurs

commandes

séparées par ; sont traitées successivement de la même manière. Si les commandes

sont

séparées par un symbole de pipe ( |) ou par lesopérateurs logiques || ou &&, le comportement de bashrun différera sensiblement du comportement normal du shell. Pour le shell bashrun, chaque commande simple dans une instruction composée apparaîtra comme si elle retournait immédiatement un succès. Cela signifie que séparer des commandes avec && ou | est effectivement équivalent à l'utilisation de ;. Séparer des commandes avec || empêchera l'exécution des commandes sur le côté droit de l'expression. Pour contourner ce comportement, les caractères ;,

&

et | peuvent être échappés avec un caractère antislash ( \). Veuillez noter que dans ce cas, les règles duterminal ne sont appliquées que sur la base du nom de commande de la première commande. À titre d'illustration, une commande comme $

cat

fichier_texte | wc -l

<term-page>


ne fonctionnera pas comme prévu et

mettra

à la place la sortie des deux commandes en pages dans des terminaux séparés, sans pipe établi entre les commandes. Vous devrez utiliser $ cat fichier_texte \| wc -l <term-page> pour

mettre


en pages le nombre de lignes

dans

fichier_texte dans une seule fenêtre de terminal comme prévu. L'édition de plusieurs lignes

ne

fonctionne pas dans bashrun. Si vous oubliez une fermeture de guillemet sur votre ligne de commande, bashrun vous demandera d'appuyer sur C-c. Votre dernière ligne d'historique peut être erronée après cela. Pour exécuter

des

commandes dans le contexte de la session shell bashrun au lieu de les faire traiter par bashrun, utilisez l'action <pass> (par défaut : M-w). FICHIER DE CONFIGURA

FICHIER DE

CONFIGURATION

Le fichier de configuration de l'utilisateur $XDG_CONFIG_HOME/bashrun/rc sera chargé comme le fichier rc pour la session bash utilisée par bashrun. En plus des variables d'environnement décrites ici, vous pouvez ajouter tout ce que vous ajouteriez habituellement à votre fichier ~/.bashrc. Par exemple, vous pourriez vouloir ajouter des fonctions ou des alias, lier des touches de fonction supplémentaires ou simplement charger votre fichier ~/.bashrc

existant.

Veuillez vous assurer que vous n'interférez pas avec les paramètres tty/bash et les raccourcis clavier réservés utilisés par bashrun. Voir CONFIGURATION DU CLAVIER, FICHIER DE CONFIGURATION et ENVIRONNEMENT ou jetez un œil à $PREFIX/share/bashrun/bashrc

.

TERMINAL_RULES=('RUN:[progs]' 'PAGE:[progs]' 'HOLD:[progs]

')
Un tableau contenant des chaînes de règles qui définissent quels programmes doivent toujours être lancés dans une fenêtre de terminal. Insérez une liste de noms de programmes séparés par des espaces après le : dans la chaîne pour la règle souhaitée. Les programmes dans la règle RUN sont toujours lancés dans un terminal. Les programmes dans la règle PAGE auront leur sortie paginée dans PAGER. Pour les programmes dans la règle HOLD, le terminal reste ouvert après la terminaison du programme.

Exemple

:


TERMINAL_RULES=(
"RUN:watch top htop less man info ncftp links"
"HOLD:ps su"
"PAGE:echo ls which uname lsusb lshal lsmod fortune"

)

HANDLERS=([regexp handler]...) (par défauts : voir

ci-dessous)
Un tableau contenant des expressions régulières bash et des chaînes de gestionnaires associées. Si la ligne de commande entrée dans bashrun n'est pas exécutable (c'est-à-dire ce n'est ni une fonction, ni un alias, ni un binaire sur PATH), une tentative est faite de faire correspondre successivement la ligne de commande aux motifs contenus dans HANDLERS. Si un motif correspond, soit la chaîne du gestionnaire suivant le motif sera utilisée comme commande à exécuter, avec la ligne de commande elle-même passée comme argument, soit, si l'expression régulière contient des sous-motifs entre parenthèses, une tentative est faite de substituer l'occurrence de $[1-9] dans la chaîne du gestionnaire par le contenu de la correspondance du sous-motif correspondant. La chaîne du gestionnaire modifiée est ensuite utilisée comme ligne de commande sans ajouter d'autres arguments.

S'il n'y a pas assez de correspondances de sous-motifs pour substituer chaque occurrence de $[0-9] dans la chaîne du gestionnaire, le gestionnaire ne sera pas exécuté et un message d'erreur sera émis à

l'utilisateur.

La chaîne du gestionnaire peut en plus être préfixée par une expression de test de fichier définissant une série de tests de fichier à effectuer sur le contenu de la ligne de commande avant d'appliquer le gestionnaire. Si l'un de ces tests échoue, le gestionnaire ne sera pas

appliqué.

L'expression de test est une série de caractères correspondant aux opérateurs de test de fichier unaires définis dans la section EXPRESSIONS CONDITIONNELLES du manuel bash(1), terminée par :. Les tests de fichier peuvent être négés en les préfixant d'un seul !. Par exemple, un gestionnaire préfixé par f!x: ne sera appliqué que si la ligne de commande est un chemin vers un fichier régulier non

exécutable.

Par exemple, pour définir des associations de fichiers pour les fichiers jpeg, vous pouvez utiliser un motif et un gestionnaire

comme


'\.jpe?g$' 'f!x:

gimp'

Cela ouvrira les lignes se terminant par .jpg ou .jpeg en utilisant gimp(1). Le test de fichier garantit que vous pouvez toujours taper une ligne

comme


$ convert foo.tif foo.

jpg

qui ne sera pas gérée bien qu'elle se termine aussi par .jpg. C'est parce que l'expression de test est appliquée à la ligne complète, donc le test f!x

échouera.

Pour ouvrir les lignes commençant par http ou https dans votre BROWSER, ajoutez une ligne comme celle-ci au tableau HANDLERS

:


'^https?'

"$BROWSER"

Pour implémenter des raccourcis web similaires à ceux du navigateur konqueror de KDE, utilisez un motif contenant un sous-motif, comme ceci

:


'^gg:(.+)

'

et utilisez une ligne comme celle-ci comme chaîne de gestionnaire

:


"$BROWSER 'http://www.google.com/se

arch?q=\$1'"

Bashrun remplacera la partie $1 de la chaîne du gestionnaire par tout ce que l'utilisateur a entré après gg:./p>

Voir le fichier de configuration utilisateur par défaut pour plus d'exemples. Si vos gestionnaires ne fonctionnent pas comme prévu, activez le mode de débogage pour voir ce qui se passe.

Les gestionnaires suivants sont configurés par défaut si le fichier de configuration par défaut est utilisé ou si HANDLERS n'est pas défini dans le fichier de configuration utilisateur :

^www, ^https?
Ouvre les lignes commençant par www, http ou https dans BROWSER
^gg:(.+)
Google
^ggl:(.+)

^sf:(.+)

LOGFILE=[chemin] (par défaut : /dev/null)
La sortie des commandes (stdout et stderr) est ajoutée à LOGFILE. S'il n'existe pas, bashrun tentera de le créer. S'il n'est pas accessible en écriture, la sortie sera redirigée vers /dev/null à la place.

La journalisation est désactivée pour les commandes exécutées avec des privilèges root.

FICHIERS

$XDG_CONFIG_HOME/bashrun/rc

Le fichier de configuration de l'utilisateur. S'il n'existe pas, il sera créé et initialisé avec la configuration par défaut.

$XDG_CONFIG_HOME/bashrun/keys

Le fichier de configuration du clavier. S'il n'existe pas, il sera créé et initialisé avec les liaisons de touches par défaut.

Si xdotool(1) est utilisé, bashrun doit être redémarré pour que les modifications apportées à ces fichiers prennent effet.

Si XDG_CONFIG_HOME n'est pas défini ou est vide, ~/.config sera utilisé à la place.

$XDG_DATA_HOME/bashrun/history

Le fichier d'historique utilisé par bashrun. Si XDG_DATA_HOME n'est pas défini ou est vide, ~/.local/share sera utilisé à la place.

$XDG_CACHE_HOME/bashrun/

Répertoire pour les fichiers temporaires créés par bashrun. Si XDG_CACHE_HOME n'est pas défini ou est vide, ~/.cache sera utilisé à la place.

ENVIRONNEMENT

X11
Les propriétés du gestionnaire de fenêtres WM_CLASS et WM_NAME sont définies sur "bashrun". Ces propriétés peuvent être utilisées avec les installations de votre gestionnaire de fenêtres pour configurer davantage l'apparence de bashrun. Notez que si vous utilisez xdotool(1), il est recommandé de rendre la fenêtre bashrun "collante" pour vous assurer qu'elle apparaîtra toujours sur le bureau actuel.
BASH
L'option shell extdebug est activée. Un piège sur DEBUG est défini chaque fois qu'une ligne de commande est émise. Le piège est désactivé à nouveau après le traitement de la ligne de commande pour l'empêcher d'interférer avec l'édition interactive de la ligne de commande.

L'envoi de ^D (eof) sur une ligne vide ne termine pas le shell si xdotool(1) est utilisé. Voir stty(1)

Le contrôle de flux XON/XOFF (Suspendre/Reprendre le terminal via C-s et C-q) est désactivé. C-s recherchera en avant dans le tampon d'historique (par défaut readline) tandis que C-q est lié à l'action <quit> lors de l'utilisation des liaisons de touches par défaut. Voir stty(1)

PROBLEMES CONNUS

Certains terminaux nécessitent la mise entre guillemets de la ligne de commande à exécuter. Cela signifie que l'exécution de lignes de commande avec beaucoup de guillemets peut échouer pour ces terminaux, bien que deux niveaux de guillemets devraient généralement fonctionner. Vous pouvez utiliser le mode de débogage pour découvrir exactement pourquoi et comment une commande fortement mise entre guillemets échoue.

Seuls xterm(1) et *rxvt(1) prennent en charge le redimensionnement à l'aide des liaisons de touches. Il a été occasionnellement constaté que xterm se bloquait pendant le redimensionnement, nécessitant au moins un SIGTERM pour le fermer.

Pour XTerm, la ressource allowWindowOps doit être définie sur True pour permettre le redimensionnement de la fenêtre. Ceci est activé dans la configuration par défaut pour xterm depuis la version 0.14 de bashrun. Notez que la définition de allowSendEvents sur True désactivera de force allowWindowOps dans XTerm.

Pour que les liaisons de touches meta (précédées de \e ou \M-) fonctionnent avec la touche Alt ou Meta, le terminal doit être configuré pour traduire votre touche meta en une échappatoire. Pour XTerm, cela peut être activé en définissant la ressource metaSendsEscape sur True. Ceci est activé dans la configuration par défaut pour xterm depuis la version 0.14 de bashrun. Pour URxvt, la ressource meta8 doit être définie sur False (ce qui est le paramètre par défaut pour URxvt).
