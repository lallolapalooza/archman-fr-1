INTRODUCTIO

N

Cette page documente le client BadVPN, un démon pour un nœud dans un réseau VPN BadVPN. Pour une description générale de BadVPN, voir badvp

n(7
).

DESCRIPTIO

N

Le client BadVPN est un démon qui s'exécute sur un nœud VPN. Il ouvre le périphérique TAP, se connecte au serveur, puis continue de

s'exécuter tout en tentant d'établir une connexion de données avec les pairs et de transférer des données entre le périphérique T
AP et les pairs. Une fois initialisé, le programme ne se termine que s'il perd la connexion au serveur ou s'il reçoit un signal.

OPTION

S

Le client BadVPN est entièrement configuré depuis la ligne de

commande.
--he
lp
Afficher la version et la syntaxe de la ligne de commande, puis
quitter.
--versi
on
Afficher la version, puis
quitter.
--logger
<stdout/syslog>
Sélectionner l'endroit où journaliser les messages. Par défaut, stdout. Syslog n'est pas disponible sur
Windows.
--syslog-facility
<string>
Lors de la journalisation vers syslog, définir la facilité de journalisation. Le nom de la facilité doit être en
minuscules.
--syslog-ident
<string>
Lors de la journalisation vers syslog, définir
l'ident.
--loglevel <0-5/none/error/warning/notice/info/deb
ug>
Définir le niveau de journalisation par
défaut.
--channel-loglevel <channel-name> <0-5/none/error/warning/notice/info/deb
ug>
Définir le niveau de journalisation pour un canal de journalisation
spécifique.
--threads
<integer>
Indication du nombre de threads supplémentaires à utiliser pour les calculs potentiellement longs (comme le chiffrement et la génération d'OTP). Si zéro (0) (par défaut), les threads supplémentaires seront désactivés et tous les calculs seront effectués dans la boucle d'événements. Si négatif (<0), une estimation sera faite, possiblement basée sur le nombre de CPU. Si positif (>0), le nombre de threads donné sera
utilisé.
--s
sl
Utiliser TLS. Nécessite --nssdb et --server-cert-na
me.
--nssdb
<string>
Lors de l'utilisation de TLS, la base de données NSS à utiliser. Probablement quelque chose comme sql:
/some/folder.
--client-cert-name
<string>
Lors de l'utilisation de TLS, le nom du certificat à utiliser. Le certificat doit être facilement
accessible.
--server-name
<string>
Définir le nom du serveur utilisé pour valider le certificat du serveur. Le nom du serveur par défaut est le nom dans l'adresse du serveur (ou une adresse numérique)
.
--server-addr
<addr>
Définir l'adresse sur laquelle le serveur doit écouter. Voir ci-dessous pour le format
d'adresse.
--tapdev
<name>
Définir le périphérique TAP à utiliser. Voir ci-dessous comment configurer le périphérique. Un périphérique TAP est une carte virtuelle dans le système d'exploitation, mais plutôt que de recevoir des trames de et d'envoyer des trames à un morceau de matériel, un programme (celui-ci) l'ouvre pour lire et écrire des trames. Si le réseau VPN est configuré correctement, les périphériques TAP sur les nœuds VPN se comporteront comme s'ils étaient tous connectés dans un commutateur
réseau.
--scope
<scope_name>
Ajouter une portée d'adresse autorisée pour la connexion aux pairs. Peut être spécifié plusieurs fois pour ajouter plusieurs portées. L'ordre des portées est sans importance. Notez qu'il doit réellement être possible de se connecter aux adresses dans la portée donnée ; lorsqu'un autre pair se lie pour que nous nous connections, nous choisissons la première adresse externe dont nous reconnaissons la portée, et n'essayons pas d'autres adresses externes, même si l'établissement de la connexion
échoue.
--bind-addr
<addr>
Ajouter une adresse à autoriser pour la liaison. Voir ci-dessous pour le format d'adresse. Lors de la tentative de liaison pour qu'un pair puisse se connecter à nous, les adresses seront essayées dans l'ordre où elles sont spécifiées. Si le transport de données UDP est utilisé, une option --num-ports doit suivre pour spécifier combien de ports continus autoriser pour la liaison. Pour que l'adresse soit utile, une ou plusieurs options --ext-addr doivent suivre. Notez que lorsque deux pairs doivent établir une connexion de données, il est arbitraire lequel essaiera de se lier en
premier.
--num-ports
<num>
Lors de l'utilisation du transport UDP, définir le nombre de ports continus pour une adresse de liaison spécifiée précédemment. Doit suivre une option --bind-addr
précédente.
--ext-addr <addr / {server_reported}:port>
<scope_name>
Ajouter une adresse externe pour une adresse de liaison spécifiée précédemment. Doit suivre une option --bind-addr précédente. Peut être spécifié plusieurs fois pour ajouter plusieurs adresses externes. Voir ci-dessous pour le format d'adresse. De plus, la partie adresse IP peut être {server_reported} pour utiliser l'adresse IPv4 telle que le serveur nous voit. Les adresses externes sont essayées par le pair qui se connecte dans l'ordre où elles sont spécifiées. Notez que le pair qui se connecte n'essaie de se connecter qu'à la première adresse dont il reconnaît la portée et n'essaie pas les autres adresses. Cela signifie que toutes les adresses doivent fonctionner pour pouvoir
communiquer.
--transport-mode
<udp/tcp>
Définit le protocole de transport pour les connexions de données. UDP est recommandé et fonctionne le mieux pour la plupart des réseaux. TCP peut être utilisé à la place si le réseau sous-jacent a une perte de paquets élevée que votre réseau virtuel ne peut pas tolérer. Doit correspondre sur tous les
pairs.
--encryption-mode <blowfish/aes/no
ne>
Lors de l'utilisation du transport UDP, définit le mode de chiffrement. None signifie aucun chiffrement, les autres options signifient un chiffrement spécifique. Notez que le chiffrement n'est utile que si les clients utilisent TLS pour se connecter au serveur. Le mode de chiffrement doit correspondre sur tous les
pairs.
--hash-mode
<md5/sha1/none>
Lors de l'utilisation du transport UDP, définit le mode de hachage. None signifie aucun hachage, les autres options signifient un type de hachage spécifique. Notez que le hachage n'est utile que si le chiffrement est également utilisé. Le mode de hachage doit correspondre sur tous les
pairs.
--otp <blowfish/aes> <num>
<num-warn>
Lors de l'utilisation du transport UDP, active les mots de passe à usage unique. Le premier argument spécifie un chiffrement de bloc utilisé pour générer des mots de passe à partir d'une graine. Le deuxième argument spécifie combien de mots de passe sont générés à partir d'une seule graine. Le troisième argument spécifie après combien de mots de passe utilisés pour l'envoi de paquets une tentative est faite pour négocier une nouvelle graine avec l'autre pair. num doit être >0, et num-warn doit être >0 et <=num. La différence (num - num-warn) doit être suffisamment grande pour permettre la négociation d'une nouvelle graine avant que l'expéditeur n'épuise ses mots de passe. La négociation d'une graine implique que le pair expéditeur l'envoie au pair récepteur via le serveur et que le pair récepteur la confirme via le serveur. Notez que les mots de passe à usage unique ne sont utiles que si les clients utilisent TLS pour se connecter au serveur. L'option OTP doit correspondre sur tous les pairs, sauf pour
num-warn.
--fragmentation-latency
<milliseconds>
Lors de l'utilisation du transport UDP, définit la latence maximale à sacrifier pour empaqueter les trames dans les paquets de données plus efficacement. Si elle est >=0, un minuteur de ce nombre de millisecondes est utilisé pour attendre d'autres trames à mettre dans un paquet incomplet depuis que le premier morceau du paquet a été écrit. Si elle est <0, les paquets sont envoyés immédiatement. Par défaut à 0, qui est le réglage
recommandé.
--peer-s
sl
Lors de l'utilisation du transport TCP, active TLS pour les connexes de données. Nécessite l'utilisation de TLS pour la connexion au serveur. Pour que cela fonctionne, les pairs doivent se faire mutuellement confiance pour leurs certificats, et les certificats doivent accorder le contexte d'utilisation du serveur TLS. Cette option doit correspondre sur tous les
pairs.
--peer-tcp-socket-sndbuf <bytes
/ 0>
Définit la valeur de l'option de socket SO_SNDBUF pour les sockets TCP des pairs (zéro pour ne pas la définir). Des valeurs plus basses amélioreront l'équité lorsque les données de plusieurs sources (locales et relais) sont envoyées à un pair donné, mais peuvent entraîner une bande passante plus faible si le produit bande passante-délai du réseau est trop
grand.
--send-buffer-size
<num-packets>
Définit la taille minimale des tampons d'envoi des pairs pour l'envoi de trames originant de ce système, en nombre de
paquets.
--send-buffer-relay-size
<num-packets>
Définit la taille minimale des tampons d'envoi des pairs pour le relais de trames d' autres pairs, en nombre de
paquets.
--max-macs
<num>
Définit le nombre maximal d'adresses MAC à mémoriser pour un pair. Lorsque le nombre est dépassé, l'emplacement le moins récemment utilisé sera
réutilisé.
--max-groups
<num>
Définit le nombre maximal d'appartenances à des groupes IGMP à mémoriser pour un pair. Lorsque le nombre est dépassé, l'emplacement le moins récemment utilisé sera
réutilisé.
--igmp-group-membership-interval
<ms>
Définit le paramètre Group Membership Interval pour l'IGMP snooping, en
millisecondes.
--igmp-last-member-query-time
<ms>
Définit le paramètre Last Member Query Time pour l'IGMP snooping, en
millisecondes.
--allow-peer-talk-without-
ssl
Lorsque SSL est activé, les clients ne se connectent pas seulement au serveur en utilisant SSL, mais échangent également des messages à travers le serveur via une au
tre couche de SSL. Cela protège les messages contre les attaques sur le serveur. Les anciennes versions de BadVPN (<1.999.109), cependant, ne prennent pas en c
harge cela. Cette option permet aux anciens et nouveaux clients d'interopérer en n'utilisant pas SSL si l' autre pair ne le prend pas en charge. Cela annule ce
pendant les avantages de sécurité de l'utilisation de SSL, puisque le serveur (potentiellement compromis) peut alors ordonner aux pairs de ne pas utiliser SSL.

CODE DE

SORTIE

Si l'initialisation échoue, se termine avec le code 1. Sinon, s'exécute jusqu'à ce qu'une terminaison soit demandée ou que la connexion au serveur soit rompue et se termine avec le code

1.

FORMAT

D'ADRESSE

Les adresses ont la forme ipaddr:port, où ipaddr est soit u

ne adresse IPv4 (nom ou numérique), soit une adresse IPv
6 entourée de crochets [] (à nouveau nom ou numérique).

CONFIGURATION DE L'APPAREIL

TAP

Pour utiliser ce programme, vous devez d'abord configurer un appareil réseau TAP qui agira comme point de terminaison pour le réseau virtuel. La configuration dépend de votre système

d'exploitation.

Notez que le programme client ne configure pas l'appareil TAP de aucune manière ; il lit et écrit seulement des trames depuis/vers celui-ci. Vous êtes responsable de sa configuration (par exemple le mettre en marche et définir son adresse IP)

.

Linu

x

Vous devez activer l'option de configuration du noyau CONFIG_TUN. Si vous l'avez activé en tant que module, vous devrez peut-être le charger (`modprobe tun`) avant de pouvoir créer

l'appareil.

Ensuite, vous devriez créer un appareil TAP persistant pour le programme client VPN à ouvrir. Cela peut être fait avec soit tunctl ou le programme openvpn. L'appareil sera associé à un compte utilisateur qui aura la permission de l'utiliser, qui devrait être le même utilisateur que celui avec lequel le programme client s'exécutera (pas root !). Pour créer l'appareil avec tunctl, utilisez `tunctl -u <user> -t tapN`, et pour le créer avec openvpn, utilisez `openvpn --mktun --user <user> --dev tapN`, où N est un nombre qui identifie l'appareil

TAP.

Une fois l'appareil TAP créé, passez `--tapdev tapN` au programme client pour le faire utiliser cet appareil. Notez que l'appareil ne sera pas préservé après un arrêt du système ; consultez la documentation de votre OS si vous souhaitez automatiser la création ou la configuration de

l'appareil.

Window

s

Windows ne fournit pas de pilote TAP. Le programme client utilise le pilote TAP-Win32, qui fait partie d'OpenVPN. Vous devez installer la version open source (!) d'OpenVPN, et dans l'installateur activer au moins les options `TAP Virtual Ethernet Adapter` et `Add Shortcuts to Start Menu`. Vous pouvez obtenir l'installateur à
http://openvpn.net/index.php/open-sou

rce/downloads.html.

L'installateur d'OpenVPN crée automatiquement un appareil TAP sur votre système lorsqu'il est exécuté pour la première fois. Pour créer un autre appareil, utilisez `Programs -> OpenVPN -> Utilities -> Add a new TAP virtual ethernet adapter`. Vous devrez peut-être réinstaller OpenVPN pour faire apparaître ce

raccourci.

Une fois que vous avez un appareil TAP, vous pouvez le configurer comme une carte réseau physique. Vous pouvez reconnaître les appareils TAP par leur champ `Device

Name`.

Pour utiliser l'appareil, passez `--tapdev "<driver_name>:<interface_name>"` au programme client, o

ù <driver_name> est le nom du pilote TAP (tap0901 pour OpenVPN 2.1 et 2.2) (sensible à la casse), et <i
nterface_name> est le nom (humain) de l'interface réseau TAP (par exemple `Local Area Connection 2`).
