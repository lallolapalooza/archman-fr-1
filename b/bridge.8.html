Contrôle si un port donné répliquera les paquets en utilisant le unicast au lieu du multicast. Par défaut, cet indicateur est désactivé.

Cela est fait en copiant le paquet par hôte et en changeant l'adresse MAC de destination multicast en une unicast en

conséquence.

mcast_to_unicast fonctionne au-dessus de la fonctionnalité d'inspection multicast du pont. Ce qui signifie que les copies unicast ne sont livrées qu'aux hôtes qui y sont intéressés et qui l'ont signalé via des rapports IGMP/MLD

précédemment.

Cette fonctionnalité est destinée aux types d'interfaces qui ont une manière plus fiable et/ou efficace de livrer des paquets unicast que des paquets de diffusion (par exemple

WiFi).

Cependant, elle ne devrait être activée que sur des interfaces où aucune suppression de rapports IGMPv2/MLDv1 n'a lieu. Le problème de la suppression de rapports IGMP/MLD est généralement surmonté par le démon réseau (supplicant) en activant l'isolation AP et en séparant ainsi tous

les STA.

La livraison du multicast IP de STA à STA est rendue possible à nouveau en activant et en utilisant le mode hairpin du pont, qui considère le port d'entrée comme un port de sortie potentiel aussi (voir l' option hairpin). Le mode hairpin est effectué après l'inspection multicast, me

nant donc à ne livrer les rapports qu'aux

Contrôle si un port est verrouillé ou non. Lorsqu'il est verrouillé, les trames non link-local reçues via le port sont abandonnées, sauf si une entrée FDB avec l'adresse MAC source pointe vers le port. Le cas d'utilisation courant est IEEE 802.1X où les hôtes peuvent s'authentifier en échangeant des trames EAPOL avec un authentificateur. Une fois l'authentification terminée, le plan de contrôle de l'espace utilisateur peut installer une entrée FDB correspondante pour permettre au trafic provenant de l'hôte d'être transmis par le pont. Lorsque l'apprentissage est activé sur un port verrouillé, le no_linklocal_learn bridge option doit être activé pour empêcher le pont d'apprendre à partir des trames EAPOL reçues. Par défaut, cet indicateur est
désactivé.
mab on ou mab
off
Contrôle si le contournement d'authentification MAC (MAB) est activé sur le port ou non. MAB ne peut être activé que sur un port verrouillé dont l'apprentissage est activé. Lorsqu'il est activé, les entrées FDB sont apprises à partir du trafic reçu et ont l'indicateur FDB "locked" défini. L'indicateur ne peut être défini que par le noyau et il indique que l'entrée FDB ne peut pas être utilisée pour authentifier l' hôte correspondant. L'espace utilisateur peut décider d'authentifier l'hôte en remplaçant l'entrée FDB et en effaçant l'indicateur FDB "locked". Les entrées FDB verrouillées peuvent migrer vers des ports non verrouillés (autorisés), auquel cas l'indicateur "locked" est effacé. Les entrées FDB ne peuvent pas migrer vers des ports verrouillés, que MAB soit activé ou non. Par conséquent, les entrées FDB verrouillées ne sont créées que si une entrée FDB avec le {MAC, VID} donné n' existe pas déjà. Ce comportement empêche les hôtes non authentifiés de perturber le trafic destiné aux hôtes déjà authentifiés. Les entrées FDB verrouillées se comportent comme des entrées dynamiques régulières en ce qui concerne la transmission et le vieillissement. Par défaut, cet indicateur est
désactivé.

intervalle entre les requêtes envoyées par le pont après la fin de la phase de démarrage.
mcast_query_response_interval QUERY_RESPONSE_INTERVAL
définit le Temps de Réponse Maximum / Délai de Réponse Maximum pour les requêtes IGMP/MLD envoyées par le pont.
msti MSTI
associe le VLAN à l'instance de spanning tree multiple (MSTI) spécifiée.

bridge vlan global show - lister les options VLAN globales.

Cette commande affiche les options VLAN globales pour chaque entrée VLAN.

dev DEV
l'interface dont seules les options VLAN globales doivent être listées. Par défaut, toutes les interfaces de pont sont listées.
vid VID
l'ID VLAN dont seules les options globales doivent être listées. Par défaut, tous les vlans sont listés.

bridge vni - liste de filtres VNI

Les objets vni contiennent les ID VNI connus pour un lien vxlan de métadonnées dst.

Les commandes correspondantes affichent les entrées de filtre vni, ajoutent de nouvelles entrées et suppriment les anciennes.

bridge vni add - ajouter une nouvelle entrée de filtre vni

Cette commande crée une nouvelle entrée de filtre vni.

dev NAME
l'interface à laquelle ce vni est associé.
vni VNI
l'ID VNI qui identifie le vni.
remote IPADDR
spécifie l'adresse IP de destination unicast à utiliser dans les paquets sortants lorsque l'adresse de couche liaison de destination n'est pas connue dans la base de données de forwarding du périphérique VXLAN. Ce paramètre ne peut pas être spécifié avec le groupe.
group IPADDR
spécifie l'adresse IP multicast à rejoindre pour ce VNI

bridge vni del - supprimer une nouvelle entrée de filtre vni

Cette commande supprime une entrée de filtre vni existante.

Les arguments sont les mêmes qu'avec bridge vni add.

bridge vni show - lister la configuration de filtrage vni.

Cette commande affiche la table de filtrage vni actuelle.

Avec l'option -statistics, la commande affiche les statistiques de trafic par vni.

dev NAME
affiche la table de filtrage vni associée au périphérique vxlan

bridge monitor - surveillance de l'état

'>bridge monitor - surveillance de l'état

L'utilitaire bridge peut surveiller en continu l'état des périphériques et des adresses. Cette option a un format légèrement différent. Plus précisément, la commande monitor est la première dans la ligne de commande, puis la liste d'objets suit

:

bridge monitor [ all | OBJECT-LI

ST ]

OBJECT-LIST est la liste des types d'objets que nous souhaitons surveiller. Elle peut contenir link, fdb, vlan et mdb. Si aucun argument file n'est donné, bridge ouvre RTNETLINK, écoute sur celui-ci et affiche les changements d'état dans le format décrit dans les sections

précédentes.

Si un nom de fichier est donné, il n'écoute pas sur RTNET

LINK, mais ouvre le fichier contenant les messages RT
NETLINK enregistrés au format binaire et les affiche.
