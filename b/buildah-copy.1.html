NOM

buildah-copy - Copie le contenu d'un fichier, d'une URL ou d'un répertoire dans le répertoire de travail d'un conteneur.

SYNOPIS

buildah copy conteneur src [[src ...] dest]

DESCRIPTION

Copie le contenu d'un fichier, d'une URL ou d'un répertoire vers le répertoire de travail d'un conteneur ou vers un emplacement spécifié dans le conteneur. Si un répertoire local est spécifié comme source, son contenu est copié vers la destination.

OPTIONS

--add-history

Ajoute une entrée à l'historique qui notera le digest du contenu ajouté. Par défaut à faux.

Note : Vous pouvez également remplacer la valeur par défaut de --add-history en définissant la variable d'environnement BUILDAH_HISTORY. export BUILDAH_HISTORY=true

--cert-dir chemin

Utilise les certificats dans chemin (*.crt, *.cert, *.key) lors de la connexion aux registres pour le téléchargement d'images nommées avec le drapeau --from. Le répertoire de certificats par défaut est /etc/containers/certs.d.

--checksum checksum

Vérifie le contenu source avec une somme de contrôle. La valeur de checksum doit être une chaîne de digest de conteneur standard. Uniquement supporté pour les sources HTTP.

--chmod permissions

Définit les permissions d'accès du contenu de destination. Accepte le format numérique. Si --from n'est pas utilisé, la valeur par défaut est 0755.

--chown propriétaire:groupe

Définit la propriété utilisateur et groupe du contenu de destination. Si --from n'est pas utilisé, la valeur par défaut est 0:0.

--contextdir répertoire

Répertoire de contexte de construction. La spécification d'un répertoire de contexte amène Buildah à faire un chroot dans le répertoire de contexte. Cela signifie que la copie de fichiers pointés par des liens symboliques en dehors du chroot échouera.

--exclude motif

Exclut la copie de fichiers correspondant au motif spécifié. L'option peut être spécifiée plusieurs fois. Voir containerignore(5) pour les formats pris en charge.

--from conteneurOuImage

Utilise le répertoire racine du conteneur de travail ou de l'image spécifié comme répertoire racine lors de la résolution des chemins sources absolus et du chemin du répertoire de contexte. Si une image doit être téléchargée, les options reconnues par buildah pull peuvent être utilisées. Si --chown ou --chmod ne sont pas utilisés, les permissions et la propriété sont préservées.

--ignorefile fichier

Chemin vers un fichier .containerignore (.dockerignore) alternatif. Nécessite que --contextdir soit spécifié.

--link

Crée une couche d'image indépendante pour les fichiers ajoutés au lieu de modifier le système de fichiers du conteneur de travail. Si buildah run crée un fichier et buildah copy --link ajoute un fichier au même chemin, le fichier de buildah copy --link sera présent dans l'image validée. La couche --link est appliquée après toutes les modifications du système de fichiers du conteneur au moment de la validation.

--parents

Préserve les répertoires de tête dans les chemins des éléments en cours de copie, par rapport soit au sommet du contexte de construction, soit au « point de pivot », un emplacement dans le chemin source marqué par un composant de chemin nommé « . » (c'est-à-dire où « /./ » apparaît dans le chemin).

--quiet, -q

S'abstient d'imprimer le digest du contenu copié.

--retry tentatives

Nombre de fois où réessayer en cas d'échec lors de l'opération de téléchargement d'images depuis un registre.

Par défaut à 3.

--retry-delay durée

Durée du délai entre les tentatives de réessai en cas d'échec lors de l'opération de téléchargement d'images depuis un registre.

Par défaut à 2s.

--timestamp secondes

Définit l'horodatage (« mtime ») pour le contenu ajouté à exactement ce nombre de secondes depuis l'époque (temps Unix 0, c'est-à-dire 00:00:00 UTC le 1er janvier 1970) pour aider à permettre des constructions déterministes.

Le répertoire de destination dans lequel le contenu est copié reflétera très probablement le moment où le contenu y a été ajouté.

--tls-verify valeur booléenne

Exige la vérification des certificats lors du téléchargement d'images référencées avec le drapeau --from* (par défaut à vrai). La vérification TLS ne peut pas être utilisée lors de la connexion à un registre non sécurisé.

EXEMPLE

buildah copy containerID '/myapp/app.conf' '/myapp/app.conf'

buildah copy --exclude=*/.md docs containerID 'docs' '/docs'

buildah copy --parents containerID './x/a.txt' './y/a.txt' '/parents'

buildah copy --chown myuser:mygroup containerID '/myapp/app.conf' '/myapp/app.conf'

buildah copy --chmod 660 containerID '/myapp/app.conf' '/myapp/app.conf'

buildah copy containerID '/home/myuser/myproject.go'

buildah copy containerID '/home/myuser/myfiles.tar' '/tmp'

buildah copy containerID '/tmp/workingdir' '/tmp/workingdir'

buildah copy containerID 'https://github.com/containers/buildah' '/tmp'

buildah copy containerID 'passwd' 'certs.d' /etc

FICHIERS

.containerignore/.dockerignore

Si le fichier .containerignore/.dockerignore existe dans le répertoire de contexte, buildah copy en lit le contenu. Si les deux existent, .containerignore est utilisé.

Lorsque l'option --ignorefile est spécifiée, Buildah la lit et l'utilise pour décider quel contenu exclure lors de la copie de contenu dans le conteneur de travail.

Les utilisateurs peuvent spécifier une série de motifs de globbing shell Unix dans un fichier d'exclusion pour identifier les fichiers/répertoires à exclure.

Buildah prend en charge une chaîne de caractères spéciale wildcard ** qui correspond à n'importe quel nombre de répertoires (y compris zéro). Par exemple, **/*.go exclura tous les fichiers se terminant par .go trouvés dans tous les répertoires.

Exemple de fichier .containerignore/.dockerignore :

# voici les fichiers que nous voulons exclure
*/*.c
**/output*
src

*/*.c Exclut les fichiers et répertoires dont les noms se terminent par .c dans n'importe quel sous-répertoire de premier niveau. Par exemple, le fichier source include/rootless.c.

**/output* Exclut les fichiers et répertoires commençant par output depuis n'importe quel répertoire.

src Exclut les fichiers nommés src et le répertoire src ainsi que tout contenu qu'il contient.

Les lignes commençant par ! (point d'exclamation) peuvent être utilisées pour faire des exceptions aux exclusions. Ce qui suit est un exemple de fichier .containerignore/.dockerignore qui utilise ce mécanisme :

*.doc
!Help.doc

Exclut tous les fichiers doc sauf Help.doc lors de la copie de contenu dans le conteneur.

Cette fonctionnalité est compatible avec la gestion des fichiers .containerignore décrite ici :

https://github.com/containers/common/blob/main/docs/containerignore.5.md
