BIND(3P) Manuel du programmeur POSIX BIND(3P)

PROLOGUE

Cette page manuelle fait partie du Manuel du programmeur POSIX. L'implémentation Linux de cette interface peut différer (consultez la page manuelle Linux correspondante pour les détails du comportement de Linux), ou l'interface peut ne pas être implémentée sur Linux.

NOM

bind — associer un nom à un socket

SYNOPSIS

#include <sys/socket.h>
int bind(int socket, const struct sockaddr *address,
    socklen_t address_len);

DESCRIPTION

La fonction bind() assigne une adresse de socket locale address à un socket identifié par le descripteur socket qui n'a pas d'adresse de socket locale assignée. Les sockets créés avec la fonction socket() sont initialement sans nom ; ils ne sont identifiés que par leur famille d'adresses.

La fonction bind() prend les arguments suivants :

socket
Spécifie le descripteur de fichier du socket à lier.
address
Pointe vers une structure sockaddr contenant l'adresse à lier au socket. La longueur et le format de l'adresse dépendent de la famille d'adresses du socket.
address_len
Spécifie la longueur de la structure sockaddr vers laquelle pointe l'argument address .

Le socket spécifié par socket peut nécessiter que le processus dispose des privilèges appropriés pour utiliser la fonction bind() .

Si la famille d'adresses du socket est AF_UNIX et que le chemin de fichier dans address nomme un lien symbolique, bind() échoue et définit errno à [EADDRINUSE].

Si l'adresse du socket ne peut pas être assignée immédiatement et que O_NONBLOCK est défini pour le descripteur de fichier du socket, bind() échoue et définit errno à [EINPROGRESS], mais la requête d'assignation ne doit pas être annulée, et l'assignation doit être complétée de manière asynchrone. Les appels ultérieurs à bind() pour le même socket, avant que l'assignation soit complétée, doivent échouer et définir errno à [EALREADY].

Lorsque l'assignation a été effectuée de manière asynchrone, pselect(), select(), et poll() doivent indiquer que le descripteur de fichier du socket est prêt pour la lecture et l'écriture.

VALEUR RENVOYÉE

À l'issue d'une exécution réussie, bind() renvoie 0 ; sinon, -1 est renvoyé et errno est défini pour indiquer l'erreur.

ERREURS

La fonction bind() doit échouer si :

EADDRINUSE
L'adresse spécifiée est déjà utilisée.
EADDRNOTAVAIL

L'adresse spécifiée n'est pas disponible depuis la machine locale.
EAFNOSUPPORT

L'adresse spécifiée n'est pas une adresse valide pour la famille d'adresses du socket spécifié.
EALREADY
Une requête d'assignation est déjà en cours pour le socket spécifié.
EBADF
L'argument socket n'est pas un descripteur de fichier valide.
EINPROGRESS
O_NONBLOCK est défini pour le descripteur de fichier du socket et l'assignation ne peut pas être effectuée immédiatement ; l'assignation doit être effectuée de manière asynchrone.
EINVAL
Le socket est déjà lié à une adresse, et le protocole ne prend pas en charge la liaison à une nouvelle adresse ; ou le socket a été fermé.
ENOBUFS
Les ressources disponibles étaient insuffisantes pour compléter l'appel.
ENOTSOCK
L'argument socket ne fait pas référence à un socket.
EOPNOTSUPP
Le type de socket du socket spécifié ne prend pas en charge la liaison à une adresse.

Si la famille d'adresses du socket est AF_UNIX, alors bind() doit échouer si :

EACCES
Un composant du chemin de préfixe refuse la permission de recherche, ou le nom demandé nécessite l'écriture dans un répertoire dont le mode refuse la permission d'écriture.
EDESTADDRREQ ou EISDIR

L'argument address est un pointeur nul.
EIO
Une erreur d'E/S s'est produite.
ELOOP
Une boucle existe dans les liens symboliques rencontrés lors de la résolution du chemin de fichier dans address.
ENAMETOOLONG

La longueur d'un composant d'un chemin de fichier est plus longue que {NAME_MAX}.
ENOENT
Un composant du chemin de préfixe du chemin de fichier dans address ne nomme pas un fichier existant ou le chemin de fichier est une chaîne vide.
ENOENT ou ENOTDIR

Le chemin de fichier dans address contient au moins un caractère non-<slash> et se termine par un ou plusieurs caractères <slash> de fin. Si le chemin de fichier sans les caractères <slash> de fin nommerait un fichier existant, une erreur [ENOENT] ne doit pas se produire.
ENOTDIR
Un composant du chemin de préfixe du chemin de fichier dans address nomme un fichier existant qui n'est ni un répertoire ni un lien symbolique vers un répertoire, ou le chemin de fichier dans address contient au moins un caractère non-<slash> et se termine par un ou plusieurs caractères <slash> de fin et le dernier composant du chemin de fichier nomme un fichier existant qui n'est ni un répertoire ni un lien symbolique vers un répertoire.
EROFS
Le nom résiderait sur un système de fichiers en lecture seule.

La fonction bind() peut échouer si :

EACCES
L'adresse spécifiée est protégée et l'utilisateur actuel n'a pas la permission de s'y lier.
EINVAL
L'argument address_len n'est pas une longueur valide pour la famille d'adresses.
EISCONN
Le socket est déjà connecté.
ELOOP
Plus de {SYMLOOP_MAX} liens symboliques ont été rencontrés lors de la résolution du chemin de fichier dans address.
ENAMETOOLONG

La longueur d'un chemin de fichier dépasse {PATH_MAX}, ou la résolution du chemin de fichier d'un lien symbolique a produit un résultat intermédiaire avec une longueur qui dépasse {PATH_MAX}.

Les sections suivantes sont informatives.

EXEMPLES

Le segment de code suivant montre comment créer un socket et le lier à un nom dans le domaine AF_UNIX.

#define MY_SOCK_PATH "/somepath"
int sfd;
struct sockaddr_un my_addr;
sfd = socket(AF_UNIX, SOCK_STREAM, 0);
if (sfd == -1)
    /* Gérer l'erreur */;
memset(&my_addr, '\0', sizeof(struct sockaddr_un));
                     /* Effacer la structure */
my_addr.sun_family = AF_UNIX;
strncpy(my_addr.sun_path, MY_SOCK_PATH, sizeof(my_addr.sun_path) -1);
if (bind(sfd, (struct sockaddr *) &my_addr,
    sizeof(struct sockaddr_un)) == -1)
    /* Gérer l'erreur */;

UTILISATION PAR LES APPLICATIONS

Un programme d'application peut récupérer le nom de socket assignée avec le getsockname().
