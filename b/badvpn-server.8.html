INTRODUCTIO

N

Cette page documente le serveur BadVPN, qui est utilisé dans un réseau VPN BadVPN par les pairs pour communiquer entre eux afin d'établir des connexions de données. Pour une description générale de BadVPN, voir badvp

n(7
).

DESCRIPTIO

N

Le serveur BadVPN est un serveur de discussion utilisé par les nœuds du rés

eau VPN pour communiquer entre eux afin d'établir des connexions de donnée
s. Une fois initialisé, le serveur ne se termine que si un signal est reçu.

OPTION

S

Le serveur BadVPN est entièrement configuré depuis la ligne de

commande.
--he
lp
Affiche la version et la syntaxe de la ligne de commande puis
quitte.
--versi
on
Affiche la version puis
quitte.
--logger
<stdout/syslog>
Sélectionne où journaliser les messages. La valeur par défaut est stdout. Syslog n'est pas disponible sur
Windows.
--syslog-facility
<string>
Lors de la journalisation vers syslog, définit la facilité de journalisation. Le nom de la facilité doit être en
minuscules.
--syslog-ident
<string>
Lors de la journalisation vers syslog, définit
l'ident.
--loglevel <0-5/none/error/warning/notice/info/deb
ug>
Définit le niveau de journalisation par
défaut.
--channel-loglevel <channel-name> <0-5/none/error/warning/notice/info/deb
ug>
Définit le niveau de journalisation pour un canal de journalisation
spécifique.
--listen-addr
<addr>
Ajoute une adresse sur laquelle le serveur doit écouter. Voir ci-dessous pour le format des
adresses.
--s
sl
Utilise TLS. Nécessite --nssdb et --server-cert-na
me.
--nssdb
<string>
Lors de l'utilisation de TLS, la base de données NSS à utiliser. Probablement quelque chose comme sql:
/some/folder.
--server-cert-name
<string>
Lors de l'utilisation de TLS, le nom du certificat à utiliser. Le certificat doit être facilement
accessible.
--comm-predicate
<string>
Définit un prédicat pour définir quelles paires de clients sont autorisées à communiquer. Le prédicat est une expression logique ; voir ci-dessous pour les détails. Fonctions disponibles :
p1name(string) - vrai si le nom commun TLS du pair 1 est égal à la chaîne donnée. Si TLS n'est pas utilisé, le nom commun est supposé être une chaîne vide.
p1addr(string) - vrai si l'adresse IP du pair 1 est égale à la chaîne donnée. La chaîne ne doit pas être un nom.
p2name(string) - vrai si le nom commun TLS du pair 2 est égal à la chaîne donnée. Si TLS n'est pas utilisé, le nom commun est supposé être une chaîne vide.
p2addr(string) - vrai si l'adresse IP du pair 2 est égale à la chaîne donnée. La chaîne ne doit pas être un nom.
Il n'y a pas de règle concernant qui est le pair 1 et qui est le pair 2. Lorsque le serveur doit déterminer s'il faut autoriser deux pairs à communiquer, il évalue le prédicat une fois et dans un ordre non
spécifique.
--relay-predicate
<string>
Définit un prédicat pour définir comment les pairs peuvent relayer des données via d'autres pairs. Le prédicat est une expression logique ; voir ci-dessous pour les détails. Si le prédicat évalue à vrai, le pair P peut relayer des données via le pair R. Fonctions disponibles :
pname(string) - vrai si le nom commun TLS du pair P est égal à la chaîne donnée. Si TLS n'est pas utilisé, le nom commun est supposé être une chaîne vide.
paddr(string) - vrai si l'adresse IP du pair P est égale à la chaîne donnée. La chaîne ne doit pas être un nom.
rname(string) - vrai si le nom commun TLS du pair R est égal à la chaîne donnée. Si TLS n'est pas utilisé, le nom commun est supposé être une chaîne vide.
raddr(string) - vrai si l'adresse IP du pair R est égale à la chaîne donnée. La chaîne ne doit pas être un nom.
--client-socket-sndbuf <bytes
/ 0>
Définit la valeur de l'option de socket SO_SNDBUF pour les sockets TCP clients (zéro
pour ne pas la définir). Des valeurs plus basses amélioreront l'équité lorsque des do
nnées de plusieurs pairs sont envoyées à un pair donné, mais peuvent entraîner une ba
nde passante plus faible si le produit bande passante-délai du réseau est trop grand.

CODE DE

SORTIE

Si l'initialisation échoue, quitte avec le cod

e 1. Sinon, s'exécute jusqu'à ce qu'une termi
naison soit demandée et quitte avec le code 1.

FORMAT DES

ADRESSES

Les adresses ont la forme ipaddr:port, où ipaddr est soit

une adresse IPv4 (nom ou numérique), soit une adresse IPv6
encadrée par des crochets [] (à nouveau nom ou numérique).

PRÉDICAT

S

Le serveur BadVPN inclut un petit langage de prédicats utilisé pour définir certaines politiques. La syntaxe et la sémantique du langage sont décrites

ici.
tr
ue
Constante logique vrai. Évalue
à 1.
fal
se
Constante logique faux. Évalue
à 0.
NOT expre
ssion
Négation logique. Si l'expression évalue à erreur, la négation évalue à
erreur.
expression OR expres
sion
Disjonction logique. La deuxième expression n'est évaluée que si la première expression évalue à faux. Si une sous-expression évalue à erreur, la disjonction évalue à
erreur.
expression AND expre
ssion
Conjonction logique. La deuxième expression n'est évaluée que si la première expression évalue à vrai. Si une sous-expression évalue à erreur, la conjonction évalue à
erreur.
function(arg, ..., arg
)
Évaluation d'une fonction fournie par l'utilisateur (function est le nom de la fonction, [a-zA-Z0-9_]+). Si la fonction avec le nom donné n'existe pas, elle évalue à erreur. Les arguments sont évalués de gauche à droite. Chaque argu
ment peut être soit une expression logique soit une chaîne (caractères encadrés par des guillemets doubles, sans aucun guillemet double). Si un argument est rencontré, mais que tous les arguments nécessaires ont déjà été évalués, la
fonction évalue à erreur. Si un argument est de type incorrect, il n'est pas évalué et la fonction évalue à erreur. Si un argument évalue à erreur, la fonction évalue à erreur. Si après que tous les arguments ont été évalués, la fonc
tion a besoin de plus d'arguments, elle évalue à erreur. Ensuite, la fonction de gestion est appelée. Si elle renvoie autre chose que 1 et 0, la fonction évalue à erreur. Sinon, elle évalue à ce que la fonction de gestion a renvoyé.
