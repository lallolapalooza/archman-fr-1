NOM

bup-fsck - vérifier ou réparer un dépôt bup

SYNTAXE

bup fsck [-r] [-g] [-v] [--quick] [-j jobs] [--par2-ok] [--disable-par2] [noms_de_fichiers...]

DESCRIPTION

bup fsck est un outil pour valider les dépôts bup de la même manière que git fsck valide les dépôts git.

Il peut également générer et/ou utiliser des « blocs de récupération » en utilisant l'outil par2(1) (si vous l'avez installé). Cela vous permet de récupérer des blocs endommagés couvrant jusqu'à 5% de vos fichiers .pack.

Dans un système de sauvegarde normal, les blocs endommagés sont moins importants, car il y a généralement suffisamment de données dupliquées entre les ensembles de sauvegarde pour qu'un seul ensemble de sauvegarde endommagé ne soit pas critique. Dans un système de sauvegarde dédupliqué comme bup, cependant, aucun bloc n'est jamais stocké plus d'une fois, même s'il est utilisé dans chaque sauvegarde. Si ce bloc devenait irrécupérable, tous vos ensembles de sauvegarde seraient endommagés en même temps. Ainsi, il est important de pouvoir vérifier l'intégrité de vos sauvegardes et de récupérer les erreurs de disque si elles se produisent.

AVERTISSEMENT : les fonctionnalités de récupération de bup fsck ne sont pas disponibles à moins que vous n'ayez le paquet gratuit par2(1) installé sur votre serveur bup.

AVERTISSEMENT : bup fsck ne peut évidemment pas récupérer d'une défaillance complète du disque. Si vos sauvegardes sont importantes, vous devez examiner attentivement la redondance (comme l'utilisation de RAID pour la redondance multi-disques, ou la création de sauvegardes hors site pour la redondance de site).

OPTIONS

-r, --repair
tente de réparer les paquets endommagés en utilisant les blocs de récupération existants. (Nécessite par2(1).)
-g, --generate
génère des blocs de récupération pour les paquets qui n'en ont pas déjà. (Nécessite par2(1).)
-v, --verbose
augmente la verbosité (peut être utilisé plus d'une fois).
--quick
n'exécute pas un git verify-pack complet sur chaque fichier de paquet ; vérifie simplement la somme de contrôle finale. Cela peut accélérer considérablement le processus sans diminution évidente de la fiabilité. Cependant, vous pourriez vouloir éviter cette option si vous êtes paranoïaque. N'a aucun effet sur les paquets qui ont déjà des informations de récupération.
-j, --jobs=nb_jobs
nombre maximum de vérifications de paquets à exécuter simultanément. La valeur optimale pour cette option dépend de la rapidité avec laquelle votre CPU peut vérifier les paquets par rapport à votre débit disque. Si vous exécutez trop de tâches simultanément, votre disque sera saturé par les va-et-vient entre les fichiers et les performances diminueront effectivement, même si nb_jobs est inférieur au nombre de cœurs CPU de votre système. Vous pouvez expérimenter avec cette option pour trouver la valeur optimale.
--par2-ok
retourne immédiatement 0 si par2(1) est installé et fonctionnel, ou 1 sinon. Ne vérifie rien.
--disable-par2
fait semblant que par2(1) n'est pas installé et ignore tous les blocs de récupération.

EXEMPLES

# génère des blocs de récupération pour tous les paquets qui n'en ont pas
bup fsck -g
# génère des blocs de récupération pour un paquet particulier
bup fsck -g ~/.bup/objects/pack/153a1420cb1c8*.pack
# vérifie tous les paquets pour l'exactitude (peut être très lent !)
bup fsck
# vérifie tous les paquets pour l'exactitude et récupère ceux qui sont
# endommagés
bup fsck -r
# vérifie un paquet particulier pour l'exactitude et le récupère
# s'il est endommagé
bup fsck -r ~/.bup/objects/pack/153a1420cb1c8*.pack
# vérifie si les blocs de récupération sont disponibles sur ce système
if bup fsck --par2-ok; then
    echo "par2 est ok"
fi
