BYACC(1) Commandes utilisateur BYACC(1)

NOM

byacc - générateur d'analyseurs LALR(1)

SYNTAXE

byacc [ -BdghilLPrtvVy ] [ -b préfixe_fichier ] [ -H fichier_définitions ] [ -o fichier_sortie ] [ -p préfixe_symbole ] nom_fichier

DESCRIPTION

Byacc lit la spécification de grammaire dans le fichier nom_fichier et génère un analyseur LALR(1) pour celle-ci. Les analyseurs consistent en un ensemble de tables d'analyse LALR(1) et une routine pilote écrite en langage C. Byacc écrit normalement les tables d'analyse et la routine pilote dans le fichier y.tab.c.

Les options suivantes sont disponibles :

-b préfixe_fichier
L'option -b change le préfixe ajouté aux noms de fichiers de sortie en la chaîne désignée par préfixe_fichier. Le préfixe par défaut est le caractère y.
-B
crée un analyseur de backtracking (configuration à la compilation pour btyacc).
-d
fait écrire le fichier d'en-tête y.tab.h. Il contient des #define pour les identificateurs de jetons.
-h
affiche un message d'utilisation sur la sortie standard d'erreur.
-H fichier_définitions
fait écrire les #define pour les identificateurs de jetons dans le fichier_définitions donné plutôt que dans le fichier y.tab.h utilisé par l'option -d.
-g
L'option -g fait écrire une description graphique de l'analyseur LALR(1) généré dans le fichier y.dot au format graphviz, prêt à être traité par dot(1).
-i
L'option -i fait écrire un fichier d'en-tête supplémentaire y.tab.i. Il contient des déclarations extern et des #define supplémentaires au besoin pour mapper les noms conventionnels yy-préfijés de yacc à ce que l'option -p peut spécifier. Le fichier de code, par exemple y.tab.c, est modifié pour inclure ce fichier ainsi que le fichier y.tab.h, imposant une utilisation cohérente des symboles définis dans ces fichiers.
Le fichier d'en-tête supplémentaire facilite la séparation de la compilation des fichiers lex et yacc.
-l
Si l'option -l n'est pas spécifiée, byacc insère des directives #line dans le code généré. Les directives #line permettent au compilateur C de relier les erreurs dans le code généré au code original de l'utilisateur. Si l'option -l est spécifiée, byacc n'insère pas les directives #line. Les directives #line spécifiées par l'utilisateur seront conservées.
-L
active le traitement des positions, par exemple, « %locations » (configuration à la compilation pour btyacc).
-o fichier_sortie
spécifie le nom de fichier pour le fichier d'analyseur. Si cette option n'est pas donnée, le nom de fichier de sortie est le préfixe du fichier concaténé avec le suffixe du fichier, par exemple, y.tab.c. Cela remplace l'option -b.
-p préfixe_symbole
L'option -p change le préfixe ajouté aux symboles générés par yacc en la chaîne désignée par préfixe_symbole. Le préfixe par défaut est la chaîne yy.
-P
crée un analyseur réentrant, par exemple, « %pure-parser ».
-r
L'option -r fait produire par byacc des fichiers séparés pour le code et les tables. Le fichier de code est nommé y.code.c, et le fichier de tables est nommé y.tab.c. Le préfixe « y. » peut être remplacé en utilisant l'option -b.
-s
supprime les instructions « #define » générées pour les littéraux de chaînes dans une instruction « %token », pour mieux correspondre au comportement original de yacc.
Normalement, lorsque byacc voit une ligne telle que
%token OP_ADD "ADD"
il remarque que « ADD » entre guillemets est un identificateur C valide, et génère un #define non seulement pour OP_ADD, mais aussi pour ADD, par exemple :
#define OP_ADD 257
#define ADD 258
Le yacc original ne génère pas le second « #define ». L'option -s supprime ce « #define ».
POSIX (IEEE 1003.1 2004) ne documente que les noms et les nombres pour « %token », bien que le yacc original et bison acceptent également les littéraux de chaînes.
-t
L'option -t modifie les directives de préprocesseur générées par byacc afin que les instructions de débogage soient incorporées dans le code compilé.
Byacc envoie la sortie de débogage à la sortie standard (compatible avec le yacc original et btyacc), tandis que btyacc écrit la sortie de débogage sur la sortie d'erreur standard (comme bison).
-v
L'option -v fait écrire une description lisible par l'homme de l'analyseur généré dans le fichier y.output.
-V
affiche le numéro de version sur la sortie standard.
-y
byacc ignore cette option, que bison supporte pour une compatibilité ostensible avec POSIX.

Le paramètre nom_fichier n'est pas optionnel. Cependant, byacc accepte un unique « - » pour lire la grammaire depuis l'entrée standard. Un marqueur double « -- » dénote la fin des options. Un unique paramètre nom_fichier est attendu après un marqueur « -- ».

DIAGNOSTICS

S'il y a des règles qui ne sont jamais réduites, leur nombre est rapporté sur la sortie d'erreur standard. S'il y a des conflits LALR(1), leur nombre est rapporté sur la sortie d'erreur standard.

EXTENSIONS

Byacc fournit quelques extensions pour la compatibilité avec bison et d'autres implémentations de yacc. Il accepte plusieurs options longues qui ont des équivalents dans byacc. Les fonctionnalités %destructor et %locations ne sont disponibles que si byacc a été configuré et compilé pour supporter la fonctionnalité de backtracking (btyacc). Les fonctionnalités restantes sont toujours disponibles :

%code mot-clé { code }
Ajoute le code source indiqué à un point donné du fichier de sortie. Le mot-clé optionnel indique à byacc où insérer le code :
top
juste après la définition de version dans le fichier de code généré.
requires
juste après la déclaration des variables publiques de l'analyseur. Si l'option -d est donnée, le code est inséré au début du fichier de définitions.
provides
juste après la déclaration des variables privées de l'analyseur. Si l'option -d est donnée, le code est inséré à la fin du fichier de définitions.
Si aucun mot-clé n'est donné, le code est inséré au début de la section de code copiée verbatim à partir du fichier source. Plusieurs directives %code peuvent être données ; byacc les insère dans le fichier de code ou de définitions correspondant dans l'ordre où elles apparaissent dans le fichier source.
%debug
Ceci a le même effet que l'option de ligne de commande « -t ».
