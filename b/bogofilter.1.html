DESCRIPTIO

N

Bogofilter est un filtre anti-spam bayésien. Dans son mode de fonctionnement normal, il prend un message courriel ou un autre texte sur l'entrée standard, effectue un test statistique par rappor

t à des listes de mots « bons » et « mauvais », et renvoie un code d'état indiquant si le message est un spam ou non. Bogofilter est conçu avec un algorithme rapide, utilise Berkeley DB pour
un démarrage et des recherches rapides, est codé directement en C, et est optimisé pour la vitesse, afin qu'il puisse être utilisé en production par des sites qui traitent beaucoup de courriels.

THÉORIE DU

FONCTIONNEMENT

Bogofilter traite son entrée comme un sac de jetons. Chaque jeton est vérifié par rapport à une liste de mots, qui maintient des comptages du nombre de fois où il est survenu dans des courriels non-spam et spam. Ces nombres sont utilisés pour calculer une estimation de la probabilité qu'un message dans lequel le jeton apparaît soit un spam. Ceux-ci sont combinés pour indiquer si le message est un spam ou un

ham.

Bien que cette méthode semble rudimentaire comparée à l'approche plus courante de la correspondance de motifs, elle s'avère extrêmement efficace. L'article de Paul Graham A Plan For Spam[1] est une lecture

recommandée.

Ce programme améliore considérablement la proposition de Paul en effectuant une analyse lexicale plus intelligente. Bogofilter effectue un décodage MIME approprié et un analyse HTML raisonnable. Des types spéciaux de jetons comme les noms d'hôte et les adresses IP sont conservés comme caractéristiques de reconnaissance plutôt que d'être découpés. Divers types de superfluités de MTA tels que les dates et les identifiants de message sont ignorés afin de ne pas gonfler la liste de mots. Les jetons trouvés dans divers champs d'en-tête sont marqués de manière

appropriée.

Une autre amélioration est que ce programme propose les modifications suggérées par Gary Robinson aux calculs (voir les paramètres robx et robs ci-dessous). Ces modifications sont décrites dans l'article de Robinson Spam Detect

ion[2].

Depuis, Robinson (voir son article dans Linux Journal A Statistical Approach to the Spam Problem[3]) et d'autres ont réalisé que le calcul peut être encore optimisé en utilisant la méthode de Fisher. Une autre amélioration[4] compense la redondance des jetons en appliquant des facteurs de taille effective (ESF) séparés aux calculs de probabilité spam et

non-spam.

En bref, voici comment cela fonctionne : Les estimations des probabilités de spam des jetons individuels sont combinées en utilisant la « fonction du chi-carré inverse ». Sa valeur indique à quel point l'hypothèse nulle selon laquelle le message est simplement une collection aléatoire de mots indépendants avec des probabilités données par nos estimations précédentes échoue. Cette fonction est très sensible aux petites probabilités (mots ham), mais pas aux hautes probabilités (mots spam) ; la valeur n'indique donc que des signes fortement ham dans un message. En utilisant maintenant les probabilités inverses pour les jetons, le même calcul est refait, donnant un indicateur selon lequel un message semble fortement spam. Enfin, ces deux indicateurs sont soustraits (et mis à l'échelle dans un intervalle 0-1). Cet indicateur combiné (bogosité) est proche de 0 si les signes pour un message ham sont plus forts que pour un message spam, et proche de 1 si la situation est l'inverse. Si les signes pour les deux sont également forts, la valeur sera proche de 0,5. Comme ces messages ne donnent pas d'indication claire, il existe un mode à trois états dans bogofilter pour marquer ces messages comme incertains, tandis que les messages clairs sont marqués comme spam ou ham, respectivement. En mode à deux états, chaque message est marqué comme spam ou

ham.

Divers paramètres influencent ces calculs, les plus importants sont

:

robx : le score donné à un jeton qui n'a pas été vu auparavant. robx est la probabilité que le jeton soit

spam.

robs : un poids sur robx qui déplace la probabilité d'un jeton rarement vu vers

robx.

min-dev : une distance minimale par rapport à .5 pour les jetons à utiliser dans le calcul. Seuls les jetons plus éloignés de 0,5 que cette valeur sont

utilisés.

spam-cutoff : les messages dont les scores sont supérieurs ou égaux à seront marqués comme

spam.

ham-cutoff : Si zéro ou spam-cutoff, tous les messages dont les valeurs sont strictement inférieures à spam-cutoff sont marqués comme ham, tous les autres comme spam (deux états). Sinon, les valeurs inférieures ou égales à ham-cutoff sont marquées comme ham, les messages dont les valeurs sont strictement comprises entre ham-cutoff et spam-cutoff sont marqués comme incertains ; le reste comme spam (trois

états)

sp-esf : le facteur de taille effective (ESF) pour le

spam.

ns-esf : l'ESF pour le non-spam. Ces valeurs ESF par défaut sont 1,0, ce qui revien

t à ne pas utiliser l'ESF dans le calcul. Des valeurs adaptées à la population de
courriels d'un utilisateur peuvent être déterminées à l'aide du programme bogotune.

OPTIONS

D'AIDE

L'option -h affiche le message d'aide et se

termine.

L'option -V affiche le numéro de version et se

termine.

L'option -Q (query) affiche la configuration de bogofilter, c'est-à-dire les paramètres d'enregistrement, les options d'analyse, le répertoire de bogofilter,

etc.

OPTIONS DE

CLASSIFICATION

L'option -p (passthrough) produit le message avec une ligne X-Bogosity à la fin de l'en-tête du message. Cela nécessite de conserver le message entier en mémoire lorsqu'il est lu depuis stdin (ou depuis un tube ou un socket). Si le message est lu depuis un fichier qui peut être rembobiné, bogofilter le lira une seconde

fois.

L'option -e (embed) indique à bogofilter de se terminer avec le code 0 si le message peut être classé, c'est-à-dire s'il n'y a pas d'erreur. Normalement, bogofilter utilise des codes différents pour les classifications spam, ham et incertain, mais cela simplifie l'utilisation de bogofilter avec procmail ou

maildrop.

L'option -t (terse) indique à bogofilter d'imprimer un message de spamicité abrégé contenant 1 lettre et le score. Le spam est indiqué par « Y », le ham par « N », et l'incertain par « U ». Remarque : le formatage peut être personnalisé à l'aide du fichier de

configuration.

L'option -T fournit un mode terse invariable pour les scripts. bogofilter imprimera un message de spamicité abrégé contenant 1 lettre et le score. Le spam est indiqué par « S », le ham par « H », et l'incertain par « U »

.

L'option -TT fournit un mode terse invariable pour les scripts. Bogofilter n'imprime que le score et l'affiche avec 16 chiffres

significatifs.

L'option -u indique à bogofilter d'enregistrer le texte du message après l'avoir classé comme spam ou non-spam. Un message spam sera enregistré sur la liste spam et un message non-spam sur la liste bonne. Si la classification est « incertain », le message ne sera pas enregistré. En pratique, cette option exécute bogofilter avec les -s ou -n drapeaux, selon le cas. La prudence est recommandée dans l'utilisation de cette fonctionnalité, car toute erreur de classification que bogofilter pourrait commettre sera préservée et s'accumulera jusqu'à ce qu'elle soit corrigée manuellement avec les -Sn et -Ns combinaisons d'options. Notez que cette option provoque l'ouverture de la base de données en accès écriture, ce qui peut entraîner des ralentissements massifs dus aux conflits de verrouillage et aux opérations d'E/S

synchrones.

L'option -H indique à bogofilter de ne pas marquer les jetons de l'en-tête. Cette option est destinée aux tests, vous ne devriez pas l'utiliser en fonctionnement

normal.

L'option -M indique à bogofilter de traiter son entrée comme un fichier au format mbox. Si les options -v ou -t sont également données, une ligne de probabilité de spam sera imprimée pour chaque message.

L'option -b (mode de traitement groupé en continu) indique à bogofilter de classifier plusieurs objets dont les noms sont lus depuis l'entrée standard. Si les options -v ou -t sont également données, bogofilter imprimera une ligne fournissant le nom du fichier et les informations de classification pour chaque fichier. Ceci est une alternative à -B qui liste les objets sur la ligne de commande.

Dans ce contexte, un objet est un maildir (détecté automatiquement), ou s'il ne s'agit pas d'un maildir, un message unique, sauf si -M est donnée, auquel cas il est traité comme un mbox. (L'en-tête Content-Length: n'est actuellement pas pris en compte.)

Lors de la lecture au format mbox, bogofilter se base sur la ligne vide après un message. Si nécessaire, formail -es garantira que c'est le cas.

L'option -B objet ... (mode de traitement groupé) indique à bogofilter de classifier plusieurs objets nommés sur la ligne de commande. Les objets peuvent être des noms de fichiers (pour les messages uniques), des boîtes aux lettres (fichiers contenant plusieurs messages) ou des répertoires (au format maildir et MH). Si les options -v ou -t sont également données, bogofilter imprimera une ligne donnant le nom du fichier et les informations de classification pour chaque fichier. Ceci est une alternative à -b qui liste les objets sur l'entrée standard.

L'option -R indique à bogofilter de produire un cadre de données R sous forme de texte sur la sortie standard. Voir la section sur l'intégration avec R, ci-dessous, pour plus de détails.

OPTIONS D'ENREGISTREMENT

L'option -s indique à bogofilter d'enregistrer le texte présenté comme spam. La base de données est créée si elle est absente.

L'option -n indique à bogofilter d'enregistrer le texte présenté comme non-spam.

Bogofilter ne détecte pas si un message est enregistré deux fois. Si vous faites cela par accident, les décomptes de jetons seront décalés de 1 par rapport à ce que vous souhaitez réellement et les scores de spam correspondants seront légèrement incorrects. Étant donné un grand nombre de jetons et de messages dans la liste de mots, cela n'a pas d'importance. Le problème *peut* être corrigé en utilisant l'option -S ou l'option -N.

L'option -S indique à bogofilter d'annuler un enregistrement précédent du même message comme spam. Si un message a été incorrectement saisi comme spam par -s ou -u et que vous souhaitez le supprimer et l'entrer comme non-spam, utilisez -Sn. Si -S est utilisé pour un message qui n'a pas été enregistré comme spam, les décomptes seront quand même décrémentés.

L'option -N indique à bogofilter d'annuler un enregistrement précédent du même message comme non-spam. Si un message a été incorrectement entré comme non-spam par -n ou -u et que vous souhaitez le supprimer et l'entrer comme spam, utilisez alors -Ns. Si -N est utilisé pour un message qui n'a pas été enregistré comme non-spam, les décomptes seront quand même décrémentés.

OPTIONS GÉNÉRALES

L'option -c nom_fichier indique à bogofilter de lire le fichier de configuration spécifié.

L'option -C empêche bogofilter de lire les fichiers de configuration.

L'option -d rép permet de définir le répertoire de la base de données. Voir la section ENVIRONNEMENT pour d'autres options de définition de répertoire.

L'option -k taille_cache définit la taille du cache pour le sous-système BerkeleyDB, en unités de 1 Mio (1 048 576 octets). Une taille de cache appropriée améliore les performances de bogofilter. La taille recommandée est d'un tiers de la taille du fichier de base de données. Vous pouvez exécuter le script bogotune (dans le répertoire de réglage) pour déterminer la taille recommandée.

L'option -l écrit une ligne d'information dans le journal du système à chaque fois que bogofilter est exécuté. Les informations enregistrées dépendent de la manière dont bogofilter est exécuté.

L'option -L étiquette configure une étiquette qui peut être incluse dans les informations enregistrées par l'option -l, mais cela nécessite un format personnalisé qui inclut la chaîne %l pour l'instant. Cette option implique -l.

L'option -I nom_fichier indique à bogofilter de lire son entrée depuis le fichier spécifié, plutôt que depuis **stdin**.

L'option -O nom_fichier indique à bogofilter où écrire sa sortie en mode de transmission directe. Notez que cela ne fonctionne que lorsque -p est explicitement donné.

OPTIONS DE PARAMÈTRES

L'option -E valeur[,valeur] permet de définir la valeur sp-esf et la valeur ns-esf. Avec deux valeurs, sp-esf et ns-esf sont toutes deux définies. Si une seule valeur est donnée, les paramètres sont définis comme décrit dans la note ci-dessous.

L'option -m valeur[,valeur][,valeur] permet de définir la valeur min-dev et, éventuellement, les valeurs robs et robx. Avec trois valeurs, min-dev, robs et robx sont toutes définies. Si moins de valeurs sont données, les paramètres sont définis comme décrit dans la note ci-dessous.

L'option -o valeur[,valeur] permet de définir les valeurs spam-cutoff et ham-cutoff. Avec deux valeurs, spam-cutoff et ham-cutoff sont toutes deux définies. Si une seule valeur est donnée, les paramètres sont définis comme décrit dans la note ci-dessous.

Note : Toutes ces options permettent de fournir moins de valeurs. Les valeurs peuvent être sautées en utilisant simplement le délimiteur virgule, auquel cas les paramètres correspondants ne seront pas modifiés. Si seule la première valeur est fournie, alors seul le premier paramètre est défini. Les valeurs finales peuvent être sautées, auquel cas les paramètres correspondants ne seront pas modifiés. Dans la liste des paramètres, les espaces ne sont pas autorisés après les virgules.

OPTIONS D'INFORMATION

L'option -v produit un rapport sur la sortie standard concernant l'analyse de l'entrée par bogofilter. Chaque v supplémentaire augmentera le niveau de détail de la sortie, jusqu'à un maximum de 4. Avec -vv, le rapport liste les jetons avec la plus grande déviation par rapport à une moyenne de 0,5 d'association avec le spam.

L'option -y date peut être utilisée pour remplacer la date actuelle lors de l'horodatage des jetons. Une valeur de zéro (0) désactive l'horodatage.

L'option -D redirige la sortie de débogage vers stdout.

L'option -x indicateurs permet de définir des indicateurs de débogage pour imprimer des informations de débogage. Voir le fichier d'en-tête debug.h pour la liste des indicateurs utilisables.

OPTIONS DE FICHIER DE CONFIGURATION

En utilisant la syntaxe GNU longopt --, une instruction nom=valeur d'un fichier de configuration devient --option=valeur d'une ligne de commande. Utilisez la commande bogofilter --help pour une liste des options et consultez bogofilter.cf.example pour plus d'informations à leur sujet. Par exemple, pour changer l'en-tête X-Bogosity en "X-Spam-Header", utilisez :

--spam-header-name=X-Spam-Header

ENVIRONNEMENT

Bogofilter utilise un répertoire de base de données, qui peut être défini dans le fichier de configuration. S'il n'est pas défini là, bogofilter utilisera la valeur de BOGOFILTER_DIR. Les deux peuvent être remplacés par l'option -d rép. Si aucune de ces options n'est disponible, bogofilter utilisera le répertoire $HOME/.bogofilter.

CONFIGURATION

La ligne de commande de bogofilter permet de définir de nombreuses options qui déterminent le fonctionnement de bogofilter. Le fichier /etc/bogofilter/bogofilter.cf peut être utilisé pour définir des paramètres supplémentaires qui affectent son fonctionnement. Le fichier /etc/bogofilter/bogofilter.cf.example contient des exemples de tous les paramètres. Les messages de statut et de journalisation peuvent être personnalisés pour chaque site.

VALEURS DE RETOUR

0 pour spam ; 1 pour non-spam ; 2 pour incertain ; 3 pour erreurs d'E/S ou autres.

Si -p et -e sont tous deux utilisés, les valeurs de retour sont : 0 pour spam ou non-spam ; 3 pour erreurs d'E/S ou autres.

L'erreur 3 signifie généralement que le fichier de mots que bogofilter souhaite lire au démarrage est manquant ou que le disque dur est plein en mode -p.

INTÉGRATION AVEC D'AUTRES OUTILS

Utilisation avec procmail

La recette suivante (a) envoie dans des dossiers de spam tout ce que bogofilter classe comme spam, (b) enregistre les mots des messages classés comme spam en tant que tels, et (c) enregistre les mots des messages classés comme non-spam en tant que tels. Avec cela en place, il ne sera normalement nécessaire à l'utilisateur d'intervenir (avec -Ns ou -Sn) que lorsque bogofilter a mal classé quelque chose.

# filtre les courriels via bogofilter, les étiquetant comme Ham, Spam, ou Inconnu,
# et met à jour la liste de mots
:0fw
| bogofilter -u -e -p
# si bogofilter échoue, renvoyer le courriel dans la file d'attente ;
# le MTA tentera de le livrer plus tard
# 75 est la valeur pour EX_TEMPFAIL dans /usr/include/sysexits.h
:0e
{ EXITCODE=75 HOST }
# classe le courriel dans spam-bogofilter s'il s'agit de spam.
:0:
* ^X-Bogosity: Spam, tests=bogofilter
spam-bogofilter
# classe le courriel dans unsure-bogofilter
# s'il ne s'agit ni de ham ni de spam.
:0:
* ^X-Bogosity: Unsure, tests=bogofilter
unsure-bogofilter
# Avec cette recette, vous pouvez entraîner bogofilter en partant d'une
# liste de mots vide. Assurez-vous de vérifier régulièrement votre dossier
# unsure, d'en retirer les messages, de les classer comme ham (ou spam), et de
# les utiliser pour entraîner bogofilter.

La règle procmail suivante prendra le courrier de l'entrée standard et le sauvegardera dans le fichier spam si bogofilter le considère comme spam :

:0HB:
* ? bogofilter
spam

et cette règle similaire enregistrera également les jetons du courrier selon la classification de bogofilter :

:0HB:
* ? bogofilter -u
spam

Si bogofilter échoue (retourne 3) le message sera traité comme non-spam.

Ceci est pour maildrop, il reporte automatiquement le courrier et réessaie plus tard lorsque la commande xfilter échoue, utilisez ceci dans votre ~/.mailfilter :

xfilter "bogofilter -u -e -p"
if (/^X-Bogosity: Spam, tests=bogofilter/)
{
  to "spam-bogofilter"
}

Les lignes .muttrc suivantes créeront des macros mutt pour envoyer le courrier à bogofilter.

macro index d "<enter-command>unset wait_key\n\
<pipe-entry>bogofilter -n\n\

<delete-message>" "supprimer le message comme non-spam"
macro index \ed "<enter-command>unset wait_key\n\
<pipe-entry>bogofilter -s\n\
<enter-command>set wait_key\n\
<delete-message>" "supprimer le message comme spam"

bogofilter.1.en

¶

NOM

bogofilter - filtre anti-spam bayésien

SYNTAXE

bogofilter [-b] [-c fichier_cfg] [-C] [-d] [-e] [-E] [-f] [-F] [-h] [-i] [-I] [-l] [-L] [-m] [-n] [-N] [-o] [-p] [-P] [-q] [-Q] [-r] [-R] [-s] [-S] [-t] [-T] [-u] [-v] [-V] [-w] [-x] [-X] [-z] [-Z] [-?] [--] [fichier_message ...]

DESCRIPTION

Bogofilter est un programme de détection de spam basé sur une approche statistique. Il utilise une version améliorée de la formule de Naive Bayes pour déterminer la probabilité qu'un message donné soit du spam.

Il est conçu pour être aussi simple que possible à utiliser et à intégrer dans un système de messagerie existant.

THÉORIE DU FONCTIONNEMENT

Bogofilter calcule la probabilité qu'un mot donné apparaisse dans un message de spam ou dans un message normal (ham). Il utilise ensuite ces probabilités pour calculer la probabilité globale qu'un message soit du spam.

L'algorithme est basé sur le travail de Paul Graham (voir NOTES[1]), mais avec des améliorations basées sur les travaux de Gary Robinson (voir NOTES[4]).

La formule de Robinson, qui est utilisée ici, est une amélioration de la formule de calcul du Chi-carré utilisée par Paul Graham.

OPTIONS

Les options suivantes sont disponibles :

-b
Active le mode "bogus". Dans ce mode, bogofilter ne modifie pas le fichier d'origine. Il écrit le résultat dans la sortie standard et ajoute un en-tête X-Bogosity au message.
-c fichier_cfg
Utilise le fichier de configuration spécifié au lieu du fichier par défaut (voir FICHIERS).
-C
Ignore les fichiers de configuration, y compris le fichier de configuration du système.
-d
Désactive la mise à jour de la base de données des mots. Cela est utile pour tester les classifications sans modifier la base de données.
-e
Ajoute un en-tête X-Bogofilter-Status au message de sortie s'il est classé comme spam.
-E
Ajoute un en-tête X-Bogofilter-Score au message de sortie.
-f
Force la classification même si le message est vide. Par défaut, les messages vides sont ignorés.
-F
Force l'utilisation de l'encodage UTF-8 pour le traitement des messages. Par défaut, bogofilter essaie de détecter l'encodage du message.
-h
Affiche un message d'aide et quitte.
-i
N'affiche pas l'en-tête X-Bogosity. Utile lorsque l'on utilise l'option -b.
-I
Examine le contenu du message à la recherche de marqueurs d'encodage et ajoute l'en-tête X-Bogosity : X-Content-Canonical-Encoding.
-l
Enregistre les messages de journalisation dans le système de journalisation du système (syslog).
-L
Traite les messages en ligne de commande comme s'ils provenaient d'une spécification de filtre de l'utilisateur, et non du système.
-m
Ne traite pas le message d'en-tête. Ceci est utile pour les programmes de messagerie qui ne transmettent pas toujours les en-têtes correctement. Le corps seul sera traité.
-n
Enregistre le message comme n'étant PAS du spam (ham).
-N
Similaire à -n, mais enregistre également le message comme n'étant PAS du spam même s'il a été précédemment classé comme spam.
-o
Ne supprime pas les en-têtes X-Bogosity, X-Bogosity-Score et X-Spam-Status existants. Utile lors de l'utilisation de l'option -b.
-p
Utilisé avec -u pour classer et mettre à jour le fichier de liste de mots. Le message est ensuite renvoyé au système de messagerie.
-P
Utilisé avec -u pour classer et mettre à jour le fichier de liste de mots. Le message n'est pas renvoyé au système de messagerie.
-q
Mode silencieux. N'affiche rien, sauf en cas d'erreur.
-Q
Mode silencieux, mais affiche toujours les erreurs.
-r
Mode "rebuild". Le fichier de base de données des mots est reconstruit.
-R
Génère un data frame R qui peut être utilisé pour vérifier les calculs de bogofilter.
-s
Enregistre le message comme étant du spam.
-S
Similaire à -s, mais enregistre également le message comme étant du spam même s'il a été précédemment classé comme non spam.
-t
Écrit un rapport de test dans la sortie standard. Ceci est utile pour tester la précision du filtre.
-T
Désactive la mise à jour de la base de données des mots. Ceci est une alternative à l'option -d.
-u
Ne pas afficher le résultat de la classification sur la sortie standard. Cela est utile lorsque vous utilisez l'option -p.
-v
Mode verbeux. Affiche des informations détaillées sur le traitement du message.
-V
Affiche la version du programme et quitte.
-w
Ne pas mettre à jour la base de données des mots. Ceci est une alternative à l'option -d.
-x
Désactive le traitement des en-têtes MIME. Ceci est utile pour les messages qui ne sont pas correctement encodés en MIME.
-X
Traite les messages en ligne de commande comme s'ils provenaient d'un programme de messagerie, et non d'un filtre utilisateur.
-z
Ignore les messages vides. Ceci est le comportement par défaut.
-Z
Traite les messages comme s'ils étaient tous marqués comme spam.
-?
Affiche un message d'aide et quitte.
--
Indique la fin des options. Tout ce qui suit est considéré comme un nom de fichier.

ENVIRONNEMENT

Les variables d'environnement suivantes peuvent être utilisées pour configurer bogofilter :

BOGOFILTER_CFG
Définit le chemin du fichier de configuration.
BOGOFILTER_DBDIR
Définit le répertoire où sont stockées les bases de données.

CONFIGURATION

Bogofilter peut être configuré à l'aide de fichiers de configuration. Le fichier de configuration système est généralement situé dans /etc/bogofilter/bogofilter.cf, et le fichier de configuration utilisateur dans ~/.bogofilter.cf.

Les options de configuration incluent :

dbdir
Répertoire où sont stockées les bases de données.
min_dev
Valeur minimale de déviation pour qu'un mot soit considéré comme significatif.
min_prob
Probabilité minimale pour qu'un message soit classé comme spam.
max_prob
Probabilité maximale pour qu'un message soit classé comme non spam.

VALEURS DE RETOUR

Bogofilter renvoie 0 en cas de succès, et une valeur non nulle en cas d'erreur.

INTÉGRATION AVEC D'AUTRES OUTILS

Pour intégrer bogofilter dans un système de messagerie, il faut généralement suivre les étapes suivantes :

1. Configurez votre MTA (Mail Transfer Agent) pour qu'il transmette les messages à bogofilter.

2. Utilisez les options appropriées de bogofilter pour qu'il ajoute les en-têtes de classification aux messages.

3. Configurez votre agent de livraison de courrier (MDA) pour qu'il trie les messages en fonction des en-têtes ajoutés par bogofilter.

4. Configurez le MTA pour qu'il appelle bogofilter sur chaque message. Cette étape est spécifique au MTA, mais vous devrez probablement utiliser les options -p, -u et -e.

5. Mettez en place un mécanisme permettant aux utilisateurs d'enregistrer les messages de spam/non-spam, ainsi que de corriger les classifications erronées. La solution la plus générique consiste à configurer des adresses électroniques alias auxquelles les utilisateurs renvoient les messages.

6. Consultez les répertoires doc et contrib pour plus d'informations.

Utilisation de R pour vérifier les calculs de bogofilter

L'option -R indique à bogofilter de générer un data frame R. Ce data frame contient une ligne par jeton analysé. Chaque ligne contient le jeton, la somme de ses comptages "bon" et "spam" dans la base de données, le comptage "bon" divisé par le nombre de messages non-spam utilisés pour créer la base de données d'apprentissage, le comptage "spam" divisé par le nombre de messages spam, le f(w) de Robinson pour le jeton, les logarithmes naturels de (1 - f(w)) et f(w), ainsi qu'un indicateur (+ si la valeur f(w) du jeton a dépassé la déviation minimale par rapport à 0,5, - sinon). Il y a une ligne supplémentaire à la fin du tableau qui contient une étiquette dans le champ jeton, suivie du nombre de mots réellement utilisés (ceux avec des indicateurs +), des valeurs P, Q, S, s et x de Robinson, et de la déviation minimale.

Le data frame R peut être enregistré dans un fichier et ensuite lu dans une session R (voir le site web du projet R[5] pour des informations sur le paquet de mathématiques R). Une simple script R (fichier bogo.R) est fourni avec la distribution de bogofilter et peut être utilisé pour vérifier les calculs de bogofilter. Les instructions pour son utilisation sont incluses dans le script sous forme de commentaires.

MESSAGES DE JOURNALISATION

Bogofilter écrit des messages dans le journal système lorsque l'option -l est utilisée. Ce qui est écrit dépend des autres options utilisées.

Une exécution de classification générera (nous n'affichons pas la partie date et hôte ici) :

bogofilter[1412]: X-Bogosity: Ham, spamicity=0.000227
bogofilter[1415]: X-Bogosity: Spam, spamicity=0.998918

L'utilisation de -u pour classifier un message et mettre à jour une liste de mots produira (sur une seule ligne) :

bogofilter[1426]: X-Bogosity: Spam, spamicity=0.998918,
  register -s, 329 mots, 1 message

L'enregistrement de mots (-l et -s, -n, -S, ou -N) produira :

bogofilter[1440]: register-n, 255 mots, 1 message

Une exécution d'enregistrement (utilisant -s, -n, -N, ou -S) générera des messages tels que :

bogofilter[17330]: register-n, 574 mots, 3 messages
bogofilter[6244]: register-s, 1273 mots, 4 messages
