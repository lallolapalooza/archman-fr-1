BIO_read(3ssl)

Paquet: openssl

Licences: Apache-2.0

BIO_READ(3ssl) OpenSSL BIO_READ(3ssl)

NOM

BIO_read_ex, BIO_write_ex, BIO_read, BIO_write, BIO_gets, BIO_get_line, BIO_puts - Fonctions d'E/S BIO

SYNOPIS

#include <openssl/bio.h>
int BIO_read_ex(BIO *b, void *data, size_t dlen, size_t *readbytes);
int BIO_write_ex(BIO *b, const void *data, size_t dlen, size_t *written);
int BIO_read(BIO *b, void *data, int dlen);
int BIO_gets(BIO *b, char *buf, int size);
int BIO_get_line(BIO *b, char *buf, int size);
int BIO_write(BIO *b, const void *data, int dlen);
int BIO_puts(BIO *b, const char *buf);

DESCRIPTION

BIO_read_ex() tente de lire dlen octets depuis le BIO b et place les données dans data. Si des octets ont été lus avec succès, le nombre d'octets lus est stocké dans *readbytes.

BIO_write_ex() tente d'écrire dlen octets depuis data vers le BIO b. En cas de succès, le nombre d'octets écrits est stocké dans *written, sauf si written est NULL.

BIO_read() tente de lire len octets depuis le BIO b et place les données dans buf.

BIO_gets() effectue l'opération « gets » du BIO et place les données dans buf. Généralement, cette opération tente de lire une ligne de données à partir du BIO d'une longueur maximale de taille-1. Il existe des exceptions, par exemple, BIO_gets() sur un BIO de digest calculera et retournera le digest, et d'autres BIOs peuvent ne pas prendre en charge BIO_gets() du tout. La chaîne retournée est toujours terminée par NUL et le '\n' est conservé s'il est présent dans les données d'entrée. Sur une entrée binaire, il peut y avoir des caractères NUL dans la chaîne ; dans ce cas, la valeur de retour (si non négative) peut donner une longueur incorrecte.

BIO_get_line() tente de lire depuis le BIO b une ligne de données jusqu'au prochain '\n' ou jusqu'à ce que la longueur maximale taille-1 soit atteinte, et place les données dans buf. La chaîne retournée est toujours terminée par NUL et le '\n' est conservé s'il est présent dans les données d'entrée. Sur une entrée binaire, il peut y avoir des caractères NUL dans la chaîne ; dans ce cas, la valeur de retour (si non négative) donne la longueur réelle lue. Pour implémenter cela, malheureusement, les données doivent être lues octet par octet.

BIO_write() tente d'écrire len octets depuis buf vers le BIO b.

BIO_puts() tente d'écrire une chaîne terminée par NUL buf vers le BIO b.

VALEUR DE RETOUR

BIO_read_ex() renvoie 1 si des données ont été lues avec succès, et 0 sinon.

BIO_write_ex() renvoie 1 si aucune erreur n'a été rencontrée lors de l'écriture des données, 0 sinon. Demander l'écriture de 0 octet n'est pas considéré comme une erreur.

BIO_write() renvoie -2 si l'opération « write » n'est pas implémentée par le BIO ou -1 en cas d'autres erreurs. Sinon, elle renvoie le nombre d'octets écrits. Cela peut être 0 si le BIO b est NULL ou dlen <= 0.

BIO_gets() renvoie -2 si l'opération « gets » n'est pas implémentée par le BIO ou -1 en cas d'autres erreurs. Sinon, elle renvoie typiquement la quantité de données lues, mais selon l'implémentation, elle peut renvoyer uniquement la longueur jusqu'au premier caractère NUL contenu dans les données lues. Dans tous les cas, le NUL final ajouté après les données lues n'est pas inclus dans la longueur retournée.

Toutes les autres fonctions renvoient soit la quantité de données lues ou écrites avec succès (si la valeur de retour est positive), soit qu'aucune donnée n'a été lue ou écrite avec succès si le résultat est 0 ou -1. Si la valeur de retour est -2, l'opération n'est pas implémentée dans le type de BIO spécifique.

NOTES

Une valeur de retour de 0 ou -1 n'est pas nécessairement une indication d'erreur. En particulier, lorsque la source/destination n'est pas bloquante ou d'un certain type, cela peut simplement indiquer qu'aucune donnée n'est actuellement disponible et que l'application devrait réessayer ultérieurement.

Une technique parfois utilisée avec les sockets bloquants consiste à utiliser un appel système (tel que select(), poll() ou un équivalent) pour déterminer quand des données sont disponibles, puis à appeler read() pour lire les données. L'équivalent avec les BIOs (c'est-à-dire appeler select() sur la structure d'E/S sous-jacente, puis appeler BIO_read() pour lire les données) ne doit pas être utilisé car un seul appel à BIO_read() peut entraîner plusieurs lectures (et écritures dans le cas des BIOs SSL) sur la structure d'E/S sous-jacente et peut bloquer en conséquence. À la place, select() (ou équivalent) devrait être combiné avec des E/S non bloquantes afin que les lectures successives demandent une nouvelle tentative au lieu de bloquer.

Voir BIO_should_retry(3) pour plus de détails sur la manière de déterminer la cause d'une nouvelle tentative et d'autres problèmes d'E/S.

Si la méthode « gets » n'est pas prise en charge par un BIO, BIO_get_line() peut être utilisé. Il est également possible de rendre BIO_gets() utilisable même si la méthode « gets » n'est pas prise en charge en ajoutant un BIO de mise en tampon BIO_f_buffer(3) à la chaîne.

VOIR AUSSI

BIO_should_retry(3)

HISTORIQUE

BIO_gets() sur 1.1.0 et les versions antérieures, lorsqu'il était appelé sur un BIO basé sur BIO_fd(), ne conservait pas le '\n' à la fin de la ligne dans le tampon.

BIO_get_line() a été ajouté dans OpenSSL 3.0.

BIO_write_ex() renvoie 1 si la taille des données à écrire est de 0 et que le paramètre written de la fonction peut être NULL depuis OpenSSL 3.0.
