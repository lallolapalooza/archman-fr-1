NOM

boltd - démon système de gestion des périphériques Thunderbolt

SYNTAXE

boltd [OPTIONS]

DESCRIPTION

boltd est le démon gestionnaire des périphériques Thunderbolt. Son objectif est de permettre l'utilisation sécurisée et pratique des périphériques Thunderbolt en utilisant les fonctionnalités de sécurité des contrôleurs Thunderbolt modernes. Il expose le nom org.freedesktop.bolt sur le bus système. boltd est démarré automatiquement via systemd/udev si un périphérique Thunderbolt est connecté.

La technologie d'E/S Thunderbolt fonctionne en pontant le PCIe entre les contrôleurs de chaque extrémité de la connexion, ce qui signifie que les périphériques connectés via Thunderbolt sont ultimement connectés via PCIe. Par conséquent, Thunderbolt peut atteindre des vitesses de connexion très élevées, suffisamment rapides pour même piloter des cartes graphiques externes. L'inconvénient est que cela rend également possibles certaines attaques. Pour atténuer ces problèmes de sécurité, la dernière version — connue sous le nom de Thunderbolt 3 — prend en charge différents niveaux de sécurité :

none

Aucune sécurité. Le comportement est identique aux versions précédentes de Thunderbolt.

dponly

Aucun tunnel PCIe n'est créé, mais les tunnels DisplayPort sont autorisés et fonctionneront.

user

Les périphériques connectés doivent être autorisés par l'utilisateur. Ce n'est qu'alors que les tunnels PCIe seront activés.

secure

Essentiellement la même chose que le mode utilisateur, mais en plus, une clé sera écrite sur le périphérique lors de la première connexion du périphérique. Cette clé sera ensuite utilisée pour vérifier l'identité du périphérique connecté.

usbonly

Un tunnel PCIe est créé vers un contrôleur USB dans une station d'accueil Thunderbolt ; aucun autre tunnel PCIe descendant n'est autorisé (nécessite un noyau 4.17 et du matériel récent).

La tâche principale de boltd est d'autoriser les périphériques Thunderbolt si le niveau de sécurité est soit utilisateur, soit sécurisé. Il fournit une API D-Bus pour lister les périphériques, les enregistrer (autoriser et stocker dans la base de données locale) et les oublier à nouveau (supprimer les périphériques précédemment enregistrés). Il émet également des signaux lorsque de nouveaux périphériques sont connectés (ou retirés). Lors de l'enregistrement, les périphériques peuvent être configurés pour être automatiquement autorisés dès qu'ils sont connectés. Un outil en ligne de commande, appelé boltctl(1), peut être utilisé pour contrôler le démon et effectuer toutes les tâches mentionnées ci-dessus.

La fonctionnalité de liste de contrôle d'accès avant le démarrage (BootACL) est active lorsqu'elle est prise en charge par le firmware et lorsque boltd s'exécute sur un noyau Linux suffisamment récent (>= 4.17). Le BootACL est une liste d'UUID, qui peut être écrite sur le contrôleur Thunderbolt. Si activé dans le BIOS, tous les périphériques de cette liste seront autorisés par le firmware pendant le pré-démarrage, ce qui signifie que ces périphériques peuvent être utilisés dans la configuration du BIOS ainsi que pendant le démarrage précoce de Linux. NB : aucune vérification de périphérique n'est effectuée, même lorsque le niveau de sécurité est défini sur le mode secure dans le BIOS, c'est-à-dire que le niveau de sécurité effectif maximal pour les périphériques dans le BootACL n'est que user. Si la prise en charge de BootACL est présente, tous les nouveaux périphériques seront automatiquement ajoutés. Les périphériques qui sont oubliés (supprimés de boltd) seront également supprimés du BootACL. Lorsqu'un contrôleur est hors ligne, les modifications apportées au BootACL seront écrites dans un journal et synchronisées lorsque le contrôleur sera de nouveau en ligne.

Prise en charge IOMMU : si le matériel et le firmware prennent en charge l'utilisation de l'unité de gestion de mémoire d'entrée/sortie (IOMMU) pour restreindre l'accès direct à la mémoire à certaines régions sûres, boltd détectera cette fonctionnalité et modifiera son comportement : tant que la prise en charge de l'IOMMU est active, comme indiqué par l'attribut sysfs iommu_dma_protection du contrôleur de domaine, les nouveaux périphériques seront automatiquement enregistrés avec la politique iommu et les périphériques existants avec la politique iommu (ou auto) seront automatiquement autorisés par boltd sans aucune interaction de l'utilisateur. Lorsque l'IOMMU n'est pas actif, les périphériques qui ont été enregistrés avec la politique iommu ne seront pas autorisés automatiquement. L'état de la prise en charge de l'IOMMU peut être inspecté en utilisant boltctl domains.

OPTIONS

-h, --help

Affiche un bref texte d'aide et quitte.

--version

Affiche le numéro de version et quitte.

-r, --replace

Remplace l'instance boltd actuellement en cours d'exécution.

--journal

Force la journalisation dans le journal.

-v, --verbose

Affiche la sortie de débogage.

ENVIRONNEMENT

RUNTIME_DIRECTORY

Spécifie le chemin où le démon stocke les données qui ne doivent exister que pendant la durée du démarrage actuel. Sera défini automatiquement lorsqu'il est démarré via systemd (>= 240). S'il n'est pas défini, le chemin par défaut pour les données d'exécution est /run/boltd.

STATE_DIRECTORY

Spécifie le chemin où le démon stocke les informations sur les périphériques, y compris les clés utilisées pour l'autorisation. Remplace le chemin défini lors de la compilation. Sera défini automatiquement lorsqu'il est démarré via systemd (>= 240).

BOLT_DBPATH

Identique à STATE_DIRECTORY mais a la priorité sur celui-ci, s'il est défini.

STATUT DE SORTIE

En cas de succès, 0 est retourné, un code d'échec non nul sinon.
