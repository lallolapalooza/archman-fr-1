DESCRIPTIO

N

Ce document décrit le contrôle d'accès sur le contenu des en-têtes de message et des lignes du corps du message ; il est mis en œuvre par le serveur Postfix cleanup(8) avant que le courrier ne soit mis en file d'attente. Voir access(5) pour le contrôle d'accès sur les informations du client SMTP

distant.

Chaque en-tête de message ou ligne du corps du message est comparé à une liste de motifs. Lorsqu'une correspondance est trouvée, l'action correspondante est exécutée, et le processus de correspondance est répété pour l'en-tête de message suivant ou la ligne du corps du message

suivante.

Remarque : les en-têtes de message sont examinés un en-tête logique à la fois, même lorsqu'un en-tête de message s'étend sur plusieurs lignes. Les lignes du corps sont toujours examinées une ligne à la

fois.

Pour des exemples, voir la section EXEMPLES à la fin de cette page de

manuel.

Les header_checks ou body_checks de Postfix sont conçus pour arrêter une inondation de courrier provenant de vers o

u de virus ; ils ne décodent pas les pièces jointes, et ils ne décompressent pas les archives. Voir les documents ré
férencés ci-dessous dans la section FICHIERS README si vous avez besoin d'une analyse de contenu plus sophistiquée.

ORDRE DE RECHERCHE DANS LA

TABLE

Pour chaque ligne d'entrée du message, les motifs sont appliqués dans l'ordre spéci

fié dans la table. Lorsqu'un motif correspondant à la ligne d'entrée est trouvé, l
'action correspondante est exécutée, puis la ligne d'entrée suivante est inspectée.

TEXTE

La substitution de sous-chaînes de l'expression correspondante dans la chaîne d'action est possible en utilisant la syntaxe Perl conventionnelle ($1, $2, etc.). Les macros dans la chaîne de résultat peuvent nécessiter d'être écrites comme ${n} ou $(n) si elles ne sont pas suivies d' espaces

blancs.

Remarque : puisque les motifs négés (ceux précédés de !) renvoient un résultat lorsque l'expression ne correspond pas,

les substitutions ne sont pas disp

ACTION

S

Les noms d'actions ne sont pas sensibles à la casse. Ils sont affichés en majuscules pour la cohérence avec la autre documentation

Postfix.
BCC user@domain
Ajoute l'adresse spécifiée en tant que destinataire BCC, et inspecte la ligne d'entrée suivante. L'adresse doit avoir une partie locale et une partie domaine. Le nombre d'adresses BCC qui peuvent être ajoutées est limité uniquement par la quantité d'espace de stockage disponible.

Note 1 : l'adresse BCC est ajoutée comme si elle avait été spécifiée avec NOTIFY=NONE. L'expéditeur ne sera pas notifié si l'adresse BCC est non livrable, tant que tous les logiciels en aval implémentent la RFC 3461.

Note 2 : ignore les adresses dupliquées (avec les mêmes options de notification de livraison).

Cette fonctionnalité est disponible dans Postfix 3.0 et versions ultérieures.

Cette fonctionnalité n'est pas prise en charge avec les vérifications d'en-tête/corps smtp.

DISCARD texte optionnel...
Déclare une livraison réussie et ignore silencieusement le message. N'inspecte pas le reste du message d'entrée. Journalise le texte optionnel s'il est spécifié, sinon journalise un message générique.

Note : cette action désactive l'inspection ultérieure des en-têtes ou du corps du message actuel et affecte tous les destinataires. Pour ignorer un seul destinataire sans ignorer tout le message, utilisez la table transport(5) pour diriger le courrier vers le service discard(8).

Cette fonctionnalité est disponible dans Postfix 2.0 et versions ultérieures.

Cette fonctionnalité n'est pas prise en charge avec les vérifications d'en-tête/corps smtp.

DUNNO
Fait semblant que la ligne d'entrée ne correspondait à aucun motif, et inspecte la ligne d'entrée suivante. Cette action peut être utilisée pour raccourcir la recherche dans la table.

Pour des raisons de compatibilité ascendante, Postfix accepte également OK, mais il est (et a toujours été) traité comme DUNNO.

Cette fonctionnalité est disponible dans Postfix 2.1 et versions ultérieures.

FILTER transport:destination
Remplace le paramètre content_filter, et inspecte la ligne d'entrée suivante. Après la mise en file d'attente du message, envoie le message entier via le filtre de contenu externe spécifié. Le nom de transport spécifie le premier champ d'une définition d'agent de livraison de courrier dans master.cf ; la syntaxe de la destination de prochain saut est décrite dans la page de manuel de l'agent de livraison correspondant. Plus d'informations sur les filtres de contenu externes sont disponibles dans le fichier Postfix FILTER_README.

Note 1 : n'utilisez pas les substitutions d'expression régulière $nombre pour transport ou destination, sauf si vous savez que les informations ont une origine fiable.

Note 2 : cette action remplace le réglage content_filter de main.cf, et affecte tous les destinataires du message. Si plusieurs actions FILTER sont déclenchées, seule la dernière est exécutée.

Note 3 : le but de la commande FILTER est de remplacer le routage des messages. Pour remplacer le transport du destinataire mais pas la destination de prochain saut, spécifiez une destination de filtre vide (Postfix 2.7 et versions ultérieures), ou spécifiez un transport:destination qui livre via une instance Postfix différente (Postfix 2.6 et versions antérieures). D'autres options sont l'utilisation des transport_maps dépendants du destinataire ou des fonctionnalités sender_dependent_default_transport_maps dépendant de l'expéditeur.

Cette fonctionnalité est disponible dans Postfix 2.0 et versions ultérieures.

Cette fonctionnalité n'est pas prise en charge avec les vérifications d'en-tête/corps smtp.

HOLD texte optionnel...
Arrange pour que le message soit placé dans la file d'attente hold, et inspecte la ligne d'entrée suivante. Le message reste en hold jusqu'à ce que quelqu'un le supprime ou le libère pour livraison. Journalise le texte optionnel s'il est spécifié, sinon journalise un message générique.

Les courriers placés en attente peuvent être examinés avec la commande postcat(1), et peuvent être détruits ou libérés avec la commande postsuper(1).

Note : utilisez "postsuper -r" pour libérer le courrier qui a été gardé en attente pendant une fraction significative de $maximal_queue_lifetime ou $bounce_queue_lifetime, ou plus longtemps. Utilisez "postsuper -H" uniquement pour le courrier qui n'expirera pas dans les quelques tentatives de livraison.

Note : cette action affecte tous les destinataires du message.

Cette fonctionnalité est disponible dans Postfix 2.0 et versions ultérieures.

Cette fonctionnalité n'est pas prise en charge avec les vérifications d'en-tête/corps smtp.

IGNORE
Supprime la ligne courante de l'entrée, et inspecte la ligne d'entrée suivante. Voir STRIP pour une alternative qui journalise l'action.
INFO texte optionnel...
Journalise un enregistrement "info :" avec le texte optionnel... (ou journalise un texte générique), et inspecte la ligne d'entrée suivante. Cette action est utile pour la journalisation de routine ou pour le débogage.

Cette fonctionnalité est disponible dans Postfix 2.8 et versions ultérieures.

PASS texte optionnel...
Journalise un enregistrement "pass :" avec le texte optionnel... (ou journalise un texte générique), et désactive l'inspection des en-têtes, du corps et des Milter pour le reste de ce message.

Note : cette fonctionnalité repose sur la confiance dans des informations faciles à falsifier.

Cette fonctionnalité est disponible dans Postfix 3.2 et versions ultérieures.

Cette fonctionnalité n'est pas prise en charge avec les vérifications d'en-tête/corps smtp.

PREPEND texte...
Prépare une ligne avec le texte spécifié, et inspecte la ligne d'entrée suivante.

Notes :

  • Le texte ajouté est affiché sur une ligne séparée, immédiatement avant l'entrée qui a déclenché l'action PREPEND.
  • Le texte ajouté n'est pas considéré comme faisant partie du flux d'entrée : il n'est pas soumis aux vérifications d'en-tête/corps ni aux réécritures d'adresses, et il n'affecte pas la façon dont Postfix ajoute les en-têtes de message manquants.
  • Lorsqu'on ajoute du texte avant une ligne d'en-tête de message, le texte ajouté doit commencer par une étiquette d'en-tête valide.
  • Cette action ne peut pas être utilisée pour ajouter du texte sur plusieurs lignes.
Cette fonctionnalité est disponible dans Postfix 2.1 et versions ultérieures.

Cette fonctionnalité n'est pas prise en charge avec les vérifications d'en-tête milter.

REDIRECT user@domain
Écrit une demande de redirection de message dans le fichier de file d'attente, et inspecte la ligne d'entrée suivante. Après la mise en file d'attente du message, il sera envoyé à l'adresse spécifiée au lieu du(des) destinataire(s) prévu(s).

Note 1 : cette action remplace l'action FILTER, et affecte tous les destinataires du message. Si plusieurs actions REDIRECT sont déclenchées, seule la dernière est exécutée.

Note 2 : une adresse REDIRECT est soumise à la canonicalisation (ajout du domaine manquant) mais N'EST PAS soumise aux mappages canoniques, masquerades, bcc ou alias virtuels.

Cette fonctionnalité est disponible dans Postfix 2.1 et versions ultérieures.

Cette fonctionnalité n'est pas prise en charge avec les vérifications d'en-tête/corps smtp.

REPLACE texte...
Remplace la ligne courante par le texte spécifié, et inspecte la ligne d'entrée suivante.

Cette fonctionnalité est disponible dans Postfix 2.2 et versions ultérieures. La description ci-dessous s'applique à Postfix 2.2.2 et versions ultérieures.

Notes :

  • Lors du remplacement d'une ligne d'en-tête de message, le texte de remplacement doit commencer par une étiquette d'en-tête valide.
  • Le texte remplacé reste faisant partie du flux d'entrée. Contrairement au résultat de l'action PREPEND, un en-tête de message remplacé peut être soumis à la réécriture d'adresses et peut affecter la façon dont Postfix ajoute les en-têtes de message manquants.
REJECT texte optionnel...
Rejette l'intégralité du message. N'inspecte pas le reste du message d'entrée. Répond avec texte optionnel... lorsque le texte optionnel est spécifié, sinon répond avec un message d'erreur générique.

Note : cette action désactive l'inspection ultérieure des en-têtes ou du corps du message actuel et affecte tous les destinataires.

Postfix version 2.3 et ultérieures prend en charge les codes de statut améliorés. Lorsqu'aucun code n'est spécifié au début de texte optionnel..., Postfix insère un code de statut amélioré par défaut de "5.7.1".

Cette fonctionnalité n'est pas prise en charge avec les vérifications d'en-tête/corps smtp.

STRIP texte optionnel...
Journalise un enregistrement "strip :" avec le texte optionnel... (ou journalise un texte générique), supprime la ligne d'entrée de l'entrée, et inspecte la ligne d'entrée suivante. Voir IGNORE pour une alternative silencieuse.

Cette fonctionnalité est disponible dans Postfix 3.2 et versions ultérieures.

WARN texte optionnel...
Journalise un enregistrement "warning :" avec le texte optionnel... (ou journalise un texte générique), et inspecte la ligne d'entrée suivante. Cette action est utile pour le débogage et pour tester un motif avant d'appliquer des actions plus drastiques.

BOGUES


Les lignes vides ne correspondent jamais, car certains types de cartes se comportent mal lorsqu'on leur donne une chaîne de recherche de longueur nulle. Cette limitation pourra être supprimée pour les tables d'expressions régulières dans une future version.

Beaucoup de gens négligent les limitations principales des règles de header_checks et body_checks.

  • Ces règles opèrent sur un en-tête de message logique ou une ligne de corps à la fois. Une décision prise pour une ligne n'est pas reportée à la ligne suivante.
  • Si le texte du corps du message est codé (RFC 2045), alors les règles doivent être spécifiées pour la forme codée.
  • De même, lorsque les en-têtes de message sont codés (RFC 2047), alors les règles doivent être spécifiées pour la forme codée.

Les en-têtes de message ajoutés par le démon cleanup(8) lui-même sont exclus de l'inspection. Exemples de tels en-têtes : From:, To:, Message-ID:, Date:.

Les en-têtes de message supprimés par le démon cleanup(8) seront examinés avant d'être supprimés. Exemples : Bcc:, Content-Length:, Return-Path:.
