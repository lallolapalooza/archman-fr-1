DESCRIPTIO

N

Le démon bounce(8) maintient des fichiers journaux par message contenant des informations d'état de livraison. Chaque fichier journal est nommé d'après le fichier de file d'attente auquel il correspond, et est conservé dans un sous-répertoire de la file d'attente nommé d'après le nom du service dans le fichier master.cf (soit bounce, defer ou trace). Ce programme s'attend à être exécuté par le gestionnaire de processus master(

8).

Le démon bounce(8) traite deux types de requêtes de service

:
  • Ajouter un enregistrement d'état de (non-)livraison d'un destinataire à un fichier journal par
    • message.
  • Mettre en file d'attente un message de notification d'état de livraison, avec une copie d'un
    • fichier journal par message et du message correspondant. Lorsque le message de notification d'éta
t de livraison est mis en file d'attente avec succès, le fichier journal par message est supprimé.

Le logiciel fait de son mieux pour envoyer les notifications. Une notification de non-livraison est envoyée même si le fichier journal ou le message original ne peuvent pas être

lus.

De manière facultative, un client bounce (defer, trace) peut demander que le fichier journal par message soi

t supprimé lorsque l'opération demandée échoue. Ceci est utilisé par des clients qui ne peuvent pas réessaye
r les transactions par eux-mêmes et qui dépendent de la logique de nouvelle tentative de leur propre client.
