DESCRIPTIO

N

BIO_s_accept() renvoie la méthode BIO d'acceptation. Il s'agit d'un enveloppement des routines d'acceptation de sockets TCP/IP de la

plateforme.

À l'aide des BIO d'acceptation, les connexions TCP/IP peuvent être acceptées et les données transférées en utilisant uniquement les routines BIO. De cette manière, les opérations spécifiques à la plateforme sont masquées par l'abstraction

BIO.

Les opérations de lecture et d'écriture sur un BIO d'acceptation effectueront des E/S sur la connexion sous-jacente. Si aucune connexion n'est établie et que le port (voir ci-dessous) est configuré correctement, le BIO attend une connexion

entrante.

Les BIO d'acceptation prennent en charge BIO_puts() mais pas BIO_get

s().

Si l'indicateur de fermeture est défini sur un BIO d'acceptation, toute connexion active sur cette chaîne est arrêtée et la socket fermée lorsque le BIO est

libéré.

Appeler BIO_reset() sur un BIO d'acceptation fermera toute connexion active et réinitialisera le BIO dans un état où il attend une autre connexion

entrante.

BIO_get_fd() et BIO_set_fd() peuvent être appelés pour récupérer ou définir la socket d'acceptation. Voir BIO_s_fd(3

)

BIO_set_accept_name() utilise la chaîne name pour définir le nom d'acceptation. Le nom est représenté sous la forme d'une chaîne "host:port", où "host" est l'interface à utiliser et "port" est le port. L'hôte peut être "*" ou vide, ce qui est interprété comme signifiant n'importe quelle interface. Si l'hôte est une adresse IPv6, elle doit être entourée de crochets, par exemple "[::1]:https". "port" a la même syntaxe que le port spécifié dans BIO_set_conn_port() pour les BIO de connexion, c'est-à-dire qu'il peut s'agir d'une chaîne de port numérique ou d'une chaîne à rechercher à l'aide de getservbyname() et d'une table de

chaînes.

BIO_set_accept_port() utilise la chaîne port pour définir le port d'acceptation du BIO b. "port" a la même syntaxe que le port spécifié dans BIO_set_conn_port() pour les BIO de connexion, c'est-à-dire qu'il peut s'agir d'une chaîne de port numérique ou d'une chaîne à rechercher à l'aide de getservbyname() et d'une table de chaînes. Si le port donné est 0, un port disponible aléatoire est choisi. Il peut être interrogé à l'aide de BIO_sock_info() et BIO_ADDR_service_s

tring(3).

BIO_new_accept() combine BIO_new() et BIO_set_accept_name() en un seul appel : il crée un nouveau BIO d'acceptation avec le port host_port

.

BIO_set_nbio_accept() définit la socket d'acceptation en mode bloquant (par défaut) si n vaut 0, ou en mode non bloquant si n vaut

1.

BIO_set_tfo_accept() active TCP Fast Open sur la socket d'acceptation si n vaut 1, ou désactive TCP Fast Open si n vaut 0 (par défaut). Définir la valeur à 1 revient à définir BIO_SOCK_TFO dans BIO_set_bind_

mode().

BIO_set_accept_bios() peut être utilisé pour définir une chaîne de BIO qui sera dupliquée et ajoutée en tête de la chaîne lorsqu'une connexion entrante est reçue. C'est utile si, par exemple, un BIO de mise en tampon ou un BIO SSL est requis pour chaque connexion. La chaîne de BIO ne doit pas être libérée après cet appel, elle sera automatiquement libérée lorsque le BIO d'acceptation sera

libéré.

BIO_get_accept_ip_family() renvoie la famille IP acceptée par le BIO b, qui peut être BIO_FAMILY_IPV4, BIO_FAMILY_IPV6, ou BIO_FAMILY_IPANY

.

BIO_set_accept_ip_family() définit la famille IP family acceptée par le BIO b. La valeur par défaut est BIO_FAMILY_IPANY

.

BIO_set_bind_mode() et BIO_get_bind_mode() définissent et récupèrent le mode de liaison courant. Si BIO_BIND_NORMAL (par défaut) est défini, une autre socket ne peut pas être liée au même port. Si BIO_BIND_REUSEADDR est défini, d'autres sockets peuvent être liées au même port. Si BIO_BIND_REUSEADDR_IF_UNUSED est défini, une tentative est d'abord faite d'utiliser BIO_BIN_NORMAL ; si cela échoue et que le port n'est pas utilisé, une seconde tentative est faite en utilisant BIO_BIND_REUSEADDR. Si BIO_SOCK_TFO est défini, la socket sera configurée pour accepter les connexions TCP Fast

Open.

BIO_do_accept() remplit deux fonctions. Lorsqu'il est appelé pour la première fois, après que le BIO d'acceptation a été configuré, il tentera de créer la socket d'acceptation et d'y lier une adresse. Deuxièmement, les appels suivants à BIO_do_accept() attendront une connexion entrante, ou dem

anderont une nouvelle ten
tative en mode non bloquant.

NOTE

S

Lorsqu'un BIO d'acceptation est à la fin d'une chaîne, il attendra une connexion entrante avant de traiter les appels d'E/S. Lorsqu'un BIO d'acceptation n'est pas à la fin d'une chaîne, il transmet les appels d'E/S au BIO suivant dans la

chaîne.

Lorsqu'une connexion est établie, une nouvelle BIO de socket est créée pour la connexion et ajoutée à la fin de la chaîne. C'est-à-dire que la chaîne est maintenant accept->socket. Cela signifie effectivement que la tentative d'E/S sur une socket d'acceptation initiale attendra une connexion entrante puis effectuera des E/S sur

celle-ci.

Si des BIO supplémentaires ont été définis à l'aide de BIO_set_accept_bios(), ils sont placés entre la socket et le BIO d'acceptation, c'est-à-dire que la chaîne sera accept->otherbios->

socket.

Si un serveur souhaite traiter plusieurs connexions (ce qui est normalement le cas), le BIO d'acceptation doit être rendu disponible pour d'autres connexions entrantes. Cela peut être fait en attendant une connexion puis en appelant

: 
connection = BIO_pop(accept)
;

Après cet appel, connection contiendra un BIO pour la connexion récemment établie et accept sera à nouveau un BIO unique qui peut être utilisé pour attendre d'autres connexions entrantes. Si aucune autre connexion ne sera acceptée, accept peut être libéré à l'aide de BIO_fre

e().

Si une seule connexion sera traitée, il est possible d'effectuer des E/S en utilisant le BIO d'acceptation lui-même. C'est souvent indésirable cependant car le BIO d'acceptation acceptera toujours des connexions entrantes supplémentaires. Cela peut être résolu en utilisant BIO_pop() (voir ci-dessus) et en libérant le BIO d'acceptation après la connexion

initiale.

Si la socket d'acceptation sous-jacente est non bloquante et que BIO_do_accept() est appelé pour attendre une connexion entrante, il est possible que BIO_should_io_special() avec la raison BIO_RR_ACCEPT. Si cela se produit, c'est l'indication qu'une tentative d'acceptation bloquerait : l'application devrait prendre les mesures appropriées pour attendre que la socket sous-jacente ait accepté une connexion et réessayer

l'appel.

EXEMPLE

S

Cet exemple accepte deux connexions sur le port 4444, envoie des messages sur chacune et finit par les fermer toutes les

deux. 
BIO *abio, *cbio, *cbio2;
/* Le premier appel à BIO_do_accept() configure le BIO d'acceptation */
abio = BIO_new_accept("4444");
if (BIO_do_accept(abio) <= 0) {
    fprintf(stderr, "Error setting up accept\n");
    ERR_print_errors_fp(stderr);
    exit(1);
}
/* Attendre une connexion entrante */
if (BIO_do_accept(abio) <= 0) {
    fprintf(stderr, "Error accepting connection\n");
    ERR_print_errors_fp(stderr);
exit(1); } fprintf(stderr, "Connection 1 established\n"); /* Récupérer le BIO pour la connexion */ cbio = BIO_pop(abio); BIO_puts(cbio, "Connection 1: Sending out Data on initial connection\n"); fprintf(stderr, "Sent out data on connection 1\n"); /* Attendre une autre connexion */ if (BIO_do_accept(abio) <= 0) { fprintf(stderr, "Error accepting connection\n"); ERR_print_errors_fp(stderr); exit(1);
} fprintf(stderr, "Connection 2 established\n"); /* Fermer le BIO d'acceptation pour refuser les connexions suivantes */ cbio2 = BIO_pop(abio); BIO_free(abio); BIO_puts(cbio2, "Connection 2: Sending out Data on second\n"); fprintf(stderr, "Sent out data on connection 2\n"); BIO_puts(cbio, "Connection 1: Second connection established\n"); /* Fermer les deux connexions établies */ BIO_free(cbio); BIO_free(cbio2);
