busy(n)

Paquet: tk

Licences: TCL

busy(n) Commandes intégrées Tk busy(n)

NOM

busy - Rend les widgets Tk occupés, bloquant temporairement les interactions utilisateur

SYNTAXE

tk busy fenêtre ?options?
tk busy hold fenêtre ?options?
tk busy configure fenêtre ?option valeur?...
tk busy forget fenêtre ?fenêtre ?...
tk busy current ?modèle?
tk busy status fenêtre

DESCRIPTION

La commande tk busy fournit un moyen simple de bloquer les événements du pointeur de la souris des widgets Tk, tout en remplaçant le curseur du widget par un curseur occupé configurable. Notez que cette commande n'empêche pas l'envoi d'événements clavier aux widgets rendus occupés.

INTRODUCTION

Il existe de nombreuses situations dans les applications où vous souhaitez restreindre temporairement les actions que l'utilisateur peut effectuer. Par exemple, une application pourrait avoir un bouton « Exécuter » qui, lorsqu'il est pressé, déclenche un traitement. Cependant, pendant que l'application est occupée à traiter, vous ne voudrez probablement pas que l'utilisateur puisse cliquer à nouveau sur le bouton « Exécuter ». Vous pourriez également vouloir restreindre l'utilisateur d'autres tâches telles que cliquer sur un bouton « Imprimer ».

La commande tk busy vous permet de rendre les widgets Tk occupés. Cela signifie que les interactions utilisateur telles que les clics de souris, le déplacement de la souris, la frappe au clavier, etc., sont ignorées par le widget. Vous pouvez définir un curseur spécial (comme une montre) qui remplace le curseur normal du widget, indiquant que l'application (widget) est temporairement occupée.

Lorsqu'un widget est rendu occupé, ce widget et tous ses descendants ignoreront les événements du pointeur. Il est facile de rendre occupé un panneau entier de widgets. Vous pouvez simplement rendre le widget de niveau supérieur (comme « . ») occupé. C'est plus facile et beaucoup plus efficace que de parcourir récursivement la hiérarchie des widgets, de désactiver chaque widget et de reconfigurer son curseur.

Souvent, la commande tk busy peut être utilisée à la place de la commande grab de Tk. Contrairement à grab qui restreint toutes les interactions utilisateur à un seul widget, avec la commande tk busy, vous pouvez avoir plus d'un widget actif (par exemple, une boîte de dialogue « Annuler » et un bouton « Aide »).

EXEMPLE

Vous pouvez rendre plusieurs widgets occupés en rendant simplement leur widget ancêtre occupé à l'aide de l'opération hold.

frame .top
button .top.button; canvas .top.canvas
pack .top.button .top.canvas
pack .top
# . . .
tk busy hold .top
update

Tous les widgets dans .top (y compris .top) sont maintenant occupés. L'utilisation de update garantit que la commande tk busy prendra effet avant que tout autre événement utilisateur ne puisse se produire.

Lorsque l'application n'est plus occupée à traiter, vous pouvez permettre à nouveau les interactions utilisateur et libérer toutes les ressources qu'elle a allouées à l'aide de l'opération forget.

tk busy forget .top

Le widget occupé a un curseur configurable. Vous pouvez modifier le curseur occupé à l'aide de l'opération configure.

tk busy configure .top -cursor "watch"

La destruction du widget nettoiera également toutes les ressources allouées par la commande tk busy.

OPÉRATIONS

Les opérations suivantes sont disponibles pour la commande tk busy :

tk busy fenêtre ?option valeur?...
Raccourci pour la commande tk busy hold.
tk busy cget fenêtre option
Interroge les options de configuration de la commande tk busy pour fenêtre. Fenêtre doit être le nom d'un widget précédemment rendu occupé par l'opération hold. La commande renvoie la valeur actuelle de l'option spécifiée. Option peut avoir l'une des valeurs acceptées par l'opération hold.
tk busy configure fenêtre ?option valeur?...
Interroge ou modifie les options de configuration de la commande tk busy pour fenêtre. Fenêtre doit être le nom d'un widget précédemment rendu occupé par l'opération hold. Si aucune option n'est spécifiée, une liste décrivant toutes les options disponibles pour fenêtre (voir Tk_ConfigureInfo pour des informations sur le format de cette liste) est renvoyée. Si option est spécifiée sans valeur, alors la commande renvoie une liste décrivant l'option nommée (cette liste sera identique à la sous-liste correspondante de la valeur renvoyée si aucune option n'est spécifiée). Si une ou plusieurs paires option-valeur sont spécifiées, alors la commande modifie l' (les) option(s) du widget donnée (s) pour qu'elles aient la (les) valeur(s) donnée(s) ; dans ce cas, la commande renvoie la chaîne vide. Option peut avoir l'une des valeurs acceptées par l'opération hold.

Veuillez noter que la base de données d'options est référencée via fenêtre. Par exemple, si le widget .frame doit être rendu occupé, le curseur occupé peut être spécifié pour celui-ci soit par la commande option :

option add *frame.busyCursor gumby
option add *Frame.BusyCursor gumby
tk busy current ?modèle?
Renvoie les noms de chemin de tous les widgets qui sont actuellement occupés. Si un modèle est donné, seuls les noms de chemin des widgets occupés correspondant au modèle sont renvoyés.
tk busy forget fenêtre ?fenêtre?...
Libère les ressources allouées par la commande tk busy pour fenêtre, y compris la fenêtre transparente. Les événements utilisateur seront à nouveau reçus par fenêtre. Les ressources sont également libérées lorsque fenêtre est détruit. Fenêtre doit être le nom d'un widget spécifié dans l'opération hold, sinon une erreur est signalée.
tk busy hold fenêtre ?option valeur?...
Fait apparaître comme occupé le fenêtre spécifié (et ses descendants dans la hiérarchie des fenêtres Tk). Fenêtre doit être un nom de chemin valide d'un widget Tk. Une fenêtre transparente est placée devant le widget spécifié. Cette fenêtre transparente est mappée la prochaine fois que les tâches inactives sont traitées, et le widget spécifié ainsi que ses descendants seront bloqués des interactions utilisateur. Normalement, update doit être appelé immédiatement après pour garantir que l'opération de maintien est en vigueur avant que l'application ne commence son traitement. Les options de configuration suivantes sont valides :
-cursor nomCurseur
Spécifie le curseur à afficher lorsque le widget est rendu occupé. NomCurseur peut être sous une forme acceptée par Tk_GetCursor. Le curseur par défaut est wait sous Windows et watch sur les autres plateformes.
tk busy status fenêtre
Renvoie le statut d'un widget fenêtre. Si fenêtre ne peut actuellement pas recevoir d'interactions utilisateur, 1 est renvoyé, sinon 0.

GESTION DES ÉVÉNEMENTS

LIAISONS

La fonctionnalité de blocage d'événements est implémentée en créant et en mappant une fenêtre transparente qui couvre complètement le widget. Lorsque la fenêtre occupée est mappée, elle protège invisiblement le widget et sa hiérarchie de tous les événements qui peuvent être envoyés. Comme les widgets Tk, les fenêtres occupées ont des noms de widget dans la hiérarchie des fenêtres Tk. Cela signifie que vous pouvez utiliser la commande bind pour gérer les événements dans la fenêtre occupée :

tk busy hold .frame.canvas
bind .frame.canvas_Busy <Enter> { ... }

Normalement, la fenêtre occupée est un frère du widget. Le nom de la fenêtre occupée est « widget_Busy » où widget est le nom du widget à rendre occupé. Dans l'exemple précédent, le nom de chemin de la fenêtre occupée est « .frame.canvas_Busy ». L'exception est lorsque le widget est un widget de niveau supérieur (comme « . ») où la fenêtre occupée ne peut pas être faite sœur.

La fenêtre occupée est alors un enfant du widget nommé « widget._Busy » où widget est le nom du widget de plus haut niveau. Dans l'exemple suivant, le chemin d'accès de la fenêtre occupée est « ._Busy ».

tk busy hold .
bind ._Busy <Enter> { ... }

événements ENTRER/SORTIR

Le mappage et le démappage des fenêtres occupées génèrent des événements Entrer/Sortir pour tous les widgets qu'ils couvrent. Veuillez en tenir compte si vous suivez les événements Entrer/Sortir dans des widgets.

événements CLAVIER

Lorsqu'un widget est marqué comme occupé, le widget ne peut pas obtenir le focus du clavier en cliquant dessus par l'utilisateur via la fenêtre occupée. Mais si le widget avait déjà le focus, il peut toujours recevoir des événements clavier. Le widget peut également toujours recevoir le focus par le biais de la navigation clavier. Pour éviter cela, vous devez déplacer le focus vers une autre fenêtre et vous assurer que le focus ne peut pas revenir aux widgets marqués comme occupés (par exemple, en restreignant le focus à un bouton d'annulation).

pack [frame .frame]
pack [text .frame.text]
tk busy hold .frame
pack [button .cancel -text "Annuler" -command exit]
focus .cancel
bind .cancel <Tab> {break}
bind .cancel <Shift-Tab> {break}
update

L'exemple ci-dessus déplace le focus de .frame immédiatement après avoir appelé la commande hold afin qu'aucun événement clavier ne soit envoyé à .frame ou à l'un de ses descendants. Il s'assure également qu'il n'est pas possible de quitter le bouton .cancel à l'aide du clavier.

PORTABILITÉ

Notez que la commande tk busy n'a actuellement aucun effet sur macOS lorsque Tk est compilé avec le support Aqua.
