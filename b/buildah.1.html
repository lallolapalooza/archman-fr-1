DESCRIPTIO

N

Le paquet Buildah fournit un outil en ligne de commande qui peut être utilisé pour

: 
* Créer un conteneur de travail, soit à partir de zéro, soit en utilisant une image comme point de départ.
* Monter le système de fichiers racine d'un conteneur
de travail pour le manipuler. * Démonter le système de fichiers racine d'un conteneur de travail. * Utiliser le contenu mis à jour du système de fichiers racine d
'un conteneur comme couche de système de fichiers pour créer une nouvelle image. * Supprimer un conteneur de travail ou une image. * Renommer un conteneur local.

OPTION

S

--cgroup-manager=gestionnai

re

Le gestionnaire de CGroup à utiliser pour les cgroups des conteneurs. Les valeurs prises en charge sont cgroupfs ou systemd. La valeur par défaut est systemd, sauf si elle est remplacée dans le fichier containers.

conf.

Remarque : Le réglage de cet indicateur peut entraîner la défaillance de certaines commandes lorsqu'elles sont appelées sur des conteneurs précédemment créés par l'autre type de gestionnaire de CGroup. Remarque : Le gestionnaire de CGroup n'est pas pris en charge en mode sans root lors de l'utilisation des CGroups Version

V1.

--imagestore chemi

n

Chemin sous lequel le contenu des images tirées et construites sera stocké. Par défaut, l'emplacement configuré --root est utilisé pour les images tirées et construites ainsi que pour les conteneurs. Si le pilote de stockage est overlay, alors toute image qui a été écrite précédemment dans l'emplacement --root sera toujours

disponible.

Cela remplacera l'option imagestore dans containers-storage.conf(5)

.

--log-level nivea

u

Le niveau de journalisation à utiliser. Soit "trace", "debug", "info", "warn", "error", "fatal", ou "panic", par défaut

"warn".

--help,

-h

Afficher

l'aide

--registries-conf chemi

n

Nom de chemin du fichier de configuration qui spécifie les registres de conteneurs qui doivent être consultés lors de la complétion des noms d'images qui n'incluent pas de composant de registre ou de domaine. Il n'est pas recommandé d'utiliser cette option, car le comportement par défaut d'utilisation de la configuration système (/etc/containers/registries.conf) est le plus souvent

préféré.

--registries-conf-dir chemi

n

Nom de chemin du répertoire qui contient des extraits de configuration spécifiant les registres qui doivent être consultés lors de la complétion des noms d'images qui n'incluent pas de composant de registre ou de domaine. Il n'est pas recommandé d'utiliser cette option, car le comportement par défaut d'utilisation de la configuration système (/etc/containers/registries.d) est le plus souvent

préféré.

--root chemi

n

Répertoire racine de stockage (par défaut : "/var/lib/containers/storage" pour l'UID 0, "$HOME/.local/share/containers/storage" pour les autres utilisateurs). Le répertoire racine par défaut est configuré dans /etc/containers/storage.

conf.

--runroot chemi

n

Répertoire d'état de stockage (par défaut : "/run/containers/storage" pour l'UID 0, "/run/user/$UID" pour les autres utilisateurs). Le répertoire d'état par défaut est configuré dans /etc/containers/storage.

conf.

--short-name-alias-conf chemi

n

Nom de chemin du fichier qui contient les correspondances en cache entre les noms d'images courts et leurs noms complets correspondants. Il est utilisé pour la correspondance à partir de noms d'images spécifiés à l'aide de noms courts comme "ubi8" qui n'incluent pas de composant de registre et un nom entièrement spécifié correspondant qui inclut un registre et tout autre composant, tel que "registry.access.redhat.com/ubi8". Il n'est pas recommandé d'utiliser cette option, car le comportement par défaut d'utilisation du cache système (/var/cache/containers/short-name-aliases.conf) ou du cache par utilisateur ($HOME/.cache/containers/short-name-aliases.conf) pour compléter les valeurs par défaut système est le plus souvent

préféré.

--storage-driver valeu

r

Pilote de stockage. Le pilote de stockage par défaut pour l'UID 0 est configuré dans /etc/containers/storage.conf ($HOME/.config/containers/storage.conf en mode sans root), et est vfs pour les autres utilisateurs. La variable d'environnement STORAGE_DRIVER remplace la valeur par défaut. Le pilote spécifié par --storage-driver remplace

tout.

Exemples : "overlay",

"vfs"

Remplacer cette option entraînera l'ignorance des paramètres storage-opt dans /etc/containers/storage.conf. L'utilisateur doit spécifier des options supplémentaires via l'indicateur --storage-opt

.

--storage-opt valeu

r

Option du pilote de stockage, Les options du pilote de stockage par défaut sont configurées dans /etc/containers/storage.conf ($HOME/.config/containers/storage.conf en mode sans root). La variable d'environnement STORAGE_OPTS remplace la valeur par défaut. Les options spécifiées par --storage-opt remplacent

tout.

--transient-store valeur-booléenn

e

Stocker les métadonnées des conteneurs sous le répertoire d'état de stockage (--runroot), avec l'intention que les enregistrements les concernant soient supprimés lors du redémarrage du système. Une collecte de déchets supplémentaire doit toujours être effectuée au démarrage, donc cette option doit rester désactivée dans la plupart des configurations. (par défaut :

false)

--userns-gid-map correspondan

ce

Spécifie directement une correspondance de GID qui doit être utilisée pour définir la propriété, au niveau du système de fichiers, sur le contenu du conteneur de travail. Les commandes exécutées lors du traitement des instructions RUN s'exécuteront par défaut dans leurs propres espaces de noms d'utilisateurs, configurés à l'aide des correspondances UID et

GID.

Les entrées de cette correspondance prennent la forme d'un ou plusieurs triplets séparés par des deux-points composés d'un GID de départ dans le conteneur, d'un GID de départ correspondant au niveau de l'hôte, et du nombre d'identifiants consécutifs que l'entrée de correspondance

représente.

Cette option remplace le paramètre remap-gids dans la section options de /etc/containers/storage.

conf.

Si cette option n'est pas spécifiée, mais qu'un paramètre global --userns-gid-map est fourni, les paramètres de l'option globale seront

utilisés.

Si aucune des options --userns-uid-map-user, --userns-gid-map-group, ou --userns-gid-map n'est spécifiée, mais que --userns-uid-map est spécifiée, la correspondance GID sera configurée pour utiliser les mêmes valeurs numériques que la correspondance

UID.

REMARQUE : Lorsque cette option est spécifiée par un utilisateur sans root, les correspondances spécifiées sont relatives à l'espace de noms d'utilisateurs sans root dans le conteneur, plutôt qu'être relatives à l'hôte comme cela serait le cas lors de l'exécution avec

root.

--userns-uid-map correspondan

ce

Spécifie directement une correspondance de UID qui doit être utilisée pour définir la propriété, au niveau du système de fichiers, sur le contenu du conteneur de travail. Les commandes exécutées lors du traitement des instructions RUN s'exécuteront par défaut dans leurs propres espaces de noms d'utilisateurs, configurés à l'aide des correspondances UID et

GID.

Les entrées de cette correspondance prennent la forme d'un ou plusieurs triplets séparés par des deux-points composés d'un UID de départ dans le conteneur, d'un UID de départ correspondant au niveau de l'hôte, et du nombre d'identifiants consécutifs que l'entrée de correspondance

représente.

Cette option remplace le paramètre remap-uids dans la section options de /etc/containers/storage.

conf.

Si cette option n'est pas spécifiée, mais qu'un paramètre global --userns-uid-map est fourni, les paramètres de l'option globale seront

utilisés.

Si aucune des options --userns-uid-map-user, --userns-gid-map-group, ou --userns-uid-map n'est spécifiée, mais que --userns-gid-map est spécifiée, la correspondance UID sera configurée pour utiliser les mêmes valeurs numériques que la correspondance

GID.

REMARQUE : Lorsque cette option est spécifiée par un utilisateur sans root, les correspondances spécifiées sont relatives à l'espace de noms d'utilisateurs sans root dans le conteneur, plutôt qu'être relatives à l'hôte comme cela serait le cas lors de l'exécution avec

Fichier

storage.conf (/etc/containers/sto

rage.conf)

storage.conf est le fichier de configuration de stockage pour tous les outils utilisant containers/storage

.

Le fichier de configuration de stockage spécifie toutes les options de stockage de conteneurs disponibles pour les outils utilisant le stockage de conteneurs

partagé.

mounts.conf (/usr/share/containers/mounts.conf et optionnellement /etc/containers/mou

nts.conf)

Les fichiers mounts.conf spécifient les fichiers ou répertoires de montage de volumes qui sont automatiquement montés à l'intérieur des conteneurs lors de l'exécution des commandes buildah run ou buildah build. Les processus du conteneur peuvent ensuite utiliser ce contenu. Le contenu du montage de volume n'est pas commité dans l'image

finale.

Habituellement, ces répertoires sont utilisés pour transmettre les secrets ou les identifiants requis par le logiciel du paquet pour accéder aux dépôts de paquets

distants.

Par exemple, un mounts.conf avec la ligne "/usr/share/rhel/secrets:/run/secrets", le contenu du répertoire /usr/share/rhel/secrets est monté sur /run/secrets à l'intérieur du conteneur. Ce point de montage permet d'utiliser les abonnements Red Hat Enterprise Linux de l'hôte à l'intérieur du conteneur. Il est également possible d'omettre la destination si elle est égale au chemin source. Par exemple, en spécifiant /var/lib/secrets, le répertoire sera monté sur le chemin de destination du conteneur /var/lib/secrets. /var/lib/secrets

.

Notez qu'il ne s'agit pas d'un montage de volume. Le contenu des volumes est copié dans le stockage du conteneur, et non monté par liaison directement depuis

l'hôte.

registries.conf (/etc/containers/regis

tries.conf)

registries.conf est le fichier de configuration qui spécifie les registres de conteneurs à consulter lors de la complétion des noms d'images qui n'incluent pas de partie registre ou de

domaine.

istries.d)
