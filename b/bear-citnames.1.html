NOM

bear-citnames - déduire la sémantique d'une commande

SYNOPSIS

bear citnames [options] --input <fichier> --output <fichier>

DESCRIPTION

Le nom citnames vient de l'inversion du mot « sémantique ».

Lorsque vous tapez une commande, vous connaissez votre intention. L'exécution de la commande n'est qu'un moyen d'atteindre votre objectif. Ce programme prend la commande qui a été exécutée et essaie de déterminer quelle était l'intention derrière l'exécution de cette commande. Il en déduit la sémantique.

Ceci est utile pour générer une base de données de compilation. Citnames reçoit une liste de commandes et crée une base de données de compilation au format JSON. (C'est actuellement la seule sortie de l'outil.)

OPTIONS

--version
Affiche le numéro de version.
--help
Affiche le message d'aide.
--verbose
Active la journalisation détaillée.
--input fichier
Spécifie le fichier d'entrée. (Nom de fichier par défaut fourni.) L'entrée est une liste d'exécutions de commandes, avec des informations supplémentaires. La syntaxe est détaillée dans une section séparée.
--output fichier
Spécifie le fichier de sortie. (Nom de fichier par défaut fourni.) La sortie est actuellement une base de données de compilation JSON.
--append
Utilise le fichier de sortie généré précédemment et y ajoute les nouvelles entrées. De cette façon, vous pouvez travailler en continu et la base de données de compilation reste à jour. La suppression et l'ajout de fichiers sont tous deux pris en compte. Cependant, les changements dans le processus de construction (changement des options du compilateur) peuvent entraîner des entrées en double.
--run-checks
Permet au programme de vérifier l'emplacement des fichiers sur la machine actuelle sur laquelle il s'exécute. (Valeur par défaut fournie. Exécutez l'aide pour la connaître.) Ceci est important si la liste d'exécution ne provient pas de l'hôte actuel.
--config fichier
Spécifie un fichier de configuration. Le fichier de configuration définit comment la sortie doit être formatée et quelles entrées elle doit contenir.

STATUT DE SORTIE

Le statut de sortie de Citnames est non nul en cas de problèmes d'E/S, sinon il est nul. Le statut de sortie est indépendant du nombre de commandes reconnues ou non.

OBSERVABILITÉ

Toute information sur la logique de reconnaissance des commandes peut être observée avec le drapeau --verbose sur la sortie d'erreur standard. Sinon, la commande est silencieuse.

FICHIER D'ENTRÉE

C'est un fichier JSON, contenant l'historique d'exécution des commandes. (Plus des métadonnées utiles pour déboguer l'application qui l'a produit.) Ce fichier peut être produit par la commande bear intercept, qui enregistre les exécutions de processus d'une construction.

Lisez-en plus sur la syntaxe du fichier dans la page de manuel de bear-intercept(1).

FICHIER DE SORTIE

Actuellement, le seul format de sortie est la base de données de compilation JSON. Lisez-en plus sur sa syntaxe dans la page de manuel de bear(1).

FICHIER DE CONFIGURATION

Le fichier de configuration influence la reconnaissance des commandes (par la section « compilation ») et le format de sortie (par la section « output »).

Le fichier de configuration est facultatif. Le programme utilisera les valeurs par défaut, qui peuvent être affichées avec l'indicateur --verbose.

Certaines parties du fichier se chevauchent avec les arguments de la ligne de commande. Si les deux sont présents, l'argument de la ligne de commande remplace les valeurs du fichier de configuration.

{
  "compilation": {
    "compilers_to_recognize": [
      {
        "executable": "/usr/bin/mpicc",
        "flags_to_add": ["-I/opt/MPI/include"],
        "flags_to_remove": ["-Wall"]
      }
    ],
    "compilers_to_exclude": []
  },
  "output": {
    "content": {
      "include_only_existing_source": true,
      "paths_to_include": [],
      "paths_to_exclude": [],
      "duplicate_filter_fields": "file_output"
    },
    "format": {
      "command_as_array": true,
      "drop_output_field": false
    }
  }
}
compilation.compilers_to_recognize
où peuvent être spécifiés des compilateurs qui ne sont pas encore reconnus par défaut. L'exécutable est un chemin absolu vers le compilateur. Les flags_to_add sont un attribut facultatif, qui contient les drapeaux qui seront ajoutés à la sortie finale. (C'est un bon candidat à utiliser pour ajouter les drapeaux d'enveloppement du compilateur OpenMPI issus de la sortie de mpicc --showme:compile.) Les flags_to_remove sont un attribut facultatif, où les drapeaux donnés seront supprimés de la liste d'arguments finale. (Les drapeaux sont vérifiés pour l'égalité uniquement, pas de correspondance regex. Les drapeaux avec des arguments ne sont pas de bons candidats à mettre ici, car la logique de suppression est trop simple pour cela.)
compilation.compilers_to_exclude
il s'agit d'une liste facultative d'exécutables (avec chemin absolu) qui doivent être supprimés de la sortie.
output.content
Les paths_to_include et paths_to_exclude servent à filtrer les entrées des répertoires correspondants. (Les noms de répertoire peuvent être des chemins absolus ou relatifs au répertoire de travail actuel si l'indicateur --run-checks est passé.) L'option include_only_existing_source autorise ou désactive la vérification des fichiers pour la sortie. L'indicateur --run-checks remplace cette valeur de configuration. Le champ duplicate_filter_fields sélectionne la méthode de détection des entrées dupliquées dans la sortie. Les valeurs possibles pour ce champ sont : all, file et file_output.
output.format
L'option command_as_array contrôle quel champ de commande est émis dans la sortie. True produit les arguments, false produit le champ commande. L'option drop_output_field désactivera le champ de sortie.
