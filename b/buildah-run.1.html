--cap-add=CAP_xx

x

Ajoute la capacité spécifiée à l'ensemble des capacités qui seront accordées à la commande spécifiée. Certaines capacités sont accordées par défaut ; cette option peut être utilisée pour en ajouter d'autres au-delà des valeurs par défaut, qui peuvent avoir été modifiées par les options --cap-add et --cap-drop utilisées avec l'invocation buildah from qui a créé le

Retire la capacité spécifiée de l'ensemble des capacités qui seront accordées à la commande spécifiée. La liste des capacités par défaut est gérée dans containers.conf(5)

Si une capacité est spécifiée à la fois dans les options --cap-add et --cap-drop, elle sera retirée, quel que soit l'ordre dans lequel les options ont été

données.

Attache un montage de système de fichiers au

conteneur.

Les types de montage actuellement pris en charge sont bind, cache, secret et tmpfs. Les écritures dans les montages bind et tmpfs sont abandonnées une fois la commande terminée, tandis que les modifications des montages cache persistent d'une utilisation à

l'autre. 
   ex.
   type=bind,source=/chemin/sur/l'hôte,destination=/chemin/dans/le/conteneur
   type=tmpfs,tmpfs-size=512M,destination=/chemin/dans/le/conteneur
   type=cache,target=/chemin/dans/le/conteneur
   Options communes :
          · src, source : spécification de la source du montage pour bind et cache. Obligatoire pour bind. Si `from` est spécifié, `src` est le sous-chemin dans le champ `from`.
          · dst, destination, target : emplacement où la commande en cours d'exécution doit voir le contenu monté.
          · ro, read-only : (par défaut true pour `type=bind`, false pour `type=tmpfs`, `type=cache`).
          · rw, read-write : (par défaut false pour `type=bind`, true pour `type=tmpfs`, `type=cache`).
   Options spécifiques à bind :
          · bind-propagation : shared, slave, private, rshared, rslave, ou rprivate (par défaut). Voir aussi mount(2). [[1]](#Footnote1)
          . bind-nonrecursive : ne pas configurer un montage bind récursif. Par défaut, il est récursif.
          · from : nom de l'image pour la racine de la source. Par défaut **--contextdir**, obligatoire si **--contextdir** n'a pas été spécifié.
          · src : emplacement dans le répertoire de contexte (ou l'image, si l'option **from** est utilisée) à monter à la place de son répertoire de premier niveau.
          · z : Définir l'étiquette SELinux partagée sur la destination montée. À utiliser si SELinux est activé sur la machine hôte.
          · Z : Définir l'étiquette SELinux privée sur la destination montée. À utiliser si SELinux est activé sur la machine hôte.
   Options spécifiques à tmpfs :
          · tmpfs-size : Taille du montage tmpfs en octets. Illimitée par défaut sous Linux.
          · tmpfs-mode : Mode de fichier du tmpfs en octal. (ex. 700 ou 0700.) Par défaut 1777 sous Linux.
          · tmpcopyup : Le chemin masqué par le montage tmpfs est copié récursivement vers le tmpfs lui-même.
   Options spécifiques à secret :
          · id : l'identifiant du secret passé à la commande `buildah bud --secret` ou `podman build --secret`.
   Options spécifiques à cache :
          · id : Distinguer ce cache des autres caches en utilisant cet ID plutôt que le chemin de montage cible.
          · mode : Mode de fichier pour le nouveau répertoire de cache en octal. Par défaut 0755.
          · src : emplacement dans le cache (ou l'image, si l'option **from** est utilisée) à monter à la place de son répertoire de premier niveau.
          · uid : uid pour le répertoire de cache.
          · gid : gid pour le répertoire de cache.
          · from : nom de l'étape pour la racine de la source. Par défaut le répertoire de cache de l'hôte.
          · sharing : Si les autres utilisateurs de ce cache doivent attendre que cette commande se termine (`sharing=locked`) ou non (`sharing=shared`, qui est la valeur par défaut).
          · z : Définir l'étiquette SELinux partagée sur la destination montée. Activé par défaut si SELinux est activé sur la machine hôte.
          · Z : Définir l'étiquette SELinux privée sur la destination montée. À utiliser si SELinux est activé sur la machine
hôte.

Montages de volumes protégés en

écriture

Vous pouvez ajouter le suffixe :ro ou :rw à un volume pour le monter en mode lecture seule ou lecture-écriture, respectivement. Par défaut, les volumes sont montés en lecture-écriture. Voir les

exemples.

Changement de propriétaire des montages de

volumes

Par défaut, Buildah ne change pas le propriétaire et le groupe des répertoires de volume source montés dans les conteneurs. Si un conteneur est créé dans un nouvel espace de noms utilisateur, l'UID et le GID dans le conteneur peuvent correspondre à un autre UID et GID sur

l'hôte.

Le suffixe :U indique à Buildah d'utiliser l'UID et le GID hôte corrects basés sur l'UID et le GID à l'intérieur du conteneur, pour changer le propriétaire et le groupe du volume

source.

Étiquetage des montages de

volumes

Les systèmes d'étiquetage comme SELinux exigent que des étiquettes appropriées soient placées sur le contenu du volume monté dans un conteneur. Sans étiquette, le système de sécurité pourrait empêcher les processus s'exécutant à l'intérieur du conteneur d'utiliser le contenu. Par défaut, Buildah ne change pas les étiquettes définies par le système

d'exploitation.

Pour changer une étiquette dans le contexte du conteneur, vous pouvez ajouter l'un des deux suffixes :z ou :Z au montage de volume. Ces suffixes indiquent à Buildah de réétiqueter les objets de fichiers sur les volumes partagés. L' option z indique à Buildah que deux conteneurs partagent le contenu du volume. En conséquence, Buildah étiquette le contenu avec une étiquette de contenu partagé. Les étiquettes de volume partagées permettent à tous les conteneurs de lire/écrire le contenu. L' option Z indique à Buildah d'étiqueter le contenu avec une étiquette privée non partagée. Seul le conteneur actuel peut utiliser un volume

privé.

Par défaut, les volumes montés en liaison sont privés. Cela signifie que tous les montages effectués à l'intérieur du conteneur ne seront pas visibles sur l'hôte et vice versa. Ce comportement peut être modifié en spécifiant une propriété de propagation de montage de

volume.

Lorsque la politique de propagation de montage est définie sur shared, tous les montages effectués à l'intérieur du conteneur sur ce volume seront visibles à la fois sur l'hôte et dans le conteneur. Nom

buildah-run - exécute une commande dans un nouveau conteneur

SYNOPSIS

buildah run [options] containerID [args ...]

DESCRIPTION

La commande buildah run exécute la commande spécifiée par args dans le conteneur containerID.

Les options modifient le comportement de la commande run.

OPTIONS

Les options suivantes sont disponibles :

--argv0 string

Substitue la chaîne string à argv[0] de la commande exécutée. Cela permet de changer la façon dont la commande s'identifie dans le système du conteneur.

--blk-io-weight uint

Poids d'E/S de bloc pour le groupe de contrôle des ressources.

--blk-io-weight-device string

Poids d'E/S de bloc pour un appareil spécifique.

--cpu-shares uint

Ratio des cycles CPU à allouer au conteneur.

--cpuset-cpus string

CPUs autorisés pour le conteneur.

--cpuset-mems string

Mèmes autorisés pour le conteneur.

-d, --detach

Exécute la commande en arrière-plan et imprime le nouveau conteneur ID.

--device string

Ajoute un périphérique hôte au conteneur.

--device-read-bps string

Limite le débit de lecture en octets par seconde pour un périphérique.

--device-read-iops string

Limite le débit de lecture en E/S par seconde pour un périphérique.

--device-write-bps string

Limite le débit d'écriture en octets par seconde pour un périphérique.

--device-write-iops string

Limite le débit d'écriture en E/S par seconde pour un périphérique.

--entrypoint string

Remplace l'entrypoint du conteneur.

--env, -e string

Définit les variables d'environnement.

--gateway string

Spécifie la passerelle réseau pour le conteneur.

--health-cmd string

Commande à exécuter pour le contrôle de santé.

--health-interval duration

Intervalle entre les contrôles de santé.

--health-retries uint

Nombre de tentatives avant de considérer le conteneur comme défaillant.

--health-start-period duration

Période de démarrage avant de lancer les contrôles de santé.

--health-timeout duration

Délai d'attente pour un contrôle de santé.

--hostname string

Définit le nom d'hôte du conteneur.

--kernel-memory bytes

Limite la mémoire du noyau pour le conteneur.

--log-driver string

Pilote de journalisation pour le conteneur.

--log-opt string

Options de journalisation pour le conteneur.

--memory, -m bytes

Limite la mémoire du conteneur.

--memory-reservation bytes

Limite souple de la mémoire du conteneur.

--memory-swap bytes

Limite la mémoire swap du conteneur.

--mount string

Ajoute un montage au conteneur. Le format est type=TYPE,SOURCE=SOURCE,TARGET=TARGET[,OPTIONS].

Les types de montage pris en charge sont :

bind : Monte un répertoire ou un fichier du système hôte dans le conteneur.

volume : Utilise un volume géré par le moteur de conteneurisation.

tmpfs : Crée un système de fichiers temporaire dans le conteneur.

Les options supplémentaires peuvent inclure :

ro : Rend le montage en lecture seule.

rw : Rend le montage en lecture/écriture (par défaut).

z : Marque le volume pour qu'il soit partagé entre plusieurs conteneurs (selinux).

Z : Marque le volume pour qu'il soit privé au conteneur (selinux).

U : Marque le volume pour qu'il soit géré par l'utilisateur (selinux).

Le montage peut être spécifié à l'aide de la syntaxe buildah mount ou docker mount. Pour la syntaxe docker mount, les options sont séparées par des virgules. Par exemple : --mount type=bind,source=/host/dir,target=/container/dir,ro.

--mount-propagation string

Définit la propriété de propagation du montage. Les valeurs possibles sont shared, slave, private, rshared, rslave, rprivate. La valeur par défaut est rprivate.

Les montages bind, les montages internes et les montages nommés sont visibles uniquement à l'intérieur du conteneur, une fois qu'ils sont activés et que tous les montages effectués sur l'hôte pour ce volume sont terminés. Pour contrôler la propriété de propagation du montage du volume, utilisez le drapeau de propagation :[r]shared, :[r]slave ou :[r]private. La propriété de propagation ne peut être spécifiée que pour les volumes bind montés et non pour les volumes internes ou nommés. Pour que la propagation du montage fonctionne sur le point de montage source (le point de montage où le répertoire source est monté), il doit avoir les bonnes propriétés de propagation. Pour les volumes partagés, le point de montage source doit être partagé. Et pour les volumes esclaves, le montage source doit être partagé ou esclave. [1] ⟨#Footnote1⟩

Utilisez df <source-dir> pour déterminer le montage source, puis utilisez findmnt -o TARGET,PROPAGATION <source-mount-dir> pour déterminer les propriétés de propagation du montage source. Si l'utilitaire findmnt n'est pas disponible, le point de montage source peut être déterminé en examinant l'entrée de montage dans /proc/self/mountinfo. Examinez les champs optionnels et voyez si des propriétés de propagation sont spécifiées. shared:X signifie que le montage est partagé, master:X signifie que le montage est esclave et s'il n'y a rien, cela signifie que le montage est privé. [1] ⟨#Footnote1⟩

Pour changer les propriétés de propagation d'un point de montage, utilisez la commande mount. Par exemple, pour monter en bind le répertoire source /foo, exécutez mount --bind /foo /foo et mount --make-private --make-shared /foo. Cela convertira /foo en un point de montage partagé. Les propriétés de propagation du montage source peuvent être modifiées directement. Par exemple, si / est le montage source pour /foo, alors utilisez mount --make-shared / pour convertir / en un montage partagé.

--workingdir directory

Définit temporairement le répertoire de travail pour le processus en cours. Contrairement à buildah config --workingdir, le répertoire de travail ne persistera pas pour les appels ultérieurs à buildah run ou à l'image créée.

NOTE : Terminez l'analyse des options avec l'option --, afin que d'autres options puissent être transmises à la commande à l'intérieur du conteneur.
