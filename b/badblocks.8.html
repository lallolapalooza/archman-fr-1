NOM

badblocks - rechercher des blocs défectueux sur un périphérique

SYNTAXE

badblocks [ -svwnfBX ] [ -b taille_bloc ] [ -c blocs_a_la_fois ] [ -d facteur_delai_lecture ] [ -e nb_max_blocs_def ] [ -i fichier_entree ] [ -o fichier_sortie ] [ -p nb_passes ] [ -t motif_test ] périphérique [ dernier_bloc ] [ premier_bloc ]

DESCRIPTION

badblocks est utilisé pour rechercher des blocs défectueux sur un périphérique (généralement une partition de disque). périphérique est le fichier spécial correspondant au périphérique (par exemple, /dev/hdc1). dernier_bloc est le dernier bloc à tester ; s'il n'est pas spécifié, le dernier bloc du périphérique est utilisé par défaut. premier_bloc est un paramètre optionnel spécifiant le numéro du bloc de départ pour le test, ce qui permet de commencer le test au milieu du disque. S'il n'est pas spécifié, le premier bloc du disque est utilisé par défaut.

Note importante : Si la sortie de badblocks doit être utilisée par les programmes e2fsck ou mke2fs, il est important que la taille des blocs soit correctement spécifiée, car les numéros de bloc générés dépendent fortement de la taille des blocs utilisée par le système de fichiers. Pour cette raison, il est fortement recommandé aux utilisateurs de ne pas exécuter badblocks directement, mais plutôt d'utiliser l'option -c des programmes e2fsck et mke2fs.

OPTIONS

-b taille_bloc
Spécifie la taille des blocs en octets. La valeur par défaut est 1024.
-c nombre_de_blocs
est le nombre de blocs testés à la fois. La valeur par défaut est 64.
-d facteur_delai_lecture
Ce paramètre, s'il est passé et différent de zéro, entraînera un délai entre les lectures si aucune erreur n'a été rencontrée lors de l'opération de lecture ; le délai sera calculé en pourcentage du temps qu'a pris l'opération de lecture. Autrement dit, une valeur de 100 entraînera un délai pour chaque lecture égal au temps pris par la lecture précédente, et une valeur de 200 un délai double.
-e nb_max_blocs_def
Spécifie un nombre maximal de blocs défectueux avant d'interrompre le test. La valeur par défaut est 0, ce qui signifie que le test se poursuivra jusqu'à la fin de la plage de test.
-f
Normalement, badblocks refuse d'effectuer un test en lecture/écriture ou un test non destructif sur un périphérique monté, car cela pourrait potentiellement provoquer un plantage du système et/ou endommager le système de fichiers, même s'il est monté en lecture seule. Ceci peut être outrepassé en utilisant le drapeau -f, mais ne devrait presque jamais être utilisé --- si vous pensez être plus malin que le programme badblocks, vous ne l'êtes presque certainement pas. La seule fois où cette option pourrait être sûre à utiliser est si le fichier /etc/mtab est incorrect, et que le périphérique n'est réellement pas monté.
-i fichier_entree
Lit une liste de blocs déjà connus comme défectueux. Badblocks ignorera le test de ces blocs car ils sont connus pour être défectueux. Si fichier_entree est spécifié comme "-", la liste sera lue depuis l'entrée standard. Les blocs listés dans cette liste seront omis de la liste des blocs défectueux nouveaux produits sur la sortie standard ou dans le fichier de sortie. L'option -b de dumpe2fs(8) peut être utilisée pour récupérer la liste des blocs actuellement marqués comme défectueux sur un système de fichiers existant, dans un format adapté à cette option.
-n
Utilise le mode lecture/écriture non destructif. Par défaut, seul un test en lecture seule non destructif est effectué. Cette option ne doit pas être combinée avec l'option -w, car elles sont mutuellement exclusives.
-o fichier_sortie
Écrit la liste des blocs défectueux dans le fichier spécifié. Sans cette option, badblocks affiche la liste sur sa sortie standard. Le format de ce fichier est adapté à l'utilisation par l'option -l de e2fsck(8) ou mke2fs(8).
-p nb_passes
Répète l'analyse du disque jusqu'à ce qu'aucun nouveau bloc ne soit découvert en nb_passes passes consécutives du disque. La valeur par défaut est 0, ce qui signifie que badblocks se terminera après la première passe.
-s
Affiche la progression de l'analyse en écrivant le pourcentage approximatif d'achèvement de la passe actuelle de badblocks sur le disque. Notez que badblocks peut effectuer plusieurs passes de test sur le disque, en particulier si l'option -p ou -w est demandée par l'utilisateur.
-t motif_test
Spécifie un motif de test à lire (et écrire) dans les blocs du disque. Le motif_test peut être une valeur numérique comprise entre 0 et ULONG_MAX-1 inclusivement, ou le mot "random", qui spécifie que le bloc doit être rempli avec un motif binaire aléatoire. Pour les modes lecture/écriture (-w) et non destructif (-n), un ou plusieurs motifs de test peuvent être spécifiés en indiquant l'option -t pour chaque motif de test souhaité. Pour le mode lecture seule, un seul motif peut être spécifié et il ne peut pas être "random". Le test en lecture seule avec un motif suppose que le motif spécifié a été précédemment écrit sur le disque - sinon, un grand nombre de blocs échoueront à la vérification. Si plusieurs motifs sont spécifiés, tous les blocs seront testés avec un motif avant de passer au motif suivant.
-v
Mode verbeux. Écrira le nombre d'erreurs de lecture, d'erreurs d'écriture et de corruptions de données sur stderr.
-w
Utilise le mode test en écriture. Avec cette option, badblocks recherche les blocs défectueux en écrivant certains motifs (0xaa, 0x55, 0xff, 0x00) sur chaque bloc du périphérique, en lisant chaque bloc et en comparant le contenu. Cette option ne peut pas être combinée avec l'option -n, car elles sont mutuellement exclusives.
-B
Utilise l'E/S en mémoire tampon et n'utilise pas l'E/S directe, même si elle est disponible.
-X
Indicateur interne uniquement destiné à être utilisé par e2fsck(8) et mke2fs(8). Il contourne la vérification de sécurité du périphérique en mode exclusif d'utilisation.

AVERTISSEMENT

N'utilisez jamais l'option -w sur un périphérique contenant un système de fichiers existant. Cette option efface les données ! Si vous souhaitez effectuer des tests en mode écriture sur un système de fichiers existant, utilisez plutôt l'option -n. Elle est plus lente, mais elle préservera vos données.

L'option -e fera en sorte que badblocks produise une liste éventuellement incomplète de blocs défectueux. Par conséquent, il est recommandé de l'utiliser uniquement lorsque l'on veut savoir s'il y a des blocs défectueux sur le périphérique, et non lorsque la liste des blocs défectueux est souhaitée.
