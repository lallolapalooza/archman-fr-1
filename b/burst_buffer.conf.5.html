DESCRIPTIO

N

burst_buffer.conf est un fichier ASCII qui décrit la configuration de la gestion des ressources des tampons élastiques. Ce fichier n'est requis que sur le(s) nœud(s) principal(aux), où le démon slurmctld s'exécute. Le fichier sera toujours situé dans le même répertoire que le slurm.c

onf.

Les noms de paramètres ne sont pas sensibles à la casse. Tout texte suivant un "#" dans le fichier de configuration est traité comme un commentaire jusqu'à la fin de cette ligne. Les modifications du fichier de configuration prennent effet lors du redémarrage des démons Slurm, de la réception du signal SIGHUP par le démon, ou de l'exécution de la commande "scontrol

reconfigure".

Les paramètres de configuration disponibles incluent

:
AllowUse
rs
Liste séparée par des virgules des noms d'utilisateurs et/ou des identifiants autorisés à utiliser les tampons élastiques. Les options AllowUsers et DenyUsers ne peuvent pas être spécifiées toutes les deux. Par défaut,
tous les utilisateurs sont autori
sés à utiliser les tampons élastiques.
DefaultPo
ol
Nom du pool utilisé par défaut pour les allocations de ressources. La valeur par défaut est le premier pool signalé par l'infrastructure des tampons élastiques. Cette option n'est utilisée que par le plugin burst_buffer/datawar
p
.
DenyUse
rs
Liste délimitée par des deux-points des noms d'utilisateurs et/ou des identifiants interdits d'utiliser les tampons élastiques. Les options AllowUsers et DenyUsers ne peuvent pas être spécifiées toutes les deux. Par défaut,
tous les utilisateurs sont autori
sés à utiliser les tampons élastiques.
Directi
ve
La chaîne qu'un travail doit utiliser pour demander un tampon élastique. Cette chaîne doit être immédi
atement précédée d'un seul caractère '#'. Elle n'est actuellement utilisée que par le plugin lua. Pou
r le plugin lua, la valeur par défaut est "BB_LUA". Voir burst_buffer.html pour plus de détails.
Fla
gs
Chaîne utilisée pour contrôler diverses fonctions. Pl
usieurs options peuvent être séparées par des vi
rgules. Les options prises en charge incluent :
DisablePersist
ent
Empêche les utilisateurs réguliers de créer et de détruire des tampons élastiques persis
tants. C'est le comportement par défaut, seuls les utilisateurs privilégiés (opérateurs
et administrateurs Slurm) peuvent créer ou détruire des tampons élastiques persistants.
EmulateCr
ay
Émulation d'un système Cray DataWarp à l'aide du scrip
t dw_wlm_cli dans le plugin burst_buffer/datawarp
. Ceci n'est utilisé que par le plugin datawarp.
EnablePersist
ent
Permet aux utilisateurs réguliers de créer et de détruire des tampons élastiques persistants. Par
défaut, seuls les utilisateurs privilégiés (opérateurs et administrateurs Slurm) peuvent créer ou
détruire des tampons élastiques persistants. Ceci n'est utilisé que par le plugin datawarp.
PrivateDa
ta
S'il est défini, alors seuls les opérateurs Slu
rm et le propriétaire du tampon élastiqu
e peuvent voir les données du tampon élastique.
TeardownFail
ure
S'il est défini, alors démantèle un tampon él
astique après une erreur de staging de
fichiers. Sinon, préserve le tampon élastiqu
e pour analyse et démantèlement manuel.
GetSysSta
te
Chemin complet d'un programme qui renverra l'état actuel du tampon élastique. Pour le plugin DataWarp, il s'agit du chemin de la commande dw_wlm_cli et sa valeur par défaut est /opt/cray/dw_wlm/defa
ult/bin/dw_wlm_cli. Ceci n'est pas
utilisé par le plugin lua.
GetSysStat
us
Chemin complet d'un programme qui renverra l'état actuel du tampon élastique. Pour le plugin DataWarp, il s'agit du chemin de la commande dwstat et sa valeur par défaut est /opt/cray/dws/defaul
t/bin/dwstat. Ceci n'est pas ut
ilisé par le plugin lua.
OtherTimeo
ut
Si une opération de tampon élastique (autre que la validation du travail, le stage in ou le stage out) dure plus longtemps que ce nombre de secondes, le travail sera placé dans un état suspendu. Un administrateur Slurm devra libérer le travail. Par défaut, il y a un délai d'attente de 300 secondes (5 minutes) pour ces opérations. Voir aussi les options StageInTimeout, StageOutTimeout et ValidateTimeout. Pour le plugin lua, la valeur de délai d'
attente maximale est de
2073600 secondes (24 jours).
PollInterv
al
Cette option ne s'applique qu'au plugin lua. Si les crochets test_data_{in|
out} renvoient succès et "BUSY", alors ils seront rappelés après avoir atten
du le nombre de secondes spécifié. La valeur par défaut est de 15 secondes.
PrivateDa
ta
S'il est défini à "true", alors les utilisateurs ne pourront voir que les tampons élastiq
ues qu'ils peuvent utiliser. Les administrateurs Slurm pourront toujours voir tous les t
ampons élastiques. Par défaut, les utilisateurs peuvent voir tous les tampons élastiques.
StageInTimeo
ut
Si le stage in des fichiers pour un travail prend plus de ce nombre de secondes, le tampon élastique sera libéré et le travail sera
placé dans un état suspendu. Un administrateur Slurm devra libérer le travail. Par défaut, il y a un délai d'attente d'un jou
r pour le processus de stage in. Pour le plugin lua, la valeur de délai d'attente maximale est de 2073600 secondes (24 jours).
StageOutTime
out
Si le stage out des fichiers pour un travail prend plus de ce nombre de secondes, le tampon élastique sera
libéré et le travail sera purgé. Par défaut, il y a un délai d'attente d'un jour pour le processus de stag
e out. Pour le plugin lua, la valeur de délai d'attente maximale est de 2073600 secondes (24 jours).
ValidateTime
out
Si la validation d'une demande de soumission de travail prend plus de ce nombre de secondes, la soumission sera rejetée. La valeur de ValidateTimeout doit être inférieure à la valeur de MessageTimeout configurée dans le fichier slurm.conf, sinon les demandes de soumission de travail peuvent échouer avec une erreur de délai d'attente de réponse. Par défaut, il y a un
délai d'attente de 5 secondes pour les opérations de validation. Dans le plugin lua, parce
que l'opération de validation ne peut pas être interrompue, cette option n'est pas utilisée.
