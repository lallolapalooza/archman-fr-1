NOM

btrfstune - régler divers paramètres du système de fichiers

SYNTAXE

btrfstune [options] <périphérique> [<périphérique>...]

DESCRIPTION

btrfstune peut être utilisé pour activer, désactiver ou régler divers paramètres du système de fichiers. Le système de fichiers doit être démonté.

Le cas d'utilisation courant est l'activation de fonctionnalités qui n'ont pas été activées au moment de la création avec mkfs. Assurez-vous de disposer du support noyau pour ces fonctionnalités. Vous pouvez trouver une liste complète des fonctionnalités et la version du noyau de leur introduction sur la page Feature by version <>. De plus, la page de manuel mkfs.btrfs(8) <> contient plus de détails sur ces fonctionnalités.

Certaines fonctionnalités peuvent également être activées sur un système de fichiers monté par d'autres moyens. Veuillez vous référer à la section FONCTIONNALITÉS DU SYSTÈME DE FICHIERS dans btrfs(5) <>.

OPTIONS

--convert-to-block-group-tree
(depuis le noyau 6.1)

Convertir des parties de l'arbre d'extensions qui suit les groupes de blocs vers un arbre de groupes de blocs séparé. Cela réduit considérablement le temps de montage. Peut également être activé lors de la création avec mkfs.

--convert-from-block-group-tree
(depuis le noyau 6.1)

Convertir les groupes de blocs suivis dans un arbre de groupes de blocs autonome vers l'arbre d'extensions et supprimer le bit de fonctionnalité block-group-tree du système de fichiers.

--convert-to-free-space-tree
(depuis le noyau 4.5)

Convertir vers la fonctionnalité free-space-tree (v2 du cache d'espace).

--enable-simple-quota
(depuis le noyau 6.7)

Activer la comptabilité de quotas simple (fonctionnalité mkfs squota). C'est une alternative aux qgroups avec un impact performance moindre mais sans notion d'utilisation partagée ou exclusive.

--remove-simple-quota
Supprimer les structures liées à la comptabilité de quotas simple.
-f
Autoriser des modifications dangereuses, par exemple effacer le drapeau d'amorçage (seeding) ou changer l'fsid. Assurez-vous d'être conscient des dangers.
-m
(depuis le noyau : 5.0)

changer l'fsid stocké sous le nom de metadata_uuid en un UUID généré aléatoirement, voir également -U

-M <UUID>
(depuis le noyau : 5.0)

changer l'fsid stocké sous le nom de metadata_uuid en un UUID donné, voir également -U

Le metadata_uuid est stocké uniquement dans le superbloc et constitue un changement rétroactivement incompatible. L'fsid dans les blocs de métadonnées reste inchangé et n'est pas écrasé, l'opération entière est donc beaucoup plus rapide que -U.

Le nouveau metadata_uuid peut être utilisé pour le montage par UUID et est également utilisé pour identifier les périphériques d'un système de fichiers multi-périphériques.

-n
(depuis le noyau : 3.14)

Activer la fonctionnalité no-holes (représentation plus efficace des trous de fichiers), activée par la fonctionnalité mkfs no-holes.

-r
(depuis le noyau : 3.7)

Activer les références d'inodes étendues (la limite de liens physiques par fichier dans un répertoire est de 65536), activée par la fonctionnalité mkfs extref.

-S <0|1>
Activer l'amorçage (seeding) sur un périphérique donné. La valeur 1 activera l'amorçage, 0 le désactivera. Un système de fichiers d'amorçage est forcé d'être monté en lecture seule. Un nouveau périphérique peut être ajouté au système de fichiers et capturera toutes les écritures, laissant le périphérique d'amorçage intact. Voir également la section SEEDING DEVICE <#man-btrfs5-seeding-device> dans btrfs(5) <>.

Attention :

La suppression du drapeau d'amorçage sur un périphérique peut être dangereuse. Si un périphérique précédemment amorcé est modifié, tous les systèmes de fichiers qui utilisaient ce périphérique deviendront impossibles à monter. Réactiver le drapeau d'amorçage ne corrigera pas cela.

Un cas d'utilisation valide est l'image de base comme périphérique d'amorçage. Supprimez le drapeau d'amorçage, mettez à jour le système de fichiers et rendez-le à nouveau amorçable, à condition qu'il soit acceptable de jeter tous les systèmes de fichiers construits sur l'image de base précédente.

-u
Changer l'fsid en un UUID généré aléatoirement ou continuer une opération précédente de changement d'fsid si elle a été interrompue.
-U <UUID>
Changer l'fsid en UUID dans tous les blocs de métadonnées.

L'UUID doit être une chaîne de 36 octets au format printf(3) <https://man7.org/linux/man-pages/man3/printf.3.html> %08x-%04x-%04x-%04x-%012x. S'il y a un changement d'fsid inachevé précédent, il ne continuera que si l'UUID correspond à celui inachevé ou si vous utilisez l'option -u.

Tous les blocs de métadonnées sont réécrits, cela peut prendre du temps, mais la compatibilité finale du système de fichiers n'est pas affectée, contrairement à -M.

Attention :

L'annulation ou l'interruption d'une opération de changement d'UUID rendra le système de fichiers temporairement impossible à monter. Pour le corriger, relancez btrfstune -u et laissez-la se terminer.
-x
(depuis le noyau : 3.10)

Activer les références d'extensions skinny pour les métadonnées (représentation plus efficace des extensions), activée par la fonctionnalité mkfs skinny-metadata.

Toutes les extensions nouvellement créées utiliseront la nouvelle représentation. Pour basculer complètement l'ensemble du système de fichiers, exécutez un équilibrage complet des métadonnées. Veuillez vous référer à btrfs-balance(8) <>.

--version
Affiche la version de btrfstune, les fonctionnalités intégrées et quitte.

STATUT DE SORTIE

btrfstune retourne 0 si aucune erreur ne s'est produite, 1 sinon.

NOTE DE COMPATIBILITÉ

Cet outil déprécié existe pour des raisons historiques mais est encore utilisé aujourd'hui. Ses fonctionnalités seront fusionnées dans l'outil principal, moment auquel btrfstune sera déclaré obsolète et programmé pour la suppression.

VOIR AUSSI
