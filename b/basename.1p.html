BASENAME(1P) Manuel du programmeur POSIX BASENAME(1P)

PROLOGUE

Ce manuel page fait partie du Manuel du programmeur POSIX. L'implémentation Linux de cette interface peut différer (consultez la page de manuel Linux correspondante pour connaître les détails du comportement sous Linux), ou l'interface peut ne pas être implémentée sous Linux.

NOM

basename — renvoie la partie non répertoire d'un chemin

SYNOPIS

basename chaîne [suffixe]

DESCRIPTION

L'opérande chaîne sera traité comme un chemin, tel que défini dans le volume Base Definitions de POSIX.1‐2017, Section 3.271, Chemin. La chaîne chaîne sera convertie en nom de fichier correspondant au dernier composant du chemin dans chaîne, puis la chaîne suffixe suffixe, si elle est présente, sera supprimée. Ceci sera fait en effectuant des actions équivalentes aux étapes suivantes dans l'ordre :

1.
Si chaîne est une chaîne vide, il est indéterminé si la chaîne résultante est '.' ou une chaîne vide. Dans les deux cas, passez aux étapes 2 à 6.
2.
Si chaîne est "//", il est défini par l'implémentation si les étapes 3 à 6 sont ignorées ou traitées.
3.
Si chaîne est entièrement composé de caractères <slash>, chaîne sera défini comme un seul caractère <slash>. Dans ce cas, passez aux étapes 4 à 6.
4.
S'il y a des caractères <slash> finaux dans chaîne, ils seront supprimés.
5.
S'il reste des caractères <slash> dans chaîne, le préfixe de chaîne jusqu'au dernier caractère <slash> inclus sera supprimé.
6.
Si l'opérande suffixe est présent, n'est pas identique aux caractères restants dans chaîne, et est identique à un suffixe des caractères restants dans chaîne, le suffixe suffixe sera supprimé de chaîne. Sinon, chaîne n'est pas modifié par cette étape. Il ne sera pas considéré comme une erreur si suffixe n'est pas trouvé dans chaîne.

La chaîne résultante sera écrite sur la sortie standard.

OPTIONS

Aucune.

OPÉRANDES

Les opérandes suivants seront pris en charge :

chaîne
Une chaîne.
suffixe
Une chaîne.

ENTRÉE STANDARD

Non utilisé.

FICHIERS D'ENTRÉE

Aucun.

VARIABLES D'ENVIRONNEMENT

Les variables d'environnement suivantes affecteront l'exécution de basename :

LANG
Fournit une valeur par défaut pour les variables d'internationalisation qui sont indéfinies ou vides. (Voir le volume Base Definitions de POSIX.1‐2017, Section 8.2, Variables d'internationalisation pour la précédence des variables d'internationalisation utilisées pour déterminer les valeurs des catégories de locale.)
LC_ALL
Si défini sur une chaîne de valeur non vide, remplace les valeurs de toutes les autres variables d'internationalisation.
LC_CTYPE
Détermine la locale pour l'interprétation des séquences d'octets de données textuelles en caractères (par exemple, caractères mono-octet par opposition aux caractères multi-octets dans les arguments).
LC_MESSAGES

Détermine la locale qui devrait être utilisée pour affecter le format et le contenu des messages de diagnostic écrits sur la sortie d'erreur standard.
NLSPATH
Détermine l'emplacement des catalogues de messages pour le traitement de LC_MESSAGES.

SORTIE STANDARD

L'utilitaire basename écrira une ligne sur la sortie standard dans le format suivant :

"%s\n", <chaîne résultante>

ERREUR STANDARD

La sortie d'erreur standard ne sera utilisée que pour les messages de diagnostic.

UTILISATION PAR L'APPLICATION

La définition de chemin spécifie un comportement défini par l'implémentation pour les chemins commençant par deux caractères <slash>. Par conséquent, les applications ne doivent pas ajouter arbitrairement des caractères <slash> au début d'un chemin, à moins qu'elles ne puissent garantir qu'il y en a plus ou moins de deux, ou qu'elles soient préparées à gérer les conséquences définies par l'implémentation.

EXEMPLES

Si la chaîne chaîne est un chemin valide :

$(basename -- "chaîne")

produit un nom de fichier qui pourrait être utilisé pour ouvrir le fichier nommé par chaîne dans le répertoire renvoyé par :

$(dirname -- "chaîne")

Si la chaîne chaîne n'est pas un chemin valide, le même algorithme est utilisé, mais le résultat n'est pas nécessairement un nom de fichier valide. L'utilitaire basename n'est pas censé porter de jugement sur la validité de chaîne en tant que chemin ; il suit simplement l'algorithme spécifié pour produire une chaîne de résultat.

Le script shell suivant compile /usr/src/cmd/cat.c et déplace la sortie vers un fichier nommé cat dans le répertoire courant lorsqu'il est invoqué avec l'argument /usr/src/cmd/cat ou avec l'argument /usr/src/cmd/cat.c :

c99 -- "$(dirname -- "$1")/$(basename -- "$1" .c).c" &&
mv a.out "$(basename -- "$1" .c)"

La section EXEMPLES de la fonction basename() (voir le volume System Interfaces de POSIX.1‐2017, basename()) comprend un tableau montrant les exemples de résultats du traitement de plusieurs chemins d'exemple par les fonctions basename() et dirname() ainsi que par les utilitaires basename et dirname.

RATIONALE

Les comportements de basename et dirname ont été coordonnés de sorte que lorsque chaîne est un chemin valide :

$(basename -- "chaîne")

serait un nom de fichier valide pour le fichier dans le répertoire :

$(dirname -- "chaîne")

Cela ne fonctionnerait pas pour les premières versions proposées de ces utilitaires en raison de la manière dont elles spécifiaient la gestion des caractères <slash> finaux.
