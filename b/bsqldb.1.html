BSQLDB(1) Manuel des commandes générales BSQLDB(1)

NOM

bsqldb — processeur de scripts SQL en lot utilisant DB-Library

SYNTAXE

bsqldb [-hqv] [-S nom_serveur] [-D base_de_donnees] [-U nom_utilisateur] [-P mot_de_passe] [-i fichier_entree] [-o fichier_sortie] [-e fichier_erreur] [-H nom_hote] [-t delimiteur_champs] [-R description_pivot]

DESCRIPTION

bsqldb est un utilitaire distribué avec FreeTDS. bsqldb est un équivalent non interactif des utilitaires "isql" distribués par Sybase et Microsoft. Comme eux, bsqldb utilise la commande "go" sur une ligne à elle seule comme séparateur entre les lots. Le dernier lot n'a pas besoin d'être suivi par "go". bsqldb utilise l'API DB-Library fournie par FreeTDS. Cette API est bien sûr également disponible pour les développeurs d'applications.

OPTIONS

-D base_de_donnees
Base de données à utiliser.
-H nom_hote
Nom d'hôte. Remplace le nom du client envoyé au serveur.
-P mot_de_passe
Mot de passe du serveur de base de données.
-S nom_serveur
Serveur de base de données auquel se connecter.
nom_utilisateur
Nom de connexion au serveur de base de données. Si le nom d'utilisateur n'est pas fourni, une connexion de domaine est tentée pour les connexions TDS 7+.
-e fichier_erreur
Nom du fichier pour les erreurs.
-h
Affiche les en-têtes de colonne avec les données dans le même fichier.
-i fichier_entree
Nom du fichier de script contenant le SQL.
-o fichier_sortie
Nom du fichier de sortie contenant les données résultantes.
-q
N'affiche pas les métadonnées des colonnes, le statut de retour ou le nombre de lignes. Remplace -h.
-t delimiteur_champs
Spécifie le délimiteur de champ. Par défaut, il s'agit de deux espaces (' '). Les séquences d'échappement reconnues sont tabulation ('\t'), retour chariot ('\r'), nouvelle ligne ('\n') et antislash ('\\').
-v
Mode verbeux, pour plus d'informations sur l'interaction DB-Library. Cela affiche également les métadonnées de l'ensemble de résultats, y compris le code de retour. Toutes les données verbeuses sont écrites sur la sortie d'erreur standard (ou dans le fichier spécifié par -e), afin de ne pas interférer avec le flux de données.
-R description_pivot
Spécifie la transformation pivot. Le format est ⟨colonnes_verticales⟩ ⟨colonnes_horizontales⟩ ⟨fonction⟩ ⟨valeur⟩. Les colonnes sont spécifiées par leurs numéros. Le format des colonnes verticales et horizontales est une liste de colonnes séparées par des virgules. La fonction est soit count, sum, min ou max.

ENVIRONNEMENT

DSQUERY nom_serveur par défaut

NOTES

bsqldb est un filtre ; il lit depuis l'entrée standard, écrit sur la sortie standard et écrit les erreurs sur la sortie d'erreur standard. Les options -i, -o et -e remplacent ces valeurs par défaut.

Le code source de bsqldb est destiné à servir de modèle aux utilisateurs de DB-Library. DB-Library dispose d'un ensemble riche de fonctions, et il peut parfois être difficile de comprendre comment les utiliser, surtout la première fois. Si vous trouvez quelque chose d'obscur dans le code source, vous êtes encouragé à envoyer vos commentaires à l'auteur.

STATUT DE SORTIE

bsqldb se termine avec 0 en cas de succès, et >0 si le serveur ne peut pas traiter la requête.

Pour les messages dont la sévérité est supérieure à 10, bsqldb appelle exit(3) avec le niveau de sévérité. Par exemple, si le niveau de sévérité est 16, bsqldb retournera un statut de sortie de 16 au shell.

HISTORIQUE

bsqldb est apparu pour la première fois dans FreeTDS 0.63.

AUTEURS

L'utilitaire bsqldb a été écrit par James K. Lowden ⟨jklowden@freetds.org⟩.

BOGUES

Les serveurs Microsoft à partir de SQL Server 7.0 SP 3 ne retournent pas les paramètres de sortie, sauf si les fonctions RPC sont utilisées. Cela signifie que bsqldb ne peut pas retourner les paramètres de sortie pour les procédures stockées avec ces serveurs.
