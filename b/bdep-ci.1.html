-dprj-dirDESCRIPTION La commandeci soumet la demande de test des paquets du projet à un serveur CI. Si aucun répertoire de projet ou de paquet n'est spécifié, le répertoire de travail courant est supposé. Si aucune configuration n'est spécifiée, les configurations par défaut sont utilisées. Si le répertoire spécifié est un répertoire de projet, tous les paquets initialisés dans les configurations sont soumis, sauf si l'option--forward est spécifiée (voir ci-dessous). Voir
bdep-projects-configs(1)pour plus de détails sur la spécification des projets et des configurations.Une requête CI se compose des paquets spécifiés et de leurs versions, ainsi que de l'URL du dépôt de contrôle de version distant du projet correspondant à l'état actuel (local) du projet. Le serveur CI doit être capable de récupérer ces versions de paquets depuis ce dépôt, ainsi que toute dépendance depuis ce dépôt ou ses dépôts prérequis/complémentaires, conformément au repositories.manifest de chaque paquet.
Si le serveur CI n'est pas explicitement spécifié avec l'option --server [[68]], la requête est soumise par défaut àci.cppget.org [[70]]. À moins que l'URL du dépôt distant ne soit spécifiée

url

sauf si elle est remplacée par remote.origin.build2Url [[79]]. L'URL du dépôt est ensuite ajustée pour correspondre à l'état actuel (local) du projet. Dans le cas de git(1) [[81]], la branche courante et l'identifiant de commit sont ajoutés en tant que fragment d'URL du dépôt (voir bpkg-repository-types(1

)

Pour les remplacements de contrainte de build, d'e-mail, auxiliaire et de clé publique de bot personnalisé spécifiques à la configuration du paquet, la configuration correspondante doit exister dans le manifeste du paquet. En revanche, le remplacement de configuration du paquet (*-build-config) ajoute une nouvelle configuration si elle n'existe pas et met à jour les arguments de la configuration existante sinon. Dans le premier cas, tous les remplacements potentiels de contrainte de build, d'e-mail, auxiliaire et de clé publique de bot personnalisé pour une telle configuration nouvellement ajoutée doivent suivre le remplacement*-build-configcorrespondant.Notez que les valeurs du groupe de contraintes de build (communes et spécifiques à la configuration du paquet de build) sont remplacées hiérarchiquement afin que les remplacements [*- ] build

Si les contraintes de build communes sont remplacées, alors toutes les contraintes spécifiques à la configuration sont supprimées. Sinon, si des contraintes spécifiques à la configuration sont remplacées, alors pour les configurations restantes, les contraintes de build sont réinitialisées àbuilds: none .De même que pour les groupes de contraintes de build, les remplacements de valeurs de clés publiques de bot personnalisé communes et spécifiques à la configuration du paquet de build sont mutuellement exclusifs. Si les clés publiques de bot personnalisé de build communes sont remplacées, alors toutes les clés publiques de bot personnalisé spécifiques à la configuration sont supprimées. Sinon, si des clés publiques de bot personnalisé spécifiques à la configuration sont remplacées, alors pour les configurations restantes, les clés publiques de bot personnalisé restent inchangées.De même que ci-dessus, les remplacements de valeurs du groupe d'e-mails de build communs et spécifiques à la configuration du paquet de build sont mutuellement exclusifs. Si les e-mails de build communs sont remplacés, alors tous les e-mails spécifiques à la configuration sont supprimés. Sinon, si des e-mails spécifiques à la configuration sont remplacés, alors pour les configurations restantes, les e-mails de build sont réinitialisés aux valeurs vides et les e-mails d'avertissement et d'erreur de build sont supprimés (ce qui désactive effectivement les notifications 
par e-mail pour ces configurations).

Si le service CI le prend en charge, un paquet peut être testé de manière interactive dans une configuration de build spécifique à l'aide de l'option --interact

CI.

--simulate
    résultat

  
Simuler le résultat spécifié du processus CI sans effectuer réellement
      aucune action visible de l'extérieur (comme tester les paquets ou
      publier le résultat). La valeur de résultat couramment utilisée est success.
      Pour les autres résultats reconnus, consultez la documentation du service CI.

OPTIONS   COMMUNES


Les options communes sont résumées ci-dessous, une description plus détaillée
    étant disponible dans bdep-common-options(1).



  
-v

  
Afficher les commandes sous-jacentes essentielles exécutées.

  
-V

  
Afficher toutes les commandes sous-jacentes exécutées.

  
--quiet|-q

  
Exécuter silencieusement, en n'affichant que les messages d'erreur.

  
--verbose
    niveau

  
Définir la verbosité des diagnostics sur niveau entre 0 et 6.

  
--stdout-format
    format

  
Format de représentation à utiliser pour l'affichage sur stdout.

  
--jobs|-j
    num

  
Nombre de tâches à effectuer en parallèle.

  
--progress

  
Afficher les indicateurs de progression pour les opérations de longue durée, telles que les transferts
      réseau, la construction, etc.

  
--no-progress

  
Supprimer les indicateurs de progression pour les opérations de longue durée, telles que les transferts
      réseau, la construction, etc.

  
--diag-color

  
Utiliser la couleur dans les diagnostics.

  
--no-diag-color

  
Ne pas utiliser la couleur dans les diagnostics.

  
--bpkg
    chemin

  
Le programme de gestion de paquets à utiliser pour la gestion de la
    configuration de construction.

  
--bpkg-option
    opt

  
Option supplémentaire à transmettre au programme de gestion de paquets.

  
--build
    chemin

  
Le programme de construction à utiliser pour construire les paquets.

  
--build-option
    opt

  
Option supplémentaire à transmettre au programme de construction.

  
--curl
    chemin

  
Le programme curl à utiliser pour les opérations réseau.

  
--curl-option
    opt

  
Option supplémentaire à transmettre au programme curl.

  
--pager
    chemin

  
Le programme de pagination à utiliser pour afficher le texte long.

  
--pager-option
    opt

  
Option supplémentaire à transmettre au programme de pagination.

  
--options-file
    fichier

  
Lire des options supplémentaires à partir de fichier.

  
--default-options
    rép

  
Le répertoire à partir duquel charger des fichiers d'options par défaut supplémentaires.

  
--no-default-options

  
Ne pas charger les fichiers d'options par défaut.








FICHIERS   D'OPTIONS   PAR   DÉFAUT


Voir bdep-default-options-files(1) pour un aperçu des
    fichiers d'options par défaut. Pour la commande ci , le répertoire de départ de la recherche
    est le répertoire du projet. Les fichiers d'options suivants sont recherchés dans
    chaque répertoire et, s'ils sont trouvés, chargés dans l'ordre indiqué :


bdep.options
bdep-ci.options


Les options de commande ci suivantes ne peuvent pas être spécifiées dans les
    fichiers d'options par défaut :


--directory|-d
