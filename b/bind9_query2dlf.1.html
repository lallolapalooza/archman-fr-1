NOM

bind9_query2dlf - convertir les journaux de requêtes BIND9 en dlf

SYNTAXE

bind9_query2dlf

DESCRIPTION

bind9_query2dlf attend des fichiers de journalisation de requêtes BIND 9 sur l'entrée standard.

Si vous avez un

channel query_logging {
        file "/var/log/named_querylog"
        versions 3 size 100M;
        print-time yes;                 // Horodate les entrées du journal
};

dans votre named.conf, les fichiers journaux produits sont supportés. Optionnellement, vous pourriez ajouter

print-category yes;             // Imprime le nom de la catégorie
print-severity yes;             // Imprime le niveau de sévérité

à ce canal. Les journaux de requêtes tels que produits par un BIND patché (voir NOTES ci-dessous) sont également supportés.

Nous supportons également le fichier journal Bind 9.3 qui utilise un nouveau format de date (15-Jul-2002) au lieu de l'ancien format syslog.

EXEMPLES

Pour traiter un journal produit par bind9 :

$ bind9_query2dlf < dns-query

bind9_query2dlf sera rarement utilisé seul, mais sera plus probablement appelé par lr_log2report :

$ lr_log2report bind9_query < /var/log/dns-query

NOTES

Les versions de Bind9 antérieures à 9.3 ne journalisaient pas si la requête était récursive, par conséquent le dernier champ dlf (DLF_RESOLVER) est un '-'. Cependant, en appliquant ce patch de Wytze van der Raay :

# patch bin/named/query.c pour journaliser l'indication de requête récursive/non-récursive
SRC=bin/named/query.c
if [ -f ${SRC}.org ]
then
        echo "Patched ${SRC} déjà en place"
else
        echo "Patch ${SRC} pour l'indication de requête récursive/non-récursive"
        cp -p ${SRC} ${SRC}.org
        patch -p0 ${SRC} <<\!
--- bin/named/query.c.org       Mon Sep 24 22:57:48 2001
+++ bin/named/query.c   Tue Sep 25 09:55:21 2001
@@ -3272,7 +3272,8 @@
        dns_rdatatype_format(rdataset->type, typename, sizeof(typename));
        ns_client_log(client, NS_LOGCATEGORY_QUERIES, NS_LOGMODULE_QUERY,
-                     level, "query: %s %s %s", namebuf, classname, typename);
+                     level, "query: %s %s %s%s", namebuf, classname, typename,
+                     WANTRECURSION(client) ? "+" : "-");
 }
 void
!
fi

produira des lignes de journal comme

Nov 11 12:06:42.829 queries: info: client 10.0.0.1#3664:
  query: 6.example.com.nl IN A+

Un '+' indique une requête récursive, - indique une requête non récursive, l'absence de + ou - indique un bind9 pré-9.3 non patché. Voir le message de Wytze du Fri, 28 Dec 2001 16:56:30 +0100 sur bind9-workers@isc.org , archivé à http://www.mail-archive.com/bind9-workers@isc.org/msg00501.html .

Ce type de fichiers journaux est reconnu par le script.

BIND 9.3 et versions ultérieures offrent un support complet pour cette fonctionnalité de journalisation. De plus, ils journalisent des informations sur la vue, le signe et EDNS, qui seront toutes ignorées par cette version du script.

Dans une discussion privée le Jeudi 18 Juil 2002 07:55:22 +0200, Wytze a écrit :

Ceci contient la version "compatible ISC" du patch pour obtenir l'enregistrement d'une requête récursive/non-récursive. ISC a décidé qu'il devait y avoir un espace entre le type et l'indicateur de récursion dans le fichier journal, soit.

Si vous souhaitez que votre BIND 9.2.1 journalise dans le style 9.3 compatible ISC, appliquez ce patch à vos sources BIND :

--- bin/named/query.c.org       Thu Mar 28 06:10:09 2002
+++ bin/named/query.c   Wed Jul 17 08:14:41 2002
@@ -3279,7 +3279,8 @@
        dns_rdatatype_format(rdataset->type, typename, sizeof(typename));
        ns_client_log(client, NS_LOGCATEGORY_QUERIES, NS_LOGMODULE_QUERY,
-                     level, "query: %s %s %s", namebuf, classname, typename);
+                     level, "query: %s %s %s %s", namebuf, classname, typename,
+                     WANTRECURSION(client) ? "+" : "-");
 }
 void

. Ce script comprend l'indication de récursivité de style Wytze et de style ISC.
