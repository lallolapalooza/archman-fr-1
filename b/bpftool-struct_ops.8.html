NOM

bpftool-struct_ops - outil pour enregistrer/désenregistrer/introspecter les BPF struct_ops

SYNTAXE

bpftool [OPTIONS] struct_ops COMMANDE

OPTIONS := { { -j | --json } [{ -p | --pretty }] | { -d | --debug } }

COMMANDES := { show | list | dump | register | unregister | help }

COMMANDES STRUCT_OPS

bpftool struct_ops { show | list } [STRUCT_OPS_MAP]
bpftool struct_ops dump [STRUCT_OPS_MAP]
bpftool struct_ops register OBJ [LINK_DIR]
bpftool struct_ops unregister STRUCT_OPS_MAP
bpftool struct_ops help
STRUCT_OPS_MAP := { id STRUCT_OPS_MAP_ID | name STRUCT_OPS_MAP_NAME }
OBJ := /un/fichier/de/bpf_struct_ops.o

DESCRIPTION

bpftool struct_ops { show | list } [STRUCT_OPS_MAP]
Affiche des informations brèves sur les struct_ops dans le système. Si STRUCT_OPS_MAP est spécifié, il affiche des informations uniquement pour le struct_ops donné. Sinon, il liste tous les struct_ops actuellement présents dans le système.

La sortie commencera par l'ID de la map struct_ops, suivi de son nom et du type noyau de son struct_ops.

bpftool struct_ops dump [STRUCT_OPS_MAP]
Affiche des informations détaillées sur les struct_ops dans le système. Si STRUCT_OPS_MAP est spécifié, il affiche des informations uniquement pour le struct_ops donné. Sinon, il affiche tous les struct_ops actuellement présents dans le système.
bpftool struct_ops register OBJ [LINK_DIR]
Enregistre les struct_ops bpf à partir de OBJ. Tous les struct_ops sous la section ELF ".struct_ops" et ".struct_ops.link" seront enregistrés dans leur sous-système noyau respectif. Pour chaque struct_ops dans la section ".struct_ops.link", un lien sera créé. Vous pouvez spécifier LINK_DIR pour fournir un chemin de répertoire où ces liens seront épinglés avec le même nom que leur nom de map correspondant.
bpftool struct_ops unregister STRUCT_OPS_MAP
Désenregistre le STRUCT_OPS_MAP du sous-système noyau.
bpftool struct_ops help
Affiche un court message d'aide.

OPTIONS

-h, --help
Affiche un court message d'aide (similaire à bpftool help).
-V, --version
Affiche le numéro de version de bpftool (similaire à bpftool version), le numéro de version de libbpf utilisée, et les fonctionnalités optionnelles qui ont été incluses lors de la compilation de bpftool. Les fonctionnalités optionnelles incluent la liaison à LLVM ou à libbfd pour fournir le désassembleur pour les programmes JIT-ted (bpftool prog dump jited) et l'utilisation de skeletons BPF (certaines fonctionnalités comme bpftool prog profile ou l'affichage des PIDs associés aux objets BPF peuvent en dépendre).
-j, --json
Génère une sortie JSON. Pour les commandes qui ne peuvent pas produire de JSON, cette option n'a aucun effet.
-p, --pretty
Génère une sortie JSON lisible par l'homme. Implique -j.
-d, --debug
Affiche tous les journaux disponibles, même les informations de niveau débogage. Cela inclut les journaux de libbpf ainsi que ceux du vérificateur, lors de la tentative de chargement des programmes.

EXEMPLES

# bpftool struct_ops show

100: dctcp           tcp_congestion_ops
105: cubic           tcp_congestion_ops

# bpftool struct_ops unregister id 105

Unregistered tcp_congestion_ops cubic id 105

# bpftool struct_ops register bpf_cubic.o

Registered tcp_congestion_ops cubic id 110
