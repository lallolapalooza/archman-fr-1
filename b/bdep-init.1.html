bdep-init - initialiser un projet da

ns des configuratio
ns de construction

SYNOPSI

S

bdep init [options] [pkg-spec] [cfg-spec] [pkg-args]
bdep init [options] [prj-spec] --empty|-E
bdep init [options] [pkg-spec] --config-add|-A cfg-dir [@cfg-name]
[pkg-args]
bdep init [options] [pkg-spec] --config-create|-C cfg-dir [@cfg-name]
[cfg-args] [-- pkg-args

]

cfg-spec = (@cfg-name | --config|-c cfg-dir)... | --all|-a
pkg-spec = (--directory|-d pkg-dir)... | prj-spec
prj-spec = --directory|-d prj-dir
pkg-args = (?pkg | cfg-var)...
cfg-args = [-- [bpkg-options]] [--existing|-e | (module | cfg-var)..

.
]

DESCRIPTIO

N

La commande init initialise un projet dans une ou plusieurs configurations de construction. La première forme initialise les paquets du projet spécifié (pkg-spec), ou, si le projet lui-même est spécifié (prj-spec), tous ses paquets disponibles, dans une ou plusieurs configurations de construction (cfg-spec) qui ont déjà été associées au projet (bdep-config(1))

.

Si aucun répertoire de projet n'est spécifié, le répertoire de travail courant est supposé. Si aucune configuration n'est spécifiée, la configuration par défaut est supposée (échec si plusieurs configurations par défaut sont présentes). Voir bdep-projects-configs(1) pour plus de détails sur la spécification des projets et des configurations. Les pkg-args facultatifs sont les paquets de dépendances supplémentaires et/ou les variables de configuration à passer à la commande sous-jacente bpkg-pkg-bui

ld(1).

La deuxième forme (--empty est spécifiée) initialise une base de données de projet vide qui peut ensuite être utilisée pour d'abord ajouter des configurations de construction (bdep-config(1)) puis initialiser les paquets du projet en utilisant la première

forme.

La troisième (--config-add) et la quatrième (--config-create) formes sont des raccourcis pour d'abord ajouter une configuration de construction existante ou nouvellement créée, puis initialiser les paquets du projet dans cette configuration. Sémantiquement, elles sont équivalentes à effectuer d'abord les commandes config add ou config create (bdep-config(1)), respectivement, suivies de la première forme. Les cfg-args facultatifs dans la quatrième forme sont les arguments supplémentaires pour la commande sous-jacente bpkg-cfg-create(1). Notez que dans ce cas, pour spécifier pkg-args sans spécifier cfg-args, vous devez utiliser deux séparateurs --, par exemple

: 
$ bdep init -C ../prj-gcc @gcc -- -- ?sys:
libsqlite3/*

Les variables de configuration peuvent être spécifiées pour ne s'appliquer qu'à des paquets spécifiques dans pkg-args en utilisant le mécanisme de regroupement d'arguments (bdep-argument-grouping(1)). De plus, ces paquets peuvent être placés dans des configurations liées spécifiques en spécifiant la configuration avec l'une des options --config* (ou la notation @) en utilisant le même mécanisme de regroupement. Par exemple (en supposant que gcc est lié à common)

: 
$ bdep init @gcc { @co
mmon config.liblarge.e
xtra=true }+ ?liblarge

EXEMPLE

S

Par exemple, considérons le projet prj avec deux paquets, foo et libfo

o : 
prj/
|-- foo/
`--
libfoo/

Les invocations suivantes illustrent les cas d'utilisation courants de init (le répertoire de travail courant est affiché avant l'invite du shell)

.

Créer une nouvelle configuration de construction dans ../prj-gcc, l'appeler gcc, et initialiser les paquets du projet foo et libfoo dans cette configuration

: 
prj/$ bdep init -C ../prj-gcc @gcc cc config.
cxx=g++

Créer une nouvelle configuration de construction dans ../prj-clang en utilisant bpkg-cfg-create(1). Puis l'ajouter en l'appelant clang et initialiser le paquet du projet foo dans cette configuration

: 
prj/$ bpkg create -d ../prj-clang cc config.cxx=clang++
prj/$ cd foo
foo/$ bdep init -A ../../prj-clang
@clang

Initialiser le paquet du projet libfoo dans la configuration de construction clang

: 
foo/$ cd ..
prj/$ bdep init -d libfoo
@clang

L'ensemble d'invocations suivant obtient le même résultat final mais en utilisant la commande bdep-config(1) pour gérer la

configuration.

Initialiser une base de données de projet vide

: 
prj/$ bdep init
--empty

Créer une nouvelle configuration de construction dans ../prj-gcc, l'appeler gcc

: 
prj/$ bdep config create ../prj-gcc @gcc cc config.
cxx=g++

Ajouter une configuration de construction existante dans ../prj-clang, l'appeler clang

. 
prj/$ bdep config add ../prj-clang
@clang

Initialiser les paquets du projet foo et libfoo dans les configurations de construction gcc et clang

. 
prj/$ bdep init @gcc
@clang

Ou, alternativement, dans toutes les configurations de construction

: 
prj/$
bdep i
nit -a

NAME

bdep-init - Initialize a build2 configuration

SYNOPSIS

bdep-init [OPTIONS] [dir]

DESCRIPTION

Initializes a new bpkg configuration. This command can be used to initialize a new build system configuration for a project (that is not yet managed by bpkg) or to add a new configuration to an existing project.

If dir is not specified, the current directory is assumed. If the project at dir is not yet managed by bpkg, it is initialized. Otherwise, a new configuration is added.

The command may create new files in the project directory, such as a buildfile, a configure.ac (for Autotools), or a CMakeLists.txt. It may also fetch dependencies if they are specified in the configuration.

EXAMPLES

1.
Initialize a new project in the current directory with default settings:
~/myproject $ bdep init
2.
Initialize a new project in ~/myproject:
$ bdep init ~/myproject
3.
Add a new configuration to the existing project in the current directory:
$ bdep init -C
4.
Add a new configuration to the existing project in ~/myproject:
$ bdep init -C ~/myproject
5.
Initialize a new project in the current directory and add a new configuration to it:
$ bdep init -C

INIT OPTIONS

The following options are specific to the init command:

--config-add|-A
Add a new configuration to an existing project.
--config-create|-C
Create a new configuration.
--config-edit|-E
Edit an existing configuration. This invokes the configured editor (see bdep-common-options(1)) with the configuration's buildfile.
--build-system|-s name
Specify the build system to use for the new configuration. Supported systems include make, ninja, cmake, autotools, xcode, and vs. If not specified, the build system is autodetected.
--compiler|-x path
Specify the compiler to use for the new configuration.
--linker|-l path
Specify the linker to use for the new configuration.
--cflags flags
Specify C compiler flags.
--cxxflags flags
Specify C++ compiler flags.
--ldflags flags
Specify linker flags.
--make path
The make program to be used. This is relevant for systems using make as their build system.
--make-option opt
Additional option to be passed to the make program.
--ninja path
The ninja program to be used. This is relevant for systems using ninja as their build system.
--ninja-option opt
Additional option to be passed to the ninja program.
--cmake path
The cmake program to be used. This is relevant for systems using cmake as their build system.
--cmake-option opt
Additional option to be passed to the cmake program.
--autotools path
The autotools script to be used. This is relevant for systems using autotools as their build system.
--autotools-option opt
Additional option to be passed to the autotools script.
--sync|-S
Synchronize the configuration after it is created. This is useful for fetching dependencies. See also bdep-sync(1) for details.
--type|--config-type typ
The type of the configuration being created. By default, configuration of type target is created. See bpkg-cfg-create(1) for background on configuration types.
--default
Make the added or created configuration the default.
--no-default
Don't make the first added or created configuration the default.
--forward
Make the added or created configuration forwarded.
--no-forward
Don't make the added or created configuration forwarded.
--auto-sync
Make the added or created configuration automatically synchronized.
--no-auto-sync
Don't make the added or created configuration automatically synchronized.
--existing|-e
Initialize a bpkg configuration based on an existing build system configuration.
--wipe
Wipe the configuration directory clean before creating the new configuration.
--all|-a
Use all build configurations.
--config|-c dir
Specify the build configuration as a directory.
--directory|-d dir
Assume project/package is in the specified directory rather than in the current working directory.
--config-name|-n name
Specify the build configuration as a name.
--config-id num
Specify the build configuration as an id.

DEFAULT OPTIONS FILES

See bdep-default-options-files(1) for an overview of the default options files. For the init command the search start directory is the project directory. The following options files are searched for in each directory and, if found, loaded in the order listed:

bdep.options
bdep-{config config-add}.options                # if --config-add|-A
bdep-{config config-add config-create}.options  # if --config-create|-C
bdep-init.options

The following init command options cannot be specified in the default options files:

--directory|-d
--config-add|-A
--config-create|-C
--wipe
