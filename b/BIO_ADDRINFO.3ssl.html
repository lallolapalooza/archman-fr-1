NOM

BIO_lookup_type, BIO_ADDRINFO, BIO_ADDRINFO_next, BIO_ADDRINFO_free, BIO_ADDRINFO_family, BIO_ADDRINFO_socktype, BIO_ADDRINFO_protocol, BIO_ADDRINFO_address, BIO_lookup_ex, BIO_lookup - Type BIO_ADDRINFO et routines

SYNTAXE

#include <sys/types.h>
#include <openssl/bio.h>
typedef union bio_addrinfo_st BIO_ADDRINFO;
enum BIO_lookup_type {
    BIO_LOOKUP_CLIENT, BIO_LOOKUP_SERVER
};
int BIO_lookup_ex(const char *host, const char *service, int lookup_type,
                  int family, int socktype, int protocol, BIO_ADDRINFO **res);
int BIO_lookup(const char *host, const char *service,
               enum BIO_lookup_type lookup_type,
               int family, int socktype, BIO_ADDRINFO **res);
const BIO_ADDRINFO *BIO_ADDRINFO_next(const BIO_ADDRINFO *bai);
int BIO_ADDRINFO_family(const BIO_ADDRINFO *bai);
int BIO_ADDRINFO_socktype(const BIO_ADDRINFO *bai);
int BIO_ADDRINFO_protocol(const BIO_ADDRINFO *bai);
const BIO_ADDR *BIO_ADDRINFO_address(const BIO_ADDRINFO *bai);
void BIO_ADDRINFO_free(BIO_ADDRINFO *bai);

DESCRIPTION

Le type BIO_ADDRINFO est un wrapper pour les types d'informations d'adresse fournis sur votre plateforme.

BIO_ADDRINFO forme normalement une chaîne de plusieurs éléments qui peuvent être sélectionnés un par un.

BIO_lookup_ex() recherche un host et un service spécifiés, et utilise lookup_type pour déterminer quelle doit être l'adresse par défaut si host est NULL. family, socktype et protocol sont utilisés pour déterminer quelle famille de protocole, quel type de socket et quel protocole doivent être utilisés pour la recherche. family peut être l'un de AF_INET, AF_INET6, AF_UNIX et AF_UNSPEC. socktype peut être SOCK_STREAM, SOCK_DGRAM ou 0. La spécification de 0 indique que tout type peut être utilisé. protocol spécifie un protocole tel que IPPROTO_TCP, IPPROTO_UDP ou IPPORTO_SCTP. S'il est défini sur 0, tout protocole peut être utilisé. res pointe vers un pointeur destiné à contenir le début d'une chaîne BIO_ADDRINFO.

Pour la famille AF_UNIX, BIO_lookup_ex() ignorera le paramètre service et attendra que le paramètre host contienne le chemin vers le fichier de socket.

BIO_lookup() fait la même chose que BIO_lookup_ex() mais ne fournit pas la possibilité de sélectionner en fonction du protocole (tout protocole peut être retourné).

BIO_ADDRINFO_family() renvoie la famille du BIO_ADDRINFO donné. Le résultat sera l'une des constantes AF_INET, AF_INET6 et AF_UNIX.

BIO_ADDRINFO_socktype() renvoie le type de socket du BIO_ADDRINFO donné. Le résultat sera l'une des constantes SOCK_STREAM et SOCK_DGRAM.

BIO_ADDRINFO_protocol() renvoie l'identifiant du protocole du BIO_ADDRINFO donné. Le résultat sera l'une des constantes IPPROTO_TCP et IPPROTO_UDP.

BIO_ADDRINFO_address() renvoie le BIO_ADDR sous-jacent du BIO_ADDRINFO donné.

BIO_ADDRINFO_next() renvoie le prochain BIO_ADDRINFO de la chaîne à partir de celui donné.

BIO_ADDRINFO_free() libère la chaîne de BIO_ADDRINFO à partir de celui donné. Si l'argument est NULL, rien n'est fait.

VALEURS DE RETOUR

BIO_lookup_ex() et BIO_lookup() renvoient 1 en cas de succès et 0 en cas d'erreur, et laisseront une indication d'erreur sur la pile d'erreurs OpenSSL dans ce cas.

Toutes les autres fonctions décrites ici renvoient 0 ou NULL lorsque les informations qu'elles sont censées retourner ne sont pas disponibles.

NOTES

L'implémentation de BIO_lookup_ex() utilise la fonction getaddrinfo() fournie par la plateforme. Sous Linux, on sait que la spécification de 0 pour le protocole ne renverra aucune adresse basée sur SCTP lors de l'appel à getaddrinfo(). Par conséquent, si une adresse SCTP est requise, le paramètre protocol de BIO_lookup_ex() doit être explicitement défini sur IPPROTO_SCTP. Il en va de même sur d'autres plateformes.

HISTORIQUE

La fonction BIO_lookup_ex() a été ajoutée dans OpenSSL 1.1.1.
