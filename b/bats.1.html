DESCRIPTIO

N

Bats est un framework de test conforme à TAP pour Bash. Il fournit une manière simple de vérifier que les programmes UNIX que vous écrivez se comportent comme

prévu.

Un fichier de test Bats est un script Bash avec une syntaxe spéciale pour définir des cas de test. En interne, chaque cas de test n'est qu'une fonction avec une

description.

Les cas de test consistent en commandes shell standard. Bats utilise l'option errexit de Bash ( errexit (set -e) lors de l'exécution des cas de test. Si chaque commande du cas de test se termine avec un code de statut 0 (succès), le test passe. De cette manière, chaque ligne est une assertion de

vérité.

Voir bats(7) pour plus d'information

s sur l'écritur
e de tests Bats.

EXÉCUTION DES

TESTS

Pour exécuter vos tests, invoquez l'interpréteur bats avec un chemin vers un fichier de test. Les cas de test du fichier sont exécutés séquentiellement et en isolation. Si tous les cas de test passent, bats se termine avec un code de statut 0 . S'il y a des échecs, bats se termine avec un code de statut 1

.

Vous pouvez invoquer l'interpréteur bats avec plusieurs arguments de fichiers de test, ou avec un chemin vers un répertoire contenant plusieurs fichiers .bats . Bats exécutera chaque fichier de test individuellement et agrégera les résultats. Si un cas de test échoue, bats se termine avec un code de

statu
t 1.

FILTRAGE DES

TESTS

Il existe plusieurs mécanismes pour filtrer quels tests exécuter

:
○
--filter <regex> pour filtrer par nom de
test
○
--filter-status <status> pour filtrer par le statut du test lors de la dernière
exécution
○
--filter-tags <tag-list> pour filtrer par les tags d'un
test

--FILTER-TAGS <var>

TAG-LIST</var>

Les tags peuvent être utilisés pour un filtrage fin de quels tests exécuter via --filter-tags. Cela accepte une liste de tags séparés par des virgules. Seuls les tests qui correspondent à tous ces tags seront exécutés. Par exemple, bats --filter-tags a,b,c sélectionnera les tests avec les tags a,b,c, mais pas les tests qui manquent un ou plusieurs de ces

tags.

De plus, vous pouvez spécifier des tags négatifs via bats --filter-tags a,!b,c, qui ne correspondra pas aux tests avec les tags a,b,c, en raison du b, mais sélectionnera a,c. De manière plus formelle, --filter-tags est une conjonction

booléenne.

Pour permettre des requêtes plus complexes, vous pouvez spécifier plusieurs --filter-tags. Un test sera exécuté s'il correspond à au moins l'un d'entre eux. Cela signifie que plusieurs --filter-tags forment une disjonction

booléenne.

Une requête --filter-tags a,!b --filter-tags b,c peut être traduite par : Exécuter uniquement les tests qui (ont le tag a, mais pas le tag b) ou (ont le tag b et c)

.

Une liste de tags

vide correspond au
x tests sans tags.

SORTI

E

Lorsque vous exécutez Bats depuis un terminal, vous verrez la sortie au fur et à mesure que chaque test est effectué, avec une coche à côté du nom du test s'il passe ou un "X" s'il

échoue. 
$ bats addition.bats
 ✓ add
ition using bc ✓ addition u
sing dc 2 tests, 0 failures

Si Bats n'est pas connecté à un terminal--en d'autres termes, si vous l'exécutez depuis un système d'intégration continue ou redirigez sa sortie vers un fichier--les résultats sont affichés au format TAP lisible par l'homme et analysable par la machine. Vous pouvez forcer la sortie TAP depuis un terminal en invoquant Bats avec l' option --

tap. 
$ bats --tap addition.bats
1..2
ok 1 addition using bc
ok 2 addition
using
dc
