NOM

Biber - module principal pour biber, un remplacement de bibtex pour les utilisateurs de biblatex

SYNOPSIS

use Biber;
my $biber = Biber->new();
$biber->parse_ctrlfile("example.bcf");
$biber->prepare;

create_uniquename_info

Rassembler les informations uniquename lors de l'examen des noms
Ce qui se passe ici est le suivant : nous enregistrons le
nombre d'occurrences de chaque nom, nom+init et nom complet dans un
contexte spécifique. Par exemple, le contexte est « global » avec uniquename
< mininit et « liste de noms » pour uniquename=mininit ou minfull. Les clés
que nous stockons pour compter cela sont les informations les plus spécifiques pour le
contexte, donc, pour uniquename < mininit, c'est le nom complet et pour
uniquename=mininit ou minfull, c'est la liste complète des noms complets.
Ces clés ont des valeurs dans un hachage qui sont ignorées. Elles servent seulement à
accumuler les occurrences répétées avec le contexte et nous ne nous soucions pas
de cela et donc les valeurs sont un réceptacle utile pour une telle répétition.
Par exemple, si nous trouvons dans le contexte global un nom de base « Smith » dans deux entrées différentes
sous la même forme « Alan Smith », la structure de données ressemblera à :
{Smith}->{global}->{Alan Smith} = 2
Nous ne nous soucions pas de la valeur car cela signifie qu'il y a 2 « Alan Smith » dans le contexte global
qui nécessitent d'être désambiguïsés de la même manière de toute façon. Donc, nous comptons simplement les clés pour le
nom de base « Smith » dans le contexte global pour voir à quel point le nom de base lui-même est ambigu. Cela
serait « 1 » et donc « Alan Smith » recevrait uniquename=false car il est non ambigu comme simplement
« Smith ».
La même chose vaut pour la désambiguïsation du contexte de liste « minimal » pour uniquename=mininit ou minfull.
Par exemple, si nous avions le nom de base « Smith » à désambiguïsé dans deux entrées avec labelname
« John Smith and Alan Jones », la structure de données ressemblerait à :
{Smith}->{Smith+Jones}->{John Smith+Alan Jones} = 2
Encore une fois, le comptage des clés du contexte pour le nom de base nous donne « 1 » ce qui signifie que nous
avons uniquename=false pour « John Smith » dans les deux entrées car c'est la même liste. Cela fonctionne aussi
pour les noms répétés dans la même liste « John Smith and Bert Smith ». Désambiguïsation
de « Smith » dans ceci :
{Smith}->{Smith+Smith}->{John Smith+Bert Smith} = 2
Donc à la fois « John Smith » et « Bert Smith » dans cette entrée reçoivent
uniquename=false (bien sûr, tant qu'il n'y a pas d'autres entrées « X Smith and
Y Smith » où X != « John » ou Y != « Bert »).
Les valeurs de biblatex.sty :
false   = 0
init    = 1
true    = 2
full    = 2
allinit = 3
allfull = 4
mininit = 5
minfull = 6

Prétraitement des options. Utilisé principalement pour effectuer des opérations gourmandes en traitement

Faire le travail principal.
Traiter et trier toutes les entrées avant d'écrire la sortie.

Faire le travail principal pour le mode outil

fetch_data

Récupérer les données de citekey et de dépendants à partir des sources de données de section
S'attend à trouver des paquets de source de données nommés :
Biber::Input::<type>::<datatype>
et une sous-routine définie appelée :
Biber::Input::<type>::<datatype>::extract_entries
qui prend comme arguments :
1 : Objet Biber
2 : Nom de la source de données
3 : Référence vers un tableau de clés de citation à rechercher
et renvoie un tableau des clés de citation qu'elle n'a pas trouvées dans la source de données

get_dependents

Obtenir les dépendants des entrées pour une liste donnée de clés de citation. Est appelé récursivement
jusqu'à ce qu'il n'y ait plus de dépendants à rechercher.
