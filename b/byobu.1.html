NOM

byobu - script d'encapsulation pour initialiser la configuration byobu d'un utilisateur et lancer un gestionnaire de fenêtres basé sur du texte (screen ou tmux)

SYNTAXE

byobu [options]

byobu-screen [options de screen]

byobu-tmux [options de tmux]

Les options de byobu sont simplement transmises à screen(1) ou tmux(1).

DESCRIPTION

byobu est un script qui lance un gestionnaire de fenêtres basé sur du texte (soit screen(1) soit tmux(1)) dans la configuration byobu. Cela permet l'affichage des informations système et des notifications d'état dans deux lignes en bas de la session écran. Il permet également des sessions terminales multiples avec onglets, accessibles par de simples combinaisons de touches.

byobu utilise par défaut tmux(1) (si présent) comme backend, mais cela peut être modifié avec l'utilitaire byobu-select-backend(1).

Notez que BYOBU_CONFIG_DIR est défini à $XDG_CONFIG_HOME/byobu si cette variable est définie, et $HOME/.byobu sinon.

COULEURS DE FOND

Les couleurs de fond des lignes de statut de byobu peuvent être ajustées en éditant les fichiers $HOME/.byobu/color (pour byobu-screen) et $HOME/.byobu/color.tmux (pour byobu-tmux). La combinaison de touches Ctrl-Shift-F5 changera la couleur de fond pour une couleur sélectionnée aléatoirement lorsque vous êtes en mode byobu-tmux. Supprimez simplement ces fichiers pour revenir à la configuration de couleur par défaut.

NOTIFICATIONS D'ÉTAT

byobu prend en charge un certain nombre de notifications d'état uniques et intéressantes sur les deux dernières lignes de l'écran. Chaque élément de notification d'état est configurable indépendamment, activé et désactivé par l'utilitaire de configuration. Le guide ci-dessous aide à identifier chaque élément d'état (par ordre alphabétique) :

apport - symbole affiché s'il y a des rapports de crash en attente ; symbole {!} affiché sur la barre inférieure vers la gauche, en noir sur fond orange

arch - architecture du système ; affichée sur la barre inférieure vers la gauche, dans la couleur de texte par défaut sur la couleur de fond par défaut

battery - informations sur la batterie ; affichées sur la barre inférieure vers la droite ; - indique la décharge, + indique la charge, = indique la charge complète ; lors de la charge ou de la décharge, la capacité actuelle de la batterie en pourcentage est affichée ; les couleurs verte, jaune et rouge sont utilisées pour indiquer davantage l'état de charge de la batterie ; vous pouvez remplacer la batterie détectée en définissant BATTERY=/proc/acpi/battery/BAT0 dans $BYOBU_CONFIG_DIR/statusrc

cpu_count - le nombre de processeurs ou de cœurs sur le système ; affiché dans la barre inférieure vers la droite dans la couleur de texte par défaut sur le fond par défaut, suivi d'un 'x'

cpu_freq - la fréquence actuelle du processeur en GHz ; affichée dans la barre inférieure vers la droite en texte blanc sur fond bleu clair

cpu_temp - la température du processeur en Celsius (défaut) ou Fahrenheit, configurez TEMP=F ou TEMP=C dans $BYOBU_CONFIG_DIR/statusrc ; affichée dans la barre inférieure vers la droite en texte jaune sur fond noir ; vous pouvez remplacer le périphérique de température du processeur détecté en définissant MONITORED_TEMP=/proc/acpi/whatever dans $BYOBU_CONFIG_DIR/statusrc

custom - scripts personnalisés définis par l'utilisateur ; doivent être des programmes exécutables de quelque type que ce soit dans $BYOBU_CONFIG_DIR/bin ; doivent être nommés N_NAME, où N est la fréquence en secondes pour actualiser l'indicateur d'état, et NAME est le nom du script ; N ne doit pas être inférieur à 5 secondes ; le script doit afficher une petite quantité de texte sur la sortie standard, la sortie d'erreur est ignorée ; l'indicateur sera affiché dans le panneau inférieur, dans les couleurs par défaut, sauf si vous spécifiez manuellement les couleurs dans la sortie de votre script ; ATTENTION, les scripts personnalisés gourmands en CPU peuvent avoir un impact sur les performances globales de votre système et pourraient indisposer votre administrateur système ! En fait, vous pouvez facilement copier et modifier n'importe quel script d'état se trouvant habituellement dans /usr/lib/byobu/* vers votre répertoire local $HOME/.byobu/.
Exemple : $BYOBU_CONFIG_DIR/bin/1000_uname
#!/bin/sh
printf "\005{= bw}%s\005{-}" "$(uname -r)"

date - la date du système au format YYYY-MM-DD, ou vous pouvez le définir sur n'importe quelle chaîne strftime(3) valide que vous aimez dans $BYOBU_CONFIG_DIR/datetime ; affichée dans la barre inférieure à l'extrême droite dans la couleur de texte par défaut sur le fond par défaut

disk - espace disque total disponible et total utilisé sur le répertoire / ; affiché dans la barre inférieure à l'extrême droite en texte blanc sur fond violet clair ; remplacez le répertoire par défaut en spécifiant un point de montage alternatif avec MONITORED_DISK=/wherever dans $BYOBU_CONFIG_DIR/statusrc

disk_io - débit de lecture/écriture instantané en ko/s ou Mo/s sur les 3 dernières secondes ; affiché dans la barre inférieure vers la droite en texte blanc sur fond violet clair avec un signe '<' indiquant la 'vitesse de lecture' et un signe '>' indiquant la 'vitesse d'écriture' ; remplacez le disque surveillé par défaut en spécifiant un périphérique alternatif avec MONITORED_DISK=/dev/sdb, et remplacez le seuil DISK_IO_THRESHOLD=50 (ko/s) par défaut dans $BYOBU_CONFIG_DIR/statusrc

distro - nom de l'OS/distribution de la version en cours d'exécution sur le système actuel tel que rapporté par lsb_release(1) ou /etc/issue ; affiché dans la barre inférieure en texte noir gras vers la gauche sur fond gris ; vous pouvez remplacer la version détectée par DISTRO=Whatever dans $BYOBU_CONFIG_DIR/statusrc

entropy - un décompte de l'entropie actuelle du système en octets ; affiché dans la barre inférieure vers la droite en texte jaune sur fond gris foncé ; il y a un 'e' initial pour indiquer 'entropie'

raid - note très proéminemment s'il y a une défaillance RAID détectée, en texte clignotant rouge sur fond blanc ; le terme 'RAID' indique qu'il y a un problème avec le RAID, et s'il y a une reconstruction/resynchronisation en cours, le pourcentage d'achèvement est également affiché

fan_speed - vitesse du ventilateur du CPU ou du système telle que rapportée par lm-sensors ; affichée dans la barre inférieure vers la droite en texte noir sur fond gris ; il y a un 'rpm' à la fin pour les unités ; vous pouvez remplacer le ventilateur détecté en définissant FAN=/sys/path/to/your/fan1_input dans $BYOBU_CONFIG_DIR/statusrc

hostname - le nom d'hôte du système ; affiché dans la barre supérieure à l'extrême droite en texte noir gras sur fond gris ; il y a un symbole '@' initial si le statut du nom d'utilisateur est également activé

ip_address - l'adresse IPv4 du système en notation décimale pointée ; affichée dans la barre supérieure à l'extrême droite en texte noir gras sur fond gris ; vous pouvez remplacer et afficher votre adresse IPv6 en définissant 'IPV6=1', et vous pouvez afficher votre adresse IP externe en définissant 'IP_EXTERNAL=1' dans $BYOBU_CONFIG_DIR/statusrc

ip_address4 - l'adresse IPv4 du système en notation décimale pointée ; affichée dans la barre supérieure à l'extrême droite en texte noir gras sur fond gris ; vous pouvez afficher votre adresse IP externe en définissant 'IP_EXTERNAL=1' dans $BYOBU_CONFIG_DIR/statusrc

ip_address6 - l'adresse IPv6 du système ; affichée dans la barre supérieure à l'extrême droite en texte noir gras sur fond gris ; vous pouvez afficher votre adresse IP externe en définissant 'IP_EXTERNAL=1' dans $BYOBU_CONFIG_DIR/statusrc

load_average - la moyenne de charge du système sur la dernière minute ; affichée dans la barre inférieure vers la droite en texte noir sur fond jaune

logo - une approximation du logo du système d'exploitation actuel ; affiché dans la barre inférieure à l'extrême gauche ; vous pouvez personnaliser ce logo en définissant un logo choisi avec LOGO=:-D dans $BYOBU_CONFIG_DIR/statusrc

mail - courrier système pour l'utilisateur actuel ; la lettre '[M]' est affichée dans la barre inférieure vers la gauche en texte noir sur fond gris

memory - mémoire totale disponible et pourcentage utilisé dans le système ; affiché dans la barre inférieure vers la droite en texte blanc sur fond vert

menu - un simple indicateur dirigeant les nouveaux utilisateurs à utiliser la combinaison de touches F9 pour accéder au menu byobu

network - bande passante instantanée en upload/download en [GMk]bps sur les 3 dernières secondes ; rien n'est affiché si le trafic est de 0 ; affiché dans la barre inférieure vers la gauche

WINDOW

S

Chaque fenêtre ouverte dans la session screen est affichée dans la barre supérieure vers l'extrême gauche. Elles sont numérotées et incluent des indicateurs d'activité dans la fenêtre (voir "activity" dans screen(1) et tmux(1) pour les définitions des symboles). La fenêtre active actuelle est mise en évidence en inversant le fond/texte du reste de la barre de

fenêtre.

Les utilisateurs peuvent créer une liste de fenêtres à lancer au démarrage dans $BYOBU_CONFIG_DIR/windows et $BYOBU_CONFIG_DIR/windows.tmux. Ce fichier utilise la même syntaxe que ~/.screenrc et ~/.tmuxrc, chaque ligne spécifiant une fenêtre, comme décrit dans screen(1) ou tmux(

1).

L'utilisateur peut également lancer Byobu avec des ensembles de fenêtres uniques. Les utilisateurs peuvent les stocker en tant que $BYOBU_CONFIG_DIR/windows.[NOM] et $BYOBU_CONFIG_DIR/windows.tmux.[NOM], et lancer Byobu avec la variable d'environnement BYOBU_WINDOWS=NOM

.

Par exemple :
$ cat $BYOBU_CONFIG_DIR/windows.ssh_sessions
screen -t localhost bash
screen -t aussie ssh root@aussie
screen -t beagle ssh root@beagle
screen -t collie ssh

root@collie

Puis :
$ BYOBU_WINDOWS=ssh_sessions

byobu

MODES DÉFILEMENT, COPIE,

COLLAGE

Chaque fenêtre dans Byobu a jusqu'à 10 000 lignes d'historique de défilement, que vous pouvez parcourir et naviguer en utilisant les touches alt-pgup et alt-pgdn. Quittez ce mode de défilement en appuyant sur entrée. Vous pouvez également facilement copier et coller du texte depuis le mode défilement. Pour ce faire, entrez en mode défilement en utilisant alt-pgup ou alt-pgdn, appuyez sur la barre d'espace pour commencer à surligner le texte, utilisez haut/bas/gauche/droite/pgup/pgdn pour sélectionner le texte, et appuyez sur entrée pour copier le texte. Vous pouvez ensuite coller le texte en utilisant alt-insert ou ctrl

BOGUE

S

Pour que les couleurs de Byobu fonctionnent correctement, les anciennes versions de GNU Screen nécessitent un patch d'une ligne pour ajuster MAX_WINMSG_REND dans screen.c. Le changement est dans le système de contrôle de source amont de GNU Screen depuis le 2010-01-26, mais GNU Screen n'a pas publié de nouvelle version amont depuis plusieurs années. Vous pouvez désactiver complètement les couleurs en définissant MONOCHROME=1 dans $BYOBU_CONFIG_DIR/statusrc. Pour plus d'informations, voir :
* http://savannah.gnu.org/bugs/?

22146

Des utilisateurs de PuTTY ont signalé que les touches de raccourci F2, F3 et F4 ne fonctionnent pas correctement. PuTTY envoie les mêmes séquences d'échappement que la console linux pour F1-F4 par défaut. Vous pouvez corriger ce problème dans la configuration de PuTTY, Terminal -> Keyboard -> Function keys: Xterm R6. Voir : http://www.mail-archive.com/screen-users@gnu.org/msg01525.

html

Les utilisateurs de PuTTY devraient configurer l'activation des caractères UTF-8 afin de corriger les problèmes de rafraîchissement de l'état. Vous pouvez corriger ce problème dans la configuration de PuTTY, Window -> Traduction : sélectionner

UTF-8.

Les utilisateurs de PuTTY devraient éviter de redimensionner leur fenêtre à une hauteur d'un caractère, car cela peut parfois faire planter byobu-screen

.

Les utilisateurs du terminal Apple Mac OSX ont signalé un « texte clignotant ». Vous pouvez corriger cela dans les paramètres avancés de l'application de terminal, avec « Declare Terminal As: xterm-color »

.

Les utilisateurs du clavier Apple Mac peuvent avoir besoin de spécifier un terminal vt100 en ajoutant ceci à votre profil OSX, afin que les touches de fonction et les couleurs de Byobu fonctionnent :
alias ssh='TERM=vt100

ssh'

Les utilisateurs d'une locale non-UTF-8 (comme cs_CZ charset ISO-8859-2), peuvent avoir besoin d'ajouter « defutf8 off » à ~/.screenrc, si certains caractères s'affichent comme « ? »

.

Les utilisateurs qui personnalisent leur invite PS1 doivent placer ce paramètre dans ~/.bashrc, plutôt que dans ~/.profile, afin qu'il fonctionne correctement avec

Byobu.

Si vous exécutez byobu(1) sous sudo(8), vous devez utiliser l'option -H, de sorte que la variable d'environnement du répertoire $HOME de l'utilisateur soit définie correctement. Sinon, byobu(1) créera un tas de répertoires dans le $HOME de $SUDO_USER, mais ils appartiendront à root. Pour éviter que cela ne se produise, byobu(1) refusera simplement de s'exécuter si $USER ne possède pas

$HOME.

Byobu nécessite des valeurs ulimit(3) appropriées pour s'exécuter. Si vous obtenez une erreur au démarrage disant « pipe: too many open files », vérifiez vos valeurs ulimit -a, car vos « open files » ou « max user processes » sont trop bas. Dans ce cas, vous devrez probablement exécuter simplement screen(

1
