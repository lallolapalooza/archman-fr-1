SPI_CURSOR_PARSE_OPEN(3) Documentation PostgreSQL 18.1 SPI_CURSOR_PARSE_OPEN(3)

NOM

SPI_cursor_parse_open - configurer un curseur à l'aide d'une chaîne de requête et de paramètres

SYNOPIS

Portal SPI_cursor_parse_open(const char *name,
                             const char *command,
                             const SPIParseOpenOptions * options)

DESCRIPTION

SPI_cursor_parse_open configure un curseur (en interne, un portail) qui exécutera la chaîne de requête spécifiée. Ceci est comparable à SPI_prepare_cursor suivi de SPI_cursor_open_with_paramlist, sauf que les références aux paramètres dans la chaîne de requête sont traitées entièrement en fournissant un objet ParamListInfo.

Pour une exécution de requête unique, cette fonction doit être préférée à SPI_prepare_cursor suivi de SPI_cursor_open_with_paramlist. Si la même commande doit être exécutée avec de nombreux paramètres différents, l'une ou l'autre méthode peut être plus rapide, en fonction du coût de la replanification par rapport à l'avantage des plans personnalisés.

L'objet options->params devrait normalement marquer chaque paramètre avec le drapeau PARAM_FLAG_CONST, car un plan unique est toujours utilisé pour la requête.

Les données de paramètres passées seront copiées dans le portail du curseur, elles pourront donc être libérées tant que le curseur existe toujours.

ARGUMENTS

const char * name

nom du portail, ou NULL pour laisser le système choisir un nom

const char * command

chaîne de commande

const SPIParseOpenOptions * options

structure contenant des arguments optionnels

Les appelants doivent toujours initialiser à zéro toute la structure options, puis remplir les champs qu'ils souhaitent définir. Cela garantit la compatibilité ascendante du code, car tous les champs qui seront ajoutés à la structure dans le futur seront définis pour se comporter de manière rétrocompatible s'ils sont à zéro. Les champs options actuellement disponibles sont :

ParamListInfo params

structure de données contenant les types et valeurs des paramètres de la requête ; NULL s'il n'y en a pas

int cursorOptions

masque de bits entier des options du curseur ; zéro produit le comportement par défaut

bool read_only

true pour une exécution en lecture seule

VALEUR DE RETOUR

Pointeur vers le portail contenant le curseur. Notez qu'il n'y a pas de convention de retour d'erreur ; toute erreur sera signalée via elog.
