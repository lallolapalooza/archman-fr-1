DESCRIPTION

Ces macros définissent des structures de données pour différents types d'arbres : arbres splay et arbres rouge-noir.

Dans les définitions de macros, TYPE est le nom d'une structure définie par l'utilisateur qui doit contenir un champ nommé FIELD, de type SPLAY_ENTRY ou RB_ENTRY. L'argument HEADNAME est le nom d'une structure définie par l'utilisateur qui doit être déclarée en utilisant les macros SPLAY_HEAD() ou RB_HEAD(). L'argument NAME doit être un préfixe de nom unique pour chaque arbre défini.

Les prototypes de fonctions sont déclarés avec SPLAY_PROTOTYPE, RB_PROTOTYPE, ou RB_PROTOTYPE_STATIC. Les corps des fonctions sont générés avec SPLAY_GENERATE, RB_GENERATE, ou RB_GENERATE_STATIC. Voir les exemples ci-dessous pour plus d'explications sur l'utilisation de ces macros.

ARbres SPLAY

Un arbre splay est une structure de données auto-organisée. Chaque opération sur l'arbre provoque un splay. Le splay déplace le nœud demandé vers la racine de l'arbre et le rééquilibre partiellement.

Cela a l'avantage que la localité des requêtes entraîne des recherches plus rapides car les nœuds demandés se déplacent vers le haut de l'arbre. D'un autre côté, chaque recherche entraîne des écritures en mémoire.

Le Théorème d'Équilibrage borne le temps d'accès total pour m opérations et n insertions sur un arbre initialement vide comme O((m + n)lg n). Le coût amorti pour une séquence de m accès à un arbre splay est O(lg n).

Un arbre splay est dirigé par une structure définie par la macro SPLAY_HEAD(). Une structure SPLAY_HEAD est déclarée comme suit :

SPLAY_HEAD(HEADNAME, TYPE) head;

où HEADNAME est le nom de la structure à définir, et struct TYPE est le type des éléments à insérer dans l'arbre.

La macro SPLAY_ENTRY() déclare une structure qui permet de connecter les éléments dans l'arbre.

Pour utiliser les fonctions qui manipulent la structure de l'arbre, leurs prototypes doivent être déclarés avec la macro SPLAY_PROTOTYPE(), où NAME est un identifiant unique pour cet arbre particulier. L'argument TYPE est le type de la structure gérée par l'arbre. L'argument FIELD est le nom de l'élément défini par SPLAY_ENTRY().

Les corps des fonctions sont générés avec la macro SPLAY_GENERATE(). Elle prend les mêmes arguments que la macro SPLAY_PROTOTYPE(), mais ne doit être utilisée qu'une seule fois.

Enfin, l'argument CMP est le nom d'une fonction utilisée pour comparer les nœuds de l'arbre entre eux. La fonction prend deux arguments de type struct TYPE *. Si le premier argument est plus petit que le second, la fonction retourne une valeur inférieure à zéro. S'ils sont égaux, la fonction retourne zéro. Sinon, elle doit retourner une valeur supérieure à zéro. La fonction de comparaison définit l'ordre des éléments de l'arbre.

La macro SPLAY_INIT() initialise l'arbre référencé par head.

L'arbre splay peut également être initialisé statiquement en utilisant la macro SPLAY_INITIALIZER() comme ceci :

SPLAY_HEAD(HEADNAME, TYPE) head = SPLAY_INITIALIZER(&head);

La macro SPLAY_INSERT() insère le nouvel élément elm dans l'arbre. En cas de succès, NULL est retourné. Si un élément correspondant existe déjà dans l'arbre, l'insertion est interrompue et un pointeur vers l'élément existant est retourné.

La macro SPLAY_REMOVE() supprime l'élément elm de l'arbre pointé par head. En cas de succès, un pointeur vers l'élément supprimé est retourné. NULL est retourné si elm n'est pas présent dans l'arbre.

La macro SPLAY_FIND() peut être utilisée pour trouver un élément particulier dans l'arbre.

struct TYPE find, *res;
find.key = 30;
res = SPLAY_FIND(NAME, &head, &find);

Les macros SPLAY_ROOT(), SPLAY_MIN(), SPLAY_MAX(), et SPLAY_NEXT() peuvent être utilisées pour parcourir l'arbre :

for (np = SPLAY_MIN(NAME, &head); np != NULL; np = SPLAY_NEXT(NAME, &head, np))

Ou, pour plus de simplicité, on peut utiliser la macro SPLAY_FOREACH() :

SPLAY_FOREACH(np, NAME, &head)

La macro SPLAY_EMPTY() doit être utilisée pour vérifier si un arbre splay est vide.

Arbres ROUGE-NOIR

Un arbre rouge-noir est un arbre binaire de recherche avec la couleur du nœud comme attribut supplémentaire. Il remplit un ensemble de conditions :

  1. chaque chemin de recherche de la racine à une feuille est constitué du même nombre de nœuds noirs,
  2. chaque nœud rouge (sauf la racine) a un parent noir,
  3. chaque nœud feuille est noir.

Chaque opération sur un arbre rouge-noir est bornée à O(lg n). La hauteur maximale d'un arbre rouge-noir est 2lg (n+1).

Un arbre rouge-noir est dirigé par une structure définie par la macro RB_HEAD(). Une structure RB_HEAD est déclarée comme suit :

RB_HEAD(HEADNAME, TYPE) head;

où HEADNAME est le nom de la structure à définir, et struct TYPE est le type des éléments à insérer dans l'arbre.

La macro RB_ENTRY() déclare une structure qui permet de connecter les éléments dans l'arbre.

Pour utiliser les fonctions qui manipulent la structure de l'arbre, leurs prototypes doivent être déclarés avec les macros RB_PROTOTYPE() ou RB_PROTOTYPE_STATIC(), où NAME est un identifiant unique pour cet arbre particulier. L'argument TYPE est le type de la structure gérée par l'arbre. L'argument FIELD est le nom de l'élément défini par RB_ENTRY().

Les corps des fonctions sont générés avec les macros RB_GENERATE() ou RB_GENERATE_STATIC(). Ces macros prennent les mêmes arguments que les macros RB_PROTOTYPE() et RB_PROTO RB_MIN(3bsd) - ArchWiki

NAME

libbsd \- macros for implementing splay and red-black trees

LIBRARY

libbsd (-lbsd)

SYNOPSIS

#include <sys/tree.h>

DESCRIPTION

These macros provide an implementation of both splay and red-black trees. They are designed to be used within a struct definition and defined as follows:

struct type_name {
	RB_ENTRY(type_name) field_name;
	/* other data */
};

then declare the head of the tree:

RB_HEAD(head_name, type_name) head_name;

Finally, define the tree macros:

RB_PROTOTYPE(head_name, type_name, field_name, compare_function)
RB_GENERATE(head_name, type_name, field_name, compare_function)

The compare_function is a function that takes two arguments of type struct type_name * and returns an integer less than zero if the first argument is less than the second, zero if they are equal, or greater than zero if the first argument is greater than the second.

SPLAY TREES

Splay trees are self-balancing binary search trees. The macros for splay trees are named SPLAY_....

RED-BLACK TREES

Red-black trees are also self-balancing binary search trees. The macros for red-black trees are named RB_....

The following macros are available:

RB_INITIALIZER()
This macro can be used to initialize a tree head statically. It takes the address of the tree head as an argument.
RB_HEAD(HEADNAME, TYPE)
Declares a structure HEADNAME that will serve as the head of a tree containing pointers to nodes of type TYPE. This macro should be used only once.
RB_PROTOTYPE(HEADNAME, TYPE, FIELD, CMP)
Declares the prototype for the tree functions. HEADNAME is the name of the tree head, TYPE is the node type, FIELD is the name of the entry point of the RB_ENTRY macro within the node structure, and CMP is the name of the comparison function.
RB_GENERATE(HEADNAME, TYPE, FIELD, CMP)
Generates the tree functions. This macro should be used in exactly one source file. This macro should be used only once.

Finally, the CMP argument is the name of a function used to compare trees' nodes with each other. The function takes two arguments of type struct TYPE *. If the first argument is smaller than the second, the function returns a value smaller than zero. If they are equal, the function returns zero. Otherwise, it should return a value greater than zero. The compare function defines the order of the tree elements.

RB_INIT()
The RB_INIT() macro initializes the tree referenced by head.

RB_INITIALIZER()
The red-black tree can also be initialized statically by using the RB_INITIALIZER() macro like this:

RB_HEAD(HEADNAME, TYPE) head = RB_INITIALIZER(&head);
RB_INSERT()
The RB_INSERT() macro inserts the new element elm into the tree. Upon success, NULL is returned. If a matching element already exists in the tree, the insertion is aborted, and a pointer to the existing element is returned.

RB_REMOVE()
The RB_REMOVE() macro removes the element elm from the tree pointed by head. RB_REMOVE() returns elm.

RB_FIND() and RB_NFIND()
The RB_FIND() and RB_NFIND() macros can be used to find a particular element in the tree. RB_FIND() finds the node with the same key as elm. RB_NFIND() finds the first node greater than or equal to the search key.

struct TYPE find, *res;
find.key = 30;
res = RB_FIND(NAME, &head, &find);
RB_ROOT(), RB_MIN(), RB_MAX(), RB_NEXT(), and RB_PREV()
The RB_ROOT(), RB_MIN(), RB_MAX(), RB_NEXT(), and RB_PREV() macros can be used to traverse the tree:

for (np = RB_MIN(NAME, &head); np != NULL; np = RB_NEXT(NAME, &head, np))
RB_FOREACH() or RB_FOREACH_REVERSE()
Or, for simplicity, one can use the RB_FOREACH() or RB_FOREACH_REVERSE() macros:

RB_FOREACH(np, NAME, &head)
RB_FOREACH_SAFE() or RB_FOREACH_REVERSE_SAFE()
The macros RB_FOREACH_SAFE() and RB_FOREACH_REVERSE_SAFE() traverse the tree referenced by head in a forward or reverse direction respectively, assigning each element in turn to np. However, unlike their unsafe counterparts, they permit both the removal of np as well as freeing it from within the loop safely without interfering with the traversal.

RB_EMPTY()
The RB_EMPTY() macro should be used to check whether a red-black tree is empty.

EXAMPLES

The following example demonstrates how to declare a red-black tree holding integers. Values are inserted into it and the contents of the tree are printed in order. Lastly, the internal structure of the tree is printed.

#include <sys/tree.h>
#include <err.h>
#include <stdio.h>
#include <stdlib.h>

struct node {
	RB_ENTRY(node) entry;
	int i;
};

int	intcmp(struct node *, struct node *);
void	print_tree(struct node *);

int
intcmp(struct node *e1, struct node *e2)
{
	return (e1->i < e2->i ? -1 : e1->i > e2->i);
}

RB_HEAD(inttree, node) head = RB_INITIALIZER(&head);
RB_PROTOTYPE(inttree, node, entry, intcmp)
RB_GENERATE(inttree, node, entry, intcmp)

int testdata[] = {
	20, 16, 17, 13, 3, 6, 1, 8, 2, 4, 10, 19, 5, 9, 12, 15, 18,
	7, 11, 14
};

void
print_tree(struct node *n)
{
	struct node *left, *right;

	if (n == NULL) {
		printf("nil");
		return;
	}
	left = RB_LEFT(n, entry);
	right = RB_RIGHT(n, entry);
	if (left == NULL && right == NULL)
		printf("%d", n->i);
	else {
		printf("%d(", n->i);
		print_tree(left);
		printf(",");
		print_tree(right);
		printf(")");
	}
}

int
main(void)
{
	int i;
	struct node *n;

	for (i = 0; i < sizeof(testdata) / sizeof(testdata[0]); i++) {
		if ((n = malloc(sizeof(struct node))) == NULL)
			err(1, NULL);
		n->i = testdata[i];
		RB_INSERT(inttree, &head, n);
	}

	RB_FOREACH(n, inttree, &head) {
		printf("%d\n", n->i);
	}
	print_tree(RB_ROOT(&head));
	printf("\n");
	return (0);
}

NOTES

Trying to free a tree in the following way is a common error:

SPLAY_FOREACH(var, NAME, &head) {
	SPLAY_REMOVE(NAME, &head, var);
	free(var);
}

Since var is free'd, the FOREACH() macro refers to a pointer that may have been reallocated already. Proper code needs a second variable.

for (var = SPLAY_MIN(NAME, &head); var != NULL; var = nxt) {
	nxt = SPLAY_NEXT(NAME, &head, var);
	SPLAY_REMOVE(NAME, &head, var);
	free(var);
}
