Specio::Constraint::Simple(3) Documentation Perl fournie par l'utilisateur Specio::Constraint::Simple(3)

NOM

Specio::Constraint::Simple - Classe pour les types simples (sans paramètres ou spéciaux)

VERSION

version 0.53

SYNOPSIS

my $str = t('Str');
print $str->name; # Str
my $parent = $str->parent;
if ( $str->value_is_valid($value) ) { ... }
$str->validate_or_die($value);
my $code = $str->inline_coercion_and_check('$_[0]');

DESCRIPTION

Cette classe implémente des contraintes de types simples, des contraintes sans propriétés spéciales ou paramètres.

Elle ne contient en fait aucun code réel. L'implémentation complète est fournie par le rôle Specio::Constraint::Role::Interface, mais l'API principale des contraintes de type est documentée ici.

Les autres classes de contraintes de cette distribution implémentent cette API, sauf indication contraire.

API

Cette classe fournit les méthodes suivantes.

Specio::Constraint::Simple->new(...)

Ceci crée une nouvelle contrainte. Elle accepte les paramètres nommés suivants :

  • name => $name

    C'est le nom du type. Le nom est optionnel, mais s'il est fourni, il doit s'agir d'une chaîne.

  • parent => $type

    Le type parent du type. Il doit s'agir d'un objet implémentant le rôle Specio::Constraint::Role::Interface.

    Ce paramètre est optionnel.

  • constraint => sub { ... }

    Une référence à une sous-routine qui implémente la contrainte. Elle sera appelée en tant que méthode sur l'objet et recevra un argument, la valeur à vérifier.

    Elle doit retourner vrai ou faux pour indiquer si la valeur correspond à la contrainte.

    Ce paramètre est mutuellement exclusif avec "inline_generator".

    Vous pouvez également passer cette option avec la clé "where" dans le paramètre.

  • inline_generator => sub { ... }

    Ce devrait être une référence à une sous-routine qui renvoie une chaîne contenant un seul terme. Ce code ne doit pas se terminer par un point-virgule. Ce code doit implémenter la contrainte.

    Le générateur sera appelé en tant que méthode sur la contrainte avec un seul argument. Cet argument est le nom de la variable à convertir, quelque chose comme '$_[0]' ou '$var'.

    Le générateur inline doit inclure du code pour implémenter le type actuel ainsi que tous ses parents. La manière la plus simple de le faire est d'écrire une sous-routine similaire à ceci :

    sub {
    my $self = shift;
    my $var  = shift;
    return $_[0]->parent->inline_check( $_[1] )
        . ' et plus de code de vérification ici';
}

    Ce paramètre est mutuellement exclusif avec "constraint".

    Vous pouvez également passer cette option avec la clé "inline" dans le paramètre.

  • inline_environment => {}

    Ce devrait être une référence à un hash de noms de variables (avec sigils) et de valeurs pour cette variable. Les valeurs doivent être des références aux valeurs des variables.

    Cet environnement sera utilisé lors de la compilation de la contrainte dans le cadre d'une sous-routine. Les variables nommées seront capturées sous forme de fermetures dans la sous-routine générée, à l'aide d'Eval::Closure.

    Il est très rare de devoir configurer ceci dans le constructeur. Il est plus probable qu'une sous-classe spéciale ait besoin de fournir des valeurs qu'elle génère en interne.

    Si vous le configurez, vous devez générer des noms de variables qui n'entrent pas en collision avec quoi que ce soit dans le code inline.

    Ce paramètre vaut par défaut une référence vide.

  • message_generator => sub { ... }

    Une sous-routine qui génère un message d'erreur lorsque la vérification du type échoue. Le message par défaut dit quelque chose comme "La validation a échoué pour le type nommé Int dans le module Specio::Library::Builtins (.../Specio/blib/lib/Specio/Library/Builtins.pm) à la ligne 147 dans la sous-routine nommée (eval) avec la valeur 1.1".

    Vous pouvez le remplacer pour fournir quelque chose de plus spécifique à la manière dont le type a échoué.

    La sous-routine que vous fournissez sera appelée comme une sous-routine, pas comme une méthode, avec deux arguments. Le premier est la description du type (le fragment du message ci-dessus commençant par "type named Int ..." et se terminant par "... in subroutine named (eval)"). Cette description indique ce qu'est l'objet et où il a été défini.

    Le second argument est la valeur qui a échoué à la vérification du type, après application de toute coercition.

    Vous pouvez également passer cette option avec la clé "message" dans le paramètre.

  • declared_at => $declared_at

    Ce paramètre doit être un objet de type Specio::DeclaredAt.

    Ce paramètre est obligatoire.

Il est possible de créer un type sans sa propre contrainte.

$type->name

Renvoie le nom du type tel que passé au constructeur.

$type->parent

Renvoie le type parent passé au constructeur. Si le type n'a pas de parent, il renvoie "undef".

$type->is_anon

Renvoie faux pour les types nommés, vrai sinon.

$type->is_a_type_of($other_type)

Étant donné un objet de type, ceci renvoie vrai si le type appelant cette méthode est un descendant de ce type ou est ce type lui-même.

$type->is_same_type_as($other_type)

Étant donné un objet de type, ceci renvoie vrai si le type appelant cette méthode est le même que l'autre type.

$type->coercions

Renvoie une liste d'objets de type Specio::Coercion appartenant à cette contrainte.

$type->coercion_from_type($name)

Étant donné un nom de type, cette méthode renvoie un objet de type Specio::Coercion qui effectue la coercition à partir de ce type, si une telle coercition existe.

$type->validate_or_die($value)

Cette méthode ne fait rien si la valeur est valide. Si elle ne l'est pas, elle lève une exception de type Specio::Exception.

$type->value_is_valid($value)

Renvoie vrai ou faux selon que la valeur $value passe la contrainte du type.

$type->has_real_constraint

Renvoie vrai si le type a été créé avec un paramètre de "constraint" ou "inline_generator". Ceci est utilisé en interne pour sauter les vérifications de types pour ceux qui n'implémentent pas de contrainte.

Specio::Constraint::Simple 3pm - Arch manual pages

NAME

Specio::Constraint::Simple - Base class for simple type constraints

VERSION

This is Specio version 0.53.

SYNOPSIS

  package My::Type;
  use Specio::Constraint;

  # ...

  package My::Role;
  use Moo::Role;
  use Specio::Constraint;

  # ...

  package My::Class;
  use Moo;
  use Specio::Constraint;

  has foo => (
    is => 'rw',
    isa => My::Type->get_type,
  );

DESCRIPTION

This is the base class for type constraints in Specio. It handles the basic plumbing required for them, and provides methods for describing and checking types.

You will almost never need to use this class directly. Instead, you will want to use Specio to create types.

If you are writing your own constraint class, you will want to inherit from this class.

API

$type->name

This returns the name of the type. If it's an anonymous type, it will return undef.

$type->description

This returns a human-readable description of the type. This will include the type's name (if it has one), and the file and line number where it was declared.

For example:

'type named Foo declared in package My::Lib (lib/My/Lib.pm) at line 42'.

If the type is anonymous the name will be "anonymous type".

$type->id

This is a unique id for the type as a string. This is useful if you need to make a hash key based on a type, for example. This should be treated as an essentially arbitrary and opaque string, and could change at any time in the future. If you want something human-readable, use the "$type->description" method.

$type->add_coercion($coercion)

This adds a new Specio::Coercion to the type. If the type already has a coercion from the same type as the new coercion, it will throw an error.

$type->has_coercion_from_type($other_type)

This method returns true if the type can coerce from the other type.

$type->coerce_value($value)

This attempts to coerce a value into a new value that matches the type. It checks all of the type's coercions. If it finds one which has a "from" type that accepts the value, it runs the coercion and returns the new value.

If it cannot find a matching coercion it returns the original value.

$type->inline_coercion_and_check($var)

Given a variable name, this returns a string of code and an environment hash that implements all of the type's coercions as well as the type check itself.

This will throw an exception unless both the type and all of its coercions are inlinable.

The generated code will throw a Specio::Exception if the type constraint fails. If the constraint passes, then the generated code returns the (possibly coerced) value.

The return value is a two-element list. The first element is the code. The second is a hash reference containing variables which need to be in scope for the code to work. This is intended to be passed to Eval::Closure's "eval_closure" subroutine.

The returned code is a single "do { }" block without a terminating semicolon.

$type->inline_assert($var)

Given a variable name, this generates code that implements the constraint and throws an exception if the variable does not pass the constraint.

The return value is a two-element list. The first element is the code. The second is a hash reference containing variables which need to be in scope for the code to work. This is intended to be passed to Eval::Closure's "eval_closure" subroutine.

$type->inline_check($var)

Given a variable name, this returns a string of code that implements the constraint. If the type is not inlinable, this method throws an error.

$type->inline_coercion($var)

Given a variable name, this returns a string of code and an environment hash that implements all of the type's coercions. It does not check that the resulting value is valid.

This will throw an exception unless all of the type's coercions are inlinable.

The return value is a two-element list. The first element is the code. The second is a hash reference containing variables which need to be in scope for the code to work. This is intended to be passed to Eval::Closure's "eval_closure" subroutine.

The returned code is a single "do { }" block without a terminating semicolon.

$type->inline_environment()

This returns a hash defining the variables that need to be closed over when inlining the type. The keys are full variable names like '$foo' or '@bar'. The values are references to a variable of the matching type.

$type->coercion_sub

This method returns a sub ref that takes a single argument and applied all relevant coercions to it. This sub ref will use Sub::Quote if all the type's coercions are inlinable.

This method exists primarily for the benefit of Moo.

OVERLOADING

All constraints implement the following overloads:

Subroutine De-referencing

This is done for the benefit of Moo. The returned subroutine uses Sub::Quote if the type constraint is inlinable.

Stringification

For non-anonymous types, this will be the type's name. For anonymous types, a string like "__ANON__(Str)" is generated. However, this string should not be expected to be stable across releases, so don't use it for things like equality checks!

Boolification

This always returns true.

String Equality (eq)

This calls "$type->is_same_type_as($other)" to compare the two types.

ROLES

This role does the Specio::Constraint::Role::Interface and Specio::Role::Inlinable roles.
