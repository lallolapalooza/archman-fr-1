DESCRIPTION

These macros define data structures for different kinds of trees: splay trees and red-black trees.

In the macro definitions, TYPE is the tag of a user-defined structure that must contain a field named FIELD and of type SPLAY_ENTRY or RB_ENTRY. The argument HEADNAME is the tag of a user-defined structure that must be declared using the macros SPLAY_HEAD() or RB_HEAD(). The argument NAME should be a unique prefix name for each defined tree.

Function prototypes are declared with SPLAY_PROTOTYPE, RB_PROTOTYPE or RB_PROTOTYPE_STATIC. Function body strings are generated with SPLAY_GENERATE, RB_GENERATE or RB_GENERATE_STATIC. See the examples below for further explanation on how these macros are used.

SPLAY TREES

A splay tree is a self-organizing data structure. Each operation on the tree causes a splay. The splay moves the requested node to the root of the tree and partially rebalances the tree.

This has the benefit that locality of requests leads to faster queries since requested nodes are moved to the top of the tree. On the other hand, every query causes writes to memory.

The Amortized Analysis bounds the total access time for m operations and n insertions on an initially empty tree as O((m + n)lg n). The amortized cost for a sequence of m queries on a splay tree is O(lg n).

A splay tree is headed by a structure defined by the macro SPLAY_HEAD(). A SPLAY_HEAD structure is declared like this:

SPLAY_HEAD(HEADNAME, TYPE) head;

where HEADNAME is the name of the structure to define and TYPE is the type of the elements to be inserted into the tree.

The macro SPLAY_ENTRY declares a structure that allows connecting elements in the tree.

To use the functions manipulating the tree structure, their prototypes must be declared with the macro SPLAY_PROTOTYPE, where NAME is a unique identifier for this particular tree. The argument TYPE is the type of the structure managing the tree. The argument FIELD is the name of the element defined by SPLAY_ENTRY).

Function body strings are generated with the macro SPLAY_GENERATE. It takes the same arguments as the SPLAY_PROTOTYPE() macro, but must be used only once.

Finally, the argument CMP is the name of a function used to compare tree nodes with each other. The function takes two arguments of type struct TYPE *. If the first argument is less than the second, the function returns a value less than zero. If they are equal, it returns zero. Otherwise, it returns a value greater than zero. The comparison function defines the order of the elements in the tree.

The macro SPLAY_INIT initializes the tree referenced by head.

The splay tree can also be initialized statically using the macro SPLAY_INITIALIZER like:

SPLAY_HEAD(HEADNAME, TYPE) head = SPLAY_INITIALIZER(&head);

The macro SPLAY_INSERT inserts the new element elm into the tree. Once successfully performed, NULL is returned. If an element corresponding to this already exists in the tree, insertion stops and a pointer to the existing element is returned.

The macro SPLAY_REMOVE removes the element elm from the tree pointed to by head. Once successfully performed, a pointer to the removed element is returned. NULL is returned if elm does not exist in the tree.

The macro SPLAY_FIND can be used to find a specific element in the tree.

struct TYPE find, *res;
find.key = 30;
res = SPLAY_FIND(NAME, &head, &find);

The macros SPLAY_ROOT, SPLAY_MIN, SPLAY_MAX, and SPLAY_NEXT can be used to iterate over the tree:

for (np = SPLAY_MIN(NAME, &head); np != NULL; np = SPLAY_NEXT(NAME, &head, np))

Or, for simplicity, the macro SPLAY_FOREACH can be used:

SPLAY_FOREACH(np, NAME, &head)

The macro SPLAY_EMPTY should be used to check if a splay tree is empty.

RED-BLACK TREES

A red-black tree is a binary search tree with node color as an additional property. It fulfills a set of conditions:

  1. Every path from the root to a leaf node contains the same number of black nodes,
  2. Every red node (except the root) has a black parent,
  3. Every leaf node is black.

Every operation on a red-black tree is bounded as O(lg n). The maximum height of a red-black tree is 2lg(n+1).

A red-black tree is headed by a structure defined by the macro RB_HEAD(). A RB_HEAD structure is declared like this:

RB_HEAD(HEADNAME, TYPE) head;

where HEADNAME is the name of the structure to define and TYPE is the type of the elements to be inserted into the tree.

The macro RB_ENTRY declares a structure that allows connecting elements in the tree.

To use the functions manipulating the tree structure, their prototypes must be declared with the macros RB_PROTOTYPE or RB_PROTOTYPE_STATIC, where NAME is a unique identifier for this particular tree. The argument TYPE is the type of the structure managing the tree. The argument FIELD is the name of the element defined by RB_ENTRY).

Function body strings are generated with the macros RB_GENERATE or RB_GENERATE_STATIC. These macros take the same arguments as the RB_PROTOTYPE() and RB_PROT

OTYPE_STATIC() macros, mais ne doit être utilisé qu'une seule fois.

Enfin, l'argument CMP est le nom d'une fonction utilisée pour comparer les nœuds des arbres entre eux. La fonction prend deux arguments de type struct TYPE *. Si le premier argument est inférieur au second, la fonction renvoie une valeur inférieure à zéro. S'ils sont égaux, la fonction renvoie zéro. Sinon, elle doit renvoyer une valeur supérieure à zéro. La fonction de comparaison définit l'ordre des éléments de l'arbre.

Le macro RB_INIT() initialise l'arbre référencé par head.

L'arbre rouge-noir peut également être initialisé statiquement en utilisant le macro RB_INITIALIZER() comme ceci:

RB_HEAD(HEADNAME, TYPE) head = RB_INITIALIZER(&head);

Le macro RB_INSERT() insère le nouvel élément elm dans l'arbre. En cas de succès, NULL est renvoyé. Si un élément correspondant existe déjà dans l'arbre, l'insertion est annulée et un pointeur vers l'élément existant est renvoyé.

Le macro RB_REMOVE() retire l'élément elm de l'arbre pointé par head. RB_REMOVE() renvoie elm.

Les macros RB_FIND() et RB_NFIND() peuvent être utilisés pour trouver un élément particulier dans l'arbre. RB_FIND() trouve le nœud avec la même clé que elm. RB_NFIND() trouve le premier nœud supérieur ou égal à la clé de recherche.

struct TYPE find, *res;
find.key = 30;
res = RB_FIND(NAME, &head, &find);

Les macros RB_ROOT(), RB_MIN(), RB_MAX(), RB_NEXT(), et RB_PREV() peuvent être utilisés pour parcourir l'arbre:

for (np = RB_MIN(NAME, &head); np != NULL; np = RB_NEXT(NAME, &head, np))

Ou, pour plus de simplicité, on peut utiliser les macros RB_FOREACH() ou RB_FOREACH_REVERSE():

RB_FOREACH(np, NAME, &head)

Les macros RB_FOREACH_SAFE() et RB_FOREACH_REVERSE_SAFE() parcourent l'arbre référencé par head dans un sens avant ou arrière respectivement, assignant chaque élément tour à tour à np. Cependant, contrairement à leurs homologues non sûrs, ils permettent à la fois la suppression de np et sa libération à partir de la boucle en toute sécurité sans interférer avec le parcours.

Le macro RB_EMPTY() doit être utilisé pour vérifier si un arbre rouge-noir est vide.

EXEMPLES

L'exemple suivant montre comment déclarer un arbre rouge-noir contenant des entiers. Des valeurs y sont insérées et le contenu de l'arbre est imprimé dans l'ordre. Enfin, la structure interne de l'arbre est imprimée.

#include <sys/tree.h>
#include <err.h>
#include <stdio.h>
#include <stdlib.h>

struct node {
	RB_ENTRY(node) entry;
	int i;
};

int	intcmp(struct node *, struct node *);
void	print_tree(struct node *);

int
intcmp(struct node *e1, struct node *e2)
{
	return (e1->i < e2->i ? -1 : e1->i > e2->i);
}

RB_HEAD(inttree, node) head = RB_INITIALIZER(&head);
RB_PROTOTYPE(inttree, node, entry, intcmp)
RB_GENERATE(inttree, node, entry, intcmp)

int testdata[] = {
	20, 16, 17, 13, 3, 6, 1, 8, 2, 4, 10, 19, 5, 9, 12, 15, 18,
	7, 11, 14
};

void
print_tree(struct node *n)
{
	struct node *left, *right;

	if (n == NULL) {
		printf("nil");
		return;
	}
	left = RB_LEFT(n, entry);
	right = RB_RIGHT(n, entry);
	if (left == NULL && right == NULL)
		printf("%d", n->i);
	else {
		printf("%d(", n->i);
		print_tree(left);
		printf(",");
		print_tree(right);
		printf(")");
	}
}

int
main(void)
{
	int i;
	struct node *n;

	for (i = 0; i < sizeof(testdata) / sizeof(testdata[0]); i++) {
		if ((n = malloc(sizeof(struct node))) == NULL)
			err(1, NULL);
		n->i = testdata[i];
		RB_INSERT(inttree, &head, n);
	}

	RB_FOREACH(n, inttree, &head) {
		printf("%d\n", n->i);
	}
	print_tree(RB_ROOT(&head));
	printf("\n");
	return (0);
}

HISTORIQUE

Les macros d'arbre sont apparus pour la première fois dans FreeBSD 4.6.

NOTES

Essayer de libérer un arbre de la manière suivante est une erreur courante:

SPLAY_FOREACH(var, NAME, &head) {
	SPLAY_REMOVE(NAME, &head, var);
	free(var);
}
free(head);

Comme var est libéré, le macro FOREACH() fait référence à un pointeur qui peut avoir déjà été réalloué. Un code correct nécessite une seconde variable.

for (var = SPLAY_MIN(NAME, &head); var != NULL; var = nxt) {
	nxt = SPLAY_NEXT(NAME, &head, var);
	SPLAY_REMOVE(NAME, &head, var);
	free(var);
}
