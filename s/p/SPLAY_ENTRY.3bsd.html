DESCRIPTION

Ces macros définissent des structures de données pour différents types d'arbres : arbres auto-ré organisateurs (splay trees) et arbres rouge-noir.

Dans les définitions de macros, TYPE est le nom d'étiquette d'une structure définie par l'utilisateur qui doit contenir un champ nommé FIELD, de type SPLAY_ENTRY ou RB_ENTRY. L'argument HEADNAME est le nom d'étiquette d'une structure définie par l'utilisateur qui doit être déclarée à l'aide des macros SPLAY_HEAD() ou RB_HEAD(). L'argument NOM doit être un préfixe de nom unique pour chaque arbre défini.

Les prototypes de fonctions sont déclarés avec SPLAY_PROTOTYPE, RB_PROTOTYPE, ou RB_PROTOTYPE_STATIC. Les corps des fonctions sont générés avec SPLAY_GENERATE, RB_GENERATE, ou RB_GENERATE_STATIC. Voir les exemples ci-dessous pour plus d'explications sur la manière dont ces macros sont utilisées.

ARbres AUTO-RÉORGANISATEURS

Un arbre auto-ré organisateur est une structure de données auto-organisatrice. Chaque opération sur l'arbre provoque une réorganisation (splay). La réorganisation déplace le nœud demandé à la racine de l'arbre et le rééquilibre partiellement.

Cela présente l'avantage que la localité des requêtes accélère les recherches car les nœuds demandés se déplacent vers le haut de l'arbre. D'un autre côté, chaque recherche entraîne des écritures en mémoire.

Le Théorème d'Équilibrage borne le temps d'accès total pour m opérations et n insertions sur un arbre initialement vide comme O((m + n)lg n). Le coût amorti pour une séquence de m accès à un arbre auto-ré organisateur est O(lg n).

Un arbre auto-ré organisateur est dirigé par une structure définie par la macro SPLAY_HEAD(). Une structure SPLAY_HEAD est déclarée comme suit :

SPLAY_HEAD(HEADNAME, TYPE) tete;

où HEADNAME est le nom de la structure à définir, et struct TYPE est le type des éléments à insérer dans l'arbre.

La macro SPLAY_ENTRY() déclare une structure qui permet de connecter les éléments dans l'arbre.

Afin d'utiliser les fonctions qui manipulent la structure de l'arbre, leurs prototypes doivent être déclarés avec la macro SPLAY_PROTOTYPE(), où NOM est un identifiant unique pour cet arbre particulier. L'argument TYPE est le type de la structure gérée par l'arbre. L'argument FIELD est le nom de l'élément défini par SPLAY_ENTRY().

Les corps des fonctions sont générés avec la macro SPLAY_GENERATE(). Elle prend les mêmes arguments que la macro SPLAY_PROTOTYPE(), mais ne doit être utilisée qu'une seule fois.

Enfin, l'argument CMP est le nom d'une fonction utilisée pour comparer les nœuds de l'arbre entre eux. La fonction prend deux arguments de type struct TYPE *. Si le premier argument est plus petit que le second, la fonction renvoie une valeur inférieure à zéro. S'ils sont égaux, la fonction renvoie zéro. Sinon, elle doit renvoyer une valeur supérieure à zéro. La fonction de comparaison définit l'ordre des éléments de l'arbre.

La macro SPLAY_INIT() initialise l'arbre référencé par tete.

L'arbre auto-ré organisateur peut également être initialisé statiquement en utilisant la macro SPLAY_INITIALIZER() comme suit :

SPLAY_HEAD(HEADNAME, TYPE) tete = SPLAY_INITIALIZER(&tete);

La macro SPLAY_INSERT() insère le nouvel élément elm dans l'arbre. En cas de succès, NULL est renvoyé. Si un élément correspondant existe déjà dans l'arbre, l'insertion est annulée et un pointeur vers l'élément existant est renvoyé.

La macro SPLAY_REMOVE() supprime l'élément elm de l'arbre pointé par tete. En cas de succès, un pointeur vers l'élément supprimé est renvoyé. NULL est renvoyé si elm n'est pas présent dans l'arbre.

La macro SPLAY_FIND() peut être utilisée pour trouver un élément particulier dans l'arbre.

struct TYPE recherche, *res;
recherche.cle = 30;
res = SPLAY_FIND(NOM, &tete, &recherche);

Les macros SPLAY_ROOT(), SPLAY_MIN(), SPLAY_MAX(), et SPLAY_NEXT() peuvent être utilisées pour parcourir l'arbre :

pour (np = SPLAY_MIN(NOM, &tete); np != NULL; np = SPLAY_NEXT(NOM, &tete, np))

Ou, pour plus de simplicité, on peut utiliser la macro SPLAY_FOREACH() :

SPLAY_FOREACH(np, NOM, &tete)

La macro SPLAY_EMPTY() doit être utilisée pour vérifier si un arbre auto-ré organisateur est vide.

ARbres ROUGE-NOIR

Un arbre rouge-noir est un arbre binaire de recherche avec la couleur du nœud comme attribut supplémentaire. Il remplit un ensemble de conditions :

  1. chaque chemin de recherche de la racine à une feuille est constitué du même nombre de nœuds noirs,
  2. chaque nœud rouge (sauf la racine) a un parent noir,
  3. chaque nœud feuille est noir.

Chaque opération sur un arbre rouge-noir est bornée à O(lg n). La hauteur maximale d'un arbre rouge-noir est 2lg (n+1).

Un arbre rouge-noir est dirigé par une structure définie par la macro RB_HEAD(). Une structure RB_HEAD est déclarée comme suit :

RB_HEAD(HEADNAME, TYPE) tete;

où HEADNAME est le nom de la structure à définir, et struct TYPE est le type des éléments à insérer dans l'arbre.

La macro RB_ENTRY() déclare une structure qui permet de connecter les éléments dans l'arbre.

Afin d'utiliser les fonctions qui manipulent la structure de l'arbre, leurs prototypes doivent être déclarés avec les macros RB_PROTOTYPE() ou RB_PROTOTYPE_STATIC(), où NOM est un identifiant unique pour cet arbre particulier. L'argument TYPE est le type de la structure gérée par l'arbre. L'argument FIELD est le nom de l'élément défini par RB_ENTRY().

LIBRARY

libbsd

SYNOPSIS

Standard splay tree macros:

#include <sys/tree.h>
SPLAY_HEAD(NAME, TYPE);
SPLAY_ENTRY(TYPE);

Standard red-black tree macros:

#include <sys/tree.h>
RB_HEAD(NAME, TYPE);
RB_ENTRY(TYPE);

DESCRIPTION

These macros implement splay trees and red-black trees. A tree is a data structure that maintains a sorted set of elements. The elements are arranged in a binary search tree.

The macros are defined in the header file <sys/tree.h>.

To use the tree macros, you must define a structure that holds the tree node. This structure must contain a field of type SPLAY_ENTRY(TYPE) for splay trees or RB_ENTRY(TYPE) for red-black trees, where TYPE is the name of your structure. This field will be used to link the nodes together.

struct mynode {
	SPLAY_ENTRY(struct mynode) next;
	/* other fields */
	int key;
};

You must also define the tree head structure, which is a structure that contains the root of the tree. The tree head structure is defined using SPLAY_HEAD() or RB_HEAD().

SPLAY_HEAD(mynametree, struct mynode);
RB_HEAD(mynametree, struct mynode);

Finally, you must provide a comparison function CMP that compares two nodes. The function takes two pointers to TYPE structures. It should return a value less than zero if the first node is less than the second, zero if they are equal, and a value greater than zero otherwise. The comparison function defines the order of the elements in the tree.

int
mycompare(struct mynode *a, struct mynode *b)
{
	return (a->key - b->key);
}

Then, you must declare the tree head and generate the tree functions using SPLAY_PROTOTYPE() and SPLAY_GENERATE() or RB_PROTOTYPE() and RB_GENERATE().

SPLAY_PROTOTYPE(mynametree, struct mynode, next, mycompare);
SPLAY_GENERATE(mynametree, struct mynode, next, mycompare);
RB_PROTOTYPE(mynametree, struct mynode, next, mycompare);
RB_GENERATE(mynametree, struct mynode, next, mycompare);

Note that the next argument in the above examples is the name of the field declared using SPLAY_ENTRY() or RB_ENTRY().

SPLAY TREES

The SPLAY_TREE macros are used to implement splay trees. Splay trees are self-balancing binary search trees that automatically move frequently accessed nodes closer to the root.

The SPLAY_HEAD() macro declares a structure that will hold the root of the tree. The first argument is the name of the tree structure, and the second argument is the name of the structure that will be stored in the tree.

The SPLAY_ENTRY() macro declares a field within your structure that will be used to link the nodes together. The argument is the name of your structure.

The SPLAY_INIT() macro initializes an empty tree pointed to by head.

The tree can also be initialized statically using the SPLAY_INITIALIZER() macro.

SPLAY_HEAD(mynametree, struct mynode) myhead = SPLAY_INITIALIZER(&myhead);

The SPLAY_INSERT() macro inserts a new node elm into the tree. If a node with the same key already exists, the new node is not inserted. The macro returns the inserted node or the existing node if a duplicate was found.

The SPLAY_FIND() macro finds a node with the key specified by elm. It returns a pointer to the node if found, or NULL otherwise.

The SPLAY_MIN() macro returns a pointer to the node with the smallest key in the tree.

The SPLAY_MAX() macro returns a pointer to the node with the largest key in the tree.

The SPLAY_NEXT() macro returns a pointer to the next node in the tree in ascending order.

The SPLAY_REMOVE() macro removes the node elm from the tree.

The SPLAY_EMPTY() macro checks if the tree is empty.

The SPLAY_FOREACH() macro iterates over all nodes in the tree in ascending order.

struct mynode *np;
SPLAY_FOREACH(np, mynametree, &myhead)

RED-BLACK TREES

The RB_TREE macros are used to implement red-black trees. Red-black trees are a type of self-balancing binary search tree in which each node has a color, red or black. These colors are used to ensure that the tree remains balanced during insertions and deletions.

The RB_HEAD() macro declares a structure that will hold the root of the tree. The first argument is the name of the tree structure, and the second argument is the name of the structure that will be stored in the tree.

The RB_ENTRY() macro declares a field within your structure that will be used to link the nodes together. The argument is the name of your structure.

The CMP argument is the name of a function used to compare trees' nodes with each other. The function takes two arguments of type struct TYPE *. If the first argument is smaller than the second, the function returns a value smaller than zero. If they are equal, the function returns zero. Otherwise, it should return a value greater than zero. The compare function defines the order of the tree elements.

The RB_INIT() macro initializes the tree referenced by head.

The red-black tree can also be initialized statically by using the RB_INITIALIZER() macro like this:

RB_HEAD(HEADNAME, TYPE) head = RB_INITIALIZER(&head);

The RB_INSERT() macro inserts the new element elm into the tree. Upon success, NULL is returned. If a matching element already exists in the tree, the insertion is aborted, and a pointer to the existing element is returned.

The RB_REMOVE() macro removes the element elm from the tree pointed by head. RB_REMOVE() returns elm.

The RB_FIND() and RB_NFIND() macros can be used to find a particular element in the tree. RB_FIND() finds the node with the same key as elm. RB_NFIND() finds the first node greater than or equal to the search key.

struct TYPE find, *res;
find.key = 30;
res = RB_FIND(NAME, &head, &find);

The RB_ROOT(), RB_MIN(), RB_MAX(), RB_NEXT(), and RB_PREV() macros can be used to traverse the tree:

for (np = RB_MIN(NAME, &head); np != NULL; np = RB_NEXT(NAME, &head, np))

Or, for simplicity, one can use the RB_FOREACH() or RB_FOREACH_REVERSE() macros:

RB_FOREACH(np, NAME, &head)

The macros RB_FOREACH_SAFE() and RB_FOREACH_REVERSE_SAFE() traverse the tree referenced by head in a forward or reverse direction respectively, assigning each element in turn to np. However, unlike their unsafe counterparts, they permit both the removal of np as well as freeing it from within the loop safely without interfering with the traversal.

The RB_EMPTY() macro should be used to check whether a red-black tree is empty.

EXAMPLES

The following example demonstrates how to declare a red-black tree holding integers. Values are inserted into it and the contents of the tree are printed in order. Lastly, the internal structure of the tree is printed.

#include <sys/tree.h>
#include <err.h>
#include <stdio.h>
#include <stdlib.h>

struct node {
	RB_ENTRY(node) entry;
	int i;
};

int	intcmp(struct node *, struct node *);
void	print_tree(struct node *);

int
intcmp(struct node *e1, struct node *e2)
{
	return (e1->i < e2->i ? -1 : e1->i > e2->i);
}

RB_HEAD(inttree, node) head = RB_INITIALIZER(&head);
RB_PROTOTYPE(inttree, node, entry, intcmp)
RB_GENERATE(inttree, node, entry, intcmp)

int testdata[] = {
	20, 16, 17, 13, 3, 6, 1, 8, 2, 4, 10, 19, 5, 9, 12, 15, 18,
	7, 11, 14
};

void
print_tree(struct node *n)
{
	struct node *left, *right;

	if (n == NULL) {
		printf("nil");
		return;
	}
	left = RB_LEFT(n, entry);
	right = RB_RIGHT(n, entry);
	if (left == NULL && right == NULL)
		printf("%d", n->i);
	else {
		printf("%d(", n->i);
		print_tree(left);
		printf(",");
		print_tree(right);
		printf(")");
	}
}

int
main(void)
{
	int i;
	struct node *n;

	for (i = 0; i < sizeof(testdata) / sizeof(testdata[0]); i++) {
		if ((n = malloc(sizeof(struct node))) == NULL)
			err(1, NULL);
		n->i = testdata[i];
		RB_INSERT(inttree, &head, n);
	}

	RB_FOREACH(n, inttree, &head) {
		printf("%d\n", n->i);
	}
	print_tree(RB_ROOT(&head));
	printf("\n");
	return (0);
}

NOTES

Trying to free a tree in the following way is a common error:

SPLAY_FOREACH(var, NAME, &head) {
	SPLAY_REMOVE(NAME, &head, var);
	free(var);
}
free(head);

Since var is free'd, the FOREACH() macro refers to a pointer that may have been reallocated already. Proper code needs a second variable.

for (var = SPLAY_MIN(NAME, &head); var != NULL; var = nxt) {
	nxt = SPLAY_NEXT(NAME, &head, var);
	SPLAY_REMOVE(NAME, &head, var);
	free(var);
}
