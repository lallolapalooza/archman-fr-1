Specio::Library::Structured(3) Documentation Perl soumise par les utilisateurs Specio::Library::Structured(3)

NOM

Specio::Library::Structured - Types structurés pour Specio (Dict, Map, Tuple)

VERSION

version 0.53

SYNOPSIS

use Specio::Library::Builtins;
use Specio::Library::String;
use Specio::Library::Structured;
my $map = t(
    'Map',
    of => {
        key   => t('NonEmptyStr'),
        value => t('Int'),
    },
);
my $tuple = t(
    'Tuple',
    of => [ t('Str'), t('Num') ],
);
my $dict = t(
    'Dict',
    of => {
        kv => {
            name => t('Str'),
            age  => t('Int'),
        },
    },
);

DESCRIPTION

Cette bibliothèque fournit une série de types structurés pour Specio, "Dict", "Map" et "Tuple". Cette bibliothèque exporte également deux fonctions d'assistance utilisées pour certains types, "optional" et "slurpy".

Tous les types structurés sont appelés via "t( 'Type Name', of => ...)". Les arguments après "of" varient en fonction de chaque type.

Dict

Un "Dict" est un hashref avec une définition bien définie des clés et des types pour chaque clé.

L'argument passé à "of" doit être un seul hashref. Ce hashref doit contenir une clé "kv" qui définit les clés attendues et les types de leurs valeurs. Cette valeur "kv" est elle-même un hashref. Si une paire clé/valeur est facultative, utilisez "optional" autour du type pour cette clé :

my $person = t(
    'Dict',
    of => {
        kv => {
            first  => t('NonEmptyStr'),
            middle => optional( t('NonEmptyStr') ),
            last   => t('NonEmptyStr'),
        },
    },
);

Si une clé est facultative, elle peut être complètement omise, mais si elle est fournie, son type sera vérifié, elle ne peut donc pas être simplement "undef".

Une clé "slurpy" peut également être fournie. Si cette clé est fournie, alors le "Dict" autorisera d'autres clés inconnues, tant qu'elles correspondent au type spécifié :

my $person = t(
    'Dict',
    of => {
        kv => {
            first  => t('NonEmptyStr'),
            middle => optional( t('NonEmptyStr') ),
            last   => t('NonEmptyStr'),
        },
        slurpy => t('Int'),
    },
);

Map

Une "Map" est un hashref avec des types spécifiques pour ses clés et ses valeurs, mais sans noms de clés bien définis.

L'argument passé à "of" doit être un seul hashref avec deux clés, "key" et "value". Le type pour la clé "key" sera typiquement un type de clé, bien que si vous utilisez un hash lié ou un objet avec surcharge de hash, il pourrait s'agir de n'importe quelle valeur.

Tuple

Un "Tuple" est un arrayref avec un ensemble fixe de membres dans un ordre spécifique.

L'argument passé à "of" doit être un seul arrayref de types. Vous pouvez marquer un emplacement dans le "Tuple" comme facultatif en appelant "optional" :

my $record = t(
    'Tuple',
    of => [
        t('PositiveInt'),
        t('Str'),
        optional( t('Num') ),
        optional( t('Num') ),
    ],
);

Vous pouvez avoir autant d'éléments "optional" que vous le souhaitez, mais ils doivent toujours être à la fin de la définition du tuple. Vous ne pouvez pas mélanger des éléments obligatoires et facultatifs.

Vous pouvez également faire en sorte que le Tuple accepte un nombre quelconque de valeurs en appelant "slurpy" sur le dernier type :

my $record = t(
    'Tuple',
    of => [
        t('PositiveInt'),
        t('Str'),
        slurpy( t('Num') ),
    ],
);

Dans ce cas, le "Tuple" exigera les deux premiers éléments, puis autorisera un nombre quelconque (y compris zéro) d'éléments "Num".

Vous ne pouvez pas mélanger "optional" et "slurpy" dans une définition de "Tuple".

LIMITATIONS

Actuellement, tous les types structurés exigent que les types avec lesquels ils sont structurés puissent être liés. Cela pourrait changer à l'avenir, mais lier tous vos types est une très bonne pratique, vous devriez donc le faire.
