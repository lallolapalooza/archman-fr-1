DESCRIPTION

Ces macros définissent des structures de données pour différents types d'arbres : arbres splay et arbres rouge-noir.

Dans les définitions de macros, TYPE est le nom d'une structure définie par l'utilisateur qui doit contenir un champ nommé FIELD de type SPLAY_ENTRY ou RB_ENTRY. L'argument HEADNAME est le nom d'une structure définie par l'utilisateur qui doit être déclarée en utilisant les macros SPLAY_HEAD() ou RB_HEAD(). L'argument NAME doit être un préfixe unique pour chaque arbre défini.

Les prototypes des fonctions sont déclarés avec SPLAY_PROTOTYPE, RB_PROTOTYPE ou RB_PROTOTYPE_STATIC. Les corps des fonctions sont générés avec SPLAY_GENERATE, RB_GENERATE ou RB_GENERATE_STATIC. Voir les exemples ci-dessous pour une explication plus détaillée de l'utilisation de ces macros.

ARbres SPLAY

Un arbre splay est une structure de données auto-organisatrice. Chaque opération sur l'arbre provoque un splay. Le splay déplace le nœud demandé vers la racine de l'arbre et rééquilibre partiellement l'arbre.

Cet avantage est que la localité des requêtes rend les recherches plus rapides, car les nœuds demandés sont déplacés vers le haut de l'arbre. En contrepartie, chaque recherche entraîne des écritures en mémoire.

Le théorème d'équilibre limite le temps d'accès total pour m opérations et n insertions dans un arbre initialement vide à O((m + n)lg n). Le coût amorti pour une séquence de m accès à un arbre splay est O(lg n).

Un arbre splay est hébergé par une structure définie à l'aide de la macro SPLAY_HEAD(). Un SPLAY_HEAD est déclaré comme suit :

SPLAY_HEAD(HEADNAME, TYPE) head;

où HEADNAME est le nom de la structure à définir, et TYPE est le type des éléments à insérer dans l'arbre.

La macro SPLAY_ENTRY déclare une structure qui permet de relier les éléments dans l'arbre.

Pour utiliser les fonctions qui manipulent la structure de l'arbre, leurs prototypes doivent être déclarés avec la macro SPLAY_PROTOTYPE, où NAME est un identifiant unique pour cet arbre particulier. L'argument TYPE est le type de la structure qui gère l'arbre. L'argument FIELD est le nom du champ défini par la macro SPLAY_ENTRY.

Les corps des fonctions sont générés avec la macro SPLAY_GENERATE. Elle prend les mêmes arguments que la macro SPLAY_PROTOTYPE, mais elle ne doit être utilisée qu'une seule fois.

Enfin, l'argument CMP est le nom d'une fonction qui compare les nœuds de l'arbre entre eux. La fonction prend deux arguments de type struct TYPE *. Si le premier argument est inférieur au second, la fonction renvoie une valeur inférieure à zéro. S'ils sont égaux, elle renvoie zéro. Sinon, elle renvoie une valeur supérieure à zéro. La fonction de comparaison définit l'ordre des éléments dans l'arbre.

La macro SPLAY_INIT initialise l'arbre référencé par head.

L'arbre splay peut également être initialisé statiquement en utilisant la macro SPLAY_INITIALIZER, comme illustré ci-dessous :

SPLAY_HEAD(HEADNAME, TYPE) head = SPLAY_INITIALIZER(&head);

La macro SPLAY_INSERT insère le nouvel élément elm dans l'arbre. Si l'insertion réussit, NULL est renvoyé. Si un élément correspondant existe déjà dans l'arbre, l'insertion est annulée et un pointeur vers l'élément existant est renvoyé.

La macro SPLAY_REMOVE supprime l'élément elm de l'arbre pointé par head. Si la suppression réussit, un pointeur vers l'élément supprimé est renvoyé. NULL est renvoyé si elm n'existe pas dans l'arbre.

La macro SPLAY_FIND peut être utilisée pour trouver un élément spécifique dans l'arbre.

struct TYPE find, *res;
find.key = 30;
res = SPLAY_FIND(NAME, &head, &find);

Les macros SPLAY_ROOT, SPLAY_MIN, SPLAY_MAX, et SPLAY_NEXT peuvent être utilisées pour parcourir l'arbre :

for (np = SPLAY_MIN(NAME, &head); np != NULL; np = SPLAY_NEXT(NAME, &head, np))

Ou, pour plus de simplicité, la macro SPLAY_FOREACH peut être utilisée :

SPLAY_FOREACH(np, NAME, &head)

La macro SPLAY_EMPTY doit être utilisée pour vérifier si un arbre splay est vide.

ARbres ROUGE-NOIR

Un arbre rouge-noir est un arbre de recherche binaire avec la couleur des nœuds comme attribut supplémentaire. Il satisfait un certain nombre de conditions :

  1. Chaque chemin de la racine à un nœud feuille contient le même nombre de nœuds noirs,
  2. Chaque nœud rouge (sauf la racine) a un parent noir,
  3. Chaque nœud feuille est noir.

Chaque opération sur un arbre rouge-noir est limitée à O(lg n). La hauteur maximale d'un arbre rouge-noir est de 2lg(n+1).

Un arbre rouge-noir est hébergé par une structure définie à l'aide de la macro RB_HEAD. Un RB_HEAD est déclaré comme suit :

RB_HEAD(HEADNAME, TYPE) head;

où HEADNAME est le nom de la structure à définir, et TYPE est le type des éléments à insérer dans l'arbre.

La macro RB_ENTRY déclare une structure qui permet de relier les éléments dans l'arbre.

Pour utiliser les fonctions qui manipulent la structure de l'arbre, leurs prototypes doivent être déclarés avec les macros RB_PROTOTYPE ou RB_PROTOTYPE_STATIC, où NAME est un identifiant unique pour cet arbre particulier. L'argument TYPE est le type de la structure qui gère l'arbre. L'argument FIELD est le nom du champ défini par la macro RB_ENTRY.

SYNTAXE

Les macros suivantes initialisent et utilisent des arbres rouge-noir :

RB_HEAD(HEADNAME, TYPE) head = RB_INITIALIZER(&head);

Les macros suivantes initialisent statiquement un arbre rouge-noir en utilisant la macro RB_INITIALIZER comme montré :

RB_HEAD(HEADNAME, TYPE) head = RB_INITIALIZER(&head);

DESCRIPTION

Les macros CMP sont une macro d'initialisation pour les arbres rouge-noir. Elles doivent être utilisées une seule fois.

Enfin, l'argument CMP est le nom d'une fonction qui compare les nœuds d'arbre. La fonction prend deux arguments de type struct TYPE *. Si le premier argument est inférieur au second, elle retourne une valeur inférieure à zéro. S'ils sont égaux, elle retourne zéro. Sinon, elle retourne une valeur supérieure à zéro. La fonction de comparaison définit l'ordre des éléments de l'arbre.

ARbres DE BALANCEMENT

Les macros RB_INIT et RB_INSERT sont utilisées pour insérer des éléments dans un arbre rouge-noir. La macro RB_REMOVE supprime un élément de l'arbre. Les macros RB_FIND et RB_NFIND sont utilisées pour trouver un élément dans l'arbre.

EXEMPLE

#include <sys/tree.h>
#include <err.h>
#include <stdio.h>
#include <stdlib.h>

struct node {
	RB_ENTRY(node) entry;
	int i;
};

int intcmp(struct node *, struct node *);
void print_tree(struct node *);

int
intcmp(struct node *e1, struct node *e2)
{
	return (e1->i < e2->i ? -1 : e1->i > e2->i);
}

RB_HEAD(inttree, node) head = RB_INITIALIZER(&head);
RB_PROTOTYPE(inttree, node, entry, intcmp)
RB_GENERATE(inttree, node, entry, intcmp)

int testdata[] = {
	20, 16, 17, 13, 3, 6, 1, 8, 2, 4, 10, 19, 5, 9, 12, 15, 18,
	7, 11, 14
};

void
print_tree(struct node *n)
{
	struct node *left, *right;

	if (n == NULL) {
		printf("nil");
		return;
	}
	left = RB_LEFT(n, entry);
	right = RB_RIGHT(n, entry);
	if (left == NULL && right == NULL)
		printf("%d", n->i);
	else {
		printf("%d(", n->i);
		print_tree(left);
		printf(",");
		print_tree(right);
		printf(")");
	}
}

int
main(void)
{
	int i;
	struct node *n;

	for (i = 0; i < sizeof(testdata) / sizeof(testdata[0]); i++) {
		if ((n = malloc(sizeof(struct node))) == NULL)
			err(1, NULL);
		n->i = testdata[i];
		RB_INSERT(inttree, &head, n);
	}

	RB_FOREACH(n, inttree, &head) {
		printf("%d\n", n->i);
	}
	print_tree(RB_ROOT(&head));
	printf("\n");
	return (0);
}

HISTORIQUE

Les macros d'arbre rouge-noir ont été introduites dans FreeBSD 4.6.

NOTES

Tenter de libérer un arbre de cette manière est une erreur courante :

SPLAY_FOREACH(var, NAME, &head) {
	SPLAY_REMOVE(NAME, &head, var);
	free(var);
}

Parce que var est libéré, la macro FOREACH fait référence à un pointeur qui pourrait avoir déjà été réattribué. Le code correct nécessite une variable supplémentaire.

for (var = SPLAY_MIN(NAME, &head); var != NULL; var = nxt) {
	nxt = SPLAY_NEXT(NAME, &head, var);
	SPLAY_REMOVE(NAME, &head, var);
	free(var);
}
