NOM

Specio::Declare - Sous-programmes de déclaration Specio

VERSION

version 0.53

SYNOPSIS

package MyApp::Type::Library;
use parent 'Specio::Exporter';
use Specio::Declare;
use Specio::Library::Builtins;
declare(
    'Foo',
    parent => t('Str'),
    where  => sub { $_[0] =~ /foo/i },
);
declare(
    'ArrayRefOfInt',
    parent => t( 'ArrayRef', of => t('Int') ),
);
my $even = anon(
    parent => t('Int'),
    inline => sub {
        my $type      = shift;
        my $value_var = shift;
        return $value_var . ' % 2 == 0';
    },
);
coerce(
    t('ArrayRef'),
    from  => t('Foo'),
    using => sub { [ $_[0] ] },
);
coerce(
    $even,
    from  => t('Int'),
    using => sub { $_[0] % 2 ? $_[0] + 1 : $_[0] },
);
# Nom Specio est DateTime
any_isa_type('DateTime');
# Nom Specio est DateTimeObject
object_isa_type( 'DateTimeObject', class => 'DateTime' );
any_can_type(
    'Duck',
    methods => [ 'duck_walk', 'quack' ],
);
object_can_type(
    'DuckObject',
    methods => [ 'duck_walk', 'quack' ],
);
enum(
    'Colors',
    values => [qw( blue green red )],
);
intersection(
    'HashRefAndArrayRef',
    of => [ t('HashRef'), t('ArrayRef') ],
);
union(
    'IntOrArrayRef',
    of => [ t('Int'), t('ArrayRef') ],
);

DESCRIPTION

Ce paquet exporte un ensemble d'aides à la déclaration de types. L'importation de ce paquet provoque également la création d'un sous-programme "t" dans le paquet appelant.

SOUS-PROGRAMMES

Ce module exporte les sous-programmes suivants.

t('nom')

Ce sous-programme vous permet d'accéder à tous les types que vous avez déclarés jusqu'à présent, ainsi qu'à tous les types que vous avez importés d'une autre bibliothèque de types.

Si vous passez un nom inconnu, une exception est levée.

declare(...)

Ce sous-programme déclare un type nommé. Le premier argument est le nom du type, suivi d'un ensemble de paramètres clé/valeur :

  • parent => $type

    Le parent doit être un autre objet de type. Spécifiquement, il peut s'agir de tout ce qui implémente le rôle Specio::Constraint::Role::Interface. Le parent peut être un type nommé ou anonyme.

  • where => sub { ... }

    Il s'agit d'un sous-programme qui définit la contrainte de type. Il recevra un seul argument, la valeur à vérifier, et il doit retourner vrai ou faux pour indiquer si la valeur est valide pour le type.

    Ce paramètre est mutuellement exclusif avec le paramètre "inline".

  • inline => sub { ... }

    Il s'agit d'un sous-programme appelé pour générer du code en ligne pour valider le type. L'inlining peut être beaucoup plus rapide que de simplement fournir un sous-programme avec le paramètre "where", mais il est souvent plus compliqué de le faire correctement.

    Le générateur en ligne est appelé comme une méthode sur le type avec un argument. Cet argument est une chaîne contenant le nom de la variable à utiliser dans le code généré. Typiquement, il s'agit de quelque chose comme '$_[0]' ou '$value'.

    Le sous-programme du générateur en ligne doit retourner une chaîne de code représentant un terme unique, et il ne doit pas être terminé par un point-virgule. Cela permet au code inliné d'être intégré en toute sécurité dans une instruction "if", par exemple. Vous pouvez utiliser des blocs "do { }" et des ternaires pour tout ramener à un seul terme. Ne modifiez pas la variable que vous testez. Ce terme unique doit évaluer à vrai ou faux.

    Le générateur en ligne est censé inclure le code pour implémenter à la fois le type actuel et tous ses parents. Généralement, la façon la plus simple de le faire est d'écrire un sous-programme comme celui-ci:

    sub {
    my $self = shift;
    my $var  = shift;
    return $self->parent->inline_check($var)
        . ' and more checking code goes here';
}

    Ou, plus concisément :

    sub { $_[0]->parent->inline_check( $_[1] ) . 'more code that checks $_[1]' }

    Le paramètre "inline" est mutuellement exclusif avec le paramètre "where".

  • message_generator => sub { ... }

    Un sous-programme pour générer un message d'erreur lorsque la vérification du type échoue. Le message par défaut dit quelque chose comme "Validation failed for type named Int declared in package Specio::Library::Builtins (.../Specio/blib/lib/Specio/Library/Builtins.pm) at line 147 in sub named (eval) with value 1.1".

    Vous pouvez le remplacer pour fournir quelque chose de plus spécifique sur la façon dont le type a échoué.

    Le sous-programme que vous fournissez sera appelé comme une méthode sur le type avec deux arguments. Le premier est la description du type (la partie du message ci-dessus commençant par "type named Int ..." et se terminant par "... in sub named (eval)". Cette description indique ce qu'est la chose et où elle a été définie.

    Le deuxième argument est la valeur qui a échoué à la vérification du type, après toute coercition qui aurait pu être appliquée.

anon(...)

Ce sous-programme déclare un type anonyme. Il est identique à "declare" sauf qu'il attend une liste de paramètres clé/valeur sans nom de type comme premier paramètre.

coerce(...)

Ceci déclare une coercition d'un type vers un autre. Le premier argument doit être un objet qui implémente le rôle Specio::Constraint::Role::Interface. Il peut s'agir d'un type nommé ou anonyme. Ce type est le type vers lequel la coercition s'effectue.

Les arguments restants sont des paramètres clé/valeur :

  • from => $type

    Cela doit être un objet qui implémente le rôle Specio::Constraint::Role::Interface. C'est le type à partir duquel nous effectuons la coercition. Encore une fois, il peut s'agir d'un type nommé ou anonyme.

  • using => sub { ... }

    Il s'agit d'un sous-programme qui définit la coercition de type. Il recevra un seul argument, la valeur à क्रमांका. Il doit retourner une nouvelle valeur du type vers lequel cette coercition s'effectue.

    Ce paramètre est mutuellement exclusif avec le paramètre "inline".

  • inline => sub { ... }

    Il s'agit d'un sous-programme appelé pour générer du code en ligne pour effectuer la coercition.

    Le générateur en ligne est appelé comme une méthode sur le type avec un argument. Cet argument est une chaîne contenant le nom de la variable à utiliser dans le code généré. Typiquement, il s'agit de quelque chose comme '$_[0]' ou '$value'.

    Le sous-programme du générateur en ligne doit retourner une chaîne de code représentant un terme unique, et il ne doit pas être terminé par un point-virgule. Cela permet au code inliné d'être intégré en toute sécurité dans une instruction "if", par exemple. Vous pouvez utiliser des blocs "do { }" et des ternaires pour tout ramener à un seul terme. Ce terme unique doit évaluer à la nouvelle valeur.

AIDES À LA DÉCLARATION

Ce module exporte également des sous-programmes d'aide pour déclarer certains types :

any_isa_type, object_isa_type

Le sous-programme "any_isa_type" crée un type qui accepte un nom de classe ou un objet de la classe donnée. Le sous-programme "object_isa_type" crée un type qui n'accepte qu'un objet de la classe donnée.

Ces sous-programmes prennent un nom de type comme premier argument. Les arguments restants sont des paires clé/valeur. Actuellement

L'argument du nom de type peut être omis pour créer un type anonyme.

Vous pouvez également passer un seul argument, auquel cas il sera utilisé à la fois comme nom de type et comme classe pour la contrainte à vérifier.

any_does_type, object_does_type

L'aide "any_does_type" crée un type qui accepte un nom de classe ou un objet qui assume le rôle donné. L'aide "object_does_type" crée un type qui n'accepte qu'un objet qui assume le rôle donné.

Ces sous-routines prennent un nom de type comme premier argument. Les arguments restants sont des paires clé/valeur. Actuellement, il s'agit uniquement de la clé "role", qui devrait être un nom de rôle. C'est la classe qu'exige le type.

Cela devrait fonctionner (j'espère) avec les rôles créés par Moose, Mouse et Moo (en utilisant Role::Tiny).

L'argument du nom de type peut être omis pour créer un type anonyme.

Vous pouvez également passer un seul argument, auquel cas il sera utilisé à la fois comme nom de type et comme rôle pour la contrainte à vérifier.

any_can_type, object_can_type

L'aide "any_can_type" crée un type qui accepte un nom de classe ou un objet avec les méthodes données. L'aide "object_can_type" crée un type qui n'accepte qu'un objet avec les méthodes données.

Ces sous-routines prennent un nom de type comme premier argument. Les arguments restants sont des paires clé/valeur. Actuellement, il s'agit uniquement de la clé "methods", qui peut être une chaîne ou une référence de tableau de chaînes. Ces chaînes sont les méthodes requises pour le type.

L'argument du nom de type peut être omis pour créer un type anonyme.

enum

Ceci crée un type qui accepte une chaîne correspondant à une liste donnée de valeurs acceptables.

Le premier argument est le nom du type. Les arguments restants sont des paires clé/valeur. Actuellement, il s'agit uniquement de la clé "values". Il doit s'agir d'une référence de tableau des valeurs de chaînes acceptables.

L'argument du nom de type peut être omis pour créer un type anonyme.

intersection

Ceci crée un type qui est l'intersection de deux types ou plus. Une union n'accepte que les valeurs qui correspondent à tous ses types sous-jacents.

Le premier argument est le nom du type. Les arguments restants sont des paires clé/valeur. Actuellement, il s'agit uniquement de la clé "of". Il doit s'agir d'une référence de tableau de types.

L'argument du nom de type peut être omis pour créer un type anonyme.

union

Ceci crée un type qui est l'union de deux types ou plus. Une union accepte n'importe lequel de ses types sous-jacents.

Le premier argument est le nom du type. Les arguments restants sont des paires clé/valeur. Actuellement, il s'agit uniquement de la clé "of". Il doit s'agir d'une référence de tableau de types.

L'argument du nom de type peut être omis pour créer un type anonyme.

TYPES PARAMÉTRÉS

Vous pouvez créer un type paramétré en appelant "t" avec des paramètres supplémentaires, comme suit :

my $arrayref_of_int = t( 'ArrayRef', of => t('Int') );
my $arrayref_of_hashref_of_int = t(
    'ArrayRef',
    of => t(
        'HashRef',
        of => t('Int'),
    ),
);

La sous-routine "t" suppose que si elle reçoit plus d'un argument, elle doit rechercher le type nommé et appeler "$type->parameterize(...)" avec les arguments supplémentaires.

Si le type nommé ne peut pas être paramétré, une erreur est générée.

Vous pouvez également appeler "$type->parameterize" directement si nécessaire. Voir Specio::Constraint::Parameterizable pour plus de détails.
