DESCRIPTION

Ces macros définissent des structures de données pour différents types d'arbres : arbres splay et arbres rouge-noir.

Dans les définitions de macros, TYPE est le nom de l'identifiant d'une structure définie par l'utilisateur qui doit contenir un champ nommé FIELD et de type SPLAY_ENTRY ou RB_ENTRY. L'argument HEADNAME est le nom de l'identifiant d'une structure définie par l'utilisateur qui doit être déclarée en utilisant les macros SPLAY_HEAD() ou RB_HEAD(). L'argument NAME doit être un nom de préfixe unique pour chaque arbre défini.

Les prototypes de fonctions sont déclarés avec SPLAY_PROTOTYPE, RB_PROTOTYPE ou RB_PROTOTYPE_STATIC. Les corps de fonctions sont générés avec SPLAY_GENERATE, RB_GENERATE ou RB_GENERATE_STATIC. Pour plus d'informations sur la façon dont ces macros sont utilisées, voir les exemples ci-dessous.

ARBRE SPLAY

Un arbre splay est une structure de données auto-organisatrice. Chaque opération sur l'arbre déclenche un "splay". Le splay déplace le nœud demandé à la racine de l'arbre et rééquilibre partiellement l'arbre.

Cela présente l'avantage que la localité des requêtes entraîne des accès plus rapides car les nœuds demandés sont déplacés vers le haut de l'arbre. D'un autre côté, chaque accès déclenché entraîne des écritures en mémoire.

Le Théorème d'Équilibrage limite le temps d'accès total pour m opérations et n insertions dans un arbre initialement vide à O((m + n)lg n). Le coût amorti pour une séquence de m accès dans un arbre splay est O(lg n).

Un arbre splay est dirigé par une structure définie par la macro SPLAY_HEAD(). Une structure SPLAY_HEAD est déclarée ainsi :

SPLAY_HEAD(HEADNAME, TYPE) head;

où HEADNAME est le nom de la structure à définir, et TYPE est le type des éléments à insérer dans l'arbre.

La macro SPLAY_ENTRY déclare une structure qui permet de relier les éléments dans l'arbre.

Pour utiliser les fonctions qui manipulent la structure de l'arbre, leurs prototypes doivent être déclarés avec la macro SPLAY_PROTOTYPE, où NAME est un identifiant unique pour cet arbre particulier. L'argument TYPE est le type de la structure gérée par l'arbre. L'argument FIELD est le nom de l'élément défini par SPLAY_ENTRY().

Les corps de fonctions sont générés avec la macro SPLAY_GENERATE. Elle prend les mêmes arguments que la macro SPLAY_PROTOTYPE(), mais ne doit être utilisée qu'une seule fois.

Enfin, l'argument CMP est le nom d'une fonction utilisée pour comparer les nœuds de l'arbre entre eux. La fonction prend deux arguments de type struct TYPE *. Si le premier argument est inférieur au second, elle renvoie une valeur inférieure à zéro. S'ils sont égaux, elle renvoie zéro. Sinon, elle renvoie une valeur supérieure à zéro. La fonction de comparaison définit l'ordre des éléments de l'arbre.

La macro SPLAY_INIT initialise l'arbre référencé par head.

L'arbre splay peut également être initialisé de manière statique en utilisant la macro SPLAY_INITIALIZER de cette manière :

SPLAY_HEAD(HEADNAME, TYPE) head = SPLAY_INITIALIZER(&head);

La macro SPLAY_INSERT insère le nouvel élément elm dans l'arbre. En cas de succès, NULL est renvoyé. Si un élément correspondant existe déjà dans l'arbre, l'insertion est interrompue et un pointeur vers l'élément existant est renvoyé.

La macro SPLAY_REMOVE supprime l'élément elm de l'arbre pointé par head. En cas de succès, un pointeur vers l'élément supprimé est renvoyé. NULL est renvoyé si elm n'est pas présent dans l'arbre.

La macro SPLAY_FIND peut être utilisée pour trouver un élément spécifique dans l'arbre.

struct TYPE find, *res;
find.key = 30;
res = SPLAY_FIND(NAME, &head, &find);

Les macros SPLAY_ROOT, SPLAY_MIN, SPLAY_MAX, et SPLAY_NEXT peuvent être utilisées pour parcourir l'arbre :

for (np = SPLAY_MIN(NAME, &head); np != NULL; np = SPLAY_NEXT(NAME, &head, np))

Ou, pour plus de simplicité, la macro SPLAY_FOREACH peut être utilisée :

SPLAY_FOREACH(np, NAME, &head)

La macro SPLAY_EMPTY doit être utilisée pour vérifier si un arbre splay est vide.

ARBRE ROUGE-NOIR

Un arbre rouge-noir est un arbre binaire de recherche avec la couleur des nœuds comme propriété supplémentaire. Il satisfait un ensemble de conditions :

  1. Tout chemin de recherche de la racine à une feuille contient le même nombre de nœuds noirs,
  2. Tout nœud rouge (sauf la racine) a un parent noir,
  3. Toute feuille est noire.

Chaque opération sur un arbre rouge-noir est bornée à O(lg n). La hauteur maximale d'un arbre rouge-noir est 2lg(n+1).

Un arbre rouge-noir est dirigé par une structure définie par la macro RB_HEAD. Une structure RB_HEAD est déclarée ainsi :

RB_HEAD(HEADNAME, TYPE) head;

où HEADNAME est le nom de la structure à définir, et TYPE est le type des éléments à insérer dans l'arbre.

La macro RB_ENTRY déclare une structure qui permet de relier les éléments dans l'arbre.

Pour utiliser les fonctions qui manipulent la structure de l'arbre, leurs prototypes doivent être déclarés avec les macros RB_PROTOTYPE ou RB_PROTOTYPE_STATIC, où NAME est un identifiant unique pour cet arbre particulier. L'argument TYPE est le type de la structure gérée par l'arbre. L'argument FIELD est le nom de l'élément défini par RB_ENTRY().

Les corps de fonctions sont générés avec les macros RB_GENERATE ou RB_GENERATE_STATIC, qui prennent les mêmes arguments que les macros RB_PROTOTYPE () et RB_PROT

DESCRIPTION

Ces macros implémentent des arbres binaires de recherche pour les structures de données de type Splay, Red-Black et d'arbres d'accès.

Toutes les structures d'arbres ont la forme suivante:

struct TYPE {
	...
	struct OTHER { ... } field;
	...
};
RB_ENTRY(TYPE); /* ou SPLAY_ENTRY, ACC_ENTRY */
RB_HEAD(NAME, TYPE); /* ou SPLAY_HEAD, ACC_HEAD */

Ici, TYPE est le nom du type de structure, et field est le nom du champ de type struct OTHER dans la structure TYPE. Il doit y avoir exactement un tel champ dans chaque structure.

Il existe trois ensembles de macros distincts qui implémentent des arbres binaires de recherche. Les arbres Splay sont implémentés par les macros commençant par SPLAY_. Les arbres Red-Black sont implémentés par les macros commençant par RB_. Les arbres d'accès sont implémentés par les macros commençant par ACC_.

La différence principale entre les arbres Splay et Red-Black est que les arbres Splay ont une opération de recherche qui renvoie l'élément recherché, tandis que les arbres Red-Black sont légèrement plus lents mais garantissent une complexité O(log n).

Les macros d'arbres d'accès sont une implémentation simplifiée d'arbres binaires de recherche sans auto-équilibrage. Elles sont beaucoup plus rapides que les arbres Red-Black, mais leur performance peut se dégrader jusqu'à O(n) dans le pire des cas.

SPLAY TREES

Les macros SPLAY_ nécessitent la définition de la macro SPLAY_HEAD et de la macro SPLAY_ENTRY pour les structures d'arbres. Voici un exemple:

struct my_node {
	int key;
	SPLAY_ENTRY(my_node) link;
};
SPLAY_HEAD(my_tree, my_node);

La déclaration de la structure d'arbre peut être fait soit par une macro SPLAY_HEAD, soit par une macro SPLAY_GENERATE. La première est un type opaque, tandis que la seconde génère le code nécessaire pour manipuler un arbre de type TYPE. La macro SPLAY_GENERATE prend le nom de la tête d'arbre, le nom du type de nœud, le nom du champ SPLAY_ENTRY et une fonction de comparaison des nœuds comme arguments.

SPLAY_PROTOTYPE génère uniquement les prototypes de fonctions pour les arbres Splay.

Les macros SPLAY_FIND et SPLAY_NFIND peuvent être utilisées pour trouver un élément particulier dans l'arbre. SPLAY_FIND trouve le nœud avec la même clé que elm. SPLAY_NFIND trouve le premier nœud dont la clé est supérieure ou égale à la clé de recherche.

Les macros SPLAY_ROOT, SPLAY_MIN, SPLAY_MAX, SPLAY_NEXT, et SPLAY_PREV peuvent être utilisées pour parcourir l'arbre.

Il est possible d'utiliser les macros SPLAY_FOREACH ou SPLAY_FOREACH_REVERSE pour simplifier le parcours.

Les macros SPLAY_FOREACH_SAFE et SPLAY_FOREACH_REVERSE_SAFE parcourent l'arbre référencé par head dans un sens ou dans l'autre, respectivement, attribuant chaque élément à tour de rôle à np. Cependant, contrairement à leurs homologues non sûrs, elles permettent à la fois la suppression de np ainsi que sa libération depuis la boucle en toute sécurité sans interférer avec le parcours.

SPLAY_INIT initialise l'arbre référencé par head.

L'arbre Splay peut également être initialisé statiquement en utilisant la macro SPLAY_INITIALIZER comme suit:

SPLAY_HEAD(HEADNAME, TYPE) head = SPLAY_INITIALIZER(&head);

SPLAY_INSERT insère le nouvel élément elm dans l'arbre. En cas de succès, NULL est retourné. Si un élément correspondant existe déjà dans l'arbre, l'insertion est interrompue et un pointeur vers l'élément existant est retourné.

SPLAY_REMOVE supprime l'élément elm de l'arbre pointé par head. SPLAY_REMOVE renvoie elm.

SPLAY_EMPTY doit être utilisée pour vérifier si un arbre Splay est vide.

RED-BLACK TREES

Les macros RB_ fonctionnent de manière très similaire aux macros SPLAY_, avec la différence qu'elles implémentent des arbres Red-Black qui garantissent une complexité O(log n) pour toutes les opérations.

La définition d'une structure d'arbre Red-Black typique ressemble à ceci:

struct my_node {
	int key;
	RB_ENTRY(my_node) link;
};
RB_HEAD(my_tree, my_node);

La déclaration de la structure d'arbre peut être fait soit par une macro RB_HEAD, soit par une macro RB_GENERATE. La première est un type opaque, tandis que la seconde génère le code nécessaire pour manipuler un arbre de type TYPE. La macro RB_GENERATE prend le nom de la tête d'arbre, le nom du type de nœud, le nom du champ RB_ENTRY et une fonction de comparaison des nœuds comme arguments.

RB_PROTOTYPE génère uniquement les prototypes de fonctions pour les arbres Red-Black.

La fonction de comparaison CMP doit comparer deux nœuds struct TYPE *. Elle doit retourner une valeur négative si le premier nœud est plus petit que le second, zéro s'ils sont égaux, et une valeur positive si le premier nœud est plus grand que le second.

L'utilisation des macros RB_HEAD et RB_ENTRY est fortement déconseillée. Préférez l'utilisation des macros RB_GENERATE et RB_PROTOTYPE.

La macro RB_INIT initialise l'arbre référencé par head.

L'arbre Red-Black peut également être initialisé statiquement en utilisant la macro RB_INITIALIZER comme suit:

RB_HEAD(HEADNAME, TYPE) head = RB_INITIALIZER(&head);

RB_INSERT insère le nouvel élément elm dans l'arbre. En cas de succès, NULL est retourné. Si un élément correspondant existe déjà dans l'arbre, l'insertion est interrompue et un pointeur vers l'élément existant est retourné.

RB_REMOVE supprime l'élément elm de l'arbre pointé par head. RB_REMOVE renvoie elm.

Les macros RB_FIND et RB_NFIND peuvent être utilisées pour trouver un élément particulier dans l'arbre. RB_FIND trouve le nœud avec la même clé que elm. RB_NFIND trouve le premier nœud plus grand ou égal à la clé de recherche.

struct TYPE find, *res;
find.key = 30;
res = RB_FIND(NAME, &head, &find);

Les macros RB_ROOT, RB_MIN, RB_MAX, RB_NEXT, et RB_PREV peuvent être utilisées pour parcourir l'arbre:

for (np = RB_MIN(NAME, &head); np != NULL; np = RB_NEXT(NAME, &head, np))

Ou, pour plus de simplicité, on peut utiliser les macros RB_FOREACH ou RB_FOREACH_REVERSE:

RB_FOREACH(np, NAME, &head)

Les macros RB_FOREACH_SAFE et RB_FOREACH_REVERSE_SAFE parcourent l'arbre référencé par head dans un sens ou dans l'autre, respectivement, attribuant chaque élément à tour de rôle à np. Cependant, contrairement à leurs homologues non sûrs, elles permettent à la fois la suppression de np ainsi que sa libération depuis la boucle en toute sécurité sans interférer avec le parcours.

RB_EMPTY doit être utilisée pour vérifier si un arbre Red-Black est vide.

EXEMPLES

L'exemple suivant montre comment déclarer un arbre Red-Black contenant des entiers. Des valeurs y sont insérées, puis le contenu de l'arbre est imprimé dans l'ordre. Enfin, la structure interne de l'arbre est imprimée.

#include <sys/tree.h>
#include <err.h>
#include <stdio.h>
#include <stdlib.h>

struct node {
	RB_ENTRY(node) entry;
	int i;
};

int	intcmp(struct node *, struct node *);
void	print_tree(struct node *);

int
intcmp(struct node *e1, struct node *e2)
{
	return (e1->i < e2->i ? -1 : e1->i > e2->i);
}

RB_HEAD(inttree, node) head = RB_INITIALIZER(&head);
RB_PROTOTYPE(inttree, node, entry, intcmp)
RB_GENERATE(inttree, node, entry, intcmp)

int testdata[] = {
	20, 16, 17, 13, 3, 6, 1, 8, 2, 4, 10, 19, 5, 9, 12, 15, 18,
	7, 11, 14
};

void
print_tree(struct node *n)
{
	struct node *left, *right;

	if (n == NULL) {
		printf("nil");
		return;
	}
	left = RB_LEFT(n, entry);
	right = RB_RIGHT(n, entry);
	if (left == NULL && right == NULL)
		printf("%d", n->i);
	else {
		printf("%d(", n->i);
		print_tree(left);
		printf(",");
		print_tree(right);
		printf(")");
	}
}

int
main(void)
{
	int i;
	struct node *n;

	for (i = 0; i < sizeof(testdata) / sizeof(testdata[0]); i++) {
		if ((n = malloc(sizeof(struct node))) == NULL)
			err(1, NULL);
		n->i = testdata[i];
		RB_INSERT(inttree, &head, n);
	}

	RB_FOREACH(n, inttree, &head) {
		printf("%d\n", n->i);
	}
	print_tree(RB_ROOT(&head));
	printf("\n");
	return (0);
}

HISTORIQUE

Les macros d'arbres sont apparues pour la première fois sous FreeBSD 4.6.

NOTES

Essayer de libérer un arbre de la manière suivante est une erreur courante:

SPLAY_FOREACH(var, NAME, &head) {
	SPLAY_REMOVE(NAME, &head, var);
	free(var);
}

Comme var est libéré, la macro FOREACH fait référence à un pointeur qui peut avoir déjà été réalloué. Un code correct nécessite une deuxième variable.

for (var = SPLAY_MIN(NAME, &head); var != NULL; var = nxt) {
	nxt = SPLAY_NEXT(NAME, &head, var);
	SPLAY_REMOVE(NAME, &head, var);
	free(var);
}
