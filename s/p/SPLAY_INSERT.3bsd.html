DESCRIPTION

These macros define data structures for different types of trees: splay trees and red-black trees.

In the macro definitions, TYPE is the user-defined structure tag that must contain a field named FIELD of type SPLAY_ENTRY or RB_ENTRY. The HEADNAME argument is the tag of a user-defined structure that must be declared using the SPLAY_HEAD() or RB_HEAD() macros. The NAME argument should be a unique prefix name for each defined tree.

Function declarations are done with SPLAY_PROTOTYPE, RB_PROTOTYPE, or RB_PROTOTYPE_STATIC. Function bodies are generated with SPLAY_GENERATE, RB_GENERATE, or RB_GENERATE_STATIC. See the examples below for further explanation of how these macros are used.

SPLAY TREES

A splay tree is a self-organizing data structure. Every operation on the tree causes a splay. The splay moves the requested node to the root of the tree and partially rebalances the tree.

This has the benefit that locality of requests results in faster queries, as requested nodes are moved to the top of the tree. On the other hand, every query causes memory writes.

The Balance Theorem bounds the total access time for m operations and n insertions into an initially empty tree as O((m + n)lg n). The amortized cost for a sequence of m accesses to a splay tree is O(lg n).

A splay tree is headed by a structure defined by the SPLAY_HEAD() macro. A SPLAY_HEAD structure is declared as follows:

SPLAY_HEAD(HEADNAME, TYPE) head;

where HEADNAME is the name of the structure to define and TYPE is the type of the elements to be inserted into the tree.

The SPLAY_ENTRY macro declares a structure that allows elements to be linked into the tree.

To use the functions that manipulate the tree structure, their prototypes must be declared with the SPLAY_PROTOTYPE macro, where NAME is a unique identifier for this particular tree. The TYPE argument is the type of the structure managing the tree. The FIELD argument is the name of the element defined by SPLAY_ENTRY().

The function bodies are generated with the SPLAY_GENERATE macro. It takes the same arguments as the SPLAY_PROTOTYPE() macro, but must be used only once.

Finally, the CMP argument is the name of a function that compares tree nodes against each other. The function takes two arguments of type struct TYPE *. If the first argument is less than the second, the function returns a value less than zero. If they are equal, it returns zero. Otherwise, it should return a value greater than zero. The comparison function defines the order of the elements in the tree.

The SPLAY_INIT macro initializes the tree pointed to by head.

The splay tree can also be initialized statically using the SPLAY_INITIALIZER macro as follows:

SPLAY_HEAD(HEADNAME, TYPE) head = SPLAY_INITIALIZER(&head);

The SPLAY_INSERT macro inserts the new element elm into the tree. If successful, it returns NULL. If an element with the same value already exists in the tree, the insertion is aborted and a pointer to the existing element is returned.

The SPLAY_REMOVE macro removes the element elm from the tree pointed to by head. If successful, it returns a pointer to the removed element. If elm is not in the tree, it returns NULL.

The SPLAY_FIND macro can be used to find a particular element in the tree.

struct TYPE find, *res;
find.key = 30;
res = SPLAY_FIND(NAME, &head, &find);

The SPLAY_ROOT, SPLAY_MIN, SPLAY_MAX, and SPLAY_NEXT macros can be used to iterate through the tree:

for (np = SPLAY_MIN(NAME, &head); np != NULL; np = SPLAY_NEXT(NAME, &head, np))

Or, for simplicity, the SPLAY_FOREACH macro can be used:

SPLAY_FOREACH(np, NAME, &head)

The SPLAY_EMPTY macro should be used to check if a splay tree is empty.

RED-BLACK TREES

A red-black tree is a binary search tree with node color as an additional property. It fulfills a number of conditions:

  1. Every path from the root to a leaf node contains the same number of black nodes.
  2. Every red node (except the root) has a black parent.
  3. Every leaf node is black.

Every operation on a red-black tree is bounded by O(lg n). The maximum height of a red-black tree is 2lg(n+1).

A red-black tree is headed by a structure defined by the RB_HEAD macro. An RB_HEAD structure is declared as follows:

RB_HEAD(HEADNAME, TYPE) head;

where HEADNAME is the name of the structure to define and TYPE is the type of the elements to be inserted into the tree.

The RB_ENTRY macro declares a structure that allows elements to be linked into the tree.

To use the functions that manipulate the tree structure, their prototypes must be declared with the RB_PROTOTYPE or RB_PROTOTYPE_STATIC macros, where NAME is a unique identifier for this particular tree. The TYPE argument is the type of the structure managing the tree. The FIELD argument is the name of the element defined by RB_ENTRY().

The function bodies are generated with the RB_GENERATE or RB_GENERATE_STATIC macros. These macros take the same arguments as the RB_PROTOTYPE() and RB_GENERATE() macros.

DESCRIPTION

These macros provide an implementation of red-black trees. The implementation is described in the paper "Implementing a Generalized Tree Data Structure" by Jeff Bonwick, but uses the CLRS algorithm for red-black trees.

A red-black tree is a binary search tree with nodes that are colored red or black. The colors are used to ensure that the tree remains balanced, i.e., that the longest path from the root to a leaf is no more than twice as long as the shortest path. The balancing is achieved by requiring that all possible paths from the root to the leaves obey a set of properties:

  • Each node is either red or black.
  • The root is black.
  • All leaves (NIL) are black.
  • If a node is red, then both its children are black.
  • Every simple path from a given node to any of its descendant leaves contains the same number of black nodes.

The tree macros are defined in the <sys/tree.h> header file.

To use the tree macros, the structure that holds the tree nodes must contain an entry of type RB_ENTRY(type). This entry holds the pointers to the children and the parent, as well as the node's color.

The RB_HEAD() macro declares the head structure for the tree. The first argument is the name of the tree head structure, and the second argument is the structure type of the nodes in the tree. It should be used once per tree.

The RB_PROTOTYPE() macro declares the prototype for the tree functions. The arguments are the tree name, the node type, the name of the RB_ENTRY field within the node structure, and the comparison function.

The RB_GENERATE() macro generates the implementation of the tree functions. It takes the same arguments as RB_PROTOTYPE(). This macro should be used once in one source file in your project.

The RB_INSERT() macro inserts the new element elm into the tree. It returns NULL on success, or a pointer to the existing element if a matching element is already present in the tree.

The RB_REMOVE() macro removes the element elm from the tree pointed to by head. It returns elm.

The RB_FIND() and RB_NFIND() macros can be used to find a particular element in the tree. RB_FIND() finds the node with the same key as elm. RB_NFIND() finds the first node whose key is greater than or equal to the search key.

The RB_LOOKUP() macro is similar to RB_FIND(), but it takes the key directly as an argument instead of a pointer to a structure containing the key.

The RB_ROOT(), RB_MIN(), RB_MAX(), RB_NEXT(), and RB_PREV() macros can be used to traverse the tree:

  • RB_ROOT() returns the root of the tree.
  • RB_MIN() returns the smallest element in the tree.
  • RB_MAX() returns the largest element in the tree.
  • RB_NEXT() returns the next larger element after elm.
  • RB_PREV() returns the next smaller element before elm.

The RB_FOREACH() and RB_FOREACH_REVERSE() macros provide simpler ways to iterate over the elements of the tree in ascending or descending order, respectively.

The RB_FOREACH_SAFE() and RB_FOREACH_REVERSE_SAFE() macros are similar to their unsafe counterparts, but they allow safe removal of elements during iteration.

The RB_INSERT_AFTER() and RB_INSERT_BEFORE() macros insert a new element elm into the tree immediately after or before the specified listelm, respectively.

The RB_EMPTY() macro should be used to check whether a red-black tree is empty.

The comparison function CMP is used to compare two nodes. It must return a negative value if the first argument is less than the second, zero if they are equal, and a positive value otherwise. The comparison function defines the order of the tree elements.

The RB_INIT() macro initializes the tree referenced by head.

The red-black tree can also be initialized statically by using the RB_INITIALIZER() macro like this:

RB_HEAD(HEADNAME, TYPE) head = RB_INITIALIZER(&head);

The RB_INSERT() macro inserts the new element elm into the tree. Upon success, NULL is returned. If a matching element already exists in the tree, the insertion is aborted, and a pointer to the existing element is returned.

The RB_REMOVE() macro removes the element elm from the tree pointed by head. RB_REMOVE() returns elm.

The RB_FIND() and RB_NFIND() macros can be used to find a particular element in the tree. RB_FIND() finds the node with the same key as elm. RB_NFIND() finds the first node greater than or equal to the search key.

struct TYPE find, *res;
find.key = 30;
res = RB_FIND(NAME, &head, &find);

The RB_ROOT(), RB_MIN(), RB_MAX(), RB_NEXT(), and RB_PREV() macros can be used to traverse the tree:

for (np = RB_MIN(NAME, &head); np != NULL; np = RB_NEXT(NAME, &head, np))

Or, for simplicity, one can use the RB_FOREACH() or RB_FOREACH_REVERSE() macros:

RB_FOREACH(np, NAME, &head)

The macros RB_FOREACH_SAFE() and RB_FOREACH_REVERSE_SAFE() traverse the tree referenced by head in a forward or reverse direction respectively, assigning each element in turn to np. However, unlike their unsafe counterparts, they permit both the removal of np as well as freeing it from within the loop safely without interfering with the traversal.

The RB_EMPTY() macro should be used to check whether a red-black tree is empty.

EXAMPLES

The following example demonstrates how to declare a red-black tree holding integers. Values are inserted into it and the contents of the tree are printed in order. Lastly, the internal structure of the tree is printed.

#include <sys/tree.h>
#include <err.h>
#include <stdio.h>
#include <stdlib.h>

struct node {
	RB_ENTRY(node) entry;
	int i;
};

int	intcmp(struct node *, struct node *);
void	print_tree(struct node *);

int
intcmp(struct node *e1, struct node *e2)
{
	return (e1->i < e2->i ? -1 : e1->i > e2->i);
}

RB_HEAD(inttree, node) head = RB_INITIALIZER(&head);
RB_PROTOTYPE(inttree, node, entry, intcmp)
RB_GENERATE(inttree, node, entry, intcmp)

int testdata[] = {
	20, 16, 17, 13, 3, 6, 1, 8, 2, 4, 10, 19, 5, 9, 12, 15, 18,
	7, 11, 14
};

void
print_tree(struct node *n)
{
	struct node *left, *right;

	if (n == NULL) {
		printf("nil");
		return;
	}
	left = RB_LEFT(n, entry);
	right = RB_RIGHT(n, entry);
	if (left == NULL && right == NULL)
		printf("%d", n->i);
	else {
		printf("%d(", n->i);
		print_tree(left);
		printf(",");
		print_tree(right);
		printf(")");
	}
}

int
main(void)
{
	int i;
	struct node *n;

	for (i = 0; i < sizeof(testdata) / sizeof(testdata[0]); i++) {
		if ((n = malloc(sizeof(struct node))) == NULL)
			err(1, NULL);
		n->i = testdata[i];
		RB_INSERT(inttree, &head, n);
	}

	RB_FOREACH(n, inttree, &head) {
		printf("%d\n", n->i);
	}
	print_tree(RB_ROOT(&head));
	printf("\n");
	return (0);
}

HISTORY

NOTES

Trying to free a tree in the following way is a common error:

SPLAY_FOREACH(var, NAME, &head) {
	SPLAY_REMOVE(NAME, &head, var);
	free(var);
}
free(head);

Since var is free'd, the FOREACH() macro refers to a pointer that may have been reallocated already. Proper code needs a second variable.

for (var = SPLAY_MIN(NAME, &head); var != NULL; var = nxt) {
	nxt = SPLAY_NEXT(NAME, &head, var);
	SPLAY_REMOVE(NAME, &head, var);
	free(var);
}
