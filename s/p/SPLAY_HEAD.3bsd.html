DESCRIPTION

Ces macros définissent des structures de données pour différents types d'arbres : arbres splay et arbres rouge-noir.

Dans les définitions de macros, TYPE est le tag d'une structure définie par l'utilisateur qui doit contenir un champ nommé FIELD de type SPLAY_ENTRY ou RB_ENTRY. L'argument HEADNAME est le tag d'une structure définie par l'utilisateur qui doit être déclarée en utilisant les macros SPLAY_HEAD() ou RB_HEAD(). L'argument NAME doit être un nom de préfixe unique pour chaque arbre défini.

Les prototypes de fonctions sont déclarés avec SPLAY_PROTOTYPE, RB_PROTOTYPE ou RB_PROTOTYPE_STATIC. Les corps des fonctions sont générés avec SPLAY_GENERATE, RB_GENERATE ou RB_GENERATE_STATIC. Voir les exemples ci-dessous pour une explication plus détaillée de l'utilisation de ces macros.

SPLAY TREES

Un arbre splay est une structure de données auto-réorganisatrice. Chaque opération sur l'arbre provoque un splay. Le splay déplace le nœud demandé vers la racine de l'arbre et rééquilibre partiellement l'arbre.

Il présente l'avantage que la localité des requêtes entraîne des recherches plus rapides car les nœuds demandés sont déplacés vers le haut de l'arbre. D'un autre côté, chaque recherche entraîne des écritures en mémoire.

Le Théorème d'Équilibrage limite le temps d'accès total pour m opérations et n insertions dans un arbre initialement vide à O((m + n)lg n). Le coût amorti d'une séquence de m accès à un arbre splay est O(lg n).

Un arbre splay est dirigé par une structure définie par la macro SPLAY_HEAD. Une structure SPLAY_HEAD est déclarée comme suit :

SPLAY_HEAD(HEADNAME, TYPE) head;

où HEADNAME est le nom de la structure à définir et struct TYPE est le type des éléments insérés dans l'arbre.

La macro SPLAY_ENTRY déclare une structure qui permet de connecter les éléments dans l'arbre.

Pour utiliser les fonctions qui manipulent la structure de l'arbre, leurs prototypes doivent être déclarés avec la macro SPLAY_PROTOTYPE, où NAME est un identifiant unique pour cet arbre particulier. L'argument TYPE est le type de la structure qui gère l'arbre. L'argument FIELD est le nom de l'élément défini par SPLAY_ENTRY.

Les corps des fonctions sont générés avec la macro SPLAY_GENERATE. Elle prend les mêmes arguments que la macro SPLAY_PROTOTYPE mais ne doit être utilisée qu'une seule fois.

Enfin, l'argument CMP est le nom d'une fonction utilisée pour comparer les nœuds de l'arbre entre eux. La fonction prend deux arguments de type struct TYPE *. Si le premier argument est inférieur au second, la fonction renvoie une valeur négative. S'ils sont égaux, elle renvoie zéro. Sinon, elle renvoie une valeur positive. La fonction de comparaison définit l'ordre des éléments de l'arbre.

La macro SPLAY_INIT initialise l'arbre référencé par head.

L'arbre splay peut également être initialisé statiquement en utilisant la macro SPLAY_INITIALIZER comme ceci :

SPLAY_HEAD(HEADNAME, TYPE) head = SPLAY_INITIALIZER(&head);

La macro SPLAY_INSERT insère le nouvel élément elm dans l'arbre. Une fois l'opération réussie, elle renvoie NULL. Si un élément correspondant existe déjà dans l'arbre, l'insertion est annulée et un pointeur vers cet élément existant est renvoyé.

La macro SPLAY_REMOVE supprime l'élément elm de l'arbre pointé par head. Une fois l'opération réussie, elle renvoie un pointeur vers l'élément supprimé. Si elm n'est pas présent dans l'arbre, elle renvoie NULL.

La macro SPLAY_FIND peut être utilisée pour trouver un élément spécifique dans l'arbre.

struct TYPE find, *res;
find.key = 30;
res = SPLAY_FIND(NAME, &head, &find);

Les macros SPLAY_ROOT(), SPLAY_MIN(), SPLAY_MAX() et SPLAY_NEXT() peuvent être utilisées pour parcourir l'arbre :

for (np = SPLAY_MIN(NAME, &head); np != NULL; np = SPLAY_NEXT(NAME, &head, np))

Ou, pour plus de simplicité, on peut utiliser la macro SPLAY_FOREACH :

SPLAY_FOREACH(np, NAME, &head)

La macro SPLAY_EMPTY doit être utilisée pour vérifier si un arbre splay est vide.

RED-BLACK TREES

Un arbre rouge-noir est un arbre de recherche binaire avec la couleur des nœuds comme propriété supplémentaire. Il garantit une série de conditions :

  1. Tout chemin de la racine à une feuille est constitué du même nombre de nœuds noirs,
  2. Chaque nœud rouge (sauf la racine) a un parent noir,
  3. Chaque nœud feuille est noir.

Chaque opération sur un arbre rouge-noir est limitée à O(lg n). La hauteur maximale d'un arbre rouge-noir est 2lg (n + 1).

Un arbre rouge-noir est dirigé par une structure définie par la macro RB_HEAD. Une structure RB_HEAD est déclarée comme suit :

RB_HEAD(HEADNAME, TYPE) head;

où HEADNAME est le nom de la structure à définir et struct TYPE est le type des éléments insérés dans l'arbre.

La macro RB_ENTRY déclare une structure qui permet de connecter les éléments dans l'arbre.

Pour utiliser les fonctions qui manipulent la structure de l'arbre, leurs prototypes doivent être déclarés avec les macros RB_PROTOTYPE ou RB_PROTOTYPE_STATIC, où NAME est un identifiant unique pour cet arbre particulier. L'argument TYPE est le type de la structure qui gère l'arbre. L'argument FIELD est le nom de l'élément défini par RB_ENTRY.

Les corps des fonctions sont générés avec les macros RB_GENERATE ou RB_GENERATE_STATIC, qui prennent les mêmes arguments que les macros RB_PROTOTYPE() et RB_PROT

DESCRIPTION

These macros implement the splay tree algorithm presented in D. Sleator and R. Tarjan's paper "Self-adjusting binary search trees". The implementation used herein is that of the red-black trees.

A red-black tree is a binary search tree where each node has a color, red or black, assigned to it according to the following rules:

  • Every node is either red or black.
  • The root is black.
  • Every leaf (NULL) is black.
  • If a node is red, then both its children are black.
  • Every simple path from a given node to any of its descendant leaves contains the same number of black nodes.

The red-black tree implementation is generic and can be used with any data structure. The data structure is required to have a pointer to its parent and its left and right children.

The RB_HEAD(HEADNAME, TYPE) macro declares the head of a red-black tree. HEADNAME is the name of the tree structure and TYPE is the name of the structure that will be stored in the tree.

The RB_PROTOTYPE(HEADNAME, TYPE, field, CMP) macro is used to declare the functions that will be used to implement the red-black tree. HEADNAME is the name of the tree structure, TYPE is the name of the structure that will be stored in the tree, field is the name of the field in TYPE that is used to link the nodes together, and CMP is the name of the comparison function.

The RB_GENERATE(HEADNAME, TYPE, field, CMP) macro is used to generate the functions that implement the red-black tree. This macro should be included in exactly one C file. It should be invoked after the RB_PROTOTYPE macro.

The field argument is the name of the macro that defines the pointer to the parent and the left and right children. This macro is defined using the RB_ENTRY() macro. The RB_ENTRY macro should only be used once per structure definition. For example:

struct myent {
	RB_ENTRY(myent) entries;
	/* other data */
};

Finally, the CMP argument is the name of a function used to compare trees' nodes with each other. The function takes two arguments of type struct TYPE *. If the first argument is smaller than the second, the function returns a value smaller than zero. If they are equal, the function returns zero. Otherwise, it should return a value greater than zero. The compare function defines the order of the tree elements.

The RB_INIT() macro initializes the tree referenced by head.

The red-black tree can also be initialized statically by using the RB_INITIALIZER() macro like this:

RB_HEAD(HEADNAME, TYPE) head = RB_INITIALIZER(&head);

The RB_INSERT() macro inserts the new element elm into the tree. Upon success, NULL is returned. If a matching element already exists in the tree, the insertion is aborted, and a pointer to the existing element is returned.

The RB_REMOVE() macro removes the element elm from the tree pointed by head. RB_REMOVE() returns elm.

The RB_FIND() and RB_NFIND() macros can be used to find a particular element in the tree. RB_FIND() finds the node with the same key as elm. RB_NFIND() finds the first node greater than or equal to the search key.

struct TYPE find, *res;
find.key = 30;
res = RB_FIND(NAME, &head, &find);

The RB_ROOT(), RB_MIN(), RB_MAX(), RB_NEXT(), and RB_PREV() macros can be used to traverse the tree:

for (np = RB_MIN(NAME, &head); np != NULL; np = RB_NEXT(NAME, &head, np))

Or, for simplicity, one can use the RB_FOREACH() or RB_FOREACH_REVERSE() macros:

RB_FOREACH(np, NAME, &head)

The macros RB_FOREACH_SAFE() and RB_FOREACH_REVERSE_SAFE() traverse the tree referenced by head in a forward or reverse direction respectively, assigning each element in turn to np. However, unlike their unsafe counterparts, they permit both the removal of np as well as freeing it from within the loop safely without interfering with the traversal.

The RB_EMPTY() macro should be used to check whether a red-black tree is empty.

EXAMPLES

The following example demonstrates how to declare a red-black tree holding integers. Values are inserted into it and the contents of the tree are printed in order. Lastly, the internal structure of the tree is printed.

#include <sys/tree.h>
#include <err.h>
#include <stdio.h>
#include <stdlib.h>

struct node {
	RB_ENTRY(node) entry;
	int i;
};

int	intcmp(struct node *, struct node *);
void	print_tree(struct node *);

int
intcmp(struct node *e1, struct node *e2)
{
	return (e1->i < e2->i ? -1 : e1->i > e2->i);
}

RB_HEAD(inttree, node) head = RB_INITIALIZER(&head);
RB_PROTOTYPE(inttree, node, entry, intcmp)
RB_GENERATE(inttree, node, entry, intcmp)

int testdata[] = {
	20, 16, 17, 13, 3, 6, 1, 8, 2, 4, 10, 19, 5, 9, 12, 15, 18,
	7, 11, 14
};

void
print_tree(struct node *n)
{
	struct node *left, *right;

	if (n == NULL) {
		printf("nil");
		return;
	}
	left = RB_LEFT(n, entry);
	right = RB_RIGHT(n, entry);
	if (left == NULL && right == NULL)
		printf("%d", n->i);
	else {
		printf("%d(", n->i);
		print_tree(left);
		printf(",");
		print_tree(right);
		printf(")");
	}
}

int
main(void)
{
	int i;
	struct node *n;

	for (i = 0; i < sizeof(testdata) / sizeof(testdata[0]); i++) {
		if ((n = malloc(sizeof(struct node))) == NULL)
			err(1, NULL);
		n->i = testdata[i];
		RB_INSERT(inttree, &head, n);
	}

	RB_FOREACH(n, inttree, &head) {
		printf("%d\n", n->i);
	}
	print_tree(RB_ROOT(&head));
	printf("\n");
	return (0);
}

NOTES

Trying to free a tree in the following way is a common error:

SPLAY_FOREACH(var, NAME, &head) {
	SPLAY_REMOVE(NAME, &head, var);
	free(var);
}
free(head);

Since var is free'd, the FOREACH() macro refers to a pointer that may have been reallocated already. Proper code needs a second variable.

for (var = SPLAY_MIN(NAME, &head); var != NULL; var = nxt) {
	nxt = SPLAY_NEXT(NAME, &head, var);
	SPLAY_REMOVE(NAME, &head, var);
	free(var);
}
