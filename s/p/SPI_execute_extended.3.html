NOM

SPI_execute_extended - exécute une commande avec des paramètres externes

SYNTAXE

int SPI_execute_extended(const char *command,
                         const SPIExecuteOptions * options)

DESCRIPTION

SPI_execute_extended exécute une commande qui peut inclure des références à des paramètres fournis extérieurement. Le texte de la commande fait référence à un paramètre par $n, et l'objet options->params (si fourni) fournit les valeurs et les informations de type pour chaque symbole de ce type. Diverses options d'exécution peuvent également être spécifiées dans la structure options.

L'objet options->params devrait normalement marquer chaque paramètre avec le drapeau PARAM_FLAG_CONST, car un plan unique est toujours utilisé pour la requête.

Si options->dest n'est pas NULL, alors les tuples de résultat sont passés à cet objet au fur et à mesure qu'ils sont générés par l'exécuteur, au lieu d'être accumulés dans SPI_tuptable. L'utilisation d'un objet DestReceiver fourni par l'appelant est particulièrement utile pour les requêtes qui peuvent générer de nombreux tuples, car les données peuvent être traitées à la volée au lieu d'être accumulées en mémoire.

ARGUMENTS

const char * command

chaîne de commande

const SPIExecuteOptions * options

structure contenant les arguments optionnels

Les appelants devraient toujours initialiser à zéro l'intégralité de la structure options, puis remplir les champs qu'ils souhaitent définir. Cela garantit la compatibilité ascendante du code, car tous les champs ajoutés à la structure dans le futur seront définis pour se comporter de manière rétrocompatible s'ils sont à zéro. Les champs actuellement disponibles dans options sont :

ParamListInfo params

structure de données contenant les types et les valeurs des paramètres de la requête ; NULL s'il n'y en a pas

bool read_only

true pour une exécution en lecture seule

bool allow_nonatomic

true autorise l'exécution non atomique des instructions CALL et DO (mais ce champ est ignoré sauf si le drapeau SPI_OPT_NONATOMIC a été passé à SPI_connect_ext)

bool must_return_tuples

si true, lève une erreur si la requête n'est pas du genre qui retourne des tuples (cela n'interdit pas le cas où elle retourne zéro tuple)

uint64 tcount

nombre maximal de lignes à retourner, ou 0 pour aucune limite

DestReceiver * dest

objet DestReceiver qui recevra tous les tuples émis par la requête ; si NULL, les tuples de résultat sont accumulés dans une structure SPI_tuptable, comme dans SPI_execute

ResourceOwner owner

Ce champ est présent pour la cohérence avec SPI_execute_plan_extended, mais il est ignoré, car le plan utilisé par SPI_execute_extended n'est jamais sauvegardé.

VALEUR DE RETOUR

La valeur de retour est la même que pour SPI_execute.

Lorsque options->dest est NULL, SPI_processed et SPI_tuptable sont définis comme dans SPI_execute. Lorsque options->dest n'est pas NULL, SPI_processed est défini à zéro et SPI_tuptable est défini à NULL. Si un compte de tuples est requis, l'objet DestReceiver de l'appelant doit le calculer.
