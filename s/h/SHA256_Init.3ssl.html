SHA256_Init(3ssl)

NOM

SHA1, SHA1_Init, SHA1_Update, SHA1_Final, SHA224, SHA224_Init, SHA224_Update, SHA224_Final, SHA256, SHA256_Init, SHA256_Update, SHA256_Final, SHA384, SHA384_Init, SHA384_Update, SHA384_Final, SHA512, SHA512_Init, SHA512_Update, SHA512_Final - Algorithme de hachage sécurisé

SYNTAXE

#include <openssl/sha.h>
unsigned char *SHA1(const unsigned char *data, size_t count, unsigned char *md_buf);
unsigned char *SHA224(const unsigned char *data, size_t count, unsigned char *md_buf);

Les fonctions suivantes ont été dépréciées depuis OpenSSL 3.0, et peuvent être entièrement masquées en définissant OPENSSL_API_COMPAT avec une valeur de version appropriée, voir openssl_user_macros(7) :

int SHA1_Init(SHA_CTX *c);
int SHA1_Update(SHA_CTX *c, const void *data, size_t len);
int SHA1_Final(unsigned char *md, SHA_CTX *c);
int SHA224_Init(SHA256_CTX *c);
int SHA224_Update(SHA256_CTX *c, const void *data, size_t len);
int SHA224_Final(unsigned char *md, SHA256_CTX *c);
int SHA256_Init(SHA256_CTX *c);
int SHA256_Update(SHA256_CTX *c, const void *data, size_t len);
int SHA256_Final(unsigned char *md, SHA256_CTX *c);
int SHA384_Init(SHA512_CTX *c);
int SHA384_Update(SHA512_CTX *c, const void *data, size_t len);
int SHA384_Final(unsigned char *md, SHA512_CTX *c);
int SHA512_Init(SHA512_CTX *c);
int SHA512_Update(SHA512_CTX *c, const void *data, size_t len);
int SHA512_Final(unsigned char *md, SHA512_CTX *c);

DESCRIPTION

Toutes les fonctions décrites sur cette page, à l'exception de SHA1(), SHA224(), SHA256(), SHA384() et SHA512(), sont dépréciées. Les applications devraient plutôt utiliser EVP_DigestInit_ex(3), EVP_DigestUpdate(3) et EVP_DigestFinal_ex(3), ou la fonction rapide en une seule étape EVP_Q_digest(3). SHA1(), SHA224(), SHA256(), SHA384(), et SHA512() peuvent continuer à être utilisées. Elles peuvent aussi être remplacées par, par exemple :

(EVP_Q_digest(d, n, md, NULL, NULL, "SHA256", NULL) ? md : NULL)

SHA-1 (Secure Hash Algorithm) est une fonction de hachage cryptographique avec une sortie de 160 bits.

SHA1() calcule la somme de contrôle du message SHA-1 des n octets à l'adresse d et la place dans md (qui doit avoir de la place pour SHA_DIGEST_LENGTH == 20 octets de sortie). Si md est NULL, la somme de contrôle est placée dans un tableau statique. Remarque : définir md à NULL n'est pas thread-safe.

Les fonctions suivantes peuvent être utilisées si le message n'est pas entièrement stocké en mémoire :

SHA1_Init() initialise une structure SHA_CTX.

SHA1_Update() peut être appelée de manière répétée avec des fragments du message à hacher (len octets à l'adresse data).

SHA1_Final() place la somme de contrôle du message dans md, qui doit avoir de la place pour SHA_DIGEST_LENGTH == 20 octets de sortie, et efface le SHA_CTX.

Les familles de fonctions SHA224, SHA256, SHA384 et SHA512 fonctionnent de la même manière que pour les fonctions SHA1. Notez que SHA224 et SHA256 utilisent un objet SHA256_CTX au lieu de SHA_CTX. SHA384 et SHA512 utilisent SHA512_CTX. Le tampon md doit avoir de la place pour la sortie de la variante SHA utilisée (définie par SHA224_DIGEST_LENGTH, SHA256_DIGEST_LENGTH, SHA384_DIGEST_LENGTH et SHA512_DIGEST_LENGTH). Notez également que, comme pour la fonction SHA1() ci-dessus, les fonctions SHA224(), SHA256(), SHA384() et SHA512() ne sont pas thread-safe si md est NULL.

VALEURS DE RETOUR

SHA1(), SHA224(), SHA256(), SHA384() et SHA512() retournent un pointeur vers la valeur de hachage.

SHA1_Init(), SHA1_Update() et SHA1_Final() et les fonctions SHA224, SHA256, SHA384 et SHA512 équivalentes retournent 1 en cas de succès, 0 sinon.

CONFORMITE

US Federal Information Processing Standard FIPS PUB 180-4 (Secure Hash Standard), ANSI X9.30
