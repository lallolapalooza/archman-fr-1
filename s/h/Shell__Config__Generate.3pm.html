Shell::Config::Generate(3) Documentation des paquets contribués Perl Shell::Config::Generate(3)

NOM

Shell::Config::Generate - Générer des configurations portables pour n'importe quel shell

VERSION

version 0.34

SYNOPSIS

Avec cette entrée en matière :

use Shell::Guess;
use Shell::Config::Generate;

my $config = Shell::Config::Generate->new;
$config->comment( 'ceci est mon fichier de configuration' );
$config->set( FOO => 'bar' );
$config->set_path(
  PERL5LIB => '/foo/bar/lib/perl5',
              '/foo/bar/lib/perl5/perl5/site',
);
$config->append_path(
  PATH => '/foo/bar/bin',
          '/bar/foo/bin',
);

Ceci :

$config->generate_file(Shell::Guess->bourne_shell, 'config.sh');

générera un fichier config.sh avec ce contenu :

# ceci est mon fichier de configuration
FOO='bar';
export FOO;
PERL5LIB='/foo/bar/lib/perl5:/foo/bar/lib/perl5/perl5/site';
export PERL5LIB;
if [ -n "$PATH" ] ; then
  PATH=$PATH:'/foo/bar/bin:/bar/foo/bin';
  export PATH
else
  PATH='/foo/bar/bin:/bar/foo/bin';
  export PATH;
fi;

et ceci :

$config->generate_file(Shell::Guess->c_shell, 'config.csh');

générera un fichier config.csh avec ce contenu :

# ceci est mon fichier de configuration
setenv FOO 'bar';
setenv PERL5LIB '/foo/bar/lib/perl5:/foo/bar/lib/perl5/perl5/site';
test "$?PATH" = 0 && setenv PATH '/foo/bar/bin:/bar/foo/bin' || setenv PATH "$PATH"/'foo/bar/bin:/bar/foo/bin';

et ceci :

$config->generate_file(Shell::Guess->cmd_shell, 'config.cmd');

générera un fichier config.cmd (script cmd.exe Windows) avec ce contenu :

rem ceci est mon fichier de configuration
set FOO=bar
set PERL5LIB=/foo/bar/lib/perl5:/foo/bar/lib/perl5/perl5/site
if defined PATH (set PATH=%PATH%;/foo/bar/bin;/bar/foo/bin) else (set PATH=/foo/bar/bin;/bar/foo/bin)

DESCRIPTION

Ce module fournit une interface pour spécifier des configurations de shell pour différents environnements de shell sans avoir à se soucier des différences archaïques entre les shells comme csh, sh, cmd.exe et command.com.

Il ne modifie pas l'environnement actuel, mais peut être utilisé pour créer des configurations de shell qui modifient l'environnement.

Ce module utilise Shell::Guess pour représenter les différents types de shells pris en charge. De cette façon, vous pouvez spécifier statiquement un ou plusieurs shells :

#!/usr/bin/perl
use Shell::Guess;
use Shell::Config::Generate;
my $config = Shell::Config::Generate->new;
# ... configuration configuration ...
$config->generate_file(Shell::Guess->bourne_shell,  'foo.sh' );
$config->generate_file(Shell::Guess->c_shell,       'foo.csh');
$config->generate_file(Shell::Guess->cmd_shell,     'foo.cmd');
$config->generate_file(Shell::Guess->command_shell, 'foo.bat');

Ceci créera des versions foo.sh et foo.csh des configurations, qui peuvent être sourcées comme suit :

#!/bin/sh
. ./foo.sh

ou

#!/bin/csh
source foo.csh

Il crée également des fichiers .cmd et .bat avec la même configuration qui peuvent être utilisés sous Windows. La configuration peut être importée dans votre shell simplement en exécutant ces fichiers :

C:\> foo.cmd

ou

C:\> foo.bat

Alternativement, vous pouvez utiliser le shell qui a appelé votre script Perl en utilisant la méthode Shell::Guess->running_shell, et écrire la sortie sur la sortie standard.

#!/usr/bin/perl
use Shell::Guess;
use Shell::Config::Generate;
my $config = Shell::Config::Generate->new;
# ... configuration configuration ...
print $config->generate(Shell::Guess->running_shell);

Si vous utilisez ce modèle, vous pouvez évaluer la sortie de votre script en utilisant la méthode backticks de votre shell pour importer la configuration dans votre shell.

#!/bin/sh
eval `script.pl`

ou

#!/bin/csh
eval `script.pl`

CONSTRUCTEUR

new

my $config = Shell::Config::Generate->new;

crée une instance de Shell::Config::Generate.

MÉTHODES

Il existe deux types de méthodes d'instance pour cette classe :

  • modificateurs

    ajustent la configuration dans un format portable interne

  • générateurs

    génèrent des configurations de shell dans un format spécifique compte tenu du format portable interne stocké dans l'instance.

L'idée est que vous pouvez apporter plusieurs modifications à l'environnement sans vous soucier des différents shells, puis lorsque vous êtes prêt, vous pouvez créer des versions spécifiques de ces modifications en utilisant les générateurs.

Cela peut être utile pour les administrateurs système qui doivent prendre en charge des utilisateurs utilisant différents shells, avec un seul script de génération de configuration écrit en Perl.

set

$config->set( $name => $value );

Définit une variable d'environnement.

set_path

$config->set_path( $name => @values );

Définit une variable d'environnement qui est stockée dans un format de type chemin standard (comme PATH ou PERL5LIB). Dans l'environnement UNIX, il s'agit d'une liste séparée par des deux-points stockée sous forme de chaîne. Sous Windows, il s'agit d'une liste séparée par des points-virgules stockée sous forme de chaîne. Vous pouvez faire la même chose en utilisant la méthode "set", mais si vous le faites, vous devez déterminer le séparateur correct.

Ceci remplacera la valeur existante de la variable d'environnement si elle existe déjà.

append_path

$config->append_path( $name => @values );

Ajoute à une variable d'environnement qui est stockée dans un format de type chemin standard. Ceci créera une nouvelle variable d'environnement si elle n'existe pas, ou ajoutera à une valeur existante.

prepend_path

$config->prepend_path( $name => @values );

Ajoute à une variable d'environnement qui est stockée dans un format de type chemin standard. Ceci créera une nouvelle variable d'environnement si elle n'existe pas, ou ajoutera à une valeur existante.

comment

$config->comment( $comment );

Génère un commentaire dans le format approprié.

notez que l'inclusion de commentaires dans votre configuration peut signifier qu'elle ne fonctionnera pas avec la méthode backticks "eval" pour importer des configurations dans votre shell.

shebang

$config->shebang;
$config->shebang($location);

Génère un shebang au début de la configuration, la rendant appropriée pour une utilisation en tant que script. Pour les shells non UNIX, il sera ignoré. Si spécifié, $location sera utilisé comme emplacement de l'interpréteur. S'il n'est pas spécifié, l'emplacement par défaut du shell sera utilisé.

notez que le shebang dans votre configuration peut signifier qu'elle ne fonctionnera pas avec la méthode backticks "eval" pour importer des configurations dans votre shell.

echo_off

$config->echo_off;

Pour les configurations DOS/Windows ("command.com" ou "cmd.exe"), émettez ceci comme première ligne de la configuration :

@echo off

echo_on

$config->echo_on;

Désactive le echo off (c'est-à-dire, ne met rien au début de la configuration) pour les configurations DOS/Windows ("command.com" ou "cmd.exe").

set_alias

$config->set_alias( $alias => $command )

Définit l'alias donné sur la commande donnée.

Remarque : certains anciens shells ne prennent pas en charge les alias, comme les originaux.

Shell::Config::Generate(3pm)

NAME

Shell::Config::Generate - generate shell configuration for common shells

VERSION

This document describes version 0.34 of Shell::Config::Generate.

SYNOPSIS

    use Shell::Config::Generate;

    my $config = Shell::Config::Generate->new(
        aliases => {
            'll' => 'ls -CF',
            'la' => 'ls -A',
        },
        paths => [qw(
            /usr/local/bin
            /opt/local/bin
        )],
        path_sep => ':', # Or ';',
        debug => 1,
    );

    # Guess the shell that's running this script
    my $shell = Shell::Guess->new;
    my $command_text = $config->generate($shell);
    print $command_text;

    # Or generate for a specific shell
    my $command_text = $config->generate('tcsh');
    print $command_text;

    # Or write to a file
    $config->generate_file('bash', 'my_bash_config.sh');

    # Escape paths
    my @escaped = cmd_escape_path(@path_list);
    my @escaped = powershell_escape_path(@path_list);
    my @escaped = win32_space_be_gone(@path_list);

DESCRIPTION

This module generates shell configuration code for various shells. It can generate code for aliasing commands, prepending or appending directories to the PATH environment variable, and exporting variables.

This module relies on Shell::Guess to determine the current shell, or to guess it if you are running it in a different shell.

The primary goal is to generate files which can be sourced by the user's shell initialization files (e.g. ~/.bashrc, ~/.tcshrc, ~/.config/fish/config.fish).

Some shells do not support aliases directly, for example the standard bourne shell. In such cases, this module will try to emulate aliases using shell functions.

For cmd.exe and command.com, aliases are implemented as functions. This is because cmd.exe and command.com do not support aliases in the same way as bourne shell. They do not support passing arguments to aliases.

For PowerShell, a simple function is used instead of an alias so that arguments may be specified.

CONSTRUCTOR

new

my $config = Shell::Config::Generate->new(%args);

Creates a new Shell::Config::Generate object. The following arguments are accepted:

aliases
A hash reference where keys are the alias names and values are the commands to execute. For example: 
    aliases => {
        'll' => 'ls -CF',
        'la' => 'ls -A',
    }
paths
An array reference of paths to add to the PATH environment variable. These will be prepended to the PATH by default. If you want them appended, you will need to configure that separately, or use the path_sep option carefully.
path_sep
The path separator to use. Defaults to the shell's default (usually ':' for Unix, ';' for Windows). See set_path_sep.
exports
A hash reference of environment variables to export. For example: 
    exports => {
        'MY_VARIABLE' => 'some_value',
        'ANOTHER_VAR' => $some_other_value,
    }
debug
If true, enables debug output. Defaults to false.
comment
A string that will be added as a comment at the beginning of the generated configuration file. Defaults to undef.

METHODS

set_path_sep

$config->set_path_sep( $sep );

Use $sep as the path separator instead of the shell default path separator (generally ":" for Unix shells and ";" for Windows shells).

Not all characters are supported, it is usually best to stick with the shell default or to use ":" or ";".

generate

my $command_text = $config->generate;
my $command_text = $config->generate( $shell );

Generate shell configuration code for the given shell. $shell is an instance of Shell::Guess. If $shell is not provided, then this method will use Shell::Guess to guess the shell that called your perl script.

You can also pass in the shell name as a string for $shell. This should correspond to the appropriate name_shell from Shell::Guess. So for csh you would pass in "c" and for tcsh you would pass in "tc", etc.

generate_file

$config->generate_file( $shell, $filename );

Generate shell configuration code for the given shell and write it to the given file. $shell is an instance of Shell::Guess. If there is an IO error it will throw an exception.

FUNCTIONS

win32_space_be_gone

my @new_path_list = win32_space_be_gone( @orig_path_list );

On "MSWin32" and "cygwin":

Given a list of directory paths (or filenames), this will return an equivalent list of paths pointing to the same file system objects without spaces. To do this Win32::GetShortPathName() is used on to find alternative path names without spaces.

NOTE that this breaks when Windows is told not to create short ("8+3") filenames; see http://www.perlmonks.org/?node_id=333930 for a discussion of this behaviour.

In addition, on just "Cygwin":

The input paths are first converted from POSIX to Windows paths using "Cygwin::posix_to_win_path", and then converted back to POSIX paths using "Cygwin::win_to_posix_path".

Elsewhere:

Returns the same list passed into it

cmd_escape_path

my @new_path_list = cmd_escape_path( @orig_path_list )

Given a list of directory paths (or filenames), this will return an equivalent list of paths escaped for cmd.exe and command.com.

powershell_escape_path

my @new_path_list = powershell_escape_path( @orig_path_list )

Given a list of directory paths (or filenames), this will return an equivalent list of paths escaped for PowerShell.

CAVEATS

The test suite tests this module's output against the actual shells that should understand them, if they can be found in the path. You can generate configurations for shells which are not available (for example "cmd.exe" configurations from UNIX or bourne configurations under windows), but the test suite only tests them if they are found during the build of this module.

The implementation for "csh" depends on the external command "test". As far as I can tell "test" should be available on all modern flavors of UNIX which are using "csh". If anyone can figure out how to prepend or append to path type environment variable without an external command in "csh", then a patch would be appreciated.

The incantation for prepending and appending elements to a path on csh probably deserve a comment here. It looks like this:

test "$?PATH" = 0 && setenv PATH '/foo/bar/bin:/bar/foo/bin' || setenv PATH "$PATH":'/foo/bar/bin:/bar/foo/bin';
•
one line

The command is all on one line, and doesn't use if, which is probably more clear and ideomatic. This for example, might make more sense:

if ( $?PATH == 0 ) then
  setenv PATH '/foo/bar/bin:/bar/foo/bin'
else
  setenv PATH "$PATH":'/foo/bar/bin:/bar/foo/bin'
endif

However, this only works if the code interpreted using the csh "source" command or is included in a csh script inline. If you try to invoke this code using csh "eval" then it will helpfully convert it to one line and if does not work under csh in one line.

There are probably more clever or prettier ways to append/prepend path environment variables as I am not a shell programmer. Patches welcome.

Only UNIX (bourne, bash, csh, ksh, fish and their derivatives) and Windows (command.com, cmd.exe and PowerShell) are supported so far.

Fish shell support should be considered a tech preview. The Fish shell itself is somewhat in flux, and thus some tests are skipped for the Fish shell since behavior is different for different versions. In particular, new lines in environment variables may not work on newer versions.

Patches welcome for your favorite shell / operating system.
