Module Scanf

Fonctions d'entrée formatées.

Attention synchronized_access. Les accès non synchronisés à Scanning.in_channel sont une erreur de programmation.

Introduction

Entrée fonctionnelle avec chaînes de format

Le module Scanf fournit des fonctions d'entrée formatées ou des analyseurs (scanners).

Les fonctions d'entrée formatées peuvent lire à partir de n'importe quel type d'entrée, y compris des chaînes de caractères, des fichiers ou tout ce qui peut retourner des caractères. La source de caractères la plus générale est nommée canal d'entrée formaté (ou tampon d'analyse) et a le type Scanf.Scanning.in_channel . La fonction d'entrée formatée la plus générale lit à partir de n'importe quel tampon d'analyse et est nommée bscanf .

D'une manière générale, les fonctions d'entrée formatées ont 3 arguments :

-le premier argument est une source de caractères pour l'entrée,

-le second argument est une chaîne de format qui spécifie les valeurs à lire,

-le troisième argument est une fonction réceptrice qui est appliquée aux valeurs lues.

Par conséquent, un appel typique à la fonction d'entrée formatée Scanf.bscanf est bscanf ic fmt f , où :

- ic est une source de caractères (typiquement un canal d'entrée formaté de type Scanf.Scanning.in_channel ),

- fmt est une chaîne de format (les mêmes chaînes de format que celles utilisées pour imprimer du matériel avec le module Printf ou Format ),

- f est une fonction qui a autant d'arguments qu'il y a de valeurs à lire dans l'entrée selon fmt .

Un exemple simple

Comme suggéré ci-dessus, l'expression bscanf ic "%d" f lit un entier décimal n à partir de la source de caractères ic et retourne f n .

Par exemple,

-si nous utilisons stdin comme source de caractères ( Scanf.Scanning.stdin est le canal d'entrée formaté prédéfini qui lit depuis l'entrée standard),

-si nous définissons le récepteur f comme let f x = x + 1 ,

alors bscanf Scanning.stdin "%d" f lit un entier n depuis l'entrée standard et retourne f n (c'est-à-dire n + 1 ). Ainsi, si nous évaluons bscanf stdin "%d" f , et que nous entrons 41 au clavier, le résultat obtenu est 42 .

L'entrée formatée comme fonctionnalité fonctionnelle

La facilité d'analyse (scanning) d'OCaml rappelle la fonctionnalité C correspondante. Cependant, elle est aussi largement différente, plus simple, et pourtant plus puissante : les fonctions d'entrée formatées sont des fonctionnels d'ordre supérieur et le mécanisme de passage de paramètres est juste l'application de fonction régulière, pas le mécanisme basé sur l'assignation de variable qui est typique pour l'entrée formatée dans les langages impératifs ; les chaînes de format OCaml comportent également des ajouts utiles pour définir facilement des jetons complexes ; comme prévu dans un langage de programmation fonctionnelle, les fonctions d'entrée formatées supportent également le polymorphisme, en particulier une interaction arbitraire avec des analyseurs définis par l'utilisateur polymorphes. De plus, la facilité d'entrée formatée d'OCaml est entièrement vérifiée par type à la compilation.

Accès non synchronisés

Les accès non synchronisés à un Scanf.Scanning.in_channel peuvent conduire à un état invalide de Scanf.Scanning.in_channel . Ainsi, les accès concurrents aux Scanf.Scanning.in_channel doivent être synchronisés (par exemple avec un Mutex.t ).

Canal d'entrée formaté

module Scanning : sig end

Type des fonctions d'entrée formatées

type ('a, 'b, 'c, 'd) scanner = ('a, Scanning.in_channel, 'b, 'c, 'a -> 'd, 'd) format6 -> 'c

Le type des analyseurs d'entrée formatée : ('a, 'b, 'c, 'd) scanner est le type d'une fonction d'entrée formatée qui lit à partir d'un certain canal d'entrée formaté selon une certaine chaîne de format ; plus précisément, si scan est une fonction d'entrée formatée, alors scan
ic fmt f applique f à tous les arguments spécifiés par la chaîne de format fmt , lorsque scan a lu ces arguments à partir du canal d'entrée formaté Scanf.Scanning.in_channel ic .

Par exemple, la fonction Scanf.scanf ci-dessous est de type ('a, 'b, 'c, 'd) scanner , car c'est une fonction d'entrée formatée qui lit à partir de Scanf.Scanning.stdin : scanf fmt f applique f aux arguments spécifiés par fmt , lisant ces arguments depuis stdin comme prévu.

Si le format fmt contient des indications %r , les fonctions d'entrée correspondantes doivent être fournies avant la fonction réceptrice f . Par exemple, si read_elem est une fonction d'entrée pour des valeurs de type t , alors bscanf ic "%r;" read_elem f lit une valeur v de type t suivie d'un caractère ';' , et retourne f v .

Depuis 3.10

type ('a, 'b, 'c, 'd) scanner_opt = ('a, Scanning.in_channel, 'b, 'c, 'a -> 'd option, 'd) format6 -> 'c

exception Scan_failure of string

Lorsque l'entrée ne peut pas être lue selon la spécification de la chaîne de format, les fonctions d'entrée formatées lèvent généralement l'exception Scan_failure .

La fonction d'entrée formatée générale

val bscanf : Scanning.in_channel -> ('a, 'b, 'c, 'd) scanner

bscanf ic fmt r1 ... rN f lit des caractères du canal d'entrée formaté Scanf.Scanning.in_channel ic et les convertit en valeurs selon la chaîne de format fmt . Comme étape finale, la fonction réceptrice f est appliquée aux valeurs lues et donne le résultat de l'appel bscanf .

Par exemple, si f est la fonction fun s i -> i + 1 , alors Scanf.sscanf "x = 1" "%s = %i" f retourne 2 .

Les arguments r1 à rN sont des fonctions d'entrée utilisateur qui lisent l'argument correspondant aux conversions %r spécifiées dans la chaîne de format.

val bscanf_opt : Scanning.in_channel -> ('a, 'b, 'c, 'd) scanner_opt

Identique à Scanf.bscanf , mais retourne None en cas d'échec de l'analyse.

Depuis 5.0

Description de la chaîne de format

La chaîne de format est une chaîne de caractères qui contient trois types d'objets :

-des caractères littéraux, qui sont simplement mis en correspondance avec les caractères de l'entrée (avec un cas spécial pour l'espace et le saut de ligne, voir Scanf.space ),

-des spécifications de conversion, chacune provoquant la lecture et la conversion d'un argument pour la fonction f (voir Scanf.conversion ),

-des indications d'analyse pour spécifier les limites des jetons (voir l'analyse de Scanf.indication ).

Le caractère espace dans les chaînes de format

Comme mentionné ci-dessus, un caractère littéral dans la chaîne de format est simplement mis en correspondance avec le caractère suivant de l'entrée ; cependant, deux caractères font exception à cette règle : le caractère espace ( ' ' ou code ASCII 32) et le caractère saut de ligne ( '\n' ou code ASCII 10). Un espace ne correspond pas à un seul caractère espace, mais à n'importe quelle quantité d'espaces blancs ('whitespace') dans l'entrée. Plus précisément, un espace dans la chaîne de format correspond à n'importe quel nombre de caractères tabulation, espace, saut de ligne et retour chariot. De même, un caractère saut de ligne dans la chaîne de format correspond soit à un seul saut de ligne, soit à un retour chariot.

Selon la structure du fichier, le format suivant est suivi :

Le caractère % est suivi d'un indicateur optionnel, d'une largeur de champ optionnelle et d'un caractère de conversion optionnel.

Les caractères de conversion et leurs significations sont :

- d : lit un entier décimal éventuellement signé (0-9+).

- i : lit un entier décimal éventuellement signé (les conventions d'entrée standard pour les décimaux (0-9+), hexadécimaux (0x[0-9a-f]+), octaux (0o[0-7]+) et binaires (0b[0-1]+) sont compris).

- u : lit un entier décimal non signé.

- x ou X : lit un entier hexadécimal non signé ([0-9a-fA-F]+).

- o : lit un entier octal non signé ([0-7]+).

- s : lit un argument chaîne qui s'étend autant que nécessaire jusqu'à ce que l'une des conditions suivantes soit remplie :

- Un caractère d'espace blanc est rencontré (voir Scanf.space),

- Un indicateur de lecture est rencontré (voir Scanf.indication),

- La fin de l'entrée est atteinte.

Par conséquent, cette conversion réussit toujours : elle renvoie une chaîne vide si la condition de bordure est remplie au début de la lecture.

- S : lit un argument chaîne délimité (les délimiteurs et les caractères spéciaux spécialisés suivent les conventions lexicales d'OCaml).

- c : lit un seul caractère. Pour tester le caractère actuel sans le lire, spécifiez une largeur de champ nulle, c'est-à-dire utilisez la spécification %0c. Lance Invalid_argument si la largeur de champ spécifiée est supérieure à 1.

- C : lit un seul caractère délimité (les délimiteurs et les caractères spéciaux spécialisés suivent les conventions lexicales d'OCaml).

- f, e, E, g, G : lit un nombre flottant éventuellement signé en notation décimale, au style dddd.ddd et/ou e/E+-dd.

- h, H : lit un nombre flottant éventuellement signé en notation hexadécimale.

- F : lit un nombre flottant selon les conventions lexicales d'OCaml (donc, le point décimal est obligatoire si la partie exposant n'est pas mentionnée).

- B : lit un argument booléen (true ou false).

- b : lit un argument booléen (pour la compatibilité descendante ; ne doit pas être utilisé dans de nouveaux programmes).

- ld, li, lu, lx, lX, lo : lit un argument int32 selon la seconde lettre de la spécification de format.

- nd, ni, nu, nx, nX, no : lit un argument nativeint selon la seconde lettre de la spécification de format.

- Ld, Li, Lu, Lx, LX, Lo : lit un argument int64 selon la seconde lettre de la spécification de format.

- [ range ] : lit des caractères qui correspondent à l'un des caractères mentionnés dans la plage de caractères range (ou non mentionnés dans celle-ci, si la plage commence par ^). Lit une chaîne qui peut être vide si le caractère d'entrée suivant ne correspond pas à la plage. L'ensemble des caractères de c1 à c2 (inclus) est noté c1-c2. Ainsi, %[0-9] renvoie une chaîne représentant un nombre décimal ou une chaîne vide si aucun chiffre décimal n'est trouvé ; de même, %[0-9a-f] renvoie une chaîne de chiffres hexadécimaux. Si une parenthèse fermante apparaît dans une plage, elle doit apparaître comme premier caractère de la plage (ou juste après le ^ en cas de négation de plage) ; ainsi, []] correspond à un caractère ] et [^]] correspond à tout caractère sauf ]. Utilisez %% et %@ pour inclure un % ou un @ dans une plage.

- r : lecteur personnalisé. Lors de la lecture de la prochaine ri d'entrée formatée, applique cette fonction au tampon de lecture ib pour lire l'argument suivant. La fonction de lecture ri doit avoir un type Scanning.in_channel -> 'a et l'argument lu a un type 'a.

- { fmt %} : lit un argument chaîne de format. La chaîne de format lue doit avoir le même type que la spécification de format fmt. Par exemple, "%{ %i %}" lit toute chaîne de format qui peut lire une valeur de type int ; ainsi, si s est la chaîne "fmt:\"number is %u\"", alors Scanf.sscanf s "fmt: %{%i%}" réussit et renvoie la chaîne de format "number is %u".

- ( fmt %) : substitution de sous-format de lecture. Lit la chaîne de format rf de l'entrée, puis sera lue avec rf au lieu de fmt. La chaîne de format rf doit avoir le même type que la spécification de format fmt qu'elle remplace. Par exemple, "%( %i %)" lit toute chaîne de format qui peut lire une valeur de type int. La conversion renvoie la chaîne de format lue rf, puis une valeur lue avec rf. Ainsi, si s est la chaîne "\"%4d\"1234.00", alors Scanf.sscanf s "%( %i %)" (fun fmt i -> fmt, i) évalue à ("\"%4d\"", 1234). Ce comportement n'est pas simplement un remplacement de format, car la conversion renvoie la chaîne de format lue comme argument supplémentaire. Si vous avez besoin d'un remplacement pur, utilisez l'indicateur spécial _ pour ignorer l'argument supplémentaire : la conversion %_( fmt %) lit une chaîne de format rf puis se comporte de la même manière que la chaîne de format rf. Ainsi, si s est la chaîne "\"%4d\"1234.00", alors Scanf.sscanf s "%_(%i%)" est équivalent à Scanf.sscanf "1234.00" "%4d".

- l : renvoie le nombre de lignes lues jusqu'à présent.

- n : renvoie le nombre de caractères lus jusqu'à présent.

- N ou L : renvoie le nombre de jetons lus jusqu'à présent.

- ! : correspond à la condition de fin d'entrée.

- % : correspond à un caractère % dans l'entrée.

- @ : correspond à un caractère @ dans l'entrée.

- , : ne fait rien.

Après le caractère % introduisant une conversion, il peut y avoir l'indicateur spécial _ : la conversion qui suit se produit normalement, mais la valeur résultante est ignorée. Par exemple, si f est la fonction fun i -> i + 1 et s est la chaîne "x = 1", alors Scanf.sscanf s "%_s = %i" f renvoie 2.

La largeur de champ se compose d'un entier littéral optionnel indiquant la largeur maximale du jeton à lire. Par exemple, %6d lit un entier avec un maximum de 6 chiffres décimaux ; %4f lit un nombre flottant avec un maximum de 4 caractères ; et %8[\000-\255] renvoie les 8 caractères suivants (ou tous les caractères encore disponibles, s'il y en a moins de 8 dans l'entrée).

Notes :

- Comme mentionné ci-dessus, une conversion %s réussit toujours, même s'il n'y a rien à lire dans l'entrée : dans ce cas, elle renvoie simplement "".

- En plus des chiffres pertinents, des caractères '_' peuvent apparaître à l'intérieur des nombres (cela rappelle les conventions lexicales standard d'OCaml). Si une analyse plus stricte est souhaitée, utilisez la fonction de conversion de plage au lieu des conversions numériques.

- L'analyseur scanf n'est pas destiné à l'analyse lexicale et au parsing intensifs. S'il n'est pas suffisant pour vos besoins, il existe plusieurs alternatives : expressions régulières (module Str), analyseurs de flux, analyseurs lexicaux générés par ocamllex, analyseurs générés par ocamlyacc.

Indicateurs de lecture dans les chaînes de format

Les indicateurs de lecture apparaissent juste après les conversions de chaîne %s et %[ range ] pour délimiter la fin du jeton. Un indicateur de lecture est introduit par un caractère @ suivi d'un caractère commun c. Il signifie que le jeton de chaîne doit se terminer juste avant le caractère suivant qui correspond à c (qui sera ignoré). Si aucun caractère c n'est trouvé, le jeton de chaîne s'étend autant que possible. Par exemple, "%s@\t" lit une chaîne jusqu'au prochain caractère de tabulation ou jusqu'à la fin de l'entrée. Si un caractère @ apparaît n'importe où dans la chaîne de format, il est traité comme un caractère ordinaire.

Note :

- Comme dans les chaînes de format standard, les caractères % et @ doivent être échappés en utilisant %% et %@ ; cette règle s'applique également à l'intérieur des spécifications de plage et des indicateurs de lecture. Par exemple, le format "%s@%%" lit une chaîne jusqu'au prochain %, et le format "%s@%@" lit une chaîne jusqu'au prochain @.

- Les indicateurs de lecture introduisent des différences minimales dans la syntaxe des chaînes de format Scanf par rapport à celles utilisées dans le module Printf. Cependant, les indicateurs de lecture sont similaires à ceux utilisés dans le module Format ; par conséquent, lors de la production de texte formaté à lire par Scanf.bscanf, il est sage d'utiliser les fonctions d'impression du module Format (ou, si vous souhaitez utiliser les fonctions du module Printf, évitez ou révisez soigneusement les chaînes de format contenant des caractères '@').

Exceptions lors de la lecture

Les lecteurs peuvent lancer les exceptions suivantes lorsqu'il est impossible de lire l'entrée selon la chaîne de format :

- Lance Scanf.Scan_failure si l'entrée ne correspond pas au format.

- Lance Failure s'il est impossible de convertir en nombre.

- Lance End_of_file si la fin de l'entrée est atteinte alors que des caractères supplémentaires sont nécessaires pour la spécification de conversion actuelle.

- Lance Invalid_argument si la chaîne de format est invalide.

Note :

- Par conséquent, la lecture d'une conversion %s ne lance jamais l'exception End_of_file : si la fin de l'entrée est atteinte, la conversion réussit et renvoie simplement les caractères lus jusqu'alors.

or "" si aucun n'a jamais été lu.

val unescaped : string -> string

unescaped s renvoie une copie de s avec les séquences d'échappement (selon les conventions lexicales d'OCaml) remplacées par leurs caractères spéciaux correspondants. Plus précisément, Scanf.unescaped a la propriété suivante : pour toute chaîne s , Scanf.unescaped (String.escaped s) = s .

Renvoie toujours une copie de l'argument, même s'il n'y a pas de séquence d'échappement dans l'argument.

Depuis 4.00

Lève Scan_failure si s n'est pas correctement échappé (c'est-à-dire que s a des séquences d'échappement invalides ou des caractères spéciaux qui ne sont pas correctement échappés). Par exemple, Scanf.unescaped "\"" échouera.
