Description Détaillée

L'élément < send > SCXML.

L'élément < send > est utile uniquement dans les configurations qui ont une implémentation du module de communication externe. Les deux profils « minimum » et « x-coin » ont des implémentations, mais le profil « minimum » n'implémente pas le module de données, de sorte que seuls des événements sans données associées peuvent être envoyés.

L'élément < send > peut avoir les attributs suivants :

  • event
  • target
  • targettype
  • sendid - non supporté
  • delay
  • namelist
  • hints - non supporté

L'élément < send > envoie des événements externes. Les machines d'état ont généralement deux files d'attente d'événements : une interne et une externe. La file d'attente d'événements interne a une priorité totale sur l'externe. Les machines d'état peuvent s'envoyer des événements externes à elles-mêmes, mais ce sont plus probablement des événements internes que vous souhaitez. Pour envoyer des événements internes, voir l'élément < event > implémenté dans ScXMLEventElt. Pour envoyer un événement externe à la machine d'état parente, ne spécifiez pas l'attribut target.

L'attribut event spécifie le nom de l'événement envoyé. Les noms d'événements sont des noms séparés par des points, tels que « error.InvalidExpr » ou « x-coin-navigation.Rotate.BEGIN », et les noms d'événements sont considérés comme sensibles à la casse dans l'implémentation actuelle de Coin SCXML. L'attribut event est obligatoire.

L'attribut targettype spécifie le type du système cible. Les autres machines d'état SCXML ont le type « scxml ». Les services liés aux systèmes de navigation Coin ont le type « x-coin-navigation ». Lors de l'envoi d'événements externes à soi-même, le type targettype peut être omis.

L'attribut target est le nom du système cible des événements. S'il n'est pas spécifié, cela signifie que l'événement sera envoyé à la machine d'état parente. Les services de navigation Coin sont typiquement nommés « Rotate », mais pour les autres machines d'état SCXML, l'attribut name de <scxml> le détermine. Ce nom n'est pas unique si plusieurs noms ont été créés, donc la cible peut également être l'identifiant de session de la machine d'état. (FIXME : vérifier si cela est implémenté)

L'attribut sendid n'est pas pris en charge.

Si un délai est spécifié, il doit prendre la forme « {nombre}s » ou « {nombre}ms », permettant de spécifier la durée de l'événement en secondes ou en millisecondes avant que l'événement ne soit envoyé. Pour que les événements retardés soient envoyés, le traitement de la file d'attente des délais de Coin doit être effectué. Les utilisateurs de Coin le font généralement sans le savoir. Si aucun délai n'est spécifié, l'événement est envoyé immédiatement à la cible. Si une machine d'état est supprimée, tout événement programmé pour être envoyé avec un délai sera perdu. La file d'attente des délais est une caractéristique de la machine d'état d'envoi, pas de la réception.

L'attribut namelist spécifie quelles variables de données sont incluses avec l'événement pour la cible de l'événement. Cet attribut n'est utile que dans les profils qui implémentent le module de données. Le profil « minimum » ne le fait pas, mais le profil « x-coin » le fait. Pour le profil « x-coin », vous pouvez spécifier des variables de données avec le schéma &_data.{ID} ou spécifier des variables temporaires avec le schéma coin:temp.{ID} ou utiliser le préfixe implicite si seul le préfixe est utilisé.

en spécifiant l'{ID}. Cette dernière est la méthode la plus utile, car les cibles d'événements ne veulent pas savoir où dans un modèle de données se trouve une variable, ni le nom qu'elle avait là où elle était contenue. Avec des variables temporaires, les valeurs peuvent obtenir des noms destinés à la cible de l'événement au lieu du nom utilisé à la source.

L'attribut hints n'est pas pris en charge.
