DESCRIPTION

Les Timestamps Signés de Certificat (SCT) sont définis par la RFC 6962, section 3.2. Ils constituent une promesse d'un journal de Transparence des Certificats (CT) d'enregistrer publiquement un certificat. En vérifiant cryptographiquement qu'un journal a effectivement émis un SCT, on peut obtenir une certaine confiance que le certificat est publiquement connu.

Une représentation interne d'un SCT peut être créée de deux manières. La première option consiste à créer un SCT vide, en utilisant SCT_new(), puis à le remplir en utilisant :

  • SCT_set_version() pour définir la version du SCT.

    Seule SCT_VERSION_V1 est actuellement prise en charge.

  • SCT_set_log_entry_type() pour définir le type de certificat pour lequel le SCT a été émis :

    CT_LOG_ENTRY_TYPE_X509 pour un certificat normal. CT_LOG_ENTRY_TYPE_PRECERT pour un pré-certificat.

  • SCT_set0_log_id() ou SCT_set1_log_id() pour définir le LogID du journal CT dont provient le SCT.

    Le premier prend possession, tandis que le second fait une copie. Voir RFC 6962, section 3.2 pour la définition de LogID.

  • SCT_set_timestamp() pour définir l'heure d'émission du SCT (heure en millisecondes depuis l'Epoch Unix).
  • SCT_set_signature_nid() pour définir le NID de la signature.
  • SCT_set0_signature() ou SCT_set1_signature() pour définir la valeur brute de la signature.

    Le premier prend possession, tandis que le second fait une copie.

  • SCT_set0_extensions() ou SCT_set1_extensions pour fournir les extensions SCT.

    Le premier prend possession, tandis que le second fait une copie.

Alternativement, le SCT peut être pré-rempli à partir des données suivantes en utilisant SCT_new_from_base64() :

  • La version du SCT (seule SCT_VERSION_V1 est actuellement prise en charge).
  • Le LogID (voir RFC 6962, section 3.2), encodé en base64.
  • Le type de certificat pour lequel le SCT a été émis : CT_LOG_ENTRY_TYPE_X509 pour un certificat normal. CT_LOG_ENTRY_TYPE_PRECERT pour un pré-certificat.
  • L'heure d'émission du SCT (heure en millisecondes depuis l'Epoch Unix).
  • Les extensions SCT, encodées en base64.
  • La signature SCT, encodée en base64.

SCT_set_source() peut être utilisé pour enregistrer où le SCT a été trouvé (extension TLS, extension de certificat X.509 ou réponse OCSP agrafée). Ceci n'est pas requis pour vérifier le SCT.

SCT_free() libère le SCT spécifié. Si l'argument est NULL, rien n'est fait.

SCT_LIST_free() libère la pile de SCT spécifiée. Si l'argument est NULL, rien n'est fait.

NOTES

Certains des setters retournent un int, au lieu de void. Tous ces fonctions retourneront 1 en cas de succès, 0 en cas d'échec. Elles ne modifieront rien en cas d'échec.

Tous les setters réinitialiseront l'état de validation du SCT à SCT_VALIDATION_STATUS_NOT_SET (voir SCT_validate(3)).

SCT_set_source() appellera SCT_set_log_entry_type() si le type de certificat pour lequel le SCT a été émis peut être déduit de l'endroit où le SCT a été trouvé. Par exemple, un SCT trouvé dans une extension X.509 doit avoir été émis pour un pré-certificat.

SCT_set_source() n'acceptera pas les valeurs inconnues.

VALEURS DE RETOUR

SCT_set_version() retourne 1 si la version spécifiée est prise en charge, 0 sinon.

SCT_set_log_entry_type() retourne 1 si le type d'entrée de journal spécifié est pris en charge, 0 sinon.

SCT_set0_log_id() et SCT_set1_log_id retournent 1 si le LogID spécifié est un hachage SHA-256 valide, 0 sinon. De plus, SCT_set1_log_id retourne 0 si malloc échoue.

SCT_set_signature_nid retourne 1 si le NID spécifié est pris en charge, 0 sinon.

SCT_set1_extensions et SCT_set1_signature retournent 1 si la copie du tampon fourni réussit, 0 sinon (c'est-à-dire si malloc échoue).

SCT_set_source retourne 1 en cas de succès, 0 sinon.
