Description détaillée

l'élément SCXML <assign>.

L'élément <assign> n'est fonctionnel que dans un profil qui implémente le module de données. Le profil "minimum" n'en implémente pas, mais le profil "x-coin" le fait.

Les attributs suivants sont acceptés :

  • location
  • dataID
  • expr

Soit location, soit dataID peut être spécifié à la fois.

Si dataID est spécifié, alors la cible de l'affectation est l'élément <data> dont l'attribut ID est défini à la même valeur.

Si location est spécifié, un adressage de variable dépendant du profil est utilisé. Le profil "minimum" ne définit aucun, et le profil "x-coin" définit les schémas d'adresse suivants pour les variables écrivables :

  • _data.{id} signifie cibler une variable <data> existante.
  • coin:temp.{id} signifie cibler une variable temporaire, en en créant une si nécessaire.

Les variables temporaires dans le profil "x-coin" ont la durée de vie d'un événement SCXML. Pour avoir des données persistantes, utilisez des variables <data>. Elles restent vivantes aussi longtemps que ScXMLStateMachine existe.

Les variables temporaires sont particulièrement utiles pour l'élément <send>, car l'attribut namelist peut y faire référence avec un préfixe implicite, ce qui signifie que les cibles d'événements peuvent les lire en utilisant des noms logiques au lieu d'adresses du modèle de données SCXML.
