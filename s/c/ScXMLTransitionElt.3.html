Description Détaillée

L'élément <transition> SCXML.

L'élément <transition> est utilisé pour invoquer du code exécutable et passer des états actifs actuels dans une machine à états vers un nouvel ensemble d'états actifs.

Par états actifs, on entend que tous les états parents des états actifs sont également actifs en même temps, ce qui est utile lors de l'organisation des transitions d'événements déclenchés par <transition>. Placer des transitions dans l'élément racine <scxml> signifie qu'elles sont toujours actives.

On peut aussi parler d'états parallèles dans SCXML. Ceci n'est pas encore implémenté dans Coin SCXML.

Les attributs suivants sont acceptés :

  • event
  • cond
  • target
  • anchor - non supporté

L'attribut event spécifie l'événement qui déclenchera la transition lorsqu'elle se trouve dans un état actif. L'attribut event peut être spécifié avec une correspondance de *caractères génériques* en utilisant "*", mais avec les restrictions suivantes :

  • "*" doit être à la fin du nom de correspondance de l'événement.
  • "*" doit correspondre à des mots entiers séparés par des points.

Exemple 1 : event="*"

Exemple 2 : event="error.*"

L'attribut cond peut être utilisé pour spécifier des conditions supplémentaires qui doivent être remplies pour que la transition soit activée. Le langage d'expressions conditionnelles dépend du profil SCXML de la machine à états.

Le profil "minimum" ne spécifie qu'une seule fonction, la fonction In({ID}). In() renvoie TRUE si la machine à états est dans l'état avec l'ID donné.

Le profil "x-coin" implémente plusieurs expressions qui évaluent à une valeur booléenne. Bien qu'en développement, la documentation du langage d'expressions semble être un effort inutile, cette partie devra donc attendre. Le code source peut parler de lui-même. Consultez Coin/src/scxml/eval-coin-tab.y.

L'attribut target spécifie les états de destination vers lesquels passer. Si des états parallèles avaient été implémentés, nous pourrions spécifier plusieurs états dans cet attribut, mais pour l'instant, nous ne pouvons spécifier qu'un seul état de destination. Si le target est omis, la transition ne change pas quel état est actif et exécute simplement les parties exécutables qu'elle contient. Si le target est l'ID de l'état dans lequel se trouve la transition, l'état sera quitté/entré et réentré. Pour les sous-états actifs, cela signifie qu'ils seront également quittés/entreront.

L'attribut anchor n'est pas supporté.

Les éléments <transition> peuvent contenir des éléments exécutables SCXML comme enfants XML, c'est-à-dire <if> / <elseif> / <else> / <assign> / <send> / <event> / <log>.

SbBool ScXMLTransitionElt::isConditionLess (void ) const

Indique s'il s'agit ou non d'une transition SCXML sans condition.

Une transition sans condition doit toujours être prise.

SbBool ScXMLTransitionElt::isTargetLess (void ) const

Indique s'il s'agit ou non d'une transition sans définition de cible.

Lorsqu'une transition sans cible est prise, l'état de la machine d'états ne change pas. Cela diffère de la définition de la cible sur son propre état, ce qui amène la machine d'états à quitter l'état et à y réentrer.

SbBool ScXMLTransitionElt::isSelfReferencing (void ) const

Indique si cette transition référence ou non son conteneur.

Si TRUE, cela signifie que vous devriez vous retrouver dans le même état qu'au départ lors de cette transition. Notez cependant qu'à l'inverse d'une transition sans cible, cette transition doit en fait quitter l'état puis le réentrer. Le contenu exécutable sera invoqué après la sortie de l'état, avant la réentrée.

SbBool ScXMLTransitionElt::isEventMatch (const ScXMLEvent * eventobj) const [virtual]

Cette fonction retourne TRUE si la transition correspond à l'objet eventobj donné et FALSE sinon.

SbBool ScXMLTransitionElt::evaluateCondition (ScXMLStateMachine * statemachine) [virtual]

Cette fonction utilise l'évaluateur de machine d'états pour évaluer son expression de condition, et retourne TRUE ou FALSE en fonction de l'évaluation.

En cas d'erreur d'expression, des événements d'erreur sont émis vers la machine d'états SCXML.

Si la transition est sans condition, cette fonction retournera TRUE.
