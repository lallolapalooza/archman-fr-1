NAME

SRCINFO - Informations sur les sources de paquets basés sur ALPM.

DESCRIPTION

Le format SRCINFO est un format textuel qui décrit les métadonnées des paquets sources. Ces fichiers sont nommés .SRCINFO et sont situés à la racine des dépôts sources à partir desquels les paquets basés sur ALPM sont construits. Ils sont créés à partir des fichiers PKGBUILD pour permettre un analyse sécurisé des métadonnées dans des scénarios où l'utilisation de bash n'est pas une option. Le format SRCINFO est utilisé par des applications telles que le logiciel de gestion de dépôts et les interfaces web personnalisées pour évaluer et présenter les informations des paquets sources.

Format général

Un fichier SRCINFO se compose d'une série de lignes, chacune fournissant des informations sur un aspect des sources d'un ou plusieurs paquets (voir alpm-split-package pour des informations sur les paquets divisés). Les lignes commençant par un signe # sont traitées comme des commentaires et sont toujours ignorées. Les lignes vides sont toujours ignorées. Les espaces blancs de début sont toujours ignorés.

Sauf indication contraire, les informations contenues dans un fichier SRCINFO sont considérées comme couvertes par l'ensemble des caractères imprimables ASCII [1].

Le format SRCINFO distingue les en-têtes de section qui introduisent des sections spécifiques des affectations de mots-clés qui peuvent être utilisées dans ces sections. Chaque ligne code des informations représentant un en-tête de section ou une affectation de mot-clé.

Le format SRCINFO exige la définition d'un seul pkgbase et d'une ou plusieurs sections pkgname. Bien que le pkgbase contienne les métadonnées partagées par tous les paquets construits à partir d'un PKGBUILD, les sections pkgname sont utilisées pour déclarer les métadonnées de paquets et fournir des substitutions spécifiques pour chaque paquet respectif.

En-têtes de section

Tous les en-têtes de section consistent en une clé, suivie d'un espace blanc, d'un signe =, d'un autre espace blanc et d'une valeur.

L'en-tête de section pour un pkgbase doit utiliser le mot pkgbase comme clé et alpm-package-base comme valeur. Il doit exister exactement un tel en-tête dans un fichier SRCINFO au début de celui-ci.

L'en-tête de section pour un pkgname doit utiliser le mot pkgname comme clé et alpm-package-name comme valeur. Il doit exister au moins un tel en-tête dans un fichier SRCINFO (un par paquet construit à partir d'un PKGBUILD), mais seulement après un en-tête pkgbase.

Sections

La section pkgbase doit inclure au moins les affectations pour les mots-clés pkgver et pkgrel, et peut inclure d'autres affectations connues. Les affectations de mots-clés présentes dans cette section s'appliquent également à toutes les sections pkgname.

Une section pkgname peut contenir zéro ou plusieurs affectations de mots-clés. Elle ne doit pas contenir d'affectations pour les mots-clés epoch, pkgver, pkgrel ou validpgpkeys, ni d'affectations de mots-clés représentant des déclarations de dépendances de construction ou de test (voir alpm-package-relation pour les détails), des déclarations de sources (voir alpm-package-source pour les détails) ou des déclarations de vérification de checksum (voir alpm-package-source-checksum pour les détails). Les affectations de mots-clés dans une section pkgname ne s'appliquent qu'au paquet spécifique décrit par la section. Plus précisément, toutes les affectations de mots-clés d'une section pkgname sont utilisées pour désactiver, étendre ou remplacer les affectations de mots-clés trouvées dans la section pkgbase. Les règles suivantes s'appliquent :

•
Un mot-clé qui a été défini précédemment dans la section pkgbase et qui peut être utilisé dans une section pkgname peut
  • être désactivé en lui affectant une valeur vide (par exemple, la section pkgbase définit depends = bash et la section pkgname définit depends =), ou
  • être remplacé en le redéfinissant (par exemple, la section pkgbase définit depends = bash et la section pkgname définit depends = zsh).
•
Tous les termes permettant plusieurs affectations et pouvant être utilisés dans une section pkgname peuvent être étendus d'abord en ajoutant toutes les affectations de mots-clés trouvées dans la section pkgbase, puis en ajoutant les affectations supplémentaires dans la section pkgname (par exemple, la section pkgbase définit depends = bash et la section pkgname définit depends = bash et depends = bash-completion).

Des règles supplémentaires peuvent s'appliquer en fonction du terme.

Mots-clés

Toutes les affectations de mots-clés sont définies comme une clé de la liste suivante, suivie d'un espace blanc, d'un signe =, d'un espace blanc et d'une valeur.

Par défaut, une affectation de mot-clé peut exister une fois par mot-clé dans un fichier SRCINFO. À titre d'exception, les mots-clés arch, backup, checkdepends, conflicts, depends, groups, license, makedepends, optdepends, options, provides, replaces, ainsi que les mots-clés liés aux sources noextract, source, validpgpkeys, b2sums, md5sums, sha1sums, sha224sums, sha256sums, sha384sums, sha512sums, cksums et alpm-architecture peuvent être fournis zéro ou plusieurs fois.

Par défaut, les affectations de mots-clés s'appliquent à tous les alpm-architectures cibles. Certains mots-clés peuvent également être fournis dans des formes spécifiques à chaque architecture en ajoutant un signe _ directement après une clé, suivi d'un alpm-architecture (tous sauf any - voir chaque section de mot-clé pour les détails). Ces affectations spécifiques à l'architecture ne s'appliquent qu'à l'architecte visé.

pkgdesc

Description du paquet. Cette affectation de mot-clé peut être fournie une fois ou aucune fois dans la section pkgbase et/ou dans chaque section pkgname. La valeur est une chaîne UTF-8, zéro ou plusieurs caractères (par exemple, Un projet utilisé pour quelque chose). Les descriptions de paquets ne doivent pas comporter d'espaces blancs en début ou fin, uniquement des espaces blancs à l'exception de l'espace " " et pas d'espaces consécutifs.

Il n'y a pas de règles spécifiques concernant la valeur, mais il est suggéré qu'elle soit "courte" et qu'elle ne contienne pas le nom du paquet (voir alpm-package-name).

pkgver

Le composant de version du paquet (voir alpm-pkgver pour des informations supplémentaires sur la valeur attendue). Cette affectation de mot-clé doit être fournie une fois, exclusivement dans la section pkgbase.

La valeur est un alpm-pkgver (par exemple, 1.0.0 ou 1:1.0.0).

pkgrel

Le composant de version du paquet (voir alpm-pkgrel pour des détails sur la valeur attendue).

Cette affectation de mot-clé doit être fournie une fois, exclusivement dans la section pkgbase.

epoch

Le composant optionnel de version du paquet (voir alpm-epoch pour des détails sur la valeur attendue).

Cette affectation de mot-clé peut être fournie une fois ou aucune fois, exclusivement dans la section pkgbase.

url

L'URL du projet du paquet. Cette affectation de mot-clé peut être fournie une fois ou aucune fois dans la section pkgbase et/ou dans chaque section pkgname.

La valeur est une URL valide ou une chaîne vide (par exemple, https://example.org).

install

Le nom d'un alpm-install-scriptlet utilisé pour les actions avant et après l'installation, la mise à jour ou la désinstallation d'un paquet. Cette affectation de mot-clé peut être fournie une fois ou aucune fois dans la section pkgbase

b> et/ou dans chaque section pkgname.

La valeur doit être une chaîne UTF-8 représentant un chemin de fichier relatif (par exemple, scriptlet.install).

changelog

Le nom du fichier contenant les informations de journal des modifications pour un paquet. Cette affectation de mot-clé peut être fournie zéro ou une fois dans la section pkgbase et/ou dans chaque section pkgname.

La valeur doit être une chaîne UTF-8, représentant un chemin de fichier relatif (par exemple, pkg.changelog).

arch

Une architecture qui s'applique à une section pkgname. Cette affectation de mot-clé peut être fournie une ou plusieurs fois dans la section pkgbase et zéro ou plusieurs fois dans chaque section pkgname.

La valeur est une architecture-alpm (par exemple, x86_64 ou any). Les règles suivantes s'appliquent si ce mot-clé est utilisé plusieurs fois :

  • chaque valeur doit être unique
  • si la valeur any est utilisée, aucune autre valeur ne peut être utilisée avec elle, car elle implique qu'un pkgname peut être utilisé sur n'importe quelle architecture (ce qui exclut logiquement le fait d'être utilisé uniquement sur une architecture spécifique)

groups

Une chaîne arbitraire, qui désigne un groupe à l'échelle de la distribution auquel appartient le paquet (voir groupe-de-paquets-alpm). Les groupes sont utilisés par exemple par les gestionnaires de paquets pour regrouper des paquets et permettre leur installation en bloc, ou par d'autres logiciels pour afficher des informations sur ces paquets connexes.

Cette affectation de mot-clé peut être fournie zéro ou plusieurs fois dans la section pkgbase ainsi que dans chaque section pkgname. La valeur est représentée par une chaîne UTF-8. Bien qu'il soit possible d'utiliser une chaîne UTF-8, il est fortement recommandé de s'appuyer sur le format nom-de-paquet-alpm pour la valeur à la place, car les gestionnaires de paquets peuvent utiliser les groupes pour installer un groupe entier de paquets.

license

Une licence qui s'applique aux paquets.

Cette affectation de mot-clé peut être fournie zéro ou plusieurs fois dans la section pkgbase ainsi que dans chaque section pkgname. La valeur représente un identifiant de licence, qui est une chaîne de longueur non nulle (par exemple, GPL). Bien qu'aucune restriction spécifique ne soit appliquée à la valeur, à part sa longueur, il est fortement recommandé de s'appuyer sur les expressions de licence SPDX (par exemple, GPL-3.0-or-later ou Apache-2.0 OR MIT). Voir la Liste des licences SPDX[5] pour plus d'informations.

checkdepends

Une dépendance pour l'exécution des tests du projet en amont du paquet. Une checkdepends spécifique à une architecture peut être spécifiée en utilisant un mot-clé composé de 'checkdepends', directement suivi d'un signe '_', directement suivi d'une architecture-alpm (toutes les architectures-alpm à l'exception de any peuvent être utilisées), par exemple, checkdepends_aarch64.

Cette affectation de mot-clé peut être fournie zéro ou plusieurs fois, exclusivement dans la section pkgbase. La valeur est une relation-de-paquet-alpm de type dépendance de test (par exemple, example ou example=1.0.0).

makedepends

Une dépendance de construction du paquet (composant virtuel ou paquet). Une makedepends spécifique à une architecture peut être spécifiée en utilisant un mot-clé composé de 'makedepends', directement suivi d'un signe '_', directement suivi d'une architecture-alpm (toutes les architectures-alpm à l'exception de any peuvent être utilisées), par exemple, makedepends_aarch64.

Cette affectation de mot-clé peut être fournie zéro ou plusieurs fois, exclusivement dans la section pkgbase. La valeur est une relation-de-paquet-alpm de type dépendance de construction (par exemple, example ou example=1.0.0).

depends

Une dépendance d'exécution du paquet (composant virtuel ou paquet). Une depends spécifique à une architecture peut être spécifiée en utilisant un mot-clé composé de 'depends', directement suivi d'un signe '_', directement suivi d'une architecture-alpm (toutes les architectures-alpm à l'exception de any peuvent être utilisées), par exemple, depends_aarch64.

Cette affectation de mot-clé peut être fournie zéro ou plusieurs fois dans la section pkgbase ainsi que dans chaque section pkgname. La valeur est une relation-de-paquet-alpm de type dépendance d'exécution (par exemple, example ou example=1.0.0).

optdepends

Une dépendance optionnelle du paquet (composant virtuel ou paquet). Une optdepends spécifique à une architecture peut être spécifiée en utilisant un mot-clé composé de 'optdepends', directement suivi d'un signe '_', directement suivi d'une architecture-alpm (toutes les architectures-alpm à l'exception de any peuvent être utilisées), par exemple, optdepends_aarch64.

Cette affectation de mot-clé peut être fournie zéro ou plusieurs fois dans la section pkgbase ainsi que dans chaque section pkgname. La valeur est une relation-de-paquet-alpm de type dépendance optionnelle (par exemple, example ou example: ceci est une description).

provides

Un autre composant virtuel ou paquet, que le paquet fournit. Une provides spécifique à une architecture peut être spécifiée en utilisant un mot-clé composé de 'provides', directement suivi d'un signe '_', directement suivi d'une architecture-alpm (toutes les architectures-alpm à l'exception de any peuvent être utilisées), par exemple, provides_aarch64.

Cette affectation de mot-clé peut être fournie zéro ou plusieurs fois dans la section pkgbase ainsi que dans chaque section pkgname. La valeur est une relation-de-paquet-alpm de type provision (par exemple, example ou example=1.0.0).

conflicts

Un autre composant virtuel ou paquet, avec lequel le paquet est en conflit. Une conflicts spécifique à une architecture peut être spécifiée en utilisant un mot-clé composé de 'conflicts', directement suivi d'un signe '_', directement suivi d'une architecture-alpm (toutes les architectures-alpm à l'exception de any peuvent être utilisées), par exemple, conflicts_aarch64.

Cette affectation de mot-clé peut être fournie zéro ou plusieurs fois dans la section pkgbase ainsi que dans chaque section pkgname. La valeur est une relation-de-paquet-alpm de type conflit (par exemple, example ou example=1.0.0).

replaces

Un autre composant virtuel ou paquet, que le paquet remplace lors de son installation. Une replaces spécifique à une architecture peut être spécifiée en utilisant un mot-clé composé de 'replaces', directement suivi d'un signe '_', directement suivi d'une architecture-alpm (toutes les architectures-alpm à l'exception de any peuvent être utilisées), par exemple, replaces_aarch64.

Cette affectation de mot-clé peut être fournie zéro ou plusieurs fois dans la section pkgbase ainsi que dans chaque section pkgname. La valeur est une relation-de-paquet-alpm de type remplacement (par exemple, example ou example=1.0.0).

noextract

Le nom d'un fichier source local (voir source-de-paquet-alpm) qui ne doit pas être extrait lors de la construction du paquet. Chaque valeur doit représenter le nom de fichier local valide d'une affectation de mot-clé source existante (par exemple, source = https://example.org/project-1.0.0.tar.gz et noextract = project-1.0.0.tar.gz). Un fichier correspondant au nom fourni n'est *pas* automatiquement extrait lors de la construction du paquet, même s'il s'agit d'un fichier compressé (par exemple, example.tar.gz ou example.zip).

Cette affectation de mot-clé peut être fournie zéro ou plusieurs fois, exclusivement dans la section pkgbase.

options

Une option utilisée par l'outil de construction de paquet (c'est-à-dire makepkg, les valeurs par défaut sont définies dans OPTIONS de makepkg.conf) lors de la construction du paquet. Cette affectation de mot-clé peut être fournie zéro ou plusieurs fois soit dans la section pkgbase, soit dans une section pkgname.

La valeur doit être un mot unique, éventuellement préfixé par un unique '!', qui indique la négation de l'option (par exemple, debug ou !debug). Si l'affectation de mot-clé est utilisée dans une section pkgname, la valeur de la première occurrence peut être vide, ce qui indique que, pour le paquet respectif, aucune des options définies dans la section pkgbase ne s'applique.

backup

Un chemin de fichier relatif d'un fichier dans un paquet donné, qui désigne un fichier pour lequel le gestionnaire de paquets doit conserver des sauvegardes au cas où il serait modifié ou supprimé lors d'une action de mise à jour de paquet (voir les fichiers '.pacnew' et '.pacsave' de pacman). Cette affectation de mot-clé peut être fournie zéro ou plusieurs fois dans la section pkgbase ainsi que dans chaque section pkgname. La valeur doit être un chemin de fichier Unix relatif valide (par exemple, etc/package.conf).

source

Une source (à distance ou locale) utilisée dans le processus de packaging du ou des paquets (voir source-de-paquet-alpm pour plus de détails sur les formats autorisés.

validpgpkeys

Une empreinte OpenPGP[2] qui peut être utilisée pour la validation de signatures OpenPGP[3] créées pour une ou plusieurs sources de paquets alpm (c'est-à-dire, un mappage de mot-clé avec le terme source).

Ce mappage de mot-clé peut être fourni zéro ou plusieurs fois, exclusivement dans la section pkgbase. S'il est utilisé, il doit être utilisé au moins une fois si :

  • une valeur source de paquet alpm utilise le fragment d'URL signed
  • ou s'il existe une source de paquet alpm se terminant par .sig, et qu'elle est identique à une autre sans cette extension de fichier
  • ou s'il existe une source de paquet alpm se terminant par .sign, qui correspond à une autre sans cette extension de fichier et supprime toutes les extensions de fichier spécifiques à l'algorithme de compression (par exemple, .xz ou .zst)

La valeur est une chaîne hexadécimale de 40 caractères (par exemple, 0123456789abcdef0123456789abcdef01234567), éventuellement séparée par des espaces (par exemple, 0123 4567 89ab cdef 0123 4567 89ab cdef 0123 4567). Bien que possible, il est déconseillé d'utiliser l'ancienne représentation non unique de l'identifiant de clé OpenPGP[4], qui est une chaîne hexadécimale de 16 caractères (par exemple, 89abcdef01234567).

md5sums

Un hash MD5[6] du fichier fourni par nom dans une valeur de source, ou la chaîne spéciale SKIP (voir alpm-package-source-checksum pour les détails sur les valeurs autorisées). Un md5sums spécifique à l'architecture peut être spécifié en utilisant un terme composé de md5sums, suivi d'un signe _, suivi d'une architecture alpm (toutes les architectures alpm sauf any peuvent être utilisées), par exemple, md5sums_aarch64.

Ce mappage de mot-clé peut être fourni zéro ou plusieurs fois, exclusivement dans la section pkgbase. S'il est utilisé, le SRCINFO doit contenir autant de mappages de mot-clé md5sums que de source (la même règle s'applique aux variantes de ce mot-clé). L'ordre des mappages de mot-clé source détermine l'ordre des md5sums (c'est-à-dire que le premier mappage de mot-clé md5sums fournit des données pour le premier mappage de mot-clé source, etc.).

sha1sums

Ce mappage de mot-clé peut être fourni zéro ou plusieurs fois, exclusivement dans la section pkgbase. S'il est utilisé, le SRCINFO doit contenir autant de mappages de mot-clé sha1sums que de source (la même règle s'applique aux variantes de ce mot-clé). L'ordre des mappages de mot-clé source détermine l'ordre des sha1sums (c'est-à-dire que le premier mappage de mot-clé sha1sums fournit des données pour le premier mappage de mot-clé source, etc.).

L'exemple ci-dessus représente un fichier SRCINFO qui décrit deux paquets fractionnés (voir alpm-split-package pour plus de détails). Les deux sections pkgname remplacent l'assignation du mot-clé pkgdesc. La première section pkgname étend en outre la spécification du mot-clé license de la section pkgbase et ajoute d'autres assignations de mots-clés spécifiques au paquet (par exemple, replaces, groups, conflicts, provides, backup, optdepends). La seconde section pkgname remplace l'assignation du mot-clé license et désactive l'assignation du mot-clé depends.

Données du paquet, par architecture

Le PKGBUILD minimal suivant définit un paquet pour deux alpm-architectures.

pkgname=example
pkgver=0.1.0
pkgrel=1
pkgdesc="An example package"
arch=(x86_64 aarch64)
url="https://example.org"
license=(GPL-3.0-or-later)
depends=(bash)
depends_x86_64=(zsh)
package() {
  pkgdesc+=" - extra info"
  depends_x86_64+=(nushell)
  depends_aarch64=(sh)
}

Ce PKGBUILD est représenté par le SRCINFO suivant :

pkgbase = example
  pkgdesc = An example package
  pkgver = 0.1.0
  pkgrel = 1
  url = https://example.org
  arch = x86_64
  arch = aarch64
  license = GPL-3.0-or-later
  depends = bash
  depends_x86_64 = zsh
pkgname = example
  pkgdesc = An example package - extra info
  depends_x86_64 = zsh
  depends_x86_64 = nushell
  depends_aarch64 = sh

Selon l'alpm-architecture cible, les données du paquet différeront une fois tous les mots-clés résolus.

Pour aarch64 :

  • pkgdesc = An example package - extra info
  • pkgver = 0.1.0
  • pkgrel = 1
  • url = https://example.org
  • arch = aarch64
  • license = GPL-3.0-or-later
  • depends = bash
  • depends = sh

Pour x86_64 :

  • pkgdesc = An example package - extra info
  • pkgver = 0.1.0
  • pkgrel = 1
  • url = https://example.org
  • arch = x86_64
  • license = GPL-3.0-or-later
  • depends = bash
  • depends = zsh
  • depends = nushell
