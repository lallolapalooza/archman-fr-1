SRP_VBASE_new(3ssl)

Paquet: openssl

Licences: Apache-2.0

SRP_VBASE_NEW(3ssl) OpenSSL SRP_VBASE_NEW(3ssl)

NOM

SRP_VBASE_new, SRP_VBASE_free, SRP_VBASE_init, SRP_VBASE_add0_user, SRP_VBASE_get1_by_user, SRP_VBASE_get_by_user - Fonctions pour créer et gérer une pile d'informations de vérification d'utilisateur SRP

SYNOPIS

#include <openssl/srp.h>

Les fonctions suivantes ont été dépréciées depuis OpenSSL 3.0, et peuvent être complètement masquées en définissant OPENSSL_API_COMPAT avec une valeur de version appropriée, voir openssl_user_macros(7).

SRP_VBASE *SRP_VBASE_new(char *seed_key);
void SRP_VBASE_free(SRP_VBASE *vb);
int SRP_VBASE_init(SRP_VBASE *vb, char *verifier_file);
int SRP_VBASE_add0_user(SRP_VBASE *vb, SRP_user_pwd *user_pwd);
SRP_user_pwd *SRP_VBASE_get1_by_user(SRP_VBASE *vb, char *username);
SRP_user_pwd *SRP_VBASE_get_by_user(SRP_VBASE *vb, char *username);

DESCRIPTION

Toutes les fonctions décrites sur cette page sont dépréciées. Il n'y a pas de fonctions de remplacement disponibles pour le moment.

La fonction SRP_VBASE_new() alloue une structure pour stocker les informations de vérification SRP côté serveur. Si seed_key n'est pas NULL, une copie est stockée et utilisée pour générer des paramètres factices pour les utilisateurs qui ne sont pas trouvés par SRP_VBASE_get1_by_user(). Cela permet au serveur de masquer le fait qu'il ne possède pas de vérificateur pour un nom d'utilisateur particulier, comme décrit dans la section 2.5.1.3 'Unknown SRP' de la RFC 5054. La chaîne de clé de départ doit contenir des données binaires aléatoires terminées par NUL (par conséquent, les données aléatoires ne doivent pas contenir de NUL !).

La fonction SRP_VBASE_free() libère la structure vb. Si vb est NULL, rien n'est fait.

La fonction SRP_VBASE_init() analyse les informations d'un fichier de vérificateur et remplit la structure vb. Le fichier de vérificateur est un fichier texte contenant plusieurs entrées, dont le format est : drapeau base64(vérificateur) base64(sel) nom_utilisateur gNid info_utilisateur(optionnel) où le drapeau peut être 'V' (valide) ou 'R' (révoqué). Notez que le codage base64 utilisé ici est non standard, il est donc recommandé d'utiliser openssl-srp(1) pour générer ce fichier.

La fonction SRP_VBASE_add0_user() ajoute les informations de vérification user_pwd à la structure vb. Voir SRP_user_pwd_new(3) pour créer et remplir cet enregistrement. La bibliothèque prend possession de user_pwd, il ne doit pas être libéré par l'appelant.

La fonction SRP_VBASE_get1_by_user() renvoie les informations de mot de passe pour l'utilisateur dont le nom correspond à username. Elle remplace SRP_VBASE_get_by_user(), qui est dépréciée. Si aucun utilisateur correspondant n'est trouvé mais qu'une clé de départ et des paramètres gN par défaut ont été définis, des informations d'authentification factices sont générées à partir de la clé de départ, permettant au serveur de masquer le fait qu'il ne dispose pas d'un vérificateur pour un nom d'utilisateur particulier. Lors de l'utilisation de SRP comme mécanisme d'authentification TLS, cela provoquera la poursuite normale de la négociation, mais le premier client sera rejeté avec une alerte "bad_record_mac", comme si le mot de passe était incorrect. Si aucun utilisateur correspondant n'est trouvé et que la clé de départ n'est pas définie, NULL est retourné. La propriété du pointeur retourné est transférée à l'appelant, il doit être libéré avec SRP_user_pwd_free().

VALEUR DE RETOUR

SRP_VBASE_init() renvoie SRP_NO_ERROR (0) en cas de succès et une valeur positive en cas d'échec. Les codes d'erreur sont SRP_ERR_OPEN_FILE si le fichier n'a pas pu être ouvert, SRP_ERR_VBASE_INCOMPLETE_FILE si le fichier n'a pas pu être analysé, SRP_ERR_MEMORY en cas d'échec d'allocation mémoire et SRP_ERR_VBASE_BN_LIB pour des valeurs de paramètres décodées invalides.

SRP_VBASE_add0_user() renvoie 1 en cas de succès et 0 en cas d'échec.

VOIR AUSSI

openssl-srp(1), SRP_create_verifier(3), SRP_user_pwd_new(3), SSL_CTX_set_srp_password(3)

HISTORIQUE

Toutes les autres fonctions ont été ajoutées dans OpenSSL 1.0.1.

Toutes ces fonctions ont été dépréciées dans OpenSSL 3.0.
