Introduction

Entrées fonctionnelles avec chaînes de format

Le module Scanf fournit des fonctions d'entrée formatées ou analyseurs (scanners).

Les fonctions d'entrée formatées peuvent lire à partir de n'importe quel type d'entrée, y compris des chaînes de caractères, des fichiers, ou tout ce qui peut retourner des caractères. La source de caractères la plus générale est nommée un canal d'entrée formatée (ou buffer d'analyse) et a le type Scanf.Scanning.in_channel. La fonction d'entrée formatée la plus générale lit à partir de n'importe quel buffer d'analyse et est nommée bscanf.

En général, les fonctions d'entrée formatées ont 3 arguments :

- le premier argument est une source de caractères pour l'entrée,

- le second argument est une chaîne de format qui spécifie les valeurs à lire,

- le troisième argument est une fonction réceptrice qui est appliquée aux valeurs lues.

Par conséquent, un appel typique à la fonction d'entrée formatée Scanf.bscanf est bscanf ic fmt f, où :

- ic est une source de caractères (typiquement un canal d'entrée formatée de type Scanf.Scanning.in_channel),

- fmt est une chaîne de format (les mêmes chaînes de format que celles utilisées pour imprimer des données avec le module Printf ou Format),

- f est une fonction qui a autant d'arguments que le nombre de valeurs à lire dans l'entrée selon fmt.

Un exemple simple

Comme suggéré ci-dessus, l'expression bscanf ic "%d" f lit un entier décimal n à partir de la source de caractères ic et retourne f n.

Par exemple,

- si nous utilisons stdin comme source de caractères (Scanf.Scanning.stdin est le canal d'entrée formatée prédéfini qui lit depuis l'entrée standard),

- si nous définissons la fonction réceptrice f comme let f x = x + 1,

alors bscanf Scanning.stdin "%d" f lit un entier n depuis l'entrée standard et retourne f n (c'est-à-dire n + 1). Ainsi, si nous évaluons bscanf stdin "%d" f, et que nous entrons ensuite 41 au clavier, le résultat obtenu est 42.

L'entrée formatée comme fonctionnalité fonctionnelle

Le système d'analyse d'OCaml rappelle la fonctionnalité correspondante en C. Cependant, il est également très différent, plus simple, et pourtant plus puissant : les fonctions d'entrée formatée sont des fonctions d'ordre supérieur et le mécanisme de passage de paramètres est simplement l'application de fonction régulière, pas le mécanisme basé sur l'assignation de variables typique des entrées formatées dans les langages impératifs ; les chaînes de format OCaml comportent également des ajouts utiles pour définir facilement des jetons complexes ; comme attendu dans un langage de programmation fonctionnel, les fonctions d'entrée formatée supportent également le polymorphisme, en particulier une interaction arbitraire avec des analyseurs définis par l'utilisateur et polymorphes. De plus, le système d'entrée formatée d'OCaml est entièrement vérifié par typage à la compilation.

Accès non synchronisés

Les accès non synchronisés à un Scanf.Scanning.in_channel peuvent entraîner un état invalide du Scanf.Scanning.in_channel. Ainsi, les accès concurrents aux Scanf.Scanning.in_channel doivent être synchronisés (par exemple avec un Mutex.t).

Type des fonctions d'entrée formatée

type ('a, 'b, 'c, 'd) scanner = ('a, Scanning.in_channel, 'b, 'c, 'a -> 'd, 'd) format6 -> 'c

Le type des analyseurs d'entrée formatée : ('a, 'b, 'c, 'd) scanner est le type d'une fonction d'entrée formatée qui lit à partir d'un certain canal d'entrée formatée selon une certaine chaîne de format ; plus précisément, si scan est un certain analyseur d'entrée formatée, alors scan
ic fmt f applique f à tous les arguments spécifiés par la chaîne de format fmt, lorsque scan a lu ces arguments à partir du canal d'entrée formatée Scanf.Scanning.in_channel ic.

Par exemple, la fonction Scanf.scanf ci-dessous a le type ('a, 'b, 'c, 'd) scanner, puisqu'il s'agit d'une fonction d'entrée formatée qui lit depuis Scanf.Scanning.stdin : scanf fmt f applique f aux arguments spécifiés par fmt, en lisant ces arguments depuis stdin comme attendu.

Si le format fmt contient des indications %r, les fonctions d'entrée formatées correspondantes doivent être fournies avant la fonction réceptrice f. Par exemple, si read_elem est une fonction d'entrée pour des valeurs de type t, alors bscanf ic "%r;" read_elem f lit une valeur v de type t suivie d'un caractère ';', et retourne f v.

La fonction générale d'entrée formatée

val bscanf : Scanning.in_channel -> ('a, 'b, 'c, 'd) scanner

bscanf ic fmt r1 ... rN f lit des caractères depuis le canal d'entrée formatée Scanf.Scanning.in_channel ic et les convertit en valeurs selon la chaîne de format fmt. Comme étape finale, la fonction réceptrice f est appliquée aux valeurs lues et donne le résultat de l'appel bscanf.

Par exemple, si f est la fonction fun s i -> i + 1, alors Scanf.sscanf "x = 1" "%s = %i" f retourne 2.

Les arguments r1 à rN sont des fonctions d'entrée définies par l'utilisateur qui lisent l'argument correspondant aux conversions %r spécifiées dans la chaîne de format.

val bscanf_opt : Scanning.in_channel -> ('a, 'b, 'c, 'd) scanner_opt

Identique à Scanf.bscanf, mais retourne None en cas d'échec d'analyse.

Description de la chaîne de format

La chaîne de format est une chaîne de caractères qui contient trois types d'objets :

- des caractères littéraux, qui sont simplement mis en correspondance avec les caractères de l'entrée (avec un cas spécial pour l'espace et le saut de ligne, voir Scanf.space),

- des spécifications de conversion, chacune provoquant la lecture et la conversion d'un argument pour la fonction f (voir Scanf.conversion),

- des indications d'analyse pour spécifier les limites des jetons (voir l'analyse Scanf.indication).

Le caractère espace dans les chaînes de format

Comme mentionné ci-dessus, un caractère littéral dans la chaîne de format est simplement mis en correspondance avec le caractère suivant de l'entrée ; cependant, deux caractères font exception à cette règle : le caractère espace (' ' ou code ASCII 32) et le caractère saut de ligne ('\n' ou code ASCII 10). Un espace ne correspond pas à un seul caractère espace, mais à n'importe quelle quantité d'espaces blancs ('whitespace') dans l'entrée. Plus précisément, un espace dans la chaîne de format correspond à n'importe quel nombre de caractères tabulation, espace, saut de ligne et retour chariot. De même, un caractère saut de ligne dans la chaîne de format correspond soit à un seul saut de ligne, soit à un retour chariot suivi d'un saut de ligne.

Correspondant à n'importe quelle quantité d'espaces blancs, un espace dans la chaîne de format ne correspond également à aucune quantité d'espaces blancs.

Spécifications de conversion dans les chaînes de format

Les spécifications de conversion consistent en le caractère % , suivi d'un indicateur optionnel, d'une largeur de champ optionnelle, et suivi d'un ou deux caractères de conversion.

Les caractères de conversion et leurs significations sont :

- d : lit un entier décimal optionnellement signé ( 0-9 +).

- i : lit un entier optionnellement signé (les conventions de lecture habituelles pour les notations décimale ( 0-9 +), hexadécimale ( 0x[0-9a-f]+ et 0X[0-9A-F]+ ), octale ( 0o[0-7]+ ), et binaire ( 0b[0-1]+ ) sont comprises).

- u : lit un entier décimal non signé.

- x ou X : lit un entier hexadécimal non signé ( [0-9a-fA-F]+ ).

- o : lit un entier octal non signé ( [0-7]+ ).

- s : lit un argument de type chaîne qui s'étend autant que possible, jusqu'à ce que la condition de délimitation suivante soit remplie :

-un espace blanc a été trouvé (voir Scanf.space ),

-une indication de scan (voir indication de scan Scanf.indication ) a été rencontrée,

-la fin de l'entrée a été atteinte.

Par conséquent, cette conversion réussit toujours : elle retourne une chaîne vide si la condition de délimitation est remplie au début du scan.

- S : lit un argument de type chaîne délimitée (les délimiteurs et les caractères spéciaux échappés suivent les conventions lexicales d'OCaml).

- c : lit un seul caractère. Pour tester le caractère d'entrée courant sans le lire, spécifiez une largeur de champ nulle, c'est-à-dire utilisez la spécification %0c . Lève Invalid_argument si la spécification de largeur de champ est supérieure à 1.

- C : lit un seul caractère délimité (les délimiteurs et les caractères spéciaux échappés suivent les conventions lexicales d'OCaml).

- f , e , E , g , G : lit un nombre à virgule flottante optionnellement signé en notation décimale, dans le style dddd.ddd
e/E+-dd .

- h , H : lit un nombre à virgule flottante optionnellement signé en notation hexadécimale.

- F : lit un nombre à virgule flottante selon les conventions lexicales d'OCaml (donc le point décimal est obligatoire si la partie exposant n'est pas mentionnée).

- B : lit un argument booléen ( true ou false ).

- b : lit un argument booléen (pour la compatibilité descendante ; ne pas utiliser dans les nouveaux programmes).

- ld , li , lu , lx , lX , lo : lit un argument int32 selon le format spécifié par la deuxième lettre pour les entiers réguliers.

- nd , ni , nu , nx , nX , no : lit un argument nativeint selon le format spécifié par la deuxième lettre pour les entiers réguliers.

- Ld , Li , Lu , Lx , LX , Lo : lit un argument int64 selon le format spécifié par la deuxième lettre pour les entiers réguliers.

- [ plage ] : lit des caractères qui correspondent à l'un des caractères mentionnés dans la plage de caractères plage (ou qui n'y sont pas mentionnés, si la plage commence par ^ ). Lit une chaîne qui peut être vide, si le caractère d'entrée suivant ne correspond pas à la plage. L'ensemble des caractères de c1 à c2 (inclus) est désigné par c1-c2 . Ainsi, %[0-9] retourne une chaîne représentant un nombre décimal ou une chaîne vide si aucun chiffre décimal n'est trouvé ; de même, %[0-9a-f] retourne une chaîne de chiffres hexadécimaux. Si une parenthèse fermante apparaît dans une plage, elle doit survenir comme premier caractère de la plage (ou juste après le ^ en cas de négation de plage) ; ainsi []] correspond à un caractère ] et [^]] correspond à tout caractère qui n'est pas ] . Utilisez %% et %@ pour inclure un % ou un @ dans une plage.

- r : lecteur défini par l'utilisateur. Prend la fonction d'entrée formatée ri suivante et l'applique au tampon de scan ib pour lire l'argument suivant. La fonction d'entrée ri doit donc avoir le type Scanning.in_channel -> 'a et l'argument lu est de type 'a .

- { fmt %} : lit un argument de chaîne de format. La chaîne de format lue doit avoir le même type que la spécification de chaîne de format fmt . Par exemple, "%{ %i %}" lit toute chaîne de format qui peut lire une valeur de type int ; ainsi, si s est la chaîne "fmt:\"nombre est %u\"" , alors Scanf.sscanf s "fmt: %{%i%}" réussit et retourne la chaîne de format "nombre est %u" .

- ( fmt %) : substitution de sous-format de scan. Lit une chaîne de format rf dans l'entrée, puis continue le scan avec rf au lieu de scanner avec fmt . La chaîne de format rf doit avoir le même type que la spécification de chaîne de format fmt qu'elle remplace. Par exemple, "%( %i %)" lit toute chaîne de format qui peut lire une valeur de type int . La conversion retourne la chaîne de format lue rf , puis une valeur lue en utilisant rf . Ainsi, si s est la chaîne "\"%4d\"1234.00" , alors Scanf.sscanf s "%(%i%)" (fun fmt i -> fmt, i) est évalué à ("%4d", 1234) . Ce comportement n'est pas une simple substitution de format, car la conversion retourne la chaîne de format lue comme argument supplémentaire. Si vous avez besoin d'une substitution de format pure, utilisez l'indicateur spécial _ pour ignorer l'argument supplémentaire : la conversion %_( fmt %) lit une chaîne de format rf et se comporte ensuite comme la chaîne de format rf . Ainsi, si s est la chaîne "\"%4d\"1234.00" , alors Scanf.sscanf s "%_(%i%)" est simplement équivalent à Scanf.sscanf "1234.00" "%4d" .

- l : retourne le nombre de lignes lues jusqu'à présent.

- n : retourne le nombre de caractères lus jusqu'à présent.

- N ou L : retourne le nombre de jetons lus jusqu'à présent.

- ! : correspond à la condition de fin d'entrée.

- % : correspond à un caractère % dans l'entrée.

- @ : correspond à un caractère @ dans l'entrée.

- , : ne fait rien.

Après le caractère % qui introduit une conversion, il peut y avoir l'indicateur spécial _ : la conversion qui suit se produit comme d'habitude, mais la valeur résultante est ignorée. Par exemple, si f est la fonction fun i -> i + 1 , et s est la chaîne "x = 1" , alors Scanf.sscanf s "%_s = %i" f retourne 2 .

La largeur de champ est composée d'un littéral entier optionnel indiquant la largeur maximale du jeton à lire. Par exemple, %6d lit un entier, comportant au plus 6 chiffres décimaux ; %4f lit un flottant avec au plus 4 caractères ; et %8[\000-\255] retourne les 8 caractères suivants (ou tous les caractères encore disponibles, s'il y en a moins de 8 dans l'entrée).

Notes :

-comme mentionné ci-dessus, une conversion %s réussit toujours, même s'il n'y a rien à lire dans l'entrée : dans ce cas, elle retourne simplement "" .

-en plus des chiffres pertinents, les caractères '_' peuvent apparaître à l'intérieur des nombres (ce qui rappelle les conventions lexicales habituelles d'OCaml). Si une analyse plus stricte est souhaitée, utilisez la facilité de conversion de plage au lieu des conversions numériques.

-la facilité scanf n'est pas destinée à l'analyse lexicale et à l'analyse syntaxique intensive. Si elle s'avère pas assez expressive pour vos besoins, plusieurs alternatives existent : expressions régulières (module Str ), analyseurs de flux, analyseurs générés par ocamllex , analyseurs générés par ocamlyacc .

Indications de scan dans les chaînes de format

Les indications de scan apparaissent juste après les conversions de chaîne %s et %[ plage ] pour délimiter la fin du jeton. Une indication de scan est introduite par un caractère @ , suivi d'un caractère ordinaire c . Cela signifie que le jeton de chaîne doit se terminer juste avant le prochain c correspondant (qui est ignoré). Si aucun caractère c n'est rencontré, le jeton de chaîne s'étend autant que possible. Par exemple, "%s@\t" lit une chaîne jusqu'au prochain caractère de tabulation ou jusqu'à la fin de l'entrée. Si un caractère @ apparaît ailleurs dans la chaîne de format, il est traité comme un caractère ordinaire.

Note :

-Comme d'habitude dans les chaînes de format, les caractères % et @ doivent être échappés en utilisant %% et %@ ; cette règle s'applique toujours dans les spécifications de plage et les indications de scan. Par exemple, la chaîne de format "%s@%%" lit une chaîne jusqu'au prochain caractère % , et la chaîne de format "%s@%@" lit une chaîne jusqu'au prochain @ .

-Les indications de scan introduisent de légères différences dans la syntaxe des chaînes de format de Scanf , par rapport à celles utilisées pour le module Printf . Cependant, les indications de scan sont similaires à celles utilisées dans le module Format ; par conséquent, lors de la production de texte formaté à analyser par Scanf.bscanf , il est conseillé d'utiliser les fonctions d'impression du module Format (ou, si vous devez utiliser des fonctions de Printf , bannissez ou vérifiez soigneusement les chaînes de format qui contiennent des caractères '@' ).

Exceptions lors du scan

Les analyseurs peuvent lever les exceptions suivantes lorsque l'entrée ne peut pas être lue conformément à la chaîne de format :

-Lève Scanf.Scan_failure si l'entrée ne correspond pas au format.

-Lève Failure si une conversion en nombre n'est pas possible.

-Lève End_of_file si la fin de l'entrée est rencontrée alors que d'autres caractères sont nécessaires pour lire la spécification de conversion courante.

-Lève Invalid_argument si la chaîne de format est invalide.

Note :

-en conséquence, le scan d'une conversion %s ne lève jamais l'exception End_of_file : si la fin de l'entrée est atteinte, la conversion réussit et retourne simplement les caractères lus jusqu'à présent, ou "" s'il n'y en a jamais eu de lus.
