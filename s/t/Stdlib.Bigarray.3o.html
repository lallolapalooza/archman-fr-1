Types d'éléments

Les tableaux peuvent contenir des éléments des types suivants :

- Nombres flottants de précision IEEE 16 bits ( Bigarray.float16_elt ),

- Nombres flottants de précision IEEE 32 bits ( Bigarray.float32_elt ),

- Nombres flottants de précision IEEE 64 bits ( Bigarray.float64_elt ),

- Nombres complexes flottants de précision IEEE 2 * 32 bits ( Bigarray.complex32_elt ),

- Nombres complexes flottants de précision IEEE 2 * 64 bits ( Bigarray.complex64_elt ),

- Entiers signés ou non signés 8 bits ( Bigarray.int8_signed_elt ou Bigarray.int8_unsigned_elt ),

- Entiers signés ou non signés 16 bits ( Bigarray.int16_signed_elt ou Bigarray.int16_unsigned_elt ),

- Entiers OCaml (entiers signés, 31 bits sur les architectures 32 bits, 63 bits sur les architectures 64 bits) ( Bigarray.int_elt ),

- Entiers 32 bits ( Bigarray.int32_elt ),

- Entiers 64 bits ( Bigarray.int64_elt ),

- Entiers natifs (32 bits sur les architectures 32 bits, 64 bits sur les architectures 64 bits) ( Bigarray.nativeint_elt ).

Chaque type d'élément est représenté au niveau typage par l'un des types *_elt définis ci-dessous (définis avec un constructeur plutôt que des types abstraits pour des raisons techniques d'injectivité).

| Float16 : (float, float16_elt) kind

Chaque type d'élément est associé à un type OCaml, qui est le type des valeurs OCaml pouvant être stockées dans le Bigarray ou lues à partir de celui-ci. Ce type n'est pas nécessairement le même que le type des éléments du tableau : par exemple, un Bigarray dont les éléments sont de type float32_elt contient des flottants de précision IEEE 32 bits, mais la lecture ou l'écriture d'un de ses éléments depuis OCaml utilise le type OCaml float, qui est des flottants de précision IEEE 64 bits.

Le type GADT ('a, 'b) kind capture cette association entre un type OCaml 'a pour les valeurs lues ou écrites dans le Bigarray et un type d'élément 'b représentant le contenu réel du Bigarray. Ses constructions listent toutes les associations possibles entre types OCaml et types d'éléments, et sont ré-exportées pour des raisons de compatibilité.

L'utilisation d'un type de données algébrique généralisé (GADT) ici permet d'écrire des fonctions polymorphiques bien typées dont le type de retour dépend du type de l'argument, comme :

  let zero : type a b. (a, b) kind -> a = function
    | Float32 -> 0.0 | Complex32 -> Complex.zero
    | Float64 -> 0.0 | Complex64 -> Complex.zero
    | Float16 -> 0.0
    | Int8_signed -> 0 | Int8_unsigned -> 0
    | Int16_signed -> 0 | Int16_unsigned -> 0
    | Int32 -> 0l | Int64 -> 0L
    | Int -> 0 | Nativeint -> 0n
    | Char -> '\000'

Comme indiqué par les types des valeurs ci-dessus, les tableaux de type float16_elt, float32_elt et float64_elt sont accédés avec le type OCaml float. Les tableaux de type complexe complex32_elt et complex64_elt sont accédés avec le type OCaml Complex.t. Les tableaux de type entier sont accédés avec le plus petit type d'entier OCaml nécessaire pour représenter les éléments du tableau : int pour les tableaux 8 et 16 bits, ainsi que les tableaux d'entiers OCaml ; int32 pour les tableaux 32 bits ; int64 pour les tableaux 64 bits ; et nativeint pour les tableaux d'entiers natifs. Enfin, les tableaux de type int8_unsigned_elt peuvent également être accédés comme des tableaux de caractères au lieu de tableaux de petits entiers, en utilisant la valeur de type char au lieu de int8_unsigned.

val kind_size_in_bytes : ('a, 'b) kind -> int

kind_size_in_bytes k est le nombre d'octets nécessaires pour stocker un élément de type k.

Depuis 4.03

Disposition des tableaux

type c_layout =
| C_layout_typ

Voir Bigarray.fortran_layout .

type fortran_layout =
| Fortran_layout_typ

Afin de faciliter l'interopérabilité avec le code C et Fortran existant, cette bibliothèque supporte deux dispositions mémoire différentes pour les tableaux Bigarray : l'une compatible avec les conventions C, l'autre compatible avec les conventions Fortran.

Dans le style C, les indices des tableaux commencent à 0, et les tableaux multidimensionnels sont alignés en format ligne. C'est-à-dire que pour un tableau à deux dimensions, tous les éléments de la ligne 0 se trouvent consécutivement en mémoire, suivis de tous les éléments de la ligne 1, etc. Autrement dit, les éléments du tableau à la position (x,y) et (x, y+1) sont voisins en mémoire.

Dans le style Fortran, les indices des tableaux commencent à 1, et les tableaux multidimensionnels sont alignés en format colonne. C'est-à-dire que les éléments du tableau à la position (x,y) et (x, y+1) sont voisins en mémoire.

Le style Fortran est utilisé pour accéder aux éléments des tableaux de type complex32_elt et complex64_elt avec le type OCaml Complex.t.

Remise en forme des Bigarrays

val reshape : ('a, 'b, 'c) Genarray.t -> int array -> ('a, 'b, 'c) Genarray.t

reshape b [|d1;...;dN|] convertit le Bigarray b en un tableau N-dimensionnel de dimensions d1 ... dN . Le tableau retourné et le tableau original b partagent leurs données et ont le même layout. Par exemple, en supposant que b est un tableau à une dimension de dimension 12, reshape b [|3;4|] retourne un tableau à deux dimensions b' de dimensions 3 et 4. Si b a un layout C, l'élément (x,y) de b' correspond à l'élément x * 3 + y de b . Si b a un layout Fortran, l'élément (x,y) de b' correspond à l'élément x + (y - 1) * 4 de b . Le Bigarray retourné doit avoir exactement le même nombre d'éléments que le Bigarray original b . C'est-à-dire, le produit des dimensions de b doit être égal à i1 * ... * iN . Sinon, Invalid_argument est levée.

Bigarrays et sécurité de concurrence

Il faut être prudent lors de l'accès concurrent aux bigarrays à partir de plusieurs domaines : l'accès à un bigarray ne plantera jamais un programme, mais des accès non synchronisés pourraient donner des résultats surprenants (non cohérents séquentiellement).

Atomicité

Toute opération sur les bigarrays qui accède à plus d'un élément du tableau n'est pas atomique. Cela inclut le découpage (slicing), le blitting et le remplissage des bigarrays.

Par exemple, considérons le programme suivant :

open Bigarray
let size = 100_000_000
let a = Array1.init Int C_layout size (fun _ -> 1)
let update f a () =
  for i = 0 to size - 1 do a.{i} <- f a.{i} done
let d1 = Domain.spawn (update (fun x -> x + 1) a)
let d2 = Domain.spawn (update (fun x -> 2 * x + 1) a)
let () = Domain.join d1; Domain.join d2

Après avoir exécuté ce code, chaque champ du bigarray a est soit 2 , 3 , 4 ou 5 . Si l'atomicité est requise, l'utilisateur doit implémenter sa propre synchronisation (par exemple, en utilisant Mutex.t ).

Courses de données

Si deux domaines n'accèdent qu'à des parties disjointes du bigarray, alors le comportement observé est équivalent à un entrelacement séquentiel des opérations des deux domaines.

Une course de données se produit lorsque deux domaines accèdent au même élément de bigarray sans synchronisation et qu'au moins l'un des accès est une écriture. En l'absence de courses de données, le comportement observé est équivalent à un entrelacement séquentiel des opérations des différents domaines.

Dans la mesure du possible, les courses de données doivent être évitées en utilisant la synchronisation pour médiatiser les accès aux éléments du bigarray.

En effet, en présence de courses de données, les programmes ne planteront pas, mais le comportement observé peut ne pas être équivalent à un entrelacement séquentiel quelconque des opérations provenant de différents domaines.

Déchirure (Tearing)

Les Bigarrays présentent une particularité en présence de courses de données : les opérations concurrentes sur les bigarrays pourraient produire des valeurs surprenantes dues à la déchirure. Plus précisément, l'entrelacement d'écritures et de lectures partielles pourrait créer des valeurs qui n'existeraient pas lors d'une exécution séquentielle. Par exemple, à la fin de

let res = Array1.init Complex64 c_layout size (fun _ -> Complex.zero)
let d1 = Domain.spawn (fun () -> Array1.fill res Complex.one)
let d2 = Domain.spawn (fun () -> Array1.fill res Complex.i)
let () = Domain.join d1; Domain.join d2

le bigarray res pourrait contenir des valeurs qui ne sont ni Complex.i ni Complex.one (par exemple 1 + i ).
