DESCRIPTION

Ces macros définissent et opèrent sur quatre types de structures de données qui peuvent être utilisées dans le code source C et C++ :

  1. Listes
  2. Listes simplement chaînées
  3. Queues simplement chaînées avec ajout en fin
  4. Queues avec ajout en fin
Les quatre structures prennent en charge les fonctionnalités suivantes :
  1. Insertion d'une nouvelle entrée en tête de liste.
  2. Insertion d'une nouvelle entrée après un élément existant dans la liste.
  3. Suppression en temps O(1) d'une entrée en tête de liste.
  4. Parcours avant dans la liste.
  5. Échange du contenu de deux listes.

Les listes simplement chaînées sont les plus simples des quatre structures de données et ne prennent en charge que les fonctionnalités ci-dessus. Les listes simplement chaînées sont idéales pour les applications avec de grands ensembles de données et peu ou pas de suppressions, ou pour implémenter une file LIFO (dernier entré, premier sorti). Les listes simplement chaînées ajoutent les fonctionnalités suivantes :

  1. Suppression en temps O(n) de n'importe quelle entrée de la liste.
  2. Concaténation en temps O(n) de deux listes.

Les queues simplement chaînées avec ajout en fin ajoutent les fonctionnalités suivantes :

  1. Des entrées peuvent être ajoutées à la fin d'une liste.
  2. Suppression en temps O(n) de n'importe quelle entrée de la liste.
  3. Elles peuvent être concaténées.
Cependant :
  1. Toutes les insertions de liste doivent spécifier la tête de la liste.
  2. Chaque entrée de tête nécessite deux pointeurs au lieu d'un.
  3. La taille du code est environ 15% plus grande et les opérations sont environ 20% plus lentes que pour les listes simplement chaînées.

Les queues simplement chaînées avec ajout en fin sont idéales pour les applications avec de grands ensembles de données et peu ou pas de suppressions, ou pour implémenter une file FIFO (premier entré, premier sorti).

Toutes les structures de données doublement chaînées (listes et queues avec ajout en fin) permettent en outre :

  1. Insertion d'une nouvelle entrée avant un élément existant dans la liste.
  2. Suppression en temps O(1) de n'importe quelle entrée de la liste.
Cependant :
  1. Chaque élément nécessite deux pointeurs au lieu d'un.
  2. La taille du code et le temps d'exécution des opérations (à l'exception de la suppression) sont environ le double de ceux des structures de données simplement chaînées.

Les listes chaînées sont les plus simples des structures de données doublement chaînées. Elles ajoutent les fonctionnalités suivantes par rapport aux listes simplement chaînées :

  1. Concaténation en temps O(n) de deux listes.
  2. Elles peuvent être parcourues en arrière.
Cependant :
  1. Pour parcourir en arrière, une entrée pour commencer le parcours et la liste dans laquelle elle se trouve doivent être spécifiées.

Les queues avec ajout en fin ajoutent les fonctionnalités suivantes :

  1. Des entrées peuvent être ajoutées à la fin d'une liste.
  2. Elles peuvent être parcourues en arrière, de la fin vers le début.
  3. Elles peuvent être concaténées.
Cependant :
  1. Toutes les insertions et suppressions de liste doivent spécifier la tête de la liste.
  2. Chaque entrée de tête nécessite deux pointeurs au lieu d'un.
  3. La taille du code est environ 15% plus grande et les opérations sont environ 20% plus lentes que pour les listes simplement chaînées.

Dans les définitions de macros, TYPE est le nom d'une structure définie par l'utilisateur. La structure doit contenir un champ nommé NAME qui est de type SLIST_ENTRY, STAILQ_ENTRY, LIST_ENTRY, ou TAILQ_ENTRY. Dans les définitions de macros, CLASSTYPE est le nom d'une classe définie par l'utilisateur. La classe doit contenir un champ nommé NAME qui est de type SLIST_CLASS_ENTRY, STAILQ_CLASS_ENTRY, LIST_CLASS_ENTRY, ou TAILQ_CLASS_ENTRY. L'argument HEADNAME est le nom d'une structure définie par l'utilisateur qui doit être déclarée en utilisant les macros SLIST_HEAD, SLIST_CLASS_HEAD, STAILQ_HEAD, STAILQ_CLASS_HEAD, LIST_HEAD, LIST_CLASS_HEAD, TAILQ_HEAD, ou TAILQ_CLASS_HEAD. LISTES SIMPLEMENT CHAÎNÉES

Une liste simplement chaînée est dirigée par une structure définie par la macro SLIST_HEAD. Cette structure contient un unique pointeur vers le premier élément de la liste. Les éléments sont simplement chaînés pour un minimum d'espace et de surcharge de manipulation de pointeur, au détriment d'une suppression en temps O(n) pour les éléments arbitraires. De nouveaux éléments peuvent être ajoutés à la liste après un élément existant ou en tête de liste. Une structure SLIST_HEAD est déclarée comme suit :

SLIST_HEAD(HEADNAME, TYPE) head;

où HEADNAME est le nom de la structure à définir, et TYPE est le type des éléments à lier dans la liste. Un pointeur vers la tête de la liste peut ensuite être déclaré comme suit :

struct HEADNAME *headp;

(Les noms head et headp sont sélectionnables par l'utilisateur.)

La macro SLIST_HEAD_INITIALIZER évalue à un initialiseur pour la liste head.

La macro SLIST_CONCAT concatène la liste dirigée par head2 à la fin de celle dirigée par head1, supprimant toutes les entrées de la première. L'utilisation de cette macro doit être évitée car elle parcourt l'intégralité de la liste head1. Une queue simplement chaînée avec ajout en fin devrait être utilisée si cette macro est nécessaire dans des chemins de code utilisés fréquemment ou pour opérer sur de longues listes.

La macro SLIST_EMPTY évalue à vrai s'il n'y a pas d'éléments dans la liste.

La macro SLIST_ENTRY déclare une structure qui relie les éléments de la liste.

La macro SLIST_FIRST renvoie le premier élément de la liste ou NULL si la liste est vide.

La macro SLIST_FOREACH parcourt la liste référencée par head dans le sens avant, assignant chaque élément à tour de rôle à var.

La macro SLIST_FOREACH_FROM se comporte de manière identique à SLIST_FOREACH lorsque var est NULL, sinon elle traite var comme un élément SLIST trouvé précédemment et commence la boucle à var au lieu du premier élément de la SLIST référencée par head.

La macro SLIST_FOREACH_SAFE parcourt la liste référencée par head dans le sens avant, assignant chaque élément à tour de rôle à var. Cependant, contrairement à SLIST_FOREACH(), ici il est permis de supprimer var ainsi que de le libérer à l'intérieur de la boucle en toute sécurité sans interférer avec le parcours.

La macro SLIST_FOREACH_FROM_SAFE se comporte de manière identique à SLIST_FOREACH_SAFE lorsque var est NULL, sinon elle traite var comme un élément SLIST trouvé précédemment et commence la boucle à var au lieu du premier élément de la SLIST référencée par head.

La macro SLIST_INIT initialise la liste référencée par head.

La macro SLIST_INSERT_HEAD insère le nouvel élément elm en tête de la liste.

La macro SLIST_INSERT_AFTER insère le nouvel élément elm après l'élément listelm.

La macro SLIST_NEXT retourne le prochain élément de la liste.

La macro SLIST_REMOVE_AFTER retire l'élément qui suit elm de la liste. Contrairement à SLIST_REMOVE, cette macro ne parcourt pas toute la liste.

La macro SLIST_REMOVE_HEAD retire l'élément elm de la tête de la liste. Pour une efficacité optimale, les éléments retirés de la tête de la liste devraient utiliser explicitement cette macro plutôt que la macro générique SLIST_REMOVE.

La macro SLIST_REMOVE retire l'élément elm de la liste. L'utilisation de cette macro doit être évitée car elle parcourt toute la liste. Une liste doublement chaînée devrait être utilisée si cette macro est nécessaire dans des chemins de code à forte utilisation ou pour opérer sur de longues listes.

La macro SLIST_SWAP échange le contenu de head1 et head2.

NAME

LIBRARY

libbsd

SYNOPSIS

DESCRIPTION

The STAILQ_CONCAT macro appends the singly linked tail queue head2 to the end of the singly linked tail queue head1. The elements are appended in the same order as they appeared in head2. After the operation, head2 is initialized as an empty queue.

The STAILQ_CONCAT_TAIL macro is identical to STAILQ_CONCAT, except that the contents of head2 are appended to the end of head1 and head1's tail pointer is updated to point to the last element of head2. This macro is more efficient than STAILQ_CONCAT if head1 is not empty.

TAIL QUEUES

Tail queues are doubly linked lists, which also maintain pointers to the first and last elements. This allows for constant time insertion and deletion at both ends of the queue.

The following macros are available for manipulating tail queues:

TAILQ_HEAD
Declares a tail queue head.
TAILQ_HEAD_INITIALIZER
Initializes a tail queue head.
TAILQ_ENTRY
Declares a tail queue entry.
TAILQ_INIT
Initializes an empty tail queue.
TAILQ_IS_EMPTY
Checks if the tail queue is empty.
TAILQ_FIRST
Returns the first element in the tail queue.
TAILQ_NEXT
Returns the next element in the tail queue.
TAILQ_LAST
Returns the last element in the tail queue.
TAILQ_PREV
Returns the previous element in the tail queue.
TAILQ_INSERT_HEAD
Inserts an element at the head of the tail queue.
TAILQ_INSERT_TAIL
Inserts an element at the tail of the tail queue.
TAILQ_INSERT_AFTER
Inserts an element after a given element.
TAILQ_INSERT_BEFORE
Inserts an element before a given element.
TAILQ_REMOVE
Removes a given element from the tail queue.
TAILQ_REMOVE_HEAD
Removes the first element from the tail queue.
TAILQ_REMOVE_TAIL
Removes the last element from the tail queue.
TAILQ_FOREACH
Iterates over the tail queue.
TAILQ_FOREACH_REVERSE
Iterates over the tail queue in reverse order.
TAILQ_SWAP
Swaps the contents of two tail queues.

TAIL QUEUE EXAMPLE

struct node {
    int             data;
    struct node {
        struct node *tqe_next;
        struct node *tqe_prev;
    } node_list;
};

struct node *np, *nnp;
struct nodehead {
    struct node_entry {
        struct node *tqe_next;
        struct node *tqe_prev;
    } tqh_first;
    struct node_entry * tqh_last;
} head;

TAILQ_INIT(&head);

np = malloc(sizeof(struct node));
np->data = 10;
TAILQ_INSERT_HEAD(&head, np, node_list);

np = malloc(sizeof(struct node));
np->data = 20;
TAILQ_INSERT_TAIL(&head, np, node_list);

nnp = TAILQ_FIRST(&head);
np = malloc(sizeof(struct node));
np->data = 15;
TAILQ_INSERT_AFTER(&head, nnp, np, node_list);

TAILQ_FOREACH(np, &head, node_list) {
    printf("%d\n", np->data);
}

np = TAILQ_LAST(&head, nodehead);
TAILQ_REMOVE(&head, np, node_list);
free(np);

np = TAILQ_FIRST(&head);
TAILQ_REMOVE_HEAD(&head, node_list);
free(np);

np = TAILQ_LAST(&head, nodehead);
TAILQ_REMOVE_TAIL(&head, node_list);
free(n1);
n1 = n2;
}

DIAGNOSTICS

When debugging queue(3), it can be useful to trace queue changes. To enable tracing, define the macro QUEUE_MACRO_DEBUG_TRACE at compile time.

It can also be useful to trash pointers that have been unlinked from a queue, to detect use after removal. To enable pointer trashing, define the macro QUEUE_MACRO_DEBUG_TRASH at compile time. The macro QMD_IS_TRASHED(void *ptr) returns true if ptr has been trashed by the QUEUE_MACRO_DEBUG_TRASH option.

BIBLIOTHÈQUE

libbsd

SYNOPSIS

#include <sys/queue.h>
void
STAILQ_CONCAT(struct nom *head1, struct nom *head2);
void
STAILQ_CONCAT_TAIL(struct nom *head1, struct nom *head2);

DESCRIPTION

La macro STAILQ_CONCAT ajoute la file à queue singulièrement chaînée head2 à la fin de la file à queue singulièrement chaînée head1. Les éléments sont ajoutés dans le même ordre qu'ils apparaissaient dans head2. Après l'opération, head2 est initialisée comme une file vide.

La macro STAILQ_CONCAT_TAIL est identique à STAILQ_CONCAT, sauf que le contenu de head2 est ajouté à la fin de head1 et le pointeur de fin de head1 est mis à jour pour pointer vers le dernier élément de head2. Cette macro est plus efficace que STAILQ_CONCAT si head1 n'est pas vide.

LISTES SINGULIÈREMENT CHAÎNÉES

Les listes singulièrement chaînées sont implémentées à l'aide des macros définies dans <sys/queue.h>. Elles sont composées d'éléments de liste qui sont liés par un seul pointeur.
