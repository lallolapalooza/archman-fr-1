Le type pour les chaînes.

val make : int -> char -> string

make n c est une chaîne de longueur n avec chaque indice contenant le caractère c.

Lève Invalid_argument si n < 0 ou n > Sys.max_string_length.

init n ~f est une chaîne de longueur n avec l'indice i contenant le caractère f i (appelé dans l'ordre d'indice croissant).

Extraction de sous-chaînes

val sub : string -> pos:int -> len:int -> string

sub s ~pos ~len est une chaîne de longueur len, contenant la sous-chaîne de s qui commence à la position pos et a une longueur len.

Lève Invalid_argument si pos et len ne désignent pas une sous-chaîne valide de s.

val split_on_char : sep:char -> string -> string list

split_on_char ~sep s est la liste de toutes les sous-chaînes (optionnellement vides) de s séparées par le caractère sep. Si s est vide, le résultat est la liste [""].

Le résultat est spécifié par les invariants suivants :

- La liste n'est pas vide.

- La concaténation de ses éléments en utilisant sep comme séparateur renvoie une chaîne égale à l'entrée ( concat (make 1 sep) (split_on_char sep s) = s ).

- Aucune des chaînes du résultat ne contient le caractère sep.

val escaped : string -> string

escaped s est s avec les caractères spéciaux représentés par des chaînes d'échappement, suivant les conventions lexicales d'OCaml.

Tous les caractères en dehors de la plage des caractères imprimables de l'ensemble de caractères ASCII [0x20;0x7E] sont échappés, ainsi que le caractère antislash (0x2F) et le caractère guillemet double (0x22).

La fonction Scanf.unescaped est un inverse gauche de escaped, c'est-à-dire que Scanf.unescaped (escaped s) = s pour toute chaîne s (sauf si escaped s échoue).

Vérification orthographique

val edit_distance : ?limit:int -> t -> t -> int

edit_distance s0 s1 est le nombre d'éditions d'un seul caractère (comprises comme insertion, suppression, substitution, transposition) nécessaires pour transformer s0 en s1 .

Si limit est fourni, la fonction retourne avec limit dès qu'il est déterminé que s0 et s1 ont une distance d'au moins limit . C'est plus rapide si vous avez une limite fixe, par exemple pour la correction orthographique.

La fonction suppose que les chaînes sont encodées en UTF-8 et utilise Uchar.t pour la notion de caractère. Les erreurs de décodage sont remplacées par Uchar.rep . La normalisation des chaînes en NFC donne de meilleurs résultats.

Note. Ceci implémente la distance plus simple Optimal String Alignment (OSA), pas la distance Damerau-Levenshtein. Avec cette fonction "ca" et "abc" ont une distance de 3 pas 2.

val spellcheck : ?max_dist:(string -> int) -> ((string -> unit) -> unit) -> string -> string list

spellcheck iter_dict s sont les chaînes énumérées par l'itérateur iter_dict dont la StringLabels.edit_distance à s est la plus petite et au plus max_dist s . Si plusieurs corrections sont retournées, leur ordre est celui trouvé dans iter_dict . Le max_dist s par défaut est :

- 0 si s a de 0 à 2 caractères Unicode.

- 1 si s a de 3 à 4 caractères Unicode.

- 2 sinon.

Si votre dictionnaire est une liste l , un iter_dict adapté est donné par (fun yield -> List.iter yield l) .

Toutes les chaînes sont supposées être encodées en UTF-8, les erreurs de décodage sont remplacées par des caractères Uchar.rep .

Décodage binaire des entiers

Les fonctions de cette section décodent les entiers en binaire à partir de chaînes.

Toutes les fonctions suivantes lèvent Invalid_argument si les caractères nécessaires à l'indice i pour décoder l'entier ne sont pas disponibles.

L'encodage little-endian (resp. big-endian) signifie que les octets de poids faible (resp. fort) sont stockés en premier. Big-endian est aussi connu sous le nom de network byte order. L'encodage native-endian est soit little-endian soit big-endian selon Sys.big_endian .

Les entiers 32 bits et 64 bits sont représentés par les types int32 et int64 , qui peuvent être interprétés comme des nombres signés ou non signés.

Les entiers 8 bits et 16 bits sont représentés par le type int , qui a plus de bits que l'encodage binaire. Ces bits supplémentaires sont étendus en signe (ou étendus à zéro) pour les fonctions qui décodent des entiers 8 bits ou 16 bits et les représentent avec des valeurs int .
