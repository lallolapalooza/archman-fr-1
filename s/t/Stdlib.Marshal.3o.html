Module Marshal

type extern_flags =
| No_sharing (* Ne pas préserver le partage *)
| Closures (* Sérialiser les closures *)
| Compat_32 (* Compatibilité 32 bits *)

Les drapeaux pour les fonctions Marshal.to_*.

val to_channel : out_channel -> 'a -> extern_flags list -> unit

Marshal.to_channel chan v flags écrit la représentation de v sur le canal chan. L'argument flags est une liste de drapeaux qui guident le comportement de sérialisation concernant le partage, les valeurs fonctionnelles et la compatibilité entre les plateformes 32 et 64 bits.

Si flags ne contient pas No_sharing, les cycles et le partage au sein de v sont détectés et préservés dans le flux d'octets produit. En particulier, cela garantit que la sérialisation se termine toujours. Le partage entre les valeurs sérialisées par des appels successifs à Marshal.to_channel n'est ni détecté ni préservé, même s'il existe. Si flags contient No_sharing, le partage est ignoré. Cela entraîne une sérialisation plus rapide si v n'a pas de sous-structures partagées, mais peut entraîner une sérialisation plus lente et des représentations plus volumineuses si v contient réellement du partage, voire ne pas se terminer si v contient des cycles.

Si flags ne contient pas Closures, la sérialisation échoue lorsqu'elle rencontre une valeur fonctionnelle dans v : seules des structures pures, ne contenant pas de fonctions ou d'objets, peuvent être transmises entre des programmes distincts. Si flags contient Closures, les valeurs fonctionnelles sont sérialisées comme la position dans le code du programme ainsi que les valeurs correspondant aux variables libres capturées dans la fermeture. Dans ce cas, le résultat de la sérialisation ne peut être lu qu'à partir de processus exécutant exactement le même programme, avec un code compilé de manière identique. (Ceci est vérifié lors de la désérialisation, en utilisant un hachage MD5 du code transmis avec la position du code.)

La définition exacte des variables libres capturées dans une fermeture n'est pas spécifiée et peut varier entre le bytecode et le code natif (et selon les drapeaux d'optimisation). En particulier, une valeur fonctionnelle accédant à une référence globale peut ou non inclure la référence dans sa fermeture. Si c'est le cas, la désérialisation de la fermeture correspondante créera une nouvelle référence, distincte de la référence globale.

Si flags contient Compat_32, la sérialisation échoue lorsqu'elle rencontre une valeur entière en dehors de la plage des entiers représentables sur une plateforme 32 bits, c'est-à-dire de -2^30 à 2^30 - 1. Cela garantit que les données sérialisées sur une plateforme 64 bits peuvent être lues en toute sécurité sur une plateforme 32 bits. Si flags ne contient pas Compat_32, les valeurs entières en dehors de la plage mentionnée sont sérialisées et peuvent être lues sur une plateforme 64 bits, mais provoqueront une erreur lors de la désérialisation sur une plateforme 32 bits. Le drapeau Marshal.Compat_32 n'est pertinent que si la sérialisation est effectuée sur une plateforme 64 bits ; il n'a aucun effet si elle est effectuée sur une plateforme 32 bits.

Lève Failure si chan n'est pas en mode binaire.

val to_bytes : 'a -> extern_flags list -> bytes

Marshal.to_bytes v flags renvoie un flux d'octets contenant la représentation de v. L'argument flags a la même signification que dans Marshal.to_channel.

Depuis 4.02

val to_string : 'a -> extern_flags list -> string

Similaire à to_bytes mais renvoie le résultat sous forme de chaîne de caractères au lieu d'un flux d'octets.

val to_buffer : bytes -> int -> int -> 'a -> extern_flags list -> int

Marshal.to_buffer buff ofs len v flags sérialise la valeur v, stockant sa représentation binaire dans le tampon buff, en commençant à la position ofs, et écrivant au maximum len octets. Renvoie le nombre d'octets réellement écrits dans le tampon. Si la représentation binaire de v ne rentre pas dans len caractères, l'exception Failure est levée.

val from_channel : in_channel -> 'a

Marshal.from_channel chan lit depuis le canal chan la représentation d'une valeur structurée, telle que produite par l'une des fonctions Marshal.to_*, et reconstruit et renvoie la valeur correspondante.

Lève End_of_file si chan est déjà à la fin du fichier.

Lève Failure si la fin du fichier est atteinte pendant la désérialisation ou si chan n'est pas en mode binaire.

val from_bytes : bytes -> int -> 'a

Marshal.from_bytes buff ofs désérialise une valeur structurée comme le fait Marshal.from_channel, mais la représentation est lue à partir du flux d'octets buff, en commençant à la position ofs. Le flux d'octets n'est pas modifié.

Depuis 4.02

val from_string : string -> int -> 'a

Similaire à from_bytes mais prend une chaîne de caractères en argument au lieu d'un flux d'octets.

val header_size : int

Les octets représentant une valeur sérialisée sont composés d'un en-tête fixe et d'une partie de données variable, dont la taille peut être déterminée à partir de l'en-tête. Marshal.header_size est la taille, en octets, de l'en-tête. Marshal.data_size buff ofs est la taille, en octets, de la partie données, en supposant qu'un en-tête valide est stocké dans buff à partir de la position ofs. Enfin, Marshal.total_size buff ofs est la taille totale, en octets, de la valeur sérialisée. Marshal.data_size et Marshal.total_size lèvent tous deux Failure si buff, ofs ne contiennent pas d'en-tête valide.

Pour lire la représentation d'une valeur sérialisée comme un flux d'octets, le programme doit d'abord lire Marshal.header_size octets dans le flux, puis déterminer la longueur du reste de la représentation avec Marshal.data_size, s'assurer que le flux est suffisamment long pour contenir les données restantes, puis les lire, et enfin appeler Marshal.from_bytes pour désérialiser la valeur.

val data_size : bytes -> int -> int

Voir Marshal.header_size.

val total_size : bytes -> int -> int

Voir Marshal.header_size.

Sérialisation et sécurité de domaine

Lorsque vous sérialisez une valeur mutable susceptible d'être modifiée par un autre domaine, vous devez être prudent. Modifier une valeur en cours de sérialisation (c'est-à-dire convertie en un flux d'octets) est une erreur de programmation et pourrait entraîner des valeurs inattendues (lors de la désérialisation) en raison du déchirement (tearing), car la sérialisation implique une copie octet par octet.
