DESCRIPTION

Ces macros fournissent une implémentation des listes chaînées simples (SLIST), des files à queue chaînées simples (STAILQ), des listes doublement chaînées (LIST) et des files à queue doublement chaînées (TAILQ).

Chaque structure de liste nécessite une définition d'entrée qui doit contenir au moins deux champs : un pointeur vers l'élément suivant et un champ pour le type de liste. Les listes doublement chaînées et les files à queue doublement chaînées ont également un pointeur vers l'élément précédent.

Les listes chaînées simples ne peuvent être parcourues que dans un sens, tandis que les files à queue chaînées simples ne peuvent pas être parcourues en arrière.

Les listes doublement chaînées et les files à queue doublement chaînées peuvent être parcourues dans les deux sens. Les files à queue doublement chaînées ont un pointeur vers la fin de la file, ce qui permet d'ajouter des éléments à la fin en temps constant.

La famille SLIST gère des listes chaînées simples.

Les macros SLIST_ENTRY, SLIST_HEAD, SLIST_INIT, SLIST_INSERT_HEAD, SLIST_INSERT_AFTER, SLIST_REMOVE_HEAD, SLIST_REMOVE_AFTER, SLIST_REMOVE, SLIST_FIRST, SLIST_NEXT, SLIST_EMPTY, SLIST_FOREACH, SLIST_FOREACH_SAFE, SLIST_FOREACH_FROM, SLIST_FOREACH_FROM_SAFE, SLIST_HEAD_INITIALIZER, SLIST_CONCAT, SLIST_SWAP, SLIST_CLASS_ENTRY et SLIST_CLASS_HEAD sont utilisées pour manipuler des listes chaînées simples.

La famille STAILQ gère des files à queue chaînées simples.

Les macros STAILQ_ENTRY, STAILQ_HEAD, STAILQ_INIT, STAILQ_INSERT_HEAD, STAILQ_INSERT_TAIL, STAILQ_INSERT_AFTER, STAILQ_REMOVE_HEAD, STAILQ_REMOVE_AFTER, STAILQ_REMOVE, STAILQ_FIRST, STAILQ_LAST, STAILQ_NEXT, STAILQ_EMPTY, STAILQ_FOREACH, STAILQ_FOREACH_SAFE, STAILQ_FOREACH_FROM, STAILQ_FOREACH_FROM_SAFE, STAILQ_HEAD_INITIALIZER, STAILQ_CONCAT, STAILQ_SWAP, STAILQ_CLASS_ENTRY et STAILQ_CLASS_HEAD sont utilisées pour manipuler des files à queue chaînées simples.

La famille LIST gère des listes doublement chaînées.

Les macros LIST_ENTRY, LIST_HEAD, LIST_INIT, LIST_INSERT_HEAD, LIST_INSERT_BEFORE, LIST_INSERT_AFTER, LIST_REMOVE, LIST_FIRST, LIST_NEXT, LIST_PREV, LIST_EMPTY, LIST_FOREACH, LIST_FOREACH_SAFE, LIST_FOREACH_FROM, LIST_FOREACH_FROM_SAFE, LIST_HEAD_INITIALIZER, LIST_CONCAT, LIST_SWAP, LIST_CLASS_ENTRY et LIST_CLASS_HEAD sont utilisées pour manipuler des listes doublement chaînées.

La famille TAILQ gère des files à queue doublement chaînées.

Les macros TAILQ_ENTRY, TAILQ_HEAD, TAILQ_INIT, TAILQ_INSERT_HEAD, TAILQ_INSERT_TAIL, TAILQ_INSERT_BEFORE, TAILQ_INSERT_AFTER, TAILQ_REMOVE, TAILQ_FIRST, TAILQ_LAST, TAILQ_NEXT, TAILQ_PREV, TAILQ_EMPTY, TAILQ_FOREACH, TAILQ_FOREACH_REVERSE, TAILQ_FOREACH_SAFE, TAILQ_FOREACH_REVERSE_SAFE, TAILQ_FOREACH_FROM, TAILQ_FOREACH_REVERSE_FROM, TAILQ_FOREACH_FROM_SAFE, TAILQ_FOREACH_REVERSE_FROM_SAFE, TAILQ_HEAD_INITIALIZER, TAILQ_CONCAT, TAILQ_SWAP, TAILQ_CLASS_ENTRY et TAILQ_CLASS_HEAD sont utilisées pour manipuler des files à queue doublement chaînées.

Dans les exemples ci-dessous, TYPE est le type de la structure de données contenant l'entrée de la liste. NOM_ENTREE est le nom du champ d'entrée de la liste au sein de la structure TYPE. NOM_QUEUE est le nom de la structure de file/liste.

Par exemple, pour une liste d'entiers simples, vous pourriez avoir quelque chose comme suit :

struct IntListItem {
    int value;
    SLIST_ENTRY(IntListItem) pointers;
};
SLIST_HEAD(IntListHead, IntListItem);

Les macros SLIST_CLASS_ENTRY et SLIST_CLASS_HEAD (et leurs équivalents pour STAILQ, LIST et TAILQ) permettent de définir des structures de liste et d'entrée qui dépendent d'un type de classe spécifié.

Les macros SLIST_CONCAT, LIST_CONCAT et TAILQ_CONCAT peuvent être utilisées pour concaténer deux listes. Pour SLIST_CONCAT, le nom du champ d'entrée doit être spécifié.

Les macros SLIST_SWAP, LIST_SWAP et TAILQ_SWAP échangent le contenu de deux listes.

Les macros SLIST_FOREACH_SAFE et SLIST_FOREACH_FROM_SAFE (et leurs équivalents pour STAILQ, LIST et TAILQ) sont destinées à être utilisées dans les boucles où des éléments peuvent être supprimés de la liste.

Les macros TAILQ_FOREACH_REVERSE et TAILQ_FOREACH_REVERSE_FROM (et leurs variantes _SAFE) permettent de parcourir une file à queue doublement chaînée en sens inverse.

EXEMPLES

Créer et initialiser une liste chaînée simple de chaînes :

#include <stdio.h>
#include <stdlib.h>
#include <string.h>
#include <sys/queue.h>

struct Node {
    char *string;
    SLIST_ENTRY(Node) next;
};

SLIST_HEAD(ListHead, Node);

int main() {
    struct ListHead head;
    SLIST_INIT(&head);

    struct Node *node1 = malloc(sizeof(struct Node));
    node1->string = "hello";
    SLIST_INSERT_HEAD(&head, node1, next);

    struct Node *node2 = malloc(sizeof(struct Node));
    node2->string = "world";
    SLIST_INSERT_HEAD(&head, node2, next);

    struct Node *current;
    SLIST_FOREACH(current, &head, next) {
        printf("%s ", current->string);
    }
    printf("\n");

    while (!SLIST_EMPTY(&head)) {
        struct Node *node = SLIST_FIRST(&head);
        SLIST_REMOVE_HEAD(&head, next);
        free(node);
    }

    return 0;
}

Créer et initialiser une file à queue chaînée simple d'entiers :

#include <stdio.h>
#include <stdlib.h>
#include <sys/queue.h>

struct IntNode {
    int value;
    STAILQ_ENTRY(IntNode) next;
};

STAILQ_HEAD(IntQueueHead, IntNode);

int main() {
    struct IntQueueHead head;
    STAILQ_INIT(&head);

    struct IntNode *node1 = malloc(sizeof(struct IntNode));
    node1->value = 10;
    STAILQ_INSERT_TAIL(&head, node1, next);

    struct IntNode *node2 = malloc(sizeof(struct IntNode));
    node2->value = 20;
    STAILQ_INSERT_TAIL(&head, node2, next);

    struct IntNode *current;
    STAILQ_FOREACH(current, &head, next) {
        printf("%d ", current->value);
    }
    printf("\n");

    while (!STAILQ_EMPTY(&head)) {
        struct IntNode *node = STAILQ_FIRST(&head);
        STAILQ_REMOVE_HEAD(&head, next);
        free(node);
    }

    return 0;
}

TAILQ_HEAD

Ces macros définissent et opèrent sur quatre types de structures de données pouvant être utilisés en C et C++ :

  1. Liste
  2. Liste doublement chaînée
  3. File d'attente à liste doublement chaînée
  4. File d'attente de liste
Les quatre structures prennent en charge la fonctionnalité suivante :
  1. Insertion d'un nouvel élément au début de la liste.
  2. Insertion d'un nouvel élément après n'importe quel élément de la liste.
  3. Suppression d'un élément au début de la liste en O(1).
  4. Parcours avant de la liste.
  5. Échange des contenus de deux listes.
Les listes doublement chaînées sont les plus simples des quatre structures et ne prennent en charge que la fonctionnalité mentionnée ci-dessus. Les listes doublement chaînées sont idéales pour les applications avec de grandes quantités de données et peu ou pas de suppressions, ou pour implémenter une pile (LIFO). Les listes doublement chaînées ajoutent la fonctionnalité suivante :
  1. Suppression de n'importe quel élément de la liste en O(n).
  2. Connexion de deux listes en O(n).
Les files d'attente à liste doublement chaînée ajoutent la fonctionnalité suivante :
  1. Il est possible d'ajouter des éléments à la fin d'une liste.
  2. Suppression de n'importe quel élément de la liste en O(n).
  3. Elles peuvent être concaténées.
Cependant :
  1. Toutes les insertions dans une liste doivent spécifier l'en-tête de la liste.
  2. Chaque en-tête de liste nécessite deux pointeurs au lieu d'un.
  3. La taille du code est environ 15 % plus grande et les opérations s'exécutent environ 20 % plus lentement que les listes doublement chaînées.
Les files d'attente à liste doublement chaînée sont idéales pour les applications avec de grandes quantités de données et peu ou pas de suppressions, ou pour implémenter une file d'attente d'entrée-sortie (FIFO). De plus, les structures doublement chaînées (listes et files d'attente) ajoutent la fonctionnalité suivante :
  1. Connexion de deux listes en O(n).
  2. Elles peuvent être parcourues en sens inverse.
Cependant :
  1. Pour parcourir en sens inverse, l'élément de départ du chemin et la liste dans laquelle il se trouve doivent être spécifiés.
Les files d'attente ajoutent la fonctionnalité suivante :
  1. Il est possible d'ajouter des éléments à la fin d'une liste.
  2. Elles peuvent être parcourues en sens inverse, de la fin vers le début.
  3. Elles peuvent être concaténées.
Cependant :
  1. Toutes les insertions et suppressions dans une liste doivent spécifier l'en-tête de la liste.
  2. Chaque en-tête de liste nécessite deux pointeurs au lieu d'un.
  3. La taille du code est environ 15 % plus grande et les opérations s'exécutent environ 20 % plus lentement que les listes doublement chaînées.
Dans les définitions de macros, TYPE est le nom d'une structure définie par l'utilisateur. La structure doit contenir un champ nommé NAME de type SLIST_ENTRY, STAILQ_ENTRY, LIST_ENTRY ou TAILQ_ENTRY. Dans les définitions de macros, CLASSTYPE est le nom d'une classe définie par l'utilisateur. La classe doit contenir un champ nommé NAME de type SLIST_CLASS_ENTRY, STAILQ_CLASS_ENTRY, LIST_CLASS_ENTRY ou TAILQ_CLASS_ENTRY. L'argument HEADNAME est le nom d'une structure définie par l'utilisateur qui doit être déclarée à l'aide des macros SLIST_HEAD, SLIST_CLASS_HEAD, STAILQ_HEAD, STAILQ_CLASS_HEAD, LIST_HEAD, LIST_CLASS_HEAD, TAILQ_HEAD ou TAILQ_CLASS_HEAD. Voir les exemples ci-dessous pour une explication plus détaillée de la façon dont ces macros sont utilisées.

LISTES SIMPLEMENT CHAÎNÉES

Une liste simplement chaînée est précédée d'une structure définie par la macro SLIST_HEAD. Cette structure contient un seul pointeur vers le premier élément de la liste. Les éléments sont chaînés simplement pour minimiser l'espace et la surcharge de manipulation des pointeurs, même si le temps de suppression des éléments arbitraires est O(n). De nouveaux éléments peuvent être ajoutés à la liste après un élément existant ou au début de la liste. Une structure SLIST_HEAD est déclarée comme suit :

SLIST_HEAD(HEADNAME, TYPE) head;

où HEADNAME est le nom de la structure à définir et TYPE est le type des éléments qui sont chaînés dans la liste. Un pointeur vers l'en-tête de la liste peut ensuite être déclaré comme suit :

struct HEADNAME *headp;

(Les noms head et headp sont sélectionnables par l'utilisateur.)

La macro SLIST_HEAD_INITIALIZER est évaluée à un initialiseur pour la liste head.

La macro SLIST_CONCAT concaténera la liste précédée par head2 à la fin de la liste précédée par head1, supprimant tous les éléments de la première. L'utilisation de cette macro doit être évitée car elle parcourt entièrement la liste head1. Une file d'attente à liste simplement chaînée doit être utilisée si nécessaire dans des chemins de code fréquemment utilisés ou pour opérer sur de longues listes.

La macro SLIST_EMPTY est évaluée à vrai s'il n'y a aucun élément dans la liste.

La macro SLIST_ENTRY déclare une structure qui relie les éléments de la liste.

La macro SLIST_FIRST renvoie le premier élément de la liste ou NULL si la liste est vide.

La macro SLIST_FOREACH parcourt la liste référencée par head dans le sens avant, assignant chaque élément dans l'ordre à var.

La macro SLIST_FOREACH_FROM se comporte de manière identique à SLIST_FOREACH lorsque var est NULL, auquel cas elle traite var comme un élément précédemment trouvé dans une liste SLIST et commence la boucle à partir de var au lieu du premier élément de la liste référencée par head.

La macro SLIST_FOREACH_SAFE parcourt la liste référencée par head dans le sens avant, assignant chaque élément dans l'ordre à var. Cependant, contrairement à SLIST_FOREACH(), il est permis de supprimer var ainsi que de la libérer dans la boucle en toute sécurité sans interférer avec le parcours.

La macro SLIST_FOREACH_FROM_SAFE se comporte de manière identique à SLIST_FOREACH_SAFE lorsque var est NULL, auquel cas elle traite var comme un élément précédemment trouvé dans une liste SLIST et commence la boucle à partir de var au lieu du premier élément de la liste référencée par head.

La macro SLIST_INIT initialise la liste référencée par head.

La macro SLIST_INSERT_HEAD insère le nouvel élément elm au début de la liste.

La macro SLIST_INSERT_AFTER insère le nouvel élément elm après l'élément

listelm.

La macro SLIST_NEXT retourne l'élément suivant dans la liste.

La macro SLIST_REMOVE_AFTER supprime l'élément suivant elm de la liste. Contrairement à SLIST_REMOVE, cette macro ne parcourt pas toute la liste.

La macro SLIST_REMOVE_HEAD supprime l'élément elm du début de la liste. Pour une efficacité optimale, les éléments à supprimer du début de la liste doivent explicitement utiliser cette macro plutôt que la macro générique SLIST_REMOVE.

La macro SLIST_REMOVE supprime l'élément elm de la liste. Son utilisation doit être évitée car elle parcourt toute la liste. Une liste doublement chaînée doit être utilisée si nécessaire dans des chemins de code à forte utilisation ou pour opérer sur de longues listes.

La macro SLIST_SWAP échange le contenu de head1 et head2.

EXEMPLE DE LISTE SIMPLEMENT CHAÎNÉE

SLIST_HEAD(slisthead, entry) head =
    SLIST_HEAD_INITIALIZER(head);
struct slisthead *headp;		/* Tête de liste simplement chaînée. */
struct entry {
	...
	SLIST_ENTRY(entry) entries;	/* Liste simplement chaînée. */
	...
} *n1, *n2, *n3, *np;

SLIST_INIT(&head);			/* Initialiser la liste. */

n1 = malloc(sizeof(struct entry));	/* Insérer en tête. */
SLIST_INSERT_HEAD(&head, n1, entries);

n2 = malloc(sizeof(struct entry));	/* Insérer après. */
SLIST_INSERT_AFTER(n1, n2, entries);

SLIST_REMOVE(&head, n2, entry, entries);/* Suppression. */
free(n2);

n3 = SLIST_FIRST(&head);
SLIST_REMOVE_HEAD(&head, entries);	/* Suppression de la tête. */
free(n3);
					/* Parcours avant. */
SLIST_FOREACH(np, &head, entries)
	np-> ...
					/* Parcours avant sécurisé. */
SLIST_FOREACH_SAFE(np, &head, entries, np_temp) {
	np->do_stuff();
	...
	SLIST_REMOVE(&head, np, entry, entries);
	free(np);
}

while (!SLIST_EMPTY(&head)) {		/* Suppression de la liste. */
	n1 = SLIST_FIRST(&head);
	SLIST_REMOVE_HEAD(&head, entries);
	free(n1);
}

FILES D'ATTENTE SIMPLEMENT CHAÎNÉES AVEC TAMPON

Une file d'attente simplement chaînée avec tampon est dirigée par une structure définie à l'aide de la macro STAILQ_HEAD. Cette structure contient une paire de pointeurs, l'un vers le premier élément de la file d'attente et l'autre vers le dernier élément. Les éléments sont chaînés de manière unique, ce qui implique un surcoût minimal en espace et en manipulation de pointeurs, en échange d'un surcoût O(n) lors de la suppression d'éléments arbitraires. De nouveaux éléments peuvent être ajoutés à la file d'attente après un élément existant, au début de la file d'attente, ou à la fin de la file d'attente. Une structure STAILQ_HEAD est déclarée ainsi :

STAILQ_HEAD(HEADNAME, TYPE) head;

où HEADNAME est le nom de la structure à définir et TYPE est le type des éléments chaînés dans la file d'attente. Un pointeur vers la tête de la file d'attente peut être déclaré plus tard ainsi :

struct HEADNAME *headp;

(Les noms head et headp sont sélectionnables par l'utilisateur.)

La macro STAILQ_HEAD_INITIALIZER évalue à un initialiseur pour la file d'attente head.

La macro STAILQ_CONCAT concatène la file d'attente dirigée par head2 à la file d'attente dirigée par head1, supprimant tous les éléments de la première.

La macro STAILQ_EMPTY évalue à vrai si la file d'attente ne contient aucun élément.

La macro STAILQ_ENTRY déclare une structure qui relie les éléments de la file d'attente.

La macro STAILQ_FIRST retourne le premier élément de la file d'attente ou NULL si la file d'attente est vide.

La macro STAILQ_FOREACH parcourt la file d'attente dirigée par head dans le sens avant, assignant chaque élément à var.

La macro STAILQ_FOREACH_FROM se comporte de manière identique à STAILQ_FOREACH lorsque var est NULL, sinon elle traite var comme un élément déjà trouvé dans la file d'attente et commence la boucle à partir de var au lieu du premier élément de la file d'attente dirigée par head.

La macro STAILQ_FOREACH_SAFE parcourt la file d'attente dirigée par head dans le sens avant, assignant chaque élément à var. Cependant, contrairement à STAILQ_FOREACH(), il est ici permis de supprimer var et de le libérer à l'intérieur de la boucle en toute sécurité sans interférer avec le parcours.

La macro STAILQ_FOREACH_FROM_SAFE se comporte de manière identique à STAILQ_FOREACH_SAFE lorsque var est NULL, sinon elle traite var comme un élément déjà trouvé dans la file d'attente et commence la boucle à partir de var au lieu du premier élément de la file d'attente dirigée par head.

La macro STAILQ_INIT initialise la file d'attente dirigée par head.

La macro STAILQ_INSERT_HEAD insère le nouvel élément elm au début de la file d'attente.

La macro STAILQ_INSERT_TAIL insère le nouvel élément elm à la fin de la file d'attente.

La macro STAILQ_INSERT_AFTER insère le nouvel élément elm après l'élément listelm.

La macro STAILQ_LAST retourne le dernier élément de la file d'attente. Si la file d'attente est vide, la valeur retournée est NULL.

La macro STAILQ_NEXT retourne l'élément suivant dans la file d'attente, ou NULL s'il s'agit du dernier.

La macro STAILQ_REMOVE_AFTER supprime l'élément suivant elm de la file d'attente. Bien qu'elle ne parcourt pas toute la file d'attente, cette macro est différente de STAILQ_REMOVE.

La macro STAILQ_REMOVE_HEAD supprime l'élément au début de la file d'attente. Pour une efficacité optimale, les éléments à supprimer du début de la file d'attente doivent explicitement utiliser cette macro plutôt que la macro générique STAILQ_REMOVE.

La macro STAILQ_REMOVE supprime l'élément elm de la file d'attente. Son utilisation doit être évitée car elle parcourt toute la liste. Une liste double doit être utilisée si nécessaire dans des chemins de code à forte utilisation ou pour opérer sur de longues listes.

La macro STAILQ_SWAP échange le contenu de head1 et head2.

Une liste est dirigée par une structure définie à l'aide de la macro LIST_HEAD. Cette structure contient un seul pointeur vers le premier élément de la liste. Les éléments sont doublement chaînés, ce qui permet de supprimer n'importe quel élément sans parcourir toute la liste. De nouveaux éléments peuvent être ajoutés à la liste après un élément existant, avant un élément existant, ou au début de la liste. Une structure LIST_HEAD est déclarée ainsi :

LIST_HEAD(HEADNAME, TYPE) head;

où HEADNAME est le nom de la structure à définir et TYPE est le type des éléments chaînés dans la liste. Un pointeur vers la tête de la liste peut être déclaré plus tard ainsi :

struct HEADNAME *headp;

(Les noms head et headp sont sélectionnables par l'utilisateur.)

La macro LIST_HEAD_INITIALIZER évalue à un initialiseur pour la liste head.

La macro LIST_CONCAT concatène la liste dirigée par head2 à la fin de la liste dirigée par head1, supprimant tous les éléments de la première. LISTS

A list is headed by a structure defined by the LIST_HEAD macro. This structure contains a pointer to the first element in the list. The elements are singly linked so that an arbitrary element can be removed without traversing the list. New elements can be added to the list after an existing element, or at the head of the list. A LIST_HEAD structure is declared as follows:

LIST_HEAD(HEADNAME, TYPE) head;

where HEADNAME is the name of the structure to be defined, and TYPE is the type of the elements to be linked into the list. A pointer to the head of the list can later be declared as:

struct HEADNAME *headp;

(The names head and headp are user selectable.)

The macro LIST_HEAD_INITIALIZER evaluates to an initializer for the list head.

The macro LIST_CONCAT concatenates the list headed by head2 onto the end of the one headed by head1 removing all entries from the former.

The macro LIST_EMPTY evaluates to true if there are no items on the list.

The macro LIST_ENTRY declares a structure that connects the elements in the list.

The macro LIST_FIRST returns the first item on the list or NULL if the list is empty.

The macro LIST_FOREACH traverses the list referenced by head in the forward direction, assigning each element in turn to var.

The macro LIST_FOREACH_FROM behaves identically to LIST_FOREACH when var is NULL, else it treats var as a previously found LIST element and begins the loop at var instead of the first element in the LIST referenced by head.

The macro LIST_FOREACH_SAFE traverses the list referenced by head in the forward direction, assigning each element in turn to var. However, unlike LIST_FOREACH() here it is permitted to both remove var as well as free it from within the loop safely without interfering with the traversal.

The macro LIST_FOREACH_FROM_SAFE behaves identically to LIST_FOREACH_SAFE when var is NULL, else it treats var as a previously found LIST element and begins the loop at var instead of the first element in the LIST referenced by head.

The macro LIST_INIT initializes the list referenced by head.

The macro LIST_INSERT_HEAD inserts the new element elm at the head of the list.

The macro LIST_INSERT_AFTER inserts the new element elm after the element listelm.

The macro LIST_INSERT_BEFORE inserts the new element elm before the element listelm.

The macro LIST_NEXT returns the next element in the list, or NULL if this is the last.

The macro LIST_PREV returns the previous element in the list, or NULL if this is the first. List head must contain element elm.

The macro LIST_REMOVE removes the element elm from the list.

The macro LIST_SWAP swaps the contents of head1 and head2.

TAIL QUEUES

A tail queue is headed by a structure defined by the TAILQ_HEAD macro. This structure contains a pair of pointers, one to the first element in the tail queue and the other to the last element in the tail queue. The elements are doubly linked so that an arbitrary element can be removed without traversing the tail queue. New elements can be added to the tail queue after an existing element, before an existing element, at the head of the tail queue, or at the end of the tail queue. A TAILQ_HEAD structure is declared as follows:

TAILQ_HEAD(HEADNAME, TYPE) head;

where HEADNAME is the name of the structure to be defined, and TYPE is the type of the elements to be linked into the tail queue. A pointer to the head of the tail queue can later be declared as:

struct HEADNAME *headp;

(The names head and headp are user selectable.)

The macro TAILQ_HEAD_INITIALIZER evaluates to an initializer for the tail queue head.

The macro TAILQ_CONCAT concatenates the tail queue headed by head2 onto the end of the one headed by head1 removing all entries from the former.

The macro TAILQ_EMPTY evaluates to true if there are no items on the tail queue.

The macro TAILQ_ENTRY declares a structure that connects the elements in the tail queue.

The macro TAILQ_FIRST returns the first item on the tail queue or NULL if the tail queue is empty.

The macro TAILQ_FOREACH traverses the tail queue referenced by head in the forward direction, assigning each element in turn to var. var is set to NULL if the loop completes normally, or if there were no elements.

The macro TAILQ_FOREACH_FROM behaves identically to TAILQ_FOREACH when var is NULL, else it treats var as a previously found TAILQ element and begins the loop at var instead of the first element in the TAILQ referenced by head.

The macro TAILQ_FOREACH_REVERSE traverses the tail queue referenced by head in the reverse direction, assigning each element in turn to var.

The macro TAILQ_FOREACH_REVERSE_FROM behaves identically to TAILQ_FOREACH_REVERSE when var is NULL, else it treats var as a previously found TAILQ element and begins the reverse loop at var instead of the last element in the TAILQ referenced by head.

The macros TAILQ_FOREACH_SAFE and TAILQ_FOREACH_REVERSE_SAFE traverse the list referenced by head in the forward or reverse direction respectively, assigning each element in turn to var. However, unlike their unsafe counterparts, TAILQ_FOREACH and TAILQ_FOREACH_REVERSE make it possible to both remove var as well as free it from within the loop safely without interfering with the traversal.

The macro TAILQ_FOREACH_FROM_SAFE behaves identically to TAILQ_FOREACH_SAFE when var is NULL, else it treats var as a previously found TAILQ element and begins the loop at var instead of the first element in the TAILQ referenced by head.

The macro TAILQ_FOREACH_REVERSE_FROM_SAFE behaves identically to TAILQ_FOREACH_REVERSE_SAFE when var is NULL, else it treats var as a previously found TAILQ element and begins the reverse loop at var instead of the last element in the TAILQ referenced by head.

The macro TAILQ_INIT initializes the tail queue referenced by head.

The macro TAILQ_INSERT_HEAD inserts the new element elm at the head of the tail queue.

The macro TAILQ_INSERT_TAIL inserts the new element elm at the end of the tail queue.

The macro TAILQ_INSERT_AFTER inserts the new element elm after the element listelm.

The macro TAILQ_INSERT_BEFORE inserts the new element elm before the element listelm.

The macro TAILQ_LAST returns the last item on the tail queue. If the tail queue is empty the return value is NULL.

The macro TAILQ_NEXT returns the next item on the tail queue, or NULL if this item is the last.

The macro TAILQ_PREV returns the previous item on the tail queue, or NULL if this item is the first.

The macro TAILQ_REMOVE removes the element elm from the tail queue.

The macro TAILQ_SWAP swaps the contents of head1 and head2.

Lors du débogage de queue(3), il peut être utile de suivre les modifications de la file d'attente. Pour activer le suivi, définissez la macro QUEUE_MACRO_DEBUG_TRACE lors de la compilation.

La macro QMD_IS_TRASHED(void *ptr) renvoie vrai si ptr a été mis en "poubelle" par l'option QUEUE_MACRO_DEBUG_TRASH.
