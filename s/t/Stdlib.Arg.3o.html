type spec =
| Unit of (unit -> unit)
(* Appel de la fonction avec argument unit
*)
| Bool of (bool -> unit)
(* Appel de la fonction avec argument bool
*)
| Set of bool ref
(* Mise à true de la référence
*)
| Clear of bool ref
(* Mise à false de la référence
*)
| String of (string -> unit)
(* Appel de la fonction avec argument string
*)
| Set_string of string ref
(* Mise à la référence de la chaîne de caractères fournie en argument
*)
| Int of (int -> unit)
(* Appel de la fonction avec argument int
*)
| Set_int of int ref
(* Mise à l'entier fourni en argument de la référence
*)
| Float of (float -> unit)
(* Appel de la fonction avec argument float
*)
| Set_float of float ref
(* Mise à la valeur float fournie en argument de la référence
*)
| Tuple of spec list
(* Prend plusieurs arguments selon la liste de spécifications
*)
| Symbol of string list * (string -> unit)
(* Prend un des symboles fournis en argument et appelle la fonction avec ce symbole
*)
| Rest of (string -> unit)
(* Arrête l'interprétation des mots-clés et appelle la fonction avec chaque argument restant
*)
| Rest_all of (string list -> unit)
(* Arrête l'interprétation des mots-clés et appelle la fonction avec tous les arguments restants
*)
| Expand of (string -> string array)
(* Si les arguments restants à traiter sont de la forme ["-foo"; "arg"] @ rest où "foo" est enregistré en tant que Expand f , alors les arguments f "arg" @ rest sont traités. Uniquement autorisé dans parse_and_expand_argv_dynamic .
*)

Le type concret qui décrit le comportement associé à un mot-clé.

type key = string

type doc = string

type usage_msg = string

type anon_fun = string -> unit

parse : (key * spec * doc) list -> anon_fun -> usage_msg -> unit

Arg.parse speclist anon_fun usage_msg analyse la ligne de commande. speclist est une liste de triplets (key, spec, doc) . key est le mot-clé de l'option, il doit commencer par un caractère '-'. spec décrit le type de l'option et la fonction à appeler lorsque cette option est rencontrée sur la ligne de commande. doc est une description sur une seule ligne de cette option. anon_fun est appelée pour les arguments anonymes. Les fonctions dans spec et anon_fun sont appelées dans le même ordre que leurs arguments apparaissent sur la ligne de commande.

En cas d'erreur, Arg.parse quitte le programme, après avoir imprimé sur stderr un message d'erreur tel que :

- La cause de l'erreur : option inconnue, argument invalide ou manquant, etc.

- usage_msg

- La liste des options, suivie de la chaîne doc correspondante. Attention : les options avec une chaîne doc vide ne seront pas incluses dans la liste.

Pour permettre à l'utilisateur de spécifier des arguments anonymes commençant par un - , incluez par exemple ("-", String anon_fun, doc) dans speclist .

Par défaut, parse reconnaît deux options unaires, -help et --help , qui imprimeront sur stdout usage_msg et la liste des options, puis quitteront le programme. Vous pouvez outrepasser ce comportement en spécifiant vos propres -help et --help dans speclist .

val parse_dynamic : (key * spec * doc) list ref -> anon_fun -> usage_msg -> unit

Identique à Arg.parse , à la différence près que speclist est une référence et peut être mis à jour pendant l'analyse. Un usage typique de cette fonctionnalité est l'analyse de lignes de commande de la forme :

- sous-commande options où la liste des options dépend de la valeur de l'argument de sous-commande.

Since 4.01

val parse_argv : ?current:int ref -> string array -> (key * spec * doc) list -> anon_fun -> usage_msg -> unit

Arg.parse_argv ~current args speclist anon_fun usage_msg analyse le tableau args comme s'il s'agissait de la ligne de commande. Il utilise et met à jour la valeur de ~current (si elle est fournie), ou Arg.current . Vous devez la définir avant d'appeler parse_argv . La valeur initiale de current est l'indice du programme (argument 0) dans le tableau. En cas d'erreur, Arg.parse_argv lève Arg.Bad avec le message d'erreur comme argument. Si -help ou --help est passé, Arg.parse_argv lève Arg.Help avec le message d'aide comme argument.

val parse_argv_dynamic : ?current:int ref -> string array -> (key * spec * doc) list ref -> anon_fun -> string -> unit

Identique à Arg.parse_argv , à la différence près que speclist est une référence et peut être mis à jour pendant l'analyse. Voir Arg.parse_dynamic .

Since 4.01

val parse_and_expand_argv_dynamic : int ref -> string array ref -> (key * spec * doc) list ref -> anon_fun -> string -> unit

Identique à Arg.parse_argv_dynamic , à la différence près que argv est une référence et peut être mis à jour pendant l'analyse des arguments Expand. Voir Arg.parse_argv_dynamic .

Since 4.05

val parse_expand : (key * spec * doc) list -> anon_fun -> usage_msg -> unit

Identique à Arg.parse , à la différence près que les arguments Expand sont autorisés et que la référence Arg.current n'est pas mise à jour.

Since 4.05

exception Help of string

Lancée par Arg.parse_argv lorsque l'utilisateur demande de l'aide.

exception Bad of string

Les fonctions dans spec ou anon_fun peuvent lancer Arg.Bad avec un message d'erreur pour rejeter des arguments invalides. Arg.Bad sera également lancé par Arg.parse_argv en cas d'erreur.

val usage : (key * spec * doc) list -> usage_msg -> unit

Arg.usage speclist usage_msg imprime sur stderr un message d'erreur incluant la liste des options valides. C'est le même message que celui imprimé par Arg.parse en cas d'erreur. speclist et usage_msg sont les mêmes que dans Arg.parse .

val usage_string : (key * spec * doc) list -> usage_msg -> string

Retourne le message qui serait imprimé par Arg.usage si les mêmes paramètres lui étaient fournis.

val align : ?limit:int -> (key * spec * doc) list -> (key * spec * doc) list

Align la documentation des chaînes en insérant des espaces au premier séparateur d'alignement (tab ou, si absent, espace), en fonction de la longueur du mot-clé. Utilisez un séparateur d'alignement comme premier caractère d'une chaîne de documentation si vous souhaitez aligner la chaîne entière. Les chaînes de documentation correspondant aux arguments Symbol sont alignées sur la ligne suivante.

val current : int ref

Position (dans Sys.argv ) de l'argument en cours de traitement. Vous pouvez changer cette valeur, par exemple pour forcer Arg.parse à sauter certains arguments. Arg.parse utilise la valeur initiale de Arg.current comme indice de l'argument 0 (le nom du programme) et commence à analyser les arguments à partir de l'élément suivant.

val read_arg : string -> string array

Arg.read_arg file lit de nouveaux arguments de ligne de commande depuis le fichier file .

Since 4.05

val read_arg0 : string -> string array

Identique à Arg.read_arg mais suppose que les arguments de ligne de commande sont terminés par un caractère nul.

Since 4.05

NOM

Arg est un module qui fournit des fonctions pour gérer les arguments de la ligne de commande.

Arg.write_arg fichier args écrit les arguments args terminés par une nouvelle ligne dans le fichier fichier. Si l'un des arguments dans args contient une nouvelle ligne, utilisez plutôt Arg.write_arg0.

Depuis 4.05

val write_arg0 : string -> string array -> unit

Identique à Arg.write_arg mais utilise le caractère nul comme terminateur au lieu d'une nouvelle ligne.
