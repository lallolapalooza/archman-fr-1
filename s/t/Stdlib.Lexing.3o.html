Positions

type position = {
pos_fname : string ;
pos_lnum : int ;
pos_bol : int ;
pos_cnum : int ;
}

Une valeur de type position décrit un point dans un fichier source. pos_fname est le nom du fichier ; pos_lnum est le numéro de ligne ; pos_bol est la position de début de ligne (nombre de caractères entre le début du lexbuf et le début de la ligne) ; pos_cnum est la position (nombre de caractères entre le début du lexbuf et la position). La différence entre pos_cnum et pos_bol est le décalage de caractère dans la ligne (c'est-à-dire le numéro de colonne, en supposant que chaque caractère est large d'une colonne).

Voir la documentation du type lexbuf pour des informations sur la manière dont le moteur de lexing gérera les positions.

val dummy_pos : position

Une valeur de type position, garantie d'être différente de toute position valide.

Tampons de lexers

type lexbuf = {
refill_buff : lexbuf -> unit ;
mutable lex_buffer : bytes ;
mutable lex_buffer_len : int ;
mutable lex_abs_pos : int ;
mutable lex_start_pos : int ;
mutable lex_curr_pos : int ;
mutable lex_last_pos : int ;
mutable lex_last_action : int ;
mutable lex_eof_reached : bool ;
mutable lex_mem : int array ;
mutable lex_start_p : position ;
mutable lex_curr_p : position ;
}

Le type des tampons de lexers. Un tampon de lexer est l'argument passé aux fonctions de scanning définies par les générateurs de scanners. Le tampon de lexer contient l'état actuel du scanner, plus une fonction pour recharger le tampon depuis l'entrée.

Les lexers peuvent optionnellement maintenir les champs lex_curr_p et lex_start_p. Ce mode « de suivi de position » est le mode par défaut, et correspond à passer ~with_position:true aux fonctions qui créent des tampons de lexer. Dans ce mode, le moteur de lexing et les actions de lexer sont responsables de la mise à jour correcte des champs de position, comme décrit dans le paragraphe suivant. Lorsque le mode est explicitement désactivé (avec ~with_position:false), le moteur de lexing ne touchera pas les champs de position et les actions de lexer doivent faire attention à ne pas le faire non plus ; les champs lex_curr_p et lex_start_p contiendront alors toujours dummy_pos (position invalide).

Le mode de positionnement fonctionne ainsi. À chaque occurrence d'un token, le moteur de lexing copiera lex_curr_p dans lex_start_p, puis modifiera le champ pos_cnum de lex_curr_p en mettant à jour sa valeur avec le nombre de caractères lus depuis le début du lexbuf. Les autres champs sont laissés inchangés par le moteur de lexing. Pour les maintenir corrects, ils doivent être initialisés avant la première utilisation du lexbuf, et mis à jour par les actions pertinentes du lexer (c'est-à-dire lors d'un saut de ligne — voir également new_line).

val from_channel : ?with_positions:bool -> in_channel -> lexbuf

Crée un tampon de lexer sur le canal d'entrée donné. Lexing.from_channel inchan renvoie un tampon de lexer qui lit à partir du canal d'entrée inchan, à la position courante.

val from_string : ?with_positions:bool -> string -> lexbuf

Crée un tampon de lexer qui lit à partir de la chaîne donnée. La lecture commence au premier caractère de la chaîne. Une condition de fin d'entrée est générée lorsque la fin de la chaîne est atteinte.

val from_function : ?with_positions:bool -> (bytes -> int -> int) -> lexbuf

Crée un tampon de lexer avec la méthode de lecture donnée. Lorsque le scanner a besoin de caractères supplémentaires, il appellera la méthode donnée, en lui passant une séquence d'octets s et un nombre d'octets n. La fonction doit placer n octets ou moins dans s, en commençant à l'index 0, et renvoyer le nombre d'octets fournis. Une valeur de retour de 0 signifie la fin de l'entrée.

val set_position : lexbuf -> position -> unit

Définit la position de lecture initiale suivie pour lexbuf à une valeur personnalisée. Ignore pos_fname. Voir Lexing.set_filename pour changer ce champ.

Depuis 4.11

val set_filename : lexbuf -> string -> unit

Définit le nom de fichier dans la position initiale suivie de lexbuf à file.

Depuis 4.11

val with_positions : lexbuf -> bool

Indique si le tampon de lexer suit les champs lex_curr_p / lex_start_p, selon l'argument optionnel correspondant pour les fonctions qui créent des tampons de lexer (dont la valeur par défaut est true).

Lorsque with_positions est false, les actions de lexer doivent éviter de modifier les champs de position. Le faire sans raison pourrait réactiver le mode with_position et dégrader les performances.

Fonctions pour les actions sémantiques du lexer

Les fonctions suivantes peuvent être appelées depuis les actions sémantiques des définitions de lexer (le code ML enfermé entre accolades qui calcule la valeur retournée par les fonctions de lexing). Ces fonctions donnent accès à la chaîne de caractères correspondant à l'expression régulière associée à l'action sémantique. Ces fonctions doivent s'appliquer à l'argument lexbuf, qui, dans le code généré par ocamllex, est associé au tampon de lexer passé à la fonction de parsing.

val lexeme : lexbuf -> string

Lexing.lexeme lexbuf renvoie la chaîne de caractères correspondant à l'expression régulière.

val lexeme_char : lexbuf -> int -> char

Lexing.lexeme_char lexbuf i renvoie le caractère numéro i dans la chaîne de caractères correspondante.

val lexeme_start : lexbuf -> int

Lexing.lexeme_start lexbuf renvoie la position de début de la chaîne de caractères correspondante dans le flux d'entrée. Le premier caractère du flux a la position 0.

val lexeme_end : lexbuf -> int

Lexing.lexeme_end lexbuf renvoie la position de début du caractère suivant la dernière caractère de la chaîne correspondante dans le flux d'entrée. Le premier caractère du flux a la position 0.

val lexeme_start_p : lexbuf -> position

Comme lexeme_start, mais renvoie une position complète au lieu d'une position de décalage. Lorsque le mode de suivi de position est désactivé, la fonction renvoie dummy_pos.

val lexeme_end_p : lexbuf -> position

Comme lexeme_end, mais renvoie une position complète au lieu d'une position de décalage. Lorsque le mode de suivi de position est désactivé, la fonction renvoie dummy_pos.

val new_line : lexbuf -> unit

Met à jour le champ lex_curr_p du tampon de lexer pour refléter le début d'une nouvelle ligne. Vous pouvez appeler cette fonction dans l'action sémantique de la règle qui correspond au caractère de fin de ligne. La fonction ne fait rien lorsque le mode de suivi de position est désactivé.

Depuis 3.11

Fonctions diverses

val flush_input : lexbuf -> unit

Supprime le contenu du tampon et réinitialise la position actuelle à 0. La prochaine utilisation du tampon de lexer déclenchera un rechargement.
