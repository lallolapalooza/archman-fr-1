Module Lazy
: (module Stdlib__Lazy)

type 'a t = 'a CamlinternalLazy.t

Une valeur de type 'a Lazy.t est un calcul différé, appelé une suspension, dont le résultat est de type 'a . La syntaxe d'expression spéciale lazy (expr) crée une suspension du calcul de expr , sans calculer expr immédiatement. Le fait de "forcer" la suspension calculera alors expr et retournera son résultat. Faire correspondre une suspension avec la syntaxe de motif spéciale lazy(motif) calcule également l'expression sous-jacente et tente de la lier au motif :

      let lazy_option_map f x =
      match x with
      | lazy (Some x) -> Some (Lazy.force f x)
      | _ -> None

Note : Si des motifs lazy apparaissent dans plusieurs cas d'une prise de motif, les expressions lazy peuvent être forcées même en dehors du cas finalement sélectionné par la prise de motif. Dans l'exemple ci-dessus, la suspension x est toujours calculée.

Note : lazy_t est le constructeur de type intégré utilisé par le compilateur pour le mot-clé lazy . Vous ne devriez pas l'utiliser directement. Utilisez toujours Lazy.t à la place.

Note : Lazy.force n'est pas sûr en concurrence. Si vous utilisez ce module avec plusieurs fibres, systhreads ou domaines, vous devrez ajouter des verrous. Le module garantit cependant la sécurité mémoire, et par conséquent, l'accès concurrent à ce module n'entraînera pas de plantage, mais le comportement n'est pas spécifié.

Note : si le programme est compilé avec l'option -rectypes , les définitions récursives mal fondées de la forme let rec x = lazy x ou let rec x = lazy(lazy(...(lazy x))) sont acceptées par le vérificateur de types et entraînent, lorsqu'elles sont forcées, des valeurs mal formées qui déclenchent des boucles infinies dans le récupérateur de mémoire et d'autres parties du système d'exécution. Sans l'option -rectypes , de telles définitions récursives mal fondées sont rejetées par le vérificateur de types.

exception Indefinie

Levée lors du forçage d'une suspension de manière concurrente à partir de plusieurs fibres, systhreads ou domaines, ou lorsque la suspension essaie de se forcer récursivement.

val forcer : 'a t -> 'a

forcer x force la suspension x et retourne son résultat. Si x a déjà été forcé, forcer x retourne la même valeur sans la recalculer. Si elle a levé une exception, la même exception est levée à nouveau.

Lève Indefinie (voir Lazy.Indefinie ).

Itérateurs

val map : ('a -> 'b) -> 'a t -> 'b t

map f x retourne une suspension qui, lorsqu'elle est forcée, force x et applique f à sa valeur.

C'est équivalent à lazy (f (forcer x)) .

Depuis 4.13

Raisonnement sur les suspensions déjà forcées

val est_valeur : 'a t -> bool

est_valeur x retourne true si x a déjà été forcé et n'a pas levé d'exception.

Depuis 4.00

val de_valeur : 'a -> 'a t

de_valeur v évalue v d'abord (comme le ferait n'importe quelle fonction) et retourne une suspension déjà forcée de son résultat. C'est la même chose que let x = v in lazy x , mais utilise des tests dynamiques pour optimiser la création de suspension dans certains cas.

Depuis 4.00

val map_valeur : ('a -> 'b) -> 'a t -> 'b t

map_valeur f x applique f directement si x est déjà forcé, sinon elle se comporte comme map f x .

Lorsque x est déjà forcé, ce comportement évite la construction d'une suspension, mais d'un autre côté, il effectue plus de travail de manière diligente qui peut ne pas être utile si vous ne forcez jamais le résultat de la fonction.

Si f lève une exception, elle sera levée immédiatement lors de est_valeur x , ou levée uniquement lors du forçage du thunk sinon.

Si map_valeur f x ne lève pas d'exception, alors est_valeur (map_valeur f x) est égal à est_valeur x .

Depuis 4.13

Avancé

Les définitions suivantes sont uniquement pour des usages avancés ; elles nécessitent une bonne compréhension du schéma de compilation lazy pour être utilisées de manière appropriée.

val de_fonction : (unit -> 'a) -> 'a t

de_fonction f est la même chose que lazy (f ()) mais légèrement plus efficace.

Elle ne devrait être utilisée que si la fonction f est déjà définie. En particulier, il est toujours moins efficace d'écrire de_fonction (fun () -> expr) que lazy expr .

Depuis 4.00

val forcer_valeur : 'a t -> 'a

forcer_valeur x force la suspension x et retourne son résultat. Si x a déjà été forcé, forcer_valeur x retourne la même valeur sans la recalculer.

Si le calcul de x lève une exception, il n'est pas spécifié si forcer_valeur x lève la même exception ou Lazy.Indefinie .

Lève Indefinie si le forçage de x tente de forcer x lui-même récursivement.

Lève Indefinie (voir Lazy.Indefinie ).
