Chaînes de caractères.

Une chaîne s de longueur n est une séquence indexable et non modifiable de n octets. Pour des raisons historiques, ces octets sont appelés caractères.

La signification des fonctions de chaîne est définie en termes d'indices et de positions. Celles-ci sont représentées et décrites comme suit.

positions 0 1 2 3 4 n-1 n +---+---+---+---+ +-----+ indices | 0 | 1 | 2 | 3 | ... | n-1 | +---+---+---+---+ +-----+

-Un indice i de s est un entier dans l'intervalle [ 0 ; n-1 ]. Il représente le i-ème octet (caractère) de s, auquel on peut accéder via l'opérateur d'indexation constant s.[i] .

-Une position i de s est un entier dans l'intervalle [ 0 ; n ]. Il représente la position au début de la chaîne, ou entre deux indices, ou à la fin de la chaîne. Le i-ème octet indexé se situe entre la position i et i+1 .

Deux entiers start et len sont considérés comme une sous-chaîne valide de s si len >= 0 et si start, start+len sont des positions de s .

Texte Unicode. Les chaînes sont des séquences arbitraires d'octets, et peuvent contenir tout type d'encodage textuel. Cependant, la recommandation pour stocker du texte Unicode dans des chaînes OCaml est UTF-8. C'est le code utilisé par les échappements Unicode dans les littéraux de chaînes. Par exemple, la chaîne "\u{1F42B}" est l'encodage UTF-8 du caractère Unicode U+1F42B.

Modifiabilité passée. Avant OCaml 4.02, les chaînes étaient modifiables au lieu d'être immuables, comme les séquences d'octets Bytes.t. Dans OCaml 4, plusieurs drapeaux de compilation et options de configuration ont été introduits pour supporter la période de transition des chaînes modifiables vers les chaînes immuables. Ces options ne sont plus disponibles, et les chaînes sont maintenant toujours immuables.

La version étiquetée de ce module peut être utilisée comme décrit dans le module StdLabels.

Chaînes

type t = string

Le type pour les chaînes de caractères.

val make : int -> char -> string

make n c est une chaîne de longueur n où chaque indice contient le caractère c .

Lève Invalid_argument si n < 0 ou n > Sys.max_string_length .

val init : int -> (int -> char) -> string

init n f est une chaîne de longueur n où l'indice i contient le caractère f i (appelé dans l'ordre croissant des indices).

Depuis 4.02

Lève Invalid_argument si n < 0 ou n > Sys.max_string_length .

val empty : string

La chaîne vide.

Depuis 4.13

val length : string -> int

length s est la longueur (nombre d'octets/caractères) de s .

val get : string -> int -> char

get s i est le caractère à l'indice i de s. Ceci est équivalent à écrire s.[i] .

Lève Invalid_argument si i n'est pas un indice valide de s .

val of_bytes : bytes -> string

Renvoie une nouvelle chaîne contenant les mêmes octets que la séquence d'octets donnée.

Depuis 4.13

val to_bytes : string -> bytes

Renvoie une nouvelle séquence d'octets contenant les mêmes octets que la chaîne donnée.

Depuis 4.13

val blit : string -> int -> bytes -> int -> int -> unit

Est équivalent à Bytes.blit_string, et il est recommandé d'utiliser ce dernier.

Concaténation

Note. L'opérateur binaire (^) concatène deux chaînes.

val concat : string -> string list -> string

concat sep ss concatène la liste de chaînes ss, en insérant le séparateur sep entre chaque élément.

Si le résultat est plus long que Sys.max_string_length octets, Invalid_argument est levée.

val cat : string -> string -> string

cat s1 s2 concatène s1 et s2 ( s1 ^ s2 ).

Depuis 4.13

Si le résultat est plus long que Sys.max_string_length octets, Invalid_argument est levée.

Prédicats et comparaisons

val equal : t -> t -> bool

equal s0 s1 est true si et seulement si s0 et s1 sont égales caractère par caractère.

Depuis 4.03 (4.05 dans StringLabels)

compare s0 s1 ordonne s0 et s1 par ordre lexicographique. compare se comporte comme compare sur les chaînes mais peut être plus efficace.

val starts_with : prefix:string -> string -> bool

starts_with ~prefix s est true si et seulement si s commence par prefix .

Depuis 4.13

val ends_with : suffix:string -> string -> bool

ends_with ~suffix s est true si et seulement si s se termine par suffix .

Depuis 4.13

val contains_from : string -> int -> char -> bool

contains_from s start c est true si et seulement si c apparaît dans s après la position start .

Lève Invalid_argument si start n'est pas une position valide de s .

val rcontains_from : string -> int -> char -> bool

rcontains_from s stop c est true si et seulement si c apparaît dans s avant la position stop+1 .

Lève Invalid_argument si stop < 0 ou si stop+1 n'est pas une position valide de s .

val contains : string -> char -> bool

contains s c est String.contains_from s 0 c .

Extraction de sous-chaînes

val sub : string -> int -> int -> string

sub s pos len est une chaîne de longueur len qui contient la sous-chaîne de s commençant à la position pos et de longueur len .

Lève Invalid_argument si pos et len ne désignent pas une sous-chaîne valide de s .

val split_on_char : char -> string -> string list

split_on_char sep s est la liste de toutes les sous-chaînes (possibles et vides) de s qui sont délimitées par le caractère sep. Si s est vide, le résultat est la liste [""] .

Le résultat de la fonction est spécifié par les invariants suivants:

-La liste n'est pas vide.

-La jointure de ses éléments avec sep comme séparateur redonne une chaîne égale à l'entrée ( concat (make 1 sep) ).

-Aucune des chaînes du résultat ne contient le caractère sep .

val trim : string -> string

trim s est s sans les espaces blancs de début et de fin. Les caractères d'espacement sont : ' ' , '\x0C' (saut de page), '\n' , '\r' et '\t' .

Depuis 4.00

val escaped : string -> string

escaped s est s avec les caractères spéciaux représentés par des séquences d'échappement, suivant les conventions lexicales d'OCaml.

Tous les caractères en dehors de la plage imprimable US-ASCII [0x20;0x7E] sont échappés, ainsi que la barre oblique inverse (0x2F) et le guillemet double (0x22).

La fonction Scanf.unescaped est une inverse gauche de escaped , c'est-à-dire que Scanf.unescaped (escaped s) = s pour toute chaîne s (à moins que escaped s n'échoue).

Lève Invalid_argument si le résultat est plus long que Sys.max_string_length octets.

val uppercase_ascii : string -> string

uppercase_ascii s est s avec toutes les lettres minuscules traduites en majuscules, en utilisant le jeu de caractères US-ASCII.

Parcours

val iter : (char -> unit) -> string -> unit

iter f s applique la fonction f tour à tour à tous les caractères de s . C'est équivalent à f s.[0]; f s.[1]; ...; f s.[length s - 1]; () .

val iteri : (int -> char -> unit) -> string -> unit

iteri est comme String.iter , mais la fonction reçoit également l'indice de caractère correspondant.

Correction orthographique

val edit_distance : ?limit:int -> t -> t -> int

edit_distance s0 s1 est le nombre d'éditions de caractères uniques (compris comme insertion, suppression, substitution, transposition) nécessaires pour transformer s0 en s1 .

Si limit est fourni, la fonction retourne avec limit dès qu'il est déterminé que s0 et s1 ont une distance d'au moins limit . C'est plus rapide si vous avez une limite fixe, par exemple pour la correction orthographique.

La fonction suppose que les chaînes sont encodées en UTF-8 et utilise Uchar.t pour la notion de caractère. Les erreurs de décodage sont remplacées par Uchar.rep . La normalisation des chaînes en NFC donne de meilleurs résultats.

Note. Ceci implémente la distance plus simple Optimal String Alignement (OSA), pas la distance Damerau-Levenshtein. Avec cette fonction, "ca" et "abc" ont une distance de 3 et non 2.

Depuis 5.4

val spellcheck : ?max_dist:(string -> int) -> ((string -> unit) -> unit) -> string -> string list

spellcheck iter_dict s sont les chaînes énumérées par l'itérateur iter_dict dont la String.edit_distance par rapport à s est la plus petite et au plus max_dist s . Si plusieurs corrections sont renvoyées, leur ordre est celui trouvé dans iter_dict . La valeur par défaut de max_dist s est :

- 0 si s a 0 à 2 caractères Unicode.

- 1 si s a 3 à 4 caractères Unicode.

- 2 sinon.

Si votre dictionnaire est une liste l , un iter_dict adapté est donné par (fun yield -> List.iter yield l) .

Toutes les chaînes sont supposées être encodées en UTF-8, les erreurs de décodage sont remplacées par des caractères Uchar.rep .

Depuis 5.4

Décodage binaire d'entiers

Les fonctions de cette section décodent des entiers en binaire à partir de chaînes.

Toutes les fonctions suivantes lèvent Invalid_argument si les caractères nécessaires à l'indice i pour décoder l'entier ne sont pas disponibles.

L'encodage little-endian (resp. big-endian) signifie que les octets les moins (resp. plus) significatifs sont stockés en premier. Big-endian est aussi connu sous le nom d'ordre des octets réseau. L'encodage native-endian est soit little-endian soit big-endian selon Sys.big_endian .

Les entiers 32 bits et 64 bits sont représentés par les types int32 et int64 , qui peuvent être interprétés comme des nombres signés ou non signés.

Les entiers 8 bits et 16 bits sont représentés par le type int , qui a plus de bits que l'encodage binaire. Ces bits supplémentaires sont étendus en signe (ou étendus avec des zéros) pour les fonctions qui décodent des entiers de 8 bits ou 16 bits et les représentent avec des valeurs int .
