Chaînes de caractères

type t = string

Le type pour les chaînes de caractères.

val make : int -> char -> string

make n c est une chaîne de longueur n où chaque indice contient le caractère c .

Lève Invalid_argument si n < 0 ou n > Sys.max_string_length .

val init : int -> (int -> char) -> string

init n f est une chaîne de longueur n où l'indice i contient le caractère f i (appelé dans l'ordre croissant des indices).

Depuis 4.02

Lève Invalid_argument si n < 0 ou n > Sys.max_string_length .

val empty : string

La chaîne vide.

Depuis 4.13

val length : string -> int

length s est la longueur (nombre d'octets/caractères) de s .

val get : string -> int -> char

get s i est le caractère à l'indice i dans s . Ceci est équivalent à écrire s.[i] .

Lève Invalid_argument si i n'est pas un indice de s .

val of_bytes : bytes -> string

Retourne une nouvelle chaîne contenant les mêmes octets que la séquence d'octets donnée.

Depuis 4.13

val to_bytes : string -> bytes

Retourne une nouvelle séquence d'octets contenant les mêmes octets que la chaîne donnée.

Depuis 4.13

val blit : string -> int -> bytes -> int -> int -> unit

Identique à Bytes.blit_string qui devrait être préférée.

Concaténation

Note. L'opérateur binaire (^) concatène deux chaînes.

val concat : string -> string list -> string

concat sep ss concatène la liste de chaînes ss en insérant la chaîne séparateur sep entre chacune.

Lève Invalid_argument si le résultat dépasse Sys.max_string_length octets.

val cat : string -> string -> string

cat s1 s2 concatène s1 et s2 ( s1 ^ s2 ).

Depuis 4.13

Lève Invalid_argument si le résultat dépasse Sys.max_string_length octets.

Prédicats et comparaisons

val equal : t -> t -> bool

equal s0 s1 est true si et seulement si s0 et s1 sont égales caractère par caractère.

val compare : t -> t -> int

compare s0 s1 trie s0 et s1 par ordre lexicographique. compare se comporte comme compare sur les chaînes mais peut être plus efficace.

val starts_with : prefix:string -> string -> bool

starts_with ~prefix s est true si et seulement si s commence par prefix .

Depuis 4.13

val ends_with : suffix:string -> string -> bool

ends_with ~suffix s est true si et seulement si s se termine par suffix .

Depuis 4.13

val contains_from : string -> int -> char -> bool

contains_from s start c est true si et seulement si c apparaît dans s après la position start .

Lève Invalid_argument si start n'est pas une position valide dans s .

val rcontains_from : string -> int -> char -> bool

rcontains_from s stop c est true si et seulement si c apparaît dans s avant la position stop+1 .

Lève Invalid_argument si stop < 0 ou stop+1 n'est pas une position valide dans s .

val contains : string -> char -> bool

contains s c est String.contains_from s 0 c .

Extraction de sous-chaînes

val sub : string -> int -> int -> string

sub s pos len est une chaîne de longueur len , contenant la sous-chaîne de s qui commence à la position pos et a une longueur len .

Lève Invalid_argument si pos et len ne désignent pas une sous-chaîne valide de s .

val split_on_char : char -> string -> string list

split_on_char sep s est la liste de toutes les sous-chaînes (éventuellement vides) de s qui sont délimitées par le caractère sep . Si s est vide, le résultat est la liste singleton [""] .

Le résultat de la fonction est spécifié par les invariants suivants :

-La liste n'est pas vide.

-Concaténer ses éléments en utilisant sep comme séparateur renvoie une chaîne égale à l'entrée ( concat (make 1 sep)
(split_on_char sep s) = s ).

-Aucune chaîne dans le résultat ne contient le caractère sep .

Depuis 4.04 (4.05 dans StringLabels)

Transformation

val map : (char -> char) -> string -> string

map f s est la chaîne résultant de l'application de f à tous les caractères de s dans l'ordre croissant.

Depuis 4.00

mapi f s est comme String.map mais l'indice du caractère est également passé à f .

val fold_left : ('acc -> char -> 'acc) -> 'acc -> string -> 'acc

fold_left f x s calcule f (... (f (f x s.[0]) s.[1]) ...) s.[n-1] , où n est la longueur de la chaîne s .

Depuis 4.13

val fold_right : (char -> 'acc -> 'acc) -> string -> 'acc -> 'acc

fold_right f s x calcule f s.[0] (f s.[1] ( ... (f s.[n-1] x) ...)) , où n est la longueur de la chaîne s .

Depuis 4.13

val for_all : (char -> bool) -> string -> bool

for_all p s vérifie si tous les caractères de s satisfont le prédicat p .

Depuis 4.13

val exists : (char -> bool) -> string -> bool

exists p s vérifie si au moins un caractère de s satisfont le prédicat p .

Depuis 4.13

val trim : string -> string

trim s est s sans les espaces blancs de début et de fin. Les caractères d'espacement sont : ' ' , '\x0C' (saut de page), '\n' , '\r' , et '\t' .

Depuis 4.00

val escaped : string -> string

escaped s est s avec les caractères spéciaux représentés par des séquences d'échappement, suivant les conventions lexicales d'OCaml.

Tous les caractères en dehors de la plage imprimable US-ASCII [0x20;0x7E] sont échappés, ainsi que la barre oblique inverse (0x2F) et le double guillemet (0x22).

La fonction Scanf.unescaped est une pseudo-inverse de escaped , c'est-à-dire que Scanf.unescaped (escaped s) = s pour toute chaîne s (à moins que escaped s n'échoue).

Lève Invalid_argument si le résultat dépasse Sys.max_string_length octets.

val uppercase_ascii : string -> string

uppercase_ascii s est s avec toutes les lettres minuscules traduites en majuscules, en utilisant le jeu de caractères US-ASCII.

Depuis 4.03 (4.05 dans StringLabels)

Parcours

val iter : (char -> unit) -> string -> unit

iter f s applique la fonction f à chaque caractère de s. C'est équivalent à f s.[0]; f s.[1]; ...; f s.[length s - 1]; ().

val iteri : (int -> char -> unit) -> string -> unit

iteri est comme String.iter, mais la fonction reçoit aussi l'indice correspondant.

Correction orthographique

val edit_distance : ?limit:int -> t -> t -> int

edit_distance s0 s1 est le nombre d'éditions de caractères (insertion, suppression, substitution, transposition) nécessaires pour transformer s0 en s1.

Si limit est fourni, la fonction retourne avec limit dès qu'il est déterminé que s0 et s1 ont une distance d'au moins limit. Ceci est plus rapide si vous avez une limite fixe, par exemple pour la correction orthographique.

La fonction suppose que les chaînes sont encodées en UTF-8 et utilise Uchar.t pour le concept de caractère. Les erreurs de décodage sont remplacées par Uchar.rep. Normaliser les chaînes en NFC donne de meilleurs résultats.

Note. Ceci implémente la distance la plus simple de l'Optimal String Alignment (OSA), pas la Damerau-Levenshtein. Avec cette fonction "ca" et "abc" ont une distance de 3 et non 2.

Since 5.4

val spellcheck : ?max_dist:(string -> int) -> ((string -> unit) -> unit) -> string -> string list

spellcheck iter_dict s sont les mots énumérés par l'itérateur iter_dict dont la String.edit_distance avec s est la plus petite et au plus égale à max_dist s. S'il y a plusieurs corrections, leur ordre est celui où elles apparaissent dans iter_dict. La valeur par défaut de max_dist s est:

- 0 si s a 0 à 2 caractères Unicode.

- 1 si s a 3 à 4 caractères Unicode.

- 2 sinon.

Si votre dictionnaire est une liste l, un itérateur approprié est fourni par (fun yield -> List.iter yield l.) .

Toutes les chaînes sont supposées être encodées en UTF-8, les erreurs de décodage sont remplacées par Uchar.rep.

Décodage binaire d'entiers

Les fonctions de cette section décodent des entiers à partir de chaînes.

Toutes les fonctions suivantes lèvent Invalid_argument si les caractères nécessaires à la position i pour décoder l'entier ne sont pas disponibles.

L'endianness (resp. l'endianness big-endian) signifie que les octets les plus significatifs (resp. les moins significatifs) sont stockés en premier. L'endianness big-endian est également connu sous le nom d'ordre des octets réseau. L'endianness natif est soit l'endianness little-endian, soit big-endian selon Sys.big_endian.

Les entiers de 32 et 64 bits sont représentés par les types int32 et int64, qui peuvent être interprétés comme des entiers signés et non signés.

Les entiers de 8 et 16 bits sont représentés par le type int, qui a plus de bits que le codage binaire. Ces bits supplémentaires sont étendus avec signe (ou zéro) pour les fonctions qui décodent des entiers de 8 ou 16 bits et les représentent comme des valeurs de int.
