Accès non synchronisés

Les accès concurrents aux tableaux dynamiques doivent être synchronisés (par exemple avec un Mutex.t). Les accès non synchronisés à un tableau dynamique constituent une erreur de programmation qui peut entraîner un état invalide du tableau dynamique, dans lequel certaines opérations pourraient échouer avec une exception Invalid_argument.

Tableaux dynamiques

Type !'a t

Un tableau dynamique contenant des valeurs de type 'a.

Un tableau dynamique a fournit des opérations en temps constant get et set sur des indices compris entre 0 et Dynarray.length a - 1 inclus. Sa Dynarray.length peut changer en temps réel lors de l'ajout ou de la suppression d'éléments à la fin du tableau.

Nous disons qu'un indice dans un tableau dynamique a est valide s'il est compris entre 0 et length a - 1 et invalide sinon.

val create : unit -> 'a t

create () est un nouveau tableau vide.

val make : int -> 'a -> 'a t

make n x est un nouveau tableau de longueur n, rempli de x.

Raises Invalid_argument si n < 0 ou n > Sys.max_array_length.

val init : int -> (int -> 'a) -> 'a t

init n f est un nouveau tableau a de longueur n, où get a i est f i. Autrement dit, les éléments de a sont f 0, puis f 1, puis f 2 ... et f (n - 1) en dernier, évalués dans cet ordre.

Ceci est similaire à Array.init.

Raises Invalid_argument si n < 0 ou n > Sys.max_array_length.

val get : 'a t -> int -> 'a

get a i est le i-ème élément de a, en commençant par l'indice 0.

Raises Invalid_argument si l'indice est invalide.

val set : 'a t -> int -> 'a -> unit

set a i x définit le i-ème élément de a à x.

Le i doit être un indice valide. set n'ajoute pas de nouveaux éléments au tableau — voir Dynarray.add_last pour ajouter un élément.

Raises Invalid_argument si l'indice est invalide.

val length : 'a t -> int

length a est le nombre d'éléments dans le tableau.

val is_empty : 'a t -> bool

is_empty a est true si a est vide, c'est-à-dire si length a = 0.

val get_last : 'a t -> 'a

get_last a est l'élément de a à l'indice length a - 1.

Raises Invalid_argument si a est vide.

val find_last : 'a t -> 'a option

find_last a est None si a est vide et Some (get_last a) sinon.

val copy : 'a t -> 'a t

copy a est une copie superficielle de a, un nouveau tableau contenant les mêmes éléments que a.

Ajout d'éléments

Note : toutes les opérations qui ajoutent des éléments lèvent Invalid_argument si la taille doit dépasser Sys.max_array_length.

val add_last : 'a t -> 'a -> unit

add_last a x ajoute l'élément x à la fin du tableau a.

val append_array : 'a t -> 'a array -> unit

append_array a b ajoute tous les éléments de b à la fin de a, dans l'ordre où ils apparaissent dans b.

Exemple :

      let a = Dynarray.of_list [1;2] in
      Dynarray.append_array a [|3; 4|];
      assert (Dynarray.to_list a = [1; 2; 3; 4])

val append_list : 'a t -> 'a list -> unit

Comme Dynarray.append_array, mais avec une liste.

val append : 'a t -> 'a t -> unit

append a b est comme append_array a b, mais b est un tableau dynamique plutôt qu'un tableau fixe.

Attention : append a a est une erreur de programmation car il itère sur a et ajoute des éléments en même temps — voir la section Dynarray.iteration. Il échoue avec Invalid_argument. Si vous voulez réellement ajouter une copie de a à lui-même, vous pouvez utiliser Dynarray.append_array a (Dynarray.to_array a), qui copie a dans un tableau temporaire.

val append_seq : 'a t -> 'a Seq.t -> unit

Comme Dynarray.append_array, mais avec une séquence.

Attention : append_seq a (to_seq_reentrant a) itère simultanément sur a et ajoute des éléments ; l'ordre de ces opérations n'est pas spécifié, et peut conduire à une boucle infinie — les nouveaux éléments peuvent être générés par to_seq_reentrant a et ajoutés à nouveau et encore.

val append_iter : 'a t -> (('a -> unit) -> 'x -> unit) -> 'x -> unit

append_iter a iter x ajoute chaque élément de x à la fin de a. C'est iter (add_last a) x.

Par exemple, append_iter a List.iter [1;2;3] ajoute 1, 2, puis 3 à la fin de a. append_iter a Queue.iter q ajoute les éléments de la file d'attente q à a.

val blit : src:'a t -> src_pos:int -> dst:'a t -> dst_pos:int -> len:int -> unit

blit ~src ~src_pos ~dst ~dst_pos ~len copie len éléments d'un tableau dynamique src, commençant à l'indice src_pos, vers un tableau dynamique dst, commençant à l'indice dst_pos. Fonctionne correctement même si src et dst sont le même tableau, et que les blocs source et destination se chevauchent.

Contrairement à Array.blit, Dynarray.blit peut étendre le tableau de destination avec de nouveaux éléments : il est valide d'appeler blit même si dst_pos + len est supérieur à length dst. La seule exigence est que dst_pos soit au plus égal à length dst (inclus), afin qu'il n'y ait pas d'espace entre les éléments actuels et le bloc copié.

Il est requis que dst_pos soit compris dans l'intervalle 0 à length dst (inclus), afin qu'il n'y ait pas d'espace entre les éléments actuels et le bloc copié.

Raises Invalid_argument si src_pos et len ne désignent pas un sous-tableau valide de src, ou si dst_pos est strictement inférieur à 0 ou strictement supérieur à length dst.

Suppression d'éléments

val pop_last_opt : 'a t -> 'a option

pop_last_opt a supprime et renvoie le dernier élément de a, ou None si le tableau est vide.

val pop_last : 'a t -> 'a

pop_last a supprime et renvoie le dernier élément de a.

Raises Not_found sur un tableau vide.

val remove_last : 'a t -> unit

remove_last a supprime le dernier élément de a, s'il existe. Ne fait rien si a est vide.

val truncate : 'a t -> int -> unit

truncate a n tronque a pour qu'il contienne au plus n éléments.

Supprime les éléments dont l'indice est supérieur ou égal à n. Ne fait rien si n >= length a.

truncate a n est équivalent à :

      if n < 0 then invalid_argument "...";
      while length a > n do
        remove_last a
      done

Raises Invalid_argument si n < 0.

val clear : 'a t -> unit

clear a est truncate a 0, ce qui supprime tous les éléments de a.

Itération

Les fonctions d'itération parcourent les éléments d'un tableau dynamique. Les parcours de a sont calculés dans l'ordre des indices croissants : de l'élément d'indice 0 à l'élément d'indice length a - 1.

Il est interdit de changer la taille du tableau (ajouter ou supprimer des éléments) pendant une itération sur le tableau. Toute fonction d'itération détectera ce cas et lèvera Invalid_argument.

val iter : ('a -> unit) -> 'a t -> unit

iter f a appelle f sur chaque élément de a .

val iteri : (int -> 'a -> unit) -> 'a t -> unit

iteri f a appelle f i x pour chaque x à l'indice i dans a .

val map : ('a -> 'b) -> 'a t -> 'b t

map f a est un nouveau tableau d'éléments de la forme f x pour chaque élément x de a .

Par exemple, si les éléments de a sont x0 , x1 , x2 , alors les éléments de b sont f x0 , f x1 , f x2 .

val mapi : (int -> 'a -> 'b) -> 'a t -> 'b t

mapi f a est un nouveau tableau d'éléments de la forme f i x pour chaque élément x de a à l'indice i .

Par exemple, si les éléments de a sont x0 , x1 , x2 , alors les éléments de b sont f 0 x0 , f 1 x1 , f 2 x2 .

val fold_left : ('acc -> 'a -> 'acc) -> 'acc -> 'a t -> 'acc

fold_left f acc a réduit f sur a dans l'ordre, en partant de l'accumulateur acc .

Par exemple, si les éléments de a sont x0 , x1 , alors fold f acc a est

      let acc = f acc x0 in
      let acc = f acc x1 in
      acc

val fold_right : ('a -> 'acc -> 'acc) -> 'a t -> 'acc -> 'acc

fold_right f a acc calcule f x0 (f x1 (... (f xn acc) ...)) où x0 , x1 , ..., xn sont les éléments de a .

val filter : ('a -> bool) -> 'a t -> 'a t

filter f a est un nouveau tableau de tous les éléments de a qui satisfont f . Autrement dit, c'est un tableau b tel que, pour chaque élément x dans a dans l'ordre, x est ajouté à b si f x est true .

Par exemple, filter (fun x -> x >= 0) a est un nouveau tableau de tous les éléments non négatifs de a , dans l'ordre.

val filter_map : ('a -> 'b option) -> 'a t -> 'b t

filter_map f a est un nouveau tableau d'éléments y tels que f x est Some y pour un élément x de a . En d'autres termes, c'est un tableau b tel que, pour chaque élément x de a dans l'ordre :

-si f x = Some y , alors y est ajouté à b ,

-si f x = None , alors aucun élément n'est ajouté à b .

Par exemple, filter_map int_of_string_opt inputs renvoie un nouveau tableau d'entiers lus à partir des chaînes dans inputs , en ignorant les chaînes qui ne peuvent pas être converties en entiers.

Balayage de Dynarray

val exists : ('a -> bool) -> 'a t -> bool

exists f a est true si un élément de a satisfait f .

Par exemple, si les éléments de a sont x0 , x1 , x2 , alors exists f a est f x0 || f x1 || f x2 .

val for_all : ('a -> bool) -> 'a t -> bool

for_all f a est true si tous les éléments de a satisfont f . Cela inclut le cas où a est vide.

Par exemple, si les éléments de a sont x0 , x1 , x2 , alors for_all f a est f x0 && f x1 && f x2 .

val exists2 : ('a -> 'b -> bool) -> 'a t -> 'b t -> bool

Identique à Dynarray.exists , mais pour un prédicat à deux arguments.

Since 5.4

Raises Invalid_argument si les deux tableaux ont des longueurs différentes.

val for_all2 : ('a -> 'b -> bool) -> 'a t -> 'b t -> bool

Identique à Dynarray.for_all , mais pour un prédicat à deux arguments.

Since 5.4

Raises Invalid_argument si les deux tableaux ont des longueurs différentes.

val mem : 'a -> 'a t -> bool

mem a set est vrai si et seulement si a est structurellement égal à un élément de set (c'est-à-dire qu'il existe un x dans set tel que compare a x = 0 ).

Since 5.3

val memq : 'a -> 'a t -> bool

Identique à Dynarray.mem , mais utilise l'égalité physique plutôt que l'égalité structurelle pour comparer les éléments du tableau.

Since 5.3

val find_opt : ('a -> bool) -> 'a t -> 'a option

find_opt f a renvoie le premier élément du tableau a qui satisfait le prédicat f , ou None s'il n'y a pas de valeur qui satisfait f dans le tableau a .

Since 5.3

val find_index : ('a -> bool) -> 'a t -> int option

find_index f a renvoie Some i , où i est l'indice du premier élément du tableau a qui satisfait f x , s'il existe un tel élément.

Il renvoie None s'il n'existe pas un tel élément.

Since 5.3

val find_map : ('a -> 'b option) -> 'a t -> 'b option

find_map f a applique f aux éléments de a dans l'ordre, et renvoie le premier résultat de la forme Some v , ou None si aucun n'existe.

Since 5.3

val find_mapi : (int -> 'a -> 'b option) -> 'a t -> 'b option

Identique à find_map , mais le prédicat est appliqué à l'indice de l'élément comme premier argument (en commençant par 0), et à l'élément lui-même comme deuxième argument.

Fonctions de comparaison

Les fonctions de comparaison itèrent sur leurs arguments ; c'est une erreur de programmation de modifier leur longueur pendant l'itération, voir la section Dynarray.iteration ci-dessus.

val equal : ('a -> 'a -> bool) -> 'a t -> 'a t -> bool

equal eq a b est vrai lorsque a et b ont la même longueur, et que pour tous les indices i , on a eq (get a i) (get b i) .

Since 5.3

val compare : ('a -> 'a -> int) -> 'a t -> 'a t -> int

compare cmp a b compare a et b selon l'ordre shortlex, c'est-à-dire que les tableaux plus courts sont plus petits et les tableaux de taille égale sont comparés dans l'ordre lexicographique en utilisant cmp pour comparer les éléments.

Pour plus de détails sur les fonctions de comparaison, voir Array.sort .

Since 5.3

Conversions vers d'autres structures de données

Note : les fonctions of_* lèvent Invalid_argument si la longueur doit dépasser Sys.max_array_length .

Les fonctions to_* , à l'exception de celles spécifiquement marquées comme « réentrantes », itèrent sur leur argument dynarray. En particulier, c'est une erreur de programmation si la longueur du dynarray change pendant leur exécution, et les fonctions de conversion lèvent Invalid_argument si elles observent un tel changement.

val of_array : 'a array -> 'a t

of_array arr renvoie un tableau dynamique correspondant au tableau de taille fixe a . Fonctionne en temps O(n) en faisant une copie.

val to_array : 'a t -> 'a array

to_array a renvoie un tableau de taille fixe correspondant au tableau dynamique a . Cela alloue toujours un nouveau tableau et copie les éléments dedans.

val of_list : 'a list -> 'a t

of_list l est le tableau contenant les éléments de l dans le même ordre.

val to_list : 'a t -> 'a list

to_list a est une liste avec les éléments contenus dans le tableau a .

val of_seq : 'a Seq.t -> 'a t

of_seq seq est un tableau contenant les mêmes éléments que seq .

Il parcourt seq une fois et ne se terminera que si seq est fini.

val to_seq : 'a t -> 'a Seq.t

to_seq a est la séquence des éléments get a 0 , get a 1 ... get a (length a - 1) .

val to_seq_reentrant : 'a t -> 'a Seq.t

to_seq_reentrant a est une variante réentrante de Dynarray.to_seq , dans le sens où l'on peut toujours accéder à ses éléments après que la longueur de a ait changé.

Demander le i -ème élément de la séquence résultante (ce qui peut arriver zéro, une ou plusieurs fois) accédera au i -ème élément de a au moment de la demande. La séquence s'arrête si a a moins de i éléments à ce moment-là.

val to_seq_rev : 'a t -> 'a Seq.t

to_seq_rev a est la séquence des éléments get a (l - 1) , get a (l - 2) ... get a 0 , où l est length a au moment où to_seq_rev est appelé.

val to_seq_rev_reentrant : 'a t -> 'a Seq.t

to_seq_rev_reentrant a est une variante réentrante de Dynarray.to_seq_rev , dans le sens où l'on peut toujours accéder à ses éléments après que la longueur de a ait changé.

Les éléments qui ont été supprimés du tableau au moment où ils sont demandés dans la séquence sont ignorés.

Sujets avancés pour la performance

Tableau de support, capacité

En interne, un tableau dynamique utilise un tableau de support (un tableau de taille fixe tel que fourni par le module Array ) dont la longueur est supérieure ou égale à la longueur du tableau dynamique. Nous définissons la capacité d'un tableau dynamique comme la longueur de son tableau de support.

La capacité d'un tableau dynamique est pertinente dans les scénarios avancés, lors du raisonnement sur les performances des programmes de tableau dynamique :

-L'utilisation de la mémoire d'un tableau dynamique est proportionnelle à sa capacité, plutôt qu'à sa longueur.

NAME

Dynarray -- mutable arrays with amortized constant time push

Module

Implements the mutable dynamic array type.

Documentation

This module implements mutable arrays (dynamic arrays) with amortized constant time push. They are similar to Pervasives.list , but with different performance characteristics.

Dynamic arrays are implemented internally using a mutable array (the "backing array") and an integer (the "length"). The length indicates the number of initialized elements in the backing array. The capacity of the dynamic array is the length of the backing array.

When a push operation would overflow the backing array, a larger backing array is allocated, and the elements are copied over. The amortized constant time complexity is achieved by using an exponential reallocation strategy: the capacity is multiplied by a constant factor (typically 2) each time it is increased. This ensures that the total number of elements copied during reallocation is proportional to the total number of elements pushed.

In short: You can think of a dynamic array as a list that you can modify, and which supports efficient random access to its elements. It is especially useful when you are building a list of unknown size, and when you need to access elements at arbitrary positions.

Usage example:

    let a = Dynarray.create () in
    Dynarray.add_last a 1;
    Dynarray.add_last a 2;
    Dynarray.add_last a 3;
    (* a = [1; 2; 3] *)
    Dynarray.set a 1 0;
    (* a = [1; 0; 3] *)
    Dynarray.insert_at 1 5;
    (* a = [1; 5; 0; 3] *)
    let b = Dynarray.sub a 1 2 in
    (* b = [5; 0] *)
    Dynarray.remove_at 1;
    (* a = [1; 0; 3] *)
    Dynarray.length a = 3

Note on GC: The elements contained in the dynamic array are the only values reachable from it. When an element is removed from the dynamic array, it becomes unreachable from the dynamic array, and may be garbage collected if it is not reachable from anywhere else.

Resizing

Dynamic arrays manage their own backing array, automatically resizing it when needed. Users typically do not need to worry about the capacity of the backing array.

The implementation uses a standard exponential reallocation strategy which guarantees amortized constant-time operation; in particular, the total capacity of all backing arrays allocated over the lifetime of a dynamic array is at worst proportional to the total number of elements added.

In other words, users need not care about capacity and reallocations, and they will get reasonable behavior by default. However, in some performance-sensitive scenarios the functions below can help control memory usage or guarantee an optimal number of reallocations.

val capacity : 'a t -> int

capacity a is the length of a 's backing array.

val ensure_capacity : 'a t -> int -> unit

ensure_capacity a n makes sure that the capacity of a is at least n .

Raises Invalid_argument if the requested capacity is outside the range 0 .. Sys.max_array_length .

An example would be to reimplement Dynarray.of_array without using Dynarray.init :

    let of_array arr =
      let a = Dynarray.create () in
      Dynarray.ensure_capacity a (Array.length arr);
      Array.iter (fun v -> add_last a v) arr

Using ensure_capacity guarantees that at most one reallocation will take place, instead of possibly several.

Without this ensure_capacity hint, the number of resizes would be logarithmic in the length of arr , creating a constant-factor slowdown noticeable when arr is large.

val ensure_extra_capacity : 'a t -> int -> unit

ensure_extra_capacity a n is ensure_capacity a (length a + n) , it makes sure that a has room for n extra items.

Raises Invalid_argument if the total requested capacity is outside the range 0 .. Sys.max_array_length .

A use case would be to implement Dynarray.append_array :

    let append_array a arr =
      ensure_extra_capacity a (Array.length arr);
      Array.iter (fun v -> add_last a v) arr

val fit_capacity : 'a t -> unit

fit_capacity a reallocates a backing array if necessary, so that the resulting capacity is exactly length a , with no additional empty space at the end. This can be useful to make sure there is no memory wasted on a long-lived array.

Note that calling fit_capacity breaks the amortized complexity guarantees provided by the default reallocation strategy. Calling it repeatedly on an array may have quadratic complexity, both in time and in total number of words allocated.

If you know that a dynamic array has reached its final length, which will remain fixed in the future, it is sufficient to call to_array and only keep the resulting fixed-size array. fit_capacity is useful when you need to keep a dynamic array for eventual future resizes.

val set_capacity : 'a t -> int -> unit

set_capacity a n reallocates a backing array if necessary, so that the resulting capacity is exactly n . In particular, all elements of index n or greater are removed.

Like Dynarray.fit_capacity , this function breaks the amortized complexity guarantees provided by the reallocation strategy. Calling it repeatedly on an array may have quadratic complexity, both in time and in total number of words allocated.

This is an advanced function; in particular, Dynarray.ensure_capacity should be preferred to increase the capacity, as it preserves those amortized guarantees.

Raises Invalid_argument if n < 0 .

val reset : 'a t -> unit

reset a clears a and replaces its backing array by an empty array.

It is equivalent to set_capacity a 0 or clear a; fit_capacity a .

No leaks: preservation of memory liveness

The user-provided values reachable from a dynamic array a are exactly the elements in the indices 0 to length a - 1 . In particular, no user-provided values are "leaked" by being present in the backing array at index length a or later.

val unsafe_to_iarray : capacity:int -> ('a t -> unit) -> 'a iarray

unsafe_to_iarray ~capacity f calls f on a new empty dynarray with the given capacity , then turns it into an immutable array without a copy, when possible, that is, if two conditions hold:

-the array elements are not floats, and

-after f returned, the array's capacity is equal to its length.

Note that the capacity argument is only a hint. For example, nothing prevents from calling Dynarray.fit_capacity at the end of f .

This function is unsafe because type safety may be broken by concurrent writes to the dynarray from other domains, without proper synchronization, before f returns.

Code examples

Min-heaps for mutable priority queues

We can use dynamic arrays to implement a mutable priority queue. A priority queue provides a function to add elements, and a function to extract the minimum element -- according to some comparison function.

(* We present our priority queues as a functor
   parametrized on the comparison function. *)
module Heap (Elem : Map.OrderedType) : sig
  type t
  val create : unit -> t
  val add : t -> Elem.t -> unit
  val pop_min : t -> Elem.t option
end = struct
  (* Our priority queues are implemented using the standard "min heap"
     data structure, a dynamic array representing a binary tree. *)
  type t = Elem.t Dynarray.t
  let create = Dynarray.create
 (* The node of index [i] has as children the nodes of index [2 * i + 1]
    and [2 * i + 2] -- if they are valid indices in the dynarray. *)
  let left_child i = 2 * i + 1
  let right_child i = 2 * i + 2
  let parent_node i = (i - 1) / 2
  (* We use indexing operators for convenient notations. *)
  let ( .!() ) = Dynarray.get
  let ( .!()<- ) = Dynarray.set
  (* Auxiliary functions to compare and swap two elements
     in the dynamic array. *)
  let order h i j =
    Elem.compare h.!(i) h.!(j)
  let swap h i j =
    let v = h.!(i) in
    h.!(i) <- h.!(j);
    h.!(j) <- v
  (* We say that a heap respects the "heap ordering" if the value of
     each node is smaller than the value of its children. The
     algorithm manipulates arrays that respect the heap algorithm,
     except for one node whose value may be too small or too large.
     The auxiliary functions [heap_up] and [heap_down] take
     such a misplaced value, and move it "up" (respectively: "down")
     the tree by permuting it with its parent value (respectively:
     a child value) until the heap ordering is restored. *)
  let rec heap_up h i =
    if i = 0 then () else
    let parent = parent_node i in
    if order h i parent < 0 then
      (swap h i parent; heap_up h parent)
  and heap_down h ~len i =
    let left, right = left_child i, right_child i in
    if left >= len then () (* no child, stop *) else
    let smallest =
      if right >= len then left (* no right child *) else
      if order h left right < 0 then left else right
    in
    if order h i smallest > 0 then
      (swap h i smallest; heap_down h ~len smallest)
  let add h s =
    let i = Dynarray.length h in
    Dynarray.add_last h s;
    heap_up h i
  let pop_min h =
    if Dynarray.is_empty h then None
    else begin
      (* Standard trick: swap the 'best' value at index 0
         with the last value of the array. *)
      let last = Dynarray.length h - 1 in
      swap h 0 last;
      (* At this point [pop_last] returns the 'best' value,
         and leaves a heap with one misplaced element at index [0]. *)
      let best = Dynarray.pop_last h in
      (* Restore the heap ordering -- does nothing if the heap is empty. *)
      heap_down h ~len:last 0;
      Some best
    end
end

The production code from which this example was inspired includes logic to free the backing array when the heap becomes empty, only in the case where the capacity is above a certain threshold. This can be done by calling the following function from pop :

let shrink h =
  if Dynarray.length h = 0 && Dynarray.capacity h > 1 lsl 18 then
    Dynarray.reset h

The Heap functor can be used to implement a sorting function, by adding all elements into a priority queue and then extracting them in order.

let heap_sort (type a) cmp li =
  let module Heap = Heap(struct type t = a let compare = cmp end) in
  let heap = Heap.create () in
  List.iter (Heap.add heap) li;
  List.map (fun _ -> Heap.pop_min heap |> Option.get) li
