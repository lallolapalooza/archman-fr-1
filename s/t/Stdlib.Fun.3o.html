Combinateurs

val id : 'a -> 'a

id est la fonction identité. Pour tout argument x , id x est x .

val const : 'a -> 'b -> 'a

const c est une fonction qui retourne toujours la valeur c . Pour tout argument x , (const c) x est c .

val compose : ('b -> 'c) -> ('a -> 'b) -> 'a -> 'c

compose f g est une composition de fonctions consistant à appliquer g puis f . Pour tous arguments f , g , et x , compose f g x est f (g x) .

Depuis 5.2

val flip : ('a -> 'b -> 'c) -> 'b -> 'a -> 'c

flip f inverse l'ordre des arguments de la fonction binaire f . Pour tous arguments x et y , (flip f) x y est f y x .

val negate : ('a -> bool) -> 'a -> bool

negate p est la négation de la fonction prédicat p . Pour tout argument x , (negate p) x est not (p x) .

Gestion des exceptions

val protect : finally:(unit -> unit) -> (unit -> 'a) -> 'a

protect ~finally work appelle work () puis finally () avant que work () ne retourne avec sa valeur ou une exception. Dans ce dernier cas, l'exception est relancée après que finally () soit exécuté. Si finally () lève une exception, alors l'exception Fun.Finally_raised est levée à la place.

protect peut être utilisé pour garantir des invariants locaux, que work () retourne normalement ou lève une exception. Cependant, il ne protège pas contre les exceptions inattendues levées à l'intérieur de finally () , telles que Out_of_memory , Stack_overflow , ou les exceptions asynchrones levées par des gestionnaires de signaux (par exemple, Sys.Break ).

Note : C'est une erreur de programmation si d'autres types d'exceptions sont levées par finally , car toute exception levée dans work () sera perdue en cas d'exception Fun.Finally_raised . Par conséquent, il faut s'assurer de les gérer à l'intérieur du finally.

exception Finally_raised of exn

Finally_raised exn est levée par protect ~finally work lorsque finally lève une exception exn . Cette exception représente soit une exception inattendue, soit une erreur de programmation. En règle générale, il ne faut pas intercepter une exception Finally_raised , sauf dans le cadre d'un gestionnaire généraliste.

Exemples

Combinateurs

Les combinateurs Fun fournissent un moyen léger et parfois plus lisible de créer des fonctions anonymes, idéalement utilisés comme arguments éphémères plutôt que comme définitions autonomes. Les exemples ci-dessous le démontreront principalement avec le module List .

[id]

List.init avec l'indice lui-même

  # List.init 3 Fun.id;;
  - : int list = [0; 1; 2]

Utilisation de List.filter_map sur une liste d'options d'entiers pour filtrer les éléments Option.t.None

  # List.filter_map Fun.id [None; Some 2; Some 3; None; Some 5];;
  - : int list = [2; 3; 5]

La distribution conditionnelle de fonctions de type foo -> foo ou leur prise en arguments est un autre endroit où id peut être utile. Considérons une fonction de journalisation primitive qui affiche une chaîne de caractères mais donne à son utilisateur la possibilité de préformater la chaîne avant de l'afficher, par exemple pour insérer un horodatage

  let log ?(preformat : string -> string = Fun.id) message =
    print_endline (preformat message)

Chaque fois que nous pouvons construire des fermetures, id est souvent utilisé pour le cas de base comme une opération nulle. Considérons une fonction qui enchaîne une liste de fonctions unaires :

  let rec chain = function
    | [] -> Fun.id
    | f :: fs -> fun x -> f (chain fs x)

[const]

Initialisation d'une liste de zéros avec List.init

  # List.init 3 (Fun.const 0);;
  - : int list = [0; 0; 0]

Un prédicat autorisant tout, qui pourrait être passé à n'importe quelle fonction de filtrage, par exemple List.filter , pour désactiver le filtrage et récupérer toutes les valeurs

  # List.filter (Fun.const true) [1; 2; 3];;
  - : int list = [1; 2; 3]

Notez que l'application de const (...) évalue l'expression (...) une seule fois et retourne une fonction qui n'a que le résultat de cette évaluation. Pour le démontrer, considérons si (...) était un appel à Random.bool () :

List.init n (Fun.const (Random.bool())) pour tout n > 0 aura exactement deux résultats possibles,

- [true; true; ...; true]

- [false; false; ...; false]

alors que List.init n (fun _ -> Random.bool()) aura 2^n résultats possibles, car l'effet aléatoire est effectué à chaque élément.

Pour des utilisations plus concrètes, considérons String.spellcheck avec une distance maximale constante de 2, au lieu de la distance maximale variable par défaut

  let spellcheck known_words word =
    let dict_iter yield = List.iter yield known_words in
    String.spellcheck ~max_dist:(Fun.const 2) dict_iter word

[flip]

Utilisation de flip pour inverser le comparateur passé à List.sort , qui trie dans l'ordre inverse

  # List.sort (Fun.flip Int.compare) [5; 3; 9; 0; 1; 6; 8];;
  - : int list = [9; 8; 6; 5; 3; 1; 0]

Inversion d'une liste en accumulant une nouvelle liste à l'aide de List.fold_left , qui attend que l'accumulateur soit le premier argument de la fonction qui lui est passée. Nous passons List.cons qui a la liste comme second argument, donc flip est utile ici

  # List.fold_left (Fun.flip List.cons) [] [1; 2; 3];;
  - : int list = [3; 2; 1]

Fait intéressant, flip peut fonctionner avec des fonctions qui ne sont pas binaires, en inversant les deux premiers arguments et en laissant les autres dans l'ordre. Ceci est dû au fait qu'une fonction qui prend n+2 arguments est, conceptuellement, une fonction binaire qui retourne une fonction qui prend n arguments. Étant donné une fonction f : a -> b -> c -> d :

- flip f aura le type b -> a -> c -> d

- fun x -> flip (f x) aura le type a -> c -> b -> d

L'utilisation de flip avec des fonctions non binaires de cette manière est déconseillée, en raison de son impact négatif sur la lisibilité et le raisonnement.

[negate]

Principalement utilisé pour inverser un prédicat dans une fonction qui en attend un, comme List.find_all et des fonctions similaires

Trouver toutes les listes qui ne sont pas vides en utilisant List.is_empty

  # List.find_all (Fun.negate List.is_empty) [[0]; [1; 2; 3]; []; [4; 5]];;
  - : int list list = [[0]; [1; 2; 3]; [4; 5]]

À partir d'une liste donnée de chemins, trouver tous les chemins qui ne sont pas occupés en utilisant Sys.file_exists

  # List.find_all (Fun.negate Sys.file_exists);;
  - : string list -> string list = <fun>

[compose]

Utilisation de List.map sur les éléments de paires avec une fonction sur le second élément

  # List.map (Fun.compose String.length snd) [1, "one"; 2, "two"; 3, "three"];;
  - : int list = [3; 3; 5]

Une implémentation potentielle de Fun.negate

  let negate f = Fun.compose not f

À partir de Fun.id , compose aurait pu être utilisé dans la branche récursive

  let rec chain = function
    | [] -> Fun.id
    | f :: fs -> Fun.compose f (chain fs)
Ou même plus concis 
  let chain fs = List.fold_right Fun.compose fs Fun.id

À partir de Fun.flip , compose et flip

pourrait être utilisée pour condenser la définition de la fonction afin qu'elle devienne

  # Fun.compose
      (String.spellcheck ~max_dist:(Fun.const 2))
      (Fun.flip List.iter)
    ;;
  - : string list -> string -> string list = <fun>

Comme on peut le voir ici, cela a un impact considérable sur la lisibilité et la capacité à raisonner sur la fonction. Ni String.spellcheck ni Fun.flip ne sont unaires, il y a donc une interaction non triviale avec l'application partielle dans cette définition.

L'utilisation intensive de ces combinatoriales en OCaml est généralement déconseillée, non seulement parce qu'elles peuvent rapidement nuire à la lisibilité et au raisonnement, mais aussi parce que les fonctions produites sont souvent sous forme de valeur, donc soumises à la restriction de valeur (voir la section 6.1.2 du manuel).
