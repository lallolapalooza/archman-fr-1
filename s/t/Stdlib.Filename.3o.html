Depuis 3.11.2

val concat : string -> string -> string

concat dir file retourne un nom de fichier désignant le fichier file dans le répertoire dir .

val is_relative : string -> bool

Retourne true si le nom de fichier est relatif au répertoire courant, false s'il est absolu (c'est-à-dire, sous Unix, commence par / ).

val is_implicit : string -> bool

Retourne true si le nom de fichier est relatif et ne commence pas par une référence explicite au répertoire courant ( ./ ou ../ sous Unix), false s'il commence par une référence explicite au répertoire racine ou au répertoire courant.

val check_suffix : string -> string -> bool

check_suffix name suff retourne true si le nom de fichier name se termine par le suffixe suff .

Sous les ports Windows (y compris Cygwin), la comparaison est insensible à la casse, reposant sur String.lowercase_ascii . Notez que cela ne correspond pas exactement à l'interprétation de l'équivalence des noms de fichiers insensibles à la casse de Windows.

val chop_suffix : string -> string -> string

chop_suffix name suff supprime le suffixe suff du nom de fichier name .

Lève Invalid_argument si name ne se termine pas par le suffixe suff .

val chop_suffix_opt : suffix:string -> string -> string option

chop_suffix_opt ~suffix filename supprime le suffixe du filename si possible, ou retourne None si le nom de fichier ne se termine pas par le suffixe.

Sous les ports Windows (y compris Cygwin), la comparaison est insensible à la casse, reposant sur String.lowercase_ascii . Notez que cela ne correspond pas exactement à l'interprétation de l'équivalence des noms de fichiers insensibles à la casse de Windows.

Depuis 4.08

val extension : string -> string

extension name est le plus court suffixe ext de name0 où :

- name0 est le plus long suffixe de name ne contenant pas de séparateur de répertoire ;

- ext commence par un point ;

- ext est précédé d'au moins un caractère autre qu'un point dans name0 .

Si un tel suffixe n'existe pas, extension name est la chaîne vide.

Depuis 4.04

val remove_extension : string -> string

Retourne le nom de fichier donné sans son extension, telle que définie dans Filename.extension . Si l'extension est vide, la fonction retourne le nom de fichier donné.

Le suivant invariant est vrai pour tout nom de fichier s :

remove_extension s ^ extension s = s

Depuis 4.04

val chop_extension : string -> string

Identique à Filename.remove_extension , mais lève Invalid_argument si le nom donné a une extension vide.

val basename : string -> string

Sépare un nom de fichier en nom de répertoire / nom de fichier de base. Si name est un nom de fichier valide, alors concat (dirname name) (basename name) retourne un nom de fichier équivalent à name . De plus, après avoir défini le répertoire courant sur dirname name (avec Sys.chdir ), les références à basename name (qui est un nom de fichier relatif) désignent le même fichier que name avant l'appel à Sys.chdir .

Cette fonction est conforme aux spécifications de POSIX.1-2008 pour l'utilitaire basename .

val dirname : string -> string

Voir Filename.basename . Cette fonction est conforme aux spécifications de POSIX.1-2008 pour l'utilitaire dirname .

val null : string

null est "/dev/null" sous POSIX et "NUL" sous Windows. Il représente un fichier sur le système d'exploitation qui écarte toutes les écritures et retourne fin de fichier à la lecture.

Depuis 4.10

val temp_file : ?temp_dir:string -> string -> string -> string

temp_file prefix suffix retourne le nom d'un nouveau fichier temporaire dans le répertoire temporaire. Le nom de base du fichier temporaire est formé en concaténant prefix , puis un nombre entier choisi judicieusement, puis suffix . L'argument optionnel temp_dir spécifie le répertoire temporaire à utiliser, par défaut le résultat actuel de Filename.get_temp_dir_name . Le fichier temporaire est créé vide, avec les permissions 0o600 (lisible et modifiable uniquement par le propriétaire du fichier). Le fichier est garanti d'être différent de tout autre fichier existant au moment de l'appel à temp_file .

Avant 3.11.2 pas d'argument optionnel ?temp_dir

Lève Sys_error si le fichier n'a pas pu être créé.

val open_temp_file : ?mode:open_flag list -> ?perms:int -> ?temp_dir:string -> string -> string -> string * out_channel

Identique à Filename.temp_file , mais retourne à la fois le nom d'un nouveau fichier temporaire et un canal de sortie ouvert (atomiquement) sur ce fichier. Cette fonction est plus sûre que temp_file : il n'y a aucun risque que le fichier temporaire soit modifié (par exemple, remplacé par un lien symbolique) avant que le programme ne l'ouvre. L'argument optionnel mode est une liste de drapeaux supplémentaires pour contrôler l'ouverture du fichier. Il peut contenir un ou plusieurs de Open_append , Open_binary , et Open_text . Le défaut est [Open_text] (ouverture en mode texte). Le fichier est créé avec les permissions perms (par défaut, lisible et modifiable uniquement par le propriétaire du fichier, 0o600 ).

Avant 4.03 pas d'argument optionnel ?perms

Avant 3.11.2 pas d'argument optionnel ?temp_dir

Lève Sys_error si le fichier n'a pas pu être ouvert.

val temp_dir : ?temp_dir:string -> ?perms:int -> string -> string -> string

temp_dir prefix suffix crée et retourne le nom d'un nouveau répertoire temporaire avec les permissions perms (par défaut 0o700) à l'intérieur de temp_dir . Le nom de base du répertoire temporaire est formé en concaténant prefix , puis un nombre entier choisi judicieusement, puis suffix . L'argument optionnel temp_dir spécifie le répertoire temporaire à utiliser, par défaut le résultat actuel de Filename.get_temp_dir_name . Le répertoire temporaire est créé vide, avec les permissions 0o700 (lisible, modifiable et consultable uniquement par le propriétaire du fichier). Le répertoire est garanti d'être différent de tout autre répertoire existant au moment de l'appel à temp_dir .

Si temp_dir n'existe pas, cette fonction ne le crée pas. Au lieu de cela, elle lève Sys_error.

Depuis 5.1

Lève Sys_error si le répertoire n'a pas pu être créé.

val get_temp_dir_name : unit -> string

Le nom du répertoire temporaire : sous Unix, la valeur de la variable d'environnement TMPDIR , ou "/tmp" si la variable n'est pas définie.

Sous Windows, la valeur retournée par GetTempPath2 (si disponible) ou GetTempPath .

Le répertoire temporaire peut être modifié avec Filename.set_temp_dir_name .

Sous Windows, avant OCaml 5.4, elle retournait la valeur de la variable d'environnement TEMP , ou "." si la variable n'était pas définie.

Depuis 4.00

val set_temp_dir_name : string -> unit

Change le répertoire temporaire retourné par Filename.get_temp_dir_name et utilisé par Filename.temp_file et Filename.open_temp_file . Le répertoire temporaire est une valeur locale au domaine, héritée par les domaines enfants.

quote_command

La version citée d'un nom de fichier, appropriée pour être utilisée comme l'un des arguments sur une ligne de commande, en échappant tous les caractères méta. Attention : sous Windows, le résultat ne sera approprié que pour les programmes qui suivent les conventions de citation standard de Windows.

val quote_command : string -> ?stdin:string -> ?stdout:string -> ?stderr:string -> string list -> string

quote_command cmd args renvoie une ligne de commande citée, appropriée pour être utilisée comme argument pour Sys.command, Unix.system et les fonctions Unix.open_process.

La chaîne cmd est la commande à exécuter. La liste args est la liste des arguments à passer à cette commande. Elle peut être vide.

Les arguments optionnels ?stdin, ?stdout et ?stderr sont des noms de fichiers utilisés pour rediriger l'entrée standard, la sortie standard ou l'erreur standard de la commande. Si ~stdin:f est spécifié, une redirection < f est effectuée et l'entrée standard de la commande lit depuis le fichier f. Si ~stdout:f est spécifié, une redirection > f est effectuée et la sortie standard de la commande est écrite dans le fichier f. Si ~stderr:f est spécifié, une redirection 2> f est effectuée et l'erreur standard de la commande est écrite dans le fichier f. Si ~stdout:f et ~stderr:f sont tous deux spécifiés avec le même nom f, une redirection 2>&1 est effectuée de sorte que la sortie standard et l'erreur standard de la commande soient fusionnées et redirigées vers le même fichier f.

Sous Unix et Cygwin, la commande, les arguments et les redirections s'ils existent sont cités en utilisant Filename.quote et concaténés. Sous Win32, des citations supplémentaires sont effectuées selon les besoins du shell cmd.exe appelé par Sys.command.

Depuis 4.10

Lève Failure si la commande ne peut pas être citée sur la plateforme actuelle.
