Module Hashtbl
: (module Stdlib__Hashtbl)

Accès non synchronisés

Les accès non synchronisés à une table de hachage peuvent entraîner un état invalide de la table. Ainsi, les accès concurrents aux tables de hachage doivent être synchronisés (par exemple avec un Mutex.t ).

Interface générique

type (!'a, !'b) t

Le type des tables de hachage de type 'a vers type 'b .

val create : ?random:bool -> int -> ('a, 'b) t

Hashtbl.create n crée une nouvelle table de hachage vide, avec une taille initiale supérieure ou égale à la taille suggérée n . Pour de meilleurs résultats, n doit être de l'ordre du nombre d'éléments attendu dans la table. La table grandit au besoin, donc n n'est qu'une estimation initiale. Si n est très petit ou négatif, il est ignoré et une petite taille par défaut est utilisée.

Le paramètre optionnel ~random (un booléen) contrôle si l'organisation interne de la table de hachage est aléatoire à chaque exécution de Hashtbl.create ou déterministe sur toutes les exécutions.

Une table de hachage créée avec ~random défini à false utilise une fonction de hachage fixe ( Hashtbl.hash ) pour distribuer les clés parmi les compartiments. En conséquence, les collisions entre clés se produisent de manière déterministe. Dans les applications web ou d'autres applications sensibles à la sécurité, les schémas de collision déterministes peuvent être exploités par un utilisateur malveillant pour créer une attaque par déni de service : l'attaquant envoie des entrées conçues pour créer de nombreuses collisions dans la table, ralentissant ainsi l'application.

Une table de hachage créée avec ~random défini à true utilise la fonction de hachage ensemencée Hashtbl.seeded_hash avec une graine choisie aléatoirement lors de la création de la table de hachage. En pratique, la fonction de hachage utilisée est sélectionnée aléatoirement parmi 2^{30} fonctions de hachage différentes. Toutes ces fonctions de hachage ont des schémas de collision différents, rendant inefficace l'attaque par déni de service décrite ci-dessus. Cependant, en raison de la randomisation, énumérer tous les éléments de la table de hachage à l'aide de Hashtbl.fold ou Hashtbl.iter n'est plus déterministe : les éléments sont énumérés dans des ordres différents à chaque exécution du programme.

Si aucun paramètre ~random n'est donné, les tables de hachage sont créées par défaut en mode non aléatoire. Ce comportement par défaut peut être modifié soit par programme en appelant Hashtbl.randomize , soit en définissant le drapeau R dans la variable d'environnement OCAMLRUNPARAM .

Avant4.00 , le paramètre ~random était absent et toutes les tables de hachage étaient créées en mode non aléatoire.

val clear : ('a, 'b) t -> unit

Vide une table de hachage. Utilisez reset au lieu de clear pour réduire la taille de la table des compartiments à sa taille initiale.

val reset : ('a, 'b) t -> unit

Vide une table de hachage et réduit la taille de la table des compartiments à sa taille initiale.

Depuis 4.00

val copy : ('a, 'b) t -> ('a, 'b) t

Retourne une copie de la table de hachage donnée.

val add : ('a, 'b) t -> 'a -> 'b -> unit

Hashtbl.add tbl clef donnée ajoute une association de clef à donnée dans la table tbl .

Attention : Les associations précédentes pour clef ne sont pas supprimées, mais simplement masquées. C'est-à-dire, après avoir effectué Hashtbl.remove tbl clef , l'association précédente pour clef , s'il y en a une, est restaurée. (Comportement identique à celui des listes associatives.)

Si vous souhaitez le comportement classique de remplacement des éléments, consultez Hashtbl.replace .

val find : ('a, 'b) t -> 'a -> 'b

Hashtbl.find tbl x retourne l'association actuelle de x dans tbl , ou lève Not_found si aucune telle association n'existe.

val find_opt : ('a, 'b) t -> 'a -> 'b option

Hashtbl.find_opt tbl x retourne l'association actuelle de x dans tbl , ou None si aucune telle association n'existe.

Depuis 4.05

val find_all : ('a, 'b) t -> 'a -> 'b list

Hashtbl.find_all tbl x retourne la liste de toutes les données associées à x dans tbl . L'association actuelle est retournée en premier, puis les associations précédentes, dans l'ordre inverse de leur introduction dans la table.

val mem : ('a, 'b) t -> 'a -> bool

Hashtbl.mem tbl x vérifie si x est associé dans tbl .

val remove : ('a, 'b) t -> 'a -> unit

Hashtbl.remove tbl x supprime l'association actuelle de x dans tbl , restaurant l'association précédente si elle existe. Elle ne fait rien si x n'est pas associé dans tbl .

val replace : ('a, 'b) t -> 'a -> 'b -> unit

Hashtbl.replace tbl clef donnée remplace l'association actuelle de clef dans tbl par une association de clef à donnée . Si clef n'est pas associée dans tbl , une association de clef à donnée est ajoutée à tbl . Ceci est fonctionnellement équivalent à Hashtbl.remove tbl clef suivi de Hashtbl.add tbl clef donnée .

val iter : ('a -> 'b -> unit) -> ('a, 'b) t -> unit

Hashtbl.iter f tbl applique f à toutes les associations de la table tbl . f reçoit la clé comme premier argument, et la valeur associée comme second argument. Chaque association est présentée exactement une fois à f .

L'ordre dans lequel les associations sont passées à f n'est pas spécifié. Cependant, si la table contient plusieurs associations pour la même clé, elles sont passées à f dans l'ordre inverse de leur introduction, c'est-à-dire que l'association la plus récente est passée en premier.

Si la table de hachage a été créée en mode non aléatoire, l'ordre dans lequel les associations sont énumérées est reproductible entre les exécutions successives du programme, et même entre les versions mineures d'OCaml. Pour les tables de hachage aléatoires, l'ordre d'énumération est entièrement aléatoire.

Le comportement n'est pas spécifié si la table de hachage est modifiée par f pendant l'itération.

val filter_map_inplace : ('a -> 'b -> 'b option) -> ('a, 'b) t -> unit

Hashtbl.filter_map_inplace f tbl applique f à toutes les associations de la table tbl et met à jour chaque association en fonction du résultat de f . Si f retourne None , l'association est supprimée. Si elle retourne Some nouvelle_val , l'association est mise à jour pour associer la clé à nouvelle_val .

Les autres commentaires pour Hashtbl.iter s'appliquent également.

Depuis 4.03

val fold : ('a -> 'b -> 'acc -> 'acc) -> ('a, 'b) t -> 'acc -> 'acc

Hashtbl.fold f tbl init calcule (f kN dN ... (f k1 d1 init)...) , où k1 ... kN sont les clés de toutes les associations de tbl , et d1 ... dN sont les valeurs associées. Chaque association est présentée exactement une fois à f .

L'ordre dans lequel les associations sont passées à f n'est pas spécifié. Cependant, si la table contient plusieurs associations pour la même clé, elles sont passées à f dans l'ordre inverse de leur introduction, c'est-à-dire que l'association la plus récente est passée en premier.

Si la table de hachage a été créée en mode non aléatoire, l'ordre dans lequel les associations sont énumérées est reproductible entre les exécutions successives du programme, et même entre les versions mineures d'OCaml. Pour les tables de hachage aléatoires, l'ordre d'énumération est entièrement aléatoire.

Le comportement n'est pas spécifié si la table de hachage est modifiée par f pendant l'itération.

val length : ('a, 'b) t -> int

Hashtbl.length tbl retourne le nombre d'associations dans tbl . Cela prend un temps constant. Les associations multiples sont comptées une fois chacune, donc Hashtbl.length donne le nombre de fois où Hashtbl.iter appelle son premier argument.

val randomize : unit -> unit

Après un appel à Hashtbl.randomize() , les tables de hachage sont créées par défaut en mode aléatoire : Hashtbl.create retourne des tables de hachage aléatoires, sauf si le paramètre optionnel ~random:false est donné. Le même effet peut être obtenu en définissant le paramètre R dans la variable d'environnement OCAMLRUNPARAM .

Il est recommandé

Tables de hachage et séquences

val to_seq : ('a, 'b) t -> ('a * 'b) Seq.t

Itère sur la table entière. L'ordre dans lequel les liaisons apparaissent dans la séquence est imprévisible. Cependant, si la table contient plusieurs liaisons pour la même clé, elles apparaissent dans l'ordre inverse de leur insertion, c'est-à-dire que la plus récente apparaît en premier.

Le comportement n'est pas spécifié si la table est modifiée pendant l'itération.

Crée une table à partir des liaisons données. Les liaisons sont ajoutées dans le même ordre où elles apparaissent dans la séquence, en utilisant Hashtbl.replace_seq, ce qui signifie que si deux paires ont la même clé, seule la plus récente apparaît dans la table.

Interface fonctionnelle

L'interface fonctionnelle permet l'utilisation de fonctions de hachage et de comparaison spécifiques, soit pour des raisons de performance ou de sécurité, soit parce que les clés ne sont pas hachables ou comparables avec les fonctions polymorphes intégrées.

Par exemple, on pourrait vouloir spécialiser une table pour des clés entières :

      module IntHash =
        struct
          type t = int
          let equal i j = i=j
          let hash i = i land max_int
        end
      module IntHashtbl = Hashtbl.Make(IntHash)
      let h = IntHashtbl.create 17 in
      IntHashtbl.add h 12 "hello"

Ceci crée un nouveau module IntHashtbl avec un nouveau type 'a t de tables associant des entiers à des valeurs de type 'a. Dans cet exemple, h contient des valeurs de type string, donc son type est string IntHashtbl.t.

Notez que le nouveau type 'a IntHashtbl.t n'est pas compatible avec le type ('a,'b) Hashtbl.t de l'interface générique. Par exemple, Hashtbl.length h ne serait pas typé ; vous devez utiliser IntHashtbl.length.

module type HashedType = sig end

La signature d'entrée du foncteur Hashtbl.Make.

module type S = sig end

La signature de sortie du foncteur Hashtbl.Make.

module Make : (H : HashedType) -> sig end

Un foncteur qui construit une implémentation de table de hachage. Le foncteur Hashtbl.Make retourne une structure contenant un type key pour les clés et un type 'a t pour les tables associatives reliant des données de type 'a à des clés de type key. Les opérations sont similaires à celles de l'interface générique, mais elles utilisent les fonctions de hachage et de comparaison spécifiées dans l'argument du foncteur H au lieu des comparaisons et hachages génériques. Comme la fonction de hachage n'est pas initialisée, l'opération create de la structure résultante renvoie toujours des tables de hachage non randomisées.

Les opérations sont similaires à celles de l'interface générique, mais elles utilisent les fonctions de hachage et de comparaison amorcées spécifiées dans l'argument du foncteur H au lieu des comparaisons et hachages génériques. L'opération create de la structure résultante supporte le paramètre optionnel ~random et renvoie des tables de hachage randomisées si ~random:true est passé ou si la randomisation est activée globalement (voir Hashtbl.randomize).

Les fonctions de hachage polymorphes

val hash : 'a -> int

Hashtbl.hash x associe un entier non négatif à n'importe quelle valeur de n'importe quel type. Il est garanti que si x = y ou Stdlib.compare x y = 0, alors hash x = hash y. De plus, hash termine toujours, même sur des structures cycliques.

val seeded_hash : int -> 'a -> int

Une variante de Hashtbl.hash paramétrée en plus par une graine entière.

Since 4.00

val hash_param : int -> int -> 'a -> int

Hashtbl.hash_param meaningful total x calcule une valeur de hachage pour x, avec les mêmes propriétés que pour hash. Les deux paramètres additionnels meaningful et total offrent un contrôle plus fin sur le hachage. Le hachage effectue un parcours en largeur, de gauche à droite, de la structure x, s'arrêtant après que meaningful nœuds significatifs aient été vus ou après que total nœuds (significatifs ou non) aient été vus. Si la valeur de total spécifiée par l'utilisateur dépasse une certaine limite, actuellement 256, alors elle est maintenue à cette limite. Les nœuds significatifs sont : les entiers ; les nombres à virgule flottante ; les chaînes de caractères ; les caractères ; les booléens ; et les constructeurs constants. Des valeurs plus élevées pour meaningful et total signifient que plus de nœuds sont pris en compte pour calculer la valeur de hachage finale, et donc les collisions sont moins probables. Cependant, le hachage est plus lent. Les paramètres meaningful et total régulent l'équilibre entre la précision et la vitesse. Par défaut, Hashtbl.hash et Hashtbl.seeded_hash prennent meaningful = 10 et total = 100.

val seeded_hash_param : int -> int -> int -> 'a -> int

Variante de Hashtbl.hash_param paramétrée en plus par une graine entière. Utilisation : Hashtbl.seeded_hash_param meaningful total seed x.

Since 4.00

Comptage d'éléments

Étant donné une séquence d'éléments (ici, une Seq.t), nous voulons compter combien de fois chaque élément distinct apparaît dans la séquence. Une façon simple de le faire, en supposant que les éléments sont comparables et hachables, est d'utiliser une table de hachage qui associe les éléments à leur nombre d'occurrences.

L'idée est illustrée ci-dessous en utilisant une séquence de caractères (type char). Nous utilisons une Char_tbl spécialisée pour char.

    # module Char_tbl = Hashtbl.Make(struct
        type t = char
        let equal = Char.equal
        let hash = Hashtbl.hash
      end)
    (*  compter les occurrences distinctes de caractères dans [seq] *)
    #

let count_chars (seq : char Seq.t) : _ list =
        let counts = Char_tbl.create 16 in
        Seq.iter
          (fun c ->
            let count_c =
              Char_tbl.find_opt counts c
              |> Option.value ~default:0
            in
            Char_tbl.replace counts c (count_c + 1))
          seq;
        (* transformer en liste *)
        Char_tbl.fold (fun c n l -> (c,n) :: l) counts []
          |> List.sort (fun (c1,_)(c2,_) -> Char.compare c1 c2)
    val count_chars : Char_tbl.key Seq.t -> (Char.t * int) list = <fun>
    (* seq de base à partir d'une chaîne *)
    # let seq = String.to_seq "hello world, and all the camels in it!"
    val seq : char Seq.t = <fun>
    # count_chars seq
    - : (Char.t * int) list =
    [(' ', 7); ('!', 1); (',', 1); ('a', 3); ('c', 1); ('d', 2); ('e', 3);
     ('h', 2); ('i', 2); ('l', 6); ('m', 1); ('n', 2); ('o', 2); ('r', 1);
     ('s', 1); ('t', 2); ('w', 1)]
    (* "abcabcabc..." *)
    # let seq2 =
        Seq.cycle (String.to_seq "abc") |> Seq.take 31
    val seq2 : char Seq.t = <fun>
    # String.of_seq seq2
    - : String.t = "abcabcabcabcabcabcabcabcabcabca"
    # count_chars seq2
    - : (Char.t * int) list = [('a', 11); ('b', 10); ('c', 10)]
