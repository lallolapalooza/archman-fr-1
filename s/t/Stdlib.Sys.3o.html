val command : chaîne -> int

Exécute la commande donnée dans le shell et retourne son code de sortie.

L'argument de Sys.command est généralement le nom d'une commande suivie de zéro, un ou plusieurs arguments, séparés par des espaces. L'argument donné est interprété par un shell : pour les ports Win32 d'OCaml, c'est cmd.exe et pour les autres ports, c'est sh. Il peut contenir des commandes shell comme echo, et aussi des caractères spéciaux comme des redirections de fichiers > et <, qui seront acceptés par le shell.

Inversement, les caractères d'espacement ou shell spéciaux apparaissant dans les noms de commandes ou dans leurs arguments doivent être échappés ou mis entre guillemets pour que le shell ne les interprète pas. Les règles de mise entre guillemets varient entre le shell POSIX et le shell Windows. La fonction Filename.quote_command effectue l'échappement approprié étant donné un nom de commande, une liste d'arguments et des redirections de fichiers optionnelles.

Stdlib.Sys Manual Page

Stdlib.Sys

module Sys : sig ... end

Platform-independent interface to system functionalities.

This module provides access to several system functionalities: command-line arguments, environment variables, the exit status of the program, the current time, a random number generator, registered finalizers, GC control, signal handling, and profiling.

Note that some functions in this module have subtle interactions with the garbage collector and with threads. See the documentation for details.

The functions in this module are thread-safe, except for Sys.catch_break and Sys.enable_runtime_warnings, which modify global state.

The following functions are not safe with respect to the garbage collector: Sys.register_finalizer, Gc.finalise, and functions that take callbacks (e.g. signal with Signal_handle). They should not be called from within signal handlers or finalizers.

All functions in this module are safe with respect to lazy evaluation.

Since 4.00

Command-line arguments

val argv : string array

The command-line arguments passed to the program. argv.(0) is the name of the program itself.

valexecutable_name : string

The name of the executable file being run. This is typically the same as argv.(0), but may differ depending on the operating system and how the program was invoked.

Since 4.06

Program termination

val exit : int -> 'a

Terminate the program immediately with the given exit status. An exit status of 0 usually indicates successful execution, while a non-zero status indicates an error.

val disconnect_runtime_system : unit -> unit

Disconnect the OCaml runtime system from the operating system. This function should be called when the OCaml program is about to exit, typically just before calling exit. It ensures that all threads and other resources managed by the runtime system are properly cleaned up. Calling this function multiple times or calling it after the runtime system has already been disconnected may lead to undefined behavior.

val random_seed : int -> unit

Seed the default random number generator (used by Random.int, etc.) with the given integer.

val get_random_seed : unit -> int

Return the current seed of the default random number generator.

Since 5.2

Finalizers

val register_finalizer : 'a -> ('a -> unit) -> unit

Register a finalizer function for a given value. When the value is no longer reachable, the finalizer function will be called with the value as its argument. The finalizer function must not retain the value, otherwise it will be finalized again.

Finalizers are not guaranteed to be called, especially when the program terminates abruptly or when the memory is not reclaimed by the garbage collector. They are also not called for values that are immediately garbage collected.

This function is not safe with respect to the garbage collector and should not be called from within signal handlers or other finalizers.

Since 4.00

Garbage collector control

val gc_quick_check : unit -> bool

Perform a quick check for unreachable objects. Returns true if the garbage collector detects unreachable objects, false otherwise. This function can be used for debugging memory leaks.

Since 4.00

val gc_compaction : unit -> unit

Perform a full garbage collection with compaction. This can help reduce memory fragmentation, but it is a relatively expensive operation.

Since 4.00

val minor_gc_if_major_gc : unit -> unit

Perform a minor garbage collection if a major garbage collection has been performed recently. This can help to free up memory quickly after a large allocation. Note that the condition "recently" is not precisely defined and depends on the garbage collector's heuristics.

Since 4.00

val alarm : float -> unit

Set an alarm that will trigger after the specified number of seconds. If the argument is less than or equal to 0, the alarm is cancelled.

This function is implemented using POSIX timers and is not available on all platforms. On platforms where it is not available, it raises an Invalid_argument exception.

This alarm is a global resource and may interact with other functions that use timers (e.g. Thread.delay). The alarm is delivered as a signal, so it is not thread-safe.

Since 5.3

val shutdown_hook : (unit -> unit) -> unit

Registers a hook to be called when the OCaml runtime system is shutting down. The hook is called with no arguments. If multiple hooks are registered, they are called in the reverse order of registration.

This function is useful for performing cleanup actions before the program exits, such as closing files or releasing resources. The hooks are called before the program's exit status is returned.

Note that hooks registered with shutdown_hook are executed before finalizers registered with Sys.register_finalizer or Gc.finalise.

Since 5.3

val disable_program_termination : unit -> unit

Disables the default behavior of program termination upon receiving certain signals (e.g., SIGTERM, SIGINT). This allows the program to handle these signals gracefully by registering custom signal handlers using `Sys.signal`.

This function is intended for use in specific scenarios where fine-grained control over program termination is required, such as in long-running services or applications that need to perform cleanup before exiting. Use with caution, as it may mask unexpected program termination signals.

Since 5.3

val enable_subprocess_handling : unit -> unit

Enables the OCaml runtime system's handling of subprocesses. This enables features such as automatic reaping of zombie processes and proper management of child process status.

This function should be called early in the program's execution, before any subprocesses are created. It is particularly relevant for applications that frequently spawn and manage child processes.

Since 5.3

val disable_runtime_warnings : unit -> unit

val opaque_identity : 'a -> 'a

For optimization purposes, this function behaves like an unknown function, preventing its argument from being optimized away. At runtime, it is equivalent to the identity function.

This is useful for benchmarking pure computations, as it ensures they are not optimized away.
