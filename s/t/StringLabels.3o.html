Chaînes de caractères.

Une chaîne de caractères s de longueur n est une séquence indexable et immuable de n octets. Pour des raisons historiques, ces octets sont appelés caractères.

La sémantique des fonctions sur les chaînes de caractères est définie en termes d'indices et de positions. Celles-ci sont représentées et décrites comme suit.

positions 0 1 2 3 4 n-1 n +---+---+---+---+ +-----+ indices | 0 | 1 | 2 | 3 | ... | n-1 | +---+---+---+---+ +-----+

-Un indice i de s est un entier dans l'intervalle [ 0 ; n-1 ]. Il représente le i ème octet (caractère) de s qui peut être accédé via l'opérateur d'indexation de chaîne à temps constant s.[i] .

-Une position i de s est un entier dans l'intervalle [ 0 ; n ]. Elle représente soit le début de la chaîne, soit le point entre deux indices, soit la fin de la chaîne. Le i ème indice d'octet se situe entre la position i et i+1 .

Deux entiers start et len sont dits définir une sous-chaîne valide de s si len >= 0 et start , start+len sont des positions de s .

Texte Unicode. Les chaînes de caractères étant des séquences arbitraires d'octets, elles peuvent contenir tout type d'encodage textuel. Cependant, l'encodage recommandé pour stocker du texte Unicode dans les chaînes OCaml est UTF-8. C'est l'encodage utilisé par les échappements Unicode dans les littéraux de chaînes. Par exemple, la chaîne "\u{1F42B}" est l'encodage UTF-8 du caractère Unicode U+1F42B.

Immuabilité dépassée. Avant OCaml 4.02, les chaînes de caractères étaient modifiables en place, comme les séquences mutables d'octets Bytes.t. OCaml 4 disposait de diverses options de compilateur et de configuration pour supporter la période de transition des chaînes mutables vers les chaînes immuables. Ces options ne sont plus disponibles, et les chaînes de caractères sont maintenant toujours immuables.

La version étiquetée de ce module peut être utilisée comme décrit dans le module StdLabels.

Chaînes

type t = string

Le type pour les chaînes de caractères.

val make : int -> char -> string

make n c est une chaîne de longueur n où chaque indice contient le caractère c .

Lève Invalid_argument si n < 0 ou n > Sys.max_string_length .

val init : int -> f:(int -> char) -> string

init n ~f est une chaîne de longueur n où l'indice i contient le caractère f i (appelé dans l'ordre croissant des indices).

Depuis 4.02

Lève Invalid_argument si n < 0 ou n > Sys.max_string_length .

val empty : string

La chaîne vide.

Depuis 4.13

val length : string -> int

length s est la longueur (nombre d'octets/caractères) de s .

val get : string -> int -> char

get s i est le caractère à l'indice i dans s . C'est la même chose qu'écrire s.[i] .

Lève Invalid_argument si i n'est pas un indice valide de s .

val of_bytes : bytes -> string

Retourne une nouvelle chaîne qui contient les mêmes octets que la séquence d'octets donnée.

Depuis 4.13

val to_bytes : string -> bytes

Retourne une nouvelle séquence d'octets qui contient les mêmes octets que la chaîne donnée.

Depuis 4.13

Identique à Bytes.blit_string qui devrait être préférée.

Concaténation

Note. L'opérateur binaire (^) concatène deux chaînes de caractères.

val concat : sep:string -> string list -> string

concat ~sep ss concatène la liste de chaînes ss , en insérant la chaîne séparateur sep entre chacune.

Lève Invalid_argument si le résultat est plus long que Sys.max_string_length octets.

val cat : string -> string -> string

cat s1 s2 concatène s1 et s2 ( s1 ^ s2 ).

Depuis 4.13

Lève Invalid_argument si le résultat est plus long que Sys.max_string_length octets.

Prédicats et comparaisons

val equal : t -> t -> bool

equal s0 s1 est true si et seulement si s0 et s1 sont égaux octet par octet.

Depuis 4.05

val compare : t -> t -> int

compare s0 s1 trie s0 et s1 par ordre lexicographique. compare se comporte comme compare sur les chaînes mais peut être plus efficace.

val starts_with : prefix:string -> string -> bool

starts_with ~prefix s est true si et seulement si s commence par prefix .

Depuis 4.13

val ends_with : suffix:string -> string -> bool

ends_with ~suffix s est true si et seulement si s se termine par suffix .

Depuis 4.13

val contains_from : string -> int -> char -> bool

contains_from s start c est true si et seulement si c apparaît dans s après la position start .

Lève Invalid_argument si start n'est pas une position valide dans s .

val rcontains_from : string -> int -> char -> bool

rcontains_from s stop c est true si et seulement si c apparaît dans s avant la position stop+1 .

Lève Invalid_argument si stop < 0 ou stop+1 n'est pas une position valide dans s .

val contains : string -> char -> bool

contains s c est String.contains_from s 0 c .

Extraction de sous-chaînes

val sub : string -> pos:int -> len:int -> string

sub s ~pos ~len est une chaîne de longueur len , contenant la sous-chaîne de s qui commence à la position pos et a la longueur len .

Lève Invalid_argument si pos et len ne désignent pas une sous-chaîne valide de s .

val split_on_char : sep:char -> string -> string list

split_on_char ~sep s est la liste de toutes les sous-chaînes (éventuellement vides) de s qui sont délimitées par le caractère sep . Si s est vide, le résultat est la liste singleton [""] .

Le résultat de la fonction est spécifié par les invariants suivants :

-La liste n'est pas vide.

-La concaténation de ses éléments en utilisant sep comme séparateur renvoie une chaîne égale à l'entrée ( concat (make 1 sep)
(split_on_char sep s) = s ).

-Aucune chaîne dans le résultat ne contient le caractère sep .

Parcours

val iter : f:(char -> unit) -> string -> unit

iter ~f s applique la fonction f sur chaque caractère de s . C'est équivalent à f s.[0]; f s.[1]; ...; f s.[length s - 1]; () .

val iteri : f:(int -> char -> unit) -> string -> unit

iteri est similaire à StringLabels.iter , mais la fonction reçoit également l'indice correspondant.

Vérification orthographique

val edit_distance : ?limit:int -> t -> t -> int

edit_distance s0 s1 est le nombre de modifications d'un seul caractère (insertion, suppression, substitution, transposition) nécessaires pour convertir s0 en s1 .

Si limit est fourni, la fonction retourne limit dès qu'il est déterminé que s0 et s1 ont une distance d'au moins limit . C'est plus rapide si vous avez une limite fixe, par exemple pour la vérification orthographique.

La fonction suppose que les chaînes sont encodées en UTF-8 et utilise Uchar.t pour la notion de caractère. Les erreurs de décodage sont remplacées par Uchar.rep . Normaliser les chaînes en NFC donne de meilleurs résultats.

Note. Ceci implémente la distance OSA (Optimal String Alignment), plus simple, pas la distance de Damerau-Levenshtein. Avec cette fonction « ca » et « abc » ont une distance de 3 et non 2.

Since 5.4

val spellcheck : ?max_dist:(string -> int) -> ((string -> unit) -> unit) -> string -> string list

spellcheck iter_dict s sont les chaînes énumérées par l'itérateur iter_dict dont la StringLabels.edit_distance à s est la plus petite et ne dépasse pas max_dist s . S'il y a plusieurs corrections, leur ordre est celui de iter_dict . La valeur par défaut max_dist s est :

- 0 si s a 0 à 2 caractères Unicode.

- 1 si s a 3 à 4 caractères Unicode.

- 2 sinon.

Si votre dictionnaire est une liste l , un itérateur approprié iter_dict est donné par (fun yield -> List.iter yield l) .

Toutes les chaînes sont supposées être encodées en UTF-8, les erreurs de décodage sont remplacées par des caractères Uchar.rep .

Since 5.4

Décodage binaire d'entiers

Les fonctions de cette section décodent des entiers à partir de chaînes.

Toutes les fonctions suivantes lèvent Invalid_argument s'il n'y a pas assez de caractères disponibles à la position i pour décoder l'entier.

Le codage little-endian (resp. big-endian) signifie que les octets les plus (resp. moins) significatifs sont stockés en premier. Big-endian est également appelé ordre réseau. L'encodage natif est little-endian ou big-endian selon Sys.big_endian .

Les entiers de 32 bits et 64 bits sont représentés par les types int32 et int64, qui peuvent être interprétés comme des nombres signés ou non signés. Les entiers de 8 bits et 16 bits sont représentés par le type int, qui a plus de bits que le codage binaire. Ces bits supplémentaires sont étendus en signe (ou étendus avec des zéros) pour les fonctions qui décodent des entiers de 8 ou 16 bits et les représentent comme des valeurs de type int .
