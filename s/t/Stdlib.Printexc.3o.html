Le type des valeurs d'exception.

val to_string : exn -> string

Printexc.to_string e renvoie une représentation string de l'exception e .

val to_string_default : exn -> string

Printexc.to_string_default e renvoie une représentation string de l'exception e , en ignorant tous les afficheurs d'exception enregistrés.

Depuis 4.09

val print : ('a -> 'b) -> 'a -> 'b

Printexc.print fn x applique fn à x et renvoie le résultat. Si l'évaluation de fn x lève une exception, le nom de l'exception est imprimé sur la sortie d'erreur standard et levé à nouveau. L'utilisation typique est de capturer et de rapporter les exceptions qui s'échappent d'une application de fonctions.

val catch : ('a -> 'b) -> 'a -> 'b

Obsolète. Cette fonction n'est plus nécessaire.

Printexc.catch fn x est similaire à Printexc.print , mais abandonne le programme avec le code de sortie 2 après avoir imprimé l'exception non capturée. Cette fonction est obsolète : le système d'exécution peut maintenant imprimer les exceptions non capturées aussi précisément que Printexc.catch . De plus, appeler Printexc.catch rend plus difficile de suivre l'emplacement de l'exception en utilisant le débogueur ou la pile d'appels. Par conséquent, n'utilisez pas Printexc.catch dans de nouveaux programmes.

val print_backtrace : out_channel -> unit

Printexc.print_backtrace oc imprime une trace d'exception sur le canal de sortie oc . La trace d'exception liste les emplacements du programme où la dernière exception a été levée et où l'exception s'est propagée à travers les appels de fonction.

Si l'appel ne se trouve pas dans un gestionnaire d'exception, la trace renvoyée n'est pas spécifiée. Si l'appel est fait après un code de capture d'exception (avant le gestionnaire ou pendant la correspondance du gestionnaire via une garde `when`), la trace peut correspondre à une exception plus récente que celle qui a été gérée.

Depuis 3.11

val get_backtrace : unit -> string

Printexc.get_backtrace () renvoie une chaîne contenant la même trace d'exception que Printexc.print_backtrace imprimerait. La même restriction d'utilisation que Printexc.print_backtrace .

Depuis 3.11

val record_backtrace : bool -> unit

Printexc.record_backtrace b active ou désactive l'enregistrement des traces d'exception (si b = true ) ou (si b = false ). Initialement, les traces d'exception ne sont pas enregistrées, sauf si le flag b est passé au programme via la variable d'environnement OCAMLRUNPARAM .

Depuis 3.11

val backtrace_status : unit -> bool

Printexc.backtrace_status() renvoie true si les traces d'exception sont actuellement enregistrées, false sinon.

Depuis 3.11

val register_printer : (exn -> string option) -> unit

Printexc.register_printer fn enregistre fn comme afficheur d'exception. L'afficheur doit renvoyer None ou lever une exception s'il ne sait pas comment convertir l'exception passée, et Some avec la chaîne résultante s s'il peut convertir l'exception passée. Les exceptions levées par l'afficheur sont ignorées.

Lors de la conversion d'une exception en chaîne, les afficheurs sont appelés dans l'ordre inverse de leur enregistrement, jusqu'à ce qu'un afficheur renvoie Some s (s'il n'existe pas un tel afficheur, des afficheurs génériques seront utilisés).

En utilisant ce mécanisme, vous devez être conscient qu'une trace d'exception est attachée au thread qui a vu l'exception, et non à l'exception elle-même. En pratique, cela signifie que le code lié à fn ne doit pas utiliser la trace s'il a levé une exception avant lui.

Depuis 3.11.2

val use_printers : exn -> string option

Printexc.use_printers e renvoie None s'il n'y a pas d'afficheurs enregistrés, et Some s avec la chaîne résultante s sinon.

Depuis 4.09

Traces brutes (raw backtraces)

type raw_backtrace

Le type raw_backtrace stocke une trace d'exception dans un format de bas niveau, qui peut être converti en un format utilisable en utilisant raw_backtrace_entries et backtrace_slots_of_raw_entry ci-dessous.

La conversion des traces d'exception en backtrace_slot est plus lente que la capture des traces. Si un programme traite beaucoup de traces, il peut être utile d'utiliser raw_backtrace pour éviter ou retarder la conversion.

Les traces brutes ne peuvent pas être sérialisées. Si vous avez besoin de sérialisation, vous devriez utiliser le tableau renvoyé par la méthode backtrace_slots de la section suivante.

Depuis 4.01

type raw_backtrace_entry = private int

Un raw_backtrace_entry est un élément d'une raw_backtrace .

Chaque raw_backtrace_entry est un entier opaque, dont la valeur n'est pas stable entre différents programmes, ou même entre différentes exécutions du même binaire.

Un raw_backtrace_entry peut être converti en un format utilisable en utilisant backtrace_slots_of_raw_entry ci-dessous. Vous devez tenir compte du fait que, en raison de l'inlining, un seul raw_backtrace_entry peut être converti en plusieurs backtrace_slot s. Comme les valeurs d'un raw_backtrace_entry ne sont pas stables, elles ne peuvent pas être sérialisées. Si elles doivent être converties, la conversion doit être effectuée par le processus qui les a générées.

Toujours en raison de l'inlining, il peut y avoir plusieurs valeurs distinctes de raw_backtrace_entry qui convergent vers les mêmes backtrace_slot s. Cependant, si deux raw_backtrace_entry s sont égales en tant qu'entiers, elles représentent les mêmes backtrace_slot s.

val get_raw_backtrace : unit -> raw_backtrace

Printexc.get_raw_backtrace () renvoie la même trace d'exception que Printexc.print_backtrace imprimerait, mais dans un format brut. La même restriction d'utilisation que Printexc.print_backtrace .

Depuis 4.01

val print_raw_backtrace : out_channel -> raw_backtrace -> unit

Imprime une trace d'exception dans le même format que Printexc.print_backtrace utilise.

Depuis 4.01

val raw_backtrace_to_string : raw_backtrace -> string

Renvoie une chaîne d'une trace d'exception, dans le même format que Printexc.get_backtrace utilise.

Depuis 4.01

val raise_with_backtrace : exn -> raw_backtrace -> 'a

Ré-lève l'exception en utilisant la trace d'exception donnée pour la source de l'exception.

Depuis 4.05

Pile d'appels actuelle

val get_callstack : int -> raw_backtrace

Printexc.get_callstack n renvoie une description du haut de la pile d'appels au point actuel du programme (pour le thread actuel), avec au maximum n entrées. (Note : cette fonction n'a aucun rapport avec les exceptions, bien qu'elle fasse partie du module Printexc.)

Depuis 4.01

Exceptions non capturées

val default_uncaught_exception_handler : exn -> raw_backtrace -> unit

Printexc.default_uncaught_exception_handler imprime l'exception et sa trace d'exception sur la sortie d'erreur standard.

Depuis 4.11

val set_uncaught_exception_handler : (exn -> raw_backtrace -> unit) -> unit

Printexc.set_uncaught_exception_handler fn enregistre fn comme gestionnaire pour les exceptions non capturées. Le gestionnaire par défaut est Printexc.default_uncaught_exception_handler .

Note : lorsque fn est appelé, toutes les fonctions enregistrées avec at_exit ont déjà été appelées.
