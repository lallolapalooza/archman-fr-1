NOM

Smokeping::probes::TelnetJunOSPing - Sonde Telnet JunOS pour SmokePing

SYNTAXE

*** Probes ***
+TelnetJunOSPing
forks = 5
offset = 50%
packetsize = 100
step = 300
timeout = 15
# Les variables suivantes peuvent être remplacées dans chaque section cible
/^influx_.+/ = influx_location = Dans le sous-sol
junospass = motdepasse # obligatoire
junosuser = utilisateur # obligatoire
pings = 5
psource = 192.168.2.129
source = 192.168.2.1 # obligatoire
# [...]
*** Targets ***
probe = TelnetJunOSPing # si c'est la sonde par défaut
# [...]
+ ma_cible
# probe = TelnetJunOSPing # si la sonde par défaut est autre
host = mon.host
/^influx_.+/ = influx_location = Dans le sous-sol
junospass = motdepasse # obligatoire
junosuser = utilisateur # obligatoire
pings = 5
psource = 192.168.2.129
source = 192.168.2.1 # obligatoire

DESCRIPTION

Intègre Juniper JunOS comme sonde dans smokeping. Utilise le protocole telnet pour exécuter un ping depuis un appareil JunOS (source) vers un autre appareil (hôte). Cette sonde utilise essentiellement le "ping étendu" de Juniper JunOS. Vous avez la possibilité de spécifier l'interface à partir de laquelle le ping est émis.

VARIABLES

Variables spécifiques à la sonde supportées :

forks
Exécuter ce nombre de processus concurrents au maximum

Exemple de valeur : 5

Valeur par défaut : 5

offset
Si vous exécutez de nombreuses sondes simultanément, vous voudrez peut-être éviter qu'elles ne frappent votre réseau en même temps. En utilisant le paramètre d'offset spécifique à la sonde, vous pouvez modifier le moment où chaque sonde sera exécutée. L'offset est spécifié en % de l'intervalle total, ou alternativement comme 'random', et l'offset de la section 'General' est utilisé si rien n'est spécifié ici. Notez que cela n'influence PAS les rrds elles-mêmes, il s'agit simplement de savoir quand l'acquisition des données est initiée. (Cette variable n'est applicable que si la variable 'concurrentprobes' est définie dans la section 'General'.)

Exemple de valeur : 50%

packetsize
L'option (optionnelle) packetsize vous permet de configurer la taille des paquets pour les pings envoyés.

Valeur par défaut : 100

step
Durée de l'intervalle de base que cette sonde doit utiliser, si elle est différente de celle spécifiée dans la section 'Database'. Notez que le pas dans les fichiers RRD est fixe lors de leur génération initiale, et si vous changez le paramètre step par la suite, vous devrez supprimer les anciens fichiers RRD ou les convertir d'une manière ou d'une autre. (Cette variable n'est applicable que si la variable 'concurrentprobes' est définie dans la section 'General'.)

Exemple de valeur : 300

timeout
Combien de temps prend un seul 'ping' au maximum

Exemple de valeur : 15

Valeur par défaut : 5

Variables spécifiques à la cible supportées :

/^influx_.+/
Il s'agit d'une balise qui sera envoyée à influxdb et n'a aucun impact sur la mesure de la sonde. Le nom de la balise sera envoyé sans le préfixe "influx_", qui sera remplacé par "tag_". Les balises peuvent être utilisées pour le filtrage.

Exemple de valeur : influx_location = Dans le sous-sol

junospass
L'option junospass vous permet de spécifier le mot de passe pour le nom d'utilisateur spécifié avec l'option junosuser.

Exemple de valeur : motdepasse

Ce réglage est obligatoire.

junosuser
L'option junosuser vous permet de spécifier un nom d'utilisateur qui a la capacité de ping sur l'appareil JunOS.

Exemple de valeur : utilisateur

Ce réglage est obligatoire.

pings
Combien de pings doivent être envoyés à chaque cible, si différent de la valeur globale spécifiée dans la section Database. Notez que le nombre de pings dans les fichiers RRD est fixe lors de leur génération initiale, et si vous changez ce paramètre par la suite, vous devrez supprimer les anciens fichiers RRD ou les convertir d'une manière ou d'une autre.

Exemple de valeur : 5

psource
L'option (optionnelle) psource spécifie une adresse IP ou une interface alternative à partir de laquelle vous souhaitez émettre vos pings. Les routeurs peuvent avoir de nombreuses adresses IP et interfaces. Lorsque vous pinguez depuis un routeur, vous avez la possibilité de choisir l'interface et/ou l'adresse IP à partir de laquelle le ping est émis. La spécification d'une adresse IP/interface ne spécifie pas nécessairement l'interface à partir de laquelle le ping partira, mais spécifiera l'adresse qui apparaîtra comme provenance des paquets. Si cette option est omise, l'appareil JunOS émettra le paquet automatiquement en fonction du routage et/ou des métriques. Si cela n'a pas de sens pour vous, laissez-la simplement de côté.

Exemple de valeur : 192.168.2.129

source
L'option source spécifie l'appareil JunOS auquel nous nous connectons par telnet. Il s'agit d'une adresse IP d'un appareil JunOS que vous/votre serveur : 1) Pouvez joindre par telnet 2) Avoir un nom d'utilisateur et un mot de passe valides pour

Exemple de valeur : 192.168.2.1

Ce réglage est obligatoire.

NOTES

Configuration JunOS

L'appareil JunOS doit avoir un nom d'utilisateur/mot de passe configuré, ainsi que la capacité de se connecter aux VTY.

Certains appareils JunOS ont un maximum de 5 VTY disponibles, soyez donc prudent à ne pas atteindre une limite avec la variable 'forks'.

Exigences

Ce module nécessite le module Net::Telnet pour perl. Il est généralement inclus dans la plupart des systèmes d'exploitation plus récents qui incluent perl.

Débogage

Il y a du code de débogage TRÈS rudimentaire intégré à ce module (il est basé sur le code de débogage écrit dans Net::Telnet). Il enregistrera des informations dans trois fichiers : "TIPreturn", "TIPoutlog" et "TIPdump". Ces fichiers seront écrits dans votre répertoire de travail courant (CWD). Vous pouvez changer les noms de ces fichiers pour quelque chose de plus significatif pour vous.

Authentification par mot de passe

Il convient de noter que la méthode d'authentification telnet utilise des transmissions en clair... ce qui signifie que sans mesures de sécurité réseau appropriées, quelqu'un pourrait intercepter votre nom d'utilisateur et votre mot de passe sur le réseau. Je pourrais tenter d'intégrer SSH dans une future version de ce module, mais c'est très peu probable. Actuellement, SSH ajoute une surcharge de traitement considérable à un routeur et n'est pas extrêmement facile à implémenter en perl.

Cela étant dit, n'ayez pas trop peur de telnet. Rappelez-vous, le module JunOSPing d'origine utilisait RSH, qui est encore plus effrayant à utiliser du point de vue de la sécurité.

Taille du paquet ping

La page man de FPing dit ceci sur le sujet de la taille des paquets ping :

Nombre d'octets de données de ping à envoyer. La taille minimale (normalement 12) laisse de la place pour les données dont fping a besoin pour son travail (numéro de séquence, horodatage). La taille des données reçues signalée inclut l'en-tête IP (normalement 20 octets) et l'en-tête ICMP (8 octets), donc la taille totale minimale est de 40 octets. Par défaut, 56, comme avec ping. Le maximum est la taille maximale théorique du datagramme IP (64 Ko), bien que la plupart des systèmes la limitent à un nombre plus petit, dépendant du système.

NAME

Smokeping_probes_TelnetJunOSPing - Telnet to a Juniper JunOS device and ping

SYNOPSIS

require Smokeping::probes::TelnetJunOSPing;
my $r = Smokeping::probes::TelnetJunOSPing->new(
    'url'   => 'junos://user:password@host/routing-instance',
    'port'  => 23,
    'descr' => 'My Juniper',
);

my $res = $r->ping;

DESCRIPTION

This probe uses Telnet to log into a JunOS device, then execute a ping command. It will measure the latency of the ping command as executed on the remote device. This is useful for measuring latency between JunOS devices, or to measure the latency from a JunOS device to some other host.

The url is of the form:

junos://user:password@host/routing-instance

If no routing-instance is specified, the default 'inet.0' will be used.

The probe connects to the JunOS device using Telnet, logs in using the provided credentials, and then executes the specified ping command.

The ping command can be configured using the pingcmd option. By default, it uses:

ping ${target} count=4 interval=0.2

The probe extracts the round-trip time (avg/max/min) from the ping command output and returns it as a hash containing min, avg, max, and loss.

Example output:

{
    min => 10.23,
    avg => 12.45,
    max => 15.67,
    loss => 0,
}

VARIABLES

url
The URL for the JunOS device, including username, password, host, and optional routing instance.
port
The Telnet port to connect to. Defaults to 23.
descr
A description for this probe.
pingcmd
The ping command to execute on the JunOS device. The placeholder `${target}` will be replaced with the actual target host. Defaults to ping ${target} count=4 interval=0.2.
timeout
The timeout for the Telnet connection and ping command execution. Defaults to 30 seconds.

AUTHORS

Peter Lindner <peter.lindner@netcup.de>

NOTES

This probe requires the Net::Telnet module to be installed.

Ensure that the JunOS device has Telnet enabled and that the provided user has the necessary privileges to execute the ping command.
