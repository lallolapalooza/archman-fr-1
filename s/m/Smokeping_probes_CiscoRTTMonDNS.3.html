NOM

Smokeping::probes::CiscoRTTMonDNS.pm - Sonde pour SmokePing

SYNTAXE

*** Sondes ***
+CiscoRTTMonDNS
forks = 5
offset = 50%
step = 300
timeout = 15
# Les variables suivantes peuvent être remplacées dans chaque section cible
/^influx_.+/ = influx_location = Au sous-sol
ioshost = RTTcommunity@Myrouter.foobar.com.au # obligatoire
iosint = 10.33.22.11
name = www.foobar.com.au # obligatoire
pings = 5
timeout = 15
# [...]
*** Cibles ***
probe = CiscoRTTMonDNS # si c'est la sonde par défaut
# [...]
+ ma_cible
# probe = CiscoRTTMonDNS # si la sonde par défaut est autre chose
host = mon.hote
/^influx_.+/ = influx_location = Au sous-sol
ioshost = RTTcommunity@Myrouter.foobar.com.au # obligatoire
iosint = 10.33.22.11
name = www.foobar.com.au # obligatoire
pings = 5
timeout = 15

DESCRIPTION

Une sonde pour smokeping, qui utilise les fonctionnalités MIB ciscoRttMon ("Service Assurance Agent", "SAA") de Cisco IOS pour chronométrer (récursif, type A) les requêtes DNS vers un serveur DNS.

VARIABLES

Variables spécifiques à la sonde supportées :

forks
Exécuter ce nombre de processus simultanés au maximum

Exemple de valeur : 5

Valeur par défaut : 5

offset
Si vous exécutez de nombreuses sondes simultanément, vous pourriez vouloir éviter qu'elles ne frappent votre réseau en même temps. En utilisant le paramètre d'offset spécifique à la sonde, vous pouvez changer le moment où chaque sonde sera exécutée. L'offset est spécifié en % de l'intervalle total, ou alternativement comme 'random', et l'offset de la section 'General' est utilisé si rien n'est spécifié ici. Notez que cela n'influence PAS les RRD eux-mêmes, c'est juste une question de quand l'acquisition de données est initiée. (Cette variable n'est applicable que si la variable 'concurrentprobes' est définie dans la section 'General'.)

Exemple de valeur : 50%

step
Durée de l'intervalle de base que cette sonde doit utiliser, si différent de celui spécifié dans la section 'Database'. Notez que le pas dans les fichiers RRD est fixe lorsqu'ils sont générés à l'origine, et si vous changez le paramètre de pas par la suite, vous devrez supprimer les anciens fichiers RRD ou les convertir d'une manière ou d'une autre. (Cette variable n'est applicable que si la variable 'concurrentprobes' est définie dans la section 'General'.)

Exemple de valeur : 300

timeout
Durée maximale d'un 'ping' unique

Exemple de valeur : 15

Valeur par défaut : 5

Variables spécifiques à la cible supportées :

/^influx_.+/
Il s'agit d'une étiquette qui sera envoyée à influxdb et n'a aucun impact sur la mesure de la sonde. Le nom de l'étiquette sera envoyé sans le préfixe "influx_", qui sera remplacé par "tag_" à la place. Les étiquettes peuvent être utilisées pour le filtrage.

Exemple de valeur : influx_location = Au sous-sol

ioshost
Le paramètre ioshost (obligatoire) spécifie le routeur Cisco qui enverra les requêtes DNS, ainsi que la chaîne de communauté SNMP sur le routeur.

Exemple de valeur : RTTcommunity@Myrouter.foobar.com.au

Ce paramètre est obligatoire.

iosint
Le paramètre iosint (facultatif) est l'adresse source pour les paquets DNS. Ce devrait être l'une des adresses IP actives (!) du routeur pour obtenir des résultats. IOS recherche l'adresse de l'hôte cible dans la table de routage et utilise ensuite les interfaces qui y sont listées pour envoyer les paquets DNS. Par défaut, IOS utilise l'adresse IP (principale) de l'interface d'envoi comme adresse source pour les paquets originaires du routeur.

Exemple de valeur : 10.33.22.11

name
Le paramètre name (obligatoire) est le nom DNS à résoudre.

Exemple de valeur : www.foobar.com.au

Ce paramètre est obligatoire.

pings
Combien de pings doivent être envoyés à chaque cible, si différent de la valeur globale spécifiée dans la section Database. Notez que le nombre de pings dans les fichiers RRD est fixe lorsqu'ils sont générés à l'origine, et si vous changez ce paramètre par la suite, vous devrez supprimer les anciens fichiers RRD ou les convertir d'une manière ou d'une autre.

Exemple de valeur : 5

timeout
Durée maximale d'un 'ping' RTTMonDNS unique plus 10 secondes de marge. Comme nous contrôlons notre propre timeout, le seul but de ceci est de ne pas être éliminé par la méthode de ping de basefork.

Exemple de valeur : 15

Valeur par défaut : 15

NOTES

paramètre host

Le paramètre host spécifie le serveur DNS que le routeur utilisera.

VERSIONS IOS

Cette sonde ne fonctionne qu'avec IOS 12.0(3)T ou supérieur. Il est recommandé de la tester d'abord sur des routeurs moins critiques.

INSTALLATION

Pour installer cette sonde, copiez ciscoRttMonMIB.pm dans ($SMOKEPINGINSTALLDIR)/lib/Smokeping et CiscoRTTMonDNS.pm dans ($SMOKEPINGINSTALLDIR)/lib/Smokeping/probes.

Le(s) routeur(s) doivent être configurés pour autoriser l'accès SNMP en lecture/écriture. Suffisant est :

snmp-server community RTTCommunity RW

Si vous voulez être un peu plus restrictif avec l'accès SNMP en écriture au routeur, envisagez de configurer quelque chose comme ceci :

access-list 2 permit 10.37.3.5
snmp-server view RttMon ciscoRttMonMIB included
snmp-server community RTTCommunity view RttMon RW 2

La configuration ci-dessus accorde l'accès SNMP en lecture-écriture uniquement à 10.37.3.5 (l'hôte smokeping) et uniquement à l'arborescence MIB ciscoRttMon. La sonde n'a pas besoin d'accéder à des variables SNMP en dehors de l'arborescence RttMon.

BOGUES

La sonde effectue des requêtes DNS inutiles, c'est-à-dire plus que ce qui est configuré dans la variable "pings", car la MIB RTTMon ne permet de définir qu'un temps total pour toutes les requêtes dans une seule exécution de mesure (une "vie"). Actuellement, la sonde définit la durée de vie à "pings"*5+3 secondes (5 secondes est la valeur de timeout codée en dur dans cette sonde).
