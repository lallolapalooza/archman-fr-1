NOM

Smokeping::probes::EchoPingChargen - une sonde echoping(1) pour SmokePing

APERÇU

Mesure les temps de réponse TCP chargen (port 19) pour SmokePing.

SYNTAXE

*** Sondes ***
+EchoPingChargen
binary = /usr/bin/echoping
forks = 5
offset = 50%
step = 300
# Les variables suivantes peuvent être remplacées dans chaque section de cible
/^influx_.+/ = influx_location = Dans la cave
extraopts = -une-lettre-que-l-auteur-n-a-pas-envisagée
fill = A
ipversion = 4
pings = 5
priority = 6
size = 510
timeout = 1
tos = 0xa0
waittime = 1
# [...]
*** Cibles ***
probe = EchoPingChargen # si cela doit être la sonde par défaut
# [...]
+ ma_cible
# probe = EchoPingChargen # si la sonde par défaut est autre chose
host = mon.hôte
/^influx_.+/ = influx_location = Dans la cave
extraopts = -une-lettre-que-l-auteur-n-a-pas-envisagée
fill = A
ipversion = 4
pings = 5
priority = 6
size = 510
timeout = 1
tos = 0xa0
waittime = 1

VARIABLES

Variables spécifiques à la sonde supportées :

binary
L'emplacement de votre exécutable echoping.

Valeur par défaut : /usr/bin/echoping

forks
Exécute ce nombre de processus concurrents au maximum

Exemple de valeur : 5

Valeur par défaut : 5

offset
Si vous exécutez de nombreuses sondes en parallèle, vous pourriez vouloir éviter qu'elles n'atteignent votre réseau en même temps. En utilisant le paramètre offset spécifique à la sonde, vous pouvez changer le moment où chaque sonde sera exécutée. L'offset est spécifié en % de l'intervalle total, ou alternativement comme 'random', et l'offset de la section 'General' est utilisé si rien n'est spécifié ici. Notez que cela n'influence PAS les fichiers RRD eux-mêmes, il s'agit simplement du moment où l'acquisition des données est initiée. (Cette variable n'est applicable que si la variable 'concurrentprobes' est définie dans la section 'General'.)

Exemple de valeur : 50%

step
Durée de l'intervalle de base que cette sonde doit utiliser, si différent de celui spécifié dans la section 'Database'. Notez que le pas dans les fichiers RRD est fixe lors de leur génération initiale, et si vous modifiez le paramètre step par la suite, vous devrez supprimer les anciens fichiers RRD ou les convertir d'une manière ou d'une autre. (Cette variable n'est applicable que si la variable 'concurrentprobes' est définie dans la section 'General'.)

Exemple de valeur : 300

Variables spécifiques à la cible supportées :

/^influx_.+/
Il s'agit d'une étiquette qui sera envoyée à influxdb et n'a aucun impact sur la mesure de la sonde. Le nom de l'étiquette sera envoyé sans le préfixe "influx_", qui sera remplacé par "tag_". Les étiquettes peuvent être utilisées pour le filtrage.

Exemple de valeur : influx_location = Dans la cave

extraopts
Toutes les options supplémentaires spécifiées ici seront passées telles quelles à echoping(1).

Exemple de valeur : -une-lettre-que-l-auteur-n-a-pas-envisagée

fill
L'option "-f" de echoping(1).

Exemple de valeur : A

ipversion
Le protocole IP utilisé. Les valeurs possibles sont "4" et "6". Passé à echoping(1) sous forme d'options "-4" ou "-6".

Exemple de valeur : 4

pings
Combien de pings doivent être envoyés à chaque cible, si différent de la valeur globale spécifiée dans la section Database. Notez que le nombre de pings dans les fichiers RRD est fixe lors de leur génération initiale, et si vous modifiez ce paramètre par la suite, vous devrez supprimer les anciens fichiers RRD ou les convertir d'une manière ou d'une autre.

Exemple de valeur : 5

priority
L'option "-p" de echoping(1).

Exemple de valeur : 6

size
L'option "-s" de echoping(1).

Exemple de valeur : 510

timeout
L'option "-t" de echoping(1).

Exemple de valeur : 1

Valeur par défaut : 5

tos
L'option "-P" de echoping(1).

Exemple de valeur : 0xa0

waittime
L'option "-w" de echoping(1).

Exemple de valeur : 1

AUTEURS

Niko Tyni <ntyni@iki.fi>

NOTES

La variable udp n'est pas supportée.
