NOM

Smokeping::probes::NFSping - Sonde NFSping pour SmokePing

SYNOPIS

*** Sondes ***
+NFSping
binary = /usr/local/bin/nfsping # obligatoire
blazemode = true
hostinterval = 1.5
mininterval = 0.001
offset = 50%
pings = 20
step = 300
tcp = true
timeout = 1.5
# Les variables suivantes peuvent être surchargées dans chaque section cible
/^influx_.+/ = influx_location = Dans le sous-sol
# [...]
*** Cibles ***
probe = NFSping # si c'est la sonde par défaut
# [...]
+ ma_cible
# probe = NFSping # si la sonde par défaut est autre chose
host = mon.hote
/^influx_.+/ = influx_location = Dans le sous-sol

DESCRIPTION

Intègre NFSping comme sonde dans smokeping. La variable binary doit pointer vers votre copie du programme NFSping.

NFSping peut être téléchargé depuis :

https://github.com/mprovost/NFSping

En mode blazemode, NFSping envoie une requête de plus que demandé, et ignore la première valeur de temps de réponse retournée car elle est susceptible d'être une valeur aberrante.

VARIABLES

Variables spécifiques à la sonde supportées :

binary
L'emplacement de votre binaire nfsping.

Exemple de valeur : /usr/local/bin/nfsping

Ce paramètre est obligatoire.

blazemode
Envoyer une requête supplémentaire puis ignorer la première réponse car la première est forcément une valeur aberrante.

Exemple de valeur : true

hostinterval
Le paramètre "-p" de nfsping, mais en secondes (potentiellement fractionnaires) plutôt qu'en millisecondes, pour la cohérence avec les autres sondes Smokeping. Ce paramètre définit le temps d'attente de nfsping entre les paquets successifs vers un hôte individuel.

Exemple de valeur : 1.5

mininterval
Le paramètre "-i" de nfsping, mais en secondes (potentiellement fractionnaires) plutôt qu'en millisecondes, pour la cohérence avec les autres sondes Smokeping. C'est l'intervalle entre les requêtes vers les hôtes successifs.

Exemple de valeur : 0.001

Valeur par défaut : 0.01

offset
Si vous exécutez de nombreuses sondes simultanément, vous pouvez souhaiter éviter qu'elles n'atteignent votre réseau au même moment. En utilisant le paramètre d'offset spécifique à la sonde, vous pouvez modifier le moment où chaque sonde sera exécutée. L'offset est spécifié en % de l'intervalle total, ou alternativement comme 'random', et l'offset de la section 'General' est utilisé si rien n'est spécifié ici. Notez que cela n'influence PAS les fichiers rrds eux-mêmes, il s'agit simplement de savoir quand l'acquisition de données est initiée. (Cette variable n'est applicable que si la variable 'concurrentprobes' est définie dans la section 'General'.)

Exemple de valeur : 50%

pings
Combien de requêtes doivent être envoyées à chaque cible, si elles diffèrent de la valeur globale spécifiée dans la section Database. Notez que le nombre de requêtes dans les fichiers RRD est fixé lors de leur génération initiale, et si vous changez ce paramètre par la suite, vous devrez supprimer les anciens fichiers RRD ou les convertir d'une manière ou d'une autre.

Exemple de valeur : 20

step
Durée de l'intervalle de base que cette sonde doit utiliser, si elle diffère de celle spécifiée dans la section 'Database'. Notez que le pas dans les fichiers RRD est fixé lors de leur génération initiale, et si vous changez le paramètre de pas par la suite, vous devrez supprimer les anciens fichiers RRD ou les convertir d'une manière ou d'une autre. (Cette variable n'est applicable que si la variable 'concurrentprobes' est définie dans la section 'General'.)

Exemple de valeur : 300

tcp
Utiliser TCP au lieu de UDP.

Exemple de valeur : true

timeout
Le paramètre "-t" de nfsping, mais en secondes (potentiellement fractionnaires) plutôt qu'en millisecondes, pour la cohérence avec les autres sondes Smokeping.

Exemple de valeur : 1.5
