NOM

Smokeping::probes::TelnetIOSPing - Sonde Cisco IOS pour SmokePing

SYNOPIS

*** Sondes ***
+TelnetIOSPing
forks = 5
offset = 50%
packetsize = 56
step = 300
timeout = 15
# Les variables suivantes peuvent être surchargées dans chaque section de cible
/^influx_.+/ = influx_location = Au sous-sol
iospass = motdepasse # obligatoire
iosuser = utilisateur # obligatoire
pings = 5
psource = 192.168.2.129
source = 192.168.2.1 # obligatoire
vrf = VRF1
# [...]
*** Cibles ***
probe = TelnetIOSPing # si cela doit être la sonde par défaut
# [...]
+ ma_cible
# probe = TelnetIOSPing # si la sonde par défaut est autre chose
host = mon.host
/^influx_.+/ = influx_location = Au sous-sol
iospass = motdepasse # obligatoire
iosuser = utilisateur # obligatoire
pings = 5
psource = 192.168.2.129
source = 192.168.2.1 # obligatoire
vrf = VRF1

DESCRIPTION

Intègre Cisco IOS en tant que sonde dans SmokePing. Il utilise le protocole telnet pour exécuter un ping depuis un périphérique Cisco IOS (source) vers un autre périphérique (cible). Cette sonde utilise essentiellement le "ping étendu" de Cisco IOS. Vous avez la possibilité de spécifier à partir de quelle interface le ping doit provenir.

VARIABLES

Variables spécifiques à la sonde :

forks
Autant de processus simultanés que possible sont exécutés.

Exemple de valeur : 5

Valeur par défaut : 5

offset
Si vous exécutez de nombreuses sondes simultanées, il peut être utile d'éviter que toutes n'atteignent votre réseau en même temps. En utilisant la variable spécifique à la cible 'offset', vous pouvez modifier le moment où chaque sonde s'exécutera. L'offset est spécifié en % de l'intervalle total, ou alternativement comme 'random', et l'offset de la section 'General' est utilisé si rien n'est spécifié ici. Il convient de noter que cela n'affecte PAS les RRD, il s'agit simplement d'une question de savoir quand la collecte de données commencera. (Cette variable n'est applicable que si la variable 'concurrentprobes' est définie dans la section 'General').

Exemple de valeur : 50 %

packetsize
L'option (facultative) packetsize permet de définir la taille des paquets pour les pings envoyés.

Valeur par défaut : 56

step
L'intervalle de base que cette sonde doit utiliser, s'il est différent de celui spécifié dans la section 'Database'. Vous devez noter que le pas des fichiers RRD est fixe au moment de leur génération initiale. Si vous modifiez ce paramètre par la suite, vous devrez supprimer les anciens fichiers RRD ou les convertir d'une manière ou d'une autre. (Cette variable n'est applicable que si la variable 'concurrentprobes' est définie dans la section 'General').

Exemple de valeur : 300

timeout
Combien de temps maximum un 'ping' est autorisé à s'exécuter.

Exemple de valeur : 15

Valeur par défaut : 5

Variables spécifiques à la cible :

/^influx_.+/
Il s'agit d'une étiquette qui est envoyée à influxdb et n'a aucun impact sur la mesure de la sonde. Le nom de l'étiquette est envoyé sans le préfixe 'influx_', qui sera remplacé par 'tag_'. Les étiquettes peuvent être utilisées pour le filtrage.

Exemple de valeur : influx_location = Au sous-sol

iospass
L'option iospass permet de spécifier le mot de passe pour l'utilisateur spécifié avec l'option iosuser.

Exemple de valeur : motdepasse

Cette valeur est obligatoire.

iosuser
L'option iosuser permet de spécifier un utilisateur ayant la capacité de ping sur le périphérique Cisco IOS.

Exemple de valeur : utilisateur

Cette valeur est obligatoire.

pings
Combien de pings doivent être envoyés à chaque cible, s'il est différent de la valeur globale spécifiée dans la section 'Database'. Vous devez noter que le nombre de pings dans les fichiers RRD est fixe au moment de leur génération initiale. Si vous modifiez ce paramètre par la suite, vous devrez supprimer les anciens fichiers RRD ou les convertir d'une manière ou d'une autre.

Exemple de valeur : 5

psource
L'option (facultative) psource spécifie une adresse IP ou une interface alternative à partir de laquelle vous souhaitez lancer vos pings. Les routeurs peuvent avoir de nombreuses adresses IP et interfaces. Lorsque vous pingez à partir d'un routeur, vous aurez la possibilité de choisir à partir de quelle interface et/ou de quelle adresse IP le ping doit provenir. La spécification d'une IP/interface ne spécifie pas nécessairement l'interface à partir de laquelle le ping sera émis, mais spécifie de quelle adresse la ou les paquets semblent provenir. Si cette option est omise, le périphérique Cisco IOS émettra automatiquement le paquet en fonction du réseau et/ou des métriques. Si cela n'a pas de sens pour vous, omettez simplement cette option.

Exemple de valeur : 192.168.2.129

source
L'option source spécifie le périphérique Cisco IOS auquel nous nous connectons via telnet. Il s'agit de l'adresse IP d'un périphérique Cisco IOS auquel vous/votre serveur : 1) Pouvez vous connecter par telnet 2) Disposez d'un nom d'utilisateur et d'un mot de passe valides.

Exemple de valeur : 192.168.2.1

Cette valeur est obligatoire.

vrf
L'option vrf permet de spécifier la VRF pour le ping.

Exemple de valeur : VRF1

NOTES

Configuration IOS

Le périphérique Cisco IOS doit avoir un utilisateur avec un mot de passe configuré, ainsi que la capacité de se connecter aux VTY. Exemple :

!
utilisateur smokeping privilège 5 motdepasse 0 SmokepingPassword
!
ligne vty 0 4
 login local
 transport input telnet
!

Certains périphériques Cisco IOS ont un maximum de 5 VTY disponibles, vous devez donc faire attention à ce que la valeur 'forks' n'atteigne pas la limite.

Prérequis

Ce module nécessite le module Net::Telnet pour Perl. Il est inclus dans la plupart des systèmes d'exploitation récents qui incluent Perl.

Débogage

Il existe un code de débogage très rudimentaire intégré à ce module (basé sur le code de débogage écrit dans Net::Telnet). Il enregistrera des informations dans trois fichiers : "TIPreturn", "TIPoutlog" et "TIPdump". Ces fichiers seront écrits dans le répertoire de travail actuel (CWD). Vous pouvez renommer ces fichiers pour quelque chose de plus significatif pour vous.

Authentification par mot de passe

Vous devez être averti que la méthode d'authentification telnet utilise des transmissions en clair... ce qui signifie que sans mesures de sécurité appropriées, quelqu'un pourrait écouter votre nom d'utilisateur et votre mot de passe sur le réseau. On pourrait essayer d'intégrer SSH dans une future version de ce module, mais c'est très peu probable. Pour l'instant, SSH ajoute une grande surcharge à un routeur, et il n'est pas très facile à implémenter en Perl.

Bien que dire cela ne devrait pas vous faire peur à telnet, rappelez-vous que le module IOSPing original utilisait RSH, qui est encore plus dangereux d'un point de vue sécurité.

Taille du paquet de ping

La page de manuel de FPing dit la chose suivante à propos de la taille du paquet de ping :

Nombre d'octets de données de ping à envoyer. La taille minimale (généralement 12) laisse de la place pour les données dont fping a besoin pour faire son travail (numéro de séquence, horodatage). La taille des données reçues rapportée inclut l'en-tête IP (généralement 20 octets) et l'en-tête ICMP (8 octets), donc la taille minimale totale est de 40 octets. La valeur par défaut est 56, comme dans ping. Le maximum est théorique.
