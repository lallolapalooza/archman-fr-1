NOM

Smokeping::probes::AnotherSSH - Une autre sonde SSH

SYNTAXE

*** Sondes ***
+AnotherSSH
forks = 5
offset = 50%
step = 300
# Les variables suivantes peuvent être remplacées dans chaque section cible
/^influx_.+/ = influx_location = Au sous-sol
greeting = SSH-Latency-Measurement-Sorry-for-this-logmessage
interval = established
mininterval = 0.5
pings = 5
port = 22
timeout = 5
# [...]
*** Cibles ***
probe = AnotherSSH # si c'est la sonde par défaut
# [...]
+ ma_cible
# probe = AnotherSSH # si la sonde par défaut est autre chose
host = mon.hote
/^influx_.+/ = influx_location = Au sous-sol
greeting = SSH-Latency-Measurement-Sorry-for-this-logmessage
interval = established
mininterval = 0.5
pings = 5
port = 22
timeout = 5

DESCRIPTION

Mesure de latence via SSH. Ceci génère des messages dans le journal sur l'autre hôte, donc obtenez la permission du propriétaire au préalable !

VARIABLES

Variables spécifiques à la sonde supportées :

forks
Exécute ce nombre de processus concurrents au maximum

Exemple de valeur : 5

Valeur par défaut : 5

offset
Si vous exécutez de nombreuses sondes simultanément, vous voudrez peut-être éviter qu'elles n'atteignent votre réseau en même temps. En utilisant le paramètre d'offset spécifique à la sonde, vous pouvez modifier le moment où chaque sonde sera exécutée. L'offset est spécifié en % de l'intervalle total, ou alternativement comme 'random', et l'offset de la section 'General' est utilisé si rien n'est spécifié ici. Notez que cela n'influence PAS les fichiers RRD eux-mêmes, il s'agit simplement de savoir quand l'acquisition des données est initiée. (Cette variable n'est applicable que si la variable 'concurrentprobes' est définie dans la section 'General'.)

Exemple de valeur : 50%

step
Durée de l'intervalle de base que cette sonde doit utiliser, si elle est différente de celle spécifiée dans la section 'Database'. Notez que le pas dans les fichiers RRD est fixe lors de leur génération initiale, et si vous modifiez le paramètre step par la suite, vous devrez supprimer les anciens fichiers RRD ou les convertir d'une manière ou d'une autre. (Cette variable n'est applicable que si la variable 'concurrentprobes' est définie dans la section 'General'.)

Exemple de valeur : 300

Variables spécifiques à la cible supportées :

/^influx_.+/
Il s'agit d'une étiquette qui sera envoyée à influxdb et qui n'a aucun impact sur la mesure de la sonde. Le nom de l'étiquette sera envoyé sans le préfixe « influx_ », qui sera remplacé par « tag_ ». Les étiquettes peuvent être utilisées pour le filtrage.

Exemple de valeur : influx_location = Au sous-sol

greeting
Chaîne de salutation à envoyer au serveur SSH. Elle apparaîtra dans le journal. Utilisez-la pour indiquer clairement qui vous êtes et ce que vous faites afin d'éviter toute confusion.

N'utilisez pas non plus quelque chose qui est une chaîne de version valide. Cette sonde suppose que la connexion est terminée en raison d'une incompatibilité de protocole.

Valeur par défaut : SSH-Latency-Measurement-Sorry-for-this-logmessage

interval
L'intervalle à mesurer. L'un des éléments suivants :
connect
Intervalle entre connect() et le message de salutation de l'hôte.
established
Intervalle entre notre message de salutation et la fin de la connexion en raison d'une incompatibilité de protocole. C'est la valeur par défaut.
complete
De connect() à la fin de la connexion.

Valeur par défaut : established

mininterval
Intervalle minimum entre le début de deux tentatives de connexion en secondes (potentiellement fractionnaires).

Valeur par défaut : 0.5

pings
Combien de pings doivent être envoyés à chaque cible, si différent de la valeur globale spécifiée dans la section Database. Notez que le nombre de pings dans les fichiers RRD est fixe lors de leur génération initiale, et si vous modifiez ce paramètre par la suite, vous devrez supprimer les anciens fichiers RRD ou les convertir d'une manière ou d'une autre.

Exemple de valeur : 5

port
Se connecter à ce port.

Valeur par défaut : 22

timeout
Délai d'attente pour la connexion.

Valeur par défaut : 5
