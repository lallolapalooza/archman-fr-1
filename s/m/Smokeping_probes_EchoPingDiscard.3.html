NOM

Smokeping::probes::EchoPingDiscard - une sonde echoping(1) pour SmokePing

APERÇU

Mesure les temps de réponse aller-retour TCP ou UDP discard (port 9) pour SmokePing.

SYNTAXE

*** Probes ***
+EchoPingDiscard
binary = /usr/bin/echoping
forks = 5
offset = 50%
step = 300
# Les variables suivantes peuvent être remplacées dans chaque section cible
/^influx_.+/ = influx_location = Dans le sous-sol
extraopts = -une-lettre-a-laquelle-l-auteur-n-a-pas-pense
fill = A
ipversion = 4
pings = 5
priority = 6
size = 510
timeout = 1
tos = 0xa0
udp = no
waittime = 1
# [...]
*** Targets ***
probe = EchoPingDiscard # si c'est la sonde par défaut
# [...]
+ mytarget
# probe = EchoPingDiscard # si la sonde par défaut est autre chose
host = my.host
/^influx_.+/ = influx_location = Dans le sous-sol
extraopts = -une-lettre-a-laquelle-l-auteur-n-a-pas-pense
fill = A
ipversion = 4
pings = 5
priority = 6
size = 510
timeout = 1
tos = 0xa0
udp = no
waittime = 1

VARIABLES

Variables spécifiques à la sonde supportées :

binary
L'emplacement de votre binaire echoping.

Valeur par défaut : /usr/bin/echoping

forks
Exécuter ce nombre de processus simultanés au maximum

Exemple de valeur : 5

Valeur par défaut : 5

offset
Si vous exécutez de nombreuses sondes simultanément, vous voudrez peut-être éviter qu'elles n'atteignent votre réseau en même temps. En utilisant le paramètre d'offset spécifique à la sonde, vous pouvez modifier le moment où chaque sonde sera exécutée. L'offset est spécifié en % de l'intervalle total, ou alternativement comme 'random', et l'offset de la section 'General' est utilisé si rien n'est spécifié ici. Notez que cela n'affecte PAS les rrds eux-mêmes, il s'agit simplement d'une question de quand l'acquisition des données est initiée. (Cette variable n'est applicable que si la variable 'concurrentprobes' est définie dans la section 'General'.)

Exemple de valeur : 50%

step
Durée de l'intervalle de base que cette sonde doit utiliser, si elle est différente de celle spécifiée dans la section 'Database'. Notez que le pas dans les fichiers RRD est fixe lors de leur génération initiale, et si vous changez le paramètre de pas par la suite, vous devrez supprimer les anciens fichiers RRD ou les convertir d'une manière ou d'une autre. (Cette variable n'est applicable que si la variable 'concurrentprobes' est définie dans la section 'General'.)

Exemple de valeur : 300

Variables spécifiques à la cible supportées :

/^influx_.+/
Il s'agit d'une balise qui sera envoyée à influxdb et qui n'a aucun impact sur la mesure de la sonde. Le nom de la balise sera envoyé sans le préfixe "influx_", qui sera remplacé par "tag_" à la place. Les balises peuvent être utilisées pour le filtrage.

Exemple de valeur : influx_location = Dans le sous-sol

extraopts
Toutes les options supplémentaires spécifiées ici seront passées sans modification à echoping(1).

Exemple de valeur : -une-lettre-a-laquelle-l-auteur-n-a-pas-pense

fill
L'option "-f" de echoping(1).

Exemple de valeur : A

ipversion
Le protocole IP utilisé. Les valeurs possibles sont "4" et "6". Passé à echoping(1) comme options "-4" ou "-6".

Exemple de valeur : 4

pings
Combien de pings doivent être envoyés à chaque cible, si cela est différent de la valeur globale spécifiée dans la section Database. Notez que le nombre de pings dans les fichiers RRD est fixe lors de leur génération initiale, et si vous changez ce paramètre par la suite, vous devrez supprimer les anciens fichiers RRD ou les convertir d'une manière ou d'une autre.

Exemple de valeur : 5

priority
L'option "-p" de echoping(1).

Exemple de valeur : 6

size
L'option "-s" de echoping(1).

Exemple de valeur : 510

timeout
L'option "-t" de echoping(1).

Exemple de valeur : 1

Valeur par défaut : 5

tos
L'option "-P" de echoping(1).

Exemple de valeur : 0xa0

udp
L'option "-u" de echoping(1). Les valeurs autres que '0' et 'no' activent l'UDP.

Exemple de valeur : no

waittime
L'option "-w" de echoping(1).

Exemple de valeur : 1
