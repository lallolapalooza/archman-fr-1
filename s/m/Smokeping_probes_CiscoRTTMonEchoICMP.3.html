NOM

Smokeping::probes::CiscoRTTMonEchoICMP - Sonde pour SmokePing

SYNOPIS

*** Sondes ***
+CiscoRTTMonEchoICMP
forks = 5
offset = 50%
step = 300
timeout = 15
# Les variables suivantes peuvent être remplacées dans chaque section de cible
/^influx_.+/ = influx_location = Dans le sous-sol
ioshost = RTTcommunity@Myrouter.foobar.com.au # obligatoire
iosint = 10.33.22.11
packetsize = 56
pings = 5
timeout = 15
tos = 160
vrf = INTERNET
# [...]
*** Cibles ***
probe = CiscoRTTMonEchoICMP # si c'est la sonde par défaut
# [...]
+ maCible
# probe = CiscoRTTMonEchoICMP # si la sonde par défaut est autre
host = mon.host
/^influx_.+/ = influx_location = Dans le sous-sol
ioshost = RTTcommunity@Myrouter.foobar.com.au # obligatoire
iosint = 10.33.22.11
packetsize = 56
pings = 5
timeout = 15
tos = 160
vrf = INTERNET

DESCRIPTION

Une sonde pour smokeping, qui utilise les fonctionnalités MIB ciscoRttMon ("Service Assurance Agent", "SAA") de Cisco IOS pour mesurer les temps d'aller-retour d'écho ICMP ("ping") entre un routeur Cisco et toute adresse IP.

VARIABLES

Variables spécifiques à la sonde supportées :

forks
Exécuter ce nombre de processus simultanés au maximum

Exemple de valeur : 5

Valeur par défaut : 5

offset
Si vous exécutez plusieurs sondes simultanément, vous voudrez peut-être éviter qu'elles n'atteignent votre réseau en même temps. En utilisant le paramètre d'offset spécifique à la sonde, vous pouvez modifier le moment où chaque sonde sera exécutée. L'offset est spécifié en % de l'intervalle total, ou alternativement comme 'random', et l'offset de la section 'General' est utilisé si rien n'est spécifié ici. Notez que cela n'influence PAS les RRD, il s'agit simplement du moment où l'acquisition de données est initiée. (Cette variable n'est applicable que si la variable 'concurrentprobes' est définie dans la section 'General'.)

Exemple de valeur : 50%

step
Durée de l'intervalle de base que cette sonde doit utiliser, si différent de celui spécifié dans la section 'Database'. Notez que le pas dans les fichiers RRD est fixe lorsqu'ils sont générés à l'origine, et si vous changez le paramètre de pas par la suite, vous devrez supprimer les anciens fichiers RRD ou les convertir d'une manière ou d'une autre. (Cette variable n'est applicable que si la variable 'concurrentprobes' est définie dans la section 'General'.)

Exemple de valeur : 300

timeout
Combien de temps prend un 'ping' unique au maximum

Exemple de valeur : 15

Valeur par défaut : 5

Variables spécifiques à la cible supportées :

/^influx_.+/
Ceci est une étiquette qui sera envoyée à influxdb et n'a aucun impact sur la mesure de la sonde. Le nom de l'étiquette sera envoyé sans le préfixe "influx_", qui sera remplacé par "tag_" à la place. Les étiquettes peuvent être utilisées pour le filtrage.

Exemple de valeur : influx_location = Dans le sous-sol

ioshost
Le paramètre (obligatoire) ioshost spécifie le routeur Cisco, qui exécutera les pings, ainsi que la chaîne de communauté SNMP sur le routeur.

Exemple de valeur : RTTcommunity@Myrouter.foobar.com.au

Ce paramètre est obligatoire.

iosint
Le paramètre (facultatif) iosint est l'adresse source pour les pings envoyés. Il devrait s'agir d'une des adresses IP actives (!) du routeur pour obtenir des résultats. IOS recherche l'adresse de l'hôte cible dans la table de routage et utilise ensuite les interfaces qui y sont listées pour envoyer les paquets ping. Par défaut, IOS utilise l'adresse IP (principale) de l'interface d'envoi comme adresse source pour un ping. Les versions MIB RTTMon antérieures à IOS 12.0(3)T ne supportaient pas ce paramètre.

Exemple de valeur : 10.33.22.11

packetsize
Le paramètre packetsize vous permet de configurer la taille des paquets pour les pings envoyés. Le minimum est 8, le maximum 16392. Utilisez le même nombre qu'avec fping, si vous voulez que les mêmes tailles de paquets soient utilisées sur le réseau.

Valeur par défaut : 56

pings
Combien de pings doivent être envoyés à chaque cible, si différent de la valeur globale spécifiée dans la section Database. Notez que le nombre de pings dans les fichiers RRD est fixe lorsqu'ils sont générés à l'origine, et si vous changez ce paramètre par la suite, vous devrez supprimer les anciens fichiers RRD ou les convertir d'une manière ou d'une autre.

Exemple de valeur : 5

timeout
Combien de temps un 'ping' RTTMonEcho ICMP unique prend au maximum plus 10 secondes de marge. Puisque nous contrôlons notre propre timeout, le seul but de ceci est de ne pas être supprimé par la méthode ping de basefork.

Exemple de valeur : 15

Valeur par défaut : 15

tos
Le paramètre (facultatif) tos spécifie la valeur de l'octet ToS dans l'en-tête IP des pings. Multipliez les valeurs DSCP par 4 et les valeurs de précedence par 32 pour calculer les valeurs ToS à configurer, par ex. ToS 160 correspond à une valeur DSCP de 40 et une valeur de précedence de 5. Les versions MIB RTTMon antérieures à IOS 12.0(3)T ne supportaient pas ce paramètre.

Exemple de valeur : 160

Valeur par défaut : 0

vrf
Le nom VPN dans lequel l'opération RTT sera utilisée. Pour une opération RTT régulière, ce champ ne doit pas être configuré. L'agent utilisera ce champ pour identifier la table de routage VPN pour cette opération.

Exemple de valeur : INTERNET

NOTES

VERSIONS IOS

Il est fortement recommandé d'utiliser cette sonde avec des routeurs exécutant IOS 12.0(3)T ou supérieur et de la tester d'abord sur des routeurs moins critiques. J'ai réussi à faire planter un routeur avec 12.0(9) de manière assez cohérente (dans la terminologie IOS, 12.0(9) est plus ancien que 12.0(3)T). Je n'ai pas observé de plantages sur des versions IOS plus récentes, mais des messages sur le routeur comme celui ci-dessous, lorsque plusieurs processus accédaient simultanément au même routeur (cas de IOS 12.1(12b)) :

Aug 20 07:30:14: %RTT-3-SemaphoreBadUnlock: %RTR: Attempt to unlock semaphore by wrong RTR process 70, locked by 78

Aug 20 07:35:15: %RTT-3-SemaphoreInUse: %RTR: Could not obtain a lock for RTR. Process 80

INSTALLATION

Pour installer cette sonde, copiez les fichiers ciscoRttMonMIB.pm dans ($SMOKEPINGINSTALLDIR)/lib/Smokeping et CiscoRTTMonEchoICMP.pm dans ($SMOKEPINGINSTALLDIR)/lib/Smokeping/probes. Une version V0.97 ou supérieure de SNMP_Session.pm de Simon Leinen est requise.

Le(s) routeur(s) doit/doivent être configuré(s) pour autoriser l'accès SNMP en lecture/écriture. Suffisant est :

snmp-server community RTTCommunity RW

Si vous souhaitez être un peu plus restrictif avec l'accès en écriture SNMP au routeur, envisagez de configurer quelque chose comme ceci

access-list 2 permit 10.37.3.5
snmp-server view RttMon ciscoRttMonMIB included
snmp-server community RTTCommunity view RttMon RW 2

La configuration ci-dessus accorde l'accès SNMP en lecture/écriture uniquement à 10.37.3.5 (l'hôte smokeping) et uniquement à l'arborescence MIB ciscoRttMon. La sonde n'a pas besoin d'accéder aux variables SNMP en dehors de l'arborescence RttMon.

BOGUES

La sonde envoie des pings inutiles, c'est-à-dire plus que ce qui est configuré dans la variable "pings", car la MIB RTTMon ne permet de définir qu'un temps total pour tous les pings lors d'une course de mesure (une "vie"). Actuellement, la sonde définit la durée de vie à "pings"*5+3 secondes (5 secondes étant la valeur de timeout ping codée en dur dans cette sonde).
