NOM

Smokeping::probes::basefork - Une autre classe de base pour implémenter les sondes SmokePing

APERÇU

Comme Smokeping::probes::basevars, mais supporte la propriété spécifique à la sonde `forks' pour déterminer combien de processus doivent être exécutés simultanément. Les cibles sont pinguées une par une, et le nombre de pings envoyés peut varier entre les cibles.

SYNTAXE

*** Probes ***
+basefork
forks = 5
offset = 50%
step = 300
timeout = 15
# Les variables suivantes peuvent être remplacées dans chaque section cible
/^influx_.+/ = influx_location = Dans le sous-sol
pings = 5
# [...]
*** Targets ***
probe = basefork # si c'est la sonde par défaut
# [...]
+ ma_cible
# probe = basefork # si la sonde par défaut est autre
host = mon.host
/^influx_.+/ = influx_location = Dans le sous-sol
pings = 5

DESCRIPTION

Tous les programmes de ping ne prennent pas en charge le test de plusieurs hôtes en une seule fois comme fping(1). Si la mesure prend suffisamment de temps, il se peut qu'il n'y ait pas assez de temps pour effectuer tous les tests dans le délai imparti. Par exemple, si le test prend 30 secondes, la mesure de dix hôtes remplit déjà l'étape par défaut de cinq minutes de SmokePing.

Ainsi, il peut être nécessaire d'effectuer certains tests simultanément. Ce module définit la méthode ping qui crée un fork du nombre de processus simultanés demandé et appelle la méthode pingone que les classes dérivées doivent fournir.

La méthode pingone est appelée avec un argument : une table contenant la cible à mesurer. Le contenu de la table est décrit dans Smokeping::probes::basevars(3pm).

Le nombre de processus simultanés est déterminé par la variable spécifique à la sonde `forks' et est de 5 par défaut. S'il y a plus de cibles que cette valeur, une autre série de forks est effectuée après la fin des premiers processus. Ceci continue jusqu'à ce que toutes les cibles aient été testées.

Le délai d'expiration dans lequel chaque enfant doit terminer est fixé à 5 secondes multipliées par le nombre maximum de 'pings' des cibles. Vous pouvez définir différemment le délai d'expiration de base si vous le souhaitez, en utilisant la propriété `timeout` de la sonde dans le fichier de configuration maître (cela sera à nouveau multiplié par le nombre maximum de pings). La sonde elle-même peut également fournir une autre valeur par défaut si désiré en modifiant la valeur _default de la variable `timeout`.

Si l'enfant ne termine pas à l'expiration du délai, il sera tué ainsi que tous les processus qu'il a démarrés.

Le nombre de pings envoyés peut être spécifié dans la variable spécifique à la cible 'pings'.

VARIABLES

Variables spécifiques à la sonde prises en charge :

forks
Exécute ce nombre de processus simultanés au maximum

Exemple de valeur : 5

Valeur par défaut : 5

offset
Si vous exécutez de nombreuses sondes simultanément, vous voudrez peut-être éviter qu'elles n'atteignent votre réseau en même temps. En utilisant le paramètre `offset` spécifique à la sonde, vous pouvez modifier le moment où chaque sonde sera exécutée. L'`offset` est spécifié en % de l'intervalle total, ou alternativement comme 'random', et l'`offset` de la section `General` est utilisé si rien n'est spécifié ici. Notez que cela n'affecte PAS les rrds eux-mêmes, il s'agit simplement d'une question de moment où l'acquisition des données est initiée. (Cette variable n'est applicable que si la variable `concurrentprobes` est définie dans la section `General`.)

Exemple de valeur : 50%

step
Durée de l'intervalle de base que cette sonde doit utiliser, si elle est différente de celle spécifiée dans la section `Database`. Notez que le `step` dans les fichiers RRD est fixe lorsqu'ils sont générés à l'origine, et si vous modifiez le paramètre `step` par la suite, vous devrez supprimer les anciens fichiers RRD ou les convertir d'une manière ou d'une autre. (Cette variable n'est applicable que si la variable `concurrentprobes` est définie dans la section `General`.)

Exemple de valeur : 300

timeout
Combien de temps prend un seul 'ping' au maximum

Exemple de valeur : 15

Valeur par défaut : 5

Variables spécifiques à la cible prises en charge :

/^influx_.+/
Ceci est une étiquette qui sera envoyée à influxdb et n'a aucun impact sur la mesure de la sonde. Le nom de l'étiquette sera envoyé sans le préfixe "influx_", qui sera remplacé par "tag_" à la place. Les étiquettes peuvent être utilisées pour le filtrage.

Exemple de valeur : influx_location = Dans le sous-sol

pings
Combien de pings doivent être envoyés à chaque cible, si cela diffère de la valeur globale spécifiée dans la section `Database`. Notez que le nombre de pings dans les fichiers RRD est fixe lorsqu'ils sont générés à l'origine, et si vous modifiez ce paramètre par la suite, vous devrez supprimer les anciens fichiers RRD ou les convertir d'une manière ou d'une autre.

Exemple de valeur : 5
