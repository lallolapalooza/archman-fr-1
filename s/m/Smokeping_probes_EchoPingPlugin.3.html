NOM

Smokeping::probes::EchoPingPlugin - une base pour utiliser les plugins d'echoping(1) comme sondes pour SmokePing

APERÇU

Mesure les temps aller-retour pour SmokePing avec un plugin echoping(1). Les plugins actuellement fournis avec echoping sont implémentés comme des sondes distinctes basées sur cette classe, mais la classe peut également être utilisée directement.

SYNTAXE

*** Sondes ***
+EchoPingPlugin
binary = /usr/bin/echoping
forks = 5
offset = 50%
step = 300
# Les variables suivantes peuvent être remplacées dans chaque section de cible
/^influx_.+/ = influx_location = Dans le sous-sol
extraopts = -une-lettre-que-l-auteur-n-a-pas-pensé-à
ipversion = 4
pings = 5
plugin = random # obligatoire
pluginargs = -p argument_spécifique_plugin
priority = 6
timeout = 1
tos = 0xa0
waittime = 1
# [...]
*** Cibles ***
probe = EchoPingPlugin # si ceci doit être la sonde par défaut
# [...]
+ ma_cible
# probe = EchoPingPlugin # si la sonde par défaut est autre chose
host = mon.hote
/^influx_.+/ = influx_location = Dans le sous-sol
extraopts = -une-lettre-que-l-auteur-n-a-pas-pensé-à
ipversion = 4
pings = 5
plugin = random # obligatoire
pluginargs = -p argument_spécifique_plugin
priority = 6
timeout = 1
tos = 0xa0
waittime = 1

VARIABLES

Variables spécifiques à la sonde supportées :

binary
L'emplacement de votre binaire echoping.

Valeur par défaut : /usr/bin/echoping

forks
Exécuter ce nombre de processus simultanés au maximum

Exemple de valeur : 5

Valeur par défaut : 5

offset
Si vous exécutez de nombreuses sondes simultanément, vous voudrez peut-être éviter qu'elles ne frappent votre réseau en même temps. En utilisant le paramètre d'offset spécifique à la sonde, vous pouvez modifier le point dans le temps où chaque sonde sera exécutée. L'offset est spécifié en % de l'intervalle total, ou alternativement comme 'random', et l'offset de la section 'General' est utilisé si rien n'est spécifié ici. Notez que cela n'influence PAS les rrds eux-mêmes, c'est juste une question de savoir quand l'acquisition des données est initiée. (Cette variable n'est applicable que si la variable 'concurrentprobes' est définie dans la section 'General'.)

Exemple de valeur : 50%

step
Durée de l'intervalle de base que cette sonde doit utiliser, si différent de celui spécifié dans la section 'Database'. Notez que le pas dans les fichiers RRD est fixe lorsqu'ils sont générés à l'origine, et si vous modifiez le paramètre step par la suite, vous devrez supprimer les anciens fichiers RRD ou les convertir d'une manière ou d'une autre. (Cette variable n'est applicable que si la variable 'concurrentprobes' est définie dans la section 'General'.)

Exemple de valeur : 300

Variables spécifiques à la cible supportées :

/^influx_.+/
Ceci est une étiquette qui sera envoyée à influxdb et n'a aucun impact sur la mesure de la sonde. Le nom de l'étiquette sera envoyé sans le préfixe "influx_", qui sera remplacé par "tag_" à la place. Les étiquettes peuvent être utilisées pour le filtrage.

Exemple de valeur : influx_location = Dans le sous-sol

extraopts
Toutes les options supplémentaires spécifiées ici seront passées sans modification à echoping(1).

Exemple de valeur : -une-lettre-que-l-auteur-n-a-pas-pensé-à

ipversion
Le protocole IP utilisé. Les valeurs possibles sont "4" et "6". Passé à echoping(1) en tant qu'options "-4" ou "-6".

Exemple de valeur : 4

pings
Combien de pings doivent être envoyés à chaque cible, si différent de la valeur globale spécifiée dans la section Database. Notez que le nombre de pings dans les fichiers RRD est fixe lorsqu'ils sont générés à l'origine, et si vous modifiez ce paramètre par la suite, vous devrez supprimer les anciens fichiers RRD ou les convertir d'une manière ou d'une autre.

Exemple de valeur : 5

plugin
Le plugin echoping qui sera utilisé. Voir echoping(1) pour les détails. Ceci peut être soit le nom du plugin, soit un chemin complet vers l'objet partagé du plugin.

Exemple de valeur : random

Ce paramètre est obligatoire.

pluginargs
Tous les arguments supplémentaires nécessaires au plugin echoping spécifié avec la variable pluginname. Ceux-ci sont généralement fournis par la sonde dérivée.

Exemple de valeur : -p argument_spécifique_plugin

priority
L'option "-p" de echoping(1).

Exemple de valeur : 6

timeout
L'option "-t" de echoping(1).

Exemple de valeur : 1

Valeur par défaut : 5

tos
L'option "-P" de echoping(1).

Exemple de valeur : 0xa0

waittime
L'option "-w" de echoping(1).

Exemple de valeur : 1

AUTEURS

Niko Tyni <ntyni@iki.fi>

NOTES

Les variables fill, size et udp de EchoPing ne sont pas valides par défaut pour les sondes dérivées de EchoPingPlugin.

Les plugins sont disponibles à partir de la version 6 d'echoping.
