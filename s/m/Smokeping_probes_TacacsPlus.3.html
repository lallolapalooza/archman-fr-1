NOM

Smokeping::probes::TacacsPlus - une sonde d'authentification TacacsPlus pour SmokePing

APERÇU

Mesure la latence d'authentification TacacsPlus pour SmokePing

SYNTAXE

*** Sondes ***
+TacacsPlus
forks = 5
offset = 50%
passwordfile = /quelque/part/secret
secretfile = /un/autre/endroit/secret
step = 300
# Les variables suivantes peuvent être surchargées dans chaque section de cible
/^influx_.+/ = influx_location = Dans la cave
authtype = CHAP
mininterval = 1
password = motdepasse-test
pings = 5
port = 49
secret = secret-test
timeout = 5
username = utilisateur-test # obligatoire
# [...]
*** Cibles ***
probe = TacacsPlus # si c'est la sonde par défaut
# [...]
+ ma-cible
# probe = TacacsPlus # si la sonde par défaut est autre chose
host = mon.hote
/^influx_.+/ = influx_location = Dans la cave
authtype = CHAP
mininterval = 1
password = motdepasse-test
pings = 5
port = 49
secret = secret-test
timeout = 5
username = utilisateur-test # obligatoire

DESCRIPTION

Cette sonde mesure la latence d'authentification TacacsPlus pour SmokePing.

Le nom d'utilisateur à tester est spécifié dans la variable `username' spécifique à la sonde ou à la cible, celle de la cible ayant la priorité sur celle de la sonde.

Le mot de passe peut être spécifié soit (par ordre de priorité, le dernier remplaçant le précédent) dans la variable `password' spécifique à la sonde, dans un fichier externe ou dans la variable `password' spécifique à la cible. L'emplacement de ce fichier est donné par la variable `passwordfile' spécifique à la sonde. Voir Smokeping::probes::passwordchecker(3pm) pour le format de ce fichier (résumé : triplets séparés par deux-points de la forme `<hote>:<nom_utilisateur>:<mot_de_passe>')

Le protocole TacacsPlus nécessite un secret partagé entre le serveur et le client. Ce secret peut être spécifié soit (par ordre de priorité, le dernier remplaçant le précédent) dans la variable `secret' spécifique à la sonde, dans un fichier externe ou dans la variable `secret' spécifique à la cible. Ce fichier externe est localisé par la variable `secretfile' spécifique à la sonde, et il doit contenir des paires séparées par des espaces de la forme `<hote> <secret>'. Les commentaires et les lignes blanches sont acceptés.

Le type d'authentification TacacsPlus par défaut est ASCII. PAP et CHAP sont également disponibles. Voir la documentation de Authen::TacacsPlus pour plus d'informations ;

La sonde essaie d'être gentille avec le serveur et n'envoie pas de requêtes d'authentification plus fréquemment qu'une fois toutes les X secondes, où X est la valeur de la variable "min_interval" spécifique à la cible (1 par défaut).

VARIABLES

Variables spécifiques à la sonde prises en charge :

forks
Exécuter ce nombre de processus concurrents au maximum

Exemple de valeur : 5

Valeur par défaut : 5

offset
Si vous exécutez de nombreuses sondes simultanément, vous voudrez peut-être éviter qu'elles ne frappent votre réseau toutes en même temps. En utilisant le paramètre d'offset spécifique à la sonde, vous pouvez modifier le moment où chaque sonde sera exécutée. L'offset est spécifié en % de l'intervalle total, ou alternativement comme 'random', et l'offset de la section 'General' est utilisé si rien n'est spécifié ici. Notez que cela n'influence PAS les rrd eux-mêmes, il s'agit simplement de savoir quand l'acquisition des données est initiée. (Cette variable n'est applicable que si la variable 'concurrentprobes' est définie dans la section 'General'.)

Exemple de valeur : 50%

passwordfile
Emplacement du fichier contenant les noms d'utilisateur et les mots de passe.

Exemple de valeur : /quelque/part/secret

secretfile
Un fichier contenant les secrets partagés TacacsPlus pour les cibles. Il doit contenir des paires séparées par des espaces de la forme `<hote> <secret>'. Les commentaires et les lignes blanches sont acceptés.

Exemple de valeur : /un/autre/endroit/secret

step
Durée de l'intervalle de base que cette sonde doit utiliser, si différent de celui spécifié dans la section 'Database'. Notez que le pas dans les fichiers RRD est fixe lors de leur génération initiale, et si vous changez le paramètre step par la suite, vous devrez supprimer les anciens fichiers RRD ou les convertir d'une manière ou d'une autre. (Cette variable n'est applicable que si la variable 'concurrentprobes' est définie dans la section 'General'.)

Exemple de valeur : 300

Variables spécifiques à la cible prises en charge :

/^influx_.+/
Ceci est une balise qui sera envoyée à influxdb et n'aura aucun impact sur la mesure de la sonde. Le nom de la balise sera envoyé sans le préfixe "influx_", qui sera remplacé par "tag_" à la place. Les balises peuvent être utilisées pour le filtrage.

Exemple de valeur : influx_location = Dans la cave

authtype
Le type d'authentification TacacsPlus : ASCII (par défaut), CHAP, PAP

Exemple de valeur : CHAP

Valeur par défaut : ASCII

mininterval
L'intervalle minimum entre chaque requête d'authentification envoyée, en secondes (potentiellement fractionnaires).

Valeur par défaut : 1

password
Le mot de passe de l'utilisateur, s'il n'est pas présent dans le fichier de mots de passe.

Exemple de valeur : motdepasse-test

pings
Combien de pings doivent être envoyés à chaque cible, si différent de la valeur globale spécifiée dans la section Database. Notez que le nombre de pings dans les fichiers RRD est fixe lors de leur génération initiale, et si vous changez ce paramètre par la suite, vous devrez supprimer les anciens fichiers RRD ou les convertir.

Exemple de valeur : 5

port
Le port TacacsPlus à utiliser

Exemple de valeur : 49

Valeur par défaut : 49

secret
Le secret partagé TacacsPlus pour la cible, s'il n'est pas présent dans le fichier de secrets.

Exemple de valeur : secret-test

timeout
Timeout en secondes pour les requêtes TacacsPlus.

Valeur par défaut : 5

username
Le nom d'utilisateur à tester.

Exemple de valeur : utilisateur-test

Ce paramètre est obligatoire.
