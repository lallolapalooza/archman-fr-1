NOM

Smokeping::probes::IOSPing - Sonde IOS Cisco pour SmokePing

SYNOPSIS

*** Sondes ***
+IOSPing
binary = /usr/bin/rsh # obligatoire
forks = 5
offset = 50%
packetsize = 56
step = 300
timeout = 15
# Les variables suivantes peuvent être remplacées dans chaque section cible
/^influx_.+/ = influx_location = Au sous-sol
ioshost = mon.routeur.cisco # obligatoire
iosint = Ethernet 1/0
iosuser = admin
pings = 5
# [...]
*** Cibles ***
probe = IOSPing # si c'est la sonde par défaut
# [...]
+ ma_cible
# probe = IOSPing # si la sonde par défaut est autre chose
host = mon.hote
/^influx_.+/ = influx_location = Au sous-sol
ioshost = mon.routeur.cisco # obligatoire
iosint = Ethernet 1/0
iosuser = admin
pings = 5

DESCRIPTION

Intègre Cisco IOS comme sonde dans smokeping. Utilise le protocole rsh / remsh pour exécuter un ping depuis un appareil IOS.

VARIABLES

Variables spécifiques à la sonde supportées :

binary
L'option binary spécifie le chemin du binaire à utiliser pour se connecter à l'appareil IOS. Les binaires couramment utilisés sont /usr/bin/rsh et /usr/bin/remsh, bien que tout script ou binaire devrait fonctionner s'il peut être appelé comme 
/chemin/vers/binaire [ -l utilisateur ] routeur ping

pour produire le dialogue de ping IOS sur stdin & stdout.

Exemple de valeur : /usr/bin/rsh

Ce réglage est obligatoire.

forks
Exécute ce nombre de processus concurrents au maximum.

Exemple de valeur : 5

Valeur par défaut : 5

offset
Si vous exécutez de nombreuses sondes simultanément, vous voudrez peut-être éviter qu'elles n'atteignent votre réseau en même temps. En utilisant le paramètre offset spécifique à la sonde, vous pouvez modifier le moment où chaque sonde sera exécutée. Offset est spécifié en % de l'intervalle total, ou alternativement comme 'random', et l'offset de la section 'General' est utilisé si rien n'est spécifié ici. Notez que cela n'influence PAS les fichiers RRD eux-mêmes, il s'agit simplement du moment où l'acquisition des données est initiée. (Cette variable n'est applicable que si la variable concurrentprobes est définie dans la section 'General'.)

Exemple de valeur : 50%

packetsize
L'option (optionnelle) packetsize vous permet de configurer la taille des paquets pour les pings envoyés.

Valeur par défaut : 56

step
Durée de l'intervalle de base que cette sonde doit utiliser, si différente de celle spécifiée dans la section 'Database'. Notez que le pas dans les fichiers RRD est fixe lorsqu'ils sont générés à l'origine, et si vous changez le paramètre step par la suite, vous devrez supprimer les anciens fichiers RRD ou les convertir d'une manière ou d'une autre. (Cette variable n'est applicable que si la variable concurrentprobes est définie dans la section 'General'.)

Exemple de valeur : 300

timeout
Combien de temps prend un seul 'ping' au maximum.

Exemple de valeur : 15

Valeur par défaut : 5

Variables spécifiques à la cible supportées :

/^influx.+/
Ceci est une étiquette (tag) qui sera envoyée à influxdb et n'a aucun impact sur la mesure de la sonde. Le nom de l'étiquette sera envoyé sans le préfixe "influx_", qui sera remplacé par "tag_" à la place. Les étiquettes peuvent être utilisées pour le filtrage.

Exemple de valeur : influx_location = Au sous-sol

ioshost
L'option ioshost spécifie l'appareil IOS qui doit être utilisé pour le ping.

Exemple de valeur : mon.routeur.cisco

Ce réglage est obligatoire.

iosint
L'option (optionnelle) iosint vous permet de spécifier l'adresse source ou l'interface dans l'appareil IOS. La valeur doit être une adresse IP ou un nom d'interface tel que "Ethernet 1/0". Si cette option est omise, l'appareil IOS choisira l'adresse IP de l'interface sortante à utiliser.

Exemple de valeur : Ethernet 1/0

iosuser
L'option (optionnelle) iosuser vous permet de spécifier le nom d'utilisateur distant de l'appareil IOS. Si cette option est omise, le nom d'utilisateur sera celui par défaut utilisé par la commande remsh (généralement l'utilisateur exécutant la commande remsh, c'est-à-dire l'utilisateur exécutant SmokePing).

Exemple de valeur : admin

pings
Combien de pings doivent être envoyés à chaque cible, si différent de la valeur globale spécifiée dans la section Database. Notez que le nombre de pings dans les fichiers RRD est fixe lorsqu'ils sont générés à l'origine, et si vous changez ce paramètre par la suite, vous devrez supprimer les anciens fichiers RRD ou les convertir d'une manière ou d'une autre.

Exemple de valeur : 5

NOTES

Configuration IOS

L'appareil IOS doit avoir rsh activé et une confiance appropriée définie, par exemple :

!
ip rcmd rsh-enable
ip rcmd remote-host smoke 192.168.1.2 smoke enable
!

Certains appareils IOS ont un maximum de 5 VTY disponibles, faites donc attention à ne pas atteindre une limite avec la variable forks.

Authentification par mot de passe

Il n'est pas possible d'utiliser l'authentification par mot de passe avec rsh ou remsh en raison de limitations fondamentales du protocole.

Taille des paquets Ping

La page de manuel de FPing dit ceci sur le sujet de la taille des paquets ping :

Nombre d'octets de données ping à envoyer. La taille minimale (normalement 12) laisse de la place pour les données dont fping a besoin pour fonctionner (numéro de séquence, horodatage). La taille des données reçues rapportées inclut l'en-tête IP (normalement 20 octets) et l'en-tête ICMP (8 octets), donc la taille totale minimale est de 40 octets. La valeur par défaut est 56, comme dans ping. Le maximum est la taille maximale théorique du datagramme IP (64 Ko), bien que la plupart des systèmes la limitent à un nombre plus petit et dépendant du système.
