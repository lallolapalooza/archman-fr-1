NAME

Smokeping::probes::SSH - Sonde SSH pour SmokePing

SYNOPSIS

*** Probes ***
+SSH
binary = /usr/bin/ssh-keyscan # obligatoire
forks = 5
init_host = 127.0.0.1
offset = 50%
step = 300
timeout = 15
# Les variables suivantes peuvent être remplacées dans chaque section de cible
/^influx_.+/ = influx_location = Dans le sous-sol
keytype = dsa
pings = 5
port = 5000
ssh_af = 4
# [...]
*** Targets ***
probe = SSH # si c'est la sonde par défaut
# [...]
+ mytarget
# probe = SSH # si la sonde par défaut est autre chose
host = my.host
/^influx_.+/ = influx_location = Dans le sous-sol
keytype = dsa
pings = 5
port = 5000
ssh_af = 4

DESCRIPTION

Intègre ssh-keyscan comme sonde dans smokeping. La variable binary doit pointer vers votre copie du programme ssh-keyscan. S'il n'est pas encore installé sur votre système, vous devriez installer openssh >= 3.8p1

La sonde demande à l'hôte donné n fois sa clé publique, où n est le nombre spécifié dans le fichier de configuration.

Dans le cadre de l'initialisation, la sonde demande à 127.0.0.1 sa clé publique et tente d'analyser la sortie. Ceci est fait pour s'assurer que la binairessh-keyscan spécifiée fournit une sortie dans le format attendu, avant de s'y fier. Assurez-vous que SSH est également en cours d'exécution sur localhost, ou spécifiez une cible init_host alternative à tester, qui est censée être disponible lors de tout redémarrage de smokeping.

VARIABLES

Variables spécifiques à la sonde supportées :

binary
L'emplacement de votre binaire ssh-keyscan.

Exemple de valeur : /usr/bin/ssh-keyscan

Ce paramètre est obligatoire.

forks
Exécute ce nombre de processus simultanés au maximum

Exemple de valeur : 5

Valeur par défaut : 5

init_host
Hôte à utiliser pour l'initialisation, par défaut l'hôte local IPv4 127.0.0.1

Exemple de valeur : 127.0.0.1

Valeur par défaut : 127.0.0.1

offset
Si vous exécutez de nombreuses sondes simultanément, vous voudrez peut-être éviter qu'elles ne frappent votre réseau toutes en même temps. En utilisant le paramètre offset spécifique à la sonde, vous pouvez changer le moment où chaque sonde sera exécutée. L'offset est spécifié en % de l'intervalle total, ou alternativement comme 'random', et l'offset de la section 'General' est utilisé si rien n'est spécifié ici. Notez que cela n'affecte PAS les rrds eux-mêmes, il s'agit simplement de la manière dont l'acquisition des données est initiée. (Cette variable n'est applicable que si la variable 'concurrentprobes' est définie dans la section 'General'.)

Exemple de valeur : 50%

step
Durée de l'intervalle de base que cette sonde doit utiliser, s'il est différent de celui spécifié dans la section 'Database'. Notez que le pas dans les fichiers RRD est fixe lors de leur génération initiale, et si vous changez le paramètre step par la suite, vous devrez supprimer les anciens fichiers RRD ou les convertir d'une manière ou d'une autre. (Cette variable n'est applicable que si la variable 'concurrentprobes' est définie dans la section 'General'.)

Exemple de valeur : 300

timeout
Combien de temps prend un seul 'ping' au maximum

Exemple de valeur : 15

Valeur par défaut : 5

Variables spécifiques à la cible supportées :

/^influx_.+/
Ceci est une étiquette qui sera envoyée à influxdb et n'a aucun impact sur la mesure de la sonde. Le nom de l'étiquette sera envoyé sans le préfixe "influx_", qui sera remplacé par "tag_". Les étiquettes peuvent être utilisées pour le filtrage.

Exemple de valeur : influx_location = Dans le sous-sol

keytype
Type de clé, utilisé dans ssh-keyscan -t keytype

Exemple de valeur : dsa

Valeur par défaut : rsa

pings
Combien de pings doivent être envoyés à chaque cible, s'il est différent de la valeur globale spécifiée dans la section Database. Notez que le nombre de pings dans les fichiers RRD est fixe lors de leur génération initiale, et si vous changez ce paramètre par la suite, vous devrez supprimer les anciens fichiers RRD ou les convertir d'une manière ou d'une autre.

Exemple de valeur : 5

port
Port à utiliser lors du test de la connexion SSH -p port

Exemple de valeur : 5000

Valeur par défaut : 22

ssh_af
Famille d'adresses (IPv4/IPV6) à utiliser lors du test de la connexion SSH, spécifiez 4 ou 6. Spécifiez 0 pour revenir à la préférence système par défaut, au lieu d'hériter de la valeur des sections parentes.

Exemple de valeur : 4

Valeur par défaut : 0
