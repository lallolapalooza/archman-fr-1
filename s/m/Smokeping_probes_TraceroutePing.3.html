NAME

Smokeping::probes::TraceroutePing - Utiliser traceroute pour obtenir le RTT pour un routeur

SYNOPSIS

*** Sondes ***
+TraceroutePing
binary = /usr/bin/traceroute # obligatoire
binaryv6 = /usr/bin/traceroute6
forks = 5
offset = 50%
step = 300
timeout = 15
# Les variables suivantes peuvent être écrasées dans chaque section de cible
/^influx_.+/ = influx_location = Dans le sous-sol
desthost = www.example.com # obligatoire
host = www-net-router.example.com # obligatoire
maxttl = 15
minttl = 11
pings = 5
wait = 3
# [...]
*** Cibles ***
probe = TraceroutePing # si c'est la sonde par défaut qui doit être utilisée
# [...]
+ ma cible
# probe = TraceroutePing # si la sonde par défaut est autre chose
host = my.host
/^influx_.+/ = influx_location = Dans le sous-sol
desthost = www.example.com # obligatoire
host = www-net-router.example.com # obligatoire
maxttl = 15
minttl = 11
pings = 5
wait = 3

DESCRIPTION

Intègre traceroute en tant que sonde dans smokeping. L'utilisation de cette sonde est destinée aux passerelles qui ne répondent pas aux paquets TCP/UDP/ICMP qui leur sont adressés, mais qui renvoient des paquets ICMP TTL_EXCEEDED pour les paquets traceroute vers un hôte qu'elles routent. Il est préférable de l'utiliser dans des situations où le routage du chemin est statique ou presque ; l'utilisation dans des réseaux à routage changeant donnera de mauvais résultats. Le meilleur endroit pour utiliser cette sonde est sur les liaisons de premier et dernier kilomètre, qui sont plus susceptibles d'avoir un routage statique et aussi plus susceptibles d'avoir des pare-feux qui ignorent les paquets ICMP ECHO_REQUEST.

La variable obligatoire binary doit contenir le chemin de l'exécutable traceroute.

La variable optionnelle binaryv6 définit un chemin d'exécutable pour votre traceroute IPv6. Si cette variable est définie à la même valeur que binary, TraceroutePing utilisera le drapeau -6 lors de l'exécution de traceroute pour les adresses IPv6. Si cette variable n'est pas définie, TraceroutePing tentera de détecter automatiquement un traceroute IPv6 fonctionnel. Il essaiera d'abord d'ajouter "6" au chemin de binary, puis tentera d'inclure le drapeau "-6" dans une commande de test. Note : Linux semble avoir une grande variété d'implémentations de traceroute IPv6. Ma machine Ubuntu 14.04 a /usr/sbin/traceroute6 d'iputils, mais /usr/bin/traceroute (de Dmitry Butskoy) accepte le drapeau -6 et est en fait une implémentation améliorée. Vous pourriez avoir besoin de permettre à TraceroutePing de le détecter automatiquement, ou d'expérimenter pour trouver le meilleur traceroute.

La variable obligatoire desthost doit nommer un hôte de destination pour la sonde. L'hôte de destination lui-même n'est pas d'intérêt et aucune donnée n'est collectée à son sujet ; son seul but est de rediriger le trafic vers votre cible réelle. Choisir une destination juste après votre cible, avec un routage statique ou préférentiellement dirigée via votre cible, donnera de meilleures données.

La variable obligatoire host doit nommer l'hôte cible pour la sonde. C'est le routeur pour lequel vous voulez collecter le RTT. Cette variable doit être soit le nom DNS inversé valide du routeur, soit son adresse IP. L'utilisation de l'adresse IP est préférable car elle permet à traceroute d'éviter les requêtes DNS.

Les variables de cible minttl et maxttl peuvent être utilisées pour décrire la plage de comptages de sauts attendus vers host. Sur des chemins plus longs ou vers des passerelles non répondantes ou des hôtes non répondants, cela réduit le temps d'exécution de la sonde. Ces valeurs par défaut sont 1 et 30.

La variable wait définit le timeout de la sonde traceroute en secondes. Elle est par défaut à 1, au lieu de la valeur traditionnellement plus élevée utilisée par LBL traceroute. Les programmes traceroute imposent généralement une limite inférieure à cette valeur.

VARIABLES

Variables spécifiques à la sonde :

binary
L'emplacement de votre binaire traceroute.

Exemple de valeur : /usr/bin/traceroute

Cette configuration est obligatoire.

binaryv6
L'emplacement de votre binaire traceroute IPv6.

Exemple de valeur : /usr/bin/traceroute6

forks
Autant de processus concurrents que possible seront exécutés.

Exemple de valeur : 5

Valeur par défaut : 5

offset
Si vous exécutez de nombreuses sondes concurrentes, vous pouvez éviter qu'elles n'arrivent toutes en même temps sur votre réseau. En utilisant le paramètre de sonde spécifique offset, vous pouvez changer le moment où chaque sonde s'exécutera. L'offset est spécifié en % de l'intervalle total, ou alternativement comme 'random', et l'offset de la section 'General' est utilisé si non spécifié ici. Notez que cela n'influence PAS les fichiers RRD, c'est uniquement une question de moment où la collecte de données commence. (Cette variable n'est applicable que si la variable 'concurrentprobes' est définie dans la section 'General'.)

Exemple de valeur : 50%

step
L'intervalle de base que cette sonde devrait utiliser, s'il est différent de celui spécifié dans la section 'Database'. Notez que le pas dans les fichiers RRD est fixe lors de leur génération initiale, et si vous changez ce paramètre par la suite, vous devrez supprimer les anciens fichiers RRD ou les convertir. (Cette variable n'est applicable que si la variable 'concurrentprobes' est définie dans la section 'General'.)

Exemple de valeur : 300

timeout
Le temps maximum qu'un 'ping' prendra.

Exemple de valeur : 15

Valeur par défaut : 5

Variables spécifiques à la cible :

/^influx_.+/
Ceci est une étiquette qui est envoyée à influxdb et n'a aucun impact sur la mesure de la sonde. Le nom de l'étiquette est envoyé sans le préfixe "influx_", qui est remplacé par "tag_". Les étiquettes peuvent être utilisées pour le filtrage.

Exemple de valeur : influx_location = Dans le sous-sol

desthost
La destination finale des paquets traceroute. Il n'est pas nécessaire qu'elle soit joignable, sauf si c'est aussi votre hôte.

Exemple de valeur : www.example.com

Cette configuration est obligatoire.

host
L'hôte d'intérêt à surveiller. Doit être soit le nom d'hôte inversé, soit une adresse IP.

Exemple de valeur : www-net-router.example.com

Cette configuration est obligatoire.

maxttl
Valeur TTL maximale. Définit le nombre maximal de sauts attendus vers l'hôte.

Exemple de valeur : 15

minttl
Valeur TTL minimale. Définit le nombre minimal de sauts attendus vers l'hôte.

Exemple de valeur : 11

pings
Combien de pings doivent être envoyés à chaque cible, si différent de la valeur globale spécifiée dans la section 'Database'. Notez que le nombre de pings dans les fichiers RRD est fixe lors de leur génération initiale, et si vous changez ce paramètre par la suite, vous devrez supprimer les anciens fichiers RRD ou les convertir.

Exemple de valeur : 5

wait
Le temps d'attente. La valeur de timeout pour les sondes traceroute, en secondes.

Exemple de valeur : 3
