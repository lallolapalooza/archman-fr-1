NOM

Smokeping::probes::OpenSSHJunOSPing - Sonde SSH JunOS pour SmokePing

SYNOPSIS

*** Sondes ***
+OpenSSHJunOSPing
forks = 5
offset = 50%
packetsize = 100
step = 300
timeout = 15
tos = 
# Les variables suivantes peuvent être écrasées dans chaque section cible
/^influx_.+/ = influx_location = Dans le sous-sol
junospass = motdepasse # obligatoire
junosuser = utilisateur # obligatoire
pings = 5
psource = 192.168.2.129
source = 192.168.2.1 # obligatoire
# [...]
*** Cibles ***
probe = OpenSSHJunOSPing # si c'est la sonde par défaut
# [...]
+ ma_cible
# probe = OpenSSHJunOSPing # si la sonde par défaut est autre chose
host = mon.hote
/^influx_.+/ = influx_location = Dans le sous-sol
junospass = motdepasse # obligatoire
junosuser = utilisateur # obligatoire
pings = 5
psource = 192.168.2.129
source = 192.168.2.1 # obligatoire

DESCRIPTION

Se connecte à Juniper JunOS via OpenSSH pour exécuter des commandes ping. Cette sonde utilise le « ping étendu » de Juniper JunOS. Vous avez la possibilité de spécifier l'interface d'où provient le ping.

VARIABLES

Variables spécifiques à la sonde supportées :

forks
Exécute ce nombre de processus simultanés au maximum.

Exemple de valeur : 5

Valeur par défaut : 5

offset
Si vous exécutez de nombreuses sondes simultanément, vous pourriez vouloir éviter qu'elles ne touchent votre réseau en même temps. En utilisant le paramètre offset spécifique à la sonde, vous pouvez modifier le moment où chaque sonde sera exécutée. L'offset est spécifié en % de l'intervalle total, ou alternativement comme 'random', et l'offset de la section 'General' est utilisé si rien n'est spécifié ici. Notez que cela n'influence PAS les fichiers RRD eux-mêmes, il s'agit simplement de la date à laquelle l'acquisition des données est initiée. (Cette variable n'est applicable que si la variable 'concurrentprobes' est définie dans la section 'General'.)

Exemple de valeur : 50%

packetsize
L'option (optionnelle) packetsize permet de configurer la taille des paquets pour les pings envoyés.

Valeur par défaut : 100

step
Durée de l'intervalle de base que cette sonde doit utiliser, si différente de celle spécifiée dans la section 'Database'. Notez que le pas dans les fichiers RRD est fixe lorsqu'ils sont générés initialement, et si vous modifiez le paramètre step par la suite, vous devrez supprimer les anciens fichiers RRD ou les convertir d'une manière ou d'une autre. (Cette variable n'est applicable que si la variable 'concurrentprobes' est définie dans la section 'General'.)

Exemple de valeur : 300

timeout
Durée maximale d'un seul 'ping'.

Exemple de valeur : 15

Valeur par défaut : 5

tos
Le type de service (optionnel) pour les pings envoyés.

Variables spécifiques à la cible supportées :

/^influx_.+/
Il s'agit d'une étiquette qui sera envoyée à influxdb et n'a aucun impact sur la mesure de la sonde. Le nom de l'étiquette sera envoyé sans le préfixe « influx_ », qui sera remplacé par « tag_ ». Les étiquettes peuvent être utilisées pour le filtrage.

Exemple de valeur : influx_location = Dans le sous-sol

junospass
L'option junospass permet de spécifier le mot de passe pour l'utilisateur spécifié avec l'option junosuser.

Exemple de valeur : motdepasse

Ce paramètre est obligatoire.

junosuser
L'option junosuser permet de spécifier un nom d'utilisateur ayant la capacité de ping sur le périphérique JunOS.

Exemple de valeur : utilisateur

Ce paramètre est obligatoire.

pings
Combien de pings doivent être envoyés à chaque cible, si différent de la valeur globale spécifiée dans la section Database. Notez que le nombre de pings dans les fichiers RRD est fixe lors de leur génération initiale, et si vous modifiez ce paramètre par la suite, vous devrez supprimer les anciens fichiers RRD ou les convertir d'une manière ou d'une autre.

Exemple de valeur : 5

psource
L'option (optionnelle) psource spécifie une adresse IP ou une interface alternative à partir de laquelle vous souhaitez envoyer vos pings. Les routeurs peuvent avoir de nombreuses adresses IP et interfaces. Lorsque vous pingez depuis un routeur, vous avez la possibilité de choisir l'interface et/ou l'adresse IP d'où provient le ping. La spécification d'une IP/interface ne spécifie pas nécessairement l'interface par laquelle le ping sortira, mais spécifiera l'adresse qui semblera provenir du paquet(s). Si cette option est laissée vide, le périphérique JunOS sourcera le paquet automatiquement en fonction du routage et/ou des métriques. Si cela n'a pas de sens pour vous, laissez-la vide.

Exemple de valeur : 192.168.2.129

source
L'option source spécifie le périphérique JunOS qui exécutera les commandes ping. Cette adresse sera utilisée pour la connexion ssh.

Exemple de valeur : 192.168.2.1

Ce paramètre est obligatoire.

NOTES

Configuration de JunOS

Le périphérique JunOS doit avoir un nom d'utilisateur/mot de passe configuré, ainsi que la capacité de se connecter aux VTY.

Assurez-vous de vous connecter une fois à l'hôte distant depuis la ligne de commande en tant qu'utilisateur exécutant smokeping. Lors de la première connexion, ssh demandera si vous souhaitez ajouter le nouvel hôte à son fichier known_hosts. Cela ne se produira pas automatiquement, donc le script échouera à se connecter jusqu'à ce que la clé ssh de votre boîtier Juniper soit dans le fichier known_hosts.

Certains périphériques JunOS ont un maximum de 5 VTY disponibles, soyez donc prudent à ne pas dépasser la limite avec la variable 'forks'.

Exigences

Ce module nécessite Net::OpenSSH et IO::Pty.
