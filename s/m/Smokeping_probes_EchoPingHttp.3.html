NOM

Smokeping::probes::EchoPingHttp - une sonde echoping(1) pour SmokePing

APERÇU

Mesure les temps d'aller-retour HTTP (serveurs web et caches) pour SmokePing.

SYNTAXE

*** Sondes ***
+EchoPingHttp
binary = /usr/bin/echoping
forks = 5
offset = 50%
step = 300
# Les variables suivantes peuvent être remplacées dans chaque section cible
/^influx_.+/ = influx_location = Dans le sous-sol
accept_redirects = yes
extraopts = -une-lettre-que-l-auteur-n-a-pas-pensée
ignore_cache = yes
ipversion = 4
pings = 5
port = 80
priority = 6
revalidate_data = no
timeout = 20
tos = 0xa0
url = /
waittime = 1
# [...]
*** Cibles ***
probe = EchoPingHttp # si ceci doit être la sonde par défaut
# [...]
+ ma_cible
# probe = EchoPingHttp # si la sonde par défaut est autre chose
host = mon.serveur
/^influx_.+/ = influx_location = Dans le sous-sol
accept_redirects = yes
extraopts = -une-lettre-que-l-auteur-n-a-pas-pensée
ignore_cache = yes
ipversion = 4
pings = 5
port = 80
priority = 6
revalidate_data = no
timeout = 20
tos = 0xa0
url = /
waittime = 1

VARIABLES

Variables spécifiques à la sonde prises en charge :

binary
L'emplacement de votre binaire echoping.

Valeur par défaut : /usr/bin/echoping

forks
Exécuter ce nombre de processus concurrents au maximum

Exemple de valeur : 5

Valeur par défaut : 5

offset
Si vous exécutez de nombreuses sondes simultanément, vous pourriez vouloir éviter qu'elles ne touchent votre réseau en même temps. En utilisant le paramètre d'offset spécifique à la sonde, vous pouvez changer le moment où chaque sonde sera exécutée. L'offset est spécifié en % de l'intervalle total, ou alternativement comme 'random', et l'offset de la section 'General' est utilisé si rien n'est spécifié ici. Notez que cela n'influence PAS les fichiers RRD eux-mêmes, il s'agit simplement d'un choix du moment où l'acquisition des données est initiée. (Cette variable n'est applicable que si la variable 'concurrentprobes' est définie dans la section 'General'.)

Exemple de valeur : 50%

step
Durée de l'intervalle de base que cette sonde doit utiliser, si elle est différente de celle spécifiée dans la section 'Database'. Notez que le pas dans les fichiers RRD est fixe lors de leur génération initiale, et si vous changez le paramètre de pas par la suite, vous devrez supprimer les anciens fichiers RRD ou les convertir d'une manière ou d'une autre. (Cette variable n'est applicable que si la variable 'concurrentprobes' est définie dans la section 'General'.)

Exemple de valeur : 300

Variables spécifiques à la cible prises en charge :

/^influx_.+/
Il s'agit d'une balise qui sera envoyée à influxdb et n'a aucun impact sur la mesure de la sonde. Le nom de la balise sera envoyé sans le préfixe "influx_", qui sera remplacé par "tag_" à la place. Les balises peuvent être utilisées pour le filtrage.

Exemple de valeur : influx_location = Dans le sous-sol

accept_redirects
L'option "-R" de echoping(1) : Accepte les codes de statut HTTP 3xx (redirections) comme réponses normales au lieu de les traiter comme des erreurs. Notez que cette option n'est disponible qu'à partir d'Echoping 6.

Activé si la valeur est autre chose que 'no' ou '0'.

Exemple de valeur : yes

extraopts
Toutes les options supplémentaires spécifiées ici seront passées inchangées à echoping(1).

Exemple de valeur : -une-lettre-que-l-auteur-n-a-pas-pensée

ignore_cache
L'option "-A" de echoping(1) : force le proxy à ignorer le cache. Activé si la valeur est autre chose que 'no' ou '0'.

Exemple de valeur : yes

ipversion
Le protocole IP utilisé. Les valeurs possibles sont "4" et "6". Passé à echoping(1) comme options "-4" ou "-6".

Exemple de valeur : 4

pings
Combien de pings doivent être envoyés à chaque cible, si différent de la valeur globale spécifiée dans la section Database. Notez que le nombre de pings dans les fichiers RRD est fixe lors de leur génération initiale, et si vous changez ce paramètre par la suite, vous devrez supprimer les anciens fichiers RRD ou les convertir d'une manière ou d'une autre.

Exemple de valeur : 5

port
Le port TCP à utiliser.

Exemple de valeur : 80

priority
L'option "-p" de echoping(1).

Exemple de valeur : 6

revalidate_data
L'option "-a" de echoping(1) : force le proxy à revalider les données avec le serveur d'origine. Activé si la valeur est autre chose que 'no' ou '0'.

Exemple de valeur : no

timeout
L'option "-t" de echoping(1).

Exemple de valeur : 20

Valeur par défaut : 10

tos
L'option "-P" de echoping(1).

Exemple de valeur : 0xa0

url
L'URL à demander au serveur web ou au cache. Peut être soit relative (/...) pour les serveurs web, soit absolue (http://...) pour les caches.

Valeur par défaut : /

waittime
L'option "-w" de echoping(1).

Exemple de valeur : 1

AUTEURS

Niko Tyni <ntyni@iki.fi>

NOTES

Vous devriez envisager de définir une valeur inférieure pour la variable "pings" par rapport à la valeur par défaut de 20, car la récupération répétitive d'URL peut être assez lourde pour le serveur.

Les variables EchoPing fill, size et udp ne sont pas valides pour EchoPingHttp.
