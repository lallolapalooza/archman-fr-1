NOM

Smokeping::probes::DNS - Sonde DNS pour SmokePing

SYNTAXE

*** Sondes ***
+DNS
binary = /usr/bin/dig # obligatoire
forks = 5
offset = 50%
step = 300
timeout = 15
# Les variables suivantes peuvent être remplacées dans chaque section cible
/^influx_.+/ = influx_location = Dans le sous-sol
lookup = www.example.org
pings = 5
server = ns1.someisp.net
# [...]
*** Cibles ***
probe = DNS # si ceci doit être la sonde par défaut
# [...]
+ ma_cible
# probe = DNS # si la sonde par défaut est autre chose
host = mon.hote
/^influx_.+/ = influx_location = Dans le sous-sol
lookup = www.example.org
pings = 5
server = ns1.someisp.net

DESCRIPTION

Intègre dig comme sonde dans smokeping. La variable binary doit pointer vers votre copie du programme dig. S'il n'est pas encore installé sur votre système, vous devriez installer bind-utils >= 9.0.0.

La sonde interroge l'hôte donné n fois pour son nom. Où n est le nombre spécifié dans le fichier de configuration.

VARIABLES

Variables spécifiques à la sonde prises en charge :

binary
L'emplacement de votre binaire dig.

Exemple de valeur : /usr/bin/dig

Ce paramètre est obligatoire.

forks
Exécuter ce nombre de processus simultanés au maximum

Exemple de valeur : 5

Valeur par défaut : 5

offset
Si vous exécutez plusieurs sondes simultanément, vous pouvez vouloir éviter qu'elles n'atteignent votre réseau en même temps. En utilisant le paramètre d'offset spécifique à la sonde, vous pouvez changer le moment où chaque sonde sera exécutée. L'offset est spécifié en % de l'intervalle total, ou alternativement comme 'random', et l'offset de la section 'General' est utilisé si rien n'est spécifié ici. Notez que cela n'influence PAS les rrds eux-mêmes, il s'agit simplement d'une question de moment où l'acquisition des données est initiée. (Cette variable n'est applicable que si la variable 'concurrentprobes' est définie dans la section 'General'.)

Exemple de valeur : 50%

step
Durée de l'intervalle de base que cette sonde doit utiliser, si différent de celui spécifié dans la section 'Database'. Notez que le pas dans les fichiers RRD est fixe lorsqu'ils sont générés à l'origine, et si vous changez le paramètre de pas par la suite, vous devrez supprimer les anciens fichiers RRD ou les convertir d'une manière ou d'une autre. (Cette variable n'est applicable que si la variable 'concurrentprobes' est définie dans la section 'General'.)

Exemple de valeur : 300

timeout
Combien de temps prend un seul 'ping' au maximum

Exemple de valeur : 15

Valeur par défaut : 5

Variables spécifiques à la cible prises en charge :

/^influx_.+/
Ceci est une étiquette qui sera envoyée à influxdb et n'a aucun impact sur la mesure de la sonde. Le nom de l'étiquette sera envoyé sans le préfixe "influx_", qui sera remplacé par "tag_" à la place. Les étiquettes peuvent être utilisées pour le filtrage.

Exemple de valeur : influx_location = Dans le sous-sol

lookup
Nom de l'hôte à rechercher dans le DNS.

Exemple de valeur : www.example.org

pings
Combien de pings doivent être envoyés à chaque cible, si différent de la valeur globale spécifiée dans la section Database. Notez que le nombre de pings dans les fichiers RRD est fixe lorsqu'ils sont générés à l'origine, et si vous changez ce paramètre par la suite, vous devrez supprimer les anciens fichiers RRD ou les convertir d'une manière ou d'une autre.

Exemple de valeur : 5

server
Nom du serveur DNS à utiliser.

Exemple de valeur : ns1.someisp.net
