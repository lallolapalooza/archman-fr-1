NOM

Smokeping::probes::DismanPing - Sonde DISMAN-PING-MIB pour SmokePing

SYNOPSIS

*** Sondes ***
+DismanPing
offset = 50%
pings = 15
step = 300
# Les variables suivantes peuvent être remplacées dans chaque section cible
/^influx_.+/ = influx_location = Au sous-sol
ownerindex = smokeping
packetsize = 56
pinghost = pinger@router.example.com # obligatoire
pingsrc = 192.0.2.9
# [...]
*** Cibles ***
probe = DismanPing # si cela doit être la sonde par défaut
# [...]
+ mytarget
# probe = DismanPing # si la sonde par défaut est autre chose
host = my.host
/^influx_.+/ = influx_location = Au sous-sol
ownerindex = smokeping
packetsize = 56
pinghost = pinger@router.example.com # obligatoire
pingsrc = 192.0.2.9

DESCRIPTION

Utilise la DISMAN-PING-MIB pour faire envoyer des sondes par un système distant.

VARIABLES

Variables spécifiques à la sonde supportées :

offset
Si vous exécutez de nombreuses sondes simultanément, vous pourriez vouloir éviter qu'elles n'impactent votre réseau au même moment. En utilisant le paramètre d'offset spécifique à la sonde, vous pouvez changer le moment où chaque sonde sera exécutée. L'offset est spécifié en % de l'intervalle total, ou alternativement comme 'random', et l'offset de la section 'General' est utilisé si rien n'est spécifié ici. Notez que cela n'influence PAS les rrds eux-mêmes, c'est juste une question de quand l'acquisition des données est initiée. (Cette variable n'est applicable que si la variable 'concurrentprobes' est définie dans la section 'General'.)

Exemple de valeur : 50%

pings
Combien de pings doivent être envoyés à chaque cible. Notez que la valeur maximale pour le MIP DismanPing est de 15, ce qui est inférieur à la valeur par défaut de SmokePing, donc cette classe a sa propre valeur par défaut. Si votre section Database spécifie une valeur inférieure à 15, vous devez également la définir pour cette sonde. Notez que le nombre de pings dans les fichiers RRD est fixe lors de leur génération initiale, et si vous changez ce paramètre par la suite, vous devrez supprimer les anciens fichiers RRD ou les convertir d'une manière ou d'une autre.

Exemple de valeur : 15

Valeur par défaut : 15

step
Durée de l'intervalle de base que cette sonde doit utiliser, si différent de celui spécifié dans la section 'Database'. Notez que le pas dans les fichiers RRD est fixe lors de leur génération initiale, et si vous changez le paramètre step par la suite, vous devrez supprimer les anciens fichiers RRD ou les convertir d'une manière ou d'une autre. (Cette variable n'est applicable que si la variable 'concurrentprobes' est définie dans la section 'General'.)

Exemple de valeur : 300

Variables spécifiques à la cible supportées :

/^influx_.+/
Ceci est une étiquette qui sera envoyée à influxdb et n'aura aucun impact sur la mesure de la sonde. Le nom de l'étiquette sera envoyé sans le préfixe "influx_", qui sera remplacé par "tag_" à la place. Les étiquettes peuvent être utilisées pour le filtrage.

Exemple de valeur : influx_location = Au sous-sol

ownerindex
L'OwnerIndex SNMP à utiliser lors de la configuration du test. Lors de l'utilisation de VACM, peut correspondre à un nom de sécurité ou à un nom de groupe de l'entité exécutant le test.

Par défaut, il sera défini sur

Exemple de valeur : smokeping

packetsize
Le paramètre packetsize vous permet de configurer la taille des paquets pour les pings envoyés. Le minimum est 8, le maximum 65507. Utilisez le même nombre qu'avec fping si vous voulez les mêmes tailles de paquets utilisées sur le réseau.

Valeur par défaut : 56

pinghost
Le paramètre (obligatoire) pinghost spécifie le système distant qui exécutera les pings, ainsi que la chaîne communautaire SNMP sur l'appareil.

Exemple de valeur : pinger@router.example.com

Ce réglage est obligatoire.

pingsrc
Le paramètre (optionnel) pingsrc spécifie l'adresse source à utiliser pour les pings. S'il est spécifié, ce paramètre doit identifier une adresse IP attribuée à pinghost.

Exemple de valeur : 192.0.2.9

NOTES

NOMS DE MENU

Cette sonde utilise le nom de menu d'un test dans le cadre de l'index unique. Si le nom du menu dépasse 32 caractères, les 32 derniers caractères sont utilisés pour l'index. Les collisions ne sont **pas** détectées et entraînent simplement l'utilisation des résultats d'un test pour tous les noms en collision.

CONFIGURATION

Cette sonde nécessite un accès en lecture/écriture à la pingCtlTable. Elle nécessite également un accès en lecture seule à la pingResultsTable et à la pingHistoryTable. La DISMAN-PING-MIB est structurée de telle sorte qu'il est possible de restreindre par pingCtlOwnerIndex. Cette sonde utilise par défaut un pingCtlOwnerIndex de "SP on hostname" comme ownerindex ; utilisez ownerindex pour configurer cela si nécessaire.

EXEMPLE DE CONFIGURATION JUNOS

Cette configuration permet à la communauté "pinger" un accès en lecture-écriture à la DISMAN-PING-MIB complète, mais uniquement lorsqu'elle provient du gestionnaire à l'adresse 192.0.2.134.

snmp {
    view pingMIB {
        oid .1.3.6.1.2.1.80 include;
    }
    community pinger {
        view pingMIB;   
        authorization read-write;
        clients {
            192.0.2.134/32;
        }
    }
}

NOTE SUR LES CONFIGURATIONS EXEMPLES

Cette configuration autorise la communauté "pinger" un accès complet à la DISMAN-PING-MIB. Il y a des informations dans la description de pingCtlOwnerIndex dans le RFC 4560 (http://tools.ietf.org/html/rfc4560) concernant l'utilisation de la vacmViewTreeFamilyTable pour restreindre davantage l'accès. L'auteur n'a pas essayé cette méthode.
