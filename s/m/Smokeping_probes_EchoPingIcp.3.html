NAME

Smokeping::probes::EchoPingIcp - une sonde echoping(1) pour SmokePing

OVERVIEW

Mesure les temps d'aller-retour ICP (Internet Cache Protocol, utilisé par les caches web) pour SmokePing.

SYNOPSIS

*** Sondes ***
+EchoPingIcp
binary = /usr/bin/echoping
forks = 5
offset = 50%
step = 300
# Les variables suivantes peuvent être surchargées dans chaque section cible
/^influx_.+/ = influx_location = Dans le sous-sol
extraopts = -une-lettre-que-l-auteur-n-a-pas-imaginée
ipversion = 4
pings = 5
priority = 6
timeout = 1
tos = 0xa0
url = http://www.example.org/ # obligatoire
waittime = 1
# [...]
*** Cibles ***
probe = EchoPingIcp # si c'est la sonde par défaut
# [...]
+ ma_cible
# probe = EchoPingIcp # si la sonde par défaut est autre chose
host = mon.host
/^influx_.+/ = influx_location = Dans le sous-sol
extraopts = -une-lettre-que-l-auteur-n-a-pas-imaginée
ipversion = 4
pings = 5
priority = 6
timeout = 1
tos = 0xa0
url = http://www.example.org/ # obligatoire
waittime = 1

VARIABLES

Variables spécifiques à la sonde prises en charge :

binary
L'emplacement de votre binaire echoping.

Valeur par défaut : /usr/bin/echoping

forks
Exécute ce nombre de processus simultanés au maximum

Exemple de valeur : 5

Valeur par défaut : 5

offset
Si vous exécutez de nombreuses sondes simultanément, vous pourriez vouloir éviter qu'elles n'atteignent votre réseau en même temps. En utilisant le paramètre d'offset spécifique à la sonde, vous pouvez modifier le moment où chaque sonde sera exécutée. L'offset est spécifié en % de l'intervalle total, ou alternativement comme 'random', et l'offset de la section 'General' est utilisé si rien n'est spécifié ici. Notez que cela n'influence PAS les rrds eux-mêmes, il s'agit juste d'une question de quand l'acquisition de données est initiée. (Cette variable n'est applicable que si la variable 'concurrentprobes' est définie dans la section 'General'.)

Exemple de valeur : 50%

step
Durée de l'intervalle de base que cette sonde doit utiliser, si elle est différente de celle spécifiée dans la section 'Database'. Notez que le pas dans les fichiers RRD est fixe lorsqu'ils sont générés à l'origine, et si vous modifiez le paramètre step par la suite, vous devrez supprimer les anciens fichiers RRD ou les convertir d'une manière ou d'une autre. (Cette variable n'est applicable que si la variable 'concurrentprobes' est définie dans la section 'General'.)

Exemple de valeur : 300

Variables spécifiques à la cible prises en charge :

/^influx_.+/
Ceci est une balise qui sera envoyée à influxdb et n'a aucun impact sur la mesure de la sonde. Le nom de la balise sera envoyé sans le préfixe "influx_", qui sera remplacé par "tag_" à la place. Les balises peuvent être utilisées pour le filtrage.

Exemple de valeur : influx_location = Dans le sous-sol

extraopts
Toutes les options supplémentaires spécifiées ici seront transmises sans modification à echoping(1).

Exemple de valeur : -une-lettre-que-l-auteur-n-a-pas-imaginée

ipversion
Le protocole IP utilisé. Les valeurs possibles sont "4" et "6". Transmis à echoping(1) comme options "-4" ou "-6".

Exemple de valeur : 4

pings
Combien de pings doivent être envoyés à chaque cible, si différent de la valeur globale spécifiée dans la section Database. Notez que le nombre de pings dans les fichiers RRD est fixe lors de leur génération initiale, et si vous modifiez ce paramètre par la suite, vous devrez supprimer les anciens fichiers RRD ou les convertir d'une manière ou d'une autre.

Exemple de valeur : 5

priority
L'option "-p" de echoping(1).

Exemple de valeur : 6

timeout
L'option "-t" de echoping(1).

Exemple de valeur : 1

Valeur par défaut : 5

tos
L'option "-P" de echoping(1).

Exemple de valeur : 0xa0

url
L'URL à demander au cache web.

Exemple de valeur : http://www.example.org/

Ce réglage est obligatoire.

waittime
L'option "-w" de echoping(1).

Exemple de valeur : 1

NOTES

Les variables fill, size et udp de EchoPing ne sont pas valides.
