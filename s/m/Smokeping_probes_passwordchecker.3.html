NOM

Smokeping::probes::passwordchecker - Une classe de base pour implémenter les sondes SmokePing

APERÇU

Similaire à Smokeping::probes::basefork, mais prend en charge un fichier de configuration spécifique à la sonde pour stocker les mots de passe et une méthode pour y accéder.

SYNTAXE

*** Probes ***
+passwordchecker
forks = 5
offset = 50%
passwordfile = /some/place/secret
step = 300
timeout = 15
# Les variables suivantes peuvent être remplacées dans chaque section de cible
/^influx_.+/ = influx_location = In the basement
pings = 5
# [...]
*** Targets ***
probe = passwordchecker # si c'est la sonde par défaut
# [...]
+ mytarget
# probe = passwordchecker # si la sonde par défaut est autre chose
host = my.host
/^influx_.+/ = influx_location = In the basement
pings = 5

DESCRIPTION

Synopsis avec plus de détails

Fichier de configuration principal de SmokePing :

*** Probes ***
+ MyPasswordChecker
# emplacement du fichier contenant les noms d'utilisateur et les mots de passe
passwordfile = /usr/share/smokeping/etc/passwords

Le fichier de mots de passe spécifié :

# hôte:nom_utilisateur:mot_de_passe
host1:joe:hardlyasecret
 # les commentaires et les lignes blanches sont autorisés
host2:sue:notasecreteither

Description réelle

Lors de l'implémentation de sondes d'authentification, il peut ne pas être souhaitable de stocker les mots de passe en texte clair nécessaires dans le fichier de configuration principal de SmokePing, car ce dernier doit être lisible à la fois par le démon SmokePing qui effectue les sondes et par le CGI qui affiche les résultats. Si les mots de passe sont stockés dans un fichier différent, ce fichier peut être rendu lisible uniquement par l'utilisateur sous lequel le démon s'exécute. De cette façon, nous pouvons être sûrs que personne ne peut tromper le CGI pour afficher les mots de passe sur le Web.

Ce module lit les mots de passe au démarrage à partir du fichier spécifié dans la variable spécifique à la sonde `passwordfile'. Les mots de passe peuvent ensuite être accédés et modifiés par la méthode password, qui nécessite l'hôte et le nom d'utilisateur correspondants comme arguments.

Format du fichier de mots de passe

Le format du fichier de mots de passe est simplement une ligne pour chaque triplet d'hôte, nom d'utilisateur et mot de passe, séparés les uns des autres par des deux-points (:).

Les lignes de commentaire, commençant par le signe `#', sont ignorées, tout comme les lignes vides.

VARIABLES

Variables spécifiques à la sonde prises en charge :

forks
Exécuter ce nombre de processus concurrents au maximum

Exemple de valeur : 5

Valeur par défaut : 5

offset
Si vous exécutez de nombreuses sondes simultanément, vous voudrez peut-être éviter qu'elles n'atteignent votre réseau toutes en même temps. En utilisant le paramètre offset spécifique à la sonde, vous pouvez modifier le moment où chaque sonde sera exécutée. L'offset est spécifié en % de l'intervalle total, ou alternativement comme 'random', et l'offset de la section 'General' est utilisé si rien n'est spécifié ici. Notez que cela n'influence PAS les rrds eux-mêmes, il s'agit simplement d'une question de moment où l'acquisition des données est initiée. (Cette variable n'est applicable que si la variable 'concurrentprobes' est définie dans la section 'General'.)

Exemple de valeur : 50%

passwordfile
Emplacement du fichier contenant les noms d'utilisateur et les mots de passe.

Exemple de valeur : /some/place/secret

step
Durée de l'intervalle de base que cette sonde doit utiliser, si elle est différente de celle spécifiée dans la section 'Database'. Notez que le pas dans les fichiers RRD est fixe lors de leur génération initiale, et si vous modifiez le paramètre step par la suite, vous devrez supprimer les anciens fichiers RRD ou les convertir d'une manière ou d'une autre. (Cette variable n'est applicable que si la variable 'concurrentprobes' est définie dans la section 'General'.)

Exemple de valeur : 300

timeout
Combien de temps un seul 'ping' prend au maximum

Exemple de valeur : 15

Valeur par défaut : 5

Variables spécifiques à la cible prises en charge :

/^influx_.+/
Il s'agit d'une balise qui sera envoyée à influxdb et n'aura aucun impact sur la mesure de la sonde. Le nom de la balise sera envoyé sans le préfixe `influx_`, qui sera remplacé par `tag_` à la place. Les balises peuvent être utilisées pour le filtrage.

Exemple de valeur : influx_location = In the basement

pings
Combien de pings doivent être envoyés à chaque cible, si cela est différent de la valeur globale spécifiée dans la section Database. Notez que le nombre de pings dans les fichiers RRD est fixe lors de leur génération initiale, et si vous modifiez ce paramètre par la suite, vous devrez supprimer les anciens fichiers RRD ou les convertir d'une manière ou d'une autre.

Exemple de valeur : 5
