NAME

Smokeping::probes::LDAP - un sondeur LDAP pour SmokePing

OVERVIEW

Mesure la latence de recherche LDAP pour SmokePing

SYNOPSIS

*** Probes ***
+LDAP
forks = 5
offset = 50%
passwordfile = /some/place/secret
step = 300
# Le jeu de variables suivant peut être surchargé dans chaque section de cible
/^influx_.+/ = influx_location = Dans le sous-sol
attrs = uid,someotherattr
base = dc=foo,dc=bar
binddn = uid=testuser,dc=foo,dc=bar
filter = uid=testuser # obligatoire
mininterval = 1
password = mypass
pings = 5
port = 389
scheme = ldap
scope = one
start_tls = 1
timeout = 10
verify = optional
version = 3
# [...]
*** Cibles ***
probe = LDAP # si cela doit être le sondeur par défaut
# [...]
+ mytarget
# probe = LDAP # si le sondeur par défaut est différent
host = my.host
/^influx_.+/ = influx_location = Dans le sous-sol
attrs = uid,someotherattr
base = dc=foo,dc=bar
binddn = uid=testuser,dc=foo,dc=bar
filter = uid=testuser # obligatoire
mininterval = 1
password = mypass
pings = 5
port = 389
scheme = ldap
scope = one
start_tls = 1
timeout = 10
verify = optional
version = 3

DESCRIPTION

Ce sondeur mesure la latence des requêtes LDAP pour SmokePing. La requête est spécifiée par la variable de section cible `filter` et éventuellement par la variable de section cible `base`. Les attributs interrogés peuvent être spécifiés dans la liste séparée par des virgules `attrs`.

Le port TCP du serveur LDAP et la version LDAP à utiliser peuvent être spécifiés par les variables `port` et `version`.

Le sondeur peut émettre la commande starttls pour mettre la connexion en mode crypté, si indiqué par la variable `start_tls`. Ceci nécessite que le module perl `IO::Socket::SSL` soit installé.

Le sondeur peut aussi éventuellement effectuer un bind authentifié LDAP, si la variable `binddn` est présente. Le mot de passe à utiliser peut être spécifié par la variable de section cible `password` ou dans un fichier externe. L'emplacement de ce fichier est spécifié par la variable de section sondeur `passwordfile`. Voir Smokeping::probes::passwordchecker(3pm) pour le format de ce fichier (résumé : triplets séparés par point-virgule de la forme <hôte> <bind-dn> <mot-de-passe>).

Le sondeur essaie d'être respectueux du serveur et n'envoie pas de requêtes d'authentification plus fréquemment que toutes les X secondes, où X est la valeur de la variable de section cible `mininterval` (1 par défaut).

VARIABLES

Variables supportées dans la section du sondeur :

forks
Nombre maximum de processus concurrents à exécuter.

Exemple de valeur : 5

Valeur par défaut : 5

offset
Si de nombreux sondes s'exécutent en parallèle, il peut être utile d'éviter qu'ils ne bombardent votre réseau simultanément. En utilisant le paramètre d'offset de la section de cible, vous pouvez décaler le moment où les sondes s'exécutent. L'offset est spécifié en pourcentage de l'intervalle total, ou alternativement comme 'random', et est utilisé si non spécifié ici. Notez que cela n'affecte pas les rrds, il s'agit seulement de savoir quand les données sont collectées. (Cette variable n'est applicable que si la variable 'concurrentprobes' est définie dans la section general.)

Exemple de valeur : 50%

passwordfile
Emplacement du fichier contenant les noms d'utilisateur et leurs mots de passe.

Exemple de valeur : /some/place/secret

step
Durée de l'intervalle de base que ce sondeur doit utiliser, si différente de celle spécifiée dans la section de base. Notez que le pas des fichiers rrd est fixe lorsqu'ils sont générés initialement, et si vous modifiez ce paramètre par la suite, vous devrez supprimer les anciens fichiers rrd ou les convertir d'une manière ou d'une autre. (Cette variable n'est applicable que si la variable 'concurrentprobes' est définie dans la section general.)

Exemple de valeur : 300

Variables supportées dans la section de cible :

/^influx_.+/
Ceci est une étiquette envoyée à influxdb et n'a aucune influence sur la mesure du sondeur. Le nom de l'étiquette est envoyé sans le préfixe « influx_ », qui est remplacé par « tag_ ». Les étiquettes peuvent être utilisées pour le filtrage.

Exemple de valeur : influx_location = Dans le sous-sol

attrs
Les attributs interrogés.

Exemple de valeur : uid,someotherattr

base
La base à utiliser dans la requête LDAP

Exemple de valeur : dc=foo,dc=bar

binddn
Si présent, authentifier le bind LDAP avec cette DN.

Exemple de valeur : uid=testuser,dc=foo,dc=bar

filter
La requête réelle à effectuer

Exemple de valeur : uid=testuser

Cette valeur est obligatoire.

mininterval
L'intervalle minimum entre chaque requête envoyée, en secondes (peut être fractionnel).

Valeur par défaut : 1

password
Le mot de passe à utiliser, s'il n'est pas trouvé dans <passwordfile>.

Exemple de valeur : mypass

pings
Combien de pings envoyer à chaque cible, si différent de la valeur globale spécifiée dans la section de base. Notez que le nombre de pings dans les fichiers rrd est fixe lorsqu'ils sont générés initialement, et si vous modifiez ce paramètre par la suite, vous devrez supprimer les anciens fichiers rrd ou les convertir d'une manière ou d'une autre.

Exemple de valeur : 5

port
Le port TCP du serveur LDAP

Exemple de valeur : 389

scheme
Le schéma LDAP à utiliser : ldap, ldaps ou ldapi

Exemple de valeur : ldap

Valeur par défaut : ldap

scope
La portée de la requête. Peut être 'base', 'one' ou 'sub'. Voir la documentation de Net::LDAP pour plus de détails.

Exemple de valeur : one

Valeur par défaut : sub

start_tls
Si défini sur vrai, chiffre la connexion avec la commande starttls. Désactivé par défaut.

Exemple de valeur : 1

timeout
Le temps de timeout de la requête LDAP en secondes.

Exemple de valeur : 10

Valeur par défaut : 5

verify
Le niveau de vérification TLS. Peut être 'none', 'optional', 'require'. Voir la documentation de Net::LDAPS pour plus de détails.

Exemple de valeur : optional

Valeur par défaut : require

version
La version LDAP à utiliser.

Exemple de valeur : 3

BUGS

Il devrait y avoir un moyen de spécifier les options TLS, telles que les certificats impliqués, etc.

Le sondeur a une méthode inhabituelle pour contourner le fait que la classe `IO::Socket::SSL` cesse de fonctionner si `start_tls()` est appelée plus d'une fois dans le même programme. Cependant, cela fonctionne pour moi (tm).
