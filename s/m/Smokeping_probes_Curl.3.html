NOM

Smokeping::probes::Curl - une sonde curl(1) pour SmokePing

APERÇU

Récupère une URL HTTP ou HTTPS en utilisant curl(1).

SYNTAXE

*** Sondes ***
+Curl
binary = /usr/bin/curl
forks = 5
offset = 50%
step = 300
# Les variables suivantes peuvent être remplacées dans chaque section de cible
/^influx_.+/ = influx_location = Au sous-sol
agent = User-Agent: Lynx/2.8.4rel.1 libwww-FM/2.14 SSL-MM/1.4.1 OpenSSL/0.9.6c
expect = Status: green
extraargs = -6 --head --user user:password
extrare = / /
follow_redirects = yes
include_redirects = yes
insecure_ssl = 1
interface = eth0
pings = 5
require_zero_status = yes
ssl2 = 1
timeout = 20
urlformat = http://%host%/ # obligatoire
# [...]
*** Cibles ***
probe = Curl # si c'est la sonde par défaut
# [...]
+ ma_cible
# probe = Curl # si la sonde par défaut est autre chose
host = mon.host
/^influx_.+/ = influx_location = Au sous-sol
agent = User-Agent: Lynx/2.8.4rel.1 libwww-FM/2.14 SSL-MM/1.4.1 OpenSSL/0.9.6c
expect = Status: green
extraargs = -6 --head --user user:password
extrare = / /
follow_redirects = yes
include_redirects = yes
insecure_ssl = 1
interface = eth0
pings = 5
require_zero_status = yes
ssl2 = 1
timeout = 20
urlformat = http://%host%/ # obligatoire

DESCRIPTION

(voir curl(1) pour les détails des options ci-dessous)

VARIABLES

Variables spécifiques à la sonde prises en charge :

binary
L'emplacement de votre binaire curl.

Valeur par défaut : /usr/bin/curl

forks
Exécuter ce nombre de processus simultanés au maximum

Exemple de valeur : 5

Valeur par défaut : 5

offset
Si vous exécutez de nombreuses sondes simultanément, vous voudrez peut-être éviter qu'elles n'atteignent votre réseau en même temps. En utilisant le paramètre d'offset spécifique à la sonde, vous pouvez modifier le moment où chaque sonde sera exécutée. L'offset est spécifié en % de l'intervalle total, ou alternativement comme 'random', et l'offset de la section 'General' est utilisé si rien n'est spécifié ici. Notez que cela n'affecte PAS les rrds eux-mêmes, c'est juste une question de quand l'acquisition des données est initiée. (Cette variable n'est applicable que si la variable 'concurrentprobes' est définie dans la section 'General'.)

Exemple de valeur : 50%

step
Durée de l'intervalle de base que cette sonde doit utiliser, si différente de celle spécifiée dans la section 'Database'. Notez que le pas dans les fichiers RRD est fixe lors de leur génération initiale, et si vous modifiez le paramètre de pas par la suite, vous devrez supprimer les anciens fichiers RRD ou les convertir d'une manière ou d'une autre. (Cette variable n'est applicable que si la variable 'concurrentprobes' est définie dans la section 'General'.)

Exemple de valeur : 300

Variables spécifiques à la cible prises en charge :

/^influx_.+/
C'est une balise qui sera envoyée à influxdb et n'a aucun impact sur la mesure de la sonde. Le nom de la balise sera envoyé sans le préfixe "influx_", qui sera remplacé par "tag_" à la place. Les balises peuvent être utilisées pour le filtrage.

Exemple de valeur : influx_location = Au sous-sol

agent
L'option "-A" de curl(1). Il s'agit d'un en-tête HTTP User-Agent complet, y compris les mots "User-Agent:". Notez qu'il n'a pas besoin de guillemets autour.

Exemple de valeur : User-Agent: Lynx/2.8.4rel.1 libwww-FM/2.14 SSL-MM/1.4.1 OpenSSL/0.9.6c

expect
Exiger que le texte donné apparaisse quelque part dans la réponse, sinon la sonde est traitée comme un échec.

Exemple de valeur : Status: green

Valeur par défaut :

extraargs
Tous les arguments supplémentaires que vous pourriez vouloir passer à curl(1). Les arguments doivent être séparés par l'expression régulière spécifiée dans "extrare", qui ne contient que le caractère espace (" ") par défaut.

Notez que curl sera appelé avec la liste d'arguments résultante sans aucune expansion de shell. Si vous devez spécifier des arguments contenant des espaces, vous devez définir "extrare" sur autre chose.

À titre d'exemple compliqué, pour définir explicitement l'en-tête "Host:" dans les requêtes Curl, vous devez définir "extrare" sur autre chose, par exemple "/;/", puis spécifier "extraargs = --header;Host: www.example.com".

Exemple de valeur : -6 --head --user user:password

extrare
L'expression régulière utilisée pour diviser la chaîne extraargs en une liste d'arguments, dans la notation "/regexp/". Elle ne contient que le caractère espace (" ") par défaut, mais si vous devez spécifier des arguments contenant des espaces, vous pouvez définir cette variable sur une valeur différente.

Exemple de valeur : / /

Valeur par défaut : / /

follow_redirects
Si cette variable est définie sur 'yes', curl suivra toutes les étapes de redirection HTTP (l'option '-L'). Si elle est définie sur 'no', les en-têtes HTTP Location: ne seront pas suivis. Voir aussi 'include_redirects'.

Exemple de valeur : yes

Valeur par défaut : no

include_redirects
Si cette variable est définie sur 'yes', le résultat de la mesure inclura le temps passé à suivre les étapes de redirection HTTP. Si elle est définie sur 'no', seule la dernière étape sera mesurée. Voir aussi 'follow_redirects'.

Exemple de valeur : yes

Valeur par défaut : no

insecure_ssl
L'option "-k" de curl(1). Accepte les connexions SSL qui n'ont pas une chaîne de certificat sécurisée vers une autorité de certification de confiance. Notez que si vous devez surveiller des cibles https, vous devrez probablement activer cette option ou spécifier le chemin CA à curl via extraargs ci-dessous. Pour plus d'informations, voir la page de manuel de curl(1).

Exemple de valeur : 1

interface
L'option "--interface" de curl(1). Se lier à une interface, une adresse IP ou un nom d'hôte spécifique.

Exemple de valeur : eth0

pings
Combien de pings doivent être envoyés à chaque cible, si différent de la valeur globale spécifiée dans la section Database. Notez que le nombre de pings dans les fichiers RRD est fixe lors de leur génération initiale, et si vous modifiez ce paramètre par la suite, vous devrez supprimer les anciens fichiers RRD ou les convertir d'une manière ou d'une autre.

Exemple de valeur : 5

require_zero_status
Si cette variable est définie sur 'yes', les réponses ne seront comptées que si le code de sortie de Curl est '0'. Ceci est utile pour signaler les timeouts comme des pertes plutôt que comme des réponses retardées.

Exemple de valeur : yes

Valeur par défaut : no

ssl2
L'option "-2" de curl(1). Forcer SSL2.

Exemple de valeur : 1

timeout
L'option "-m" de curl(1). Timeout maximum en secondes.

Exemple de valeur : 20

Valeur par défaut : 10

urlformat
Le modèle de l'URL à récupérer. Peut être n'importe lequel de ceux supportés par curl. Toute occurrence de la chaîne '%host%' sera remplacée par l'hôte à sonder.

Exemple de valeur : http://%host%/

Ce réglage est obligatoire.

NOTES

Vous devriez envisager de régler la variable "pings" à une valeur inférieure à la valeur par défaut, car l'extraction répétée d'URL peut être assez coûteuse pour le serveur.

L'URL à tester utilisait auparavant la variable 'url' dans les anciennes versions de Smokeping, et le paramètre 'host' n'avait aucune influence sur celle-ci. Le nom de la variable a maintenant été changé en 'urlformat', et peut (et dans la plupart des cas devrait) contenir un remplacement pour le paramètre 'host'.
