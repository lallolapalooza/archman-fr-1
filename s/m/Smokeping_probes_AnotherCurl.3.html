NAME

Smokeping::probes::AnotherCurl - une sonde curl(1) pour SmokePing

OVERVIEW

Collecte une URL HTTP ou HTTPS en utilisant curl(1).

SYNOPSIS

*** Probes ***
+AnotherCurl
binary = /usr/bin/curl
forks = 5
offset = 50%
step = 300
# Les variables suivantes peuvent être surchargées dans chaque section de cible
/^influx_.+/ = influx_location = In the basement
agent = User-Agent: Lynx/2.8.4rel.1 libwww-FM/2.14 SSL-MM/1.4.1 OpenSSL/0.9.6c
extraargs = -6 --head --user user:password
extrare = / /
follow_redirects = yes
include_redirects = yes
insecure_ssl = 1
interface = eth0
pings = 5
ssl2 = 1
timeout = 20
urlformat = http://%host%/ # obligatoire
write_out = 
# [...]
*** Cibles ***
probe = AnotherCurl # si cela doit être la sonde par défaut
# [...]
+ mytarget
# probe = AnotherCurl # si la sonde par défaut est différente
host = my.host
/^influx_.+/ = influx_location = In the basement
agent = User-Agent: Lynx/2.8.4rel.1 libwww-FM/2.14 SSL-MM/1.4.1 OpenSSL/0.9.6c
extraargs = -6 --head --user user:password
extrare = / /
follow_redirects = yes
include_redirects = yes
insecure_ssl = 1
interface = eth0
pings = 5
ssl2 = 1
timeout = 20
urlformat = http://%host%/ # obligatoire
write_out =

DESCRIPTION

(voir curl(1) pour les détails des options ci-dessous)

VARIABLES

Variables spécifiques à la sonde:

binary
Emplacement de votre binaire curl.
Valeur par défaut : /usr/bin/curl
forks
Autant de processus concurrents que possible seront exécutés.
Exemple : 5
Valeur par défaut : 5
offset
Si vous exécutez plusieurs sondes simultanément, vous voudrez peut-être éviter qu'elles ne frappent toutes votre réseau en même temps. En utilisant le paramètre d'offset spécifique à la cible, vous pouvez changer le moment où chaque sonde sera exécutée. L'offset est spécifié en % de l'intervalle total, ou alternativement comme 'random', et la valeur de l'intervalle général sera utilisée si non spécifié ici. Notez que cela n'affecte pas les rrd, c'est juste un problème du moment où l'acquisition de données commence. (Cette variable n'est applicable que si la variable 'concurrentprobes' est définie dans la section 'General').
Exemple : 50%
step
L'intervalle de base que cette sonde doit utiliser, si différent de celui spécifié dans la section 'Database'. Notez que le pas dans les fichiers rrd est fixé à l'original et si vous changez ce paramètre par la suite, vous devrez supprimer les anciens fichiers rrd ou les convertir. (Cette variable n'est applicable que si la variable 'concurrentprobes' est définie dans la section 'General').
Exemple : 300

Variables spécifiques à la cible:

/^influx_.+/
Ceci est une étiquette qui est envoyée à influxdb et n'affecte pas la mesure de la sonde. Le nom de l'étiquette est envoyé sans le préfixe 'influx_', qui est remplacé par 'tag_'. Les étiquettes peuvent être utilisées pour le filtrage.
Exemple : influx_location = In the basement
agent
L'option '-A' de curl(1) pour l'en-tête HTTP User-Agent. Il s'agit d'un en-tête User-Agent complet incluant des mots tels que 'User-Agent:'. Notez qu'il ne nécessite pas de guillemets autour.
Exemple : User-Agent: Lynx/2.8.4rel.1 libwww-FM/2.14 SSL-MM/1.4.1 OpenSSL/0.9.6c
extraargs
Arguments supplémentaires que vous pourriez passer à curl(1). Les arguments doivent être séparés par le motif spécifié dans 'extrare', qui ne contient que le caractère espace (' ').
Remarque : curl sera appelé avec la liste d'arguments résultante sans expansion de shell. Si vous avez besoin de spécifier des arguments contenant des espaces, vous devez définir 'extrare' sur une autre valeur.
À titre d'exemple complexe, pour définir explicitement l'en-tête 'Host:' dans les requêtes Curl, vous devez définir 'extrare' sur une autre valeur, par exemple '/;/', puis spécifier "extraargs = --header;Host: www.example.com".
Exemple : -6 --head --user user:password
extrare
Le motif de séparation des arguments supplémentaires de 'extraargs', dans la notation '/regexp/'. Il ne contient que le caractère espace (' ') par défaut, mais si vous avez besoin de spécifier des arguments contenant des espaces, vous pouvez définir cette variable sur une autre valeur.
Exemple : / /
Valeur par défaut : / /
follow_redirects
Si cette variable est 'yes', curl suivra toutes les redirections HTTP (l'option '-L'). Si elle est 'no', les en-têtes 'Location:' ne seront pas suivis. Voir aussi 'include_redirects'.
Exemple : yes
Valeur par défaut : no
include_redirects
Si cette variable est 'yes', le résultat de la mesure inclura le temps passé à suivre les redirections HTTP. Si elle est 'no', seule la dernière étape sera mesurée. Voir aussi 'follow_redirects'.
Exemple : yes
Valeur par défaut : no
insecure_ssl
L'option '-k' de curl(1) pour accepter les connexions SSL sans chaîne de certificat sécurisée vers une autorité de certification approuvée. Notez que si vous surveillez des cibles https, vous devrez probablement activer cette option ou spécifier le chemin de l'AC via 'extraargs' ci-dessous. Pour plus d'informations, veuillez consulter la page de manuel de curl(1).
Exemple : 1
interface
L'option '--interface' de curl(1) pour se lier à une interface, une adresse IP ou un nom d'hôte.
Exemple : eth0
pings
Combien de pings doivent être envoyés à chaque cible, si différent de la valeur globale spécifiée dans la section 'Database'. Notez que le nombre de pings dans les fichiers rrd est fixé à l'original et si vous changez ce paramètre par la suite, vous devrez supprimer les anciens fichiers rrd ou les convertir.
Exemple : 5
ssl2
L'option '-2' de curl(1) pour forcer SSL2.
Exemple : 1
timeout
L'option '-m' de curl(1) pour le temps maximum en secondes.
Exemple : 20
Valeur par défaut : 10
urlformat
Le modèle d'URL à récupérer. Il peut s'agir de n'importe lequel de ceux que curl supporte. Chaque occurrence de '%host%' sera remplacée par l'hôte à tester.
Exemple : http://%host%/
Cette configuration est obligatoire.
write_out
Choisissez quelle valeur de write-out vous souhaitez envoyer à Smokeping. La valeur peut être l'une des suivantes : 'time_appconnect', 'time_connect', 'time_namelookup', 'time_pretransfer', 'time_redirect', 'time_starttransfer', 'time_total'. Le comportement par défaut est le même que celui de la sonde curl précédente.
Remarque : le comportement par défaut est le même que celui de la sonde curl précédente.

NOTAS

Vous devriez envisager une valeur plus basse pour la variable "pings" que la valeur par défaut de 20, car la répétition des requêtes vers les URL peut être problématique.

être assez lourd pour le serveur.

L'URL à tester était spécifiée par la variable 'url' dans les versions antérieures de Smokeping, et le réglage 'host' ne l'influençait pas d'une quelconque manière. Le nom de la variable a maintenant été changé en 'urlformat', et il peut (et dans la plupart des cas devrait) contenir un espace réservé pour la variable 'host'.

La sonde Curl héritée ne retourne que le temps de chargement de la page. Avec AnotherCurl, vous pouvez spécifier la valeur 'write-out' que vous souhaitez obtenir (veuillez vous référer à curl(1) pour plus de détails sur l'option write_out.
