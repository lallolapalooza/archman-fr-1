NOM

SMIME_write_ASN1_ex, SMIME_write_ASN1 - convertir une structure au format S/MIME

SYNOPSIS

#include <openssl/asn1.h>
int SMIME_write_ASN1_ex(BIO *out, ASN1_VALUE *val, BIO *data, int flags,
                        int ctype_nid, int econt_nid,
                        STACK_OF(X509_ALGOR) *mdalgs, const ASN1_ITEM *it,
                        OSSL_LIB_CTX *libctx, const char *propq);
int SMIME_write_ASN1(BIO *out,
    ASN1_VALUE *val, BIO *data, int flags, int ctype_nid, int econt_nid,
    STACK_OF(X509_ALGOR) *mdalgs, const ASN1_ITEM *it);

DESCRIPTION

SMIME_write_ASN1_ex() ajoute les en-têtes MIME appropriés à une structure d'objet pour produire un message S/MIME.

out est le BIO sur lequel écrire les données. valeur est la structure ASN1_VALUE appropriée (soit CMS_ContentInfo, soit PKCS7). Si le streaming est activé, le contenu doit être fourni via data. flags est un ensemble optionnel d'indicateurs. ctype_nid est le NID du type de contenu, econt_nid est le NID du type de contenu intégré et mdalgs est une liste d'algorithmes de résumé de données signées. Les valeurs valides qui peuvent être utilisées par la structure ASN.1 it sont ASN1_ITEM_rptr(PKCS7) ou ASN1_ITEM_rptr(CMS_ContentInfo). Le contexte de bibliothèque libctx et la requête de propriété propq sont utilisés lors de la récupération des algorithmes auprès des fournisseurs.

NOTES

Les fonctions de plus haut niveau SMIME_write_CMS(3) et SMIME_write_PKCS7(3) devraient être utilisées à la place de SMIME_write_ASN1().

Les indicateurs suivants peuvent être passés dans le paramètre flags.

Si CMS_DETACHED est défini, la signature en clair sera utilisée, cette option n'a de sens que pour SignedData où CMS_DETACHED est également défini lors de l'appel à la méthode sign().

Si l'indicateur CMS_TEXT est défini, les en-têtes MIME pour le type text/plain sont ajoutés au contenu, cela n'a de sens que si CMS_DETACHED est également défini.

Si l'indicateur CMS_STREAM est défini, le streaming est effectué. Cet indicateur ne doit être défini que si CMS_STREAM a également été défini dans l'appel précédent à une fonction de création de CMS_ContentInfo ou PKCS7.

Si la signature en clair est utilisée et que CMS_STREAM n'est pas défini, les données doivent être lues deux fois : une fois pour calculer la signature dans la méthode sign, et une fois pour sortir le message S/MIME.

Si le streaming est effectué, le contenu est généré au format BER en utilisant l'encodage construit de longueur indéfinie, sauf dans le cas des données signées avec contenu détaché où le contenu est absent et le format DER est utilisé.

VALEURS DE RETOUR

SMIME_write_ASN1_ex() et SMIME_write_ASN1() retournent 1 en cas de succès ou 0 en cas d'échec.
