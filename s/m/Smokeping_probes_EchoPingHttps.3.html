NOM

Smokeping::probes::EchoPingHttps - une sonde echoping(1) pour SmokePing

APERÇU

Mesure les temps d'aller-retour HTTPS (HTTP sur SSL) (serveurs web et caches) pour SmokePing.

SYNOPSIS

*** Probes ***
+EchoPingHttps
binary = /usr/bin/echoping
forks = 5
offset = 50%
step = 300
# Les variables suivantes peuvent être écrasées dans chaque section de cible
/^influx_.+/ = influx_location = Dans le sous-sol
accept_redirects = yes
extraopts = -une-lettre-que-l-auteur-n-a-pas-pensée-à
ignore_cache = yes
ipversion = 4
pings = 5
port = 80
priority = 6
prot = 3443
revalidate_data = no
timeout = 20
tos = 0xa0
url = /
waittime = 1
# [...]
*** Targets ***
probe = EchoPingHttps # si c'est la sonde par défaut
# [...]
+ mytarget
# probe = EchoPingHttps # si la sonde par défaut est autre chose
host = my.host
/^influx_.+/ = influx_location = Dans le sous-sol
accept_redirects = yes
extraopts = -une-lettre-que-l-auteur-n-a-pas-pensée-à
ignore_cache = yes
ipversion = 4
pings = 5
port = 80
priority = 6
prot = 3443
revalidate_data = no
timeout = 20
tos = 0xa0
url = /
waittime = 1

DESCRIPTION

Comme EchoPingHttp(3pm), mais avec SSL activé.

VARIABLES

Variables spécifiques à la sonde prises en charge :

binary
L'emplacement de votre exécutable echoping.

Valeur par défaut : /usr/bin/echoping

forks
Exécute ce nombre de processus simultanés au maximum.

Exemple de valeur : 5

Valeur par défaut : 5

offset
Si vous exécutez de nombreuses sondes simultanément, vous voudrez peut-être éviter qu'elles ne touchent votre réseau en même temps. En utilisant le paramètre offset spécifique à la sonde, vous pouvez changer le moment où chaque sonde sera exécutée. L'offset est spécifié en % de l'intervalle total, ou alternativement comme 'random', et l'offset de la section 'General' est utilisé si rien n'est spécifié ici. Notez que cela n'influence PAS les fichiers RRD eux-mêmes, c'est juste une question de quand l'acquisition des données est initiée. (Cette variable n'est applicable que si la variable 'concurrentprobes' est définie dans la section 'General'.)

Exemple de valeur : 50%

step
Durée de l'intervalle de base que cette sonde doit utiliser, si elle est différente de celle spécifiée dans la section 'Database'. Notez que le pas dans les fichiers RRD est fixe lorsqu'ils sont générés initialement, et si vous changez le paramètre step par la suite, vous devrez supprimer les anciens fichiers RRD ou les convertir d'une manière ou d'une autre. (Cette variable n'est applicable que si la variable 'concurrentprobes' est définie dans la section 'General'.)

Exemple de valeur : 300

Variables spécifiques à la cible prises en charge :

/^influx_.+/
C'est une étiquette qui sera envoyée à influxdb et n'a aucun impact sur la mesure de la sonde. Le nom de l'étiquette sera envoyé sans le préfixe "influx_", qui sera remplacé par "tag_" à la place. Les étiquettes peuvent être utilisées pour le filtrage.

Exemple de valeur : influx_location = Dans le sous-sol

accept_redirects
L'option "-R" de echoping(1) : Accepte les codes de statut HTTP 3xx (redirections) comme des réponses normales au lieu de les traiter comme des erreurs. Notez que cette option n'est disponible qu'à partir d'Echoping 6.

Activé si la valeur est autre chose que 'no' ou '0'.

Exemple de valeur : yes

extraopts
Toutes les options supplémentaires spécifiées ici seront passées incontestablement à echoping(1).

Exemple de valeur : -une-lettre-que-l-auteur-n-a-pas-pensée-à

ignore_cache
L'option "-A" de echoping(1) : force le proxy à ignorer le cache. Activé si la valeur est autre chose que 'no' ou '0'.

Exemple de valeur : yes

ipversion
Le protocole IP utilisé. Les valeurs possibles sont "4" et "6". Passé à echoping(1) comme les options "-4" ou "-6".

Exemple de valeur : 4

pings
Combien de pings doivent être envoyés à chaque cible, si différent de la valeur globale spécifiée dans la section Database. Notez que le nombre de pings dans les fichiers RRD est fixe lorsqu'ils sont générés initialement, et si vous changez ce paramètre par la suite, vous devrez supprimer les anciens fichiers RRD ou les convertir d'une manière ou d'une autre.

Exemple de valeur : 5

port
Le port TCP à utiliser.

Exemple de valeur : 80

priority
L'option "-p" de echoping(1).

Exemple de valeur : 6

prot
Exemple de valeur : 3443

Valeur par défaut : 443

revalidate_data
L'option "-a" de echoping(1) : force le proxy à revalider les données avec le serveur d'origine. Activé si la valeur est autre chose que 'no' ou '0'.

Exemple de valeur : no

timeout
L'option "-t" de echoping(1).

Exemple de valeur : 20

Valeur par défaut : 10

tos
L'option "-P" de echoping(1).

Exemple de valeur : 0xa0

url
L'URL à demander au serveur web ou au cache. Peut être relative (/...) pour les serveurs web ou absolue (http://...) pour les caches.

Valeur par défaut : /

waittime
L'option "-w" de echoping(1).

Exemple de valeur : 1

AUTEURS

Niko Tyni <ntyni@iki.fi>

NOTES

Vous devriez envisager de définir une valeur plus basse pour la variable "pings" que la valeur par défaut de 20, car la récupération répétée d'URL peut être assez lourde pour le serveur.

    NOM

    Smokeping::probes::EchoPingHttps - Sonde EchoPingHttps pour Smokeping

    DESCRIPTION

    Cette sonde teste la disponibilité et la latence des serveurs Web via HTTPS. Elle utilise le protocole HTTP/S pour envoyer une requête de type HEAD à une URL spécifiée et mesure le temps nécessaire pour recevoir une réponse.

    SYNTAXE

        <probe EchoPingHttps>
        url = https://www.example.com/
        # Autres options...
    </probe>

    OPTIONS

    Outre les options communes à toutes les sondes Smokeping, EchoPingHttps prend en charge les options suivantes :

    • url : L'URL complète du point de terminaison HTTPS à tester. Elle doit commencer par https://.

    • host : Spécifie l'en-tête HTTP Host à utiliser. Si non spécifié, il est dérivé de l'URL.

    • timeout : Délai d'attente en secondes pour la réponse de la requête HTTPS. La valeur par défaut est 10 secondes.

    • sslVerify : Spécifie si la vérification du certificat SSL doit être activée. La valeur par défaut est 1 (activée). Mettez à 0 pour la désactiver (non recommandé pour la production).

    • sni : Spécifie le nom du serveur à utiliser pour le SNI (Server Name Indication) lors de l'établissement de la connexion TLS. Utile lorsque le certificat du serveur couvre plusieurs noms d'hôtes. Si non spécifié, il est dérivé de l'URL.

    EXEMPLE

        <probe EchoPingHttps>
        name = ExampleHTTPS
        url = https://www.google.com/
        timeout = 5
        sslVerify = 1
    </probe>

    AUTEUR

    Thomas Reindl <th.reindl@gmail.com>

    NOTES

    Cette sonde dépend du module Perl LWP::UserAgent. Assurez-vous qu'il est installé.
