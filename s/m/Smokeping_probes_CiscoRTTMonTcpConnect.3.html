NOM

Smokeping::probes::CiscoRTTMonTcpConnect - Sonde pour SmokePing

SYNOPIS

*** Sondes ***
+CiscoRTTMonTcpConnect
forks = 5
offset = 50%
step = 300
timeout = 15
# Les variables suivantes peuvent être écrasées dans chaque section cible
/^influx_.+/ = influx_location = Dans le sous-sol
ioshost = RTTcommunity@Myrouter.foobar.com.au # obligatoire
iosint = 10.33.22.11
pings = 5
port = 80
timeout = 15
tos = 160
# [...]
*** Cibles ***
probe = CiscoRTTMonTcpConnect # si c'est la sonde par défaut
# [...]
+ ma_cible
# probe = CiscoRTTMonTcpConnect # si la sonde par défaut est autre chose
host = mon.host
/^influx_.+/ = influx_location = Dans le sous-sol
ioshost = RTTcommunity@Myrouter.foobar.com.au # obligatoire
iosint = 10.33.22.11
pings = 5
port = 80
timeout = 15
tos = 160

DESCRIPTION

Une sonde pour smokeping, qui utilise la fonctionnalité MIB ciscoRttMon ("Service Assurance Agent", "SAA") de Cisco IOS pour mesurer les temps de connexion TCP entre un routeur Cisco et un serveur TCP. La valeur mesurée est le temps nécessaire pour établir une session TCP, c'est-à-dire le temps entre le paquet TCP initial "SYN" du routeur et le paquet "SYN ACK" de l'hôte. Le routeur termine la session TCP immédiatement après la réception du "SYN ACK" avec un paquet "FIN".

VARIABLES

Variables spécifiques à la sonde prises en charge :

forks
Exécuter ce nombre de processus simultanés au maximum

Exemple de valeur : 5

Valeur par défaut : 5

offset
Si vous exécutez de nombreuses sondes simultanément, vous voudrez peut-être éviter qu'elles n'atteignent votre réseau en même temps. En utilisant le paramètre d'offset spécifique à la sonde, vous pouvez modifier le moment où chaque sonde sera exécutée. L'offset est spécifié en % de l'intervalle total, ou alternativement comme 'random', et l'offset de la section 'General' est utilisé si rien n'est spécifié ici. Notez que cela n'influence PAS les RRD eux-mêmes, il s'agit simplement d'une question de moment où l'acquisition des données est initiée. (Cette variable n'est applicable que si la variable 'concurrentprobes' est définie dans la section 'General'.)

Exemple de valeur : 50%

step
Durée de l'intervalle de base que cette sonde doit utiliser, si elle est différente de celle spécifiée dans la section 'Database'. Notez que le pas dans les fichiers RRD est fixe lorsqu'ils sont générés à l'origine, et si vous modifiez le paramètre de pas par la suite, vous devrez supprimer les anciens fichiers RRD ou les convertir d'une manière ou d'une autre. (Cette variable n'est applicable que si la variable 'concurrentprobes' est définie dans la section 'General'.)

Exemple de valeur : 300

timeout
Combien de temps prend un seul 'ping' au maximum

Exemple de valeur : 15

Valeur par défaut : 5

Variables spécifiques à la cible prises en charge :

/^influx_.+/
Il s'agit d'une étiquette qui sera envoyée à influxdb et n'a aucun impact sur la mesure de la sonde. Le nom de l'étiquette sera envoyé sans le préfixe "influx_", qui sera remplacé par "tag_". Les étiquettes peuvent être utilisées pour le filtrage.

Exemple de valeur : influx_location = Dans le sous-sol

ioshost
Le paramètre ioshost (obligatoire) spécifie le routeur Cisco, qui établira les connexions TCP ainsi que la chaîne communautaire SNMP sur le routeur.

Exemple de valeur : RTTcommunity@Myrouter.foobar.com.au

Ce réglage est obligatoire.

iosint
Le paramètre iosint (facultatif) est l'adresse source pour les connexions TCP. Il doit s'agir de l'une des adresses IP actives (!) du routeur pour obtenir des résultats. IOS recherche l'adresse de l'hôte cible dans la table de routage, puis utilise l'interface(s) qui y sont répertoriées pour envoyer les paquets TCP. Par défaut, IOS utilise l'adresse IP (principale) sur l'interface d'envoi comme adresse source pour une connexion.

Exemple de valeur : 10.33.22.11

pings
Combien de pings doivent être envoyés à chaque cible, si différent de la valeur globale spécifiée dans la section Database. Notez que le nombre de pings dans les fichiers RRD est fixe lors de leur génération initiale, et si vous modifiez ce paramètre par la suite, vous devrez supprimer les anciens fichiers RRD ou les convertir d'une manière ou d'une autre.

Exemple de valeur : 5

port
Le paramètre port (facultatif) vous permet de configurer le port TCP de destination sur l'hôte. La valeur par défaut est le port http 80.

Valeur par défaut : 80

timeout
Combien de temps prend un 'ping' RTTMon TcpConnect au maximum plus 10 secondes pour être tranquille. Puisque nous contrôlons notre propre délai d'expiration, le seul but de ceci est de ne pas être éliminé par la méthode ping de basefork.

Exemple de valeur : 15

Valeur par défaut : 15

tos
Le paramètre tos (facultatif) spécifie la valeur de l'octet ToS dans l'en-tête IP des paquets provenant du routeur. Multipliez les valeurs DSCP par 4 et les valeurs de priorité par 32 pour calculer les valeurs ToS à configurer, par exemple, ToS 160 correspond à une valeur DSCP de 40 et une valeur de priorité de 5. Veuillez noter que cela n'influencera pas la valeur ToS dans les paquets envoyés par l'hôte.

Exemple de valeur : 160

Valeur par défaut : 0

NOTES

VERSIONS IOS

Cette sonde ne fonctionne qu'avec Cisco IOS 12.0(3)T ou supérieur. Il est recommandé de la tester d'abord sur des routeurs moins critiques.

INSTALLATION

Pour installer cette sonde, copiez ciscoRttMonMIB.pm dans ($SMOKEPINGINSTALLDIR)/Smokeping/lib et CiscoRTTMonTcpConnect.pm dans ($SMOKEPINGINSTALLDIR)/lib/Smokeping/probes. V0.97 ou supérieur de SNMP_Session.pm de Simon Leinen est requis.

Le(s) routeur(s) doit (doivent) être configuré(s) pour permettre l'accès SNMP en lecture/écriture. Suffisant est :

snmp-server community RTTCommunity RW

Si vous souhaitez être un peu plus restrictif avec l'accès SNMP en écriture au routeur, envisagez de configurer quelque chose comme ceci :

access-list 2 permit 10.37.3.5
snmp-server view RttMon ciscoRttMonMIB included
snmp-server community RTTCommunity view RttMon RW 2

La configuration ci-dessus accorde l'accès SNMP lecture-écriture uniquement à 10.37.3.5 (l'hôte smokeping) et uniquement à l'arborescence MIB ciscoRttMon. La sonde n'a pas besoin d'accéder aux variables SNMP en dehors de l'arborescence RttMon.

BOGUES

La sonde établit des connexions inutiles, c'est-à-dire plus que ce qui est configuré dans la variable "pings", car la MIB RTTMon ne permet que de définir une durée totale pour toutes les connexions lors d'une exécution de mesure (une "vie"). Actuellement, la sonde définit la durée de vie à "pings"*5+3 secondes (5 secondes est la valeur de délai d'attente codée en dur dans cette sonde).
