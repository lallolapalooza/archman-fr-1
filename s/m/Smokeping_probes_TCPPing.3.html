NOM

Smokeping::probes::TCPPing - Sonde TCPPing pour SmokePing

SYNTAXE

*** Sondes ***
+TCPPing
binary = /usr/bin/tcpping # obligatoire
forks = 5
offset = 50%
step = 300
timeout = 15
# Les variables suivantes peuvent être redéfinies dans chaque section cible
/^influx_.+/ = influx_location = Dans la cave
pings = 5
port = 80
# [...]
*** Cibles ***
probe = TCPPing # si ceci doit être la sonde par défaut
# [...]
+ ma_cible
# probe = TCPPing # si la sonde par défaut est autre chose
host = mon.hote
/^influx_.+/ = influx_location = Dans la cave
pings = 5
port = 80

DESCRIPTION

Intègre TCPPing comme sonde dans smokeping. La variable binary doit pointer vers votre copie du programme TCPPing. S'il n'est pas encore installé sur votre système, vous pouvez l'obtenir à l'adresse https://github.com/deajan/tcpping.

L'option (facultative) port vous permet de configurer le port pour les pings envoyés. La page de manuel de TCPPing dit ceci à ce sujet :

Le problème est qu'avec l'utilisation généralisée des pare-feux sur l'Internet moderne, bon nombre des paquets envoyés par traceroute(8) finissent par être filtrés, rendant impossible de retracer complètement le chemin vers la destination. Cependant, dans de nombreux cas, ces pare-feux autoriseront les paquets TCP entrants vers des ports spécifiques sur lesquels les hôtes derrière le pare-feu écoutent les connexions. En envoyant des paquets TCP SYN au lieu de paquets UDP ou ICMP ECHO, tcptraceroute est capable de contourner les filtres de pare-feu les plus courants.

Il est à noter que tcptraceroute n'établit jamais complètement une connexion TCP avec l'hôte de destination. Si l'hôte n'écoute pas les connexions entrantes, il répondra avec un RST indiquant que le port est fermé. Si l'hôte répond plutôt avec un SYN|ACK, le port est connu pour être ouvert, et un RST est envoyé par le noyau sur lequel tcptraceroute s'exécute pour terminer la connexion sans compléter la poignée de main en trois temps. C'est la même technique de balayage semi-ouvert que nmap(1) utilise lorsqu'il est appelé avec l'option -sS.

VARIABLES

Variables spécifiques à la sonde prises en charge :

binary
L'emplacement de votre script tcpping.

Exemple de valeur : /usr/bin/tcpping

Ce réglage est obligatoire.

forks
Exécute ce nombre de processus concurrents au maximum

Exemple de valeur : 5

Valeur par défaut : 5

offset
Si vous exécutez de nombreuses sondes simultanément, vous voudrez peut-être éviter qu'elles ne frappent votre réseau toutes en même temps. En utilisant le paramètre offset spécifique à la sonde, vous pouvez modifier le moment où chaque sonde sera exécutée. L'offset est spécifié en % de l'intervalle total, ou alternativement comme 'random', et l'offset de la section 'General' est utilisé si rien n'est spécifié ici. Notez que cela n'influence PAS les fichiers rrds eux-mêmes, il s'agit simplement d'une question de quand l'acquisition des données est initiée. (Cette variable n'est applicable que si la variable 'concurrentprobes' est définie dans la section 'General'.)

Exemple de valeur : 50%

step
Durée de l'intervalle de base que cette sonde doit utiliser, si différent de celui spécifié dans la section 'Database'. Notez que le pas dans les fichiers RRD est fixe lorsqu'ils sont générés à l'origine, et si vous changez le paramètre step par la suite, vous devrez supprimer les anciens fichiers RRD ou les convertir d'une manière ou d'une autre. (Cette variable n'est applicable que si la variable 'concurrentprobes' est définie dans la section 'General'.)

Exemple de valeur : 300

timeout
Combien de temps prend un 'ping' unique au maximum

Exemple de valeur : 15

Valeur par défaut : 5

Variables spécifiques à la cible prises en charge :

/^influx_.+/
Ceci est une étiquette qui sera envoyée à influxdb et n'a aucun impact sur la mesure de la sonde. Le nom de l'étiquette sera envoyé sans le préfixe "influx_", qui sera remplacé par "tag_". Les étiquettes peuvent être utilisées pour le filtrage.

Exemple de valeur : influx_location = Dans la cave

pings
Combien de pings doivent être envoyés à chaque cible, si différent de la valeur globale spécifiée dans la section Database. Notez que le nombre de pings dans les fichiers RRD est fixe lors de leur génération initiale, et si vous changez ce paramètre par la suite, vous devrez supprimer les anciens fichiers RRD ou les convertir d'une manière ou d'une autre.

Exemple de valeur : 5

port
Le port TCP que la sonde doit mesurer.

Exemple de valeur : 80
