NAME

Smokeping::probes::WebProxyFilter - vérifie la fonctionnalité et les performances d'un filtre de proxy web.

OVERVIEW

Ce test vérifie si votre filtre de proxy web fonctionne comme il se doit. Il tire une liste de sites web interdits, essaie d'établir une connexion avec chacun d'eux et enregistre une 'perte' lorsqu'une connexion est établie.

Si vous souhaitez tester la disponibilité d'un site web, utilisez le test EchoPingHttp.

SYNOPSIS

*** Probes ***
+WebProxyFilter
forks = 5
maxsize = 2000
min_interval = 0.1
offset = 50%
step = 300
timeout = 15
useragent = SmokePing/2.x (WebProxyFilter Probe)
# Les variables suivantes peuvent être écrasées dans chaque section cible
/^influx_.+/ = influx_location = Dans le sous-sol
deny_re = Accès interdit
more_hosts = www.playboy.com, www.our-competition.com
pings = 5
timeout = 2
# [...]
*** Cibles ***
probe = WebProxyFilter # si c'est le probe par défaut
# [...]
+ mytarget
# probe = WebProxyFilter # si le probe par défaut est différent
host = my.host
/^influx_.+/ = influx_location = Dans le sous-sol
deny_re = Accès interdit
more_hosts = www.playboy.com, www.our-competition.com
pings = 5
timeout = 2

DESCRIPTION

Le probe utilise le module LWP::UserAgent pour récupérer un certain nombre de pages web. Il s'attend à obtenir la page 'site-interdit' des firewalls. Toute réponse (ou une perte réelle) est enregistrée comme une perte et peut déclencher une alerte.

Le probe essaie d'être gentil avec le firewall et attend au moins X secondes entre le démarrage des transferts de fichiers, où X est la valeur de la variable spécifique au probe 'min_interval' (par défaut 1).

De nombreuses variables peuvent être spécifiées dans le probe et dans la définition de la cible, et la variable de la cible spécifique écrase les variables du probe.

VARIABLES

Variables spécifiques au probe :

forks
Autant de processus simultanés que maximum

Valeur exemple : 5

Valeur par défaut : 5

maxsize
Quelle partie de la page web doit être récupérée.

Valeur par défaut : 2000

min_interval
L'intervalle minimum entre chaque début de GET en secondes.

Valeur exemple : 0.1

Valeur par défaut : 1

offset
Si vous exécutez de nombreux sondes simultanément, vous voudrez peut-être éviter que toutes ne frappent votre réseau en même temps. En utilisant le paramètre d'offset spécifique au probe, vous pouvez modifier le point auquel chaque sonde s'exécute. L'offset est spécifié en % de l'intervalle total, ou alternativement comme 'random', et l'offset de la section 'General' est utilisé si rien n'est spécifié ici. Remarque : ce paramètre n'affecte pas les RRD, il s'agit simplement d'une question de savoir quand les données commenceront à être collectées. (Cette variable n'est applicable que si la variable 'concurrentprobes' est définie dans la section 'General').

Valeur exemple : 50%

step
La période de base que ce probe devrait utiliser, si différente de celle spécifiée dans la section 'Database'. Remarque : le pas dans les fichiers RRD est fixe au moment de leur génération, et si vous modifiez ce paramètre par la suite, vous devrez supprimer les anciens fichiers RRD ou les convertir. (Cette variable n'est applicable que si la variable 'concurrentprobes' est définie dans la section 'General').

Valeur exemple : 300

timeout
Le temps maximum autorisé pour un 'ping'.

Valeur exemple : 15

Valeur par défaut : 5

useragent
Le navigateur Web que nous prétendons être, juste au cas où le FW serait intéressé.

Valeur par défaut : SmokePing/2.x (WebProxyFilter Probe)

Variables spécifiques à la cible :

/^influx_.+/
Il s'agit d'une balise envoyée à influxdb et n'affecte pas la mesure du probe. Le nom de la balise est envoyé sans le préfixe 'influx_', qui est remplacé par 'tag_'. Les balises peuvent être utilisées pour le filtrage.

Valeur exemple : influx_location = Dans le sous-sol

deny_re
Expression régulière qui correspond à la réponse 'refus' du pare-feu.

Valeur exemple : Accès interdit

more_hosts
Une liste séparée par des virgules de sites Web interdits à tester en plus de celui spécifié dans la variable host. Les sites seront testés les uns après les autres en cycle, ce qui signifie que bien que les sondes normales exécutent le même test plusieurs fois de suite, celui-ci modifie la page Web à chaque cycle. La raison en est que bien que nous essayions de récupérer des pages Web distantes, la réponse provient toujours du pare-feu, donc nous parvenons à "faire d'une pierre deux coups". D'abord, nous testons la latence du pare-feu, puis nous nous assurons que son filtre fonctionne correctement.

Valeur exemple : www.playboy.com, www.our-competition.com

pings
Combien de pings doivent être envoyés à chaque cible, si différent de la valeur globale spécifiée dans la section 'Database'. Remarque : le nombre de pings dans les fichiers RRD est fixe au moment de leur génération, et si vous modifiez ce paramètre par la suite, vous devrez supprimer les anciens fichiers RRD ou les convertir.

Valeur exemple : 5

timeout
Le temps en secondes pour que le test complet s'achève.

Valeur exemple : 2

Valeur par défaut : 2

AUTHORS

Tobias Oetiker <tobi@oetiker.ch> parrainé par Virtela

BUGS

Ce probe est quelque peu peu orthodoxe car il considère la récupération réussie d'une page Web interdite comme une perte.
