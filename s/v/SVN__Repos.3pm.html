NOM

SVN::Repos - Fonctions de dépôt Subversion

SYNTAXE

use SVN::Core;
use SVN::Repos;
my $repos = SVN::Repos::open('/chemin/vers/le/repos');
print $repos->fs()->youngest_rev;

DESCRIPTION

SVN::Repos encapsule les fonctions orientées objet de svn_repos_t, donnant accès à un dépôt Subversion sur le système de fichiers local.

CONSTRUCTEURS

SVN::Repos::open($chemin)
Cette fonction ouvre un dépôt existant et retourne un objet SVN::Repos.
create($chemin, undef, undef, $config, $fs_config)
Cette fonction crée un nouveau dépôt et retourne un objet SVN::Repos.

MÉTHODES

$repos->dump_fs($dump_fh, $feedback_fh, $start_rev, $end_rev, $incremental, $deltify, $cancel_callback)
$repos->dump_fs2($dump_fh, $feedback_fh, $start_rev, $end_rev, $incremental, $deltify, $cancel_callback)
Crée un fichier de vidage du dépôt de la révision $start_rev à $end_rev et le sauvegarde dans le fichier $dump_fh. Le feedback est écrit dans le fichier $feedback_fh. Si $incremental est VRAI, la première révision vidée sera une différence par rapport à la précédente (ce qui ressemble généralement à un vidage complet de l'arbre). Si $use_deltas est VRAI, seuls les propriétés des nœuds ayant changé par rapport aux contenus précédents sont montrées, et les contenus textes sont montrés comme des données svndiff par rapport aux contenus précédents. Indépendamment de la valeur de ce drapeau, la première révision d'un vidage non incrémental sera faite avec du texte brut complet. Un vidage avec @a use_deltas défini ne peut pas être chargé par Subversion 1.0.x. Si $cancel_callback n'est pas "undef", il doit s'agir d'une référence de code appelée périodiquement pour déterminer si le client souhaite annuler le vidage. Voir « ANNULATION DE CALLBACK » dans SVN::Client pour plus de détails.
$repos->load_fs($dumpfile_fh, $feedback_fh, $uuid_action, $parent_dir, $cancel_callback);
$repos->load_fs2($dumpfile_fh, $feedback_fh, $uuid_action, $parent_dir, $use_pre_commit_hook, $use_post_commit_hook, $cancel_callback);
Charge un fichier de vidage spécifié par $dumpfile_fh dans le dépôt. Si le flux de vidage contient un historique de copie non disponible dans le dépôt, une erreur sera levée. L'UUID du dépôt sera mis à jour si le flux de vidage contient un UUID et que $uuid_action n'est pas égal à $SVN::Repos::load_uuid_ignore et que le dépôt n'a pas de révisions ou que $uuid_action est égal à $SVN::Repos::load_uuid_force.
$repos->fs()
Retourne l'objet "SVN::Fs" pour ce dépôt.
$repos->get_logs([$chemin, ...], $début, $fin, $discover_changed_paths, $strict_node_history, $receiver)
Itère sur toutes les révisions affectant la liste des chemins fournis en premier paramètre, commençant à $début et se terminant à $fin. Le $receiver est appelé pour chaque changement. Les arguments de $receiver sont :
$self
L'objet "SVN::Repos".
$chemins
Est "undef" si $discover_changed_paths est faux. Sinon, il contient une table de hachage des chemins qui ont changé dans cette révision.
$rev
La révision où ce changement a été effectué.
$date
La date et l'heure auxquelles cette révision a été effectuée.
$msg
Le message de log associé à cette révision.
$pool
Un objet "SVN::Pool" qui peut être utilisé dans la fonction.

Si $strict_node_history est vrai, les copies ne sont pas tracées.
