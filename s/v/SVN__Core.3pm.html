NOM

SVN::Core - Module d'implémentation de base de Subversion dans les bindings Perl

SYNTAXE

use SVN::Core; # démarre et arrête le contexte APR pour vous
# crée un pool racine et le définit comme le pool par défaut pour une utilisation ultérieure
my $pool = SVN::Pool->new_default;
sub something {
    # crée un sous-pool du pool par défaut actuel
    my $pool = SVN::Pool->new_default_sub;
    # quelques opérations SVN...
    # $pool est détruit et le pool par défaut précédent est restauré lorsque le scope de $pool se termine
}
# handle IO natif comme svn_stream_t
my $stream = $txn->root->apply_text('trunk/filea', undef);
print $stream $text;
close $stream;
# handle IO natif comme svn_stream_t
SVN::Repos::dump_fs($repos, \*STDOUT, \*STDERR,
                    0, $repos->fs->youngest_rev, 0);

DESCRIPTION

SVN::Core implémente les fonctions de haut niveau des fonctions fondamentales de Subversion.

FONCTIONS

SVN::Core::auth_open([auth provider array]);
Prend une référence vers un tableau de fournisseurs d'authentification et renvoie un auth_baton. Si vous utilisez des fournisseurs d'authentification avec prompt, vous ne pouvez pas utiliser cette fonction, mais devez utiliser auth_open_helper.
SVN::Core::auth_open_helper([auth provider array]);
Les fournisseurs d'authentification avec prompt renvoient deux valeurs au lieu d'une. Le second paramètre est une référence à ce qui leur a été passé comme callback. auth_open_helper décompose ces arguments, passant les objets fournisseurs à auth_open, ce qui vous donne un auth_baton et le reste dans un tableau. La première valeur renvoyée par cette fonction est l'auth_baton, la seconde est une référence vers un tableau contenant les références vers les callbacks.

Ces tableaux de callbacks doivent être stockés dans l'objet auquel l'auth_baton est associé.

AUTRES OBJETS

svn_stream_t - SVN::Stream

Vous pouvez utiliser des handles IO natifs (y compris les handles IO globaux) comme svn_stream_t dans les fonctions Subversion. Les svn_stream_t renvoyés sont également convertis en handles IO en Perl, vous pouvez donc y accéder avec print, read, etc.

Note : certaines fonctions prennent un stream pour lire ou écrire, mais ne ferment pas le stream tout en conservant la référence au handle IO. Dans ce cas, le handle ne sera pas correctement détruit. Vous devez toujours définir le pool par défaut correctement avant d'appeler de telles fonctions.

svn_pool_t - SVN::Pool

Les bindings Perl simplifient considérablement l'utilisation des pools, bien que vous puissiez toujours les ajuster manuellement.

Pour les fonctions qui nécessitent un pool comme dernier argument (ce qui est le cas de presque toutes les fonctions Subversion), l'argument du pool est optionnel. Le pool par défaut est utilisé si aucun n'est spécifié. Lors du chargement de SVN::Core, il crée un nouveau pool par défaut, qui est également disponible via SVN::Core->gpool.

Pour les fonctions qui fournissent un pool à votre sous-routine, vous pouvez également utiliser $pool->default pour en faire le pool par défaut dans le scope.

Méthodes

new([$parent])
Crée un nouveau pool. Le pool est un pool racine si $parent n'est pas fourni.
new_default([$parent])
Crée un nouveau pool. Le pool est un pool racine si $parent n'est pas fourni. Définit le nouveau pool comme pool par défaut.
new_default_sub
Crée un sous-pool du pool par défaut actuel et définit le pool résultant comme nouveau pool par défaut.
clear
Nettoie le pool.
DESTROY
Détruit le pool. Si le pool était le pool par défaut, restaure le pool par défaut précédent. Ceci est appelé automatiquement lorsque l'objet SVN::Pool n'est plus utilisé et est détruit par le garbage collector Perl.

svn_error_t - SVN::Error

Par défaut, les bindings Perl gèrent les exceptions pour vous. Le gestionnaire par défaut croak automatiquement avec un message d'erreur approprié. Ceci est suffisant pour des scripts simples, mais pour une utilisation plus complexe, les exceptions doivent être gérées.

Vous pouvez remplacer le gestionnaire par défaut en modifiant la variable $SVN::Error::handler. Cette variable contient une référence à une sous-routine Perl qui est appelée chaque fois qu'une exception est renvoyée par une fonction svn. Cette sous-routine recevra un objet svn_error_t. Sa valeur de retour est ignorée.

Si vous définissez $SVN::Error::handler sur undef, chaque appel renverra un objet svn_error_t comme premier retour en cas d'erreur, suivi des valeurs de retour normales. S'il n'y a pas d'erreur, aucun objet svn_error_t ne sera renvoyé et seules les valeurs de retour normales seront renvoyées. En utilisant ce mode, vous devez être prudent et appeler uniquement dans un contexte de tableau. Par exemple : my ($ci) = $ctx->mkdir('http://svn/foo'); Dans ce cas, $ci sera un objet svn_error_t si une erreur se produit et un objet svn_client_commit_info sinon. Si vous omettez les parenthèses autour de $ci (contexte scalaire), ce sera l'objet commit_info, qui en cas d'erreur sera undef.

Si vous prévoyez d'utiliser la gestion explicite des exceptions, il est utile de comprendre le système de gestion des exceptions utilisé par l'API C. Vous pouvez trouver des informations à ce sujet dans le fichier HACKING et la documentation de l'API. Vérifier l'implémentation de SVN::Error::croak_on_error et SVN::Error::expanded_message peut également être utile.

$svn_error_t->apr_err()
Valeur d'erreur APR, potentiellement une erreur SVN personnalisée.
$svn_error_t->message()
Détails du producteur de l'erreur.
$svn_error_t->child()
Objet svn_error_t de l'erreur qui est encapsulée.
$svn_error_t->pool()
Le pool qui contient cette erreur et toute erreur enfant encapsulée.
$svn_error_t->file()
Le fichier où l'erreur s'est produite.
$svn_error_t->line()
La ligne du fichier où l'erreur s'est produite.
SVN::Error::strerror($apr_status_t)
Renvoie la description en anglais du code d'état.
$svn_error_t->strerror()
Renvoie la description en anglais du code d'erreur apr_err de l'objet svn_error_t. Ceci est un raccourci pour : SVN::Error::strerror($svn_error_t->apr_err());
SVN::Error::create($apr_err, $child, $message);
Renvoie un nouvel objet svn_error_t avec le statut d'erreur spécifié dans $apr_err, l'enfant comme $child, et le message d'erreur de $message.
SVN::Error::quick_wrap($child, $new_msg); ou $child->quick_wrap($new_msg);
Une méthode rapide et facile pour créer un wrapper d'exception avec votre propre message avant de le faire remonter dans la pile.

Le $child est l'objet svn_error_t que vous souhaitez encapsuler et $new_msg est le nouveau message d'erreur que vous souhaitez définir.

SVN::Error::compose($chain, $new_error); ou $chain->compose($new_error);
Ajoute $new_error à la fin de la chaîne d'erreurs de $chain.

Le $new_err sera copié dans le pool de $chain et détruit, donc $new_err devient invalide après cette fonction.

svn_depth_t - SVN::Depth

Une énumération des constantes suivantes :

$SVN::Depth::unknown
Profondeur indéterminée ou ignorée. Dans certains contextes, cela signifie que le client doit choisir une profondeur par défaut appropriée. Le serveur la traitera généralement comme $SVN::Depth::infinity.
$SVN::Depth::exclude
Exclure (c'est-à-dire ne pas descendre dans) le répertoire D.

Note : Dans Subversion 1.5, $SVN::Depth::exclude n'est **pas** pris en charge nulle part dans le code côté client (Wc/Client/etc) ; il n'est pris en charge qu'en tant qu'argument des fonctions set_path dans les reporters Ra et Repos. (Cela permettra aux futures versions de Subversion d'exécuter des mises à jour, etc., contre des serveurs 1.5 avec un comportement $SVN::Depth::exclude correct, une fois que nous aurons la possibilité d'implémenter la prise en charge côté client de $SVN::Depth::exclude).

$SVN::Depth::empty
Juste le répertoire nommé D, aucune entrée.

Les mises à jour n'incluront aucun fichier ou sous-répertoire non présent.

$SVN::Depth::files
D + ses fichiers enfants, mais pas les sous-répertoires.

Les mises à jour incluront tous les fichiers non présents, mais pas les sous-répertoires.

$SVN::Depth::immediates
D + enfants immédiats (D et ses entrées).

Les mises à jour incluront tous les fichiers ou sous-répertoires non présents ; les entrées 'this_dir' de ces sous-répertoires auront une profondeur 'depth-empty'.

$SVN::Depth::infinity
D + tous les descendants (récursion complète depuis D).

Les mises à jour incluront tous les fichiers ou sous-répertoires non présents ; les entrées 'this_dir' de ces sous-répertoires auront une profondeur 'depth-infinity'. Équivalent au comportement de mise à jour par défaut avant la version 1.5.

svn_opt_revision_t

Une révision, spécifiée d'une des manières "SVN::Core::opt_revision_*".

Une énumération indiquant comment la révision $rev a été spécifiée. Une parmi $SVN::Core::opt_revision_unspecified, $SVN::Core::opt_revision_number, $SVN::Core::opt_revision_date, $SVN::Core::opt_revision_committed, $SVN::Core::opt_revision_previous, $SVN::Core::opt_revision_base, $SVN::Core::opt_revision_working ou $SVN::Core::opt_revision_head.

Données supplémentaires sur la révision. Uniquement pertinent si "$rev->kind" est $SVN::Core::opt_revision_number (où il contient le numéro de révision) ou $SVN::Core::opt_revision_date (où il contient une date).

_p_svn_lock_t

Les objets de cette classe contiennent des informations sur les verrous placés sur les fichiers dans un dépôt. Elle possède les méthodes d'accès suivantes :

path
Le chemin complet vers le fichier qui est verrouillé, commençant par une barre oblique ("/").
token
Une chaîne contenant le jeton de verrouillage, qui est une URI unique.
owner
Le nom d'utilisateur de celui qui possède le verrou.
comment
Un commentaire associé au verrou, ou undef s'il n'y en a pas.
is_dav_comment
Vrai si le commentaire a été fait par un client DAV générique.
creation_date
L'heure à laquelle le verrou a été créé, sous forme de nombre de microsecondes depuis 00:00:00 le 1er janvier 1970 UTC. Divisez-le par 1 000 000 pour obtenir une valeur time_t Unix.
expiration_date
Quand le verrou expirera. A la valeur '0' si le verrou n'expirera jamais.
