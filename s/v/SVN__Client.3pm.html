DESCRIPTION

SVN::Client encapsule les fonctions de plus haut niveau fournies par subversion pour accomplir des tâches spécifiques dans une API orientée objet. Les méthodes sont similaires aux fonctions fournies par l'API C et en tant que tel, la documentation de celle-ci peut être utile pour comprendre cette interface.

Il y a quelques différences notables par rapport à l'API C. La plupart des appels de fonction C prennent un pointeur svn_client_ctx_t comme avant-dernier paramètre. Les appels de méthode Perl prennent un objet SVN::Client comme premier paramètre. Cela permet l'invocation des méthodes sous forme d'appels de méthode. Par exemple, les lignes suivantes sont équivalentes :

SVN::Client::add($client,$path, $recursive, $pool);
$client->add($path, $recursive, $pool);

Beaucoup des appels de l'API C prennent également un pointeur apr_pool_t comme dernier argument. Les liaisons Perl s'occupent généralement de cela pour vous et vous n'avez pas besoin de passer un paramètre de pool. Cependant, vous pouvez toujours passer un paramètre de pool comme dernier argument pour remplacer la gestion automatique de cela pour vous.

Les utilisateurs de cette interface ne doivent pas manipuler directement les valeurs de hachage sous-jacentes mais doivent utiliser les méthodes d'attributs respectives. Beaucoup de ces méthodes d'attributs font d'autres choses, surtout lors de la définition d'un attribut, en plus de simplement manipuler la valeur dans le hachage.

NOTES SUR LES PARAMÈTRES

Les méthodes client décrites ci-dessous prennent une variété de paramètres. Beaucoup d'entre eux sont similaires. Les méthodes acceptant les paramètres nommés ci-dessous suivront les règles ci-dessous ou seront notées autrement dans la description de la méthode.

$client
Un objet SVN::Client que vous obtenez du constructeur.
$url
Ceci est une URL vers un dépôt subversion.
$path
Ceci est un chemin vers un fichier ou un répertoire sur le système de fichiers local. Les chemins doivent être canonisés avant d'être passés aux API Subversion. Les chemins sur le système de fichiers local sont appelés dirents et peuvent être canonisés en appelant "SVN::Core::dirent_canonicalize".
$paths
Cet argument peut être soit un $path unique (tel que défini ci-dessus) soit une référence à un tableau de ceux-ci.
$target
Ceci est un chemin vers un fichier ou un répertoire dans une copie de travail ou une URL vers un fichier ou un répertoire dans un dépôt subversion. Les chemins et les URL doivent être canonisés avant d'être passés aux API Subversion. Les chemins sur le système de fichiers local sont appelés dirents et peuvent être canonisés en appelant "SVN::Core::dirent_canonicalize". Les URL peuvent être canonisées en appelant "SVN::Core::uri_canonicalize".
$targets
Cet argument peut être soit un $target unique (tel que défini ci-dessus) soit une référence à un tableau de ceux-ci.
$revision
Ceci spécifie une révision dans le dépôt Subversion. Vous pouvez spécifier une révision de plusieurs manières. La plus facile et la plus évidente est de fournir directement le numéro de révision. Vous pouvez également utiliser les chaînes (alias mots-clés de révision) 'HEAD', 'BASE', 'COMMITTED', et 'PREV' qui ont les mêmes significations que dans le client en ligne de commande. Lors de la référence à une copie de travail, vous pouvez utiliser la chaîne 'WORKING' pour faire référence à BASE plus toute modification locale. "undef" peut être utilisé pour spécifier une révision non spécifiée. Vous pouvez également passer une date en spécifiant la date entre accolades '{}'. Les formats de date acceptés sont les mêmes que ceux acceptés par le client en ligne de commande. Enfin, un objet "_p_svn_opt_revision_t" est accepté (qui pourrait avoir été retourné par certaines fonctions Subversion).
$recursive $nonrecursive.
Un paramètre booléen qui spécifie si l'action doit suivre les répertoires. Il doit seulement être 1 ou 0. $recursive signifie, 1 pour descendre dans les répertoires, 0 pour ne pas le faire. $nonrecursive a le sens inverse.
$pool
Pool est toujours un paramètre optionnel. Si vous souhaitez passer un paramètre de pool, il doit s'agir d'un objet SVN::Pool ou apr_pool_t.

La $peg_revision définit la révision à laquelle le chemin dans l'$url est traité comme représentant.

$allow_unver_obstructions s'il est défini à VRAI, l'opération tolérera les éléments non versionnés existants qui obstruent les chemins entrants. $client->commit($targets, $nonrecursive, $pool);
Commite les fichiers ou répertoires référencés par la cible. Utilisera le rappel log_msg pour obtenir le message de log pour le commit.

Si $targets ne contient aucun chemin (zéro élément), alors ne fait rien et retourne immédiatement sans erreur.

Appelle le rappel notify au fur et à mesure de la progression du commit avec l'une des actions suivantes : $SVN::Wc::Notify::Action::commit_modified, $SVN::Wc::Notify::Action::commit_added, $SVN::Wc::Notify::Action::commit_deleted, $SVN::Wc::Notify::Action::commit_replaced, $SVN::Wc::Notify::Action::commit_postfix_txdelta.

Utilisez $nonrecursive pour indiquer que les sous-répertoires des cibles de répertoires doivent être ignorés.

Renvoie un objet svn_client_commit_info_t. Si la révision membre de l'objet d'informations de commit est $SVN::Core::INVALID_REVNUM et qu'aucune erreur n'a été levée, alors le commit était un no-op ; rien n'avait besoin d'être commité.

$client->copy($src_target, $src_revision, $dst_target, $pool);
Copie $src_target vers $dst_target.

$src_target doit être un fichier ou un répertoire sous contrôle de version, ou l'URL d'un élément versionné dans le dépôt. Si $src_target est une URL, $src_revision est utilisé pour choisir la révision à partir de laquelle copier le $src_target. $dst_path doit être un fichier ou un répertoire sous contrôle de version, ou une URL de dépôt, existant ou non.

Si $dst_target est une URL, tente immédiatement de commiter l'action de copie dans le dépôt. Le rappel log_msg sera appelé pour demander un message de log de commit. Si le commit réussit, renvoie un objet svn_client_commit_info_t.

Si $dst_target n'est pas une URL, alors il s'agit d'une variante de $client->add(), où les éléments $dst_path sont planifiés pour ajout en tant que copies. Aucun changement ne sera apporté au dépôt tant qu'un commit n'aura pas eu lieu. Cette planification peut être supprimée avec $client->revert(). Indéfini sera renvoyé dans ce cas.

Appelle le rappel notify pour chaque élément ajouté au nouvel emplacement, en passant le chemin nouveau et relatif de l'élément ajouté.

$client->delete($targets, $force, $pool);
Supprime des éléments d'un dépôt ou d'une copie de travail.

Si les chemins dans $targets sont des URLs, tente immédiatement de commiter une suppression des URLs du dépôt. Le rappel log_msg sera appelé pour demander un message de log de commit. Si le commit réussit, renvoie un objet svn_client_commit_info_t. Chaque chemin doit appartenir au même dépôt.

Sinon, planifie la suppression des chemins de copie de travail dans $targets du dépôt. Le parent de chaque chemin doit être sous contrôle de révision. Il ne s'agit que d'une opération de planification. Aucun changement ne sera apporté au dépôt tant qu'un commit n'aura pas eu lieu. Cette planification peut être supprimée avec $client->revert(). Si un chemin est un fichier, il est immédiatement supprimé de la copie de travail. Si le chemin est un répertoire, il restera dans la copie de travail mais tous les fichiers, et tous les éléments non versionnés qu'il contient, seront supprimés. Si $force n'est pas défini, alors cette opération échouera si un chemin contient des éléments localement modifiés et/ou non versionnés. Si $force est défini, de tels éléments seront supprimés.

Le rappel notify est appelé pour chaque élément supprimé avec le chemin de l'élément supprimé.

N'a pas de retour.

SVN::Client - Subversion client interface use SVN::Client; my $client = SVN::Client->new(...); ...

Provides a Perl interface to the Subversion client library. This module provides bindings for the most commonly used client functions. It is intended to be used by applications that need to interact with Subversion working copies and repositories.

Most methods are wrappers around the corresponding C API functions. Consult the Subversion book and C API documentation for a more complete explanation of the functionality provided.

The API is largely modeled after the PySVN interface. It uses the same basic object model: SVN::Client, SVN::Pool, SVN::Repos, SVN::Wc, etc.

A $pool argument is present on most functions. This is a memory pool for the Subversion library to use for its own temporary allocations. You should generally pass $SVN::Pool::new() as the pool argument.

Most functions that operate on paths can accept either a working copy path or a repository URL. Repository URLs are distinguished by starting with 'http:', 'https:', 'svn:', 'svn+ssh:', etc.

Many functions have a &notify_receiver callback. This is a Perl subroutine (or code reference) that will be called to report progress and other events back to the caller. The function signature and the arguments passed to it vary by function.

Many functions take a $revision argument. This can be a number, or one of the SVN::Core constants such as SVN_REVISION_HEAD, SVN_REVISION_BASE, SVN_REVISION_WORKING, etc. It can also be a reference to a two-element array specifying a revision range, e.g. [1, 10].

Many functions take a $peg_revision argument. This is the revision at which the $path_or_url argument is considered to be valid. The peg revision is important when dealing with moves, copies, and branches. It defaults to SVN_REVISION_UNSPECIFIED, which means to use HEAD for URLs and the working revision for working copy paths.

Produce a diff between $target1 at $revision1 and $target2 at $revision2. $target1 and $target2 can be either working-copy paths or URLs.

The results are written to $outstream, which should be a filehandle. The default diff format is unified context diff.

$diff_options is a reference to an array of additional arguments to pass to diff process invoked to compare files. You'll usually just want to use [] to pass an empty array to return a unified context diff (like `diff -u`).

$client->diff_summarize($target1, $revision1, $target2, $revision2, $recursive, $ignore_ancestry, \&summarize_func, $pool);
Produce a diff summary which lists the changed items between $target1 at $revision1 and $target2 at $revision2 without creating text deltas. $target1 and $target2 can be either working-copy paths or URLs.

The function may report false positives if $ignore_ancestry is false, since a file might have been modified between two revisions, but still have the same contents.

Calls \&summarize_func with with a svn_client_diff_summarize_t structure describing the difference.

See diff() for a description of the other parameters.

$client->export($from, $to, $revision, $force, $pool);
Export the contents of either a subversion repository or a subversion working copy into a 'clean' directory (meaning a directory with no administrative directories).

$from is either the path to the working copy on disk, or a URL to the repository you wish to export.

$to is the path to the directory where you wish to create the exported tree.

$revision is the revision that should be exported, which is only used when exporting from a repository. It may be undef otherwise.

The notify callback will be called for the items exported.

Returns the value of the revision actually exported or $SVN::Core::INVALID_REVNUM for local exports.

$client->import($path, $url, $nonrecursive, $pool);
Import file or directory $path into repository directory $url at head.

If some components of $url do not exist then create parent directories as necessary.

If $path is a directory, the contents of that directory are imported directly into the directory identified by $url. Note that the directory $path itself is not imported; that is, the basename of $path is not part of the import.

If $path is a file, then the dirname of $url is the directory receiving the import. The basename of $url is the filename in the repository. In this case if $url already exists, raise an error.

The notify callback (if defined) will be called as the import progresses, with any of the following actions: $SVN::Wc::Notify::Action::commit_added, $SVN::Wc::Notify::Action::commit_postfix_txdelta.

Use $nonrecursive to indicate that imported directories should not recurse into any subdirectories they may have.

Uses the log_msg callback to determine the log message for the commit when one is needed.

Returns a svn_client_commit_info_t object.

If both revision arguments are either svn_opt_revision_unspecified or NULL, then information will be pulled solely from the working copy; no network connections will be made.

Définit le rappel de notification pour le contexte client à une référence de code que vous passez. Il retourne toujours la référence de code actuellement définie.

La sous-routine pointée par cette référence sera appelée lorsqu'une modification sera apportée à la copie de travail. La valeur de retour de cette fonction est ignorée. Son seul but est de vous notifier du changement.

La sous-routine recevra 6 paramètres. Le premier paramètre sera le chemin du fichier modifié (absolu ou relatif au répertoire de travail courant). Le deuxième est un entier spécifiant le type d'action effectuée. Voir SVN::Wc pour une liste des actions possibles et ce qu'elles signifient. Le 3ème est un entier spécifiant le type de nœud du chemin, qui peut être : $SVN::Node::none, $SVN::Node::file, $SVN::Node::dir, $SVN::Node::inconnue. Le quatrième paramètre est le type MIME du fichier ou undef si le type MIME est inconnu (il sera toujours undef pour les répertoires). Le 5ème paramètre est l'état du fichier, voir à nouveau SVN::Wc pour une liste des états possibles. Le 6ème et dernier paramètre est le numéro de révision numérique du fichier modifié. Le numéro de révision sera -1 sauf lorsque l'action est $SVN::Wc::Notify::Action::update_completed.

$client->log_msg(\&log_msg)
Définit le rappel de log_msg pour le contexte client à une référence de code que vous passez. Il retourne toujours la référence de code actuellement définie.

La sous-routine pointée par cette référence de code sera appelée pour obtenir le message de log pour toute opération qui validera une révision dans le dépôt.

Elle reçoit 4 paramètres. Le premier paramètre est une référence à une valeur scalaire dans laquelle le rappel doit placer le log_msg. Si vous souhaitez annuler la validation, vous pouvez définir ce scalaire à undef. La 2ème valeur est un chemin vers un fichier temporaire qui pourrait contenir ce message de log, ou undef si aucun fichier de ce type n'existe (cependant, si log_msg est undef, cette valeur est indéfinie). Le message de log **DOIT** être une chaîne UTF8 avec des séparateurs de ligne LF. Le 3ème paramètre est une référence à un tableau d'objets svn_client_commit_item3_t, qui peuvent être entièrement ou seulement partiellement remplis, en fonction du type d'opération de validation. Le 4ème et dernier paramètre sera une piscine.

Si la fonction souhaite retourner une erreur, elle doit retourner un objet svn_error_t créé avec SVN::Error::create. Toute autre valeur de retour sera interprétée comme SVN_NO_ERROR.

CALLBACK D'ANNULATION

Cette fonction de rappel sera appelée périodiquement pour vérifier si l'opération doit être annulée. Si l'opération doit être annulée, la fonction peut renvoyer une des valeurs suivantes :

Un objet svn_error_t créé avec SVN::Error::create.

Toute valeur vraie, auquel cas les liaisons généreront un objet svn_error_t pour vous avec le code d'erreur SVN_ERR_CANCELLED et la chaîne définie sur "By cancel callback".

Une chaîne de caractères, auquel cas les liaisons généreront un objet svn_error_t pour vous avec le code d'erreur SVN_ERR_CANCELLED et la chaîne définie sur la chaîne que vous avez renvoyée.

Toute autre valeur sera interprétée comme une volonté de continuer l'opération. Généralement, il est préférable de renvoyer 0 pour continuer l'opération.

NOM

SVN::Client - Client class for Subversion.

SYNTAXIS

  use SVN::Client;
  my $client = SVN::Client->new(...);

DESCRIPTION

This is the client class for Subversion.

A SVN::Client object represents a handle to a Subversion client instance. You can use it to perform various operations against a Subversion repository. SVN::Client objects are designed to be tied to a particular working copy, and all operations are performed relative to that working copy. You can change the working copy that the client is operating on by calling SVN::Client->set_config_dir() with a new directory path. Otherwise, the client will use the default configuration directory.

You can get a list of all available methods by using the SVN::Client->methods() method.

PARAMETER NOTES

Most methods take a list of parameters. These parameters are typically passed as a hash.

The available parameters depend on the method being called. Please refer to the Subversion documentation for a complete list of parameters for each method.

Some common parameters include:

  • path: The path to the file or directory to operate on.
  • revision: The revision number to operate on.
  • recurse: A boolean value indicating whether to operate recursively on directories.
  • depth: The depth of recursion to use (e.g., SVN_DEPTH_INFINITY, SVN_DEPTH_FILESYNC, SVN_DEPTH_IMMEDIATES, SVN_DEPTH_EMPTY).
  • message: The commit message for commit operations.

AUTHENTICATION PROVIDERS

By default, SVN::Client uses the built-in Subversion authentication provider. You can provide your own authentication provider by calling $client->set_auth_provider() with a custom authentication provider object.

A custom authentication provider must implement the following methods:

prompt($realm, $prompt, $may_save)
Prompts the user for credentials.
first_creds($realm, $username, $password, $realm_passed)
Provides the first set of credentials.
next_creds($realm, $username, $password, $realm_passed)
Provides the next set of credentials.

CANCELLATION CALLBACK

You can provide a cancellation callback function by calling $client->set_cancel_func() with a callback function. This function will be called periodically during long-running operations. If the callback function returns a true value, the operation will be cancelled.

OBJECTS

The methods of SVN::Client return various objects, depending on the method called. These objects are typically blessed hashes that contain the results of the operation.

For example, $client->info() returns an SVN::Client::Info2 object, which contains information about a Subversion repository or working copy.

Please refer to the documentation for each method for a description of the objects it returns.
