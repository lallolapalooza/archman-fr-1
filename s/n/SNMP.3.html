NAME

SNMP - L'extension Perl5 "SNMP" pour la bibliothèque Net-SNMP du protocole SNMP.

SYNOPSIS

use SNMP;
...
$sess = new SNMP::Session(DestHost => localhost, Community => public);
$val = $sess->get('sysDescr.0');
...
$vars = new SNMP::VarList([sysDescr,0], [sysContact,0], [sysLocation,0]);
@vals = $sess->get($vars);
...
$vb = new SNMP::Varbind();
do {
   $val = $sess->getnext($vb);
   print "@{$vb}\n";
} until ($sess->{ErrorNum});
...
$SNMP::save_descriptions = 1;
SNMP::initMib(); # en supposant que le mib n'est pas déjà chargé
print "$SNMP::MIB{sysDescr}{description}\n";

DESCRIPTION

Note : Le module Perl5 SNMP qui accompagne Net-SNMP 5.0 et les versions ultérieures est différent des versions antérieures à plusieurs égards. Premièrement, son comportement est similaire à celui d'un programme SNMP réel et appelle correctement init_snmp, ce qui signifie qu'il lira les fichiers de configuration et utilisera les valeurs par défaut de manière appropriée, analysera les fichiers MIB, etc. Cela peut affecter vos applications Perl si vous avez des valeurs par défaut configurées dans votre fichier snmp.conf (car le module Perl utilisera désormais ces valeurs par défaut). Cependant, la documentation n'a pas encore été mise à jour (sauf cette note), et l'implémentation par défaut de read_config n'est pas entièrement terminée.

Les opérations de base du protocole SNMP sont fournies par ce module via une interface orientée objet pour la modularité et la facilité d'utilisation. La classe principale est SNMP::Session qui encapsule les aspects persistants d'une connexion entre le gestionnaire et l'agent géré. En interne, la classe est implémentée comme une référence de hachage bidirectionnelle. Cette classe fournit des appels de méthode tels que get, getnext, set, fget et fgetnext. Les arguments d'entrée sont divers et prennent en charge les opérations synchrones et asynchrones via une API polymorphique (c'est-à-dire que le comportement des méthodes varie en fonction des arguments passés - voir ci-dessous).

SNMP::Session

$sess = new SNMP::Session(DestHost => 'localhost', ...)

Les arguments suivants peuvent être passés sous forme de hachage lors de la création.

Options de base

DestHost
L'hôte ou l'adresse IP de l'agent SNMP auquel vous souhaitez communiquer. Il est spécifié dans les adresses d'agent Net-SNMP formatées. Ces adresses ressemblent généralement à l'une des suivantes : 
localhost
tcp:localhost
tls:localhost
tls:localhost:9876
udp6:[::1]:9876
unix:/some/path/to/file/socket

La valeur par défaut est 'localhost'.

Version
La version SNMP à utiliser.

La valeur par défaut est tirée de la configuration de la bibliothèque - probablement 3 [1, 2 (identique à 2c), 2c, 3].

Timeout
Le nombre de microsecondes à attendre avant de renvoyer une requête.

La valeur par défaut est '1000000'

Retries
Le nombre de fois où une requête doit être tentée.

La valeur par défaut est '5'

RetryNoSuch
Si activé, les erreurs NOSUCH dans les PDU 'get' seront corrigées, supprimant le varbind en erreur et renvoyant - undef sera retourné pour tous les varbinds NOSUCH, lorsque défini sur '0', cette fonction est désactivée et toute la requête get échouera à toute erreur NOSUCH (s'applique uniquement à v1).

La valeur par défaut est '0'.

Options SNMPv3/TLS

OurIdentity
Notre identité X.509 à utiliser, qui doit être une empreinte digitale ou le nom du fichier qui stocke la certification.
TheirIdentity
L'identité du serveur distant auquel se connecter, spécifiée comme une empreinte digitale ou un nom de fichier. Ceci doit être spécifié, ou le nom d'hôte ci-dessous et une ancre de confiance.
TheirHostname
Le nom d'hôte du serveur distant attendu. Si le certificat présenté par le serveur a été signé par un CA, le nom d'hôte dans le certificat doit correspondre à cette valeur, sinon la connexion échouera (pour éviter les attaques de type man-in-the-middle).
TrustCert
Une certification de confiance à utiliser comme ancre de confiance (comme une certification de CA) pour vérifier le certificat du serveur distant. Si une certification de CA est utilisée pour valider un certificat, TheirHostname doit également être spécifié pour garantir que le nom d'hôte présenté dans le certificat correspond.

Options SNMPv3/USM

SecName
Le nom de sécurité SNMPv3 à utiliser (le plus courant en SNMPv3 avec USM).

La valeur par défaut est 'initial'.

SecLevel
Le niveau de sécurité SNMPv3 à utiliser [noAuthNoPriv, authNoPriv, authPriv] (v3)

La valeur par défaut est 'noAuthNoPriv'.

SecEngineId
L'identifiant du moteur de sécurité SNMPv3 à utiliser (si nécessaire pour le modèle SNMPv3). Le format est une chaîne sans le préfixe '0x'. Par exemple, si snmptrapd.conf contient "-e 0x8000000001020304", utilisez SecEngineId => '8000000001020304'.

La valeur par défaut est <aucun>, et tentera de découvrir si elle n'est pas spécifiée (v3).

ContextEngineId
L'identifiant du moteur de contexte SNMPv3 à utiliser.

La valeur par défaut est <aucun> et sera définie sur la valeur de SecEngineId si elle est spécifiée, ou découverte par d'autres moyens si TLS est utilisé (découverte basée sur RFC5343).

Context
Le nom de contexte SNMPv3 à utiliser.

La valeur par défaut est une chaîne vide ('')

AuthProto
Le protocole d'authentification SNMPv3/USM à utiliser [MD5, SHA].

La valeur par défaut est 'MD5'.

AuthPass
Le mot de passe d'authentification SNMPv3/USM à utiliser.

La valeur par défaut est <aucun>, le mot de passe d'authentification.

PrivProto
Le protocole de confidentialité SNMPv3/USM à utiliser [DES, AES].

La valeur par défaut est 'DES'.

PrivPass
Le mot de passe de confidentialité SNMPv3/USM à utiliser.

La valeur par défaut est <aucun>, le mot de passe de confidentialité (v3).

AuthMasterKey
PrivMasterKey
AuthLocalizedKey
PrivLocalizedKey
Les clés directement spécifiées de SNMPv3 USM (utilisées si vous souhaitez spécifier les clés plutôt que de les dériver d'un mot de passe comme auparavant).

Options SNMPv1 et SNMPv2c

Community
Pour SNMPv1 et SNMPv2c, le nom de communauté en clair à utiliser.

La valeur par défaut est 'public'.

Autres options de configuration

VarFormats
par défaut 'undef', utilisé par 'fget[next]', contient une référence de hachage des formats de valeurs de sortie, (ex. {<obj> => <sub-ref>}, <obj> doit correspondre au <obj> et au format utilisé dans l'opération de get. Un <obj> spécial, '*', peut être utilisé pour s'appliquer à tous les <obj>, le sub sera appelé pour traduire la valeur dans un nouveau format. Le sub est appelé en passant le Varbind

Ce site n'est en aucun cas associé à Arch Linux ni affilié à ce projet. Le contenu est uniquement une traduction des pages de manuel d'Arch publiées sur man.archlinux.org.

as la arg
TypeFormats
par défaut 'undef', utilisé par 'fget[next]', contient une référence de hachage des formateurs de valeur de sortie, (par exemple, {<type> => <sous-référence>, ... }, la sous-référence fournie est appelée pour traduire la valeur dans un nouveau format, sauf si un VarFormat correspond en premier (par exemple, $sess->{TypeFormats}{INTEGER} = \&mapEnum(); bien que cela puisse être fait plus efficacement en activant $SNMP::use_enums ou le paramètre de création de session 'UseEnums')
UseLongNames
par défaut à la valeur de SNMP::use_long_names au moment de la création de la session. défini sur non nul pour que les <balises> pour les méthodes 'getnext' soient générées en privilégiant la convention de nom MIB plus longue (par exemple, system.sysDescr vs juste sysDescr)
UseSprintValue
par défaut à la valeur de SNMP::use_sprint_value au moment de la création de la session. défini sur non nul pour que les valeurs de retour pour les méthodes 'get' et 'getnext' soient formatées avec la fonction snprint_value de la bibliothèque. Cela résultera en certains types de données retournés dans un format non canonique. Note : les valeurs retournées avec cette option activée peuvent ne pas être appropriées pour les opérations 'set' (voir la discussion sur les formats de valeur dans la section de description de <vars>)
UseEnums
par défaut à la valeur de SNMP::use_enums au moment de la création de la session. Défini sur non nul pour que les valeurs d'entier retournées soient converties en identificateurs d'énumération si possible. Ces valeurs seront également acceptables lorsqu'elles sont fournies aux opérations 'set'.
UseNumeric
par défaut à la valeur de SNMP::use_numeric au moment de la création de la session. défini sur non nul pour que les <balises> pour les méthodes get soient retournées comme des OID numériques plutôt que des descriptions. UseLongNames sera défini de manière à ce que l'OID complet soit retourné à l'appelant.
BestGuess
par défaut à la valeur de SNMP::best_guess au moment de la création de la session. Ce réglage contrôle comment les <balises> sont analysées. Le réglage à 0 provoque une recherche régulière. Le réglage à 1 provoque une correspondance d'expression régulière (définie comme -Ib dans snmpcmd) et le réglage à 2 provoque une recherche aléatoire (définie comme -IR dans snmpcmd).
NonIncreasing
par défaut à la valeur de SNMP::non_increasing au moment de la création de la session. Ce réglage contrôle si un OID non croissant pendant un bulkwalk provoque une erreur. Le réglage à 0 provoque le comportement par défaut (qui peut, sur des agents très peu performants, résulter en une boucle sans fin). Le réglage à 1 provoque une erreur (OID non croissant) lorsque cette erreur se produit.
ErrorStr
lecture seule, contient le message d'erreur associé à la dernière requête
ErrorNum
lecture seule, contient le snmp_err ou le statut de la dernière requête
ErrorInd
lecture seule, contient l'indice snmp_err lorsque approprié

Variables privées :

DestAddr
champ interne utilisé pour contenir le champ DestHost traduit
SessPtr
champ interne utilisé pour mettre en cache une structure de session créée
RemotePort
Obsolète. Veuillez utiliser le spécificateur DestHost pour indiquer la combinaison nom d'hôte et port au lieu de ce paramètre.

Méthodes SNMP::Session

$sess->update(<fields>)
Met à jour l'objet SNMP::Session avec les valeurs des champs passés sous forme de liste de hachage (similaire à new(<fields>)) (ATTENTION ! pas entièrement implémenté)
$sess->get(<vars> [,<callback>])
effectue une requête SNMP GET, plusieurs formats de <vars> sont acceptés. Pour une opération synchrone, <vars> sera mis à jour avec la ou les valeurs et le ou les types, et retournera également la ou les valeurs récupérées. Si un <callback> est fourni, la méthode fonctionnera de manière asynchrone.
$sess->fget(<vars> [,<callback>])
effectue une requête SNMP GET comme 'get' et formate les valeurs selon les gestionnaires spécifiés dans $sess->{VarFormats} et $sess->{TypeFormats}.
$sess->getnext(<vars> [,<callback>])
effectue une requête SNMP GETNEXT, plusieurs formats de <vars> sont acceptés, retourne la ou les valeurs récupérées. Les <vars> passés en arguments sont mis à jour pour indiquer le prochain <obj>, <iid>, <val>, et <type> lexicographiques.

Note : le format simple de chaînes <vars> (par exemple, 'sysDescr.0') n'est pas mis à jour. Si un <callback> est fourni, la méthode fonctionnera de manière asynchrone.

$sess->fgetnext(<vars> [,<callback>])
effectue une requête SNMP GETNEXT comme getnext et formate les valeurs selon les gestionnaires spécifiés dans $sess->{VarFormats} et $sess->{TypeFormats}.
$sess->set(<vars> [,<callback>])
effectue une requête SNMP SET, plusieurs formats de <vars> sont acceptés. La valeur dans tous les formats de <vars> doit être dans un format canonique (c'est-à-dire, un format bien connu) pour assurer une traduction sans ambiguïté en valeur de données MIB SNMP (voir la discussion sur le format de valeur canonique dans la section de description de <vars>), retourne snmp_errno. Si un <callback> est fourni, la méthode fonctionnera de manière asynchrone.
$sess->getbulk(<non-repeaters>, <max-repeaters>, <vars>)
effectue un SNMP GETBULK. À partir de la liste de Varbinds, la prochaine instance lexicographique unique est récupérée pour les n premières Varbinds définies par <non-repeaters>. Pour les Varbinds restantes, m instances lexicographiques sont récupérées pour chacune des Varbinds restantes, où m est <max-repeaters>.
$sess->bulkwalk(<non-repeaters>, <max-repeaters>, <vars> [,<callback>])
Effectue un "bulkwalk" de la liste de Varbinds. Ceci est fait en envoyant une requête GETBULK (voir getbulk() ci-dessus) pour les Varbinds. Pour chaque variable demandée, la réponse est examinée pour voir si la prochaine instance lexicographique a quitté le sous-arbre demandé. Toutes les instances supplémentaires retournées pour cette variable sont ignorées, et la recherche pour ce sous-arbre est considérée comme terminée.

Si des sous-arbres n'ont pas été complétés lorsque la fin des réponses est atteinte, une autre requête est composée, consistant en les variables restantes. Ce processus est répété jusqu'à ce que tous les sous-arbres aient été complétés, ou que trop de paquets aient été échangés (pour éviter les boucles).

La méthode bulkwalk() retourne un tableau contenant un tableau de Varbinds, un pour chaque variable demandée, dans l'ordre des demandes de variables. En cas d'erreur, bulkwalk() retourne undef et définit $sess->ErrorStr et $sess->ErrorNum. Si un callback est fourni, bulkwalk() retourne l'identifiant de la requête SNMP et retourne immédiatement. Le callback sera appelé avec la liste d'arguments fournie et la liste des variables retournées.

Note : Parce que le client doit "découvrir" que l'arbre est complet en comparant les variables retournées avec celles qui ont été demandées, il y a un "piège" potentiel lors de l'utilisation de la valeur max-repeaters. Considérez le code suivant pour afficher une liste d'interfaces et de nombres d'octets :

$numInts = $sess->get('ifNumber.0');
($desc, $in, $out) = $sess->bulkwalk(0, $numInts,
              [['ifDescr'], ['ifInOctets'], ['ifOutOctets']]);
for $i (0..($numInts - 1)) {
    printf "Interface %4s: %s inOctets, %s outOctets\n",
              $$desc[$i]->val, $$in[$i]->val, $$out[$i]->val;
}

Ce code effectuera *deux* requêtes à l'agent -- la première pour obtenir les valeurs d'interface, et la seconde pour découvrir que toutes les informations étaient dans le premier paquet. Pour contourner cela, utilisez '$numInts + 1' pour la valeur max_repeaters. Cela demande à l'agent d'inclure une variable supplémentaire (sans rapport) qui signale la fin du sous-arbre, permettant à bulkwalk() de déterminer que la requête est terminée.

$results = $sess->gettable(<OID_TABLE>, <OPTIONS>)
Ceci récupérera une table entière de données et retournera une référence de hachage vers ces données. La référence de hachage retournée aura des index des suffixes d'OID pour les données d'index comme clé. La valeur pour chaque entrée sera une autre hachage contenant les données pour une ligne donnée. Les clés de ce hachage seront les noms des colonnes, et les valeurs seront les données.

Exemple :

#!/usr/bin/perl
use SNMP;
use Data::Dumper;
my $s = new SNMP::Session(DestHost => 'localhost');
print Dumper($s->gettable('ifTable'));

Sur ma machine produit :

$VAR1 = {
          '6' => {
                   'ifMtu' => '1500',
                   'ifPhysAddress' => 'PV',
                   # ...
                   'ifInUnknownProtos' => '0'
                 },
          '4' => {
                   'ifMtu' => '1480',
                   'ifPhysAddress' => '',
                   # ...
                   'ifInUnknownProtos' => '0'
                 },
          # ...
         };

Par défaut, il essaiera de faire une récupération aussi optimisée que possible. Il demandera plusieurs colonnes à la fois et utilisera GETBULK si possible. Quelques options peuvent être spécifiées en passant un hachage d'OPTIONS contenant divers paramètres :

noindexes => 1
Indique au code de ne pas analyser les index et de placer les résultats dans le second hachage. Si vous n'avez pas besoin des données d'index, ce sera plus rapide.
columns => [ colname1, ... ]
Ceci spécifie quelles colonnes collecter. Par défaut, il essaiera de collecter toutes les colonnes définies dans la table MIB.
repeat => COUNT
Spécifie un compte de répétition GETBULK COUNT. C'est-à-dire qu'il demandera ce nombre de varbinds par colonne lors de l'utilisation de l'opération GETBULK. Réduire cela signifie des paquets plus petits, ce qui peut aider à traverser certains systèmes. Par défaut, cette valeur est calculée et tente de deviner ce qui contiendra tous les résultats dans 1000 octets. Ce calcul est assez sûr, espérons-le, mais vous pouvez augmenter ou diminuer le nombre en utilisant cette option si vous le souhaitez. Sur les réseaux peu fiables, vous voulez vous assurer que les paquets ne sont pas fragmentés et réduire cette valeur est un moyen d'y aider.
nogetbulk => 1
Force l'utilisation de GETNEXT au lieu de GETBULK. (toujours vrai pour SNMPv1, car il n'a pas de GETBULK de toute façon). Certains agents sont d'excellents implémenteurs de GETBULK et cela vous permet de forcer l'utilisation des opérations GETNEXT à la place.
callback => \&sous-routine
callback => [\&sous-routine, optarg1, optarg2, ...]
Si une fonction de rappel est spécifiée, gettable renverra rapidement sans renvoyer de résultats. Lorsque les résultats seront finalement récupérés, la sous-routine de rappel sera appelée (voir les autres sections définissant le comportement de rappel et comment utiliser SNMP::MainLoop, qui est requis pour que cela fonctionne). Un argument supplémentaire du hachage de résultat normal sera ajouté aux arguments de la sous-routine de rappel.

Note 1 : en interne, la fonction gettable utilise ses propres fonctions de rappel qui sont transmises à getnext/getbulk selon le cas.

Note 2 : la prise en charge des fonctions de rappel n'est disponible que dans le module SNMP version 5.04 et supérieure. Pour tester cela dans un code destiné à prendre en charge à la fois les versions antérieures à 5.04 et les versions 5.04 et supérieures, le code suivant devrait fonctionner :

if ($response = $sess->gettable('ifTable', callback => \&my_sub)) {
    # réponse obtenue, gettable ne prend pas en charge le rappel
    my_sub($response);
    $no_mainloop = 1;
}

La décision d'utiliser ou non SNMP::MainLoop est laissée comme exercice au lecteur, car elle dépend de l'utilisation par votre code d'autres fonctions de rappel.

Formats de variables acceptables :

<vars> peut être l'une des formes suivantes :

SNMP::VarList
représente un tableau d'objets MIB à obtenir ou à définir, implémenté comme une référence bénie à un tableau de SNMP::Varbinds (par exemple, [<varbind1>, <varbind2>, ...])
SNMP::Varbind
représente un seul objet MIB à obtenir ou à définir, implémenté comme une référence bénie à un tableau de 4 éléments ; [<obj>, <iid>, <val>, <type>].
<obj>
l'une des formes suivantes :
1)
identifiant de feuille (par exemple, 'sysDescr') supposé être unique à des fins pratiques
2)
identifiant qualifié complet (par exemple, '.iso.org.dod.internet.mgmt.mib-2.system.sysDescr')
3)
OID numérique qualifié complet en notation décimale pointée (par exemple, '.1.3.6.1.2.1.1.1')
<iid>
l'identifiant d'instance en notation décimale pointée. Pour les objets MIB scalaires, utilisez '0'
<val>
la valeur de données SNMP récupérée ou définie dans la MIB de l'agent. Pour les opérations (f)get(next), <val> peut avoir une variété de formats déterminés par les paramètres de session et de package. Cependant, pour les opérations set, le format <val> doit être canonique pour garantir une traduction sans ambiguïté. Les formes canoniques sont les suivantes :
OBJECTID
décimale pointée (par exemple, .1.3.6.1.2.1.1.1)
OCTETSTR
scalaire Perl contenant des octets
INTEGER
entier signé décimal (ou énuméré)
NETADDR
décimale pointée
IPADDR
décimale pointée
COUNTER
entier décimal non signé
COUNTER64
entier décimal non signé
GAUGE
entier décimal non signé
UINTEGER
entier décimal non signé
TICKS
entier décimal non signé
OPAQUE
scalaire Perl contenant des octets
NULL
scalaire Perl ne contenant rien
<type>
type de données SNMP (voir la liste ci-dessus), ce champ est renseigné par les opérations 'get' et 'getnext'. Dans certains cas, le programmeur doit renseigner ce champ lors de la transmission à une opération 'set'. ce champ n'a pas besoin d'être fourni lorsque l'attribut indiqué par <tag> est déjà décrit par des modules MIB chargés. pour les 'set', si un OID numérique est utilisé et que l'objet n'est pas actuellement dans la MIB chargée, le champ <type> doit être fourni
chaîne simple
forme légère de <var> utilisée pour 'set' ou 'get' un seul attribut sans construire un SNMP::Varbind. stocké dans un scalaire Perl, a la forme '<tag>.<iid>', (par exemple, 'sysDescr.0'). pour les opérations 'set', la valeur est passée comme second argument. Note : ce format d'argument n'est pas mis à jour dans les opérations get[next] comme le sont les autres formes.

Formats de rappel acceptables

<callback> peut être l'une des formes suivantes :

sans arguments
\&nom_sous-routine
sous { ... }
ou avec arguments
[ \&nom_sous-routine, $arg1, ... ]
[ sous { ... }, $arg1, ... ]
[ "méthode", $obj, $arg1, ... ]

La fonction de rappel sera appelée lorsque la réponse sera reçue ou en cas de délai d'attente. Le dernier argument passé à la fonction de rappel sera une référence SNMP::VarList. En cas de délai d'attente, le dernier argument sera undef.

&SNMP::MainLoop([<timeout>, [<callback>]])
à utiliser avec les appels asynchrones SNMP::Session. MainLoop doit être appelé après les appels asynchrones initiaux afin que les paquets de retour de l'agent soient traités. Si aucun argument n'est fourni, cette fonction entre dans une boucle infinie, le programme doit donc être quitté dans une fonction de rappel ou interrompu extérieurement. Si <timeout (sic)
&SNMP::finish()
Cette fonction, lorsqu'elle est appelée à partir d'une fonction de rappel SNMP::MainLoop(), provoquera le retour de SNMP::MainLoop() actuel après l'achèvement de la fonction de rappel. finish() peut être utilisé pour terminer une MainLoop autrement infinie. Une nouvelle instance de MainLoop() peut alors être démarrée pour gérer les requêtes ultérieures.

Variables et fonctions du package SNMP

$SNMP::VERSION
le spécificateur de version actuel (par exemple, 3.1.0)
$SNMP::auto_init_mib
par défaut '1', mis à 0 pour désactiver la lecture automatique de la MIB lors de la création de la session. mis à une valeur non nulle pour appeler initMib lors de la création de la session, ce qui entraînera le chargement de la MIB selon les variables d'environnement Net-SNMP (voir man mib_api)
$SNMP::verbose
par défaut '0', contrôle la sortie des avertissements/informations du module SNMP, 0 => aucune sortie, 1 => active la sortie des avertissements/informations du module SNMP lui-même (est également contrôlé par SNMP::debugging - voir ci-dessous)
$SNMP::use_long_names
par défaut '0', mis à une valeur non nulle pour activer l'utilisation d'identifiants MIB plus longs. voir translateObj. influencera également le formatage de <tag> dans les varbinds renvoyés par les opérations 'getnext'. Peut être défini par session (UseLongNames)
$SNMP::use_sprint_value
par défaut '0', mis à une valeur non nulle pour activer le formatage des valeurs de réponse à l'aide de la fonction snprint_value des bibliothèques snmp. peut également être défini par session (voir UseSprintValue) Note : les valeurs renvoyées peuvent ne pas convenir aux opérations 'set'
$SNMP::use_enums
par défaut '0', mis à une valeur non nulle pour renvoyer les valeurs sous forme d'énumérés et permettre les définitions utilisant des énumérés le cas échéant. les entiers seront toujours acceptés pour les opérations de définition. peut également être défini par session (voir UseEnums)
$SNMP::use_numeric
par défaut '0', mis à une valeur non nulle pour que les <tags> des méthodes 'get' soient renvoyés sous forme d'OID numériques plutôt que de descriptions. UseLongNames sera défini de manière à ce que l'OID complet soit renvoyé. Défini par session (voir UseNumeric).
$SNMP::best_guess
par défaut '0'. Ce paramètre contrôle la façon dont les <tags> sont analysés. Le réglage à 0 provoque une recherche normale. Le réglage à 1 provoque une correspondance d'expression régulière (définie comme -Ib dans snmpcmd) et le réglage à 2 provoque une recherche à accès aléatoire (définie comme -IR dans snmpcmd). Peut également être défini par session (voir BestGuess)
$SNMP::save_descriptions
par défaut '0', mis à une valeur non nulle pour que l'analyseur MIB enregistre les descriptions d'attributs. doit être défini avant l'initialisation de la MIB
$SNMP::debugging
>
par défaut '0', contrôle le niveau de sortie de débogage dans le module SNMP et libsnmp
1.
active 'SNMP::verbose' (voir ci-dessus)
2.
niveau 1 plus snmp_set_do_debugging(1)
3.
niveau 2 plus snmp_set_dump_packet(1)
$SNMP::dump_packet
par défaut '0', définir à 'non-zéro' pour définir indépendamment snmp_set_dump_packet()
SNMP::register_debug_tokens()
Permet d'enregistrer un ou plusieurs jetons de débogage, tout comme l'option -D de snmpd. Chaque jeton de débogage active un groupe d'instructions de débogage. Un exemple: SNMP::register_debug_tokens("tdomain,netsnmp_unix");

%SNMP::MIB

une table liée pour accéder aux informations MIB analysées. Après que la MIB a été chargée, cette table permet d'accéder aux métadonnées MIB analysées (la structure de la MIB (c'est-à-dire le schéma)). La table renvoie des références bénies à des objets SNMP::MIB::NODE qui représentent un seul attribut MIB. Les nœuds peuvent être récupérés à l'aide de plusieurs formats de 'clé' - le nom de feuille (par exemple, sysDescr) ou un nom entièrement/partiellement qualifié (par exemple, system.sysDescr) ou un OID numérique entièrement qualifié. L'objet nœud renvoyé prend en charge les champs suivants:

objectID
OID entièrement qualifié en décimal pointé
label
identifiant textuel de feuille (par exemple, 'sysDescr')
subID
composant OID numérique de feuille d'objectID (par exemple, '1')
moduleID
identifiant textuel du module (par exemple, 'RFC1213-MIB')
parent
nœud parent
children
référence de tableau des nœuds enfants
nextNode
prochain nœud lexicographique (BUG! ne renvoie pas dans l'ordre lexicographique)
type
renvoie le type d'application (voir getType pour les valeurs)
access
renvoie ACCESS (ReadOnly, ReadWrite, WriteOnly, NoAccess, Notify, Create)
status
renvoie STATUS (Mandatory, Optional, Obsolete, Deprecated)
syntax
renvoie 'textualConvention' si défini, sinon 'type'
textualConvention
renvoie TEXTUAL-CONVENTION
TCDescription
renvoie le champ DESCRIPTION de TEXTUAL-CONVENTION.
units
renvoie UNITS
hint
renvoie HINT
enums
renvoie une référence de table {tag => num, ...}
ranges
renvoie une référence de tableau de références de table [{low => num, high => num}, ...]
description
renvoie DESCRIPTION ($SNMP::save_descriptions doit être défini avant l'initialisation/l'analyse MIB)
reference
renvoie la clause REFERENCE
indexes
renvoie les objets de la clause INDEX
implied
renvoie vrai si le dernier objet de l'INDEX est IMPLIED

Fonctions MIB

&SNMP::setMib(<fichier>)
permet l'analyse dynamique de la mib et la spécification explicite du fichier mib indépendamment des variables d'environnement. appelé sans argument agit comme initMib, chargeant les MIBs indiquées par les variables d'environnement (voir la documentation de l'API mib de Net-SNMP). passer un argument second non nul force la libération et le remplacement de la mib précédente (Note : le second argument ne fonctionne pas car la libération de la Mib précédente est plus complexe qu'auparavant).
&SNMP::initMib()
appelle la fonction init_mib de la bibliothèque si la Mib n'est pas déjà chargée - ne fait rien si la Mib est déjà chargée. analysera les répertoires et chargera les modules selon les variables d'environnement décrites dans la documentation Net-SNMP. (voir man mib_api, MIBDIRS, MIBS, MIBFILE(S), etc.)
&SNMP::addMibDirs(<dir>,...)
appelle add_mibdir de la bibliothèque pour chaque répertoire fourni. provoquera l'ajout du(des) répertoire(s) à la liste interne et leur mise à disposition pour la recherche dans les appels loadModules ultérieurs
&SNMP::addMibFiles(<fichier>,...)
appelle la fonction read_mib de la bibliothèque. Le(s) fichier(s) fourni(s) sera(ont) lu(s) et toutes les définitions de modules Mib qu'il(s) contient(ont) seront ajoutées à la structure d'arbre mib interne
&SNMP::loadModules(<mod>,...)
appelle la fonction read_module de la bibliothèque. Le(s) module(s) fourni(s) sera(ont) recherché(s) dans les mibdirs actuels et ajouté(s) à la structure d'arbre mib interne. Passer le module spécial <mod>, 'ALL', provoquera le chargement de tous les modules connus.
&SNMP::unloadModules(<mod>,...)
*Non implémenté*
&SNMP::translateObj(<var>[,arg,[arg]])
convertira une étiquette d'objet texte en OID et vice-versa. Tout suffixe iid est conservé numériquement. Le comportement par défaut lors de la conversion d'un OID numérique en forme texte est de renvoyer uniquement l'identifiant de feuille (par exemple, 'sysDescr'), mais lorsque $SNMP::use_long_names est non nul ou qu'un second argument non nul est fourni, il renverra un identifiant textuel plus long. Un troisième argument optionnel non nul provoquera l'ajout du nom du module au début du nom texte (par exemple, 'SNMPv2-MIB::sysDescr'). Lors de la conversion d'un objet texte, l'option $SNMP::best_guess est utilisée. Si aucune Mib n'est chargée lors de l'appel et que $SNMP::auto_init_mib est activé, la Mib sera chargée. Renverra 'undef' en cas d'échec.
&SNMP::getType(<var>)
renvoie le type de données SNMP pour l'identifiant textuel donné OBJECTID, OCTETSTR, INTEGER, NETADDR, IPADDR, COUNTER GAUGE, TIMETICKS, OPAQUE, ou undef
&SNMP::mapEnum(<var>)
convertit une valeur entière en étiquette d'énumération définie dans la Mib ou convertit l'étiquette en entier en fonction de l'entrée. la fonction renverra la valeur entière correspondante *ou* l'étiquette pour un attribut MIB et une valeur donnés. La fonction détectera la direction de la conversion. Divers formats d'arguments sont pris en charge
$val = SNMP::mapEnum($varbind);
où $varbind est SNMP::Varbind ou équivalent. note: $varbind sera mis à jour
$val = SNMP::mapEnum('ipForwarding', 'forwarding');
$val = SNMP::mapEnum('ipForwarding', 1);

Dépannage

Si des problèmes surviennent, il y a plusieurs domaines à examiner pour réduire les possibilités.

La première étape devrait être de tester l'installation Net-SNMP indépendamment de l'interface Perl5 SNMP.

Essayez d'exécuter les applications de la distribution Net-SNMP.

Assurez-vous que votre agent (snmpd) est en cours d'exécution et correctement configuré avec un accès en lecture/écriture pour la communauté que vous utilisez.

Assurez-vous que vos MIBs sont installées et que les variables d'environnement sont définies correctement (voir man mib_api)

Soyez sûr de supprimer les anciennes installations net-snmp et de vous assurer que les en-têtes et les bibliothèques des anciennes installations CMU ne sont pas utilisées par erreur.

Si le problème survient lors de la compilation/liaison, vérifiez que la bibliothèque snmp utilisée pour la liaison est bien la bibliothèque Net-SNMP (il y a eu des conflits de noms avec les bibliothèques snmp existantes).

Vérifiez également que les fichiers d'en-tête sont corrects et à jour.

Parfois, la compilation de la bibliothèque Net-SNMP avec 'code indépendant de la position' activé est nécessaire (HP-UX spécifiquement).

Si vous ne parvenez pas à résoudre le problème, vous pouvez poster sur comp.lang.perl.modules ou net-snmp-users@net-snmp-users@lists.sourceforge.net

veuillez fournir suffisamment d'informations pour analyser le problème (type de système d'exploitation, versions du système d'exploitation/Perl/Net-SNMP/compilateur, sortie d'erreur complète, etc.)
