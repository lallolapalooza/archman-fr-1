NOM

SUPER - contrôle de la transmission des méthodes de classe mère

SYNTAXE

Trouver la méthode parente qui s'exécuterait si celle-ci n'était pas là :

sub my_method
{
    my $self = shift;
    my $super = $self->super('my_method'); # Qui est ton papa ?
    if ($want_to_deal_with_this)
    {
        # ...
    }
    else
    {
        $super->($self, @_)
    }
}

Ou style Ruby :

sub my_method
{
    my $self = shift;
    if ($want_to_deal_with_this)
    {
        # ...
    }
    else
    {
        super;
    }
}

Ou appeler manuellement la méthode super, en tenant compte de l'héritage, et en passant des arguments différents :

sub my_method
{
    my $self = shift;
    # le parent gère les arguments dans l'ordre inverse
    $self->SUPER( reverse @_ );
}

DESCRIPTION

Lors de la sous-classification d'une classe, vous voudrez parfois déléguer le contrôle à la classe mère -- au moins conditionnellement et temporairement. La syntaxe Perl pour appeler sa classe mère est laide et encombrante :

$self->SUPER::method(@_);

surtout comparée à son équivalent Ruby :

super;

C'est encore pire car le mécanisme normal de re-transmission de Perl ne délègue qu'à la classe parente de la classe contenant la méthode au moment de la compilation. Cela ne fonctionne pas très bien pour les mixins et les rôles.

Ce module fournit des équivalents plus agréables, ainsi que la méthode universelle "super" pour déterminer la classe mère d'une classe. Cela vous permet de faire des choses comme :

goto &{$_[0]->super('my_method')};

si vous n'aimez pas gaspiller de précieuses piles d'appels.

Si vous utilisez des rôles ou des mixins, ou si vous intégrez des méthodes d'autres packages qui doivent déléguer à leurs méthodes super, ou si vous voulez passer des arguments différents à la méthode super, utilisez la méthode SUPER() :

$self->SUPER( qw( autres arguments ici ) );

FONCTIONS et MÉTHODES

Ce module fournit les fonctions et méthodes suivantes :

super()
Cette fonction appelle la méthode super de la méthode actuellement exécutée, où qu'elle se trouve dans la hiérarchie.

Elle ne prend aucun argument ; elle passe les mêmes arguments que ceux passés à la méthode actuellement exécutée.

Le module exporte cette fonction par défaut.

Remarque : vous devez avoir la déclaration "package" appropriée en place pour que cela fonctionne. Autrement dit, vous devez avoir compilé la méthode dans laquelle vous utilisez cette fonction dans le package à partir duquel vous voulez l'utiliser. C'est comme ça avec Perl 5.

"find_parent( $class, $method, $prune, $invocant )"
Tente de trouver une implémentation parente de $method en commençant par $class. Si vous passez $prune, elle n'ignorera pas la méthode trouvée dans ce package, si elle existe là. Passez $invocant si l'objet lui-même peut avoir une idée différente de ses parents.

Le module n'exporte pas cette fonction par défaut. Appelez-la directement.

"get_all_parents( $invocant, $class )"
Retourne tous les parents de $invocant, s'il supporte la méthode "__get_parents()" ou le contenu de @ISA pour $class. Vous ne devriez probablement pas l'appeler vous-même.
SUPER()
Appelle la méthode super de la méthode actuellement exécutée. Vous pouvez passer des arguments. C'est une méthode.

NOTES

Attention : si vous faites des choses étranges avec la génération de code, assurez-vous de nommer vos sous-routines anonymes. Voir Perl Hacks #57.

L'utilisation de "super" ne vous permet pas de passer des arguments alternatifs à la méthode de votre classe mère. Si vous voulez passer des arguments différents, utilisez plutôt "SUPER". D'oh.

Ce module effectue un petit peu de Magie Profonde pour trouver les arguments de la méthode qui appelle elle-même super(). Cela peut perturber des outils tels que "Devel::Cover".

Dans votre propre code, si vous faites des choses compliquées avec des objets proxy et similaires, définissez "__get_parents()" pour retourner une liste de tous les parents de l'objet auquel vous voulez réellement déléguer.
