Sub::Exporter::Util(3) Documentation Perl fournie par l'utilisateur Sub::Exporter::Util(3)

NOM

Sub::Exporter::Util - utilitaires pour faciliter l'utilisation de Sub::Exporter

VERSION

version 0.991

DESCRIPTION

Ce module fournit un certain nombre de fonctions utilitaires pour effectuer des opérations courantes ou utiles lors de la configuration de Sub::Exporter. Tous les utilitaires peuvent être exportés, mais aucun ne l'est par défaut.

VERSION PERL

Cette bibliothèque devrait fonctionner sur des versions de Perl publiées depuis longtemps. Elle devrait fonctionner sur n'importe quelle version de perl publiée au cours des cinq dernières années.

Bien qu'elle puisse fonctionner sur des versions plus anciennes de perl, rien ne garantit que la version minimale requise ne sera pas augmentée. La version peut être augmentée pour quelque raison que ce soit, et il n'y a aucune promesse que des correctifs seront acceptés pour abaisser la version minimale requise de perl.

LES UTILITAIRES

curry_method

exports => {
  some_method => curry_method,
}

Cet utilitaire renvoie un générateur qui produira une version "curried" d'une méthode, avec l'invocant. En d'autres termes, il exportera un appel de méthode avec la classe exportatrice intégrée comme invocant.

Un module qui importe le code de l'exemple ci-dessus pourrait faire ceci :

use Some::Module qw(some_method);
my $x = some_method;

Ce serait l'équivalent de :

use Some::Module;
my $x = Some::Module->some_method;

Si Some::Module est sous-classé et que la méthode d'importation de la sous-classe est appelée pour importer "some_method", la sous-classe sera curryée comme invocant.

Si un argument est fourni pour "curry_method", il est utilisé comme nom de la méthode curryée à exporter. Cela signifie que vous pourriez exporter un constructeur de Widget comme ceci :

exports => { widget => curry_method('new') }

Cet utilitaire peut également être appelé sous le nom "curry_class", pour des raisons de compatibilité descendante.

curry_chain

"curry_chain" se comporte comme "curry_method", mais est destiné à générer des exportations qui appelleront plusieurs méthodes successivement.

exports => {
  reticulate => curry_chain(
    new => gather_data => analyze => [ detail => 100 ] => 'results'
  ),
}

Si elle est importée depuis Spliner, l'appel de la routine "reticulate" sera équivalent à :

Spliner->new->gather_data->analyze(detail => 100)->results;

Si une méthode renvoie quelque chose sur lequel des méthodes ne peuvent pas être appelées, la routine plante.

Les arguments de "curry_chain" forment une liste d'options. Les noms sont des méthodes à appeler et les arguments, s'ils sont donnés, sont des tableaux référencés à déréférencer et à passer comme arguments à ces méthodes. "curry_chain" renvoie un générateur comme ceux attendus par Sub::Exporter.

Attention ! à l'heure actuelle, il n'y a aucun moyen de passer des arguments de la routine générée aux appels de méthode. Cela sera probablement résolu dans les futures révisions en permettant aux valeurs de la liste d'options d'être des sous-routines qui seront appelées avec la pile de la routine générée.

merge_col

exports => {
  merge_col(defaults => {
    twiddle => \'_twiddle_gen',
    tweak   => \&_tweak_gen,
  }),
}

Cet utilitaire encapsule le générateur donné dans un autre qui fusionnera la collection nommée dans ses arguments avant de l'appeler. Cela signifie que vous pouvez prendre en charge un collecteur "par défaut" dans plusieurs exportations sans écrire le code à chaque fois.

Vous pouvez spécifier autant de paires de noms de collection et de générateurs que vous le souhaitez.

mixin_installer

use Sub::Exporter -setup => {
  installer => Sub::Exporter::Util::mixin_installer,
  exports   => [ qw(foo bar baz) ],
};

Cet utilitaire renvoie un installateur qui s'installera dans une super-classe et ajustera la classe qui importe ISA pour inclure la super-classe nouvellement générée.

Si la cible de l'importation est un objet, la hiérarchie est inversée : la nouvelle classe sera ISA de la classe de l'objet, et l'objet sera reblessé.

Prérequis : Cet utilitaire nécessite que Package::Generator soit installé.

like

C'est un collecteur qui ajoute des importations pour tout ce qui correspond au regex donné.

Si vous fournissez cette configuration :

exports    => [ qw(igrep imap islurp exhausted) ],
collectors => { -like => Sub::Exporter::Util::like },

Un utilisateur peut importer depuis votre module comme ceci :

use Your::Iterator -like => qr/^i/; # importe igre, imap, islurp

ou

use Your::Iterator -like => [ qr/^i/ => { -prefix => 'your_' } ];

Les arguments de préfixe et de suffixe group-like sont respectés ; d'autres arguments sont transmis aux générateurs pour les exportations correspondantes.
