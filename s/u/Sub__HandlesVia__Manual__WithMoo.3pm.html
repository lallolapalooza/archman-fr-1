NOM

Sub::HandlesVia::Manual::WithMoo - utiliser Sub::HandlesVia avec Moo

SYNOPSIS

package Kitchen {
  use Moo;
  use Sub::HandlesVia;
  use Types::Standard qw( ArrayRef Str );

  has food => (
    is          => 'ro',
    isa         => ArrayRef[Str],
    handles_via => 'Array',
    default     => sub { [] },
    handles     => {
      'add_food'    => 'push',
      'find_food'   => 'grep',
    },
  );
}

MANUEL

Sub::HandlesVia permet de déléguer des méthodes de votre classe aux valeurs des attributs de vos objets.

Conceptuellement, il permet de définir "$objet->push_number($n)" comme un raccourci pour "$objet->numbers->push($n)", sauf que "$objet->numbers" est un arrayref, il n'a donc pas de méthodes appelables dessus comme "push".

Vous devriez pouvoir utiliser Sub::HandlesVia comme un remplacement direct de MooX::HandlesVia, qui fournit une fonctionnalité similaire, bien qu'avec une implémentation plus limitée. Sub::HandlesVia respecte les contraintes de type, et peut muter des valeurs non référencées.

Quelles méthodes peuvent être déléguées ?

L'option "handles_via" indique quelle bibliothèque de méthodes doit être disponible. Les valeurs valides incluent Array, Blessed, Bool, Code, Counter, Enum, Hash, Number, Scalar et String.

Un arrayref peut être fourni pour "handles_via", bien que plusieurs options soient conceptuellement contradictoires.

handles_via => [ 'Number', 'Scalar' ]

BOGUES

Veuillez signaler tout bogue à https://github.com/tobyink/p5-sub-handlesvia/issues.

Boguess potentiels d'ordre de chargement

Contrairement à Moose, Moo n'offre pas beaucoup d'API pour les extensions. Par conséquent, la plupart des modules qui fournissent des extensions le font en encapsulant les mots-clés Moo (en particulier "has"). Sub::HandlesVia ne fait pas exception. Si vous utilisez plusieurs extensions Moo, vous devrez peut-être ajuster l'ordre dans lequel vous les "use" pour qu'elles fonctionnent correctement ensemble. Dans certaines combinaisons, il peut n'y avoir aucun ordre qui fonctionne entièrement !

Certains modules connus qui devraient être importés *avant* Sub::HandlesVia si vous les utilisez : MooX::Should.

Certains modules connus qui devraient être importés *après* Sub::HandlesVia si vous les utilisez : MooX::ProtectedAttributes.

Certains modules connus qui entrent en conflit avec Sub::HandlesVia : aucun pour l'instant !
