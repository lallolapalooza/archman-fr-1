NOM

Sub::Exporter::Tutorial - un guide convivial pour exporter avec Sub::Exporter

VERSION

version 0.991

DESCRIPTION

Qu'est-ce qu'un Exporter ?

Lorsque vous "utilisez" un module, il est d'abord requis, puis sa méthode "import" est appelée. La documentation Perl nous indique que les deux lignes suivantes sont équivalentes :

use Module LIST;
BEGIN { require Module; Module->import(LIST); }

La méthode nommée "import" est l'"exporter" du module, elle exporte des fonctions et des variables dans l'espace de noms de son appelant.

Les bases de Sub::Exporter

Sub::Exporter construit un exportateur personnalisé qui peut ensuite être installé dans votre module. Il construit cette méthode basée sur la configuration passée à sa méthode "setup_exporter".

Un cas d'utilisation très basique pourrait ressembler à ceci :

package Addition;
use Sub::Exporter;
Sub::Exporter::setup_exporter({ exports => [ qw(plus) ]});
sub plus { my ($x, $y) = @_; return $x + $y; }

Cela signifierait que lorsque quelqu'un utilise votre module Addition, il pourrait avoir sa routine "plus" importée dans son propre package :

use Addition qw(plus);
my $z = plus(2, 2); # cela fonctionne, car plus est maintenant dans le package principal

La syntaxe pour configurer l'exportateur, ci-dessus, est un peu verbeuse, donc pour le cas simple de simplement nommer quelques exportations, vous pouvez écrire ceci :

use Sub::Exporter -setup => { exports => [ qw(plus) ] };

...ce qui est identique à l'exemple original -- sauf que maintenant l'exportateur est construit et installé au moment de la compilation. Eh bien, et vous avez tapé moins.

Utilisation des groupes d'exportation

Vous pouvez spécifier des groupes entiers d'éléments qui devraient être exportables ensemble. Ce sont des groupes. L'exportateur les appelle des tags. Pour spécifier des groupes, vous passez simplement une clé "groups" dans la configuration de votre exportateur :

package Food;
use Sub::Exporter -setup => {
  exports => [ qw(apple banana beef fluff lox rabbit) ],
  groups  => {
    fauna  => [ qw(beef lox rabbit) ],
    flora  => [ qw(apple banana) ],
  }
};

Maintenant, pour importer toute cette délicieuse viande étrangère, votre consommateur n'a qu'à écrire :

use Food qw(:fauna);
use Food qw(-fauna);

L'une ou l'autre des options ci-dessus est acceptable. Un deux-points est plus traditionnel, mais les barewords avec un deux-points initial ne peuvent pas être mis entre guillemets par une flèche grasse. Nous verrons pourquoi cela est important plus tard.

Les groupes peuvent contenir d'autres groupes. Si vous incluez un nom de groupe (avec le trait d'union ou les deux-points initial) dans une définition de groupe, il sera développé récursivement lorsque l'exportateur sera appelé. L'exportateur ne récursera pas dans le même groupe deux fois lors de l'expansion des groupes.

Il existe deux groupes spéciaux : "all" et "default". Le groupe "all" est défini pour vous et contient toutes les sous-routines exportables. Vous pouvez le redéfinir, si vous souhaitez exporter seulement un sous-ensemble lorsque toutes les exportations sont demandées. Le groupe "default" est l'ensemble des routines à exporter lorsque rien de spécifique n'est demandé. Par défaut, il n'y a pas de groupe "default".

Renommer vos importations

Parfois, vous voulez importer quelque chose, mais vous n'aimez pas le nom sous lequel il est importé. Sub::Exporter peut renommer vos importations pour vous. Si vous vouliez importer "lox" du package Food, mais que vous n'aimiez pas le nom, vous pourriez écrire ceci :

use Food lox => { -as => 'salmon' };

Maintenant, vous obtiendriez la routine "lox", mais elle serait appelée salmon dans votre package. Vous pouvez également renommer des groupes entiers en utilisant l'option "prefix" :

use Food -fauna => { -prefix => 'cute_little_' };

Maintenant, vous pouvez appeler votre routine "cute_little_rabbit". (Vous pouvez aussi appeler "cute_little_beef", mais cela semble à peine aussi attrayant.)

Lorsque vous définissez des groupes, vous pouvez inclure le renommage.

use Sub::Exporter -setup => {
  exports => [ qw(apple banana beef fluff lox rabbit) ],
  groups  => {
    fauna  => [ qw(beef lox), rabbit => { -as => 'coney' } ],
  }
};

Un préfixe sur un groupe comme celui-ci fait ce qu'il faut. C'est là qu'il est utile d'utiliser un trait d'union au lieu de deux-points pour indiquer un groupe : vous pouvez placer une flèche grasse entre le groupe et ses arguments, alors.

use Food -fauna => { -prefix => 'lovely_' };
eat( lovely_coney ); # cela fonctionne

Les préfixes s'appliquent également récursivement. Cela signifie que ce code fonctionne :

use Sub::Exporter -setup => {
  exports => [ qw(apple banana beef fluff lox rabbit) ],
  groups  => {
    fauna   => [ qw(beef lox), rabbit => { -as => 'coney' } ],
    allowed => [ -fauna => { -prefix => 'willing_' }, 'banana' ],
  }
};
...
use Food -allowed => { -prefix => 'any_' };
$dinner = any_willing_coney; # miam !

Les groupes peuvent également recevoir un argument "-suffix".

Enfin, si l'argument "-as" pour une routine exportée est une référence à un scalaire, une référence à la routine sera placée dans ce scalaire.

Construire des sous-routines à la demande

Parfois, vous voulez exporter des choses que vous n'avez pas sous la main. Vous pourriez vouloir offrir des routines personnalisées construites selon les spécifications de votre consommateur ; c'est juste une bonne gestion ! Avec Sub::Exporter, c'est facile.

Pour offrir des sous-routines à la demande, vous devez fournir un générateur lorsque vous configurez votre exportateur. Un générateur est juste une routine qui retourne une nouvelle routine. perlref parle de ceux-ci lorsqu'il discute des fermetures et des modèles de fonction. L'exemple canonique d'un générateur construit un incrémenteur unique ; voici comment vous feriez cela avec Sub::Exporter ;

package Package::Counter;
use Sub::Exporter -setup => {
  exports => [ counter => sub { my $i = 0; sub { $i++ } } ],
  groups  => { default => [ qw(counter) ] },
};

Maintenant, n'importe qui peut utiliser votre module Package::Counter et il recevra un "counter" dans son package. Il comptera jusqu'à un, et n'interférera jamais avec le compteur de quiconque.

Ce n'est cependant pas très utile, à moins que le consommateur ne puisse expliquer ce qu'il veut. Ceci est fait, en partie, en fournissant des arguments lors de l'importation. L'exemple suivant montre comment un générateur peut prendre et utiliser des arguments :

package Package::Counter;
sub _build_counter {
  my ($class, $name, $arg) = @_;
  $arg ||= {};
  my $i = $arg->{start} || 0;
  return sub { $i++ };
}
use Sub::Exporter -setup => {
  exports => [ counter => \'_build_counter' ],
  groups  => { default => [ qw(counter) ] },
};

Maintenant, le consommateur peut (s'il le souhaite) spécifier une valeur de départ pour son compteur :

use Package::Counter counter => { start => 10 };

Les arguments d'un groupe sont transmis aux générateurs des routines de ce groupe, mais les arguments de Sub::Exporter -- tout ce qui commence par un trait d'union -- ne sont jamais transmis. Lorsque les groupes sont imbriqués, les arguments sont fusionnés lorsque les groupes sont développés.

Remarquez également que dans l'exemple ci-dessus, nous avons donné une référence à un *nom* de méthode plutôt qu'à une *implémentation* de méthode. En donnant le nom plutôt que la sous-routine, nous permettons aux sous-classes de notre module "Package::Counter" de remplacer la méthode "_build_counter".

Lorsqu'un générateur est appelé, il reçoit quatre paramètres :

  • l'invocant sur lequel l'exportateur a été appelé
  • le nom de l'exportation en cours de génération (pas le nom sous lequel elle est installée)
  • les arguments fournis pour la routine
  • la collection d'arguments génériques

Le quatrième élément est la dernière caractéristique majeure qui n'a pas été abordée.

Collecteurs d'arguments

Les collecteurs d'arguments sont des routines qui prennent les arguments qui leur sont passés, et qui les retournent dans un format qui leur convient. Ils sont particulièrement utiles lorsque vous avez affaire à des générateurs, car ils vous permettent de spécifier des arguments qui seront ensuite passés au générateur.

Voici comment vous pourriez créer un générateur qui construit un compteur, mais qui permet à l'utilisateur de spécifier à la fois la valeur de départ et l'incrément :

package Package::Counter;
sub _build_counter {
  my ($class, $name, $args) = @_;
  $args ||= {};
  my $start = $args->{start} || 0;
  my $step  = $args->{step}  || 1;
  return sub {
    my $current = $start;
    $start += $step;
    return $current;
  };
}
sub _collect_args {
  my ($class, $name, @args) = @_;
  my $hashref;
  if (@args == 1 && ref $args[0] eq 'HASH') {
    $hashref = $args[0];
  } else {
    $hashref = { map { $_ => 1 } @args };
  }
  return $hashref;
}
use Sub::Exporter -setup => {
  exports => [
    counter => {
      generator => \'_build_counter',
      collector => \'_collect_args',
    },
  ],
  groups => { default => [ qw(counter) ] },
};

Maintenant, l'utilisateur peut spécifier l'incrément :

use Package::Counter counter => { start => 10, step => 3 };
my @nums = map { counter() } 1 .. 5; # (10, 13, 16, 19, 22)

Le collecteur d'arguments est également appelé lorsque des groupes sont utilisés. Si vous avez un groupe qui utilise des arguments, ces arguments sont d'abord passés au collecteur d'arguments du groupe, puis transmis au collecteur d'arguments de chaque routine du groupe.

Les arguments génériques sont également collectés. Ceux-ci sont stockés dans la quatrième clé de l'argument, et sont transmis aux générateurs des routines.

Arguments génériques

Les arguments génériques sont des arguments qui ne sont pas destinés à une routine spécifique, mais à l'exportateur dans son ensemble. Ils sont identifiés par un trait d'union initial, et ils sont collectés avant que les arguments destinés à des routines spécifiques ne soient traités.

Voici un exemple :

package MyExporter;
use Sub::Exporter -setup => {
  exports => [
    foo => sub { print "foo\n" },
    bar => sub { print "bar\n" },
  ],
  groups => {
    all => [ qw(foo bar) ],
    default => [ qw(foo) ],
  },
};

Dans cet exemple, vous pouvez importer "foo" et "bar" comme ceci :

use MyExporter qw(:all);

Ou simplement "foo" :

use MyExporter;

Les arguments génériques sont particulièrement utiles lorsque vous utilisez des groupes imbriqués. Par exemple, si vous aviez un groupe appelé "utils" qui incluait "foo" et "bar", vous pourriez les importer tous les deux comme ceci :

use MyExporter -utils => { -prefix => 'my_' };

Les arguments génériques sont transmis aux générateurs des routines via le quatrième argument. Dans l'exemple ci-dessus, le générateur de "foo" recevrait les arguments génériques (-prefix => 'my_').

Parfois, vous voudrez accepter des arguments une fois qu'ils pourront être disponibles pour n'importe quelle sous-routine que vous allez exporter. Pour ce faire, vous spécifiez des collecteurs, comme suit :

package Menu::Airline
use Sub::Exporter -setup => {
  exports =>  ... ,
  groups  =>  ... ,
  collectors => [ qw(allergies ethics) ],
};

Les collecteurs ressemblent à des exportations normales dans l'appel d'importation, mais ils ne font rien d'autre que de collecter des données qui peuvent plus tard être transmises aux générateurs. Si le module était utilisé comme suit :

use Menu::Airline allergies => [ qw(peanuts) ], ethics => [ qw(vegan) ];

... le consommateur obtiendrait une salade. De plus, tous les générateurs seraient transmis, en tant que quatrième argument, quelque chose comme ceci :

{ allerges => [ qw(peanuts) ], ethics => [ qw(vegan) ] }

Les générateurs peuvent également avoir des arguments dans leur définition. Ceux-ci doivent être des refs de code qui effectuent la validation des valeurs collectées. Ils sont transmis la valeur de collecte et peuvent retourner vrai ou faux. S'ils retournent faux, l'exportateur lèvera une exception.

Générer de nombreuses routines dans une seule portée

Parfois, il est utile d'avoir plusieurs routines générées dans une seule portée. De cette façon, elles peuvent partager des données lexicales qui sont autrement inaccessibles. Pour ce faire, vous pouvez fournir un générateur pour un groupe qui renvoie un hashref de noms et de références de code. Ce générateur reçoit toutes les données habituelles, et le groupe peut recevoir les arguments habituels "-prefix" ou "-suffix".

La version peut être augmentée pour quelque raison que ce soit, et rien ne garantit que les correctifs seront acceptés pour abaisser la version minimale requise de perl.
