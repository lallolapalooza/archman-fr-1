Sub::HandlesVia::Manual::WithGeneric(3) Documentation Perl fournie par l'utilisateur Sub::HandlesVia::Manual::WithGeneric(3)

NOM

Sub::HandlesVia::Manual::WithGeneric - utiliser Sub::HandlesVia avec des classes Perl génériques

MANUEL

Sub::HandlesVia vous permet de déléguer des méthodes de votre classe aux valeurs des attributs de vos objets.

Conceptuellement, cela vous permet de définir "$objet->push_nombre($n)" comme un raccourci pour "$objet->nombres->push($n)", sauf que "$objet->nombres" est un tableau référencé, il n'a donc pas de méthodes que vous pouvez appeler dessus comme "push".

Pour Moose et Mouse, Sub::HandlesVia peut utiliser leurs protocoles de méta-objets pour saisir la définition d'un attribut et installer les méthodes dont il a besoin. Pour Moo, il peut envelopper "has" et faire son travail de cette façon. Pour d'autres classes, vous devez être plus explicite et lui dire quelles méthodes déléguer à quels attributs.

package Cuisine {

  # constructeur
  sub new {
    my ( $class, %arg ) = @_;
    $arg{nourriture} ||= [];
    return bless( \%arg, $class );
  }

  # getter/setter pour `nourriture`
  sub nourriture {
    (@_ == 1) ? $_[0]{nourriture} : ( $_[0]{nourriture} = $_[1] );
  }

  use Sub::HandlesVia qw( delegations );

  delegations(
    attribute   => 'nourriture'
    handles_via => 'Array',
    handles     => {
      'ajouter_nourriture'    => 'push',
      'trouver_nourriture'   => 'grep',
    },
  );
}

Définir "attribute" sur "nourriture" signifie que lorsque Sub::HandlesVia a besoin de récupérer la liste des aliments, il appellera "$cuisine->nourriture" et lorsqu'il aura besoin de définir la liste des aliments, il appellera "$cuisine->nourriture($valeur)". Si vous avez des méthodes getter et setter séparées, faites simplement :

attribute   => [ 'get_nourriture', 'set_nourriture' ],

Ou si vous n'avez pas d'accesseurs et que vous voulez que Sub::HandlesVia accède directement au hashref sous-jacent :

attribute   => '{nourriture}',

Ou peut-être avez-vous un setter, mais vous voulez utiliser l'accès hashref pour le getter :

attribute   => [ '{nourriture}', 'set_nourriture' ],

Ou peut-être voulez-vous toujours un accès direct pour le getter, mais votre objet est un tableau référencé béni au lieu d'un hashref béni :

attribute   => [ '[7]', 'set_nourriture' ],

Ou peut-être que vos besoins sont uniques et fous :

attribute   => [ \&getter, \&setter ],

Les références de code reçoivent l'instance comme premier argument, et le setter reçoit également une valeur à définir.

Vraiment, je ne pense pas qu'il existe de système objet pour lequel cela ne fonctionnera pas !

Si vous fournissez un tableau référencé avec un getter et un setter, il est également possible de fournir un troisième argument qui est une référence de code ou une chaîne qui sera appelée comme méthode si besoin est de "réinitialiser" la valeur. Cela peut être considéré comme une valeur par défaut ou un constructeur.

(La fonction "delegations" peut également être importée dans les classes Moo/Mouse/Moose, auquel cas l'"attribute" doit être le même nom d'attribut que celui que vous avez passé à "has". Vous ne pouvez pas utiliser un tableau référencé, une référence de code, une clé de hachage ou un index de tableau.)
