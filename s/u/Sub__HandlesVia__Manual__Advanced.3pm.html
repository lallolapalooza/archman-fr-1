Sub::HandlesVia::Manual::Advanced(3) Documentation Perl fournie par l'utilisateur Sub::HandlesVia::Manual::Advanced(3)

NOM

Sub::HandlesVia::Manual::Advanced - documentation avancée divers

MANUEL

Les informations suivantes s'appliquent quel que soit l'outil OO que vous utilisez.

Chaînage de méthodes

Disons que vous avez ceci

handles_via => 'Array',
handles     => {
  'add_food'    => 'push',
  'find_food'   => 'grep',
  'remove_food' => 'pop',
},

Maintenant, "$kitchen->remove_food" supprimera le dernier aliment de la liste et le retournera. Mais que faire si nous ne nous soucions pas de l'aliment qui a été supprimé ? Nous voulons juste supprimer l'aliment et l'ignorer. Vous pouvez faire ceci :

handles_via => 'Array',
handles     => {
  'add_food'    => 'push',
  'find_food'   => 'grep',
  'remove_food' => 'pop...',
},

Maintenant, la méthode "remove_food" retournera l'objet cuisine au lieu de retourner l'aliment. Cela le rend adapté au chaînage des appels de méthode :

# supprime les trois derniers aliments
$kitchen->remove_food->remove_food->remove_food;

Délégation à des CodeRefs

Vous pouvez déléguer à des coderefs :

handles_via => 'Array',
handles    => {
  'find_healthiest' => sub { my $foods = shift; ... },
}

Délégation à des méthodes nommées

La bibliothèque de gestionnaires Sub::HandlesVia::HandlerLibrary::Blessed vous permet de déléguer à des méthodes nommées d'un objet béni.

isa         => InstanceOf['HTTP::Tiny'],
handles_via => 'Blessed',
handles     => {
  'http_get'   => 'get',
  'http_post'  => 'post',
},

Cependant, dans Moo, Moose, Mouse et Mite, ce type de délégation est intégré, vous n'avez donc même pas besoin de Sub::HandlesVia !

isa         => InstanceOf['HTTP::Tiny'],
handles     => {
  'http_get'   => 'get',
  'http_post'  => 'post',
},

Néanmoins, la bibliothèque de gestionnaires Sub::HandlesVia::HandlerLibrary::Blessed peut toujours être utile si vous souhaitez utiliser d'autres fonctionnalités de Sub::HandlesVia comme le chaînage, ou si vous utilisez un autre toolkit OO.

Un exemple combinant la délégation à des méthodes nommées avec la délégation de style « trait natif »... disons que « FoodList » est une classe où les instances sont des bibliothèques d'arrayrefs de chaînes de caractères.

isa         => InstanceOf['FoodList'],
handles_via => 'Array', 'Blessed',
handles     => {
  'find_food'             => 'grep',
  'find_healthiest_food'  => 'find_healthiest',
},

Maintenant, "$kitchen->find_food($coderef)" fait ceci (ce qui enfreint l'encapsulation) :

my @result = grep $coderef->(), @{ $kitchen->food };

Mais comme "find_healthiest" n'est pas l'une des méthodes proposées par Sub::HandlesVia::HandlerList::Array, Sub::HandlesVia suppose que vous souhaitez l'appeler sur l'arrayref comme une méthode normale, donc "$kitchen->find_healthiest_food" fait ceci :

$kitchen->food->find_healthiest

Il peut être utile d'être explicite sur les méthodes que vous souhaitez déléguer à un tableau de style « trait natif » et celles qui sont des méthodes nommées à appeler sur un objet béni :

isa         => InstanceOf['FoodList'],
handles_via => [ 'Array', 'Blessed' ],
handles     => {
  'find_food'             => 'Array->grep',
  'find_healthiest_food'  => 'Blessed->find_healthiest',
},

Voir « Délégation à plusieurs bibliothèques de gestionnaires ».

Arguments curryés

Toute cette histoire de nourriture me donne faim, mais autant que je voudrais manger un curry en ce moment, ce n'est pas le type de curry dont nous parlons.

handles_via => 'Array',
handles     => {
  'get_food'   => 'get',
},

"$kitchen->get_food(0)" retournera le premier élément de la liste. "$kitchen->get_food(1)" retournera le deuxième élément de la liste. Et ainsi de suite.

handles_via => 'Array',
handles     => {
  'first_food'   => [ 'get' => 0 ],
  'second_food'  => [ 'get' => 1 ],
},

Je pense que vous savez déjà ce que cela fait. N'est-ce pas ?

Et oui, le curry fonctionne avec les coderefs.

handles_via => 'Array',
handles     => {
  'blargy'       => [ sub { ... }, @curried ],
},

Vérification des arguments plus lâche

Sub::HandlesVia essaie d'être strict par défaut. Par exemple, si votre attribut spécifie "isa => ArrayRef[Int]" alors votre méthode qui délègue à "push" vérifiera que ses arguments sont des entiers.

Vous pouvez lui dire d'être moins rigoureux dans la vérification des arguments de méthode en utilisant le préfixe "~" :

handles_via => 'Array',
handles     => {
  'find_food'   => '~grep',
},

Délégation à plusieurs bibliothèques de gestionnaires

Parfois, vous souhaiterez choisir des méthodes à déléguer à partir de plusieurs bibliothèques de gestionnaires. Ceci est possible en définissant "handles_via" sur un arrayref.

isa         => ArrayRef|HashRef,
handles_via => [ 'Array', 'Hash' ],
handles     => {
  the_keys     => 'keys',
  ship_shape   => 'sort_in_place',
}

Ici, vous avez un attribut qui peut être un arrayref ou un hashref. Quand c'est un arrayref, "$object->ship_shape" fonctionnera bien, mais "$object->the_keys" échouera lourdement.

Cependant, ce genre de choses peut avoir du sens si vous avez un objet qui surcharge à la fois "@{}" et "%{}".

En particulier, la bibliothèque Sub::HandlesVia::HandlerLibrary::Scalar a souvent du sens à combiner avec les autres bibliothèques car les chaînes, les entiers, les nombres, les booléens, et même les arrayrefs, les hashrefs et les coderefs sont tous des scalaires.

Parfois, un nom de méthode sera ambigu. Par exemple, il existe une méthode "get" pour les hachages et les tableaux. Dans ce cas, celle du tableau gagnera car vous l'avez listée en premier dans "handles_via".

Mais vous pouvez être spécifique :

isa         => ArrayRef|HashRef,
handles_via => [ 'Array', 'Hash' ],
handles     => {
  get_by_index => 'Array->get',
  get_by_key   => 'Hash->get',
}
