DESCRIPTION

Ces macros définissent et opèrent sur quatre types de structures de données qui peuvent être utilisées en C et C++ :

  1. Liste
  2. Liste doublement chaînée
  3. File d'attente
  4. File
Les quatre structures supportent la fonctionnalité suivante :
  1. Insertion d'un nouvel élément au début de la liste.
  2. Insertion d'un nouvel élément après n'importe quel élément de la liste.
  3. Suppression O(1) d'un élément du début de la liste.
  4. Parcours avant de la liste.
  5. Échange du contenu de deux listes.
Les listes doublement chaînées sont les plus simples des quatre structures et ne supportent que la fonctionnalité mentionnée. Les listes doublement chaînées sont idéales pour les applications avec de grands ensembles de données et peu ou pas de suppressions, ou pour implémenter une pile LIFO. Les listes doublement chaînées ajoutent la fonctionnalité suivante :
  1. Suppression O(n) de n'importe quel élément de la liste.
  2. Concaténation O(n) de deux listes.
Les files d'attente ajoutent la fonctionnalité suivante :
  1. Les éléments peuvent être insérés à la fin d'une liste.
  2. Suppression O(n) de n'importe quel élément de la liste.
  3. Peuvent être concaténées.
Cependant :
  1. Toutes les insertions dans la liste doivent spécifier le début de la liste.
  2. Chaque entrée d'en-tête nécessite deux pointeurs au lieu d'un.
  3. La taille du code est approximativement 15% plus grande et les opérations prennent approximativement 20% plus de temps que dans les listes doublement chaînées.
Les files d'attente sont idéales pour les applications avec de grands ensembles de données et peu ou pas de suppressions, ou pour implémenter une file FIFO.

Toutes les structures de données doublement chaînées (listes et files d'attente) permettent également :

  1. Insertion d'un nouvel élément avant n'importe quel élément de la liste.
  2. Suppression O(1) de n'importe quel élément de la liste.
Cependant :
  1. Chaque élément nécessite deux pointeurs au lieu d'un.
  2. La taille du code et le temps d'exécution des opérations (à l'exception de la suppression) sont approximativement le double de ceux des structures de données doublement chaînées.

Les listes sont les plus simples des structures de données doublement chaînées. Elles ajoutent la fonctionnalité suivante par rapport aux précédentes :

  1. Concaténation O(n) de deux listes.
  2. Peuvent être parcourues en sens inverse.
Cependant :
  1. Pour parcourir en sens inverse, l'élément initial et la liste dans laquelle il se trouve doivent être spécifiés.

Les files ajoutent la fonctionnalité suivante :

  1. Les éléments peuvent être insérés à la fin d'une liste.
  2. Peuvent être parcourues en sens inverse, de la fin vers le début.
  3. Peuvent être concaténées.
Cependant :
  1. Toutes les insertions et suppressions dans la liste doivent spécifier le début de la liste.
  2. Chaque entrée d'en-tête nécessite deux pointeurs au lieu d'un.
  3. La taille du code est approximativement 15% plus grande et les opérations prennent approximativement 20% plus de temps que dans les listes doublement chaînées.

Dans les définitions de macros, TYPE est le nom d'une structure définie par l'utilisateur. La structure doit inclure un champ nommé NAME du type SLIST_ENTRY, STAILQ_ENTRY, LIST_ENTRY ou TAILQ_ENTRY. Dans les définitions de macros, CLASSTYPE est le nom d'une classe définie par l'utilisateur. La classe doit inclure un champ nommé NAME du type SLIST_CLASS_ENTRY, STAILQ_CLASS_ENTRY, LIST_CLASS_ENTRY ou TAILQ_CLASS_ENTRY. L'argument HEADNAME est le nom d'une structure définie par l'utilisateur qui doit être déclarée en utilisant les macros SLIST_HEAD, SLIST_CLASS_HEAD, STAILQ_HEAD, STAILQ_CLASS_HEAD, LIST_HEAD, LIST_CLASS_HEAD, TAILQ_HEAD ou TAILQ_CLASS_HEAD. Voir les exemples suivants pour une explication plus détaillée de l'utilisation de ces macros.

LISTES SIMPLEMENT CHAÎNÉES

Une liste simplement chaînée est dirigée par une structure définie à l'aide de la macro SLIST_HEAD. Cette structure contient un unique pointeur vers le premier élément de la liste. Les éléments sont simplement chaînés pour minimiser l'espace et la surcharge de manipulation des pointeurs, mais au prix de O(n) pour supprimer des éléments arbitraires. De nouveaux éléments peuvent être ajoutés à la liste après un élément existant ou au début de la liste. Une structure SLIST_HEAD est déclarée comme suit :

SLIST_HEAD(HEADNAME, TYPE) head;

où HEADNAME est le nom de la structure à définir, et TYPE est le type des éléments de la liste. Un pointeur vers la tête de la liste peut être déclaré plus tard comme suit :

struct HEADNAME *headp;

(Les noms head et headp sont sélectionnables par l'utilisateur.)

La macro SLIST_HEAD_INITIALIZER évalue à un initialiseur pour la liste head.

La macro SLIST_CONCAT concatène la liste dirigée par head2 à la fin de la liste dirigée par head1, supprimant tous les éléments de la première. L'utilisation de cette macro doit être évitée, car elle parcourt toute la liste head1. Une file d'attente simplement chaînée (tailq) devrait être utilisée si cette macro est nécessaire dans des chemins de code à usage intensif ou pour opérer sur de longues listes.

La macro SLIST_EMPTY évalue à vrai s'il n'y a pas d'éléments dans la liste.

La macro SLIST_ENTRY déclare une structure qui relie les éléments de la liste.

La macro SLIST_FIRST renvoie le premier élément de la liste ou NULL si la liste est vide.

La macro SLIST_FOREACH parcourt la liste référencée par head dans le sens avant, assignant chaque élément dans l'ordre à var.

La macro SLIST_FOREACH_FROM se comporte de manière identique à SLIST_FOREACH lorsque var est NULL, sinon elle traite var comme un élément précédemment trouvé dans une liste SLIST et commence la boucle sur var au lieu du premier élément de la liste référencée par head.

La macro SLIST_FOREACH_SAFE parcourt la liste référencée par head dans le sens avant, assignant chaque élément dans l'ordre à var. Cependant, contrairement à SLIST_FOREACH(), il est permis de supprimer var et de libérer la mémoire en toute sécurité à l'intérieur de la boucle sans interférer avec le trajet de parcours.

La macro SLIST_FOREACH_FROM_SAFE se comporte de manière identique à SLIST_FOREACH_SAFE lorsque var est NULL, sinon elle traite var comme un élément précédemment trouvé dans une liste SLIST et commence la boucle sur var au lieu du premier élément de la liste référencée par head.

La macro SLIST_INIT initialise la liste référencée par head.

La macro SLIST_INSERT_HEAD insère le nouvel élément elm au début de la liste.

La macro SLIST_INSERT_AFTER insère le nouvel élément elm après l'élément.

LISTS

A list is headed by a structure defined by the LIST_HEAD macro. This structure contains a pointer to the first element in the list. The elements are singly linked so that the list cannot be traversed backwards. New elements can be added to the list after an existing element, or at the head of the list. A LIST_HEAD structure is declared as follows:

LIST_HEAD(HEADNAME, TYPE) head;

where HEADNAME is the name of the structure to be defined, and TYPE is the type of the elements to be linked into the list. A pointer to the head of the list can later be declared as:

struct HEADNAME *headp;

(The names head and headp are user selectable.)

The macro LIST_HEAD_INITIALIZER evaluates to an initializer for the list head.

The macro LIST_ENTRY declares a structure that connects the elements in the list.

The macro LIST_FIRST returns the first element on the list or NULL if the list is empty.

The macro LIST_FOREACH traverses the list referenced by head in the forward direction, assigning each element in turn to var.

The macro LIST_FOREACH_FROM behaves identically to LIST_FOREACH when var is NULL, else it treats var as a previously found LIST element and begins the loop at var instead of the first element in the LIST referenced by head.

The macro LIST_FOREACH_SAFE traverses the list referenced by head in the forward direction, assigning each element in turn to var. However, unlike LIST_FOREACH() here it is permitted to both remove var as well as free it from within the loop safely without interfering with the traversal.

The macro LIST_FOREACH_FROM_SAFE behaves identically to LIST_FOREACH_SAFE when var is NULL, else it treats var as a previously found LIST element and begins the loop at var instead of the first element in the LIST referenced by head.

The macro LIST_INIT initializes the list referenced by head.

The macro LIST_INSERT_HEAD inserts the new element elm at the head of the list.

The macro LIST_INSERT_AFTER inserts the new element elm after the element listelm.

The macro LIST_INSERT_BEFORE inserts the new element elm before the element listelm.

The macro LIST_NEXT returns the next element in the list, or NULL if this is the last.

The macro LIST_PREV returns the previous element in the list, or NULL if this is the first. List head must contain element elm.

The macro LIST_REMOVE removes the element elm from the list.

The macro LIST_SWAP swaps the contents of head1 and head2.

LIST_FOREACH(np, &head, entries)
	np-> ...

					/* Safe forward traversal. */
LIST_FOREACH_SAFE(np, &head, entries, np_temp) {
	np->do_stuff();
	...
	LIST_REMOVE(np, entries);
	free(np);
}

while (!LIST_EMPTY(&head)) {		/* List Deletion. */
	n1 = LIST_FIRST(&head);
	LIST_REMOVE(n1, entries);
	free(n1);
}

n1 = LIST_FIRST(&head);			/* Faster List Deletion. */
while (n1 != NULL) {
	n2 = LIST_NEXT(n1, entries);
	free(n1);
	n1 = n2;
}
LIST_INIT(&head);

TAIL QUEUES

A tail queue is headed by a structure defined by the TAILQ_HEAD macro. This structure contains a pair of pointers, one to the first element in the tail queue and the other to the last element in the tail queue. The elements are doubly linked so that an arbitrary element can be removed without traversing the tail queue. New elements can be added to the tail queue after an existing element, before an existing element, at the head of the tail queue, or at the end of the tail queue. A TAILQ_HEAD structure is declared as follows:

TAILQ_HEAD(HEADNAME, TYPE) head;

where HEADNAME is the name of the structure to be defined, and TYPE is the type of the elements to be linked into the tail queue. A pointer to the head of the tail queue can later be declared as:

struct HEADNAME *headp;

(The names head and headp are user selectable.)

The macro TAILQ_HEAD_INITIALIZER evaluates to an initializer for the tail queue head.

The macro TAILQ_CONCAT concatenates the tail queue headed by head2 onto the end of the one headed by head1 removing all entries from the former.

The macro TAILQ_EMPTY evaluates to true if there are no items on the tail queue.

The macro TAILQ_ENTRY declares a structure that connects the elements in the tail queue.

The macro TAILQ_FIRST returns the first item on the tail queue or NULL if the tail queue is empty.

The macro TAILQ_FOREACH traverses the tail queue referenced by head in the forward direction, assigning each element in turn to var. var is set to NULL if the loop completes normally, or if there were no elements.

The macro TAILQ_FOREACH_FROM behaves identically to TAILQ_FOREACH when var is NULL, else it treats var as a previously found TAILQ element and begins the loop at var instead of the first element in the TAILQ referenced by head.

The macro TAILQ_FOREACH_REVERSE traverses the tail queue referenced by head in the reverse direction, assigning each element in turn to var.

The macro TAILQ_FOREACH_REVERSE_FROM behaves identically to TAILQ_FOREACH_REVERSE when var is NULL, else it treats var as a previously found TAILQ element and begins the reverse loop at var instead of the last element in the TAILQ referenced by head.

The macros TAILQ_FOREACH_SAFE and TAILQ_FOREACH_REVERSE_SAFE traverse the list referenced by head in the forward or reverse direction respectively, assigning each element in turn to var. However, unlike their unsafe counterparts, TAILQ_FOREACH and TAILQ_FOREACH_REVERSE make it possible to both remove var as well as free it from within the loop safely without interfering with the traversal.

The macro TAILQ_FOREACH_FROM_SAFE behaves identically to TAILQ_FOREACH_SAFE when var is NULL, else it treats var as a previously found TAILQ element and begins the loop at var instead of the first element in the TAILQ referenced by head.

The macro TAILQ_FOREACH_REVERSE_FROM_SAFE behaves identically to TAILQ_FOREACH_REVERSE_SAFE when var is NULL, else it treats var as a previously found TAILQ element and begins the reverse loop at var instead of the last element in the TAILQ referenced by head.

The macro TAILQ_INIT initializes the tail queue referenced by head.

The macro TAILQ_INSERT_HEAD inserts the new element elm at the head of the tail queue.

The macro TAILQ_INSERT_TAIL inserts the new element elm at the end of the tail queue.

The macro TAILQ_INSERT_AFTER inserts the new element elm after the element listelm.

The macro TAILQ_INSERT_BEFORE inserts the new element elm before the element listelm.

The macro TAILQ_LAST returns the last item on the tail queue. If the tail queue is empty the return value is NULL.

The macro TAILQ_NEXT returns the next item on the tail queue, or NULL if this item is the last.

The macro TAILQ_PREV returns the previous item on the tail queue, or NULL if this item is the first.

The macro TAILQ_REMOVE removes the element elm from the tail queue.

The macro TAILQ_SWAP swaps the contents of head1 and head2.

TAIL QUEUE EXAMPLE

TAILQ_HEAD(tailhead, entry) head =
    TAILQ_HEAD_INITIALIZER(head);
struct tailhead *headp;			/* Tail queue head. */
struct entry {
	...
	TAILQ_ENTRY(entry) entries;	/* Tail queue. */
	...
} *n1, *n2, *n3, *np;

TAILQ_INIT(&head);			/* Initialize the queue. */

n1 = malloc(sizeof(struct entry));	/* Insert at the head. */
TAILQ_INSERT_HEAD(&head, n1, entries);

n1 = malloc(sizeof(struct entry));	/* Insert at the tail. */
TAILQ_INSERT_TAIL(&head, n1, entries);

n2 = malloc(sizeof(struct entry));	/* Insert after. */
TAILQ_INSERT_AFTER(&head, n1, n2, entries);

n3 = malloc(sizeof(struct entry));	/* Insert before. */
TAILQ_INSERT_BEFORE(n2, n3, entries);

TAILQ_REMOVE(&head, n2, entries);	/* Deletion. */
free(n2);
					/* Forward traversal. */
TAILQ_FOREACH(np, &head, entries)
	np-> ...
					/* Safe forward traversal. */
TAILQ_FOREACH_SAFE(np, &head, entries, np_temp) {
	np->do_stuff();
	...
	TAILQ_REMOVE(&head, np, entries);
	free(np);
}
					/* Reverse traversal. */
TAILQ_FOREACH_REVERSE(np, &head, tailhead, entries)
	np-> ...
					/* TailQ Deletion. */
while (!TAILQ_EMPTY(&head)) {
	n1 = TAILQ_FIRST(&head);
	TAILQ_REMOVE(&head, n1, entries);
	free(n1);
}
					/* Faster TailQ Deletion. */
n1 = TAILQ_FIRST(&head);
while (n1 != NULL) {
	n2 = TAILQ_NEXT(n1, entries);
	free(n1);
	n1 = n2;
}
TAILQ_INIT(&head);

DESCRIPTION

Les fonctions queue fournissent un moyen de gérer une liste d'éléments, où chaque élément est ajouté à la fin de la liste, et la liste est parcourue du début à la fin. Il s'agit d'une implémentation de liste simplement chaînée.

LISTES SIMPLEMENT CHAÎNÉES

Cette implémentation utilise une liste simplement chaînée, où chaque nœud contient un pointeur vers le nœud suivant dans la liste. La liste est gérée de manière à permettre des opérations d'insertion et de suppression efficaces.

EXEMPLE DE LISTE SIMPLEMENT CHAÎNÉE

#include <libbsd.h>

int
main(int argc, char *argv[]) {
    struct queue *q = queue_new();
    struct queue *n1 = queue_new();
    struct queue *n2 = queue_new();

    queue_add_tail(q, n1);
    queue_add_tail(q, n2);

    queue_print(q);

    free(n1);
    n1 = n2;
}
TAILQ_INIT(&head);

Cette implémentation utilise une file d'attente à queue, où la queue (la fin) de la file est conservée à la fin de la liste. La liste est parcourue du début à la fin, et la queue est toujours à la fin de la liste.

    tail_queue_print(tq);

    free(n1);
    n1 = n2;
}
TAILQ_INIT(&head);

DIAGNOSTICS

Lors du débogage de queue(3), il peut être utile de tracer les modifications de la file. Pour activer le traçage, définissez la macro QUEUE_MACRO_DEBUG_TRACE au moment de la compilation.

Il peut également être utile de corrompre les pointeurs qui ont été désolidarisés d'une file, afin de détecter leur utilisation après suppression. Pour activer la corruption des pointeurs, définissez la macro QUEUE_MACRO_DEBUG_TRASH au moment de la compilation. La macro QMD_IS_TRASHED(void *ptr) renvoie vrai si ptr a été corrompu par l'option QUEUE_MACRO_DEBUG_TRASH.
