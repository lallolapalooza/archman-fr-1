DESCRIPTION

Ces macros définissent et opèrent sur quatre types de structures de données qui peuvent être utilisées dans le code source C et C++ :

  1. Listes
  2. Listes chaînées simples
  3. Queues de liste chaînées simples
  4. Queues de liste
Les quatre structures supportent les fonctionnalités suivantes :
  1. Insertion d'une nouvelle entrée en tête de liste.
  2. Insertion d'une nouvelle entrée après un élément existant dans la liste.
  3. Suppression en O(1) d'une entrée de la tête de liste.
  4. Parcours avant dans la liste.
  5. Échange du contenu de deux listes.

Les listes chaînées simples sont les plus simples des quatre structures de données et ne supportent que les fonctionnalités ci-dessus. Les listes chaînées simples sont idéales pour les applications avec de grands ensembles de données et peu ou pas de suppressions, ou pour implémenter une pile (LIFO). Les listes chaînées simples ajoutent les fonctionnalités suivantes :

  1. Suppression en O(n) de n'importe quelle entrée dans la liste.
  2. Concaténation en O(n) de deux listes.

Les queues de liste chaînées simples ajoutent les fonctionnalités suivantes :

  1. Les entrées peuvent être ajoutées à la fin d'une liste.
  2. Suppression en O(n) de n'importe quelle entrée dans la liste.
  3. Elles peuvent être concaténées.
Cependant :
  1. Toutes les insertions dans la liste doivent spécifier la tête de la liste.
  2. Chaque entrée de tête nécessite deux pointeurs au lieu d'un.
  3. La taille du code est environ 15% plus grande et les opérations sont environ 20% plus lentes que pour les listes chaînées simples.

Les queues de liste chaînées simples sont idéales pour les applications avec de grands ensembles de données et peu ou pas de suppressions, ou pour implémenter une file d'attente (FIFO).

Toutes les structures de données de type doublement chaînées (listes et queues de liste) permettent en outre :

  1. Insertion d'une nouvelle entrée avant un élément existant dans la liste.
  2. Suppression en O(1) de n'importe quelle entrée dans la liste.
Cependant :
  1. Chaque élément nécessite deux pointeurs au lieu d'un.
  2. La taille du code et le temps d'exécution des opérations (à l'exception de la suppression) sont environ le double de ceux des structures de données simplement chaînées.

Les listes chaînées sont les plus simples des structures de données doublement chaînées. Elles ajoutent les fonctionnalités suivantes par rapport à celles ci-dessus :

  1. Concaténation en O(n) de deux listes.
  2. Elles peuvent être parcourues en arrière.
Cependant :
  1. Pour parcourir en arrière, une entrée pour commencer le parcours et la liste dans laquelle elle se trouve doivent être spécifiées.

Les queues de liste ajoutent les fonctionnalités suivantes :

  1. Les entrées peuvent être ajoutées à la fin d'une liste.
  2. Elles peuvent être parcourues en arrière, de la queue à la tête.
  3. Elles peuvent être concaténées.
Cependant :
  1. Toutes les insertions et suppressions de liste doivent spécifier la tête de la liste.
  2. Chaque entrée de tête nécessite deux pointeurs au lieu d'un.
  3. La taille du code est environ 15% plus grande et les opérations sont environ 20% plus lentes que pour les listes chaînées simples.

Dans les définitions de macros, TYPE est le nom d'une structure définie par l'utilisateur. La structure doit contenir un champ appelé NOM qui est de type SLIST_ENTRY, STAILQ_ENTRY, LIST_ENTRY, ou TAILQ_ENTRY. Dans les définitions de macros, CLASSTYPE est le nom d'une classe définie par l'utilisateur. La classe doit contenir un champ appelé NOM qui est de type SLIST_CLASS_ENTRY, STAILQ_CLASS_ENTRY, LIST_CLASS_ENTRY, ou TAILQ_CLASS_ENTRY. L'argument NOMTETE est le nom d'une structure définie par l'utilisateur qui doit être déclarée en utilisant les macros SLIST_HEAD, SLIST_CLASS_HEAD, STAILQ_HEAD, STAILQ_CLASS_HEAD, LIST_HEAD, LIST_CLASS_HEAD, TAILQ_HEAD, ou TAILQ_CLASS_HEAD. Voir les exemples ci-dessous pour plus d'explications sur l'utilisation de ces macros.

LISTES CHAÎNÉES SIMPLES

Une liste chaînée simple est dirigée par une structure définie par la macro SLIST_HEAD. Cette structure contient un seul pointeur vers le premier élément de la liste. Les éléments sont chaînés simplement pour un minimum d'espace et de surcharge de manipulation de pointeurs, au détriment d'une suppression en O(n) pour des éléments arbitraires. De nouveaux éléments peuvent être ajoutés à la liste après un élément existant ou en tête de liste. Une structure SLIST_HEAD est déclarée comme suit :

SLIST_HEAD(NOMTETE, TYPE) tete;

où NOMTETE est le nom de la structure à définir, et TYPE est le type des éléments à lier dans la liste. Un pointeur vers la tête de la liste peut ensuite être déclaré comme :

struct NOMTETE *teteP;

(Les noms tete et teteP sont sélectionnables par l'utilisateur.)

La macro SLIST_HEAD_INITIALIZER évalue à un initialiseur pour la liste tete.

La macro SLIST_CONCAT concatène la liste dirigée par tete2 à la fin de celle dirigée par tete1, en supprimant toutes les entrées de la première. L'utilisation de cette macro doit être évitée car elle parcourt la totalité de la liste tete1. Une queue de liste chaînée simple devrait être utilisée si cette macro est nécessaire dans des chemins de code à forte utilisation ou pour opérer sur de longues listes.

La macro SLIST_EMPTY évalue à vrai s'il n'y a aucun élément dans la liste.

La macro SLIST_ENTRY déclare une structure qui relie les éléments de la liste.

La macro SLIST_FIRST renvoie le premier élément de la liste ou NULL si la liste est vide.

La macro SLIST_FOREACH parcourt la liste référencée par tete dans la direction avant, affectant chaque élément en tour à var.

La macro SLIST_FOREACH_FROM se comporte identiquement à SLIST_FOREACH lorsque var est NULL, sinon elle traite var comme un élément SLIST trouvé précédemment et commence la boucle à var au lieu du premier élément de la liste SLIST référencée par tete.

La macro SLIST_FOREACH_SAFE parcourt la liste référencée par tete dans la direction avant, affectant chaque élément en tour à var. Cependant, contrairement à SLIST_FOREACH(), ici il est permis de supprimer var ainsi que de le libérer depuis l'intérieur de la boucle en toute sécurité sans interférer avec le parcours.

La macro SLIST_FOREACH_FROM_SAFE se comporte identiquement à SLIST_FOREACH_SAFE lorsque var est NULL, sinon elle traite var comme un élément SLIST trouvé précédemment et commence la boucle à var au lieu du premier élément de la liste SLIST référencée par tete.

La macro SLIST_INIT initialise la liste référencée par tete.

La macro SLIST_INSERT_HEAD insère le nouvel élément elm en tête de la liste.

La macro SLIST_INSERT_AFTER insère le nouvel élément elm après l'élément

EXEMPLE DE LISTE LIAISON SIMPLE

SLIST_HEAD(slisthead, entry) head =
    SLIST_HEAD_INITIALIZER(head);
struct slisthead *headp;		/* Tête de liste liaison simple. */
struct entry {
	...
	SLIST_ENTRY(entry) entries;	/* Liaison simple. */
	...
} *n1, *n2, *n3, *np;

SLIST_INIT(&head);			/* Initialiser la liste. */

n1 = malloc(sizeof(struct entry));	/* Insérer en tête. */
SLIST_INSERT_HEAD(&head, n1, entries);

n2 = malloc(sizeof(struct entry));	/* Insérer après. */
SLIST_INSERT_AFTER(n1, n2, entries);

SLIST_REMOVE(&head, n2, entry, entries);/* Suppression. */
free(n2);

n3 = SLIST_FIRST(&head);
SLIST_REMOVE_HEAD(&head, entries);	/* Suppression de la tête. */
free(n3);
					/* Parcours en avant. */
SLIST_FOREACH(np, &head, entries)
	np-> ...
					/* Parcours en avant sécurisé. */
SLIST_FOREACH_SAFE(np, &head, entries, np_temp) {
	np->do_stuff();
	...
	SLIST_REMOVE(&head, np, entry, entries);
	free(np);
}

while (!SLIST_EMPTY(&head)) {		/* Suppression de la liste. */
	n1 = SLIST_FIRST(&head);
	SLIST_REMOVE_HEAD(&head, entries);
	free(n1);
}

FILES D'ATTENTE À EXTRACTION PAR LA TÊTE LIAISON SIMPLE

Une file d'attente à extraction par la tête liaison simple est gérée par une structure définie à l'aide de la macro STAILQ_HEAD. Cette structure contient une paire de pointeurs, l'un vers le premier élément de la file d'attente et l'autre vers le dernier élément. Les éléments sont liés de manière simple pour minimiser la surcharge d'espace et la manipulation des pointeurs, mais avec un coût de O(n) pour supprimer des éléments arbitraires. De nouveaux éléments peuvent être ajoutés à la file d'attente après un élément existant, en tête de la file d'attente ou à la fin de la file d'attente. Une structure STAILQ_HEAD est déclarée comme suit :

STAILQ_HEAD(HEADNAME, TYPE) head;

où HEADNAME est le nom de la structure à définir et TYPE est le type des éléments liés dans la file d'attente. Une adresse de pointeur vers la tête de la file d'attente peut être déclarée ultérieurement comme suit :

struct HEADNAME *headp;

(Les noms head et headp sont sélectionnables par l'utilisateur.)

La macro STAILQ_HEAD_INITIALIZER évalue à un initialiseur pour la file d'attente head.

La macro STAILQ_CONCAT concaténera la file d'attente gérée par head2 à la fin de la file d'attente gérée par head1, vidant tous les éléments de la première file d'attente.

La macro STAILQ_EMPTY évalue à vrai s'il n'y a pas d'éléments dans la file d'attente.

La macro STAILQ_ENTRY déclare une structure qui relie les éléments de la file d'attente.

La macro STAILQ_FIRST renvoie le premier élément de la file d'attente ou NULL si la file d'attente est vide.

La macro STAILQ_FOREACH parcourt la file d'attente référencée par head dans le sens avant, affectant chaque élément à var.

La macro STAILQ_FOREACH_FROM se comporte de manière identique à STAILQ_FOREACH lorsque var est NULL, sinon elle traite var comme un élément précédemment trouvé dans la file d'attente et commence la boucle à partir de var au lieu du premier élément de la file d'attente référencée par head.

La macro STAILQ_FOREACH_SAFE parcourt la file d'attente référencée par head dans le sens avant, affectant chaque élément à var. Cependant, contrairement à STAILQ_FOREACH(), il est permis de supprimer var et de le libérer dans la boucle de manière sûre sans interférer avec la traversée.

La macro STAILQ_FOREACH_FROM_SAFE se comporte de manière identique à STAILQ_FOREACH_SAFE lorsque var est NULL, sinon elle traite var comme un élément précédemment trouvé dans la file d'attente et commence la boucle à partir de var au lieu du premier élément de la file d'attente référencée par head.

La macro STAILQ_INIT initialise la file d'attente référencée par head.

La macro STAILQ_INSERT_HEAD insère le nouvel élément elm en tête de la file d'attente.

La macro STAILQ_INSERT_TAIL insère le nouvel élément elm à la fin de la file d'attente.

La macro STAILQ_INSERT_AFTER insère le nouvel élément elm après l'élément listelm.

La macro STAILQ_LAST renvoie le dernier élément de la file d'attente. Si la file d'attente est vide, la valeur renvoyée est NULL.

La macro STAILQ_NEXT renvoie le prochain élément de la file d'attente, ou NULL s'il s'agit du dernier.

La macro STAILQ_REMOVE_AFTER supprime l'élément suivant elm de la file d'attente. Contrairement à STAILQ_REMOVE, cette macro ne parcourt pas toute la file d'attente.

La macro STAILQ_REMOVE_HEAD supprime l'élément en tête de la file d'attente. Pour optimiser l'efficacité, les éléments à supprimer de la tête de la file d'attente doivent explicitement utiliser cette macro au lieu de la macro générique STAILQ_REMOVE.

La macro STAILQ_REMOVE supprime l'élément elm de la file d'attente. Son utilisation doit être évitée car elle parcourt toute la liste. Une file d'attente doublement chaînée doit être utilisée si cette macro est nécessaire dans des chemins de code fréquemment utilisés ou pour opérer sur de longues files d'attente.

La macro STAILQ_SWAP échange le contenu de head1 et head2.

EXEMPLE DE FILE D'ATTENTE À EXTRACTION PAR LA TÊTE LIAISON SIMPLE

STAILQ_HEAD(stailhead, entry) head =
    STAILQ_HEAD_INITIALIZER(head);
struct stailhead *headp;		/* Tête de file d'attente à extraction par la tête liaison simple. */
struct entry {
	...
	STAILQ_ENTRY(entry) entries;	/* File d'attente à extraction par la tête liaison simple. */
	...
} *n1, *n2, *n3, *np;

STAILQ_INIT(&head);			/* Initialiser la file d'attente. */

n1 = malloc(sizeof(struct entry));	/* Insérer en tête. */
STAILQ_INSERT_HEAD(&head, n1, entries);

n1 = malloc(sizeof(struct entry));	/* Insérer à la fin. */
STAILQ_INSERT_TAIL(&head, n1, entries);

n2 = malloc(sizeof(struct entry));	/* Insérer après. */
STAILQ_INSERT_AFTER(&head, n1, n2, entries);
					/* Suppression. */
STAILQ_REMOVE(&head, n2, entry, entries);
free(n2);
					/* Suppression de la tête. */
n3 = STAILQ_FIRST(&head);
STAILQ_REMOVE_HEAD(&head, entries);
free(n3);
					/* Parcours en avant. */
STAILQ_FOREACH(np, &head, entries)
	np-> ...
					/* Parcours en avant sécurisé. */
STAILQ_FOREACH_SAFE(np, &head, entries, np_temp) {
	np->do_stuff();
	...
	STAILQ_REMOVE(&head, np, entry, entries);
	free(np);
}
					/* Suppression de la file d'attente. */
while (!STAILQ_EMPTY(&head)) {
	n1 = STAILQ_FIRST(&head);
	STAILQ_REMOVE_HEAD(&head, entries);
	free(n1);
}
					/* Suppression plus rapide de la file d'attente. */
n1 = STAILQ_FIRST(&head);
while (n1 != NULL) {
	n2 = STAILQ_NEXT(n1, entries);
	free(n1);
	n1 = n2;
}
STAILQ_INIT(&head);

LISTES

Une liste est gérée par une structure définie à l'aide de la macro LIST_HEAD. Cette structure contient un seul pointeur vers le premier élément de la liste. Les éléments sont doublement chaînés, ce qui permet de supprimer n'importe quel élément sans parcourir toute la liste. De nouveaux éléments peuvent être ajoutés à la liste après un élément existant, avant un élément existant, ou en tête de la liste. Une structure LIST_HEAD est déclarée comme suit :

LIST_HEAD(HEADNAME, TYPE) head;

où HEADNAME est le nom de la structure à définir et TYPE est le type des éléments liés dans la liste. Une adresse de pointeur vers la tête de la liste peut être déclarée ultérieurement comme suit :

struct HEADNAME *headp;

(Les noms head et headp sont sélectionnables par l'utilisateur.)

La macro LIST_HEAD_INITIALIZER évalue à un initialiseur pour la liste head.

La macro LIST_CONCAT concaténera la liste gérée par head2 à la fin de la liste gérée par head1, vidant tous les éléments de la première liste. Son utilisation doit être évitée car elle parcourt toute la liste head1. Une file d'attente à extraction par la tête doit être utilisée si cette macro est nécessaire dans des chemins de code fréquemment utilisés ou pour opérer sur de longues listes.

La macro LIST_EMPTY évalue à vrai s'il n'y a pas d'éléments dans la liste.

La macro LIST_ENTRY déclare une structure qui relie les éléments de la liste.

La macro LIST_FIRST renvoie le premier élément de la liste ou NULL si la liste est vide.

La macro LIST_FOREACH parcourt la liste référencée par head dans le sens avant, affectant chaque élément à var.

La macro LIST_FOREACH_FROM se comporte de manière identique à LIST_FOREACH lorsque var est NULL, sinon elle traite var comme un élément précédemment trouvé dans la liste et commence la boucle à partir de var au lieu du premier élément de la liste référencée par head.

La macro LIST_FOREACH_SAFE parcourt la liste référencée par head dans le sens avant, affectant chaque élément à var. Cependant, contrairement à LIST_FOREACH(), il est permis de supprimer var et de le libérer dans la boucle de manière sûre sans interférer avec la traversée.

La macro LIST_FOREACH_FROM_SAFE se comporte de manière identique à LIST_FOREACH_SAFE lorsque var est NULL, sinon elle traite var comme un élément précédemment trouvé dans la liste et commence la boucle à partir de var au lieu du premier élément de la liste référencée par head.

LISTS

Una lista enlazada simple está definida por la macro LIST_HEAD. Esta estructura contiene un puntero al primer elemento de la lista. Los elementos se enlazan en una sola dirección, lo que significa que cada elemento es consciente de su siguiente elemento, pero no de su elemento anterior. Los elementos nuevos se pueden insertar al principio de la lista o después de un elemento existente. Una estructura LIST_HEAD se declara como:

LIST_HEAD(HEADNAME, TYPE) head;

donde HEADNAME es el nombre de la estructura a definir y TYPE es el tipo de los elementos vinculados en la lista. Un puntero a la cabeza de la lista puede ser declarado más tarde como:

struct HEADNAME *headp;

(Los nombres head y headp son seleccionables del usuario.)

El macro LIST_HEAD_INITIALIZER se evalúa como un inicializador para la cabeza de lista head.

El macro LIST_EMPTY se evalúa como TRUE si la lista está vacía.

El macro LIST_ENTRY declara una estructura que enlaza los elementos de la lista.

El macro LIST_FIRST devuelve el primer elemento de la lista o NULL si la lista está vacía.

El macro LIST_FOREACH recorre la lista referida a head en la dirección forward, asignando cada elemento en su orden a var.

El macro LIST_FOREACH_FROM se comporta de forma idéntica al macro LIST_FOREACH cuando var es NULL, sino que trata var como un elemento previamente encontrado en la lista referida a head y comienza el bucle desde var en lugar del primer elemento de la lista referida a head.

El macro LIST_FOREACH_SAFE recorre la lista referida a head en la dirección forward, asignando cada elemento en su orden a var. Sin embargo, a diferencia de LIST_FOREACH() aquí está permitido tanto remover var como liberar de forma segura var dentro del bucle sin interferir con la travesía.

El macro LIST_FOREACH_FROM_SAFE se comporta de forma idéntica al macro LIST_FOREACH_SAFE cuando var es NULL, sino que trata var como un elemento previamente encontrado en la lista referida a head y comienza el bucle desde var en lugar del primer elemento de la lista referida a head.

El macro LIST_INIT inicializa la lista referida a head.

El macro LIST_INSERT_HEAD inserta el nuevo elemento elm al frente de la lista.

El macro LIST_INSERT_AFTER inserta el nuevo elemento elm después del elemento listelm.

El macro LIST_INSERT_BEFORE inserta el nuevo elemento elm antes del elemento listelm.

El macro LIST_NEXT devuelve el siguiente elemento en la lista, o NULL si este es el último.

El macro LIST_PREV devuelve el elemento anterior en la lista, o NULL si este es el primero. La lista head debe contener el elemento elm.

El macro LIST_REMOVE elimina el elemento elm de la lista.

El macro LIST_SWAP intercambia los contenidos de head1 y head2.

LIST EXAMPLE

LIST_HEAD(listhead, entry) head =
    LIST_HEAD_INITIALIZER(head);
struct listhead *headp;			/* List head. */
struct entry {
	...
	LIST_ENTRY(entry) entries;	/* List. */
	...
} *n1, *n2, *n3, *np, *np_temp;

LIST_INIT(&head);			/* Initialize the list. */

n1 = malloc(sizeof(struct entry));	/* Insert at the head. */
LIST_INSERT_HEAD(&head, n1, entries);

n2 = malloc(sizeof(struct entry));	/* Insert after. */
LIST_INSERT_AFTER(n1, n2, entries);

n3 = malloc(sizeof(struct entry));	/* Insert before. */
LIST_INSERT_BEFORE(n2, n3, entries);

LIST_REMOVE(n2, entries);		/* Deletion. */
free(n2);
					/* Forward traversal. */
LIST_FOREACH(np, &head, entries)
	np-> ...

					/* Safe forward traversal. */
LIST_FOREACH_SAFE(np, &head, entries, np_temp) {
	np->do_stuff();
	...
	LIST_REMOVE(np, entries);
	free(np);
}

while (!LIST_EMPTY(&head)) {		/* List Deletion. */
	n1 = LIST_FIRST(&head);
	LIST_REMOVE(n1, entries);
	free(n1);
}

n1 = LIST_FIRST(&head);			/* Faster List Deletion. */
while (n1 != NULL) {
	n2 = LIST_NEXT(n1, entries);
	free(n1);
	n1 = n2;
}
LIST_INIT(&head);

TAIL QUEUES

Una cola con cola final (tail queue) está definida por la macro TAILQ_HEAD. Esta estructura contiene un par de punteros, uno al primer elemento de la cola con cola final y el otro al último elemento de la cola con cola final. Los elementos están enlazados doblemente, lo que permite la eliminación de cualquier elemento sin tener que recorrer toda la cola con cola final. Los nuevos elementos pueden agregarse a la cola con cola final después de un elemento existente, antes de un elemento existente, al frente de la cola con cola final, o al final de la cola con cola final. Una estructura TAILQ_HEAD se declara como:

TAILQ_HEAD(HEADNAME, TYPE) head;

donde HEADNAME es el nombre de la estructura a definir y TYPE es el tipo de los elementos enlazados en la cola con cola final. Un puntero a la cabeza de la cola con cola final puede ser declarado más tarde como:

struct HEADNAME *headp;

(Los nombres head y headp son seleccionables por el usuario.)

El macro TAILQ_HEAD_INITIALIZER se evalúa como un inicializador para la cola con cola final head.

El macro TAILQ_CONCAT concatenará la cola con cola final referenciada por head2 al final de la cola con cola final referenciada por head1, eliminando todas las entradas de la primera.

El macro TAILQ_EMPTY se evalúa como TRUE si no hay elementos en la cola con cola final.

El macro TAILQ_ENTRY declara una estructura que conecta los elementos de la cola con cola final.

El macro TAILQ_FIRST devuelve el primer elemento de la cola con cola final o NULL si la cola con cola final está vacía.

El macro TAILQ_FOREACH recorre la cola con cola final referenciada por head en la dirección forward, asignando cada elemento en su orden a var. var se establece a NULL si el bucle termina normalmente, o si no hay elementos.

El macro TAILQ_FOREACH_FROM se comporta de forma idéntica al macro TAILQ_FOREACH cuando var es NULL, sino que trata var como un elemento previamente encontrado en la cola con cola final y comienza el bucle desde var en lugar del primer elemento de la cola con cola final referenciada por head.

El macro TAILQ_FOREACH_REVERSE recorre la cola con cola final referenciada por head en la dirección reverse, asignando cada elemento en su orden a var.

El macro TAILQ_FOREACH_REVERSE_FROM se comporta de forma idéntica al macro TAILQ_FOREACH_REVERSE cuando var es NULL, sino que trata var como un elemento previamente encontrado en la cola con cola final y comienza el bucle en reversa desde var en lugar del último elemento de la cola con cola final referenciada por head.

Los macros TAILQ_FOREACH_SAFE y TAILQ_FOREACH_REVERSE_SAFE recorren la lista referenciada por head en la dirección forward o reverse respectivamente, asignando cada elemento en su orden a var. Sin embargo, a diferencia de sus contrapartes no seguras, TAILQ_FOREACH y TAILQ_FOREACH_REVERSE permiten tanto remover var como liberar de forma segura var dentro del bucle sin interferir con la travesía.

El macro TAILQ_FOREACH_FROM_SAFE se comporta de forma idéntica al macro TAILQ_FOREACH_SAFE cuando var es NULL, sino que trata var como un elemento previamente encontrado en la cola con cola final y comienza el bucle desde var en lugar del primer elemento de la cola con cola final referenciada por head.

El macro TAILQ_FOREACH_REVERSE_FROM_SAFE se comporta de forma idéntica al macro TAILQ_FOREACH_REVERSE_SAFE cuando var es NULL, sino que trata var como un elemento previamente encontrado en la cola con cola final y comienza el bucle en reversa desde var en lugar del último elemento de la cola con cola final referenciada por head.

El macro TAILQ_INIT inicializa la cola con cola final referenciada por head.

El macro TAILQ_INSERT_HEAD inserta el nuevo elemento elm al frente de la cola con cola final.

El macro TAILQ_INSERT_TAIL inserta el nuevo elemento elm al final de la cola con cola final.

El macro TAILQ_INSERT_AFTER inserta el nuevo elemento elm después del elemento listelm.

El macro TAILQ_INSERT_BEFORE inserta el nuevo elemento elm antes del elemento listelm.

El macro TAILQ_LAST devuelve el último elemento de la cola con cola final. Si la cola con cola final está vacía, el valor devuelto es NULL.

El macro TAILQ_NEXT devuelve el siguiente elemento de la cola con cola final, o NULL si este es el último.

El macro TAILQ_PREV devuelve el elemento anterior de la cola con cola final, o NULL si este es el primero.

El macro TAILQ_REMOVE elimina el elemento elm de la cola con cola final.

El macro TAILQ_SWAP intercambia los contenidos de head1 y head2.

DIAGNOSTICS

Lors du débogage de queue(3), il peut être utile de tracer les changements de file d'attente. Pour activer le traçage, définissez la macro QUEUE_MACRO_DEBUG_TRACE au moment de la compilation.

Il peut également être utile de corrompre les pointeurs qui ont été retirés d'une file d'attente, afin de détecter une utilisation après suppression. Pour activer la corruption des pointeurs, définissez la macro QUEUE_MACRO_DEBUG_TRASH au moment de la compilation. La macro QMD_IS_TRASHED(void *ptr) renvoie vrai si ptr a été corrompu par l'option QUEUE_MACRO_DEBUG_TRASH.
