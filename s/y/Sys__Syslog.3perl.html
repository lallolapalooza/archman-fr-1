Sys::Syslog(3perl) Perl Programmers Reference Guide Sys::Syslog(3perl)

NAME

Sys::Syslog - Perl interface to the UNIX syslog(3) calls

VERSION

This is the documentation of version 0.36

SYNOPSIS

use Sys::Syslog;                        # all except setlogsock()
use Sys::Syslog qw(:standard :macros);  # standard functions & macros
openlog($ident, $logopt, $facility);    # don't forget this
syslog($priority, $format, @args);
$oldmask = setlogmask($mask_priority);
closelog();

DESCRIPTION

"Sys::Syslog" is an interface to the UNIX syslog(3) program. Call syslog() with a string priority and a list of printf() args just like syslog(3).

EXPORTS

"Sys::Syslog" exports the following "Exporter" tags:

  • ":standard" exports the standard syslog(3) functions: 
    openlog closelog setlogmask syslog
  • ":extended" exports the Perl specific functions for syslog(3): 
    setlogsock
  • ":macros" exports the symbols corresponding to most of your syslog(3) macros and the LOG_UPTO() and LOG_MASK() functions. See "CONSTANTS" for the supported constants and their meaning.

By default, "Sys::Syslog" exports the symbols from the ":standard" tag.

FUNCTIONS

openlog($ident, $logopt, $facility)
Opens the syslog. $ident is prepended to every message. $logopt contains zero or more of the options detailed below. $facility specifies the part of the system to report about, for example "LOG_USER" or "LOG_LOCAL0": see "Facilities" for a list of well-known facilities, and your syslog(3) documentation for the facilities available in your system. Check "SEE ALSO" for useful links. Facility can be given as a string or a numeric macro.

This function will croak if it can't connect to the syslog daemon.

Note that openlog() now takes three arguments, just like openlog(3).

You should use openlog() before calling syslog().

Options

  • "cons" - This option is ignored, since the failover mechanism will drop down to the console automatically if all other media fail.
  • "ndelay" - Open the connection immediately (normally, the connection is opened when the first message is logged).
  • "noeol" - When set to true, no end of line character ("\n") will be appended to the message. This can be useful for some syslog daemons. Added in "Sys::Syslog" 0.29.
  • "nofatal" - When set to true, openlog() and syslog() will only emit warnings instead of dying if the connection to the syslog can't be established. Added in "Sys::Syslog" 0.15.
  • "nonul" - When set to true, no "NUL" character ("\0") will be appended to the message. This can be useful for some syslog daemons. Added in "Sys::Syslog" 0.29.
  • "nowait" - Don't wait for child processes that may have been created while logging the message. (The GNU C library does not create a child process, so this option has no effect on Linux.)
  • "perror" - Write the message to standard error output as well to the system log. Added in "Sys::Syslog" 0.22.
  • "pid" - Include PID with each message.

Examples

Open the syslog with options "ndelay" and "pid", and with facility "LOCAL0":

openlog($name, "ndelay,pid", "local0");

Same thing, but this time using the macro corresponding to "LOCAL0":

openlog($name, "ndelay,pid", LOG_LOCAL0);
syslog($priority, $message)
syslog($priority, $format, @args)
If $priority permits, logs $message or "sprintf($format, @args)" with the addition that %m in $message or $format is replaced with "$!" (the latest error message).

$priority can specify a level, or a level and a facility. Levels and facilities can be given as strings or as macros. When using the "eventlog" mechanism, priorities "DEBUG" and "INFO" are mapped to event type "informational", "NOTICE" and "WARNING" to "warning" and "ERR" to "EMERG" to "error".

If you didn't use openlog() before using syslog(), syslog() will try to guess the $ident by extracting the shortest prefix of $format that ends in a ":".

Examples

# informational level
syslog("info", $message);
syslog(LOG_INFO, $message);
# information level, Local0 facility
syslog("info|local0", $message);
syslog(LOG_INFO|LOG_LOCAL0, $message);
Note
"Sys::Syslog" version v0.07 and older passed the $message as the formatting string to sprintf() even when no formatting arguments were provided. If the code calling syslog() might execute with older versions of this module, make sure to call the function as "syslog($priority, "%s", $message)" instead of "syslog($priority, $message)". This protects against hostile formatting sequences that might show up if $message contains tainted data.
setlogmask($mask_priority)
Sets the log mask for the current process to $mask_priority and returns the old mask. If the mask argument is 0, the current log mask is not modified. See "Levels" for the list of available levels. You can use the LOG_UPTO() function to allow all levels up to a given priority (but it only accept the numeric macros as arguments).

Exa

EXAMPLES

This module is meant to be a drop-in replacement for the C functionality, so if you have seen code like this:

    #include <syslog.h>
    ...
    openlog(argv[0], LOG_PID|LOG_CONS, LOG_USER);
    syslog(LOG_INFO, "I am starting up, pid=%d", getpid());
    ...
    syslog(LOG_ERR, "I've encountered a fatal error");
    closelog();

Then you can write the equivalent Perl code:

    use Sys::Syslog qw(:standard :macros);
    ...
    openlog($program_name, "pid,cons", LOG_USER);
    syslog(LOG_INFO, "I am starting up, pid=%d", $pid);
    ...
    syslog(LOG_ERR, "I've encountered a fatal error");
    closelog();

Or, if you prefer string constants:

    use Sys::Syslog qw(:standard);
    ...
    openlog($program_name, "pid,cons", "user");
    syslog("info", "I am starting up, pid=%d", $pid);
    ...
    syslog("err", "I've encountered a fatal error");
    closelog();

Note that "pid,cons" is automatically mapped to the numeric options LOG_PID|LOG_CONS.

BUGS

When using the "eventlog" mechanism under Windows, priorities "DEBUG" and "INFO" are mapped to event type "informational", priorities "NOTICE" and "WARNING" to "warning", and priorities "ERR" to "EMERG" to "error". This is not a bug, but a feature to ensure that the messages are displayed correctly in the event viewer.

Please report bugs to syslog-bugs@franke.de.

The module does not handle the SYSLOG_CLOCK_ROTATE mechanism. However, this mechanism is deprecated and should not be used.

The module does not provide access to the SYSLOG_OPEN and SYSLOG_CLOSE mechanism. As noted in the description of openlog(), the Perl module automatically opens the connection to the syslog daemon, and it will close the connection when the program terminates.

The module does not allow to specify the socket used by the syslog daemon. That is, it uses the default socket, which is usually /dev/log on UNIX and the event log on Windows.

The module does not support the setlogsock() function under Windows. There is no equivalent functionality in Windows.

NOM

Sys::Syslog - Interface Perl pour les appels syslog(3) UNIX

VERSION

Ceci est la documentation de la version 0.36

SYNTAXE

use Sys::Syslog;                        # tout sauf setlogsock()
use Sys::Syslog qw(:standard :macros);  # fonctions standard & macros
openlog($ident, $logopt, $facility);    # n'oubliez pas ceci
syslog($priority, $format, @args);

DESCRIPTION

"Sys::Syslog" est une interface pour le programme syslog(3) d'UNIX. Appelez syslog() avec une priorité sous forme de chaîne et une liste d'arguments printf(), tout comme syslog(3).

EXPORTATIONS

"Sys::Syslog" exporte les étiquettes "Exporter" suivantes :

  • ":standard" exporte les fonctions standard de syslog(3) : 
    openlog closelog setlogmask syslog
  • ":extended" exporte les fonctions spécifiques à Perl pour syslog(3) : 
    setlogsock
  • ":macros" exporte les symboles correspondant à la plupart de vos macros syslog(3) ainsi que les fonctions LOG_UPTO() et LOG_MASK(). Voir "CONSTANTES" pour les constantes prises en charge et leur signification.

Par défaut, "Sys::Syslog" exporte les symboles de l'étiquette ":standard".

FONCTIONS

openlog($ident, $logopt, $facility)
Ouvre le syslog. $ident est ajouté au début de chaque message. $logopt contient zéro ou plusieurs des options détaillées ci-dessous. $facility spécifie la partie du système sur laquelle porte le rapport, par exemple "LOG_USER" ou "LOG_LOCAL0" : voir "Services" pour une liste des services bien connus, et votre documentation syslog(3) pour les services disponibles sur votre système. Consultez "VOIR AUSSI" pour des liens utiles. Le service peut être donné sous forme de chaîne ou de macro numérique.

Cette fonction provoquera une erreur si elle ne parvient pas à se connecter au démon syslog.

Notez que openlog() prend maintenant trois arguments, tout comme openlog(3).

Vous devez utiliser openlog() avant d'appeler syslog().

Options

  • "cons" - Cette option est ignorée, car le mécanisme de basculement descendra automatiquement vers la console si tous les autres médias échouent.
  • "ndelay" - Ouvre la connexion immédiatement (normalement, la connexion est ouverte lors de la journalisation du premier message).
  • "noeol" - Lorsqu'elle est définie à vrai, aucun caractère de fin de ligne ("\n") ne sera ajouté au message. Cela peut être utile pour certains démons syslog. Ajouté dans "Sys::Syslog" 0.29.
  • "nofatal" - Lorsqu'elle est définie à vrai, openlog() et syslog() n'émettront que des avertissements au lieu de mourir si la connexion au syslog ne peut être établie. Ajouté dans "Sys::Syslog" 0.15.
  • "nonul" - Lorsqu'elle est définie à vrai, aucun caractère "NUL" ("\0") ne sera ajouté au message. Cela peut être utile pour certains démons syslog. Ajouté dans "Sys::Syslog" 0.29.
  • "nowait" - N'attend pas les processus enfants qui peuvent avoir été créés lors de la journalisation du message. (La bibliothèque C GNU ne crée pas de processus enfant, donc cette option n'a aucun effet sous Linux.)
  • "perror" - Écrit également le message dans la sortie d'erreur standard en plus du journal système. Ajouté dans "Sys::Syslog" 0.22.
  • "pid" - Inclut le PID avec chaque message.

Exemples

Ouvre le syslog avec les options "ndelay" et "pid", et avec le service "LOCAL0" :

openlog($name, "ndelay,pid", "local0");

Même chose, mais cette fois en utilisant la macro correspondant à "LOCAL0" :

openlog($name, "ndelay,pid", LOG_LOCAL0);
syslog($priority, $message)
syslog($priority, $format, @args)
Si $priority le permet, enregistre $message ou "sprintf($format, @args)" avec la particularité que %m dans $message ou $format est remplacé par "$!" (le dernier message d'erreur).

$priority peut spécifier un niveau, ou un niveau et un service. Les niveaux et services peuvent être donnés sous forme de chaînes ou de macros. Lors de l'utilisation du mécanisme "eventlog", les priorités "DEBUG" et "INFO" sont mappées au type d'événement "informational", "NOTICE" et "WARNING" à "warning", et "ERR" à "EMERG" à "error".

Si vous n'avez pas utilisé openlog() avant d'utiliser syslog(), syslog() essaiera de deviner l'$ident en extrayant le plus court préfixe de $format qui se termine par un ":".

Exemples

# niveau informationnel
syslog("info", $message);
syslog(LOG_INFO, $message);
# niveau informationnel, service Local0
syslog("info|local0", $message);
syslog(LOG_INFO|LOG_LOCAL0, $message);
Note
La version v0.07 et antérieures de "Sys::Syslog" passaient le $message comme chaîne de formatage à sprintf() même lorsque aucun argument de formatage n'était fourni. Si le code appelant syslog() peut s'exécuter avec d'anciennes versions de ce module, assurez-vous d'appeler la fonction comme "syslog($priority, "%s", $message)" au lieu de "syslog($priority, $message)". Ceci protège contre les séquences de formatage hostiles qui pourraient apparaître si $message contient des données contaminées.
setlogmask($mask_priority)
Définit le masque de journalisation pour le processus courant à $mask_priority et retourne l'ancien masque. Si l'argument masque est 0, le masque de journalisation actuel n'est pas modifié. Voir "Niveaux" pour la liste des niveaux disponibles. Vous pouvez utiliser la fonction LOG_UPTO() pour autoriser tous les niveaux jusqu'à une priorité donnée (mais elle n'accepte que les macros numériques comme arguments).

BOGUES

Lors de l'utilisation du mécanisme "eventlog" sous Windows, les priorités "DEBUG" et "INFO" sont mappées au type d'événement "informational", les priorités "NOTICE" et "WARNING" à "warning", et les priorités "ERR" à "EMERG" à "error". Ce n'est pas un bogue, mais une fonctionnalité pour garantir que les messages s'affichent correctement dans le visualiseur d'événements.

Veuillez signaler les bogues à syslog-bugs@franke.de.

Le module ne gère pas le mécanisme SYSLOG_CLOCK_ROTATE. Cependant, ce mécanisme est obsolète et ne devrait pas être utilisé.

Le module ne fournit pas d'accès aux mécanismes SYSLOG_OPEN et SYSLOG_CLOSE. Comme noté dans la description de openlog(), le module Perl ouvre automatiquement la connexion au démon syslog, et il fermera la connexion lorsque le programme se terminera.

Le module ne permet pas de spécifier le socket utilisé par le démon syslog. Autrement dit, il utilise le socket par défaut, qui est généralement /dev/log sous UNIX et le journal des événements sous Windows.

Le module ne prend pas en charge la fonction setlogsock() sous Windows. Il n'y a pas de fonctionnalité équivalente sous Windows.

DIAGNOSTICS

"Invalid argument passed to setlogsock"
(F) Vous avez passé une valeur invalide à setlogsock() pour $sock_type.
"eventlog passed to setlogsock, but no Win32 API available"
(W) Vous avez indiqué que setlogsock() utiliserait le journal des événements Win32, mais le système exécutant le programme n'est pas Win32 ou ne fournit pas les capacités compatibles.
"no connection to syslog available"
(F) syslog() n'a pas pu se connecter à la socket spécifiée.
"stream passed to setlogsock, but %s is not writable"
(W) Vous avez indiqué que setlogsock() utiliserait une socket de flux, mais le chemin fourni n'est pas accessible en écriture.
"stream passed to setlogsock, but could not find any device"
(W) Vous avez indiqué que setlogsock() utiliserait une socket de flux, mais vous n'avez pas fourni de chemin et "Sys::Syslog" n'a trouvé aucun périphérique approprié.
"tcp passed to setlogsock, but tcp service unavailable"
(W) Vous avez indiqué que setlogsock() utiliserait une socket TCP, mais le service n'est pas disponible sur le système.
"syslog: expecting argument %s"
(F) Vous avez oublié de passer l'argument indiqué à syslog().
"syslog: invalid level/facility: %s"
(F) Vous avez spécifié un niveau ou une catégorie invalide.
"syslog: too many levels given: %s"
(F) Vous avez spécifié trop de niveaux.
"syslog: too many facilities given: %s"
(F) Vous avez spécifié trop de catégories.
"syslog: level must be given"
(F) Vous avez oublié de spécifier un niveau.
"udp passed to setlogsock, but udp service unavailable"
(W) Vous avez indiqué que setlogsock() utiliserait une socket UDP, mais le service n'est pas disponible sur le système.
"unix passed to setlogsock, but path not available"
(W) Vous avez indiqué que setlogsock() utiliserait une socket UNIX, mais "Sys::Syslog" n'a pas pu trouver de périphérique approprié.

HISTORIQUE

"Sys::Syslog" est un module de base, faisant partie de la distribution standard de Perl depuis 1990. À cette époque, les modules tels que nous les connaissons n'existaient pas, la bibliothèque Perl était une collection de fichiers .pl et le module pour envoyer des messages syslog était simplement lib/syslog.pl, inclus avec Perl 3.0. Il a été converti en module avec Perl 5.0, mais n'a eu un numéro de version qu'à partir de Perl 5.6. Voici un bref tableau avec les versions correspondantes de Perl et de "Sys::Syslog".
