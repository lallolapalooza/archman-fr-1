NOM

Symbol - manipuler les symboles Perl et leurs noms

SYNTAXE

use Symbol;
$sym = gensym;
open($sym, '<', "filename");
$_ = <$sym>;
# etc.
ungensym $sym;      # aucun effet
# remplace la poignée *FOO{IO} mais pas $FOO, %FOO, etc.
*FOO = geniosym;
print qualify("x"), "\n";              # "main::x"
print qualify("x", "FOO"), "\n";       # "FOO::x"
print qualify("BAR::x"), "\n";         # "BAR::x"
print qualify("BAR::x", "FOO"), "\n";  # "BAR::x"
print qualify("STDOUT", "FOO"), "\n";  # "main::STDOUT" (global)
print qualify(\*x), "\n";              # retourne \*x
print qualify(\*x, "FOO"), "\n";       # retourne \*x
use strict refs;
print { qualify_to_ref $fh } "foo!\n";
$ref = qualify_to_ref $name, $pkg;
use Symbol qw(delete_package);
delete_package('Foo::Bar');
print "deleted\n" unless exists $Foo::{'Bar::'};

DESCRIPTION

"Symbol::gensym" crée un glob anonyme et retourne une référence vers celui-ci. Une telle référence de glob peut être utilisée comme un descripteur de fichier ou de répertoire.

Pour la compatibilité descendante avec les anciennes implémentations qui ne supportaient pas les globs anonymes, "Symbol::ungensym" est également fournie. Mais elle ne fait rien.

"Symbol::geniosym" crée un descripteur d'IO anonyme. Il peut être assigné dans un glob existant sans affecter les parties non-IO du glob.

"Symbol::qualify" transforme les noms de symboles non qualifiés en noms de variables qualifiés (par exemple, "ma_variable" -> "MonPackage::ma_variable"). Si un deuxième paramètre est fourni, "qualify" l'utilise comme paquet par défaut ; sinon, il utilise le paquet de l'appelant. Quoi qu'il en soit, les noms de variables globales (par exemple, "STDOUT", "ENV", "SIG") sont toujours qualifiés avec "main::".

La qualification s'applique uniquement aux noms de symboles (chaînes de caractères). Les références sont laissées inchangées en supposant qu'il s'agit de références de glob, qui sont qualifiées par leur nature.

"Symbol::qualify_to_ref" est comme "Symbol::qualify" sauf qu'elle retourne une référence de glob plutôt qu'un nom de symbole, vous pouvez donc utiliser le résultat même si "use strict 'refs'" est activé.

"Symbol::delete_package" efface tout un espace de noms de paquet. Notez que cette routine n'est pas exportée par défaut - vous pourriez vouloir l'importer explicitement.

BOGUES

"Symbol::delete_package" est un peu trop puissant. Il annule la définition de chaque symbole qui vit dans le paquet spécifié. Comme Perl, pour des raisons de performance, n'effectue pas de recherche dans la table des symboles à chaque fois qu'une fonction est appelée ou qu'une variable globale est accédée, certains codes qui ont déjà été chargés et qui utilisent des symboles du paquet "Foo" peuvent cesser de fonctionner après que vous ayez supprimé "Foo", même si vous rechargez le module "Foo" par la suite.
