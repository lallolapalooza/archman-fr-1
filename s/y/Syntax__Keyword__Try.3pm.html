NOM

"Syntax::Keyword::Try" - une syntaxe "try/catch/finally" pour perl

SYNOPSIS

use Syntax::Keyword::Try;
sub foo {
   try {
      attempt_a_thing();
      return "succès";
   }
   catch ($e) {
      warn "Ça a échoué - $e";
      return "échec";
   }
}

DESCRIPTION

Ce module fournit un plugin de syntaxe qui implémente des sémantiques de gestion d'exceptions sous une forme familière aux utilisateurs d'autres langages, basé sur un bloc étiqueté avec le mot-clé "try", suivi d'au moins un bloc "catch" ou "finally".

En plus de fournir une syntaxe pratique pour ce comportement utile, ce module contient également un certain nombre d'exemples de code sur la façon d'implémenter des plugins de parseur et de manipuler des arbres d'options pour fournir de nouvelles syntaxes et de nouveaux comportements pour le code perl.

Une syntaxe similaire à celle de ce module a maintenant été ajoutée au cœur de perl, à partir de la version 5.34.0. Si vous écrivez du nouveau code, il est suggéré d'utiliser plutôt le module Feature::Compat::Try, car il activera la fonctionnalité principale sur les versions de perl prises en charge, en se rabattant sur "Syntax::Keyword::Try" sur les versions plus anciennes de perl.

FONCTIONNALITÉS EXPÉRIMENTALES

Certaines fonctionnalités de ce module sont actuellement marquées comme expérimentales. Elles provoqueront des avertissements dans la catégorie "experimental", sauf si elles sont supprimées.

Vous pouvez le faire taire avec "no warnings 'experimental'", mais cela supprimera tous les avertissements expérimentaux, ce qui pourrait en masquer involontairement d'autres. Pour une approche plus granulaire, vous pouvez utiliser la ligne d'importation de ce module pour supprimer sélectivement les avertissements de ce module :

use Syntax::Keyword::Try qw( try :experimental(typed) );
use Syntax::Keyword::Try qw( try :experimental );  # tout ce qui précède

N'oubliez pas d'importer le symbole principal "try" lui-même, pour activer la syntaxe.

MOTS-CLÉS

try

try {
   INSTRUCTIONS...
}
...

Une instruction "try" fournit le corps principal du code qui sera appelé, et doit être suivie d'une instruction "catch", d'une instruction "finally", ou des deux.

L'exécution de l'instruction "try" elle-même commence à partir du bloc donné à l'instruction et se poursuit jusqu'à ce qu'elle lance une exception, ou qu'elle se termine avec succès en atteignant la fin du bloc. Ce qui se passe ensuite dépend de la présence d'une instruction "catch" ou "finally" qui la suit immédiatement.

Le corps d'un bloc "try {}" peut contenir une expression "return". Si elle est exécutée, une telle expression provoquera le retour de la fonction entière contenant la valeur fournie. Ceci est différent d'un simple bloc "eval {}", où seule l'évaluation "eval" elle-même retournerait, pas la fonction entière.

Le corps d'un bloc "try {}" peut contenir des expressions de contrôle de boucle ( "redo", "next", "last") qui auront leur effet habituel sur les boucles dont le bloc "try {}" fait partie.

Les règles d'analyse syntaxique pour l'ensemble des instructions (le bloc "try" et ses blocs "catch" et "finally" associés) sont telles qu'elles sont analysées comme une instruction autonome. Pour cette raison, il n'est pas nécessaire de terminer par un point-virgule.

Même s'il est analysé comme une instruction et non comme une expression, un bloc "try" peut toujours renvoyer une valeur s'il apparaît comme la dernière instruction dans son bloc "sub" ou "do" contenant. Par exemple :

my $result = do {
   try { attempt_func() }
   catch ($e) { "Valeur de repli" }
};

Notez (en particulier pour les utilisateurs de Try::Tiny et similaires) que le bloc "try {}" lui-même n'empêche pas nécessairement les exceptions lancées à l'intérieur de se propager à l'extérieur. C'est la présence d'un bloc "catch {}" ultérieur qui provoque cela. Un "try" avec seulement un "finally" et sans "catch" propagera toujours les exceptions aux appelants comme d'habitude.

catch

...
catch ($var) {
   INSTRUCTIONS...
}

ou

...
catch {
   INSTRUCTIONS...
}

Une instruction "catch" fournit un bloc de code à l'instruction "try" précédente qui sera appelé dans le cas où le bloc de code principal lance une exception. Optionnellement, une nouvelle variable lexicale peut être fournie pour stocker l'exception. Si elle n'est pas fournie, le bloc "catch" peut inspecter l'exception levée en regardant dans $@ à la place.

La présence de cette instruction "catch" rend toute exception lancée par le bloc "try" précédent non fatale pour le code environnant. Si le bloc "catch" souhaite gérer certaines exceptions mais pas d'autres, il peut les relancer (ou une autre exception) en appelant "die" de la manière habituelle.

Comme pour "try", le corps d'un bloc "catch {}" peut également contenir une expression "return", qui, comme précédemment, a sa signification habituelle, provoquant le retour de la fonction entière contenant avec la valeur donnée. Le corps peut également contenir des expressions de contrôle de boucle ( "redo", "next" ou "last") qui ont également leur effet habituel.

Si une instruction "catch" n'est pas fournie, alors toute exception levée par le bloc "try" est levée vers l'appelant comme d'habitude.

catch (typé)

...
catch ($var isa Classe) { ... }
...
catch ($var =~ m/^Correspondance_Regex/) { ... }

Expérimental ; depuis la version 0.15.

Optionnellement, plusieurs instructions catch peuvent être fournies, où chaque bloc reçoit une condition de garde, pour contrôler s'il attrape ou non des valeurs d'exception particulières. L'utilisation de cette syntaxe provoquera un avertissement de catégorie "experimental" sur les versions de perl compatibles, sauf s'il est supprimé en important la balise :experimental(typed) (voir ci-dessus).

Deux types de conditions sont pris en charge :

  • catch ($var isa Classe)

    Le bloc est invoqué uniquement si l'exception attrapée est un objet béni et dérive du nom de package donné.

    À partir de la version 5.32 de Perl, ce test conditionnel est implémenté en utilisant le même type d'opération que celui fourni par la syntaxe de base "$var isa Class" et fonctionne exactement de la même manière.

    Sur les versions plus anciennes de perl, il est émulé par une fonction de compatibilité. Actuellement, cette fonction ne respecte pas une surcharge de méthode "->isa" sur l'instance d'exception. Habituellement, cela ne devrait pas poser de problème, car les types de classes d'exception fournissent rarement une telle méthode.

  • catch ($var =~ m/regex/)

    Le bloc est invoqué uniquement si l'exception attrapée est une chaîne de caractères qui correspond à la regexp donnée.

Lorsqu'une exception est attrapée, chaque condition est testée dans l'ordre où elle est écrite, jusqu'à ce qu'un cas correspondant soit trouvé.

finally

...
finally {
   STATEMENTS...
}

Un bloc "finally" fournit des instructions qui seront exécutées après que le bloc "try" ait terminé son exécution, qu'elle se soit terminée normalement, par une exception, ou par une instruction de sortie de boucle ou un retour.

Un bloc "finally" est exécuté dans les cas suivants :

  • Si le bloc "try" se termine normalement.

  • Si le bloc "try" lance une exception, et qu'il y a un bloc "catch" qui la gère.

  • Si une instruction de contrôle de boucle ( "redo", "next" ou "last") est rencontrée dans le bloc "try" ou "catch".

  • Si une instruction "return" est rencontrée dans le bloc "try" ou "catch".

Les blocs "finally" ne sont pas exécutés si le programme se termine (par exemple, en appelant "exit" ou s'il y a une erreur de segmentation).

Le corps d'un bloc "finally {}" ne peut pas contenir d'instruction "return". Tenter de le faire provoquera une erreur d'analyse.

Les blocs "finally" ne peuvent pas non plus contenir d'expressions de contrôle de boucle ( "redo", "next" ou "last").

Si un bloc "finally" lève une exception, cette exception supplante toute exception précédemment attrapée ou levée.

EXEMPLE

use Syntax::Keyword::Try;

sub process_file {
    my ($filename) = @_;
    my $handle;
    my $result;

    try {
        $handle = IO::File->new($filename, O_RDONLY)
            or die "Can't open $filename: $!";
        $result = do { local $/; $handle->read(my $buffer, -s $handle) };
    }
    catch ($e) {
        warn "Error processing $filename: $e";
        return undef; # Return undef on error
    }
    finally {
        $handle->close; # Ensure file is closed
    }

    return $result; # Return content on success
}

# Example usage:
my $content = process_file("my_data.txt");

if (defined $content) {
    print "File content:\n$content\n";
} else {
    print "Failed to process file.\n";
}

finally

...
finally {
   STATEMENTS...
}

Une instruction "finally" fournit un bloc de code à l'instruction "try" précédente (ou à la paire "try/catch") qui est exécuté ensuite, tant en cas d'exécution normale qu'en cas d'exception déclenchée. Ce bloc de code peut être utilisé pour fournir toutes les opérations de nettoyage qui pourraient être requises par le code précédent.

Parce qu'il est exécuté pendant une opération de nettoyage de la pile, un bloc "finally {}" ne peut pas provoquer le retour de la fonction contenant, ni modifier sa valeur de retour. Il ne peut pas non plus voir le tableau d'arguments @_ de la fonction contenant (bien qu'étant dans la portée du bloc à l'intérieur de la fonction, il continuera à partager toutes les variables lexicales normales déclarées jusqu'à ce point). Il est protégé contre la modification de la valeur de $@. Si le code du bloc "finally {}" déclenche une exception, celle-ci sera affichée comme un avertissement et ignorée, laissant $@ contenant l'exception d'origine, s'il y en avait une.

AUTRES MODULES

Il existe déjà un certain nombre de modules sur CPAN qui fournissent une syntaxe de type "try/catch" pour Perl.

  • Try
  • TryCatch
  • Try::Tiny
  • Syntax::Feature::Try

De plus, Perl lui-même a intégré une syntaxe "try/catch" basée sur ce module à la version 5.34.0. Elle est disponible via "use feature 'try'".

Ils sont comparés ici, par fonctionnalité :

Plugin de syntaxe réel

Comme Try et Syntax::Feature::Try, ce module est implémenté comme un véritable plugin de syntaxe, lui permettant de fournir de nouvelles règles d'analyse non disponibles pour de simples fonctions. Ici, cela signifie surtout que la combinaison résultante n'a pas besoin de se terminer par un point-virgule.

La fonctionnalité principale "feature 'try'" est également implémentée comme une syntaxe native réelle dans l'analyseur Perl.

En comparaison, Try::Tiny est du Perl pur et fournit sa fonctionnalité à l'aide de fonctions Perl standard ; ainsi, sa syntaxe nécessite le point-virgule final.

TryCatch est un hybride qui utilise Devel::Declare pour analyser l'arbre syntaxique.

@_ dans un bloc try ou catch

Étant donné que le code des blocs "try" et "catch" est contenu dans un bloc réel plutôt que dans une sous-routine anonyme entière, leur invocation n'interfère pas avec le tableau d'arguments @_. Le code à l'intérieur de ces blocs peut interagir avec le tableau de la fonction appelante comme auparavant.

Cette fonctionnalité est unique parmi ces modules ; aucun des autres listés n'a cette capacité.

La fonctionnalité principale "feature 'try'" se comporte également de cette manière.

"return" dans un bloc try ou catch

Comme TryCatch et Syntax::Feature::Try, l'instruction "return" a son effet habituel dans une sous-routine contenant la syntaxe fournie par ce module. À savoir, elle provoque le retour de la "sub" contenant elle-même.

Elle se comporte également ainsi avec la fonctionnalité principale "feature 'try'".

En comparaison, l'utilisation de Try ou Try::Tiny signifie qu'une instruction "return" ne sortira que du bloc "try".

"next"/"last"/"redo" dans un bloc try ou catch

Les mots-clés de contrôle de boucle "next", "last" et "redo" ont leur effet habituel sur les boucles dynamiquement contenues.

Ceux-ci fonctionnent également correctement lors de l'utilisation de la fonctionnalité principale "feature 'try'".

Syntax::Feature::Try documente que ceux-ci n'y fonctionnent pas. Les autres modules ne font aucune déclaration à ce sujet.

Sémantique de valeur

Comme Try et Syntax::Feature::Try, la syntaxe fournie par ce module ne fonctionne qu'en tant qu'instruction au niveau syntaxique et non comme une expression. Vous ne pouvez pas assigner le résultat d'un bloc "try". Une solution courante consiste à encapsuler l'instruction "try/catch" dans un bloc "do", où son expression finale peut être capturée et utilisée comme valeur.

Le même encapsulage avec un bloc "do" fonctionne également pour la fonctionnalité principale "feature 'try'".

En comparaison, le comportement implémenté par Try::Tiny peut être utilisé comme une expression valorisée, par exemple assignée à une variable ou retournée à l'appelant de sa fonction contenante.

"try" sans "catch"

Comme Syntax::Feature::Try, la syntaxe fournie par ce module permet à un bloc "try" d'être suivi uniquement d'un bloc "finally", sans "catch". Dans ce cas, les exceptions déclenchées par le code contenu dans le "try" ne sont pas supprimées, elles se propagent au contraire normalement vers les appelants. Cela correspond au comportement familier des programmeurs Java ou C++.

En comparaison, le code fourni par Try et Try::Tiny supprime toujours la propagation des exceptions, même sans bloc "catch" réel.

Le module TryCatch n'autorise pas un bloc "try" non suivi d'un "catch".

La fonctionnalité principale "feature 'try'" n'implémente pas du tout "finally", et exige également que chaque bloc "try" soit suivi d'un "catch".

"catch" typé

Try et Try::Tiny ne font aucune tentative pour effectuer une forme de dispatch typé afin de distinguer les types d'exceptions capturés par les blocs "catch".

De même, la fonctionnalité principale "feature 'try'" ne fournit actuellement pas cette capacité, bien que ce soit un domaine de travail de conception en cours.

TryCatch et Syntax::Feature::Try tentent tous deux de fournir une forme de dispatch typé où différentes classes d'exceptions sont capturées par différents blocs de code, ou propagées entièrement vers les appelants.

Ce module fournit une telle capacité, via la syntaxe actuellement expérimentale "catch (VAR cond...)".

Les réflexions sur la conception se poursuivent sur le ticket RT https://rt.cpan.org/Ticket/Display.html?id=123918.

AVEC D'AUTRES MODULES

Future::AsyncAwait

À partir de la version 0.10 de "Future::AsyncAwait" et de la version 0.07 de Syntax::Keyword::Try, les tests d'intégration inter-modules affirment que les blocs "try/catch" de base à l'intérieur d'une "async sub" fonctionnent correctement, y compris ceux qui tentent de "return" depuis l'intérieur de "try".

use Future::AsyncAwait;
use Syntax::Keyword::Try;
async sub attempt
{
   try {
      await func();
      return "success";
   }
   catch {
      return "failed";
   }
}

PROBLÈMES

La thread-sécurité au chargement ne peut être assurée avant perl 5.16

Sur les versions de perl 5.16 et supérieures, ce module est thread-safe.

Sur la version 5.14 de perl, ce module est thread-safe à condition qu'il soit chargé avec "use" avant la création de fils supplémentaires.

Cependant, lors de l'utilisation de la version 5.14, il y a une condition de concurrence si ce module est chargé tardivement dans le démarrage du programme, après la création de fils supplémentaires. Cela conduit à la possibilité qu'il soit démarré plusieurs fois simultanément, ce qui crée des courses de données lors de la modification des structures internes et conduit probablement à une erreur de segmentation, soit lors du chargement, soit peu après lors de la compilation de code supplémentaire.

En guise de solution de contournement, pour tout programme de ce type qui crée plusieurs fils, charge du code supplémentaire (comme des plugins découverts dynamiquement) et doit s'exécuter sur la version 5.14, il doit s'assurer de

use Syntax::Keyword::Try;

tôt dans le démarrage, avant de lancer des fils supplémentaires.

(Voir également https://rt.cpan.org/Public/Bug/Display.html?id=123547)
