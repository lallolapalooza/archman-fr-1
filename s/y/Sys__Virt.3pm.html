NOM

Sys::Virt - Représenter et gérer une connexion hyperviseur libvirt

SYNOPSIS

my $conn = Sys::Virt->new(uri => $uri);
my @domains = $conn->list_domains();
foreach my $dom (@domains) {
  print "Domaine ", $dom->get_id, " ", $dom->get_name, "\n";
}

DESCRIPTION

Le module Sys::Virt fournit une liaison XS Perl aux API de gestion de machines virtuelles de libvirt. Cela permet de gérer des machines fonctionnant dans des conteneurs de virtualisation arbitraires avec une API cohérente.

GESTION DES RAPPELS

Chaque routine d'enregistrement de rappel retourne un $callbackID (sauf pour "domain_event_register" et "register_close_callback"). Cette valeur de retour doit être conservée et utilisée pour la désinscription des rappels.

IMPORTANT : Tous les rappels doivent être désinscrits (y compris ceux enregistrés à l'aide de "domain_event_register" et "register_close_callback") ; ne pas le faire empêche l'objet "Sys::Virt" d'être collecté par le garbage collector et la connexion à "libvirtd" de se fermer.

GESTION DES ERREURS

Toutes les opérations de l'API Sys::Virt présentant des scénarios d'échec déclencheront une instance du module Sys::Virt::Error. Pour attraper ces erreurs, il suffit d'encapsuler la méthode dans un bloc eval :

eval { my $conn = Sys::Virt->new(uri => $uri); };
if ($@) {
  print STDERR "Impossible d'ouvrir la connexion à $addr" . $@->message . "\n";
}

Pour plus de détails sur les informations contenues dans les objets d'erreur, consultez la page de manuel de Sys::Virt::Error.

MÉTHODES

my $conn = Sys::Virt->new(uri => $uri, readonly => $ro, flags => $flags);
Se connecte à l'hôte de virtualisation identifié par "uri". Le paramètre "uri" peut être omis, auquel cas la connexion par défaut sera établie avec l'hyperviseur Xen local. Voici quelques exemples d'URI :
xen:///
Xen sur la machine locale
test:///default
Pilote factice "en mémoire" pour les suites de tests
qemu:///system
Pilote système pour la virtualisation QEMU / KVM
qemu:///session
Pilote par utilisateur pour la virtualisation QEMU
qemu+tls://somehost/system
Pilote QEMU système sur "somehost" utilisant la sécurité TLS
xen+tcp://somehost/
Pilote Xen sur "somehost" utilisant TCP / sécurité SASL

Pour plus de détails, consultez "http://libvirt.org/uri.html"

Si le paramètre optionnel "readonly" est fourni, une connexion non privilégiée à l'hyperviseur sera tentée. S'il n'est pas fourni, la valeur par défaut est d'établir une connexion entièrement privilégiée à l'hyperviseur. Si l'application appelante n'est pas exécutée en tant que root, il peut être nécessaire de fournir des rappels d'authentification.

Si le paramètre optionnel "auth" est défini sur une valeur non nulle, l'authentification sera activée pendant la connexion, en utilisant l'ensemble par défaut de rappels de collecte d'identifiants. Les rappels par défaut demandent les identifiants sur la console, ils ne conviennent donc pas aux applications graphiques. Pour de telles applications, une implémentation personnalisée devrait être fournie. Le paramètre "credlist" doit être une référence de tableau listant l'ensemble des types d'identifiants qui seront pris en charge. Les constantes d'identifiants de ce module peuvent être utilisées comme valeurs dans cette liste. Le paramètre "callback" doit être une référence de sous-routine contenant le code nécessaire pour collecter les identifiants. Lorsqu'elle est invoquée, elle recevra un seul paramètre, une référence de tableau des identifiants demandés. Les éléments du tableau sont des références de hachage, avec les clés "type" donnant le type d'identifiant, "prompt" donnant une invite descriptive pour l'utilisateur, "challenge" donnant le nom de l'identifiant requis. La réponse doit être collectée auprès de l'utilisateur et renvoyée en définissant la clé "result". Cette clé peut déjà être définie avec un résultat par défaut si applicable.

Comme exemple simple renvoyant des identifiants codés en dur

my $uri  = "qemu+tcp://192.168.122.1/system";
my $username = "test";
my $password = "123456";
my $con = Sys::Virt->new(uri => $uri,
                         auth => 1,
                         credlist => [
                           Sys::Virt::CRED_AUTHNAME,
                           Sys::Virt::CRED_PASSPHRASE,
                         ],
                         callback =>
     sub {
           my $creds = shift;
           foreach my $cred (@{$creds}) {
              if ($cred->{type} == Sys::Virt::CRED_AUTHNAME) {
                  $cred->{result} = $username;
              }
              if ($cred->{type} == Sys::Virt::CRED_PASSPHRASE) {
                  $cred->{result} = $password;
              }
           }
           return 0;
     });

Pour des raisons de compatibilité avec les versions antérieures, le paramètre "address" est accepté comme synonyme du paramètre "uri". L'utilisation de "uri" est recommandée pour tout nouveau code.

Sys::Virt - Perl interface to libvirt

  use Sys::Virt;

  my $conn = Sys::Virt->new(uri => "qemu:///system");
  # ou
  my $conn = Sys::Virt->connect(uri => "qemu:///system");

  # Pour se déconnecter
  $conn->close();

  # Obtenir un domaine
  my $domain = $conn->get_domain(name => "my_vm");

  # Obtenir tous les domaines
  my @domains = $conn->list_domains();

  # Gérer les callbacks
  $conn->add_domain_event_callback(sub { ... });
  $conn->add_connection_close_callback(sub { ... });

  # Gérer les erreurs
  eval {
    # Code qui peut échouer
  };
  if ($@) {
    my $error = Sys::Virt::Error->get_last();
    # ... gérer l'erreur ...
  }

DESCRIPTION

Ce module fournit une interface Perl pour l'API libvirt.

CALLBACK HANDLING

Le module prend en charge la gestion des événements via des callbacks. Vous pouvez enregistrer des sous-routines pour être appelées lors de divers événements, tels que la création ou la destruction d'un domaine, ou la fermeture de la connexion.

add_domain_event_callback($callback)
Enregistre une sous-routine à appeler lors d'événements liés aux domaines.
add_connection_close_callback($callback)
Enregistre une sous-routine à appeler lorsque la connexion est fermée.
remove_domain_event_callback($callback)
Supprime un callback d'événement de domaine.
remove_connection_close_callback($callback)
Supprime un callback de fermeture de connexion.

ERROR HANDLING

Les erreurs libvirt sont capturées et peuvent être récupérées via l'objet Sys::Virt::Error. Utilisez le bloc eval pour attraper les exceptions.

Sys::Virt::Error::get_last()
Récupère la dernière erreur libvirt.
