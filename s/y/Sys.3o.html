Module Sys

Interface système.

Chaque fonction de ce module lève Sys_error avec un message informatif lorsque l'appel système sous-jacent signale une erreur.

val argv : string array

Les arguments de la ligne de commande donnés au processus. Le premier élément est le nom de la commande utilisée pour invoquer le programme. Les éléments suivants sont les arguments de la ligne de commande donnés au programme.

val executable_name : string

Le nom du fichier contenant l'exécutable actuellement en cours d'exécution. Ce nom peut être absolu ou relatif au répertoire courant, en fonction de la plateforme et si le programme a été compilé en bytecode ou en exécutable natif.

val file_exists : string -> bool

Teste si un fichier portant le nom donné existe.

val is_directory : string -> bool

Retourne true si le nom donné fait référence à un répertoire, false s'il fait référence à un autre type de fichier.

Depuis 3.10

val is_regular_file : string -> bool

Retourne true si le nom donné fait référence à un fichier régulier, false s'il fait référence à un autre type de fichier.

Depuis 5.1

val remove : string -> unit

Supprime le nom de fichier donné du système de fichiers.

val rename : string -> string -> unit

Renomme un fichier ou un répertoire. rename oldpath newpath renomme le fichier ou le répertoire appelé oldpath, en lui donnant newpath comme nouveau nom, le déplaçant entre (répertoires parents) si nécessaire. Si un fichier nommé newpath existe déjà, son contenu sera remplacé par celui de oldpath. En fonction du système d'exploitation, les métadonnées (permissions, propriétaire, etc.) de newpath peuvent soit être préservées, soit remplacées par celles de oldpath.

val command : string -> int

Exécute la commande shell donnée et retourne son code de sortie.

L'argument de Sys.command est généralement le nom d'une commande suivi de zéro, un ou plusieurs arguments, séparés par des espaces. L'argument donné est interprété par un shell : soit le shell Windows cmd.exe pour les ports Win32 d'OCaml, soit le shell POSIX sh pour les autres ports. Il peut contenir des commandes intégrées au shell comme echo, ainsi que des caractères spéciaux comme les redirections de fichiers > et <, qui seront respectés par le shell.

Inversement, les espaces ou caractères spéciaux du shell apparaissant dans les noms de commandes ou dans leurs arguments doivent être mis entre guillemets ou échappés afin que le shell ne les interprète pas. Les règles de mise entre guillemets varient entre le shell POSIX et le shell Windows. Filename.quote_command effectue la mise entre guillemets appropriée étant donné un nom de commande, une liste d'arguments et des redirections de fichiers optionnelles.

val readdir : string -> string array

Retourne les noms de tous les fichiers présents dans le répertoire donné. Les noms désignant le répertoire courant et le répertoire parent ( "." et ".." sous Unix) ne sont pas retournés. Chaque chaîne de caractères dans le résultat est un nom de fichier plutôt qu'un chemin complet. Il n'y a aucune garantie que les chaînes de noms du tableau résultant apparaîtront dans un ordre spécifique ; elles ne sont pas, en particulier, garanties d'apparaître par ordre alphabétique.

val io_buffer_size : int

Taille des buffers C utilisés par le système d'exécution et les primitives d'E/S de la bibliothèque unix.

Les primitives qui lisent ou écrivent des valeurs de type string ou bytes utilisent généralement un tampon intermédiaire de cette taille pour éviter de détenir le verrou de domaine.

Gestion des signaux

type signal = int

Le type pour les numéros de signaux.

Les nombres négatifs sont utilisés par OCaml pour fournir un numéro indépendant de la plateforme pour les signaux reconnus par OCaml. Les nombres positifs sont toujours la valeur dépendante de la plateforme pour un signal donné. La fonction Sys.signal_of_int convertit les numéros de signaux dépendants de la plateforme en numéros indépendants, et Sys.signal_to_int fait le contraire.

Depuis 5.4

type signal_behavior =
| Signal_default
| Signal_ignore
| Signal_handle of (signal -> unit)

Que faire lors de la réception d'un signal :

- Signal_default : adopter le comportement par défaut (généralement : abandonner le programme)

- Signal_ignore : ignorer le signal

- Signal_handle f : appeler la fonction f , en lui donnant le numéro du signal comme argument.

val signal : signal -> signal_behavior -> signal_behavior

Définit le comportement du système lors de la réception d'un signal donné. Le premier argument est le numéro du signal. Retourne le comportement précédemment associé au signal. Si le numéro de signal est invalide (ou non disponible sur votre système), une exception Invalid_argument est levée.

Si un numéro de signal dépendant de la plateforme est utilisé, il sera converti en un signal indépendant de la plateforme à l'aide de Sys.signal_of_int avant d'appeler le gestionnaire.

val set_signal : signal -> signal_behavior -> unit

Identique à Sys.signal mais la valeur de retour est ignorée.

exception Break

Exception levée lors d'une interruption interactive si Sys.catch_break est activé.

val catch_break : bool -> unit

catch_break détermine si une interruption interactive (ctrl-C) doit terminer le programme ou lever l'exception Break. Appelez catch_break true pour activer la levée de Break, et catch_break false pour laisser le système terminer le programme lors d'une interruption utilisateur.

Dans les programmes multi-threads, l'exception Break sera levée dans l'un des threads actifs, et continuera de l'être lors d'interruptions interactives ultérieures jusqu'à ce que tous les threads soient terminés. Utilisez les masques de signaux de Thread.sigmask pour diriger l'interruption vers un thread spécifique.

val ocaml_version : string

ocaml_version est la version d'OCaml. C'est une chaîne de la forme "major.minor[.patchlevel][(+|~)additional-info]" , où major , minor et patchlevel sont des entiers, et additional-info est une chaîne arbitraire. La partie [.patchlevel] était absente avant la version 3.08.0 et est devenue obligatoire à partir de 3.08.0. La partie [(+|~)additional-info] peut être absente.

val development_version : bool

true si c'est une version de développement, false sinon.

Optimisation

val opaque_identity : 'a -> 'a

Dans un but d'optimisation, opaque_identity se comporte comme une fonction inconnue (et donc potentiellement avec des effets de bord).

À l'exécution, opaque_identity disparaît complètement. Cependant, elle empêche l'argument d'être collecté par le garbage collector jusqu'à l'emplacement où l'appel aurait eu lieu.

Une utilisation typique de cette fonction est d'empêcher les calculs purs d'être optimisés hors des boucles de benchmarking. Par exemple :

      for _round = 1 to 100_000 do
        ignore (Sys.opaque_identity (my_pure_computation ()))
      done
