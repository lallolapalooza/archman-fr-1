NAME

Sys::Virt::StorageVol - Représenter et gérer un volume de stockage libvirt

DESCRIPTION

Le module "Sys::Virt::StorageVol" représente un volume de stockage géré par libvirt. Un volume de stockage est toujours associé à un pool de stockage ("Sys::Virt::StoragePool").

MÉTHODES

mon $nom = $vol->get_name()
Retourne une chaîne représentant le nom local unique du volume de stockage.
mon $nom = $vol->get_key()
Retourne une chaîne représentant la clé globale unique du volume de stockage.
mon $nom = $vol->get_path()
Retourne une chaîne représentant le chemin d'accès local unique du volume de stockage.
mon $xml = $vol->get_xml_description()
Retourne un document XML contenant une description complète de la configuration du volume de stockage.
$vol->delete($flags)
Supprime immédiatement le volume de stockage, libérant ses ressources de stockage. Le paramètre "flags" indique toute action spéciale à effectuer lors de la suppression du volume.
$vol->resize($newcapacity, $flags=0)
Redimensionne le volume de stockage. La valeur $newcapacity a une signification qui dépend du paramètre $flags. Si $flags spécifie "RESIZE_DELTA", alors $newcapacity est relatif à la taille actuelle. Si $flags spécifie "RESIZE_SHRINK", alors la valeur $newcapacity est la quantité d'espace à réduire.
$vol->wipe($flags = 0)
Efface les données du volume de stockage afin d'empêcher la récupération future des informations. Le paramètre "flags" est actuellement inutilisé et se comporte comme 0.
$vol->wipe_pattern($algorithm, $flags = 0)
Efface les données du volume de stockage afin d'empêcher la récupération future des informations. Le paramètre $algorithm spécifie le motif de données utilisé pour effacer les données, et doit être l'une des CONSTANTES de MOTIF D'EFFACEMENT mentionnées plus loin. Le paramètre "flags" est actuellement inutilisé et se comporte comme 0.
mon $info = $vol->get_info($flags = 0)
Obtient des informations en temps réel sur le volume de stockage. La valeur $info est une référence à un hash contenant trois clés. "type" indique si le volume est un fichier ou un périphérique bloc. "capacity" fournit la taille logique maximale du volume. "allocation" fournit l'utilisation physique actuelle du volume. L'allocation peut être inférieure à la taille de capacité pour les volumes épars, ou elle peut croître à la demande. L'allocation peut également être supérieure à la taille de capacité, s'il y a une sur-allocation de métadonnées pour le format du volume. Le paramètre $flags peut prendre l'une des valeurs suivantes :
Sys::Virt::StorageVol::USE_ALLOCATION
Retourne la taille d'allocation actuelle.
Sys::Virt::StorageVol::GET_PHYSICAL
Retourne la taille physique allouée.
$vol->download($st, $offset, $length, $flags=0);
Télécharge les données depuis $vol en utilisant le flux $st. Si $offset et $length ne sont pas nuls, les données sont limitées à la plage d'octets spécifiée du volume de stockage. Le paramètre $flags accepte les valeurs suivantes :
Sys::Virt::StorageVol::VOL_DOWNLOAD_SPARSE_STREAM
Si ce flag est défini dans @flags, le streaming des trous est autorisé. Cela suppose que le flux $st est utilisé en combinaison avec "sparse_recv_all" ou "recv($flags = VIR_STREAM_RECV_STOP_AT_HOLE)" pour accepter les trous envoyés par le serveur.
$vol->upload($st, $offset, $length, $flags=0);
Téléverse les données vers $vol en utilisant le flux $st. Si $offset et $length ne sont pas nuls, les données sont limitées à la plage d'octets spécifiée du volume de stockage. Le paramètre $flags accepte les valeurs suivantes :
Sys::Virt::StorageVol::VOL_UPLOAD_SPARSE_STREAM
Si ce flag est défini dans $flags, le streaming des trous est autorisé. Cela suppose que le flux $st est utilisé en combinaison avec "sparse_send_all" ou "send_hole" pour préserver la sparsité de la source de fichier.

CONSTANTES

Les sections de constantes suivantes sont utiles lors de la manipulation des volumes de stockage.

TYPES DE VOLUMES

Les constantes suivantes sont utiles pour interpréter le champ "type" dans le hash retourné par la méthode "get_info".

Sys::Virt::StorageVol::TYPE_FILE
Le volume est un fichier plat.
Sys::Virt::StorageVol::TYPE_BLOCK
Le volume est un périphérique bloc.
Sys::Virt::StorageVol::TYPE_DIR
Le volume est un répertoire.
Sys::Virt::StorageVol::TYPE_NETWORK
Le volume est une source réseau.
Sys::Virt::StorageVol::TYPE_NETDIR
Le volume est un répertoire réseau.
Sys::Virt::StorageVol::TYPE_PLOOP
Le volume est un répertoire ploop.

MODES DE CRÉATION

Les constantes suivantes sont utiles pour le paramètre "flags" de la méthode "create".

Sys::Virt::StorageVol::CREATE_PREALLOC_METADATA
Pré-alloue les métadonnées d'en-tête lors de la création du volume.
Sys::Virt::StorageVol::CREATE_REFLINK
Effectue une copie par référence (copy-on-write).
Sys::Virt::StorageVol::CREATE_VALIDATE
Valide le document XML par rapport au schéma.

MODES DE SUPPRESSION

Les constantes suivantes sont utiles pour le paramètre "flags" de la méthode "delete".

Sys::Virt::StorageVol::DELETE_NORMAL
Effectue une suppression normale sans tenter d'effacer les données.
Sys::Virt::StorageVol::DELETE_ZEROED
Supprime un volume avec des données effacées.
Sys::Virt::StorageVol::DELETE_ZEROED
Supprime un volume avec des données effacées.

NAME

Sys::Virt::StorageVol — Interface to storage volumes within libvirt

DESCRIPTION

This module provides access to storage volumes within libvirt. Storage volumes represent virtual disks or raw block devices that can be used by virtual machines.

The module allows for creation, deletion, resizing, and other operations on storage volumes.

METHODS

This module does not expose any public methods.

CONSTANTS

DELETE CONSTANTS

The following constants are used to control the behavior when deleting a storage volume:

Sys::Virt::StorageVol::DELETE_ZEROED
Zero out current allocated blocks when deleting the volume
Sys::Virt::StorageVol::DELETE_WITH_SNAPSHOTS
Delete snapshots associated with the volume

WIPE ALGORITHM CONSTANTS

The following constants specify the algorithm for erasing data

Sys::Virt::StorageVol::WIPE_ALG_BSI
9-pass method recommended by the German Center of Security in Information Technologies
Sys::Virt::StorageVol::WIPE_ALG_DOD
4-pass Dod 5220.22-M section, 8-306 procedure
Sys::Virt::StorageVol::WIPE_ALG_GUTMANN
The canonical 35-pass sequence
Sys::Virt::StorageVol::WIPE_ALG_NNSA
4-pass NNSA Policy Letter NAP-14.1-C (XVI-8)
Sys::Virt::StorageVol::WIPE_ALG_PFITZNER7
7-pass random
Sys::Virt::StorageVol::WIPE_ALG_PFITZNER33
33-pass random
Sys::Virt::StorageVol::WIPE_ALG_RANDOM
1-pass random
Sys::Virt::StorageVol::WIPE_ALG_SCHNEIER
7-pass method described by Bruce Schneier in "Applied Cryptography" (1996)
Sys::Virt::StorageVol::WIPE_ALG_ZERO
1-pass, all zeroes
Sys::Virt::StorageVol::WIPE_ALG_TRIM
1-pass, trim all data on the volume by using TRIM or DISCARD

VOLUME RESIZE CONSTANTS

The following constants control how storage volumes can be resized

Sys::Virt::StorageVol::RESIZE_ALLOCATE
Fully allocate the extra space required during resize
Sys::Virt::StorageVol::RESIZE_DELTA
Treat the new capacity as a delta to the current capacity
Sys::Virt::StorageVol::RESIZE_SHRINK
Treat the new capacity as an amount to remove from the capacity
