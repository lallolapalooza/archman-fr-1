Search__Xapian(3pm)

Xapian(3) Documentation Perl fournie par l'utilisateur Xapian(3)

NOM

Search::Xapian - Interface Perl XS vers la bibliothèque de recherche C++ Xapian.

SYNOPIS

use Search::Xapian;
my $db = Search::Xapian::Database->new( '[RÉPERTOIRE BASE DE DONNÉES]' );
my $enq = $db->enquire( '[TERME RECHERCHE]' );
printf "Exécution de la requête '%s'\n", $enq->get_query()->get_description();
my @matches = $enq->matches(0, 10);
print scalar(@matches) . " résultats trouvés\n";
foreach my $match ( @matches ) {
  my $doc = $match->get_document();
  printf "ID %d %d%% [ %s ]\n", $match->get_docid(), $match->get_percent(), $doc->get_data();
}

DESCRIPTION

Ce module enveloppe la plupart des méthodes de la plupart des classes Xapian. Les classes et méthodes manquantes devraient être ajoutées à l'avenir. Il fournit également une interface simplifiée et plus 'perlée' pour certaines opérations courantes, comme démontré ci-dessus.

Il y a quelques lacunes dans la documentation POD pour les classes enveloppées, mais vous pouvez consulter la documentation de l'API C++ de Xapian sur https://xapian.org/docs/apidoc/html/annotated.html pour plus de détails. Alternativement, jetez un œil au code dans les exemples et les tests.

Si vous souhaitez utiliser Search::Xapian et le module threads ensemble, assurez-vous d'utiliser Search::Xapian >= 1.0.4.0 et Perl >= 5.8.7. À partir de 1.0.4.0, Search::Xapian utilise CLONE_SKIP pour s'assurer que les objets wrapper perl ne sont pas copiés vers de nouveaux threads - sans cela, les objets C++ sous-jacents peuvent être détruits plus d'une fois.

Si vous rencontrez des problèmes, ou si vous avez des commentaires, des suggestions, des correctifs, etc., veuillez envoyer un e-mail à la liste de discussion Xapian-discuss (dont les détails se trouvent sur https://xapian.org/lists).

EXPORT

Aucun par défaut.

:db

DB_OPEN
Ouvre une base de données, échoue si la base de données n'existe pas.
DB_CREATE
Crée une nouvelle base de données, échoue si la base de données existe déjà.
DB_CREATE_OR_OPEN
Ouvre une base de données existante, sans détruire les données, ou crée une nouvelle base de données si elle n'existe pas déjà.
DB_CREATE_OR_OVERWRITE
Écrase la base de données si elle existe.

:ops

OP_AND
Correspond si les deux sous-requêtes sont satisfaites.
OP_OR
Correspond si l'une ou l'autre des sous-requêtes est satisfaite.
OP_AND_NOT
Correspond si la sous-requête de gauche est satisfaite mais pas celle de droite.
OP_XOR
Correspond si la requête de gauche ou de droite est satisfaite, mais pas les deux.
OP_AND_MAYBE
Correspond si la requête de gauche est satisfaite, mais utilise les poids des deux.
OP_FILTER
Similaire à OP_AND, mais ne pondère qu'avec la requête de gauche.
OP_NEAR
Correspond si les mots sont proches les uns des autres. La fenêtre doit être spécifiée comme paramètre de "Search::Xapian::Query::Query", mais elle défaut au nombre de termes dans la liste.
OP_PHRASE
Correspond en tant que phrase (Tous les mots dans l'ordre).
OP_ELITE_SET
Sélectionne un ensemble d'élite parmi les sous-requêtes et effectue une requête avec celles-ci combinées comme une requête OR.
OP_VALUE_RANGE
Filtre par un test de plage sur une valeur de document.

:qpflags

FLAG_DEFAULT
Ceci donne les paramètres de drapeau par défaut du QueryParser, vous permettant d'ajouter facilement des drapeaux aux drapeaux par défaut.
FLAG_BOOLEAN
Prend en charge AND, OR, etc. et les sous-expressions entre parenthèses.
FLAG_LOVEHATE
Prend en charge + et -.
FLAG_PHRASE
Prend en charge les phrases entre guillemets.
FLAG_BOOLEAN_ANY_CASE
Prend en charge AND, OR, etc., même s'ils ne sont pas en MAJUSCULES.
FLAG_WILDCARD
Prend en charge la troncature à droite (par exemple, Xap*).
FLAG_PURE_NOT
Permet des requêtes telles que 'NOT pommes'.

Celles-ci nécessitent l'utilisation d'une liste de tous les documents de la base de données, ce qui peut être coûteux. Cette fonctionnalité n'est donc pas activée par défaut.

FLAG_PARTIAL
Active la correspondance partielle.

La correspondance partielle amène le parseur à traiter la requête comme une recherche "partiellement saisie". Cela traitera automatiquement le dernier mot comme une correspondance avec un troncature, sauf s'il est suivi d'un espace blanc, afin de produire des résultats plus stables à partir des recherches interactives.

FLAG_SPELLING_CORRECTION
FLAG_SYNONYM
FLAG_AUTO_SYNONYMS
FLAG_AUTO_MULTIWORD_SYNONYMS

:qpstem

STEM_ALL
Racine tous les termes.
STEM_NONE
Ne racinise aucun terme.
STEM_SOME
Racinise certains termes, d'une manière compatible avec Omega (les mots en majuscules et ceux des phrases ne sont pas racinisés).

:enq_order

ENQ_ASCENDING
Les docids sont triés par ordre croissant (par défaut)
ENQ_DESCENDING
Les docids sont triés par ordre décroissant
ENQ_DONT_CARE
Les docids sont triés dans l'ordre le plus efficace pour le backend

:standard

Standard est db + ops + qpflags + qpstem

Fonctions de version

major_version
Retourne la version majeure de la bibliothèque C++ Xapian utilisée. Par exemple, pour Xapian 1.0.9, cela retournerait 1.
minor_version
Retourne la version mineure de la bibliothèque C++ Xapian utilisée. Par exemple, pour Xapian 1.0.9, cela retournerait 0.
revision
Retourne la révision de la bibliothèque C++ Xapian utilisée. Par exemple, pour Xapian 1.0.9, cela retournerait 9. Dans une série de versions stables, les bibliothèques Xapian avec les mêmes versions mineure et majeure sont généralement compatibles ABI, donc cela ne correspondra souvent pas au troisième composant de $Search::Xapian::VERSION (qui est la version des wrappers Search::Xapian XS).
