SELECT INTO(7) Documentation PostgreSQL 18.1 SELECT INTO(7)

NOM

SELECT_INTO - définir une nouvelle table à partir des résultats d'une requête

SYNTAXE

[ WITH [ RECURSIVE ] requete_with [, ...] ]
SELECT [ ALL | DISTINCT [ ON ( expression [, ...] ) ] ]
    [ { * | expression [ [ AS ] nom_sortie ] } [, ...] ]
    INTO [ TEMPORARY | TEMP | UNLOGGED ] [ TABLE ] nouvelle_table
    [ FROM element_from [, ...] ]
    [ WHERE condition ]
    [ GROUP BY expression [, ...] ]
    [ HAVING condition ]
    [ WINDOW nom_fenetre AS ( definition_fenetre ) [, ...] ]
    [ { UNION | INTERSECT | EXCEPT } [ ALL | DISTINCT ] select ]
    [ ORDER BY expression [ ASC | DESC | USING operateur ] [ NULLS { FIRST | LAST } ] [, ...] ]
    [ LIMIT { compte | ALL } ]
    [ OFFSET debut [ ROW | ROWS ] ]
    [ FETCH { FIRST | NEXT } [ compte ] { ROW | ROWS } ONLY ]
    [ FOR { UPDATE | SHARE } [ OF nom_table [, ...] ] [ NOWAIT ] [...] ]

DESCRIPTION

SELECT INTO crée une nouvelle table et la remplit avec les données calculées par une requête. Les données ne sont pas retournées au client, contrairement à un SELECT normal. Les colonnes de la nouvelle table auront les noms et types de données associés aux colonnes de sortie du SELECT.

PARAMETRES

TEMPORARY ou TEMP

Si spécifié, la table est créée en tant que table temporaire. Reportez-vous à CREATE TABLE (CREATE_TABLE(7)) pour plus de détails.

UNLOGGED

Si spécifié, la table est créée en tant que table non enregistrée (unlogged). Reportez-vous à CREATE TABLE (CREATE_TABLE(7)) pour plus de détails.

nouvelle_table

Le nom (éventuellement qualifié par un schéma) de la table à créer.

Tous les autres paramètres sont décrits en détail sous SELECT(7).

NOTES

CREATE TABLE AS est fonctionnellement similaire à SELECT INTO. CREATE TABLE AS est la syntaxe recommandée, car cette forme de SELECT INTO n'est pas disponible dans ECPG ou PL/pgSQL, car ils interprètent la clause INTO différemment. De plus, CREATE TABLE AS offre un sur-ensemble des fonctionnalités fournies par SELECT INTO.

Contrairement à CREATE TABLE AS, SELECT INTO ne permet pas de spécifier des propriétés telles que la méthode d'accès d'une table avec USING methode ou l'espace de table de la table avec TABLESPACE nom_tablespace. Utilisez CREATE TABLE AS si nécessaire. Par conséquent, la méthode d'accès par défaut est choisie pour la nouvelle table. Voir default_table_access_method pour plus d'informations.

EXEMPLES

Créer une nouvelle table films_recent ne contenant que les entrées récentes de la table films :

SELECT * INTO films_recent FROM films WHERE date_prod >= '2002-01-01';

COMPATIBILITE

La norme SQL utilise SELECT INTO pour représenter la sélection de valeurs dans des variables scalaires d'un programme hôte, plutôt que pour créer une nouvelle table. C'est effectivement l'usage trouvé dans ECPG (voir Chapitre 34) et PL/pgSQL (voir Chapitre 41). L'utilisation de SELECT INTO par PostgreSQL pour représenter la création de table est historique. Certaines autres implémentations SQL utilisent également SELECT INTO de cette manière (mais la plupart des implémentations SQL prennent en charge CREATE TABLE AS à la place). Indépendamment de ces considérations de compatibilité, il est préférable d'utiliser CREATE TABLE AS à cette fin dans du nouveau code.
