Paquet: postgresql

SET SESSION AUTHORIZATION(7) Documentation PostgreSQL 18.1 SET SESSION AUTHORIZATION(7)

NOM

SET_SESSION_AUTHORIZATION - définit l'identifiant utilisateur de session et l'identifiant utilisateur courant de la session actuelle

SYNTAXE

SET [ SESSION | LOCAL ] SESSION AUTHORIZATION nom_utilisateur
SET [ SESSION | LOCAL ] SESSION AUTHORIZATION DEFAULT
RESET SESSION AUTHORIZATION

DESCRIPTION

Cette commande définit l'identifiant utilisateur de session et l'identifiant utilisateur courant de la session SQL actuelle sur nom_utilisateur. Le nom d'utilisateur peut être écrit sous forme d'identifiant ou de littéral chaîne. En utilisant cette commande, il est possible, par exemple, d'incarner temporairement un utilisateur non privilégié et de revenir plus tard au rôle de superutilisateur.

L'identifiant utilisateur de session est initialement défini sur le nom d'utilisateur fourni par le client (potentiellement authentifié). L'identifiant utilisateur courant est normalement égal à l'identifiant utilisateur de session, mais peut changer temporairement dans le contexte des fonctions SECURITY DEFINER et de mécanismes similaires ; il peut également être changé par SET ROLE. L'identifiant utilisateur courant est pertinent pour la vérification des permissions.

L'identifiant utilisateur de session ne peut être changé que si l'utilisateur de session initial (l'utilisateur authentifié) possède les privilèges de superutilisateur. Sinon, la commande est acceptée uniquement si elle spécifie le nom d'utilisateur authentifié.

Les modificateurs SESSION et LOCAL agissent de la même manière que pour la commande SET régulière.

Les formes DEFAULT et RESET réinitialisent les identifiants utilisateur de session et courant à être le nom d'utilisateur authentifié d'origine. Ces formes peuvent être exécutées par n'importe quel utilisateur.

NOTES

SET SESSION AUTHORIZATION ne peut pas être utilisé à l'intérieur d'une fonction SECURITY DEFINER.

EXEMPLES

SELECT SESSION_USER, CURRENT_USER;
 session_user | current_user
--------------+--------------
 peter        | peter
SET SESSION AUTHORIZATION 'paul';
SELECT SESSION_USER, CURRENT_USER;
 session_user | current_user
--------------+--------------
 paul         | paul

COMPATIBILITÉ

La norme SQL autorise certaines autres expressions à la place du littéral nom_utilisateur, mais ces options ne sont pas importantes en pratique. PostgreSQL autorise la syntaxe d'identifiant ("nom_utilisateur"), ce que SQL ne fait pas. SQL n'autorise pas cette commande pendant une transaction ; PostgreSQL ne fait pas cette restriction car il n'y a aucune raison de le faire. Les modificateurs SESSION et LOCAL sont une extension PostgreSQL, tout comme la syntaxe RESET.

Les privilèges nécessaires pour exécuter cette commande sont laissés à la définition de l'implémentation par la norme.
