NOM

Search::Xapian::Enquire - Effectuer des requêtes sur une base de données

DESCRIPTION

Cette classe fournit une interface au système de recherche d'information dans le but de rechercher.

MÉTHODES

set_query
prend soit un objet Search::Xapian::Query prêt à l'emploi, soit une chaîne contenant une requête, qui sera alors passée au constructeur de Search::Xapian::Query, ainsi que tout autre argument passé.

set_collapse_key <clé_de_regroupement>
set_docid_order <ordre>
Définit la direction dans laquelle les documents sont ordonnés par ID de document dans le MSet renvoyé.

Cet ordre n'a d'effet que sur les documents qui auraient autrement un rang égal. Pour une correspondance probabiliste pondérée sans valeur de tri, cela signifie les documents de poids égal. Pour une correspondance booléenne, sans valeur de tri, cela signifie tous les documents. Et si une valeur de tri est utilisée, cela signifie les documents de valeur de tri égale (et aussi de poids égal si l'on trie sur la pertinence après le tri).

ordre peut être ENQ_ASCENDING (par défaut, les IDs de documents sont triés par ordre croissant), ENQ_DESCENDING (les IDs de documents sont triés par ordre décroissant), ou ENQ_DONT_CARE (les IDs de documents sont triés dans l'ordre le plus efficace pour le backend.)

Remarque : Si vous ajoutez des documents dans un ordre chronologique strict, alors une recherche booléenne, c'est-à-dire set_weighting_scheme(Search::Xapian::BoolWeight->new()) avec set_docid_order(ENQ_DESCENDING) est un moyen très efficace pour effectuer un « tri par date, le plus récent d'abord ».

set_cutoff <pourcentage_limite> [<poids_limite>]
set_sort_by_relevance
Définit le tri par pertinence uniquement. C'est le comportement par défaut.
set_sort_by_value <clé_de_tri> [<ascendant>]
Définit le tri par valeur uniquement.

clé_de_tri - numéro de valeur pour réorganiser. Le tri est effectué par comparaison de chaînes. Si ascendant est vrai (par défaut), plus la valeur est élevée, mieux c'est ; si ascendant est faux, plus la valeur est basse, mieux c'est.

ascendant - Si vrai, les valeurs de document qui trient plus haut par comparaison de chaînes sont meilleures. Si faux, l'ordre de tri est inversé. (par défaut vrai)

set_sort_by_value_then_relevance <clé_de_tri> [<ascendant>]
Définit le tri par valeur, puis par pertinence pour les documents ayant la même valeur.

clé_de_tri - numéro de valeur pour réorganiser. Le tri est effectué par comparaison de chaînes. Si ascendant est vrai (par défaut), plus la valeur est élevée, mieux c'est ; si ascendant est faux, plus la valeur est basse, mieux c'est.

ascendant - Si vrai, les valeurs de document qui trient plus haut par comparaison de chaînes sont meilleures. Si faux, l'ordre de tri est inversé. (par défaut vrai)

set_sort_by_relevance_then_value <clé_de_tri> [<ascendant>]
Définit le tri par pertinence, puis par valeur.

Notez qu'avec le schéma de pondération par défaut BM25, les documents non identiques auront rarement le même poids, donc ce paramètre donnera des résultats très similaires à set_sort_by_relevance(). Il devient plus utile avec des paramètres BM25 particuliers (par exemple, BM25Weight(1,0,1,0,0)) ou des schémas de pondération personnalisés.

clé_de_tri - numéro de valeur pour réorganiser. Le tri est effectué par comparaison de chaînes. Si ascendant est vrai (par défaut), plus la valeur est élevée, mieux c'est ; si ascendant est faux, plus la valeur est basse, mieux c'est.

ascendant - Si vrai, les valeurs de document qui trient plus haut par comparaison de chaînes sont meilleures. Si faux, l'ordre de tri est inversé. (par défaut vrai)

set_sort_by_key <trieur> [<ascendant>]
Définit le tri par clé uniquement.

trieur - le foncteur à utiliser pour construire la clé.

ascendant - Si vrai, les clés qui trient plus haut par comparaison de chaînes sont meilleures. Si faux, l'ordre de tri est inversé. (par défaut vrai)

set_sort_by_key_then_relevance <trieur> [<ascendant>]
Définit le tri par clé, puis par pertinence pour les documents ayant la même clé.

trieur - le foncteur à utiliser pour construire la clé.

ascendant - Si vrai, les clés qui trient plus haut par comparaison de chaînes sont meilleures. Si faux, l'ordre de tri est inversé. (par défaut vrai)

set_sort_by_relevance_then_key <trieur> [<ascendant>]
Définit le tri par pertinence, puis par clé.

trieur - le foncteur à utiliser pour construire la clé.

ascendant - Si vrai, les clés qui trient plus haut par comparaison de chaînes sont meilleures. Si faux, l'ordre de tri est inversé. (par défaut vrai)
