NOM

SET_TRANSACTION - définir les caractéristiques de la transaction en cours

SYNTAXE

SET TRANSACTION mode_transaction [, ...]
SET TRANSACTION SNAPSHOT id_instantané
SET SESSION CHARACTERISTICS AS TRANSACTION mode_transaction [, ...]
où mode_transaction est l'un des éléments suivants :
    ISOLATION LEVEL { SERIALIZABLE | REPEATABLE READ | READ COMMITTED | READ UNCOMMITTED }
    READ WRITE | READ ONLY
    [ NOT ] DEFERRABLE

DESCRIPTION

La commande SET TRANSACTION définit les caractéristiques de la transaction en cours. Elle n'a aucun effet sur les transactions ultérieures. SET SESSION CHARACTERISTICS définit les caractéristiques de transaction par défaut pour les transactions ultérieures d'une session. Ces valeurs par défaut peuvent être remplacées par SET TRANSACTION pour une transaction individuelle.

Les caractéristiques de transaction disponibles sont le niveau d'isolation de la transaction, le mode d'accès de la transaction (lecture/écriture ou lecture seule) et le mode reportable. De plus, un instantané peut être sélectionné, bien que uniquement pour la transaction en cours, et non comme valeur par défaut de session.

Le niveau d'isolation d'une transaction détermine quelles données la transaction peut voir lorsque d'autres transactions s'exécutent simultanément :

READ COMMITTED

Une instruction ne peut voir que les lignes validées avant son début. C'est le défaut.

REPEATABLE READ

Toutes les instructions de la transaction en cours ne peuvent voir que les lignes validées avant que la première requête ou instruction de modification de données ne soit exécutée dans cette transaction.

SERIALIZABLE

Toutes les instructions de la transaction en cours ne peuvent voir que les lignes validées avant que la première requête ou instruction de modification de données ne soit exécutée dans cette transaction. Si un schéma de lectures et d'écritures entre transactions sérialisables concurrentes créait une situation qui n'aurait pas pu se produire pour une exécution sérielle (une par une) de ces transactions, l'une d'elles sera annulée avec une erreur serialization_failure.
La norme SQL définit un niveau supplémentaire, READ UNCOMMITTED. Dans PostgreSQL, READ UNCOMMITTED est traité comme READ COMMITTED.

Le niveau d'isolation de la transaction ne peut pas être modifié après l'exécution de la première requête ou instruction de modification de données (SELECT, INSERT, DELETE, UPDATE, MERGE, FETCH ou COPY) d'une transaction. Voir le Chapitre 13 pour plus d'informations sur l'isolation des transactions et le contrôle de concurrence.

Le mode d'accès de la transaction détermine si la transaction est en lecture/écriture ou en lecture seule. Lecture/écriture est le défaut. Lorsqu'une transaction est en lecture seule, les commandes SQL suivantes sont interdites : INSERT, UPDATE, DELETE, MERGE et COPY FROM si la table qu'elles écriraient n'est pas une table temporaire ; toutes les commandes CREATE, ALTER et DROP ; COMMENT, GRANT, REVOKE, TRUNCATE ; et EXPLAIN ANALYZE et EXECUTE si la commande qu'ils exécuteraient fait partie de celles listées. C'est une notion de haut niveau de lecture seule qui n'empêche pas toutes les écritures sur disque.

La propriété de transaction DEFERRABLE n'a aucun effet à moins que la transaction ne soit également SERIALIZABLE et READ ONLY. Lorsque ces trois propriétés sont sélectionnées pour une transaction, la transaction peut se bloquer lors de l'acquisition initiale de son instantané, après quoi elle est en mesure de s'exécuter sans la surcharge normale d'une transaction SERIALIZABLE et sans aucun risque de contribuer à un échec de sérialisation ou d'être annulée par celui-ci. Ce mode est bien adapté aux rapports ou sauvegardes de longue durée.

La commande SET TRANSACTION SNAPSHOT permet à une nouvelle transaction de s'exécuter avec le même instantané qu'une transaction existante. La transaction préexistante doit avoir exporté son instantané avec la fonction pg_export_snapshot (voir la Section 9.28.5). Cette fonction renvoie un identifiant d'instantané, qui doit être donné à SET TRANSACTION SNAPSHOT pour spécifier quel instantané doit être importé. L'identifiant doit être écrit sous forme de chaîne littérale dans cette commande, par exemple '00000003-0000001B-1'. SET TRANSACTION SNAPSHOT ne peut être exécuté qu'au début d'une transaction, avant la première requête ou instruction de modification de données (SELECT, INSERT, DELETE, UPDATE, MERGE, FETCH ou COPY) de la transaction. De plus, la transaction doit déjà être réglée sur le niveau d'isolation SERIALIZABLE ou REPEATABLE READ (sinon, l'instantané serait immédiatement rejeté, car le mode READ COMMITTED prend un nouvel instantané pour chaque commande). Si la transaction importatrice utilise le niveau d'isolation SERIALIZABLE, alors la transaction qui a exporté l'instantané doit également utiliser ce niveau d'isolation. De plus, une transaction sérialisable non en lecture seule ne peut pas importer un instantané d'une transaction en lecture seule.

NOTES

Si SET TRANSACTION est exécuté sans START TRANSACTION ou BEGIN préalable, il émet un avertissement et n'a par ailleurs aucun effet.

Il est possible de se passer de SET TRANSACTION en spécifiant les modes_transaction souhaités dans BEGIN ou START TRANSACTION. Mais cette option n'est pas disponible pour SET TRANSACTION SNAPSHOT.

Les modes de transaction par défaut de la session peuvent également être définis ou examinés via les paramètres de configuration default_transaction_isolation, default_transaction_read_only et default_transaction_deferrable. (En fait, SET SESSION CHARACTERISTICS est juste un équivalent verbeux pour définir ces variables avec SET.) Cela signifie que les valeurs par défaut peuvent être définies dans le fichier de configuration, via ALTER DATABASE, etc. Consultez le Chapitre 19 pour plus d'informations.

Les modes de la transaction en cours peuvent de même être définis ou examinés via les paramètres de configuration transaction_isolation, transaction_read_only et transaction_deferrable. La définition de l'un de ces paramètres agit de la même manière que l'option correspondante de SET TRANSACTION, avec les mêmes restrictions quant au moment où cela peut être fait. Cependant, ces paramètres ne peuvent pas être définis dans le fichier de configuration, ni à partir d'une source autre que SQL en direct.

EXEMPLES

Pour démarrer une nouvelle transaction avec le même instantané qu'une transaction déjà existante, exportez d'abord l'instantané de la transaction existante. Cela renverra l'identifiant de l'instantané, par exemple :

BEGIN TRANSACTION ISOLATION LEVEL REPEATABLE READ;
SELECT pg_export_snapshot();
 pg_export_snapshot
---------------------
 00000003-0000001B-1
(1 ligne)

Donnez ensuite l'identifiant de l'instantané dans une commande SET TRANSACTION SNAPSHOT au début de la transaction nouvellement ouverte :

BEGIN TRANSACTION ISOLATION LEVEL REPEATABLE READ;
SET TRANSACTION SNAPSHOT '00000003-0000001B-1';

COMPATIBILITÉ

Ces commandes sont définies dans la norme SQL, à l'exception du mode de transaction DEFERRABLE et de la forme SET TRANSACTION SNAPSHOT, qui sont des extensions PostgreSQL.

SERIALIZABLE est le niveau d'isolation de transaction par défaut dans la norme. Dans PostgreSQL, le défaut est généralement READ COMMITTED, mais vous pouvez le modifier comme mentionné ci-dessus.

Dans la norme SQL, il existe une autre caractéristique de transaction qui peut être définie avec ces commandes : la taille de la zone de diagnostic. Ce concept est spécifique à SQL embarqué et n'est donc pas implémenté dans le serveur PostgreSQL.

La norme SQL exige des virgules entre les modes_transaction successifs, mais pour des raisons historiques, PostgreSQL autorise les virgules à être omises.

NAME

SET_TRANSACTION - PostgreSQL transaction control

SYNOPSIS

SET TRANSACTION [ ISOLATION LEVEL { SERIALIZABLE | REPEATABLE READ | READ COMMITTED } ] [ READ ONLY | READ WRITE ] [ DEFERRABLE | NOT DEFERRABLE ]

DESCRIPTION

SET TRANSACTION sets the characteristics of the current transaction. It can only be used at the beginning of a transaction (before any SQL statement other than SET or SHOW has been executed).

The following transaction characteristics can be set:

ISOLATION LEVEL

This clause specifies the isolation level of the transaction. The possible levels are:

SERIALIZABLE
The highest isolation level. It guarantees that concurrently executing transactions will produce results that would be possible if transactions were executed one after another (serially).
REPEATABLE READ
Guarantees that if a transaction reads data multiple times, it will see the same data each time. This prevents dirty reads and non-repeatable reads.
READ COMMITTED
Guarantees that only committed data will be read. This prevents dirty reads.

If this clause is omitted, the default isolation level is READ COMMITTED.

READ ONLY | READ WRITE

This clause specifies whether the transaction is read-only or read-write. By default, transactions are READ WRITE.

If a transaction is declared READ ONLY, it cannot execute commands that modify data. Any such command will result in an error. This can be useful for ensuring that a transaction does not accidentally modify data. It can also provide certain performance benefits, as PostgreSQL can make some optimizations knowing that no data will be changed.

DEFERRABLE | NOT DEFERRABLE

This clause specifies whether the transaction is deferrable. A deferrable transaction is one that can be delayed until it can be committed without causing conflicts with other transactions.

This option is only meaningful for SERIALIZABLE transactions. If the transaction is SERIALIZABLE and DEFERRABLE, the transaction may be allowed to proceed even if it would normally have to wait for other transactions to complete. However, it may be aborted later if it turns out that the transaction could not have committed immediately.

By default, transactions are NOT DEFERRABLE.

NOTES

The SET TRANSACTION command can only be issued at the beginning of a transaction. If it is issued after other SQL statements have been executed within the transaction, an error will be reported.

The isolation levels SERIALIZABLE and REPEATABLE READ are implemented using snapshot isolation. This means that the transaction sees a consistent snapshot of the database as of the time the transaction began.

For more details on transaction isolation levels and their implications, refer to the PostgreSQL documentation.

EXAMPLES

Start a transaction with the SERIALIZABLE isolation level:

BEGIN;
SET TRANSACTION ISOLATION LEVEL SERIALIZABLE;
-- Transaction commands here...
COMMIT;

Start a read-only transaction:

BEGIN;
SET TRANSACTION READ ONLY;
-- Transaction commands here...
COMMIT;

Start a deferrable transaction with the SERIALIZABLE isolation level:

BEGIN;
SET TRANSACTION ISOLATION LEVEL SERIALIZABLE DEFERRABLE;
-- Transaction commands here...
COMMIT;

COMPATIBILITY

SET TRANSACTION is a PostgreSQL extension. Standard SQL supports SET TRANSACTION ISOLATION LEVEL, but not the READ ONLY/WRITE or DEFERRABLE options.

NOM

SET_TRANSACTION - Contrôle des transactions PostgreSQL

SYNTAXE

SET TRANSACTION [ ISOLATION LEVEL { SERIALIZABLE | REPEATABLE READ | READ COMMITTED } ] [ READ ONLY | READ WRITE ] [ DEFERRABLE | NOT DEFERRABLE ]

DESCRIPTION

SET TRANSACTION définit les caractéristiques de la transaction courante. Il ne peut être utilisé qu'au début d'une transaction (avant toute instruction SQL autre que SET ou SHOW n'ait été exécutée).

Les caractéristiques de transaction suivantes peuvent être définies :

ISOLATION LEVEL

Cette clause spécifie le niveau d'isolation de la transaction. Les niveaux possibles sont :

SERIALIZABLE
Le niveau d'isolation le plus élevé. Il garantit que les transactions exécutées de manière concurrente produiront des résultats qui seraient possibles si les transactions étaient exécutées les unes après les autres (sérielement).
REPEATABLE READ
Garantit que si une transaction lit des données plusieurs fois, elle verra les mêmes données à chaque fois. Cela empêche les lectures sales et les lectures non répétables.
READ COMMITTED
Garantit que seules les données validées seront lues. Cela empêche les lectures sales.

Si cette clause est omise, le niveau d'isolation par défaut est READ COMMITTED.

READ ONLY | READ WRITE

Cette clause spécifie si la transaction est en lecture seule ou en lecture/écriture. Par défaut, les transactions sont READ WRITE.

Si une transaction est déclarée READ ONLY, elle ne peut pas exécuter de commandes qui modifient des données. Toute commande de ce type entraînera une erreur. Cela peut être utile pour s'assurer qu'une transaction ne modifie pas accidentellement des données. Cela peut également fournir certains avantages en termes de performances, car PostgreSQL peut effectuer des optimisations en sachant qu'aucune donnée ne sera modifiée.

DEFERRABLE | NOT DEFERRABLE

Cette clause spécifie si la transaction est différable. Une transaction différable est une transaction qui peut être retardée jusqu'à ce qu'elle puisse être validée sans causer de conflits avec d'autres transactions.

Cette option n'est significative que pour les transactions SERIALIZABLE. Si la transaction est SERIALIZABLE et DEFERRABLE, la transaction peut être autorisée à continuer même si elle devrait normalement attendre que d'autres transactions se terminent. Cependant, elle peut être annulée plus tard s'il s'avère que la transaction n'aurait pas pu être validée immédiatement.

Par défaut, les transactions sont NOT DEFERRABLE.

NOTES

La commande SET TRANSACTION ne peut être émise qu'au début d'une transaction. Si elle est émise après l'exécution d'autres instructions SQL dans la transaction, une erreur sera signalée.

Les niveaux d'isolation SERIALIZABLE et REPEATABLE READ sont implémentés à l'aide de l'isolation par instantané (snapshot isolation). Cela signifie que la transaction voit un instantané cohérent de la base de données au moment où la transaction a commencé.

Pour plus de détails sur les niveaux d'isolation des transactions et leurs implications, consultez la documentation PostgreSQL.

EXEMPLES

Démarrer une transaction avec le niveau d'isolation SERIALIZABLE :

BEGIN;
SET TRANSACTION ISOLATION LEVEL SERIALIZABLE;
-- Commandes de transaction ici...
COMMIT;

Démarrer une transaction en lecture seule :

BEGIN;
SET TRANSACTION READ ONLY;
-- Commandes de transaction ici...
COMMIT;

Démarrer une transaction différable avec le niveau d'isolation SERIALIZABLE :

BEGIN;
SET TRANSACTION ISOLATION LEVEL SERIALIZABLE DEFERRABLE;
-- Commandes de transaction ici...
COMMIT;

COMPATIBILITÉ

SET TRANSACTION est une extension PostgreSQL. SQL standard prend en charge SET TRANSACTION ISOLATION LEVEL, mais pas les options READ ONLY/WRITE ou DEFERRABLE.
