NOM

Search::Xapian::QueryParser - Analyse une chaîne de requête en un objet Search::Xapian::Query

DESCRIPTION

Ce module transforme une chaîne lisible par l'homme en quelque chose que Xapian peut comprendre. La syntaxe prise en charge est conçue pour être similaire à celle d'autres moteurs de recherche basés sur le web, afin que les utilisateurs qui leur sont familiers n'aient pas à apprendre une syntaxe entièrement nouvelle.

SYNOPSIS

use Search::Xapian qw/:standard/;
my $qp = new Search::Xapian::QueryParser( [$database] );
$qp->set_stemmer(new Search::Xapian::Stem("english"));
$qp->set_default_op(OP_AND);
$database->enquire($qp->parse_query('a NEAR word OR "a phrase" NOT (too difficult) +eh'));

METHODES

new <base_de_données>
Constructeur de QueryParser.
set_stemmer <racineur>
Définit l'objet Search::Xapian::Stem à utiliser pour la racinisation des termes de la requête.
set_stemming_strategy <stratégie>
Définit la stratégie de racinisation. Les valeurs valides sont "STEM_ALL", "STEM_SOME", "STEM_NONE".
set_stopper <exclueur>
Définit l'objet Search::Xapian::Stopper à utiliser pour identifier les mots vides.
set_default_op <opérateur>
Définit l'opérateur par défaut.

Cet opérateur est utilisé pour combiner les éléments de requête qui ne sont pas des filtres lorsque aucun opérateur explicite n'est utilisé.

Les valeurs les plus utiles pour cela sont OP_OR (par défaut) et OP_AND. OP_NEAR et OP_PHRASE peuvent également être utiles.

Voir Search::Xapian pour des descriptions de ces constantes.

get_default_op
Retourne l'opérateur par défaut actuel.
set_database <base_de_données>
Passe un objet Search::Xapian::Database utilisé pour vérifier si les termes existent dans certaines situations.
parse_query <chaîne_requête> [<indicateurs>]
Analyse la chaîne de requête selon les règles définies dans la documentation du parseur de requêtes ci-dessous. Vous pouvez spécifier certains indicateurs pour modifier le comportement de recherche : 
FLAG_BOOLEAN, FLAG_PHRASE, FLAG_LOVEHATE, FLAG_BOOLEAN_ANY_CASE,
FLAG_WILDCARD, FLAG_PURE_NOT, FLAG_PARTIAL, FLAG_SPELLING_CORRECTION,
FLAG_SYNONYM, FLAG_AUTO_SYNONYMS, FLAG_AUTO_MULTIWORD_SYNONYMS

Pour spécifier plusieurs indicateurs, utilisez un « OU bit à bit » (avec "|"). Les indicateurs par défaut sont "FLAG_PHRASE|FLAG_BOOLEAN|FLAG_LOVEHATE"

add_prefix <champ> <préfixe>
Ajoute un préfixe de terme probabiliste. Par exemple, $qp->add_prefix("auteur", "A");

Permet à l'utilisateur de rechercher auteur:orwell, ce qui recherchera le terme "Aorwel" (en supposant que la racinisation anglaise est utilisée). Plusieurs champs peuvent être mappés au même préfixe (vous pouvez donc par exemple faire des alias pour titre: et sujet:).

Paramètres : champ le nom du champ visible par l'utilisateur préfixe le préfixe de terme auquel mapper ce champ.

add_boolean_prefix <champ> préfixe
Ajoute un préfixe de terme booléen permettant à l'utilisateur de restreindre une recherche avec un filtre booléen spécifié dans la requête en texte libre. Par exemple, 
$p->add_boolean_prefix("site", "H");

Permet à l'utilisateur de restreindre une recherche avec site:xapian.org, ce qui sera converti en Hxapian.org combiné avec toute requête probabiliste avec "OP_FILTER".

Plusieurs champs peuvent être mappés au même préfixe (vous pouvez donc par exemple faire des alias pour site: et domaine:).

Paramètres : champ le nom du champ visible par l'utilisateur préfixe le préfixe de terme auquel mapper ce champ.

stoplist_begin
stoplist_end
unstem_begin
unstem_end
get_description
Retourne une chaîne décrivant cet objet.
get_corrected_query_string
Obtient la chaîne de requête avec correction orthographique.

Ceci ne sera défini que si FLAG_SPELLING_CORRECTION est spécifié lorsque QueryParser::parse_query() a été appelé la dernière fois.

S'il n'y a pas eu de corrections, une chaîne vide est retournée.

set_max_wildcard_expansion <limite>
Spécifie l'expansion maximale d'un terme générique.

Remarque : vous devez également définir FLAG_WILDCARD pour que l'expansion des génériques se produise.

Le paramètre limite est le nombre maximum de termes que chaque générique dans la requête peut développer, ou 0 pour aucune limite (ce qui est la valeur par défaut).
