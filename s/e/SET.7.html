NAME

SET - changer un paramètre d'exécution

SYNOPSIS

SET [ SESSION | LOCAL ] paramètre_configuration { = | TO } { valeur | 'valeur' | DEFAULT }
SET [ SESSION | LOCAL ] TIME ZONE { valeur | 'valeur' | LOCAL | DEFAULT }

DESCRIPTION

La commande SET change les paramètres de configuration à l'exécution. Plusieurs des paramètres de configuration décrits au Chapitre 19 peuvent être changés à la volée avec SET. (Certains paramètres ne peuvent être changés que par les superutilisateurs et les utilisateurs qui ont reçu le privilège SET sur ce paramètre. Il y a aussi des paramètres qui ne peuvent pas être changés après le démarrage du serveur ou de la session.) SET n'affecte que la valeur utilisée par la session courante.

Si SET (ou l'équivalent SET SESSION) est exécuté à l'intérieur d'une transaction qui est ensuite annulée, les effets de la commande SET disparaîtront lors de l'annulation de la transaction. Une fois que la transaction englobante est confirmée, les effets persisteront jusqu'à la fin de la session, sauf s'ils sont remplacés par un autre SET.

Les effets de SET LOCAL ne durent que jusqu'à la fin de la transaction, qu'elle soit confirmée ou annulée. Un cas spécial est SET suivi de SET LOCAL au sein d'une seule transaction : la valeur SET LOCAL sera visible jusqu'à la fin de la transaction, mais après (si la transaction est confirmée), la valeur SET s'appliquera.

Les effets de SET ou SET LOCAL sont également annulés lors du retour à un point de sauvegarde antérieur à la commande.

Si SET LOCAL est utilisé à l'intérieur d'une fonction ayant une option SET pour la même variable (voir CREATE FUNCTION (CREATE_FUNCTION(7)), les effets de la commande SET LOCAL disparaîtront à la sortie de la fonction ; c'est-à-dire que la valeur effective au moment où la fonction a été appelée sera restaurée. Cela permet d'utiliser SET LOCAL pour des changements dynamiques ou répétés d'un paramètre à l'intérieur d'une fonction, tout en conservant la commodité de l'option SET pour sauvegarder et restaurer la valeur de l'appelant. Cependant, une commande SET régulière remplace toute option SET de fonction qui aurait été spécifiée ; ses effets persisteront jusqu'à ce qu'elle soit annulée.


Note

Dans les versions PostgreSQL 8.0 à 8.2, les effets de SET LOCAL étaient annulés lors de la libération d'un point de sauvegarde antérieur ou lors de la sortie réussie d'un bloc d'exception PL/pgSQL. Ce comportement a été modifié car il était jugé peu intuitif.

PARAMÈTRES

SESSION

Indique que la commande s'applique à la session courante. (C'est la valeur par défaut si SESSION ou LOCAL n'est pas spécifié).

LOCAL

Indique que la commande s'applique uniquement à la transaction courante. Après COMMIT ou ROLLBACK, le réglage de session redevient effectif. L'exécution de cette commande en dehors d'un bloc transactionnel génère un avertissement et n'a par ailleurs aucun effet.

paramètre_configuration

Nom d'un paramètre de configuration modifiable. Les paramètres disponibles sont documentés au Chapitre 19 et suivants.

valeur

Nouvelle valeur du paramètre. Les valeurs peuvent être spécifiées sous forme de constantes de chaînes, d'identifiants, de nombres ou de listes séparées par des virgules, selon ce qui convient au paramètre. DEFAULT peut être utilisé pour réinitialiser le paramètre à sa valeur par défaut (c'est-à-dire la valeur qu'il aurait si aucun SET n'avait été exécuté dans cette session).

En plus des paramètres de configuration décrits au Chapitre 19, il y en a quelques-uns qui ne peuvent être réglés qu'avec la commande SET ou qui ont un symbole spécial :

SCHEMA

SET SCHEMA 'valeur' est un alias de SET search_path TO valeur. Un seul schéma peut être spécifié avec ce symbole.

NAMES

SET NAMES 'valeur' est un alias de SET client_encoding TO valeur.

SEED

Définit la graine interne du générateur de nombres aléatoires (fonction random). Les valeurs permises sont des nombres flottants compris entre -1 et 1, inclus.

La graine peut également être définie en appelant la fonction setseed :

SELECT setseed(valeur);

TIME ZONE

SET TIME ZONE 'valeur' est un alias de SET timezone TO 'valeur'. La syntaxe SET TIME ZONE permet une syntaxe spéciale pour la spécification des fuseaux horaires. Voici des exemples de valeurs valides :

'America/Los_Angeles'

Fuseau horaire de Berkeley, Californie.

'Europe/Rome'

Fuseau horaire de l'Italie.

-7

Fuseau horaire 7 heures à l'ouest de l'UTC (équivalent à PDT). Les valeurs positives sont orientées vers l'UTC.

'INTERVAL '-08:00' HOUR TO MINUTE'

Fuseau horaire 8 heures à l'ouest de l'UTC (équivalent à PST).

LOCAL

Définit le fuseau horaire sur votre fuseau horaire local (c'est-à-dire la valeur par défaut de l'attribut timezone du serveur).

Les valeurs de fuseau horaire données sous forme de nombres ou d'intervalles sont converties en interne en syntaxe POSIX de fuseau horaire. Par exemple, après SET TIME ZONE -7, SHOW TIME ZONE rapportera <-07>+07.

Les abréviations de fuseaux horaires ne sont pas prises en charge par SET ; voir la section 8.5.3 pour plus d'informations sur les fuseaux horaires.

NOTES

La fonction set_config fournit la même fonctionnalité ; voir la section RESET(7). Il est également possible de mettre à jour la vue pg_settings pour réaliser l'équivalent de SET.

EXEMPLES

Définir le schéma de recherche :

SET search_path TO my_schema, public;

Définir le style de date sur le style traditionnel POSTGRES avec la convention d'entrée 'jour avant mois'

SET datestyle TO postgres, dmy;

Définir le fuseau horaire sur Berkeley, Californie :

SET TIME ZONE 'America/Los_Angeles';

Définir le fuseau horaire sur l'Italie :

SET TIME ZONE 'Europe/Rome';

COMPATIBILITÉ

SET TIME ZONE étend la syntaxe définie dans la norme SQL. La norme ne permet que des valeurs numériques de décalage horaire, tandis que PostgreSQL permet une spécification plus flexible. Tous les autres aspects des fonctionnalités de SET sont des extensions PostgreSQL.
