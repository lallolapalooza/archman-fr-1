NOM

SelfLoader - charge les fonctions uniquement à la demande

SYNOPSIS

package FOOBAR;
use SelfLoader;
... (code d'initialisation)
__DATA__
sub {....

DESCRIPTION

Ce module indique à ses utilisateurs que les fonctions du paquet FOOBAR doivent être chargées à la demande après le jeton "__DATA__". Voir aussi "Autoloading" dans perlsub.

Le jeton __DATA__

Le jeton "__DATA__" indique au compilateur perl que le code perl pour la compilation est terminé. Tout ce qui suit le jeton "__DATA__" est disponible en lecture via le descripteur de fichier FOOBAR::DATA, où FOOBAR est le nom du paquet courant lorsque le jeton "__DATA__" est atteint. Cela fonctionne de la même manière que "__END__" dans le paquet 'main', mais pour d'autres modules, les données après "__END__" ne sont pas automatiquement récupérables, alors que les données après "__DATA__" le sont. Le jeton "__DATA__" n'est pas reconnu dans les versions de perl antérieures à 5.001m.

Notez qu'il est possible d'avoir des jetons "__DATA__" dans le même paquet dans plusieurs fichiers, et que le dernier jeton "__DATA__" dans un paquet donné rencontré par le compilateur est celui accessible par le descripteur de fichier. Cela s'applique également à "__END__" et à main, c'est-à-dire que si le programme 'main' a un "__END__", mais qu'un module 'require'd (_pas_ 'use'd) par ce programme a une déclaration de 'package main;' suivie d'un '"__DATA__"', alors le descripteur de fichier "DATA" est configuré pour accéder aux données après le "__DATA__" dans le module, _pas_ aux données après le jeton "__END__" dans le programme 'main', car le compilateur rencontre le fichier 'require'd plus tard.

Chargement à la demande avec SelfLoader

SelfLoader fonctionne en demandant à l'utilisateur de placer le jeton "__DATA__" après le code perl qui doit être compilé et exécuté au moment du 'require', mais avant les déclarations de sous-programmes qui peuvent être chargées plus tard - généralement parce qu'elles pourraient ne jamais être appelées.

SelfLoader lira à partir du descripteur de fichier FOOBAR::DATA pour charger les données après "__DATA__", et chargera toute sous-routine lorsqu'elle sera appelée. Les coûts sont l'analyse unique des données après "__DATA__", et un délai de chargement pour le _premier_ appel de toute fonction chargée à la demande. Les avantages (espérons-le) sont une phase de compilation accélérée, sans avoir besoin de charger des fonctions jamais utilisées.

SelfLoader cessera de lire à partir de "__DATA__" s'il rencontre le jeton "__END__" - comme on pourrait s'y attendre. Si le jeton "__END__" est présent, et est suivi du jeton DATA, alors SelfLoader laisse le descripteur de fichier FOOBAR::DATA ouvert sur la ligne après ce jeton.

SelfLoader exporte la sous-routine "AUTOLOAD" dans le paquet utilisant SelfLoader, et celle-ci charge la sous-routine appelée lors de son premier appel.

Il n'y a aucun avantage à placer des sous-programmes qui seront _toujours_ appelés après le jeton "__DATA__".

Chargement à la demande et lexicales de paquet

Une instruction 'my $pack_lexical' rend la variable $pack_lexical locale _uniquement_ au fichier jusqu'au jeton "__DATA__". Les sous-programmes déclarés ailleurs _ne peuvent pas_ voir ces types de variables, tout comme si vous déclariez des sous-programmes dans le paquet mais dans un autre fichier, ils ne peuvent pas voir ces variables.

Donc spécifiquement, les fonctions chargées à la demande ne peuvent pas voir les lexicales de paquet (cela s'applique à la fois à SelfLoader et à Autoloader). Le pragma "vars" fournit une alternative à la définition de globales de niveau paquet qui seront visibles par les routines chargées à la demande. Voir la documentation sur vars dans la section des pragmas de perlmod.

SelfLoader et AutoLoader

SelfLoader peut remplacer AutoLoader - changez simplement 'use AutoLoader' en 'use SelfLoader' (bien qu'il soit à noter que SelfLoader exporte la fonction AUTOLOAD - mais si vous avez votre propre AUTOLOAD et utilisez aussi AutoLoader, vous savez probablement ce que vous faites), et le jeton "__END__" en "__DATA__". Vous aurez besoin de la version de perl 5.001m ou ultérieure pour l'utiliser (version 5.001 avec tous les patchs jusqu'au patch m).

Il n'est pas nécessaire d'hériter de SelfLoader.

SelfLoader fonctionne de manière similaire à AutoLoader, mais récupère les sous-programmes après le "__DATA__" au lieu du répertoire 'lib/auto'. Il y a un gain de maintenance à ne pas avoir besoin d'exécuter AutoSplit sur le module lors de l'installation, et un gain d'exécution à ne pas avoir besoin de continuer à ouvrir et fermer des fichiers pour charger des sous-programmes. Il y a une perte d'exécution à devoir analyser le code après le "__DATA__". Les détails de AutoLoader et une autre perspective de ces distinctions se trouvent dans la documentation de ce module.

__DATA__, __END__, et le descripteur de fichier FOOBAR::DATA

Cette section n'est pertinente que si vous souhaitez utiliser "FOOBAR::DATA" avec SelfLoader.

Les données après le jeton "__DATA__" dans un module sont lues en utilisant le descripteur de fichier FOOBAR::DATA. "__END__" peut toujours être utilisé pour marquer la fin de la section "__DATA__" s'il est suivi du jeton DATA - ceci est supporté par SelfLoader. Le descripteur de fichier "FOOBAR::DATA" est laissé ouvert si un "__END__" suivi d'un DATA est trouvé, avec le descripteur de fichier positionné au début de la ligne après le jeton "__END__". Si aucun jeton "__END__" n'est présent, ou un jeton "__END__" sans jeton DATA sur la même ligne, alors le descripteur de fichier est fermé.

SelfLoader lit à partir de la position actuelle du descripteur de fichier "FOOBAR::DATA", jusqu'à EOF ou "__END__". Cela signifie que si vous souhaitez utiliser ce descripteur de fichier (et SEULEMENT si vous le souhaitez), vous devriez soit

1. Placer toutes vos déclarations de sous-programmes immédiatement après le jeton "__DATA__" et placer vos propres données après ces déclarations, en utilisant le jeton "__END__" pour marquer la fin des déclarations de sous-programmes. Vous devez également vous assurer que SelfLoader lit en premier en appelant 'SelfLoader->load_stubs();', ou en utilisant une fonction qui est chargée à la demande ;

ou

2. Vous devriez lire en premier le descripteur de fichier "FOOBAR::DATA", laissant le descripteur ouvert et positionné à la première ligne des déclarations de sous-programmes.

Vous pourriez éventuellement faire les deux.

Classes et méthodes héritées

Pour les modules qui ne sont pas des classes, cette section n'est pas pertinente. Cette section n'est pertinente que si vous avez des méthodes qui pourraient être héritées.

Une ébauche de sous-programme (ou déclaration anticipée) ressemble à

sub stub;

c'est-à-dire une déclaration de sous-programme sans le corps du sous-programme. Pour les modules qui ne sont pas des classes, il n'y a pas de réel besoin d'ébauches en ce qui concerne le chargement à la demande.

Pour les modules QUI SONT des classes, et qui doivent gérer l'hérit

NOM

SelfLoader – charger paresseusement des sous-routines depuis des données

SYNOPSIS

    package MyModule;
    use strict;
    use warnings;

    use SelfLoader;

    # ... initialisation ...

    sub Toplevel::sub { ... }
    sub Another::sub { ... }
    sub YetAnother::sub { ... }

    1; # Must return true value

    __DATA__
    sub Toplevel::sub {
        print "Loaded Toplevel::sub\n";
        return 1;
    }

    sub Another::sub {
        print "Loaded Another::sub\n";
        return 2;
    }

    sub YetAnother::sub {
        print "Loaded YetAnother::sub\n";
        return 3;
    }

DESCRIPTION

Le module SelfLoader permet à un module de charger paresseusement des sous-routines à partir des données d'exécution associées à ce module. Le code de ces sous-routines est placé dans la section "__DATA__" du fichier du module.

Lorsque SelfLoader est utilisé, il intercepte les appels aux sous-routines qui n'existent pas encore dans le package. Il recherche alors une définition de cette sous-routine dans la section "__DATA__". Si elle est trouvée, elle est chargée dans le package et le code original est exécuté.

Pour que le mécanisme d'héritage des méthodes fonctionne correctement, en particulier avec les méthodes qui seront chargées à partir de la section "__DATA__", des stubs sont nécessaires. Vous pouvez charger les stubs dans le module au moment du "require" en ajoutant l'instruction "SelfLoader->load_stubs();" au module pour ce faire.

L'alternative est de placer les stubs avant le jeton "__DATA__" AVANT de publier le module, et à cette fin le module "Devel::SelfStubber" est disponible. Cependant, cela nécessite l'étape supplémentaire de s'assurer que les stubs sont présents dans le module. Si cela est fait, je recommande fortement que cela soit fait AVANT de publier le module – cela ne devrait généralement PAS être fait au moment de l'installation.

Packages multiples et noms de sous-routines entièrement qualifiés

Les sous-routines dans plusieurs packages du même fichier sont supportées – mais vous devez noter que cela nécessite l'exportation de "SelfLoader::AUTOLOAD" vers chaque package qui en a besoin. Ceci est fait automatiquement par SelfLoader lorsqu'il charge d'abord les subs dans le cache, mais vous devriez vraiment le spécifier dans l'initialisation avant "__DATA__" en plaçant une instruction "use SelfLoader" dans chaque package.

Les noms de sous-routines entièrement qualifiés sont également supportés. Par exemple,

__DATA__
sub foo::bar {23}
package baz;
sub dob {32}

seront tous correctement chargés par SelfLoader, et SelfLoader s'assurera que les packages 'foo' et 'baz' ont correctement la méthode "AUTOLOAD" de SelfLoader lorsque les données après "__DATA__" sont d'abord analysées.
