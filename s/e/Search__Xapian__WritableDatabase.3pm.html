NOM

Search::Xapian::WritableDatabase - objet de base de données inscriptible

DESCRIPTION

Cette classe représente une base de données Xapian pour l'indexation. C'est une sous-classe de Search::Xapian::Database, qui est utilisée pour la recherche.

MÉTHODES

new <database> ou new <chemin> <mode>
Constructeur de classe. Prend soit un objet de base de données, soit un chemin et l'un des modes DB_OPEN, DB_CREATE, DB_CREATE_OR_OPEN ou DB_CREATE_OR_OVERWRITE. Ceux-ci sont exportés par Search::Xapian avec l'option 'db'.
clone
Retourne un clone de cette classe.
flush
Écrit sur disque toutes les modifications apportées à la base de données.

Pour des raisons d'efficacité, lors de l'exécution de plusieurs mises à jour sur une base de données, il est préférable (voire essentiel) d'effectuer autant de modifications que la mémoire le permet en un seul passage dans la base de données. Pour garantir cela, Xapian regroupe les modifications.

Flush peut être appelée à tout moment pour s'assurer que les modifications effectuées ont été écrites sur disque : si la vidange réussit, toutes les modifications précédentes auront été écrites sur disque.

Si l'une des modifications échoue, une exception sera levée et la base de données restera dans un état où chaque opération d'ajout, de remplacement ou de suppression aura été entièrement effectuée ou non effectuée du tout : il appartiendra alors à l'application de déterminer quelles opérations doivent être répétées.

Attention à ne pas appeler flush trop fréquemment : cela aura un coût de performance sévère.

Notez que flush n'a pas besoin d'être appelé explicitement : il sera appelé automatiquement lorsque la base de données sera fermée, ou lorsqu'un nombre suffisant de modifications auront été effectuées.

add_document <document>
Ajoute un nouveau document à la base de données.

Cette méthode ajoute le document spécifié à la base de données, retournant un nouvel identifiant de document alloué.

Notez que cela ne signifie pas que le document apparaîtra immédiatement dans la base de données ; voir flush() pour plus de détails.

Comme pour toutes les opérations de modification de base de données, l'effet est atomique : le document sera soit entièrement ajouté, soit l'ajout du document échouera et une exception sera levée (éventuellement plus tard, lors de l'appel à flush ou lors de la fermeture de la base de données).

delete_document <id_doc>
Supprime un document de la base de données. Cette méthode supprime le document avec l'identifiant de document spécifié de la base de données.

Notez que cela ne signifie pas que le document disparaîtra immédiatement de la base de données ; voir flush() pour plus de détails.

Comme pour toutes les opérations de modification de base de données, l'effet est atomique : le document sera soit entièrement supprimé, soit la suppression du document échouera et une exception sera levée (éventuellement plus tard, lors de l'appel à flush ou lors de la fermeture de la base de données).

delete_document_by_term <terme>
Supprime de la base de données tous les documents indexés par un terme. Cette méthode supprime de la base de données tous les documents indexés par le terme spécifié.

L'utilisation prévue est de permettre de mapper facilement des UID d'un autre système à des termes dans Xapian, bien que cette méthode ait probablement d'autres utilisations.

replace_document <id_doc> <document>
Remplace un document donné dans la base de données.

Cette méthode remplace le document avec l'identifiant de document spécifié. Notez que cela ne signifie pas que le document sera immédiatement modifié dans la base de données ; voir flush() pour plus de détails.

Comme pour toutes les opérations de modification de base de données, l'effet est atomique : le document sera soit entièrement remplacé, soit le remplacement du document échouera et une exception sera levée (éventuellement plus tard, lors de l'appel à flush ou lors de la fermeture de la base de données).

replace_document_by_term <terme_unique> <document>
Remplace tous les documents correspondant à un terme unique.

Cette méthode remplace tous les documents indexés par le terme spécifié par le document spécifié. Si des documents sont indexés par le terme, le plus petit ID de document sera utilisé pour le document, sinon un nouvel ID de document sera généré comme pour add_document.

L'utilisation prévue est de permettre de mapper facilement des UID d'un autre système à des termes dans Xapian, bien que cette méthode ait probablement d'autres utilisations.

Notez que cela ne signifie pas que le(s) document(s) sera/seront immédiatement modifié(s) dans la base de données ; voir flush() pour plus de détails.

Comme pour toutes les opérations de modification de base de données, l'effet est atomique : le(s) document(s) sera/seront soit entièrement remplacé(s), soit le(s) document(s) échouera/échoueront à être remplacé(s) et une exception sera levée (éventuellement plus tard, lors de l'appel à flush ou lors de la fermeture de la base de données).

add_spelling <mot> <freqinc>
Ajoute un mot au dictionnaire d'orthographe.

Si le mot est déjà présent, sa fréquence est augmentée.

Paramètres :
mot Le mot à ajouter.
freqinc De combien augmenter sa fréquence (par défaut 1).

remove_spelling <mot> <freqdec>
Supprime un mot du dictionnaire d'orthographe.

La fréquence du mot est diminuée, et s'il devient nulle ou inférieure, le mot est complètement supprimé.

Paramètres :
mot Le mot à supprimer.
freqdec De combien diminuer sa fréquence (par défaut 1).

reopen
Rouvre la base de données pour s'assurer que vous utilisez la dernière révision.
close
Ferme la base de données. Cela implique également un commit() sauf si une transaction est en cours.
