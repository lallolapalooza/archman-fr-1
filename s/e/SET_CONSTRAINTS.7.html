SET CONSTRAINTS(7) Documentation PostgreSQL 18.1 SET CONSTRAINTS(7)

NOM

SET CONSTRAINTS - définir le moment de vérification des contraintes pour la transaction courante

SYNTAXE

SET CONSTRAINTS { ALL | nom [, ...] } { DEFERRED | IMMEDIATE }

DESCRIPTION

SET CONSTRAINTS définit le comportement de la vérification des contraintes au sein de la transaction courante. Les contraintes IMMEDIATE sont vérifiées à la fin de chaque instruction. Les contraintes DEFERRED ne sont vérifiées qu'au moment de la validation de la transaction. Chaque contrainte a son propre mode IMMEDIATE ou DEFERRED.

Lors de sa création, une contrainte reçoit l'une des trois caractéristiques suivantes : DEFERRABLE INITIALLY DEFERRED, DEFERRABLE INITIALLY IMMEDIATE, ou NOT DEFERRABLE. La troisième catégorie est toujours IMMEDIATE et n'est pas affectée par la commande SET CONSTRAINTS. Les deux premières catégories débutent chaque transaction dans le mode indiqué, mais leur comportement peut être modifié au sein d'une transaction par SET CONSTRAINTS.

SET CONSTRAINTS avec une liste de noms de contraintes modifie le mode de ces contraintes uniquement (qui doivent toutes être déferrables). Chaque nom de contrainte peut être qualifié par un schéma. Le chemin de recherche des schémas courant est utilisé pour trouver le premier nom correspondant si aucun nom de schéma n'est spécifié. SET CONSTRAINTS ALL modifie le mode de toutes les contraintes déferrables.

Lorsque SET CONSTRAINTS modifie le mode d'une contrainte de DEFERRED à IMMEDIATE, le nouveau mode prend effet rétroactivement : toute modification de données en attente qui aurait dû être vérifiée à la fin de la transaction est plutôt vérifiée pendant l'exécution de la commande SET CONSTRAINTS. Si une telle contrainte est violée, SET CONSTRAINTS échoue (et ne modifie pas le mode de la contrainte). Ainsi, SET CONSTRAINTS peut être utilisé pour forcer la vérification des contraintes à un moment précis d'une transaction.

Actuellement, seules les contraintes UNIQUE, PRIMARY KEY, REFERENCES (clé étrangère) et EXCLUDE sont affectées par ce réglage. Les contraintes NOT NULL et CHECK sont toujours vérifiées immédiatement lors de l'insertion ou de la modification d'une ligne (pas à la fin de l'instruction). Les contraintes d'unicité et d'exclusion qui n'ont pas été déclarées DEFERRABLE sont également vérifiées immédiatement.

L'exécution des déclencheurs (triggers) déclarés comme « déclencheurs de contrainte » est également contrôlée par ce réglage — ils s'exécutent au même moment où la contrainte associée devrait être vérifiée.

NOTES

Puisque PostgreSQL n'exige pas que les noms de contraintes soient uniques au sein d'un schéma (mais seulement par table), il est possible qu'il y ait plus d'une correspondance pour un nom de contrainte spécifié. Dans ce cas, SET CONSTRAINTS agira sur toutes les correspondances. Pour un nom non qualifié par un schéma, une fois qu'une ou plusieurs correspondances ont été trouvées dans un schéma du chemin de recherche, les schémas apparaissant plus tard dans le chemin ne sont pas recherchés.

Cette commande modifie uniquement le comportement des contraintes au sein de la transaction courante. L'émission de cette commande en dehors d'un bloc de transaction émet un avertissement et n'a aucun autre effet.

COMPATIBILITÉ

Cette commande est conforme au comportement défini dans la norme SQL, à l'exception de la limitation selon laquelle, dans PostgreSQL, elle ne s'applique pas aux contraintes NOT NULL et CHECK. De plus, PostgreSQL vérifie immédiatement les contraintes d'unicité non déferrables, et non à la fin de l'instruction comme le suggérerait la norme.
