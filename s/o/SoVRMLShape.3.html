Description Détaillée

La classe SoVRMLShape contient les noeuds de géométrie et d'apparence de la géométrie.

La documentation détaillée de la classe est prise verbatim de la norme VRML97 (ISO/IEC 14772-1:1997). Elle est la propriété du Web3D Consortium et est utilisée avec la permission du Consortium :

Shape {
  exposedField SFNode appearance NULL
  exposedField SFNode geometry   NULL
}

Le noeud Shape a deux champs, appearance et geometry, qui sont utilisés pour créer des objets rendus dans le monde. Le champ appearance contient un noeud SoVRMLAppearance qui spécifie les propriétés visuelles (par exemple, le matériau et la texture) appliquées à la géométrie. Le champ geometry contient un noeud de géométrie. Le noeud de géométrie spécifié est rendu avec les noeuds d'apparence spécifiés. Voir 4.6.3, Shapes et géométrie (http://www.web3d.org/documents/specifications/14772/V2.0/part1/concepts.html#4.6.3), et SoVRMLAppearance, pour plus d'informations.

4.14, Modèle d'éclairage (http://www.web3d.org/documents/specifications/14772/V2.0/part1/concepts.html#4.14), contient des détails sur le modèle d'éclairage VRML et l'interaction entre les noeuds d'apparence et les noeuds de géométrie. Si le champ de géométrie est NULL, l'objet n'est pas dessiné.

SbBool SoVRMLShape::affectsState (void ) const [virtual]

Renvoie TRUE si le noeud pourrait avoir un effet sur l'état pendant la navigation.

Si elle renvoie FALSE, aucune donnée de l'état de navigation ne changera entre l'état avant la navigation et l'état après la navigation. Le noeud SoSeparator renverra FALSE, car il pousse et dépile l'état avant et après la navigation de ses enfants. Tous les noeuds SoShape renverront également FALSE, car seules les données de géométrie sont affichées avant le rendu, ce qui n'affecte pas l'état de rendu réel.

La méthode par défaut renvoie TRUE, basée sur le principe "mieux vaut prévenir que guérir".

Detailed Description

The VRML Shape node defines a geometrical object. A shape node is a grouping node that holds a geometry node and an appearance node. The geometry node defines the geometric primitive(s) of the shape, and the appearance node defines the material properties (color, texture, etc.) of the shape.

A shape node must have a geometry node. The appearance node is optional. If it is NULL, then the default appearance (a white, opaque material with no texture) is used.

The nodes are referenced by the geometry and appearance fields.

The renderCaching and boundingBoxCaching fields control the render caching strategy for the node.

Note that if the geometry or appearance fields are set to NULL, the node will not be rendered.

The actual geometry is defined by an SoVRMLGeometry node, and the appearance by an SoVRMLAppearance node.

void SoVRMLShape::copyContents (const SoFieldContainer * from, SbBool copyconnections) [virtual]

Makes a deep copy of all data of from into this instance, except external scene graph references if copyconnections is FALSE.

This is the method that should be overridden by extension node / engine / dragger / whatever subclasses which need to account for internal data that are not handled automatically.

For copying nodes from application code, you should not invoke this function directly, but rather call the SoNode::copy() function:

SoNode * mynewnode = templatenode->copy();

The same also goes for engines.

Make sure that when you override the copyContents() method in your extension class that you also make it call upwards to its parent superclass in the inheritance hierarchy, as copyContents() in for instance SoNode and SoFieldContainer does important work. It should go something like this:

void
MyCoinExtensionNode::copyContents(const SoFieldContainer * from,
                                  SbBool copyconnections)
{
  // let parent superclasses do their thing (copy fields, copy
  // instance name, etc.)
  SoNode::copyContents(from, copyconnections);
  // [..then copy internal data..]
}

Reimplemented from SoNode.
