Description Détaillée

La classe SoVRMLAppearance spécifie les propriétés visuelles des formes.

La documentation détaillée de la classe est extraite mot pour mot de la norme VRML97 (ISO/IEC 14772-1:1997). Elle est protégée par le droit d'auteur du Web3D Consortium et est utilisée avec la permission du Consortium :

Appearance {
  exposedField SFNode material          NULL
  exposedField SFNode texture           NULL
  exposedField SFNode textureTransform  NULL
}

Le nœud Appearance spécifie les propriétés visuelles de la géométrie. La valeur de chacun des champs de ce nœud peut être NULL. Cependant, si le champ n'est pas NULL, il doit contenir un nœud du type approprié. Le champ material, s'il est spécifié, doit contenir un nœud VRMLMaterial. Si le champ material est NULL ou non spécifié, l'éclairage est désactivé (toutes les lumières sont ignorées lors du rendu de l'objet qui référence cette Appearance) et la couleur de l'objet non éclairé est (1, 1, 1). Les détails du modèle d'éclairage VRML se trouvent dans 4.14, Modèle d'éclairage (http://www.web3d.org/documents/specifications/14772/V2.0/part1/concepts.html#4.14).

Le champ texture, s'il est spécifié, doit contenir un des différents types de nœuds de texture (VRMLImageTexture, VRMLMovieTexture, ou VRMLPixelTexture). Si le nœud texture est NULL ou si le champ texture n'est pas spécifié, l'objet qui référence cette Appearance n'est pas texturé. Le champ textureTransform, s'il est spécifié, doit contenir un nœud VRMLTextureTransform. Si textureTransform est NULL ou non spécifié, le champ textureTransform n'a aucun effet.

void SoVRMLAppearance::copyContents (const SoFieldContainer * from, SbBool copyconnections) [virtual]

Realiza una copia profunda de todos los datos de from en esta instancia, excepto las referencias externas al grafo de escena si copyconnections es FALSE.

Este es el método que deben sobrescribir las subclases de nodo de extensión / motor / dragger / lo que sea que necesiten tener en cuenta los datos internos que no se manejan automáticamente.

Para copiar nodos desde código de aplicación, no debes invocar esta función directamente, sino llamar a la función SoNode::copy():

SoNode * mynewnode = templatenode->copy();

Lo mismo se aplica a los motores.

Asegúrate de que cuando sobrescribas el método copyContents() en tu clase de extensión, también llames a su superclase principal en la jerarquía de herencia, ya que copyContents() en, por ejemplo, SoNode y SoFieldContainer realiza un trabajo importante. Debería ser algo así:

void
MyCoinExtensionNode::copyContents(const SoFieldContainer * from,
                                  SbBool copyconnections)
{
  // deja que las superclases principales hagan lo suyo (copiar campos, copiar
  // nombre de instancia, etc.)
  SoNode::copyContents(from, copyconnections);
  // [..luego copia los datos internos..]
}
