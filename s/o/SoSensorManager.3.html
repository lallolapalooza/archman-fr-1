Description détaillée

La classe SoSensorManager gère les files d'attente de capteurs.

Il existe deux types principaux de capteurs dans Coin, les « capteurs à délai » et les « capteurs de temporisation » :

•
Les capteurs à délai sont déclenchés lorsque l'application est sinon inactive. De plus, afin d'éviter une stagnation dans les applications constamment occupées, la file d'attente des capteurs à délai possède également un délai d'attente qui, une fois atteint, vide la file d'attente automatiquement.
•
Les capteurs de temporisation sont configurés pour être déclenchés à des moments absolus spécifiques.

Chacun de ces deux types a sa propre file d'attente, gérée par SoSensorManager. Les files d'attente sont maintenues triées selon l'heure de déclenchement (SoSensorManager) ou selon la priorité (SoSensorManager).

La mécanique des capteurs est cruciale dans Coin pour un certain nombre de fonctions importantes, notamment le reprogrammage de la mise à jour de la vue lors d'un changement d'état, et pour permettre la définition d'animations dans la hiérarchie des scènes qui ne nécessitent aucune gestion de la part du code de l'application.

La classe SoSensorManager doit généralement être considérée comme une classe interne à l'API de Coin. Elle n'intéresse que les développeurs d'applications lors de l'implémentation de nouvelles bibliothèques spécifiques au système de fenêtrage (comme SoQt, SoXt, SoGtk, SoWin ou Sc21 de Kongsberg Oil & Gas Technologies) ou des wrappers. Dans ce cas, le code doit être configuré pour vider les files d'attente aux bons intervalles. Pour des informations détaillées sur la manière de procéder, il est recommandé de consulter l'implémentation de ces mécanismes dans les bibliothèques So*-de SIM.

Note : Avant Coin 2.3.1, les capteurs de priorité égale (ou avec la même heure de déclenchement pour les capteurs de type SoTimerQueue) étaient traités dans l'ordre inverse. Cela a été changé en FIFO pour être conforme à SGI Inventor.

void SoSensorManager::processDelayQueue (SbBool isidle)

Déclencher tous les enregistrements de la file d'attente des capteurs à délai par ordre de priorité.

Le paramètre isidle indique si le traitement a été effectué parce que l'application était inactive ou parce que le délai d'attente de la file d'attente des capteurs à délai a été atteint.

Un capteur à délai avec une priorité supérieure à 0 ne peut être déclenché qu'une seule fois lors d'un appel à cette fonction. Si un capteur à délai se reprograme pendant processDelayQueue(), il ne sera pas traité tant que cette fonction n'aura pas été appelée à nouveau. Ceci est fait pour éviter un cercle infini lors du traitement des capteurs.

Un capteur à délai avec une priorité de 0 est appelé un capteur immédiat.

void SoSensorManager::setDelaySensorTimeout (const SbTime & t)

Les capteurs de délai ne sont généralement déclenchés que lorsque le système est inactif. Mais lorsqu'il y a des mises à jour continues du graphe de scène, il est possible que la file d'attente de délai se vide et que les capteurs ne soient jamais déclenchés. Pour s'assurer que cela ne se produise pas, il s'agit d'une valeur de délai d'expiration pour la file d'attente de délai. Lorsque ce délai d'expiration est atteint, les capteurs de la file d'attente de délai sont traités avant les autres capteurs et événements. Cette méthode permet à l'utilisateur de définir cette valeur de délai d'expiration.

La valeur par défaut est 1/12 de seconde.

Spécifier un temps nul désactive le délai d'expiration, ouvrant la voie à une potentielle famine de la file d'attente de délai.

NOTE : CETTE MÉTHODE EST OBSOLÈTE. NE L'UTILISEZ PAS.

Il s'agit d'un wrapper autour de l'appel standard select(2), qui s'assurera que les files d'attente de capteurs sont mises à jour pendant l'attente de toute action sur les descripteurs de fichiers donnés.

Les arguments void* doivent être des pointeurs valides vers des structures fd_set. Nous avons modifié cela par rapport à l'API d'origine de SGI Inventor afin d'éviter de mélanger le fichier d'en-tête avec des inclusions spécifiques au système.
