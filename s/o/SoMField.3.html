Description détaillée

La classe SoMField est la classe de base pour les champs pouvant contenir plusieurs valeurs.

Tous les types de champs pouvant contenir plus d'une valeur héritent de cette classe. SoMField est une classe abstraite.

Utilisez setValue(), setValues() ou set1Value() pour définir les valeurs des champs héritant de SoMField, et utilisez getValues() ou l'opérateur d'indexation [] pour lire les valeurs. Exemple de code :

SoText2 * textnode = new SoText2;
textnode->ref();
// Définition des valeurs multi-champs. /////////////////////////////
// Définit la première valeur du champ SoMFString du nœud SoText2.
// Le tableau de champ sera tronqué pour ne contenir que cette valeur unique.
textnode->string.setValue("Morten");
// Contenu complet du SoMFString : [ "Morten" ]
// La méthode setValue() et l'opérateur = sont interchangeables,
// cette ligne de code fait la même chose que la ligne précédente.
textnode->string = "Peder";
// Contenu complet du SoMFString maintenant : [ "Peder" ]
// Définit la valeur à l'index 2. Si le tableau de valeurs du champ contenait
// moins de 3 éléments avant cet appel, il sera d'abord étendu pour contenir
// 3 éléments.
textnode->string.set1Value(2, "Lars");
// Contenu complet du SoMFString : [ "Peder", <non défini>, "Lars" ]
// Ceci définit 3 valeurs du tableau, en commençant à l'index 5. Si le
// conteneur de tableau avait moins de 8 éléments avant l'appel setValues(),
// le tableau sera d'abord étendu.
SbString s[3] = { "Eriksen", "Blekken", "Aas" };
textnode->string.setValues(5, sizeof(s) / sizeof(s[0]), s);
// Contenu complet du SoMFString maintenant :
//     [ "Peder", <non défini>, "Lars", <non défini>, <non défini>,
//       "Eriksen", "Blekken", "Aas" ]
// Notez également que l'appel setValues()

Manejo de campos multivalor

Los campos multivalor (como por ejemplo un SoMFString o un SoMFNode) pueden contener un número arbitrario de valores. Para manejar estos campos, se utilizan las siguientes convenciones:

Para establecer un nuevo conjunto de valores para un campo multivalor, se usa el método setValues().

SbString n[4] = { "Dixon", "Adams", "Bould", "Winterburn" };
textnode->string.setValues(0, sizeof(n) / sizeof(n[0]), n);
// Contenido completo de SoMFString es ahora:
//     [ "Dixon", "Adams", "Bould", "Winterburn", <undefined>,
//       "Eriksen", "Blekken", "Aas" ]

Observando los valores de campo múltiple. //////////////////////////

Esto leerá el segundo elemento (contando desde cero) del campo multivalor y lo colocará en "val".

SbString val = textnode->string[2];

Esto nos da un puntero al array que el campo de valores múltiples está utilizando para almacenar los valores. Tenga en cuenta que el valor de retorno es "const", por lo que solo puede leer del array, no escribir en él.

const SbString * vals = textnode->string.getValues(0);

Modificación de valores de campo múltiple. ///////////////////////////

Por supuesto, puede modificar los valores de campos múltiples utilizando los métodos set- y get- que se mostraron anteriormente, pero cuando trabaje con grandes conjuntos de datos, esto será ineficaz. Use esta técnica en su lugar:

SbString * modvals = textnode->string.startEditing();
// ... muchas modificaciones en el array "modvals" aquí ...
// Llamar al método finishEditing() es necesario para que el
// gráfico de escena se actualice (y se vuelva a renderizar).
textnode->string.finishEditing();

La razón por la que es más eficaz agrupar muchas modificaciones dentro de startEditing() / finishEditing() es porque evitamos la corriente de mensajes de notificación que de otro modo se enviarían por cada modificación realizada. En su lugar, solo habrá una notificación sobre los cambios, desencadenada por la llamada a finishEditing().

La forma correcta de preasignar un número específico de valores de campo en un solo bloque es usar el método SoMField::setNum(), por ejemplo, antes de usar los métodos startEditing() y finishEditing(). Los valores del campo no estarán inicializados después de expandir el campo con la llamada setNum().

Tenga en cuenta que el código de su aplicación debe tener cuidado de no hacer cosas tontas durante una notificación activada por setValues(). Si tiene código que se parece, por ejemplo, a esto:

// actualizar el conjunto de índices de coordenadas al principio de, por ejemplo,
// el campo coordIndex de un SoIndexedFaceSet...
ifs->coordIndex.setValues(0, runner->numIndices, runner->indices);
// ..luego truncar para asegurarse de que tenga el tamaño correcto.
ifs->coordIndex.setNum(runner->numIndices);

Dado que setValues() puede dejar algunos elementos al final del array que típicamente pueden ser índices no válidos después de que se ejecuta la primera declaración, algo puede salir mal durante la notificación si tiene código de aplicación monitoreando cambios, y el código de aplicación luego, por ejemplo, desencadena una acción o algo que intenta usar el campo coordIndex antes de que se actualice a su tamaño correcto con la llamada setNum().

(La notificación puede en este caso, como siempre, ser temporalmente deshabilitada para estar seguro:

somefield.enableNotify(FALSE);
somefield.setValues(...);
somefield.setNum(...);
somefield.enableNotify(TRUE);
somefield.touch();

Esto garantizará que el par setValues() y setNum() se ejecutará como una operación atómica.)

Cuando los nodos, motores u otros tipos de contenedores de campo se escriben en un archivo, sus campos de valores múltiples se escriben en el siguiente formato:

containerclass {
  fieldname [ value0, value1, value2, ...]
  ...
}

..así, por ejemplo, un nodo Coordinate3 que proporciona 6 coordenadas de vértice en forma de valores SbVec3f en su campo "point" para, por ejemplo, un faceset, lineset o pointset:

Coordinate3 {
   point [
      -1 1 0, -1 -1 0, 1 -1 0,
      0 2 -1, -2 0 -1, 0 -2 -1,
   ]
}

Algunos campos admiten el intercambio de datos de la aplicación a través de un método setValuesPointer(). setValuesPointer() hace posible establecer el puntero de datos directamente en el campo. Normalmente (cuando se usa setValues()), Coin hace una copia de sus datos, por lo que este método puede ser muy útil si su aplicación necesita los datos internamente y solo está utilizando Coin para la visualización. Código de ejemplo:

myapp->calculateCoordinates(SOME_LARGE_VALUE);
SbVec3f * mycoords = myapp->getCoordinates();
SoCoordinate3 * mynode = myapp->getCoordinateNode();
mynode->point.setValuesPointer(SOME_LARGE_VALUE, mycoords);

Tenga en cuenta que su campo debe ser de solo lectura cuando establezca los datos de esta manera. Si escribe en el campo, los valores en el array de su aplicación se sobrescribirán. Si agrega valores al campo, se asignará un nuevo array y los datos se copiarán en él antes de agregar los nuevos valores. El puntero del array se descartará entonces.

Tenga en cuenta también que cada vez que cambie algún valor en el array, debe notificar manualmente a Coin llamando a SoField::touch(). Para nuestro ejemplo:

SbVec3f * mycoords = myapp->getCoordinate();
myapp->updateCoordinate(mycoords);
SoCoordinate3 * mynode = myapp->getCoordinateNode();
mynode->point.touch(); // esto notificará a Coin que el campo ha cambiado

Puede usar SoMField::enableDeleteValues() para hacer que Coin elimine el array por usted cuando el campo sea destruido o el puntero del array sea descartado porque ya no se necesita (por ejemplo, cuando se cambia el tamaño del array). El array se eliminará utilizando el operador C++ delete[], por lo que si lo usa, su array debe ser asignado utilizando el operador C++ new[].

SoMField::enableDeleteValues() solo se admite para ser compatible con versiones posteriores de TGS Inventor y no recomendamos su uso. Puede tener resultados indefinidos en la plataforma Microsoft Windows. Asignar memoria en la aplicación y destruirla en una DLL puede ser algo malo, causando fallos misteriosos, si no tiene mucho cuidado con cómo su aplicación y las DLL se enlazan con la biblioteca C subyacente.

void SoMField::setNum(const int numarg)

Establece el número de valores a num.

Si el número actual de valores es mayor que num, el array de valores se truncará desde el final. Pero si num es mayor, el array se expandirá automáticamente (y se establecerán valores aleatorios para los nuevos elementos del array).

void SoMField::deleteValues(int start, int numarg = -1) [virtual]

Elimina elementos de valor desde el índice start hasta e incluyendo el índice start + num - 1.

Los elementos con índices mayores que el último elemento eliminado se moverán hacia abajo en el array de valores.

Si num es igual a -1, eliminar desde el índice start hasta el final del array.

Reimplementado en SoMFEngine, SoMFNode y SoMFPath.

void SoMField::insertSpace(int start, int numarg) [virtual]

Inserta num "espacios" para nuevos elementos de valor a partir de start. Los elementos ya presentes desde start se moverán "hacia arriba" en el array extendido.

Reimplementado en SoMFEngine, SoMFNode y SoMFPath.

SbBool SoMField::set1(const int index, const char *const valuestring)

void SoMField::enableDeleteValues(void) [virtual]

Se puede usar para hacer que Coin elimine el puntero del array establecido a través de una llamada a setValuesPointer(). Consulte la documentación de SoMField para obtener información sobre la función setValuesPointer().
