Description Détaillée

La classe SoNurbsCurve est un nœud pour représenter des courbes lisses.

Une explication générale des NURBS dépasse le cadre de la documentation de Coin. Pour des informations détaillées, référez-vous à la littérature spécialisée sur le sujet (par exemple, "An Introduction to NURBS: With Historical Perspective" par David F. Rogers). Un aperçu de base du rendu de courbes et surfaces utilisant les NURBS se trouve dans le chapitre 8 de "The Inventor Mentor".

Notez que les valeurs de nœuds doivent être spécifiées comme [0, 1, 2,..., a] plutôt que [0, 1/a, 2/a,..., 1] pour éviter les erreurs de tessellation dues à des problèmes de précision en virgule flottante. (Même si la courbe rendue *semble* correcte, de tels problèmes pourraient survenir lors, par exemple, du picking, car la représentation tessellée utilisée en interne n'est pas la même que celle que vous voyez rendue par OpenGL à l'écran.)

Chaque point de contrôle a un poids qui modifie la forme de sa fonction de base. Le poids est analogue à avoir des aimants tirant sur la courbe. Coordinate3 définit les points de contrôle avec un poids égal de 1.0 (non rationnel). Utilisez Coordinate4 pour spécifier les valeurs x, y, z et le poids (rationnel).

Un petit exemple d'utilisation (dessiner un cercle en utilisant une courbe rationnelle) :

#Inventor V2.1 ascii
Coordinate4 {
   point [
     0.0 -5.0     0.0 1.0,
     2.5 -2.5     0.0 0.5,
     2.5 -0.66987 0.0 1.0,
     0.0  1.94013 0.0 0.5,
    -2.5 -0.66987 0.0 1.0,
    -2.5 -2.5     0.0 0.5,
     0.0 -5.0     0.0 1.0
   ]
}
NurbsCurve {
   numControlPoints 7
   knotVector [ 0, 0, 0, 1, 1, 2, 2, 3, 3, 3 ]
}
# debug: show all the control points
BaseColor { rgb 1 1 0 }
DrawStyle { pointSize 3 }
PointSet { numPoints 7 }

FORMAT DE FICHIER/VALEURS PAR DÉFAUT :

NurbsCurve {
    numControlPoints 0
    knotVector 0
}

void SoNurbsCurve::generatePrimitives (SoAction * action) [protected], [virtual]

La méthode implémente le comportement d'action pour les nœuds de forme pour SoCallbackAction. Elle est invoquée depuis SoShape::callback(). (Les sous-classes ne doivent pas réimplémenter SoNode::callback().)

Les implémentations de sous-classes utilisent les méthodes de commodité SoShape::beginShape(), SoShape::shapeVertex() et SoShape::endShape(), avec des instances de SoDetail, pour passer les primitives qui forment la forme à l'appelant.

SoDetail * SoNurbsCurve::createLineSegmentDetail (SoRayPickAction * action, const SoPrimitiveVertex * v1, const SoPrimitiveVertex * v2, SoPickedPoint * pp) [protected], [virtual]

Crée un détail de ligne pour un SoPickedPoint. Cette méthode n'est appelée qu'en interne lorsque generatePrimitives() est utilisé pour la sélection (SoShape::rayPick() n'est pas réimplémenté).

Cette méthode retourne NULL dans Open Inventor, et les sous-classes doivent la réimplémenter pour créer des détails pour un SoPickedPoint.

Ce n'est pas nécessaire avec Coin. En fait, si vous choisissez de la réimplémenter, elle fonctionnera de la même manière qu'Open Inventor.

Pour qu'elle fonctionne, vous devez fournir un polygone ou un détail de ligne lorsque vous générez des primitives. Si vous fournissez NULL pour l'argument de détail dans SoShape::beginShape(), vous devrez réimplémenter cette méthode.
