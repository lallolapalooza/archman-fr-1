Description détaillée

La classe SoGLImage est utilisée pour gérer les textures OpenGL 2D/3D.

Un certain nombre de variables d'environnement peuvent être définies pour contrôler la création des textures. Ceci est utile pour ajuster Coin à votre système. Par exemple, si vous utilisez un ordinateur portable, il peut être judicieux de désactiver le filtrage linéaire et les mipmaps.

•
COIN_TEX2_LINEAR_LIMIT : Le filtrage linéaire est activé si Complexity::textureQuality est supérieur ou égal à cette valeur. La valeur par défaut est 0.2.
•
COIN_TEX2_MIPMAP_LIMIT : Les mipmaps sont créés si textureQuality est supérieur ou égal à cette valeur. La valeur par défaut est 0.5.
•
COIN_TEX2_LINEAR_MIPMAP_LIMIT : Le filtrage linéaire entre les niveaux de mipmap est activé si textureQuality est supérieur ou égal à cette valeur. La valeur par défaut est 0.8.
•
COIN_TEX2_SCALEUP_LIMIT : Les textures dont la largeur ou la hauteur ne sont pas des puissances de deux seront toujours mises à l'échelle si textureQuality est supérieur ou égal à cette valeur. La valeur par défaut est 0.7. Si textureQuality est inférieur à cette valeur, et que la largeur ou la hauteur est supérieure à 256 pixels, la texture n'est mise à l'échelle que si elle est relativement proche de la taille de puissance de deux suivante. Cela pourrait économiser beaucoup de mémoire de texture.
•
COIN_TEX2_USE_GLTEXSUBIMAGE : Si défini, et si les nouvelles données de texture ont les mêmes attributs que les anciennes données, glTexSubImage() sera utilisé pour copier les nouvelles données dans la texture au lieu de recréer la texture. Ceci n'est pas activé par défaut, car cela semble déclencher un bug dans les pilotes nVidia sous Linux. Cela se produit dans certains cas non reproductibles. Cela pourrait être un bug dans notre code glTexSubImage(), bien sûr. :)
•
COIN_TEX2_USE_SGIS_GENERATE_MIPMAP : Si défini, utilise l'extension GL_SGIS_generate_mipmap (si disponible) pour générer les mipmaps, sinon utilise une routine interne rapide pour les générer. L'utilisation de GL_SGIS_generate_mipmap n'est pas activée par défaut car nous suspectons que certains pilotes ATi ont des problèmes avec cette extension.
•
COIN_ENABLE_CONFORMANT_GL_CLAMP : Si défini, GL_CLAMP sera utilisé lorsque SoGLImage::CLAMP est spécifié comme mode de répétition de texture. Par défaut, GL_CLAMP_TO_EDGE est utilisé, car c'est généralement ce que les gens veulent. Voir http://www.opengl.org/discussion_boards/ubb/Forum3/HTML/007306.html pour une discussion concernant GL_CLAMP et GL_CLAMP_TO_EDGE.
•
COIN_TEX2_ANISOTROPIC_LIMIT : Le filtrage anisotrope est activé pour les textures lorsque la qualité de la texture est supérieure à cette valeur. La valeur par défaut est 0.85.

Soyez conscient que cette classe est une extension de Coin et n'est pas disponible dans l'API originale SGI Open Inventor v2.1.

Membres de énumération de la documentation

enum SoGLImage::Wrap

Est utilisé pour spécifier comment les coordonnées de texture < 0.0 et > 1.0 doivent être traitées. Il peut s'agir de REPEAT, clamped (CLAMP) ou clamped to edge (CLAMP_TO_EDGE), ce qui est utile lors de l'utilisation de textures en mosaïque. Depuis le 2002-11-18, CLAMP est traité comme CLAMP_TO_EDGE. La variable d'environnement COIN_ENABLE_CONFORMANT_GL_CLAMP peut être utilisée pour redéfinir ce comportement.

enum SoGLImage::ResizeReason

Est envoyé en paramètre à SoGLImageResizeCB comme indicateur de la raison pour laquelle une image est redimensionnée. IMAGE signifie que toute l'image est redimensionnée initialement (par exemple, une image de texture). SUBIMAGE et MIPMAP ne sont pas utilisés et sont réservés pour l'avenir.

enum SoGLImage::Flags

Peut être utilisé pour ajuster ou optimiser la gestion des textures dans OpenGL. Normalement, la qualité de la texture est utilisée pour décider de la mise à l'échelle et du filtrage, et les données de l'image sont analysées pour décider si l'image est (partiellement) transparente, et si la texture peut être rendue avec le test alpha au lieu du mélange si elle contient de la transparence. Si vous connaissez le contenu de votre image de texture ou si vous avez des exigences particulières quant à la manière dont la texture doit être rendue, vous pouvez définir les indicateurs en utilisant la méthode SoGLImage::setFlags().

void SoGLImage::setData (const SbImage * image, const Wrap wraps, const Wrap wrapt, const Wrap wrapr, const float quality = 0.5f, const int border = 0, SoState * createinstate = NULL) [virtual]

Définit les données pour cette image GL. Elle ne doit être appelée que lorsqu'un des paramètres a changé, car cela provoquera la recréation de l'objet de texture GL. L'appelant doit s'assurer d'envoyer des valeurs de wrap légales. CLAMP_TO_EDGE n'est pris en charge que dans les implémentations d'OpenGL v1.2 et en tant qu'extension dans certaines anciennes implémentations SGI (GL_SGIS_texture_edge_clamp).

Pour l'instant, si la qualité est supérieure à 0,5 lors de la création, des mipmaps sont créés, sinon une texture ordinaire. Notez que si vous créez une texture avec une qualité de 0,4 et que vous l'appliquez ensuite avec une qualité supérieure à 0,5, l'objet de texture sera recréé en tant que texture mipmap. Cela ne se produit cependant qu'une seule fois.

Si border != 0, la texture OpenGL est créée avec cette taille de bordure. Notez que cela peut être extrêmement lent sur le matériel PC.

Normalement, l'objet de texture OpenGL n'est pas créé tant qu'il n'est pas nécessaire pour la première fois, mais si createinstate != NULL, il est créé immédiatement. C'est utile si vous utilisez un tampon temporaire pour stocker les données de texture. Soyez prudent lorsque vous utilisez cette fonctionnalité, car les données de texture peuvent être nécessaires à des étapes ultérieures (par exemple, pour créer un objet de texture pour un autre contexte). Vous ne pourrez pas créer d'objets de texture pour d'autres contextes de cache si createinstate != NULL.

De plus, si createinstate est fourni et que tous les attributs sont identiques aux données actuelles de l'image, glTexSubImage() sera utilisé pour insérer les données de l'image au lieu de créer un nouvel objet de texture. C'est beaucoup plus rapide sur les pilotes OpenGL et très utile, par exemple, lors de la création de textures animées.

Si vous fournissez NULL pour image, l'instance sera réinitialisée, provoquant la libération de toutes les listes d'affichage et de la mémoire.

DESCRIPTION

This class represents a 3D texture image that is to be rendered using OpenGL.

It provides methods to:

  • Control the texture flags for OpenGL texture mapping.
  • Access the underlying image data.
  • Manage the OpenGL display list used for rendering the texture.
  • Query properties like transparency and alpha test usage.
  • Control texture wrapping modes.
  • Get the texture quality and an ID for the GL texture object.
  • Provide static methods for managing texture resources globally, such as starting and ending rendering frames, tagging images in use, setting the maximum age of display lists, and freeing all textures.

MEMBER ENUMERATION DOCUMENTATION

Flags

Defines flags to control how the texture is handled/initialized.

USE_MIPMAP
Indicates that mipmaps should be used for this texture.
USE_FILTER
Indicates that filtering should be used for this texture.
USE_TRILINEAR
Indicates that trilinear filtering should be used.
USE_GL_MIPMAP
Specifies that OpenGL mipmap generation functions should be used.
GL_NEAREST
OpenGL texture filtering mode: nearest neighbor.
GL_LINEAR
OpenGL texture filtering mode: linear interpolation.
GL_NEAREST_MIPMAP_NEAREST
OpenGL mipmap filtering mode: nearest neighbor for texel and nearest neighbor for mipmap level.
GL_LINEAR_MIPMAP_NEAREST
OpenGL mipmap filtering mode: linear interpolation for texel and nearest neighbor for mipmap level.
GL_NEAREST_MIPMAP_LINEAR
OpenGL mipmap filtering mode: nearest neighbor for texel and linear interpolation for mipmap level.
GL_LINEAR_MIPMAP_LINEAR
OpenGL mipmap filtering mode: linear interpolation for texel and linear interpolation for mipmap level.

Wrap

Defines the texture wrap strategies.

WRAP_NONE
No wrapping is applied. Texels outside the texture range are not defined.
WRAP_CLAMP
Texture coordinates outside the range [0, 1] are clamped to the edge.
WRAP_REPEAT
Texture coordinates are repeated, tiling the texture.
WRAP_MIRRORED_REPEAT
Texture coordinates are repeated, but mirrored on each repetition.
