La classe SoVRMLNavigationInfo est utilisée pour spécifier les configurations de l'avatar et du visualiseur.

La documentation détaillée de la classe est tirée verbatim de la norme VRML97 (ISO/IEC 14772-1:1997). Elle est la propriété de Web3D Consortium et est utilisée avec leur permission :

NavigationInfo {
  eventIn      SFBool   set_bind
  exposedField MFFloat  avatarSize      [0.25, 1.6, 0.75] # [0, inf)
  exposedField SFBool   headlight       TRUE
  exposedField SFFloat  speed           1.0               # [0, inf)
  exposedField MFString type            ["WALK", "ANY"]
  exposedField SFFloat  visibilityLimit 0.0               # [0, inf)
  eventOut     SFBool   isBound
}

Le nœud NavigationInfo contient des informations décrivant les caractéristiques physiques de l'avatar et du modèle de vue de l'utilisateur. Le nœud NavigationInfo est un nœud liant (voir 4.6.10, Nœuds enfants liants : http://www.web3d.org/documents/specifications/14772/V2.0/part1/concepts.html#4.6.10). Il existe donc une pile de nœuds NavigationInfo où le nœud le plus haut dans la pile est le nœud actuellement lié. Le nœud actuellement lié est considéré comme un enfant du nœud Viewpoint actuel, quelle que soit sa position initiale dans le fichier VRML. Chaque fois que le nœud Viewpoint actuel change, le nœud actuellement lié est ré-parenté au nouveau nœud Viewpoint par le navigateur. Chaque fois que le nœud NavigationInfo actuel change, le nouveau nœud NavigationInfo est ré-parenté au nœud Viewpoint actuel par le navigateur. Si une valeur TRUE est envoyée à l'événement set_bind d'un nœud NavigationInfo, le nœud est placé en haut de la pile de nœuds NavigationInfo. Lorsqu'un nœud NavigationInfo est lié, le navigateur utilise les champs du nœud NavigationInfo pour définir les contrôles de navigation de son interface utilisateur et le nœud NavigationInfo est conceptuellement ré-parenté sous le nœud Viewpoint actuellement lié. Tous les changements ultérieurs de l'échelle du système de coordonnées du nœud Viewpoint actuel modifient automatiquement les aspects (voir ci-dessous) des valeurs du nœud NavigationInfo utilisées par le navigateur (par exemple, les changements d'échelle de toute transformation ancestrale). Une valeur FALSE envoyée à set_bind place le nœud NavigationInfo en haut de la pile, génère un événement isBound FALSE et le place au prochain enregistrement de la pile pour être ré-parenté au nœud Viewpoint actuel. 4.6.10, Nœuds enfants liants, contient plus de détails sur la pile de liaison (http://www.web3d.org/documents/specifications/14772/V2.0/part1/concepts.html#4.6.10)).

Le champ type spécifie une liste ordonnée de paradigmes de navigation qui spécifient une combinaison de types de navigation et le type de navigation initial. Le type de navigation du nœud NavigationInfo actuellement lié détermine les capacités de l'interface utilisateur du navigateur. Par exemple, si le type de navigation actuellement lié est « WALK », le navigateur doit présenter une interface de navigation de type WALK (voir la description de WALK ci-dessous). Les navigateurs doivent reconnaître et prendre en charge au moins les types de navigation suivants : « ANY », « WALK », « EXAMINE », « FLY » et « NONE ».

Si « ANY » n'apparaît pas dans la liste des types de navigation du nœud NavigationInfo actuellement lié, l'interface utilisateur du navigateur doit être limitée aux types de navigation reconnus dans la liste. Dans ce cas, les navigateurs ne doivent pas présenter une interface utilisateur qui permet de changer le type de navigation vers un type non spécifié dans la liste. Cependant, si une valeur dans le champ type est « ANY », le navigateur peut fournir n'importe quel type d'interface de navigation et permettre à l'utilisateur de changer le type de navigation dynamiquement. De plus, le premier type reconnu dans la liste sera le type de navigation initial présenté par l'interface utilisateur du navigateur.

Le type de navigation ANY spécifie que le navigateur peut choisir le paradigme de navigation le mieux adapté au contenu et fournir une interface utilisateur permettant à l'utilisateur de changer le paradigme de navigation dynamiquement. Les résultats sont indéfinis si la valeur de type du nœud NavigationInfo actuellement lié est « ANY » et que des transitions de vue sont déclenchées (voir SoVRMLViewpoint).

La navigation de type WALK est utilisée pour explorer un monde virtuel en marchant ou dans un véhicule qui se trouve sur ou au-dessus de la surface du sol. Il est fortement recommandé que la navigation de type WALK définisse le vecteur ascendant dans la direction +Y et fournisse des types de suivi du terrain et de gravité pour produire une expérience de marche ou de conduite. Si le type de nœud NavigationInfo lié est « WALK », le navigateur doit prendre en charge strictement la détection de collision (voir SoVRMLCollision).

La navigation de type FLY est similaire à la navigation de type WALK, mais les suivis de terrain et la gravité peuvent être désactivés ou ignorés. Bien qu'il y ait toujours une notion de « haut », si le type de nœud NavigationInfo lié est « FLY », le navigateur doit prendre en charge strictement la détection de collision (voir 6.8, Collision).

La navigation de type EXAMINE est utilisée pour visualiser des objets individuels et comprend généralement (mais pas exclusivement) la capacité de tourner autour d'un objet et de déplacer la vue vers l'avant ou vers l'arrière.

La navigation de type NONE désactive et supprime toutes les interfaces de navigation spécifiques au navigateur, forçant l'utilisateur à naviguer uniquement à l'aide de mécanismes fournis dans le scénario, tels que les nœuds d'ancrage ou les scripts incluant loadURL().

Si le type de NavigationInfo est « WALK », « FLY », « EXAMINE », ou « NONE » ou une combinaison de ces types (c'est-à-dire que « ANY » n'est pas dans la liste), les transitions de vue (voir SoVRMLViewpoint) déclenchées par le nœud Anchor (voir SoVRMLAnchor) ou la méthode loadURL() de scripting sont implémentées comme une courte transition de vue de l'ancienne vers la nouvelle vue avec des effets de transition qui ne doivent pas être activés.
