Description Détaillée

La classe SoInput est une abstraction de la fonctionnalité d'importation de fichiers.

Cette classe gère la plupart des tâches d'importation de données dans Coin. Elle met une couche d'abstraction sur les opérations de lecture pour rendre transparent pour le reste du code Coin si nous lisons à partir d'un fichier, d'un tampon mémoire ou de l'entrée standard.

SoInput gère également la vérification de la validité des fichiers, ainsi que les informations sur les fonctionnalités des différents formats de fichiers pris en charge.

Exemple d'utilisation :

int
main(void)
{
  SoDB::init();
  SoInput in;
  if (in.openFile("fab_model.iv")) {
    SoSeparator * root = SoDB::readAll(&in);
    if (root) {
      // Faites quelque chose avec le graphe de scène importé ici
      // ...
      return 0;
    }
  }
  return 1;
}

Note importante : il existe plusieurs méthodes publiques et protégées qui permettent de passer ou de retourner des structures FILE* dans cette classe. N'utilisez *pas* ces méthodes lorsque la bibliothèque Coin a été compilée en tant que DLL Microsoft Windows, car passer des instances de FILE* vers ou depuis des DLL est dangereux et causera très probablement un crash. Ceci est une limitation intrinsèque des DLL Microsoft Windows.

Cette classe prend en charge une variable d'environnement appelée COIN_SOINPUT_SEARCH_GLOBAL_DICT. Lorsqu'elle est définie sur "1", le dictionnaire global est recherché après le dictionnaire de fichiers actuel lors de la résolution des mots-clés USE. Cela permet de référencer des nœuds dans d'autres fichiers. La raison de l'introduction de cette fonctionnalité est que le nœud SoFile relit le fichier chaque fois que le champ name change. La première fois que le fichier est lu, il est possible de référencer des nœuds dans le fichier parent, en utilisant le mot-clé USE. Mais, lorsque le fichier est relu, ce n'est plus possible, car la lecture commence maintenant au nœud SoFile, avec un dictionnaire vide.

void SoInput::setStringArray (const char * strings[])

Configure le flux d'entrée pour la lecture à partir des chaînes pointées par un tableau de pointeurs de chaînes terminé par NULL. Il est destiné à la lecture de graphes de scène en mémoire intégrée.

La raison d'être de cette fonction est qu'il existe un problème de portabilité des compilateurs lors de la compilation de grands tampons de chaînes statiques. Certains compilateurs ont des longueurs maximales fixes pour cette fonctionnalité, juste un peu plus de 1 Ko, ce qui devient évidemment un problème très rapidement. Cette méthode vous permet de spécifier le tampon comme un tableau de plus petits tampons de chaînes, généralement une chaîne pour chaque ligne du fichier Inventor.

SoNode *
makeSceneGraph(void) {
  static const char * inlinescenegraph[] = {
    "#Inventor V2.1 ascii\n",
    "\n",
    "Separator {\n",
    "  Cube {\n",
    "  }\n",
    "}\n",
    NULL
  };
  SoInput in;
  if ( !in.setStringArray(inlinescenegraph) ) return NULL;
  return SoDB::readAll(&in);
}

SbBool SoInput::read (SbString & s) [virtual]

Ignore les espaces blancs et extrait la chaîne. Une chaîne peut être placée entre guillemets, auquel cas nous retournerons tous les caractères entre les guillemets (y compris les espaces, tabulations, sauts de ligne, etc.). Un caractère guillemet (c'est-à-dire "'") peut également faire partie de la chaîne, mais doit alors être précédé d'un caractère \'.

Une chaîne non contenue entre guillemets est terminée par le premier espace blanc qui suit.

Retourne FALSE en cas de fin de fichier (EOF) avant que la chaîne ne soit complètement analysée, ou en cas d'autre erreur. Note : Cette fonction ne retourne pas FALSE lors de la rencontre de toutes les fins de fichier. Lorsque plusieurs fichiers sont sur la pile et qu'une chaîne est en cours d'analyse (l'analyseur a trouvé un ou plusieurs caractères valides) et qu'une fin de fichier est rencontrée, l'analyse s'arrête et la chaîne lue ainsi que TRUE sont renvoyées. La prochaine fois que la méthode read sera appelée, la pile sera dépilée et une chaîne lue à partir du fichier suivant sera renvoyée - ne retournant pas toujours FALSE entre les fichiers (bien que cela puisse arriver dans certaines circonstances). La solution consiste à tester la fin de fichier après chaque opération de lecture successive.

SbBool SoInput::read (SbName & n, SbBool validIdent = FALSE) [virtual]

Lit un nom à partir du flux courant et le place dans n.

Cette méthode ne doit pas être utilisée spécifiquement pour lire toutes les instances de SbName. Les sémantiques de l'interface sont telles qu'elle est conçue pour gérer les jetons d'identificateur des formats de fichiers Inventor / VRML. C'est-à-dire les cas où les noms de nœuds, les types de nœuds et les noms de champs doivent être lus. Si votre objectif est de lire la valeur d'un champ SbName qui n'est aucun des éléments ci-dessus, et au moins lorsque la chaîne peut être mise entre guillemets, alors vous devriez très probablement utiliser SoInput::read(SbString &) à la place.

Si validIdent est TRUE, le nom doit être un identificateur valide (pas de caractères réservés, etc.), tandis que validIdent égal à FALSE signifie que nous lirons simplement les caractères du mot suivant jusqu'à ce que nous rencontrions un espace blanc ou l'un des délimiteurs "{"/"}".

Retourne FALSE en cas de fin de fichier avant qu'un nom complet n'ait été lu -- si validIdent est également FALSE. Si validIdent est passé comme TRUE, la valeur de retour sera FALSE si aucun nom valide n'a été trouvé, mais pas nécessairement en fin de fichier.

FILE * SoInput::findFile (const char * basename, SbString & fullname) [protected]

Cette API member est considérée comme interne à la bibliothèque, car elle ne devrait pas intéresser le programmeur d'application.


Retourne le flux actuellement actif.

Parcourt les répertoires d'inclusion dans l'ordre et essaie de trouver un fichier avec le nom donné dans l'un d'eux. Si le fichier est trouvé, place le nom complet avec le chemin complet depuis le répertoire courant du processus dans fullname, ouvre le fichier et retourne le pointeur de fichier.

Si le fichier ne peut être trouvé ou ouvert en lecture, retourne NULL.

Note importante : n'utilisez pas cette méthode lorsque la bibliothèque Coin a été compilée en tant que DLL Microsoft Windows, car le passage d'instances de FILE* vers ou depuis des DLL est dangereux et causera très probablement un crash. C'est une limitation intrinsèque des DLL Microsoft Windows.
