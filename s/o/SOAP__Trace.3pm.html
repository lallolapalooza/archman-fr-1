SOAP::Trace(3) Documentation fournie par les utilisateurs Perl SOAP::Trace(3)

NOM

SOAP::Trace - utilisé uniquement pour gérer et manipuler le traçage d'exécution en temps réel dans la boîte à outils

DESCRIPTION

Cette classe n'a pas de méthodes ni d'objets. Elle est utilisée uniquement pour gérer et manipuler le traçage d'exécution en temps réel dans la boîte à outils. En l'absence de méthodes, cette section passe en revue les événements qui peuvent être configurés et les moyens de les configurer.

SYNOPIS

Le traçage est activé via la méthode d'importation de SOAP::Lite. Cela se fait généralement à la compilation, bien que cela puisse être fait explicitement en appelant directement import. Les commandes de configuration du traçage commencent par le mot-clé +trace. Alternativement, +debug peut également être utilisé ; ils sont interchangeables. Après le mot-clé initial, un ou plusieurs des signaux détaillés ici peuvent être spécifiés, éventuellement avec un rappel (callback) pour les gérer. Lorsque plusieurs signaux sont spécifiés pour être gérés par un seul rappel, il suffit de lister tous les signaux d'abord, puis le rappel, comme ceci :

use SOAP::Lite +trace =>
  method => fault => \&message_level,
  trace => objects => \&lower_level;

Dans l'extrait, la référence à message_level est installée comme rappel pour les signaux method et fault, tandis que lower_level est installée pour les signaux trace et object. Si aucun rappel n'est explicitement fourni, l'action de traçage par défaut est d'enregistrer un message dans le descripteur de fichier STDOUT de Perl. Les rappels doivent attendre un ou plusieurs arguments, bien que le type des arguments varie en fonction du signal.

Tout signal peut être désactivé en préfixant son nom par un tiret, comme -result. Ceci est utile avec le pseudosignal « all » qui est un raccourci pour la liste complète des signaux. L'extrait suivant désactive uniquement les deux signaux, tout en activant les autres :

SOAP::Lite->import(+trace => all => -result => -parameters);

Si le mot-clé +trace (ou +debug) est utilisé sans signaux spécifiés, il active tous les signaux (comme si tous étaient implicites).

Les signaux et leur signification suivent. Chacun porte également une note sur la pertinence du signal pour une application serveur, client ou les deux.

SIGNALS DE TRACAGE

transport Client uniquement
Déclenché au niveau du transport juste avant l'envoi d'une requête et immédiatement après la réception d'une réponse. Chaque fois que le signal est envoyé, le seul argument du rappel est l'objet pertinent. Pour les requêtes, il s'agit d'un objet HTTP::Request ; pour les réponses, il s'agit d'un objet HTTP::Response.
dispatch Serveur uniquement
Déclenché avec le nom complet de la méthode exécutée, juste avant de passer le contrôle à la méthode. Actuellement désactivé dans SOAP::Lite 0.55.
result Serveur uniquement
Déclenché après l'exécution de la méthode et reçoit les résultats renvoyés par la méthode sous forme de liste. Les valeurs de résultat n'ont pas été sérialisées lorsque ce signal est envoyé.
parameters Serveur uniquement
Déclenché avant que la méthode ne soit réellement exécutée, avec les données attendues pour l'appel. Les paramètres de la méthode sont envoyés sous forme de liste, après avoir été désérialisés en données Perl.
headers Serveur uniquement
Ce signal devrait être pour le déclenchement sur les en-têtes d'un message entrant, mais il n'est pas implémenté dans SOAP::Lite 0.55.
objects Client ou serveur
Met en évidence l'instanciation ou la destruction d'un objet. Déclenché sur les méthodes new et DESTROY des classes SOAP::Lite.
method Client ou serveur
Déclenché avec la liste des arguments lorsque la méthode envelope de SOAP::Serializer est appelée avec un argument initial de méthode. La chaîne initiale elle-même n'est pas transmise au rappel.
fault Client ou serveur
Comme pour le signal method ci-dessus, sauf que ce signal est déclenché lorsque SOAP::Serializer::envelope est appelé avec un argument initial de fault.
freeform Client ou serveur
Similaire aux deux précédents, ce signal est déclenché lorsque la méthode SOAP::Serializer::envelope est appelée avec un paramètre initial de freeform. Cette syntaxe est utilisée lorsque la méthode crée des objets SOAP::Data à partir de données d'entrée libres.
trace Client ou serveur
Déclenché au point d'entrée de nombreuses fonctions les plus significatives. Toutes les fonctions au sein des classes SOAP::Lite ne déclenchent pas ce signal. Celles qui le font sont principalement les fonctions visibles décrites dans les descriptions d'interface des classes.
debug Client ou serveur
Utilisé dans les modules de transport pour tracer le contenu des requêtes et des réponses (en tant que chaînes ordinaires, pas en tant qu'objets) à différents points.

EXEMPLES

SÉLECTION DES SIGNAUX À TRACER

Le fragment de code suivant active le traçage pour tous les signaux :

use SOAP::Lite +trace => 'all';

Vous pouvez désactiver le traçage pour un ensemble de signaux en spécifiant le nom du signal avec un tiret. Par conséquent, si vous souhaitez activer le traçage pour tous les signaux sauf les signaux de transport, vous utiliseriez le code suivant :

use SOAP::Lite +trace => [ qw(all -transport) ];

ENREGISTRER LES SIGNAUX DANS UN FICHIER

Vous pouvez éventuellement fournir une sous-routine ou un rappel à chaque signal de traçage que vous déclarez. Chaque fois qu'un signal est reçu, il est transmis au rappel correspondant. Par exemple, le code suivant enregistre tous les signaux de fault dans un fichier nommé fault.log :

use SOAP::Lite +trace => [ fault => \&log_faults ];
sub log_faults {
  open LOGFILE,">fault.log";
  print LOGFILE, $_[0] . "\n";
  close LOGFILE;
}

Vous pouvez également utiliser un seul rappel pour plusieurs signaux avec le code suivant :

use SOAP::Lite +trace => [ method, fault => \&log ];

ENREGISTRER LE CONTENU DES MESSAGES

Le signal transport est unique en ce sens que le signal n'est pas une chaîne de caractères, mais l'objet HTTP::Request qui est envoyé (avant d'être envoyé) ou l'objet HTTP::Response (immédiatement après avoir été reçu). L'exemple suivant montre comment l'utiliser :

use SOAP::Lite +trace => [ transport => \&log_message ];
sub log_message {
  my ($in) = @_;
  if (class($in) eq "HTTP::Request") {
    # faire quelque chose...
    print $in->contents; # ...exemple
  } elsif (class($in) eq "HTTP::Response") {
    # faire quelque chose
  }
}

ON_DEBUG

La méthode « on_debug » est disponible, comme suit :

use SOAP::Lite;
my $client = SOAP::Lite
  ->uri($NS)
  ->proxy($HOST)
  ->on_debug( sub { print @_; } );
