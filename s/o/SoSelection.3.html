Description

Ce noeud de scène peut être inséré dans une arborescence de scène pour activer la sélection d'objets par l'utilisateur.

L'insertion d'un noeud SoSelection dans votre arborescence de scène vous permet de laisser l'utilisateur « cliquer » avec le bouton gauche de la souris pour sélectionner/désélectionner des objets situés sous le noeud SoSelection.

L'utilisation d'un SoBoxHighlightRenderAction ou d'un SoLineHighlightRenderAction pour rendre les arborescences de scène contenant des noeuds SoSelection offre un moyen pratique de fournir un retour visuel sur les sélections à l'utilisateur de l'application.

Attention, une hypothèse erronée courante concernant ce noeud est que la scène sera automatiquement redessinée lorsque l'utilisateur clique sur des objets. Ce n'est pas le cas, le programmeur de l'application doit lui-même planifier un redessin. Un moyen simple d'y parvenir est d'appeler SoNode::touch() sur le noeud SoSelection dans la fonction de rappel de sélection/désélection.

Un « squelette » pour l'utilisation basique des noeuds SoSelection est donné ci-dessous :

extern SoSeparator * make_scenegraph( void );
static SoSelection * selection = NULL;
// Fonction de rappel déclenchée pour la sélection / désélection.
void made_selection( void * userdata, SoPath * path )
{
  (void)fprintf( stdout, "%sselected %s\n",
                 userdata == (void *)1L ? "" : "de",
                 path->getTail()->getTypeId().getName().getString() );
  selection->touch(); // pour redessiner
}
// *************************************************************************
// Affiche un bref avis d'instructions sur stdout.
void show_instructions( void )
{
  (void)fprintf( stdout, "\nThis example program demonstrates the use of the SoSelection node type.\n" );
  (void)fprintf( stdout, "\nQuick instructions:\n\n" );
  (void)fprintf( stdout, "  * pick with left mouse button\n" );
  (void)fprintf( stdout, "  * hold SHIFT to select multiple objects\n" );
  (void)fprintf( stdout, "  * hit ESC to toggle back and forth to view mode\n" );
  (void)fprintf( stdout, "\n" );
}
// *************************************************************************
int main( int argc, char ** argv )
{
  QWidget * window = SoQt::init( argv[0] );
  show_instructions();
  selection = new SoSelection;
  selection->policy = SoSelection::SHIFT;
  selection->ref();
  selection->addChild( make_scenegraph() );
  selection->addSelectionCallback( made_selection, (void *)1L );
  selection->addDeselectionCallback( made_selection, (void *)0L );
  SoQtExaminerViewer * examinerviewer = new SoQtExaminerViewer( window );
  examinerviewer->setSceneGraph( selection );
  examinerviewer->setGLRenderAction( new SoBoxHighlightRenderAction );
  examinerviewer->setViewing( FALSE );
  examinerviewer->show();
  SoQt::show( window );
  SoQt::mainLoop();
  delete examinerviewer;
  selection->unref();
  return 0;
}

Ce noeud n'est pas initialisé dans SoDB::init(), car il fait partie du « module d'extension » du kit d'interaction. Avant d'utiliser ce noeud, vous devez donc appeler SoInteraction::init(). Si vous utilisez l'un des kits d'interface graphique standard (SoXt / SoQt / SoWin), SoInteraction::init() sera appelé pour vous par la méthode So[Xt|Qt|Win]::init() et vous n'aurez pas à vous en soucier.

Concernant l'utilisation de plusieurs noeuds SoSelection simultanément dans la même arborescence de scène : c'est possible, mais pas direct. Les visualiseurs standard fournis par SoQt, SoWin, etc., ne surveillent qu'un seul noeud SoSelection (qui fait partie de l'API héritée d'InventorXt de SGI), de sorte que les changements de sélection sur les autres ne déclenchent pas de redessin. Autrement dit, vous ne voyez pas nécessairement ce qui se passe. Vous devrez vous connecter manuellement et déclencher vous-même les redessins.

Sachez également que lorsque plusieurs noeuds SoSelection sont actifs en même temps dans l'arborescence de scène, les traversées de SoHandleEventAction que vous destinez aux changements de sélection sur un noeud SoSelection affecteront également tous les autres noeuds SoSelection de la scène — désélectionnant généralement tout ce qui se trouve en dessous, car vous cliquerez en dehors des objets sélectionnables. Vous devrez donc également remplacer manuellement ce comportement si vous voulez que le changement de sélection sur un noeud SoSelection n'affecte pas les autres.

Detailed Description

This node collects SoPath's, allowing applications to select parts of the scene graph.

The node keeps track of a list of selected paths. A path can be added to the selection list using addPath() or setSelection(). A path can be removed from the selection list using removePath(). The selection list can be cleared using clear(). The currently selected paths can be retrieved using getPaths().

There is a list of callbacks that can be registered with the node to be informed about selection changes. See addSelectionCallback().

The policy field controls how the selection list is modified when an application calls one of the methods that modify the selection. The following policies are defined:

SoSelection::SHIFT
If the new path is already in the selection list, it is removed. Otherwise it is added.
SoSelection::SHIFT_ADD
The new path is always added to the selection list.
SoSelection::SHIFT_REM
The new path is removed from the selection list if it is present. Otherwise, nothing is done.
SoSelection::TOGGLE
If the new path is already in the selection list, it is removed. Otherwise it is added.
SoSelection::SET
The new path is added to the selection list, and all previously selected paths are removed.

The node also implements the event handling for SoHandleEventAction. It reacts to mouse button presses by performing a pick using the given mouse button state. If the picked object is selectable, it is added to the selection list according to the current policy.

The node is designed to be placed in the scene graph below the objects that are to be selected. When an SoHandleEventAction is traversed, this node will perform a pick into the scene graph below itself. If any objects are picked, they are added to the selection list.

If SoHandleEventAction is applied to the scene graph below the SoSelection node, the node will receive an event. It inspects the event data from action, and processes it if it is something which this node should react to.

Nodes influencing relevant state variables for how event handling is done also override this method.

If you want to extend the selection functionality (e.g. by adding more selection policies or by handling events in a custom way) you can derive a new class from SoSelection. The methods addPath(), removePath() and handleEvent() are protected and can be overridden in derived classes.
