Description Détaillée

La classe SoGeoOrigin est utilisée pour spécifier une localisation géographique absolue par rapport à laquelle la géométrie est référencée.

FORMAT DE FICHIER/VALEURS PAR DÉFAUT :

GeoOrigin {
  geoSystem ["GD", "WE"]
  geoCoords 0 0 0
}

Un problème courant lors du traitement de données géographiques est la précision réduite des nombres à virgule flottante que vous obtenez souvent. Les coordonnées UTM ont souvent une magnitude de 10^5 à 10^6, et cela laisse très peu de précision pour les détails à cette position.

Les nœuds SoGeo sont donc utiles lorsque vous souhaitez conserver vos données dans leur système d'origine, tout en bénéficiant d'une bonne précision en virgule flottante lors du rendu.

Coin a besoin d'un système de coordonnées cartésiennes local pour le rendu. Lorsqu'un nœud SoGeoOrigin est utilisé, Coin créera un système de coordonnées à la position de SoGeoOrigin, et toute la géométrie (et la caméra) dans le graphe de scène sera projetée dans ce système de coordonnées.

Le système de coordonnées aura toujours l'axe Z pointant vers le haut depuis le sol. L'axe Y pointera vers le pôle nord, et l'axe X sera déterminé par la règle de la main droite.

Un graphe de scène ne devrait contenir qu'un seul nœud GeoOrigin, et toute la géométrie du graphe de scène sera, comme indiqué précédemment, rendue par rapport à cette position. Cela signifie que la précision sera meilleure si la position de GeoOrigin est aussi proche que possible de la position réelle de la caméra. Si vous vous déplacez sur une grande zone, il peut donc être judicieux de déplacer la position de GeoOrigin au lieu de la caméra.

Pour placer la géométrie dans le graphe de scène, vous pouvez utiliser soit un nœud SoGeoSeparator, soit un nœud SoGeoCoordinate. Lors de l'utilisation d'un nœud GeoSeparator, toute la géométrie à l'intérieur de ce séparateur sera rendue par rapport à sa position et son orientation dans le système géo, et vous utiliserez ensuite des formes régulières et des nœuds SoCoordinate3 réguliers pour spécifier des données (les points dans un SoCoordinate3 doivent être ajustés pour être relatifs à la position de GeoSeparator).

Le nœud SoGeoCoordinate, en revanche, peut contenir des coordonnées géo de double précision, et ce nœud recalculera en interne le tableau de double précision en un tableau de simple précision relatif au nœud SoGeoOrgin.

Une note concernant les projections UTM : Comme il est très courant de supposer une terre plate lors du travail avec des données UTM, il est possible de fournir un mot-clé "FLAT" pour les systèmes de coordonnées UTM :

GeoOrigin {
  geoSystem [ "UTM", "Z17", "FLAT" ]
  geoCoords  846889 4313850 0
}

Description

This node defines the origin of a geographic coordinate system. It is primarily used to simplify transformations involving geographic coordinates.

When a transformation is applied to the scene graph, the origin node's transformation is prepended to the matrix applied to the rest of the scene graph. This effectively moves the origin of the scene graph to the geographic location specified by the node.

The geographic coordinate system can be specified by the geoSystem field.

Member Data Documentation

SoSFVec3d SoGeoOrigin::geoCoords

Used for specifying the geographic coordinates. For the GD system this should be <latitude> <longitude> <elevation>. For UTM it is <easting> <northing> <elevation>, and for GC it is simply <x> <y> <z>.

SoMFString SoGeoOrigin::geoSystem

Used to specify a spatial reference frame. Coin currently supports three different systems. Support for more systems might be added in the future.

•
"GD" - The Geodetic system (latitude/longitude).
•
"UTM" - Universal Transverse Mercator coordinate system. The second string should be the zone, encoded as "Z<n>".
•
"GC" - Earth-fixed Geocentric with respect to the WGS84 ellipsoid.

The "GD" and "UTM" systems can, for future support, have an ellipsoid specification. The default is "WE" which is the WGS84 ellipsoid, the only ellipsoid currently supported in Coin.
