Description Détaillée

La classe SoDataSensor est la classe de base abstraite pour les capteurs qui surveillent les changements dans une scène graphique.

Si vous devez savoir quand une entité particulière (telle qu'un champ ou un nœud) change, vous pouvez utiliser des sous-classes de SoDataSensor pour surveiller l'entité et être notifié quand elle change.

Documentation Fonctions Membre

void SoDataSensor::setDeleteCallback (SoSensorCB * function, void * data = NULL)

Si un objet surveillé par un capteur de données est supprimé, le rappel donné est appelé avec les données utilisateur fournies.

Le réglage de la priorité du capteur n'affecte pas le rappel de suppression. Il est appelé immédiatement, avant que l'objet ne soit supprimé.

SoNode * SoDataSensor::getTriggerNode (void ) const

Retourne un pointeur vers le nœud qui a causé le déclenchement du capteur, ou NULL s'il n'existe pas de tel nœud.

NULL sera également retourné pour les capteurs qui ne sont pas des capteurs immédiats (c'est-à-dire, dont la priorité est égale à 0), car le résultat pourrait être trompeur (les capteurs non immédiats pourraient avoir été planifiés et replanifiés plusieurs fois, il n'y aurait donc pas de nœud unique responsable du déclenchement du capteur).

Le résultat n'est valide que dans le cadre d'un appel à trigger(), donc si vous souhaitez utiliser le pointeur en dehors de votre rappel de capteur, vous devez le stocker.

SoField * SoDataSensor::getTriggerField (void ) const

Retourne un pointeur vers le champ qui a causé le déclenchement du capteur, ou NULL si le changement n'a pas commencé dans un champ.

N'est valide que pour les capteurs immédiats (retournera NULL sinon), pour des raisons similaires à celles décrites dans getTriggerNode().

Le résultat n'est valide que dans le cadre d'un appel à trigger(), donc si vous souhaitez utiliser le pointeur en dehors de votre rappel de capteur, vous devez le stocker.

SoPath * SoDataSensor::getTriggerPath (void ) const

Retourne un pointeur vers le chemin allant du nœud surveillé par ce capteur (directement ou indirectement via un observateur de champ) au nœud qui a causé le déclenchement du capteur.

Cela ne fonctionne que pour les capteurs en mode immédiat, pour des raisons similaires à celles décrites dans getTriggerNode().

Le chemin résultant n'est valide que dans le cadre de trigger(), donc si vous souhaitez utiliser le chemin en dehors de votre rappel de capteur, vous devez stocker le pointeur et appeler SoPath::ref() pour éviter sa destruction à la fin de SoDataSensor::trigger().

void SoDataSensor::setTriggerPathFlag (SbBool flag)

Ce drapeau indique si le chemin doit ou non être recherché chaque fois qu'un nœud déclenche le capteur de données.

Ce drapeau est fourni car la recherche d'un chemin de nœud à travers une scène graphique est une opération coûteuse en calcul.

Retourne si oui ou non les opérateurs de déclenchement de nœuds induits feront que le capteur trouvera le chemin du nœud qui l'a causé.
