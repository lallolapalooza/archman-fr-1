Description Détaillée

La classe SoLOD est utilisée pour choisir un enfant en fonction de la distance entre le spectateur et l'objet.

La documentation de la classe du nœud SoLOD serait suffisamment similaire à celle de SoLevelOfDetail pour que nous vous renvoyions à celle-ci en premier lieu. Elle expliquera les principes généraux d'un mécanisme de niveau de détail, et pourquoi et comment l'utiliser.

(La principale différence entre SoLOD et SoLevelOfDetail est que SoLOD utilise la technique plus rapide de "distance au spectateur" pour implémenter la fonctionnalité de niveau de détail, par opposition à la technique plus correcte (mais potentiellement plus lente) de "zone de bbox projetée" utilisée par SoLevelOfDetail.)

Voici un exemple fictif (en style de format de fichier Inventor, mais facilement convertible en code) qui montre comment utiliser ce nœud :

LOD {
   range [ 10, 20, 30, 40 ]
   Sphere { }
   Cylinder { }
   Cone { }
   Cube { }
   Info { }
}

Pour le sous-graphe ci-dessus, lorsque l'objet LOD est à moins de 10 unités de la caméra de point de vue, une SoSphere sera affichée. Pour des distances de 10 à 20 unités, ce sera changé en SoCylinder, et ainsi de suite. Pour des distances de *plus* de 40 unités de la caméra, un nœud SoInfo sera parcouru / rendu -- c'est-à-dire que rien ne sera affiché. (C'est une "astuce" courante utilisée pour optimiser le rendu lorsque les modèles s'éloignent suffisamment de la caméra pour que nous voulions les supprimer complètement).

Notez que lors de l'utilisation d'une SoOrthographicCamera dans les vues d'examinateur des bibliothèques SoQt, SoWin et SoXt, il semblera que le nœud SoLOD ne fonctionne pas lors de l'utilisation de la fonctionnalité "Zoom". Ce qui se passe est qu'une SoOrthographicCamera n'est pas réellement déplacée, l'effet de "zoom" est réalisé simplement en modifiant son paramètre de hauteur de vue (c'est-à-dire la valeur du champ SoOrthographicCamera::height), mais sa position reste constante. Ainsi, la distance à la caméra ne changera pas, ce qui signifie que SoLOD choisira le même enfant, peu importe la quantité de "zoom".

(Le nœud SoLevelOfDetail utilise la zone de l'objet dans l'espace écran pour décider quand changer d'enfant, donc ce nœud fonctionnera toujours avec SoOrthographicCamera.)

FORMAT DE FICHIER/VALEURS PAR DÉFAUT :

LOD {
    center 0 0 0
    range [  ]
}

NOM

SoLOD

Dessine les enfants de ce groupe de manière dépendante de la distance.

SYNOPSIS

Inclure

#include <Inventor/nodes/SoLOD.h>

Inheritance:

public SoGroup

Instantiation: Yes

DESCRIPTION

Le nœud SoLOD (Level Of Detail) est un groupe dont les enfants sont dessinés de manière dépendante de la distance. Il permet de gérer différents niveaux de détails pour un objet, en affichant une version plus détaillée lorsque l'observateur est proche et une version plus simple lorsqu'il est loin. Les enfants du nœud SoLOD sont organisés dans un tableau et chaque enfant est associé à une plage de distances. L'action de parcours utilise ces plages pour déterminer quel enfant doit être parcouru.

L'ordre des enfants est important. Le premier enfant (indice 0) est utilisé pour les plus courtes distances, et le dernier enfant est utilisé pour les plus grandes distances. Les plages de distances sont définies par le champ range.

Par exemple, si un nœud SoLOD a trois enfants et que le champ range est défini sur [0.0, 10.0, 20.0], alors :

  • L'enfant 0 sera utilisé lorsque la distance est comprise entre 0.0 et 10.0.
  • L'enfant 1 sera utilisé lorsque la distance est comprise entre 10.0 et 20.0.
  • L'enfant 2 sera utilisé lorsque la distance est supérieure à 20.0.

Si le champ range ne contient qu'une seule valeur, tous les enfants seront dessinés.

Le champ center permet de spécifier un point de référence pour le calcul de la distance. Par défaut, il est à [0, 0, 0], ce qui signifie que la distance est calculée depuis le centre géométrique de l'objet.

DOCUMENTATION DES DONNÉES MEMBRES

SoMFFloat SoLOD::range

Les plages de distances qui décident quand utiliser chaque enfant pour le parcours / rendu. Voir l'exemple d'utilisation dans la documentation de la classe principale de SoLOD pour une explication sur la manière de configurer correctement ce vecteur.

Par défaut, ce vecteur ne contient qu'une seule valeur 0.0f.

SoSFVec3f SoLOD::center

Ce vecteur représente un décalage à l'intérieur de l'objet, du point central géométrique au point central à partir duquel le programmeur de l'application souhaite réellement que la distance entre le spectateur et l'objet soit calculée.

La valeur par défaut est [0, 0, 0]. Il n'est généralement pas nécessaire de modifier ce champ.
