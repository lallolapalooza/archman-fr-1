Description Détaillée

La classe SoLevelOfDetail est utilisée pour choisir un enfant en fonction de sa taille projetée.

Un mécanisme de niveau de détail est typiquement utilisé par les programmeurs d'applications pour aider la bibliothèque à accélérer le rendu.

Le fonctionnement d'un mécanisme de niveau de détail est essentiellement le suivant :

Plusieurs versions de complexité variable du *même* objet 3D / forme sont fournies par le programmeur d'application dans un ordre trié, de la plus "complexe" à la moins "complexe" (où "complexe" dans ce contexte doit être compris comme étant plus ou moins détaillé en termes de nombre de polygones / formes utilisés pour le représenter).

Le système de rendu à l'exécution, lors du parcours du graphe de scène, calculera à la volée soit la distance entre la caméra et le modèle 3D en question, soit le nombre de pixels dans la projection à l'écran du modèle 3D. Cette valeur est ensuite utilisée pour décider quelle version du modèle sera réellement rendue : à mesure que le modèle s'éloigne de la caméra, une version moins détaillée du modèle est utilisée. Et inversement, lorsque le modèle se rapproche de la caméra, des versions de plus en plus détaillées sont rendues.

C'est, dans de nombreuses circonstances, un moyen très efficace de laisser le programmeur d'applications aider à *optimiser profondément* le rendu de sa scène 3D.

Il existe bien sûr un compromis avec la technique du niveau de détail : plus de versions du même modèle 3D signifient que le graphe de scène utilisera plus de mémoire vive. De plus, générer l'ensemble des versions de moins en moins détaillées d'un modèle 3D à partir de l'original n'est souvent pas une tâche triviale à réaliser correctement. Le processus est souvent assisté par des logiciels comme ceux proposés par Kongsberg Oil & Gas Technologies dans leur package <a href="http://www.rational-reducer.com">Rational Reducer</a>.

Le nœud SoLevelOfDetail implémente la technique de niveau de détail variante "taille projetée" (par opposition à la technique "distance à l'objet", réalisée par le nœud SoLOD). Le nœud compare la taille projetée actuelle du plus petit rectangle couvrant la boîte englobante de la géométrie de son enfant. Avec cet ensemble de modèles de la même forme, une spécification de quand les alterner est également fournie.

Exemple de disposition du graphe de scène :

LevelOfDetail {
    screenArea [ 2000, 500, 50 ]
    DEF version-0 Separator {
        # version la plus complexe / détaillée / lourde du sous-graphe
    }
    DEF version-1 Separator {
        # version moins complexe
    }
    DEF version-2 Separator {
        # version encore moins complexe
    }
    DEF version-3 Separator {
        # version la plus simple / "légère"
    }
}

Le fonctionnement du sous-graphe de scène ci-dessus serait le suivant : si la zone rectangulaire autour de la boîte englobante projetée du modèle couvre *plus de 2000 pixels* (ce qui signifie qu'il sera assez proche de la caméra), la version la plus complexe du modèle (version-0) sera parcourue (et rendue, bien sûr). Si la zone projetée se situe *entre 500 et 2000 pixels*, le modèle \c version-1 sera utilisé. Idem si la zone projetée se situe entre 50 et 500 pixels, la version \c version-2 du modèle sera utilisée. Enfin, si la surface de la boîte englobante projetée est *inférieure à 50 pixels carrés*, la version, supposément la moins détaillée du modèle, sera utilisée.

(Une "astuce" courante consiste à faire en sorte que le dernier des enfants du nœud SoLevelOfDetail soit simplement un sous-graphe vide, de sorte qu'aucune géométrie ne soit rendue si le modèle est suffisamment éloigné. Cela aura bien sûr un effet positif sur le temps de rendu total pour le graphe de scène complet.)

Notez que le vecteur SoLevelOfDetail::screenArea sera influencé par les nœuds SoComplexity précédents de la manière suivante : si SoComplexity::value est défini de 0,0 à 0,5, des niveaux de détail inférieurs à la normale seront sélectionnés pour le parcours. Si SoComplexity::value est supérieur à 0,5, des niveaux de détail supérieurs à la normale seront utilisés. Une valeur SoComplexity::value égale à 1,0 provoquera toujours l'utilisation du premier enfant de SoLevelOfDetail.

Comme mentionné ci-dessus, il existe un autre nœud de niveau de détail dans la bibliothèque Coin : SoLOD. La différence entre celui-ci et celui-ci est simplement qu'au lieu de la surface projetée de la boîte englobante, SoLOD utilise la distance entre la caméra et l'objet pour déterminer quand passer d'une version à l'autre du modèle.

L'utilisation de SoLOD est plus rapide, car le calcul de la surface projetée de la boîte englobante nécessite un certain nombre de calculs. Mais l'utilisation de SoLevelOfDetail est souvent "meilleure", en ce sens qu'elle est vraiment la taille et la visibilité d'un modèle dans la fenêtre d'affichage qui déterminent si nous pouvons passer à une version moins complexe sans perdre suffisamment de détails pour entraîner une dégradation visuelle notable.

Description Détaillée

Ce nœud est utilisé pour implémenter des graphiques de niveau de détail. Le système de niveau de détail sélectionne un enfant à insérer du graphique de niveau de détail en fonction de la zone de l'écran que le nœud occupe. L'enfant approprié est choisi en itérant sur chaque enfant et en vérifiant si sa zone d'écran est plus grande ou égale à la valeur de screenArea.

Par exemple, le graphique de niveau de détail suivant:

 SoLevelOfDetail {
   screenArea [ 10000.0, 100.0, 10.0 ]
   children [
     Separator { ... high detail geometry ... },
     Separator { ... medium detail geometry ... },
     Separator { ... low detail geometry ... }
   ]
 }

s'assurerait que le premier enfant est rendu s'il occupe au moins 10000 pixels à l'écran, le deuxième enfant s'il occupe au moins 100 pixels à l'écran, et le troisième enfant s'il occupe au moins 10 pixels à l'écran. Un enfant est également choisi s'il y a suffisamment d'espace pour tous les enfants. En d'autres termes, le système trouvera le premier enfant dont la zone d'écran est supérieure ou égale à sa zone de sélection d'écran et le rendra.

Le nœud SoLevelOfDetail est une sous-classe de SoGroup.

Pour une implémentation d'exemple, veuillez vous référer à la classe de documentation principale de SoLevelOfDetail.

Le membre screenArea sera par défaut à 0.0f. Le nœud le traitera comme s'il était défini sur SoNode::getScreenArea().
