DESCRIPTION

Un SoSeparator est un nœud de groupe qui préserves l'état du rendu. Il est utilisé pour séparer différentes parties d'un graphe de scène de telle sorte que les changements d'état (tels que les transformations, les couleurs, les matériaux, etc.) apportés à l'intérieur d'un SoSeparator ne seront pas visibles à l'extérieur de celui-ci. De plus, tout état du rendu qui était actif avant l'entrée dans le SoSeparator sera restauré à la sortie de celui-ci.

Ceci est réalisé en enregistrant l'état actuel du rendu à l'entrée dans le SoSeparator, en traitant ses enfants, puis en restaurrant l'état enregistré à la sortie. La plupart des nœuds Inventor, SoSeparator est le nœud le plus utilisé pour la hiérarchisation de la scène.

La définition de l'état de rendu est effectuée en utilisant les SoActions. Les actions qui modifient l'état du rendu sont déclarées comme telles, et c'est le rôle du SoSeparator de gérer les changements d'état.

En général, les enfants d'un SoSeparator sont des nœuds qui définissent la géométrie et l'apparence de la scène. Les SoSeparators peuvent être imbriqués pour créer des structures de scène plus complexes.

Les SoSeparators ont aussi un système de mise en cache optionnel qui peut améliorer les performances de rendu. La mise en cache peut être activée ou désactivée en utilisant la méthode setCacheEnable.

Les dérivés de SoSeparator incluent SoAnnotation, SoGeoSeparator, SoLocateHighlight, SoSelection, et SoShadowGroup.

Description Détaillée

La classe SoSeparator est un nœud de groupe qui préserve l'état.

Les sous-graphes parentés par des nœuds SoSeparator n'affecteront pas l'état, car ils poussent et dépilent l'état de parcours avant et après le parcours de leurs enfants.

Les nœuds SoSeparator fournissent également des options d'optimisation de parcours grâce à l'utilisation de la mise en cache.

FORMAT DE FICHIER/VALEURS PAR DÉFAUT :

Separator {
    renderCaching AUTO
    boundingBoxCaching AUTO
    renderCulling AUTO
    pickCulling AUTO
}

void SoSeparator::setNumRenderCaches (const int howmany) [static]

Définit le nombre maximum de caches que les nœuds SoSeparator peuvent allouer pour la mise en cache du rendu.

Ceci est une valeur globale utilisée pour tous les nœuds SoSeparator, mais la valeur indique le nombre maximum par SoSeparator individuel.

Plus de caches peuvent améliorer les performances, mais utiliseront plus de mémoire. La valeur par défaut intégrée est 2.

La valeur peut également être modifiée globalement en définissant la variable d'environnement du système hôte IV_SEPARATOR_MAX_CACHES sur le nombre souhaité. Ceci est principalement pour aider au débogage, en permettant de désactiver complètement la mise en cache du rendu (par exemple, en définissant IV_SEPARATOR_MAX_CACHES=0) sans avoir à modifier le code de l'application.

Descripción detallada

El nodo SoSeparator está diseñado para optimizar las operaciones de renderizado y selección de sus nodos hijos. Para este fin, SoSeparator puede cachear el estado de renderizado (por ejemplo, listas de visualización de OpenGL) y/o el bounding box de sus hijos.

SoSeparator también puede realizar una culling de vista de frustum para evitar la travesía y renderizado de geometría que no es visible para la cámara.

Los campos de control de SoSeparator (renderCaching, boundingBoxCaching, renderCulling y pickCulling) se pueden establecer en uno de los siguientes valores:

SoSeparator::OFF
La optimización está desactivada.
SoSeparator::ON
La optimización está activada.
SoSeparator::AUTO
El sistema determinará automáticamente si activar o no la optimización. Este es el valor por defecto.

El modo AUTO intentará optimizar el rendimiento. Sin embargo, puede ser más rápido establecer explícitamente uno de estos campos en ON o OFF si conoce los requisitos de su aplicación.

En general, el uso de SoSeparator con optimizaciones activadas reducirá el tiempo de renderizado y selección para escenas complejas. Si los nodos hijos de un SoSeparator cambian con frecuencia, puede que sea más rápido desactivar las optimizaciones para ese SoSeparator.

Documentación de enumeración de miembros

SoSeparator::autoSwitch

Este valor de enumeración indica al sistema que decida automáticamente si debe o no habilitar el caché o la culling. Este es el valor por defecto para todos los campos de control de SoSeparator.

SoSeparator::off

Este valor de enumeración indica que la optimización correspondiente debe estar desactivada.

SoSeparator::on

Este valor de enumeración indica que la optimización correspondiente debe estar activada.

SbBool SoSeparator::affectsState (void ) const [virtual]

Devuelve TRUE si el nodo podría tener cualquier efecto durante la travesía del estado.

Si devuelve FALSE, no cambiará el estado del travesado de pre-travesado a post-travesado. El SoSeparator nodo devolverá FALSE, ya que presiona y despresiona el estado antes y después de la travesada de sus hijos. Todos los SoShape nodos también devolverán FALSE, ya que solo se mueve datos de geometría al renderizador no afecta el estado real de renderizado.

El método por defecto devuelve TRUE, basado en el principio de "más seguro es mejor que el riesgo".

SbBool SoSeparator::readInstance (SoInput * in, unsigned short flags) [protected], [virtual]

Este método está principalmente destinado a su uso interna durante operaciones de importación de archivos.

Lee una definición de un objeto de instanciación desde el flujo de entrada in. El estado del flujo de entrada apunta a la parte inicial de una representación serializada/persistente de una instancia de este tipo de clase.

Devuelve TRUE o FALSE dependiendo de si la instanciación y la configuración del nuevo objeto de esta clase fue exitosa o no. El proceso de importación debería ser robusto y manejar correctamente flujos de entrada corruptos devolviendo FALSE.

SoSFEnum SoSeparator::renderCaching

Política para el caché de instrucciones de renderizado para ejecución más rápida. Esta usará normally el mecanismo de displaylist de OpenGL.

Valor por defecto es SoSeparator::AUTO.

Si sabes que ciertas partes de tu escena nunca cambiarán, podría ser beneficioso explicitamente establecer este campo a SoSeparator::ON. Si por el contrario sabes que partes de la escena cambiarán mucho (como en cada recarga), será beneficioso establecer este campo a SoSeparator::OFF para el nodo principal de separador de esta (sub)grafía.

Normalmente el valor por defecto de AUTO manejará cualquier escena muy bien. Las ventajas que se pueden obtener al establecer SoSeparator::renderCaching a ON son:

•
Si conoces con certeza que la geometría bajo el SoSeparator es estática, se establecerá el caché de inmediato.

De otro lado, el código de Coin hará un poco de pruebas y decidirá por alguna heurística si o no habilitar esta función. Esto hará que el renderizado sea ligeramente más lento después del arranque que cuando renderCaching está establecido a ON.

La disminución debería ser casi imperceptible, así que no se recomienda a los desarrolladores de aplicaciones a hacer esto.

•
Para muchos nodos de forma de superficie que pueden contener muchos primitivos básicos, como por ejemplo SoFaceSet, SoIndexedFaceSet, SoLineSet, etc., hay un umbral interno que indica cuántos primitivos un nodo puede contener antes de que no se realice el caché cuando SoSeparator::renderCaching está establecido a AUTO.

La razón por la cual lo hacemos es porque los listas de renderizado de OpenGL pueden consumir un gran número de recursos de memoria de la tarjeta gráfica.

Pero si sabes que es ventajoso en tu plataforma particular, puedes reemplazar este mediante establecer SoSeparator::renderCaching a ON.

También se recomienda a los desarrolladores de aplicaciones a hacer esto. Una mejor solución en estos casos sería contactar con SIM y describir la plataforma y el problema, y podríamos integrar una solución adecuada en Coin.

Hay razones buenas para establecer renderCaching a OFF, como cuando sabes que la geometría cambiará mucho. Sin embargo, Coin debería funcionar bastante bien incluso sin esta optimización. (Si renderCaching está AUTO en una subgrafía con geometría que cambia o otros nodos de caché que rompen, los algoritmos de caché de SoSeparator detendrán su intento de hacer cachés, al menos después de varios intentos fallidos.)

La historia breve sobre cómo se funciona el caché automático es como sigue:

  • Para formas basadas en vértices con menos de 100 triángulos y donde la geometría se considera bastante estática, el caché se activa.
  • Para formas con más de 1000 triángulos, el caché se desactiva para evitar que se use demasiado la memoria de la tarjeta gráfica.
  • Para formas con más de 100 pero menos de 1000 triángulos, el caché de display list se activa si nuestras heurísticas deciden que la geometría puede considerarse estática.

El umbral máximo (de 1000) es mayor cuando se realiza renderizado remoto (como cuando se renderiza de un sistema X11 a otro).

El desactivar el caché de display list tiene prioridad sobre activar, así que si tienes un SoSeparator que contiene una forma con más de 1000 triángulos y otra con menos de 100, el caché se desactivará para el SoSeparator.

Es posible ajustar los límites utilizando algunas variables de entorno:

  • COIN_AUTOCACHE_LOCAL_MIN puede usarse para cambiar el límite de habilitar el caché, mientras que COIN_AUTOCACHE_LOCAL_MAX controla el límite de deshabilitar el caché.
  • Las variables correspondientes para renderizado remoto son COIN_AUTOCACHE_REMOTE_MIN y COIN_AUTOCACHE_REMOTE_MAX.

SoSFEnum SoSeparator::boundingBoxCaching

Política para cachear cálculos de bounding box. Valor por defecto es SoSeparator::AUTO.

Ver también documentación para SoSeparator::renderCaching.

SoSFEnum SoSeparator::renderCulling

Política para realizar culling de vista durante las travesadas de renderizado. Valor por defecto es SoSeparator::AUTO.

Cuando el culling de renderizado está desactivado en Coin, se dejará a los algoritmos de renderización del biblioteca de renderizado inmediato. Esto suele ser más rápido que hacer culling desde dentro de Coin, así que debes monitorear el cambio de velocidad de ejecución si estás configurando este campo a SoSeparator::ON.

Ver también documentación para SoSeparator::renderCaching.
