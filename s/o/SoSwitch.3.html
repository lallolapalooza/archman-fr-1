Description Détaillée

La classe SoSwitch est un nœud de groupe qui sélectionne une sous-hiérarchie d'enfant pour la traversée. Lequel des enfants sera traversé est contrôlé par le champ SoSwitch::whichChild du programme. En plus de sélectionner un seul enfant pour la traversée, il est également possible d'inverser tous les enfants à l'intérieur ou à l'extérieur de la traversée.

Ce nœud est très utile pour activer ou désactiver conditionnellement des parties de la hiérarchie de scène en fonction du mode de rendu actuel, du mode de visualisation ou de tout autre élément que le programme peut gérer.

FORMAT DE FICHIER/SOURCE :

Switch {
    whichChild -1
}

SbBool SoSwitch::affectsState (void ) const [virtuel]

Renvoie TRUE si le nœud pourrait avoir un effet sur l'état pendant la traversée.

Si la valeur renvoyée est FALSE, aucune donnée dans l'état de traversée ne changera de l'état précédent à l'état suivant. Le nœud SoSeparator renverra FALSE, car avant et après la traversée de ses enfants, il pousse et dépile l'état. Tous les nœuds SoShape renverront également FALSE, car seules les données géométriques sont envoyées au moteur de rendu, ce qui n'affecte pas l'état de rendu réel.

La méthode par défaut renvoie TRUE, selon une philosophie de "mieux vaut être prudent".

Documentation Donnée Membre

SoSFInt32 SoSwitch::whichChild

Sélectionne quel enfant doit être parcouru pendant le rendu (et certaines autres) actions.

La valeur doit être SO_SWITCH_NONE (pour parcourir aucun enfant, comme un nœud SoGroup vide), SO_SWITCH_ALL (pour parcourir comme un nœud SoGroup), SO_SWITCH_INHERIT (pour parcourir le même enfant que le dernier nœud SoSwitch), ou un index pour un enfant.

Lors de l'utilisation de SO_SWITCH_INHERIT, il est important de comprendre comment le nœud SoSwitch est affecté par d'autres nœuds SoSwitch. S'il y a plusieurs commutateurs dans le graphe de scène, le dernier avec son champ whichChild défini sur une valeur autre que SO_SWITCH_INHERIT sera utilisé. Le commutateur n'hérite pas seulement de son nœud parent commutateur, mais aussi de ses frères et sœurs, situés avant lui dans le graphe de scène. Un exemple aidera à clarifier cela :

#Inventor V2.1 ascii
Separator {
  Switch {
    whichChild 0
    Group {
      Switch {
        whichChild 1
        BaseColor { rgb 1 0 0 } # rouge
        BaseColor { rgb 1 1 0 } # jaune
      }
      Switch {
        whichChild -2 # SO_SWITCH_INHERIT
        BaseColor { rgb 0 1 0 } # vert
        BaseColor { rgb 0 0 1 } # bleu
      }
      Cube { }
    }
  }
}

Ceci aboutit à un carré bleu à l'écran. La raison en est que la valeur du champ précédent whichChild a été héritée par le dernier commutateur, sélectionnant l'enfant 1 - le BaseColor bleu.

Lors de la construction de fichiers ASCII Inventor, les valeurs entières des termes doivent être utilisées à la place de leurs noms. Ce sont -1 pour SO_SWITCH_NONE, -2 pour SO_SWITCH_INHERIT, et -3 pour SO_SWITCH_ALL.

La valeur par défaut du champ est SO_SWITCH_NONE.
