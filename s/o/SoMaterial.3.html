Description Détaillée

La classe SoMaterial est un type de nœud pour configurer les valeurs de matériau pour la géométrie de la scène.

Après avoir traversé un nœud SoMaterial, les nœuds de forme ultérieurs avec de la géométrie dans le graphe de scène utiliseront les valeurs du "pool" de matériaux de l'état de parcours configuré à partir de nœuds de ce type.

Pour des informations détaillées sur les différents composants, consultez le modèle de couleur OpenGL, présenté dans le chapitre "Couleurs et Coloration" (chapitre 2.13 de la spécification OpenGL 1.4).

Notez que les valeurs d'un nœud de matériau *remplaceront* les valeurs précédentes de l'état de parcours, elles ne s'accumuleront *pas*. C'est le cas même lorsque par exemple les changements de matériau sont *implicites* dans un fichier iv, comme l'illustre l'exemple suivant :

Notez également que la prise en charge de plusieurs valeurs dans ambientColor, emissiveColor, specularColor et shininess a été obsolète dans Open Inventor 2.1. La raison de ce changement de conception était axée sur les performances, car il est relativement lent de modifier les propriétés de matériau OpenGL. La modification de la valeur diffuseColor est cependant rapide, il est donc toujours possible d'avoir plusieurs valeurs diffuseColor et transparency.

#Inventor V2.1 ascii
Material { ambientColor 1 0 0 }
Cone { }
Translation { translation 5 0 0 }
Material { }
Sphere { }

(Le SoSphere n'"héritera" pas de la SoMaterial::ambientColor du premier nœud SoMaterial, même si elle n'est pas explicitement définie dans le second nœud de matériau. La valeur par défaut de SoMaterial::ambientColor sera utilisée.)

Notez que les nœuds importés dans le cadre d'un fichier VRML V1.0 ont un cas spécial, où les champs SoMaterial::ambientColor, SoMaterial::diffuseColor et SoMaterial::specularColor contiennent des valeurs nulles, et SoMaterial::emissiveColor contient une ou plusieurs valeurs. Les valeurs de SoMaterial::emissiveColor devraient alors être traitées comme un éclairage précalculé, et les autres champs devraient être ignorés.

Vous pouvez détecter ce cas en vérifiant les valeurs des éléments de matériau lorsque le graphe de scène est traversé à l'aide d'une SoCallbackAction. SoDiffuseColorElement, SoAmbientColorElement, et SoSpecularColorElement contiendront une valeur avec une couleur complètement noire (0.0f, 0.0f, 0.0f), SoShininessElement contiendra une valeur de 0.0f, et SoEmissiveColorElement contiendra une ou plusieurs valeurs. Ceci est fait pour que le rendu fonctionne correctement sur les systèmes qui ne testent pas ce cas spécifique.

Vous ne devriez vérifier ce cas que lorsque vous parcourez un graphe de scène de fichier VRML V1.0, bien sûr. Voir SoNode::getNodeType() pour des informations sur la manière dont les nœuds peuvent être testés pour savoir s'ils ont été importés ou autrement configurés comme étant de type VRML1 par rapport au type Inventor.

Lorsque le graphe de scène est rendu à l'aide d'une SoGLRenderAction, les éléments seront définis différemment pour optimiser le rendu. Le SoDiffuseColorElement sera défini sur les valeurs de SoMaterial::emissiveColor, et le modèle d'éclairage sera défini sur SoLightModel::BASE_COLOR.

Les valeurs de SoMaterial::transparency seront toujours traitées normalement.

Voici un exemple d'utilisation très simple :

#Inventor V2.1 ascii
Separator {
   Coordinate3 {
      point [ 0 0 0, 1 0 0, 1 1 0 ]
   }
   Material {
      diffuseColor [ 1 0 0, 1 1 0, 0 0 1 ]
   }
   MaterialBinding {
      value PER_VERTEX
   }
   IndexedFaceSet {
      coordIndex [ 0, 1, 2, -1 ]
   }
}

FORMAT DE FICHIER/VALEURS PAR DÉFAUT :

Documentation des données membres

SoMFColor SoMaterial::ambientColor

Valeurs de couleur pour la partie ambiante des matériaux. Contient par défaut une seule valeur de [0.2, 0.2, 0.2] (c'est-à-dire un gris foncé).

La partie ambiante du matériau n'est pas influencée par les sources de lumière et doit être conceptuellement considérée comme la contribution constante, bien que faible, de la lumière dans un environnement "suintant" de partout.

Pensez à la contribution ambiante dans le contexte où il y a toujours des photons qui clignotent partout, même dans une pièce sombre sans sources de lumière.

Seule la première valeur de ce champ sera utilisée. Toutes les autres seront ignorées.

Voir aussi

SoEnvironment::ambientIntensity

SoMFColor SoMaterial::diffuseColor

Valeurs de couleur pour la partie diffuse des matériaux. Ce champ est initialisé par défaut avec une seule valeur de [0.8, 0.8, 0.8] (c'est-à-dire un gris clair).

La partie diffuse est combinée avec la lumière émise par les sources de lumière de la scène.

L'implémentation traditionnelle d'Open Inventor utilise le même bit de substitution pour la couleur diffuse et la transparence. Pour contourner ce problème si vous souhaitez substituer l'une sans l'autre, définissez la variable d'environnement "COIN_SEPARATE_DIFFUSE_TRANSPARENCY_OVERRIDE". Ceci est une extension de Coin et ne fonctionnera pas dans d'autres implémentations d'Open Inventor.

SoMFColor SoMaterial::specularColor

Valeurs de couleur pour la partie spéculaire des matériaux. La valeur par défaut est une seule valeur de [0, 0, 0] (noir).

Seule la première valeur de ce champ sera utilisée. Toutes les autres seront ignorées.

SoMFColor SoMaterial::emissiveColor

La couleur de la lumière "émise" par la géométrie suivante, indépendamment de l'éclairage ou de la texture.

Contient par défaut une seule valeur de [0, 0, 0] (noir, c'est-à-dire aucune contribution).

Seule la première valeur de ce champ sera utilisée. Toutes les autres seront ignorées.

SoMFFloat SoMaterial::shininess

Valeurs de brillance. Elles déterminent comment les lumières des sources lumineuses sont distribuées sur les surfaces de la géométrie. La plage valide est de 0.0 (apparence grisâtre) à 1.0 (surfaces brillantes).

Contient par défaut une seule valeur de 0.2.

Seule la première valeur de ce champ sera utilisée. Toutes les autres seront ignorées.

SoMFFloat SoMaterial::transparency

Valeurs de transparence. La plage valide est de 0.0 (complètement opaque, ce qui est la valeur par défaut) à 1.0 (complètement transparent, c'est-à-dire invisible).

Contient par défaut une seule valeur de 0.0.

L'implémentation traditionnelle d'Open Inventor utilise le même bit de substitution pour la transparence et la couleur diffuse. Pour contourner ce problème si vous souhaitez substituer l'une sans l'autre, définissez la variable d'environnement "COIN_SEPARATE_DIFFUSE_TRANSPARENCY_OVERRIDE". Ceci est une extension de Coin et ne fonctionnera pas dans d'autres implémentations d'Open Inventor.
