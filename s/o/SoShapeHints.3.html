Description Détaillée

La classe SoShapeHints est un nœud contenant des indications sur la manière de rendre la géométrie.

Le nœud SoShapeHints est utilisé pour fournir des indices au sous-système de rendu sur la manière dont certains aspects de la géométrie subsquéquente dans le graphe de scène doivent être dessinés.

Voici un exemple sur la façon d'afficher une scène en mode fil de fer qui ne montre que les triangles orientés vers la caméra.

#include <Inventor/nodes/SoCone.h>
#include <Inventor/nodes/SoDrawStyle.h>
#include <Inventor/nodes/SoLightModel.h>
#include <Inventor/nodes/SoSeparator.h>
#include <Inventor/nodes/SoShapeHints.h>
#include <Inventor/Win/SoWin.h>
#include <Inventor/Win/viewers/SoWinExaminerViewer.h>
int main(int, char * argv[])
{
  HWND window = SoWin::init(argv[0]);
  SoSeparator * root = new SoSeparator;
  // fil de fer
  SoDrawStyle * drawStyle = new SoDrawStyle;
  drawStyle->style = SoDrawStyle::LINES;
  root->addChild(drawStyle);
  // échenillage de face arrière
  SoShapeHints * shapeHints = new SoShapeHints;
  shapeHints->vertexOrdering = SoShapeHints::COUNTERCLOCKWISE;
  shapeHints->shapeType = SoShapeHints::SOLID;
  root->addChild(shapeHints);
  // garder une couleur unie
  SoLightModel * lightModel = new SoLightModel;
  lightModel->model = SoLightModel::BASE_COLOR;
  root->addChild(lightModel);
  // un cône
  SoCone * cone = new SoCone;
  root->addChild(cone);
  // configurer une fenêtre
  SoWinExaminerViewer * viewer = new SoWinExaminerViewer(window);
  SbViewportRegion vpRegion = viewer->getViewportRegion();
  viewer->setSceneGraph(root);
  viewer->show();
  SoWin::mainLoop();
  delete viewer;
  return 0;
}

Les paramètres par défaut du système de rendu sont optimisés pour la commodité du programmeur. Par exemple, par défaut, les deux côtés de tous les polygones sont rendus pour éviter tout « trou » dans la géométrie si l'ordre des sommets venait à différer entre différents polygones.

Si le programmeur renonce à une partie de cette commodité et utilise des nœuds SoShapeHints pour spécifier plus précisément les informations sur la géométrie du graphe de scène, les indices fournis par le nœud (ou les nœuds) SoShapeHints seront alors utilisés par le sous-système de rendu pour éviter certaines opérations coûteuses. Des gains significatifs en vitesse de rendu pourraient en résulter.

Notez que la manière dont l'échenillage de face arrière et l'éclairage bidirectionnel sont décidés par le système de rendu n'est pas du tout intuitive. Voici les règles courantes sur la façon dont les formes primitives se rendent en fonction des valeurs des champs SoShapeHints::vertexOrdering et SoShapeHints::shapeType :

  • vertexOrdering == CLOCKWISE ou COUNTERCLOCKWISE, shapeType == SOLID : provoque l'échenillage de face arrière des primitives et leur rendu avec un éclairage unilatéral.
  • vertexOrdering == CLOCKWISE ou COUNTERCLOCKWISE, shapeType == UNKNOWN_SHAPE_TYPE : les primitives ne sont *pas* échenillées par face arrière et sont rendues avec un éclairage bidirectionnel.
  • vertexOrdering == UNKNOWN_ORDERING, quel que soit shapeType : les primitives ne sont *pas* échenillées par face arrière et sont rendues avec un éclairage unilatéral. L'ordre des sommets OpenGL sera défini sur l'ordre antihoraire.

L'énumération UNKNOWN_ORDERING a une signification spéciale et peu intuitive. L'ordre est en fait défini sur antihoraire – en OpenGL et lors de la génération des normales. Cependant, si vous souhaitez rendre votre géométrie avec un éclairage unilatéral et l'échenillage de face arrière désactivé, vous devez utiliser cette valeur d'énumération, et vos polygones doivent être en ordre antihoraire.

FORMAT DE FICHIER/DÉFAUTS :

ShapeHints {
    vertexOrdering UNKNOWN_ORDERING
    shapeType UNKNOWN_SHAPE_TYPE
    faceType CONVEX
    creaseAngle 0
}

Detailed Description

This node provides hints to the rendering system about the nature of the geometry that follows it in the scene graph. This allows the rendering system to optimize its behavior, for instance by enabling or disabling certain internal checks or operations.

The hints can be used to optimize the rendering of complex polygons by allowing Coin to check for convexity and also to determine the winding order of faces. The winding order is important to determine if faces are front-facing or back-facing, which in turn can be used for backface culling.

Note that SoShapeHints can also be used to pass information about the creaseAngle to be used when generating normals for the geometry.

The internal tessellator is used by Coin to break up complex polygons into triangles before they are passed on to the underlying OpenGL immediate mode rendering system. The tessellator is enabled by default when complex polygons are detected. However, the tessellator has some limitations, and for certain complex polygons, it might fail to break them up correctly. In such cases, you may want to disable the tessellator by setting the faceType field to SoShapeHints::CONVEX.

So if you are seeing weird artifacts in how complex polygons are rendered, try to change the SoShapeHints::faceType field to this value and see if they are then rendered correctly.

Beware that turning on this functionality might have the effect of making the rendering performance worse. If it has a noticeable effect on your particular scene graph, we advise that you investigate whether you could change how the polygons are generated for Coin rendering and then avoid using this flag.

enum SoShapeHints::VertexOrdering

Enumeration of different vertex orderings.

Enumerator

UNKNOWN_ORDERING
The vertex ordering is unknown. No backface culling will be performed. This is the default value.
CLOCKWISE
Vertices are ordered clockwise. Backface culling is enabled.
COUNTERCLOCKWISE
Vertices are ordered counter-clockwise. Backface culling is enabled.

enum SoShapeHints::ShapeType

Enumeration of different shape types.

Enumerator

UNKNOWN_SHAPE_TYPE
The shape type is unknown. The rendering system will assume that shapes may be open and will not perform optimizations based on shape type. This is the default value.
SOLID
The shape is known to be solid (closed). This allows certain optimizations to be performed.
SHELL
The shape is known to be a shell (open). This allows certain optimizations to be performed.

enum SoShapeHints::FaceType

Enumeration of different face types.

This enumeration is used to control how complex polygons are handled by Coin's internal tessellator. The tessellator is used to break up complex polygons into triangles before they are passed on to the underlying OpenGL immediate mode rendering system.

The OpenGL rendering system handles most complex polygon types, but not all: it can for instance have problems with many-sided, concave polygons (concave polygons are "hollow", that is: rounded inwards). Coin's internal tessellator will most often handle the cases that OpenGL fails on.

So if you are seeing weird artifacts in how complex polygons are rendered, try to change the SoShapeHints::faceType field to this value and see if they are then rendered correctly.

Beware that turning on this functionality might have the effect of making the rendering performance worse. If it has a noticeable effect on your particular scene graph, we advise that you investigate whether you could change how the polygons are generated for Coin rendering and then avoid using this flag.

CONVEX
Subsequent faces are all convex, so turn off the check for and tessellation of not convex faces.

Subsequent polygons from faceset-type nodes (like SoFaceSet and SoIndexedFaceSet) will be sent unmodified to OpenGL, thereby assuming that the polygons are in a form handled by OpenGL.

enum SoShapeHints::WindingType

Enumeration of different winding types.

Enumerator

NO_WINDING_TYPE
Draw without holes.

SoSFEnum SoShapeHints::vertexOrdering

Specifies how vertices are ordered for polygon faces.

Set this field to SoShapeHints::CLOCKWISE or SoShapeHints::COUNTERCLOCKWISE if possible to turn on backface culling and thereby optimize rendering.

Default value is SoShapeHints::UNKNOWN_ORDERING.

SoSFEnum SoShapeHints::shapeType

Hint about whether or not shapes are known to be "closed". Default value is SoShapeHints::UNKNOWN_SHAPE_TYPE.

SoSFEnum SoShapeHints::faceType

Hint about whether or not polygon faces are known to be convex. Default value is SoShapeHints::CONVEX.

SoSFEnum SoShapeHints::windingType

Hint about the winding type that is used to define holes in a polygon. Default value is SoShapeHints::NO_WINDING_TYPE, i.e. no winding type is used and therefore no holes are drawn. Up to now Coin does not support other winding types than the default.

SoSFFloat SoShapeHints::creaseAngle

When normals are automatically generated by Coin (i.e. SoNormal nodes are not used), this is the smallest angle between two faces where we would still calculate normals to do flat shading.

If the angle between the normals of two neighboring faces is less than the value of this field, the faces will be smooth shaded around their common edge.

The angle is specified in radians, and the default value is 0.0, meaning no smoothing will be done by default.
