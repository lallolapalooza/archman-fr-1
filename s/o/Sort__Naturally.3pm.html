Sort::Naturally(3) Documentation Perl fournie par l'utilisateur Sort::Naturally(3)

NOM

Sort::Naturally -- trier lexicalement, mais trier les parties numériques numériquement

SYNTAXE

@them = nsort(qw(
 foo12a foo12z foo13a foo 14 9x foo12 fooa foolio Foolio Foo12a
));
print join(' ', @them), "\n";

Affiche :

9x 14 foo fooa foolio Foolio foo12 foo12a Foo12a foo12z foo13a

(Ou "foo12a" + "Foo12a" et "foolio" + "Foolio" pourraient être échangés, en fonction de votre locale.)

DESCRIPTION

Ce module exporte deux fonctions, "nsort" et "ncmp" ; elles sont utilisées pour implémenter mon idée d'un algorithme de "tri naturel". Sous le tri naturel, les sous-chaînes numériques sont comparées numériquement, et les autres caractères de mots sont comparés lexicalement.

Voici comment je définis le tri naturel :

  • Les sous-chaînes de caractères de mots non numériques sont triées lexicalement, insensible à la casse : "Foo" vient entre "fish" et "fowl".
  • Les sous-chaînes numériques sont triées numériquement : "100" vient après "20", pas avant.
  • Les sous-chaînes \W (ni caractères de mot ni chiffres) sont *ignorées*.
  • Notre utilisation de \w, \d, \D et \W dépend de la locale : Sort::Naturally utilise une instruction "use locale".
  • Lors de la comparaison de deux chaînes, où une sous-chaîne numérique à un endroit n'est *pas* à côté d'une sous-chaîne numérique à un autre endroit, le non-numérique vient toujours en premier. Ceci est simulé en lisant en prétendant que l'absence d'une sous-chaîne numérique a la valeur -1, comme suit : 
    foo       =>  "foo",  -1
foobar    =>  "foo",  -1,  "bar"
foo13     =>  "foo",  13,
foo13xyz  =>  "foo",  13,  "xyz"

    C'est pour que "foo" vienne avant "foo13", qui vient avant "foobar".

  • Le début d'une chaîne est exceptionnel : les composants non-\W (non-mot, non-chiffre) en tête sont ignorés, et les nombres viennent *avant* les lettres.
  • Je définis "sous-chaîne numérique" simplement comme des séquences correspondant à m/\d+/ -- les notations scientifiques, les virgules, les décimales, etc., ne sont pas vues. Si vos données contiennent des séparateurs de milliers dans les nombres ("20 000 lieues sous les mers"), envisagez de les supprimer avant de les fournir à "nsort" ou "ncmp".

La fonction nsort

Cette fonction prend une liste de chaînes, et retourne une copie de la liste, triée.

C'est ce que la plupart des gens voudront utiliser :

@stuff = nsort(...liste...);

Lorsque nsort doit comparer des sous-chaînes non numériques, elle utilise la fonction "lc" de Perl dans le contexte de <use locale>. Et lorsque nsort doit mettre en minuscules des chaînes, elle utilise la fonction "lc" de Perl dans le contexte de <use locale>. Si vous voulez que nsort utilise d'autres fonctions à la place, vous pouvez les spécifier dans un arrayref comme premier argument de nsort :

@stuff = nsort( [
                  \&comparateur_de_chaîne,   # optionnel
                  \&fonction_minuscules  # optionnel
                ],
                ...liste...
              );

Si vous voulez spécifier un comparateur de chaîne mais pas de mise en minuscules, alors la liste d'options est "[\&comparateur, '']" ou "[\&comparateur]". Si vous voulez spécifier aucun comparateur de chaîne mais une mise en minuscules, alors la liste d'options est "['', \&minuscules]".

Tout comparateur que vous spécifiez est appelé comme "$comparateur->($gauche, $droite)", et, comme un remplacement normal de "cmp" de Perl, doit retourner -1, 0 ou 1 selon que l'argument gauche est lexicographiquement inférieur, égal ou supérieur à l'argument droit.

Toute fonction de mise en minuscules que vous spécifiez est appelée comme "$minuscules = $fonction_minuscules->($original)". La routine ne doit pas modifier son $_[0].

La fonction ncmp

Souvent, lors du tri de valeurs non-chaînes comme ceci :

@objets_tries = sort { $a->tag cmp $b->tag } @objets;

...ou même dans une transformation de Schwartz, comme ceci :

@chaines =
  map $_->[0]
  sort { $a->[1] cmp $b->[1] }
  map { [$_, cle_de_tri_a_partir_de($_) ]
  @_
;

...vous pourriez vouloir quelque chose qui remplace non pas "sort", mais "cmp". C'est à cela que sert la fonction "ncmp" de Sort::Naturally. Appelez-la avec la syntaxe "ncmp($gauche,$droite)" au lieu de "$gauche cmp $droite", mais sinon c'est un bon remplacement :

@objets_tries = sort { ncmp($a->tag,$b->tag) } @objets;
@chaines =
  map $_->[0]
  sort { ncmp($a->[1], $b->[1]) }
  map { [$_, cle_de_tri_a_partir_de($_) ]
  @_
;

Tout comme "nsort" peut accepter différents comparateurs de chaînes et/ou fonctions de mise en minuscules, vous pouvez faire de même avec "ncmp", en passant un arrayref comme premier argument :

ncmp( [
        \&comparateur_de_chaîne,   # optionnel
        \&fonction_minuscules  # optionnel
      ],
      $gauche, $droite
    )

Vous pourriez obtenir des comparateurs de chaînes de Sort::ArbBiLex.

NOTES

  • Ce module ne remplace pas Sort::Versions ! Si vous avez juste besoin d'un tri de versions correct, utilisez *celui-là* !
  • Si vous avez besoin de quelque chose qui fonctionne *à peu près* comme les fonctions de ce module, mais pas exactement pareil, envisagez de parcourir le code source de ce module, et d'adapter ce que vous voyez. Outre les fonctions qui compilent réellement dans ce module, après le POD, il y a plusieurs tentatives alternatives de ma part pour des routines de tri naturel, qui ne sont pas compilées dans le module, mais que vous pourriez trouver utiles. Elles devraient toutes être des implémentations *fonctionnelles* d'algorithmes légèrement différents (toutes basées sur le "nsort" de Martin Pool) que j'ai fini par abandonner au profit de mon algorithme. Si vous avez à trier naturellement des jeux de données *très volumineux*, et que le tri devient déraisonnablement lent, vous pourriez envisager d'essayer l'une de ces fonctions abandonnées -- j'ai le sentiment qu'elles pourraient être plus rapides sur de grands jeux de données. Testez-les sur vos données et voyez. (Sauf si vous avez *besoin* de la vitesse, ne vous embêtez pas. Indice : substituez "sort" à "nsort" dans votre code, et sauf si votre programme s'accélère considérablement, ce n'est pas le tri qui ralentit les choses. Mais s'il s'agit bien de "nsort" qui ralentit les choses, envisagez simplement : 
    if(@set >= UN_NOMBRE_TRÈS_GRAND) {
  no locale; # vroom vroom
  @triées = sort(@set);  # feh, c'est suffisant
} elsif(@set >= UN_NOMBRE_GRAND) {
  use locale;
  @triées = sort(@set);  # feh, c'est suffisant
} else {
  # mais gardons-le joli pour les cas normaux
  @triées = nsort(@set);
}

Sort::Naturally(3pm)

Sort::Naturally — Provides natural sorting.

NOM

Sort::Naturally - Provides natural sorting.

SYNTAXE

  use Sort::Naturally;

  @sorted = sort natural @list;
  @sorted = sort &naturalcmp(@list);

DESCRIPTION

This module provides a function to sort a list of strings naturally. Natural sorting is a sorting algorithm that sorts strings containing numbers in the way a human would expect. For example, a natural sort order of "file1.txt", "file10.txt", "file2.txt" would be "file1.txt", "file2.txt", "file10.txt". This is in contrast to a standard lexicographical sort, which would sort the strings as "file1.txt", "file10.txt", "file2.txt".

The module exports two subroutines:

  • natural: This is a sort subroutine that can be used with the sort builtin function. It sorts the list in place.

  • naturalcmp: This is a comparison subroutine that returns -1, 0, or 1 depending on whether the first argument is less than, equal to, or greater than the second argument. This can also be used with the sort builtin function.

Example:

  use Sort::Naturally;

  my @files = ( "file10.txt", "file1.txt", "file2.txt" );
  my @sorted_files = sort natural @files;
  # @sorted_files is now ( "file1.txt", "file2.txt", "file10.txt" )

  my @numbers = ( "10", "1", "2" );
  my @sorted_numbers = sort naturalcmp @numbers;
  # @sorted_numbers is now ( "1", "2", "10" )

NOTES

The sorting algorithm used is a simple one that splits strings by non-digit characters and then compares the resulting parts. Numeric parts are compared as numbers, while non-numeric parts are compared lexicographically.
