Description Détaillée

La classe SoVRMLLOD est utilisée pour représenter différents niveaux de détail en fonction de la distance.

La documentation détaillée de la classe est extraite textuellement de la norme VRML97 (ISO/IEC 14772-1:1997). Elle est copyright par The Web3D Consortium et est utilisée avec la permission du Consortium :

LOD {
  exposedField MFNode  level    []
  field        SFVec3f center   0 0 0    # (-,)
  field        MFFloat range    []       # (0,)
}

Le nœud LOD spécifie différents niveaux de détail ou de complexité pour un objet donné, et fournit des indications permettant aux navigateurs de choisir automatiquement la version appropriée de l'objet en fonction de la distance par rapport à l'utilisateur. Le champ level contient une liste de nœuds qui représentent le même objet ou des objets à différents niveaux de détail, ordonnés du niveau de détail le plus élevé au niveau de détail le plus bas. Le champ range spécifie les distances idéales auxquelles passer d'un niveau à l'autre. Le sous-clause 4.6.5, Nœuds de regroupement et enfants (http://www.web3d.org/documents/specifications/14772/V2.0/part1/concepts.html#4.6.5), contient des détails sur les types de nœuds qui sont des valeurs légales pour level.

Le champ center est un décalage de translation dans le système de coordonnées local qui spécifie le centre du nœud LOD pour les calculs de distance.

Le nombre de nœuds dans le champ level doit dépasser d'un le nombre de valeurs dans le champ range (c'est-à-dire N+1 valeurs de niveau pour N valeurs de plage). Le champ range contient des valeurs monotones croissantes qui doivent être supérieures à zéro. Afin de calculer quel niveau afficher, la distance est d'abord calculée depuis la position du spectateur, transformée dans le système de coordonnées local du nœud LOD (y compris toute transformation d'échelle), jusqu'au point central du nœud LOD. Ensuite, le nœud LOD évalue la fonction échelon L(d) pour choisir un niveau pour une valeur donnée de d (où d est la distance de la position du spectateur au centre du nœud LOD). Soit n plages, R0, R1, R2, ..., Rn-1, qui partitionnent le domaine (0, +infini) en n+1 sous-intervalles donnés par (0, R0), [R0, R1)... , [Rn-1, +infini). Soient également n niveaux L0, L1, L2, ..., Ln-1 les valeurs de la fonction échelon L(d). Le nœud de niveau, L(d), pour une distance donnée d est défini comme suit :

  L(d) = L0,   si d < R0,
       = Li+1, si Ri <= d < Ri+1, pour -1 < i < n-1,
       = Ln-1, si d >= Rn-1.

Spécifier trop peu de niveaux entraînera l'utilisation répétée du dernier niveau pour les niveaux de détail les plus bas. Si plus de niveaux que de plages sont spécifiés, les niveaux supplémentaires sont ignorés. Une plage vide est une exception à cette règle. Ce cas est une indication pour le navigateur qu'il peut choisir un niveau automatiquement pour maintenir un taux d'affichage constant. Chaque valeur du champ range doit être supérieure à la valeur précédente.

Les nœuds LOD sont évalués de haut en bas dans le graphe de scène. Seuls les descendants du niveau actuellement sélectionné sont rendus. Tous les nœuds sous un nœud LOD continuent de recevoir et d'envoyer des événements, quel que soit le niveau LOD actif. Par exemple, si un TimeSensor actif est contenu dans un niveau inactif d'un nœud LOD, le TimeSensor envoie des événements indépendamment de l'état du nœud LOD.

SbBool SoVRMLLOD::affectsState (void ) const [virtual]

Retourne TRUE si le nœud peut avoir un effet sur l'état lors du parcours.

S'il retourne FALSE, aucune donnée dans l'état de parcours ne changera entre l'état avant parcours et l'état après parcours. Le nœud SoSeparator, par exemple, retournera FALSE, car il pousse et dépile l'état avant et après le parcours de ses enfants. Tous les nœuds SoShape retourneront également FALSE, car le simple envoi de données géométriques au moteur de rendu n'affectera pas l'état de rendu réel.

La méthode par défaut retourne TRUE, selon la philosophie du "mieux vaut prévenir que guérir".

TRUE ou FALSE est retourné, selon que l'instanciation et la configuration du nouvel objet de ce type de classe se sont déroulées correctement ou non. Le processus d'importation doit être robuste et gérer les flux d'entrée corrompus en retournant FALSE.

flags est utilisé en interne lors de l'importation binaire lors de la lecture de nœuds d'extension utilisateur, de nœuds de groupe ou de moteurs.

void SoVRMLLOD::copyContents (const SoFieldContainer * from, SbBool copyconnections) [protected], [virtual]

Crée une copie profonde de toutes les données de from dans cette instance, sauf les références externes du graphe de scène si copyconnections est FALSE.

C'est la méthode qui devrait être surchargée par les sous-classes de nœuds d'extension / moteurs / draggers / etc. qui ont besoin de prendre en compte des données internes qui ne sont pas gérées automatiquement.

Pour copier des nœuds depuis le code de l'application, vous ne devez pas appeler cette fonction directement, mais plutôt appeler la fonction SoNode::copy():

SoNode * mynewnode = templatenode->copy();

Il en va de même pour les moteurs.

Assurez-vous que lorsque vous surchargez la méthode copyContents() dans votre classe d'extension, vous l'appelez également vers sa super-classe parente dans la hiérarchie d'héritage, car copyContents() dans par exemple SoNode et SoFieldContainer effectue un travail important. Cela devrait ressembler à ceci:

void
MyCoinExtensionNode::copyContents(const SoFieldContainer * from,
                                  SbBool copyconnections)
{
  // laisser les super-classes parentes faire leur travail (copier les champs, copier
  // le nom de l'instance, etc.)
  SoNode::copyContents(from, copyconnections);
  // [..puis copier les données internes..]
}

NAME

SoVRMLLOD — Node for Level Of Detail (LOD) functionality, inspired by VRML97.

SYNOPSIS

Inherits from SoNode.

SoVRMLLOD {
  MFNode  children      []
  SFNode  activeLevel   NULL
  SFBool  disableAutoSwitch TRUE
}

Detailed Description

This node is the Coin equivalent of the VRML97 "LevelOfDetail" node. It is used to group several child nodes, each representing a different level of detail for the same object. The scene graph traversal mechanism automatically selects the most appropriate child node to render based on the distance of the camera from the object. This allows for optimization of rendering complexity.

The SoVRMLLOD node can also be configured to manually switch between detail levels using the activeLevel field, or to disable the automatic switching altogether using the disableAutoSwitch field.
