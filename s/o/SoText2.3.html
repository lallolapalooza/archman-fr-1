Description Détaillée

La classe SoText2 est un type de nœud pour afficher du texte 2D aligné avec le plan de la caméra.

Le texte SoText2 n'est pas mis à l'échelle en fonction de la distance par rapport à la caméra et n'est pas influencé par la rotation ou la mise à l'échelle comme les principes 3D. Si ce sont des propriétés que vous souhaitez que le texte ait, vous devez utiliser un nœud SoText3 ou SoAsciiText à la place.

Note : Bien que la taille du texte 2D ne soit pas influencée par la distance par rapport à la caméra, le texte est toujours soumis aux règles habituelles concernant la boîte de profondeur, il sera donc *masqué* par le graphique situé devant.

Le texte sera positionné *par défaut* en fonction de la transformation actuelle. La position x du texte est le premier pixel du caractère le plus à gauche du texte. La position y du texte est la ligne de base du premier paragraphe de texte (la ligne de base est la ligne imaginaire sur laquelle reposent toutes les lettres majuscules).

La taille des polices à l'écran est déterminée par le champ SoFont::size d'un nœud SoFont utilisé précédemment dans la scène, qui spécifie la taille en unités de pixels. Cette valeur définit approximativement la dimension verticale des lettres. La valeur par défaut si aucun nœud SoFont n'est utilisé est 10.

Un problème important concernant les performances de rendu : comme le positionnement et le rendu d'un nœud SoText2 dépendent du viewport et de la caméra actuels, la présence de nœuds SoText2 dans la scène peut entraîner une dépendance de cache par rapport aux nœuds SoCamera rencontrés précédemment. Cela peut avoir une influence négative considérable sur les performances de rendu, car si la caméra est située au-dessus du nœud SoSeparator le plus proche du SoText2, le SoSeparator ne pourra pas mettre en cache la géométrie en dessous.

(Des performances de rendu encore plus mauvaises seront imposées si l'indicateur SoSeparator::renderCaching est explicitement défini sur ON, car le nœud SoSeparator générera et détruira continuellement le même cache pendant que la caméra se déplace.)

NAME

SoText2 - 2D text node

SYNOPSIS

#include <Inventor/nodes/SoText2.h>

SoNode {
  // Field declarations
  MFString      string
  SFFloat       spacing
  SFEnum        justification
}

Detailed Description

This node represents a 2D text string. The text is rendered using bitmap fonts.

The text is rendered in the XY plane. The text is aligned such that the first string's baseline is on the X-axis at the origin.

The SoText2 node should be used in conjunction with an SoFont node. The SoFont node determines which font is used to render the text. In addition, the SoFontStyle node can be used to specify the font family, style and size.

The appearance of the text can be further controlled by SoMaterial nodes, which set the text color, transparency, etc.

The origin of the text is at the baseline of the first line of text. The X axis points to the right, and the Y axis points upwards. The Z axis is perpendicular to the XY plane.

The string field specifies the text string(s) to be rendered. Each string in the field is rendered on a separate line.

The spacing field controls the vertical spacing between lines. A value of 1.0 means that the spacing is equal to the height of the highest character in the font's bitmap alphabet. Smaller values will result in text lines overlapping.

The justification field controls the horizontal alignment of the text strings. It can be set to LEFT, RIGHT, or CENTER. The alignment is relative to the origin, which is located at the baseline of the first line of text.

Note that SoText2 nodes are intended for use with static geometry. If you need to animate the text, consider using a different text node, such as SoText3.

Also note that SoText2 nodes cache the ids and positions of each glyph bitmap used to render string. This means that USE of a DEF'ed SoText2 node, with a different font, will be noticeably slower than using two separate SoText2 nodes, one for each font, since it will have to recalculate glyph bitmap ids and positions for each call to GLrender().

SoScale nodes cannot be used to influence the dimensions of the rendering output of SoText2 nodes.

FILE FORMAT/DEFAULTS:

Text2 {
    string ""
    spacing 1
    justification LEFT
}

Member Data Documentation

SoMFString SoText2::string

The set of strings to render. Each string in the multiple value field will be rendered on a separate line.

The default value of the field is a single empty string.

SoSFFloat SoText2::spacing

Vertical spacing between the baselines of two consecutive horizontal lines. Default value is 1.0, which means that it is equal to the vertical size of the highest character in the bitmap alphabet.

SoSFEnum SoText2::justification

Determines horizontal alignment of text strings.

If justification is set to SoText2::LEFT, the left edge of the first string is at the origin and all strings are aligned with their left edges. If set to SoText2::RIGHT, the right edge of the first string is at the origin and all strings are aligned with their right edges. Otherwise, if set to SoText2::CENTER, the center of the first string is at the origin and all strings are aligned with their centers. The origin is always located at the baseline of the first line of text.

Default value is SoText2::LEFT.
