Fon

La clase SoTexture2 se utiliza para mapear una textura 2D a la geometría subsiguiente en el árbol de escena.

Las nodos de forma dentro del ámbito de nodos SoTexture2 (es decir, debajo de la misma SoSeparator y a la derecha del SoTexture2) tendrán aplicada la textura según las características individuales de cada tipo de forma. Consulte la documentación de los diferentes tipos de forma (SoFaceSet, SoCube, SoSphere, etc.) para obtener información sobre cómo se aplicará la textura.

Un ejemplo simple de uso puede encontrarse en la documentación de la clase SoSFImage.

Un error común en muchos programas que tienen soporte para exportar archivos VRML o Inventor es que se exporte el mismo archivo de texto varias veces, aunque se le asignen diferentes nodos. Esto puede causar un uso excesivo de memoria de texturas y un rendimiento lento. A continuación, se muestra un ejemplo de código que corrige este problema reemplazando todas las instancias de la misma textura con un puntero al primer nodo:

#include <Inventor/actions/SoSearchAction.h>
#include <Inventor/actions/SoWriteAction.h>;
#include <Inventor/nodes/SoSeparator.h>;
#include <Inventor/nodes/SoTexture2.h>;
#include <Inventor/SoDB.h>;
#include <Inventor/SoInput.h>;
#include <Inventor/SoOutput.h>;
int main(int argc, char ** argv)
{
  if (argc < 2) return -1;
  SoDB::init();
  SoInput in;
  if (!in.openFile(argv[1])) return -1;
  SoSeparator * root = SoDB::readAll(&in);
  if (!root) return -1;
  root->ref();
  SoSearchAction sa;
  sa.setType(SoTexture2::getClassTypeId());
  sa.setInterest(SoSearchAction::ALL);
  sa.setSearchingAll(TRUE);
  sa.apply(root);
  SoPathList & pl = sa.getPaths();
  SbDict namedict;
  for (int i = 0; i < pl.getLength(); i++) {
    SoFullPath * p = (SoFullPath*) pl[i];
    if (p->getTail()->isOfType(SoTexture2::getClassTypeId())) {
      SoTexture2 * tex = (SoTexture2*) p->getTail();
      if (tex->filename.getValue().getLength()) {
        SbName name = tex->filename.getValue().getString();
        unsigned long key = (unsigned long) ((void*) name.getString());
        void * tmp;
        if (!namedict.find(key, tmp)) {
          // nuevo texto. solo insertar en la lista
          (void) namedict.enter(key, tex);
        }
        else if (tmp != (void*) tex) { // reemplazar con el nodo encontrado en la lista
          SoGroup * parent = (SoGroup*) p->getNodeFromTail(1);
          int idx = p->getIndexFromTail(0);
          parent->replaceChild(idx, (SoNode*) tmp);
        }
      }
    }
  }
  sa.reset();
  // salida del escenario con texto fijado a stdout
  SoOutput out;
  SoWriteAction wa(&out);
  wa.apply(root);
  root->unref();
}

Cuando se trabaja con archivos Inventor, uno suele querer incorporar archivos de texto de texturas externos en los archivos Inventor mismos. A continuación, se muestra un ejemplo mínimo y independiente que muestra cómo puede lograrse mediante la llamada a SoField::touch() sobre los campos SoTexture2::image antes de la exportación del árbol de escena:

#include <Inventor/SoDB.h>;
#include <Inventor/nodes/SoSeparator.h>;
#include <Inventor/nodes/SoTexture2.h>;
#include <Inventor/actions/SoSearchAction.h>;
#include <Inventor/actions/SoWriteAction.h>;
int
main(void)
{
  if (argc == 1) {
    fprintf(stderr,"Uso: %s <infile> > outfile.iv\n", argv[0]);
    return -1;
  }
  SoDB::init();
  // abrir el archivo (no usar stdin) para que Coin pueda buscar texturas relacionadas con el archivo de entrada.
  SoInput in;
  if (!in.openFile(argv[1])) {
    return -1;
  }
  SoSeparator * root = SoDB::readAll(&in);
  if (!root) { exit(1); }
  root->ref();
  SoSearchAction searchaction;
  searchaction.setType(SoTexture2::getClassTypeId());
  searchaction.setSearchingAll(TRUE);
  searchaction.setInterest(SoSearchAction::ALL);
  searchaction.apply(root);
  const SoPathList & pl = searchaction.getPaths();
  for (int i=0; i < pl.getLength(); i++) {
    SoFullPath * fp = (SoFullPath *)pl[i];
    SoTexture2 * tex = (SoTexture2 *)fp->getTail();
    assert(tex->getTypeId() == SoTexture2::getClassTypeId());
    tex->image.touch();
  }
  SoWriteAction wa;
  wa.apply(root);
  root->unref();
  return 0;
}

Mantén toda la estructura del archivo. L">DECAL
Image de texture surimpose le ombrage des polygones. Les pixels texturés ne seront pas recouverts par le ombrage Phong. Comportement indéfini pour les textures en niveaux de gris et gris-alpha.
BLEND
Ce modèle est généralement utilisé avec des textures monochromes (c'est-à-dire des textures à un ou deux composants). Le premier composant, l'intensité, est utilisé pour le mélange entre la couleur ombrée d'un polygone et SoTexture2::blendColor.
REPLACE
Image de texture surimpose le ombrage des polygones. Les pixels texturés ne seront pas recouverts par le ombrage Phong. Prend en charge les textures en niveaux de gris et gris-alpha. Cette fonctionnalité nécessite OpenGL 1.1. MODULATE sera utilisé si une version d'OpenGL inférieure à 1.1 est détectée.

Note : L'utilisation de ce modèle de texture rendra vos fichiers Inventor incompatibles avec les anciennes versions de Coin et Inventor. Vous avez besoin de Coin >= 2.2 ou TGS Inventor 4.0 pour charger des fichiers Inventor qui utilisent le modèle de texture REPLACE.

SoSFString SoTexture2::filename

Nom du fichier de texture, faisant référence à un fichier au format bitmap image sur disque.

Par défaut, il contient une chaîne vide, ce qui signifie que la texture sera lue à partir de SoTexture2::image et non du disque. (Spécifiez cette propriété ou utilisez SoTexture2::image, pas les deux).

FIXME : La section sur simage est obsolète.

Pour lire des fichiers image depuis le disque, Coin utilise la bibliothèque « simage » de Kongsberg Oil & Gas Technologies. Cette bibliothèque doit être installée pour pouvoir charger des fichiers image.

L'ensemble des formats d'image que vous pouvez lire dépend en fait de la manière dont la bibliothèque simage a été compilée, car simage dépend elle-même de bibliothèques d'importation/exportation de fichiers de bas niveau (par exemple, prise en charge de JPEG, GIF, TIFF et PNG). Pour vous assurer que tous les formats souhaités sont disponibles, vous devriez compiler vous-même la bibliothèque simage.

L'ensemble des formats d'image garantis par simage sont Targa (.tga), PIC (.pic), SGI RGB (.rgb, .bw) et XWD (.xwd).

Pour plus d'informations sur la bibliothèque simage, y compris les instructions de téléchargement et de compilation, consultez le dépôt Coin.

SoSFEnum SoTexture2::wrapT

Stratégie d'enroulement pour la coordonnée T lorsque la texture est plus courte que l'objet à mapper. La valeur par défaut est SoTexture2::REPEAT.

SoSFEnum SoTexture2::model

Modèle de texture pour la manière dont la texture est "mélangée" avec les primitives polygonales auxquelles elle est appliquée. La valeur par défaut est SoTexture2::MODULATE.

SoSFColor SoTexture2::blendColor

Couleur de mélange. Utilisée lorsque SoTexture2::model est SoTexture2::BLEND. La valeur par défaut est [0, 0, 0], noir, ce qui signifie qu'aucune contribution n'est apportée au mélange.

SoSFBool SoTexture2::enableCompressedTexture

Indication à Coin d'utiliser des textures compressées si celles-ci sont prises en charge par le matériel graphique et les pilotes OpenGL. L'utilisation de textures compressées réduit généralement l'utilisation de la mémoire de texture pour une texture de 4 à 6 fois.
