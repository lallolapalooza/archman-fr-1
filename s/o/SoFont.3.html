Detailed Description

La classe SoFont est un nœud d'apparence pour définir des polices.

Les nœuds de rendu de texte successifs (comme SoText2, SoText3, SoAsciiText, etc.) utiliseront la police spécifiée par un nœud SoFont lors de l'affichage du texte.

Le nom de la police est reconnu dans le format « famille:style ». La gamme des familles de polices supportées dépend des polices installées sur le système. Une famille de polices typique pourrait être « Arial » ou « Times NewRoman ».

Le style peut être « Bold », « Italic » ou « Bold Italic ».

Les espaces avant ou après « : » seront ignorés.

Si une correspondance satisfaisante pour la police choisie ne peut être trouvée, la police par défaut sera chargée. La police par défaut 2D est une police bitmap intégrée de 8x12 points. La police 3D est une police avec empattements, dans le style de Times New Roman. Il n'est pas possible d'appliquer des styles à l'une des polices bitmap intégrées. Il n'est pas possible de spécifier une taille pour la police bitmap 2D par défaut.

La police par défaut peut être explicitement sélectionnée en réglant « defaultFont » comme nom de police, ou simplement en laissant le champ SoFont::name vide, car c'est sa valeur par défaut. Dans ce sens, notez que SoFont n'hérite pas / n'accumule pas les parties des nœuds SoFont précédents, même si l'un ou l'autre de ses champs est vide, par exemple dans un fichier .iv, comme ceci :

#Inventor V2.1 ascii
Font { name "Helvetica"  size 50 }
Text2 { string "hepp" }
Translation { translation 5 80 0 }
BaseColor { rgb 1 1 0 }
Font { size 30 }
Text2 { string "svupp" }

(La seconde chaîne dans l'exemple ci-dessus sera rendue avec la police par défaut, pas en Helvetica.)

Les polices par défaut sont toujours accessibles par Coin car elles sont intégrées dans la bibliothèque d'exécution. Si vous voulez garantir que le texte ait la même apparence dans tous les cas, la police par défaut sera un choix sûr. Une autre solution pourrait être d'utiliser le moteur de polices *FreeType* et de spécifier un fichier de polices. Cette information est décrite plus loin.

Voici un exemple simple d'impression d'une chaîne en utilisant une police Arial gras et italique :

#Inventor V2.1 ascii
Separator {
   Font {
     name "Arial:Bold Italic"
     size 14
   }
   Text2 {
     string ["This is a", "Coin font test"]
     justification CENTER
   }    
}

Coin prend en charge deux API de polices différentes. Sur les plateformes non Windows, la bibliothèque *FreeType* ainsi que la bibliothèque optionnelle *Fontconfig* sont utilisées.

Si la bibliothèque *Fontconfig* est installée, l'emplacement du fichier de polices pour une police donnée est trouvé grâce à elle. Pour plus d'informations sur *Fontconfig*, voir http://freedesktop.org/software/fontconfig. De plus, *Fontconfig* permet de faire correspondre des polices spécifiques en utilisant sa propre syntaxe de correspondance (voir http://pdx.freedesktop.org/~fontconfig/fontconfig-user.html). Veuillez noter que la valeur de taille de point dans la représentation textuelle de la syntaxe de *Fontconfig* est actuellement remplacée par la taille du champ SoFont et si aucune taille n'est spécifiée, la valeur par défaut du champ s'applique. Dans le cas où vous souhaiteriez utiliser votre application sur des systèmes où la bibliothèque *Fontconfig* n'est pas attendue, vous ne devriez pas utiliser la syntaxe de correspondance de *Fontconfig*. L'utilisation de *Fontconfig* peut être désactivée en réglant la variable d'environnement « COIN_FORCE_FONTCONFIG_OFF » à 1.

Voici un exemple d'impression d'une chaîne en utilisant la syntaxe de correspondance de *Fontconfig* avec une police gras et italique où Times New Roman est la famille de polices préférée.

#Inventor V2.1 ascii
Separator {
   Font {
     name "Times New Roman,Arial,Helvetica:italic:bold"
     size 24
   }
   Text2 {
     string ["This is a", "Coin font test"]
     justification CENTER
   }    
}

Sous Windows, la bibliothèque GDI de Win32 est utilisée. Les bibliothèques *FreeType* et *Fontconfig* sont chargées dynamiquement par Coin si le support des polices est demandé dans un nœud. Lors du chargement du support des polices sous Windows, *FreeType* aura la priorité sur la bibliothèque GDI si elle est trouvée. Cela peut être empêché en réglant la variable d'environnement « COIN_FORCE_FREETYPE_OFF » à 1. Lors de l'utilisation de *FreeType*, la version 2.1 ou ultérieure de *FreeType* est requise. Sous Mac OS X, une version 2.1.7 ou ultérieure est requise.

Si Coin ne parvient pas à charger la bibliothèque *FreeType*, et que vous n'utilisez pas Windows, seules les polices par défaut seront disponibles.

Il est possible de spécifier directement une police TrueType si *FreeType* est utilisé comme moteur de polices. Ceci est réalisé en incluant le fichier « .ttf » dans le nom du fichier, par exemple « Comic_Sans_MS.ttf ». Coin recherchera alors dans le chemin local du programme en cours d'exécution et, ensuite, dans le chemin spécifié par la variable d'environnement « COIN_FONT_PATH ». Si le programme utilise *FreeType* sur une plateforme Windows, le dossier « $WINDIR/Fonts » sera également recherché.

Il n'est pas possible de spécifier directement une police TrueType si Windows gère les polices. Ceci est dû à la façon dont Windows accède aux polices via le registre du système. Toutes les polices doivent être correctement installées et avoir un nom système assigné. Ouvrez le « Panneau de configuration » et double-cliquez sur l'icône « Polices » pour obtenir un résumé des polices installées et de leurs noms.

Comme certaines versions non anglaises de Windows utilisent des noms différents pour les styles (par exemple, « Italique » au lieu de « Italic »), ces noms sont supportés dans Coin, mais il est recommandé de n'utiliser que les termes anglais pour une meilleure portabilité. Veuillez noter qu'il y a toujours une possibilité qu'aucune police n'utilise les termes « Bold » ou « Italic » installés sur la plateforme Windows. Pour garantir qu'une police soit accessible, vous devez utiliser la bibliothèque *FreeType* et inclure une police TrueType dans votre distribution, ou éviter d'utiliser les styles et vous en tenir aux polices standard de Windows.

Si la variable d'environnement « COIN_DEBUG_FONTSUPPORT » est réglée à 1, une grande quantité d'informations concernant le chargement, l'initialisation et l'utilisation des polices sera émise. Les problèmes tels que la non-disponibilité des polices et d'autres problèmes connexes seront rapportés, il est donc recommandé d'essayer d'abord cette option de débogage lorsque quelque chose ne fonctionne pas comme prévu.

Member Data Documentation

SoSFName SoFont::name

Name of font.

Which font names are available is rather system dependent, not only on whether or not you are running on a UNIX/Linux system, Microsoft Windows or whatever, but also on which fonts and font types (like TrueType) are installed on a particular user's system.

All font rendering nodes have a built-in fallback font to use, though, so even though Coin cannot find a font on the system of the specified type, the text should be rendered somehow.

In summation, consider this node type and this particular field as a hint to the font rendering engines of Coin, and do not base your models on a particular font being available.

SoSFFloat SoFont::size

Size of font. Defaults to 10.0.

For 2D rendered bitmap fonts (like for SoText2), this value is the height of a character in screen pixels. For 3D text, this value is the world space coordinates height of a character in the current units setting (see documentation for SoUnits node).

Documentation des données membres

SoSFName SoFont::name

Nom de la police.

Les noms de polices disponibles dépendent largement du système, pas seulement du fait que vous soyez sous un système UNIX/Linux, Microsoft Windows ou autre, mais aussi des polices et des types de polices (comme TrueType) installés sur le système d'un utilisateur particulier.

Tous les nœuds de rendu de police disposent d'une police de secours intégrée à utiliser, de sorte que même si Coin ne trouve pas de police sur le système du type spécifié, le texte devrait être rendu d'une manière ou d'une autre.

En résumé, considérez ce type de nœud et ce champ particulier comme un indice pour les moteurs de rendu de polices de Coin, et ne basez pas vos modèles sur la disponibilité d'une police particulière.

SoSFFloat SoFont::size

Taille de la police. Par défaut à 10.0.

Pour les polices bitmap rendues en 2D (comme pour SoText2), cette valeur est la hauteur d'un caractère en pixels à l'écran. Pour le texte 3D, cette valeur est la hauteur en coordonnées d'espace monde d'un caractère dans le réglage d'unités actuel (voir la documentation du nœud SoUnits).
