Description détaillée

La classe SoReorganizeAction réorganise votre graphe de scène pour optimiser la navigation/le rendu.

Remarque. Ceci est un travail en cours. pederb, 2005-04-05.

Le code suivant est un exemple de programme qui applique un SoReorganizeAction sur un graphe de scène, convertissant toutes les formes en formes qui peuvent être rendues en utilisant le rendu par sommet ou le VBO.

static void strip_node(SoType type, SoNode * root)
{
  SoSearchAction sa;
  sa.setType(type);
  sa.setSearchingAll(TRUE);
  sa.setInterest(SoSearchAction::ALL);
  sa.apply(root);
  SoPathList & pl = sa.getPaths();
  for (int i = 0; i < pl.getLength(); i++) {
    SoFullPath * p = (SoFullPath*) pl[i];
      if (p->getTail()->isOfType(type)) {
        SoGroup * g = (SoGroup*) p->getNodeFromTail(1);
        g->removeChild(p->getIndexFromTail(0));
      }
    }
  sa.reset();
}

Description détaillée


Cette action réorganise la hiérarchie de la scène. Elle peut être utilisée pour optimiser la structure du scenegraph, par exemple en fusionnant des groupes consécutifs ou en supprimant des nœuds inutiles.

Coin 2.5

void SoReorganizeAction::apply (SoPath * path)
  [virtual]


Applique l'action aux parties du graphe définies par path.


Note : Un SoPath contiendra également tous les nœuds qui pourraient l'influencer, par exemple, les nœuds de géométrie sur le chemin. Ainsi, appliquer une SoGLRenderAction à un SoPath rendra correctement le chemin dans la vue, où les matériaux, textures et autres configurations d'apparence seront correctement appliqués.


Si le path se termine sur un nœud SoGroup, l'action parcourra également les enfants du nœud final.

void   SoReorganizeAction::apply (const SoPathList & pathlist, SbBool   obeysrules = FALSE) [virtual]


Applique l'action aux graphes définis par pathlist. Si obeysrules est TRUE, pathlist doit obéir aux quatre conditions suivantes (ce qui est le cas pour les listes de chemins renvoyées par les actions de recherche pour les nœuds non-groupes et les listes de chemins renvoyées par les actions de sélection) :


Tous les chemins doivent commencer par le même nœud tête. Tous les chemins doivent être triés dans l'ordre de parcours. Les chemins doivent être uniques. Aucun chemin ne doit suivre le point final d'un autre chemin.

void   SoReorganizeAction::beginTraversal (SoNode * node) [protected],   [virtual]


Cette méthode virtuelle est appelée depuis SoAction::apply(), et est le point d'entrée pour le parcours de la hiérarchie de scène.


Elle peut être surchargée pour initialiser l'action au début du parcours, pour des initialisations spécifiques dans les sous-classes de SoAction héritant de SoAction.


L'implémentation par défaut appelle traverse(), qui doit être appelée par toute implémentation surchargée de cette méthode (ou appeler SoAction::beginTraversal()) pour démarrer le parcours de la hiérarchie.
