Description détaillée

La classe SoCache est la classe parente de toutes les classes de cache internes.

Elle organise le comptage de références pour permettre le partage d'instances de cache. Elle organise également une liste d'éléments qui affecteront le cache. Si l'un des éléments a changé depuis la création du cache, le cache est invalide.

L'algorithme de test des éléments de cache dans Coin fonctionne comme suit :

Chaque élément lu avant d'être écrit lors de la création d'un cache est stocké dans la liste des éléments du SoCache. Ceci est fait pour détecter quand quelque chose en dehors du cache a changé.

Exemple : vous avez un nœud SoCoordinate3 à l'extérieur d'un SoSeparator, mais un SoIndexedFaceSet à l'intérieur du SoSeparator. Si le SoSeparator crée un cache, SoIndexedFaceSet lira SoCoordinateElement, et comme SoCoordinateElement n'a pas été défini après l'ouverture du cache, le cache stocke cet élément dans la liste des dépendances du cache.

Lors de la trame suivante, le SoSeparator testera si le cache est valide, puis testera tous les éléments de dépendance. Si l'un des éléments ne correspond pas, le cache n'est pas valide et ne peut pas être utilisé.

Ce sont les bases. Il y a quelques étapes à suivre lors de la création d'un cache pour que les dépendances du cache fonctionnent. En gros, vous devez faire comme ceci :

SbBool storedinvalid = SoCacheElement::setInvalid(FALSE);
state->push();
SoMyCache * cache = new SoMyCache(state);
cache->ref();
SoCacheElement::set(state, cache);
buildMyCache();
state->pop();
SoCacheElement::setInvalid(storedinvalid);

Vous réinitialisez d'abord et stockez l'ancienne valeur du drapeau d'invalidation du cache. Ensuite, vous poussez l'état pour que le cache puisse détecter lorsque quelque chose en dehors du cache a changé (et pour pouvoir modifier l'élément du cache). Ensuite, vous créez le cache - n'oubliez pas de le référencer. Enfin, définissez le cache actuel dans l'élément de cache et construisez le cache. Après avoir construit le cache, vous retirez l'état et restaurez le drapeau de cache invalide.

Lors de la construction du cache, tous les éléments qui sont lus seront copiés dans le cache (en utilisant SoElement::copyMatchInfo()), et ces éléments copiés sont utilisés pour tester la validité du cache (dans SoCache::isValid()).

Vous n'avez pas besoin d'ajouter manuellement les dépendances des éléments. Elles seront automatiquement détectées lors de la création du cache. Ceci est géré dans SoElement::getConstElement().

Si vous souhaitez que le cache soit invalidé lorsque certains champs de votre nœud sont modifiés, il est courant de surcharger la méthode notify(), et d'appeler SoCache::invalidate() chaque fois que la méthode notify() de votre nœud est appelée. Voir par exemple SoShape::notify().

De plus, ne supprimez pas le cache dans votre méthode notify(). Attendez la prochaine fois que le cache sera nécessaire avant de déréférencer l'ancien cache.
