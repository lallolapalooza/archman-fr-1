La classe SoVRMLPlaneSensor mappe les mouvements du périphérique d'entrée en translations dans l'espace des objets.

La documentation détaillée de la classe SoVRMLPlaneSensor a été extraite littéralement de la norme VRML97 (ISO/IEC 14772-1:1997). Elle est soumise au droit d'auteur du consortium Web3D et utilisée avec la permission du détenteur de licence :

PlaneSensor {
  exposedField SFBool  autoOffset          TRUE
  exposedField SFBool  enabled             TRUE
  exposedField SFVec2f maxPosition         -1 -1     # (-,)
  exposedField SFVec2f minPosition         0 0       # (-,)
  exposedField SFVec3f offset              0 0 0     # (-,)
  eventOut     SFBool  isActive
  eventOut     SFVec3f trackPoint_changed
  eventOut     SFVec3f translation_changed
}

Le nœud PlaneSensor mappe les mouvements du périphérique d'entrée en translations bidimensionnelles sur un plan parallèle au plan Z=0 du système de coordonnées locales. Le nœud PlaneSensor utilise la géométrie descendante de son nœud parent pour déterminer s'il est sur le point de générer des événements.

Le champ exposé enabled active et désactive le PlaneSensor. Si enabled est TRUE, le capteur réagit correctement aux événements utilisateur. Si enabled est FALSE, le capteur ne gère pas les entrées utilisateur et n'envoie pas d'événements.

Si enabled reçoit un événement FALSE et que isActive est TRUE, le capteur est désactivé et rendu inactif, et un événement isActive FALSE est généré.

Si enabled reçoit un événement TRUE, le capteur est activé et prêt pour l'activation par l'utilisateur.

Le nœud PlaneSensor génère des événements lorsque le périphérique d'entrée est actif alors que le pointeur indique un nœud de géométrie descendant du groupe du capteur.

Une fois le périphérique d'entrée activé (par exemple, en appuyant sur le bouton principal de la souris), un événement isActive TRUE est envoyé. Le mouvement du pointeur est mappé sur une translation relative dans le plan de suivi (un plan parallèle au plan Z=0 du système de coordonnées local du capteur et coïncidant avec le point d'intersection initial). Pour chaque mouvement ultérieur du pointeur, un événement translation_changed est généré, qui correspond à la somme de la translation relative entre le point d'intersection d'origine et le point d'intersection du nouveau pointeur sur le plan, plus la valeur de décalage. Le signe de la translation est défini par le plan Z=0 du système de coordonnées du capteur.

Les événements trackPoint_changed reflètent la position de glissement non contrainte sur la surface de ce plan. Lorsque le périphérique d'entrée est désactivé et que autoOffset est TRUE, le décalage est défini sur la dernière valeur de translation_changed et un événement offset_changed est généré. Plus de détails sont fournis à la section 4.6.7.4, Capteurs de glissement (http://www.web3d.org/documents/specifications/14772/V2.0/part1/concepts.html#4.6.7.4).

Lorsque le capteur génère un événement isActive TRUE, tous les événements de mouvement du périphérique d'entrée sont capturés jusqu'à ce qu'il soit désactivé et qu'un événement isActive FALSE soit généré. D'autres capteurs de périphériques d'entrée ne génèrent pas d'événements pendant ce temps. La mobilité du périphérique d'entrée pendant que isActive est TRUE est appelée « glissement » (drag).

Si un périphérique d'entrée 2D (par exemple, une souris) est utilisé, les événements isActive reflètent généralement l'état du bouton principal associé au périphérique (c'est-à-dire que isActive est TRUE lorsque le bouton principal est enfoncé et FALSE lorsqu'il est relâché).

Si un périphérique d'entrée 3D (par exemple, un trident) est utilisé, les événements isActive reflètent généralement si le pointeur se trouve à l'intérieur ou en contact avec la géométrie du capteur.

Les champs minPosition et maxPosition peuvent être définis pour contraindre les translations translation_changed à une plage de valeurs mesurées depuis l'origine du plan Z=0. Si la composante X ou Y de minPosition est supérieure à celle correspondante de maxPosition, aucune contrainte n'est appliquée dans cette dimension. Si la composante X ou Y de minPosition est égale à celle correspondante de maxPosition, cette composante est limitée à la valeur donnée. Cette technique permet d'implémenter un capteur linéaire qui mappe le mouvement de glissement en une translation unidimensionnelle.

Pendant que le périphérique d'entrée est actif et déplacé, des événements trackPoint_changed et translation_changed sont envoyés. Les événements trackPoint_changed représentent les points d'intersection non contraints sur la surface du plan de suivi.

Description détaillée

Conservez la structure du fichier. Si le dispositif d'entrée glisse hors du plan de suivi pendant qu'il est actif (par exemple, au-dessus de la ligne d'horizon), les navigateurs peuvent interpréter cela de diverses manières (par exemple, verrouiller toutes les valeurs sur la ligne d'horizon). Chaque mouvement du dispositif d'entrée, tant que isActive est TRUE, génère des événements trackPoint_changed et translation_changed. Plus d'informations sur ce comportement peuvent être trouvées dans les sections 4.6.7.3, Capteurs de dispositifs de pointage (http://www.web3d.org/documents/specifications/14772/V2.0/part1/concepts.html#4.6.7.3), 4.6.7.4, Capteurs de pointage (http://www.web3d.org/documents/specifications/14772/V2.0/part1/concepts.html#4.6.7.4), et 4.6.7.5, Capteurs d'activation et de manipulation (http://www.web3d.org/documents/specifications/14772/V2.0/part1/concepts.html#4.6.7.5)).
