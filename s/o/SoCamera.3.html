Description Détaillée

La classe SoCamera est la classe de base abstraite pour la définition de caméra.

Pour pouvoir visualiser une scène, il faut avoir une caméra dans le graphe de scène. Un nœud caméra configurera les matrices de projection et de vue pour le rendu de la géométrie dans la scène.

Ce nœud définit simplement l'interface abstraite en regroupant les champs communs dont tous les nœuds de type caméra ont besoin. Utilisez les sous-classes de caméra non abstraites au sein d'un graphe de scène. Les plus courantes par défaut dans la bibliothèque Coin sont SoPerspectiveCamera et SoOrthographicCamera, qui utilisent les deux projections différentes indiquées par leur nom.

Notez que les composants de visualisation des bibliothèques d'interface graphique de Coin (SoXt, SoQt, SoWin, etc.) insèrent automatiquement une caméra dans un graphe de scène si aucune n'a été définie.

Il est possible d'avoir plus d'une caméra dans un graphe de scène. Une astuce courante consiste par exemple à utiliser une deuxième caméra pour afficher une géométrie statique ou une géométrie superposée (par exemple, pour des affichages tête haute ("HUD")), comme le montre cet exemple de code :

#include <Inventor/Qt/SoQt.h>
#include <Inventor/Qt/viewers/SoQtExaminerViewer.h>
#include <Inventor/nodes/SoNodes.h>
int
main(int argc, char ** argv)
{
  QWidget * mainwin = SoQt::init(argv[0]);
  SoSeparator * root = new SoSeparator;
  root->ref();
  // Ajoute une caméra et un cône rouge. La première caméra trouvée dans le
  // graphe de scène par SoQtExaminerViewer sera capturée et
  // initialisée automatiquement.
  root->addChild(new SoPerspectiveCamera);
  SoMaterial * material = new SoMaterial;
  material->diffuseColor.setValue(1.0, 0.0, 0.0);
  root->addChild(material);
  root->addChild(new SoCone);
  // Configure une deuxième caméra pour la géométrie restante. Cette caméra
  // ne sera pas capturée et influencée par le visualiseur, donc la
  // géométrie restera statique.
  SoPerspectiveCamera * pcam = new SoPerspectiveCamera;
  pcam->position = SbVec3f(0, 0, 5);
  pcam->nearDistance = 0.1;
  pcam->farDistance = 10;
  root->addChild(pcam);
  // Ajoute un cône vert pour démontrer la géométrie statique.
  SoMaterial * greenmaterial = new SoMaterial;
  greenmaterial->diffuseColor.setValue(0, 1.0, 0.0);
  root->addChild(greenmaterial);
  root->addChild(new SoCone);
  SoQtExaminerViewer * viewer = new SoQtExaminerViewer(mainwin);
  viewer->setSceneGraph(root);
  viewer->show();
  SoQt::show(mainwin);
  SoQt::mainLoop();
  delete viewer;
  root->unref();
  return 0;
}

NB : Le support des caméras multiples dans Coin est limité, et les problèmes avec plusieurs caméras seront traités au cas par cas.

virtual SbViewVolume SoCamera::getViewVolume (float useaspectratio = 0.0f) const [pure virtual]

Retourne le volume de vue total couvert par la caméra selon les paramètres actuels.

Ce volume de vue n'est pas ajusté pour tenir compte de la cartographie du viewport. Si vous souhaitez le même volume de vue que celui utilisé lors du rendu, vous devriez utiliser getViewVolume(SbViewportRegion & vp, const SbMatrix & mm), ou faire quelque chose comme ceci :

SbViewVolume vv;
float aspectratio = myviewport.getViewportAspectRatio();
switch (camera->viewportMapping.getValue()) {
case SoCamera::CROP_VIEWPORT_FILL_FRAME:
case SoCamera::CROP_VIEWPORT_LINE_FRAME:
case SoCamera::CROP_VIEWPORT_NO_FRAME:
  vv = camera->getViewVolume(0.0f);
  break;
case SoCamera::ADJUST_CAMERA:
  vv = camera->getViewVolume(aspectratio);
  if (aspectratio < 1.0f) vv.scale(1.0f / aspectratio);
  break;
case SoCamera::LEAVE_ALONE:
  vv = camera->getViewVolume(0.0f);
  break;
default:
  assert(0 && "unknown viewport mapping");
  break;
}

De plus, pour les mappages de viewport CROPPED, le viewport peut être modifié si le rapport d'aspect du viewport n'est pas égal au rapport d'aspect de la caméra. Voir le code source de SoCamera::getView() (méthode privée) pour voir comment cela est fait.

Implémenté dans SoFrustumCamera, SoOrthographicCamera et SoPerspectiveCamera.

void SoCamera::viewAll (SoNode *const sceneroot, const SbViewportRegion & vpregion, const float slack = 1.0f)

Positionne la caméra de manière à ce que toute la géométrie de la scène de sceneroot soit contenue dans le volume de vue de la caméra, tout en gardant l'orientation de la caméra constante.

Trouve la boîte englobante de la scène et appelle SoCamera::viewBoundingBox(). Une sphère englobante sera calculée à partir de la boîte englobante de la scène, de sorte que la caméra "voit tout" même lorsque la scène est tournée, quelle que soit la manière.

L'argument slack donne un facteur de multiplication pour la distance que la caméra est censée s'éloigner du point médian de sceneroot.

Une valeur inférieure à 1.0 pour l'argument slack rapprochera donc la caméra de la scène, une valeur de 1.0 positionnera la caméra juste à l'extérieur de la sphère englobante de la scène, et une valeur supérieure à 1.0 donnera un "slack supplémentaire" par rapport à la sphère englobante de la scène.

void SoCamera::setStereoAdjustment (float adjustment)

Définit l'ajustement stéréo. C'est la distance entre l'"œil" gauche et droit lors du rendu stéréo.

Lors du rendu stéréo, Coin rendra deux vues, une pour l'œil gauche et une pour l'œil droit. L'ajustement stéréo est, de manière simplifiée, le déplacement de la caméra le long de l'axe X local entre la vue gauche et la vue droite.

La distance par défaut est de 0.1, qui est choisie car c'est la distance approximative entre les yeux humains.

Pour créer un effet stéréo agréable et visible, le programmeur d'application devra souvent ajuster cette valeur. Si tout ce que vous voulez faire est d'examiner des objets 3D simples et autonomes, il est possible de calculer un décalage stéréo basé sur la boîte englobante du modèle 3D (ou de réduire l'échelle du modèle à une taille appropriée).

Cependant, si vous avez une scène volumineuse, dans laquelle vous voulez voler et voir la stéréo sur différents objets à mesure que vous vous en approchez, vous ne pouvez pas calculer le décalage stéréo basé sur la boîte englobante de la scène, mais utiliser plutôt un décalage stéréo basé sur l'échelle des objets/détails individuels que vous souhaitez examiner.

Veuillez noter qu'il est important de définir une distance focale raisonnable lors du rendu stéréo. Voir setBalanceAdjustment() pour des informations sur la façon dont la distance focale affecte le rendu stéréo.

NAME

SoCamera - abstract camera node class

INHERITANCE

Object > SoNotRec > SoNode > SoCamera

TEXT

An abstract base class for all camera nodes, like SoPerspectiveCamera and SoOrthographicCamera. It defines the common fields and methods for cameras.

A camera defines the viewpoint and projection for rendering a scene graph. The camera node itself doesn't render anything, but it influences the rendering operations performed by other nodes.

FILE: Inventor/nodes/SoCamera.h

SoCamera::farDistance

SoSFFloat SoCamera::farDistance

Distance de la position de la caméra au plan de clipping éloigné dans le volume de vue de la caméra.

La valeur par défaut est 10.0. Doit être supérieure à la valeur de SoCamera::nearDistance, sinon il ne sera pas possible de construire un volume de vue valide.

Notez que la plage [nearDistance, farDistance] décide de la plage dynamique du z-buffer dans le rasterizer de rendu de polygones sous-jacent. Cela signifie que si les plans de clipping proche et éloigné de la caméra sont très espacés, la possibilité d'artefacts visuels augmentera. Les artefacts se manifesteront sous forme de scintillement des primitives proches en profondeur.

Il est donc conseillé de garder les plans de clipping proche et éloigné de vos caméras aussi ajustés que possible autour de la géométrie du graphe de scène.
