Description détaillée

La classe SoCallbackAction invoque des callbacks sur des nœuds spécifiques.

Cette action dispose de mécanismes pour suivre la position de parcours et l'état du parcours. Combiné avec la capacité de passer des géométries de sommets à des actions de rappel définies par l'utilisateur, cela rend, par exemple, l'extraction de la géométrie d'un graphe de scène assez simple.

Vous devriez être en mesure d'utiliser cette action pour la plupart de vos besoins de parcours "simples", plutôt que d'écrire votre propre code, car SoCallbackAction est assez flexible.

Une utilisation courante de cette action est l'extraction de la géométrie de formes non primitives comme les triangles. Un exemple complet qui démontre cela dans un graphe de scène avec deux sphères suit:

#include <Inventor/SoDB.h>
#include <Inventor/SoPrimitiveVertex.h>
#include <Inventor/actions/SoCallbackAction.h>;
#include <Inventor/nodes/SoCoordinate3.h>;
#include <Inventor/nodes/SoIndexedFaceSet.h>;
#include <Inventor/nodes/SoSeparator.h>;
#include <Inventor/nodes/SoShape.h>;
#include <Inventor/nodes/SoSphere.h>;
#include <Inventor/nodes/SoTranslation.h>;
static SoCoordinate3 * coord3 = NULL;
static SoIndexedFaceSet * ifs = NULL;
static int coord3idx = 0;
static void
triangle_cb(void * userdata, SoCallbackAction * action,
            const SoPrimitiveVertex * v1,
            const SoPrimitiveVertex * v2,
            const SoPrimitiveVertex * v3)
{
  const SbVec3f vtx[] = { v1->getPoint(), v2->getPoint(), v3->getPoint() };
  const SbMatrix mm = action->getModelMatrix();
  SbVec3f vx[3];
  for (int j=0; j < 3; j++) { mm.multVecMatrix(vtx[j], vx[j]); }
  // (Ceci est sous-optimal -- il faudrait rechercher les coordonnées de sommet existantes dans le nœud SoCoordinate3.
  // Ainsi, de nombreuses coordonnées dupliquées seraient obtenues.)
  coord3->point.setNum(coord3->point.getNum() + 3);
  coord3->point.setValues(coord3idx, 3, vx);
  int32_t indices[] = { coord3idx, coord3idx + 1, coord3idx + 2, -1 };
  coord3idx += 3;
  int oldsize = ifs->coordIndex.getNum();
  ifs->coordIndex.setNum(oldsize + 4);
  ifs->coordIndex.setValues(oldsize, 4, indices);
  // (Note: Dans un projet réel, il serait souhaitable de capturer les vecteurs normaux, les matériaux et/ou les coordonnées de texture.
  // Comme le montre le code ci-dessus, il n'est pas montré comment faire, mais ce n'est pas très différent de l'extraction des coordonnées de sommet.)
}
int
main(void)
{
  SoDB::init();
  SoSeparator * root = new SoSeparator;
  root->addChild(new SoSphere);
  SoTranslation * trans = new SoTranslation;
  trans->translation.setValue(10, 0, 0);
  root->addChild(trans);
  SoSphere * ss = new SoSphere;
  ss->radius = 3;
  root->addChild(ss);
  root->ref();
  coord3 = new SoCoordinate3;
  coord3->point.setNum(0);
  ifs = new SoIndexedFaceSet;
  ifs->coordIndex.setNum(0);
  SoCallbackAction ca;
  ca.addTriangleCallback(SoShape::getClassTypeId(), triangle_cb, NULL);
  ca.apply(root);
  root->unref();
  // [Les nœuds SoCoordinate3 et SoIndexedFaceSet générés seraient alors typiquement utilisés dans un graphe de scène dans un visualiseur, ou écrits sur disque ou quelque chose de similaire]
  return 0;
}

Documentation des typedefs de membres

typedef Response SoCallbackAction::SoCallbackActionCB(void *userdata, SoCallbackAction *action, const SoNode *node)

Les fonctions de rappel doivent être de ce type. node est le nœud actuel dans le graphe de scène.

Documentation des énumérations de membres

Énumération SoCallbackAction::Response

Valeurs de Response pour les fonctions de rappel.

Énumérateurs:

CONTINUE
Continuer le parcours comme d'habitude.
ABORT
Interrompre immédiatement le parcours. Aucune autre fonction de rappel ne sera appelée après ce retour.
PRUNE
Ne pas parcourir le nœud actuel (s'il est retourné depuis un rappel de pré-parcours) ni ses enfants.

Si un retour est effectué à partir d'un rappel de pré-visite, les fonctions de post-visite seront toujours appelées. Si un retour est effectué à partir d'un rappel de post-visite, le comportement sera le même que si l'on retournait avec CONTINUE.

SoCallbackAction - perform a traversal, and call a set of callbacks for specific nodes

Detailed Description

The SoCallbackAction class is a subclass of of SoAction that can be used to perform a traversal of a scene graph, and to call a set of callback routines for specific nodes encountered during the traversal.

A typical use for SoCallbackAction is to implement custom traversals that need to perform specific actions when certain node types are visited. For example, you might want to collect all the geometry in a scene graph, or to find all nodes of a particular type.

To use SoCallbackAction, you create an instance of the class and then register callback functions for the node types you are interested in. You can use addCallback() to register a callback for a specific node type, or addObjInvented() to register a callback for all node types that inherit from a given class.

Once you have registered your callbacks, you can initiate the traversal by calling the SoAction::apply() method, passing the root node of the scene graph to be traversed. The SoCallbackAction will then traverse the scene graph, and for each node it visits, it will check if a callback has been registered for that node type. If a callback is registered, it will be invoked with the node and the current traversal path as arguments.

beginTraversal

This virtual method is called from SoAction::apply(), and is the entry point for the actual scene graph traversal.

It can be overridden to initialize the action at traversal start, for specific initializations in the action subclasses inheriting SoAction.

Default method just calls traverse(), which any overridden implementation of the method must do too (or call SoAction::beginTraversal()) to trigger the scene graph traversal.
