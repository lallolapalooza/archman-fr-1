Description détaillée

La classe SoType est la base du système de typage d'exécution dans Coin.

De nombreuses classes de la bibliothèque Coin doivent enregistrer des informations sur leur type avant de pouvoir créer des instances (y compris, mais sans s'y limiter, les moteurs, les nœuds, les champs, les actions, les nœuds de type de nœud et les gestionnaires). L'utilisation de SoType pour stocker ces informations offre de nombreuses fonctionnalités diverses pour travailler avec des hiérarchies de classes, comparer des types de classes, créer des instances d'objets à partir de noms de classes, etc.

Il est possible de faire des choses comme celles-ci:

void cleanLens(SoNode * anode)
{
  assert(anode->getTypeId().isDerivedFrom(SoCamera::getClassTypeId()));
  if (anode->getTypeId() == SoPerspectiveCamera::getClassTypeId()) {
    // faire quelque chose...
  }
  else if (anode->getTypeId() == SoOrthographicCamera::getClassTypeId()) {
    // faire quelque chose...
  }
  else {
    SoDebugError::postWarning("cleanLens", "Type de caméra inconnu %s!\n",
                              anode->getTypeId().getName());
  }
}

Une caractéristique remarquable de la classe SoType est qu'elle n'a que 16 bits et doit donc être passée par valeur pour des raisons d'efficacité.

Une note importante sur l'utilisation de SoType pour enregistrer les informations de classe : les éléments parents doivent être enregistrés avant leurs classes dérivées.

Voir également Chargement dynamique de nœuds d'extension pour des informations supplémentaires relatives à SoType.

Documentation des typedefs de membre

typedef void *(* SoType::instantiationMethod) (void)

Il s'agit d'un typedef pratique pour la signature de la méthode de création d'une classe typée. Il s'agit d'une extension de l'API d'origine d'Inventor. Je l'utilise principalement à des fins internes.

Une méthode de création ne prendra aucun argument et renverra un pointeur vers un nouvel objet initialisé de la classe typée.

Documentation des fonctions membre

SoType SoType::fromName (const SbName name) [static]

Cette fonction statique renvoie l'objet SoType associé au nom name.

Les objets de type pour les types de données intégrés peuvent être obtenus avec ou sans le préfixe "So". Pour les nœuds d'extension chargeables dynamiquement, le nom donné à cette fonction doit correspondre exactement.

Si aucun type de nœud portant le nom donné n'a été initialisé, un nœud d'extension chargeable dynamiquement de ce nom est recherché. S'il est trouvé, il est chargé et initialisé, et l'objet SoType du type de classe nouvellement initialisé est renvoyé. Si aucun module n'est trouvé, ou si l'initialisation du module échoue, SoType::badType() est renvoyé.

La prise en charge des nœuds d'extension chargeables dynamiquement varie d'une plateforme à l'autre et d'une suite de compilateurs à l'autre.

Jusqu'à présent, le code compilé avec les compilateurs suivants est pris en charge : GCC v2-4, Microsoft Visual C++ v6, 2003, 2005 et 2008), SGI MIPSPro v7.

Les extensions compilées avec des compilateurs connus pour être binaires compatibles avec les compilateurs susmentionnés sont également prises en charge, tels que, par exemple, le compilateur Intel x86 compatible MSVC++.

Pour prendre en charge le chargement dynamique d'autres compilateurs, nous devons savoir comment le compilateur maintient la magie du symbole « static void classname::initClass(void) » du compilateur. Si votre compilateur n'est pas pris en charge, veuillez nous informer sur coin-support@coin3d.org de quel compilateur il s'agit et envoyer le résultat d'un dump de symboles dans le fichier partagé. Vous pouvez généralement faire

$ nm <Node>.so | grep initClass

pour trouver le symbole magique pertinent.

int SoType::getAllDerivedFrom (const SoType type, SoTypeList & list) [static]

Cette méthode ajoute tous les types de classe dérivés de type à list et renvoie le nombre de types ajoutés à la liste. Les types internes ne sont pas inclus dans la liste, ni comptés.

Le type lui-même est également ajouté à la liste, car un type est considéré comme une dérivation de son propre type.

NB : N'écrivez pas de code qui dépend d'une manière ou d'une autre de l'ordre des éléments renvoyés dans list.

Voici un petit exemple autonome qui montre comment cette méthode peut être utilisée pour l'introspection, en listant tous les sous-types de la superclasse SoBase :

#include <cstdio>
#include <Inventor/SoDB.h>
#include <Inventor/lists/SoTypeList.h>
static void
list_subtypes(SoType t, unsigned int indent = 0)
{
  SoTypeList tl;
  SoType::getAllDerivedFrom(t, tl);
  for (unsigned int i=0; i < indent; i++) { printf("  "); }
  printf("%s\n", t.getName().getString());
  indent++;
  for (int j=0; j < tl.getLength(); j++) {
    if (tl[j].getParent() == t) { // seulement intéressé par les descendants directs
      list_subtypes(tl[j], indent);
    }
  }
}

SbBool SoType::canCreateInstance (void ) const

Cette méthode renvoie FALSE pour les classes de base abstraites, et TRUE pour les types de classes qui peuvent être instanciés.

void * SoType::createInstance (void ) const

Cette méthode instancie un objet du type actuel.

Pour les types qui ne peuvent pas être instanciés, NULL est retourné.

Notez que si la bibliothèque Coin a été compilée en tant que DLL sous Microsoft Windows et que vous utilisez cette méthode à partir du code d'application, vous devez vous assurer que la DLL Coin et l'exécutable de l'application utilisent la même instance d'une bibliothèque C Run-Time (CRT). Sinon, vous subirez une corruption de la mémoire vive lors de la désallocation des instances retournées, ce qui entraînera finalement des plantages mystérieux.


Ceci n'est pas nuisible si vous appelez seulement SoType::createInstance() sur des types pour des types de classes comptabilisés par référence. Cela inclut tous les nœuds, moteurs, chemins, kits de nœuds, draggers et manipulateurs.

const SoType SoType::createType (const SoType parent, const SbName name, const instantiationMethod method = NULL, const uint16_t data = 0) [static]

Cette méthode crée et enregistre un nouveau type de classe.

Les classes qui n'héritent d'aucune autre classe devraient utiliser SoType::badType() pour le premier argument. Les classes abstraites devraient utiliser NULL pour l'argument method.

La valeur passée pour le paramètre data peut être récupérée avec SoType::getData().

const SoType SoType::overrideType (const SoType originalType, const instantiationMethod method = NULL) [static]

Cette méthode permet à la méthode d'instanciation d'une nouvelle classe de remplacer la méthode d'instanciation d'une classe existante.

Le nouveau type devrait être une sous-classe C++ du type de classe original, mais cela ne sera pas vérifié.

Si NULL est passé comme deuxième argument, le type sera considéré comme non instanciable -- il ne rétablit pas la configuration aux paramètres par défaut comme on pourrait le penser.

Voici un exemple de code complet qui montre comment remplacer entièrement une classe de nœud Coin intégrée, de sorte que a) votre classe d'extension spécifique à l'application soit instanciée au lieu de la classe intégrée lors de l'importation du graphe de scène, et b) elle soit correctement écrite lors de l'exportation :

#include <Inventor/SoDB.h>
#include <Inventor/actions/SoWriteAction.h>
#include <Inventor/errors/SoDebugError.h>
#include <Inventor/nodes/SoSeparator.h>
#include <Inventor/nodes/SoWWWInline.h>
class MyWWWInline : public SoWWWInline {
  SO_NODE_HEADER(MyWWWInline);
public:
  static void initClass(void);
  MyWWWInline(void);
protected:
  virtual ~MyWWWInline();
  virtual SbBool readInstance(SoInput * in, unsigned short flags);
  virtual const char * getFileFormatName(void) const;
};
SO_NODE_SOURCE(MyWWWInline);
MyWWWInline::MyWWWInline(void)
{
  SO_NODE_CONSTRUCTOR(MyWWWInline);
  // Trompe la bibliothèque pour qu'elle croie qu'il s'agit d'une classe interne,
  // afin qu'elle soit écrite de la même manière que les classes intégrées,
  // au lieu d'une classe d'extension. Il existe de légères différences, que vous
  // voudrez éviter lors du remplacement d'une classe comme nous le faisons ici
  // avec MyWWWInline par rapport à SoWWWInline.
  this->isBuiltIn = TRUE;
}
MyWWWInline::~MyWWWInline()
{
}
void
MyWWWInline::initClass(void)
{
  SO_NODE_INIT_CLASS(MyWWWInline, SoWWWInline, "SoWWWInline");
  // Remplace la méthode d'instanciation, afin que nous obtenions MyWWWInline au lieu de
  // instances SoWWWInline lors de l'importation du graphe de scène.
  (void)SoType::overrideType(SoWWWInline::getClassTypeId(),
                             MyWWWInline::createInstance);
}
// Remplace SoBase::getFileFormatName() pour que le nœud soit écrit comme
// "WWWInline" au lieu de "MyWWWInline".
const char *
MyWWWInline::getFileFormatName(void) const
{
  return "WWWInline";
}
SbBool
MyWWWInline::readInstance(SoInput * in, unsigned short flags)
{
  SoDebugError::postInfo("MyWWWInline::readInstance", "hepp");
  return SoWWWInline::readInstance(in, flags);
}
int
main(int argc, char ** argv)
{
  SoDB::init();
  MyWWWInline::initClass();
  const char * ivscene =
    "#Inventor V2.1 ascii\n\n"
    "Separator {"
    "  WWWInline { }"
    "}";
  SoInput in;
  in.setBuffer(ivscene, strlen(ivscene));
  SoSeparator * root = SoDB::readAll(&in);
  root->ref();
  SoOutput out;
  SoWriteAction wa(&out);
  wa.apply(root);
  root->unref();
  return 0;
}
