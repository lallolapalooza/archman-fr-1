Description Détaillée

La classe SoPointLightDragger fournit une géométrie interactive pour manipuler une source de lumière ponctuelle.

Voici à quoi ressemble le dragger avec sa géométrie par défaut lorsqu'il est inactif :

Ce dragger est bien adapté pour être utilisé afin de définir les champs d'un nœud SoPointLight, car il fournit la géométrie permettant à l'utilisateur final de translater un point dans l'espace 3D.

La bibliothèque Coin inclut également une classe de manipulateur, SoPointLightManip, qui encapsule la fonctionnalité fournie par cette classe dans les mécanismes nécessaires pour la connecter à des instances de nœuds SoPointLight dans une hiérarchie de scène.

SoPointLightDragger::translation

Cette propriété est mise à jour en permanence pour contenir la position de la lumière ponctuelle du dragger. Le développeur d'application la connecte généralement à la propriété SoPointLight::location d'un nœud SoPointLight (sauf si la classe SoPointLightManip est utilisée, auquel cas elle est gérée automatiquement).

void SoPointLightDragger::setDefaultOnNonWritingFields (void ) [protected], [virtual]

(Remarque : Cette méthode n'intéresse généralement pas le développeur d'application qui ne souhaite pas étendre la bibliothèque avec de nouveaux nodekits ou de nouvelles classes de dragger. Si c'est le cas, consultez les informations de la documentation de la classe SoBaseKit.)

Ceci est une méthode virtuelle et le code qu'elle contient doit appeler SoField::setDefault() avec l'argument TRUE pour les champs qui ne doivent pas être écrits pendant les opérations d'exportation du graphe de scène.

Ceci est généralement fait quand :

1.
la valeur du champ est NULL et le champ est NULL par défaut
2.
c'est un nœud de type SoGroup ou SoSeparator sans enfants
3.
c'est un nœud de type liste de champ sans enfants et contient un SoGroup ou SoSeparator
4.
c'est un champ non-feuille et est de type SoGroup et tous les champs sont à leurs valeurs par défaut

Les descendants remplacent généralement cette méthode pour configurer de nouveaux champs. N'oubliez pas d'appeler setDefaultOnNonWritingFields() de votre superclasse depuis votre classe.
