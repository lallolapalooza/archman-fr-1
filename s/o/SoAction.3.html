Description Détaillée

La classe SoAction est la classe de base pour toutes les actions de parcours.

L'application d'actions est le mécanisme de base dans Coin pour exécuter diverses opérations sur des arbres de scène ou des chemins à l'intérieur d'eux, y compris les opérations de recherche, de rendu, d'interaction par sélection, etc.

L'opération de base consiste à instancier une action, à la configurer avec des paramètres supplémentaires si nécessaire, puis à appeler la méthode apply() du nœud racine de l'arbre de scène (ou sous-graphe d'un arbre de scène). Une fois appliquée, l'action parcourt l'arbre de scène depuis le nœud racine, en profondeur d'abord et vers la gauche, appliquant son traitement spécifique aux nœuds où elle s'applique.

(La classe SoAction et ses dérivées dans Coin est une implémentation du modèle architectural connu sous le nom de modèle "Visitor".)

Voici un exemple simple montrant comment utiliser la classe SoWriteAction pour imprimer un arbre de scène au format Inventor dans un fichier :

int write_scenegraph(const char * filename, SoNode * root)
{
  SoOutput output;
  if (!output.openFile(filename)) return 0;
  // C'est là que l'action est appliquée. ;-)
  SoWriteAction wa(&output);
  wa.apply(root);
  return 1;
}

Après le parcours, certains types d'actions ont stocké des informations sur la (sous-)scène graphique qui a été parcourue, que vous pouvez obtenir via des méthodes telles que SoGetBoundingBoxAction::getBoundingBox(), SoRayPickAction::getPickedPoint(), SoGetPrimitiveCountAction::getTriangleCount(), etc.

Pour plus d'informations, consultez les différentes actions intégrées (c'est-à-dire les sous-classes de cette classe), ou référez-vous à l'exemple de code de la bibliothèque Coin pour voir comment les actions sont utilisées.

Pour étendre la bibliothèque Coin avec vos propres classes, nous vous recommandons de vous familiariser avec l'excellent livre The Inventor Toolmaker (ISBN 0-201-62493-1), qui décrit en détail les travaux impliqués. Ce livre a été écrit par les concepteurs originaux d'Inventor chez SGI et explique bon nombre des idées de conception de base, tout en fournissant de nombreux exemples pratiques sur la manière d'étendre le toolkit Coin de manière réaliste sur une base de conception fondamentale. (The Inventor Toolmaker est également disponible dans la bibliothèque en ligne SGI, gratuitement. Voir Download The Inventor Toolmaker.) La lecture du code source des classes intégrées de Coin peut également être très utile.

A class that may be applied to a scene graph.

The SoAction class is the abstract base class for all classes that traverse and/or process a scene graph. An action is typically created, configured, and then applied to a scene graph.

The simplest action is SoWriteAction, which writes the scene graph to a file. Other actions include SoGLRenderAction (for rendering the scene graph), SoGetBoundingBoxAction (for computing the bounding box), SoHandleEventAction (for handling user input events), and SoSearchAction (for finding nodes in the graph).

Actions operate on nodes, paths, or lists of paths.

All actions are derived from SoAction. To create a new action class, you should derive from an existing action class or directly from SoAction. You must implement the getTypeId() method and the various apply() methods. The helper macros found in <Inventor/actions/SoSubAction.h> are recommended for doing this.

Returns the type identification of an action derived from a class inheriting SoAction. This is used for runtime type checking and "downward" casting.

Usage example:

void bar(SoAction * action)
{
  if (action->getTypeId() == SoGLRenderAction::getClassTypeId()) {
    // safe downward cast, know the type
    SoGLRenderAction * glrender = (SoGLRenderAction *)action;
  }
  return; // ignore if not render action
}

For application programmers wanting to extend the library with new actions: this method needs to be overridden in all subclasses. This is typically done as part of setting up the full type system for extension classes, which is usually accomplished by using the predefined macros available through Inventor/nodes/SoSubAction.h: SO_ACTION_SOURCE, SO_ACTION_INIT_CLASS and SO_ACTION_CONSTRUCTOR.

For more information on writing Coin extensions, see the SoAction class documentation.

Applies the action to the parts of the graph defined by path.

Note that an SoPath will also contain all nodes that may influence e.g. geometry nodes in the path. So for instance applying an SoGLRenderAction on an SoPath will render that path as expected in the view, where geometry will get its materials, textures, and other appearance settings correctly.

If the path ends in an SoGroup node, the action will also traverse the tail node's children.

void SoAction::beginTraversal (SoNode * node) [protected], [virtual]

Cette méthode virtuelle est appelée depuis SoAction::apply() et est le point d'entrée pour le parcours réel du graphe de scène.

Elle peut être redéfinie pour initialiser l'action au début du parcours, pour des initialisations spécifiques dans les sous-classes d'action héritant de SoAction.

La méthode par défaut appelle simplement traverse(), ce que toute implémentation redéfinie de la méthode doit également faire (ou appeler SoAction::beginTraversal()) pour déclencher le parcours du graphe de scène.

Réimplémenté dans SoAudioRenderAction, SoCallbackAction, SoGetBoundingBoxAction, SoGetMatrixAction, SoGetPrimitiveCountAction, SoGlobalSimplifyAction, SoGLRenderAction, SoHandleEventAction, SoPickAction, SoRayPickAction, SoReorganizeAction, SoSearchAction, SoShapeSimplifyAction, SoSimplifyAction, SoToVRML2Action, SoToVRMLAction, et SoWriteAction.
