Detailed Description

This class handles OpenGL texture objects for cube map images.

It inherits from SoGLImage and implements the necessary virtual methods to create and manage OpenGL texture objects for cube maps. Cube maps are a set of six square textures that are applied to the faces of a cube. They are commonly used for environment mapping, where the textures represent reflections of the surrounding environment.

The SoGLCubeMapImage class provides methods for setting texture quality, updating texture data, and retrieving OpenGL display list information. It also handles the creation and management of OpenGL texture objects, ensuring that they are created with the appropriate parameters and optimized for performance.

Key features and behaviors of SoGLCubeMapImage include:

  • Texture Quality Management: The setTextureQuality() method allows you to control the quality of the generated OpenGL texture. Higher quality settings may result in more detailed textures but can also increase memory usage and rendering time. The texture object is recreated if the quality changes from below 0.4 to above 0.5.

  • Border Handling: The constructor accepts a border parameter, which specifies the size of the border around the texture. Be aware that using a non-zero border can significantly impact performance on most PC hardware.

  • Immediate Texture Object Creation: If createinstate is not NULL, the OpenGL texture object is created immediately upon instantiation. This is useful when using temporary buffers for texture data. However, care must be taken, as this can prevent the creation of texture objects for other cache contexts if the texture data is needed later.

  • Efficient Texture Updates: If createinstate is provided and the texture attributes match the current image data, glTexSubImage() is used for data insertion, which is generally faster than creating a new texture object. This is particularly beneficial for animated textures.

  • Instance Reset: Passing NULL for the image parameter in the constructor resets the instance, freeing all associated display lists and memory.

  • OpenGL Display List Retrieval: The getGLDisplayList() method returns or creates an SoGLDisplayList for rendering, returning NULL if creation fails.

This class is reimplemented from SoGLImage to provide specific functionality for cube map textures within the Coin 3D library.

Constructs a new SoGLCubeMapImage object.

The constructor takes the following parameters:

  • pd: A pointer to the SoSFImage::PixelData structure containing the image data for the cube map. This structure should hold the pixel data for all six faces of the cube map.

  • border: An integer specifying the border width for the OpenGL texture. A value of 0 means no border. Be aware that a non-zero border can significantly impact performance on most PC hardware.
  • createinstate: An integer flag. If it is not NULL (non-zero), the OpenGL texture object is created immediately. This is useful if you are using a temporary buffer to hold the texture data. However, if createinstate is non-NULL, you cannot create texture objects for other cache contexts later.

If pd is NULL, the instance will be reset, causing all display lists and memory to be freed.

Member Function Documentation

void SoGLCubeMapImage::reTexture (SoState * state, const SoSFImage::PixelData * pd, SoTexture::TextureQuality tq)

This method re-textures the OpenGL texture object with new image data. It is called when the texture data needs to be updated, for example, due to changes in the image or texture quality settings.

If the texture quality is changed such that the existing texture object is no longer suitable (e.g., changing from mipmap generation disabled to enabled), the texture object will be recreated. For instance, if the initial texture quality is 0.4, and later the texture is applied with a texture quality greater than 0.5, the texture object will be recreated as a mipmap texture object. This recreation happens only once.

If border != 0, the OpenGL texture will be created with this border size. Be aware that this might be extremely slow on most PC hardware.

Normally, the OpenGL texture object isn't created until the first time it is needed, but if createinstate is != NULL, the texture object is created immediately. This is useful if you use a temporary buffer to hold the texture data. Be careful when using this feature, since the texture data might be needed at a later stage (for instance to create a texture object for another context). It will not be possible to create texture objects for other cache contexts when createinstate is != NULL.

Also if createinstate is supplied, and all the attributes are the same as the current data in the image, glTexSubImage() will be used to insert the image data instead of creating a new texture object. This is much faster on most OpenGL drivers, and is very useful, for instance when doing animated textures.

If you supply NULL for image, the instance will be reset, causing all display lists and memory to be freed.
