Description détaillée

La classe SoConcatenate est utilisée pour concaténer plusieurs entrées en une seule sortie.

Prend toutes les valeurs des 10 champs d'entrée multivalues à tour de rôle et les concatène dans la sortie multivalue.

Notez que le champ de sortie de ce moteur dévie un peu du mécanisme de sortie "standard" de la majorité des classes de moteurs : SoConcatenate::output n'est pas une instance permanente de SoEngineOutput, mais un *pointeur* vers une instance de SoEngineOutput. La raison est qu'il est nécessaire d'allouer le champ de sortie dynamiquement pour qu'il corresponde à ce à quoi SoConcatenate::input est connecté, car le type de SoConcatenate::output doit toujours être le même que celui de SoConcatenate::input.

Le format de fichier pour ce champ est un peu spécial. Notez la spécification de type initiale, qui n'est pas nécessaire pour la plupart des autres types de champs :

Concatenate {
  type <multivaluefieldtype>
  [...fields...]
}

virtual SoType SoConcatenate::getTypeId (void ) const [virtual]

Retourne l'identification de type d'un objet dérivé d'une classe héritant de SoBase. Ceci est utilisé pour la vérification de type à l'exécution et le transtypage "vers le bas". Exemple d'utilisation :

void foo(SoNode * node)
{
  if (node->getTypeId() == SoFile::getClassTypeId()) {
    SoFile * filenode = (SoFile *)node;  // transtypage sûr vers le bas, connaît le type
  }
}

Pour les programmeurs d'applications souhaitant étendre la bibliothèque avec de nouveaux nœuds, moteurs, kits de nœuds, draggers ou autres : cette méthode doit être redéfinie dans *toutes* les sous-classes. Ceci est généralement fait dans le cadre de la mise en place du système de types complet pour les classes d'extension, ce qui est généralement accompli en utilisant les macros prédéfinis disponibles via par exemple Inventor/nodes/SoSubNode.h (SO_NODE_INIT_CLASS et SO_NODE_CONSTRUCTOR pour les classes de nœuds), Inventor/engines/SoSubEngine.h (pour les classes de moteurs) et ainsi de suite.

Pour plus d'informations sur l'écriture d'extensions Coin, voir la documentation de classe des superclasses de niveau supérieur pour les divers groupes de classes.
