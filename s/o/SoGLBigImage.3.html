Description Détaillée

La classe SoGLBigImage est utilisée pour gérer les textures OpenGL 2D de toute taille.

Cette classe est interne. Pour activer ou désactiver la gestion des grandes textures, vous devez utiliser le nœud SoTextureScalePolicy.

La technique utilisée est la suivante : la texture est divisée en blocs de taille égale en x*y. Toutes ces sous-textures ont une taille de 2^n et sont typiquement très petites (256x256 ou moins). Chaque triangle est découpé selon les coordonnées de texture, en plusieurs triangles plus petits. Ces triangles sont garantis n'utiliser qu'une seule sous-texture. Ils sont ensuite projetés sur l'écran, et la taille maximale projetée pour chaque sous-texture est calculée. Les sous-textures hors du viewport sont rejetées. Chaque sous-texture est réduite à une puissance de 2 proche de la taille projetée, et une texture GL est créée avec cette taille. Cette texture GL est utilisée lors du rendu des triangles qui sont découpés dans cette sous-texture.

Le mipmapping est désactivé dans SoGLBigImage. Les problèmes d'aliasing ne devraient pas se produire car la taille de projection de la texture est calculée en temps réel. Lorsque le mipmapping est activé, la taille mémoire de la texture utilisée est doublée et la création de l'objet texture est beaucoup plus lente, nous évitons donc cela dans SoGLBigImage.

Vous devez noter que cette classe est une extension pour Coin et n'est pas disponible dans l'API originale SGI Open Inventor v2.1.

Detailed Description

This class is an extension of SoGLImage which handles larger images than normally supported by OpenGL. It does this by breaking the image up into smaller sub-textures, and then rendering a geometry plane for each subtexture.

The image data is handled by the SbImage class, and we use the same parameters for texture wrapping and quality settings as SoGLImage.

The main difference between SoGLImage and SoGLBigImage is that SoGLBigImage will create multiple texture objects if the image dimensions exceed the current OpenGL implementation limits, while SoGLImage will just fail.

The texture quality parameter is used to determine whether or not to create mipmaps. A quality of 0.5 or higher will enable mipmaps.

The border parameter allows you to specify a border width for the texture. This is not recommended for performance reasons on most PC hardware.

The constructor takes no arguments. You must call setData() after constructing an SoGLBigImage object to load the image data.

The exceededChangeLimit() and setChangeLimit() methods are used to control the maximum number of subtextures that can be updated per frame. This is to prevent excessive rendering time for large images with frequent updates.

void SoGLBigImage::setData (const SbImage * image, const Wrap wraps, const Wrap wrapt, const Wrap wrapr, const float quality = 0.5f, const int border = 0, SoState * createinstate = NULL) [virtual]

Sets the data for this GL image. Should only be called when one of the parameters have changed, since this will cause the GL texture object to be recreated. Caller is responsible for sending legal wrap values. CLAMP_TO_EDGE is only supported on OpenGL v1.2 implementations, and as an extension on some earlier SGI implementations (GL_SGIS_texture_edge_clamp).

For now, if quality > 0.5 when created, we create mipmaps, otherwise a regular texture is created. Be aware, if you for instance create a texture with texture quality 0.4, and then later try to apply the texture with a texture quality greater than 0.5, the texture object will be recreated as a mipmap texture object. This will happen only once though, of course.

If border != 0, the OpenGL texture will be created with this border size. Be aware that this might be extremely slow on most PC hardware.

Normally, the OpenGL texture object isn't created until the first time it is needed, but if createinstate is != NULL, the texture object is created immediately. This is useful if you use a temporary buffer to hold the texture data. Be careful when using this feature, since the texture data might be needed at a later stage (for instance to create a texture object for another context). It will not be possible to create texture objects for other cache contexts when createinstate is != NULL.

Also if createinstate is supplied, and all the attributes are the same as the current data in the image, glTexSubImage() will be used to insert the image data instead of creating a new texture object. This is much faster on most OpenGL drivers, and is very useful, for instance when doing animated textures.

If you supply NULL for image, the instance will be reset, causing all display lists and memory to be freed.
