Description Détaillée

La classe SoEventCallback fournit des fonctionnalités pour capturer des événements.

Utilisez des nœuds SoEventCallback dans le graphe de scène pour capturer les événements d'interaction utilisateur avec le canevas de rendu du graphe de scène.

C'est ainsi que la gestion des événements fonctionne dans Coin : lorsque l'utilisateur interagit avec le canevas de rendu, par exemple en utilisant le pointeur de la souris ou en tapant sur le clavier, la boîte à outils de l'interface graphique (c'est-à-dire SoQt, SoWin, SoXt, Sc21 ...) attrape l'événement et le traduit d'un événement spécifique au système de fenêtres vers un événement Coin générique. (Pour les types d'événements Coin génériques, voir les classes dérivées de SoEvent.) Cet événement sera ensuite encapsulé dans un SoHandleEventAction et appliqué au graphe de scène. Tout cela se passe au sein de la boîte à outils So[Qt|Xt|Win|...].

Le SoHandleEventAction parcourt ensuite le graphe de scène, transmettant l'événement à tout type de nœud qui y "s'intéresse". Le type de nœud SoEventCallback intercepte l'action et transmet l'événement à une fonction de rappel configurée par le programmeur de l'application.

Faites attention à la position dans le graphe de scène où vous insérez les nœuds SoEventCallback si vous utilisez également des éléments de la bibliothèque Coin intégrée qui s'intéressent aux événements d'interaction utilisateur (comme par exemple les classes de dragger et de manipulateur et les nœuds SoSelection). Ces éléments Coin peuvent intercepter l'événement pour eux-mêmes, court-circuitant le parcours de l'SoHandleEventAction afin que l'événement n'atteigne jamais les nœuds SoEventCallback que vous insérez.

void SoEventCallback::setHandled (void )

Utilisez cette méthode à partir d'une fonction de rappel pour notifier le nœud que l'événement a été traité.

Les autres rappels enregistrés avec le nœud seront toujours appelés, mais les nœuds SoEventCallback ultérieurs dans la scène ne seront pas notifiés de l'événement, ni aucun autre élément Coin dans le graphe de scène (comme par exemple les objets SoDragger, les nœuds SoSelection ou les manipulateurs).

Étant donné que les rappels enregistrés dans le même nœud SoEventCallback seront toujours invoqués après que l'événement ait été traité, il est probable que vous devriez utiliser SoEventCallback::isHandled() pour vérifier cette condition dans vos fonctions de rappel.

SbBool SoEventCallback::isHandled (void ) const

Vérifie si l'événement de la SoHandleEventAction a été traité ou non.

void SoEventCallback::grabEvents (void )

Configure le nœud de sorte que tous les événements futurs (jusqu'à ce que releaseEvents() soit appelé) dans Coin soient directement transférés à ce nœud.

void SoEventCallback::releaseEvents (void )

Ne pas saisir davantage le traitement des événements.
