Descripción Detallada

La clase SoPolygonOffset es un tipo de nodo para renderizar los "capas" de primitivas.

Un problema común con sistemas de renderización en 3D en tiempo real es que las primitivas que se muestran a la misma profundidad con respecto a la perspectiva del observador se ven como si estuvieran en una fluctuación. Es decir: desde un ángulo, una primitiva parece estar más cercana, mientras que desde otro ángulo, otra primitiva parece estar más cercana. Cuando esto ocurre, las imágenes renderizadas en ese parte del escenario se verán claramente menos visualmente atractivas.

Una situación común donde este problema ocurre es cuando intentas poner un cuadrícula de líneas como un contorno sobre polígonos llenos.

La causa del problema descrito es que el buffer de profundidad de cualquier sistema de renderizado tiene una resolución limitada, a menudo de 16, 24 o 32 bits. Debido a esto, las primitivas que son cercanas pueden obtener el mismo valor de profundidad en el buffer de profundidad, aunque no estén realmente en la misma coordenada de profundidad.

Para resolver el problema de la fluctuación, esta nodo puede ser insertado en el árbol de escena en el lugar adecuado para definir explícitamente cómo las primitivas, líneas y/o puntos deben ajustarse con respecto a otras primitivas.

En cuanto a los detalles de cómo se deben configurar los valores de SoPolygonOffset::factor y SoPolygonOffset::units, citamos la documentación de OpenGL:

    El valor del desplazamiento es
        factor * DZ + r * units
    donde DZ es una medición del cambio de profundidad con respecto a la área de pantalla de la primitiva, y r es el valor más pequeño que garantiza producir un desplazamiento resoluble para una implementación dada. El desplazamiento se agrega antes del test de profundidad y antes de escribir el valor en el buffer de profundidad.

Un aviso de una palabra con respecto a la cita anterior de la documentación de OpenGL: no es realmente sentido establecer factor y units a valores con signos diferentes, es decir, factor a un valor negativo y units a un valor positivo, o viceversa.

Los píxeles se mostrarían entonces "pushed back" en el orden de profundidad por una parte de la ecuación, pero al mismo tiempo se "pushen forward" por la otra parte de la ecuación. Esto haría probablemente resultados muy inconsistentes, pero que podrían parecer al principio aceptables.

Mencionamos este potencial de hacer un error, ya que parece ser un error común.

A continuación, un ejemplo de uso simple y correcto:

#Inventor V2.1 ascii
Separator {
   Coordinate3 { point [ -1 -1 0, 1 -1 0, 1 1 0, -1 1 0 ] }
   Separator {
      BaseColor { rgb 1 1 0 }
      # necesita dibujar polígonos como líneas, y no líneas reales -- ver
      # la documentación a continuación por qué esto es así:
      DrawStyle { style LINES }
      # dibujar dos triángulos para obtener una línea que atraviesa la cara de
      # el polígono:
      IndexedFaceSet { coordIndex [ 0, 1, 2, -1, 0, 2, 3 -1 ] }
   }
   PolygonOffset {
      styles FILLED
      factor 1.0
      units 1.0
   }
   BaseColor { rgb 0 0.5 0 }
   FaceSet { numVertices [ 4 ] }
}

Sin el nodo de offset de polígonos en el ejemplo anterior, las líneas podrían parecer irregularmente estipuladas con algunos drivers de gráficos, ya que parte de ella mostrará través de la face-set, otras no. Esto ocurre en partes al parecer aleatorias, ya que los cálculos de profundidad en el buffer flotante serán fáciles de hacer dependiendo si la polígono o la línea esté más cerca del observador.

Ver la documentación de API de la propiedad SoPolygonOffset::styles para una discusión de una limitación importante de la mecánica del buffer de profundidad de OpenGL: solo funciona con polígonos o polígonos renderizados en modo línea o punto, usando el campo SoDrawStyle::style.

FORMATO DE ARCHIVO/DEFALTES:

PolygonOffset {
    factor 1
    units 1
    styles FILLED
    on TRUE
}

Documentation des données membres

SoSFFloat SoPolygonOffset::factor

Facteur de multiplication du décalage. Met à l'échelle la profondeur variable dans le tampon z des primitives rendues.

Voir la documentation principale de la classe SoPolygonOffset ci-dessus pour des informations détaillées sur l'utilisation de la valeur du facteur.

La valeur par défaut est 1.0.

SoSFFloat SoPolygonOffset::units

Facteur de multiplication de la translation du décalage. Sera multiplié par la valeur qui représente le plus petit pas discret qui peut être distingué avec la résolution du tampon z sous-jacent.

Voir la documentation principale de la classe SoPolygonOffset ci-dessus pour des informations détaillées sur l'utilisation de la valeur des unités.

Notez que les valeurs positives pousseront la géométrie "loin" dans le tampon z, tandis que les valeurs négatives "déplaceront" la géométrie plus près.

La valeur par défaut est 1.0.

SoSFBitMask SoPolygonOffset::styles

Le type de primitive de rendu à influencer par ce nœud. Il s'agit d'une variable de masque de bits, vous pouvez donc sélectionner plusieurs types de primitives (parmi les polygones remplis, les lignes et les points) à influencer par le décalage en même temps.

Il existe une limitation très importante d'OpenGL à connaître à cet égard : le décalage du tampon z ne peut être effectué que pour les polygones, ou pour les polygones rendus en tant que lignes ou en tant que points.

Les tentatives d'utilisation de ce nœud pour décaler par exemple les primitives SoLineSet / SoIndexedLineSet ou SoPointSet ne fonctionneront pas.

Voir les commentaires dans le graphe de scène ci-dessous pour un exemple détaillé de ce que SoPolygonOffset peut et ne peut pas faire:

#Inventor V2.1 ascii
Separator {
   # render polygon:
   Coordinate3 { point [ -1.1 -1.1 0, 1.1 -1.1 0, 1.1 1.1 0, -1.1 1.1 0 ] }
   BaseColor { rgb 0 0.5 0 }
   FaceSet { numVertices [ 4 ] }
   # offset polygon-as-lines to be in front of above polygon:
   PolygonOffset {
      styles LINES
      factor -2.0
      units 1.0
   }
   # render lines:
   Coordinate3 { point [ -1 -1 0, 1 -1 0, 1 1 0, -1 1 0 ] }
   BaseColor { rgb 1 1 0 }
   Switch {
      # change this to '0' to see how glPolygonOffset() does *not* work
      # with "true" lines
      whichChild 1
      DEF child0 Group {
         # can *not* be offset
         IndexedLineSet { coordIndex [ 0, 1, 2, 3, 0, 2, -1, 1, 3 -1 ]
         }
      }
      DEF child1 Group {
         # will be offset
         DrawStyle { style LINES }
         FaceSet { numVertices [ 4 ] }
      }
   }
}

La valeur par défaut du champ est SoPolygonOffset::FILLED.

SoSFBool SoPolygonOffset::on

Indique si le décalage est activé ou désactivé. La valeur par défaut est que SoPolygonOffset::on est TRUE.
