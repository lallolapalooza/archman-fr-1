Description Détaillée

La classe SoSearchAction fournit des méthodes pour rechercher dans les graphes de scène.

Les nœuds peuvent être recherchés par pointeur, type et nom, ou par une combinaison de ces critères. Les types peuvent être interprétés comme des types exacts, ou le type peut correspondre à des nœuds qui en dérivent. Chaque nœud individuel peut être recherché, ou les règles de parcours normales peuvent être suivies lors de la recherche (ceci est particulièrement important à noter en ce qui concerne les nœuds de type switch).

Lors de l'utilisation de plus d'un des appels setNode(), setType() et setName(), notez que l'action recherchera le(s) nœud(s) avec une combinaison « ET » des critères de recherche donnés.

L'une des erreurs les plus courantes lors de l'utilisation de la classe SoSearchAction est d'appeler la fonction isFound() après avoir effectué une recherche. Elle ne retourne pas ce que vous attendez si vous n'avez pas lu la documentation de cette fonction.

Soyez conscient que si vous effectuez des opérations de recherche sur un SoSearchAction créé sur la pile, vous pouvez obtenir des effets secondaires regrettables si vous ne faites pas attention. Étant donné que SoSearchAction conserve une liste du(des) chemin(s) trouvé(s) lors de la dernière recherche, les nœuds de ces chemins seront désengagés lorsque l'instance de pile SoSearchAction sera détruite à la fin de votre fonction. Si la racine de votre graphe de scène a alors un compteur de références de zéro (il est souvent utile de faire un unrefNoDelete() avant de retourner un nœud d'une fonction pour laisser le référencement à l'appelant), le nœud racine sera détruit ! Il pourrait être préférable de créer une instance sur le tas de l'action de recherche dans ces cas, car vous pourrez alors détruire l'action de recherche avant d'appeler unrefNoDelete(). Une autre solution serait d'appeler reset() avant d'appeler unrefNoDelete() sur votre objet, car reset() tronque la liste des chemins.

Voir la documentation de SoTexture2 pour un exemple complet d'utilisation de SoSearchAction.

void SoSearchAction::setSearchingAll (const SbBool searchallarg)

Spécifie si le parcours normal du graphe doit être effectué (searchall est FALSE, ce qui est le réglage par défaut), ou si chaque nœud doit être recherché (searchall est TRUE).

Si l'indicateur searchall est TRUE, même les nœuds considérés comme « cachés » par d'autres actions sont recherchés (comme par exemple les enfants désactivés des nœuds SoSwitch).

SoBaseKit::setSearchingChildren() doit être utilisé pour rechercher des nœuds sous des kits de nœuds.

SoPath * SoSearchAction::getPath (void ) const

Retourne le chemin vers le nœud d'intérêt qui correspond aux critères de recherche. Si aucune correspondance n'a été trouvée, NULL est retourné.

Notez que si TOUTES les correspondances sont d'intérêt, le résultat d'une action de recherche doit être récupéré via SoSearchAction::getPaths().

Il y a une question fréquemment posée concernant les chemins retournés par cette méthode ou par la méthode getPaths() ci-dessous : « pourquoi ne reçois-je pas le chemin complet comme

expected?"

Bien, alors vous devrez probablement caster le chemin vers un SoFullPath, car certains nœuds (nodekits, de nombreux nœuds VRML97) ont des enfants cachés. SoPath::getTail() renverra le premier nœud qui a des enfants cachés, ou la queue s'il n'y a aucun nœud avec des enfants cachés. SoFullPath::getTail() renverra toujours la queue réelle. Faites simplement comme ceci :

SoFullPath * path = (SoFullPath *) searchaction->getPath();
SoVRMLCoordinate * vrmlcord = (SoVRMLCoordinate *) path->getTail();

SoPathList & SoSearchAction::getPaths (void )

Renvoie une liste de chemins de tous les nœuds qui correspondent aux critères de recherche.

Notez que si l'intérêt était uniquement PREMIER ou DERNIER, SoSearchAction::getPath() devrait être utilisé à la place de cette méthode.

void SoSearchAction::beginTraversal (SoNode * node) [protected], [virtual]

Cette méthode virtuelle est appelée depuis SoAction::apply(), et est le point d'entrée pour le parcours réel du graphe de scène.

Elle peut être redéfinie pour initialiser l'action au début du parcours, pour des initialisations spécifiques dans les sous-classes d'action héritant de SoAction.

La méthode par défaut appelle simplement traverse(), ce que toute implémentation redéfinie de la méthode doit faire aussi (ou appeler SoAction::beginTraversal()) pour déclencher le parcours du graphe de scène.

SbBool SoSearchAction::duringSearchAll = FALSE [static]

Indicateur global obsolète, présent uniquement pour des raisons de compatibilité avec l'ancien code d'application SGI / TGS Inventor.

Il est défini sur TRUE lorsqu'un parcours SoSearchAction avec SoSearchAction::isSearchingAll() égal à TRUE est démarré, et est réinitialisé à FALSE après la fin du parcours.

(L'indicateur est utilisé par SGI / TGS Inventor dans SoSwitch::affectsState() pour savoir quand SoSwitch::whichChild devrait se comporter comme SoSwitch::SO_SWITCH_ALL. Nous avons une meilleure solution pour ce problème dans Coin.)
