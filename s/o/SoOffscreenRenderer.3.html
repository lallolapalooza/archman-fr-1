Description détaillée

La classe SoOffscreenRenderer est utilisée pour le rendu de scènes dans des tampons hors écran.

Si vous souhaitez effectuer le rendu dans un tampon mémoire au lieu d'un contexte OpenGL à l'écran, utilisez cette classe. Le rendu dans un tampon mémoire peut être utilisé pour générer des textures à la volée, ou pour enregistrer des instantanés de la scène dans des fichiers disque (sous forme de bitmaps pixelisés ou de fichiers PostScript pour l'envoi à une imprimante compatible PostScript).

Voici un exemple d'utilisation très simple, juste le code directement lié à SoOffscreenRenderer :

SoOffscreenRenderer myRenderer(vpregion);
SoNode * root = myViewer->getSceneManager()->getSceneGraph();
SbBool ok = myRenderer.render(root);
unsigned char * imgbuffer = myRenderer.getBuffer();
// [puis utiliser le tampon image dans une texture, ou l'écrire dans un fichier, ou autre]

Et voici un exemple complet et autonome avec une caméra mobile enregistrant plusieurs images sur disque au format JPG :

#include <Inventor/SoDB.h>
#include <Inventor/SoOffscreenRenderer.h>
#include <Inventor/engines/SoInterpolateVec3f.h>
#include <Inventor/nodes/SoCube.h>
#include <Inventor/nodes/SoDirectionalLight.h>
#include <Inventor/nodes/SoPerspectiveCamera.h>
#include <Inventor/nodes/SoSeparator.h>
#include <iostream>
int main()
{
  // Initialisation de Coin
  SoDB::init();
  // Le nœud racine
  SoSeparator * root = new SoSeparator;
  root->ref();
  // Il est obligatoire d'avoir au moins une lumière pour le rendu hors écran
  SoDirectionalLight * light = new SoDirectionalLight;
  root->addChild(light);
  // Il est obligatoire d'avoir au moins une caméra pour le rendu hors écran
  SoPerspectiveCamera * camera = new SoPerspectiveCamera;
  SbRotation cameraRotation = SbRotation::identity();
  cameraRotation *= SbRotation(SbVec3f(1, 0, 0), -0.4f);
  cameraRotation *= SbRotation(SbVec3f(0, 1, 0), 0.4f);
  camera->orientation = cameraRotation;
  root->addChild(camera);
  // Quelque chose à montrer... Une boîte
  SoCube * cube = new SoCube;
  root->addChild(cube);
  // Configuration des deux positions de caméra entre lesquelles déplacer la caméra
  SoInterpolateVec3f * interpolate = new SoInterpolateVec3f;
  interpolate->input0 = SbVec3f(2, 2, 9);
  interpolate->input1 = SbVec3f(2, 2, 5);
  camera->position.connectFrom(&interpolate->output);
  // Configuration du rendu hors écran
  SbViewportRegion vpRegion(400, 300);
  SoOffscreenRenderer offscreenRenderer(vpRegion);
  // Nombre d'images à rendre pour la vidéo
  int frames = 5;
  std::cout << "Écriture de " << frames << " images..." << std::endl;
  for (int i = 0; i < frames; i++) {
    // Mise à jour de la position de la caméra
    interpolate->alpha = float(i) / (frames - 1);
    // Rendu de la scène
    SbBool ok = offscreenRenderer.render(root);
    // Sauvegarde de l'image sur disque
    SbString filename = SbString("coinvideo-") + (i + 1) + ".jpg";
    if (ok) {
      offscreenRenderer.writeToFile(filename.getString(), "jpg");
    } else {
      std::cout << "Erreur lors de la sauvegarde de l'image : " << filename.getString() << std::endl;
      break;
    }
  }
  std::cout << "Terminé !" << std::endl;
  root->unref();
  return 0;
}

Notez que SoOffscreenRenderer alloue potentiellement une quantité assez importante de ressources, à la fois OpenGL et des ressources système générales, pour chaque instance. Il est donc conseillé d'essayer de réutiliser les instances de SoOffscreenRenderer, au lieu d'en construire et de détruire une nouvelle par exemple pour chaque image lors de la génération d'images pour une vidéo.

Le rendu hors écran est effectué en interne via un contexte hors écran GLX (c'est-à-dire OpenGL sur X11), WGL (c'est-à-dire OpenGL sur Win32), AGL (ancien style OpenGL sur Mac OS X) ou CGL (nouveau style Mac OS X).

Si le pilote OpenGL prend en charge l'extension pbuffer, il est détecté et utilisé pour fournir un rendu hors écran accéléré matériellement.

Les données pixelisées sont extraites du tampon OpenGL avec glReadPixels(), les arguments format et type étant définis sur GL_RGBA et GL_UNSIGNED_BYTE, respectivement. Cela signifie que la résolution maximale est de 32 bits, 8 bits pour chacun des composants R/G/B/A.

Une utilisation particulière de SoOffscreenRenderer est de le faire rendre des images destinées à la construction de films. La technique générale pour ce faire consiste à itérer sur les actions suivantes :

  • déplacer la caméra à la bonne position pour l'image
  • mettre à jour le champ global realTime (voir explication ci-dessous)
  • invoquer le SoOffscreenRenderer
  • sauvegarder la scène rendue dans un fichier

...ensuite, vous utilisez un outil ou une bibliothèque externe pour construire le fichier vidéo, par exemple au format MPEG, à partir de l'ensemble des fichiers sauvegardés sur disque lors du processus itératif ci-dessus.

Le code ressemblerait à peu près à ceci (style pseudo-code). D'abord, nous devons empêcher la bibliothèque Coin elle-même de faire des mises à jour automatiques du champ realTime, donc votre initialisation d'application pour Coin devrait ressembler à ceci :

[...] = SoQt::init([...]); // ou SoWin::init() ou SoDB::init()
// ..et ensuite immédiatement :
// Contrôler le champ realTime nous-mêmes, de sorte que les animations dans la scène
// suivent le "temps du film" et non le "temps horloge".
SoDB::enableRealTimeSensor(FALSE);
SoSceneManager::enableRealTimeUpdate(FALSE);
SoSFTime * realtime = SoDB::getGlobalField("realTime");
realtime->setValue(0.0);

Notez qu'il est important que le champ realTime soit initialisé à *votre* temps de début *avant* de configurer des moteurs ou d'autres entités dans le système qui utilisent le champ realTime.

Ensuite, pour la boucle de rendu, quelque chose comme :

for (int i=0; i < NRFRAMES; i++) {
  // [...repositionner la caméra ici, si nécessaire...]
  // rendu
  offscreenrend->render(root);
  // sauvegarder dans un fichier
  SbString framefile;
  framefile.sprintf("frame%06d.rgb", i);
  offscreenrend->writeToRGB(framefile.getString());
  // avancer le "temps actuel" par la valeur d'images par seconde, qui
  // est de 24 ips i
dans cet exemple realtime->setValue(realtime.getValue() + 1/24.0); }

Lors de la création de films, vous devez écrire le code de contrôle de votre application pour vous occuper vous-même du déplacement de la caméra le long de la trajectoire correcte, et pour contrôler explicitement le champ realTime global. Ce dernier est ainsi afin que vous puissiez "avancer" avec des unités de temps appropriées pour chaque opération de rendu (par exemple, si vous voulez un film avec un taux de rafraîchissement de 24 images par seconde, rendez d'abord avec realTime=0.0, puis ajoutez 1/24s au champ realTime, rendez à nouveau une nouvelle image, ajoutez encore 1/24s au champ realTime, rendez, et ainsi de suite).

Pour plus d'informations sur la façon de contrôler le champ realTime, consultez la documentation de SoDB::getGlobalField(), SoDB::enableRealTimeSensor() et SoSceneManager::enableRealTimeUpdate().

Si vous souhaitez utiliser cette classe pour créer des instantanés de la vue de votre spectateur actuel, mais que vous souhaitez contrôler la taille de l'instantané, vous devez modifier légèrement la caméra lors du rendu pour vous assurer que tout ce que vous voyez dans la vue actuelle est visible dans l'instantané.

Vous trouverez ci-dessous un pseudo-code qui fait cela. Il existe probablement d'autres façons de le faire également.

void render_offscreen(const SbVec2s size)
{
  SbVec2s glsize = this->getGLSize(); // taille de votre spectateur normal
  float glar = float(glsize[0] / float(glsize[1]));
  float ar = float(size[0]) / float(size[1]);
  SoCamera * camera = this->getCamera(); // la caméra que vous utilisez
  SoCamera::ViewportMapping oldmap = (SoCamera::ViewportMapping)
    camera->viewportMapping.getValue();
  float oldar = camera->aspectRatio.getValue();
  camera->viewportMapping = SoCamera::LEAVE_ALONE;
  camera->aspectRatio = ar;
  float scaleheight = 1.0f;
  if (glar > ar) {
    scaleheight = glar / ar;
    camera->scaleHeight(scaleheight);
  }
  else {
    scaleheight = ar / glar;
    camera->scaleHeight(scaleheight);
  }
  SoOffscreenRenderer * renderer = new SoOffscreenRenderer(size);
  renderer->render(root);
  // ... sauvegarder l'image
  // restaurer la caméra
  camera->viewportMapping = oldmap;
  camera->aspectRatio = oldar;
  if (scaleheight != 1.0f) {
    camera->scaleHeight(1.0f / scaleheight);
  }
}

void SoOffscreenRenderer::setComponents (const Components components)

Définit le format des composantes du tampon hors écran.

Si défini sur LUMINANCE, une image en niveaux de gris est rendue, LUMINANCE_TRANSPARENCY nous donne une image en niveaux de gris avec transparence, RGB donnera une image 24 bits avec 8 bits pour chaque composante rouge, verte et bleue, et RGB_TRANSPARENCY produira une image 32 bits (RVB plus transparence).

Le format par défaut pour le rendu est RGB.

Cela invalidera le tampon actuel, le cas échéant. Le tampon ne contiendra pas de données valides tant qu'un nouvel appel à SoOffscreenRenderer::render() n'aura pas eu lieu.

SbBool SoOffscreenRenderer::render (SoNode * scene)

Rend le graphe de scène enraciné à scene dans notre tampon de pixels interne.

Note importante : assurez-vous de passer un pointeur de nœud scene qui possède à la fois une caméra et au moins une source de lumière en dessous - sinon, vous obtiendrez probablement juste un tampon d'image vide ou noir.

Cette erreur est facilement commise si vous utilisez un SoOffscreenRenderer sur un graphe de scène d'un des composants de spectateur standard, car vous laisserez souvent l'ajout d'une caméra et d'une lumière d'appoint au spectateur pour la configuration. Cette caméra et cette source de lumière font alors partie du "super-graphe" privé du spectateur en dehors de la portée du graphe de scène passé par le programmeur d'application. Pour vous assurer que le graphe de scène complet (y compris les "parties privées" du spectateur (ricanement)) est passé à cette méthode, vous pouvez obtenir la racine du graphe de scène de l'instance SoSceneManager interne du spectateur au lieu de la méthode getSceneGraph() du spectateur lui-même, comme ceci :

SoOffscreenRenderer * myRenderer = new SoOffscreenRenderer(vpregion);
SoNode * root = myViewer->getSceneManager()->getSceneGraph();
SbBool ok = myRenderer->render(root);
// [puis utilisez le tampon d'image dans une texture, ou écrivez-le dans un fichier, ou autre]

Si vous faites cela et obtenez toujours un tampon vide, un autre problème courant est d'avoir une caméra qui ne pointe pas réellement sur la géométrie de la scène dont vous voulez un instantané. Si vous suspectez que cela pourrait être la cause de problèmes de votre côté, jetez un œil à SoCamera::pointAt() et SoCamera::viewAll() pour voir comment vous pouvez faire en sorte qu'un nœud de caméra soit garanti d'être dirigé vers la géométrie de la scène.

Une autre erreur courante lors de la configuration de la caméra est de spécifier des valeurs pour les champs SoCamera::nearDistance et SoCamera::farDistance qui n'englobent pas la scène complète. Cela se traduira soit par la couleur d'arrière-plan seulement, soit par le fait que des parties à l'avant ou à l'arrière de la scène ne seront pas visibles dans le rendu.

const void *const & SoOffscreenRenderer::getDC (void ) const

Win32 uniquement :

retourne un handle direct vers le DC interne du contexte hors écran.

Utile pour un accès efficace à l'image brute dans certaines circonstances spéciales. getBuffer() peut être trop lent, par exemple en raison de la conversion du format de pixel (les DC Windows sont généralement BGRA, tandis que les tampons 32 bits retournés par getBuffer() sont RGBA).

Notes :

La valeur de retour est une référence à un HDC. Le typedef HDC a été déroulé vers un type C++ natif pour des raisons de compatibilité multiplateforme.

La référence retournée contiendra une valeur NULL sur d'autres plateformes.

Limitation importante : si les dimensions actuelles du SoOffscreenRenderer sont plus grandes que ce qui peut être rendu avec un seul tampon hors écran, le découpage sera utilisé par le SoOffscreenRenderer, et le HDC retourné ne contiendra qu'une partie de l'image rendue complète.

SbBool SoOffscreenRenderer::isWriteSupported (const SbName & filetypeextension) const

Retourne TRUE si le tampon peut être enregistré sous forme de fichier de type filetypeextension, en utilisant SoOffscreenRenderer::writeToFile(). Cette fonction nécessite simage v1.1 ou plus récent.

Exemples d'extensions potentiellement prises en charge : "jpg", "png", "tiff", "gif", "bmp", etc. La correspondance de l'extension n'est pas sensible à la casse.

Les formats qui sont *effectivement* pris en charge dépendent des capacités de la bibliothèque de support de Coin pour la gestion de l'importation et de l'exportation de fichiers de données pixel : la bibliothèque simage. Si la bibliothèque simage n'est pas installée sur votre système, aucun format de sortie d'extension ne sera pris en charge.

De plus, notez qu'il est possible de compiler et d'installer une bibliothèque simage qui manque de support pour la plupart ou la totalité des formats de fichiers qu'elle est *capable* de supporter. Ceci est dû au fait que la bibliothèque simage dépend d'autres bibliothèques tierces externes -- de la même manière que Coin dépend de la bibliothèque simage pour un support supplémentaire des formats de fichiers.

Les deux formats intégrés qui sont pris en charge via les méthodes SoOffscreenRenderer::writeToRGB() et SoOffscreenRenderer::writeToPostScript() (pour le format SGI RGB et pour les fichiers Adobe PostScript, respectivement) ne sont *pas* considérés par cette méthode, car ces deux formats sont garantis d'être *toujours* pris en charge par ces fonctions.

Donc, si vous voulez avoir la garantie de pouvoir exporter une capture d'écran dans le format souhaité, vous devrez utiliser l'une des méthodes mentionnées ci-dessus pour écrire directement en SGI RGB ou Adobe PostScript, ou vous assurer que la bibliothèque Coin a été compilée et fonctionne sur une version de la bibliothèque simage (que vous avez de préférence compilée vous-même) avec les formats de fichiers que vous souhaitez supporter.

Cette méthode est une extension par rapport à l'API originale SGI Open Inventor.

getWriteFiletypeInfo()

void SoOffscreenRenderer::getWriteFiletypeInfo (const int idx, SbPList & extlist, SbString & fullname, SbString & description)

Retourne des informations sur un exportateur d'images. extlist est une liste d'extensions de nom de fichier pour un format de fichier. Par exemple, pour JPEG, il est légal d'utiliser à la fois jpg et jpeg. extlist contiendra des pointeurs const char * (vous devrez caster les pointeurs void * en const char * avant de les utiliser).

fullname est le nom complet du format d'image. description est une chaîne optionnelle avec plus d'informations sur le format de fichier.

Voir SoOffscreenRenderer::isWriteSupported() pour des informations sur les formats de fichiers que vous pouvez vous attendre à trouver.

Cette méthode est une extension par rapport à l'API originale SGI Open Inventor.

Voici un exemple de code autonome et complet montrant comment vous pouvez vérifier exactement quels formats de sortie sont pris en charge :

#include <Inventor/SoDB.h>
#include <Inventor/SoOffscreenRenderer.h>
int
main(int argc, char **argv)
{
  SoDB::init();
  SoOffscreenRenderer * r = new SoOffscreenRenderer(*(new SbViewportRegion));
  int num = r->getNumWriteFiletypes();
  if (num == 0) {
    (void)fprintf(stdout,
                  "Aucun format d'image pris en charge par le "
                  "SoOffscreenRenderer, sauf SGI RGB et PostScript.\n");
  }
  else {
    for (int i=0; i < num; i++) {
      SbPList extlist;
      SbString fullname, description;
      r->getWriteFiletypeInfo(i, extlist, fullname, description);
      (void)fprintf(stdout, "%s: %s (extension%s: ",
                    fullname.getString(), description.getString(),
                    extlist.getLength() > 1 ? "s" : "");
      for (int j=0; j < extlist.getLength(); j++) {
        (void)fprintf(stdout, "%s%s", j>0 ? ", " : "", (const char*) extlist[j]);
      }
      (void)fprintf(stdout, ")\n");
    }
  }
  delete r;
  return 0;
}

void SoOffscreenRenderer::setPbufferEnable (SbBool enable)

Contrôle si SoOffscreenRenderer peut utiliser la fonctionnalité "pbuffer" d'OpenGL pour rendre les scènes avec accélération matérielle.

Ceci est une fonction factice dans Coin, fournie pour des raisons de compatibilité d'API, car elle est réellement superflue :

Coin possède des heuristiques internes pour déterminer si les pbuffers sont disponibles et peuvent être alloués et utilisés pour le SoOffscreenRenderer. Le SoOffscreenRenderer se rabattra également automatiquement sur des tampons "logiciels" s'il ne peut pas utiliser de pbuffers (ou toute autre technique de rendu accélérée par matériel).

Depuis

Coin 3.1
