Description Détaillée

La classe SoBase est la classe de base principale pour un certain nombre de hiérarchies de classes.

SoBase fournit les interfaces et méthodes de base pour le comptage de références, l'identification de type et l'importation/exportation. Toutes les classes dans Coin qui utilisent ces mécanismes descendent de cette classe.

Un problème important avec les classes dérivées de SoBase est qu'elles ne doivent pas être allouées statiquement, ni dans la mémoire statique d'un module, ni sur les cadres de pile d'une fonction. Les classes dérivées de SoBase doivent toujours être allouées dynamiquement à partir du tas mémoire avec l'opérateur new.

Ceci est nécessaire car les instances dérivées de SoBase sont comptées par référence, et s'auto-détruiront au moment approprié. Pour que cela fonctionne, elles doivent être explicitement allouées en mémoire du tas. Voir la documentation de la classe SoNode pour plus d'informations.

SoBase

Base class for all Open Inventor objects

Inherited from SoBase .

Description

The SoBase class is the base class for all objects within the Open Inventor scenegraph. All scenegraph nodes, fields, engines, accumulators, sensors, etc. are derived from SoBase.

The class provides basic mechanisms for object identification, scenegraph traversal, notification, and naming.

Objects derived from SoBase can be assigned names. These names are used to reference objects from other parts of the scene graph, for example, via DEF/USE keywords when writing or reading scene graph description files. Names are also used by the global dictionary of named objects, which can be queried to find objects by name.

Names can be arbitrary sequences of characters, but they are subject to certain restrictions. For example, names cannot contain special token characters).

Invalid characters will be automatically replaced by underscore characters. If the name starts with an invalid character, the new name will be preceded by an underscore character.

For the exact definitions of what constitutes legal and illegal characters for SoBase names, see the SbName functions listed below.

SbBool SoBase::read (SoInput * in, SoBase *& base, SoType expectedtype) [static]

Read next SoBase derived instance from the in stream, check that it is derived from expectedtype and place a pointer to the newly allocated instance in base.

FALSE is returned on read errors, mismatch with the expectedtype, or if there are attempts at referencing (through the USE keyword) unknown instances.

If we return TRUE with base equal to NULL, three things might have happened:

1.
End-of-file. Use SoInput::eof() after calling this method to detect end-of-file conditions.
2.
in didn't have a valid identifier name at the stream for us to read. This happens either in the case of errors, or when all child nodes of a group have been read. Check if the next character in the stream is a '}' to detect the latter case.
3.
A child was given as the NULL keyword. This can happen when reading the contents of SoSFNode fields (note that NULL is not allowed for SoMFNode)

If TRUE is returned and base is not NULL upon return, the instance was allocated and initialized according to what was read from the in stream.

Description

The SoBase class is the root of the Coin class hierarchy. All objects in Coin inherit from this class, directly or indirectly. It provides the basic mechanisms for object identification, reference counting and memory management.

SoBase provides a basic type system using the SoType class. This type system allows you to query the type of an object at runtime, check if an object is derived from a certain class, and get the name of a class.

All SoBase objects are reference counted. When an object is created, its reference count is one. You can increment the reference count using the ref() method and decrement it using the unref() method. When the reference count reaches zero, the object is automatically deleted.

The SoBase class also handles the automatic loading and unloading of libraries. When a class is used for the first time, its library is loaded automatically. When a class is no longer used, its library is unloaded automatically.

SoBase also provides basic support for writing and reading objects to and from files. The write() and read() methods can be used for this purpose.

Note: The methods marked as [protected] are not intended to be called directly by application programmers. They are for internal use by Coin.

void SoBase::assertAlive (void ) const

This API member is considered internal to the library, as it is not likely to be of interest to the application programmer.


There are 4 bits allocated for each SoBase-object for a bitpattern that indicates the object is still "alive". The pattern is changed when the object is destructed. If this method is then called after destruction, an assert will hit.

This is used internally in Coin (in for instance SoBase::ref()) to try to detect when the instance has been prematurely destructed. This is a very common mistake made by application programmers (letting the refcount drop to zero before it should, that is), so the extra piece of assistance through the accompanying assert() in this method to detect dangling references to the object, with subsequent memory corruption and mysterious crashes, should be a Good Thing.

This function is an extension for Coin, and it is not available in the original SGI Open Inventor v2.1 API.

Since

Coin 2.0

SbBool SoBase::writeHeader (SoOutput * out, SbBool isgroup, SbBool isengine) const [protected]

Write out the header of any SoBase derived object. The header consists of the DEF keyword and the object name (if the object has a name, otherwise these will be skipped), the class name and a left bracket.

Alternatively, the object representation may be made up of just the USE keyword plus the object name, if this is the second or subsequent reference written to the file.

If the object has been completed just by writing the header (which will be the case if we're writing multiple references of an object), we return TRUE, otherwise FALSE.

If we return FALSE (i.e. there's more to write), we will increment the indentation level.

TRUE or FALSE is returned, depending on if the instantiation and configuration of the new object of this class type went OK or not. The import process should be robust and handle corrupted input streams by returning FALSE.
