Description détaillée

La classe SoField est la classe abstraite de plus haut niveau pour les champs.

Les champs sont le mécanisme utilisé dans Coin pour encapsuler des types de données de base afin de détecter les modifications qui leur sont apportées, et de fournir des fonctionnalités de conversion, d'importation et d'exportation.

La plupart des propriétés publiques des nœuds sont stockées dans des champs, tout comme les entrées et les sorties des moteurs de traitement. Par conséquent, les champs peuvent être considérés comme le principal mécanisme permettant aux nœuds de la scène graphique et aux moteurs d'exposer leur API publique.

Le fait que la modification des données se fasse par une interface publique tout en cachant les membres de données permet de détecter et de réagir automatiquement aux changements dans les structures de données établies par le programmeur.

Par exemple, le comportement par défaut lors de la modification de la valeur d'un champ dans un nœud de scène est d'avoir une chaîne de notifications automatiques — du champ vers le nœud propriétaire, de ce nœud vers son nœud parent, et ainsi de suite jusqu'au nœud racine le plus élevé, où l'application est notifiée de la nécessité d'une mise à jour du rendu.

Ce mécanisme de notification est la base de la fonctionnalité qui fait que la bibliothèque Coin est classée comme une API de scène graphique « pilotée par les données ».

Les conséquences pratiques de ceci sont que le rendu et les autres actions de traitement sont planifiés par défaut pour se produire uniquement lorsqu'il y a un changement dans les structures de données maintenues, ce qui rend la bibliothèque Coin beaucoup moins gourmande en ressources de traitement que, par exemple, une API « pilotée par l'application » comme celle de SGI IRIS Performer, qui re-rend périodiquement même en l'absence de changements dans les structures de données ou dans la fenêtre d'affichage de la caméra.

Stocker les membres de données sous forme de champs offre également d'autres avantages pour le programmeur :

•
Les champs peuvent être connectés entre eux. Cela permet, par exemple, d'avoir des scènes « auto-régénérantes », c'est-à-dire que les entités peuvent réagir automatiquement aux changements dans d'autres entités. Cela fournit également un mécanisme nécessaire pour avoir des scènes « auto-animées », car il est possible de connecter n'importe quel champ au champ global nommé realTime, qui sert d'horloge en temps réel.
•
En connectant des champs entre eux, Coin dispose de mécanismes internes pour effectuer des conversions automatiques entre différents types de champs.
•
Les champs permettent la persistance des opérations d'importation (et d'exportation) de la scène graphique. Cela inclut l'animation des entités, de sorte que les animations peuvent être stockées dans des fichiers au format Inventor standard.
•
Les champs offrent des fonctionnalités d'introspection : ils ont un système de type, tout comme les nœuds et les actions, ils sont nommés et on peut trouver quel nœud, moteur ou entité possède un champ.
•
Les champs peuvent contenir plusieurs valeurs. Les champs à valeurs multiples ont une interface d'abstraction plus élevée que les tableaux C/C++ standard.

Remarque : certaines classes de champs ont été déclarées obsolètes depuis l'API Open Inventor. Ce sont : SoSFLong, SoSFULong, SoMFLong et SoMFULong. Vous devriez utiliser ces classes à la place (respectivement) : SoSFInt32, SoSFUInt32, SoMFInt32 et SoMFUInt32.

Ce livre a été écrit par les concepteurs originaux de l'API Inventor de SGI et explique bon nombre des idées fondamentales derrière cette conception, ainsi que des exemples pratiques sur la manière d'étendre l'outil Coin de manière qui est t...

•
Si ce champ est déjà connecté à master, nous retournerons FALSE.

Description

Ce champ de données fait référence à une partie des données dans un nœud ou un moteur. Un champ peut être connecté à la sortie d'un autre champ ou à la sortie d'un moteur. Dans ce cas, son auditeur est notifié lorsque la valeur du champ maître change.

Un champ peut être le maître d'autres champs. Ces champs sont appelés « auditeurs » du champ maître. Lorsqu'un champ maître change sa valeur, il notifie tous ses auditeurs.

La classe SoField est la classe de base pour tous les champs.

SbBool SoField::connectFrom (SoField * master, SbBool append = TRUE)

Se connecte au champ maître en tant qu'esclave. Si append est TRUE (par défaut), toutes les connexions existantes sont conservées. Si append est FALSE, toutes les connexions préexistantes sont rompues.

Les connexions à des champs maîtres préexistants sont rompues si append est FALSE.

Appelez avec notnotify si vous voulez éviter la notification initiale des auditeurs connectés (également appelés esclaves).

La fonction retournera TRUE sauf si :

•
Si le champ dont on se connecte (from) a un type différent du champ auquel on se connecte (to), un convertisseur de champ est inséré. Pour certaines combinaisons de champs, aucune conversion n'est possible, et nous retournerons FALSE.
•
Si ce champ est déjà connecté au maître, nous retournerons FALSE.

void SoField::touch (void ) [virtual]

Notifie le champ ainsi que le propriétaire / conteneur du champ qu'il a été modifié.

Toucher un champ qui fait partie d'un composant (moteur ou nœud) dans un graphe de scène entraînera un redessin forcé. Ceci est utile si vous avez effectué plusieurs mises à jour du champ encapsulées dans une paire d'appels à enableNotify() pour notifier les auditeurs du champ que sa valeur a changé.

Description

The SoField class is the base class for all field classes within the Coin library. Fields are used to store and manage data within scenegraph nodes. They provide a uniform interface for accessing and modifying data, as well as handling connections between fields and engines.

Key features of SoField:

  • Type Information: Each field has a specific type (e.g., SoSFInt32, SoMFString) that determines the kind of data it holds and how it's represented.

  • Notification: Fields can notify interested parties (auditors) when their values change. This is crucial for updating the scenegraph dynamically.

  • Connections: Fields can be connected to other fields, engines, or interpolators. This allows for data flow and dependencies within the scenegraph.

  • Persistence: Fields can be read from and written to files, enabling scene saving and loading.

  • Default Values: Fields have a concept of a default value. The isDefault() method checks if the field's current value is the default.

This class provides a foundational interface for all field types. Specific field types inherit from SoField and implement the necessary methods for handling their particular data types.

void SoField::touch (void )

This method marks the field as "dirty", meaning its value has changed and might need to be updated or re-evaluated by dependent nodes or engines. It will also notify any auditors that the field's value has changed.

void SoField::touch (bool resetdefault)

This method marks the field as "dirty" and optionally resets the flag indicating whether the field has its default value. If resetdefault is TRUE, the flag is set to FALSE, meaning the field is no longer considered to have its default value.

The method will also notify any auditors that the field's value has changed.

SbBool SoField::readConnection (SoInput * in) [protected], [virtual]

Reads the master field of a field-to-field connection from the input stream, along with its field container.

If the input parsing is successful, this field will be connected as a slave to the master field.

Note that this slave field will not be marked as "dirty" upon connection. It will retain its value until the first update of the master field occurs after the connection was set up. This behavior conforms to the Inventor Mentor specification for importing field connections (see page 270).
