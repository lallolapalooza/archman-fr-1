Description Détaillée

La classe SoInteractionKit est une classe de base pour les draggers.

Cette nodekit rend possible la définition de chemins substituts pour les parties. Au lieu de créer une nouvelle géométrie pour le dragger, il est possible de spécifier un chemin existant dans votre scène pour être utilisé lors de l'interaction. Tous les picks sur ce chemin seront gérés par le dragger.

La classe SoInteractionKit est principalement une classe interne utilisée comme superclasse pour les classes de draggers, et il est peu probable qu'elle intéresse les programmeurs d'applications, sauf si vous avez des besoins très spécifiques dans votre application.

Structure de la Nodekit (nouvelles entrées par rapport à la classe parente marquées avec un préfixe flèche) :

CLASS SoInteractionKit
-->"this"
      "callbackList"
-->   "topSeparator"
-->      "geomSeparator"

(Voir SoBaseKit::printDiagram() pour des informations sur le formatage de la sortie.)

Informations détaillées sur les parties du catalogue :

CLASS SoInteractionKit
PVT   "this",
SoInteractionKit --- "callbackList", SoNodeKitListPart [ SoCallback, SoEventCallback ] PVT "topSeparator", SoSeparator --- PVT "geomSeparator", SoSeparator ---

(Voir SoBaseKit::printTable() pour des informations sur le formatage de la sortie.)

void SoInteractionKit::copyContents (const SoFieldContainer * from, SbBool copyconnections) [protected], [virtual]

Crée une copie profonde de toutes les données de from dans cette instance, sauf les références externes au graphe de scène si copyconnections est FALSE.

C'est la méthode qui doit être surchargée par les sous-classes de nœuds d'extension / moteurs / draggers / etc. qui ont besoin de prendre en compte des données internes qui ne sont pas gérées automatiquement.

Pour copier des nœuds depuis le code de l'application, vous ne devez pas appeler cette fonction directement, mais plutôt appeler la fonction SoNode::copy() :

SoNode * mynewnode = templatenode->copy();

Il en va de même pour les moteurs.

Assurez-vous que lorsque vous surchargez la méthode copyContents() dans votre classe d'extension, vous l'appelez également vers le haut dans la hiérarchie d'héritage de sa superclasse, car copyContents(), par exemple dans SoNode et SoFieldContainer, effectue un travail important. Cela devrait ressembler à ceci :

void
MyCoinExtensionNode::copyContents(const SoFieldContainer * from,
                                  SbBool copyconnections)
{
  // laisser les superclasses parentes faire leur travail (copier les
  // champs, copier le nom de l'instance, etc.)
  SoNode::copyContents(from, copyconnections);
  // [..puis copier les données internes..]
}

SbBool SoInteractionKit::readInstance (SoInput * in, unsigned short flags) [protected], [virtual]

Cette méthode est principalement destinée à un usage interne lors des opérations d'importation de fichiers.

Elle lit une définition d'objet d'instance à partir du flux d'entrée in. L'état du flux d'entrée pointe vers le début d'une représentation sérialisée / persistante d'une instance de ce type de classe.

Elle renvoie TRUE ou FALSE selon que l'instanciation et la configuration du nouvel objet de ce type de classe ont réussi ou non. Le processus d'importation doit être robuste et gérer les entrées corrompues en renvoyant FALSE.

La valeur flags est utilisée en interne lors de l'importation binaire lors de la lecture de nœuds d'extension utilisateur, de nœuds de groupe ou de moteurs.

void SoInteractionKit::readDefaultParts (const char * fileName, const char defaultBuffer[], int defBufSize) [static], [protected]

Lit les parties par défaut pour un dragger.

Cette méthode est appelée depuis les constructeurs de dragger pour configurer le nodekit de géométrie d'interaction et de retour d'un dragger.

Le fileName est le fichier de ressources modifiable par l'utilisateur au format Inventor, tandis que defaultBuffer et defBufSize peuvent pointer vers les parties par défaut compilées statiquement.

L'environnement de la variable SO_DRAGGER_DIR doit être défini sur un préfixe valide pour fileName, sinon aucun fichier de ressources ne sera chargé (et defaultBuffer sera utilisé à la place).

Si à la fois fileName et defaultBuffer sont fournis, le fichier sera recherché et chargé en premier, s'il échoue, il tentera de lire la géométrie à partir du buffer.

void SoInteractionKit::setDefaultOnNonWritingFields (void ) [protected], [virtual]

(Bien que cette méthode ne soit probablement pas d'intérêt pour le programmeur d'applications qui ne souhaite pas étendre la bibliothèque avec de nouveaux nodekits personnalisés ou des classes de dragger. Si vous écrivez vraiment des extensions, consultez les informations dans la documentation de la classe SoBaseKit.)

Ceci est une méthode virtuelle, et le code qu'elle contient devrait appeler SoField::setDefault() avec l'argument TRUE sur les champs de partie qui ne doivent pas être écrits lors des opérations d'exportation de graphe.

Ceci est généralement fait lorsque :

1.
la valeur du champ est NULL et le champ est NULL par défaut
2.
c'est un nœud de type SoGroup ou SoSeparator sans enfants
3.
c'est un nœud de liste de partie sans enfants et qu'il contient un SoGroup ou SoSeparator conteneur
4.
c'est une partie non feuille de type SoGroup et que tous les champs sont aux valeurs par défaut

Les sous-classes remplacent généralement cette méthode pour configurer de nouveaux champs membres. Vous devez vous rappeler d'appeler setDefaultOnNonWritingFields() de votre super-classe "vers le haut".
