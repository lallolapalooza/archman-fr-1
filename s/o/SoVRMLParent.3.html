SbBool SoVRMLParent::affectsState (void ) const [virtuel]

Retourne TRUE si le nœud peut avoir un effet sur l'état pendant le parcours.

S'il retourne FALSE, aucune donnée dans l'état de parcours ne changera entre l'état avant le parcours et l'état après le parcours. Le nœud SoSeparator retournera par exemple FALSE, car il empile et dépile l'état avant et après le parcours de ses enfants. Tous les nœuds SoShape retourneront également FALSE, car le simple envoi de données de géométrie au moteur de rendu n'affectera pas l'état de rendu réel.

La méthode par défaut retourne TRUE, selon une philosophie de "mieux vaut prévenir que guérir".

Detailed Description

This class is the base class for nodes that can contain other nodes, and that are specific to VRML. Its primary purpose is to provide a common interface for all VRML nodes that have children.

VRMLParent is a subclass of SoGroup, and therefore inherits all of its functionality for managing children.

The main difference between SoGroup and SoVRMLParent is that SoVRMLParent is intended for use with VRML nodes, which have specific requirements for how their children are managed and interpreted. For example, VRML nodes often have a specific order in which their children must be processed, and SoVRMLParent provides the necessary mechanisms to enforce this order.

The SoVRMLParent class introduces the following public fields:

  • children: An SoMFNode field that holds the children of this node. This field is typically used to add or remove child nodes from the scene graph.

It also introduces the following protected fields:

  • addChildren: An SoMFNode eventIn that is used to add children to this node.
  • removeChildren: An SoMFNode eventIn that is used to remove children from this node.

In addition, SoVRMLParent overrides the copyContents() method from SoGroup to provide VRML-specific copying behavior. This method is used to create a deep copy of the node, including its children and any associated data. The copyContents() method is called internally by the SoNode::copy() method, which should be used by applications to create copies of nodes.

Reimplemented from SoGroup.

Member Function Documentation

virtual void SoVRMLParent::copyContents (const SoFieldContainer * from, SbBool copyconnections) [protected], [virtual]

Makes a deep copy of all data of from into this instance, except external scene graph references if copyconnections is FALSE.

This is the method that should be overridden by extension node / engine / dragger / whatever subclasses which need to account for internal data that are not handled automatically.

For copying nodes from application code, you should not invoke this function directly, but rather call the SoNode::copy() function:

SoNode * mynewnode = templatenode->copy();

The same also goes for engines.

Make sure that when you override the copyContents() method in your extension class that you also make it call upwards to its parent superclass in the inheritance hierarchy, as copyContents() in for instance SoNode and SoFieldContainer does important work. It should go something like this:

void
MyCoinExtensionNode::copyContents(const SoFieldContainer * from,
                                  SbBool copyconnections)
{
  // let parent superclasses do their thing (copy fields, copy
  // instance name, etc.)
  SoNode::copyContents(from, copyconnections);
  // [..then copy internal data..]
}
