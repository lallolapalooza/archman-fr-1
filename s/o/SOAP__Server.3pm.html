SOAP::Server(3) Documentation Perl fournie par la communauté SOAP::Server(3)

NOM

SOAP::Server - fournit le cadre de base sur lequel les classes serveur spécifiques au transport peuvent s'appuyer.

DESCRIPTION

La classe SOAP::Server fournit le cadre de base sur lequel les classes serveur spécifiques au transport peuvent s'appuyer. Notez que dans aucun des exemples de code fournis avec SOAP::Lite cette classe n'est utilisée directement. Au lieu de cela, elle est conçue pour être une superclasse au sein de classes d'implémentation plus spécifiques. Les méthodes fournies par SOAP::Server elle-même sont :

MÉTHODES

new(paires clé/valeur optionnelles)
$server = SOAP::Server->new(%options);

Crée un nouvel objet de la classe. Diverses valeurs d'instance par défaut sont configurées, et comme beaucoup des constructeurs de ce module, la plupart des méthodes de classe décrites ici peuvent être passées dans l'appel de construction en donnant le nom suivi du paramètre (ou une référence de tableau s'il y a plusieurs paramètres).

action(nouvelle valeur optionnelle)
$action = $server->action

Récupère ou définit la valeur de l'attribut d'action sur l'objet serveur. Cet attribut est utilisé lors du mappage de la requête à un espace de noms ou une routine appropriée. Par exemple, la bibliothèque HTTP définit l'attribut sur la valeur de l'en-tête SOAPAction lors du traitement de la requête, de sorte que la méthode find_target décrite plus tard puisse récupérer la valeur pour la faire correspondre à la configuration du serveur. Renvoie l'objet lui-même lors de la définition de l'attribut.

myuri(nouvelle valeur optionnelle)
$server->myuri("http://localhost:9000/SOAP");

Obtient ou définit l'attribut myuri. Ceci spécifie l'URI spécifique auquel le serveur répond aux requêtes (qui peut être différent de la valeur spécifiée dans action ou dans l'en-tête SOAPAction).

serializer(nouvelle valeur optionnelle)
deserializer(nouvelle valeur optionnelle)
$serializer = $server->serializer;
$server->deserializer($new_deser_obj);

Comme pour les objets client, ces méthodes fournissent un accès direct aux objets de sérialisation et désérialisation que l'objet serveur utilise pour transformer les entrées et sorties XML. Il y a généralement peu ou pas de besoin de les définir explicitement sur de nouvelles valeurs.

options(nouvelle valeur optionnelle)
$server->options({compress_threshold => 10000});

Définit (ou récupère) les options serveur actuelles sous forme de référence de table de hachage. À l'heure actuelle, une seule option est utilisée au sein des bibliothèques SOAP::Lite elles-mêmes :

compress_threshold
La valeur de cette option est attendue comme une valeur numérique. Si elle est définie, et si la bibliothèque Compress::Zlib est disponible, les messages dont la taille en octets dépasse cette valeur sont compressés pour la transmission. Les deux extrémités de la conversation doivent supporter cela et l'avoir activé.

D'autres options peuvent être définies et transmises en utilisant ce mécanisme. Notez que la définition des options à l'aide de cet accesseur nécessite une référence de table de hachage complète. Pour définir une seule valeur ou quelques valeurs, récupérez la référence de la valeur actuelle et utilisez-la pour définir la ou les clés.

dispatch_with(nouvelle valeur optionnelle)
$server->dispatch_with($new_table);

Représente l'une des deux manières dont un objet SOAP::Server (ou dérivé) peut spécifier des mappages de requêtes entrantes à des sous-routines ou espaces de noms côté serveur. La valeur de l'attribut est une référence de table de hachage. Pour définir l'attribut, vous devez passer une nouvelle référence de table de hachage. Les clés de la table de hachage sont des chaînes d'URI (URI littéraux ou les valeurs potentielles de l'en-tête SOAPAction), et les valeurs correspondantes sont soit un nom de classe, soit une référence d'objet. Les requêtes arrivant pour un URI trouvé dans la table sont acheminées vers la classe spécifiée ou via l'objet spécifié.

dispatch_to(liste de nouvelles valeurs optionnelles)
$server->dispatch_to($dir, 'Module', 'Mod::meth');

C'est la manière la plus traditionnelle de spécifier des modules et des paquets pour acheminer les requêtes. C'est aussi un accesseur, mais il renvoie une liste de valeurs lorsqu'il est appelé sans arguments (plutôt qu'une seule).

Chaque élément de la liste des valeurs passées à cette méthode est attendu comme l'une des quatre choses suivantes :

Chemin du répertoire
Si la valeur est un chemin de répertoire, tous les modules situés dans ce chemin sont disponibles pour une utilisation à distance.
Nom du paquet
Lorsque la valeur est un nom de paquet (sans inclure un nom de méthode spécifique), toutes les routines du paquet sont disponibles à distance.
Nom de méthode entièrement qualifié
Alternativement, lorsque la valeur est un nom de sous-routine ou de méthode qualifié par le paquet, cette routine spécifique est rendue disponible. Cela permet au serveur de rendre disponibles des méthodes sélectionnées sans ouvrir tout le paquet.
Référence d'objet
Si la valeur est une référence d'objet, l'objet lui-même achemine la requête.

La liste des valeurs conservées par la table dispatch_to n'est comparée qu'après consultation de la table de mappage d'URI de l'attribut dispatch_with. Si l'URI de la requête ou l'en-tête SOAPAction ne correspondent pas à une configuration spécifique, le chemin spécifié par l'en-tête d'action (ou en l'absence, l'URI) est converti en nom de paquet et comparé à cet ensemble de valeurs.

objects_by_reference(liste de nouvelles valeurs optionnelles)
$server->objects_by_reference(qw(My:: Class));

Ceci renvoie également une liste de valeurs lors de la récupération de la valeur d'attribut actuelle, par opposition à une seule valeur.

Cette méthode ne spécifie pas directement les classes pour le routage des requêtes, mais modifie le comportement du routage pour les classes spécifiées. Les classes qui sont données comme arguments à cette méthode sont marquées pour être traitées comme produisant des objets persistants. Le client reçoit une représentation d'objet qui ne contient qu'une poignée sur un objet local avec une persistance par défaut de 600 secondes d'inactivité. Chaque opération sur l'objet réinitialise le minuteur d'inactivité à zéro. Cette facilité est considérée comme expérimentale dans la version actuelle de SOAP::Lite.

Une variable globale/« constante » permet aux développeurs de spécifier le temps pendant lequel un objet sera conservé. La valeur par défaut est de 600 secondes d'inactivité. Cette valeur peut être modifiée en utilisant le code suivant :

$SOAP::Constants::OBJS_BY_REF_KEEPALIVE = 1000;
on_action(nouvelle valeur optionnelle)
$server->on_action(sub { ...nouveau code });

Obtient ou définit la référence à une sous-routine utilisée pour exécuter le hook on_action. Là où le code client utilise ce hook pour construire les données de la requête d'action (comme pour un en-tête SOAPAction), le serveur utilise le hook on_action pour effectuer des tests de dernière minute sur la requête elle-même, avant qu'elle ne soit acheminée vers une destination finale. Lorsqu'il est appelé, la routine du hook reçoit trois arguments :

action
L'URI d'action lui-même, récupéré de la méthode action décrite plus haut.
method_uri
L'URI de l'espace de noms XML avec lequel le nom de la méthode est étiqueté.
method_name
Le nom de la méthode appelée par la requête.
t id="on_dispatch(optional">on_dispatch(optionnel nouvelle valeur) 
($uri, $name) = $serveur->on_dispatch->($requête);

Obtient ou définit la référence de sous-routine utilisée pour le crochet on_dispatch. Ce crochet est appelé au début de la phase de routage des requêtes et reçoit un seul argument lorsqu'il est appelé :

requête
Un objet de la classe SOAP::SOM, contenant la requête désérialisée du client.
find_target
($classe, $uri, $nom) = $serveur->find_target($req)

Prenant comme argument un objet de la classe SOAP::SOM qui contient la requête désérialisée, cette méthode retourne une liste à trois éléments décrivant la méthode qui doit être appelée. Les éléments sont :

classe
La classe dans laquelle l'appel de méthode doit être effectué. Cela peut être renvoyé sous forme de chaîne de caractères ou de référence d'objet, si le routage est configuré à l'aide d'une instance d'objet.
uri
L'identifiant URN associé à la méthode de la requête. C'est la valeur qui a été utilisée lors de la configuration du routage des méthodes sur l'objet serveur.
nom
Le nom de la méthode à appeler.
handle
$serveur->handle($texte_requête);

Implémente la fonctionnalité principale du processus de service, dans lequel le serveur prend une requête entrante et la distribue à la sous-routine côté serveur correcte. Le paramètre pris en entrée est soit du XML brut, soit du contenu encodé MIME (si le support de l'encodage MIME est activé).

make_fault
retourne $serveur->makefault($code, $message);

Crée un objet SOAP::Fault à partir des données transmises. L'ordre des arguments est : code, message, détail, acteur. Les deux premiers sont obligatoires (car ils doivent être présents dans tous les faults), mais les deux derniers peuvent être omis sauf s'ils sont nécessaires.

SOAP::Server::Parameters

Cette classe fournit deux méthodes, mais le but principal du point de vue du développeur est de permettre aux classes qu'un serveur SOAP expose d'hériter d'elle. Lorsqu'une classe hérite de la classe SOAP::Server::Parameters, la liste des paramètres passés à une méthode appelée inclut la requête désérialisée sous la forme d'un objet SOAP::SOM. Ce paramètre est passé à la fin de la liste des arguments, donnant aux méthodes la possibilité de l'ignorer sauf si elle est nécessaire.

La classe fournit deux sous-routines (pas des méthodes) pour récupérer les paramètres de l'objet SOAP::SOM. Celles-ci sont conçues pour être appelées sans référence d'objet dans la liste des paramètres, mais avec une référence de tableau à la place (comme premier paramètre). Le reste de la liste des arguments est censé être la liste de l'appel de méthode lui-même, y compris l'objet SOAP::SOM à la fin de la liste. Les routines peuvent être utiles à comprendre si une application souhaite sous-classer SOAP::Server::Parameters et hériter de la nouvelle classe à la place.

byNameOrOrder(ordre, liste de paramètres, enveloppe)
@args = SOAP::Server::Parameters::byNameOrOrder ([qw(a b)], @_);

En utilisant la liste des noms d'arguments passés dans l'argument initial comme référence de tableau, cette routine retourne une liste des valeurs de paramètres pour les paramètres correspondant à ces noms, dans cet ordre. Si aucun des noms donnés dans la référence de tableau initiale n'existe dans la liste des paramètres, les valeurs sont retournées dans l'ordre dans lequel elles apparaissent déjà dans la liste des paramètres. Dans ce cas, le nombre de valeurs retournées peut différer de la longueur de la liste des paramètres demandés.

byName(ordre, liste de paramètres, enveloppe)
@args = SOAP::Server::Parameters::byName ([qw(a b c)], @_);

Agit de manière similaire à la précédente, à la différence qu'elle retourne toujours autant de valeurs que demandé, même si certaines (ou toutes) n'existent pas. Les paramètres qui n'existent pas dans la liste des paramètres sont retournés comme valeurs undef.

EXEMPLE

Voici un exemple de service Web basé sur CGI qui utilise un module Perl qui hérite de la classe "SOAP::Server::Parameters". Cela permet aux méthodes de cette classe d'accéder à ses entrées par leur nom.

#!/usr/bin/perl
use SOAP::Transport::HTTP;
SOAP::Transport::HTTP::CGI
  ->dispatch_to('C2FService')
  ->handle;
BEGIN {
  package C2FService;
  use vars qw(@ISA);
  @ISA = qw(Exporter SOAP::Server::Parameters);
  use SOAP::Lite;
  sub c2f {
    my $self = shift;
    my $envelope = pop;
    my $temp = $envelope->dataof("//c2f/temperature");
    return SOAP::Data->name('convertedTemp' => (((9/5)*($temp->value)) + 32));
  }
}
