Description Détaillée

Le nœud SoShadowGroup est un nœud de groupe utilisé pour le rendu d'ombres.

Les enfants de ce nœud peuvent recevoir des ombres et en projeter sur d'autres enfants. Utilisez le nœud SoShadowStyle pour contrôler les projecteurs d'ombres et les récepteurs d'ombres.

Veuillez noter que tous les projecteurs d'ombres seront rendus deux fois. Une fois pour créer la carte d'ombres, et une fois pour le rendu normal. Si vous rencontrez des problèmes de performance, vous devriez envisager de réduire le nombre de projecteurs d'ombres.

L'algorithme utilisé pour rendre les ombres est Variance Shadow Maps (http://www.punkuser.net/vsm/). En bonus, toute la géométrie rendue avec des ombres peut également être rendue avec un éclairage Phong par fragment.

Ce nœud recherchera dans son sous-graphe et calculera les ombres pour tous les nœuds SoSpotLight. Le nœud utilisera une unité de texture pour chaque lumière spot, donc pour que ce nœud fonctionne à 100%, vous avez besoin d'unités de texture libres pour chaque lumière spot lors du rendu du sous-graphe.

Actuellement, nous ne prenons en charge que les scènes avec un maximum de deux unités de texture actives lors du rendu d'ombres (unité 0 et unité 1). Ceci est dû au fait que nous émulations le modèle d'ombrage OpenGL dans un programme de shader, et nous travaillons toujours à la création d'une solution qui met à jour le programme de shader pendant le parcours du graphe de scène. Actuellement, un programme de shader est créé lors de l'entrée dans le nœud SoShadowGroup, et celui-ci est utilisé pour tout le sous-graphe.

FORMAT DE FICHIER / VALEURS PAR DÉFAUT :

SoShadowGroup {
  isActive TRUE
  intensity 0.5
  precision 0.5
  quality 0.5
  shadowCachingEnabled TRUE
  visibilityRadius -1.0
  visibilityFlag LONGEST_BBOX_EDGE_FACTOR
  epsilon 0.00001
  threshold 0.1
  smoothBorder 0.0
}

Une note importante concernant cette fonction :

La conception de l'API de cette fonction présente une grave lacune, car les fonctionnalités d'OpenGL doivent être testées dans un contexte OpenGL, et cette fonction ne fournit aucun moyen de spécifier le contexte. Elle est implémentée de cette manière pour correspondre à la signature de la fonction dans TGS Inventor, pour des raisons de compatibilité.

(Un contexte OpenGL temporaire hors écran est mis en place pour les tests de fonctionnalités. Cela devrait généralement suffire pour décider si le pilote / la carte graphique prend en charge les fonctionnalités nécessaires au rendu des ombres.)

void SoShadowGroup::GLRenderBelowPath (SoGLRenderAction * action) [virtual]

SGI Open Inventor v2.1 a rendu obsolète la prise en charge de SoGLRenderAction::addMethod(). Au lieu de cela, GLRender() peut être appelé directement, et pour optimiser le parcours, le nœud SoSeparator appelle GLRenderBelowPath lorsque le code de parcours est BELOW_PATH ou NO_PATH (le code de parcours est garanti de ne pas changer). Pour être compatible avec Inventor de SGI (et par conséquent aussi avec celui de TGS), nous avons choisi de suivre leur implémentation à cet égard.

SoSeparator::GLRenderBelowPath() ne parcourt pas ses enfants en utilisant SoChildList::traverse(), mais appelle GLRenderBelowPath() directement pour tous ses enfants.

void SoShadowGroup::enableSubgraphSearchOnNotify (const SbBool onoff)

Par défaut, le nœud SoShadowGroup recherchera dans son sous-graphe les nouvelles lumières ponctuelles chaque fois qu'un nœud de groupe en dessous sera touché. Cependant, cela pourrait entraîner de mauvaises performances dans certains cas, il est donc possible de désactiver cette fonctionnalité en utilisant cette méthode. Si vous désactivez cette fonctionnalité, assurez-vous de la réactiver avant d'insérer une nouvelle lumière ponctuelle, ou insérez toutes les lumières ponctuelles dans le graphe de scène avant de rendre la scène une fois, et définissez simplement "on" sur FALSE si vous voulez activer/désactiver les lumières ponctuelles à la volée.

Documentation Donnees Membre

SoSFBool SoShadowGroup::isActive

Utilisez ce champ pour activer/désactiver le rendu des ombres pour le sous-graphe. La valeur par défaut est TRUE.

SoSFFloat SoShadowGroup::intensity

Pas encore utilisé. Fourni pour la compatibilité TGS Inventor.

SoSFFloat SoShadowGroup::precision

Utilisé pour calculer la taille de la carte d'ombre. Une précision de 1.0 signifie que la taille maximale du tampon d'ombre sera utilisée (généralement 2048x2048 sur les cartes graphiques actuelles). La valeur par défaut est 0.5.

SoSFFloat SoShadowGroup::quality

Peut être utilisé pour ajuster la complexité du programme shader. Une valeur plus élevée signifiera que plus de calculs sont effectués par fragment au lieu de par sommet. La valeur par défaut est 0.5.

SoSFFloat SoShadowGroup::smoothBorder

SoShadowGroup::VisibilityFlag SoShadowGroup::ABSOLUTE_RADIUS

Les valeurs absolues de visibilityNearRadius et visibilityRadius seront utilisées.

SoShadowGroup::VisibilityFlag SoShadowGroup::LONGEST_BBOX_EDGE_FACTOR

Le bord le plus long de la boîte englobante sera utilisé pour déterminer les plans de découpe proche et lointain.

SoShadowGroup::VisibilityFlag SoShadowGroup::PROJECTED_BBOX_DEPTH_FACTOR

La profondeur de la boîte englobante (projetée pour faire face à la caméra) sera utilisée pour calculer les plans de découpe.

Nous avons quelques problèmes avec cette fonctionnalité, elle n'est donc pas prise en charge pour le moment.

Utilisé pour ajouter un lissage des bords d'ombre. Ceci est actuellement fait comme une étape de post-traitement sur la carte d'ombre. L'algorithme utilisé est le lissage de Gauss, mais à l'avenir, nous changerons probablement cela et utiliserons une méthode d'échantillonnage par aire sommée à la place. La valeur doit être un nombre compris entre 0 (pas de lissage) et 1 (lissage maximal).

Si vous souhaitez activer le lissage, choisir une valeur faible (~0.1) fonctionne le mieux dans l'implémentation actuelle.

La valeur par défaut est 0.0.

SoSFBool SoShadowGroup::shadowCachingEnabled

Pas encore utilisé. Fourni pour la compatibilité TGS Inventor.

SoSFFloat SoShadowGroup::visibilityNearRadius

Peut être utilisé pour définir manuellement le plan de découpe proche des cartes d'ombre. Si une valeur négative est fournie, le groupe calculera un plan proche basé sur la boîte englobante des enfants. La valeur par défaut est -1.0.

visibilityFlag

SoSFEnum SoShadowGroup::visibilityFlag

Détermine comment visibilityRadius et visibilitNearRadius sont utilisés pour calculer les plans de découpe proche et lointain pour le volume d'ombre.

SoSFFloat SoShadowGroup::epsilon

Epsilon est utilisé pour décaler la profondeur de la carte d'ombre par rapport à la profondeur du modèle. Il doit être défini à un nombre aussi bas que possible sans provoquer de scintillement dans les ombres ou sur les objets non ombragés. La valeur par défaut est 0.00001.

SoSFFloat SoShadowGroup::threshold

Peut être utilisé pour éviter les fuites de lumière dans les ombres fusionnées projetées par différents objets.

Un seuil pour éliminer complètement toute fuite de lumière peut être calculé à partir du rapport des distances des occluseurs qui se chevauchent du point de vue de la lumière. Voir http://forum.beyond3d.com/showthread.php?t=38165 pour une discussion sur ce problème.
