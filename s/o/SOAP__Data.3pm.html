SOAP::Data(3) Documentation soumise par les utilisateurs Perl SOAP::Data(3)

Nom

SOAP::Data - cette classe fournit les moyens par lesquels tous les aspects de la façon dont les données Perl sont exprimées en tant qu'entités SOAP peuvent être explicitement manipulés et contrôlés.

Description

La classe SOAP::Data fournit les moyens par lesquels tous les aspects de la façon dont les données Perl sont exprimées en tant qu'entités SOAP peuvent être explicitement manipulés et contrôlés. La plupart des méthodes sont des accesseurs, qui, comme pour SOAP::Lite, sont conçus pour renvoyer la valeur actuelle si aucune nouvelle valeur n'est passée, tout en renvoyant une référence à l'objet dans le cas contraire (permettant des appels de méthodes chaînées). Note : presque tous les accesseurs (à l'exception de la valeur) acceptent une nouvelle valeur pour l'objet de données comme deuxième argument.

Méthodes

new(paires clé/valeur facultatives)
$obj = SOAP::Data->new(name => 'idx', value => 5);

C'est le constructeur de la classe. La plupart des attributs liés à la classe peuvent être passés au constructeur sous forme de paires clé-valeur. Cette méthode n'est pas fréquemment utilisée car les objets SOAP::Data sont généralement créés pour un usage temporaire. Elle est disponible pour les cas qui en ont besoin.

name(nouveau nom, valeur facultative)
$obj->name('index');

Récupère ou définit la valeur actuelle du nom, tel que l'objet le considère. Le nom est ce que le sérialiseur utilisera pour l'étiquetage lors de la génération du XML pour cet objet. C'est ce qui deviendra l'accès à l'élément de données. Optionnellement, la valeur de l'objet peut être mise à jour si elle est passée comme deuxième argument.

type(nouveau type, valeur facultative)
$obj->type('int');

Récupère ou définit le type associé à la valeur actuelle dans l'objet. C'est utile dans les cas où l'objet SOAP::Data est utilisé pour spécifier explicitement le type de données qui serait autrement interprété comme un type différent (par exemple, interpréter la chaîne 123 comme un entier plutôt qu'un nombre). Permet de définir la valeur de l'objet si elle est passée comme deuxième argument à la méthode.

uri(nouvel URI, valeur facultative)
$obj->uri('http://www.perl.com/SOAP');

Récupère ou définit l'URI qui sera utilisée comme espace de noms pour l'entité XML résultante, si désiré. Cela ne définit pas l'étiquetage de l'espace de noms. S'il n'est pas fourni via la méthode prefix, il est généré automatiquement si nécessaire. Permet également de définir la valeur de l'objet, si elle est passée comme deuxième argument à la méthode.

prefix(nouveau préfixe, valeur facultative)
$obj->prefix('perl');

Fournit le préfixe, ou l'étiquetage, à utiliser lors de l'association de l'objet de données à un espace de noms spécifique. Permet également de définir la valeur de l'objet, si elle est passée comme deuxième argument à la méthode.

attr(référence de hachage d'attributs, valeur facultative)
$obj->attr({ attr1 => 'value' });

Permet de définir des attributs arbitraires sur l'objet de données. Gardez à l'esprit que tout attribut non natif connu par SOAP doit être étiqueté avec l'espace de noms. Permet également de définir la valeur de l'objet, si elle est passée comme deuxième argument à la méthode.

value(nouvelle valeur)
$obj->value(10);

Récupère la valeur actuelle encapsulée par l'objet, ou la définit explicitement.

Les quatre dernières méthodes sont des raccourcis pour les attributs pris en charge par SOAP lui-même. Chacune permet également d'inclure une nouvelle valeur, comme deuxième argument facultatif.

actor(nouvel acteur, valeur facultative)
$obj->actor($new_actor_name);

Récupère ou définit la valeur de la propriété actor ; utile uniquement lorsque l'objet génère une entité pour l'en-tête du message.

mustUnderstand(booléen, valeur facultative)
$obj->mustUnderstand(0);

Manipule l'attribut mustUnderstand, qui indique si le processeur SOAP doit comprendre l'entité en question.

encodingStyle(nouvel URN d'encodage, valeur facultative)
$obj->encodingStyle($soap_11_encoding);

Cette méthode est probablement plus utilisée dans des endroits autres que la création d'en-têtes. Elle définit encodingStyle, qui spécifie un style d'encodage différent de celui utilisé par défaut.

root(booléen, valeur facultative)
$obj->root(1);

Lorsque l'application doit explicitement spécifier quel élément de données doit être considéré comme l'élément racine pour générer le modèle objet, cette méthode fournit l'accès à l'attribut root.

Détection du type

Le sérialiseur SOAP::Lite détectera le type de toute valeur scalaire passée comme objet SOAP::Data. Comme Perl est faiblement typé, le sérialiseur ne peut détecter que des types basés sur un ensemble prédéfini d'expressions régulières. Par conséquent, la détection de type n'est pas toujours précise. Dans ce cas, vous pourriez avoir besoin de définir explicitement le type de l'élément qui est sérialisé. Par exemple, par défaut, le code suivant sera sérialisé comme un entier :

$elem = SOAP::Data->name('idx')->value(5);

Cependant, si vous devez le sérialiser comme un entier, le code suivant le fera :

$elem = SOAP::Data->name('idx')->value(5)->type('long');

Exemples

Types Simples

L'exemple suivant produira le même XML :

$elem1 = SOAP::Data->new(name => 'idx', value => 5);
$elem2 = SOAP::Data->name('idx' => 5);
$elem3 = SOAP::Data->name('idx')->value(5);

Types Complexes

Une question fréquente est de savoir comment créer des éléments XML imbriqués en utilisant SOAP::Lite. L'exemple suivant montre comment :

SOAP::Data->name('foo' => \SOAP::Data->value(
    SOAP::Data->name('bar' => '123')));

Le code ci-dessus produira le XML suivant :

<foo>
  <bar>123</bar>
</foo>

Arbre de données

Le code suivant :

$elem1 = SOAP::Data->name('item' => 123)->type('SomeObject');
$elem2 = SOAP::Data->name('item' => 456)->type('SomeObject');
push(@array,$elem1);
push(@array,$elem2);
my $client = SOAP::Lite
    ->readable(1)
    ->uri($NS)
    ->proxy($HOST);
$temp_elements = SOAP::Data
    ->name("CallDetails" => \SOAP::Data->value(
          SOAP::Data->name("elem1" => 'foo'),
          SOAP::Data->name("elem2" => 'baz'),
          SOAP::Data->name("someArray" => \SOAP::Data->value(
              SOAP::Data->name("someArrayItem" => @array)
                        ->type("SomeObject"))
                   )->type("ArrayOf_SomeObject"))
->type("SomeObject");
$response = $client->someMethod($temp_elements);

produira le XML suivant :

<?xml version="1.0" encoding="UTF-8"?>
<SOAP-ENV:Envelope
    xmlns:xsi="http://www.w3.org/2001/XMLSchema-instance"
    xmlns:SOAP-ENC="http://schemas.xmlsoap.org/soap/encoding/"
    xmlns:SOAP-ENV="http://schemas.xmlsoap.org/soap/envelope/"
    xmlns:xsd="http://www.w3.org/2001/XMLSchema"
    xmlns:namesp2="http://namespaces.soaplite.com/perl"
    SOAP-ENV:encodingStyle="http://schemas.xmlsoap.org/soap/encoding/">
  <SOAP-ENV:Body>
    <namesp1:someMethod xmlns:namesp1="urn:TemperatureService">
      <CallDetails xsi:type="namesp2:SomeObject">
