Description Détaillée

La classe SoProto gère les définitions PROTO.

SoProto et SoProtoInstance sont principalement des classes internes. Elles sont conçues pour lire et gérer les PROTOs VRML97. Cependant, il est possible de définir vos PROTOs en C++. Vous devez définir votre PROTO dans un tableau de caractères, et lire ce tableau de caractères en utilisant SoInput::setBuffer() et SoDB::readAllVRML(). Exemple :

char myproto[] =
"#VRML V2.0 utf8\n"
"PROTO ColorCube [\n"
"  field SFColor color 1 1 1\n"
"  field SFVec3f size 1 1 1\n"
"]\n"
"{\n"
"  Shape {\n"
"    appearance Appearance {\n"
"      material Material {\n"
"        diffuseColor IS color\n"
"      }\n"
"    }\n"
"    geometry Box { size IS size }\n"
"  }\n"
"}\n"
"ColorCube { color 1 0 0 size 2 1 1 }\n";
SoInput in;
in.setBuffer(myproto, strlen(myproto));
SoVRMLGroup * protoroot = SoDB::readAllVRML(&in);

Maintenant, vous pouvez créer de nouvelles instances du PROTO ColorCube en utilisant SoProto::findProto() et SoProto::createProtoInstance(). Si vous souhaitez insérer des instances de PROTO dans votre graphe de scène, vous devez insérer le nœud renvoyé par SoProtoInstance::getRootNode().

Voir http://www.web3d.org/documents/specifications/14772/V2.0/part1/concepts.html#4.8 pour plus d'informations sur les PROTOs en VRML97.

SoType SoProto::getTypeId (void ) const [virtual]

Renvoie l'identification de type d'un objet dérivé d'une classe héritant de SoBase. Ceci est utilisé pour la vérification de type au moment de l'exécution et pour le "downcast" (conversion vers une classe de base). Exemple d'utilisation :

void foo(SoNode * node)
{
  if (node->getTypeId() == SoFile::getClassTypeId()) {
    SoFile * filenode = (SoFile *)node;  // downcast sûr, connaît le type
  }
}

Pour les programmeurs d'applications souhaitant étendre la bibliothèque avec de nouveaux nœuds, moteurs, kits de nœuds, draggers ou autres : cette méthode doit être redéfinie dans *toutes* les sous-classes. Ceci est généralement fait dans le cadre de la configuration du système de types complet pour les classes d'extension, ce qui est généralement réalisé en utilisant les macros prédéfinies disponibles via, par exemple, Inventor/nodes/SoSubNode.h (SO_NODE_INIT_CLASS et SO_NODE_CONSTRUCTOR pour les classes de nœuds), Inventor/engines/SoSubEngine.h (pour les classes de moteurs) et ainsi de suite.

Pour plus d'informations sur l'écriture d'extensions Coin, voir la documentation de classe des super-classes de niveau supérieur pour les divers groupes de classes.

SbBool SoProto::readInstance (SoInput * in, unsigned short flags) [virtual]

Cette méthode est principalement destinée à un usage interne lors des opérations d'importation de fichiers.

Elle lit une définition d'une instance à partir du flux d'entrée in. L'état du flux d'entrée pointe vers le début d'une représentation série/persistante d'une instance de ce type de classe.

TRUE ou FALSE est retourné, selon que l'instanciation et la configuration du nouvel objet de ce type de classe se sont bien déroulées ou non. Le processus d'importation doit être robuste et gérer les flux d'entrée corrompus en retournant FALSE.

flags est utilisé en interne lors de l'importation binaire lors de la lecture de nœuds d'extension utilisateur, de nœuds de groupe ou d'engines.
