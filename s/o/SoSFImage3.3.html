Description Détaillée

La classe SoSFImage3 est utilisée pour stocker des images 3D (volumiques).

La classe SoSFImage3 fournit un stockage pour les cartes d'images 3D inline. Les images 3D dans Coin sont principalement utilisées pour le support du mappage de textures 3D.

Les instances de SoSFImage3 peuvent être exportées et importées comme toute autre classe de champ dans Coin.

Les composantes d'un SoSFImage3 sont : ses dimensions d'image (largeur, hauteur et profondeur), le nombre d'octets utilisés pour décrire chaque pixel (nombre de composantes) et un tampon de pixels associé. La taille du tampon de pixels sera largeur*hauteur*profondeur*composantes.

Pour les cartes de textures, les composantes / octets-par-pixel se traduisent comme suit : utiliser 1 pour une image en niveaux de gris, 2 pour niveaux de gris + opacité (c'est-à-dire valeur alpha), 3 pour RVB (1 octet chacune pour rouge, vert et bleu) et 4 composantes signifie 3 octets pour RVB + 1 octet d'opacité (également appelé RVBA).

Ce champ est sérialisable dans le format de fichier Inventor / Coin de la manière suivante :

NOM_DU_CHAMP X Y Z C 0xRRGGBBAA 0xRRGGBBAA ...

"X", "Y" et "Z" sont les dimensions de l'image le long des axes donnés, "C" est le nombre de composantes dans l'image. Le nombre de spécifications de couleur de pixel 0xRRGGBBAA doit être égal au nombre exact de pixels, qui est X*Y*Z. Chaque partie de la valeur de couleur du pixel est comprise entre 0x00 et 0xff (hexadécimal, 0 à 255 décimal).

Pour les images à 3 composantes, le format du pixel est 0xXXRRGGBB, où l'octet dans la valeur de couleur du pixel marqué comme "XX" est ignoré et peut être omis.

Pour les images à 2 composantes, le format du pixel est 0xXXXXGGAA, où les octets dans les valeurs de couleur des pixels marqués comme "XX" sont ignorés et peuvent être omis. "GG" est la partie qui donne une valeur de niveaux de gris et "AA" est pour l'opacité.

Pour les images à 1 composante, le format du pixel est 0xXXXXXXGG, où les octets dans les valeurs de couleur des pixels marqués comme "XX" sont ignorés et peuvent être omis.

Les pixels sont lus comme étant ordonnés en lignes le long de X (largeur), colonnes le long de Y (hauteur, du bas vers le haut) et plans Z (profondeur, de l'avant vers l'arrière).

Voici un exemple simple de sérialisation du format de fichier, pour une image RVB 2x2x2 à l'intérieur d'un nœud SoTexture3 :

Texture3 {
  images 2 2 2 3
  0x000000 0x00ff00
  0xff0000 0xffff00
  0x000000 0x0000ff
  0x00ff00 0x00ffff
}

L'image ci-dessus est colorée en noir+vert sur la première ligne et en rouge+jaune sur la seconde ligne dans le premier plan Z. Le second plan Z est coloré en noir+bleu sur la première ligne et en vert+cyan sur la seconde ligne.

NAME

SoSFImage3 — 3D image field

SYNOPSIS

Inherits from SoField.

class SoSFImage3 : public SoField {
  public:
    // Types
    typedef unsigned char             PixelType;

    // Constructor
    SoSFImage3();

    // Public methods
    void                  setValue(const SbVec3s & size, const int nc, const PixelType * bytes);
    const PixelType *     getValue(SbVec3s & size, int & nc) const;
    PixelType *           startEditing(SbVec3s & size, int & nc);
    void                  finishEditing();
    int                   operator==(const SoSFImage3 & field) const;
    int                   operator!=(const SoSFImage3 & field) const;

    // Pure virtual methods from SoField
    virtual void          copyFrom(const SoField & f);
    virtual SbBool        isSame(const SoField & f) const;
    virtual SoType          getTypeId() const;

    // Internal methods
    static SoType          getClassTypeId();
    static void           initClass();
    void *                createInstance();

  protected:
    // Constructor for derived classes
    SoSFImage3(const SoSFImage3 & f);
    SoSFImage3(const int nc, const SbVec3s & size, const PixelType * bytes);
    virtual ~SoSFImage3();

    // Notification methods
    virtual void          notify(const SoField * field);
};

DESCRIPTION

A 3D image field is a field that contains a 3D image. A 3D image is defined by a size (width, height, depth) and an array of pixel values. The pixel values can be either RGB triplets (three bytes per pixel) or single-component values (one byte per pixel).

The SoSFImage3 class is an extension for Coin, and it is not available in the original SGI Open Inventor v2.1 API.

See also

SoTexture3, SoSFImage

Since

Coin 2.0

TGS Inventor 2.6
