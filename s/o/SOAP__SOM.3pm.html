SOAP::SOM(3) Documentation Perl fournie par l'utilisateur SOAP::SOM(3)

NOM

SOAP::SOM - fournit un accès aux valeurs contenues dans une réponse SOAP

DESCRIPTION

Les objets de la classe SOAP::SOM ne sont généralement pas instanciés directement par une application. Ils sont plutôt retournés par la désérialisation d'un message. En d'autres termes, les développeurs ne feront presque jamais ceci :

$som = SOAP::SOM->new;

Les objets SOAP::SOM sont retournés par un appel SOAP::Lite dans un contexte client. Par exemple :

my $client = SOAP::Lite
    ->readable(1)
    ->uri($NS)
    ->proxy($HOST)
$som = $client->someMethod();

MÉTHODES

new(message)
$som = SOAP::SOM->new($message_as_xml);

Comme mentionné, le besoin de créer réellement un objet de cette classe devrait être très rare. Cependant, si le besoin se présente, la syntaxe doit être respectée. L'argument unique de new doit être un document XML valide que l'analyseur comprendra comme une réponse SOAP.

Le groupe de méthodes suivant fournit une récupération générale des données à partir de l'objet SOAP::SOM. Le modèle pour cela est une forme abrégée d'XPath. Suite à ce groupe se trouvent des méthodes axées sur la récupération spécifique d'éléments couramment demandés.

match(path)
$som->match('/Envelope/Body/[1]');

Cette méthode définit les pointeurs internes dans la structure de données afin que les méthodes de récupération suivantes aient accès aux données souhaitées. Dans le chemin d'exemple, la correspondance est faite contre l'entité de méthode, qui est le premier élément enfant du corps dans une réponse SOAP. L'énumération des enfants conteneurs commence à 1 dans cette syntaxe, pas à 0. La valeur retournée dépend du contexte de l'appel. Si l'appel est effectué dans un contexte booléen (tel que "if ($som->match($path))"), la valeur de retour est un booléen indiquant si le chemin demandé a correspondu ou non. Sinon, une référence d'objet est retournée. L'objet retourné est également une instance de SOAP::SOM mais est plus petite, contenant le sous-ensemble de l'arbre de document correspondant à l'expression.

valueof(node)
$res = $som->valueof('[1]');

Lorsque l'objet SOAP::SOM a fait correspondre un chemin en interne avec la méthode match, cette méthode permet la récupération des données à l'intérieur de n'importe lequel des nœuds correspondants. Les données reviennent sous forme de données Perl natives, pas d'instance de classe (voir dataof). Dans un contexte scalaire, cette méthode retourne uniquement le premier élément d'un ensemble de nœuds correspondant. Dans un contexte de tableau, tous les éléments sont retournés. En supposant que l'appel précédent se fait après l'appel précédent à match, il récupère l'entité de résultat de la réponse de méthode qui est contenue dans $som, car c'est le premier élément enfant d'une balise de réponse de méthode.

dataof(node)
$resobj = $som->dataof('[1]');

Effectue la même opération que la méthode valueof précédente, sauf que les données sont laissées sous leur forme SOAP::Data, plutôt que d'être désérialisées. Cela permet un accès complet à tous les attributs qui ont été sérialisés avec les données, tels que l'espace de noms et l'encodage.

headerof(node)
$resobj = $som->headerof('[1]');

Agit beaucoup comme dataof, sauf qu'il retourne un objet de la classe SOAP::Header (couvert plus loin dans ce chapitre), plutôt que SOAP::Data. C'est l'interface préférée pour manipuler les entités d'en-tête dans un message.

namespaceuriof(node)
$ns = $som->namespaceof('[1]');

Récupère l'URI d'espace de noms qui régit le nœud demandé. Notez que les espaces de noms sont hérités, donc cette méthode retournera la valeur pertinente, même si elle dérive d'un nœud parent ou autre ancêtre.

Les méthodes suivantes fournissent un accès plus direct à l'enveloppe du message. Toutes ces méthodes retournent une forme de valeur Perl, le plus souvent une référence de hachage, lorsqu'elles sont appelées. Le contexte est également pertinent : dans un contexte scalaire seul le premier nœud correspondant est retourné, tandis que dans un contexte de tableau, tous les nœuds correspondants le sont. Lorsqu'elles sont appelées en tant que méthode statique ou en tant que fonction régulière (telle que "SOAP::SOM::envelope"), n'importe laquelle des méthodes suivantes retourne la chaîne XPath qui est utilisée avec la méthode match pour récupérer les données.

root
$root = $som->root;

Retourne la valeur de l'élément racine sous forme de référence de hachage. Il se comporte exactement comme "$som-"valueof('/')> fait.

envelope
$envelope = $som->envelope;

Récupère l'élément « Envelope » du message, le retournant ainsi que ses données sous forme de référence de hachage. Les clés dans le hachage seront Header et Body (plus tout élément optionnel qui peut être présent dans une enveloppe SOAP 1.1), dont les valeurs seront respectivement l'en-tête et le corps sérialisés.

header
$header = $som->header;

Récupère la partie en-tête de l'enveloppe sous forme de référence de hachage. Toutes les données qu'elle contient auront été désérialisées. Si les attributs de l'en-tête sont souhaités, la forme statique de la méthode peut être combinée avec match pour récupérer l'en-tête en tant qu'objet SOAP::Data :

$header = $som->match(SOAP::SOM::header)->dataof;
headers
@hdrs = $som->headers;

Récupère l'ensemble de nœuds des valeurs avec les en-têtes désérialisés à l'intérieur du conteneur Header. Ceci est différent de la méthode header précédente en ce qu'elle retourne l'en-tête entier sous une seule structure, et celle-ci retourne les éléments enfants sous forme de tableau. En d'autres termes, les expressions suivantes donnent la même structure de données :

$header = ($som->headers)[0];
$header = $som->valueof(SOAP::SOM::header.'/[1]');
body
$body = $som->body;

Récupère le corps du message sous forme de référence de hachage. Les balises d'entité agissent comme des clés, avec leur contenu désérialisé fournissant les valeurs.

fault
if ($som->fault) { die $som->fault->faultstring }

Agit à la fois comme un test booléen pour savoir si une erreur s'est produite, et comme un moyen de récupérer l'entité Fault elle-même à partir du corps du message sous forme de référence de hachage. Si le message contient une erreur, les quatre méthodes suivantes (faultcode, faultstring, faultactor et faultdetail) peuvent être utilisées pour récupérer les parties respectives de l'erreur (qui sont également disponibles sur la référence de hachage en tant que clés). Si fault dans un contexte booléen est vrai, les méthodes "result", "paramsin", "paramsout" et "method" retournent toutes "undef".

faultcode
$code = $som->faultcode;

Retourne l'élément faultcode de l'erreur s'il y a une erreur ; undef sinon.

faultstring
$string = $som->faultstring;

Retourne l'élément faultstring de l'erreur s'il y a une erreur ; undef sinon.

faultactor
$actor = $som->faultactor;

Retourne l'élément faultactor de l'erreur, s'il y a une erreur et si l'acteur a été spécifié à l'intérieur. L'élément faultactor est optionnel dans la sérialisation d'une erreur, il peut donc ne pas toujours être présent. Cet élément est généralement une chaîne de caractères.

SOAP::SOM - Perl SOAP::Lite documentation

NAME

SOAP::SOM - Perl SOAP::Lite documentation

DESCRIPTION

SOAP::SOM is a class that provides access to the SOAP Structure Object Model. It is an abstract representation of a SOAP message as a traversable structure.

The SOAP::SOM class provides a convenient interface for accessing various parts of a SOAP message, such as the method name, parameters, results, and fault information. It can be used for both parsing incoming SOAP messages and constructing outgoing ones.

The detail element was provided. Note that the name of the element isn't the same as the method, due to the possibility for confusion had the method been called simply, detail. As with the faultactor element, this isn't always a required component of a fault, so it isn't guaranteed to be present. The specification for the detail portion of a fault calls for it to contain a series of element tags, so the application may expect a hash reference as a return value when detail information is available (and undef otherwise).

METHODS

method
$method = $som->method

Retrieves the "method" element of the message, as a hash reference. This includes all input parameters when called on a request message or all result/output parameters when called on a response message. If there is a fault present in the message, it returns undef.

result
$value = $som->result;

Returns the value that is the result of a SOAP response. The value will be already deserialized into a native Perl datatype.

paramsin
@list = $som->paramsin;

Retrieves the parameters being passed in on a SOAP request. If called in a scalar context, the first parameter is returned. When called in a list context, the full list of all parameters is returned. Each parameter is a hash reference, following the established structure for such return values.

paramsout
@list = $som->paramsout;

Returns the output parameters from a SOAP response. These are the named parameters that are returned in addition to the explicit response entity itself. It shares the same scalar/list context behavior as the paramsin method.

paramsall
@list = $som->paramsall;

Returns all parameters from a SOAP response, including the result entity itself, as one array.

parts()
Return an array of "MIME::Entity"'s if the current payload contains attachments, or returns undefined if payload is not MIME multipart.
is_multipart()
Returns true if payload is MIME multipart, false otherwise.

EXAMPLES

ACCESSING ELEMENT VALUES

Suppose for the following SOAP Envelope:

<Envelope>
  <Body>
    <fooResponse>
      <bar>abcd</bar>
    </fooResponse>
  </Body>
</Envelope>

And suppose you wanted to access the value of the bar element, then use the following code:

my $soap = SOAP::Lite
    ->uri($SOME_NS)
    ->proxy($SOME_HOST);
my $som = $soap->foo();
print $som->valueof('//fooResponse/bar');

ACCESSING ATTRIBUTE VALUES

Suppose the following SOAP Envelope:

<Envelope>
  <Body>
    <c2fResponse>
      <convertedTemp test="foo">98.6</convertedTemp>
    </c2fResponse>
  </Body>
</Envelope>

Then to print the attribute 'test' use the following code:

print "The attribute is: " .
  $som->dataof('//c2fResponse/convertedTemp')->attr->{'test'};

ITERATING OVER AN ARRAY

Suppose for the following SOAP Envelope:

<Envelope>
  <Body>
    <catalog>
      <product>
        <title>Programming Web Service with Perl</title>
        <price>$29.95</price>
      </product>
      <product>
        <title>Perl Cookbook</title>
        <price>$49.95</price>
      </product>
    </catalog>
  </Body>
</Envelope>

If the SOAP Envelope returned contained an array, use the following code to iterate over the array:

for my $t ($som->valueof('//catalog/product')) {
  print $t->{title} . " - " . $t->{price} . "\n";
}

DETECTING A SOAP FAULT

A SOAP::SOM object is returned by a SOAP::Lite client regardless of whether the call succeeded or not. Therefore, a SOAP Client is responsible for determining if the returned value is a fault or not. To do so, use the fault() method which returns 1 if the SOAP::SOM object is a fault and 0 otherwise.

my $som = $client->someMethod(@parameters);
if ($som->fault) {
  print $som->faultdetail;
} else {
  # do something
}

PARSING ARRAYS OF ARRAYS

The most efficient way To parse and to extract data out of an array containing another array encoded in a SOAP::SOM object is the following:

$xml = <<END_XML;
<foo>
  <person>
    <foo>123</foo>
    <foo>456</foo>
  </person>
  <person>
    <foo>789</foo>
    <foo>012</foo>
  </person>
</foo>
END_XML
my $som = SOAP::Deserializer->deserialize($xml);
my $i = 0;
foreach my $a ($som->dataof("//person/*")) {
    $i++;
    my $j = 0;
    foreach my $b ($som->dataof("//person/[$i]/*")) {
        $j++;
        # do something
    }
}
