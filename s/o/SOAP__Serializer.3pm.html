NOM

SOAP::Serializer - le moyen par lequel la boîte à outils gère l'expression des données sous forme de XML

DESCRIPTION

La classe SOAP::Serializer est le moyen par lequel la boîte à outils gère l'expression des données sous forme de XML. L'objet qu'une instance de SOAP::Lite utilise par défaut est généralement suffisant pour la tâche, sans qu'il soit nécessaire pour l'application de créer le sien. Le but principal de cette classe est de fournir un endroit où les applications peuvent étendre le sérialiseur en définissant des méthodes supplémentaires pour gérer de nouveaux types de données.

MÉTHODES

new(paires clé/valeur optionnelles)
$serialize = SOAP::Serializer->new( );

Ceci est la méthode constructeur pour la classe. En plus de créer un objet de base et de l'initialiser avec des valeurs par défaut, le constructeur peut également prendre des noms et des valeurs pour la plupart des méthodes d'accès prises en charge par la classe.

envelope(méthode, arguments de données)
$serialize->envelope(fault => $fault_obj);

Fournit le but principal de la classe SOAP::Serializer. Elle crée l'enveloppe SOAP complète basée sur les entrées qui lui sont passées. Les arguments de données passés dans la liste de paramètres de la méthode sont divisés en deux sous-listes : tous les paramètres qui sont des objets SOAP::Header ou des dérivés vont dans une liste, tandis que les restants vont dans l'autre. Les objets non-header sont utilisés comme contenu du corps du message, le corps lui-même dépendant largement de la valeur du premier argument de la liste. Cet argument est attendu comme une chaîne de caractères et doit être l'un des suivants :

contexte
$serialize->context->packager();

Ceci fournit l'accès au contexte d'appel de "SOAP::Serializer". Dans un contexte côté client, cela signifie souvent une référence à une instance de SOAP::Lite. Dans un contexte côté serveur, cela signifie une référence à une instance de SOAP::Server.

méthode
L'enveloppe est créée pour encapsuler un appel de méthode de style RPC.
réponse
Le message créé est celui d'une réponse résultant d'un appel de méthode de style RPC.
erreur
Pour ce spécificateur, l'enveloppe créée sert à transmettre une erreur.
texte_libre
Cet identifiant est utilisé comme style de codage général pour les messages qui ne correspondent à aucun des cas précédents. Les arguments sont codés dans la balise Body de l'enveloppe sans aucune sensibilité au contexte.

Toute valeur autre que ces quatre entraîne une erreur.

préfixe_env(valeur optionnelle)
$serialize->envprefix('env');

Récupère ou définit le préfixe qui étiquette l'espace de noms de l'enveloppe SOAP. Par défaut, c'est SOAP-ENV.

préfixe_enc(valeur optionnelle)
$serialize->envprefix('enc');

Récupère ou définit le préfixe qui étiquette l'espace de noms de codage SOAP. Par défaut, c'est SOAP-ENC.

version_soap(valeur optionnelle)
$serialize->soapversion('1.2');

Si aucun paramètre n'est donné, retourne la version actuelle de SOAP utilisée comme base pour la sérialisation des messages. Si un paramètre est donné, tente de le définir comme la version de SOAP utilisée. La valeur doit être 1.1 ou 1.2. Lorsque la version SOAP est définie, le package sélectionne de nouveaux URN pour les espaces d'enveloppe et de codage et appelle également la méthode xmlschema pour définir la définition du schéma appropriée.

schéma_xml(valeur optionnelle)
$serialize->xmlschema($xml_schema_1999);

Récupère ou définit l'URN du schéma utilisé pour exprimer la structure du XML généré par le sérialiseur. Lors de la définition de la valeur, l'entrée doit être l'URN complet pour le nouveau schéma et elle est vérifiée par rapport à la liste des schémas SOAP connus.

enregistrer_ns
La sous-routine register_ns permet aux utilisateurs d'enregistrer un espace de noms global avec l'Enveloppe SOAP. Le premier paramètre est l'espace de noms, le second paramètre à cette sous-routine est un préfixe optionnel. Si un préfixe n'est pas fourni, un sera généré automatiquement pour vous. Tous les espaces de noms enregistrés auprès du sérialiseur sont déclarés dans l'élément <soap:Envelope />.
trouver_préfixe
La sous-routine find_prefix prend un espace de noms comme paramètre et retourne le préfixe attribué à cet espace de noms. Cela élimine le besoin de déclarer et redéclarer des espaces de noms dans une enveloppe. Cette sous-routine est particulièrement utile pour déterminer le bon préfixe lors de l'attribution d'un type à un élément SOAP::Data. Un bon exemple de la façon dont cela pourrait être utilisé est le suivant : 
SOAP::Data->name("foo" => $inputParams{'foo'})
   ->type($client->serializer->find_prefix('urn:Foo').':Foo');

TYPES DE DONNÉES PERSONNALISÉS

Lors de la sérialisation d'un objet, ou d'une référence de hachage blessée, en XML, "SOAP::Serializer" vérifie d'abord si une sous-routine a été définie pour le nom de classe correspondant. Par exemple, dans le code ci-dessous, "SOAP::Serializer" vérifiera si une sous-routine appelée "as_MyModule__MyPackage" a été définie. Si c'est le cas, elle passera $foo à cette sous-routine avec d'autres données connues de l'élément "SOAP::Data" en cours de codage.

$foo = MyModule::MyPackage->new;
my $client = SOAP::Lite
   ->uri($NS)
   ->proxy($HOST);
$som = $client->someMethod(SOAP::Data->name("foo" => $foo));

EXIGENCES SOUS-ROUTINE as_TypeName

Convention de nommage
La sous-routine doit toujours être précédée de "as_" suivi du nom du type. Le nom du type doit avoir tous les deux-points (':') remplacés par un underscore ('_').
Entrée
L'entrée de "as_TypeName" aura au moins un paramètre, et au plus quatre. Le premier paramètre sera toujours la valeur ou l'objet à coder. Les trois paramètres suivants dépendent du contexte de la valeur/objet en cours de codage.

Si la valeur/l'objet en cours de codage faisait partie d'un objet "SOAP::Data" (comme dans l'exemple ci-dessus), alors le deuxième, troisième et quatrième paramètres seront le nom, le type et l'ensemble d'attributs de l'élément "SOAP::Data" respectivement. Si, par ailleurs, la valeur/l'objet en cours de codage n'est *pas* partie d'un objet "SOAP::Data", comme dans le code ci-dessous :

$foo = MyModule::MyPackage->new;
my $client = SOAP::Lite
   ->uri($NS)
   ->proxy($HOST);
$som = $client->someMethod($foo);

Alors les deuxième et troisième paramètres seront le nom de la classe de la valeur/objet en cours de codage (par exemple, "MyModule::MyPackage" dans l'exemple ci-dessus), et le quatrième paramètre sera une table de hachage vide.

Sortie
La sous-routine de codage doit retourner un tableau contenant trois éléments : 1) le nom de l'élément XML, 2) une table de hachage contenant les attributs à placer dans l'élément, et 3) la valeur de l'élément.

NOM

SOAP::Serializer.3pm

DESCRIPTION

SOAP::Serializer.3pm est un manuel de référence décrivant la bibliothèque SOAP::Serializer, un module Perl permettant de sérialiser des objets au format XML en utilisant la norme SOAP.

MÉTHODES

SOAP::Serializer.3pm décrit les méthodes disponibles dans la bibliothèque SOAP::Serializer, y compris la sérialisation d'objets, la détection de types autonomes et la configuration de types personnalisés.

TYPES DE DONNÉES PERSONNALISÉS

SOAP::Serializer.3pm permet d'enregistrer des types de données personnalisés qui peuvent être détectés automatiquement et sérialisés en XML.

EXIGENCES DES SOUS-ROUTINES as_TypeName

SOAP::Serializer.3pm spécifie les exigences pour les sous-routines utilisées comme types de données personnalisés.

AUTOTYPAGE

SOAP::Serializer.3pm décrit le processus d'autotypage, où le module détecte automatiquement les types de données et les utilise pour sérialiser les objets.
