NOM

Switch - Un cas pour Perl, n'utilisez pas si vous pouvez utiliser given/when

SYNOPIS

use Switch;
switch ($val) {
    case 1          { print "nombre 1" }
    case "a"        { print "chaîne a" }
    case [1..10,42] { print "nombre dans la liste" }
    case (\@array)  { print "nombre dans la liste" }
    case /\w+/      { print "modèle" }
    case qr/\w+/    { print "modèle" }
    case (\%hash)   { print "entrée dans le hash" }
    case (\&sub)    { print "argument pour la sous-routine" }
    else            { print "cas précédent non vrai" }
}

PRÉAMBULE

[Sautez à « DESCRIPTION » si les pourquoi et où de cette structure de contrôle vous indiffèrent]

En quête d'une « meilleure instruction de cas » pour les conditions distribuées en Perl, il est utile de généraliser cette notion de conditions distribuées autant que possible. Spécifiquement, le concept de « correspondance » entre la valeur du switch et les valeurs des cas ne devrait pas être limité à l'égalité numérique (ou chaîne, ou référentielle), comme c'est le cas dans d'autres langages. En fait, comme le montre le Tableau 1, Perl offre au moins dix-huit manières différentes dont deux valeurs pourraient correspondre.

En réalité, le Tableau 1 couvre 31 alternatives, car seules les tests d'égalité et d'intersection sont commutatifs ; dans les autres cas, les rôles des variables $s et $c peuvent être inversés pour produire un test différent. Par exemple, au lieu de tester une seule clé dans un ensemble de hashs (correspond si exists $s->{$c}), on pourrait tester l'existence d'une seule clé dans un ensemble de hashs (correspond si exists $c->{$s}).

DESCRIPTION

Le module Switch.pm implémente un mécanisme de contrôle généralisé qui couvre la plupart (mais pas toutes) des diverses combinaisons possibles de switch et de case décrites ci-dessus.

Le module étend la syntaxe standard de Perl avec deux nouvelles instructions de contrôle : switch et case. Le switch prend un argument scalaire de n'importe quel type, spécifié entre parenthèses. Le switch stocke cette valeur comme la valeur de switch actuelle dans une variable de contrôle locale. La valeur est suivie d'un bloc qui peut contenir une ou plusieurs instructions Perl (y compris l'instruction case décrite ci-dessous). Le bloc est exécuté de manière inconditionnelle une fois que la valeur du switch a été mise en cache.

Une instruction case prend un argument scalaire (entre parenthèses obligatoires s'il s'agit d'une variable ; sinon, les parenthèses sont optionnelles) et sélectionne le type de comparaison approprié entre cet argument et la valeur actuelle du switch. Le type de comparaison est déterminé par les types respectifs de la valeur du switch et de l'argument du case, tel que spécifié dans le Tableau 1. Si la comparaison réussit, le bloc obligatoire associé à l'instruction case est exécuté.

Pour le reste, l'instruction case est sémantiquement identique à une instruction if. Par exemple, elle peut être suivie d'une instruction else et peut être utilisée comme modificateur d'instruction ultérieure.

Cependant, lorsqu'un bloc case est exécuté, le contrôle passe automatiquement à l'instruction suivant le bloc switch englobant, plutôt qu'à l'instruction suivante dans le bloc. En d'autres termes, le succès de n'importe quelle instruction case empêche l'exécution d'autres cas dans le même périmètre. Mais voir « Autoriser la chute » ci-dessous.

Ces deux nouvelles instructions fournissent un mécanisme de contrôle entièrement généralisé :

use Switch;
# Et puis...
%special = ( woohoo => 1,  d'oh => 1 );
while (<>) {
    chomp;
    switch ($_) {
        case (%special) { print "homer\n"; }      # si $special{$_}
        case /[a-z]/i   { print "alpha\n"; }      # si $_ =~ /a-z/i
        case [1..9]     { print "petit nombre\n"; }  # si $_ dans [1..9]
        case { $_[0] >= 10 } { print "grand nombre\n"; } # si $_ >= 10
        print "doit être de la ponctuation\n"; case /\W/;  # si $_ n'est pas /\W/
    }
}

Remarque : Les switch peuvent être imbriqués dans des blocs case (ou tout autre bloc) et une série d'instructions case peuvent tenter différents types de comparaisons — appartenance à un hash, correspondance de modèle, intersection de tableaux, etc. — avec la même valeur de switch.

L'utilisation de tests d'intersection sur une référence de tableau est particulièrement utile pour regrouper des cas entiers :

sub classifier_digit
{
        switch ($_[0]) { case 0            { return 'zéro' }
                         case [2,4,6,8]    { return 'pair' }
                         case [1,3,5,7,9]  { return 'impair' }
                         case /[A-F]/i     { return 'hex' }
                       }
}

Autoriser la chute

La chute (tenter un autre cas après qu'un autre ait déjà réussi) est généralement une mauvaise idée dans un bloc de switch. Cependant, en Perl, ce n'est pas un état réprimandé, il existe donc un moyen de le faire si vous le souhaitez.

Si un bloc case exécute une instruction next sans argument, le contrôle passe immédiatement à l'instruction suivant le bloc case (c'est-à-dire, généralement une autre instruction de cas), au lieu de sortir du bloc switch englobant.

Exemple :

switch ($val) {
        case 1      { handle_num_1(); next }    # et tentez le cas suivant...
        case "1"     { handle_str_1(); next }    # et tentez le cas suivant...
        case [0..9] { handle_num_any(); }       # et nous avons terminé
        case /\d/   { handle_dig_any(); next }  # et tentez le cas suivant...
        case /.*/   { handle_str_any(); next }  # et tentez le cas suivant...
}

Si $val valait le nombre 1, le bloc switch devrait appeler les trois premières instructions handle_..., en passant à chaque test de cas lorsqu'il rencontre un next. Après l'exécution du troisième bloc case, le contrôle passerait à la fin du bloc switch englobant.

En revanche, si $val valait 10, seules les deux dernières instructions handle_... seraient appelées.

Remarque : Cette mécanique permet la notion de chute conditionnelle. Par exemple :

switch ($val)

NOM

Switch - une instruction switch/case plus flexible pour Perl

SYNTAXE

    use Switch;
    use Switch '-t';
    use Switch qw( $switch_op );
    use Switch qw( default );
    use Switch qw( fallthrough );
    use Switch qw( Perl6 );
    use Switch qw( __ );
    use Switch qw( default Perl6 );
    use Switch qw( default fallthrough );

    switch ( EXPR ) {
        case LIST    { STATEMENT(S) }
        case /REGEXP/ { STATEMENT(S) }
        case SUB     { STATEMENT(S) }
        case ( VAL ) { STATEMENT(S) }
        case ( VAL ) { STATEMENT(S) }
        ...
        default      { STATEMENT(S) }
    }

CONTEXTE

Dans la conception de Perl, les instructions if et else sont utilisées pour le contrôle de flux conditionnel. Cependant, pour une série de tests d'égalité sur une seule variable, une longue chaîne if/elsif peut devenir fastidieuse et inefficace. L'instruction switch de ce module offre une alternative plus lisible et souvent plus performante.

DESCRIPTION

Le module Switch fournit une construction switch/case plus flexible que ce qui était traditionnellement disponible en Perl. Il permet de tester une expression contre diverses listes, expressions régulières, sous-routines ou valeurs scalaires.

Permettre le passage

Par défaut, chaque bloc case se termine par un next implicite, qui passe le contrôle au cas suivant. Pour inhiber ce comportement et sortir complètement du bloc switch, un last doit être explicitement utilisé. Le comportement par défaut peut être inversé en important le module avec l'option '-t' (pour "fall-through").

    use Switch '-t';
    switch ($val) {
            case 1      { handle_num_1(); }
            case "1"    { handle_str_1(); }
            case [0..9] { handle_num_any(); last } # Le last est nécessaire ici
            case /\d/   { handle_dig_any(); }
            case /.*/   { handle_str_any(); }
    }

Dans cet exemple, le contrôle passe automatiquement au cas suivant à moins qu'un last ne soit rencontré.

Utilisation de last et next

Les mots-clés last et next peuvent être utilisés dans les blocs case pour contrôler le flux de sortie du bloc switch. last quitte complètement le bloc switch, tandis que next passe au bloc case suivant.

switch ($val) {
        case [0..9] { handle_num_any(); next if $val < 7; }
        case /\d/   { handle_dig_any(); }
}

Si une instruction last non ciblée est exécutée dans un bloc case, elle transfère immédiatement le contrôle hors du bloc switch englobant (en d'autres termes, il y a un last implicite à la fin de chaque bloc case normal). Ainsi, l'exemple précédent aurait également pu être écrit:

switch ($val) {
        case [0..9] { handle_num_any(); last if $val >= 7; next; }
        case /\d/   { handle_dig_any(); }
}

Automatiser le passage

Dans les situations où le passage des cas devrait être la norme, plutôt qu'une exception, une succession infinie de next terminaux est fastidieuse et laide. Par conséquent, il est possible d'inverser le comportement par défaut en spécifiant la chaîne "fallthrough" lors de l'importation du module. Par exemple, le code suivant est équivalent au premier exemple dans "Permettre le passage":

use Switch 'fallthrough';
switch ($val) {
        case 1      { handle_num_1(); }
        case "1"    { handle_str_1(); }
        case [0..9] { handle_num_any(); last }
        case /\d/   { handle_dig_any(); }
        case /.*/   { handle_str_any(); }
}

Notez l'utilisation explicite d'un last pour préserver le comportement sans passage du troisième cas.

Syntaxe alternative

Perl 6 fournira une instruction switch intégrée avec des sémantiques essentiellement identiques à celles offertes par Switch.pm, mais avec une paire de mots-clés différente. En Perl 6, switch sera orthographié given, et case sera prononcé when. De plus, l'instruction when ne nécessitera pas que les valeurs de switch ou de case soient entre parenthèses.

Cette syntaxe future est également (en grande partie) disponible via le module Switch.pm, en l'important avec l'argument Perl6. Par exemple:

use Switch 'Perl6';
given ($val) {
        when 1       { handle_num_1(); }
        when ($str1) { handle_str_1(); }
        when [0..9]  { handle_num_any(); last }
        when /\d/    { handle_dig_any(); }
        when /.*/    { handle_str_any(); }
        default      { handle anything else; }
}

Notez que les scalaires doivent toujours être mis entre parenthèses, car ils seraient ambigus en Perl 5.

Notez également que vous pouvez mélanger les deux syntaxes en important le module avec:

use Switch 'Perl5', 'Perl6';

Opérations d'ordre supérieur

Une situation où switch et case ne fournissent pas un bon substitut à un if en cascade est lorsqu'une valeur de switch doit être testée par rapport à une série de conditions. Par exemple:

sub beverage {
    switch (shift) {
        case { $_[0] < 10 } { return 'milk' }
        case { $_[0] < 20 } { return 'coke' }
        case { $_[0] < 30 } { return 'beer' }
        case { $_[0] < 40 } { return 'wine' }
        case { $_[0] < 50 } { return 'malt' }
        case { $_[0] < 60 } { return 'Moet' }
        else                { return 'milk' }
    }
}

(Ceci est équivalent à écrire case (sub { $_[0] < 10 }), etc. ; $_[0] est l'argument de la sous-routine anonyme.)

La nécessité de spécifier chaque condition comme un bloc de sous-routine est fastidieuse. Pour surmonter cela, lors de l'importation de Switch.pm, une sous-routine spéciale "placeholder" nommée __ [sic] peut également être importée. Cette sous-routine convertit (presque) toute expression dans laquelle elle apparaît en une référence à une fonction d'ordre supérieur. C'est-à-dire que l'expression:

use Switch '__';
__ < 2

est équivalente à:

sub { $_[0] < 2 }

Avec __, les déclarations case laides précédentes peuvent être réécrites:

case  __ < 10  { return 'milk' }
case  __ < 20  { return 'coke' }
case  __ < 30  { return 'beer' }
case  __ < 40  { return 'wine' }
case  __ < 50  { return 'malt' }
case  __ < 60  { return 'Moet' }
else           { return 'milk' }

La sous-routine __ utilise intensivement la surcharge d'opérateurs pour effectuer sa magie. Toutes les opérations impliquant __ sont surchargées pour produire une sous-routine anonyme qui implémente une version paresseuse de l'opération d'origine.

Le seul problème est que la surcharge d'opérateurs ne permet pas de surcharger les opérateurs booléens && et ||. Ainsi, une instruction case comme celle-ci:

case  0 <= __ && __ < 10  { return 'digit' }

n'agit pas comme prévu, car lorsqu'elle est exécutée, elle construit deux sous-routines d'ordre supérieur, puis traite les deux références résultantes comme des arguments pour &&:

sub { 0 <= $_[0] } && sub { $_[0] < 10 }

Cette expression booléenne est inévitablement vraie, car les deux références ne sont pas fausses. Heureusement, l'opérateur 'bool' surchargé attrape cette situation et la signale comme une erreur.

BOGUES

Il y a sans aucun doute des bogues sérieux qui se cachent quelque part dans un code aussi funky :-) Les rapports de bogues et autres commentaires sont les bienvenus.

Peut créer des erreurs de syntaxe dans d'autres parties du code.

Sur perl 5.10.x, peut causer une erreur de syntaxe si "case" est présent à l'intérieur d'un heredoc.

En général, utilisez plutôt given/when. Ils ont été introduits dans perl 5.10.0. Perl 5.10.0 a été publié en 2007.

LIMITATIONS

En raison de la nature heuristique de l'analyse de source de Switch.pm, la présence d'expressions régulières avec des sauts de ligne intégrés qui sont spécifiées avec des délimiteurs bruts /.../ et qui n'ont pas de modificateur //x sont indiscernables des blocs de code commençant par l'opérateur de division /. Comme solution de contournement, vous devez utiliser m/.../ ou m?...? pour de tels motifs. De plus, la présence d'expressions régulières spécifiées avec des délimiteurs bruts ?...? peut provoquer des erreurs mystérieuses. La solution de contournement est d'utiliser m?...? à la place.

En raison de la façon dont les filtres source fonctionnent dans Perl, vous ne pouvez pas utiliser Switch dans un eval de chaîne.

Peut ne pas fonctionner si des prototypes de sous-routines sont utilisés (RT#33988).

Les captures d'expressions régulières dans when ne sont pas disponibles pour le code.

Si votre fichier source est plus long qu'un million de caractères et que vous avez une instruction switch qui traverse la limite d'un million (ou deux millions, etc.) de caractères, vous obtiendrez des erreurs mystérieuses. La solution de contournement consiste à utiliser des fichiers source plus petits.
