DESCRIPTION

sd-id128.h fait partie de libsystemd(3) et fournit des API pour générer, convertir et comparer des valeurs d'identifiant de 128 bits. Les valeurs d'identifiant de 128 bits traitées et générées par ces API sont une généralisation des UUIDs définis dans la RFC 4122[1] mais utilisent un format de chaîne plus simple. Ces fonctions n'imposent aucune structure aux identifiants utilisés, mais sont tout à fait compatibles avec les UUIDs de l'OSF ou les GUIDs de Microsoft, tout en étant principalement compatibles avec eux.

Un identifiant de 128 bits est implémenté comme le type union suivant :

typedef union sd_id128 {
  uint8_t bytes[16];
  uint64_t qwords[2];
} sd_id128_t;

Ce type union permet d'accéder à l'identifiant de 128 bits comme 16 octets séparés ou comme deux mots de 64 bits. Il est généralement plus sûr d'accéder aux composants de l'identifiant via son tableau de 8 bits pour éviter les problèmes d'endianness. Ce type union est destiné à être passé par valeur (plutôt que par référence) et peut être manipulé directement par les clients.

Plusieurs macros sont définies pour dénoter et décoder les identifiants de 128 bits :

SD_ID128_MAKE() est utilisé pour écrire un ID constant dans le code source. Une pratique courante consiste à attribuer un nom à un ID en utilisant cette macro :

#define SD_MESSAGE_COREDUMP SD_ID128_MAKE(fc,2e,22,bc,6e,e6,47,b6,b9,07,29,ab,34,a2,50,b1)

SD_ID128_NULL définit un identifiant composé uniquement d'octets NUL (c'est-à-dire, tous les bits sont à 0).

SD_ID128_ALLF définit un identifiant composé uniquement d'octets 0xFF (c'est-à-dire, tous les bits sont à 1).

SD_ID128_MAKE_STR() est similaire à SD_ID128_MAKE(), mais crée une expression const char* qui peut être facilement utilisée dans les formats de messages :

#include <stdio.h>
#define SD_MESSAGE_COREDUMP_STR SD_ID128_MAKE_STR(fc,2e,22,bc,6e,e6,47,b6,b9,07,29,ab,34,a2,50,b1)
int main(int argc, char **argv) {
  puts("Match for coredumps: MESSAGE_ID=" SD_MESSAGE_COREDUMP_STR);
}

SD_ID128_CONST_STR() convertit des IDs constants en chaînes constantes pour la sortie. L'exemple de code suivant affichera la chaîne fc2e22bc6ee647b6b90729ab34a250b1 :

int main(int argc, char *argv[]) {
  puts("Match for coredumps: %s", SD_ID128_CONST_STR(SD_MESSAGE_COREDUMP));
}

SD_ID128_FORMAT_STR et SD_ID128_FORMAT_VAL() sont utilisés pour formater un ID dans un format printf(3) comme le montre l'exemple suivant :

int main(int argc, char *argv[]) {
  sd_id128_t id;
  id = SD_ID128_MAKE(ee,89,be,71,bd,6e,43,d6,91,e6,c5,5d,eb,03,02,07);
  printf("The ID encoded in this C file is " SD_ID128_FORMAT_STR ".\n", SD_ID128_FORMAT_VAL(id));
  return 0;
}

SD_ID128_UUID_FORMAT_STR et SD_ID128_MAKE_UUID_STR() sont similaires à SD_ID128_FORMAT_STR et SD_ID128_MAKE_STR(), mais incluent des tirets au milieu du format pour se conformer à la représentation canonique de l'UUID[2]. Le format est basé sur les règles de la RFC4122[1], c'est-à-dire la conversion en ordre de prédominance des octets Big Endian. Cela correspond au comportement de la plupart des infrastructures de l'espace utilisateur Linux. Il est probable qu'il soit préférable d'éviter les UUIDs d'autres variantes pour éviter une ambiguïté inutile. Tous les identifiants de 128 bits générés par les API sd-id128 suivent strictement les variantes 1 Version 4 des UUIDs conformément à la RFC 4122.

sd_id128_equal() compare deux identifiants de 128 bits :

int main(int argc, char *argv[]) {
  sd_id128_t a, b, c;
  a = SD_ID128_MAKE(ee,89,be,71,bd,6e,43,d6,91,e6,c5,5d,eb,03,02,07);
  b = SD_ID128_MAKE(f2,28,88,9c,5f,09,44,15,9d,d7,04,77,58,cb,e7,3e);
  c = a;
  assert(sd_id128_equal(a, c));
  assert(!sd_id128_equal(a, b));
  return 0;
}

sd_id128_string_equal() est similaire à sd_id128_equal(), mais le premier identifiant est formé comme const char*. Les mêmes restrictions s'appliquent qu'au premier argument de sd_id128_from_string().

sd_id128_is_null() vérifie si un identifiant ne contient que des octets NUL :

assert(sd_id128_is_null(SD_ID128_NULL));

De même, sd_id128_is_allf() vérifie si un identifiant ne contient que des octets 0xFF (tous les bits sont à 1) :

assert(sd_id128_is_allf(SD_ID128_ALLF));

sd_id128_in_set_sentinel() prend une liste d'identifiants et renvoie vrai si le premier argument est égal à l'un des arguments suivants. La liste d'arguments est terminée par un SD_ID1

Le code décrit ici utilise getenv(3), qui n'est pas déclaré comme étant thread-safe. Cela signifie que le code appelant les fonctions décrites ici ne doit pas appeler setenv(3) à partir d'un thread parallèle. Il est recommandé de n'appeler setenv() qu'à une phase précoce du programme, lorsque aucun autre thread n'a été démarré.
