SD_EVENT_PRIORITY_NORMAL(3) sd_event_source_set_priority SD_EVENT_PRIORITY_NORMAL(3)

NOM

sd_event_source_set_priority, sd_event_source_get_priority, SD_EVENT_PRIORITY_IMPORTANT, SD_EVENT_PRIORITY_NORMAL, SD_EVENT_PRIORITY_IDLE - Définir ou récupérer la priorité des sources d'événements

SYNTAXE

#include <systemd/sd-event.h>
enum {
        SD_EVENT_PRIORITY_IMPORTANT = -100,
        SD_EVENT_PRIORITY_NORMAL = 0,
        SD_EVENT_PRIORITY_IDLE = 100,
};

int sd_event_source_set_priority(sd_event_source *source, int64_t priorité);

int sd_event_source_get_priority(sd_event_source *source, int64_t *priorité);

DESCRIPTION

sd_event_source_set_priority() peut être utilisée pour définir la priorité de l'objet source d'événements spécifié par source. La priorité est spécifiée comme un entier signé de 64 bits arbitraire. La priorité est initialisée à SD_EVENT_PRIORITY_NORMAL (0) lorsque la source d'événements est allouée avec un appel tel que sd_event_add_io(3) ou sd_event_add_time(3), et peut être modifiée avec cet appel. Si plusieurs sources d'événements ont reçu des événements en même temps, elles sont traitées dans l'ordre indiqué par les priorités des sources d'événements. Les sources d'événements avec des valeurs de priorité plus basses sont traitées en premier. Comme points de référence bien connus, les constantes SD_EVENT_PRIORITY_IMPORTANT (-100), SD_EVENT_PRIORITY_NORMAL (0) et SD_EVENT_PRIORITY_IDLE (100) peuvent être utilisées pour indiquer des sources d'événements qui doivent être traitées tôt, normalement ou tard. Il est recommandé de spécifier les priorités en se basant sur ces définitions, et par rapport à elles — cependant, toute la plage des entiers signés de 64 bits est disponible pour ordonner les sources d'événements.

Les priorités définissent l'ordre dans lequel les sources d'événements qui ont reçu des événements sont traitées. Il faut veiller à ce que les sources d'événements à haute priorité (celles avec des valeurs de priorité négatives attribuées) ne provoquent pas la famine des sources d'événements à basse priorité (celles avec des valeurs de priorité positives attribuées).

L'ordre dans lequel les sources d'événements de même priorité sont traitées est indéfini, mais la boucle d'événements essaie généralement de les traiter dans l'ordre où elle a appris l'existence d'événements sur celles-ci. Comme les primitives du noyau sous-jacentes ne fournissent pas d'informations précises sur l'ordre dans lequel les événements se sont produits, cela n'est pas nécessairement fiable. Cependant, il est garanti que si des événements sont détectés sur plusieurs sources d'événements de même priorité en même temps, chacune d'elles n'est pas traitée à nouveau tant que toutes les autres n'ont pas été traitées une fois. Ce comportement garantit que, au sein de chaque priorité, des sources d'événements particulières ne provoquent pas de famine ou ne dominent pas la boucle d'événements.

La priorité des sources d'événements peut être modifiée à tout moment de leur durée de vie, à l'exception des sources d'événements inotify (c'est-à-dire celles créées avec sd_event_add_inotify(3)) dont la priorité ne peut être modifiée qu'entre leur création initiale et la première itération suivante de la boucle d'événements.

sd_event_source_get_priority() peut être utilisée pour interroger la priorité actuelle attribuée à l'objet source d'événements source.

VALEUR DE RETOUR

En cas de succès, sd_event_source_set_priority() et sd_event_source_get_priority() renvoient un entier positif. En cas d'échec, elles renvoient un code d'erreur négatif de style errno.

Erreurs

Les erreurs renvoyées peuvent indiquer les problèmes suivants :

-EINVAL

source n'est pas un pointeur valide vers un objet sd_event_source.

-ENOMEM

Pas assez de mémoire.

-ESTALE

La boucle d'événements est déjà terminée.

-ECHILD

La boucle d'événements a été créée dans un autre processus, bibliothèque ou instance de module.

NOTES

Les fonctions décrites ici sont disponibles en tant que bibliothèque partagée, qui peut être compilée et liée avec le fichier libsystemd pkg-config(1).

Le code décrit ici utilise getenv(3), qui est déclaré comme n'étant pas thread-safe. Cela signifie que le code appelant les fonctions décrites ici ne doit pas appeler setenv(3) depuis un thread parallèle. Il est recommandé de ne faire des appels à setenv() que dans une phase précoce du programme, lorsqu'aucun autre thread n'a été démarré.

HISTORIQUE

sd_event_source_set_priority() et sd_event_source_get_priority() ont été ajoutées dans la version 229.
