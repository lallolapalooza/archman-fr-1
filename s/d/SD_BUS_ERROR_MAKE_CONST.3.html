DESCRIPTION

La structure sd_bus_error transporte des informations sur une condition d'erreur D-Bus, ou son absence. Les fonctions décrites ci-dessous peuvent être utilisées pour définir et interroger les champs de cette structure.

•Le champ name contient un identifiant court d'erreur. Il doit suivre les règles de nommage des erreurs décrites dans la spécification D-Bus, section Valid D-Bus Names[1]. Certains noms d'erreurs courants et standardisés sont décrits dans sd-bus-errors(3), mais des erreurs spécifiques au domaine peuvent être définies par les applications.
•Le champ message contient généralement une chaîne de caractères lisible par l'homme décrivant les détails, mais peut être NULL.

Une structure sd_bus_error non définie devrait avoir ses deux champs initialisés à NULL et signifier l'absence d'erreur, c'est-à-dire le succès. Affecter SD_BUS_ERROR_NULL à la structure pour initialiser les deux champs à NULL. Lorsqu'elle n'est plus nécessaire, les ressources gérées par la structure sd_bus_error doivent être libérées avec sd_bus_error_free().

sd_bus_error_set() définit une structure d'erreur aux chaînes spécifiées dans name et message. Les chaînes sont copiées dans une nouvelle mémoire allouée en interne. Il est essentiel de libérer le contenu plus tard lorsque vous n'en avez plus besoin (voir ci-dessus). Vous ne devez pas utiliser cet appel sur des structures d'erreur déjà définies. Si vous souhaitez réutiliser une structure d'erreur, libérez d'abord les anciennes données avec sd_bus_error_free().

sd_bus_error_set() renvoie une valeur similaire à errno (voir errno(3)) déterminée à partir du nom d'erreur spécifié name. Si name est NULL, aucune erreur n'est supposée s'être produite et 0 est renvoyé. Si name n'est pas NULL, il renvoie toujours une valeur négative. Si e est NULL, aucune structure d'erreur n'est initialisée, mais name est converti en une valeur de style errno.

Les erreurs D-Bus bien connues sont converties en errno bien connus correspondants, et les autres en -EIO. Voir sd-bus-errors(3) pour une liste des noms d'erreurs bien connues. Des mappages supplémentaires peuvent être définis avec sd_bus_error_add_map(3).

sd_bus_error_set() est conçu pour être utilisé commodément dans une déclaration return. Si message est NULL, aucun message n'est défini. Cet appel peut échouer s'il n'y a pas assez de mémoire pour stocker les chaînes name et message, auquel cas une erreur SD_BUS_ERROR_NO_MEMORY sera définie et -ENOMEM sera renvoyé.

sd_bus_error_setf() et sd_bus_error_setfv() sont similaires à sd_bus_error_set(), mais utilisent un format printf(3) pour générer le champ message. sd_bus_error_setf() utilise des arguments variadiques, et sd_bus_error_setfv() accepte les arguments sous forme de liste de paramètres va_arg(3).

sd_bus_error_set_const() est similaire à sd_bus_error_set(), mais les paramètres de chaîne ne sont pas copiés en interne et doivent rester constants et valides pendant toute la durée de vie de e. Utilisez cet appel pour éviter les allocations mémoire lors de la définition des structures d'erreur. Comme cet appel n'alloue pas de mémoire, il n'échouera pas avec une erreur de mémoire, comme sd_bus_error_set() peut le faire, comme décrit ci-dessus. Alternativement, la macro SD_BUS_ERROR_MAKE_CONST() peut être utilisée pour générer une structure d'erreur littérale et constante au moment de la compilation.

sd_bus_error_set_errno() renvoie immédiatement 0 si le paramètre error est 0. Sinon, il définit name à une valeur de style errno convertie en une structure d'erreur D-Bus. Il utilise strerror_r(3) pour définir message. Si name est applicable, un nom d'erreur de type D-Bus sera utilisé, sinon un nom est généré dans l'espace de noms System.Error. Le signe du numéro d'erreur donné est ignoré et la valeur absolue est utilisée implicitement. Si le numéro d'erreur donné error est non nul, l'appel renvoie toujours une valeur négative, pour une utilisation pratique dans les déclarations return. Cet appel peut échouer en raison d'un manque de mémoire, auquel cas une erreur SD_BUS_ERROR_NO_MEMORY sera définie et -ENOMEM sera renvoyé.

sd_bus_error_set_errnof() et sd_bus_error_set_errnof() sont similaires à sd_bus_error_set_errno(), mais en plus de error, ils prennent un format printf(3) et des arguments correspondants. Le champ message est généré à partir de format et des arguments. sd_bus_error_set_errnof() utilise des arguments variadiques, et sd_bus_error_set_errnofv() accepte les arguments sous forme de liste de paramètres va_arg(3).

sd_bus_error_get_errno() convertit le champ name d'une structure d'erreur en une valeur de style errno (positive) en utilisant les mêmes règles que sd_bus_error_set(). Si e est NULL, 0 est renvoyé.

sd_bus_error_copy() initialise dst en utilisant les valeurs de e, si e a été défini avec une valeur d'erreur auparavant. Sinon, il renvoie immédiatement. Si les chaînes dans e ont été définies en utilisant sd_bus_error_set_const(), elles seront partagées. Sinon, elles seront copiées. Avant cet appel, dst doit être déconnecté, c'est-à-dire initialisé à NULL ou réinitialisé avec sd_bus_error_free().

sd_bus_error_copy() renvoie généralement 0 ou une valeur négative de style errno basée sur le paramètre d'entrée e : 0 s'il n'était pas défini et une valeur négative s'il était défini avec une erreur, de manière similaire à sd_bus_error_set(). Il peut renvoyer une erreur générée en interne,

DESCRIPTION

Les structures sd_bus_error sont utilisées pour décrire les erreurs qui se produisent lors de l'interaction avec D-Bus.

La fonction sd_bus_error_make_const() initialise la structure d'erreur e avec le nom d'erreur name et le message d'erreur message. Ces pointeurs doivent rester valides tant que la structure d'erreur est utilisée. Aucun argument de formatage n'est pris en charge par cette fonction. Si la structure e contenait déjà une erreur, elle est d'abord libérée.

La fonction sd_bus_error_copy() copie une structure d'erreur src dans une structure dst. Si src ne contient aucune erreur, dst est initialisée à SD_BUS_ERROR_NULL. Si dst est NULL, aucune opération n'est effectuée. La fonction peut échouer avec des erreurs d'allocation mémoire, typiquement -ENOMEM, si l'allocation mémoire pour la nouvelle chaîne échoue.

La fonction sd_bus_error_move() est similaire à sd_bus_error_copy(), mais elle déplace toute information d'erreur de e vers dst, en réinitialisant la première. Cette fonction ne peut pas échouer, car aucune nouvelle mémoire n'est allouée. Notez que si e n'est pas défini, dst est initialisée à SD_BUS_ERROR_NULL. De plus, si dst est NULL, aucune opération n'est exécutée sur elle et les ressources détenues par e sont libérées et réinitialisées. Renvoie une valeur d'erreur positive de type errno convertie.

La fonction sd_bus_error_is_set() renvoie une valeur non nulle si e n'est pas NULL et qu'une erreur a été définie, false sinon.

La fonction sd_bus_error_has_name() renvoie une valeur non nulle si e n'est pas NULL et qu'une erreur du même name a été définie, false sinon.

La fonction sd_bus_error_has_names_sentinel() est similaire à sd_bus_error_has_name(), mais elle prend plusieurs noms à vérifier. La liste doit être terminée par NULL. sd_bus_error_has_names() est une macro enveloppe autour de sd_bus_error_has_names_sentinel() qui ajoute automatiquement le sentinelle NULL.

La fonction sd_bus_error_free() détruit les ressources détenues par e. Le paramètre lui-même ne sera pas désalloué et doit être free(3) par l'appelant si nécessaire. La fonction peut également être appelée sans risque sur des erreurs non définies (structures d'erreur avec les deux champs définis sur NULL), auquel cas elle n'effectue aucune opération. Cet appel réinitialisera la structure d'erreur après la libération des données, de sorte que tous les champs soient définis sur NULL. La structure peut être réutilisée par la suite.

REFERENCE OWNERSHIP

sd_bus_error n'est pas comptée par référence. Les utilisateurs doivent détruire les ressources qu'elle détient en appelant sd_bus_error_free(). Habituellement, les structures d'erreur sont allouées sur la pile ou passées en tant que paramètres de fonction, mais elles peuvent également être allouées dynamiquement, auquel cas il incombe à l'appelant de free(3) la mémoire détenue par la structure elle-même après avoir libéré son contenu avec sd_bus_error_free().

RETURN VALUE

Les fonctions sd_bus_error_set(), sd_bus_error_setf() et sd_bus_error_set_const() renvoient toujours 0 lorsque la valeur d'erreur spécifiée est NULL, et une valeur négative de type errno correspondant au paramètre name sinon. Les fonctions sd_bus_error_set_errno(), sd_bus_error_set_errnof() et sd_bus_error_set_errnofv() renvoient 0 lorsque la valeur d'erreur spécifiée est 0, et une valeur négative de type errno correspondant au paramètre error sinon. Si une erreur survient en interne, l'une des valeurs d'erreur négatives listées ci-dessous sera renvoyée. Cela permet d'utiliser ces fonctions de manière pratique dans une instruction return, voir l'exemple ci-dessous.

sd_bus_error_get_errno() renvoie false lorsque e est NULL, et une valeur positive de errno mappée à partir de e->name sinon.

sd_bus_error_copy() et sd_bus_error_move() renvoient une valeur d'erreur négative convertie à partir de l'erreur source, et zéro si l'erreur n'a pas été définie. Cela permet d'utiliser ces fonctions de manière pratique dans une instruction return, voir l'exemple ci-dessous.

sd_bus_error_is_set() renvoie une valeur non nulle lorsque e et le champ name ne sont pas NULL, zéro sinon.

sd_bus_error_has_name(), sd_bus_error_has_names() et sd_bus_error_has_names_sentinel() renvoient une valeur non nulle lorsque e n'est pas NULL et que le champ name est égal à l'un des noms donnés, zéro sinon.

Erreurs

La valeur de retour peut indiquer les problèmes suivants lors de l'invocation de la fonction elle-même :

-EINVAL

L'erreur était déjà définie dans la structure sd_bus_error lors de l'appel de l'une des fonctions de définition d'erreur.

-ENOMEM

Échec de l'allocation mémoire.

En cas de succès, sd_bus_error_set(), sd_bus_error_setf(), sd_bus_error_set_const(), sd_bus_error_set_errno(), sd_bus_error_set_errnof(), sd_bus_error_set_errnofv(), sd_bus_error_copy() et sd_bus_error_move() renverront une valeur négative convertie de style errno, ou 0 si le paramètre d'erreur est NULL ou non défini. Les erreurs D-Bus sont converties en une valeur entière de style errno, et le mécanisme de mappage est extensible, voir la discussion ci-dessus. Cela signifie effectivement que presque toute valeur négative de style errno peut être renvoyée.

EXEMPLES

Exemple 1. Utilisation de la valeur de retour négative pour propager une erreur

/* SPDX-License-Identifier: MIT-0 */
#include <errno.h>
#include <string.h>
#include <unistd.h>
#include <systemd/sd-bus.h>
int writer_with_negative_errno_return(int fd, sd_bus_error *error) {
  const char *message = "Hello, World!\n";
  ssize_t n = write(fd, message, strlen(message));
  if (n >= 0)
    return n; /* En cas de succès, renvoyer le nombre d'octets écrits, éventuellement 0. */
  /* En cas d'erreur, initialiser la structure d'erreur, et également propager la valeur errno que write(2) a définie pour nous. */
  return sd_bus_error_set_errnof(error, errno, "Failed to write to fd %i: %s", fd, strerror(errno));
}

NOTES

Les fonctions décrites ici sont disponibles sous forme de bibliothèque partagée, qui peut être compilée et liée avec le fichier pkg-config(1) de libsystemd.

Le code décrit ici utilise getenv(3), qui est déclaré comme n'étant pas thread-safe. Cela signifie que le code appelant les fonctions décrites ici ne doit pas appeler setenv(3) à partir d'un thread parallèle. Il est recommandé de n'effectuer des appels à setenv() qu'à une phase précoce du programme, lorsqu'aucun autre thread n'a été démarré.
