NOM

SDBM_File - Accès lié aux fichiers sdbm

SYNOPSIS

use Fcntl;   # Pour O_RDWR, O_CREAT, etc.
use SDBM_File;
tie(%h, 'SDBM_File', 'nom_fichier', O_RDWR|O_CREAT, 0666)
  or die "Impossible de lier le fichier SDBM 'nom_fichier' : $!; abandon";
# Maintenant lire et modifier le hash
$h{nouvelle_cle} = nouvelle_valeur;
print $h{ancienne_cle}; 
...
untie %h;

DESCRIPTION

"SDBM_File" établit une connexion entre une variable de hachage Perl et un fichier au format SDBM_File. Vous pouvez manipuler les données dans le fichier comme s'il s'agissait d'un hachage Perl, mais lorsque votre programme se termine, les données resteront dans le fichier, pour être utilisées la prochaine fois que votre programme s'exécutera.

Liaison

Utilisez "SDBM_File" avec la fonction intégrée Perl "tie" pour établir la connexion entre la variable et le fichier.

tie %hash, 'SDBM_File', $basename, $modeflags, $perms;
tie %hash, 'SDBM_File', $dirfile,  $modeflags, $perms, $pagfilename;

$basename est le nom de fichier de base pour la base de données. La base de données est constituée de deux fichiers avec les extensions ".dir" et ".pag" ajoutées à $basename,

$basename.dir     (ou .sdbm_dir sur VMS, selon la constante DIRFEXT)
$basename.pag

Les deux noms de fichiers peuvent également être donnés séparément en entier comme $dirfile et $pagfilename. Ceci convient pour deux fichiers sans les extensions ".dir" et ".pag", peut-être par exemple deux fichiers de File::Temp.

$modeflags peut être les constantes suivantes du module "Fcntl" (dans le style de l'appel système open(2)),

O_RDONLY          accès en lecture seule
O_WRONLY          accès en écriture seule
O_RDWR            accès en lecture et écriture

Si vous souhaitez créer le fichier s'il n'existe pas, ajoutez un OU bit à bit ("|") "O_CREAT". Si vous omettez "O_CREAT" et que la base de données n'existe pas, l'appel "tie" échouera.

O_CREAT           crée la base de données si elle n'existe pas déjà

$perms sont les bits de permissions de fichier à utiliser si de nouveaux fichiers de base de données sont créés. Ce paramètre est obligatoire même lorsqu'on ne crée pas une nouvelle base de données. Les permissions seront réduites par l'umask de l'utilisateur, donc la valeur habituelle ici serait 0666, ou si des données très privées alors 0600. (Voir "umask" dans perlfunc.)

EXPORTATIONS

SDBM_File exporte optionnellement les constantes suivantes :

  • "PAGFEXT" - l'extension utilisée pour le fichier de pages, généralement ".pag".
  • "DIRFEXT" - l'extension utilisée pour le fichier de répertoire, ".dir" partout sauf sur VMS, où c'est ".sdbm_dir".
  • "PAIRMAX" - la taille maximale d'une entrée de hachage stockée, incluant la longueur de la clé et de la valeur.

Ces constantes peuvent également être utilisées avec des noms entièrement qualifiés, par exemple "SDBM_File::PAGFEXT".

DIAGNOSTICS

En cas d'échec, l'appel "tie" renvoie une valeur indéfinie et définit probablement $! pour contenir la raison pour laquelle le fichier n'a pas pu être lié.

"sdbm store returned -1, errno 22, key "..." at ..."

Cet avertissement est émis lorsque vous essayez de stocker une clé ou une valeur trop longue. Cela signifie que la modification n'a pas été enregistrée dans la base de données. Voir BUGS ET AVERTISSEMENTS ci-dessous.

AVERTISSEMENT DE SÉCURITÉ

N'acceptez pas de fichiers SDBM provenant de sources non fiables !

Le format de fichier sdbm a été conçu pour la vitesse et la commodité, pas pour la portabilité ou la sécurité. Un fichier créé de manière malveillante pourrait faire planter perl, voire exposer une vulnérabilité de sécurité.

BUGS ET AVERTISSEMENTS

Il existe un certain nombre de limites à la taille des données que vous pouvez stocker dans le fichier SDBM. La plus importante est que la longueur d'une clé, plus la longueur de sa valeur associée, ne peut pas dépasser 1008 octets.

Voir "tie" dans perlfunc, perldbmfilter, Fcntl
