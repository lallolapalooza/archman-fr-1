SD_BUS_MESSAGE_SIGNAL(3) sd_bus_message_signal SD_BUS_MESSAGE_SIGNAL(3)

NAME

sd_bus_message_signal, sd_bus_message_signal_ref, sd_bus_message_signal_unref, sd_bus_message_signal_unrefp, SD_BUS_MESSAGE_SIGNAL, sd_bus_message_get_bus - Créer un objet de message de bus et gérer ses références

SYNOPSIS

#include <systemd/sd-bus.h>
enum {
      SD_BUS_MESSAGE_SIGNAL,
};

int sd_bus_message_signal(sd_bus *bus, sd_bus_message **m, uint8_t type);

sd_bus_message_signal_ref(sd_bus_message *m);

sd_bus_message_signal_unref(sd_bus_message *m);

void sd_bus_message_signal_unrefp(sd_bus_message **mp);

sd_bus *sd_bus_message_get_bus(sd_bus_message *m);

DESCRIPTION

sd_bus_message_signal() crée un objet de message de bus attaché au bus bus et le renvoie dans le paramètre de sortie m. Cet objet est compté par référence, et sera détruit lorsque toutes les références seront libérées. Initialement, l'appelant de cette fonction détient la seule référence à l'objet message. Notez que l'objet message détient une référence à l'objet bus, donc l'objet bus ne sera pas détruit tant que le message existe.

Note : ceci est un appel de bas niveau. Dans la plupart des cas, des fonctions telles que sd_bus_message_signal_method_call(3), sd_bus_message_signal_method_error(3), sd_bus_message_signal_method_return(3), et sd_bus_message_signal_signal(3) qui créent un message d'un certain type et initialisent divers champs sont plus faciles à utiliser.

Le paramètre type spécifie le type du message. Il doit être l'un des suivants : SD_BUS_MESSAGE_SIGNAL — un message de type signal.

Le drapeau pour l'autorisation interactive est initialisé en fonction de la valeur actuelle dans l'objet bus, voir sd_bus_set_allow_interactive_authorization(3). Ceci peut être changé en utilisant sd_bus_message_set_allow_interactive_authorization(3).

sd_bus_message_signal_ref() incrémente le compteur de référence interne de m de un.

sd_bus_message_signal_unref() décrémente le compteur de référence interne de m de un. Une fois que le compteur est tombé à zéro, l'objet message est détruit et ne peut plus être utilisé, donc les appels à sd_bus_message_signal_ref() ou sd_bus_message_signal_unref() sont illégaux.

sd_bus_message_signal_unrefp() est similaire à sd_bus_message_signal_unref(), mais prend un pointeur vers un pointeur vers un objet sd_bus_message. Cet appel est utile conjointement avec l'attribut de variable de nettoyage [1]. Voir sd_bus_new(3) pour un exemple d'utilisation de l'attribut de variable de nettoyage.

sd_bus_message_signal_ref() et sd_bus_message_signal_unref() n'effectuent aucune opération si l'objet message m passé est NULL. sd_bus_message_signal_unrefp() déréférence d'abord son argument, qui ne doit pas être NULL, et n'effectue aucune opération si celui-ci est NULL.

sd_bus_message_get_bus() renvoie l'objet bus auquel le message m est attaché.

RETURN VALUE

En cas de succès, sd_bus_message_signal() renvoie 0 ou une valeur positive. En cas d'échec, il renvoie un code d'erreur négatif.

sd_bus_message_signal_ref() renvoie toujours l'argument.

sd_bus_message_signal_unref() renvoie toujours NULL.

sd_bus_message_get_bus() renvoie toujours l'objet bus.

Erreurs

Les erreurs renvoyées peuvent indiquer les problèmes suivants :

-EINVAL

Le type spécifié est invalide.

-ENOTCONN

Le paramètre bus est NULL ou le bus n'est pas connecté.

-ENOMEM

Échec de l'allocation de mémoire.

NOTES

Les fonctions décrites ici sont disponibles sous forme de bibliothèque partagée, qui peut être compilée et liée avec libsystemd [1].

Le code décrit ici utilise getenv(3), qui est déclaré comme non thread-safe. Cela signifie que le code appelant ces fonctions ne doit pas appeler setenv(3) à partir d'un thread parallèle. Il est recommandé de n'appeler setenv() qu'au début du programme, lorsqu'aucun autre thread n'a encore été lancé.

HISTORY

sd_bus_message_signal(), sd_bus_message_signal_ref(), sd_bus_message_signal_unref(), sd_bus_message_signal_unrefp(), et sd_bus_message_get_bus() ont été ajoutés dans la version 240.
