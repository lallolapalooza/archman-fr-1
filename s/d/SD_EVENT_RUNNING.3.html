SD_EVENT_WAIT(3) sd_event_wait SD_EVENT_WAIT(3)

NOM

sd_event_wait, sd_event_prepare, sd_event_dispatch, sd_event_get_state, sd_event_get_iteration, SD_EVENT_INITIAL, SD_EVENT_PREPARING, SD_EVENT_ARMED, SD_EVENT_PENDING, SD_EVENT_RUNNING, SD_EVENT_EXITING, SD_EVENT_FINISHED - Opérations de bas niveau de la boucle d'événements

SYNOPIS

#include <systemd/sd-event.h>
enum {
        SD_EVENT_INITIAL,
        SD_EVENT_PREPARING,
        SD_EVENT_ARMED,
        SD_EVENT_PENDING,
        SD_EVENT_RUNNING,
        SD_EVENT_EXITING,
        SD_EVENT_FINISHED,
};

int sd_event_prepare(sd_event *event);

int sd_event_wait(sd_event *event, uint64_t usec);

int sd_event_dispatch(sd_event *event);

int sd_event_get_state(sd_event *event);

int sd_event_get_iteration(sd_event *event, uint64_t *ret);

DESCRIPTION

Les fonctions de bas niveau sd_event_prepare(), sd_event_wait() et sd_event_dispatch() peuvent être utilisées pour exécuter des phases spécifiques d'une boucle d'événements. Voir sd_event_run(3) et sd_event_loop(3) pour des fonctions de plus haut niveau qui exécutent des itérations individuelles mais complètes d'une boucle d'événements ou qui l'exécutent en continu.

sd_event_prepare() vérifie les événements en attente et arme les minuteurs nécessaires. Si des événements sont prêts à être traités ("en attente"), elle renvoie une valeur positive non nulle, et l'appelant doit traiter ces événements avec sd_event_dispatch().

sd_event_dispatch() distribue la source d'événements de plus haute priorité qui a un événement en attente. En cas de succès, sd_event_dispatch() renvoie soit zéro, ce qui indique qu'aucune autre source d'événements ne peut être distribuée et que la sortie de la boucle d'événements a été demandée via sd_event_exit(3) ; soit une valeur positive non nulle, ce qui signifie qu'une source d'événements a été distribuée et que la boucle est revenue à son état initial, et que l'appelant doit initier la prochaine itération de la boucle d'événements en invoquant à nouveau sd_event_prepare().

Dans le cas où sd_event_prepare() a renvoyé zéro, sd_event_wait() doit être appelée pour attendre d'autres événements ou un délai d'attente. Si des événements sont prêts à être traités, elle renvoie une valeur positive non nulle, et les événements doivent être distribués avec sd_event_dispatch(). Sinon, la boucle d'événements est revenue à son état initial et la prochaine itération de la boucle d'événements doit être initiée en invoquant à nouveau sd_event_prepare().

sd_event_get_state() peut être utilisée pour déterminer l'état dans lequel se trouve actuellement la boucle d'événements. Elle renvoie l'un des états décrits ci-dessous.

sd_event_get_iteration() peut être utilisée pour déterminer l'itération actuelle de la boucle d'événements. Elle renvoie un entier non signé de 64 bits contenant un compteur qui augmente monotonically à chaque itération de la boucle d'événements, en commençant par 0. Le compteur est incrémenté au moment de l'invocation de sd_event_prepare().

Les cinq fonctions prennent, comme premier argument, l'objet de boucle d'événements event qui a été créé avec sd_event_new(). Le délai d'attente pour sd_event_wait() est spécifié en usec en microsecondes. (uint64_t) -1 peut être utilisé pour spécifier un délai d'attente infini.

MACHINE D'ÉTAT

La boucle d'événements connaît les états suivants, qui peuvent être interrogés avec sd_event_get_state().

SD_EVENT_INITIAL

L'état initial de la boucle d'événements, avant chaque itération de la boucle d'événements. Utilisez sd_event_prepare() pour faire passer la boucle d'événements aux états SD_EVENT_ARMED ou SD_EVENT_PENDING.

Ajouté dans la version 229.

SD_EVENT_PREPARING

Une source d'événements est en cours de préparation, c'est-à-dire que le gestionnaire de préparation est actuellement exécuté, tel que défini avec sd_event_source_set_prepare(3). Cet état n'est vu que dans le gestionnaire de préparation d'événements qui est invoqué à partir de l'appel sd_event_prepare() et est immédiatement suivi par SD_EVENT_ARMED ou SD_EVENT_PENDING.

Ajouté dans la version 229.

SD_EVENT_ARMED

sd_event_prepare() a été appelée et aucune source d'événements n'était prête à être distribuée. Utilisez sd_event_wait() pour attendre de nouveaux événements et passer à SD_EVENT_PENDING ou revenir à SD_EVENT_INITIAL.

Ajouté dans la version 229.

SD_EVENT_PENDING

sd_event_prepare() ou sd_event_wait() ont été appelées et il y avait des sources d'événements avec des événements en attente. Utilisez sd_event_dispatch() pour distribuer la source d'événements de plus haute priorité et revenir à SD_EVENT_INITIAL, ou à SD_EVENT_FINISHED.

Ajouté dans la version 229.

SD_EVENT_RUNNING

Une source d'événements régulière est en cours de distribution. Cet état n'est vu que dans le gestionnaire de la source d'événements qui est invoqué à partir de l'appel sd_event_dispatch(), et est immédiatement suivi par SD_EVENT_INITIAL ou SD_EVENT_FINISHED dès que le gestionnaire de la source d'événements revient. Notez que lors de la distribution des sources d'événements de sortie, l'état SD_EVENT_EXITING est vu à la place.

Ajouté dans la version 229.

SD_EVENT_EXITING

Similaire à SD_EVENT_RUNNING mais est l'état en vigueur lors de la distribution des sources d'événements de sortie. Il est suivi par SD_EVENT_INITIAL ou SD_EVENT_FINISHED dès que le gestionnaire d'événements revient.

Ajouté dans la version 229.

SD_EVENT_FINISHED

La boucle d'événements est terminée. Toutes les sources d'événements de sortie ont été exécutées. Si la boucle d'événements est dans cet état, elle n'a plus aucune utilité et devrait être libérée.

Ajouté dans la version 229.

VALEUR RETOUR

En cas de succès, ces fonctions renvoient 0 ou un entier positif. En cas d'échec, elles renvoient un code d'erreur négatif de style errno. Dans le cas de sd_event_prepare() et sd_event_wait(), un code de retour positif non nul indique que des événements sont prêts à être traités et zéro indique qu'aucun événement n'est prêt. Dans le cas de sd_event_dispatch(), un code de retour positif non nul indique que la boucle d'événements est revenue à son état initial et zéro indique que la boucle d'événements s'est terminée. sd_event_get_state() renvoie un état positif ou zéro en cas de succès.

Erreurs

Les erreurs retournées peuvent indiquer les problèmes suivants :

-EINVAL

Le paramètre event est invalide ou **NULL**.

-EBUSY

L'objet de la boucle d'événements n'est pas dans le bon état.

-ESTALE

La boucle d'événements est déjà terminée.

sd_event_running(3) — systemd — Arch Linux

NAME

sd_event_running, sd_event_get_state, sd_event_get_iteration, sd_event_prepare, sd_event_wait, sd_event_dispatch, sd_event_get_fd, sd_event_set_exit_code, sd_event_exit, sd_event_loop — Event loop API

SYNOPSIS

#include <systemd/sd-event.h>

int sd_event_run(sd_event *event, uint64_t usec);

int sd_event_get_state(sd_event *event);

uint64_t sd_event_get_iteration(sd_event *event);

int sd_event_prepare(sd_event *event);

int sd_event_wait(sd_event *event, uint64_t usec);

int sd_event_dispatch(sd_event *event);

int sd_event_get_fd(sd_event *event);

int sd_event_set_exit_code(sd_event *event, int exit_code);

int sd_event_exit(sd_event *event, int exit_code);

int sd_event_loop(sd_event *event);

DESCRIPTION

The sd_event(3) object provides an event loop implementation. The event loop is the central piece of asynchronous programming. It waits for events to occur, and dispatches them to the appropriate handlers.

sd_event_run() runs the event loop for at most usec microseconds. If usec is 0, it will run indefinitely until the loop is terminated.

sd_event_get_state() returns the current state of the event loop. Possible return values are:

sd_event_get_iteration() returns the number of times the event loop has gone through its main loop.

sd_event_prepare(), sd_event_wait(), and sd_event_dispatch() represent the three main phases of the event loop's operation:

sd_event_prepare(): This function is called once per iteration of the event loop. It is used to update the internal state of the event loop and to prepare for waiting for events. For example, it might set up new timers or update the set of file descriptors to monitor.

sd_event_wait(): This function blocks until one or more events occur or until the timeout specified by usec expires. The timeout is determined by the latest timer in the event loop.

sd_event_dispatch(): This function is called after sd_event_wait() returns. It dispatches the events that have occurred to their respective handlers. This may involve calling I/O event handlers, timer event handlers, or child process exit handlers.

sd_event_get_fd() returns the main file descriptor of the event loop. This file descriptor is used to signal the event loop from other threads or processes. It is useful for implementing inter-process communication or for waking up the event loop when an asynchronous operation completes.

sd_event_set_exit_code() sets the exit code that will be used by sd_event_loop() if the loop is terminated prematurely.

sd_event_exit() requests the event loop to terminate. The exit_code parameter is the exit code that will be returned by sd_event_loop().

sd_event_loop() runs the event loop until it is explicitly terminated by sd_event_exit(). It then returns the exit code specified by sd_event_set_exit_code() or passed to sd_event_exit().

STATE MACHINE

The event loop manages a state machine. The states are:

SD_EVENT_IDLE: The event loop is idle and not waiting for any events.

SD_EVENT_WAITING: The event loop is waiting for events.

SD_EVENT_DISPATCHING: The event loop is dispatching events.

SD_EVENT_PREPARING: The event loop is preparing for the next iteration.

RETURN VALUE

On success, these functions return 0 or a positive integer. On failure, they return a negative error number. See errno(3) for details.

Possible error codes include:

-EINVAL: Invalid argument supplied.

-ENOMEM: Out of memory.

-ESTALE: The event loop has been created in a different process, library or module instance.

Other errors are possible, too.

NOTES

Functions described here are available as a shared library, which can be compiled against and linked to with the libsystemd pkg-config(1) file.

The code described here uses getenv(3), which is declared to be not multi-thread-safe. This means that the code calling the functions described here must not call setenv(3) from a parallel thread. It is recommended to only do calls to setenv() from an early phase of the program when no other threads have been started.

HISTORY

sd_event_prepare(), sd_event_wait(), sd_event_dispatch(), and sd_event_get_state() were added in version 221.

sd_event_get_iteration() was added in version 231.
