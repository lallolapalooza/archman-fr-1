SD_JOURNAL_OPEN(3) sd_journal_open SD_JOURNAL_OPEN(3)

NOM

sd_journal_open, sd_journal_open_directory, sd_journal_open_directory_fd, sd_journal_open_files, sd_journal_open_files_fd, sd_journal_open_namespace, sd_journal_close, sd_journal, SD_JOURNAL_LOCAL_ONLY, SD_JOURNAL_RUNTIME_ONLY, SD_JOURNAL_SYSTEM, SD_JOURNAL_CURRENT_USER, SD_JOURNAL_OS_ROOT, SD_JOURNAL_ALL_NAMESPACES, SD_JOURNAL_INCLUDE_DEFAULT_NAMESPACE, SD_JOURNAL_TAKE_DIRECTORY_FD - Ouvrir le journal pour la lecture

SYNTAXIS

#include <systemd/sd-journal.h>

int sd_journal_open(sd_journal **ret, int flags);

int sd_journal_open_namespace(sd_journal **ret, const char *namespace, int flags);

int sd_journal_open_directory(sd_journal **ret, const char *path, int flags);

int sd_journal_open_directory_fd(sd_journal **ret, int fd, int flags);

int sd_journal_open_files(sd_journal **ret, const char **paths, int flags);

int sd_journal_open_files_fd(sd_journal **ret, int fds[], unsigned n_fds, int flags);

void sd_journal_close(sd_journal *j);

DESCRIPTION

sd_journal_open() ouvre le journal système en lecture. Il recherche automatiquement tous les fichiers de journal et les intercale lors de la lecture. Le premier argument prend un pointeur vers un pointeur sd_journal, qui, en cas de succès, contiendra un objet de contexte de journal. Le deuxième argument est un champ d'indicateurs, qui peut être composé des indicateurs suivants combinés par OU logique : SD_JOURNAL_LOCAL_ONLY garantit que seuls les fichiers de journal générés sur la machine locale sont ouverts. SD_JOURNAL_RUNTIME_ONLY garantit que seuls les fichiers de journal non persistants sont ouverts, excluant ceux stockés sur un support persistant. SD_JOURNAL_SYSTEM fera en sorte que les fichiers de journal des services système et du noyau soient ouverts (par opposition aux processus utilisateur). SD_JOURNAL_CURRENT_USER fera en sorte que les fichiers de journal de l'utilisateur actuel soient ouverts. Si ni SD_JOURNAL_SYSTEM ni SD_JOURNAL_CURRENT_USER ne sont spécifiés, tous les types de fichiers de journal seront ouverts.

sd_journal_open_namespace() est similaire à sd_journal_open(), mais prend un paramètre supplémentaire namespace qui spécifie sur quel espace de noms opérer. Si spécifié comme NULL, l'appel est identique à sd_journal_open(). Si non NULL, seules les données de l'espace de noms spécifié seront accessibles. Cet appel comprend deux indicateurs supplémentaires : si SD_JOURNAL_ALL_NAMESPACES est spécifié, le paramètre namespace est ignoré et tous les espaces de noms définis seront accessibles simultanément ; si SD_JOURNAL_INCLUDE_DEFAULT_NAMESPACE est spécifié, l'espace de noms spécifié et l'espace de noms par défaut seront accessibles, mais aucun autre (cet indicateur n'a pas d'effet lorsque namespace est passé comme NULL). Pour plus de détails sur les espaces de noms de journal, voir systemd-journald.service(8).

sd_journal_open_directory() est similaire à sd_journal_open(), mais prend un chemin de répertoire absolu comme argument. Tous les fichiers de journal dans ce répertoire seront ouverts et automatiquement intercalés. Cet appel prend également un argument d'indicateurs. Les paramètres d'indicateurs acceptés par cet appel sont SD_JOURNAL_OS_ROOT, SD_JOURNAL_SYSTEM et SD_JOURNAL_CURRENT_USER. Si SD_JOURNAL_OS_ROOT est spécifié, les fichiers de journal sont recherchés sous les chemins usuels /var/log/journal et /run/log/journal, au lieu d'être directement sous le chemin spécifié. Les deux autres indicateurs limitent les fichiers qui sont ouverts, de la même manière que dans sd_journal_open().

sd_journal_open_directory_fd() est similaire à sd_journal_open_directory(), mais prend une référence à un répertoire dans le système de fichiers comme argument au lieu d'un chemin système absolu. En plus des indicateurs acceptés par sd_journal_open_directory(), cette fonction accepte également SD_JOURNAL_TAKE_DIRECTORY_FD. Si SD_JOURNAL_TAKE_DIRECTORY_FD est spécifié, la fonction prendra possession du descripteur de fichier spécifié avec succès, et il sera fermé par sd_journal_close(), donc l'appelant de la fonction ne doit pas fermer le descripteur de fichier. Lorsque l'indicateur n'est pas spécifié, sd_journal_close() ne fermera pas le descripteur, donc l'appelant doit le fermer après sd_journal_close().

sd_journal_open_files() est similaire à sd_journal_open(), mais prend une liste de chemins de fichiers se terminant par NULL à ouvrir. Tous les fichiers seront ouverts et automatiquement intercalés. Cet appel prend également un argument d'indicateurs, mais il doit être passé comme 0 car aucun indicateur n'est compris dans cet appel. Veuillez noter que dans le cas d'un journal actif, cette fonction n'est utile que pour le débogage, car les fichiers de journal individuels peuvent être mis en rotation à tout moment et l'ouverture de fichiers spécifiques est intrinsèquement une course.

sd_journal_open_files_fd() est similaire à sd_journal_open_files(), mais prend un tableau de descripteurs de fichiers qui doivent faire référence à des fichiers de journal, au lieu d'un tableau de chemins système. Passez le tableau de descripteurs comme deuxième argument, et le nombre d'entrées du tableau comme troisième argument. Le paramètre d'indicateurs doit être passé comme 0.

Les objets sd_journal ne peuvent pas être utilisés dans le processus enfant après un fork. Les fonctions qui prennent un objet de journal comme argument (sd_journal_next() et autres) renverront -ECHILD après un fork.

sd_journal_close() fermera le contexte de journal alloué avec sd_journal_open() ou sd_journal_open_directory() et libérera ses ressources.

Lors de l'ouverture du journal, seuls les fichiers de journal accessibles à l'utilisateur appelant seront ouverts. Si les fichiers de journal ne sont pas accessibles à l'utilisateur, cela sera ignoré silencieusement.

Voir sd_journal_next(3) pour un exemple sur la façon d'itérer sur le journal après l'avoir ouvert avec sd_journal_open().

L'objet de contexte de journal renvoyé par sd_journal_open() fait référence à un fichier de journal spécifique en tant qu'entrée actuelle, similaire à un index de fichier dans un système de fichiers classique, mais sans positions absolues. Il peut être modifié par sd_journal_next(3) et sd_journal_seek_head(3) et les appels associés. La position de l'entrée actuelle peut être exportée dans des chaînes de curseur, comme accessible via sd_journal_get_cursor(3). Les chaînes de curseur peuvent être utilisées globalement pour identifier de manière stable une entrée de journal spécifique, puis rechercher cette entrée (ou si l'entrée spécifique n'est pas disponible localement, son entrée la plus proche dans le temps) via sd_journal_seek_cursor(3).

La notification des changements du journal est disponible via sd_journal_get_fd() et les appels associés.

VALEUR RENVOYÉE

Les appels sd_journal_open(), sd_journal_open_directory() et sd_journal_open_files() renvoient 0 en cas de succès ou un code d'erreur de type errno. sd_journal_close() ne renvoie rien.

NOTES

Toutes les fonctions mentionnées ici sont indépendantes des threads et un seul thread peut opérer sur un objet donné à un moment donné. Différents threads peuvent accéder au même objet à des moments différents. Plusieurs objets indépendants peuvent être utilisés en parallèle à partir de différents threads.

Les fonctions décrites ici sont disponibles sous forme de bibliothèque partagée, qui peut être compilée et liée avec le fichier libsystemd en utilisant pkg-config(1).

HISTORIQUE

sd_journal_open_files() a été ajouté dans la version 205.

sd_journal_open_directory_fd() et sd_journal_open_files_fd() ont été ajoutés dans la version 230.

sd_journal_open_namespace() a été ajouté dans la version 245.
