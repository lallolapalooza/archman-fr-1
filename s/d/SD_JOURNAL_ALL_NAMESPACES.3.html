SD_JOURNAL_OPEN(3) sd_journal_open SD_JOURNAL_OPEN(3)

NOM

sd_journal_open, sd_journal_open_directory, sd_journal_open_directory_fd, sd_journal_open_files, sd_journal_open_files_fd, sd_journal_open_namespace, sd_journal_close, sd_journal, SD_JOURNAL_LOCAL_ONLY, SD_JOURNAL_RUNTIME_ONLY, SD_JOURNAL_SYSTEM, SD_JOURNAL_CURRENT_USER, SD_JOURNAL_OS_ROOT, SD_JOURNAL_ALL_NAMESPACES, SD_JOURNAL_INCLUDE_DEFAULT_NAMESPACE, SD_JOURNAL_TAKE_DIRECTORY_FD - Ouvre le journal système en lecture

SYNTAXE

#include <systemd/sd-journal.h>

int sd_journal_open(sd_journal **ret, int flags);

int sd_journal_open_namespace(sd_journal **ret, const char *namespace, int flags);

int sd_journal_open_directory(sd_journal **ret, const char *path, int flags);

int sd_journal_open_directory_fd(sd_journal **ret, int fd, int flags);

int sd_journal_open_files(sd_journal **ret, const char **paths, int flags);

int sd_journal_open_files_fd(sd_journal **ret, int fds[], unsigned n_fds, int flags);

void sd_journal_close(sd_journal *j);

DESCRIPTION

sd_journal_open() ouvre le journal des logs en lecture. Il trouvera automatiquement tous les fichiers du journal et les entrelacera automatiquement lors de la lecture. Comme premier argument, il prend un pointeur vers un pointeur sd_journal, qui, en cas de succès, contiendra un objet contexte du journal. Le deuxième argument est un champ de drapeaux, qui peut être constitué des drapeaux suivants combinés par OR : SD_JOURNAL_LOCAL_ONLY assure que seuls les fichiers du journal générés sur la machine locale seront ouverts. SD_JOURNAL_RUNTIME_ONLY assure que seuls les fichiers du journal volatils seront ouverts, excluant ceux qui sont stockés sur un support persistant. SD_JOURNAL_SYSTEM provoquera l'ouverture des fichiers du journal des services système et du noyau (par opposition aux processus de session utilisateur). SD_JOURNAL_CURRENT_USER provoquera l'ouverture des fichiers du journal de l'utilisateur courant. Si ni SD_JOURNAL_SYSTEM ni SD_JOURNAL_CURRENT_USER ne sont spécifiés, tous les types de fichiers du journal seront ouverts.

sd_journal_open_namespace() est similaire à sd_journal_open() mais prend un paramètre namespace additionnel qui spécifie sur quel namespace de journal opérer. S'il est spécifié comme NULL, l'appel est identique à sd_journal_open(). S'il est non NULL, seules les données du namespace identifié par le paramètre spécifié sont accessibles. Cet appel comprend deux drapeaux additionnels : si SD_JOURNAL_ALL_NAMESPACES est spécifié, le paramètre namespace est ignoré et tous les namespaces définis sont accessibles simultanément ; si SD_JOURNAL_INCLUDE_DEFAULT_NAMESPACE, le namespace spécifié et le namespace par défaut sont accessibles mais aucun autre (ce drapeau n'a aucun effet lorsque namespace est passé comme NULL). Pour plus de détails sur les namespaces de journal, voir systemd-journald.service(8).

sd_journal_open_directory() est similaire à sd_journal_open() mais prend un chemin de répertoire absolu comme argument. Tous les fichiers du journal dans ce répertoire seront ouverts et entrelacés automatiquement. Cet appel prend également un argument de drapeaux. Les paramètres de drapeaux acceptés par cet appel sont SD_JOURNAL_OS_ROOT, SD_JOURNAL_SYSTEM et SD_JOURNAL_CURRENT_USER. Si SD_JOURNAL_OS_ROOT est spécifié, les fichiers du journal sont recherchés sous /var/log/journal et /run/log/journal par rapport au chemin spécifié, au lieu d'être directement en dessous. Les deux autres drapeaux limitent les fichiers qui sont ouverts, de la même manière que pour sd_journal_open().

sd_journal_open_directory_fd() est similaire à sd_journal_open_directory(), mais prend un descripteur de fichier référençant un répertoire dans le système de fichiers au lieu d'un chemin de système de fichiers absolu. En plus des drapeaux acceptés par sd_journal_open_directory(), cette fonction accepte également SD_JOURNAL_TAKE_DIRECTORY_FD. Si SD_JOURNAL_TAKE_DIRECTORY_FD est spécifié, la fonction prendra la propriété du descripteur de fichier spécifié en cas de succès, et il sera fermé par sd_journal_close(), par conséquent, l'appelant de la fonction ne doit pas fermer le descripteur de fichier. Lorsque le drapeau n'est pas spécifié, sd_journal_close() ne fermera pas le descripteur de fichier, donc l'appelant devrait le fermer après sd_journal_close().

sd_journal_open_files() est similaire à sd_journal_open() mais prend une liste de chemins de fichiers se terminant par NULL à ouvrir. Tous les fichiers seront ouverts et entrelacés automatiquement. Cet appel prend également un argument de drapeaux, mais il doit être passé comme 0 car aucun drapeau n'est actuellement compris pour cet appel. Veuillez noter que dans le cas d'un journal en direct, cette fonction est uniquement utile pour le débogage, car les fichiers individuels du journal peuvent être remplacés à tout moment, et l'ouverture de fichiers spécifiques est intrinsèquement sujette à des courses.

sd_journal_open_files_fd() est similaire à sd_journal_open_files() mais prend un tableau de descripteurs de fichiers ouverts qui doivent référencer des fichiers du journal, au lieu d'un tableau de chemins de systèmes de fichiers. Passez le tableau de descripteurs de fichiers comme deuxième argument, et le nombre d'entrées du tableau dans le troisième. Le paramètre de drapeaux doit être passé comme 0.

Les objets sd_journal ne peuvent pas être utilisés dans l'enfant après un fork. Les fonctions qui prennent un objet journal comme argument (sd_journal_next() et autres) retourneront -ECHILD après un fork.

sd_journal_close() fermera le contexte du journal alloué avec sd_journal_open() ou sd_journal_open_directory() et libérera ses ressources.

Lors de l'ouverture du journal, seuls les fichiers du journal accessibles à l'utilisateur appelant seront ouverts. Si les fichiers du journal ne sont pas accessibles à l'appelant, cela sera silencieusement ignoré.

Voir sd_journal_next(3) pour un exemple sur la manière d'itérer dans le journal après l'avoir ouvert avec sd_journal_open().

Un objet contexte de journal renvoyé par sd_journal_open() fait référence à une entrée de journal spécifique comme entrée courante, similaire à un index de recherche de fichier dans un fichier système de fichiers classique, mais sans positions absolues. Il peut être modifié avec sd_journal_next() et sd_journal_seek_head(3) et les appels associés. La position de l'entrée courante peut être exportée dans des chaînes curseur, comme accessible via sd_journal_get_cursor(3). Les chaînes curseur peuvent être utilisées pour identifier globalement une entrée de journal d'une manière stable, puis plus tard pour s'y positionner (ou si l'entrée spécifique n'est pas disponible localement, vers son entrée la plus proche dans le temps) sd_journal_seek_cursor(3).

La notification des changements du journal est disponible via sd_journal_get_fd() et les appels associés.

VALEUR RENVOYÉE

Les appels sd_journal_open(), sd_journal_open_directory() et sd_journal_open_files() renvoient 0 en cas de succès ou un code d'erreur négatif de style errno. sd_journal_close() ne renvoie rien.

NOTES

Toutes les fonctions listées ici sont indépendantes des threads et un seul thread peut opérer sur un objet donné à un moment donné. Différents threads peuvent accéder au même objet à différents moments. Plusieurs objets indépendants peuvent être utilisés à partir de différents threads en parallèle.

Les fonctions décrites ici sont disponibles sous forme de bibliothèque partagée, qui peut être compilée et liée avec le fichier libsystemd pkg-config(1).

HISTORIQUE

sd_journal_open(), sd_journal_open_directory() et sd_journal_close() ont été ajoutés dans la version 187.

sd_journal_open_files() a été ajoutée dans la version 205.

sd_journal_open_directory_fd() et sd_journal_open_files_fd() ont été ajoutés dans la version 230.

sd_journal_open_namespace() a été ajouté dans la version 245.
