NOM

sd_journal_get_fd, sd_journal_get_events, sd_journal_get_timeout, sd_journal_process, sd_journal_wait, sd_journal_reliable_fd, SD_JOURNAL_NOP, SD_JOURNAL_APPEND, SD_JOURNAL_INVALIDATE - Interface de notification de changement du journal

SYNTAXE

#include <systemd/sd-journal.h>

int sd_journal_get_fd(sd_journal *j);

int sd_journal_get_events(sd_journal *j);

int sd_journal_get_timeout(sd_journal *j, uint64_t *timeout_usec);

int sd_journal_process(sd_journal *j);

int sd_journal_wait(sd_journal *j, uint64_t timeout_usec);

int sd_journal_reliable_fd(sd_journal *j);

DESCRIPTION

sd_journal_get_fd() renvoie un descripteur de fichier qui peut être interrogé de manière asynchrone dans une boucle d'événements externe et qui est signalé dès que le journal change, car de nouvelles entrées ou de nouveaux fichiers ont été ajoutés, une rotation a eu lieu, ou des fichiers ont été supprimés, etc. Le descripteur de fichier convient à une utilisation dans poll(2). Utilisez sd_journal_get_events() pour obtenir un masque d'événements à surveiller. L'appel prend un argument : l'objet de contexte du journal. Notez que tous les systèmes de fichiers ne sont pas capables de générer les événements nécessaires pour réveiller ce descripteur de fichier pour que les changements soient remarqués immédiatement. En particulier, les systèmes de fichiers réseau ne génèrent pas toujours des événements de changement de fichier appropriés. Ces cas peuvent être détectés avec sd_journal_reliable_fd(), ci-dessous. sd_journal_get_timeout() assurera dans ces cas que les réveils se produisent suffisamment fréquemment pour que les changements soient remarqués, bien qu'avec une certaine latence.

sd_journal_get_events() renverra le masque poll() à attendre. Cette fonction renverra une combinaison de POLLIN et POLLOUT et similaires à remplir dans le champ ".events" de struct pollfd.

sd_journal_get_timeout() renverra une valeur de délai d'attente pour l'utilisation dans poll(). Elle renvoie une valeur en microsecondes depuis l'époque de CLOCK_MONOTONIC pour le délai d'attente de poll() dans timeout_usec. Voir clock_gettime(2) pour des détails sur CLOCK_MONOTONIC. S'il n'y a pas de délai d'attente à attendre, elle remplira (uint64_t) -1 à la place. Notez que poll() prend un délai d'attente relatif en millisecondes plutôt qu'un délai d'attente absolu en microsecondes. Pour convertir le délai absolu 'us' en délai relatif 'ms', utilisez du code comme suit :

uint64_t t;
int msec;
sd_journal_get_timeout(m, &t);
if (t == (uint64_t) -1)
  msec = -1;
else {
  struct timespec ts;
  uint64_t n;
  clock_gettime(CLOCK_MONOTONIC, &ts);
  n = (uint64_t) ts.tv_sec * 1000000 + ts.tv_nsec / 1000;
  msec = t > n ? (int) ((t - n + 999) / 1000) : 0;
}

Le code ci-dessus n'effectue aucune vérification d'erreur pour des raisons de brièveté. L'entier msec calculé peut être passé directement comme paramètre de délai d'attente de poll().

Après chaque réveil de poll(), sd_journal_process() doit être appelé pour traiter les événements. Cet appel indiquera également quel type de changement a été détecté (voir ci-dessous ; notez que les réveils intempestifs sont possibles).

Une alternative synchrone à l'utilisation de sd_journal_get_fd(), sd_journal_get_events(), sd_journal_get_timeout() et sd_journal_process() est sd_journal_wait(). Elle attendra synchrone jusqu'à ce que le journal soit modifié. Le temps maximum pendant lequel cet appel dort peut être contrôlé par le paramètre timeout_usec. Passez (uint64_t) -1 pour attendre indéfiniment. En interne, cet appel combine simplement sd_journal_get_fd(), sd_journal_get_events(), sd_journal_get_timeout(), poll() et sd_journal_process() en un seul.

sd_journal_reliable_fd() peut être utilisé pour vérifier si les événements de réveil du descripteur de fichier renvoyé par sd_journal_get_fd() sont connus pour être déclenchés rapidement. Sur certains systèmes de fichiers où les événements de changement de fichier de l'OS ne sont pas disponibles (comme NFS), les changements doivent être sondés à plusieurs reprises, et ne sont donc détectés qu'avec une latence considérable. Cet appel renverra une valeur positive si les changements du journal sont détectés rapidement et zéro lorsqu'ils doivent être sondés. Notez qu'il n'est généralement pas nécessaire d'invoquer cette fonction directement car sd_journal_get_timeout() demandera les délais d'attente appropriés de toute façon.

Notez que toutes les interfaces de notification de changement ci-dessus ne signalent pas les changements instantanément. Des latences sont introduites pour plusieurs raisons : comme mentionné, certains backends de stockage nécessitent un sondage basé sur le temps, dans d'autres cas, les réveils sont optimisés en regroupant les événements, et l'OS introduit des latences supplémentaires de planification d'E/S/CPU.

VALEUR RENVOYÉE

sd_journal_get_fd() renvoie un descripteur de fichier valide en cas de succès ou un code d'erreur négatif de style errno.

sd_journal_get_events() renvoie une combinaison de POLLIN, POLLOUT et similaires en cas de succès ou un code d'erreur négatif de style errno.

sd_journal_reliable_fd() renvoie un entier positif si le descripteur de fichier renvoyé par sd_journal_get_fd() déclenchera des réveils immédiats pour tous les changements du journal. Renvoie 0 s'il peut y avoir une latence.

sd_journal_process() et sd_journal_wait() renvoient un code d'erreur négatif de style errno, ou l'un des suivants : SD_JOURNAL_NOP, SD_JOURNAL_APPEND ou SD_JOURNAL_INVALIDATE en cas de succès :

•Si SD_JOURNAL_NOP est renvoyé, le journal n'a pas changé depuis la dernière invocation.
•Si SD_JOURNAL_APPEND est renvoyé, de nouvelles entrées ont été ajoutées à la fin du journal. Dans ce cas, il suffit de continuer à lire à l'emplacement précédent de la fin du journal pour lire les entrées nouvellement ajoutées.
•Si SD_JOURNAL_INVALIDATE, des fichiers du journal ont été ajoutés ou supprimés de l'ensemble des fichiers du journal surveillés (par exemple, en raison d'une rotation ou d'un nettoyage), et par conséquent, des entrées ont pu apparaître ou disparaître à des endroits arbitraires dans le flux de logs, potentiellement avant ou après l'ancienne fin du flux de logs. Si SD_JOURNAL_INVALIDATE est renvoyé, les interfaces d'aperçu en direct qui souhaitent refléter à l'écran l'état précis des données de logs sur le disque devraient probablement rafraîchir entièrement leur affichage (par rapport au curseur de l'entrée de log en haut de l'écran). Les programmes qui ne s'intéressent qu'à un flux de données de logs strictement séquentiel peuvent traiter SD_JOURNAL_INVALIDATE de la même manière que SD_JOURNAL_APPEND, ignorant ainsi toute modification de la vue des logs antérieure à l'ancienne fin du flux de logs.

SÉCURITÉ DES SIGNAUX

En général, sd_journal_get_fd(), sd_journal_get_events() et sd_journal_get_timeout() ne sont *pas* "async signal safe" au sens de signal-safety(7). Néanmoins, seul le premier appel à l'une de ces trois fonctions effectue des opérations non sûres, de sorte que les appels subséquents *sont* sûrs.

sd_journal_process() et sd_journal_wait() ne sont pas sûrs. sd_journal_reliable_fd() est sûr.

NOTES

Toutes les fonctions listées ici sont indépendantes des threads et un seul thread peut opérer sur un objet donné à un moment donné. Différents threads peuvent accéder au même objet à des moments différents. Plusieurs objets indépendants peuvent être utilisés à partir de différents threads en parallèle.

Les fonctions décrites ici sont disponibles sous forme de bibliothèque partagée, qui peut être compilée et liée avec le fichier libsystemd pkg-config(1).

sd_journal_wait.3.en - archlinux manual pages

NAME

sd_journal_wait - Wait for journal changes or a specific entry

SYNOPSIS

    #include <systemd/sd-journal.h>

    int sd_journal_wait(sd_journal *j, uint64_t timeout_usec);
    int sd_journal_process(sd_journal *j);
    int sd_journal_get_fd(sd_journal *j);
    int sd_journal_get_events(sd_journal *j);
    int sd_journal_get_timeout(sd_journal *j, uint64_t *timeout_usec);
    int sd_journal_reliable_fd(sd_journal *j);

DESCRIPTION

The function sd_journal_wait() waits until at least one new message is available in the journal j, or until the specified timeout_usec time has passed (in microseconds). If timeout_usec is set to (uint64_t) -1, the function will block indefinitely until a new message is available.

sd_journal_process() should be called after sd_journal_wait() returns or after any other event that might indicate new journal data. It processes any newly available data, updating the internal state of the journal object. It returns the number of new entries that were made available since the last call.

sd_journal_get_fd() returns the file descriptor that can be used with e.g. poll() or select() to wait for new journal entries. This file descriptor will become readable when new journal entries are available.

sd_journal_get_events() returns the events that should be watched on the file descriptor returned by sd_journal_get_fd(). This value should be passed as the events argument to sd_journal_get_fd().

sd_journal_get_timeout() retrieves the suggested timeout in microseconds. This value is intended to be used with poll() or select(), or as the timeout_usec argument to sd_journal_wait(). If the journal object is configured to block indefinitely, it returns (uint64_t) -1.

sd_journal_reliable_fd() returns a file descriptor that is guaranteed to be readable exactly once when new journal data is available. This might be useful in specific scenarios where the file descriptor returned by sd_journal_get_fd() might be readable multiple times for the same event.

RETURN VALUE

On success, sd_journal_wait() returns the number of new entries available. If the timeout occurred and no new entries are available, it returns 0. On failure, it returns a negative error number.

sd_journal_process() returns the number of new entries that were made available. On failure, it returns a negative error number.

sd_journal_get_fd(), sd_journal_get_events(), and sd_journal_reliable_fd() return a valid file descriptor on success, or -1 on failure.

sd_journal_get_timeout() returns 0 on success and sets timeout_usec to the timeout value. On failure, it returns a negative error number.

SIGNAL SAFETY

sd_journal_wait(), sd_journal_process(), sd_journal_get_fd(), sd_journal_get_events(), sd_journal_get_timeout(), and sd_journal_reliable_fd() are thread-safe.

NOTES

These functions are available as a shared library, which can be compiled and linked to with the pkg-config(1) macro: pkg-config --cflags --libs libsystemd.

The file descriptor returned by sd_journal_get_fd() should not be closed, duplicated or used for anything other than waiting for events with poll(), select() or similar functions. The same applies to the file descriptor returned by sd_journal_reliable_fd().

It is recommended to use sd_journal_wait() in a loop together with sd_journal_process(). The typical pattern is:

  sd_journal *j;
  sd_journal_open(&j, SD_JOURNAL_LOCAL_ONLY);

  // Optionally, set up a filter
  // sd_journal_add_filter(j, "PRIORITY=0");

  // Loop processing entries
  for (;;) {
    int r;

    r = sd_journal_wait(j, (uint64_t) -1); // Wait indefinitely
    if (r < 0) {
      fprintf(stderr, "Failed to wait for journal entries: %s\n", strerror(-r));
      break;
    }

    // Process all available entries
    while ((r = sd_journal_process(j)) > 0) {
      // Optionally, read and process the entry data
      // const char *data;
      // size_t length;
      // sd_journal_get_data(j, "MESSAGE", &data, &length);
      // printf("%.*s\n", (int) length, data);
    }
    if (r < 0) {
      fprintf(stderr, "Failed to process journal entries: %s\n", strerror(-r));
      break;
    }
  }

  sd_journal_close(j);

EXAMPLES

Basic Usage:

  /* SPDX-License-Identifier: MIT-0 */
  #include <stdio.h>
  #include <stdlib.h>
  #include <string.h>
  #include <systemd/sd-journal.h>

  int main(int argc, char *argv[]) {
    sd_journal *j = NULL;
    int r;

    r = sd_journal_open(&j, SD_JOURNAL_LOCAL_ONLY);
    if (r < 0) {
      fprintf(stderr, "Failed to open journal: %s\n", strerror(-r));
      return EXIT_FAILURE;
    }

    // Optional: Add a filter
    // r = sd_journal_add_filter(j, "PRIORITY=0");
    // if (r < 0) {
    //   fprintf(stderr, "Failed to add filter: %s\n", strerror(-r));
    //   sd_journal_close(j);
    //   return EXIT_FAILURE;
    // }

    printf("Waiting for journal entries...\n");

    for (;;) {
      const void *d;
      size_t l;

      /* Wait for new entries indefinitely */
      r = sd_journal_wait(j, (uint64_t) -1);
      if (r < 0) {
        fprintf(stderr, "Failed to wait for journal entries: %s\n", strerror(-r));
        break;
      }

      /* Process all available entries */
      while ((r = sd_journal_process(j)) > 0) {
        r = sd_journal_get_data(j, "MESSAGE", &d, &l);
        if (r < 0) {
          fprintf(stderr, "Failed to get message: %s\n", strerror(-r));
          continue; // Continue to next entry
        }
        printf("%.*s\n", (int) l, (const char*) d);
      }
      if (r < 0) {
        fprintf(stderr, "Failed to process journal entries: %s\n", strerror(-r));
        break;
      }
      // If r is 0, it means we waited but no new entries were processed.
      // This usually happens after a timeout in sd_journal_wait(),
      // but since we wait indefinitely here, it should ideally not happen
      // unless there's an issue. We continue the loop anyway.
    }

    sd_journal_close(j);
    return 0;
  }

Waiting with poll() (this example lacks all error checking for the sake of simplicity):

  /* SPDX-License-Identifier: MIT-0 */
  #define _GNU_SOURCE 1
  #include <poll.h>
  #include <time.h>
  #include <systemd/sd-journal.h>

  int wait_for_changes(sd_journal *j) {
    uint64_t t;
    int msec;
    struct pollfd pollfd;

    sd_journal_get_timeout(j, &t);
    if (t == (uint64_t) -1)
      msec = -1;
    else {
      struct timespec ts;
      uint64_t n;
      clock_gettime(CLOCK_MONOTONIC, &ts);
      n = (uint64_t) ts.tv_sec * 1000000 + ts.tv_nsec / 1000;
      msec = t > n ? (int) ((t - n + 999) / 1000) : 0;
    }

    pollfd.fd = sd_journal_get_fd(j);
    pollfd.events = sd_journal_get_events(j);
    poll(&pollfd, 1, msec);

    return sd_journal_process(j);
  }
