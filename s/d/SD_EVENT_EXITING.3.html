SD_EVENT_EXITING(3) sd_event_exit SD_EVENT_EXITING(3)

NOM

sd_event_exit, sd_event_prepare, sd_event_wait, sd_event_dispatch, sd_event_get_state, sd_event_get_iteration, SD_EVENT_INITIAL, SD_EVENT_PREPARING, SD_EVENT_ARMED, SD_EVENT_PENDING, SD_EVENT_RUNNING, SD_EVENT_EXITING, SD_EVENT_FINISHED - Opérations de boucle d'événements de bas niveau

SYNOPIS

#include <systemd/sd-event.h>
enum {
        SD_EVENT_INITIAL,
        SD_EVENT_PREPARING,
        SD_EVENT_ARMED,
        SD_EVENT_PENDING,
        SD_EVENT_RUNNING,
        SD_EVENT_EXITING,
        SD_EVENT_FINISHED,
};

int sd_event_prepare(sd_event*event);

int sd_event_wait(sd_event*event, uint64_tusec);

int sd_event_dispatch(sd_event*event);

int sd_event_get_state(sd_event*event);

int sd_event_get_iteration(sd_event*event, uint64_t*ret);

DESCRIPTION

Les fonctions sd_event_prepare(), sd_event_wait() et sd_event_dispatch() peuvent être utilisées pour exécuter des phases spécifiques d'une boucle d'événements. Voir sd_event_run(3) et sd_event_loop(3) pour les fonctions de plus haut niveau qui exécutent des itérations individuelles mais complètes d'une boucle d'événements ou l'exécutent continuellement.

La fonction sd_event_prepare() vérifie s'il y a des événements en attente et arme les timers nécessaires. S'il y a des événements prêts à être traités (« en attente »), elle renvoie une valeur positive et non nulle, et l'appelant doit traiter ces événements avec sd_event_dispatch().

La fonction sd_event_dispatch() déclenche la source d'événement la plus prioritaire avec un événement en attente. En cas de succès, sd_event_dispatch() renvoie zéro, ce qui indique qu'aucune autre source d'événement ne peut être déclenchée et que la boucle d'événements doit être fermée en appelant sd_event_exit(3) ; ou renvoie une valeur positive non nulle, indiquant qu'une source d'événement a été déclenchée et que la boucle d'événements revient à son état initial, et l'appelant doit démarrer la prochaine itération de la boucle d'événements en appelant à nouveau sd_event_prepare().

Dans le cas où sd_event_prepare() renvoie zéro, sd_event_wait() doit être appelé pour attendre de nouveaux événements ou un délai d'attente. S'il y a des événements prêts à être traités, elle renvoie une valeur positive non nulle et les événements doivent être déclenchés avec sd_event_dispatch(). Sinon, la boucle d'événements revient à son état initial et la prochaine itération de la boucle d'événements doit être démarrée en appelant à nouveau sd_event_prepare().

La fonction sd_event_get_state() peut être utilisée pour déterminer l'état de la boucle d'événements. Elle renvoie l'un des états décrits ci-dessous.

La fonction sd_event_get_iteration() peut être utilisée pour déterminer l'itération actuelle de la boucle d'événements. Elle renvoie un entier non signé de 64 bits qui augmente de façon monotone à chaque itération de la boucle d'événements, commençant à 0. Le compteur est incrémenté lors de l'appel à sd_event_prepare().

Les cinq fonctions prennent, comme premier argument, l'objet de boucle d'événements event qui a été créé avec sd_event_new(). Le délai d'attente de sd_event_wait() est spécifié en usec en microsecondes. (uint64_t) -1 peut être utilisé pour spécifier un délai d'attente infini.

MACHINE D'ÉTAT

La boucle d'événements connaît les états suivants, qui peuvent être consultés avec sd_event_get_state().

SD_EVENT_INITIAL

L'état initial de la boucle d'événements avant chaque itération de la boucle. Utilisez sd_event_prepare() pour passer à l'état SD_EVENT_ARMED ou SD_EVENT_PENDING.

Ajouté dans la version 229.

SD_EVENT_PREPARING

Une source d'événement est en cours de préparation, c'est-à-dire que la fonction de préparation est en cours d'exécution, telle que définie par sd_event_source_set_prepare(3). Cet état n'est vu que dans le gestionnaire de préparation de source d'événement qui est appelé depuis sd_event_prepare() et est immédiatement suivi par SD_EVENT_ARMED ou SD_EVENT_PENDING.

Ajouté dans la version 229.

SD_EVENT_ARMED

sd_event_prepare() a été appelé et aucune source d'événement n'était prête à être déclenchée. Utilisez sd_event_wait() pour attendre de nouveaux événements et passer à l'état SD_EVENT_PENDING ou revenir à l'état SD_EVENT_INITIAL.

Ajouté dans la version 229.

SD_EVENT_PENDING

sd_event_prepare() ou sd_event_wait() ont été appelés et il y a des sources d'événement avec des événements en attente. Utilisez sd_event_dispatch() pour déclencher la source d'événement de priorité la plus élevée et passer à l'état SD_EVENT_INITIAL, ou à SD_EVENT_FINISHED.

Ajouté dans la version 229.

SD_EVENT_RUNNING

Une source d'événement régulière est en cours de déclenchement. Cet état n'est vu que dans le gestionnaire de source d'événement qui est appelé depuis sd_event_dispatch(), et est immédiatement suivi par SD_EVENT_INITIAL ou SD_EVENT_FINISHED une fois que le gestionnaire de source d'événement renvoie. Notez que pendant le déclenchement de la source d'événement de sortie, l'état SD_EVENT_EXITING est vu.

Ajouté dans la version 229.

SD_EVENT_EXITING

Similaire à SD_EVENT_RUNNING mais c'est l'état dans lequel la source d'événement de sortie est déclenchée. Il est immédiatement suivi par SD_EVENT_INITIAL ou SD_EVENT_FINISHED une fois que le gestionnaire de source d'événement renvoie.

Ajouté dans la version 229.

SD_EVENT_FINISHED

La boucle d'événements est terminée. Toutes les sources d'événement de sortie ont été exécutées. Si la boucle d'événements est dans cet état, elle n'a plus de sens et doit être libérée.

Ajouté dans la version 229.

VALEUR DE RETOUR

En cas de succès, ces fonctions renvoient 0 ou une valeur positive. En cas d'échec, elles renvoient un code d'erreur de type -errno. Pour sd_event_prepare() et sd_event_wait(), une valeur positive non nulle indique que des événements sont prêts à être traités et 0 indique qu'aucun événement n'est prêt. Pour sd_event_dispatch(), une valeur positive non nulle indique que la boucle d'événements est revenue à son état initial et 0 indique que la boucle d'événements s'est terminée. sd_event_get_state() renvoie une valeur positive ou nulle en cas de succès.

Erreurs

Les erreurs retournées peuvent indiquer les problèmes suivants :

-EINVAL

Le paramètre event est invalide ou est NULL.

-EBUSY

L'objet de boucle d'événements n'est pas dans le bon état.

-ESTALE

La boucle d'événements a déjà été terminée.

«Pp">-ECHILD

La boucle d'événements a été créée dans un processus, une instance de bibliothèque ou un module différent.

D'autres erreurs sont également possibles.

NOTES

Les fonctions décrites ici sont disponibles en tant que bibliothèque partagée, qui peut être compilée et liée à l'aide du fichier pkg-config(1) de libsystemd.

Le code décrit ici utilise getenv(3), qui est déclaré comme n'étant pas sûr pour le multithreading. Cela signifie que le code qui appelle les fonctions décrites ici ne doit pas appeler setenv(3) à partir d'un thread parallèle. Il est recommandé de n'appeler setenv() qu'à un stade précoce du programme, lorsque aucun autre thread n'a encore été lancé.

HISTORIQUE

sd_event_prepare(), sd_event_wait(), sd_event_dispatch(), et sd_event_get_state() ont été ajoutés dans la version 221.

sd_event_get_iteration() a été ajouté dans la version 231.
