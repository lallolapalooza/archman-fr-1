DESCRIPTION

La structure sd_bus_error transporte des informations sur une condition d'erreur D-Bus, ou son absence. Les fonctions décrites ci-dessous peuvent être utilisées pour définir et interroger les champs de cette structure.

•Le champ name contient un identifiant court d'erreur. Il doit suivre les règles pour les noms d'erreur décrites dans la spécification D-Bus, sous-section Valid D-Bus Names[1]. Un certain nombre de noms d'erreur courants et standardisés sont décrits dans sd-bus-errors(3), mais des erreurs supplémentaires spécifiques au domaine peuvent être définies par les applications.
•Le champ message contient généralement une chaîne lisible par l'homme décrivant les détails, mais peut être NULL.

Une structure sd_bus_error non définie doit avoir ses deux champs initialisés à NULL, et signifie l'absence d'erreur, c'est-à-dire le succès. Assignez SD_BUS_ERROR_NULL à la structure afin d'initialiser les deux champs à NULL. Lorsque les ressources détenues par la structure sd_bus_error ne sont plus nécessaires, elles doivent être détruites avec sd_bus_error_free().

sd_bus_error_set() définit une structure d'erreur avec les chaînes de nom et de message spécifiées. Les chaînes seront copiées dans une mémoire interne nouvellement allouée. Il est essentiel de libérer le contenu à nouveau lorsqu'il n'est plus requis (voir ci-dessus). N'utilisez pas cet appel sur des structures d'erreur déjà définies. Si vous avez l'intention de réutiliser une structure d'erreur, libérez d'abord les anciennes données qu'elle contient avec sd_bus_error_free().

sd_bus_error_set() renvoie une valeur de type errno (voir errno(3)) déterminée à partir du nom d'erreur spécifié name. Si name est NULL, on suppose qu'aucune erreur ne s'est produite, et 0 est retourné. Si name est non nul, une valeur négative est toujours retournée. Si e est NULL, aucune structure d'erreur n'est initialisée, mais name est toujours converti en une valeur de style errno.

Diverses erreurs D-Bus bien connues sont converties en leurs équivalents errno bien connus, et les autres sont converties en -EIO. Voir sd-bus-errors(3) pour une liste des noms d'erreurs bien connus. Des correspondances d'erreurs supplémentaires peuvent être définies avec sd_bus_error_add_map(3).

sd_bus_error_set() est conçu pour être utilisé de manière pratique dans une instruction return. Si message est NULL, aucun message n'est défini. Cet appel peut échouer si aucune mémoire ne peut être allouée pour les chaînes de nom et de message, auquel cas une erreur SD_BUS_ERROR_NO_MEMORY sera définie à la place et -ENOMEM sera renvoyé.

sd_bus_error_setf() et sd_bus_error_setfv() sont similaires à sd_bus_error_set(), mais prennent une chaîne de format printf(3) et les arguments correspondants pour générer le champ message. sd_bus_error_setf() utilise des arguments variadiques, et sd_bus_error_setfv() accepte les arguments sous forme d'une liste de paramètres va_arg(3).

sd_bus_error_set_const() est similaire à sd_bus_error_set(), mais les chaînes de paramètres ne sont pas copiées en interne, et doivent donc rester constantes et valides pendant toute la durée de vie de e. Utilisez cet appel pour éviter les allocations mémoire lors de la définition de structures d'erreur. Comme cet appel n'alloue pas de mémoire, il n'échouera pas avec un manque de mémoire comme sd_bus_error_set() peut le faire, comme décrit ci-dessus. Alternativement, la macro SD_BUS_ERROR_MAKE_CONST() peut être utilisée pour générer une structure d'erreur littérale et constante à la volée.

sd_bus_error_set_errno() renverra immédiatement 0 si le paramètre d'erreur spécifié error est 0. Sinon, il définira name à partir d'une valeur de style errno qui est convertie en une erreur D-Bus. strerror_r(3) sera utilisé pour définir message. Les noms d'erreurs D-Bus bien connus seront utilisés pour name si applicable, sinon un nom dans l'espace de noms "System.Error." sera généré. Le signe du numéro d'erreur spécifié est ignoré et la valeur absolue est utilisée implicitement. Si le numéro d'erreur spécifié error est non nul, l'appel renvoie toujours une valeur négative, pour une utilisation pratique dans les instructions return. Cet appel peut échouer en raison d'un manque de mémoire, auquel cas une erreur SD_BUS_ERROR_NO_MEMORY est définie à la place, et -ENOMEM est renvoyé.

sd_bus_error_set_errnof() et sd_bus_error_set_errnof() sont similaires à sd_bus_error_set_errno(), mais en plus de error, prennent une chaîne de format printf(3) et les arguments correspondants. Le champ message sera généré à partir de format et des arguments. sd_bus_error_set_errnof() utilise des arguments variadiques, et sd_bus_error_set_errnofv() accepte les arguments sous forme d'une liste de paramètres va_arg(3).

sd_bus_error_get_errno() convertit le champ name d'une structure d'erreur en une valeur de style errno (positive) en utilisant les mêmes règles que sd_bus_error_set(). Si e est NULL, 0 sera retourné.

sd_bus_error_copy() initialisera dst avec les valeurs de e, si e a été précédemment défini avec une valeur d'erreur. Sinon, il renverra immédiatement. Si les chaînes de e ont été définies en utilisant sd_bus_error_set_const(), elles seront partagées. Sinon, elles seront copiées. Avant cet appel, dst doit être non défini, c'est-à-dire soit fraîchement initialisé avec NULL, soit réinitialisé en utilisant sd_bus_error_free().

sd_bus_error_copy() renvoie généralement 0 ou une valeur négative de style errno basée sur le paramètre d'entrée e: 0 s'il était non défini et un entier négatif s'il était défini sur une erreur, de manière similaire à sd_bus_error_set(). DESCRIPTION

Les structures sd_bus_error sont utilisées pour transmettre les informations d'erreur entre les processus dans le cadre du protocole D-Bus. Elles contiennent généralement un nom d'erreur et un message d'erreur.

La structure sd_bus_error elle-même est conçue pour être allouée sur la pile. Son contenu, cependant, peut être alloué dynamiquement. Le champ name pointe vers une chaîne qui est soit une chaîne littérale fixe (lorsque la fonction sd_bus_error_set_const() est utilisée), soit une chaîne qui a été allouée dynamiquement par les fonctions d'initialisation d'erreur. Le champ message pointe toujours vers une chaîne allouée dynamiquement.

Les fonctions sd_bus_error_set(), sd_bus_error_setf() et sd_bus_error_set_const() définissent un nouveau nom et un nouveau message d'erreur dans la structure d'erreur donnée. Si la structure d'erreur contenait déjà une erreur, elle sera d'abord vidée avec sd_bus_error_free(). La fonction sd_bus_error_set() copie le nom et le message d'erreur. La fonction sd_bus_error_setf() est similaire à printf() et formate le message d'erreur à partir d'une chaîne de format et d'arguments variables. La fonction sd_bus_error_set_const() est similaire à sd_bus_error_set(), mais elle ne crée pas de copie dynamique du nom, supposant qu'il s'agit d'une chaîne littérale qui ne sera pas libérée pendant la durée de vie de la structure d'erreur.

Les fonctions sd_bus_error_set_errno(), sd_bus_error_set_errnof() et sd_bus_error_set_errnofv() sont similaires aux fonctions sd_bus_error_set() et sd_bus_error_setf(), mais elles prennent également un argument error_value qui est un entier de type errno. Ces fonctions essaieront de mapper cette valeur errno à un nom d'erreur D-Bus approprié. Si aucun mappage n'est trouvé, le nom d'erreur générique org.freedesktop.DBus.Error.Unknown sera utilisé. Notez que le mappage est extensible (voir sd_bus_error_add_map(3)).

La fonction sd_bus_error_get_errno() tente de mapper le nom d'erreur D-Bus stocké dans error->name à une valeur errno entière. S'il réussit, la valeur errno est écrite dans *error_value et un valeur positive est renvoyée. S'il échoue ou si la structure d'erreur est vide, 0 est renvoyé.

La fonction sd_bus_error_copy() copie le contenu d'une structure d'erreur src dans une structure d'erreur dst. Si dst contient déjà une erreur, elle sera vidée avant la copie. Cette fonction peut échouer avec -ENOMEM si une allocation de mémoire échoue.

La fonction sd_bus_error_move() est similaire à sd_bus_error_copy(), mais elle déplacera toutes les informations d'erreur de src vers dst, en réinitialisant la première. Cette fonction ne peut pas échouer, car aucune nouvelle mémoire n'est allouée. Notez que si src n'est pas définie, dst est initialisée à SD_BUS_ERROR_NULL. De plus, si dst est NULL, aucune opération n'est effectuée sur elle et les ressources détenues par src sont libérées et réinitialisées. Renvoie une valeur d'erreur non positive convertie de type errno.

La fonction sd_bus_error_is_set() renverra une valeur non nulle si error n'est pas NULL et qu'une erreur a été définie, sinon false.

La fonction sd_bus_error_has_name() renverra une valeur non nulle si error n'est pas NULL et qu'une erreur portant le même nom name a été définie, sinon false.

La fonction sd_bus_error_has_names_sentinel() est similaire à sd_bus_error_has_name(), mais prend plusieurs noms à vérifier. La liste doit être terminée par NULL. sd_bus_error_has_names() est un wrapper macro autour de sd_bus_error_has_names_sentinel() qui ajoute le sentinelle NULL automatiquement.

La fonction sd_bus_error_free() détruira les ressources détenues par error. Le paramètre lui-même ne sera pas désalloué et devra être libéré par l'appelant avec free(3) si nécessaire. La fonction peut également être appelée en toute sécurité sur des erreurs non définies (structures d'erreur avec les deux champs définis sur NULL), auquel cas elle n'effectue aucune opération. Cet appel réinitialisera la structure d'erreur après la libération des données, de sorte que tous les champs soient définis sur NULL. La structure peut être réutilisée par la suite.

PROPRIÉTÉ DES RÉFÉRENCES

sd_bus_error n'a pas de comptage de références. Les utilisateurs doivent détruire les ressources qu'elle détient en appelant sd_bus_error_free(). Généralement, les structures d'erreur sont allouées sur la pile ou passées en tant que paramètres de fonction, mais elles peuvent également être allouées dynamiquement, auquel cas il incombe à l'appelant de libérer la mémoire détenue par la structure elle-même après avoir libéré son contenu avec sd_bus_error_free().

VALEUR DE RETOUR

Les fonctions sd_bus_error_set(), sd_bus_error_setf() et sd_bus_error_set_const() renvoient toujours 0 lorsque la valeur d'erreur spécifiée est NULL, et une valeur d'erreur négative de type errno correspondant au paramètre name sinon. Les fonctions sd_bus_error_set_errno(), sd_bus_error_set_errnof() et sd_bus_error_set_errnofv() renvoient 0 lorsque la valeur d'erreur spécifiée est 0, et une valeur d'erreur négative de type errno correspondant au paramètre error sinon. Si une erreur survient en interne, l'une des valeurs d'erreur négatives listées ci-dessous sera renvoyée. Cela permet d'utiliser ces fonctions de manière pratique dans une instruction return, voir l'exemple ci-dessous.

La fonction sd_bus_error_get_errno() renvoie false lorsque error est NULL, et une valeur errno positive mappée à partir de error->name sinon.

Les fonctions sd_bus_error_copy() et sd_bus_error_move() renvoient une valeur d'erreur négative convertie de l'erreur source, et zéro si l'erreur n'a pas été définie. Cela permet d'utiliser ces fonctions de manière pratique dans une instruction return, voir l'exemple ci-dessous.

La fonction sd_bus_error_is_set() renvoie une valeur non nulle lorsque error et le champ name ne sont pas NULL, zéro sinon.

Les fonctions sd_bus_error_has_name(), sd_bus_error_has_names() et sd_bus_error_has_names_sentinel() renvoient une valeur non nulle lorsque error n'est pas NULL et que le champ name est égal à l'un des noms donnés, zéro sinon.

Erreurs

La valeur de retour peut indiquer les problèmes suivants dans l'appel de la fonction elle-même :

-EINVAL

L'erreur était déjà définie dans la structure sd_bus_error lorsqu'une des fonctions de définition d'erreur a été appelée.

-ENOMEM

L'allocation de mémoire a échoué.

En cas de succès, sd_bus_error_set(), sd_bus_error_setf(), sd_bus_error_set_const(), sd_bus_error_set_errno(), sd_bus_error_set_errnof(), sd_bus_error_set_errnofv(), sd_bus_error_copy() et sd_bus_error_move() renverront une valeur négative convertie de type errno, ou 0 si le paramètre d'erreur est NULL ou non défini. Les erreurs D-Bus sont converties en valeurs entières de type errno, et le mécanisme de mappage est extensible, voir la discussion ci-dessus. Cela signifie effectivement que presque toute valeur négative de type errno peut être renvoyée.

EXEMPLES

Exemple 1. Utilisation de la valeur de retour négative pour propager une erreur

/* SPDX-License-Identifier: MIT-0 */
#include <errno.h>
#include <string.h>
#include <unistd.h>
#include <systemd/sd-bus.h>
int writer_with_negative_errno_return(int fd, sd_bus_error *error) {
  const char *message = "Hello, World!\n";
  ssize_t n = write(fd, message, strlen(message));
  if (n >= 0)
    return n; /* En cas de succès, renvoyer le nombre d'octets écrits, éventuellement 0. */
  /* En cas d'erreur, initialiser la structure d'erreur, et également propager la valeur errno que write(2) a définie pour nous. */
  return sd_bus_error_set_errnof(error, errno, "Failed to write to fd %i: %s", fd, strerror(errno));
}

NOTES

Les fonctions décrites ici sont disponibles en tant que bibliothèque partagée, qui peut être compilée et liée avec le fichier pkg-config(1) de libsystemd.

Le code décrit ici utilise getenv(3), qui est déclaré comme n'étant pas sûr pour les appels multithread. Cela signifie que le code appelant les fonctions décrites ici ne doit pas appeler setenv(3) à partir d'un thread parallèle. Il est recommandé de n'effectuer des appels à setenv() que lors d'une phase précoce du programme, lorsque aucun autre thread n'a été démarré.
