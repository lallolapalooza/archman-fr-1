SD_BUS_MESSAGE_METHOD_RETURN(3)

SD_BUS_MESSAGE_METHOD_RETURN(3) sd_bus_message_new SD_BUS_MESSAGE_METHOD_RETURN(3)

NOM

sd_bus_message_new, sd_bus_message_ref, sd_bus_message_unref, sd_bus_message_unrefp, SD_BUS_MESSAGE_METHOD_CALL, SD_BUS_MESSAGE_METHOD_RETURN, SD_BUS_MESSAGE_METHOD_ERROR, SD_BUS_MESSAGE_SIGNAL, sd_bus_message_get_bus - Créer un objet de message de bus et créer ou détruire les références

SYNOPSIS

#include <systemd/sd-bus.h>
enum {
      SD_BUS_MESSAGE_METHOD_CALL,
      SD_BUS_MESSAGE_METHOD_RETURN,
      SD_BUS_MESSAGE_METHOD_ERROR,
      SD_BUS_MESSAGE_SIGNAL,
};

int sd_bus_message_new(sd_bus *bus, sd_bus_message **m, uint8_t type);

sd_bus_message *sd_bus_message_ref(sd_bus_message *m);

sd_bus_message *sd_bus_message_unref(sd_bus_message *m);

void sd_bus_message_unrefp(sd_bus_message **mp);

sd_bus *sd_bus_message_get_bus(sd_bus_message *m);

DESCRIPTION

sd_bus_message_new() crée un objet de message de bus associé au bus bus et le place dans le paramètre de sortie m. Cet objet est référencé et sera détruit lorsque toutes les références auront été supprimées. Initialement, l'appelant de cette fonction détient la seule référence à l'objet message. Notez : l'objet message détient une référence à l'objet bus, donc le bus ne sera pas détruit tant que le message existe.

Notez : il s'agit d'un appel de bas niveau. Dans la plupart des cas, les fonctions telles que sd_bus_message_new_method_call(3), sd_bus_message_new_method_error(3), sd_bus_message_new_method_return(3) et sd_bus_message_new_signal(3) qui créent un message d'un type donné et initialisent divers champs sont plus faciles à utiliser.

Le paramètre type spécifie le type du message. Il doit s'agir de l'un des suivants : SD_BUS_MESSAGE_METHOD_CALL — un appel de méthode, SD_BUS_MESSAGE_METHOD_RETURN — un retour de méthode, SD_BUS_MESSAGE_METHOD_ERROR — un retour d'erreur à un appel de méthode, SD_BUS_MESSAGE_SIGNAL — un message de notification sans retour.

Le drapeau d'autorisation interactive est initialisé en fonction de la valeur actuelle dans l'objet bus, voir sd_bus_set_allow_interactive_authorization(3). Ceci peut être modifié en utilisant sd_bus_message_set_allow_interactive_authorization(3).

sd_bus_message_ref() incrémente le compteur de références interne de m de un.

sd_bus_message_unref() décrémente le compteur de références interne de m de un. Une fois que le compteur est descendu à zéro, l'objet message est détruit et ne peut plus être utilisé ; par conséquent, les appels à sd_bus_message_ref() ou sd_bus_message_unref() sont illégaux.

sd_bus_message_unrefp() est similaire à sd_bus_message_unref() mais prend un pointeur vers un pointeur vers un objet sd_bus_message. Cet appel est utile lorsque vous utilisez l'attribut de variable de nettoyage [1]. Voir sd_bus_new(3) pour un exemple d'utilisation de l'attribut.

sd_bus_message_ref() et sd_bus_message_unref() n'effectuent aucune opération si l'objet message m est passé comme NULL. sd_bus_message_unrefp() déréférence d'abord son argument, qui doit être NULL, et n'effectue aucune opération si celui-ci est NULL.

sd_bus_message_get_bus() renvoie l'objet bus auquel le message m est associé.

VALEUR RENVOYÉE

En cas de succès, sd_bus_message_new() renvoie 0 ou une valeur positive. En cas d'erreur, il renvoie un code d'erreur de type -errno.

sd_bus_message_ref() renvoie toujours l'argument.

sd_bus_message_unref() renvoie toujours NULL.

sd_bus_message_get_bus() renvoie toujours l'objet bus.

Erreurs

Les erreurs renvoyées peuvent indiquer les problèmes suivants :

-EINVAL

Le type spécifié type est invalide.

-ENOTCONN

Le paramètre bus est NULL ou le bus n'est pas connecté.

-ENOMEM

Une allocation mémoire a échoué.

NOTES

Les fonctions décrites ici sont disponibles en tant que bibliothèque partagée, qui peut être compilée et liée avec le fichier libsystemd [1] en utilisant le fichier pkg-config(1).

Le code décrit ici utilise getenv(3), qui est déclaré non sécurisé pour le multi-threading. Cela signifie que le code appelant ces fonctions ne doit pas appeler setenv(3) à partir d'un fil d'exécution parallèle. Il est recommandé de n'appeler setenv() qu'à un moment précoce du programme lorsque aucun autre fil d'exécution n'a été lancé.

HISTORIQUE

sd_bus_message_new(), sd_bus_message_ref(), sd_bus_message_unref(), sd_bus_message_unrefp() et sd_bus_message_get_bus() ont été ajoutés dans la version 240.
