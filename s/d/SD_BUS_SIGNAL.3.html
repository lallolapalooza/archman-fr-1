Notez qu'une valeur entière positive peut être renvoyée à partir d'une fonction de rappel de type method sans envoyer immédiatement de réponse. Cela informe sd-bus que la fonction de rappel prendra la responsabilité de répondre à la requête sans forcer la fonction de rappel à produire une réponse immédiatement. Cela permet à une fonction de rappel d'effectuer le nombre d'opérations asynchrones nécessaires pour construire une réponse. Cependant, si la production d'une réponse prend trop de temps, l'appel de méthode expirera côté appelant. Ceci n'est disponible que pour les méthodes et non pour les propriétés.

Si une fonction de rappel a été appelée pour traiter une requête qui attend une réponse et que la fonction de rappel renvoie une valeur négative, la valeur est interprétée comme un code d'erreur négatif de style errno et renvoyée à l'appelant sous forme d'erreur D-Bus, comme si sd_bus_reply_method_errno(3) avait été appelée. De plus, toutes les fonctions de rappel acceptent un paramètre de sortie sd_bus_error qui peut être utilisé pour fournir des informations d'erreur plus détaillées. Si ret_error est défini lorsque la fonction de rappel se termine, l'erreur D-Bus correspondante est renvoyée à l'appelant, comme si sd_bus_reply_method_error(3) avait été appelée. Toute erreur stockée dans ret_error a priorité sur toute valeur négative renvoyée par la même fonction de rappel pour déterminer quelle erreur renvoyer à l'appelant. Utilisez sd_bus_error_set(3) ou l'une de ses variantes pour définir ret_error et renvoyer un entier négatif depuis une fonction de rappel avec un seul appel de fonction. Pour envoyer une réponse d'erreur après qu'une fonction de rappel a déjà terminé, utilisez sd_bus_reply_method_errno(3) ou l'une de ses variantes.

Pour toutes les fonctions, un slot de correspondance est créé en interne. Si le paramètre de sortie slot est NULL, un slot "flottant" est créé, voir sd_bus_slot_set_floating(3). Sinon, un pointeur vers l'objet slot est renvoyé. Dans ce cas, la référence à l'objet slot doit être libérée lorsque la table des méthodes (vtable) n'est plus nécessaire, voir sd_bus_slot_unref(3).

Le tableau sd_bus_vtable

Le tableau est constitué des structures de type sd_bus_vtable, mais il ne doit jamais être rempli manuellement, mais via l'une des macros suivantes :

SD_BUS_VTABLE_START(flags), SD_BUS_VTABLE_END

Celles-ci doivent toujours être le premier et le dernier élément. Le paramètre flags peut être utilisé pour définir des attributs qui s'appliquent à l'ensemble du tableau ; voir la section "Flags" ci-dessous.

SD_BUS_METHOD_WITH_ARGS_OFFSET(), SD_BUS_METHOD_WITH_ARGS()

Déclare une méthode D-Bus avec le nom member, les arguments args et le résultat result. args attend une séquence de paires type/nom d'arguments enveloppées dans la macro SD_BUS_ARGS(). Les éléments aux indices pairs de cette liste décrivent les types des arguments de la méthode. La signature de paramètre de la méthode est la concaténation de toutes les littéraux de chaîne aux indices pairs dans args. Si une méthode n'a pas de paramètres, passez SD_BUS_NO_ARGS à args. Les éléments aux indices impairs décrivent les noms des arguments de la méthode. result attend une séquence de paires type/nom enveloppées dans la macro SD_BUS_RESULT() dans le même format que SD_BUS_ARGS(). La signature du résultat de la méthode est la concaténation de toutes les littéraux de chaîne aux indices pairs dans result. Si une méthode n'a pas de résultat, passez SD_BUS_NO_RESULT à result. Notez que les types d'arguments doivent être des littéraux de chaîne entre guillemets et les noms d'arguments doivent être des littéraux de chaîne non entre guillemets. Voir ci-dessous pour un exemple complet.

La fonction de traitement handler doit être de type sd_bus_message_handler_t. Elle sera appelée pour traiter les messages entrants qui appellent cette méthode. Elle reçoit un pointeur qui est le paramètre userdata passé à la fonction d'enregistrement décalé de offset octets. Ceci peut être utilisé pour passer des pointeurs vers différents champs dans la même structure de données à différentes méthodes dans la même table des méthodes. Pour envoyer une réponse depuis handler, appelez sd_bus_reply_method_return(3) avec le message avec lequel la fonction de rappel a été appelée. Le paramètre flags est une combinaison de drapeaux, voir ci-dessous.

SD_BUS_METHOD_WITH_ARGS() est un raccourci pour appeler SD_BUS_METHOD_WITH_ARGS_OFFSET() avec un décalage de zéro.

SD_BUS_METHOD_WITH_NAMES_OFFSET(), SD_BUS_METHOD_WITH_NAMES(), SD_BUS_METHOD_WITH_OFFSET(), SD_BUS_METHOD()

Déclare une méthode D-Bus avec le nom member, la signature de paramètre signature, et la signature de résultat result. Les paramètres in_names et out_names spécifient les noms des arguments des arguments d'entrée et de sortie dans la signature de la fonction. in_names et out_names doivent être créés à l'aide de la macro SD_BUS_PARAM(), voir ci-dessous. À tous autres égards, cette macro se comporte exactement comme SD_BUS_METHOD_WITH_ARGS_OFFSET().

SD_BUS_METHOD_WITH_NAMES(), SD_BUS_METHOD_WITH_OFFSET() et SD_BUS_METHOD() sont des variantes qui spécifient un décalage nul (le paramètre userdata est passé sans modification), omettent les noms (c'est-à-dire aucun nom de paramètre), ou les deux.

Privilégiez l'utilisation de SD_BUS_METHOD_WITH_ARGS_OFFSET() et SD_BUS_METHOD_WITH_ARGS() par rapport à ces macros, car elles permettent de spécifier les types et les noms des arguments côte à côte, ce qui est moins sujet aux erreurs que de spécifier d'abord tous les types d'arguments, puis tous les noms d'arguments.

SD_BUS_SIGNAL_WITH_ARGS()

Déclare un signal D-Bus avec le nom member et les arguments args. args attend une séquence de paires type/nom d'arguments enveloppées dans la macro SD_BUS_ARGS(). Les éléments aux indices pairs de cette liste décrivent les types des arguments du signal. La signature de paramètre du signal est la concaténation de toutes les littéraux de chaîne aux indices pairs dans args. Si un signal n'a pas de paramètres, passez SD_BUS_NO_ARGS à args. Les éléments aux indices impairs décrivent les noms des arguments du signal. Le paramètre flags est une combinaison de drapeaux. Voir ci-dessous pour un exemple complet.

SD_BUS_SIGNAL_WITH_NAMES(), SD_BUS_SIGNAL()

Déclare un signal D-Bus avec le nom member, la signature de paramètre signature, et les noms d'arguments names. names doit être créé à l'aide de la macro SD_BUS_PARAM(), voir ci-dessous. Le paramètre flags est une combinaison de drapeaux, voir ci-dessous.

SD_BUS_SIGNAL() est équivalent à SD_BUS_SIGNAL_WITH_NAMES() avec le paramètre names omis (c'est-à-dire aucun nom de paramètre).

Privilégiez l'utilisation de SD_BUS_SIGNAL_WITH_ARGS() par rapport à ces macros, car elle permet de spécifier les types et les noms des arguments côte à côte, ce qui est moins sujet aux erreurs que de spécifier d'abord tous les types d'arguments, puis tous les noms d'arguments.

SD_BUS_WRITABLE_PROPERTY(), SD_BUS_PROPERTY()

Déclare une propriété D-Bus avec le nom member et la signature de valeur signature. Les paramètres get et set sont les méthodes de lecture et d'écriture. Elles sont appelées avec un pointeur qui est le paramètre userdata passé à la fonction d'enregistrement décalé de offset octets. Ceci peut être utilisé pour passer des pointeurs vers différents champs dans la même structure de données à différents accesseurs (setters/getters) dans la même table des méthodes. Le paramètre flags est une combinaison de drapeaux, voir ci-dessous.

Les méthodes d'écriture et de lecture peuvent être omises (spécifiées comme NULL), si la propriété est de type basique ou "as" dans le cas de propriétés en lecture seule. Dans ces cas, les paramètres userdata et offset doivent ensemble pointer vers une variable valide du type correspondant. Un accesseur (setter/getter) par défaut sera fourni, qui copiera simplement l'argument entre cette variable et le message.

SD_BUS_PROPERTY() est utilisé pour définir une propriété en lecture seule.

SD_BUS_PARAM()

Les noms de paramètres doivent être enveloppés dans cette macro, voir l'exemple ci-dessous.

Drapeaux

Le paramètre flags est utilisé pour spécifier une combinaison d'annotations D-Bus[1].

SD_BUS_VTABLE_DEPRECATED

Marque cette entrée de table des méthodes comme obsolète en utilisant l'annotation org.freedesktop.DBus.Deprecated dans les données d'introspection. Si spécifié pour SD_BUS_VTABLE_START(), l'annotation est appliquée à l'interface englobante.

SD_BUS_VTABLE_HIDDEN

Rend cette entrée de table des méthodes cachée. Elle ne sera pas affichée dans les données d'introspection. Si spécifié pour SD_BUS_VTABLE_START(), toutes les entrées du tableau sont cachées.

SD_BUS_VTABLE_METHOD_NO_REPLY

Marque cette entrée de table des méthodes comme une méthode qui ne renverra pas de réponse en utilisant l'annotation org.freedesktop.DBus.Method.NoReply dans les données d'introspection.

SD_BUS_VTABLE_PROPERTY_CONST, SD_BUS_VTABLE_PROPERTY_EMITS_CHANGE, SD_BUS_VTABLE_PROPERTY_EMITS_INVALIDATION

Ces trois drapeaux correspondent à différentes valeurs de l'annotation org.freedesktop.DBus.Property.EmitsChangedSignal, qui spécifie si le signal org.freedesktop.DBus.Properties.PropertiesChanged est émis chaque fois que la propriété change. SD_BUS_VTABLE_PROPERTY_CONST correspond à const et signifie que la propriété ne change jamais pendant la durée de vie de l'objet auquel elle appartient, donc aucun signal ne doit être émis. SD_BUS_VTABLE_PROPERTY_EMITS_CHANGE correspond à true et signifie que le signal est émis. SD_BUS_VTABLE_PROPERTY_EMITS_INVALIDATION correspond à invalidates et signifie que le signal est émis, mais que la valeur n'est pas incluse dans le signal.

SD_BUS_VTABLE_PROPERTY_EXPLICIT

Marque cette entrée de propriété de table des méthodes comme nécessitant une demande explicite pour que la valeur soit affichée (généralement parce que la valeur est volumineuse ou lente à calculer). Cette entrée ne peut pas être combinée avec SD_BUS_VTABLE_PROPERTY_EMITS_CHANGE, et ne sera pas affichée dans les listes de propriétés par défaut (par exemple, busctl introspect). Ceci correspond à l'annotation org.freedesktop.systemd1.Explicit dans les données d'introspection.

SD_BUS_VTABLE_SENSITIVE

Marque cette entrée de méthode de table des méthodes comme traitant des données sensibles. Lorsqu'il est défini, les messages d'appel de méthode entrants et leurs messages de réponse sortants sont marqués comme sensibles en utilisant sd_bus_message_sensitive(3), de sorte qu'ils soient effacés de la mémoire lorsqu'ils sont libérés.

Mantén toda la estructura del archivo.
L'accès à cette entrée de vtable sera autorisé si le processus appelant possède la capacité capability, comme décrit dans sd_bus_query_sender_privilege(3). Si elle est utilisée pour SD_BUS_VTABLE_START(), elle fournit une valeur par défaut pour toutes les entrées du tableau. Si elle n'est pas spécifiée, CAP_SYS_ADMIN est vérifiée par défaut pour chaque entrée individuelle ou pour le tableau entier. Voir capabilities(7) pour plus d'informations sur les capacités.

#define _GNU_SOURCE 1
#include <errno.h>
#include <stdbool.h>
#include <stddef.h>
#include <stdlib.h>
#include <stdio.h>
#include <systemd/sd-bus.h>
#define _cleanup_(f) __attribute__((cleanup(f)))
typedef struct object {
  char *name;
  uint32_t number;
} object;
static int method(sd_bus_message *m, void *userdata, sd_bus_error *error) {
  int r;
  printf("Got called with userdata=%p\n", userdata);
  if (sd_bus_message_is_method_call(m,
                                    "org.freedesktop.systemd.VtableExample",
                                    "Method4"))
    return 1;
  const char *string;
  r = sd_bus_message_read(m, "s", &string);
  if (r < 0) {
    fprintf(stderr, "sd_bus_message_read() failed: %s\n", strerror(-r));
    return 0;
  }
  r = sd_bus_reply_method_return(m, "s", string);
  if (r < 0) {
    fprintf(stderr, "sd_bus_reply_method_return() failed: %s\n", strerror(-r));
    return 0;
  }
  return 1;
}
static const sd_bus_vtable vtable[] = {
        SD_BUS_VTABLE_START(0),
        SD_BUS_METHOD(
            "Method1", "s", "s", method, 0),
        SD_BUS_METHOD_WITH_NAMES_OFFSET(
            "Method2",
            "so", SD_BUS_PARAM(string) SD_BUS_PARAM(path),
            "s", SD_BUS_PARAM(returnstring),
            method, offsetof(object, number),
            SD_BUS_VTABLE_DEPRECATED),
        SD_BUS_METHOD_WITH_ARGS_OFFSET(
            "Method3",
            SD_BUS_ARGS("s", string, "o", path),
            SD_BUS_RESULT("s", returnstring),
            method, offsetof(object, number),
            SD_BUS_VTABLE_UNPRIVILEGED),
        SD_BUS_METHOD_WITH_ARGS(
            "Method4",
            SD_BUS_NO_ARGS,
            SD_BUS_NO_RESULT,
            method,
            SD_BUS_VTABLE_UNPRIVILEGED),
        SD_BUS_SIGNAL(
            "Signal1",
            "so",
            0),
        SD_BUS_SIGNAL_WITH_NAMES(
            "Signal2",
            "so", SD_BUS_PARAM(string) SD_BUS_PARAM(path),
            0),
        SD_BUS_SIGNAL_WITH_ARGS(
            "Signal3",
            SD_BUS_ARGS("s", string, "o", path),
            0),
        SD_BUS_WRITABLE_PROPERTY(
            "AutomaticStringProperty", "s", NULL, NULL,
            offsetof(object, name),
            SD_BUS_VTABLE_PROPERTY_EMITS_CHANGE),
        SD_BUS_WRITABLE_PROPERTY(
            "AutomaticIntegerProperty", "u", NULL, NULL,
            offsetof(object, number),
            SD_BUS_VTABLE_PROPERTY_EMITS_INVALIDATION),

  int r;
  sd_bus_default(&bus);
  object object = { .number = 666 };
  object.name = strdup("name");
  if (!object.name) {
    fprintf(stderr, "OOM\n");
    return EXIT_FAILURE;
  }
  r = sd_bus_add_object_vtable(bus, NULL,
                               "/org/freedesktop/systemd/VtableExample",
                               "org.freedesktop.systemd.VtableExample",
                               vtable,
                               &object);
  if (r < 0) {
    fprintf(stderr, "sd_bus_add_object_vtable() failed: %s\n", strerror(-r));
    return EXIT_FAILURE;
  }
  r = sd_bus_request_name(bus,
                          "org.freedesktop.systemd.VtableExample",
                          0);
  if (r < 0) {
    fprintf(stderr, "sd_bus_request_name() failed: %s\n", strerror(-r));
    return EXIT_FAILURE;
  }
  for (;;) {
    r = sd_bus_wait(bus, UINT64_MAX);
    if (r < 0) {
      fprintf(stderr, "sd_bus_wait() failed: %s\n", strerror(-r));
      return EXIT_FAILURE;
    }
    r = sd_bus_process(bus, NULL);
    if (r < 0) {
      fprintf(stderr, "sd_bus_process() failed: %s\n", strerror(-r));
      return EXIT_FAILURE;
    }
  }
  r = sd_bus_release_name(bus, "org.freedesktop.systemd.VtableExample");
  if (r < 0) {
    fprintf(stderr, "sd_bus_release_name() failed: %s\n", strerror(-r));
    return EXIT_FAILURE;
  }
  free(object.name);
  return 0;
}

Valeur de retour

En cas de succès, sd_bus_add_object_vtable() et sd_bus_add_fallback_vtable() renvoient un entier non négatif. En cas d'erreur, ils renvoient un code d'erreur négatif.

Erreurs

Les erreurs renvoyées peuvent indiquer les problèmes suivants :

-EINVAL

Un paramètre requis est NULL ou invalide. Une interface D-Bus réservée a été passée comme valeur pour interface.

-ENOPKG

Le bus ne peut pas être résolu.

-ECHILD

Le bus a été créé dans un processus, une bibliothèque ou un module différent.

-ENOMEM

Échec de l'allocation de mémoire.

-EPROTOTYPE

sd_bus_add_object_vtable() et sd_bus_add_fallback_vtable() ont été appelés pour le même objet de bus, ce qui n'est pas autorisé.

-EEXIST

Cette vtable a déjà été enregistrée pour cette interface et ce path.
