NOM

SSL_new_domain, SSL_is_domain, SSL_get0_domain - Interface de l'objet SSL pour la gestion des domaines d'événements QUIC

SYNOPSIS

#include <openssl/ssl.h>
SSL *SSL_new_domain(SSL_CTX *ctx, uint64_t flags);
int SSL_is_domain(SSL *ssl);
SSL *SSL_get0_domain(SSL *ssl);

DESCRIPTION

La fonction SSL_new_domain() crée un nouveau domaine d'événements QUIC, représenté sous forme d'objet SSL. C'est ce qu'on appelle un objet SSL de domaine QUIC (QDSO). Le concept de domaine d'événements QUIC est discuté en détail dans openssl-quic-concurrency(7).

L'argument flags de SSL_new_domain() spécifie un ensemble de drapeaux de domaine. Si l'argument flags de SSL_new_domain() ne spécifie pas l'un des drapeaux SSL_DOMAIN_FLAG_SINGLE_THREAD, SSL_DOMAIN_FLAG_MULTI_THREAD ou SSL_DOMAIN_FLAG_THREAD_ASSISTED, les drapeaux de domaine configurés sur le SSL_CTX sont hérités par défaut et tous les autres drapeaux dans flags sont ajoutés à l'ensemble des drapeaux hérités. Sinon, les drapeaux de domaine dans flags sont utilisés. Voir SSL_CTX_set_domain_flags(3) pour les détails des drapeaux de domaine disponibles et comment ils peuvent être configurés sur un SSL_CTX.

Un objet SSL de domaine QUIC peut être géré de la même manière que tout autre objet SSL, en ce sens qu'il peut être compté en références et libéré normalement. Un objet SSL de domaine QUIC est le parent d'un certain nombre d'objets enfants tels que les objets SSL d'écoute QUIC. Une fois qu'un objet SSL de domaine QUIC a été créé, un écouteur peut être créé sous celui-ci en utilisant SSL_new_listener_from(3).

SSL_is_domain() renvoie 1 si un objet SSL est un objet SSL de domaine QUIC.

SSL_get0_domain() obtient un pointeur vers l'objet SSL de domaine QUIC dans une hiérarchie d'objets SSL (le cas échéant).

Tous les objets SSL d'un domaine d'événements QUIC utilisent les mêmes drapeaux de domaine, et les drapeaux de domaine d'un domaine QUIC ne peuvent pas être modifiés après la construction.

Opérations supportées

Un objet SSL de domaine QUIC existe pour contenir d'autres objets SSL QUIC et fournir une gestion unifiée des événements. Par conséquent, il ne prend en charge que les opérations suivantes :

  • Comptage de références standard et opérations de libération, telles que SSL_up_ref(3) et SSL_free(3) ;
  • APIs d'activation du traitement des événements et de sondage telles que SSL_handle_events(3), et SSL_get_event_timeout(3).
  • Création d'écouteurs sous le domaine en utilisant SSL_new_listener_from(3).

Le flux de travail de base de l'utilisation d'un objet de domaine est le suivant :

  • Créer un nouvel objet de domaine en utilisant SSL_new_domain() avec un SSL_CTX qui utilise une SSL_METHOD prise en charge (telle que OSSL_QUIC_server_method(3)) ;
  • Créer des écouteurs sous le domaine en utilisant SSL_new_listener_from(3).

Référez-vous à SSL_new_listener_from(3) pour les détails sur l'utilisation des écouteurs.

Actuellement, les objets SSL de domaine ne sont pris en charge que pour l'utilisation QUIC via toute SSL_METHOD QUIC.

VALEURS DE RETOUR

SSL_new_domain() renvoie un nouvel objet SSL de domaine ou NULL en cas d'échec.

SSL_is_domain() renvoie 0 ou 1 en fonction du type de l'objet SSL sur lequel il est appelé.

SSL_get0_domain() renvoie un pointeur d'objet SSL (potentiellement vers le même objet sur lequel il est appelé) ou NULL.

VOIR AUSSI

SSL_new_listener_from(3) SSL_handle_events(3), SSL_CTX_set_domain_flags(3), openssl-quic-concurrency(7)

HISTORIQUE

Ces fonctions ont été ajoutées dans OpenSSL 3.5.
