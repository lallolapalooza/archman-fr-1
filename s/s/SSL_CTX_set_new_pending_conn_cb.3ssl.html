SSL_CTX_set_new_pending_conn_cb(3ssl)

Paquet: openssl

Licences: Apache-2.0

SSL_CTX_SET_NEW_PENDING_CONN_CB(3ssl) OpenSSL SSL_CTX_SET_NEW_PENDING_CONN_CB(3ssl)

NOM

SSL_CTX_set_new_pending_conn_cb, SSL_set_new_pending_conn_cb_fn - fonction de rappel pour signaler la création d'objets SSL de connexion QUIC

SYNTAXE

typedef int (*SSL_set_new_pending_conn_cb_fn)(SSL_CTX *c, SSL *new_ssl,
                                              void *arg);
void SSL_CTX_set_new_pending_conn_cb(SSL_CTX *c,
                                    SSL_set_new_pending_conn_cb_fn *f,
                                    void *arg);

DESCRIPTION

SSL_CTX_set_new_pending_conn_cb() définit la fonction de rappel new_pending_conn et l'argument de données d'application associé arg. Lors de l'utilisation du transport QUIC, le traitement de la poignée de main TLS peut se produire indépendamment du thread qui accepte la connexion que la poignée de main établit. À ce titre, des objets SSL représentant la connexion peuvent être alloués et initialisés avant un appel à SSL_accept_connection(). Ce rappel enregistré peut être utilisé pour décorer l'objet SSL préalloué ou créer d'autres associations avec son SSL parent avant un appel à SSL_accept_connection().

VALEURS DE RETOUR

SSL_CTX_set_new_pending_conn_cb() ne retourne aucune valeur.

SSL_set_new_pending_conn_cb_fn() retourne une valeur entière. Une valeur de retour de 0 indique que la pile QUIC doit rejeter cet objet SSL nouvellement créé, ce qui implique que la nouvelle connexion associée ne sera pas disponible pour le traitement lors d'un appel ultérieur à SSL_accept_connection(). Une valeur de retour non nulle est traitée comme un succès, permettant à la nouvelle connexion d'être mise en file d'attente d'acceptation.

VOIR AUSSI

SSL_set_ex_data(3)

NOTES

Les rappels dans les connexions QUIC ont certaines limitations qui devraient être prises en considération lors de l'écriture d'une application.

Les connexions QUIC peuvent commencer à être traitées avant que l'application n'appelle SSL_accept_connection(). Par conséquent, il peut arriver que des rappels soient livrés aux rappels TLS enregistrés par les applications avant que ces objets SSL ne soient retournés dans SSL_accept_connection(). Les applications doivent s'attendre à cette possibilité.

En particulier, aucune référence ne doit être conservée sur les objets SSL passés aux rappels pour les connexions QUIC jusqu'à ce qu'ils soient retournés via un appel à SSL_accept_connection.

HISTORIQUE

SSL_CTX_set_new_pending_conn_cb() a été ajouté dans OpenSSL 3.5
