SSL_get_peer_signature_nid(3ssl)

Paquet: openssl

Licences: Apache-2.0

SSL_GET_PEER_SIGNATURE_NID(3ssl) OpenSSL SSL_GET_PEER_SIGNATURE_NID(3ssl)

NOM

SSL_get0_peer_signature_name, SSL_get_peer_signature_nid, SSL_get_peer_signature_type_nid, SSL_get0_signature_name, SSL_get_signature_nid, SSL_get_signature_type_nid - obtenir les types de signature TLS

SYNTAXE

#include <openssl/ssl.h>
int SSL_get0_peer_signature_name(const SSL *ssl, const char **sigalg);
int SSL_get_peer_signature_nid(SSL *ssl, int *psig_nid);
int SSL_get_peer_signature_type_nid(const SSL *ssl, int *psigtype_nid);
int SSL_get0_signature_name(SSL *ssl, const char **sigalg);
int SSL_get_signature_nid(SSL *ssl, int *psig_nid);
int SSL_get_signature_type_nid(const SSL *ssl, int *psigtype_nid);

DESCRIPTION

SSL_get0_peer_signature_name() définit *sigalg sur le nom IANA du schéma de signature https://www.iana.org/assignments/tls-parameters/tls-parameters.xhtml#tls-signaturescheme utilisé par le pair pour signer la poignée de main TLS. L'appelant ne doit pas libérer le pointeur retourné. La chaîne retournée doit être copiée si elle doit être conservée au-delà de la durée de vie de la connexion SSL.

SSL_get_peer_signature_nid() définit *psig_nid sur le NID du digest utilisé par le pair pour signer les messages TLS. Il est implémenté comme une macro.

SSL_get_peer_signature_type_nid() définit *psigtype_nid sur le type de signature utilisé par le pair pour signer les messages TLS. Actuellement, le type de signature est le NID du type de clé publique utilisé pour la signature, sauf pour la signature PSS où c'est EVP_PKEY_RSA_PSS. Pour différencier entre les signatures rsa_pss_rsae_* et rsa_pss_pss_*, il est nécessaire de vérifier le type de clé publique dans le certificat du pair.

SSL_get0_signature_name(), SSL_get_signature_nid() et SSL_get_signature_type_nid() retournent les informations équivalentes pour l'extrémité locale de la connexion.

VALEUR DE RETOUR

Ces fonctions retournent 1 en cas de succès et 0 en cas d'échec. Il existe plusieurs raisons possibles d'échec : le pair ou l'extrémité locale est un client et n'a pas signé la poignée de main (n'a pas utilisé de certificat client), la suite de chiffrements n'a pas de signature (par exemple, elle utilise un échange de clés RSA ou est anonyme), la version TLS est antérieure à 1.2 ou les fonctions ont été appelées trop tôt, par exemple, avant que le pair n'ait signé un message.

VOIR AUSSI

ssl(7), SSL_get_peer_certificate(3),

HISTORIQUE

Les fonctions SSL_get0_peer_signature_name() et SSL_get0_signature_name() ont été ajoutées dans OpenSSL 3.5.

SSL_get_signature_nid() a été ajoutée dans OpenSSL 1.1.1a.
