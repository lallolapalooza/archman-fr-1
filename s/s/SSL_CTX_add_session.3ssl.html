NOM

SSL_CTX_add_session, SSL_CTX_remove_session - manipuler le cache de sessions

SYNTAXE

#include <openssl/ssl.h>
int SSL_CTX_add_session(SSL_CTX *ctx, SSL_SESSION *c);
int SSL_CTX_remove_session(SSL_CTX *ctx, SSL_SESSION *c);

DESCRIPTION

SSL_CTX_add_session() ajoute la session c au contexte ctx. Le compteur de références de la session c est incrémenté de 1. Si une session avec le même ID de session existe déjà, l'ancienne session est supprimée en appelant SSL_SESSION_free(3).

SSL_CTX_remove_session() supprime la session c du contexte ctx et la marque comme non-reprise. SSL_SESSION_free(3) est appelée une fois pour c.

NOTES

Lors de l'ajout d'une nouvelle session au cache de sessions interne, il est vérifié si une session avec le même ID de session existe déjà. Dans ce cas, on suppose que les deux sessions sont identiques. Si la même session est stockée dans un objet SSL_SESSION différent, l'ancienne session est supprimée et remplacée par la nouvelle session. Si la session est effectivement identique (l'objet SSL_SESSION est identique), SSL_CTX_add_session() ne fait rien et la valeur de retour est 0.

Si un SSL_CTX serveur est configuré avec le drapeau SSL_SESS_CACHE_NO_INTERNAL_STORE, le cache interne ne sera pas automatiquement rempli par les nouvelles sessions négociées par l'implémentation SSL/TLS, bien que le cache interne soit automatiquement recherché pour les demandes de reprise de session (ce dernier peut être supprimé par SSL_SESS_CACHE_NO_INTERNAL_LOOKUP). L'application peut donc utiliser SSL_CTX_add_session() directement pour avoir un contrôle total sur les sessions qui peuvent être reprises si désiré.

VALEURS DE RETOUR

Les valeurs suivantes sont retournées par toutes les fonctions :

0
L'opération a échoué. Dans le cas de l'opération d'ajout, on a essayé d'ajouter la même session (identique) deux fois. Dans le cas de l'opération de suppression, la session n'a pas été trouvée dans le cache.
1
L'opération a réussi.
