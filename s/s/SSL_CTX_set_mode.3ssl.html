SSL_CTX_set_mode(3ssl) OpenSSL SSL_CTX_set_mode(3ssl)

NAME

SSL_CTX_set_mode, SSL_CTX_clear_mode, SSL_set_mode, SSL_clear_mode, SSL_CTX_get_mode, SSL_get_mode - modifier le mode du moteur SSL

SYNOPSIS

#include <openssl/ssl.h>
long SSL_CTX_set_mode(SSL_CTX *ctx, long mode);
long SSL_CTX_clear_mode(SSL_CTX *ctx, long mode);
long SSL_set_mode(SSL *ssl, long mode);
long SSL_clear_mode(SSL *ssl, long mode);
long SSL_CTX_get_mode(SSL_CTX *ctx);
long SSL_get_mode(SSL *ssl);

DESCRIPTION

SSL_CTX_set_mode() ajoute le mode spécifié par le masque de bits dans mode à ctx. Les modes déjà définis avant sont ignorés. SSL_CTX_clear_mode() supprime le mode spécifié par le masque de bits dans mode de ctx.

SSL_set_mode() ajoute le mode spécifié par le masque de bits dans mode à ssl. Les modes déjà définis avant sont ignorés. SSL_clear_mode() supprime le mode spécifié par le masque de bits dans mode de ssl.

SSL_CTX_get_mode() renvoie le mode défini dans ctx.

SSL_get_mode() renvoie le mode défini dans ssl.

NOTES

Les modifications de mode suivantes sont disponibles:

SSL_MODE_ENABLE_PARTIAL_WRITE
Permettre à SSL_write_ex(..., n, &r) de retourner avec 0 < r < n (c'est-à-dire signaler le succès lorsque seule une partie d'un enregistrement a été écrite). Ceci fonctionne de manière similaire pour SSL_write(). Lorsque ce mode n'est pas activé (par défaut), SSL_write_ex() ou SSL_write() ne signaleront le succès qu'une fois que le bloc complet a été écrit. Une fois que SSL_write_ex() ou SSL_write() renvoie le succès, r octets ont été envoyés et l'appel suivant à SSL_write_ex() ou SSL_write() doit envoyer les n-r octets restants, imitant le comportement de write().

Ce mode ne peut pas être activé pendant une opération d'écriture incomplète en cours.

SSL_MODE_ACCEPT_MOVING_WRITE_BUFFER
Permettre de ré-essayer SSL_write_ex() ou SSL_write() avec un emplacement de tampon différent (le contenu du tampon doit rester identique). Ce n'est pas le comportement par défaut afin d'éviter toute confusion où SSL_write() non bloquant se comporterait comme write() non bloquant.
SSL_MODE_AUTO_RETRY
Les enregistrements de données non appliqués peuvent devoir être envoyés ou reçus par l'application, mais l'application n'en est pas consciente. Si un enregistrement de données non appliqué a été traité, SSL_read_ex(3) et SSL_read(3) peuvent retourner une erreur et indiquer la nécessité de réessayer avec SSL_ERROR_WANT_READ. Si un enregistrement de données non appliqué a été traité, le drapeau SSL_MODE_AUTO_RETRY tentera de traiter l'enregistrement suivant au lieu de retourner.

Dans un environnement non bloquant, les programmes doivent être prêts à gérer les opérations de lecture/écriture incomplètes. Définir SSL_MODE_AUTO_RETRY sur un BIO non bloquant traitera les enregistrements de données non appliqués jusqu'à ce qu'il n'y ait plus de données ou qu'un enregistrement de données appliqué ait été traité.

Dans un environnement bloquant, les programmes ne sont pas toujours préparés à gérer les fonctions qui renvoient des indications intermédiaires comme des demandes de réessai, et la définition du drapeau SSL_MODE_AUTO_RETRY entraînera le retour des fonctions seulement après le traitement d'un enregistrement de données appliqué ou d'un échec.

Désactiver SSL_MODE_AUTO_RETRY peut être utile avec les BIO bloquants si ceux-ci sont utilisés en combinaison avec quelque chose comme select() ou poll(). Sinon, l'appel à SSL_read() ou SSL_read_ex() pourrait attendre indéfiniment lorsqu'un enregistrement de données non appliqué a été envoyé et qu'aucun enregistrement de données appliqué n'a été envoyé.

SSL_MODE_RELEASE_BUFFERS
Une fois qu'un tampon de lecture ou d'écriture n'est plus nécessaire pour un SSL donné, la mémoire utilisée pour le stocker sera libérée. L'utilisation de ce drapeau peut économiser environ 34 Ko par connexion SSL vide. Ce drapeau n'a aucun effet sur les connexions SSL v2 ou les connexions DTLS.
SSL_MODE_SEND_FALLBACK_SCSV
Envoyer SSL_FALLBACK_SCSV dans le ClientHello. Ceci ne doit être activé que par les applications qui se reconnectent avec une version de protocole dégradée ; voir draft-ietf-tls-downgrade-scsv-00 pour plus de détails.

N'activez PAS CE MODE si votre application tente un handshake normal. Il ne doit être utilisé que lors de réessais explicites suivant les instructions de draft-ietf-tls-downgrade-scsv-00.

SSL_MODE_ASYNC
Activer le traitement asynchrone. Les opérations d'E/S TLS peuvent indiquer une demande de réessai avec SSL_ERROR_WANT_ASYNC si un moteur capable de traiter de manière asynchrone pour les opérations cryptographiques est utilisé. Voir SSL_get_error(3).
SSL_MODE_DTLS_SCTP_LABEL_LENGTH_BUG
Les anciennes versions d'OpenSSL présentaient un bug dans le calcul de la longueur de l'étiquette utilisée pour calculer le secret partagé entre les points d'extrémité. Le bug consistait à inclure un caractère nul de fin dans la longueur de l'étiquette. L'activation de cette option permet l'interopérabilité avec des implémentations de ce type. Veuillez noter que l'activation de cette option casse l'interopérabilité avec les implémentations correctes. Cette option ne s'applique qu'aux connexions DTLS sur SCTP.

Tous les modes sont désactivés par défaut, à l'exception de SSL_MODE_AUTO_RETRY qui est activé par défaut depuis la version 1.1.1.

VALEURS DE RETOUR

SSL_CTX_set_mode() et SSL_set_mode() renvoient le nouveau masque de bits du mode après l'ajout de mode.

SSL_CTX_get_mode() et SSL_get_mode() renvoient le masque de bits actuel.

VOIR AUSSI

ssl(7), SSL_read_ex(3), SSL_read(3), SSL_write_ex(3) ou SSL_write(3), SSL_get_error(3)

HISTORIQUE

SSL_MODE_ASYNC a été ajouté dans OpenSSL 1.1.0.

SSL_CTX_set_mode(3ssl)

SSL_CTX_set_mode - modifie le mode de la structure SSL_CTX

NAME

SSL_CTX_set_mode, SSL_CTX_get_mode, SSL_set_mode, SSL_get_mode - modifie le mode de la structure SSL_CTX ou SSL

SYNOPSIS

#include <openssl/ssl.h>

long SSL_CTX_set_mode(SSL_CTX *ctx, long mode);
long SSL_CTX_get_mode(const SSL_CTX *ctx);
long SSL_set_mode(SSL *ssl, long mode);
long SSL_get_mode(const SSL *ssl);

DESCRIPTION

SSL_CTX_set_mode() active les modes spécifiés par le paramètre mode pour la structure ctx.

Les modes sont un ensemble de drapeaux de bits, qui sont OR-és avec les modes existants.

SSL_CTX_get_mode() renvoie les modes actuellement activés pour ctx.

SSL_set_mode() active les modes spécifiés par le paramètre mode pour la structure ssl.

SSL_get_mode() renvoie les modes actuellement activés pour ssl.

Les modes suivants sont définis :

SSL_MODE_AUTO_RETRY
Si une opération d'E/S renvoie SSL_ERROR_WANT_READ ou SSL_ERROR_WANT_WRITE, des tentatives répétées d'E/S seront effectuées jusqu'à ce que l'opération soit terminée ou qu'une autre erreur se produise. Ceci est utile pour masquer le comportement des E/S bloquantes pour certaines applications. La valeur par défaut est de ne pas effectuer de nouvelles tentatives.
SSL_MODE_ACCEPT_MOVING_V2
Si ce mode est activé, la bibliothèque est autorisée à accepter les négations de version TLSv1.3 qui se produisent lors de l'établissement d'une connexion TLSv1.2. Cela peut être nécessaire pour interagir avec certaines implémentations de serveurs TLSv1.3 plus anciennes. La valeur par défaut est de ne pas autoriser cela.
SSL_MODE_ENABLE_PARTIAL_WRITE
Si ce mode est activé, SSL_write() peut renvoyer un nombre d'octets écrits inférieur au nombre demandé. Cela permet aux applications d'utiliser SSL_write() avec des tampons qui ne correspondent pas aux tailles des enregistrements TLS. La valeur par défaut est de ne pas permettre cela.
SSL_MODE_FAIL_SERVER_HELLO_V2
Si ce mode est activé, une négation de version TLSv1.3 qui se produit lors de l'établissement d'une connexion TLSv1.2 entraînera un échec de la négociation. Cela peut être nécessaire pour interagir avec certaines implémentations de serveurs TLSv1.3 plus anciennes. La valeur par défaut est de ne pas échouer dans ce cas.
SSL_MODE_Release_BUFFERS
Si ce mode est activé, les tampons sont libérés après chaque appel à SSL_shutdown(). Ceci peut être utilisé pour réduire l'utilisation de la mémoire, mais peut avoir un impact sur les performances si plusieurs connexions doivent être établies. La valeur par défaut est de ne pas libérer les tampons.
SSL_MODE_SEND_FALLBACK_SCSV
Si ce mode est activé, les clients et les serveurs enverront le code SCSV de repli (RFC 7633) lors de l'établissement de connexions TLSv1.2. Cela permet de détecter et de prévenir les attaques de repli. La valeur par défaut est de ne pas envoyer le SCSV de repli.
SSL_MODE_SIGNATURE_ALL
Si ce mode est activé, les clients et les serveurs signeront toutes les données d'authentification du serveur avec la clé privée du serveur. Ceci est une mesure de sécurité supplémentaire pour prévenir les attaques par falsification. La valeur par défaut est de ne pas signer toutes les données.
SSL_MODE_TLSEXT_PADDING
Si ce mode est activé, le remplissage TLSv1.3 sera utilisé lors de l'établissement de connexions TLSv1.2. Cela peut améliorer la sécurité en masquant les différences de taille des enregistrements TLS. La valeur par défaut est de ne pas utiliser le remplissage TLSv1.3.
SSL_MODE_USE_ెరLS
Si ce mode est activé, les extensions ECP et ER existantes seront prises en charge. Ceci permet l'utilisation de l'échange de clés elliptiques (ECP) et du chiffrement et déchiffrement récupérables (ER) lors de l'établissement de connexions TLSv1.2. La valeur par défaut est de ne pas autoriser cela.
SSL_MODE_VALIDATE_SERVER_CERTIFICATE
Si ce mode est activé, les certificats des serveurs seront validés. Ceci est une mesure de sécurité importante pour s'assurer que le serveur est authentique. La valeur par défaut est de ne pas valider les certificats des serveurs.
SSL_MODE_VERIFY_PEER
Si ce mode est activé, les certificats des pairs seront vérifiés. Ceci est une mesure de sécurité importante pour s'assurer que le pair est authentique. La valeur par défaut est de ne pas vérifier les certificats des pairs.

RETURN VALUES

SSL_CTX_set_mode() et SSL_set_mode() renvoient les modes précédents activés pour ctx ou ssl.
