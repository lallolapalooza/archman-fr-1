SSL_CTX_set_info_callback(3ssl) OpenSSL SSL_CTX_set_info_callback(3ssl)

NOM

SSL_CTX_set_info_callback, SSL_CTX_get_info_callback, SSL_set_info_callback, SSL_get_info_callback - gérer le callback d'informations pour les connexions SSL

SYNTAXE

#include <openssl/ssl.h>
void SSL_CTX_set_info_callback(SSL_CTX *ctx,
                               void (*callback) (const SSL *ssl, int type, int val));
void (*SSL_CTX_get_info_callback(SSL_CTX *ctx)) (const SSL *ssl, int type, int val);
void SSL_set_info_callback(SSL *ssl,
                           void (*callback) (const SSL *ssl, int type, int val));
void (*SSL_get_info_callback(const SSL *ssl)) (const SSL *ssl, int type, int val);

DESCRIPTION

SSL_CTX_set_info_callback() définit la fonction de rappel, qui peut être utilisée pour obtenir des informations sur l'état des objets SSL créés à partir de ctx pendant l'établissement et l'utilisation de la connexion. La valeur de ctx est écrasée si une valeur est spécifiée pour ssl. Lorsque callback est NULL, aucune fonction de rappel n'est utilisée.

SSL_set_info_callback() définit la fonction de rappel, qui peut être utilisée pour obtenir des informations sur l'état de ssl pendant l'établissement et l'utilisation de la connexion. Lorsque callback est NULL, la valeur actuelle de ctx est utilisée. ssl NE DOIT PAS être NULL.

SSL_CTX_get_info_callback() retourne un pointeur vers la fonction de rappel d'informations actuellement définie pour ctx.

SSL_get_info_callback() retourne un pointeur vers la fonction de rappel d'informations actuellement définie pour ssl.

NOTES

Lors de l'établissement d'une connexion et pendant son utilisation, il est possible d'obtenir des informations sur l'état des objets SSL/TLS du moteur. Lorsqu'elle est active, une fonction de rappel est appelée lorsqu'un événement significatif se produit, tel qu'un changement d'état, une alerte ou une erreur.

La fonction de rappel est appelée comme suit : callback(SSL *ssl, int where, int ret). L'argument where spécifie des informations sur l'endroit (dans quel contexte) la fonction de rappel a été appelée. Si ret est 0, un état d'erreur s'est produit. Si une alerte a été traitée, la valeur SSL_CB_ALERT est définie et ret spécifie les informations sur l'alerte.

where est un masque de bits composé des bits suivants :

SSL_CB_LOOP
La fonction de rappel a été appelée pour indiquer un changement d'état ou un événement significatif dans la machine à états. Cela peut signifier que la fonction de rappel est invoquée plus d'une fois par état dans certains cas.
SSL_CB_EXIT
La fonction de rappel a été appelée pour indiquer la sortie d'une fonction de handshake. Cela se produira après la fin d'un handshake, mais peut se produire à d'autres moments, par exemple en cas d'erreur ou lorsque l'E/S peut bloquer et que le mode non bloquant est utilisé.
SSL_CB_READ
La fonction de rappel a été appelée pendant une opération de lecture.
SSL_CB_WRITE
La fonction de rappel a été appelée pendant une opération d'écriture.
SSL_CB_ALERT
La fonction de rappel a été appelée en raison d'une alerte envoyée ou reçue.
SSL_CB_READ_ALERT (SSL_CB_ALERT|SSL_CB_READ)
SSL_CB_WRITE_ALERT (SSL_CB_ALERT|SSL_CB_WRITE)
SSL_CB_ACCEPT_LOOP (SSL_ST_ACCEPT|SSL_CB_LOOP)
SSL_CB_ACCEPT_EXIT (SSL_ST_ACCEPT|SSL_CB_EXIT)
SSL_CB_CONNECT_LOOP (SSL_ST_CONNECT|SSL_CB_LOOP)
SSL_CB_CONNECT_EXIT (SSL_ST_CONNECT|SSL_CB_EXIT)
SSL_CB_HANDSHAKE_START
La fonction de rappel a été appelée car un nouveau handshake a démarré. Elle se produit également lorsqu'un handshake est repris après une pause pour gérer des données obsolètes.
SSL_CB_HANDSHAKE_DONE
La fonction de rappel a été appelée car un handshake est terminé. Elle se produit également si le handshake est en pause pour permettre l'échange de données obsolètes.

Les informations sur l'état actuel peuvent être obtenues à l'aide des familles de fonctions SSL_state_string(3).

Les informations sur ret peuvent être évaluées à l'aide des familles de fonctions SSL_alert_type_string(3).

VALEURS DE RETOUR

SSL_set_info_callback() ne fournit aucune information diagnostique.

SSL_get_info_callback() retourne la valeur actuelle.

EXEMPLES

L'exemple de fonction de rappel suivant imprime des chaînes sur l'état, des informations sur les alertes et des messages d'erreur sur la BIO bio_err.

void apps_ssl_info_callback(const SSL *s, int where, int ret)
{
    const char *str;
    int w = where & ~SSL_ST_MASK;
    if (w & SSL_ST_CONNECT)
        str = "SSL_connect";
    else if (w & SSL_ST_ACCEPT)
        str = "SSL_accept";
    else
        str = "undefined";
    if (where & SSL_CB_LOOP) {
        BIO_printf(bio_err, "%s:%s\n", str, SSL_state_string_long(s));
    } else if (where & SSL_CB_ALERT) {
        str = (where & SSL_CB_READ) ? "read" : "write";
        BIO_printf(bio_err, "SSL3 alert %s:%s:%s\n", str,
                   SSL_alert_type_string_long(ret),
                   SSL_alert_desc_string_long(ret));
    } else if (where & SSL_CB_EXIT) {
        if (ret == 0) {
            BIO_printf(bio_err, "%s:failed in %s\n", str, SSL_state_string_long(s));
        } else if (ret < 0) {
            BIO_printf(bio_err, "%s:error in %s\n", str, SSL_state_string_long(s));
        }
    }
}
