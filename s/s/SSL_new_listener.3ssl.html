NOM

SYNTAXE

#include <openssl/ssl.h>
SSL *SSL_new_listener(SSL_CTX *ctx, uint64_t flags);
SSL *SSL_new_listener_from(SSL *ssl, uint64_t flags);
int SSL_is_listener(SSL *ssl);
SSL *SSL_get0_listener(SSL *ssl);
int SSL_listen(SSL *ssl);
#define SSL_ACCEPT_CONNECTION_NO_BLOCK
SSL *SSL_accept_connection(SSL *ssl, uint64_t flags);
size_t SSL_get_accept_connection_queue_len(SSL *ssl);
SSL *SSL_new_from_listener(SSL *ssl, uint64_t flags);

DESCRIPTION

La fonction SSL_new_listener() crée un objet SSL auditeur. Les objets SSL auditeurs sont spécialisés pour accepter uniquement des connexions réseau d'une manière agnostique au protocole. Ils ne peuvent pas être utilisés, par exemple, pour envoyer ou recevoir des données en utilisant SSL_write_ex(3) ou SSL_read_ex(3). En général, seuls les fonctions expressément documentées comme étant supportées par un objet SSL auditeur sont disponibles.

La fonction SSL_new_listener_from() crée un objet SSL auditeur qui est subordonné à un objet SSL de domaine QUIC ssl. Voir SSL_new_domain(3) et openssl-quic-concurrency(7) pour les détails sur les objets SSL de domaine QUIC.

Un objet SSL auditeur supporte les opérations suivantes :

  • Comptage de références standard et opérations de libération, telles que SSL_up_ref(3) et SSL_free(3) ;
  • Opérations de configuration des BIO réseau, telles que SSL_set_bio(3) ;
  • API d'activation du traitement des événements et de sondage telles que SSL_handle_events(3), SSL_get_event_timeout(3), SSL_get_rpoll_descriptor(3), SSL_get_wpoll_descriptor(3), SSL_net_read_desired(3) et SSL_net_write_desired(3) ;
  • Certains paramètres configurables décrits dans SSL_get_value_uint(3) (voir SSL_get_value_uint(3) pour les détails) ;
  • Acceptation des connexions réseau en utilisant les fonctions documentées dans cette page de manuel, telles que SSL_accept_connection().

Le flux de travail de base de l'utilisation d'un objet auditeur est le suivant :

  • Créer un nouvel objet auditeur en utilisant SSL_new_listener() avec un SSL_CTX qui utilise une SSL_METHOD supportée (comme OSSL_QUIC_server_method(3)) ;
  • Configurer les BIO réseau appropriés en utilisant SSL_set_bio(3) sur l'objet SSL auditeur ;
  • Configurer le mode de blocage en utilisant SSL_set_blocking_mode(3) ;
  • Accepter les connexions dans une boucle en appelant SSL_accept_connection(). Chaque objet SSL retourné est une connexion valide qui peut être utilisée de manière normale.

La fonction SSL_is_listener() retourne 1 si et seulement si un objet SSL est un objet SSL auditeur.

La fonction SSL_get0_listener() retourne un objet auditeur qui est lié à l'objet SSL donné, s'il y en a un. Pour un objet auditeur, c'est le même objet (la fonction retourne son argument). Pour un objet de connexion qui a été créé par un objet auditeur, cet objet auditeur est retourné. Si l'argument ssl est un objet SSL qui n'est pas un objet auditeur et qui n'est pas descendant d'un objet auditeur (par exemple, une connexion obtenue en utilisant SSL_accept_connection()) ou indirectement d'un objet auditeur (par exemple, un objet SSL de flux QUIC obtenu en utilisant SSL_accept_stream() appelé sur une connexion obtenue en utilisant SSL_accept_connection()), la valeur de retour est NULL. Voir NOTES ci-dessous pour les mises en garde concernant les connexions SSL en attente dans la file d'attente d'acceptation d'un auditeur QUIC.

La fonction SSL_listen() commence à surveiller l'auditeur ssl pour les connexions entrantes. Des BIO appropriés doivent avoir été configurés avant d'appeler SSL_listen(), ainsi que toute autre configuration nécessaire pour l'objet SSL auditeur. Il n'est généralement pas nécessaire d'appeler SSL_listen() car elle sera appelée automatiquement lors du premier appel à SSL_accept_connection(). Cependant, SSL_listen() peut être appelée explicitement si l'on souhaite contrôler précisément quand le processus d'écoute commence, ou pour s'assurer qu'aucune erreur ne survient lors du démarrage de l'écoute des connexions. Après un appel à SSL_listen() (ou SSL_accept_connection()) réussi. La fonction SSL_listen() est idempotente, les appels ultérieurs sur le même objet ssl sont des no-ops. Cet appel n'est supporté que sur les objets SSL auditeurs.

L'appel SSL_accept_connection() n'est supporté que sur un objet SSL auditeur et accepte une nouvelle connexion entrante. Un nouvel objet SSL représentant la connexion acceptée est créé et retourné en cas de succès. Si aucune connexion entrante n'est disponible et que l'objet SSL auditeur est configuré en mode non bloquant, NULL est retourné.

Le nouvel objet SSL retourné par SSL_accept_connection() peut avoir terminé ou non son handshake au moment de son retour. Optionnellement, vous pouvez utiliser la fonction SSL_is_init_finished(3) pour déterminer cela. Vous pouvez appeler les fonctions SSL_accept(3), SSL_do_handshake(3) ou SSL_handle_events(3) pour faire progresser l'état de l'objet SSL vers la fin du handshake. D'autres fonctions d'"E/S" peuvent également faire progresser implicitement l'état du handshake, telles que SSL_poll(3), SSL_read(3) et SSL_write(3).

Le drapeau SSL_ACCEPT_CONNECTION_NO_BLOCK peut être spécifié à SSL_accept_connection(). S'il est spécifié, l'appel ne bloque pas même si l'objet SSL auditeur est configuré en mode bloquant.

L'appel SSL_get_accept_connection_queue_len() retourne le nombre de connexions en attente dans la file d'attente de l'auditeur ssl. SSL_accept_connection() retourne la prochaine connexion en attente, la retirant de la file d'attente. Le nombre de connexions retourné est une valeur à un instant donné, le nombre réel de connexions qui seront finalement retournées peut être différent.

Actuellement, les objets SSL auditeurs ne sont pris en charge que pour une utilisation côté serveur QUIC via OSSL_QUIC_server_method(3), ou une utilisation côté client QUIC uniquement via OSSL_QUIC_client_method(3) ou OSSL_QUIC_client_thread_method(3) (voir "UTILISATION CÔTÉ CLIENT UNIQUEMENT"). Il est prévu que l'interface d'auditeur, qui fournit une API abstraite pour l'acceptation de connexions, soit étendue pour prendre en charge d'autres protocoles, tels que TLS sur TCP, TCP simple ou DTLS à l'avenir.

SSL_listen() et SSL_accept_connection() sont des fonctions d'"E/S", ce qui signifie qu'elles mettent à jour la valeur retournée par SSL_get_error(3) si elles échouent.

UTILISATION CÔTÉ CLIENT UNIQUEMENT

Il est également possible d'utiliser l'interface d'auditeur sans accepter de connexions et sans écouter les connexions. Cela peut être utile dans des circonstances où il est souhaitable que plusieurs connexions partagent les mêmes ressources réseau sous-jacentes. Par exemple, plusieurs connexions client QUIC sortantes pourraient utiliser le même socket UDP sous-jacent.

Pour désactiver la validation des adresses client sur un objet SSL auditeur, le drapeau SSL_LISTENER_FLAG_NO_VALIDATE peut être passé dans le champ flags de SSL_new_listener() et SSL_new_listener_from(). Notez que ce drapeau n'affecte que l'envoi de trames de renvoi pour la validation des adresses serveur. Des jetons peuvent toujours être communiqués par le serveur via des trames NEW_TOKEN, qui seront toujours validés à la réception dans les connexions futures. Notez que ce réglage n'est pas recommandé et peut être dangereux dans des environnements non fiables. Ne pas effectuer de validation d'adresse expose le serveur à des clients malveillants qui peuvent ouvrir un grand nombre de connexions sans jamais y effectuer de transactions de données (équivalent à peu près à une attaque par inondation SYN TCP), ce que la validation d'adresse atténue.

VALEURS_DE_RETOUR

SSL_new_listener() et SSL_new_listener_from() renvoient un nouvel objet SSL d'écoute ou NULL en cas d'erreur.

SSL_is_listener() renvoie 1 si son argument ssl est un objet d'écoute, 0 sinon.

SSL_get0_listener() renvoie un pointeur vers un objet SSL (potentiellement le même objet sur lequel il est appelé) ou NULL.

SSL_listen() renvoie 1 en cas de succès ou 0 en cas d'erreur.

SSL_accept_connection() renvoie un pointeur vers un nouvel objet SSL en cas de succès ou NULL en cas d'erreur. En cas de succès, l'appelant prend possession de la référence.

SSL_get_accept_connection_queue_len() renvoie une valeur non négative, ou 0 si la file d'attente est vide, ou si un objet SSL d'un type non pris en charge est appelé.

SSL_new_from_listener() renvoie un pointeur vers un nouvel objet SSL en cas de succès ou NULL en cas d'erreur. En cas de succès, l'appelant prend possession de la référence.

NOTES

SSL_get0_listener() se comporte différemment dans les rappels QUIC. Les connexions QUIC entamant des opérations de négociation TLS avant d'être acceptées par SSL_accept_connection(), une application peut recevoir des rappels pour des connexions en attente avant leur acceptation par SSL_accept_connection(). Comme l'association de l'écoute se produit pendant le processus d'acceptation, avant de renvoyer depuis SSL_accept_connection(), les appels à SSL_get0_listener() effectués à partir de tels rappels renverront NULL. Cela peut être utilisé comme un indicateur dans le rappel que l'objet SSL référencé n'a pas encore été accepté.
