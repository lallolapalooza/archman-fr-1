Paquet: openssl

Licences: Apache-2.0

SSL_NEW_STREAM(3ssl) OpenSSL SSL_NEW_STREAM(3ssl)

NOM

SSL_new_stream, SSL_STREAM_FLAG_UNI, SSL_STREAM_FLAG_NO_BLOCK, SSL_STREAM_FLAG_ADVANCE - créer un nouveau flux initié localement par QUIC

SYNOPSIS

#include <openssl/ssl.h>
#define SSL_STREAM_FLAG_UNI          (1U << 0)
#define SSL_STREAM_FLAG_NO_BLOCK     (1U << 1)
#define SSL_STREAM_FLAG_ADVANCE      (1U << 2)
SSL *SSL_new_stream(SSL *ssl, uint64_t flags);

DESCRIPTION

La fonction SSL_new_stream(), lorsqu'elle est appelée avec un objet SSL de connexion QUIC, crée un nouveau flux QUIC bidirectionnel ou unidirectionnel initié localement et retourne l'objet SSL de flux QUIC nouvellement créé.

Si le drapeau SSL_STREAM_FLAG_UNI est passé, un flux unidirectionnel est créé ; sinon, un flux bidirectionnel est créé.

Pour récupérer l'ID du flux nouvellement créé, utilisez SSL_get_stream_id(3).

Il incombe à l'appelant de libérer l'objet SSL du flux QUIC en utilisant SSL_free(3). La durée de vie de l'objet SSL de la connexion QUIC doit être supérieure à celle de l'objet SSL du flux QUIC ; en d'autres termes, l'objet SSL du flux QUIC doit être libéré en premier.

Une fois qu'un flux a été créé à l'aide de SSL_new_stream(), il peut être utilisé de manière normale en utilisant SSL_read(3) et SSL_write(3).

Cette fonction ne peut être utilisée que pour créer des objets de flux pour les flux initiés localement. Pour accepter des flux entrants initiés par un pair, utilisez SSL_accept_stream(3).

Appeler SSL_new_stream() s'il n'y a pas de flux par défaut déjà présent empêche la création future d'un flux par défaut. Voir openssl-quic(7).

La création de nouveaux flux est soumise au contrôle de flux par le protocole QUIC. S'il n'est actuellement pas possible de créer un nouveau flux initié localement du type spécifié, un appel à SSL_new_stream() bloquera (si la connexion est configurée en mode bloquant) jusqu'à ce qu'un nouveau flux puisse être créé, ou retournera NULL sinon.

Cette fonction fonctionne en mode bloquant si l'objet SSL de la connexion QUIC est configuré en mode bloquant (voir SSL_set_blocking_mode(3)). Elle peut également être utilisée en mode non bloquant sur une connexion configurée en mode bloquant en passant le drapeau SSL_STREAM_FLAG_NO_BLOCK.

Le drapeau SSL_STREAM_FLAG_ADVANCE peut être utilisé pour créer un objet SSL de flux QUIC même si un nouveau flux QUIC ne peut pas encore être ouvert en raison du contrôle de flux. L'appelant peut commencer à utiliser le nouveau flux et remplir le tampon d'écriture du flux en appelant SSL_write(3). Cependant, aucune donnée de flux réelle (ou trames QUIC concernant le flux) ne sera envoyée tant que le contrôle de flux QUIC ne le permettra pas. Toutes les données mises en file d'attente seront envoyées dès qu'un pair le permettra. Il n'y a aucune garantie que le flux sera finalement créé ; par exemple, la connexion pourrait échouer, ou un pair pourrait simplement décider de ne jamais augmenter le nombre de flux autorisés pour le reste de la durée de vie de la connexion.

VALEURS DE RETOUR

SSL_new_stream() retourne un nouveau flux objet, ou NULL en cas d'erreur.

Cette fonction échoue si elle est appelée sur un objet SSL de flux QUIC ou sur un objet SSL non-QUIC.

SSL_new_stream() peut également échouer si la connexion sous-jacente a atteint le nombre maximum de flux, basé sur les valeurs du paramètre de transport max_streams_bidi ou max_streams_uni négociées avec le pair. Dans ce cas, le retour NULL sera accompagné d'une erreur dans la pile d'erreurs (obtenable via ERR_get_error()), qui conterra un code de raison SSL_R_STREAM_COUNT_LIMITED. Lorsque cette erreur est rencontrée, l'opération peut être retentée. Il est recommandé, avant la nouvelle tentative, de vider la pile d'erreurs via un appel à ERR_clear_error(), et d'activer la machine à états TLS via un appel à SSL_handle_events() pour traiter toute mise à jour potentielle du serveur autorisant la création de flux supplémentaires.

VOIR AUSSI

SSL_accept_stream(3), SSL_free(3)

HISTORIQUE

SSL_new_stream() a été ajouté dans OpenSSL 3.2.
