SSL_handle_events(3ssl)

Paquet: openssl

Licences: Apache-2.0

SSL_HANDLE_EVENTS(3ssl) OpenSSL SSL_HANDLE_EVENTS(3ssl)

NOM

SSL_handle_events - fait avancer la machine d'état asynchrone et effectue les E/S réseau

SYNTAXE

#include <openssl/ssl.h>
int SSL_handle_events(SSL *ssl);

DESCRIPTION

SSL_handle_events() effectue les opérations internes qui sont dues sur un objet SSL. Les opérations exactes effectuées par SSL_handle_events() varient en fonction du type de protocole utilisé avec l'objet SSL donné. Par exemple, SSL_handle_events() peut gérer les événements de délai d'expiration qui sont arrivés à échéance, ou peut tenter, dans la mesure du possible actuellement, d'effectuer des opérations d'E/S réseau sur l'un des BIO sous-jacents à l'objet SSL.

Le cas d'utilisation principal de SSL_handle_events() est de permettre à une application qui utilise OpenSSL en mode non bloquant de donner à OpenSSL l'opportunité de gérer les événements de minuteur, ou de répondre à la disponibilité de nouvelles données à lire à partir d'un BIO sous-jacent, ou de répondre à l'opportunité d'écrire des données en attente dans un BIO sous-jacent.

SSL_handle_events() ne peut être utilisé qu'avec les types d'objets SSL suivants :

Objets SSL DTLS
L'utilisation de SSL_handle_events() sur un objet SSL utilisé avec une méthode DTLS permet de gérer correctement les événements de délai d'expiration. Ceci est équivalent à un appel à DTLSv1_handle_timeout(3). Étant donné que SSL_handle_events() gère un sur-ensemble des cas d'utilisation de DTLSv1_handle_timeout(3), il devrait être privilégié pour les nouvelles applications qui ne nécessitent pas de prise en charge d'OpenSSL 3.1 ou versions antérieures.

Lors de l'utilisation de DTLS, une application doit appeler SSL_handle_events() comme indiqué par les appels à SSL_get_event_timeout(3) ; la gestion des événements n'est pas effectuée automatiquement par les appels à d'autres fonctions SSL telles que SSL_read(3) ou SSL_write(3). Notez que cela est différent de QUIC qui effectue également la gestion des événements implicitement ; voir ci-dessous.

Objets SSL de connexion QUIC
L'utilisation de SSL_handle_events() sur un objet SSL qui représente une connexion QUIC permet de gérer correctement les événements de délai d'expiration, ainsi que de traiter les données réseau entrantes et d'écrire les données réseau sortantes mises en file d'attente, si le BIO sous-jacent a la capacité de les accepter.

Normalement, lorsqu'une application utilise un objet SSL en mode bloquant, elle n'a pas besoin d'appeler SSL_handle_events() car OpenSSL effectue le "ticking" en interne sur une base automatique. Cependant, si une application utilise une connexion QUIC en mode non bloquant, elle doit au minimum s'assurer que SSL_handle_events() est appelée périodiquement pour permettre la gestion des événements de délai d'expiration. Une application peut savoir quand elle doit appeler SSL_handle_events() pour cet usage (le cas échéant) en appelant SSL_get_event_timeout(3).

Appeler SSL_handle_events() sur un objet SSL de connexion QUIC utilisé en mode bloquant n'est pas nécessaire à moins qu'aucun appel d'E/S (tel que SSL_read(3) ou SSL_write(3)) ne soit effectué sur l'objet pendant une période substantielle. Tant qu'au moins un appel à l'objet SSL est bloquant, aucun appel de ce type n'est nécessaire. Cependant, SSL_handle_events() peut éventuellement être utilisé sur un objet de connexion QUIC si désiré.

Avec le mode de fonctionnement assisté par thread OSSL_QUIC_client_thread_method(3), il est inutile d'appeler SSL_handle_events() car le thread d'assistance gère les événements de connexion QUIC.

Appeler SSL_handle_events() sur tout autre type d'objet SSL est une opération nulle (no-op). Ceci est considéré comme un cas de succès.

Notez que SSL_handle_events() remplace la fonction plus ancienne DTLSv1_handle_timeout(3) pour tous les cas d'utilisation.

VALEURS DE RETOUR

Retourne 1 en cas de succès et 0 en cas d'échec.

VOIR AUSSI

SSL_get_event_timeout(3), DTLSv1_handle_timeout(3), ssl(7)

HISTORIQUE

La fonction SSL_handle_events() a été ajoutée dans OpenSSL 3.2.
