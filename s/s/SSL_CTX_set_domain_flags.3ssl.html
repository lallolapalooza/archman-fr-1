SSL_CTX_set_domain_flags(3ssl)

Paquet: openssl

Licences: Apache-2.0

SSL_CTX_SET_DOMAIN_FLAGS(3ssl) OpenSSL SSL_CTX_SET_DOMAIN_FLAGS(3ssl)

NOM

SSL_CTX_set_domain_flags, SSL_CTX_get_domain_flags, SSL_get_domain_flags, SSL_DOMAIN_FLAG_SINGLE_THREAD, SSL_DOMAIN_FLAG_MULTI_THREAD, SSL_DOMAIN_FLAG_THREAD_ASSISTED, SSL_DOMAIN_FLAG_BLOCKING, SSL_DOMAIN_FLAG_LEGACY_BLOCKING - contrôler le modèle de concurrence utilisé par un domaine QUIC

SYNTAXE

#include <openssl/ssl.h>
#define SSL_DOMAIN_FLAG_SINGLE_THREAD
#define SSL_DOMAIN_FLAG_MULTI_THREAD
#define SSL_DOMAIN_FLAG_LEGACY_BLOCKING
#define SSL_DOMAIN_FLAG_BLOCKING
#define SSL_DOMAIN_FLAG_THREAD_ASSISTED
int SSL_CTX_set_domain_flags(SSL_CTX *ctx, uint64_t flags);
int SSL_CTX_get_domain_flags(SSL_CTX *ctx, uint64_t *flags);
int SSL_get_domain_flags(SSL *ssl, uint64_t *flags);

DESCRIPTION

SSL_CTX_set_domain_flags() et SSL_CTX_get_domain_flags() définissent et obtiennent les drapeaux de domaine QUIC sur un SSL_CTX utilisant une SSL_METHOD QUIC. Ces drapeaux déterminent le modèle de concurrence qui est utilisé pour un domaine QUIC. Une introduction détaillée à ces concepts se trouve dans openssl-quic-concurrency(7).

Les applications peuvent utiliser l'un des drapeaux ici :

SSL_DOMAIN_FLAG_SINGLE_THREAD
La spécification de ce drapeau configure le modèle de concurrence à thread unique (SCM).
SSL_DOMAIN_FLAG_MULTI_THREAD
La spécification de ce drapeau configure le modèle de concurrence contrôlée (CCM) (sauf si SSL_DOMAIN_FLAG_THREAD_ASSISTED est également spécifié).

Si OpenSSL a été compilé sans support de threads, ceci est identique à SSL_DOMAIN_FLAG_SINGLE_THREAD.

SSL_DOMAIN_FLAG_THREAD_ASSISTED
La spécification de ce drapeau configure le modèle de concurrence assistée par threads (TACM). Il implique SSL_DOMAIN_FLAG_MULTI_THREAD et SSL_DOMAIN_FLAG_BLOCKING.

Ce modèle de concurrence n'est pas disponible si OpenSSL a été compilé sans support de threads, auquel cas tenter de le configurer entraînera une erreur.

SSL_DOMAIN_FLAG_BLOCKING
Active le support fiable pour les appels d'E/S bloquants, allouant toutes les ressources système nécessaires pour le réaliser. Si ce drapeau est spécifié, SSL_DOMAIN_FLAG_LEGACY_BLOCKING est ignoré.
SSL_DOMAIN_FLAG_LEGACY_BLOCKING
Active le mode de compatibilité de blocage hérité. Voir « Compatibilité du support de blocage hérité » dans openssl-quic-concurrency(7).

Les combinaisons de drapeaux mutuellement exclusives entraînent une erreur (par exemple, combiner SSL_DOMAIN_FLAG_SINGLE_THREAD et SSL_DOMAIN_FLAG_MULTI_THREADED).

Étant donné qu'un seul modèle de concurrence doit être choisi, les drapeaux de domaine ne peuvent pas être définis à 0 et tenter de le faire entraînera une erreur.

La modification de ces drapeaux à l'aide de SSL_CTX_set_domain_flags() n'a aucun effet sur les domaines QUIC qui ont déjà été créés.

L'ensemble par défaut de drapeaux de domaine défini sur un SSL_CTX nouvellement créé peut varier selon la version d'OpenSSL, la SSL_METHOD choisie et l'environnement d'exploitation. Voir openssl-quic-concurrency(7) pour les détails. Une application peut récupérer les drapeaux de domaine par défaut en appelant SSL_CTX_get_domain_flags() immédiatement après la construction d'un SSL_CTX.

SSL_get_domain_flags() récupère les drapeaux de domaine qui sont effectifs pour un domaine QUIC lorsqu'il est appelé sur n'importe quel objet SSL QUIC de ce domaine.

VALEURS DE RETOUR

SSL_CTX_set_domain_flags(), SSL_CTX_get_domain_flags() et SSL_get_domain_flags() retournent 1 en cas de succès et 0 en cas d'échec.

SSL_CTX_set_domain_flags() échoue s'il est appelé avec un ensemble de drapeaux incohérents ou qui ne peuvent pas être pris en charge compte tenu de l'environnement actuel.

SSL_CTX_set_domain_flags() et SSL_CTX_get_domain_flags() échouent s'ils sont appelés sur un SSL_CTX qui n'utilise pas une SSL_METHOD QUIC.

SSL_get_domain_flags() échoue s'il est appelé sur un objet SSL non-QUIC.

VOIR AUSSI

SSL_new_domain(3), openssl-quic-concurrency(7)

HISTORIQUE

Ces fonctions ont été ajoutées dans OpenSSL 3.5.
