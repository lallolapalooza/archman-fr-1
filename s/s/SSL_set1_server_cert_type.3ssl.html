SSL_set1_server_cert_type(3ssl) OpenSSL SSL_set1_server_cert_type(3ssl)

NAME

SSL_set1_client_cert_type, SSL_set1_server_cert_type, SSL_CTX_set1_client_cert_type, SSL_CTX_set1_server_cert_type, SSL_get0_client_cert_type, SSL_get0_server_cert_type, SSL_CTX_get0_client_cert_type, SSL_CTX_get0_server_cert_type - support pour les types de certificats (RFC7250)

SYNOPSIS

#include <openssl/ssl.h>
int SSL_set1_client_cert_type(SSL *s, const unsigned char *val, size_t len);
int SSL_set1_server_cert_type(SSL *s, const unsigned char *val, size_t len);
int SSL_CTX_set1_client_cert_type(SSL_CTX *ctx, const unsigned char *val, size_t len);
int SSL_CTX_set1_server_cert_type(SSL_CTX *ctx, const unsigned char *val, size_t len);
int SSL_get0_client_cert_type(const SSL *s, unsigned char **val, size_t *len);
int SSL_get0_server_cert_type(const SSL *s, unsigned char **val, size_t *len);
int SSL_CTX_get0_client_cert_type(const SSL_CTX *ctx, unsigned char **val, size_t *len);
int SSL_CTX_get0_server_cert_type(const SSL_CTX *s, unsigned char **val, size_t *len);

DESCRIPTION

Les fonctions SSL_set1_client_cert_type() et SSL_CTX_set1_client_cert_type() définissent les valeurs pour le type de certificat du client. Les fonctions SSL_get0_client_cert_type() et SSL_CTX_get0_client_cert_type() récupèrent les valeurs locales pour le type de certificat du client.

Les fonctions SSL_set1_server_cert_type() et SSL_CTX_set1_server_cert_type() définissent les valeurs pour le type de certificat du serveur. Les fonctions SSL_get0_server_cert_type() et SSL_CTX_get0_server_cert_type() récupèrent les valeurs locales pour le type de certificat du serveur.

NOTES

Les types de certificats sont utilisés pour négocier le type de certificat à utiliser dans la poignée de main. Ces extensions permettent à chaque côté de savoir quels types de certificats l'autre côté peut accepter.

Le type de certificat client est envoyé du client au serveur pour indiquer quels types de certificats le client peut présenter. Les valeurs sont définies par ordre de préférence. Sur le serveur, ce réglage détermine quels types de certificats le serveur est prêt à accepter. Le serveur choisit finalement quel type de certificat utiliser (si nécessaire). Par défaut (si aucune valeur explicite n'est spécifiée), seuls les certificats X.509 sont supportés.

Le type de certificat serveur est envoyé du client au serveur pour indiquer quels types de certificats le client accepte. Les valeurs sont définies par ordre de préférence. Sur le serveur, ce réglage détermine quels types de certificats le serveur est prêt à présenter. Le serveur choisit finalement quel type de certificat utiliser (si nécessaire) parmi les valeurs mutuellement compatibles. Par défaut (si aucune valeur explicite n'est spécifiée), seuls les certificats X.509 sont supportés.

Si RPK est spécifié en premier, cela signifie que le côté tentera d'envoyer (ou de demander) RPK si son partenaire le supporte également, sinon un certificat X.509 sera utilisé si les deux l'ont spécifié (ou n'ont pas configuré ces options).

Les deux valeurs possibles dans le tableau val sont :

TLSEXT_cert_type_x509
Correspond à un certificat X.509 normalement utilisé dans TLS.
TLSEXT_cert_type_rpk
Correspond à une clé publique brute.

Si val est défini sur une valeur non nulle, alors l'extension est envoyée lors de la poignée de main. Si val est défini sur une valeur nulle (et len est 0), alors l'extension est désactivée. La valeur par défaut est NULL, ce qui signifie que l'extension n'est pas envoyée et que les certificats X.509 sont utilisés lors de la poignée de main.

Les clés publiques brutes peuvent être utilisées à la place des certificats lorsque le type de certificat est spécifié et négocié. Les clés publiques brutes n'ont pas de sujet, d'émetteur, de dates de validité ou de signatures numériques.

Utilisez les fonctions SSL_get_negotiated_client_cert_type(3) et SSL_get_negotiated_server_cert_type(3) pour obtenir les valeurs du type de certificat négociées (à la fin de la poignée de main ou dans les callbacks qui se produisent après le traitement du ServerHello).

RETURN VALUES

Toutes les fonctions retournent 1 en cas de succès et 0 en cas d'échec.

La mémoire retournée par les fonctions get0 doit être libérée.

EXAMPLES

Pour utiliser des clés publiques brutes sur le serveur, configurez le SSL_CTX et le SSL comme suit :

SSL_CTX *ctx;
SSL *ssl;
unsigned char cert_type[] = { TLSEXT_cert_type_rpk, TLSEXT_cert_type_x509 };
EVP_PKEY *rpk;
/* Remplissez rpk avec une EVP_PKEY obtenue à partir d'un fichier ou d'un autre moyen */
if ((ctx = SSL_CTX_new(TLS_server_method())) == NULL)
    /* erreur */
if ((ssl = SSL_new(ctx)) == NULL)
    /* erreur */
if (!SSL_set1_server_cert_type(ssl, cert_type, sizeof(cert_type)))
    /* erreur */
/* Pas besoin de spécifier un certificat lors de l'utilisation de clés publiques brutes */
if (!SSL_use_PrivateKey(ssl, rpk))
    /* erreur */
/* Effectuer des opérations SSL_accept() */

Pour vous connecter à ce serveur, configurez le SSL_CTX et le SSL comme suit :

/* Fonction de connexion */
SSL_CTX *ctx;
SSL *ssl;
const char *dane_tlsa_domain = "smtp.example.com";
unsigned char cert_type[] = { TLSEXT_cert_type_rpk, TLSEXT_cert_type_x509 };
EVP_PKEY *rpk;
int verify_result;
/* Remplissez rpk avec une EVP_PKEY obtenue à partir d'un fichier ou d'un autre moyen */
if ((ctx = SSL_CTX_new(TLS_client_method())) == NULL)
    /* erreur */
if (SSL_CTX_dane_enable(ctx) <= 0)
    /* erreur */
if ((ssl = SSL_new(ctx)) == NULL)
    /* erreur */
/*
 * Le `dane_tlsa_domain` définit le nom d'hôte par défaut pour SNI.
 * Il peut être défini sur NULL lorsque DANE est activé côté serveur.
 */
if (SSL_dane_enable(ssl, dane_tlsa_domain) <= 0)
    /* erreur */
if (!SSL_set1_server_cert_type(ssl, cert_type, sizeof(cert_type)))
    /* erreur */
if (!SSL_add_expected_rpk(ssl, rpk))
    /* erreur */
/* Effectuer le handshake SSL_connect() et gérer les erreurs ici */
/* Facultatif : vérifier la RPK côté serveur */
verify_result = SSL_get_verify_result(ssl);
if (verify_result == X509_V_OK) {
    /* La clé publique brute du serveur a correspondu à l'enregistrement TLSA */
} else if (verify_result == X509_V_ERR_DANE_NO_MATCH) {
    /*
     * La clé publique brute du serveur, ou la clé dans le certificat, n'a pas correspondu à l'enregistrement TLSA
     */
} else if (verify_result == X509_V_ERR_RPK_UNTRUSTED) {
    /*
     * Aucun enregistrement TLSA du type correct n'a été trouvé pour vérifier la clé publique brute du serveur. Cela ne se produirait pas dans cet exemple, car un enregistrement TLSA est configuré.
     */
} else {
    /* Erreur de vérification dans d'autres cas */
}

Pour valider les clés publiques du client, le code de l'exemple client pourrait être incorporé dans la partie serveur.

SYNOPSIS

#include <openssl/ssl.h>

int SSL_set1_server_cert_type(SSL *ssl, int cert_type);

DESCRIPTION

La fonction SSL_set1_server_cert_type attribue le type de certificat de serveur spécifié par cert_type au contexte SSL ssl.

Les valeurs de cert_type sont des entiers représentant des types de certificats, tels que SSL_CERT_TYPE_RSA ou SSL_CERT_TYPE_DSS.

NOTES

Cette fonction doit être appelée avant d'établir une connexion SSL/TLS.

L'utilisation de cette fonction est généralement réservée aux scénarios avancés où un contrôle fin du type de certificat du serveur est nécessaire.

VALEURS DE RETOUR

La fonction retourne 1 en cas de succès, et 0 en cas d'échec.

EXEMPLES

Voici un exemple simple d'utilisation de SSL_set1_server_cert_type :

SSL_CTX *ctx;
SSL *ssl;
int cert_type = SSL_CERT_TYPE_RSA;

/* Initialisation du contexte SSL et de la structure SSL */
/* ... */

if (SSL_set1_server_cert_type(ssl, cert_type) == 0) {
    /* Gérer l'erreur */
}
