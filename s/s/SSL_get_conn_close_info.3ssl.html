SYNTAXE

#include <openssl/ssl.h>
#define SSL_CONN_CLOSE_FLAG_LOCAL
#define SSL_CONN_CLOSE_FLAG_TRANSPORT
typedef struct ssl_conn_close_info_st {
    uint64_t error_code, frame_type;
    char     *reason;
    size_t   reason_len;
    uint32_t flags;
} SSL_CONN_CLOSE_INFO;
int SSL_get_conn_close_info(SSL *ssl, SSL_CONN_CLOSE_INFO *info,
                            size_t info_len);

#define OSSL_QUIC_ERR_CONNECTION_REFUSED        0x02

DESCRIPTION

La fonction SSL_get_conn_close_info fournit des informations sur la raison et la manière dont une connexion QUIC a été fermée.

Les informations de fermeture de connexion sont écrites dans *info, qui ne doit pas être nul. La valeur info_len doit être définie à sizeof(*info).

Les champs suivants sont définis :

error_code
Il s'agit d'un code d'erreur QUIC de 62 bits. C'est un code d'erreur d'application (si le drapeau SSL_CONN_CLOSE_FLAG_TRANSPORT n'est pas défini dans flags) ou un code d'erreur de transport QUIC standard (si le drapeau SSL_CONN_CLOSE_FLAG_TRANSPORT est défini dans flags).
frame_type
Si le drapeau SSL_CONN_CLOSE_FLAG_TRANSPORT est défini, cela peut être 0 si aucun type de trame n'a été spécifié qui a causé la fermeture de la connexion. Si le drapeau SSL_CONN_CLOSE_FLAG_TRANSPORT n'est pas défini, il est défini à 0.
reason
S'il n'est pas nul, il s'agit d'une courte chaîne UTF-8 décrivant la raison pour laquelle la connexion a été fermée. La longueur en octets de la chaîne reason est donnée dans reason_len. Bien que, s'il n'est pas nul, OpenSSL garantit que cette chaîne est terminée par zéro, mais vous devez considérer que ce tampon peut avoir été généré par le côté opposé (non fiable) et peut contenir des zéros ailleurs. Par conséquent, l'utilisation de reason_len est recommandée. Bien que ce soit censé être une chaîne UTF-8 selon le protocole QUIC, rien ne garantit que ce soit le cas pour les chaînes reçues du côté opposé.
SSL_CONN_CLOSE_FLAG_LOCAL
Si le drapeau flags a SSL_CONN_CLOSE_FLAG_LOCAL défini, la fermeture de la connexion a été provoquée localement. Cela peut être dû à une demande de l'application (par exemple, si le drapeau SSL_CONN_CLOSE_FLAG_TRANSPORT n'est pas défini), ou (si le drapeau SSL_CONN_CLOSE_FLAG_TRANSPORT est défini) en raison de la logique interne de l'implémenteur QUIC (par exemple, si le côté opposé viole le protocole ou si un délai d'attente expire).
SSL_CONN_CLOSE_FLAG_TRANSPORT
Si le drapeau flags a SSL_CONN_CLOSE_FLAG_TRANSPORT défini, la fermeture de la connexion a été provoquée pour des raisons de protocole QUIC. Sinon, la fermeture de la connexion a été provoquée par l'application locale ou distante.

Les macros OSSL_QUIC_ERR définis fournissent les codes d'erreur de transport QUIC définis par RFC 9000. Le macro OSSL_QUIC_ERR_CRYPTO_ERR() peut être utilisé pour convertir un code d'alerte TLS en un code d'erreur de transport QUIC, en mappant ce code à la plage réservée à de tels codes par RFC 9000. Cette plage commence à OSSL_QUIC_ERR_CRYPTO_ERR_BEGIN et se termine à OSSL_QUIC_ERR_CRYPTO_ERR_END inclus.

CODES D'ERREUR DE TRANSPORT NON STANDARD

Certaines conditions qui peuvent entraîner la terminaison d'une connexion QUIC ne sont pas communiquées sur le fil et n'ont donc pas de codes d'erreur standard. OpenSSL indique ces erreurs en appelant SSL_get_conn_close_info() en définissant le drapeau SSL_CONN_CLOSE_FLAG_TRANSPORT et en utilisant l'une des valeurs d'erreur suivantes. Ces codes sont spécifiques à OpenSSL et ne peuvent pas être envoyés sur le fil car ils sont supérieurs à 2^62.

OSSL_QUIC_LOCAL_ERR_IDLE_TIMEOUT
La connexion a été terminée immédiatement en raison de l'expiration du délai d'inactivité.

VALEUR DE RETOUR

La fonction SSL_get_conn_close_info() renvoie 1 en cas de succès et 0 en cas d'échec. Cette fonction échoue si elle est appelée sur un objet SSL de connexion QUIC qui n'a pas encore été terminé. Elle échoue également si elle est appelée sur un objet SSL de flux QUIC ou un objet SSL non QUIC.
