NOM

SSL_poll, SSL_POLL_EVENT_NONE, SSL_POLL_EVENT_F, SSL_POLL_EVENT_EL, SSL_POLL_EVENT_EC, SSL_POLL_EVENT_ECD, SSL_POLL_EVENT_ER, SSL_POLL_EVENT_EW, SSL_POLL_EVENT_R, SSL_POLL_EVENT_W, SSL_POLL_EVENT_IC, SSL_POLL_EVENT_ISB, SSL_POLL_EVENT_ISU, SSL_POLL_EVENT_OSB, SSL_POLL_EVENT_OSU, SSL_POLL_EVENT_RW, SSL_POLL_EVENT_RE, SSL_POLL_EVENT_WE, SSL_POLL_EVENT_RWE, SSL_POLL_EVENT_E, SSL_POLL_EVENT_IS, SSL_POLL_EVENT_ISE, SSL_POLL_EVENT_I, SSL_POLL_EVENT_OS, SSL_POLL_EVENT_OSE, SSL_POLL_FLAG_NO_HANDLE_EVENTS - déterminer ou attendre les conditions de disponibilité d'un ou plusieurs objets sondables

SYNOP

#include <openssl/ssl.h>
#define SSL_POLL_EVENT_NONE        0
#define SSL_POLL_EVENT_F           /* F   (Échec) */
#define SSL_POLL_EVENT_EL          /* EL  (Exception sur Écouteur) */
#define SSL_POLL_EVENT_EC          /* EC  (Exception sur Connexion) */
#define SSL_POLL_EVENT_ECD         /* ECD (Exception sur Connexion Vidée) */
#define SSL_POLL_EVENT_ER          /* ER  (Exception sur Lecture) */
#define SSL_POLL_EVENT_EW          /* EW  (Exception sur Écriture) */
#define SSL_POLL_EVENT_R           /* R   (Lisible) */
#define SSL_POLL_EVENT_W           /* W   (Écrivable) */
#define SSL_POLL_EVENT_IC          /* IC  (Connexion entrante) */
#define SSL_POLL_EVENT_ISB         /* ISB (Flux entrant: Bidi) */
#define SSL_POLL_EVENT_ISU         /* ISU (Flux entrant: Uni) */
#define SSL_POLL_EVENT_OSB         /* OSB (Flux sortant: Bidi) */
#define SSL_POLL_EVENT_OSU         /* OSU (Flux sortant: Uni) */
#define SSL_POLL_EVENT_RW          /* R   | W               */
#define SSL_POLL_EVENT_RE          /* R   | ER              */
#define SSL_POLL_EVENT_WE          /* W   | EW              */
#define SSL_POLL_EVENT_RWE         /* RE  | WE              */
#define SSL_POLL_EVENT_E           /* EL  | EC  | ER  | EW  */
#define SSL_POLL_EVENT_IS          /* ISB | ISU             */
#define SSL_POLL_EVENT_ISE         /* IS  | EC              */
#define SSL_POLL_EVENT_I           /* IS                    */
#define SSL_POLL_EVENT_OS          /* OSB | OSU             */
#define SSL_POLL_EVENT_OSE         /* OS  | EC              */
typedef struct ssl_poll_item_st {
    BIO_POLL_DESCRIPTOR desc;
    uint64_t            events, revents;
} SSL_POLL_ITEM;
#define SSL_POLL_FLAG_NO_HANDLE_EVENTS
int SSL_poll(SSL_POLL_ITEM         *items,
             size_t                num_items,
             size_t                stride,
             const struct timeval  *timeout,
             uint64_t              flags,
             size_t                *result_count);

DESCRIPTION

SSL_poll() permet de déterminer les conditions de disponibilité des ressources représentées par une ou plusieurs structures BIO_POLL_DESCRIPTOR. En particulier, il peut être utilisé pour interroger les conditions de disponibilité des objets SSL de connexion QUIC et des objets SSL de flux QUIC en un seul appel. Il peut également être utilisé pour bloquer jusqu'à ce qu'au moins une des ressources données soit prête.

Un appel à SSL_poll() spécifie un tableau de structures SSL_POLL_ITEM, chacune désignant une ressource pour laquelle on interroge la disponibilité, et un ensemble d'indicateurs d'événements qui indiquent les événements de disponibilité spécifiques auxquels l'appelant s'intéresse par rapport à la ressource spécifiée.

Les champs de SSL_POLL_ITEM sont les suivants :

desc
La ressource pour laquelle on interroge la disponibilité, telle que représentée par un BIO_POLL_DESCRIPTOR. Actuellement, il doit s'agir d'un descripteur de sondage de type BIO_POLL_DESCRIPTOR_TYPE_SSL, représentant un pointeur d'objet SSL, et l'objet SSL doit être un objet SSL de connexion QUIC ou un objet SSL de flux QUIC.

Si un SSL_POLL_ITEM a un type de descripteur de sondage de BIO_POLL_DESCRIPTOR_TYPE_NONE, ou si le pointeur d'objet SSL est NULL, l'entrée du tableau SSL_POLL_ITEM est ignorée et revents sera mis à 0 au retour.

events
C'est l'ensemble de zéro ou plusieurs événements dont l'appelant souhaite être informé par rapport à la ressource décrite par desc. Il s'agit d'une collection de zéro ou plusieurs indicateurs SSL_POLL_EVENT. Voir "TYPES D'ÉVÉNEMENTS" pour une description de chaque type d'événement.
revents
Après le retour de SSL_poll(), c'est l'ensemble de zéro ou plusieurs événements qui sont réellement applicables à la ressource décrite par desc. Comme pour events, il s'agit d'une collection de zéro ou plusieurs indicateurs SSL_POLL_EVENT.

revents n'a pas besoin d'être un sous-ensemble des événements spécifiés dans events, car certains types d'événements sont définis comme étant toujours activés (non masquables). Voir "TYPES D'ÉVÉNEMENTS" pour plus d'informations.

Pour utiliser SSL_poll(), appelez-le avec un tableau de structures SSL_POLL_ITEM. Le tableau doit rester alloué uniquement pour la durée de l'appel. num_items doit être défini sur le nombre d'entrées du tableau, et stride doit être défini sur sizeof(SSL_POLL_ITEM).

L'argument timeout spécifie le délai d'attente à utiliser, et, implicitement, s'il faut utiliser SSL_poll() en mode bloquant ou non bloquant :

  • Si timeout est NULL, la fonction se bloque indéfiniment jusqu'à ce qu'au moins une ressource soit prête.
  • Si timeout n'est pas NULL, et pointe vers un struct timeval réglé à zéro, la fonction opère en mode non bloquant et retourne immédiatement avec les informations de disponibilité.
  • Si timeout n'est pas NULL, et pointe vers un struct timeval réglé à une valeur autre que zéro, la fonction se bloque pendant l'intervalle spécifié ou jusqu'à ce qu'au moins une des ressources spécifiées soit prête, selon la première éventualité.

L'implémentation actuelle de SSL_poll() est un sous-ensemble des fonctionnalités qui seront disponibles à terme. Pour plus d'informations, voir "LIMITATIONS".

Les indicateurs suivants sont actuellement définis pour l'argument flags :

SSL_POLL_FLAG_NO_HANDLE_EVENTS
Cet indicateur indique que le traitement de la machine d'état interne ne doit pas être effectué pour tenter de générer de nouveaux événements de disponibilité. Seuls les événements de disponibilité existants seront rapportés.

Si cet indicateur est utilisé en mode non bloquant (avec un délai d'attente de zéro), aucun traitement de la machine d'état interne n'est effectué.

Si cet indicateur est utilisé en mode bloquant (par exemple, avec timeout réglé à NULL), le traitement des événements ne se produit pas à moins que la fonction ne se bloque.

L'argument result_count est facultatif. S'il n'est pas NULL, il est utilisé pour indiquer le nombre d'entrées dans le tableau qui ont des champs revents non nuls lorsque l'appel à SSL_poll() retourne ; voir "VALEURS DE RETOUR" pour plus de détails.

TYPES D'ÉVÉNEMENTS

L'interface SSL_poll() rapporte zéro ou plusieurs types d'événements sur une ressource donnée, représentés par un masque de bits.

Tous les types d'événements sont déclenchés au niveau et représentent une condition de disponibilité ou une exception permanente ; ainsi, après qu'un événement a été rapporté par SSL_poll() pour une ressource, il continuera d'être rapporté dans les futurs appels à SSL_poll() jusqu'à ce que la condition cesse d'être effective. Un appelant doit masquer le bit du type d'événement donné dans les futurs appels à SSL_poll() s'il ne souhaite pas recevoir de notifications répétées et n'a pas provoqué la désactivation de la condition de disponibilité sous-jacente (par exemple, en consommant toutes les données disponibles à l'aide de SSL_read_ex(3) après que SSL_POLL_EVENT_R ait été rapporté).

Certains types d'événements n'ont pas de sens pour un type de ressource donné. Dans ce cas, spécifier ce type d'événement dans events est une opération nulle et sera ignoré, et l'événement donné ne sera jamais rapporté dans revents.

L'échec du mécanisme de sondage lui-même est considéré comme distinct d'une condition d'exception sur une ressource qui a été sondée avec succès. Voir SSL_POLL_EVENT_F et "VALEURS DE RETOUR" pour plus de détails.

En général, une application doit toujours écouter les types d'événements correspondant aux conditions d'exception si elle écoute les types d'événements non-exceptionnels correspondants (par exemple, SSL_POLL_EVENT_EC et SSL_POLL_EVENT_ER pour SSL_POLL_EVENT_R), car ne pas le faire n'est probablement pas une conception saine.

Certains types d'événements ne sont pas masquables et peuvent être rapportés dans revents, qu'ils aient été demandés ou non dans events.

Les types d'événements suivants sont pris en charge :

SSL_POLL_EVENT_F
Échec du sondage. Cet événement est déclenché lorsqu'une ressource n'a pas pu être sondée. Il est distinct d'une condition d'exception signalée sur une ressource qui a été sondée avec succès et représente un échec du processus de sondage lui-même par rapport à une ressource. Cela peut signifier que SSL_poll() ne prend pas en charge le type de ressource spécifié.

Lorsque cet événement est déclenché sur au moins un élément de items, SSL_poll() retournera 0 et la pile ERR contiendra des informations relatives au premier élément de items avec SSL_POLL_EVENT_F défini. Voir "VALEURS DE RETOUR" pour plus d'informations.

Ce type d'événement peut être déclenché même s'il n'a pas été demandé dans events ; la spécification de ce type d'événement dans events ne fait rien.

SSL_POLL_EVENT_EL
Erreur au niveau de l'écouteur. Cet événement est déclenché lorsqu'un écouteur a échoué, par exemple si un BIO réseau a rencontré une erreur permanente.

Cet événement n'est jamais déclenché sur des objets qui ne sont pas des écouteurs, mais son occurrence provoquera le déclenchement de SSL_POLL_EVENT_EC sur toutes les connexions dépendantes.

SSL_POLL_EVENT_EC
Erreur au niveau de la connexion. Cet événement est déclenché lorsqu'une connexion a échoué. En particulier, il est déclenché lorsqu'une connexion commence à se terminer.

Cet événement n'est jamais déclenché sur des objets qui ne sont pas des connexions.

SSL_POLL_EVENT_ECD
Erreur au niveau de la connexion (vidée). Cet événement est déclenché lorsqu'une connexion a fini de se terminer et a atteint l'état de terminé. Cet événement se produira généralement après un intervalle de temps après que l'événement SSL_POLL_EVENT_EC a été déclenché sur une connexion.

Cet événement n'est jamais déclenché sur des objets qui ne sont pas des connexions.

SSL_POLL_EVENT_ER
Erreur en direction de lecture. Pour QUIC, ceci est déclenché uniquement dans le cas où un flux a une partie de lecture et que cette partie de lecture a été réinitialisée par le pair (par exemple, en utilisant une trame RESET_STREAM).
SSL_POLL_EVENT_EW
Erreur en direction d'écriture. Pour QUIC, ceci est déclenché uniquement dans le cas où un flux a une partie d'écriture et que cette partie d'écriture a été réinitialisée par le pair en utilisant une trame STOP_SENDING.
SSL_POLL_EVENT_R
Lisible. Cet événement est déclenché lorsqu'un objet SSL de flux QUIC (ou un objet SSL de connexion QUIC avec un flux par défaut attaché) a des données d'application en attente d'être lues à l'aide de SSL_read_ex(3), ou un événement FIN tel que représenté par SSL_ERROR_ZERO_RETURN en attente d'être lu.

Il n'est pas déclenché dans le cas où la partie réception de flux QUIC est réinitialisée par le pair ; voir SSL_POLL_EVENT_ER.

SSL_POLL_EVENT_W
Écrivable. Cet événement est déclenché lorsqu'un objet SSL de flux QUIC (ou un objet SSL de connexion QUIC avec un flux par défaut attaché) peut accepter plus de données d'application à l'aide de SSL_write_ex(3).

Cet événement n'est jamais déclenché par un flux en lecture seule.

Cet événement n'est jamais déclenché par un flux dont la partie d'envoi a été conclue normalement (comme avec SSL_stream_conclude(3)) ou réinitialisée localement (comme avec SSL_stream_reset(3)).

Cet événement ne garantit pas qu'un appel ultérieur à SSL_write_ex(3) réussira.

SSL_POLL_EVENT_IC
Cet événement, qui n'est déclenché que par un objet SSL d'écouteur QUIC, est déclenché lorsqu'une ou plusieurs connexions QUIC entrantes sont disponibles pour être acceptées à l'aide de SSL_accept_connection(3).
SSL_POLL_EVENT_ISB
Cet événement, qui n'est déclenché que par un objet SSL de connexion QUIC, est déclenché lorsqu'un ou plusieurs flux bidirectionnels entrants sont disponibles pour être acceptés à l'aide de SSL_accept_stream(3).
SSL_POLL_EVENT_ISU
Cet événement, qui n'est déclenché que par un objet SSL de connexion QUIC, est déclenché lorsqu'un ou plusieurs flux unidirectionnels entrants sont disponibles pour être acceptés à l'aide de SSL_accept_stream(3).
SSL_POLL_EVENT_OSB
Cet événement, qui n'est déclenché que par un objet SSL de connexion QUIC, est déclenché lorsque le contrôle de flux de création de flux QUIC permet actuellement la création d'au moins un flux bidirectionnel supplémentaire.
SSL_POLL_EVENT_OSU
Cet événement, qui n'est déclenché que par un objet SSL de connexion QUIC, est déclenché lorsque le contrôle de flux de création de flux QUIC permet actuellement la création d'au moins un flux unidirectionnel supplémentaire.

LIMITATIONS

SSL_poll(), tel qu'implémenté actuellement, présente la limitation suivante :

•
Seules les structures BIO_POLL_DESCRIPTOR de type BIO_POLL_DESCRIPTOR_TYPE_SSL, référençant des objets SSL d'écouteur, de connexion ou de flux QUIC, sont prises en charge.

Cette limitation pourra être révisée dans une future version d'OpenSSL.

VALEURS DE RETOUR

SSL_poll() retourne 1 en cas de succès et 0 en cas d'échec.

Sauf si le pointeur items lui-même est invalide, SSL_poll() initialisera toujours les champs revents de tous les éléments du tableau d'entrée lors du retour, même s'il retourne un échec.

Si result_count n'est pas NULL, il est toujours écrit avec le nombre d'éléments dans le tableau avec des champs revents non nuls, même si l'appel SSL_poll() retourne un échec.

Il est possible que result_count soit écrit comme 0 même si l'appel SSL_poll() retourne un succès, notamment si aucun événement n'a été produit mais que le processus de sondage a réussi (par exemple, en mode non bloquant) ou a expiré.

Il est possible que result_count soit écrit comme une valeur non nulle si l'appel SSL_poll() retourne un échec, par exemple en raison d'événements SSL_POLL_EVENT_F, ou parce que certains événements ont été détectés et produits avant de rencontrer une condition d'échec lors du traitement d'une entrée suivante dans le tableau items.

Si au moins un événement SSL_POLL_EVENT_F est produit, SSL_poll() est garanti de retourner 0 et garanti de placer au moins un ERR sur la pile d'erreurs décrivant le premier SSL_POLL_EVENT_F produit. Les informations détaillées sur les éventuels événements SSL_POLL_EVENT_F supplémentaires ne sont pas disponibles. SSL_poll() peut ou peut ne pas produire plus d'un événement SSL_POLL_EVENT_F à la fois.

"Normal" les événements représentant des conditions d'E/S exceptionnelles qui ne constituent pas un échec du mécanisme SSL_poll() lui-même ne sont pas considérés comme des erreurs par SSL_poll() et sont plutôt représentés par leur propre type d'événement ; voir "TYPES D'ÉVÉNEMENTS" pour les détails.

L'appelant peut établir la signification des valeurs de retour et de sortie de SSL_poll() comme suit :

  • Si SSL_poll() retourne 1 et result_count est zéro, l'opération a expiré avant que toute ressource ne soit prête.
  • Si SSL_poll() retourne 1 et result_count est non nul, ce nombre d'événements a été produit.
  • Si SSL_poll() retourne 0 et result_count est zéro, l'appelant a commis une erreur d'utilisation de base ; vérifiez la pile ERR pour les détails.
  • Si SSL_poll() retourne 0 et result_count est non nul, inspectez le tableau items pour les structures SSL_POLL_ITEM avec le type d'événement SSL_POLL_EVENT_F déclenché dans revents. Les entrées ajoutées à la pile ERR (dont il est garanti qu'il y en a au moins une) reflètent la cause de l'échec du premier élément de items avec SSL_POLL_EVENT_F déclenché. Notez qu'il peut y avoir des événements autres que SSL_POLL_EVENT_F produits pour des éléments qui précèdent le premier élément avec SSL_POLL_EVENT_F déclenché, et des événements SSL_POLL_EVENT_F supplémentaires peuvent ou non avoir été produits, les deux étant reflétés dans result_count.

HISTORIQUE

SSL_poll() a été ajouté dans OpenSSL 3.3.

Avant la version 3.5, SSL_poll() ne prenait pas en charge le fonctionnement bloquant et échouerait s'il était appelé avec un paramètre timeout NULL ou un paramètre timeout pointant vers une struct timeval qui n'était pas nulle.

Avant la version 3.5, les types d'événements SSL_POLL_EVENT_EL et SSL_POLL_EVENT_IC n'étaient pas présents.
