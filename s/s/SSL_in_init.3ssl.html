SSL_IN_INIT(3ssl) OpenSSL SSL_IN_INIT(3ssl)

NOM

SSL_in_before, SSL_in_init, SSL_is_init_finished, SSL_in_connect_init, SSL_in_accept_init, SSL_get_state - récupérer des informations sur la machine d'état de la négociation

SYNTAXE

#include <openssl/ssl.h>
int SSL_in_init(const SSL *s);
int SSL_in_before(const SSL *s);
int SSL_is_init_finished(const SSL *s);
int SSL_in_connect_init(SSL *s);
int SSL_in_accept_init(SSL *s);
OSSL_HANDSHAKE_STATE SSL_get_state(const SSL *ssl);

DESCRIPTION

SSL_in_init() renvoie 1 si la machine d'état SSL/TLS est actuellement en train de traiter ou d'attendre des messages de négociation, ou 0 sinon.

SSL_in_before() renvoie 1 si aucune négociation SSL/TLS n'a encore été initiée, ou 0 sinon.

SSL_is_init_finished() renvoie 1 si la connexion SSL/TLS est dans un état où des données applicatives entièrement protégées peuvent être transférées, ou 0 sinon.

Notez que dans certaines circonstances (par exemple, lorsque des données anticipées sont transférées), SSL_in_init(), SSL_in_before() et SSL_is_init_finished() peuvent tous renvoyer 0.

s NE DOIT PAS être NULL.

SSL_in_connect_init() renvoie 1 si s agit en tant que client et que SSL_in_init() renverrait 1, ou 0 sinon.

SSL_in_accept_init() renvoie 1 si s agit en tant que serveur et que SSL_in_init() renverrait 1, ou 0 sinon.

SSL_in_connect_init() et SSL_in_accept_init() sont implémentés comme des macros.

SSL_get_state() renvoie une valeur indiquant l'état actuel de la machine d'état de la négociation. OSSL_HANDSHAKE_STATE est un type énuméré où chaque valeur indique un état discret de la machine d'état. Notez que les futures versions d'OpenSSL peuvent définir plus d'états, donc les applications doivent s'attendre à recevoir des valeurs d'état non reconnues. Le format de nommage est composé d'un certain nombre d'éléments comme suit :

protocole_ST_rôle_message

protocole est soit TLS soit DTLS. DTLS est utilisé lorsqu'un état est spécifique au protocole DTLS. Sinon, TLS est utilisé.

rôle est CR, CW, SR ou SW pour indiquer respectivement « client lecture », « client écriture », « serveur lecture » ou « serveur écriture ».

message est le nom d'un message de négociation qui est en cours d'envoi ou qui a été envoyé, ou qui est en cours de traitement ou a été traité.

En outre, il existe quelques états spéciaux qui ne respectent pas le format ci-dessus. Ce sont :

TLS_ST_BEFORE
Aucun message de négociation n'a encore été envoyé ou reçu.
TLS_ST_OK
L'envoi/traitement des messages de négociation est terminé.
TLS_ST_EARLY_DATA
Les données anticipées sont en cours de traitement.
TLS_ST_PENDING_EARLY_DATA_END
Attente de la fin du traitement des données anticipées.

VALEURS DE RETOUR

SSL_in_init(), SSL_in_before(), SSL_is_init_finished(), SSL_in_connect_init() et SSL_in_accept_init() renvoient les valeurs indiquées ci-dessus.

SSL_get_state() renvoie l'état actuel de la négociation.
