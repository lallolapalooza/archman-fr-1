SSL_CTX_set_psk_client_callback(3ssl)

Paquet: openssl

Licences: Apache-2.0

SSL_CTX_SET_PSK_CLIENT_CALLBACK(3ssl) OpenSSL SSL_CTX_SET_PSK_CLIENT_CALLBACK(3ssl)

NOM

SSL_psk_cb_func, SSL_psk_use_session_cb_func, SSL_CTX_set_psk_client_callback, SSL_set_psk_client_callback, SSL_CTX_set_psk_use_session_callback, SSL_set_psk_use_session_callback - définir le rappel client PSK

SYNOPIS

#include <openssl/ssl.h>
typedef int (*SSL_psk_use_session_cb_func)(SSL *ssl, const EVP_MD *md,
                                           const unsigned char **id,
                                           size_t *idlen,
                                           SSL_SESSION **sess);
void SSL_CTX_set_psk_use_session_callback(SSL_CTX *ctx,
                                          SSL_psk_use_session_cb_func cb);
void SSL_set_psk_use_session_callback(SSL *s, SSL_psk_use_session_cb_func cb);
typedef unsigned int (*SSL_psk_client_cb_func)(SSL *ssl,
                                               const char *hint,
                                               char *identity,
                                               unsigned int max_identity_len,
                                               unsigned char *psk,
                                               unsigned int max_psk_len);
void SSL_CTX_set_psk_client_callback(SSL_CTX *ctx, SSL_psk_client_cb_func cb);
void SSL_set_psk_client_callback(SSL *ssl, SSL_psk_client_cb_func cb);

DESCRIPTION

Une application client souhaitant utiliser les PSK de TLSv1.3 doit utiliser soit SSL_CTX_set_psk_use_session_callback(), soit SSL_set_psk_use_session_callback(), selon le cas. Ces fonctions ne peuvent pas être utilisées pour les PSK de TLSv1.2 et versions antérieures.

La fonction de rappel reçoit un pointeur vers la connexion SSL dans ssl.

Lors du premier appel de la fonction de rappel pour une connexion, le paramètre md est NULL. Dans certaines circonstances, la fonction de rappel sera appelée une deuxième fois. Dans ce cas, le serveur aura déjà spécifié un chiffrement à utiliser et le PSK doit être compatible avec le hachage pour ce chiffrement. Le hachage sera donné dans md. Le PSK retourné par la fonction de rappel peut être différent entre la première et la seconde appel.

En cas de succès, la fonction de rappel doit stocker un pointeur vers un identifiant du PSK dans *id. La longueur de l'identifiant en octets doit être stockée dans *idlen. La mémoire pointée par *id reste la propriété de l'application et doit être libérée par celle-ci selon les besoins une fois la négociation terminée.

De plus, la fonction de rappel doit stocker un pointeur vers un objet SSL_SESSION dans *sess. Ceci est utilisé comme base pour le PSK et doit, au minimum, avoir les champs suivants définis :

La clé maître
Celle-ci peut être définie via un appel à SSL_SESSION_set1_master_key(3).
Un chiffrement
Seul le hachage de négociation associé au chiffrement est pertinent pour le PSK (le serveur peut ensuite négocier n'importe quel chiffrement compatible avec le hachage). L'application peut utiliser n'importe quel chiffrement TLSv1.3. Si md n'est pas NULL, le hachage de négociation du chiffrement doit être le même. Le chiffrement peut être défini via un appel à <SSL_SESSION_set_cipher(3)>. Le hachage de négociation d'un objet SSL_CIPHER peut être vérifié en utilisant <SSL_CIPHER_get_handshake_digest(3)>.
La version du protocole
Celle-ci peut être définie via un appel à SSL_SESSION_set_protocol_version(3) et doit être TLS1_3_VERSION.

De plus, la valeur maximale des données anticipées doit être définie via un appel à SSL_SESSION_set_max_early_data(3) si le PSK sera utilisé pour l'envoi de données anticipées.

Alternativement, un SSL_SESSION créé à partir d'une précédente négociation non-PSK peut également être utilisé comme base pour un PSK.

La propriété de l'objet SSL_SESSION est transférée à la bibliothèque OpenSSL et ne doit donc pas être libérée par l'application.

Il est également possible que la fonction de rappel réussisse sans fournir de PSK. Dans ce cas, aucun PSK ne sera envoyé au serveur mais la négociation se poursuivra. Pour ce faire, la fonction de rappel doit retourner avec succès et s'assurer que *sess est NULL. Le contenu de *id et *idlen sera ignoré.

Une application client souhaitant utiliser des chiffrements PSK pour TLSv1.2 et versions antérieures doit fournir une fonction de rappel différente. Cette fonction sera appelée lorsque le client envoie le message ClientKeyExchange au serveur.

Le but de la fonction de rappel est de sélectionner l'identité PSK et la clé pré-partagée à utiliser pendant la phase d'établissement de la connexion.

La fonction de rappel est définie à l'aide des fonctions SSL_CTX_set_psk_client_callback() ou SSL_set_psk_client_callback(). La fonction de rappel reçoit la connexion dans le paramètre ssl, un indice d'identité PSK se terminant par un caractère NUL envoyé par le serveur dans le paramètre hint, un tampon identity d'une longueur de max_identity_len octets (y compris le terminateur NUL) où l'identité résultante se terminant par un caractère NUL doit être stockée, et un tampon psk d'une longueur de max_psk_len octets où la clé pré-partagée résultante doit être stockée.

La fonction de rappel pour une utilisation dans TLSv1.2 fonctionnera également dans TLSv1.3 bien qu'il soit recommandé d'utiliser SSL_CTX_set_psk_use_session_callback() ou SSL_set_psk_use_session_callback() à cette fin à la place. Si TLSv1.3 a été négocié, OpenSSL vérifiera d'abord si une fonction de rappel a été définie via SSL_CTX_set_psk_use_session_callback() ou SSL_set_psk_use_session_callback() et l'utilisera de préférence. Si aucune fonction de rappel de ce type n'est présente, il vérifiera si une fonction de rappel a été définie via SSL_CTX_set_psk_client_callback() ou SSL_set_psk_client_callback() et l'utilisera. Dans ce cas, la valeur de hint sera toujours NULL et le hachage de négociation sera par défaut SHA-256 pour tout PSK retourné. Les échanges de données anticipées TLSv1.3 sont possibles dans les connexions PSK uniquement avec la fonction de rappel SSL_psk_use_session_cb_func, et ne sont pas possibles avec la fonction de rappel SSL_psk_client_cb_func.

NOTES

Notez que le paramètre hint donné à la fonction de rappel peut être NULL.

Une connexion établie via un PSK TLSv1.3 apparaîtra comme si la reprise de session avait eu lieu, de sorte que SSL_session_reused(3) retournera vrai.

Il n'y a pas de problèmes de sécurité connus liés au partage du même PSK entre TLSv1.2 (ou versions antérieures) et TLSv1.3. Cependant, la RFC contient cette mise en garde :

"Bien qu'il n'y ait aucun moyen connu par lequel le même PSK pourrait produire des sorties liées dans les deux versions, seule une analyse limitée a été effectuée. Les implémentations peuvent assurer la sécurité contre les sorties liées entre protocoles en ne réutilisant pas les PSK entre TLS 1.3 et TLS 1.2."

VALEUR DE RETOUR

Les valeurs de retour de la fonction de rappel SSL_psk_client_cb_func sont interprétées comme suit :

En cas de succès (la fonction de rappel a trouvé une identité PSK et une clé pré-partagée à utiliser), la longueur (> 0) de psk en octets est retournée.

Sinon ou en cas d'erreur, la fonction de rappel doit retourner 0. Dans ce cas, l'établissement de la connexion échoue.

La fonction de rappel SSL_psk_use_session_cb_func doit retourner 1 en cas de succès ou 0 en cas d'échec. En cas d'échec, l'établissement de la connexion échoue.

HISTORIQUE
