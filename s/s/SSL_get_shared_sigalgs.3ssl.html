SSL_GET_SHARED_SIGALGS(3ssl) OpenSSL SSL_GET_SHARED_SIGALGS(3ssl)

NOM

SSL_get_shared_sigalgs, SSL_get_sigalgs - obtenir les algorithmes de signature pris en charge

SYNTAXE

#include <openssl/ssl.h>
int SSL_get_shared_sigalgs(SSL *s, int idx,
                           int *psign, int *phash, int *psignhash,
                           unsigned char *rsig, unsigned char *rhash);
int SSL_get_sigalgs(SSL *s, int idx,
                    int *psign, int *phash, int *psignhash,
                    unsigned char *rsig, unsigned char *rhash);

DESCRIPTION

SSL_get_shared_sigalgs() renvoie des informations sur les algorithmes de signature partagés pris en charge par le pair s. Le paramètre idx indique l'indice de l'algorithme de signature partagé à renvoyer, en commençant par zéro. Le NID de l'algorithme de signature est écrit dans *psign, le NID du hachage dans *phash et le NID de la signature et du hachage dans *psignhash. Les valeurs brutes de signature et de hachage sont écrites dans *rsig et *rhash.

SSL_get_sigalgs() est similaire à SSL_get_shared_sigalgs(), sauf qu'il renvoie des informations sur tous les algorithmes de signature pris en charge par s dans l'ordre où ils ont été envoyés par le pair.

VALEURS DE RETOUR

SSL_get_shared_sigalgs() et SSL_get_sigalgs() renvoient le nombre d'algorithmes de signature ou 0 si le paramètre idx est hors limites.

NOTES

Ces fonctions sont généralement appelées à des fins de débogage (pour signaler les préférences du pair) ou lorsque une application souhaite un contrôle plus fin sur la sélection des certificats. La plupart des applications s'appuieront sur la gestion interne et n'auront pas besoin de les appeler.

Si une application n'est intéressée que par l'algorithme de signature partagé le plus préféré, elle peut simplement définir idx à zéro.

N'importe lequel ou tous les paramètres psign, phash, psignhash, rsig ou rhash peuvent être définis sur NULL si la valeur n'est pas requise. En les définissant tous sur NULL et en définissant idx sur zéro, le nombre total d'algorithmes de signature peut être déterminé : qui peut être zéro.

Ces fonctions doivent être appelées après que le pair a envoyé une liste d'algorithmes de signature pris en charge : après un client hello (pour les serveurs) ou une requête de certificat (pour les clients). Elles peuvent (par exemple) être appelées dans la fonction de rappel de certificat.

Seuls TLS 1.2, TLS 1.3 et DTLS 1.2 prennent actuellement en charge les algorithmes de signature. Si ces fonctions sont appelées sur une version antérieure de TLS ou DTLS, zéro est renvoyé.

Les algorithmes de signature partagés renvoyés par SSL_get_shared_sigalgs() sont ordonnés selon la configuration et les préférences du pair.

Les valeurs brutes correspondent à la forme sur le fil telle que définie par RFC5246 et suivants. Les NIDs sont des équivalents OpenSSL. Par exemple, si le pair a envoyé sha256(4) et rsa(1), alors *rhash serait 4, *rsign 1, *phash NID_sha256, *psig NID_rsaEncryption et *psignhash NID_sha256WithRSAEncryption.

Si un algorithme de signature n'est pas reconnu, les NIDs correspondants seront définis sur NID_undef. Cela peut être parce que la valeur n'est pas prise en charge, n'est pas une combinaison appropriée (par exemple MD5 et DSA) ou que l'algorithme de signature n'utilise pas de hachage (par exemple Ed25519).
