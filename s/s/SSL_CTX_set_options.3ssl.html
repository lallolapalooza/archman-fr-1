SSL_CTX_SET_OPTIONS(3ssl) OpenSSL SSL_CTX_SET_OPTIONS(3ssl)

NOM

SSL_CTX_set_options, SSL_set_options, SSL_CTX_clear_options, SSL_clear_options, SSL_CTX_get_options, SSL_get_options, SSL_get_secure_renegotiation_support - manipuler les options SSL

SYNTAXE

#include <openssl/ssl.h>
uint64_t SSL_CTX_set_options(SSL_CTX *ctx, uint64_t options);
uint64_t SSL_set_options(SSL *ssl, uint64_t options);
uint64_t SSL_CTX_clear_options(SSL_CTX *ctx, uint64_t options);
uint64_t SSL_clear_options(SSL *ssl, uint64_t options);
uint64_t SSL_CTX_get_options(const SSL_CTX *ctx);
uint64_t SSL_get_options(const SSL *ssl);
long SSL_get_secure_renegotiation_support(SSL *ssl);

DESCRIPTION

SSL_CTX_set_options() ajoute les options définies par le masque de bits dans options à ctx. ctx ne DOIT PAS être NULL. Les options déjà définies auparavant ne sont pas effacées !

SSL_set_options() ajoute les options définies par le masque de bits dans options à ssl. Les options déjà définies auparavant ne sont pas effacées !

SSL_CTX_clear_options() efface les options définies par le masque de bits dans options de ctx.

SSL_clear_options() efface les options définies par le masque de bits dans options de ssl.

SSL_CTX_get_options() retourne les options définies pour ctx.

SSL_get_options() retourne les options définies pour ssl.

SSL_get_secure_renegotiation_support() indique si le pair prend en charge la renégociation sécurisée. Notez que ceci est implémenté via une macro.

NOTES

Le comportement de la bibliothèque SSL peut être modifié en définissant plusieurs options. Les options sont codées sous forme de masques de bits et peuvent être combinées par une opération ou binaire (|).

SSL_CTX_set_options() et SSL_set_options() affectent le comportement (externe) du protocole de la bibliothèque SSL. Le comportement (interne) de l'API peut être modifié en utilisant les fonctions similaires SSL_CTX_set_mode(3) et SSL_set_mode().

Pendant une négociation, les paramètres d'options de l'objet SSL sont utilisés. Lorsqu'un nouvel objet SSL est créé à partir d'un contexte en utilisant SSL_new(), le réglage d'option actuel est copié. Les modifications apportées à ctx n'affectent pas les objets SSL déjà créés. SSL_clear() n'affecte pas les réglages.

Les options de correction de bug suivantes sont disponibles :

SSL_OP_CRYPTOPRO_TLSEXT_BUG
Ajoute une extension server-hello de la première version du brouillon cryptopro lors de la négociation d'une suite de chiffrement GOST. Nécessaire pour l'interopérabilité avec CryptoPro CSP 3.x.
SSL_OP_DONT_INSERT_EMPTY_FRAGMENTS
Désactive une contre-mesure contre une vulnérabilité du protocole SSL 3.0/TLS 1.0 affectant les chiffrements CBC, qui ne peuvent pas être gérés par certaines implémentations SSL défectueuses. Cette option n'a aucun effet pour les connexions utilisant d'autres chiffrements.
SSL_OP_SAFARI_ECDHE_ECDSA_BUG
Ne pas préférer les chiffrements ECDHE-ECDSA lorsque le client semble être Safari sur OS X. OS X 10.8..10.8.3 a un support défectueux pour les chiffrements ECDHE-ECDSA.
SSL_OP_TLSEXT_PADDING
Ajoute une extension de remplissage pour garantir que la taille de ClientHello ne se situe jamais entre 256 et 511 octets. Ceci est nécessaire comme solution de contournement pour certaines implémentations.
SSL_OP_ALL
Toutes les corrections de bugs ci-dessus.

Il est généralement sûr d'utiliser SSL_OP_ALL pour activer les options de correction de bugs si la compatibilité avec des implémentations un peu défectueuses est souhaitée.

Les options de modification suivantes sont disponibles :

SSL_OP_ALLOW_CLIENT_RENEGOTIATION
La renégociation initiée par le client est désactivée par défaut. Utilisez cette option pour l'activer.
SSL_OP_ALLOW_NO_DHE_KEX
Dans TLSv1.3, autoriser un mode d'échange de clés non basé sur (ec)dhe lors de la reprise. Cela signifie qu'il n'y aura pas de confidentialité persistante pour la session reprise.
SSL_OP_PREFER_NO_DHE_KEX
Dans TLSv1.3, lors de la reprise, laisser le serveur préférer un mode d'échange de clés non basé sur (ec)dhe plutôt qu'un mode basé sur (ec)dhe. Ignoré sans que SSL_OP_ALLOW_NO_DHE_KEX soit également défini. Toujours ignoré côté client.
SSL_OP_ALLOW_UNSAFE_LEGACY_RENEGOTIATION
Autoriser la renégociation héritée non sécurisée entre OpenSSL et les clients ou serveurs non patchés. Voir la section RENÉGOCIATION SÉCURISÉE pour plus de détails.
SSL_OP_SERVER_PREFERENCE
Lors du choix d'un chiffrement, d'une signature, d'une courbe (TLS 1.2) ou d'un groupe (TLS 1.3), utiliser les préférences du serveur au lieu des préférences du client. Lorsque non défini, le serveur SSL suit toujours les préférences du client. Lorsqu'il est défini, le serveur SSL choisit en suivant ses propres préférences. L'utilisation de l'ancien nom, quelque peu trompeur, SSL_OP_CIPHER_SERVER_PREFERENCE est toujours possible mais déconseillée.
SSL_OP_CISCO_ANYCONNECT
Utiliser l'identifiant de version de Cisco pour DTLS_BAD_VER lors de l'établissement d'une connexion DTLSv1. Uniquement disponible lors de l'utilisation de l'API dépréciée DTLSv1_client_method().
SSL_OP_CLEANSE_PLAINTEXT
Par défaut, les objets SSL TLS et QUIC conservent une copie des données d'application en clair reçues dans un tampon statique jusqu'à ce qu'elles soient écrasées par la portion de données suivante. Lors de l'activation de SSL_OP_CLEANSE_PLAINTEXT, les données d'application déchiffrées sont effacées en appelant OPENSSL_cleanse(3) après avoir passé les données à l'application. Les données sont également effacées lors de la libération de la connexion (par exemple, SSL_free(3)).

Comme OpenSSL n'efface que les tampons internes, l'application reste responsable de l'effacement de tous les autres tampons. Cela s'applique notamment aux tampons passés aux fonctions telles que SSL_read(3), SSL_peek(3), mais aussi comme SSL_write(3).

Les connexions TLS ne mettent pas en tampon les données à envoyer en clair. Les objets de flux QUIC mettent en tampon les données en clair à envoyer et cette option entraînera également l'effacement de ces données lorsqu'elles sont rejetées.

Cette option peut être définie différemment sur des objets de flux QUIC individuels et n'a aucun effet sur les objets de connexion QUIC (sauf lorsqu'un flux par défaut est utilisé).

SSL_OP_COOKIE_EXCHANGE
Active l'échange de cookies tel que décrit dans la RFC4347 Section 4.2.1. N'affecte que les connexions DTLS.
SSL_OP_DISABLE_TLSEXT_CA_NAMES
Désactive les noms CA TLS Extension. Vous pourriez vouloir le désactiver pour des raisons de sécurité ou pour la compatibilité avec certaines implémentations TLS sous Windows qui plantent lorsque cette extension est supérieure à 1024 octets.
SSL_OP_ENABLE_KTLS
Active l'utilisation de TLS par le noyau. Pour bénéficier du TLS par le noyau, OpenSSL doit avoir été compilé avec le support pour cela, et il doit être supporté par les suites de chiffrement et extensions négociées. Les suites de chiffrement et extensions spécifiques qui sont supportées peuvent varier selon la plateforme et la version du noyau.

Le chemin de données TLS par le noyau implémente la couche d'enregistrement et l'algorithme de chiffrement. Le noyau utilisera le meilleur matériel disponible pour le chiffrement. L'utilisation du chemin de données du noyau devrait réduire l'empreinte mémoire d'OpenSSL car aucun mise en tampon n'est nécessaire. De plus, le débit devrait s'améliorer car la copie de données est évitée lorsque les données utilisateur sont chiffrées en mémoire du noyau au lieu du chiffrement puis copie habituelle vers le noyau.

Le TLS par le noyau pourrait ne pas supporter toutes les fonctionnalités d'OpenSSL. Par exemple, la renégociation et la définition de la taille maximale des fragments ne sont pas possibles à partir de Linux 4

SSL_OP_NO_TICKET
SSL/TLS prend en charge deux mécanismes pour reprendre des sessions : les identifiants de session et les tickets de session persistants.
Lors de l'utilisation des identifiants de session, une copie des informations de session est stockée sur le serveur et un identifiant unique est envoyé au client. Lorsque le client souhaite reprendre, il fournit l'identifiant unique afin que le serveur puisse récupérer les informations de session depuis son cache.
Lors de l'utilisation des tickets de session persistants, le serveur utilise une clé de chiffrement de ticket pour chiffrer les informations de session. Ces données chiffrées sont envoyées au client sous forme de "ticket". Lorsque le client souhaite reprendre, il renvoie les données chiffrées au serveur. Le serveur utilise sa clé pour déchiffrer les données et reprendre la session. Ainsi, le serveur peut fonctionner de manière sans état - aucune information de session locale ne doit être stockée.
Le protocole TLSv1.3 ne prend en charge que les tickets et non directement les identifiants de session. Cependant, OpenSSL permet deux modes de fonctionnement des tickets en TLSv1.3 : statique et non statique. Les tickets non statiques fonctionnent de manière similaire à ceux de TLSv1.2 et versions antérieures. Les tickets non statiques imitent le comportement des identifiants de session disponibles dans TLSv1.2 et versions antérieures. Les informations de session sont stockées sur le serveur, et l'identifiant de session est envoyé dans un ticket et renvoyé au client. Lorsque le client souhaite reprendre, il présente un ticket dans le même mode que pour les tickets non statiques. Le serveur peut extraire l'identifiant de session du ticket et récupérer les informations de session depuis son cache.
Par défaut, OpenSSL utilisera des tickets non statiques. L'option SSL_OP_NO_TICKET empêchera l'émission de tickets. En TLSv1.2 et versions antérieures, cela signifie qu'aucun ticket n'est envoyé au client. En TLSv1.3, un ticket statique est envoyé. Il s'agit d'une option côté serveur.
En TLSv1.3, il est possible de supprimer tous les tickets (statiques et non statiques) en appelant SSL_CTX_set_num_tickets(3) ou SSL_set_num_tickets(3).
SSL_OP_PRIORITIZE_CHACHA
Lorsque SSL_OP_SERVER_PREFERENCE est activée, le chiffrement ChaCha20-Poly1305 est reclassé en haut de la liste des chiffrements du serveur si un chiffrement ChaCha20-Poly1305 est en haut de la liste des chiffrements du client. Cela aide les clients (par exemple, mobiles) à utiliser ChaCha20-Poly1305 si ce chiffrement se trouve quelque part dans la liste des chiffrements du serveur, mais permet toujours aux autres clients d'utiliser AES et d'autres chiffrements. Nécessite SSL_OP_SERVER_PREFERENCE.

Certains clients violent cette règle en s'adaptant à la réponse du serveur. (Exemple : le client envoie un hello SSLv2 et accepte jusqu'à SSLv3.1=TLSv1, le serveur ne comprend que jusqu'à SSLv3. Dans ce cas, le client devrait continuer à utiliser l'annonce SSLv3.1=TLSv1. Certains clients reviennent à SSLv3 en fonction de la réponse du serveur et violent la protection contre les retours arrière de version.)

SECURE RENEGOTIATION

OpenSSL tente toujours d'utiliser la renégociation sécurisée telle que décrite dans la RFC5746. Cela permet de contrer l'attaque par préfixe décrite dans la CVE-2009-3555 et ailleurs.

Cette attaque a des conséquences de grande portée dont les auteurs d'applications devraient être conscients. Dans la description ci-dessous, une implémentation prenant en charge la renégociation sécurisée est désignée comme patchée. Un serveur ne prenant pas en charge la renégociation sécurisée est désigné comme non patché.

Les sections suivantes décrivent les opérations permises par l'implémentation de renégociation sécurisée d'OpenSSL.

Client et serveur patchés

Les connexions et la renégociation sont toujours autorisées par les implémentations OpenSSL.

Client non patché et serveur OpenSSL patché

La connexion initiale réussit mais la renégociation par le client est refusée par le serveur avec une alerte d'avertissement no_renegotiation si TLS v1.0 est utilisé ou une alerte fatale handshake_failure en SSL v3.0.

Si le serveur OpenSSL patché tente de renégocier, une alerte fatale handshake_failure est envoyée. Ceci est dû au fait que le code du serveur peut ne pas être conscient de la nature non patchée du client.

Si l'option SSL_OP_ALLOW_UNSAFE_LEGACY_RENEGOTIATION est définie, alors la renégociation réussit toujours.

Client OpenSSL patché et serveur non patché

Si l'option SSL_OP_LEGACY_SERVER_CONNECT ou SSL_OP_ALLOW_UNSAFE_LEGACY_RENEGOTIATION est définie, alors les connexions initiales et la renégociation entre clients OpenSSL patchés et serveurs non patchés réussissent. Si aucune des options n'est définie, alors les connexions initiales aux serveurs non patchés échoueront.

Définir l'option SSL_OP_LEGACY_SERVER_CONNECT a des implications en matière de sécurité ; les clients qui acceptent de se connecter à des serveurs qui n'implémentent pas la renégociation sécurisée RFC 5746 sont soumis à des attaques telles que CVE-2009-3555.

Les applications clientes OpenSSL souhaitant s'assurer qu'elles peuvent se connecter à des serveurs non patchés devraient toujours définir SSL_OP_LEGACY_SERVER_CONNECT.

Les applications clientes OpenSSL qui souhaitent s'assurer qu'elles ne peuvent pas se connecter à des serveurs non patchés (et ainsi éviter tout problème de sécurité) devraient toujours effacer SSL_OP_LEGACY_SERVER_CONNECT en utilisant SSL_CTX_clear_options() ou SSL_clear_options().

La différence entre les options SSL_OP_LEGACY_SERVER_CONNECT et SSL_OP_ALLOW_UNSAFE_LEGACY_RENEGOTIATION est que SSL_OP_LEGACY_SERVER_CONNECT permet les connexions initiales et la renégociation sécurisée entre les clients OpenSSL et les serveurs non patchés uniquement, tandis que SSL_OP_ALLOW_UNSAFE_LEGACY_RENEGOTIATION permet les connexions initiales et la renégociation entre clients ou serveurs OpenSSL et non patchés.

Ces options s'appliquent aux objets SSL faisant référence à un flux QUIC :

SSL_OP_CLEANSE_PLAINTEXT

Les options sur les connexions QUIC sont initialisées à partir des options définies sur SSL_CTX avant la création d'un objet SSL de connexion QUIC. Les options sur les flux QUIC sont initialisées à partir des options configurées sur l'objet SSL de connexion QUIC à partir duquel ils sont créés.

La définition d'options relatives aux flux QUIC sur un objet SSL de connexion QUIC n'a pas d'effet direct sur l'objet SSL de connexion QUIC lui-même, mais modifiera les options définies sur le flux par défaut (s'il en existe un) et déterminera également les options par défaut définies sur tous les flux futurs qui seront créés.

Les autres options non mentionnées ci-dessus n'ont aucun effet et seront ignorées.

Les options relatives aux flux QUIC peuvent également être définies directement sur les objets SSL de flux QUIC. La définition d'options liées à la connexion sur un tel objet n'a aucun effet.

VALEURS DE RETOUR

SSL_CTX_set_options() et SSL_set_options() retournent le nouveau masque d'options après avoir ajouté options.

SSL_CTX_clear_options() et SSL_clear_options() retournent le nouveau masque d'options après avoir effacé options.

SSL_CTX_get_options() et SSL_get_options() retournent le masque d'options actuel.

SSL_get_secure_renegotiation_support() retourne 1 si le pair prend en charge la renégociation sécurisée et 0 s'il ne la prend pas en charge.

VOIR AUSSI

ssl(7), SSL_new(3), SSL_clear(3), SSL_shutdown(3) SSL_CTX_set_tmp_dh_callback(3), SSL_CTX_set_min_proto_version(3), openssl-dhparam(1)

HISTORIQUE

La tentative d'utiliser toujours la renégociation sécurisée a été ajoutée dans OpenSSL 0.9.8m.

Les options SSL_OP_PRIORITIZE_CHACHA et SSL_OP_NO_RENEGOTIATION ont été ajoutées dans OpenSSL 1.1.1.

Les options SSL_OP_NO_EXTENDED_MASTER_SECRET et SSL_OP_IGNORE_UNEXPECTED_EOF ont été ajoutées dans OpenSSL 3.0.

Les constantes SSL_OP_ et les paramètres et valeurs de retour correspondants des fonctions affectées ont été changés en type "uint64_t" dans OpenSSL 3.0. Pour cette raison, il n'est plus possible d'utiliser les valeurs macro SSL_OP_ dans les conditions de préprocesseur "#if". Cependant, il est toujours possible de tester si ces macros sont définies ou non.

À partir d'OpenSSL 3.6, l'utilisation de la constante SSL_OP_CIPHER_SERVER_PREFERENCE est déconseillée et sa sémantique est devenue disponible en utilisant la constante nommée plus justement SSL_OP_SERVER_PREFERENCE.

SSL_CTX_set_options(3ssl)

SSL_CTX_set_options, SSL_CTX_clear_options, SSL_CTX_get_options, SSL_set_options, SSL_clear_options, SSL_get_options — définir et obtenir les options SSL/TLS

NOM

SSL_CTX_set_options, SSL_CTX_clear_options, SSL_CTX_get_options, SSL_set_options, SSL_clear_options, SSL_get_options — définir et obtenir les options SSL/TLS

SYNTAXIS


#include <openssl/ssl.h>

long SSL_CTX_set_options(SSL_CTX *ctx, long options);
long SSL_CTX_clear_options(SSL_CTX *ctx, long options);
long SSL_CTX_get_options(const SSL_CTX *ctx);

long SSL_set_options(SSL *ssl, long options);
long SSL_clear_options(SSL *ssl, long options);
long SSL_get_options(const SSL *ssl);

DESCRIPTION

SSL_CTX_set_options() définit les bits d'options spécifiés dans options pour le contexte SSL ctx. Les options sont des drapeaux qui modifient le comportement du protocole SSL/TLS. La valeur retournée est l'ensemble des options, y compris celles qui viennent d'être définies.

SSL_CTX_clear_options() efface les bits d'options spécifiés dans options pour le contexte SSL ctx. La valeur retournée est l'ensemble des options restantes.

SSL_CTX_get_options() renvoie l'ensemble actuel des options définies pour le contexte SSL ctx.

SSL_set_options(), SSL_clear_options() et SSL_get_options() font la même chose que leurs homologues SSL_CTX_*, mais pour une connexion SSL individuelle ssl au lieu d'un contexte SSL.

Les options suivantes peuvent être utilisées :

SSL_OP_ALL
Active un grand nombre d'options de compatibilité pour les versions plus anciennes de SSL/TLS. Il n'est généralement pas recommandé de l'utiliser.
SSL_OP_ALLOW_NO_DTLS
Permet la négociation de connexions DTLS (Datagram Transport Layer Security) même si le transport sous-jacent n'est pas un datagramme. Ceci peut être nécessaire pour certains scénarios RFC 5238.
SSL_OP_CIPHER_SERVER_PREFERENCE
Indique au serveur de préférer l'ordre des chiffrements spécifié dans sa propre liste, plutôt que l'ordre envoyé par le client.
SSL_OP_CISCO_ANYCONNECT
Active une ancienne extension utilisée par Cisco AnyConnect pour permettre la négociation de cipher suites avec des clés publiques RSA de petite taille.
SSL_OP_COOKIE_EXCHANGE
Nécessite un échange de cookies pour la négociation DTLS. Ceci est utilisé pour atténuer les attaques par déni de service.
SSL_OP_CRYPTLIB_RDLOCK
Active une ancienne option liée à l'utilisation de bibliothèques de chiffrement plus anciennes. Il est généralement déconseillé de l'utiliser.
SSL_OP_DONT_INSERT_EMPTY_FRAGMENTS
Désactive l'insertion de fragments vides lors de l'envoi d'enregistrements TLS. Cela peut améliorer les performances mais peut également poser des problèmes de compatibilité avec certains clients ou serveurs plus anciens.
SSL_OP_EPHEMERAL_REDUCE_OPTIMIZATION
Une optimisation pour réduire le temps de négociation en utilisant des clés éphémères.
SSL_OP_LEGACY_SERVER_CONNECT
Permet la connexion à des serveurs plus anciens qui peuvent ne pas respecter entièrement les normes TLS. Ceci peut être utilisé pour des fins de compatibilité mais peut introduire des risques de sécurité.
SSL_OP_MICROSOFT_BIG_SSLv3
Active une option pour des raisons de compatibilité avec d'anciennes implémentations Microsoft de SSLv3. Elle n'est généralement pas recommandée.
SSL_OP_MICROSOFT_SESS_ID_REVOCATION
Active une option pour des raisons de compatibilité avec d'anciennes implémentations Microsoft concernant la révocation d'ID de session.
SSL_OP_MSIE_SSLv2_SUPPORT
Active une option pour des raisons de compatibilité avec d'anciennes versions d'Internet Explorer qui utilisaient SSLv2. SSLv2 est obsolète et dangereux.
SSL_OP_NETSCAPE_CHALLENGE_CB
Active une ancienne option liée à la gestion des défis Netscape.
SSL_OP_NETSCAPE_DEMO_CIPHER_CHANGE_ORDER
Active une ancienne option pour la compatibilité avec des démonstrations de Netscape concernant le changement d'ordre des chiffrements.
SSL_OP_NETSCAPE_REUSE_CERT_TYPE_OK
Active une ancienne option pour la compatibilité avec Netscape concernant la réutilisation du type de certificat.
SSL_OP_NO_Compression
Désactive la compression. La compression peut être vulnérable à des attaques telles que CRIME.
SSL_OP_NO_DTLS_PARA
Désactive l'utilisation de paramètres spécifiques à DTLS.
SSL_OP_NO_OCSP_FREEBLOB
Désactive l'utilisation de l'extension OCSP FreeBlob.
SSL_OP_NO_QUERY_MTU
Désactive la requête de MTU pour les connexions DTLS.
SSL_OP_NO_RENEGOTIATION
Désactive la renégociation de la connexion SSL/TLS. La renégociation peut être utilisée dans des attaques de type "man-in-the-middle".
SSL_OP_NO_SESSION_REUSE
Désactive la réutilisation des sessions. La réutilisation des sessions peut améliorer les performances en évitant une négociation complète, mais elle peut également poser des problèmes de sécurité dans certains cas.
SSL_OP_NO_SSLv2
Désactive SSLv2. SSLv2 est obsolète et dangereux.
SSL_OP_NO_SSLv3
Désactive SSLv3. SSLv3 est obsolète et vulnérable à des attaques comme POODLE.
SSL_OP_NO_TLSv1
Désactive TLSv1.0.
SSL_OP_NO_TLSv1_1
Désactive TLSv1.1.
SSL_OP_NO_TLSv1_2
Désactive TLSv1.2.
SSL_OP_NO_TLSv1_3
Désactive TLSv1.3.
SSL_OP_PKCS1_CHECK_1_2_PAD
Active une option pour vérifier le padding PKCS#1 v1.5 lors du déchiffrement.
SSL_OP_PKCS1_CHECK_RETRY
Active une option pour réessayer le déchiffrement avec un padding PKCS#1 v1.5.
SSL_OP_onneur_CHECK_REQUEST
Active une option pour vérifier les requêtes avec des paramètres non standards.
SSL_OP_POST_HANDSHAKE_RENEGOTIATION
Active la renégociation après la poignée de main initiale.
SSL_OP_RANDOM_LENGTH_BITS
Définit la longueur des bits aléatoires pour les clés éphémères.
SSL_OP_RDH_TLS_REUSE_CERT_TYPE_OK
Active une option pour la compatibilité avec certains systèmes.
SSL_OP_RENEGOTIATE_CLIENT_VERSION
Active la renégociation en utilisant la version du client.
SSL_OP_SAFARI_ECDHE_ECDSA_DES_CBC_SHA
Active une option pour la compatibilité avec Safari.
SSL_OP_SEND_FALLBACK_SCSV
Indique au client d'envoyer l'extension Fallback SCSV pour empêcher les attaques de Downgrade.
SSL_OP_SINGLE_DH_USE
Utilise une clé DH unique pour chaque session.
SSL_OP_SINGLE_ECDH_USE
Utilise une clé ECDH unique pour chaque session.
SSL_OP_SSLEAY_080
Active une ancienne option pour la compatibilité avec SSLeay 0.8.0.
SSL_OP_SSLV23_HOST_HELLO
Indique que SSLv23_server_hello est utilisé.
SSL_OP_TLS_ROLLBACK_BUG
Contourne un bogue dans certaines versions de TLS qui pourrait permettre des attaques de rétrogradation.
SSL_OP_TLS_SERVER_SESSION_TICKET_TOLERANCE
Active une tolérance pour les tickets de session TLS côté serveur.
SSL_OP_TLS_TUNE_ECPOINT_FORMATS
Ajuste les formats de point EC pour la compatibilité.
SSL_OP_USE_AECDH
Active l'utilisation de AECDH (Anonymously Ephemeral Diffie-Hellman).
SSL_OP_USE_CHACHA
Active l'utilisation de la suite de chiffrement ChaCha20-Poly1305.
SSL_OP_USE_ETC2
Active l'utilisation de ETC2 (Elliptic Curve Twofish Cipher).
SSL_OP_USE_TLS_FEATURES
Indique l'utilisation de TLS Features.

NOTES

Les options peuvent être combinées à l'aide de l'opérateur OU bit à bit (|). Par exemple, pour activer à la fois SSL_OP_NO_SSLv3 et SSL_OP_NO_TLSv1, vous utiliseriez :


SSL_CTX_set_options(ctx, SSL_OP_NO_SSLv3 | SSL_OP_NO_TLSv1);

Pour effacer des options, utilisez SSL_CTX_clear_options() avec les mêmes combinaisons d'options.

Il est souvent conseillé de désactiver les versions de protocoles plus anciennes et moins sécurisées comme SSLv2, SSLv3 et TLSv1.0. La désactivation de la compression est également recommandée en raison des vulnérabilités potentielles.

RENÉGOCIATION SÉCURISÉE

Par défaut, la renégociation est activée. Cependant, la renégociation peut être exploitée dans des attaques de type "man-in-the-middle". Pour désactiver la renégociation, utilisez SSL_OP_NO_RENEGOTIATION.

Si vous devez autoriser la renégociation, il est fortement recommandé de s'assurer que la renégociation est sécurisée en utilisant des extensions TLS appropriées. OpenSSL prend en charge la renégociation sécurisée par défaut lorsque cela est possible.

VALEURS DE RETOUR

SSL_CTX_set_options() et SSL_set_options() retournent l'ensemble des options après la modification. En cas d'erreur, une valeur peut être retournée indiquant l'échec, bien que la documentation spécifique soit limitée.

SSL_CTX_clear_options() et SSL_clear_options() retournent l'ensemble des options restantes après l'effacement.

SSL_CTX_get_options() et SSL_get_options() retournent l'ensemble actuel des options.
