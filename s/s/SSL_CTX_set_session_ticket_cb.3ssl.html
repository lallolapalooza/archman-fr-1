SSL_CTX_set_session_ticket_cb(3ssl)

Paquet: openssl

Licences: Apache-2.0

SSL_CTX_set_session_ticket_cb(3ssl) OpenSSL SSL_CTX_set_session_ticket_cb(3ssl)

NOM

SSL_CTX_set_session_ticket_cb, SSL_SESSION_get0_ticket_appdata, SSL_SESSION_set1_ticket_appdata, SSL_CTX_generate_session_ticket_fn, SSL_CTX_decrypt_session_ticket_fn - gérer les données d'application pour les tickets de session

SYNOPSIS

#include <openssl/ssl.h>
typedef int (*SSL_CTX_generate_session_ticket_fn)(SSL *s, void *arg);
typedef SSL_TICKET_RETURN (*SSL_CTX_decrypt_session_ticket_fn)(SSL *s, SSL_SESSION *ss,
                                                               const unsigned char *keyname,
                                                               size_t keyname_len,
                                                               SSL_TICKET_STATUS status,
                                                               void *arg);
int SSL_CTX_set_session_ticket_cb(SSL_CTX *ctx,
                                  SSL_CTX_generate_session_ticket_fn gen_cb,
                                  SSL_CTX_decrypt_session_ticket_fn dec_cb,
                                  void *arg);
int SSL_SESSION_set1_ticket_appdata(SSL_SESSION *ss, const void *data, size_t len);
int SSL_SESSION_get0_ticket_appdata(SSL_SESSION *ss, void **data, size_t *len);

DESCRIPTION

SSL_CTX_set_set_session_ticket_cb() configure les rappels d'application gen_cb et dec_cb qui sont utilisés par un serveur pour créer et récupérer des données d'application stockées dans une session, et placées dans un ticket de session. L'une ou l'autre des fonctions de rappel peut être définie sur NULL. La valeur de arg est transmise aux rappels.

gen_cb est le rappel d'application défini qui est appelé lorsqu'un ticket de session est sur le point d'être créé. L'application peut appeler SSL_SESSION_set1_ticket_appdata() à ce stade pour ajouter des données d'application au ticket de session. La valeur de arg est la même que celle donnée à SSL_CTX_set_session_ticket_cb(). Le rappel gen_cb est défini comme le type SSL_CTX_generate_session_ticket_fn.

dec_cb est le rappel d'application défini qui est appelé après qu'une tentative de décodage d'un ticket de session a été effectuée et que toute donnée d'application du ticket de session est disponible. Si le décodage du ticket a réussi, l'argument ss contient les données de la session. Les arguments keyname et keyname_len identifient la clé utilisée pour décoder le ticket de session. L'argument status indique le résultat du décodage du ticket. Voir la section NOTES pour plus de détails. La valeur de arg est la même que celle donnée à SSL_CTX_set_session_ticket_cb(). Le rappel dec_cb est défini comme le type SSL_CTX_decrypt_session_ticket_fn.

SSL_SESSION_set1_ticket_appdata() définit les données d'application spécifiées par data et len dans ss, qui sont ensuite placées dans tout ticket de session généré. Elle peut être appelée à tout moment avant la génération d'un ticket de session pour mettre à jour les données placées dans le ticket de session. Cependant, comme les sessions et les tickets sont créés pendant le handshake, le rappel gen_cb est fourni pour informer l'application qu'un ticket de session va être généré.

SSL_SESSION_get0_ticket_appdata() assigne data aux données d'application du ticket de session et assigne len à la longueur des données d'application du ticket de session de ss. Les données d'application peuvent être définies via SSL_SESSION_set1_ticket_appdata() ou via un ticket de session. S'il n'y a pas de données d'application de session dans le ticket, data sera assigné à NULL et len à 0. SSL_SESSION_get0_ticket_appdata() peut être appelée à tout moment après la création d'une session. Le rappel dec_cb est fourni pour informer l'application qu'un ticket de session a été décodé.

NOTES

Lorsque le rappel dec_cb est appelé, le ss de SSL_SESSION n'a pas encore été assigné au s de SSL. Le status indique le résultat du décodage du ticket. Le rappel doit vérifier la valeur du status avant d'effectuer toute action, car il est appelé même si le décodage du ticket échoue.

Les arguments keyname et keyname_len du rappel dec_cb peuvent être utilisés pour identifier la clé utilisée pour chiffrer le ticket de session.

La valeur du status peut être l'une des suivantes :

SSL_TICKET_EMPTY
Un ticket vide est présent. Aucune donnée du ticket ne sera utilisée et un nouveau ticket doit être envoyé au client. Ceci n'est pertinent que pour TLSv1.2 ou versions antérieures. En TLSv1.3, il n'est pas valide pour un client d'envoyer un ticket vide.
SSL_TICKET_NO_DECRYPT
Le ticket n'a pas pu être décodé. Aucune donnée du ticket ne sera utilisée et un nouveau ticket doit être envoyé au client.
SSL_TICKET_SUCCESS
Le ticket a été décodé avec succès, toute donnée d'application de session devrait être disponible. Aucun nouveau ticket ne doit être envoyé au client.
SSL_TICKET_SUCCESS_RENEW
Identique à SSL_TICKET_SUCCESS, mais un nouveau ticket doit être envoyé au client.

La valeur de retour peut être l'une des suivantes :

SSL_TICKET_RETURN_ABORT
Le handshake doit être abandonné, soit en raison d'une erreur, soit d'une politique. Note : En TLSv1.3, un client peut envoyer plus d'un ticket lors d'un même handshake. Par conséquent, le simple fait qu'un ticket soit inacceptable ne signifie pas que tous les tickets sont inacceptables. Pour cette raison, cette option doit être utilisée avec prudence.
SSL_TICKET_RETURN_IGNORE
Ne pas utiliser de ticket (s'il y en avait un de disponible). Aucun nouveau ticket ne doit être envoyé au client.
SSL_TICKET_RETURN_IGNORE_RENEW
Ne pas utiliser de ticket (s'il y en avait un de disponible). Un nouveau ticket doit être envoyé au client.

Si le rappel ne souhaite pas modifier le comportement par défaut des tickets, il doit renvoyer cette valeur si le status est SSL_TICKET_EMPTY ou SSL_TICKET_NO_DECRYPT.

SSL_TICKET_RETURN_USE
Utiliser le ticket. Aucun nouveau ticket ne doit être envoyé au client. C'est une erreur pour le rappel de retourner cette valeur si le status n'est pas SSL_TICKET_SUCCESS ou SSL_TICKET_SUCCESS_RENEW.

Si le rappel ne souhaite pas modifier le comportement par défaut des tickets, il doit renvoyer cette valeur si le status est SSL_TICKET_SUCCESS.

SSL_TICKET_RETURN_USE_RENEW
Utiliser le ticket. Un nouveau ticket doit être envoyé au client. C'est une erreur pour le rappel de retourner cette valeur si le status n'est pas SSL_TICKET_SUCCESS ou SSL_TICKET_SUCCESS_RENEW.

Si le rappel ne souhaite pas modifier le comportement par défaut des tickets, il doit renvoyer cette valeur si le status est SSL_TICKET_SUCCESS_RENEW.

Si le status est SSL_TICKET_EMPTY ou SSL_TICKET_NO_DECRYPT, aucune donnée de session ne sera disponible et le rappel ne doit pas utiliser l'argument ss. Si le status est SSL_TICKET_SUCCESS ou SSL_TICKET_SUCCESS_RENEW, l'application peut appeler SSL_SESSION_get0_ticket_appdata() en utilisant la session fournie dans l'argument ss pour récupérer les données d'application.

Lorsque le rappel gen_cb est appelé, la fonction SSL_get_session() peut être utilisée pour obtenir le SSL_SESSION pour SSL_SESSION_set1_ticket_appdata().

Par défaut, en TLSv1.2 et versions antérieures, un nouveau ticket de session n'est pas émis en cas de succès et par conséquent gen_cb n'est pas appelé. En TLSv1.3, le comportement par défaut est d'émettre un nouveau ticket chaque fois qu'une reprise réussit. Ce comportement peut être modifié si un rappel de clé de ticket est utilisé.

VALEUR DE RETOUR

Les fonctions SSL_CTX_set_session_ticket_cb(), SSL_SESSION_set1_ticket_appdata() et SSL_SESSION_get0_ticket_appdata() renvoient 1 en cas de succès et 0 en cas d'erreur.

Le rappel gen_cb doit retourner 1 pour continuer.
