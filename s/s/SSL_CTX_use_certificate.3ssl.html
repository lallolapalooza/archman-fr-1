DESCRIPTION

Ces fonctions chargent les certificats et les clés privées dans l'objet SSL_CTX ou SSL, respectivement.

La classe de fonctions SSL_CTX_* charge les certificats et les clés dans l'objet SSL_CTX ctx. Les informations sont copiées vers les objets SSL ssl créés à partir de ctx avec SSL_new(3), de sorte que les changements appliqués à ctx ne se propagent pas aux objets SSL déjà existants.

La classe de fonctions SSL_* charge les certificats et les clés dans un objet SSL spécifique. Les informations spécifiques sont conservées lorsque SSL_clear(3) est appelé pour cet objet SSL.

SSL_CTX_use_certificate() charge le certificat x dans ctx, SSL_use_certificate() charge x dans ssl. Les autres certificats nécessaires pour former la chaîne de certificats complète peuvent être spécifiés en utilisant la fonction SSL_CTX_add_extra_chain_cert(3). En cas de succès, le compteur de références de x est incrémenté.

SSL_CTX_use_certificate_ASN1() charge le certificat encodé ASN1 à partir de l'emplacement mémoire d (avec la longueur len) dans ctx, SSL_use_certificate_ASN1() charge le certificat encodé ASN1 dans ssl.

SSL_CTX_use_certificate_file() charge le premier certificat stocké dans file dans ctx. Le format type du certificat doit être spécifié parmi les types connus SSL_FILETYPE_PEM, SSL_FILETYPE_ASN1. SSL_use_certificate_file() charge le certificat depuis file dans ssl. Voir la section NOTES pour savoir pourquoi SSL_CTX_use_certificate_chain_file() devrait être préféré.

SSL_CTX_use_certificate_chain_file() charge une chaîne de certificats depuis file dans ctx. Les certificats doivent être au format PEM et triés en commençant par le certificat du sujet (certificat client ou serveur réel), suivi des certificats d'autorité de certification intermédiaires le cas échéant, et se terminant au plus haut niveau (racine) de l'AC. SSL_use_certificate_chain_file() est similaire sauf qu'il charge la chaîne de certificats dans ssl.

SSL_CTX_use_PrivateKey() ajoute pkey comme clé privée à ctx. ctx NE DOIT PAS être NULL. SSL_CTX_use_RSAPrivateKey() ajoute la clé privée rsa de type RSA à ctx. SSL_use_PrivateKey() ajoute pkey comme clé privée à ssl ; SSL_use_RSAPrivateKey() ajoute rsa comme clé privée de type RSA à ssl. Si un certificat a déjà été défini et que la clé privée n'appartient pas au certificat, une erreur est retournée. Pour changer une paire [certificat/clé privée], le nouveau certificat doit être défini en premier avec SSL_use_certificate() ou SSL_CTX_use_certificate() avant de définir la clé privée avec SSL_CTX_use_PrivateKey() ou SSL_use_PrivateKey(). En cas de succès, le compteur de références de pkey/rsa est incrémenté.

SSL_CTX_use_cert_and_key() et SSL_use_cert_and_key() assignent le certificat X.509 x, la clé privée key et la chaîne de certificats chain aux objets ssl ou ctx correspondants. L'argument pkey doit être la clé privée du certificat X.509 x. Si l'argument override est 0, alors x, pkey et chain sont définis uniquement si tous n'étaient pas précédemment définis. Si override est différent de 0, alors le certificat, la clé privée et les certificats de chaîne sont toujours définis. Si pkey est NULL, alors la clé publique de x est utilisée comme clé privée. Ceci est destiné à être utilisé avec du matériel (via l'interface ENGINE) qui stocke la clé privée de manière sécurisée, de sorte qu'elle ne puisse pas être accédée par OpenSSL. Le compteur de références de la clé publique est incrémenté (deux fois s'il n'y a pas de clé privée) ; il n'est pas copié ni dupliqué. Cela permet à toutes les vérifications de validation de clé privée de réussir sans qu'une clé privée réelle ne soit assignée via SSL_CTX_use_PrivateKey(), etc.

SSL_CTX_use_PrivateKey_ASN1() ajoute la clé privée de type pk stockée à l'emplacement mémoire d (longueur len) à ctx. SSL_CTX_use_RSAPrivateKey_ASN1() ajoute la clé privée de type RSA stockée à l'emplacement mémoire d (longueur len) à ctx. SSL_use_PrivateKey_ASN1() et SSL_use_RSAPrivateKey_ASN1() ajoutent la clé privée à ssl.

SSL_CTX_use_PrivateKey_file() ajoute la première clé privée trouvée dans file à ctx. Le format type de la clé privée doit être spécifié parmi les types connus SSL_FILETYPE_PEM, SSL_FILETYPE_ASN1. SSL_CTX_use_RSAPrivateKey_file() ajoute la première clé privée RSA trouvée dans file à ctx. SSL_use_PrivateKey_file() ajoute la première clé privée trouvée dans file à ssl ; SSL_use_RSAPrivateKey_file() ajoute la première clé privée RSA trouvée à ssl. ctx NE DOIT PAS être NULL.

SSL_CTX_check_private_key() vérifie la cohérence d'une clé privée avec le certificat correspondant chargé dans ctx. S'il y a plus d'une paire clé/certificat (RSA/DSA) installée, le dernier élément installé sera vérifié. Si par exemple le dernier élément était un certificat ou une clé RSA, la paire clé/certificat RSA sera vérifiée. SSL_check_private_key() effectue la même vérification pour ssl. Si aucune clé/certificat n'a été explicitement ajouté pour cet ssl, le dernier élément ajouté à ctx sera vérifié.

NOTES

Le magasin interne de certificats d'OpenSSL peut contenir plusieurs paires de clés privées/certificats à la fois. Le certificat utilisé dépend du chiffrement sélectionné, voir également SSL_CTX_set_cipher_list(3).

Lors de la lecture de certificats et de clés privées à partir de fichiers, les fichiers de type SSL_FILETYPE_ASN1 (également connus sous le nom de DER, encodage binaire) ne peuvent contenir qu'un seul certificat ou clé privée, par conséquent SSL_CTX_use_certificate_chain_file() n'est applicable qu'au format PEM. Les fichiers de type SSL_FILETYPE_PEM peuvent contenir plus d'un élément.

SSL_CTX_use_certificate_chain_file() ajoute le premier certificat trouvé dans le fichier au magasin de certificats. Les autres certificats sont ajoutés au magasin de certificats de chaîne en utilisant SSL_CTX_add1_chain_cert(3). Note : les versions d'OpenSSL antérieures à 1.0.2 n'avaient qu'un seul magasin de chaînes de certificats pour tous les certi

DESCRIPTION

These functions are used to configure the certificate and private key that should be used by the ctx SSL context.

The certificate is typically an X.509 certificate. The private key can be an RSA private key or an ECDSA private key. The key must match the certificate.

The private key can be supplied in different forms:

  • SSL_CTX_use_certificate(), SSL_CTX_use_RSAPrivateKey(), SSL_CTX_use_PrivateKey(), SSL_CTX_use_id_eccKey(), and SSL_CTX_use_ECKey() accept a pointer to a certificate (X509), RSA key (RSA), private key (EVP_PKEY), ECDSA key (ECDSA_KEY) or EC key (EC_KEY) structure respectively. The structure is not freed after use.
  • SSL_CTX_use_certificate_ASN1(), SSL_CTX_use_RSAPrivateKey_ASN1(), SSL_CTX_use_PrivateKey_ASN1(), SSL_CTX_use_id_eccKey_ASN1(), and SSL_CTX_use_ECKey_ASN1() accept a pointer to a DER-encoded ASN.1 structure and its length. The data is copied.
  • SSL_CTX_use_certificate_chain_file(), SSL_CTX_use_RSAPrivateKey_file(), SSL_CTX_use_PrivateKey_file(), SSL_CTX_use_id_eccKey_file(), and SSL_CTX_use_ECKey_file() accept a filename. The functions will try to load the certificate or key from the specified file.

    The type argument for the file loading functions specifies the format of the file. It can be SSL_FILETYPE_PEM or SSL_FILETYPE_ASN1. For most users, SSL_FILETYPE_PEM

    SSL_CTX_use_certificate_chain_file() is special in that it can load a certificate chain. This means that the file can contain multiple certificates, forming a chain. The first certificate in the file is used as the certificate for the context. Any subsequent certificates are added to a list of certificates that can be sent to the peer during the TLS handshake.

    The intermediate certificates required to form the chain are expected to be ordered correctly, with the issuing CA certificate immediately following the end-entity certificate, and so on.

    For OpenSSL 1.0.2 and later, certificates and private keys are managed separately. For example, if you load a certificate chain using SSL_CTX_use_certificate_chain_file(), this does not automatically load the associated private key. You must load the private key separately using one of the SSL_CTX_use_...Private..._file() functions. This also applies to older versions if you wish to use a certificate chain and a trusted CA storage is not used or the issuing CA is not to be added to the trusted CA storage.

    Starting from OpenSSL 1.0.2, for certificate types, OpenSSL has a separate chain store for each type. SSL_CTX_use_certificate_chain_file() should be used instead of the SSL_CTX_use_certificate_file() function in order to allow the use of complete certificate chains even when no trusted CA storage is used or when the CA issuing the certificate shall not be added to the trusted CA

    storage.

If additional certificates are needed to complete the chain during the TLS negotiation, CA certificates are additionally looked up in the locations of trusted CA certificates, see SSL_CTX_load_verify_locations(3).

The private keys loaded from file can be encrypted. In order to successfully load encrypted keys, a function returning the passphrase must have been supplied, see SSL_CTX_set_default_passwd_cb(3). (Certificate files might be encrypted as well from the technical point of view, it however does not make sense as the data in the certificate is considered public anyway.)

All of the functions to set a new certificate will replace any existing certificate of the same type that has already been set. Similarly all of the functions to set a new private key will replace any private key that has already been set. Applications should call SSL_CTX_check_private_key(3) or SSL_check_private_key(3) as appropriate after loading a new certificate and private key to confirm that the certificate and key match.

RETURN VALUES

On success, the functions return 1. Otherwise check out the error stack to find out the reason.

DESCRIPTION

Ces fonctions sont utilisées pour configurer le certificat et la clé privée qui doivent être utilisés par le contexte SSL ctx.

Le certificat est typiquement un certificat X.509. La clé privée peut être une clé privée RSA ou une clé privée ECDSA. La clé doit correspondre au certificat.

La clé privée peut être fournie sous différentes formes :

  • SSL_CTX_use_certificate(), SSL_CTX_use_RSAPrivateKey(), SSL_CTX_use_PrivateKey(), SSL_CTX_use_id_eccKey(), et SSL_CTX_use_ECKey() acceptent respectivement un pointeur vers une structure de certificat (X509), une clé RSA (RSA), une clé privée (EVP_PKEY), une clé ECDSA (ECDSA_KEY) ou une clé EC (EC_KEY). La structure n'est pas libérée après utilisation.
  • SSL_CTX_use_certificate_ASN1(), SSL_CTX_use_RSAPrivateKey_ASN1(), SSL_CTX_use_PrivateKey_ASN1(), SSL_CTX_use_id_eccKey_ASN1(), et SSL_CTX_use_ECKey_ASN1() acceptent un pointeur vers une structure ASN.1 encodée en DER et sa longueur. Les données sont copiées.
  • SSL_CTX_use_certificate_chain_file(), SSL_CTX_use_RSAPrivateKey_file(), SSL_CTX_use_PrivateKey_file(), SSL_CTX_use_id_eccKey_file(), et SSL_CTX_use_ECKey_file() acceptent un nom de fichier. Les fonctions essaieront de charger le certificat ou la clé depuis le fichier spécifié.

    L'argument type pour les fonctions de chargement de fichier spécifie le format du fichier. Il peut s'agir de SSL_FILETYPE_PEM ou SSL_FILETYPE_ASN1. Pour la plupart des utilisateurs, SSL_FILETYPE_PEM

    SSL_CTX_use_certificate_chain_file() est spéciale en ce sens qu'elle peut charger une chaîne de certificats. Cela signifie que le fichier peut contenir plusieurs certificats, formant une chaîne. Le premier certificat dans le fichier est utilisé comme certificat pour le contexte. Tous les certificats suivants sont ajoutés à une liste de certificats qui peuvent être envoyés à l'homologue pendant la négociation TLS.

    Les certificats intermédiaires nécessaires pour former la chaîne doivent être correctement ordonnés, avec le certificat de l'autorité de certification émettrice immédiatement après le certificat de l'entité finale, et ainsi de suite.

    Pour OpenSSL 1.0.2 et versions ultérieures, les certificats et les clés privées sont gérés séparément. Par exemple, si vous chargez une chaîne de certificats à l'aide de SSL_CTX_use_certificate_chain_file(), cela ne charge pas automatiquement la clé privée associée. Vous devez charger la clé privée séparément en utilisant l'une des fonctions SSL_CTX_use_...Private..._file(). Ceci s'applique également aux versions antérieures si vous souhaitez utiliser une chaîne de certificats et qu'un stockage CA de confiance n'est pas utilisé ou que la CA émettrice ne doit pas être ajoutée au stockage CA de confiance.

    À partir d'OpenSSL 1.0.2, pour les types de certificats, OpenSSL dispose d'un magasin de chaînes séparé pour chaque type. SSL_CTX_use_certificate_chain_file() doit être utilisé à la place de la fonction SSL_CTX_use_certificate_file() afin de permettre l'utilisation de chaînes de certificats complètes même lorsqu'aucun stockage CA de confiance n'est utilisé ou lorsque la CA émettrice du certificat ne doit pas être ajoutée au stockage CA de confiance.

    storage.

Si des certificats supplémentaires sont nécessaires pour compléter la chaîne pendant la négociation TLS, les certificats CA sont recherchés supplémentairement dans les emplacements des certificats CA de confiance, voir SSL_CTX_load_verify_locations(3).

Les clés privées chargées depuis un fichier peuvent être chiffrées. Pour charger avec succès des clés chiffrées, une fonction retournant la phrase de passe doit avoir été fournie, voir SSL_CTX_set_default_passwd_cb(3). (Les fichiers de certificat pourraient être chiffrés également d'un point de vue technique, mais cela n'a pas de sens car les données dans le certificat sont de toute façon considérées comme publiques.)

Toutes les fonctions permettant de définir un nouveau certificat remplaceront tout certificat existant du même type qui a déjà été défini. De même, toutes les fonctions permettant de définir une nouvelle clé privée remplaceront toute clé privée qui a déjà été définie. Les applications doivent appeler SSL_CTX_check_private_key(3) ou SSL_check_private_key(3) de manière appropriée après avoir chargé un nouveau certificat et une nouvelle clé privée pour confirmer que le certificat et la clé correspondent.
