SSL_set_fd(3ssl)

Paquet: openssl

Licences: Apache-2.0

SSL_SET_FD(3ssl) OpenSSL SSL_SET_FD(3ssl)

NOM

SSL_set_fd, SSL_set_rfd, SSL_set_wfd - connecter l'objet SSL avec un descripteur de fichier

SYNTAXE

#include <openssl/ssl.h>
int SSL_set_fd(SSL *ssl, int fd);
int SSL_set_rfd(SSL *ssl, int fd);
int SSL_set_wfd(SSL *ssl, int fd);

DESCRIPTION

SSL_set_fd() définit le descripteur de fichier fd comme installation d'entrée/sortie pour le côté TLS/SSL (chiffré) de ssl. fd sera typiquement le descripteur de fichier de socket d'une connexion réseau.

Lors de l'opération, un socket BIO est automatiquement créé pour l'interface entre ssl et fd. Le BIO et donc le moteur SSL héritent du comportement de fd. Si fd est non bloquant, le ssl aura également un comportement non bloquant.

Lorsqu'il est utilisé sur un objet SSL de connexion QUIC, un datagram BIO est automatiquement créé au lieu d'un socket BIO. Ces fonctions échouent si elles sont appelées sur un objet SSL de flux QUIC.

S'il y avait déjà un BIO connecté à ssl, BIO_free() sera appelé (pour le côté lecture et écriture, si différent).

SSL_set_rfd() et SSL_set_wfd() effectuent l'action respective, mais uniquement pour le canal de lecture ou le canal d'écriture, qui peuvent être définis indépendamment.

VALEURS DE RETOUR

Les valeurs de retour suivantes peuvent survenir :

0
L'opération a échoué. Vérifiez la pile d'erreurs pour savoir pourquoi.
1
L'opération a réussi.

NOTES

Sous Windows, un handle de socket est un type de données 64 bits (UINT_PTR), ce qui entraîne un avertissement du compilateur (conversion de 'SOCKET' en 'int', perte de données possible) lors du passage du handle de socket à SSL_set_*fd(). Pour le moment, cet avertissement peut être ignoré sans risque, car bien que la documentation Microsoft affirme que la limite supérieure est INVALID_SOCKET-1 (2^64 - 2), en pratique l'implémentation actuelle de socket() renvoie un index dans la table des handles du noyau, dont la taille est limitée à 2^24.
