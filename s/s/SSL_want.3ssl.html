SSL_want(3ssl)

Paquet: openssl

Licences: Apache-2.0

SSL_WANT(3ssl) OpenSSL SSL_WANT(3ssl)

NOM

SSL_want, SSL_want_nothing, SSL_want_read, SSL_want_write, SSL_want_x509_lookup, SSL_want_retry_verify, SSL_want_async, SSL_want_async_job, SSL_want_client_hello_cb - obtenir des informations d'état sur les opérations d'E/S TLS/SSL

SYNTAXE

#include <openssl/ssl.h>
int SSL_want(const SSL *ssl);
int SSL_want_nothing(const SSL *ssl);
int SSL_want_read(const SSL *ssl);
int SSL_want_write(const SSL *ssl);
int SSL_want_x509_lookup(const SSL *ssl);
int SSL_want_retry_verify(const SSL *ssl);
int SSL_want_async(const SSL *ssl);
int SSL_want_async_job(const SSL *ssl);
int SSL_want_client_hello_cb(const SSL *ssl);

DESCRIPTION

SSL_want() retourne des informations d'état pour l'objet SSL ssl. ssl NE DOIT PAS être NULL.

Les autres appels SSL_want_*() sont des raccourcis pour les états possibles retournés par SSL_want().

NOTES

SSL_want() examine les informations d'état internes de l'objet SSL. Ses valeurs de retour sont similaires à celles de SSL_get_error(3). Contrairement à SSL_get_error(3), qui évalue également la file d'attente d'erreurs, les résultats sont obtenus en examinant uniquement un indicateur d'état interne. Les informations ne doivent donc être utilisées que pour un fonctionnement normal dans des conditions d'E/S non bloquantes. Les conditions d'erreur ne sont pas gérées et doivent être traitées à l'aide de SSL_get_error(3).

Le résultat retourné par SSL_want() doit toujours être cohérent avec le résultat de SSL_get_error(3).

VALEUR DE RETOUR

Les valeurs de retour suivantes peuvent actuellement survenir pour SSL_want():

SSL_NOTHING
Il n'y a pas de données à écrire ou à lire.
SSL_WRITING
Il y a des données dans le tampon SSL qui doivent être écrites sur la couche BIO sous-jacente afin de compléter l'opération SSL_*() réelle. Un appel à SSL_get_error(3) devrait retourner SSL_ERROR_WANT_WRITE.
SSL_READING
Plus de données doivent être lues à partir de la couche BIO sous-jacente afin de compléter l'opération SSL_*() réelle. Un appel à SSL_get_error(3) devrait retourner SSL_ERROR_WANT_READ.
SSL_X509_LOOKUP
L'opération ne s'est pas terminée car une fonction de rappel d'application définie par SSL_CTX_set_client_cert_cb() a demandé à être rappelée. Un appel à SSL_get_error(3) devrait retourner SSL_ERROR_WANT_X509_LOOKUP.
SSL_RETRY_VERIFY
L'opération ne s'est pas terminée car une fonction de rappel de vérification de certificat a demandé à être rappelée via SSL_set_retry_verify(3). Un appel à SSL_get_error(3) devrait retourner SSL_ERROR_WANT_RETRY_VERIFY.
SSL_ASYNC_PAUSED
Une opération asynchrone s'est terminée partiellement et a ensuite été mise en pause. Voir SSL_get_all_async_fds(3). Un appel à SSL_get_error(3) devrait retourner SSL_ERROR_WANT_ASYNC.
SSL_ASYNC_NO_JOBS
Le travail asynchrone n'a pas pu démarrer car aucun travail asynchrone n'était disponible dans le pool (voir ASYNC_init_thread(3)). Un appel à SSL_get_error(3) devrait retourner SSL_ERROR_WANT_ASYNC_JOB.
SSL_CLIENT_HELLO_CB
L'opération ne s'est pas terminée car une fonction de rappel d'application définie par SSL_CTX_set_client_hello_cb() a demandé à être rappelée. Un appel à SSL_get_error(3) devrait retourner SSL_ERROR_WANT_CLIENT_HELLO_CB.

SSL_want_nothing(), SSL_want_read(), SSL_want_write(), SSL_want_x509_lookup(), SSL_want_retry_verify(), SSL_want_async(), SSL_want_async_job(), et SSL_want_client_hello_cb() retournent 1 lorsque la condition correspondante est vraie, ou 0 sinon.

CONSIDÉRATIONS SPÉCIFIQUES QUIC

Pour QUIC, ces fonctions se rapportent uniquement à la couche de poignée de main TLS.

VOIR AUSSI

ssl(7), SSL_get_error(3)

HISTORIQUE

La fonction SSL_want_client_hello_cb() et la valeur de retour SSL_CLIENT_HELLO_CB ont été ajoutées dans OpenSSL 1.1.1.

SSL_want_retry_verify() a été ajoutée dans OpenSSL 3.0.
