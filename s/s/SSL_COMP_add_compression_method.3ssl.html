SSL_COMP_add_compression_method(3ssl)

Paquet: openssl

Licences: Apache-2.0

SSL_COMP_ADD_COMPRESSION_METHOD(3ssl) OpenSSL SSL_COMP_ADD_COMPRESSION_METHOD(3ssl)

NOM

SSL_COMP_add_compression_method, SSL_COMP_get_compression_methods, SSL_COMP_get0_name, SSL_COMP_get_id, SSL_COMP_free_compression_methods - gérer les méthodes de compression intégrées SSL/TLS

SYNTAXE

#include <openssl/ssl.h>
int SSL_COMP_add_compression_method(int id, COMP_METHOD *cm);
STACK_OF(SSL_COMP) *SSL_COMP_get_compression_methods(void);
const char *SSL_COMP_get0_name(const SSL_COMP *comp);
int SSL_COMP_get_id(const SSL_COMP *comp);

La fonction suivante a été dépréciée depuis OpenSSL 1.1.0, et peut être complètement masquée en définissant OPENSSL_API_COMPAT avec une valeur de version appropriée, voir openssl_user_macros(7):

void SSL_COMP_free_compression_methods(void);

DESCRIPTION

SSL_COMP_add_compression_method() ajoute la méthode de compression cm avec l'identifiant id à la liste des méthodes de compression disponibles. Cette liste est maintenue globalement pour toutes les opérations SSL au sein de cette application. Elle ne peut pas être définie pour des objets SSL_CTX ou SSL spécifiques.

SSL_COMP_get_compression_methods() retourne une pile de toutes les méthodes de compression disponibles ou NULL en cas d'erreur.

SSL_COMP_get0_name() retourne le nom de la méthode de compression comp.

SSL_COMP_get_id() retourne l'identifiant de la méthode de compression comp.

SSL_COMP_free_compression_methods() libère toutes les ressources acquises pour maintenir la table interne des méthodes de compression.

NOTES

Le standard TLS (ou SSLv3) permet l'intégration de méthodes de compression dans la communication. Le RFC TLS ne spécifie cependant pas de méthodes de compression ni leurs identifiants correspondants, il n'y a donc actuellement aucun moyen compatible d'intégrer la compression avec des pairs inconnus. Il est donc actuellement déconseillé d'intégrer la compression dans les applications. Les applications à usage non public peuvent convenir de certaines méthodes de compression. L'utilisation de méthodes de compression différentes avec le même identifiant entraînera un échec de connexion.

Un client OpenSSL parlant un protocole qui autorise la compression (SSLv3, TLSv1) enverra inconditionnellement la liste de toutes les méthodes de compression activées avec SSL_COMP_add_compression_method() au serveur pendant la négociation. Contrairement aux mécanismes de définition d'une liste de chiffrements, il n'y a pas de méthode disponible pour restreindre la liste des méthodes de compression sur une base par connexion.

Un serveur OpenSSL fera correspondre les identifiants listés par un client avec ses propres méthodes de compression et activera inconditionnellement la compression lorsqu'un identifiant correspondant est trouvé. Il n'y a aucun moyen de restreindre la liste des méthodes de compression prises en charge sur une base par connexion.

Si elles sont activées lors de la compilation, la bibliothèque OpenSSL disposera des méthodes de compression suivantes disponibles :

COMP_zlib()
COMP_brotli()
COMP_brotli_oneshot()
COMP_zstd()
COMP_zstd_oneshot()

VALEURS DE RETOUR

SSL_COMP_add_compression_method() peut retourner les valeurs suivantes :

0
L'opération a réussi.
1
L'opération a échoué. Vérifiez la file d'attente d'erreurs pour connaître la raison.

SSL_COMP_get_compression_methods() retourne la pile des méthodes de compression ou NULL en cas d'erreur.

SSL_COMP_get0_name() retourne le nom de la méthode de compression ou NULL en cas d'erreur.

SSL_COMP_get_id() retourne le nom de la méthode de compression ou -1 en cas d'erreur.

VOIR AUSSI

ssl(7)

HISTORIQUE

La fonction SSL_COMP_free_compression_methods() a été dépréciée dans OpenSSL 1.1.0. Les fonctions SSL_COMP_get0_name() et SSL_comp_get_id() ont été ajoutées dans OpenSSL 1.1.0d.
