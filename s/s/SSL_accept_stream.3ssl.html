SSL_accept_stream(3ssl)

Paquet: openssl

Licences: Apache-2.0

SSL_ACCEPT_STREAM(3ssl) OpenSSL SSL_ACCEPT_STREAM(3ssl)

NOM

SSL_accept_stream, SSL_get_accept_stream_queue_len, SSL_ACCEPT_STREAM_NO_BLOCK, SSL_ACCEPT_STREAM_UNI, SSL_ACCEPT_STREAM_BIDI - accepter un flux QUIC entrant d'un pair QUIC

SYNTAXIS

#include <openssl/ssl.h>
#define SSL_ACCEPT_STREAM_NO_BLOCK
#define SSL_ACCEPT_STREAM_UNI
#define SSL_ACCEPT_STREAM_BIDI
SSL *SSL_accept_stream(SSL *ssl, uint64_t flags);
size_t SSL_get_accept_stream_queue_len(SSL *ssl);

DESCRIPTION

La fonction SSL_accept_stream() tente de dépiler un flux entrant de l'objet SSL de connexion QUIC donné et retourne le nouvel objet SSL de flux QUIC alloué.

Si la file d'attente des flux entrants est vide, cette fonction retourne NULL (en mode non bloquant) ou attend un flux entrant (en mode bloquant). Cette fonction peut toujours retourner NULL en mode bloquant, par exemple si la connexion sous-jacente est terminée.

L'appelant est responsable de la gestion de la durée de vie de l'objet SSL de flux QUIC retourné ; pour plus d'informations, voir SSL_free(3).

Cette fonction bloquera si l'objet SSL de connexion QUIC est configuré en mode bloquant (voir SSL_set_blocking_mode(3)), mais cela peut être contourné en passant le drapeau SSL_ACCEPT_STREAM_NO_BLOCK dans flags. Si ce drapeau est défini, cette fonction ne bloque jamais.

Par défaut, cette fonction retournera le premier flux entrant, qu'il soit unidirectionnel ou bidirectionnel. Passer le drapeau SSL_ACCEPT_STREAM_UNI ou SSL_ACCEPT_STREAM_BIDI retournera le premier flux qui est respectivement unidirectionnel ou bidirectionnel. Si ces deux drapeaux sont définis, l'un ou l'autre type peut être retourné. Une valeur de retour NULL peut signifier qu'il y a encore des flux qui peuvent être dépilés.

Appeler SSL_accept_stream() s'il n'y a pas de flux par défaut déjà présent inhibe la création future d'un flux par défaut. Voir openssl-quic(7).

SSL_get_accept_stream_queue_len() retourne le nombre de flux entrants en attente dans la file d'acceptation.

Ces fonctions peuvent être utilisées à partir de plusieurs threads pour la même connexion QUIC.

Selon que la fonctionnalité de flux par défaut est utilisée, il peut être nécessaire de configurer explicitement la politique de flux entrant avant que les flux ne puissent être acceptés ; voir SSL_set_incoming_stream_policy(3). Voir également "MODES OF OPERATION" dans openssl-quic(7) pour plus d'informations sur la fonctionnalité de flux par défaut.

VALEURS DE RETOUR

SSL_accept_stream() retourne un objet SSL de flux QUIC nouvellement alloué, ou NULL si aucun nouveau flux entrant n'est disponible, ou si la connexion a été terminée, ou si elle est appelée sur un objet SSL autre qu'un objet SSL de connexion QUIC. SSL_get_error(3) peut être utilisé pour obtenir plus d'informations dans ce cas.

SSL_get_accept_stream_queue_len() retourne le nombre de flux entrants actuellement en attente dans la file d'acceptation, ou 0 si elle est appelée sur un objet SSL autre qu'un objet SSL de connexion QUIC.

VOIR AUSSI

"MODES OF OPERATION" dans openssl-quic(7), SSL_new_stream(3), SSL_set_blocking_mode(3), SSL_free(3)

HISTORIQUE

SSL_accept_stream() et SSL_get_accept_stream_queue_len() ont été ajoutés dans OpenSSL 3.2.
