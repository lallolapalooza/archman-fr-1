SSL_alert_type_string(3ssl)

Paquet: openssl

Licences: Apache-2.0

SSL_ALERT_TYPE_STRING(3ssl) OpenSSL SSL_ALERT_TYPE_STRING(3ssl)

NOM

SSL_alert_type_string, SSL_alert_type_string_long, SSL_alert_desc_string, SSL_alert_desc_string_long - obtenir une description textuelle des informations d'alerte

SYNTAXE

#include <openssl/ssl.h>
const char *SSL_alert_type_string(int value);
const char *SSL_alert_type_string_long(int value);
const char *SSL_alert_desc_string(int value);
const char *SSL_alert_desc_string_long(int value);

DESCRIPTION

SSL_alert_type_string() retourne une chaîne d'un seul caractère indiquant le type de l'alerte spécifiée par value.

SSL_alert_type_string_long() retourne une chaîne indiquant le type de l'alerte spécifiée par value.

SSL_alert_desc_string() retourne une chaîne de deux caractères sous forme abrégée décrivant la raison de l'alerte spécifiée par value.

SSL_alert_desc_string_long() retourne une chaîne décrivant la raison de l'alerte spécifiée par value.

NOTES

Lorsqu'un côté d'une communication SSL/TLS souhaite informer son interlocuteur d'une situation spéciale, il envoie une alerte. L'alerte est envoyée comme un message spécial et n'influence pas le flux de données normal (sauf si son contenu entraîne l'annulation de la communication).

Une alerte d'avertissement est envoyée lorsqu'une condition d'erreur non fatale se produit. L'alerte "close notify" (notification de fermeture) est envoyée comme une alerte d'avertissement. D'autres exemples d'erreurs non fatales sont les erreurs de certificat ("certificate expired", "unsupported certificate"), pour lesquelles une alerte d'avertissement peut être envoyée. (Cependant, la partie émettrice peut décider d'envoyer une erreur fatale.) Le côté récepteur peut annuler la connexion à la réception d'une alerte d'avertissement à sa discrétion.

Plusieurs messages d'alerte doivent être envoyés sous forme d'alertes fatales, comme spécifié par la RFC TLS. Une alerte fatale entraîne toujours un abandon de connexion.

VALEURS DE RETOUR

Les chaînes suivantes peuvent apparaître pour SSL_alert_type_string() ou SSL_alert_type_string_long() :

"W"/"warning"
"F"/"fatal"
"U"/"unknown"
Ceci indique qu'aucun support n'est disponible pour ce type d'alerte. Probablement, value ne contient pas un message d'alerte correct.

Les chaînes suivantes peuvent apparaître pour SSL_alert_desc_string() ou SSL_alert_desc_string_long() :

"CN"/"close notify"
La connexion doit être fermée. C'est une alerte d'avertissement.
"UM"/"unexpected message"
Un message inapproprié a été reçu. Cette alerte est toujours fatale et ne devrait jamais être observée dans la communication entre des implémentations correctes.
"BM"/"bad record mac"
Cette alerte est retournée si un enregistrement est reçu avec un MAC incorrect. Ce message est toujours fatal.
"DF"/"decompression failure"
La fonction de décompression a reçu une entrée incorrecte (par exemple, des données qui se décompresseraient de manière excessive). Ce message est toujours fatal.
"HF"/"handshake failure"
La réception d'un message d'alerte handshake_failure indique que l'expéditeur n'a pas pu négocier un ensemble acceptable de paramètres de sécurité étant donné les options disponibles. C'est une erreur fatale.
"NC"/"no certificate"
Un client, à qui il a été demandé d'envoyer un certificat, n'en envoie pas (SSLv3 seulement).
"BC"/"bad certificate"
Un certificat était corrompu, contenait des signatures qui n'ont pas été vérifiées correctement, etc.
"UC"/"unsupported certificate"
Un certificat était d'un type non supporté.
"CR"/"certificate revoked"
Un certificat a été révoqué par son émetteur.
"CE"/"certificate expired"
Un certificat a expiré ou n'est pas actuellement valide.
"CU"/"certificate unknown"
Un autre problème (non spécifié) est survenu lors du traitement du certificat, le rendant inacceptable.
"IP"/"illegal parameter"
Un champ dans la négociation était hors limites ou incohérent avec d'autres champs. C'est toujours fatal.
"DC"/"decryption failed"
Un TLSCiphertext a été décrypté d'une manière invalide : soit ce n'était pas un multiple pair de la longueur de bloc, soit ses valeurs de remplissage, une fois vérifiées, n'étaient pas correctes. Ce message est toujours fatal.
"RO"/"record overflow"
Un enregistrement TLSCiphertext a été reçu avec une longueur supérieure à 2^14+2048 octets, ou un enregistrement décrypté a donné un enregistrement TLSCompressed de plus de 2^14+1024 octets. Ce message est toujours fatal.
"CA"/"unknown CA"
Une chaîne de certificats valide ou une chaîne partielle a été reçue, mais le certificat n'a pas été accepté car le certificat de l'AC n'a pas pu être trouvé ou n'a pas pu être associé à une AC connue et de confiance. Ce message est toujours fatal.
"AD"/"access denied"
Un certificat valide a été reçu, mais lorsque le contrôle d'accès a été appliqué, l'expéditeur a décidé de ne pas poursuivre la négociation. Ce message est toujours fatal.
"DE"/"decode error"
Un message n'a pas pu être décodé car un champ était hors de la plage spécifiée ou la longueur du message était incorrecte. Ce message est toujours fatal.
"CY"/"decrypt error"
Une opération cryptographique de négociation a échoué, y compris l'incapacité de vérifier correctement une signature, de décrypter un échange de clés, ou de valider un message fini.
"ER"/"export restriction"
Une négociation non conforme aux restrictions d'exportation a été détectée ; par exemple, tenter de transférer une clé RSA éphémère de 1024 bits pour la méthode de négociation RSA_EXPORT. Ce message est toujours fatal.
"PV"/"protocol version"
La version du protocole que le client a tenté de négocier est reconnue, mais non supportée. (Par exemple, les anciennes versions de protocole peuvent être évitées pour des raisons de sécurité). Ce message est toujours fatal.
"IS"/"insufficient security"
Retourné à la place de handshake_failure lorsqu'une négociation a échoué spécifiquement parce que le serveur requiert des chiffrements plus sécurisés que ceux supportés par le client. Ce message est toujours fatal.
"IE"/"internal error"
Une erreur interne sans rapport avec l'interlocuteur ou la correction du protocole rend impossible la poursuite (par exemple, une allocation de mémoire échouée). Ce message est toujours fatal.
"US"/"user canceled"
Cette négociation est annulée pour une raison non liée à une défaillance du protocole. Si l'utilisateur annule une opération après la fin de la négociation, il est plus approprié de simplement fermer la connexion en envoyant un close_notify. Cette alerte devrait être suivie d'un close_notify. Ce message est généralement un avertissement.
"NR"/"no renegotiation"
Envoyé par le client en réponse à une demande de hello ou par le serveur en réponse à un client hello après la négociation initiale. L'une ou l'autre conduirait normalement à une renégociation ; lorsque ce n'est pas approprié, le destinataire doit répondre avec cette alerte ; à ce moment-là, le demandeur initial peut décider de poursuivre la connexion. Un cas où cela serait approprié serait lorsqu'un serveur a lancé un processus pour satisfaire une demande ; le processus pourrait recevoir des paramètres de sécurité (longueur de clé, authentification, etc.) au démarrage et il pourrait être difficile de communiquer des changements à ces paramètres par la suite. Ce message est toujours un avertissement.
"UP"/"unknown PSK identity"
Envoyé par le serveur pour indiquer qu'il ne reconnaît pas une identité PSK ou une identité SRP.
"UK"/"unknown"
Ceci indique qu'aucune description n'est disponible pour ce type d'alerte. Probablement, value ne contient pas un message d'alerte correct.
