SSL_CTX_sess_set_get_cb(3ssl)

Paquet: openssl

Licences: Apache-2.0

SSL_CTX_SESS_SET_GET_CB(3ssl) OpenSSL SSL_CTX_SESS_SET_GET_CB(3ssl)

NOM

SSL_CTX_sess_set_get_cb, SSL_CTX_sess_set_remove_cb, SSL_CTX_sess_set_get_cb, SSL_CTX_sess_get_new_cb, SSL_CTX_sess_get_remove_cb, SSL_CTX_sess_get_get_cb - fonctions de rappel pour la mise en cache de session côté serveur

SYNOPIS

#include <openssl/ssl.h>
void SSL_CTX_sess_set_new_cb(SSL_CTX *ctx,
                             int (*new_session_cb)(SSL *, SSL_SESSION *));
void SSL_CTX_sess_set_remove_cb(SSL_CTX *ctx,
                                void (*remove_session_cb)(SSL_CTX *ctx,
                                                          SSL_SESSION *));
void SSL_CTX_sess_set_get_cb(SSL_CTX *ctx,
                             SSL_SESSION (*get_session_cb)(SSL *,
                                                           const unsigned char *,
                                                           int, int *));
int (*SSL_CTX_sess_get_new_cb(SSL_CTX *ctx))(struct ssl_st *ssl,
                                             SSL_SESSION *sess);
void (*SSL_CTX_sess_get_remove_cb(SSL_CTX *ctx))(struct ssl_ctx_st *ctx,
                                                 SSL_SESSION *sess);
SSL_SESSION *(*SSL_CTX_sess_get_get_cb(SSL_CTX *ctx))(struct ssl_st *ssl,
                                                      const unsigned char *data,
                                                      int len, int *copy);

DESCRIPTION

SSL_CTX_sess_set_new_cb() définit la fonction de rappel appelée lorsqu'une nouvelle session a été négociée.

SSL_CTX_sess_set_remove_cb() définit la fonction de rappel appelée lorsqu'une session est supprimée par le moteur SSL. Par exemple, cela peut se produire parce que la session est jugée inacceptable ou est devenue obsolète en raison d'un dépassement de délai d'attente.

SSL_CTX_sess_set_get_cb() définit la fonction de rappel appelée lorsqu'un client TLS propose de reprendre une session mais que la session n'est pas trouvée dans le cache de session interne (voir SSL_CTX_set_session_cache_mode(3)). (Uniquement pour le serveur TLS).

SSL_CTX_sess_get_new_cb(), SSL_CTX_sess_get_remove_cb() et SSL_CTX_sess_get_get_cb() récupèrent les pointeurs vers les fonctions définies par les fonctions de rappel correspondantes. Si aucune fonction de rappel n'a été définie, un pointeur nul est renvoyé.

NOTES

Pour permettre la mise en cache de session externe, la synchronisation avec le cache de session interne est effectuée via des fonctions de rappel. Dans ces fonctions de rappel, la session peut être sauvegardée sur disque ou placée dans une base de données en utilisant l'interface d2i_SSL_SESSION(3).

La fonction new_session_cb() est appelée chaque fois qu'une nouvelle session a été négociée et que le cache de session est activé (voir SSL_CTX_set_session_cache_mode(3)). La fonction new_session_cb() reçoit la connexion ssl et la nouvelle session sess créée. Comme les sessions sont des objets de référence, le compteur de références de l'objet session est incrémenté avant que la fonction de rappel ne soit exécutée, au nom de l'application. Si la fonction de rappel renvoie 0, la session sera immédiatement supprimée du cache interne et le compteur de références sera libéré. Si la fonction de rappel renvoie 1, l'application conserve le compteur de références (pour un enregistrement dans le cache de session géré par l'application), et est responsable de l'appel à SSL_SESSION_free() lorsque le compteur de références n'est plus utilisé.

Note : dans TLSv1.3, les sessions sont établies après le handshake principal. Le serveur décide quand envoyer les informations de session au client et cela peut se produire un certain temps après la fin du handshake (ou pas du tout). Cela signifie que les applications doivent s'attendre à ce que la fonction new_session_cb() soit appelée pendant le handshake (pour <= TLSv1.2) ou après le handshake (pour TLSv1.3). Il est également possible dans TLSv1.3 que plusieurs sessions soient établies avec une seule connexion. Dans ces cas, la fonction new_session_cb() sera appelée plusieurs fois.

Dans TLSv1.3, il est recommandé que chaque objet SSL_SESSION ne soit utilisé qu'une seule fois. Une façon de garantir cela est d'appeler SSL_CTX_remove_session(3) après qu'une session a été utilisée.

La fonction remove_session_cb() est appelée lorsque le moteur SSL supprime une session du cache interne. Cela peut se produire lorsque la session est supprimée car expirée ou lorsqu'une connexion n'a pas été fermée correctement. Cela se produit également pour toutes les sessions dans le cache de session interne lorsque SSL_CTX_free(3) est appelé. La fonction remove_session_cb() reçoit le ctx et la session sess du moteur SSL. Elle ne fournit pas de retour d'information.

La fonction get_session_cb() n'est appelée que sur les serveurs SSL/TLS et reçoit l'identifiant de session proposé par le client. La fonction get_session_cb() est toujours appelée, même lorsque la mise en cache de session a été désactivée. La fonction get_session_cb() reçoit la connexion ssl et l'identifiant de session de longueur length à l'emplacement mémoire data. En définissant le paramètre copy à 1, la fonction de rappel peut demander au moteur SSL d'incrémenter le compteur de références de l'objet SSL_SESSION ; définir copy à 0 laisse le compteur de références inchangé. Si la fonction get_session_cb() n'écrit pas dans copy, le compteur de références est incrémenté et la session doit être explicitement libérée avec SSL_SESSION_free(3).

VALEURS DE RETOUR

SSL_CTX_sess_get_new_cb(), SSL_CTX_sess_get_remove_cb() et SSL_CTX_sess_get_get_cb() renvoient des pointeurs différents aux fonctions de rappel respectives.
