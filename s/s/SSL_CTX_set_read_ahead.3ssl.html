SSL_CTX_set_read_ahead(3ssl)

Paquet: openssl

Licences: Apache-2.0

SSL_CTX_SET_READ_AHEAD(3ssl) OpenSSL SSL_CTX_SET_READ_AHEAD(3ssl)

NOM

SSL_CTX_set_read_ahead, SSL_CTX_get_read_ahead, SSL_set_read_ahead, SSL_get_read_ahead, SSL_CTX_get_default_read_ahead - gérer la lecture de tous les octets d'entrée possibles

SYNTAXE

#include <openssl/ssl.h>
void SSL_set_read_ahead(SSL *s, int yes);
int SSL_get_read_ahead(const SSL *s);
SSL_CTX_set_read_ahead(SSL_CTX *ctx, int yes);
long SSL_CTX_get_read_ahead(SSL_CTX *ctx);
long SSL_CTX_get_default_read_ahead(SSL_CTX *ctx);

DESCRIPTION

SSL_CTX_set_read_ahead() et SSL_set_read_ahead() définissent s'il faut lire autant d'octets d'entrée que possible (pour les lectures non bloquantes) ou non. Par exemple, si x octets sont actuellement requis par OpenSSL, mais que y octets sont disponibles à partir du BIO sous-jacent (où y > x), alors OpenSSL lira tous les y octets dans son tampon (à condition que le tampon soit suffisamment grand) si la lecture anticipée est activée, ou x octets sinon. Définir le paramètre yes à 0 désactive la lecture anticipée, les autres valeurs l'activent. SSL_CTX_set_default_read_ahead() est identique à SSL_CTX_set_read_ahead().

SSL_CTX_get_read_ahead() et SSL_get_read_ahead() indiquent si la lecture anticipée a été définie ou non. SSL_CTX_get_default_read_ahead() est identique à SSL_CTX_get_read_ahead().

Ces fonctions ne peuvent pas être utilisées avec des objets SSL QUIC. SSL_set_read_ahead() n'a aucun effet si elle est appelée sur un objet SSL QUIC.

NOTES

Ces fonctions n'ont aucun impact lorsqu'elles sont utilisées avec DTLS. Les valeurs de retour pour SSL_CTX_get_read_head() et SSL_get_read_ahead() sont indéfinies pour DTLS. La définition de read_ahead peut avoir un impact sur le comportement de la fonction SSL_pending() (voir SSL_pending(3)).

Comme SSL_read() peut retourner SSL_ERROR_WANT_READ pour des enregistrements de données non applicatives, et que SSL_has_pending() ne peut pas faire la différence entre les données traitées et non traitées, il est recommandé que si la lecture anticipée est activée, SSL_MODE_AUTO_RETRY ne soit pas désactivé à l'aide de SSL_CTX_clear_mode(). Cela évitera d'obtenir SSL_ERROR_WANT_READ lorsqu'il reste un enregistrement complet disponible qui n'a pas été traité.

Si l'application souhaite continuer à utiliser le transport sous-jacent (par exemple, une connexion TCP) après que la connexion SSL soit terminée en utilisant SSL_shutdown(), la lecture anticipée doit être désactivée. Sinon, la structure SSL pourrait lire des données qu'elle ne devrait pas.

VALEURS DE RETOUR

SSL_get_read_ahead() et SSL_CTX_get_read_ahead() retournent 0 si la lecture anticipée est désactivée, et une valeur non nulle sinon.
