NOM

SSL_CTX_set_alpn_protos, SSL_set_alpn_protos, SSL_CTX_set_alpn_select_cb, SSL_CTX_set_next_proto_select_cb, SSL_CTX_set_next_protos_advertised_cb, SSL_select_next_proto, SSL_get0_alpn_selected, SSL_get0_next_proto_negotiated - gérer la négociation de protocoles d'application (ALPN)

SYNTAXE

#include <openssl/ssl.h>
int SSL_CTX_set_alpn_protos(SSL_CTX *ctx, const unsigned char *protos,
                            unsigned int protos_len);
int SSL_set_alpn_protos(SSL *ssl, const unsigned char *protos,
                        unsigned int protos_len);
void SSL_CTX_set_alpn_select_cb(SSL_CTX *ctx,
                                int (*cb) (SSL *ssl,
                                           const unsigned char **out,
                                           unsigned char *outlen,
                                           const unsigned char *in,
                                           unsigned int inlen,
                                           void *arg), void *arg);
void SSL_get0_alpn_selected(const SSL *ssl, const unsigned char **data,
                            unsigned int *len);
void SSL_CTX_set_next_protos_advertised_cb(SSL_CTX *ctx,
                                           int (*cb)(SSL *ssl,
                                                     const unsigned char **out,
                                                     unsigned int *outlen,
                                                     void *arg),
                                           void *arg);
void SSL_CTX_set_next_proto_select_cb(SSL_CTX *ctx,
                              int (*cb)(SSL *s,
                                        unsigned char **out,
                                        unsigned char *outlen,
                                        const unsigned char *in,
                                        unsigned int inlen,
                                        void *arg),
                              void *arg);
int SSL_select_next_proto(unsigned char **out, unsigned char *outlen,
                          const unsigned char *server,
                          unsigned int server_len,
                          const unsigned char *client,
                          unsigned int client_len);
void SSL_get0_next_proto_negotiated(const SSL *s, const unsigned char **data,
                            unsigned *len);

DESCRIPTION

SSL_CTX_set_alpn_protos() et SSL_set_alpn_protos() sont utilisés par le client pour définir la liste des protocoles disponibles à négocier. Les protos doivent être dans le format de liste de protocoles, décrit ci-dessous. La longueur de protos est spécifiée par protos_len. La définition de protos_len à 0 supprime toute liste ALPN précédente et aucune extension ALPN ne sera envoyée au serveur.

SSL_CTX_set_alpn_select_cb() définit le rappel cb utilisé par un serveur pour sélectionner quel protocole utiliser pour la connexion entrante. Lorsque cb est NULL, ALPN n'est pas utilisé. La valeur arg est un pointeur qui est passé au rappel de l'application.

cb est le rappel défini par l'application. Les paramètres in, inlen sont un tableau au format de liste de protocoles. La valeur de out, outlen doit être définie à la valeur d'un seul protocole sélectionné à partir du tableau in, inlen. Le buffer out peut pointer directement vers in, ou vers un buffer qui survit à la négociation TLS. La valeur arg est le pointeur défini par SSL_CTX_set_alpn_select_cb().

SSL_select_next_proto() est une fonction utilitaire utilisée pour sélectionner des protocoles. Elle implémente la sélection standard de protocoles. On s'attend à ce que cette fonction soit appelée depuis le rappel d'application cb. Les données dans server, server_len et client, client_len doivent être au format de liste de protocoles décrit ci-dessous. Le premier élément dans la liste server, server_len qui correspond à un élément dans la liste client, client_len est sélectionné et renvoyé dans out, outlen. La valeur out pointera vers server ou client, il doit donc être copié immédiatement. La liste client doit contenir au moins un élément valide (non vide) dans la liste.

La fonction SSL_select_next_proto() peut être utile à partir du rappel ALPN ou du rappel NPN (décrit ci-dessous). S'il n'y a pas de correspondance, le premier élément de client, client_len est renvoyé dans out, outlen et OPENSSL_NPN_NO_OVERLAP est renvoyé. Ceci peut être utile lors de l'implémentation du rappel NPN. Dans le cas d'ALPN, la valeur renvoyée dans out et outlen doit être ignorée si OPENSSL_NPN_NO_OVERLAP a été renvoyé par SSL_select_next_proto().

SSL_CTX_set_next_proto_select_cb() définit un rappel cb qui est appelé lorsqu'un client doit sélectionner un protocole à partir de la liste fournie par le serveur, et un argument utilisateur arg qui est passé à ce rappel. Pour le rappel lui-même, out doit pointer vers le protocole sélectionné (qui peut être dans in). La longueur du nom du protocole doit être écrite dans outlen. Les protocoles annoncés par le serveur sont fournis dans in et inlen. Le rappel peut supposer que in est syntaxiquement valide. Le client doit sélectionner un protocole (même si cela peut être un protocole vide ou de longueur nulle). Si ce rappel renvoie une valeur autre que SSL_TLSEXT_ERR_OK, la connexion est fatale. La valeur arg est le pointeur défini par SSL_CTX_set_next_proto_select_cb().

SSL_CTX_set_next_protos_advertised_cb() définit un rappel cb qui est appelé lorsqu'un serveur a besoin d'une liste de protocoles pris en charge pour la négociation de protocoles. La liste renvoyée doit être au format de liste de protocoles décrit ci-dessous. La liste est renvoyée en définissant out pour qu'il pointe vers elle et outlen pour sa longueur. Cette mémoire ne sera pas modifiée, mais le SSL conservera une référence à celle-ci. Le rappel doit renvoyer SSL_TLSEXT_ERR_OK s'il souhaite annoncer. Sinon, aucune extension de ce type ne sera incluse dans le ServerHello.

SSL_get0_alpn_selected() renvoie un pointeur vers le protocole sélectionné dans data avec la longueur len. Il n'est pas terminé par NUL. data est défini à NULL et len est défini à 0 si aucun protocole n'a été sélectionné. data ne doit pas être libéré.

SSL_get0_next_proto_negotiated() définit data et len pour pointer vers le protocole demandé par le client sur cette connexion. Si le client n'a demandé aucun protocole ou si NPN n'est pas activé, data est défini à NULL et len est défini à 0. Note : le client peut demander n'importe quel protocole de son choix. La valeur renvoyée par cette fonction n'a pas besoin d'être un membre de la liste des protocoles pris en charge par le rappel.

La fonctionnalité NPN ne peut pas être utilisée avec des objets SSL QUIC. L'utilisation d'ALPN est obligatoire lors de l'utilisation d'objets SSL QUIC. SSL_CTX_set_next_protos_advertised_cb() et SSL_CTX_set_next_proto_select_cb() n'ont aucun effet s'ils sont appelés sur un contexte SSL QUIC.

NOTES

Les listes de protocoles doivent être dans le format de fil de fer, défini comme un tableau de chaînes non vides, précédées de leur longueur par un octet. L'octet de préfixe n'est pas inclus dans la longueur. Chaque chaîne est limitée à 255 octets. Une chaîne de longueur d'octet 0 est invalide. Une chaîne tronquée est invalide. La longueur du tableau n'est pas incluse dans le tableau lui-même, mais dans une variable distincte.

Exemple :

unsigned char vector[] = {
    6, 's', 'p', 'd', 'y', '/', '1',
    8, 'h', 't', 't', 'p', '/', '1', '.', '1'
};
unsigned int length = sizeof(vector);

Le rappel ALPN est exécuté après le rappel du nom du serveur. Comme le rappel du nom du serveur peut mettre à jour le SSL_CTX, et par conséquent, le rappel ALPN.

S'il n'y a pas de proposition ALPN dans le ClientHello, le rappel ALPN n'est pas appelé.

SSL_CTX_set_alpn_select_cb(3ssl)

NAME

SSL_CTX_set_alpn_select_cb, SSL_CTX_set_next_proto_select_cb, SSL_CTX_set_next_protos_advertised_cb - set Application-Layer Protocol Negotiation (ALPN) callbacks

SYNOPSIS 

 #include <openssl/ssl.h>
 int SSL_CTX_set_alpn_select_cb(SSL_CTX *ctx,
     int (*cb)(SSL *ssl, const unsigned char **out,
     unsigned int *outlen, void *arg),
     void *arg);
 int SSL_CTX_set_next_proto_select_cb(SSL_CTX *ctx,
     void (*cb)(SSL *ssl, const unsigned char **out,
     unsigned char *outlen, void *arg),
     void *arg);
 int SSL_CTX_set_next_protos_advertised_cb(SSL_CTX *ctx,
     int (*cb)(SSL *ssl, const unsigned char **out,
     unsigned int *outlen, void *arg),
     void *arg);

DESCRIPTION

The SSL_CTX_set_alpn_select_cb() function sets a callback function cb in ctx. This callback is invoked when a TLS extension is received from the client indicating the Application-Layer Protocol Negotiation (ALPN) extension is present. The callback should select a protocol from the list offered by the client. The client's list is passed via the out and outlen parameters. The callback must set out to point to the chosen protocol and outlen to its length. The callback must return one of the SSL_TLSEXT_ERR_OK, SSL_TLSEXT_ERR_ALERT_FATAL, or SSL_TLSEXT_ERR_NOACK values. Any other return value is fatal to the connection. The arg is a user-provided pointer that is passed to the callback.

The callback set using SSL_CTX_set_next_proto_select_cb() is the original callback used for ALPN, but using a different name. The callback is invoked when the server receives the Next Protocol Negotiation extension from the client. The callback must select a protocol from the list offered by the client. The client's list is passed via the out and outlen parameters. The callback must set out to point to the chosen protocol and outlen to its length. The callback must return 0 on success. Any other return value is fatal to the connection. The arg is a user-provided pointer that is passed to the callback.

The callback set using SSL_CTX_set_next_protos_advertised_cb() is used to provide the list of protocols that the server wishes to advertise. The callback is invoked when the server is constructing its TLS handshake messages. The callback must set out to point to a buffer containing a list of protocols and outlen to its length. The list is encoded as a sequence of length-prefixed protocol names, e.g., \x02h1\x03h23. The callback must return SSL_TLSEXT_ERR_OK if it successfully provides a list of protocols to advertise. Any other return value means that no such extension will be included in the ServerHello. The arg is a user-provided pointer that is passed to the callback.

NOTES

The ALPN extension is defined in RFC 7469. The Next Protocol Negotiation extension is a predecessor, defined in an earlier draft, and should not be used.

The callback provided to SSL_CTX_set_alpn_select_cb() receives the client's offered protocols in out and outlen. The callback must select one of these protocols and make out and outlen point to the selected protocol. The memory pointed to by out must remain valid until the SSL connection is closed. If the callback returns SSL_TLSEXT_ERR_NOACK, then no ALPN extension is sent in the ServerHello. If the callback returns SSL_TLSEXT_ERR_ALERT_FATAL, a fatal alert is sent to the client. If the callback returns SSL_TLSEXT_ERR_OK, then the selected protocol is sent in the ServerHello.

The callback provided to SSL_CTX_set_next_proto_select_cb() receives the client's offered protocols in out and outlen. The callback must select one of these protocols and make out and outlen point to the selected protocol. The memory pointed to by out must remain valid until the SSL connection is closed. If the callback returns NULL, then no Next Protocol Negotiation extension is sent in the ServerHello. If the callback returns any other value, a fatal alert is sent to the client. The callback must return 0 on success, setting *out to the selected protocol and *outlen to its length.

The callback provided to SSL_CTX_set_next_protos_advertised_cb() is called to get the list of protocols to advertise. The callback must set *out to a buffer containing the list of protocols and *outlen to its length. The buffer must remain valid until the SSL connection is closed. If the callback returns SSL_TLSEXT_ERR_OK, then the advertised protocols are sent in the ServerHello. If the callback returns any other value, no Next Protocol Negotiation extension is sent.

Note: The callback signature for SSL_CTX_set_next_proto_select_cb() is different from the others. It takes an unsigned char *outlen instead of an unsigned int *outlen, and it returns 0 on success, while the others return SSL_TLSEXT_ERR_OK on success. The function SSL_CTX_set_alpn_select_cb() is the modern API and should be preferred over SSL_CTX_set_next_proto_select_cb().

The callback should not block or perform lengthy operations.

The server-side ALPN callback is invoked during the server's handshake. The client-side ALPN callback is invoked during the client's handshake. The callback is called with an SSL(3) object. The context pointer arg is the same value that was passed to SSL_CTX_set_alpn_select_cb().

The client may offer an empty list of protocols. In this case, the callback should return SSL_TLSEXT_ERR_NOACK. (This applies to the callback set via SSL_CTX_set_alpn_select_cb()). For the callback set via SSL_CTX_set_next_proto_select_cb(), the callback should return NULL.

The server may choose not to support ALPN at all. In this case, it should set the callback to NULL. If the client sends an ALPN extension and the server does not support it (i.e., the callback is NULL), the connection will be terminated with an incompatible protocol alert.

The callback is responsible for managing the memory pointed to by out. The pointer must remain valid for the lifetime of the SSL connection. A common approach is to store the selected protocol in a buffer associated with the SSL object, for example, using SSL_set_ex_data(3).

The server callback function cb, when set using SSL_CTX_set_alpn_select_cb(), must return one of the following:

SSL_TLSEXT_ERR_OK
ALPN protocol selected.
SSL_TLSEXT_ERR_ALERT_FATAL
There was no overlap between the client's supplied list and the server configuration.
SSL_TLSEXT_ERR_NOACK
ALPN protocol not selected, e.g., because no ALPN protocols are configured for this connection.

The callback set using SSL_CTX_set_next_proto_select_cb() should return 0 if successful. Any other value is fatal to the connection.

The callback set using SSL_CTX_set_next_protos_advertised_cb() should return SSL_TLSEXT_ERR_OK if it wishes to advertise. Otherwise, no such extension will be included in the ServerHello.

RETURN VALUES

All functions return 1 on success and 0 on failure.
