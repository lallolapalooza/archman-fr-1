NOM

SSL_connect - initier la négociation TLS/SSL avec un serveur TLS/SSL

SYNTAXE

#include <openssl/ssl.h>
int SSL_connect(SSL *ssl);

DESCRIPTION

SSL_connect() initie la négociation TLS/SSL avec un serveur. Le canal de communication doit déjà avoir été établi et assigné à ssl en définissant un BIO sous-jacent. ssl NE DOIT PAS être NULL.

NOTES

Le comportement de SSL_connect() dépend du BIO sous-jacent.

Si le BIO sous-jacent est bloquant, SSL_connect() ne retournera qu'une fois la négociation terminée ou qu'une erreur s'est produite.

Si le BIO sous-jacent est non bloquant, SSL_connect() retournera également lorsque le BIO sous-jacent n'aura pas pu satisfaire les besoins de SSL_connect() pour continuer la négociation, indiquant le problème par la valeur de retour -1. Dans ce cas, un appel à SSL_get_error() avec la valeur de retour de SSL_connect() renverra SSL_ERROR_WANT_READ ou SSL_ERROR_WANT_WRITE. Le processus appelant doit alors répéter l'appel après avoir pris les mesures appropriées pour satisfaire les besoins de SSL_connect(). L'action dépend du BIO sous-jacent. En utilisant un socket non bloquant, rien n'est à faire, mais select() peut être utilisé pour vérifier la condition requise. En utilisant un BIO de mise en tampon, comme une paire de BIO, des données doivent être écrites dans le BIO ou récupérées de celui-ci avant de pouvoir continuer.

De nombreux systèmes implémentent l'algorithme de Nagle par défaut, ce qui signifie qu'il mettra en mémoire tampon les données TCP sortantes si un paquet TCP a déjà été envoyé pour lequel aucun ACK correspondant n'a encore été reçu du pair. Cela peut avoir un impact sur les performances après une négociation TLSv1.3 réussie ou une reprise de négociation TLSv1.2 (ou inférieure) réussie, car le dernier pair à communiquer dans la négociation est le client. Si le client est également le premier à envoyer des données d'application (comme c'est typique pour de nombreux protocoles), ces données pourraient être mises en mémoire tampon jusqu'à ce qu'un ACK soit reçu pour le dernier message de négociation.

L'option de socket TCP_NODELAY est souvent disponible pour désactiver l'algorithme de Nagle. Si une application choisit de désactiver l'algorithme de Nagle, il convient d'envisager de le réactiver plus tard si nécessaire. La fonction d'aide BIO_set_tcp_ndelay() peut être utilisée pour activer ou désactiver l'option TCP_NODELAY.

VALEURS DE RETOUR

Les valeurs de retour suivantes peuvent se produire :

0
La négociation TLS/SSL n'a pas abouti mais a été arrêtée de manière contrôlée et conformément aux spécifications du protocole TLS/SSL. Appelez SSL_get_error() avec la valeur de retour ret pour connaître la raison.
1
La négociation TLS/SSL s'est terminée avec succès, une connexion TLS/SSL a été établie.
<0
La négociation TLS/SSL n'a pas abouti, car une erreur fatale s'est produite au niveau du protocole ou une défaillance de connexion s'est produite. L'arrêt n'a pas été propre. Cela peut également se produire si une action est nécessaire pour continuer l'opération pour les BIO non bloquants. Appelez SSL_get_error() avec la valeur de retour ret pour connaître la raison.
