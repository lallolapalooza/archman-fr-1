SSL_CTX_set1_cert_comp_preference(3ssl)

Paquet: openssl

Licences: Apache-2.0

SSL_CTX_set1_cert_comp_preference(3ssl) OpenSSL SSL_CTX_set1_cert_comp_preference(3ssl)

NOM

SSL_CTX_set1_cert_comp_preference, SSL_set1_cert_comp_preference, SSL_CTX_compress_certs, SSL_compress_certs, SSL_CTX_get1_compressed_cert, SSL_get1_compressed_cert, SSL_CTX_set1_compressed_cert, SSL_set1_compressed_cert - Fonctions de compression de certificats

SYNOPIS

#include <openssl/ssl.h>
int SSL_CTX_set1_cert_comp_preference(SSL_CTX *ctx, int *algs, size_t len);
int SSL_set1_cert_comp_preference(SSL *ssl, int *algs, size_t len);
int SSL_CTX_compress_certs(SSL_CTX *ctx, int alg);
int SSL_compress_certs(SSL *ssl, int alg);
size_t SSL_CTX_get1_compressed_cert(SSL_CTX *ctx, int alg, unsigned char **data,
                                    size_t *orig_len);
size_t SSL_get1_compressed_cert(SSL *ssl, int alg, unsigned char **data,
                                size_t *orig_len);
int SSL_CTX_set1_compressed_cert(SSL_CTX *ctx, int alg,
                                 unsigned char *comp_data,
                                 size_t comp_length, size_t orig_length);
int SSL_set1_compressed_cert(SSL *ssl, int alg, unsigned char *comp_data,
                             size_t comp_length, size_t orig_length);

DESCRIPTION

Ces fonctions contrôlent la fonctionnalité de compression de certificats. La compression de certificats n'est disponible que pour TLSv1.3, comme défini dans la RFC8879.

SSL_CTX_set1_cert_comp_preference() et SSL_set1_cert_comp_preference() sont utilisés pour spécifier les algorithmes de compression préférés. L'argument algs est un tableau d'algorithmes et length est le nombre d'éléments dans le tableau algs. Seuls les algorithmes activés dans la bibliothèque seront acceptés dans algs, les algorithmes inconnus dans algs sont ignorés. En cas d'erreur, l'ordre de préférence n'est pas modifié.

Les algorithmes de compression suivants (arguments alg) peuvent être utilisés :

  • TLSEXT_comp_cert_brotli
  • TLSEXT_comp_cert_zlib
  • TLSEXT_comp_cert_zstd

L'ordre ci-dessus est également l'ordre de préférence par défaut. Si aucun ordre de préférence n'est spécifié, l'ordre par défaut est envoyé à l'autre partie et l'ordre de préférence de la partie réceptrice est utilisé lors de la compression d'un certificat. Sinon, l'ordre de préférence configuré est envoyé à l'autre partie et est utilisé pour filtrer l'ordre de préférence de la partie réceptrice.

SSL_CTX_compress_certs() et SSL_compress_certs() sont utilisés pour précompresser tous les certificats configurés dans un objet SSL_CTX/SSL avec l'algorithme alg. Si alg est 0, les certificats sont compressés avec les algorithmes spécifiés dans la liste de préférences. Appeler ces fonctions sur un objet SSL_CTX/SSL côté client entraînera une erreur, car seuls les certificats côté serveur peuvent être précompressés.

SSL_CTX_get1_compressed_cert() et SSL_get1_compressed_cert() sont utilisés pour obtenir le certificat précompressé le plus récent qui peut être stocké pour une utilisation ultérieure. Appeler ces fonctions sur un objet SSL_CTX/SSL côté client entraînera une erreur, car seuls les certificats côté serveur peuvent être précompressés. Les arguments data et orig_len sont obligatoires.

Les données de certificat compressé peuvent être transmises à SSL_CTX_set1_compressed_cert() ou SSL_set1_compressed_cert() pour fournir une version précompressée du certificat le plus récent. Cette version précompressée du certificat ne peut être utilisée que par un serveur.

NOTES

Chaque côté de la connexion envoie sa liste d'algorithmes de préférence de compression à l'autre côté indiquant le support de la compression de certificats. La liste de préférences reçue est filtrée par l'ordre de préférences configuré (c'est-à-dire que l'intersection est conservée). Comme l'ordre par défaut inclut tous les algorithmes activés, ne pas spécifier d'ordre de préférences permet à tout algorithme activé par l'autre partie. L'ordre de préférences de la partie réceptrice est utilisé pour déterminer quel algorithme utiliser lors de l'envoi d'un certificat compressé.

Seuls les certificats serveur peuvent être précompressés. L'appel de l'une de ces fonctions (sauf SSL_CTX_set1_cert_comp_preference()/SSL_set1_cert_comp_preference()) sur un objet SSL_CTX/SSL client renverra une erreur. Les certificats client sont compressés à la demande, lorsque le contexte de compression du serveur est utilisé conjointement avec le certificat.

Pour SSL_CTX_set1_cert_comp_preference() et SSL_set1_cert_comp_preference(), l'argument len est la taille de algs en octets.

Le certificat compressé renvoyé par SSL_CTX_get1_compressed_cert() et SSL_get1_compressed_cert() est le dernier certificat défini dans l'objet SSL_CTX/SSL. Le certificat est copié par la fonction et l'utilisateur doit libérer *data à l'aide de OPENSSL_free().

Les données de certificat compressé définies par SSL_CTX_set1_compressed_cert() et SSL_set1_compressed_cert() sont copiées dans l'objet SSL_CTX/SSL.

SSL_CTX_compress_certs() et SSL_compress_certs() renvoient une erreur dans les conditions suivantes :

  • Si aucun certificat n'a été configuré.
  • Si l'algorithme spécifié alg n'est pas activé.
  • Si alg est 0 et aucun algorithme n'est activé.

La compression de certificats peut être désactivée sur une connexion à l'aide de l'option SSL_OP_NO_TX_CERTIFICATE_COMPRESSION. La compression de certificats peut être désactivée sur une connexion à l'aide de l'option SSL_OP_NO_RX_CERTIFICATE_COMPRESSION.

VALEURS DE RETOUR

SSL_CTX_set1_cert_comp_preference(), SSL_set1_cert_comp_preference(), SSL_CTX_compress_certs(), SSL_compress_certs(), SSL_CTX_set1_compressed_cert() et SSL_set1_compressed_cert() renvoient 1 en cas de succès et 0 en cas d'erreur.

SSL_CTX_get1_compressed_cert() et SSL_get1_compressed_cert() renvoient la longueur de la mémoire allouée en cas de succès et 0 en cas d'erreur.

VOIR AUSSI
