SSL_CTX_set_tlsext_servername_callback(3ssl)

Paquet: openssl

Licences: Apache-2.0

SSL_CTX_set_tlsext_servername_callback(3ssl) OpenSSL SSL_CTX_set_tlsext_servername_callback(3ssl)

NOM

SSL_CTX_set_tlsext_servername_callback, SSL_CTX_set_tlsext_servername_arg, SSL_get_servername_type, SSL_get_servername, SSL_set_tlsext_host_name - gestion des indicateurs de nom de serveur (SNI)

SYNOPIS

#include <openssl/ssl.h>
long SSL_CTX_set_tlsext_servername_callback(SSL_CTX *ctx,
                                  int (*cb)(SSL *s, int *al, void *arg));
long SSL_CTX_set_tlsext_servername_arg(SSL_CTX *ctx, void *arg);
const char *SSL_get_servername(const SSL *s, const int type);
int SSL_get_servername_type(const SSL *s);
int SSL_set_tlsext_host_name(const SSL *s, const char *name);

DESCRIPTION

La fonctionnalité fournie par le callback de nom de serveur est principalement remplacée par le callback ClientHello, qui peut être configuré en utilisant SSL_CTX_set_client_hello_cb(). Cependant, même lorsque le callback ClientHello est utilisé, le callback servername est toujours nécessaire pour confirmer le nom de serveur demandé par le client.

SSL_CTX_set_tlsext_servername_callback() configure le callback d'application cb utilisé par le serveur pour effectuer toute action ou configuration basée sur le nom de serveur reçu dans la connexion entrante. Lorsque cb est nul, SNI n'est pas utilisé.

Le callback servername doit retourner l'une des valeurs suivantes :

SSL_TLSEXT_ERR_OK
Ceci est utilisé pour indiquer que le nom de serveur demandé par le client a été accepté. Généralement, un serveur appellera SSL_set_SSL_CTX() dans le callback pour définir une configuration différente pour le nom de serveur sélectionné dans ce cas.
SSL_TLSEXT_ERR_ALERT_FATAL
Dans ce cas, le nom de serveur demandé par le client n'a pas été accepté et le handshake est interrompu. La valeur de l'alerte à utiliser doit être stockée dans l'emplacement indiqué par le paramètre al du callback. Par défaut, cette valeur est initialisée à SSL_AD_UNRECOGNIZED_NAME.
SSL_TLSEXT_ERR_ALERT_WARNING
Si cette valeur est retournée, alors le nom de serveur n'a pas été accepté par le serveur. Cependant, le handshake continuera et enverra une alerte d'avertissement à la place. La valeur de l'alerte doit être stockée dans l'emplacement indiqué par le paramètre al, comme pour SSL_TLSEXT_ERR_ALERT_FATAL. Notez que TLSv1.3 ne prend pas en charge les alertes d'avertissement, donc si TLSv1.3 a été négocié, cette valeur de retour est traitée de manière identique à SSL_TLSEXT_ERR_NOACK.
SSL_TLSEXT_ERR_NOACK
Cette valeur de retour indique que le nom de serveur n'a pas été accepté par le serveur. Aucune alerte n'est envoyée et le nom de serveur demandé n'est pas reconnu par le serveur.

SSL_CTX_set_tlsext_servername_arg() définit un argument de contexte spécifique qui est passé au callback (via le paramètre arg) pour ce SSL_CTX.

Le comportement de SSL_get_servername() dépend de plusieurs facteurs. Notamment, il est important de noter que dans TLSv1.3, le nom de serveur sera négocié à chaque handshake. Dans TLSv1.2, le nom de serveur sera négocié uniquement lors des handshakes initiaux et non lors des handshakes de résumé.

Du côté client, avant le handshake
Si un nom de serveur a été défini par un appel à SSL_set_tlsext_host_name(), alors il retournera ce nom de serveur.

Sinon, mais si un handshake de résumé TLSv1.2 est tenté et que la session du handshake d'origine avait un nom de serveur accepté par le serveur, il retournera ce nom de serveur.

Sinon, il retourne NULL.

Du côté client, pendant ou après le handshake et un handshake de résumé TLSv1.2 (ou inférieur) se produit
Si la session du handshake d'origine avait un nom de serveur accepté par le serveur, il retournera ce nom de serveur.

Sinon, il retourne le nom de serveur défini par SSL_set_tlsext_host_name() ou NULL s'il n'a pas été appelé.

Du côté client, pendant ou après le handshake et un handshake de résumé TLSv1.2 (ou inférieur) ne se produit pas
Il retournera le nom de serveur défini par SSL_set_tlsext_host_name() ou NULL s'il n'a pas été appelé.
Du côté serveur, avant le handshake
La fonction retourne toujours NULL avant le handshake.
Du côté serveur, après que l'extension de nom de serveur ait été traitée et qu'un handshake de résumé TLSv1.2 (ou inférieur) ait eu lieu
Si le nom de serveur a été accepté par le serveur lors du handshake d'origine, il retournera ce nom de serveur, ou NULL sinon.
Du côté serveur, après que l'extension de nom de serveur ait été traitée et qu'un handshake de résumé TLSv1.2 (ou inférieur) n'ait pas eu lieu
Il retournera le nom de serveur demandé par le client lors de ce handshake ou NULL si aucun n'a été demandé.

Note : le callback ClientHello se produit avant le traitement d'une extension de nom de serveur du client. Les callbacks servername, certificate et ALPN se produisent après le traitement d'une extension de nom de serveur du client.

SSL_get_servername_type() retourne le type de nom de serveur ou -1 si aucun nom de serveur n'est présent. Actuellement, le seul type pris en charge (défini dans RFC3546) est TLSEXT_NAMETYPE_host_name.

SSL_set_tlsext_host_name() définit la valeur de l'extension de nom de serveur dans le ClientHello pour contenir la valeur name. Le type d'extension de nom de serveur est défini sur TLSEXT_NAMETYPE_host_name (défini dans RFC3546).

NOTES

Plusieurs callbacks sont exécutés pendant le processus de ClientHello, y compris le callback ClientHello, ALPN et les callbacks de nom de serveur. Le callback ClientHello est exécuté en premier, puis le callback servername, suivi du callback ALPN.

La fonction SSL_set_tlsext_host_name() ne doit être appelée que sur les objets SSL qui agissent en tant que clients; sinon, la valeur définie name sera ignorée.

VALEURS DE RETOUR

SSL_CTX_set_tlsext_servername_callback() et SSL_CTX_set_tlsext_servername_arg() retournent toujours 1, indiquant le succès. SSL_set_tlsext_host_name() retourne 1 en cas de succès, 0 en cas d'erreur.

HISTORIQUE

Historiquement, SSL_get_servername() a donné des résultats inattendus dans certains cas limites. Cela a été corrigé depuis OpenSSL 1.1.1e.

Avant 1.1.1e, lorsque le client demandait un nom de serveur lors d'un handshake TLSv1.2 initial, le serveur l'acceptait, puis le client reprenait avec succès mais définissait un nom de serveur différent lors du second handshake, alors que SSL_get_servername() retournait le nom de serveur du second handshake lorsqu'il était appelé côté client. Ceci a été modifié pour retourner le nom de serveur demandé lors du handshake d'origine.

Également avant 1.1.1e, si le client envoyait un nom de serveur lors du premier handshake mais que le serveur ne l'acceptait pas, puis qu'un second handshake de résumé TLSv1.2 réussissait, et qu'ensuite il était appelé côté serveur, il retournait le nom de serveur demandé lors du handshake d'origine. Ceci a été modifié pour retourner NULL.
