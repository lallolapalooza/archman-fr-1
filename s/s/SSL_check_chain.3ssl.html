NOM

SSL_check_chain - vérifier l'adéquation de la chaîne de certificats

SYNTAXE

#include <openssl/ssl.h>
int SSL_check_chain(SSL *s, X509 *x, EVP_PKEY *pk, STACK_OF(X509) *chain);

DESCRIPTION

SSL_check_chain() vérifie si le certificat x, la clé privée pk et la chaîne de certificats chain sont appropriés pour être utilisés avec la session actuelle s.

VALEURS DE RETOUR

SSL_check_chain() retourne un masque de bits d'indicateurs indiquant la validité de la chaîne.

CERT_PKEY_VALID : la chaîne peut être utilisée avec la session actuelle. Si cet indicateur n'est pas défini, le certificat ne sera jamais utilisé même si l'application essaie de le définir car il est incohérent avec les préférences du pair.

CERT_PKEY_SIGN : la clé de l'entité finale peut être utilisée pour la signature.

CERT_PKEY_EE_SIGNATURE : l'algorithme de signature du certificat de l'entité finale est acceptable.

CERT_PKEY_CA_SIGNATURE : les algorithmes de signature de tous les certificats d'AC sont acceptables.

CERT_PKEY_EE_PARAM : les paramètres du certificat de l'entité finale sont acceptables (par exemple, c'est une courbe supportée).

CERT_PKEY_CA_PARAM : les paramètres de tous les certificats d'AC sont acceptables.

CERT_PKEY_EXPLICIT_SIGN : l'algorithme du certificat de l'entité finale peut être utilisé explicitement pour la signature (c'est-à-dire qu'il est mentionné dans l'extension des algorithmes de signature).

CERT_PKEY_ISSUER_NAME : le nom de l'émetteur est acceptable. Ceci n'est pertinent que pour l'authentification client.

CERT_PKEY_CERT_TYPE : le type de certificat est acceptable. Uniquement pertinent pour l'authentification client.

CERT_PKEY_SUITEB : la chaîne est adaptée à une utilisation Suite B.

NOTES

SSL_check_chain() doit être appelé sur les serveurs après un message client hello ou sur les clients après un message de demande de certificat. Il sera généralement appelé dans la fonction de rappel de certificat.

Une application souhaitant prendre en charge plusieurs chaînes de certificats peut appeler cette fonction sur chaque chaîne tour à tour : en commençant par celle qu'elle considère comme la plus sécurisée. Elle pourrait alors utiliser la chaîne du premier ensemble qui renvoie les indicateurs appropriés.

Au minimum, l'indicateur CERT_PKEY_VALID doit être défini pour qu'une chaîne soit utilisable. Une application prenant en charge plusieurs chaînes avec différents algorithmes de signature d'AC peut également souhaiter vérifier CERT_PKEY_CA_SIGNATURE. Si aucune chaîne n'est appropriée, un serveur devrait se rabattre sur la chaîne la plus sécurisée qui définit CERT_PKEY_VALID.

La validité d'une chaîne est déterminée en vérifiant si elle correspond à un algorithme de signature pris en charge, des courbes prises en charge et, dans le cas de l'authentification client, des types de certificats et des noms d'émetteurs.

Étant donné que l'extension des algorithmes de signature pris en charge n'est utilisée que dans TLS 1.2, TLS 1.3 et DTLS 1.2, les résultats pour les versions antérieures de TLS et DTLS peuvent ne pas être très utiles. Les applications peuvent souhaiter spécifier une chaîne "héritée" différente pour les versions antérieures de TLS ou DTLS.
