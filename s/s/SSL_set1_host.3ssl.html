SSL_set1_host(3ssl)

Paquet: openssl

Licences: Apache-2.0

SSL_SET1_HOST(3ssl) OpenSSL SSL_SET1_HOST(3ssl)

NOM

SSL_set1_host, SSL_add1_host, SSL_set_hostflags, SSL_get0_peername - Paramètres de vérification du serveur SSL

SYNTAXE

#include <openssl/ssl.h>
int SSL_set1_host(SSL *s, const char *host);
int SSL_add1_host(SSL *s, const char *host);
void SSL_set_hostflags(SSL *s, unsigned int flags);
const char *SSL_get0_peername(SSL *s);

DESCRIPTION

Ces fonctions configurent les vérifications du nom d'hôte du serveur dans le client SSL.

SSL_set1_host() définit dans les paramètres de vérification de s le nom d'hôte DNS ou l'adresse IP attendus à host, effaçant toute adresse IP et tout nom d'hôte précédemment spécifiés. Si host est NULL ou une chaîne vide, les vérifications d'adresse IP et de nom d'hôte ne sont pas effectuées sur le certificat du pair. Lorsqu'un host non vide est spécifié, la vérification du certificat vérifie automatiquement le nom d'hôte du pair via X509_check_host(3) avec les flags spécifiés via SSL_set_hostflags(). Les clients qui activent l'authentification DANE TLSA via SSL_dane_enable(3) devraient laisser à cette fonction le soin de définir l'identifiant de référence principal du pair, et ne devraient pas appeler SSL_set1_host().

SSL_add1_host() ajoute host comme identifiant de référence supplémentaire pouvant correspondre au certificat du pair. Tous les noms d'hôtes précédents définis via SSL_set1_host() ou SSL_add1_host() sont conservés. L'ajout d'une adresse IP n'est autorisé que si aucune adresse IP n'a été définie auparavant. Aucun changement n'est apporté si host est NULL ou vide. Lorsqu'une adresse IP et/ou plusieurs noms d'hôtes sont configurés, le pair est considéré comme vérifié lorsque l'un de ces identifiants correspond. Cette fonction est requise pour DANE TLSA en présence d'une indirection de nom de service via des enregistrements CNAME, MX ou SRV, comme spécifié dans les RFC 7671, 7672 et 7673.

Il est recommandé aux clients TLS d'utiliser SSL_set1_host() ou SSL_add1_host() pour la validation du nom d'hôte ou de l'adresse IP du serveur, ainsi que SSL_set_tlsext_host_name(3) pour l'indication du nom du serveur (SNI), ce qui peut également être crucial pour le routage correct de la demande de connexion.

SSL_set_hostflags() définit les flags qui seront transmis à X509_check_host(3) lorsque les vérifications de noms sont applicables, par défaut la valeur des flags est 0. Voir X509_check_host(3) pour la liste des flags disponibles et leur signification.

SSL_get0_peername() retourne le nom d'hôte DNS ou le CommonName du sujet du certificat du pair qui correspondait à l'un des identifiants de référence. Lorsque la correspondance joker n'est pas désactivée, le nom correspondant dans le certificat du pair peut être un nom joker. Lorsqu'un des identifiants de référence configurés via SSL_set1_host() ou SSL_add1_host() commence par ".", indiquant un préfixe de domaine parent plutôt qu'un nom fixe, le nom du pair correspondant peut être un sous-domaine de l'identifiant de référence. La chaîne retournée est allouée par la bibliothèque et n'est plus valide une fois que le descripteur ssl associé est effacé ou libéré, ou qu'une renégociation a lieu. Les applications ne doivent pas libérer la valeur de retour.

Il est conseillé aux clients SSL d'utiliser ces fonctions plutôt que d'appeler explicitement X509_check_host(3). Les vérifications de noms d'hôtes peuvent être hors de portée avec l'utilisation de certificat DANE-EE RFC 7671, et la vérification interne sera supprimée de manière appropriée lorsque DANE est activé.

VALEURS DE RETOUR

SSL_set1_host() et SSL_add1_host() retournent 1 en cas de succès et 0 en cas d'échec.

SSL_set_hostflags() ne retourne rien du tout.

SSL_get0_peername() retourne NULL si la vérification du nom du pair n'est pas applicable (comme avec DANE-EE RFC 7671), ou si aucun nom de pair digne de confiance n'a été trouvé. Sinon, il retourne le nom du pair trouvé. Pour déterminer si la vérification a réussi, appelez SSL_get_verify_result(3).

EXEMPLES

Supposons que "smtp.example.com" soit le nom d'hôte MX du domaine "example.com". Les appels ci-dessous organiseront la correspondance soit du nom d'hôte MX, soit du nom de domaine de destination dans le certificat du serveur SMTP. Les jokers sont pris en charge, mais doivent correspondre à l'étiquette entière. Le nom réel trouvé dans le certificat (qui pourrait être un joker) est récupéré et doit être copié par l'application s'il doit être conservé au-delà de la durée de vie de la connexion SSL.

SSL_set_hostflags(ssl, X509_CHECK_FLAG_NO_PARTIAL_WILDCARDS);
if (!SSL_set1_host(ssl, "smtp.example.com"))
    /* erreur */
if (!SSL_add1_host(ssl, "example.com"))
    /* erreur */
/* XXX : Effectuer SSL_connect() handshake et gérer les erreurs ici */
if (SSL_get_verify_result(ssl) == X509_V_OK) {
    const char *peername = SSL_get0_peername(ssl);
    if (peername != NULL)
        /* Les vérifications de noms étaient applicables et correspondaient au peername */
}
