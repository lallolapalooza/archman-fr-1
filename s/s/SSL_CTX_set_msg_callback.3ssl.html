SSL_CTX_set_msg_callback(3ssl) OpenSSL SSL_CTX_set_msg_callback(3ssl)

NOM

SSL_CTX_set_msg_callback, SSL_CTX_set_msg_callback_arg, SSL_set_msg_callback, SSL_set_msg_callback_arg, SSL_trace - installer une fonction de rappel pour observer les messages de protocole

SYNOPSIS

#include <openssl/ssl.h>
void SSL_CTX_set_msg_callback(SSL_CTX *ctx,
                              void (*cb)(int write_p, int version,
                                         int content_type, const void *buf,
                                         size_t len, SSL *ssl, void *arg));
void SSL_CTX_set_msg_callback_arg(SSL_CTX *ctx, void *arg);
void SSL_set_msg_callback(SSL *ssl,
                          void (*cb)(int write_p, int version,
                                     int content_type, const void *buf,
                                     size_t len, SSL *ssl, void *arg));
void SSL_set_msg_callback_arg(SSL *ssl, void *arg);
void SSL_trace(int write_p, int version, int content_type,
               const void *buf, size_t len, SSL *ssl, void *arg);

DESCRIPTION

SSL_CTX_set_msg_callback() ou SSL_set_msg_callback() peuvent être utilisés pour définir une fonction de rappel cb afin d'observer tous les messages de protocole SSL/TLS/QUIC (tels que les messages de handshake) qui sont reçus ou envoyés, ainsi que d'autres événements qui se produisent pendant le traitement. SSL_CTX_set_msg_callback_arg() et SSL_set_msg_callback_arg() peuvent être utilisés pour définir l'argument arg pour la fonction de rappel, qui est disponible pour une utilisation arbitraire par l'application.

SSL_CTX_set_msg_callback() et SSL_CTX_set_msg_callback_arg() spécifient les valeurs par défaut qui sont copiées aux nouveaux objets SSL par SSL_new(3). SSL_set_msg_callback() et SSL_set_msg_callback_arg() modifient les valeurs effectives d'un objet SSL. L'utilisation d'un pointeur NULL pour cb désactive la fonction de rappel.

Lorsque cb est appelé par la bibliothèque SSL/TLS/QUIC, les arguments ont la signification suivante :

write_p
Ce drapeau est 0 lorsqu'un message de protocole a été reçu et 1 lorsqu'un message de protocole a été envoyé.
version
Le numéro de version du protocole selon lequel le message de protocole est interprété par la bibliothèque, comme TLS1_3_VERSION, TLS1_2_VERSION, OSSL_QUIC1_VERSION etc. Pour le type de contenu pseudo SSL3_RT_HEADER (voir NOTES ci-dessous), cette valeur sera le champ décodé / legacy_version de l'en-tête de l'enregistrement.
content_type
C'est l'une des valeurs de type de contenu définies dans la spécification du protocole (SSL3_RT_CHANGE_CIPHER_SPEC, SSL3_RT_ALERT, SSL3_RT_HANDSHAKE; mais jamais SSL3_RT_APPLICATION_DATA car la fonction de rappel ne sera appelée que pour les messages de protocole). Alternativement, cela peut être un type de contenu pseudo. Ces types de contenu pseudo sont utilisés pour signaler un autre événement dans le traitement des données (voir NOTES ci-dessous).
buf, len
buf pointe vers un tampon contenant le message de protocole ou d'autres données (dans le cas de types de contenu pseudo), qui contient len octets. Le tampon n'est pas valide une fois que la fonction de rappel a terminé.
ssl
L'objet SSL qui a reçu ou envoyé le message.
arg
L'argument personnalisé optionnel défini par SSL_CTX_set_msg_callback_arg() ou SSL_set_msg_callback_arg().

La fonction SSL_trace() peut être utilisée comme fonction de rappel prédéfinie dans un appel à SSL_CTX_set_msg_callback() ou SSL_set_msg_callback(). Elle nécessite une BIO à utiliser comme argument de rappel, via SSL_CTX_set_msg_callback_arg() ou SSL_set_msg_callback_arg(). La définition de cette fonction de rappel entraînera l'écriture d'informations de diagnostic lisibles par l'homme sur une connexion SSL/TLS/QUIC dans la BIO.

NOTES

Les messages de protocole sont envoyés à la fonction de rappel après le déchiffrement et la réassemblage des fragments, le cas échéant. (Par conséquent, les limites d'enregistrement ne sont pas visibles.)

Si le traitement d'un message de protocole reçu entraîne une erreur, la fonction de rappel ne sera pas appelée. Par exemple, la fonction de rappel ne verra jamais les messages considérés comme trop volumineux pour être traités.

En raison de la négociation automatique de la version du protocole, la valeur version n'est pas nécessairement la version de l'expéditeur du message : si un message de type ClientHello de TLS 1.0 est reçu par un serveur uniquement SSL 3.0, version sera SSL3_VERSION.

Les valeurs de type de contenu pseudo peuvent être envoyées à divers points pendant le traitement des données. Les types de contenu pseudo suivants sont actuellement définis :

SSL3_RT_HEADER
Utilisé lors de l'envoi ou de la réception d'un enregistrement TLS. Le buf ne contient que les octets de l'en-tête de l'enregistrement.
SSL3_RT_INNER_CONTENT_TYPE
Utilisé lors de l'envoi ou de la réception d'un enregistrement TLSv1.3 chiffré. Dans les enregistrements TLSv1.3 chiffrés, le type de contenu dans l'en-tête de l'enregistrement est toujours SSL3_RT_APPLICATION_DATA. Le type de contenu réel de l'enregistrement est contenu dans un type de contenu « interne ». Le buf contient les octets encodés du type de contenu « interne ».
SSL3_RT_QUIC_DATAGRAM
Utilisé lors de l'envoi ou de la réception d'un datagramme QUIC.
SSL3_RT_QUIC_PACKET
Utilisé lors de l'envoi ou de la réception d'un paquet QUIC.
SSL3_RT_QUIC_FRAME_FULL
Utilisé lors de l'envoi ou de la réception d'une trame QUIC. Ceci n'est utilisé que pour les trames de données non chiffrées et de flux. Les données complètes de la trame QUIC sont fournies.
SSL3_RT_QUIC_FRAME_HEADER
Utilisé lors de l'envoi ou de la réception d'une trame de données QUIC ou chiffrée. Seul l'en-tête de la trame QUIC est fourni.
SSL3_RT_QUIC_FRAME_PADDING
Utilisé lors de l'envoi ou de la réception d'une séquence d'une ou plusieurs trames de remplissage QUIC. Une trame de remplissage se compose d'un seul octet et il est courant d'avoir plusieurs trames de ce type dans une séquence. Au lieu de fournir chaque trame individuellement, la fonction de rappel fournit toutes les trames de remplissage en une seule fois via ce type de contenu pseudo.

VALEURS DE RETOUR

SSL_CTX_set_msg_callback(), SSL_CTX_set_msg_callback_arg(), SSL_set_msg_callback() et SSL_set_msg_callback_arg() ne retournent pas de valeur.

VOIR AUSSI

ssl(7), SSL_new(3)

HISTORIQUE

Le type de contenu pseudo SSL3_RT_HEADER a été ajouté dans OpenSSL 1.1.1.

Les types de contenu pseudo SSL3_RT_QUIC_DATAGRAM, SSL3_RT_QUIC_PACKET, SSL3_RT_QUIC_FRAME_FULL, SSL3_RT_QUIC_FRAME_HEADER et SSL3_RT_QUIC_FRAME_PADDING ont été ajoutés dans OpenSSL 3.2.

Dans les versions antérieures à OpenSSL 3.0, cb était appelé avec 0 comme valeur de version pour le type de contenu pseudo SSL3_RT_HEADER pour les enregistrements TLS.

Dans les versions antérieures à OpenSSL 3.2, cb était appelé avec 0 comme valeur de version pour le type de contenu pseudo SSL3_RT_HEADER pour les enregistrements DTLS.
