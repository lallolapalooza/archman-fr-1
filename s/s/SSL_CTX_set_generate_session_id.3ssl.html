SSL_CTX_set_generate_session_id(3ssl)

Paquet: openssl

Licences: Apache-2.0

SSL_CTX_set_generate_session_id(3ssl) OpenSSL SSL_CTX_set_generate_session_id(3ssl)

NOM

SSL_CTX_set_generate_session_id, SSL_set_generate_session_id, SSL_has_matching_session_id, GEN_SESSION_CB - manipuler la génération d'ID de session SSL (serveur uniquement)

SYNTAXIS

#include <openssl/ssl.h>
typedef int (*GEN_SESSION_CB)(SSL *ssl, unsigned char *id,
                              unsigned int *id_len);
int SSL_CTX_set_generate_session_id(SSL_CTX *ctx, GEN_SESSION_CB cb);
int SSL_set_generate_session_id(SSL *ssl, GEN_SESSION_CB, cb);
int SSL_has_matching_session_id(const SSL *ssl, const unsigned char *id,
                                unsigned int id_len);

DESCRIPTION

SSL_CTX_set_generate_session_id() définit la fonction de rappel pour générer de nouveaux ID de session pour les sessions SSL/TLS de ctx à cb.

SSL_set_generate_session_id() définit la fonction de rappel pour générer de nouveaux ID de session pour les sessions SSL/TLS de ssl à cb.

SSL_has_matching_session_id() vérifie si une session avec l'ID id (de longueur id_len) existe déjà dans le cache de sessions du contexte parent de ssl.

NOTES

Lorsqu'une nouvelle session est établie entre un client et un serveur, le serveur génère un ID de session. L'ID de session est une séquence arbitraire d'octets. La longueur de l'ID de session se situe entre 1 et 32 octets. L'ID de session n'est pas critique en termes de sécurité, mais il doit être unique pour le serveur. De plus, l'ID de session est transmis en clair lorsque la session est réutilisée, il ne doit donc contenir aucune information sensible.

Sans fonction de rappel définie, un serveur OpenSSL génère un ID de session unique à partir de nombres pseudo-aléatoires de longueur maximale possible. Avec la fonction de rappel, l'ID de session peut être modifié pour inclure des informations supplémentaires, telles qu'un ID d'hôte, afin d'améliorer les techniques d'équilibrage de charge ou de mise en cache externe.

La fonction de rappel reçoit un pointeur vers l'emplacement mémoire où placer id et un pointeur vers la longueur maximale autorisée id_len. La zone mémoire à l'emplacement id est garantie d'avoir uniquement la taille id_len. La fonction ne permet de générer qu'un ID plus court et de réduire id_len ; la fonction ne doit jamais augmenter id_len ni écrire dans la zone id en dehors de la limite donnée.

L'emplacement id est initialement rempli de 0x00 avant que la fonction ne soit appelée, de sorte que la fonction puisse ne remplir qu'une partie de la longueur possible et laisser id_len inchangé, tout en maintenant la reproductibilité.

Puisque les sessions doivent être distinguées, les ID de session doivent être uniques. Sans la fonction de rappel, un nombre aléatoire est utilisé, de sorte que la probabilité de générer le même ID est extrêmement faible (2^256 pour SSLv3/TLSv1). Pour garantir l'unicité de l'ID de session généré, la fonction doit appeler SSL_has_matching_session_id() et générer un autre ID en cas de conflit. Si un conflit n'est pas résolu, le handshake échouera. Si l'application code par exemple un ID d'hôte unique, un numéro de processus unique et un numéro de séquence unique dans l'ID de session, l'unicité pourrait facilement être assurée sans la randomisation supplémentaire (bien qu'il faille faire attention à ne pas lire d'informations confidentielles de cette manière). Si l'application ne peut pas garantir l'unicité, il est recommandé d'utiliser le id_len maximum et de remplir les octets inutilisés avec des données aléatoires pour éviter les collisions.

SSL_has_matching_session_id() ne consulte que le cache de sessions interne, pas externe. Comme l'ID de session est généré avant le handshake, il n'est pas immédiatement ajouté au cache. Si un autre thread utilise le même cache de sessions interne, une condition de concurrence peut survenir dans un autre thread générant le même ID de session. Des collisions peuvent également survenir lors de l'utilisation d'un cache externe, car le cache externe n'est pas vérifié avec SSL_has_matching_session_id() et la même condition de concurrence s'applique.

La fonction doit retourner 0 si elle ne peut pas générer d'ID de session pour une raison quelconque et 1 en cas de succès.

VALEUR DE RETOUR

SSL_CTX_set_generate_session_id() et SSL_set_generate_session_id() retournent 1 en cas de succès et 0 en cas d'échec.

SSL_has_matching_session_id() retourne 1 s'il y a déjà une session avec le même ID dans le cache, ou 0 sinon.

EXEMPLES

La fonction de rappel ci-dessous génère un ID de session avec l'ID donné par le serveur, et remplit le reste avec des octets pseudo-aléatoires:

const char session_id_prefix = "www-18";
#define MAX_SESSION_ID_ATTEMPTS 10
static int generate_session_id(SSL *ssl, unsigned char *id,
                               unsigned int *id_len)
{
    unsigned int count = 0;
    do {
        RAND_pseudo_bytes(id, *id_len);
        /*
         * Préfixer l'ID de session avec le préfixe requis. NB : Si notre
         * préfixe est trop long, le tronquer - mais il y aura de pires effets
         * de toute façon, par exemple le serveur ne pourrait créer qu'une seule
         * ID de session (c'est-à-dire le préfixe !) donc toutes les futures négociations
         * de session échoueront en raison de conflits.
         */
        memcpy(id, session_id_prefix, strlen(session_id_prefix) < *id_len ?
                                      strlen(session_id_prefix) : *id_len);
    } while (SSL_has_matching_session_id(ssl, id, *id_len)
              && ++count < MAX_SESSION_ID_ATTEMPTS);
    if (count >= MAX_SESSION_ID_ATTEMPTS)
        return 0;
    return 1;
}
