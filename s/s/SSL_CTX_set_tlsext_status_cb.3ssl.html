DESCRIPTION

Une application cliente peut demander à un serveur de renvoyer des réponses de statut OCSP (également appelées OCSP stapling). Pour ce faire, le client doit appeler la fonction SSL_CTX_set_tlsext_status_type() avant de créer tout objet SSL. Alternativement, une application peut appeler la fonction SSL_set_tlsext_status_type() sur un objet SSL avant d'initier l'échange de poignée de main. Actuellement, le seul type pris en charge est TLSEXT_STATUSTYPE_ocsp. Cette valeur doit être transmise par l'argument type. Appeler SSL_CTX_get_tlsext_status_type() renverra le type TLSEXT_STATUSTYPE_ocsp précédemment défini via SSL_CTX_set_tlsext_status_type() ou -1 s'il n'est pas défini.

Pour les versions de TLS antérieures à 1.3, une seule réponse de statut OCSP est envoyée par le serveur. TLS 1.3 spécifie que le serveur peut envoyer des réponses de statut OCSP pour l'ensemble complet de certificats (OCSP multi-stapling).

Le client doit également fournir une fonction de rappel pour décider quoi faire des réponses OCSP renvoyées en appelant SSL_CTX_set_tlsext_status_cb(). La fonction de rappel doit déterminer si les réponses OCSP renvoyées sont acceptables ou non. La fonction sera passée comme argument la valeur précédemment définie via un appel à SSL_CTX_set_tlsext_status_arg(). Il convient de noter que la fonction ne sera pas appelée dans le cas d'une poignée de main où la session est réutilisée (car aucun certificat n'a été échangé). La fonction précédemment définie via SSL_CTX_set_tlsext_status_cb() peut être récupérée en appelant SSL_CTX_get_tlsext_status_cb(), et l'argument via SSL_CTX_get_tlsext_status_arg().

Du côté client, SSL_get_tlsext_status_type() peut être utilisé pour déterminer si le client a précédemment appelé SSL_set_tlsext_status_type(). Il renverra TLSEXT_STATUSTYPE_ocsp s'il l'a fait ou -1 sinon. Du côté serveur, SSL_get_tlsext_status_type() peut être utilisé pour déterminer si le client a demandé l'OCSP stapling. Si le client l'a demandé, cette fonction renverra TLSEXT_STATUSTYPE_ocsp ou -1 sinon.

Une réponse renvoyée uniquement par le serveur (TLS < 1.3) peut être obtenue en appelant SSL_get_tlsext_status_ocsp_resp(). La valeur *resp est mise à jour pour pointer vers les données de la réponse OCSP et la valeur renvoyée sera la longueur de ces données. Souvent, une fonction de rappel obtiendra un objet OCSP_RESPONSE de ces données en appelant la fonction d2i_OCSP_RESPONSE(). Si le serveur n'a fourni aucune donnée de réponse, *resp sera NULL et la valeur renvoyée par SSL_get_tlsext_status_ocsp_resp() sera -1.

Une application serveur doit également appeler la fonction SSL_CTX_set_tlsext_status_cb() si elle souhaite pouvoir fournir aux clients une réponse OCSP (unique) pour le certificat du serveur. Souvent, la fonction de rappel du serveur obtiendra le certificat qui sera envoyé au client en appelant SSL_get_certificate() ; elle récupérera la réponse OCSP associée à envoyer ; puis elle définira les données de réponse en appelant SSL_set_tlsext_status_ocsp_resp(). Un pointeur vers les données de réponse doit être fourni dans l'argument resp, et la longueur de ces données dans l'argument len.

Dans le cas de multi-stapling, les réponses à renvoyer par le serveur peuvent être obtenues en appelant SSL_get0_tlsext_status_ocsp_resp_ex(). La valeur *resp est mise à jour pour pointer vers la pile de réponses OCSP et la valeur renvoyée sera le nombre de réponses dans la pile. Les réponses OCSP dans la pile doivent être dans le même ordre que les certificats de la chaîne. S'il n'y a pas de réponse OCSP disponible pour un certificat de la chaîne, un élément NULL dans la pile le représentera. Souvent, une fonction de rappel obtiendra un objet OCSP_RESPONSE de la pile en appelant sk_OCSP_RESPONSE_pop. Si le serveur n'a fourni aucune donnée de réponse, *resp sera NULL et la valeur renvoyée par SSL_get0_tlsext_status_ocsp_resp_ex() sera -1.

Une application serveur doit également appeler la fonction SSL_CTX_set_tlsext_status_cb() si elle souhaite pouvoir fournir aux clients des réponses de statut de certificat OCSP, où TLS 1.3 permet le multi-stapling, c'est-à-dire, fournir des réponses pour tous les certificats de la chaîne du certificat du serveur (à l'exception du certificat de la CA racine). Les certificats qui sont envoyés au client et pour lesquels les réponses OCSP doivent être obtenues peuvent être obtenus en appelant SSL_get_certificate() et SSL_get0_chain_certs(). Les réponses OCSP sont définies en appelant SSL_set0_tlsext_status_ocsp_resp_ex(). Une pile de réponses OCSP doit être fournie dans l'argument resp. Les réponses OCSP dans la pile doivent être dans le même ordre que les certificats de la chaîne. S'il n'y a pas de réponse OCSP disponible pour un certificat de la chaîne, un élément NULL dans la pile le représentera.

VALEURS DE RETOUR

La fonction de rappel, lorsqu'elle est utilisée du côté client, doit renvoyer une valeur négative en cas d'erreur ; 0 si la réponse n'est pas acceptable (auquel cas la poignée de main échouera) ou une valeur positive si elle est acceptable.

La fonction de rappel, lorsqu'elle est utilisée du côté serveur, doit renvoyer soit SSL_TLSEXT_ERR_OK (signifiant que la réponse OCSP qui a été définie doit être renvoyée), SSL_TLSEXT_ERR_NOACK (signifiant qu'aucune réponse OCSP ne devrait être renvoyée) ou SSL_TLSEXT_ERR_ALERT_FATAL (signifiant qu'une erreur grave s'est produite).

SSL_CTX_set_tlsext_status_cb(), SSL_CTX_set_tlsext_status_arg(), SSL_CTX_set_tlsext_status_type(), SSL_set_tlsext_status_type(), SSL_set_tlsext_status_ocsp_resp() renvoient 0 en cas d'erreur ou 1 en cas de succès. SSL_set0_tlsext_status_ocsp_resp_ex() renvoie toujours 1.

SSL_CTX_get_tlsext_status_type() renvoie la valeur précédemment définie via SSL_CTX_set_tlsext_status_type(), ou -1 si elle n'est pas définie.

SSL_get_tlsext_status_ocsp_resp() renvoie la longueur des données de la réponse OCSP ou -1 s'il n'y a pas de réponse OCSP.

SSL_get0_tlsext_status_ocsp_resp_ex() renvoie le nombre de réponses dans la pile ou -1 s'il n'y a pas de réponse OCSP.

SSL_get_tlsext_status_type() renvoie TLSEXT_STATUSTYPE_ocsp du côté client si SSL_set_tlsext_status_type() a été appelé précédemment, ou du côté serveur si le client a demandé l'OCSP stapling. Sinon, il renvoie -1.

HISTORIQUE

Les fonctions SSL_get_tlsext_status_type(), SSL_CTX_get_tlsext_status_type() et SSL_CTX_set_tlsext_status_type() ont été ajoutées dans OpenSSL 1.1.0.

Les macros SSL_get0_tlsext_status_ocsp_resp_ex() et SSL_set0_tlsext_status_ocsp_resp_ex() ont été ajoutées dans OpenSSL 3.6.
