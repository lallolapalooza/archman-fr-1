SSL_set_async_callback(3ssl)

Paquet: openssl

Licences: Apache-2.0

SSL_SET_ASYNC_CALLBACK(3ssl) OpenSSL SSL_SET_ASYNC_CALLBACK(3ssl)

NOM

SSL_CTX_set_async_callback, SSL_CTX_set_async_callback_arg, SSL_set_async_callback, SSL_set_async_callback_arg, SSL_get_async_status, SSL_async_callback_fn - gérer les opérations asynchrones

SYNTAXE

#include <openssl/ssl.h>
typedef int (*SSL_async_callback_fn)(SSL *s, void *arg);
int SSL_CTX_set_async_callback(SSL_CTX *ctx, SSL_async_callback_fn callback);
int SSL_CTX_set_async_callback_arg(SSL_CTX *ctx, void *arg);
int SSL_set_async_callback(SSL *s, SSL_async_callback_fn callback);
int SSL_set_async_callback_arg(SSL *s, void *arg);
int SSL_get_async_status(SSL *s, int *status);

DESCRIPTION

SSL_CTX_set_async_callback() définit une fonction de rappel asynchrone. Tous les objets SSL générés à partir de ce SSL_CTX auront ce rappel. Si un moteur prend en charge le mécanisme de rappel, il sera automatiquement appelé si SSL_MODE_ASYNC a été défini et qu'un moteur capable d'asynchronisme termine une opération cryptographique pour notifier l'application de reprendre le flux de travail interrompu.

SSL_CTX_set_async_callback_arg() définit l'argument de rappel.

SSL_set_async_callback() permet à une application de définir un rappel dans un objet SSL asynchrone, de sorte que lorsqu'un moteur termine une opération cryptographique, le rappel sera appelé pour notifier l'application de reprendre le flux de travail interrompu.

SSL_set_async_callback_arg() définit un argument pour l'objet SSL lorsque le rappel ci-dessus est appelé.

SSL_get_async_status() renvoie l'état du moteur. Cette fonction facilite la communication du moteur à l'application. Pendant une session SSL, les opérations cryptographiques sont soumises à un moteur. L'état du moteur est très utile pour qu'une application sache si l'opération a été correctement soumise. Si le moteur ne prend pas en charge cette méthode de rappel supplémentaire, ASYNC_STATUS_UNSUPPORTED sera renvoyé. Voir ASYNC_WAIT_CTX_set_status() pour une description de toutes les valeurs d'état.

Un exemple des fonctions ci-dessus serait le suivant :

1.
L'application définit le rappel asynchrone et les données de rappel sur une connexion SSL en appelant SSL_set_async_callback().
2.
L'application définit SSL_MODE_ASYNC et effectue un appel SSL asynchrone
3.
OpenSSL soumet la requête asynchrone au moteur. Si une nouvelle tentative se produit à ce stade, l'état dans ASYNC_WAIT_CTX sera défini et la fonction de rappel asynchrone sera appelée (retour à l'étape 7).
4.
Le moteur OpenSSL interrompt le travail en cours et renvoie, de sorte que l'application puisse continuer à traiter d'autres connexions.
5.
À un moment donné dans le futur (probablement via un mécanisme de sondage ou via une interruption), le moteur sera informé que la requête asynchrone a fini d'être traitée.
6.
Le moteur appellera le rappel de l'application en passant les données de rappel comme paramètre.
7.
La fonction de rappel devrait alors s'exécuter. Remarque : il est requis que la fonction de rappel soit petite et ne bloque pas, car elle sera exécutée dans le contexte d'un mécanisme de sondage ou d'une interruption.
8.
Il incombe à l'application, via la fonction de rappel, de planifier le rappel de la fonction asynchrone OpenSSL et de continuer le traitement.
9.
La fonction de rappel a la possibilité de vérifier l'état renvoyé via SSL_get_async_status() pour déterminer si une nouvelle tentative s'est produite au lieu que la requête soit soumise, permettant un traitement différent si nécessaire.

VALEURS DE RETOUR

SSL_CTX_set_async_callback(), SSL_set_async_callback(), SSL_CTX_set_async_callback_arg(), SSL_CTX_set_async_callback_arg() et SSL_get_async_status() renvoient 1 en cas de succès ou 0 en cas d'erreur.

VOIR AUSSI

ssl(7)

HISTORIQUE

SSL_CTX_set_async_callback(), SSL_CTX_set_async_callback_arg(), SSL_set_async_callback(), SSL_set_async_callback_arg() et SSL_get_async_status() ont été ajoutés pour la première fois à OpenSSL 3.0.
