Net::DBus::Reactor(3) Documentation Perl fournie par l'utilisateur Net::DBus::Reactor(3)

NOM

Net::DBus::Reactor - boucle d'événements de l'application

SYNOPIS

Créer et exécuter une boucle d'événements :

use Net::DBus::Reactor;
my $reactor = Net::DBus::Reactor->main();
$reactor->run();

Gérer des gestionnaires de fichiers

$reactor->add_read($fd,
                   Net::DBus::Callback->new(method => sub {
                      my $fd = shift;
                      ...lire des données...
                   }, args => [$fd]));
$reactor->add_write($fd,
                    Net::DBus::Callback->new(method => sub {
                       my $fd = shift;
                       ...écrire des données...
                    }, args => [$fd]));

Activer (dés)temporairement un gestionnaire

# Désactiver
$reactor->toggle_read($fd, 0);
# Activer
$reactor->toggle_read($fd, 1);

Supprimer définitivement un gestionnaire

$reactor->remove_read($fd);

Gérer un délai d'attente régulier toutes les 100 millisecondes

my $timer = $reactor->add_timeout(100,
                                  Net::DBus::Callback->new(
           method => sub {
              ...traiter l'alarme...
           }));

Activer (dés)temporairement un minuteur

# Désactiver
$reactor->toggle_timeout($timer, 0);
# Activer
$reactor->toggle_timeout($timer, 1);

Supprimer définitivement un minuteur

$reactor->remove_timeout($timer);

Ajouter un hook post-dispatch

my $hook = $reactor->add_hook(Net::DBus::Callback->new(
      method => sub {
         ... faire un travail...
      }));

Supprimer un hook

$reactor->remove_hook($hook);

DESCRIPTION

Cette classe fournit une boucle d'événements à usage général pour multiplexer les événements d'E/S et les délais d'attente dans un seul processus. L'implémentation sous-jacente est réalisée à l'aide de l'appel système select. Les descripteurs de fichiers peuvent être enregistrés pour une surveillance des événements de lecture, d'écriture et d'exception (données hors bande). Les minuteurs peuvent être enregistrés pour expirer avec une fréquence périodique. Ceux-ci sont implémentés à l'aide du paramètre timeout de l'appel système select. Comme ce paramètre ne représente qu'une limite supérieure au temps pendant lequel l'appel système select est autorisé à dormir, la période réelle des minuteurs peut varier. En cas de charge normale, cette variance est généralement de 10 millisecondes. Enfin, des hooks peuvent être enregistrés, qui seront appelés à chaque itération de la boucle d'événements (c'est-à-dire après le traitement des événements de fichier, ou des délais d'attente indiqués par le retour de l'appel système select).

MÉTHODES

my $reactor = Net::DBus::Reactor->new();
Crée une nouvelle boucle d'événements prête à surveiller les descripteurs de fichiers, ou à générer des délais d'attente. Sauf circonstances très inhabituelles (dont je ne peux pas penser d'exemples), il n'est pas nécessaire ou souhaitable de créer explicitement de nouvelles instances de réacteur. Appelez plutôt la méthode main pour obtenir une référence à l'instance singleton.
$reactor = Net::DBus::Reactor->main;
Retourne une référence à l'instance singleton du réacteur. C'est la manière recommandée d'obtenir un réacteur, car elle évite aux modules de devoir transmettre des références à leurs réacteurs créés en privé.
$reactor->manage($connection);
$reactor->manage($server);
Enregistre un objet "Net::DBus::Binding::Connection" ou "Net::DBus::Binding::Server" pour être géré par la boucle d'événements. Cela implique essentiellement de relier les callbacks de surveillance et de délai d'attente à la boucle d'événements. Pour les connexions, il enregistrera également un hook pour appeler périodiquement la méthode "dispatch".
$reactor->run();
Démarre la boucle d'événements qui surveille tous les descripteurs de fichiers et délais d'attente enregistrés. Au moins un descripteur de fichier ou un minuteur doit avoir été enregistré avant d'exécuter le réacteur, sinon il se terminera immédiatement. Le réacteur s'exécutera jusqu'à ce que tous les descripteurs de fichiers ou délais d'attente enregistrés aient été supprimés ou désactivés. Le réacteur peut être arrêté explicitement en appelant la méthode "shutdown".
$reactor->shutdown();
Arrête explicitement le réacteur après le traitement des événements en attente.
$reactor->step();
Effectue une itération de la boucle d'événements, en se mettant en sommeil jusqu'à ce qu'un événement se produise sur un descripteur de fichier enregistré, ou qu'un délai d'attente se produise. Cette méthode n'est généralement pas nécessaire dans l'utilisation quotidienne.
$reactor->add_read($fd, $callback[, $status]);
Enregistre un descripteur de fichier pour la surveillance des événements de lecture. Le paramètre $callback spécifie soit une référence de code vers une sous-routine, soit une instance de l'objet "Net::DBus::Callback" à appeler chaque fois qu'un événement se produit. Le paramètre facultatif $status est une valeur booléenne pour spécifier si la surveillance est initialement activée.
$reactor->add_write($fd, $callback[, $status]);
Enregistre un descripteur de fichier pour la surveillance des événements d'écriture. Le paramètre $callback spécifie soit une référence de code vers une sous-routine, soit une instance de l'objet "Net::DBus::Callback" à appeler chaque fois qu'un événement se produit. Le paramètre facultatif $status est une valeur booléenne pour spécifier si la surveillance est initialement activée.
$reactor->add_exception($fd, $callback[, $status]);
Enregistre un descripteur de fichier pour la surveillance des événements d'exception. Le paramètre $callback spécifie soit une référence de code vers une sous-routine, soit une instance de l'objet "Net::DBus::Callback" à appeler chaque fois qu'un événement se produit. Le paramètre facultatif $status est une valeur booléenne pour spécifier si la surveillance est initialement activée.
my $id = $reactor->add_timeout($interval, $callback, $status);
Enregistre un nouveau délai d'attente pour expirer toutes les $interval millisecondes. Le paramètre $callback spécifie soit une référence de code vers une sous-routine, soit une instance de l'objet "Net::DBus::Callback" à appeler chaque fois que le délai d'attente expire. Le paramètre facultatif $status est une valeur booléenne pour spécifier si le délai d'attente est initialement activé. Le paramètre de retour est un identifiant unique qui peut être utilisé pour supprimer ou désactiver ultérieurement le délai d'attente.
$reactor->remove_timeout($id);
Supprime un délai d'attente précédemment enregistré spécifié par le paramètre $id.
$reactor->toggle_timeout($id, $status[, $interval]);
Met à jour l'état d'un délai d'attente précédemment enregistré spécifié par le paramètre $id. Le paramètre $status spécifie si le délai d'attente doit être activé ou désactivé, tandis que le paramètre facultatif $interval peut être utilisé pour modifier la période du délai d'attente.
my $id = $reactor->add_hook($callback[, $status]);
Enregistre un nouveau hook à déclencher à chaque itération de la boucle d'événements. Le paramètre $callback spécifie soit une référence de code vers une sous-routine, soit une instance de la classe "Net::DBus::Callback" à appeler. Le paramètre $status détermine si le hook est initialement activé ou désactivé. Le paramètre de retour est un ID unique qui doit être utilisé pour supprimer ou désactiver ultérieurement le hook.
$reactor->remove_hook($id)
Supprime le hook précédemment enregistré identifié par $id.
$reactor->toggle_hook($id, $status)
Met à jour l'état du hook précédemment enregistré identifié par $id. Le paramètre $status détermine si le hook doit être activé ou désactivé.
$reactor->remove_read($fd);
$reactor->remove_write($fd);
$reactor->remove_exception($fd);
Supprime une surveillance du descripteur de fichier $fd.
$reactor->toggle_read($fd, $status);
$reactor->toggle_write($fd, $status);
$reactor->toggle_exception($fd, $status);
Met à jour l'état d'une surveillance du descripteur de fichier $fd. Le paramètre $status spécifie si la surveillance doit être activée ou désactivée.

VOIR AUSSI
