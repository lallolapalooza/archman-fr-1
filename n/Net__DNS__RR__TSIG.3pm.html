NOM

Net::DNS::RR::TSIG - enregistrement de ressource TSIG DNS

SYNOPSIS

use Net::DNS;
$tsig = Net::DNS::RR::TSIG->create( $keyfile );
$tsig = Net::DNS::RR::TSIG->create(
                        $keyfile,
                        fudge => 300
                        );

DESCRIPTION

Classe pour les enregistrements de ressource TSIG (Transaction Signature) DNS.

MÉTHODES

Les méthodes disponibles sont celles héritées de la classe de base, augmentées par les méthodes spécifiques au type définies dans ce paquet.

L'utilisation de fonctionnalités non documentées du paquet ou l'accès direct aux structures de données internes est déconseillée et pourrait entraîner l'arrêt du programme ou d'autres comportements imprévisibles.

algorithm

$algorithm = $rr->algorithm;
$rr->algorithm( $algorithm );

Un nom de domaine qui spécifie le nom de l'algorithme.

key

$rr->key( $key );

Représentation Base64 du matériel clé.

keybin

$rr->keybin( $keybin );

Représentation binaire du matériel clé.

time_signed

$time_signed = $rr->time_signed;
$rr->time_signed( $time_signed );

Temps de signature comme nombre de secondes depuis le 1er janvier 1970 00:00:00 UTC. Le temps de signature par défaut est l'heure actuelle.

fudge

$fudge = $rr->fudge;
$rr->fudge( $fudge );

"fudge" représente l'erreur autorisée dans le temps de signature. Le fudge par défaut est de 300 secondes.

mac

$rr->mac( $mac );

Code d'authentification de message (MAC). Le programmeur doit appeler la méthode d'objet data() de Net::DNS::Packet avant que cela ne renvoie quoi que ce soit de significatif.

macbin

$macbin = $rr->macbin;
$rr->macbin( $macbin );

Code d'authentification de message (MAC) binaire.

prior_mac

$prior_mac = $rr->prior_mac;
$rr->prior_mac( $prior_mac );

Code d'authentification de message (MAC) précédent.

prior_macbin

$prior_macbin = $rr->prior_macbin;
$rr->prior_macbin( $prior_macbin );

Code d'authentification de message (MAC) précédent binaire.

request_mac

$request_mac = $rr->request_mac;
$rr->request_mac( $request_mac );

Code d'authentification de message (MAC) de requête.

request_macbin

$request_macbin = $rr->request_macbin;
$rr->request_macbin( $request_macbin );

Code d'authentification de message (MAC) de requête binaire.

original_id

$original_id = $rr->original_id;
$rr->original_id( $original_id );

L'identifiant du message de l'en-tête du paquet d'origine.

error

vrfyerrstr

$rcode = $tsig->error;

Renvoie le RCODE couvrant le traitement TSIG. Les valeurs courantes sont NOERROR, BADSIG, BADKEY et BADTIME. Voir RFC8945 pour les détails.

other

$other = $tsig->other;

Ce champ doit être vide sauf si l'erreur est BADTIME, auquel cas il contiendra l'heure du serveur sous forme de secondes depuis le 1er janvier 1970 00:00:00 UTC.

sig_function

sub signing_function {
        my ( $keybin, $data ) = @_;
        my $hmac = Digest::HMAC->new( $keybin, 'Digest::MD5' );
        hmac->add( $data );
        return $hmac->digest;
}
$tsig->sig_function( \&signing_function );

Ceci définit la fonction de signature à utiliser pour cet enregistrement TSIG. La fonction de signature par défaut est HMAC-MD5.

sig_data

$sigdata = $tsig->sig_data($packet);

Renvoie le paquet empaqueté selon RFC8945 dans un format à signer. Ceci n'est nécessaire que si vous souhaitez fournir une fonction de signature externe, comme c'est le cas pour TSIG-GSS.

create

$tsig = Net::DNS::RR::TSIG->create( $keyfile );
$tsig = Net::DNS::RR::TSIG->create(
                        $keyfile,
                        fudge => 300
                        );

Renvoie un RR TSIG construit en utilisant les paramètres du fichier clé spécifié, qui est supposé avoir été généré par tsig-keygen.

verify

$verify = $tsig->verify( $data );
$verify = $tsig->verify( $packet );
$verify = $tsig->verify( $reply,  $query );
$verify = $tsig->verify( $packet, $prior );

La méthode booléenne verify renverra vrai si le hachage sur les données du paquet est conforme aux données du TSIG lui-même.

Clés TSIG

Le mécanisme d'authentification TSIG utilise une clé secrète partagée pour établir une relation de confiance entre deux entités.

Il convient de noter qu'il est possible que plus d'une clé soit utilisée simultanément entre une telle paire d'entités.

Les clés TSIG sont générées en utilisant l'utilitaire tsig-keygen distribué avec ISC BIND :

tsig-keygen -a HMAC-SHA256 host1-host2.example.

D'autres algorithmes peuvent être substitués à HMAC-SHA256 dans l'exemple ci-dessus.

Ces clés doivent être protégées de manière similaire aux clés privées, afin qu'une tierce partie ne puisse se faire passer pour l'une des parties prévues en falsifiant le code d'authentification du message (MAC).

Configuration du serveur de noms BIND

La clé générée doit être ajoutée à la configuration /etc/named.conf ou à un fichier séparé introduit par la directive $INCLUDE :

key "host1-host2.example. {
        algorithm hmac-sha256;
        secret "Secret+known+only+by+participating+entities=";
};

BOGUES

Une représentation sur 32 bits du temps est utilisée, contrairement à la RFC8945 qui exige 48 bits. Cette décision de conception devra être revue avant que le code ne cesse de fonctionner le 7 février 2106.
