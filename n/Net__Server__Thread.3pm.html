NOM

Net::Server::Thread - Personnalité de Net::Server

SYNTAXE

use base qw(Net::Server::Thread);
sub process_request {
    #...code...
}
__PACKAGE__->run();

DESCRIPTION

Veuillez d'abord lire le pod de Net::Server. Ce module est une personnalité, une extension, ou une sous-classe du module Net::Server.

Cette personnalité se lie à un ou plusieurs ports, puis attend une connexion client. Lorsqu'une connexion est reçue, le serveur lance un nouveau thread. Le thread gère la requête puis se ferme.

Étant donné que cette variante de Net::Server lance et détruit un thread pour chaque requête, elle ne devrait vraiment être utilisée que lorsque le traitement de chaque requête peut être long ou complexe. Si des requêtes courtes et légères sont utilisées, Perl peut ne pas restituer volontairement la mémoire utilisée. Ceci dépend fortement du système.

ARGUMENTS

check_for_dead
Nombre de secondes à attendre avant de rechercher les processus morts. Ceci n'a lieu que si le nombre maximum de processus enfants (max_servers) a été atteint. La valeur par défaut est 60 secondes.
max_servers
Le nombre maximum d'enfants à créer. Le serveur n'acceptera pas de connexions tant qu'il n'y aura pas d'enfants libres. La valeur par défaut est de 256 enfants.

FICHIER DE CONFIGURATION

Voir Net::Server.

FLUX DE TRAITEMENT

Le flux de traitement suit Net::Server jusqu'à la phase post_accept. À ce stade, un enfant est créé. Le parent est immédiatement capable d'attendre une autre requête. L'enfant gère la requête puis se termine.

HOOKS

Le serveur Fork a les hooks suivants en plus des hooks fournis par la classe de base Net::Server. Voir Net::Server

"$self->pre_accept_hook()"
Ce hook se produit juste avant l'appel de accept.
"$self->pre_thread_hook()"
Ce hook se produit juste après accept mais avant le fork.
"$self->post_accept_hook()"
Ce hook se produit dans l'enfant après accept et fork.
