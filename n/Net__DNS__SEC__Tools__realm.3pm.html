NOM

Net::DNS::SEC::Tools::realm - Manipuler un fichier de domaine DNSSEC-Tools.

SYNOPSIS

use Net::DNS::SEC::Tools::realm;
realm_lock();
realm_read("localhost.realm");
@rlmnames = realm_names();
$flag = realm_exists("example");
$rrec = realm_fullrec("example");
%rrhash = %$rrec;
$zname = $rrhash{"maxttl"};
$val = realm_recval("example","state");
realm_add("realm","example",\%realmfields);
realm_del("example");
realm_rename("example","test-realm");
realm_setval("example","rollrec","example.rrf");
realm_delfield("example","user");
@realmfields = realm_fields();
$count = realmrec_merge("primary.realm", "new0.realm", "new1.realm");
@retvals = realmrec_split("new-realm.rrf", @list_of_realms);
$default_file = realm_default();
realm_write();
realm_close();
realm_discard();
realm_unlock();

DESCRIPTION

Le module Net::DNS::SEC::Tools::realm manipule le contenu d'un fichier realm de DNSSEC-Tools. Les fichiers realm décrivent l'état d'un environnement de rollover DNSSEC, tel que géré par les programmes DNSSEC-Tools. Des interfaces de module existent pour consulter les enregistrements realm, créer de nouveaux enregistrements et modifier les enregistrements existants.

Un fichier realm est organisé en ensembles d'enregistrements realm. Les realm décrivent l'état d'un environnement de rollover. Un realm se compose d'un ensemble d'entrées de type clé/valeur. L'exemple suivant est un realm :

realm "production"
        state           "active"
        realmdir        "/usr/etc/dnssec-tools/realms/production"
        configdir       "/usr/etc/dnssec-tools/configs/production"
        rollrec         "production.rollrec"
        administrator   "sysfolks@example.com"
        display         "1"
        args            "-loglevel phase -logfile log.prod -display"
        user            "prodmgr"

La première étape pour utiliser ce module doit être la lecture du fichier realm. L'interface realm_read() lit le fichier et le parse dans un format interne. Les enregistrements du fichier sont copiés dans une table de hachage (pour une référence facile par les routines realm.pm) et dans un tableau (pour préserver le formatage et les commentaires.)

Après la lecture du fichier, le contenu est référencé en utilisant realm_fullrec() et realm_recval(). Les interfaces realm_add() et realm_setval() sont utilisées pour modifier le contenu d'un enregistrement realm.

Si le fichier realm a été modifié, il doit être explicitement écrit ou les changements ne seront pas sauvegardés. realm_write() sauvegarde le nouveau contenu sur disque. realm_close() sauvegarde le fichier et ferme le descripteur de fichier Perl du fichier realm. Si un fichier realm ne doit plus être ouvert, mais que le contenu ne doit pas être sauvegardé, realm_discard() se débarrasse des données, ferme le descripteur de fichier **sans** sauvegarder les données modifiées.

Lors de la lecture d'un fichier realm, les lignes vides consécutives sont réduites à une seule ligne vide. Au fur et à mesure que les entrées realm sont ajoutées et supprimées, que les fichiers sont fusionnés et que les fichiers sont divisés, il est possible que des blocs de lignes vides consécutives s'agrandissent. Ceci empêchera ces blocs de devenir excessivement grands.

VERROUILLAGE DE DOMAINE

Ce module inclut des interfaces pour synchroniser l'accès aux fichiers realm. Cette synchronisation est très simple et repose sur le verrouillage et le déverrouillage d'un seul fichier de verrouillage pour tous les fichiers realm.

Le verrouillage de realm n'est pas requis avant d'utiliser ce module, mais il est recommandé. L'utilisation attendue de ces installations est la suivante :

realm_lock() || die "impossible de verrouiller le fichier realm\n";
realm_read();
... effectuer d'autres opérations sur le realm ...
realm_close();
realm_unlock();

La synchronisation est effectuée de cette manière en raison de la façon dont les fonctionnalités du module sont implémentées, ainsi que pour offrir de la flexibilité aux utilisateurs du module. Elle offre également une démarcation claire dans le code des appelants quant à l'endroit et au moment où le verrouillage du realm est effectué.

Cette méthode de synchronisation présente l'inconvénient d'avoir un seul fichier de verrouillage comme goulot d'étranglement pour tout accès aux fichiers realm. Cependant, elle réduit la complexité des interfaces de verrouillage et limite le nombre potentiel de fichiers de verrouillage requis.

L'utilisation d'un seul fichier de synchronisation peut ne pas être pratique dans les installations de grande taille. Si tel est le cas, cela sera revu.

INTERFACES DE DOMAINE

Les interfaces du module realm.pm sont présentées ci-dessous.

realm_add(realm_type,realm_name,fields)
Cette routine ajoute un nouveau realm au fichier realm et à la représentation interne du contenu du fichier. Le realm est ajouté à la fois à la table de hachage %realms et au tableau @realmlines. Les entrées ne sont ajoutées que si elles sont définies pour les realms.

realm_type est le type du realm. Il doit être "realm". realm_name est le nom du realm. fields est une référence à une table de hachage qui contient les champs realm nom/valeur. Les clés de la table de hachage sont toujours converties en minuscules, mais les valeurs des entrées sont laissées telles quelles.

Une ligne vide est ajoutée après la dernière ligne du nouveau realm. Le fichier realm n'est pas écrit après realm_add(), bien qu'il soit marqué en interne comme ayant été modifié.

realm_del(realm_name)
Cette routine supprime un realm du fichier realm et de la représentation interne du contenu du fichier. Le realm est supprimé à la fois de la table de hachage %realms et du tableau @realmlines.

Seul le realm lui-même est supprimé du fichier. Tous les commentaires associés et les lignes vides environnantes sont laissés intacts. Le fichier realm n'est pas écrit après realm_del(), bien qu'il soit marqué en interne comme ayant été modifié.

Les valeurs de retour sont :

 0 suppression de realm réussie
-1 nom inconnu
realm_close()
Cette interface sauvegarde la version interne du fichier realm (ouvert avec realm_read()) et ferme le descripteur de fichier.
realm_delfield(realm_name,field)
Supprime le champ donné du realm spécifié. Le fichier n'est **pas** écrit après la mise à jour de la valeur, mais le drapeau interne de modification du fichier est défini. La valeur est sauvegardée à la fois dans %realms et dans @realmlines.

Valeurs de retour :

0 - échec (realm non trouvé ou realm ne contient pas
    le champ)
1 - succès
realm_discard()
Cette routine retire un fichier realm de l'utilisation par un programme. Les données stockées en interne sont supprimées et le descripteur de fichier realm est fermé. Cependant, les données modifiées ne sont pas sauvegardées avant la fermeture du descripteur de fichier. Ainsi, les données modifiées et nouvelles seront perdues.
realm_exists(realm_name)
Cette routine retourne un drapeau booléen indiquant si le realm nommé dans realm_name existe.
realm_fullrec(realm_name)
realm_fullrec() retourne une référence au realm spécifié dans realm_name.
realm_lock()
realm_lock() verrouille le fichier de verrouillage du realm. Un verrou exclusif est demandé, donc l'exécution sera suspendue jusqu'à ce que le verrou

realm_merge(target_realm_file, realm_file1, ... realm_fileN)
Esta interfaz fusiona los archivos de realm especificados. Lee cada archivo y parsea los mismos en un hash de realm y un array de contenidos de archivo. El resultado de la fusión se escribe en el archivo denominado por target_realm_file. Si otro realm está ya abierto, se cierra primero y se guarda antes de abrir el nuevo realm.
Si target_realm_file es un archivo existente de realm, se fusionará su contenido con los otros archivos que se pasan a realm_merge(). Si el archivo no existe, realm_merge() creará el archivo y fusionará los restantes archivos en él.
Una vez exitosa, realm_read() devuelve el número de realms leídos del archivo.
Valores de retorno de error:
-1 no se especificaron archivos de realm para realm_merge() -2 no se pudo crear el archivo de sincronización de realm -3 no se pudo leer el primer archivo de realm -4 se produjo un error al leer los nombres de realm -5 los archivos de realm se duplicaron en la lista de archivos de realm
Se devuelve el éxito o el fracaso.
realm_names()
Esta rutina devuelve una lista de los nombres de realm del archivo.
realm_read(realm_file)
Esta interfaz lee el archivo de realm especificado y lo parsea en un hash de realm y un array de contenidos de archivo. realm_read() debe llamarse antes de cualquier llamada a las otras interfaces de realm.pm. Si otro realm está ya abierto, se cierra primero y se guarda antes de abrir el nuevo realm.
realm_read() intenta abrir el archivo de realm para lectura y escritura. Si esto falla, intenta abrirlo solo para lectura.
realm_read() es una interfaz de frente para realm_readfile(). Establece los datos guardados del módulo antes de leer un nuevo archivo de realm. Estas acciones de mantenimiento no se realizan por realm_readfile().
Una vez exitosa, realm_read() devuelve el número de realms leídos del archivo.
Valores de retorno de error:
-1 el archivo de realm especificado no existe -2 no se pudo abrir el archivo de realm -3 nombres duplicados en el archivo de realm
Se devuelve el éxito o el fracaso.
realm_readfile(realm_file_handle)
Esta interfaz lee el archivo de desencriptado especificado y lo parsea en un hash de realm y un array de contenidos de archivo. El hash de realm y el array de contenidos de archivo no se limpian antes de añadir datos a ellos.
Una vez exitosa, realm_read() devuelve 0.
Valores de retorno de error:
-1 nombres duplicados en el archivo de realm
Se devuelve el éxito o el fracaso.
realm_rectype(realm_name,rectype)
Establece el tipo de registro de realm especificado. El archivo no se escribe después de actualizar el valor, pero se establece el flag interno de modificación. El valor se guarda tanto en %realms como en @realmlines.
realm_name es el nombre del realm que se modificará. rectype es el nuevo tipo de realm, que debe ser "realm".
Valores de retorno:
0 - error (tipo de registro inválido o realm no encontrado) 1 - éxito
Se devuelve el éxito o el fracaso.
realm_recval(realm_name,realm_field)
Esta rutina devuelve el valor de un campo específico en un realm. realm_name es el nombre del realm a consultar. realm_field es el nombre del campo dentro del realm.
Ejemplo: el archivo de realm actual contiene el siguiente realm:
realm       "example"  
    rollrec        "example.rrf"
La llamada:
realm_recval("example", "rollrec")
devolverá el valor "example.rrf".
Se devuelve el éxito o el fracaso.
realm_rename(old_realm_name,new_realm_name)
Esta rutina cambia el nombre del realm especificado por old_realm_name a new_realm_name. El efecto real es cambiar el nombre en la línea de realm para que sea new_realm_name. El nombre se cambia solo en la versión interna del archivo de realm. El archivo no se cambia, pero debe ser guardado llamando a realm_write(), realm_save() o realm_saveas().
old_realm_name debe ser el nombre de un realm existente. Contra todo, new_realm_name no debe ser el nombre de un realm existente.
Valores de retorno:
0 - éxito -1 - old_realm_name es nulo o vacío -2 - new_realm_name es nulo o vacío -3 - old_realm_name no es un realm existente -4 - new_realm_name ya es un realm -5 - error interna que nunca debería ocurrir
Se devuelve el éxito o el fracaso.
realm_setval(realm_name,field,value)
Establece el valor de un par de nombre/field en un realm especificado. El archivo no se escribe después de actualizar el valor, pero se establece el flag interno de modificación. El valor se guarda tanto en %realms como en @realmlines.
realm_name es el nombre del realm que se modificará. Si el realm especificado no existe, se creará como un realm-tipo realm. field es el campo del realm a modificar. value es el nuevo valor del campo.
Se devuelve el éxito o el fracaso.
realm_split(new_realm_file,realm_names)
Mueve un conjunto de entradas de realm del archivo de realm actual a un nuevo archivo. Las entradas de realm movidas se eliminan tanto del archivo de realm actual como de los datos internos del módulo que representan ese archivo.
El parámetro new_realm_file contiene el nombre del nuevo archivo de realm. Si este archivo no existe, se creará. Si existe, las entradas de realm se anexarán a este archivo.
realm_names es una lista de entradas de realm que se moverán del archivo de realm actual al archivo denominado por new_realm_file. Si algunos de los nombres de realm dados son inválidos, los nombres válidos se moverán al nuevo archivo y los nombres inválidos se devolverán en una lista al llamante.
Solo las entradas de realm se moverán al nuevo archivo de realm. Los comentarios asociados se dejarán en el archivo de realm actual.
Una vez exitosa, se devuelve el número de entradas de realm movidas. Los valores de retorno de error se dan abajo.
Valores de retorno de error:
-1 - no hay archivo de realm como destino en new_realm_file -2 - no hay nombres de realm dados en realm_names -3 - ninguno de los nombres de realm dados es un realm existente -4 - no se puede abrir el archivo de realm en new_realm_file -5 - los nombres de realm inválidos fueron especificados en realm_names, seguido por la lista de nombres inválidos.
Se devuelve el éxito o el fracaso.
realm_unlock()
realm_unlock() desbloquea el archivo de sincronización de realm.
realm_write()
Esta interfaz guarda la versión interna del archivo de realm (abierto con realm_read()). No cierra el handle del archivo. Como medida de eficiencia, se verifica primero el flag interno de modificación antes de escribir el archivo. Si el programa no ha modificado el contenido del archivo de realm, no se reescribirá.
realm_write() obtiene un bloque exclusivo del archivo de realm mientras se escribe.
Se devuelve el éxito o el fracaso.

INTERFACES INTERNAS DE REALM

Las interfaces descritas en esta sección están diseñadas para uso interno por el módulo realm.pm. Sin embargo, hay situaciones en las que otras entidades pueden necesitarlas. Úselas con cuidado, ya que su uso incorrecto puede dañar o perder archivos de realm.
realm_init()
Esta rutina inicializa los datos internos de realm. Los cambios pendientes se perderán. Debe leer un nuevo archivo de realm antes de utilizar las interfaces de realm.pm nuevamente.
realm_default()
Esta rutina devuelve el nombre del archivo de realm por defecto.

INTERFACES DE DEBUGGING DE REALM

Las siguientes interfaces muestran información sobre el archivo de realm actualmente analizado. Están diseñadas para uso en depuración y pruebas, pero pueden ser útiles en otros momentos.
realm_dump_hash()
Esta rutina imprime el archivo de realm tal como se almacena internamente en un hash. Los realms se imprimen en orden alfabético, con los campos ordenados alfabéticamente para cada realm. Los nuevos realms y campos de realm se imprimen junto con los realms y campos actuales. Los comentarios del archivo de realm no se incluyen en el hash.
