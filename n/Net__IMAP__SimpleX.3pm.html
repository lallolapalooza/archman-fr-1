Net::IMAP::SimpleX(3) Pages de manuel sur les paquets contribués Perl Net::IMAP::SimpleX(3)

NOM

Net::IMAP::SimpleX - Extensions pour Net::IMAP::Simple

SYNTAXE

use strict;
use warnings;
use Net::IMAP::SimpleX;

Net::IMAP::SimpleX utilise Net::IMAP::Simple comme base, donc la création d'objets est la même que pour l'héritage :

my $imap = Net::IMAP::SimpleX->new('imap.example.com') ||
   die "Impossible de se connecter à IMAP : $Net::IMAP::Simple::errstr\n";
$imap->select("INBOX");

Net::IMAP::SimpleX est un ensemble de méthodes utiles qui ne sont pas simples, nécessitent Parse::RecDescent, ou sont expérimentales.

DESCRIPTION

Ce module ajoute des fonctionnalités utiles, mais pas si simples, par-dessus Net::IMAP::Simple.

MÉTHODES

new
Détails sur l'invocation, lire Net::IMAP::Simple.
body_summary
Les invocations typiques prendraient cette forme générale. 
# obtenir une représentation du corps du message
my $summary = $imap->body_summary($message_number);
# message multipart
if ($summary->has_parts) {
    for my $subpart ($summary->parts) {
        if ($subpart->has_parts) { ... }
        # examiner la partie du message
        my @attr = map { $subpart->$_ } qw/content_type encoding encoded_size/;
        # obtenir la partie du message
        my $subpart_body = $imap->get($message_number, $subpart->part_number);
    }
} else {
    my $body = $summary->body;
    my @attr = map { $body->$_ } qw/content_type encoding encoded_size/;
}

Cette méthode renvoie un objet simple contenant une représentation du corps d'un message. L'objet est construit avec un analyseur Parse::RecDescent à l'aide de la sortie d'une commande IMAP fetch body. L'analyseur utilise la syntaxe formelle définie par RFC3501 http://tools.ietf.org/html/rfc3501#section-9.

my $body = $summary->body;
my @attr = map { $body->$_ } qw/
    content_description
    encoded_size
    charset
    content_type
    part_number
    format
    id
    encoding
/;

Pour les messages multipart, l'objet contient des sous-objets pour chaque partie du message, accessibles via la méthode parts() et inspectés avec la méthode has_parts(). La méthode type décrit le type de multipart (comme mixed ou alternative). La méthode parts renvoie une liste de sous-parties, qui peuvent elles-mêmes avoir des sous-parties, et ainsi de suite.

Un exemple de message multipart, alternative avec un corps texte et une version html du corps ressemblerait à ceci :

if ($summary->has_parts) {
    if ($summary->type eq 'alternative') {
        my ($html) = grep { $_->content_type eq 'text/html' } $summary->parts;
    }
}

Un message multipart vraiment complexe pourrait ressembler à ceci :

if ($summary->has_parts && $summary->type eq 'mixed') {
    for my $part ($summary->parts) {
        if ($part->has_parts && $part->type eq 'mixed') { ... }
        ...
    }
}
fetch
La commande fetch renvoie les parties des messages que les utilisateurs demandent. C'est assez complexe (en suivant RFC3501 à l'aide d'une grammaire/d'un analyseur), mais il existe quelques modèles de base qu'elle suit. 
my $res  =$imap->fetch('30:32' => 'UID BODY.PEEK[HEADER.FIELDS (DATE)] FLAGS')
# $res = {
#   30 => {
#           "BODY[HEADER.FIELDS (DATE)]" => "Date: Sun, 18 Jul 2010 20:54:48 -0400\r\n\r\n",
#           "FLAGS" => ["\\Flagged", "\\Seen"],
#           "UID" => 58890,
#         },
#   31 => {
#           "BODY[HEADER.FIELDS (DATE)]" => "Date: Wed, 21 Jul 2010 09:09:04 -0400\r\n\r\n",
#           "FLAGS" => ["\\Seen"],
#           "UID" => 58891,
#         },
#   32 => {
#           "BODY[HEADER.FIELDS (DATE)]" => "Date: Sat, 24 Jul 2010 05:12:06 -0700\r\n\r\n",
#           "FLAGS" => ["\\Seen"],
#           "UID" => 58892,
#         },
# }

Ce qui est renvoyé comme "parenthèses" sera renvoyé sous forme de tableau (voir "FLAGS") mais presque tout le reste sera renvoyé sous forme de chaînes. Cela inclut les requêtes parenthésées. Par exemple, "BODY.PEAK[HEADER.FIELDS (DATE FROM SUBJECT)]", le résultat sera les lignes d'en-tête RFC822 (comme l'exemple ci-dessus "Date: Sun, ...").

Pour plus d'informations sur les différents types de requêtes, consultez RFC3501. Il y a un nombre surprenant de choses qui peuvent être demandées.

uidfetch
Ceci est presque identique à la méthode fetch() ci-dessus, mais la requête est effectuée sur UID au lieu de séquences. Les clés de $res sont toujours les séquences.

my $res  =$imap->fetch('58890' => 'UID BODY.PEEK[HEADER.FIELDS (DATE)] FLAGS')
# $res = {
#   30 => {
#           "BODY[HEADER.FIELDS (DATE)]" => "Date: Sun, 18 Jul 2010 20:54:48 -0400\r\n\r\n",
#           "FLAGS" => ["\\Flagged", "\\Seen"],
#           "UID" => 58890,
#         },
#   ...

Net::IMAP::SimpleX(3pm)

NAME

Net::IMAP::SimpleX - An IMAP client that is simple, but not too simple

SYNOPSIS

use Net::IMAP::SimpleX;

# Connect to the server
my $imap = Net::IMAP::SimpleX->new(
    Host => 'imap.example.com',
    User => 'username',
    Password => 'password',
    Port => 993,
    UseSSL => 1
);

# List folders
my @folders = $imap->folders;
print "Folders: @folders\n";

# Select a folder
$imap->select('INBOX');

# Get message UIDs
my @uids = $imap->uids;
print "Number of messages: @{[scalar @uids]}\n";

# Fetch messages
my @messages = $imap->fetch(@uids, 'RFC822');
foreach my $message (@messages) {
    print "Subject: ", $message->subject, "\n";
}

# Logout
$imap->logout;

DESCRIPTION

Net::IMAP::SimpleX is a Perl module that provides a simple interface to the IMAP protocol. It is designed to be easy to use for common tasks such as fetching and sending email.

The module supports SSL/TLS connections for secure communication.

METHODS

new(%args)

Creates a new Net::IMAP::SimpleX object and connects to the IMAP server. The following arguments are accepted:

Host
The hostname or IP address of the IMAP server (required).
Port
The port number to connect to (defaults to 143 or 993 if UseSSL is enabled).
User
The username for authentication (required).
Password
The password for authentication (required).
UseSSL
A boolean value indicating whether to use SSL/TLS (defaults to false).
folders()

Returns a list of available mail folders on the server.

select($folder)

Selects the specified mail folder. This must be done before performing operations like fetching messages.

uids()

Returns a list of UIDs (Unique Identifiers) for all messages in the currently selected folder.

fetch($uids, $criteria)

Fetches messages specified by their UIDs. The $criteria argument specifies the message part to fetch (e.g., 'RFC822' for the entire message).

logout()

Logs out from the IMAP server and closes the connection.

EXAMPLE

See the SYNOPSIS section for a basic example.

BUGS

Please report bugs to the author.

SEE ALSO

perl(1), Net::IMAP::Simple
