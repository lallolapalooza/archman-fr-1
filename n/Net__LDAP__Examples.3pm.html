NOM

Net::LDAP::Examples - Exemple LDAP en PERL

DESCRIPTION

Les exemples suivants sont bien sûr du code PERL, conçus pour fonctionner avec les modules Net::LDAP.

L'intention de ce document est de fournir au lecteur un point de départ par copier-coller pour faire fonctionner une application LDAP.

Vous trouverez ci-dessous des extraits de code qui devraient fonctionner tels quels, avec seulement un peu de travail pour corriger les affectations de variables et les spécificités LDAP, par exemple la syntaxe du Distinguished Name, relatives à la propre implémentation de l'utilisateur.

La procédure opérationnelle standard (POS) suivie ici est :

1 Package - use Net::LDAP
2 Initialisation - new
3 Liaison - bind
4 Opération - add modify moddn search
4.1 Traitement - affichage des données d'une recherche
5 Erreur - affichage des informations d'erreur
6 Déconnexion - unbind

Consultez chacune de ces sections pour un extrait de code répondant à vos besoins.

Ce qui n'est pas couvert par ces exemples pour le moment :

méthodes abandon et compare
sous-routines de callback

OPERATION - Générer une RECHERCHE

sub LDAPsearch
{
  my ($ldap,$chaineRecherche,$attributs,$base) = @_;
  # s'il ne passe pas de base... on lui en met une
  if (!$base ) { $base = "o=maSociete, c=monPays"; }
  # s'il ne passe pas un tableau d'attributs...
  # on en prépare un pour lui
  if (!$attributs ) { $attributs = [ 'cn','mail' ]; }
  my $resultat = $ldap->search ( base    => "$base",
                               scope   => "sub",
                               filter  => "$chaineRecherche",
                               attrs   =>  $attributs
                             );

}

my @Attrs = ( );               # demander le retour de tous les attributs disponibles.
                               # à utiliser.
my $resultat = LDAPsearch ( $ldap, "sn=*", \@Attrs );

TRAITEMENT - Affichage des résultats de RECHERCHE

#------------
#
# Accéder aux données comme si elles étaient dans une structure
# c'est-à-dire en utilisant la méthode "as_struct"
#
my $href = $resultat->as_struct;
# obtenir un tableau des noms DN
my @DNs  = keys %$href;        # utiliser les hashes DN
# traiter chaque DN en l'utilisant comme clé
foreach ( @DNs ) {
  print $_, "\n";
  my $valref = $$href{$_};
  # obtenir un tableau des noms d'attributs
  # passés pour ce DN.
  my @Attrs = sort keys %$valref; #utiliser les hashes d'Attributs
  my $nomAttr;
  foreach $nomAttr (@Attrs) {
    # ignorer les données binaires: berk!
    next if ( $nomAttr =~ /;binary$/ );
    # obtenir la valeur de l'attribut (pointeur) en utilisant le
    # nom de l'attribut comme clé de hash
    my $valAttr =  @$valref{$nomAttr};
    print "\t $nomAttr: @$valAttr \n";
  }
  print "#-------------------------------\n";
  # Fin de ce DN
}
#
# fin de la méthode as_struct
#
#--------
#------------
#
# traiter chaque résultat indépendamment
# c'est-à-dire en utilisant la méthode de parcours
#
my @entrees = $resultat->entries;
my $entr;
foreach $entr ( @entrees ) {
  print "DN : ", $entr->dn, "\n";
  my $attr;
  foreach $attr ( sort $entr->attributes ) {
    # ignorer les données binaires que nous ne pouvons pas traiter
    next if ( $attr =~ /;binary$/ );
    print "  $attr : ", $entr->get_value ( $attr ) ,"\n";
  }
  print "#-------------------------------\n";
}
#
# fin de la méthode de parcours
#------------

if ( $resultat->count != 1 ) { exit; }  # Non.. on sort
my $dn = $entrees[0]->dn;         # Oui.. on récupère le DN
#######################################
#
#   MODIFICATION à l'aide d'un HASH
#
my %HashRemplacement = ( motclé => "x", proxy => "x" );
my $resultat = LDAPmodifyUsingHash ( $ldap, $dn, \%HashRemplacement );
sub LDAPmodifyUsingHash
{
  my ($ldap, $dn, $ceQuiDoitChanger ) = @_;
  my $resultat = $ldap->modify ( $dn,
                               replace => { %$ceQuiDoitChanger }
                             );
  return $resultat;
}
#######################################
#
#   MODIFICATION à l'aide d'une LISTE DE TABLEAUX
#
my @ListeTableauRemplacement = [ 'motclé', "xxxxxxxxxx",
                         'proxy' , "yyyyyyyyyy"   ];
my $resultat = LDAPmodifyUsingArrayList ( $ldap, $dn, \@ListeTableauRemplacement );
sub LDAPmodifyUsingArrayList
{
  my ($ldap, $dn, $ceQuiDoitChanger ) = @_;
  my $resultat = $ldap->modify ( $dn,
                               changes => [
                                 replace => @$ceQuiDoitChanger
                               ]
                             );
  return $resultat;
}
#######################################
#
#   MODIFICATION à l'aide d'un TABLEAU
#
my @TableauRemplacement = ( 'motclé', "xxxxxxxxxx" ,
                     'proxy' , "yyyyyyyyyy"   );
my $resultat = LDAPmodifyUsingArray ( $ldap, $dn, \@TableauRemplacement );
sub LDAPmodifyUsingArray
{
  my ($ldap, $dn, $ceQuiDoitChanger ) = @_;
  my $resultat = $ldap->modify ( $dn,
                               changes => [
                                 replace => [ @$ceQuiDoitChanger ]
                               ]
                             );
  return $resultat;
}
#######################################
#
#   MODIFIER un enregistrement existant en utilisant 'Changes'
#    (ou une combinaison de add/delete/replace)
#
my @ceQuiDoitChanger;
my @TableauRemplacement;
my @TableauSuppression;
my @TableauAjout;
push @TableauAjout, 'cn', "moi-même";
push @TableauRemplacement, 'sn', '!@#$%^&*()__+Bonjour Ici';
push @TableauRemplacement, 'cn', "moi-même Moi";
push @TableauSuppression, 'cn', "moi-même";
if ( $#TableauRemplacement > 0 ) {
  push @ceQuiDoitChanger, 'replace';
  push @ceQuiDoitChanger, \@TableauRemplacement;
}
if ( $#TableauSuppression > 0 ) {
  push @ceQuiDoitChanger, 'delete';
  push @ceQuiDoitChanger, \@TableauSuppression;
}
if ( $#TableauAjout > 0 ) {
  push @ceQuiDoitChanger, 'add';
  push @ceQuiDoitChanger, \@TableauAjout;
}
$resultat = LDAPmodify ( $ldap, $dn, \@ceQuiDoitChanger );
sub LDAPmodify
{
  my ($ldap, $dn, $ceQuiDoitChanger) = @_;
  my $resultat = $ldap->modify ( $dn,
                               changes => [
                                 @$ceQuiDoitChanger
                               ]
                             );
  return $resultat;
}

OPERATION - Changer le RDN

my $nouveauRDN = "cn=Joseph User";
my $resultat = LDAPrdnChange ( $ldap, $dn, $nouveauRDN, "archive" );
sub LDAPrdnChange
{
  my ($ldap,$dn,$ceQuiDoitChanger,$action) = @_;
  my $branche;
  #
  # si l'action d'archivage est sélectionnée, déplacer cette
  # entrée vers un autre endroit dans l'annuaire.
  #
  if ( $action =~ /archive/i )  {
    $branche = "ou=nouvelleBranche, o=maSociete, c=monPays";
  }
  #
  # utiliser 'deleteoldrdn' pour éviter d'obtenir
  # des multivalues dans l'attribut de NOMMAGE.
  # dans la plupart des cas, il s'agirait de l'attribut 'CN'
  #
  my $resultat = $ldap->moddn ( $dn,
                              newrdn => $ceQuiDoitChanger,
                              deleteoldrdn => '1',
                              newsuperior => $branche
                            );
  return $resultat;
}

LDAP SCHEMA RETRIEVAL

Le code suivant montre comment récupérer des informations de schéma.

La première procédure consiste à initialiser un nouvel objet LDAP en utilisant les mêmes procédures que celles mentionnées au début du document.

La deuxième procédure consiste à se lier au serveur d'annuaire. Certains serveurs peuvent nécessiter une authentification pour récupérer le schéma du serveur d'annuaire. Cette procédure est mentionnée au début du document.

Après une liaison réussie, vous êtes prêt à récupérer les informations du schéma. Ceci est fait en initialisant un objet de schéma.

$schema = $ldap->schema ( );

Dans ce cas, Net::LDAP tentera de déterminer le DN sous lequel le schéma peut être trouvé. Il recherchera d'abord l'attribut "subschemaSubentry" dans le DSE racine. S'il n'est pas trouvé, "cn=schema" sera supposé.

Alternativement, vous pouvez spécifier le DN où le schéma sera trouvé avec:

$schema = $ldap->schema ( dn => $dn );

Une fois que vous avez un DN à rechercher, Net::LDAP recherchera l'enregistrement de schéma avec:

$mesg = $self->search ( base => $dn, scope => 'base', filter => '(objectClass=subschema)' );

Une fois l'objet de schéma initialisé, des méthodes de schéma sont utilisées pour récupérer les données. Il existe plusieurs façons de procéder. Les informations sur les méthodes de schéma se trouvent dans la documentation de la bibliothèque Net::LDAP::Schema.

Le processus est essentiellement le même pour obtenir les informations d'objectClass. Si schema->all_attributes() est utilisé, il doit être remplacé par schema->all_objectclasses(). À partir de ce moment, le processus est le même pour les deux types de données.
