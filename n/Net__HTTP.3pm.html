NOM

Net::HTTP - Connexion HTTP de bas niveau (client)

VERSION

version 6.24

SYNOPSIS

use Net::HTTP;
my $s = Net::HTTP->new(Host => "www.perl.com") || die $@;
$s->write_request(GET => "/", 'User-Agent' => "Mozilla/5.0");
my($code, $mess, %h) = $s->read_response_headers;
while (1) {
   my $buf;
   my $n = $s->read_entity_body($buf, 1024);
   die "lecture échouée : $!" unless defined $n;
   last unless $n;
   print $buf;
}

DESCRIPTION

La classe "Net::HTTP" est un client HTTP de bas niveau. Une instance de la classe "Net::HTTP" représente une connexion à un serveur HTTP. Le protocole HTTP est décrit dans la RFC 2616. La classe "Net::HTTP" prend en charge "HTTP/1.0" et "HTTP/1.1".

La classe "Net::HTTP" est une sous-classe de l'une des suivantes : "IO::Socket::IP" (IPv6+IPv4), "IO::Socket::INET6" (IPv6+IPv4) ou "IO::Socket::INET" (IPv4 uniquement). Vous pouvez combiner les méthodes décrites ci-dessous avec la lecture et l'écriture directes de la connexion. Ce n'est pas une bonne idée, sauf si vous savez ce que vous faites.

Les méthodes suivantes sont fournies (en plus de celles de "IO::Socket::INET") :

"$s = Net::HTTP->new( %options )"
La méthode constructeur de "Net::HTTP" prend les mêmes options que "IO::Socket::INET" ainsi que celles-ci :
Host:            Valeur initiale de l'attribut "Host"
KeepAlive:       Valeur initiale de l'attribut "KeepAlive"
SendTE:          Valeur initiale de l'attribut "SendTE"
HTTPVersion:     Valeur initiale de l'attribut "HTTPVersion"
PeerHTTPVersion: Valeur initiale de l'attribut "PeerHTTPVersion"
MaxLineLength:   Valeur initiale de l'attribut "MaxLineLength"
MaxHeaderLines:  Valeur initiale de l'attribut "MaxHeaderLines"

L'attribut "Host" est également la valeur par défaut pour "IO::Socket::INET" "PeerAddr". La valeur par défaut de "PeerPort" est 80 si elle n'est pas fournie. Le spécificateur de "PeerPort" peut également être inclus dans "PeerAddr" avec un préfixe « : » et en fermant l'adresse IPv6 entre crochets « [] » si nécessaire :

L'attribut "Listen" fourni par la méthode constructeur de "IO::Socket::INET" n'est pas autorisé.

Si la connexion au serveur HTTP donné échoue, le constructeur renvoie "undef" et $@ contient la raison. Après une connexion réussie, une instance de "Net:HTTP" est renvoyée.

"$s->host"
Obtient/définit la valeur par défaut de l'en-tête "Host" à envoyer. La valeur $host ne doit pas être définie à une chaîne vide (ou "undef") pour HTTP/1.1.
"$s->keep_alive"
Obtient/définit la valeur de *keep-alive*. Si cette valeur est VRAIE, un en-tête est envoyé indiquant que le serveur tentera de maintenir la connexion ouverte afin que plusieurs requêtes puissent être envoyées.

Les en-têtes effectivement définis dépendent de la valeur des attributs "http_version" et "peer_http_version".

"$s->send_te"
Obtient/définit une valeur indiquant si un en-tête "TE" sera envoyé pour indiquer les encodages de transfert que le serveur peut choisir. La liste des encodages annoncés comme acceptés par ce client dépend de la disponibilité des modules suivants : "Compress::Raw::Zlib" pour *deflate*, et "IO::Compress::Gunzip" pour *gzip*.
"$s->http_version"
Obtient/définit le numéro de version du protocole HTTP que ce client doit annoncer. Cette valeur ne peut être définie qu'à « 1.0 » ou « 1.1 ». La valeur par défaut est « 1.1 ».
"$s->peer_http_version"
Obtient/définit le numéro de version du protocole de notre interlocuteur. Cette valeur est initialisée à « 1.0 », mais est mise à jour par un appel à la méthode read_response_headers().
"$s->max_line_length"
Obtient/définit une limite sur la longueur de la ligne de réponse et des lignes d'en-tête de réponse. La valeur par défaut est 8192. Une valeur de 0 signifie qu'il n'y a pas de limite.
"$s->max_header_length"
Obtient/définit une limite sur le nombre de lignes d'en-tête qu'une réponse peut avoir. La valeur par défaut est 128. Une valeur de 0 signifie qu'il n'y a pas de limite.
"$s->format_request($method, $uri, %headers, [$content])"
Formate un message de requête et le renvoie sous forme de chaîne. Si les en-têtes n'incluent pas d'en-tête "Host", un en-tête avec la valeur de l'attribut "host" est inséré. Des en-têtes tels que "Connection" et "Keep-Alive" peuvent également être ajoutés en fonction de l'état de la propriété "keep_alive".

Si la valeur de $content est donnée (et n'est pas vide), un en-tête "Content-Length" est automatiquement ajouté, sauf s'il existe déjà.

"$s->write_request($method, $uri, %headers, [$content])"
Formate et envoie un message de requête. Les arguments sont les mêmes que pour format_request(). Renvoie vrai en cas de succès.
"$s->format_chunk( $data )"
Renvoie la chaîne à écrire pour le bloc de données donné.
"$s->write_chunk($data)"
Écrit un nouveau bloc de données de corps de requête. Cette méthode ne doit être utilisée que si un en-tête "Transfer-Encoding" avec la valeur "chunked" a été envoyé dans la requête. Remarque : l'écriture de données de longueur nulle est un NOP. Utilisez la méthode write_chunk_eof() pour signaler la fin du corps des données.

Renvoie vrai en cas de succès.

"$s->format_chunk_eof( %trailers )"
Renvoie la chaîne à écrire pour signaler la fin des données lors de l'utilisation d'un "Transfer-Encoding" de "chunked".
"$s->write_chunk_eof( %trailers )"
Écrit un marqueur de fin de bloc pour les données *chunked* et les en-têtes *trailers* optionnels. Remarque : les en-têtes *trailers* ne devraient pas vraiment être utilisés, sauf s'ils ont été signalés avec un en-tête "Trailer".

Renvoie vrai en cas de succès.

"($code, $mess, %headers) = $s->read_response_headers( %opts )"
Lit les en-têtes de réponse du serveur et les renvoie. La valeur $code est le code d'état à 3 chiffres du protocole HTTP (voir HTTP::Status) et $mess est le message textuel qui l'accompagnait. Les en-têtes sont renvoyés sous forme de paires clé/valeur. Comme la casse des clés n'est pas normalisée et que la même clé peut apparaître plusieurs fois, l'attribution directe de ces valeurs à une table de hachage n'est pas recommandée. Seul $code est renvoyé si cette méthode est appelée dans un contexte scalaire.

À la suite de cette méthode, l'attribut "peer_http_version" est mis à jour.

Les options peuvent être passées sous forme de paires clé/valeur. Actuellement, seules deux options sont prises en charge : "laxed" et "junk_out".

L'option "laxed" rendra read_response_headers() plus tolérante envers les serveurs qui n'ont pas appris à parler HTTP correctement. L'option "laxed" est un indicateur booléen et est activée en passant une valeur vraie. L'option "junk_out" peut être utilisée pour capturer les en-têtes mal formés lorsque "laxed" est activé. La valeur doit être une référence à un tableau. Les en-têtes mal formés seront ajoutés à ce tableau.

L'option "laxed" doit être spécifiée dans l'ordre.

EXEMPLE

Exemple d'utilisation :

use Net::HTTP;
my $s = Net::HTTP->new(Host => "www.perl.com") || die $@;
$s->write_request(GET => "/", 'User-Agent' => "Mozilla/5.0");
my($code, $mess, %h) = $s->read_response_headers;
while (1) {
   my $buf;
   my $n = $s->read_entity_body($buf, 1024);
   die "lecture échouée : $!" unless defined $n;
   last unless $n;
   print $buf;
}

NOM

Net::HTTP

VERSION

Net::HTTP - Extension Perl pour HTTP

SYNOPSIS

use Net::HTTP;

DESCRIPTION

Les méthodes read_response_headers() et read_entity_body() invoqueront la méthode sysread() lorsqu'elles auront besoin de plus de données. Les sous-classes pourraient vouloir redéfinir cette méthode pour contrôler comment la lecture se déroule.

L'objet lui-même est un glob. Les sous-classes devraient éviter d'utiliser des noms de clés de hachage préfixés par "http_" et "io_".

SOUSCLASSES
