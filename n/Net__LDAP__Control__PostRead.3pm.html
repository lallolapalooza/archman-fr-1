NOM

Net::LDAP::Control::PostRead - Objet de contrôle PostRead LDAPv3

SYNOPIS

use Net::LDAP;
use Net::LDAP::Control::PostRead;
use Net::LDAP::Constant qw( LDAP_CONTROL_POSTREAD LDAP_SUCCESS );
$ldap = Net::LDAP->new( "ldap.mydomain.eg" );
$postread = Net::LDAP::Control::PostRead->new( attrs => [ qw/givenName/ ] );
my $mesg = $ldap->modify( "cn=Barbara Jensen, o=University of Michigan, c=US",
                          replace => { givenName => "Babs" },
                          control => $postread );
if ($mesg->code eq LDAP_SUCCESS) {
  my ($afterwards) = $mesg->control( LDAP_CONTROL_POSTREAD ); # Correction: devrait être LDAP_CONTROL_POSTREAD
  my $entry = $afterwards ? $afterwards->entry() : undef;
  if ($entry) {
    print "givenName a changé en '" .
          join("', '", $entry->get_value(givenName") .
          "' à 'Babs'\n");
  }
}

DESCRIPTION

"Net::LDAP::Control::PostRead" fournit une interface pour la création et la manipulation d'objets qui représentent les "Contrôles Post-Read" tels que décrits par la RFC 4527.

Dans les opérations de modification, le "Contrôle de requête Post-Read" indique au serveur qu'une copie de l'entrée modifiée après la mise à jour doit être retournée. Après l'achèvement réussi de l'opération, le "Contrôle de réponse Post-Read" accompagnant permet de récupérer la valeur mise à jour à partir de la réponse du serveur.

Un cas d'utilisation de ce contrôle peut être d'obtenir les valeurs des attributs opérationnels, tels que les attributs "entryUUID" et "modifyTimestamp", mis à jour par le serveur dans le cadre de l'opération de mise à jour.

ARGUMENTS DU CONSTRUCTEUR

En plus des arguments du constructeur décrits dans Net::LDAP::Control, les suivants sont fournis.

attrs => [ ATTR, ... ]
Une liste d'attributs à retourner dans l'entrée retournée dans le contrôle de réponse.

Si absent, tous les attributs sont retournés.

Les attributs opérationnels peuvent être inclus dans la liste en les demandant explicitement ou en utilisant la fonctionnalité spéciale "+" (à condition que le serveur prenne en charge cette fonctionnalité).

MÉTHODES

Comme avec Net::LDAP::Control, chaque argument du constructeur décrit ci-dessus est également disponible sous forme de méthode sur l'objet, qui retournera la valeur actuelle de l'attribut si appelée sans argument, et définira une nouvelle valeur pour l'attribut si appelée avec un argument.

En plus de ces méthodes, le contrôle prend également en charge la méthode suivante :

entry ()
Retourne l'entrée du contrôle de réponse dans le message de réponse à la requête LDAP qui contenait le contrôle de requête.

Le résultat est soit un objet Net::LDAP::Entry, soit undefined.
