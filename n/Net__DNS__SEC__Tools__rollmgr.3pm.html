NOM

Net::DNS::SEC::Tools::rollmgr - Communiquer avec le gestionnaire de rollover DNSSEC-Tools.

SYNTAXE

use Net::DNS::SEC::Tools::rollmgr;
$dir = rollmgr_dir();
$idfile = rollmgr_idfile();
$id = rollmgr_getid();
rollmgr_dropid();
rollmgr_rmid();
rollmgr_cmdint();
$runflag = rollmgr_running();
rollmgr_halt();
rollmgr_phasemsg('long');
rollmgr_channel(1);
($cmd,$data) = rollmgr_getcmd();
$ret = rollmgr_verifycmd($cmd);
rollmgr_sendcmd(CHANNEL_CLOSE,ROLLCMD_ROLLZSK,"example.com");
rollmgr_sendcmd(CHANNEL_WAIT,ROLLCMD_ROLLZSK,"example.com");
($retcode, $respmsg) = rollmgr_getresp();
$descr = rollmgr_get_phase('KSK', $phasecnt);

DESCRIPTION

Le module Net::DNS::SEC::Tools::rollmgr fournit des méthodes standard et indépendantes de la plateforme pour qu'un programme communique avec le gestionnaire de rollover rollerd de DNSSEC-Tools. Deux interfaces sont décrites ici : les interfaces générales et de communication.

INTERFACES GÉNÉRALES

Les interfaces du module Net::DNS::SEC::Tools::rollmgr sont détaillées ci-dessous.

rollmgr_dir()
Cette routine renvoie le répertoire de rollerd.
rollmgr_idfile()
Cette routine renvoie le fichier d'identité de rollerd.
rollmgr_getid()
Cette routine renvoie l'identifiant du processus de rollerd. Si une valeur non nulle est passée comme argument, le fichier d'identité sera laissé ouvert et accessible via le handle PIDFILE. Voir la section WARNING ci-dessous.

Valeurs de retour :

Si le fichier d'identité existe, la première partie du contenu du fichier (80 caractères maximum) est renvoyée.
-1 si le fichier d'identité n'existe pas.
rollmgr_dropid()
Cette interface s'assure qu'aucun autre processus rollerd n'est en cours d'exécution et crée un fichier d'identité pour référence future.

Valeurs de retour :

1 - Le fichier d'identité a été créé avec succès pour ce processus.
0 - Un autre processus agit déjà comme rollerd.
-1 - Échec de la création du fichier d'identité.
rollmgr_rmid()
Cette interface supprime le fichier d'identité de rollerd.

Valeurs de retour :

1 - Le fichier d'identité a été supprimé avec succès.
0 - Aucun fichier d'identité n'existe.
-1 - Le processus actuel n'est pas rollerd.
-2 - Échec de la suppression du fichier d'identité.
rollmgr_cmdint()
Cette routine informe rollerd qu'une commande a été envoyée via rollmgr_sendcmd().

Valeurs de retour :

-1 - Un identifiant de processus invalide pour rollerd a été trouvé.
Toute autre valeur indique le nombre de processus qui ont été signalés.
(Cela devrait être 1 uniquement.)
rollmgr_running()
Cette routine détermine si rollerd est en cours d'exécution et renvoie une valeur indiquant son état.

Valeurs de retour :

1 - rollerd est en cours d'exécution.
0 - Le processus spécifié dans le fichier d'identité de rollerd n'est pas en cours d'exécution.
-1 - Échec de l'obtention de l'identifiant du processus de rollerd.
rollmgr_halt()
Cette routine demande à rollerd de s'arrêter.

Dans l'implémentation actuelle, le code de retour de la commande kill() est renvoyé.

-1 - Un identifiant de processus invalide pour rollerd a été trouvé.
Toute autre valeur indique le nombre de processus qui ont été signalés.
(Cela devrait être 1 uniquement.)
rollmgr_loadzone(ctlprog,opts,zone)
Cette routine demande à un serveur de noms de recharger son fichier de zone correspondant. L'argument $ctlprog est la commande qui sera exécutée pour contrôler le serveur de noms. Si cet argument est une chaîne vide, la valeur par défaut de DNSSEC-Tools sera utilisée. L'argument $opts est un ensemble d'options qui seront passées à $ctlprog. L'argument $zone est le nom de la zone à recharger.

La commande à exécuter sera construite dans ce format :

<$zone> <$opts> reload <$zone>

Ce format suppose que la commande rndc sera utilisée pour signaler au serveur de noms.

La valeur renvoyée sera le code de retour de l'exécution de $ctlprog.

rollmgr_phasemsg()
Cette routine définit la longueur du message de phase dans les messages de journalisation liés à rollerd. Les niveaux valides sont « long » et « short », « long » étant la valeur par défaut.

La longueur du message de phase signifie qu'une description de phase sera incluse avec certains messages de journalisation. Par exemple, la forme longue d'un message sur la phase de rollover ZSK 3 ressemblera à ceci : « Phase ZSK 3 (Attente de l'expiration des anciennes données de zone dans les caches) ».

La longueur du message de phase courte signifie qu'aucune description de phase ne sera incluse avec certains messages de journalisation. Par exemple, la forme courte d'un message sur la phase de rollover ZSK 3 ressemblera à ceci : « Phase ZSK 3 ».

Valeurs de retour :

1 - La longueur du message de phase a été définie.
0 - Une valeur invalide a été spécifiée pour la longueur du message de phase.

INTERFACES DE COMMUNICATION AVEC ROLLMGR

rollmgr_channel(serverflag)
Cette interface établit un canal persistant pour communiquer avec rollerd. Si serverflag est vrai, le côté serveur du canal est créé. Si serverflag est faux, le côté client du canal est créé.

Actuellement, la connexion ne peut être établie qu'avec localhost. Cela pourrait être modifié pour permettre des connexions à distance si nécessaire.

Valeurs de retour :

1 - Le canal de communication a été établi avec succès.
0 - Échec de la connexion au serveur.
-1 - Échec de la création d'un socket Unix.
-2 - Échec de l'association au socket Unix. (serveur uniquement)
-3 - Échec de la modification des permissions du socket Unix. (serveur uniquement)
-4 - Échec de l'écoute sur le socket Unix. (serveur uniquement)
-5 - Le nom du socket était trop long pour un socket Unix.
rollmgr_queuecmd(cmdname, value)
Cette interface enregistre en interne une commande et sa valeur optionnelle pour traitement ultérieur. Voir rollmgr_getcmd() pour plus de détails.
rollmgr_getcmd()
rollmgr_getcmd() traite les commandes qui doivent être traitées. S'il y a des commandes stockées en interne qui ont été traitées via la fonction rollmgr_queuecmd(), elles sont traitées en premier. Ensuite, une commande envoyée par un programme client via le canal de communication de rollerd est récupérée. Les commandes et leurs données sont envoyées dans chaque message.

Les commandes et leurs données sont renvoyées à l'appelant.

rollmgr_sendcmd(closeflag,cmd,data)
rollmgr_sendcmd() envoie une commande à rollerd. La commande doit être l'une des commandes du tableau ci-dessous. Cette interface établit un canal de communication avec rollerd et envoie le message. Le canal n'est pas fermé, au cas où l'appelant souhaiterait recevoir une réponse de rollerd.

Les commandes disponibles et leurs données requises sont :

commandes           données           objectif
-------              ----            -------
ROLLCMD_DISPLAY      1/0             démarrer/arrêter rollerd

La valeur renvoyée sera le code de retour de l'exécution de $ctlprog.

Les données ne sont pas validées par rollmgr_sendcmd() ; la validation des données est la responsabilité de rollerd.

Si l'appelant n'a pas besoin d'une réponse de rollerd, closeflag doit être défini sur CHANNEL_CLOSE ; si une réponse est requise, closeflag doit être défini sur CHANNEL_WAIT. Ces valeurs sont des valeurs booléennes, et les constantes ne sont pas nécessaires.

En cas de succès, 1 est renvoyé. En cas de commande invalide, 0 est renvoyé.

Après avoir exécuté une commande envoyée par rollmgr_sendcmd(), rollerd enverra une réponse au client. rollmgr_getresp() permet au client de récupérer la réponse.

Un code de retour et une chaîne de réponse sont renvoyés, dans cet ordre. Les deux sont spécifiques à la commande envoyée.

rollmgr_verifycmd() vérifie que cmd est une commande valide pour rollerd. 1 est renvoyé pour une commande valide ; 0 pour une commande invalide.

1 est renvoyé pour une commande valide ; 0 pour une commande invalide.

rollmgr_get_phase() renvoie une description d'une phase spécifique pour un type de rollover donné. phasetype spécifie le type de rollover, et peut être "KSK" ou "ZSK". phasenum spécifie le numéro de phase que vous souhaitez décrire. Il doit s'agir d'un entier compris entre 0 et 7 (KSK) ou 0 et 4 (ZSK). Si un type de phase ou un numéro invalide est spécifié, une chaîne vide est renvoyée.

1. rollmgr_getid() essaie de verrouiller exclusivement le fichier d'identification. Définissez un délai si cela est important pour vous.

2. rollmgr_getid() présente un léger problème de condition de concurrence. Nous devrions verrouiller le fichier avant de l'ouvrir, mais nous ne pouvons pas le faire sans qu'il soit ouvert.
