NOM

Net::Telnet - interagir avec le port TELNET ou d'autres ports TCP

SYNOPSIS

"use Net::Telnet ();"

voir les sections MÉTHODES ou EXEMPLES ci-dessous

DESCRIPTION

Net::Telnet vous permet d'établir des connexions client vers un port TCP et d'effectuer des E/S réseau, en particulier vers un port utilisant le protocole TELNET. Des méthodes d'E/S simples comme print, get et getline sont fournies. Des fonctionnalités interactives plus sophistiquées sont offertes car se connecter à un port TELNET implique ultimement de communiquer avec un programme conçu pour l'interaction humaine. Ces fonctionnalités interactives incluent la capacité de spécifier un délai d'attente et d'attendre que des modèles apparaissent dans le flux d'entrée, tels que l'invite d'un shell. Le support IPv6 est disponible lorsque vous utilisez perl 5.14 ou plus récent, voir family().

Autres raisons d'utiliser ce module que strictement avec un port TELNET :

  • Vous n'êtes pas familier avec les sockets et vous souhaitez un moyen simple d'établir des connexions client vers des services TCP.
  • Vous voulez pouvoir spécifier votre propre délai d'attente lors de la connexion, de la lecture ou de l'écriture.
  • Vous communiquez avec un programme interactif à l'autre bout d'un socket ou d'un tube et vous souhaitez attendre que certains modèles apparaissent.

Voici un exemple qui affiche qui est connecté sur un hôte distant. En plus d'un nom d'utilisateur et d'un mot de passe, vous devez également connaître l'invite du shell de l'utilisateur, qui dans cet exemple est "bash$ "

use Net::Telnet ();
$t = new Net::Telnet (Timeout => 10,
                      Prompt => '/bash\$ $/');
$t->open($host);
$t->login($username, $passwd);
@lines = $t->cmd("who");
print @lines;

Voir la section EXEMPLES ci-dessous pour plus d'exemples.

Les questions d'utilisation doivent être adressées au groupe de discussion perlmonks.org. Les bogues peuvent être consultés ou signalés sur cpan.org dans la page Net::Telnet.

Ce qu'il faut savoir avant d'utiliser

  • Toute sortie est vidée tandis que toute entrée est mise en mémoire tampon. Chaque objet contient son propre tampon d'entrée.
  • Le séparateur d'enregistrement de sortie pour print() et cmd() est défini sur "\n" par défaut, de sorte que vous n'ayez pas à ajouter un retour à la ligne à toutes vos commandes. Pour éviter d'imprimer un "\n" final, utilisez put() ou définissez le output_record_separator sur "".
  • Les méthodes login() et cmd() utilisent le paramètre prompt de l'objet pour déterminer quand une connexion ou une commande à distance est terminée. Ces méthodes échoueront avec un délai d'attente si vous ne définissez pas correctement l'invite.
  • Utilisez une combinaison de print() et waitfor() comme alternative à login() ou cmd() lorsqu'ils ne font pas ce que vous voulez.
  • Les erreurs telles que les dépassements de délai sont gérées conformément à l'action du mode d'erreur. L'action par défaut est d'imprimer un message d'erreur sur la sortie standard et de faire mourir le programme. Voir la méthode errmode() pour plus d'informations.
  • Lors de la construction de l'argument de l'opérateur de correspondance pour prompt() ou waitfor(), utilisez toujours des guillemets simples au lieu de guillemets doubles pour éviter une interprétation inattendue des antislashs (par exemple, '/bash\$ $/'). Si vous construisez un chemin de fichier de type DOS, vous devrez utiliser quatre antislashs pour en représenter un (par exemple, '/c:\\\\users\\\\bill>$/i').

    Bien sûr, n'oubliez pas les métacaractères regexp comme ".", "[" ou "$". Vous n'aurez besoin que d'un seul antislash pour les échapper. Les métacaractères d'ancre "^" et "$" font référence à des positions dans le tampon d'entrée. Pour éviter de faire correspondre des caractères lus qui ressemblent à une invite, il est conseillé de terminer votre modèle d'invite par l'ancre "$". Ainsi, l'invite ne correspondra que si elle est la dernière chose lue.

  • Dans le flux d'entrée, chaque séquence de retour chariot et de saut de ligne (c'est-à-dire "\015\012" ou CR LF) est convertie en "\n". Dans le flux de sortie, chaque occurrence de "\n" est convertie en une séquence de CR LF. Voir binmode() pour modifier ce comportement. Les protocoles TCP utilisent généralement la séquence ASCII, retour chariot et saut de ligne pour désigner un saut de ligne.
  • Le délai d'attente lors de l'établissement d'une connexion est désactivé pour les machines qui ne prennent pas en charge la fonction alarm(). Les machines MS-Windows notamment.
  • Vous devez exécuter au moins la version 5.002 de Perl pour utiliser ce module. Ce module ne nécessite aucune bibliothèque qui ne soit déjà fournie avec une distribution Perl standard.

    Si vous avez les bibliothèques IO:: installées (elles sont fournies en standard avec perl5.004 et versions ultérieures), alors IO::Socket::INET est utilisé comme classe de base, sinon FileHandle est utilisé.

Débogage

Le bug d'utilisation typique provoque une erreur de délai d'attente parce que vous avez fait des hypothèses incorrectes sur ce que l'autre côté envoie réellement. La manière la plus simple de réconcilier ce que l'autre côté envoie avec vos attentes est d'utiliser input_log() ou dump_log().

dump_log() vous permet de voir les données envoyées par l'autre côté avant toute traduction, tandis que input_log() vous montre les résultats après la traduction. La traduction comprend la conversion des caractères de fin de ligne, la suppression et la réponse aux commandes du protocole TELNET dans le flux de données.

Style de paramètres nommés

Deux styles différents de paramètres nommés sont pris en charge. Ce document ne montre que le style IO:: :

Net::Telnet->new(Timeout => 20);

cependant le style avec options commençant par un trait d'union est également autorisé :

Net::Telnet->new(-timeout => 20);

Connexion à une machine MS-Windows distante

Par défaut, MS-Windows ne fournit pas de serveur TELNET. Cependant, des serveurs TELNET tiers sont disponibles. Malheureusement, beaucoup de ces serveurs prétendent à tort être des serveurs TELNET. C'est particulièrement vrai pour le soi-disant « Microsoft Telnet Server » qui est installé avec certaines versions plus récentes de MS-Windows.

Lorsqu'un serveur TELNET accepte une connexion pour la première fois, il doit utiliser les caractères de contrôle ASCII retour chariot et saut de ligne pour commencer une nouvelle ligne (voir RFC854). Un serveur comme le « Microsoft Telnet Server » qui ne le fait pas, n'est pas un serveur TELNET. Ces serveurs envoient des séquences d'échappement de terminal ANSI pour se positionner sur une colonne d'une ligne suivante et même pour se positionner tout en écrivant des caractères adjacents. Pire encore, lors de l'envoi de la sortie, ces serveurs renvoient la sortie de commande précédemment envoyée dans une tentative malavisée d'afficher un écran de terminal entier.

Connecter Net::Telnet à un de ces faux serveurs TELNET rend votre travail d'analyse de la sortie des commandes très difficile. Il est préférable de remplacer un faux serveur TELNET par un vrai serveur TELNET. Les meilleurs serveurs TELNET pour MS-Windows vous permettent d'éviter les échappements ANSI en désactivant quelque chose qu'ils appellent parfois le *mode console*.

mode_binaire - basculer la traduction des nouvelles lignes
$mode = $obj->mode_binaire;
$prev = $obj->mode_binaire($mode);

Cette méthode contrôle si les séquences de retours chariot et de sauts de ligne (CR LF ou plus spécifiquement "\015\012") sont traduites ou non. Par défaut, elles sont traduites (c'est-à-dire que le mode binaire est 0).

Si aucun argument n'est donné, le mode actuel est retourné.

Si $mode est 1, le mode binaire est activé et la traduction des nouvelles lignes n'est pas effectuée.

Si $mode est 0, le mode binaire est désactivé et la traduction des nouvelles lignes est effectuée. Dans le flux d'entrée, chaque séquence CR LF est convertie en "\n" et dans le flux de sortie, chaque occurrence de "\n" est convertie en une séquence CR LF.

Notez que l'entrée est toujours mise en tampon. Le changement du mode binaire n'affecte pas ce qui a déjà été lu dans le tampon. La sortie n'est pas mise en tampon et le changement du mode binaire aura un effet immédiat.

interruption - envoyer le caractère d'interruption TELNET
$ok = $obj->interruption;

Cette méthode envoie le caractère d'interruption TELNET. Ce caractère est fourni car c'est un signal en dehors de l'ensemble de caractères ASCII qui a actuellement une signification locale au sein de nombreux systèmes. Il est destiné à indiquer que la touche Pause ou la touche Attention a été enfoncée.

Cette méthode retourne 1 en cas de succès, ou effectue l'action de mode d'erreur en cas d'échec.

tampon - référence scalaire au tampon d'entrée de l'objet
$ref = $obj->tampon;

Cette méthode retourne une référence scalaire vers le tampon d'entrée de $obj. Les données dans le tampon d'entrée sont des données qui ont été lues du côté distant mais qui n'ont pas encore été lues par l'utilisateur. Les modifications apportées au tampon d'entrée sont retournées par une lecture ultérieure.

tampon_vide - effacer toutes les données dans le tampon d'entrée de l'objet
$obj->tampon_vide;

Cette méthode supprime toutes les données du tampon d'entrée de $obj.

fermer - fermer l'objet
$ok = $obj->fermer;

Cette méthode ferme le socket, le fichier ou le tuyau associé à l'objet. Elle retourne toujours une valeur de 1.

cmd - émettre une commande et récupérer la sortie
$ok = $obj->cmd($chaine);
$ok = $obj->cmd(Chaine   => $chaine,
                [Sortie  => $ref,]
                [Mode_suppression_cmd => $mode,]
                [Mode_erreur => $mode,]
                [Separateur_enregistrement_entree => $car,]
                [Ors     => $car,]
                [Separateur_enregistrement_sortie => $car,]
                [Invite  => $match,]
                [Rs      => $car,]
                [Delai => $secs,]);
@sortie = $obj->cmd($chaine);
@sortie = $obj->cmd(Chaine   => $chaine,
                    [Sortie  => $ref,]
                    [Mode_suppression_cmd => $mode,]
                    [Mode_erreur => $mode,]
                    [Separateur_enregistrement_entree => $car,]
                    [Ors     => $car,]
                    [Separateur_enregistrement_sortie => $car,]
                    [Invite  => $match,]
                    [Rs      => $car,]
                    [Delai => $secs,]);

Cette méthode envoie la commande $chaine et lit les caractères renvoyés par la commande jusqu'à et y compris l'invite correspondante. On suppose que le programme auquel vous envoyez est une sorte d'interpréteur de commandes, comme un shell.

La commande $chaine se voit automatiquement ajouter le séparateur d'enregistrement de sortie, qui par défaut est "\n". C'est similaire à quelqu'un tapant une commande et appuyant sur la touche retour. Définissez le séparateur d'enregistrement de sortie pour changer ce comportement.

Dans un contexte scalaire, les caractères lus du côté distant sont ignorés et 1 est retourné en cas de succès. En cas de dépassement de délai, de fin de fichier (eof) ou d'autres échecs, l'action de mode d'erreur est effectuée. Voir errmode().

Dans un contexte de liste, seule la sortie générée par la commande est retournée, une ligne par élément. En d'autres termes, tous les caractères entre la chaîne de commande renvoyée et l'invite sont retournés. Si la commande ne génère aucune sortie, une liste contenant un élément, la chaîne vide, est retournée. Ceci afin que la liste soit considérée comme vraie dans un contexte booléen. En cas de dépassement de délai, de fin de fichier (eof) ou d'autres échecs, l'action de mode d'erreur est effectuée. Voir errmode().

Les caractères qui ont correspondu à l'invite peuvent être récupérés en utilisant last_prompt().

De nombreux interpréteurs de commandes renvoient la commande envoyée. Dans la plupart des situations, cette méthode supprime la première ligne renvoyée par le côté distant (c'est-à-dire la commande renvoyée). Voir cmd_remove_mode() pour plus de contrôle sur cette fonctionnalité.

Utilisez dump_log() pour déboguer lorsque cette méthode continue de dépasser le délai sans raison apparente et que vous pensez que ce ne devrait pas être le cas.

Envisagez d'utiliser une combinaison de print() et waitfor() comme alternative à cette méthode lorsqu'elle ne fait pas ce que vous voulez, par exemple, lorsque la commande que vous envoyez demande une saisie.

Le paramètre nommé Sortie offre une méthode alternative pour recevoir la sortie de la commande. Si vous passez une référence scalaire, toute la sortie (même si elle contient plusieurs lignes) est retournée dans le scalaire référencé. Si vous passez une référence de tableau ou de hachage, les lignes de sortie sont retournées dans le tableau ou le hachage référencé. Vous pouvez utiliser input_record_separator() pour changer la notion de ce qui sépare une ligne.

Les paramètres nommés optionnels sont fournis pour remplacer les paramètres actuels de cmd_remove_mode, errmode, input_record_separator, ors, output_record_separator, prompt, rs, et timeout. Rs est synonyme de input_record_separator et ors est synonyme de output_record_separator.

mode_suppression_cmd - basculer la suppression des commandes renvoyées
$mode = $obj->mode_suppression_cmd;
$prev = $obj->mode_suppression_cmd($mode);

Cette méthode contrôle comment traiter les commandes renvoyées dans la sortie retournée par cmd(). Typiquement, lorsque vous envoyez une commande au côté distant, la première ligne de sortie renvoyée est la commande renvoyée. Utilisez ce mode pour supprimer la première ligne de sortie normalement retournée par cmd().

Si aucun argument n'est donné, le mode actuel est retourné.

Si $mode est 0, alors les lignes de sortie de commande retournées par cmd() ne sont pas supprimées. Si $mode est un entier positif, alors les $mode premières lignes de la sortie de commande sont supprimées.

auto_accept_echo - aceptar automáticamente el eco del lado remoto
$bool = $obj->auto_accept_echo;
$prev = $obj->auto_accept_echo($bool);

Par défaut, $mode est configuré sur "auto". Auto signifie que, selon que le côté distant ait proposé l'écho, la première ligne de sortie de la commande sera supprimée ou non. Par défaut, Net::Telnet accepte toujours une proposition d'écho du côté distant. Vous pouvez modifier ce comportement en utilisant option_accept().

Un avertissement est imprimé sur STDERR lorsque l'on tente de définir cette propriété sur autre chose que "auto" ou un entier non négatif.

dump_log - journal I/O au format dump
$fh = $obj->dump_log;
$fh = $obj->dump_log($fh);
$fh = $obj->dump_log($tiefh);
$fh = $obj->dump_log($filename);

Cette méthode démarre ou arrête la journalisation des I/O au format dump de toute entrée et sortie de l'objet. Le format dump affiche les blocs de lecture et d'écriture en format hexadécimal et en caractères lisibles. Cette méthode est utile pour le débogage, bien que vous puissiez d'abord essayer input_log() car il est plus lisible.

Si aucun argument n'est fourni, le fichier journal est renvoyé. Une chaîne vide indique que la journalisation est désactivée.

Pour arrêter la journalisation, utilisez un argument vide. Le fichier journal arrêté n'est pas fermé.

Si un descripteur de fichier ouvert est fourni, il est utilisé pour la journalisation et renvoyé. Sinon, l'argument est considéré comme le nom d'un fichier, et un fichier journal est ouvert et un descripteur de fichier est renvoyé. Si le fichier journal n'est pas ouvert ou si le nom ne peut pas être ouvert en écriture, le mode d'action d'erreur est exécuté. Le fichier journal peut être un descripteur de fichier lié.

eof - indicateur de fin de fichier
$eof = $obj->eof;

Cette méthode renvoie 1 si l'indicateur de fin de fichier a été lu, sinon elle renvoie une chaîne vide. Comme l'entrée est bufferisée, cela ne signifie pas que $obj a été fermé. Autrement dit, $obj peut être fermé mais il peut encore y avoir du contenu dans le tampon qui peut être lu. Dans ce cas, vous pouvez lire mais vous ne pourrez pas écrire.

errmode - définir l'action à effectuer en cas d'erreur
$mode = $obj->errmode;
$prev = $obj->errmode($mode);

Cette méthode obtient ou définit l'action qui sera exécutée lorsqu'une erreur sera détectée par l'objet. Le premier appel de séquence renvoie le mode d'erreur actuel. Le second appel de séquence définit le mode d'erreur sur $mode et renvoie le mode précédent. Les valeurs valides pour $mode sont "die" (par défaut), "return", une référence de code ou un tableau de références.

Lorsque le mode est "die" et qu'une erreur est détectée par l'objet, un message d'erreur est imprimé sur STDERR et le programme se termine.

Lorsque le mode est "return", le message d'erreur généré est stocké dans l'objet et renvoie une valeur indéfinie dans un contexte scalaire et une liste vide dans un contexte de liste. Le message d'erreur peut être obtenu en utilisant errmsg().

Lorsque le mode est une référence de code, lorsqu'une erreur est détectée, la référence de code est appelée avec le message d'erreur comme premier argument. En utilisant ce mode, vous pouvez gérer vos propres sous-routines d'erreur. Si la référence de code renvoie elle-même, la méthode générant l'erreur renvoie une valeur indéfinie ou une liste vide selon le contexte.

Lorsque le mode est un tableau de références, le premier élément de la référence doit être une référence de code. Tous les éléments suivants sont les arguments de la référence de code. Lorsqu'une erreur est détectée, la référence de code est appelée avec ses arguments. En utilisant ce mode, vous pouvez gérer vos propres sous-routines d'erreur. Si la référence de code renvoie elle-même, la méthode générant l'erreur renvoie une valeur indéfinie ou une liste vide selon le contexte.

Un avertissement est imprimé sur STDERR lorsque l'on tente de définir cette propriété sur autre chose que "die", "return", une référence de code, ou un tableau de références dont le premier élément n'est pas une référence de code.

errmsg - message d'erreur le plus récent
$msg = $obj->errmsg;
$prev = $obj->errmsg(@msgs);

Le premier appel de séquence renvoie le message d'erreur associé à l'objet. Une chaîne vide est renvoyée s'il n'y a pas eu d'erreur détectée. Le second appel de séquence définit le message d'erreur de l'objet à la concaténation de @msgs et renvoie le message précédent. Normalement, les messages d'erreur sont définis en interne par une méthode lorsqu'une erreur est détectée.

error - exécuter l'action du mode d'erreur
$obj->error(@msgs);

Cette méthode concatène @msgs en une chaîne et la place dans l'objet comme message d'erreur. Voir également errmsg(). Elle exécute ensuite l'action du mode d'erreur. Voir également errmode().

Si le mode d'erreur ne provoque pas la fin du programme, une valeur indéfinie ou une liste vide est renvoyée selon le contexte.

Cette méthode est principalement utilisée par cette classe ou une sous-classe pour exécuter l'action demandée par l'utilisateur lorsqu'une erreur est détectée.

family - famille d'adresses IP pour l'hôte distant
$family = $obj->family;
$prev   = $obj->family($family);

Cette méthode indique à quelle famille d'adresses IP host() fait référence, c'est-à-dire IPv4 ou IPv6. Le support de l'IPv6 est disponible lors de l'utilisation de perl 5.14 ou ultérieure. Sans argument, elle renvoie la valeur actuellement configurée dans l'objet. Avec un argument, elle définit la famille actuelle sur $family et renvoie la famille précédente. Les valeurs valides sont "ipv4", "ipv6", ou "any". Lorsque "any", host() peut être un nom d'hôte ou une adresse IP pour IPv4 et IPv6. Après la connexion, vous pouvez utiliser sockfamily() pour déterminer quelle famille d'adresses IP a été utilisée.

La valeur par défaut est "ipv4".

L'action du mode d'erreur est effectuée lorsque l'on tente de définir cette propriété sur autre chose que "ipv4", "ipv6", ou "any". Elle est également effectuée lorsque l'on tente de définir sur "ipv6" lorsque le module Socket est de version inférieure à 1.94 ou lorsque l'IPv6 n'est pas supporté sur le système d'exploitation tel qu'indiqué par Socket::AF_INET6 n'étant pas défini.

fhopen - utiliser un descripteur de fichier déjà ouvert pour I/O
$ok = $obj->fhopen($fh);

Cette méthode associe le descripteur de fichier déjà ouvert $fh à $obj pour les I/O supplémentaires. Le descripteur de fichier $fh doit être déjà ouvert.

Supposons que vous souhaitiez utiliser les fonctionnalités de ce module pour effectuer des I/O sur quelque chose d'autre que TCP, par exemple STDIN ou un descripteur de fichier ouvert en lecture à partir d'un processus. Au lieu d'ouvrir l'objet pour des I/O sur un port TCP en utilisant open() ou new(), appelez cette méthode.

La valeur 1 est renvoyée en cas de succès, et l'action du mode d'erreur est exécutée en cas d'échec.

get - lire un bloc de données
$data = $obj->get([Binmode    => $mode,]
                  [Errmode    => $errmode,]
                  [Telnetmode => $mode,]
                  [Timeout    => $secs,]);

Cette méthode lit un bloc de données de l'objet et le renvoie avec toutes les données bufferisées disponibles. Dans la plupart des cas, votre sortie est lue par un interpréteur de commandes qui n'accepte pas une commande tant qu'une nouvelle ligne n'a pas été lue. C'est similaire à appuyer sur la touche Entrée après avoir tapé une commande. Pour éviter d'imprimer une nouvelle ligne finale "\n", utilisez put() ou définissez output_record_separator sur une chaîne vide.

En cas d'échec, il est possible qu'une partie des données ait été écrite. Si vous souhaitez récupérer d'un délai d'attente d'impression, utilisez print_length() pour déterminer la quantité écrite avant l'échec.

Vous pouvez également utiliser le séparateur de champ pour imprimer une chaîne entre les éléments de la liste. Voir output_field_separator().

print_length - nombre d'octets écrits par print
$num = $obj->print_length;

Ceci renvoie le nombre d'octets écrits avec succès par la dernière print() ou put().

prompt - modèle pour trouver une invite
$matchop = $obj->prompt;
$prev = $obj->prompt($matchop);

Cette méthode définit le modèle utilisé pour trouver une invite dans le flux d'entrée. Il doit s'agir d'une chaîne représentant un opérateur de correspondance Perl valide. Les méthodes login() et cmd() tentent de lire jusqu'à ce qu'elles correspondent au modèle que vous avez choisi. Si le modèle que vous avez choisi ne correspond pas à ce que renvoie l'extrémité distante, elles échoueront avec une erreur de délai d'attente.

Sans argument, elle renvoie le modèle défini dans l'objet. Avec un argument, elle définit le modèle sur $matchop et renvoie la valeur précédente.

Le modèle par défaut est '/[\$%#>] $/'

Utilisez toujours des guillemets simples, pas des guillemets doubles, pour construire $matchop (exemple : '/bash\$ $/'). Si vous construisez un chemin de fichier de type DOS, vous aurez besoin de quatre barres obliques inverses pour en représenter une (exemple : '/c:\\\\users\\\\bill>$/i').

En fait, n'oubliez pas les caractères métacaractères regex comme ".", "[", ou "$". Vous n'aurez besoin que d'une seule barre oblique inverse pour les échapper. Les métacaractères de début et de fin de chaîne "^" et "$" font référence à des positions dans le tampon d'entrée.

L'action du mode d'erreur est exécutée lorsque vous tentez de définir cet attribut avec un opérateur de correspondance qui a omis son délimiteur initial.

put - écrire dans l'objet
$ok = $obj->put($string);
$ok = $obj->put(String      => $string,
                [Binmode    => $mode,]
                [Errmode    => $errmode,]
                [Telnetmode => $mode,]
                [Timeout    => $secs,]);

Cette méthode écrit $string à l'objet ouvert et renvoie 1 si toutes les données ont été correctement écrites. Cette méthode est similaire à print() sauf qu'elle n'écrit pas le délimiteur de sortie "\n" par défaut. En cas de délai d'attente ou d'échec, l'action du mode d'erreur est exécutée. Voir errmode().

En cas d'échec, il est possible qu'une partie des données ait été écrite. Si vous souhaitez récupérer d'un délai d'attente de mise, utilisez print_length() pour déterminer la quantité écrite avant l'échec.

Des paramètres nommés optionnels sont fournis pour remplacer les configurations actuelles de binmode, errmode, telnetmode et timeout.

rs - délimiteur de ligne d'entrée
$chars = $obj->rs;
$prev = $obj->rs($chars);

Cette méthode est équivalente à input_record_separator().

sockfamily - famille d'adresses IP du socket local connecté
$sockfamily = $obj->sockfamily;

Cette méthode retourne la famille d'adresses IP que open() a utilisée pour se connecter avec succès. Elle est particulièrement utile lorsque la famille d'adresses family() demandée pour open() était "any". Les valeurs retournées peuvent être "ipv4", "ipv6", ou "" (lorsqu'il n'y a pas de connexion).

sockhost - Adresse IP de cette extrémité de la connexion socket
$ipaddr = $obj->sockhost;

Cette méthode retourne une chaîne représentant l'adresse IPv4 ou IPv6 à laquelle le socket local est lié. Elle retourne "" lorsqu'il n'y a pas de connexion.

sockport - Port TCP de cette extrémité de la connexion socket
$port = $obj->sockport;

Cette méthode retourne le numéro de port auquel le socket local est lié. Elle retourne "" lorsqu'il n'y a pas de connexion.

telnetmode - désactiver/activer l'interprétation des commandes telnet
$mode = $obj->telnetmode;
$prev = $obj->telnetmode($mode);

Cette méthode contrôle si les commandes TELNET dans le flux de données sont reconnues et traitées. Le protocole TELNET utilise certaines séquences de caractères envoyées dans le flux de données pour contrôler la session. Si le port auquel vous vous connectez n'utilise pas le protocole TELNET, vous devriez désactiver ce mode. La valeur par défaut est activée.

Si aucun argument n'est fourni, le mode actuel est retourné.

Si $mode est 0, le mode telnet est désactivé. Si $mode est 1, le mode telnet est activé.

timed_out - indicateur de dépassement de délai
$boolean = $obj->timed_out;
$prev = $obj->timed_out($boolean);

Cette méthode indique si une opération de lecture, d'écriture ou d'ouverture précédente a dépassé le délai imparti. N'oubliez pas qu'un dépassement de délai est une erreur en soi. Pour pouvoir invoquer timed_out() après une erreur de dépassement de délai, vous devriez changer le mode d'erreur par défaut à quelque chose d'autre que "die". Voir errmode().

Sans argument, cette méthode retourne 1 si l'opération précédente a dépassé le délai imparti. Avec un argument, elle définit l'indicateur. Normalement, seules les méthodes internes définissent cet indicateur.

timeout - intervalle de délai d'attente pour les E/S
$secs = $obj->timeout;
$prev = $obj->timeout($secs);

Cette méthode définit l'intervalle de délai d'attente utilisé lors des opérations d'E/S ou lors de la connexion à un port. Lorsqu'une méthode ne se termine pas dans l'intervalle de délai imparti, cela constitue une erreur et l'action définie par le mode d'erreur est exécutée.

Un délai peut être exprimé comme une valeur relative ou absolue. Si $secs est supérieur ou égal au moment où le programme a démarré, tel que déterminé par $^T, alors il s'agit d'une valeur de temps absolue pour le moment où le délai expire. La fonction Perl time() peut être utilisée pour obtenir une valeur de temps absolue. Pour une valeur de délai relative inférieure à $^T, le délai expire $secs après le début de la méthode.

Si $secs est 0, le délai expire si les données ne peuvent pas être immédiatement lues ou écrites. Utilisez la valeur indéfinie pour désactiver complètement le délai d'attente.

Sans argument, cette méthode retourne le délai d'attente défini dans l'objet. Avec un argument, elle définit le délai d'attente à $secs et retourne la valeur précédente. La valeur de délai par défaut est de 10 secondes.

Un avertissement est imprimé sur STDERR lors de la tentative de définition de cet attribut à quelque chose qui n'est pas une valeur "undef" ou un entier non négatif.

waitfor - attendre un motif dans l'entrée
$ok = $obj->waitfor($matchop);
$ok = $obj->waitfor([Match      => $matchop,]
                    [String     => $string,]
                    [Binmode    => $mode,]
                    [Errmode    => $errmode,]
                    [Telnetmode => $mode,]
                    [Timeout    => $secs,]);
($prematch, $match) = $obj->waitfor($matchop);
($prematch, $match) = $obj->waitfor([Match      => $matchop,]
                                    [String     => $string,]
                                    [Binmode    => $mode,]
                                    [Errmode    => $errmode,]
                                    [Telnetmode => $mode,]
                                    [Timeout    => $secs,]);

Cette méthode lit jusqu'à ce qu'un motif ou une chaîne soit trouvé dans le flux d'entrée. Tous les caractères avant et y compris la correspondance sont retirés du flux d'entrée.

Dans un contexte de liste, les caractères avant la correspondance et les caractères correspondants sont retournés dans $prematch et $match. Dans un contexte scalaire, les caractères correspondants et tous les caractères avant eux sont ignorés et 1 est retourné en cas de succès. En cas de dépassement de délai, de fin de fichier (eof) ou d'autres erreurs, pour les contextes scalaire et de liste, l'action du mode d'erreur est exécutée. Voir errmode().

Vous pouvez spécifier plusieurs motifs ou chaînes en fournissant simplement plusieurs paramètres nommés Match et/ou String. Un $matchop doit être une chaîne représentant un opérateur de correspondance de motif Perl valide. Le $string est simplement une sous-chaîne à trouver dans le flux d'entrée.

Utilisez dump_log() pour déboguer lorsque cette méthode dépasse continuellement le délai imparti et que vous pensez qu'elle ne le devrait pas.

Un paramètre nommé optionnel est fourni pour remplacer le paramètre actuel du délai d'attente.

Pour éviter une interprétation inattendue des antislashs, utilisez toujours des guillemets simples plutôt que des guillemets doubles pour construire un argument d'opérateur de correspondance pour prompt() et waitfor() (par exemple, '/bash\$ $/'). Si vous construisez un chemin de fichier de type DOS, vous devrez utiliser quatre antislashs pour en représenter un (par exemple, '/c:\\\\users\\\\bill>$/i').

N'oubliez pas les métacaractères d'expression régulière comme ".", "[", ou "$". Vous n'aurez besoin que d'un seul antislash pour les échapper. Les métacaractères d'ancre "^" et "$" font référence à des positions dans le tampon d'entrée.

Définir prompt() pour qu'il corresponde à l'invite du shell d'un utilisateur peut être délicat. Cet exemple se connecte sans connaître l'invite du shell, puis la définit pour correspondre à prompt(). Il nécessite /usr/bin/env et /bin/sh sur l'hôte distant.

my $host = 'votre_hote_destination_ici';
my $user = 'votre_nom_utilisateur_ici';
my $passwd = 'votre_mot_de_passe_ici';
my ($t, @output);
## Créer un objet Net::Telnet.
use Net::Telnet ();
$t = new Net::Telnet (Timeout  => 10);
## Connexion et connexion.
$t->open($host);
$t->waitfor('/login: ?$/i');
$t->print($user);
$t->waitfor('/password: ?$/i');
$t->print($passwd);
## Passer à un shell connu, en utilisant une invite connue.
$t->prompt('/<xPROMPTx> $/');
$t->errmode("return");
$t->cmd("exec /usr/bin/env 'PS1=<xPROMPTx> ' /bin/sh -i")
    or die "la connexion à l'hôte distant $host a échoué";
$t->errmode("die");
## Vous pouvez maintenant utiliser cmd() à votre guise.
@output = $t->cmd("uname -a");
print @output;
exit;

Généralement, vous voulez que la variable d'environnement TERM distante soit définie sur quelque chose comme "dumb" afin de ne pas lire les séquences d'échappement destinées à être interprétées par un terminal d'affichage. Il est préférable de la définir via cmd(), ou via waitfor() et print(). Il est également possible de négocier le type de terminal via telnet. Voici comment procéder.

## Import du module.
use Net::Telnet qw(TELNET_IAC TELNET_SB TELNET_SE TELOPT_TTYPE);
## Variables globales.
my $Term;
## Programme principal.
{
    my $host = "votre_hote_destination_ici";
    my $user = "votre_nom_utilisateur_ici";
    my $passwd = "votre_mot_de_passe_ici";
    my $prompt = '/bash\$ $/';  # votre expression régulière pour l'invite du shell ici
    my $t;
    $t = new Net::Telnet (Prompt => $prompt);
    ## Configuration des rappels pour négocier le type de terminal.
    $t->option_callback(sub {});
    $t->suboption_callback(\&subopt_callback);
    $t->option_accept(Do => TELOPT_TTYPE);
    ## Connexion et impression de la valeur de TERM.
    $Term = "dumb";
    $t->open($host);
    $t->login($user, $passwd);
    print $t->cmd('hostname');
    print "TERM=", $t->cmd('echo $TERM');
    $t->close;
    exit;
} # fin du programme principal
sub subopt_callback {
    my ($t, $option, $parameters) = @_;
    my $telcmd;
    if ($option == TELOPT_TTYPE) {
        $telcmd = pack("C4 A* C2", TELNET_IAC, TELNET_SB, TELOPT_TTYPE, 0,
                       $Term, TELNET_IAC, TELNET_SE);
        $t->put(String => $telcmd,
                Telnetmode => 0);
    }

NAME

        
Net::Telnet - Perl module for interacting with remote Telnet servers.

    

    

        
SYNOPSIS

        
 use Net::Telnet;

 ## Automatically handle the login.
 my $t = new Net::Telnet (
                  -Host   => "some.host.name",
                  -Port   => 23,
                  -Timeout => 10,
                  -Prompt => '/#\s?$/',
                  -Login => 'myusername',
                  -Password => 'mypassword'
                 );
 my @lines = $t->cmd("ls -l");
 print @lines;
 $t->close;

 ## Manually handle the login.
 my $t = new Net::Telnet (
                  -Timeout => 10,
                  -Prompt => '/#\s?$/'
                 );
 $t->open("some.host.name");
 $t->login("myusername", "mypassword");
 my @lines = $t->cmd("ls -l");
 print @lines;
 $t->close;

 ## Interact with local programs.
 my $pty = spawn("passwd");
 my $passwd = new Net::Telnet (-fhopen => $pty, -telnetmode => 0);
 $passwd->waitfor('/password: ?$/i');
 $passwd->print("changeme");
 $passwd->waitfor('/new (\w+\s)?password: ?$/i');
 $passwd->print("changeme");
 $passwd->waitfor('/new (\w+\s)?password: ?$/i');
 $passwd->print("changeme");
 print $passwd->lastline;
 $passwd->close;


    

    

        
DESCRIPTION

        
The Net::Telnet module provides an object-oriented interface for
            communicating with remote Telnet servers. It supports automatic login,
            command execution, and interaction with interactive programs. It can also
            be used to interact with local programs by spawning them under a pseudo-terminal
            (pty).

    

    

        
METHODS

        

            
new

            
Creates a new Net::Telnet object. Accepts a hash of attributes:

            
-Host

            
The hostname or IP address of the Telnet server.

            
-Port

            
The port number to connect to (default is 23).

            
-Timeout

            
The timeout in seconds for network operations.

            
-Prompt

            
A regular expression matching the command prompt.

            
-Login

            
The username for automatic login.

            
-Password

            
The password for automatic login.

            
-Telnetmode

            
Set to 0 to disable Telnet protocol negotiation (useful for interacting with non-Telnet services or local programs).

            
-cmd_remove_mode

            
Set to 1 to remove the command string from the output of cmd().

            
-output_record_separator

            
The record separator used for output. Defaults to "\r\n".

            
-errmode

            
Set to 'return' to have methods return undef on error, otherwise they die.

            
-fhopen

            
A filehandle to use instead of opening a new connection.

            
open

            
Connects to the specified host and port.

            
login

            
Logs in to the server with the provided username and password.

            
waitfor

            
Waits for a specific pattern to appear in the output.

            
print

            
Sends a string to the server.

            
cmd

            
Sends a command string to the server and waits for the prompt.

            
getc

            
Reads a single character from the server.

            
get_page

            
Reads all output until the prompt is encountered.

            
close

            
Closes the connection.

            
lastline

            
Returns the last line received from the server.

            
error

            
Returns the last error message.

This example shows how to interact with the passwd
            program locally. It uses the spawn() subroutine to
            start the program and associate a filehandle with its standard I/O. The
            IO::Pty module is used to create a new pseudo-terminal
            for passwd, as it prompts for passwords on its
            controlling terminal.

        
## Main program.
{
    my ($pty, $passwd);
    my $oldpw = "changeme";
    my $newpw = "changeme";

    ## Start passwd program.
    $pty = spawn("passwd");
    ## Create a Net::Telnet object to perform I/O on passwd's tty.
    use Net::Telnet;
    $passwd = new Net::Telnet (-fhopen => $pty,
                               -timeout => 2,
                               -output_record_separator => "\r",
                               -telnetmode => 0,
                               -cmd_remove_mode => 1);
    $passwd->errmode("return");
    ## Send existing password.
    $passwd->waitfor('/password: ?$/i')
        or die "no old password prompt: ", $passwd->lastline;
    $passwd->print($oldpw);
    ## Send new password.
    $passwd->waitfor('/new (\w+\s)?password: ?$/i')
        or die "bad old password: ", $passwd->lastline;
    $passwd->print($newpw);
    ## Send new password verification.
    $passwd->waitfor('/new (\w+\s)?password: ?$/i')
        or die "bad new password: ", $passwd->lastline;
    $passwd->print($newpw);
    ## Display success or failure.
    $passwd->waitfor('/(changed|updated)/')
        or die "bad new password: ", $passwd->lastline;
    print $passwd->lastline;
    $passwd->close;
    exit;
} # end main program


        
The spawn() subroutine:

        
sub spawn {
    my (@cmd) = @_;
    my ($pid, $pty, $tty, $tty_fd);

    ## Create a new pseudo terminal.
    use IO::Pty ();
    $pty = new IO::Pty
        or die $!;
    ## Execute the program in another process.
    unless ($pid = fork) {  # child process
        die "problem spawning program: $!\n" unless defined $pid;
        ## Disassociate process from its controlling terminal.
        use POSIX ();
        POSIX::setsid()
            or die "setsid failed: $!";
        ## Associate process with a new controlling terminal.
        $pty->make_slave_controlling_terminal;
        $tty = $pty->slave;
        $tty_fd = $tty->fileno;
        close $pty;
        ## Make standard I/O use the new controlling terminal.
        open STDIN, "<&" . $tty_fd or die $!;
        open STDOUT, ">&" . $tty_fd or die $!;
        open STDERR, ">&STDOUT" or die $!;
        close $tty;
        ## Execute requested program.
        exec @cmd
            or die "problem executing $cmd[0]\n";
    } # end child process
    $pty;
} # end sub spawn


        
Here is an example that uses the openssh
            program to connect to a remote host. It uses the spawn()
            subroutine to start the ssh program and then read
            and write to it via a Net::Telnet object. This
            example turns off ssh host key checking, which reduces your ability to know
            when someone on the network is impersonating the remote host.

        
## Main program.
{
    my $host = "changeme";
    my $user = "changeme";
    my $passwd = "changeme";
    my $prompt = '/changeme\$ $/';
    my ($buf, $match, $pty, $ssh, @lines);
    ## Start ssh program.
    $pty = spawn("ssh",
                 "-l", $user,
                 "-e", "none",
                 "-F", "/dev/null",
                 "-o", "PreferredAuthentications=password",
                 "-o", "NumberOfPasswordPrompts=1",
                 "-o", "StrictHostKeyChecking=no",
                 "-o", "UserKnownHostsFile=/dev/null",
                 $host);
    ## Create a Net::Telnet object to perform I/O on ssh's tty.
    use Net::Telnet;
    $ssh = new Net::Telnet (-fhopen => $pty,
                            -prompt => $prompt,
                            -telnetmode => 0,
                            -output_record_separator => "\r",
                            -cmd_remove_mode => 1);
    ## Wait for the password prompt and send password.
    $ssh->waitfor(-match => '/password: ?$/i',
                  -errmode => "return")
        or die "problem connecting to \"$host\": ", $ssh->lastline;
    $ssh->print($passwd);
    ## Wait for the shell prompt.
    (undef, $match) = $ssh->waitfor(-match => $ssh->prompt,
                                    -match => '/^Permission denied/m',
                                    -errmode => "return")
        or return $ssh->error("login failed: expected shell prompt ",
                              "doesn't match actual\n");
    return $ssh->error("login failed: bad login-name or password\n")
        if $match =~ /^Permission denied/m;
    ## Run commands on remote host.
    print $ssh->cmd("hostname");
    print $ssh->cmd("uptime");
    $ssh->close;
    exit;
} # end main program


        
Some shells have a rather restrictive 255 character line limit. If
            you run into this problem, here is an example for sending lines longer than
            254 as a sequence of shorter lines.

        
## Main program.
{
    my $host = "changeme";
    my $user = "changeme";
    my $passwd = "changeme";
    my $prompt = '/changeme\$ $/';
    my $cmd = join("", "echo ",
                   "11111111112222222222333333333344444444445555555555",
                   "66666666667777777777888888888899999999990000000000",
                   "11111111112222222222333333333344444444445555555555",
                   "66666666667777777777888888888899999999990000000000",
                   "11111111112222222222333333333344444444445555555555",
                   "66666666667777777777888888888899999999990000000000");
    use Net::Telnet ();
    my $t = new Net::Telnet (-prompt => $prompt);
    $t->open($host);
    $t->login($user, $passwd);
    my @output = cmd_unixlong($t, $cmd);
    print @output;
    exit;
} # end main program
sub cmd_unixlong {
    my ($obj, $cmd) = @_;
    my ($line, $pos);
    my $max_tty_line = 254;
    ## Start a Bourne shell.
    $obj->cmd(-string => "/usr/bin/env " .
              "'PS1=<xPROMPTx> ' 'PS2=<xPROMPTx> ' /bin/sh -i",
              -prompt => '/<xPROMPTx> $/')
        or return;
    ## Break-up the one large command line and send as shorter lines.
    $pos = 0;
    while (1) {
        $line = substr $cmd, $pos, $max_tty_line;
        $pos += length $line;
        last unless $pos < length $cmd;
        ## Send the line with continuation char.
        $obj->cmd(-string => "$line\\",
                  -prompt => '/<xPROMPTx> $/')
            or return;
    }
    ## Send the last line and return the output.
    $obj->cmd("$line ; exit");
} # end sub cmd_unixlong
