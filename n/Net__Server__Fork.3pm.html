NOM

Net::Server::Fork - Personnalité de Net::Server

SYNOPIS

use base qw(Net::Server::Fork);
sub process_request {
    #...code...
}
__PACKAGE__->run();

DESCRIPTION

Veuillez lire d'abord le pod de Net::Server. Ce module est une personnalité, ou une extension, ou une sous-classe du module Net::Server.

Cette personnalité se lie à un ou plusieurs ports, puis attend la connexion d'un client. Lorsqu'une connexion est reçue, le serveur crée un processus fils (fork). Le fils traite la requête puis se ferme.

À l'exception de la signalisation parent/enfant, ce module fonctionnera (avec des fonctionnalités de base) sur les systèmes Win32.

ARGUMENTS

check_for_dead
Nombre de secondes à attendre avant de rechercher les processus fils inactifs. Ceci n'a lieu que si le nombre maximum de processus fils (max_servers) a été atteint. La valeur par défaut est de 60 secondes.
max_servers
Nombre maximum de processus fils à créer. Le serveur n'acceptera pas de connexions tant qu'il n'y aura pas de processus fils libres. La valeur par défaut est de 256 processus fils.
max_dequeue
Nombre maximum de processus de traitement en file d'attente à démarrer. Si une valeur de zéro ou undef est donnée, aucun processus de traitement en file d'attente ne sera démarré. Le nombre de processus de traitement en file d'attente en cours d'exécution sera vérifié par la variable check_for_dead.
check_for_dequeue
Secondes à attendre avant de créer un processus de traitement en file d'attente. Il est prévu d'utiliser le processus de traitement en file d'attente pour s'occuper d'éléments tels que les files d'attente de courrier. Si une valeur de undef est donnée, aucun processus de traitement en file d'attente ne sera démarré.

FICHIER DE CONFIGURATION

Voir Net::Server.

FLUX DE PROCESSUS

Le flux de processus suit Net::Server jusqu'à la phase post_accept. À ce stade, un processus fils est créé. Le processus parent est immédiatement prêt à attendre une autre requête. Le processus fils traite la requête puis se termine.

HOOKS

Le serveur Fork dispose des hooks suivants en plus des hooks fournis par la classe de base Net::Server. Voir Net::Server

"$self->pre_accept_hook()"
Ce hook se produit juste avant que l'appel à accept ne soit effectué.
"$self->post_accept_hook()"
Ce hook se produit dans le processus fils après l'appel à accept et le fork.
"$self->run_dequeue()"
Ce hook n'est appelé qu'en conjonction avec le réglage check_for_dequeue.

DÉPLOIEMENT À CHAUD

Depuis la version 2.000, le serveur Fork accepte les signaux TTIN et TTOU. Lorsqu'un signal TTIN est reçu, max_servers est augmenté de 1. Si un signal TTOU est reçu, max_servers est diminué de 1. Cela permet d'ajuster le nombre de processus de traitement sans avoir à redémarrer le serveur.
