NOM

Net::DNS::SEC::Validator - interface vers libval(3) et constantes, structures et fonctions associées

SYNTAXE

use Net::DNS::SEC::Validator;
use Net::DNS::Packet;
use Net::hostent;
use Net::addrinfo;
use Socket qw(:all);
sub callback {
}
my $validator = new Net::DNS::SEC::Validator(policy => ":");
$validator.map_ns("dnssec-tools.org", "127.0.0.1");
my (@r) = $validator->getaddrinfo("good-A.test.dnssec-tools.org");
my $r = $validator->res_query("dnssec-tools.org", "IN", "MX");
my $h = $validator->gethostbyname("good-AAAA.test.dnssec-tools.org",
                                  AF_INET6);
$validator->async_submit("badsign-a.test.dnssec-tools.org", 
      "IN", "A", 0, \&callback, undef);
do {
  my $ref = $val->async_gather($readfds, $timeout);
  my $ret = $ref->[0];
  my $readfds = $ref->[1];
  my $timeout = $ref->[2];
  if (! @$readfds) {
      last;
  }
  my @readyarr = IO::Select->new(@$readfds)->can_read($timeout);
  $ret = $validator->async_check(\@readyarr);
} while(1);

DESCRIPTION

Le module Validator fournit un accès à la bibliothèque de résolution validante libval(3), ainsi qu'aux constantes, structures et fonctions associées. Les fonctions de la bibliothèque sont accessibles via une interface orientée objet. L'interface est conçue pour masquer une partie de la complexité des résolveurs de validation. Le comportement de l'interface applicative peut être personnalisé via des fichiers de configuration fournis par libval, et des codes d'erreur détaillés sont retournés.

Comme Validator est une passerelle vers libval, la documentation de libval fournira des détails supplémentaires sur la manière dont les interfaces et les paramètres de Validator peuvent être utilisés.

Des détails sur DNSSEC et le comportement des résolveurs associés peuvent être trouvés dans les RFC DNSSEC principaux (4033-4035).

INTERFACE

Ce module prend en charge les recherches synchrones et asynchrones. Une description de l'API suit.

Constructeur Validator

Ce constructeur crée un nouvel objet validateur, utilisé pour effectuer les différents appels de résolution. Lors de la création de l'objet validateur, un objet policy est créé. L'objet policy fournit un certain nombre de paramètres qui contrôleront divers aspects de la résolution DNS.

Pour créer un objet validateur, utilisez la méthode Net::DNS::SEC::Validator-new()>. Cette méthode accepte un certain nombre de paramètres optionnels, qui seront décrits ci-dessous.

Un objet policy peut être nommé avec le paramètre policy, qui associe une étiquette à une policy particulière. Cela permet de référencer cette policy ultérieurement. Si l'étiquette n'est pas spécifiée, elle recevra l'étiquette par défaut du fichier dnsval.conf de libval.

Les paramètres du constructeur sont passés sous forme de hachage, la clé et la valeur étant données dans l'appel. Outre l'étiquette de policy, il existe deux ensembles de paramètres de constructeur. Ceux-ci sont séparés en fonction de la manière dont ils sont stockés et utilisés dans libval.

Options de Contexte

Ce groupe de paramètres est stocké dans une structure val_context_opt dans libval. Cette structure est définie dans dnssec/validator/include/validator/validator.h. Les options de contexte ci-dessous sont les valeurs de clé de hachage utilisées dans l'appel du constructeur.

dnsval_conf
Politique de configuration pour la bibliothèque libval.

Ce fichier contient la politique du validateur. La valeur par défaut est /usr/local/etc/dnssec-tools/dnsval.conf, mais cela peut avoir été modifié lors de la construction et de l'installation de libval.

Champ val_context_opt : vc_val_conf

nslist
Ceci est une liste de serveurs de noms qui devraient être utilisés pour la résolution des noms. Il doit s'agir d'une liste d'adresses IP ou IPv6 délimitées par des espaces blancs.

Champ val_context_opt : vc_nslist

polflags
Il s'agit d'un ensemble de drapeaux de politique bitmap. Les drapeaux valides sont définis dans dnssec/validator/include/validator/validator.h. La valeur par défaut est CTX_DYN_POL_RES_OVR.

Champ val_context_opt : vc_polflags

qflags
Ceci est l'ensemble des drapeaux de requête par défaut. Les drapeaux valides sont définis dans dnssec/validator/include/validator/validator.h. La valeur par défaut est 0.

Champ val_context_opt : vc_qflags

resolv_conf
Ce fichier contient les options de noms de serveur et de recherche pour la bibliothèque libval. La valeur par défaut est /usr/local/etc/dnssec-tools/resolv.conf, mais cela peut avoir été modifié lors de la construction et de l'installation de libval.

Champ val_context_opt : vc_res_conf

root_hints
Ce fichier contient des informations d'amorçage pour le résolveur de noms. La valeur par défaut est /usr/local/etc/dnssec-tools/root.hints, mais cela peut avoir été modifié lors de la construction et de l'installation de libval.

Champ val_context_opt : vc_root_conf

valpol
Ceci fournit un élément personnalisé de configuration du validateur à la configuration du validateur par défaut en tant qu'extension ou remplacement. Ceci est nul par défaut.

Champ val_context_opt : vc_valpol

Options Globales

Ce groupe de paramètres est stocké dans une structure val_global_opt, qui est elle-même stockée dans le champ gopt de la structure val_context_opt. Cette structure est définie dans dnssec/validator/include/validator/validator.h. Les options globales ci-dessous sont les valeurs de clé de hachage utilisées dans l'appel du constructeur.

Pour tous les champs sauf log_target, une valeur de -1 indique une condition "ignorer". Cela signifie que le validateur n'inclura pas les options globales fournies dynamiquement avec une valeur de -1 lors de la création de son contexte. Cela permet à une application de remplacer un sous-ensemble d'options globales tout en utilisant les options globales fournies par défaut dans le fichier dnsval.conf.

Même si libval utilise les options globales dans une structure séparée des options de contexte, elles sont toutes spécifiées dans le même hachage lorsqu'elles sont passées en paramètres au constructeur Validator.

app_policy
Ce champ est équivalent à l'option env-policy dans un fichier dnsval.conf. Les valeurs suivantes sont légales et leurs équivalences env-policy : 
VAL_POL_GOPT_DISABLE       "disable"
VAL_POL_GOPT_ENABLE        "enable"
VAL_POL_GOPT_OVERRIDE      "override"

La valeur par défaut est -1.

Champ val_global_opt : gopt.app_policy

closest_ta_only
Ce champ est équivalent à l'option closest-ta-only dans un fichier dnsval.conf. Le régler à 1 est équivalent à régler closest-ta-only à "yes" ; le régler à 0 est équivalent à "no". La valeur par défaut est -1.

Champ val_global_opt : gopt.closest_ta_only

edns0_size
Ce champ est équivalent à l'option edns0-size dans un fichier dnsval.conf. La valeur par défaut est -1.

Champ val_global_opt : gopt.edns0_size

env_policy
Ce champ est équivalent à l'option env-policy dans un fichier dnsval.conf. Les valeurs suivantes sont légales et leurs équivalences env-policy : 
VAL_POL_GOPT_DISABLE       "disable"
VAL_POL_GOPT_ENABLE        "enable"
VAL_POL_GOPT_OVERRIDE      "override"

La valeur par défaut est -1.

Champ val_global_opt : gopt.env_policy

local_is_trusted
Ce champ est équivalent à l'option trust-oob-answers dans un fichier dnsval.conf. Le régler à 1 est équivalent

Champs de résultat du validateur

L'état des opérations et les résultats se trouvent dans les champs de résultat du validateur suivants :

$validator->{error}        => le code d'erreur du dernier appel
$validator->{errorStr}     => la chaîne d'erreur du dernier appel
$validator->{valStatus}    => le val_status du dernier appel (si c'est un appel unique)
$validator->{valStatusStr} => la chaîne val_status du dernier appel

Les valeurs de ces champs sont décrites dans la section suivante.

$validator->getaddrinfo(<name>[,<service>[,<hints>]])

où :

<name> => est le nom du nœud ou l'adresse numérique en cours de requête
<service> => est le nom ou le numéro représentant le service
(note : <name> ou <service> peut être indéfini, mais pas les deux)
<hint> => un objet Net::addrinfo spécifiant les flags, la famille, etc.

retourne :

Un tableau d'objets Net::addrinfo (avec un champ 'val_status') en cas de succès. En cas d'erreur, retourne un tableau vide. En contexte scalaire, retourne le premier objet Net::addrinfo, ou undef en cas d'erreur.

$validator->gethostbyname(<name>[,<family>])

où :

<name> => est le nom du nœud ou l'adresse numérique en cours de requête
<family> => la famille d'adresse de l'enregistrement retourné (par défaut : AF_INET)

retourne :

Un objet Net::hostent. Les champs valStatus/valStatusStr du validateur seront mis à jour. En cas d'erreur, undef est retourné et les champs de l'objet validateur sont mis à jour.

$validator->res_query(<name>[,<class>[,<type>]])

où :

<name>      => est le nom du nœud ou l'adresse numérique en cours de requête
<class>     => est la classe DNS de l'enregistrement en cours de requête (par défaut : IN)
<type>      => est le type d'enregistrement DNS en cours de requête (par défaut : A)

retourne :

Un résultat de requête DNS packagé est retourné en cas de succès. Cet objet est approprié pour être passé à l'interface Net::DNS::Packet(\$result) pour analyse. Les champs valStatus/valStatusStr du validateur seront mis à jour. En cas d'erreur, undef est retourné et les champs de l'objet validateur sont mis à jour.

$validator->policy([<label>])

où :

<label>     => l'étiquette de politique à utiliser (le contexte précédent est détruit)
(par défaut : ": " la politique par défaut de dnsval.conf)

retourne :

L'étiquette de politique actuelle (après changement).

$validator->istrusted([<val_status>])

où :

<val_status> => le code numérique de l'état du validateur
(par défaut : $validator->{valStatus})

retourne :

Une valeur booléenne positive si <val_status> est un résultat de confiance.

$validator->valStatusStr([<val_status>])

où :

<val_status> => le code numérique de l'état du validateur
(par défaut : $validator->{valStatus})

retourne :

Une représentation textuelle de la valeur <val_status> donnée.

$validator->map_ns(<zone>, <ipaddr>, <recursive>)

où :

<zone> => la valeur de la zone
<ipaddr> => l'adresse IP à laquelle toutes les requêtes associées à la zone précédente doivent être adressées.
<recursive> => si défini sur 1, ce serveur de noms est considéré comme récursif (les requêtes avec le bit RD défini sont envoyées). La valeur par défaut est de considérer ce serveur de noms comme autoritaire.

retourne :

0 si l'association entre la zone et l'adresse IP peut être faite avec succès ; une autre valeur si l'association ne peut pas être créée.

CHAMP_DONNÉES_VALIDATEUR

Les champs error et errorStr du validateur sont définis avec des valeurs correspondant à celles des fonctions standard herror() et hstrerror() de netdb.h. Ces valeurs sont définies dans netdb.h. Ces valeurs sont :

error      errorStr
  0        Resolver Error 0 (pas d'erreur)
  1        Hôte introuvable
  2        Erreur de recherche de nom d'hôte
  3        Erreur de serveur
  4        Aucune adresse associée au nom

Les valeurs du champ valStatus du validateur sont définies dans .../dnssec-tools/validator/include/validator/val_errors.h. Les valeurs des champs valStatusStr sont représentées textuellement comme les valeurs des constantes valStatus. Les valeurs possibles pour valStatus sont indiquées ci-dessous, et plus de détails se trouvent dans libval(3) :

VAL_BARE_RRSIG
VAL_INDETERMINATE
VAL_BOGUS
VAL_DNS_ERROR
VAL_IGNORE_VALIDATION
VAL_NONEXISTENT_NAME
VAL_NONEXISTENT_NAME_NOCHAIN
VAL_NONEXISTENT_TYPE
VAL_NONEXISTENT_TYPE_NOCHAIN
VAL_NOTRUST
VAL_OOB_ANSWER
VAL_PINSECURE
VAL_PINSECURE_UNTRUSTED
VAL_SUCCESS
VAL_TRUSTED_ANSWER
VAL_UNTRUSTED_ANSWER
VAL_UNTRUSTED_ZONE
VAL_VALIDATED_ANSWER

Les fonctions istrusted() et isvalidated() peuvent être utilisées pour tester si une valeur particulière de valStatus correspond à un état de confiance ou à un état validé. Les valeurs qui ne sont ni de confiance ni validées doivent être traitées comme non fiables par l'application.

EXEMPLES

  use Net::DNS::SEC::Validator;
  use Net::DNS::Packet;
  use Net::hostent;
  use Net::addrinfo;
  use Socket qw(:all);

  # construire l'objet
  my $validator = new Net::DNS::SEC::Validator(policy => ":");

  # changer la politique de validation
  $validator->policy("validate_tools:");

  # obtenir un tableau de Net::addrinfo
  my (@r) = $validator->getaddrinfo("good-A.test.dnssec-tools.org");
  foreach $a (@r) {
     print $a->stringify, " est digne de confiance\n"
        if $validator->istrusted($a->val_status));
  }

  # interroger un enregistrement MX
  my $r = $validator->res_query("dnssec-tools.org", "IN", "MX");
  my ($pkt, $err) = new Net::DNS::Packet(\$r);
  print ($validator->istrusted ?
        "le résultat est digne de confiance\n" :
        "le résultat N'EST PAS digne de confiance\n");

  my $h = $validator->gethostbyname("good-A.test.dnssec-tools.org");
  if ( @{$h->addr_list}) {
  my $i;
     for $addr ( @{$h->addr_list} ) {
        printf "\tadresse #%d est [%s]\n", $i++, inet_ntoa($addr);
     }
  }
  # obtenir les détails de validation
  my $a = $validator->resolve_and_check("good-a.test.dnssec-tools.org", "IN", "A", 0);
  foreach my $h (@$a) {
   print "Statut : " .  ${$h}{status} . "\n";
   print ($validator->istrusted(${$h}{status}) ?
           "le résultat est digne de confiance\n" :
           "le résultat N'EST PAS digne de confiance\n");
   $acs = ${$h}{answer};
   foreach my $ac ($acs) {
        print "Statut AC : " . ${$ac}{status} . "\n";
        $acr = ${$ac}{rrset};
        $acd = ${$acr}{data};
        foreach $d (@$acd) {
            print "Statut RR données : " . ${$d}{rrstatus} . "\n";
            ${$d}{rrdata}->print;
        }
        $acs = ${$acr}{sigs};
        foreach $d (@$acs) {
            print "Statut RR Sig : " . ${$d}{rrstatus} . "\n";
            ${$d}{rrdata}->print;
        }
   }
}
