Net::LDAP::FilterMatch(3) Documentation Perl fournie par l'utilisateur Net::LDAP::FilterMatch(3)

NOM

Net::LDAP::FilterMatch - Correspondance d'entrées LDAP

SYNOPIS

use Net::LDAP::Entry;
use Net::LDAP::Filter;
use Net::LDAP::FilterMatch;
my $entry = new Net::LDAP::Entry;
$entry->dn("cn=dummy entry");
$entry->add (
 'cn' => 'dummy entry',
 'street' => [ '1 some road','nowhere' ] );
my @filters = (qw/(cn=dummy*)
               (ou=*)
               (&(cn=dummy*)(street=*road))
               (&(cn=dummy*)(!(street=nowhere)))/);
for (@filters) {
  my $filter = Net::LDAP::Filter->new($_);
  print $_,' : ', $filter->match($entry) ? 'match' : 'no match' ,"\n";
}

ABSTRAIT

Cette extension de la classe Net::LDAP::Filter fournit des fonctionnalités de correspondance d'entrées côté Perl.

Étant donné une entrée, elle indiquera si l'entrée correspond à l'objet filtre.

Elle peut être utilisée seule ou dans le cadre d'un serveur LDAP basé sur Net::LDAP::Server.

MÉTHODE

match ( ENTRY [ ,SCHEMA ] )
Retourne si ENTRY correspond à l'objet filtre. Si un objet schéma est fourni, la sélection des algorithmes de correspondance sera dérivée du schéma.

En cas d'erreur, undef est retourné.

Pour les correspondances approximatives telles que (cn~=Schmidt), plusieurs modules peuvent être utilisés. Par défaut, les modules suivants seront essayés dans cet ordre :

String::Approx
Text::Metaphone
Text::Soundex

Si aucun de ces modules n'est trouvé, il se rabattra sur un simple algorithme d'expression régulière.

Si vous souhaitez spécifiquement utiliser une seule implémentation, faites simplement

use Net::LDAP::FilterMatch qw(Text::Soundex);
