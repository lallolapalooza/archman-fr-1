NOM

Net::DNS::SEC::Tools::tooloptions - Routines d'options DNSSEC-Tools.

SYNOPIS

use Net::DNS::SEC::Tools::tooloptions;
@specopts = ("propagate+", "waittime=i");
%opts = opts_cmdline($restoreargv,@calleropts);
$optsref = opts_cmdopts(@specopts);
%options = %$optsref;
$zoneref = opts_zonekr($keyrec_file,$keyrec_name,@specopts);
%zone_kr = %$zoneref;
opts_setcsopts(@specopts);
opts_createkrf();
opts_suspend();
opts_restore();
opts_drop();
opts_reset();
opts_gui();
opts_nogui();
$oldaction = opts_onerr(1);
opts_onerr(0);

DESCRIPTION

DNSSEC-Tools prend en charge un ensemble d'options communes à tous les outils de la suite. Ces options peuvent être définies à partir des valeurs par défaut de DNSSEC-Tools, des valeurs définies dans le fichier de configuration dnssec-tools.conf, dans un fichier keyrec, à partir des options spécifiques à la commande, à partir des options de la ligne de commande, ou de toute combinaison de ces cinq sources. Afin d'appliquer une séquence commune d'interprétation des options, tous les outils DNSSEC-Tools devraient utiliser les routines tooloptions.pm pour initialiser leurs options.

Les routines tooloptions.pm combinent les données provenant des sources d'options mentionnées ci-dessus dans une table de hachage. La table de hachage est retournée à l'appelant, qui utilisera ensuite les options selon les besoins.

Les options de la ligne de commande sont sauvegardées entre les appels, de sorte qu'une commande puisse appeler les routines tooloptions.pm plusieurs fois tout en incluant les options de la ligne de commande dans la table de hachage finale. Ceci est utile pour examiner plusieurs keyrec dans une seule commande. L'inclusion des options de la ligne de commande peut être suspendue et restaurée en utilisant les appels opts_suspend() et opts_restore(). Les options peuvent être supprimées entièrement en appelant opts_drop() ; une fois supprimées, les options de la ligne de commande ne pourront plus jamais être restaurées. La suspension, la restauration et la suppression des options de la ligne de commande ne sont effectives qu'après l'appel initial à tooloptions.pm.

Les sources d'options sont combinées dans cet ordre :

1. Valeurs par défaut de DNSSEC-Tools
Les valeurs par défaut de DNSSEC-Tools, telles que définies dans conf.pm, sont placées dans une table de hachage, les noms d'options servant de clé de hachage.
2. Fichier de configuration DNSSEC-Tools
Le fichier de configuration système de DNSSEC-Tools est lu et ces valeurs d'options sont ajoutées à la collection d'options. Là encore, les noms d'options sont utilisés comme clés de hachage.
3. Fichier keyrec
Si un fichier keyrec a été spécifié, alors le keyrec nommé par keyrec_name sera récupéré. Les champs du keyrec sont ajoutés à la table de hachage. Tout champ dont le mot-clé correspond à une clé de hachage existante remplacera les valeurs existantes.
4. Options spécifiques à la commande
Les options spécifiques aux commandes appelantes peuvent être spécifiées dans @specopts. Ce tableau est analysé par Getoptions() du module Perl Getopt::Long. Ces options sont fusionnées dans la table de hachage ; remplaçant éventuellement les valeurs de hachage existantes. Les options fournies dans @specopts doivent être dans le format requis par Getoptions().
5. Options de la ligne de commande
Les options de la ligne de commande sont analysées à l'aide de Getoptions() du module Perl Getopt::Long. Ces options sont fusionnées dans la table de hachage ; remplaçant à nouveau éventuellement les valeurs de hachage existantes. Les options fournies dans @specopts doivent être dans le format requis par Getoptions() .

Une référence à la table de hachage créée lors de ces étapes est retournée à l'appelant.

EXEMPLE

dnssec-tools.conf contient ces entrées :

ksklength      2048
zsklength      1024

example.keyrec contient cette entrée :

key         "Kexample.com.+005+12345"
        zsklength        "2048"

zonesigner est exécuté avec cette ligne de commande :

zonesigner -zsklength 4096 -wait 3600 ...  example.com

opts_zonekr("example.keyrec","Kexample.com.+005+12345",("wait=i")) lira chaque source d'options tour à tour, pour finir avec :
ksklength 1024
zsklength 4096
wait 600

INTERFACES TOOLOPTIONS

opts_cmdline($restoreargv,@calleropts)
Cette routine analyse une ligne de commande à la recherche des arguments dans l'ensemble standard d'options et un ensemble optionnel d'options spécifiées par l'appelant. Si le premier argument est vrai, le programme global @ARGV est restauré après l'analyse. Si l'appelant fournit d'autres arguments, ils sont ajoutés en tant qu'options supplémentaires. Les options analysées sont retournées à l'appelant dans une table de hachage.
opts_cmdopts(@csopts)
L'appel opts_cmdopts() construit une table de hachage d'options à partir du fichier de configuration système, d'un keyrec, et d'un ensemble d'options spécifiques à la commande. Une référence à cette table de hachage d'options est retournée à l'appelant.

Si $keyrec_file est donné comme une chaîne vide, alors aucun fichier keyrec ne sera consulté. Dans ce cas, il est supposé que $keyrec_name sera omis entièrement.

Si un fichier $keyrec_file inexistant est donné et que opts_createkrf() a été appelé, alors le fichier keyrec nommé sera créé. opts_createkrf() doit être appelé pour chaque fichier keyrec qui doit être créé, car l'état de création de keyrec de tooloptions est réinitialisé une fois que tooloptions() est terminé.

opts_zonekr($keyrec_file,$keyrec_name,@csopts)
Cette routine retourne une référence aux options collectées à partir des sources d'options de base et du keyrec de zone nommé par $keyrec_name, qui se trouve dans $keyrec_file. Les champs keyrec du KSK et du ZSK de la zone sont également intégrés, mais les champs keyrec_ de la clé sont exclus. Cet appel garantit que le keyrec nommé est un keyrec de zone ; s'il ne l'est pas, undef est retourné.

Le fichier keyrec est lu avec keyrec_read(). Pour s'assurer qu'il est correctement lu, keyrec_close() est appelé d'abord.

L'argument $keyrec_file spécifie un fichier keyrec qui sera consulté. Le keyrec nommé par l'argument $keyrec_name sera chargé. Si un fichier keyrec est trouvé et que opts_createkrf() a été appelé précédemment, alors le fichier keyrec sera créé s'il n'existe pas.

Si $keyrec_file est donné comme "", alors la ligne de commande recherche une option -krfile. Si $keyrec_name est donné comme "", alors le nom est pris de $ARGV[0].

Le tableau @specopts contient les arguments spécifiques à la commande ; les arguments doivent être dans le format prescrit par le module Perl Getopt::Long.

Si la ligne de commande contient l'option -dtconfig, alors opts_zonekr() définit cette option comme étant le fichier de configuration. Il analyse ensuite ce fichier et l'utilise comme source des données du fichier de configuration.

opts_setcsopts(@csopts)
Cette routine sauvegarde une copie des options spécifiques à la commande fournies dans @csopts. Cette collection d'options est ajoutée au tableau @csopts qui peut être passé aux routines tooloptions.pm.
opts_createkrf()
Cette routine indique que les fichiers keyrec spécifiés sur la ligne de commande doivent être créés s'ils n'existent pas. Cela n'a d'effet que si la commande est appelée avec l'option -krfile. L'état de création des fichiers keyrec est réinitialisé à la fin de l'appel à tooloptions().
opts_suspend()
Suspend la prise en compte des options de la ligne de commande. Les appels ultérieurs aux routines tooloptions n'incluront pas les options de la ligne de commande, jusqu'à ce que opts_restore() soit appelé.
opts_restore()
Restaure la prise en compte des options de la ligne de commande qui avait été suspendue par un appel précédent à opts_suspend().
opts_drop()
Supprime définitivement la prise en compte des options de la ligne de commande. Les appels ultérieurs aux routines tooloptions n'incluront pas les options de la ligne de commande, et elles ne pourront plus jamais être restaurées.
opts_reset()
Réinitialise toutes les options à leurs valeurs par défaut. Cela inclut la suppression des options de la ligne de commande, du fichier de configuration, des fichiers keyrec, et des options spécifiques à la commande. Les appels ultérieurs à tooloptions commenceront à partir de zéro.
opts_gui()
Définit un indicateur interne pour signaler que l'interface graphique est utilisée. Ceci est utile pour les outils qui peuvent avoir des comportements différents en fonction de l'interface.
opts_nogui()
Définit un indicateur interne pour signaler que l'interface graphique n'est pas utilisée. Ceci est utile pour les outils qui peuvent avoir des comportements différents en fonction de l'interface.
opts_onerr($action)
Contrôle la manière dont les erreurs sont gérées. Si $action est vrai, une erreur entraînera la sortie du programme. Si $action est faux, une erreur retournera simplement la valeur d'erreur à l'appelant. La valeur précédente de l'action d'erreur est retournée. Par défaut, les erreurs entraînent la sortie.

NOM
NOM
opts_zonekr()
Forcera la création d'un fichier keyrec vide si le fichier spécifié n'existe pas. Cela peut se produire lors d'appels à opts_zonekr().
opts_suspend()
Arrête l'inclusion des options de la ligne de commande dans la table de réponses finale.
opts_restore()
Restaure l'inclusion des options de la ligne de commande dans la table de réponses finale.
opts_drop()
Supprime les options de la ligne de commande. Celles-ci ne seront pas disponibles pour la construction de la table de réponses finale pour cette exécution de commandes.
opts_reset()
Réinitialise un indicateur interne afin que les options de la ligne de commande puissent être réexaminées. Ceci est généralement utile si les options ont été modifiées par le programme appelant.
opts_gui()
Définit un indicateur interne pour que les arguments de commande puissent être spécifiés via une interface graphique. L'utilisation d'une interface graphique nécessite que Getopt::GUI::Long soit disponible. Sinon, Getopt::Long sera utilisé.
opts_nogui()
Définit un indicateur interne pour que l'interface graphique ne soit pas utilisée pour spécifier les arguments de commande.
opts_onerr(exitflag)
Définit un indicateur interne indiquant ce qui doit être fait si une option invalide est spécifiée sur la ligne de commande. Si la valeur de exitflag est non nulle, le processus se terminera en cas d'option invalide ; si elle est nulle, le processus ne se terminera pas. Le comportement par défaut est d'informer d'une erreur sans quitter.

Le comportement précédent est renvoyé.
