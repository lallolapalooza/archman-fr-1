Net::LDAP::Entry(3) Documentation Perl fournie par l'utilisateur Net::LDAP::Entry(3)

NOM

Net::LDAP::Entry - Un objet d'entrée LDAP

SYNOPSIS

use Net::LDAP;
$ldap = Net::LDAP->new ( $host );
$mesg = $ldap->search ( @search_args );
my $max = $mesg->count;
for ( $i = 0 ; $i < $max ; $i++ ) {
  my $entry = $mesg->entry ( $i );
  foreach my $attr ( $entry->attributes ) {
    print join( "\n ", $attr, $entry->get_value( $attr ) ), "\n";
  }
}
# ou
use Net::LDAP::Entry;
$entry = Net::LDAP::Entry->new;
$entry->dn($dn);
$entry->add (
  attr1 => 'valeur1',
  attr2 => [ qw(valeur1 valeur2) ]
);
$entry->delete ( 'non-souhaité' );
$entry->replace (
  attr1 => 'nouvelle valeur',
  attr2 => [ qw(nouvelles valeurs) ]
);
$entry->update ( $ldap ); # mettre à jour le serveur d'annuaire
$entry2 = $entry->clone; # copie l'entrée
# nouvelle syntaxe alternative
$entry = Net::LDAP::Entry->new ( $dn,
  attr1 => 'valeur1',
  attr2 => [ qw(valeur1 valeur2) ]
)->add(
  attr3   => 'valeur'
)->update( $ldap );

DESCRIPTION

L'objet Net::LDAP::Entry représente une seule entrée dans l'annuaire. C'est un conteneur pour des paires attribut-valeur.

Un objet Net::LDAP::Entry peut être utilisé dans deux situations. La première et probablement l'utilisation la plus courante est dans le résultat d'une recherche sur le serveur d'annuaire.

L'autre situation est lorsqu'un nouvel objet est créé localement, puis qu'une seule commande est envoyée au serveur d'annuaire pour ajouter, modifier ou remplacer une entrée. Les entrées à cet effet peuvent également être créées en lisant un fichier LDIF avec le module Net::LDAP::LDIF.

CONSTRUCTEURS

new ( )
Crée un nouvel objet d'entrée avec le type de modification défini sur 'add'. Optionnellement, vous pouvez fournir un DN et une liste d'arguments passés à la méthode add. 
Net::LDAP::Entry->new()
# ou
Net::LDAP::Entry->new( $dn )
# ou
Net::LDAP::Entry->new( $dn ,
 objectClass => [ qw( top posixAccount )] , uid => 'admin'
)
clone ( )
Retourne une copie de l'objet Net::LDAP::Entry.

MÉTHODES

add ( ATTR => VALEUR, ... )
Ajoute plus d'attributs ou de valeurs à l'entrée et retourne l'entrée elle-même. Chaque "VALEUR" doit être une chaîne si une seule valeur est souhaitée pour l'attribut, ou une référence à un tableau de chaînes si plusieurs valeurs sont souhaitées. Les valeurs fournies seront ajoutées aux valeurs existantes pour les attributs donnés. 
$entry->add ( 'sn' => 'Barr' );
$entry->add ( 'street' => [ '1 some road','nowhere' ] );

NOTE : ces modifications sont locales au client et n'apparaîtront pas sur le serveur d'annuaire tant que la méthode "update" n'est pas appelée. Comme "add" retourne l'entrée, vous pouvez écrire quelque chose comme.

$entry->add ( 'sn' => 'Barr' )->update( $ldap );
attributes ( OPTIONS )
Retourne une liste d'attributs dans cette entrée
nooptions => 1
Retourne une liste des noms d'attributs sans aucune option. Par exemple, pour l'entrée 
name: Graham Barr
name;en-us: Bob
jpegPhoto;binary: **données binaires**

alors

@values = $entry->attributes;
print "défaut: @values\n";
@values = $entry->attributes ( nooptions => 1 );
print "sans options: @values\n";

affichera

défaut: name name;en-us jpegPhoto;binary
sans options: name jpegPhoto
changetype ( )
Retourne le type d'opération qui serait effectué lors de l'appel de la méthode update.
changetype ( TYPE )
Définit le type d'opération qui sera effectué lors de l'appel de la méthode update à "TYPE". Retourne l'entrée elle-même.

Les valeurs possibles pour "TYPE" sont

add
La méthode update appellera la méthode add sur l'objet client, ce qui entraînera l'ajout de l'entrée au serveur d'annuaire.
delete
La méthode update appellera la méthode delete sur l'objet client, ce qui entraînera la suppression de l'entrée du serveur d'annuaire. 
$entry->delete->update( $ldap )
modify
La méthode update appellera la méthode modify sur l'objet client, ce qui entraînera la prise en compte de toute modification apportée localement à l'entrée sur le serveur d'annuaire.
moddn/modrdn
La méthode update appellera la méthode moddn sur l'objet client, ce qui entraînera la prise en compte de toute modification de DN apportée localement à l'entrée sur le serveur d'annuaire. Ces modifications de DN sont spécifiées en définissant les attributs de l'entrée newrdn, deleteoldrdn et (optionnellement) newsupérieur.
delete ( )
Supprime l'entrée du serveur lors du prochain appel à "update".
delete ( ATTR => [ VALEUR, ... ], ... )
Supprime les valeurs des attributs donnés de l'entrée. Les valeurs sont des références à des tableaux ; passer une référence à un tableau vide équivaut à passer "undef", et entraînera la suppression de l'attribut entier. Par exemple : 
$entry->delete ( 'mail' => [ 'foo.bar@example.com' ] );
$entry->delete ( 'description' => [ ], 'streetAddress' => [ ] );

NOTE : ces modifications sont locales au client et n'apparaîtront pas sur le serveur d'annuaire tant que la méthode "update" n'est pas appelée.

dn ( )
Obtient le DN de l'entrée.
dn ( DN )
Définit le DN de l'entrée et retourne la valeur précédente.

NOTE : ces modifications sont locales au client et n'apparaîtront pas sur le serveur d'annuaire tant que la méthode "update" n'est pas appelée.

ldif ( OPTION => VALEUR, ... )
Retourne l'entrée sous forme de chaîne LDIF. Les options possibles sont toutes les options que "new" dans Net::LDAP::LDIF autorise, avec deux traitées spécialement :
change => VALEUR
Si une valeur vraie est donnée, alors le LDIF sera généré comme un enregistrement de modification. Si c'est faux, alors le LDIF généré représentera le contenu de l'entrée. Si non spécifié, il sera par défaut vrai si l'entrée a des modifications et faux si aucune modification n'a été appliquée à l'entrée.
version => VALEUR
Quelle que soit la valeur passée, elle sera ignorée et traitée comme si 0 avait été donné.
dump ( [ FILEHANDLE ] )
Dump l'entrée dans le handle de fichier donné.

Cette méthode est destinée à des fins de débogage et ne traite pas spécialement les attributs binaires. Elle ne gère pas non plus correctement les entrées résultant des enregistrements de modification LDIF.

Voir Net::LDAP::LDIF pour savoir comment générer une sortie LDIF.

Si "FILEHANDLE" est omis, "STDOUT" est utilisé par défaut.

exists ( ATTR )
Retourne "TRUE" si l'entrée a un attribut nommé "ATTR".
get_value ( ATTR, OPTIONS )
Obtient les valeurs pour l'attribut "ATTR". Dans un contexte de liste, retourne toutes les valeurs pour l'attribut donné, ou la liste vide si l'attribut n'existe pas. Dans un contexte scalaire, retourne la première valeur pour l'attribut ou undef

NOM

Net::LDAP::Entry - Gérer une entrée d'annuaire LDAP

SYNOPSIS

  use Net::LDAP;

  my $ldap  = Net::LDAP->new ( 'ldap.example.com' ) or die;
  my $mesg  = $ldap->search (
    base   => 'o=Example,c=Com',
    filter => 'inetMailAddress=test@example.com',
  );

  my @entries = $mesg->entries;

  foreach my $entry (@entries) {
    # ...
    my $name = $entry->get_value('name');
    # ...
  }

  $ldap->unbind;

DESCRIPTION

Cet objet représente une seule entrée d'annuaire LDAP. Il peut être utilisé pour ajouter, modifier et supprimer des attributs pour cette entrée.

Il est retourné par les méthodes entries des objets Net::LDAP::Message.

CONSTRUCTEURS

Aucun constructeur public n'est exposé pour cet objet. Il est instancié par les méthodes de recherche de Net::LDAP.

MÉTHODES

add ( ATTR => VALUE, ... )
Ajoute des valeurs à un attribut. Si l'attribut n'existe pas, il est créé. Les valeurs fournies sont ajoutées aux valeurs existantes pour cet attribut.
all_attributes
Retourne une liste de tous les noms d'attributs dans l'entrée.
delete ( ATTR )
Supprime un attribut et toutes ses valeurs de l'entrée.
delete_value ( ATTR => VALUE )
Supprime une valeur spécifique d'un attribut. Si la valeur spécifiée n'existe pas pour l'attribut donné, rien ne se passe.
dn
Retourne le DN (Distinguished Name) de l'entrée sous forme de chaîne.
get_value ( NAME [, OPTIONS ] )
Retourne la valeur (ou les valeurs) d'un attribut. Si plusieurs valeurs existent pour l'attribut, la première valeur est retournée par défaut. Si l'attribut n'existe pas, "undef" est retourné.

Les OPTIONS suivantes sont reconnues.

alloptions => 1
Le résultat sera une référence de hachage. Les clés du hachage seront les options et la valeur du hachage seront les valeurs pour ces attributs. Par exemple, si une entrée contenait :
name: Graham Barr
name;en-us: Bob

Alors une récupération de l'attribut « name » avec alloptions défini à une valeur vraie

$ref = $entry->get_value ( 'name', alloptions => 1 );

retournera une référence de hachage qui ressemblerait à

{
  ''       => [ 'Graham Barr' ],
  ';en-us' => [ 'Bob' ]
}

Si alloptions n'est pas défini ou est défini à faux, seules les valeurs d'attributs pour le nom correspondant exactement sont retournées.

nooptions => 1
Au lieu de retourner uniquement les valeurs du nom d'attribut correspondant exactement, récupère les valeurs d'attribut de tous les attributs ayant le nom de base donné. C'est-à-dire, dans l'exemple ci-dessus, l'appel
@array = $entry->get_value ( 'name', nooptions => 1 );

donnera

( 'Graham Barr', 'Bob' )

Le nom de cette option a été choisi pour la cohérence avec l'option de même nom dans la méthode attributes.

asref => 1
Le résultat sera une référence à un tableau contenant toutes les valeurs pour l'attribut, ou "undef" si l'attribut n'existe pas. 
$scalar = $entry->get_value ( 'name' );

$scalar sera la première valeur pour l'attribut « name », ou "undef" si l'entrée ne contient pas d'attribut « name ».

$ref = $entry->get_value ( 'name', asref => 1 );

$ref sera une référence à un tableau, qui contiendra toutes les valeurs pour l'attribut « name ». Si l'entrée n'a pas d'attribut appelé « name », alors $ref sera "undef".

NOTE : Dans un souci de performance, les références de tableaux retournées par "get_value" peuvent être des références à des structures contenues dans l'objet entrée. Ces valeurs et leur contenu ne doivent PAS être modifiés directement.

replace ( ATTR => VALUE, ... )
Similaire à "add", sauf que les valeurs fournies remplaceront toutes les valeurs qui existent déjà pour les attributs donnés.

NOTE : ces modifications sont locales au client et n'apparaîtront sur le serveur d'annuaire que lorsque la méthode "update" sera appelée.

update ( CLIENT [, OPTIONS ] )
Met à jour le serveur d'annuaire avec toutes les modifications apportées localement aux attributs de cette entrée. Cela signifie toutes les appels qui ont été faits à add, replace ou delete depuis le dernier appel à changetype ou update.

Cette méthode peut également être utilisée pour modifier le DN de l'entrée sur le serveur, en spécifiant moddn ou modrdn comme changetype, et en définissant les attributs d'entrée newrdn, deleteoldrdn, et (facultativement) newsuperior.

"CLIENT" est un objet "Net::LDAP" vers lequel la mise à jour sera envoyée.

"OPTIONS" peut être des options pour les actions "Net::LDAP" sur CLIENT correspondant au changetype de l'entrée.

Le résultat sera un objet de type Net::LDAP::Message tel que retourné par la méthode add, modify ou delete appelée sur CLIENT.

Alternativement, "CLIENT" peut également être un objet "Net::LDAP::LDIF", qui doit être un fichier LDIF ouvert en écriture.

Ici aussi, le résultat est une classe d'objet "Net::LDAP::Message". En cas d'erreur, le code d'erreur est "LDAP_OTHER" avec le message d'erreur LDIF dans le texte d'erreur.
