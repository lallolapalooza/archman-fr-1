NAME

Net::LDAP::Control::VLV - Contrôle de liste virtuelle LDAP (v3)

SYNOPSIS

use Net::LDAP;
use Net::LDAP::Control::VLV;
use Net::LDAP::Constant qw( LDAP_CONTROL_VLVRESPONSE );
$ldap = Net::LDAP->new( "ldap.mydomain.eg" );
# Récupérer les 20 premiers enregistrements
$vlv  = Net::LDAP::Control::VLV->new(
          before  => 0,        # Nombre d'enregistrements avant l'enregistrement cible
          after   => 19,       # 19 enregistrements après l'enregistrement cible
          content => 0,        # Taille de la liste inconnue
          offset  => 1,        # L'enregistrement cible est le premier
        );
$sort = Net::LDAP::Control::Sort->new( order => 'cn' );
@args = ( base     => "o=Ace Industry, c=us",
          scope    => "subtree",
          filter   => "(objectClass=inetOrgPerson)",
          callback => \&process_entry, # Appelle cette sous-routine pour chaque enregistrement
          control  => [ $vlv, $sort ],
);
$mesg = $ldap->search( @args );
# Obtenir le contrôle de réponse VLV
($resp)  = $mesg->control( LDAP_CONTROL_VLVRESPONSE )  or die;
$vlv->response( $resp );
# Définir le contrôle pour obtenir les 20 derniers enregistrements
$vlv->end;
$mesg = $ldap->search( @args );
# Obtenir le contrôle de réponse VLV
($resp)  = $mesg->control( LDAP_CONTROL_VLVRESPONSE )  or die;
$vlv->response( $resp );
# Maintenant, récupérer le précédent de la page
$vlv->scroll_page( -1 );
$mesg = $ldap->search( @args );
# Obtenir le contrôle de réponse VLV
($resp)  = $mesg->control( LDAP_CONTROL_VLVRESPONSE )  or die;
$vlv->response( $resp );
# Maintenant, afficher le premier enregistrement commençant par "B" au milieu
$vlv->before(9);       # Changer la page pour afficher 9 avant
$vlv->after(10);       # Changer la page pour afficher 10 après
$vlv->assert("B");     # Affirmer "B"
$mesg = $ldap->search( @args );

DESCRIPTION

"Net::LDAP::Control::VLV" fournit une interface pour la création et la manipulation d'objets qui représentent la liste virtuelle LDAP comme décrit dans draft-ietf-ldapext-ldapv3-vlv-09.txt.

Lorsqu'un contrôle de liste virtuelle LDAP est utilisé dans une recherche, il doit être accompagné d'un contrôle de tri. Voir Net::LDAP::Control::Sort.

ARGUMENTS DU CONSTRUCTEUR

En plus des arguments du constructeur décrits dans Net::LDAP::Control, les suivants sont fournis.

after
Définit le nombre d'enregistrements que le serveur doit renvoyer de la liste après l'enregistrement cible.
assert
Définit la valeur d'assertion de l'utilisateur pour localiser l'enregistrement cible. Cette valeur doit être une valeur légale pour comparaison avec le premier attribut du contrôle de tri qui est passé avec le contrôle VLV. L'enregistrement cible est le premier dans la liste qui est supérieur ou égal à la valeur d'assertion.
before
Définit le nombre d'enregistrements que le serveur doit renvoyer de la liste avant l'enregistrement cible.
content
Définit le nombre d'enregistrements dans la liste. Lors de la première recherche, cette valeur doit être définie à zéro. Lors des recherches ultérieures, elle doit être définie à la longueur de la liste, telle que renvoyée par le contrôle VLVResponse.
context
Définit l'identifiant de contexte. Lors de la première recherche, cette valeur doit être définie à zéro. Lors des recherches ultérieures, elle doit être définie à la valeur de contexte renvoyée par le contrôle VLVResponse.
offset
Définit le décalage de l'enregistrement cible.

MÉTHODES

Comme avec Net::LDAP::Control, chaque argument du constructeur décrit ci-dessus est également disponible en tant que méthode sur l'objet, qui renverra la valeur actuelle de la propriété si elle est appelée sans argument, et définira une nouvelle valeur pour la propriété si un argument lui est passé.

Les attributs "offset" et "assert" s'excluent mutuellement. La définition de l'un ou l'autre entraînera l'oubli des valeurs précédemment définies par l'autre. L'attribut "content" est également associé à l'attribut "offset", donc la définition de "assert" entraînera l'oubli de toute valeur de "content".

end
Définit l'enregistrement cible à la dernière entrée de la liste. Cette méthode modifiera les attributs "before" et "after" de manière à ce que l'enregistrement cible soit le dernier de la page.
response VLV_RESPONSE
Définit les attributs du contrôle selon VLV_RESPONSE. VLV_RESPONSE doit être un contrôle de type Net::LDAP::Control::VLVResponse renvoyé par le serveur. "response" remplira les attributs "context", "offset" et "content" du contrôle avec les valeurs de VLV_RESPONSE. Parce que cela définit l'attribut "offset", toute définition antérieure de l'attribut "assert" sera oubliée.
scroll NUM
Déplace l'enregistrement cible de NUM entrées. Une valeur positive déplacera l'enregistrement cible vers la fin de la liste, et une valeur négative vers le début. Renvoie l'index du nouvel enregistrement cible, ou "undef" si l'enregistrement actuel est identifié par une assertion.

"scroll" peut modifier les attributs "before" et "after" si la valeur du défilement faisait que la page sortait d'un bord de la liste. Cependant, la taille de la page sera maintenue.

scroll_page NUM
Déplace la page de NUM pages. Cette méthode calcule la taille actuelle de la page et appelle "scroll" avec "NUM * $page_size"
start
Définit l'enregistrement cible au début de la liste. Cette méthode modifiera les attributs "before" et "after" de manière à ce que l'enregistrement cible soit la première entrée de la page.

Net::LDAP::Control::VLV(3pm)

NAME

Net::LDAP::Control::VLV - Virtual List View control

SYNOPSIS

use Net::LDAP::Control::VLV;

my $vlv = Net::LDAP::Control::VLV->new (
    
    sequence        => 0,
    
    target          => 5,
    
    
    sizelimit       => 10,
    
    
    filter          => '(objectClass=person)',
    
    
    by              => 'cn',
    
    
    reverse         => 0,
);

$ldap->search (
    ...,
    control => $vlv,
    ...,
);

DESCRIPTION

The Virtual List View control is used to implement a virtual list view which is a mechanism that allows the client to request a subset of the search results. This is particularly useful for displaying large lists of entries in a user interface without needing to retrieve all entries at once.

The control is typically used in conjunction with the LDAP search operation. The client sends a search request with the VLV control, specifying the desired range of entries, the criteria for ordering the results, and optionally a filter to further refine the search.

The server processes the request, retrieves the entries that match the search criteria, sorts them according to the specified order, and returns the requested subset of entries to the client. The server may also return information about the total number of entries matching the search criteria, allowing the client to determine the overall size of the list.

The Net::LDAP::Control::VLV module provides an interface for creating and manipulating the VLV control. It allows you to specify the various parameters of the control, such as the target entry, the size limit, the sorting criteria, and the ordering direction.

CONSTRUCTOR ARGUMENTS

The constructor Net::LDAP::Control::VLV->new() accepts the following arguments:

  • sequence: The sequence number of the VLV request. This is used to maintain context between multiple VLV requests.
  • target: The target entry for the VLV request. This can be a specific entry in the search results or a position relative to the beginning or end of the list.
  • sizelimit: The maximum number of entries to return in the response.
  • filter: A filter string to further refine the search results.
  • by: The attribute to use for sorting the search results.
  • reverse: A boolean value indicating whether to sort the results in reverse order (1 for true, 0 for false).
