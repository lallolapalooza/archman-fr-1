NOM

Net::DNS::SEC::Tools::Donuts - Exécuter des tests de type lintage DNS et DNSSEC sur les données de zone

SYNOPSIS

# charger une zone, des règles et analyser tout
#   par défaut, cela affichera les erreurs au format 'texte enveloppé'
#   sur la sortie standard.
my $donuts = new Net::DNS::SEC::Tools::Donuts();
$donuts->load_zone("/chemin/vers/example.com.signed", "example.com");
$donuts->load_rule_files("/chemin/vers/regles/installees/*.txt");
my ($rulecount, $errorcount) = $donuts->analyze();
# envoyer la sortie au format json vers /tmp/foo.json à la place
$donuts->set_output_format('json');
$donuts->set_output_location('file:/tmp/foo.json');
$donuts->analyze();
# afficher les fonctionnalités disponibles
print "fonctionnalités : ", join(", ", $donuts->available_features()), "\n";
# activer les fonctionnalités 'live' et 'check_data' dans les jeux de règles
$donuts->set_feature_list('live', 'check_data);
# ignorer certaines règles (expressions régulières pour correspondre aux noms de règles)
$donuts->set_ignore_list('NSEC');
# récupérer les règles chargées dans la zone
my @rules = $donuts->rules();
# récupérer les enregistrements de la zone chargée
#  (ce seront des enregistrements basés sur Net::DNS::RR)
my @records = $donuts->zone_records();
# ou juste d'un certain nom :
#   (ce sera une référence de hachage comme { type => [enregistrements] })
my $records = $donuts->find_records_by_name('www.example.com');
# ou juste d'un type pour un nom :
#   (ce sera une référence de tableau vers les [enregistrements])
my $records =
   $donuts->find_records_by_name_and_type('www.example.com', 'A');

DESCRIPTION

Le module Net::DNS::SEC::Tools::Donuts (alias Donuts) est capable de charger un fichier de zone, des règles à tester contre celui-ci, puis d'analyser les règles et de rapporter les résultats.

Création d'une instance Donuts

La création d'une instance d'objet Donuts est simple :

use Net::DNS::SEC::Tools::Donuts
my $donuts = new Net::DNS::SEC::Tools::Donuts();

Chargement et Accès aux Données de Zone

load_zone(SPECIFIER, ZONENAME)

Les données de zone peuvent être chargées dans le module Donuts en utilisant la fonction load_zone(). Cette fonction prend un chemin de fichier comme argument par défaut, ou l'un des spécificateurs spéciaux listés ci-dessous.

$donuts->load_zone("/chemin/vers/fichier", "example.com");
Charge un fichier à partir d'un fichier de données de zone typique (basé sur du texte). Il utilise le module Net::DNS::Zonefile::Fast pour analyser le fichier de zone en enregistrements Net::DNS::RR.
$donuts->load_zone("axfr:example.com", "example.com");
Si l'hôte a la capacité d'effectuer un transfert axfr d'une zone donnée, ce spécificateur peut être utilisé pour transférer dynamiquement les données de zone à partir des serveurs en ligne.
$donuts->load_zone("live:www,ftp:aaaa,ns", "example.com");
Lorsque le préfixe de spécificateur live: est utilisé, le module Donuts tente d'effectuer des requêtes uniques à partir de la zone pour les listes spécifiées de préfixes de noms de domaine pour la zone. La liste par défaut (c'est-à-dire juste "live:") des enregistrements de zone à interroger est juste "www". Les types de requêtes peuvent être spécifiés en séparant le libellé par un caractère ':', comme dans l'exemple ci-dessus qui indique qu'un enregistrement AAAA doit être interrogé pour l'hôte 'ftp'.

En plus de la liste spécifiée dans le spécificateur lui-même, chaque zone est toujours interrogée pour les entrées suivantes :

- ZONENAME:DNSKEY
- ZONENAME:SOA
- ZONENAME:NS

Notez que comme la zone ne sera pas entièrement complète, une sélection ou exclusion minutieuse des règles (voir "Ignorer et Exécuter Uniquement les Règles") sera probablement nécessaire pour filtrer les mauvais résultats lors de toute analyse effectuée.
