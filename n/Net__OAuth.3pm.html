NOM

Net::OAuth - OAuth 1.0 pour Perl

SYNOPSIS

# Exemple de serveur Web (Dancer)
# Cet exemple est simplifié à des fins d'illustration, voir le code complet dans /demo
# Notez que client_id est la clé consommateur et client_secret est le secret consommateur
use Dancer;
use Net::OAuth::Client;
sub client {
      Net::OAuth::Client->new(
              config->{client_id},
              config->{client_secret},
              site => 'https://www.google.com/',
              request_token_path => '/accounts/OAuthGetRequestToken?scope=https%3A%2F%2Fwww.google.com%2Fm8%2Ffeeds%2F',
              authorize_path => '/accounts/OAuthAuthorizeToken',
              access_token_path => '/accounts/OAuthGetAccessToken',
              callback => uri_for("/auth/google/callback"),
              session => \&session,
      );
}
# Envoyer l'utilisateur à autoriser avec le fournisseur de services
get '/auth/google' => sub {
      redirect client->authorize_url;
};
# L'utilisateur est revenu avec le jeton et le vérificateur ajoutés à l'URL.
get '/auth/google/callback' => sub {
      # Utiliser le code d'authentification pour récupérer le jeton d'accès
      my $access_token =  client->get_access_token(params->{oauth_token}, params->{oauth_verifier});
      # Utiliser le jeton d'accès pour récupérer une ressource protégée
      my $response = $access_token->get('/m8/feeds/contacts/default/full');
      # Faire quelque chose avec ladite ressource...
      if ($response->is_success) {
        return "Hourra, ça a marché : " . $response->decoded_content;
      }
      else {
        return "Erreur : " . $response->status_line;
      }
};
dance;

IMPORTANT

Net::OAuth fournit une API de bas niveau pour lire et écrire des messages OAuth.

Vous devriez probablement commencer avec Net::OAuth::Client.

RÉSUMÉ

OAuth est

"Un protocole ouvert pour permettre l'authentification sécurisée d'API d'une manière simple et standard à partir d'applications de bureau et Web."

En termes pratiques, OAuth est un mécanisme permettant à un Consommateur de demander des ressources protégées à un Fournisseur de Services au nom d'un utilisateur.

Veuillez vous référer à la spécification OAuth : http://oauth.net/documentation/spec

Net::OAuth fournit :

  • des classes qui encapsulent les messages OAuth (requêtes et réponses).
  • la signature de messages
  • la sérialisation et l'analyse de messages.
  • les requêtes en 2 pattes (également appelées requêtes sans jeton, également appelées requêtes consommateur), voir "REQUÊTES CONSOMMATEUR"

Net::OAuth ne fournit pas :

  • l'encapsulation de consommateur ou de fournisseur de services
  • le stockage/la gestion de jetons/nonces/clés

DESCRIPTION

MESSAGES OAUTH

Un message OAuth est un ensemble de paires clé-valeur. Les types de messages suivants sont pris en charge :

Requêtes

  • Jeton de requête (Net::OAuth::RequestTokenRequest)
  • Jeton d'accès (Net::OAuth::AccessTokenRequest)
  • Authentification utilisateur (Net::OAuth::UserAuthRequest)
  • Ressource protégée (Net::OAuth::ProtectedResourceRequest)
  • Requête consommateur (Net::OAuth::ConsumerRequest) (requête en 2 pattes / sans jeton)

Réponses

  • Jeton de requête (Net::OAuth::RequestTokenResponse)
  • Jeton d'accès (Net::OAuth:AccessTokenResponse)
  • Authentification utilisateur (Net::OAuth::UserAuthResponse)

Chaque type de message OAuth a un ou plusieurs paramètres requis, zéro ou plusieurs paramètres optionnels, et la plupart autorisent des paramètres arbitraires.

Toutes les requêtes OAuth doivent être signées par le Consommateur. Les réponses du Fournisseur de Services, cependant, ne sont pas signées.

Pour créer un message, la façon la plus simple est d'utiliser les méthodes de fabrique (Net::OAuth->request, Net::OAuth->response, Net::OAuth->message). Les appels de méthode suivants sont tous équivalents :

$request = Net::OAuth->request('authentification utilisateur')->new(%params);
$request = Net::OAuth->request('user_auth')->new(%params);
$request = Net::OAuth->request('UserAuth')->new(%params);
$request = Net::OAuth->message('UserAuthRequest')->new(%params);

La manière plus verbeuse est d'utiliser directement la classe :

use Net::OAuth::UserAuthRequest;
$request = Net::OAuth::UserAuthRequest->new(%params);

Vous pouvez également créer un message en le désérialisant à partir d'un en-tête d'authentification, d'une URL, d'un hachage de requête ou d'un corps POST.

$request = Net::OAuth->request('ressource protégée')->from_authorization_header($ENV{HTTP_AUTHORIZATION}, %api_params);
$request = Net::OAuth->request('ressource protégée')->from_url($url, %api_params);
$request = Net::OAuth->request('ressource protégée')->from_hash({$q->Vars}, %api_params); # CGI
$request = Net::OAuth->request('ressource protégée')->from_hash($c->request->params, %api_params); # Catalyst
$response = Net::OAuth->response('jeton de requête')->from_post_body($response_content, %api_params);

Notez que les méthodes de désérialisation (par opposition à new()) attendent que les paramètres du protocole OAuth soient précédés de 'oauth_', comme on peut s'y attendre dans un message OAuth valide.

Avant d'envoyer une requête, le Consommateur doit d'abord la signer :

$request->sign;

Lors de la réception d'une requête, le Fournisseur de Services doit d'abord vérifier la signature :

die "Échec de la vérification de la signature" unless $request->verify;

Lors de l'envoi d'un message, la dernière étape consiste à le sérialiser et à l'envoyer là où il doit aller. Les méthodes de sérialisation suivantes sont disponibles :

$response->to_post_body # un corps POST application/x-www-form-urlencoded
$request->to_url # la chaîne de requête d'une URL
$request->to_authorization_header # la valeur d'un en-tête HTTP Authorization
$request->to_hash # un hachage qui pourrait être utilisé pour une autre sérialisation

PARAMÈTRES API vs PARAMÈTRES MESSAGE

Net::OAuth définit les 'paramètres de message' comme les paramètres qui font partie du message OAuth transmis. Ceux-ci incluent tout paramètre de protocole (précédé de 'oauth_' dans le message), et tout paramètre de message supplémentaire (le hachage extra_params).

Les 'paramètres API' sont des paramètres requis pour construire un objet message qui ne sont pas transmis avec le message, par exemple consumer_secret, token_secret, request_url, request_method.

Il existe diverses méthodes pour inspecter une classe de message afin de voir quels paramètres sont définis :

$request->required_message_params;
$request->optional_message_params;
$request->all_message_params;
$request->required_api_params;
$request->optional_api_params;
$request->all_api_params;
$request->all_params;

Par exemple :

use Net::OAuth;
use Data::Dumper;
print Dumper(Net::OAuth->request("ressource protégée")->required_message_params);
$VAR1 = [
         'consumer_key',
         'signature_method',
         'timestamp',
         'nonce',
         'token'
       ];

ACCÈS AUX PARAMÈTRES

Tous les paramètres peuvent être obtenus/définis à l'aide de méthodes d'accès. Par exemple :

my $consumer_key = $request->consumer_key;
$request->request_method('POST');

LE PARAMÈTRE REQUEST_URL

Tous les paramètres de requête dans request_url sont supprimés et ajoutés au hachage extra_params lors de la génération de la signature.

Par exemple, les requêtes suivantes sont pratiquement équivalentes :

 my $request = Net::OAuth->request('Jeton de requête')->new(
  %params,
  request_url => 'https://photos.example.net/request_token',
  extra_params => {
   foo => 'bar'
  },
);
 my $request = Net::OAuth->request('Jeton de requête')->new(
  %params,
  request_url => 'https://photos.example.net/request_token?foo=bar',
 );

Appeler $request->request_url renverra toujours ce que vous y avez initialement défini. Si vous souhaitez obtenir le request_url avec les paramètres de requête supprimés, vous pouvez faire :

my $url = $request->normalized_request_url;

MÉTHODES DE SIGNATURE

Les méthodes de signature suivantes sont prises en charge :

  • PLAINTEXT
  • HMAC-SHA1
  • HMAC-SHA256
  • RSA

Ce site n'est en aucun cas associé à Arch Linux ni affilié à ce projet. Le contenu est uniquement une traduction des pages de manuel d'Arch publiées sur man.archlinux.org.

-SHA1

La méthode de signature est déterminée par la valeur du paramètre signature_method passé au constructeur du message.

Si une méthode de signature inconnue est spécifiée, la signature/vérification lèvera une exception.

SIGNATURES PLAINTEXT

Cette méthode est une signature triviale qui n'ajoute aucune sécurité. Non recommandée.

SIGNATURES HMAC-SHA1

Cette méthode est disponible si vous avez installé Digest::SHA. C'est de loin la méthode la plus couramment utilisée.

SIGNATURES HMAC-SHA256

Cette méthode est disponible si vous avez installé Digest::SHA.

SIGNATURES RSA-SHA1

Pour utiliser les signatures RSA-SHA1, passez un objet Crypt::OpenSSL::RSA (ou tout objet capable de faire $o->sign($str) et/ou $o->verify($str, $sig)).

Par exemple :

Consommateur :

use Crypt::OpenSSL::RSA;
use File::Slurp;
$keystring = read_file('private_key.pem');
$private_key = Crypt::OpenSSL::RSA->new_private_key($keystring);
$request = Net::OAuth->request('request token')->new(%params);
$request->sign($private_key);

Fournisseur de services :

use Crypt::OpenSSL::RSA;
use File::Slurp;
$keystring = read_file('public_key.pem');
$public_key = Crypt::OpenSSL::RSA->new_public_key($keystring);
$request = Net::OAuth->request('request token')->new(%params);
if (!$request->verify($public_key)) {
       die "Signature verification failed";
}

Notez que vous pouvez passer la clé en tant que paramètre appelé 'signature_key' au constructeur du message, plutôt que de la passer à la méthode sign/verify, si vous le souhaitez.

DEMANDES CONSOMMATEUR

Pour envoyer une demande sans inclure de jeton, utilisez une demande Consommateur :

my $request = Net::OAuth->request('consumer')->new(
        consumer_key => 'dpf43f3p2l4k3l03',
        consumer_secret => 'kd94hf93k423kf44',
        request_url => 'http://provider.example.net/profile',
        request_method => 'GET',
        signature_method => 'HMAC-SHA1',
        timestamp => '1191242096',
        nonce => 'kllo9940pd9333jh',
);
$request->sign;

Voir Net::OAuth::ConsumerRequest

I18N

Conformément à la spécification OAuth, lors de la création de la signature, Net::OAuth encode d'abord les paramètres en UTF-8. Cela signifie que tous les paramètres que vous passez à Net::OAuth, s'ils peuvent être en dehors de l'ensemble de caractères ASCII, doivent être traités avec Encode::decode() (ou une couche PerlIO équivalente) au préalable pour les décoder dans la structure de caractères interne de Perl.

OAUTH 1.0A

Contexte :

http://mojodna.net/2009/05/20/an-idiots-guide-to-oauth-10a.html

http://oauth.googlecode.com/svn/spec/core/1.0a/drafts/3/oauth-core-1_0a.html

Net::OAuth est conforme par défaut à la spécification OAuth 1.0 et prend en charge OAuth 1.0 Rev A avec un commutateur optionnel :

use Net::OAuth
$Net::OAuth::PROTOCOL_VERSION = Net::OAuth::PROTOCOL_VERSION_1_0A;

Il est recommandé que tout nouveau projet utilise ce commutateur si possible, et que les projets existants prennent en charge ce commutateur dès que possible. La méthode la plus simple pour les projets existants est probablement d'activer le commutateur et d'exécuter la suite de tests. Le constructeur Net::OAuth lèvera une exception si les nouveaux paramètres du protocole (callback, callback_confirmed, verifier) sont manquants.

En interne, le constructeur Net::OAuth::Message vérifie $Net::OAuth::PROTOCOL_VERSION et tente de charger la sous-classe équivalente dans l'espace de noms Net::OAuth::V1_0A::. Ainsi, si vous instanciez un objet Net::OAuth::RequestTokenRequest, vous obtiendrez un Net::OAuth::V1_0A::RequestTokenRequest (un sous-classe de Net::OAuth::RequestTokenRequest) si la version du protocole est définie sur PROTOCOL_VERSION_1_0A. Vous pouvez également sélectionner une sous-classe 1.0a par message en passant

protocol_version => Net::OAuth::PROTOCOL_VERSION_1_0A

dans le hachage des paramètres de l'API.

Si vous n'êtes pas sûr que l'entité avec laquelle vous communiquez soit conforme à la norme 1.0A, vous pouvez essayer d'instancier d'abord un message 1.0A, puis revenir à 1.0 si cela échoue :

use Net::OAuth
$Net::OAuth::PROTOCOL_VERSION = Net::OAuth::PROTOCOL_VERSION_1_0A;
my $is_oauth_1_0 = 0;
my $response = eval{Net::OAuth->response('request token')->from_post_body($res->content)};
if ($@) {
    if ($@ =~ /Missing required parameter 'callback_confirmed'/) {
        # fallback to OAuth 1.0
        $response = Net::OAuth->response('request token')->from_post_body(
            $res->content,
            protocol_version => Net::OAuth::PROTOCOL_VERSION_1_0
        );
        $is_oauth_1_0 = 1; # from now on treat the server as OAuth 1.0 compliant
    }
    else {
        die $@;
    }
}

À un moment donné dans le futur, Net::OAuth utilisera par défaut Net::OAuth::PROTOCOL_VERSION_1_0A.
