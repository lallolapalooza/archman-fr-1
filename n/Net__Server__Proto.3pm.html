NAME

Net::Server::Proto - Couche de compatibilité pour les protocoles Net::Server

SYNOPSIS

NOTE : Depuis Net::Server 2.005, la valeur par défaut pour ipv est IPv* signifiant que si aucun hôte n'est passé ou si un nom d'hôte est passé, tous les types de socket disponibles seront attribués. Vous pouvez forcer l'IPv4 uniquement en ajoutant un ipv => 4 dans l'une des six formes permises.
NOTE : Pour IPv6, Net::Server tentera d'abord d'utiliser le module listé dans le fichier de configuration server_config_ipv6_package, puis Net::Server::ipv6_package, puis IO::Socket::IP, puis IO::Socket::INET6 (qui est obsolète).
# Net::Server::Proto et ses modules associés ne sont pas destinés à être utilisés en dehors du cadre de Net::Server.
# C'est donc ainsi que vous l'utilisez. Ceci est juste pour toute personne souhaitant étendre les protocoles pour inclure d'autres (par exemple, un protocole de base de données).
use Net::Server::Proto;
my @info = Net::Server::Proto->parse_info(
    $port,            # port à connecter
    $default_host,    # hôte à utiliser si non trouvé au port
    $default_proto,   # protocole à utiliser si non trouvé au port
    $default_ipv,     # IPv6 ou IPv4 par défaut si non trouvé au port
    $server_obj,      # objet Net::Server
);
my @raw_info = Net::Server::Proto->get_addr_info($host, $port, $proto);
# renvoie un tableau de références d'ips résolues, de ports et de valeurs ipv
my $sock = Net::Server::Proto->object({
    port  => $port,
    host  => $host,
    proto => $proto,
    ipv   => $ipv, # * (IPv*) si faux (par défaut faux)
}, $server);
# Net::Server::Proto tentera d'interfacer avec les modules sous-classes nommés de manière similaire à Net::Server::Proto::TCP
# Chaque module sous-classe est chargé par Net::Server::Proto lorsque nécessaire.
use Net::Server::Proto::TCP; # ou UDP ou UNIX etc
# Renvoie un objet qui est une sous-classe de IO::Socket
# À ce stade, l'objet n'est pas connecté.
# La méthode peut collecter toute information supplémentaire dont elle a besoin à partir de l'objet serveur.
my $sock = Net::Server::Proto::TCP->object({
    port  => $port,
    host  => $host,
    proto => $proto,
    ipv   => 6, # IPv6 - la valeur par défaut est * - peut également être '4'
}, $server);
# Journalisation de la connexion à établir.
# Utilise les fonctionnalités de l'objet Net::Server passé.
$sock->log_connect( $server );
# Liez réellement au port ou au fichier socket. Ceci est généralement fait en appelant la méthode configure de la superclasse IO::Socket.
$sock->connect();
# Permet de relier un fichier socket déjà ouvert. Ceci est généralement fait avec un fdopen utilisant la superclasse IO::Socket.
$sock->reconnect();
### Renvoie un identifiant unique pour ce socket qui peut être utilisé lors de la reconnexion.
my $str = $sock->hup_string();
# Renvoie le protocole utilisé par ce module.
my $proto = $sock->NS_proto();

DESCRIPTION

Net::Server::Proto est un module intermédiaire qui renvoie des objets de style IO::Socket affublés de leur propre ensemble de classes (c'est-à-dire Net::Server::Proto::TCP, Net::Server::Proto::UNIX).

Seuls trois ou quatre protocoles sont pré-installés avec Net::Server. TCP, UDP, UNIX, UNIXDGRAM et SSLEAY. TCP est une implémentation de SOCK_STREAM sur un socket INET. UDP est une implémentation de SOCK_DGRAM sur un socket INET. UNIX utilise un fichier socket de type UNIX avec le protocole SOCK_STREAM. UNIXGRAM utilise un fichier socket de type UNIX avec le protocole SOCK_DGRAM. SSLEAY est en fait juste une couche au-dessus de TCP mais utilise Net::SSLeay pour lire et écrire depuis le flux.

Le protocole passé à Net::Server peut être le nom d'un autre module qui contient les implémentations du protocole. Si un protocole comme MyServer::MyTCP est passé, le socket sera affublé de cette classe. Si Net::Server::Proto::TCP est passé, vous obtiendrez cette classe. Si un mot en minuscules, comme tcp, udp, unix, unixdgram ou ssleay, est passé, il sera mis en majuscules et ajouté à la fin de "Net::Server::Proto::" (c'est-à-dire tcp = Net::Server::Proto::TCP).

MÉTHODES

Les noms de protocoles utilisés par Net::Server::Proto doivent être des sous-classes de IO::Socket. Ces classes doivent également contenir, au minimum, les méthodes suivantes :

object
Renvoie un objet qui est une sous-classe de IO::Socket. À ce stade, l'objet n'est pas connecté. La méthode peut collecter toute information supplémentaire dont elle a besoin à partir de l'objet serveur. Les arguments sont l'hôte par défaut, le port et un objet de style Net::Server.
log_connect
Journalisation de la connexion à établir. Utilise les fonctionnalités de l'objet Net::Server passé. Il doit s'agir d'une chaîne informative expliquant quelles propriétés sont utilisées.
connect
Lie réellement au port ou au fichier socket. Ceci est généralement fait en appelant la méthode configure de la superclasse IO::Socket.
reconnect
Permet de relier un fichier socket déjà ouvert. Ceci est généralement fait avec un fdopen utilisant la superclasse IO::Socket.
hup_string
Renvoie un identifiant unique pour ce socket qui peut être utilisé lors de la reconnexion. Ceci est fait pour permettre le passage d'informations, y compris le descripteur de fichier des sockets ouverts, via %ENV lors d'un exec. Cette chaîne doit toujours être la même selon les paramètres de configuration.
NS_port
Protocole Net::Server. Renvoie le port utilisé par ce module. Si le type sous-jacent est UNIX, le port sera en fait le chemin du fichier socket UNIX.
NS_host
Protocole Net::Server. Renvoie le protocole utilisé par ce module. Il ne s'agit pas nécessairement d'un protocole enregistré ou connu.
NS_proto
Protocole Net::Server. Renvoie le protocole utilisé par ce module. Il ne s'agit pas nécessairement d'un protocole enregistré ou connu.
show
Similaire à log_connect, mais affiche simplement une liste des propriétés trouvées. Peut être utilisé à tout moment.

HOST

Le nom d'hôte peut être vide, '*', une adresse IPv4, une adresse IPv6, un nom d'hôte ou un nom d'hôte avec des spécifications IPv*.

host => "127.0.0.1",  # une adresse IPv4
host => "::1",        # une adresse IPv6
host => 'localhost',  # adresses renvoyées par localhost (par défaut IPv* - IPv4 et/ou IPv6)
host => 'localhost/IPv*',  # identique
ipv  => '*',
host => 'localhost',  # identique
ipv  => 6,
host => 'localhost',  # adresses renvoyées par localhost (IPv6)
ipv  => 'IPv4 IPv6',
host => 'localhost',  # adresses renvoyées par localhost (nécessite IPv6 et IPv4)
host => '*',          # toute interface locale (par défaut IPv*)
ipv  => '*',
host => '*',          # toute interface locale (IPv6 ou IPv4)
host => '*/IPv*',     # identique

IPV

En plus de pouvoir spécifier IPV comme paramètre séparé, ipv peut également être passé dans le cadre de l'hôte, du port, du protocole, ou spécifié via $ENV{'IPV'}. La priorité de l'ordre est la suivante :

1) Adresse IPv4 ou IPv6 explicite - gagne
2) valeur ipv spécifiée dans le port
3) valeur ipv spécifiée dans l'hôte
4) valeur ipv spécifiée dans le protocole
5) valeur ipv spécifiée dans les valeurs par défaut
6) valeur ipv spécifiée dans $ENV{'IPV'}
7) la valeur par défaut est IPv*

PORT

Le port est l'argument le plus important passé aux classes de modules et à Net::Server::Proto lui-même. Pour les ports de type TCP, UDP ou SSLEAY, la forme générale est généralement host:port/protocol, [host]:port/protocol, host|port|protocol, host/port, ou port. Si host est une adresse IPv6 numérique, elle doit être entre crochets pour éviter toute ambiguïté lors de l'analyse d'un numéro de port, par exemple : "[::1]:80". Séparer par des espaces, des virgules ou des barres verticales est également autorisé, par exemple "::1, 80". Pour les sockets UNIX, la forme générale est généralement socket_file|unix ou socket_file.

Pour aider à surmonter l'ambiguïté d'analyse, il est également possible de passer le port sous forme de hashref (ou de tableau de hashrefs) d'informations comme :

port => {
    host  => "localhost",
    ipv   => 6, # peut également passer IPv6 (* est la valeur par défaut)
    port  => 20203,
    proto => 'tcp',
}

Si un hashref n'inclut pas host, ipv, ou proto, la valeur par défaut fournie par la configuration générale sera utilisée.

Net::Server::Proto(3pm) — Arch Linux

NAME

Net::Server::Proto - Helper class to parse Net::Server protocol string

SYNOPSIS

use Net::Server::Proto;

my $info = Net::Server::Proto->parse_info($port, $def_host, $def_proto, $def_ipv);

DESCRIPTION

This is a helper class for parsing the protocol string that is passed into Net::Server. Net::Server generally expects a protocol string that it can use to determine how to create a server socket. However, the protocol string has a number of different forms it can take, and for that reason, it is passed through this helper class first.

The parse_info method takes the following arguments:

port
The protocol string itself. This can take several forms:
port
port/proto
host:port
host:port/proto
/path/to/socket|unix
/path/to/socket|unixproto
host:port/proto|unix_type

The following lists all of the possible forms:

A port number (e.g. 20203). In this case, the host and proto arguments are used to determine the rest of the info.
A host and port combination (e.g. someother.com:20203). This overrides the default host.
A protocol string with a port (e.g. 20203/udp). This overrides the default protocol.
A protocol string with a host and port (e.g. someother.com:20203/udp). This overrides both the default host and protocol.
A Unix domain socket path (e.g. /tmp/mysock.file|unix).
A Unix domain socket path and protocol (e.g. /tmp/mysock.file|unixdgram).
A host, port, protocol, and IPv string (e.g. [::1]:20203 ipv6 tcp). Note that the IPv string can be a number (4 or 6) or a keyword (ipv4, ipv6, ip*).

Also, the default protocol and host can be specified by the def_proto and def_host arguments.

The default protocol can be specified with the IPV environment variable. It can be set to 4, 6, or IP* (to allow both).

The parse_info method returns a hashref containing the parsed information, or a list of hashrefs if the input string allows for multiple protocol families.

Possible keys in the returned hashref:

host
The hostname or IP address to bind to. Defaults to '*' if not specified.
port
The port number or the path to the Unix domain socket.
proto
The protocol to use (e.g. 'tcp', 'udp', 'unix'). This will be used to determine which protocol class to load.
ipv
The address family. 4 for IPv4, 6 for IPv6, or '*' for any.
unix_type
For Unix domain sockets, this specifies the socket type (e.g. 'SOCK_STREAM' or 'SOCK_DGRAM'). Defaults to 'SOCK_STREAM'.

The ipv key specifies the desired address family of the binding address. A PF_INET socket can only accept IPv4 connections. A PF_INET6 socket accepts IPv6 connections, but may also accept IPv4 connections, depending on the OS and its settings. For example, on FreeBSD systems setting a sysctl net.inet6.ip6.v6only to 0 will allow IPv4 connections to a PF_INET6 socket. By default on Linux, binding to host [::] will accept IPv4 or IPv6 connections.

The Net::Server::Proto::object method returns a list of objects corresponding to created sockets. For Unix and INET sockets the list typically contains just one element, but may return multiple objects when multiple protocol families are allowed or when a host name resolves to multiple local binding addresses. This is particularly true when an ipv value of '*' is passed in allowing hostname resolution.

You can see what Net::Server::Proto parsed out by looking at the logs to see what log_connect said. You could also include a post_bind_hook similar to the following to debug what happened:

sub post_bind_hook {
    my $self = shift;
    foreach my $sock ( @{ $self->{server}->{sock} } ){
        $self->log(2,$sock->show);
    }
}
