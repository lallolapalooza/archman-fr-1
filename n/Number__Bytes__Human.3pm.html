NOM

Number::Bytes::Human - Convertir un nombre d'octets en un format lisible par l'homme

SYNTAXE

use Number::Bytes::Human qw(format_bytes parse_bytes);
$size = format_bytes(0); # '0'
$size = format_bytes(2*1024); # '2.0K'
$size = format_bytes(1_234_890, bs => 1000); # '1.3M'
$size = format_bytes(1E9, bs => 1000); # '1.0G'
my $bytes = parse_bytes('1.0K');   # 1024
my $bytes = parse_bytes('1.0KB');  # 1000, unité SI
my $bytes = parse_bytes('1.0KiB'); # 1024, unité SI
# la manière orientée objet
$human = Number::Bytes::Human->new(bs => 1000, si => 1);
$size = $human->format(1E7); # '10MB'
$bytes = $human->parse('10MB');   # 10*1000*1000
$bytes = $human->parse('10MiB');  # 10*1024*1024
$bytes = $human->parse('10M');    # Erreur, pas d'unité SI
$human->set_options(zero => '-');
$size = $human->format(0);    # '-'
$bytes = $human->parse('-');  # 0
$human = Number::Bytes::Human->new(bs => 1000, round_style => 'round', precision => 2);
$size = $human->format(10240000); # '10.24MB'

DESCRIPTION

CECI EST UN LOGICIEL ALPHA : LA DOCUMENTATION ET LE CODE POURRONT CHANGER UN JOUR (MERCI, DIEU !).

Ce module fournit un formateur qui transforme les nombres d'octets en un format lisible habituel, comme '2.0K', '3.1G', '100B'. Il a été inspiré par l'option "-h" des utilitaires Unix comme "du", "df" et "ls" pour une sortie "lisible par l'homme".

Extrait de la page de manuel FreeBSD de "df" : http://www.freebsd.org/cgi/man.cgi?query=df

"Lisible par l'homme" sortie. Utilise des suffixes d'unité : Byte, Kilooctet,
Megaoctet, Gigaoctet, Téraoctet et Pétabye dans le but de réduire le
nombre de chiffres à quatre ou moins en utilisant la base 2 pour les tailles.
octet         B
kilo-octet    K = 2**10 B = 1024 B
méga-octet    M = 2**20 B = 1024 * 1024 B
giga-octet    G = 2**30 B = 1024 * 1024 * 1024 B
téra-octet    T = 2**40 B = 1024 * 1024 * 1024 * 1024 B
péta-octet    P = 2**50 B = 1024 * 1024 * 1024 * 1024 * 1024 B
exaoctet      E = 2**60 B = 1024 * 1024 * 1024 * 1024 * 1024 * 1024 B
zeta-octet    Z = 2**70 B = 1024 * 1024 * 1024 * 1024 * 1024 * 1024 * 1024 B
yota-octet    Y = 2**80 B = 1024 * 1024 * 1024 * 1024 * 1024 * 1024 * 1024 * 1024 B

J'ai trouvé ce lien très utile :

http://www.t1shopper.com/tools/calculate/

Si vous vous sentez comme un fabricant de disques durs, vous pouvez commencer à compter les octets par puissances de 1000 (au lieu des généreux 1024). Utilisez simplement "bs => 1000".

Mais si vous êtes un fabricant de disquettes et que vous voulez commencer à compter en unités de 1024000 (pour vos disquettes de "1.44 Mo") ? Alors utilisez "bs => 1_024_000".

Si vous vous sentez comme un universitaire puriste, vous pouvez forcer l'utilisation des préfixes métriques conformément à la norme de décembre 1998 de la CEI. Peu importe que les unités pour la base 1000 soient "('B', 'kB', 'MB', 'GB', 'TB', 'PB', 'EB', 'ZB', 'YB')" et, pire encore, celles pour la base 1024 soient "('B', 'KiB', 'MiB', 'GiB', 'TiB', 'PiB', 'EiB', 'ZiB', 'YiB')" avec les noms horribles : octets, kibioctets, mébioctets, etc. Tout ce que vous avez à faire est d'utiliser "si => 1". N'est-ce pas beau le système SI ? Lisez-en plus à ce sujet :

http://physics.nist.gov/cuu/Units/binary.html

Vous pouvez essayer une commande purement Perl inspirée de "ls -lh" avec le one-liner, euh, two-liner :

$ perl -MNumber::Bytes::Human=format_bytes \
       -e 'printf "%5s %s\n", format_bytes(-s), $_ for @ARGV' *

Pourquoi écrire un tel module ? Parce que si les gens peuvent écrire de telles choses en C, cela peut être écrit beaucoup plus facilement en Perl et ensuite réutilisé, refactorisé, maltraité. Et puis, quand il sera beaucoup amélioré, une âme courageuse pourra le reporter en C (ne serait-ce que pour le sentiment chaleureux de programmation douloureuse).

Il est également possible d'analyser des octets formatés lisibles par l'homme. La détection automatique du format reconnaît les unités SI avec les tailles de blocs de 1000 et 1024 respectivement, ainsi que les K / M / G habituels, etc. avec une taille de bloc de 1024. Lorsque si => 1 est ajouté aux options, seules les unités SI sont reconnues. La spécification explicite d'une taille de bloc la modifie pour toutes les unités détectées.

OBJETS

Une alternative au style fonctionnel de ce module est la mode OO. C'est utile pour éviter l'analyse inutile des arguments encore et encore si vous devez formater de nombreux nombres

for (@tailles) {
  my $fmt_size = format_bytes($_, @args);
  ...
}

contre

my $human = Number::Bytes::Human->new(@args);
for (@tailles) {
  my $fmt_size = $human->format($_);
  ...

FONCTIONS

format_bytes
$h_size = format_bytes($size, @options);

Transforme un nombre d'octets (comme 1230) en un format lisible comme '1.3K'. Vous avez un tas d'options à votre disposition. Voir la section "OPTIONS" pour connaître les détails.

parse_bytes
$size = parse_bytes($h_size, @options);

Transforme un nombre d'octets lisible par l'homme en un nombre d'octets équivalents.

MÉTHODES

new
$h = Number::Bytes::Human->new(@options);

Le constructeur. Pour les détails sur les arguments, voir la section "OPTIONS".

format
$h_size = $h->format($size);

Transforme un nombre d'octets (comme 1230) en un format lisible comme '1.3K'. Les instructions

$h = Number::Bytes::Human->new(@options);
$h_size = $h->format($size);

sont équivalentes à "$h_size = format_bytes($size, @options)", avec une seule passe pour les arguments d'options.

parse
$size = $h->parse($h_size)

Transforme un nombre d'octets lisible par l'homme en nombre d'octets. Les instructions

$h = Number::Bytes::Human->new(@options);
$size = $h->format($h_size);

sont équivalentes à "$size = parse_bytes($h_size, @options)", avec une seule passe pour les arguments d'options.

set_options
$h->set_options(@options);

Pour modifier les options d'un objet "Number::Bytes::Human". Voir "OPTIONS".

OPTIONS

BASE
block | base | block_size | bs => 1000 | 1024 | 1024000
base_1024 | block_1024 | 1024 => 1
base_1000 | block_1000 | 1000 => 1

La base à utiliser : 1024 (par défaut), 1000 ou 1024000.

Toute autre valeur lève une exception.

SUFFIXES
suffixes => 1000 | 1024 | 1024000 | si_1000 | si_1024 | $arrayref

Par défaut, les suffixes utilisés représentent '', 'K', 'M', ... pour la base 1024 et '', 'k', 'M', ... pour la base 1000 (qui sont en fait les préfixes métriques habituels avec une unité implicite comme octets, 'B'). Pour la base étrange 1024000, les suffixes sont '', 'M', 'T', etc.

ZERO
zero => string | undef

La chaîne 0 est mappée sur ('0' par défaut). Si "undef", le cas général est utilisé. La chaîne peut contenir '%S' auquel cas le suffixe pour octet est utilisé.

format_bytes(0, zero => '-') => '-'
SYSTÈME MÉTRIQUE
si => 1
ARRONDI

NOM

Number::Bytes::Human

SYNOPIS

use Number::Bytes::Human;

DESCRIPTION

Number::Bytes::Human est un module Perl qui fournit un format lisible par l'homme pour les nombres, similaire à la fonctionnalité trouvée dans le package GNU coreutils. Il vous permet de formater les nombres d'une manière facile à comprendre, avec la prise en charge de divers styles et paramètres de précision.

DIAGNOSTICS

Voici les messages de diagnostic que vous pourriez rencontrer :

  • unknown round style '$style'
  • invalid base: $block (should be 1024, 1000 or 1024000)
  • round function ($args{round_function}) should be a code ref
  • suffixes ($args{suffixes}) should be 1000, 1024, 1024000 or an array ref
  • negative numbers are not allowed
