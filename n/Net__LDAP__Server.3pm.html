Net::LDAP::Server(3) Documentation Perl fournie par l'utilisateur Net::LDAP::Server(3)

NOM

Net::LDAP::Server - Gestion du protocole côté serveur LDAP

SYNOPIS

package MyServer;
use Net::LDAP::Server;
use Net::LDAP::Constant qw(LDAP_SUCCESS);
use base 'Net::LDAP::Server';
sub search {
    my $self = shift;
    my ($reqData, $fullRequest) = @_;
    print "Searching\n";
    ...
    return {
        'matchedDN' => '',
        'errorMessage' => '',
        'resultCode' => LDAP_SUCCESS
    }, @entries;
}

package main;
my $handler = MyServer->new($socket);
$handler->handle;
# ou avec des descripteurs d'entrée et de sortie distincts
package main;
my $handler = MyServer->new( $input_handle, $output_handle );
$handler->handle;

ABSTRAIT

Cette classe fournit la gestion du protocole pour un serveur LDAP. Vous pouvez la sous-classer et implémenter les méthodes dont vous avez besoin (voir ci-dessous). Ensuite, il suffit d'instancier votre sous-classe et d'appeler sa méthode "handle" pour établir une connexion avec le client.

SOUS-CLASSEMENT

Vous pouvez sous-classer Net::LDAP::Server avec les lignes suivantes :

package MyServer;
use Net::LDAP::Server;
use base 'Net::LDAP::Server';

Ensuite, vous pouvez ajouter vos méthodes personnalisées en implémentant simplement une sous-routine nommée d'après le nom de chaque méthode. Voici les méthodes supportées :

"bind"
"unbind"
"search"
"add"
"modify"
"delete"
"modifyDN"
"compare"
"abandon"

Pour toute méthode non fournie, Net::LDAP::Server retournera une "LDAP_UNWILLING_TO_PERFORM".

new()

Vous pouvez également sous-classer le constructeur "new" pour effectuer une action lors de la connexion :

sub new {
   my ($class, $sock) = @_;
   my $self = $class->SUPER::new($sock);
   printf "Accepted connection from: %s\n", $sock->peerhost();
   return $self;
}

Notez que $self est construit en utilisant le pragma fields, donc si vous voulez ajouter des données à celui-ci, vous devriez ajouter une ligne comme celle-ci dans votre sous-classe :

use fields qw(myCustomField1 myCustomField2);

Méthodes

Lorsqu'une méthode est appelée, elle recevra évidemment $self tel que généré par "new", et deux variables :

  • la structure de données de Requête spécifique à cette méthode (par exemple, BindRequest) ;
  • le message de requête complet (utile si vous souhaitez accéder aux parties messageID ou controls).

Vous pouvez regarder Net::LDAP::ASN ou utiliser Data::Dumper pour savoir ce qui est passé à votre méthode :

use Data::Dumper;
sub search {
   print Dumper \@_;
}

Si quelque chose tourne mal dans le module que vous spécifiez (par exemple, il a planté ou le résultat n'est pas une structure ldapresult correcte), Net::LDAP::Server retournera une "LDAP_OPERATIONS_ERROR" où errorMessage spécifiera ce qui s'est mal passé.

Toutes les méthodes doivent retourner un hachage LDAPresult, par exemple :

return({
    'matchedDN' => '',
    'errorMessage' => '',
    'resultCode' => LDAP_SUCCESS
});

"search" doit retourner un hachage LDAPresult suivi d'une liste d'entrées (si applicable). Les entrées peuvent être codées soit comme des structures searchResEntry ou searchRefEntry, soit comme des objets Net::LDAP::Entry ou Net::LDAP::Reference.

GESTION CLIENT

handle()

Lorsque vous obtenez un socket d'un client, vous pouvez instancier la classe et gérer la requête :

my $handler = MyServer->new($socket);
$handler->handle;

Ou, alternativement, vous pouvez passer deux descripteurs pour l'entrée et la sortie, respectivement.

my $handler = MyServer->new(*STDIN{IO},*STDOUT{IO});
$handler->handle;

Voir les exemples dans le répertoire examples/ pour des serveurs d'exemple, utilisant IO::Select, Net::Daemon ou Net::Server.
