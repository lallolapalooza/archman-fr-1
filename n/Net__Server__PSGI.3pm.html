NOM

Net::Server::PSGI - classe de serveur PSGI HTTP basée sur Net::Server

UNE LIGNE DE TEST

perl -e 'use base qw(Net::Server::PSGI); main->run(port => 8080, ipv => "*")'
# lance un serveur d'écho par défaut

SYNOPSIS

use base qw(Net::Server::PSGI);
__PACKAGE__->run(app => \&my_echo_handler); # liera le port IPv4 80
sub my_echo_handler {
    my $env = shift;
    my $txt = qq{<form method="post" action="/bam"><input type="text" name="foo"><input type="submit"></form>\n};
    require Data::Dumper;
    local $Data::Dumper::Sortkeys = 1;
    require CGI::PSGI;
    my $form = {};
    my $q = CGI::PSGI->new($env);
    $form->{$_} = $q->param($_) for $q->param;
    $txt .= "<pre>".Data::Dumper->Dump([$env, $form], ['env', 'form'])."</pre>";
    return [200, ['Content-type', 'text/html'], [$txt]];
}

DESCRIPTION

Si vous souhaitez une expérience PSGI plus complète, il est conseillé de vous tourner vers les modules Plack et Starman. Net::Server::PSGI est conçu comme une passerelle facile vers PSGI. Mais pour tirer le meilleur parti de tout ce que PSGI a à offrir, vous devriez consulter Plack et Plack::Middleware. Si vous n'avez besoin que de quelque chose d'un peu plus rudimentaire, alors Net::Server::PSGI pourrait vous convenir.

Net::Server::PSGI pousse Net::Server::HTTP un niveau plus loin. Il commence avec le type de base MultiType, qui est par défaut Net::Server::Fork. Il est facile de le changer pour n'importe quelle autre saveur de Net::Server en passant server_type => $autre_saveur dans la configuration du serveur. Le port a également été défini par défaut au port 80 - mais il pourrait facilement être changé pour un autre via la configuration du serveur. Vous pouvez également ajouter très facilement le SSL en incluant, proto=>"ssl" et en fournissant un fichier SSL_cert_file et SSL_key_file.

Par exemple, voici un serveur de base qui se liera à toutes les interfaces, parlera à la fois HTTP sur le port 8080 et HTTPS sur 8443, et parlera à la fois IPv4, ainsi qu'IPv6 si disponible.

use base qw(Net::Server::PSGI);
__PACKAGE__->run(
    port  => [8080, "8443/ssl"],
    ipv   => '*', # IPv6 si disponible
    SSL_key_file  => '/my/key',
    SSL_cert_file => '/my/cert',
);

MÉTHODES

"process_request"
Cette méthode a été remplacée dans Net::Server::PSGI - vous ne devriez pas l'utiliser lors de l'utilisation de Net::Server::PSGI. Cette méthode remplacée analyse l'environnement et configure les alarmes de requête et gère les échecs de mort. Elle appelle process_psgi_request une fois que la requête est prête et que les en-têtes ont été analysés.
"process_psgi_request"
Utilisée lorsque psgi_enabled est vrai. Pendant cette méthode, find_psgi_handler sera appelée pour retourner le gestionnaire de réponse psgi approprié. Une fois terminé, print_psgi_headers et print_psgi_body sont utilisés pour imprimer la réponse. Voir PSGI.

Typiquement, cette méthode ne devrait pas être remplacée. Au lieu de cela, une méthode appropriée pour trouver l'application doit être donnée à find_psgi_handler ou app.

"find_psgi_handler"
Utilisée pour rechercher le gestionnaire PSGI approprié. Une référence au hashef $env déjà analysé est passée. PATH_INFO sera initialisé à la partie chemin complet de l'URI. SCRIPT_NAME sera initialisé à la chaîne vide. Ce gestionnaire doit définir les valeurs appropriées pour SCRIPT_NAME et PATH_INFO en fonction du chemin correspondant. Une référence de code pour le gestionnaire doit être retournée. Le find_psgi_handler par défaut appellera la méthode "app". Si cela échoue, une référence au psgi_echo_handler est retournée comme application par défaut. 
sub find_psgi_handler {
    my ($self, $env) = @_;
    if ($env->{'PATH_INFO'} && $env->{'PATH_INFO'} =~ s{^ (/foo) (?= $ | /) }{}x) {
        $env->{'SCRIPT_NAME'} = $1;
        return \&foo_app;
    }
    return $self->SUPER::find_psgi_handler($env);
}
"app"
Retourne une référence à l'application servie. Ce doit être une application PSGI valide. Voir PSGI. Par défaut, elle vérifiera la valeur de l'option de configuration "app". La méthode "app" peut également être utilisée pour définir l'option de configuration "app". 
package MyApp;
use base qw(Net::Server::PSGI);
sub default_server_type { 'Prefork' }
sub my_app {
    my $env = shift;
    return [200, ['Content-type', 'text/html'], ["Hello world"]];
}
MyApp->run(app => \&my_app);
# OU
sub app { \&my_app }
MyApp->run;
# OU
my $server = MyApp->new;
$server->app(\&my_app);
$server->run;

OPTIONS

En plus des arguments de ligne de commande des classes de base de Net::Server::HTTP, vous pouvez également définir les options suivantes.

app
Doit retourner une référence de code de l'application PSGI. Est retournée par la méthode app.
