NOTE : Le RFC5952 d'août 2010 stipule :

4.3. Minuscules
Les lettres "a", "b", "c", "d", "e", et "f" dans une adresse IPv6
    doivent être représentées en minuscules.

use NetAddr::IP qw(:lower);

use NetAddr::IP qw(:upper);

* Pour définir une limite sur la quantité de nets traités ou retournés par NetAddr::IP.

Définit le nombre maximum de réseaux qui seront retournés lorsqu'une erreur NetAddr::IP est retournée, comme une puissance de 2 (valeur par défaut 16 ou 65536 réseaux). Chaque 2**16 consomme environ 4 Mo de mémoire. Un 2**20 consomme 64 Mo de mémoire, un 2**24 consomme 1 Go de mémoire.

use NetAddr::IP qw(netlimit);
netlimit 20;

Le netlimit maximum autorisé est de 2**24. Les tentatives de définition de limites inférieures à la valeur par défaut de 16 ou supérieures au maximum de 24 sont ignorées.

INSTALLATION

Décompressez la distribution dans un répertoire approprié et exécutez :

perl Makefile.PL
make
make test
make install

NetAddr::IP dépend de NetAddr::IP::Util, qui est installé par défaut avec ses fonctions principales compilées à l'aide des extensions XS de Perl pour construire une bibliothèque C. Si vous ne disposez pas d'un compilateur C ou si vous préférez utiliser le langage Perl plus lent pour d'autres raisons, exécutez :

perl Makefile.PL -noxs
make
make test
make install

DESCRIPTION

Ce module fournit une abstraction orientée objet sur les adresses IPv4 ou IPv6, permettant une manipulation aisée. La version 4.xx de NetAddr::IP fonctionne avec les anciennes versions de Perl et est compatible avec Math::BigInt.

La représentation interne de tous les objets IP est en notation IPv6 sur 128 bits. Les objets IPv4 et IPv6 peuvent être mélangés librement.

Opérateurs orientés objet

De nombreux opérateurs ont été surchargés, comme décrit ci-dessous :

Assignation ("=")
A été optimisée pour copier rapidement un objet NetAddr::IP à un autre.
"->copy()"
L'opérateur d'affectation ("=") ne s'exécute que lorsque l'objet copié est modifié par un autre opérateur surchargé. Voir SYMBOLS POUR L'UTILISATION DE overload pour plus de détails.

"->copy()" crée réellement un nouvel objet lorsqu'il est appelé.

Normalisation de chaîne
Un objet peut être utilisé simplement comme une chaîne. Par exemple, le code suivant : 
my $ip = new NetAddr::IP '192.168.1.123';
print "$ip\n";

Imprime la chaîne 192.168.1.123/32.

Équivalence
Vous pouvez vérifier l'équivalence avec "eq" ou "==". "eq" permet de comparer avec des chaînes arbitraires ainsi qu'avec des objets NetAddr::IP. L'exemple suivant : 
if (NetAddr::IP->new('127.0.0.1','255.0.0.0') eq '127.0.0.1/8')
   { print "Yes\n"; }

imprime "Yes".

La comparaison avec "==" exige que les deux opérandes soient des objets NetAddr::IP.

Si la valeur CIDR représentée par les opérandes est égale, une valeur vraie est retournée.

Comparaison via >, <, >=, <=, <=> et "cmp"
En interne, tous les objets réseau sont représentés au format 128 bits. La représentation numérique du réseau est comparée via l'opération correspondante. Les comparaisons sont d'abord tentées sur la partie adresse de l'objet et, si elles sont égales, les parties numériques des masques sont comparées. Cela conduit à un résultat contradictoire, tel que : 
/24 > /16

Il ne faut pas comparer directement les objets réseau avec des masques CIDR différents, car cela pourrait produire des résultats indéterminés ou inattendus. Au lieu de cela, pour déterminer quel bloc réseau est plus grand ou plus petit, il faut comparer :

$ip1->masklen <=> $ip2->masklen
Addition d'une valeur constante ("+")
Ajoute une valeur entière de 32 bits à la partie adresse d'un objet NetAddr. Cette opération modifie la partie adresse pour qu'elle pointe autant d'hôtes que possible au-dessus du début de l'adresse actuelle. Par exemple, ce code : 
print NetAddr::IP->new('127.0.0.1/8') + 5;

imprime 127.0.0.6/8. L'adresse fera un double saut jusqu'à la diffusion du réseau. Ce code :

print NetAddr::IP->new('10.0.0.1/24') + 255;
outputs 10.0.0.0/24.

Retourne l'objet sans modification si la valeur constante est absente ou hors limites.

2147483647 <= constant >= -2147483648
Soustraction d'une valeur constante ("-")
Le complément de l'addition d'une valeur constante.
Différence ("-")
Retourne la différence entre les parties d'adresse de deux objets NetAddr::IP. Retourne un nombre signé de 32 bits.

Retourne undef si la différence est hors limites.

Auto-incrément
L'auto-incrémentation d'un objet NetAddr::IP ajuste la partie adresse à l'adresse hôte suivante dans le sous-réseau. Elle se terminera à l'adresse de diffusion et recommencera à partir de l'adresse réseau.

Sérialisation et Désérialisation

Ce module définit des crochets pour collaborer avec Storable pour la sérialisation des objets "NetAddr::IP", via des chaînes compactes et lisibles. Vous pouvez revenir à l'ancien format en invoquant ce module comme suit :

use NetAddr::IP ':old_storable';

Vous devez le faire si vous avez des fichiers de données hérités contenant des objets NetAddr::IP stockés à l'aide du module Storable.

Méthodes

"->new([$addr, [ $mask|IPv6 ]])"
"->new6([$addr, [ $mask]])"
"->new_no([$addr, [ $mask]])"
"->new_from_aton($netaddr)"
new_cis et new_cis6 sont DÉPRÉCIÉS
"->new_cis("$addr $mask)"
"->new_cis6("$addr $mask)"
Les deux premières méthodes créent une nouvelle adresse avec l'adresse fournie dans $addr et un masque de réseau optionnel $mask, qui peut être omis pour obtenir un masque de réseau /32 ou /128 pour les adresses IPv4 / IPv6 respectivement.

La troisième méthode "new_no" est exclusivement pour les adresses IPv4 et filtre les chaînes de points quadruples mal formatées pour les zéros initiaux qui seraient normalement interprétés comme un format octal par NetAddr selon les spécifications de inet_aton.

new_from_aton prend une adresse IPv4 packée et suppose un masque /32. Cette fonction remplace la fonctionnalité :aton DÉPRÉCIÉE qui est fondamentalement défectueuse.

Les deux dernières méthodes new_cis et new_cis6 diffèrent de new et new6 uniquement en ce qu'elles acceptent la notation d'adresse Cisco courante pour les paires adresse/masque avec un espace comme séparateur au lieu d'une barre oblique (/)

Ces méthodes sont DÉPRÉCIÉES car la fonctionnalité est maintenant incluse dans les autres méthodes "new".

c'est-à-dire ->new_cis('1.2.3.0 24')
      ou
      ->new_cis6('::1.2.3.0 120')

"new6" et "new_cis6" marquent l'adresse comme étant dans l'espace d'adresses ipV6 même si le format suggérerait le contraire.

c'est-à-dire ->new6('1.2.3.4') résultera en ::102:304
les adresses soumises à ->new en notation ipV6 resteront
en notation ipV6 de façon permanente. c'est-à-dire
      ->new('::1.2.3.4') résultera en ::102:304
alors que new('1.2.3.4') s'affichera comme 1.2.3.4
Voir "STRINGIFICATION" ci-dessous.

$addr peut être presque tout ce qui peut être résolu en une adresse IP dans toutes les notations que j'ai vues au fil du temps. Il peut éventuellement contenir le masque en notation CIDR.

La notation préfixe est comprise, avec la limitation que la plage spécifiée par le préfixe doit correspondre à un sous-réseau valide.

Les adresses dans le même format retourné par "inet_aton" ou "gethostbyname" peuvent également être comprises, bien qu'aucun masque ne puisse leur être spécifié. Par défaut, ce format n'est pas tenté d'être reconnu, car il semble rarement utilisé.

"->broadcast()"
Retourne un nouvel objet se référant à l'adresse de diffusion d'un sous-réseau donné. L'adresse de diffusion a tous les bits à un dans toutes les positions de bits où le masque de réseau a des bits à zéro. Ceci est normalement utilisé pour adresser tous les hôtes d'un sous-réseau donné.
"->network()"
Retourne un nouvel objet se référant à l'adresse réseau d'un sous-réseau donné. Une adresse réseau a tous les bits à zéro là où les bits du masque de réseau sont à zéro. Normalement, cela est utilisé pour se référer à un sous-réseau.
"->addr()"
Retourne une scalaire avec la partie adresse de l'objet sous forme de chaîne texte IPv4 ou IPv6 selon le cas. Ceci est utile pour l'impression ou pour passer la partie adresse de l'objet NetAddr::IP à d'autres composants qui attendent une adresse IP. Si l'objet est une adresse ipV6 ou a été créé en utilisant ->new6($ip), il sera rapporté en format hexadécimal ipV6, sinon il sera rapporté en format point décimal uniquement s'il réside dans l'espace d'adresses ipV4.
"->mask()"
Retourne une scalaire avec le masque sous forme de chaîne texte IPv4 ou IPv6 comme décrit ci-dessus.
"->masklen()"
Retourne une scalaire représentant le nombre de bits à un dans le masque.
"->bits()"
Retourne la largeur de l'adresse en bits. Normalement 32 pour v4 et 128 pour v6.
"->version()"
Retourne la version de l'adresse ou du sous-réseau. Actuellement, cela peut être soit 4, soit 6.
"->cidr()"
Retourne une scalaire avec l'adresse et le masque en notation CIDR. Un objet NetAddr::IP se stringify vers le résultat de cette fonction. (voir les commentaires sur ->new6() et ->addr() pour les formats de sortie)
"->aton()"
Retourne la partie adresse de l'objet NetAddr::IP dans le même format que la fonction inet_aton() ou "ipv6_aton" respectivement. Si l'objet a été créé en utilisant ->new6($ip), l'adresse retournée sera toujours en format ipV6, même pour les adresses dans l'espace d'adresses ipV4.
"->range()"
Retourne une scalaire avec l'adresse de base et l'adresse de diffusion séparées par un tiret et des espaces. Ceci est appelé notation de plage.
"->prefix()"
Retourne une scalaire avec l'adresse et le masque en représentation préfixe ipV4. Ceci est utile pour certains programmes qui attendent leur entrée dans ce format. Cette méthode inclura l'adresse de diffusion dans l'encodage.
"->nprefix()"
Tout comme "->prefix()", mais n'inclut pas l'adresse de diffusion.
"->numeric()"
Lorsqu'appelé dans un contexte scalaire, retourne une représentation numérique de la partie adresse de l'adresse IP. Lorsqu'appelé dans un contexte de tableau, il retourne une liste de deux éléments. Le premier élément est tel que décrit, le second élément est la représentation numérique du masque de réseau.

Cette méthode est essentielle pour la sérialisation de la représentation d'un sous-réseau.

"->bigint()"
Lorsqu'appelé dans un contexte scalaire, retourne une représentation Math::BigInt de la partie adresse de l'adresse IP. Lorsqu'appelé dans un contexte de tableau, il retourne une liste de deux éléments. Le premier élément est tel que décrit, le second élément est la représentation Math::BigInt du masque de réseau.
"->wildcard()"
Lorsqu'appelé dans un contexte scalaire, retourne les bits joker correspondant au masque, en format point décimal ou ipV6 selon le cas.

Lorsqu'appelé dans un contexte de tableau, retourne un tableau à deux éléments. Le premier élément est la partie adresse. Le second élément est la traduction joker du masque.

"->short()"
Retourne la partie adresse dans une notation courte ou compacte. 
(par exemple, 127.0.0.1 devient 127.1).

Fonctionne avec V4 et V6.

"->canon()"
Retourne la partie adresse en notation canonique sous forme de chaîne. Pour ipV4, c'est le point décimal, et c'est le même que la valeur de retour de "->addr()". Pour ipV6, c'est conformément à la RFC5952, et c'est le même que la valeur en minuscules retournée par "->short()".
"->full()"
Retourne la partie adresse en notation FULL pour ipV4 et ipV6 respectivement. 
par exemple pour ipV4
  0000:0000:0000:0000:0000:0000:127.0.0.1
     pour ipV6
  0000:0000:0000:0000:0000:0000:0000:0000

Pour forcer les adresses ipV4 dans le format ipV6 complet, utiliser :

"->full6()"
Retourne la partie adresse en notation ipV6 COMPLÈTE
"->full6m()"
Retourne la partie masque en notation ipV6 COMPLÈTE
"$me->contains($other)"
Retourne vrai lorsque $me contient complètement $other. Faux est retourné sinon et "undef" est retourné si $me et $other ne sont pas tous deux des objets "NetAddr::IP".
"$me->within($other)"
Le complément de "->contains()". Retourne vrai lorsque $me est complètement contenu dans $other.

Notez que $me et $other doivent être des objets "NetAddr::IP".

C->is_rfc1918()>
Retourne vrai lorsque $me est une adresse RFC 1918.

NetAddr::IP - manipulation of IP addresses and networks

  use NetAddr::IP;
  my $ip = new NetAddr::IP('192.168.1.0/24');
  my $ip2 = new NetAddr::IP('10.0.0.1');
  my $ip3 = new NetAddr::IP('::1');
  my $ip4 = new NetAddr::IP('192.168.1.1');
  print $ip->addr();         # 192.168.1.0
  print $ip->mask();         # 255.255.255.0
  print $ip->cidr();         # 24
  print $ip->version();      # 4
  print $ip->addr . "/" . $ip->cidr; # 192.168.1.0/24
  print $ip->broadcast();    # 192.168.1.255
  print $ip->first();        # 192.168.1.1
  print $ip->last();         # 192.168.1.254
  print $ip->next();         # 192.168.1.1
  print $ip->prev();         # 192.168.1.254
  print $ip->hostenum();     # ( 192.168.1.1 192.168.1.2 ... )
  print $ip->contains($ip4); # 1
  my $ip5 = $ip->mask('255.255.255.192');
  print $ip5->cidr();        # 26
  my $ip6 = $ip->mask('/26');
  print $ip6->mask();        # 255.255.255.192
  my $ip7 = $ip->mask(26);
  print $ip7->mask();        # 255.255.255.192
  my $ip8 = new NetAddr::IP('192.168.1.5');
  my $ip9 = $ip->mask($ip8);
  print $ip9->cidr();        # 32
  my $ip10 = $ip->mask($ip8->addr);
  print $ip10->cidr();       # 32
  my @list = (new NetAddr::IP('192.168.1.0/25'),
              new NetAddr::IP('192.168.1.128/25'));
  my $compacted = NetAddr::IP::compact(\@list);
  print $compacted->[0]->cidr(); # 24
  my $regex = $ip->re();
  print $regex; # Matches 192.168.1.0 to 192.168.1.255
  my $regex6 = $ip3->re6();
  print $regex6; # Matches ::1

NetAddr::IP is a Perl module that allows the manipulation of IP addresses and networks.

It supports both IPv4 and IPv6 addresses.

The primary object is NetAddr::IP.

See the NetAddr::IP::Util man page for utility functions and constants.

->address_range()
Returns the number of usable IP addresses within the subnet. 
WARNING: NetAddr::IP will calculate and return a numeric string for
network ranges as large as 2**128. These values are TEXT strings and
perl can treat them as integers for numeric calculations.
Perl on 32 bit platforms only handles integer numbers up to 2**32 and
on 64 bit platforms to 2**64.
If you wish to manipulate numeric strings returned by NetAddr::IP that
are larger than 2**32 or 2**64, respectively, you must load
additional modules such as Math::BigInt, bignum or some similar
package to do the integer math.

NOTE: As of version 4.42 of NetAddr::IP and version 1.27 of NetAddr::IP::Lite a /31 and /127 with return a net num value of 2 instead of 0 (zero) for point-to-point networks.

Version 4.00 of NetAddr::IP and version 1.00 of NetAddr::IP::Lite return the number of usable IP addresses within the subnet, not counting the broadcast or network address.

Previous versions worked only for ipV4 addresses, returned a maximum span of 2**32 and returned the number of IP addresses not counting the broadcast address. (one greater than the new behavior)

To use the old behavior for ->nth($index) and ->num():

    use NetAddr::IP::Lite qw(:old_nth);
->addr()
Returns the IP address in dotted decimal notation (IPv4) or canonical (IPv6) notation.
->broadcast()
Returns a new NetAddr::IP object representing the broadcast address for the network.
->cidr()
Returns the CIDR notation mask length for the network.
->clone()
Returns a new object that is a copy of the original.
->contains($addr2)
Returns true if the current object's network contains the given $addr2. $addr2 must be a NetAddr::IP object.
->first()
Returns a new object representing the first usable IP address within the subnet (ie, the first host address).
->host()
Returns the host portion of the IP address.
->hostenum()
Returns the list of hosts within a subnet.

ERROR conditions:

    ->hostenum will DIE with the message 'netlimit exceeded'
      if the number of return objects exceeds 'netlimit'.
      See function 'netlimit' above (default 2**16 or 65536 nets).
->hostenumref()
Faster version of ->hostenum(), returning a reference to a list.

NOTE: hostenum and hostenumref report zero (0) useable hosts in a /31 network. This is the behavior expected prior to RFC 3021. To report 2 useable hosts for use in point-to-point networks, use :rfc3021 tag.

    use NetAddr::IP qw(:rfc3021);

This will cause hostenum and hostenumref to return two (2) useable hosts in a /31 network.

->is_local()
Returns true when $me is a local network address. 
      i.e.    ipV4    127.0.0.0 - 127.255.255.255
or            ipV6    === ::1
->is_private()
Returns true when the IP address belongs to one of the private network ranges defined by RFC 1918 and others.
->last()
Returns a new object representing the last usable IP address within the subnet (ie, one less than the broadcast address).
->mask($mask)
Returns a new NetAddr::IP object with the mask applied. $mask can be a CIDR notation (e.g. 26), a dot quad mask (e.g. 255.255.255.192), an IP address (e.g. 192.168.1.200), or another NetAddr::IP object.
->masklen()
Returns the mask length in bits.
->next()
Returns the next IP address.
->num()
As of version 4.42 of NetAddr::IP and version 1.27 of NetAddr::IP::Lite a /31 and /127 with return a net num value of 2 instead of 0 (zero) for point-to-point networks.

Version 4.00 of NetAddr::IP and version 1.00 of NetAddr::IP::Lite return the number of usable IP addresses within the subnet, not counting the broadcast or network address.

Previous versions worked only for ipV4 addresses, returned a maximum span of 2**32 and returned the number of IP addresses not counting the broadcast address. (one greater than the new behavior)

To use the old behavior for ->nth($index) and ->num():

    use NetAddr::IP::Lite qw(:old_nth);

WARNING:

NetAddr::IP will calculate and return a numeric string for network ranges as large as 2**128. These values are TEXT strings and perl can treat them as integers for numeric calculations.

Perl on 32 bit platforms only handles integer numbers up to 2**32 and on 64 bit platforms to 2**64.

If you wish to manipulate numeric strings returned by NetAddr::IP that are larger than 2**32 or 2**64, respectively, you must load additional modules such as Math::BigInt, bignum or some similar package to do the integer math.

->re6()
Returns a Perl regular expression that will match an IP address within the given subnet. Always returns an ipV6 regex.
->short()
Returns the shortest string representation of the IP address or network. e.g. 
  192.168.0.1/24      => 192.168.0.0/24
  ::1                 => ::1
  2001:db8:0:0:0:0:0:0/64 => 2001:db8::/64
->split($bits,[optional $bits1,$bits2,...])
Similar to ->splitref above but returns the list rather than a list reference. You may not want to use this if a large number of objects is expected.
->splitref($bits,[optional $bits1,$bits2,...])
Returns a reference to a list of objects, representing subnets of "bits" mask produced by splitting the original object, which is left unchanged. Note that $bits must be longer than the original mask in order for it to be splittable.

ERROR conditions:

    ->splitref will DIE with the message 'netlimit exceeded'
      if the number of return objects exceeds 'netlimit'.
      See function 'netlimit' above (default 2**16 or 65536 nets).
    ->splitref returns undef when C<bits> or the (bits list)
      will not fit within the original object.
    ->splitref returns undef if a supplied ipV4, ipV6, or NetAddr
      mask in inappropriately formatted,

bits may be a CIDR mask, a dot quad or ipV6 string or a NetAddr::IP object. If "bits" is missing, the object is split for into all available addresses within the ipV4 or ipV6 object ( auto-mask of CIDR 32, 128 respectively ).

With optional additional "bits" list, the original object is split into parts sized based on the list. NOTE: a short list will replicate the last item. If the last item is too large to for what remains of the object after splitting off the first parts of the list, a "best fits" list of remaining objects will be returned based on an increasing sort of the CIDR values of the "bits" list.

    i.e.  my $ip = new NetAddr::IP('192.168.0.0/24');
          my $objptr = $ip->split(28, 29, 28, 29, 26);
     has split plan 28 29 28 29 26 26 26 28
     and returns this list of objects
          192.168.0.0/28
          192.168.0.16/29
          192.168.0.24/28
          192.168.0.40/29
          192.168.0.48/26
          192.168.0.112/26
          192.168.0.176/26
          192.168.0.240/28

NOTE: that /26 replicates twice beyond the original request and /28 fills the remaining return object requirement.

->rsplit($bits,[optional $bits1,$bits2,...])
Similar to ->rsplitref above but returns the list rather than a list reference. You may not want to use this if a large number of objects is expected.
->rsplitref($bits,[optional $bits1,$bits2,...])

$me->compact($addr1, $addr2, ...)
@compacted_object_list = Compact(@object_list)
Given a list of objects (including $me), this method will compact all the addresses and subnets into the largest (ie, least specific) subnets possible that contain exactly all of the given objects.

Note that in versions prior to 3.02, if fed with the same IP subnets multiple times, these subnets would be returned. From 3.02 on, a more "correct" approach has been adopted and only one address would be returned.

Note that $me and all $addr's must be "NetAddr::IP" objects.

$me->compactref(\@list)
$compacted_object_list = Compact(\@list)
As usual, a faster version of ->compact() that returns a reference to a list. Note that this method takes a reference to a list instead.

Note that $me must be a "NetAddr::IP" object.

$me->coalesce($masklen, $number, @list_of_subnets)
$arrayref = Coalesce($masklen,$number,@list_of_subnets)
Will return a reference to list of "NetAddr::IP" subnets of $masklen mask length, when $number or more addresses from @list_of_subnets are found to be contained in said subnet.

Subnets from @list_of_subnets with a mask shorter than $masklen are passed "as is" to the return list.

Subnets from @list_of_subnets with a mask longer than $masklen will be counted (actually, the number of IP addresses is counted) towards $number.

Called as a method, the array will include $me.

WARNING: the list of subnet must be the same type. i.e ipV4 or ipV6

->nth($index)
Returns a new object representing the n-th usable IP address within the subnet (ie, the n-th host address). If no address is available (for example, when the network is too small for $index hosts), "undef" is returned.

Version 4.00 of NetAddr::IP and version 1.00 of NetAddr::IP::Lite implements ->nth($index) and ->num() exactly as the documentation states. Previous versions behaved slightly differently and not in a consistent manner. See the README file for details.

To use the old behavior for ->nth($index) and ->num():

    use NetAddr::IP::Lite qw(:old_nth);
    old behavior:
    NetAddr::IP->new('10/32')->nth(0) == undef
    NetAddr::IP->new('10/32')->nth(1) == undef
    NetAddr::IP->new('10/31')->nth(0) == undef
    NetAddr::IP->new('10/31')->nth(1) == 10.0.0.1/31
    NetAddr::IP->new('10/30')->nth(0) == undef
    NetAddr::IP->new('10/30')->nth(1) == 10.0.0.1/30
    NetAddr::IP->new('10/30')->nth(2) == 10.0.0.2/30
    NetAddr::IP->new('10/30')->nth(3) == 10.0.0.3/30

Note that in each case, the broadcast address is represented in the output set and that the 'zero'th index is alway undef except for a point-to-point /31 or /127 network where there are exactly two addresses in the network.

    new behavior:
    NetAddr::IP->new('10/32')->nth(0)  == 10.0.0.0/32
    NetAddr::IP->new('10.1/32'->nth(0) == 10.0.0.1/32
    NetAddr::IP->new('10/31')->nth(0)  == 10.0.0.0/31
    NetAddr::IP->new('10/31')->nth(1)  == 10.0.0.1/31
    NetAddr::IP->new('10/30')->nth(0) == 10.0.0.1/30
    NetAddr::IP->new('10/30')->nth(1) == 10.0.0.2/30
    NetAddr::IP->new('10/30')->nth(2) == undef

Note that a /32 net always has 1 usable address while a /31 has exactly two usable addresses for point-to-point addressing. The first index (0) returns the address immediately following the network address except for a /31 or /127 when it return the network address.

Private network ranges:

10.0.0.0      -   10.255.255.255  (10/8 prefix)
172.16.0.0    -   172.31.255.255  (172.16/12 prefix)
192.168.0.0   -   192.168.255.255 (192.168/16 prefix)
