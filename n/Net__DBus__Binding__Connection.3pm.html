Net::DBus::Binding::Connection(3) Documentation fournie par les utilisateurs de Perl Net::DBus::Binding::Connection(3)

NAME

Net::DBus::Binding::Connection - Connexion entre client et serveur

SYNOPSIS

Créer une connexion à un serveur et envoyer un message

use Net::DBus::Binding::Connection;
my $con = Net::DBus::Binding::Connection->new(address => "unix:/path/to/socket");
$con->send($message);

Enregistrer des gestionnaires de messages

sub handle_something {
    my $con = shift;
    my $msg = shift;
    ... faire quelque chose avec le message...
}
$con->register_message_handler(
  "/some/object/path",
  \&handle_something);

Se joindre à une boucle d'événements :

my $reactor = Net::DBus::Binding::Reactor->new();
$reactor->manage($con);
$reactor->run();

DESCRIPTION

Une connexion sortante vers un serveur, ou une connexion entrante d'un client. Les méthodes définies dans ce module correspondent étroitement aux méthodes dbus_connection_XXX de l'API C. Pour plus de détails sur leur comportement, il peut être utile de consulter la documentation de l'API C.

MÉTHODES

my $con = Net::DBus::Binding::Connection->new(address => "unix:/path/to/socket");
Crée une nouvelle connexion vers le serveur spécifié dans le paramètre "address". Si le paramètre "private" est spécifié et défini à une valeur vraie, la connexion ouverte est privée ; sinon, une connexion partagée est ouverte. Une connexion privée doit être fermée explicitement avec la méthode "disconnect" avant que la dernière référence à l'objet ne soit libérée. Une connexion partagée ne doit jamais être fermée explicitement.
$status = $con->is_connected();
Retourne zéro si la connexion a été déconnectée, sinon une valeur positive.
$status = $con->is_authenticated();
Retourne zéro si la connexion n'a pas encore terminé l'authentification avec succès, sinon une valeur positive.
$con->disconnect()
Ferme cette connexion vers l'hôte distant. Cette méthode est appelée automatiquement lors de la récupération des objets (c'est-à-dire dans la méthode DESTROY) si le programmeur omet explicitement la déconnexion.
$con->flush()
Arrête l'exécution jusqu'à ce que toutes les données dans le pipeline de sortie aient été envoyées. Cette méthode ne ré-entre pas dans la boucle d'événements de l'application.
$con->send($message)
Met en file d'attente un message à envoyer à l'hôte distant. Les données sont envoyées de manière asynchrone selon la boucle d'événements de l'application. Pour forcer l'envoi immédiat des données, suivez cette méthode par un appel à "flush". Cette méthode retournera le numéro de séquence du message, qui peut être utilisé pour identifier un message ultérieur (si possible).
my $reply = $con->send_with_reply_and_block($msg, $timeout);
Met en file d'attente un message à envoyer à l'hôte distant et bloque jusqu'à ce que le message ait été envoyé et qu'une réponse correspondante ait été reçue. La valeur retournée par cette méthode sera un objet "Net::DBus::Binding::Message::MethodReturn" ou "Net::DBus::Binding::Message::Error".
my $pending_call = $con->send_with_reply($msg, $timeout);
Met en file d'attente un message à envoyer à l'hôte distant et retourne immédiatement une référence vers un objet "Net::DBus::Binding::PendingCall". Cet objet peut être utilisé pour attendre/observer une réponse. Cela permet de traiter les méthodes de manière asynchrone.
$con->dispatch;
Déclenche tout message en attente dans la file d'attente d'entrée vers ses gestionnaires de messages. Cette méthode est généralement appelée à chaque itération de la boucle d'événements principale où des données ont été lues à partir de la file d'attente d'entrée.
$message = $con->borrow_message
Retire temporairement le premier message de la file d'attente des messages entrants. Aucun autre fil d'exécution ne peut accéder au message pendant qu'il est 'emprunté', vous devez donc le remplacer avec la méthode "return_message" ou le supprimer définitivement avec la méthode "steal_message" dès que possible.
$con->return_message($msg)
Remplace un message précédemment emprunté dans la file d'attente des messages entrants pour un déploiement ultérieur aux gestionnaires enregistrés.
$con->steal_message($msg)
Supprime définitivement un message emprunté de la file d'attente des messages entrants. Aucun autre gestionnaire enregistré ne sera exécuté pour ce message.
$msg = $con->pop_message();
Supprime définitivement le premier message de la file d'attente des messages entrants, sans exécuter de gestionnaire enregistré. Si vous êtes connecté à une boucle d'événements (comme "Net::DBus::Binding::Reactor"), vous ne voudrez probablement pas appeler cette méthode.
$con->set_watch_callbacks(\&add_watch, \&remove_watch, \&toggle_watch);
Enregistre un ensemble de callbacks pour ajouter, supprimer et mettre à jour les watchers dans la boucle d'événements de l'application. Chaque paramètre doit être une référence à une sous-routine, qui à chaque invocation recevra deux paramètres, l'objet de connexion et l'objet de watcher. Si vous utilisez un objet "Net::DBus::Binding::Reactor" comme boucle d'événements de l'application, la méthode 'manage' de cet objet appellera cette méthode pour vous.
$con->set_timeout_callbacks(\&add_timeout, \&remove_timeout, \&toggle_timeout);
Enregistre un ensemble de callbacks pour ajouter, supprimer et mettre à jour les minuteurs dans la boucle d'événements de l'application. Chaque paramètre doit être une référence à une sous-routine, qui à chaque invocation recevra deux paramètres, l'objet de connexion et le minuteur. Si vous utilisez un objet "Net::DBus::Binding::Reactor" comme boucle d'événements de l'application, la méthode 'manage' de cet objet appellera cette méthode pour vous.
$con->register_object_path($path, \&handler)
Enregistre un gestionnaire pour les messages dont le chemin correspond au chemin spécifié dans le paramètre $path. La référence de la sous-routine fournie sera appelée avec deux paramètres, l'objet de connexion sur lequel le message a été reçu et le message à traiter (un objet de la classe "Net::DBus::Binding::Message").
$con->unregister_object_path($path)
Désenregistre le gestionnaire associé au chemin d'objet $path. Le gestionnaire aurait été précédemment enregistré avec les méthodes "register_object_path" ou "register_fallback".
$con->register_fallback($path, \&handler)
Enregistre un gestionnaire pour les messages dont le chemin commence par le préfixe spécifié dans le paramètre $path. La référence de la sous-routine fournie sera appelée avec deux paramètres, l'objet de connexion sur lequel le message a été reçu et le message à traiter (un objet de la classe "Net::DBus::Binding::Message").
$con->set_max_message_size($bytes)
Définit la taille maximale autorisée pour un seul message entrant. Les messages dépassant cette limite seront rejetés avant de dépasser le seuil. La taille du message est spécifiée en octets.
$bytes = $con->get_max_message_size();
Récupère la taille maximale autorisée pour les messages entrants. La taille retournée est mesurée en octets.
$con->set_max_received_size($bytes)
Définit la taille maximale de la file d'attente des messages entrants. Une fois ce seuil dépassé, aucun autre message ne sera lu avant qu'un ou plusieurs des messages existants ne soient envoyés à leurs gestionnaires enregistrés. L'implication est que la file d'attente des messages peut dépasser ce seuil d'un maximum de la taille d'un message.
$bytes $con->get_max_received_size()
Récupère la taille maximale de la file d'attente des messages entrants. La taille retournée est mesurée en octets.
$con->add_filter($coderef);
Ajoute un filtre à la connexion qui sera appelé chaque fois qu'un message est reçu. Le $coderef doit être une référence à une sous-routine, qui retourne une valeur vraie si le message doit être filtré, ou une valeur fausse si le déploiement normal du message doit continuer.

Net::DBus::Binding::Connection(3pm)

NAME

Net::DBus::Binding::Connection - DBUS connection object

SYNOPSIS

  use Net::DBus::Binding;

  my $bus = Net::DBus::Binding::Bus->get_session();
  my $con = $bus->get_connection();

  # ... do things with $con ...

DESCRIPTION

The Net::DBus::Binding::Connection object represents a connection to a DBUS message bus. You can send and receive DBUS messages on this connection.

This is a low level object, you normally do not need to interact with this directly. The higher level Net::DBus::Connection class provides a more convenient API.

METHODS

my $con = Net::DBus::Binding::Bus->get_session
Get the connection to the session bus.
my $con = Net::DBus::Binding::Bus->get_system
Get the connection to the system bus.
my $con = $con->clone
Create a new connection object that is a clone of the existing one. This is useful for multi-threaded applications, where you can have a separate connection object per thread. The underlying connection to the DBUS bus is shared.
my $msg = $con->make_raw_message($rawmsg)
Crée un nouveau message, en l'initialisant à partir de l'objet de message C de bas niveau fourni par le paramètre $rawmsg. L'objet retourné sera transtypé vers la sous-classe appropriée de Net::DBus::Binding::Message.
my $msg = $con->make_error_message( replyto => $method_call, name => $name, description => $description);
Crée un nouveau message, représentant une erreur qui s'est produite lors du traitement de l'objet d'appel de méthode passé comme paramètre "replyto". Le paramètre "name" est le nom formel de la condition d'erreur, tandis que la "description" est un court texte donnant des informations plus spécifiques sur l'erreur.
my $call = $con->make_method_call_message( $service_name, $object_path, $interface, $method_name);
Crée un message représentant un appel sur l'objet situé au chemin $object_path dans le client possédant le nom bien connu donné par $service_name. La méthode à invoquer a le nom $method_name dans l'interface spécifiée par le paramètre $interface.
my $msg = $con->make_method_return_message( replyto => $method_call);
Crée un message représentant une réponse à l'appel de méthode passé dans le paramètre "replyto".
my $signal = $con->make_signal_message( object_path => $path, interface => $interface, signal_name => $name);
Crée un nouveau message, représentant un signal [à émettre] par l'objet situé sous le chemin donné par le paramètre "object_path". Le nom du signal est donné par le paramètre "signal_name", et est limité à l'interface donnée par le paramètre "interface".
