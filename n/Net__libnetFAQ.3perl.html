Obtenir et installer libnet

Qu'est-ce que libnet ?

libnet est une collection de modules perl5 qui sont tous liés à la programmation réseau. La majorité des modules disponibles fournissent le côté client des protocoles serveur-client populaires utilisés dans la communauté Internet.

Quelle version de perl ai-je besoin ?

Cette version de libnet nécessite Perl 5.8.1 ou supérieur.

Quels autres modules ai-je besoin ?

Aucun module non essentiel n'est requis pour une utilisation normale, sauf sur os390, qui nécessite Convert::EBCDIC.

Authen::SASL est requis pour le support AUTH.

IO::Socket::SSL version 2.007 ou supérieure est requis pour le support SSL.

IO::Socket::IP version 0.25 ou IO::Socket::INET6 version 2.62 est requis pour le support IPv6.

Quelles machines supportent libnet ?

libnet elle-même est une distribution entièrement en code Perl, donc elle devrait fonctionner sur n'importe quelle machine sur laquelle Perl s'exécute.

Où puis-je obtenir la dernière version de libnet

La dernière version de libnet est toujours sur CPAN, vous la trouverez à

https://metacpan.org/release/libnet

Utilisation de Net::FTP

Comment télécharger des fichiers depuis un serveur FTP ?

Un exemple tiré d'un article posté sur comp.lang.perl.misc

#!/votre/chemin/vers/perl
# un module qui facilite la vie
use Net::FTP;
# pour le débogage : $ftp = Net::FTP->new('site','Debug',10);
# ouvrir une connexion et se connecter !
$ftp = Net::FTP->new('site_cible.quelque.xxx');
$ftp->login('nom_utilisateur','mot_de_passe');
# régler le mode de transfert en binaire
$ftp->binary();
# changer de répertoire sur le site ftp
$ftp->cwd('/quel/chemin/vers/quelque/part/');
foreach $nom ('fichier1', 'fichier2', 'fichier3') {
# les arguments de get sont dans l'ordre suivant :
# nom du fichier sur le serveur ftp
# nom du fichier à enregistrer lors du transfert sur la machine locale
# peut être simplement utilisé comme get($nom) si vous voulez le même nom
  $ftp->get($nom,$nom);
}
# ftp terminé !
$ftp->quit;

Comment transférer des fichiers en mode binaire ?

Pour transférer des fichiers sans traduction de <LF><CR> Net::FTP fournit la méthode "binary"

$ftp->binary;

Comment puis-je changer les permissions d'un fichier sur un serveur distant ?

Le protocole FTP ne dispose pas d'une commande pour changer les permissions d'un fichier sur le serveur distant. Mais certains serveurs ftp peuvent autoriser l'émission d'une commande chmod via une commande SITE, par exemple

$ftp->quot('site chmod 0777',$nom_fichier);

Mais cela n'est pas garanti de fonctionner.

Changer de répertoire vers "" ne fait pas échouer ?

Passer un argument de "" à ->cwd() a le même effet que d'appeler ->cwd() sans aucun argument. Activez le Débogage (Voir ci-dessous) et vous verrez ce qui se passe

$ftp = Net::FTP->new($hote, Debug => 1);
$ftp->login;
$ftp->cwd("");

donne

Net::FTP=GLOB(0x82196d8)>>> CWD /
Net::FTP=GLOB(0x82196d8)<<< 250 CWD command successful.

Je suis derrière un pare-feu SOCKS, mais l'option Firewall ne fonctionne pas ?

L'option Firewall concerne uniquement un type de pare-feu. Le type supporté est un proxy ftp.

Pour utiliser Net::FTP, ou tout autre module de la distribution libnet, à travers un pare-feu SOCKS, vous devez créer un exécutable perl "socksifié" en compilant Perl avec la bibliothèque socks.

Je suis derrière un pare-feu proxy FTP, mais je ne peux pas accéder aux machines externes ?

Net::FTP implémente l'approche la plus populaire des pare-feux proxy FTP. Le schéma implémenté est celui où vous vous connectez au pare-feu avec "utilisateur@nom_hote"

J'ai entendu parler d'un autre type de pare-feu qui nécessite une connexion au pare-feu avec un compte, puis une seconde connexion avec "utilisateur@nom_hote". Vous pouvez toujours utiliser Net::FTP pour traverser ces pare-feux, mais une approche plus manuelle doit être adoptée, par exemple

UTILISATION DE Net::SMTP

Pourquoi la partie d'une adresse e-mail après le @ ne peut-elle pas être utilisée comme nom d'hôte ?

La partie après le @ dans une adresse e-mail n'est pas nécessairement un nom d'hôte, mais un domaine de messagerie. Pour trouver le nom d'un hôte auquel se connecter pour un domaine de messagerie, il faut effectuer une recherche DNS MX.

Pourquoi Net::SMTP n'effectue-t-il pas de recherches DNS MX ?

Net::SMTP implémente le protocole SMTP. La recherche DNS MX ne fait pas partie de ce protocole.

La méthode verify retourne-t-elle toujours true ?

Bien que cela puisse sembler le cas, ce n'est pas le cas. La méthode verify retourne true si la commande a réussi. Si vous lui passez une adresse que le serveur devrait normalement transférer à une autre machine, la commande sera exécutée avec quelque chose comme :

252 Couldn't verify <someone@there> but will attempt delivery anyway

Cette commande échouera uniquement si vous lui passez une adresse dans un domaine que le serveur livre directement et que cette adresse n'existe pas.

DÉBOGAGE DE SCRIPTS

Comment puis-je déboguer mes scripts qui utilisent les modules Net::* ?

La plupart des classes clientes de libnet permettent de passer des options au constructeur. Dans la plupart des cas, une option est nommée "Debug". Passer cette option avec une valeur non nulle active une journalisation du protocole, qui sera envoyée à STDERR. Cette journalisation peut être utile pour voir quels commandes sont envoyées au serveur distant et quelles réponses sont reçues.

#!/your/path/to/perl
use Net::FTP;
my $ftp = new Net::FTP($host, Debug => 1);
$ftp->login('gbarr','password');
$ftp->quit;

Ce script affichera quelque chose comme :

Net::FTP: Net::FTP(2.22)
Net::FTP:   Exporter
Net::FTP:   Net::Cmd(2.0801)
Net::FTP:   IO::Socket::INET
Net::FTP:     IO::Socket(1.1603)
Net::FTP:       IO::Handle(1.1504)
Net::FTP=GLOB(0x8152974)<<< 220 imagine FTP server (Version wu-2.4(5) Tue Jul 29 11:17:18 CDT 1997) ready.
Net::FTP=GLOB(0x8152974)>>> user gbarr
Net::FTP=GLOB(0x8152974)<<< 331 Password required for gbarr.
Net::FTP=GLOB(0x8152974)>>> PASS ....
Net::FTP=GLOB(0x8152974)<<< 230 User gbarr logged in.  Access restrictions apply.
Net::FTP=GLOB(0x8152974)>>> QUIT
Net::FTP=GLOB(0x8152974)<<< 221 Goodbye.

Les lignes initiales indiquent les bibliothèques que Net::FTP utilise et leurs versions. Ces informations sont utiles pour moi lorsqu'un utilisateur signale un bogue. Les sept dernières lignes montrent la communication avec le serveur. Chaque ligne comporte trois parties. La première partie est l'objet lui-même, utile pour séparer la sortie si vous utilisez plusieurs objets. La deuxième partie est soit <<<<<<> pour indiquer des données provenant du serveur, soit <>>>>>> pour indiquer des données envoyées au serveur. Le reste de la ligne est la commande envoyée ou la réponse reçue.
