NOM

Net::Server::Proto::SSL - Protocole SSL pour Net::Server.

SYNOPSIS

Jusqu'à cette version, il était préférable d'utiliser le module Net::Server::Proto::SSLEAY. Les versions récentes incluent du code qui dépasse les limitations d'origine.

Voir Net::Server::Proto. Voir Net::Server::Proto::SSLEAY.

use base qw(Net::Server::HTTP);
main->run(
    proto => 'ssl',
    SSL_key_file  => "/chemin/vers/mon/fichier.key",
    SSL_cert_file => "/chemin/vers/mon/fichier.crt",
);
# OU
sub SSL_key_file  { "/chemin/vers/mon/fichier.key" }
sub SSL_cert_file { "/chemin/vers/mon/fichier.crt" }
main->run(proto = 'ssl');
# OU
main->run(
    port => [443, 8443, "80/tcp"],  # se connecter à deux ports ssl et un port tcp
    proto => "ssl",       # utiliser ssl comme défaut
    ipv  => "*",          # se connecter aux interfaces IPv4 et IPv6
    SSL_key_file  => "/chemin/vers/mon/fichier.key",
    SSL_cert_file => "/chemin/vers/mon/fichier.crt",
);
# OU
main->run(port => [{
    port  => "443",
    proto => "ssl",
    # ipv => 4, # par défaut - ne fait que IPv4
    SSL_key_file  => "/chemin/vers/mon/fichier.key",
    SSL_cert_file => "/chemin/vers/mon/fichier.crt",
}, {
    port  => "8443",
    proto => "ssl",
    ipv   => "*", # IPv4 et IPv6
    SSL_key_file  => "/chemin/vers/mon/fichier2.key", # clé séparée
    SSL_cert_file => "/chemin/vers/mon/fichier2.crt", # certificat séparé
    SSL_foo => 1, # Toute clé préfixée par SSL_ passée en tant que hachage de port
                  # la clé/valeur sera automatiquement passée à IO::Socket::SSL
}]]);

DESCRIPTION

Module de protocole pour Net::Server basé sur IO::Socket::SSL. Ce module implémente une couche de socket sécurisée sur tcp (également appelée SSL) via le module IO::Socket::SSL. Si ce module ne fonctionne pas dans votre cas, veuillez également considérer l'utilisation du protocole SSLEAY (Net::Server::Proto::SSLEAY) qui interagit directement avec Net::SSLeay. Voir Net::Server::Proto.

Si vous savez que votre serveur n'aura besoin que d'IPv4 (ce qui est le défaut pour Net::Server), vous pouvez charger IO::Socket::SSL en mode inet4, ce qui l'empêchera d'utiliser Socket6, IO::Socket::IP, ou IO::Socket::INET6 car ils représenteraient une surcharge supplémentaire et inutile.

use IO::Socket::SSL qw(inet4);
use base qw(Net::Server::Fork);
__PACKAGE__->run(proto => "ssl");

PARAMÈTRES

En plus des paramètres normaux de Net::Server, tous les paramètres SSL de IO::Socket::SSL peuvent également être spécifiés. Voir IO::Socket::SSL pour des informations sur la configuration. Tous les arguments préfixés par SSL_ seront passés à la méthode IO::Socket::SSL->configure.

BOGUES

Jusqu'à la version 2 de Net::Server, Net::Server::Proto::SSL utilisait la méthode d'acceptation par défaut de IO::Socket::SSL. Cette ancienne approche introduit une vulnérabilité DDOS dans le serveur, où le socket est accepté, mais le serveur parent doit ensuite bloquer jusqu'à ce que le client négocie la connexion SSL. Cela a maintenant été résolu en remplaçant la méthode d'acceptation et en acceptant la négociation SSL après que le socket parent ait eu la possibilité de revenir à l'écoute.

LICENCE

Distribué sous les mêmes termes que Net::Server

REMERCIEMENTS

Merci à Vadim d'avoir signalé que IO::Socket::SSL::accept renvoyait des objets bénis dans la mauvaise classe.
