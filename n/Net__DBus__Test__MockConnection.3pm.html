NOM

Net::DBus::Test::MockConnection - Simule une connexion au bus pour les tests unitaires

SYNOPSIS

use Net::DBus;
my $bus = Net::DBus->test
# Enregistre un service et l'objet à tester
use MyObject
my $service = $bus->export_service("org.example.MyService");
my $object = MyObject->new($service);
# Acquiert le service et effectue les tests
my $remote_service = $bus->get_service('org.example.MyService');
my $remote_object = $service->get_object("/org/example/MyObjct");
# Ceci parcourt la connexion simulée, invoquant finalement
# 'testSomething' sur l'objet $object ci-dessus.
$remote_object->testSomething()

DESCRIPTION

Cet objet fournit une implémentation factice de Net::DBus::Binding::Connection, permettant de simuler un bus de messages entièrement en mémoire. Il est destiné à faciliter la création de tests unitaires pour des services qui devraient autrement appeler d'autres objets sur un bus de messages réel. Il est utilisé en conjonction avec le module Net::DBus::Test::MockObject, qui est la manière de fournir des objets factices sur le bus factice.

MÉTHODES

mon $con = Net::DBus::Test::MockConnection->new()
Crée une nouvelle instance d'objet de connexion simulée. Il n'est généralement pas nécessaire de créer directement des instances de cet objet ; à la place, la méthode "test" de l'objet Net::DBus peut être utilisée pour obtenir une référence vers un bus de test.
$con->send($message)
Envoie un message sur la connexion simulée. Si le message est un appel de méthode, il sera directement distribué à tout objet simulé correspondant enregistré. Si le message est une erreur ou un retour de méthode, il sera disponible comme valeur de retour pour la méthode "send_with_reply_and_block". Si le message est un signal, il sera mis en file d'attente pour traitement par la méthode "dispatch".
$bus->request_name($service_name)
Simule l'envoi d'une requête au bus pour enregistrer le nom bien connu spécifié dans le paramètre $service_name. En réalité, ce n'est qu'une opération vide donnant l'impression que le nom a été enregistré avec succès.
mon $reply = $con->send_with_reply_and_block($msg)
Envoie un message sur la connexion simulée et attend une réponse. Le $msg doit être une instance de "Net::DBus::Binding::Message::MethodCall" et la réponse $reply sera une instance de "Net::DBus::Binding::Message::MethodReturn". Il est également possible qu'une erreur soit levée, l'erreur levée étant blessée dans la classe "Net::DBus::Error".
$con->dispatch;
Traite tous les messages en attente dans la file d'attente entrante pour les envoyer à leurs gestionnaires de messages. Cette méthode doit être appelée par les suites de tests chaque fois qu'elles prévoient des signaux en attente à traiter.
$con->add_filter($coderef);
Ajoute un filtre à la connexion qui sera invoqué chaque fois qu'un message est reçu. Le $coderef doit être une référence à une sous-routine, qui renvoie une valeur vraie si le message doit être filtré, ou une valeur fausse si le traitement normal du message doit être effectué.
$bus->add_match($rule)
Enregistre une règle de correspondance de signal auprès du contrôleur de bus, permettant aux signaux diffusés correspondants d'être acheminés vers ce client. En réalité, ce n'est qu'une opération vide donnant l'impression que la correspondance a été enregistrée avec succès.
$bus->remove_match($rule)
Désenregistre une règle de correspondance de signal auprès du contrôleur de bus, empêchant ainsi d'autres signaux diffusés d'être acheminés vers ce client. En réalité, ce n'est qu'une opération vide donnant l'impression que la correspondance a été désenregistrée avec succès.
$con->register_object_path($path, \&handler)
Enregistre un gestionnaire pour les messages dont le chemin correspond à celui spécifié dans le paramètre $path. Le code de référence fourni sera invoqué avec deux paramètres : l'objet de connexion sur lequel le message a été reçu et le message à traiter (une instance de la classe "Net::DBus::Binding::Message").
$con->register_fallback($path, \&handler)
Enregistre un gestionnaire pour les messages dont le chemin commence par le préfixe spécifié dans le paramètre $path. Le code de référence fourni sera invoqué avec deux paramètres : l'objet de connexion sur lequel le message a été reçu et le message à traiter (une instance de la classe "Net::DBus::Binding::Message").
$con->unregister_object_path($path)
Désenregistre le gestionnaire associé au chemin d'objet $path. Le gestionnaire aurait été précédemment enregistré avec les méthodes "register_object_path" ou "register_fallback".
mon $msg = $con->make_error_message($replyto, $name, $description)
Crée un nouveau message représentant une erreur survenue lors du traitement de l'objet d'appel de méthode passé comme paramètre $replyto. Le paramètre $name est le nom formel de la condition d'erreur, tandis que $description est un court texte donnant des informations plus spécifiques sur l'erreur.
mon $call = $con->make_method_call_message( $service_name, $object_path, $interface, $method_name);
Crée un message représentant un appel sur l'objet situé au chemin $object_path chez le client possédant le nom bien connu donné par $service_name. La méthode à invoquer porte le nom $method_name au sein de l'interface spécifiée par le paramètre $interface.
mon $msg = $con->make_method_return_message($replyto)
Crée un message représentant une réponse au message d'appel de méthode passé dans le paramètre $replyto.
mon $msg = $con->make_signal_message($object_path, $interface, $signal_name);
Crée un nouveau message représentant un signal [qui doit être] émis par l'objet situé sous le chemin donné par le paramètre $object_path. Le nom du signal est donné par le paramètre $signal_name, et est délimité par l'interface donnée par le paramètre $interface.

BOGUES

Il ne réplique pas complètement l'API de Net::DBus::Binding::Connection, juste assez pour que les liaisons de haut niveau fonctionnent dans un scénario de test.
