NOM

Net::LDAP::Control::ProxyAuth - Objet de contrôle d'autorisation de proxy LDAPv3

SYNTAXE

use Net::LDAP;
use Net::LDAP::Control::ProxyAuth;
$ldap = Net::LDAP->new( "ldap.mydomain.eg" );
$auth = Net::LDAP::Control::ProxyAuth->new( authzID => 'dn:cn=me,ou=people,o=myorg.com' );
@args = ( base     => "cn=subnets,cn=sites,cn=configuration,$BASE_DN",
          scope    => "subtree",
          filter   => "(objectClass=subnet)",
          callback => \&process_entry, # Appeler cette sous-routine pour chaque entrée
          control  => [ $auth ],
);
while (1) {
  # Effectuer la recherche
  my $mesg = $ldap->search( @args );
  # Continuer uniquement en cas de succès LDAP
  $mesg->code and last;
}

DESCRIPTION

"Net::LDAP::Control::ProxyAuth" fournit une interface pour la création et la manipulation d'objets qui représentent le "Contrôle d'autorisation de proxy" tel que décrit par la RFC 4370.

Il permet à un client d'être lié à un serveur LDAP avec sa propre identité, mais d'effectuer des opérations pour le compte d'un autre utilisateur, l'"authzID".

À l'exception de toute extension qui provoque un changement dans l'authentification, l'autorisation ou la confidentialité des données, un seul "Contrôle d'autorisation de proxy" peut être inclus dans toute opération de recherche, comparaison, modification, ajout, suppression, moddn ou opération étendue.

Comme requis par la RFC, la criticité de ce contrôle est automatiquement définie sur VRAI afin de protéger les clients contre la soumission de requêtes avec des identités autres que celles qu'ils ont l'intention d'utiliser.

ARGUMENTS DU CONSTRUCTEUR

En plus des arguments du constructeur décrits dans Net::LDAP::Control, les arguments suivants sont fournis.

authzID
L'authzID requis. C'est l'identité que nous demandons aux opérations d'utiliser.
proxyDN
Dans les premières versions des brouillons de la RFC 4370, draft-weltman-ldapv3-proxy-XX.txt, la valeur dans le contrôle et donc l'argument du constructeur était un DN et s'appelait "proxyDN". Il servait le même but que "authzID" dans les versions récentes du contrôle "proxyAuthorization".

Veuillez noter : Malheureusement, l'OID et l'encodage du "Contrôle d'autorisation de proxy" ont changé de manière significative entre les premières versions de draft-weltman-ldapv3-proxy-XX.txt et la RFC finale. Net::LDAP::Control::ProxyAuth essaie de gérer cette situation et modifie l'OID et l'encodage utilisés en fonction de l'argument du constructeur.

Avec "proxyDN" comme argument de constructeur, l'ancien OID et l'ancien encodage sont utilisés, tandis qu'avec "authzID" comme argument de constructeur, le nouvel OID et le nouvel encodage sont utilisés. En utilisant cette logique, les serveurs supportant l'un ou l'autre OID peuvent être gérés correctement.

MÉTHODES

Comme avec Net::LDAP::Control, chaque argument du constructeur décrit ci-dessus est également disponible en tant que méthode sur l'objet qui retournera la valeur actuelle de l'attribut s'il est appelé sans argument, et définira une nouvelle valeur pour l'attribut s'il est appelé avec un argument.
