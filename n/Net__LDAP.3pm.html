NOM

Net::LDAP - Protocole d'accès aux annuaires réseau (LDAP)

SYNOPIS

use Net::LDAP;
$ldap = Net::LDAP->new( 'ldap.example.com' )  or  die "$@";
$mesg = $ldap->bind;                         # liaison anonyme
$mesg->code  and  die $mesg->error;          # vérifier les erreurs
$srch = $ldap->search( base   => "c=US",     # effectuer une recherche
                       filter => "(&(sn=Barr)(o=Texas Instruments))"
                     );
$srch->code  and  die $srch->error;          # vérifier les erreurs
foreach $entry ($srch->entries) { $entry->dump; }
$mesg = $ldap->unbind;                       # fermer la session
$ldap = Net::LDAP->new( 'ldaps://ldap.example.com' )  or  die "$@";
# liaison avec DN et mot de passe
$mesg = $ldap->bind( 'cn=root, o=University of Michigan, c=us',
                     password => 'secret'
                   );
$mesg->code  and  die $mesg->error;          # vérifier les erreurs
$result = $ldap->add( 'cn=Barbara Jensen, o=University of Michigan, c=US',
                      attrs => [
                        cn          => ['Barbara Jensen', 'Barbs Jensen'],
                        sn          => 'Jensen',
                        mail        => 'b.jensen@umich.edu',
                        objectclass => ['top', 'person',
                                        'organizationalPerson',
                                        'inetOrgPerson' ],
                      ]
                    );
$result->code  and  warn "échec de l'ajout de l'entrée : ", $result->error;
$mesg = $ldap->unbind;                       # fermer la session

DESCRIPTION

Net::LDAP est une collection de modules qui implémente une API de service LDAP pour les programmes Perl. Le module peut être utilisé pour rechercher dans des annuaires ou pour effectuer des fonctions de maintenance telles que l'ajout, la suppression ou la modification d'entrées.

Ce document suppose que le lecteur a une certaine connaissance du protocole LDAP.

CONSTRUCTEUR

new ( HOST, OPTIONS )
Crée un objet Net::LDAP et ouvre une connexion à l'hôte nommé.

"HOST" peut être un nom d'hôte ou une adresse IP. Le port TCP peut être spécifié après le nom d'hôte suivi de deux points (comme localhost:10389). Le port par défaut pour LDAP est 389.

Vous pouvez également spécifier une URI, comme 'ldap://127.0.0.1:666' ou 'ldaps://127.0.0.1:666'. Remarque : les '%' dans le chemin de la connexion LDAPI sont traduits en '/'. Ceci est pour supporter des options de requête LDAP comme base, search, etc. bien que la partie chemin de l'URI sera ignorée dans ce contexte. Si le port n'a pas été spécifié dans l'URI, la valeur par défaut sera 389 ou 636 pour les schémas 'LDAP' et 'LDAPS' respectivement.

"HOST" peut également être une référence à un tableau d'hôtes, de paires hôte-port ou d'URI à tenter. Chacun est essayé dans l'ordre jusqu'à ce qu'une connexion soit établie. Ce n'est que lorsque tous ont échoué que le résultat de "undef" sera retourné.

Le port sur lequel se connecter au serveur distant. Peut être remplacé par "HOST".
Le schéma à utiliser lorsque aucune URI n'est utilisée comme "HOST". (Par défaut : ldap)
La valeur de "keepalive" est définie selon la valeur booléenne de l'option. (Par défaut : utiliser la valeur par défaut du système)
Le délai d'attente passé à IO::Socket lors de la connexion au serveur distant. (Par défaut : 120)
La valeur de "multihomed" est passée comme paire "MultiHomed" lors de la connexion au serveur distant
La valeur de "localaddr" est passée comme paire "LocalAddr" lors de la connexion, qui définit l'adresse IP du client (au lieu de l'adresse IP du serveur).
La valeur de "debug" est définie pour le niveau de débogage. Voir la méthode debug pour plus de détails.
Effectuer toutes les opérations de manière asynchrone.
La valeur de "onerror" est définie pour le comportement lorsqu'une erreur est détectée en mode synchrone.
die => 'die'
Net::LDAP échouera lorsqu'une erreur est détectée.
warn => 'warn'
Net::LDAP émettra un avertissement lorsqu'une erreur est détectée.
undef => 'undef'
Net::LDAP émettra un avertissement lorsqu'une erreur est détectée et que "-w" est actif. La valeur retournée sera "undef". Remarque : cette valeur est la chaîne 'undef', pas la valeur "undef").
sub { ... }
La sous-routine donnée est appelée dans un contexte scalaire avec un seul argument, le message d'erreur. La valeur retournée sera la valeur retournée par la méthode appelée.
version => N
Définit la version du protocole à utiliser (par défaut : LDAPv3). Ceci est utile si vous voulez parler à un ancien serveur et donc devoir utiliser LDAPv2.
La valeur de "raw" est utilisée comme REGEX pour désigner les noms d'attributs qui seront considérés comme binaires dans les résultats de recherche.

Lorsque cette option est spécifiée, Net::LDAP convertit les valeurs d'attributs qui ne correspondent pas à ce REGEX en chaînes Perl UTF-8, permettant aux opérateurs réguliers (}$, `~=`, etc.) de fonctionner comme prévu, même avec des caractères internationaux dans les chaînes.

Si cette option n'est pas spécifiée, les valeurs d'attributs sont considérées comme des chaînes d'octets.

Exemple : raw => qr/(?i:^jpegPhoto|;binary)/

La valeur de "inet4" est utilisée pour se connecter à un serveur en utilisant le protocole IPv4. La valeur par défaut est d'utiliser les deux protocoles (IPv4 et IPv6).
La valeur de "inet6" est utilisée pour se connecter à un serveur en utilisant le protocole spécifié, c'est-à-dire IPv4 ou IPv6. Si le protocole sélectionné n'est pas supporté, la connexion échouera.

Exemple

$ldap = Net::LDAP->new( 'remote.host', async => 1 );

Les connexions LDAPS ont quelques options supplémentaires valides, voir la méthode start_tls pour plus de détails. Remarque : le port par défaut pour LDAPS est 636, et la valeur par défaut pour 'sslversion' est la valeur par défaut utilisée par IO::Socket::SSL.

Pour les connexions LDAPI, HOST est en fait l'emplacement d'un socket UNIX de domaine auquel se connecter. La valeur par défaut est '/var/run/ldapi'.

bind ( DN, OPTIONS )
Se connecte (s'identifie) au serveur. "DN" est le DN utilisé pour la connexion. Une connexion anonyme peut être effectuée en appelant bind sans arguments.
control => CONTROL
control => [ CONTROL, ... ]
Voir "CONTROLS" ci-dessous
callback => CALLBACK
Voir "CALLBACKS" ci-dessous
noauth | anonymous => 1
Se connecte sans mot de passe. La valeur passée avec cette option est ignorée.
password => PASSWORD
Se connecte avec le mot de passe donné.
sasl => SASLOBJ
Se connecte en utilisant un mécanisme SASL. L'argument donné doit être une sous-classe de Authen::SASL ou une connexion client Authen::SASL obtenue en appelant "client_new" sur un objet Authen::SASL.

Si un objet Authen::SASL est passé, alors "client_new" sera appelé pour créer un objet de connexion client. Le nom d'hôte passé par "Net::LDAP" à "client_new" peut être défini en utilisant l'option "sasl_host" ci-dessous. Si ce n'est pas correct pour votre environnement, envisagez d'appeler "client_new" vous-même et de passer l'objet de connexion client comme "SASLOBJ".

sasl_host => SASLHOST
Lors de la connexion avec SASL, permet au nom d'hôte utilisé dans la communication SASL de différer du nom d'hôte auquel on est connecté.

Si "SASLHOST" est évalué à TRUE, alors il est utilisé comme nom d'hôte SASL.

S'il est évalué à FALSE, alors la valeur est déterminée en appelant "peerhost" sur le socket. Dans les anciennes versions de Net::LDAP, c'était le comportement standard, mais cela s'est avéré causer plus de problèmes qu'il n'en résolvait.

Lorsque l'option n'est pas donnée, le nom d'hôte SASL utilisé est par défaut le nom d'hôte / adresse IP tiré du paramètre "HOST" lors de la connexion.

Exemple

$mesg = $ldap->bind; # Connexion anonyme
$mesg = $ldap->bind( $dn, password => $password );
# $sasl est un objet de la classe Authen::SASL
$mesg = $ldap->bind( $dn, sasl => $sasl, version => 3 );

modify ( DN, OPTIONS )
Modifie le contenu de l'entrée donnée par "DN" sur le serveur. "DN" peut être une chaîne de caractères ou un objet Net::LDAP::Entry.
add => { ATTR => VALUE, ... }
Ajoute des attributs ou des valeurs à l'entrée. "VALUE" doit être une chaîne de caractères si une seule valeur est souhaitée dans l'attribut, ou une référence vers un tableau de chaînes de caractères si plusieurs valeurs sont souhaitées. 
$mesg = $ldap->modify( $dn,
  add => {
    description => 'Liste des membres',    # Ajoute l'attribut description
    member      => [
      'cn=member1,ou=people,dc=example,dc=com',    # Ajoute à l'attribut
      'cn=member2,ou=people,dc=example,dc=com',
    ]
  }
);
delete => [ ATTR, ... ]
Supprime des attributs complets de l'entrée. 
$mesg = $ldap->modify( $dn,
  delete => ['member','description'] # Supprime des attributs
);
delete => { ATTR => VALUE, ... }
Supprime des valeurs individuelles d'un attribut. "VALUE" doit être une chaîne de caractères si seule une valeur est supprimée de l'attribut, ou une référence vers un tableau de chaînes de caractères si plusieurs valeurs sont supprimées.

Si "VALUE" est une référence vers un tableau vide ou si toutes les valeurs existantes de l'attribut sont supprimées, alors l'attribut sera supprimé de l'entrée.

$mesg = $ldap->modify( $dn,
  delete => {
    description => 'Liste des membres',
    member      => [
      'cn=member1,ou=people,dc=example,dc=com',    # Supprime des membres
      'cn=member2,ou=people,dc=example,dc=com',
    ],
    seeAlso => [],   # Supprime l'attribut
  }
);
replace => { ATTR => VALUE, ... }
Remplace toutes les valeurs existantes dans chaque attribut donné par "VALUE". "VALUE" doit être une chaîne de caractères si seule une valeur est souhaitée dans l'attribut, ou une référence vers un tableau de chaînes de caractères si plusieurs valeurs sont souhaitées. Une référence vers un tableau vide supprimera l'attribut entier. Si l'attribut n'existe pas déjà dans l'entrée, il sera créé. 
$mesg = $ldap->modify( $dn,
  replace => {
    description => 'Nouvelle Liste des membres', # Change la description
    member      => [ # Remplace toute la liste par celles-ci
      'cn=member1,ou=people,dc=example,dc=com',
      'cn=member2,ou=people,dc=example,dc=com',
    ],
    seeAlso => [],   # Supprime l'attribut
  }
);
increment => { ATTR => VALUE, ... }
Incrémente atomiquement la valeur existante dans chaque attribut donné par la "VALUE" fournie. Les attributs doivent avoir une syntaxe entière, ou être autrement "incrémentables". Notez que cela fonctionMantenga toda la estructura del archivo.
Le serveur ne fonctionne que si le serveur annonce la prise en charge de LDAP_FEATURE_MODIFY_INCREMENT. Utilisez « supported_feature » dans Net::LDAP::RootDSE pour vérifier cela.
$mesg = $ldap->modify( $dn,
  increment => {
    uidNumber => 1 # incrémente uidNumber de 1
  }
);
changes => [ OP => [ ATTR => VALUE ], ... ]
Ceci est une alternative à add, delete, replace et increment, où toute l'opération peut être fournie en un seul argument. « OP » doit être add, delete, replace ou increment. « VALUE » doit être une chaîne ou une référence à un tableau de chaînes, comme précédemment.

Utilisez cette forme si vous souhaitez contrôler l'ordre dans lequel les opérations sont effectuées.

$mesg = $ldap->modify( $dn,
  changes => [
    add => [
      description => 'Une description',
      member      => $newMember,
    ],
    delete => [
      seeAlso => [],
    ],
    add => [
      anotherAttribute => $value,
    ],
  ]
);
control => CONTROL
control => [ CONTROL, ... ]
Voir « CONTROLS » ci-dessous.
callback => CALLBACK
Voir « CALLBACKS » ci-dessous.

Exemple

$mesg = $ldap->modify( $dn, add => { sn => 'Barr' } );
$mesg = $ldap->modify( $dn, delete => [qw(faxNumber)] );
$mesg = $ldap->modify( $dn, delete => { 'telephoneNumber' => '911' } );
$mesg = $ldap->modify( $dn, replace => { 'mail' => 'gbarr@pobox.com' } );
$mesg = $ldap->modify( $dn,
                       changes => [
                           # add sn=Barr
                         add     => [ sn => 'Barr' ],
                           # delete all fax numbers
                         delete  => [ faxNumber => []],
                           # delete phone number 911
                         delete  => [ telephoneNumber => ['911']],
                           # change email address
                         replace => [ mail => 'gbarr@pobox.com']
                       ]
                     );
search ( OPTIONS )
Recherche dans le répertoire à l'aide d'un filtre donné. Cela peut être utilisé pour lire des attributs d'une seule entrée, d'entrées immédiatement sous une entrée spécifique ou de l'arborescence entière des entrées.

Le résultat est un objet de classe Net::LDAP::Search.

base => DN
Le DN qui est l'entrée d'objet de base par rapport à laquelle la recherche est effectuée.
scope => 'base' | 'one' | 'sub' | 'subtree' | 'children'
Par défaut, la recherche est effectuée sur toute l'arborescence sous l'objet de base spécifié. Cela peut être modifié en spécifiant un paramètre « scope » avec l'une des valeurs suivantes :
base
Recherche uniquement dans l'entrée d'objet de base.
one
Recherche dans les entrées immédiatement sous l'entrée d'objet de base.
sub
subtree
Recherche dans toute l'arborescence des entrées (y compris l'entrée d'objet de base elle-même). C'est la valeur par défaut.
children
Recherche dans toute l'arborescence des entrées sous l'entrée d'objet de base, à l'exception de l'entrée d'objet de base elle-même.

Remarque : le scope children nécessite l'extension de fonctionnalités LDAPv3.

deref => 'never' | 'search' | 'find' | 'always'
Par défaut, les alias sont déréférencés pour localiser l'entrée d'objet de base de la recherche, mais pas lors de la recherche dans les subordonnés de l'entrée d'objet de base. Cela peut être modifié en spécifiant un paramètre « deref » avec l'une des valeurs suivantes :
never
Ne pas déréférencer les alias lors de la recherche ou lors de la localisation de l'entrée d'objet de base de la recherche.
search
Déréférencer les alias dans les subordonnés de l'entrée d'objet de base pendant la recherche, mais pas lors de la localisation de l'entrée d'objet de base de la recherche.
find
Déréférencer les alias lors de la localisation de l'entrée d'objet de base de la recherche, mais pas lors de la recherche dans les subordonnés de l'entrée d'objet de base. C'est la valeur par défaut.
always
Déréférencer les alias à la fois lors de la recherche et lors de la localisation de l'entrée d'objet de base de la recherche.
sizelimit => N
Une limite de taille qui restreint le nombre maximum d'entrées à retourner dans le cadre de la recherche. Une valeur de 0, et la valeur par défaut, signifie qu'aucune limite n'est demandée. Les serveurs peuvent imposer un maximum d'entrées à retourner.
timelimit => N
Une limite de temps qui restreint le temps maximum (en secondes) autorisé pour une recherche. Une valeur de 0 (par défaut) signifie qu'aucune limite de temps n'est demandée.
typesonly => 1
Seuls les types d'attributs sont retournés (sans valeurs). Normalement, les types d'attributs et leurs valeurs sont retournés.
filter => FILTER
Un filtre qui définit les conditions qu'une entrée d'annuaire doit remplir pour être retournée par la recherche. Il peut s'agir d'une chaîne ou d'un objet Net::LDAP::Filter. Les valeurs à l'intérieur des filtres peuvent nécessiter une échappement pour éviter les problèmes de sécurité ; voir Net::LDAP::Filter pour une définition du format du filtre, y compris les règles d'échappement.
attrs => [ ATTR, ... ]
Une liste d'attributs à retourner pour chaque entrée qui correspond au filtre de recherche.

Si non spécifié, les serveurs retourneront les attributs accessibles par défaut étant donné vos informations d'identification de liaison.

Certains attributs supplémentaires comme « createTimestamp » et d'autres attributs opérationnels peuvent également être disponibles :

$mesg = $ldap->search( ... ,
                       attrs => ['createTimestamp']
                     );

Pour récupérer les attributs par défaut et d'autres attributs, utilisez « * ».

$mesg = $ldap->search( ... ,
                       attrs => ['*', 'createTimestamp']
                     );

Pour ne récupérer aucun attribut (le serveur ne retourne que les DN des entrées correspondantes), utilisez « 1.1 » :

$mesg = $ldap->search( ... ,
                       attrs => ['1.1']
                     );
control => CONTROL
control => [ CONTROL, ... ]
Voir « CONTROLS » ci-dessous.
callback => CALLBACK
Voir « CALLBACKS » ci-dessous.
raw => REGEX
Utilisez REGEX pour désigner les noms d'attributs considérés comme binaires dans les résultats de recherche.

Lorsque cette option est fournie, Net::LDAP convertit toutes les valeurs d'attributs qui ne correspondent pas à ce REGEX en chaînes Perl UTF-8 afin que les opérateurs Perl réguliers (recherche de motifs, etc.) puissent fonctionner comme prévu, même sur des chaînes contenant des caractères internationaux.

Si cette option n'est pas fournie, les valeurs d'attributs sont traitées comme des chaînes d'octets.

La valeur fournie ici remplace la valeur héritée du constructeur.

Exemple : raw => qr/(?i:^jpegPhoto|;binary)/

Exemple

$mesg = $ldap->search(
                       base   => $base_dn,
                       scope  => 'sub',
                       filter => '(|(objectclass=rfc822mailgroup)(sn=jones))'
                     );
Net::LDAP::LDIF->new( \*STDOUT,"w" )->write( $mesg->entries );
start_tls ( OPTIONS )
Appeler cette méthode convertira la connexion existante en une connexion utilisant le Transport Layer Security (TLS), qui fournit une connexion chiffrée. Ceci n'est possible *que* si la connexion utilise LDAPv3 et nécessite que le serveur annonce la prise en charge de LDAP_EXTENSION_START_TLS. Utilisez « supported_extension » dans Net::LDAP::RootDSE pour vérifier cela.
verify => 'none' | 'optional' | 'require'
Comment vérifier la certification du serveur :
none
Le serveur peut fournir une certification mais elle ne sera pas vérifiée - cela peut signifier que vous êtes connecté à un mauvais serveur.
optional
Vérifie uniquement lorsque le serveur propose une certification.
require
Le serveur doit fournir une certification et celle-ci doit être valide.

Si vous définissez verify sur optional ou require, vous devez également définir cafile ou capath. L'option la plus sûre est require.

sslversion => 'sslv2' | 'sslv3' | 'sslv23' | 'tlsv1' | 'tlsv1_1' | 'tlsv1_2'
Définit la version du protocole SSL/TLS à utiliser. La valeur par défaut est celle utilisée par IO::Socket::SSL par défaut.

Voir « SSL_version » dans IO::Socket::SSL pour plus de détails.

sslserver => SSLHOST
Permet de modifier le nom du serveur à utiliser lors de la vérification de la certification, au cas où le nom de la cible ne correspondrait pas au certificat du serveur LDAP. S'il n'est pas spécifié, la valeur par défaut est le nom de l'hôte connecté.

Voir « SSL_verifycn_name » dans IO::Socket::SSL pour plus de détails.

ciphers => CIPHERS
Spécifie le sous-ensemble des suites de chiffrement autorisées pour cette connexion.
clientcert => '/chemin/vers/cert.pem'
clientkey => '/chemin/vers/cle.pem'
keydecrypt => sub { ... }
Si desea que el cliente ofrezca un certificado al servidor para la autenticación SSL (lo que no es lo mismo que en la operación LDAP Bind), entonces establezca clientcert al directorio de certificados del usuario y clientkey a su clave privada. Estos archivos deben estar en formato PEM.

Si la clave privada está cifrada (recomendado), entonces keydecrypt debe ser una subrutina que devuelva la clave de descifrado. Por ejemplo:

$ldap = Net::LDAP->new( 'monhote.example.com', version => 3 );
$mesg = $ldap->start_tls(
                          verify => 'require',
                          clientcert => 'moncert.pem',
                          clientkey => 'maclé.pem',
                          keydecrypt => sub { 'secret'; },
                          capath => '/usr/local/cacerts/'
                        );
capath => '/chemin/vers/certificats_serveur/'
cafile => '/chemin/vers/certificat_serveur.pem'
Lors de la vérification du certificat du serveur, définissez capath au chemin du répertoire contenant les certificats de CA, ou définissez cafile au chemin du fichier contenant le certificat de CA qui a signé le certificat du serveur. Tous ces certificats doivent être au format PEM.

Le répertoire dans 'capath' doit contenir des certificats nommés en utilisant la valeur de hachage des noms des sujets des certificats. Pour générer ces noms, utilisez OpenSSL comme suit sous Unix:

ln -s cacert.pem `openssl x509 -hash -noout < cacert.pem`.0

(en supposant que le certificat de la CA est dans cacert.pem.)

checkcrl => 1
Si capath est configuré, alors une liste de révocation de certificats (CRLs) sera également recherchée lors de la vérification du certificat du serveur. Les noms des CRL doivent suivre le format hash.rnum, où hash est la valeur de hachage du DN de l'émetteur et num est un nombre commençant à 0.

Voir "SSL_check_crl" dans IO::Socket::SSL pour plus d'informations.

unbind ( )
La méthode unbind ne prend aucun paramètre et se chargera de vous déconnecter du serveur. Certains serveurs peuvent vous permettre de vous reconnecter ou d'effectuer des opérations après la déconnexion. Si vous souhaitez passer à un autre ensemble d'informations d'identification tout en utilisant la même connexion, la reconnexion avec un autre DN et mot de passe sans déconnexion sera généralement fonctionnelle.

Exemple

$mesg = $ldap->unbind;
done ( )
Alias de commodité pour unbind(), nommé d'après la méthode de nettoyage de Net::LDAP::LDIF.

Les méthodes suivantes sont des méthodes de commodité et ne retournent pas d'objets de classe "Net::LDAP::Message".

async ( VALUE )
Si VALUE est donné, le mode asynchrone sera défini. La valeur précédente sera retournée. La valeur est VRAIE si des opérations asynchrones LDAP sont en cours.
certificate ( )
Retourne un objet X509_Certificate contenant le certificat du serveur. Voir la documentation de IO::Socket::SSL pour des informations sur cette classe.

Pour obtenir le nom du DN du certificat du serveur (dans un format particulièrement spécifique à OpenSSL, différent de RFC 1779 et RFC 4514), faites ceci :

print "Subject DN: " . $ldaps->certificate->subject_name . "\n";
cipher ( )
Retourne le mode de chiffrement utilisé par la connexion, dans le format utilisé par OpenSSL.
debug ( VALUE )
Si VALUE est donné, le bit de débogage sera défini. La valeur précédente sera retournée. La sortie de débogage sera envoyée à "STDERR". Les bits de cette valeur sont : 
1   Afficher les paquets sortants (en utilisant asn_hexdump).
2   Afficher les paquets entrants (en utilisant asn_hexdump).
4   Afficher les paquets sortants (en utilisant asn_dump).
8   Afficher les paquets entrants (en utilisant asn_dump).

La valeur par défaut est 0.

disconnect ( )
Déconnecte du serveur
root_dse ( OPTIONS )
La méthode root_dse retourne les informations stockées dans le rootDSE du serveur.
attrs => [ ATTR, ...]
Une référence à une liste d'attributs à retourner. Si non spécifié, les attributs suivants seront demandés : 
subschemaSubentry
namingContexts
altServer
supportedExtension
supportedFeatures
supportedControl
supportedSASLMechanisms
supportedLDAPVersion

Le résultat est un objet de classe Net::LDAP::RootDSE.

Exemple

my $root = $ldap->root_dse;
# obtenir le nom du contexte
$root->get_value( 'namingContexts', asref => 1 );
# obtenir les versions LDAP
$root->supported_version;

Comme le rootDSE peut changer dans certaines circonstances - par exemple lors du changement de connexion en utilisant start_tls - vous devriez toujours utiliser la méthode root_dse pour obtenir la copie la plus actuelle du rootDSE.

schema ( OPTIONS )
Lit les informations de schéma du serveur.

Le résultat est un objet de classe Net::LDAP::Schema. Pour plus d'informations sur les méthodes qui peuvent être effectuées avec cet objet, consultez la documentation de ce document.

dn => DN
Si un DN est fourni, il deviendra l'entrée d'objet de base à partir de laquelle la recherche d'informations de schéma sera effectuée. Si aucun DN n'est fourni, l'entrée d'objet de base sera déterminée à partir du rootDSE.

Exemple

my $schema = $ldap->schema;
# obtenir les objectClasses
@ocs = $schema->all_objectclasses;
# obtenir les attributs
@atts = $schema->all_attributes;
sasl ( )
Retourne l'objet Authen::SASL associé à l'objet LDAP, ou "undef" s'il n'est pas présent.
socket ( OPTIONS )
Retourne l'objet socket sous-jacent utilisé.

Le type exact de l'objet retourné dépend de la présence de couches SASL établies. Sans couches SASL, le résultat sera toujours un objet "IO::Socket" ; avec des couches SASL, le résultat dépend des options fournies :

sasl_layer => FLAG
Cette option n'est pertinente que si des couches SASL sont établies.

Si elle n'existe pas ou si une valeur évaluant à FAUX est définie, la couche SASL est retournée. Selon la bibliothèque SASL utilisée, l'objet retourné ne sera pas nécessairement un objet "IO::Socket".

Si elle existe mais qu'une valeur évaluant à FAUX est définie, l'objet "IO::Socket" de base sous la couche SASL est retourné.

host ( )
Retourne l'hôte auquel la connexion a été établie. Pour les connexions LDAPI, le chemin du socket est retourné.
port ( )
Retourne le port connecté ou "undef" en cas de connexions LDAPI.
uri ( )
Retourne l'URI connecté.

La valeur retournée est l'élément de l'argument du constructeur avec lequel la connexion a été établie, elle peut donc être un URI valide ou non.

scheme ( )
Retourne le schéma de la connexion. L'une des valeurs possibles est "ldap", "ldaps" ou "ldapi".
sync ( MESG )
Attend qu'une requête spécifiée par "MESG" soit terminée sur le serveur. Si "MESG" n'est pas spécifié, attend que toutes les requêtes en attente soient terminées.

Retourne un code d'erreur défini dans Net::LDAP::Constant.

process ( MESG )
Traite tout message que le serveur a envoyé, mais ne bloque pas. Si "MESG" est spécifié, retourne immédiatement au moment où "MESG" a été traité.

Retourne un code d'erreur défini dans Net::LDAP::Constant.

version ( )
Retourne la version du protocole LDAP utilisée.

CONTRÔLES

De nombreuses méthodes décrites ci-dessus acceptent un paramètre de contrôle. Cela permet de passer des contrôles au serveur comme décrit dans LDAPv3.

Un contrôle est une référence à un HASH et doit contenir les trois éléments suivants. Si l'un des contrôles est nul, la méthode "to_asn" est appelée, qui doit retourner une référence à un HASH contenant les trois éléments décrits.

Pour la plupart des utilisations, les objets Net::LDAP::Control sont la méthode la plus simple pour générer des contrôles.

type => OID
Cet élément doit être présent et est le nom du type de contrôle demandé.
critical => FLAG
critical est optionnel et doit être une valeur booléenne. S'il n'est pas spécifié, il est supposé être "faux".

CONTROLS

value => VALUE
Si le contrôle demandé nécessite une valeur, cet élément doit contenir la valeur pour le serveur.

CALLBACKS

La plupart des commandes ci-dessus acceptent une option de rappel. Cette option doit être une référence à une sous-routine. Cette sous-routine sera appelée pour chaque paquet reçu du serveur en réponse à la requête envoyée.

Lorsque la sous-routine est appelée, le premier argument sera l'objet Net::LDAP::Message qui a été retourné par la méthode.

Si la requête est une recherche, plusieurs paquets peuvent être reçus du serveur. Chaque entrée est reçue comme un paquet séparé. Pour chacun d'eux, la sous-routine sera appelée avec un objet Net::LDAP::Entry comme deuxième argument.

Lors d'une recherche, le serveur peut également envoyer une liste de références. Lorsqu'une telle liste est reçue, la sous-routine sera appelée avec un objet Net::LDAP::Reference comme deuxième argument.

CODES D'ERREUR LDAP

Net::LDAP exporte également des constantes pour les codes d'erreur qui peuvent être reçus du serveur, voir Net::LDAP::Constant.
