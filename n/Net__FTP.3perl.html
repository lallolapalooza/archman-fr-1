NAME

Net::FTP - Classe cliente FTP

SYNOPSIS

use Net::FTP;
$ftp = Net::FTP->new("some.host.name", Debug => 0)
  or die "Impossible de se connecter à some.host.name: $@";
$ftp->login("anonymous",'anonymous@')
  or die "Impossible de se connecter ", $ftp->message;
$ftp->cwd("/pub")
  or die "Impossible de changer de répertoire ", $ftp->message;
$ftp->get("that.file")
  or die "get a échoué ", $ftp->message;
$ftp->quit;

DESCRIPTION

Net::FTP est une classe implémentant un client FTP simple en Perl, tel que décrit dans la RFC959. Elle offre des wrappers pour le sous-ensemble commun des commandes de la RFC959. Si IO::Socket::IP ou IO::Socket::INET6 sont installés, elle fournit également un support pour IPv6 tel que décrit dans la RFC2428. Avec IO::Socket::SSL installé, elle fournit également un support pour FTPS implicite et explicite tel que décrit dans la RFC4217.

La classe Net::FTP est une sous-classe de Net::Cmd et (selon la disponibilité) de IO::Socket::IP, IO::Socket::INET6 ou IO::Socket::INET.

À propos

FTP est le File Transfer Protocol. C'est une façon de transférer des fichiers entre machines sur un réseau. Le protocole définit un client (dont les informations sont fournies par ce module) et un serveur (non implémenté dans ce module). La communication est toujours initiée par le client, et le serveur répond avec un message et un code d'état (et parfois des données).

Le protocole FTP permet d'envoyer des fichiers vers le serveur ou d'en récupérer depuis le serveur. Chaque transfert implique un fichier local (sur le client) et un fichier distant (sur le serveur). Dans ce module, le même nom de fichier sera utilisé pour le fichier local et le fichier distant si un seul est spécifié. Cela signifie que le transfert du fichier distant "/path/to/file" tentera de placer ce fichier à l'emplacement "/path/to/file" localement, à moins qu'un nom de fichier local ne soit spécifié.

Le protocole définit également plusieurs types standard de traductions que les fichiers peuvent appliquer pendant le transfert. Ce sont ASCII, EBCDIC, binaire et octet. ASCII est le type par défaut, indiquant que l'expéditeur des fichiers traduira les fins de ligne dans une représentation standard que le récepteur traduira ensuite vers sa représentation locale. EBCDIC indique que le fichier transféré est au format EBCDIC. Binaire (également appelé image) envoie les données comme une séquence de bits contigus. Octet envoie les données comme des octets, dont les valeurs restent les mêmes, quelle que soit la différence de taille d'octet entre les deux machines (en théorie - en pratique, vous ne devriez l'utiliser que si vous savez vraiment ce que vous faites). Cette classe ne prend pas en charge les formats EBCDIC ou octet, et par défaut, le format binaire sera utilisé si vous essayez d'en utiliser un.

Méthodes_de_Classe

"new([$host][, %options])"
Ceci est le constructeur d'un objet Net::FTP. $host est le nom de la machine distante à laquelle une connexion FTP doit être établie.

$host est optionnel. S'il n'est pas spécifié, il peut être passé comme paramètre "Host" décrit ci-dessous.

%options sont passées sous forme de paires clé-valeur. Les options possibles sont :

Host - La machine FTP à laquelle se connecter. Peut être un scalaire unique, tel que défini pour le paramètre "PeerAddr" dans IO::Socket::INET, ou une référence à un tableau d'hôtes à essayer dans l'ordre. La méthode "host" renverra la valeur qui a été utilisée pour se connecter à la machine.

Firewall - Le nom d'une machine agissant comme un pare-feu FTP. Ceci peut être substitué par la variable d'environnement "FTP_FIREWALL". Si spécifié et que la machine donnée ne peut pas être connectée directement, la connexion est établie à la machine de pare-feu et l'identifiant est ajouté avec @hostname. Cette configuration est également appelée proxy FTP.

FirewallType - Le type de pare-feu trouvé sur la machine spécifiée par Firewall. Ceci peut être substitué par la variable d'environnement "FTP_FIREWALL_TYPE". Pour une liste des types autorisés, voir la description de ftp_firewall_type dans Net::Config.

BlockSize - La taille de bloc que Net::FTP utilisera lors des transferts. (par défaut : 10240)

Port - Le numéro de port auquel se connecter à la machine distante pour la connexion FTP.

SSL - Si la connexion doit être établie dès le départ avec SSL, au lieu d'être mise à niveau via "starttls".

SSL_* - Arguments SSL qui s'appliquent lors de la mise à niveau de la connexion de contrôle ou de données vers SSL. Vous pouvez utiliser les arguments SSL tels que documentés dans IO::Socket::SSL, mais ils utiliseront généralement déjà les arguments corrects.

Timeout - Définit une valeur de délai d'attente en secondes (par défaut : 120)

Debug - niveau de débogage (voir la méthode debug dans Net::Cmd)

Passive - Si défini sur une valeur non nulle, tous les transferts de données seront effectués en mode passif. S'il est défini sur zéro, les transferts de données seront effectués en mode actif. Si la machine est directement connectée à Internet, les deux modes devraient fonctionner de manière égale. Derrière la plupart des pare-feux et des configurations NAT, le mode passif a une meilleure chance de fonctionner. Cependant, dans certaines rares configurations de pare-feux, le mode actif fonctionne lorsque le mode passif ne fonctionne pas. Certaines machines très anciennes peuvent ne pas implémenter les transferts passifs. Si non spécifié, le mode de transfert est défini par la variable d'environnement "FTP_PASSIVE" ou, si cette variable n'est pas définie, par l'utilitaire libnetcfg. Si aucun de ceux-ci ne s'applique, le mode passif sera utilisé.

Hash - Si un pointeur vers un descripteur de fichier de sortie est passé (par exemple, "\*STDOUT"), imprime # dans ce descripteur de fichier toutes les 1024 octets. Ceci appelle simplement la méthode hash() pour vous, donc des # seront affichés pour tous les transferts. Vous pouvez appeler explicitement la méthode hash() quand vous le souhaitez.

LocalAddr - L'adresse locale à utiliser pour toutes les connexions socket. Cet argument est passé à la superclasse, c'est-à-dire à IO::Socket::INET ou IO::Socket::IP.

Domain - Le domaine à utiliser, c'est-à-dire AF_INET ou AF_INET6. Cet argument est passé à la superclasse IO::Socket. Ceci peut être utilisé pour forcer IPv4 même si IO::Socket::IP est utilisé, qui se comporterait par défaut comme IPv6. Family est accepté comme nom alternatif de Domain.

Si le constructeur échoue, undef sera renvoyé et un message d'erreur se trouvera dans $@.

Méthodes_d_Objet

Sauf indication contraire, toutes les méthodes renvoient vrai ou faux, vrai indiquant que l'opération a réussi. Lorsqu'une méthode indique qu'elle renvoie une valeur, elle renverra faux ou une liste vide en cas d'échec.

Net::FTP hérite de Net::Cmd, donc les méthodes définies dans Net::Cmd peuvent être utilisées pour envoyer des commandes à la machine FTP distante en plus de celles mentionnées ici.

"login([$login[, $password[, $account]]])"
Se connecte à la machine FTP distante avec les informations de connexion fournies. Si aucun argument n'est fourni, "Net::FTP" utilise le module "Net::Netrc" pour rechercher les informations de connexion pour l'hôte connecté. Si aucune information n'est trouvée, une connexion anonyme est utilisée. Si un mot de passe n'est pas fourni et que la connexion est anonyme, "anonymous@" sera utilisé comme mot de passe.

Si la connexion est établie via un pare-feu, la méthode "authorize" sera appelée sans arguments.

  • Envoie une commande SITE au serveur distant et attend une réponse.

    Retourne le chiffre le plus significatif du code de réponse.

  • ascii()
  • Transfère le fichier en ASCII. La traduction CRLF sera effectuée si nécessaire.
  • binary()
  • Transfère le fichier en mode binaire. Aucune transformation ne sera effectuée.

    Indice : Si les machines serveur et client utilisent la même fin de ligne pour les fichiers texte, il sera plus rapide de transférer tous les fichiers en mode binaire.

  • type([$type])
  • Définit ou obtient si les fichiers seront transférés en mode ASCII ou binaire.
  • "rename($oldname, $newname)"
  • Renomme un fichier sur le serveur FTP distant de $oldname à $newname. Ceci est fait en envoyant les commandes RNFR et RNTO.
  • delete($filename)
  • Envoie une demande au serveur pour supprimer $filename.
  • cwd([$dir])
  • Tente de changer de répertoire pour celui indiqué dans $dir. Si $dir est "..", la commande FTP "CDUP" est utilisée pour tenter de remonter d'un répertoire. Si aucun répertoire n'est donné, une tentative est faite pour changer de répertoire vers le répertoire racine.
  • cdup()
  • Change de répertoire pour celui du parent du répertoire courant.
  • passive([$passive])
  • Définit ou obtient si les connexions de données seront initiées en mode passif.
  • pwd()
  • Retourne le chemin complet du répertoire courant.
  • restart($where)
  • Définit le décalage en octets à partir duquel commencer le prochain transfert de données. Net::FTP enregistre simplement cette valeur et l'utilise lors du prochain transfert de données. Pour cette raison, cette méthode ne retournera pas d'erreur, mais sa définition peut entraîner l'échec d'un transfert de données ultérieur.
  • "rmdir($dir[, $recurse])"
  • Supprime le répertoire nommé $dir. Si $recurse est *vrai*, alors "rmdir" tentera de supprimer tout le contenu du répertoire.
  • "mkdir($dir[, $recurse])"
  • Crée un nouveau répertoire nommé $dir. Si $recurse est *vrai*, alors "mkdir" tentera de créer tous les répertoires du chemin donné.

    Retourne le chemin complet du nouveau répertoire.

  • alloc($size[, $record_size])
  • La commande alloc vous permet de donner au serveur ftp un indice sur la taille du fichier sur le point d'être transféré en utilisant la commande ftp ALLO. Certains systèmes de stockage l'utilisent pour prendre des décisions intelligentes sur la façon de stocker le fichier. L'argument $size représente la taille du fichier en octets. L'argument $record_size indique une taille maximale d'enregistrement ou de page pour les fichiers envoyés avec une structure d'enregistrement ou de page.

    La taille du fichier sera déterminée et envoyée automatiquement au serveur pour les fichiers normaux, de sorte que cette méthode n'a besoin d'être appelée que si vous transférez des données depuis une socket, un pipe nommé ou un autre flux non associé à un fichier normal.

  • ls([$dir])
  • Obtient une liste du répertoire de $dir, ou du répertoire courant.

    Dans un contexte de tableau, retourne une liste de lignes renvoyées par le serveur. Dans un contexte scalaire, retourne une référence à une liste.

  • dir([$dir])
  • Obtient une liste du répertoire de $dir, ou du répertoire courant en format long.

    Dans un contexte de tableau, retourne une liste de lignes renvoyées par le serveur. Dans un contexte scalaire, retourne une référence à une liste.

  • "get($remote_file[, $local_file[, $where]])"
  • Récupère $remote_file du serveur et le stocke localement. $local_file peut être un nom de fichier ou un descripteur de fichier. S'il n'est pas spécifié, le fichier sera stocké dans le répertoire courant avec le même nom de feuille que le fichier distant.

    Si $where est donné, alors les $where premiers octets du fichier ne seront pas transférés, et les octets restants seront ajoutés au fichier local s'il existe déjà.

    Retourne $local_file, ou le nom de fichier local généré si $local_file n'est pas donné. Si une erreur a été rencontrée, undef est retourné.

  • "put($local_file[, $remote_file])"
  • Envoie un fichier sur le serveur distant. $local_file peut être un nom ou un descripteur de fichier. Si $local_file est un descripteur de fichier, alors $remote_file doit être spécifié. Si $remote_file n'est pas spécifié, le fichier sera stocké dans le répertoire courant avec le même nom de feuille que $local_file.

    Retourne $remote_file, ou le nom de fichier distant généré si $remote_file n'est pas donné.

    REMARQUE : Si pour une raison quelconque le transfert ne se termine pas et qu'une erreur est retournée, le contenu qui avait été transféré ne sera pas supprimé automatiquement.

  • "put_unique($local_file[, $remote_file])"
  • Identique à put mais utilise la commande "STOU".

    Retourne le nom du fichier sur le serveur.

  • "append($local_file[, $remote_file])"
  • Identique à put mais ajoute le contenu au fichier sur le serveur distant.

    Retourne $remote_file, ou le nom de fichier distant généré si $remote_file n'est pas donné.

  • unique_name()
  • Retourne le nom du dernier fichier stocké sur le serveur en utilisant la commande "STOU".
  • mdtm($file)
  • Retourne l' *heure de modification* du fichier donné.
  • size($file)
  • Retourne la taille en octets du fichier donné tel qu'il est stocké sur le serveur distant.

    REMARQUE : La taille signalée est la taille du fichier stocké sur le serveur distant. Si le fichier est ensuite transféré depuis le serveur en mode ASCII et que le serveur distant et la machine locale ont des conventions différentes pour "End Of Line" (fin de ligne), la taille du fichier sur la machine locale après le transfert peut être différente.

  • supported($cmd)
  • Retourne VRAI si le serveur distant prend en charge la commande donnée.
  • "hash([$filehandle_glob_ref[, $bytes_per_hash_mark]])"
  • Appelé sans paramètres, ou avec le premier argument faux, les marques de hachage sont supprimées. Si le premier argument est vrai mais n'est pas une référence à un descripteur de fichier glob, alors \*STDERR est utilisé. Le second argument est le nombre d'octets par marque de hachage imprimée, et vaut par défaut 1024. Dans tous les cas, la valeur de retour est une référence à un tableau de deux éléments : la référence du descripteur de fichier glob et le nombre d'octets par marque de hachage.
  • feature($name)
  • Détermine si le serveur prend en charge la fonctionnalité spécifiée. La valeur de retour est une liste de lignes avec lesquelles le serveur a répondu pour décrire les options qu'il prend en charge pour la fonctionnalité donnée. Si la fonctionnalité n'est pas prise en charge, la liste vide est retournée. 
    if ($ftp->feature( 'MDTM' )) {
  # Faire quelque chose
}
if (grep { /\bTLS\b/ } $ftp->feature('AUTH')) {
  # Le serveur prend en charge TLS
}

Les méthodes suivantes peuvent retourner des résultats différents selon la manière dont elles sont appelées. Si l'utilisateur appelle explicitement l'une des méthodes "pasv" ou "port", alors ces méthodes retourneront une valeur *vraie* ou *fausse*. Si l'utilisateur n'appelle aucune de ces méthodes, le résultat sera une référence à un objet basé sur "Net::FTP::dataconn".

  • Identique à "nlst" mais en utilisant la commande "LIST".

  • Démarre la récupération d'un fichier nommé $file depuis le serveur distant.
    • stor($file)
  • Indique au serveur que vous souhaitez stocker un fichier. $file est le nom du nouveau fichier qui doit être créé.
    • stou($file)
  • Identique à put mais utilise la commande "STOU".

    Retourne le nom du fichier sur le serveur.
