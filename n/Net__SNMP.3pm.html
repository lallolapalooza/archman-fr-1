NOM

Net::SNMP - Interface orientée objet pour SNMP

SYNTAXE

Le module Net::SNMP implémente une interface orientée objet pour le protocole SNMP (Simple Network Management Protocol). Les applications Perl peuvent utiliser le module pour récupérer ou mettre à jour des informations sur un hôte distant en utilisant le protocole SNMP. Le module prend en charge SNMP version-1, SNMP version-2c (Community-Based SNMPv2) et SNMP version-3. Le module Net::SNMP suppose que l'utilisateur a une compréhension de base du protocole SNMP et des concepts de gestion de réseau associés.

DESCRIPTION

Le module Net::SNMP abstrait les détails complexes du protocole SNMP en fournissant une interface de programmation de haut niveau au protocole. Chaque objet Net::SNMP fournit une correspondance un-à-un entre un objet Perl et un agent ou un gestionnaire SNMP distant. Une fois qu'un objet est créé, il peut être utilisé pour effectuer les actions d'échange de protocole de base définies par SNMP.

Un objet Net::SNMP peut être créé de manière à avoir des propriétés "bloquantes" ou "non bloquantes". Par défaut, les méthodes utilisées pour envoyer des messages SNMP ne retournent pas tant que l'échange de protocole n'est pas terminé avec succès ou qu'une période de délai d'attente n'a pas expiré. Ce comportement confère à l'objet une propriété "bloquante" car le flux du code est arrêté jusqu'à ce que la méthode retourne.

L'argument nommé optionnel -nonblocking peut être passé au constructeur de l'objet avec une valeur vraie pour donner à l'objet un comportement "non bloquant". Une méthode appelée par un objet non bloquant met en file d'attente le message SNMP et retourne immédiatement, permettant au flux du code de continuer. Les messages SNMP mis en file d'attente ne sont envoyés qu'une fois qu'une boucle d'événements est entrée en appelant la méthode snmp_dispatcher(). Lorsque les messages SNMP sont envoyés, toute réponse aux messages déclenche la sous-routine définie par l'utilisateur lors de la mise en file d'attente initiale du message. La boucle d'événements se termine lorsque tous les messages ont été retirés de la file d'attente, soit en recevant une réponse, soit en dépassant le nombre de tentatives au niveau de la couche de transport.

Objets bloquants

Le comportement par défaut des méthodes associées à un objet Net::SNMP est de bloquer le flux du code jusqu'à ce que la méthode se termine. Pour les méthodes qui initient un échange de protocole SNMP nécessitant une réponse, une référence de hachage contenant les résultats de la requête est retournée. La valeur indéfinie est retournée par toutes les méthodes lorsqu'un échec s'est produit. La méthode error() peut être utilisée pour déterminer la cause de l'échec.

La référence de hachage retournée par un échange de protocole SNMP pointe vers un hachage construit à partir de la VarBindList contenue dans le message de réponse SNMP. Le hachage est créé en utilisant les paires ObjectName et ObjectSyntax dans la VarBindList. Les clés du hachage sont les IDENTIFIANTS D'OBJET en notation décimale correspondant à chaque ObjectName dans la VarBindList. La valeur de chaque entrée du hachage est définie égale à la valeur de l'ObjectSyntax correspondante. Cette référence de hachage peut également être récupérée en utilisant la méthode var_bind_list().

Objets non bloquants

Lorsqu'un objet Net::SNMP est créé avec un comportement non bloquant, l'appel d'une méthode associée à l'objet retourne immédiatement, permettant au flux du code de continuer. Lorsqu'une méthode est appelée qui initierait un échange de protocole SNMP nécessitant une réponse, soit une valeur vraie (c'est-à-dire 0x1) est retournée immédiatement, soit la valeur indéfinie est retournée s'il y a eu un échec. La méthode error() peut être utilisée pour déterminer la cause de l'échec.

Le contenu de la VarBindList contenue dans le message de réponse SNMP peut être récupéré en appelant la méthode var_bind_list() en utilisant la référence d'objet passée comme premier argument au rappel. La valeur retournée par la méthode var_bind_list() est une référence de hachage créée en utilisant les paires ObjectName et ObjectSyntax dans la VarBindList. Les clés du hachage sont les IDENTIFIANTS D'OBJET en notation décimale correspondant à chaque ObjectName dans la VarBindList. La valeur de chaque entrée de hachage est définie égale à la valeur de l'ObjectSyntax correspondante. La valeur indéfinie est retournée s'il y a eu un échec et que la méthode error() peut être utilisée pour déterminer la raison.

Arguments des objets non bloquants
Lorsqu'un objet Net::SNMP a été créé avec une propriété "non bloquante", la plupart des méthodes qui génèrent un message SNMP prennent des arguments supplémentaires pour prendre en charge cette propriété.
Callback (Rappel)
La plupart des méthodes associées à un objet non bloquant ont un argument nommé optionnel appelé -callback. L'argument -callback attend une référence à une sous-routine ou à un tableau dont le premier élément doit être une référence à une sous-routine. La sous-routine définie par l'option -callback est exécutée lorsqu'une réponse à un message SNMP est reçue, qu'une condition d'erreur s'est produite ou que le nombre de tentatives pour le message a été dépassé.

Lorsque l'argument -callback ne contient qu'une référence de sous-routine, la sous-routine est évaluée en passant une référence à l'objet Net::SNMP d'origine comme seul paramètre. Si l'argument -callback a été défini comme une référence de tableau, tous les éléments du tableau sont passés à la sous-routine après la référence à l'objet Net::SNMP. Le premier élément, qui doit être une référence à une sous-routine, est supprimé avant que les arguments restants ne soient transmis à cette sous-routine.

Une fois qu'une méthode est appelée avec l'argument -callback, cet argument reste avec l'objet et est utilisé par les appels ultérieurs aux méthodes utilisant l'option -callback si l'argument est absent. La valeur indéfinie peut être passée à l'argument -callback pour supprimer le rappel.

NOTE : La sous-routine passée avec l'argument nommé -callback ne doit pas provoquer de blocage elle-même. Cela provoquera l'arrêt de toutes les actions dans la boucle d'événements, annulant la propriété non bloquante du module Net::SNMP.

Délai
Un argument optionnel -delay peut également être passé aux objets non bloquants. L'argument -delay demande à l'objet d'attendre le nombre de secondes passé à l'argument avant d'exécuter l'échange de protocole SNMP. La période de délai commence lorsque la boucle d'événements est entrée. Le paramètre -delay est appliqué à toutes les méthodes associées à l'objet une fois qu'il est spécifié. La valeur de délai doit être remise à 0 seconde pour désactiver le paramètre de délai.
Arguments SNMPv3
Un contexte SNMP est une collection d'informations de gestion accessibles par une entité SNMP. Un élément d'information de gestion peut exister dans plus d'un contexte et une entité SNMP a potentiellement accès à de nombreux contextes. La combinaison d'un contextEngineID et d'un contextName identifie sans ambiguïté un contexte au sein d'un domaine administratif. Dans un message SNMPv3, le contextEngineID et le contextName sont inclus dans le cadre du scopedPDU. Toutes les méthodes qui génèrent un message SNMP acceptent optionnellement un argument -contextengineid et -contextname pour configurer ces champs.
Moteur de contexte ID
L'argument -contextengineid attend une chaîne hexadécimale représentant le contextEngineID désiré. La chaîne doit être longue de 10 à 64 caractères (5 à 32 octets) et peut être préfixée d'un "0x" optionnel. Une fois le -contextengineid spécifié, il reste avec l'objet jusqu'à ce qu'il soit à nouveau modifié ou réinitialisé par défaut en passant la valeur indéfinie. Par défaut, le contextEngineID est défini pour correspondre à l'authoritativeEngineID du moteur SNMP d'autorité.

Arguments de domaine de transport
Le module Net::SNMP utilise UDP/IPv4 comme domaine de transport par défaut pour échanger des messages SNMP entre les appareils locaux et distants. Il prend également en charge UDP/IPv6, TCP/IPv4 et TCP/IPv6 en tant qu'alternatives. L'argument -domain peut être utilisé pour modifier le domaine de transport en définissant la valeur sur l'une des chaînes suivantes : « udp6 », « udp/ipv6 » ; « tcp », « tcp4 », « tcp/ipv4 » ; « tcp6 », ou « tcp/ipv6 ». L'argument -domain accepte également les chaînes « udp », « udp4 », ou « udp/ipv4 » qui correspondent au domaine de transport par défaut UDP/IPv4.

L'adresse de transport de l'appareil SNMP de destination peut être spécifiée via l'argument -hostname. Cet argument est facultatif et prend par défaut la valeur « localhost ». Le numéro de port de destination peut être spécifié dans le cadre de l'adresse de transport ou via l'argument -port. Un numéro de port numérique ou un nom de service textuel peuvent être spécifiés. Un numéro de port numérique entre parenthèses peut éventuellement suivre le nom du service. Ce numéro de port sera utilisé si le nom du service ne peut pas être résolu. Si le numéro de port de destination n'est pas spécifié, le port bien connu 161 est utilisé.

Par défaut, les adresses et ports de transport source sont attribués dynamiquement par l'appareil local sur lequel le module Net::SNMP est utilisé. Cette attribution dynamique peut être remplacée en utilisant les arguments -localaddr et -localport. Ces arguments acceptent les mêmes valeurs que les arguments -hostname et -port respectivement. L'adresse résolue doit correspondre à une adresse valide d'une interface de l'appareil local.

Lors de l'utilisation d'un domaine de transport IPv4, l'adresse de transport peut être spécifiée comme un nom d'hôte réseau IP ou comme une adresse IPv4 en notation décimale à points standard. Les informations de port peuvent éventuellement être jointes au nom d'hôte ou à l'adresse séparées par un deux-points. Les formats d'adresse de transport IPv4 acceptés sont "address", "address:port", "hostname" et "hostname:port".

Lors de l'utilisation d'un domaine de transport IPv6, l'adresse de transport peut être spécifiée comme un nom d'hôte IP (qui sera recherché en tant qu'enregistrement quad-A) ou comme une adresse IPv6 en notation de présentation. Les informations de port peuvent éventuellement être incluses après un deux-points suivant le nom d'hôte ou l'adresse. Lors de l'inclusion de ces informations après une adresse IPv6, l'adresse doit être entourée de crochets. L'index de zone (décrit dans la RFC 4007) peut être spécifié après l'adresse sous forme d'une valeur décimale séparée par un signe pourcentage. Les formats d'adresse de transport IPv6 acceptés sont "address", "address%zone", "[address]:port", "[address%zone]:port", "hostname" et "hostname:port".

Arguments du modèle de sécurité
L'argument -version contrôle quels autres arguments sont requis par le constructeur session(). Le module Net::SNMP prend en charge SNMPv1, SNMPv2c et SNMPv3. Le module utilise SNMPv1 par défaut si l'argument -version n'est pas spécifié. L'argument -version attend un nombre (c'est-à-dire « 1 », « 2 » ou « 3 ») ou une chaîne spécifiant la version (par exemple, « snmpv1 », « snmpv2c », ou « snmpv3 ») pour définir la version SNMP.

Le modèle de sécurité utilisé par l'objet Net::SNMP est basé sur la version SNMP associée à l'objet. Si la version SNMP est SNMPv1 ou SNMPv2c, un modèle de sécurité basé sur la communauté sera utilisé, tandis que si la version est SNMPv3, le modèle de sécurité basé sur l'utilisateur (USM) sera utilisé.

Argument du modèle de sécurité basé sur la communauté
Si le modèle de sécurité est basé sur la communauté, le seul argument disponible est -community. Cet argument attend une chaîne qui sera utilisée comme nom de communauté. Par défaut, le nom de communauté est défini sur « public » si l'argument est absent.
Arguments du modèle de sécurité basé sur l'utilisateur
Le modèle de sécurité basé sur l'utilisateur (USM) utilisé par SNMPv3 nécessite la spécification d'un nom de sécurité à l'aide de l'argument -username. La création d'un objet Net::SNMP avec la version définie sur SNMPv3 échouera si l'argument -username est manquant. L'argument -username attend une chaîne de 1 à 32 octets.

Différents niveaux de sécurité sont autorisés par le modèle de sécurité basé sur l'utilisateur qui traitent des préoccupations d'authentification et de confidentialité. Un objet Net::SNMP SNMPv3 dérivera le niveau de sécurité (securityLevel) en fonction de celui des arguments suivants qui est spécifié.

Par défaut, un niveau de sécurité « noAuthNoPriv » est supposé. Si les arguments -authkey ou -authpassword sont spécifiés, le niveau de sécurité devient « authNoPriv ». L'argument -authpassword attend une chaîne d'au moins 1 octet. Facultativement, l'argument -authkey peut être utilisé afin qu'un mot de passe en texte clair n'ait pas à être spécifié dans un script. L'argument -authkey attend une chaîne hexadécimale produite en hachant le mot de passe avec l'authoritativeEngineID de l'appareil de destination spécifique. L'utilitaire "snmpkey" inclus dans la distribution peut être utilisé pour créer la chaîne hexadécimale (voir snmpkey).

Deux algorithmes de hachage différents sont définis par SNMPv3 qui peuvent être utilisés par le modèle de sécurité pour l'authentification. Ces algorithmes sont HMAC-MD5-96 « MD5 » (RFC 1321) et HMAC-SHA-96 « SHA-1 » (NIST FIPS PUB 180-1). L'algorithme par défaut utilisé par le module est HMAC-MD5-96. Ce comportement peut être modifié en utilisant l'argument -authprotocol. Cet argument attend soit la chaîne « md5 » soit « sha » pour modifier l'algorithme de hachage.

Lors de la spécification des arguments -privkey ou -privpassword, le niveau de sécurité associé à l'objet devient « authPriv ». Selon SNMPv3, la confidentialité nécessite l'utilisation de l'authentification. Par conséquent, si l'un de ces deux arguments est présent et que les arguments -authkey ou -authpassword sont absents, la création de l'objet échoue. Les arguments -privkey et -privpassword attendent le même type d'entrée que les arguments -authkey et -authpassword respectivement.

Le modèle de sécurité basé sur l'utilisateur décrit dans la RFC 3414 définit un seul protocole de chiffrement pour la confidentialité. Ce protocole, CBC-DES « DES » (NIST FIPS PUB 46-1), est utilisé par défaut ou si la chaîne « des » est passée à l'argument -privprotocol. Le module prend également en charge la RFC 3826 qui décrit l'utilisation de CFB128-AES-128 « AES » (NIST FIPS PUB 197) dans l'USM. Le protocole de chiffrement AES peut être sélectionné en passant « aes » ou « aes128 » à l'argument -privprotocol. En travaillant avec le Extended Security Options Consortium http://www.snmp.com/protocol/eso.shtml, le module prend également en charge CBC-3DES-EDE « Triple-DES » (NIST FIPS 46-3) dans le modèle de sécurité basé sur l'utilisateur. Cette définition se trouve dans le brouillon http://www.snmp.com/eso/draft-reeder-snmpv3-usm-3desede-00.txt. Le protocole de chiffrement Triple-DES peut être sélectionné en utilisant l'argument -privprotocol avec la chaîne « 3des » ou « 3desede ».

$result = $session->get_request(

                    );

Cette méthode effectue une requête SNMP get-request pour collecter des données de l'agent distant sur l'hôte associé à l'objet Net::SNMP. Le message est construit en utilisant la liste des IDENTIFIANTS D'OBJETS en notation décimale passée à la méthode sous forme de référence de tableau via l'argument -varbindlist. Chaque IDENTIFIANT D'OBJET est placé dans une unique PDU SNMP GetRequest dans le même ordre qu'il figurait dans la liste d'origine.

Une référence à une table de hachage est retournée en mode bloquant, contenant le contenu de la VarBindList. En mode non bloquant, une valeur vraie est retournée lorsqu'aucune erreur ne s'est produite. Dans les deux modes, la valeur indéfinie est retournée lorsqu'une erreur s'est produite. trap() - envoie un trap SNMP au gestionnaire distant

$result = $session->trap(
                       [-delay           => $seconds,]   # non bloquant
                       [-enterprise      => $oid,]
                       [-agentaddr       => $ipaddress,]
                       [-generictrap     => $generic,]
                       [-specifictrap    => $specific,]
                       [-timestamp       => $timeticks,]
                       -varbindlist      => \@oid_value,
                    );

Cette méthode envoie un trap SNMP au gestionnaire distant associé à l'objet Net::SNMP. Tous les arguments sont optionnels et recevront les valeurs par défaut suivantes en l'absence d'un argument nommé correspondant :

  • La valeur par défaut pour le -enterprise du trap est "1.3.6.1.4.1", qui correspond à "iso.org.dod.internet.private.enterprises". La valeur de l'entreprise est attendue comme un IDENTIFIANT D'OBJET en notation décimale.
  • Lorsque le Domaine de Transport est UDP/IPv4 ou TCP/IPv4, la valeur par défaut pour le -agentaddr du trap est l'adresse IP associée à l'interface sur laquelle le trap sera transmis. Pour les autres Domaines de Transport, le -agentaddr est par défaut "0.0.0.0". Lorsqu'il est spécifié, l'agent-addr est attendu comme une IpAddress en notation décimale.
  • La valeur par défaut pour le type -generictrap est 6, ce qui correspond à "enterpriseSpecific". Les types de traps génériques sont définis et peuvent être exportés sur demande (voir "EXPORTS").
  • La valeur par défaut pour le type -specifictrap est 0. Aucune valeur prédéfinie n'est disponible pour les types de traps spécifiques.
  • La valeur par défaut pour le -timestamp du trap est l'"uptime" du script. L'"uptime" du script est le nombre de centièmes de seconde écoulés depuis le début de l'exécution du script. Le timestamp est attendu comme un nombre TimeTicks en centièmes de seconde.
  • La valeur par défaut pour le -varbindlist du trap est une référence de tableau vide. Les liaisons de variables sont attendues sous forme de tableau consistant en des groupes d'un IDENTIFIANT D'OBJET, d'un type d'objet et de la valeur réelle de l'objet. Ceci est identique à la liste attendue par la méthode set_request(). Les IDENTIFIANTS D'OBJETS dans chaque trio doivent être en notation décimale. Le type d'objet est un octet correspondant au type ASN.1 pour la valeur. Chacun des types pris en charge a été défini et est exporté par défaut (voir "EXPORTS").

Une valeur vraie est retournée lorsque la méthode réussit. La valeur indéfinie est retournée lorsqu'un échec se produit. La méthode error() peut être utilisée pour déterminer la cause de l'échec. Comme il n'y a pas d'accusés de réception pour les TRAP-PDU, il n'y a aucun moyen de déterminer si l'hôte distant a effectivement reçu le trap.

NOTE : Lorsque l'objet est en mode non bloquant, le trap n'est pas envoyé tant que la boucle d'événements n'est pas entrée et aucun rappel n'est jamais exécuté.

NOTE : Cette méthode ne peut être utilisée que lorsque la version de l'objet est définie sur SNMPv1.

get_bulk_request() - envoie une requête SNMP get-bulk-request à l'agent distant

$result = $session->get_bulk_request(
                       [-callback        => sub {},]     # non bloquant
                       [-delay           => $seconds,]   # non bloquant
                       [-contextengineid => $engine_id,] # v3
                       [-contextname     => $name,]      # v3
                       [-nonrepeaters    => $non_reps,]
                       [-maxrepetitions  => $max_reps,]
                       -varbindlist      => \@oids,
                    );

Cette méthode effectue une requête SNMP get-bulk-request pour collecter des données de l'agent distant sur l'hôte associé à l'objet Net::SNMP. Tous les arguments sont optionnels sauf -varbindlist et recevront les valeurs par défaut suivantes en l'absence d'un argument nommé correspondant :

  • La valeur par défaut pour le -nonrepeaters de la requête get-bulk-request est 0. La valeur non-repeaters spécifie le nombre de variables dans la liste des liaisons de variables pour lesquelles un seul successeur doit être retourné.
  • La valeur par défaut pour le -maxrepetitions de la requête get-bulk-request est 0. La valeur max-repetitions spécifie le nombre de successeurs à retourner pour les variables restantes dans la liste des liaisons de variables.
  • L'argument -varbindlist attend une référence de tableau consistant en une liste d'IDENTIFIANTS D'OBJETS en notation décimale. Chaque IDENTIFIANT D'OBJET est placé dans une unique PDU SNMP GetBulkRequest dans le même ordre qu'il figurait dans la liste d'origine.

Une référence à une table de hachage est retournée en mode bloquant, contenant le contenu de la VarBindList. Cette méthode effectue des requêtes SNMP get-next-request ou get-bulk-request (lors de l'utilisation de SNMPv2c ou SNMPv3) pour collecter des données de l'agent distant associé à l'objet Net::SNMP. Chaque message spécifie des données pour chaque IDENTIFIANT D'OBJET spécifié dans le tableau -columns. Les IDENTIFIANTS D'OBJET doivent correspondre aux entrées de colonne d'une ligne conceptuelle d'une table. Il peut s'agir de colonnes de différentes tables, à condition que chaque table soit indexée de manière similaire. L'argument optionnel -endindex peut être spécifié comme une valeur décimale unique ou en notation point-virgule. Si le -endindex est spécifié, il sera inclus dans les résultats de la requête. Si -endindex n'est pas spécifié, des requêtes SNMP répétées sont émises jusqu'à ce que la réponse ne renvoie pas d'entrées correspondant à l'un des identifiants d'objet spécifiés dans le tableau -columns.

Le -maxrepetitions peut être utilisé pour spécifier la valeur de répétition maximale qui est passée aux requêtes get-bulk lors de l'utilisation de SNMPv2c ou SNMPv3. Si cet argument est absent, une valeur est calculée en fonction de la taille maximale du message de l'objet et du nombre de colonnes spécifié dans le tableau -columns. Si la valeur est définie sur 1 ou moins, des requêtes get-next seront utilisées à la place des requêtes get-bulk.

Dans l'un ou l'autre mode, une valeur indéfinie est renvoyée en cas d'erreur. La méthode error() peut être utilisée pour déterminer la cause de l'erreur.

Lorsque l'objet décode le PDU GetResponse retourné en réponse à un message SNMP, certaines valeurs sont traduites dans une forme plus "lisible par l'homme". Par défaut, les traductions suivantes s'opèrent :

  • Les chaînes OCTET STRING et OPAQUE contenant des octets qui ne font pas partie de l'ensemble de caractères défini comme DisplayString dans la RFC 2679 sont converties en une représentation hexadécimale précédée de "0x". Les codes de contrôle NUL(0x00), BEL(0x07), BS(0x08), HT(0x09), LF(0x0A), VT(0x0b), FF(0x0C) et CR(0x0D) font partie de l'ensemble de caractères et ne généreront pas de traduction. La séquence "CR x" pour tout x n'étant ni LF ni NUL est illégale et générera une traduction.
  • Les valeurs TimeTicks sont converties en un format temporel.
  • Les valeurs NULL retournent la chaîne "NULL" au lieu d'une chaîne vide.
  • Les valeurs noSuchObject retournent la chaîne "noSuchObject" au lieu d'une chaîne vide.
  • Les valeurs noSuchInstance retournent la chaîne "noSuchInstance" au lieu d'une chaîne vide.
  • Les valeurs endOfMibView retournent la chaîne "endOfMibView" au lieu d'une chaîne vide.
  • Les valeurs Counter64, Counter, Gauge et TimeTick qui ont été codées de manière incorrecte comme des valeurs négatives sont retournées comme des valeurs non signées.

La méthode translate() peut être appelée avec deux types d'arguments différents.

Si l'argument passé est n'importe quel type de variable Perl à l'exception d'une référence de tableau, le mode de traduction de tous les types ASN.1 est défini sur activé ou désactivé selon la valeur du paramètre passé. Toute valeur que Perl considère comme vraie active le mode de traduction pour tous les types, tandis qu'une valeur fausse désactive la traduction pour tous les types.

Une référence de tableau peut être passée à la méthode translate() pour définir le mode de traduction par type ASN.1. La référence attendue contient une liste de paires d'arguments nommés pour chaque type ASN.1 à modifier. Les arguments de la liste sont appliqués dans l'ordre où ils sont passés dans le tableau. Les arguments en fin de liste remplacent ceux passés précédemment dans la liste. L'argument "-all" peut être utilisé pour spécifier que le mode s'applique à tous les types ASN.1. Seuls les arguments pour les types ASN.1 à modifier doivent être inclus dans la liste.

La méthode translate() retourne un masque de bits indiquant les types ASN.1 à traduire. Les définitions des bits aux types ASN.1 peuvent être exportées en utilisant le tag :translate (voir "EXPORTS"). La valeur undefined est retournée en cas d'erreur et la méthode error() peut être utilisée pour déterminer la cause.

La valeur actuelle du masque de débogage est retournée par la méthode. Le débogage peut également être activé en utilisant la fonction indépendante snmp_debug(). Cette fonction peut être exportée sur demande (voir "EXPORTS").

EXEMPLES

1. Bloquer une requête SNMPv1 get pour sysUpTime

Cet exemple récupère la valeur de sysUpTime d'un hôte distant.

#! /usr/local/bin/perl
use strict;
use warnings;
use Net::SNMP;
my $OID_sysUpTime = '1.3.6.1.2.1.1.3.0';
my ($session, $error) = Net::SNMP->session(
   -hostname  => shift || 'localhost',
   -community => shift || 'public',
);
if (!defined $session) {
   printf "ERREUR : %s.\n", $error;
   exit 1;
}
my $result = $session->get_request(-varbindlist => [ $OID_sysUpTime ],);
if (!defined $result) {
   printf "ERREUR : %s.\n", $session->error();
   $session->close();
   exit 1;
}
printf "Le sysUpTime pour l'hôte '%s' est %s.\n",
       $session->hostname(), $result->{$OID_sysUpTime};
$session->close();
exit 0;

2. Bloquer une requête SNMPv3 set pour sysContact

Cet exemple définit la valeur de sysContact sur un hôte distant à "Help Desk x911". Les arguments nommés transmis à la fonction session() sont utilisés uniquement pour la démonstration de la syntaxe. Ces paramètres doivent être configurés en fonction des paramètres SNMPv3 de l'hôte distant. L'utilitaire "snmpkey" inclus dans la distribution peut être utilisé pour créer les valeurs de clé.

use warnings;
use Net::SNMP;
my $OID_sysContact = '1.3.6.1.2.1.1.4.0';
my ($session, $error) = Net::SNMP->session(
   -hostname     => 'myv3host.example.com',
   -version      => 'snmpv3',
   -username     => 'myv3Username',
   -authprotocol => 'sha1',

3. Requête SNMPv2c get-bulk non bloquante pour ifTable

Cet exemple récupère le contenu de ifTable en envoyant des requêtes get-bulk jusqu'à ce que les réponses ne fassent plus partie de ifTable. ifTable peut également être récupéré en utilisant la fonction get_table(). L'objet ifPhysAddress dans la table est au format OCTET STRING. Par défaut, la traduction est activée et les OCTET STRING non imprimables sont traduits en format hexadécimal. Parfois, les OCTET STRING ne contiennent que des caractères imprimables, ce qui peut entraîner un résultat inattendu si la traduction n'est pas désactivée. L'exemple désactive la traduction pour OCTET STRING et formate la sortie spécifiquement pour les objets ifPhysAddress.

#! /usr/local/bin/perl
use strict;
use warnings;
use Net::SNMP qw(:snmp);
my $OID_ifTable = '1.3.6.1.2.1.2.2';
my $OID_ifPhysAddress = '1.3.6.1.2.1.2.2.1.6';
my ($session, $error) = Net::SNMP->session(
   -hostname    => shift || 'localhost',
   -community   => shift || 'public',
   -nonblocking => 1,
   -translate   => [-octetstring => 0],
   -version     => 'snmpv2c',
);
if (!defined $session) {
   printf "ERREUR : %s.\n", $error;
   exit 1;
}
my %table; # Hash pour stocker les résultats
my $result = $session->get_bulk_request(
   -varbindlist    => [ $OID_ifTable ],
   -callback       => [ \&table_callback, \%table ],
   -maxrepetitions => 10,
);
if (!defined $result) {
   printf "ERREUR : %s\n", $session->error();
   $session->close();
   exit 1;
}
# Lancer maintenant l'échange des messages SNMP.
snmp_dispatcher();
$session->close();
# Afficher les résultats, spécifiquement pour ifPhysAddress.
for my $oid (oid_lex_sort(keys %table)) {
   if (!oid_base_match($OID_ifPhysAddress, $oid)) {
      printf "%s = %s\n", $oid, $table{$oid};
   } else {
      printf "%s = %s\n", $oid, unpack 'H*', $table{$oid};
   }
}
exit 0;
sub table_callback
{
   my ($session, $table) = @_;
   my $list = $session->var_bind_list();
   if (!defined $list) {
      printf "ERREUR : %s\n", $session->error();
      return;
   }
   # Parcourir chacun des OIDs dans la réponse et assigner les paires clé/valeur à la référence qui a été passée avec le callback. Assurez-vous d'être toujours dans la table avant d'assigner les paires clé/valeur.
   my @names = $session->var_bind_names();
   my $next  = undef;
   while (@names) {
      $next = shift @names;
      if (!oid_base_match($OID_ifTable, $next)) {
         return; # La table est terminée.
      }
      $table->{$next} = $list->{$next};
   }
   # La table n'est pas terminée, envoyer une autre requête, en commençant par le dernier OID de la réponse. Il n'est pas nécessaire de spécifier l'argument callback, le même callback que celui spécifié pour la requête originale sera utilisé.
   my $result = $session->get_bulk_request(
      -varbindlist    => [ $next ],
      -maxrepetitions => 10,
   );
   if (!defined $result) {
      printf "ERREUR : %s.\n", $session->error();
   }
   return;
}

4. Requêtes SNMPv1 get et set non bloquantes sur plusieurs hôtes

Cet exemple interroge d'abord plusieurs hôtes pour leur sysUpTime. Si l'interrogation de l'hôte réussit, les informations sysContact et sysLocation sont définies sur l'hôte. Les informations sysContact sont codées en dur à "Help Desk x911", tandis que les informations sysLocation sont passées comme argument au callback.

#! /usr/local/bin/perl
use strict;
use warnings;
use Net::SNMP;
my $OID_sysUpTime = '1.3.6.1.2.1.1.3.0';
my $OID_sysContact = '1.3.6.1.2.1.1.4.0';
my $OID_sysLocation = '1.3.6.1.2.1.1.6.0';
# Hash des hôtes et des données de localisation.
my %host_data = (
   '10.1.1.2'  => 'Building 1, Second Floor',
   '10.2.1.1'  => 'Building 2, First Floor',
   'localhost' => 'Right here!',
);
# Créer une session pour chaque hôte et mettre en file d'attente une requête get pour sysUpTime.
for my $host (keys %host_data) {
   my ($session, $error) = Net::SNMP->session(
      -hostname    => $host,
      -community   => 'private',
      -nonblocking => 1,
   );
   if (!defined $session) {
      printf "ERREUR : Échec de la création de la session pour l'hôte '%s': %s.\n",
             $host, $error;
      next;
   }
   my $result = $session->get_request(
      -varbindlist => [ $OID_sysUpTime ],
      -callback    => [ \&get_callback, $host_data{$host} ],
   );
   if (!defined $result) {
      printf "ERREUR : Échec de la mise en file d'attente de la requête get pour l'hôte '%s': %s.\n",
             $session->hostname(), $session->error();
   }
}
# Lancer maintenant l'échange des messages SNMP.
snmp_dispatcher();
exit 0;
sub get_callback
{
   my ($session, $location) = @_;
   my $result = $session->var_bind_list();
   if (!defined $result) {
      printf "ERREUR : Échec de la requête get pour l'hôte '%s': %s.\n",
             $session->hostname(), $session->error();
      return;
   }
   printf "Le sysUpTime pour l'hôte '%s' est %s.\n",
           $session->hostname(), $result->{$OID_sysUpTime};
   # Définir maintenant sysContact et sysLocation pour l'hôte.
   $result = $session->set_request(
      -varbindlist =>
      [
         $OID_sysContact,  OCTET_STRING, 'Help Desk x911',
         $OID_sysLocation, OCTET_STRING, $location,
      ],
      -callback    => \&set_callback,
   );
   if (!defined $result) {
      printf "ERREUR : Échec de la mise en file d'attente de la requête set pour l'hôte '%s': %s.\n",
             $session->hostname(), $session->error();
   }
   return;
}
sub set_callback
{
   my ($session) = @_;
   my $result = $session->var_bind_list();
   if (defined $result) {
      printf "Le sysContact pour l'hôte '%s' a été défini à '%s'.\n",
             $session->hostname(), $result->{$OID_sysContact};
      printf "Le sysLocation pour l'hôte '%s' a été défini à '%s'.\n",
             $session->hostname(), $result->{$OID_sysLocation};
   } else {
      printf "ERREUR : Échec de la requête set pour l'hôte '%s': %s.\n",
             $session->hostname(), $session->error();

}
