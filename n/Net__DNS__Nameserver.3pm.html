NOM

Net::DNS::Nameserver - Classe de serveur DNS

SYNOPIS

use Net::DNS::Nameserver;
my $nameserver = Net::DNS::Nameserver->new(
                LocalAddr       => ['::1', '127.0.0.1'],
                LocalPort       => 15353,
                ZoneFile        => 'nom_fichier'
                );
my $nameserver = Net::DNS::Nameserver->new(
                LocalAddr       => '10.1.2.3',
                LocalPort       => 15353,
                ReplyHandler    => \&gestionnaire_reponse
                );
$nameserver->start_server($timeout);
$nameserver->stop_server;

DESCRIPTION

Net::DNS::Nameserver offre un mécanisme simple pour l'instanciation d'objets de serveur DNS personnalisés destinés à fournir des réponses de test aux requêtes émanant d'un résolveur client.

Ce n'est pas, et ne sera jamais, une implémentation de serveur DNS à usage général.

Voir "EXEMPLES" ci-dessous pour plus de détails.

MÉTHODES

new

$nameserver = Net::DNS::Nameserver->new(
                LocalAddr       => ['::1', '127.0.0.1'],
                LocalPort       => 15353,
                ZoneFile        => "nom_fichier"
                );
$nameserver = Net::DNS::Nameserver->new(
                LocalAddr       => '10.1.2.3',
                LocalPort       => 15353,
                ReplyHandler    => \&gestionnaire_reponse,
                Verbose         => 1,
                Truncate        => 0
                );

Instancie un objet Net::DNS::Nameserver. Une exception est levée si l'objet n'a pas pu être créé.

Chaque instance est configurée en utilisant les arguments optionnels suivants :

LocalAddr
Adresse IP sur laquelle écouter. Par défaut, l'adresse de boucle locale.
LocalPort
Port sur lequel écouter.
ZoneFile
Nom du fichier contenant les RR accédés en utilisant la sous-routine interne de gestion des réponses.
ReplyHandler
Référence à une sous-routine personnalisée de gestion des réponses.
NotifyHandler
Référence à une sous-routine de gestion des réponses pour les requêtes avec l'opcode NOTIFY (RFC1996).
UpdateHandler
Référence à une sous-routine de gestion des réponses pour les requêtes avec l'opcode UPDATE (RFC2136).
Verbose
Rapporte l'activité interne. Par défaut à 0 (désactivé).
Truncate
Tronque les paquets UDP trop volumineux pour la réponse. Par défaut à 1 (activé).

L'attribut LocalAddr peut alternativement être spécifié comme un tableau d'adresses IP sur lesquelles écouter.

La sous-routine ReplyHandler reçoit le nom de la requête, la classe de la requête, le type de la requête, l'hôte distant, l'enregistrement de la requête et le descripteur de connexion. Elle doit soit retourner le code de réponse et des références aux sections de réponse, d'autorité et additionnelles de la réponse, soit retourner undef pour laisser la requête sans réponse. Les codes de réponse courants sont :

NOERROR
Pas d'erreur
FORMERR
Erreur de format
SERVFAIL
Échec du serveur
NXDOMAIN
Domaine inexistant (nom inexistant)
NOTIMP
Non implémenté
REFUSED
Requête refusée

Pour une utilisation avancée, il peut également contenir un masque d'en-tête contenant un hash avec les paramètres des bits d'en-tête "aa", "ra" et "ad". L'argument est de la forme : {ad => 1, aa => 0, ra => 1}

Les options EDNS peuvent être spécifiées de manière similaire en utilisant le masque d'options : {$optioncode => $valeur, $nomoption => $valeur}

Voir RFC1035 et le fichier des paramètres DNS de l'IANA pour plus d'informations :

Le serveur DNS écoutera les connexions UDP et TCP. Sur Linux et d'autres systèmes Unix, les utilisateurs non privilégiés n'ont pas accès aux ports inférieurs à 1024.

La fonctionnalité de troncature des réponses UDP a été introduite dans Net::DNS 0.66. La limite de taille est déterminée par la taille EDNS0 annoncée dans la requête, sinon 512 est utilisé. Si vous souhaitez effectuer la troncature des paquets vous-même, vous devriez définir Truncate=>0 et tronquer le paquet de réponse dans le code de la ReplyHandler.

start_server

$ns->start_server( <TEMPS_MORT_EN_SECONDES> );

Démarre un processus serveur pour chacun des sockets UDP et TCP spécifiés qui répond continuellement aux connexions utilisateur.

Le paramètre de délai d'attente spécifie le temps pendant lequel le serveur doit rester actif. S'il est appelé sans paramètre, un délai d'attente par défaut de 10 minutes est appliqué.

stop_server

$ns->stop_server();

Termine tous les processus serveur de manière ordonnée.

EXEMPLES

Exemple 1 : Script de test avec serveur DNS intégré

L'exemple suivant est un script de test autonome qui interroge des données de zone DNS servies par une instance intégrée de Net::DNS::Nameserver.

use strict;
use warnings;
use Test::More;
plan skip_all => 'Net::DNS::Nameserver non disponible'
                unless eval { require Net::DNS::Nameserver }
                and Net::DNS::Nameserver->can('start_server');
plan tests => 2;
my $resolver = Net::DNS::Resolver->new(
                nameserver => ['::1', '127.0.0.1'],
                port       => 15353
                );

my $ns = Net::DNS::Nameserver->new(
                LocalAddr => [$resolver->nameserver],
                LocalPort => $resolver->port,
                Verbose   => 0,
                ZoneFile  => \*DATA
                ) or die "impossible de créer l'objet nameserver";
$ns->start_server(10);
my $reply = $resolver->send(qw(example.com SOA));
is( ref($reply), 'Net::DNS::Packet', 'paquet de réponse reçu' );
my ($rr) = $reply->answer;
is( $rr->type, 'SOA', 'la réponse contient un enregistrement SOA' );
$ns->stop_server();
exit;
__DATA__
$ORIGIN example.com.
@       IN SOA  mname rname 2023 2h 1h 2w 1h
www     IN A    93.184.216.34

DESCRIPTION

Net::DNS::Nameserver est un module Perl qui permet d'interagir avec des serveurs de noms sur UDP. Le module offre des fonctionnalités pour créer et gérer des connexions avec des serveurs de noms, gérer les requêtes UDP et le protocole DNS.

MÉTHODES

Les principales méthodes du module incluent :

  • new() : Crée un nouvel objet serveur de noms.
  • start_server() : Démarre le serveur de noms sur un port spécifié.
  • ReplyHandler() : Définit le gestionnaire pour les réponses UDP.

EXEMPLES

my $ns = Net::DNS::Nameserver->new(
                LocalPort    => 15353,
                ReplyHandler => \&reply_handler,
                Verbose      => 1
                ) or die "couldn't create nameserver object";
$ns->start_server(60);
exit;   # leaving nameserver processes running for 60 seconds

BOGUES

Les limitations de Perl rendent impossible de garantir que les réponses aux requêtes UDP provenant de Net::DNS::Nameserver soient envoyées depuis l'adresse IP à laquelle la requête était destinée, et que l'adresse source soit choisie en fonction de la perception du système d'exploitation de « l'adresse la plus proche ». Cette limitation est atténuée en créant un socket et un processus fils distincts pour chaque adresse IP.
