NOM

Net::XMPP::Client - Module client XMPP

SYNOPIS

Net::XMPP::Client est un module qui fournit un accès facile aux protocoles Extensible Messaging and Presence Protocol (XMPP).

DESCRIPTION

Client.pm utilise Protocol.pm pour fournir suffisamment d'API de haut niveau et d'automatisation des API de bas niveau qui rendent trivial l'écriture d'un client XMPP en Perl. Pour ceux qui souhaitent travailler avec les bas niveaux, ils le peuvent également, mais ces fonctionnalités sont couvertes dans le fichier d'aide de chaque module.

Net::XMPP::Client fournit des fonctions pour se connecter à un serveur XMPP, se connecter, envoyer et recevoir des messages, définir des informations personnelles, créer un nouveau compte utilisateur, gérer le roster et se déconnecter. Vous pouvez utiliser toutes les fonctionnalités ou aucune d'entre elles, il n'y a aucune exigence.

Pour plus d'informations sur la façon dont les détails de Net::XMPP sont écrits, vous pouvez consulter l'aide de Net::XMPP elle-même.

Pour une liste complète des fonctionnalités de haut niveau disponibles, voir Net::XMPP::Protocol.

Fonctionnalités de base

use Net::XMPP;
$Con = Net::XMPP::Client->new();
$Con->SetCallbacks(...);
$Con->Execute(hostname=>"jabber.org",
              username=>"bob",
              password=>"XXXX",
              resource=>"Work"
             );

Pour la liste des fonctionnalités disponibles, voir Net::XMPP::Protocol.

$Con->Disconnect();

MÉTHODES

Fonctionnalités de base

new

new(debuglevel=>0|1|2,
    debugfile=>string,
    debugtime=>0|1)

Crée l'objet Client. debugfile doit être défini sur le chemin du fichier journal de débogage. S'il est défini sur "stdout", le journal sera envoyé là-bas. debuglevel contrôle la quantité de débogage. Pour plus d'informations sur les valeurs valides pour debuglevel, debugfile et debugtime, voir Net::XMPP::Debug.

Connect

Connect(hostname=>string,
        port=>integer,
        timeout=>int,
        connectiontype=>string,
        tls=>0|1,
        srv=>0|1,
        componentname=>string)

Ouvre une connexion au serveur répertorié dans hostname (par défaut localhost), sur le port (par défaut 5222), en utilisant le type de connexion spécifié (par défaut tcpip). Les deux types de connexion disponibles sont :

tcpip  socket TCP standard
http   socket TCP, mais avec les en-têtes nécessaires pour communiquer via un proxy web

Si tls est spécifié, alors TLS sera utilisé si disponible comme fonctionnalité.

Si srv est spécifié et que Net::DNS est installé et peut être chargé, une requête SRV est envoyée à srv.hostname et les résultats sont traités pour remplacer le hostname et le port. Si la recherche échoue ou si Net::DNS ne peut pas être chargé, alors le hostname et le port restent tels quels.

Alternativement, vous pouvez spécifier manuellement componentname comme le composant du jid et laisser hostname défini sur le hostname réel du serveur XMPP.

Execute

Execute(hostname=>string,       
        port=>int,              
        tls=>0|1,               
        username=>string,       
        password=>string,       
        resource=>string,       
        register=>0|1,          
        connectiontype=>string, 
        connecttimeout=>string, 
        connectattempts=>int,   
        connectsleep=>int,      
        processtimeout=>int)

Boucle intérieure générale pour se connecter à un serveur, appeler Process et retenter la connexion si elle est perdue. Cinq callbacks sont disponibles et sont appelés à différents moments :

onconnect - lorsque le client a établi une connexion.
onauth - lorsque la connexion a été établie et que l'utilisateur a été authentifié. C'est à ce moment que vous pouvez commencer à faire des choses comme envoyer la présence, obtenir le roster, etc.
onprocess - la boucle la plus intérieure et est appelée le plus fréquemment. Vous devez être très prudent avec ce que vous passez ici, car cela peut affecter *DRASTIQUEMENT* les performances.
ondisconnect - lorsque le client se déconnecte du serveur.
onexit - lorsque la fonction abandonne la tentative de connexion et quitte.

Les arguments sont transmis directement à la méthode Connect, à l'exception de connectattempts et connectsleep. connectattempts est le nombre de fois où le Composant doit tenter la connexion avant d'abandonner. -1 signifie essayer indéfiniment. La valeur par défaut est -1. connectsleep est le nombre de secondes pendant lequel il faut dormir entre chaque tentative de connexion.

Si vous spécifiez register=>1, le client tentera de s'enregistrer pour vous, si l'utilisateur spécifié n'existe pas.

Process

Process(integer)

prend le temps d'attente comme argument. Si aucun temps d'attente n'est spécifié, la méthode se bloque jusqu'à ce qu'un paquet soit reçu. Sinon, elle attend ce nombre de secondes, puis se termine pour que votre programme puisse poursuivre des tâches utiles. REMARQUE : C'est important pour les interfaces graphiques. Vous devez laisser du temps pour traiter les commandes de l'interface graphique, même si vous attendez des paquets. Les valeurs de retour possibles et leur signification sont les suivantes :

  1   - État correct, données reçues.
  0   - État correct, aucune donnée reçue.
undef - État incorrect, arrêter le traitement.

IMPORTANT : Vous devez vérifier la sortie de chaque Process. Si vous obtenez undef, la connexion a été fermée et vous devez agir en conséquence.

Disconnect

Disconnect()

Ferme la connexion au serveur.

Connected

Connected()

renvoie 1 si la connexion au serveur est stable, et 0 si ce n'est pas le cas.
