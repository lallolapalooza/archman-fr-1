Nom

Net::Ping - vérifier l'accessibilité d'un hôte distant

Syntaxe

use Net::Ping;
my $p = Net::Ping->new();
print "$host est vivant.\n" if $p->ping($host);
$p->close();
my $p = Net::Ping->new("icmp");
$p->bind($my_addr); # Spécifier l'interface source des pings
foreach my $host (@host_array)
{
    print "$host est ";
    print "PAS " unless $p->ping($host, 2);
    print "accessible.\n";
    sleep(1);
}
$p->close();
my $p = Net::Ping->new("icmpv6");
my $ip = "[fd00:dead:beef::4e]";
print "$ip est vivant.\n" if $p->ping($ip);
my $p = Net::Ping->new("tcp", 2);
# Essayer de se connecter au port d'écho de www
$p->port_number(scalar(getservbyname("http", "tcp")));
while ($stop_time > time())
{
    print "$host n'est pas accessible ", scalar(localtime()), "\n"
        unless $p->ping($host);
    sleep(300);
}
undef($p);
# Compatible avec le protocole tcp
my $p = Net::Ping->new("syn");
$p->port_number(getservbyname("http", "tcp"));
foreach my $host (@host_array) {
  $p->ping($host);
}
while (my ($host, $rtt, $ip) = $p->ack) {
  print "HÔTE : $host [$ip] ACKed en $rtt secondes.\n";
}
# Syntaxe haute précision (nécessite Time::HiRes)
my $p = Net::Ping->new();
$p->hires();
my ($ret, $duration, $ip) = $p->ping($host, 5.5);
printf("$host [ip: $ip] est vivant (temps de réponse du paquet : %.2f ms)\n",
        1000 * $duration)
  if $ret;
$p->close();
# Pour la compatibilité avec les versions antérieures
print "$host est vivant.\n" if pingecho($host);

Description

Cette librairie contient des méthodes pour vérifier l'accessibilité d'hôtes distants sur un réseau. Un objet ping est d'abord créé avec des paramètres optionnels, plusieurs hôtes peuvent être pingés successivement, puis la connexion est fermée.

Vous pouvez choisir parmi six protocoles différents à utiliser pour le ping. Le protocole tcp est celui par défaut. Il faut noter qu'un hôte distant vivant peut néanmoins ne pas être accessible via certains de ces protocoles. Par exemple, www.microsoft.com est généralement vivant mais n'est pas accessible via le protocole icmp.

Avec le protocole tcp, la méthode ping essaie d'établir une connexion avec le port d'écho de l'hôte distant. Si la connexion est établie avec succès, l'hôte distant est considéré comme accessible. Aucune donnée n'est réellement envoyée. Ce protocole ne nécessite pas de privilèges spéciaux mais a une surcharge plus élevée que les protocoles udp et icmp.

Si le protocole udp est spécifié, la méthode ping envoie un paquet udp au port d'écho de l'hôte distant. Si un paquet d'écho est reçu de l'hôte distant et que le paquet reçu contient les mêmes données que le paquet envoyé, l'hôte distant est considéré comme accessible. Ce protocole ne nécessite pas de privilèges spéciaux. Il faut noter que, pour un ping udp, un hôte est signalé comme non accessible s'il n'exécute pas le service d'écho correspondant. Pour les systèmes Unix-like, voir inetd(8) pour plus d'informations.

Si le protocole icmp est spécifié, la méthode ping envoie un message icmp echo à l'hôte distant, ce qui est ce que fait le programme unix ping. Si le message echo est reçu de l'hôte distant et que les informations du message echo sont correctes, l'hôte distant est considéré comme accessible. Il est nécessaire que le programme soit exécuté en tant que root ou que le programme soit configuré avec le bit setuid root.

Si le protocole external est spécifié, la méthode ping essaie d'utiliser le module "Net::Ping::External" pour pinger l'hôte distant. Le module "Net::Ping::External" communique avec l'utilitaire ping par défaut de votre système et produit des résultats relativement précis. Si "Net::Ping::External" n'est pas installé sur votre système, spécifier le protocole external entraînera une erreur.

Si le protocole syn est spécifié, la méthode ping enverra uniquement un paquet TCP SYN à l'hôte distant, puis retournera immédiatement. Si le paquet SYN est envoyé avec succès, il retournera une valeur vraie, sinon il retournera faux. REMARQUE : La valeur de retour ne détermine pas si l'hôte distant est vivant ou non, car il n'a pas encore terminé le handshake en trois étapes. L'hôte distant n'est considéré comme accessible que si un paquet ACK TCP est reçu dans le délai imparti. Pour commencer à attendre les paquets ACK, utilisez la méthode ack comme expliqué. Utilisez le protocole syn plutôt que le protocole tcp pour déterminer l'accessibilité de plusieurs destinations simultanément en envoyant des paquets TCP SYN en parallèle. Il ne bloque pas lors du test de chaque hôte distant. Ce protocole ne nécessite pas de privilèges spéciaux.

Fonctions

Net::Ping->new([proto, timeout, bytes, device, tos, ttl, family, host, port, bind, gateway, retrans, pingstring, source_verify econnrefused dontfrag IPV6_USE_MIN_MTU IPV6_RECVPATHMTU])
Crée un nouvel objet ping. Tous les paramètres sont optionnels et peuvent être passés sous forme de référence de hachage. Toutes les options sauf les 7 premières doivent être passées sous forme de référence de hachage.

Le paramètre "proto" spécifie le protocole à utiliser lors du ping. Les options actuelles sont "tcp", "udp", "icmp", "icmpv6", "stream", "syn", ou "external". La valeur par défaut est "tcp".

Si un "timeout" est fourni en secondes, il est utilisé lorsqu'aucun délai d'attente n'est spécifié dans la méthode ping() (ci-dessous). Le délai d'attente doit être supérieur à 0 et la valeur par défaut, si non spécifiée, est de 5 secondes.

Si le nombre d'octets ("bytes") est spécifié, autant d'octets de données que spécifié sont inclus dans le paquet ping envoyé à l'hôte distant. Si le protocole est "tcp", le nombre d'octets est ignoré. Le nombre minimum (et par défaut) d'octets de données est de 1 si le protocole est "udp" et 0 sinon. Le nombre maximum d'octets pouvant être spécifié est de 65535, mais il est recommandé de le maintenir inférieur à l'MTU (1472 octets pour ICMP). De nombreux petits appareils ne peuvent pas gérer les paquets ICMP fragmentés.

Si le "device" est spécifié, ce périphérique est utilisé pour lier le point de terminaison source avant d'envoyer le paquet ping. Je pense que cela ne fonctionne qu'avec des privilèges de superutilisateur et avec les protocoles udp et icmp à l'heure actuelle.

Si "tos" est spécifié, le ToS est configuré sur le socket.

Pour icmp, "ttl" peut être spécifié pour définir le TTL du paquet sortant.

Valeurs valides pour "family" en IPv4 :

4, v4, ip4, ipv4, AF_INET (constante)

Valeurs valides pour "family" en IPv6 :

6, v6, ip6, ipv6, AF_INET6 (constante)

Le paramètre "host" spécifie implicitement la famille si le paramètre family n'est pas spécifié.

Le paramètre "port" n'est valide que pour un ping udp, tcp ou stream et ne fera pas ce à quoi vous vous attendez. Le ping retourne vrai lorsqu'un message "Connection refused" est reçu ! La valeur par défaut est le port d'écho.

Le paramètre "bind" spécifie l'adresse locale à lier. En spécifiant un argument bind, la méthode bind n'est plus nécessaire.

Le paramètre "gateway" n'est valide que pour IPv6 et nécessite une adresse IPv6.

Le paramètre "retrans" spécifie le taux de retrait exponentiel, par défaut 1.2. Il correspond à la valeur globale $def_factor.

Le paramètre "dontfrag" définit le bit IP_DONTFRAG, mais veuillez noter que IP_DONTFRAG n'est pas encore défini par Socket et n'est pas disponible sur de nombreux systèmes. Il sera donc ignoré. Sous Linux, il définit également IP_MTU_DISCOVER sur IP_PMTUDISC_DO, mais les paquets de taille excessive ne doivent pas être fragmentés. Vous devez configurer $data_size manuellement.

$p->ping($host [, $timeout [, $family]]);
Ping l'hôte distant et attend une réponse. $host peut être le nom d'hôte ou le numéro IP.
Mantén toda la estructura del archivo. El tiempo de espera opcional debe ser mayor que 0 segundos y se comporta como el especificado cuando se creó el objeto ping. Devuelve un flag de éxito. Si el hostname no puede ser encontrado o hay un problema con el número de IP, el flag devuelto será undef. De lo contrario, el flag será 1 si el host es alcanzable y 0 si no lo es. Para propósitos prácticos, undef y 0 se pueden tratar como iguales. En contexto de array, el tiempo transcurrido y la forma string del IP del host resuelto también se devuelven. El valor del tiempo transcurrido será un float, como devuelto por la función Time::HiRes::time(), si hires() ha sido llamada previamente, de lo contrario se devuelve como entero.
El método source_verify( { 0 | 1 } ) permite habilitar o deshabilitar la verificación del endpoint fuente. Es útil para destinos remotos con múltiples interfaces donde la respuesta podría no provenir del mismo endpoint que el destino original. Esto solo afecta los pings de tipo UDP y ICMP.

Este está habilitado por defecto.

El método service_check( { 0 | 1 } ) establece si el comportamiento de conexión debe garantizar la disponibilidad y la alcanzabilidad del servicio remoto. Normalmente, si el servidor remoto reportó ECONNREFUSED, debe haber sido alcanzable por el paquete de estado. Con esta opción habilitada, la tres etapa TCP completa debe haberse establecido correctamente antes de declarar que el host es alcanzable. NOTA: No realiza más que conectar y desconectar. No habla ningún protocolo (es decir, HTTP o FTP) para garantizar que el servidor remoto sea "sane" en cualquier manera. El procesador del servidor puede estar enfriándose y no respondiendo a clientes conectados, pero si el kernel envía el paquete ACK, se considera vivo. Para determinar si el servidor responde bien realmente, sería específica de la aplicación y está fuera del alcance de Net::Ping. Para el protocolo UDP, habilitar esta opción requiere que el servidor remoto devuelva el mismo dato UDP que se le envió, como se definió por el servicio UDP echo.

Afecta los protocolos "udp", "tcp" y "syn".

Está deshabilitado por defecto.

El método tcp_service_check( { 0 | 1 } ) es un método obsoleto pero realiza lo mismo que el método service_check().
El método hires( { 0 | 1 } ) con 1 causa este módulo a usar el módulo Time::HiRes, permitiendo devolver milisegundos en las llamadas a ping().
El método time devuelve el tiempo actual, incluyendo el valor de hires o no.
El método socket_blocking_mode( $fh, $mode ) establece o elimina el flag O_NONBLOCK en un handle de archivo.
El método IPV6_USE_MIN_MTU con argumentos establece la opción. Sin argumentos devuelve el valor de la opción.
El método IPV6_RECVPATHMTU notifica el valor de MTU correspondiente para IPv6.

Con argumentos establece la opción. Sin argumentos devuelve el valor de la opción.

El método IPV6_HOPLIMIT con argumentos establece la opción. Sin argumentos devuelve el valor de la opción.
El método IPV6_REACHCONF NYI establece la alcanzabilidad IPv6. NYI significa que no está implementado.

Con argumentos establece la opción. Sin argumentos devuelve el valor de la opción.

No está implementado aún.

El método bind($local_addr) establece la dirección de fuente desde la cual se envían los pings. Debe ser la dirección de uno de los interfaces locales.

$local_addr puede especificarse como un nombre de host o como una dirección IP texto (como "192.168.1.1").

Si el protocolo es "tcp", este método puede llamarse cualquier número de veces, y cada llamada a la metodología ping() (más abajo) utilizará el valor más reciente de $local_addr. Si el protocolo es "icmp" o "udp", debe llamarse al método bind() al máximo una vez por objeto, y (si se llama al menos una vez) debe llamarse antes de la primera llamada a ping() para ese objeto.

La llamada bind() puede omitirse cuando se especifique el opción "bind" del método new().

El método message_type([$ping_type]) permite cambiar el tipo de mensaje a "echo" o "timestamp" (solo para IPv4, ver RFC 792).

Sin argumento, devuelve el tipo de protocolo icmp actualmente usado. Por defecto, devuelve "echo".

El método open($host) cuando se utiliza el protocolo "stream" preabre el socket TCP. Es necesario solo si se quiere proporcionar un timeout diferente al crear la conexión, o eliminar el overhead de establecer la conexión desde el primer ping. Si no se llama a open(), la conexión se abre automáticamente al primer llamado a ping(). Esta llamada simplemente hace nada si se está utilizando cualquier protocolo otros que "stream".

El argumento $host puede omitirse cuando se especifique el opción "host" del método new().

El método ack( [ $host ] ) cuando se utiliza el protocolo "syn" permite determinar la alcanzabilidad del host remoto. Este método está diseñado para llamarse tantas veces como veces se haya llamado a ping(). Cada llamada devuelve el host (como pasado a ping()) que respondió con el ACK TCP. El orden en el que se devuelven los hosts puede no ser el mismo que el orden en el que fueron SYN-queued por el método ping(). Si el tiempo de espera se alcanza antes de recibir el ACK TCP, o si el host no está escuchando en el puerto solicitado, la conexión TCP no se establecerá y ack() devolverá undef. En contexto de lista, se devolverán el host, el tiempo de ACK, la cadena IP en punto decimal y el número de puerto. Si se especifica el argumento opcional $host, el valor devuelto será relativo a ese host. Esta llamada simplemente hace nada si se está utilizando cualquier protocolo otros que "syn".

Cuando el método new tuvo un opción de host, este host se usará. Sin argumento $host, se escaneará todo el host.

El método nack( $failed_ack_host ) indica la razón por la cual "host $failed_ack_host" no recibió un ACK válido. Es útil para encontrar por qué devuelve un valor falso al llamado ack($fail_ack_host).
El método ack_unfork($host) es la variante llamada por ack() con el protocolo "syn" y el parámetro $syn_forking habilitado.
El método ping_icmp([$host, $timeout, $family]) es el método ping utilizado con el protocolo icmp.
El método ping_icmpv6([$host, $timeout, $family]) es el método ping utilizado con el protocolo icmpv6.
El método ping_stream([$host, $timeout, $family]) es el método ping utilizado con el protocolo stream.

Realiza un ping stream. Si la conexión TCP no está abierta, la abre. Luego envía datos y espera una respuesta. Deja la conexión stream abierta al salir.

El método ping_syn([$host, $ip, $start_time, $stop_time]) es el método ping utilizado con el protocolo syn. Envía un paquete TCP SYN al host especificado.
El método ping_syn_fork([$host, $timeout, $family]) es el método ping utilizado con el protocolo forked syn.
El método ping_tcp([$host, $timeout, $family]) es el método ping utilizado con el protocolo tcp.
El método ping_udp([$host, $timeout, $family]) es el método ping utilizado con el protocolo udp.

Realiza un ping de echo UDP. Construye un mensaje de al menos el número de secuencia de un byte y cualquier dato adicional. Envía el mensaje y espera una respuesta. Si recibes un mensaje, asegúrate de que todos sus componentes coincidan. Si coinciden, terminas. De lo contrario, espera hasta que se acabe el tiempo y devuelve el resultado de tus esfuerzos.

El método ping_external([$host, $timeout, $family]) es el método ping utilizado con el protocolo externo. Usa Net::Ping::External para realizar un ping externo.
El método tcp_connect([$ip, $timeout]) inicia una conexión TCP, para un ping tcp.
El método tcp_echo([$ip, $timeout, $pingstring]) realiza un echo TCP. Escribe la cadena dada en el socket y luego la lee de vuelta. Devuelve 1 en caso de éxito, 0 en caso de fallo.
El método close() cierra la conexión de red para este objeto ping. La conexión de red también se cierra cuando se define undef $p. La conexión de red se cierra automáticamente si el objeto ping se sale de alcance (por ejemplo, $p es local a una función y se sale de la función).
El método port_number([$port_number]) cuando se llama con un número de puerto, establece el número de puerto usado para ping a $port_number en lugar del puerto de echo. También tiene el efecto de llamar a $p->service_check(1) y hacer que una respuesta de ping sea exitosa solo si ese puerto es accesible. Esta función devuelve el valor del puerto que ping conectará a.
El método mselect es un wrapper de select() que compensa las peculiaridades de plataforma.
El método ntop es una abstracción de plataforma sobre inet_ntop().
El método checksum($msg) realiza un checksum en el mensaje. básicamente suma todos los palabras cortas y doblete los bits de alto en los de bajo.
El método icmp_result devuelve una lista de addr, type, subcode.
El método pingecho($host[, $timeout]); para proporcionar compatibilidad retroactiva con la versión anterior de Net::Ping, se dispone de una subrutina pingecho() utiliza el protocolo tcp. Los valores devueltos y parámetros son los mismos que se describen para el método ping. Esta subrutina es obsoleta y podría ser eliminada en una versión futura de Net::Ping.
El método wakeonlan($mac, [$host, [$port]]) emite el paquete UDP popular de wake-on-lan para despertar un dispositivo local. Vea también Net::Wake, pero este tiene el mac como primer argumento. $host debe ser el gateway local. Sin él se broadcastará.

El host por defecto es '255.255.255.255' y el puerto por defecto es 9. 

perl -MNet::Ping=wakeonlan -e'wakeonlan "e0:69:95:35:68:d2"'
