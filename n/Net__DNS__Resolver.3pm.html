Net::DNS::Resolver(3) Documentation fournie par Perl Net::DNS::Resolver(3)

NOM

Net::DNS::Resolver - Classe de résolveur DNS

SYNTAXE

use Net::DNS;
$resolver = Net::DNS::Resolver->new();
# Faire une recherche, en utilisant la liste de recherche si approprié.
$reply = $resolver->search( 'example.com' );
# Faire une recherche, sans la liste de recherche
$reply = $resolver->query( 'example.com', 'MX' );
# Faire une recherche, sans pré ou post-traitement
$reply = $resolver->send( 'example.com', 'MX', 'IN' );
# Envoyer un paquet de requête préfabriqué
$query = Net::DNS::Packet->new( ... );
$reply = $resolver->send( $query );

DESCRIPTION

Les instances de la classe Net::DNS::Resolver représentent des objets résolveurs. Un programme peut avoir plusieurs objets résolveurs, chacun conservant son propre état tel que les serveurs de noms à interroger, si la récursion est souhaitée, etc.

MÉTHODES

new

# Utiliser la configuration par défaut
$resolver = Net::DNS::Resolver->new();
# Utiliser ma propre configuration de fichier
$resolver = Net::DNS::Resolver->new( config_file => '/my/dns.conf' );
# Définir les options dans le constructeur
$resolver = Net::DNS::Resolver->new(
                nameservers => [ '2001:DB8::1', 'ns.example.com' ],
                recurse     => 0,
                debug       => 1
                );

Renvoie un objet résolveur. Si aucun argument n'est spécifié, new() renvoie un objet avec la configuration par défaut.

Sur les systèmes Unix et Linux, les valeurs par défaut sont lues dans les fichiers suivants, dans l'ordre indiqué :

/etc/resolv.conf, $HOME/.resolv.conf, ./.resolv.conf

Les termes suivants sont reconnus dans les fichiers de configuration du résolveur :

nameserver
L'adresse IP d'un serveur de noms que le résolveur doit interroger.
domain
Le suffixe de domaine à joindre à un nom court et non absolu.
search
Une liste de domaines séparés par des espaces dans le chemin de recherche souhaité.
options
Une liste de paires clé-valeur séparées par des espaces.

À l'exception de /etc/resolv.conf, les fichiers ne sont lus que s'ils appartiennent à l'utilisateur effectif exécutant le programme. De plus, plusieurs variables d'environnement peuvent contenir des informations de configuration ; voir ENVIRONMENT.

Remarque : les termes domain et search s'excluent mutuellement. S'ils sont tous deux présents, le comportement résultant est indéterminé. S'ils sont absents, le domaine est déterminé à partir du nom d'hôte local.

Sur les systèmes Windows, il est tenté de déterminer les valeurs par défaut en utilisant le registre. Les systèmes avec plusieurs interfaces réseau configurées dynamiquement peuvent dérouter Net::DNS.

Si un fichier de configuration personnalisé est spécifié lors du premier démarrage, tous les autres fichiers de configuration et variables d'environnement sont ignorés.

Les arguments explicites à new() remplacent les variables de configuration correspondantes. L'argument de liste consiste en une séquence de paires (nom=>valeur), chacune interprétée comme un appel à la méthode correspondante.

print

$resolver->print;

Imprime l'état du résolveur sur la sortie standard.

query

$packet = $resolver->query( 'host' );
$packet = $resolver->query( 'host.example.com' );
$packet = $resolver->query( '2001:DB8::1' );
$packet = $resolver->query( 'example.com', 'MX' );
$packet = $resolver->query( 'annotation.example.com', 'TXT', 'IN' );

Effectue une requête DNS pour le nom donné ; la liste de recherche n'est pas appliquée. Si "defnames" est vrai, le suffixe de domaine par défaut est ajouté aux noms non spécifiés.

Le type d'enregistrement et la classe peuvent être omis ; par défaut, ce sont A et IN. Si le nom semble être une adresse IP (IPv4 ou IPv6), une requête sera effectuée dans in-addr.arpa ou ip6.arpa.

Renvoie un objet Net::DNS::Packet, ou "undef" si aucune réponse n'est trouvée. La raison de l'échec peut être déterminée avec errorstring().

Si vous avez besoin d'examiner le paquet de réponse, qu'il contienne ou non des réponses, utilisez plutôt la méthode send().

search

$packet = $resolver->search( 'host' );
$packet = $resolver->search( 'host.example.com' );
$packet = $resolver->search( '2001:DB8::1' );
$packet = $resolver->search( 'example.com', 'MX' );
$packet = $resolver->search( 'annotation.example.com', 'TXT', 'IN' );

Effectue une requête DNS pour le nom donné, en appliquant la liste de recherche si approprié. L'algorithme de recherche est le suivant :

Si le nom contient un ou plusieurs points non terminaux, une requête initiale est effectuée en utilisant le nom tel quel.

Si le nombre de points est inférieur à "ndots" et qu'il n'y a pas de point terminal, il est tenté d'ajouter chaque suffixe de la liste de recherche.

Le type d'enregistrement et la classe peuvent être omis ; par défaut, ce sont A et IN. Si le nom semble être une adresse IP (IPv4 ou IPv6), une requête sera effectuée dans in-addr.arpa ou ip6.arpa.

Renvoie un objet Net::DNS::Packet, ou "undef" si aucune réponse n'est trouvée. La raison de l'échec peut être déterminée avec errorstring().

Si vous avez besoin d'examiner le paquet de réponse, qu'il contienne ou non des réponses, utilisez plutôt la méthode send().

send

$packet = $resolver->send( $query );
$packet = $resolver->send( 'host.example.com' );
$packet = $resolver->send( '2001:DB8::1' );
$packet = $resolver->send( 'example.com', 'MX' );
$packet = $resolver->send( 'annotation.example.com', 'TXT', 'IN' );

Effectue une requête DNS pour le nom donné. Ni la liste de recherche ni le domaine par défaut ne sont ajoutés.

L'argument peut être un paquet de requête préfabriqué Net::DNS::Packet ou une liste de chaînes. Le type d'enregistrement et la classe peuvent être omis ; par défaut, ce sont A et IN. Si le nom semble être une adresse IP (IPv4 ou IPv6), une requête sera effectuée dans in-addr.arpa ou ip6.arpa.

Renvoie un objet Net::DNS::Packet si des réponses ont été trouvées, ou "undef" si aucune réponse n'a été reçue. La raison de l'échec peut être déterminée avec "$packet->header->ancount" ou "$packet->answer" pour voir s'il y a des enregistrements dans la section de réponse. Renvoie "undef" si aucune réponse n'a été reçue.

axfr

@zone = $resolver->axfr();
@zone = $resolver->axfr( 'example.com' );
@zone = $resolver->axfr( 'example.com', 'IN' );
$iterator = $resolver->axfr();
$iterator = $resolver->axfr( 'example.com' );
$iterator = $resolver->axfr( 'example.com', 'IN' );
$rr = $iterator->();

Effectue un transfert de zone en utilisant les serveurs de noms de ce résolveur, tentés dans l'ordre de la liste.

Si la zone n'est pas spécifiée, la valeur par défaut est la première zone dans la liste de recherche du résolveur.

Si la classe n'est pas spécifiée, la valeur par défaut est IN.

Lorsqu'elle est appelée dans un contexte de liste, axfr() renvoie une liste d'objets Net::DNS::RR. L'enregistrement SOA qui termine le transfert de zone n'est pas renvoyé à l'appelant.

Conformément à la RFC1035(6.3), on s'attend à ce que le transfert complet renvoie tous les enregistrements de la zone ou rien du tout. Si aucun enregistrement n'est renvoyé par axfr(), la raison de l'échec peut être déterminée avec errorstring().

Voici un exemple utilisant un délai d'attente et une vérification TSIG :

$resolver->tcp_timeout( 10 );
$resolver->tsig( $keyfile );
@zone = $resolver->axfr( 'example.com' );
foreach $rr (@zone) {
        $rr->print;
}

Lorsqu'elle est appelée dans un contexte scalaire, axfr() renvoie un objet itérateur. Chaque appel à l'itérateur renvoie un unique Net::DNS::RR ou "undef" lorsque la zone est épuisée.

Une exception est levée si le transfert de zone ne peut pas être complété.

L'enregistrement SOA qui termine le transfert de zone n'est pas renvoyé à l'appelant.

Ce site n'est en aucun cas associé à Arch Linux ni affilié à ce projet. Le contenu est uniquement une traduction des pages de manuel d'Arch publiées sur man.archlinux.org.

zone transfer n'est pas retournée à l'appelant.

Voici l'exemple ci-dessus, implémenté à l'aide d'un itérateur :

$resolver->tcp_timeout( 10 );
$resolver->tsig( $keyfile );
$iterator = $resolver->axfr( 'example.com' );
while ( $rr = $iterator->() ) {
        $rr->print;
}

bgsend

$handle = $resolver->bgsend( $packet ) || die $resolver->errorstring;
$handle = $resolver->bgsend( 'host.example.com' );
$handle = $resolver->bgsend( '2001:DB8::1' );
$handle = $resolver->bgsend( 'example.com', 'MX' );
$handle = $resolver->bgsend( 'annotation.example.com', 'TXT', 'IN' );

Effectue une requête DNS en arrière-plan pour le nom donné et retourne immédiatement sans attendre la réponse. Le programme peut ensuite effectuer d'autres tâches en attendant la réponse du serveur de noms.

La liste des arguments peut être soit un objet Net::DNS::Packet, soit une liste de chaînes de caractères. Le type d'enregistrement et la classe peuvent être omis ; ils valent par défaut A et IN. Si le nom ressemble à une adresse IP (IPv4 ou IPv6), alors une requête dans in-addr.arpa ou ip6.arpa sera effectuée.

Retourne une poignée opaque qui est passée aux invocations ultérieures des méthodes bgbusy() et bgread(). Les erreurs sont indiquées par le retour de "undef", auquel cas la raison de l'échec peut être déterminée à l'aide de errorstring().

L'objet Net::DNS::Packet de réponse est obtenu en appelant bgread().

ATTENTION : Les programmes ne doivent faire aucune supposition quant à la nature des poignées retournées par bgsend(), qui doivent être utilisées strictement comme décrit ici.

bgread

$handle = $resolver->bgsend( 'www.example.com' );
$packet = $resolver->bgread($handle);

Lit la réponse suite à une requête en arrière-plan. L'argument est la poignée retournée par bgsend().

Retourne un objet Net::DNS::Packet ou "undef" si aucune réponse n'a été reçue avant que l'intervalle de temps imparti n'ait expiré.

bgbusy

$handle = $resolver->bgsend( 'foo.example.com' );
while ($resolver->bgbusy($handle)) {
        ...
}
$packet = $resolver->bgread($handle);

Retourne vrai tant que la réponse est attendue ou que la transaction expire. L'argument est la poignée retournée par bgsend().

Les paquets UDP tronqués seront retentés de manière transparente en utilisant TCP tout en continuant d'indiquer occupé à l'appelant.

debug

print 'debug flag: ', $resolver->debug, "\n";
$resolver->debug(1);

Obtient ou définit le drapeau de débogage. S'il est activé, les appels à search(), query() et send() afficheront des informations de débogage sur la sortie standard. La valeur par défaut est false.

defnames

print 'defnames flag: ', $resolver->defnames, "\n";
$resolver->defnames(0);

Obtient ou définit le drapeau defnames. S'il est vrai, les appels à query() ajouteront le domaine par défaut pour résoudre les noms qui ne sont pas complètement qualifiés. La valeur par défaut est true.

dnsrch

print 'dnsrch flag: ', $resolver->dnsrch, "\n";
$resolver->dnsrch(0);

Obtient ou définit le drapeau dnsrch. S'il est vrai, les appels à search() appliqueront la liste de recherche pour résoudre les noms qui ne sont pas complètement qualifiés. La valeur par défaut est true.

domain

$domain = $resolver->domain;
$resolver->domain( 'domain.example' );

Obtient ou définit le domaine par défaut du résolveur.

igntc

print 'igntc flag: ', $resolver->igntc, "\n";
$resolver->igntc(1);

Obtient ou définit le drapeau igntc. S'il est vrai, les paquets tronqués seront ignorés. S'il est faux, la requête sera retentée en utilisant TCP. La valeur par défaut est false.

nameserver, nameservers

@nameservers = $resolver->nameservers();
$resolver->nameservers( '2001:DB8::1', '192.0.2.1' );
$resolver->nameservers( 'ns.domain.example.' );

Obtient ou définit les serveurs de noms à interroger.

Voir également les notes sur le transport IPv6 ci-dessous

persistent_tcp

print 'Persistent TCP flag: ', $resolver->persistent_tcp, "\n";
$resolver->persistent_tcp(1);

Obtient ou définit le paramètre TCP persistant. S'il est vrai, Net::DNS gardera un socket TCP ouvert pour chaque hôte:port auquel il se connecte. Ceci est utile si vous utilisez TCP et avez besoin de faire de nombreuses requêtes ou mises à jour au même serveur de noms.

La valeur par défaut est false, sauf si vous utilisez un Perl SOCKSifié, auquel cas la valeur par défaut est true.

persistent_udp

print 'Persistent UDP flag: ', $resolver->persistent_udp, "\n";
$resolver->persistent_udp(1);

Obtient ou définit le paramètre UDP persistant. S'il est vrai, un résolveur Net::DNS utilisera le même socket UDP pour toutes les requêtes au sein de chaque famille d'adresses.

Cela évite le coût de création et de suppression des sockets UDP, mais rend également aléatoire le port source.

port

print 'sending queries to port ', $resolver->port, "\n";
$resolver->port(9732);

Obtient ou définit le port auquel les requêtes sont envoyées. Pratique pour tester les serveurs de noms en utilisant un port non standard. Le port par défaut est 53.

recurse

print 'recursion flag: ', $resolver->recurse, "\n";
$resolver->recurse(0);

Obtient ou définit le drapeau de récursion. S'il est vrai, cela demandera aux serveurs de noms d'effectuer une requête récursive. La valeur par défaut est true.

retrans

print 'retrans interval: ', $resolver->retrans, "\n";
$resolver->retrans(3);

Obtient ou définit l'intervalle de retransmission. La valeur par défaut est de 5 secondes.

retry

print 'number of tries: ', $resolver->retry, "\n";
$resolver->retry(2);

Obtient ou définit le nombre de tentatives de requête. La valeur par défaut est 4.

searchlist

@searchlist = $resolver->searchlist;
$resolver->searchlist( 'a.example', 'b.example', 'c.example' );

Obtient ou définit la liste de recherche du résolveur.

srcaddr

$resolver->srcaddr('2001::DB8::1');

Définit l'adresse source à partir de laquelle les requêtes sont envoyées. Pratique pour forcer les requêtes à partir d'une interface spécifique sur un hôte multi-homed. La valeur par défaut est d'utiliser n'importe quelle adresse locale.

srcport

$resolver->srcport(5353);

Définit le port à partir duquel les requêtes sont envoyées. La valeur par défaut est 0, ce qui signifie n'importe quel port.

tcp_timeout

print 'TCP timeout: ', $resolver->tcp_timeout, "\n";
$resolver->tcp_timeout(10);

Obtient ou définit le délai d'attente TCP en secondes. La valeur par défaut est de 120 secondes (2 minutes).

udp_timeout

print 'UDP timeout: ', $resolver->udp_timeout, "\n";
$resolver->udp_timeout(10);

Obtient ou définit le délai d'attente UDP pour bgsend() en secondes. La valeur par défaut est de 30 secondes.

udppacketsize

print "udppacketsize: ", $resolver->udppacketsize, "\n";
$resolver->udppacketsize(2048);

Obtient ou définit la taille du paquet UDP. Si elle est définie à une valeur non inférieure à la taille par défaut du paquet DNS, une extension EDNS sera ajoutée indiquant la prise en charge de grands datagrammes UDP.

usevc

print 'usevc flag: ', $resolver->usevc, "\n";
$resolver->usevc(1);

Obtient ou définit le drapeau usevc. S'il est vrai, les requêtes seront effectuées en utilisant des circuits virtuels (TCP) au lieu de datagrammes (UDP). La valeur par défaut est false.

replyfrom

print 'last response was from: ', $resolver->replyfrom, "\n";

Retourne l'adresse IP à partir de laquelle le paquet le plus récent a été reçu en réponse à une requête.

errorstring

print 'query status: ', $resolver->errorstring, "\n";

Retourne une chaîne contenant des informations d'erreur de la plus récente interaction du protocole DNS. errorstring() n'a de sens que lorsqu'il est interrogé immédiatement après l'appel de la méthode correspondante.

dnssec

print "dnssec flag: ", $resolver->dnssec, "\n";
$resolver->dnssec(0);

Le drapeau dnssec amène le résolveur à transmettre des requêtes DNSSEC et à ajouter un enregistrement EDNS0 comme requis par les RFC2671 et RFC3225. Les actions, et la réponse, du serveur de noms distant sont déterminées par les paramètres des drapeaux AD et CD.

L'appel de la méthode dnssec() avec une valeur non nulle définira également la taille du paquet UDP à la valeur par défaut de 2048. Si cela est trop petit ou trop grand pour votre environnement, vous devriez appeler la méthode udppacketsize() immédiatement après.

$resolver->dnssec(1);
$resolver->udppacketsize(1250); # ajuster la taille du paquet UDP

Une exception fatale sera levée si le

dnssec() la méthode est appelée mais la bibliothèque Net::DNS::SEC n'a pas été installée.

adflag

$resolver->dnssec(1);
$resolver->adflag(1);
print "drapeau d'authentification souhaitée : ", $resolver->adflag, "\n";

Obtient ou définit le bit AD pour les requêtes dnssec. Ce bit indique que l'appelant est intéressé par le bit AD (données authentifiées) retourné mais ne nécessite pas que des RR dnssec soient inclus dans la réponse. La valeur par défaut est false.

cdflag

$resolver->dnssec(1);
$resolver->cdflag(1);
print "drapeau de vérification désactivé : ", $resolver->cdflag, "\n";

Obtient ou définit le bit CD pour les requêtes dnssec. Ce bit indique que l'authentification par les serveurs de noms en amont doit être supprimée. Tous les RR dnssec requis pour exécuter la procédure d'authentification doivent être inclus dans la réponse. La valeur par défaut est false.

tsig

$resolver->tsig( $keyfile );
$resolver->tsig( $keyfile, fudge => 60 );
$resolver->tsig( undef );

Définit l'enregistrement TSIG utilisé pour signer automatiquement les requêtes sortantes, les transferts de zone et les mises à jour. La signature automatique est désactivée si appelée avec des arguments indéfinis.

Le comportement par défaut du résolveur est de ne signer aucun paquet. Vous devez appeler cette méthode pour définir la clé si vous souhaitez que le résolveur signe et vérifie automatiquement les paquets.

Les paquets peuvent également être signés manuellement ; voir les pages de manuel Net::DNS::Packet et Net::DNS::Update pour des exemples. Les enregistrements TSIG dans les paquets signés manuellement ont priorité sur ceux que le résolveur ajouterait automatiquement.

ENVIRONNEMENT

Les variables d'environnement suivantes peuvent également être utilisées pour configurer le résolveur :

RES_NAMESERVERS

# Shell Bourne
RES_NAMESERVERS="2001:DB8::1 192.0.2.1"
export RES_NAMESERVERS
# Shell C
setenv RES_NAMESERVERS "2001:DB8::1 192.0.2.1"

Une liste de serveurs de noms séparés par des espaces à interroger.

RES_SEARCHLIST

# Shell Bourne
RES_SEARCHLIST="a.example.com b.example.com c.example.com"
export RES_SEARCHLIST
# Shell C
setenv RES_SEARCHLIST "a.example.com b.example.com c.example.com"

Une liste de domaines séparés par des espaces à inclure dans la liste de recherche.

LOCALDOMAIN

# Shell Bourne
LOCALDOMAIN=example.com
export LOCALDOMAIN
# Shell C
setenv LOCALDOMAIN example.com

Le domaine par défaut.

RES_OPTIONS

# Shell Bourne
RES_OPTIONS="retrans:3 retry:2 inet6"
export RES_OPTIONS
# Shell C
setenv RES_OPTIONS "retrans:3 retry:2 inet6"

Une liste d'options de résolveur séparées par des espaces à définir. Les options qui prennent des valeurs sont spécifiées comme "option:valeur".

TRANSPORT IPv4

Les méthodes force_v4(), force_v6(), prefer_v4(), et prefer_v6() avec un argument non nul peuvent être utilisées pour configurer la sélection du transport.

Le comportement de la méthode nameserver() illustre le mécanisme de sélection du transport. Si, par exemple, le transport IPv4 a été forcé, la méthode nameserver() ne retournera que des adresses IPv4 :

$resolver->nameservers( '192.0.2.1', '192.0.2.2', '2001:DB8::3' );
$resolver->force_v4(1);
print join ' ', $resolver->nameservers();

affichera

192.0.2.1 192.0.2.2

RESOLVEURS PERSONNALISÉS

Net::DNS::Resolver est en fait une sous-classe vide. Au moment de la compilation, une super-classe est choisie en fonction de la plateforme actuelle. Un avantage secondaire de cela permet une modification facile des méthodes de Net::DNS::Resolver. Vous pouvez simplement ajouter une méthode à l'espace de noms !

Par exemple, si nous voulions mettre en cache les recherches :

package Net::DNS::Resolver;
my %cache;
sub send {
        my ( $self, @q ) = @_;
        return $cache{"@q"} ||= $self->SUPER::send(@q);
}
