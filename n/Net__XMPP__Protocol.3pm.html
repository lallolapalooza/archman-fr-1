NOM

Net::XMPP::Protocol - Module de protocole XMPP

SYNOPIS

Net::XMPP::Protocol est un module qui permet aux développeurs d'avoir un accès facile au protocole de messagerie instantanée XMPP. Il offre des fonctions de haut niveau aux objets Client Net::XMPP. Ces fonctions sont héritées par ce module.

DESCRIPTION

Protocol.pm cherche à fournir suffisamment d'API de haut niveau et d'automatisation des API de bas niveau pour que l'écriture d'un client XMPP en Perl soit simple. Pour ceux qui souhaitent travailler au niveau bas, ils le peuvent aussi, mais les fonctions sont couvertes dans la documentation de chaque module.

Net::XMPP::Protocol fournit des fonctions pour se connecter, envoyer et recevoir des messages, définir des informations personnelles, créer un nouvel utilisateur, gérer la liste de contacts et se déconnecter. Vous pouvez utiliser toutes ces fonctions ou aucune, il n'y a pas d'exigences.

Pour plus d'informations sur la façon dont les détails de Net::XMPP sont écrits, consultez l'aide de Net::XMPP.

Pour plus d'informations sur la façon d'écrire un client, consultez Net::XMPP::Client.

Modes

Plusieurs fonctions acceptent un argument de mode qui vous permet de spécifier comment la fonction doit se comporter :

block
envoie le paquet avec un ID, puis attend jusqu'à ce qu'une réponse arrive. Vous pouvez éventuellement spécifier un délai d'attente pour ne pas bloquer éternellement.
nonblock
envoie le paquet avec un ID, mais renvoie ensuite cet ID et le contrôle au programme principal. Net::XMPP continue d'enregistrer ce paquet, vous devez donc utiliser la fonction CheckID pour savoir quand il arrive. (Ce mode pourrait ne pas être très utile...)
passthru
envoie le paquet avec un ID, mais ne l'enregistre pas auprès de Net::XMPP, puis renvoie l'ID. Ceci est utile lorsqu'il est combiné avec la fonction XPath, car vous pouvez enregistrer une fonction unique liée à l'ID que vous recevez.

MÉTHODES

Fonctions de Base

GetErrorCode()
renvoie une chaîne qui contiendra probablement des informations utiles sur la raison pour laquelle une fonction a renvoyé une valeur indéfinie.
SetErrorCode
SetErrorCode(string)

définit un message utile avant de renvoyer une valeur indéfinie à l'appelant.

SetCallBacks
SetCallBacks(message=>function,
               presence=>function,
               iq=>function,
               send=>function,
               receive=>function,
               update=>function)

définit les fonctions de rappel pour les balises principales mentionnées. Les balises disponibles sont <message/>, <presence/> et <iq/>. Si un paquet est reçu avec un ID qui se trouve dans la liste des ID enregistrés (voir RegisterID ci-dessous), il n'est pas envoyé à ces fonctions, mais est plutôt inséré dans une LISTE et peut être récupéré par certaines fonctions que nous mentionnerons plus tard.

send et receive sont utilisés pour enregistrer ce qui est envoyé et reçu. update est utilisé comme moyen de mettre à jour votre programme pendant qu'il attend un paquet avec un ID pour qu'il soit renvoyé (utile pour les applications graphiques).

Une modification majeure qui est intervenue avec la dernière version est que l'ID de session est passé comme premier argument aux fonctions de rappel. Cela a été fait pour faciliter le module serveur.

L'argument suivant dépend du rappel dont vous parlez. message, presence et iq reçoivent des objets Net::XMPP qui correspondent à ces types. send et receive reçoivent des chaînes de caractères. update ne reçoit rien, pas même l'ID de session.

Si vous définissez la fonction à undef, alors le rappel est retiré de la liste.

SetPresenceCallBacks
SetPresenceCallBacks(type=>function etc...)

définit les fonctions de rappel pour le type de présence spécifié. La fonction prend les types comme clé principale et permet de spécifier une fonction pour chaque type de paquet que vous pouvez recevoir.

"available"
"unavailable"
"subscribe"
"unsubscribe"
"subscribed"
"unsubscribed"
"probe"
"error"

Lorsqu'un paquet <presence/> est reçu, il vérifie si le type="=" a un rappel défini. S'il y en a un, il l'appelle avec deux arguments :

l'ID de session et l'objet Net::XMPP::Presence.

Si vous définissez la fonction à undef, alors le rappel est retiré de la liste.

NOTE : Si vous utilisez cette méthode qui est plus propre, alors vous ne devez pas spécifier de rappel pour la présence dans la fonction SetCallBacks.

Net::XMPP définit certains rappels par défaut pour plusieurs types :
"subscribe" - répond avec "subscribed"
"unsubscribe" - répond avec "unsubscribed"
"subscribed" - répond avec "subscribed"
"unsubscribed" - répond avec "unsubscribed"
SetMessageCallBacks
SetMessageCallBacks(type=>function, etc...)

définit les fonctions de rappel pour le type de message spécifié. La fonction prend les types comme clé principale et permet de spécifier une fonction pour chaque type de paquet que vous pouvez recevoir.

"normal"
"chat"
"groupchat"
"headline"
"error"

Lorsqu'un paquet <message/> est reçu, il vérifie si le type="=" a un rappel défini. S'il y en a un, il l'appelle avec deux arguments :

l'ID de session et l'objet Net::XMPP::Message.

Si vous définissez la fonction à undef, alors le rappel est retiré de la liste.

NOTE : Si vous utilisez cette méthode qui est plus propre, alors vous ne devez pas spécifier de rappel pour le message dans la fonction SetCallBacks.

SetIQCallBacks
SetIQCallBacks(namespace=>{
                   get=>function,
                   set=>function,
                   result=>function
                 },
                 etc...)

définit les fonctions de rappel pour l'espace de noms spécifié. La fonction prend les espaces de noms comme clé principale et permet de spécifier une fonction pour chaque type de paquet que vous pouvez recevoir.

"get"
"set"
"result"

Lorsqu'un paquet <iq/> est reçu, il vérifie si le type="=" et xmlns="=" ont un rappel défini. S'il y en a un, il l'appelle avec deux arguments : l'ID de session et l'objet Net::XMPP::xxxx.

Si vous définissez la fonction à undef, alors le rappel est retiré de la liste.

NOTE : Si vous utilisez cette méthode qui est plus propre, alors vous ne devez pas spécifier de rappel pour iq dans la fonction SetCallBacks.

SetXPathCallBacks
SetXPathCallBacks(xpath=>function, etc...)

enregistre une fonction de rappel pour chaque xpath spécifié. Si Net::XMPP correspond à l'xpath, alors il appelle la fonction avec deux arguments :

l'ID de session et l'objet Net::XMPP::Message.

Les Xpaths sont à la racine de chaque paquet :

/message[@type="chat"]
/iq/*[xmlns="jabber:iq:roster"][1]
...
RemoveXPathCallBacks
RemoveXPathCallBacks(xpath=>function, etc...)

supprime une fonction de rappel pour chaque xpath spécifié.

SetDirectXPathCallBacks
SetDirectXPathCallBacks(xpath=>function, etc...)

enregistre une fonction de rappel pour chaque xpath spécifié. Si Net::XMPP correspond à l'xpath, alors il appelle la fonction avec deux arguments :

l'ID de session et l'objet XML::Stream::Node.

Les Xpaths sont à la racine de chaque paquet :

/anything
/anotherthing/foo/[1]
...

La principale différence entre ceci et les fonctions de rappel standard est que ceci transmet le XML directement et non un objet Net::XMPP.

RemoveDirectXPathCallBacks
RemoveDirectXPathCallBacks(xpath=>function, etc...)

supprime une fonction de rappel pour chaque xpath spécifié.

Process
    Process(integer)
prend la période de temps d'attente comme argument. Si aucun
temps d'attente n'est spécifié, la fonction bloque jusqu'à ce qu'un
paquet soit reçu. Sinon, elle attend ce nombre de secondes puis se termine
pour que votre programme puisse continuer à faire des choses utiles.
NOTE : Ceci est important pour les applications graphiques. Vous devez
laisser du temps pour traiter les commandes de l'interface graphique même si vous
attendez des paquets. Les valeurs de retour suivantes sont possibles, et ce qu'elles
signifient :
    1   - Statut ok, données reçues.
    0   - Statut ok, pas de données reçues.
  undef - Statut non ok, arrêter le traitement.

IMPORTANT : Vous devez vérifier la sortie de chaque Process. Si vous obtenez undef, alors la connexion a été fermée et vous devez agir en conséquence.

Send
Send(object, ignoreActivity)
Send(string, ignoreActivity)

reçoit soit un objet Net::XMPP::xxxxx, soit une chaîne comme argument et l'envoie au serveur. Si vous définissez ignoreActivty à 1, alors le module XML::Stream n'enregistrera pas ce paquet comme contribuant à l'activité de l'utilisateur.

Fonctions d'ID

SendWithID
SendWithID(object)
SendWithID(string)

reçoit soit un objet Net::XMPP::xxxxx, soit une chaîne comme argument, ajoute le prochain numéro d'ID disponible et envoie ce paquet au serveur. Renvoie le numéro d'ID attribué.

SendAndReceiveWithID
SendAndReceiveWithID(object, timeout)
SendAndReceiveWithID(string, timeout)

utilise SendWithID et WaitForID pour fournir un moyen complet d'envoyer et de recevoir des paquets avec des IDs. Peut recevoir soit un objet Net::XMPP::xxxxx, soit une chaîne. Renvoie l'objet Net::XMPP::xxxxx approprié en fonction du type de paquet reçu. Le temps d'attente est passé à WaitForID, voir cette fonction pour savoir comment fonctionne le temps d'attente.

ReceivedID
ReceivedID(integer)

renvoie 1 si un paquet avec l'ID spécifié a été reçu, 0 sinon.

GetID
GetID(integer)

renvoie l'objet Net::XMPP::xxxxx approprié en fonction du type de paquet reçu avec l'ID spécifié. Si l'ID n'a pas encore été reçu, GetID renvoie 0.

WaitForID
WaitForID(integer, timeout)

bloque jusqu'à ce qu'un paquet avec l'ID spécifié soit reçu. Renvoie l'objet Net::XMPP::xxxxx approprié en fonction du type de paquet reçu. Si le délai d'attente est atteint et que le paquet n'est pas arrivé, il est ignoré.

NOTE : Seuls les <iq/> sont officiellement pris en charge avec les IDs, donc l'envoi d'un <message/> ou d'un <presence/> avec un ID est risqué. Le serveur ignorera la balise ID et la transmettra, donc les deux clients doivent prendre en charge la balise ID pour que ces fonctions soient utiles.

AddNamespace
AddNamespace(ns=>string,
             tag=>string,
             xpath=>hash)

ajoute un espace de noms spécifié. Les paramètres ns, tag et xpath sont les mêmes que dans la fonction précédente.

Fonctions de Message

MessageSend
MessageSend(hash)

Modifie le hash et le transmet à SetMessage dans Net::XMPP::Message (voir là-bas pour les valeurs valides). Ensuite, il envoie le message au serveur.

Fonctions de Présence

PresenceSend
PresenceSend()
PresenceSend(hash, signature=>string)

Sans arguments, envoie une présence vide au serveur pour indiquer que vous êtes disponible. Si vous fournissez un hash, ce hash est transmis à la fonction SetPresence() définie dans le module Net::XMPP::Presence. Vous pouvez éventuellement spécifier une signature et elle sera placée dans l'attribut jabber:x:signed de <presence/>.

Fonctions d'Abonnement

Subscription
Subscription(hash)

Modifie le hash et le transmet à SetPresence dans Net::XMPP::Presence (voir là-bas pour les valeurs valides). Ensuite, il envoie l'abonnement au serveur.

Les types d'abonnement valides sont :

subscribe    - s'abonner à la présence d'un JID
unsubscribe  - se désabonner de la présence d'un JID
subscribed   - réponse à un subscribe
unsubscribed - réponse à un unsubscribe

Fonctions de Base de Données de Présence

PresenceDB
PresenceDB()

Demande à l'objet d'initialiser les callbacks pour peupler automatiquement la base de données de présence.

PresenceDBParse
PresenceDBParse(Net::XMPP::Presence)

Pour chaque présence que vous recevez, transmettez l'objet de présence à la DB afin qu'elle puisse enregistrer les ressources et les priorités pour vous. Renvoie soit la présence transmise, si elle ne peut pas être analysée pour la DB, soit la présence actuelle trouvée par la fonction PresenceDBQuery.

PresenceDBDelete
PresenceDBDelete(string|Net::XMPP::JID)

Supprime l'entrée du JID de la DB.

PresenceDBClear
PresenceDBClear()

Supprime toutes les entrées de la base de données.

PresenceDBQuery
PresenceDBQuery(string|Net::XMPP::JID)

Renvoie la présence NX qui a été reçue en dernier pour la priorité la plus élevée de ce JID. Vous pouvez lui passer une chaîne de caractères ou un objet JID NX.

PresenceDBResources
PresenceDBResources(string|Net::XMPP::JID)

Renvoie un tableau de ressources par ordre de priorité, de la plus élevée à la plus basse.

Fonctions IQ

Fonctions d'Authentification

AuthSend
AuthSend(username=>string,
         password=>string,
         resource=>string)

Remplit toutes les informations et construit un paquet Net::XMPP::IQ::Auth. Ensuite, il l'envoie au serveur avec un ID et attend que l'ID revienne. Il examine ensuite le paquet résultant pour déterminer si l'authentification a réussi. Le tableau renvoyé par AuthSend a ce format :

[ type , message ]

Si le type est "ok", alors l'authentification a réussi, sinon message contient plus de détails sur l'erreur.

Fonctions IQ::Register

RegisterRequest
RegisterRequest(to=>string,  timeout=>int)
RegisterRequest()

Envoie une requête <iq/> au serveur/transport spécifié, s'il n'est pas spécifié, il est envoyé au serveur actuel. La fonction renvoie un hash contenant les champs nécessaires. Voici un exemple de hash :

$hash{fields} - les champs RAW de iq:register.

$hash{instructions} - comment remplir le formulaire.

$hash{form} - les nouveaux formulaires dynamiques.

Dans $hash{form}, les champs présents sont les champs requis par le serveur.

RegisterSend
RegisterSend(hash)

Modifie le contenu du hash et le transmet à la fonction SetRegister du module Net::XMPP::Query jabber:iq:register. Cette fonction renvoie un tableau qui a ce format :

[ type , message ]

Si le type est "ok", alors l'enregistrement a réussi, sinon message contient plus de détails sur l'erreur.

Roster()

RosterParse
RosterParse(IQ object)

Renvoie un hash contenant la liste de contacts analysée dans la structure suivante :
