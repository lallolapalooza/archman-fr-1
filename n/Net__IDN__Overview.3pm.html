NOM

Net::IDN::Overwiew — Noms de domaine internationalisés pour les applications (IDNA)

DESCRIPTION

Les modules "Net::IDN::*" fournissent un cadre pour la gestion des noms de domaine internationalisés pour les applications (IDNA) dans les programmes perl.

Ce document fournit un aperçu des modules disponibles afin de vous permettre de choisir le meilleur module pour la tâche à accomplir.

MODULES DISPONIBLES

HAUT NIVEAU (UTILISEZ CECI)

Net::IDN::Encode
fournit une interface de haut niveau pour la conversion des noms de domaine (et, par commodité, des adresses e-mail).

Utilisez ce module si vous voulez simplement convertir des noms de domaine et que la méthode interne ne vous importe pas.

Actuellement, ce module utilise Net::IDN::UTS46. Cependant, cela pourrait changer à l'avenir si une autre spécification (par exemple, une révision de IDNA2008) devient plus appropriée.

L'auteur vise à ce que Net::IDN::Encode utilise toujours la spécification qui fournira les résultats les moins surprenants.

SPÉCIFIQUES À UNE NORME

Ces modules implémentent différentes versions des spécifications IDNA. Utilisez l'un de ces modules uniquement si vous avez besoin de compatibilité avec une incarnation spécifique d'IDNA.

Net::IDN::IDNA2003
implémente la spécification IDNA originale, publiée en 2003 (IDNA2003), qui est maintenant obsolète.

IDNA2003 est définie dans le RFC 3490 http://tools.ietf.org/rfc/3490 et les documents associés.

Net::IDN::UTS46
implémente la norme technique Unicode #46 (UTS #46 http://unicode.org/reports/tr46/), le traitement de compatibilité IDNA Unicode. Cette spécification prend en charge tous les noms de domaine autorisés par IDNA2003 ou IDNA2008.

ENCODAGE

Net::IDN::Punycode
effectue la conversion réelle entre la forme ASCII et Unicode des chaînes. Punycode est défini dans le RFC 3492 http://tools.ietf.org/rfc/3492 et les documents associés.

Généralement, il n'est pas conseillé d'utiliser ce module directement. Si vous convertissez des étiquettes de domaine (ou d'autres chaînes) sans préparation adéquate, vous pourriez obtenir un encodage ASCII qui n'est pas interopérable ou qui pose des problèmes de sécurité en raison d'usurpations.

Même si vous pensez que vos noms de domaine sont valides et dans un format déjà mappé, vous pourriez être trompé par différentes formes de normalisation Unicode (par exemple, certains environnements peuvent automatiquement convertir vos données en NFD, ce qui casse IDNA).

OBSOLÈTE/COMPATIBILITÉ

Ces modules sont uniquement maintenus afin de ne pas casser les applications qui pourraient en dépendre.

Encode::Punycode
fournit un plugin Encode pour Punycode. Comme Punycode n'est pas un encodage à usage général, ses applications sont limitées.
IDNA::Punycode
a une API qui dépend de variables globales. N'utilisez pas ce module.

DISTRIBUTIONS

Net-IDN-Encode
est la distribution principale couvrant les cas les plus courants de conversion des noms de domaine entre ASCII et Unicode.

L'auteur essaie de maintenir la chaîne de dépendances aussi petite que possible ; actuellement, cette distribution ne dépend que de perl 5.8.5 (y compris le module de base Unicode::Normalize).

Net-IDN-IDNA2003
fournit le module Net::IDN::IDNA2003. Ceci est séparé car il a une dépendance à Unicode::Stringprep (via Net::IDN::Nameprep).
Encode-Punycode
IDNA-Punycode
sont séparés car ils sont d'une utilité limitée pour l'utilisateur/programmeur perl moyen.
