Net::XMPP::Namespaces(3pm) Documentation Perl Contribuée par l'Utilisateur Net::XMPP::Namespaces(3pm)

NOM

Net::XMPP::Namespaces - Discussion approfondie sur la manière dont les espaces de noms sont gérés

SYNOPSIS

Net::XMPP::Namespaces offre un aperçu détaillé de la manière dont Net::XMPP gère les espaces de noms, et comment ajouter les vôtres. Il sert également de dépôt pour toutes les informations d'espace de noms dont Net::XMPP a besoin.

DESCRIPTION

XMPP en tant que protocole est très bien défini. Il existe trois principaux paquets de niveau supérieur (message, iq et présence). Il existe également un moyen d'étendre le protocole de manière très claire et structurée, via des espaces de noms.

Deux manières principales dont les espaces de noms sont utilisés dans Jabber sont de faire de <iq/> un wrapper générique, et comme moyen d'ajouter des données à n'importe quel paquet via une balise enfant <x/>. Nous utiliserons <x/> pour représenter le paquet, mais en réalité, il pourrait s'agir de n'importe quelle balise enfant : <foo/>, <data/>, <error/>, etc.

Le paquet Info/Query <iq/> utilise des espaces de noms pour déterminer le type d'informations à accéder. Habituellement, il y a une balise <query/> dans le <iq/> qui représente l'espace de noms, mais en fait, il peut s'agir de n'importe quelle balise. La définition de la partie Query est la première balise qui a un espace de noms.

<iq type="get"><query xmlns="..."/></iq>

ou

<iq type="get"><foo xmlns="..."/></iq>

Après ce stanza de requête, il peut y avoir un nombre quelconque d'autres stanzas (<x/> tags) que vous souhaitez inclure. Le paquet Query est représenté et disponible en appelant GetQuery() ou GetChild(), et les autres espaces de noms sont disponibles en appelant GetChild().

La balise X est juste un moyen de transmettre des données sur d'autres paquets. Comme intégrer l'horodatage d'un message en utilisant jabber:x:delay, ou signer sa présence pour le chiffrement en utilisant jabber:x:signed.

À cette fin, Net::XMPP a cherché à trouver un moyen simple et clair de définir les fonctions nécessaires pour accéder au XML d'un espace de noms. Nous passerons en revue les documents complets, puis montrerons deux exemples d'espaces de noms réels afin que vous puissiez voir de quoi nous parlons.

Vue d'ensemble

Pour éviter que de nombreux modules désagréables ne consomment de la mémoire inutilement, et pour éviter de devoir changer 15 modules lorsqu'une modification mineure est introduite, les modules Net::XMPP ont poussé AUTOLOAD à l'extrême. Namespaces.pm n'est rien d'autre qu'un ensemble d'appels de fonctions qui génère un grand hachage de hachages. Le hachage est accédé par la fonction AUTOLOAD de Stanza.pm pour faire quelque chose. (Cela aura du sens, je le promets.)

Avant de continuer, je vous suggère vivement de lire un livre sur Perl traitant d'AUTOLOAD et de son fonctionnement. À partir de maintenant, je supposerai que vous comprenez.

Lorsque vous créez un objet Net::XMPP::IQ et que vous lui ajoutez une Query (NewChild), plusieurs choses se produisent en arrière-plan. L'argument de NewChild est l'espace de noms que vous souhaitez ajouter. (espace-de-noms-personnalisé)

Maintenant que vous avez un objet Query avec lequel travailler, vous appellerez les fonctions GetXXX et SetXXX pour définir les données. Il n'y a pas de fonctions GetXXX et SetXXXX définies. Vous ne pouvez pas regarder dans le fichier Namespaces.pm et les trouver. Au lieu de cela, vous trouverez quelque chose comme ceci :

&add_ns(ns    => "monespace",
        tag   => "maballe",
        xpath => {
                  JID       => { type=>'jid', path => '@jid' },
                  Username  => { path => 'username/text()' },
                  Test      => { type => 'master' }
                 }
       );

Lorsque la fonction GetUsername() est appelée, la fonction AUTOLOAD recherche dans le hachage Namespaces.pm une clé "Username". En fonction du "type" du champ (scalaire étant le défaut), elle utilisera le "path" comme une XPath pour récupérer les données et appeler la méthode XPathGet() dans Stanza.pm.

Confus encore ?

Espaces de noms privés Net::XMPP

Et c'est là que cela commence à devenir un peu délicat. Lorsque vous voyez un espace de noms avec __netxmpp__, ou __netjabber__ de Net::Jabber, au début, il s'agit généralement de quelque chose de personnalisé pour Net::XMPP et NON de la partie réelle du protocole XMPP.

Il existe certains endroits où la structure du XML autorise plusieurs enfants du même nom. Les principaux endroits où vous verrez ce comportement sont là où vous avez plusieurs balises du même nom et celles-ci ont des enfants en dessous (jabber:iq:roster).

Dans jabber:iq:roster, la balise <item/> peut être répétée plusieurs fois, et est un peu comme un mini-espace de noms en soi. À cette fin, nous la traitons comme un espace de noms séparé et avons défini un espace de noms __netxmpp__:iq:roster:item pour le contenir. Ce qui se passe, c'est ceci : dans mon code, je définis que la balise des <item/> est "item" et tout ce qui a ce nom de balise doit créer un nouvel objet Net::XMPP::Stanza avec l'espace de noms __netxmpp__:iq:roster:item qui devient alors un enfant de l'objet Stanza jabber:iq:roster. De plus, lorsque vous souhaitez ajouter un nouvel élément à un projet jabber:iq:roster, vous appelez NewQuery avec l'espace de noms privé.

Je sais que cela semble compliqué. Et si après avoir lu l'intégralité de ce document, cela reste compliqué, envoyez-moi un e-mail, posez des questions, et je les surveillerai et ajusterai ces documents pour répondre aux questions que les gens posent.

add_ns()

Pour répéter, voici un exemple d'appel à add_ns() :

add_ns(ns    => "monespace",
        tag   => "maballe",
        xpath => {
                  JID       => { type=>'jid', path => '@jid' },
                  Username  => { path => 'username/text()' },
                  Test      => { type => 'master' }
                 }
       );

ns - C'est le nouvel espace de noms que vous essayez d'ajouter.

tag - C'est la balise racine à utiliser pour les objets basés sur cet espace de noms.

xpath - La référence de hachage passée dans l'appel add_ns à chaque nom d'entrée indique à Net::XMPP comment gérer les appels ultérieurs GetXXXX(), SetXXXX(), DefinedXXXX(), RemoveXXXX(), AddXXXX(). Les options de base que vous pouvez passer sont :

type - Ceci indique à Stanza comment gérer l'appel. Les valeurs possibles sont :

         array - La valeur à définir et retournée est une référence
                 de tableau. Par exemple, <group/> dans jabber:iq:roster.
         child - Ceci indique à Stanza qu'il doit rechercher les enfants
                 portant les noms de style __netxmpp__. AddXXX() ajoute
                 un nouvel enfant, et GetXXX() renverra un nouvel objet
                 Stanza représentant le paquet.
         flag - Ceci est pour les éléments enfants qui sont des balises
                en eux-mêmes : <foo/>. Puisque la présence de la balise est
                ce qui est important, et qu'il n'y a pas de cdata à stocker,
                nous l'appelons simplement un drapeau.
         jid - La valeur est un Jabber ID. GetXXX() renverra un objet
               Net::XMPP::JID à moins que vous ne lui passiez "jid", alors il
               renvoie une chaîne.
         master - Les appels GetXXX() et SetXXX() renvoient et prennent un
                  hachage représentant tous les appels GetXXX() et SetXXX().
                  Par exemple :
                    SetTest(foo=>"bar",
                            bar=>"baz");
                  Se traduit par :
                    SetFoo("bar");
                    SetBar("baz");
                  GetTest() renverrait un hachage contenant ce que le paquet
                  contient :
                    { foo=>"bar",  bar=>"baz" }
         raw - Ceci insérera le XML brut que vous spécifiez directement
               dans le Stanza à l'endroit où le chemin le spécifie.
         scalar - Ceci définira et obtiendra une valeur scalaire. C'est le
                  cheval de bataille principal car les attributs et CDATA sont
                  représentés par un scalaire. C'est le réglage par défaut si
                  vous n'en fournissez pas.
         special - Le type spécial est unique en ce sens qu'au lieu d'une
                   chaîne "special", vous lui donnez en fait un tableau :
                     [ "special" , <subtype> ]
                   Cela permet à Net::XMPP de gérer l'appel SetXXXX() d'une
                   manière spéciale selon votre choix. Actuellement, ceci est
                   principalement utilisé par jabber:iq:time pour définir
                   automatiquement les informations de temps dans le bon format,
                   et par jabber:iq:version pour définir le système d'exploitation
                   de la machine et ajouter la version de Net::Jabber au paquet
                   de retour. Vous n'aurez probablement PAS besoin d'utiliser
                   ceci, mais je voulais le mentionner.
         timestamp - Si vous appelez SetXXX() mais que vous ne lui passez rien,

Net::XMPP::Namespaces(3pm)

NAME

Net::XMPP::Namespaces - A module for adding new XMPP Namespaces

SYNOPSIS

  use Net::XMPP::Namespaces;

  # Register a new namespace
  &add_ns(
      ns    => 'mynamespace',
      tag   => 'mytag',
      xpath => {
                JID       => { type=>'jid', path => '@jid' },
                Username  => { path => 'username/text()' },
                Test      => { type => 'master' }
               }
  );

  # Instantiate a new XMPP object with our custom namespace
  my $xmpp = Net::XMPP->new( ... );
  $xmpp->register_namespace( 'mynamespace' );

  # Use the generated API calls
  $xmpp->SetJID( 'user@example.com' );
  print $xmpp->GetJID();

  $xmpp->SetUsername( 'myusername' );
  print $xmpp->GetUsername();

  $xmpp->SetTest( 'some value' );
  print $xmpp->GetTest();

DESCRIPTION

The Net::XMPP::Namespaces module allows you to define and register custom XMPP namespaces for use with the Net::XMPP module. This is useful if you are implementing an XMPP client or server that uses custom stanzas or extensions not defined in the standard XMPP specifications.

The core function is add_ns(), which takes a hash of arguments to define a new namespace and its associated elements and attributes.

The arguments to add_ns() are:

ns
This is the namespace URI that you want to register. This can be a standard XMPP namespace (e.g., jabber:iq:roster) or a custom namespace defined by your application (e.g., http://example.com/myapp).
tag
This is the primary tag name for the XML stanza associated with this namespace. For example, if you are defining the roster namespace, the tag would be iq.
xpath
This is a hash reference that defines how data within the XML stanza is accessed and manipulated. Each key in this hash corresponds to an API call that will be generated. The value for each key is another hash reference with the following options:
type
This specifies the data type for the element or attribute. Possible values include:
  • jid - For XMPP JID (Jabber ID) values.
  • master - A generic type, often used for the main element of a stanza.
  • any - A catch-all type.
If not specified, it defaults to any.
path
This is the XPath expression to locate the data within the XML stanza. It's a relative path, starting from the context of the stanza's root element. For example, @jid refers to the `jid` attribute of the current element, while username/text() refers to the text content of the username child element.
timestamp
If set to an empty string "", Net::XMPP will automatically insert a timestamp at the specified XPath location.

The add_ns() function generates corresponding API methods for getting, setting, and checking the existence of the data at the specified XPath locations. For example, if you define an XPath for JID, it will generate GetJID(), SetJID(), and DefinedJID() methods.

The Net::XMPP::Namespaces module also provides support for defining how child objects or stanzas are handled within a namespace. This is done through the child argument, which is a hash reference containing options like:

ns
The namespace URI for the child object.
skip_xmlns => 1
Prevents Net::XMPP from adding an xmlns='' attribute to the child object's XML.
specify_name => 1
Allows specifying the tag name for the child object dynamically. This is generally discouraged as it can lead to less predictable XML structures.
tag
The default tag name to use for the child object if specify_name is enabled.

The calls argument is an array reference that explicitly defines the methods to be generated for a given namespace element. Commonly generated calls include Get, Set, Defined, and Remove. For child types, you can customize the available methods based on how you want your API to interact with these child objects (e.g., ["Get","Add"]).

Here's an example breakdown of how add_ns() generates API calls:

  &add_ns(ns    => "mynamespace",
          tag   => "mytag",
          xpath => {
                    JID       => { type=>'jid', path => '@jid' },
                    Username  => { path => 'username/text()' },
                    Test      => { type => 'master' }
                   }
         );

This definition will result in the following API methods being available:

  GetJID()
  SetJID()
  DefinedJID()
  RemoveJID()
  GetUsername()
  SetUsername()
  DefinedUsername()
  RemoveUsername()
  GetTest()
  SetTest()
  DefinedTest()
  RemoveTest()

For elements that are not explicitly defined with a type, or when using the master type, Net::XMPP will generally handle them as strings. If you need to store binary data, you can use a specific type or handle it as CDATA. If you pass an empty string "" for the path or timestamp, then Net::XMPP will place a timestamp in the xpath location.

The path argument is a simplified form of XPath, relative to the stanza's root element. It doesn't require a fully rooted path. For instance, if your stanza's tag is "foo" and the path is "bar/text()", the effective XPath will be rooted within the <foo/> packet, targeting the CDATA of <bar>: <foo><bar>xxxxx</bar></foo>.

For a flag and a child type, simply specify the child element. Refer to the source code of this file for more examples and clarifications. It is also recommended to familiarize yourself with XPath if you are not already acquainted with it.

The child hash reference is used by Net::XMPP to manage adding and retrieving child objects. The keys for this hash are:

ns
The actual or custom namespace (e.g., __netxmpp__) to be used for the child packet.
skip_xmlns => 1
Instructs Net::XMPP not to add an xmlns='' attribute to the XML for the child object.
specify_name => 1
Enables specifying the tag name when calling NewChild("ns","tag"). The author considers this bad practice, suggesting that the tag of a child object should be known and that attributes or CDATA should be used to modify stanza types instead. It is strongly advised not to use this option.
tag
If specify_name is used, this option defines the default tag name. It is also advised not to use this.

The calls argument is an array reference that specifies which functions should be generated for this name. For most types above, you will get Get, Set, Defined, and Remove. For child types, you need to decide how your API should look and specify them yourself, for example:

  ["Get","Defined"]
  ["Add"]
  ["Get","Add","Defined"]

This choice depends on the desired API design.

Once more... The following:

  &add_ns(ns    => "mynamespace",
          tag   => "mytag",
          xpath => {
                    JID       => { type=>'jid', path => '@jid' },
                    Username  => { path => 'username/text()' },
                    Test      => { type => 'master' }
                   }
         );

generates the following API calls:

  GetJID()
  SetJID()
  DefinedJID()
  RemoveJID()
  GetUsername()
  SetUsername()
  DefinedUsername()
  RemoveUsername()
  GetTest()
  SetTest()
  DefinedTest()
  RemoveTest()

Wrap Up

Hopefully, this documentation has not deterred you from writing a custom namespace for your application and utilizing Net::XMPP. Please refer to the Net::XMPP::Protocol manpage for an example of how to use the add_ns() function to register your custom namespace, enabling Net::XMPP to handle it correctly.
