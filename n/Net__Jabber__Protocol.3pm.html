NOM

Net::Jabber::Protocol - Bibliothèque de protocole Jabber

SYNOPSIS

Net::Jabber::Protocol est un module qui fournit aux développeurs un accès facile au protocole Jabber de messagerie instantanée. Il fournit des fonctions de haut niveau aux objets Client, Component et Server de Net::Jabber. Ces fonctions sont automatiquement incluses dans ces modules via AUTOLOAD et les délégations.

DESCRIPTION

Protocol.pm cherche à fournir suffisamment d'API de haut niveau et d'automatisation des API de bas niveau pour que l'écriture d'un client/transport Jabber en Perl soit triviale. Pour ceux qui souhaitent travailler avec le bas niveau, c'est également possible, mais ces fonctions sont couvertes dans la documentation de chaque module.
Net::Jabber::Protocol fournit des fonctions pour se connecter, envoyer et recevoir des messages, définir des informations personnelles, créer un nouveau compte utilisateur, gérer le roster et se déconnecter. Vous pouvez utiliser toutes les fonctions ou aucune d'entre elles, il n'y a aucune obligation.
Pour plus d'informations sur la façon dont Net::Jabber est écrit, veuillez consulter l'aide de Net::Jabber lui-même.
Pour plus d'informations sur l'écriture d'un client, consultez Net::Jabber::Client.
Pour plus d'informations sur l'écriture d'un transport, consultez Net::Jabber::Transport.

Modes

Plusieurs fonctions acceptent un argument de mode qui vous permet de spécifier comment la fonction doit se comporter :
  block - envoie le paquet avec un ID, puis bloque jusqu'à ce qu'une réponse revienne. Vous pouvez éventuellement spécifier un délai d'attente afin de ne pas bloquer indéfiniment.

  nonblock - envoie le paquet avec un ID, puis renvoie cet ID et le contrôle au programme principal. Net::Jabber suit toujours ce paquet, vous devez donc utiliser la fonction CheckID pour savoir quand il arrive. (Cela pourrait ne pas être très utile...)
  passthru - envoie le paquet avec un ID, mais ne l'enregistre PAS auprès de Net::Jabber, puis renvoie l'ID. C'est utile lorsqu'il est combiné avec la fonction XPath car vous pouvez enregistrer une fonction à usage unique liée à l'ID que vous obtenez en retour.

                        vous vous poseriez la question. Pour plus d'informations sur les

NOM


Net::Jabber::Protocol - Protocol implementation for Jabber






SYNTAXIS


use Net::Jabber::Protocol;

my $protocol = Net::Jabber::Protocol->new(host => 'jabber.org',
                                             port => 5100);
$protocol->Connect;

# Search
$protocol->SearchRequest(to => 'buddy.jabber.org',
                          mode => 'wait');

# Time
$protocol->TimeQuery(to => 'buddy.jabber.org',
                      mode => 'wait');

# Version
$protocol->VersionQuery(to => 'buddy.jabber.org',
                         mode => 'wait');

# Presence
$protocol->SendPresence(type => 'available',
                         show => 'chat',
                         status => 'Hello World');

# Message
$protocol->SendMessage(to => 'buddy@jabber.org',
                         body => 'Hello World!');

$protocol->Disconnect;






DESCRIPTION


This module implements the core protocol for Jabber. The protocol
    is what allows Jabber clients and servers to communicate with each other.
    This module is used by Net::Jabber.


The protocol is XML-based, and this module handles the XML
    creation and parsing.

Presence Functions


SendPresence(to=>string|JID, - sends presence information to the
             type=>string,    specified JID.  Possible types are
             show=>string,    available, unavailable, probe,
             status=>string,   subscribe, subscribed, unsubscribe,
             priority=>int)   unsubscribed.
             The show argument can be one of: away, chat,
             dnd, ext-away, invisible, xa.
             The status is a string that will be displayed
             to the user.
             The priority is an integer value used to
             determine which presence is the most
             important.
