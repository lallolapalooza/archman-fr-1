NAME

Net::DNS::SEC::Tools::keyrec - Opérations de fichiers keyrec DNSSEC-Tools

SYNOPSIS

use Net::DNS::SEC::Tools::keyrec;
keyrec_creat("localzone.keyrec");
keyrec_open("localzone.keyrec");  (OBSOLÈTE)
$okfile = keyrec_filestat("localzone.keyrec");
keyrec_read("localzone.keyrec");
@krnames = keyrec_names();
$krec = keyrec_fullrec("example.com");
%keyhash = %$krec;
$zname = $keyhash{"algorithm"};
$val = keyrec_recval("example.com","zonefile");
$exists = keyrec_exists("example.com");
keyrec_add("zone","example.com",\%zone_krfields);
keyrec_add("key","Kexample.com.+005+12345",\%keydata);
keyrec_del("example.com");
keyrec_setval("zone","example.com","zonefile","db.example.com");
keyrec_delval("example.com","kskrev");
@kskpaths = keyrec_keypaths("example.com","kskcur");
$obsflag = keyrec_revoke_check("Kexample.com.+005+12345");
$setname = keyrec_signset_newname("example.com");
keyrec_signset_new($zone,"example-set-21","zskcur");
keyrec_signset_addkey("example-keys","Kexample.com+005+12345",
                                       "Kexample.com+005+54321");
keyrec_signset_addkey("example-keys",@keylist);
keyrec_signset_delkey("example-keys","Kexample.com+005+12345");
$flag = keyrec_signset_haskey("example-keys","Kexample.com+005+12345");
keyrec_signset_clear("example-keys","Kexample.com+005+12345");
@signset = keyrec_signsets();
$sset_prefix = keyrec_signset_prefix("example.com");
keyrec_settime("zone","example.com");
keyrec_settime("set","signing-set-42");
keyrec_settime("key","Kexample.com.+005+76543");
@keyfields = keyrec_keyfields();
@zonefields = keyrec_zonefields();
keyrec_write();
keyrec_saveas("filecopy.krf);
keyrec_close();
keyrec_discard();
$current_krf = keyrec_curkrf();
$default_krf = keyrec_defkrf();

DESCRIPTION

Le module Net::DNS::SEC::Tools::keyrec gère le contenu d'un fichier keyrec DNSSEC-Tools. Les fichiers keyrec contiennent des informations sur les domaines signés et les clés générées par les programmes DNSSEC-Tools. Des interfaces existent pour interroger les enregistrements keyrec, en créer de nouveaux et modifier ceux qui existent.

Un fichier keyrec est organisé en ensembles d'enregistrements keyrec. Chaque enregistrement keyrec doit être de type key ou zone. Les enregistrements keyrec décrivent comment les clés ont été générées, tandis que les enregistrements zonekeyrec décrivent comment les domaines ont été signés. Un enregistrement keyrec consiste en une série d'entrées clé/valeur. Voici un exemple d'enregistrement keyrec :

key     "Kexample.com.+005+30485"
      zonename        "example.com"
      keyrec_type     "kskcur"
      algorithm       "rsasha1"
      random          "/dev/urandom"
      ksklength       "2048"
      ksklife         "15768000"
      revperiod       "3888000"
      revtime         "1103277532"
      keyrec_gensecs  "1101183727"
      keyrec_gendate  "Tue Nov 23 04:22:07 2004"

La première étape pour utiliser ce module devrait être de créer un nouveau fichier keyrec ou d'ouvrir et de lire un fichier existant. L'interface keyrec_creat() crée un fichier keyrec s'il n'existe pas. L'interface keyrec_read() ouvre et lit le fichier, puis le parse en un format interne. Les enregistrements du fichier sont copiés dans une table de hachage (pour une référence rapide et facile par les routines de Net::DNS::SEC::Tools::keyrec) et dans un tableau (pour préserver le format et les commentaires). L'interface keyrec_filestat() peut être utilisée pour vérifier que le fichier donné est un fichier keyrec, bien qu'elle ne vérifie pas le contenu du fichier.

Après la lecture du fichier, les contenus sont référencés par keyrec_fullrec() et keyrec_recval(). Les contenus keyrec sont modifiés par keyrec_add() et keyrec_setval(). L'interface keyrec_settime() met à jour le tampon temporel d'un enregistrement keyrec à l'heure actuelle. Les enregistrements keyrec peuvent être supprimés avec l'interface keyrec_del().

Si le fichier keyrec a été modifié, il doit être explicitement sauvegardé, sinon les changements ne seront pas conservés. L'interface keyrec_write() sauvegarde les nouveaux contenus sur le disque. L'interface keyrec_saveas() sauvegarde le contenu en mémoire de keyrec sous le nom spécifié, sans affecter le fichier d'origine.

L'interface keyrec_close() sauvegarde le fichier et ferme le handle de fichier Perl du fichier keyrec. Si le fichier keyrec n'a plus besoin d'être ouvert mais que les contenus ne doivent pas être sauvegardés, keyrec_discard() supprime les données et ferme le handle sans sauvegarder les changements.

INTERFACES KEYREC

Les interfaces du module Net::DNS::SEC::Tools::keyrec sont présentées ci-dessous.

keyrec_add(keyrec_type,keyrec_name,fields)
Cette routine ajoute un nouvel enregistrement keyrec à un fichier keyrec et à la représentation interne du contenu du fichier. L'enregistrement keyrec est ajouté à la fois à la table de hachage %keyrecs et au tableau @keyreclines.

keyrec_type spécifie le type d'enregistrement keyrec — "key" ou "zone". keyrec_name est le nom de l'enregistrement keyrec. fields est une référence à une table de paires clé-valeur contenant les champs clé/valeur de l'enregistrement keyrec. Les clés de la table sont toujours converties en minuscules, mais les valeurs sont laissées telles quelles.

Le champ ksklength n'est ajouté que si la valeur du champ keyrec_type est "kskcur".

Le champ zsklength n'est ajouté que si la valeur du champ keyrec_type est "zsk", "zskcur", "zskpub" ou "zsknew".

Les champs d'horodatage sont ajoutés à la fin de l'enregistrement keyrec. Pour les enregistrements keyrec, les champs keyrec_gensecs et keyrec_gendate sont ajoutés. Pour les enregistrements zonekeyrec, les champs keyrec_signsecs et keyrec_signdate sont ajoutés.

Si un champ spécifié n'est pas défini pour le type d'enregistrement keyrec, le champ n'est pas ajouté. Cela évite que les données d'enregistrement zonekeyrec ne soient mélangées avec les données d'enregistrement keyrec.

Une ligne vide est ajoutée après la dernière ligne du nouvel enregistrement keyrec. Après l'ajout de tous les nouveaux enregistrements keyrec, le fichier keyrec est écrit mais pas fermé.

Les valeurs retournées sont :

0 succès
-1 valeur invalide pour krtype
keyrec_close()
Cette interface sauvegarde la version interne du fichier keyrec (ouvert avec keyrec_read()) et ferme le handle de fichier.
keyrec_creat(keyrec_file)
Cette interface crée un fichier keyrec s'il n'existe pas et tronque le fichier s'il existe déjà.

keyrec_creat() renvoie 1 si le fichier a été créé avec succès. Elle renvoie 0 s'il y a eu une erreur lors de la création du fichier.

keyrec_curkrf()
Cette routine renvoie le nom du fichier keyrec actuellement utilisé. Cette valeur est le nom passé à keyrec_read() ou keyrec_creat() ; elle ne garantit pas qu'il s'agit d'un nom absolu ou relatif.
keyrec_defkrf()
Cette routine renvoie le nom par défaut du fichier keyrec à partir du fichier de configuration DNSSEC-Tools.
keyrec_del(keyrec_name)
Cette routine supprime un enregistrement keyrec d'un fichier keyrec et de la représentation interne du contenu du fichier. L'enregistrement keyrec est supprimé à la fois de la table de hachage %keyrecs et du tableau @keyreclines.

L'enregistrement keyrec est supprimé de la table de hachage %keyrecs et du tableau @keyreclines si le nom de l'enregistrement est spécifié.

keyrec_discard()
Cette interface supprime les données du fichier keyrec et ferme le handle, sans sauvegarder les changements effectués.
keyrec_defkrf()
Cette routine renvoie le nom par défaut du fichier keyrec à partir du fichier de configuration DNSSEC-Tools.
keyrec_delval(keyrec_name,field)
Cette routine supprime un champ d'un enregistrement keyrec.
keyrec_read()
Cette interface ouvre et lit le fichier keyrec, puis le parse en un format interne.
keyrec_setval(keyrec_type,zone_name,field,value)
Cette routine définit une valeur dans un enregistrement keyrec.
keyrec_settime(keyrec_type,zone_name)
Cette routine met à jour le champ d'horodatage d'un enregistrement keyrec à l'heure actuelle.
keyrec_signset_addkey(keyrec_type,keydata)
Cette routine ajoute une clé à un jeu de clés de signature.
keyrec_signset_clear(keyrec_type,keydata)
Cette routine supprime une clé d'un jeu de clés de signature.
keyrec_signset_haskey(keyrec_type,keydata)
Cette routine vérifie si une clé est dans un jeu de clés de signature.
keyrec_signset_new($zone,$setname,$keytype)
Cette routine crée un nouveau jeu de clés de signature.
keyrec_signset_newname($zone,$setname)
Cette routine génère un nouveau nom de jeu de clés de signature.
keyrec_signset_prefix($zone)
Cette routine renvoie le préfixe d'un jeu de clés de signature.
keyrec_signset_addkey($keylist,$key1,$key2)
Cette routine ajoute des clés à un jeu de clés de signature.
keyrec_signset_delkey($keylist,$key1)
Cette routine supprime une clé d'un jeu de clés de signature.
keyrec_signset_haskey($keylist,$key1)
Cette routine vérifie si une clé est dans un jeu de clés de signature.
keyrec_signset_clear($keylist,$key1)
Cette routine supprime une clé d'un jeu de clés de signature.

Seul le keyrec lui-même est supprimé du fichier. Les commentaires associés et les lignes vides qui l'entourent sont laissés intacts.

Les valeurs de retour sont :

 0 suppression réussie du keyrec
-1 type de kr invalide (chaîne vide ou nom inconnu)
keyrec_delval(keyrec_name, field)
Cette routine supprime le field du keyrec nommé par keyrec_name. Le keyrec est supprimé de la table de hachage %keyrecs et du tableau @keyreclines.

Les valeurs de retour sont :

-1 keyrec_name n'est pas le nom d'un keyrec existant
 0 champ non trouvé dans keyrec
 1 champ supprimé de keyrec
keyrec_discard()
Cette routine retire un fichier keyrec de l'utilisation par un programme. Les données stockées en interne sont supprimées et le descripteur de fichier keyrec est fermé. Cependant, les données modifiées ne sont pas sauvegardées avant la fermeture du descripteur de fichier. Ainsi, les données modifiées et nouvelles seront perdues.
keyrec_exists(keyrec_name)
keyrec_exists() renvoie une valeur booléenne indiquant si un keyrec portant le nom spécifié keyrec_name existe.
keyrec_filestat(keyrec_name)
keyrec_filestat() vérifie qu'un fichier donné peut être un candidat raisonnable pour un fichier keyrec de DNSSEC-Tools. Les vérifications à effectuer peuvent être déduites de la liste des valeurs de retour.

Les valeurs de retour sont :
0 - retourné si tous les tests réussissent
1 - aucun nom réel n'a été donné
2 - le fichier n'existe pas
3 - le fichier n'est pas un fichier ordinaire
4 - le fichier n'est pas lisible
5 - le fichier est vide

keyrec_fullrec(keyrec_name)
keyrec_fullrec() renvoie une référence au keyrec spécifié dans keyrec_name.
keyrec_keyfields()
Cette routine renvoie une liste des champs reconnus pour un keyrec de clé.
keyrec_keypaths(zonename,keytype)
keyrec_keypaths() renvoie une liste de chemins vers un ensemble de fichiers de clés pour une zone donnée. La zone est spécifiée dans zonename et le type de clé est donné dans keytype.

keytype doit être l'une des valeurs suivantes : "kskcur", "kskpub", "kskrev", "kskobs"", "zskcur", "zskpub", "zsknew", "zskobs", "ksk", "zsk", ou "all". La casse n'a pas d'importance pour le keytype.

Si keytype est l'une des étiquettes spéciales ("ksk", "zsk", ou "all") alors un ensemble de chemins de clés sera renvoyé. Un keytype de "ksk" renverra les chemins vers toutes les clés KSK pour la zone, un keytype de "zsk" renverra les chemins vers toutes les clés ZSK pour la zone, et un keytype de "all" renverra les chemins vers toutes les clés pour la zone.

Si le type de clé donné n'est pas défini dans le keyrec de zone donné ou si le type de clé n'est pas reconnu, alors un ensemble nul est renvoyé.

keyrec_names()
Cette routine renvoie une liste des noms de keyrec du fichier.
keyrec_open(keyrec_file) OBSOLÈTE
Cette routine servait à ouvrir un fichier keyrec DNSSEC-Tools existant. Cependant, c'était une opération inutile car keyrec_read() ouvrait le fichier s'il n'était pas déjà ouvert.

Cet appel sera finalement supprimé. Pour l'instant, il appelle keyrec_filestat() pour vérifier la validité du fichier keyrec spécifié.

Valeurs de retour :

1 si le fichier passe tous les tests de keyrec_filestat()
0 si le fichier échoue à l'un des tests de keyrec_filestat()

Pour des raisons de compatibilité ascendante, le sens succès/échec des valeurs de retour correspond au sens succès/échec des retours originaux de keyrec_open().

keyrec_read(keyrec_file)
Cette interface lit le fichier keyrec spécifié et le parse en une table de hachage keyrec et un tableau du contenu du fichier. keyrec_read() **doit** être appelé avant toute autre appel des routines de Net::DNS::SEC::Tools::keyrec. Si un autre keyrec est déjà ouvert, il est sauvegardé et fermé avant d'ouvrir le nouveau keyrec.

En cas de succès, keyrec_read() renvoie le nombre de keyrec lus à partir du fichier.

Valeurs de retour en cas d'échec :

-1 le fichier keyrec spécifié n'existe pas
-2 impossible d'ouvrir le fichier keyrec
-3 noms de keyrec dupliqués dans le fichier
keyrec_recval(keyrec_name,keyrec_field)
Cette routine renvoie la valeur d'un champ spécifié dans un keyrec donné. keyrec_name est le nom du keyrec particulier à consulter. keyrec_field est le nom du champ dans ce keyrec.

Par exemple, le fichier keyrec actuel contient le keyrec suivant :

zone        "example.com"
            zonefile        "db.example.com"

L'appel :

keyrec_recval("example.com","zonefile")

renverra la valeur "db.example.com".

keyrec_revoke_check(key)
Cette interface vérifie le keyrec d'une clé KSK révoquée pour déterminer si elle se trouve dans ou hors de sa période de révocation. La clé doit être de type "kskrev", et elle doit avoir les champs "revtime" et "revperiod" définis dans le keyrec.

La détermination est faite en soustrayant le temps de révocation du temps actuel. Si cela est supérieur à la période de révocation, alors la clé a dépassé le temps pendant lequel elle doit être révoquée. Sinon, elle doit rester révoquée.

Valeurs de retour :

 1 la clé spécifiée est en dehors de la période de révocation et devrait être
   marquée comme obsolète
 0 la clé spécifiée est dans la période de révocation et devrait rester
   révoquée
-1 erreur (type de clé invalide, données de keyrec manquantes)
keyrec_saveas(keyrec_file_copy)
Cette interface enregistre la version interne du fichier keyrec (ouvert avec keyrec_read()) dans le fichier nommé dans le paramètre keyrec_file_copy. Le descripteur de fichier du nouveau fichier est fermé, mais le fichier d'origine et le descripteur de fichier correspondant ne sont pas affectés.
keyrec_setval(keyrec_type,keyrec_name,field,value)
Définit la valeur d'une paire nom/champ dans un keyrec spécifié. Le fichier n'est **pas** écrit après la mise à jour de la valeur. La valeur est sauvegardée à la fois dans %keyrecs et dans @keyreclines, et le drapeau de modification du fichier est défini.

keyrec_type spécifie le type du keyrec. Ceci n'est utilisé que si un nouveau keyrec est créé par cet appel. keyrec_name est le nom du keyrec qui sera modifié. field est le champ du keyrec qui sera modifié. value est la nouvelle valeur pour le champ.

Les valeurs de retour sont :

0 si la création a réussi
-1 un type invalide a été donné
keyrec_settime(keyrec_type,keyrec_name)
Définit l'horodatage d'un keyrec spécifié. Le fichier n'est **pas** écrit après la mise à jour de la valeur. La valeur est sauvegardée à la fois dans %keyrecs et dans @keyreclines, et le drapeau de modification du fichier est défini. Les champs keyrec_signdate et keyrec_signsecs du keyrec sont modifiés.
keyrec_write()
Cette interface enregistre la version interne du fichier keyrec (ouvert avec keyrec_read()). Elle ne ferme pas le descripteur de fichier. À titre de mesure d'efficacité, un drapeau de modification interne est vérifié avant d'écrire le fichier. Si le programme n'a pas modifié le contenu du fichier keyrec, il n'est pas réécrit.

keyrec_write() obtient un verrou exclusif sur le fichier keyrec pendant l'écriture.

keyrec_zonefields()
Cette routine renvoie une liste des champs reconnus pour un keyrec de zone.

INTERFACES KEYREC SIGNING-SET

Les ensembles de signature sont des collections de clés de chiffrement, définies par leur inclusion dans un keyrec d'ensemble particulier. Les noms des clés se trouvent dans l'enregistrement keys du keyrec, qui contient les noms des keyrec de clés. En raison de la manière dont les noms de clés sont gérés, les noms dans un ensemble de signature ne doivent pas contenir d'espaces.
