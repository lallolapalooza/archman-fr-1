Net::DBus::Exporter(3) Documentation Perl fournie par l'utilisateur Net::DBus::Exporter(3)

NOM

Net::DBus::Exporter - Exporter des méthodes et des signaux vers le bus

SYNTAXE

# Définir un nouveau paquet pour l'objet que nous allons
# exporter
package Demo::HelloWorld;
# Spécifier l'interface principale fournie par notre objet
use Net::DBus::Exporter qw(org.example.demo.Greeter);
# Nous allons être un objet DBus
use base qw(Net::DBus::Object);
# S'assurer que seules les méthodes explicitement exportées peuvent être invoquées
dbus_strict_exports;
# Exporter un signal 'Greeting' acceptant un paramètre string
dbus_signal("Greeting", ["string"]);
# Exporter 'Hello' comme une méthode acceptant un paramètre string unique
# et retournant une valeur string unique
dbus_method("Hello", ["string"], ["string"]);
# Exporter 'Goodbye' comme une méthode acceptant un paramètre string unique
# et retournant une valeur string unique, mais le placer dans
# l'interface 'org.exaple.demo.Farewell'
dbus_method("Goodbye", ["string"], ["string"], "org.example.demo.Farewell");

DESCRIPTION

Le module "Net::DBus::Exporter" est utilisé pour exporter des méthodes et des signaux définis dans un objet vers le bus de messages. Comme Perl est un langage faiblement typé, il n'est pas possible de déterminer automatiquement les informations de type correctes pour les méthodes à exporter. Ainsi, lors de la sous-classification de Net::DBus::Object, ce paquet fournira les informations de type pour les méthodes et les signaux.

Lors de l'importation de ce paquet, un argument optionnel peut être fourni pour spécifier le nom d'interface par défaut à associer aux méthodes et signaux, pour lesquels une interface explicite n'est pas spécifiée. Ainsi, dans le cas courant où les objets ne fournissent qu'une seule interface, cela évite de répéter le nom de l'interface pour chaque méthode exportée.

TYPES SCALAIRES

Lors de la spécification des types de données scalaires pour les paramètres et les valeurs de retour, les constantes de chaîne suivantes doivent être utilisées pour désigner le type de données. Lorsque les valeurs correspondant à ces types sont (dé)sérialisées, elles sont représentées par le type de données SCALAR de Perl (voir perldata).

"string"
Une chaîne de caractères en UTF-8
"int16"
Un entier signé sur 16 bits
"uint16"
Un entier non signé sur 16 bits
"int32"
Un entier signé sur 32 bits
"uint32"
Un entier non signé sur 32 bits
"int64"
Un entier signé sur 64 bits. NB, ce type n'est pas supporté par de nombreuses versions de Perl sur des plateformes 32 bits, donc s'il est utilisé, vos données risquent d'être tronquées à 32 bits.
"uint64"
Un entier non signé sur 64 bits. NB, ce type n'est pas supporté par de nombreuses versions de Perl sur des plateformes 32 bits, donc s'il est utilisé, vos données risquent d'être tronquées à 32 bits.
"byte"
Un seul octet sur 8 bits
"bool"
Une valeur booléenne
"double"
Un flottant double précision IEEE

TYPES COMPOSÉS

Lors de la spécification de types de données composés pour les paramètres et les valeurs de retour, une référence de tableau doit être utilisée, le premier élément étant le nom du type composé.

["array", TYPE_TABLEAU]
Un tableau de valeurs, dont le type est "TYPE_TABLEAU". Le "TYPE_TABLEAU" peut être soit un nom de type scalaire, soit un type composé imbriqué. Lorsque les valeurs correspondant au type tableau sont (dé)sérialisées, elles sont représentées par le type ARRAY de Perl (voir perldata). Si, par exemple, une méthode était déclarée pour avoir un seul paramètre de type ["array", "string"], alors lors de l'appel de la méthode, on fournirait une référence de tableau de chaînes : 
$object->hello(["John", "Doe"])
["dict", TYPE_CLÉ, TYPE_VALEUR]
Un dictionnaire de valeurs, plus communément appelé table de hachage. Le "TYPE_CLÉ" est le nom du type de données scalaire utilisé pour les clés du dictionnaire. Le "TYPE_VALEUR" est le nom du type de données scalaire ou composé utilisé pour les valeurs du dictionnaire. Lorsque les valeurs correspondant au type dict sont (dé)sérialisées, elles sont représentées par le type HASH de Perl (voir perldata). Si, par exemple, une méthode était déclarée pour avoir un seul paramètre de type ["dict", "string", "string"], alors lors de l'appel de la méthode, on fournirait une référence de hachage de chaînes, 
$object->hello({forename => "John", surname => "Doe"});
["struct", TYPE_VALEUR_1, TYPE_VALEUR_2]
Une structure de valeurs, à considérer comme une variation du type tableau où les éléments peuvent varier. De nombreux langages ont un nom explicite associé à chaque valeur, mais comme Perl n'a pas de représentation native des structures, elles sont représentées par le type LIST. Si, par exemple, une méthode était déclarée pour avoir un seul paramètre de type ["struct", "string", "string"], correspondant à la structure C 
struct {
  char *forename;
  char *surname;
} name;

alors, lors de l'appel de la méthode, on fournirait une référence de tableau avec les valeurs ordonnées pour correspondre à la structure

$object->hello(["John", "Doe"]);

TYPES MAGIQUES

Lors de la spécification des données d'introspection pour un service exporté, il existe quelques types dits "magiques". Les paramètres déclarés comme types magiques ne sont pas visibles par les clients, mais leurs valeurs sont plutôt fournies automatiquement par les bindings côté serveur. Une utilisation des types magiques est d'obtenir un paramètre supplémentaire transmis avec le nom unique de l'appelant invoquant la méthode.

"caller"
La valeur transmise est le nom unique de l'appelant de la méthode. Les noms uniques sont des chaînes attribuées automatiquement aux connexions clientes par le démon de bus, par exemple ':1.15'
"serial"
La valeur transmise est un entier dans la portée d'un appelant, qui s'incrémente à chaque appel de méthode.

ANNOTATIONS

Lors de l'exportation de méthodes, de signaux et de propriétés, en plus des informations fondamentales de typage des données, un certain nombre d'annotations de métadonnées sont possibles. Celles-ci sont spécifiées en passant une référence de hachage avec les clés souhaitées comme dernier paramètre lors de la définition de l'exportation. Les annotations suivantes sont actuellement supportées :

no_return
Indique que cette méthode ne retourne aucune valeur, et donc aucun message de réponse ne doit être envoyé sur le fil, informant de même les clients de ne pas s'attendre / attendre un message de réponse.
deprecated
Indique que l'utilisation de cette méthode/signal/propriété est déconseillée, et qu'elle pourrait disparaître complètement dans une future version. Les clients afficheront généralement un message d'avertissement lorsqu'une méthode/signal/propriété dépréciée est utilisée.
param_names
Un tableau de chaînes spécifiant les noms des paramètres d'entrée de la méthode ou du signal. S'il est omis, aucun nom ne sera attribué.
return_names
Un tableau de chaînes spécifiant les noms des paramètres de retour de la méthode. S'il est omis, aucun nom ne sera attribué.
strict_exceptions
Les exceptions levées par cette méthode qui ne sont pas de type Net::DBus::Error ne seront pas interceptées et converties en erreurs D-Bus. Elles seront relancées et continueront de remonter la pile jusqu'à ce que quelque chose d'autre les intercepte (ou que le processus meure).

MÉTHODES

dbus_method($name, $params, $returns, [\%annotations]);
dbus_method($name, $params, $returns, $interface, [\%annotations]);
Exporte une méthode nommée $name, ayant des paramètres dont les types sont définis par $params
Net::DBus::Exporter(3pm)

NAME

Net::DBus::Exporter — A helper class for exporting methods, signals, and properties.

SYNOPSIS

    use Net::DBus::Exporter;
    my $exporter = Net::DBus::Exporter->new($obj);
    $exporter->dbus_method($name, $params, $returns, [\%attributes]);
    $exporter->dbus_property($name, $type, $access, [\%attributes]);
    $exporter->dbus_signal($name, $params, [\%attributes]);
    $exporter->dbus_no_strict_exports();

DESCRIPTION

This class is used to export methods, signals, and properties from a Net::DBus::Object to D-Bus. It handles the generation of D-Bus introspection data, and makes it easier to define the interfaces that your object implements.

SCALAR TYPES

The following scalar types are supported:

string
array
int8
int16
int32
int64
uint8
uint16
uint32
uint64
double
float
boolean
byte
object
signature
variant

COMPOUND TYPES

The following compound types are supported:

dict
Takes two arguments, the type of the key and the type of the value.
struct
Takes one or more arguments, the types of the fields in the struct.
array
Takes one argument, the type of the elements in the array.

For example:

    dbus_method("MyMethod", [], ["dict", "string", "int32"]);
    dbus_method("MyMethod2", ["array", "string"], []);
    dbus_method("MyMethod3", [], ["struct", "string", "int32"]);

MAGIC TYPES

The following magic types are supported:

any
Represents any valid D-Bus type. This is useful for properties that can hold any type of value.
error
Represents a D-Bus error.

ANNOTATIONS

You can pass a hash reference of annotations as the last argument to dbus_method, dbus_property, and dbus_signal. The following annotations are supported:

deprecated
A boolean value indicating whether the method, signal, or property is deprecated.
no_return
A boolean value indicating that a method does not return any values. This is useful for methods that only perform an action.
param_names
An array reference of strings, where each string is the name of a parameter. This is useful for documenting the parameters of a method or signal.
return_names
An array reference of strings, where each string is the name of a return value. This is useful for documenting the return values of a method.
get_closure
A boolean value indicating that a property is read-only and is accessed via a closure.
set_closure
A boolean value indicating that a property is write-only and is accessed via a closure.

METHODS

dbus_method($name, $params, $returns, [\%attributes]);
Exports a method called $name, with parameters whose types are defined by $params and returning values whose types are defined by $returns. If the $interface parameter is provided, then the method is associated with that interface, otherwise the default interface for the calling package is used. The value for the $params parameter should be an array reference with each element defining the data type of a parameter to the method. Likewise, the $returns parameter should be an array reference with each element defining the data type of a return value. If it not possible to export a method which accepts a variable number of parameters, or returns a variable number of values.
dbus_no_strict_exports();
If a object is using the Exporter to generate DBus introspection data, the default behaviour is to only allow invocation of methods which have been explicitly exported.

To allow clients to access methods which have not been explicitly exported, call "dbus_no_strict_exports". NB, doing this may be a security risk if you have methods considered to be "private" for internal use only. As such this method should not normally be used. It is here only to allow switching export behaviour to match earlier releases.

dbus_property($name, $type, $access, [\%attributes]);
dbus_property($name, $type, $access, $interface, [\%attributes]);
Exports a property called $name, whose data type is $type. If the $interface parameter is provided, then the property is associated with that interface, otherwise the default interface for the calling package is used.
dbus_signal($name, $params, [\%attributes]);
dbus_signal($name, $params, $interface, [\%attributes]);
Exports a signal called $name, having parameters whose types are defined by $params. If the $interface parameter is provided, then the signal is associated with that interface, otherwise the default interface for the calling package is used. The value for the $params parameter should be an array reference with each element defining the data type of a parameter to the signal. Signals do not have return values. It not possible to export a signal which has a variable number of parameters.

EXAMPLES

No parameters, no return values
A method which simply prints "Hello World" each time its called 
sub Hello {
    my $self = shift;
    print "Hello World\n";
}
dbus_method("Hello", [], []);
One string parameter, returning an boolean value
A method which accepts a process name, issues the killall command on it, and returns a boolean value to indicate whether it was successful. 
sub KillAll {
    my $self = shift;
    my $processname = shift;
    my $ret  = system("killall $processname");
    return $ret == 0 ? 1 : 0;
}
dbus_method("KillAll", ["string"], ["bool"]);
One list of strings parameter, returning a dictionary
A method which accepts a list of files names, stats them, and returns a dictionary containing the last modification times. 
sub LastModified {
   my $self = shift;
   my $files = shift;
   my %mods;
   foreach my $file (@{$files}) {
      $mods{$file} = (stat $file)[9];
   }
   return \%mods;
}
dbus_method("LastModified", ["array", "string"], ["dict", "string", "int32"]);
Annotating methods with metdata
A method which is targeted for removal, and also does not return any value 
sub PlayMP3 {
    my $self = shift;
    my $track = shift;
    system "mpg123 $track &";
}
dbus_method("PlayMP3", ["string"], [], { deprecated => 1, no_return => 1 });

Or giving names to input parameters:

sub PlayMP3 {
    my $self = shift;
    my $track = shift;
    system "mpg123 $track &";
}
dbus_method("PlayMP3", ["string"], [], { param_names => ["track"] });
