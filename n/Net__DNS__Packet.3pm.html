Net::DNS::Packet(3) Documentation fournie par les utilisateurs de Perl Net::DNS::Packet(3)

NOM

Net::DNS::Packet - Paquet du protocole DNS

SYNTAXE

use Net::DNS::Packet;
$query = Net::DNS::Packet->new( 'example.com', 'MX', 'IN' );
$reply = $resolver->send( $query );

DESCRIPTION

Un objet Net::DNS::Packet représente un paquet du protocole DNS.

MÉTHODES

new

$packet = Net::DNS::Packet->new( 'example.com' );
$packet = Net::DNS::Packet->new( 'example.com', 'MX', 'IN' );
$packet = Net::DNS::Packet->new();

Si un domaine, un type et une classe sont passés, new() crée un objet Net::DNS::Packet approprié pour effectuer une requête DNS pour les informations spécifiées. Le type et la classe peuvent être omis ; par défaut, le type est A et la classe est IN.

Si appelé avec un argument vide, new() crée un paquet vide.

decode

$packet = Net::DNS::Packet->decode( \$data );
$packet = Net::DNS::Packet->decode( \$data, 1 );        # debug
$packet = Net::DNS::Packet->new( \$data ... );

Un nouvel objet paquet est créé en décodant les données du paquet DNS contenues dans la valeur scalaire référencée par le premier argument. L'argument booléen optionnel active la sortie de débogage.

Retourne undef si l'objet paquet ne peut pas être créé.

Les erreurs de décodage, y compris la corruption ou la troncature des données, sont collectées dans la variable $@ ($EVAL_ERROR).

( $packet, $length ) = Net::DNS::Packet->decode( \$data );

Si appelé dans un contexte de tableau, retourne un objet paquet et le nombre d'octets décodés avec succès.

Note : Le nombre de RR dans chaque section du paquet peut différer de la valeur correspondante dans l'en-tête si les données ont été tronquées ou corrompues pendant la transmission.

encode

$data = $packet->encode;
$data = $packet->encode( $size );

Retourne les données du paquet au format binaire, approprié pour être envoyé en tant que requête de recherche ou de mise à jour à un serveur de noms.

La taille peut être spécifiée en utilisant un argument optionnel non nul.

header

$header = $packet->header;

Méthode constructeur qui retourne un objet Net::DNS::Header représentant la section d'en-tête du paquet.

edns

$version = $packet->edns->version;
$UDPsize = $packet->edns->size;

Fonction utilitaire qui fournit un accès au RR d'extension EDNS du protocole.

reply

$reply = $query->reply( $UDPmax );

Méthode constructeur qui retourne un nouveau paquet de réponse.

L'argument optionnel UDPsize indique la taille maximale du paquet UDP qui peut être réassemblée par la pile réseau locale, et est annoncée en réponse à une requête EDNS.

question, zone

@question = $packet->question;

Retourne une liste d'objets Net::DNS::Question représentant la section de question du paquet.

Dans les paquets de mise à jour dynamique, cette section est appelée zone() et spécifie la zone DNS à mettre à jour.

answer, pre, prerequisite

@answer = $packet->answer;

Retourne une liste d'objets Net::DNS::RR représentant la section de réponse du paquet.

Dans les paquets de mise à jour dynamique, cette section est appelée pre() ou prerequisite() et spécifie les RR ou les RRsets qui doivent exister ou ne pas exister.

authority, update

@authority = $packet->authority;

Retourne une liste d'objets Net::DNS::RR représentant la section d'autorité du paquet.

Dans les paquets de mise à jour dynamique, cette section est appelée update() et spécifie les RR ou les RRsets à ajouter ou à supprimer.

additional

@additional = $packet->additional;

Retourne une liste d'objets Net::DNS::RR représentant la section supplémentaire du paquet.

print

$packet->print;

Imprime le paquet complet dans le flux de sortie actuel en utilisant le format maître tel qu'imposé par la RFC1035.

string

print $packet->string;

Retourne une représentation sous forme de chaîne de caractères du paquet.

from

print "paquet reçu de ", $packet->from, "\n";

Retourne l'adresse IP d'où ce paquet a été reçu. Cette méthode retournera undef pour les paquets créés par l'utilisateur.

size

print "taille du paquet : ", $packet->size, " octets\n";

Retourne la taille du paquet en octets tel qu'il a été reçu d'un serveur de noms. Cette méthode retournera undef pour les paquets créés par l'utilisateur (utilisez length($packet->data) à la place).

push

$ancount = $packet->push( prereq => $rr );
$nscount = $packet->push( update => $rr );
$arcount = $packet->push( additional => $rr );
$nscount = $packet->push( update => $rr1, $rr2, $rr3 );
$nscount = $packet->push( update => @rr );

Ajoute des RR à la section spécifiée du paquet.

Retourne le nombre d'enregistrements de ressources dans la section spécifiée.

Les noms de section peuvent être abrégés aux trois premiers caractères.

unique_push

$ancount = $packet->unique_push( prereq => $rr );
$nscount = $packet->unique_push( update => $rr );
$arcount = $packet->unique_push( additional => $rr );
$nscount = $packet->unique_push( update => $rr1, $rr2, $rr3 );
$nscount = $packet->unique_push( update => @rr );

Ajoute des RR à la section spécifiée du paquet, à condition que les RR ne soient pas déjà présents dans la même section.

Retourne le nombre d'enregistrements de ressources dans la section spécifiée.

Les noms de section peuvent être abrégés aux trois premiers caractères.

pop

my $rr = $packet->pop( 'pre' );
my $rr = $packet->pop( 'update' );
my $rr = $packet->pop( 'additional' );

Supprime un RR d'une section spécifiée du paquet.

sign_tsig

$query = Net::DNS::Packet->new( 'www.example.com', 'A' );
$query->sign_tsig(
        $keyfile,
        fudge => 60
        );
$reply = $res->send( $query );
$reply->verify( $query ) || die $reply->verifyerr;

Ajoute un enregistrement TSIG à un objet Net::DNS::Packet, qui sera utilisé pour signer le paquet (voir RFC 2845).

L'enregistrement TSIG peut être personnalisé via des arguments supplémentaires dans la méthode sign_tsig() ou via les méthodes correspondantes de Net::DNS::RR::TSIG.

Si vous souhaitez créer un enregistrement TSIG avec un algorithme non standard, vous devrez le créer vous-même. Dans tous les cas, le nom de l'enregistrement TSIG doit identifier de manière unique la clé partagée entre les parties, et le nom de l'algorithme doit identifier la fonction de signature à utiliser avec la clé spécifiée.

$tsig = Net::DNS::RR->new(
        name            => 'tsig.example',
        type            => 'TSIG',
        algorithm       => 'custom-algorithm',
        key             => '<base64 key text>',
        sig_function    => sub {
                                  my ($key, $data) = @_;
                                        ...
                                }
        );
$query->sign_tsig( $tsig );

La réponse à une requête entrante est signée à l'aide de l'enregistrement TSIG précédemment spécifié.

envoyant la requête à la place du paramètre de clé.

$response = $request->reply;
$response->sign_tsig( $request, @options );

Les transactions multi-paquets sont signées en chaînant les appels sign_tsig() comme suit :

$opaque = $packet1->sign_tsig( 'Kexample.+165+13281.private' );
$opaque = $packet2->sign_tsig( $opaque );
$opaque = $packet3->sign_tsig( $opaque );

Les références d'objet intermédiaires opaques retournées lors de la signature multi-paquets ne sont pas destinées à être accessibles par l'application de l'utilisateur final. Tout accès de ce type est expressément interdit.

Notez qu'un enregistrement TSIG est ajouté à chaque paquet ; cette implémentation ne prend pas en charge le schéma de signature supprimé décrit dans la RFC2845.

verify et verifyerr

$reply->verify($query) || die $reply->verifyerr;

Vérifie la signature TSIG d'une réponse à la requête correspondante.

$opaque  = $packet1->verify( $query ) || die $packet1->verifyerr;
$opaque  = $packet2->verify( $opaque );
$verifed = $packet3->verify( $opaque ) || die $packet3->verifyerr;

Vérifie la signature TSIG d'une réponse multi-paquets à la requête correspondante.

Les références d'objet intermédiaires opaques retournées par verify() à chaque étape seront indéfinies (Booléen faux) si la vérification échoue. Il n'est pas nécessaire de tester à chaque étape, ce qui produit une erreur BADSIG sur le paquet final en l'absence d'informations plus spécifiques. L'accès aux objets eux-mêmes, s'ils existent, est expressément interdit.

sign_sig0

La prise en charge de SIG0 est fournie par la classe Net::DNS::RR::SIG. Les composants cryptographiques requis ne sont pas intégrés dans Net::DNS mais résident dans la distribution Net::DNS::SEC disponible sur CPAN.

$update = Net::DNS::Update->new('example.com');
$update->push( update => rr_add('foo.example.com A 10.1.2.3'));
$update->sign_sig0('Kexample.com+003+25317.private');

L'exécution sera terminée si Net::DNS::SEC n'est pas disponible.

verify SIG0

$packet->verify( $keyrr )               || die $packet->verifyerr;
$packet->verify( [$keyrr, ...] )        || die $packet->verifyerr;

Vérifie la signature du paquet SIG0 par rapport à un ou plusieurs enregistrements KEY spécifiés.

sigrr

$sigrr = $packet->sigrr() || die 'unsigned packet';

La méthode sigrr renvoie l'enregistrement de signature d'un paquet signé ou indéfini si la signature est absente.

truncate

La méthode truncate prend une longueur maximale comme argument, puis tente de tronquer le paquet et de définir le bit TC conformément aux règles de la section 9 de la RFC2181.

La plus petite limite de longueur honorée est de 512 octets.
