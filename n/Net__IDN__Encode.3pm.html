NOM

Net::IDN::Encode - Internationalizing Domain Names in Applications (IDNA)

SYNOPSIS

use Net::IDN::Encode ':all';
my $a = domain_to_ascii("müller.example.org");
my $e = email_to_ascii("POSTMASTER@例。テスト");
my $u = domain_to_unicode('EXAMPLE.XN--11B5BS3A9AJ6G');

DESCRIPTION

Ce module fournit une interface facile à utiliser pour l'encodage et le décodage des noms de domaine internationalisés (IDN).

Les IDN utilisent des caractères provenant d'un large répertoire (Unicode), mais l'IDNA permet de représenter les caractères non ASCII en utilisant uniquement les caractères ASCII déjà autorisés dans les soi-disant noms d'hôtes aujourd'hui (lettre-chiffre-tiret, "/[A-Z0-9-]/i").

Utilisez ce module si vous souhaitez simplement convertir des noms de domaine (ou des adresses e-mail), en utilisant la norme IDNA qui convient le mieux pour le moment.

Vous devez être familier avec le support Unicode dans Perl, car ce module attend une entrée correctement encodée. Voir perlunitut, perluniintro et perlunicode pour plus de détails.

VERSION UNICODE

Pour convertir correctement les étiquettes entre Unicode et ASCII, chaque caractère de l'étiquette doit être présent dans la version Unicode supportée par votre Perl. Par conséquent, ce module refusera de convertir les étiquettes avec de nouveaux caractères Unicode sur les anciennes versions de Perl (voir ci-dessous).

FONCTIONS

Par défaut, ce module n'exporte aucune sous-routine. Vous pouvez utiliser le tag ":all" pour tout importer. Vous pouvez également utiliser des expressions régulières telles que "/^to_/" ou "/^email_/" pour sélectionner certaines fonctions, voir Exporter pour plus de détails.

Les fonctions suivantes sont disponibles :

to_ascii( $label, %param )
Convertit une seule étiquette $label en ASCII. Lèvera une exception en cas d'entrée invalide. Si $label est déjà une étiquette de domaine ASCII valide (y compris la plupart des étiquettes NON-LDH comme celles utilisées pour les enregistrements SRV et les fausses étiquettes A), cette fonction ne générera jamais d'erreur mais retournera $label tel quel si la conversion échoue.

Cette fonction accepte les paramètres optionnels suivants (%param) :

AllowUnassigned
(booléen) Si défini à une valeur vraie, les points de code non assignés dans la version Unicode supportée par votre Perl sont autorisés. C'est une extension de UTS #46.

Bien que cela augmente le nombre d'étiquettes qui peuvent être converties avec succès (en particulier sur les anciennes versions de Perl) et maximise ainsi la compatibilité avec les noms de domaine créés sous les futures versions d'Unicode, cela introduit également le risque de conversions incorrectes. Les caractères ajoutés dans les versions ultérieures d'Unicode pourraient avoir des propriétés qui affectent la conversion ; s'ils ne sont pas connus sur votre version de Perl, vous pourriez donc vous retrouver avec une conversion incorrecte.

La valeur par défaut est false.

UseSTD3ASCIIRules
(booléen) Si défini à une valeur vraie, vérifie la conformité de l'étiquette avec la syntaxe STD 3 (RFC 1123) pour les parties du nom d'hôte. Les vérifications exactes effectuées dépendent de la norme IDNA utilisée. Habituellement, vous voudrez définir cela sur true.

Veuillez noter que UseSTD3ASCIIRules n'affecte que la conversion entre les étiquettes ASCII (étiquettes A) et les étiquettes Unicode (étiquettes U). Les étiquettes qui sont en ASCII peuvent toujours être transmises telles quelles.

Pour des raisons historiques, la valeur par défaut est false (contrairement à "domain_to_ascii").

TransitionalProcessing
(booléen) Si défini à true, la conversion sera compatible avec IDNA2003. Cela n'affecte que quatre caractères : 'ß' (U+00DF), 'ς' (U+03C2), ZWJ (U+200D) et ZWNJ (U+200C). Habituellement, vous voudrez définir cela sur false.

La valeur par défaut est false.

Cette fonction ne gère pas les chaînes qui consistent en plusieurs étiquettes (comme les noms de domaine). Utilisez plutôt "domain_to_ascii".

to_unicode( $label, %param )
Convertit une seule étiquette $label en Unicode. Lèvera une exception en cas d'entrée invalide. Si $label est une étiquette ASCII (y compris la plupart des étiquettes NON-LDH comme celles utilisées pour les enregistrements SRV), cette fonction ne générera pas d'erreur mais retournera $label tel quel si la conversion échoue.

Cette fonction accepte les mêmes paramètres optionnels que "to_ascii", avec les mêmes valeurs par défaut.

Si $label est déjà en ASCII, cette fonction ne générera jamais d'erreur mais retournera $label tel quel en dernier recours (c'est-à-dire transmission sans modification).

Cette fonction accepte les paramètres optionnels suivants (%param) :

AllowUnassigned
UseSTD3ASCIIRules
Voir "to_unicode" ci-dessus. Veuillez noter qu'il n'y a pas besoin de "TransitionalProcessing" pour "to_unicode".

Cette fonction ne gère pas les chaînes qui consistent en plusieurs étiquettes (comme les noms de domaine). Utilisez plutôt "domain_to_unicode".

domain_to_ascii( $label, %param )
Convertit toutes les étiquettes du nom d'hôte $domain (avec les étiquettes séparées par des points) en ASCII (en utilisant "to_ascii"). Lèvera une exception en cas d'entrée invalide.

Cette fonction accepte les paramètres optionnels suivants (%param) :

AllowUnassigned
TransitionalProcessing
Voir "to_unicode" ci-dessus.
UseSTD3ASCIIRules
(booléen) Si défini à une valeur vraie, vérifie la conformité de l'étiquette avec la syntaxe STD 3 (RFC 1123) pour les parties du nom d'hôte.

La valeur par défaut est true (contrairement à "to_ascii").

Cette fonction convertira tous les points en ASCII, c'est-à-dire en U+002E (point). Les caractères suivants sont reconnus comme des points : U+002E (point), U+3002 (point idéographique), U+FF0E (point pleine chasse), U+FF61 (point idéographique demi-chasse).

domain_to_unicode( $domain, %param )
Convertit toutes les étiquettes du nom d'hôte $domain (avec les étiquettes séparées par des points) en Unicode. Lèvera une exception en cas d'entrée invalide.

Cette fonction accepte les mêmes paramètres optionnels que "domain_to_ascii", avec les mêmes valeurs par défaut.

Cette fonction accepte les paramètres optionnels suivants (%param) :

AllowUnassigned
UseSTD3ASCIIRules
Voir "domain_to_unicode" ci-dessus. Veuillez noter qu'il n'y a pas de "TransitionalProcessing" pour "domain_to_unicode".

Cette fonction conservera la version originale des points. Les caractères suivants sont reconnus comme des points : U+002E (point), U+3002 (point idéographique), U+FF0E (point pleine chasse) et U+FF61 (point idéographique demi-chasse).

email_to_ascii( $email, %param )
Convertit la partie domaine (côté droit, séparée par un signe @) d'une adresse e-mail RFC 2821/2822 en ASCII, en utilisant "domain_to_ascii". Peut lever une exception en cas d'entrée invalide.

Prend les mêmes paramètres que "domain_to_ascii".

Cette fonction ne gère actuellement pas l'internationalisation de la partie locale (côté gauche). Les futures versions de ce module pourraient implémenter une conversion en ASCII pour la partie locale, si une telle norme venait à être standardisée.

Cette fonction convertira le signe @ en ASCII, c'est-à-dire en U+0040 (arobase), ainsi que les séparateurs d'étiquettes. Les caractères suivants sont reconnus comme des signes @ : U+0040 (arobase), U+FE6B (petite arobase) et U+FF20 (arobase pleine chasse).

email_to_unicode( $email, %param )
Convertit la partie domaine (côté droit, séparée par un signe @) d'une adresse e-mail RFC 2821/2822 en Unicode, en utilisant "domain_to_unicode". Peut lever une exception en cas d'entrée invalide.

Prend les mêmes paramètres que "domain_to_unicode".

Cette fonction ne gère actuellement pas l'internationalisation de la partie locale (côté gauche). Les futures versions de ce module pourraient implémenter une conversion depuis l'ASCII pour la partie locale, si une telle norme venait à être standardisée.

Cette fonction conservera la version originale des signes @ (et des séparateurs d'étiquettes). Les caractères suivants sont reconnus comme des signes @ : U+0040 (arobase), U+FE6B (petite arobase) et U+FF20 (arobase pleine chasse).
