NOM

NetAddr::IP::Lite - Gestion des adresses et sous-réseaux IPv4 et IPv6

SYNOPIS

use NetAddr::IP::Lite qw(
      Zeros
      Ones
      V4mask
      V4net
      :aton           OBSOLÈTE !
      :old_nth
      :upper
      :lower
      :nofqdn
);
my $ip = new NetAddr::IP::Lite '127.0.0.1';
      ou si vous préférez
my $ip = NetAddr::IP::Lite->new('127.0.0.1);
      ou à partir d'une adresse IPv4 packée
my $ip = new_from_aton NetAddr::IP::Lite (inet_aton('127.0.0.1'));
      ou à partir d'une adresse IPv4 octale filtrée
my $ip = new_no NetAddr::IP::Lite '127.012.0.0';
print "L'adresse est ", $ip->addr, " avec le masque ", $ip->mask, "\n" ;
if ($ip->within(new NetAddr::IP::Lite "127.0.0.0", "255.0.0.0")) {
    print "C'est une adresse de boucle locale\n";
}
                              # Ceci imprime 127.0.0.1/32
print "Vous pouvez aussi dire $ip...\n";
Les quatre fonctions suivantes retournent des représentations IPv6 de :
::                                       = Zeros();
FFFF:FFFF:FFFF:FFFF:FFFF:FFFF:FFFF:FFFF  = Ones();
FFFF:FFFF:FFFF:FFFF:FFFF:FFFF::          = V4mask();
::FFFF:FFFF                              = V4net();
Elle retourne aussi une représentation IPv4 ou IPv6 d'un nom de domaine complet (FQDN) résoluble.

INSTALLATION

Décompressez la distribution dans un répertoire approprié et exécutez :

perl Makefile.PL
make
make test
make install

NetAddr::IP::Lite dépend de NetAddr::IP::Util, qui est installé par défaut avec ses fonctions principales compilées à l'aide d'extensions de langage C de Perl. Si vous n'avez pas de compilateur C disponible ou si vous voulez la version la plus lente de Perl pour d'autres raisons, alors exécutez :

perl Makefile.PL -noxs
make
make test
make install

DESCRIPTION

Ce module fournit une abstraction orientée objet sur les adresses ou sous-réseaux IP, permettant des manipulations aisées. La plupart des opérations de NetAddr::IP sont prises en charge. Ce module fonctionnera avec les anciennes versions de Perl et sera compatible avec Math::BigInt.

* Par défaut, NetAddr::IP fonctionne et les méthodes d'objets retournent les adresses IPv6 en majuscules. Pour passer en minuscules :

REMARQUE : Le RFC5952 d'août 2010 stipule :

4.3. Majuscules
  Les lettres « a », « b », « c », « d », « e » et « f » dans une adresse IPv6
  doivent être représentées en minuscules.

Il est recommandé que les nouvelles applications utilisant NetAddr::IP::Lite soient invoquées comme indiqué dans la ligne suivante :

use NetAddr::IP::Lite qw(:lower);

* Pour garantir le comportement de chaînage d'IPv6 en majuscules même si la valeur par défaut change :

use NetAddr::IP::Lite qw(:upper);

La représentation interne de tous les objets IP est en notation IPv6 de 128 bits. Les adresses IPv4 et IPv6 peuvent être mélangées librement.

Les opérations prises en charge sont décrites ci-dessous :

Opérateurs surchargés

Assignation (« = »)
A été optimisée pour copier très rapidement un objet NetAddr::IP::Lite à un autre.
« ->copy() »
L'opérateur d'affectation (« = ») s'exécute uniquement lorsque l'objet copié est muté par une autre opération surchargée. Voir À PROPOS DES SYMBOLES D'AFFECTATION DANS UTILISATION DE OVERLOAD pour plus de détails.

« ->copy() » crée un nouvel objet lorsqu'il est appelé.

Stringification
Un objet peut être utilisé comme une chaîne de caractères. Par exemple, le code suivant :

my $ip = new NetAddr::IP::Lite '192.168.1.123';
print "$ip\n";

Imprime la chaîne 192.168.1.123/32.

my $ip = new6 NetAddr::IP::Lite '192.168.1.123';
print "$ip\n";

Imprime la chaîne 0:0:0:0:0:0:C0A8:17B/128

Égalité
Vous pouvez comparer avec « eq », « ne », « == » ou « != ». « eq », « ne » permet de comparer avec des chaînes arbitraires et des objets NetAddr::IP::Lite. L'exemple suivant :

if (NetAddr::IP::Lite->new('127.0.0.1','255.0.0.0') eq '127.0.0.1/8')
   { print "Oui\n"; }

Imprime « Oui ».

Les comparaisons avec « == » et « != » nécessitent que les deux opérandes soient des objets NetAddr::IP::Lite.

Comparaison
En interne, tous les objets réseau sont représentés en notation de 128 bits. La représentation numérique du réseau est comparée à l'aide de l'opération correspondante. Les comparaisons tentent d'abord la partie adresse de l'objet et, si celle-ci est égale, comparent la partie numérique des masques. Cela conduit à un résultat contre-intuitif, tel que :

/24 > /16

Vous ne devriez pas comparer avec des objets réseau ayant des CIDR différents, car cela pourrait produire des résultats indéterminés ou inattendus. Il est préférable de comparer :

$ip1->masklen <=> $ip2->masklen
Addition d'une valeur constante (« + »)
Ajoute une valeur entière de 32 bits à la partie adresse d'un objet NetAddr. Cette opération modifie la partie adresse afin qu'elle corresponde à l'adresse des hôtes commençant après l'adresse actuelle. Par exemple, ce code :

print NetAddr::IP::Lite->new('127.0.0.1/8') + 5;

imprime 127.0.0.6/8. L'adresse sera doublée pour le broadcast vers l'adresse réseau. Ce code :

print NetAddr::IP::Lite->new('10.0.0.1/24') + 255;

imprime 10.0.0.0/24.

Retourne l'objet inchangé si la valeur est absente ou hors de portée.

2147483647 <= constante >= -2147483648
Soustraction d'une valeur constante (« - »)
Le complément de l'addition d'une valeur constante.
Différence (« - »)
Retourne la différence entre les parties adresses des objets NetAddr::IP::Lite sous forme d'entier 32 bits.

Retourne undef si la différence est hors de portée.

Auto-incrémentation
L'auto-incrémentation d'un objet NetAddr::IP::Lite provoque l'ajustement de la partie adresse à la prochaine adresse d'hôte dans le sous-réseau. Elle doublera pour l'adresse de broadcast et recommencera à partir de l'adresse réseau.
Auto-décrémentation
L'auto-décrémentation d'un objet NetAddr::IP::Lite effectue exactement l'inverse de l'auto-incrémentation, comme prévu.

Méthodes

"->new([$addr, [ $mask|IPv6 ]])"
"->new6([$addr, [ $mask]])"
"->new6FFFF([$addr, [ $mask]])"
"->new_no([$addr, [ $mask]])"
"->new_from_aton($netaddr)"
new_cis et new_cis6 sont OBSOLÈTES
"->new_cis("$addr $mask)"
"->new_cis6("$addr $mask)"
Les trois premières méthodes créent une nouvelle adresse avec l'adresse fournie dans $addr et un masque optionnel $mask, qui peut être omis pour obtenir un masque de /32 ou /128 pour les adresses IPv4 ou IPv6 respectivement.

new6FFFF retourne une adresse IPv4 au format IPv6 selon le RFC4291

new6               ::xxxx:xxxx
new6FFFF      ::FFFF:xxxx:xxxx

La troisième méthode "new_no" est exclusivement pour les adresses IPv4 et filtre les chaînes de points-en-carré mal formatées pour les zéros initiaux qui sont normalement interprétés comme un format octal par NetAddr selon les spécifications de inet_aton.

new_from_aton prend une adresse IPv4 packée et suppose un masque /32. Cette fonction remplace la DEPRECATED :aton qui est fondamentalement mal implémentée.

Les deux dernières méthodes new_cis et new_cis6 diffèrent de new et new6 seulement en ce qu'elles acceptent la notation Cisco d'adresses/masques avec un espace comme séparateur au lieu d'un slash (/).

Ces méthodes sont DEPRECATED car la fonctionnalité est maintenant incluse dans les autres méthodes "new".

c'est-à-dire  ->new_cis('1.2.3.0 24')
      ou
      ->new_cis6('::1.2.3.0 120')

"->new6" et "->new_cis6" marquent l'adresse comme appartenant à l'espace d'adressage IPv6 même si le format suggère le contraire.

c'est-à-dire  ->new6('1.2.3.4') résultera en ::102:304
les adresses envoyées à ->new en notation IPv6 resteront dans cette notation de façon permanente. c'est-à-dire
      ->new('::1.2.3.4') résultera en ::102:304
alors que new('1.2.3.4') sera imprimé sous la forme 1.2.3.4
Voir "STRINGIFICATION" ci-dessous.

$addr peut être presque n'importe quoi qui peut être résolu en une adresse IP dans toutes les notations que j'ai vues. Il peut contenir optionnellement le masque en notation CIDR. Si le module Perl OPCIONAL Socket6 est disponible dans la bibliothèque locale, il sera auto-détecté et les noms d'hôtes IPv6 ainsi que les noms IPv4 seront résolus.

La notation de préfixe est comprise, avec la limitation que la plage spécifiée par le préfixe doit correspondre à un sous-réseau valide.

Les adresses dans la même notation retournée par "inet_aton" ou "gethostbyname" peuvent également être comprises, même si un masque ne peut pas être spécifié. La valeur par défaut est de ne pas essayer de reconnaître cette notation, car elle semble rarement utilisée.

"->broadcast()"
Retourne un nouvel objet faisant référence à l'adresse de diffusion d'un sous-réseau. L'adresse de diffusion a tous les bits à 1 dans les positions où le masque a des 0. Ceci est normalement utilisé pour s'adresser à tous les nœuds d'un sous-réseau.
"->network()"
Retourne un nouvel objet faisant référence à l'adresse réseau d'un sous-réseau. Une adresse réseau a tous les bits à 0 où les bits du masque sont à 0. Elle est normalement utilisée pour faire référence à un sous-réseau.
"->addr()"
Retourne un scalaire avec la partie adresse de l'objet sous forme de chaîne texte IPv4 ou IPv6 correspondante. Il est utile pour imprimer ou passer la partie adresse de l'objet NetAddr::IP::Lite à d'autres composants qui attendent une adresse IP. Si l'objet est une adresse IPv6 ou a été créé en utilisant ->new6($ip), il sera rapporté au format hexadécimal IPv6, sinon seulement au format points-en-carré s'il réside dans l'espace d'adressage IPv4.
"->mask()"
Retourne un scalaire avec le masque sous forme de chaîne texte IPv4 ou IPv6 correspondante.
"->masklen()"
Retourne un scalaire avec le nombre de bits du masque.
"->bits()"
Retourne la largeur en bits de l'adresse. Normalement 32 pour IPv4 et 128 pour IPv6.
"->version()"
Retourne la version de l'adresse ou du sous-réseau. Actuellement, cela peut être 4 ou 6.
"->cidr()"
Retourne un scalaire avec l'adresse et le masque en notation CIDR. Un objet NetAddr::IP::Lite se *stringifie* au résultat de cette méthode. (voir commentaires sur ->new6() et ->addr() pour les formats de sortie)
"->aton()"
Retourne la partie adresse de l'objet NetAddr::IP::Lite dans le même format que la fonction inet_aton() ou "ipv6_aton" respectivement. Si l'objet a été créé en utilisant ->new6($ip), l'adresse retournée sera toujours au format IPv6, même pour les adresses dans l'espace d'adressage IPv4.
"->range()"
Retourne un scalaire avec l'adresse de base et l'adresse de diffusion séparées par un tiret et des espaces. Ceci est appelé notation de plage.
"->numeric()"
Lorsqu'il est appelé dans un contexte scalaire, retourne une représentation numérique de la partie adresse IP. Lorsqu'il est appelé dans un contexte de tableau, retourne une liste de deux éléments. Le premier élément est tel que décrit, le second élément est la représentation numérique du masque de réseau.
Cette méthode est essentielle pour sérialiser la représentation d'un sous-réseau.
"->bigint()"
Lorsqu'il est appelé dans un contexte scalaire, retourne une représentation Math::BigInt de la partie adresse IP. Lorsqu'il est appelé dans un contexte de tableau, retourne une liste de deux éléments. Le premier élément est tel que décrit, le second élément est la représentation Math::BigInt du masque de réseau.
"$me->contains($other)"
Retourne vrai lorsque $me contient complètement $other. Faux est retourné sinon et "undef" est retourné si $me et $other ne sont pas tous deux des objets de type "NetAddr::IP::Lite".
"$me->within($other)"
Le complément de "->contains()". Retourne vrai lorsque $me est complètement contenu dans $other, undef si $me et $other ne sont pas tous deux des objets de type "NetAddr::IP::Lite".
C->is_rfc1918()>
Retourne vrai lorsque $me est une adresse RFC 1918. Les adresses suivantes sont valides :
10.0.0.0        -   10.255.255.255  (10/8 prefix)
172.16.0.0      -   172.31.255.255  (172.16/12 prefix)
192.168.0.0     -   192.168.255.255 (192.168/16 prefix)
Vrai lorsque $me est une adresse locale.
c'est-à-dire    ipV4    127.0.0.0 - 127.255.255.255
ou           ipV6    === ::1
Retourne un nouvel objet représentant l'adresse la plus utilisable dans le sous-réseau (c'est-à-dire, l'adresse hôte la plus basse).
Retourne un nouvel objet représentant l'adresse la plus utilisable dans le sous-réseau (c'est-à-dire, une adresse hôte plus basse).

La version 4.00 de NetAddr::IP et la version 1.00 de NetAddr::IP::Lite implémentent "->nth($index)" et "->num()" exactement comme la documentation l'indique. Les versions antérieures se comportaient différemment et de manière incohérente.
Pour utiliser l'ancien comportement de "->nth($index)" et "->num()" :
use NetAddr::IP::Lite qw(:old_nth);
ancien comportement :
NetAddr::IP->new('10/32')->nth(0) == undef
NetAddr::IP->new('10/32')->nth(1) == undef
NetAddr::IP->new('10/31')->nth(0) == undef
NetAddr::IP->new('10/31')->nth(1) == 10.0.0.1/31
NetAddr::IP->new('10/30')->nth(0) == undef
NetAddr::IP->new('10/30')->nth(1) == 10.0.0.1/30
NetAddr::IP->new('10/30')->nth(2) == 10.0.0.2/30
NetAddr::IP->new('10/30')->nth(3) == 10.0.0.3/30
Notez que dans chaque cas, l'adresse de diffusion est représentée dans l'ensemble de sortie et que l'index 0 est toujours undef, sauf pour un /31 ou /127 point à point où il y a exactement deux adresses dans le réseau.
nouveau comportement :
NetAddr::IP->new('10/32')->nth(0)  == 10.0.0.0/32
NetAddr::IP->new('10.1/32'->nth(0) == 10.0.0.1/32
NetAddr::IP->new('10/31')->nth(0)  == 10.0.0.0/32
NetAddr::IP->new('10/31')->nth(1)  == 10.0.0.1/32
NetAddr::IP->new('10/30')->nth(0) == 10.0.0.1/30
NetAddr::IP->new('10/30')->nth(1) == 10.0.0.2/30
NetAddr::IP->new('10/30')->nth(2) == undef
Notez qu'un réseau /32 a toujours 1 adresse utile tandis qu'un /31 a exactement deux adresses utiles pour les adresses point à point. L'index 0 (0) retourne l'adresse immédiatement suivante à l'adresse réseau, sauf pour un /31 ou /127 où il retourne l'adresse réseau.
Vrai lorsque l'index 0 retourne l'adresse immédiatement suivante à l'adresse réseau, sauf pour un /31 ou /127 où il retourne l'adresse réseau.
La version 4.00 de NetAddr::IP et la version 1.00 de NetAddr::IP::Lite retournent le nombre d'adresses utiles dans le sous-réseau, sans compter l'adresse de diffusion ou l'adresse réseau.
Les anciennes versions ne fonctionnaient que pour les adresses IPv4.
