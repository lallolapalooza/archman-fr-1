NOM

Net::LDAP::Control - classe de base pour les objets de contrôle LDAPv3

SYNOPIS

use Net::LDAP::Control;
use Net::LDAP::Constant qw( LDAP_CONTROL_MANAGEDSAIT );
my $req_ctrl1 = Net::LDAP::Control->new( type => LDAP_CONTROL_MANAGEDSAIT );
my $req_ctrl2 = Net::LDAP::Control->new(
  type     => "1.2.3.4",
  value    => "help",
  critical => 0
);
$mesg = $ldap->search( @args, control => [ $req_ctrl1, $req_ctrl2 ]);
my @res_ctrls = $mesg->control();

DESCRIPTION

"Net::LDAP::Control" est la classe de base pour les objets de contrôle LDAPv3.

Les contrôles fournissent un mécanisme qui permet d'étendre la signification et les arguments des opérations LDAP. Les contrôles peuvent être joints aux opérations LDAP et n'affectent que la signification de l'opération à laquelle ils sont joints.

Les contrôles envoyés par les clients sont appelés contrôles de requête, et sont définis en utilisant l'option "control" des opérations LDAP correspondantes. Les contrôles envoyés par les serveurs sont appelés contrôles de réponse, et peuvent être trouvés en utilisant la méthode control() des objets de message de réponse.

Les serveurs annoncent les contrôles qu'ils supportent dans la propriété "supportedControls" de leur RootDSE.

CONSTRUCTEURS

new ( ARGS )
ARGS est une liste de paires clé-valeur valides, où :
critical
Une valeur booléenne, si elle est VRAIE et que le contrôle n'est pas reconnu par le serveur ou n'est pas approprié pour l'opération demandée, le serveur retournera une erreur et l'opération ne sera pas effectuée.

Si elle est FAUSSE et que le contrôle n'est pas reconnu par le serveur ou n'est pas approprié pour l'opération demandée, le serveur ignorera le contrôle et effectuera l'opération demandée comme si le contrôle n'avait pas été donné.

Si elle est absente, elle est supposée FAUSSE.

type
Une représentation décimale pointée d'un IDENTIFIANT D'OBJET (OBJECT IDENTIFIER) qui identifie de manière unique le contrôle. Ceci évite les conflits entre les noms de contrôle.

Ceci peut être omis si le constructeur est appelé dans une sous-classe de Net::LDAP::Control qui s'est enregistrée pour être associée à un OID. Si le constructeur est appelé dans la classe Net::LDAP::Control, alors cet argument doit être fourni. Si l'OID donné a été enregistré par une classe, l'objet retourné sera du type enregistré pour gérer cet OID.

value
Informations facultatives associées au contrôle. Son format est spécifique au contrôle donné.
from_asn ( ASN )
ASN est une référence à un HASH, typiquement extrait d'un PDU. Il contient un élément "type" et facultativement "critical" et "value". À la fin, ASN est béni comme un objet de classe. Si "type" est un OID enregistré, alors ASN est béni dans la classe enregistrée, sinon, il est béni dans Net::LDAP::Control.

Ce constructeur est utilisé en interne par Net::LDAP et suppose que le HASH passé contient un contrôle valide. Il doit être utilisé avec précaution.

MÉTHODES

En plus des méthodes listées, chaque paramètre nommé lors de l'appel à "new" est également disponible comme méthode. "type" retournera l'OID de l'objet de contrôle. "value" et "critical" sont des méthodes de définition/obtention et retourneront la valeur actuelle de chaque attribut si aucun argument n'est passé, mais peuvent également être appelées avec des arguments pour définir de nouvelles valeurs.

error ()
S'il y a eu une erreur, renvoie une description de l'erreur, sinon renvoie "undef"
init ()
"init" est appelé comme dernière étape dans les deux constructeurs. Ce qu'il fait dépend de la sous-classe. Il doit toujours retourner l'objet.
register ( OID )
"register" est fourni aux implémenteurs de sous-classes. Il doit être appelé comme méthode de classe sur une sous-classe de Net::LDAP::Control avec l'OID que la classe gérera. Net::LDAP::Control se souvient de cette paire classe et OID et l'utilise dans les cas suivants.
  • "new" est appelé comme méthode de classe sur la classe Net::LDAP::Control et l'OID est passé comme argument. L'objet retourné est béni dans la classe qui a enregistré l'OID.
  • "new" est appelé comme méthode de classe sur une classe enregistrée et le "type" n'est pas spécifié. Le "type" sera défini sur l'OID enregistré par cette classe.
  • "from_asn" est appelé pour construire un objet à partir d'ASN. L'objet retourné est béni dans la classe qui a enregistré l'OID dans l'ASN.
( to_asn )
Retourne une structure appropriée pour être passée à Convert::ASN1 pour l'encodage. Cette méthode est appelée par Net::LDAP lorsque le contrôle est utilisé.

L'implémentation de base de la méthode appelle la méthode "value" sans arguments pour permettre à une sous-classe de coder sa valeur. Les sous-classes n'ont pas nécessairement besoin de surcharger cette méthode.

valid ()
Retourne vrai si l'objet est valide et peut être encodé. L'implémentation par défaut de cette méthode est de retourner VRAI s'il n'y a pas d'erreurs, mais les sous-classes peuvent la surcharger.
