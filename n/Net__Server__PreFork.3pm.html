Net::Server::PreFork(3) Documentation Perl fournie par l'utilisateur Net::Server::PreFork(3)

NOM

Net::Server::PreFork - Personnalité de Net::Server

SYNTAXE

use base qw(Net::Server::PreFork);
sub process_request {
    #...code...
}
__PACKAGE__->run();

DESCRIPTION

Veuillez lire d'abord la documentation pod de Net::Server et Net::Server::PreForkSimple. Ce module est une personnalité, ou une extension, ou une sous-classe de la classe Net::Server::PreForkSimple qui est une sous-classe de Net::Server. Voir Net::Server::PreForkSimple.

Cette personnalité se lie à un ou plusieurs ports, puis crée des processus enfants ("min_servers"). Le serveur s'assurera qu'à tout moment il y a "min_spare_servers" processus disponibles pour recevoir une requête client, jusqu'à un maximum de "max_servers". Chacun de ces enfants traitera jusqu'à "max_requests" connexions client. Ce type est bon pour un site très fréquenté et devrait bien évoluer pour la plupart des applications. (L'acceptation de plusieurs ports est réalisée en utilisant flock pour sérialiser les enfants).

À l'heure actuelle, il semble que ce module ne passera pas les tests sur les systèmes Win32. Toutes idées ou correctifs pour faire passer les tests seraient les bienvenus.

EXEMPLE DE CODE

Veuillez voir l'exemple listé dans Net::Server.

ARGUMENTS EN LIGNE DE COMMANDE

En plus des arguments en ligne de commande des classes de base Net::Server et Net::Server::PreForkSimple, Net::Server::PreFork contient plusieurs autres paramètres configurables. Vous devriez également consulter Net::Server::PreForkSimple.

Clé                 Valeur                  Défaut
min_servers         \d+                     5
min_spare_servers   \d+                     2
max_spare_servers   \d+                     10
max_servers         \d+                     50
max_requests        \d+                     1000
serialize           (flock|semaphore
                     |pipe|none)            undef
# serialize par défaut est flock sur multi_port ou sur Solaris
lock_file           "nom_de_fichier"              File::Temp->new
check_for_dead      \d+                     30
check_for_waiting   \d+                     10
max_dequeue         \d+                     undef
check_for_dequeue   \d+                     undef
child_communication 1                       undef
min_servers
Nombre minimum de serveurs à maintenir en fonctionnement.
min_spare_servers
Nombre minimum de serveurs à avoir en attente de requêtes. Les nombres minimum et maximum ne doivent pas être trop proches, sinon le serveur créera et tuera des enfants trop souvent.
max_spare_servers
Nombre maximum de serveurs à avoir en attente de requêtes. Voir min_spare_servers.
max_servers
Nombre maximum de serveurs enfants à démarrer. Cela ne s'applique pas aux processus de défilement.
check_for_waiting
Secondes à attendre avant de vérifier si nous pouvons supprimer des serveurs en attente.
check_for_spawn
Secondes entre les vérifications pour voir si nous devons démarrer plus d'enfants
min_child_ttl
Nombre minimum de secondes entre le démarrage d'enfants et la terminaison d'un processus enfant
child_communication
Active la communication enfant-parent via des sockets Unix. Si défini à vrai, permettra aux enfants d'écrire sur le socket contenu dans $self->{'server'}->{'parent_sock'}. Le parent sera notifié via child_is_talking_hook où le premier argument est le socket vers l'enfant. Le socket de l'enfant est stocké dans $self->{'server'}->{'children'}->{$child_pid}->{'sock'}.
serialize
Voir la documentation sous Net::Server::PreForkSimple.

FICHIER DE CONFIGURATION

"Net::Server::PreFork" permet d'utiliser un fichier de configuration pour lire les paramètres du serveur. Le format de ce fichier de configuration est simple : paires clé-valeur. Les commentaires et les espaces blancs sont ignorés.

#-------------- fichier test.conf --------------
### informations du serveur
min_servers   20
max_servers   80
min_spare_servers 10
min_spare_servers 15
max_requests  1000
### utilisateur et groupe à devenir
user        quelqu'un
group       toutlemonde
### journalisation ?
log_file    /var/log/serveur.log
log_level   3
pid_file    /tmp/serveur.pid
### contrôle d'accès
allow       .+\.(net|com)
allow       domaine\.com
deny        a.+
### mettre le processus en arrière-plan ?
background  1
### ports à lier
host        127.0.0.1
port        localhost:20204
port        20205
### recherches inversées ?
# reverse_lookups on
### activer la communication enfant ?
# child_communication
#-------------- fichier test.conf --------------

FLUX DE PROCESSUS

Le flux de processus suit Net::Server jusqu'à la phase de boucle. À ce stade, "min_servers" sont créés et attendent les connexions. Lorsqu'un enfant accepte une connexion, termine le traitement d'un client ou se termine, il transmet cette information au parent, qui la suit et s'assure qu'il y a suffisamment d'enfants pour satisfaire "min_servers", "min_spare_servers", "max_spare_servers" et "max_servers".

HOOKS

Le serveur PreFork a les hooks suivants en plus des hooks fournis par PreForkSimple. Voir Net::Server::PreForkSimple.

"$self->run_n_children_hook()"
Ce hook se produit en haut de run_n_children, qui est appelé chaque fois que le serveur est sur le point de démarrer des processus enfants supplémentaires. Cela donne au parent la possibilité de faire sa propre comptabilité (selon le besoin). L'idée de ce hook vient de James FitzGibbon.
"$self->parent_read_hook()"
Ce hook se produit chaque fois que le parent lit des informations de l'enfant. La ligne de l'enfant est envoyée comme argument.
"$self->child_is_talking_hook()"
Ce hook se produit si child_communication est vrai et que l'enfant a écrit dans $self->{'server'}->{'parent_sock'}. Le premier argument sera le socket ouvert vers l'enfant.
"$self->idle_loop_hook()"
Ce hook est appelé à chaque passage dans la boucle d'attente du processus principal, toutes les "check_for_waiting" secondes. Le premier argument est une référence à un tableau de descripteurs de fichiers qui peuvent être lus à ce moment-là.
"$self->cleanup_dead_child_hook( $child )"
Ce hook est appelé lorsqu'un enfant mort est détecté. Un enfant est considéré comme mort lorsque le pid n'existe plus. Ce hook pourrait être utilisé pour nettoyer d'éventuels fichiers temporaires ou verrous laissés par un enfant mort.

DÉPLOIEMENT À CHAUD

Depuis la version 2.000, le serveur PreFork accepte les signaux TTIN et TTOU. Lorsqu'un TTIN est reçu, min et max_servers sont augmentés de 1. Si un TTOU est reçu, min et max_servers sont diminués de 1. Cela permet d'ajuster le nombre de processus de traitement sans avoir à redémarrer le serveur.

BOGUES

Les tests ne semblent pas fonctionner sous Win32. Toutes idées ou correctifs seraient les bienvenus.
