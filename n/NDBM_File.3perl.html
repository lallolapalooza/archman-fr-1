NOM

NDBM_File - Accès lié aux fichiers ndbm

SYNOPSIS

use Fcntl;   # Pour O_RDWR, O_CREAT, etc.
use NDBM_File;
tie(%h, 'NDBM_File', 'nom_fichier', O_RDWR|O_CREAT, 0666)
  or die "Impossible de lier le fichier NDBM 'nom_fichier' : $!; abandon";
# Maintenant, lire et modifier le hachage
$h{nouvelle_cle} = nouvelle_valeur;
print $h{ancienne_cle};
...
untie %h;

DESCRIPTION

"NDBM_File" établit une connexion entre une variable de hachage Perl et un fichier au format NDBM_File. Vous pouvez manipuler les données du fichier comme s'il s'agissait d'un hachage Perl, mais lorsque votre programme se termine, les données resteront dans le fichier, prêtes à être utilisées la prochaine fois que votre programme s'exécutera.

Utilisez "NDBM_File" avec la fonction intégrée Perl "tie" pour établir la connexion entre la variable et le fichier. Les arguments de "tie" doivent être :

1.
La variable de hachage que vous souhaitez lier.
2.
La chaîne "NDBM_File". (Cela indique à Perl d'utiliser le package "NDBM_File" pour effectuer les fonctions du hachage.)
3.
Le nom du fichier auquel vous souhaitez lier le hachage.
4.
Les indicateurs (flags). Utilisez l'un des suivants :
"O_RDONLY"
Accès en lecture seule aux données du fichier.
"O_WRONLY"
Accès en écriture seule aux données du fichier.
"O_RDWR"
Accès en lecture et écriture.

Si vous souhaitez créer le fichier s'il n'existe pas, ajoutez "O_CREAT" à l'un de ceux-ci, comme dans l'exemple. Si vous omettez "O_CREAT" et que le fichier n'existe pas encore, l'appel "tie" échouera.

5.
Les permissions par défaut à utiliser si un nouveau fichier est créé. Les permissions réelles seront modifiées par l'umask de l'utilisateur, vous devriez donc probablement utiliser 0666 ici. (Voir "umask" dans perlfunc.)

DIAGNOSTICS

En cas d'échec, l'appel "tie" renvoie une valeur indéfinie et définit probablement $! pour contenir la raison pour laquelle le fichier n'a pas pu être lié.

"ndbm store returned -1, errno 22, key "..." at ..."

Cet avertissement est émis lorsque vous essayez de stocker une clé ou une valeur trop longue. Cela signifie que la modification n'a pas été enregistrée dans la base de données. Voir BUGS AND WARNINGS ci-dessous.

SÉCURITÉ ET PORTABILITÉ

N'acceptez pas de fichiers NDBM provenant de sources non fiables.

Sur les systèmes Linux modernes, il s'agit généralement de fichiers GDBM, qui ne sont pas portables entre les plateformes.

La documentation GDBM n'indique pas que les fichiers provenant de sources non fiables puissent être utilisés en toute sécurité avec "libgdbm".

Les systèmes qui n'utilisent pas la compatibilité GDBM pour le support ndbm utiliseront une bibliothèque spécifique à la plateforme, éventuellement héritée des systèmes BSD, où il peut être sûr ou non d'utiliser un fichier non fiable.

Un fichier malveillant pourrait faire planter perl, voire exposer une vulnérabilité de sécurité.

BUGS AND WARNINGS

Il existe un certain nombre de limites à la taille des données que vous pouvez stocker dans le fichier NDBM. La plus importante est que la longueur d'une clé, plus la longueur de sa valeur associée, ne peut pas dépasser 1008 octets.

Voir "tie" dans perlfunc, perldbmfilter, Fcntl
