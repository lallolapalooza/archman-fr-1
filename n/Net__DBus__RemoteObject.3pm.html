NOM

Net::DBus::RemoteObject - Accéder aux objets fournis sur le bus

SYNOPIS

my $service = $bus->get_service("org.freedesktop.DBus");
my $object = $service->get_object("/org/freedesktop/DBus");
print "Noms sur le bus {\n";
foreach my $name (sort @{$object->ListNames}) {
    print "  ", $name, "\n";
}
print "}\n";

DESCRIPTION

Ce module fournit l'API pour accéder aux objets distants disponibles sur le bus. Il utilise l'autoloader pour simuler la présence de méthodes basées sur l'API de l'objet distant. Il y a également un support pour définir des callbacks pour les signaux, et pour accéder aux propriétés de l'objet.

MÉTHODES

my $object = Net::DBus::RemoteObject->new($service, $object_path[, $interface], \%params);
Crée une nouvelle poignée vers un objet distant. Le paramètre $service est une instance de la méthode Net::DBus::RemoteService, et $object_path est l'identifiant d'un objet exporté par ce service, par exemple "/org/freedesktop/DBus". Pour les objets distants qui implémentent plus d'une interface, il est possible de spécifier un nom d'interface optionnel comme troisième paramètre. Ceci n'est réellement nécessaire, cependant, que si deux interfaces de l'objet fournissent des méthodes portant le même nom, car les données d'introspection peuvent être utilisées pour résoudre automatiquement la bonne interface à appeler dans les cas où les noms de méthodes sont uniques. Plutôt que d'utiliser ce constructeur directement, il est préférable d'utiliser la méthode "get_object" sur Net::DBus::RemoteService, car celle-ci met en cache les poignées des objets distants, éliminant les recherches de données d'introspection inutiles.

Le paramètre %params contient des paramètres de configuration supplémentaires pour l'objet. Actuellement, un seul paramètre est supporté, "timeout", qui prend une valeur en millisecondes à utiliser comme délai d'attente pour les appels de méthodes sur l'objet.

my $object = $object->as_interface($interface);
Convertit l'objet en une interface spécifique, retournant une nouvelle instance de Net::DBus::RemoteObject spécialisée pour l'interface souhaitée. Il n'est nécessaire de convertir les objets en une interface spécifique que si deux interfaces exportent des méthodes ou des signaux portant le même nom, ou si l'objet distant ne supporte pas l'introspection.
my $service = $object->get_service
Récupère une poignée pour le service distant auquel cet objet est attaché. L'objet retourné est une instance de Net::DBus::RemoteService
my $path = $object->get_object_path
Récupère l'identifiant de chemin unique pour cet objet au sein du service.
my $object = $object->get_child_object($subpath, [$interface])
Récupère une poignée vers un enfant de cet objet, identifié par le chemin relatif $subpath. L'objet retourné est une instance de "Net::DBus::RemoteObject". Le paramètre optionnel $interface peut être utilisé pour convertir immédiatement l'objet en un type spécifique.
my $sigid = $object->connect_to_signal($name, $coderef);
Connecte un callback à un signal émis par l'objet. Le paramètre $name est le nom du signal au sein de l'objet, et $coderef est une référence à une sous-routine anonyme. Lorsque le signal $name est émis par l'objet distant, la sous-routine $coderef sera invoquée et recevra les paramètres du signal. Un $sigid unique sera retourné, qui pourra plus tard être passé à "disconnect_from_signal" pour supprimer le gestionnaire.
$object->disconnect_from_signal($name, $sigid);
Se déconnecte d'un signal émis par l'objet. Le paramètre $name est le nom du signal au sein de l'objet. Le $sigid doit être l'identifiant unique du gestionnaire de signal retourné par un appel précédent à la méthode "connect_to_signal".
