NOM

Net::Config - Données de configuration locales pour libnet

SYNOPIS

use Net::Config qw(%NetConfig);

DESCRIPTION

"Net::Config" contient les données de configuration pour les modules de la distribution libnet. Lors de l'installation, il vous sera demandé ces valeurs.

Les données de configuration sont conservées globalement dans un fichier dans l'arborescence d'installation de perl, mais un utilisateur peut remplacer l'une de ces valeurs en fournissant les siennes. Cela peut être fait en ayant un fichier ".libnetrc" dans son répertoire personnel. Ce fichier doit retourner une référence à un HASH contenant les clés décrites ci-dessous. Par exemple

# .libnetrc
{
    nntp_hosts => [ "mon_hote_prefere" ],
    ph_hosts   => [ "mon_serveur_ph" ],
}
__END__

Méthodes de classe

"Net::Config" définit les méthodes suivantes. Ce sont des méthodes car elles sont invoquées comme des méthodes de classe. C'est parce que "Net::Config" hérite de "Net::LocalCfg" que vous pouvez remplacer ces méthodes si vous le souhaitez.

requiert_parefeu($hote)
Tente de déterminer si un hôte donné est à l'extérieur de votre pare-feu. Les valeurs de retour possibles sont : 
-1  Impossible de rechercher le nom d'hôte
 0  L'hôte est à l'intérieur du pare-feu (ou il n'y a pas d'entrée ftp_firewall)
 1  L'hôte est à l'extérieur du pare-feu

Ceci est fait en utilisant la recherche de nom d'hôte et l'entrée "local_netmask" dans les données de configuration.

Valeurs NetConfig

nntp_hosts

smtp_hosts
ph_hosts
daytime_hosts
time_hosts
Chacun est une référence à un tableau de noms d'hôtes (par ordre de préférence), qui devraient être utilisés pour le protocole donné
inet_domain
Votre nom de domaine internet
ftp_firewall
Si vous avez un pare-feu proxy FTP (PAS un pare-feu HTTP ou SOCKS) alors cette valeur doit être définie sur le nom d'hôte du pare-feu. Si votre pare-feu n'écoute pas sur le port 21, alors cette valeur doit être définie sur "nom_hote:port" (par ex. "nom_hote:99")
ftp_firewall_type
Il existe de nombreux produits de pare-feu FTP différents disponibles. Mais malheureusement, il n'y a pas de norme sur la façon de traverser un pare-feu. La liste ci-dessous montre la séquence de commandes que Net::FTP utilisera :

ftp_ext_passive
ftp_int_passive
Les serveurs FTP peuvent fonctionner en mode passif ou actif. Le mode actif est lorsque vous souhaitez transférer des données, vous devez dire au serveur l'adresse et le port auxquels se connecter. Le mode passif est lorsque le serveur fournit l'adresse et le port, et que vous établissez la connexion.

Avec certains pare-feux, le mode actif ne fonctionne pas car le serveur ne peut pas se connecter à votre machine (car vous êtes derrière un pare-feu) et le pare-feu ne réécrit pas la commande. Dans ce cas, vous devriez définir "ftp_ext_passive" sur une valeur *vraie*.

Certains serveurs sont configurés pour fonctionner uniquement en mode passif. Si vous en avez un, vous pouvez forcer "Net::FTP" à transférer toujours en mode passif ; lorsque vous ne passez pas par un pare-feu, en définissant "ftp_int_passive" sur une valeur *vraie*.

local_netmask
Une référence à une liste de chaînes de masque réseau sous la forme "134.99.4.0/24". Celles-ci sont utilisées par la fonction "requiert_firewall" pour déterminer si un hôte donné est à l'intérieur ou à l'extérieur de votre pare-feu.

Les entrées suivantes sont utilisées lors de l'installation et des tests sur le paquet libnet :

test_hosts
Si vrai, alors "make test" peut tenter de se connecter aux hôtes spécifiés dans la configuration.
test_exists
Si vrai, alors "Configure" vérifiera que chaque nom d'hôte donné existe.

Net::Config(3perl)

NAME

Net::Config - module pour la configuration réseau

SYNOPSIS

 use Net::Config;

 # Obtenir la configuration réseau
 my $config = Net::Config->new();
 print $config->{'hostname'}, "\n";

 # Modifier la configuration réseau
 $config->{'gateway'} = '192.168.1.1';
 $config->store();

DESCRIPTION

Le module Net::Config fournit une interface pour lire et écrire la configuration réseau d'un système.
