Description détaillée

Point de restauration

Les Points de restauration sont conservés dans une liste qui est essentiellement un index référençant chaque 1001ème objet. Ainsi, en sautant l'objet 0, il compte 1000, 2001, 3002, ...

Note

Cette classe est basée sur des observations, car aucune documentation publique n'est disponible. Il existe des fonctions API non documentées pour la gestion de RestorePoint. Et cela semble en être une.

décalage du fichier non compressé

Ceci désigne le décalage dans le contenu non compressé du LogContainer, où commence un Objet. Cet Objet n'est pas nécessairement le premier ou le dernier Objet, mais un objet arbitraire.

uint32_t Vector::BLF::RestorePoint::unknownRestorePoint {}

À faire

On ne sait pas à quoi sert cette variable.

Peut-être juste un champ réservé pour les extensions futures.

Les exemples montrent :

  • Fichier1 : 0, 0x9a
  • Fichier2 : 0, 1, 2, 3, 4, 5, 6
  • Fichier3 : 0, 0xffffffff, 0x10020
  • Fichier4 : 0xb9
  • Fichier5 : 0, 0x2c9a8a00

Ce sont des données similaires à celles de LogContainer.unknownLogContainer.
