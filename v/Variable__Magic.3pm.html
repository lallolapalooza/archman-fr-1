NOM

Variable::Magic - Associer une magie définie par l'utilisateur aux variables depuis Perl.

VERSION

Version 0.64

SYNOPSIS

use Variable::Magic qw<wizard cast VMG_OP_INFO_NAME>;
{ # Un traceur de variable
 my $wiz = wizard(
  set  => sub { print "maintenant défini à ${$_[0]}!\n" },
  free => sub { print "détruit!\n" },
 );
 my $a = 1;
 cast $a, $wiz;
 $a = 2;        # "maintenant défini à 2!"
}               # "détruit!"
{ # Un hash avec une valeur par défaut
 my $wiz = wizard(
  data     => sub { $_[1] },
  fetch    => sub { $_[2] = $_[1] unless exists $_[0]->{$_[2]}; () },
  store    => sub { print "clé $_[2] stockée dans $_[-1]\n" },
  copy_key => 1,
  op_info  => VMG_OP_INFO_NAME,
 );
 my %h = (_default => 0, pomme => 2);
 cast %h, $wiz, '_default';
 print $h{banane}, "\n"; # "0" (il n'y a pas de clé 'banane' dans %h)
 $h{poire} = 1;           # "clé poire stockée dans helem"
}

DESCRIPTION

La magie est la façon dont Perl améliore les variables. Ce mécanisme permet à l'utilisateur d'ajouter des données supplémentaires à n'importe quelle variable et de réagir aux opérations syntaxiques (telles que l'accès, l'assignation ou la destruction) qui peuvent lui être appliquées. Avec ce module, vous pouvez ajouter votre propre magie à n'importe quelle variable sans avoir à écrire une seule ligne de XS.

Vous réaliserez que ces variables magiques ressemblent beaucoup aux variables liées (tied variables). Ce n'est pas surprenant, car les variables liées sont implémentées comme un type spécial de magie, tout comme toute variable Perl 'irrégulière' : scalaires comme $!, $( ou $^W, les hashes %ENV et %SIG, le tableau %ISA, les lvalues de vec() et substr(), les variables threads::shared... Elles partagent toutes la même API C sous-jacente, et ce module vous y donne un accès direct.

Cependant, la magie mise à disposition par ce module diffère du liaison (tieing) et de la surcharge (overloading) de plusieurs manières :

  • La magie n'est pas copiée lors de l'assignation.

    Vous l'attachez aux variables, pas aux valeurs (comme pour les références bénies).

  • La magie ne remplace pas la sémantique d'origine.

    Les callbacks de magie sont généralement déclenchés avant que l'action d'origine ne se produise, et ne peuvent pas l'empêcher. Cela rend la capture d'événements individuels plus facile qu'avec "tie", où vous devez fournir des méthodes de repli pour toutes les actions en héritant généralement de la classe correcte "Tie::Std*" et en remplaçant les méthodes individuelles dans votre propre classe.

  • La magie est multivaluée.

    Vous pouvez appliquer en toute sécurité différents types de magie à la même variable, et chacune d'elles sera appelée successivement.

  • La magie est agnostique au type.

    La même magie peut être appliquée sur des scalaires, des tableaux, des hashes, des sous-routines ou des globs. Mais le même hook (voir ci-dessous pour une liste) peut se déclencher différemment selon le type de la variable.

  • La magie est invisible au niveau Perl.

    Les variables magiques et non magiques ne peuvent pas être distinguées avec "ref", "tied" ou une autre astuce.

  • La magie est notablement plus rapide.

    Principalement parce que la façon dont Perl gère la magie est plus légère par nature, et parce qu'il n'y a pas besoin de résolution de méthode. De plus, comme vous n'avez pas à réimplémenter toute la sémantique de la variable, vous ne payez que pour ce que vous utilisez réellement.

Les opérations qui peuvent être surchargées sont :

  • get

    Cette magie est appelée lorsque la variable est évaluée. Elle n'est jamais appelée pour les tableaux et les hashes.

  • set

    Cette magie est appelée chaque fois que la valeur de la variable change. Elle est appelée pour les sous-indices et les tranches de tableaux, mais jamais pour les hashes.

  • len

    Cette magie s'applique uniquement aux tableaux (bien qu'elle s'appliquait aussi aux scalaires), et est déclenchée lorsque la 'taille' ou la 'longueur' de la variable doit être connue par Perl. C'est typiquement la magie impliquée lorsqu'un tableau est évalué dans un contexte scalaire, mais aussi lors de l'assignation de tableau et des boucles ("for", "map" ou "grep"). La longueur est retournée par le callback sous forme d'entier.

    À partir de perl 5.12, cette magie n'est plus appelée par le mot-clé "length", et à partir de perl 5.17.4, elle n'est plus appelée pour les scalaires dans aucune situation, rendant cette magie significative uniquement sur les tableaux. Vous pouvez utiliser les constantes "VMG_COMPAT_SCALAR_LENGTH_NOLEN" et "VMG_COMPAT_SCALAR_NOLEN" pour savoir si cette magie est disponible pour les scalaires ou non.

  • clear

    Cette magie est appelée lorsque la variable est réinitialisée, comme lorsqu'un tableau est vidé. Veuillez noter que c'est différent de l'annulation de la définition de la variable, même si la magie est appelée lorsque le nettoyage est le résultat de l'annulation de la définition (par exemple, pour un tableau, mais en fait un bug empêche son fonctionnement avant perl 5.9.5 - voir l'historique).

  • free

    Cette magie est appelée lorsqu'une variable est détruite suite à la sortie de sa portée (mais pas lors de son annulation de définition). Elle se comporte globalement comme les destructeurs d'objets Perl (c'est-à-dire les méthodes "DESTROY"), sauf que les exceptions lancées depuis un callback free seront toujours propagées au code environnant.

  • copy

    Lorsqu'elle est appliquée aux tableaux et hashes liés, cette magie se déclenche lorsque vous essayez d'accéder ou de modifier leurs éléments.

    À partir de perl 5.17.0, elle peut également être appliquée aux prototypes de fermeture (closure prototypes), auquel cas la magie sera appelée lorsque le prototype sera cloné. La constante "VMG_COMPAT_CODE_COPY_CLONE" est vraie lorsque votre perl prend en charge cette fonctionnalité.

  • dup

    Cette magie est appelée lorsque la variable est clonée entre les threads. Elle n'est actuellement pas disponible.

  • local

    Lorsque cette magie est définie sur une variable, toutes les localisations subséquentes de la variable déclencheront le callback. Elle est disponible sur votre perl si et seulement si "MGf_LOCAL" est vrai.

Les actions suivantes s'appliquent uniquement aux hashes et sont disponibles si et seulement si "VMG_UVAR" est vrai. Elles sont désignées sous le nom de magies uvar.

  • fetch

    Cette magie est appelée chaque fois qu'un élément est récupéré du hash.

  • store

    Celle-ci est appelée lorsqu'un élément est stocké dans le hash.

  • exists

    Cette magie se déclenche lorsqu'une clé est testée pour son existence dans le hash.

  • delete

    Cette magie est déclenchée lorsqu'une clé est supprimée du hash, que la clé y existe ou non.

Vous pouvez vous référer aux tests pour avoir plus d'informations sur l'endroit où les différentes magies sont appelées.

NAME

Variable::Magic - Perl's magic variable interface

SYNOPSIS

 use Variable::Magic;

 my $wiz = wizard(
  "name"  => 'my magic',
  "=~"     => sub { ... }, # bind
  "set"    => sub { ... }, # set
  "get"    => sub { ... }, # get
  "len"    => sub { ... }, # length
  "free"   => sub { ... }, # free
  "copy"   => sub { ... }, # copy
  "local"  => sub { ... }, # local
  "fetch"  => sub { ... }, # fetch
  "store"  => sub { ... }, # store
  "exists" => sub { ... }, # exists
  "delete" => sub { ... }, # delete
  "default"=> 1,       # allow default behaviour
  "data"   => sub { ... }, # constructor for private data
 );

 my $x;
 cast $x, $wiz, @args;
 my $data = getdata $x, $wiz;
 dispell $x, $wiz;

DESCRIPTION

This module allows you to extend Perl's native magic variable feature. The latter gives you a way to hook into operations on variables, like assignment, evaluation, getting the length etc.

There are two main ways to use this module:

  • As a generic interface to Perl's magic API. This is done by calling "wizard" with named arguments.
  • As a simpler way to install magic on variables.

There are two functions provided by this module:

wizard
Returns a magic object that can be used with "cast", "getdata" and "dispell".
cast
Installs magic on a variable.
getdata
Fetches the private data associated with a magic variable.
dispell
Removes magic from a variable.

wizard

my $wiz = wizard(%args)

This function creates and returns a magic object. The possible arguments are:

  • "name", "=~", "bind"

    A code reference to be called when the magic is bound to a variable (i.e. when "cast" is called). The callback is called in scalar context each time the magic is cast onto a variable, with $_[0] being a reference to this variable and @_[1 .. @_-1] being all extra arguments that were passed to "cast". The scalar returned from this call is then attached to the variable and can be retrieved later with "getdata".

  • "get", "set", "len", "clear", "free", "copy", "local", "fetch", "store", "exists" and "delete"

    Code (or string) references to the respective magic callbacks. You don't have to specify all of them : the magic corresponding to undefined entries will simply not be hooked.

    When those callbacks are executed, $_[0] is a reference to the magic variable and $_[1] is the associated private data (or "undef" when no private data constructor is supplied with the wizard). Other arguments depend on which kind of magic is involved :

  • len

    $_[2] contains the natural, non-magical length of the variable (which can only be a scalar or an array as len magic is only relevant for these types). The callback is expected to return the new scalar or array length to use, or "undef" to default to the normal length.

  • copy

    When the variable for which the magic is invoked is an array or an hash, $_[2] is a either an alias or a copy of the current key, and $_[3] is an alias to the current element (i.e. the value). Since $_[2] might be a copy, it is useless to try to change it or cast magic on it.

    Starting from perl 5.17.0, this magic can also be called for code references. In this case, $_[2] is always "undef" and $_[3] is a reference to the cloned anonymous subroutine.

  • fetch, store, exists and delete

    $_[2] is an alias to the current key. Note that $_[2] may rightfully be readonly if the key comes from a bareword, and as such it is unsafe to assign to it. You can ask for a copy instead by passing "copy_key => 1" to "wizard" which, at the price of a small performance hit, allows you to safely assign to $_[2] in order to e.g. redirect the action to another key.

Finally, if "op_info => $num" is also passed to "wizard", then one extra element is appended to @_. Its nature depends on the value of $num :

  • "VMG_OP_INFO_NAME"

    $_[-1] is the current op name.

  • "VMG_OP_INFO_OBJECT"

    $_[-1] is the "B::OP" object for the current op.

Both result in a small performance hit, but just getting the name is lighter than getting the op object.

These callbacks are always executed in scalar context. The returned value is coerced into a signed integer, which is then passed straight to the perl magic API. However, note that perl currently only cares about the return value of the len magic callback and ignores all the others. Starting with Variable::Magic 0.58, a reference returned from a non-len magic callback will not be destroyed immediately but will be allowed to survive until the end of the statement that triggered the magic. This lets you use this return value as a token for triggering a destructor after the original magic action takes place. You can see an example of this technique in the cookbook.

Each callback can be specified as :

  • a code reference, which will be called as a subroutine.
  • a string reference, where the string denotes which subroutine is to be called when magic is triggered. If the subroutine name is not fully qualified, then the current package at the time the magic is invoked will be used instead.
  • a reference to "undef", in which case a no-op magic callback is installed instead of the default one. This may especially be helpful for local magic, where an empty callback prevents magic from being copied during localization.

Note that free magic is never called during global destruction, as there is no way to ensure that the wizard object and the callback were not destroyed before the variable.

Here is a simple usage example :

# A simple scalar tracer
my $wiz = wizard(
 get  => sub { print STDERR "got ${$_[0]}\n" },
 set  => sub { print STDERR "set to ${$_[0]}\n" },
 free => sub { print STDERR "${$_[0]} was deleted\n" },
);

"cast"

cast [$@%&*]var, $wiz, @args

This function associates $wiz magic to the supplied variable, without overwriting any other kind of magic. It returns true on success or when $wiz magic is already attached, and croaks on error. When $wiz provides a data constructor, it is called just before magic is cast onto the variable, and it receives a reference to the target variable in $_[0] and the content of @args in @_[1 .. @args]. Otherwise, @args is ignored.

# Casts $wiz onto $x, passing (\$x, '1') to the data constructor.
my $x;
cast $x, $wiz, 1;

The "var" argument can be an array or hash value. Magic for these scalars behaves like for any other, except that it is dispelled when the entry is deleted from the container. For example, if you want to call "POSIX::tzset" each time the 'TZ' environment variable is changed in %ENV, you can use :

use POSIX;
cast $ENV{TZ}, wizard set => sub { POSIX::tzset(); () };

If you want to handle the possible deletion of the 'TZ' entry, you must also specify store magic.

"getdata"

getdata [$@%&*]var, $wiz

This accessor fetches the private data associated with the magic $wiz in the variable. It croaks when $wiz does not represent a valid magic object, and returns an empty list if no such magic is attached to the variable or when the wizard has no data constructor.

# Get the data attached to $wiz in $x, or undef if $wiz
# did not attach any.
my $data = getdata $x, $wiz;

"dispell"

dispell [$@%&*]variable, $wiz

The exact opposite of "cast" : it dissociates $wiz magic from the variable. This function returns true on success, 0 when no magic represented by $wiz could be found in the variable, and croaks if the supplied wizard is invalid.

# Dispell now.
die 'no such magic in $x' unless dispell $x, $wiz;

CONSTANTS

"MGf_COPY"

Evaluates to true if and only if the copy magic is available. This is the case for perl 5.7.3 and greater, which is ensured by the requirements of this module.

"MGf_DUP"

Evaluates to true if and only if the dup magic is available. This is the case for perl 5.7.3 and greater, which is ensured by the requirements of this module.

"MGf_LOCAL"

Evaluates to true if and only if the local magic is available. This is the case for perl 5.9.3 and greater.

"VMG_UVAR"

When this constant is true, you can use the fetch, store, exists and delete magics on hashes. Initial "VMG_UVAR" capability was introduced in perl 5.9.5, with a fully functional implementation shipped with perl 5.10.0.

"VMG_COMPAT_SCALAR_LENGTH_NOLEN"

True for perls that don't call len magic when taking the "length" of a magical scalar.

"VMG_COMPAT_SCALAR_NOLEN"

True for perls that don't call len magic on scalars. Implies "VMG_COMPAT_SCALAR_LENGTH_NOLEN".

"VMG_COMPAT_ARRAY_PUSH_NOLEN"

True for perls that don't call len magic when you push an element in a magical array. Starting from perl 5.11.0, this only refers to pushes in non-void context and hence is false.

"VMG_COMPAT_ARRAY_PUSH_NOLEN_VOID"

True for perls that don't call len magic when you push an element in a magical array in void context.

MANUEL DE CUISINE

Associer un objet à n'importe quelle variable perl

Cette technique peut être utile pour passer des données utilisateur via des API limitées. Elle est similaire à l'utilisation d'objets inside-out, mais sans l'inconvénient de devoir implémenter un destructeur complexe.

{
 package Magical::UserData;
 use Variable::Magic qw<wizard cast getdata>;
 my $wiz = wizard data => sub { \$_[1] };
 sub ud (\[$@%*&]) : lvalue {
  my ($var) = @_;
  my $data = &getdata($var, $wiz);
  unless (defined $data) {
   $data = \(my $slot);
   &cast($var, $wiz, $slot)
             or die "Impossible de caster la magie UserData sur la variable";
  }
  $$data;
 }
}
{
 BEGIN { *ud = \&Magical::UserData::ud }
 my $cb;
 $cb = sub { print 'Bonjour, ', ud(&$cb), "!\n" };
 ud(&$cb) = 'monde';
 $cb->(); # Bonjour, monde!
}

Appliquer récursivement la magie aux structures de données

"cast" peut être appelé depuis n'importe quel callback magique, et en particulier depuis "data". Cela vous permet d'appliquer récursivement la magie aux structures de données :

my $wiz;
$wiz = wizard data => sub {
 my ($var, $depth) = @_;
 $depth ||= 0;
 my $r = ref $var;
 if ($r eq 'ARRAY') {
  &cast((ref() ? $_ : \$_), $wiz, $depth + 1) for @$var;
 } elsif ($r eq 'HASH') {
  &cast((ref() ? $_ : \$_), $wiz, $depth + 1) for values %$var;
 }
 return $depth;
},
free => sub {
 my ($var, $depth) = @_;
 my $r = ref $var;
 print "libération $r à la profondeur $depth\n";
 ();
};
{
 my %h = (
  a => [ 1, 2 ],
  b => { c => 3 }
 );
 cast %h, $wiz;
}

Lorsque %h sort de la portée, cela affiche quelque chose comme :

libération HASH à la profondeur 0
libération HASH à la profondeur 1
libération SCALAR à la profondeur 2
libération ARRAY à la profondeur 1
libération SCALAR à la profondeur 3
libération SCALAR à la profondeur 3

Bien sûr, cet exemple ne fait rien avec les valeurs qui sont ajoutées après le "cast".

Actions magiques retardées

À partir de Variable::Magic 0.58, la valeur de retour des callbacks magiques peut être utilisée pour retarder l'action jusqu'après que l'action d'origine ait eu lieu :

my $delayed;
my $delayed_aux = wizard(
 data => sub { $_[1] },
 free => sub {
  my ($target) = $_[1];
  my $target_data = &getdata($target, $delayed);
  local $target_data->{guard} = 1;
  if (ref $target eq 'SCALAR') {
   my $orig = $$target;
   $$target = $target_data->{mangler}->($orig);
  }
  return;
 },
);
$delayed = wizard(
 data => sub {
  return +{ guard => 0, mangler => $_[1] };
 },
 set  => sub {
  return if $_[1]->{guard};
  my $token;
  cast $token, $delayed_aux, $_[0];
  return \$token;
 },
);
my $x = 1;
cast $x, $delayed => sub { $_[0] * 2 };
$x = 2;
# $x vaut maintenant 4
# Mais notez que l'action retardée n'a lieu qu'à la fin de
# l'instruction actuelle :
my @y = ($x = 5, $x);
# $x vaut maintenant 10, mais @y est (5, 5)

Les endroits où la magie est invoquée ont un peu changé au fil de l'histoire de perl. Voici une petite liste des plus récents.

  • 5.6.x

    p14416 : Magie copy et dup.

  • 5.8.9

    p28160 : Intégration de p25854 (voir ci-dessous).

    p32542 : Intégration de p31473 (voir ci-dessous).

  • 5.9.3

    p25854 : La magie len n'est plus appelée lors de l'ajout d'un élément à un tableau magique.

    p26569 : Magie local.

  • 5.9.5

    p31064 : Magie uvar significative.

    p31473 : La magie clear n'était pas invoquée lors de la suppression d'un tableau. Le bug est corrigé à partir de cette version.

  • 5.10.0

    Puisque "PERL_MAGIC_uvar" est en majuscules, hv_magic_check() déclenche la magie copy sur les stockages de tables pour les tables (non liées) qui ont également la magie uvar.

  • 5.11.x

    p32969 : La magie len n'est plus invoquée lors de l'appel de "length" avec un scalaire magique.

    p34908 : La magie len n'est plus appelée lors de l'ajout / suppression d'un élément à un tableau magique dans un contexte vide. La partie "push" était déjà couverte par p25854.

    g9cdcb38b : La magie len est à nouveau appelée lors de l'ajout à un tableau magique dans un contexte non vide.

EXPORT

Les fonctions "wizard", "cast", "getdata" et "dispell" sont exportées uniquement sur demande. Toutes sont exportées par les tags ':funcs' et ':all'.

Toutes les constantes sont également exportées uniquement sur demande, soit individuellement, soit par les tags ':consts' et ':all'.

ATTENTION

Pour intercepter les opérations de table avec la magie, vous avez besoin d'au moins perl 5.10.0 (voir "VMG_UVAR").

Si vous voulez stocker un objet magique dans le slot de données privé, vous ne pourrez pas récupérer la magie avec "getdata", car la magie n'est pas copiée par affectation. Vous pouvez contourner ce problème en stockant plutôt une référence à l'objet magique.

Si vous définissez un wizard avec la magie free et que vous le lui appliquez, cela crée un cycle de mémoire, donc ce destructeur ne sera pas appelé lorsque le wizard sera libéré.

Variable::Magic - Perl

DESCRIPTION

Ce module vous permet de créer et de manipuler des variables magiques dans Perl.

Une variable magique est une variable qui a une routine spéciale associée à elle. Cette routine est appelée lorsque la variable est accédée (lue, écrite, etc.).

Ceci peut être utilisé pour implémenter des fonctionnalités telles que des variables de trace, des hooks d'accès, ou des liaisons de données. Le module fournit une interface simple pour attacher et détacher des routines magiques aux variables.

Vous pouvez également utiliser ce module pour inspecter les variables magiques existantes et leurs propriétés.

FUNCTIONS

Les fonctions suivantes sont exportées par défaut:

magic_assign
Attribue une routine magique à une variable.
magic_get
Récupère la routine magique associée à une variable.
magic_clear
Supprime la routine magique associée à une variable.
is_magic
Vérifie si une variable est magique.
magic_each
Itère sur toutes les variables magiques.

CONSTANTS

Les constantes suivantes sont disponibles:

M_ACCESS
Indique que la magie est appelée lors de l'accès à la variable.
M_ASSIGN
Indique que la magie est appelée lors de l'affectation à la variable.
M_CLONE
Indique que la magie est appelée lors du clonage de la variable.
M_LOCAL
Indique que la magie est appelée lors de la localisation de la variable.

COOKBOOK

Voici quelques exemples d'utilisation de ce module:

    # Exemple 1: Créer une variable qui trace ses accès
    use Variable::Magic;

    sub trace_access {
        my ($caller, $varname, $value) = @_;
        print "Variable '$varname' accessed with value '$value'\n";
        return $value;
    }

    my $x;
    magic_assign( \$x, \&trace_access, M_ACCESS );

    print $x;  # Affichera: Variable '$x' accessed with value ''
    $x = 10;   # Affichera: Variable '$x' accessed with value '10'
    print $x;  # Affichera: Variable '$x' accessed with value '10'

    # Exemple 2: Créer une variable qui se valide à l'affectation
    use Variable::Magic;

    sub validate_integer {
        my ($caller, $varname, $value) = @_;
        die "Value must be an integer" unless $value =~ /^\d+$/;
        return $value;
    }

    my $count;
    magic_assign( \$count, \&validate_integer, M_ASSIGN );

    $count = 5;     # Fonctionne
    # $count = "hello"; # Provoquera une erreur

PERL MAGIC HISTORY

Ce module est basé sur le mécanisme de magie des variables de Perl, introduit dans Perl 5.005.

EXPORT

Par défaut, ce module exporte les fonctions suivantes: magic_assign, magic_get, magic_clear, is_magic, et magic_each.

Il exporte également les constantes M_ACCESS, M_ASSIGN, M_CLONE, et M_LOCAL.

CAVEATS

Les variables magiques peuvent avoir un impact sur les performances, utilisez-les judicieusement.

Le comportement exact des routines magiques peut dépendre de la version de Perl.

DEPENDENCIES
