VALUES(7)

Paquet: postgresql

Licences: PostgreSQL

VALUES(7) Documentation PostgreSQL 18.1 VALUES(7)

NOM

VALUES — calculer un ensemble de lignes

SYNTAXE

VALUES ( expression [, ...] ) [, ...]
    [ ORDER BY expression_de_tri [ ASC | DESC | USING opérateur ] [, ...] ]
    [ LIMIT { compteur | ALL } ]
    [ OFFSET début [ ROW | ROWS ] ]
    [ FETCH { FIRST | NEXT } [ compteur ] { ROW | ROWS } ONLY ]

DESCRIPTION

VALUES calcule une valeur de ligne ou un ensemble de valeurs de lignes spécifiées par des expressions de valeur. Il est le plus couramment utilisé pour générer une “table constante” dans une commande plus grande, mais il peut être utilisé seul.

Lorsque plusieurs lignes sont spécifiées, toutes les lignes doivent avoir le même nombre d'éléments. Les types de données des colonnes de la table résultante sont déterminés en combinant les types explicites ou inférés des expressions apparaissant dans cette colonne, en utilisant les mêmes règles que pour UNION (voir Section 10.5).

Dans les commandes plus grandes, VALUES est syntaxiquement permis partout où SELECT l'est. Parce qu'il est traité comme un SELECT par la grammaire, il est possible d'utiliser les clauses ORDER BY, LIMIT (ou FETCH FIRST de manière équivalente) et OFFSET avec une commande VALUES.

PARAMETRES

expression

Une constante ou une expression à calculer et à insérer à l'endroit indiqué dans la table résultante (ensemble de lignes). Dans une liste VALUES apparaissant au niveau supérieur d'un INSERT, une expression peut être remplacée par DEFAULT pour indiquer que la valeur par défaut de la colonne de destination doit être insérée. DEFAULT ne peut pas être utilisé lorsque VALUES apparaît dans d'autres contextes.

expression_de_tri

Une expression ou une constante entière indiquant comment trier les lignes résultantes. Cette expression peut faire référence aux colonnes du résultat VALUES en tant que colonne1, colonne2, etc. Pour plus de détails, voir la clause ORDER BY dans la documentation de SELECT(7).

opérateur

Un opérateur de tri. Pour plus de détails, voir la clause ORDER BY dans la documentation de SELECT(7).

compteur

Le nombre maximum de lignes à retourner. Pour plus de détails, voir la clause LIMIT dans la documentation de SELECT(7).

début

Le nombre de lignes à ignorer avant de commencer à retourner des lignes. Pour plus de détails, voir la clause LIMIT dans la documentation de SELECT(7).

NOTES

Les listes VALUES comportant un très grand nombre de lignes devraient être évitées, car vous pourriez rencontrer des échecs de manque de mémoire ou de mauvaises performances. VALUES apparaissant dans INSERT est un cas spécial (car les types de colonnes souhaités sont connus de la table cible de INSERT, et n'ont pas besoin d'être inférés en analysant la liste VALUES), donc il peut gérer des listes plus grandes que celles qui sont pratiques dans d'autres contextes.

EXEMPLES

Une commande VALUES simple :

VALUES (1, 'one'), (2, 'two'), (3, 'three');

Ceci retournera une table de deux colonnes et trois lignes. C'est essentiellement équivalent à :

SELECT 1 AS column1, 'one' AS column2
UNION ALL
SELECT 2, 'two'
UNION ALL
SELECT 3, 'three';

Plus couramment, VALUES est utilisé dans une commande SQL plus grande. L'utilisation la plus courante est dans INSERT :

INSERT INTO films (code, title, did, date_prod, kind)
    VALUES ('T_601', 'Yojimbo', 106, '1961-06-16', 'Drama');

Dans le contexte de INSERT, les entrées d'une liste VALUES peuvent être DEFAULT pour indiquer que la valeur par défaut de la colonne doit être utilisée ici au lieu de spécifier une valeur :

INSERT INTO films VALUES
    ('UA502', 'Bananas', 105, DEFAULT, 'Comedy', '82 minutes'),
    ('T_601', 'Yojimbo', 106, DEFAULT, 'Drama', DEFAULT);

VALUES peut également être utilisé là où une sous-SELECT pourrait être écrite, par exemple dans une clause FROM :

SELECT f.*
  FROM films f, (VALUES('MGM', 'Horror'), ('UA', 'Sci-Fi')) AS t (studio, kind)
  WHERE f.studio = t.studio AND f.kind = t.kind;
UPDATE employees SET salary = salary * v.increase
  FROM (VALUES(1, 200000, 1.2), (2, 400000, 1.4)) AS v (depno, target, increase)
  WHERE employees.depno = v.depno AND employees.sales >= v.target;

Notez qu'une clause AS est requise lorsque VALUES est utilisé dans une clause FROM, tout comme c'est le cas pour SELECT. Il n'est pas nécessaire que la clause AS spécifie des noms pour toutes les colonnes, mais c'est une bonne pratique de le faire. (Les noms de colonnes par défaut pour VALUES sont colonne1, colonne2, etc. dans PostgreSQL, mais ces noms peuvent être différents dans d'autres systèmes de bases de données.)

Lorsque VALUES est utilisé dans INSERT, les valeurs sont toutes automatiquement converties vers le type de données de la colonne de destination correspondante. Lorsqu'il est utilisé dans d'autres contextes, il peut être nécessaire de spécifier le type de données correct. Si les entrées sont toutes des littéraux constants entre guillemets, la conversion du premier suffit à déterminer le type supposé pour tous :

SELECT * FROM machines
WHERE ip_address IN (VALUES('192.168.0.1'::inet), ('192.168.0.10'), ('192.168.1.43'));

Astuce

Pour des tests IN simples, il est préférable de s'appuyer sur la forme de liste de scalaires de IN plutôt que d'écrire une requête VALUES comme illustré ci-dessus. La méthode de liste de scalaires requiert moins d'écriture et est souvent plus efficace.

COMPATIBILITE

VALUES est conforme à la norme SQL. LIMIT et OFFSET sont des extensions PostgreSQL ; voir aussi sous SELECT(7).

VOIR AUSSI
