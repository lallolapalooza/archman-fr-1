PMNOTIFYTHROTTLE(3) Manuel des fonctions de bibliothèque PMNOTIFYTHROTTLE(3)

NOM

__pmNotifyThrottle, __pmResetNotifyThrottle - contrôle du "débordement" de messages de diagnostic

C SYNTAXE

#include <pcp/pmapi.h>
#include <pcp/libpcp.h>

int __pmNotifyThrottle(char *key, int subkey);
int __pmResetNotifyThrottle(char *key, int subkey);

cc ... -lpcp

AVERTISSEMENT

Cette documentation est destinée à un usage interne par les développeurs de Performance Co-Pilot (PCP).

Ces interfaces ne font pas partie des API PCP garanties comme restant fixes d'une version à l'autre, et elles peuvent ne pas fonctionner, ou présenter une sémantique différente à un moment donné dans le futur.

DESCRIPTION

Lorsque la même condition d'erreur se produit de manière répétée, comme lors d'une attaque par déni de service, d'une défaillance réseau catastrophique, d'une mauvaise configuration système ou d'un bug logiciel, il existe un risque qu'une application PCP génère un grand nombre de messages de diagnostic identiques, remplissant ainsi un fichier journal et donc un système de fichiers. __pmNotifyThrottle est conçu pour être utilisé comme un garde qui peut détecter des appels répétés pour la même condition d'erreur et permettre à l'appelant d'arrêter d'émettre des messages lorsque des problèmes répétés surviennent.

La condition d'erreur est identifiée par key et subkey, et le cas d'utilisation le plus courant serait que ceux-ci soient __FILE__ et __LINE__ au point où __pmNotifyThrottle est appelé.

Pour chaque paire unique de key et subkey, __pmNotifyThrottle maintient un compte du nombre de fois où il a été appelé durant la vie du processus appelant.

Les valeurs de retour sont 0 si la limite de limitation pour key et subkey n'a pas été atteinte, 1 si la limite de limitation a été atteinte, et 2 si la limite de limitation a été dépassée.

La même limite de limitation s'applique à toutes les conditions d'erreur et est définie par la variable d'environnement PCP_NOTIFY_THROTTLE, ou par défaut 10 si la variable d'environnement n'est pas définie, bien que cela puisse être modifié ultérieurement en appelant __pmResetNotifyThrottle.

__pmResetNotifyThrottle peut être utilisé pour réinitialiser le compteur d'une condition d'erreur à zéro, afin que la sortie de diagnostic puisse reprendre si l'appelant détermine qu'il est sûr de le faire. Si limit est supérieur à zéro, alors la limite pour la condition d'erreur est également réinitialisée, sinon la limite reste inchangée.

Appeler __pmResetNotifyThrottle avec une valeur de key égale à NULL réinitialisera les compteurs (et potentiellement les limites) pour toutes les conditions d'erreur, et dans ce cas, si limit est supérieur à zéro, la limite par défaut pour toutes nouvelles conditions d'erreur sera également définie (remplaçant le réglage par défaut ou la valeur initialisée depuis la variable d'environnement PCP_NOTIFY_THROTTLE).

__pmResetNotifyThrottle retournera -ENOENT si key et subkey ne correspondent pas à une condition d'erreur existante, sinon la valeur de retour est la somme du nombre de fois où la limite a été dépassée pour toutes les conditions d'erreur sélectionnées.

EXEMPLE

Ce qui suit est une simple limitation qui arrête de signaler les erreurs après 10 occurrences. 

if ((sts = __pmNotifyThrottle(__FILE__, __LINE__)) < 2) {
    fprintf(stderr, "Message d'erreur quelconque\n");
    if (sts == 1)
	fprintf(stderr, "[les messages supplémentaires seront supprimés]\n");
}

L'exemple plus sophistiqué ci-dessous limite les messages, mais les réactive après 10 minutes. 

int    lineno;
time_t first_throttle;
...
lineno = __LINE__ + 1;
if ((sts = __pmNotifyThrottle(__FILE__, lineno)) < 2) {
    pmNotifyErr(LOG_INFO, "Message d'erreur quelconque");
    if (sts == 1) {
	first_throttle = time(NULL);
	pmNotifyErr(LOG_INFO, "[les messages supplémentaires seront supprimés]");
    }
}
else if (sts == 2) {
    if (time(NULL) - first_throttle >= 600) {
	sts = __pmResetNotifyThrottle(__FILE__, lineno, -1);
	pmNotifyErr(LOG_INFO, "[%d messages ont été supprimés]", sts);
    }
}
