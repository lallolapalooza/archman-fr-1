NOM

__pmLocalPMDA - changer la table des PMDA DSO pour les contextes PM_CONTEXT_LOCAL

C SYNTAXE

#include"pmapi.h"
#include"libpcp.h"

int __pmLocalPMDA(int op,
int domaine, const char *nom, const char *init);

cc ... -lpcp

AVERTISSEMENT

Cette documentation est destinée à un usage interne par les développeurs de Performance Co-Pilot (PCP).

Ces interfaces ne font pas partie des API PCP garanties pour rester fixes d'une version à l'autre, et elles pourraient ne pas fonctionner, ou fournir des sémantiques différentes à un moment donné dans le futur.

DESCRIPTION

Les contextes PCP de type PM_CONTEXT_LOCAL sont utilisés par les clients qui souhaitent récupérer les métriques directement à partir d'un ou plusieurs PMDA sur l'hôte local sans impliquer pmcd(1). Un PMDA qui doit être utilisé de cette manière doit avoir été compilé en tant que Dynamic Shared Object (DSO).

Historiquement, la table des PMDA disponibles pour une utilisation avec PM_CONTEXT_LOCAL était codée en dur comme suit :

  • Le ou les PMDA qui exportent les données de performance du système d'exploitation et les données sur l'activité des processus.
  • Le PMDA mmv.
  • Le PMDA sample si $PCP_LITE_SAMPLE ou $PMDA_LOCAL_SAMPLE est défini dans l'environnement - utilisé principalement pour l'assurance qualité et les tests.

La table initiale des PMDA disponibles pour une utilisation avec PM_CONTEXT_LOCAL est maintenant générée dynamiquement à partir de tous les PMDA qui ont été installés en tant que DSO sur l'hôte local. La seule exception est le PMDA ``pmcd'' qui ne fonctionne correctement que dans l'espace d'adressage d'un processus pmcd(1) en cours d'exécution et n'est donc pas disponible pour une application utilisant un contexte PM_CONTEXT_LOCAL.

__pmLocalPMDA fournit un certain nombre de services pour modifier la table des PMDA disponibles pour une utilisation avec PM_CONTEXT_LOCAL.

L'argument op spécifie ce qui doit être fait et prend l'une des valeurs et actions suivantes :

PM_LOCAL_ADD
Ajoute une entrée à la table pour le PMDA avec un domaine de métriques de performance (PMD) de domaine, le chemin vers le DSO PMDA est donné par chemin et la routine d'initialisation du PMDA est init.
PM_LOCAL_DEL
Supprime toutes les entrées de la table où le domaine correspond, ou le chemin correspond. En définissant les arguments domaine à -1 ou chemin à NULL pour forcer la correspondance sur l'autre argument. L'argument init est ignoré.
PM_LOCAL_CLEAR
Supprime toutes les entrées de la table. Tous les autres arguments sont ignorés dans ce cas.

Les arguments domaine, nom et init ont une syntaxe et des sémantiques similaires aux champs associés dans le fichier de configuration de pmcd(1). La seule différence est l'argument chemin qui est utilisé par __pmLocalPMDA pour trouver un DSO apparemment approprié en recherchant dans cet ordre : $PCP_PMDAS_DIR/chemin, chemin, $PCP_PMDAS_DIR/chemin.suffixe_dso et enfin chemin.suffixe_dso (suffixe_dso est le suffixe de nom de fichier par défaut spécifique à la plateforme locale pour un DSO, par exemple so pour Linux, dylib pour macOS, dll pour Windows, etc.).

VALEUR DE RETOUR

Dans la plupart des cas, __pmLocalPMDA renvoie 0 pour indiquer le succès. Si op est invalide, la valeur de retour est PM_ERR_CONV sinon s'il n'y a pas d'entrée de table correspondante trouvée pour une opération PM_LOCAL_DEL, PM_ERR_INDOM est retourné.

VOIR AUSSI

pmcd(1), PMAPI(3), pmNewContext(3) et pmSpecLocalPMDA(3).
