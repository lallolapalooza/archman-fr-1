NOM

__pmParseHostAttrsSpec, __pmUnparseHostAttrsSpec, __pmFreeHostAttrsSpec, __pmFreeAttrsSpec - analyseur de spécification d'hôtes et d'attributs

C SYNOPIS

#include "pmapi.h"
#include "libpcp.h"

int __pmParseHostAttrsSpec(const char *string,
__pmHostSpec **hostsp, int *count, __pmHashCtl *attrs, char **errmsg);

int __pmUnparseHostAttrsSpec(__pmHostSpec *hostsp,
int *count, __pmHashCtl *attrs, char *string, size_t size);

void __pmFreeHostAttrsSpec(__pmHostSpec *hosts,
int count, __pmHashCtl *attrs);

void __pmFreeAttrsSpec(__pmHashCtl *attrs);

cc ... -lpcp

AVERTISSEMENT

Cette documentation est destinée à un usage interne des développeurs de Performance Co-Pilot (PCP).

Ces interfaces ne font pas partie des API PCP garanties de rester fixes entre les versions, et elles pourraient ne pas fonctionner, ou fournir des sémantiques différentes à l'avenir.

DESCRIPTION

__pmParseHostAttrsSpec accepte une chaîne spécifiant l'emplacement d'un démon collecteur de métriques de performance PCP, et tout attribut qui devrait être associé à la connexion à ce démon.

La syntaxe permet la spécification optionnelle d'un protocole (protocole PCP natif, protocole PCP crypté ou protocole de socket de domaine Unix).

Si le protocole spécifié est le protocole PCP natif, ou le protocole PCP crypté, un nom d'hôte pmcd(1) initial avec des numéros de port optionnels et un hôte proxy optionnel, et des attributs optionnels qui doivent être associés à la connexion peuvent être spécifiés. Quelques exemples suivent :


pcp://nas1.servers.com:44321@firewalls.r.us?compress
pcps://nas1.servers.com?user=otto&pass=blotto&compress

Si le protocole spécifié est un protocole de socket de domaine Unix, le chemin vers le socket dans le système de fichiers local peut être spécifié ainsi que les attributs optionnels qui doivent être associés à la connexion. Par exemple :


unix://$PCP_RUN_DIR/pmcd.socket:?compress
local://my/local/pmcd.socket:?user=otto&pass=blotto&compress

Si le composant de protocole optionnel n'est pas spécifié, le paramètre par défaut sera utilisé - qui est le protocole binaire PCP natif. Cependant, cela peut toujours être remplacé via l'environnement comme décrit dans PCPIntro(1). Si le préfixe de protocole est spécifié, il doit être soit "pcp://" (clair), "pcps://" (sécurisé, crypté), "unix://" (authentifié local) ou "local://" ("unix://" puis "pcp://").

Le chemin spécifié pour les protocoles "unix://" et "local://" sera toujours interprété comme un nom de chemin absolu. Par exemple, les suivants sont tous interprétés de manière identique comme $PCP_RUN_DIR/pmcd.socket.


unix://$PCP_RUN_DIR/pmcd.socket
unix:/$PCP_RUN_DIR/pmcd.socket
unix:$PCP_RUN_DIR/pmcd.socket

Se référer à __pmParseHostSpec(3) pour plus de détails sur les composants hôte et hôte proxy.

Si des attributs de connexion optionnels doivent être spécifiés, ils sont séparés du composant nom d'hôte par le caractère '?'. Chaque attribut est séparé par le caractère '&', et chacun peut être soit un indicateur d'attribut simple (tel que "compress") soit une paire nom=valeur (tel que "username=fred").

__pmParseHostAttrsSpec prend une spécification hôte-et-attributs se terminant par un nul string et retourne un tableau de structures __pmHostSpec, où le tableau a count entrées, et une table de hachage attrs contenant tous les attributs (y compris le protocole optionnel, s'il a été spécifié).

Les détails complets des structures __pmHostSpec sont fournis dans __pmParseHostSpec(3).

La structure __pmHashCtl qui est remplie au retour via attributes, représente chaque attribut individuel dans la chaîne de spécification string avec toute valeur associée. Elle doit être considérée comme une structure opaque et devrait être initialisée à zéro au préalable.

La structure de contrôle de table de hachage retournée peut être parcourue en utilisant l'un des mécanismes d'itération fournis - __pmHashWalkCB (un mécanisme basé sur rappel) ou __pmHashWalk (un mécanisme procédural simple). Ceux-ci donnent accès aux nœuds de hachage individuels, en tant qu'entrées __pmHashNode, qui donnent accès aux attributs décodés et à leurs valeurs (optionnelles).

    typedef struct __pmHashNode {
        __pmHashNode    *next;    /* nœud suivant dans le compartiment de hachage (interne) */
        unsigned int    key;      /* clé identifiant un attribut particulier */
        void            *data;    /* valeur de l'attribut (optionnel, chaîne) */
    } __pmHashNode;

Il existe un certain nombre d'attributs valides, cependant ceux-ci peuvent être étendus dans de futures versions à mesure que de nouveaux paramètres de connexion deviennent nécessaires. Ceux-ci peuvent être identifiés via les macros PCP_ATTR_* dans les fichiers d'en-tête PCP.

__pmUnparseHostSpec effectue l'opération inverse, créant une représentation en chaîne à partir des structures hosts et attributes. La taille du tampon string fourni doit être donnée par l'appelant en utilisant le paramètre size.

VALEUR DE RETOUR

Si la chaîne donnée est analysée avec succès, __pmParseHostAttrsSpec retourne zéro. Dans ce cas, le stockage dynamique alloué par __pmParseHostAttrsSpec peut être libéré en appelant __pmFreeHostAttrsSpec en utilisant les adresses retournées par __pmParseHostAttrsSpec

Alternativement, la mémoire hosts et attributes peut être libérée séparément, en utilisant __pmFreeHostSpec(3) et __pmFreeAttrsSpec.

__pmParseHostAttrsSpec retourne PM_ERR_GENERIC et une chaîne de message d'erreur allouée dynamiquement dans errmsg, si la chaîne donnée ne peut pas être analysée, et le pointeur d'utilisateur errmsg n'est pas nul. Assurez-vous de free(3) la chaîne de message d'erreur dans cette situation.

En cas d'erreur, à la fois hosts et attributes sont indéfinis. En cas de succès, errmsg est indéfini.

En cas de succès, __pmUnparseHostAttrsSpec retourne une valeur positive indiquant le nombre de caractères écrits dans le tampon fourni. Cependant, si le tampon fourni était trop petit, un code de statut négatif de -E2BIG sera retourné.

VOIR AUSSI
