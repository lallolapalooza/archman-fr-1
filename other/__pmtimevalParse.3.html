NOM

__pmtimevalParse, __pmtimespecParse - analyser la spécification d'un point temporel

C SYNOPSIS

#include "pmapi.h"
#include "libpcp.h"

int __pmtimevalParse(const char *string,
struct timeval *logStart, struct timeval *logEnd, struct timeval *rslt, char **errMsg);

int __pmtimespecParse(const char *string,
struct timespec *logStart, struct timespec *logEnd, struct timespec *rslt, char **errMsg);

cc ... -lpcp

AVERTISSEMENT

Cette documentation est destinée à un usage interne par les développeurs de Performance Co-Pilot (PCP).

Ces interfaces ne font pas partie des API PCP qui sont garanties de rester fixes entre les versions, et elles pourraient ne pas fonctionner, ou avoir des sémantiques différentes, à un moment donné dans le futur.

DESCRIPTION

__pmtimevalParse et __pmtimespecParse sont conçus pour encapsuler l'interprétation d'une spécification de point temporel dans les commutateurs de ligne de commande pour une utilisation par les outils clients PCP.

Ces fonctions s'attendent à être appelées avec la spécification du point temporel comme string. Si l'outil fonctionne avec des archives PCP, vous devez également fournir l'heure de début de la première (et unique) archive comme logStart, et la fin de la dernière (et unique) archive comme logEnd. Voir pmGetArchiveLabel(3) et pmGetArchiveEnd(3) pour savoir comment obtenir les valeurs de ces paramètres. Si l'outil fonctionne avec un flux de données de performance en direct, logStart doit être l'heure actuelle (mais pourrait être aligné sur la seconde suivante, par exemple), tandis que logEnd doit avoir son composant tv_sec défini sur PM_MAX_TIME_T.

La structure rslt doit être allouée avant d'appeler __pmtimevalParse ou __pmtimespecParse.

Vous devez également définir le fuseau horaire de rapport PCP actuel pour refléter correctement les paramètres de ligne de commande -z et -Z avant d'appeler __pmtimevalParse ou __pmtimespecParse. Voir pmUseZone(3) et ses semblables pour plus d'informations sur la façon de procéder.

Si la conversion réussit, __pmtimevalParse et __pmtimespecParse renvoient 0 et remplissent rslt avec la valeur temporelle définie par les paramètres d'entrée. Si les chaînes d'arguments n'ont pas pu être analysées, elles renvoient -1 et un message d'erreur alloué dynamiquement dans errMsg. Assurez-vous de free(3) ce message d'erreur.
