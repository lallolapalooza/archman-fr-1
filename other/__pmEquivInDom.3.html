NOM

__pmEquivInDom - vérifier si deux domaines d'instance sont équivalents

C SYNTAXE

#include <pcp/pmapi.h>
#include <pcp/libpcp.h>

int __pmEquivInDom(pmInDom a, pmInDom b)

cc ... -lpcp

AVERTISSEMENT

Cette documentation est destinée à l'usage interne des développeurs de Performance Co-Pilot (PCP).

Ces interfaces ne font pas partie des API de PCP garanties comme restant fixes entre les versions, et à un moment donné dans le futur, elles pourraient ne pas fonctionner ou fournir des sémantiques différentes.

DESCRIPTION

Au sein de Performance Co-Pilot (PCP), chaque domaine d'instance se voit attribuer un Identifiant de Domaine d'Instance (pmInDom) unique. En interne, un pmInDom est construit à partir de 2 champs : le numéro de domaine (de l'Agent de Domaine de Métriques de Performance (PMDA) associé) et le numéro de série (attribué par le PMDA).

Dans certaines circonstances inhabituelles, différents PMDA peuvent prendre en charge des domaines d'instance indépendants qui sont sémantiquement équivalents, par exemple, par identifiant de CPU ou par processus. __pmEquivInDom fournit un mécanisme pour déterminer si le Domaine d'Instance a est équivalent au Domaine d'Instance b.

L'« équivalence » des domaines d'instance est définie par un fichier de configuration externe, identifié par la variable d'environnement $PCP_INDOM_CONFIG ou par défaut par $PCP_ETC_DIR/pcp/indom.config. Le format du fichier de configuration est défini dans la section FICHIER DE CONFIGURATION ci-dessous.

Si $PCP_INDOM_CONFIG est une chaîne vide, aucun mappage d'équivalence n'est chargé.

FICHIER DE CONFIGURATION

Un fichier de mappage d'équivalence de domaines d'instance respecte la syntaxe suivante :

1.
Les lignes commençant par des espaces blancs optionnels, suivis de « # », sont considérées comme des commentaires.
2.
Les lignes vides sont ignorées.
3.
Chaque ligne restante définit une « carte d'équivalence » avec une liste de domaines d'instance séparés par des espaces, chacun consistant en un nombre (le numéro de domaine), un point « . », et un nombre (le numéro de série). À titre de cas spécial pour « faire correspondre tous les numéros de série », la partie numéro de série peut être « * ».

Le format d'un pmInDom exige qu'un numéro de domaine soit dans la plage 0 à 511, et qu'un numéro de série numérique soit dans la plage 0 à 4194303.

DIAGNOSTICS ET VALEURS DE RETOUR

La valeur de retour est 1 si les domaines d'instance sont équivalents, sinon 0 s'ils ne le sont pas. Dans de rares cas, une valeur de retour de -1 est utilisée pour indiquer un problème (signalé sur la sortie standard) lors de l'ouverture ou de l'analyse du fichier de configuration.
