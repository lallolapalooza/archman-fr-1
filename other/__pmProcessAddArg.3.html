PMPROCESSEXEC(3) Manuel des fonctions de bibliothèque PMPROCESSEXEC(3)

NOM

__pmProcessAddArg, __pmProcessUnpickArgs, __pmProcessExec - support d'exécution de processus

C SYNTAXE

#include "pmapi.h"
#include "libpcp.h"

int __pmProcessAddArg(__pmExecCtl_t **handle, const char *arg);
int __pmProcessUnpickArgs(__pmExecCtl_t **handle,
const char *command);

int __pmProcessExec(__pmExecCtl_t **handle,
int toss, int wait);

cc ... -lpcp

ATTENTION

Cette documentation est destinée à un usage interne par les développeurs de Performance Co-Pilot (PCP).

Ces interfaces ne font pas partie des API PCP dont la stabilité est garantie d'une version à l'autre, et elles pourraient ne pas fonctionner, ou avoir une sémantique différente à un moment donné dans le futur.

DESCRIPTION

Au sein des bibliothèques et applications de Performance Co-Pilot (PCP), ces routines fournissent une alternative pratique et sûre à system(3) pour exécuter des commandes dans un processus séparé.

Utilisez __pmProcessAddArg pour enregistrer l'exécutable et les arguments de la commande dans l'ordre. handle doit être défini à NULL avant le premier appel à __pmProcessAddArg pour une exécution de commande donnée. Il sera ensuite défini à un pointeur opaque vers des structures de données qui sont manipulées dans __pmProcessAddArg, __pmProcessExec et les routines associées de __pmProcessPipe(3).

Lorsqu'il est appelé avec handle défini à NULL, arg est traité comme le nom de la commande à exécuter et les appels subséquents (s'il y en a) concernent les arguments de cette commande. Le nom de la commande peut être un chemin absolu, ou le nom d'un exécutable qui peut être trouvé dans le $PATH courant, conformément aux règles de execvp(2) utilisé par __pmProcessExec.

__pmProcessUnpickArgs est un wrapper pratique pour aider à la conversion de code qui suppose que la command est une commande shell qui a été préparée pour être utilisée avec system(3) ou popen(3) dans du code existant. Les arguments de command sont extraits un par un et utilisés pour appeler __pmProcessAddArg. L'analyseur est simple, car la routine est conçue pour une syntaxe de commande shell simple, où les arguments sont séparés par un ou plusieurs espaces, mais des espaces incorporés au sein d'un argument sont autorisés si l'argument est entouré de guillemets simples ou doubles. Une syntaxe shell plus avancée, comme les caractères d'échappement et la redirection d'entrée-sortie, n'est pas reconnue.

Une fois que le nom de la commande et tous les arguments ont été enregistrés, l'appel à __pmProcessExec utilise une séquence de fork(2) et execvp(2) pour exécuter la commande.

L'argument toss peut être utilisé pour assigner tout ou partie des flux d'entrée/sortie standard de la commande à /dev/null - spécifiquement, toss est soit PM_EXEC_TOSS_NONE pour conserver tous les flux d'E/S identiques à ceux du processus parent, soit le OU bit à bit de PM_EXEC_TOSS_STDIN et/ou PM_EXEC_TOSS_STDOUT et/ou PM_EXEC_TOSS_STDERR pour réassigner respectivement stdin, stdout et stderr. PM_EXEC_TOSS_ALL est une macro pratique équivalente à PM_EXEC_TOSS_STDIN | PM_EXEC_TOSS_STDOUT | PM_EXEC_TOSS_STDERR.

L'argument wait doit être PM_EXEC_WAIT si __pmProcessExec doit attendre la fin de la commande et récupérer son statut de sortie, sinon PM_EXEC_NOWAIT auquel cas __pmProcessExec retourne immédiatement (exécutant effectivement la commande en arrière-plan).

Les appels imbriqués de __pmProcessExec et/ou __pmProcessPipe(3) ne sont pas autorisés. Une fois que __pmProcessAddArg est appelé avec handle défini à NULL pour démarrer la séquence d'enregistrement et d'exécution, toute tentative de démarrer une seconde séquence d'enregistrement sera bloquée jusqu'à ce que la première soit terminée en appelant __pmProcessExec ou __pmProcessPipe(3).

DIAGNOSTICS

En cas de succès, __pmProcessAddArg retourne 0. D'autres conditions sont rares (par exemple, échec d'allocation mémoire) et sont indiquées par une valeur de retour qui peut être décodée à l'aide de pmErrStr(3). Lorsqu'une erreur se produit, __pmProcessAddArg nettoie toutes les allocations effectuées lors de l'appel actuel et utilise handle pour nettoyer toutes les allocations faites par les appels précédents, de sorte que l'appelant n'a pas à se soucier des fuites de mémoire, puis (re)définit handle à NULL avant de retourner.

__pmProcessUnpickArgs retourne 0 en cas de succès. En cas de chaîne non terminée, un message est généré et PM_ERR_GENERIC est retourné. D'autres valeurs de retour inférieures à 0 indiquent une erreur plus grave et la valeur peut être décodée à l'aide de pmErrStr(3). En cas d'erreur, le nettoyage est similaire à celui de __pmProcessAddArg, de sorte que l'appelant n'a pas à se soucier des fuites de mémoire.

Le statut de retour de __pmProcessExec est plus complexe. Si PM_EXEC_NOWAIT est spécifié, ou si la commande se termine avec un statut de sortie de 0, la valeur de retour est 0. Les valeurs de retour inférieures à 0 indiquent une erreur plus grave et la valeur peut être décodée à l'aide de pmErrStr(3). Si la commande a été exécutée mais ne s'est pas terminée avec le statut 0, alors la valeur de retour est un encodage du statut de waitpid(2) comme suit : 2000 si quelque chose d'inconnu s'est mal passé, sinon si 1000 + le numéro du signal la commande a été arrêtée ou tuée par un signal, sinon le statut de sortie de la commande.

VOIR AUSSI

execvp(2), fork(2), __pmProcessPipe(3), popen(3), system(3) et waitpid(3).
