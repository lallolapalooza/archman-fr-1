_LONGJMP(3P) Manuel du programmeur POSIX _LONGJMP(3P)

PROLOGUE

Cette page de manuel fait partie du Manuel du programmeur POSIX. L'implémentation Linux de cette interface peut différer (consultez la page de manuel Linux correspondante pour les détails du comportement Linux), ou l'interface peut ne pas être implémentée sous Linux.

NOM

_longjmp, _setjmp — saut non local

SYNOPSIS

#include <setjmp.h>
void _longjmp(jmp_buf env, int val);
int _setjmp(jmp_buf env);

DESCRIPTION

Les fonctions _longjmp() et _setjmp() sont équivalentes à longjmp() et setjmp(), respectivement, avec la restriction supplémentaire que _longjmp() et _setjmp() ne manipulent pas le masque de signaux.

Si _longjmp() est appelée alors que env n'a jamais été initialisée par un appel à _setjmp(), ou lorsque le dernier appel de ce type était dans une fonction qui est depuis retournée, les résultats sont indéfinis.

VALEUR DE RETOUR

Se référer à longjmp() et setjmp().

ERREURS

Aucune erreur n'est définie.

Les sections suivantes sont informatives.

EXEMPLES

Aucun.

UTILISATION APPLICATION

Si _longjmp() est exécutée et que l'environnement dans lequel _setjmp() a été exécutée n'existe plus, des erreurs peuvent survenir. Les conditions dans lesquelles l'environnement de _setjmp() n'existe plus incluent la sortie de la fonction contenant l'appel _setjmp(), et la sortie d'un bloc interne avec stockage temporaire. Cette condition peut ne pas être détectable, dans ce cas _longjmp() se produit et, si l'environnement n'existe plus, le contenu du stockage temporaire d'un bloc interne est imprévisible. Cette condition peut également provoquer une terminaison de processus inattendue. Si la fonction est retournée, les résultats sont indéfinis.

Passer à longjmp() un pointeur vers un tampon non créé par setjmp(), passer à _longjmp() un pointeur vers un tampon non créé par _setjmp(), passer à siglongjmp() un pointeur vers un tampon non créé par sigsetjmp(), ou passer à l'une de ces trois fonctions un tampon qui a été modifié par l'utilisateur peut causer tous les problèmes listés ci-dessus, et plus encore.

Les fonctions _longjmp() et _setjmp() sont incluses pour prendre en charge les programmes écrits pour des interfaces système historiques. Les nouvelles applications devraient utiliser siglongjmp() et sigsetjmp() respectivement.

RATIONALE

Aucun.

DIRECTIONS FUTURES

Les fonctions _longjmp() et _setjmp() pourraient être supprimées dans une version future.

VOIR AUSSI

longjmp(), setjmp(), siglongjmp(), sigsetjmp()
