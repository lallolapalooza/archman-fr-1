PMPROCESSPIPE(3) Manuel des fonctions de bibliothèque PMPROCESSPIPE(3)

NOM

__pmProcessPipe, __pmProcessPipeClose - support pour l'exécution de processus à la fin d'un tube

C SYNTAXE

#include "pmapi.h"
#include "libpcp.h"

int __pmProcessPipe(__pmExecCtl_t **handle,
const char *type, int toss, FILE **fp);

int __pmProcessPipeClose(FILE *fp);

cc ... -lpcp

ATTENTION

Cette documentation est destinée à un usage interne par les développeurs de Performance Co-Pilot (PCP).

Ces interfaces ne font pas partie des API de PCP dont la stabilité est garantie d'une version à l'autre, et elles pourraient ne pas fonctionner, ou fournir des sémantiques différentes à un moment donné dans le futur.

DESCRIPTION

Au sein des bibliothèques et applications de Performance Co-Pilot (PCP), ces routines fournissent une alternative pratique et sûre à popen(3) et pclose(3) pour exécuter des commandes dans un processus séparé qui est connecté à l'appelant par un tube.

La configuration de la commande et de ses arguments est entièrement documentée dans __pmProcessAddArg(3) et est identique à la procédure utilisée pour configurer __pmProcessExec(3).

Une fois que le nom de la commande et ses arguments ont été enregistrés, l'appel à __pmProcessPipe utilise une séquence de pipe(2), fork(2) et execvp(2) pour exécuter la commande.

L'argument type doit être ``r'' pour lire depuis le tube, sinon ``w'' pour écrire dans le tube.

L'argument toss peut être utilisé pour assigner certains ou tous les flux d'E/S standard du processus à /dev/null - spécifiquement, toss est soit PM_EXEC_TOSS_NONE pour conserver tous les flux d'E/S identiques à ceux du processus parent, soit le résultat d'une opération ET bit à bit entre PM_EXEC_TOSS_STDIN et/ou PM_EXEC_TOSS_STDOUT et/ou PM_EXEC_TOSS_STDERR pour réassigner respectivement stdin, stdout et stderr. PM_EXEC_TOSS_ALL est une macro de commodité équivalente à PM_EXEC_TOSS_STDIN | PM_EXEC_TOSS_STDOUT | PM_EXEC_TOSS_STDERR.

Évidemment, certaines combinaisons de valeurs d'arguments n'ont aucun sens, par exemple type égal à ``r'' et PM_EXEC_TOSS_STDOUT défini dans toss, ou type égal à ``w'' et PM_EXEC_TOSS_STDIN défini dans type.

__pmProcessPipe retourne un flux d'E/S standard pour le tube via l'argument fp.

Une fois que l'appelant détermine que tout le travail est terminé, __pmProcessPipeClose doit être appelé.

Les appels imbriqués à __pmProcessExec(3) et/ou __pmProcessPipe ne sont pas autorisés. Une fois que __pmProcessAddArg(3) est appelé avec handle défini à NULL pour démarrer la séquence d'enregistrement et d'exécution, toute tentative de démarrer une seconde séquence d'enregistrement sera bloquée jusqu'à ce que la première soit terminée en appelant __pmProcessExec(3) ou __pmProcessPipe.

DIAGNOSTICS

En cas de succès, __pmProcessPipe retourne 0. D'autres conditions sont rares (par exemple, échec d'allocation mémoire) et sont indiquées par une valeur de retour qui peut être décodée en utilisant pmErrStr(3).

La valeur de retour de __pmProcessPipeClose est un peu plus compliquée. Si la commande se termine avec un statut de sortie de 0, la valeur de retour est 0. Les valeurs de retour inférieures à 0 indiquent une erreur plus grave et la valeur peut être décodée en utilisant pmErrStr(3). Si la commande a été exécutée, mais qu'elle n'a pas abouti avec un statut de 0, la valeur de retour est un encodage du statut de waitpid(2) comme suit : 2000 si quelque chose d'inconnu s'est mal passé, sinon si 1000 + le numéro du signal du processus tué ou arrêté par un signal, sinon le statut de sortie de la commande.

VOIR AUSSI

execvp(2), fork(2), pclose(2), pipe(2), popen(2), __pmProcessAddArg(3), __pmProcessExec(3) et waitpid(3).
