PMPARSEHOSTSPEC(3) Manuel des fonctions de bibliothèque PMPARSEHOSTSPEC(3)

NOM

__pmParseHostSpec, __pmUnparseHostSpec, __pmFreeHostSpec - analyseur uniforme de spécification d'hôte

SYNTAXE C

#include"pmapi.h"
#include"libpcp.h"

int __pmParseHostSpec(const char *string,
__pmHostSpec **hostsp, int *count, char **errmsg);

int __pmUnparseHostSpec(__pmHostSpec *hosts,
int count, char *string, size_t size);

void __pmFreeHostSpec(__pmHostSpec *hosts, int count);

cc ... -lpcp

AVERTISSEMENT

Cette documentation est destinée à un usage interne par les développeurs de Performance Co-Pilot (PCP).

Ces interfaces ne font pas partie des API de PCP qui sont garanties de rester fixes entre les versions, et elles peuvent ne pas fonctionner, ou fournir des sémantiques différentes à un moment donné dans le futur.

DESCRIPTION

__pmParseHostSpec accepte une string spécifiant l'emplacement d'un démon collecteur de métriques de performance PCP. La syntaxe des différents formats de cette string est décrite dans PCPIntro(1) où plusieurs exemples sont également présentés.

La syntaxe permet au nom d'hôte initial de pmcd(1) d'être optionnellement suivi d'une liste de numéros de port, qui seront essayés dans l'ordre lors de la connexion à pmcd sur cet hôte. La liste des numéros de port est séparée du nom d'hôte à l'aide d'un deux-points, et chaque port de la liste est séparé par une virgule.

De plus, un ou plusieurs hôtes pmproxy(1) optionnels peuvent être spécifiés (actuellement, un seul hôte proxy est supporté par les protocoles PCP). Ceux-ci sont séparés les uns des autres et du composant pmcd à l'aide du caractère @. Ceux-ci peuvent également être suivis d'une liste de ports optionnelle, utilisant la même syntaxe séparée par des virgules qu'auparavant.

__pmParseHostSpec prend une string de spécification d'hôte terminée par un caractère nul et retourne un tableau de structures __pmHostSpec, où le tableau a count entrées.

Ces structures __pmHostSpec retournées via hostsp représentent chaque hôte individuel dans la spécification string et ont la déclaration suivante :

    typedef struct {
        char    *name;       /* nom d'hôte (toujours valide) */
        int     *ports;      /* tableau de numéros de port d'hôte */
        int     nports;      /* nombre de ports dans le tableau de ports d'hôte */
    } __pmHostSpec;

__pmUnparseHostSpec effectue l'opération inverse, créant une représentation sous forme de string à partir d'un certain nombre de structures hosts. Là où le count de structures indiqué par hosts est supérieur à un, la syntaxe proxy est utilisée pour indiquer une chaîne d'hôtes proxys. La taille du tampon string fourni doit être fournie par l'appelant en utilisant le paramètre size.

VALEUR DE RETOUR

Si la string donnée est analysée avec succès, __pmParseHostSpec retourne zéro. Dans ce cas, le stockage dynamique alloué par __pmParseHostSpec peut être libéré en appelant __pmFreeHostSpec en utilisant l'adresse retournée par __pmParseHostSpec via hosts.

__pmParseHostSpec retourne PM_ERR_GENERIC et une chaîne de message d'erreur allouée dynamiquement dans errmsg, si la string donnée ne peut pas être analysée, et que le pointeur errmsg fourni par l'utilisateur n'est pas nul. Assurez-vous de free(3) la chaîne de message d'erreur dans cette situation.

En cas d'erreur, hosts n'est pas défini. En cas de succès, errmsg n'est pas défini.

En cas de succès, __pmUnparseHostSpec retourne une valeur positive indiquant le nombre de caractères écrits dans le tampon fourni. Cependant, si le tampon fourni était trop petit, un code de statut négatif de -E2BIG est retourné.
