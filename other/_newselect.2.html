DESCRIPTION

AVERTISSEMENT : select() ne peut surveiller que les descripteurs de fichiers dont le numéro est inférieur à FD_SETSIZE (1024) — une limite déraisonnablement basse pour de nombreuses applications modernes — et cette limite ne changera pas. Toutes les applications modernes devraient utiliser à la place poll(2) ou epoll(7), qui ne souffrent pas de cette limitation.

select() permet à un programme de surveiller plusieurs descripteurs de fichiers, attendant qu'un ou plusieurs descripteurs de fichiers deviennent "prêts" pour une certaine classe d'opération d'E/S (par exemple, entrée possible). Un descripteur de fichier est considéré comme prêt si une opération d'E/S correspondante (par exemple, read(2), ou un write(2) suffisamment court) peut être effectuée sans blocage.

fd_set

Un type de structure qui peut représenter un ensemble de descripteurs de fichiers. Selon POSIX, le nombre maximum de descripteurs de fichiers dans une structure fd_set est la valeur de la macro FD_SETSIZE.

Ensembles de descripteurs de fichiers

Les arguments principaux de select() sont trois "ensembles" de descripteurs de fichiers (déclarés avec le type fd_set), qui permettent à l'appelant d'attendre trois classes d'événements sur l'ensemble spécifié de descripteurs de fichiers. Chacun des arguments fd_set peut être spécifié comme NULL si aucun descripteur de fichier ne doit être surveillé pour la classe d'événements correspondante.

Attention : Au retour, chacun des ensembles de descripteurs de fichiers est modifié sur place pour indiquer quels descripteurs de fichiers sont actuellement "prêts". Ainsi, si vous utilisez select() dans une boucle, les ensembles doivent être réinitialisés avant chaque appel.

Le contenu d'un ensemble de descripteurs de fichiers peut être manipulé en utilisant les macros suivantes :

FD_ZERO()
Cette macro efface (retire tous les descripteurs de fichiers de) set. Elle devrait être utilisée comme première étape de l'initialisation d'un ensemble de descripteurs de fichiers.
FD_SET()
Cette macro ajoute le descripteur de fichier fd à set. L'ajout d'un descripteur de fichier déjà présent dans l'ensemble n'a aucun effet et ne génère pas d'erreur.
FD_CLR()
Cette macro retire le descripteur de fichier fd de set. Le retrait d'un descripteur de fichier qui n'est pas présent dans l'ensemble n'a aucun effet et ne génère pas d'erreur.
FD_ISSET()
select() modifie le contenu des ensembles selon les règles décrites ci-dessous. Après avoir appelé select(), la macro FD_ISSET() peut être utilisée pour tester si un descripteur de fichier est toujours présent dans un ensemble. FD_ISSET() renvoie une valeur non nulle si le descripteur de fichier fd est présent dans set, et zéro sinon.

Arguments

Les arguments de select() sont les suivants :

readfds
Les descripteurs de fichiers de cet ensemble sont surveillés pour voir s'ils sont prêts en lecture. Un descripteur de fichier est prêt en lecture si une opération de lecture ne bloquera pas ; en particulier, un descripteur de fichier est également prêt en cas de fin de fichier.
Après le retour de select(), readfds sera vidé de tous les descripteurs de fichiers sauf ceux qui sont prêts en lecture.
writefds
Les descripteurs de fichiers de cet ensemble sont surveillés pour voir s'ils sont prêts en écriture. Un descripteur de fichier est prêt en écriture si une opération d'écriture ne bloquera pas. Cependant, même si un descripteur de fichier indique être accessible en écriture, une écriture importante peut toujours bloquer.
Après le retour de select(), writefds sera vidé de tous les descripteurs de fichiers sauf ceux qui sont prêts en écriture.
exceptfds
Les descripteurs de fichiers de cet ensemble sont surveillés pour les "conditions exceptionnelles". Pour des exemples de conditions exceptionnelles, voir la discussion de POLLPRI dans poll(2).
Après le retour de select(), exceptfds sera vidé de tous les descripteurs de fichiers sauf ceux pour lesquels une condition exceptionnelle s'est produite.
nfds
Cet argument doit être défini au descripteur de fichier portant le numéro le plus élevé dans l'un des trois ensembles, plus 1. Les descripteurs de fichiers indiqués dans chaque ensemble sont vérifiés, jusqu'à cette limite (mais voir BUGS).
timeout
L'argument timeout est une structure timeval (montrée ci-dessous) qui spécifie l'intervalle pendant lequel select() doit bloquer en attendant qu'un descripteur de fichier devienne prêt. L'appel bloquera jusqu'à ce que :
•
un descripteur de fichier devienne prêt ;
•
l'appel soit interrompu par un gestionnaire de signal ; ou
•
le délai d'attente expire.
Notez que l'intervalle de timeout sera arrondi à la granularité de l'horloge système, et les retards de planification du noyau impliquent que l'intervalle de blocage peut dépasser légèrement le délai.
Si les deux champs de la structure timeval sont à zéro, alors select() retourne immédiatement. (Ceci est utile pour le polling.)
Si timeout est spécifié comme NULL, select() bloque indéfiniment en attendant qu'un descripteur de fichier devienne prêt.

pselect()

L'appel système pselect() permet à une application d'attendre en toute sécurité jusqu'à ce qu'un descripteur de fichier devienne prêt ou qu'un signal soit capturé.

Le fonctionnement de select() et pselect() est identique, à l'exception de ces trois différences :

•
select() utilise un délai d'attente qui est une struct timeval (avec secondes et microsecondes), tandis que pselect() utilise une struct timespec (avec secondes et nanosecondes).
•
select() peut mettre à jour l'argument timeout pour indiquer combien de temps il restait. pselect() ne modifie pas cet argument.
•
select() n'a pas d'argument sigmask et se comporte comme pselect() appelé avec sigmask NULL.

sigmask est un pointeur vers un masque de signaux (voir sigprocmask(2)) ; s'il n'est pas NULL, alors pselect() remplace d'abord le masque de signaux actuel par celui qui est fourni.

VALEUR DE RETOUR

Au succès, select() et pselect() renvoient le nombre total de descripteurs de fichiers qui sont prêts dans les ensembles (y compris les descripteurs de fichiers qui sont devenus prêts pour plus d'une classe d'E/S). Si le délai d'attente expire avant que tous les descripteurs de fichiers spécifiés ne deviennent prêts, ils renvoient 0.

En cas d'échec, -1 est renvoyé et errno est défini pour indiquer l'erreur.

Les descripteurs de fichiers prêts sont indiqués par la présence du descripteur dans l'ensemble correspondant au retour de l'appel. Si readfds est non-NULL, les descripteurs de fichiers qui sont prêts en lecture seront présents dans readfds. De même pour writefds et exceptfds.

ERREURS

EBADF

Un descripteur de fichier dans l'un des ensembles n'est pas un descripteur de fichier valide.

EINTR

Un appel interrompu par un signal. Les ensembles readfds, writefds, et exceptfds sont laissés dans un état indéfini.

EINVAL

La valeur de nfds est négative ou supérieure à la valeur maximale autorisée pour un descripteur de fichier.

ENOMEM

Un manque de mémoire système est disponible pour un usage interne.

CONFORMITÉ

Les appels système select() et pselect() sont conformes aux normes POSIX.1-2001 et POSIX.1-2008.

BOGUES

La valeur de FD_SETSIZE est fixée à 1024 par défaut. Si un programme doit surveiller plus de 1024 descripteurs de fichiers, select() échouera avec EINVAL si nfds est supérieur à FD_SETSIZE. Il est possible de remplacer cette valeur en définissant la macro FD_SETSIZE avant d'inclure ``, mais ce n'est pas recommandé. Utiliser poll(2) ou epoll(7) est préférable pour gérer un grand nombre de descripteurs de fichiers.

Le comportement de select() avec des descripteurs de fichiers qui ne sont pas ordonnables (par exemple, des pipes qui ne sont pas encore ouverts) est non spécifié par POSIX. Sur certains systèmes, ils peuvent toujours apparaître comme prêts.

La précision de timeout est limitée par la granularité de l'horloge système et les retards de planification du noyau. Elle peut être de plusieurs millisecondes.

La valeur de retour de select() peut être incorrecte si l'appelant fournit des ensembles de taille supérieure à ce que le noyau peut gérer.

Sous Linux, la valeur de nfds peut être supérieure à FD_SETSIZE, auquel cas select() échouera avec EINVAL. Ceci est une différence par rapport à d'autres implémentations Unix, où select() peut fonctionner en ignorant simplement les descripteurs de fichiers supérieurs à FD_SETSIZE.

EXEMPLE

L'exemple suivant montre comment utiliser select() pour attendre soit une entrée sur stdin, soit un délai d'expiration.

#include <stdio.h>
#include <stdlib.h>
#include <sys/select.h>
#include <sys/time.h>
#include <unistd.h>

int
main(void)
{
    fd_set read_fds;
    struct timeval tv;
    int ready_fds;
    char buf[256];

    /* Initialiser l'ensemble des descripteurs de fichiers pour la lecture */
    FD_ZERO(&read_fds);
    FD_SET(STDIN_FILENO, &read_fds); /* Surveiller stdin */

    /* Initialiser le délai d'attente */
    tv.tv_sec = 5;  /* 5 secondes */
    tv.tv_usec = 0; /* 0 microsecondes */

    printf("Veuillez entrer quelque chose dans les 5 prochaines secondes...\n");

    /* Attendre un descripteur de fichier prêt ou un délai d'expiration */
    ready_fds = select(STDIN_FILENO + 1, &read_fds, NULL, NULL, &tv);

    if (ready_fds < 0) {
        perror("select");
        exit(EXIT_FAILURE);
    } else if (ready_fds == 0) {
        printf("Délai d'attente dépassé. Aucune entrée.\n");
    } else {
        /* Vérifier si stdin est prêt */
        if (FD_ISSET(STDIN_FILENO, &read_fds)) {
            ssize_t count = read(STDIN_FILENO, buf, sizeof(buf) - 1);
            if (count < 0) {
                perror("read");
            } else if (count == 0) {
                printf("Fin de fichier détectée.\n");
            } else {
                buf[count] = '\0'; /* Terminer la chaîne */
                printf("Vous avez entré : %s", buf);
            }
        }
    }

    return 0;
}

Applications

multithreadées

Si un descripteur de fichier surveillé par select() est fermé dans un autre thread, le résultat est indéfini. Sur certains systèmes UNIX, select() se débloque et retourne, avec une indication que le descripteur de fichier est prêt (une opération d'E/S suivante échouera probablement avec une erreur, sauf si un autre processus rouvre le descripteur de fichier entre le moment où select() est retourné et le moment où l'opération d'E/S est effectuée). Sur Linux (et certains autres systèmes), fermer le descripteur de fichier dans un autre thread n'a aucun effet sur select(). En résumé, toute application qui repose sur un comportem

L'interface pselect() décrite dans cette page est implémentée par glibc. L'appel système Linux sous-jacent est nommé pselect6(). Cet appel système a un comportement quelque peu différent de celui de la fonction wrapper

glibc.

L'appel système Linux pselect6() modifie son argument timeout. Cependant, la fonction wrapper glibc masque ce comportement en utilisant une variable locale pour l'argument timeout qui est passée à l'appel système. Ainsi, la fonction glibc pselect() ne modifie pas son argument timeout ; c'est le comportement exigé par POSIX.

1-2001.

Le dernier argument de l'appel système pselect6() n'est pas un pointeur sigset_t *, mais plutôt une structure de la forme

;

BUG

S

POSIX permet à une implémentation de définir une limite supérieure, annoncée via la constante FD_SETSIZE, oDans la plage de descripteurs de fichiers qui peuvent être spécifiés dans un ensemble de descripteurs de fichiers. Le noyau Linux n'impose aucune limite fixe, mais l'implémentation glibc fait de fd_set un type de taille fixe, avec FD_SETSIZE défini sur 1024, et les macros FD_*() opérant selon cette limite. Pour surveiller les descripteurs de fichiers supérieurs à 1023, utilisez plutôt poll(2) ou epoll(7).

L'implémentation des arguments fd_set en tant qu'arguments valeur-résultat est une erreur de conception qui est évitée dans poll(2) et epoll(7).

Selon POSIX, select() doit vérifier tous les descripteurs de fichiers spécifiés dans les trois ensembles de descripteurs de fichiers, jusqu'à la limite nfds-1. Cependant, l'implémentation actuelle ignore tout descripteur de fichier dans ces ensembles qui est supérieur au numéro de descripteur de fichier maximum que le processus a actuellement ouvert. Selon POSIX, tout descripteur de fichier de ce type spécifié dans l'un des ensembles devrait entraîner l'erreur EBADF.

À partir de glibc 2.1, glibc a fourni une émulation de pselect() qui était implémentée en utilisant sigprocmask(2) et select(). Cette implémentation est restée vulnérable à la condition de concurrence même que pselect() a été conçu pour empêcher. Les versions modernes de glibc utilisent l'appel système pselect() (sans condition de concurrence) sur les noyaux où il est fourni.

Sous Linux, select() peut signaler un descripteur de fichier de socket comme étant « prêt à la lecture », tout en néanmoins une lecture ultérieure bloquant. Cela pourrait par exemple se produire lorsque des données sont arrivées mais, lors de l'examen, ont un checksum incorrect et sont discardées. Il peut y avoir d'autres circonstances dans lesquelles un descripteur de fichier est signalé à tort comme étant prêt. Il peut donc être plus sûr d'utiliser O_NONBLOCK sur les sockets qui ne devraient pas bloquer.

Sous Linux, select() modifie également timeout si l'appel est interrompu par un gestionnaire de signaux (c'est-à-dire que le retour d'erreur EINTR). Cela n'est pas autorisé par POSIX.1. L'appel système pselect() de Linux a le même comportement, mais l'enveloppe glibc masque ce comportement en copiant en interne timeout dans une variable locale et en passant cette variable à l'appel système.

EXEMPLES

#include <stdio.h>
#include <stdlib.h>
#include <sys/select.h>
#include <sys/time.h>
int
main(void)
{
    int             retval;
    fd_set          rfds;
    struct timeval  tv;
    /* Surveiller stdin (fd 0) pour voir quand il y a une entrée.  */
    FD_ZERO(&rfds);
    FD_SET(0, &rfds);
    /* Attendre jusqu'à cinq secondes.  */
    tv.tv_sec = 5;
    tv.tv_usec = 0;
    retval = select(1, &rfds, NULL, NULL, &tv);
    /* Ne vous fiez pas à la valeur de tv maintenant ! */
    if (retval == -1)
        perror("select()");
    else if (retval)
        printf("Des données sont disponibles maintenant.\n");
        /* FD_ISSET(0, &rfds) sera vrai.  */
    else
        printf("Pas de données dans les cinq secondes.\n");
    exit(EXIT_SUCCESS);
}
