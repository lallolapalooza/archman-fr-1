OSSL_PARAM_allocate_from_text(3ssl)

Paquet: openssl

OSSL_PARAM_allocate_from_text(3ssl) OpenSSL OSSL_PARAM_allocate_from_text(3ssl)

NOM

OSSL_PARAM_allocate_from_text - Utilitaires pour la construction d'OSSL_PARAM

SYNTAXE

#include <openssl/params.h>
int OSSL_PARAM_allocate_from_text(OSSL_PARAM *to,
                                  const OSSL_PARAM *paramdefs,
                                  const char *key, const char *value,
                                  size_t value_n,
                                  int *found);

DESCRIPTION

Avant OpenSSL version 3.0, les paramètres étaient passés ou récupérés des implémentations d'algorithmes via des fonctions de contrôle. Certaines de ces fonctions de contrôle existaient sous des variations qui acceptaient des paramètres textuels, par exemple EVP_PKEY_CTX_ctrl_str(3).

OpenSSL 3.0 introduit un nouveau mécanisme pour faire la même chose avec un ensemble de paramètres contenant un nom, une valeur, un type de valeur et une taille de valeur (voir OSSL_PARAM(3) pour plus d'informations).

OSSL_PARAM_allocate_from_text() utilise key pour rechercher un élément dans paramdefs. Si un élément est trouvé, il convertit value en quelque chose d'approprié pour le type de valeur de l'élément trouvé, et stocke le résultat dans to->data ainsi que sa taille dans to->data_size. to->key et to->data_type reçoivent les valeurs correspondantes de l'élément trouvé, et to->return_size est mis à zéro.

to->data est toujours alloué avec OPENSSL_zalloc(3) et doit être libéré par l'appelant lorsqu'il n'est plus utilisé, en utilisant OPENSSL_free(3).

Si found n'est pas nul, *found est mis à 1 si key peut être trouvé dans paramdefs, et à 0 sinon.

Utilisation détaillée de key et value

OSSL_PARAM_allocate_from_text() prend en compte si key commence par "hex" et n'utilise que le reste de key pour rechercher un élément dans paramdefs dans ce cas. Par exemple, si key est "hexid", "id" est recherché dans paramdefs.

Lorsqu'un élément dans paramdefs a été trouvé, value est converti selon le type de valeur de l'élément trouvé, comme suit :

OSSL_PARAM_INTEGER et OSSL_PARAM_UNSIGNED_INTEGER
Si key ne commençait pas par "hex", value est supposé contenir value_n caractères décimaux, qui sont décodés, et les octets résultants sont convertis en nombre stocké dans la mémoire de to->data.

Si value commence par "0x", il est supposé contenir value_n caractères hexadécimaux.

Si key commençait par "hex", value est supposé contenir value_n caractères hexadécimaux sans le préfixe "0x".

Si value contient des caractères qui ne peuvent pas être décodés en hexadécimal ou décimal, OSSL_PARAM_allocate_from_text() considère cela comme une erreur.

OSSL_PARAM_UTF8_STRING
Si key commençait par "hex", OSSL_PARAM_allocate_from_text() considère cela comme une erreur.

Sinon, value est considéré comme une chaîne C et est copié dans la mémoire de to->data. Sur les systèmes où le jeu de caractères natif est EBCDIC, les octets dans to->data sont convertis en ASCII.

OSSL_PARAM_OCTET_STRING
Si key commençait par "hex", value est supposé contenir value_n caractères hexadécimaux, qui sont décodés, et les octets résultants sont stockés dans la mémoire de to->data. Si value contient des caractères qui ne peuvent pas être décodés en hexadécimal ou décimal, OSSL_PARAM_allocate_from_text() considère cela comme une erreur.

Si key ne commençait pas par "hex", value_n octets de value sont copiés dans la mémoire de to->data.

VALEURS DE RETOUR

OSSL_PARAM_allocate_from_text() retourne 1 si key est trouvé dans paramdefs et qu'il n'y a pas d'autres erreurs, sinon 0.

NOTES

Le tableau de description des paramètres provient de fonctions dédiées à leur retour. Les attributs OSSL_PARAM(3) suivants sont utilisés :

key
data_type
data_size

Tous les autres attributs sont ignorés.

L'attribut data_size peut être zéro, ce qui signifie que le paramètre décrit est censé avoir des données de n'importe quelle longueur.

EXEMPLES

Le code qui ressemblait à ceci :

int mac_ctrl_string(EVP_PKEY_CTX *ctx, const char *value)
{
    int rv;
    char *stmp, *vtmp = NULL;
    stmp = OPENSSL_strdup(value);
    if (stmp == NULL)
        return -1;
    vtmp = strchr(stmp, ':');
    if (vtmp != NULL)
        *vtmp++ = '\0';
    rv = EVP_MAC_ctrl_str(ctx, stmp, vtmp);
    OPENSSL_free(stmp);
    return rv;
}
...
for (i = 0; i < sk_OPENSSL_STRING_num(macopts); i++) {
    char *macopt = sk_OPENSSL_STRING_value(macopts, i);
    if (pkey_ctrl_string(mac_ctx, macopt) <= 0) {
        BIO_printf(bio_err,
                   "MAC parameter error \"%s\"\n", macopt);
        ERR_print_errors(bio_err);
        goto mac_end;
    }
}

Peut être écrit comme ceci à la place :

 OSSL_PARAM *params =
     OPENSSL_zalloc(sizeof(*params)
                    * (sk_OPENSSL_STRING_num(opts) + 1));
 const OSSL_PARAM *paramdefs = EVP_MAC_settable_ctx_params(mac);
 size_t params_n;
 char *opt = "<unknown>";
 for (params_n = 0; params_n < (size_t)sk_OPENSSL_STRING_num(opts);
      params_n++) {
     char *stmp, *vtmp = NULL;
     opt = sk_OPENSSL_STRING_value(opts, (int)params_n);
     if ((stmp = OPENSSL_strdup(opt)) == NULL
             || (vtmp = strchr(stmp, ':')) == NULL)
         goto err;
     *vtmp++ = '\0';
     if (!OSSL_PARAM_allocate_from_text(&params[params_n],
                                        paramdefs, stmp,
                                        vtmp, strlen(vtmp), NULL))
         goto err;
 }
 params[params_n] = OSSL_PARAM_construct_end();
 if (!EVP_MAC_CTX_set_params(ctx, params))
     goto err;
 while (params_n-- > 0)
     OPENSSL_free(params[params_n].data);
 OPENSSL_free(params);
 /* ... */
 return;
err:
 BIO_printf(bio_err, "MAC parameter error '%s'\n", opt);
 ERR_print_errors(bio_err);
