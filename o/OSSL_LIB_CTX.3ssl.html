OSSL_LIB_CTX(3ssl)

OSSL_LIB_CTX(3ssl) OpenSSL OSSL_LIB_CTX(3ssl)

NOM

OSSL_LIB_CTX, OSSL_LIB_CTX_get_data, OSSL_LIB_CTX_new, OSSL_LIB_CTX_new_from_dispatch, OSSL_LIB_CTX_new_child, OSSL_LIB_CTX_free, OSSL_LIB_CTX_load_config, OSSL_LIB_CTX_get0_global_default, OSSL_LIB_CTX_set0_default - Contexte de bibliothèque OpenSSL

SYNOPSIS

#include <openssl/crypto.h>
typedef struct ossl_lib_ctx_st OSSL_LIB_CTX;
OSSL_LIB_CTX *OSSL_LIB_CTX_new(void);
OSSL_LIB_CTX *OSSL_LIB_CTX_new_from_dispatch(const OSSL_CORE_HANDLE *handle,
                                             const OSSL_DISPATCH *in);
OSSL_LIB_CTX *OSSL_LIB_CTX_new_child(const OSSL_CORE_HANDLE *handle,
                                     const OSSL_DISPATCH *in);
int OSSL_LIB_CTX_load_config(OSSL_LIB_CTX *ctx, const char *config_file);
void OSSL_LIB_CTX_free(OSSL_LIB_CTX *ctx);
OSSL_LIB_CTX *OSSL_LIB_CTX_get0_global_default(void);
OSSL_LIB_CTX *OSSL_LIB_CTX_set0_default(OSSL_LIB_CTX *ctx);
void *OSSL_LIB_CTX_get_data(OSSL_LIB_CTX *ctx, int index);

DESCRIPTION

OSSL_LIB_CTX est un type de contexte de bibliothèque interne d'OpenSSL. Les applications peuvent créer leurs propres contextes, mais peuvent également utiliser NULL pour utiliser un contexte par défaut avec les fonctions qui acceptent un OSSL_LIB_CTX comme argument.

Lorsqu'un contexte de bibliothèque non par défaut est utilisé, des précautions doivent être prises dans les applications multithread pour nettoyer les ressources locales aux threads avant de libérer l'OSSL_LIB_CTX. Voir OPENSSL_thread_stop_ex(3) pour plus d'informations.

OSSL_LIB_CTX_new() crée un nouveau contexte de bibliothèque OpenSSL.

OSSL_LIB_CTX_new_from_dispatch() crée un nouveau contexte de bibliothèque OpenSSL initialisé avec des rappels de la structure OSSL_DISPATCH. Ceci est principalement utile pour les auteurs de fournisseurs. Les arguments handle et dispatch doivent être les mêmes que ceux passés à la fonction OSSL_provider_init d'un fournisseur. Certaines fonctions OpenSSL, telles que BIO_new_from_core_bio(3), nécessitent la création du contexte de bibliothèque de cette manière pour fonctionner.

OSSL_LIB_CTX_new_child() est utile uniquement pour les auteurs de fournisseurs et fait la même chose que OSSL_LIB_CTX_new_from_dispatch(), mais rattache le nouveau contexte de bibliothèque au contexte de bibliothèque de l'application. Le nouveau contexte de bibliothèque est un contexte de bibliothèque complet en soi, mais il aura tous les mêmes fournisseurs disponibles que ceux disponibles dans le contexte de bibliothèque de l'application (sans avoir à les recharger). Si l'application charge ou décharge des fournisseurs à partir du contexte de bibliothèque de l'application, cela se reflétera automatiquement dans le contexte de bibliothèque enfant.

Outre les fournisseurs, le contexte de bibliothèque enfant examine également les propriétés par défaut (définies via EVP_set_default_properties(3)) de la bibliothèque parente de l'application. Si EVP_set_default_properties(3) est appelé directement sur le contexte de bibliothèque enfant, les nouvelles propriétés remplaceront celles de la bibliothèque parente de l'application et la recherche des propriétés s'arrêtera.

Lorsque OSSL_LIB_CTX_new_child() est appelé dans le cadre de la fonction OSSL_provider_init d'un fournisseur, le fournisseur actuel n'est pas encore disponible dans le contexte de bibliothèque de l'application et ne sera donc pas disponible dans le nouveau contexte de bibliothèque enfant. Une fois que OSSL_provider_init est revenu, le nouveau fournisseur sera disponible dans le contexte de bibliothèque de l'application et se reflétera dans le nouveau contexte de bibliothèque enfant.

OSSL_LIB_CTX_load_config() charge un fichier de configuration en utilisant le contexte ctx. Cela peut être utilisé pour associer un contexte de bibliothèque à des fournisseurs chargés à partir d'une configuration. Cette fonction ne doit pas être appelée simultanément depuis plusieurs threads sur le même ctx.

OSSL_LIB_CTX_free() libère le contexte ctx, sauf s'il s'agit du contexte par défaut d'OpenSSL. Si l'argument est NULL, rien ne se passe.

OSSL_LIB_CTX_get0_global_default() renvoie une référence concrète (non NULL) au contexte de bibliothèque global par défaut.

OSSL_LIB_CTX_set0_default() définit le contexte de bibliothèque OpenSSL par défaut pour le thread actuel sur ctx. Le contexte par défaut précédent est renvoyé. L'appelant doit prendre soin de restaurer le contexte par défaut précédent avec un appel ultérieur à cette fonction. Si ctx est NULL, aucun changement ne sera apporté au contexte par défaut, mais un pointeur vers le contexte actuel est renvoyé. En cas d'appel réussi à cette fonction, la valeur renvoyée sera toujours un contexte de bibliothèque concret (non NULL).

Étant donné que le contexte par défaut est modifié, il faut être prudent lors du démarrage de tâches asynchrones (voir ASYNC_start_job(3)), car lors du démarrage d'une tâche asynchrone, le contexte de bibliothèque par défaut sera utilisé pendant la durée de la tâche, indépendamment de la manière dont les modifications ultérieures sont apportées dans le thread d'exécution de l'appelant. Cela signifie que le thread d'exécution de l'appelant doit éviter de libérer le contexte de bibliothèque qui était par défaut au début de la tâche asynchrone, jusqu'à ce que la tâche soit terminée.

OSSL_LIB_CTX_get_data() renvoie un pointeur vers une adresse mémoire dont l'interprétation dépend de l'indice. L'argument d'indice fait référence à un membre du contexte que vous souhaitez récupérer. Les valeurs d'indice sont actuellement privées à OpenSSL et, par conséquent, les applications ne devraient pas appeler cette fonction. Si le contexte est NULL, la fonction opère sur le contexte par défaut. OSSL_LIB_CTX_get_data() renvoie un pointeur vers une adresse mémoire dont l'interprétation dépend de l'indice.

VALEURS DE RETOUR

OSSL_LIB_CTX_new(), OSSL_LIB_CTX_get0_global_default() et OSSL_LIB_CTX_set0_default() renvoient un pointeur vers un contexte de bibliothèque en cas de succès, ou NULL en cas d'erreur.

OSSL_LIB_CTX_free() ne renvoie aucune valeur.

OSSL_LIB_CTX_load_config() renvoie 1 en cas de succès, 0 en cas d'erreur.

OSSL_LIB_CTX_get_data() renvoie un pointeur vers une adresse mémoire dont l'interprétation dépend de l'indice.

HISTORIQUE

Toutes les fonctions décrites sur cette page ont été ajoutées dans OpenSSL 3.0.

OSSL_LIB_CTX_get_data() a été introduite dans OpenSSL 3.4.
