NOM

Object::Realize::Later - Création différée d'objets

SYNTAXE

package MonObjetParesseux;
use Object::Realize::Later
   becomes => 'MonVraiObjet',
   realize => 'charger';

DESCRIPTION

La classe "Object::Realize::Later" aide à implémenter la réalisation transparente à la demande des données d'un objet. Ceci est lié aux astuces de chargement automatique des données, le cousin moins connu du chargement automatique de fonctionnalités.

La réalisation à la demande vise à gagner en performance. Pourquoi dépenser un temps coûteux pour réaliser un objet, alors que les données de l'objet ne sont jamais (ou pas encore) utilisées ? Dans les programmes interactifs, la réalisation différée peut accélérer le démarrage : la réalisation des objets est déclenchée par leur utilisation, donc étalée dans le temps.

MÉTHODES

Construction

use(Object::Realize::Later %options)
Lorsque vous invoquez ("use") le package "Object::Realize::Later", il ajoutera un ensemble de méthodes à votre package (voir la section "Ajoutées à VOTRE classe"). 
-Option            --Défaut
 becomes             <requis>
 believe_caller      <faux>
 realize             <requis>
 source_module       <becomes>
 warn_realization    <faux>
 warn_realize_again  <faux>
becomes => CLASSE
Quel type cet objet deviendra après la réalisation.
believe_caller => BOOLEEN
Lorsqu'une méthode est appelée sur l'objet non réalisé, AUTOLOAD vérifie si cela résout le besoin. Sinon, la réalisation n'est pas effectuée. Cependant, lorsque la réalisation peut entraîner un objet qui étend les fonctionnalités de la classe spécifiée avec "becomes", cette vérification doit être désactivée. Dans ce cas, spécifiez vrai pour cette option.
realize => MÉTHODE|CODE
Comment transformer. Si vous spécifiez une référence de code, alors celle-ci sera appelée avec l'objet paresseux comme premier argument, et la méthode demandée comme second.

Après la réalisation, vous pouvez toujours avoir l'objet paresseux entre les mains à divers endroits. Assurez-vous que votre méthode de réalisation gère cela, par exemple en utilisant Memoize. Voir les exemples ci-dessous.

source_module => CLASSE
Si la classe (un package) est incluse dans un fichier (module) portant un nom différent, utilisez alors cet argument pour spécifier le nom du fichier. Le nom attendu est le même que celui utilisé dans l'appel "require" qui le chargerait.
warn_realization => BOOLEEN
Affiche un message d'avertissement lorsque la réalisation commence. Ceci est à des fins de débogage.
warn_realize_again => BOOLEEN
Lorsqu'un objet est réalisé, l'objet d'origine -qui fonctionnait comme un stub- est reconstruit pour servir de proxy à l'objet réalisé. Cette option émettra un avertissement lorsque ce proxy est utilisé, ce qui signifie qu'une variable quelque part dans votre programme détient encore une référence au stub. Ce dernier n'est pas problématique du tout, bien que cela ralentisse chaque appel de méthode.

Ajoutées à VOTRE classe

$obj->AUTOLOAD()
Lorsqu'une méthode est appelée qui n'est pas disponible pour l'objet paresseux, AUTOLOAD est appelée.
$obj->can($method)
Object::Realize::Later->can($method)
La méthode spécifiée $method est-elle disponible pour la version paresseuse ou réalisée de cet objet ? Elle retournera la référence au code.

exemple:

MonObjetParesseux->can('travailParesseux')      # vrai
MonObjetParesseux->can('travailRéel')      # vrai
my $paresseux = MonObjetParesseux->new;
$paresseux->can('travailParesseux');            # vrai
$paresseux->can('travailRéel');            # vrai
$obj->forceRealize()
Vous pouvez forcer le chargement en appelant cette méthode sur votre objet. Elle retourne l'objet réalisé.
Object::Realize::Later->isa($class)
Cet objet est-il une (sous-)classe de la classe spécifiée $class ou peut-il devenir une (sous-)classe de $class.

exemple:

MonObjetParesseux->isa('MonVraiObjet')      # vrai
MonObjetParesseux->isa('SuperClasseDeParesseux'); # vrai
MonObjetParesseux->isa('SuperClasseDeVrai'); # vrai
my $paresseux = MonObjetParesseux->new;
$paresseux->isa('MonVraiObjet');            # vrai
$paresseux->isa('SuperClasseDeParesseux');        # vrai
$paresseux->isa('SuperClasseDeVrai');        # vrai
$obj->willRealize()
Retourne quelle classe sera réalisée pour succéder à cette classe.

Internals de Object::Realize::Later

Les méthodes suivantes ne sont pas exportées vers la classe où le `use' a eu lieu. Ces méthodes implémentent la réalisation réelle.

Object::Realize::Later->import(%options)
Les %options utilisées pour "import" sont les valeurs après le nom de la classe avec "use". Cette routine implémente donc l'analyse réelle des options. Elle génère du code dynamiquement, qui est ensuite évalué dans l'espace de noms de l'appelant.
Object::Realize::Later->realizationOf( $objet, [$réalisé] )
Retourne la version $réalisé de $objet, éventuellement après l'avoir définie auparavant. Lorsque la méthode retourne "undef", la réalisation n'a pas encore eu lieu ou l'objet réalisé a déjà été supprimé.
Object::Realize::Later->realize(%options)
Cette méthode est appelée lorsqu'une "$objet-"forceRealize()> a lieu. Elle vérifie si la réalisation a déjà été effectuée (auquel cas l'objet réalisé est retourné).

DÉTAILS

À propos du chargement paresseux

Il existe deux façons d'implémenter un comportement paresseux : vous pouvez choisir de vérifier si vous avez réalisé les données dans chaque méthode qui accède aux données, ou utiliser l'astuce du chargement automatique des données.

Une implémentation de la première solution est :

sub realize {
    my $self = shift;
    return $self unless $self->{_is_realized};
    # lire les données du fichier, ou autre
    $self->{data} = ....;
    $self->{_is_realized} = 1;
    $self;
}
sub getData() {
    my $self = shift;
    return $self->realize->{data};
}

L'implémentation ci-dessus est sujette aux erreurs, car vous pouvez facilement oublier d'appeler realize(). Les tests ne peuvent pas couvrir toutes les ordonnances d'appels de méthodes pour détecter les erreurs.

La *seconde approche* utilise le chargement automatique et est supportée par ce package. D'abord, nous créons un objet stub, qui sera transformable en un objet réalisé plus tard. Cette transformation est déclenchée par AUTOLOAD.

Cet objet stub peut contenir certaines méthodes de l'objet réalisé, afin de réduire le besoin de réalisation. Le stub contiendra également certaines informations nécessaires à la création du véritable objet.

NOM

Object::Realize::Later

SYNOPSIS

use Object::Realize::Later;

DESCRIPTION

Object::Realize::Later est un module Perl qui permet le chargement différé d'objets, permettant une gestion efficace de grandes structures de données en reportant le chargement des objets jusqu'à ce qu'ils soient nécessaires.

METHODES

Le module fournit des méthodes pour retarder la réalisation des objets. Ces méthodes permettent le chargement différé des objets, ce qui est particulièrement utile dans les scénarios où les données complètes d'un objet ne sont pas nécessaires tant qu'elles ne sont pas consultées.

DETAILS

Le module permet la réalisation des objets de manière différée. Cette approche garantit que les objets ne sont pas chargés tant qu'ils ne sont pas nécessaires, ce qui peut améliorer les performances des applications où les données ne sont pas requises immédiatement.

EXEMPLES

Exemple 1

Dans le premier exemple, nous chargeons un message de manière différée. Au moment où le message est défini, nous ne prenons que l'emplacement. Lorsque les données du message sont récupérées (en-tête ou corps), les données sont chargées automatiquement.

package Mail::Message::Delayed;
use Object::Realize::Later
  ( becomes => 'Mail::Message::Real'
  , realize => 'loadMessage'
  );
sub new($) {
    my ($class, $file) = @_;
    bless { filename => $file }, $class;
}
sub loadMessage() {
    my $self = shift;
    Mail::Message::Real->new($self->{filename});
}

Dans le programme principal :

package main;
use Mail::Message::Delayed;
my $msg    = Mail::Message::Delayed->new('/home/user/mh/1');
$msg->body->print;     # ceci déclenchera le chargement automatique.

Exemple 2

Votre réalisation peut également se faire par reblessisation. Dans ce cas, pour changer le type de votre objet en un type différent qui stocke les mêmes informations. Est-ce correct ? Êtes-vous sûr ? Pour des cas simples, cela peut être possible :

package Alive;
use Object::Realize::Later
     becomes => 'Dead',
     realize => 'kill';
sub new()         {my $class = shift; bless {@_}, $class}
sub jump()        {print "Jump!\n"}
sub showAntlers() {print "Fight!\n"}
sub kill()        {bless(shift, 'Dead')}
package Dead;
sub takeAntlers() {...}

Dans le programme principal :

my $deer   = Alive->new(Animal => 'deer');
my $trophy = $deer->takeAntlers();

Dans cette situation, l'objet (référence) n'est pas modifié mais est *reblessé*. Il n'y a aucun danger que la version non réalisée de l'objet soit conservée quelque part : toutes les variables qui connaissent ce *cerf* particulier voient le changement.

Exemple 3

Ce module est particulièrement utile pour les projets plus importants, où il y a un besoin de rapidité ou de réduction de mémoire. Dans ce cas, vous pouvez avoir un aperçu supplémentaire des objets qui ont été réalisés (transformés) et de ceux qui ne l'ont pas été. Cet exemple est tiré des modules MailBox :

Le module Mail::Box tente d'accélérer le temps d'accès à un dossier. Si vous n'avez besoin que des messages du dernier jour, pourquoi tout lire ? Ainsi, MailBox ne crée d'abord qu'un inventaire des messages. Il prend les en-têtes de tous les messages, mais laisse le corps (contenu) du message dans le fichier.

Dans le cas de MailBox, l'objet Mail::Message a le choix entre un certain nombre de Mail::Message::Body, dont l'un a seulement été préparé pour lire le corps lorsque nécessaire. Un extrait de code :

package Mail::Message;
sub new($$)
{   my ($class, $head, $body) = @_;
    my $self = bless {head => $head, body => $body}, $class;
    $body->message($self);          # dit au corps quel est le message
}
sub head()     { shift->{head} }
sub body()     { shift->{body} }
sub loadBody()
{   my $self = shift;
    my $body = $self->body;
    # Capture les révocations du chargement. Si n'importe où il y avait encore
    # une référence à l'ancien corps (non réalisé) de ce message, nous
    # retournons directement le nouveau.
    return $body unless $body->can('forceRealize');
    # Charge le corps (le change en quelque chose qui est réellement
    # du type promis, ou une sous-classe de celui-ci.
    my ($lines, $size) = .......;    # récupère les données
    $self->{body} = Mail::Message::Body::Lines
                         ->new($lines, $size, $self);
    # Retourne l'objet réalisé.
    return $self->{body};
}
package Mail::Message::Body::Lines;
use base 'Mail::Message::Body';
sub new($$$)
{   my ($class, $lines, $size, $message) = @_;
    bless { lines => $lines, size => $size
          , message => $message }, $class;
}
sub size()    { shift->{size} }
sub lines()   { shift->{lines} }
sub message() { shift->{message);
package Mail::Message::Body::Delayed;
use Object::Realize::Later
    becomes => 'Mail::Message::Body',
    realize => sub {shift->message->loadBody};
sub new($)
{   my ($class, $size) = @_;
    bless {size => $size}, $class;
}
sub size() { shift->{size} }
sub message(;$)
{   my $self = shift;
    @_ ? ($self->{message} = shift) : $self->{messages};
}
package main;
use Mail::Message;
use Mail::Message::Body::Delayed;
my $body    = Mail::Message::Body::Delayed->new(42);
my $message = Mail::Message->new($head, $body);
print $message->size;         # ne déclenchera pas la réalisation !
print $message->can('lines'); # vrai, mais pas encore de réalisation.
print $message->lines;        # réalise automatiquement.
