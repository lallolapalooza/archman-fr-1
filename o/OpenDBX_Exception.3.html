Description détaillée

Exceptions levées par les classes OpenDBX.

La plupart des appels aux méthodes des objets OpenDBX lèvent une exception en cas d'erreur dans la bibliothèque de base de données sous-jacente. En plus des autres exceptions qui héritent de la classe d'exception STL, elles contiendront non seulement un message d'erreur traduit selon les paramètres de l'utilisateur, mais aussi un code d'erreur lisible par machine et un indicateur de la sévérité de l'erreur.

Documentation Constructeur & Destructeur

OpenDBX::Exception::Exception (const string & msg, int err, int type)

Initialise l'objet exception. Le premier paramètre, le message d'erreur, doit être la description lisible par l'homme de ce qui s'est mal passé. Il doit également être déjà traduit dans la langue de l'utilisateur, ce qui dépend des paramètres de son environnement lorsque, par exemple, GNU gettext est utilisé. Les erreurs levées par la bibliothèque C++ OpenDBX sont déjà traduites.

Le code d'erreur OpenDBX est le code lisible par machine pour l'erreur qui s'est produite.

Le dernier paramètre doit être une valeur indiquant la sévérité de l'erreur levée. Si la valeur est inférieure à zéro, l'erreur est fatale et la connexion à la base de données ne peut pas être récupérée et doit être fermée et rouverte avant que l'application ne puisse essayer de continuer. Si elle est supérieure à zéro, l'opération a échoué mais la connexion à la base de données est toujours utilisable. Zéro représente une opération réussie et ne doit pas être utilisé car une exception ne doit être levée que dans des conditions d'erreur.

Paramètres

msg Message d'erreur lisible par l'homme
err Code d'erreur OpenDBX
type Sévérité de l'erreur (négatif : fatal, zéro : succès, positif : avertissement)

Documentation des fonctions membres

int OpenDBX::Exception::getCode () const

Retourne le code d'erreur OpenDBX lié à l'erreur. Le code lisible par machine décrivant l'erreur qui s'est produite peut être utilisé par l'application pour agir différemment en fonction de l'erreur spécifique. Les codes actuellement définis sont :

  • ODBX_ERR_SUCCESS
    L'opération s'est terminée avec succès.
  • ODBX_ERR_BACKEND
    Une erreur s'est produite dans la bibliothèque de base de données native ou dans le serveur de base de données.
  • ODBX_ERR_NOCAP
    La capacité n'est pas disponible dans le backend actuellement sélectionné.
  • ODBX_ERR_PARAM
    L'un des paramètres fournis est invalide et ne correspond pas aux attentes.
  • ODBX_ERR_NOMEM
    Une condition de manque de mémoire s'est produite.
  • ODBX_ERR_SIZE
    La mémoire allouée en interne est incapable de stocker la valeur.
  • ODBX_ERR_NOTEXIST
    La bibliothèque backend n'a pas été trouvée ou le chargement de la bibliothèque a échoué.
  • ODBX_ERR_NOOP
    La fonction requise n'est pas disponible ou l'opération n'est pas possible dans ce backend.
  • ODBX_ERR_OPTION
    L'option fournie est inconnue et donc invalide.
  • ODBX_ERR_OPTRO
    L'option demandée est en lecture seule et sa valeur ne peut pas être modifiée.
  • ODBX_ERR_OPTWR
    La définition de l'option donnée à la nouvelle valeur a échoué.
  • ODBX_ERR_RESULT
    L'attente du jeu de résultats après l'envoi d'une instruction au serveur de base de données a échoué.
  • ODBX_ERR_NOTSUP
    La fonctionnalité demandée n'est pas prise en charge par le backend.
  • ODBX_ERR_HANDLE
    La structure de données interne qui doit stocker les détails d'accès à la base de données est invalide.

Retourne

Code d'erreur

int OpenDBX::Exception::getType () const

Retourne l'indicateur de sévérité. La valeur retournée classifie l'erreur levée. Si elle est négative, l'erreur est fatale (par exemple, la connexion à la base de données est perdue) et l'application ne peut pas continuer sans fermer et rouvrir la connexion.

Si la valeur est positive, la base de données n'a pas pu effectuer l'action demandée, mais la connexion est toujours OK et peut être utilisée pour envoyer d'autres requêtes à la base de données. Si elle est nulle, tout s'est bien passé et aucune erreur ne s'est produite. Cela ne devrait pas arriver lors de la capture de l'une de ces exceptions.

Retourne

Sévérité de l'erreur (négatif : fatal, zéro : succès, positif : avertissement)
