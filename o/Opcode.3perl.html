NOM

Opcode - Désactiver des opcodes nommés lors de la compilation du code Perl

SYNOPIS

use Opcode;

DESCRIPTION

Le code Perl est toujours compilé en un format interne avant son exécution.

L'évaluation de code Perl (par exemple, via "eval" ou "do 'file'") entraîne la conversion du code en un format interne et, en cas d'erreur de compilation, son exécution. Le format interne est basé sur de nombreux opcodes différents.

Par défaut, aucun opmask n'est appliqué et tout code peut être compilé.

Le module Opcode permet de définir un masque d'opcodes qui sera appliqué lors de la prochaine compilation de code par Perl. Tenter de compiler du code contenant un opcode marqué par le masque entraînera l'échec de la compilation avec une erreur. Le code ne sera pas exécuté.

NOTE

Le module Opcode n'est normalement pas utilisé directement. Consultez les pragmas ops et le module Safe pour des utilisations plus typiques.

AVERTISSEMENT

Le module Opcode n'implémente pas un bac à sable efficace pour l'évaluation de code non fiable avec l'interpréteur Perl.

Les bugs dans l'interpréteur Perl qui pourraient être exploités pour contourner les restrictions d'Opcode ne sont pas traités comme des vulnérabilités. Voir perlsecpolicy pour plus d'informations.

Les auteurs ne garantissent pas l'adéquation de ce logiciel pour la sécurité ou une utilisation sûre.

Les auteurs ne seront pas responsables des dommages spéciaux, accessoires, consécutifs, indirects ou similaires qui pourraient découler de l'utilisation de ce logiciel.

Votre performance variera. En cas de doute, ne l'utilisez pas.

Noms d'opérateurs et listes d'opérateurs

La liste canonique des noms d'opérateurs est le contenu du tableau PL_op_name défini et initialisé dans le fichier opcode.h de la distribution source de Perl (et installé dans la bibliothèque Perl).

Chaque opérateur a à la fois un nom court (son opname) et un nom plus détaillé ou reconnaissable. La fonction opdesc peut être utilisée pour renvoyer une liste de descriptions d'opérateurs données.

De nombreuses fonctions et méthodes mentionnées ici acceptent une liste d'opérateurs comme paramètres. La plupart des listes d'opérateurs peuvent consister en plusieurs types d'éléments. Chaque élément peut être l'un des suivants :

un nom d'opérateur (opname)
Les noms d'opérateurs sont généralement de courts termes en minuscules tels que enterloop, leaveloop, last, next, redo, etc. Parfois, ce sont des codes assez obscurs tels que gv2cv, i_ncmp et ftsvtx.
un nom d'étiquette d'opérateur (optag)
Les noms d'étiquettes d'opérateurs peuvent être utilisés pour faire référence à des groupes (ou ensembles) d'opérateurs. Les noms d'étiquettes commencent toujours par un signe deux-points. Le module Opcode définit plusieurs optags et l'utilisateur peut en définir d'autres en utilisant la fonction define_optag.
un nom d'opérateur ou d'étiquette d'opérateur nié
Un opérateur ou une étiquette peut être préfixé d'un point d'exclamation, par exemple, !mkdir. Nier un nom d'opérateur ou d'étiquette signifie supprimer les opérateurs correspondants de la collection en cours d'accumulation.
un ensemble d'opérateurs (opset)
Un opset est une chaîne binaire d'environ 44 octets contenant un ensemble de zéro ou plusieurs opérateurs.

Les fonctions opset et opset_to_ops peuvent être utilisées pour convertir une liste d'opérateurs en un opset et vice versa.

Là où une liste d'opérateurs peut être fournie, un ou plusieurs opsets peuvent être utilisés. Voir également la manipulation d'opsets ci-dessous.

Fonctions Opcode

Le paquet Opcode contient des fonctions pour manipuler les noms d'opérateurs, les étiquettes et les ensembles d'opérateurs. Toutes sont disponibles à l'exportation par le paquet.

opcodes
Dans un contexte scalaire, renvoie le nombre d'opcodes dans cette version de Perl (environ 350 pour perl-5.7.0). Dans un contexte de liste, renvoie une liste de tous les noms d'opérateurs. (Pas encore implémenté, utilisez @names = opset_to_ops(full_opset)).
opset (OP, ...)
Renvoie un opset contenant les opérateurs indiqués.
opset_to_ops (OPSET)
Renvoie une liste de noms d'opérateurs correspondant aux opérateurs de l'ensemble.
opset_to_hex (OPSET)
Renvoie une représentation sous forme de chaîne hexadécimale d'un opset. Peut être utile pour le débogage.
full_opset
Renvoie un opset contenant tous les opérateurs.
empty_opset
Renvoie un opset ne contenant aucun opérateur.
invert_opset (OPSET)
Renvoie un opset qui est l'inverse de celui fourni.
verify_opset (OPSET, ...)
Renvoie vrai si l'ensemble d'opérateurs fourni semble valide (c'est-à-dire qu'il a la bonne longueur, etc.). Sinon, renvoie faux. Si le deuxième paramètre est vrai, verify_opset lèvera une erreur si l'ensemble d'opérateurs est invalide. Les fonctions Opcode restantes appellent automatiquement verify_opset et lèveront une erreur si un ensemble d'opérateurs invalide leur est transmis.
define_optag (OPTAG, OPSET)
Définit OPTAG comme un nom symbolique pour OPSET. Les noms d'optag commencent toujours par un signe deux-points ":".

Le nom d'optag utilisé ne doit pas déjà être défini (define_optag lèvera une erreur s'il est déjà défini). Les noms d'optag sont globaux pour le processus Perl et ne peuvent pas être modifiés ou supprimés une fois définis.

Il est recommandé que les applications utilisant Opcode utilisent un nom d'étiquette commençant par une majuscule, car les noms en minuscules sont réservés au module Opcode. Si vous utilisez Opcode au sein d'un module, il est recommandé de préfixer les noms d'étiquettes avec le nom du module pour garantir l'unicité et éviter les conflits avec d'autres modules.

Manipulation des Opsets

Les opsets peuvent être manipulés en utilisant les opérateurs bit à bit & (et), | (ou), ^ (xor) et ~ (négation/inversion).

Cependant, vous ne devez jamais dépendre de la position numérique d'un opcode dans l'opset. En d'autres termes, les deux côtés d'un opérateur bit à bit doivent être des opsets renvoyés par les fonctions Opcode.

De plus, comme le nombre d'opcodes dans la version actuelle de Perl peut ne pas être un multiple exact de huit, il peut y avoir des bits inutilisés dans le dernier octet d'un opset. Cela ne causera pas de problèmes (les fonctions Opcode ignorent ces bits supplémentaires), mais cela signifie que l'opérateur ~ ne produira généralement pas le même 'string' d'opset 'physique' que la fonction invert_opset.

À FAIRE (peut-être)

$bool = opset_eq($opset1, $opset2)  vrai si les opsets sont logiquement équivalents
$yes = opset_can($opset, @ops)      vrai si
$opset a tous les @ops définis @diff = opset_diff($opset1, $opset2) => ('foo', '!bar', ...)

:base_mem
Ces ops liés à la mémoire ne sont pas inclus dans :base_core car ils peuvent facilement être utilisés pour implémenter une attaque par épuisement des ressources (par exemple, consommer toute la mémoire disponible). 
concat multiconcat repeat join range
anonlist anonhash

Notez que malgré l'existence de ce tag d'options, une attaque par épuisement des ressources mémoire peut toujours être possible en utilisant uniquement les ops de :base_core.

La désactivation de ces ops est une manière *très* radicale de tenter de prévenir une attaque par épuisement des ressources mémoire. Il est probable qu'un mécanisme de limitation de la mémoire soit ajouté à Perl dans un avenir proche.

:base_loop
Ces ops de boucles ne sont pas inclus dans :base_core car ils peuvent facilement être utilisés pour implémenter une attaque par épuisement des ressources (par exemple, consommer tout le temps CPU disponible).

:base_io
Ces ops activent l'entrée et la sortie basées sur les *descripteurs de fichier* (plutôt que sur les noms de fichiers). Ils sont sûrs à condition que seuls des descripteurs de fichier préexistants soient disponibles. Habituellement, pour créer de nouveaux descripteurs de fichier, d'autres ops comme 'open' devraient être activés, si l'on ne tient pas compte de l'ouverture magique de ARGV.

:browse
Un nom de tag pratique pour un ensemble *raisonnable* d'ops par défaut au-delà du tag d'options :default. Comme :default (et en fait tous les autres tags d'options), sa définition actuelle est instable pendant que le développement se poursuit. Elle changera.

Le tag :browse représente la prochaine étape au-delà de :default. C'est un sur-ensemble des ops de :default et ajoute :filesys_read et :sys_db. L'intention étant que les scripts puissent accéder à plus d'informations (potentiellement sensibles) sur votre système mais sans pouvoir le modifier.
