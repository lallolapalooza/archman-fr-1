NOM

OPENSSL_config, OPENSSL_no_config - fonctions simples de configuration OpenSSL

SYNTAXE

#include <openssl/conf.h>

Les fonctions suivantes sont obsolètes depuis OpenSSL 1.1.0, et peuvent être entièrement masquées en définissant OPENSSL_API_COMPAT avec une valeur de version appropriée, voir openssl_user_macros(7) :

void OPENSSL_config(const char *appname);
void OPENSSL_no_config(void);

DESCRIPTION

OPENSSL_config() configure OpenSSL en utilisant le fichier standard openssl.cnf et lit depuis la section de l'application appname. Si appname est NULL, la section par défaut, openssl_conf, sera utilisée. Les erreurs sont ignorées silencieusement. Les appels multiples n'ont aucun effet.

OPENSSL_no_config() désactive la configuration. Si elle est appelée avant OPENSSL_config(), aucune configuration n'a lieu.

Si l'application est compilée avec OPENSSL_LOAD_CONF défini, alors un appel à OpenSSL_add_all_algorithms() appellera implicitement OPENSSL_config() en premier.

NOTES

La fonction OPENSSL_config() est conçue pour être une fonction très simple de type « appelez-la et oubliez-la ». Elle est cependant bien mieux que rien. Les applications qui ont besoin d'un contrôle plus fin sur leur fonctionnalité de configuration devraient utiliser directement les fonctions de configuration telles que CONF_modules_load(). Cette fonction est obsolète et son utilisation devrait être évitée. Les applications devraient plutôt appeler CONF_modules_load() lors de l'initialisation (c'est-à-dire avant de démarrer des threads).

Il existe plusieurs raisons pour lesquelles l'appel des routines de configuration OpenSSL est conseillé. Par exemple, pour charger des modules ENGINE dynamiques depuis des bibliothèques partagées (DSO). Cependant, très peu d'applications prennent actuellement en charge l'interface de contrôle et donc très peu peuvent charger et utiliser des modules ENGINE dynamiques. De même, à l'avenir, des modules ENGINE plus sophistiqués nécessiteront certaines opérations de contrôle pour les personnaliser. Si une application appelle OPENSSL_config(), elle n'a pas besoin de connaître ou de se soucier des opérations de contrôle des modules ENGINE car elles peuvent être effectuées en modifiant un fichier de configuration.

ENVIRONNEMENT

OPENSSL_CONF
Le chemin vers le fichier de configuration. Ignoré dans les programmes exécutés avec les privilèges de l'utilisateur ou du groupe modifiés.

VALEURS DE RETOUR

Ni OPENSSL_config() ni OPENSSL_no_config() ne renvoient de valeur.

VOIR AUSSI

config(5), CONF_modules_load_file(3)

HISTORIQUE

Les fonctions OPENSSL_no_config() et OPENSSL_config() ont été déclarées obsolètes dans OpenSSL 1.1.0 par OPENSSL_init_crypto().
