NOM

OSSL_HTTP_open, OSSL_HTTP_bio_cb_t, OSSL_HTTP_proxy_connect, OSSL_HTTP_set1_request, OSSL_HTTP_exchange, OSSL_HTTP_get, OSSL_HTTP_transfer, OSSL_HTTP_close - Fonctions de haut niveau pour client HTTP

SYNOPSIS

#include <openssl/http.h>
typedef BIO *(*OSSL_HTTP_bio_cb_t)(BIO *bio, void *arg,
                                   int connect, int detail);
OSSL_HTTP_REQ_CTX *OSSL_HTTP_open(const char *server, const char *port,
                                  const char *proxy, const char *no_proxy,
                                  int use_ssl, BIO *bio, BIO *rbio,
                                  OSSL_HTTP_bio_cb_t bio_update_fn, void *arg,
                                  int buf_size, int overall_timeout);
int OSSL_HTTP_proxy_connect(BIO *bio, const char *server, const char *port,
                            const char *proxyuser, const char *proxypass,
                            int timeout, BIO *bio_err, const char *prog);
int OSSL_HTTP_set1_request(OSSL_HTTP_REQ_CTX *rctx, const char *path,
                           const STACK_OF(CONF_VALUE) *headers,
                           const char *content_type, BIO *req,
                           const char *expected_content_type, int expect_asn1,
                           size_t max_resp_len, int timeout, int keep_alive);
BIO *OSSL_HTTP_exchange(OSSL_HTTP_REQ_CTX *rctx, char **redirection_url);
BIO *OSSL_HTTP_get(const char *url, const char *proxy, const char *no_proxy,
                   BIO *bio, BIO *rbio,
                   OSSL_HTTP_bio_cb_t bio_update_fn, void *arg,
                   int buf_size, const STACK_OF(CONF_VALUE) *headers,
                   const char *expected_content_type, int expect_asn1,
                   size_t max_resp_len, int timeout);
BIO *OSSL_HTTP_transfer(OSSL_HTTP_REQ_CTX **prctx,
                        const char *server, const char *port,
                        const char *path, int use_ssl,
                        const char *proxy, const char *no_proxy,
                        BIO *bio, BIO *rbio,
                        OSSL_HTTP_bio_cb_t bio_update_fn, void *arg,
                        int buf_size, const STACK_OF(CONF_VALUE) *headers,
                        const char *content_type, BIO *req,
                        const char *expected_content_type, int expect_asn1,
                        size_t max_resp_len, int timeout, int keep_alive);
int OSSL_HTTP_close(OSSL_HTTP_REQ_CTX *rctx, int ok);

DESCRIPTION

OSSL_HTTP_open() initie une session HTTP en utilisant l'argument bio, s'il n'est pas NULL, sinon connecte à un serveur donné éventuellement via un proxy proxy.

Normalement, OpenSSL compilé supporte les sockets et l'argument bio est NULL. Dans ce cas, rbio doit également être NULL et server ne doit pas être nul. La fonction crée un BIO réseau en interne en utilisant BIO_new_connect(3) pour se connecter au serveur donné et au port optionnel, par défaut 80 pour HTTP ou 443 pour HTTPS. Ce BIO interne est ensuite utilisé pour établir une connexion et échanger une ou plusieurs requêtes et réponses.

Si bio est fourni et rbio est NULL, alors ce bio est utilisé à la place. Si bio et rbio sont tous deux fournis (ce qui peut être des BIOs de mémoire, par exemple), aucune connexion explicite n'est établie, mais bio est utilisé pour écrire les requêtes et rbio pour lire les réponses. Une fois que le client a vidé bio, le serveur doit être prêt à fournir une réponse ou à indiquer une condition d'attente via rbio.

Si bio est fourni, il n'est pas permis de fournir des arguments non nuls pour proxy ou no_proxy, tandis que server et port peuvent être fournis pour supporter la sortie diagnostique. Si bio est NULL, le paramètre optionnel proxy peut être utilisé pour établir un proxy HTTP(S) (sauf s'il est spécifié par "no_proxy"). Si le TLS n'est pas utilisé, la valeur par défaut est la variable d'environnement "http_proxy" si elle est définie, sinon "HTTP_PROXY". Si use_ssl est non nul, la valeur par défaut est "https_proxy" si elle est définie, sinon "HTTPS_PROXY". Une chaîne vide "" empêche l'utilisation d'un proxy. Sinon, le format est "[http[s]://][userinfo@]host[:port][/path][?query][#fragment]", où tout userinfo, path, query et fragment fourni est ignoré. Si l'hôte est une adresse IP ou IPv6, il doit être encadré par "[" et "]". Le port par défaut du proxy est 80, ou 443 dans le cas où "https:" est fourni. Les fonctions de client HTTP se connectent via le proxy fourni, sauf si le serveur se trouve dans la liste optionnelle no_proxy d'adresses de serveurs proxy, séparées par "," et/ou des espaces blancs (si non NULL ; par défaut la variable d'environnement "no_proxy" si elle est définie, sinon "NO_PROXY"). Le proxying HTTP plat est supporté directement, tandis que l'utilisation d'un proxy pour les connexions HTTPS nécessite une fonction de rappel appropriée comme OSSL_HTTP_proxy_connect(), décrite ci-dessous.

Si use_ssl est non nul, une connexion TLS est demandée et le paramètre bio_update_fn doit être fourni.

Le paramètre bio_update_fn, qui est optionnel si use_ssl est 0, peut être utilisé pour modifier le BIO de connexion utilisé par le client HTTP, mais ne peut pas être utilisé lorsque bio et rbio sont tous deux fournis. bio_update_fn est une fonction de rappel de connexion/déconnexion pour BIO avec le prototype :

BIO *(*OSSL_HTTP_bio_cb_t)(BIO *bio, void *arg, int connect, int detail)

La fonction de rappel peut modifier le BIO fourni dans l'argument bio, où elle peut utiliser un argument optionnellement défini arg, qui peut pointer vers une structure SSL_CTX. Pendant l'établissement de la connexion, juste après l'appel à BIO_do_connect_retry(), la fonction de rappel est invoquée avec l'argument connect étant 1 et detail étant 1 si use_ssl est non nul (c'est-à-dire HTTPS est demandé), sinon 0. Lors de la déconnexion, connect est 0 et detail est 1 s'il n'y a pas d'erreur, sinon 0. Par exemple, lors de la connexion, la fonction de rappel peut pousser un BIO SSL pour implémenter HTTPS ; après la déconnexion, elle peut effectuer une sortie diagnostique et dépiler et libérer le BIO SSL.

La fonction de rappel doit retourner, ou NULL, le BIO modifié bio ou indiquer une erreur, auquel cas elle ne doit pas modifier le BIO.

Voici un exemple simple qui supporte les connexions TLS (mais pas via un proxy) :

BIO *http_tls_cb(BIO *bio, void *arg, int connect, int detail)
{
    if (connect && detail) { /* connexion avec TLS */
        SSL_CTX *ctx = (SSL_CTX *)arg;
        BIO *sbio = BIO_new_ssl(ctx, 1);
        bio = sbio != NULL ? BIO_push(sbio, bio) : NULL;
    } else if (!connect) { /* déconnexion */
        BIO *hbio;
        if (!detail) { /* une erreur s'est produite */
            /* éventuellement ajouter un diagnostic ici */
        }
        BIO_ssl_shutdown(bio);
        hbio = BIO_pop(bio);
        BIO_free(bio); /* BIO SSL */
        bio = hbio;
    }
    return bio;
}

Après la déconnexion, le BIO modifié sera libéré en utilisant BIO_free_all(). L'argument optionnel arg de la fonction de rappel n'est pas consommé, il doit donc être libéré par l'appelant lorsqu'il n'en a plus besoin.

Le paramètre buf_size spécifie la longueur maximale de la ligne d'en-tête de la réponse. Une valeur <= 0 indique que la valeur par défaut OSSL_HTTP_DEFAULT_MAX_LINE_LEN (4 KiB) est utilisée. Le buf_size est également utilisé comme nombre d'octets lus à la fois.

Si le paramètre overall_timeout est > 0, il indique le nombre maximum de secondes que le processus de transfert HTTP (c'est-à-dire la configuration de la connexion si nécessaire, l'envoi des requêtes et la réception des réponses) peut prendre pour se terminer. Une valeur <= 0 permet d'attendre indéfiniment, c'est-à-dire sans délai d'attente.

OSSL_HTTP_proxy_connect() peut être utilisé par une fonction de pré-connexion BIO pour établir une connexion TLS/SSL via un proxy HTTP. Il promeut le BIO bio représentant une connexion précédemment établie avec un proxy TLS en utilisant la méthode HTTP CONNECT, en utilisant éventuellement les identifiants client proxyuser et proxypass pour se connecter finalement au serveur server et port avec protection TLS. Si l'argument port est NULL ou une chaîne vide, la valeur par défaut est "443". Si le paramètre timeout est > 0, il indique le nombre maximum de secondes que l'établissement de la connexion peut prendre. Une valeur <= 0 permet d'attendre indéfiniment, c'est-à-dire sans délai d'attente. Étant donné que cette fonction est typiquement appelée par des applications comme openssl-s_client(1), elle utilise les paramètres bio_err et prog (s'ils ne sont pas NULL) pour imprimer des informations diagnostiques supplémentaires.

NOM

OSSL_HTTP_set1_request()

OSSL_HTTP_exchange()

OSSL_HTTP_get()

OSSL_HTTP_transfer()

OSSL_HTTP_close()

SYNTAXE

OSSL_HTTP_set1_request() configure dans rctx l'en-tête de la requête et les données du contenu, ainsi que les attentes concernant la réponse, en utilisant les paramètres suivants.

OSSL_HTTP_exchange() échange toute forme de requête et réponse HTTP telle que spécifiée par rctx.

OSSL_HTTP_get() utilise la méthode HTTP GET pour obtenir des données de bio si non NULL, sinon du serveur contenu dans url.

OSSL_HTTP_transfer() échange une requête et une réponse HTTP sur une connexion gérée via prctx.

OSSL_HTTP_close() ferme la connexion et libère rctx.

DESCRIPTION

OSSL_HTTP_set1_request() configure dans rctx l'en-tête de la requête et les données du contenu, ainsi que les attentes concernant la réponse, en utilisant les paramètres suivants. Si <rctx> indique l'utilisation d'un proxy pour HTTP (mais pas HTTPS), l'hôte du serveur (et éventuellement le port) doit être placé dans l'en-tête ; il doit donc être présent dans rctx. Pour des raisons de compatibilité ascendante, le serveur (et le port optionnel) peut également être fourni dans l'argument path en commençant par "http://" (donc en donnant un URI absolu). Si path est NULL, la valeur par défaut est "/". Si req est NULL, la méthode HTTP GET sera utilisée pour envoyer la requête, sinon HTTP POST avec le contenu de req et le content_type optionnel, où la longueur des données dans req n'a pas besoin d'être déterminée à l'avance : le BIO sera lu à la volée lors de l'envoi de la requête, ce qui prend en charge le streaming. La liste optionnelle headers peut contenir des lignes d'en-tête HTTP personnalisées supplémentaires. Le paramètre max_resp_len spécifie la longueur maximale autorisée du contenu de la réponse, où la valeur 0 indique aucune limite. Pour la signification des paramètres expected_content_type, expect_asn1, timeout et keep_alive, voir OSSL_HTTP_REQ_CTX_set_expected(3).

OSSL_HTTP_exchange() échange toute forme de requête et réponse HTTP telle que spécifiée par rctx, qui doit inclure à la fois les données de connexion et de requête, généralement configurées à l'aide de OSSL_HTTP_open() et OSSL_HTTP_set1_request(). Il implémente le cœur des fonctions décrites ci-dessous. Si la méthode HTTP est GET et que redirection_url n'est pas NULL, ce dernier pointeur est utilisé pour fournir toute nouvelle localisation que le serveur peut renvoyer avec le code HTTP 301 (MOVED_PERMANENTLY) ou 302 (FOUND). Dans ce cas, la fonction retourne NULL et l'appelant est responsable de la désallocation de l'URL avec OPENSSL_free(3). Si l'en-tête de réponse contient une ou plusieurs lignes "Content-Length" et/ou si une réponse encodée en ASN.1 est attendue, ce qui devrait inclure une longueur totale, les indications de longueur reçues sont vérifiées pour leur cohérence et pour ne pas dépasser la longueur de réponse maximale donnée. Si une réponse encodée en ASN.1 est attendue, la fonction retourne en cas de succès le contenu mis en mémoire tampon dans un BIO mémoire, qui ne prend pas en charge le streaming. Sinon, elle retourne directement le BIO lu qui contient le contenu de la réponse, ce qui permet une réponse de longueur indéfinie et peut prendre en charge le streaming. L'appelant est responsable de libérer le pointeur BIO obtenu.

OSSL_HTTP_get() utilise la méthode HTTP GET pour obtenir des données de bio si non NULL, sinon du serveur contenu dans url, et les retourne sous forme de BIO. Il prend en charge la redirection via les codes d'état HTTP 301 ou 302. Il est destiné aux transferts avec un seul aller-retour, donc ne prend pas en charge les connexions persistantes. Si bio est non-NULL, les composants hôte et port de url ne sont pas utilisés pour la connexion mais le nom d'hôte est utilisé, comme d'habitude, pour l'en-tête "Host". Tout composant userinfo et fragment dans url est ignoré. Tout composant de requête est traité comme faisant partie du composant de chemin. Si le composant schéma de url est "https", une connexion TLS est demandée et le bio_update_fn, tel que décrit pour OSSL_HTTP_open(), doit être fourni. De plus, les paramètres restants sont interprétés comme décrit pour OSSL_HTTP_open() et OSSL_HTTP_set1_request(), respectivement. L'appelant est responsable de libérer le pointeur BIO obtenu.

OSSL_HTTP_transfer() échange une requête et une réponse HTTP sur une connexion gérée via prctx sans prendre en charge la redirection. Il combine OSSL_HTTP_open(), OSSL_HTTP_set1_request(), OSSL_HTTP_exchange() et OSSL_HTTP_close(). Si prctx n'est pas NULL, il réutilise toute connexion ouverte représentée par un *prctx non-NULL. Il maintient la connexion ouverte si une connexion persistante est demandée ou requise et que cela a été accordé par le serveur, sinon il ferme la connexion et assigne NULL à *prctx. Les paramètres restants sont interprétés comme décrit pour OSSL_HTTP_open() et OSSL_HTTP_set1_request(), respectivement. L'appelant est responsable de libérer le pointeur BIO obtenu.

OSSL_HTTP_close() ferme la connexion et libère rctx. Le paramètre ok est passé à toute fonction de mise à jour BIO donnée lors de la configuration, comme décrit ci-dessus pour OSSL_HTTP_open(). Il doit être 1 si aucune erreur ne s'est produite pendant le transfert HTTP et 0 sinon.

NOTES

Les noms des variables d'environnement utilisées par cette implémentation : "http_proxy", "HTTP_PROXY", "https_proxy", "HTTPS_PROXY", "no_proxy", et "NO_PROXY" ont été choisis pour une compatibilité maximale avec d'autres implémentations de clients HTTP telles que wget, curl et git.

Lorsqu'il est compilé avec le traçage activé, OSSL_HTTP_transfer() et toutes les fonctions qui l'utilisent peuvent être tracés à l'aide de OSSL_TRACE_CATEGORY_HTTP. Voir également OSSL_trace_enabled(3) et openssl-env(7).

VALEURS DE RETOUR

OSSL_HTTP_open() retourne en cas de succès un OSSL_HTTP_REQ_CTX, sinon NULL.

OSSL_HTTP_proxy_connect() et OSSL_HTTP_set1_request() retournent 1 en cas de succès, 0 en cas d'erreur.

En cas de succès, OSSL_HTTP_exchange(), OSSL_HTTP_get(), et OSSL_HTTP_transfer() retournent un BIO mémoire qui met en tampon toutes les données reçues si une réponse encodée en ASN.1 est attendue, sinon un BIO qui peut supporter le streaming. Le BIO doit être libéré par l'appelant. En cas d'échec, ils retournent NULL. Les conditions d'échec incluent le délai de connexion/transfert, les erreurs d'analyse, etc. L'appelant est responsable de libérer le pointeur BIO obtenu.

OSSL_HTTP_close() retourne 0 si quelque chose s'est mal passé lors de la déconnexion, sinon 1.
