OSSL_CMP_log_open(3ssl)

Paquet: openssl

Licences: Apache-2.0

OSSL_CMP_LOG_OPEN(3ssl) OpenSSL OSSL_CMP_LOG_OPEN(3ssl)

NOM

OSSL_CMP_log_open, OSSL_CMP_log_close, OSSL_CMP_severity, OSSL_CMP_LOG_EMERG, OSSL_CMP_LOG_ALERT, OSSL_CMP_LOG_CRIT, OSSL_CMP_LOG_ERR, OSSL_CMP_LOG_WARNING, OSSL_CMP_LOG_NOTICE, OSSL_CMP_LOG_INFO, OSSL_CMP_LOG_DEBUG, OSSL_CMP_LOG_TRACE,

OSSL_CMP_log_cb_t, OSSL_CMP_print_to_bio, OSSL_CMP_print_errors_cb - fonctions pour la journalisation et le rapport d'erreurs

SYNOPIS

#include <openssl/cmp_util.h>
int  OSSL_CMP_log_open(void);
void OSSL_CMP_log_close(void);
/* les déclarations de niveaux de sévérité ressemblent à celles de syslog.h */
typedef int OSSL_CMP_severity;
#define OSSL_CMP_LOG_EMERG   0
#define OSSL_CMP_LOG_ALERT   1
#define OSSL_CMP_LOG_CRIT    2
#define OSSL_CMP_LOG_ERR     3
#define OSSL_CMP_LOG_WARNING 4
#define OSSL_CMP_LOG_NOTICE  5
#define OSSL_CMP_LOG_INFO    6
#define OSSL_CMP_LOG_DEBUG   7
#define OSSL_CMP_LOG_TRACE   8
typedef int (*OSSL_CMP_log_cb_t)(const char *component,
                                 const char *file, int line,
                                 OSSL_CMP_severity level, const char *msg);
int OSSL_CMP_print_to_bio(BIO *bio, const char *component, const char *file,
                          int line, OSSL_CMP_severity level, const char *msg);
void OSSL_CMP_print_errors_cb(OSSL_CMP_log_cb_t log_fn);

DESCRIPTION

Le système de journalisation et de rapport d'erreurs décrit ici contient des fonctions pratiques pour la journalisation spécifique à CMP, y compris un préfixe de chaîne qui reflète les niveaux de sévérité de syslog.h, et des améliorations du mécanisme de file d'attente d'erreurs nécessaires pour les grands messages de diagnostic produits par la bibliothèque CMP en cas d'échec de validation de certificat.

Lorsqu'une activité intéressante est effectuée ou qu'une erreur se produit, certains détails doivent être fournis pour l'information de l'utilisateur, le débogage et l'audit. Une application CMP peut obtenir ces informations en fournissant une fonction de rappel du type suivant :

typedef int (*OSSL_CMP_log_cb_t)(const char *component,
                                 const char *file, int line,
                                 OSSL_CMP_severity level, const char *msg);

Les paramètres peuvent fournir des informations sur le composant (qui peut être un nom de module et/ou de fonction) ou NULL, un chemin de fichier ou NULL, un numéro de ligne ou 0 indiquant l'emplacement du code source, un niveau de sévérité et une chaîne de message décrivant la nature de l'événement, terminée par '\n'.

Même lorsqu'une activité réussit, certains avertissements peuvent être utiles et un certain degré d'audit peut être requis. Par conséquent, le système de journalisation prend en charge un niveau de sévérité et la fonction de rappel a un paramètre level indiquant un tel niveau, de sorte que les erreurs, avertissements, informations, débogages, etc. peuvent être traités différemment. Le rappel est activé uniquement lorsque le niveau de sévérité est suffisant selon le niveau de verbosité actuel, qui par défaut est OSSL_CMP_LOG_INFO.

La fonction de rappel peut elle-même effectuer des tâches non triviales comme écrire dans un fichier journal ou un flux distant, ce qui peut à son tour échouer. Par conséquent, la fonction doit retourner 1 en cas de succès et 0 en cas d'échec.

OSSL_CMP_log_open() initialise le système de journalisation spécifique à CMP pour tout afficher sur STDOUT. Il échoue si le traçage intégré est désactivé ou si STDIO n'est pas disponible. Il peut être appelé lors du démarrage de l'application. Alternativement, OSSL_CMP_CTX_set_log_cb(3) peut être utilisé pour plus de flexibilité. Tant que ni l'un ni l'autre n'est utilisé, toute sortie de journal est ignorée.

OSSL_CMP_log_close() peut être appelé une fois toutes les activités terminées pour vider toute sortie de journal CMP en attente et désallouer les ressources associées. Il peut être appelé plusieurs fois. Il est appelé lors de l'arrêt d'OpenSSL.

OSSL_CMP_print_to_bio() imprime les informations sur le composant donné, le nom de fichier, le numéro de ligne, le niveau de sévérité et le message de journal ou le message de la file d'attente d'erreurs au bio donné. component est généralement un nom de fonction ou de module. S'il est NULL, vide ou "(unknown function)", alors "CMP" est utilisé comme solution de secours.

OSSL_CMP_print_errors_cb() affiche toutes les entrées de la file d'attente d'erreurs OpenSSL. Il est similaire à ERR_print_errors_cb(3) mais utilise la fonction de rappel de journalisation CMP log_fn pour l'uniformité avec la journalisation CMP si non NULL. Sinon, il imprime sur STDERR en utilisant OSSL_CMP_print_to_bio(3) (sauf si OPENSSL_NO_STDIO est défini).

VALEUR DE RETOUR

OSSL_CMP_log_close() et OSSL_CMP_print_errors_cb() ne retournent rien.

Toutes les autres fonctions retournent 1 en cas de succès, 0 en cas d'erreur.

HISTORIQUE

Le support CMP d'OpenSSL a été ajouté dans OpenSSL 3.0.
