DESCRIPTION

Ceci est l'API de contexte pour l'utilisation du protocole CMP (Certificate Management Protocol) avec OpenSSL.

OSSL_CMP_CTX_new() alloue une structure OSSL_CMP_CTX associée au contexte de la librairie libctx et à la chaîne de propriétés propq, les deux pouvant être NULL pour utiliser les valeurs par défaut. Le reste des champs est initialisé à leurs valeurs par défaut - par exemple, le niveau de verbosité de la journalisation est défini sur OSSL_CMP_LOG_INFO, le délai d'attente des messages est défini à 120 secondes et la méthode de preuve de possession est définie sur OSSL_CRMF_POPO_SIGNATURE.

OSSL_CMP_CTX_free() libère la structure OSSL_CMP_CTX. Si l'argument est NULL, rien ne se fait.

OSSL_CMP_CTX_reinit() prépare le contexte donné ctx pour une transaction ultérieure, en effaçant l'état interne CMP (également appelé session) de la transaction précédente, les informations d'état de la PKI et tout résultat précédent (newCert, newChain, caPubs et extraCertsIn). Il efface également tous les ITAV qui ont pu être ajoutés avec OSSL_CMP_CTX_push0_genm_ITAV(). Toutes les autres valeurs de champ (c'est-à-dire les options CMP) sont conservées pour une réutilisation potentielle.

OSSL_CMP_CTX_get0_libctx() retourne l'argument libctx utilisé lors de la construction de ctx avec OSSL_CMP_CTX_new(), qui peut être NULL.

OSSL_CMP_CTX_get0_propq() retourne l'argument propq utilisé lors de la construction de ctx avec OSSL_CMP_CTX_new(), qui peut être NULL.

OSSL_CMP_CTX_set_option() définit la valeur donnée pour l'option donnée (par exemple, OSSL_CMP_OPT_IMPLICIT_CONFIRM) dans la structure OSSL_CMP_CTX donnée.

Les options suivantes peuvent être définies:

OSSL_CMP_OPT_LOG_VERBOSITY
Le niveau de sévérité requis pour émettre des messages de log en raison d'erreurs, d'avertissements, d'informations générales, de débogage, etc. La valeur par défaut est OSSL_CMP_LOG_INFO. Voir également OSSL_CMP_log_open(3).
OSSL_CMP_OPT_KEEP_ALIVE
Si la valeur donnée est 0, alors les connexions HTTP ne sont pas maintenues ouvertes après réception d'une réponse, ce qui est le comportement par défaut pour HTTP 1.0. Si la valeur est 1 ou 2, des connexions persistantes sont demandées. Si la valeur est 2, des connexions persistantes sont requises, c'est-à-dire qu'en cas de refus par le serveur, une erreur se produit. La valeur par défaut est 1 : préfère maintenir la connexion ouverte.
OSSL_CMP_OPT_MSG_TIMEOUT
Le nombre de secondes pendant lequel une demande de message de réponse CMP est autorisée avant qu'une erreur de délai d'attente ne soit renvoyée. Une valeur <= 0 signifie sans limite (attendre indéfiniment). La valeur par défaut est d'utiliser le paramètre OSSL_CMP_OPT_TOTAL_TIMEOUT.
OSSL_CMP_OPT_TOTAL_TIMEOUT
Le nombre total maximum de secondes qu'une transaction peut prendre, y compris la mise en attente. Une valeur <= 0 signifie sans limite (attendre indéfiniment). La valeur par défaut est 0.
OSSL_CMP_OPT_USE_TLS
Utilisez cette option pour indiquer à l'implémentation HTTP si TLS doit être utilisé pour la connexion (ce qui aboutit à HTTPS). La valeur 1 indique que TLS sera utilisé pour les connexions HTTP côté client, ce qui doit être implémenté via une fonction de rappel définie par OSSL_CMP_CTX_set_http_cb(). La valeur 0 indique que TLS ne sera pas utilisé. La valeur par défaut est -1 pour des raisons de compatibilité descendante : TLS sera utilisé côté client si et seulement si OSSL_CMP_CTX_set_http_cb_arg() définit une valeur non nulle dans l'argument arg.
OSSL_CMP_OPT_VALIDITY_DAYS
Le nombre de jours pendant lesquels de nouveaux certificats validés sont demandés pour une période donnée.
OSSL_CMP_OPT_SUBJECTALTNAME_NODEFAULT
Ne pas utiliser les valeurs par défaut des noms alternatifs du sujet dans le certificat.
OSSL_CMP_OPT_SUBJECTALTNAME_CRITICAL
Exiger que les valeurs données des noms alternatifs du sujet soient marquées comme critiques.
OSSL_CMP_OPT_POLICIES_CRITICAL
Exiger que les politiques données soient marquées comme critiques.
OSSL_CMP_OPT_POPO_METHOD
La méthode de preuve de possession à utiliser. Valeurs possibles : 
OSSL_CRMF_POPO_NONE       - Le champ ProofOfPossession est omis, ce qui implique une génération de clé centrale.
OSSL_CRMF_POPO_RAVERIFIED - Affirmer que l'AR a déjà vérifié le POPO.
OSSL_CRMF_POPO_SIGNATURE  - Signer une valeur avec la clé privée, ce qui est la valeur par défaut.
OSSL_CRMF_POPO_KEYENC     - Décoder le certificat chiffré (« méthode indirecte »).

Remarque : un POPO basé sur la signature ne peut être produit que si une clé privée est fournie comme nouvelle clé ou composant de clé du contexte CMP.

OSSL_CMP_OPT_DIGEST_ALGNID
Le NID de l'algorithme de hachage à utiliser dans MSG_SIG_ALG de RFC 4210 pour la protection des messages et le POPO. La valeur par défaut est SHA256.
OSSL_CMP_OPT_OWF_ALGNID
Le NID de l'algorithme de hachage à utiliser comme fonction à sens unique (OWF) pour la protection des messages basée sur une clé de mot de passe (PBM). Voir la section 5.1.3.1 de RFC 4210 pour plus de détails. La valeur par défaut est SHA256.
OSSL_CMP_OPT_MAC_ALGNID
Le NID de l'algorithme de protection des messages à utiliser basé sur PBM. La valeur par défaut est HMAC-SHA1 comme spécifié dans RFC 4210.
OSSL_CMP_OPT_REVOCATION_REASON
Le code de raison à inclure dans une demande de révocation (RR) ; valeurs : 0..10 (RFC 5210, 5.3.1) ou -1 pour aucune, ce qui est la valeur par défaut.
OSSL_CMP_OPT_IMPLICIT_CONFIRM
Exiger que le serveur active le mode de confirmation implicite, où le client n'a pas besoin d'envoyer de confirmation à la réception du certificat. Si le serveur n'active pas le mode de confirmation implicite dans la réponse, la confirmation est tout de même envoyée.
OSSL_CMP_OPT_DISABLE_CONFIRM
Empêcher la confirmation des certificats enregistrés, pour traiter les serveurs défectueux qui n'implémentent pas correctement le mode de confirmation implicite. AVERTISSEMENT : Ce paramètre entraîne un comportement non spécifié et est destiné exclusivement à permettre l'interopérabilité avec des implémentations de serveur qui violent RFC 4210.
OSSL_CMP_OPT_UNPROTECTED_SEND
Envoyer des messages de requête ou de réponse sans protection au niveau CMP.
OSSL_CMP_OPT_UNPROTECTED_ERRORS
Accepter les réponses d'erreur non protégées qui sont explicites ou dont la vérification de protection a échoué. S'applique aux messages d'erreur normaux, aux réponses de certificat (IP/CP/KUP) et aux réponses de rejet (RP) avec rejet. AVERTISSEMENT : Ce paramètre entraîne un comportement non spécifié et est destiné exclusivement à permettre l'interopérabilité avec des implémentations de serveur qui violent RFC 4210.
OSSL_CMP_OPT_IGNORE_KEYUSAGE
Ignorer les restrictions d'utilisation de clé dans le certificat du signataire lors de la validation de la protection de signature basée sur les messages reçus. Sinon, 'digitalSignature' doit être autorisé par les certificats du signataire CMP.
OSSL_CMP_OPT_PERMIT_TA_IN_EXTRACERTS_FOR_IR
Permettre la récupération d'une racine de confiance à partir des certificats supplémentaires et son utilisation pour valider la chaîne de certificats d'un message IP. Ceci est un paramètre de compatibilité descendante ajouté pour prendre en charge 3GPP TS 33.310.

Remarque : l'utilisation de ce paramètre est dangereuse, car le certificat obtenu de cette manière n'a pas été authentifié (bien que pas au niveau CMP). L'utilisation de ce paramètre comme racine de confiance implémente l'utilisation de TOFU (confiance au premier octet).

OSSL_CMP_OPT_NO_CACHE_EXTRACERTS
Empêcher la mise en cache des certificats reçus dans le champ extraCerts des messages CMP. Sinon, ils sont stockés pour aider à valider les messages futurs.

OSSL_CMP_CTX_get_option() lit la valeur actuelle de l'option donnée (par exemple, OSSL_CMP_OPT_IMPLICIT_CONFIRM) à partir de la structure ctx.

OSSL_CMP_CTX_set_log_cb() définit dans ctx la fonction de rappel cb pour gérer les entrées dans la file d'attente d'erreurs et les messages de log. Si cb est NULL, les erreurs sont imprimées sur STDERR (si disponible, sinon ignorées). Les messages de log sont ignorés si une fonction de rappel est définie dans ctx. Alternativement, OSSL_CMP_log_open(3) peut être utilisé pour diriger la journalisation vers STDOUT.

OSSL_CMP_CTX_set_log_verbosity() est une macro qui définit la valeur de l'option OSSL_CMP_OPT_LOG_VERBOSITY au niveau donné.

OSSL_CMP_CTX_print_errors() affiche toutes les entrées dans la file d'attente d'erreurs d'OpenSSL. C'est similaire à ERR_print_errors_cb(3) mais utilise la fonction de rappel de log CMP si elle est définie dans ctx pour une uniformité avec le logging CMP. Sinon, elle utilise ERR_print_errors(3) pour imprimer sur STDERR (sauf si OPENSSL_NO_STDIO est défini).

OSSL_CMP_CTX_set1_serverPath() définit le chemin du serveur CMP sur l'hôte, également connu sous le nom d'"alias CMP". La valeur par défaut est "/".

OSSL_CMP_CTX_set1_server() définit l'adresse du serveur address (qui peut être un nom d'hôte, une adresse IP ou NULL) dans le ctx. Si OSSL_CMP_CTX_get_transfer_cb_arg() définit un argument non nul, ces informations d'adresse serveur ne sont utilisées que pour la sortie diagnostique.

OSSL_CMP_CTX_set_serverPort() définit le port du serveur CMP auquel se connecter. Si non utilisé ou si l'argument port est 0, il applique le port par défaut, qui est 80 pour HTTP et 443 pour HTTPS. Si OSSL_CMP_CTX_get_transfer_cb_arg() définit un argument non nul, ces informations de port serveur ne sont utilisées que pour la sortie diagnostique.

OSSL_CMP_CTX_set1_proxy() définit le proxy HTTP à utiliser pour se connecter au serveur CMP, sauf si un réglage "no_proxy" est remplacé (voir ci-dessous). Si TLS n'est pas utilisé, la valeur par défaut est la valeur de la variable d'environnement "http_proxy" si elle est définie, sinon "HTTP_PROXY". Sinon, la valeur par défaut est la valeur de "https_proxy" si elle est définie, sinon "HTTPS_PROXY". Une chaîne de proxy vide signifie ne pas utiliser de proxy. Sinon, le format est "[http[s]://][userinfo@]host[:port][/path][?query][#fragment]", où toute information de userinfo, path, query et fragment est ignorée. Si la chaîne de l'hôte est une adresse IPv6, elle doit être entourée de "[" et "]". Le port par défaut est 80, ou 443 si "https:" est spécifié comme faisant partie de la valeur.

OSSL_CMP_CTX_set1_no_proxy() définit la liste des noms d'hôtes des serveurs auxquels un proxy ne doit pas être appliqué. Les noms peuvent être séparés par des virgules et/ou des espaces. La valeur par défaut est la variable d'environnement "no_proxy" si elle est définie, sinon "NO_PROXY".

OSSL_CMP_CTX_set_http_cb() définit la fonction de rappel optionnelle bio pour la connexion/déconnexion, qui a le prototype :

typedef BIO *(*HTTP_bio_cb_t) (BIO *bio, void *arg, int connect, int detail);

Le rappel peut modifier le bio fourni par OSSL_CMP_MSG_http_perform pour l'utilisation de ctx s'il est défini dans cb pour une utilisation uniforme avec le logging CMP.

OSSL_CMP_CTX_set1_serverPath() définit le chemin du serveur CMP sur l'hôte, également connu sous le nom d'"alias CMP". La valeur par défaut est "/".

OSSL_CMP_CTX_set1_server() définit l'adresse du serveur address (qui peut être un nom d'hôte, une adresse IP ou NULL) dans le ctx. Si OSSL_CMP_CTX_get_transfer_cb_arg() définit un argument non nul, ces informations d'adresse serveur ne sont utilisées que pour la sortie diagnostique.

OSSL_HTTP_open(3) décrit le callback qui peut utiliser un argument personnalisé arg, tel que décrit pour le paramètre arg de OSSL_HTTP_open(3). L'argument est stocké dans le OSSL_CMP_CTX par OSSL_CMP_CTX_set_http_cb_arg(). Voir aussi l'option OSSL_CMP_OPT_USE_TLS décrite précédemment.

OSSL_CMP_CTX_set_http_cb_arg() définit l'argument, respectivement un pointeur vers une structure contenant des arguments tels qu'une structure SSL_CTX, éventuellement utilisé par le callback de connexion/déconnexion HTTP. arg n'est pas consommé et doit donc être libéré explicitement lorsqu'il n'est plus nécessaire. arg peut être NULL pour supprimer l'entrée. Si une valeur non NULL est définie, ni OSSL_CMP_CTX_set1_proxy() ni OSSL_CMP_CTX_set1_no_proxy() ne peuvent être utilisés pour définir des chaînes non NULL.

OSSL_CMP_CTX_get_http_cb_arg() récupère l'argument, respectivement le pointeur vers une structure contenant des arguments, précédemment défini par OSSL_CMP_CTX_set_http_cb_arg() ou NULL s'il n'est pas défini.

OSSL_CMP_CTX_set_transfer_cb() définit la fonction de transfert de messages, qui a le type

typedef OSSL_CMP_MSG *(*OSSL_CMP_transfer_cb_t) (OSSL_CMP_CTX *ctx,
                                                 const OSSL_CMP_MSG *req);

La valeur par défaut est NULL, ce qui implique l'utilisation de OSSL_CMP_MSG_http_perform(3). La fonction de callback doit envoyer le message CMP de requête qu'elle reçoit via le paramètre req et, en cas de succès, retourner la réponse, sinon retourner NULL. La fonction de transfert peut utiliser un argument personnalisé stocké dans le ctx via OSSL_CMP_CTX_set_transfer_cb_arg(), qui peut être récupéré via OSSL_CMP_CTX_get_transfer_cb_arg().

OSSL_CMP_CTX_set_transfer_cb_arg() définit un argument, respectivement un pointeur vers une structure contenant des arguments, éventuellement utilisé par la fonction de transfert. arg n'est pas consommé et doit donc être libéré explicitement lorsqu'il n'est plus nécessaire. arg peut être NULL pour supprimer l'entrée.

OSSL_CMP_CTX_get_transfer_cb_arg() récupère l'argument, respectivement le pointeur vers une structure contenant des arguments, précédemment défini par OSSL_CMP_CTX_set_transfer_cb_arg() ou NULL s'il n'est pas défini.

OSSL_CMP_CTX_set1_srvCert() définit la certification attendue du serveur dans ctx et lui fait confiance directement (même si elle est expirée) lors de la vérification des messages de réponse signés. Cela fixe le serveur accepté et a pour conséquence d'ignorer toute configuration définie avec OSSL_CMP_CTX_set0_trusted(). Toute valeur précédemment définie est libérée. L'argument cert peut être NULL pour supprimer l'entrée. S'il est défini, le sujet de la certification est également utilisé comme valeur par défaut pour le destinataire des requêtes CMP et comme valeur par défaut pour l'émetteur des réponses CMP.

OSSL_CMP_CTX_set1_expected_sender() définit le nom du Distinguished Name (DN) attendu dans le champ émetteur des requêtes CMP. La valeur par défaut est le sujet de la certification fixée sur le serveur, si elle est présente. Ceci peut être utilisé pour s'assurer qu'une seule entité spécifique est acceptée comme signataire des messages CMP, et que les attaquants ne peuvent pas utiliser les calculs de certificats d'une hiérarchie PKI de confiance pour se faire passer pour un serveur CMP. Notez que cela offre un peu plus de flexibilité que OSSL_CMP_CTX_set1_srvCert(), qui fixe le serveur à la possession d'une certification spécifique, tandis que le nom de l'émetteur continuera à correspondre même après des mises à jour de la certification du serveur.

OSSL_CMP_CTX_set0_trusted() est un alias de l'original OSSL_CMP_CTX_set0_trustedStore(). Il définit dans le contexte CMP ctx le magasin de certificats de type X509_STORE qui contient les certificats de confiance, typiquement les certificats racines. Ceci est ignoré lorsqu'une certification est fixée avec OSSL_CMP_CTX_set1_srvCert(). Le magasin peut également inclure des CRLs et une fonction de vérification de certificats utilisée pour l'authentification basée sur signature. Toute entrée précédemment définie est libérée. Lorsque vous passez un paramètre NULL, l'entrée est effacée.

OSSL_CMP_CTX_get0_trusted() est un alias de l'original OSSL_CMP_CTX_get0_trustedStore(). Il extrait du contexte CMP ctx le pointeur vers le magasin de certificats actuellement défini qui contient les points d'ancrage de confiance, ou un magasin vide s'il n'est pas défini.

OSSL_CMP_CTX_set1_untrusted() définit une liste de certificats non fiables de CAs intermédiaires qui peuvent être utiles pour la construction de chaînes dans le certificat CMP lui-même, pour le certificat TLS lui-même (s'il existe), lors de la vérification des certificats de protection CMP, et lors de la vérification des certificats nouvellement enrôlés. Les compteurs de références de ces certificats correctement traités sont incrémentés. La liste des certificats non fiables dans ctx sera étendue avec les extraCerts reçus dans les messages CMP, à moins que OSSL_CMP_OPT_NO_CACHE_EXTRACERTS ne soit configuré.

OSSL_CMP_CTX_get0_untrusted() retourne un pointeur vers la liste des certificats non fiables dans ctx, qui peut être vide s'il n'est pas défini.

OSSL_CMP_CTX_set1_cert() définit la certification du certificat signataire, également appelé certificat de protection, associé à la clé privée utilisée pour la protection des messages CMP basés sur signature. Par conséquent, la clé publique de ce cert doit correspondre à la clé privée définie avant ou après via OSSL_CMP_CTX_set1_pkey(). Lors de l'utilisation de la protection basée sur signature des messages CMP, ce certificat signataire sera inclus en premier dans le champ extraCerts. Il sert de certificat de référence de repli, voir OSSL_CMP_CTX_set1_oldCert(). Le sujet de ce cert sera utilisé comme champ émetteur des messages sortants, tandis que le sujet de tout certificat défini via OSSL_CMP_CTX_set1_oldCert(), le sujet de tout certificat généré via OSSL_CMP_CTX_set1_p10CSR(), et toute valeur définie via OSSL_CMP_CTX_set1_subjectName() sera utilisé en repli.

L'argument cert peut être NULL pour supprimer l'entrée.

OSSL_CMP_CTX_build_cert_chain() construit une chaîne de certificats pour le certificat signataire CMP défini précédemment dans ctx. Il ajoute les candidates, une liste de certificats CA intermédiaires qui peuvent déjà constituer la chaîne cible, aux certificats non fiables qui existent déjà dans ctx. Ensuite, la fonction utilise cette liste étendue pour construire la chaîne. Si own_trusted est NULL, elle construit la chaîne aussi profondément que possible et ignore toute erreur de vérification. Sinon, le certificat signataire du serveur doit être vérifiable lorsque la chaîne atteint un point d'ancrage de confiance contenu dans own_trusted. En cas de succès, la fonction stocke la chaîne résultante dans ctx pour être incluse dans le champ extraCerts des messages protégés par signature. L'appel à cette fonction est optionnel ; par défaut, la construction de la chaîne est effectuée à la demande, ce qui équivaut à appeler cette fonction avec les paramètres candidates et own_trusted étant NULL.

OSSL_CMP_CTX_set1_pkey() définit la clé privée du client correspondant à la certification du serveur CMP définie via OSSL_CMP_CTX_set1_cert(). Cette clé est utilisée pour créer la protection basée sur signature (protectionAlg = MSG_SIG_ALG) des messages sortants, à moins qu'une clé secrète n'ait été définie via OSSL_CMP_CTX_set1_secretValue(). L'argument pkey peut être NULL pour supprimer l'entrée.

OSSL_CMP_CTX_set1_secretValue() définit dans ctx la chaîne d'octets sec de longueur len comme clé secrète partagée préalable, ou la supprime si l'argument sec est NULL. Si elle est présente, cette clé est utilisée pour créer l'authentification et la protection d'intégrité (plutôt que d'appliquer une protection basée sur signature) des messages sortants, et pour vérifier l'authenticité et l'intégrité des messages entrants avec une protection basée sur MAC (protectionAlg = "MSG_MAC_ALG").

OSSL_CMP_CTX_set1_referenceValue() définit la valeur donnée ref avec la longueur len dans le contexte ctx ou la supprime si l'argument ref est NULL. Selon le RFC 4210 section 5.1.1, si la valeur du champ émetteur dans les en-têtes de message CMP ne peut pas être déterminée (c'est-à-dire qu'il n'y a pas de certification de signataire et que le DN du sujet n'a pas été défini via OSSL_CMP_CTX_set1_subjectName()), le champ émetteur contiendra le DN NULL et le champ senderKID de l'en-tête du message CMP doit être défini. Lors de l'utilisation de la protection basée sur signature, le senderKID sera défini sur le subjectKeyIdentifier de la certification du signataire CMP. S'il n'est pas présent ou lors de l'utilisation de la protection basée sur MAC, la valeur ref sera utilisée comme valeur de repli pour senderKID.

OSSL_CMP_CTX_set1_recipient() définit le nom du destinataire à utiliser dans l'en-tête PKI des requêtes CMP, c'est-à-dire le nom X509 du serveur (CA).

Le champ destinataire dans l'en-tête d'un message CMP est obligatoire. S'il n'est pas explicitement spécifié, le destinataire est déterminé dans l'ordre suivant : le sujet de la certification du serveur définie via OSSL_CMP_CTX_set1_srvCert(), la valeur définie via OSSL_CMP_CTX_set1_issuer(), l'émetteur de la certification définie via OSSL_CMP_CTX_set1_oldCert(), l'émetteur de la certification du signataire CMP, si aucun de ceux-ci n'est présent, sinon le DN NULL en dernier recours.

OSSL_CMP_CTX_push0_geninfo_ITAV() ajoute itav à la pile dans le contexte ctx pour être ajouté au champ generalInfo de l'en-tête PKIMessage d'un message CMP envoyé avec ce contexte.

OSSL_CMP_CTX_reset_geninfo_ITAVs() efface tous les ITAVs ajoutés via OSSL_CMP_CTX_push0_geninfo_ITAV().

OSSL_CMP_CTX_get0_geninfo_ITAVs() retourne la liste des ITAVs définis dans ctx à inclure dans le champ generalInfo de l'en-tête PKIMessage des requêtes ou NULL s'il n'est pas défini.

OSSL_CMP_CTX_set1_extraCertsOut() définit la pile d'extraCerts à envoyer à distance.

OSSL_CMP_CTX_set0_newPkey() peut être utilisé explicitement pour définir la structure donnée priv comme la clé privée ou publique à certifier dans le contexte CMP. Le paramètre priv doit être 0 si et seulement si la clé donnée est une clé publique.

OSSL_CMP_CTX_get0_newPkey() retourne la clé pour l'enrôlement de certificat en fonction des champs de la structure de contexte CMP : le newPkey (qui peut être une clé privée ou publique) s'il est présent, sinon la clé publique dans le p10CSR s'il est présent, sinon la clé privée du client. Si le paramètre priv n'est pas 0 et que la clé sélectionnée n'a pas de composante privée, NULL est retourné.

OSSL_CMP_CTX_set1_issuer() définit le nom de l'émetteur intentionnel qui sera défini dans le CertTemplate, c'est-à-dire le nom X509 du serveur (CA) utilisé.

OSSL_CMP_CTX_set1_serialNumber() définit le numéro de série optionnel utilisé pour sélectionner la certification à révoquer dans les requêtes de révocation (RR).

OSSL_CMP_CTX_set1_subjectName() définit le DN du sujet à utiliser dans la structure CertTemplate lors de la demande d'une nouvelle certification. Pour les demandes de mise à jour de clé (KUR), la valeur par défaut est le DN du sujet de la certification de référence.

Mantén toda la estructura del archivo. OSSL_CMP_CTX_set1_oldCert(). Cette valeur par défaut n'est utilisée que pour les demandes d'initialisation (IR) et les demandes de certificat (CR), à moins que des SANs spécifiques n'aient été spécifiés. Le subjectName est également utilisé comme solution de repli pour le champ du destinataire dans les messages CMP sortants s'il n'y a pas de certificat de référence disponible.

OSSL_CMP_CTX_push1_subjectAltName() ajoute le nom X509 donné à la liste des noms alternatifs dans le modèle de demande de certificat. Cela ne peut pas être utilisé si des extensions de noms alternatifs ont été spécifiées via OSSL_CMP_CTX_set0_reqExtensions(). Par défaut, si OSSL_CMP_OPT_SUBJECTALTNAME_NODEFAULT n'est pas défini, les noms alternatifs sont copiés du certificat de référence, voir OSSL_CMP_CTX_set1_oldCert(). Si et que le DN du sujet n'est pas défini via OSSL_CMP_CTX_set1_subjectName(), le modèle d'un IR ou CR n'aura pas le DN du sujet par défaut du certificat de référence. Si un DN de sujet est souhaité, il doit être explicitement défini via OSSL_CMP_CTX_set1_subjectName().

OSSL_CMP_CTX_set0_reqExtensions() définit les extensions X.509v3 à utiliser dans IR/CR/KUR.

OSSL_CMP_CTX_reqExtensions_have_SAN() renvoie 1 si le contexte contient une extension de noms alternatifs, sinon 0 ou -1 en cas d'erreur.

OSSL_CMP_CTX_push0_policy() ajoute les informations d'objet de politique aux X509_EXTENSIONS du modèle de demande de certificat.

OSSL_CMP_CTX_set1_oldCert() définit le certificat obsolète à mettre à jour dans les demandes de changement de clé (KUR) ou à révoquer dans les demandes de révocation (RR). Pour RR, cette valeur est ignorée si le nom de l'émetteur et le numéro de série sont fournis via OSSL_CMP_CTX_set1_issuer() et OSSL_CMP_CTX_set1_serialNumber(). Pour IR/CR/KUR, cela définit le certificat de référence, qui est autrement utilisé comme certificat CMP. Le certificat de référence déterminé de cette manière, s'il existe, est utilisé pour fournir des valeurs par défaut pour la clé publique, le DN du sujet, les noms alternatifs et le DN de l'émetteur dans le modèle de certificat des messages IR/CR/KUR.

Le sujet du certificat de référence est utilisé comme valeur du champ destinataire dans les en-têtes des messages CMP. Son émetteur est utilisé comme destinataire par défaut dans les en-têtes des messages CMP.

OSSL_CMP_CTX_set1_p10CSR() définit le CSR PKCS#10 à utiliser dans les messages P10CR. Si un CSR est fourni, ses champs sujet et clé publique sont également utilisés comme valeurs de remplacement pour le modèle IR/CR/KUR/RR, et les extensions incluses sont ajoutées au modèle IR/CR/KUR.

OSSL_CMP_CTX_push0_genm_ITAV() ajoute le itav à la pile dans le ctx qui constituera le corps d'un message général envoyé avec ce contexte.

OSSL_CMP_certConf_cb() est la fonction de rappel par défaut pour la confirmation des certificats. Si l'argument du rappel n'est pas NULL, il doit pointer vers un ensemble de certificats de confiance. Dans ce cas, la fonction vérifie que le certificat nouvellement inscrit peut être vérifié en utilisant cet ensemble de certificats de confiance et les certificats non fiables du ctx, qui ont été étendus par la liste de extraCerts. Pendant cette vérification, toute vérification de statut est désactivée. Si l'argument du rappel est NULL, la fonction tente de construire une chaîne approximative aussi loin que possible en utilisant les mêmes certificats non fiables du ctx, et si cela échoue, elle utilise les extraCerts reçus comme solution de repli. La chaîne de certificats résultante peut être récupérée via OSSL_CMP_CTX_get1_newChain(). Cette chaîne exclut le certificat feuille, c'est-à-dire le certificat nouvellement inscrit. L'ancre de confiance (le certificat racine) est également exclue.

OSSL_CMP_CTX_set_certConf_cb() définit le rappel utilisé pour évaluer le certificat nouvellement inscrit avant que la bibliothèque n'envoie, en fonction du résultat, un message de type certConf positif ou négatif au serveur. Le rappel a le type :

typedef int (*OSSL_CMP_certConf_cb_t) (OSSL_CMP_CTX *ctx, X509 *cert, int fail_info, const char **txt);

et doit inspecter le certificat obtenu via le paramètre cert et peut compléter la prédiction donnée dans les paramètres fail_info et *txt. S'il accepte le certificat, il doit renvoyer 0, indiquant le succès. Sinon, il doit renvoyer un champ de bits reflétant OSSL_CMP_PKIFailureInfo avec au moins un bit d'échec et peut définir le paramètre *txt pour pointer vers une constante de chaîne avec plus de détails. Le rappel de transfert peut utiliser un argument défini par l'utilisateur stocké dans le ctx via OSSL_CMP_CTX_set_certConf_cb_arg(), qui peut être récupéré via OSSL_CMP_CTX_get_certConf_cb_arg(). En général, le rappel vérifiera au moins que le certificat peut être vérifié à l'aide d'un ensemble de certificats de confiance. Il pourrait également comparer le DN du sujet et d'autres champs du certificat nouvellement inscrit au modèle de certificat du demandeur.

OSSL_CMP_CTX_set_certConf_cb_arg() définit un argument, respectivement un pointeur vers une structure contenant les arguments, éventuellement utilisé par le rappel de confirmation de certificat. arg n'est pas consommé et doit donc être explicitement libéré lorsqu'il n'est plus nécessaire. arg peut être NULL pour effacer l'enregistrement.

OSSL_CMP_CTX_get_certConf_cb_arg() obtient l'argument, respectivement le pointeur vers une structure contenant les arguments, précédemment défini via OSSL_CMP_CTX_set_certConf_cb_arg(), ou NULL s'il n'a pas été défini.

OSSL_CMP_CTX_get_status() renvoie pour les contextes client le OSSL_CMP_PKISTATUS du statut PKI du dernier message CertRepMessage ou Revocation Response ou message d'erreur reçu : =item OSSL_CMP_PKISTATUS_request s'il n'a pas été possible de produire une demande IR/CR/KUR/RR/GENM :

OSSL_CMP_PKISTATUS_request
s'il n'a pas été possible de produire une demande IR/CR/KUR/RR/GENM,
OSSL_CMP_PKISTATUS_trans
en cas d'erreur de transmission ou d'erreur de transaction pour ce type de requête, et
OSSL_CMP_PKISTATUS_unspecified
si aucune requête de ce type n'a été tentée ou si OSSL_CMP_CTX_reinit() a été appelé.

Pour les contextes serveur, renvoie OSSL_CMP_PKISTATUS_trans si une transaction est ouverte, sinon OSSL_CMP_PKISTATUS_unspecified.

OSSL_CMP_CTX_get0_statusString() renvoie le statusString du dernier message CertRepMessage ou Revocation Response ou message d'erreur reçu, ou NULL s'il n'a pas été défini.

OSSL_CMP_CTX_get_failInfoCode() renvoie le code d'erreur du champ failInfo du dernier message CertRepMessage ou Revocation Response ou message d'erreur reçu, ou -1 si aucune réponse de ce type n'a été reçue ou si OSSL_CMP_CTX_reinit() a été appelé. Il s'agit d'un champ de bits et les drapeaux sont spécifiés dans le fichier d'en-tête <openssl/cmp.h>. Les drapeaux commencent par OSSL_CMP_CTX_FAILINFO, par exemple : OSSL_CMP_CTX_FAILINFO_badAlg. Renvoie -1 si le champ failInfoCode n'est pas défini.

OSSL_CMP_CTX_get0_validatedSrvCert() renvoie le certificat correctement validé que le serveur a utilisé dans la transaction actuelle pour la protection des messages de réponse basée sur la signature, ou NULL si le serveur a utilisé une protection basée sur MAC. La valeur n'est pertinente qu'à la fin d'une transaction réussie. Elle peut être utilisée pour vérifier l'autorisation du serveur en fonction de son certificat.

OSSL_CMP_CTX_get0_newCert() renvoie le pointeur vers le nouveau certificat obtenu s'il est disponible, sinon NULL.

OSSL_CMP_CTX_get1_newChain() renvoie un pointeur vers une copie de la pile de certificats X.509 calculée par OSSL_CMP_certConf_cb() (si cette fonction a été appelée) dans le message de réponse de la dernière transaction IP/CP/KUP.

OSSL_CMP_CTX_get1_caPubs() renvoie un pointeur vers une copie de la liste des certificats X.509 dans le champ caPubs de la dernière réponse du message de certification (de type IP, CP ou KUP), ou une pile vide si aucun caPubs n'a été reçu dans la transaction actuelle.

OSSL_CMP_CTX_get1_extraCertsIn() renvoie un pointeur vers une copie de la liste des certificats X.509 contenus dans le champ extraCerts de la dernière réponse du message de certification (sauf pour pollRep et OSSL_CMP_PKIConf), ou une pile vide si aucun extraCerts n'a été reçu dans la transaction actuelle.

OSSL_CMP_CTX_set1_transactionID() définit l'ID de transaction donné dans la structure OSSL_CMP_CTX donnée.

OSSL_CMP_CTX_set1_senderNonce() stocke le nonce du destinataire le plus récent dans ctx. Celui-ci sera utilisé pour valider le nonce réciproque dans les messages entrants.

CMP est défini dans la RFC 4210 (et CRMF dans la RFC 4211).

VALEURS DE RETOUR

OSSL_CMP_CTX_free() et OSSL_CMP_CTX_print_errors() ne renvoient rien.

OSSL_CMP_CTX_new(), OSSL_CMP_CTX_get0_libctx(), OSSL_CMP_CTX_get0_propq(), OSSL_CMP_CTX_get_http_cb_arg(), OSSL_CMP_CTX_get_transfer_cb_arg(), OSSL_CMP_CTX_get0_trusted(), OSSL_CMP_CTX_get0_untrusted(), OSSL_CMP_CTX_get0_geninfo_ITAVs(), OSSL_CMP_CTX_get0_newPkey(), OSSL_CMP_CTX_get_certConf_cb_arg(), OSSL_CMP_CTX_get0_statusString(), OSSL_CMP_CTX_get0_validatedSrvCert(), OSSL_CMP_CTX_get0_newCert(), OSSL_CMP_CTX_get1_caPubs(), et OSSL_CMP_CTX_get1_extraCertsIn() renvoient la valeur de pointeur prévue comme décrit ou NULL en cas d'erreur.

OSSL_CMP_CTX_get_option(), OSSL_CMP_CTX_reqExtensions_have_SAN(), OSSL_CMP_CTX_get_status(), et OSSL_CMP_CTX_get_failInfoCode() renvoient la valeur prévue comme décrit ou -1 en cas d'erreur.

OSSL_CMP_certConf_cb() renvoie fail_info s'il n'est pas égal à 0, sinon 0 en cas de validation réussie, ou un champ de bits avec le bit OSSL_CMP_PKIFAILUREINFO_incorrectData défini.

Toutes les autres fonctions, y compris OSSL_CMP_CTX_reinit() et OSSL_CMP_CTX_reset_geninfo_ITAVs(), renvoient 1 en cas de succès, 0 en cas d'erreur.

EXEMPLES

Le code suivant omet la gestion des erreurs.

Configure un contexte client CMP pour envoyer des requêtes et vérifier les réponses :

cmp_ctx = OSSL_CMP_CTX_new();

OSSL_CMP_CTX_set1_serverPort(cmp_ctx, port_string);
OSSL_CMP_CTX_set1_serverPath(cmp_ctx, path_or_alias);
OSSL_CMP_CTX_set0_trusted(cmp_ctx, ts);

Configure les identifiants symétriques pour la protection basée sur MAC comme PBM :

OSSL_CMP_CTX_set1_referenceValue(cmp_ctx, ref, ref_len);
OSSL_CMP_CTX_set1_secretValue(cmp_ctx, sec, sec_len);

DESCRIPTION

The OpenSSL CMP (Certificate Management Protocol) implementation uses a context structure OSSL_CMP_CTX to hold all information related to a CMP transaction.

OSSL_CMP_CTX_new() allocates and initializes a new context. The config_name is a name of a configuration section, see openssl.cnf(5) for details. If config_name is NULL then the default context is used.

OSSL_CMP_CTX_free() frees the context and all associated allocated memory.

OSSL_CMP_CTX_init() initializes an already allocated context.

The functions starting with OSSL_CMP_CTX_set... are used to set various parameters and credentials in the context. Functions with set0 transfer ownership of the passed parameter to the context. Functions with set1 copy the parameter and transfer ownership of the copy to the context. Functions with get0 return a pointer to the parameter inside the context, without copying. The caller must not free the returned value, nor modify it.

The available parameters are:

newNode:
The new certificate to be registered in the context.
recipientKey:
The recipient's private key, used for encrypting the message in transit.
newPkey:
The new private key associated with the certificate being requested or updated.
oldPkey:
The old private key, in case of key update.
finalPkey:
The final private key after the key update transaction.
caName:
The general name of the CA that issued the certificate.
caCrl:
The CRL published by the CA.
sender:
The sender information as specified in RFC 4210, Section 5.3.4.
recipient:
The recipient information as specified in RFC 4210, Section 5.3.5.
certProfile:
The certificate profile to be used.
algPROTECT:
The protection algorithm to be used. If not set, it is determined by the server.
serverPath:
The path for the CMP server, e.g. /cmp/server. If not set, it defaults to /
proxyPath:
The path for the CMP proxy server.
transid:
The transaction identifier.
failInfo:
Information about a failure.
reason:
The reason for the failure.
prompt:
A prompt string for user interaction.
certOrChain:
A certificate chain to be sent to the server, e.g. as part of a certification request.
chainOrCert:
A certificate or chain to be sent to the server, e.g. as part of a certification request.
trusted:
A stack of trusted certificates (trusted CA certificates).
crl:
A stack of CRLs.
untrusted:
A stack of untrusted certificates.
privateKey:
The private key to be used for signing requests.
cert:
The certificate to be used for signing requests.
subjectName:
The subject name for a certificate request.
serialNumber:
The serial number of a certificate.
referenceValue:
A reference value, e.g. for authentication.
secretValue:
A secret value, e.g. for authentication.
signKey:
The private key used to sign the outgoing CMP message.
signCert:
The certificate used to sign the outgoing CMP message.
authInfo:
Authentication information, e.g. credentials.
libctx:
OpenSSL library context.
propq:
Property query string.
validatedSrvCert:
The server certificate validated by the client.

OSSL_CMP_CTX_set_transfer_cb() sets a callback function cb that will be called to perform the actual transport of CMP messages. The callback function is provided with the context, an input BIO in, an output BIO out, and an arbitrary argument arg. The callback should read the request from in and write it to out, or vice versa for the response. It should return 1 on success and 0 on failure. The argument arg can be set using OSSL_CMP_CTX_set_transfer_cb_arg() and retrieved using OSSL_CMP_CTX_get_transfer_cb_arg().

OSSL_CMP_CTX_push0_genm_ITAV() adds an Information Template Attribute Value (ITAV) to the general information field of the next outgoing CMP message. Ownership of itav is transferred to the context. Use OSSL_CMP_CTX_pop0_genm_ITAV() to remove and free the last added ITAV.

OSSL_CMP_CTX_get0_genm_ITAVs() returns the stack of ITAVs in the context.

OSSL_CMP_CTX_reset_geninfo_ITAVs() removes all ITAVs from the context.

OSSL_CMP_CTX_reinit() resets the CMP transaction state in the context, clearing any pending messages, transaction IDs, and other state specific to the previous transaction.

OSSL_CMP_CTX_ctrl() is a generic function to control various aspects of the CMP context. The specific commands and their arguments are defined in the OpenSSL internal headers.

OSSL_CMP_CTX_get_cmp_version() and OSSL_CMP_CTX_set_cmp_version() get and set the CMP protocol version to be used.

OSSL_CMP_CTX_get_log() and OSSL_CMP_CTX_set_log() get and set the logging object.

The functions related to outstanding reports provide statistics on received CMP reports.

OSSL_CMP_CTX_get_last_error(), OSSL_CMP_CTX_get_last_req_msg(), OSSL_CMP_CTX_get_last_rep_msg(), OSSL_CMP_CTX_get_last_cmp_err(), OSSL_CMP_CTX_get_last_http_code(), OSSL_CMP_CTX_get_last_expected_http_code(), OSSL_CMP_CTX_get_last_expected_srv_cert(), and OSSL_CMP_CTX_get_last_transport_data() retrieve information about the last executed CMP transaction, including the last error, the last request and reply messages, the last CMP error code, the last HTTP response code, the expected HTTP response code, the server certificate, and the transport data.

NOTES

Ownership semantics: functions with set0 transfer ownership of the passed pointer to the context. The caller must not free this pointer afterwards. Functions with set1 make a copy of the passed object and transfer ownership of the copy to the context. The caller can free the original object. Functions with get0 return a pointer to an object owned by the context. The caller must not free this pointer.

All pointers passed to set* functions are owned by the context after the call, and will be freed when OSSL_CMP_CTX_free() or OSSL_CMP_CTX_reinit() is called.

The set0 functions must be used with caution, as the context takes ownership and will free the object pointer when appropriate. Using a dangling pointer after a set0 call will lead to undefined behavior.

The CMP functions are designed to be used in a transactional manner. The context OSSL_CMP_CTX holds the state between individual steps of a transaction.

For example, a certificate request transaction typically involves these steps:

  1. Initialize context: ctx = OSSL_CMP_CTX_new(...)
  2. Set up credentials and parameters: OSSL_CMP_CTX_set1_signKey(...), OSSL_CMP_CTX_set1_signCert(...), OSSL_CMP_CTX_set1_subjectName(...), etc.
  3. Perform transaction: e.g. OSSL_CMP_exec_certreq(ctx)
  4. Check result and free context: OSSL_CMP_CTX_free(ctx)

Note that for multi-step transactions, like enrolling a new certificate and then using it to update the key, the context needs to be reinitialized and populated with new credentials between steps.

RETURN VALUES

OSSL_CMP_CTX_new(), OSSL_CMP_CTX_init(), and all OSSL_CMP_CTX_set* functions return 1 on success, and 0 on failure.

OSSL_CMP_CTX_free() returns void.

OSSL_CMP_CTX_get*() functions return the value associated with the context, or NULL if not set.

OSSL_CMP_CTX_reinit() returns 1 on success, and 0 on failure.

OSSL_CMP_CTX_push0_genm_ITAV() and OSSL_CMP_CTX_pop0_genm_ITAV() return 1 on success, and 0 on failure.

OSSL_CMP_CTX_get0_genm_ITAVs() returns a pointer to the stack of ITAVs, or NULL if none are set.

OSSL_CMP_CTX_reset_geninfo_ITAVs() returns void.

OSSL_CMP_CTX_ctrl() returns 1 on success, and 0 on failure.

OSSL_CMP_CTX_get_cmp_version() returns the CMP version, or 0 if not set.

OSSL_CMP_CTX_set_cmp_version() returns 1 on success, 0 on failure.

OSSL_CMP_CTX_get_log() returns the log object, or NULL if not set.

OSSL_CMP_CTX_set_log() returns 1 on success, 0 on failure.

Functions for outstanding reports return the count of items, or -1 on error.

OSSL_CMP_CTX_get_last_error(), OSSL_CMP_CTX_get_last_req_msg(), OSSL_CMP_CTX_get_last_rep_msg(), OSSL_CMP_CTX_get_last_expected_srv_cert(), and OSSL_CMP_CTX_get_last_transport_data() return pointers to the respective objects, or NULL if not available.

OSSL_CMP_CTX_get_last_cmp_err(), OSSL_CMP_CTX_get_last_http_code(), and OSSL_CMP_CTX_get_last_expected_http_code() return long integers, or 0 or -1 if not available.

OSSL_CMP_CTX_set_transfer_cb(), OSSL_CMP_CTX_get_transfer_cb(), OSSL_CMP_CTX_set_transfer_cb_arg(), and OSSL_CMP_CTX_get_transfer_cb_arg() return 1 on success, and 0 on failure.

EXAMPLES

Set up the details for certificate requests:

OSSL_CMP_CTX_set1_subjectName(cmp_ctx, name);
OSSL_CMP_CTX_set0_newPkey(cmp_ctx, 1, initialKey);

Perform an Initialization Request transaction:

initialCert = OSSL_CMP_exec_IR_ses(cmp_ctx);

Reset the transaction state of the CMP context and the credentials:

OSSL_CMP_CTX_reinit(cmp_ctx);
OSSL_CMP_CTX_set1_referenceValue(cmp_ctx, NULL, 0);
OSSL_CMP_CTX_set1_secretValue(cmp_ctx, NULL, 0);

Perform a Certification Request transaction, making use of the new credentials:

OSSL_CMP_CTX_set1_cert(cmp_ctx, initialCert);
OSSL_CMP_CTX_set1_pkey(cmp_ctx, initialKey);
OSSL_CMP_CTX_set0_newPkey(cmp_ctx, 1, curentKey);
currentCert = OSSL_CMP_exec_CR_ses(cmp_ctx);

Perform a Key Update Request, signed using the cert (and key) to be updated:

OSSL_CMP_CTX_reinit(cmp_ctx);
OSSL_CMP_CTX_set1_cert(cmp_ctx, currentCert);
OSSL_CMP_CTX_set1_pkey(cmp_ctx, currentKey);
OSSL_CMP_CTX_set0_newPkey(cmp_ctx, 1, updatedKey);
currentCert = OSSL_CMP_exec_KUR_ses(cmp_ctx);
currentKey = updatedKey;

Perform a General Message transaction including, as an example, the id-it-signKeyPairTypes OID and prints info on the General Response contents:

OSSL_CMP_CTX_reinit(cmp_ctx);
ASN1_OBJECT *type = OBJ_txt2obj("1.3.6.1.5.5.7.4.2", 1);
OSSL_CMP_ITAV *itav = OSSL_CMP_ITAV_create(type, NULL);
OSSL_CMP_CTX_push0_genm_ITAV(cmp_ctx, itav);
STACK_OF(OSSL_CMP_ITAV) *itavs;
itavs = OSSL_CMP_exec_GENM_ses(cmp_ctx);
print_itavs(itavs);
sk_OSSL_CMP_ITAV_pop_free(itavs, OSSL_CMP_ITAV_free);

HISTORIQUE

Les fonctions CMP d'OpenSSL ont été ajoutées dans OpenSSL 3.0.

OSSL_CMP_CTX_get0_trustedStore() a été renommé en OSSL_CMP_CTX_get0_trusted() et OSSL_CMP_CTX_set0_trustedStore() a été renommé en OSSL_CMP_CTX_set0_trusted(), en utilisant des macros, tout en gardant les anciens noms pour des raisons de compatibilité ascendante, dans OpenSSL 3.2.

OSSL_CMP_CTX_reset_geninfo_ITAVs() a été ajouté dans OpenSSL 3.0.8.

OSSL_CMP_CTX_set1_serialNumber(), OSSL_CMP_CTX_get0_libctx(), OSSL_CMP_CTX_get0_propq(), et OSSL_CMP_CTX_get0_validatedSrvCert() ont été ajoutés dans OpenSSL 3.2.

OSSL_CMP_CTX_get0_geninfo_ITAVs() a été ajouté dans OpenSSL 3.3.

La prise en charge de la génération de clé centrale, demandée via OSSL_CRMF_POPO_NONE, a été ajoutée dans OpenSSL 3.5.
