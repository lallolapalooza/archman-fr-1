Documentation Constructeur & Destructeur

OpenDBX::Conn::Conn ()

Le constructeur par défaut pour les objets de connexion nouvellement créés sans paramètres. Cette méthode est fournie pour permettre aux programmeurs d'utiliser des objets de connexion comme variables membres d'autres classes. Ils sont initialisés lors de la construction de l'objet englobant lorsqu'aucune valeur pour le backend, l'hôte et le port n'est encore disponible.

Il est nécessaire de remplacer l'objet créé ultérieurement par une instance de connexion pour laquelle les paramètres nécessaires ont été fournis via l'un des autres constructeurs. L'appel de l'une des fonctions membres d'une instance créée par le constructeur par défaut n'est pas possible et lèvera une exception.

Retourne

Instance de connexion vide

OpenDBX::Conn::Conn (const char * backend, const char * host = '', const char * port = '')

Crée un objet de connexion en utilisant des paramètres de chaîne de caractères de style C. Initialise une nouvelle connexion en utilisant les paramètres backend, host et port, mais n'ouvre pas encore la connexion à la base de données. Cette méthode autorise les chaînes de caractères de style C comme valeurs pour tous les paramètres. Un autre constructeur pour les chaînes de caractères de style C++ est également disponible. Il retourne une nouvelle instance de connexion, qui peut être utilisée pour interroger les options implémentées par le pilote ou pour créer une requête. En cas d'erreur, il lève une exception OpenDBX avec le message d'erreur, le code et la sévérité.

Le paramètre backend est le nom du pilote que la bibliothèque OpenDBX doit utiliser pour se connecter à une base de données. Le nom doit être l'un des pilotes implémentés et disponibles sur le système et est sensible à la casse. Tous les noms de pilotes sont en minuscules, par exemple 'mysql'.

Selon le pilote de base de données, host peut avoir des significations différentes. Normalement, c'est le nom ou l'adresse IP du serveur hébergeant l'application serveur de base de données. Dans le cas d'implémentations de bases de données sans serveur comme SQLite, c'est le chemin du répertoire où se trouve le fichier de base de données. Le chemin doit contenir les séparateurs de chemin spécifiques à la plateforme comme le slash ('/') sur les systèmes de type Unix et le backslash ('\') sur les systèmes Windows. Le chemin doit également se terminer par le séparateur de chemin comme '/chemin/vers/fichier/'.

De plus, port peut être le numéro ou le nom auquel l'application serveur de base de données écoute. Si un nom au lieu du numéro est autorisé dépend de la bibliothèque cliente de base de données, mais le numéro sous forme de chaîne fonctionne toujours. Si une chaîne vide est fournie, le port par défaut de l'application serveur de base de données est utilisé par la bibliothèque cliente de base de données.

Paramètres

backend Nom du module backend à utiliser
host Nom ou adresse IP du serveur de base de données
port Nom ou numéro du port utilisé par le serveur de base de données

Retourne

Instance de connexion

Exceptions

std::invalid_argument Si l'objet a été uniquement initialisé par le constructeur par défaut
OpenDBX::Exception Si la bibliothèque de base de données sous-jacente renvoie une erreur

OpenDBX::Conn::~Conn ()

Détruit l'instance de connexion s'il n'y a pas d'autres références. Chaque objet de connexion utilise un compteur de références pour se souvenir si la connexion est partagée avec d'autres objets. OpenDBX::Conn::Conn (const Conn & ref)

Constructeur de copie. Permet le transfert de l'état interne d'un objet ref du même type vers cet objet. Les deux objets partagent la même connexion à la base de données et le compteur de références par la suite. Le compteur de références est incrémenté chaque fois qu'un objet est copié et sera décrémenté s'il est détruit.

void OpenDBX::Conn::bind (const char * database, const char * who = '', const char * cred = '', odbxbind method = ODBX_BIND_SIMPLE)

Authentifie l'utilisateur et sélectionne la base de données en utilisant des paramètres de chaîne de style C. Après avoir initialisé l'instance de l'objet avec l'un des constructeurs prenant un backend, un hôte et un port en paramètre, il est nécessaire d'authentifier l'utilisateur et de sélectionner une base de données. Selon la bibliothèque cliente de base de données, cela établit également la connexion au serveur de base de données. Cette méthode accepte des chaînes de style C pour le nom de la base de données, le nom d'utilisateur et le mot de passe.

Le premier paramètre, le nom de la base de données, sera utilisé pour sélectionner la base de données sur laquelle toutes les commandes ultérieures opèrent. La base de données est le conteneur pour les tables, les vues, etc., qui stockent les enregistrements et fournissent un accès à ceux-ci.

L'authentification se fait dans la plupart des cas par une combinaison d'un nom d'utilisateur et d'un mot de passe. Si le nom d'utilisateur est connu du serveur de base de données et que le mot de passe fourni correspond à celui stocké, le serveur de base de données autorisera l'utilisateur à opérer sur la base de données sélectionnée et ses tables, à condition que l'utilisateur ait les permissions de lire et/ou de modifier le contenu.

Le paramètre method peut être utilisé pour sélectionner différentes méthodes d'authentification. Actuellement, seule l'authentification simple (ODBX_BIND_SIMPLE) avec nom d'utilisateur et mot de passe est disponible.

Paramètres

database Nom de la base de données gérée par le serveur de base de données
who Nom du compte utilisateur connu du serveur de base de données
cred Identifiant nécessaire appartenant au compte utilisateur
method Méthode utilisée pour l'authentification

Exceptions

std::invalid_argument Si l'objet a été uniquement initialisé par le constructeur par défaut
OpenDBX::Exception Si la bibliothèque de base de données sous-jacente renvoie une erreur

Stmt OpenDBX::Conn::create (const char * sql, unsigned long size = 0, Stmt::Type type = Stmt::Simple)

Crée un objet de requête à partir d'une chaîne de texte SQL à l'aide d'un tampon de style C. Cette méthode renvoie une instance de la classe Stmt qui contient la requête envoyée au serveur de base de données ultérieurement. Actuellement, seules les requêtes simples sont prises en charge, qui sont envoyées au serveur de base de données pour analyse et renvoi du résultat après l'appel de Stmt::execute(). Plus tard, des requêtes préparées seront également possibles, qui sont analysées par le serveur de base de données lors de la création de l'objet et seuls les paramètres seront envoyés au serveur de base de données lors de l'exécution. Cela peut accélérer le traitement, surtout si la requête est exécutée plusieurs fois avec un contenu différent pour les paramètres.

Le paramètre nommé sql doit contenir la chaîne de texte SQL qui doit être envoyée au serveur de base de données pour exécution. Il doit s'agir d'un tampon de style C dans ce cas. Pour une référence des instructions SQL valides, veuillez consulter la documentation de votre serveur de base de données.

La longueur de la requête, à l'exclusion de l'octet '0' final, doit être fournie via le deuxième paramètre size. Si la longueur de la requête est inconnue, vous pouvez également fournir zéro (0) comme valeur de taille, ce qui est également la valeur par défaut si vous ne fournissez qu'un seul paramètre. Dans ce cas, la longueur de la chaîne est calculée en interne par cette fonction avant que la requête ne soit transmise à la bibliothèque de base de données native.

Via le dernier paramètre, il est possible de sélectionner comment la requête doit être traitée en interne par OpenDBX et la bibliothèque de base de données native. Actuellement, seul le traitement simple est disponible, qui envoie des instructions SQL complètes, y compris leurs paramètres, sous forme de chaîne au serveur de base de données pour analyse et exécution. Plus tard, la gestion des requêtes préparées sera également disponible, qui analyse d'abord les instructions et n'envoie que les paramètres au serveur avant l'exécution. Ce paramètre est également facultatif.

L'objet renvoyé représente la requête donnée, qui peut être exécutée plus tard. La requête n'est valide que pour la connexion actuelle et dès que la connexion devient invalide ou est fermée, travailler avec cet objet provoquera une erreur.

Paramètres

sql Chaîne de texte SQL contenant une instruction valide comprise par le serveur de base de données
size Taille de la chaîne de texte SQL en octets
type Type d'objet de requête qui doit être créé

Retourne

Instance de requête liée à cette connexion

Exceptions

std::invalid_argument Si l'objet a été uniquement initialisé par le constructeur par défaut
OpenDBX::Exception Si la bibliothèque de base de données sous-jacente renvoie une erreur

string & OpenDBX::Conn::escape (const char * from, unsigned long fromlen, string & to)

Échappe les caractères potentiellement dangereux dans l'entrée utilisateur à l'aide d'un tampon de style C. Pour prévenir les attaques par injection SQL qui peuvent avoir des effets désastreux, toute entrée textuelle qui fera partie d'une instruction SQL doit être échappée. Cela s'applique également au contenu utilisateur déjà stocké dans la base de données et qui doit être copié dans un autre enregistrement ou stocké à nouveau, car l'échappement est supprimé avant que le serveur de base de données n'écrive le contenu sur le disque.

Le premier paramètre doit contenir la séquence de caractères à échapper sous forme de chaîne de caractères de style C. Cette chaîne elle-même ne sera pas modifiée par cette méthode.

La chaîne échappée sera écrite dans le troisième paramètre nommé to, qui doit également être une chaîne de caractères de style C++. Après avoir transformé l'entrée en une chaîne échappée, le résultat peut être plus du double de la taille de l'entrée d'origine. Les séquences d'échappement supplémentaires ne sont pas stockées dans la colonne de la base de données, donc seule la chaîne d'origine sera écrite sur le disque.

Une référence C++ du troisième paramètre contenant la chaîne échappée est également retournée par cette méthode, offrant ainsi la possibilité d'écrire un code plus élégant.

Paramètres

from Chaîne d'entrée contenant potentiellement des caractères dangereux
fromlen Taille de la chaîne d'entrée à échapper en octets
to Instance de chaîne où les caractères échappés doivent être écrits

Retourne

Référence au deuxième paramètre contenant les caractères échappés

Exceptions

std::invalid_argument Si l'objet a été initialisé uniquement par le constructeur par défaut
OpenDBX::Exception Si la bibliothèque de base de données sous-jacente renvoie une erreur

bool OpenDBX::Conn::getCapability (odbxcap cap)

Teste si le module de pilote de base de données comprend certaines extensions. La bibliothèque OpenDBX se compose d'un ensemble de fonctions de base qui doivent être implémentées par tous les pilotes et d'ensembles optionnels pour des fonctionnalités supplémentaires. Cette méthode permet à une application de demander au pilote sélectionné par le premier paramètre du constructeur de cet objet s'il prend en charge un ou plusieurs ensembles optionnels. Les ensembles disponibles et leurs constantes sont :

  • ODBX_CAP_BASIC
    L'ensemble de fonctions de base qui doit être implémenté par tous les backends. Il se compose de toutes les fonctions nécessaires pour se connecter à la base de données, lui envoyer des requêtes textuelles et traiter les résultats simples renvoyés par le serveur de base de données, ainsi que des fonctions de gestion des erreurs.
  • ODBX_CAP_LO
    L'ensemble de fonctions pour gérer les objets volumineux dont le contenu n'est pas accessible par les fonctions de base. Actuellement, Firebird/Interbase et Oracle nécessitent l'utilisation des fonctions LOB.

L'ensemble de base garantit que tous les pilotes peuvent gérer les connexions aux bases de données, envoyer des instructions et récupérer les résultats. Il est pris en charge par tous les pilotes et ne nécessite généralement pas de vérification.

Certaines bibliothèques clientes de bases de données fournissent le contenu des objets volumineux non pas via les fonctions de base. Au lieu de cela, la méthode Result::fieldValue() ne renvoie qu'un handle vers l'objet volumineux, et la lecture ou la modification du contenu de cet objet de données nécessite d'appeler des méthodes supplémentaires.

Paramètres

cap Constante de la capacité

Retourne

Vrai si pris en charge, faux sinon

OpenDBX::Exception Si la bibliothèque de base de données sous-jacente renvoie une erreur

void OpenDBX::Conn::getOption (odbxopt option, void * value)

Obtient la valeur d'une option spécifique fournie par le module de pilote de base de données. Il interroge le module backend pour les options implémentées et leurs valeurs actuelles. Cette fonction peut être utilisée à tout moment et son objectif principal est de découvrir les fonctionnalités prises en charge par le module backend. Ces fonctionnalités peuvent être activées avec setOption() avant que la connexion au serveur de base de données ne soit établie en appelant bind().

Plusieurs valeurs d'options sont définies comme des constantes nommées dans le fichier d'en-tête opendbx/api.h. Certaines sont uniquement à titre informatif, tandis que la plupart des options peuvent également être définies sur différentes valeurs par setOption() pour modifier le comportement du module backend. Ces options sont :

  • ODBX_OPT_API_VERSION
    La version de l'API implémentée par le backend. Elle renvoie un nombre à cinq chiffres représentant la version de l'API du module backend sous la forme XYYZZ, où X est le numéro majeur, YY la révision et ZZ le numéro mineur de l'API.
  • ODBX_OPT_THREAD_SAFE
    S'il est sûr d'utiliser ce backend et en particulier la bibliothèque cliente native de base de données dans une application qui utilise des threads où plus d'un thread ouvre des connexions de base de données via la bibliothèque OpenDBX.
  • ODBX_OPT_TLS
    La bibliothèque cliente de base de données peut prendre en charge la transmission sécurisée de toutes les données en chiffrant le trafic réseau via SSL ou TLS.
  • ODBX_OPT_MULTI_STATEMENTS
    Le serveur de base de données peut prendre en charge plusieurs instructions SQL dans une seule chaîne envoyée à la base de données.
  • ODBX_OPT_PAGED_RESULTS
    Tous les serveurs de base de données et bibliothèques clientes peuvent transférer les enregistrements ligne par ligne. Certains d'entre eux peuvent également transférer plusieurs lignes, voire toutes en une seule fois, afin de minimiser la charge du serveur, le trafic réseau et la latence. L'inconvénient est une consommation de mémoire accrue.
  • ODBX_OPT_COMPRESS
    Prise en charge du trafic réseau compressé entre le client et le serveur de base de données. Cela peut entraîner un débit plus élevé si le réseau est le goulot d'étranglement.
  • ODBX_OPT_MODE
    Certains serveurs de base de données prennent en charge différents modes de fonctionnement, par exemple, des modes pour la conformité à d'autres implémentations SQL ou des langages de requête complètement différents.

Le paramètre value doit être un pointeur vers une variable entière où le module backend stockera le résultat pour l'option fournie. Sauf indication contraire, la valeur attribuée à ce paramètre sera de nature booléenne et sera donc ODBX_ENABLE pour une option prise en charge ou ODBX_DISABLE pour une option non prise en charge.

void OpenDBX::Conn::setOption (odbxopt option, void * value)

Définit une certaine option fournie par le module de pilote de base de données. Modifie la valeur de l'option spécifiée dans le module backend ou dans la bibliothèque de base de données native. Avant de tenter de définir une option, vous devez la tester avec getOption() pour vous assurer qu'elle est prise en charge par le backend. Presque toutes les options doivent être définies avant de se connecter au serveur de base de données en utilisant bind() pour avoir un effet.

Il existe plusieurs valeurs d'option définies comme constantes nommées dans le fichier opendbx/api.h. Les options possibles sont :

  • ODBX_OPT_TLS
    Utilise le chiffrement pour transmettre toutes les données de manière sécurisée sur le réseau via SSL ou TLS. Cette option peut être définie sur ODBX_TLS_NEVER (la valeur par défaut) pour éviter le chiffrement, ODBX_TLS_ALWAYS pour exiger le chiffrement et échouer s'il ne peut pas être utilisé entre la bibliothèque client et le serveur, ou ODBX_TLS_TRY pour utiliser le chiffrement si possible avec la possibilité de revenir à une connexion non chiffrée.
  • ODBX_OPT_MULTI_STATEMENTS
    Permet au serveur de base de données d'accepter plusieurs instructions dans une seule chaîne vers la base de données si la valeur est définie sur ODBX_ENABLE. Cependant, il peut être possible de la désactiver en la définissant sur ODBX_DISABLE.
  • ODBX_OPT_PAGED_RESULTS
    Tous les serveurs de base de données et les bibliothèques clientes sont capables de transférer les enregistrements ligne par ligne. Certains d'entre eux peuvent également transférer plusieurs lignes, voire toutes en une seule fois, afin de minimiser la charge du serveur, le trafic réseau et la latence. L'inconvénient est une consommation de mémoire accrue. Si les résultats paginés sont pris en charge par le backend, la transmission de valeurs positives récupérera le nombre spécifié d'enregistrements à la fois à partir du serveur de base de données. La valeur zéro ('0') est spéciale dans ce cas car elle demande au module backend de récupérer tous les enregistrements à la fois.
  • ODBX_OPT_COMPRESS
    Active le trafic réseau compressé entre le client et le serveur de base de données. Cela peut maximiser le débit si le réseau est le goulot d'étranglement. Transmettez une variable entière avec ODBX_ENABLE pour activer la compression ou avec ODBX_DISABLE pour la désactiver pour cette connexion.
  • ODBX_OPT_MODE
    Certains serveurs de base de données prennent en charge différents modes de fonctionnement, par exemple des modes de conformité à d'autres implémentations SQL ou des langages de requête complètement différents. La valeur de cette option doit pointer vers une chaîne terminée par null.

Sauf indication contraire, le type de la valeur transmise au deuxième paramètre, appelé value, doit être un pointeur vers un entier. Ses valeurs doivent être dans la plage spécifiée par l'option en cours de modification.

Paramètres

option Constante de l'option
value Pointeur vers la mémoire contenant la nouvelle valeur

Exceptions

OpenDBX::Exception Si le bibliothécaire de base de données renvoie une erreur
