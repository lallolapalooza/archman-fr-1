Object::Event(3) Documentation Perl fournie par l'utilisateur Object::Event(3)

NOM

Object::Event - Une classe qui fournit une interface de rappel d'événements

VERSION

Version 1.23

SYNOPSIS

package foo;
use Object::Event;
our @ISA = qw/Object::Event/;
package main;
my $o = foo->new;
my $regguard = $o->reg_cb (foo => sub {
   print "I got an event, with these args: $_[1], $_[2], $_[3]\n";
});
$o->event (foo => 1, 2, 3);
$o->unreg_cb ($regguard);
# ou simplement:
$regguard = undef;

DESCRIPTION

Ce module a été principalement écrit pour AnyEvent::XMPP, AnyEvent::IRC, AnyEvent::HTTPD et BK afin de fournir une API cohérente pour l'enregistrement et l'émission d'événements. Bien que je l'aie initialement écrit pour ces modules, je l'ai publié séparément au cas où ce module pourrait être utile à quelqu'un.

Pour une gestion d'événements plus complète, consultez également Glib et POE.

Cette classe fournit un moyen simple d'étendre une classe, en héritant de cette classe, avec une interface de rappel d'événements.

Vous pourrez enregistrer des rappels pour des événements, identifiés par leurs noms (une chaîne de caractères) et les appeler plus tard en invoquant la méthode "event" avec le nom de l'événement et quelques arguments.

Il existe même un sucre syntaxique qui permet d'appeler des méthodes sur les instances de classes dérivées d'Object::Event, pour invoquer des événements. Pour cette fonctionnalité, consultez la section "ÉVÉNEMENTS DE MÉTHODES" de ce document.

PERFORMANCE

Dans la première version telle que présentée ici, aucune optimisation spéciale de performance n'a été appliquée. Faites donc attention à ce qu'elle soit assez rapide pour vos besoins. Au moins pour des modules comme AnyEvent::XMPP, la surcharge n'est probablement pas perceptible, car d'autres technologies comme XML déjà gaspillent beaucoup plus de cycles CPU. De plus, les E/S introduisent généralement des surcharges _beaucoup_ plus importantes/longues que cette simple interface d'événements.

FONCTIONS

Object::Event::register_priority_alias ($alias, $priority)
Cette fonction du package ajoutera un alias de priorité global. Si $priority est indéfini, l'alias sera supprimé.

Il y a 4 alias prédéfinis :

avant      =>  1000
ext_avant  =>   500
ext_apres  =>  -500
apres      => -1000

Voir également la méthode "reg_cb" pour plus d'informations sur les alias.

MÉTHODES

Object::Event->new (%args)
Votre::SousClasse::De::Object::Event->new (%args)
C'est le constructeur pour Object::Event, il créera une référence de hachage bénie initialisée avec %args.
$obj->init_object_events ()
Cette méthode ne doit être appelée que si vous ne pouvez pas appeler le constructeur "new" de cette classe. Dans ce cas, vous devez appeler cette méthode pour initialiser le système d'événements.
$obj->set_exception_cb ($cb->($exception, $eventname))
Cette méthode installe un rappel qui sera appelé lorsqu'un autre rappel d'événement lève une exception. Le premier argument de $cb sera l'exception et le second le nom de l'événement.
$guard = $obj->reg_cb ($eventname => $cb->($obj, @args), ...)
$guard = $obj->reg_cb ($eventname => $prio, $cb->($obj, @args), ...)
Cette méthode enregistre un rappel $cb1 pour l'événement avec le nom $eventname1. Vous pouvez également passer plusieurs de ces paires nom d'événement => rappel.

La valeur de retour $guard sera une garde qui représente l'ensemble des rappels que vous avez installés. Vous pouvez soit simplement "oublier" le contenu de $guard pour désenregistrer les rappels, soit appeler "unreg_cb" avec cet identifiant pour les supprimer à nouveau. Si "reg_cb" est appelé dans un contexte vide, aucune garde n'est retournée et vous n'avez aucune possibilité de désenregistrer les rappels enregistrés.

Le premier argument pour les rappels enregistrés avec la fonction "reg_cb" sera toujours l'objet maître $obj.

La valeur de retour des rappels est ignorée. Si vous avez besoin de passer des informations d'un gestionnaire à l'appelant de l'événement, vous devez établir votre propre "protocole" pour cela. Je recommande de passer une référence de tableau aux gestionnaires :

$obj->reg_cb (event_foobar => sub {
   my ($self, $results) = @_;
   push @$results, time / 30;
});
my @results;
$obj->event (event_foobar => \@results);
for (@results) {
   # ...
}

L'ordre des rappels dans la chaîne d'appel de l'événement dépend de leur priorité. Si vous n'avez spécifié aucune priorité (voir ci-dessous), ils reçoivent la priorité par défaut de 0, et sont ajoutés aux autres rappels de priorité 0. Plus le numéro de priorité est élevé, plus tôt les rappels sont appelés dans la chaîne.

Si $eventname1 commence par 'avant_', le rappel reçoit une priorité de 1000, et s'il commence par 'ext_avant_', il reçoit la priorité 500. 'apres_' est mappé à la priorité -1000 et 'ext_apres_' à -500.

Si vous souhaitez un contrôle plus granulaire, vous pouvez passer une référence de tableau au lieu du nom de l'événement :

($eventname1, $prio) = ('test_abc', 100);
$obj->reg_cb ([$eventname1, $prio] => sub {
   ...
});
$obj->unreg_cb ($cb)
Supprime le rappel $cb de l'ensemble des rappels enregistrés.
mon $handled = $obj->event ($eventname, @args)
Émet l'événement $eventname et passe les arguments @args aux rappels. La valeur de retour $handled est une valeur vraie si un gestionnaire a été trouvé et exécuté. Elle renvoie false si aucun gestionnaire n'a été trouvé (voir également la méthode "handles" ci-dessous). En gros : elle renvoie la même valeur que la méthode "handles".

Veuillez noter qu'un événement peut être arrêté et réémis pendant son traitement.

Voir également la spécification des événements avant et après dans "reg_cb" ci-dessus.

NOTE : Chaque fois qu'un événement est émis, l'ensemble actuel des rappels enregistrés pour cet événement sera utilisé. Donc, si vous enregistrez un autre rappel d'événement pour le même événement qui est en cours d'exécution au moment présent, il sera appelé la **prochaine** fois que l'événement sera émis. Exemple :

$obj->reg_cb (event_test => sub {
   my ($obj) = @_;
   print "Test1\n";
   $obj->unreg_me;
   $obj->reg_cb (event_test => sub {
      my ($obj) = @_;
      print "Test2\n";
      $obj->unreg_me;
   });
});
$obj->event ('event_test'); # affiche "Test1"
$obj->event ('event_test'); # affiche "Test2"
mon $bool = $obj->handles ($eventname)
Cette méthode renvoie vrai si un gestionnaire d'événement a été configuré pour l'événement $eventname.

Elle renvoie faux si ce n'est pas le cas.

$obj->event_name
Renvoie le nom de l'événement actuellement exécuté.
$obj->unreg_me
Désenregistre le rappel actuellement exécuté.
$continue_cb = $obj->stop_event
Cette méthode arrête l'exécution des rappels de l'événement courant, et renvoie (dans un contexte non vide) un rappel qui vous permettra de continuer l'exécution.
$obj->add_forward ($obj, $cb)
OBSOLÈTE : Ne l'utilisez pas ! Uniquement pour la compatibilité ascendante pour AnyEvent::XMPP version 0.4.
$obj->remove_forward ($obj)
OBSOLÈTE : Ne l'utilisez pas ! Uniquement pour la compatibilité ascendante pour AnyEvent::XMPP version 0.4.
$obj->remove_all_callbacks ()
Cette méthode supprime

Object::Event 1.23-13 - perl: event handling and callbacks

NOM

Object::Event - système de gestion d'événements et de rappels orienté objet.

VERSION

1.23-13

SYNOPSIS

        use Object::Event;

        package MyEventClass;
        use base qw(Object::Event);
        sub new {
            my $class = shift;
            my $self  = $class->SUPER::new(@_);
            return $self;
        }

        # Register callbacks
        $obj->add_event_handler('some_event', \&callback_sub);
        $obj->add_event_handler('some_event', sub { print "another callback\n"; });
        $obj->add_event_handler('other_event', \&another_sub, 100); # Priority 100

        # Trigger event
        $obj->event('some_event');
        $obj->event('some_event', 'arg1', 'arg2'); # Pass arguments

        # Get registered handlers
        my @handlers = $obj->handles('some_event');

        # Get a string dump of all registered callbacks (for debugging)
        my $dump = $obj->events_as_string_dump();

        package main;
        my $obj = MyEventClass->new;
        $obj->event('some_event');

        # Define event handlers as static methods (using attributes)
        package MyEventClassWithAttributes;
        use base qw(Object::Event);
        sub test : event_cb { print "test event handler!\n" }
        sub test_prio : event_cb(10) { print "test_prio event handler!\n" }
        sub test_alias : event_cb(10, test) { print "test_alias event handler!\n" } # alias for test with priority 10

        my $obj_attr = MyEventClassWithAttributes->new;
        $obj_attr->test();
        $obj_attr->event('test');
        $obj_attr->test_prio();
        $obj_attr->event('test_prio');
        $obj_attr->test_alias();
        $obj_attr->event('test_alias');

DESCRIPTION

Object::Event provides a generic object-oriented event handling system. It allows you to register callback functions or subroutines for specific events and to trigger those events later on. This is useful for implementing observer patterns, decoupling components, and creating more flexible and extensible object-oriented code.

The module supports different ways of registering callbacks:

  • Using the add_event_handler method to register anonymous or named subroutines.
  • Using Perl's attribute system to define event handlers directly as static methods within your class.

It also provides methods to inspect and debug the registered event handlers.

PERFORMANCE

No specific performance considerations for this module, other than the general advice to keep callback functions efficient.

FUNCTIONS

$obj->add_event_handler(EVENT, CALLBACK [, PRIORITY ])
Registers a CALLBACK subroutine for the given EVENT. The optional PRIORITY argument (a number) influences the order in which callbacks are executed. Lower numbers indicate higher priority (executed earlier). The default priority is 0.
$obj->remove_event_handler(EVENT, CALLBACK)
Removes a previously registered event handler. CALLBACK must be the exact same subroutine reference that was used during registration.
$obj->event(EVENT [, ARGS... ])
Triggers the given EVENT. All registered callbacks for this event will be executed in order of their priority. Any additional arguments (ARGS...) passed to event will be forwarded to the callbacks.
$obj->handles(EVENT)
Returns a list of all registered callback subroutines for the given EVENT.
$obj->remove_all_event_handlers([EVENT])
Removes all registered event handlers. If an EVENT name is provided, only handlers for that specific event are removed.

METHODS

The following methods are part of the Object::Event class and are typically called on an object instance.

$obj->add_event_handler(EVENT, CALLBACK [, PRIORITY ])
See FUNCTIONS.
$obj->remove_event_handler(EVENT, CALLBACK)
See FUNCTIONS.
$obj->event(EVENT [, ARGS... ])
See FUNCTIONS.
$obj->handles(EVENT)
See FUNCTIONS.
$obj->remove_all_event_handlers([EVENT])
See FUNCTIONS.
$obj->events_as_string_dump ()
Cette méthode renvoie une représentation textuelle de tous les rappels d'événements enregistrés. Cette méthode est uniquement à des fins de débogage.

EVENT METHODS

Vous pouvez définir des méthodes statiques dans un package qui agissent comme gestionnaires d'événements. Ceci est fait en utilisant la fonctionnalité des attributs de Perl. Pour qu'une méthode agisse comme gestionnaire d'événements, vous devez lui ajouter l'attribut "event_cb".

NOTE : Pour que cela fonctionne, les méthodes doivent être définies au moment de la compilation. Cela signifie que vous ne pouvez pas ajouter de gestionnaires d'événements en utilisant "AUTOLOAD" !

NOTE : Les attributs de Perl ont une syntaxe très basique, vous devez faire attention à ne pas insérer d'espaces, l'attribut doit être une seule chaîne de caractères ne contenant aucun espace. Cela signifie : "event_cb (1)" n'est pas la même chose que event_cb(1) !

Voici un exemple :

package foo;
use base qw/Object::Event/;
sub test : event_cb { print "test event handler!\n" }
package main;
my $o = foo->new;
$o->test ();        # imprime 'test event handler!'
$o->event ('test'); # imprime aussi 'test event handler!'!

Si vous souhaitez définir une priorité, utilisez cette syntaxe :

sub test : event_cb(-1000) { ... }

Ou :

sub test : event_cb(after) { ... }

Vous voudrez peut-être consulter les tests de la distribution Object::Event pour plus d'exemples.

ALIASES

Si vous souhaitez définir plusieurs gestionnaires d'événements comme méthodes de package, vous pouvez utiliser l'attribut "event_cb" avec un argument supplémentaire :

package foo;
use base qw/Object::Event/;
sub test : event_cb { # la priorité par défaut est toujours 0
   print "middle\n";
}
sub test_last : event_cb(-1,test) {
   print "after\n";
}
sub test_first : event_cb(1,test) {
   print "before\n";
}
package main;
my $o = foo->new;
$o->test ();        # imprime "after\n" "middle\n" "before\n"
$o->event ('test'); # imprime la même chose
$o->test_first ();  # imprime aussi la même chose

NOTE : Veuillez noter que si vous ne fournissez aucun ordre, les méthodes sont triées *alphabétiquement* :

package foo;
use base qw/Object::Event/;
sub test : event_cb { # la priorité par défaut est toujours 0
   print "middle\n";
}
sub x : event_cb(, test) { # notez l'élément vide avant la ','!
   print "after\n";
}
sub a : event_cb(, test) {
   print "before\n";
}
package main;
my $o = foo->new;
$o->test ();        # imprime "after\n" "middle\n" "before\n"
$o->event ('test'); # imprime la même chose
$o->x ();           # imprime aussi la même chose

ALIAS ORDERING

L'ordre d'exécution des méthodes de gestionnaires d'événements, s'ils sont tous définis pour le même événement, est strictement défini :

1.
L'ordre des méthodes pour le même événement dans la hiérarchie d'héritage est toujours dominé par la priorité du rappel d'événement.
2.
Ensuite, s'il y a plusieurs méthodes avec la même priorité, la place dans la hiérarchie d'héritage détermine l'ordre d'exécution des méthodes. Plus la classe est haute dans la hiérarchie, plus elle sera appelée tôt.
3.
À l'intérieur d'une classe, le nom de la méthode pour l'événement décide quel événement est exécuté en premier. (Tous si les priorités sont les mêmes)

DEBUGGING

Il existe une variable globale du package appelée $DEBUG qui contrôle les capacités de débogage.

Définissez-la à 1 pour produire une sortie "events_as_string_dump" légèrement étendue.

Définissez-la à 2 et tous les événements seront vidés dans un arbre d'invocations d'événements.

Vous pouvez définir la variable soit dans votre programme principal :

$Object::Event::DEBUG = 2;

Ou utiliser la variable d'environnement "PERL_OBJECT_EVENT_DEBUG" :

export PERL_OBJECT_EVENT_DEBUG=2
