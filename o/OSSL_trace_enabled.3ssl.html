DESCRIPTION

Les fonctions décrites ici intéressent principalement ceux qui fournissent des fonctionnalités OpenSSL, que ce soit dans OpenSSL lui-même ou dans des modules moteur ou des modules similaires.

Si le système de traçage est activé (voir "Configurer le traçage" ci-dessous), ces fonctions sont utilisées pour générer des sorties de traçage en texte libre.

La sortie de traçage est divisée en types qui sont activés individuellement par l'application. Les types de traçage sont décrits en détail dans "Types de traçage" dans OSSL_trace_set_callback(3). Le type de secours OSSL_TRACE_CATEGORY_ALL ne doit pas être utilisé avec les fonctions décrites ici.

Le traçage pour une catégorie spécifique est activé à l'exécution si un soi-disant canal de traçage lui est attaché. Un canal de traçage est simplement un objet BIO dans lequel l'application peut écrire sa sortie de traçage.

L'application dispose de deux manières différentes d'enregistrer un canal de traçage, soit en fournissant directement un objet BIO à l'aide de OSSL_trace_set_channel(3), soit en fournissant une routine de rappel à l'aide de OSSL_trace_set_callback(3). Ce dernier est encapsulé en interne par un objet BIO dédié, de sorte que pour le code de traçage, les deux types de canal sont effectivement indiscernables. Nous les appelons respectivement un canal de traçage simple et un canal de traçage par rappel.

Pour produire une sortie de traçage, il est nécessaire d'obtenir un pointeur vers le canal de traçage (c'est-à-dire l'objet BIO) à l'aide de OSSL_trace_begin(), d'écrire dedans à l'aide de routines de sortie BIO arbitraires, et enfin de libérer le canal à l'aide de OSSL_trace_end(). Les appels OSSL_trace_begin()/OSSL_trace_end() entourant la sortie de traçage créent un groupe, qui agit comme une section critique (protégée par un mutex) pour garantir que la sortie de traçage de différents threads ne soit pas mélangée.

Le code de traçage n'appelle normalement pas directement OSSL_trace_{begin,end}(), mais utilise plutôt un ensemble de macros pratiques, voir la section "Macros" ci-dessous.

Fonctions

OSSL_trace_enabled() peut être utilisé pour vérifier si le traçage pour la catégorie donnée est activé, c'est-à-dire si le système de traçage a été activé statiquement (voir "Configurer le traçage" ci-dessous) et qu'un canal de traçage a été enregistré à l'aide de OSSL_trace_set_channel(3) ou OSSL_trace_set_callback(3).

OSSL_trace_begin() est utilisé pour démarrer une section de traçage et obtenir le canal pour la catégorie donnée sous forme de BIO. Ce BIO ne peut être utilisé que pour la sortie. Le pointeur retourné est NULL si la catégorie est invalide ou non activée.

OSSL_trace_end() est utilisé pour terminer une section de traçage.

L'utilisation de OSSL_trace_begin() et OSSL_trace_end() pour entourer les sections de traçage est obligatoire. Le résultat d'une tentative de production de sortie de traçage en dehors de telles sections est indéfini.

OSSL_trace_string() sort les données de longueur size sous forme de chaîne sur le BIO out. Si text est 0, la fonction masque tous les caractères de contrôle inclus, à l'exception des nouvelles lignes, et s'assure pour une entrée non vide que la sortie se termine par une nouvelle ligne. Sauf si full est non nul, la longueur est limitée (avec un avertissement approprié) à OSSL_TRACE_STRING_MAX caractères, qui est actuellement de 80.

Macros

Il existe un certain nombre de macros pratiques définies pour faciliter et uniformiser le traçage.

OSSL_TRACE_BEGIN() et OSSL_TRACE_END() réservent le BIO "trc_out" et sont utilisés comme suit pour entourer une section de traçage :

OSSL_TRACE_BEGIN(TLS) {
    BIO_printf(trc_out, ... );
} OSSL_TRACE_END(TLS);

Cela se développera normalement en :

do {
    BIO *trc_out = OSSL_trace_begin(OSSL_TRACE_CATEGORY_TLS);
    if (trc_out != NULL) {
        ...
        BIO_printf(trc_out, ...);
    }
    OSSL_trace_end(OSSL_TRACE_CATEGORY_TLS, trc_out);
} while (0);

OSSL_TRACE_CANCEL() doit être utilisé avant de retourner ou de sauter hors d'une section de traçage :

OSSL_TRACE_BEGIN(TLS) {
    if (some_error) {
        OSSL_TRACE_CANCEL(TLS);
        goto err;
    }
    BIO_printf(trc_out, ... );
} OSSL_TRACE_END(TLS);

Cela se développera normalement en :

do {
    BIO *trc_out = OSSL_trace_begin(OSSL_TRACE_CATEGORY_TLS);
    if (trc_out != NULL) {
        if (some_error) {
            OSSL_trace_end(OSSL_TRACE_CATEGORY_TLS, trc_out);
            goto err;
        }
        BIO_printf(trc_out, ... );
    }
    OSSL_trace_end(OSSL_TRACE_CATEGORY_TLS, trc_out);
} while (0);

OSSL_TRACE() et OSSL_TRACE1(), OSSL_TRACE2(), ... OSSL_TRACE9() sont des macros dites instantanées :

L'appel de macro "OSSL_TRACE(category, text)", produit une sortie de traçage en texte littéral.

L'appel de macro "OSSL_TRACEn(category, format, arg1, ..., argn)" produit une sortie de traçage de style printf avec n arguments de champ de format (n=1,...,9). Elle se développe en :

OSSL_TRACE_BEGIN(category) {
    BIO_printf(trc_out, format, arg1, ..., argN);
} OSSL_TRACE_END(category)

En interne, toutes les macros instantanées sont implémentées à l'aide d'une macro générique OSSL_TRACEV(), car C90 ne prend pas en charge les macros variadiques. Cette macro d'aide a une synopsis plutôt étrange et ne doit pas être utilisée directement.

L'appel de macro "OSSL_TRACE_STRING(category, text, full, data, len)" sort les données de longueur size sous forme de chaîne si le traçage pour la catégorie donnée est activé. Elle se développe en :

OSSL_TRACE_BEGIN(category) {
    OSSL_trace_string(trc_out, text, full, data, len);
} OSSL_TRACE_END(category)

La macro OSSL_TRACE_ENABLED() peut être utilisée pour exécuter conditionnellement du code uniquement si une catégorie de traçage spécifique est activée. Dans certaines situations, c'est plus simple que d'entrer dans une section de traçage à l'aide de OSSL_TRACE_BEGIN() et OSSL_TRACE_END(). Par exemple, le code

if (OSSL_TRACE_ENABLED(TLS)) {
    ...
}

se développe en

if (OSSL_trace_enabled(OSSL_TRACE_CATEGORY_TLS) {
    ...
}

NOTES

Il n'est pas nécessaire de protéger les appels de fonctions de sortie de traçage comme OSSL_TRACE(category, ...) par OSSL_TRACE_ENABLED(category).

Si la production de la sortie de traçage nécessite d'effectuer des calculs auxiliaires, ce code auxiliaire doit être placé à l'intérieur d'un bloc conditionnel qui n'est exécuté que si la catégorie de traçage est activée.

La manière la plus naturelle de le faire est de placer le code à l'intérieur de la section de traçage elle-même car elle introduit déjà un tel bloc conditionnel.

OSSL_TRACE_BEGIN(TLS) {
    int var = do_some_auxiliary_calculation();
    BIO_printf(trc_out, "var = %d\n", var);
} OSSL_TRACE_END(TLS);

Dans certains cas, il est plus avantageux d'utiliser un simple groupe conditionnel plutôt qu'une section de traçage. C'est le cas si les calculs et le traçage se produisent à différents endroits du code, ou si les calculs sont si coûteux en temps qu'il serait trop sujet à la contention de les placer à l'intérieur d'une section de traçage (critique).

Configurer le traçage

Par défaut, la bibliothèque OpenSSL est compilée avec le traçage désactivé. Pour utiliser la fonctionnalité de traçage décrite ici, il est donc nécessaire de configurer et de compiler OpenSSL avec l'option 'enable-trace'.

Lorsque la bibliothèque est compilée avec le traçage désactivé :

  • La macro OPENSSL_NO_TRACE est définie dans <openssl/opensslconf.h>.
  • Toutes les fonctions sont toujours présentes, mais OSSL_trace_enabled() indiquera toujours que les catégories sont désactivées, et toutes les autres fonctions ne feront rien.
  • Les macros de commodité sont définies pour produire du code mort. Par exemple, prenons cet exemple de la section « Macros » ci-dessus : 
    OSSL_TRACE_BEGIN(TLS) {
    if (condition) {
        OSSL_TRACE_CANCEL(TLS);
        goto err;
    }
    BIO_printf(trc_out, ... );
} OSSL_TRACE_END(TLS);

    Lorsque l'API de traçage n'est pas opérationnelle, cela se développe en :

    do {
    BIO *trc_out = NULL;
    if (0) {
        if (condition) {
            ((void)0);
            goto err;
        }
        BIO_printf(trc_out, ... );
    }
} while (0);

VALEURS DE RETOUR

OSSL_trace_enabled() renvoie 1 si le traçage pour le type donné est opérationnel et activé, sinon 0.

OSSL_trace_begin() renvoie un pointeur BIO si le type donné est activé, sinon NULL.

OSSL_trace_string() renvoie le nombre de caractères émis, ou -1 en cas d'erreur.
