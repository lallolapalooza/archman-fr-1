NOM

OCSP_resp_find_status, OCSP_resp_count, OCSP_resp_get0, OCSP_resp_find, OCSP_single_get0_status, OCSP_resp_get0_produced_at, OCSP_resp_get0_signature, OCSP_resp_get0_tbs_sigalg, OCSP_resp_get0_respdata, OCSP_resp_get0_certs, OCSP_resp_get0_signer, OCSP_resp_get0_id, OCSP_resp_get1_id, OCSP_check_validity, OCSP_basic_verify - Fonctions utilitaires de réponse OCSP

SYNTAXE

#include <openssl/ocsp.h>
int OCSP_resp_find_status(OCSP_BASICRESP *bs, OCSP_CERTID *id, int *status,
                          int *reason,
                          ASN1_GENERALIZEDTIME **revtime,
                          ASN1_GENERALIZEDTIME **thisupd,
                          ASN1_GENERALIZEDTIME **nextupd);
int OCSP_resp_count(OCSP_BASICRESP *bs);
OCSP_SINGLERESP *OCSP_resp_get0(OCSP_BASICRESP *bs, int idx);
int OCSP_resp_find(OCSP_BASICRESP *bs, OCSP_CERTID *id, int last);
int OCSP_single_get0_status(OCSP_SINGLERESP *single, int *reason,
                            ASN1_GENERALIZEDTIME **revtime,
                            ASN1_GENERALIZEDTIME **thisupd,
                            ASN1_GENERALIZEDTIME **nextupd);
const ASN1_GENERALIZEDTIME *OCSP_resp_get0_produced_at(
                            const OCSP_BASICRESP* single);
const ASN1_OCTET_STRING *OCSP_resp_get0_signature(const OCSP_BASICRESP *bs);
const X509_ALGOR *OCSP_resp_get0_tbs_sigalg(const OCSP_BASICRESP *bs);
const OCSP_RESPDATA *OCSP_resp_get0_respdata(const OCSP_BASICRESP *bs);
const STACK_OF(X509) *OCSP_resp_get0_certs(const OCSP_BASICRESP *bs);
int OCSP_resp_get0_signer(OCSP_BASICRESP *bs, X509 **signer,
                          STACK_OF(X509) *extra_certs);
int OCSP_resp_get0_id(const OCSP_BASICRESP *bs,
                      const ASN1_OCTET_STRING **pid,
                      const X509_NAME **pname);
int OCSP_resp_get1_id(const OCSP_BASICRESP *bs,
                      ASN1_OCTET_STRING **pid,
                      X509_NAME **pname);
int OCSP_check_validity(ASN1_GENERALIZEDTIME *thisupd,
                        ASN1_GENERALIZEDTIME *nextupd,
                        long sec, long maxsec);
int OCSP_basic_verify(OCSP_BASICRESP *bs, STACK_OF(X509) *certs,
                     X509_STORE *st, unsigned long flags);

DESCRIPTION

OCSP_resp_find_status() recherche dans bs une réponse OCSP pour le id. En cas de succès, les champs de la réponse sont renvoyés dans *status, *reason, *revtime, *thisupd et *nextupd. La valeur de *status sera l'une de V_OCSP_CERTSTATUS_GOOD, V_OCSP_CERTSTATUS_REVOKED ou V_OCSP_CERTSTATUS_UNKNOWN. Les champs *reason et *revtime sont définis uniquement si le statut est V_OCSP_CERTSTATUS_REVOKED. Si défini, le champ *reason est défini sur la raison de révocation, qui sera l'une de OCSP_REVOKED_STATUS_NOSTATUS, OCSP_REVOKED_STATUS_UNSPECIFIED, OCSP_REVOKED_STATUS_KEYCOMPROMISE, OCSP_REVOKED_STATUS_CACOMPROMISE, OCSP_REVOKED_STATUS_AFFILIATIONCHANGED, OCSP_REVOKED_STATUS_SUPERSEDED, OCSP_REVOKED_STATUS_CESSATIONOFOPERATION, OCSP_REVOKED_STATUS_CERTIFICATEHOLD ou OCSP_REVOKED_STATUS_REMOVEFROMCRL.

OCSP_resp_count() renvoie le nombre de OCSP_SINGLERESP dans bs.

OCSP_resp_get0() renvoie le OCSP_SINGLERESP dans bs correspondant à la position idx, où idx va de 0 à OCSP_resp_count(bs) - 1.

OCSP_resp_find() recherche dans bs le id et renvoie l'indice de la première entrée correspondante après last ou depuis le début si last est -1.

OCSP_single_get0_status() extrait les champs de single dans *reason, *revtime, *thisupd et *nextupd.

OCSP_resp_get0_produced_at() extrait le champ producedAt de la réponse bs.

OCSP_resp_get0_signature() renvoie la signature de bs.

OCSP_resp_get0_tbs_sigalg() renvoie le signatureAlgorithm de bs.

OCSP_resp_get0_respdata() renvoie le tbsResponseData de bs.

OCSP_resp_get0_certs() renvoie tous les certificats inclus dans bs.

OCSP_resp_get0_signer() tente de récupérer le certificat qui a directement signé bs. Le protocole OCSP ne requiert pas que ce certificat soit inclus dans le champ certs de la réponse, de sorte que des certificats supplémentaires peuvent être fournis via extra_certs si les certificats ayant pu signer la réponse sont connus par un mécanisme hors bande.

OCSP_resp_get0_id() obtient l'ID du répondeur de bs. Si l'ID du répondeur est un nom, *pname est défini sur le nom et *pid sur NULL. Si l'ID est basé sur une clé, *pid est défini sur la clé et *pname sur NULL.

OCSP_resp_get1_id() est identique à OCSP_resp_get0_id() mais laisse la propriété de *pid et *pname à l'appelant, qui est responsable de leur libération sauf si la fonction renvoie 0.

OCSP_check_validity() vérifie la validité de ses arguments thisupd et nextupd, qui seront typiquement obtenus à partir de OCSP_resp_find_status() ou OCSP_single_get0_status(). Si sec est non nul, il indique la quantité de secondes de marge autorisée dans la vérification. Si maxsec est positif, il indique l'âge maximum de thisupd en secondes.

OCSP_basic_verify() vérifie que le message de réponse de base bs est correctement signé et que le certificat signataire peut être validé. Il reçoit st comme le magasin de certificats de confiance et certs comme un ensemble de certificats intermédiaires non fiables. Il tente d'abord de trouver le certificat signataire de la réponse dans certs. Ensuite, il recherche les certificats que le répondeur aurait pu inclure dans bs à moins que flags ne contienne OCSP_NOINTERN. Il échoue s'il ne peut pas trouver le certificat signataire. Ensuite, à moins que flags ne contienne OCSP_NOSIGS, il vérifie la signature de bs et échoue en cas d'erreur. Si flags contient OCSP_NOVERIFY ou si le certificat signataire a été trouvé dans certs et que flags contient OCSP_TRUSTOTHER, la fonction renvoie succès. Sinon, elle continue à valider le certificat signataire. Si flags contient OCSP_PARTIAL_CHAIN, il prend les certificats CA intermédiaires dans st comme nœuds de confiance. Pour plus de détails, voir la description de X509_V_FLAG_PARTIAL_CHAIN dans "VÉRIFICATION DES CERTIFICATS" dans X509_VERIFY_PARAM_set_flags(3). Si flags contient OCSP_NOCHAIN, il ignore tous les certificats dans certs et dans bs, sinon il les considère comme des certificats CA intermédiaires et les utilise pour construire le chemin de vérification du certificat signataire. Les vérifications d'état de révocation à l'aide de CRL sont désactivées pendant la vérification du chemin si le certificat signataire contient l'extension id-pkix-ocsp-no-check. Après une vérification de chemin réussie, la fonction renvoie succès si l'indicateur OCSP_NOCHECKS est défini. Sinon, elle vérifie que le certificat signataire remplit les critères OCSP, y compris la possibilité de délégation. Si cela n'est pas atteint et que l'indicateur OCSP_NOEXPLICIT n'est pas défini, la fonction vérifie la confiance explicite du certificat signataire dans le certificat racine.

VALEURS DE RETOUR

OCSP_resp_find_status() renvoie 1 si id est trouvé dans bs et 0 sinon.

OCSP_resp_count() renvoie le nombre total de champs OCSP_SINGLERESP dans bs ou -1 en cas d'erreur.

OCSP_resp_get0() renvoie un pointeur vers une structure OCSP_SINGLERESP ou NULL en cas d'erreur, comme par exemple si idx est hors limites.

OCSP_resp_find() renvoie l'indice de id dans bs (qui peut être 0) ou -1 en cas d'erreur, comme lorsque id n'a pas été trouvé.

OCSP_single_get0_status() renvoie le statut de single ou -1 si une erreur s'est produite.

OCSP_resp_get0_produced_at() renvoie le champ producedAt de bs.

OCSP_resp_get0_signature() renvoie la signature de bs.

OCSP_resp_get0_tbs_sigalg() renvoie le signatureAlgorithm de bs.

OCSP_resp_get0_respdata() renvoie le tbsResponseData de bs.

OCSP_resp_get0_certs() renvoie tous les certificats inclus dans bs.

OCSP_resp_get0_signer() renvoie 1 si le certificat de signature a été trouvé, ou 0 s'il n'a pas été trouvé ou en cas d'erreur.

>OCSP_resp_get0_id() et OCSP_resp_get1_id() retournent 1 en cas de succès, 0 en cas d'échec.

OCSP_check_validity() retourne 1 si thisupd et nextupd sont des valeurs temporelles valides et que l'heure actuelle + sec n'est pas avant thisupd et, si maxsec >= 0, que l'heure actuelle - maxsec n'est pas après nextupd. Sinon, elle retourne 0 pour indiquer une erreur.

OCSP_basic_verify() retourne 1 en cas de succès, 0 si la vérification n'est pas réussie, ou -1 en cas d'erreur fatale telle qu'un échec d'allocation mémoire.

NOTES

Les applications appellent généralement OCSP_resp_find_status() en utilisant l'identifiant du certificat d'intérêt, puis vérifient sa validité à l'aide de OCSP_check_validity(). Elles peuvent ensuite prendre les mesures appropriées en fonction du statut du certificat.

Une réponse OCSP pour un certificat contient les champs thisUpdate et nextUpdate. Normalement, l'heure actuelle doit se situer entre ces deux valeurs. Pour tenir compte du décalage horaire, le champ maxsec peut être défini à une valeur non nulle dans OCSP_check_validity(). Certains répondeurs ne définissent pas le champ nextUpdate, ce qui aurait autrement pour conséquence qu'une réponse ancienne serait considérée comme valide : le paramètre maxsec de OCSP_check_validity() peut être utilisé pour limiter l'âge autorisé des réponses.

Les valeurs écrites dans *revtime, *thisupd et *nextupd par OCSP_resp_find_status() et OCSP_single_get0_status() sont des pointeurs internes qui NE DOIVENT PAS être libérés par l'application appelante. N'importe lequel ou tous ces paramètres peuvent être mis à NULL si leur valeur n'est pas requise.
