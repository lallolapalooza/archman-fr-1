OSSL_ESS_check_signing_certs(3ssl)

Paquet: openssl

Licences: Apache-2.0

OSSL_ESS_CHECK_SIGNING_CERTS(3ssl) OpenSSL OSSL_ESS_CHECK_SIGNING_CERTS(3ssl)

NOM

OSSL_ESS_signing_cert_new_init, OSSL_ESS_signing_cert_v2_new_init, OSSL_ESS_check_signing_certs - Fonctions Enhanced Security Services (ESS)

SYNOPIS

#include <openssl/ess.h>
ESS_SIGNING_CERT *OSSL_ESS_signing_cert_new_init(const X509 *signcert,
                                                 const STACK_OF(X509) *certs,
                                                 int set_issuer_serial);
ESS_SIGNING_CERT_V2 *OSSL_ESS_signing_cert_v2_new_init(const EVP_MD *hash_alg,
                                                       const X509 *signcert,
                                                       const
                                                       STACK_OF(X509) *certs,
                                                       int set_issuer_serial);
int OSSL_ESS_check_signing_certs(const ESS_SIGNING_CERT *ss,
                                 const ESS_SIGNING_CERT_V2 *ssv2,
                                 const STACK_OF(X509) *chain,
                                 int require_signing_cert);

DESCRIPTION

OSSL_ESS_signing_cert_new_init() génère une nouvelle structure ESS_SIGNING_CERT référençant le signcert donné et tous les certs supplémentaires donnés en utilisant leurs empreintes SHA-1. Si set_issuer_serial est différent de zéro, le nom de l'émetteur et le numéro de série du signcert sont également inclus dans le ESS_CERT_ID en tant que champ issuerSerial. Pour tous les membres de certs, le champ issuerSerial est toujours inclus.

OSSL_ESS_signing_cert_v2_new_init() est identique à OSSL_ESS_signing_cert_new_init() à l'exception qu'elle utilise l'algorithme de hachage hash_alg donné et génère une structure ESS_SIGNING_CERT_V2 avec des éléments ESS_CERT_ID_V2.

OSSL_ESS_check_signing_certs() vérifie si la chaîne de validation chain contient les certificats requis par les identifiants donnés dans ss et/ou ssv2. Si require_signing_cert est différent de zéro, ss ou ssv2 ne doivent pas être NULL. Si ss et ssv2 ne sont pas NULL, ils sont évalués indépendamment. La liste des identifiants de certificat dans ss est de type ESS_CERT_ID, tandis que la liste contenue dans ssv2 est de type ESS_CERT_ID_V2. Tant que ces listes sont présentes, elles doivent être non vides. Le certificat identifié par sa première entrée doit être le premier élément de chain, c'est-à-dire le certificat du signataire. Tous les certificats supplémentaires référencés dans la liste doivent également être trouvés dans chain. La correspondance est effectuée en utilisant l'algorithme de hachage et la valeur de certificat donnés. En plus des vérifications requises par les RFC 2624 et 5035, si le champ issuerSerial est inclus dans un ESSCertID ou ESSCertIDv2, il doit correspondre aux attributs de l'émetteur et du numéro de série du certificat.

NOTES

ESS a été défini dans la RFC 2634, qui a été mise à jour dans la RFC 5035 (version 2 d'ESS) pour prendre en charge des algorithmes de hachage autres que SHA-1. Ceci est utilisé pour TSP (RFC 3161) et CAdES-BES (RFC 5126 informationnelle).

VALEUR DE RETOUR

OSSL_ESS_signing_cert_new_init() et OSSL_ESS_signing_cert_v2_new_init() retournent un pointeur vers la nouvelle structure ou NULL en cas d'échec d'allocation mémoire.

OSSL_ESS_check_signing_certs() retourne 1 en cas de succès, 0 si un certificat requis ne peut pas être trouvé, -1 en cas d'autre erreur.

VOIR AUSSI

TS_VERIFY_CTX_set_certs(3), CMS_verify(3)

HISTORIQUE

OSSL_ESS_signing_cert_new_init(), OSSL_ESS_signing_cert_v2_new_init(), et OSSL_ESS_check_signing_certs() ont été ajoutés dans OpenSSL 3.0.
