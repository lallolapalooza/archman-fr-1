OPENSSL_init_crypto(3ssl)

Paquet: openssl

OPENSSL_INIT_CRYPTO(3ssl) OpenSSL OPENSSL_INIT_CRYPTO(3ssl)

NAME

FONCTIONS D'INITIALISATION ET DE NETTOYAGE D'OPENSSL

SYNOPSIS

#include <openssl/crypto.h>
void OPENSSL_cleanup(void);
int OPENSSL_init_crypto(uint64_t opts, const OPENSSL_INIT_SETTINGS *settings);
int OPENSSL_atexit(void (*handler)(void));
void OPENSSL_thread_stop_ex(OSSL_LIB_CTX *ctx);
void OPENSSL_thread_stop(void);
OPENSSL_INIT_SETTINGS *OPENSSL_INIT_new(void);
int OPENSSL_INIT_set_config_filename(OPENSSL_INIT_SETTINGS *init,
                                     const char* filename);
int OPENSSL_INIT_set_config_file_flags(OPENSSL_INIT_SETTINGS *init,
                                       unsigned long flags);
int OPENSSL_INIT_set_config_appname(OPENSSL_INIT_SETTINGS *init,
                                    const char* name);
void OPENSSL_INIT_free(OPENSSL_INIT_SETTINGS *init);

DESCRIPTION

Lors du fonctionnement normal, OpenSSL (libcrypto) alloue diverses ressources qui doivent être libérées à la fin de l'exécution de la bibliothèque. De plus, certaines ressources sont allouées par thread (si l'application est multi-threadée) et celles-ci doivent être libérées avant que le thread ne se termine.

Depuis la version 1.1.0, OpenSSL alloue automatiquement toutes les ressources nécessaires, il n'est donc pas nécessaire de procéder à une initialisation explicite. De même, il se nettoie automatiquement.

Cependant, des situations peuvent survenir où une initialisation explicite est requise ou souhaitée, par exemple, lorsqu'une initialisation non par défaut est nécessaire. La fonction OPENSSL_init_crypto() peut être utilisée à cette fin dans libcrypto (voir aussi OPENSSL_init_ssl(3) pour l'équivalent dans libssl).

De nombreuses fonctions internes d'OpenSSL appellent OPENSSL_init_crypto(). Par conséquent, pour effectuer une initialisation non par défaut, OPENSSL_init_crypto() doit être appelée par le code de l'application avant tout autre appel aux fonctions d'OpenSSL.

Le paramètre opts spécifie quels aspects de libcrypto doivent être initialisés. Les options valides sont :

OPENSSL_INIT_NO_LOAD_CRYPTO_STRINGS
Supprime le chargement automatique des chaînes d'erreur de libcrypto. Cette option n'est pas par défaut. Une fois sélectionnée, les appels ultérieurs à OPENSSL_init_crypto() avec l'option OPENSSL_INIT_LOAD_CRYPTO_STRINGS seront ignorés.
OPENSSL_INIT_LOAD_CRYPTO_STRINGS
Charge automatiquement les chaînes d'erreur de libcrypto. Avec cette option, la bibliothèque charge les chaînes d'erreur de libcrypto automatiquement. Cette option est par défaut. Une fois sélectionnée, les appels ultérieurs à OPENSSL_init_crypto() avec l'option OPENSSL_INIT_NO_LOAD_CRYPTO_STRINGS seront ignorés.
OPENSSL_INIT_ADD_ALL_CIPHERS
Avec cette option, la bibliothèque charge et rend disponibles tous les chiffrements de libcrypto. Cette option est par défaut. Une fois sélectionnée, les appels ultérieurs à OPENSSL_init_crypto() avec l'option OPENSSL_INIT_NO_ADD_ALL_CIPHERS seront ignorés.
OPENSSL_INIT_ADD_ALL_DIGESTS
Avec cette option, la bibliothèque charge et rend disponibles tous les digests de libcrypto. Cette option est par défaut. Une fois sélectionnée, les appels ultérieurs à OPENSSL_init_crypto() avec l'option OPENSSL_INIT_NO_ADD_ALL_DIGESTS seront ignorés.
OPENSSL_INIT_NO_ADD_ALL_CIPHERS
Avec cette option, la bibliothèque supprime le chargement automatique des chiffrements de libcrypto. Cette option n'est pas par défaut. Une fois sélectionnée, les appels ultérieurs à OPENSSL_init_crypto() avec l'option OPENSSL_INIT_ADD_ALL_CIPHERS seront ignorés.
OPENSSL_INIT_NO_ADD_ALL_DIGESTS
Avec cette option, la bibliothèque supprime le chargement automatique des digests de libcrypto. Cette option n'est pas par défaut. Une fois sélectionnée, les appels ultérieurs à OPENSSL_init_crypto() avec l'option OPENSSL_INIT_ADD_ALL_DIGESTS seront ignorés.
OPENSSL_INIT_LOAD_CONFIG
Avec cette option, un fichier de configuration OpenSSL est chargé et utilisé via OPENSSL_config(). C'est une option par défaut. Remarque : dans OpenSSL 1.1.1, c'était l'option par défaut pour libssl mais pas pour libcrypto (voir OPENSSL_init_ssl(3) pour plus de détails sur l'initialisation de libssl). Dans OpenSSL 1.1.0, c'était une option non par défaut pour libssl et libcrypto. Voir la description de OPENSSL_INIT_new(), ci-dessous.
OPENSSL_INIT_NO_LOAD_CONFIG
Supprime le chargement des fichiers de configuration OpenSSL. C'est équivalent à appeler OPENSSL_no_config(). Ce n'est pas par défaut.
OPENSSL_INIT_ASYNC
Avec cette option, la bibliothèque démarre automatiquement la sous-bibliothèque ASYNC_start_job(3). C'est une option par défaut.
OPENSSL_INIT_ENGINE_RDRAND
Avec cette option, la bibliothèque charge et démarre automatiquement le moteur RDRAND (s'il est disponible). Ce n'est pas par défaut et il est désactivé dans OpenSSL 3.0.
OPENSSL_INIT_ENGINE_DYNAMIC
Avec cette option, la bibliothèque charge et démarre automatiquement le moteur dynamique. Ce n'est pas par défaut et il est désactivé dans OpenSSL 3.0.
OPENSSL_INIT_ENGINE_OPENSSL
Avec cette option, la bibliothèque charge et démarre automatiquement le moteur OpenSSL. Ce n'est pas par défaut et il est désactivé dans OpenSSL 3.0.
OPENSSL_INIT_ENGINE_CRYPTODEV
Avec cette option, la bibliothèque charge et démarre automatiquement le moteur cryptodev (s'il est disponible). Ce n'est pas par défaut et il est désactivé dans OpenSSL 3.0.
OPENSSL_INIT_ENGINE_CAPI
Avec cette option, la bibliothèque charge et démarre automatiquement le moteur CAPI (s'il est disponible). Ce n'est pas par défaut et il est désactivé dans OpenSSL 3.0.
OPENSSL_INIT_ENGINE_PADLOCK
Avec cette option, la bibliothèque charge et démarre automatiquement le moteur padlock (s'il est disponible). Ce n'est pas par défaut et il est désactivé dans OpenSSL 3.0.
OPENSSL_INIT_ENGINE_AFALG
Avec cette option, la bibliothèque charge et démarre automatiquement le moteur AFALG. Ce n'est pas par défaut et il est désactivé dans OpenSSL 3.0.
OPENSSL_INIT_ENGINE_ALL_BUILTIN
Avec cette option, la bibliothèque charge et démarre automatiquement tous les moteurs intégrés listés ci-dessus, à l'exception des moteurs OpenSSL et AFALG. Ce n'est pas par défaut et il est désactivé dans OpenSSL 3.0.
OPENSSL_INIT_ATFORK
Avec cette option, la bibliothèque enregistre ses gestionnaires de fork. Voir OPENSSL_fork_prepare(3) pour plus de détails.
OPENSSL_INIT_NO_ATEXIT
Par défaut, OpenSSL tentera de se nettoyer à la fin du processus via un gestionnaire atexit. L'utilisation de cette option supprime cette action. Cela signifie que l'application doit explicitement nettoyer OpenSSL en utilisant OPENSSL_cleanup().

DESCRIPTION

La fonction OPENSSL_init_crypto() initialise la bibliothèque libcrypto. Elle doit être appelée avant toute autre fonction de libcrypto, à l'exception des fonctions liées à la gestion des erreurs. Elle peut être appelée plusieurs fois, mais l'initialisation réelle n'a lieu que lors du premier appel. Les appels suivants sont des opérations nulles, sauf si l'une des options permettant d'ajouter des éléments a été spécifiée, dans ce cas, l'appel peut ajouter ces éléments.

Les options suivantes peuvent être utilisées avec OPENSSL_init_crypto() :

  • OPENSSL_INIT_LOAD_CRYPTO_STRINGS : Charge les chaînes d'erreurs et les noms de fonctions liés à libcrypto. Ceci est la valeur par défaut si aucune option n'est fournie.
  • OPENSSL_INIT_LOAD_SSL_STRINGS : Charge les chaînes d'erreurs et les noms de fonctions liés à libssl. Ceci est la valeur par défaut si aucune option n'est fournie.
  • OPENSSL_INIT_NO_LOAD_CRYPTO_STRINGS : Ne charge pas les chaînes d'erreurs et les noms de fonctions liés à libcrypto.
  • OPENSSL_INIT_NO_LOAD_SSL_STRINGS : Ne charge pas les chaînes d'erreurs et les noms de fonctions liés à libssl.
  • OPENSSL_INIT_APPLINK : Pour les applications Windows qui doivent définir une forme spécifique d'initialisation pour les DLL liées statiquement. Elle n'a pas d'effet sur les autres plateformes.
  • OPENSSL_INIT_MAX_ERRORS : Limite le nombre d'erreurs pouvant être stockées dans la pile d'erreurs.
  • OPENSSL_INIT_DELEGATED_CREDENTIAL_SUPPORT : Active le support des crédentiels délégués.
  • OPENSSL_INIT_NO_ADD_ALL_CIPHERS : N'ajoute pas tous les chiffrements disponibles au moment de l'initialisation. Les chiffrements doivent être chargés explicitement plus tard.
  • OPENSSL_INIT_NO_ADD_ALL_DIGESTS : N'ajoute pas toutes les fonctions de hachage disponibles au moment de l'initialisation. Les fonctions de hachage doivent être chargées explicitement plus tard.
  • OPENSSL_INIT_ENGINE_SET_DEFAULT : Définit le moteur par défaut utilisé par OpenSSL.
  • OPENSSL_INIT_LOAD_CONFIG : Charge les fichiers de configuration OpenSSL. Ceci est équivalent à un appel à CONF_modules_load_file(3) avec un nom de fichier NULL et un nom d'application NULL, ainsi que les drapeaux CONF_MFLAGS_IGNORE_MISSING_FILE, CONF_MFLAGS_IGNORE_RETURN_CODES et CONF_MFLAGS_DEFAULT_SECTION.

La fonction OPENSSL_init_ssl() est similaire à OPENSSL_init_crypto(), mais elle initialise également libssl.

Plusieurs options peuvent être combinées dans un seul appel à OPENSSL_init_crypto(). Par exemple :

OPENSSL_init_crypto(OPENSSL_INIT_NO_ADD_ALL_CIPHERS
                    | OPENSSL_INIT_NO_ADD_ALL_DIGESTS, NULL);

La fonction OPENSSL_cleanup() désinitialise OpenSSL (libcrypto et libssl). Toutes les ressources allouées par OpenSSL sont libérées. Normalement, il n'est pas nécessaire d'appeler cette fonction directement car elle est initiée automatiquement à la sortie de l'application. Ceci est fait via la fonction standard C atexit(). Dans le cas où l'application se termine d'une manière qui n'appelle pas les gestionnaires atexit() enregistrés, l'application doit appeler OPENSSL_cleanup() directement. Il est déconseillé aux développeurs de bibliothèques utilisant OpenSSL d'appeler cette fonction et devrait plutôt, en général, s'appuyer sur la désinitialisation automatique. Ceci est afin d'éviter des conditions d'erreur où une application et une bibliothèque dont elle dépend utilisent toutes deux OpenSSL, et où la bibliothèque le désinitialise avant que l'application ait fini de l'utiliser.

Une fois que OPENSSL_cleanup() a été appelée, la bibliothèque ne peut pas être réinitialisée. Les tentatives d'appel à OPENSSL_init_crypto() échoueront et une erreur ERR_R_INIT_FAIL sera ajoutée à la pile d'erreurs. Notez que comme l'initialisation a échoué, les chaînes d'erreurs OpenSSL ne seront pas disponibles, seulement un code d'erreur. Ce code peut être traité par l'application en ligne de commande openssl errstr pour produire une erreur lisible par l'homme (voir openssl-errstr(1)).

La fonction OPENSSL_atexit() permet l'enregistrement d'une fonction à appeler lors de OPENSSL_cleanup(). Les gestionnaires d'arrêt sont appelés après la désinitialisation des ressources locales à un thread, mais avant que les autres ressources globales du processus ne soient libérées. Dans le cas où plusieurs gestionnaires d'arrêt sont enregistrés, aucune garantie n'est faite quant à l'ordre d'exécution.

La fonction OPENSSL_thread_stop_ex() désalloue les ressources associées au thread courant pour le contexte OSSL_LIB_CTX donné ctx. Le paramètre ctx peut être NULL, auquel cas le contexte OSSL_LIB_CTX par défaut est utilisé.

Normalement, cette fonction sera appelée automatiquement par la bibliothèque lorsque le thread se termine tant que le OSSL_LIB_CTX n'a pas été libéré avant la fin du thread. Si OSSL_LIB_CTX_free() est appelée, OPENSSL_thread_stop_ex sera appelée automatiquement pour le thread courant (mais pas pour les autres threads qui auraient pu utiliser ce OSSL_LIB_CTX).

OPENSSL_thread_stop_ex doit être appelée sur tous les threads qui se termineront après la libération du OSSL_LIB_CTX. Normalement, ce n'est pas nécessaire pour le OSSL_LIB_CTX par défaut (car toutes les ressources sont nettoyées à la sortie de la bibliothèque) sauf si les ressources locales au thread doivent être libérées avant la sortie de la bibliothèque, ou dans les circonstances décrites dans la section NOTES ci-dessous.

OPENSSL_thread_stop() est identique à OPENSSL_thread_stop_ex() sauf que le OSSL_LIB_CTX par défaut est toujours utilisé.

L'option OPENSSL_INIT_LOAD_CONFIG chargera un fichier de configuration, comme avec CONF_modules_load_file(3) avec un nom de fichier et un nom d'application NULL et les options CONF_MFLAGS_IGNORE_MISSING_FILE, CONF_MFLAGS_IGNORE_RETURN_CODES et CONF_MFLAGS_DEFAULT_SECTION. Le nom de fichier, le nom de l'application et les options peuvent être personnalisés en fournissant un objet OPENSSL_INIT_SETTINGS non nul. L'objet peut être alloué via OPENSSL_INIT_new(). La fonction OPENSSL_INIT_set_config_filename() peut être utilisée pour spécifier un nom de fichier non par défaut, qui est copié et n'a pas besoin de faire référence à un stockage persistant. De même, OPENSSL_INIT_set_config_appname() peut être utilisée pour spécifier un nom d'application non par défaut. Enfin, OPENSSL_INIT_set_file_flags peut être utilisée pour spécifier des options non par défaut. Si l'option CONF_MFLAGS_IGNORE_RETURN_CODES n'est pas incluse, toute erreur dans le fichier de configuration provoquera un retour d'erreur de OPENSSL_init_crypto ou indirectement de OPENSSL_init_ssl(3). L'objet peut être libéré avec OPENSSL_INIT_free() une fois terminé. Si l'argument de OPENSSL_INIT_free() est NULL, rien n'est fait.

NOTES

Les ressources locales à un thread sont désallouées automatiquement lorsque le thread se termine (par exemple, dans un environnement pthreads, lors de l'appel à pthread_exit()). Sur les plateformes Windows, cela se fait en réponse à un message DLL_THREAD_DETACH envoyé au point d'entrée de libcrypto32.dll. Certaines fonctions Windows peuvent provoquer la sortie des threads sans envoyer ce message (par exemple ExitProcess()). Si l'application utilise de telles fonctions, elle doit libérer les ressources OpenSSL directement via un appel à OPENSSL_thread_stop() sur chaque thread. De même, ce message ne sera pas envoyé si OpenSSL est lié statiquement, et donc les applications utilisant la liaison statique devraient également appeler OPENSSL_thread_stop() sur chaque thread. De plus, si OpenSSL est chargé dynamiquement via LoadLibrary() et que les threads ne sont pas détruits avant que FreeLibrary() ne soit appelée, alors chaque thread doit appeler OPENSSL_thread_stop() avant l'appel à FreeLibrary().

Sous Linux/Unix où OpenSSL a été chargé via dlopen() et que l'application est multi-threadée et si dlclose() est ensuite appelée avant la destruction des threads, OpenSSL ne sera pas en mesure de désallouer les ressources associées à ces threads. L'application doit soit appeler OPENSSL_thread_stop() sur chaque thread avant l'appel à dlclose(), soit utiliser l'option RTLD_NODELETE lors de l'appel initial à dlopen() (si disponible sur la plateforme).

VALEUR DES RETOURS

Les fonctions OPENSSL_init_crypto, OPENSSL_atexit() et OPENSSL_INIT_set_config_appname() retournent 1 en cas de succès ou 0 en cas d'erreur.
