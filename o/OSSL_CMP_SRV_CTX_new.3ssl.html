DESCRIPTION

OSSL_CMP_SRV_process_request() implémente les aspects généraux d'un serveur CMP. Ses arguments sont le OSSL_CMP_SRV_CTX srv_ctx et le message de requête CMP req. Il effectue les vérifications générales sur req, appelle la fonction de rappel correspondante (si elle est présente) pour un traitement plus spécifique, puis assemble le résultat, qui peut être un message d'erreur CMP. Si après le retour de la fonction, l'expression OSSL_CMP_CTX_get_status(OSSL_CMP_SRV_CTX_get0_cmp_ctx(srv_ctx)) renvoie -1, alors la fonction a fermé la transaction en cours, ce qui peut être dû à une fin normale de transaction ou à une erreur.

OSSL_CMP_CTX_server_perform() est une interface pour OSSL_CMP_SRV_process_request() qui peut être utilisée par un client CMP de manière similaire à OSSL_CMP_MSG_http_perform(3). Le OSSL_CMP_SRV_CTX doit être défini comme transfer_cb_arg du client_ctx.

OSSL_CMP_SRV_CTX_new() crée et initialise une structure OSSL_CMP_SRV_CTX associée au contexte de bibliothèque libctx et à la chaîne de propriétés propq, les deux pouvant être NULL pour sélectionner les valeurs par défaut.

OSSL_CMP_SRV_CTX_free() libère le srv_ctx donné. Si l'argument est NULL, rien n'est fait.

OSSL_CMP_SRV_CTX_init() configure dans srv_ctx un contexte personnalisé du serveur CMP et les fonctions de rappel qui effectuent le traitement spécifique des requêtes de certificats, des requêtes de révocation, des requêtes de confirmation de certificats, des messages généraux, des messages d'erreur et des requêtes de sondage. Tous les arguments sauf srv_ctx peuvent être NULL. Si aucune fonction de rappel n'est fournie pour un certain type de message, cela signifie que ce type de message n'est pas pris en charge par le serveur.

OSSL_CMP_SRV_CTX_init_trans() configure dans srv_ctx les fonctions de rappel optionnelles pour déclencher la livraison retardée des réponses et nettoyer une transaction. Si la fonction delay> est NULL, la livraison des réponses n'est jamais retardée. Sinon, delay prend un contexte personnalisé du serveur et un message de requête en entrée. Elle doit renvoyer 1 si la livraison de la réponse correspondante doit être retardée, 0 sinon, et -1 en cas d'erreur. Si la fonction clean> est NULL, aucun nettoyage spécifique n'est effectué. Sinon, clean prend un contexte personnalisé du serveur et un pointeur vers l'identifiant de la transaction en entrée, où le pointeur est NULL si une nouvelle transaction est initiée, et fournit l'identifiant de la transaction qui se termine. La fonction clean> doit réinitialiser les parties correspondantes de l'état et libérer la mémoire associée. Elle doit renvoyer 1 en cas de succès et 0 en cas d'erreur.

OSSL_CMP_SRV_CTX_get0_cmp_ctx() renvoie le OSSL_CMP_CTX du srv_ctx.

OSSL_CMP_SRV_CTX_get0_custom_ctx() renvoie le contexte personnalisé du serveur du srv_ctx qui a été configuré à l'aide de OSSL_CMP_SRV_CTX_init().

OSSL_CMP_SRV_CTX_set_send_unprotected_errors() active l'envoi de messages d'erreur et de réponses négatives non protégés.

OSSL_CMP_SRV_CTX_set_accept_unprotected() active l'acceptation des requêtes non protégées avec validation de protection.

OSSL_CMP_SRV_CTX_set_accept_raverified() active l'acceptation des messages ir/cr/kur avec POPO 'RAVerified'.

OSSL_CMP_SRV_CTX_set_grant_implicit_confirm() active la confirmation implicite des nouveaux certificats si demandé.

NOTES

CMP est défini dans la RFC 4210 (et CRMF dans la RFC 4211).

À ce jour, l'implémentation du serveur CMP est limitée à une requête par message CMP (et donc à un composant de réponse maximum par message CMP).

OSSL_CMP_SRV_CTX_new() renvoie une structure OSSL_CMP_SRV_CTX en cas de succès, NULL en cas d'erreur.

OSSL_CMP_SRV_CTX_get0_cmp_ctx() renvoie un OSSL_CMP_CTX.

OSSL_CMP_SRV_CTX_get0_custom_ctx() renvoie le contexte personnalisé du serveur du srv_ctx qui a été configuré à l'aide de OSSL_CMP_SRV_CTX_init().

OSSL_CMP_SRV_CTX_set_send_unprotected_errors() active l'envoi de messages d'erreur et de réponses négatives non protégés.

NAME

OSSL_CMP_SRV_CTX_new, OSSL_CMP_SRV_CTX_up_ref, OSSL_CMP_SRV_CTX_free, OSSL_CMP_SRV_CTX_get0_custom_ctx, OSSL_CMP_SRV_CTX_set0_custom_ctx, OSSL_CMP_SRV_CTX_init, OSSL_CMP_SRV_CTX_init_trans ― functions for creating and managing CMP server contexts.

SYNOPSIS

#include <openssl/cmp_v0_10.h>

OSSL_CMP_SRV_CTX *OSSL_CMP_SRV_CTX_new(OSSL_LIB_CTX *libctx, const char *config);
int OSSL_CMP_SRV_CTX_up_ref(OSSL_CMP_SRV_CTX *ctx);
void OSSL_CMP_SRV_CTX_free(OSSL_CMP_SRV_CTX *ctx);
void *OSSL_CMP_SRV_CTX_get0_custom_ctx(const OSSL_CMP_SRV_CTX *ctx);
int OSSL_CMP_SRV_CTX_set0_custom_ctx(OSSL_CMP_SRV_CTX *ctx, void *custom_ctx);
OSSL_CMP_SRV_CTX *OSSL_CMP_SRV_CTX_init(OSSL_CMP_CTX *cmp_ctx,
                                       OSSL_CMP_MSG *request,
                                       OSSL_CMP_MSG *response,
                                       OSSL_CMP_SRV_CTX *srv_ctx);
OSSL_CMP_SRV_CTX *OSSL_CMP_SRV_CTX_init_trans(OSSL_CMP_CTX *cmp_ctx,
                                             OSSL_CMP_MSG *request,
                                             OSSL_CMP_MSG *response,
                                             OSSL_CMP_SRV_CTX *srv_ctx,
                                             int accept_delayed);

DESCRIPTION

The OSSL_CMP_SRV_CTX_new function allocates and initializes a new OSSL_CMP_SRV_CTX structure, which represents the context for a CMP server.

The OSSL_CMP_SRV_CTX_up_ref function increments the reference count of an OSSL_CMP_SRV_CTX structure.

The OSSL_CMP_SRV_CTX_free function frees the given OSSL_CMP_SRV_CTX structure and all its associated resources.

The OSSL_CMP_SRV_CTX_init function initializes a CMP server context. It takes an existing OSSL_CMP_CTX, and potentially pre-existing request, response, and server contexts. This is useful for reusing contexts or for setting up server-side processing.

The OSSL_CMP_SRV_CTX_init_trans function is similar to OSSL_CMP_SRV_CTX_init but also supports delayed delivery of response messages. The accept_delayed parameter, when non-zero, indicates that the server context should be prepared to handle delayed responses.

The OSSL_CMP_SRV_CTX_set0_custom_ctx function sets a custom server context within the OSSL_CMP_SRV_CTX. The ownership of the custom context is transferred to the server context.

The OSSL_CMP_SRV_CTX_get0_custom_ctx function returns the custom server context that has been set using OSSL_CMP_SRV_CTX_set0_custom_ctx.

NOTES

The OSSL_CMP_SRV_CTX_new function returns a pointer to the newly allocated OSSL_CMP_SRV_CTX structure on success, and NULL on error.

The OSSL_CMP_SRV_CTX_up_ref function returns 1 on success and 0 on error.

The OSSL_CMP_SRV_CTX_free function does not return a value.

The OSSL_CMP_SRV_CTX_init and OSSL_CMP_SRV_CTX_init_trans functions return a pointer to the initialized OSSL_CMP_SRV_CTX structure on success, and NULL on error.

The OSSL_CMP_SRV_CTX_set0_custom_ctx function returns 1 on success and 0 on error.

The OSSL_CMP_SRV_CTX_get0_custom_ctx function returns the custom server context that has been set using OSSL_CMP_SRV_CTX_init.

All other functions return 1 on success, 0 on error.

RETURN VALUES

OSSL_CMP_SRV_CTX_new returns a pointer to the newly allocated OSSL_CMP_SRV_CTX structure on success, and NULL on error.

OSSL_CMP_SRV_CTX_up_ref returns 1 on success, 0 on error.

OSSL_CMP_SRV_CTX_free does not return a value.

OSSL_CMP_SRV_CTX_init and OSSL_CMP_SRV_CTX_init_trans return a pointer to the initialized OSSL_CMP_SRV_CTX structure on success, NULL on error.

OSSL_CMP_SRV_CTX_set0_custom_ctx returns 1 on success, 0 on error.

OSSL_CMP_SRV_CTX_get0_custom_ctx returns the custom server context that has been set using OSSL_CMP_SRV_CTX_init.

All other functions return 1 on success, 0 on error.

HISTORY

The OpenSSL CMP support was added in OpenSSL 3.0.

OSSL_CMP_SRV_CTX_init_trans supporting delayed delivery of all types of response messages was added in OpenSSL 3.3.
