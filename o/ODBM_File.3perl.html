NOM

ODBM_File - Accès lié aux fichiers odbm

SYNOPSIS

use Fcntl;   # Pour O_RDWR, O_CREAT, etc.
use ODBM_File;
tie(%h, 'ODBM_File', 'nom_fichier.dbmx', O_RDWR|O_CREAT, 0640)
  or die "Impossible de lier le fichier ODBM 'nom_fichier.dbmx': $!; abandon";
# Maintenant, lire et modifier le hash
$h{nouvelle_cle} = nouvelle_valeur;
print $h{ancienne_cle};
...
untie %h;

DESCRIPTION

"ODBM_File" établit une connexion entre une variable de hachage Perl et un fichier au format ODBM_File. Vous pouvez manipuler les données du fichier comme si elles étaient dans un hachage Perl, mais lorsque votre programme se termine, les données resteront dans le fichier, pour être utilisées la prochaine fois que votre programme s'exécutera.

Utilisez "ODBM_File" avec la fonction intégrée de Perl "tie" pour établir la connexion entre la variable et le fichier. Les arguments de "tie" doivent être :

1.
La variable de hachage que vous souhaitez lier.
2.
La chaîne "ODBM_File". (Cela indique à Perl d'utiliser le package "ODBM_File" pour effectuer les fonctions du hachage.)
3.
Le nom du fichier auquel vous souhaitez lier le hachage.
4.
Indicateurs. Utilisez l'un des suivants :
"O_RDONLY"
Accès en lecture seule aux données du fichier.
"O_WRONLY"
Accès en écriture seule aux données du fichier.
"O_RDWR"
Accès en lecture et en écriture.

Si vous souhaitez créer le fichier s'il n'existe pas, ajoutez "O_CREAT" à l'un de ceux-ci, comme dans l'exemple. Si vous omettez "O_CREAT" et que le fichier n'existe pas déjà, l'appel "tie" échouera.

5.
Les permissions par défaut à utiliser si un nouveau fichier est créé. Les permissions réelles seront modifiées par la valeur umask de l'utilisateur, vous devriez donc probablement utiliser 0666 ici. (Voir "umask" dans perlfunc.)

DIAGNOSTICS

En cas d'échec, l'appel "tie" retourne une valeur indéfinie et définit probablement $! pour contenir la raison pour laquelle le fichier n'a pas pu être lié.

"odbm store returned -1, errno 22, key "..." at ..."

Cet avertissement est émis lorsque vous essayez de stocker une clé ou une valeur trop longue. Cela signifie que la modification n'a pas été enregistrée dans la base de données. Voir BUGS ET AVERTISSEMENTS ci-dessous.

SÉCURITÉ ET PORTABILITÉ

Ne recevez pas de fichiers ODBM de sources non fiables.

Sur les systèmes Linux modernes, il s'agit généralement de fichiers GDBM, qui ne sont pas portables entre les plateformes.

La documentation GDBM n'implique pas que les fichiers provenant de sources non fiables puissent être utilisés en toute sécurité avec "libgdbm".

Les systèmes qui n'utilisent pas la compatibilité GDBM pour l'ancien support dbm utiliseront une bibliothèque spécifique à la plateforme, héritée éventuellement des systèmes BSD, où il peut être sûr ou non d'utiliser un fichier non fiable.

Un fichier malveillamment conçu pourrait entraîner un crash de perl ou même exposer une vulnérabilité de sécurité.

BUGS ET AVERTISSEMENTS

Il existe un certain nombre de limites sur la taille des données que vous pouvez stocker dans le fichier ODBM. Le plus important est que la longueur d'une clé, plus la longueur de sa valeur associée, ne peut pas dépasser 1008 octets.

Voir "tie" dans perlfunc, perldbmfilter, Fcntl
