O(3perl) Guide de référence pour programmeurs Perl O(3perl)

NOM

O - Interface générique pour les backends du compilateur Perl

SYNOPSIS

perl -MO=[-q,]Backend[,OPTIONS] foo.pl

DESCRIPTION

C'est le module utilisé comme frontal pour le compilateur Perl.

Si vous passez l'option "-q" au module, alors le descripteur de fichier STDOUT sera redirigé vers la variable $O::BEGIN_output pendant la compilation. Ceci a pour effet que toute sortie imprimée sur STDOUT par les blocs BEGIN ou les modules utilisés sera stockée dans cette variable plutôt qu'imprimée. C'est utile avec les backends qui produisent leur propre sortie ("Deparse", "Concise" etc.), afin que leur sortie ne soit pas confondue avec celle générée par le code en cours de compilation.

L'option "-qq" se comporte comme "-q", sauf qu'elle ferme également STDERR après la fin du décompilage. Cela supprime le message « Syntax OK » normalement produit par perl.

CONVENTIONS

La plupart des backends de compilateur utilisent les conventions suivantes : OPTIONS consiste en une liste de mots séparés par des virgules (pas d'espaces blancs). L'option "-v" met généralement le backend en mode verbeux. L'option "-ofile" génère la sortie dans file au lieu de stdout. L'option "-D" suivie de diverses lettres active diverses options de débogage internes. Voir la documentation du backend souhaité (nommé "B::Backend" pour l'exemple ci-dessus) pour en savoir plus sur ce backend.

IMPLÉMENTATION

Cette section n'est nécessaire que pour ceux qui souhaitent écrire un module de backend de compilateur utilisable via ce module.

La ligne de commande mentionnée dans la section SYNOPSIS correspond au code Perl

use O ("Backend", OPTIONS);

La fonction "O::import" charge le module "B::Backend" approprié et appelle sa fonction "compile", en lui passant OPTIONS. Cette fonction est censée retourner une référence de sous-routine que nous appellerons CALLBACK. Ensuite, le drapeau « compile-only » est activé (équivalent à l'option en ligne de commande "-c") et un bloc CHECK est enregistré qui appelle CALLBACK. Ainsi, le programme Perl principal mentionné sur la ligne de commande est lu, analysé et compilé sous forme d'arbre syntaxique interne. Puisque le drapeau "-c" est défini, le programme ne démarre pas son exécution (sauf les blocs BEGIN, bien sûr), mais la fonction CALLBACK enregistrée par le backend du compilateur est appelée.

En résumé, un module de backend de compilateur doit s'appeler "B::Foo" pour un certain foo et résider dans le répertoire approprié pour ce nom. Il doit définir une fonction appelée "compile". Lorsque l'utilisateur tape

perl -MO=Foo,OPTIONS foo.pl

cette fonction est appelée et reçoit ces OPTIONS (divisées par des virgules). Elle doit retourner une référence de sous-routine vers la fonction de compilation principale. Après que le programme de l'utilisateur ait été chargé et analysé, la référence de sous-routine retournée est invoquée, qui peut alors procéder à la compilation, généralement en utilisant la fonctionnalité du module "B".

BOGUES

Les options "-q" et "-qq" ne fonctionnent pas correctement si perl n'est pas compilé avec le support PerlIO : STDOUT sera fermé au lieu d'être redirigé vers $O::BEGIN_output.
