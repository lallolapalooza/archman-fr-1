OSSL_STORE_OPEN(3ssl) OpenSSL OSSL_STORE_OPEN(3ssl)

NOM

OSSL_STORE_CTX, OSSL_STORE_post_process_info_fn, OSSL_STORE_OPEN, OSSL_STORE_OPEN_ex, OSSL_STORE_ctrl, OSSL_STORE_load, OSSL_STORE_eof, OSSL_STORE_delete, OSSL_STORE_error, OSSL_STORE_close - Types et fonctions pour lire des objets depuis une URI

SYNTAXE

#include <openssl/store.h>
typedef struct ossl_store_ctx_st OSSL_STORE_CTX;
typedef OSSL_STORE_INFO *(*OSSL_STORE_post_process_info_fn)(OSSL_STORE_INFO *,
                                                            void *);
OSSL_STORE_CTX *OSSL_STORE_OPEN(const char *uri, const UI_METHOD *ui_method,
                                void *ui_data,
                                OSSL_STORE_post_process_info_fn post_process,
                                void *post_process_data);
OSSL_STORE_CTX *
OSSL_STORE_OPEN_ex(const char *uri, OSSL_LIB_CTX *libctx, const char *propq,
                   const UI_METHOD *ui_method, void *ui_data,
                   const OSSL_PARAM params[],
                   OSSL_STORE_post_process_info_fn post_process,
                   void *post_process_data);
OSSL_STORE_INFO *OSSL_STORE_LOAD(OSSL_STORE_CTX *ctx);
int OSSL_STORE_EOF(OSSL_STORE_CTX *ctx);
int OSSL_STORE_DELETE(const char *uri, OSSL_LIB_CTX *libctx, const char *propq,
                      const UI_METHOD *ui_method, void *ui_data,
                      const OSSL_PARAM params[]);
int OSSL_STORE_ERROR(OSSL_STORE_CTX *ctx);
int OSSL_STORE_CLOSE(OSSL_STORE_CTX *ctx);

Les fonctions suivantes sont obsolètes depuis OpenSSL 3.0 et peuvent être entièrement masquées en définissant OPENSSL_API_COMPAT avec une valeur appropriée, voir openssl_user_macros(7) :

int OSSL_STORE_CTRL(OSSL_STORE_CTX *ctx, int cmd, ... /* args */);

DESCRIPTION

Ces fonctions aident le programme à obtenir les objets pris en charge (voir "SUPPORTED OBJECTS" dans OSSL_STORE_INFO(3) pour savoir lesquels) depuis une URI donnée. La méthode générale pour ce faire est d'ouvrir l'URI en utilisant OSSL_STORE_OPEN(), de lire chaque objet disponible et pris en charge en utilisant OSSL_STORE_LOAD() jusqu'à ce que OSSL_STORE_EOF() ne soit pas atteint, et de le terminer avec OSSL_STORE_CLOSE().

Les informations récupérées sont stockées dans un OSSL_STORE_INFO, qui est décrit dans OSSL_STORE_INFO(3).

Types

OSSL_STORE_CTX est un contexte qui contient toutes les informations internes nécessaires pour que OSSL_STORE_OPEN(), OSSL_STORE_OPEN_ex(), OSSL_STORE_LOAD(), OSSL_STORE_EOF() et OSSL_STORE_CLOSE() fonctionnent ensemble.

Fonctions

OSSL_STORE_OPEN_ex() prend une URI ou un chemin uri, une méthode d'entrée de mot de passe ui_method avec des données associées ui_data, et un rappel de post-traitement post_process avec des données associées post_process_data, un contexte de bibliothèque libctx avec une requête de propriété propq, et ouvre un flux pour les données situées dans l'URI, renvoyant un OSSL_STORE_CTX avec toutes les informations internes nécessaires. Les données associées ui_method et ui_data seront utilisées par toutes les fonctions utilisant OSSL_STORE_CTX lorsqu'une interaction est requise, par exemple pour fournir un mot de passe. Les paramètres auxiliaires OSSL_PARAM(3) dans params peuvent être définis pour modifier davantage le comportement du magasin. Les données associées post_process et post_process_data seront utilisées par OSSL_STORE_LOAD() pour modifier ou supprimer la valeur à renvoyer. Le rappel post_process supprime les valeurs en renvoyant NULL, ce qui amènera OSSL_STORE_LOAD() à commencer son processus de chargement de l'objet suivant, jusqu'à ce que post_process renvoie quelque chose de différent de NULL, ou jusqu'à ce que la fin des données indiquée par OSSL_STORE_EOF() soit atteinte.

OSSL_STORE_OPEN() est similaire à OSSL_STORE_OPEN_ex() mais utilise NULL pour params, le contexte de bibliothèque libctx et la requête de propriété propq.

OSSL_STORE_CTRL() prend un OSSL_STORE_CTX et un numéro de commande cmd et des arguments supplémentaires non spécifiés ici. Les numéros de commande spécifiques au chargeur et les arguments que chacun prend dépendent du chargeur utilisé et sont documentés avec ce chargeur.

Des contrôles globaux sont également disponibles :

OSSL_STORE_C_USE_SECMEM
Contrôle si le chargeur doit tenter d'utiliser une mémoire sécurisée pour tout OSSL_STORE_INFO et son contenu. Ce contrôle attend un argument, un pointeur vers un int qui est censé avoir la valeur 1 (oui) ou 0 (non). Toute autre valeur est une erreur.

OSSL_STORE_LOAD() prend un OSSL_STORE_CTX et tente de charger l'objet suivant et le renvoie encapsulé dans OSSL_STORE_INFO.

OSSL_STORE_DELETE() supprime l'objet identifié par uri.

OSSL_STORE_EOF() prend un OSSL_STORE_CTX et vérifie si la fin des données a été atteinte.

OSSL_STORE_ERROR() prend un OSSL_STORE_CTX et vérifie si une erreur s'est produite lors du dernier appel à OSSL_STORE_LOAD(). Remarque : il peut être utile de tenter de charger d'autres objets, à moins que OSSL_STORE_EOF() n'indique que la fin des données a été atteinte.

OSSL_STORE_CLOSE() prend un OSSL_STORE_CTX, ferme le flux qui a été ouvert par OSSL_STORE_OPEN() et libère toutes les informations qui ont été stockées dans le OSSL_STORE_CTX, ainsi que le OSSL_STORE_CTX lui-même. Si ctx est NULL, il ne fait rien.

NOTES

Une chaîne sans préfixe de schéma (c'est-à-dire une chaîne non-URI) est interprétée implicitement comme utilisant le schéma file:.

Il existe des outils qui peuvent être utilisés conjointement avec OSSL_STORE_OPEN() pour déterminer si une erreur est due à une URI non analysable ou si c'est une erreur différente (comme des échecs d'allocation mémoire) ; si l'URI était analysable mais que le schéma n'est pas enregistré, l'erreur la plus haute aura la raison "OSSL_STORE_R_UNREGISTERED_SCHEME".

Ces fonctions ne font aucune supposition directe concernant la phrase secrète reçue du rappel de mot de passe. Les chargeurs peuvent cependant faire des suppositions. Par exemple, le chargeur file: hérite des suppositions faites par la fonctionnalité d'OpenSSL qui gère différents types de fichiers ; ceci est principalement pertinent pour les objets PKCS#12. Voir passphrase-encoding(7) pour plus d'informations.

VALEURS DE RETOUR

OSSL_STORE_OPEN() renvoie un pointeur vers OSSL_STORE_CTX en cas de succès, ou NULL en cas d'échec.

OSSL_STORE_LOAD() renvoie un pointeur vers OSSL_STORE_INFO en cas de succès, ou NULL en cas d'erreur ou à la fin des données. Utilisez OSSL_STORE_ERROR() et OSSL_STORE_EOF() pour déterminer la signification d'un retour NULL.

OSSL_STORE_EOF() renvoie 1 si la fin des données a été atteinte ou si une erreur s'est produite, 0 sinon.

OSSL_STORE_ERROR() renvoie 1 si une erreur s'est produite lors d'un appel à OSSL_STORE_LOAD(), sinon 0.

OSSL_STORE_DELETE(), OSSL_STORE_CTRL() et OSSL_STORE_CLOSE() renvoient 1 en cas de succès, ou 0 en cas d'échec.

VOIR AUSSI

ossl_store(7), OSSL_STORE_INFO(3), OSSL_STORE_register_loader(3), passphrase-encoding(7)

HISTORIQUE

OSSL_STORE_DELETE() a été ajouté dans OpenSSL 3.2.

OSSL_STORE_OPEN_ex() a été ajouté dans OpenSSL 3.0.

OSSL_STORE_CTX, OSSL_STORE_post_process_info_fn(), OSSL_STORE_OPEN(), OSSL_STORE_CTRL(), OSSL_STORE_LOAD(), OSSL_STORE_EOF() et OSSL_STORE_CLOSE() ont été ajoutés dans OpenSSL 1.1.1.

La gestion d'un argument ctx nul pour OSSL_STORE_CLOSE() a été introduite dans OpenSSL 1.1.1h.

OSSL_STORE_CTRL() et OSSL_STORE_vctrl() ont été obsolètes dans OpenSSL 3.0.

OSSL_STORE_open(3ossl) — Manuel OpenSSL

NAME

OSSL_STORE_open, OSSL_STORE_close, OSSL_STORE_attach, OSSL_STORE_eof, OSSL_STORE_error, OSSL_STORE_NUMBER, OSSL_STORE_FETCH, OSSL_STORE_LOAD, OSSL_STORE_INFO, OSSL_STORE_HAS_LOADER, OSSL_STORE_supports_mech

SYNOPSIS

#include <openssl/store.h>
OSSL_STORE_CTX *OSSL_STORE_open(const char *uri, OSSL_LIB_CTX *libctx,
                                const char *propq);
int OSSL_STORE_close(OSSL_STORE_CTX *ctx);
OSSL_STORE_attach *OSSL_STORE_attach(OSSL_STORE_CTX *ctx,
                                   OSSL_STORE_attach_mode_t mode);
int OSSL_STORE_eof(OSSL_STORE_CTX *ctx);
int OSSL_STORE_error(OSSL_STORE_CTX *ctx);
long OSSL_STORE_NUMBER(OSSL_STORE_CTX *ctx);
OSSL_STORE_INFO *OSSL_STORE_FETCH(OSSL_STORE_CTX *ctx);
OSSL_STORE_INFO *OSSL_STORE_LOAD(OSSL_STORE_CTX *ctx);
OSSL_STORE_INFO *OSSL_STORE_LOAD_BY_OBJ(OSSL_STORE_CTX *ctx, OSSL_OBJECT *obj);
int OSSL_STORE_has_loader(OSSL_STORE_CTX *ctx);
int OSSL_STORE_supports_mech(OSSL_STORE_CTX *ctx, const char *mech);

DESCRIPTION

The OpenSSL store (OSSL_STORE) module provides an abstraction for accessing collections of cryptographic objects, such as certificates, CRLs, private keys, and parameter objects. The module aims to provide a common interface to various sources of such objects, including files, directories, and other storage mechanisms.

The main entry point for accessing a store is OSSL_STORE_open(). This function takes a URI (uri), a library context (libctx), and an optional property query string (propq).

The uri parameter specifies the location of the store to open. The format of the URI depends on the underlying implementation. For example, a file-based store might use a URI like file:/path/to/objects, and a directory-based store might use dir:/path/to/directory.

The libctx parameter is an OSSL_LIB_CTX object that provides the application's library context. This is used to load necessary cryptographic algorithms and implementations.

The propq parameter is a property query string that can be used to select specific types of objects or implementations from the store. If it's NULL, a default set of properties is used.

OSSL_STORE_open() returns an OSSL_STORE_CTX pointer upon success, which represents the opened store context. If an error occurs, it returns NULL.

OSSL_STORE_close() closes the store context represented by ctx and releases any associated resources. It returns 1 on success and 0 on failure.

OSSL_STORE_attach() attaches to the store context ctx in the specified mode. It returns an OSSL_STORE_attach pointer on success, or NULL on failure.

OSSL_STORE_eof() checks if the end-of-file has been reached in the store context ctx. It returns 1 if EOF is reached, and 0 otherwise.

OSSL_STORE_error() checks if an error has occurred in the store context ctx. It returns 1 if an error occurred, and 0 otherwise.

OSSL_STORE_NUMBER() returns the number of objects available in the store context ctx. This function may not be supported by all store implementations.

OSSL_STORE_FETCH() fetches the next available cryptographic object from the store context ctx. It returns an OSSL_STORE_INFO pointer to the fetched object, or NULL if no more objects are available or an error occurred.

OSSL_STORE_LOAD() is similar to OSSL_STORE_FETCH(), but it attempts to load the object's content if it's not already loaded. This might be necessary for objects stored in a compressed or encoded format.

OSSL_STORE_LOAD_BY_OBJ() attempts to load the content of the object specified by obj within the store context ctx.

OSSL_STORE_has_loader() checks if the store context ctx has a loader for the current URI. It returns 1 if a loader is available, and 0 otherwise.

OSSL_STORE_supports_mech() checks if the store context ctx supports the specified mechanism (mech). It returns 1 if supported, and 0 otherwise.

NOTES

The OSSL_STORE module is designed to be extensible. New store implementations can be added by implementing the necessary functions and registering them with the OpenSSL library.

The URI format is crucial for specifying the store location. Refer to the documentation of specific store implementations for supported URI schemes and formats.

Error handling is important. Applications should always check the return values of OSSL_STORE functions and use OSSL_STORE_error() to diagnose issues.

RETURN VALUES

The return values are described in the SYNOPSIS section for each function.
