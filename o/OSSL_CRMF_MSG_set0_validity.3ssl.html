OSSL_CRMF_MSG_set0_validity(3ssl)

Paquet: openssl

Licences: Apache-2.0

OSSL_CRMF_MSG_SET0_VALIDITY(3ssl) OpenSSL OSSL_CRMF_MSG_SET0_VALIDITY(3ssl)

NOM

OSSL_CRMF_MSG_set0_validity, OSSL_CRMF_MSG_set_certReqId, OSSL_CRMF_CERTTEMPLATE_fill, OSSL_CRMF_MSG_set0_extensions, OSSL_CRMF_MSG_push0_extension, OSSL_CRMF_MSG_create_popo, OSSL_CRMF_MSGS_verify_popo - fonctions de population et de vérification des structures CertReqMsg CRMF

SYNOPSIS

#include <openssl/crmf.h>
int OSSL_CRMF_MSG_set0_validity(OSSL_CRMF_MSG *crm,
                                ASN1_TIME *notBefore, ASN1_TIME *notAfter);
int OSSL_CRMF_MSG_set_certReqId(OSSL_CRMF_MSG *crm, int rid);
int OSSL_CRMF_CERTTEMPLATE_fill(OSSL_CRMF_CERTTEMPLATE *tmpl,
                                EVP_PKEY *pubkey,
                                const X509_NAME *subject,
                                const X509_NAME *issuer,
                                const ASN1_INTEGER *serial);
int OSSL_CRMF_MSG_set0_extensions(OSSL_CRMF_MSG *crm, X509_EXTENSIONS *exts);
int OSSL_CRMF_MSG_push0_extension(OSSL_CRMF_MSG *crm, X509_EXTENSION *ext);
int OSSL_CRMF_MSG_create_popo(int meth, OSSL_CRMF_MSG *crm,
                              EVP_PKEY *pkey, const EVP_MD *digest,
                              OSSL_LIB_CTX *libctx, const char *propq);
int OSSL_CRMF_MSGS_verify_popo(const OSSL_CRMF_MSGS *reqs,
                               int rid, int acceptRAVerified,
                               OSSL_LIB_CTX *libctx, const char *propq);

DESCRIPTION

OSSL_CRMF_MSG_set0_validity() définit les champs notBefore et notAfter comme contraintes de validité dans le certTemplate de crm. N'importe lequel des paramètres notBefore et notAfter peut être NULL, ce qui signifie aucune contrainte pour le champ respectif. En cas de succès, la propriété de notBefore et notAfter est transférée à crm.

OSSL_CRMF_MSG_set_certReqId() définit rid comme l'identifiant de demande de certificat (certReqId) de crm.

OSSL_CRMF_CERTTEMPLATE_fill() remplit ces champs du certTemplate tmpl pour lesquels des valeurs non NULL sont fournies : pubkey, subject, issuer, et/ou serial. Les extensions X.509 peuvent être définies à l'aide de OSSL_CRMF_MSG_set0_extensions(). En cas de succès, le compteur de référence de pubkey (si fourni) est incrémenté, tandis que les structures subject, issuer et serial (si fournies) sont copiées.

OSSL_CRMF_MSG_set0_extensions() définit exts comme les extensions dans le certTemplate de crm. Libère toutes celles préexistantes et consomme exts.

OSSL_CRMF_MSG_push0_extension() ajoute l'extension X509 ext aux extensions dans le certTemplate de crm. Consomme ext.

OSSL_CRMF_MSG_create_popo() crée et définit la preuve de possession (POPO) selon la méthode meth dans crm. Le contexte de bibliothèque libctx et la chaîne de requête de propriétés propq peuvent être NULL pour sélectionner les valeurs par défaut. Si la méthode est OSSL_CRMF_POPO_SIGNATURE, la POPO est calculée en utilisant la clé privée pkey et la méthode de hachage digest, où l'argument digest est ignoré si pkey est d'un type (tel que Ed25519 et Ed448) qui est implicitement associé à un algorithme de hachage.

meth peut être l'une des suivantes :

  • OSSL_CRMF_POPO_NONE - RFC 4211, section 4, champ POP omis. Le CA/RA utilise une méthode hors bande pour vérifier la POP. Notez que les serveurs peuvent échouer dans ce cas, résultant par exemple en un code d'erreur HTTP 500 (Erreur interne).
  • OSSL_CRMF_POPO_RAVERIFIED - RFC 4211, section 4, indication explicite que le RA a déjà vérifié la POP.
  • OSSL_CRMF_POPO_SIGNATURE - RFC 4211, section 4.1, seul le cas 3 est pris en charge jusqu'à présent.
  • OSSL_CRMF_POPO_KEYENC - RFC 4211, section 4.2, seule la méthode indirecte (subsequentMessage/enccert) est prise en charge, l'échange de défi-réponse (challengeResp) n'est pas encore pris en charge.
  • OSSL_CRMF_POPO_KEYAGREE - RFC 4211, section 4.3, non encore pris en charge.

OSSL_CRMF_MSGS_verify_popo vérifie la preuve de possession de la demande avec le rid donné dans la liste des reqs. Accepte optionnellement RAVerified. Il peut utiliser le contexte de bibliothèque libctx et la chaîne de requête de propriétés propq.

VALEUR DE RETOUR

Toutes les fonctions retournent 1 en cas de succès, 0 en cas d'erreur.

VOIR AUSSI

RFC 4211
