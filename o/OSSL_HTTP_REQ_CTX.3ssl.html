OSSL_HTTP_REQ_CTX(3ssl) OpenSSL OSSL_HTTP_REQ_CTX(3ssl)

NAME

OSSL_HTTP_REQ_CTX, OSSL_HTTP_REQ_CTX_new, OSSL_HTTP_REQ_CTX_free, OSSL_HTTP_REQ_CTX_set_request_line, OSSL_HTTP_REQ_CTX_add1_header, OSSL_HTTP_REQ_CTX_set_expected, OSSL_HTTP_REQ_CTX_set1_req, OSSL_HTTP_REQ_CTX_nbio, OSSL_HTTP_REQ_CTX_nbio_d2i, OSSL_HTTP_REQ_CTX_exchange, OSSL_HTTP_REQ_CTX_get0_mem_bio, OSSL_HTTP_REQ_CTX_get_resp_len, OSSL_HTTP_REQ_CTX_set_max_response_length, OSSL_HTTP_REQ_CTX_set_max_response_hdr_lines, OSSL_HTTP_is_alive - Fonctions de bas niveau pour client HTTP

SYNOPSIS

#include <openssl/http.h>
typedef struct ossl_http_req_ctx_st OSSL_HTTP_REQ_CTX;
OSSL_HTTP_REQ_CTX *OSSL_HTTP_REQ_CTX_new(BIO *wbio, BIO *rbio, int buf_size);
void OSSL_HTTP_REQ_CTX_free(OSSL_HTTP_REQ_CTX *rctx);
int OSSL_HTTP_REQ_CTX_set_request_line(OSSL_HTTP_REQ_CTX *rctx, int method_POST,
                                       const char *server, const char *port,
                                       const char *path);
int OSSL_HTTP_REQ_CTX_add1_header(OSSL_HTTP_REQ_CTX *rctx,
                                  const char *name, const char *value);
int OSSL_HTTP_REQ_CTX_set_expected(OSSL_HTTP_REQ_CTX *rctx,
                                   const char *expected_content_type, int expect_asn1,
                                   int timeout, int keep_alive);
int OSSL_HTTP_REQ_CTX_set1_req(OSSL_HTTP_REQ_CTX *rctx, const char *content_type,
                               const ASN1_ITEM *it, const ASN1_VALUE *req);
int OSSL_HTTP_REQ_CTX_nbio(OSSL_HTTP_REQ_CTX *rctx);
int OSSL_HTTP_REQ_CTX_nbio_d2i(OSSL_HTTP_REQ_CTX *rctx,
                               ASN1_VALUE **pval, const ASN1_ITEM *it);
BIO *OSSL_HTTP_REQ_CTX_exchange(OSSL_HTTP_REQ_CTX *rctx);
BIO *OSSL_HTTP_REQ_CTX_get0_mem_bio(const OSSL_HTTP_REQ_CTX *rctx);
size_t OSSL_HTTP_REQ_CTX_get_resp_len(const OSSL_HTTP_REQ_CTX *rctx);
void OSSL_HTTP_REQ_CTX_set_max_response_length(OSSL_HTTP_REQ_CTX *rctx,
                                               unsigned long len);
void OSSL_HTTP_REQ_CTX_set_max_response_hdr_lines(OSSL_HTTP_REQ_CTX *rctx,
                                                  size_t count);
int OSSL_HTTP_is_alive(const OSSL_HTTP_REQ_CTX *rctx);

DESCRIPTION

OSSL_HTTP_REQ_CTX est une structure de contexte pour une requête HTTP et sa réponse, utilisée pour collecter toutes les données nécessaires pour effectuer une telle requête.

Ce fichier documente les fonctions de bas niveau HTTP rarement utilisées directement. Les fonctions de haut niveau telles que OSSL_HTTP_get(3) et OSSL_HTTP_transfer(3) devraient être préférées.

OSSL_HTTP_REQ_CTX_new() alloue une nouvelle structure de contexte de requête HTTP, qui est remplie avec les BIO pour écrire/envoyer la requête à (wbio), les BIO pour lire/recevoir la réponse depuis (rbio, qui peut être identique à wbio), et la taille maximale de ligne attendue buf_size. Une valeur <= 0 indique que la valeur par défaut OSSL_HTTP_DEFAULT_MAX_LINE_LEN de 4 KiB doit être utilisée. buf_size est également utilisé comme nombre d'octets à lire à la fois. Le contexte structuré comprend un BIO de mémoire interne qui collecte les lignes d'en-tête de la requête HTTP.

OSSL_HTTP_REQ_CTX_free() libère le contexte de requête HTTP rctx. Le rbio n'est pas libéré, wbio est libéré si free_wbio est spécifié. Si l'argument est NULL, rien n'est fait.

OSSL_HTTP_REQ_CTX_set_request_line() ajoute la première ligne de la requête HTTP à rctx. La méthode HTTP est déterminée par method_POST, qui doit être 1 pour indiquer "POST" ou 0 pour indiquer "GET". server et port peuvent être définis pour indiquer le serveur et le port optionnel qu'un proxy HTTP doit passer la requête, sinon ils doivent être NULL. path fournit le chemin de la requête HTTP; s'il est NULL, "/" est utilisé. Pour une compatibilité ascendante, path peut commencer par "http://" et ainsi un URI absolu peut être spécifié. Dans ce cas, cela indique qu'un proxy HTTP est utilisé et fournit également le serveur (et optionnellement le port) que le proxy doit passer la requête. Dans ce cas, server et port doivent être NULL.

OSSL_HTTP_REQ_CTX_add1_header() ajoute l'en-tête name avec la valeur value à rctx. Il peut être appelé plusieurs fois pour ajouter plusieurs lignes d'en-tête. Par exemple, pour ajouter l'en-tête "Host" pour "example.com", on appellerait :

OSSL_HTTP_REQ_CTX_add1_header(ctx, "Host", "example.com");

OSSL_HTTP_REQ_CTX_set_expected() définit éventuellement les attentes du client HTTP quant à la réponse. En raison de la structure d'une requête HTTP, si l'argument keep_alive est non nul, il doit être appelé avant d'utiliser OSSL_HTTP_REQ_CTX_set1_req().

Si l'argument expected_content_type n'est pas NULL, le client vérifiera que la valeur spécifiée dans la ligne d'en-tête "Content-Type" est incluse dans l'en-tête de réponse et retournera une erreur si ce n'est pas le cas. Dans la ligne d'en-tête "Content-Type", la valeur spécifiée doit être présente telle quelle, ou si la valeur spécifiée ne contient pas de caractère ";", il suffit qu'elle apparaisse comme préfixe dans la ligne d'en-tête, suivi d'un ";" et de tout texte supplémentaire. Par exemple, si l'argument expected_content_type spécifie "text/html", il correspondra à "Text/HTML", "text/html; charset=UTF-8", etc.

Si le paramètre expect_asn1 est non nul, une structure au format ASN.1 est attendue comme corps de réponse et le flux de données est désactivé. Cela signifie qu'une séquence ASN.1 est requise dans l'en-tête, son champ de longueur est vérifié et OSSL_HTTP_REQ_CTX_get0_mem_bio() doit être utilisé pour obtenir le corps de réponse précédemment bufferisé. Sinon (par défaut), tout format d'entrée est autorisé, avec des vérifications de longueur du corps de réponse uniquement sur les messages d'erreur. Dans ce cas, le BIO donné comme rbio dans OSSL_HTTP_REQ_CTX_new() doit être utilisé directement pour lire les contenus de la réponse, qui peut supporter le streaming.

Si le paramètre timeout est supérieur à 0, il indique le nombre maximum de secondes pendant lesquelles le transfert HTTP (envoi de la requête et réception d'une réponse) est autorisé à se terminer. timeout == 0 permet d'attendre indéfiniment, c'est-à-dire sans limite de temps. C'est la valeur par défaut. timeout < 0 prend la valeur définie par l'argument overall_timeout de OSSL_HTTP_open(3) avec la valeur par défaut de 0, ce qui signifie pas de limite de temps.

Si le paramètre keep_alive est 0, ce qui est la valeur par défaut, la connexion n'est pas maintenue après réception d'une réponse. C'est le comportement par défaut pour HTTP 1.0. Si la valeur est 1 ou 2, une connexion persistante est demandée. Si la valeur est 2, une connexion persistante est exigée, c'est-à-dire qu'une erreur se produit si le serveur ne l'accorde pas.

OSSL_HTTP_REQ_CTX_set1_req() finalise le contexte de requête HTTP. Il est nécessaire si le paramètre method_POST dans OSSL_HTTP_REQ_CTX_set_request_line() était 1 et qu'une requête ASN.1 doit être envoyée. Il doit également être utilisé lorsque le "keep-alive" est demandé, même si une requête GET doit être envoyée, auquel cas req doit être NULL. Sauf si req est NULL, la fonction ajoute l'encodage DER de req en utilisant le schéma ASN.1 it pour effectuer l'encodage (ce qui ne supporte pas le streaming). L'en-tête HTTP "Content-Length" est rempli avec la longueur de la requête. content_type doit être NULL si req est NULL. Si content_type n'est pas NULL, l'en-tête "Content-Type" est également ajouté avec la valeur spécifiée. Les lignes d'en-tête sont ajoutées au BIO de mémoire interne du contexte de requête HTTP.

OSSL_HTTP_REQ_CTX_nbio() tente d'envoyer la requête préparée dans rctx et de collecter la réponse via HTTP, en utilisant les wbio et rbio qui ont été utilisés lors de l'appel à OSSL_HTTP_REQ_CTX_new(). La fonction peut avoir besoin d'être appelée à nouveau si son résultat est -1, ce qui indique BIO_should_retry(3). Dans ce cas, il est recommandé d'attendre un peu entre les appels, en utilisant BIO_wait(3) sur le BIO de lecture pour éviter une boucle d'attente. Voir OSSL_HTTP_REQ_CTX_set_expected() sur la façon dont le type de contenu de la réponse, le corps de la réponse, le temps de transfert HTTP et le "keep-alive" sont gérés. Tout corps de message d'erreur est consommé

OSSL_HTTP_REQ_CTX_nbio_d2i() est similaire à OSSL_HTTP_REQ_CTX_nbio(), mais avec l'intention de décoder la réponse HTTP en une structure ASN.1. L'argument pval pointe vers un pointeur vers ASN1_VALUE où la valeur décodée sera stockée. L'argument it spécifie le schéma ASN.1 à utiliser pour le décodage. La fonction peut avoir besoin d'être appelée plusieurs fois si son résultat est -1.

OSSL_HTTP_REQ_CTX_exchange() est un raccourci pour appeler OSSL_HTTP_REQ_CTX_new(), OSSL_HTTP_REQ_CTX_set_request_line(), OSSL_HTTP_REQ_CTX_add1_header(), OSSL_HTTP_REQ_CTX_set_expected(), OSSL_HTTP_REQ_CTX_set1_req() (si nécessaire), et enfin OSSL_HTTP_REQ_CTX_nbio(). La fonction renvoie le BIO de réponse, qui peut être soit le rbio spécifié dans OSSL_HTTP_REQ_CTX_new(), soit le BIO interne de mémoire si le streaming n'est pas utilisé.

OSSL_HTTP_REQ_CTX_get0_mem_bio() renvoie le BIO de mémoire interne utilisé pour stocker les en-têtes de requête et le corps de réponse si le streaming n'est pas utilisé. Le pointeur retourné ne doit pas être libéré, et sa durée de vie est liée à celle de rctx.

OSSL_HTTP_REQ_CTX_get_resp_len() renvoie la longueur du corps de réponse reçue jusqu'à présent, en octets. Si la réponse n'a pas encore été entièrement reçue, la valeur renvoyée est la longueur actuelle. S'il y a eu une erreur lors de la réception, la valeur renvoyée est indéfinie.

OSSL_HTTP_REQ_CTX_set_max_response_length() définit la longueur maximale du corps de réponse à len octets. Toute réponse dépassant cette longueur entraînera une erreur. La valeur par défaut est 2 MiB.

OSSL_HTTP_REQ_CTX_set_max_response_hdr_lines() définit le nombre maximal de lignes d'en-tête de réponse autorisées à count. Toute réponse dépassant ce nombre de lignes entraînera une erreur. La valeur par défaut est 100.

OSSL_HTTP_is_alive() renvoie 1 si la connexion HTTP peut être réutilisée après réception de la réponse, et 0 sinon. Cela dépend de la valeur de l'en-tête "Connection" dans la réponse du serveur.

RETURN VALUES

Les fonctions de configuration retournent généralement 1 en cas de succès et 0 en cas d'échec.

OSSL_HTTP_REQ_CTX_new(), OSSL_HTTP_REQ_CTX_exchange() et OSSL_HTTP_REQ_CTX_get0_mem_bio() retournent NULL en cas d'échec.

OSSL_HTTP_REQ_CTX_nbio() et OSSL_HTTP_REQ_CTX_nbio_d2i() retournent 1 en cas de succès, 0 si un état indéterminé se produit (par exemple, lors de la lecture ou de l'écriture non bloquante), et -1 en cas d'erreur.

OSSL_HTTP_REQ_CTX_get_resp_len() renvoie la longueur de la réponse reçue.

OSSL_HTTP_is_alive() renvoie 1 si la connexion est persistante, 0 sinon.

Si l'en-tête "Content-Length" est présent dans la réponse et que sa valeur dépasse la longueur maximale autorisée du contenu de la réponse, ou si la réponse est un message d'erreur dont la longueur du corps dépasse cette valeur, ou si le contenu est une structure encodée en ASN.1 avec une longueur dépassant cette valeur, ou si les deux indications de longueur sont présentes mais divergent, alors une erreur se produit.

OSSL_HTTP_REQ_CTX_nbio_d2i() est similaire à OSSL_HTTP_REQ_CTX_nbio() mais en cas de succès, il analyse en plus la réponse, qui doit être une structure ASN.1 encodée en DER, en utilisant le modèle ASN.1 it et place le résultat dans *pval.

OSSL_HTTP_REQ_CTX_exchange() appelle OSSL_HTTP_REQ_CTX_nbio() aussi souvent que nécessaire pour échanger une requête et une réponse, ou jusqu'à ce qu'un délai d'attente soit atteint. En cas de succès, il renvoie un pointeur vers le BIO qui peut être utilisé pour lire le résultat. Si une réponse encodée en ASN.1 était attendue, il s'agit du BIO renvoyé par OSSL_HTTP_REQ_CTX_get0_mem_bio() après l'échange. Ce BIO mémoire ne prend pas en charge le streaming. Sinon, le BIO renvoyé est le rbio donné à OSSL_HTTP_REQ_CTX_new(), qui peut prendre en charge le streaming. Lorsque ce BIO est renvoyé, il a été lu au-delà de la fin de l'en-tête de réponse, de sorte que le corps de réponse réel puisse en être lu. Le pointeur BIO renvoyé NE DOIT PAS être libéré par l'appelant.

OSSL_HTTP_REQ_CTX_get0_mem_bio() renvoie le BIO mémoire interne. Avant l'envoi de la requête HTTP, il peut être utilisé pour adapter ses lignes d'en-tête. À utiliser avec précaution ! Après réception d'une réponse via HTTP, le BIO représente l'état actuel de la lecture de l'en-tête de réponse. Si la réponse était censée être encodée en ASN.1, son contenu peut être lu via ce BIO, qui ne prend pas en charge le streaming. Le pointeur BIO renvoyé ne doit pas être libéré par l'appelant.

OSSL_HTTP_REQ_CTX_get_resp_len() renvoie la taille du contenu de la réponse dans rctx s'il est fourni par le serveur via le champ d'en-tête "Content-Length", sinon 0.

OSSL_HTTP_REQ_CTX_set_max_response_length() définit la longueur maximale autorisée du contenu de la réponse pour rctx à len. Si elle n'est pas définie ou si len est 0, alors la valeur OSSL_HTTP_DEFAULT_MAX_RESP_LEN est utilisée, qui est actuellement de 100 KiB.

OSSL_HTTP_REQ_CTX_set_max_response_hdr_lines() modifie la limite du nombre de lignes d'en-tête HTTP autorisées à être reçues dans une réponse. La limite par défaut est OSSL_HTTP_DEFAULT_MAX_RESP_HDR_LINES, actuellement 256. Si la limite n'est pas de 0 et que le nombre de lignes dépasse la limite, une erreur HTTP_R_RESPONSE_TOO_MANY_HDRLINES est indiquée. La définition de la limite à 0 désactive la vérification.

OSSL_HTTP_is_alive() peut être utilisé pour vérifier si la connexion HTTP donnée par rctx est toujours active, c'est-à-dire qu'elle n'a pas été fermée. Elle renvoie 0 si rctx est NULL.

Si l'application cliente a demandé ou exigé une connexion persistante et que cela a été accordé par le serveur, elle peut conserver rctx aussi longtemps qu'elle le souhaite pour envoyer des requêtes supplémentaires et que OSSL_HTTP_is_alive() renvoie une valeur non nulle, sinon elle devrait appeler OSSL_HTTP_REQ_CTX_free(rctx) ou OSSL_HTTP_close(3). Si l'application cliente conserve rctx mais que la connexion meurt pour une raison quelconque du côté du serveur, elle s'en apercevra en obtenant une erreur d'E/S en essayant d'envoyer la requête suivante via rctx.

AVERTISSEMENTS

La réponse du serveur peut être inattendue si le nom d'hôte utilisé pour créer le wbio, un en-tête "Host", et l'hôte spécifié dans l'URL de la requête ne correspondent pas.

Beaucoup de ces fonctions doivent être appelées dans un certain ordre.

Tout d'abord, le contexte de requête HTTP doit être alloué : OSSL_HTTP_REQ_CTX_new().

Ensuite, la requête HTTP doit être préparée avec les données de requête :

1.
Appel de OSSL_HTTP_REQ_CTX_set_request_line().
2.
Ajout de lignes d'en-tête supplémentaires avec OSSL_HTTP_REQ_CTX_add1_header(). Ceci est facultatif et peut être fait plusieurs fois avec des noms différents.
3.
Finalisation de la requête à l'aide de OSSL_HTTP_REQ_CTX_set1_req(). Ceci peut être omis si la méthode GET est utilisée et que le mode "keep-alive" n'est pas demandé.

Lorsque le contexte de requête est entièrement préparé, l'échange HTTP peut être effectué avec OSSL_HTTP_REQ_CTX_nbio() ou OSSL_HTTP_REQ_CTX_exchange().

NOTES

Lorsqu'il est compilé avec le traçage activé, OSSL_HTTP_REQ_CTX_nbio() et toutes les fonctions qui l'utilisent, telles que OSSL_HTTP_REQ_CTX_exchange() et OSSL_HTTP_transfer(3), peuvent être tracés en utilisant OSSL_TRACE_CATEGORY_HTTP. Voir aussi OSSL_trace_enabled(3) et openssl-env(7).

VALEURS DE RETOUR

OSSL_HTTP_REQ_CTX_new() renvoie un pointeur vers un OSSL_HTTP_REQ_CTX, ou NULL en cas d'erreur.

OSSL_HTTP_REQ_CTX_free(), OSSL_HTTP_REQ_CTX_set_max_response_length(), et OSSL_HTTP_REQ_CTX_set_max_response_hdr_lines() ne renvoient pas de valeurs.

OSSL_HTTP_REQ_CTX_set_request_line(), OSSL_HTTP_REQ_CTX_add1_header(), OSSL_HTTP_REQ_CTX_set1_req(), et OSSL_HTTP_REQ_CTX_set_expected() renvoient 1 en cas de succès et 0 en cas d'échec.

OSSL_HTTP_REQ_CTX_nbio() et OSSL_HTTP_REQ_CTX_nbio_d2i() renvoient 1 en cas de succès, 0 en cas d'erreur ou de redirection, -1 si une nouvelle tentative est nécessaire.

OSSL_HTTP_REQ_CTX_exchange() et OSSL_HTTP_REQ_CTX_get0_mem_bio() renvoient un pointeur vers un BIO en cas de succès, comme décrit ci-dessus, ou NULL en cas d'échec. Le BIO renvoyé ne doit pas être libéré par l'appelant.

OSSL_HTTP_REQ_CTX_get_resp_len() renvoie la taille du contenu de la réponse ou 0 si elle n'est pas disponible ou si une erreur s'est produite.

OSSL_HTTP_is_alive() renvoie 1 si son argument est non NULL et que le client a demandé une connexion persistante et que le serveur n'a pas refusé de garder la connexion ouverte, sinon 0.
