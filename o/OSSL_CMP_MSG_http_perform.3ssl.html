NOM

OSSL_CMP_MSG_http_perform - transfert HTTP(S) côté client d'une paire requête-réponse CMP

SYNOPSIS

#include <openssl/cmp.h>
OSSL_CMP_MSG *OSSL_CMP_MSG_http_perform(OSSL_CMP_CTX *ctx,
                                        const OSSL_CMP_MSG *req);

DESCRIPTION

OSSL_CMP_MSG_http_perform() envoie le message PKIMessage req donné au serveur CMP spécifié dans ctx et renvoie le résultat obtenu.

Si OSSL_CMP_CTX_set_transfer_cb_arg(3) a été utilisé pour définir l'argument de rappel de transfert, alors le pointeur fourni bios est pris comme un tableau BIO de deux éléments à utiliser pour l'échange avec le serveur, comme décrit pour les paramètres bio et rbio de OSSL_HTTP_open(3). Par exemple, les deux pointeurs BIO peuvent être égaux et pointer vers une connexion TLS, comme dans BRSKI-AE où un canal TLS pré-établi est réutilisé pour CMP.

Sinon, le serveur spécifié via OSSL_CMP_CTX_set1_server(3) et éventuellement OSSL_CMP_CTX_set_serverPort(3) est contacté, où le port par défaut est 80 pour HTTP et 443 pour HTTPS. Le chemin HTTP (alias « alias CMP » dans ce contexte) à utiliser est par défaut "/", sinon la chaîne spécifiée via OSSL_CMP_CTX_set1_serverPath(3). En cas de succès, la fonction renvoie le message PKIMessage de réponse du serveur.

La fonction utilise toute fonction de rappel HTTP définie via OSSL_CMP_CTX_set_http_cb(3). Elle respecte toute valeur de délai d'attente définie via OSSL_CMP_CTX_set_option(3) avec un argument OSSL_CMP_OPT_MSG_TIMEOUT. Elle respecte également toute option de proxy HTTP(S) définie via OSSL_CMP_CTX_set1_proxy(3) et OSSL_CMP_CTX_set1_no_proxy(3) et les variables d'environnement correspondantes. Le proxying HTTP simple est pris en charge directement, tandis que l'utilisation d'un proxy pour les connexions HTTPS nécessite une fonction de rappel appropriée telle que OSSL_HTTP_proxy_connect(3).

NOTES

CMP est défini dans la RFC 4210. Le transfert HTTP pour CMP est défini dans la RFC 6712.

VALEUR DE RETOUR

OSSL_CMP_MSG_http_perform() renvoie le message de réponse CMP reçu en cas de succès, sinon NULL.

VOIR AUSSI

OSSL_CMP_CTX_new(3), OSSL_HTTP_open(3), et OSSL_HTTP_proxy_connect(3).

HISTORIQUE

Le support OpenSSL CMP a été ajouté dans OpenSSL 3.0.

L'utilisation de OSSL_CMP_MSG_http_perform() avec transfer_cb_arg a été ajoutée dans OpenSSL 3.5.
