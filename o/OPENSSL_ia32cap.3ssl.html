NOM

OPENSSL_ia32cap - le vecteur de capacités du processeur x86[_64]

SYNOPSIS

env OPENSSL_ia32cap=... <application>

DESCRIPTION

OpenSSL prend en charge une variété d'extensions d'ensembles d'instructions x86[_64] et de fonctionnalités. Ces extensions sont désignées par des bits individuels ou des groupes de bits stockés en interne sous forme de dix vecteurs de 32 bits et, par souci de simplicité, représentés logiquement comme cinq vecteurs de 64 bits. Ce type de vecteur (LV) est utilisé pour simplifier la définition de la variable d'environnement OPENSSL_ia32cap.

Lors de l'initialisation de la boîte à outils, les vecteurs de capacités sont remplis en exécutant successivement l'instruction CPUID, après quoi tout changement dans les bits de la variable d'environnement OPENSSL_ia32cap est appliqué. Après l'initialisation de la boîte à outils, les vecteurs remplis sont utilisés pour choisir entre différentes voies d'exécution afin d'optimiser les performances sur un large éventail de processeurs x86[_64].

Plus d'informations sur les informations du processeur peuvent être trouvées dans le « Intel® Processor Instruction Set Architecture Extensions Programming Reference » et le « AMD64 Architecture Programmer's Manual (Volume 3) ».

Bits de capacités remarquables pour LV0

Voici les bits de capacités remarquables de LV0 (LV0) résultant de l'exécution de CPUID.(EAX=01H).EDX et CPUID.(EAX=01H).ECX :

bit #0+4 indiquant la présence du compteur de temps de référence ;
bit #0+19 indiquant la disponibilité de l'instruction CLFLUSH ;
bit #0+20, réservé par Intel, est utilisé pour choisir entre les voies RC4 ;
bit #0+23 indiquant la prise en charge de MMX ;
bit #0+24, bit FXSR, indiquant la disponibilité des registres XMM ;
bit #0+25 indiquant la prise en charge de SSE ;
bit #0+26 indiquant la prise en charge de SSE2 ;
bit #0+28 indiquant la prise en charge de l'Hyperthreading, qui est utilisé pour distinguer les cœurs avec cache partagé ;
bit #0+30, réservé par Intel, désigne spécifiquement un processeur Intel ;
bit #0+33 indiquant la disponibilité de l'instruction PCLMULQDQ ;
bit #0+41 indiquant la prise en charge de SSSE3, support complémentaire SSE3 ;
bit #0+43 indiquant la prise en charge d'AMD XOP (forcé à zéro sur les processeurs non-AMD) ;
bit #0+54 indiquant la disponibilité de l'instruction MOVBE ;
bit #0+57 indiquant l'extension d'instruction AES-NI ;
bit #0+58, bit XSAVE, dont l'absence, avec MOVBE, est utilisée pour identifier le noyau Atom Silvermont ;
bit #0+59, bit OSXSAVE, indiquant la disponibilité des registres YMM ;
bit #0+60 indiquant l'extension AVX ;
bit #0+62 indiquant la disponibilité de l'instruction RDRAND ;

bit #64+19 indiquant la disponibilité des instructions ADCX et ADOX ;
bit #64+21 indiquant la disponibilité de l'extension AVX512IFMA ;
bit #64+29 indiquant la disponibilité de l'extension SHA ;
bit #64+30 indiquant la disponibilité de l'extension AVX512BW ;
bit #64+31 indiquant la disponibilité de l'extension AVX512VL ;

bit #64+42 indiquant la disponibilité de l'extension VPCLMULQDQ ;

bit #256+50 indiquant la prise en charge AVX10 ZMM ;

NAME

OPENSSL_ia32cap — environment variable for processor capability control

SYNOPSIS

#include <openssl/ia32cap.h>

The environment variable is named OPENSSL_ia32cap.

DESCRIPTION

The environment variable OPENSSL_ia32cap can be used to control the processor capabilities that OpenSSL uses. It is intended to be used to disable specific instruction set extensions, for example, to test specific code paths or to avoid issues with certain CPU families.

The value of the environment variable is a colon-separated list of logical vectors (LV). Each logical vector is represented by a sequence of decimal, octal or hexadecimal numbers. The format is "LV0:LV1:LV2:LV3:LV4". Not all logical vectors are necessarily present; missing ones are treated as zero. The maximum number of logical vectors is 5.

Each number within a logical vector represents a bitmask of processor capabilities. The capabilities are arranged into logical vectors, where LV0 typically covers x86 instructions, LV1 covers x86-64 instructions, and so on. The exact meaning of the bits is determined by the OpenSSL build and the processor architecture.

By default, OpenSSL queries the processor capabilities using the CPUID instruction and uses all available extensions. Setting OPENSSL_ia32cap overrides this behaviour.

There are two main ways to set the value:

"env OPENSSL_ia32cap=LV0:LV1:LV2:LV3:LV4"

Used in this form, each non-null logical vector will *overwrite* the entire corresponding capability vector pair with the provided value. To keep compatibility with the behaviour of the original OPENSSL_ia32cap environment variable <env OPENSSL_ia32cap=LV0:LV1>, the next capability vector pairs will be set to zero.

To illustrate, the following will zero all capability bits in logical vectors 1 and further (disable all post-AVX extensions):

"env OPENSSL_ia32cap=:0"

The following will zero all capability bits in logical vectors 2 and further:

"env OPENSSL_ia32cap=::0"

The following will zero all capability bits only in logical vector 1: "env OPENSSL_ia32cap=:0::::"

A more likely usage scenario would be to disable specific instruction set extensions. The '~' character is used to specify a bit mask of the extensions to be disabled for a particular logical vector.

To illustrate, the following will disable AVX2 code paths and further extensions:

"env OPENSSL_ia32cap=:~0x20000000000"

The following will disable AESNI (LV0 bit 57) and VAES (LV1 bit 41) extensions and therefore any code paths using those extensions but leave the rest of the logical vectors unchanged:

"env OPENSSL_ia32cap=~0x200000000000000:~0x20000000000:~0x0:~0x0:~0x0"

NOTES

Not all capability bits are copied from CPUID output verbatim. An example of this is the somewhat less intuitive clearing of LV0 bit #28, or ~0x10000000 in the "environment variable" terms. It has been adjusted to reflect whether or not the data cache is actually shared between logical cores. This in turn affects the decision on whether or not expensive countermeasures against cache-timing attacks are applied, most notably in AES assembler module.

RETURN VALUES

Not available.
