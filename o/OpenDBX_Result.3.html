OpenDBX::Result::~Result ()

Détruit une instance Result s'il n'y a plus de références. Chaque objet de résultat utilise un compteur de références pour se souvenir si les variables internes sont partagées avec d'autres objets. Si ce n'est pas le cas ou si cet objet est le dernier à référencer les variables, l'objet est nettoyé et l'espace mémoire alloué est libéré.

OpenDBX::Result::Result (const Result & ref)

Constructeur de copie. Permet le transfert de l'état interne d'une instance ref du même type vers cet objet. Les deux objets partagent les mêmes variables et le compteur de références par la suite. Le compteur de références est incrémenté chaque fois qu'un objet est copié et décrémenté lorsqu'il est détruit.

Paramètres

ref Instance de l'objet de résultat d'origine

Documentation des fonctions membres

unsigned long OpenDBX::Result::columnCount ()

Retourne le nombre de colonnes disponibles dans cet ensemble de résultats. Le nombre de colonnes ne change pas dans un ensemble de résultats avec une exception notable : si l'ensemble de résultats précédent n'a pas été complètement récupéré par getRow() avant que getResult() ne soit à nouveau appelé, le nombre de colonnes peut changer.

Retourne

Nombre de colonnes

Exceptions

const string OpenDBX::Result::columnName (unsigned long pos)

Retourne le nom de la colonne dans l'ensemble de résultats actuel. Obtient le nom de la colonne spécifiée par pos dans l'ensemble de résultats actuel. Les noms de colonnes ne changeront pas dans l'ensemble de résultats, sauf dans le cas de MySQL lorsque le premier ensemble de résultats n'a pas été complètement récupéré avant que getResult() ne soit à nouveau appelé.

unsigned long OpenDBX::Result::columnPos (const string & name)

Associe le nom de la colonne à son numéro de colonne requis par d'autres méthodes. Cette fonction retourne l'index de la colonne qui a le nom du contenu de chaîne donné par le paramètre name. L'index de la colonne ne changera pas dans l'ensemble de résultats.

odbxtype OpenDBX::Result::columnType (unsigned long pos)

Retourne le type de la colonne dans l'ensemble de résultats actuel. Le type de la colonne s'applique à tous les champs dans la même position des lignes récupérées par getRow(). Les définitions sont basées sur la norme SQL2003 et les types de données de la base de données doivent être conformes à la spécification de la norme. Ce sont :

Valeurs numériques exactes :

  • ODBX_TYPE_BOOLEAN : Valeurs vrai/faux
  • ODBX_TYPE_SMALLINT : Entier signé 16 bits
  • ODBX_TYPE_INTEGER : Entier signé 32 bits
  • ODBX_TYPE_BIGINT : Entier signé 64 bits
  • ODBX_TYPE_DECIMAL : Valeurs numériques exactes avec une précision définie par l'utilisateur

Valeurs numériques approximatives :

const char * OpenDBX::Result::fieldValue (unsigned long pos)

Renvoie un pointeur vers le contenu de la ligne actuelle à la position spécifiée. Cette fonction renvoie un pointeur vers les données de la colonne spécifiée par l'indice pos. Le champ fait partie de la ligne actuelle qui a été obtenue par le dernier appel à getRow(). Toutes les valeurs, à l'exception des objets binaires, sont renvoyées sous forme de chaînes de caractères terminées par un caractère nul. Ceci s'applique également aux valeurs numériques, dates, etc. Elles doivent être converties en leur représentation binaire dépendante de la machine avant d'effectuer des opérations arithmétiques. Si une valeur est indéfinie, c'est-à-dire NULL dans la base de données, un pointeur équivalent à NULL est renvoyé.

void OpenDBX::Result::finish ()

Récupère les lignes non chargées et nettoie les tables de résultats disponibles. Après l'exécution d'une commande, au moins une table de résultats est renvoyée par le serveur de base de données. Dans le cas de commandes de manipulation de données, aucune ligne n'est renvoyée, mais la table de résultats doit tout de même être nettoyée. Ceci est généralement fait en appelant getResult() dans une boucle jusqu'à ce qu'il renvoie 'done'. Pour simplifier le développement d'applications, la méthode finish() s'en charge pour vous.

Exceptions

OpenDBX::Exception Si la bibliothèque de base de données renvoie une erreur

Lob OpenDBX::Result::getLob (const char * value)

Crée une instance d'objet volumineux si la base de données le prend en charge. Renvoie une instance de la classe Lob représentant un objet volumineux stocké dans la base de données. Cette classe fait référence à l'objet volumineux et fournit des méthodes pour accéder et modifier son contenu.

Le paramètre requis par cette fonction doit être la valeur renvoyée par la méthode fieldValue() d'une colonne d'objet volumineux.

Cette fonction ne doit être utilisée que si le moteur de base de données indique qu'il prend en charge les objets volumineux via Conn::getCapabilities(). Sinon, le contenu peut être récupéré directement via la méthode fieldValue().

odbxres OpenDBX::Result::getResult (struct timeval * timeout = NULL, unsigned long chunk = 0)

Obtient une table de résultats de la base de données. Récupère le résultat d'une instruction de requête de la base de données. Si l'instruction était un INSERT, UPDATE, DELETE ou similaire, le nombre de lignes affectées peut être obtenu via rowsAffected().

Le paramètre timeout limite le temps pendant lequel la fonction attend une réponse de la base de données. Il peut être NULL pour attendre indéfiniment qu'un résultat soit reçu. Sinon, il peut contenir un nombre quelconque de secondes et de microsecondes dans une structure timeval pour attendre une réponse. La structure timeval doit être définie à chaque fois avant d'appeler getResult(), car son contenu peut être modifié par la fonction. Si la base de données ne répond pas dans le délai imparti, la requête n'est pas annulée ! Au lieu de cela, le prochain appel à cette fonction attendra le même résultat de la table de résultats. L'attente pendant la durée spécifiée peut être implémentée dans les backends si possible, mais il n'y a aucune garantie. Sinon, getResult() ne renverra pas avant qu'une réponse n'arrive.

En fonction de la bibliothèque de base de données native, il peut être possible de récupérer toutes les lignes en une seule fois (si la valeur de chunk est zéro), une par une, ou plusieurs lignes à la fois. Toutes les valeurs positives, y compris zéro, sont autorisées comme valeurs pour chunk. Si la base de données ne prend pas en charge la pagination (plus d'une ligne à la fois), elle utilisera 'une par une' ou 'toutes en une seule fois' si c'est la seule méthode disponible.

getResult() renvoie ODBX_RES_ROWS si une table de résultats peut être obtenue et ODBX_RES_DONE si plus aucun résultat ne sera renvoyé par la dernière requête réussie. ODBX_RES_NOROWS est renvoyé si l'instruction a été exécutée avec succès mais qu'aucune table de résultats ne sera renvoyée (comme dans INSERT, UPDATE et DELETE). ODBX_RES_TIMEOUT indique un timeout.

Paramètres

timeout Pointeur vers une structure timeval spécifiant combien de temps attendre une réponse de la base de données
chunk Nombre de lignes à récupérer de la base de données à la fois (zéro signifie toutes les lignes à la fois)

Retour

Code d'état ou d'erreur

Exceptions

OpenDBX::Exception Si la bibliothèque de base de données renvoie une erreur

odbxrow OpenDBX::Result::getRow ()

Met à disposition les données de la ligne suivante. Récupère les valeurs d'une ligne de la table de résultats obtenue via getResult(). Jusqu'à ce que cette fonction soit appelée, aucune donnée de ligne n'est disponible ni via fieldLength() ou fieldValue(), et ces méthodes lèveront une exception.

getRow() renverra ODBX_ROW_NEXT tant qu'il y aura des lignes disponibles dans la table de résultats. Après que la dernière ligne ait été mise à disposition, les appels ultérieurs à cette fonction renverront ODBX_ROW_DONE, indiquant que la table de résultats ne contient plus de lignes.

Retour

État de la tentative d'obtention d'une ligne supplémentaire

Exceptions

OpenDBX::Exception Si la bibliothèque de base de données renvoie une erreur

uint64_t OpenDBX::Result::rowsAffected ()

Renvoie le nombre de lignes affectées par les instructions INSERT, DELETE ou UPDATE. Renvoie le nombre de lignes qui ont été modifiées par l'instruction actuelle dont la table de résultats a été obtenue via getResult() et zéro si la base de données n'a modifié aucune ligne. Seules les lignes affectées par les instructions DELETE, INSERT ou UPDATE sont renvoyées, et leur nombre exact dépend de l'implémentation de la base de données. Certaines bases de données comme MySQL peuvent renvoyer un nombre inférieur à celui attendu car elles ne modifient pas les enregistrements dont les valeurs n'auraient pas changé.
