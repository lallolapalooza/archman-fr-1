OpenDBX::Lob::~Lob ()

Détruit l'objet volumineux s'il n'y a pas d'autres références. Chaque objet volumineux utilise un compteur de références pour savoir si ses variables internes sont partagées avec d'autres objets. Si ce n'est pas le cas, ou si cet objet est le dernier à référencer les variables, l'objet est nettoyé et l'espace mémoire alloué est libéré.

OpenDBX::Lob::Lob (const Lob & ref)

Constructeur par copie. Permet le transfert de l'état interne d'un objet ref du même type vers cet objet. Les deux objets partagent les mêmes variables et le compteur de références par la suite. Le compteur de références est incrémenté chaque fois qu'un objet est copié et décrémenté s'il est détruit.

Documentation fonction membre

void OpenDBX::Lob::close ()

Ferme l'objet volumineux et valide les changements. Après avoir lu ou écrit du nouveau contenu dans l'objet volumineux, il doit être fermé pour valider les changements sur le disque et libérer les ressources. Si cette opération n'est pas effectuée, le destructeur de l'objet tentera de fermer l'objet volumineux automatiquement, mais il n'y a aucune garantie de succès car le destructeur ne lève pas d'exception en cas d'erreur. Par conséquent, il est recommandé d'appeler cette méthode une fois que vous n'avez plus besoin de l'objet.

ssize_t OpenDBX::Lob::read (void * buffer, size_t buflen)

Lit le contenu de l'objet volumineux dans le tampon. Pour obtenir le contenu de l'objet volumineux, cette méthode récupère les données en une ou plusieurs parties du serveur et les stocke dans le tampon fourni par l'utilisateur. Le premier appel à read() retournera les octets à partir du début. Les appels ultérieurs et tous les autres retourneront une partie du contenu de l'objet volumineux jusqu'à la fin des données. Pour relire le contenu, vous devez fermer le descripteur de l'objet volumineux et le rouvrir, car certaines bases de données ne permettent pas de repositionner le pointeur de fichier interne pour le flux. Le contenu de l'objet volumineux obtenu du serveur est stocké dans le tampon fourni par l'utilisateur jusqu'à buflen octets.

La méthode retourne le nombre d'octets placés dans le tampon, ce qui peut être jusqu'à buflen octets. Si la fin du contenu est atteinte et qu'il n'y a plus de données disponibles, la valeur retournée sera 0 (zéro).

Paramètres

buffer Pointeur vers un tableau d'octets où les données doivent être écrites
buflen Longueur du tampon en octets

Retourne

Nombre d'octets écrits dans le tampon

Exceptions

OpenDBX::Exception Si la bibliothèque de base de données retourne une erreur

ssize_t OpenDBX::Lob::write (void * buffer, size_t buflen)

Écrit des données du tampon dans l'objet volumineux. Envoie les données fournies dans le tampon au serveur pour les stocker dans l'objet volumineux. La fonction peut être appelée plusieurs fois pour ajouter des parties successives du contenu à l'objet. S'il ne s'agit pas d'un nouvel objet ou d'un objet vide, les données existantes seront écrasées et tronquées à la nouvelle taille. Il n'est pas possible de mettre à jour seulement des parties du contenu existant, car certaines bases de données ne permettent pas de repositionner le pointeur de fichier interne. Les données qui doivent être envoyées au serveur sont lues à partir du tampon jusqu'à buflen octets.

La méthode retourne le nombre d'octets lus depuis le tampon et envoyés au serveur, ce qui peut être jusqu'à buflen octets. Il n'est pas garanti que le bloc complet ait été envoyé au serveur, le nombre d'octets retournés peut donc être inférieur à la valeur de buflen.

Paramètres

buffer Pointeur vers un tableau d'octets contenant le contenu
buflen Longueur du contenu dans le tampon en octets

Retourne

Nombre d'octets écrits dans l'objet volumineux

Exceptions

OpenDBX::Exception Si la bibliothèque de base de données retourne une erreur
Une erreur est survenue
