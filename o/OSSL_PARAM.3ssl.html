NOM

OSSL_PARAM — structure pour passer ou demander des paramètres d'objet

SYNOPIS

#include <openssl/core.h>
typedef struct ossl_param_st OSSL_PARAM;
struct ossl_param_st {
    const char *key;             /* nom du paramètre */
    unsigned int data_type;      /* indique le type de contenu trouvé dans data */
    void *data;                  /* valeur passée ou reçue */
    size_t data_size;            /* taille des données */
    size_t return_size;          /* taille retournée */
};

DESCRIPTION

OSSL_PARAM est un type qui permet de passer des données arbitraires entre deux parties qui ont peu ou pas de connaissance l'une de l'autre des structures internes de leurs objets respectifs.

Un exemple typique d'utilisation pourrait être un programme qui souhaite configurer certains paramètres d'un objet ou souhaite trouver certains paramètres d'un objet.

Des tableaux de ce type peuvent être utilisés pour les objectifs suivants :

  • Configurer des paramètres d'un objet quelconque

    L'appelant configure le tableau OSSL_PARAM et appelle une fonction (la fonction de définition) qui a une connaissance approfondie de l'objet, qui peut prendre les données du tableau OSSL_PARAM et les attribuer de manière appropriée à la structure interne de l'objet.

  • Demander des paramètres d'un objet quelconque

    L'appelant (le demandeur) configure le tableau OSSL_PARAM et appelle une fonction (la fonction de réponse) qui a une connaissance approfondie de l'objet, qui peut prendre les données internes de l'objet et copier (éventuellement convertir) ces données dans la mémoire préparée par le demandeur et pointée par le OSSL_PARAM data.

  • Demander des descriptions de paramètres

    L'appelant obtient un tableau d'éléments OSSL_PARAM constants qui décrivent les paramètres disponibles et certaines de leurs propriétés ; nom, type de données et taille attendue. Pour une description détaillée de chaque champ pour cette utilisation, voir les descriptions des champs ci-dessous.

    L'appelant peut ensuite utiliser les informations de ce tableau de description pour construire son propre tableau OSSL_PARAM à passer à un set ou responder.

Normalement, l'ordre des éléments d'un tableau OSSL_PARAM n'est pas pertinent. Cependant, si le responder peut gérer plusieurs éléments avec la même clé, ceux-ci doivent être gérés dans l'ordre où ils apparaissent.

Un tableau OSSL_PARAM doit avoir un élément final où key est NULL. Le modèle de terminaison complet habituel est :

{ NULL, 0, NULL, 0, 0 }

Cela peut également être spécifié à l'aide de OSSL_PARAM_END(3).

Support fonctionnel

Libcrypto offre un ensemble limité de fonctions auxiliaires pour gérer OSSL_PARAM et les tableaux qui en contiennent. Veuillez consulter OSSL_PARAM_get_int(3). Les développeurs peuvent les étendre ou les remplacer comme ils le souhaitent.

Champs OSSL_PARAM

key
L'identifiant du paramètre sous forme de chaîne.

Dans un tableau OSSL_PARAM, un élément dont ce champ est NULL est considéré comme un élément terminal.

data_type
Le data_type est une valeur qui décrit le type et l'organisation des données. Voir la section « Types pris en charge » ci-dessous pour une description des types.
data
data_size
data est un pointeur vers la mémoire où se trouvent les données du paramètre (lors de la définition des paramètres) ou seront stockées (lors de la demande des paramètres), et data_size est leur taille en octets. L'organisation des données dépend du type de paramètre et du drapeau.

Une attention particulière doit être portée au type OSSL_PARAM_UTF8_STRING par rapport aux chaînes C. Lors de la définition des paramètres, la taille doit être la longueur de la chaîne, sans inclure l'octet NUL. Lors de la demande des paramètres, la taille doit être la taille du tampon à remplir, qui doit avoir de la place pour un octet NUL.

Lors de la demande de paramètres, data peut être NULL. Cela peut être utilisé par le demandeur pour déterminer dynamiquement la taille du tampon nécessaire pour stocker les données du paramètre. Dans ce cas, data_size est ignoré.

Lorsque le OSSL_PARAM est utilisé comme descripteur de paramètre, data doit être ignoré. Si data_size est zéro, cela signifie qu'une taille arbitraire est acceptée, sinon il spécifie la taille maximale autorisée.

return_size
Lors de l'utilisation d'un tableau OSSL_PARAM pour demander des données, le responder doit définir ce champ pour indiquer la taille des données du paramètre, y compris le padding le cas échéant. Dans le cas où data_size n'est pas une taille appropriée pour les données, le responder doit quand même définir ce champ pour indiquer la taille minimale nécessaire. (notes supplémentaires dans « NOTES » ci-dessous).

Lorsque le OSSL_PARAM est utilisé comme descripteur de paramètre, return_size doit être ignoré.

NOTE :

Les noms de clés et les types associés sont définis par l'entité qui propose ces paramètres, c'est-à-dire que les noms des paramètres fournis par les bibliothèques OpenSSL sont définis par ces bibliothèques, et les noms des paramètres fournis par les fournisseurs sont définis par les fournisseurs, sauf pour les formulaires de pointeurs (voir les descriptions de types ci-dessous). Les entités qui souhaitent définir ou demander des paramètres doivent savoir quelles sont ces clés et de quel type, et toute fonction entre ces deux entités doit être insensible et ne doit faire que passer le tableau OSSL_PARAM.

Types pris en charge

Le champ data_type peut être l'un des types suivants :

OSSL_PARAM_INTEGER
OSSL_PARAM_UNSIGNED_INTEGER
Les données du paramètre sont un entier (entier ou entier non signé) de longueur arbitraire, organisé de manière native, c'est-à-dire que l'octet le plus significatif est le premier sur les systèmes à grand boutisme, et l'octet le moins significatif est le premier sur les systèmes à petit boutisme.
OSSL_PARAM_REAL
Les données du paramètre sont une valeur à virgule flottante en mode natif.
OSSL_PARAM_UTF8_STRING
Les données du paramètre sont une chaîne imprimable.
OSSL_PARAM_OCTET_STRING
Les données du paramètre sont une chaîne d'octets arbitraire.
OSSL_PARAM_UTF8_PTR
Les données du paramètre sont un pointeur vers une chaîne imprimable.

La différence entre celui-ci et OSSL_PARAM_UTF8_STRING est que data ne pointe pas directement vers les données, mais vers un pointeur qui pointe vers les données.

En cas de doute sur ce qu'il faut utiliser, OSSL_PARAM_UTF8_STRING est presque toujours le bon choix.

Il est utilisé pour indiquer que des données constantes seront passées ou sont passées, et par conséquent, il n'est pas nécessaire de copier les données qui sont passées, seulement le pointeur vers celles-ci.

data_size doit être défini à la taille des données, pas à la taille du pointeur vers les données. S'il est utilisé dans une demande de paramètres, data_size n'est pas pertinent. Cependant, le responder définira return_size à la taille des données.

Remarque : L'utilisation de ce type est fragile et ne peut être utilisée en toute sécurité que pour des données qui restent constantes et se trouvent dans un emplacement constant pendant une période suffisante (telle que la durée de vie de l'entité qui propose ces paramètres).

OSSL_PARAM_OCTET_PTR
Les données du paramètre sont un pointeur vers une chaîne d'octets arbitraire.

La différence entre celui-ci et OSSL_PARAM_OCTET_STRING est que data pointe vers un ensemble d'octets arbitraires, tandis que OSSL_PARAM_UTF8_PTR pointe vers un pointeur qui pointe vers les données.

En cas de doute sur ce qu'il faut utiliser, OSSL_PARAM_UTF8_STRING est presque toujours le bon choix.

Il est utilisé pour indiquer que des données constantes seront passées ou sont passées, et par conséquent, il n'est pas nécessaire de copier les données qui sont passées, seulement le pointeur vers celles-ci.

data_size doit être défini à la taille des données, pas à la taille du pointeur vers les données. S'il est utilisé dans une demande de paramètres, data_size n'est pas pertinent. Cependant, le responder définira return_size à la taille des données.

Remarque : L'utilisation de ce type est fragile et ne peut être utilisée en toute sécurité que pour des données qui restent constantes et se trouvent dans un emplacement constant pendant une période suffisante (telle que la durée de vie de l'entité qui propose ces paramètres).

NOM

L_PARAM_OCTET_STRING

indique que data ne fait pas référence directement aux données, mais à un pointeur qui pointe vers les données.

En cas de doute sur ce qu'il faut utiliser, OSSL_PARAM_OCTET_STRING est presque toujours le bon choix.

Ceci est utilisé pour indiquer que des données constantes seront ou sont passées, et par conséquent, il n'est pas nécessaire de copier les données qui seront passées, mais seulement le pointeur vers celles-ci.

Le data_size doit être défini à la longueur des données, pas à la longueur du pointeur vers les données. Si utilisé dans une requête de paramètres, data_size n'est pas pertinent. Cependant, le responder définira return_size à la longueur des données.

Note : L'utilisation de ce type est fragile et ne peut être utilisée en toute sécurité que pour des données qui restent constantes et dans un emplacement constant pendant une période suffisante (telle que la durée de vie de l'entité qui fournit ces paramètres).

NOTES

Lors de la définition et de la requête de paramètres, les fonctions appelées devront décider de ce qui est une erreur et de ce qui ne l'est pas. Le comportement recommandé est le suivant :

  • Les clés qu'un setter ou responder ne reconnaît pas doivent simplement être ignorées. Ceci n'est pas une erreur en soi.
  • Si les clés qu'un setter reconnaît forment un ensemble de données cohérent, cet appel devrait réussir.
  • À part return_size, un responder ne doit jamais modifier les champs d'un OSSL_PARAM. Pour retourner une valeur, il doit modifier le contenu de la mémoire vers lequel data pointe.
  • Si le type de données associé à une clé est incorrect, la fonction appelée peut retourner une erreur.

    La fonction appelée peut également tenter de convertir les données dans un format approprié (par exemple, il est plausible de passer un grand nombre sous forme de OSSL_PARAM_OCTET_STRING, donc même si une clé est définie comme OSSL_PARAM_UNSIGNED_INTEGER, la valeur peut être passée sous forme de OSSL_PARAM_OCTET_STRING.

  • Si le data d'un OSSL_PARAM_OCTET_STRING ou d'un OSSL_PARAM_UTF8_STRING est NULL, le responder doit définir return_size à la longueur de l'élément à retourner et retourner le succès. Ensuite, le responder sera appelé à nouveau avec data pointant vers l'emplacement où placer la valeur.
  • Si un responder constate que certaines dimensions de données sont trop petites pour les données demandées, il doit définir return_size pour chaque tel OSSL_PARAM à la longueur minimale requise et éventuellement retourner une erreur.
  • Pour les paramètres de type entier (OSSL_PARAM_UNSIGNED_INTEGER et OSSL_PARAM_INTEGER), un responder peut choisir de retourner une erreur si data_size n'est pas une taille appropriée (même si data_size est supérieur au nécessaire). Si le responder trouve la taille appropriée, il doit remplir tous les data_size octets et assurer le bon remplissage pour l'endianness natif, et définir return_size à la même valeur que data_size.

EXEMPLES

Une paire d'exemples pour montrer comment les tableaux d'OSSL_PARAM pourraient être configurés.

Exemple 1

Cet exemple est pour définir des paramètres dans un certain objet :

#include <openssl/core.h>
const char *foo = "some string";
size_t foo_l = strlen(foo);
const char bar[] = "some other string";
OSSL_PARAM set[] = {
    { "foo", OSSL_PARAM_UTF8_PTR, &foo, foo_l, 0 },
    { "bar", OSSL_PARAM_UTF8_STRING, (void *)&bar, sizeof(bar) - 1, 0 },
    { NULL, 0, NULL, 0, 0 }
};

Exemple 2

Cet exemple est pour demander des paramètres dans un certain objet :

const char *foo = NULL;
size_t foo_l;
char bar[1024];
size_t bar_l;
OSSL_PARAM request[] = {
    { "foo", OSSL_PARAM_UTF8_PTR, &foo, 0 /*irrelevant*/, 0 },
    { "bar", OSSL_PARAM_UTF8_STRING, &bar, sizeof(bar), 0 },
    { NULL, 0, NULL, 0, 0 }
};

Un responder recevant ce tableau (comme params dans cet exemple) pourrait remplir les paramètres ainsi :

/* OSSL_PARAM *params */
int i;
for (i = 0; params[i].key != NULL; i++) {
    if (strcmp(params[i].key, "foo") == 0) {
        *(char **)params[i].data = "foo value";
        params[i].return_size = 9; /* longueur de "foo value" */
    } else if (strcmp(params[i].key, "bar") == 0) {
        memcpy(params[i].data, "bar value", 10);
        params[i].return_size = 9; /* longueur de "bar value" */
    }
    /* Ignorer ce qui n'est pas connu */
}
