DESCRIPTION

Le OSSL_DECODER_CTX contient des données sur plusieurs décodeurs, nécessaires pour déterminer quel type d'entrée est requis et pour essayer de le décoder en un des plusieurs résultats possibles. Ceci inclut également la chaîne de décodeurs, de sorte que la sortie d'un peut être l'entrée pour un autre. Cela permet d'avoir des décodeurs génériques comme PEM vers DER, ainsi que des décodeurs plus spécialisés comme DER vers RSA.

Les chaînes peuvent être limitées en spécifiant un type d'entrée, qui est considéré comme un point de départ. Ceci est pris en compte par OSSL_DECODER_CTX_add_extra(), qui arrête l'ajout d'autres implémentations de décodeurs lorsqu'elles ont déjà été ajoutées celles qui utilisent le type d'entrée spécifié, et par des fonctions comme OSSL_DECODER_from_bio(3), qui commence le processus de décodage seulement avec les implémentations de décodeur qui utilisent ce type d'entrée. Par exemple, si le type d'entrée est défini sur "DER", un décodeur PEM vers DER sera ignoré.

Le type d'entrée peut également être NULL, ce qui signifie que l'appelant ne sait pas quel type d'entrée il a. Dans ce cas, OSSL_DECODER_from_bio() essaie simplement une implémentation de décodeur après l'autre, et découvre ainsi quel type d'entrée le l'appelant a fourni.

Pour chaque décodage effectué, même un intermédiaire, le constructeur fourni par l'appelant est appelé pour essayer de construire un type / une structure que l'appelant sait comment gérer à partir du résultat de décodage actuel. Le constructeur est défini avec OSSL_DECODER_CTX_set_construct().

OSSL_DECODER_INSTANCE est une structure opaque qui contient des données sur le décodeur qui a été utilisé récemment, et qui peut être utile pour le constructeur. Il existe quelques fonctions pour extraire des données de ce type, décrites ci-dessous.

Fonctions

OSSL_DECODER_CTX_new() crée un nouveau contexte OSSL_DECODER_CTX vide.

OSSL_DECODER_settable_ctx_params() retourne un tableau de descriptions de paramètres OSSL_PARAM(3).

OSSL_DECODER_CTX_set_params() essaie de définir les paramètres spécifiés avec un tableau OSSL_PARAM(3) params. Ces paramètres sont passés à tous les décodeurs qui ont été ajoutés à ctx jusqu'à présent. Les paramètres qu'une implémentation ne reconnaît pas doivent être ignorés par celle-ci.

OSSL_DECODER_CTX_free() libère le contexte ctx donné. Si l'argument est NULL, rien n'est fait.

OSSL_DECODER_CTX_add_decoder() peuple le OSSL_DECODER_CTX ctx avec un décodeur, pour l'utiliser afin d'essayer de décoder un type d'entrée.

OSSL_DECODER_CTX_add_extra() trouve les décodeurs qui génèrent une entrée pour les décodeurs déjà ajoutés et les ajoute également. Ceci est utilisé pour construire des chaînes de décodeurs.

OSSL_DECODER_CTX_set_input_type() définit le type d'entrée initial. Ceci limite les chaînes de décodeurs à considérer, comme expliqué dans la description générale.

OSSL_DECODER_CTX_set_input_structure() définit le nom de la structure attendue pour l'entrée. Ceci peut être utilisé pour déterminer quelles implémentations de décodeur peuvent être utilisées. NULL est une valeur de structure d'entrée valide, lorsqu'elle n'est pas pertinente, ou lorsque les implémentations de décodeur s'attendent à ce qu'elle soit ainsi.

OSSL_DECODER_CTX_get_num_decoders() obtient le nombre de décodeurs actuellement ajoutés au contexte ctx.

OSSL_DECODER_CTX_set_construct() définit le constructeur construct.

OSSL_DECODER_CTX_set_construct_data() définit les données du constructeur qui sont passées à chaque appel du constructeur.

OSSL_DECODER_CTX_set_cleanup() définit la fonction de nettoyage cleanup. Cette fonction est appelée par OSSL_DECODER_CTX_free(3).

OSSL_DECODER_CTX_get_construct(), OSSL_DECODER_CTX_get_construct_data() et OSSL_DECODER_CTX_get_cleanup() retournent les valeurs qui ont été définies par OSSL_DECODER_CTX_set_construct(), OSSL_DECODER_CTX_set_construct_data() et OSSL_DECODER_CTX_set_cleanup() respectivement.

OSSL_DECODER_export() est une fonction de repli pour les constructeurs qui ne peuvent pas utiliser directement les données qu'ils reçoivent pour plusieurs raisons. Elle transmet la même instance de décodeur decoder_inst que le constructeur a obtenue et un objet reference, décompose l'objet référencé, et exporte le même via la création d'un tableau OSSL_PARAM(3) qui est ensuite passé à export_cb, avec export_arg.

Constructeur

Un OSSL_DECODER_CONSTRUCT reçoit les arguments suivants :

decoder_inst
L' OSSL_DECODER_INSTANCE pour le décodeur à partir duquel le constructeur obtient ses données.
object
Une abstraction d'objet native produite par le décodeur. Plus d'informations sur l'abstraction d'objet native du fournisseur peuvent être trouvées dans provider-object(7).
construct_data
Le pointeur qui a été défini avec OSSL_DECODE_CTX_set_construct_data().

DESCRIPTION

The decoder framework provides a way to decode data into various object types. The primary object is the OSSL_DECODER(3) which represents a decoder implementation. The OSSL_DECODER_CTX structure is a context that holds a collection of decoders and can be used to manage the decoding process.

OSSL_DECODER_CTX_new() creates and returns a new decoder context.

OSSL_DECODER_CTX_free() frees the decoder context ctx.

OSSL_DECODER_CTX_load_remove_decoder() loads or removes a decoder from the context. If remove is true, the decoder is removed. If remove is false, the decoder is added.

OSSL_DECODER_CTX_add_decoder() adds an already loaded decoder to the context.

OSSL_DECODER_CTX_add_extra() attempts to load a decoder implementation from the named provider provider, or from the default provider if provider is NULL. If the name name is specified, it attempts to load a decoder with that name. Otherwise, it loads the first available decoder. This is often used to dynamically load decoders from providers.

OSSL_DECODER_CTX_set_construct() sets the constructor function and its associated data for the decoder context. The constructor function is called when a decoder is chosen and needs to create an object. construct_fn is the function pointer, and construct_data is the data to be passed to that function.

OSSL_DECODER_CTX_set_construct_data() sets only the construct_data for the constructor function.

OSSL_DECODER_CTX_set_cleanup() sets the cleanup function that will be called when the decoder context is freed. This is used to free any resources allocated by the constructor function.

OSSL_DECODER_CTX_get_construct(), OSSL_DECODER_CTX_get_construct_data() and OSSL_DECODER_CTX_get_cleanup() retrieve the currently set constructor function, constructor data, and cleanup function, respectively.

OSSL_DECODER_settable_ctx_params() returns an array of OSSL_PARAM(3) structures that describe the parameters that can be set for a decoder context. This is specific to the decoder implementation passed in decoder.

OSSL_DECODER_CTX_set_params() sets parameters in the decoder context ctx using the provided array of OSSL_PARAM(3) structures. These parameters are passed to the underlying decoder implementations.

OSSL_DECODER_CTX_num_decoders() returns the number of decoders currently available in the decoder context ctx.

OSSL_DECODER_export() performs the decoding operation. It takes the input data from cin and attempts to decode it into an object structure, which is then exported through cout. The details of the decoded object are stored in instance. This function is typically used internally by other OpenSSL functions.

OSSL_DECODER_INSTANCE_decoder() returns the OSSL_DECODER pointer from a decoder instance instance. This may be NULL.

OSSL_DECODER_INSTANCE_decoder_ctx() returns the provider context pointer from a decoder instance instance. This may be NULL.

These utility functions may be used by a constructor:

OSSL_DECODER_INSTANCE_get_decoder() can be used to get the decoder implementation from a decoder instance decoder_inst.

OSSL_DECODER_INSTANCE_get_decoder_ctx() can be used to get the decoder implementation's provider context from a decoder instance decoder_inst.

OSSL_DECODER_INSTANCE_get_input_type() can be used to get the decoder implementation's input type from a decoder instance decoder_inst.

OSSL_DECODER_INSTANCE_get_input_structure() can be used to get the input structure for the decoder implementation from a decoder instance decoder_inst. This may be NULL.

RETURN VALUES

OSSL_DECODER_CTX_new() returns a pointer to a OSSL_DECODER_CTX, or NULL if the context structure couldn't be allocated.

OSSL_DECODER_settable_ctx_params() returns an OSSL_PARAM(3) array, or NULL if none is available.

OSSL_DECODER_CTX_set_params() returns 1 if all recognised parameters were valid, or 0 if one of them was invalid or caused some other failure in the implementation.

OSSL_DECODER_CTX_add_decoder(), OSSL_DECODER_CTX_add_extra(), OSSL_DECODER_CTX_set_construct(), OSSL_DECODER_CTX_set_construct_data() and OSSL_DECODER_CTX_set_cleanup() return 1 on success, or 0 on failure.

OSSL_DECODER_CTX_get_construct(), OSSL_DECODER_CTX_get_construct_data() and OSSL_DECODER_CTX_get_cleanup() return the current pointers to the constructor, the constructor data and the cleanup functions, respectively.

OSSL_DECODER_CTX_num_decoders() returns the current number of decoders. It returns 0 if ctx is NULL.

OSSL_DECODER_export() returns 1 on success, or 0 on failure.

OSSL_DECODER_INSTANCE_decoder() returns an OSSL_DECODER pointer on success, or NULL on failure.

OSSL_DECODER_INSTANCE_decoder_ctx() returns a provider context pointer on success, or NULL on failure.
