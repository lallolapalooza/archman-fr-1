Description détaillée

API C++ OpenDBX.

L'API C++ OpenDBX est une couche d'abstraction de base de données orientée objet basée sur l'API C procédurale de la bibliothèque OpenDBX. L'API C++ fournit des objets encapsulant les connexions, les instructions, les ensembles de résultats et les objets volumineux.

L'utilisation de l'API commence par l'établissement d'une connexion au serveur de base de données en créant une instance de la classe Conn avec les paramètres backend, host et port. Conn::getCapability() teste les capacités implémentées de la bibliothèque de base de données sous-jacente tandis que Conn::getOption() et Conn::setOption() sont utilisés pour tester et modifier un certain nombre d'options. Les options doivent être modifiées avant d'authentifier la connexion avec la méthode Conn::bind() pour avoir un effet. Il est également possible de relier une connexion en utilisant des identifiants différents après que Conn::unbind() ait été appelée. De plus, la classe Conn est capable d'échapper les séquences de caractères potentiellement dangereuses avec Conn::escape() si, par exemple, l'entrée utilisateur doit faire partie d'une instruction en tant que valeur.

La méthode Conn::create() crée et initialise une nouvelle instance d'instruction à partir d'une chaîne SQL. Actuellement, seuls des objets d'instruction simples sont implémentés, qui doivent être des instructions complètes pouvant être envoyées à la base de données avec Stmt::execute(). Cette méthode renvoie un objet Result encapsulant un ou plusieurs ensembles de résultats retournés par la base de données en fonction de l'instruction envoyée.

Chaque ensemble de résultats doit être récupéré en utilisant Result::getResult(), tandis que Result::getRows() récupère une ligne de l'ensemble de résultats courant si l'instruction était de type SELECT. Sinon, Result::rowsAffected() peut être utilisé pour obtenir le nombre de lignes qui ont été affectées par l'instruction. Si l'instruction peut retourner des lignes, les méthodes Result::columnName() et Result::columnType() peuvent fournir des informations sur les colonnes indexées de 0 à n. Il est également possible de mapper le nom de la colonne avec la méthode Result::columnPos() à l'index de la colonne requis par les autres méthodes de colonne. Pour obtenir la valeur réelle et la longueur du contenu dans la ligne courante à la position donnée, les méthodes Result::fieldValue() et Result::fieldLength() doivent être appelées.

Dans le cas où la bibliothèque de base de données sous-jacente nécessite une gestion spéciale des objets volumineux (LOB binaires ou texte), la valeur de Result::fieldValue() doit être alimentée dans la méthode Result::getLob(). Elle renvoie un objet Lob qui permet à l'application de lire et d'écrire dans un objet volumineux en utilisant respectivement Lob::read() et Lob::write(). Ceci n'est nécessaire que si la méthode Conn::getCapability() renvoie true lors de la requête de ODBX_CAP_LO.

Si une erreur se produit dans l'une des méthodes d'objet, les objets lèveront une instance de la classe Exception qui hérite de l'exception runtime_error de la STL. L'instance contient un message d'erreur, le code d'erreur OpenDBX et un type d'erreur indiquant la sévérité de l'erreur. Ces informations peuvent être récupérées par les méthodes Exception::what(), Exception::getCode() et Exception::getType().
