QMCINDOM(3) Manuel des fonctions de bibliothèque QMCINDOM(3)

NOM

QmcIndom - conteneur pour une description de domaine d'instance

SYNOPSIS C++

#include <QmcIndom.h>

c++ ... -lpcp_qmc -lpcp

DESCRIPTION

Un objet QmcIndom représente un domaine d'instance de PMAPI(3). Cela inclut une description de toutes les instances dans le domaine d'instance.

Une QmcInstance est une structure utilisée pour décrire chaque instance dans le domaine d'instance. Cela inclut :


- identifiant interne. Si celui-ci est inférieur à zéro, l'instance est traitée comme une entrée NULLE dans la table d'instances.

- nom externe

- compteur de références, c'est-à-dire le nombre d'objets QmcMetric référençant cette instance.

- la position probable de l'instance dans le pmResult d'un pmFetch(3). Ceci est également utilisé pour indiquer la position de la prochaine instance NULLE dans la table d'instances, si cette entrée est également NULLE.

- un indicateur indiquant si l'instance était présente dans le dernier pmGetInDom(3).

L'objet QmcIndom possède une liste de structures QmcInstance, ainsi que divers drapeaux et compteurs pour prendre en charge les domaines d'instance dynamiques où les instances peuvent apparaître et disparaître à chaque récupération et pour une génération efficace de profils.

CONSTRUCTEURS

QmcIndom::QmcIndom(int type, QmcDesc &desc);
Appelle pmGetInDom(3) et pmGetInDomArchive(3) pour les contextes d'hôte et d'archive afin d'obtenir la liste complète des instances pour le domaine d'instance de type type et identifié dans desc.

DOMAINS DYNAMIQUES

La prise en charge des domaines d'instance dynamiques pour les contextes en direct est complexe car de nombreuses métriques peuvent référencer n'importe laquelle des instances du domaine. Par conséquent, la liste des instances peut être éparse car la position des instances dans la liste doit être maintenue.

Lorsque le domaine d'instance est mis à jour, les instances peuvent être supprimées de la liste si elles ne figurent pas dans la nouvelle liste d'instances (telle que retournée par pmGetInDom(3)) et ne sont pas référencées par des métriques. Chaque instance de la nouvelle liste est ensuite comparée à l'ancienne liste pour déterminer quelles instances sont toujours actives, et les nouvelles instances doivent être ajoutées. Une instance est considérée comme identique si ses identifiants interne et externe sont les mêmes. Les nouvelles instances sont d'abord insérées aux positions des instances supprimées avant d'être ajoutées à la liste.

Cet algorithme est coûteux (potentiellement O(N^2)).

bool changed() const;
Retourne true si le domaine d'instance a potentiellement changé lors de la dernière récupération.
void newFetch();
Réinitialise les drapeaux qui indiquaient potentiellement que le domaine d'instance avait changé. Ceci est appelé par QmcContext::fetch.
void hasChanged();
Définit les drapeaux pour indiquer que le domaine d'instance a potentiellement changé. Ceci est appelé par QmcMetric::extractValues.
int update();
Met à jour le domaine d'instance comme décrit ci-dessus. Lors des appels ultérieurs, avant la prochaine récupération, cette méthode supprimera toutes les instances qui ne sont plus référencées sans mettre à jour la liste d'instances avec un appel à pmGetInDom(3).
uint_t numInsts() const;
Retourne le nombre d'instances qui ne sont pas NULLES.
uint_t numActiveInsts() const;
Retourne le nombre d'instances qui sont actives selon le dernier appel à QmcIndom::update.
uint_t listLen() const;
Retourne la longueur de la liste d'instances, y compris les instances NULLES.

PROFILS

L'algorithme pour déterminer le profil le plus compact utilise le nombre d'instances (_instances.length()), le nombre d'instances référencées (_count), le nombre d'instances actives (_numActive) et le nombre d'instances actives référencées (_numActiveRef).


si (toutes les instances actives sont référencées
    ou s'il n'y a pas d'instances actives)
        demander toutes les instances implicitement
sinon si (le nombre d'instances référencées
         est inférieur au nombre d'instances actives
         qui ne sont pas référencées)
        supprimer toutes les instances du profil
        ajouter toutes les instances référencées
sinon
        ajouter toutes les instances au profil
        supprimer toutes les instances qui ne sont pas référencées
bool diffProfile() const;
Retourne true si le profil a potentiellement changé depuis le dernier appel à QmcIndom::genProfile.
int genProfile();
Génère un nouveau profil pour le domaine d'instance. Un code d'erreur PMAPI(3) est retourné si la génération du profil a échoué.

DIAGNOSTICS

Les messages d'erreur sont générés à l'aide de pmprintf(3) mais ne sont pas vidés. Il incombe à l'utilisateur d'appeler pmflush(3) pour afficher tous les messages.

Des diagnostics supplémentaires peuvent être activés en ajoutant les options pmc et/ou indom à la spécification de débogage globale, comme décrit dans pmSetDebug(3).

BOGUES

Les utilisateurs n'ont aucun contrôle sur l'algorithme utilisé pour générer le profil. Dans le cas des métriques proc, un profil implicite pourrait être généré si toutes les instances de processus sont requises, même si cela n'entraînera pas le retour de valeurs dans la récupération.

VOIR AUSSI
