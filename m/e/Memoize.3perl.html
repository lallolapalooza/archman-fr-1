Memoize(3perl) Guide de référence des programmeurs Perl Memoize(3perl)

NOM

Memoize - Accélérer les fonctions en échangeant espace contre temps

SYNOPIS

use Memoize;
memoize('fonction_lente');
fonction_lente(arguments);    # Est plus rapide qu'avant

C'est normalement tout ce que vous avez besoin de savoir. Cependant, de nombreuses options sont disponibles :

memoize(fonction, options...);

Les options incluent :

NORMALIZER => fonction
INSTALL => nouveau_nom
SCALAR_CACHE => 'MEMORY'
SCALAR_CACHE => ['HASH', \%cache_hash ]
SCALAR_CACHE => 'FAULT'
SCALAR_CACHE => 'MERGE'
LIST_CACHE => 'MEMORY'
LIST_CACHE => ['HASH', \%cache_hash ]
LIST_CACHE => 'FAULT'
LIST_CACHE => 'MERGE'

DESCRIPTION

La mémorisation d'une fonction la rend plus rapide en échangeant espace contre temps. Elle le fait en mettant en cache les valeurs de retour de la fonction dans une table. Si vous appelez la fonction à nouveau avec les mêmes arguments, "memoize" intervient et vous donne la valeur à partir de la table, au lieu de laisser la fonction recalculer la valeur.

EXEMPLE

Voici un exemple extrême. Considérons la suite de Fibonacci, définie par la fonction suivante :

# Calculer les nombres de Fibonacci
sub fib {
  my $n = shift;
  return $n if $n < 2;
  fib($n-1) + fib($n-2);
}

Cette fonction est très lente. Pourquoi ? Pour calculer fib(14), elle veut d'abord calculer fib(13) et fib(12), et ajouter les résultats. Mais pour calculer fib(13), elle doit d'abord calculer fib(12) et fib(11), puis elle revient calculer fib(12) à nouveau même si la réponse est la même. Et chaque fois qu'elle veut calculer fib(12), elle doit calculer fib(11) à partir de zéro, puis le faire à nouveau chaque fois qu'elle veut calculer fib(13). Cette fonction effectue tellement de recalculs de résultats anciens qu'elle prend beaucoup de temps à s'exécuter --- fib(14) effectue 1 200 appels récursifs supplémentaires à elle-même, pour calculer et recalculer des choses qu'elle a déjà calculées.

Cette fonction est un bon candidat pour la mémorisation. Si vous mémorisez la fonction "fib" ci-dessus, elle calculera fib(14) exactement une fois, la première fois qu'elle en aura besoin, puis sauvegardera le résultat dans une table. Ensuite, si vous demandez à nouveau fib(14), elle vous donnera le résultat à partir de la table. En calculant fib(14), au lieu de calculer fib(12) deux fois, elle le fait une fois ; la deuxième fois qu'elle a besoin de la valeur, elle l'obtient de la table. Elle ne calcule pas fib(11) quatre fois ; elle le calcule une fois, l'obtenant de la table les trois fois suivantes. Au lieu de faire 1 200 appels récursifs à "fib", elle en fait 15. Cela rend la fonction environ 150 fois plus rapide.

Vous pourriez faire la mémorisation vous-même, en réécrivant la fonction, comme ceci :

# Calculer les nombres de Fibonacci, version mémorisée
{ my @fib;
  sub fib {
    my $n = shift;
    return $fib[$n] if defined $fib[$n];
    return $fib[$n] = $n if $n < 2;
    $fib[$n] = fib($n-1) + fib($n-2);
  }
}

Ou vous pourriez utiliser ce module, comme ceci :

use Memoize;
memoize('fib');
# Le reste de la fonction fib, comme dans la version originale.

Cela permet d'activer et de désactiver facilement la mémorisation.

Voici un exemple encore plus simple : j'ai écrit un traceur de rayons simple ; le programme regardait dans une certaine direction, déterminait ce qu'il regardait, puis convertissait la valeur de "couleur" (typiquement une chaîne comme "rouge") de cet objet en une valeur de pixel rouge, vert et bleu, comme ceci :

for ($direction = 0; $direction < 300; $direction++) {
  # Déterminer quel objet est dans la direction $direction
  $couleur = $objet->{couleur};
  ($r, $g, $b) = @{&ColorToRGB($couleur)};
  ...
}

Puisqu'il y a relativement peu d'objets dans une image, il n'y a que peu de couleurs, qui sont recherchées encore et encore. La mémorisation de "ColorToRGB" a accéléré le programme de plusieurs pour cent.

DÉTAILS

Ce module exporte exactement une fonction, "memoize". Le reste des fonctions de ce paquet ne vous regardent pas.

Vous devriez dire

memoize(fonction)

où "fonction" est le nom de la fonction que vous voulez mémoriser, ou une référence vers celle-ci. "memoize" renvoie une référence vers la nouvelle version mémorisée de la fonction, ou "undef" en cas d'erreur non fatale. Actuellement, il n'y a pas d'erreurs non fatales, mais il pourrait y en avoir à l'avenir.

Si "fonction" était le nom d'une fonction, alors "memoize" cache l'ancienne version et installe la nouvelle version mémorisée sous l'ancien nom, de sorte que &fonction(...) appelle réellement la version mémorisée.

OPTIONS

Il existe quelques options facultatives que vous pouvez passer à "memoize" pour modifier légèrement son comportement. Pour fournir des options, invoquez "memoize" comme ceci :

memoize(fonction, NORMALIZER => fonction,
                  INSTALL => nouveau_nom,
                  SCALAR_CACHE => option,
                  LIST_CACHE => option
                 );

Chacune de ces options est facultative ; vous pouvez en inclure certaines, toutes ou aucune.

INSTALL

Si vous fournissez un nom de fonction avec "INSTALL", memoize installera la nouvelle version mémorisée de la fonction sous le nom que vous donnez. Par exemple,

memoize('fib', INSTALL => 'fastfib')

installe la version mémorisée de "fib" en tant que "fastfib" ; sans l'option "INSTALL", elle aurait remplacé l'ancien "fib" par la version mémorisée.

Pour empêcher "memoize" d'installer la version mémorisée n'importe où, utilisez "INSTALL => undef".

NORMALIZER

Supposons que votre fonction ressemble à ceci :

# Appel typique : f('aha!', A => 11, B => 12);
sub f {
  my $a = shift;
  my %hash = @_;
  $hash{B} ||= 2;  # B a pour valeur par défaut 2
  $hash{C} ||= 7;  # C a pour valeur par défaut 7
  # Faire quelque chose avec $a, %hash
}

Maintenant, les appels suivants à votre fonction sont tous complètement équivalents :

f(OUCH);
f(OUCH, B => 2);
f(OUCH, C => 7);
f(OUCH, B => 2, C => 7);
f(OUCH, C => 7, B => 2);
(etc.)

Cependant, à moins que vous ne disiez à "Memoize" que ces appels sont équivalents, il ne le saura pas, et il calculera les valeurs pour ces invocations de votre fonction séparément, et les stockera séparément.

Pour éviter cela, fournissez une fonction "NORMALIZER" qui transforme les arguments du programme en une chaîne de caractères de manière à ce que des arguments équivalents produisent la même chaîne. Une fonction "NORMALIZER" pour "f" ci-dessus pourrait ressembler à ceci :

sub normalize_f {
  my $a = shift;
  my %hash = @_;
  $hash{B} ||= 2;
  $hash{C} ||= 7;
  join(',', $a, map ($_ => $hash{$_}) sort keys %hash);
}

Chacune des listes d'arguments ci-dessus sort de la fonction "normalize_f" exactement de la même manière, comme ceci :

OUCH,B,2,C,7

Vous diriez à "Memoize" d'utiliser ce normalisateur comme ceci :

memoize('f', NORMALIZER => 'normalize_f');

"memoize" sait que si la version normalisée des arguments est la même pour deux listes d'arguments, alors il peut en toute sécurité rechercher la valeur qu'il a calculée pour une liste d'arguments et la retourner comme résultat de l'appel de la fonction avec l'autre liste d'arguments, même si les listes d'arguments semblent différentes.

Le normalisateur par défaut concatène simplement les arguments avec le caractère 28 entre eux. (En ASCII, cela s'appelle FS ou contrôle-\.) Cela fonctionne toujours correctement pour les fonctions avec un seul argument de chaîne, et aussi lorsque les arguments ne contiennent jamais le caractère 28. Cependant, cela peut confondre certaines listes d'arguments :

normalizer("a\034", "b")
normalizer("a", "\034b")
normalizer("a\034\034b")

Comme les clés de hachage sont des chaînes de caractères, le normaliseur par défaut ne fera pas la distinction entre "undef" et la chaîne vide. Il ne fonctionnera pas non plus lorsque les arguments de la fonction sont des références. Par exemple, considérons une fonction "g" qui reçoit deux arguments : un nombre et une référence à un tableau de nombres :

g(13, [1,2,3,4,5,6,7]);

Le normaliseur par défaut transformera cela en quelque chose comme "13\034ARRAY(0x436c1f)". Cela irait bien, sauf qu'un tableau de nombres ultérieur pourrait être stocké à un emplacement différent même s'il contient les mêmes données. Si cela se produit, "Memoize" pensera que les arguments sont différents, même s'ils sont équivalents. Dans ce cas, un normaliseur comme celui-ci est approprié :

sub normalize { join ' ', $_[0], @{$_[1]} }

Pour l'exemple ci-dessus, cela produit la clé "13 1 2 3 4 5 6 7".

Une autre utilisation des normaliseurs est lorsque la fonction dépend de données autres que celles de ses arguments. Supposons que vous ayez une fonction qui renvoie une valeur dépendant de l'heure actuelle :

sub on_duty {
  my ($problem_type) = @_;
  my $hour = (localtime)[2];
  open my $fh, "$DIR/$problem_type" or die...;
  my $line;
  while ($hour-- > 0)
    $line = <$fh>;
  }
  return $line;
}

À 10h23, cette fonction génère la 10ème ligne d'un fichier de données ; à 15h45, elle génère la 15ème ligne à la place. Par défaut, "Memoize" ne verra que l'argument $problem_type. Pour résoudre ce problème, incluez l'heure actuelle dans le normaliseur :

sub normalize { join ' ', (localtime)[2], @_ }

Le contexte d'appel de la fonction (contexte scalaire ou liste) est propagé au normaliseur. Cela signifie que si la fonction mémoïsée traite ses arguments différemment en contexte de liste qu'en contexte scalaire, vous pouvez faire en sorte que la fonction normaliseuse sélectionne son comportement en fonction des résultats de "wantarray". Même appelée dans un contexte de liste, une normaliseuse devrait toujours renvoyer une seule chaîne de caractères.

"SCALAR_CACHE", "LIST_CACHE"

Normalement, "Memoize" met en cache les valeurs de retour de votre fonction dans une variable de hachage Perl ordinaire. Cependant, vous pourriez vouloir mettre en cache les valeurs sur le disque, afin qu'elles persistent d'une exécution à l'autre de votre programme, ou vous pourriez vouloir associer d'autres sémantiques intéressantes aux valeurs mises en cache.

Il y a une légère complication sous le capot de "Memoize" : il y a en fait *deux* caches, un pour les valeurs scalaires et un pour les valeurs de liste. Lorsque votre fonction est appelée en contexte scalaire, sa valeur de retour est mise en cache dans un hachage, et lorsque votre fonction est appelée en contexte de liste, sa valeur est mise en cache dans l'autre hachage. Vous pouvez contrôler le comportement de mise en cache des deux contextes indépendamment avec ces options.

L'argument de "LIST_CACHE" ou "SCALAR_CACHE" doit être l'une des quatre chaînes suivantes :

MEMORY
FAULT
MERGE
HASH

ou bien il doit s'agir d'une référence à un tableau dont le premier élément est l'une de ces quatre chaînes, par exemple "[HASH, arguments...]".

"MEMORY"
"MEMORY" signifie que les valeurs de retour de la fonction seront mises en cache dans une variable de hachage Perl ordinaire. Le hachage ne persistera pas après la sortie du programme. C'est le comportement par défaut.
"HASH"
"HASH" vous permet de spécifier qu'un hachage particulier que vous fournissez sera utilisé comme cache. Vous pouvez lier ce hachage au préalable pour lui donner le comportement souhaité.

Un hachage lié peut avoir n'importe quelle sémantique. Il est généralement lié à une base de données sur disque, de sorte que les valeurs mises en cache sont stockées dans la base de données et récupérées lorsque nécessaire, et le fichier disque persiste généralement après la sortie de votre programme. Voir "perltie" pour plus de détails sur "tie".

Un exemple typique est :

use DB_File;
tie my %cache => 'DB_File', $filename, O_RDWR|O_CREAT, 0666;
memoize 'function', SCALAR_CACHE => [HASH => \%cache];

Cela a pour effet de stocker le cache dans une base de données "DB_File" dont le nom est dans $filename. Le cache persistera après la sortie du programme. La prochaine fois que le programme s'exécutera, il trouvera le cache déjà rempli par l'exécution précédente du programme. Ou vous pouvez peupler le cache de force en construisant un programme batch qui s'exécute en arrière-plan et remplit le fichier de cache. Ensuite, lorsque vous exécuterez votre programme réel, la fonction mémoïsée sera rapide car tous ses résultats auront été précalculés.

Une autre raison d'utiliser "HASH" est de fournir votre propre variable de hachage. Vous pouvez ensuite inspecter ou modifier le contenu du hachage pour obtenir un contrôle plus fin sur la gestion du cache.

"TIE"
Cette option n'est plus supportée. Elle est toujours documentée uniquement pour aider au débogage d'anciens programmes qui l'utilisent. Les anciens programmes devraient être convertis pour utiliser l'option "HASH" à la place. 
memoize ... ['TIE', PACKAGE, ARGS...]

est simplement un raccourci pour

require PACKAGE;
{ tie my %cache, PACKAGE, ARGS...;
  memoize ... [HASH => \%cache];
}
"FAULT"
"FAULT" signifie que vous ne vous attendez jamais à appeler la fonction en contexte scalaire (ou de liste), et que si "Memoize" détecte un tel appel, il doit arrêter le programme. Le message d'erreur est l'un des suivants : 
`foo' function called in forbidden list context at line ...
`foo' function called in forbidden scalar context at line ...
"MERGE"
"MERGE" signifie normalement que la fonction mémoïsée ne fait pas de distinction entre le contexte de liste et le contexte scalaire, et que les valeurs de retour dans les deux contextes doivent être stockées ensemble. "LIST_CACHE => MERGE" et "SCALAR_CACHE => MERGE" signifient la même chose.

Considérez cette fonction :

sub complicated {
  # ... calcul coûteux en temps de $result
  return $result;
}

La fonction "complicated" renverra la même valeur numérique $result, qu'elle soit appelée en contexte de liste ou scalaire.

Normalement, le code suivant entraînera deux appels à "complicated", même si "complicated" est mémoïsée :

$x = complicated(142);
($y) = complicated(142);
$z = complicated(142);

Le premier appel mettra en cache le résultat, disons 37, dans le cache scalaire ; le second mettra en cache la liste "(37)" dans le cache de liste. Le troisième appel n'appellera pas la vraie fonction "complicated" ; il obtiendra la valeur 37 du cache scalaire.

Évidemment, le deuxième appel à "complicated" est une perte de temps, et stocker sa valeur de retour est un gaspillage d'espace. Spécifier "LIST_CACHE => MERGE" fera en sorte que "memoize" utilise le même cache pour les valeurs de retour scalaires et de liste, de sorte que le deuxième appel utilise le cache scalaire qui a été peuplé par le premier appel. "complicated" ne sera appelé qu'une seule fois, et les deux appels suivants renverront 37 depuis le cache, quel que soit le contexte d'appel.

Valeurs de liste en contexte scalaire

Considérez cette fonction :

sub iota { return reverse (1..$_[0]) }

Cette fonction renvoie normalement une liste. Supposons que vous la mémoïsiez et fusionniez les caches :

memoize 'iota', SCALAR_CACHE => 'MERGE';
@i7 = iota(7);
$i7 = iota(7);

Ici, le premier appel met en cache la liste (1,2,3,4,5,6,7). Le second appel n'a pas vraiment de sens. "Memoize" ne peut pas deviner quel comportement "iota" devrait avoir en contexte scalaire sans l'appeler réellement en contexte scalaire. Normalement, "Memoize" *appellerait* "iota" en contexte scalaire et mettrait en cache le résultat, mais l'option "SCALAR_CACHE => 'MERGE'" dit de ne pas le faire, mais d'utiliser plutôt la valeur de liste mise en cache. Mais cela ne peut pas renvoyer une liste de sept éléments dans un contexte scalaire. Dans ce cas, $i7 recevra le **premier élément** de la valeur de liste mise en cache, à savoir 7.

Caches disque fusionnés

Une autre utilisation de "MERGE" est lorsque vous voulez que les deux types de valeurs de retour soient stockés dans le même fichier disque ; cela vous évite d'avoir à gérer deux fichiers disque au lieu d'un seul. Vous pouvez utiliser une fonction normaliseuse pour séparer les deux ensembles de valeurs de retour. Par exemple :

local $MLDBM::UseDB = 'DB_File';
tie my %cache => 'MLDBM', $filename, ...;
memoize 'myfunc',
  NORMALIZER => 'n',
  SCALAR_CACHE => [HASH => \%cache],
  LIST_CACHE => 'MERGE',
;
sub n {
  my $context = wantarray() ? 'L' : 'S';
  # ... maintenant calculer la clé de hachage à partir des arguments ...
  $hashkey = "$context:$hashkey";
}

Cette fonction normaliseuse stockera les valeurs de retour en contexte scalaire dans le fichier disque sous des clés commençant par "S:", et les valeurs de retour en contexte de liste sous des clés commençant par "L:".

AUTRES FACILITÉS

"unmemoize"

Il existe une fonction "unmemoize" que vous pouvez importer si vous le souhaitez. Pourquoi le voudriez-vous ? Voici un exemple : Supposons que votre cache soit lié à un fichier DBM, et que vous vouliez vous assurer que le cache est écrit sur disque si quelqu'un interrompt le programme. Si le programme se termine normalement, cela se produira de toute façon, mais si

alguien pulsa Control-C o algo similar, el programa terminará inmediatamente sin sincronizar la base de datos. Por lo tanto, lo que puedes hacer en su lugar es

$SIG{INT} = sub { unmemoize 'function' };

«unmemoize» acepta una referencia a, o el nombre de una función previamente memorizada, y deshace lo que hizo para restaurar la versión original memorizada, incluyendo hacer que el nombre se refiera a la versión no memorizada si es necesario. Devuelve una referencia a la versión no memorizada de la función.

Si intentas desmemorizar una función que nunca fue memorizada, se producirá un error.

«flush_cache»

flush_cache(function) descarta las cachés, descartando *todos* los datos cacheados. El argumento puede ser el nombre de una función o una referencia a una función. Para un control más fino sobre cuándo se descartan o caducan los datos, consulta la documentación de «Memoize::Expire», incluida en este paquete.

Nota: si la caché es una tabla enlazada, «flush_cache» intentará invocar el método «CLEAR» en la tabla. Si no hay un método «CLEAR», se producirá un error en tiempo de ejecución.

Un enfoque alternativo para limpiar la caché es usar la opción «HASH» (ver arriba) para pedir a «Memoize» que utilice una variable hash específica como su caché. Luego puedes examinar o modificar la tabla de caché en cualquier momento. Puedes limpiar la caché mediante «%hash = ()»).

ADVERTENCIAS

La memorización no es una cura universal:

  • No debes memorizar una función cuyo comportamiento dependa del estado del programa más allá de sus propios argumentos, como variables globales, la hora del día o la entrada de archivos. Estas funciones no producirán resultados correctos cuando se memoricen. Un ejemplo particular: 
    sub f {
  time;
}

    Esta función no acepta argumentos y, para «Memoize», siempre devuelve el mismo resultado. «Memoize» está equivocado, y la versión memorizada de esta función llamará a «time» una vez para obtener la hora actual, y devolverá la misma hora cada vez que la llames después.

  • No debes memorizar una función con efectos secundarios. 
    sub f {
  my ($a, $b) = @_;
  my $s = $a + $b;
  print "$a + $b = $s.\n";
}

    Esta función acepta dos argumentos, los suma y los imprime. Su valor de retorno es el número de caracteres que imprime, pero probablemente no te importe. Sin embargo, «Memoize» no lo entiende. Si memorizas esta función, obtendrás el resultado esperado la primera vez que preguntes por la suma de 2 y 3, pero las llamadas posteriores devolverán 1 (el valor de retorno de «print») sin imprimir nada.

  • No debes memorizar una función que devuelve una estructura de datos modificada por su llamante.

    Considera estas funciones: «getusers» devuelve una lista de usuarios de alguna manera, y luego «main» elimina el primer usuario de la lista e imprime el resto: 

    sub main {
  my $userlist = getusers();
  shift @$userlist;
  foreach $u (@$userlist) {
    print "User $u\n";
  }
}
sub getusers {
  my @users;
  # Haz algo para obtener una lista de usuarios;
  \@users;  # Devuelve una referencia a la lista.
}

    Si memorizas «getusers» aquí, funcionará correctamente exactamente una vez. La referencia a la lista de usuarios se almacenará en la tabla de memorización. «main» eliminará el primer elemento de la lista referenciada. La próxima vez que invoques «main», «Memoize» no llamará a «getusers»; simplemente devolverá la misma referencia a la misma lista que obtuviste la última vez. Pero esta vez la lista ya ha perdido su cabeza; «main» eliminará otro elemento de ella. La lista se hará cada vez más corta al llamar a «main».

    De manera similar, esto:

    $u1 = getusers();    
$u2 = getusers();    
pop @$u1;

    modificará $u2 así como $u1, porque ambos son referencias a la misma lista. Si «getusers» no estuviera memorizada, $u1 y $u2 se referirían a listas diferentes.

  • No debes memorizar una función muy simple.

    Recientemente alguien me comentó que el módulo Memoize hacía que su programa fuera más lento que rápido. Lo que se reveló fue que estaba memorizando la siguiente función:

    sub square {
  $_[0] * $_[0];
}

    Pude señalarle que «Memoize» utiliza un hash, y que buscar un número en el hash llevará inevitablemente más tiempo que una sola multiplicación. De hecho, no hay forma de acelerar la función «square».

    La memorización no es mágica.

SOPORTE DE CACHÉ PERSISTENTE

Puedes enlazar las tablas de caché a cualquier tipo de tabla enlazada que desees, siempre que soporte «TIEHASH», «FETCH», «STORE» y «EXISTS». Por ejemplo,

tie my %cache => 'GDBM_File', $filename, O_RDWR|O_CREAT, 0666;
memoize 'function', SCALAR_CACHE => [HASH => \%cache];

funciona perfectamente. Para algunos métodos de almacenamiento, necesitas un poco de pegamento.

«SDBM_File» no proporciona un método «EXISTS», por lo que incluido en este paquete hay un módulo de pegamento llamado «Memoize::SDBM_File» que sí lo proporciona. Usa este en lugar de «SDBM_File» para almacenar tu tabla de caché en una base de datos «SDBM_File»:

tie my %cache => 'Memoize::SDBM_File', $filename, O_RDWR|O_CREAT, 0666;
memoize 'function', SCALAR_CACHE => [HASH => \%cache];

«NDBM_File» tiene el mismo problema y la misma solución. (Usa «Memoize::NDBM_File» en lugar de «NDBM_File».)

«Storable» no es una clase de tabla enlazada. Puedes usarla para almacenar un hash en disco y recuperarlo, pero no puedes modificar el hash mientras está en el disco. Por lo tanto, si quieres almacenar tu tabla de caché en una base de datos «Storable», usa «Memoize::Storable», que proporciona una capa de interfaz similar a un hash para «Storable». La tabla de caché está realmente en la memoria, y se carga desde tu archivo «Storable» cuando memorizas la función, y se vuelve a guardar cuando desmemorizas la función (o cuando tu programa se cierra):

tie my %cache => 'Memoize::Storable', $filename;
memoize 'function', SCALAR_CACHE => [HASH => \%cache];
tie my %cache => 'Memoize::Storable', $filename, 'nstore';
memoize 'function', SCALAR_CACHE => [HASH => \%cache];

Incluye la opción «nstore» para que la base de datos «Storable» se escriba en *orden de red*. (Ver Storable para más detalles sobre esto.)

La función «flush_cache() lanzará un error en tiempo de ejecución si el paquete enlazado no proporciona un método «CLEAR».

SOPORTE DE CADUCIDAD

Consulta Memoize::Expire, que es un módulo de extensión que añade funcionalidad de caducidad a Memoize. Si no te gustan las políticas de caducidad que implementa Memoize::Expire, es fácil escribir tu propio módulo de extensión para implementar cualquier política que desees. Memoize viene con varios ejemplos. Una gestión de caducidad que implementa una política LRU está disponible en CPAN como Memoize::ExpireLRU.

ERRORES

El conjunto de pruebas es mucho mejor, pero siempre necesita mejora.

Hay algunos problemas con el funcionamiento de «goto &f» bajo Perl multi-hilo, posiblemente debido a la *scoping* de @_. Este es un error en Perl, y hasta que se resuelva, las funciones memorizadas verán un caller() ligeramente diferente y se ejecutarán un poco más lentamente en perls multi-hilo que en perls no multi-hilo.

Algunas versiones de «DB_File» no permiten almacenar datos bajo una clave de longitud 0. Esto significa que si tienes una función «f» que hayas memorizado y la caché está en una base de datos «DB_File», el valor de «f() («f» llamada sin argumentos) no será memorizado. Si esto es un gran problema, puedes proporcionar un normalizador que anteponga «x» a cada clave.

NOM

Memoize

SYNOPIS

use Memoize;

DESCRIPTION

Memoize est un module Perl qui fournit un cache pour les appels de fonction. Il vous permet de stocker les résultats des appels de fonction et de les récupérer rapidement, ce qui peut améliorer considérablement les performances en évitant les calculs redondants.

EXEMPLE

sub foo { return 42; }

DÉTAILS

Memoize fonctionne en mettant en cache les résultats des appels de fonction. Lorsqu'une fonction est appelée, si le résultat est déjà dans le cache, il renvoie la valeur mise en cache au lieu de la recalculer. Si le résultat n'est pas dans le cache, il le calcule et le stocke pour une utilisation future.

OPTIONS

Le module fournit plusieurs options pour personnaliser son comportement, telles que la spécification du type de cache, de la politique d'expiration et du normalisateur par défaut.

AUTRES FONCTIONNALITÉS

Memoize prend en charge des fonctionnalités supplémentaires telles que la prise en charge de cache persistant et la prise en charge d'expiration, vous permettant de gérer les données du cache plus efficacement.

AVERTISSEMENTS

Certains avertissements incluent la nécessité de gérer l'invalidation du cache et le potentiel d'utilisation de la mémoire si elle n'est pas gérée correctement.

PRISE EN CHARGE DE CACHE PERSISTANT

Memoize prend en charge le stockage de cache persistant, permettant aux données mises en cache de survivre après les redémarrages du serveur.

PRISE EN CHARGE D'EXPIRATION

Memoize inclut la prise en charge de l'expiration, vous permettant de définir une limite de temps pour que les données mises en cache expirent après une certaine période.

BOGUES

Certains bogues peuvent exister, et les utilisateurs sont encouragés à les signaler aux mainteneurs.

VOIR AUSSI

Ce module est lié aux sujets suivants : cache, mémoïsation et expiration.
