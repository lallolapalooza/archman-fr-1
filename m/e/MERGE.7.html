NOM

MERGE - insère, met à jour ou supprime conditionnellement des lignes d'une table

SYNTAXE

[ WITH requete_avec [, ...] ]
MERGE INTO [ ONLY ] nom_table_cible [ * ] [ [ AS ] alias_cible ]
    USING source_donnees ON condition_jointure
    clause_quand [...]
    [ RETURNING [ WITH ( { OLD | NEW } AS alias_sortie [, ...] ) ]
                { * | expression_sortie [ [ AS ] nom_sortie ] } [, ...] ]
où source_donnees est :
    { [ ONLY ] nom_table_source [ * ] | ( requete_source ) } [ [ AS ] alias_source ]
et clause_quand est :
    { WHEN MATCHED [ AND condition ] THEN { mise_a_jour_fusion | suppression_fusion | DO NOTHING } |
      WHEN NOT MATCHED BY SOURCE [ AND condition ] THEN { mise_a_jour_fusion | suppression_fusion | DO NOTHING } |
      WHEN NOT MATCHED [ BY TARGET ] [ AND condition ] THEN { insertion_fusion | DO NOTHING } }
et insertion_fusion est :
    INSERT [( nom_colonne [, ...] )]
        [ OVERRIDING { SYSTEM | USER } VALUE ]
        { VALUES ( { expression | DEFAULT } [, ...] ) | DEFAULT VALUES }
et mise_a_jour_fusion est :
    UPDATE SET { nom_colonne = { expression | DEFAULT } |
                 ( nom_colonne [, ...] ) = [ ROW ] ( { expression | DEFAULT } [, ...] ) |
                 ( nom_colonne [, ...] ) = ( sous-SELECT )
               } [, ...]
et suppression_fusion est :
    DELETE

DESCRIPTION

MERGE effectue des actions qui modifient les lignes de la table cible identifiée par nom_table_cible, en utilisant la source_donnees. MERGE fournit une seule instruction SQL qui peut conditionnellement INSERT, UPDATE ou DELETE des lignes, une tâche qui nécessiterait autrement plusieurs instructions en langage procédural.

Premièrement, la commande MERGE effectue une jointure de la source_donnees à la table cible produisant zéro ou plusieurs lignes de modification candidates. Pour chaque ligne de modification candidate, le statut MATCHED, NOT MATCHED BY SOURCE, ou NOT MATCHED [BY TARGET] est défini une seule fois, après quoi les clauses WHEN sont évaluées dans l'ordre spécifié. Pour chaque ligne de modification candidate, la première clause évaluée comme vraie est exécutée. Pas plus d'une clause WHEN n'est exécutée pour une ligne de modification candidate.

Les actions MERGE ont le même effet que les commandes régulières UPDATE, INSERT ou DELETE du même nom. La syntaxe de ces commandes est différente, notamment qu'il n'y a pas de clause WHERE et qu'aucun nom de table n'est spécifié. Toutes les actions se réfèrent à la table cible, bien que des modifications à d'autres tables puissent être effectuées à l'aide de déclencheurs (triggers).

Lorsque DO NOTHING est spécifié, la ligne source est ignorée. Puisque les actions sont évaluées dans leur ordre spécifié, DO NOTHING peut être utile pour ignorer les lignes sources non intéressantes avant un traitement plus détaillé.

La clause RETURNING optionnelle provoque le calcul et le retour de valeurs par MERGE en fonction de chaque ligne insérée, mise à jour ou supprimée. Toute expression utilisant les colonnes de la table source ou cible, ou la fonction merge_action() peut être calculée. Par défaut, lorsqu'une action INSERT ou UPDATE est effectuée, les nouvelles valeurs des colonnes de la table cible sont utilisées, et lorsqu'un DELETE est effectué, les anciennes valeurs des colonnes de la table cible sont utilisées, mais il est également possible de demander explicitement les anciennes et nouvelles valeurs. La syntaxe de la liste RETURNING est identique à celle de la liste de sortie de SELECT.

Il n'y a pas de privilège MERGE séparé. Si vous spécifiez une action de mise à jour, vous devez avoir le privilège UPDATE sur la ou les colonnes de la table cible qui sont référencées dans la clause SET. Si vous spécifiez une action d'insertion, vous devez avoir le privilège INSERT sur la table cible. Si vous spécifiez une action de suppression, vous devez avoir le privilège DELETE sur la table cible. Si vous spécifiez une action DO NOTHING, vous devez avoir le privilège SELECT sur au moins une colonne de la table cible. Vous aurez également besoin du privilège SELECT sur toute colonne de la source_donnees et de la table cible référencée dans une condition (y compris join_condition) ou une expression. Les privilèges sont testés une fois au début de l'instruction et sont vérifiés que les clauses WHEN particulières soient exécutées ou non.

MERGE n'est pas pris en charge si la table cible est une vue matérialisée, une table étrangère, ou si elle possède des règles définies sur elle.

PARAMETRES

requete_avec

La clause WITH permet de spécifier une ou plusieurs sous-requêtes qui peuvent être référencées par nom dans la requête MERGE. Voir la Section 7.8 et SELECT(7) pour les détails. Notez que WITH RECURSIVE n'est pas pris en charge par MERGE.

nom_table_cible

Le nom (éventuellement qualifié par un schéma) de la table ou vue cible dans laquelle fusionner. Si ONLY est spécifié avant un nom de table, les lignes correspondantes sont mises à jour ou supprimées uniquement dans la table nommée. Si ONLY n'est pas spécifié, les lignes correspondantes sont également mises à jour ou supprimées dans toutes les tables héritant de la table nommée. Optionnellement, * peut être spécifié après le nom de la table pour indiquer explicitement que les tables descendantes sont incluses. Le mot-clé ONLY et l'option * n'affectent pas les actions d'insertion, qui insèrent toujours uniquement dans la table nommée.

Si nom_table_cible est une vue, elle doit soit être automatiquement mettable à jour sans aucun déclencheur INSTEAD OF, soit avoir des déclencheurs INSTEAD OF pour chaque type d'action (INSERT, UPDATE et DELETE) spécifié dans les clauses WHEN. Les vues avec des règles ne sont pas prises en charge.

alias_cible

Un nom substitut pour la table cible. Lorsqu'un alias est fourni, il masque complètement le nom réel de la table. Par exemple, étant donné MERGE INTO foo AS f, le reste de l'instruction MERGE doit faire référence à cette table comme f et non comme foo.

nom_table_source

Le nom (éventuellement qualifié par un schéma) de la table source, de la vue ou de la table de transition. Si ONLY est spécifié avant le nom de la table, les lignes correspondantes sont incluses uniquement à partir de la table nommée. Si ONLY n'est pas spécifié, les lignes correspondantes sont également incluses à partir de toutes les tables héritant de la table nommée. Optionnellement, * peut être spécifié après le nom de la table pour indiquer explicitement que les tables descendantes sont incluses.

requete_source

Une requête (instruction SELECT ou instruction VALUES) qui fournit les lignes à fusionner dans la table cible. Référez-vous à la déclaration SELECT(7) ou à la déclaration VALUES(7) pour une description de la syntaxe.

alias_source

Un nom substitut pour la source de données. Lorsqu'un alias est fourni, il masque complètement le nom réel de la table ou le fait qu'une requête ait été émise.

condition_jointure

condition_jointure est une expression résultant en une valeur booléenne (similaire à une clause WHERE) qui spécifie quelles lignes dans la source_donnees correspondent aux lignes de la table cible.

Attention
Seules les colonnes de la table cible qui tentent de correspondre aux lignes de source_donnees doivent apparaître dans condition_jointure. Les sous-expressions condition_jointure qui font référence uniquement aux colonnes de la table cible peuvent affecter l'action entreprise, souvent de manière surprenante.

Si les clauses WHEN NOT MATCHED BY SOURCE et WHEN NOT MATCHED [BY TARGET] sont toutes deux spécifiées, la commande MERGE effectuera une jointure COMPLÈTE entre source_donnees et la table cible. Pour que cela fonctionne, au moins une sous-expression condition_jointure doit utiliser un opérateur qui peut supporter une jointure par hachage (hash join), ou toutes les sous-expressions doivent utiliser des opérateurs qui peuvent supporter une jointure par tri fusion (merge join).

clause_quand

Au moins une clause WHEN est requise.

La clause WHEN peut spécifier WHEN MATCHED, WHEN NOT MATCHED BY SOURCE, ou WHEN NOT MATCHED [BY TARGET]. Notez que la norme SQL ne définit que WHEN MATCHED et WHEN NOT MATCHED (qui est défini comme aucune ligne cible correspondante). WHEN NOT MATCHED BY SOURCE est une extension à la norme SQL, tout comme l'option d'ajouter BY TARGET à WHEN NOT MATCHED, pour rendre son sens plus explicite.

Si la clause WHEN spécifie WHEN MATCHED et que la ligne de modification candidate correspond à une ligne dans la source_donnees par rapport à une ligne dans la table cible, la clause WHEN est exécutée si la condition est absente ou si elle s'évalue à vrai.

Si la clause WHEN spécifie WHEN NOT MATCHED BY SOURCE et que la ligne de modification candidate représente une ligne dans la table cible qui ne correspond pas à une ligne dans la source_donnees, la clause WHEN est exécutée si la condition est absente ou si elle s'évalue à vrai.

DATA_SOURCE

Une data_source qui ne correspond à aucune ligne dans la table cible, le bloc WHEN est exécuté si la condition est absente ou évaluée à vrai.

condition

Une expression qui retourne une valeur booléenne. Si l'expression pour un bloc WHEN retourne vrai, l'action de ce bloc est exécutée pour cette ligne.

Une condition dans un bloc WHEN MATCHED peut faire référence à des colonnes dans les deux relations source et cible. Une condition dans un bloc WHEN NOT MATCHED BY SOURCE ne peut faire référence qu'aux colonnes de la relation cible, car par définition il n'y a pas de ligne source correspondante. Une condition dans un bloc WHEN NOT MATCHED [BY TARGET] ne peut faire référence qu'aux colonnes de la relation source, car par définition il n'y a pas de ligne cible correspondante. Seuls les attributs système de la table cible sont accessibles.

merge_insert

La spécification d'une action INSERT qui insère une ligne dans la table cible. Les noms de colonnes de la table cible peuvent apparaître dans n'importe quel ordre. Si une liste de noms de colonnes n'est pas spécifiée, la valeur par défaut est toutes les colonnes de la table dans leur ordre déclaré.

Chaque colonne non présente dans la liste explicite ou implicite sera remplie avec une valeur par défaut, soit sa valeur par défaut déclarée, soit NULL s'il n'y en a pas.

Si la table cible est une table partitionnée, chaque ligne est dirigée vers la partition appropriée et insérée dans celle-ci. Si la table cible est une partition, une erreur se produit si une ligne d'entrée viole la contrainte de partition.

Les noms de colonnes ne peuvent pas être spécifiés plus d'une fois. Les actions INSERT ne peuvent pas contenir de sous-requêtes.

Une seule instruction VALUES peut être spécifiée. L'instruction VALUES ne peut faire référence qu'aux colonnes de la relation source, car par définition il n'y a pas de ligne cible correspondante.

merge_update

La spécification d'une action UPDATE qui met à jour la ligne actuelle de la table cible. Les noms de colonnes ne peuvent pas être spécifiés plus d'une fois.

Ni un nom de table ni une clause WHERE ne sont autorisés.

merge_delete

Spécifie une action DELETE qui supprime la ligne actuelle de la table cible. N'incluez pas le nom de la table ou toute autre clause, car cela serait effectué normalement avec une instruction DELETE(7).

column_name

Le nom d'une colonne de la table cible. Le nom de la colonne peut être qualifié par un nom de sous-champ ou un sous-indice, si nécessaire. (L'insertion uniquement dans certains champs d'une colonne composite laisse les autres champs nuls.) N'incluez pas le nom de la table dans la spécification d'une colonne cible.

OVERRIDING SYSTEM VALUE

Sans cette clause, il est une erreur de spécifier une valeur explicite (autre que DEFAULT) pour une colonne définie comme GENERATED ALWAYS. Cette clause remplace cette restriction.

OVERRIDING USER VALUE

Si cette clause est spécifiée, toute valeur fournie pour les colonnes définies comme GENERATED BY DEFAULT est ignorée et les valeurs générées par la séquence par défaut sont appliquées.

DEFAULT VALUES

Toutes les colonnes sont remplies avec leurs valeurs par défaut. (L'utilisation d'une clause OVERRIDING n'est pas autorisée dans ce format.)

expression

Une expression à attribuer à la colonne. Si elle est utilisée dans un bloc WHEN MATCHED, l'expression peut utiliser des valeurs de la ligne d'origine dans la table cible et des valeurs de la ligne data_source. Si elle est utilisée dans un bloc WHEN NOT MATCHED BY SOURCE, l'expression ne peut utiliser que des valeurs de la ligne d'origine dans la table cible. Si elle est utilisée dans un bloc WHEN NOT MATCHED [BY TARGET], l'expression ne peut utiliser que des valeurs de la ligne data_source.

DEFAULT

Définit la colonne à sa valeur par défaut (qui sera NULL si aucune expression de valeur par défaut n'a été explicitement attribuée).

sub-SELECT

Une sous-requête SELECT qui génère autant de colonnes de sortie que spécifié dans la liste de colonnes précédente. La sous-requête doit générer au maximum une seule ligne. Si elle génère une ligne, ses valeurs de colonne sont attribuées aux colonnes cibles ; si elle ne génère aucune ligne, des valeurs NULL sont attribuées aux colonnes cibles. Si elle est utilisée dans un bloc WHEN MATCHED, la sous-requête peut faire référence à des valeurs de la ligne d'origine dans la table cible et à des valeurs de la ligne data_source. Si elle est utilisée dans un bloc WHEN NOT MATCHED BY SOURCE, la sous-requête ne peut faire référence qu'à des valeurs de la ligne d'origine dans la table cible.

output_alias

Un nom optionnel qui remplace OLD ou NEW dans la liste RETURNING.

Par défaut, les anciennes valeurs de la table cible peuvent être retournées en écrivant OLD.column_name ou OLD.*, et les nouvelles valeurs peuvent être retournées en écrivant NEW.column_name ou NEW.*. Lorsqu'un alias est fourni, ces noms sont masqués et les enregistrements anciens ou nouveaux doivent être référencés en utilisant l'alias. Par exemple, RETURNING WITH (OLD AS o, NEW AS n) ou o.*, n.*.

output_expression

Une expression qui est calculée et retournée par l'instruction MERGE après chaque ligne modifiée (insérée, mise à jour ou supprimée). L'expression peut utiliser n'importe quelle colonne de la table source ou de la table cible, ou la fonction merge_action() pour retourner des informations supplémentaires sur l'action exécutée.

Écrire * retourne toutes les colonnes de la table source, suivies de toutes les colonnes de la table cible. Cela entraîne généralement un grand doublon, car les tables source et cible ont souvent de nombreuses colonnes en commun. Vous pouvez éviter cela en spécifiant * avec le nom ou l'alias de la table source ou de la table cible.

Un nom de colonne ou * peut également être qualifié avec OLD ou NEW, ou avec l'alias de sortie correspondant pour OLD ou NEW, pour retourner les anciennes ou nouvelles valeurs de la table cible. Un nom de colonne non qualifié de la table cible, ou une colonne de la table cible ou * qualifiée avec le nom ou l'alias de la table cible, retourne les nouvelles valeurs pour les actions INSERT et UPDATE, et les anciennes valeurs pour les actions DELETE.

output_name

Un nom pour une colonne retournée.

SORTIES

Après une complétion réussie, une instruction MERGE retourne un tag de commande de la forme

MERGE total_count

Le total_count est le nombre total de lignes modifiées (insérées, mises à jour ou supprimées). Si total_count est 0, aucune ligne n'a été modifiée.

Si l'instruction MERGE contient une clause RETURNING, le résultat sera similaire à celui d'une instruction SELECT contenant les colonnes et les valeurs définies dans la liste RETURNING, calculées sur les lignes insérées, mises à jour ou supprimées par l'instruction.

NOTES

Les étapes suivantes sont effectuées lors de l'exécution de MERGE.

1. Exécute tous les déclencheurs BEFORE STATEMENT pour toutes les actions spécifiées, indépendamment de si leurs clauses WHEN correspondent.
2. Effectue une jointure de la table source à la table cible. La requête résultante sera normalement optimisée et produira un ensemble de lignes candidates pour la modification. Pour chaque ligne candidate de modification,
1. Évalue si chaque ligne est MATCHED, NOT MATCHED BY SOURCE ou NOT MATCHED [BY TARGET].
2. Teste chaque clause WHEN dans l'ordre spécifié jusqu'à ce qu'une retourne vrai.
3. Lorsqu'une clause retourne vrai, les actions suivantes sont exécutées :
1. Exécute tous les déclencheurs BEFORE ROW qui sont activés pour le type d'événement de l'action.
2. Exécute l'action spécifiée, en invoquant toutes les contraintes de la table cible.
3. Exécute tous les déclencheurs AFTER ROW qui sont activés pour le type d'événement de l'action.

Si la relation cible est une vue avec des déclencheurs INSTEAD OF ROW pour le type d'événement de l'action, ces déclencheurs seront utilisés pour effectuer l'action à la place.

3. Exécute tous les déclencheurs AFTER STATEMENT pour les actions spécifiées, indépendamment de si elles se produisent ou non. Ceci est similaire au comportement d'une instruction UPDATE qui ne modifie aucune ligne.

En résumé, les déclencheurs de type événement (par exemple, INSERT) sont déclenchés chaque fois qu'une action de ce type est spécifiée. En revanche, les déclencheurs de niveau ligne sont déclenchés uniquement pour le type d'événement spécifique en cours d'exécution. Ainsi, une instruction MERGE pourrait déclencher des déclencheurs de type événement UPDATE et INSERT, même si seuls des déclencheurs de niveau ligne UPDATE ont été déclenchés.

Vous devez vous assurer que la jointure produit au maximum une ligne candidate de modification par ligne cible. En d'autres termes, une ligne cible ne doit pas correspondre à plus d'une ligne source. Si c'est le cas, seule l'une des lignes candidates de modification sera utilisée pour modifier la ligne cible ; les tentatives ultérieures entraîneront une erreur. Cela peut également se produire si les déclencheurs de niveau ligne modifient la table cible et que les lignes modifiées sont ensuite modifiées par MERGE. Si l'action répétée est INSERT, cela entraînera une violation d'unicité, tandis qu'une action répétée UPDATE ou DELETE entraînera une violation de cardinalité ; cette dernière est requise par la norme SQL. Cette différence contraste avec le comportement précédent des jointures dans les instructions UPDATE et DELETE de PostgreSQL, où les tentatives ultérieures sont ignorées.

Si une clause WHEN omet une sous-clause AND, elle devient la clause finalement atteignable de ce type (MATCHED, NOT MATCHED BY SOURCE, ou NOT MATCHED [BY TARGET]). Si une clause WHEN de ce type est spécifiée plus tard, elle sera probablement inaccessible et une erreur sera générée. Si aucune clause finalement atteignable de l'un des types n'est spécifiée, aucune action ne peut être effectuée pour une ligne candidate de modification.

L'ordre dans lequel les lignes sont générées à partir de la source est indéterminé par défaut. Une source_query peut être utilisée pour spécifier un ordre cohérent, si nécessaire, ce qui pourrait aider à éviter les blocages entre transactions concurrentes.

Lorsque MERGE est exécuté simultanément avec d'autres commandes qui modifient la table cible, les règles d'isolation des transactions s'appliquent normalement ; voir la section 13.2 pour une explication du comportement à chaque niveau d'isolation. Vous pourriez également envisager d'utiliser INSERT ... ON CONFLICT comme une instruction alternative qui offre la possibilité d'exécuter un UPDATE si un INSERT concurrent se produit. Il existe des différences et des restrictions entre les deux instructions et elles ne sont pas interchangeables.

EXEMPLES

Effectuer la maintenance sur customer_accounts en fonction des nouvelles recent_transactions.

MERGE INTO customer_account ca
USING recent_transactions t
ON t.customer_id = ca.customer_id
WHEN MATCHED THEN
  UPDATE
E SET balance = balance + transaction_value WHEN NOT MATCHED THEN INSERT (customer_id, balance) VALUES (t.customer_id, t.transaction_value);

Essayer d'insérer un nouvel article en stock avec la quantité de stock. Si l'article existe déjà, mettre à jour le compte de stock de l'article existant. Ne pas autoriser les entrées avec un stock nul. Retourner les détails de toutes les modifications effectuées.

MERGE INTO wines w
USING wine_stock_changes s
ON s.winename = w.winename
WHEN NOT MATCHED AND s.stock_delta > 0 THEN
  INSERT VALUES(s.winename, s.stock_delta)
WHEN MATCHED AND w.stock + s.stock_delta > 0 THEN
  UPDATE SET stock = w.stock + s.stock_delta
WHEN MATCHED THEN
  DELETE
RETURNING merge_action(), w.winename, old.stock AS old_stock, new.stock AS new_stock;

La table wine_stock_changes peut être, par exemple, une table temporaire récemment chargée dans la base de données.

Mettre à jour wines en fonction d'une liste de vins de remplacement, insérer des lignes pour tout nouveau stock, mettre à jour les entrées de stock modifiées et supprimer tous les vins qui ne sont pas présents dans la nouvelle liste.

MERGE INTO wines w
USING new_wine_list s
ON s.winename = w.winename
WHEN NOT MATCHED BY TARGET THEN
  INSERT VALUES(s.winename, s.stock)
WHEN MATCHED AND w.stock != s.stock THEN
  UPDATE SET stock = s.stock
WHEN NOT MATCHED BY SOURCE THEN
  DELETE;

COMPATIBILITÉ

Cette commande est conforme à la norme SQL.

La clause WITH, les qualificateurs BY SOURCE et BY TARGET pour WHEN NOT MATCHED, l'action DO NOTHING, et la clause RETURNING sont des extensions à la norme SQL.
