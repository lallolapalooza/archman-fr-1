META(5) Manuel des formats de fichiers META(5)

NOM

META - [Fichier spécifiant les métadonnées des paquets OCaml]

GRAMMAIRE

         fichier_meta ::= entree*
            entree ::= assignation | addition | sous_paquet
         sous_paquet ::= "package" nom_paquet '(' fichier_meta ')'
         assignation ::= nom_variable [ predicats_formels ] '='  valeur
         addition ::= nom_variable [ predicats_formels ] '+=' valeur
predicats_formels ::= '(' predicat_formel { ',' predicat_formel } ')'
            nom_variable ::= nom
 predicat_formel ::= nom | '-' nom
             nom ::= [ 'A'-'Z' 'a'-'z' '0'-'9' '_' '.' ]+
          nom_paquet ::= '"' (caractere mais pas '.')* '"'
            valeur ::= '"' caractere* '"'

DESCRIPTION

Si un répertoire de paquet contient un fichier au nom fixe "META", il est interprété comme décrit ici. Le fichier est une séquence d'entrées suivant la grammaire donnée ; chaque entrée définit une variable sous une certaine condition donnée par la liste des prédicats formels, ou elle introduit un sous-paquet.

Il y a une liste de variables prédéfinies et une liste de prédicats standards. Ces variables définissent : les paquets requis, la description, les informations de version, les répertoires, les fichiers archive, et les options du linker. Les prédicats dénotent les circonstances de l'application des variables : si le bytecode ou le compilateur natif est utilisé, s'il y a une boucle de dépannage compilée, des détails sur l'exécution multi-thread, des détails sur le profilage.

DÉTAILS DU FORMAT DE FICHIER

Le fichier consiste en une séquence d'entrées qui doivent être formées selon la grammaire. Les jetons lexicaux sont des noms, des valeurs, et de la ponctuation comme '(', ',' et ainsi de suite. Notez que les sauts de ligne ne jouent pas de rôle spécial, c'est-à-dire qu'une définition d'entrée peut être donnée sur plusieurs lignes, ou plusieurs définitions peuvent apparaître sur une seule ligne. Il peut y avoir des commentaires qui commencent par '#' et s'étendent jusqu'à la fin de la ligne.

Les noms sont des séquences des caractères A-Z, a-z, 0-9, ou _. Les noms contenant des lettres majuscules et les noms commençant par des chiffres sont autorisés mais non recommandés.

Les valeurs sont entourées de guillemets doubles. Les valeurs peuvent contenir n'importe quel caractère. Les caractères " et \ doivent être précédés de barres obliques inverses.

Les noms de paquets ne doivent pas contenir le caractère '.' car il est utilisé comme délimiteur de noms composés.

PAQUETS PRINCIPAUX ET SOUS-PAQUETS

Les affectations et additions de variables les plus externes appartiennent au paquet principal. Le nom du paquet principal n'est pas défini dans META ; c'est soit le nom du répertoire contenant META, soit le suffixe du fichier META (si le nom du fichier META est formé comme META.nom).

Le mot-clé package démarre la définition d'un sous-paquet. Il ne doit pas y avoir deux définitions de ce type avec le même nom. Dans les parenthèses, les affectations et additions de variables se réfèrent au sous-paquet. Il est autorisé qu'un sous-paquet contienne d'autres sous-paquets.

Le nom du paquet suivant package est le nom local par rapport au paquet principal, c'est-à-dire que le nom du paquet principal n'est pas mentionné. Partout ailleurs, cependant, le sous-paquet doit être préfixé par le nom du paquet contenant, séparé par un '.'.

Les sous-paquets sont indépendants du paquet contenant, sauf que le sous-paquet pointe vers le même répertoire d'installation que le paquet contenant (c'est-à-dire que l'emplacement du répertoire d'installation est hérité du paquet contenant).

SEMANTIQUE DES DÉFINITIONS DE VARIABLES

Afin de déterminer la valeur d'une variable, d'abord toutes les affectations sont inspectées, et l'affectation la plus spécifique est prise (s'il n'y en a pas, la chaîne vide sera prise comme valeur). Dans un second temps, toutes les additions sont parcourues une par une dans l'ordre où elles apparaissent dans le fichier, et les valeurs de toutes les additions correspondantes sont ajoutées à la valeur courante. Ci-après, il est précisé quelles affectations sont les plus spécifiques, quelles additions correspondent réellement, et à quoi ressemblent les détails de l'addition de valeur.

L'affectation la plus spécifique est sélectionnée sur un ensemble de prédicats réels, c'est-à-dire l'ensemble des prédicats supposés vrais. Les prédicats apparaissant dans les définitions d'affectations et d'additions sont appelés prédicats formels. Ils peuvent être positifs ou négatifs ; ces derniers sont préfixés par un signe '-'. Afin de déterminer la valeur après l'évaluation des affectations, les règles suivantes s'appliquent :

Une affectation ne peut être utilisée que si tous les prédicats formels positifs sont inclus dans l'ensemble des prédicats réels, et si tous les prédicats formels négatifs ne sont pas inclus dans l'ensemble des prédicats réels. Une telle affectation est dite applicable. S'il n'y a pas d'affectation de ce type, la variable n'aura pas de valeur.
S'il y a plus d'une affectation applicable, la définition avec le plus grand nombre de prédicats formels est sélectionnée.
S'il y a encore plus d'une affectation applicable, à la fois applicable et avec un nombre maximal de prédicats formels, la définition qui est définie en premier est sélectionnée.

Une addition correspond lorsqu'elle satisfait tous les prédicats formels positifs qui sont inclus dans l'ensemble des prédicats réels, et tous les prédicats formels négatifs qui ne sont pas inclus.

La valeur d'une addition est ajoutée à la valeur courante avec un espace blanc implicite comme séparateur.

VARIABLES

Il y a un ensemble de variables ayant une signification prédéfinie :

La variable "directory" redéfinit l'emplacement du répertoire du paquet. Normalement, le fichier META est le premier fichier lu dans le répertoire du paquet, et avant que tout autre fichier ne soit lu, la variable "directory" est évaluée afin de voir si le répertoire du paquet doit être modifié. La valeur de la variable "directory" est déterminée avec un ensemble vide de prédicats réels. La valeur doit être soit : un nom de chemin absolu du répertoire alternatif, soit un nom de chemin relatif au répertoire stdlib d'OCaml (écrit "+chemin"), soit un nom de chemin relatif normal (sans syntaxe spéciale). Dans ce dernier cas, l'interprétation dépend de s'il est contenu dans un paquet principal ou sous-paquet, et si le layout de dépôt standard ou le layout alternatif est en vigueur (voir site-lib pour ces termes). Pour un paquet principal en layout standard, le répertoire de base est le répertoire contenant physiquement le fichier META, et le chemin relatif est interprété par rapport à ce répertoire de base. Pour un paquet principal en layout alternatif, le répertoire de base est le répertoire contenant physiquement les fichiers META.pkg. Le répertoire de base pour les sous-paquets est le répertoire du paquet contenant. (Dans le cas où une définition de sous-paquet n'a pas de réglage "directory", le sous-paquet hérite simplement du répertoire du paquet contenant. En écrivant une directive "directory" on peut changer à nouveau cet emplacement.)
La variable "requires" spécifie la liste des paquets requis. Les noms des paquets doivent être séparés par des espaces blancs et/ou des virgules. Les noms doivent être complètement qualifiés (c'est-à-dire lorsqu'ils font référence à un sous-paquet, les noms de tous les paquets contenant doivent être préfixés, séparés par '.').
La variable "description" peut inclure une brève description du paquet (affichée par ocamlfind list).
La variable "version" spécifie la chaîne de version.
La variable "archive" spécifie la liste des fichiers archive. Ces fichiers doivent être donnés soit comme (1) plai

Le nom de la variable « plugin » spécifie les fichiers de plugin du paquet. Ceux-ci peuvent être chargés dynamiquement avec le module Fl_dynload. Les fichiers de plugin peuvent avoir les suffixes « .cmo », « .cma » ou « .cmxs ».
La variable « linkopts » spécifie les options de liaison supplémentaires.
La variable « error » peut être utilisée pour signaler des conditions d'erreur. Lorsque cette variable est applicable, le compilateur ocaml arrête son exécution et un message d'erreur est imprimé. Le message est la valeur de la variable.
La variable « warning » peut être utilisée pour signaler des avertissements. Lorsque cette variable est applicable, l'avertissement est imprimé, mais la compilation continue. Le message est la valeur de la variable.
La variable « exists_if » peut être utilisée pour désactiver des sous-paquets. La valeur de « exists_if » est un fichier ; le sous-paquet est caché si ce fichier n'existe pas. Plusieurs fichiers peuvent également être énumérés, et le sous-paquet est caché si aucun d'entre eux n'existe.
La variable « ppx » est une commande ajoutée à l'appel du compilateur via l'option -ppx (disponible depuis OCaml-4.01). Si la commande est relative au répertoire courant (par exemple, ./cmd), la commande est attendue dans le répertoire du paquet. Les formes spéciales définies pour le cas « archive » sont également disponibles (par exemple, @otherpkg/cmd). Des arguments supplémentaires peuvent être spécifiés dans l'appel de ocamlfind avec l'option -ppxopt ou la variable « ppxopt ».
La variable « ppxopt » est un ensemble d'options ajoutées à l'appel du rewriter ppx. Le contenu de la variable se compose d'une ou plusieurs parties séparées par des espaces blancs. Chaque partie se compose de sous-parties séparées par des virgules ; la première sous-partie indique le paquet contenant l'appel du rewriter ppx, et les parties restantes indiquent les options à ajouter. Si l'option est un chemin relatif au répertoire courant (par exemple, ./foo.cma), le chemin est développé relativement au répertoire du paquet. Les formes spéciales définies pour « archive » sont également disponibles (par exemple, @otherpkg/foo.cma).

Il est possible de définir des variables supplémentaires, mais aucun logiciel ne les interprète actuellement.

PRÉDICATS

Il existe une liste de prédicats standard :

Le prédicat « byte » signifie que le compilateur bytecode est utilisé.
Le prédicat « native » signifie que le compilateur natif est utilisé.
Le prédicat « toploop » signifie que le toploop est disponible dans le programme lié. Il est défini uniquement lorsque le toploop est en cours d'exécution, pas lors de sa génération.
Le prédicat « create_toploop » signifie qu'un toploop est créé (en utilisant ocamlmktop).
Le prédicat « mt » signifie que le programme est multi-threadé.
Le prédicat « mt_posix » signifie que, si « mt » est défini, les bibliothèques POSIX sont utilisées pour implémenter les threads.
Le prédicat « mt_vm » signifie que, si « mt » est défini, les bibliothèques basées sur la VM sont utilisées pour implémenter les threads.
Le prédicat « gprof » signifie que, si « native » est défini, le programme est compilé pour le profilage.
Le prédicat « autolink » signifie que ocamlc peut/fait la liaison automatique.
Le prédicat « preprocessor » signifie que les variables META sont analysées pour les options du préprocesseur.
Le prédicat « syntax » signifie que l'option -syntax est présente sur la ligne de commande.

Héritage : Le prédicat « plugin » a pu être utilisé dans certaines versions de findlib pour sélectionner des fichiers cmxs au lieu de cmxa. Cette fonctionnalité est toujours possible mais il est recommandé de l'éviter.

En plus de ces prédicats, il existe des prédicats de paquet pour chaque paquet qui est finalement sélectionné. En fait, ces types de prédicats ne doivent pas être utilisés pour sélectionner les variables « directory » et « requires », mais ils sont valides pour les autres variables. Les prédicats de paquet ont la forme « pkg_ » suivie du nom du paquet (avec l'extension complètement qualifiée).
