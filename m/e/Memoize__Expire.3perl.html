Memoize::Expire(3perl) Guide de référence du programmeur Perl Memoize::Expire(3perl)

NOM

Memoize::Expire - Module plug-in pour l'expiration automatique des valeurs mémoïsées

SYNOPSIS

use Memoize;
use Memoize::Expire;
tie my %cache => 'Memoize::Expire',
                   LIFETIME => $lifetime,    # En secondes
                   NUM_USES => $n_uses;
memoize 'function', SCALAR_CACHE => [HASH => \%cache ];

DESCRIPTION

Memoize::Expire est un module plug-in pour Memoize. Il permet aux valeurs mises en cache des fonctions mémoïsées d'expirer automatiquement. Ce manuel suppose que vous êtes déjà familiarisé avec le module Memoize. Sinon, vous devriez étudier ce manuel attentivement d'abord, en accordant une attention particulière à la fonctionnalité HASH.

Memoize::Expire est une couche logicielle que vous pouvez insérer entre Memoize lui-même et le package sous-jacent qui implémente le cache. La couche présente une variable de hachage dont les valeurs expirent lorsqu'elles deviennent trop anciennes, ont été utilisées trop souvent, ou les deux. Vous indiquez à "Memoize" d'utiliser ce hachage oubliant comme cache au lieu du défaut, qui est un hachage ordinaire.

Pour spécifier un délai d'expiration en temps réel, fournissez l'option "LIFETIME" avec une valeur numérique. Les données mises en cache expireront après ce nombre de secondes, et seront récupérées à nouveau lorsqu'elles auront expiré. Lorsqu'un élément de données est récupéré à nouveau, sa durée de vie est réinitialisée.

Si vous spécifiez "NUM_USES" avec un argument de n, alors chaque élément de données mis en cache sera jeté et récupéré à nouveau après la n-ième fois que vous y accédez. Lorsqu'un élément de données est récupéré à nouveau, son nombre d'utilisations est réinitialisé.

Si vous spécifiez les deux arguments, les données seront jetées du cache lorsque l'une ou l'autre condition d'expiration sera remplie.

Memoize::Expire utilise un hachage réel en interne pour stocker les données mises en cache. Vous pouvez utiliser l'option "HASH" à Memoize::Expire pour fournir un hachage lié à la place du hachage ordinaire que Memoize::Expire utilisera normalement. Vous pouvez utiliser cette fonctionnalité pour ajouter Memoize::Expire comme couche entre un hachage de disque persistant et Memoize. Si vous faites cela, vous obtenez un cache de disque persistant dont les entrées expirent automatiquement. Par exemple :

#   Memoize
#      |
#   Memoize::Expire  applique la politique d'expiration des données
#      |
#   DB_File  implémente la persistance des données dans un fichier disque
#      |
#   Fichier disque
use Memoize;
use Memoize::Expire;
use DB_File;
# Configurer la persistance
tie my %disk_cache => 'DB_File', $filename, O_CREAT|O_RDWR, 0666];
# Configurer la politique d'expiration, en fournissant le hachage persistant comme cible
tie my %cache => 'Memoize::Expire', 
                   LIFETIME => $lifetime,    # En secondes
                   NUM_USES => $n_uses,
                   HASH => \%disk_cache; 
# Configurer la mémoïsation, en fournissant le hachage persistant expirable pour le cache
memoize 'function', SCALAR_CACHE => [ HASH => \%cache ];

INTERFACE

Il n'y a rien de spécial à propos de Memoize::Expire. C'est juste un exemple. Si la politique qu'il implémente ne vous plaît pas, vous êtes libre d'écrire votre propre module de politique d'expiration qui implémente la politique que vous désirez. Voici comment faire. Supposons que votre module s'appellera MyExpirePolicy.

Résumé court : Vous devez créer un package qui définit quatre méthodes :

TIEHASH
Construit et retourne l'objet cache.
EXISTS
Étant donné un argument de fonction, la valeur de fonction correspondante est-elle dans le cache, et si oui, est-elle assez récente pour être utilisée ?
FETCH
Étant donné un argument de fonction, recherche la valeur de fonction correspondante dans le cache et la retourne.
STORE
Étant donné un argument de fonction et la valeur de fonction correspondante, les stocke dans le cache.
CLEAR
(Optionnel.) Vide complètement le cache.

L'utilisateur qui souhaite que le cache de mémoïsation soit expiré selon votre politique dira ainsi en écrivant

tie my %cache => 'MyExpirePolicy', arguments...;
memoize 'function', SCALAR_CACHE => [HASH => \%cache];

Cela invoquera "MyExpirePolicy->TIEHASH(arguments)". MyExpirePolicy::TIEHASH doit faire ce qui est approprié pour configurer le cache, et il doit retourner l'objet cache à l'appelant.

Par exemple, MyExpirePolicy::TIEHASH pourrait créer un objet qui contient un hachage Perl régulier (qu'il utilisera pour stocker les valeurs mises en cache) et des informations supplémentaires sur les arguments, leur ancienneté, etc. Appelons cet objet "C".

Lorsque Memoize a besoin de vérifier si une entrée est déjà dans le cache, il invoquera "C->EXISTS(clé)". "clé" est l'argument de fonction normalisé. MyExpirePolicy::EXISTS doit retourner 0 si la clé n'est pas dans le cache, ou si elle a expiré, et 1 si une valeur non expirée est dans le cache. Il ne doit *pas* retourner "undef", car il y a un bug dans certaines versions de Perl qui provoquera un FETCH erroné si la méthode EXISTS retourne "undef".

Si votre fonction EXISTS retourne vrai, Memoize essaiera de récupérer la valeur mise en cache en invoquant "C->FETCH(clé)". MyExpirePolicy::FETCH doit retourner la valeur mise en cache. Sinon, Memoize appellera la fonction mémoïsée pour calculer la valeur appropriée, et la stockera dans le cache en appelant "C->STORE(clé, valeur)".

Voici un exemple très bref d'un module de politique qui expire chaque élément de cache après dix secondes.

package Memoize::TenSecondExpire;
sub TIEHASH {
  my ($package, %args) = @_;
  my $cache = $args{HASH} || {};
  bless $cache => $package;
}
sub EXISTS {
  my ($cache, $key) = @_;
  if (exists $cache->{$key} && 
      $cache->{$key}{EXPIRE_TIME} > time) {
    return 1
  } else {
    return 0;  # Ne PAS retourner undef ici
  }
}
sub FETCH {
  my ($cache, $key) = @_;
  return $cache->{$key}{VALUE};
}
sub STORE {
  my ($cache, $key, $newvalue) = @_;
  $cache->{$key}{VALUE} = $newvalue;
  $cache->{$key}{EXPIRE_TIME} = time + 10;
}

Pour utiliser cette politique d'expiration, l'utilisateur dirait

use Memoize;
tie my %cache10sec => 'Memoize::TenSecondExpire';
memoize 'function', SCALAR_CACHE => [HASH => \%cache10sec];

Memoize appellerait alors "function" chaque fois qu'une valeur mise en cache serait complètement absente ou aurait plus de dix secondes.

Vous devriez toujours prendre en charge un argument "HASH" pour "TIEHASH" qui lie le cache sous-jacent afin que l'utilisateur puisse spécifier que le cache est également persistant ou qu'il a d'autres sémantiques intéressantes. L'exemple ci-dessus démontre comment faire, tout comme "Memoize::Expire".

Un autre exemple de module, Memoize::Saves, est disponible dans une distribution séparée sur CPAN. Il implémente une politique qui vous permet de spécifier que certaines valeurs de fonction seront toujours récupérées à nouveau. Voir la documentation pour plus de détails.

ALTERNATIVES

Brent Powers a un module Memoize::ExpireLRU qui a été conçu pour fonctionner avec Memoize et fournit l'expiration des données les moins récemment utilisées. Le cache est maintenu à un nombre fixe d'entrées, et lorsque de nouvelles données arrivent, les données les moins récemment utilisées sont expirées.

Le module Tie::Cache de Joshua Chamas pourrait être utile en tant que gestionnaire d'expiration. (Si vous essayez cela, faites-moi savoir comment cela fonctionne.)

Si vous développez des gestionnaires d'expiration utiles qui, selon vous, devraient être distribués avec Memoize, veuillez m'en informer.

CAVEATS

Ce module est expérimental et peut contenir des bugs. Veuillez signaler les bugs à l'adresse ci-dessous.

Le nombre d'utilisations est stocké sous forme d'entier non signé de 16 bits, il ne peut donc pas dépasser 65535.

En raison de la granularité de l'horloge, les heures d'expiration peuvent survenir jusqu'à une seconde plus tôt que prévu. Par exemple, supposez que vous stockiez une valeur avec une durée de vie de dix secondes, et que vous la stockiez à 12:00:00.998 un jour donné. Memoize regardera l'horloge et verra 12:00:00. Neuf virgule zéro une secondes plus tard, à 12:00:10.008, vous essayez de la relire. Memoize regardera l'horloge et verra 12:
