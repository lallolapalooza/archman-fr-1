MRO::Compat(3) Documentation Perl fournie par l'utilisateur MRO::Compat(3)

NOM

MRO::Compat - compatibilité de l'interface mro::* pour les Perl < 5.9.5

SYNOPIS

package PPP;      use base qw/Exporter/;
package X;        use base qw/PPP/;
package Y;        use base qw/PPP/;
package Z;        use base qw/PPP/;
package FooClass; use base qw/X Y Z/;
package main;
use MRO::Compat;
my $linear = mro::get_linear_isa('FooClass');
print join(q{, }, @$linear);
# Affiche : FooClass, X, PPP, Exporter, Y, Z

DESCRIPTION

L'espace de noms "mro" fournit plusieurs utilitaires pour gérer l'ordre de résolution des méthodes et la mise en cache des méthodes en général dans les versions de Perl 5.9.5 et supérieures.

Ce module fournit ces interfaces pour les versions antérieures de Perl (jusqu'à 5.6.0 au moins).

Utiliser ce module sur des versions 5.9.5+ est sans danger et n'a aucun effet. Autrement dit, le code qui utilise correctement MRO::Compat fonctionnera sans modification sur les anciennes versions de Perl comme sur les versions 5.9.5+.

Si vous écrivez un logiciel qui souhaite utiliser les parties des interfaces mro:: de 5.9.5+ supportées ici, et que vous souhaitez la compatibilité avec les anciennes versions de Perl, ce module est fait pour vous.

Certaines parties de ce code fonctionneront mieux et/ou plus rapidement avec Class::C3::XS installé (qui est une prérequis optionnel de Class::C3, qui est lui-même un prérequis de ce paquet), mais ce n'est pas une obligation.

Ce module n'exporte jamais de fonctions. Tous les appels doivent être entièrement qualifiés avec le préfixe "mro::".

La documentation de l'interface ici sert uniquement de référence rapide sur ce que fait fondamentalement la fonction et sur les différences entre MRO::Compat et les versions 5.9.5+ à surveiller. Les principales documentations de mro de 5.9.5 sont les véritables documentations de l'interface et contiennent beaucoup d'autres informations utiles.

Fonctions

mro::get_linear_isa($classname[, $type])

Retourne une référence de tableau qui est l'"ISA" linéarisée de la classe donnée. Utilise l'ordre MRO actuellement en vigueur pour cette classe par défaut, ou l'ordre MRO donné (soit "c3" soit "dfs" si spécifié comme $type).

L'ISA linéarisée d'une classe est une liste ordonnée unique de toutes les classes qui seraient visitées lors de la résolution d'une méthode sur la classe donnée, en commençant par elle-même. Elle n'inclut pas d'entrées dupliquées.

Notez que "UNIVERSAL" (et tous les membres de l'ordre MRO de "UNIVERSAL") ne font pas partie de l'ordre MRO d'une classe, même si toutes les classes héritent implicitement de méthodes de "UNIVERSAL" et de ses parents.

mro::import

Ceci permet les syntaxes "use mro 'dfs'" et "use mro 'c3'", à condition que vous ayez d'abord utilisé "use MRO::Compat". Veuillez consulter la section "UTILISATION DE C3" pour plus de détails.

mro::set_mro($classname, $type)

Définit l'ordre MRO de $classname à l'un des types "dfs" ou "c3". Veuillez consulter la section "UTILISATION DE C3" pour plus de détails.

mro::get_mro($classname)

Retourne l'ordre MRO de la classe donnée (soit "c3", soit "dfs").

Il considère toute classe utilisant Class::C3 comme ayant un ordre MRO C3, même avant que Class::C3::initialize() ne soit appelée.

mro::get_isarev($classname)

Retourne une référence de tableau des classes qui sont des sous-classes de la classe nommée donnée. En d'autres termes, les classes dont la hiérarchie @ISA nous inclut, quelle que soit la profondeur.

Ceci est beaucoup plus lent sur les versions de Perl antérieures à 5.9.5 avec MRO::Compat que sur les versions 5.9.5+, car il doit rechercher dans tout l'espace de noms des packages.

mro::is_universal($classname)

Retourne un état booléen indiquant si la classe nommée donnée est "UNIVERSAL" elle-même, ou l'un des parents de "UNIVERSAL" par héritage @ISA.

Toute classe pour laquelle cette fonction renvoie vrai est "universelle" dans le sens où toutes les classes héritent potentiellement de méthodes de celle-ci.

mro::invalidate_all_method_caches

Incrémente "PL_sub_generation", ce qui invalide la mise en cache des méthodes dans tous les packages.

Veuillez noter que ceci est rarement nécessaire, sauf si vous traitez une situation qui est connue pour confondre la mise en cache des méthodes de Perl.

mro::method_changed_in($classname)

Invalide le cache de méthodes de toutes les classes dépendant de la classe donnée. Dans MRO::Compat sur les versions de Perl antérieures à 5.9.5, c'est un alias pour "mro::invalidate_all_method_caches" ci-dessus, car les versions de Perl antérieures à 5.9.5 n'ont aucun autre moyen de le faire. Il continuera à imposer l'exigence que vous lui passiez un nom de classe, pour des raisons de compatibilité.

Veuillez noter que ceci est rarement nécessaire, sauf si vous traitez une situation qui est connue pour confondre la mise en cache des méthodes de Perl.

mro::get_pkg_gen($classname)

Retourne un entier qui est incrémenté chaque fois qu'une méthode locale ou la @ISA du package donné change sur Perl 5.9.5+. Sur les versions de Perl antérieures avec ce module MRO::Compat, il s'incrémentera probablement beaucoup plus souvent que nécessaire.

UTILISATION DE C3

Bien que ce module rende disponibles les syntaxes "use mro 'c3'" et "mro::set_mro("Foo", 'c3')" de 5.9.5+ sur les anciennes versions de Perl, il le fait simplement en passant le travail à Class::C3.

Il ne vous dispense pas de la nécessité d'appeler Class::C3::initialize(), Class::C3::reinitialize(), et/ou Class::C3::uninitialize() aux moments appropriés, comme documenté dans la documentation de Class::C3. Ces trois fonctions sont toujours fournies par MRO::Compat, soit via Class::C3 lui-même sur les anciennes versions de Perl, soit directement comme des no-ops sur les versions 5.9.5+.
