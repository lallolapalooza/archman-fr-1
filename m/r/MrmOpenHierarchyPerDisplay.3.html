MrmOpenHierarchyPerDisplay(appel de bibliothèque) MrmOpenHierarchyPerDisplay(appel de bibliothèque)

NOM

MrmOpenHierarchyPerDisplay — Alloue un ID de hiérarchie et ouvre tous les fichiers UID dans la hiérarchie

SYNOPSIS

#include <Mrm/MrmPublic.h>
Cardinal MrmOpenHierarchyPerDisplay(
Display *display,
MrmCount num_files,
String file_names_list[],
MrmOsOpenParamPtr *ancillary_structures_list,
MrmHierarchy *hierarchy_id);

DESCRIPTION

MrmOpenHierarchyPerDisplay vous permet de spécifier la liste des fichiers UID que MRM recherche lors des opérations de récupération ultérieures. Toutes les opérations de récupération ultérieures retournent la première occurrence de l'élément nommé rencontrée lors de la traversée de la hiérarchie UID depuis le premier élément de la liste (spécification de fichier UID) jusqu'au dernier élément de la liste. Cette fonction alloue également un ID de hiérarchie et ouvre tous les fichiers UID dans la hiérarchie. Elle initialise les listes de recherche optimisées dans la hiérarchie. Si MrmOpenHierarchyPerDisplay rencontre des erreurs lors de son exécution, tous les fichiers qui ont été ouverts sont fermés.

L'application doit appeler XtAppInitialize avant d'appeler MrmOpenHierarchyPerDisplay.

display
Spécifie la connexion au serveur X et la valeur à passer à XtResolvePathname. Pour plus d'informations sur la structure Display, voir la fonction Xlib XOpenDisplay.
num_files
Spécifie le nombre de fichiers dans la liste de noms.
file_names_list
Spécifie un tableau de chaînes de caractères identifiant les fichiers UID.
ancillary_structures_list
Une liste de structures auxiliaires dépendantes du système d'exploitation correspondant à des éléments tels que les noms de fichiers, les indicateurs de modification, etc. Cet argument doit être NULL pour la plupart des opérations. Si vous avez besoin de référencer cette structure, voir la définition de MrmOsOpenParamPtr dans le fichier d'en-tête MrmPublic.h pour plus d'informations.
hierarchy_id
Retourne l'ID de la hiérarchie de recherche. L'ID de la hiérarchie de recherche identifie la liste des fichiers UID que MRM recherche (dans l'ordre) lors des appels de récupération ultérieurs.

Chaque chaîne de fichier UID dans file_names_list peut spécifier soit un chemin d'accès complet, soit un nom de fichier. Si une chaîne de fichier UID a un / (barre oblique) comme préfixe, elle spécifie un chemin d'accès complet, et MRM ouvre le fichier tel que spécifié. Sinon, la chaîne de fichier UID spécifie un nom de fichier. Dans ce cas, MRM recherche le fichier le long d'un chemin de recherche spécifié par la variable d'environnement UIDPATH ou par un chemin de recherche par défaut, qui varie selon que la variable d'environnement XAPPLRESDIR est définie ou non.

La variable d'environnement UIDPATH spécifie un chemin de recherche et des conventions de nommage associées aux fichiers UID. Elle peut contenir le champ de substitution %U, où la chaîne de fichier UID de l'argument file_names_list à MrmOpenHierarchyPerDisplay est substituée pour %U. Elle peut également contenir les champs de substitution acceptés par XtResolvePathname. Le champ de substitution %T est toujours mappé à uid. Le chemin entier est d'abord recherché avec %S mappé à .uid. Si aucun fichier n'est trouvé, il est à nouveau recherché avec %S mappé à NULL. Par exemple, la valeur UIDPATH et l'appel MrmOpenHierarchyPerDisplay suivants amènent MRM à ouvrir deux fichiers UID distincts :

UIDPATH=/uidlib/%L/%U.uid:/uidlib/%U/%L
  static char *uid_files[] = {"/usr/users/me/test.uid", "test2"};
  MrmHierarchy  *Hierarchy_id;
  MrmOpenHierarchyPerDisplay((MrmCount)2,uid_files, NULL, Hierarchy_id)

MRM ouvre le premier fichier, /usr/users/me/test.uid, tel que spécifié dans l'argument file_names_list à MrmOpenHierarchyPerDisplay, car la chaîne de fichier UID dans l'argument file_names_list spécifie un chemin d'accès complet. MRM recherche le second fichier, test2, d'abord comme /uidlib/%L/test2.uid, puis comme /uidlib/test2/%L, où la chaîne de langue de l'affichage est substituée à %L.

Après que MrmOpenHierarchyPerDisplay a ouvert la hiérarchie UID, vous ne devez pas supprimer ou modifier les fichiers UID tant que vous n'avez pas fermé la hiérarchie UID en appelant MrmCloseHierarchy.

Si UIDPATH n'est pas défini, mais que la variable d'environnement XAPPLRESDIR est définie, MRM recherche les chemins d'accès suivants :

•
%U%S
•
$XAPPLRESDIR/%L/uid/%N/%U%S
•
$XAPPLRESDIR/%l/uid/%N/%U%S
•
$XAPPLRESDIR/uid/%N/%U%S
•
$XAPPLRESDIR/%L/uid/%U%S
•
$XAPPLRESDIR/%l/uid/%U%S
•
$XAPPLRESDIR/uid/%U%S
•
$HOME/uid/%U%S
•
$HOME/%U%S
•
/usr/lib/X11/%L/uid/%N/%U%S
•
/usr/lib/X11/%l/uid/%N/%U%S
•
/usr/lib/X11/uid/%N/%U%S
•
/usr/lib/X11/%L/uid/%U%S
•
/usr/lib/X11/%l/uid/%U%S
•
/usr/lib/X11/uid/%U%S
•
/usr/include/X11/uid/%U%S

Si ni UIDPATH ni XAPPLRESDIR ne sont définis, MRM recherche les chemins d'accès suivants :

•
%U%S
•
$HOME/%L/uid/%N/%U%S
•
$HOME/%l/uid/%N/%U%S
•
$HOME/uid/%N/%U%S
•
$HOME/%L/uid/%U%S
•
$HOME/%l/uid/%U%S
•
$HOME/uid/%U%S
•
$HOME/%U%S
•
/usr/lib/X11/%L/uid/%N/%U%S
•
/usr/lib/X11/%l/uid/%N/%U%S
•
/usr/lib/X11/uid/%N/%U%S
•
/usr/lib/X11/%L/uid/%U%S
•
/usr/lib/X11/%l/uid/%U%S
•
/usr/lib/X11/uid/%U%S
•
/usr/include/X11/uid/%U%S

Ces chemins sont des valeurs par défaut que les fournisseurs peuvent modifier. Par exemple, un fournisseur peut utiliser des répertoires différents pour /usr/lib/X11 et /usr/include/X11.

Les substitutions suivantes sont utilisées dans ces chemins :

%U
La chaîne de fichier UID, provenant de l'argument file_names_list.
%N
Le nom de classe de l'application.
%L
La chaîne de langue de l'affichage. Cette chaîne est influencée par XtSetLanguageProc. La chaîne par défaut est déterminée en appelant setlocale(LC_ALL, NULL).
%l
Le composant langue de la chaîne de langue de l'affichage.
%S
Le suffixe du nom de fichier. Le chemin entier est d'abord recherché avec un suffixe de .uid. Si aucun fichier n'est trouvé, il est à nouveau recherché avec un suffixe NULL.

RETOUR

Cette fonction retourne l'une des constantes de retour de statut suivantes :

MrmSUCCESS
La fonction s'est exécutée avec succès.
MrmNOT_FOUND
Fichier non trouvé.
MrmFAILURE
La fonction a échoué.

VOIR AUSSI

MrmCloseHierarchy(3).
