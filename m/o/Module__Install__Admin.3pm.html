Module::Install::Admin(3) Documentation Perl fournie par la communauté Module::Install::Admin(3)

NOM

Module::Install::Admin - Gestionnaire côté auteur pour Module::Install

SYNTAXE

Dans un module d'extension Module::Install :

sub extension_method {
    my $self = shift;
    $self->admin->some_method(@args);
}

En ligne de commande :

% perl "-MModule::Install::Admin" -e'&some_method(@args);'

Les deux extraits ci-dessus sont en réalité des raccourcis pour

$some_obj->some_method(@args)

où $some_obj est l'objet singleton d'une classe dans l'espace de noms "Module::Install::Admin::*" qui fournit la méthode "some_method". Voir "MÉTHODES" pour une liste des méthodes intégrées.

DESCRIPTION

Ce module implémente le mécanisme interne pour initialiser, inclure et gérer les extensions, et ne devrait intéresser que les développeurs d'extensions ; il n'est jamais inclus dans le répertoire inc/ d'une distribution, ni aucune des extensions Module::Install::Admin::*.

Pour une utilisation normale de Module::Install, veuillez consulter Module::Install et "MANUEL / EXEMPLES" dans Module::Install.

Amorçage

Lorsqu'une personne exécute un Makefile.PL qui contient "use inc::Module::Install", et qu'il n'y a pas de répertoire inc/ dans le répertoire courant, Module::Install s'amorce lui-même, via les étapes suivantes :

  • D'abord, Module/Install.pm est débarrassé de son POD et copié de @INC vers inc/. Ceci ne devrait se produire que côté auteur, jamais côté utilisateur final.
  • Recharge inc/Module/Install.pm si le fichier courant est ailleurs. Cela garantit que la version incluse de inc/Module/Install.pm est toujours préférée à la version installée.
  • Examine inc/Module/Install/*.pm et les charge tous.
  • Met en place une fonction "main::AUTOLOAD" pour déléguer les appels de fonction manquants à "Module::Install::Admin::load" — encore une fois, cela ne devrait se produire que côté auteur.
  • Fournit une fonction "Module::Install::purge_self" pour supprimer les fichiers inclus sous inc/.
