NOM

Mouse::Meta::Attribute - La classe méta pour les attributs de Mouse

VERSION

Ce document décrit la version de Mouse v2.6.0

DESCRIPTION

Ceci est un protocole d'objet méta pour les attributs de Mouse, qui est un sous-ensemble de Moose::Meta::Attribute.

MÉTHODES

"new(%options) -> Mouse::Meta::Attribute"

Crée une nouvelle instance de Mouse::Meta::Attribute. Il n'effectue aucune autre action.

Il ajoute les options suivantes au constructeur :

"is => 'ro', 'rw', 'bare'"
Cette option fournit un raccourci pour spécifier le nom du "lecteur", "écrivain" ou "accesseur". Si l'attribut est en lecture seule ('ro'), il aura une méthode "lecteur" du même nom que l'attribut. S'il est en lecture et écriture ('rw'), il aura une méthode "accesseur" du même nom. Si un "écrivain" explicite est fourni pour un attribut en lecture et écriture, il aura un "lecteur" du même nom que l'attribut, et un "écrivain" avec le nom fourni.
Utilisez 'bare' lorsque vous souhaitez délibérément ne pas installer de méthodes (accesseur, lecteur, etc.) associées à cet attribut ; sinon, Moose émettra un avertissement de dépréciation lorsque cet attribut sera ajouté à un méta-corps.
"isa => Type"
Cette option accepte un type. Le type peut être une chaîne de caractères, qui doit être le nom d'un type. Si le nom du type est inconnu, il sera supposé qu'il s'agit du nom d'une classe.

Cette option peut également accepter un objet Moose::Meta::TypeConstraint.

Si vous fournissez également un "does", alors votre "isa" doit être un nom de classe, et cette classe doit effectuer le rôle spécifié par "does".

"does => Role"
Ceci est un raccourci pour dire que le type de l'attribut doit être un objet qui effectue le rôle spécifié.
Cette option n'est pas encore disponible.
"coerce => Bool"
Cette option n'est valide que pour les objets ayant une contrainte de type ("isa"). Si elle est vraie, les coercitions seront appliquées chaque fois que cet attribut est défini.

Vous pouvez définir à la fois ceci et le "weak_ref" à vrai.

"trigger => CodeRef"
Cette option accepte une référence de sous-routine qui est appelée après que l'attribut a été défini.
"required => Bool"
Un attribut requis doit être fourni au constructeur. Un attribut requis peut également avoir une "default" ou un "builder", qui satisferont son exigence.

Un attribut requis doit avoir une "default", un "builder", ou un "init_arg" non "undef".

"lazy => Bool"
Un attribut paresseux doit avoir un "default" ou un "builder". Lorsqu'un attribut est paresseux, la valeur par défaut ne sera pas calculée tant que l'attribut ne sera pas lu.
"weak_ref => Bool"
Si vrai, la valeur de l'attribut sera stockée sous forme de référence faible.
"auto_deref => Bool"
Si vrai, le lecteur déréférencera la valeur lors de son appel. L'attribut doit avoir une contrainte de type qui définit l'attribut comme une référence à un tableau ou à une table de hachage.
"lazy_build => Bool"
En définissant ceci à vrai, l'attribut devient paresseux et plusieurs méthodes par défaut sont fournies.

Exemple :

has 'size' => (
    is         => 'ro',
    lazy_build => 1,
);

est équivalent à :

has 'size' => (
    is        => 'ro',
    lazy      => 1,
    builder   => '_build_size',
    clearer   => 'clear_size',
    predicate => 'has_size',
);

associate_method(MethodName)

Associe une méthode à l'attribut. En général, ceci est appelé en interne lorsqu'un attribut génère ses accesseurs.

Actuellement, l'argument MethodName est ignoré dans Mouse.

"verify_against_type_constraint(Item) -> TRUE | ERROR"

Vérifie que la valeur donnée passe la contrainte de l'attribut. Renvoie "true" en cas de succès, sinon "confess".

"clone_and_inherit_options(options) -> Mouse::Meta::Attribute"

Crée un nouvel attribut dans la classe propriétaire, héritant des options des classes parents. Les accesseurs et les méthodes d'aide sont installés. Certaines vérifications d'erreurs sont effectuées.

"get_read_method_ref"

"get_write_method_ref"

Renvoie la référence de sous-routine appropriée pour lire ou écrire la valeur de l'attribut dans la classe associée. Ces méthodes renvoient toujours une référence de sous-routine, que l'attribut soit en lecture seule ou en écriture.
