NOM

Module::Implementation - Charge l'une des plusieurs implémentations alternatives pour un module

VERSION

version 0.09

SYNOPSIS

package Foo::Bar;
use Module::Implementation;
BEGIN {
    my $loader = Module::Implementation::build_loader_sub(
        implementations => [ 'XS',  'PurePerl' ],
        symbols         => [ 'run', 'check' ],
    );
    $loader->();
}
package Consumer;
# charge la première implémentation viable
use Foo::Bar;

DESCRIPTION

Ce module abstrait le processus de sélection de l'une des plusieurs implémentations sous-jacentes pour un module. Il peut être utilisé pour fournir des implémentations XS et PurePerl d'un module, ou il pourrait être utilisé pour charger une implémentation pour un système d'exploitation donné ou tout autre cas nécessitant de fournir plusieurs implémentations.

Ce module n'est utile que lorsque vous connaissez toutes les implémentations à l'avance. Si vous souhaitez charger des implémentations arbitraires, vous avez probablement besoin de quelque chose comme un système de plugins, pas de ce module.

API

Ce module fournit deux sous-routines, dont aucune n'est exportée.

Module::Implementation::build_loader_sub(...)

Cette sous-routine prend les arguments suivants.

  • implementations

    Doit être une référence de tableau des noms d'implémentations. Chaque nom doit correspondre à un module dans l'espace de noms de l'appelant.

    En d'autres termes, en utilisant l'exemple du "SYNOPSIS", ce module recherchera les modules "Foo::Bar::XS" et "Foo::Bar::PurePerl".

    Cet argument est requis.

  • symbols

    Une liste de symboles à copier du package d'implémentation vers le package appelant.

    Ceux-ci peuvent être préfixés par un type de variable : "$", "@", "%", "&", ou "*)". Si aucun préfixe n'est donné, le symbole est supposé être une sous-routine.

    Cet argument est optionnel.

Cette sous-routine retourne le chargeur d'implémentation en tant que référence de sous.

Il vous appartient d'appeler cette sous-routine de chargement dans votre code.

Je recommande de ne pas appeler ce chargeur dans une sous-routine import(). Si un appelant demande explicitement aucune importation, votre sous-routine import() ne sera pas exécutée du tout, ce qui peut causer des dysfonctionnements étranges.

Module::Implementation::implementation_for($package)

Étant donné un nom de package, cette sous-routine retourne l'implémentation qui a été chargée pour le package. Ce n'est pas un nom de package complet, juste le suffixe qui identifie l'implémentation. Pour l'exemple du "SYNOPSIS", cette sous-routine serait appelée comme Module::Implementation::implementation_for('Foo::Bar'), et elle retournerait "XS" ou "PurePerl".

COMMENT LE CHARGEUR D'IMPLÉMENTATION FONCTIONNE

Le chargeur d'implémentation fonctionne comme suit...

Premièrement, il vérifie une variable %ENV spécifiant l'implémentation à charger. La variable d'environnement est basée sur le nom du package qui charge les implémentations. Le séparateur de package "::" est remplacé par "_" et converti entièrement en majuscules. Enfin, nous ajoutons "_IMPLEMENTATION" à ce nom.

Ainsi, dans notre exemple du "SYNOPSIS", la clé %ENV correspondante serait "FOO_BAR_IMPLEMENTATION".

Si cela est défini, le chargeur essaiera uniquement de charger cette implémentation.

Si l'environnement demande une implémentation qui ne correspond pas à l'une des implémentations spécifiées lors de la création du chargeur, une erreur est levée.

Si cette implémentation unique échoue à se charger, le chargeur lève une erreur. Ceci est utile pour les tests. Vous pouvez demander une implémentation spécifique dans un fichier de test en écrivant quelque chose comme ceci :

BEGIN { $ENV{FOO_BAR_IMPLEMENTATION} = 'XS' }
use Foo::Bar;

Si la variable d'environnement n'est pas définie, le chargeur essaie simplement les implémentations passées à l'origine à "Module::Implementation". Les implémentations sont essayées dans l'ordre où elles ont été passées à l'origine.

Le chargeur utilisera la première implémentation qui se charge sans erreur. Il copiera tous les symboles demandés de cette implémentation.

Si aucune des implémentations ne peut être chargée, le chargeur lève une exception.

Le chargeur retourne le nom du package qu'il a chargé.
