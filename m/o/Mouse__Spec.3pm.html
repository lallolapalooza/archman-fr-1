NOM

Mouse::Spec - Dans quelle mesure Mouse est compatible avec Moose

VERSION

Ce document décrit la version de Mouse v2.6.0

SYNOPSIS

use Mouse::Spec;
printf "Mouse/%s est compatible avec Moose/%s\n",
    Mouse::Spec->MouseVersion, Mouse::Spec->MooseVersion;

DESCRIPTION

Mouse est un sous-ensemble de Moose. Ce document décrit dans quelle mesure Mouse est compatible (et incompatible) avec Moose.

Compatibilité avec Moose

APIs sucrées

Les APIs sucrées sont très compatibles avec Moose. Les méthodes qui ont le même nom que celles de Moose sont censées être compatibles avec celles de Moose.

Protocoles d'objets méta

Les protocoles d'objets méta sont un sous-ensemble de leurs homologues dans Moose. Leurs méthodes qui ont le même nom que celles de Moose sont censées être compatibles avec celles de Moose. N'hésitez pas à utiliser ces méthodes même si elles ne sont pas documentées.

Cependant, il existe des différences entre les MOP de Moose et ceux de Mouse. Par exemple, les protocoles d'objets méta dans Mouse n'ont pas d'attributs par défaut, donc "$metaclass->meta->make_immutable()" ne fonctionnera pas comme vous l'attendez. Ne rendez pas les classes méta immuables.

Mouse::Meta::Instance

Le mécanisme d'instance méta n'est pas implémenté, vous ne pouvez donc pas changer le type de référence des objets Mouse de la même manière que dans Moose.

Exclusion de rôle

L'exclusion de rôle, exclude(), n'est pas implémentée.

-metaclass dans Mouse::Exporter

"use Mouse -metaclass => ..." n'est pas implémenté. Utilisez plutôt "use Mouse -traits => ...".

Mouse::Meta::Attribute::Native

Les traits natifs ne sont pas directement pris en charge, mais "MouseX::NativeTraits" est disponible sur CPAN. Une fois installé, vous pouvez l'utiliser de la même manière que dans Moose. C'est-à-dire que les traits natifs sont automatiquement chargés par Mouse.

Voir MouseX::NativeTraits pour plus de détails.

Notes sur Moose::Cookbook

De nombreuses recettes dans Moose::Cookbook conviennent à Mouse, notamment :

  • Moose::Cookbook::Basics::Recipe1 - L'exemple (toujours classique) de Point
  • Moose::Cookbook::Basics::Recipe2 - Un exemple simple de BankAccount
  • Moose::Cookbook::Basics::Recipe3 - Un exemple de BinaryTree paresseux
  • Moose::Cookbook::Basics::Recipe4 - Sous-types, et modélisation d'une hiérarchie de classes Company simple
  • Moose::Cookbook::Basics::Recipe5 - Plus de sous-types, coercition dans une classe Request
  • Moose::Cookbook::Basics::Recipe6 - L'exemple augment/inner
  • Moose::Cookbook::Basics::Recipe7 - Rendre Moose rapide avec immutable
  • Moose::Cookbook::Basics::Recipe8 - Méthodes builder et lazy_build
  • Moose::Cookbook::Basics::Recipe9 - Surcharge d'opérateurs, sous-types et coercition
  • Moose::Cookbook::Basics::Recipe10 - Utilisation de BUILDARGS et BUILD pour s'intégrer à la construction d'objets
  • Moose::Cookbook::Roles::Recipe1 - L'exemple Moose::Role
  • Moose::Cookbook::Roles::Recipe2 - Composition avancée de rôles - exclusion et alias de méthodes
  • Moose::Cookbook::Roles::Recipe3 - Application d'un rôle à une instance d'objet
  • Moose::Cookbook::Meta::Recipe2 - Un attribut méta, attributs avec étiquettes
  • Moose::Cookbook::Meta::Recipe3 - Étiquettes implémentées via des traits d'attributs
  • Moose::Cookbook::Extending::Recipe3 - Fournir une classe objet de base alternative
