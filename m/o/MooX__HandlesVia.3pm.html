NOM

MooX::HandlesVia - Comportement de type NativeTrait pour Moo.

VERSION

version 0.001009

SYNOPSIS

{
  package Hashy;
  use Moo;
  use MooX::HandlesVia;
  has hash => (
    is => 'rw',
    handles_via => 'Hash',
    handles => {
      get_val => 'get',
      set_val => 'set',
      all_keys => 'keys'
    }
  );
}
my $h = Hashy->new(hash => { a => 1, b => 2});
$h->get_val('b'); # 2
$h->set_val('a', 'BAR'); # définit a à BAR
my @keys = $h->all_keys; # retourne a, b

DESCRIPTION

MooX::HandlesVia est une extension de la fonctionnalité d'attribut 'handles' de Moo. Il fournit un moyen de déléguer la fonctionnalité d'une classe externe à l'attribut donné. Ceci est le plus couramment utilisé comme moyen d'émuler le comportement de 'Native Trait' qui est devenu courant dans le code Moose, pour lequel il n'y avait pas d'alternative Moo.

INCONVENIENTS

En raison des détails d'implémentation actuels de Moo, il y a quelques lacunes dans MooX::HandlesVia par rapport à ce que l'on attend des traits natifs de Moose.

  • les méthodes déléguées via l'interface 'handles' de Moo reçoivent directement la valeur de l'attribut, et il n'y a aucun moyen d'accéder à la classe parente. Cela signifie que si un attribut est mis à jour, les déclencheurs ou les coercions de type NE SERONT PAS déclenchés.
  • les délégations de méthodes d'attribut Moo reçoivent la valeur de l'attribut. Ceci est acceptable pour les références (objets, tableaux, hachages...), mais cela signifie que les types scalaires simples sont EN LECTURE SEULE. Cela signifie malheureusement que Number, String, Counter, Bool ne peuvent pas modifier la valeur des attributs, ce qui les rend largement inutiles.

Si cela vous pose problème, envisagez Sub::HandlesVia, qui utilise une architecture différente, respectant les déclencheurs et les coercions, et permettant un accès en lecture-écriture aux valeurs non-référencées. Il devrait être possible d'utiliser Sub::HandlesVia comme remplacement direct de MooX::HandlesVia.

INTERFACE/FONCTIONS FOURNIES

process_has(@_)
MooX::HandlesVia prétraite les arguments passés aux déclarations d'attribut has() via la fonction process_has. Dans une classe Moo donnée, si 'handles_via' est défini à une chaîne ClassName, et 'handles' est défini avec une table de correspondance (hashref) des méthodes de classe Moo désirées qui devraient être mappées aux méthodes de ClassName, process_has() créera la liaison appropriée pour créer le mappage SI ClassName fournit cette méthode nommée. 
has options => (
  is => 'rw',
  handles_via => 'Array',
  handles => {
    mixup => 'shuffle',
    unique_options => 'uniq',
    all_options => 'elements'
  }
);

Les mots-clés handles_via suivants sont réservés comme raccourcis pour le mappage à Data::Perl :

  • Hash mappe à Data::Perl::Collection::Hash::MooseLike
  • Array mappe à Data::Perl::Collection::Array::MooseLike
  • String mappe à Data::Perl::String::MooseLike
  • Number mappe à Data::Perl::Number::MooseLike
  • Bool mappe à Data::Perl::Bool::MooseLike
  • Code mappe à Data::Perl::Code
