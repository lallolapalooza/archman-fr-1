NOM

Mouse::Role - Le Rôle Mouse

VERSION

Ce document décrit la version de Mouse v2.6.0

SYNOPSIS

package Comparable;
use Mouse::Role; # le package est maintenant un rôle Mouse
# Déclarer les méthodes requises par ce rôle
requires qw(compare);
# Définir les méthodes fournies par ce rôle
sub equals {
    my($self, $other) = @_;
    return $self->compare($other) == 0;
}
# et plus tard
package MyObject;
use Mouse;
with qw(Comparable); # Maintenant MyObject peut faire equals()
sub compare {
    # ...
}
my $foo = MyObject->new();
my $bar = MyObject->new();
$obj->equals($bar); # oui, il est comparable

DESCRIPTION

Ce module déclare la classe appelante comme étant un rôle Mouse.

Le concept de rôles est documenté dans Moose::Manual::Roles. Ce document sert de documentation d'API.

FONCTIONS EXPORTÉES

Mouse::Role prend en charge toutes les fonctions exportées par Mouse, mais diffère légèrement dans la manière dont certains éléments sont gérés (voir "CAVEATS" ci-dessous pour plus de détails).

Mouse::Role offre également deux mots-clés spécifiques aux rôles :

requires(@noms_de_méthodes)

Les rôles peuvent exiger que certaines méthodes soient implémentées par toute classe qui "does" le rôle.

Notez que les accesseurs d'attributs comptent également comme des méthodes aux fins de satisfaire les exigences d'un rôle.

excludes(@noms_de_rôles)

Ceci est exporté mais non implémenté dans Mouse.

IMPORT ET DÉSIMPORT

import

Importer Mouse::Role vous donnera du sucre syntaxique. "-traits" sont également pris en charge.

unimport

Veuillez désimporter ("no Mouse::Role") afin que si quelqu'un appelle l'un des mots-clés (comme "has"), cela échoue bruyamment au lieu d'échouer subtilement.

CAVEATS

Le support des rôles a quelques limitations :

  • Les rôles ne peuvent pas utiliser le mot-clé "extends" ; cela lèvera une exception pour l'instant. Il en va de même pour les mots-clés "augment" et "inner" (on ne sait pas vraiment si cela a du sens pour les rôles). Tous les autres mots-clés Mouse seront différés afin qu'ils puissent être appliqués à la classe consommatrice.
  • La composition de rôles fait de son mieux pour **ne pas** être sensible à l'ordre en ce qui concerne la résolution des conflits et la détection des exigences. Cependant, elle est sensible à l'ordre en ce qui concerne les modificateurs de méthodes. Tous les modificateurs avant/autour/après sont inclus chaque fois qu'un rôle est composé dans une classe, puis appliqués dans l'ordre dans lequel les rôles sont utilisés. Cela signifie également qu'il n'y a pas de conflit pour les modificateurs avant/autour/après.

    Dans la plupart des cas, ce ne sera pas un problème ; cependant, il est bon de le garder à l'esprit lors de l'utilisation de modificateurs de méthodes dans un rôle. Vous ne devriez jamais supposer d'ordre.
