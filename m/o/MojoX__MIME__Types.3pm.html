MojoX::MIME::Types(3) Documentation des contributeurs Perl MojoX::MIME::Types(3)

NOM

MojoX::MIME::Types - Types MIME pour Mojolicious

HÉRITAGE

MojoX::MIME::Types
  est un Mojo::Base

SYNTAXE

use MojoX::MIME::Types;
# définir par défaut dans Mojolicious
$app->types(MojoX::MIME::Types->new);
app->types(MojoX::MIME::Types->new);   # ::Lite
# interface basique traduite vers du pur MIME::Types
$types->type(foo => 'text/foo');
say $types->type('foo');

DESCRIPTION

[Ajouté à MIME::Types 2.07] Ce module est un substitut de remplacement pour Mojolicious::Types, mais avec une gestion plus correcte et une liste complète de types... une très grande liste de types.

Certaines méthodes ignorent les informations qu'elles reçoivent : ces paramètres sont acceptés pour des raisons de compatibilité avec l'interface Mojolicious::Types, mais ne doivent pas contenir d'informations utiles.

Lisez les "DÉTAILS" ci-dessous, sur la façon de connecter ce module à Mojolicious et les différences que vous obtiendrez.

MÉTHODES

Constructeurs

$class->new(%options)
Crée le gestionnaire 'type' pour Mojolicious. Quand vous ne spécifiez pas votre propre objet MIME::Type ("mime_types"), il sera instancié pour vous. Créez-en un vous-même lorsque vous souhaitez passer des paramètres au constructeur de l'objet.
-Option    --Valeur par défaut
 mime_types  <créé en interne>
 types       undef
mime_types => MIME::Types-objet
Passez votre propre objet MIME::Types préparé, lorsque vous avez besoin de paramètres d'instanciation différents de ceux par défaut.
types => HASH
Ignoré.

exemple:

$app->types(MojoX::MIME::Types->new);
# quand vous avez besoin de passer des options à MIME::Types->new
my $mt    = MIME::Types->new(%opts);
my $types = MojoX::MIME::Types->new(mime_types => $mt);
$app->types($types);

Attributs

$obj->mapping( [\%table] )
Dans Mojolicious::Types, cet attribut expose la gestion interne des types, offrant une interface propre et abstraite pour le modifier. Cette interface défectueuse prend maintenant en charge les internes les plus complexes.

Évitez cette méthode ! Le HASH renvoyé est coûteux à construire, les modifications passées par %table sont ignorées : MIME::Types est très complet !

$obj->mimeTypes()
Renvoie l'objet interne des types MIME.

Actions

$obj->content_type($controller, \%options)
Définit un type de contenu dans le contrôleur lorsqu'il n'est pas encore défini. Le %options contient "ext" ou "file" qui spécifie une extension ou un nom de fichier utilisé pour dériver le type de contenu. Ajouté et marqué comme EXPÉRIMENTAL dans Mojo 7.94.
$obj->detect( $accept, [$prio] )
Renvoie une liste d'extensions de fichier. L'en-tête $accept HTTP peut contenir plusieurs types, avec une priorité indiquée (attributs 'q'). La liste renvoyée contient une liste avec des extensions, les extensions associées au type de priorité la plus élevée en premier. Le drapeau $prio est ignoré. Voir MIME::Types::httpAccept().

Cette fonction detect() n'est pas la bonne approche pour l'en-tête Accept : "Accept" peut contenir des jokers ('*') dans les types pour le globbing, ce qui ne produit pas d'extensions. Il vaut mieux utiliser MIME::Types::httpAcceptBest() ou MIME::Types::httpAcceptSelect().

exemple:

my $exts = $types->detect('application/json;q=9');
my $exts = $types->detect('text/html, application/json;q=9');
$obj->file_type($filename)
Renvoie le type MIME pour un nom de fichier. Ajouté et marqué comme EXPÉRIMENTAL dans Mojo 7.94.
$obj->type( $ext, [$type|\@types] )
Renvoie le nom du type pour une extension $ext, sauf si vous spécifiez les noms de type.

Lorsque vous spécifiez un seul $type ou un ARRAY de @types, l'objet actuel est renvoyé. Aucune action n'est effectuée avec les informations fournies.

DÉTAILS

Pourquoi ?

Le module Mojolicious::Types ne connaît que très peu de ce qui est réellement nécessaire pour traiter correctement les types, et ne contient qu'une liste très restreinte d'extensions. MIME::Types tente de suivre les normes de très près et contient tous les types trouvés dans diverses listes sur Internet.

Comment utiliser avec Mojolicious

Démarrez votre application Mojolicious comme suit :

package MyApp;
use Mojo::Base 'Mojolicious';
sub startup {
   my $self = shift;
   ...
   $self->types(MojoX::MIME::Types->new);
}

Si vous avez des options spéciales pour MIME::Types::new(), créez alors d'abord votre propre objet MIME::Types :

my $mt    = MIME::Types->new(%opts);
my $types = MojoX::MIME::Types->new(mime_types => $mt);
$self->types($types);

Dans tous les cas, vous pouvez atteindre l'objet intelligent MIME::Types plus tard comme ceci :

my $mt    = $app->types->mimeTypes;
my $mime  = $mt->mimeTypeOf($filename);

Comment utiliser avec Mojolicious::Lite

L'utilisation dans les applications Mojolicious::Lite est juste légèrement différente :

app->types(MojoX::MIME::Types->new);
my $types = app->types;

Différences avec Mojolicious::Types

Il y a quelques différences principales avec Mojolicious::Types :

  • Les tables maintenues par MIME::Types sont complètes. Par conséquent : il ne devrait pas y avoir besoin d'ajouter vos propres types, ni via types(), ni via type(). Toutes les tentatives d'ajout de types sont ignorées ; supprimez-les de votre code.
  • Ce plugin comprend le flag expérimental 'x-' dans les types et gère les problèmes de casse.
  • Les modifications du hash interne via types() sont simplement ignorées car coûteuses à implémenter (et n'ajouteront rien de nouveau).
  • Le detect() est implémenté de manière compatible, mais ne comprend pas les jokers ('*'). Vous devez utiliser MIME::Types::httpAcceptBest() ou MIME::Types::httpAcceptSelect() pour remplacer cette fonction mal conçue.
