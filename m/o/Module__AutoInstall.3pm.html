NOM

Module::AutoInstall - Installation automatique des dépendances via CPAN

SYNTAXE

Dans Makefile.PL, avec Module::Install disponible sur le système de l'auteur :

use inc::Module::Install;

name        'Joe-Hacker';
abstract    'Interface Perl avec Joe Hacker';
author      'Joe Hacker <joe@hacker.org>';
include     'Module::AutoInstall';

requires    'Module0';          # modules requis

feature     'Feature1',
    -default    => 0,
    'Module2'   => '0.1';

feature     'Feature2',
    -default    => 0,
    'Module3'   => '1.0';

auto_install(
    make_args   => '--hello',   # options pour CPAN::Config
    force       => 1,           # option pseudo pour installer de force
    do_once     => 1,           # omettre les modules qui ont déjà échoué
);

WriteAll;

Exécution du résultat de Makefile.PL :

% perl Makefile.PL                  # comportement interactif
% perl Makefile.PL --defaultdeps    # accepte la valeur par défaut lors des requêtes
% perl Makefile.PL --checkdeps      # vérifie seulement, ne génère pas Makefile
% perl Makefile.PL --skipdeps       # ignore toutes les dépendances
% perl Makefile.PL --testonly       # ne génère pas de cibles d'installation

Note : les termes 'deps' à la fin peuvent aussi être omis.

Utiliser --defaultdeps fera agir Makefile.PL de manière similaire à un fichier Makefile.PL régulier avec PREREQ_PM.

Des variables d'environnement (voir "ENVIRONMENT") peuvent être utilisées pour spécifier un comportement par défaut au lieu de le spécifier sur la ligne de commande pour chaque invocation de Makefile.PL.

Utilisation de make (ou nmake) :

% make [all|test|install]           # installe d'abord les dépendances
% make checkdeps                    # identique à --checkdeps ci-dessus
% make installdeps                  # installe seulement les dépendances
% make installdeps_notest           # identique sans exécuter les tests
% make upgradedeps                  # met à jour toutes les dépendances, même si déjà installées
% make upgradedeps_notest           # identique sans exécuter les tests
% make listdeps                     # imprime les dépendances non satisfaites, une par ligne
% make listalldeps                  # imprime toutes les dépendances, une par ligne

DESCRIPTION

Module::AutoInstall permet aux développeurs de modules de spécifier une façon plus sophistiquée d'informer sur les dépendances que l'option PREREQ_PM offerte par ExtUtils::MakeMaker.

Ce module fonctionne mieux avec le framework Module::Install, un substitut direct de MakeMaker. Cependant, il supporte également les fichiers Makefile.PL basés sur MakeMaker ; voir "EXEMPLES" pour les instructions.

En attendant que le module Module::AutoInstall détermine quels modules sont nécessaires, il vérifiera si il est exécuté dans le shell CPAN et laissera donc CPAN gérer les dépendances.

Finalement, la méthode WriteMakefile() est surchargée pour effectuer quelques vérifications supplémentaires, ainsi que pour éviter les tests associés aux fonctionnalités désactivées par l'option -tests.

L'installation réelle se produit à la fin de la cible make config ; make test et make install déclenchent l'installation des modules nécessaires.

Si vous n'exécutez pas dans CPAN, l'installateur essaie de trouver une connexion active en résolvant le domaine cpan.org et vérifie la permission de l'utilisateur d'utiliser CPAN. Si tout va bien, un instanciateur CPAN indépendant est créé pour installer les modules nécessaires.

Si vous avez le paquet CPANPLUS installé sur votre système, il est préféré à CPAN ; il accepte également quelques options supplémentaires (par exemple, -target => 'skiptest', -skiptest => 1 pour sauter les tests).

Tous les modules prévus pour être installés seront d'abord supprimés de %INC, de sorte que ExtUtils::MakeMaker vérifiera les modules récemment installés.

De plus, vous pouvez utiliser la cible make installdeps pour installer les modules, et la cible make checkdeps pour vérifier les dépendances sans les installer ; la commande perl Makefile.PL --checkdeps a un effet équivalent.

Si le Makefile.PL lui-même doit utiliser un module indépendant (par exemple, Acme::KillarApp, v1.21 ou supérieur), utilisez quelque chose comme :

BEGIN {
    require Module::AutoInstall;
    # le premier argument est un arrayref des flags -config
    Module::AutoInstall->install([], 'Acme::KillerApp' => 1.21);
}
use Acme::KillerApp 1.21;
Module::AutoInstall->import(
    # ... arguments comme d'habitude...
);

Note : le test de version dans l'utilisation ; si vous êtes si près du bord de la version la plus récente que Acme::KillerApp 1.20 soit sur CPAN, cela évitera que votre module ne se détruise.

Prérequis et Fonctionnalités

Les prérequis sont regroupés en fonctionnalités, et l'utilisateur peut choisir oui/non pour chacune de ses dépendances ; le développeur peut également spécifier une valeur booléenne via -default pour indiquer la valeur par défaut.

Les Fonctionnalités de Prérequis marquées par le nom -core seront revues par l'utilisateur s'il n'installe pas les modules obligatoires. Ceci diffère du comportement d'installation silencieuse pré-0.26.

Depuis la version 0.27, si -core est réglé à la chaîne 'all' (sans tenir compte de la casse), chaque fonctionnalité sera considérée comme obligatoire.

Les dépendances sont exprimées comme des paires Module => version dans un array referencé. Si l'ordre n'a pas d'importance et qu'il n'y a pas de -default, -tests ou -skiptests pour cette fonctionnalité, vous pouvez utiliser un hash referencé.

Une fois que Module::AutoInstall a déterminé quels modules sont nécessaires, il vérifie s'il est exécuté dans le shell CPAN et laisse donc CPAN gérer les dépendances.

Hooks Définies par l'Utilisateur

Des hooks d'installation avant et après sont disponibles via les sous-routines MY::preinstall et MY::postinstall, comme montré :

# gestionnaire pour l'installation préalable ; reçoit $module_name et $version
sub MY::preinstall  { return 1; } # retourne false pour omettre l'installation
# gestionnaire pour l'installation postérieure ; reçoit $module_name, $version, $success
sub MY::postinstall { return; }   # la valeur de retour n'a pas d'importance

Note : étant donné que Module::AutoInstall effectue l'installation au moment de l'utilisation (c'est-à-dire avant que perl n'analyse le reste de Makefile.PL), vous devez déclarer ces deux gestionnaires avant l'instruction use pour qu'ils puissent être effectués.

Si l'utilisateur n'a pas installé un module ou si le module existe déjà sur le système, aucun des gestionnaires n'est appelé. Les deux gestionnaires sont appelés une fois pour chaque module lors de la tentative d'installation.

Le gestionnaire MY::preinstall prend deux arguments, $module_name et $version ; s'il retourne une valeur false, l'installation de ce module sera omise, et MY::postinstall ne sera pas appelé.

Le gestionnaire MY::postinstall prend trois arguments, $module_name, $version et $success. Ce dernier indique si l'installation a réussi ou non : 1 = installation terminée avec succès, 0 = échec lors de l'installation, undef = tentative d'installation omise, potentiellement.
