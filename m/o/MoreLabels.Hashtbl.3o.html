Tables de hachage et fonctions de hachage.

Les tables de hachage sont des tables d'association en mémoire, avec modification sur place. Comme les opérations sur une table de hachage modifient son contenu, elles sont couramment utilisées dans du code impatient. La recherche de la valeur associée à une clé (voir MoreLabels.Hashtbl.find, MoreLabels.Hashtbl.find_opt) est normalement très rapide, souvent plus rapide que la recherche équivalente dans MoreLabels.Map.

Les foncteurs MoreLabels.Hashtbl.Make et MoreLabels.Hashtbl.MakeSeeded peuvent être utilisés lorsque la performance ou la flexibilité est requise. L'utilisateur fournit des fonctions personnalisées d'égalité et de hachage pour le type de clé, obtenant ainsi un type de table de hachage personnalisé pour ce type de clé.

Un avertissement : Une table de hachage n'est meilleure que sa fonction de hachage. Une mauvaise fonction de hachage transformera la table en une liste d'association linéaire, avec une recherche linéaire au lieu d'une recherche en temps constant.

La table de hachage polymorphique MoreLabels.Hashtbl.t est utile dans des cas simples ou dans des environnements interactifs. Elle utilise la fonction de hachage polymorphique MoreLabels.Hashtbl.hash définie dans le langage OCaml (au moment de la rédaction, c'est SipHash), ainsi que l'égalité polymorphique (=).

Voir MoreLabels.Hashtbl.examples.

Accès non synchronisés

Les accès non synchronisés à une table de hachage peuvent conduire à un état invalide de la table. Par conséquent, les accès concurrents à une table de hachage doivent être synchronisés (par exemple avec Mutex.t).

Interface générique

type ('a, 'b) t = ('a, 'b) Hashtbl.t

Le type des tables de hachage du type 'a vers le type 'b

val create : ?random:bool -> int -> ('a, 'b) t

Hashtbl.create n crée une nouvelle table de hachage vide, avec une taille initiale supérieure ou égale à la taille suggérée n. Pour des résultats optimaux, n devrait être de l'ordre des éléments attendus dans la table. La table grandit au besoin, donc n est juste une estimation initiale. Si n est très petit ou négatif, il est ignoré et une petite taille par défaut est utilisée.

Le paramètre optionnel ~random (un booléen) contrôle si l'organisation interne de la table de hachage est aléatoire à chaque exécution de Hashtbl.create ou déterministe à toutes les exécutions.

Une table de hachage créée avec ~random défini à false utilise une fonction de hachage fixe (MoreLabels.Hashtbl.hash) pour distribuer les clés entre les buckets. Par conséquent, les collisions entre clés se produisent de manière déterministe. Dans les applications web ou d'autres contextes sécurisés, les modèles de collision déterministes peuvent être exploités par un utilisateur malveillant pour créer une attaque par déni de service : l'attaquant envoie une entrée construite pour créer de nombreuses collisions dans la table, ralentissant ainsi l'application.

Une table de hachage créée avec ~random défini à true utilise la fonction de hachage amorcée MoreLabels.Hashtbl.seeded_hash avec une amorce choisie aléatoirement lors de la création de la table. En effet, la fonction de hachage utilisée est sélectionnée aléatoirement parmi 2^30 fonctions de hachage différentes. Toutes ces fonctions ont des modèles de collision distincts, rendant inefficace l'attaque par déni de service décrite ci-dessus. Cependant, en raison de la randomisation, l'énumération de tous les éléments de la table à l'aide de MoreLabels.Hashtbl.fold ou MoreLabels.Hashtbl.iter n'est plus déterministe : les éléments sont énumérés dans des ordres différents à chaque exécution du programme.

Si le paramètre ~random n'est pas fourni, la table de hachage est créée en mode non aléatoire par défaut. Ce mode peut être modifié par programme en appelant MoreLabels.Hashtbl.randomize ou en définissant le drapeau R dans le fichier de configuration OCAMLRUNPARAM.

Avant 4.00 le paramètre ~random n'existait pas et toutes les tables de hachage étaient créées en mode non aléatoire.

Vide une table de hachage. Utilisez reset pour réduire la taille de la table des buckets à sa taille initiale.

val reset : ('a, 'b) t -> unit

Vide une table de hachage et réduit la taille de la table des buckets à sa taille initiale.

Depuis 4.00

val copy : ('a, 'b) t -> ('a, 'b) t

Retourne une copie de la table de hachage donnée.

val add : ('a, 'b) t -> key:'a -> data:'b -> unit

Hashtbl.add tbl ~key ~data ajoute une association de key à data dans la table tbl.

Avertissement : Les associations précédentes pour key ne sont pas supprimées, mais simplement masquées. Autrement dit, après avoir effectué MoreLabels.Hashtbl.remove tbl key, l'association précédente pour key est restaurée, si elle existe. (Comportement similaire aux listes d'association.)

Si vous souhaitez le comportement classique de remplacement des éléments, consultez MoreLabels.Hashtbl.replace.

val find : ('a, 'b) t -> 'a -> 'b

Hashtbl.find tbl x renvoie l'association actuelle de x dans tbl, ou Not_found si aucune association de ce type n'existe.

val find_opt : ('a, 'b) t -> 'a -> 'b option

Hashtbl.find_opt tbl x renvoie l'association actuelle de x dans tbl, ou None si aucune association de ce type n'existe.

Depuis 4.05

val find_all : ('a, 'b) t -> 'a -> 'b list

Hashtbl.find_all tbl x renvoie la liste des données associées à x dans tbl. Les données actuelles sont renvoyées en premier, puis les associations précédentes, dans l'ordre inverse de leur introduction dans la table.

val mem : ('a, 'b) t -> 'a -> bool

Hashtbl.mem tbl x vérifie si x est associé dans tbl.

val remove : ('a, 'b) t -> 'a -> unit

Hashtbl.remove tbl x supprime l'association actuelle de x dans tbl, en restaurant l'association précédente si elle existe. Si x n'est pas associé dans tbl, elle ne fait rien.

val replace : ('a, 'b) t -> key:'a -> data:'b -> unit

Hashtbl.replace tbl ~key ~data remplace l'association actuelle de key dans tbl par une association de key à data. Si key n'est pas associé dans tbl, une nouvelle association de key à data est ajoutée à tbl. C'est fonctionnellement équivalent à MoreLabels.Hashtbl.remove tbl key suivi de MoreLabels.Hashtbl.add tbl key data.

val iter : f:(key:'a -> data:'b -> unit) -> ('a, 'b) t -> unit

Hashtbl.iter ~f tbl applique f à toutes les associations de la table tbl. f reçoit la clé comme premier argument, et la valeur associée comme deuxième argument. Chaque association est présentée exactement une fois à f.

L'ordre dans lequel les associations sont passées à f n'est pas spécifié. Cependant, si la table contient plusieurs associations pour la même clé, elles sont passées à f dans l'ordre inverse d'introduction, c'est-à-dire que l'association la plus récente est passée en premier.

Si la table de hachage a été créée en mode non aléatoire, l'ordre dans lequel les associations sont énumérées est reproductible entre les exécutions successives du programme, même entre les versions mineures d'OCaml. Pour les tables de hachage randomisées, l'ordre d'énumération est entièrement aléatoire.

Le comportement n'est pas spécifié si la table de hachage est modifiée pendant l'itération avec f.

val filter_map_inplace : f:(key:'a -> data:'b -> 'b option) -> ('a, 'b) t -> unit

Hashtbl.filter_map_inplace ~f tbl applique f à toutes les associations de la table tbl et met à jour chaque association en fonction du résultat de f. Si f renvoie None, l'association est supprimée. Si elle renvoie Some new_val, l'association est mise à jour pour associer la clé à new_val.

D'autres commentaires pour MoreLabels.Hashtbl.iter s'appliquent également.

Depuis 4.03

val fold : f:(key:'a -> data:'b -> 'acc -> 'acc) -> ('a, 'b) t -> init:'acc -> 'acc

Hashtbl.fold ~f tbl ~init calcule (f kN dN ... (f k1 d1 init)...), où k1 ... kN sont les clés de toutes les tables.

Tables de hachage et séquences

val to_seq : ('a, 'b) t -> ('a * 'b) Seq.t

Itère sur la table entière. L'ordre dans lequel les entrées apparaissent dans la séquence est imprévisible. Cependant, si la table contient plusieurs entrées avec la même clé, elles apparaissent dans l'ordre inverse de leur insertion, c'est-à-dire que la plus récente apparaît en premier.

Le comportement n'est pas spécifié si la table est modifiée pendant l'itération.

Since 4.07

val of_seq : ('a * 'b) Seq.t -> ('a, 'b) t

Crée une table à partir des entrées données. Les entrées sont ajoutées dans le même ordre qu'elles apparaissent dans la séquence, en utilisant MoreLabels.Hashtbl.replace_seq, ce qui signifie que si deux paires ont la même clé, seule la dernière apparaît dans la table.

Interface fonctorielle

L'interface fonctorielle permet d'utiliser des fonctions de hachage et de comparaison spécifiques, soit pour des raisons de performance ou de sécurité, soit parce que les clés ne sont pas hashables/comparables avec les construits polymorphiques.

Par exemple, on peut vouloir spécialiser une table pour des clés de type entier :

        module IntHash =
          struct
            type t = int
            let equal i j = i=j
            let hash i = i land max_int
          end
        module IntHashtbl = Hashtbl.Make(IntHash)
        let h = IntHashtbl.create 17 in
        IntHashtbl.add h 12 "hello"

Ceci crée un nouveau module IntHashtbl, avec un nouveau type 'a IntHashtbl.t de tables de int vers 'a. Dans cet exemple, h contient des valeurs de type string, donc son type est string IntHashtbl.t.

Notez que le nouveau type 'a IntHashtbl.t n'est pas compatible avec le type ('a,'b) Hashtbl.t de l'interface générique. Par exemple, Hashtbl.length h ne sera pas typé, vous devez utiliser IntHashtbl.length.

Un fonctor qui implémente la structure des tables de hachage. Le fonctor Hashtbl.Make renvoie une structure contenant un type key de clés et un type 'a t de tables associatives reliant des données de type 'a à des clés de type key. Les opérations se comportent de manière similaire à celles de l'interface générique, mais elles utilisent les fonctions de hachage et de comparaison spécifiées dans le fonctor argument H au lieu des comparaisons et hachages génériques.

Fonctions de hachage polymorphiques

val hash : 'a -> int

La fonction Hashtbl.hash x associe un nombre non négatif à toute valeur de n'importe quel type. Il est garanti que si x = y ou Stdlib.compare x y = 0, alors hash x = hash y. De plus, hash termine toujours, même sur des structures cycliques.

val seeded_hash : int -> 'a -> int

Variante de MoreLabels.Hashtbl.hash avec un paramètre de germe entier.

Since 4.00

val hash_param : int -> int -> 'a -> int

La fonction Hashtbl.hash_param meaningful total x calcule une valeur de hachage pour x, avec les mêmes propriétés que hash. Les paramètres supplémentaires meaningful et total offrent un contrôle plus fin sur le hachage. La fonction de hachage effectue un parcours en largeur, de gauche à droite, de la structure x, s'arrêtant après meaningful nœuds significatifs ou total nœuds (significatifs ou non). Si la valeur de total spécifiée par l'utilisateur dépasse une valeur donnée (actuellement 256), elle est limitée à cette valeur. Les nœuds significatifs sont les entiers, les nombres à virgule flottante, les chaînes, les caractères, les booléens et les constructions constantes. Des valeurs plus élevées pour meaningful et total impliquent que plus de nœuds sont pris en compte pour calculer la valeur de hachage finale, réduisant ainsi les collisions. Cependant, le hachage est plus lent. Les paramètres meaningful et total régulent l'équilibre entre la précision et la vitesse. Par défaut, MoreLabels.Hashtbl.hash et MoreLabels.Hashtbl.seeded_hash utilisent meaningful = 10 et total = 100.

Hashtbl.hash_param — OCaml Manual 5.4.0

NAME

Hashtbl.hash_param

hash function with a seed

Module

Hashtbl

Documentation

This module provides functions for defining hash tables. The functions Hashtbl.hash and Hashtbl.equal are used to hash and compare keys. They are used by default for common types. For custom types, you should use the Hashtbl.Make functor.

The function Hashtbl.seeded_hash is also provided. It is defined as follows:

val seeded_hash : int -> 'a -> int

Returns a hash value for the given data, with a seed.

The function Hashtbl.hash_param is also provided.

val hash_param : int -> int -> 'a -> int

hash_param k n x computes a hash value for x. The integers k and n are two parameters that influence the hashing. The function should be such that hash_param k n x produces a different result for different values of k and n. For example, one might use hash_param 2 1000 x, which means the hash value is computed with respect to parameters k=2 and n=1000.

This function is parameterized by an integer seed. Usage: Hashtbl.seeded_hash meaningful_total_seed x.

Since 4.00

Examples

Basic Example

      (* 0...99 *)
      let seq = Seq.ints 0 |> Seq.take 100
      (* build from Seq.t *)
      # let tbl =
          seq
          |> Seq.map (fun x -> x, string_of_int x)
          |> Hashtbl.of_seq
      val tbl : (int, string) Hashtbl.t = <abstr>
      # Hashtbl.length tbl
      - : int = 100
      # Hashtbl.find_opt tbl 32
      - : string option = Some "32"
      # Hashtbl.find_opt tbl 166
      - : string option = None
      # Hashtbl.replace tbl 166 "one six six"
      - : unit = ()
      # Hashtbl.find_opt tbl 166
      - : string option = Some "one six six"
      # Hashtbl.length tbl
      - : int = 101

Counting Elements

Given a sequence of elements (here, a Seq.t ), we want to count how many times each distinct element occurs in the sequence. A simple way to do this, assuming the elements are comparable and hashable, is to use a hash table that maps elements to their number of occurrences.

Here we illustrate that principle using a sequence of (ascii) characters (type char ). We use a custom Char_tbl specialized for char .

      # module Char_tbl = Hashtbl.Make(struct
          type t = char
          let equal = Char.equal
          let hash = Hashtbl.hash
        end)
      (*  count distinct occurrences of chars in [seq] *)
      # let count_chars (seq : char Seq.t) : _ list =
          let counts = Char_tbl.create 16 in
          Seq.iter
            (fun c ->
              let count_c =
                Char_tbl.find_opt counts c
                |> Option.value ~default:0
              in
              Char_tbl.replace counts c (count_c + 1))
            seq;
          (* turn into a list *)
          Char_tbl.fold (fun c n l -> (c,n) :: l) counts []
            |> List.sort (fun (c1,_)(c2,_) -> Char.compare c1 c2)
      val count_chars : Char_tbl.key Seq.t -> (Char.t * int) list = <fun>
      (* basic seq from a string *)
      # let seq = String.to_seq "hello world, and all the camels in it!"
      val seq : char Seq.t = <fun>
      # count_chars seq
      - : (Char.t * int) list =
      [(' ', 7); ('!', 1); (',', 1); ('a', 3); ('c', 1); ('d', 2); ('e', 3);
       ('h', 2); ('i', 2); ('l', 6); ('m', 1); ('n', 2); ('o', 2); ('r', 1);
       ('s', 1); ('t', 2); ('w', 1)]
      (* "abcabcabc..." *)
      # let seq2 =
          Seq.cycle (String.to_seq "abc") |> Seq.take 31
      val seq2 : char Seq.t = <fun>
      # String.of_seq seq2
      - : String.t = "abcabcabcabcabcabcabcabcabcabca"
      # count_chars seq2
      - : (Char.t * int) list = [('a', 11); ('b', 10); ('c', 10)]
