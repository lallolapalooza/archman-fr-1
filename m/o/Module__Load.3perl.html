Module::Load(3perl) Guide de référence des programmeurs Perl Module::Load(3perl)

NOM

Module::Load — chargement dynamique des modules et fichiers

SYNOPSIS

use Module::Load;
my $module = 'Data::Dumper';
load Data::Dumper;     # charge ce module, mais n'importe aucune fonction
                       # -> impossible d'utiliser la fonction 'Dumper'
load 'Data::Dumper';   # idem
load $module           # idem
autoload Data::Dumper; # charge ce module et importe les fonctions par défaut
                       # -> possible d'utiliser la fonction 'Dumper'
my $script = 'some/script.pl'
load $script;
load 'some/script.pl';  # utiliser des guillemets à cause de la ponctuation
load thing;             # essaie 'thing' d'abord, puis 'thing.pm'
load CGI, ':all';       # comme 'use CGI qw[:standard]'

DESCRIPTION

"Module::Load" élimine le besoin de savoir si vous essayez de charger un fichier ou un module.

Si vous consultez "perldoc -f require", vous verrez que "require" se comporte différemment lorsqu'on lui donne un mot-clé sans guillemets (bareword) ou une chaîne de caractères.

Dans le cas d'une chaîne de caractères, "require" suppose que vous voulez charger un fichier. Mais dans le cas d'un mot-clé sans guillemets, il suppose que vous faites référence à un module.

Cela crée une surcharge désagréable lorsque vous essayez de charger dynamiquement des modules à l'exécution, car vous devrez adapter la notation du module ("Acme::Comment") à une notation de fichier adaptée à la plateforme spécifique sur laquelle vous vous trouvez.

"Module::Load" élimine ce besoin et fait simplement ce que vous voulez (DWYM).

Différence entre "load" et "autoload"

"Module::Load" importe les deux fonctions : "load" et "autoload".

"autoload" importe les fonctions par défaut automatiquement, mais "load" n'importe aucune fonction.

"autoload" est utilisable sous "BEGIN{};".

Les deux fonctions peuvent importer les fonctions spécifiées.

Les codes suivants sont identiques.

load File::Spec::Functions, qw/splitpath/;
autoload File::Spec::Functions, qw/splitpath/;

FONCTIONS

load
Charge un module spécifié.

Voir les "Règles" pour les détails de la règle de chargement.

autoload
Charge un module spécifié et importe les fonctions par défaut.

À l'exception de l'importation des fonctions, 'autoload' est identique à 'load'.

load_remote
Charge un module spécifié dans le paquet spécifié. 
use Module::Load 'load_remote';
my $pkg = 'Other::Package';
load_remote $pkg, 'Data::Dumper'; # charge un module dans 'Other::Package'
                                  # mais n'importe pas la fonction 'Dumper'

Un module à charger doit être entre guillemets.

À l'exception de la spécification du paquet et du nom du module entre guillemets, 'load_remote' est identique à 'load'.

autoload_remote
Charge un module spécifié et importe les fonctions par défaut dans le paquet spécifié. 
use Module::Load 'autoload_remote';
my $pkg = 'Other::Package';
autoload_remote $pkg, 'Data::Dumper'; # charge un module dans 'Other::Package'
                                      # et importe la fonction 'Dumper'

Un module à charger doit être entre guillemets.

À l'exception de la spécification du paquet et du nom du module entre guillemets, 'autoload_remote' est identique à 'load_remote'.

Règles

Toutes les fonctions suivent les règles suivantes pour décider de ce qu'elles pensent que vous voulez :

  • Si l'argument contient des caractères autres que ceux correspondant à "\w", ":" ou "'", il doit s'agir d'un fichier
  • Si l'argument correspond uniquement à "[\w:']", il doit s'agir d'un module
  • Si l'argument correspond uniquement à "\w", il peut s'agir soit d'un module, soit d'un fichier. Nous essaierons de trouver "file.pm" d'abord dans @INC et si cela échoue, nous essaierons de trouver "file" dans @INC. Si les deux échouent, nous mourrons avec les messages d'erreur respectifs.

IMPORTE LES FONCTIONS

'load' et 'autoload' sont importés par défaut, mais 'load_remote' et 'autoload_remote' ne le sont pas.

Pour utiliser 'load_remote' ou 'autoload_remote', spécifiez-le lors de l'appel à 'use'.

"load","autoload","load_remote","autoload_remote"
Importe les fonctions sélectionnées. 
# importe 'load' et 'autoload' (par défaut)
use Module::Load;
# importe seulement 'autoload'
use Module::Load 'autoload';
# importe 'autoload' et 'autoload_remote', mais n'importe pas 'load' ;
use Module::Load qw/autoload autoload_remote/;
'all'
Importe toutes les fonctions. 
use Module::Load 'all'; # importe load, autoload, load_remote, autoload_remote
'','none',undef
N'importe aucune fonction ("load" et "autoload" ne sont pas importés). 
use Module::Load '';
use Module::Load 'none';
use Module::Load undef;

Limitations

En raison d'un bug dans perl (#19213), au moins dans la version 5.6.1, nous devons coder en dur le séparateur de chemin pour un require sur Win32 en tant que "/", comme sur Unix plutôt que le "\" de Win32. Sinon, perl ne lira pas correctement son propre %INC, chargera deux fois les fichiers s'ils sont rechargés, ou dans le pire des cas, plantera.

"Module::Load" ne peut pas faire d'importations implicites, seulement explicites. (En d'autres termes, vous devez toujours spécifier explicitement ce que vous souhaitez importer d'un module, même si les fonctions se trouvent dans la liste @EXPORT de ce module)

VOIR AUSSI

Module::Runtime fournit des fonctions pour charger des modules, vérifier la validité d'un nom de module, convertir un nom de module en chemin partiel ".pm", et des fonctions utilitaires connexes.

"require" dans perlfunc https://metacpan.org/pod/perlfunc#require et "use" dans perlfunc https://metacpan.org/pod/perlfunc#use.

Mojo::Loader est un "chargeur de classe et framework de plugins", et est inclus dans la distribution Mojolicious https://metacpan.org/release/Mojolicious.

Module::Loader est un module pour trouver et charger des modules dans un espace de noms donné, inspiré par "Mojo::Loader".
