Nom

Module::ScanDeps - Scanner le code Perl à la recherche de dépendances

Synopsis

Via le programme de ligne de commande scandeps.pl:

% scandeps.pl *.pm          # Afficher la section PREREQ_PM pour *.pm
% scandeps.pl -e "use utf8" # Lire le script depuis la ligne de commande
% scandeps.pl -B *.pm       # Inclure les modules de base
% scandeps.pl -V *.pm       # Afficher les fichiers d'autoload, partagés et de données

Utilisé dans un programme:

use Module::ScanDeps;
# Usage standard
my $hash_ref = scan_deps(
    files   => [ 'a.pl', 'b.pl' ],
    recurse => 1,
);
# Format court ; suppose recurse == 1
my $hash_ref = scan_deps( 'a.pl', 'b.pl' );
# Interface compatible avec App::Packer::Frontend
# voir App::Packer::Frontend pour le format de retour de get_files
my $scan = Module::ScanDeps->new;
$scan->set_file( 'a.pl' );
$scan->set_options( add_modules => [ 'Test::More' ] );
$scan->calculate_info;
my $files = $scan->get_files;

Description

Ce module analyse les modules potentiels utilisés par les programmes Perl et renvoie une référence de hash ; ses clés sont les noms des modules tels qu'ils apparaissent dans %INC (par exemple, "Test/More.pm") ; les valeurs sont des références de hash avec cette structure:

{
    file    => '/usr/local/lib/perl5/5.8.0/Test/More.pm',
    key     => 'Test/More.pm',
    type    => 'module',    # ou 'autoload', 'data', 'shared'
    used_by => [ 'Test/Simple.pm', ... ],
    uses    => [ 'Test/Other.pm', ... ],
}

Une fonction, "scan_deps", est exportée par défaut. D'autres fonctions telles que ("scan_line", "scan_chunk", "add_deps", "path_to_inc_name") sont exportées lorsqu'elles sont demandées.

Les utilisateurs d'App::Packer peuvent également utiliser ce module comme interface frontend pour vérifier les dépendances, en ajustant leur p2e.pl comme suit:

use Module::ScanDeps;
...
my $packer = App::Packer->new( frontend => 'Module::ScanDeps' );
...

Veuillez consulter App::Packer::Frontend pour une explication détaillée du format de retour de get_files.

scan_deps

$rv_ref = scan_deps(
    files      => \@files,     recurse => $recurse,
    rv         => \%rv,        skip    => \%skip,
    compile    => $compile,    execute => $execute,
);
$rv_ref = scan_deps(@files); # syntaxe courte, avec recurse == 1

Cette fonction analyse chaque fichier dans @files, enregistrant ses dépendances dans %rv, et renvoie une référence à %rv mise à jour. La signification des clés et des valeurs est expliquée ci-dessus.

Si $recurse est vrai, scan_deps s'appelle récursivement, pour effectuer une recherche en largeur dans les fichiers texte (tel que défini par l'opérateur -T).

Si \%skip est spécifié, les fichiers qui existent comme ses clés sont ignorés. Ceci est utilisé en interne pour éviter la récursion infinie.

Si $compile ou $execute est vrai, les fichiers sont exécutés en mode compilation uniquement ou en mode normal, et leur %INC est inspecté après la fermeture pour déterminer les dépendances d'exécution supplémentaires.

Si $execute est une référence de tableau, il transmet @$execute comme arguments à chaque fichier dans @files lors de l'exécution.

Si vous vous souciez de la vitesse du processus de balayage, vous pouvez définir l'option cache_file à un nom de fichier. Les résultats de l'analyse seront stockés dans le fichier et utilisés pour accélérer l'analyse lors des exécutions futures.

De plus, une option "warn_missing" est reconnue. Si elle est définie à vrai, scan_deps émet un avertissement à STDERR pour chaque fichier de module dont il dépend mais qui ne peut être trouvé. Notez que cela peut également signaler de nombreux faux positifs. Par conséquent, par défaut, l'algorithme heuristique ignore silencieusement toutes les dépendances qui ne peuvent être trouvées.

scan_deps_runtime

Similaire à scan_deps, mais omet la partie analyse statique.

scan_line

@modules = scan_line($line);

Divise une ligne en morceaux (actuellement avec des caractères de point-virgule) et renvoie l'union des appels à scan_chunk à partir d'eux.

Si la ligne est "__END__" ou "__DATA__", un élément "__END__" est renvoyé pour indiquer la fin du programme.

De même, il renvoie un élément "__POD__" si la ligne correspond à "/^=\w/" ; l'appelant est responsable de sauter le nombre approprié de lignes jusqu'à "=cut" avant d'appeler à nouveau scan_line.

scan_chunk

$module = scan_chunk($chunk);
@modules = scan_chunk($chunk);

Applique diverses heuristiques à $chunk pour trouver et renvoyer le(s) nom(s) de module qu'il contient. En contexte scalaire, il renvoie uniquement le premier module ou "undef".

add_deps

$rv_ref = add_deps( rv => \%rv, modules => \@modules );
$rv_ref = add_deps( @modules ); # syntaxe courte, sans rv

Résout une liste de noms de modules vers leur emplacement réel sur disque, en recherchant dans @INC et @Module::ScanDeps::IncludeLibs ; les modules qui ne peuvent être trouvés sont ignorés.

Cette fonction remplit le hash %rv avec des paires module/nom_de_fichier, et renvoie une référence vers celui-ci.

path_to_inc_name

$perl_name = path_to_inc_name($path, $warn)

Suppose que $path fait référence à un fichier Perl et fait de son mieux pour renvoyer le nom tel qu'il apparaîtrait dans %INC. Renvoie undef s'il n'y a pas de correspondance et imprime un avertissement à STDERR si $warn est vrai.

Exemple : si $path = perl/site/lib/Module/ScanDeps.pm, alors $perl_name sera Module/ScanDeps.pm.

Notes

@Module::ScanDeps::IncludeLibs

Vous pouvez définir cette variable globale pour spécifier des répertoires supplémentaires dans lesquels rechercher des modules sans modifier @INC.

$Module::ScanDeps::ScanFileRE

Vous pouvez définir cette variable globale pour spécifier un motif régulier afin d'identifier quels fichiers analyser. Par défaut, il inclut tous les fichiers des types suivants : .pm, .pl, .t et .al. De plus, il prend en compte tous les fichiers sans extension.

Par exemple, si vous voulez analyser tous les fichiers, utilisez ce qui suit :

"$Module::ScanDeps::ScanFileRE = qr/./"

Mises en garde

Ce module ignore intentionnellement le hack BSDPAN sous FreeBSD — le répertoire supplémentaire est retiré de @INC.

L'algorithme d'analyse statique n'est probablement pas précis à 100 %, en particulier pour les modules qui chargent d'autres modules de manière dynamique.

Les blocs qui s'étendent sur plusieurs lignes ne sont pas correctement gérés. Par exemple, ceci fonctionne :

use base 'Foo::Bar';

Mais ceci ne fonctionne pas :

use base
    'Foo::Bar';

Voir également

scandeps.pl est un utilitaire intégré qui écrit la section PREREQ_PM pour divers fichiers.

Une utilisation de Module::ScanDeps est de générer des exécutables à partir de scripts contenant des modules de dépendance ; ce module prend en charge deux projets de ce type : PAR et App::Packer. Veuillez consulter leur documentation respective sur CPAN pour plus d'informations.

Autres modules qui atteignent le même objectif avec une approche différente : Module::ExtractUse, Perl::PrereqScan

NOM

Module::ScanDeps

Un module Perl pour scanner les dépendances

SYNOPSIS

Utilisez ceci pour installer ce module :

    cpan install Module::ScanDeps

Alternativement, utilisez la commande suivante :

    perl -MModule::ScanDeps -e 'Module::ScanDeps::main();'

DESCRIPTION

Module::ScanDeps est un module Perl qui aide à scanner les dépendances pour d'autres modules. Il fournit un moyen de découvrir quels modules sont requis pour un ensemble donné de modules.
