NOM

MooX::late - traduire facilement du code Moose en Moo

SYNTAXE

package Foo;
use Moo;
use MooX::late;
has bar => (is => "ro", isa => "Str", default => "MacLaren's Pub");

(Exemples de rôles Moo dans la section ci-dessous.)

DESCRIPTION

Moo est un cadre de programmation orienté objet léger qui vise à être compatible avec Moose. Il y parvient en détectant lorsque Moose a été chargé, et en "gonflant" automatiquement ses classes et rôles en classes et rôles Moose complets. Ainsi, les classes Moo peuvent consommer des rôles Moose, les classes Moose peuvent étendre des classes Moo, et ainsi de suite.

Cependant, la syntaxe de surface de Moo diffère quelque peu de celle de Moose. Par exemple, l'option "isa" lors de la définition d'attributs dans Moose doit être une chaîne de caractères ou un objet béni Moose::Meta::TypeConstraint ; mais dans Moo, elle doit être un coderef. Ces différences de syntaxe de surface rendent le portage de code de Moose à Moo potentiellement délicat. MooX::late offre une aide en permettant une syntaxe de surface légèrement plus "Moosey".

MooX::late fait ce qui suit :

1.
Prend en charge "isa => $stringytype".
2.
Prend en charge "does => $rolename" .
3.
Prend en charge "lazy_build => 1".
4.
Export des fonctions "blessed" et "confess" dans votre espace de noms.
5.
Gère les traits d'attributs natifs.

Cinq fonctionnalités. Le but de "MooX::late" n'est pas de faire en sorte que chaque aspect de Moo se comporte exactement comme Moose. Il s'attaque simplement aux fruits faciles à cueillir. Il fait donc cinq choses actuellement, et je promets que les futures versions n'en feront jamais plus de sept.

Les versions précédentes de MooX::late ajoutaient la prise en charge de "coerce => 1" et "default => $nonref". Ces fonctionnalités ont maintenant été ajoutées à Moo lui-même, de sorte que MooX::late n'a plus à s'en occuper.

Utilisation dans les rôles Moo::Role

MooX::late devrait fonctionner dans Moo::Role, sans aucune mise en garde particulière.

package MyRole;
use Moo::Role;
use MooX::late;

Package::Variant peut être utilisé pour construire l'équivalent Moo des rôles paramétrés. MooX::late devrait fonctionner dans les rôles construits avec Package::Variant.

use Package::Variant
   importing => [ qw( Moo::Role MooX::late ) ],
   subs      => [ qw( has with ) ];

Contraintes de type

Les chaînes de caractères de contraintes de type sont interprétées à l'aide de Type::Parser, en utilisant les contraintes de type définies dans Types::Standard. Cela fournit un sous-ensemble très léger de la syntaxe des contraintes de type et des contraintes de type intégrées de Moose.

Toute chaîne de caractères non reconnue qui ressemble à un nom de classe est interprétée comme une contrainte de type de classe.

Héritage

MooX::late est conçu pour être raisonnablement facile à sous-classer. Il y a des commentaires dans le code source expliquant les points d'extension pour l'extensibilité.

VOIR AUSSI

"MooX::late" utilise Types::Standard pour vérifier les contraintes de type.

"MooX::late" utilise Sub::HandlesVia pour fournir la prise en charge des traits d'attributs natifs.

Les modules suivants apportent des fonctionnalités Moose supplémentaires à Moo, au-delà de ce que propose MooX::late :

  • MooX::Override - prend en charge override/super
  • MooX::Augment - prend en charge augment/inner

MooX vous permet de charger Moo plus plusieurs modules d'extension MooX en une seule ligne.
