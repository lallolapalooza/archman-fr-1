Module::Metadata(3perl) Guide du programmeur Perl Module::Metadata(3perl)

NOM

Module::Metadata - Rassembler des informations sur les paquets et les POD à partir des fichiers de modules Perl

VERSION

version 1.000038

SYNTAXE

use Module::Metadata;
# informations sur un fichier .pm
my $info = Module::Metadata->new_from_file( $file );
my $version = $info->version;
# champ 'provides' de CPAN META pour les fichiers .pm dans un répertoire
my $provides = Module::Metadata->provides(
  dir => 'lib', version => 2
);

DESCRIPTION

Ce module fournit une manière standard de collecter des métadonnées d'un fichier .pm via une analyse (principalement) statique et (quelques) exécutions de code. Lors de la détermination de la version d'un module, l'affectation $VERSION est évaluée ("eval"ed), comme il est traditionnel dans la chaîne d'outils CPAN.

MÉTHODES DE CLASSE

"new_from_file($filename, collect_pod => 1, decode_pod => 1)"

Construit un objet "Module::Metadata" à partir du chemin d'un fichier. Retourne undef si le nom du fichier n'existe pas.

"collect_pod" est un argument booléen optionnel qui détermine si les données POD sont collectées et stockées pour référence. Les données POD ne sont pas collectées par défaut. Les en-têtes POD sont toujours collectés.

Si le fichier commence par une marque d'ordre d'octets UTF-8, UTF-16BE ou UTF-16LE, celle-ci est ignorée avant le traitement, et le contenu du fichier est également décodé de manière appropriée à partir de perl 5.8.

Alternativement, si "decode_pod" est défini, il décodera les sections POD collectées selon la déclaration "=encoding".

"new_from_handle($handle, $filename, collect_pod => 1, decode_pod => 1)"

Cela fonctionne comme "new_from_file", sauf qu'un descripteur (handle) peut être fourni comme premier argument.

Notez qu'il n'y a aucune validation pour confirmer que le descripteur est un descripteur ou quelque chose qui peut agir comme tel. Passer quelque chose qui n'est pas un descripteur provoquera une exception lors de la tentative de lecture à partir de celui-ci. L'argument "filename" est obligatoire, sinon undef sera retourné.

Vous êtes responsable de la configuration des couches de décodage sur $handle si nécessaire.

"new_from_module($module, collect_pod => 1, inc => \@dirs, decode_pod => 1)"

Construit un objet "Module::Metadata" à partir d'un nom de module ou de paquet. Retourne undef si le module ne peut être trouvé.

En plus d'accepter les arguments "collect_pod" et "decode_pod" comme décrit ci-dessus, cette méthode accepte un argument "inc" qui est une référence à un tableau de répertoires où rechercher le module. Si aucun n'est donné, la valeur par défaut est @INC.

Si le fichier qui contient le module commence par une marque d'ordre d'octets UTF-8, UTF-16BE ou UTF-16LE, celle-ci est ignorée avant le traitement, et le contenu du fichier est également décodé de manière appropriée à partir de perl 5.8.

"find_module_by_name($module, \@dirs)"

Retourne le chemin d'un module étant donné le nom du module ou du paquet. Une liste de répertoires peut être passée en paramètre optionnel, sinon @INC est recherché.

Peut être appelée comme méthode d'objet ou de classe.

"find_module_dir_by_name($module, \@dirs)"

Retourne l'entrée dans @dirs (ou @INC par défaut) qui contient le module $module. Une liste de répertoires peut être passée en paramètre optionnel, sinon @INC est recherché.

Peut être appelée comme méthode d'objet ou de classe.

provides( %options )

Ceci est un wrapper de commodité autour de "package_versions_from_directory" pour générer une structure de données "provides" de CPAN META. Elle prend des paires clé/valeur. Les clés d'option valides incluent :

version (requis)
Spécifie quelle version de CPAN::Meta::Spec doit être utilisée comme format de la sortie "provides". Actuellement, seuls '1.4' et '2' sont pris en charge (et leur format est identique). Cela pourrait changer à l'avenir à mesure que la définition de "provides" évolue.

L'option "version" est requise. Si elle est omise ou si une version non prise en charge est donnée, "provides" générera une erreur.

dir
Répertoire à rechercher récursivement pour les fichiers .pm. Ne peut pas être spécifié avec "files".
files
Référence d'un tableau de fichiers à examiner. Ne peut pas être spécifié avec "dir".
prefix
Chaîne à préfixer au champ "file" de la sortie résultante. Par défaut, c'est lib, ce qui est le cas le plus courant pour la plupart des distributions CPAN avec leurs fichiers .pm dans lib. Cette option garantit que les informations META ont le chemin relatif correct, même lorsque les arguments "dir" ou "files" sont absolus ou ont des chemins relatifs depuis un emplacement autre que la racine de la distribution.

Par exemple, étant donné "dir" égal à 'lib' et "prefix" égal à 'lib', la valeur de retour est un hashref de la forme :

{
  'Package::Name' => {
    version => '0.123',
    file => 'lib/Package/Name.pm'
  },
  'OtherPackage::Name' => ...
}

"package_versions_from_directory($dir, \@files?)"

Analyse $dir à la recherche de fichiers .pm (sauf si @files est fourni, auquel cas il recherche ces fichiers dans $dir - et lit chaque fichier pour trouver les paquets et les versions, retournant un hashref de la forme :

{
  'Package::Name' => {
    version => '0.123',
    file => 'Package/Name.pm'
  },
  'OtherPackage::Name' => ...
}

Les paquets "DB" et "main" sont toujours omis, tout comme les paquets "privés" qui ont des traits de soulignement initiaux dans l'espace de noms (par exemple, "Foo::_private")

Notez que le chemin du fichier est relatif à $dir si celui-ci est spécifié. Ceci **ne doit pas** être utilisé directement pour le CPAN META "provides". Voir plutôt la méthode "provides".

"log_info_(interne)"

Méthode interne. Les messages de journalisation sont acheminés vers le package Log::Log4perl s'il est disponible, sinon vers Carp::croak.

MÉTHODES POUR OBJET

version

Retourne la version du module ou undef si elle n'a pas pu être trouvée.

name

Retourne le nom du module (par exemple, "My::Module") ou undef.

path

Retourne le chemin du fichier module, ou undef.

author_test_requires

Retourne une liste des dépendances requises pour les tests auteur (ceux qui ne sont pas des dépendances de runtime). Ces informations sont généralement trouvées dans les commentaires Perl du fichier module.

all_requires

Retourne une liste de toutes les dépendances requises par le module, y compris les dépendances de runtime et de test auteur. Les informations sont généralement trouvées dans les commentaires Perl du fichier module.

pod_title

Retourne le titre du POD du module (la première ligne après .=head1 NAME).

pod_sections

Retourne une liste de sections POD du module. Chaque élément de la liste est une paire de chaînes, où le premier élément est le nom de la section et le second est le contenu de la section.

defines_method($method_name)

Retourne vrai si le module définit la méthode donnée, faux sinon.

first_line

Retourne la première ligne du fichier du module.

defines_package($package_name)

Retourne vrai si le module définit le paquet donné, faux sinon.

package_name

Retourne le nom du paquet principal défini dans le fichier du module.

files_read

Retourne une liste des fichiers qui ont été lus pour obtenir les métadonnées.

NOTES

L'analyse statique ne peut pas toujours déterminer les dépendances, la version ou le nom du package. Dans ces cas, la méthode retournera undef.

Le code du module est "eval"é pour déterminer la version du module. Cela signifie que le code du module est exécuté. Si le module a des effets secondaires lors de son évaluation, ces effets secondaires se produiront.

La méthode "provides" est destinée à générer des informations au format CPAN META. Si vous avez besoin de construire manuellement des informations Provides, vous devriez plutôt utiliser la méthode "package_versions_from_directory", et ajouter manuellement le préfixe de répertoire comme requis pour CPAN META.

MÉTHODES OBJET

nom()

Retourne le nom du package représenté par ce module. S'il y a plus d'un package, il fait de son mieux en se basant sur le nom du fichier. S'il s'agit d'un script (c'est-à-dire qu'il ne s'agit pas d'un *.pm), le nom du package est 'main'.

version($package)

Retourne la version définie par la variable $VERSION du package tel que retourné par la méthode "nom" si aucun argument n'est donné. Si le nom d'un package est donné, il essaie de retourner la version de ce package s'il est spécifié dans le fichier.

nom_fichier()

Retourne le chemin absolu du fichier. Note : ce fichier peut ne pas encore exister sur le disque, par exemple si le module a été lu à partir d'un fichier en mémoire.

packages_internes()

Retourne une liste de packages. Note : c'est une liste de packages découverts (ou supposés, dans le cas de "main"). Ils ne sont pas filtrés pour "DB", "main" ou les packages privés de la manière dont la méthode "fournit" le fait. Les noms de packages invalides ne sont pas retournés, par exemple "Foo:Bar". Les noms de packages étranges mais valides sont retournés, par exemple "Foo::Bar::", et il appartient à l'appelant de décider comment les gérer.

pod_interne()

Retourne une liste de sections POD.

contient_pod()

Retourne vrai s'il y a du POD dans le fichier.

pod($section)

Retourne les données POD dans la section spécifiée.

est_indexable($package) ou est_indexable()

Disponible à partir de la version 1.000020.

Retourne un booléen indiquant si le package (si fourni) ou n'importe quel package (sinon) est indexable par PAUSE, le serveur de mise en ligne des auteurs Perl. Note : ceci vérifie uniquement les déclarations de "package" valides et ne prend pas en compte les informations de propriété.
