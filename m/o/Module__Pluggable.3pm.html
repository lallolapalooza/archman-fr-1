NOM

Module::Pluggable - donne automatiquement à votre module la capacité d'avoir des plugins

SYNTAXE

Utilisation simple de Module::Pluggable -

package MonClasse;
use Module::Pluggable;

et plus tard ...

use MonClasse;
my $mc = MonClasse->new();
# retourne les noms de tous les plugins installés sous MonClasse::Plugin::*
my @plugins = $mc->plugins();

EXEMPLE

Pourquoi voudriez-vous faire cela ? Disons que vous avez quelque chose qui veut passer un objet à un certain nombre de plugins différents l'un après l'autre. Par exemple, vous pourriez vouloir extraire des métadonnées de chaque e-mail que vous recevez et en faire quelque chose. Les plugins ont du sens ici car vous pouvez continuer à ajouter de nouveaux analyseurs de métadonnées et toute la logique et la documentation pour chacun d'eux seront autonomes et les nouveaux gestionnaires sont faciles à ajouter sans modifier le code principal. Pour cela, vous pourriez faire quelque chose comme ...

package Email::Examiner;
use strict;
use Email::Simple;
use Module::Pluggable require => 1;
sub handle_email {
    my $self  = shift;
    my $email = shift;
    foreach my $plugin ($self->plugins) {
        $plugin->examine($email);
    }
    return 1;
}

.. et tous les plugins auront la possibilité à tour de rôle de l'examiner.

Cela peut être trivialement étendu afin que les plugins puissent sauvegarder l'e-mail quelque part et qu'aucun autre plugin n'essaie de le faire. Faites simplement en sorte que la méthode "examine" renvoie 1 si elle a sauvegardé l'e-mail quelque part. Vous pourriez également vouloir être paranoïaque et vérifier si le plugin a une méthode "examine".

foreach my $plugin ($self->plugins) {
    next unless $plugin->can('examine');
    last if     $plugin->examine($email);
}

Et ainsi de suite. Le ciel est la limite.

DESCRIPTION

Fournit un moyen simple mais, espérons-le, extensible d'avoir des 'plugins' pour votre module. Évidemment, ce ne sera pas la solution ultime, mais ça marche pour moi.

Essentiellement, tout ce qu'il fait est d'exporter une méthode dans votre espace de noms qui parcourt un chemin de recherche pour les fichiers .pm et les transforme en noms de classes.

Optionnellement, il instancie ces classes pour vous.

UTILISATION AVANCÉE

Alternativement, si vous ne voulez pas utiliser 'plugins' comme méthode ...

package MonClasse;
use Module::Pluggable sub_name => 'foo';

et plus tard ...

my @plugins = $mc->foo();

Ou si vous voulez chercher dans un autre espace de noms

package MonClasse;
use Module::Pluggable search_path => ['Acme::MonClasse::Plugin', 'MonClasse::Extend'];

ou un répertoire

use Module::Pluggable search_dirs => ['mylibs/Foo'];

Ou si vous voulez instancier chaque plugin plutôt que de simplement retourner le nom

package MonClasse;
use Module::Pluggable instantiate => 'new';

et puis

# tout ce qui est passé à 'plugins' sera passé
# à 'new' pour chaque plugin
my @plugins = $mc->plugins(@options);

alternativement, vous pouvez simplement exiger le module sans l'instancier

package MonClasse;
use Module::Pluggable require => 1;

puisque l'exigence recherche automatiquement les paquets internes, ce qui peut ne pas être souhaitable, vous pouvez désactiver cela

package MonClasse;
use Module::Pluggable require => 1, inner => 0;

Vous pouvez limiter les plugins chargés en utilisant l'option except, soit sous forme de chaîne, de référence de tableau ou d'expression régulière

package MonClasse;
use Module::Pluggable except => 'MonClasse::Plugin::Foo';

ou

package MonClasse;
use Module::Pluggable except => ['MonClasse::Plugin::Foo', 'MonClasse::Plugin::Bar'];

ou

package MonClasse;
use Module::Pluggable except => qr/^MonClasse::Plugin::(Foo|Bar)$/;

et de même pour only, qui ne chargera que les plugins qui correspondent.

N'oubliez pas que vous pouvez utiliser le module plus d'une fois

package MonClasse;
use Module::Pluggable search_path => 'MonClasse::Filters', sub_name => 'filters';
use Module::Pluggable search_path => 'MonClasse::Plugins', sub_name => 'plugins';

et plus tard ...

my @filters = $self->filters;
my @plugins = $self->plugins;

RECHERCHE DE PLUGINS

Chaque fois que vous appelez 'plugins', tout le chemin de recherche est parcouru à nouveau. Cela permet le chargement dynamique de plugins même au moment de l'exécution. Cependant, cela peut coûter cher et donc si vous ne vous attendez pas à vouloir ajouter de nouveaux plugins au moment de l'exécution, vous pourriez faire

package Foo;
use strict;
use Module::Pluggable sub_name => '_plugins';
our @PLUGINS;
sub plugins { @PLUGINS ||= shift->_plugins }
1;

PAQUETS INTERNES

Si vous avez, par exemple, un fichier lib/Something/Plugin/Foo.pm qui contient des définitions de paquets pour "Something::Plugin::Foo" et "Something::Plugin::Bar", alors tant que vous avez l'option require ou instantiate définie, nous trouverons également "Something::Plugin::Bar". Malin !

OPTIONS

Vous pouvez passer une table d'options lors de l'importation de ce module.

Les options peuvent être ...

nom_de_la_sous-routine

Le nom de la sous-routine à créer dans votre espace de noms.

Par défaut, c'est 'plugins'

chemin_de_recherche

Un tableau de références d'espaces de noms à rechercher.

repertoire_de_recherche

Un tableau de références de répertoires à rechercher avant @INC.

instancier

Appelle cette méthode sur la classe. En général, ce sera probablement 'new' mais cela peut être tout ce que vous voulez. Quels que soient les arguments passés à 'plugins', ils seront passés à la méthode.

La valeur par défaut est 'undef', c'est-à-dire qu'il renvoie simplement le nom de la classe.

exiger

Exige simplement la classe, ne l'instancie pas (remplace 'instancier');

interne

S'il est défini à 0, il ne recherchera pas les paquets internes. S'il est défini à 1, il remplacera "exiger".

seulement

Prend une chaîne de caractères, une référence de tableau ou une expression régulière décrivant les noms des seuls plugins à retourner. Bien que cela puisse sembler pervers... eh bien, ça l'est. Mais cela a aussi du sens. Faites-moi confiance.

sauf

Similaire à "seulement", il prend une description des plugins à exclure du retour. C'est légèrement moins pervers.

paquet

Ceci est destiné à être utilisé par les modules d'extension qui s'appuient sur "Module::Pluggable" : passer une option "paquet" vous permet de placer la méthode de plugin dans un package différent de votre propre package.

regex_fichier

Par défaut, "Module::Pluggable" ne recherche que les fichiers .pm.

En fournissant un nouveau "regex_fichier", vous pouvez modifier ce comportement, par exemple

regex_fichier => qr/\.plugin$/

inclure_poubelles_editeur

Par défaut, "Module::Pluggable" ignore les fichiers qui semblent avoir été laissés par les éditeurs. Cela signifie actuellement les fichiers se terminant par ~ (~), les extensions .swp ou .swo, ou les fichiers commençant par .#.

Définir "inclure_
