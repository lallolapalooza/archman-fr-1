Module::Build::Compat(3pm) Documentation Perl fournie par l'utilisateur Module::Build::Compat(3pm)

NOM

Module::Build::Compat - Compatibilité avec ExtUtils::MakeMaker

SYNOPSIS

# Dans un Build.PL :
use Module::Build;
my $build = Module::Build->new
  ( module_name => 'Foo::Bar',
    license     => 'perl',
    create_makefile_pl => 'traditional' );
...

DESCRIPTION

Étant donné que "ExtUtils::MakeMaker" a été la méthode standard de distribution des modules pendant longtemps, de nombreux outils (CPAN.pm, ou votre administrateur système) peuvent s'attendre à trouver un Makefile.PL fonctionnel dans chaque distribution qu'ils téléchargent depuis CPAN. Si vous voulez leur faciliter la tâche, vous pouvez utiliser "Module::Build::Compat" pour générer automatiquement un Makefile.PL pour vous, dans l'un de plusieurs styles différents.

"Module::Build::Compat" fournit également du code qui aide le Makefile.PL au moment de l'exécution.

AVERTISSEMENT

Notez que "Module::Build::Compat" cause plus souvent des problèmes d'installation qu'il n'en résout, et chacun des trois styles de génération de Makefile.PL a des problèmes de compatibilité ou de fonctionnalité uniques qui ne seront probablement pas corrigés. Par conséquent, l'utilisation de ce module et de "create_makefile_pl" est déconseillée.

MÉTHODES

create_makefile_pl($style, $build)
Crée un Makefile.PL dans le répertoire courant dans l'un de plusieurs styles, basé sur l'objet "Module::Build" fourni $build. Ceci est généralement contrôlé en passant le style désiré comme paramètre "create_makefile_pl" à la méthode new() de "Module::Build" ; le Makefile.PL sera alors automatiquement créé lors de l'action "distdir".

Les styles actuellement supportés sont :

traditional
Un Makefile.PL sera créé dans le style "traditionnel", c'est-à-dire qu'il utilisera "ExtUtils::MakeMaker" et ne dépendra pas du tout de "Module::Build". Pour créer le Makefile.PL, nous inclurons les dépendances "requires" et "build_requires" comme paramètre "PREREQ_PM".

Vous ne voulez pas utiliser ce style si, lors de l'étape "perl Build.PL", vous posez des questions à l'utilisateur, ou effectuez une détection automatique de l'environnement de l'utilisateur, ou si vous héritez de "Module::Build" pour effectuer une personnalisation, car le Makefile.PL simple ne fera rien de tout cela. De nombreuses fonctionnalités standard de "Module::Build" comme "test_requires" ne sont pas non plus prises en charge.

small
Un petit Makefile.PL sera créé qui transmettra toute la fonctionnalité au script Build.PL dans le même répertoire. L'utilisateur doit déjà avoir "Module::Build" installé pour pouvoir l'utiliser, sinon il recevra une erreur de type module introuvable.

Ce style tente (avec succès variable) de traduire le protocole Makefile.PL en Build.PL, et est inutile sur tout outillage moderne qui reconnaît les métadonnées "configure_requires" décrites ci-dessous, car Build.PL sera exécuté par défaut dans ce cas. Voir https://rt.cpan.org/Public/Bug/Display.html?id=75936 pour un exemple des problèmes qu'il peut causer.

passthrough (OBSOLÈTE)
Ceci est identique à l'option "small" ci-dessus, mais si "Module::Build" n'est pas déjà installé sur le système de l'utilisateur, le script proposera de l'utiliser "CPAN.pm" pour le télécharger et l'installer avant de continuer la construction.

Cette option a été dépréciée et pourrait être supprimée dans une future version de Module::Build. Les outils modernes CPAN.pm et CPANPLUS reconnaissent la propriété de métadonnées "configure_requires" et installent Module::Build avant d'exécuter Build.PL si Module::Build est listé et que Module::Build s'ajoute maintenant à configure_requires par défaut.

Perl 5.10.1 inclut la prise en charge de "configure_requires". À l'avenir, lorsque la prise en charge de "configure_requires" sera considérée comme suffisamment répandue, le style "passthrough" sera supprimé.

run_build_pl(args => \@ARGV)
Cette méthode exécute le script Build.PL, en lui passant tous les arguments que l'utilisateur aurait pu fournir à la commande "perl Makefile.PL". Parce que "ExtUtils::MakeMaker" et "Module::Build" acceptent des arguments différents, cette méthode effectue également une certaine traduction entre les deux.

run_build_pl() accepte les paramètres nommés suivants :

args
Le paramètre "args" spécifie les paramètres qui apparaîtraient normalement sur la ligne de commande de la commande "perl Makefile.PL" - typiquement, vous passerez juste une référence à @ARGV.
script
C'est le nom du fichier du script à exécuter - il vaut par défaut "Build.PL".
write_makefile()
Cette méthode écrit un Makefile 'factice' qui transmettra toutes les commandes aux actions correspondantes de "Module::Build".

write_makefile() accepte les paramètres nommés suivants :

makefile
Le nom du fichier à écrire - il vaut par défaut la chaîne de caractères "Makefile".

SCÉNARIOS

Voici donc quelques scénarios courants :

1.
Inclure simplement un script Build.PL (sans script Makefile.PL), et donner les instructions d'installation dans un document README ou INSTALL expliquant comment installer le module. En particulier, expliquer que l'utilisateur doit installer "Module::Build" avant d'installer votre module.

Notez que si vous faites cela, vous pourriez vous faciliter la tâche, mais compliquer celle des personnes ayant des versions plus anciennes de CPAN ou CPANPLUS sur leur système, car ces outils ne comprennent généralement que la méthode Makefile.PL/"ExtUtils::MakeMaker".

2.
Inclure un script Build.PL et un Makefile.PL "traditionnel", créé manuellement ou avec create_makefile_pl(). Les utilisateurs n'auront jamais besoin d'installer "Module::Build" s'ils utilisent le Makefile.PL, mais ils ne pourront pas non plus profiter des fonctionnalités supplémentaires de "Module::Build".

Pour faire bonne mesure, bien sûr, testez à la fois le Makefile.PL et le Build.PL avant de distribuer.

3.
Inclure un script Build.PL et un Makefile.PL "pass-through" construit avec "Module::Build::Compat". Cela signifie que les personnes pourront continuer

NOM

Module::Build::Compat

SYNOPIS

use Module::Build::Compat;

DESCRIPTION

Module::Build::Compat est un module de compatibilité pour Module::Build.

AVERTISSEMENT

Ce module n'est pas entièrement testé et peut contenir des bugs.

MÉTHODES

Ce module fournit les méthodes suivantes :

  • compat()

  • compat_build()

  • compat_clean()

  • compat_install()

  • compat_run()

SCÉNARIOS

Ce module est utile dans les scénarios suivants :

  • Compatibilité avec les anciennes versions de CPAN et CPANPLUS.

  • Utilisation avec Module::Build.

  • Utilisation avec ExtUtils::MakeMaker.
