NOM

Module::Build::Bundling - Comment regrouper Module::Build avec une distribution

SYNOPSIS

# Build.PL
use inc::latest 'Module::Build';
Module::Build->new(
  module_name => 'Foo::Bar',
  license => 'perl',
)->create_build_script;

DESCRIPTION

ATTENTION -- CECI EST UNE FONCTIONNALITÉ EXPÉRIMENTALE

Pour installer une distribution utilisant Module::Build, les utilisateurs doivent avoir Module::Build disponible sur leurs systèmes. Il y a deux façons de faire cela. La première consiste à inclure Module::Build dans le champ de métadonnées "configure_requires". Ce champ est pris en charge par les versions récentes de CPAN et CPANPLUS et est une fonctionnalité standard du cœur de Perl à partir de Perl 5.10.1. Module::Build s'ajoute maintenant à "configure_requires" par défaut.

La seconde méthode prend en charge les anciens Perl qui n'ont pas mis à niveau CPAN ou CPANPLUS et implique le regroupement d'une copie entière de Module::Build dans le répertoire "inc/" de la distribution. C'est la même approche utilisée par Module::Install, un wrapper moderne autour de ExtUtils::MakeMaker pour les distributions basées sur Makefile.PL.

L'« astuce » pour faire fonctionner cela pour Module::Build est de s'assurer que la version la plus récente de Module::Build est utilisée, qu'elle soit dans "inc/" ou déjà installée sur le système de l'utilisateur. Cela garantit que toutes les fonctionnalités nécessaires sont disponibles ainsi que les nouvelles corrections de bogues. Ceci est fait en utilisant le module expérimental inc::latest, disponible sur CPAN.

Un Build.PL « normal » ressemble à ceci (avec seulement les champs requis minimum) :

use Module::Build;
Module::Build->new(
  module_name => 'Foo::Bar',
  license     => 'perl',
)->create_build_script;

Un Build.PL de « regroupement » remplace la ligne « use » initiale par un remplacement presque transparent :

use inc::latest 'Module::Build';
Module::Build->new(
  module_name => 'Foo::Bar',
  license => 'perl',
)->create_build_script;

Pour les auteurs, lorsque « Build dist » est exécuté, Module::Build sera automatiquement regroupé dans "inc" selon les règles de inc::latest.

Pour les utilisateurs, inc::latest chargera la dernière version de Module::Build, qu'elle soit installée ou regroupée dans "inc/".

REGROUPEMENT D'AUTRES DÉPENDANCES DE CONFIGURATION

La même approche fonctionne pour d'autres dépendances de configuration -- modules qui *doivent* être disponibles pour que Build.PL s'exécute. Toutes les autres dépendances peuvent être spécifiées comme d'habitude dans Build.PL et CPAN ou CPANPLUS les installera après que Build.PL soit terminé.

Par exemple, pour regrouper le module Devel::AssertOS::Unix (qui assure un système d'exploitation « de type Unix »), on pourrait faire ceci :

use inc::latest 'Devel::AssertOS::Unix';
use inc::latest 'Module::Build';
Module::Build->new(
  module_name => 'Foo::Bar',
  license => 'perl',
)->create_build_script;

Le module "inc::latest" crée des répertoires groupés basés sur le fichier packlist d'une distribution installée. Même si "inc::latest" prend des arguments de nom de module, il est préférable de le considérer comme le regroupement et la mise à disposition d'intégralités *distributions*. Lorsqu'un module est chargé via "inc::latest", il recherche dans toutes les distributions regroupées dans "inc/" un module plus récent que celui qui peut être trouvé dans le tableau @INC existant.

Ainsi, le nom de module fourni devrait généralement être le nom du module « de haut niveau » d'une distribution, bien que ce ne soit pas strictement requis. Par exemple, Module::Build a un certain nombre d'heuristiques pour mapper les noms de modules aux fichiers packlist, permettant aux utilisateurs de faire des choses comme ceci :

use inc::latest 'Devel::AssertOS::Unix';

même si Devel::AssertOS::Unix est contenu dans la distribution Devel-CheckOS.

À l'heure actuelle, les fichiers packlist sont requis. Ainsi, le regroupement de modules double-cœur, *y compris Module::Build*, peut nécessiter une « installation forcée » sur les versions du dernier Perl afin de créer le fichier packlist nécessaire pour le regroupement. Cette limitation sera, espérons-le, résolue dans une future version de Module::Build.

ATTENTION -- Comment gérer les chaînes de dépendances

Avant de regrouper une distribution, vous devez vous assurer que toutes les prérequis sont également regroupés et qu'ils se chargent dans le bon ordre. Pour Module::Build lui-même, cela ne devrait pas être nécessaire, mais c'est nécessaire pour toute autre distribution. (Une future version de Module::Build devrait, espérons-le, résoudre cette lacune.)

Par exemple, si vous avez besoin de "Wibble", mais que "Wibble" dépend de "Wobble", votre Build.PL pourrait ressembler à ceci :

use inc::latest 'Wobble';
use inc::latest 'Wibble';
use inc::latest 'Module::Build';
Module::Build->new(
  module_name => 'Foo::Bar',
  license => 'perl',
)->create_build_script;

Il est fortement suggéré aux auteurs de limiter autant que possible le regroupement de dépendances supplémentaires et de tester soigneusement leurs archives de distribution sur d'anciennes versions de Perl avant de les télécharger sur CPAN.
