NOM

Module::Manifest - Analyse et examine un fichier MANIFEST de distribution Perl

VERSION

version 1.09

SYNOPSIS

Ouvrir et analyser un fichier MANIFEST et MANIFEST.SKIP :

my $manifest = Module::Manifest->new( 'MANIFEST', 'MANIFEST.SKIP' );

Vérifier si un fichier donné correspond à l'un des motifs d'exclusion connus :

print "yes\n" if $manifest->skipped('.svn');

DESCRIPTION

Module::Manifest est un module simple créé à l'origine pour être utilisé dans Module::Inspector.

Il peut charger un fichier MANIFEST qui est inclus dans une archive tar d'une distribution Perl, examiner son contenu et effectuer quelques tâches simples. Il peut également charger le fichier MANIFEST.SKIP et le vérifier.

Bien que les fonctionnalités nécessaires pour cela soient assez simples, le schéma de spécification MANIFEST de distribution Perl contient un certain nombre de particularités, telles que les commentaires en ligne et les commentaires séparés par des espaces.

L'utilisation de ce module implique que tous les petits détails sont gérés en arrière-plan, vous permettant de concentrer votre tâche principale sur ce qui compte vraiment.

Comparaison avec ExtUtils::Manifest

Ce module est assez similaire à ExtUtils::Manifest, ou du moins dans son champ d'application. Cependant, il y a une différence générale dans la méthodologie.

ExtUtils::Manifest est impératif, nécessite l'existence du fichier MANIFEST actuel sur le disque, et exige que votre répertoire actuel reste le même.

Module::Manifest traite le fichier MANIFEST comme un objet, peut charger le fichier depuis n'importe quel endroit sur le disque, et peut effectuer certaines des mêmes fonctionnalités sans avoir à changer le contexte du répertoire actuel.

Bien qu'il soit dit ainsi, vous devez savoir que Module::Manifest est destiné à lire et vérifier les fichiers MANIFEST existants, plutôt qu'à en créer de nouveaux.

COMPATIBILITÉ

Ce module devrait être compatible avec Perl 5.005 et versions ultérieures. Cependant, il n'a été rigoureusement testé que sur Perl 5.10.0 sous Linux.

Si vous rencontrez des problèmes sur une version ou une architecture différente, veuillez contacter le mainteneur.

MÉTHODES

new

Module::Manifest->new( $manifest, $skip )

Crée un objet "Module::Manifest", qui analyse soit les fichiers référencés par $manifest (pour MANIFEST) et $skip (pour MANIFEST.SKIP). S'il n'y a pas de paramètres, il crée un objet vide.

Exemple de code :

my $manifest = Module::Manifest->new;
my $manifest = Module::Manifest->new( $manifest );
my $manifest = Module::Manifest->new( $manifest, $skip );

Cette méthode renvoie un objet Module::Manifest approprié ou lance une exception en cas d'erreur.

open

$manifest->open( $type => $filename )

Ouvre et analyse le fichier donné par $filename, qui peut être un chemin relatif. Les options disponibles pour $type sont 'skip' ou 'manifest'.

Exemple de code :

$manifest->open( skip => 'MANIFEST.SKIP' );
$manifest->open( manifest => 'MANIFEST' );

Cette méthode ne renvoie rien, mais peut lancer une exception en cas d'erreur.

parse

$manifest->parse( $type => \@files )

Analyse "\@files", qui est une référence de tableau contenant une liste de fichiers ou de motifs d'expressions régulières. Les options disponibles pour $type sont 'skip' ou 'manifest'.

Exemple de code :

$manifest->parse( skip => [
     '\B\.svn\b',
     '^Build$',
     '\bMakefile$',
]);

Cette méthode ne renvoie rien, mais peut lancer une exception en cas d'erreur.

skipped

$manifest->skipped( $filename )

Vérifie si $filename correspond à l'un des motifs qui devraient être ignorés, étant donné les expressions régulières fournies aux méthodes "parse" ou "open".

Les chemins absolus doivent être relativisés et convertis en une chaîne de chemin de style Unix en utilisant la méthode "normalize".

Exemple de code :

if ($manifest->skipped('Makefile.PL')) {
  # faire quelque chose
}

Cette méthode renvoie une valeur booléenne indiquant si le chemin doit être ignoré selon le motif "skipfile".

normalize

Module::Manifest->normalize( $path, $rel )
$manifest->normalize( $path, $rel )

Cette méthode prend un chemin spécifique à la plateforme et le convertit en une chaîne de chemin de style Unix compatible avec les schémas MANIFEST et MANIFEST.SKIP.

Note : Cette méthode normalise les chemins en fonction de la plateforme détectée par $^O — c'est-à-dire que les chemins Win32 peuvent être normalisés uniquement si le module s'exécute sous Win32.

Par défaut, cette méthode relativise les chemins de fichiers par rapport au répertoire actuel (en utilisant la méthode "abs2rel" de File::Spec sans $root). Pour désactiver cette action, définissez $rel à une valeur fausse.

Exemple de code :

# utile pour normaliser les chemins Win32
my $normal = Module::Manifest->normalize('t\\test\\file');
# renvoie : t/test/file (en style Unix pour MANIFEST)

Renvoie une version normalisée du chemin donné.

file

$manifest->file

L'accesseur "file" renvoie le chemin absolu du fichier MANIFEST qui a été chargé.

skipfile

$manifest->skipfile

L'accesseur "skipfile" renvoie le chemin absolu du fichier MANIFEST.SKIP qui a été chargé.

dir

$manifest->dir

L'accesseur "dir" renvoie le chemin du répertoire qui contient le fichier MANIFEST ou le fichier skip, et devrait donc être la racine de la distribution.

files

$manifest->files

La méthode "files" renvoie la liste (relative, style Unix) des fichiers dans le manifest. En contexte scalaire, elle renvoie le nombre de fichiers dans le manifest.

Exemple de code :

my @files = $manifest->files;

LIMITATIONS

Le chemin renvoyé par la méthode "dir" est écrasé chaque fois que la méthode "open" est appelée. Cela signifie que, si MANIFEST et MANIFEST.SKIP ne sont pas dans le même répertoire, le module peut être un peu confus.
