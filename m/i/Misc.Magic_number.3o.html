Module Magic_number
: sig end

un nombre magique typique est "Caml1999I011"; il est formé d'un préfixe alphanumérique, ici Caml1990I, suivi d'une version, ici 011. Le préfixe identifie le type des données versionnées : ici le I indique qu'il s'agit du nombre magique pour les fichiers .cmi.

Tous les nombres magiques ont la même longueur en octets, magic_length , et cela est important pour les utilisateurs car cela leur donne le nombre d'octets à lire pour obtenir la séquence d'octets qui devrait être un nombre magique. Un code utilisateur typique ressemblera à ceci:

        let ic = open_in_bin path in
        let magic =
          try really_input_string ic Magic_number.magic_length
          with End_of_file -> ... in
        match Magic_number.parse magic with
        | Error parse_error -> ...
        | Ok info -> ...

Une version donnée du compilateur attend une version spécifique pour chaque type de fichier objet, et échouera si elle reçoit une version non prise en charge. Comme les versions augmentent de manière monotone, vous pouvez comparer la version analysée avec la "version actuelle" attendue pour un type, afin de déterminer si le fichier objet au nombre magique incorrect provient du passé ou du futur.

Un exemple de bloc de code qui attend la "version actuellement prise en charge" d'un type donné de nombres magiques, ici Cmxa , est le suivant:

        let ic = open_in_bin path in
        begin
          try Magic_number.(expect_current Cmxa (get_info ic)) with
          | Parse_error error -> ...
          | Unexpected error -> ...
        end;
        ...

Les erreurs d'analyse distinguent les entrées qui sont Not_a_magic_number str , qui proviennent probablement d'un fichier complètement différent, et Truncated str , levée par des en-têtes qui sont le préfixe (éventuellement vide) d'un nombre magique valide.

Les erreurs inattendues correspondent à des nombres magiques valides qui ne sont pas ceux attendus, soit parce qu'ils correspondent à un type différent, soit à une version plus récente ou plus ancienne.

Les fonctions d'aide explain_parse_error et explain_unexpected_error généreront une explication textuelle de chaque erreur, à utiliser dans les messages d'erreur.

Analyse des nombres magiques

type parse_error =
| Truncated of string
| Not_a_magic_number of string

val explain_parse_error : kind option -> parse_error -> string

Produit une explication pour une erreur d'analyse. Si aucun type n'est fourni, nous utilisons une formulation non spécifique suggérant que tout fichier objet produit par le compilateur aurait été satisfaisant.

val parse : raw -> (info, parse_error) result

Analyse un nombre magique brut

val read_info : in_channel -> (info, parse_error) result

Lit un nombre magique brut à partir d'un canal d'entrée.

Si les données lues str ne constituent pas un nombre magique valide, elles peuvent être récupérées à partir de la charge utile Truncated str | Not_a_magic_number str du cas Error parse_error .

Si l'analyse réussit avec un résultat Ok info , nous savons que exactement magic_length octets ont été consommés du canal d'entrée.

Si vous souhaitez également vous assurer que le nombre magique correspond à la version actuelle, voir Misc.Magic_number.read_current_info ci-dessous.

val magic_length : int

tous les nombres magiques prennent le même nombre d'octets

type unexpected_error =

| Version of kind * version unexpected

val check_current : kind -> info -> (unit, unexpected_error) result

check_current kind info vérifie que les info magiques fournies correspondent à la version actuelle de l'en-tête magique de kind.

val explain_unexpected_error : unexpected_error -> string

Fournit une explication de l'unexpected_error.

type error =
| Parse_error of parse_error
| Unexpected_error of unexpected_error

val read_current_info : expected_kind:kind option -> in_channel -> (info, error) result

Lit un nombre magique comme read_info , et vérifie qu'il est de la version actuelle de son type. Si l'argument expected_kind est None , n'importe quel type est accepté.

Représentations brutes

Principalement pour un usage interne et des tests.

type raw_kind = string

le type des types de nombres magiques bruts, tels que "Caml1999A" pour les fichiers .cma

val parse_kind : raw_kind -> kind option

analyse un type brut en un type

val raw_kind : kind -> raw_kind

la représentation brute actuelle d'un type.

Dans certains cas, la représentation brute d'un type a changé au fil des versions du compilateur, de sorte que d'autres fichiers du même type peuvent avoir des types bruts différents. Notez que tous les cas actuellement connus sont analysés correctement par parse_kind.

val raw : info -> raw

Une représentation brute valide du nombre magique.

En raison des changements passés et futurs dans la représentation textuelle des nombres magiques, nous ne pouvons garantir que les chaînes brutes renvoyées pour les versions passées et futures correspondent réellement aux attentes de ces compilateurs. La représentation est exacte pour les versions actuelles, et elle est correctement analysée pour revenir au type souhaité par les fonctions d'analyse ci-dessus.
