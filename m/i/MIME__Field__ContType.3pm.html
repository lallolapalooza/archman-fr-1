MIME::Field::ContType(3) Documentation Perl fournie par l'utilisateur MIME::Field::ContType(3)

NOM

MIME::Field::ContType - un champ "Content-type"

DESCRIPTION

Une sous-classe de Mail::Field.

N'utilisez pas cette classe directement... son nom peut changer à l'avenir ! Demandez plutôt à Mail::Field de nouvelles instances basées sur le nom du champ !

SYNTAXE

use Mail::Field;
use MIME::Head;
# Créer une instance à partir de texte :
$field = Mail::Field->new('Content-type',
                          'text/HTML; charset="US-ASCII"');
# Obtenir le type MIME, comme 'text/plain' ou 'x-foobar'.
# Retourne 'text/plain' par défaut, conformément à la RFC 2045 :
my ($type, $subtype) = split('/', $field->type);
# Obtenir des informations générales :
print $field->name;
# Obtenir des informations liées au type "message" :
if ($type eq 'message') {
    print $field->id;
    print $field->number;
    print $field->total;
}
# Obtenir des informations liées au type "multipart" :
if ($type eq 'multipart') {
    print $field->boundary;            # la valeur de base, corrigée
    print $field->multipart_boundary;  # vide si ce n'est pas un message multipart !
}
# Obtenir des informations liées au type "text" :
if ($type eq 'text') {
    print $field->charset;      # retourne 'us-ascii' par défaut
}

INTERFACE PUBLIQUE

boundary
Retourne le champ boundary. Le boundary est retourné exactement tel qu'il est fourni dans le champ "Content-type:" ; c'est-à-dire que les deux tirets précédents ("--") ne sont *pas* préfixés.

(Enfin, *presque* exactement... selon la RFC 2046 :

(Si un boundary semble se terminer par un espace blanc, l'espace blanc
doit être présumé avoir été ajouté par une passerelle, et doit être supprimé.)

nous nous conformons donc et supprimons tous les espaces en queue de chaîne.)

Retourne une chaîne vide s'il n'y a pas de boundary, ou si le boundary est illégal (par exemple, s'il est vide après suppression de tous les espaces blancs en queue de chaîne).

multipart_boundary
Comme boundary(), sauf que cela retournera également une chaîne vide si le message n'est pas un message multipart. En d'autres termes, il y a une vérification automatique de la cohérence.
type
Essaye de déterminer le type de contenu (par exemple, "text/plain", "image/gif", "x-weird-type", qui est retourné en minuscules.

Une chose agréable : le code suivant fonctionnera comme vous le souhaitez, même s'il n'y a pas de sous-type (comme dans "x-weird-type")... dans ce cas, le $subtype serait simplement une chaîne vide :

($type, $subtype) = split('/', $head->mime_type);

Si l'information content-type est manquante, elle prend par défaut "text/plain", conformément à la RFC 2045 :

Les messages RFC 2822 par défaut sont typés par ce protocole comme du texte brut dans
l'ensemble de caractères US-ASCII, ce qui peut être explicitement spécifié comme
"Content-type: text/plain; charset=us-ascii". Si aucun Content-Type n'est
spécifié, ce défaut est supposé.

Note : selon le principe "soyez libéral dans ce que nous acceptons", cette routine ne vérifie plus la syntaxe du type de contenu. Si ce n'est pas vide, il suffit de le mettre en minuscules et de le retourner.

NOTES

Puisque presque tous (sinon tous) les paramètres doivent avoir des valeurs non vides pour être considérés comme valides, nous retournons simplement une chaîne vide pour signaler les champs manquants. Si vous avez besoin d'obtenir la valeur sous-jacente *réelle*, utilisez la méthode héritée param() (qui retourne undef si le paramètre est manquant).
