NOM

MIME::Parser::Filer - gérer le fichier de sortie du parseur

SYNOPIS

Avant de continuer, vous devriez regarder MIME::Parser pour vous assurer que vous comprenez où ce module s'intègre dans le schéma général des choses. Allez-y, faites-le maintenant. Je vais attendre.

Prêt ? Ok... maintenant lisez "DESCRIPTION" ci-dessous, et tout le reste devrait avoir du sens.

Interface publique

### Crée un "filer" de la classe souhaitée :
my $filer = MIME::Parser::FileInto->new($dir);
my $filer = MIME::Parser::FileUnder->new($basedir);
...
### Pour ajouter une sécurité, ne laissez pas les externes nommer vos fichiers :
$filer->ignore_filename(1);
### Préparez-vous pour le parsing d'un nouveau message de haut niveau :
$filer->init_parse;
### Renvoie le chemin où les données de ce message devraient aller :
$path = $filer->output_path($head);

Interface semi-publique

Ces méthodes peuvent être écrasées ou ignorées dans certaines sous-classes, donc elles ne sont pas toujours valides dans tous les cas :

### Ajustez la correspondance type de contenu vers extension :
$emap = $filer->output_extension_map;
$emap->{"text/html"} = ".htm";

DESCRIPTION

Comment cette classe est utilisée lors du parsing

Quand un MIME::Parser décide qu'il veut écrire un fichier sur disque, il utilise son objet "Filer" - une instance d'une classe sous-classe de MIME::Parser::Filer - pour déterminer où placer le fichier.

Chaque parseur a un objet Filer unique, qu'il utilise pour tout le parsing. Vous pouvez obtenir le Filer pour un $parser comme ceci :

$filer = $parser->filer;

Au début de chaque parse(), l'état interne du filer est réinitialisé par le parseur :

$parser->filer->init_parse;

Ensuite, le parseur peut obtenir un chemin pour chaque entité dans le message en remettant l'en-tête (un MIME::Head) au filer, et en le faisant travailler, comme ceci :

$new_file = $parser->filer->output_path($head);

Puisqu'il est agréable de pouvoir nettoyer après un parse (surtout un parse raté), le parseur dit au filer quand il a effectivement utilisé un chemin :

$parser->filer->purgeable($new_file);

Ensuite, si vous voulez nettoyer les fichiers qui ont été créés pour un parse particulier (et aussi tous les répertoires que le Filer a créés), vous feriez ceci :

$parser->filer->purge;

Écrire vos propres sous-classes

Il existe deux classes "Filer" standard (voir ci-dessous) : MIME::Parser::FileInto, qui lance tous les fichiers de tous les parses dans un même répertoire, et MIME::Parser::FileUnder (préféré), qui crée un sous-répertoire pour chaque message. Nous espérons qu'ils suffiront pour la plupart des usages, mais juste au cas où vous auriez besoin...

La seule méthode que vous devez écraser est output_path() :

$filer->output_path($head);

Cette méthode est appelée par MIME::Parser quand il veut mettre le corps d'un message décrypté dans un fichier de sortie. Elle doit renvoyer un chemin pour créer le fichier. L'échec est indiqué en lançant une exception.

Le chemin renvoyé par output_path() doit être "prêt pour open()" : tous les répertoires parents nécessaires doivent exister à ce moment. Ces répertoires peuvent être créés par le Filer, si vous le souhaitez, et doivent être marqués comme purgeable() s'ils doivent être supprimés.

En fait, si votre problème est plus où vont les fichiers que comment ils s'appellent, vous pouvez utiliser la méthode par défaut output_path() et juste écraser une de ses parties :

$dir  = $filer->output_dir($head);
$name = $filer->output_filename($head);
...

INTERFACE PUBLIQUE

MIME::Parser::Filer

C'est la super-classe abstraite de tous les objets "filer".

new INITARGS...
Méthode de classe, constructeur. Crée un nouveauuteur de sortie pour le parseur donné. Tous les arguments suivants sont transmis à init(), que les sous-classes doivent écraser pour leur propre usage (l'init par défaut ne fait rien).
results RESULTS
Méthode d'instance. Connecte ce filer à un objet MIME::Parser::Results qui va quantifier les messages. Notez que nous évitons de le connecter au parseur pour éviter une référence circulaire !
init_parse
Méthode d'instance. Prépare le début du parsing d'un nouveau message. Les sous-classes doivent s'assurer d'appeler la méthode héritée.
evil_filename NOM_FICHIER
Méthode d'instance. Est-ce un nom de fichier indésirable ; c'est-à-dire un qui ne devrait pas être utilisé comme nom de fichier sur disque ? Si l'un des éléments suivants est vrai : 
* il est vide ou seulement composé d'espaces
* il contient des espaces au début ou à la fin
* c'est une chaîne de points : ".", "..", etc.
* il contient des caractères non présents dans l'ensemble : "A" - "Z", "a" - "z",
  "0" - "9", "-", "_", "+", "=", ".", ",", "@", "#",
  "$", et " ".
* il est trop long

Si vous voulez changer ce comportement, vous devriez écraser cette méthode dans la sous-classe de MIME::Parser::Filer que vous utilisez.

Note : Les sous-classes de MIME::Parser::Filer qui écrasent output_path() pourraient ne pas appeler cette méthode ; cependant, notez que les substituts internes appellent cette méthode.

Merci à Andrew Pimlott pour avoir trouvé un véritable bug dans la version originale. Merci à Nickolay Saukh pour avoir noté que le mal est dans l'œil de celui qui regarde.

exorcise_filename NOM_FICHIER
Méthode d'instance. Si un nom donné est indésirable (voir "evil_filename"), nous essayons de le sauver en effectuant quelques opérations basiques : tronquer le nom, supprimer les caractères indésirables, etc., et en vérifiant chacun contre evil_filename().

Renvoie le nom sauvé (qui est garanti de ne pas être indésirable), ou undef s'il n'a pas pu être sauvé.

Avertissement : au moment où cette méthode est appelée, le NOM_FICHIER a déjà été décrypté dans l'ensemble de caractères locaux. Si vous utilisez un ensemble de caractères autre que ASCII, ISO-8859-*, ou UTF-8, l'interprétation des caractères de "chemin" peut être très différente, et vous devrez écraser cette méthode. Voir "unmime" dans MIME::WordDecoder pour plus de détails.

find_unused_path DIR, NOM_FICHIER
Méthode d'instance, pour les sous-classes uniquement. Nous avons décidé d'un répertoire de sortie et d'un nom de fichier provisoire, mais il y a une chance qu'il existe déjà. Ajoute un suffixe numérique "-1", "-2", etc., au nom jusqu'à ce que nous trouvions un chemin inutilisé, puis renvoie ce chemin.

Le suffixe est ajouté avant le premier "." dans le nom s'il y en a un ; par exemple :

picture.gif       archive.tar.gz      readme
picture-1.gif     archive-1.tar.gz    readme-1
picture-2.gif     archive-2.tar.gz    readme-2
...               ...                 ...
picture-10.gif
...

Cela peut être une opération coûteuse et risquée si vous ne voulez pas renommer les fichiers, il est donc dans votre meilleur intérêt de minimiser les situations où ces collisions se produisent. Cependant, si un message multipartite donne à toutes ses parties...

NOM

MIME::Parser::Filer - le classe de base pour le dépôt de fichiers

SYNOPSIS

    use MIME::Parser;
    $parser = MIME::Parser->new();
    $parser->filer( 'MIME::Parser::FileInto' => '/tmp/foo' );
    # ou
    $parser->filer( 'MIME::Parser::FileUnder' => '/tmp/foo' );
    # ou
    $parser->filer( 'MonFiler' => &ma_fonction_de_choix_du_chemin );
    # ou
    $parser->filer( 'MonFiler' ); # si MonFiler est une sous-classe de MIME::Parser::Filer
    
    # ... plus tard ...
    
    $head = $parser->parse_open($msg);
    if ($head) {
        print "saved to: ", $head->output_path, "\n";
    }

DESCRIPTION

Un objet MIME::Parser::Filer est responsable de décider où et sous quel nom les parties de corps des messages MIME sont enregistrées. Le comportement par défaut est d'enregistrer les fichiers dans le répertoire courant, en utilisant le nom de fichier recommandé dans l'en-tête de la partie, en s'assurant qu'il n'y a pas de collision avec des fichiers existants.

Vous pouvez remplacer le classe de filer utilisée par le parser en appelant la méthode filer() sur l'objet parser. Ceci peut être fait soit avec une chaîne indiquant le nom de la classe de filer à utiliser (elle doit être une sous-classe de MIME::Parser::Filer), soit avec une chaîne représentant le nom de la classe et une fonction qui sera appelée pour déterminer le chemin de sortie, soit avec une chaîne représentant le nom de la classe et des arguments pour son initialiseur.

Vous n'avez probablement pas besoin de vous soucier de ces classes à moins que vous n'utilisiez pas les classes par défaut MIME::Parser::FileInto ou MIME::Parser::FileUnder.

INTERFACE PUBLIQUE

Les classes de filtres implémentent les méthodes suivantes:

evil_filename FILENAME
Méthode d'instance. Retourne vrai si FILENAME est jugé comme étant "mauvais" (par exemple, s'il contient des caractères non autorisés, ou s'il est vide, ou s'il est une séquence de points, ou s'il est trop long, etc.). Avec un argument, définit cette valeur. La valeur par défaut est de considérer comme mauvais les noms de fichier contenant des caractères non-ASCII ou des caractères de contrôle.
find_unused_path DIRECTORY, FILENAME
Méthode d'instance. Trouve un nom de fichier inutilisé dans DIRECTORY, en utilisant FILENAME comme base. S'il n'y a pas de collision, il retourne DIRECTORY/FILENAME. Sinon, il essaie DIRECTORY/FILENAME.1, puis DIRECTORY/FILENAME.2, etc., jusqu'à ce qu'il en trouve un inutilisé. Retourne le chemin complet du fichier.
output_dir HEAD
Méthode d'instance. Retourne le répertoire de sortie pour l'en-tête donné. La méthode par défaut retourne ".".

Note: Si vous vous attendez à ce que les noms de fichiers recommandés soient les mêmes pour chaque message, et que vous les placez tous dans le même répertoire, cette méthode pourrait être inévitable.

ignore_filename [YESNO]
Méthode d'instance. Retourne vrai si nous devons toujours ignorer les noms de fichiers recommandés dans les messages, en choisissant plutôt de générer toujours nos propres noms de fichiers. Avec un argument, définit cette valeur.

Note: les sous-classes de MIME::Parser::Filer qui redéfinissent output_path() pourraient ne pas honorer ce paramètre ; notez cependant que les sous-classes intégrées l'honorent.

output_dir HEAD
Méthode d'instance. Retourne le répertoire de sortie pour l'en-tête donné. La méthode par défaut retourne ".".
output_filename HEAD
Méthode d'instance, sous-classes uniquement. Un nom de fichier recommandé donné n'a pas été fourni, ou il a été jugé comme étant mauvais. Retourne un nom bidon, utilisant éventuellement des informations de l'en-tête du message HEAD. Notez qu'il s'agit juste du nom du fichier, pas du chemin complet.

Utilisé par output_path(). Si vous utilisez la valeur par défaut de output_path(), vous n'avez probablement pas à vous soucier d'éviter les collisions avec des fichiers existants ; nous nous en chargeons dans find_unused_path().

output_prefix [PREFIX]
Méthode d'instance. Obtient la courte chaîne par laquelle tous les noms de fichiers pour les parties de corps extraites commenceront (en supposant qu'il n'y ait pas de meilleur "nom de fichier recommandé"). La valeur par défaut est "msg".

Si PREFIX n'est pas donné, le préfixe de sortie actuel est retourné. Si PREFIX est donné, le préfixe de sortie est défini à la nouvelle valeur, et la valeur précédente est retournée.

Utilisé par output_filename().

Note: les sous-classes de MIME::Parser::Filer qui redéfinissent output_path() ou output_filename() pourraient ne pas honorer ce paramètre ; notez cependant que les sous-classes intégrées l'honorent.

output_type_ext
Méthode d'instance. Retourne une référence au hash utilisé par la valeur par défaut de output_filename() pour mapper les types de contenu aux extensions lorsqu'il n'y a pas d'extension par défaut à utiliser. 
$emap = $filer->output_typemap;
$emap->{'text/plain'} = '.txt';
$emap->{'text/html'}  = '.html';
$emap->{'text/*'}     = '.txt';
$emap->{'*/*'}        = '.dat';

Note: les sous-classes de MIME::Parser::Filer qui redéfinissent output_path() ou output_filename() pourraient ne pas consulter ce hash ; notez cependant que les sous-classes intégrées le consultent.

output_path HEAD
Méthode d'instance, sous-classes uniquement. Étant donné un en-tête MIME d'un fichier à extraire, trouvez un bon chemin de sortie pour le fichier extrait. C'est la seule méthode dont vous devez vous soucier si vous créez un filtre personnalisé.

L'implémentation par défaut effectue beaucoup de travail ; les implémenteurs de sous-classes devraient vraiment essayer de simplement redéfinir ses composants au lieu de l'ensemble.

$directory = $self->output_dir($head);
$filename = $head->recommended_filename();
if (!$filename or
     $self->ignore_filename() or
     $self->evil_filename($filename)) {
    $filename = $self->output_filename($head);
}
return $self->find_unused_path($directory, $filename);

Note: Il existe de nombreuses façons dont vous pourriez vouloir contrôler la dénomination des fichiers, en fonction de votre application. Si le comportement de cette fonction ne vous plaît pas, vous pouvez facilement définir votre propre sous-classe de MIME::Parser::Filer et la redéfinir là.

Note: Nickolay Saukh a souligné que, compte tenu de la nature subjective de ce qui est "mauvais", cette fonction ne devrait pas réellement avertir d'un nom de fichier mauvais, mais peut-être émettre seulement un message de débogage. J'y ai réfléchi, mais ensuite j'ai pensé : si le débogage était désactivé, les gens ne sauraient pas pourquoi (ni même si) un nom de fichier donné a été ignoré. Dans les robots de messagerie qui dépendent des noms de fichiers fournis extérieurement, cela pourrait causer des problèmes difficiles à diagnostiquer. Le message reste donc un avertissement.

Merci à Laurent Amon d'avoir signalé des problèmes avec l'implémentation originale et d'avoir fait de bonnes suggestions. Merci également à Achim Bohnet d'avoir souligné qu'il devrait y avoir un moyen purement orienté objet de redéfinir le chemin de sortie.

purge
Méthode d'instance, finale. Nettoie tous les fichiers/répertoires créés par la dernière analyse. Cette méthode parcourt simplement la liste des fichiers/répertoires à nettoyer dans l'ordre inverse (voir "purgeable") et supprime tous les fichiers/répertoires existants qui y figurent. Vous ne devriez pas avoir besoin de redéfinir cette méthode.
purgeable [FILE]
Méthode d'instance, finale. Ajoute FILE à la liste des fichiers/répertoires "à nettoyer" (ceux qui seront supprimés si vous appelez purge()). Vous ne devriez pas avoir besoin de redéfinir cette méthode.

Si FILE n'est pas donné, la liste "à nettoyer" est retournée. Ceci peut être utilisé pour un nettoyage plus sophistiqué.

À titre de cas spécial, l'invocation de cette méthode avec un FILE qui est un ref d'array remplacera la liste à nettoyer par une copie du contenu de l'array, ainsi [] peut être utilisé pour vider la liste.

Notez que la liste "à nettoyer" est vidée lorsqu'un parser commence une nouvelle analyse ; par conséquent, si vous voulez utiliser purge() pour le nettoyage, vous devez le faire avant de commencer une nouvelle analyse !

MIME::Parser::FileInto

Cette sous-classe concrète de MIME::Parser::Filer prend en charge le dépôt dans un répertoire donné.

init DIRECTORY
Méthode d'instance, initialiseur. Définit le répertoire où tous les fichiers iront.

MIME::Parser::FileUnder

Cette sous-classe concrète de MIME::Parser::Filer prend en charge le dépôt sous un répertoire donné, en utilisant un sous-répertoire par message, mais avec toutes les parties du message dans le même répertoire.

init BASEDIR, OPTSHASH...
Méthode d'instance, initialiseur. Définit le répertoire de base qui contiendra les répertoires des messages. Si utilisé, chaque analyse commence par la création d'un nouveau sous-répertoire de BASEDIR où les parties réelles du message sont placées. OPTSHASH peut contenir les éléments suivants :
DirName
Définit explicitement le nom du sous-répertoire créé. La valeur par défaut est d'utiliser l'heure, l'ID du processus et un numéro de séquence, mais vous pourriez vouloir un répertoire prévisible.
Purge
Nettoie automatiquement le contenu du répertoire (y compris tous les sous-répertoires) avant chaque analyse. Ceci n'est vraiment nécessaire que si vous utilisez un DirName explicite, et est fourni comme une simple commodité. Actuellement, nous utilisons la forme à 1 argument de File::Path::rmtree ; vous devriez vous familiariser avec les mises en garde qui y sont associées.

La méthode output_dir() retournera le chemin vers ce répertoire spécifique au message jusqu'à ce que la prochaine analyse ne soit commencée, vous pouvez donc faire ceci :

use File::Path;
$parser->output_under("/tmp");
$ent = eval { $parser->parse_open($msg); };   ### analyse
if (!$ent) {         ### échec de l'analyse
    rmtree($parser->output_dir);
    die "l'analyse a échoué : $@";
}
else {               ### succès de l'analyse
    ...faire des choses...
}
