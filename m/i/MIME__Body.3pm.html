NOM

MIME::Body - le corps d'un message MIME

SYNOPSIS

Avant de lire la suite, vous devriez consulter MIME::Tools pour vous assurer que vous comprenez où ce module s'intègre dans le schéma général. Allez-y, faites-le maintenant. J'attends.

Prêt ? Ok...

Obtention des corps

### Obtenir le handle du corps d'un objet MIME::Entity :
$body = $entity->bodyhandle;
### Créer un corps qui stocke les données dans un fichier disque :
$body = new MIME::Body::File "/chemin/vers/le/fichier";
### Créer un corps qui stocke les données dans un tableau en mémoire :
$body = new MIME::Body::InCore \@strings;

Ouverture, fermeture et utilisation des descripteurs d'E/S

### Écrire des données dans le corps :
$IO = $body->open("w")      || die "ouverture du corps : $!";
$IO->print($message);
$IO->close                  || die "fermeture du descripteur d'E/S : $!";
### Lire des données depuis le corps (dans ce cas, ligne par ligne) :
$IO = $body->open("r")      || die "ouverture du corps : $!";
while (defined($_ = $IO->getline)) {
    ### faire quelque chose
}
$IO->close                  || die "fermeture du descripteur d'E/S : $!";

Autres E/S

### Enregistrer les données du corps ENCODÉES dans un descripteur de fichier :
$body->print(\*STDOUT);
### Charger toutes les données NON ENCODÉES, et les mettre dans un scalaire :
$string = $body->as_string;
### Charger toutes les données NON ENCODÉES, et les mettre dans un tableau de lignes :
@lines = $body->as_lines;

Travailler directement avec les chemins vers les fichiers sous-jacents

### Où sont les données ?
if (defined($body->path)) {   ### les données sont sur disque :
    print "les données sont stockées en externe, dans ", $body->path;
}
else {                        ### les données sont en mémoire :
    print "les données sont déjà en mémoire, et sont...\n", $body->as_string;
}
### Supprimer tout ce qui est sur disque :
$body->purge;

DESCRIPTION

Les messages MIME peuvent être très longs (par exemple, fichiers tar, MPEGs, etc.) ou très courts (notes textuelles courtes, comme dans un courrier ordinaire). Les messages longs sont mieux stockés dans des fichiers, tandis que les courts sont peut-être mieux stockés en mémoire.

Cette classe est une tentative de définir une interface commune pour les objets qui contiennent des données de message, indépendamment de la manière dont les données sont physiquement stockées. La durée de vie d'un objet "body" ressemble généralement à ceci :

1.
L'objet corps est créé par un MIME::Parser lors de l'analyse. C'est à ce moment que la sous-classe MIME::Body réelle est choisie, et que new() est appelée. (Par exemple : si les données du corps vont dans un fichier, c'est à ce moment que la classe MIME::Body::File, et le nom du fichier, sont choisis).
2.
Les données sont écrites dans le corps (généralement par le parseur MIME) comme ceci : Le corps est ouvert en écriture, via open("w"). Cela écrasera tout contenu précédent, et retournera un "descripteur d'E/S" ouvert en écriture. Les données sont écrites dans ce descripteur d'E/S, via print(). Ensuite, le descripteur d'E/S est fermé, via close().
3.
Les données sont lues depuis le corps (généralement par l'application utilisateur) comme ceci : Le corps est ouvert en lecture par une application utilisateur, via open("r"). Cela retournera un "descripteur d'E/S" ouvert en lecture. Les données sont lues depuis le descripteur d'E/S, via read(), getline() ou getlines(). Ensuite, le descripteur d'E/S est fermé, via close().
4.
L'objet corps est détruit.

Vous pouvez écrire vos propres sous-classes, tant qu'elles suivent l'interface décrite ci-dessous. Les implémenteurs de sous-classes doivent supposer que les étapes 2 et 3 peuvent être répétées plusieurs fois, et dans des ordres différents (par exemple, 1-2-2-3-2-3-3-3-3-3-2-4).

Dans tous les cas, une fois qu'un MIME::Body a été créé, vous demandez à l'ouvrir en lecture ou en écriture, ce qui vous donne un "descripteur d'E/S" : vous utilisez ensuite les mêmes mécanismes pour lire ou écrire à partir de ce descripteur, quelle que soit sa classe.

Attention : à moins de savoir avec certitude quel type de corps vous avez, vous ne devriez *pas* supposer que le corps a un descripteur de fichier sous-jacent.

INTERFACE PUBLIQUE

new ARGS...
Méthode de classe, constructeur. Crée un nouveau corps. Tous les ARGS sont envoyés à init().
init ARGS...
Méthode d'instance, abstraite, initialiseur. Ceci est appelé automatiquement par new(), avec les arguments fournis à new(). Les arguments sont optionnels, et entièrement à la discrétion de la sous-classe. La méthode par défaut ne fait rien,
as_lines
Méthode d'instance. Retourne le contenu du corps sous forme de tableau de lignes (chacune se terminant par un retour à la ligne, à l'exception possible de la dernière). Retourne une chaîne vide en cas d'échec (NB : indiscernable d'un corps vide !).

Note : la méthode par défaut récupère les données via des appels répétés à getline() ; votre sous-classe pourrait souhaiter redéfinir cela.

as_string
Méthode d'instance. Retourne les données du corps sous forme de chaîne (en les chargeant en mémoire si nécessaire). Il est préférable de ne pas le faire à moins d'être *sûr* que le corps est raisonnablement petit ! Retourne une chaîne vide pour un corps vide, et undef en cas d'échec.

Note : la méthode par défaut utilise print(), qui récupère les données via des appels répétés à read() ; votre sous-classe pourrait souhaiter redéfinir cela.

binmode [ONOFF]
Méthode d'instance. Avec un argument, indique si open() doit retourner un descripteur d'E/S avec binmode() activé. Sans argument, retourne simplement la valeur actuelle.
is_encoded [ONOFF]
Méthode d'instance. Si défini sur oui, aucun décodage n'est appliqué à la sortie. Ce drapeau est défini par MIME::Parser, si le parseur fonctionne en mode decode_bodies(0), de sorte que le contenu est géré sans modification.
dup
Méthode d'instance. Duplique le handle du corps.

Attention : les données externes dans les handles de corps ne sont *pas* copiées dans de nouveaux fichiers ! Modifier les données dans le fichier de données d'un corps, ou purger ce corps, affectera *son* double. Les corps avec des données en mémoire n'ont probablement pas à s'en soucier.

open READWRITE
Méthode d'instance, abstraite. Doit faire tout le nécessaire pour ouvrir le corps soit en écriture (si READWRITE est "w") soit en lecture (si le mode est "r").

On attend de cette méthode qu'elle retourne un objet de type "descripteur d'E/S" en cas de succès, et undef en cas d'erreur. Un descripteur d'E/S peut être n'importe quel objet qui supporte un petit ensemble de méthodes standard pour lire/écrire des données. Voir la classe IO::Handle pour un exemple.

path [PATH]
Méthode d'instance. Si vous stockez les données du corps en externe (par exemple, dans un fichier disque), vous voudrez donner aux applications la possibilité d'accéder à ces données, pour le nettoyage. Cette méthode doit retourner le chemin d'accès aux données, ou undef s'il n'y en a pas.

Le cas échéant, le chemin *devrait* être une simple chaîne, comme un nom de fichier. Avec un argument, définit le PATH, qui devrait être undef s'il n'y en a pas.

print FILEHANDLE
Méthode d'instance. Sortie des données du corps vers le descripteur de fichier donné, ou vers celui actuellement sélectionné s'il n'y en a pas.
purge
Méthode d'instance, abstraite. Supprime toutes les données qui résident à l'extérieur du programme (par exemple, dans des fichiers disque). Immédiatement après un purge(), path() devrait retourner undef pour indiquer que les données externes ne sont plus disponibles.

MIME::Body::File

Une classe de corps qui stocke les données dans un fichier sur disque. Appelez le constructeur comme suit:

$body = new MIME::Body::File "/path/to/file";

Dans ce cas, la méthode path() renverra le chemin donné, ainsi vous pouvez dire:

if (defined($body->path)) {
    open BODY, $body->path or die "open: $!";
    while (<BODY>) {
        ### faire quelque chose
    }
    close BODY;
}

Mais il vaut mieux ne pas faire cela.

MIME::Body::Scalar

Une classe de corps qui stocke les données en mémoire, dans un scalaire simple. Appelez le constructeur comme suit:

$body = new MIME::Body::Scalar \$string;

Un argument scalaire unique définit le corps à cette valeur, exactement comme si vous aviez ouvert le corps en écriture, écrit la valeur, puis refermé le corps:

$body = new MIME::Body::Scalar "Ligne 1\nLigne 2\nLigne 3";

Un tableau de références unique définit le corps à la concaténation de tous les éléments de ce tableau:

$body = new MIME::Body::Scalar ["Ligne 1\n",
                                "Ligne 2\n",
                                "Ligne 3"];

MIME::Body::InCore

Une classe de corps qui stocke les données en mémoire. Appelez le constructeur comme suit:

$body = new MIME::Body::InCore \$string;
$body = new MIME::Body::InCore  $string;
$body = new MIME::Body::InCore \@stringarray

Un argument scalaire unique définit le corps à cette valeur, exactement comme si vous aviez ouvert le corps en écriture, écrit la valeur, puis refermé le corps:

$body = new MIME::Body::InCore "Ligne 1\nLigne 2\nLigne 3";

Un tableau de références unique définit le corps à la concaténation de tous les scalaires qu'il contient:

$body = new MIME::Body::InCore ["Ligne 1\n",
                                "Ligne 2\n",
                                "Ligne 3"];

Définir vos propres sous-classes

Pas à l'aise avec les fichiers et les tableaux de scalaires? Pas de problème: définissez votre propre classe MIME::Body et créez une sous-classe de MIME::Parser ou MIME::ParserBase qui renverra un objet de votre classe lorsque la méthode new_body_for(head) sera utilisée.

Votre classe de "corps" doit hériter de MIME::Body (ou d'une de ses sous-classes), et doit fournir (ou hériter de la valeur par défaut) les méthodes suivantes...

La méthode par défaut héritée devrait fonctionner pour tous ceux-ci:

new
binmode [ONOFF]
path

La méthode par défaut héritée peut fonctionner pour ceux-ci, mais il pourrait y avoir une meilleure implémentation pour votre sous-classe.

init ARGS...
as_lines
as_string
dup
print
purge

La méthode par défaut héritée ne fonctionnera probablement pas pour ceux-ci:

open

NOTES

Une des raisons pour lesquelles je n'ai pas utilisé directement des objets IO::Handle pour les corps de message était que je voulais que l'objet "corps" soit un type de stockage de programme persistant, complètement encapsulé; c'est-à-dire, que les utilisateurs puissent écrire du code comme ceci...

### Obtenir le handle du corps de ce message MIME et lire ses données:
$body = $entity->bodyhandle;
$IO = $body->open("r");
while (defined($_ = $IO->getline)) {
    print STDOUT $_;
}
$IO->close;

...sans avoir à savoir comment l'objet $body stocke réellement ses données (fichier sur disque, variable scalaire, tableau de scalaires, ou peu importe).

Stocker le corps de chaque message MIME dans un fichier qui serait ouvert de manière persistante à l'aide d'IO::Handle était une possibilité, mais cela semblait être une mauvaise idée, étant donné qu'un message MIME multipart pourrait facilement consommer tous les descripteurs de fichiers disponibles sur certains systèmes. Ce risque augmente si l'utilisateur traite plus d'une entité MIME à la fois.
