NOM

MIME::Lite - générateur de messages MIME à faible volume

ATTENTION !

MIME::Lite n'est pas recommandé par son mainteneur actuel. Il existe plusieurs alternatives, comme Email::MIME ou MIME::Entity et Email::Sender, que vous devriez utiliser à la place. MIME::Lite continue de recevoir des rapports de bugs étranges et ne fait pas l'objet de beaucoup de refactorisations en raison de la disponibilité d'alternatives meilleures. Envisagez d'utiliser une autre option.

SYNTAXE

Créer et envoyer un message en utilisant la méthode d'envoi par défaut pour votre système d'exploitation un message à partie unique :

use MIME::Lite;
### Créer un nouveau message à partie unique, pour envoyer un fichier GIF :
$msg = MIME::Lite->new(
    From     => 'moi@monhost.com',
    To       => 'toi@tonhost.com',
    Cc       => 'quelqun@autre.com, quelqun@encore.com',
    Subject  => 'Bonjour infirmière !',
    Type     => 'image/gif',
    Encoding => 'base64',
    Path     => 'bonjourinfirmiere.gif'
);
$msg->send; # envoyer par défaut

Créer un message multipart (c'est-à-dire avec des pièces jointes) et envoyer par SMTP :

### Créer un nouveau message multipart :
$msg = MIME::Lite->new(
    From    => 'moi@monhost.com',
    To      => 'toi@tonhost.com',
    Cc      => 'quelqun@autre.com, quelqun@encore.com',
    Subject => 'Un message avec 2 parties...',
    Type    => 'multipart/mixed'
);
### Ajouter des parties (chaque "attach" a les mêmes arguments que "new") :
$msg->attach(
    Type => 'TEXT',
    Data => 'Voici le fichier GIF que vous vouliez'
);
$msg->attach(
    Type     => 'image/gif',
    Path     => 'aaa000123.gif',
    Filename => 'logo.gif',
    Disposition => 'attachment'
);
### utiliser Net::SMTP pour l'envoi
$msg->send('smtp','hote.com', Debug=>1 );

Imprimer un message :

### Formater comme une chaîne :
$str = $msg->as_string;
### Imprimer dans un flux de sortie (par exemple, un flux "sendmail") :
$msg->print(\*SENDMAIL);

Envoyer un message :

### Envoyer de la manière "optimale" (par défaut, utiliser "sendmail") :
$msg->send;
### Envoyer de manière spécifique :
$msg->send('type',@args);

Définir la méthode d'envoi par défaut :

MIME::Lite->send('smtp','hote.com',Debug=>0);

avec authentification :

MIME::Lite->send('smtp','hote.com', AuthUser=>$user, AuthPass=>$pass);

en utilisant SSL :

MIME::Lite->send('smtp','hote.com', SSL => 1, Port => 465 );

DESCRIPTION

Dans la quête éternelle d'un bon goût avec moins de calories, nous présentons : MIME::Lite.

MIME::Lite est un module simple et autonome pour générer (pas parser !) des messages MIME... spécifiquement, il permet à votre utilisateur de générer un message simple et décent à une ou plusieurs parties avec du texte ou des fichiers binaires. Il n'a pas besoin que vous ayez les bibliothèques Mail:: ou MIME:: installées, mais il fonctionnera avec elles si vous les avez.

Vous pouvez spécifier chaque partie du message comme des données littérales (dans un scalaire ou un tableau), ou comme une chaîne qui peut être passée à open() pour obtenir un fichier de sortie à lire (par exemple, "<nom_fichier>" ou "une_commande|").

Vous n'avez pas à vous soucier de l'encodage de votre message : ce module s'en chargera pour vous. Il gère les 5 encodages MIME standards.

MIME::Lite->field_order()
Lorsqu'elle est utilisée comme méthode de classe, cela modifie l'ordre par défaut dans lequel les en-têtes sont générés pour *tous* les messages. Cependant, veuillez considérer l'utilisation de la variante de méthode d'instance à la place, afin de ne pas écraser les autres expéditeurs de messages dans la même application.
MIME::Lite->quiet()
Cette méthode de classe peut être utilisée pour supprimer/restaurer tous les avertissements provenant de ce module.
MIME::Lite->send()
Lorsqu'elle est utilisée comme méthode de classe, elle peut être utilisée pour spécifier un mécanisme d'envoi de message par défaut différent. Le défaut initial est : 
MIME::Lite->send("sendmail", "/usr/lib/sendmail -t -oi -oem");

Cependant, vous devriez considérer la variante similaire mais plus intelligente et résistante à la corruption :

MIME::Lite->send("sendmail");

Ou, pour les utilisateurs non Unix :

MIME::Lite->send("smtp");
$MIME::Lite::AUTO_CC
Si vrai, envoie automatiquement aux adresses Cc/Bcc pour send_by_smtp(). Par défaut : vrai.
$MIME::Lite::AUTO_CONTENT_TYPE
Si vrai, tente de choisir automatiquement le type de contenu à partir du nom de fichier dans new()/build(). En d'autres termes, définir cette option sur vrai modifie le type par défaut "Type" de "TEXT" à "AUTO".

Par défaut : faux, car nous devons maintenir la compatibilité descendante avec le comportement antérieur. Veuillez envisager de le laisser à faux, et d'utiliser simplement le type 'AUTO' lorsque vous faites build() ou attach().

$MIME::Lite::AUTO_ENCODE
Si vrai, choisit automatiquement l'encodage à partir du type de contenu. Par défaut : vrai.
$MIME::Lite::AUTO_VERIFY
Si vrai, vérifie les chemins des pièces jointes juste avant l'impression, levant une exception si un chemin n'est pas lisible. Par défaut : vrai.
$MIME::Lite::PARANOID
Si vrai, nous ne tenterons pas d'utiliser MIME::Base64, MIME::QuotedPrint, ou MIME::Types, même s'ils sont disponibles. Par défaut : faux. Veuillez considérer de le laisser à faux, et de faire confiance à ces autres paquets pour faire ce qu'il faut.

Construction

new [PARAMHASH]
Méthode de classe, constructeur. Crée un nouvel objet message.

Si des arguments sont fournis, ils sont passés à build() ; sinon, seul l'objet vide est créé.

attach PART
attach PARAMHASH...
Méthode d'instance. Ajoute une nouvelle partie à ce message, et retourne la nouvelle partie.

Si vous fournissez un seul argument PART, il sera considéré comme un objet MIME::Lite à joindre. Sinon, cette méthode suppose que vous fournissez des paires PARAMHASH qui seront envoyées à new() pour créer la nouvelle partie.

L'une des astuces potentiellement très utiles est l'astuce "attach-to-singlepart" : si vous tentez de joindre une partie (appelons-la "partie 1") à un message qui n'a pas de type de contenu "multipart" ou "message", voici ce qui se passe :

  • Une nouvelle partie (appelons-la "partie 0") est créée.
  • Les attributs et données MIME (mais *pas* les autres en-têtes) sont extraits du message "self", et collés dans "partie 0".
  • Le "self" est transformé en un message "multipart/mixed".
  • La nouvelle "partie 0" est ajoutée au "self", et *ensuite* la "partie 1" est ajoutée.

L'un des effets secondaires positifs est que vous pouvez créer un message texte, puis y ajouter zéro ou plusieurs pièces jointes, un peu comme le permet un agent utilisateur tel que Netscape.

build [PARAMHASH]
Méthode de classe/instance, initialisateur. Crée (ou initialise) un objet message MIME. Normalement, vous utiliserez les clés suivantes dans PARAMHASH : 
* Data, FH, ou Path      (l'un de ceux-ci, ou aucun s'il s'agit de multipart)
* Type                   (par exemple, "image/jpeg")
* From, To, et Subject  (si c'est le "niveau supérieur" d'un message)

Le PARAMHASH peut contenir les clés suivantes :

(fieldname)
Tout champ que vous souhaitez placer dans l'en-tête du message, tiré de la liste standard des champs d'en-tête (vous n'avez pas à vous soucier de la casse) : 
Approved      Encrypted     Received      Sender
Bcc           From          References    Subject
Cc            Keywords      Reply-To      To
Comments      Message-ID    Resent-*      X-*
Content-*     MIME-Version  Return-Path
Date                        Organization

Pour donner aux utilisateurs expérimentés un pouvoir de veto, ces champs seront définis *après* ceux que je définis... alors faites attention : *ne définissez aucun champ MIME* (comme "Content-type") à moins de savoir ce que vous faites !

Pour spécifier un nom de champ qui n'est *pas* dans la liste ci-dessus, même un qui est identique à une option ci-dessous, donnez-le simplement avec un ":" final, comme "My-field:". En cas de doute, cela signale *toujours* un champ de messagerie (et cela ressemble un peu à cela aussi).

Data
Alternative à "Path" ou "FH". Les données réelles du message. Cela peut être un scalaire ou une référence à un tableau de chaînes ; si c'est le dernier, le message consiste en une simple concaténation de toutes les chaînes du tableau.
Datestamp
Optionnel. Si défini sur vrai (ou omis), nous forçons la création d'un champ "Date:" estampillé avec la date/heure actuelle s'il s'agit d'un message de niveau supérieur. Vous pourriez le vouloir si vous utilisez send_by_smtp(). Si vous ne voulez pas que cela soit fait, fournissez votre propre date ou définissez-le explicitement sur faux.
Disposition
Optionnel. La disposition du contenu, "inline" ou "attachment". Par défaut : "inline".
Encoding
Optionnel. Le codage de transfert de contenu qui doit être utilisé pour encoder vos données : 
Utiliser le codage: | Si votre message contient:
------------------------------------------------------------
7bit              | Uniquement du texte 7 bits, toutes les lignes <1000 caractères
8bit              | Texte 8 bits, toutes les lignes <1000 caractères
quoted-printable  | Texte 8 bits ou lignes longues (plus fiable que "8bit")
base64            | Données largement non textuelles : un GIF, un fichier tar, etc.

Le défaut est tiré du Type ; généralement c'est "binaire" (aucun encodage) pour text/*, message/*, et multipart/*, et "base64" pour tout le reste. Une valeur de "binaire" n'est généralement *pas* adaptée pour envoyer autre chose que des fichiers texte ASCII avec des lignes inférieures à 1000 caractères, alors envisagez d'utiliser une des autres valeurs à la place.

Dans le cas de "7bit"/"8bit", les lignes longues sont automatiquement coupées à la longueur légale ; dans le cas de "7bit", tous les caractères 8 bits sont automatiquement *supprimés*. Cela pourrait ne pas être ce que vous voulez, alors choisissez bien votre encodage ! Pour plus d'informations, voir "A MIME PRIMER".

FH
Alternative à "Data" ou "Path". Manette de fichier contenant les données, ouverte en lecture. Voir aussi "ReadNow".
Filename
Optionnel. Le nom de la pièce jointe. Vous pouvez l'utiliser pour fournir un nom de fichier recommandé à l'utilisateur final qui enregistre la pièce jointe sur disque. Vous n'en avez besoin que si le nom de fichier à la fin du "Path" est inadéquat, ou si vous utilisez "Data" au lieu de "Path". Vous ne devriez *pas* y mettre d'informations de chemin (par exemple, pas de caractères "/" ou "\" ou ":").
Id
Optionnel. Identique à la définition de "content-id".
Length
Optionnel. Définit explicitement la longueur du contenu. Normalement, cet en-tête est calculé automatiquement, mais seulement dans certaines circonstances (voir "Limitations bénignes").
Path
Alternative à "Data" ou "FH". Chemin vers un fichier contenant les données... en fait, cela peut être n'importe quelle expression open()able. S'il ressemble à un chemin, le dernier élément sera automatiquement traité comme le nom de fichier. Voir aussi "ReadNow".
ReadNow
Optionnel, pour utilisation avec "Path". Si vrai, ouvrira le chemin et chargera le contenu en mémoire maintenant. C'est utile si le Path pointe vers une commande et que vous ne voulez pas exécuter la commande plusieurs fois si vous générez le message plusieurs fois. Une exception fatale sera levée si l'ouverture échoue.
Top
Optionnel. S'il est défini, indique si c'est un message MIME de "niveau supérieur" ou non. Les parties d'un message multipart ne sont *pas* de niveau supérieur. Par défaut : vrai.
Type
Optionnel. Le type de contenu MIME, ou l'une des valeurs spéciales suivantes (sensible à la casse) : 
"TEXT"   signifie "text/plain"
"BINARY" signifie "application/octet-stream"
"AUTO"   signifie tenter de deviner à partir du nom de fichier, en se rabattant sur 'application/octet-stream'. Ceci est utile si vous avez
         MIME::Types sur votre système et que vous n'avez aucune idée du fichier
         qui pourrait être utilisé pour la pièce jointe.

Définition/obtention des en-têtes et des attributs

add TAG,VALEUR
Méthode d'instance. Ajoute le champ TAG avec la valeur donnée à la fin de l'en-tête. Le TAG sera mis en minuscules, et la valeur sera rendue « sûre » (elle sera retournée avec un espace ajouté à la fin).

Attention : tout champ MIME que vous ajoutez remplacera tout attribut MIME qui pourrait être présent lors de la génération de la sortie. Normalement, vous utiliserez cette méthode pour ajouter des champs non-MIME :

$msg->add("Sujet" => "Salut !");

Fournir une valeur sous forme de tableau rendra toutes ces valeurs ajoutées. Ceci n'est utile que pour des champs à valeurs multiples comme Received :

$msg->add("Reçu" => ["ici", "là", "partout"]

Fournir une valeur vide ajoute un espace réservé invisible dans l'en-tête, qui peut être utilisé pour supprimer la sortie des champs Content-* ou du champ spécial MIME-Version. Lorsque vous supprimez des champs, vous devriez utiliser replace() plutôt que add() :

$msg->replace("Content-disposition" => "");

Note : le nom provient de Mail::Header.

attr ATTRIBUT,[VALEUR]
Méthode d'instance. Définit l'attribut MIME ATTRIBUT à la valeur CHAÎNE. ATTRIBUT sera mis en minuscules. Cette méthode est normalement utilisée pour définir/obtenir des attributs MIME : 
$msg->attr("content-type"         => "text/html");  
$msg->attr("content-type.charset" => "US-ASCII");  
$msg->attr("content-type.name"    => "homepage.html");

Cela produirait une sortie finale quelque chose comme :

Content-type: text/html; charset=US-ASCII; name="homepage.html"

Le sous-domaine vide indique le premier champ anonyme.

Fournir une valeur de undef provoquera la suppression du contenu du sous-domaine correspondant.

Sans argument, retourne la valeur de l'attribut :

$type = $msg->attr("content-type");        ### retourne "text/html"  
$name = $msg->attr("content-type.name");   ### retourne "homepage.html"
delete TAG
Méthode d'instance. Supprime le champ TAG avec la valeur donnée de l'en-tête. Le TAG sera mis en minuscules. 
$msg->delete("Sujet");

Note : le nom provient de Mail::Header.

field_order CHAMP,...CHAMP
Méthode de classe/d'instance. Change l'ordre dans lequel les champs d'en-tête sont générés pour cet objet : 
$msg->field_order('from', 'to', 'content-type', 'subject');

Lorsqu'elle est utilisée comme méthode de classe, elle change les paramètres par défaut pour tous les objets :

MIME::Lite->field_order('from', 'to', 'content-type', 'subject');

La casse n'a pas d'importance : tous les noms sont mis en minuscules. Dans tous les cas, fournir un tableau vide restaure l'ordre par défaut.

fields
Méthode d'instance. Retourne l'en-tête complet de l'objet sous forme d'un tableau de paires "[TAG, VALEUR]", où chaque TAG est entièrement en minuscules. Notez que tout champ que l'utilisateur a explicitement défini remplacera les champs MIME qui seraient normalement générés. Ainsi, vous ne devriez pas dire : 
$msg->set("Content-type" => "text/html; charset=US-ASCII");

sauf si vous voulez que la valeur précédente écrase le champ MIME Content-type qui serait normalement généré.

Note : J'ai nommé cette méthode fields car la méthode header() de Mail::Header retourne quelque chose de différent, mais c'est suffisamment similaire pour causer de la confusion.

Vous pouvez changer l'ordre des champs : voir field_order. Cela ne devrait pas être nécessaire, mais certains doivent gérer des modules mal implémentés.

filename [NOMFICHIER]
Méthode d'instance. Définit le nom de fichier qui sera rapporté pour ces données. Cela définit en fait les deux attributs standard.

Sans argument, retourne le nom tel qu'indiqué par le content-disposition.

get TAG,[INDEX]
Méthode d'instance. Obtient le contenu du champ TAG, qui pourrait avoir été défini avec set() ou replace(). Retourne le texte du champ. 
$ml->get('Sujet', 0);

Si l'index optionnel basé sur 0 est donné, il retournera l'OCCURRENCE-0 du champ TAG. Sinon, cela dépend du contexte : dans un contexte scalaire, il ne retournera que l'OCCURRENCE-0 ; dans un contexte tableau, il retournera toutes les OCCURRENCES.

Attention : ne doit être utilisé qu'avec des champs non-MIME. Le comportement avec les champs MIME est en attente de définition, et générera une exception pour le moment.

get_length
Méthode d'instance. Recalcule la longueur du corps du message si le processus est trivial, et définit l'attribut content-length par effet secondaire : 
$msg->get_length;

Retourne la longueur, ou undef si elle n'est pas définie.

Note : la longueur du contenu peut être difficile à calculer, car elle implique de construire le corps complet encodé et de prendre sa longueur (ce qui, dans le cas de messages multipart, implique de figer tous les sous-composants, etc.).

Cette méthode ne définit la longueur à une valeur définie que si le message est un composant unique avec un encodage binary, et que le corps est disponible en mémoire ou sous forme de fichier simple. Sinon, la longueur est définie comme indéfinie.

Comme le content-length n'est pas un champ MIME standard (donc il est correct !), cela semble assez raisonnable.

parts
Méthode d'instance. Retourne les composants de cette entité, et seulement cette entité. Retourne un tableau vide si cette entité n'a pas de composants.

Ce n'est **pas** récursif ! Les composants peuvent avoir des sous-composants ; utilisez parts_DFS() pour obtenir tout.

parts_DFS
Méthode d'instance. Retourne la liste de tous les objets MIME::Lite contenus dans cette entité, en commençant par l'entité elle-même, dans un ordre de parcours en profondeur d'abord. Si cet objet n'a pas de composants, lui seul est retourné.
preamble [TEXTE]
Méthode d'instance. Obtient/définit la chaîne de préambule, en supposant que cet objet a des sous-composants. La définir à undef pour la chaîne par défaut.
replace TAG,VALEUR
Méthode d'instance. Supprime toutes les occurrences de champs nommés TAG, et ajoute un nouveau champ avec la valeur donnée. TAG sera mis en minuscules.

Attention : les champs MIME (MIME-version, Content-*) : si vous remplacez un champ MIME, le texte de remplacement écrasera les attributs MIME réels lors de la génération de la sortie de ce champ. Ainsi, vous utiliserez normalement attr() pour changer les champs MIME et add()/replace() pour changer les champs non-MIME :

$msg->replace("Sujet" => "Salut !");

Fournir une valeur comme la chaîne vide supprimera effectivement ce champ de la sortie. C'est la manière correcte de supprimer les champs MIME spéciaux :

$msg->replace("Content-disposition" => "");

Fournir une valeur comme undef supprimera toutes les valeurs explicites pour TAG sans en ajouter de nouvelles.

Note : le nom de cette méthode provient de Mail::Header.

scrub
Méthode d'instance. Ceci est du code alpha. Si vous l'utilisez, s'il vous plaît, dites-moi comment ça se passe. Parcourt récursivement l'arbre des composants de ce message et recherche les attributs MIME qui peuvent être supprimés. Avec un argument tableau, il supprime exactement ces attributs ; par exemple : 
$msg->scrub(['content-disposition', 'content-length']);

C'est la même chose que de le faire récursivement :

$msg->replace('Content-dispo
sition' => ''); $msg->replace('Content-length' => '');

Réglage/obtention des données du message

binmode [OVERRIDE]
Méthode d'instance. Sans argument, renvoie si oui ou non il pense que les données (telles que fournies par l'argument "Path" de build()) doivent être lues en utilisant binmode() (par exemple, lorsque read_now() est appelée).

Le comportement par défaut est que tout type de contenu autre que "text/*" ou "message/*" est mis en mode binaire ; cela devrait en général bien fonctionner.

Avec un argument défini, cette méthode définit une valeur d'"override" explicite. Un argument indéfini annule l'override. La nouvelle valeur actuelle est renvoyée.

data [DONNÉES]
Méthode d'instance. Obtenir/définir les DONNÉES littérales du message. Les DONNÉES peuvent être un scalaire, ou une référence à un tableau de scalaires (qui seront simplement joints).

Attention : la définition des données entraîne le recalcul de l'attribut "content-length" (potentiellement à rien).

fh [DESC_FICHIER]
Méthode d'instance. Obtenir/définir le DESC_FICHIER qui contient les données du message.

Prend un descripteur de fichier en entrée et le stocke dans l'objet. Cette routine est similaire à path() ; une différence importante est qu'aucune tentative n'est faite pour définir la longueur du contenu.

path [CHEMIN]
Méthode d'instance. Obtenir/définir le CHEMIN vers les données du message.

Attention : la définition du chemin recalcule tout champ "content-length" existant, et redéfinit le "filename" (au dernier élément du chemin s'il ressemble à un chemin simple, et à rien sinon).

resetfh [DESC_FICHIER]
Méthode d'instance. Rétablir la position actuelle du descripteur de fichier au début. S'applique uniquement si vous avez utilisé "FH" dans build() ou attach() pour ce message.

Renvoie faux si incapable de réinitialiser le descripteur de fichier (car tous les descripteurs de fichier ne sont pas recherchables).

read_now
Méthode d'instance. Force la lecture immédiate des données à partir du chemin/descripteur de fichier (comme spécifié par build()) dans la mémoire, comme si vous l'aviez fourni littéralement avec la clé "Data".

Notez que les données en mémoire seront toujours utilisées si elles sont disponibles.

Soyez conscient que tout est aspiré dans un scalaire géant : vous ne voudrez peut-être pas l'utiliser pour envoyer des fichiers tar ! L'avantage de *ne pas* lire les données est que des fichiers très volumineux peuvent être gérés par ce module s'ils restent sur disque jusqu'à ce que le message soit sorti via print() ou print_body().

sign PARAMHASH
Méthode d'instance. Signe le message. Cela force le message à être lu dans la mémoire, après quoi la signature est ajoutée.
Data
Comme dans build() : les données de signature littérales. Peut être un scalaire ou une référence à un tableau de scalaires.
Path
Comme dans build() : le chemin du fichier.

Si aucun argument n'est donné, le défaut est :

Path => "$ENV{HOME}/.signature"

La longueur du contenu est recalculée.

verify_data
Méthode d'instance. Vérifie que tous les "chemins" vers les données jointes existent, récursivement. Il peut être judicieux de le faire avant un print(), pour éviter une sortie partielle accidentelle si un fichier est manquant. Lève une exception si un chemin n'est pas lisible.

Sortie

print [DESC_SORTIE]
Méthode d'instance. Imprime le message dans le descripteur de sortie donné, ou dans le descripteur de fichier actuellement sélectionné si aucun n'a été donné.

Tout DESC_SORTIE doit être un descripteur de fichier (potentiellement une référence glob), ou tout objet qui répond à un message print().

print_body [DESC_SORTIE] [IS_SMTP]
Méthode d'instance. Imprime le corps d'un message dans le descripteur de sortie donné, ou dans le descripteur de fichier actuellement sélectionné si aucun n'a été donné.

Tout DESC_SORTIE doit être un descripteur de fichier (potentiellement une référence glob), ou tout objet qui répond à un message print().

Exception fatale levée si incapable d'ouvrir l'un des fichiers d'entrée, ou si une partie ne contient aucune donnée, ou si un encodage non pris en charge est rencontré.

IS_SMPT est une option spéciale pour gérer les e-mails SMTP un peu plus intelligemment que ce que d'autres mécanismes d'envoi peuvent requérir. Spécifiquement, cela garantit que le dernier octet envoyé N'EST PAS '\n' (octal \012) si les deux derniers octets ne sont pas '\r\n' (\015\012) car cela pourrait faire planter certains serveurs SMTP.

print_header [DESC_SORTIE]
Méthode d'instance. Imprime l'en-tête du message dans le descripteur de sortie donné, ou dans le descripteur de fichier actuellement sélectionné si aucun n'a été donné.

Tout DESC_SORTIE doit être un descripteur de fichier (potentiellement une référence glob), ou tout objet qui répond à un message print().

as_string
Méthode d'instance. Renvoie le message entier sous forme de chaîne, avec un en-tête et un corps encodé.
body_as_string
Méthode d'instance. Renvoie le corps encodé sous forme de chaîne. C'est la partie après l'en-tête et la ligne vide.

Note : prépare réellement le corps en "imprimant" vers un scalaire. Preuve que vous pouvez donner aux méthodes "print*()" n'importe quel objet béni qui répond à un message print().

header_as_string
Méthode d'instance. Renvoie l'en-tête sous forme de chaîne.

Envoi

send
send HOW, HOWARGS...
Méthode de classe/d'instance. C'est la méthode principale pour envoyer du courrier, et pour configurer comment le courrier sera envoyé.

En tant que méthode de classe avec un argument HOW et des HOWARGS optionnels, elle définit le mécanisme d'envoi par défaut que la méthode sans argument utilisera. HOW est un nom de fonctionnalité (voir ci-dessous), et HOWARGS est interprété par la fonctionnalité. La méthode de classe renvoie HOW et HOWARGS précédents sous forme de tableau.

MIME::Lite->send('sendmail', "d:\\\\programs\\\\sendmail.exe");
...
$msg = MIME::Lite->new(...);
$msg->send;

En tant que méthode d'instance avec arguments (un argument HOW et des HOWARGS optionnels), envoie le message de la manière demandée ; par exemple :

$msg->send('sendmail', "d:\\\\programs\\\\sendmail.exe");

En tant que méthode d'instance sans arguments, envoie le message par le mécanisme par défaut configuré par la méthode de classe. Renvoie ce que la routine de gestion du courrier renvoie : cela devrait être vrai en cas de succès, faux/exception en cas d'erreur :

$msg = MIME::Lite->new(From=>...);
$msg->send || die "vous N'AVEZ PAS de courrier !";

Sur les systèmes Unix (ou plutôt non-Win32), le réglage par défaut est équivalent à :

MIME::Lite->send("sendmail", "/usr/lib/sendmail -t -oi -oem");

Sur les systèmes Win32, le réglage par défaut est équivalent à :

MIME::Lite->send("smtp");

On suppose que sur Win32, votre fichier site/lib/Net/libnet.cfg sera préconfiguré pour utiliser le serveur SMTP approprié. Voir ci-dessous pour la configuration de l'authentification.

Il existe trois fonctionnalités :

"sendmail", ARGS...
Envoie un message en le redirigeant vers la commande "sendmail". Utilise la méthode send_by_sendmail(), en lui passant les ARGS. Cette utilisation implémente (et déprécie) la méthode sendmail().
"smtp", [HOSTNAME, [NAMEDPARMS] ]
Envoie un message par SMTP, en utilisant HOSTNAME optionnel comme hôte d'envoi SMTP. Net::SMTP sera requis. Utilise la méthode send_by_smtp(). Tous les arguments supplémentaires passés seront également transmis à send_by_smtp. Ceci est utile pour des choses comme les serveurs de messagerie nécessitant une authentification où vous pouvez dire quelque chose comme ce qui suit 
MIME::Lite->send('smtp', $host, AuthUser=>$user, AuthPass=>$pass);

ce qui configurera les choses de manière à ce que les utilisations futures de

$msg->send();

fassent ce qu'il faut.

"sub", \&SUBREF, ARGS...
Envoie un message MSG en appelant la sous-routine SUBREF de votre choix, avec MSG comme premier argument, et les ARGS suivants.

Par exemple : disons que vous êtes sur un système d'exploitation qui ne dispose pas de la fonctionnalité Unix "sendmail" habituelle, mais que vous y avez installé quelque chose de similaire, et que vous devez configurer votre script Perl pour utiliser ce programme "sendmail.exe". Faites ceci dans la configuration de votre script :

MIME::Lite->send('sendmail', "d:\\\\programs\\\\sendmail.exe");

Ensuite, chaque fois que vous aurez besoin d'envoyer un message $msg, dites simplement :

$msg->send;

C'est tout. Maintenant, si jamais vous déplacez votre script sur une machine Unix, tout ce que vous avez à faire est de changer cette ligne dans la configuration et c'est fait. Toutes vos invocations $msg->send fonctionneront comme prévu.

Après l'envoi, la méthode last_send_successful() peut être utilisée pour déterminer si l'envoi a réussi ou non.

send_by_sendmail SENDMAILCMD

Divers

quiet ONOFF
Méthode de classe. Supprime/ignore tous les avertissements provenant de ce module. 
MIME::Lite->quiet(1);       ### Je sais ce que je fais

Je vous suggère d'inclure cette observation telle quelle. Pendant que vous écrivez, dites à voix haute: si cela ne vous convient pas, peut-être devriez-vous reconsidérer tout ce bourbier. ";-)"

NOTES

Comment empêcher les en-têtes Content de s'afficher dans mon lecteur de courrier?

Apparemment, certains utilisateurs utilisent des lecteurs de courrier qui affichent des en-têtes MIME comme "Content-disposition", et ils souhaitent que MIME::Lite ne les génère pas "parce qu'ils sont laids".

Soupir.

Cependant, quoi? Ici, les en-têtes ne sont pas juste pour l'esthétique. Ils aident à s'assurer que les messages sont correctement compris par les lecteurs de courrier. Mais vous, qu'est-ce que vous voulez? Ici, vous pouvez supprimer les en-têtes MIME standard. Avant d'envoyer le message, faites ceci:

$msg->scrub;

Vous pouvez scrub() n'importe quelle partie d'un message multipart de manière indépendante; sachez simplement que cela fonctionne récursivement. Avant de faire le ménage, notez les règles que j'applique:

Content-type
Vous pouvez supprimer l'attribut "content-type" si, et seulement si, la partie est de type "text/plain" avec le jeu de caractères "us-ascii".
Content-transfer-encoding
Vous pouvez supprimer l'attribut "content-transfer-encoding" si, et seulement si, la partie utilise un codage "7bit", "8bit" ou "binary". Si votre ligne fait moins de 1000 caractères, vous feriez mieux de le faire. Généralement, cela signifie que vous pouvez le supprimer pour du texte brut, mais pas pour des images, etc.
Content-disposition
Vous pouvez supprimer l'attribut "content-disposition" si vous faites confiance à votre lecteur de courrier pour faire le bon travail lorsqu'il décide d'afficher une pièce jointe en ligne ou sous forme de lien. Notez que la suppression de "content-disposition" et de "content-type" signifie qu'il n'y aura aucun moyen de recommander un nom de fichier pour la pièce jointe!

Note: il y a eu des rapports de MAU désespérés qui font des bêtises lorsqu'on leur fournit "content-disposition". Si vos pièces jointes s'affichent en ligne ou vice versa, essayez de supprimer cet attribut.

Content~4

Comment donner un nom de recommandation différent à une pièce jointe?

En utilisant l'option Filename (différent de Path!):

$msg->a
ttach(Type => "image/gif",
             Path => "/here/is/the/real/file.GIF",
             Filename => "logo.gif");

Vous ne devez pas inclure d'informations de chemin dans Filename.

Utilisation d'UTF-8 et d'autres jeux de caractères

Tout texte ajouté à votre courriel doit être correctement encodé. MIME::Lite ne le fait pas pour vous. Par exemple, si vous souhaitez envoyer votre courriel en UTF-8, où $to, $subject et $text ont ces valeurs :

  • To: "Ramón Nuñez <foo@bar.com>"
  • Subject: "¡Aquí está!"
  • Text: "¿Quieres ganar muchos €'s?"
use MIME::Lite;
use Encode qw(encode encode_utf8 );
my $to      = "Ram\363n Nu\361ez <foo\@bar.com>";
my $subject = "\241Aqu\355 est\341!";
my $text    = "\277Quieres ganar muchos \x{20ac}'s?";
### Créer un nouveau message encodé en UTF-8 :
my $msg = MIME::Lite->new(
    From    => 'me@myhost.com',
    To      => encode( 'MIME-Header', $to ),
    Subject => encode( 'MIME-Header', $subject ),
    Data    => encode_utf8($text)
);
$msg->attr( 'content-type' => 'text/plain; charset=utf-8' );
$msg->send;

Remarque :

  • L'exemple ci-dessous suppose que les valeurs que vous souhaitez encoder sont au format interne de Perl, c'est-à-dire que les chaînes contiennent des caractères décodés UTF-8, et non les octets qui représentent ces caractères.
  • Si, pour le corps du message, vous souhaitez utiliser un jeu de caractères autre que UTF-8, vous devez l'encoder correctement et définir le "content-type", par exemple :
    • ...
Data => encode('iso-8859-15',$text)
...
$msg->attr( 'content-type' => 'text/plain; charset=iso-8859-15' );
  • Encode::MIME::Header ne prend en charge que UTF-8, mais les clients modernes devraient pouvoir le gérer. Il n'y a pas de problème à ce que les en-têtes soient dans un encodage différent de celui du corps du message.

Limitations bénignes

C'est "lite", après tout...

  • Il n'y a pas d'analyse. Obtenez MIME-tools si vous avez besoin d'analyser des messages MIME.
  • Les messages MIME::Lite ne sont actuellement pas interchangeables avec les objets Mail::Internet ou MIME::Entity. C'est un module complètement distinct.
  • Un champ content-length n'est inséré que si l'encodage est binaire, le message est uniparti et toutes les données du document sont disponibles au moment de la construction du message car elles résident dans un chemin simple ou en mémoire.
  • MIME::Lite ne peut vous aider à perdre du poids que si vous complétez son utilisation avec une alimentation saine et de l'exercice.

Envoi d'e-mails facile et économique

Je pensais qu'inclure un appel par défaut à "sendmail" n'était pas si mal, car de nombreux Perl-programmers sont sur des systèmes UNIX. (Depuis la version 3.02, c'est seulement le défaut sur les machines non-Win32. Sur les machines Win32, le défaut est d'utiliser SMTP et les paramètres par défaut fournis dans site/lib/Net/libnet.cfg)

La configuration par défaut est :

MIME::Lite->send('sendmail', "/usr/lib/sendmail -t -oi -oem");

Cependant, ces arguments pour sendmail sont :

-t      Recherche dans le message les lignes To:, Cc:, Bcc:, etc.
-oi     Ne traite pas une ligne contenant uniquement un "." comme terminateur de message. Par exemple, "-oi vey, it truncated my message... why?!"
-oem    En cas d'erreur, renvoie le message (en supposant l'adresse correspondante donnée dans l'en-tête). Lorsque l'e-mail est envoyé, la boucle est complète. Jai Guru Deva -oem.

Remarque : ce sont les mêmes arguments que vous obtenez si vous vous configurez pour utiliser le courrier intelligent et sécurisé :

MIME::Lite->send('sendmail');

Si vous obtenez des en-têtes "X-Authentication-Warning" de cette façon, vous pouvez éviter la manipulation de l'enveloppe en spécifiant :

MIME::Lite->send('sendmail', SetSender=>0);

Et si vous n'êtes pas sur un système Unix, ou si vous souhaitez envoyer l'e-mail d'une autre manière, il existe toujours les méthodes SMTP, qui exigent aujourd'hui probablement une authentification, vous devrez donc probablement spécifier :

MIME::Lite->send('smtp', "smtp.myisp.net",
   AuthUser=>"YourName",AuthPass=>"YourPass" );

Ou vous pouvez configurer votre propre sous-routine à appeler. Dans tous les cas, vérifiez la méthode send().

AVERTISSEMENTS

Adresses e-mail correctes vs incorrectes avec send_by_smtp()

Si vous utilisez send_by_smtp, rappelez-vous que, à moins que vous ne fournissiez explicitement les adresses e-mail auxquelles envoyer et à partir desquelles recevoir, MIME::Lite forcera l'extraction des adresses e-mail d'une liste éventuellement fournie dans les colonnes "To:", "Cc:" et "Bcc:". C'est délicat et par conséquent, cela ne fonctionnera de manière fiable qu'avec les types d'adresses suivants :

username
full.name@some.host.com
"Name, Full" <full.name@some.host.com>

Avertissement : MIME::Lite n'a jamais été conçu intentionnellement comme un agent utilisateur de courrier électronique, il ne s'attend donc pas à une implémentation complète de RFC-822. Limitez-vous aux formes courantes d'adresses Internet décrites ici et tout devrait aller bien. Si cela n'est pas possible, envisagez d'utiliser MIME::Lite uniquement pour préparer le message et utilisez Net::SMTP explicitement pour l'envoyer.

Remarque : depuis la version 3.02 de MIME::Lite, les routines d'extraction de noms d'e-mail ont été considérablement améliorées. De plus, si Mail::Address est fourni, le nom sera extrait en utilisant celui-ci. La recommandation ci-dessus est donc moins pertinente qu'auparavant. Les adresses e-mail complexes devraient maintenant fonctionner correctement. Néanmoins, l'avertissement demeure. Les petits correctifs sont les bienvenus. :-)

Formatage des en-têtes différé jusqu'à print()

Cette classe traite un en-tête MIME de manière plus abstraite, comme une collection d'attributs de haut niveau. Les champs d'en-tête RFC-822 ne sont pas construits avant que le message ne soit effectivement imprimé.

Encodage des données différé jusqu'à print()

Lorsque vous spécifiez des corps de message (dans build() ou attach()), que ce soit via FH, Data ou Path, sachez que nous n'essayons pas d'ouvrir des fichiers, de lire des descripteurs d'entrée ou d'encoder les données avant que print() ne soit appelé.

Par le passé, cela a créé de la confusion pour les utilisateurs qui utilisaient sendmail et fournissaient des chemins incorrects pour le corps de la pièce jointe, car suffisamment de print() réussissaient pour extraire la première partie du message. Désormais, $AUTO_VERIFY est utilisé pour vérifier les chemins avant que le service de messagerie ne soit utilisé. Plus lent, mais beaucoup plus sûr.

Remarque : si vous fournissez un corps de message via FH et tentez d'imprimer un message deux fois, la deuxième impression ne fera pas ce qu'elle est censée faire, à moins que vous ne rembobiez explicitement le descripteur de fichier.

Vous pouvez échapper à ces difficultés en utilisant l'option ReadNow, à condition d'avoir suffisamment de mémoire pour gérer vos messages.

Les attributs MIME sont séparés des champs d'en-tête !

Important : les attributs MIME sont stockés et manipulés séparément des champs d'en-tête de message ; lorsqu'il est temps d'imprimer l'en-tête, tout champ d'en-tête explicitement donné annule ceux qui seraient créés à partir des attributs MIME. Cela signifie que :

### DANGER ### DANGER ### DANGER ### DANGER ### DANGER ###
$msg->add("Content-type", "text/html; charset=US-ASCII");

définira exactement le champ "Content-type" dans l'en-tête que j'écris, indépendamment des attributs MIME réels.

Cette fonction est réservée aux utilisateurs expérimentés, comme une échappatoire au cas où le code qui formate normalement les champs d'en-tête MIME ne ferait pas ce que vous attendez. Et, comme toute échappatoire, elle comporte un avertissement : MIME::Lite vous avertira si vous essayez de set() ou replace() un champ d'en-tête MIME. Utilisez plutôt attr().

Attention aux lignes composées d'un seul point

Julian Haight a noté que MIME::Lite permet de créer des messages avec des lignes dans le corps qui consistent en un seul ". ". C'est vrai : cela devrait être totalement inoffensif, sauf si sendmail est utilisé avec l'option -oi (voir "Envoi d'e-mails facile et économique").

Cependant, je ne sais pas si l'utilisation de Net::SMTP pour transférer un message avec cette structure est tout aussi sûre. Vos commentaires sont les bienvenus.

Mon point de vue : je ne veux pas manipuler magiquement un message utilisateur, sauf si c'est absolument nécessaire. Certains utilisateurs pourraient vouloir envoyer des fichiers avec seulement un "." sur une ligne ; mon petit ajustement pourrait leur nuire gravement.

Les boucles infinies peuvent signifier des données corrompues !

Stefan Sautter a signalé un bug dans la version 2.106, où une correspondance m//gc échouait en raison de données corrompues, ce qui entraînait une boucle infinie dans MIME::Lite.

J'essaie de corriger cela, mais gardez à l'esprit que ma correction corrompra silencieusement les données (compte tenu du contexte dans lequel le problème survient, cela devrait être bénéfique : j'ai déjà étiqueté le code source avec des commentaires UNTAINT pour les curieux).

Donc : ne désactivez pas la vérification de taint pour vous éviter de sortir avec des données corrompues.

Ne pas ajuster la configuration globale

Les variables de configuration globales sont mauvaises, et elles devraient être supprimées. En attendant qu'elles le soient, veuillez suivre les instructions spécifiques à chaque configuration sur la manière de ne pas les modifier.

Un aperçu de MIME

Types de contenu

Le paramètre « Type » de build() est un type de contenu. C'est le type réel des données que vous envoyez. Il s'agit généralement d'une chaîne de la forme "majortype/minortype".

Voici les types MIME majeurs. Une liste plus complète peut être trouvée dans RFC-2046.

application
Données qui ne correspondent à aucune des catégories restantes, en particulier les données traitées par un type quelconque de programme d'application. "application/octet-stream", "application/gzip", "application/postscript"...
audio
Données audio. "audio/basic"...
image
Données graphiques. "image/gif", "image/jpeg"...
message
Un message, généralement un autre email ou message MIME. "message/rfc822"...
multipart
Un message contenant d'autres messages. "multipart/mixed", "multipart/alternative"...
text
Données textuelles, destinées à être lues par des humains. "text/plain", "text/html"...
video
Données vidéo ou données vidéo+audio. "video/mpeg"...

Codages de transfert de contenu

Le paramètre « Encoding » de build(). C'est ainsi que le corps du message est envoyé pour un transit sécurisé.

Voici les cinq codages MIME principaux. Une liste plus complète peut être trouvée dans RFC-2045.

7bit
Fondamentalement, aucune codification réelle n'est effectuée. Cependant, cette étiquette garantit qu'il n'y a pas de caractères 8 bits et que les lignes ne dépassent pas 1000 caractères de long.
8bit
Fondamentalement, aucune codification réelle n'est effectuée. Le message peut contenir des caractères 8 bits, mais ce codage garantit que les lignes ne dépassent pas 1000 caractères de long.
binary
Aucune codification n'est effectuée. Le message peut contenir des caractères 8 bits, et les lignes peuvent être plus longues que 1000 caractères.
base64
Similaire à « uuencode », mais bien défini. C'est ainsi que vous devriez envoyer des informations binaires (fichiers tar, GIFs, JPEGs, etc.).
quoted-printable
Utile pour encoder des messages qui sont textuels mais contiennent des caractères non ASCII (par exemple, Latin-1, Latin-2, ou tout autre alphabet 8 bits).

MODULES D'AIDE

MIME::Lite fonctionne bien avec d'autres modules s'ils sont présents. Les modules recommandés à installer sont la dernière version de MIME::Types, Mail::Address, MIME::Base64, MIME::QuotedPrint, et Net::SMTP. Email::Date::Format est strictement nécessaire.

Si ces modules ne sont pas présents, certaines fonctions ne fonctionneront pas, et d'autres fonctionnalités seront moins performantes ou moins à jour qu'elles ne pourraient l'être. Ce sont cependant des extras optionnels.

BONBONS GROUPÉS

MIME::Lite est livré avec plusieurs fichiers supplémentaires dans le groupe de distribution. Cela inclut des exemples et des modules utilitaires que vous pouvez utiliser pour commencer à utiliser le module.

Le répertoire ./examples contient divers extraits préparés, généralement documentés, mais qui devraient être faciles à comprendre.

Le répertoire ./contrib contient des modules/outils compagnons qui sont inclus avec MIME::Lite, mais ne sont pas installés par défaut. Veuillez consulter les POD qui les accompagnent.

BOGUES

La raison pour laquelle la version 3.0 a été publiée était de s'assurer que MIME::Lite soit à jour et corrigé. Si vous rencontrez un problème, veuillez le signaler.

Autant que je sache, MIME::Lite n'a actuellement aucun problème sérieux, mais mon utilisation est pratiquement incomplète.

Malgré tout, il y a plusieurs problèmes ouverts qui me préoccupent, principalement causés par l'avancement de la communauté depuis qu'Eryq a sorti la dernière version. Les tests reposent sur un framework de test intéressant mais non standard. Je voudrais passer à Test::More.

Si les tests échouent, veuillez consulter le répertoire ./testout et, dans tout rapport de bogue, inclure la sortie du fichier pertinent. C'est la seule caractéristique rédemptrice de ne pas utiliser Test::More que je vois.

Les corrections, les correctifs et les contributions sont les bienvenus, bien que je ne les applique probablement pas s'ils n'ont pas de test associé. Cela signifie que si je n'ai pas le temps d'écrire le test, la correction ne sera pas appliquée, alors veuillez inclure des tests pour toute correction que vous fournissez.
