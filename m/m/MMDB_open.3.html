DESCRIPTION

La bibliothèque libmaxminddb fournit des fonctions pour travailler avec des fichiers MaxMind DB. Consultez https://maxmind.github.io/MaxMind-DB/ pour la spécification du format des fichiers MaxMind DB. Les bases de données et les résultats sont représentés par différentes structures. Les bases de données sont ouvertes en appelant MMDB_open(). Vous pouvez rechercher des adresses IP en tant que chaîne de caractères avec MMDB_lookup_string() ou en tant que structure sockaddr avec MMDB_lookup_sockaddr().

Si la recherche trouve l'adresse IP dans la base de données, elle renvoie une structure MMDB_lookup_result_s. Si cette structure indique que la base de données contient des données pour l'adresse IP, plusieurs fonctions peuvent être utilisées pour récupérer ces données. Celles-ci incluent MMDB_get_value() et MMDB_get_entry_data_list(). Consultez la documentation des fonctions pour plus de détails ci-dessous.

Lorsque vous avez terminé avec le handle de la base de données, vous devez appeler MMDB_close().

Toutes les fonctions, structures et macros publiques commencent par MMDB_.

STRUCTURES DE DONNÉES

Toutes les structures exportées par le fichier maxminddb.h de cette bibliothèque sont définies comme typedef struct foo_s { ... } foo_s, vous pouvez donc y faire référence sans le préfixe struct.

Cette bibliothèque fournit les structures suivantes :

MMDB_s

Ceci est la référence du handle d'un fichier MaxMind DB. Nous ne documentons que certains des champs de cette structure destinés à un usage public. Tous les autres champs sont sujets à modification et sont destinés uniquement à un usage interne.

typedef struct MMDB_s {
    uint32_t flags;
    const char *filename;
    ...
    MMDB_metadata_s metadata;
} MMDB_s;
  • uint32_t flags - les indicateurs avec lesquels cette base de données a été ouverte. Consultez la documentation de MMDB_open() pour plus de détails.
  • const char *filename - le nom du fichier qui a été ouvert, tel que passé à MMDB_open().
  • MMDB_metadata_s metadata - les métadonnées de la base de données.

MMDB_metadata_s et MMDB_description_s

Cette structure peut être obtenue à partir de la structure MMDB_s. Elle contient les métadonnées lues à partir d'un fichier de base de données. Note : il peut être plus pratique d'accéder à ces métadonnées en appelant MMDB_get_metadata_as_entry_data_list().

typedef struct MMDB_metadata_s {
    uint32_t node_count;
    uint16_t record_size;
    uint16_t ip_version;
    const char *database_type;
    struct {
        size_t count;
        const char **names;
    } languages;
    uint16_t binary_format_major_version;
    uint16_t binary_format_minor_version;
    uint64_t build_epoch;
    struct {
        size_t count;
        MMDB_description_s **descriptions;
    } description;
} MMDB_metadata_s;
typedef struct MMDB_description_s {
    const char *language;
    const char *description;
} MMDB_description_s;

Ces structures devraient être principalement auto-explicatives.

Le membre ip_version doit toujours être 4 ou 6. Le membre binary_format_major_version doit toujours être 2.

Il n'y a aucune exigence que les métadonnées de la base de données incluent des langues ou des descriptions, donc les valeurs count pour ces parties des métadonnées peuvent être zéro. Tous les autres membres de MMDB_metadata_s doivent être remplis.

MMDB_lookup_result_s

Cette structure est renvoyée comme résultat de la recherche d'une adresse IP.

typedef struct MMDB_lookup_result_s {
    bool found_entry;
    MMDB_entry_s entry;
    uint16_t netmask;
} MMDB_lookup_result_s;

Si le membre found_entry est faux, les autres membres de cette structure ne contiennent pas de valeurs significatives. Vous devez toujours vérifier d'abord que found_entry est vrai.

Le membre entry est utilisé pour rechercher les données associées à l'adresse IP.

Le membre netmask indique à quelle sous-réseau appartient l'adresse IP dans cette base de données. Par exemple, si vous recherchez l'adresse 1.1.1.1 dans une base de données IPv4 et que la valeur renvoyée est 16, alors l'adresse appartient à la sous-réseau 1.1.0.0/16.

Si la base de données est une base de données IPv6, la valeur renvoyée pour netmask est toujours une longueur de préfixe IPv6 (de 0 à 128), même si cette base de données contient également des réseaux IPv4. Si vous recherchez une adresse IPv4 et souhaitez convertir le masque de réseau en une valeur de sous-réseau IPv4, vous pouvez simplement soustraire 96 de la valeur.

MMDB_result_s

Vous n'avez pas vraiment besoin d'explorer cette structure. Vous obtiendrez cette structure à partir d'une structure MMDB_lookup_result_s et vous passerez cette structure à diverses fonctions.

MMDB_entry_data_s

Cette structure est utilisée pour renvoyer un seul bloc de données à partir d'une adresse IP. Ces blocs de données peuvent pointer vers d'autres blocs de données, comme dans le cas des maps et des tableaux. Certains membres de cette structure ne sont pas documentés car ils sont destinés uniquement à un usage interne.

typedef struct MMDB_entry_data_s {
    bool has_data;
    union {
        uint32_t pointer;
        const char *utf8_string;
        double double_value;
        const uint8_t *bytes;
        uint16_t uint16;
        uint32_t uint32;
        int32_t int32;
        uint64_t uint64;
        {mmdb_uint128_t or uint8_t[16]} uint128;
        bool boolean;
        float float_value;
    };
    ...
    uint32_t data_size;
    uint32_t type;
} MMDB_entry_data_s;

Le membre has_data est vrai si des données ont été trouvées pour une recherche donnée. Consultez MMDB_get_value() pour plus de détails. Si ce membre est faux, aucune des autres valeurs de la structure n'est significative.

L'union au début de la structure définit les données réelles. Pour déterminer quel membre de l'union est actif, consultez MMDB_get_value().

Ce site n'est en aucun cas associé à Arch Linux ni affilié à ce projet. Le contenu est uniquement une traduction des pages de manuel d'Arch publiées sur man.archlinux.org.

lated vous devriez regarder le membre type. Le membre pointer de l'union ne doit jamais être rempli dans des données retournées par l'API. Les pointeurs doivent toujours être résolus en interne.

Le membre data_size n'est pertinent que pour les données utf8_string et bytes. utf8_string n'est pas terminé par un caractère nul et data_size doit être utilisé pour déterminer sa longueur.

Le membre type peut être comparé à l'une des macros MMDB_DATA_TYPE_*.

Entiers 128 bits

La gestion des données uint128 dépend de la manière dont votre plateforme prend en charge les entiers 128 bits, si elle le fait. Avec GCC 4.4 et 4.5, nous pouvons écrire unsigned int __attribute__ ((__mode__ (TI))). Avec les versions plus récentes de GCC (4.6+) et clang (3.2+), nous pouvons simplement écrire "unsigned __int128".

Afin de contourner ces différences, cette bibliothèque définit un type mmdb_uint128_t. Ce type est défini dans l'en-tête maxminddb.h afin que vous puissiez l'utiliser dans votre propre code.

Avec les anciens compilateurs, nous ne pouvons pas utiliser un entier et utilisons à la place un tableau de 16 octets de valeurs uint8_t. Il s'agit des données brutes de la base de données.

Cette bibliothèque fournit une macro publique MMDB_UINT128_IS_BYTE_ARRAY. Si elle est vraie (1), alors les valeurs uint128 sont retournées sous forme de tableau d'octets, si elle est fausse, elles sont retournées sous forme d'entier mmdb_uint128_t.

Macros de types de données

Cette bibliothèque fournit une macro pour chaque type de données défini par la spécification MaxMind DB.

  • MMDB_DATA_TYPE_UTF8_STRING
  • MMDB_DATA_TYPE_DOUBLE
  • MMDB_DATA_TYPE_BYTES
  • MMDB_DATA_TYPE_UINT16
  • MMDB_DATA_TYPE_UINT32
  • MMDB_DATA_TYPE_MAP
  • MMDB_DATA_TYPE_INT32
  • MMDB_DATA_TYPE_UINT64
  • MMDB_DATA_TYPE_UINT128
  • MMDB_DATA_TYPE_ARRAY
  • MMDB_DATA_TYPE_BOOLEAN
  • MMDB_DATA_TYPE_FLOAT

Il existe également quelques types réservés à un usage interne :

  • MMDB_DATA_TYPE_EXTENDED
  • MMDB_DATA_TYPE_POINTER
  • MMDB_DATA_TYPE_CONTAINER
  • MMDB_DATA_TYPE_END_MARKER

Si vous en voyez dans les données retournées, quelque chose s'est mal passé. La base de données est endommagée ou a été générée incorrectement, ou il y a un bug dans le code de libmaxminddb.

Valeurs de pointeur et MMDB_close()

Les membres utf8_string, bytes et (peut-être) uint128 de cette structure sont tous des pointeurs directs dans la section de données de la base de données. Il peut s'agir d'un bloc de mémoire alloué par calloc ou mmap. Dans les deux cas, ces pointeurs deviendront invalides après l'appel de MMDB_close().

Si vous devez faire référence à ces données après ce délai, vous devriez copier les données avec une fonction appropriée (strdup, memcpy, etc.).

MMDB_entry_data_list_s

Cette structure encapsule une liste chaînée de structures MMDB_entry_data_s.

typedef struct MMDB_entry_data_list_s {
    MMDB_entry_data_s entry_data;
    struct MMDB_entry_data_list_s *next;
} MMDB_entry_data_list_s;

Cette structure vous permet d'examiner l'ensemble des données d'une carte ou d'un tableau en parcourant la liste chaînée.

MMDB_search_node_s

Cette structure encapsule les deux enregistrements d'un nœud de recherche. Ceci est vraiment utile uniquement si vous souhaitez écrire du code qui parcourt l'arbre de recherche complet au lieu de rechercher une adresse IP spécifique.

typedef struct MMDB_search_node_s {
    uint64_t left_record;
    uint64_t right_record;
    uint8_t left_record_type;
    uint8_t right_record_type;
    MMDB_entry_s left_record_entry;
    MMDB_entry_s right_record_entry;
} MMDB_search_node_s;

Les deux types d'enregistrements prendront l'une des valeurs suivantes :

  • MMDB_RECORD_TYPE_SEARCH_NODE - L'enregistrement pointe vers le nœud de recherche suivant.
  • MMDB_RECORD_TYPE_EMPTY - L'enregistrement est un espace réservé qui indique qu'il n'y a pas de données pour l'adresse IP. La recherche doit se terminer ici.
  • MMDB_RECORD_TYPE_DATA - L'enregistrement contient des données dans la section de données de la base de données. Utilisez l'entrée pour l'enregistrement lors de la recherche des données de cet enregistrement.
  • MMDB_RECORD_TYPE_INVALID - L'enregistrement est invalide. Soit un nœud invalide a été recherché, soit la base de données est corrompue.

La MMDB_entry_s pour l'enregistrement n'est valide que si le type est MMDB_RECORD_TYPE_DATA. Les tentatives d'utilisation d'une entrée pour d'autres types d'enregistrements entraîneront une erreur ou des données invalides.

CODES DE STATUT

Cette bibliothèque retourne (ou peuple) des codes de statut pour de nombreuses fonctions. Ces codes de statut sont :

  • MMDB_SUCCESS - tout a fonctionné
  • MMDB_FILE_OPEN_ERROR - il y a eu une erreur lors de la tentative d'ouverture du fichier MaxMind DB.
  • MMDB_IO_ERROR - une opération d'E/S a échoué. Vérifiez errno pour plus de détails.
  • MMDB_CORRUPT_SEARCH_TREE_ERROR - la recherche d'une adresse IP dans l'arbre de recherche a donné un résultat impossible. La base de données est endommagée ou a été générée incorrectement, ou il y a un bug dans le code de libmaxminddb.
  • MMDB_INVALID_METADATA_ERROR - quelque chose dans la base de données est incorrect. Cela inclut les clés de métadonnées manquantes ainsi que les valeurs impossibles (comme une ip_version de 7).
  • MMDB_UNKNOWN_DATABASE_FORMAT_ERROR - Les métadonnées de la base de données indiquent que sa version majeure n'est pas 2. Cette bibliothèque ne peut gérer que la version majeure 2.
  • MMDB_OUT_OF_MEMORY_ERROR - un appel d'allocation mémoire (malloc, etc.) a échoué.
  • MMDB_INVALID_DATA_ERROR - une entrée dans la section de données contient des données invalides. Par exemple, un champ uint16 prétend avoir plus de 2 octets. La base de données est probablement endommagée ou a été générée incorrectement.
  • MMDB_INVALID_LOOKUP_PATH_ERROR - Le chemin de recherche passé à MMDB_get_value, MMDB_vget_value ou MMDB_aget_value contient un décalage de tableau supérieur à LONGMAX ou inférieur à LONGMIN.
  • MMDB_LOOKUP_PATH_DOES_NOT_MATCH_DATA_ERROR - Le chemin de recherche passé à MMDB_get_value,MMDB_vget_value, ou MMDB_aget_value ne correspond pas à la structure de données de l'entrée. Il y a plusieurs raisons à cela. Le chemin de recherche pourrait inclure une clé non présente dans une carte. Le chemin de recherche pourrait inclure un index de tableau supérieur à la taille d'un tableau ou inférieur au décalage minimum à partir de la fin d'un tableau. Cela peut également se produire lorsque le chemin s'attend à trouver une carte ou un tableau là où aucun n'existe.

Tous les codes de statut doivent être traités comme des valeurs int.

MMDB_strerror()

const char *MMDB_strerror(int error_code)

Cette fonction prend un code de statut et retourne une chaîne en anglais expliquant le statut.

FONCTIONS

Cette bibliothèque fournit les fonctions exportées suivantes :

MMDB_open()

int MMDB_open(
    const char *const filename,
    uint32_t flags,
    MMDB_s *const mmdb);

Cette fonction ouvre un handle vers un fichier MaxMind DB. Sa valeur de retour est un code de statut tel que défini ci-dessus. Vérifiez toujours la valeur de retour de cet appel.

MMDB_s mmdb;
int status =
    MMDB_open("/path/to/file.mmdb", MMDB_MODE_MMAP, &mmdb);
if (MMDB_SUCCESS != status) { ... }
...
MMDB_close(&mmdb);

filename doit être encodé en UTF-8 sur Windows.

La structure MMDB_s que vous passez peut être sur la pile ou allouée depuis le tas. Cependant, si l'ouverture réussit, elle contiendra des données allouées par le tas, vous devrez donc la fermer avec MMDB_close(). Si le statut retourné n'est pas MMDB_SUCCESS, cette bibliothèque s'assure que toute la mémoire allouée est libérée avant de retourner.

Les drapeaux actuellement fournis sont :

•
MMDB_MODE_MMAP - ouvrir la base de données avec mmap().

Passer d'autres valeurs pour flags peut donner des résultats imprévisibles. À l'avenir, nous pourrions ajouter des indicateurs supplémentaires que vous pouvez combiner par un OU binaire avec le mode, ainsi que des modes supplémentaires.

Vous pouvez également passer 0 comme valeur de flags, auquel cas la base de données sera ouverte avec les drapeaux par défaut. Cependant, ces valeurs par défaut peuvent changer dans les futures versions. La valeur par défaut actuelle est MMDB_MODE_MMAP.

MMDB_close()

void MMDB_close(MMDB_s *const mmdb);

Cela libère toute mémoire allouée ou mappée en mémoire détenue par la structure MMDB_s. *Cela ne libère pas la mémoire allouée

pour la structure elle-même ! Si vous avez alloué la structure à partir du tas, vous êtes responsable de sa libération.

MMDB_lookup_string()

MMDB_lookup_result_s MMDB_lookup_string(
    MMDB_s *const mmdb,
    const char *const ipstr,
    int *const gai_error,
    int *const mmdb_error);

Cette fonction recherche une adresse IP passée sous forme de chaîne de caractères se terminant par un caractère nul. En interne, elle appelle getaddrinfo() pour résoudre l'adresse sous forme binaire. Ensuite, elle appelle MMDB_lookup_sockaddr() pour rechercher l'adresse dans la base de données. Si vous avez déjà résolu une adresse, vous pouvez appeler MMDB_lookup_sockaddr() directement, plutôt que de résoudre l'adresse deux fois.

int gai_error, mmdb_error;
MMDB_lookup_result_s result =
    MMDB_lookup_string(&mmdb, "1.2.3.4", &gai_error, &mmdb_error);
if (0 != gai_error) { ... }
if (MMDB_SUCCESS != mmdb_error) { ... }
if (result.found_entry) { ... }

Cette fonction renvoie toujours une structure MMDB_lookup_result_s, mais vous devez également vérifier les paramètres gai_error et mmdb_error. Si l'un de ces paramètres indique une erreur, la structure renvoyée est dénuée de sens.

Si aucune erreur ne s'est produite, vous devez toujours vous assurer que le membre found_entry dans le résultat renvoyé est vrai. S'il est faux, cela signifie que l'adresse IP n'a pas d'entrée dans la base de données.

Cette fonction fonctionnera avec les adresses IPv4 même lorsque la base de données contient des données pour les adresses IPv4 et IPv6. L'adresse IPv4 sera recherchée en tant que '::xxx.xxx.xxx.xxx' plutôt que d'être remappée dans le bloc ::ffff:xxx.xxx.xxx.xxx alloué aux adresses IPv6 mappées IPv4.

Si vous passez une adresse IPv6 à une base de données ne contenant que des données IPv4, le membre found_entry sera faux, mais le statut mmdb_error sera toujours MMDB_SUCCESS.

MMDB_lookup_sockaddr()

MMDB_lookup_result_s MMDB_lookup_sockaddr(
    MMDB_s *const mmdb,
    const struct sockaddr *const sockaddr,
    int *const mmdb_error);

Cette fonction recherche une adresse IP qui a déjà été résolue par getaddrinfo().

À part le fait de ne pas appeler getaddrinfo() elle-même, cette fonction est identique à la fonction MMDB_lookup_string().

int mmdb_error;
MMDB_lookup_result_s result =
    MMDB_lookup_sockaddr(&mmdb, address->ai_addr, &mmdb_error);
if (MMDB_SUCCESS != mmdb_error) { ... }
if (result.found_entry) { ... }

Fonctions de recherche de données

Il existe trois fonctions pour rechercher des données associées à une adresse IP.

int MMDB_get_value(
    MMDB_entry_s *const start,
    MMDB_entry_data_s *const entry_data,
    ...);
int MMDB_vget_value(
    MMDB_entry_s *const start,
    MMDB_entry_data_s *const entry_data,
    va_list va_path);
int MMDB_aget_value(
    MMDB_entry_s *const start,
    MMDB_entry_data_s *const entry_data,
    const char *const *const path);

Les trois fonctions permettent trois styles d'appel légèrement différents, mais elles font toutes la même chose.

Le premier paramètre est une valeur MMDB_entry_s. Dans la plupart des cas, elle proviendra de la valeur MMDB_lookup_result_s renvoyée par MMDB_lookup_string() ou MMDB_lookup_sockaddr().

Le second paramètre est une référence à une structure MMDB_entry_data_s. Elle sera remplie avec les données recherchées, si des données sont trouvées. Si rien n'est trouvé, le membre has_data de cette structure sera faux. Si has_data est vrai, vous pouvez regarder le membre data_type.

Le dernier paramètre est un chemin de recherche. Le chemin se compose d'un ensemble de chaînes de caractères représentant soit des clés de carte (par exemple, « ville »), soit des indices de tableau (par exemple, « 0 », « 1 », « -1 ») à utiliser dans la recherche.

Les indices de tableau négatifs seront traités comme un décalage par rapport à la fin du tableau. Par exemple, « -1 » fait référence au dernier élément du tableau.

Le chemin de recherche vous permet de naviguer dans une structure de données complexe. Par exemple, étant donné ces données :

{
    "names": {
        "en": "Germany",
        "de": "Deutschland"
    },
    "cities": [ "Berlin", "Frankfurt" ]
}

Nous pourrions rechercher le nom en anglais avec ce code :

MMDB_lookup_result_s result =
    MMDB_lookup_sockaddr(&mmdb, address->ai_addr, &mmdb_error);
MMDB_entry_data_s entry_data;
int status =
    MMDB_get_value(&result.entry, &entry_data,
                   "names", "en", NULL);
if (MMDB_SUCCESS != status) { ... }
if (entry_data.has_data) { ... }

Si nous voulions trouver la première ville, le chemin de recherche serait "cities", "0". Si vous ne fournissez pas du tout de chemin de recherche, vous obtiendrez l'entrée qui correspond à la carte de niveau supérieur. Le chemin de recherche doit toujours se terminer par NULL, quelle que soit la fonction que vous appelez.

La fonction MMDB_get_value prend un nombre variable d'arguments. Tous les arguments après le pointeur de structure MMDB_entry_data_s * sont le chemin de recherche. Le dernier argument doit être NULL.

La fonction MMDB_vget_value accepte une va_list comme chemin de recherche. Le dernier élément récupéré par va_arg() doit être NULL.

Enfin, la fonction MMDB_aget_value accepte un tableau de chaînes de caractères comme chemin de recherche. Le dernier membre de ce tableau doit être NULL.

Si vous souhaitez obtenir toutes les données d'entrée en une seule fois, vous pouvez appeler MMDB_get_entry_data_list() à la place.

Pour chacune des trois fonctions, la valeur de retour est un code d'état tel que défini ci-dessus.

MMDB_get_entry_data_list()

int MMDB_get_entry_data_list(
    MMDB_entry_s *start,
    MMDB_entry_data_list_s **const entry_data_list);

Cette fonction vous permet d'obtenir toutes les données d'une structure de données complexe en une seule fois, plutôt que de rechercher chaque élément à l'aide d'appels répétés à MMDB_get_value().

MMDB_lookup_result_s result =
    MMDB_lookup_sockaddr(&mmdb, address->ai_addr, &mmdb_error);
MMDB_entry_data_list_s *entry_data_list, *first;
int status =
    MMDB_get_entry_data_list(&result.entry, &entry_data_list);
if (MMDB_SUCCESS != status) { ... }
// sauvegarder ceci pour pouvoir libérer ces données plus tard
first = entry_data_list;
while (1) {
    MMDB_entry_data_list_s *next = entry_data_list = entry_data_list->next;
    if (NULL == next) {
        break;
    }
    switch (next->entry_data.type) {
        case MMDB_DATA_TYPE_MAP: { ... }
        case MMDB_DATA_TYPE_UTF8_STRING: { ... }
        ...
    }
}
MMDB_free_entry_data_list(first);

Il vous appartient d'interpréter la structure de données entry_data_list. La liste est liée dans un parcours en profondeur. Utilisons cette structure comme exemple :

{
    "names": {
        "en": "Germany",
        "de": "Deutschland"
    },
    "cities": [ "Berlin", "Frankfurt" ]
}

La liste sera composée des éléments suivants :

1.
MAP - carte de niveau supérieur
2.
UTF8_STRING - clé « names »
3.
MAP - carte pour la clé « names »
4.
UTF8_STRING - clé « en »
5.
UTF8_STRING - valeur pour la clé « en »
6.
UTF8_STRING - clé « de »
7.
UTF8_STRING - valeur pour la clé « de »
8.
UTF8_STRING - clé « cities »
9.
ARRAY - valeur pour la clé « cities »
10.
UTF8_STRING - tableau[0]
11.
UTF8_STRING - tableau[1]

La valeur de retour de la fonction est un code d'état tel que défini ci-dessus.

MMDB_free_entry_data_list()

void MMDB_free_entry_data_list(
    MMDB_entry_data_list_s *const entry_data_list);

Les fonctions MMDB_get_entry_data_list() et MMDB_get_metadata_as_entry_data_list() alloueront la structure de liste chaînée à partir du tas. Appelez cette fonction pour libérer la structure MMDB_entry_data_list_s.

MMDB_get_metadata_as_entry_data_list()

int MMDB_get_metadata_as_entry_data_list(
    MMDB_s *const mmdb,
    MMDB_entry_data_list_s **const entry_data_list);

Cette fonction vous permet de récupérer les métadonnées de la base de données sous forme de liste chaînée de structures MMDB_entry_data_list_s. Cela peut être une manière plus pratique de traiter les métadonnées que d'utiliser directement la structure des métadonnées.

    MMDB_entry_data_list_s *entry_data_list, *first;
    int status =
        MMDB_get_metadata_as_entry_data_list(&mmdb, &entry_data_list);
    if (MMDB_SUCCESS != status) { ... }
    first = entry_data_list;
    ... // faire quelque chose avec les données
    MMDB_free_entry_data_list(first);

La valeur de retour de la fonction est un code d'état tel que défini ci-dessus.

MMDB_dump_entry_data_list()

int MMDB_dump_entry_data_list(
    FILE *const stream,
    MMDB_entry_data_list_s *const entry_data_list,
    int indent);

Cette fonction prend une liste chaînée de structures MMDB_entry_data_list_s et la transforme en chaîne de caractères pour le stream donné. Le paramètre indent est le niveau d'indentation de départ pour la sortie générée. Il est incrémenté pour les structures de données imbriquées (cartes, tableaux, etc.).

Le stream doit être un descripteur de fichier ( stdout, etc.). Si votre plateforme fournit quelque chose comme open_memstream() de GNU, vous pouvez l'utiliser pour capturer la sortie sous forme de chaîne.

La sortie est formatée d'une manière similaire au JSON, mais les valeurs sont marquées avec leur type de données (sauf pour les cartes et les tableaux qui sont affichés avec « {} » et « [] » respectivement).

Le format de sortie spécifique peut changer dans les futures versions

MMDB_open(3) — libmaxminddb

NAME

MMDB_open, MMDB_close, MMDB_read_node, MMDB_lib_version — MaxMind DB file access

SYNOPSIS

#include <maxminddb.h>
int MMDB_open(
    const char *filename,
    MMDB_mode_e mode,
    MMDB_s *const mmdb);
void MMDB_close(MMDB_s *mmdb);
int MMDB_read_node(
    MMDB_s *const mmdb,
    uint32_t node_number,
    MMDB_search_node_s *const node);
const char *MMDB_lib_version(void);

DESCRIPTION

The MaxMind DB file format is a binary format that stores geographical data. This library allows you to read that data.

MMDB_open() opens a MaxMind DB file in the path specified by filename. If the file cannot be opened or if it is not a valid MaxMind DB file, an error is returned.

The mode argument specifies how the file should be accessed. The following modes are supported:

MMDB_MODE_MMAP
Memory map the database file. This is the most performant mode. This is the default mode.
MMDB_MODE_FILE
Read the database file using standard file I/O operations.

MMDB_close() closes the database file and releases any associated resources.

MMDB_read_node() reads a specific node from the database's search tree. This is useful for iterating over the entire database, or for debugging purposes.

MMDB_lib_version() returns a string representing the version of the library.

MMDB_lookup_string()

MMDB_lookup_result_s MMDB_lookup_string(
    MMDB_s *const mmdb,
    const char *ip_address,
    int *gai_error,
    int *mmdb_error);

This is the primary function for looking up an IP address in the database. The ip_address argument should be a string representation of the IP address you want to look up.

The function returns an MMDB_lookup_result_s structure, which contains information about the lookup result. The gai_error and mmdb_error arguments are pointers to integers that will be populated with error codes from getaddrinfo() and libmaxminddb, respectively, if an error occurs.

If the IP address is found in the database, the found_entry field of the returned structure will be true, and the entry field will contain the data for that entry.

MMDB_strerror()

const char *MMDB_strerror(int status);

This function returns a human-readable string representation of the given status code.

MMDB_dump_entry_data_list()

void MMDB_dump_entry_data_list(
    FILE *file,
    MMDB_entry_data_list_s *entry_data_list,
    int indent);

This function dumps the contents of an MMDB_entry_data_list_s structure to the given file pointer. This is useful for debugging and understanding the structure of the data in the database. The indent argument specifies the indentation level for the output.

This function is intended for debugging and user display only. The output format is not guaranteed to be stable across library versions.

MMDB_free_entry_data_list()

void MMDB_free_entry_data_list(MMDB_entry_data_list_s *entry_data_list);

Frees the memory allocated for an MMDB_entry_data_list_s structure. This should be called after you are finished with the list returned by MMDB_get_entry_data_list().

MMDB_get_entry_data_list()

int MMDB_get_entry_data_list(
    MMDB_entry_s *entry,
    MMDB_entry_data_list_s **entry_data_list);

This function retrieves the data associated with a specific entry in the MaxMind DB database as a linked list of MMDB_entry_data_s structures. The entry is identified by the MMDB_entry_s structure obtained from a lookup operation.

The data is returned in the entry_data_list argument, which is a pointer to a pointer to an MMDB_entry_data_list_s. The function allocates memory for this list and its contents, which must be freed later using MMDB_free_entry_data_list().

The return value is a status code. If the operation is successful, it returns MMDB_SUCCESS. Errors may include MMDB_ALLOC_ERROR if memory allocation fails, or other error codes if the entry data cannot be retrieved.

MMDB_search_node_s

This structure represents a node in the MaxMind DB search tree. It is populated by the MMDB_read_node() function.

typedef struct {
    uint32_t node_number;
    MMDB_record_type_e record_type;
    union {
        uint32_t search_node;
        MMDB_entry_s entry;
    } content;
} MMDB_search_node_s;

The fields are:

node_number
The number of this node in the search tree.
record_type
The type of the record stored in this node. Possible values are MMDB_RECORD_TYPE_INTERNAL, MMDB_RECORD_TYPE_SEARCH_NODE, and MMDB_RECORD_TYPE_DATA.
content
A union containing the actual content of the node, depending on the record_type.
search_node
If record_type is MMDB_RECORD_TYPE_SEARCH_NODE, this holds the node number of the next node to read.
entry
If record_type is MMDB_RECORD_TYPE_DATA, this holds the MMDB_entry_s structure representing the data found at this node.

Note that the MMDB_read_node() function populates this structure. The format of the returned data is specific to the internal representation of the library and should not be relied upon for parsing. It is intended for user display and debugging.

MMDB_entry_data_s

This structure represents a piece of data within a MaxMind DB entry. It is part of the linked list returned by MMDB_get_entry_data_list().

typedef struct MMDB_entry_data_list_s {
    MMDB_entry_data_s entry_data;
    struct MMDB_entry_data_list_s *next;
} MMDB_entry_data_list_s;

The fields of the MMDB_entry_data_s structure within the list are:

type
The data type of this value (e.g., string, integer, map, array).
size
The size of the data in bytes.
uint8
Pointer to the data, treated as an array of unsigned 8-bit integers.

The MMDB_entry_data_list_s structure itself is a node in a singly linked list. The entry_data field holds the actual data for this part of the entry, and the next field points to the next data element in the entry, or NULL if this is the last element.

The data pointed to by uint8 is not null-terminated and is not necessarily a string. You will need to interpret the data based on its type. For example, if the type is MMDB_DATA_TYPE_STRING, the data is a UTF-8 encoded string of length size. If the type is MMDB_DATA_TYPE_UINT32, the data represents a 32-bit unsigned integer. The library does not perform byte-swapping; you must handle endianness yourself if necessary.

The specific formatting and interpretation of this data is complex and depends on the MaxMind DB specification. For most use cases, it is recommended to use higher-level functions or tools that handle the data interpretation, rather than directly parsing the MMDB_entry_data_s structure.

MMDB_lookup_result_s

This structure is returned by lookup functions like MMDB_lookup_string() and contains the result of the IP address lookup.

typedef struct {
    int found_entry;
    MMDB_entry_s entry;
} MMDB_lookup_result_s;

The fields are:

found_entry
A boolean flag indicating whether an entry for the requested IP address was found in the database. It is true if an entry was found, false otherwise.
entry
If found_entry is true, this field contains an MMDB_entry_s structure representing the data associated with the found IP address. If no entry was found, this structure is in an indeterminate state.

MMDB_entry_s

This structure represents a single entry (record) in the MaxMind DB database. It is returned within the MMDB_lookup_result_s structure if an IP address lookup is successful.

typedef struct {
    uint32_t node_number;
    MMDB_record_type_e record_type;
    union {
        uint32_t search_node;
        MMDB_entry_data_list_s *entry_data_list;
    } content;
} MMDB_entry_s;

The fields are:

node_number
The internal node number within the MaxMind DB tree structure where this entry's data is located.
record_type
Indicates the type of record this entry represents. It can be MMDB_RECORD_TYPE_INTERNAL, MMDB_RECORD_TYPE_SEARCH_NODE, or MMDB_RECORD_TYPE_DATA. For lookup results, it's typically MMDB_RECORD_TYPE_DATA.
content
A union holding the specific content of the entry based on its record_type.
search_node
If record_type is MMDB_RECORD_TYPE_SEARCH_NODE, this holds the number of the next node to follow in the search tree.
entry_data_list
If record_type is MMDB_RECORD_TYPE_DATA, this is a pointer to the head of a linked list (MMDB_entry_data_list_s) containing the actual data associated with the IP address. This list needs to be freed using MMDB_free_entry_data_list() after use.

It's important to note that the entry field in MMDB_lookup_result_s might contain an MMDB_entry_s structure where the entry_data_list pointer is NULL or points to an invalid structure if the lookup failed or if the entry itself is empty. Always check the found_entry flag first. When you get an entry, you typically want to call MMDB_get_entry_data_list() to properly retrieve and allocate the data associated with it.

STATUS CODES

The functions in this library return integer status codes. The following codes are defined:

MMDB_SUCCESS
The operation was successful.
MMDB_FILE_NOT_FOUND_ERROR
The database file could not be found.
MMDB_CORRUPT_MMDB_ERROR
The database file is corrupt or not a valid MaxMind DB file.
MMDB_INVALID_INTERFACE_ERROR
An invalid interface was used (e.g., trying to use a closed database).
MMDB_INVALID_MMDB_ERROR
The database file is not a valid MaxMind DB format.
MMDB_IO_ERROR
An I/O error occurred while reading the database file.
MMDB_OUT_OF_MEMORY_ERROR
Not enough memory is available.
MMDB_NULL_POINTER_ERROR
A required pointer argument was NULL.
MMDB_INVALID_LOOKUP_PATH_ERROR
The lookup path specified was invalid.
MMDB_INVALID_LICENSE_KEY_ERROR
The license key provided was invalid.
MMDB_INVALID_NODE_NUMBER_ERROR
The provided node number is out of bounds for the database.
MMDB_UNEXPECTED_END_OF_MMDB_DATA_ERROR
The end of the database file was reached unexpectedly during parsing.
MMDB_OUT_OF_Trie_ALLOCATIONS_ERROR
A limit on the number of trie allocations was exceeded.
MMDB_CRASH_EXIT_SUCCESS_CODE
This is not an error code but an internal value used to signal a specific condition.

FUNCTIONS

The libmaxminddb library provides the following functions:

MMDB_open()

int MMDB_open(
    const char *filename,
    MMDB_mode_e mode,
    MMDB_s *const mmdb);

Opens a MaxMind DB database file. filename is the path to the database file. mode specifies how the file should be accessed. See MMDB_MODE_MMAP and MMDB_MODE_FILE under DESCRIPTION for supported modes. mmdb is a pointer to an MMDB_s structure that will be initialized by this function.

Returns MMDB_SUCCESS on success, or an error code otherwise.

MMDB_close()

void MMDB_close(MMDB_s *mmdb);

Closes the MaxMind DB database file opened by MMDB_open() and frees any associated resources.

MMDB_lookup_string()

MMDB_lookup_result_s MMDB_lookup_string(
    MMDB_s *const mmdb,
    const char *ip_address,
    int *gai_error,
    int *mmdb_error);

Looks up the given IP address string in the database. mmdb is a pointer to an initialized MMDB_s structure. ip_address is the string representation of the IP address to look up. gai_error and mmdb_error are pointers to integers that will receive error codes from getaddrinfo(3) and libmaxminddb respectively, if an error occurs during the lookup.

Returns an MMDB_lookup_result_s structure. Check the found_entry field of the returned structure to determine if an entry was found. If found_entry is true, the entry field will contain the result.

MMDB_strerror()

const char *MMDB_strerror(int status);

Returns a human-readable string describing the given status code. This is useful for error reporting.

MMDB_get_entry_data_list()

int MMDB_get_entry_data_list(
    MMDB_entry_s *entry,
    MMDB_entry_data_list_s **entry_data_list);

Retrieves the data associated with a MaxMind DB entry as a linked list. entry is a pointer to the MMDB_entry_s structure obtained from a lookup result. entry_data_list is a pointer to a pointer where the head of the newly allocated linked list will be stored. The caller is responsible for freeing this list using MMDB_free_entry_data_list().

Returns MMDB_SUCCESS on success, or an error code (e.g., MMDB_ALLOC_ERROR) on failure.

MMDB_free_entry_data_list()

void MMDB_free_entry_data_list(MMDB_entry_data_list_s *entry_data_list);

Frees the memory allocated for the linked list returned by MMDB_get_entry_data_list().

MMDB_dump_entry_data_list()

void MMDB_dump_entry_data_list(
    FILE *file,
    MMDB_entry_data_list_s *entry_data_list,
    int indent);

Dumps the contents of an entry data list to a file stream for debugging or display. file is the output stream. entry_data_list is the list to dump. indent specifies the indentation level for the output. This function is intended for debugging and user display only; its output format is not guaranteed to be stable across library versions.

The return value of the function is a status code. If you pass a node_number that is greater than the number of nodes in the database, this function will return MMDB_INVALID_NODE_NUMBER_ERROR, otherwise it will return MMDB_SUCCESS.

The first node in the search tree is always node 0. If you wanted to iterate over the whole search tree, you would start by reading node 0 and then following the the records that make up this node, based on the type of each record. If the type is MMDB_RECORD_TYPE_SEARCH_NODE then the record contains an integer for the next node to look up.

MMDB_read_node()

int MMDB_read_node(
    MMDB_s *const mmdb,
    uint32_t node_number,
    MMDB_search_node_s *const node);

This reads a specific node in the search tree. The third argument is a reference to an MMDB_search_node_s structure that will be populated by this function.

The return value is a status code. If you pass a node_number that is greater than the number of nodes in the database, this function will return MMDB_INVALID_NODE_NUMBER_ERROR, otherwise it will return MMDB_SUCCESS.

The first node in the search tree is always node 0. If you wanted to iterate over the whole search tree, you would start by reading node 0 and then following the the records that make up this node, based on the type of each record. If the type is MMDB_RECORD_TYPE_SEARCH_NODE then the record contains an integer for the next node to look up.

MMDB_lib_version()

const char *MMDB_lib_version(void)

This function returns the library version as a string, something like "2.0.0".

EXAMPLE

#include <errno.h>
#include <maxminddb.h>
#include <stdlib.h>
#include <string.h>
int main(int argc, char **argv)
{
    char *filename = argv[1];
    char *ip_address = argv[2];
    MMDB_s mmdb;
    int status = MMDB_open(filename, MMDB_MODE_MMAP, &mmdb);
    if (MMDB_SUCCESS != status) {
        fprintf(stderr, "\n  Can't open %s - %s\n",
                filename, MMDB_strerror(status));
        if (MMDB_IO_ERROR == status) {
            fprintf(stderr, "    IO error: %s\n", strerror(errno));
        }
        exit(1);
    }
    int gai_error, mmdb_error;
    MMDB_lookup_result_s result =
        MMDB_lookup_string(&mmdb, ip_address, &gai_error, &mmdb_error);
    if (0 != gai_error) {
        fprintf(stderr,
                "\n  Error from getaddrinfo for %s - %s\n\n",
                ip_address, gai_strerror(gai_error));
        exit(2);
    }
    if (MMDB_SUCCESS != mmdb_error) {
        fprintf(stderr,
                "\n  Got an error from libmaxminddb: %s\n\n",
                MMDB_strerror(mmdb_error));
        exit(3);
    }
    MMDB_entry_data_list_s *entry_data_list = NULL;
    int exit_code = 0;
    if (result.found_entry) {
        int status = MMDB_get_entry_data_list(&result.entry,
                                              &entry_data_list);
        if (MMDB_SUCCESS != status) {
            fprintf(
                stderr,
                "Got an error looking up the entry data - %s\n",
                MMDB_strerror(status));
            exit_code = 4;
            goto end;
        }
        if (NULL != entry_data_list) {
            MMDB_dump_entry_data_list(stdout, entry_data_list, 2);
        }
    } else {
        fprintf(
            stderr,
            "\n  No entry for this IP address (%s) was found\n\n",
            ip_address);
        exit_code = 5;
    }
    end:
        MMDB_free_entry_data_list(entry_data_list);
        MMDB_close(&mmdb);
        exit(exit_code);
}
