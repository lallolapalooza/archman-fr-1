DESCRIPTION

La bibliothèque libmaxminddb fournit des fonctions pour travailler avec des fichiers MaxMind DB. Pour plus d'informations, consultez https://maxmind.github.io/MaxMind-DB/ pour la spécification du format MaxMind DB. Les données de la base de données et les résultats sont représentés par différentes structures. Les bases de données sont ouvertes en appelant MMDB_open(). Vous pouvez rechercher des adresses IP sous forme de chaînes avec MMDB_lookup_string() ou sous forme de pointeurs vers des structures sockaddr avec MMDB_lookup_sockaddr().

Si la recherche trouve l'adresse IP dans la base de données, elle renvoie une structure MMDB_lookup_result_s. Si cette structure indique que la base de données a des données pour l'adresse IP, plusieurs fonctions peuvent être utilisées pour obtenir ces données. Celles-ci incluent MMDB_get_value() et MMDB_get_entry_data_list(). Pour plus de détails, consultez la documentation des fonctions.

Lorsque vous avez terminé avec le gestionnaire de base de données, appelez MMDB_close().

Toutes les fonctions publiques, structures et macros commencent par MMDB_.

STRUCTURES DE DONNÉES

Toutes les structures exportées par l'en-tête maxminddb.h de cette bibliothèque sont définies comme typedef struct foo_s { ... } foo_s, vous pouvez donc y faire référence sans le préfixe struct.

Cette bibliothèque fournit les structures suivantes :

MMDB_s

Ceci est la référence au fichier de base de données MaxMind. Nous ne documentons que certains des champs de cette structure destinés à un usage public. Tous les autres champs sont susceptibles d'être modifiés et sont utiles uniquement en interne.

typedef struct MMDB_s {
    uint32_t flags;
    const char *filename;
    ...
    MMDB_metadata_s metadata;
} MMDB_s;
  • uint32_t flags - les drapeaux avec lesquels la base de données a été ouverte. Consultez la documentation de MMDB_open() pour plus de détails.
  • const char *filename - le nom du fichier ouvert, tel que passé à MMDB_open().
  • MMDB_metadata_s metadata - les métadonnées de la base de données.

MMDB_metadata_s et MMDB_description_s

Cette structure peut être obtenue à partir de MMDB_s. Elle contient les métadonnées lues à partir de la base de données. Remarque : il peut être plus pratique d'accéder à ces métadonnées en appelant MMDB_get_metadata_as_entry_data_list() plutôt qu'en y accédant directement.

typedef struct MMDB_metadata_s {
    uint32_t node_count;
    uint16_t record_size;
    uint16_t ip_version;
    const char *database_type;
    struct {
        size_t count;
        const char **names;
    } languages;
    uint16_t binary_format_major_version;
    uint16_t binary_format_minor_version;
    uint64_t build_epoch;
    struct {
        size_t count;
        MMDB_description_s **descriptions;
    } description;
} MMDB_metadata_s;
typedef struct MMDB_description_s {
    const char *language;
    const char *description;
} MMDB_description_s;

Ces structures devraient être assez autonomes.

Le membre ip_version doit toujours être 4 ou 6. Le membre binary_format_major_version doit toujours être 2.

Il n'y a aucune obligation que les métadonnées de la base de données incluent des langues ou des descriptions, donc le count pour ces aspects des métadonnées peut être de zéro. Tous les autres membres de MMDB_metadata_s doivent être remplis.

MMDB_lookup_result_s

Cette structure est renvoyée comme résultat d'une recherche d'adresse IP.

typedef struct MMDB_lookup_result_s {
    bool found_entry;
    MMDB_entry_s entry;
    uint16_t netmask;
} MMDB_lookup_result_s;

Si le membre found_entry est faux, les autres membres de cette structure ne contiennent pas de valeurs significatives. Vous devez toujours vérifier que found_entry est vrai en premier.

Le membre entry est utilisé pour rechercher les données associées à l'adresse IP.

Le membre netmask indique à quel sous-réseau l'adresse IP appartient dans cette base de données. Par exemple, si vous recherchez l'adresse 1.1.1.1 dans une base de données IPv4 et que la valeur renvoyée est 16, l'adresse appartient au sous-réseau 1.1.0.0/16.

Si la base de données est IPv6, la valeur renvoyée par netmask est toujours un préfixe IPv6 (de 0 à 128), même si cette base de données contient également des réseaux IPv4. Si vous recherchez une adresse IPv4 et que vous souhaitez convertir le masque de réseau en une valeur de sous-réseau IPv4, soustrayez simplement 96 de la valeur.

MMDB_result_s

Vous n'avez pas besoin de vous plonger dans cette structure. Vous obtiendrez cette structure à partir d'une structure MMDB_lookup_result_s et la transmettrez à diverses fonctions.

MMDB_entry_data_s

Cette structure est utilisée pour renvoyer un seul bloc de données associé à une adresse IP. Ces blocs peuvent pointer vers d'autres blocs, comme c'est le cas pour les maps et les tableaux. Certains membres de cette structure ne sont pas documentés car ils sont uniquement utiles en interne.

typedef struct MMDB_entry_data_s {
    bool has_data;
    union {
        uint32_t pointer;
        const char *utf8_string;
        double double_value;
        const uint8_t *bytes;
        uint16_t uint16;
        uint32_t uint32;
        int32_t int32;
        uint64_t uint64;
        {mmdb_uint128_t or uint8_t[16]} uint128;
        bool boolean;
        float float_value;
    };
    ...
    uint32_t data_size;
    uint32_t type;
} MMDB_entry_data_s;

Le membre has_data est vrai si des données ont été trouvées pour une recherche spécifique. Consultez MMDB_get_value() pour plus de détails. Si ce membre est faux, aucune des autres valeurs de la structure n'est significative.

L'union au début de la structure définit les données réelles. Pour déterminer...

MMDB_entry_data_list_s

Cette structure est utilisée pour renvoyer une liste de structures MMDB_entry_data_s. C'est utile lorsque vous récupérez des données qui sont des tableaux ou des maps.

typedef struct MMDB_entry_data_list_s {
    MMDB_entry_data_s entry_data;
    struct MMDB_entry_data_list_s *next;
} MMDB_entry_data_list_s;

Le membre entry_data contient les données pour le nœud actuel de la liste. Le membre next est un pointeur vers le nœud suivant de la liste, ou NULL s'il s'agit du dernier nœud.

MMDB_search_node_s

Cette structure est utilisée par MMDB_read_node() pour renvoyer des informations sur un nœud spécifique dans la base de données MaxMind DB.

typedef struct MMDB_search_node_s {
    uint32_t number;
    uint32_t prefix_length;
    const char *ip_address;
    uint32_t node_offset;
    uint32_t record_offset;
    uint32_t record_in_use;
} MMDB_search_node_s;

Les champs de cette structure représentent les propriétés d'un nœud dans la structure de données MaxMind DB.

Le membre type peut être comparé à l'une des macros MMDB_DATA_TYPE_*.

Entiers 128 bits

La gestion des données uint128 dépend de la manière dont votre plateforme prend en charge les entiers 128 bits, si elle le fait. Avec GCC 4.4 et 4.5, nous pouvons écrire unsigned int __attribute__ ((__mode__ (TI))). Avec les versions plus récentes de GCC (4.6+) et clang (3.2+), nous pouvons simplement écrire "unsigned __int128".

Afin de contourner ces différences, cette bibliothèque définit un type mmdb_uint128_t. Ce type est défini dans l'en-tête maxminddb.h afin que vous puissiez l'utiliser dans votre propre code.

Avec les anciens compilateurs, nous ne pouvons pas utiliser un entier et utilisons à la place un tableau de 16 octets de valeurs uint8_t. Ce sont les données brutes de la base de données.

Cette bibliothèque fournit une macro publique MMDB_UINT128_IS_BYTE_ARRAY. Si cette valeur est vraie (1), alors les valeurs uint128 sont retournées sous forme de tableau d'octets ; si elle est fausse, elles sont retournées sous forme d'entier mmdb_uint128_t.

Macros de types de données

Cette bibliothèque fournit une macro pour chaque type de données défini par la spécification MaxMind DB.

  • MMDB_DATA_TYPE_UTF8_STRING
  • MMDB_DATA_TYPE_DOUBLE
  • MMDB_DATA_TYPE_BYTES
  • MMDB_DATA_TYPE_UINT16
  • MMDB_DATA_TYPE_UINT32
  • MMDB_DATA_TYPE_MAP
  • MMDB_DATA_TYPE_INT32
  • MMDB_DATA_TYPE_UINT64
  • MMDB_DATA_TYPE_UINT128
  • MMDB_DATA_TYPE_ARRAY
  • MMDB_DATA_TYPE_BOOLEAN
  • MMDB_DATA_TYPE_FLOAT

Il existe également quelques types réservés à un usage interne :

  • MMDB_DATA_TYPE_EXTENDED
  • MMDB_DATA_TYPE_POINTER
  • MMDB_DATA_TYPE_CONTAINER
  • MMDB_DATA_TYPE_END_MARKER

Si vous voyez l'un de ces types dans des données retournées, quelque chose s'est très mal passé. La base de données est endommagée ou a été générée incorrectement, ou il y a un bug dans le code de libmaxminddb.

Valeurs pointeurs et MMDB_close()

Les membres utf8_string, bytes et (peut-être) uint128 de cette structure sont tous des pointeurs directs dans la section de données de la base de données. Il peut s'agir d'un bloc de mémoire alloué via calloc ou mmap. Dans les deux cas, ces pointeurs deviendront invalides après l'appel de MMDB_close().

Si vous devez faire référence à ces données après cette période, vous devez copier les données à l'aide d'une fonction appropriée (strdup, memcpy, etc.).

MMDB_entry_data_list_s

Cette structure encapsule une liste chaînée de structures MMDB_entry_data_s.

typedef struct MMDB_entry_data_list_s {
    MMDB_entry_data_s entry_data;
    struct MMDB_entry_data_list_s *next;
} MMDB_entry_data_list_s;

Cette structure vous permet de consulter des données de type map ou array entières en parcourant la liste chaînée.

MMDB_search_node_s

Cette structure encapsule les deux enregistrements d'un nœud de recherche. Ceci est vraiment utile uniquement si vous souhaitez écrire du code qui parcourt l'arbre de recherche complet au lieu de rechercher une adresse IP spécifique.

typedef struct MMDB_search_node_s {
    uint64_t left_record;
    uint64_t right_record;
    uint8_t left_record_type;
    uint8_t right_record_type;
    MMDB_entry_s left_record_entry;
    MMDB_entry_s right_record_entry;
} MMDB_search_node_s;

Les deux types d'enregistrements peuvent prendre l'une des valeurs suivantes :

  • MMDB_RECORD_TYPE_SEARCH_NODE - L'enregistrement pointe vers le nœud de recherche suivant.
  • MMDB_RECORD_TYPE_EMPTY - L'enregistrement est un espace réservé indiquant qu'il n'y a pas de données pour l'adresse IP. La recherche doit se terminer ici.
  • MMDB_RECORD_TYPE_DATA - L'enregistrement contient des données dans la section de données de la base de données. Utilisez l'entrée pour l'enregistrement lors de la recherche des données.
  • MMDB_RECORD_TYPE_INVALID - L'enregistrement est invalide. Soit un nœud invalide a été recherché, soit la base de données est corrompue.

L'MMDB_entry_s de l'enregistrement n'est valide que si le type est MMDB_RECORD_TYPE_DATA. Toute tentative d'utilisation d'une entrée pour d'autres types d'enregistrement entraînera une erreur ou des données invalides.

CODES DE STATUT

Cette bibliothèque retourne (ou peuple) des codes de statut pour de nombreuses fonctions. Ces codes de statut sont :

  • MMDB_SUCCESS - tout a fonctionné
  • MMDB_FILE_OPEN_ERROR - une erreur s'est produite lors de la tentative d'ouverture du fichier MaxMind DB.
  • MMDB_IO_ERROR - une opération d'E/S a échoué. Vérifiez errno pour plus de détails.
  • MMDB_CORRUPT_SEARCH_TREE_ERROR - la recherche d'une adresse IP dans l'arbre de recherche a donné un résultat impossible. La base de données est endommagée ou a été générée incorrectement, ou il y a un bug dans le code libmaxminddb.
  • MMDB_INVALID_METADATA_ERROR - quelque chose dans la base de données est incorrect. Cela inclut les clés de métadonnées manquantes ainsi que les valeurs impossibles (comme une ip_version de 7).
  • MMDB_UNKNOWN_DATABASE_FORMAT_ERROR - Les métadonnées de la base de données indiquent que sa version majeure n'est pas 2. Cette bibliothèque ne peut gérer que la version majeure 2.
  • MMDB_OUT_OF_MEMORY_ERROR - un appel d'allocation mémoire (malloc, etc.) a échoué.
  • MMDB_INVALID_DATA_ERROR - une entrée dans la section de données contient des données invalides. Par exemple, un champ uint16 prétend avoir plus de 2 octets de long. La base de données est probablement endommagée ou a été générée incorrectement.
  • MMDB_INVALID_LOOKUP_PATH_ERROR - Le chemin de recherche passé à MMDB_get_value, MMDB_vget_value ou MMDB_aget_value contient un décalage de tableau supérieur à LONGMAX ou inférieur à LONGMIN.
  • MMDB_LOOKUP_PATH_DOES_NOT_MATCH_DATA_ERROR - Le chemin de recherche passé à MMDB_get_value,MMDB_vget_value, ou MMDB_aget_value ne correspond pas à la structure de données de l'entrée. Il existe un certain nombre de raisons pour lesquelles cela peut se produire. Le chemin de recherche peut inclure une clé qui n'est pas dans une map. Le chemin de recherche peut inclure un index de tableau supérieur à un tableau ou inférieur au décalage minimum par rapport à la fin d'un tableau. Cela peut également se produire lorsque le chemin s'attend à trouver une map ou un tableau là où il n'y en a pas.

Tous les codes de statut doivent être traités comme des valeurs int.

MMDB_strerror()

const char *MMDB_strerror(int error_code)

Cette fonction prend un code de statut et retourne une chaîne en anglais expliquant le statut.

FONCTIONS

Cette bibliothèque fournit les fonctions exportées suivantes :

MMDB_open()

int MMDB_open(
    const char *const filename,
    uint32_t flags,
    MMDB_s *const mmdb);

Cette fonction ouvre un descripteur vers un fichier MaxMind DB. Sa valeur de retour est un code de statut tel que défini ci-dessus. Vérifiez toujours la valeur de retour de cet appel.

MMDB_s mmdb;
int status =
    MMDB_open("/path/to/file.mmdb", MMDB_MODE_MMAP, &mmdb);
if (MMDB_SUCCESS != status) { ... }
...
MMDB_close(&mmdb);

filename doit être encodé en UTF-8 sous Windows.

La structure MMDB_s que vous passez peut être sur la pile ou allouée depuis le tas. Cependant, si l'ouverture réussit, elle contiendra des données allouées sur le tas, vous devrez donc la fermer avec MMDB_close(). Si le statut retourné n'est pas MMDB_SUCCESS, cette bibliothèque s'assure que toute la mémoire allouée est libérée avant de retourner.

Les indicateurs actuellement fournis sont :

•
MMDB_MODE_MMAP - ouvre la base de données avec mmap().

Passer d'autres valeurs pour flags peut donner des résultats imprévisibles. À l'avenir, nous pourrons ajouter des indicateurs supplémentaires que vous pourrez combiner avec le mode par un OU logique bit à bit, ainsi que des modes supplémentaires.

Vous pouvez également passer 0 comme valeur de flags, auquel cas la base de données sera ouverte avec les indicateurs par défaut. Cependant, ces valeurs par défaut peuvent changer dans les futures versions. La valeur par défaut actuelle est MMDB_MODE_MMAP.

MMDB_close()

void MMDB_close(MMDB_s *const mmdb);

Ceci libère toute mémoire allouée ou mappée qui est détenue par la structure MMDB_s. *Il ne libère pas

la mémoire allouée pour la structure elle-même ! Si vous avez alloué la structure à partir du tas, vous êtes responsable de sa libération.

MMDB_lookup_string()

MMDB_lookup_result_s MMDB_lookup_string(
    MMDB_s *const mmdb,
    const char *const ipstr,
    int *const gai_error,
    int *const mmdb_error);

Cette fonction recherche une adresse IP passée sous forme de chaîne de caractères terminée par un caractère nul. En interne, elle appelle getaddrinfo() pour résoudre l'adresse en une forme binaire. Elle appelle ensuite MMDB_lookup_sockaddr() pour rechercher l'adresse dans la base de données. Si vous avez déjà résolu une adresse, vous pouvez appeler MMDB_lookup_sockaddr() directement, plutôt que de résoudre l'adresse deux fois.

int gai_error, mmdb_error;
MMDB_lookup_result_s result =
    MMDB_lookup_string(&mmdb, "1.2.3.4", &gai_error, &mmdb_error);
if (0 != gai_error) { ... }
if (MMDB_SUCCESS != mmdb_error) { ... }
if (result.found_entry) { ... }

Cette fonction renvoie toujours une structure MMDB_lookup_result_s, mais vous devez également vérifier les paramètres gai_error et mmdb_error. Si l'un d'eux indique une erreur, la structure renvoyée n'est pas significative.

Si aucune erreur ne s'est produite, vous devez toujours vous assurer que le membre found_entry dans le résultat renvoyé est vrai. S'il est faux, cela signifie que l'adresse IP n'a pas d'entrée dans la base de données.

Cette fonction fonctionnera avec les adresses IPv4 même lorsque la base de données contient des données pour les adresses IPv4 et IPv6. L'adresse IPv4 sera recherchée sous la forme '::xxx.xxx.xxx.xxx' plutôt que d'être remappée dans le bloc ::ffff:xxx.xxx.xxx.xxx alloué aux adresses IPv6 mappées IPv4.

Si vous passez une adresse IPv6 à une base de données ne contenant que des données IPv4, le membre found_entry sera faux, mais le statut mmdb_error sera toujours MMDB_SUCCESS.

MMDB_lookup_sockaddr()

MMDB_lookup_result_s MMDB_lookup_sockaddr(
    MMDB_s *const mmdb,
    const struct sockaddr *const sockaddr,
    int *const mmdb_error);

Cette fonction recherche une adresse IP qui a déjà été résolue par getaddrinfo().

En plus de ne pas appeler elle-même getaddrinfo(), cette fonction est identique à la fonction MMDB_lookup_string().

int mmdb_error;
MMDB_lookup_result_s result =
    MMDB_lookup_sockaddr(&mmdb, address->ai_addr, &mmdb_error);
if (MMDB_SUCCESS != mmdb_error) { ... }
if (result.found_entry) { ... }

Fonctions de recherche de données

Il existe trois fonctions pour rechercher des données associées à une adresse IP.

int MMDB_get_value(
    MMDB_entry_s *const start,
    MMDB_entry_data_s *const entry_data,
    ...);
int MMDB_vget_value(
    MMDB_entry_s *const start,
    MMDB_entry_data_s *const entry_data,
    va_list va_path);
int MMDB_aget_value(
    MMDB_entry_s *const start,
    MMDB_entry_data_s *const entry_data,
    const char *const *const path);

Les trois fonctions permettent trois styles d'appel légèrement différents, mais elles font toutes la même chose.

Le premier paramètre est une valeur MMDB_entry_s. Dans la plupart des cas, elle proviendra de la valeur MMDB_lookup_result_s renvoyée par MMDB_lookup_string() ou MMDB_lookup_sockaddr().

Le deuxième paramètre est une référence à une structure MMDB_entry_data_s. Elle sera remplie avec les données recherchées, si des données sont trouvées. Si rien n'est trouvé, le membre has_data de cette structure sera faux. Si has_data est vrai, vous pouvez examiner le membre data_type.

Le dernier paramètre est un chemin de recherche. Le chemin est constitué d'un ensemble de chaînes représentant soit des clés de mappe (par exemple, "city"), soit des indices de tableau (par exemple, "0", "1", "-1") à utiliser dans la recherche.

Les indices de tableau négatifs seront traités comme un décalage à partir de la fin du tableau. Par exemple, "-1" fait référence au dernier élément du tableau.

Le chemin de recherche vous permet de naviguer dans une structure de données complexe. Par exemple, étant donné ces données :

{
    "names": {
        "en": "Germany",
        "de": "Deutschland"
    },
    "cities": [ "Berlin", "Frankfurt" ]
}

Nous pourrions rechercher le nom anglais avec ce code :

MMDB_lookup_result_s result =
    MMDB_lookup_sockaddr(&mmdb, address->ai_addr, &mmdb_error);
MMDB_entry_data_s entry_data;
int status =
    MMDB_get_value(&result.entry, &entry_data,
                   "names", "en", NULL);
if (MMDB_SUCCESS != status) { ... }
if (entry_data.has_data) { ... }

Si nous voulions trouver la première ville, le chemin de recherche serait "cities", "0". Si vous ne fournissez pas de chemin de recherche du tout, vous obtiendrez l'entrée qui correspond à la carte de niveau supérieur. Le chemin de recherche doit toujours se terminer par NULL, quelle que soit la fonction que vous appelez.

La fonction MMDB_get_value prend un nombre variable d'arguments. Tous les arguments après le pointeur de structure MMDB_entry_data_s * constituent le chemin de recherche. Le dernier argument doit être NULL.

La fonction MMDB_vget_value accepte une va_list comme chemin de recherche. Le dernier élément récupéré par va_arg() doit être NULL.

Enfin, la fonction MMDB_aget_value accepte un tableau de chaînes comme chemin de recherche. Le dernier membre de ce tableau doit être NULL.

Si vous souhaitez obtenir toutes les données d'entrée en une seule fois, vous pouvez appeler MMDB_get_entry_data_list() à la place.

Pour chacune des trois fonctions, la valeur de retour est un code d'état tel que défini ci-dessus.

MMDB_get_entry_data_list()

int MMDB_get_entry_data_list(
    MMDB_entry_s *start,
    MMDB_entry_data_list_s **const entry_data_list);

Cette fonction vous permet d'obtenir toutes les données d'une structure de données complexe en une seule fois, au lieu de rechercher chaque élément en appelant répétitivement MMDB_get_value().

MMDB_lookup_result_s result =
    MMDB_lookup_sockaddr(&mmdb, address->ai_addr, &mmdb_error);
MMDB_entry_data_list_s *entry_data_list, *first;
int status =
    MMDB_get_entry_data_list(&result.entry, &entry_data_list);
if (MMDB_SUCCESS != status) { ... }
// sauvegarder ceci pour pouvoir libérer ces données plus tard
first = entry_data_list;
while (1) {
    MMDB_entry_data_list_s *next = entry_data_list = entry_data_list->next;
    if (NULL == next) {
        break;
    }
    switch (next->entry_data.type) {
        case MMDB_DATA_TYPE_MAP: { ... }
        case MMDB_DATA_TYPE_UTF8_STRING: { ... }
        ...
    }
}
MMDB_free_entry_data_list(first);

Il vous appartient d'interpréter la structure de données entry_data_list. La liste est liée dans un parcours en profondeur. Utilisons cette structure comme exemple :

{
    "names": {
        "en": "Germany",
        "de": "Deutschland"
    },
    "cities": [ "Berlin", "Frankfurt" ]
}

La liste sera composée des éléments suivants :

1.
MAP - carte de niveau supérieur
2.
UTF8_STRING - clé "names"
3.
MAP - carte pour la clé "names"
4.
UTF8_STRING - clé "en"
5.
UTF8_STRING - valeur pour la clé "en"
6.
UTF8_STRING - clé "de"
7.
UTF8_STRING - valeur pour la clé "de"
8.
UTF8_STRING - clé "cities"
9.
ARRAY - valeur pour la clé "cities"
10.
UTF8_STRING - tableau[0]
11.
UTF8_STRING - tableau[1]

La valeur de retour de la fonction est un code d'état tel que défini ci-dessus.

MMDB_free_entry_data_list()

void MMDB_free_entry_data_list(
    MMDB_entry_data_list_s *const entry_data_list);

Les fonctions MMDB_get_entry_data_list() et MMDB_get_metadata_as_entry_data_list() alloueront la structure de liste chaînée à partir du tas. Appelez cette fonction pour libérer la structure MMDB_entry_data_list_s.

MMDB_get_metadata_as_entry_data_list()

int MMDB_get_metadata_as_entry_data_list(
    MMDB_s *const mmdb,
    MMDB_entry_data_list_s **const entry_data_list);

Cette fonction vous permet de récupérer les métadonnées de la base de données sous forme de liste chaînée de structures MMDB_entry_data_list_s. Cela peut être une manière plus pratique de traiter les métadonnées que d'utiliser directement la structure des métadonnées.

    MMDB_entry_data_list_s *entry_data_list, *first;
    int status =
        MMDB_get_metadata_as_entry_data_list(&mmdb, &entry_data_list);
    if (MMDB_SUCCESS != status) { ... }
    first = entry_data_list;
    ... // faire quelque chose avec les données
    MMDB_free_entry_data_list(first);

La valeur de retour de la fonction est un code d'état tel que défini ci-dessus.

MMDB_dump_entry_data_list()

int MMDB_dump_entry_data_list(
    FILE *const stream,
    MMDB_entry_data_list_s *const entry_data_list,
    int indent);

Cette fonction prend une liste chaînée de structures MMDB_entry_data_list_s et la convertit en chaîne de caractères sur le flux donné. Le paramètre indent est le niveau d'indentation de départ pour la sortie générée. Il est incrémenté pour les structures de données imbriquées (mappes, tableaux, etc.).

Le flux doit être un descripteur de fichier (stdout, etc.). Si votre plate-forme fournit quelque chose comme open_memstream() de GNU, vous pouvez l'utiliser pour capturer la sortie sous forme de chaîne.

La sortie est formatée d'une manière similaire à JSON, mais les valeurs sont marquées avec leur type de données (sauf pour les cartes et les tableaux qui sont affichés avec "{}" et "[]" respectivement).

libmaxminddb(3) — Arch Linux

NAME

libmaxminddb - C library for reading MaxMind DB files

SYNOPSIS

#include <maxminddb.h>

MMDB_s *mmdb_handle;

MMDB_lookup_result_s result;

int status;

DESCRIPTION

The MaxMind DB file format is a binary format that allows efficient lookups of geographical location data by IP address. The libmaxminddb library is a C library for reading these files.

It provides functions to open and close MaxMind DB files, perform lookups by IP address, and retrieve the data associated with an IP address.

DATA STRUCTURES

MMDB_s
The main structure representing an open MaxMind DB file. It holds information about the file, including metadata, data structures, and search tree pointers.
MMDB_lookup_result_s
Represents the result of an IP address lookup. It contains a flag indicating if an entry was found and an MMDB_entry_s structure if an entry was found.
MMDB_entry_s
Represents a single entry (record) within the MaxMind DB file. It contains information about the data type and value of the entry.
MMDB_entry_data_s
Represents the data associated with a specific field within an entry. It includes the data type, pointer to the data, and size.
MMDB_entry_data_list_s
A linked list of MMDB_entry_data_s structures, used to represent the full data of an entry, including nested structures.
MMDB_search_node_s
Represents a node in the search tree used for IP address lookups. It contains information about the node's children and the data it points to.

STATUS CODES

The library functions return an integer status code. Possible values are:

MMDB_SUCCESS
Operation completed successfully.
MMDB_SUCCESS_PARTIAL_READ
A partial read occurred, but the data is still usable.
MMDB_FILE_NOT_FOUND_ERROR
The specified database file could not be found.
MMDB_INVALID_INTERFACE_ERROR
An invalid argument was passed to a function.
MMDB_INVALID_METADATA_ERROR
The database metadata is invalid or corrupt.
MMDB_INVALID_DATA_ERROR
The database data is invalid or corrupt.
MMDB_OUT_OF_MEMORY_ERROR
Memory allocation failed.
MMDB_IO_ERROR
An input/output error occurred while accessing the database file.
MMDB_NULL_POINTER_ERROR
A NULL pointer was passed to a function where it is not allowed.
MMDB_UNKNOWN_METADATA_FIELD_ERROR
An unknown field was encountered in the metadata.
MMDB_CORRUPTED_DATABASE_ERROR
The database file is corrupted.
MMDB_INVALID_NODE_NUMBER_ERROR
The provided node number is out of bounds.
MMDB_INVALID_LOOKUP_PATH_ERROR
The lookup path is invalid.
MMDB_LOOKUP_PATH_DOES_NOT_CONTAIN_A_KEY_IN_THE_DATABASE_ERROR
The lookup path does not contain a key present in the database.

FUNCTIONS

MMDB_open()
int MMDB_open(const char *filename, int flags, MMDB_s *const mmdb);

Opens a MaxMind DB file specified by filename. The flags argument controls how the file is opened. Common flags include MMDB_MODE_MMAP (memory-map the file) and MMDB_MODE_FILE (read the file directly). The opened database handle is stored in the mmdb structure. Returns MMDB_SUCCESS on success, or an error code on failure.

MMDB_close()
void MMDB_close(MMDB_s *mmdb);

Closes an opened MaxMind DB file handle and frees any associated resources.

MMDB_lookup_string()
MMDB_lookup_result_s MMDB_lookup_string(MMDB_s *const mmdb, const char *ip_address, int *gai_error, int *mmdb_error);

Performs a lookup for the given IP address string (ip_address) in the database represented by mmdb. It also takes pointers to integer variables (gai_error and mmdb_error) that will be populated with error codes from getaddrinfo and libmaxminddb respectively. Returns an MMDB_lookup_result_s structure containing the lookup result.

MMDB_lookup_sock()
MMDB_lookup_result_s MMDB_lookup_sock(MMDB_s *const mmdb, const struct sockaddr *sa, int *mmdb_error);

Similar to MMDB_lookup_string, but performs the lookup using a network address structure (struct sockaddr) instead of an IP address string.

MMDB_get_entry_data_list()
int MMDB_get_entry_data_list(const MMDB_entry_s *const entry, MMDB_entry_data_list_s **entry_data_list);

Retrieves the data for a given entry as a linked list of MMDB_entry_data_s structures. This allows you to traverse the nested structure of the data. The list is allocated and must be freed using MMDB_free_entry_data_list.

MMDB_free_entry_data_list()
void MMDB_free_entry_data_list(MMDB_entry_data_list_s *entry_data_list);

Frees the memory allocated for an entry data list created by MMDB_get_entry_data_list.

MMDB_get_metadata()
MMDB_metadata_s MMDB_get_metadata(MMDB_s *const mmdb);

Retrieves the metadata associated with the MaxMind DB file. The metadata contains information about the database format version, build time, and database type.

MMDB_strerror()
const char *MMDB_strerror(int status);

Returns a human-readable string representation of the given status code.

MMDB_dump_entry_data_list()
void MMDB_dump_entry_data_list(FILE *file, MMDB_entry_data_list_s *entry_data_list, int indent);

Dumps the contents of an entry data list to the specified file stream (file). The indent parameter controls the indentation level for pretty-printing.

The specific formatting produced by this function may change in future releases, so you should not rely on it. It is intended for showing data to users in a readable way and for debugging purposes.

The return value of the function is a status code as defined above.

MMDB_read_node()
int MMDB_read_node(
    MMDB_s *const mmdb,
    uint32_t node_number,
    MMDB_search_node_s *const node);

This reads a specific node in the search tree. The third argument is a reference to an MMDB_search_node_s structure that will be populated by this function.

The return value is a status code. If you pass a node_number that is greater than the number of nodes in the database, this function will return MMDB_INVALID_NODE_NUMBER_ERROR, otherwise it will return MMDB_SUCCESS.

The first node in the search tree is always node 0. If you wanted to iterate over the whole search tree, you would start by reading node 0 and then following the the records that make up this node, based on the type of each record. If the type is MMDB_RECORD_TYPE_SEARCH_NODE then the record contains an integer for the next node to look up.

MMDB_lib_version()
const char *MMDB_lib_version(void)

This function returns the library version as a string, something like "2.0.0".

EXAMPLE

#include <errno.h>
#include <maxminddb.h>
#include <stdlib.h>
#include <string.h>
int main(int argc, char **argv)
{
    char *filename = argv[1];
    char *ip_address = argv[2];
    MMDB_s mmdb;
    int status = MMDB_open(filename, MMDB_MODE_MMAP, &mmdb);
    if (MMDB_SUCCESS != status) {
        fprintf(stderr, "\n  Can't open %s - %s\n",
                filename, MMDB_strerror(status));
        if (MMDB_IO_ERROR == status) {
            fprintf(stderr, "    IO error: %s\n", strerror(errno));
        }
        exit(1);
    }
    int gai_error, mmdb_error;
    MMDB_lookup_result_s result =
        MMDB_lookup_string(&mmdb, ip_address, &gai_error, &mmdb_error);
    if (0 != gai_error) {
        fprintf(stderr,
                "\n  Error from getaddrinfo for %s - %s\n\n",
                ip_address, gai_strerror(gai_error));
        exit(2);
    }
    if (MMDB_SUCCESS != mmdb_error) {
        fprintf(stderr,
                "\n  Got an error from libmaxminddb: %s\n\n",
                MMDB_strerror(mmdb_error));
        exit(3);
    }
    MMDB_entry_data_list_s *entry_data_list = NULL;
    int exit_code = 0;
    if (result.found_entry) {
        int status = MMDB_get_entry_data_list(&result.entry,
                                              &entry_data_list);
        if (MMDB_SUCCESS != status) {
            fprintf(
                stderr,
                "Got an error looking up the entry data - %s\n",
                MMDB_strerror(status));
            exit_code = 4;
            goto end;
        }
        if (NULL != entry_data_list) {
            MMDB_dump_entry_data_list(stdout, entry_data_list, 2);
        }
    } else {
        fprintf(
            stderr,
            "\n  No entry for this IP address (%s) was found\n\n",
            ip_address);
        exit_code = 5;
    }
    end:
        MMDB_free_entry_data_list(entry_data_list);
        MMDB_close(&mmdb);
        exit(exit_code);
}

THREAD SAFETY

This library is thread safe when compiled and linked with a thread-safe malloc and free implementation.
