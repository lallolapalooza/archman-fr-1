DESCRIPTION

La bibliothèque libmaxminddb fournit des fonctions pour travailler avec les fichiers MaxMind DB. Voir https://maxmind.github.io/MaxMind-DB/ pour la spécification du format MaxMind DB. La base de données et les résultats sont représentés par différentes structures de données. Les bases de données sont ouvertes en appelant MMDB_open(). Vous pouvez rechercher des adresses IP sous forme de chaîne de caractères avec MMDB_lookup_string() ou sous forme de pointeur vers une structure sockaddr avec MMDB_lookup_sockaddr().

Si la recherche trouve l'adresse IP dans la base de données, elle renvoie une structure MMDB_lookup_result_s. Si cette structure indique que la base de données contient des données pour l'IP, il existe un certain nombre de fonctions qui peuvent être utilisées pour récupérer ces données. Celles-ci incluent MMDB_get_value() et MMDB_get_entry_data_list(). Voir la documentation des fonctions ci-dessous pour plus de détails.

Lorsque vous avez terminé avec le handle de la base de données, vous devez appeler MMDB_close().

Toutes les fonctions, structures et macros publiquement visibles commencent par "MMDB_".

STRUCTURES DE DONNÉES

Toutes les structures de données exportées par l'en-tête maxminddb.h de cette bibliothèque sont typées sous la forme typedef struct foo_s { ... } foo_s afin que vous puissiez vous y référer sans le préfixe struct.

Cette bibliothèque fournit les structures de données suivantes :

MMDB_s

C'est le handle pour un fichier MaxMind DB. Nous documentons seulement quelques champs de cette structure destinés à un usage public. Tous les autres champs sont sujets à modification et sont destinés à un usage interne uniquement.

typedef struct MMDB_s {
    uint32_t flags;
    const char *filename;
    ...
    MMDB_metadata_s metadata;
} MMDB_s;
  • uint32_t flags - les drapeaux avec lesquels cette base de données a été ouverte. Voir la documentation de MMDB_open() pour plus de détails.
  • const char *filename - le nom du fichier qui a été ouvert, tel que passé à MMDB_open().
  • MMDB_metadata_s metadata - les métadonnées de la base de données.

MMDB_metadata_s et MMDB_description_s

Cette structure peut être récupérée de la structure MMDB_s. Elle contient les métadonnées lues à partir du fichier de la base de données. Notez qu'il peut être plus pratique d'accéder à ces métadonnées en appelant MMDB_get_metadata_as_entry_data_list() à la place.

typedef struct MMDB_metadata_s {
    uint32_t node_count;
    uint16_t record_size;
    uint16_t ip_version;
    const char *database_type;
    struct {
        size_t count;
        const char **names;
    } languages;
    uint16_t binary_format_major_version;
    uint16_t binary_format_minor_version;
    uint64_t build_epoch;
    struct {
        size_t count;
        MMDB_description_s **descriptions;
    } description;
} MMDB_metadata_s;
typedef struct MMDB_description_s {
    const char *language;
    const char *description;
} MMDB_description_s;

Ces structures devraient être en grande partie auto-explicatives.

Le membre ip_version doit toujours être 4 ou 6. Le membre binary_format_major_version doit toujours être 2.

Il n'est pas requis que les métadonnées de la base de données incluent des langues ou des descriptions, donc le count pour ces parties des métadonnées peut être zéro. Tous les autres champs de MMDB_metadata_s devraient être renseignés.

MMDB_lookup_result_s

Cette structure est renvoyée comme résultat de la recherche d'une adresse IP.

typedef struct MMDB_lookup_result_s {
    bool found_entry;
    MMDB_entry_s entry;
    uint16_t netmask;
} MMDB_lookup_result_s;

Si le membre found_entry est faux, alors les autres membres de cette structure ne contiennent pas de valeurs significatives. Vérifiez toujours que found_entry est vrai en premier.

Le membre entry est utilisé pour rechercher les données associées à l'adresse IP.

Le membre netmask vous indique à quel sous-réseau l'adresse IP appartient dans cette base de données. Par exemple, si vous recherchez l'adresse 1.1.1.1 dans une base de données IPv4 et que le netmask renvoyé est 16, alors l'adresse fait partie du sous-réseau 1.1.0.0/16.

Si la base de données est une base de données IPv6, le masque de réseau renvoyé est toujours une longueur de préfixe IPv6 (de 0 à 128), même si cette base de données contient également des réseaux IPv4. Si vous recherchez une adresse IPv4 et souhaitez convertir le masque de réseau en une valeur de masque de réseau IPv4, vous pouvez simplement soustraire 96 de la valeur.

MMDB_result_s

Vous n'avez pas vraiment besoin de fouiller dans cette structure. Vous l'obtiendrez d'une structure MMDB_lookup_result_s et la passerez à diverses fonctions.

MMDB_entry_data_s

Cette structure est utilisée pour renvoyer une seule entrée de section de données pour une IP. Ces entrées peuvent à leur tour pointer vers d'autres entrées, comme c'est le cas pour des éléments tels que les cartes et les tableaux. Certains membres de cette structure ne sont pas documentés car ils sont réservés à un usage interne.

typedef struct MMDB_entry_data_s {
    bool has_data;
    union {
        uint32_t pointer;
        const char *utf8_string;
        double double_value;
        const uint8_t *bytes;
        uint16_t uint16;
        uint32_t uint32;
        int32_t int32;
        uint64_t uint64;
        {mmdb_uint128_t or uint8_t[16]} uint128;
        bool boolean;
        float float_value;
    };
    ...
    uint32_t data_size;
    uint32_t type;
} MMDB_entry_data_s;

Le membre has_data est vrai si des données ont été trouvées pour une recherche donnée. Voir MMDB_get_value() pour plus de détails. Si ce membre est faux, alors aucune des autres valeurs de la structure n'est significative.

L'union au début de la structure définit les données réelles. Pour déterminer quel membre de l'union

Le membre type peut être comparé à l'une des macros MMDB_DATA_TYPE_*.

Entiers 128 bits

La gestion des données de type uint128 dépend de la manière dont votre plateforme supporte les entiers 128 bits, si elle le fait. Avec GCC 4.4 et 4.5, nous pouvons écrire unsigned int __attribute__ ((__mode__ (TI))). Avec les versions plus récentes de GCC (4.6+) et clang (3.2+), nous pouvons simplement écrire « unsigned __int128 ».

Afin de contourner ces différences, cette bibliothèque définit un type mmdb_uint128_t. Ce type est défini dans l'en-tête maxminddb.h afin que vous puissiez l'utiliser dans votre propre code.

Avec les anciens compilateurs, nous ne pouvons pas utiliser un entier et utilisons à la place un tableau de 16 octets de valeurs uint8_t. Ce sont les données brutes de la base de données.

Cette bibliothèque fournit une macro publique MMDB_UINT128_IS_BYTE_ARRAY. Si celle-ci est vraie (1), les valeurs uint128 sont retournées sous forme de tableau d'octets ; si elle est fausse, elles sont retournées sous forme d'un entier mmdb_uint128_t.

Macros Types de Données

Cette bibliothèque fournit une macro pour chaque type de données défini par la spécification MaxMind DB.

  • MMDB_DATA_TYPE_UTF8_STRING
  • MMDB_DATA_TYPE_DOUBLE
  • MMDB_DATA_TYPE_BYTES
  • MMDB_DATA_TYPE_UINT16
  • MMDB_DATA_TYPE_UINT32
  • MMDB_DATA_TYPE_MAP
  • MMDB_DATA_TYPE_INT32
  • MMDB_DATA_TYPE_UINT64
  • MMDB_DATA_TYPE_UINT128
  • MMDB_DATA_TYPE_ARRAY
  • MMDB_DATA_TYPE_BOOLEAN
  • MMDB_DATA_TYPE_FLOAT

Il existe également quelques types réservés à un usage interne :

  • MMDB_DATA_TYPE_EXTENDED
  • MMDB_DATA_TYPE_POINTER
  • MMDB_DATA_TYPE_CONTAINER
  • MMDB_DATA_TYPE_END_MARKER

Si vous rencontrez l'une de ces valeurs dans les données retournées, quelque chose s'est très mal passé. La base de données est endommagée ou a été générée incorrectement, ou il y a un bug dans le code de libmaxminddb.

Valeurs de Pointeur et MMDB_close()

Les membres utf8_string, bytes et (potentiellement) uint128 de cette structure sont tous des pointeurs directement dans la section de données de la base de données. Cela peut être un bloc de mémoire alloué par calloc ou par mmap. Dans les deux cas, ces pointeurs deviendront invalides après l'appel à MMDB_close().

Si vous avez besoin de faire référence à ces données après ce moment, vous devriez copier les données avec une fonction appropriée ( strdup, memcpy, etc.).

MMDB_entry_data_list_s

Cette structure encapsule une liste chaînée de structures MMDB_entry_data_s.

typedef struct MMDB_entry_data_list_s {
    MMDB_entry_data_s entry_data;
    struct MMDB_entry_data_list_s *next;
} MMDB_entry_data_list_s;

Cette structure vous permet de consulter l'intégralité des données d'une mappe ou d'un tableau en parcourant la liste chaînée.

MMDB_search_node_s

Cette structure encapsule les deux enregistrements d'un nœud de recherche. Ceci est vraiment utile uniquement si vous souhaitez écrire du code qui itère sur l'arbre de recherche complet au lieu de rechercher une adresse IP spécifique.

typedef struct MMDB_search_node_s {
    uint64_t left_record;
    uint64_t right_record;
    uint8_t left_record_type;
    uint8_t right_record_type;
    MMDB_entry_s left_record_entry;
    MMDB_entry_s right_record_entry;
} MMDB_search_node_s;

Les deux types d'enregistrement prendront l'une des valeurs suivantes :

  • MMDB_RECORD_TYPE_SEARCH_NODE - L'enregistrement pointe vers le nœud de recherche suivant.
  • MMDB_RECORD_TYPE_EMPTY - L'enregistrement est un espace réservé indiquant qu'il n'y a pas de données pour l'adresse IP. La recherche doit se terminer ici.
  • MMDB_RECORD_TYPE_DATA - L'enregistrement concerne les données dans la section de données de la base de données. Utilisez l'entrée de l'enregistrement lors de la recherche des données pour cet enregistrement.
  • MMDB_RECORD_TYPE_INVALID - L'enregistrement est invalide. Soit un nœud invalide a été recherché, soit la base de données est corrompue.

Le MMDB_entry_s pour l'enregistrement n'est valide que si le type est MMDB_RECORD_TYPE_DATA. Les tentatives d'utilisation d'une entrée pour d'autres types d'enregistrement entraîneront une erreur ou des données invalides.

CODES STATUT

Cette bibliothèque renvoie (ou renseigne) des codes statut pour de nombreuses fonctions. Ces codes statut sont :

  • MMDB_SUCCESS - tout a fonctionné
  • MMDB_FILE_OPEN_ERROR - une erreur s'est produite lors de la tentative d'ouverture du fichier MaxMind DB.
  • MMDB_IO_ERROR - une opération d'E/S a échoué. Vérifiez errno pour plus de détails.
  • MMDB_CORRUPT_SEARCH_TREE_ERROR - la recherche d'une adresse IP dans l'arbre de recherche nous a donné un résultat impossible. La base de données est endommagée ou a été générée incorrectement, ou il y a un bug dans le code de libmaxminddb.
  • MMDB_INVALID_METADATA_ERROR - quelque chose dans la base de données est incorrect. Cela inclut des clés de métadonnées manquantes ainsi que des valeurs impossibles (comme une ip_version de 7).
  • MMDB_UNKNOWN_DATABASE_FORMAT_ERROR - Les métadonnées de la base de données indiquent que sa version majeure n'est pas 2. Cette bibliothèque ne peut gérer que la version majeure 2.
  • MMDB_OUT_OF_MEMORY_ERROR - un appel d'allocation de mémoire (malloc, etc.) a échoué.
  • MMDB_INVALID_DATA_ERROR - une entrée dans la section de données contient des données invalides. Par exemple, un champ uint16 prétend avoir plus de 2 octets de long. La base de données est probablement endommagée ou a été générée incorrectement.
  • MMDB_INVALID_LOOKUP_PATH_ERROR - Le chemin de recherche transmis à MMDB_get_value, MMDB_vget_value ou MMDB_aget_value contient un index de tableau supérieur à LONGMAX ou inférieur à LONGMIN.
  • MMDB_LOOKUP_PATH_DOES_NOT_MATCH_DATA_ERROR - Le chemin de recherche transmis à MMDB_get_value,MMDB_vget_value ou MMDB_aget_value ne correspond pas à la structure de données de l'entrée. Il existe plusieurs raisons pour lesquelles cela peut se produire. Le chemin de recherche peut inclure une clé qui n'est pas dans une mappe. Le chemin de recherche peut inclure un index de tableau supérieur à la taille du tableau ou inférieur à l'offset minimum depuis la fin d'un tableau. Cela peut également se produire lorsque le chemin s'attend à trouver une mappe ou un tableau là où il n'en existe aucun.

Tous les codes statut doivent être traités comme des valeurs int.

MMDB_strerror()

const char *MMDB_strerror(int error_code)

Cette fonction prend un code statut et renvoie une chaîne en anglais expliquant le statut.

FONCTIONS

Cette bibliothèque fournit les fonctions exportées suivantes :

MMDB_open()

int MMDB_open(
    const char *const filename,
    uint32_t flags,
    MMDB_s *const mmdb);

Cette fonction ouvre un descripteur pour un fichier MaxMind DB. Sa valeur de retour est un code statut tel que défini ci-dessus. Vérifiez toujours la valeur de retour de cet appel.

MMDB_s mmdb;
int status =
    MMDB_open("/path/to/file.mmdb", MMDB_MODE_MMAP, &mmdb);
if (MMDB_SUCCESS != status) { ... }
...
MMDB_close(&mmdb);

filename doit être encodé en UTF-8 sous Windows.

La structure MMDB_s que vous passez peut être sur la pile ou allouée à partir du tas. Cependant, si l'ouverture réussit, elle contiendra des données allouées par le tas, vous devrez donc la fermer avec MMDB_close(). Si le statut retourné n'est pas MMDB_SUCCESS, cette bibliothèque s'assure que toute la mémoire allouée est libérée avant de retourner.

Les drapeaux actuellement fournis sont :

•
MMDB_MODE_MMAP - ouvre la base de données avec mmap().

Passer d'autres valeurs pour flags peut entraîner des résultats imprévisibles. À l'avenir, nous pourrions ajouter des indicateurs supplémentaires que vous pourrez combiner par un OU bit à bit avec le mode, ainsi que des modes supplémentaires.

Vous pouvez également passer 0 comme valeur pour flags, auquel cas la base de données sera ouverte avec les indicateurs par défaut. Cependant, ces défauts peuvent changer dans les futures versions. Le défaut actuel est MMDB_MODE_MMAP.

MMDB_close()

void MMDB_close(MMDB_s *const mmdb);

Ceci libère toute mémoire allouée ou mmapée qui est détenue par la structure MMDB_s. *Cela ne libère pas la mémoire

MMDB_lookup_string()

MMDB_lookup_result_s MMDB_lookup_string(
    MMDB_s *const mmdb,
    const char *const ipstr,
    int *const gai_error,
    int *const mmdb_error);

Cette fonction recherche une adresse IP fournie sous forme de chaîne de caractères terminée par un caractère nul. Elle appelle en interne getaddrinfo() pour résoudre l'adresse sous forme binaire. Ensuite, elle appelle MMDB_lookup_sockaddr() pour rechercher l'adresse dans la base de données. Si vous avez déjà résolu une adresse, vous pouvez appeler MMDB_lookup_sockaddr() directement, sans avoir à la résoudre deux fois.

int gai_error, mmdb_error;
MMDB_lookup_result_s result =
    MMDB_lookup_string(&mmdb, "1.2.3.4", &gai_error, &mmdb_error);
if (0 != gai_error) { ... }
if (MMDB_SUCCESS != mmdb_error) { ... }
if (result.found_entry) { ... }

Cette fonction retourne toujours une structure MMDB_lookup_result_s, mais vous devriez également vérifier les paramètres gai_error et mmdb_error. Si l'un d'eux indique une erreur, la structure retournée est inutile.

Si aucune erreur ne s'est produite, vous devez quand même vous assurer que le membre found_entry de la structure retournée est vrai. Si ce n'est pas le cas, cela signifie que l'adresse IP n'a pas d'entrée dans la base de données.

Cette fonction fonctionne avec les adresses IPv4 même lorsque la base de données contient des données pour les deux IPv4 et IPv6. L'adresse IPv4 sera recherchée sous la forme "::xxx.xxx.xxx.xxx" au lieu d'être remappée vers le bloc ::ffff:xxx.xxx.xxx.xxx réservé aux adresses IPv6 mappées IPv4.

Si vous passez une adresse IPv6 à une base de données qui ne contient que des données IPv4, le membre found_entry sera faux, mais l'état mmdb_error restera MMDB_SUCCESS.

MMDB_lookup_sockaddr()

MMDB_lookup_result_s MMDB_lookup_sockaddr(
    MMDB_s *const mmdb,
    const struct sockaddr *const sockaddr,
    int *const mmdb_error);

Cette fonction recherche une adresse IP qui a déjà été résolue à l'aide de getaddrinfo().

À l'exception du fait qu'elle n'appelle pas getaddrinfo(), cette fonction est identique à la fonction MMDB_lookup_string().

int mmdb_error;
MMDB_lookup_result_s result =
    MMDB_lookup_sockaddr(&mmdb, address->ai_addr, &mmdb_error);
if (MMDB_SUCCESS != mmdb_error) { ... }
if (result.found_entry) { ... }

Fonctions de Recherche de Données

Il existe trois fonctions pour rechercher des données associées à une adresse IP.

int MMDB_get_value(
    MMDB_entry_s *const start,
    MMDB_entry_data_s *const entry_data,
    ...);
int MMDB_vget_value(
    MMDB_entry_s *const start,
    MMDB_entry_data_s *const entry_data,
    va_list va_path);
int MMDB_aget_value(
    MMDB_entry_s *const start,
    MMDB_entry_data_s *const entry_data,
    const char *const *const path);

Les trois fonctions permettent trois styles d'appel légèrement différents, mais elles effectuent toutes la même tâche.

Le premier paramètre est une valeur MMDB_entry_s. Dans la plupart des cas, cela proviendra de la valeur MMDB_lookup_result_s retournée par MMDB_lookup_string() ou MMDB_lookup_sockaddr().

Le deuxième paramètre est une référence à une structure MMDB_entry_data_s. Celle-ci sera remplie avec les données recherchées, si elles existent. Si rien n'est trouvé, le membre has_data de cette structure sera faux. Si has_data est vrai, vous pouvez examiner le membre data_type.

Le dernier paramètre est un chemin de recherche. Le chemin se compose d'une série de chaînes de caractères représentant des clés de map (par exemple, "city") ou des index de tableau (par exemple, "0", "1", "-1") à utiliser dans la recherche.

Les index de tableau négatifs sont traités comme un décalage par rapport à la fin du tableau. Par exemple, "-1" fait référence au dernier élément du tableau.

Le chemin de recherche permet de naviguer dans une structure complexe. Par exemple, étant donné cette structure :

{
    "names": {
        "en": "Germany",
        "de": "Deutschland"
    },
    "cities": [ "Berlin", "Frankfurt" ]
}

Nous pouvons rechercher le nom en anglais avec ce code :

MMDB_lookup_result_s result =
    MMDB_lookup_sockaddr(&mmdb, address->ai_addr, &mmdb_error);
MMDB_entry_data_s entry_data;
int status =
    MMDB_get_value(&result.entry, &entry_data,
                   "names", "en", NULL);
if (MMDB_SUCCESS != status) { ... }
if (entry_data.has_data) { ... }

Si nous voulons trouver la première ville, le chemin de recherche serait "cities" et "0". Si vous ne spécifiez pas de chemin de recherche, vous obtiendrez l'entrée correspondant à la map de niveau supérieur. Le chemin de recherche doit toujours se terminer par NULL, quelle que soit la fonction que vous utilisez.

La fonction MMDB_get_value accepte un nombre variable d'arguments. Tous les arguments après le pointeur vers MMDB_entry_data_s constituent le chemin de recherche. Le dernier argument doit être NULL.

La fonction MMDB_vget_value accepte une va_list comme chemin de recherche. Le dernier élément récupéré par va_arg() doit être NULL.

Enfin, la fonction MMDB_aget_value accepte un tableau de chaînes de caractères comme chemin de recherche. Le dernier élément de ce tableau doit être NULL.

Si vous souhaitez obtenir toutes les données d'une entrée en une seule fois, vous pouvez appeler MMDB_get_entry_data_list().

Pour chacune des trois fonctions, la valeur retournée est un code d'état tel que défini ci-dessus.

MMDB_get_entry_data_list()

int MMDB_get_entry_data_list(
    MMDB_entry_s *start,
    MMDB_entry_data_list_s **const entry_data_list);

Cette fonction vous permet d'obtenir toutes les données d'une structure complexe en une seule fois, au lieu de rechercher chaque partie par des appels répétés à MMDB_get_value().

MMDB_lookup_result_s result =
    MMDB_lookup_sockaddr(&mmdb, address->ai_addr, &mmdb_error);
MMDB_entry_data_list_s *entry_data_list, *first;
int status =
    MMDB_get_entry_data_list(&result.entry, &entry_data_list);
if (MMDB_SUCCESS != status) { ... }
// sauvegarder ceci pour pouvoir libérer plus tard
first = entry_data_list;
while (1) {
    MMDB_entry_data_list_s *next = entry_data_list = entry_data_list->next;
    if (NULL == next) {
        break;
    }
    switch (next->entry_data.type) {
        case MMDB_DATA_TYPE_MAP: { ... }
        case MMDB_DATA_TYPE_UTF8_STRING: { ... }
        ...
    }
}
MMDB_free_entry_data_list(first);

Il s'agit d'interpréter la structure entry_data_list. La liste est liée en profondeur. J'utiliserai cette structure comme exemple :

{
    "names": {
        "en": "Germany",
        "de": "Deutschland"
    },
    "cities": [ "Berlin", "Frankfurt" ]
}

La liste contiendra les éléments suivants :

1.
MAP - la map racine
2.
UTF8_STRING - la clé "names"
3.
MAP - la map de "names"
4.
UTF8_STRING - la clé "en"
5.
UTF8_STRING - la valeur pour la clé "en"
6.
UTF8_STRING - la clé "de"
7.
UTF8_STRING - la valeur pour la clé "de"
8.
UTF8_STRING - la clé "cities"
9.
ARRAY - la valeur pour la clé "cities"
10.
UTF8_STRING - array[0]
11.
UTF8_STRING - array[1]

La valeur retournée par la fonction est un code d'état tel que défini ci-dessus.

Les fonctions MMDB_get_entry_data_list() et MMDB_get_metadata_as_entry_data_list() allouent la structure de liste chaînée en mémoire. Appelez cette fonction pour libérer la structure MMDB_entry_data_list_s.

Cette fonction vous permet de récupérer les métadonnées de la base de données sous forme de liste chaînée de structures MMDB_entry_data_list_s. Cela peut être plus pratique que d'utiliser directement la structure des métadonnées.

La valeur retournée par la fonction est un code d'état tel que défini ci-dessus.

MMDB_dump_entry_data_list()

int MMDB_dump_entry_data_list(
    FILE *const stream,
    MMDB_entry_data_list_s *const entry_data_list,
    int indent);

Cette fonction prend une liste chaînée de structures MMDB_entry_data_list_s et la sérialise dans le flux donné. Le paramètre indent est le niveau d'indentation initial pour la sortie générée. Il est incrémenté pour les structures imbriquées (maps, tableaux, etc.).

Le flux doit être un handle de fichier (stdout, etc.). Si votre plate-forme fournit quelque chose comme open_memstream() (GNU), vous pouvez l'utiliser pour capturer la sortie sous forme de chaîne.

La sortie est formatée de manière similaire à JSON, mais les valeurs sont étiquetées avec leur type de données (sauf si les maps et les tableaux sont affichés comme "{}" et "[]" respectivement).

La forme spécifique de la sortie peut changer dans les futures versions.

MMDB_lookup_string(3)

NOM

MMDB_lookup_string

SYNTAXE

int MMDB_lookup_string( MMDB_s *const mmdb, const char *const ip_address, int *const gai_error, int *const mmdb_error);

DESCRIPTION

Cette fonction recherche une adresse IP dans la base de données. Le deuxième argument est un pointeur vers un objet de type MMDB_lookup_result_s qui contiendra le résultat de la recherche.

STRUCTURES DE DONNÉES

La structure MMDB_lookup_result_s contient les champs suivants :

  • found_entry (bool): indique si une entrée a été trouvée.

  • entry (MMDB_entry_s *const): pointe vers une entrée.

  • gai_error (int): code d'erreur de getaddrinfo.

  • mmdb_error (int): code d'erreur de libmaxminddb.

CODES DE STATUT

Les codes de statut de cette fonction sont définis comme suit :

  • MMDB_SUCCESS: succès.

  • MMDB_INVALID_NODE_NUMBER_ERROR: numéro de nœud invalide.

  • MMDB_IO_ERROR: erreur d'entrée/sortie.

  • MMDB_NOT_FOUND: entrée non trouvée.

  • MMDB_LOOKUP_FAILED: recherche échouée.

FONCTIONS

int MMDB_lookup_string(
    MMDB_s *const mmdb,
    const char *const ip_address,
    int *const gai_error,
    int *const mmdb_error);

Cette fonction recherche une adresse IP dans la base de données. Le deuxième argument est un pointeur vers un objet de type MMDB_lookup_result_s qui contiendra le résultat de la recherche.

La valeur de retour est un code de statut. Si un numéro de nœud supérieur au nombre de nœuds dans la base de données est passé, cette fonction retournera MMDB_INVALID_NODE_NUMBER_ERROR, sinon elle retournera MMDB_SUCCESS.

Le premier nœud dans l'arbre de recherche est toujours le nœud 0. Si vous souhaitez parcourir l'intégralité de l'arbre, vous devez d'abord lire le nœud 0, puis suivre les enregistrements qui composent ce nœud, en fonction du type de chaque enregistrement. Si le type est MMDB_RECORD_TYPE_SEARCH_NODE, l'enregistrement contient un entier pour le nœud suivant à rechercher.

EXEMPLE

#include <errno.h>
#include <maxminddb.h>
#include <stdlib.h>
#include <string.h>
int main(int argc, char **argv)
{
    char *filename = argv[1];
    char *ip_address = argv[2];
    MMDB_s mmdb;
    int status = MMDB_open(filename, MMDB_MODE_MMAP, &mmdb);
    if (MMDB_SUCCESS != status) {
        fprintf(stderr, "\n  Can't open %s - %s\n",
                filename, MMDB_strerror(status));
        if (MMDB_IO_ERROR == status) {
            fprintf(stderr, "    IO error: %s\n", strerror(errno));
        }
        exit(1);
    }
    int gai_error, mmdb_error;
    MMDB_lookup_result_s result =
        MMDB_lookup_string(&mmdb, ip_address, &gai_error, &mmdb_error);
    if (0 != gai_error) {
        fprintf(stderr,
                "\n  Error from getaddrinfo for %s - %s\n\n",
                ip_address, gai_strerror(gai_error));
        exit(2);
    }
    if (MMDB_SUCCESS != mmdb_error) {
        fprintf(stderr,
                "\n  Got an error from libmaxminddb: %s\n\n",
                MMDB_strerror(mmdb_error));
        exit(3);
    }
    MMDB_entry_data_list_s *entry_data_list = NULL;
    int exit_code = 0;
    if (result.found_entry) {
        int status = MMDB_get_entry_data_list(&result.entry,
                                              &entry_data_list);
        if (MMDB_SUCCESS != status) {
            fprintf(
                stderr,
                "Got an error looking up the entry data - %s\n",
                MMDB_strerror(status));
            exit_code = 4;
            goto end;
        }
        if (NULL != entry_data_list) {
            MMDB_dump_entry_data_list(stdout, entry_data_list, 2);
        }
    } else {
        fprintf(
            stderr,
            "\n  No entry for this IP address (%s) was found\n\n",
            ip_address);
        exit_code = 5;
    }
    end:
        MMDB_free_entry_data_list(entry_data_list);
        MMDB_close(&mmdb);
        exit(exit_code);
}
