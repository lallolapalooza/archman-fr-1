DESCRIPTION

La bibliothèque libmaxminddb fournit des fonctions pour travailler avec des fichiers MaxMind DB. Consultez https://maxmind.github.io/MaxMind-DB/ pour la spécification du format MaxMind DB. Les bases de données et les résultats sont représentés par des structures différentes. Les bases de données sont ouvertes en appelant MMDB_open(). Vous pouvez interroger des adresses IP en tant que chaînes avec MMDB_lookup_string() ou en tant que pointeurs vers des structures sockaddr avec MMDB_lookup_sockaddr().

Si la requête trouve l'adresse IP dans la base de données, elle renvoie une structure MMDB_lookup_result_s. Si cette structure indique que la base de données contient des données pour l'adresse IP, plusieurs fonctions peuvent être utilisées pour obtenir ces données. Celles-ci incluent MMDB_get_value() et MMDB_get_entry_data_list(). Consultez la documentation des fonctions pour plus de détails.

Lorsque vous avez terminé avec le handle de base de données, vous devez appeler MMDB_close().

Toutes les fonctions, structures et macros publiques commencent par "MMDB_".

STRUCTURES DE DONNÉES

Toutes les structures exportées par l'en-tête maxminddb.h de cette bibliothèque sont définies comme typedef struct foo_s { ... } foo_s, vous pouvez donc y faire référence sans le préfixe struct.

Cette bibliothèque fournit les structures suivantes :

MMDB_s

C'est la référence du handle d'un fichier MaxMind DB. Nous ne documentons que certains champs de cette structure destinés à un usage public. Tous les autres champs sont sujets à modification et sont destinés à un usage interne uniquement.

typedef struct MMDB_s {
    uint32_t flags;
    const char *filename;
    ...
    MMDB_metadata_s metadata;
} MMDB_s;
  • uint32_t flags - les flags avec lesquels cette base de données a été ouverte. Consultez la documentation de MMDB_open() pour plus de détails.
  • const char *filename - le nom du fichier qui a été ouvert, tel que passé à MMDB_open().
  • MMDB_metadata_s metadata - les métadonnées de la base de données.

MMDB_metadata_s et MMDB_description_s

Cette structure peut être obtenue à partir de la structure MMDB_s. Elle contient les métadonnées lues à partir d'un fichier de base de données. Il devrait être plus pratique d'accéder à ces métadonnées en appelant MMDB_get_metadata_as_entry_data_list().

typedef struct MMDB_metadata_s {
    uint32_t node_count;
    uint16_t record_size;
    uint16_t ip_version;
    const char *database_type;
    struct {
        size_t count;
        const char **names;
    } languages;
    uint16_t binary_format_major_version;
    uint16_t binary_format_minor_version;
    uint64_t build_epoch;
    struct {
        size_t count;
        MMDB_description_s **descriptions;
    } description;
} MMDB_metadata_s;
typedef struct MMDB_description_s {
    const char *language;
    const char *description;
} MMDB_description_s;

Ces structures devraient être principalement auto-explicatives.

Le membre ip_version doit toujours être 4 ou 6. Le membre binary_format_major_version doit toujours être 2.

Il n'est pas obligatoire que les métadonnées de la base de données incluent des langues ou des descriptions, donc les membres count pour ces aspects des métadonnées peuvent être zéro. Tous les autres membres de MMDB_metadata_s doivent être renseignés.

MMDB_lookup_result_s

Cette structure est renvoyée comme résultat d'une requête d'adresse IP.

typedef struct MMDB_lookup_result_s {
    bool found_entry;
    MMDB_entry_s entry;
    uint16_t netmask;
} MMDB_lookup_result_s;

Si le membre found_entry est faux, les autres membres de cette structure ne contiennent pas de valeurs significatives. Vous devez d'abord vérifier que found_entry est vrai.

Le membre entry est utilisé pour rechercher les données associées à l'adresse IP.

Le membre netmask indique à quel sous-réseau l'adresse IP appartient dans cette base de données. Par exemple, si vous interrogez l'adresse 1.1.1.1 dans une base de données IPv4 et que la valeur renvoyée netmask est 16, alors l'adresse appartient au sous-réseau 1.1.0.0/16.

Si la base de données est une base de données IPv6, la valeur renvoyée netmask est toujours une longueur de préfixe IPv6 (de 0 à 128), même si cette base de données contient également des réseaux IPv4. Si vous interrogez une adresse IPv4 et que vous souhaitez convertir le netmask en une valeur de sous-réseau IPv4, vous pouvez simplement soustraire 96 de la valeur.

MMDB_result_s

Vous n'avez pas besoin de regarder en profondeur dans cette structure. Vous l'obtiendrez d'une structure MMDB_lookup_result_s et la passerez à diverses fonctions.

MMDB_entry_data_s

Cette structure est utilisée pour renvoyer un seul bloc de données d'une adresse IP. Ces blocs peuvent pointer vers d'autres blocs, comme c'est le cas pour les cartes et les tableaux. Certains membres de cette structure ne sont pas documentés car ils sont uniquement à usage interne.

typedef struct MMDB_entry_data_s {
    bool has_data;
    union {
        uint32_t pointer;
        const char *utf8_string;
        double double_value;
        const uint8_t *bytes;
        uint16_t uint16;
        uint32_t uint32;
        int32_t int32;
        uint64_t uint64;
        {mmdb_uint128_t or uint8_t[16]} uint128;
        bool boolean;
        float float_value;
    };
    ...
    uint32_t data_size;
    uint32_t type;
} MMDB_entry_data_s;

Le membre has_data est vrai si des données ont été trouvées pour une requête spécifique. Consultez MMDB_get_value() pour plus de détails. Si ce membre est faux, aucune des valeurs restantes dans la structure n'est significative.

L'union au début de la structure définit les données réelles. Pour déterminer quelle union est utilisée, vous pouvez consulter la valeur de type.

member est renseigné, vous devez examiner le membre type. Le membre pointer de l'union ne doit jamais être renseigné dans les données retournées par l'API. Les pointeurs doivent toujours être résolus en interne.

Le membre data_size n'est pertinent que pour les données utf8_string et bytes. utf8_string n'est pas terminé par un caractère nul et data_size doit être utilisé pour déterminer sa longueur.

Le membre type peut être comparé à l'une des macros MMDB_DATA_TYPE_*.

Entiers 128 bits

La gestion des données uint128 dépend de la manière dont votre plateforme prend en charge les entiers 128 bits, si tant est qu'elle le fasse. Avec GCC 4.4 et 4.5, nous pouvons écrire unsigned int __attribute__ ((__mode__ (TI))). Avec les versions plus récentes de GCC (4.6+) et clang (3.2+), nous pouvons simplement écrire "unsigned __int128".

Afin de contourner ces différences, cette bibliothèque définit un type mmdb_uint128_t. Ce type est défini dans l'en-tête maxminddb.h afin que vous puissiez l'utiliser dans votre propre code.

Avec les anciens compilateurs, nous ne pouvons pas utiliser un entier, donc nous utilisons à la place un tableau de 16 octets de valeurs uint8_t. Ce sont les données brutes de la base de données.

Cette bibliothèque fournit une macro publique MMDB_UINT128_IS_BYTE_ARRAY. Si celle-ci est vraie (1), alors les valeurs uint128 sont retournées sous forme de tableau d'octets, si elle est fausse, elles sont retournées sous forme d'un entier mmdb_uint128_t.

Macros de types de données

Cette bibliothèque fournit une macro pour chaque type de données défini par la spécification MaxMind DB.

  • MMDB_DATA_TYPE_UTF8_STRING
  • MMDB_DATA_TYPE_DOUBLE
  • MMDB_DATA_TYPE_BYTES
  • MMDB_DATA_TYPE_UINT16
  • MMDB_DATA_TYPE_UINT32
  • MMDB_DATA_TYPE_MAP
  • MMDB_DATA_TYPE_INT32
  • MMDB_DATA_TYPE_UINT64
  • MMDB_DATA_TYPE_UINT128
  • MMDB_DATA_TYPE_ARRAY
  • MMDB_DATA_TYPE_BOOLEAN
  • MMDB_DATA_TYPE_FLOAT

Il existe également quelques types réservés à un usage interne :

  • MMDB_DATA_TYPE_EXTENDED
  • MMDB_DATA_TYPE_POINTER
  • MMDB_DATA_TYPE_CONTAINER
  • MMDB_DATA_TYPE_END_MARKER

Si vous voyez l'un de ces éléments dans les données renvoyées, c'est que quelque chose s'est très mal passé. La base de données est endommagée ou a été générée incorrectement, ou il y a un bug dans le code de libmaxminddb.

Valeurs de pointeur et MMDB_close()

Les membres utf8_string, bytes et (peut-être) uint128 de cette structure sont tous des pointeurs directement dans la section de données de la base de données. Il peut s'agir d'un bloc de mémoire alloué avec calloc ou mmap. Dans les deux cas, ces pointeurs deviendront invalides après l'appel à MMDB_close().

Si vous avez besoin de faire référence à ces données après ce moment, vous devriez copier les données avec une fonction appropriée ( strdup, memcpy, etc.).

MMDB_entry_data_list_s

Cette structure encapsule une liste chaînée de structures MMDB_entry_data_s.

typedef struct MMDB_entry_data_list_s {
    MMDB_entry_data_s entry_data;
    struct MMDB_entry_data_list_s *next;
} MMDB_entry_data_list_s;

Cette structure vous permet d'examiner une entrée de données de type map ou array entière en parcourant la liste chaînée.

MMDB_search_node_s

Cette structure encapsule les deux enregistrements d'un nœud de recherche. Elle est surtout utile si vous souhaitez écrire du code qui parcourt l'arbre de recherche entier au lieu de rechercher une adresse IP spécifique.

typedef struct MMDB_search_node_s {
    uint64_t left_record;
    uint64_t right_record;
    uint8_t left_record_type;
    uint8_t right_record_type;
    MMDB_entry_s left_record_entry;
    MMDB_entry_s right_record_entry;
} MMDB_search_node_s;

Les deux types d'enregistrement prendront l'une des valeurs suivantes :

  • MMDB_RECORD_TYPE_SEARCH_NODE - L'enregistrement pointe vers le nœud de recherche suivant.
  • MMDB_RECORD_TYPE_EMPTY - L'enregistrement est un espace réservé qui indique qu'il n'y a pas de données pour l'adresse IP. La recherche doit se terminer ici.
  • MMDB_RECORD_TYPE_DATA - L'enregistrement est destiné aux données dans la section de données de la base de données. Utilisez l'entrée de l'enregistrement lors de la recherche des données pour cet enregistrement.
  • MMDB_RECORD_TYPE_INVALID - L'enregistrement est invalide. Soit un nœud invalide a été recherché, soit la base de données est corrompue.

Le membre MMDB_entry_s pour l'enregistrement n'est valide que si le type est MMDB_RECORD_TYPE_DATA. Les tentatives d'utilisation d'une entrée pour d'autres types d'enregistrement entraîneront une erreur ou des données invalides.

CODES DE STATUT

Cette bibliothèque retourne (ou renseigne) des codes de statut pour de nombreuses fonctions. Ces codes de statut sont :

  • MMDB_SUCCESS - tout a fonctionné
  • MMDB_FILE_OPEN_ERROR - une erreur s'est produite lors de la tentative d'ouverture du fichier MaxMind DB.
  • MMDB_IO_ERROR - une opération d'E/S a échoué. Vérifiez errno pour plus de détails.
  • MMDB_CORRUPT_SEARCH_TREE_ERROR - la recherche d'une adresse IP dans l'arbre de recherche nous a donné un résultat impossible. La base de données est endommagée ou a été générée incorrectement, ou il y a un bug dans le code libmaxminddb.
  • MMDB_INVALID_METADATA_ERROR - quelque chose dans la base de données est incorrect. Cela inclut les clés de métadonnées manquantes ainsi que les valeurs impossibles (comme un ip_version de 7).
  • MMDB_UNKNOWN_DATABASE_FORMAT_ERROR - Les métadonnées de la base de données indiquent que sa version majeure n'est pas 2. Cette bibliothèque ne peut gérer que la version majeure 2.
  • MMDB_OUT_OF_MEMORY_ERROR - un appel d'allocation de mémoire (malloc, etc.) a échoué.
  • MMDB_INVALID_DATA_ERROR - une entrée dans la section de données contient des données invalides. Par exemple, un champ uint16 prétend avoir plus de 2 octets de longueur. La base de données est probablement endommagée ou a été générée incorrectement.
  • MMDB_INVALID_LOOKUP_PATH_ERROR - Le chemin de recherche transmis à MMDB_get_value, MMDB_vget_value ou MMDB_aget_value contient un décalage de tableau supérieur à LONGMAX ou inférieur à LONGMIN.
  • MMDB_LOOKUP_PATH_DOES_NOT_MATCH_DATA_ERROR - Le chemin de recherche transmis à MMDB_get_value,MMDB_vget_value ou MMDB_aget_value ne correspond pas à la structure de données de l'entrée. Il y a un certain nombre de raisons pour lesquelles cela peut se produire. Le chemin de recherche pourrait inclure une clé qui n'est pas dans une map. Le chemin de recherche pourrait inclure un index de tableau supérieur à un tableau ou inférieur à l'offset minimum à partir de la fin d'un tableau. Cela peut également se produire lorsque le chemin s'attend à trouver une map ou un tableau là où il n'y en a pas.

Tous les codes de statut doivent être traités comme des valeurs int.

MMDB_strerror()

const char *MMDB_strerror(int error_code)

Cette fonction prend un code de statut et retourne une chaîne en anglais expliquant le statut.

FONCTIONS

Cette bibliothèque fournit les fonctions exportées suivantes :

MMDB_open()

int MMDB_open(
    const char *const filename,
    uint32_t flags,
    MMDB_s *const mmdb);

Cette fonction ouvre une poignée pour un fichier MaxMind DB. Sa valeur de retour est un code de statut tel que défini ci-dessus. Vérifiez toujours la valeur de retour de cet appel.

MMDB_s mmdb;
int status =
    MMDB_open("/path/to/file.mmdb", MMDB_MODE_MMAP, &mmdb);
if (MMDB_SUCCESS != status) { ... }
...
MMDB_close(&mmdb);

filename doit être encodé en UTF-8 sur Windows.

La structure MMDB_s que vous passez peut être sur la pile ou allouée à partir du tas. Cependant, si l'ouverture réussit, elle contiendra des données allouées sur le tas, vous devrez donc la fermer avec MMDB_close(). Si le statut retourné n'est pas MMDB_SUCCESS, cette bibliothèque s'assure que toute la mémoire allouée est libérée avant de retourner.

Les indicateurs actuellement fournis sont :

•
MMDB_MODE_MMAP - ouvre la base de données avec mmap().

Passer d'autres valeurs pour flags peut donner des résultats imprévisibles. À l'avenir, nous pourrions ajouter des indicateurs supplémentaires que vous pouvez combiner avec le mode par un OU bit à bit, ainsi que des modes supplémentaires.

Vous pouvez également passer 0 comme valeur pour flags, auquel cas la base de données sera ouverte avec les indicateurs par défaut. Cependant, ces valeurs par défaut peuvent changer dans les futures versions. La valeur par défaut actuelle est MMDB_MODE_MMAP.

MMDB_close()

void MMDB_close(MMDB_s *const mmdb);

Cela libère toute mémoire allouée ou mappée en mémoire détenue par la structure MMDB_s. Cela ne libère pas la mémoire

MMDB_lib_version()

const char * MMDB_lib_version(void);

Devuelve la cadena de la versión de la biblioteca.

printf("Using libmaxminddb version %s\n", MMDB_lib_version());

MMDB_open()

int MMDB_open(
    const char *filename,
    uint32_t flags,
    MMDB_s **const mmdb);

Abre un archivo de base de datos MaxMind DB. flags puede ser 0 o MMDB_AUTO_CLOSE_FILE. Si se especifica MMDB_AUTO_CLOSE_FILE, la biblioteca cerrará automáticamente el archivo cuando la estructura MMDB_s se libere usando MMDB_close().

Si has allocado la estructura MMDB_s tú mismo, puedes pasar un puntero a ella, pero esto no está permitido.

MMDB_s *mmdb;
int status = MMDB_open("my-db.mmdb", MMDB_AUTO_CLOSE_FILE, &mmdb);
if (MMDB_SUCCESS != status) {
    fprintf(stderr, "Error opening database: %s\n",
            MMDB_strerror(status));
    return 1;
}
// ... lookup data ...
MMDB_close(mmdb);

Si filename no se puede abrir o si la base de datos no es válida, se devolverá un código de error. Los códigos de error están definidos en mmdb.h.

Se devuelve MMDB_SUCCESS si se abre correctamente.

La estructura MMDB_s devuelta se aloja en el heap. Debes liberarla usando MMDB_close().

MMDB_close()

void MMDB_close(MMDB_s *const mmdb);

Cierra un archivo de base de datos MaxMind DB y libera todos los recursos asociados.

Si la base de datos se abrió con MMDB_AUTO_CLOSE_FILE, el archivo también se cerrará.

Si has allocado el estructura para la estructura en sí, entonces eres responsable de liberarla.

MMDB_lookup_string()

MMDB_lookup_result_s MMDB_lookup_string(
    MMDB_s *const mmdb,
    const char *const ipstr,
    int *const gai_error,
    int *const mmdb_error);

Esta función busca una dirección IP que se pasa como una cadena terminada en nulo. Internamente llama a getaddrinfo() para resolver la dirección en forma binaria. Luego llama a MMDB_lookup_sockaddr() para buscar la dirección en la base de datos. Si ya has resuelto una dirección, puedes llamar a MMDB_lookup_sockaddr() directamente, en lugar de resolverla dos veces.

int gai_error, mmdb_error;
MMDB_lookup_result_s result =
    MMDB_lookup_string(&mmdb, "1.2.3.4", &gai_error, &mmdb_error);
if (0 != gai_error) { ... }
if (MMDB_SUCCESS != mmdb_error) { ... }
if (result.found_entry) { ... }

Esta función siempre devuelve una estructura MMDB_lookup_result_s, pero también debes verificar los parámetros gai_error y mmdb_error. Si alguno indica un error, la estructura devuelta será inútil.

Si no hay error, aún debes asegurarte de que el miembro found_entry en la estructura devuelta sea verdadero. Si no lo es, esto significa que la dirección IP no tiene un registro en la base de datos.

Esta función funciona con direcciones IPv4 incluso cuando la base de datos contiene datos para tanto IPv4 como IPv6. La dirección IPv4 se buscará como '::xxx.xxx.xxx.xxx' en lugar de ser remapeada a la reserva ::ffff:xxx.xxx.xxx.xxx reservada para direcciones IPv4-mapeadas IPv6.

Si pasas una dirección IPv6 a una base de datos que solo contiene datos IPv4, el miembro found_entry será falso, pero el estado mmdb_error será aún MMDB_SUCCESS.

MMDB_lookup_sockaddr()

MMDB_lookup_result_s MMDB_lookup_sockaddr(
    MMDB_s *const mmdb,
    const struct sockaddr *const sockaddr,
    int *const mmdb_error);

Esta función busca una dirección IP que ya ha sido resuelta con getaddrinfo().

A no ser que no llames a getaddrinfo() por sí sola, esta función es idéntica a la función MMDB_lookup_string().

int mmdb_error;
MMDB_lookup_result_s result =
    MMDB_lookup_sockaddr(&mmdb, address->ai_addr, &mmdb_error);
if (MMDB_SUCCESS != mmdb_error) { ... }
if (result.found_entry) { ... }

Fonctions de recherche de données

Il existe trois fonctions pour rechercher les données associées à une adresse IP.

int MMDB_get_value(
    MMDB_entry_s *const start,
    MMDB_entry_data_s *const entry_data,
    ...);
int MMDB_vget_value(
    MMDB_entry_s *const start,
    MMDB_entry_data_s *const entry_data,
    va_list va_path);
int MMDB_aget_value(
    MMDB_entry_s *const start,
    MMDB_entry_data_s *const entry_data,
    const char *const *const path);

Les trois fonctions permettent trois styles d'appel légèrement différents, mais elles effectuent toutes la même tâche.

Le premier paramètre est une valeur MMDB_entry_s. Dans la plupart des cas, il s'agira de la valeur MMDB_lookup_result_s renvoyée par MMDB_lookup_string() ou MMDB_lookup_sockaddr().

Le second paramètre est une référence à une structure MMDB_entry_data_s. Celle-ci sera remplie avec les données recherchées, si elles existent. Si rien n'est trouvé, le membre has_data de cette structure sera faux. Si has_data est vrai, vous pouvez consulter le membre data_type.

Le dernier paramètre est un chemin de recherche. Le chemin se compose d'un ensemble de chaînes représentant des clés de carte (par exemple, "city") ou des indices de tableau (par exemple, "0", "1", "-1") à utiliser dans la recherche.

Les indices négatifs dans le tableau seront traités comme un décalage par rapport à la fin du tableau. Par exemple, "-1" fait référence au dernier élément du tableau.

Le chemin de recherche permet de naviguer dans une structure complexe. Par exemple, étant donné ces données :

{
    "names": {
        "en": "Germany",
        "de": "Deutschland"
    },
    "cities": [ "Berlin", "Frankfurt" ]
}

Nous pouvons rechercher le nom en anglais avec ce code :

MMDB_lookup_result_s result =
    MMDB_lookup_sockaddr(&mmdb, address->ai_addr, &mmdb_error);
MMDB_entry_data_s entry_data;
int status =
    MMDB_get_value(&result.entry, &entry_data,
                   "names", "en", NULL);
if (MMDB_SUCCESS != status) { ... }
if (entry_data.has_data) { ... }

Si nous voulons trouver la première ville, le chemin de recherche serait "cities", "0". Si vous ne fournissez pas de chemin de recherche, vous obtiendrez l'enregistrement correspondant à la carte de niveau supérieur. Le chemin de recherche doit toujours se terminer par NULL, quelle que soit la fonction que vous utilisez.

La fonction MMDB_get_value accepte un nombre variable d'arguments. Tous les arguments après le MMDB_entry_data_s * constituent le chemin de recherche. Le dernier argument doit être NULL.

La fonction MMDB_vget_value accepte un va_list comme chemin de recherche. Le dernier élément récupéré avec va_arg() doit être NULL.

Enfin, la fonction MMDB_aget_value accepte un tableau de chaînes comme chemin de recherche. Le dernier élément de ce tableau doit être NULL.

Si vous souhaitez obtenir toutes les données de l'entrée en une seule fois, vous pouvez appeler MMDB_get_entry_data_list().

Pour chacune des trois fonctions, la valeur de retour est un code d'état tel que décrit.

MMDB_get_entry_data_list()

int MMDB_get_entry_data_list(
    MMDB_entry_s *start,
    MMDB_entry_data_list_s **const entry_data_list);

Cette fonction vous permet d'obtenir toutes les données d'une structure complexe en une seule fois, au lieu de rechercher chaque partie avec des appels répétés à MMDB_get_value().

MMDB_lookup_result_s result =
    MMDB_lookup_sockaddr(&mmdb, address->ai_addr, &mmdb_error);
MMDB_entry_data_list_s *entry_data_list, *first;
int status =
    MMDB_get_entry_data_list(&result.entry, &entry_data_list);
if (MMDB_SUCCESS != status) { ... }
// enregistrer ceci afin de pouvoir libérer ces données plus tard
first = entry_data_list;
while (1) {
    MMDB_entry_data_list_s *next = entry_data_list = entry_data_list->next;
    if (NULL == next) {
        break;
    }
    switch (next->entry_data.type) {
        case MMDB_DATA_TYPE_MAP: { ... }
        case MMDB_DATA_TYPE_UTF8_STRING: { ... }
        ...
    }
}
MMDB_free_entry_data_list(first);

Il est de votre responsabilité d'interpréter la structure entry_data_list. La liste est chaînée dans un parcours en profondeur. Nous utiliserons cette structure comme exemple :

{
    "names": {
        "en": "Germany",
        "de": "Deutschland"
    },
    "cities": [ "Berlin", "Frankfurt" ]
}

La liste contiendra les éléments suivants :

1.
MAP - carte de niveau supérieur
2.
UTF8_STRING - clé "names"
3.
MAP - carte de "names"
4.
UTF8_STRING - clé "en"
5.
UTF8_STRING - valeur de "en"
6.
UTF8_STRING - clé "de"
7.
UTF8_STRING - valeur de "de"
8.
UTF8_STRING - clé "cities"
9.
ARRAY - valeur de "cities"
10.
UTF8_STRING - array[0]
11.
UTF8_STRING - array[1]

La valeur de retour de la fonction est un code d'état tel que défini ci-dessus.

MMDB_free_entry_data_list()

void MMDB_free_entry_data_list(
    MMDB_entry_data_list_s *const entry_data_list);

Les fonctions MMDB_get_entry_data_list() et MMDB_get_metadata_as_entry_data_list() allouent la structure de liste chaînée dans le tas. Appelez cette fonction pour libérer la structure MMDB_entry_data_list_s.

MMDB_get_metadata_as_entry_data_list()

int MMDB_get_metadata_as_entry_data_list(
    MMDB_s *const mmdb,
    MMDB_entry_data_list_s **const entry_data_list);

Cette fonction permet de récupérer les métadonnées de la base de données sous forme de liste chaînée de structures MMDB_entry_data_list_s. Cela peut être une manière plus pratique de gérer les métadonnées que d'utiliser directement la structure de métadonnées.

    MMDB_entry_data_list_s *entry_data_list, *first;
    int status =
        MMDB_get_metadata_as_entry_data_list(&mmdb, &entry_data_list);
    if (MMDB_SUCCESS != status) { ... }
    first = entry_data_list;
    ... // faire quelque chose avec les données
    MMDB_free_entry_data_list(first);

La valeur de retour de la fonction est un code d'état tel que défini ci-dessus.

MMDB_dump_entry_data_list()

int MMDB_dump_entry_data_list(
    FILE *const stream,
    MMDB_entry_data_list_s *const entry_data_list,
    int indent);

Cette fonction prend une liste chaînée de structures MMDB_entry_data_list_s et la sérialise dans le flux donné stream. Le paramètre indent est le niveau d'indentation initial pour la sortie générée. Il est incrémenté pour les structures imbriquées (cartes, tableaux, etc.).

Le stream doit être un descripteur de fichier (stdout, etc.). Si votre plateforme fournit quelque chose comme open_memstream() (GNU), vous pouvez l'utiliser pour capturer la sortie sous forme de chaîne.

La sortie est formatée de manière similaire à JSON, mais les valeurs sont étiquetées avec leur type de données (sauf que les cartes et les tableaux sont affichés sous forme de "{}" et "[]" respectivement).

Le format spécifique de la sortie peut changer.

libmaxminddb - MMDB_get_entry_data_list(3)

NAME

MMDB_get_entry_data_list, MMDB_free_entry_data_list, MMDB_dump_entry_data_list, MMDB_read_node, MMDB_lib_version - manipulate MaxMind DB data

SYNOPSIS

#include <maxminddb.h>
void MMDB_free_entry_data_list(MMDB_entry_data_list_s *p);
void MMDB_dump_entry_data_list(FILE *file,
    MMDB_entry_data_list_s *p, int depth);
int MMDB_get_entry_data_list(MMDB_entry_s *entry,
    MMDB_entry_data_list_s **p);
int MMDB_read_node(MMDB_s *const mmdb, uint32_t node_number,
    MMDB_search_node_s *const node);
const char *MMDB_lib_version(void);

DESCRIPTION

The MMDB_get_entry_data_list function returns a list of MMDB_entry_data_s elements. This list is a representation of the data associated with an entry in the MaxMind DB file. The list is allocated by this function and must be freed by calling MMDB_free_entry_data_list.

The MMDB_dump_entry_data_list function will print the contents of the data list to the specified file handle. The depth argument is used to indent the output, and should start at 0.

The MMDB_free_entry_data_list function frees the data list previously allocated by MMDB_get_entry_data_list.

The MMDB_read_node function reads a specific node in the search tree. The third argument is a reference to an MMDB_search_node_s structure that will be populated by this function. The first node in the search tree is always node 0. If you wanted to iterate over the whole search tree, you would start by reading node 0 and then following the the records that make up this node, based on the type of each record. If the type is MMDB_RECORD_TYPE_SEARCH_NODE then the record contains an integer for the next node to look up.

The MMDB_lib_version function returns the library version as a string, something like "2.0.0".

DATA STRUCTURES

The MMDB_entry_data_list_s structure contains a pointer to the first element in the list, and a pointer to the next element. If the data is a map or an array, the elements are ordered. The last element in the list will have its entry_data.type set to MMDB_DATA_TYPE_NULL.

The MMDB_search_node_s structure contains a pointer to the data associated with this node. If the data is a map or an array, the elements are ordered. The last element in the list will have its entry_data.type set to MMDB_DATA_TYPE_NULL.

The MMDB_entry_data_s structure contains the type and value of a piece of data. The value is stored in MMDB_entry_data_s.union_data. The type is stored in MMDB_entry_data_s.type.

The MMDB_lookup_result_s structure contains the result of a lookup. If an entry was found, found_entry will be true, and the entry field will contain the entry. Otherwise, found_entry will be false.

STATUS CODES

The functions in this library return status codes. The possible values are:

MMDB_SUCCESS
Operation successful.
MMDB_START_ERROR
An error occurred during initialization. See errno.
MMDB_INVALID_DATA_ERROR
The MaxMind DB file is corrupted or invalid.
MMDB_INVALID_METADATA_ERROR
The MaxMind DB metadata is invalid.
MMDB_INVALID_NODE_NUMBER_ERROR
The provided node number is invalid.
MMDB_IO_ERROR
An I/O error occurred.
MMDB_OUT_OF_MEMORY_ERROR
Out of memory.
MMDB_FULL_IMMUTABLE_METADATA_ERROR
The metadata is full and cannot be modified.
MMDB_LOOKUP_FAILED_ERROR
The lookup failed.

FUNCTIONS

MMDB_get_entry_data_list()

int MMDB_get_entry_data_list(
    MMDB_entry_s *const entry,
    MMDB_entry_data_list_s **p);

This function retrieves the data associated with an entry in the MaxMind DB database. The data is returned as a linked list of MMDB_entry_data_s structures, pointed to by p. The list must be freed using MMDB_free_entry_data_list.

The return value is a status code. It will be MMDB_SUCCESS on success, or an error code otherwise. If the entry is not found, the function will return MMDB_LOOKUP_FAILED_ERROR.

MMDB_free_entry_data_list()

void MMDB_free_entry_data_list(MMDB_entry_data_list_s *p);

Frees the linked list allocated by MMDB_get_entry_data_list.

MMDB_dump_entry_data_list()

void MMDB_dump_entry_data_list(FILE *file,
    MMDB_entry_data_list_s *p, int depth);

Dumps the contents of the entry data list to the specified file handle. The depth parameter is used for indentation.

This function is intended for debugging and showing data to users. The output format may change in future releases, so you should not rely on the specific formatting produced by this function.

MMDB_read_node()

int MMDB_read_node(
    MMDB_s *const mmdb,
    uint32_t node_number,
    MMDB_search_node_s *const node);

This reads a specific node in the search tree. The third argument is a reference to an MMDB_search_node_s structure that will be populated by this function.

The return value is a status code. If you pass a node_number that is greater than the number of nodes in the database, this function will return MMDB_INVALID_NODE_NUMBER_ERROR, otherwise it will return MMDB_SUCCESS.

The first node in the search tree is always node 0. If you wanted to iterate over the whole search tree, you would start by reading node 0 and then following the the records that make up this node, based on the type of each record. If the type is MMDB_RECORD_TYPE_SEARCH_NODE then the record contains an integer for the next node to look up.

MMDB_lib_version()

const char *MMDB_lib_version(void)

This function returns the library version as a string, something like "2.0.0".

EXAMPLE

#include <errno.h>
#include <maxminddb.h>
#include <stdlib.h>
#include <string.h>
int main(int argc, char **argv)
{
    char *filename = argv[1];
    char *ip_address = argv[2];
    MMDB_s mmdb;
    int status = MMDB_open(filename, MMDB_MODE_MMAP, &mmdb);
    if (MMDB_SUCCESS != status) {
        fprintf(stderr, "\n  Can't open %s - %s\n",
                filename, MMDB_strerror(status));
        if (MMDB_IO_ERROR == status) {
            fprintf(stderr, "    IO error: %s\n", strerror(errno));
        }
        exit(1);
    }
    int gai_error, mmdb_error;
    MMDB_lookup_result_s result =
        MMDB_lookup_string(&mmdb, ip_address, &gai_error, &mmdb_error);
    if (0 != gai_error) {
        fprintf(stderr,
                "\n  Error from getaddrinfo for %s - %s\n\n",
                ip_address, gai_strerror(gai_error));
        exit(2);
    }
    if (MMDB_SUCCESS != mmdb_error) {
        fprintf(stderr,
                "\n  Got an error from libmaxminddb: %s\n\n",
                MMDB_strerror(mmdb_error));
        exit(3);
    }
    MMDB_entry_data_list_s *entry_data_list = NULL;
    int exit_code = 0;
    if (result.found_entry) {
        int status = MMDB_get_entry_data_list(&result.entry,
                                              &entry_data_list);
        if (MMDB_SUCCESS != status) {
            fprintf(
                stderr,
                "Got an error looking up the entry data - %s\n",
                MMDB_strerror(status));
            exit_code = 4;
            goto end;
        }
        if (NULL != entry_data_list) {
            MMDB_dump_entry_data_list(stdout, entry_data_list, 2);
        }
    } else {
        fprintf(
            stderr,
            "\n  No entry for this IP address (%s) was found\n\n",
            ip_address);
        exit_code = 5;
    }
    end:
        MMDB_free_entry_data_list(entry_data_list);
        MMDB_close(&mmdb);
        exit(exit_code);
}
