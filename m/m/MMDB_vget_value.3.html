DESCRIPTION

La bibliothèque libmaxminddb fournit des fonctions pour travailler avec des fichiers MaxMind DB. Voir https://maxmind.github.io/MaxMind-DB/ pour la spécification du format MaxMind DB. Les bases de données et les résultats sont représentés par différentes structures. Les bases de données sont ouvertes en appelant MMDB_open(). Vous pouvez rechercher des adresses IP sous forme de chaînes avec MMDB_lookup_string() ou sous forme de référence à une structure sockaddr avec MMDB_lookup_sockaddr().

Si la recherche trouve l'adresse IP dans la base de données, elle renvoie une structure MMDB_lookup_result_s. Si cette structure indique que la base de données contient des données pour l'adresse IP, plusieurs fonctions peuvent être utilisées pour obtenir ces données. Celles-ci incluent MMDB_get_value() et MMDB_get_entry_data_list(). Voir la documentation des fonctions séparément pour plus de détails.

Lorsque vous avez terminé avec le handle de la base de données, vous devez appeler MMDB_close().

Toutes les fonctions publiques, structures et macros commencent par MMDB_.

STRUCTURES DE DONNÉES

Toutes les structures exportées par le fichier d'en-tête maxminddb.h de cette bibliothèque sont définies comme typedef struct foo_s { ... } foo_s, vous pouvez donc y faire référence sans le préfixe struct.

Cette bibliothèque fournit les structures suivantes :

MMDB_s

Il s'agit du handle pour un fichier MaxMind DB. Nous ne documentons que certains des champs de cette structure destinés à un usage public. Tous les autres champs sont sujets à modification et sont uniquement destinés à un usage interne.

typedef struct MMDB_s {
    uint32_t flags;
    const char *filename;
    ...
    MMDB_metadata_s metadata;
} MMDB_s;
  • uint32_t flags - les indicateurs avec lesquels la base de données a été ouverte. Voir la documentation de MMDB_open() pour plus de détails.
  • const char *filename - le nom du fichier qui a été ouvert, tel que passé à MMDB_open().
  • MMDB_metadata_s metadata - les métadonnées de la base de données.

MMDB_metadata_s et MMDB_description_s

Cette structure peut être obtenue à partir de la structure MMDB_s. Elle contient les métadonnées lues à partir d'un fichier de base de données. Notez qu'il peut être plus pratique d'accéder à ces métadonnées en appelant MMDB_get_metadata_as_entry_data_list().

typedef struct MMDB_metadata_s {
    uint32_t node_count;
    uint16_t record_size;
    uint16_t ip_version;
    const char *database_type;
    struct {
        size_t count;
        const char **names;
    } languages;
    uint16_t binary_format_major_version;
    uint16_t binary_format_minor_version;
    uint64_t build_epoch;
    struct {
        size_t count;
        MMDB_description_s **descriptions;
    } description;
} MMDB_metadata_s;
typedef struct MMDB_description_s {
    const char *language;
    const char *description;
} MMDB_description_s;

Ces structures devraient être largement auto-explicatives.

Le membre ip_version doit toujours être 4 ou 6. Le membre binary_format_major_version doit toujours être 2.

Il n'est pas obligatoire que les métadonnées de la base de données incluent des langues ou des descriptions, donc le count pour ces aspects des métadonnées peut être zéro. Tous les autres membres de MMDB_metadata_s doivent être renseignés.

MMDB_lookup_result_s

Cette structure est renvoyée comme résultat de la recherche d'une adresse IP.

typedef struct MMDB_lookup_result_s {
    bool found_entry;
    MMDB_entry_s entry;
    uint16_t netmask;
} MMDB_lookup_result_s;

Si le membre found_entry est faux, les autres membres de cette structure ne contiennent pas de valeurs significatives. Vous devez d'abord vérifier que found_entry est vrai.

Le membre entry est utilisé pour rechercher les données associées à l'adresse IP.

Le membre netmask indique à quelle sous-réseau l'adresse IP appartient dans cette base de données. Par exemple, si vous recherchez l'adresse 1.1.1.1 dans une base de données IPv4 et que la valeur renvoyée netmask est 16, alors l'adresse appartient au sous-réseau 1.1.0.0/16.

Si la base de données est une base de données IPv6, la valeur renvoyée netmask est toujours un préfixe IPv6 (de 0 à 128), même si cette base de données contient également des réseaux IPv4. Si vous recherchez une adresse IPv4 et que vous souhaitez convertir le netmask en une valeur de sous-réseau IPv4, vous pouvez simplement soustraire 96 de la valeur.

MMDB_result_s

Vous n'avez pas besoin de vous plonger dans cette structure. Elle sera obtenue à partir d'une structure MMDB_lookup_result_s et passée à diverses fonctions.

MMDB_entry_data_s

Cette structure est utilisée pour renvoyer un seul bloc de données associé à une adresse IP. Ces blocs peuvent pointer vers d'autres blocs, comme dans le cas des cartes et des tableaux. Certains membres de cette structure ne sont pas documentés en raison de leur utilisation interne exclusive.

typedef struct MMDB_entry_data_s {
    bool has_data;
    union {
        uint32_t pointer;
        const char *utf8_string;
        double double_value;
        const uint8_t *bytes;
        uint16_t uint16;
        uint32_t uint32;
        int32_t int32;
        uint64_t uint64;
        {mmdb_uint128_t or uint8_t[16]} uint128;
        bool boolean;
        float float_value;
    };
    ...
    uint32_t data_size;
    uint32_t type;
} MMDB_entry_data_s;

Le membre has_data est vrai si des données ont été trouvées pour une recherche donnée. Voir MMDB_get_value() pour plus de détails. Si ce membre est faux, aucune des autres valeurs de la structure n'est significative.

L'union au début de la structure définit les données réelles. Pour déterminer quel membre de l'union est utilisé, vous pouvez vérifier la valeur de has_data.

Mantén toda la estructura del archivo.

Si deseas llenar la estructura, debes ver la propiedad type. La propiedad pointer de la unión nunca debe ser poblada en cualquier datos devueltos por la API. Los punteros deben resolverse internamente.

La propiedad data_size es solo relevante para datos de tipo utf8_string y bytes. utf8_string no es terminada con null y data_size debe usarse para determinar su longitud.

La propiedad type puede compararse con una de las macros MMDB_DATA_TYPE_*.

Entiers 128 bits

La gestión de datos de tipo uint128 depende de cómo tu plataforma soporta los enteros de 128 bits, si lo hace o no. Con GCC 4.4 y 4.5 podemos escribir unsigned int __attribute__ ((__mode__ (TI))). Con versiones más recientes de GCC (4.6+) y clang (3.2+) podemos simplemente escribir "unsigned __int128".

Para trabajar alrededor de estas diferencias, esta biblioteca define un tipo mmdb_uint128_t. Este tipo está definido en el encabezado maxminddb.h, así puedes usarlo en tu código propio.

Con compiladores antiguos no podemos usar un entero, por lo que usamos un arreglo de 16 bytes de uint8_t. Esto es el datos directo de la base de datos.

Esta biblioteca proporciona una macro pública MMDB_UINT128_IS_BYTE_ARRAY. Si esta es verdadera (1), los valores uint128 se devuelven como un arreglo de bytes, si es falsa se devuelven como un entero mmdb_uint128_t.

Macros de Tipo de Dato

Esta biblioteca proporciona una macro para cada tipo de datos definido por el esquema MaxMind DB.

  • MMDB_DATA_TYPE_UTF8_STRING
  • MMDB_DATA_TYPE_DOUBLE
  • MMDB_DATA_TYPE_BYTES
  • MMDB_DATA_TYPE_UINT16
  • MMDB_DATA_TYPE_UINT32
  • MMDB_DATA_TYPE_MAP
  • MMDB_DATA_TYPE_INT32
  • MMDB_DATA_TYPE_UINT64
  • MMDB_DATA_TYPE_UINT128
  • MMDB_DATA_TYPE_ARRAY
  • MMDB_DATA_TYPE_BOOLEAN
  • MMDB_DATA_TYPE_FLOAT

También hay algunos tipos que se usan solo internamente:

  • MMDB_DATA_TYPE_EXTENDED
  • MMDB_DATA_TYPE_POINTER
  • MMDB_DATA_TYPE_CONTAINER
  • MMDB_DATA_TYPE_END_MARKER

Si ves uno de estos en los datos devueltos, algo ha ido muy mal. La base de datos está dañada o fue generada incorrectamente o hay un error en el código de libmaxminddb.

Valores Puntero y MMDB_close()

Los miembros utf8_string, bytes y (puede ser) el miembro uint128 de esta estructura son direcciones directas a la sección de datos de la base de datos. Esto puede ser un bloque calloc o un bloque mmap de memoria. En cualquiera de los casos, estos punteros se invalidarán después de que se llame a MMDB_close().

Si necesitas referirte a este dato después de ese tiempo, debes copiar los datos con una función adecuada (strdup, memcpy, etc.).

MMDB_entry_data_list_s

Esta estructura encapsula una lista enlazada de estructuras MMDB_entry_data_s.

typedef struct MMDB_entry_data_list_s {  
    MMDB_entry_data_s entry_data;  
    struct MMDB_entry_data_list_s *next;  
} MMDB_entry_data_list_s;

Esta estructura te permite ver datos de mapa o arreglo completa iterando sobre la lista enlazada.

MMDB_search_node_s

Esta estructura encapsula los dos registros en un nodo de búsqueda. Esto es realmente útil solo si quieres escribir código que itera por el árbol de búsqueda completo en lugar de buscar un IP específico.

typedef struct MMDB_search_node_s {  
    uint64_t left_record;  
    uint64_t right_record;  
    uint8_t left_record_type;  
    uint8_t right_record_type;  
    MMDB_entry_s left_record_entry;  
    MMDB_entry_s right_record_entry;  
} MMDB_search_node_s;

Los dos tipos de registro tomarán uno de los siguientes valores:

  • MMDB_RECORD_TYPE_SEARCH_NODE - El registro apunta al siguiente nodo de búsqueda.
  • MMDB_RECORD_TYPE_EMPTY - El registro es un placeholder que indica que no hay datos para el IP. El búsqueda debe terminar aquí.
  • MMDB_RECORD_TYPE_DATA - El registro es para datos en la sección de datos de la base de datos. Usa la entrada del registro al buscar los datos del registro.
  • MMDB_RECORD_TYPE_INVALID - El registro es inválido. Esto puede ocurrir por un nodo inválido buscado o por una base de datos corrupta.

El MMDB_entry_s del registro es válido solo si el tipo es MMDB_RECORD_TYPE_DATA. Los intentos de usar un registro para otros tipos de registro generarán un error o datos inválidos.

CÓDIGOS DE ESTADO

Esta biblioteca devuelve (o popula) códigos de estado para muchas funciones. Estos códigos de estado son:

  • MMDB_SUCCESS - todo funcionó
  • MMDB_FILE_OPEN_ERROR - hubo un error al abrir el archivo MaxMind DB.
  • MMDB_IO_ERROR - una operación de I/O falló. Verifica errno para más detalles.
  • MMDB_CORRUPT_SEARCH_TREE_ERROR - al buscar un IP en el árbol de búsqueda se obtuvo un resultado imposible. La base de datos está dañada o fue generada incorrectamente o hay un error en el código de libmaxminddb.
  • MMDB_INVALID_METADATA_ERROR - algo en la base de datos está mal. Esto incluye claves de metadatos ausentes o valores imposibles (como ip_version = 7).
  • MMDB_UNKNOWN_DATABASE_FORMAT_ERROR - la metadata de la base de datos indica que su versión major es 2. Esta biblioteca solo puede manejar versiones major 2.
  • MMDB_OUT_OF_MEMORY_ERROR - falló una llamada a un algoritmo de asignación de memoria (malloc, etc.).
  • MMDB_INVALID_DATA_ERROR - un campo de datos en la sección de datos contiene datos inválidos. Por ejemplo, una uint16 campo afirma ser más de 2 bytes. La base de datos es probablemente dañada o fue generada incorrectamente.
  • MMDB_INVALID_LOOKUP_PATH_ERROR - el camino de búsqueda pasado a MMDB_get_value, MMDB_vget_value, o MMDB_aget_value contiene un desplazamiento de array mayor que LONG_MAX o menor que LONG_MIN.
  • MMDB_LOOKUP_PATH_DOES_NOT_MATCH_DATA_ERROR - el camino de búsqueda pasado a MMDB_get_value, MMDB_vget_value, o MMDB_aget_value no coincide con la estructura de datos para el registro. Pueden ocurrir varias razones. El camino de búsqueda puede incluir un clave no en un mapa. El camino de búsqueda puede incluir un índice de array mayor que un array o menor que el desplazamiento mínimo desde el final de un array. Puede ocurrir cuando el camino espera encontrar un mapa o array donde ninguno exista.

Todos los códigos de estado deben tratarse como valores int.

MMDB_strerror()

const char *MMDB_strerror(int error_code)

Esta función toma un código de estado y devuelve una cadena en inglés explicando el estado.

FUNCIONES

Esta biblioteca proporciona las siguientes funciones exportadas:

MMDB_open()

int MMDB_open(  
    const char *const filename,  
    uint32_t flags,  
    MMDB_s *const mmdb);

Esta función abre un handle a un archivo MaxMind DB. El valor de retorno es un código de estado como definido anteriormente. Siempre verifica el valor de retorno de esta llamada.

MMDB_s mmdb;  
int status =  
    MMDB_open("/path/to/file.mmdb", MMDB_MODE_MMAP, &mmdb);  
if (MMDB_SUCCESS != status) { ... }  
...  
MMDB_close(&mmdb);

El filename debe codificarse como UTF-8 en Windows.

La estructura MMDB_s que pasas puede estar en la pila o alojada en la memoria heap. Sin embargo, si la apertura es exitosa, contendrá datos alojados en la memoria heap, por lo que necesitas cerrarla con MMDB_close(). Si el estado devuelto no es MMDB_SUCCESS, esta biblioteca asegura que todo el espacio de memoria asignado se libere antes de devolverlo.

Los flags actualmente proporcionados son:

•
MMDB_MODE_MMAP - abre el archivo con mmap().

Pasar otros valores para flags puede producir resultados inesperados. En el futuro, podríamos agregar más flags que puedas unir con el modo, así como más modos.

También puedes pasar 0 como valor para flags, en el cual el archivo se abrirá con los flags por defecto. Sin embargo, estos valores por defecto pueden cambiar en futuras versiones. El valor por defecto actual es MMDB_MODE_MMAP.

MMDB_close()

void MMDB_close(MMDB_s *const mmdb);

Esta libera cualquier memoria asignada o mmap'd que se encuentre en la estructura MMDB_s. No libera la memoria del todo.

Toda la estructura del archivo.

MMDB_lookup_string()

MMDB_lookup_result_s MMDB_lookup_string(
    MMDB_s *const mmdb,
    const char *const ipstr,
    int *const gai_error,
    int *const mmdb_error);

Esta fonction recherche une adresse IP fournie sous forme de chaîne terminée par un caractère nul. Elle appelle en interne getaddrinfo() pour résoudre l'adresse sous forme binaire. Elle appelle ensuite MMDB_lookup_sockaddr() pour rechercher l'adresse dans la base de données. Si vous avez déjà résolu une adresse, vous pouvez appeler directement MMDB_lookup_sockaddr() sans avoir à la résoudre deux fois.

int gai_error, mmdb_error;
MMDB_lookup_result_s result =
    MMDB_lookup_string(&mmdb, "1.2.3.4", &gai_error, &mmdb_error);
if (0 != gai_error) { ... }
if (MMDB_SUCCESS != mmdb_error) { ... }
if (result.found_entry) { ... }

Cette fonction retourne toujours une structure MMDB_lookup_result_s, mais vous devez également vérifier les paramètres gai_error et mmdb_error. Si l'un d'eux indique une erreur, la structure retournée sera inutile.

En l'absence d'erreurs, vous devez toujours vous assurer que le membre found_entry de la structure retournée est vrai. Si ce n'est pas le cas, cela signifie que l'adresse IP n'a pas d'entrée dans la base de données.

Cette fonction fonctionne avec les adresses IPv4 même lorsque la base de données contient des données IPv4 et IPv6. L'adresse IPv4 sera recherchée comme ::xxx.xxx.xxx.xxx, et non comme ::ffff:xxx.xxx.xxx.xxx.

Si vous passez une adresse IPv6 à une base de données ne contenant que des données IPv4, le membre found_entry sera faux, mais le statut mmdb_error sera toujours MMDB_SUCCESS.

MMDB_lookup_sockaddr()

MMDB_lookup_result_s MMDB_lookup_sockaddr(
    MMDB_s *const mmdb,
    const struct sockaddr *const sockaddr,
    int *const mmdb_error);

Cette fonction recherche une adresse IP qui a déjà été résolue à l'aide de getaddrinfo().

À part le fait qu'elle n'appelle pas getaddrinfo() elle-même, cette fonction est identique à la fonction MMDB_lookup_string().

int mmdb_error;
MMDB_lookup_result_s result =
    MMDB_lookup_sockaddr(&mmdb, address->ai_addr, &mmdb_error);
if (MMDB_SUCCESS != mmdb_error) { ... }
if (result.found_entry) { ... }

Fonctions de recherche de données

Il existe trois fonctions pour rechercher des données associées à une adresse IP.

int MMDB_get_value(
    MMDB_entry_s *const start,
    MMDB_entry_data_s *const entry_data,
    ...);
int MMDB_vget_value(
    MMDB_entry_s *const start,
    MMDB_entry_data_s *const entry_data,
    va_list va_path);
int MMDB_aget_value(
    MMDB_entry_s *const start,
    MMDB_entry_data_s *const entry_data,
    const char *const *const path);

Les trois fonctions permettent des styles d'appel légèrement différents, mais elles font toutes la même chose.

Le premier paramètre est une valeur MMDB_entry_s. Dans la plupart des cas, cela proviendra de la structure MMDB_lookup_result_s retournée par MMDB_lookup_string() ou MMDB_lookup_sockaddr().

Le deuxième paramètre est une référence à une structure MMDB_entry_data_s. Celle-ci sera remplie avec les données recherchées si des données sont trouvées. Si aucune donnée n'est trouvée, le membre has_data de cette structure sera faux. Si has_data est vrai, vous pouvez consulter le membre data_type.

Le dernier paramètre est un chemin de recherche. Le chemin se compose d'un ensemble de chaînes représentant des clés de mappage (par exemple, "city") ou des index de tableau (par exemple, "0", "1", "-1") à utiliser dans la recherche.

Les index négatifs dans le tableau sont considérés comme un décalage par rapport à la fin du tableau. Par exemple, "-1" fait référence au dernier élément du tableau.

Le chemin de recherche permet de naviguer dans une structure complexe. Par exemple, étant donné ces données :

{
    "names": {
        "en": "Germany",
        "de": "Deutschland"
    },
    "cities": [ "Berlin", "Frankfurt" ]
}

Nous pourrions rechercher le nom en anglais avec le code suivant :

MMDB_lookup_result_s result =
    MMDB_lookup_sockaddr(&mmdb, address->ai_addr, &mmdb_error);
MMDB_entry_data_s entry_data;
int status =
    MMDB_get_value(&result.entry, &entry_data,
                   "names", "en", NULL);
if (MMDB_SUCCESS != status) { ... }
if (entry_data.has_data) { ... }

Si nous voulons trouver la première ville, le chemin de recherche serait "cities", "0". Si vous ne fournissez pas de chemin de recherche, vous obtiendrez l'entrée correspondant au mappage de niveau supérieur. Le chemin de recherche doit toujours se terminer par "NULL", quelle que soit la fonction que vous utilisez.

La fonction MMDB_get_value accepte un nombre variable d'arguments. Tous les arguments après le pointeur vers la structure MMDB_entry_data_s constituent le chemin de recherche. Le dernier argument doit être "NULL".

La fonction MMDB_vget_value accepte une va_list comme chemin de recherche. Le dernier élément récupéré par va_arg() doit être "NULL".

Enfin, la fonction MMDB_aget_value accepte un tableau de chaînes comme chemin de recherche. Le dernier élément de ce tableau doit être "NULL".

Si vous souhaitez obtenir toutes les données d'une entrée en une seule fois, vous pouvez appeler MMDB_get_entry_data_list().

Pour chacune des trois fonctions, la valeur de retour est un code d'état tel que défini ci-dessus.

MMDB_get_entry_data_list()

int MMDB_get_entry_data_list(
    MMDB_entry_s *start,
    MMDB_entry_data_list_s **const entry_data_list);

Cette fonction vous permet d'obtenir toutes les données d'une structure complexe en une seule fois, au lieu de rechercher chaque partie par des appels répétés à MMDB_get_value().

MMDB_lookup_result_s result =
    MMDB_lookup_sockaddr(&mmdb, address->ai_addr, &mmdb_error);
MMDB_entry_data_list_s *entry_data_list, *first;
int status =
    MMDB_get_entry_data_list(&result.entry, &entry_data_list);
if (MMDB_SUCCESS != status) { ... }
// sauvegarder cette structure pour pouvoir la libérer plus tard
first = entry_data_list;
while (1) {
    MMDB_entry_data_list_s *next = entry_data_list = entry_data_list->next;
    if (NULL == next) {
        break;
    }
    switch (next->entry_data.type) {
        case MMDB_DATA_TYPE_MAP: { ... }
        case MMDB_DATA_TYPE_UTF8_STRING: { ... }
        ...
    }
}
MMDB_free_entry_data_list(first);

Il est de votre responsabilité d'interpréter la structure entry_data_list. La liste est chaînée dans un parcours en profondeur. Nous utiliserons cette structure comme exemple :

{
    "names": {
        "en": "Germany",
        "de": "Deutschland"
    },
    "cities": [ "Berlin", "Frankfurt" ]
}

La liste contiendra les éléments suivants :

1.
MAP - mappage de niveau supérieur
2.

MMDB_free_entry_data_list()

void MMDB_free_entry_data_list(
    MMDB_entry_data_list_s *const entry_data_list);

Les fonctions MMDB_get_entry_data_list() et MMDB_get_metadata_as_entry_data_list() allouent la structure de liste chaînée dans la mémoire du tas. Appelez cette fonction pour libérer la structure MMDB_entry_data_list_s.

MMDB_get_metadata_as_entry_data_list()

int MMDB_get_metadata_as_entry_data_list(
    MMDB_s *const mmdb,
    MMDB_entry_data_list_s **const entry_data_list);

Cette fonction vous permet de récupérer les métadonnées de la base de données sous forme de liste chaînée de structures MMDB_entry_data_list_s. Cela peut être une manière plus pratique de gérer les métadonnées que d'utiliser directement la structure.

    MMDB_entry_data_list_s *entry_data_list, *first;
    int status =
        MMDB_get_metadata_as_entry_data_list(&mmdb, &entry_data_list);
    if (MMDB_SUCCESS != status) { ... }
    first = entry_data_list;
    ... // faire quelque chose avec les données
    MMDB_free_entry_data_list(first);

La valeur de retour est un code d'état tel que défini ci-dessus.

MMDB_dump_entry_data_list()

int MMDB_dump_entry_data_list(
    FILE *const stream,
    MMDB_entry_data_list_s *const entry_data_list,
    int indent);

Cette fonction prend une liste chaînée de structures MMDB_entry_data_list_s et la sérialise dans le fichier stream. Le paramètre indent est le niveau d'indentation initial pour la sortie générée. Il est incrémenté pour les structures imbriquées (cartes, tableaux, etc.).

Le stream doit être un fichier (par exemple, stdout). Si votre plateforme fournit quelque chose comme open_memstream() de GNU, vous pouvez l'utiliser pour capturer la sortie sous forme de chaîne.

La sortie est formatée de manière similaire au JSON, mais les valeurs sont marquées avec leur type de données (sauf pour les cartes et les tableaux qui sont affichés comme "{}" et "[]").

Le format de sortie spécifique peut changer dans les futures versions.

MMDB_read_node()

SYNTAXIS

int MMDB_read_node(
    MMDB_s *const mmdb,
    uint32_t node_number,
    MMDB_search_node_s *const node);

DESCRIPTION

Cette fonction lit un nœud spécifique dans l'arbre de recherche. Le troisième argument est une référence à une structure MMDB_search_node_s qui sera remplie par cette fonction.

STRUCTURES DE DONNÉES

La valeur de retour de la fonction est un code d'état tel que défini ci-dessus.

CODES D'ÉTAT

La fonction renvoie un code d'état. Si un node_number supérieur au nombre de nœuds dans la base de données est passé, cette fonction retournera MMDB_INVALID_NODE_NUMBER_ERROR, sinon elle retournera MMDB_SUCCESS.

FONCTIONS

Le premier nœud dans l'arbre de recherche est toujours le nœud 0. Si vous souhaitez parcourir l'intégralité de l'arbre de recherche, vous devez lire le nœud 0, puis suivre les enregistrements qui composent ce nœud, en fonction du type de chaque enregistrement. Si le type est MMDB_RECORD_TYPE_SEARCH_NODE, l'enregistrement contient un entier pour le nœud suivant à rechercher.

EXEMPLE

#include <errno.h>
#include <maxminddb.h>
#include <stdlib.h>
#include <string.h>
int main(int argc, char **argv)
{
    char *filename = argv[1];
    char *ip_address = argv[2];
    MMDB_s mmdb;
    int status = MMDB_open(filename, MMDB_MODE_MMAP, &mmdb);
    if (MMDB_SUCCESS != status) {
        fprintf(stderr, "\n  Can't open %s - %s\n",
                filename, MMDB_strerror(status));
        if (MMDB_IO_ERROR == status) {
            fprintf(stderr, "    IO error: %s\n", strerror(errno));
        }
        exit(1);
    }
    int gai_error, mmdb_error;
    MMDB_lookup_result_s result =
        MMDB_lookup_string(&mmdb, ip_address, &gai_error, &mmdb_error);
    if (0 != gai_error) {
        fprintf(stderr,
                "\n  Error from getaddrinfo for %s - %s\n\n",
                ip_address, gai_strerror(gai_error));
        exit(2);
    }
    if (MMDB_SUCCESS != mmdb_error) {
        fprintf(stderr,
                "\n  Got an error from libmaxminddb: %s\n\n",
                MMDB_strerror(mmdb_error));
        exit(3);
    }
    MMDB_entry_data_list_s *entry_data_list = NULL;
    int exit_code = 0;
    if (result.found_entry) {
        int status = MMDB_get_entry_data_list(&result.entry,
                                              &entry_data_list);
        if (MMDB_SUCCESS != status) {
            fprintf(
                stderr,
                "Got an error looking up the entry data - %s\n",
                MMDB_strerror(status));
            exit_code = 4;
            goto end;
        }
        if (NULL != entry_data_list) {
            MMDB_dump_entry_data_list(stdout, entry_data_list, 2);
        }
    } else {
        fprintf(
            stderr,
            "\n  No entry for this IP address (%s) was found\n\n",
            ip_address);
        exit_code = 5;
    }
    end:
        MMDB_free_entry_data_list(entry_data_list);
        MMDB_close(&mmdb);
        exit(exit_code);
}
