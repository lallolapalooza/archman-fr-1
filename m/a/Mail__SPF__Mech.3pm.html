Mail::SPF::Mech(3) Documentation Perl fournie par l'utilisateur Mail::SPF::Mech(3)

NOM

Mail::SPF::Mech - classe de base des mécanismes d'enregistrement SPF

VERSION

version 3.20250505

DESCRIPTION

Un objet de la classe Mail::SPF::Mech représente un mécanisme dans un enregistrement SPF. Mail::SPF::Mech ne peut pas être instancié directement. Créez plutôt une instance d'une sous-classe concrète.

Constructeurs

Les constructeurs suivants sont fournis :

new(%options) : retourne Mail::SPF::Mech
Abstrait. Crée un nouvel objet mécanisme d'enregistrement SPF.

%options est une liste de paires clé/valeur représentant l'une des options suivantes :

text
Une chaîne indiquant le texte non analysé du mécanisme.
qualifier
Un chaîne d'un seul caractère indiquant le qualificateur du mécanisme. L'un des éléments suivants peut être spécifié : '+' ("Pass"), '-' ("Fail"), '~' ("SoftFail"), '?' ("Neutral"). Voir RFC 4408, 4.6.2 et 2.5, pour leur signification. La valeur par défaut est '+'.
name
Une chaîne indiquant le nom du mécanisme. Requis si un objet Mail::SPF::Mech générique (par opposition à une sous-classe spécifique) est en cours de construction.
ip_network
Un objet NetAddr::IP indiquant un paramètre de réseau d'adresse IP facultatif du mécanisme. Peut être une adresse IPv4 ou IPv6, avec un préfixe de réseau facultatif. Les adresses IPv6 mappées IPv4 (par exemple, '::ffff:192.168.0.1') ne doivent pas être spécifiées directement, mais comme des adresses IPv4 simples.
domain_spec
Soit une chaîne simple, soit un objet Mail::SPF::MacroString indiquant un paramètre "domain-spec" facultatif du mécanisme.
ipv4_prefix_length
ipv6_prefix_length
Une chaîne indiquant une longueur de préfixe de réseau IPv4 ou IPv6 facultative pour le "domain_spec" du mécanisme. Notez que ces options ne s'appliquent pas à l'option "ip_network", qui inclut déjà une longueur de préfixe de réseau facultative.

D'autres options peuvent être spécifiées par des sous-classes de Mail::SPF::Mech.

new_from_string($text, %options) : retourne Mail::SPF::Mech ; lève Mail::SPF::ENothingToParse, Mail::SPF::EInvalidMech
Abstrait. Crée un nouvel objet mécanisme d'enregistrement SPF en analysant la chaîne et les options fournies.

Méthodes de classe

Les méthodes de classe suivantes sont fournies :

default_qualifier : retourne chaîne
Retourne le qualificateur par défaut, c'est-à-dire '+'.
default_ipv4_prefix_length : retourne entier
Retourne la longueur de préfixe de réseau IPv4 par défaut, c'est-à-dire 32.
default_ipv6_prefix_length : retourne entier
Retourne la longueur de préfixe de réseau IPv6 par défaut, c'est-à-dire 128.
qualifier_pattern : retourne Regexp
Retourne une expression régulière qui correspond à tout qualificateur de mécanisme légal, c'est-à-dire '+', '-', '~', ou '?'.
name : retourne chaîne
Abstrait. Retourne le nom du mécanisme.

Cette méthode est abstraite et doit être implémentée par les sous-classes de Mail::SPF::Mech.

name_pattern : retourne Regexp
Retourne une expression régulière qui correspond à tout nom de mécanisme légal.

Méthodes d'instance

Les méthodes d'instance suivantes sont fournies :

text : retourne chaîne ; lève Mail::SPF::ENoUnparsedText
Retourne le texte non analysé du mécanisme. Lève une exception Mail::SPF::ENoUnparsedText si le mécanisme a été créé synthétiquement au lieu d'être analysé, et qu'aucun texte n'a été fourni.
qualifier : retourne chaîne
Retourne le qualificateur du mécanisme. Voir la description de l'option "qualifier" du constructeur "new".
params : retourne chaîne
Abstrait. Retourne les paramètres du mécanisme formatés sous forme de chaîne.

Une sous-classe de Mail::SPF::Mech n'a pas à implémenter cette méthode si elle ne supporte aucun paramètre.

stringify : retourne chaîne
Formate le qualificateur, le nom et les paramètres du mécanisme en une chaîne et la retourne. (Un qualificateur correspondant à la valeur par défaut de '+' est omis.) Vous pouvez simplement utiliser un objet Mail::SPF::Mech comme une chaîne pour le même effet, voir "OVERLOADING".
domain($server, $request) : retourne chaîne
Retourne le domaine cible du mécanisme. Selon que le mécanisme ait ou non un paramètre explicite "domain_spec", il s'agit soit du paramètre "domain_spec" macro-étendu, soit du domaine d'autorité de la requête (voir "authority_domain" dans Mail::SPF::Request) sinon. Un objet Mail::SPF::Server et un objet Mail::SPF::Request sont nécessaires pour résoudre le domaine cible.
match($server, $request) : retourne booléen ; lève Mail::SPF::Result::Error
Abstrait. Vérifie si le mécanisme correspond aux paramètres de la requête donnée (voir Mail::SPF::Request) et retourne true s'il correspond, ou false sinon. Dans tous les cas, prend un objet Mail::SPF::Server et un objet Mail::SPF::Request.

Cette méthode est abstraite et doit être implémentée par les sous-classes de Mail::SPF::Mech.

match_in_domain($server, $request) : retourne booléen ; lève Mail::SPF::Result::Error
match_in_domain($server, $request, $domain) : retourne booléen ; lève Mail::SPF::Result::Error
Vérifie si le nom de domaine cible du mécanisme (c'est-à-dire l'un de ses enregistrements DNS "A" ou "AAAA") correspond à l'adresse IP de la requête donnée (voir "ip_address" dans Mail::SPF::Request), et retourne true si c'est le cas, ou false sinon. Si un domaine explicite est spécifié, il est utilisé à la place du domaine cible du mécanisme. Les longueurs de préfixe de réseau IP du mécanisme sont respectées lors de la comparaison des enregistrements d'adresse DNS avec l'adresse IP de la requête. Voir RFC 4408, 5, pour l'algorithme exact utilisé.

Cette méthode existe principalement pour la commodité des sous-classes de Mail::SPF::Mech.

explain($server, $request): returns string; throws Mail::SPF::Result::Error
Abstrait. Retourne une explication du résultat de la correspondance du mécanisme.

Cette méthode est abstraite et doit être implémentée par les sous-classes de Mail::SPF::Mech.

OVERLOADING

L'opérateur de conversion en chaîne est surchargé pour appeler la méthode stringify.

DIAGNOSTICS

Les exceptions suivantes peuvent être levées :

Mail::SPF::ENothingToParse
Aucune chaîne n'a été fournie à new_from_string().
Mail::SPF::EInvalidMech
La chaîne fournie à new_from_string() n'a pas pu être analysée comme un mécanisme SPF valide.
Mail::SPF::ENoUnparsedText
Tentative d'appeler la méthode text() sur un objet qui n'a pas été créé à partir d'une chaîne.
Mail::SPF::Result::Error
Une erreur s'est produite lors de la tentative de faire correspondre un mécanisme à une requête.

EXEMPLE

```perl
use Mail::SPF;

my $mech = Mail::SPF::Mech->new(
text => 'a',
qualifier => '+',
name => 'a',
);

print $mech->stringify; # Produit "a"

my $spf_record = 'v=spf1 a mx ip4:192.168.0.0/16 ~all';
my $parser = Mail::SPF::Parser->new();
my $record = $parser->parse($spf_record);

foreach my $mech (@{$record->mechanisms}) {
print $mech, "\n";
}
# Produit :
# a
# mx
# ip4:192.168.0.0/16
# ~all
```

rver,">explain($server, $request, $result)
Génère localement une explication de la raison pour laquelle le mécanisme a provoqué le résultat donné, et la stocke dans l'état de l'objet de requête donné.

Il n'est pas nécessaire de remplacer cette méthode dans les sous-classes. Voir la méthode "explanation_template".

explanation_template($server, $request, $result): retourne string
Retourne un modèle de chaîne de caractères macro pour une explication générée localement de la raison pour laquelle le mécanisme a provoqué l'objet de résultat donné.

Les sous-classes doivent soit définir une constante de hachage "explanation_templates_by_result_code" avec leurs propres modèles, soit remplacer cette méthode.

SOBRECHARGE

Si un objet Mail::SPF::Mech est utilisé comme une chaîne de caractères, la méthode "stringify" est utilisée pour convertir l'objet en une chaîne de caractères.
