NAME

Mail::SPF::Query - Interroger le système de politique d'expédition (SPF) pour une adresse IP, un courriel, HELO

VERSION

1.999.1

SYNOPSIS

my $query = new Mail::SPF::Query (ip => "127.0.0.1", sender=>'foo@example.com', helo=>"somehost.example.com", trusted=>0, guess=>0);
my ($result,           # pass | fail | softfail | neutral | none | error | unknown [mechanism]
    $smtp_comment,     # "please see http://www.openspf.org/why.html?..."  when rejecting, return this string to the SMTP client
    $header_comment,   # prepend_header("Received-SPF" => "$result ($header_comment)")
    $spf_record,       # "v=spf1 ..." original SPF record for the domain
   ) = $query->result();
if    ($result eq "pass") { "Le domaine n'est pas usurpé. Appliquer le filtrage RHSBL et de contenu." }
elsif ($result eq "fail") { "Le domaine est usurpé. Rejeter ou mettre dans la boîte de spam." }

ABSTRACT

Le protocole SPF repose sur les domaines d'expédition pour décrire leurs expéditeurs désignés dans le DNS. Étant donné une adresse de courriel, Mail::SPF::Query détermine la légitimité d'une adresse IP du client SMTP.

DESCRIPTION

Il existe deux manières d'utiliser Mail::SPF::Query. Votre choix dépend si le domaine pour lequel votre serveur est un serveur MX a des serveurs MX secondaires que votre serveur ne connaît pas.

La première et la plus courante, en appelant result(), convient lorsque tout le courrier est reçu directement de l'expéditeur MTA. Si les domaines que vous recevez n'ont pas de serveurs MX secondaires, cette méthode convient. Cette méthode est décrite dans le SYNOPSIS ci-dessus. C'est la situation la plus courante.

La seconde méthode est plus complexe, mais fonctionne lorsque votre serveur reçoit du courrier de serveurs MX secondaires. Elle effectue des vérifications lors du traitement de chaque destinataire. Si le message provient d'un serveur MX secondaire valide pour un destinataire, alors la vérification SPF n'est pas effectuée et un résultat pass est immédiatement renvoyé. Pour ce faire, appelez result2() et message_result2() au lieu de result().

Si vous ne savez pas ce qu'est un serveur MX secondaire, vous n'en avez probablement pas. Utilisez la première méthode.

Vous pouvez tester Mail::SPF::Query en ligne de commande avec la commande suivante :

perl -MMail::SPF::Query -le 'print for Mail::SPF::Query->new(
    helo => shift, ipv4 => shift, sender => shift)->result' \
    helohost.example.com 1.2.3.4 user@example.com

BUGS

Mail::SPF::Query tente d'implémenter le schéma SPF (voir "SEE ALSO") aussi fidèlement que possible, étant donné que M:S:Q a été la première implémentation SPF et a évolué avec le schéma SPF au fil du temps. Par conséquent, M:S:Q présente divers défauts connus qui ne peuvent pas être corrigés avec un effort raisonnable :

  • Impossible d'interroger HELO et MAIL FROM séparément. M:S:Q n'est pas conçu pour supporter l'interrogation *séparée* des identités HELO et MAIL FROM. Passer l'identité HELO comme argument "sender" pour une vérification HELO peut généralement fonctionner mais peut produire des résultats inattendus.
  • Pas de support pour IPv6. IPv6 n'est pas supporté. Les mécanismes "ip6" dans les enregistrements SPF et partout ailleurs sont simplement ignorés.
  • L'explication des résultats peut ne pas être adéquate pour les résultats de politique locale. Si le résultat a été causé par quelque chose d'autre qu'un enregistrement SPF réel (c'est-à-dire une politique locale, des substitutions, etc.) et qu'aucune valeur "default_explanation" personnalisée n'a été spécifiée, le commentaire du domaine ou l'explication par défaut de M:S:Q sera renvoyé. Notez que dans ce cas, le commentaire peut ne pas expliquer correctement la raison de ce résultat artificiel.

FONCTIONNALITÉS NON STANDARD

En raison de sa longue histoire, M:S:Q possède certaines fonctionnalités obsolètes qui ne font pas partie du schéma SPF officiel, principalement le *traitement de meilleure supposition* et la *vérification des identifiants des expéditeurs de confiance*. Veuillez faire preuve de prudence lorsque vous utilisez ces *fonctionnalités non standard* ou lorsque vous les reproduisez dans votre propre implémentation SPF, car elles peuvent produire des résultats inattendus.

MÉTHODES

"Mail::SPF::Query->new()"

my $query = eval { new Mail::SPF::Query (
    ip          => '127.0.0.1',
    sender      => 'foo@example.com',
    helo        => 'host.example.com',
    # Paramètres optionnels :
    debug       => 1, debuglog => sub { print STDERR "@_\n" },
    local       => 'include:extra mechanisms',
    trusted     => 1,                   # traitement des expéditeurs de confiance
    guess       => 1,                   # traitement de meilleure supposition s'il n'y a pas d'enregistrement SPF
    default_explanation => 'Please see http://spf.my.isp/spferror.html for details',
    max_lookup_count    => 10,          # nombre total d'includes/redirects
    sanitize    => 0,                   # ne pas nettoyer toutes les chaînes retournées
    myhostname  => 'foo.example.com',   # préfixé à header_comment
    override    => {   'example.net' => 'v=spf1 a mx -all',
                     '*.example.net' => 'v=spf1 a mx -all' },
    fallback    => {   'example.org' => 'v=spf1 a mx -all',
                     '*.example.org' => 'v=spf1 a mx -all' }
) };
if ($@) { warn "mauvaise entrée pour Mail::SPF::Query: $@" }

Définissez "trusted=>1" pour activer la vérification des identifiants "spf.trusted-forwarder.org". Le mécanisme "include:spf.trusted-forwarder.org" est utilisé juste avant un "-all" ou "?all". Les circonstances précises sont un peu plus complexes, mais le cas "v=spf1 -all" est bien géré — c'est-à-dire que "spf.trusted-forwarder.org" n'est pas vérifié. C'est une fonctionnalité non standard.

Définissez "guess=>1" pour activer le traitement automatique de meilleure supposition. Il utilisera l'enregistrement SPF de meilleure supposition lorsqu'il ne peut pas en trouver dans le DNS. Notez qu'il ne peut renvoyer que "pass" ou "neutral". Les indicateurs "trusted" et "local" fonctionnent également lors de l'utilisation de la "best_guess". C'est une fonctionnalité non standard.

Définissez "local=>'include:local.domain'" pour inclure un traitement supplémentaire avant un "-all" ou "?all". Le traitement local se produit juste avant le traitement des expéditeurs de confiance. C'est une fonctionnalité non standard.

Définissez "default_explanation" à une chaîne qui sera utilisée s'il n'y a pas d'explication spécifique dans l'enregistrement SPF. La valeur par défaut dirige l'utilisateur vers une page sur www.openspf.org avec le message suivant :

Please see http://www.openspf.org/why.html?sender=%{S}&ip=%{I}&receiver=%{R}

Note : Les noms de domaine des arguments dans override et fallback doivent être en minuscules.

Définissez "sanitize" à 0 pour ne pas nettoyer toutes les chaînes retournées. Alternativement, passez une référence de fonction et cette fonction sera utilisée pour nettoyer les valeurs retournées. La fonction doit prendre un seul argument et renvoyer une chaîne contenant le résultat nettoyé.

Définissez "debug=>1" pour voir les requêtes.

Définissez "override" pour définir des enregistrements SPF pour des domaines qui publient mais que vous souhaitez quand même remplacer. Les caractères génériques sont pris en charge. C'est une fonctionnalité non standard.

Définissez "fallback" pour définir des enregistrements SPF fictifs pour des domaines qui ne publient pas encore. Les caractères génériques sont pris en charge. C'est une fonctionnalité non standard.

Note : Les noms de domaine des arguments dans override et fallback doivent être en minuscules.

my ($result,           # pass | fail | softfail | neutral | none | error | unknown [mechanism]
    $smtp_comment,     # "please see http://www.openspf.org/why.html?..."  when rejecting, return this string to the SMTP client
    $header_comment,   # prepend_header("Received-SPF" => "$result ($header_comment)")
    $spf_record,       # "v=spf1 ..." original SPF record for the domain
   ) = $query->result();

C'est la façon courante d'utiliser, où result() est appelé pour obtenir le résultat SPF.

()&quot;'>"$query->result()" 
my ($result, $smtp_comment, $header_comment, $spf_record, $detail) = $query->result();

$result sera l'une des valeurs suivantes : "pass", "fail", "softfail", "neutral", "none", "error" ou "unknown [...]" :

"pass"
L'adresse IP du client est un expéditeur de courrier autorisé pour le domaine de l'expéditeur. Le courrier doit être accepté sous réserve de la politique locale concernant l'expéditeur.
"fail"
L'adresse IP du client n'est pas un expéditeur autorisé, et l'expéditeur souhaite que vous rejetiez la transaction par crainte de falsification.
"softfail"
L'adresse IP du client n'est pas un expéditeur autorisé, mais l'expéditeur préfère que vous acceptiez la transaction car il n'est pas absolument certain que tous ses utilisateurs envoient des e-mails via des serveurs approuvés. Le statut "softfail" est souvent utilisé lors du déploiement initial des enregistrements SPF par un domaine.
"neutral"
L'expéditeur ne fait aucune déclaration concernant le statut de l'adresse IP du client.
"none"
Il n'y a pas d'enregistrement SPF pour ce domaine.
"error"
La recherche DNS a rencontré une erreur temporaire pendant le traitement.
"unknown [...]"
Le domaine a une erreur de configuration dans les données publiées ou définit un mécanisme que cette bibliothèque ne comprend pas. Si les données contenaient un mécanisme non reconnu, il sera présenté après "unknown". Vous devriez tester pour unknown en utilisant une expression régulière "/^unknown/" plutôt que "eq "unknown"".

Les résultats sont mis en cache en interne pendant une durée par défaut de 120 secondes. Vous pouvez appeler "->result()" de manière répétée ; les recherches ultérieures n'atteindront pas votre DNS.

"smtp_comment" doit être affiché au client SMTP.

"header_comment" va dans un en-tête "Received-SPF", comme ceci :

Received-SPF: $result ($header_comment)

"spf_record" montre l'enregistrement SPF original récupéré pour la requête. S'il n'y a pas d'enregistrement SPF, il est vide. Sinon, il commencera par "v=spf1" et contiendra les mécanismes SPF et autres qui décrivent le domaine.

Notez que les chaînes retournées par cette méthode (et la plupart des autres méthodes) sont (au moins partiellement) sous le contrôle du domaine de l'expéditeur. Cela signifie que, si l'expéditeur est un attaquant, le contenu peut être considéré comme malveillant. Les différentes méthodes qui retournent ces chaînes s'assurent que (par défaut) les chaînes retournées ne contiennent que des caractères dans la plage 32 - 126. Ce comportement peut être modifié en réglant "sanitize" sur 0 pour désactiver complètement la sanitisation. Vous pouvez également régler "sanitize" sur une référence de fonction pour effectuer une sanitisation personnalisée. En particulier, supposez que "smtp_comment" puisse contenir un caractère de nouvelle ligne.

"detail" est une table de hachage de tous les éléments de résultat précédents, plus des données supplémentaires renvoyées par le résultat SPF.

Pourquoi cette duplication étrange ? Au début, result() ne retournait qu'une seule valeur, le $result. Ensuite, $smtp_comment et $header_comment sont arrivés. Puis $spf_record. Au-delà d'un certain nombre de résultats positionnels, il est plus logique d'avoir une table de hachage. Mais nous ne voulions pas casser la compatibilité ascendante, alors nous avons simplement déclaré que le cinquième résultat serait une table de hachage et que les retours futurs y seraient placés.

Les clés de la table de hachage sont :

result
smtp_comment
header_comment
header_pairs
spf_record
modifiers

"$query->result2()"

my ($result, $smtp_comment, $header_comment, $spf_record) = $query->result2('recipient@domain', 'recipient2@domain');

result2() fait tout ce que result() fait, mais il vérifie d'abord si le système d'envoi est un serveur MX secondaire reconnu pour le(s) destinataire(s). Si c'est le cas, il renvoie "pass" et n'effectue pas la requête SPF. Notez que le système d'envoi peut être un serveur MX secondaire pour certains (mais pas tous) des destinataires d'un message à multiples destinataires, c'est pourquoi result2 accepte une liste d'arguments. Voir aussi message_result2().

Ceci est une fonctionnalité non standard. Cette fonctionnalité est également obsolète, car l'exemption des relais de confiance, tels que les serveurs MX secondaires, devrait réellement être effectuée par le logiciel qui utilise cette bibliothèque avant d'effectuer un test SPF.

$result sera l'une des valeurs suivantes : "pass", "fail", "neutral [...]", ou "unknown". Voir result() ci-dessus pour les significations.

Si vous avez des serveurs MX secondaires et si vous ne pouvez pas les ajouter explicitement à la liste blanche avant que les tests SPF n'aient lieu, vous pouvez utiliser cette méthode à la place de result(), en l'appelant autant de fois qu'il y a de destinataires, ou simplement en fournissant tous les destinataires à la fois.

"smtp_comment" peut être affiché au client SMTP.

Par exemple :

my $query = new Mail::SPF::Query (ip => "127.0.0.1",
                                  sender=>'foo@example.com',
                                  helo=>"somehost.example.com");
...
my ($result, $smtp_comment, $header_comment);
($result, $smtp_comment, $header_comment) = $query->result2('recip1@example.com');
# renvoyer un code d'erreur approprié basé sur $result eq 'fail' ou non
($result, $smtp_comment, $header_comment) = $query->result2('recip2@example.org');
# renvoyer un code d'erreur approprié basé sur $result eq 'fail' ou non
($result, $smtp_comment, $header_comment) = $query->message_result2();
# renvoyer une erreur appropriée si $result eq 'fail'
# préfixer le message avec "Received-SPF: $result ($header_comment)"

"$query->message_result2()"

my ($result, $smtp_comment, $header_comment, $spf_record) = $query->message_result2();

message_result2() renvoie un statut global pour le message après zéro ou plusieurs appels à result2(). Ce sera toujours le dernier statut renvoyé par result2(), ou le statut renvoyé par result() si result2() n'a jamais été appelé.

$result sera l'une des valeurs suivantes : "pass", "fail", "neutral [...]", ou "error". Voir result() ci-dessus pour les significations.

"$query->best_guess()"

my ($result, $smtp_comment, $header_comment) = $query->best_guess();

Lorsqu'un domaine ne publie pas d'enregistrement SPF, cette bibliothèque peut produire une supposition éclairée.

Elle fait semblant que le domaine a défini des mécanismes A, MX et PTR, ainsi que quelques autres. L'ensemble par défaut de directives est

a/24 mx/24 ptr

Cet ensemble par défaut renverra soit "pass" soit "neutral".

Si vous souhaitez expérimenter avec un autre défaut, vous pouvez le passer comme argument : "$query->best_guess("a mx ptr")"

Ceci est une fonctionnalité non standard. Cette méthode est également obsolète. Vous devriez plutôt définir "guess=>1" sur la méthode new().

"$query->trusted_forwarder()"

my ($result, $smtp_comment, $header_comment) = $query->best_guess();

Il est possible que le message provienne d'un relais connu comme fiable comme "acm.org" ou "pobox.com". Pendant la période de transition, de nombreux services légitimes peuvent apparaître comme falsifiant une adresse d'expéditeur : par exemple, un site d'actualités peut avoir un lien "envoyez-moi cet article par e-mail".

Le domaine "trusted-forwarder.org" est une liste blanche d'hôtes connus qui transmettent des e-mails ou effectuent une falsification bénigne de l'expéditeur de l'enveloppe :

include:spf.trusted-forwarder.org

Ceci renverra soit "pass" soit "neutral".

Ceci est une fonctionnalité non standard. Cette méthode est également obsolète. Vous devriez plutôt définir "trusted=>1" sur la méthode new().

"$query->sanitize('string')"

Ceci applique les règles de sanitisation pour l'objet de requête particulier. Ces règles sont contrôlées par le paramètre "sanitize" de la méthode c<new()>.

strict_sanitize('string')

Ceci garantit que tous les caractères de la chaîne retournée sont imprimables. Tous les espaces blancs sont convertis en espaces, et tous les autres caractères non imprimables sont convertis en points d'interrogation. Ceci est probablement trop agressif pour de nombreuses applications.

Cette fonction est utilisée par défaut lorsque l'option "sanitize" est passée à la méthode new().

Cette fonction n'est pas une méthode de classe.

AVERTISSEMENTS

Mail::Query::SPF ne devrait être utilisé qu'au moment où les messages sont reçus d'Internet. L'hypothèse sous-jacente est que l'expéditeur de l'e-mail vous envoie le message directement, ou à l'un de vos serveurs MX secondaires. Si votre MTA ne dispose pas d'une liste exhaustive des serveurs MX secondaires, alors les méthodes result2() et message_result2() peuvent être utilisées. Ces méthodes prennent soin de permettre le courrier provenant des serveurs MX secondaires.
