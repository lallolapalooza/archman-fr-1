NOM

Mail::Message::Construct::Rebuild - modifier un Mail::Message

SYNOPSIS

my $cleanup = $msg->rebuild;

DESCRIPTION

Modifier des messages existants est une corvée, surtout si cela doit être fait de manière automatisée. Les problèmes sont particulièrement nombreux lorsque des multipartes doivent être créées ou supprimées. La méthode rebuild() tente de simplifier cette tâche et d'ajouter quelques fonctionnalités standard.

MÉTHODES

Construction d'un message

$obj->rebuild(%options)
Reconstruit un message existant pour en créer un nouveau. Renvoie un nouveau message si des modifications ont été apportées, "undef" si le message n'a plus de corps, ou le message original si aucune modification n'a dû être apportée.

Exemples d'utilisation : vous avez un message contenant uniquement du HTML et vous souhaitez le traduire en un message multiple qui contient le HTML original et sa traduction textuelle. Ou bien, vous avez un message avec des parties marquées pour suppression, et vous souhaitez que ces modifications soient intégrées à la structure en mémoire. Une autre possibilité : supprimer tous les groupes de renvoi (voir Mail::Message::Head::ResentGroup) de l'en-tête, avant qu'il ne soit écrit dans un fichier.

La reconstruction est une tâche délicate, où interviennent des multipartes à plusieurs niveaux et des messages imbriqués. La méthode rebuild essaie de vous simplifier la gestion de ces messages.

-Option         --Défaut
 extra_rules      []
 keep_message_id  false
 rules            <voir texte>
extra_rules => ARRAY
L'ensemble standard de règles, qui est le défaut pour l'option "rules", est un réglage modéré. Au lieu de copier cette liste dans un ensemble complet de règles pour votre compte, vous pouvez également spécifier uniquement quelques règles supplémentaires qui seront ajoutées en tête de l'ensemble de règles par défaut.

L'ordre des règles est respecté, ce qui signifie que vous n'avez pas toujours besoin de réécrire la règle entière (voir l'option "rule"). Par exemple, la règle supplémentaire de "removeDeletedParts" renvoie un "undef", ce qui signifie qu'elle annule l'effet de la règle par défaut "replaceDeletedParts".

keep_message_id => BOOLEAN
L'identifiant de message (message-id) est une identification unique du message : aucun message différent ne doit exister simultanément. Cependant, en pratique, lorsqu'un message est modifié lors de sa transmission, l'ID est souvent, à tort, pas modifié. Cela peut entraîner des complications dans les applications qui voient les deux messages avec le même ID.
rules => ARRAY
L'ARRAY est une liste de règles, chacune décrivant une action qui sera appelée sur chaque partie trouvée dans le message. La plupart des règles ne correspondront probablement pas, mais certaines apporteront des modifications au contenu. Les règles peuvent être spécifiées comme un nom de méthode, ou comme une référence de code. Voir le chapitre "DETAILS" de cette page de manuel et recursiveRebuildPart().

Par défaut, seules les transformations relativement sûres sont effectuées : "replaceDeletedParts", "descendMultiparts", "descendNested", "flattenMultiparts", "flattenEmptyMultiparts". À l'avenir, d'autres transformations sûres pourront être ajoutées à cette liste.

» exemple:

# supprime toutes les parties supprimées
my $cleaned = $msg->rebuild(keep_message_id => 1);
$folder->addMessage($cleaned) if defined $cleaned;
# Remplace les parties supprimées par un espace réservé
my $cleaned = $msg->rebuild(
  keep_message_id => 1,
  extra_rules => [ 'removeEmpty', 'flattenMultiparts' ],
);

Internes

$obj->recursiveRebuildPart($part, %options)
-Option--Défaut
 rules   <obligatoire>
rules => ARRAY-OF-RULES
Les règles sont des noms de méthodes qui peuvent être appelées sur des objets message et partie de message. L'ARRAY peut également contenir des références de code qui peuvent être appelées. Dans tous les cas, chaque règle sera appelée de la même manière : 
$code->(MESSAGE, PART)

Le retour peut être "undef" ou tout construct complexe basé sur un Mail::Message::Part ou coercissable en une telle partie. Pour chaque partie, toutes les règles sont appelées en séquence. Lorsqu'une règle renvoie un objet modifié, les règles recommencent, cependant "undef" l'arrête immédiatement.

DÉTAILS

Reconstruction d'un message

Modifier un message existant est une tâche compliquée. Non seulement vous devez savoir ce que vous voulez changer, mais vous devez prendre en compte les multipartes (éventuellement imbriqués sur plusieurs niveaux), les messages encapsulés rfc822, la cohérence des champs d'en-tête, etc. La méthode rebuild() vous permet de vous concentrer sur la tâche et s'occupe du reste.

La méthode rebuild() utilise des règles pour transformer un message en un autre. Si une ou plusieurs règles s'appliquent, un nouveau message sera renvoyé. Une simple comparaison numérique indique si le message a changé. Par exemple

print "Aucun changement"
   if $message == $message->rebuild;

La transformation est effectuée avec un ensemble de règles. Chaque règle n'effectue qu'une petite étape, ce qui la rend facilement configurable. Les règles sont ordonnées, et lorsqu'une modification est apportée au résultat, le résultat est passé à toutes les règles à nouveau jusqu'à ce qu'aucune règle ne modifie plus la partie. Une règle peut également renvoyer "undef" auquel cas la partie sera supprimée du message (résultant).

Règles générales

Cette section décrit les règles de configuration générales : toutes des transformations assez simples sur la structure du message. Les règles marquées par (*) sont utilisées par défaut.

  • descendMultiparts (*)

    Applique les règles aux parties des multipartes (éventuellement imbriqués), pas seulement au message de plus haut niveau.

  • descendNested (*)

    Applique les règles au message encapsulé "message/rfc822" également.

  • flattenEmptyMultiparts (*)

    Les messages multipartes qui n'ont plus de parties sont remplacés par une seule partie contenant le préambule, l'épilogue et une brève explication.

  • flattenMultiparts (*)

    Lorsqu'un multiparte ne contient qu'une seule partie, cette partie prend la place du multiparte : suppression d'un niveau d'imbrication. De cette manière, le préambule et l'épilogue du multiparte (qui n'ont pas de sens, officiellement) sont perdus.

  • flattenNesting

    Supprime l'encapsulation "message/rfc822". Seules les lignes liées au contenu du corps encapsulé sont préservées un niveau plus haut. D'autres informations seront perdues, ce qui n'est souvent pas très grave.

  • removeDeletedParts

    Toutes les parties marquées pour suppression sont retirées du message sans laisser de trace. Si un message imbriqué est rencontré dont le contenu encapsulé est marqué pour suppression, il sera supprimé en entier.

  • removeEmptyMultiparts

    Les messages multipartes qui n'ont plus de parties sont supprimés. Les informations du préambule et de l'épilogue sont perdues.

  • removeEmptyBodies

    Les corps de message simples qui ne contiennent aucune ligne de contenu sont supprimés. Cela fera perdre les informations stockées dans les en-têtes de ces corps.

NOM

Mail::Message::Construct::Rebuild

SYNOPSIS

my $result = $msg->rebuild(
  extra_rules => [ 'textAlternativeForHtml' ],
  textAlternativeForHtml => { leftmargin => 0 },
);

DESCRIPTION

Cette section décrit les règles qui tentent d'être intelligentes avec le contenu. Contribuez avec des idées et des implémentations.

  • removeHtmlAlternativeToText
    Lorsqu'une pièce multipart alternative contenant à la fois une partie texte brut et une partie HTML est rencontrée, la partie HTML est supprimée. C'est particulièrement utile en combinaison avec la règle "flattenMultiparts".
  • textAlternativeForHtml
    Toute partie "text/html" qui n'est pas accompagnée d'une partie texte brut alternative se verra en ajouter une. Vous devez avoir une version fonctionnelle de Mail::Message::Convert::HtmlFormatText installée, ce qui implique que vous devez avoir HTML::TreeBuilder et HTML::FormatText installés sur votre système.

    • Si vous envisagez de créer un filtre automatique de conversion HTML vers texte brut pour votre courrier, vous devriez consulter https://github.com/logological/mimestrip

» Exemple : utiliser un paramètre avec "textAlternativeForHtml"

my $result = $msg->rebuild(
  extra_rules => [ 'textAlternativeForHtml' ],
  textAlternativeForHtml => { leftmargin => 0 },
);
removeExtraAlternativeText
Au cas où une pièce multipart alternative serait rencontrée, tout son contenu sauf le dernier (la pièce préférée selon RFC2046) est supprimé. En pratique, cela a généralement pour effet de supprimer la partie texte brut alternative d'un message HTML. C'est utile en combinaison avec la règle "flattenMultiparts".

Ajouter vos propres règles

Si vous avez conçu votre propre règle, envisagez de contribuer à Mail::Box ; elle pourrait être utile à d'autres utilisateurs.

Chaque règle est appelée

my $new = $code->($message, $part, %options)

où %options sont définies par la méthode interne rebuild(). Au moins l'option "rules" est passée, qui est une expansion complète de toutes les règles qui seront appliquées.

Votre sous-routine doit retourner $part s'il n'y a pas de changement, "undef" si la pièce doit être supprimée, et toute nouvelle "Mail::Message::Part" s'il y a eu des changements. Il est plus facile de commencer par regarder le code source de ce paquet et de copier une routine similaire.

Lorsque vous avez votre propre routine, vous l'appelez simplement ainsi :

my $rebuild_message = $message->rebuild(
  extra_rules => [ \&my_own_rule, 'other_rule' ],
);
