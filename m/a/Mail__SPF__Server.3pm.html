Mail::SPF::Server(3) Perl contributed documentation Mail::SPF::Server(3)

Nom

Mail::SPF::Server - classe serveur pour le traitement des requêtes SPF

VERSION

version 3.20250505

SYNTAXE

use Mail::SPF;
my $spf_server  = Mail::SPF::Server->new(
    # Options par défaut pour l'explication de l'autorité :
    default_authority_explanation =>
        'Rejeté par l_enregistrement SPF.'

DESCRIPTION

Mail::SPF::Server est une classe serveur pour le traitement des requêtes SPF. Chaque instance de serveur peut être configurée avec des paramètres de traitement spécifiques. De plus, le résolveur DNS par défaut Net::DNS::Resolver utilisé pour effectuer des recherches DNS peut être remplacé par un objet résolveur personnalisé.

Constructeur

Le constructeur suivant est fourni :

new(%options): retourne Mail::SPF::Server
Création d'une nouvelle instance d'objet serveur pour traiter les requêtes SPF.

%options est une liste de paires clé-valeur représentant toutes les options suivantes :

default_authority_explanation
Une chaîne de caractères indiquant l'explication d'autorité par défaut (non étendue par macro) à utiliser si le domaine d'autorité ne spécifie pas sa propre chaîne d'explication. La valeur par défaut est : 
'Rejeté par l_enregistrement SPF.'

Comme on peut le voir d'après la valeur par défaut, un pseudo-macro _scope est pris en charge et s'étend au nom du périmètre de l'identité. (Note : Aucune macro non standard ne doit être utilisée dans les explications publiées sur DNS.)

hostname
Une chaîne de caractères indiquant le nom d'hôte complet du système à utiliser pour étendre la macro "r" dans les explications. La valeur par défaut est le nom d'hôte du système configuré.
dns_resolver
Un objet résolveur DNS facultatif. S'il n'est pas spécifié, un nouvel objet Net::DNS::Resolver est utilisé. L'objet résolveur peut être d'une classe différente, mais il doit fournir une interface similaire à celle de Net::DNS::Resolver — au minimum, les méthodes "send" et "errorstring" doivent être disponibles, et la méthode "send" doit retourner soit un objet de classe Net::DNS::Packet, soit, en cas d'erreur, undef.
query_rr_types
Types d'enregistrements de ressources (RR) à rechercher lors de la réalisation de recherches et de la sélection d'enregistrements SPF. Les valeurs suivantes sont prises en charge :
Mail::SPF::Server->query_rr_type_all
Types d'enregistrements de ressources "TXT" et "SPF".
Mail::SPF::Server->query_rr_type_txt (par défaut)
Types d'enregistrements de ressources "TXT" uniquement.
Mail::SPF::Server->query_rr_type_spf
Types d'enregistrements de ressources "SPF" uniquement.

Il y a des années, Mail::SPF recherchait par défaut les types d'enregistrements de ressources "SPF" et "TXT", comme le recommande la RFC 4408. L'expérience a montré qu'une grande partie des serveurs de noms souffrent de graves troubles cérébraux concernant la gestion des requêtes pour des types d'enregistrements de ressources qu'ils ne connaissent pas, comme le type d'enregistrement de ressources "SPF". Pour cette raison, Mail::SPF recherche désormais par défaut uniquement les types d'enregistrements de ressources "TXT". Ceci peut être remplacé par l'option query_rr_types.

Voir RFC 4408, 3.1.1, pour une discussion sur le sujet, ainsi que la description de la méthode "select_record".

max_dns_interactive_terms
Un entier indiquant le nombre maximum de termes (mécanismes et modificateurs) par vérification SPF qui effectuent des recherches DNS, comme défini dans la RFC 4408, 10.1, paragraphe 6. Si undef est spécifié, il n'y a pas de limite au nombre de tels termes. La valeur par défaut est 10, qui est la valeur définie dans la RFC 4408.

Une valeur supérieure à la valeur par défaut est fortement déconseillée pour des raisons de sécurité. Une valeur inférieure a des implications concernant la prédictibilité des résultats SPF. Vous ne devriez changer la valeur par défaut que si vous savez ce que vous faites !

max_name_lookups_per_term
Un entier indiquant le nombre maximum de recherches DNS par terme (mécanisme ou modificateur), comme défini dans la RFC 4408, 10.1, paragraphe 7. Si undef est spécifié, il n'y a pas de limite au nombre de recherches effectuées. La valeur par défaut est 10, qui est la valeur définie dans la RFC 4408.

Une valeur supérieure à la valeur par défaut est fortement déconseillée pour des raisons de sécurité. Une valeur inférieure a des implications concernant la prédictibilité des résultats SPF. Vous ne devriez changer la valeur par défaut que si vous savez ce que vous faites !

max_name_lookups_per_mx_mech
max_name_lookups_per_ptr_mech
Un entier indiquant le nombre maximum de recherches DNS par mécanisme mx ou ptr. La valeur par défaut est la valeur de l'option "max_name_lookups_per_term". Voir là-bas pour plus d'informations et des notes de sécurité.
max_void_dns_lookups
Un entier indiquant le nombre maximum de recherches DNS « vides » par vérification SPF, c'est-à-dire le nombre de recherches DNS provoquées par des recherches interactives de types d'enregistrements de ressources et de macros (telles que définies dans la RFC 4408, 10.1, paragraphes 6 et 7) et qui peuvent renvoyer une réponse vide avec RCODE 0 ou RCODE 3 (« NXDOMAIN ») avant que le traitement ne soit interrompu avec un résultat « permerror ». Si undef est spécifié, il n'y a pas de limite plus stricte que les limites de traitement normales. La valeur par défaut est 2.

Plus précisément, les recherches DNS soumises à cette limite sont celles provoquées par les mécanismes "a", "mx", "ptr" et "exists", ainsi que la macro "p".

Une valeur de 2 est susceptible d'éviter les attaques efficaces contre les domaines de victimes tierces. Cependant, une limite définie peut entraîner des résultats « permerror » même avec des politiques d'expéditeur inoffensives (très complexes) où des résultats utiles seraient normalement renvoyés.

Méthodes_de_classe

Les méthodes de classe suivantes sont fournies :

result_class: retourne classe
result_class($name): retourne classe
Renvoie une classe héritant de Mail::SPF::Result déterminée à partir du nom de résultat donné, via la classe de base des résultats du serveur, ou renvoie la classe de base des résultats du serveur si aucun nom de résultat n'est fourni. Cette méthode peut également être utilisée comme méthode d'instance.

Note : N'écrivez pas de code qui invoque des méthodes de classe sur des noms de classes de résultats littéraux, car cela ignorerait toute classe de résultat dérivée fournie par Mail::SPF.

NAME

Mail::SPF::Server - SPF server object

SYNOPSIS

  use Mail::SPF::Server;

  my $server = Mail::SPF::Server->new(
      # see constructor options below
  );

  my $request  = Mail::SPF::Request->new(...);
  my $result   = $server->process($request);

  # --- using a specific result object ---
  my $result_no_record = $server->throw_result('none', $request);
  my $result_fail      = $server->throw_result('fail', $request, 'bad sender');

  # --- accessing server properties ---
  my $host = $server->hostname;
  my $resolver = $server->dns_resolver;

DESCRIPTION

This class provides the server object used by Mail::SPF to perform SPF policy lookups and evaluations. The server object is initialized with a set of options, which are then used by its methods, in particular by the process() and select_record() methods.

A server object is generally intended to be reused for the evaluation of multiple SPF requests, so that the configured options and any cached DNS records are shared. This leads to a significant performance advantage.

A server object has a number of methods for throwing result objects, which are described in the following section.

Result throwing methods

throw_result($name): throws Mail::SPF::Result
Throws a Mail::SPF::Result descendant determined from the given result name. This method is intended to be used by Mail::SPF extension modules.
throw_result($name, $request): throws Mail::SPF::Result
Throws a Mail::SPF::Result descendant determined from the given result name, associating the given Mail::SPF::Request object with the result object. This method may also be used as an instance method.

Note: Do not write code invoking "throw" on literal result class names as this would ignore any derivative result classes provided by Mail::SPF extension modules.

throw_result($name, $request, $text): throws Mail::SPF::Result
Throws a Mail::SPF::Result descendant determined from the given result name via the server's inherent result base class, passing an optional result text and associating the given Mail::SPF::Request object with the result object. This method may also be used as an instance method.

Note: Do not write code invoking "throw" on literal result class names as this would ignore any derivative result classes provided by Mail::SPF extension modules.

Instance methods

The following instance methods are provided:

process($request): returns Mail::SPF::Result
Processes the given Mail::SPF::Request object, queries the authoritative domain for an SPF sender policy (see the description of the "select_record" method), evaluates the policy with regard to the given identity and other request parameters, and returns a Mail::SPF::Result object denoting the result of the policy evaluation. See RFC 4408, 4, and RFC 4406, 4, for details.
select_record($request): returns Mail::SPF::Record; throws Mail::SPF::EDNSError, Mail::SPF::ENoAcceptableRecord, Mail::SPF::ERedundantAcceptableRecords, Mail::SPF::ESyntaxError
Queries the authority domain of the given Mail::SPF::Request object for SPF sender policy records and, if multiple records are available, selects the record of the highest acceptable record version that covers the requested scope.

More precisely, the following algorithm is performed (assuming that both "TXT" and "SPF" RR types are being queried):

1.
Determine the authority domain, the set of acceptable SPF record versions, and the identity scope from the given request object.
2.
Query the authority domain for SPF records of the "SPF" DNS RR type, discarding any records that are of an inacceptable version or do not cover the desired scope.

If this yields no SPF records, query the authority domain for SPF records of the "TXT" DNS RR type, discarding any records that are of an inacceptable version or do not cover the desired scope.

If still no acceptable SPF records could be found, throw a Mail::SPF::ENoAcceptableRecord exception.

3.
Discard all records but those of the highest acceptable version found.

If exactly one record remains, return it. Otherwise, throw a Mail::SPF::ERedundantAcceptableRecords exception.

If the querying of either RR type has been disabled via the "new" constructor's "query_rr_types" option, the respective part in step 2 will be skipped.

Mail::SPF::EDNSError exceptions due to DNS look-ups and Mail::SPF::ESyntaxError exceptions due to invalid acceptable records may also be thrown.

get_acceptable_records_from_packet($packet, $rr_type, \@versions, $scope, $domain): returns list of Mail::SPF::Record
Filters from the given Net::DNS::Packet object all resource records of the given RR type and for the given domain name, discarding any records that are not SPF records at all, that are of an inacceptable SPF record version, or that do not cover the given scope. Returns a list of acceptable records.
dns_lookup($domain, $rr_type): returns Net::DNS::Packet; throws Mail::SPF::EDNSTimeout, Mail::SPF::EDNSError
Queries the DNS using the configured resolver for resource records of the desired type at the specified domain and returns a Net::DNS::Packet object if an answer packet was received. Throws a Mail::SPF::EDNSTimeout exception if a DNS time-out occurred. Throws a Mail::SPF::EDNSError exception if an error (other than RCODE 3 AKA "NXDOMAIN") occurred.
count_dns_interactive_term($request): throws Mail::SPF::EProcessingLimitExceeded
Increments by one the count of DNS-interactive mechanisms and modifiers that have been processed so far during the evaluation of the given Mail::SPF::Request object. If this exceeds the configured limit (see the "new" constructor's "max_dns_interactive_terms" option), throws a Mail::SPF::EProcessingLimitExceeded exception.

This method is supposed to be called by the "match" and "process" methods of Mail::SPF::Mech and Mail::SPF::Mod sub-classes before (and only if) they do any DNS look-ups.

count_void_dns_lookup($request): throws Mail::SPF::EProcessingLimitExceeded
Increments by one the count of "void" DNS look-ups that have occurred so far during the evaluation of the given Mail::SPF::Request object. If this exceeds the configured limit (see the "new" constructor's "max_void_dns_lookups" option), throws a Mail::SPF::EProcessingLimitExceeded exception.

This method is supposed to be called by any code after any calls to the "dns_lookup" method whenever (i) no answer records were returned, and (ii) this fact is a possible indication of a DoS attack against a third-party victim domain, and (iii) the number of "void" look-ups is not already constrained otherwise (as for example is the case with the "include" mechanism and the "redirect" modifier). Specifically, this applies to look-ups performed by the "a", "mx", "ptr", and "exists" mechanisms and the "p" macro.

default_authority_explanation: returns Mail::SPF::MacroString
Returns the default authority explanation as a MacroString object. See the description of the "new" constructor's "default_authority_explanation" option.
hostname: returns string
Returns the local system's host name. See the description of the "new" constructor's "hostname" option.
dns_resolver: returns Net::DNS::Resolver or compatible object
Returns the DNS resolver object of the server object. See the description of the "new" constructor's "dns_resolver" option.
query_rr_types: returns integer
Returns a value denoting the RR types for which to query when looking up and selecting SPF records. See the description of the "new" constructor's "query_rr_types" option.
max_dns_interactive_terms: returns integer
max_name_lookups_per_term: returns integer
max_name_lookups_per_mx_mech: returns integer
max_name_lookups_per_ptr_mech: returns integer
max_void_dns_lookups: returns integer
Return the limit values of the server object. See the description of the "new" constructor's corresponding options.
