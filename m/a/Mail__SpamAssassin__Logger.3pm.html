Mail::SpamAssassin::Logger(3) Documentation Perl fournie par l'utilisateur Mail::SpamAssassin::Logger(3)

NOM

Mail::SpamAssassin::Logger - Module de journalisation de SpamAssassin

SYNTAXE

use Mail::SpamAssassin::Logger;
$SIG{__WARN__} = sub {
  log_message("warn", $_[0]);
};
$SIG{__DIE__} = sub {
  log_message("error", $_[0])  if !$^S;
};

MÉTHODES

add_facilities(facilities)
Active la journalisation de débogage pour des installations spécifiques. Chaque installation est le domaine du code à déboguer. Les installations peuvent être spécifiées sous forme de référence de table associative (les noms des clés sont utilisés), de référence de tableau, de tableau ou de chaîne scalaire séparée par des virgules. Les noms d'installation sont sensibles à la casse.

Si "all" est listé, alors toutes les installations de débogage sont implicitement activées, à l'exception de celles explicitement désactivées. Un nom d'installation peut être précédé de "no" (insensible à la casse), ce qui le désactive explicitement, remplaçant "all". Par exemple : all,norules,noconfig,nodcc. Lorsque les noms d'installation sont donnés sous forme de liste ordonnée (tableau ou scalaire, pas une table associative), la dernière entrée s'applique, par exemple 'nodcc,dcc,dcc,noddc' est équivalent à 'nodcc'. Notez qu'actuellement aucun nom d'installation ne commence par "no", il est conseillé de conserver cette pratique avec les nouveaux noms d'installation ajoutés pour vous faciliter la tâche.

Les messages d'information de priorité supérieure qui conviennent à la journalisation dans des circonstances normales sont disponibles avec un domaine de "info". Certains messages très verbeux nécessitent que l'installation soit spécifiquement activée (voir "would_log" ci-dessous).

log_message($level, @message)
Journalise un message à un niveau spécifique. Les niveaux sont spécifiés sous forme de chaînes : "warn", "error", "info", et "dbg". Le premier élément du message doit être préfixé par un nom d'installation suivi directement de deux-points.
dbg("installation: message")
Ceci est utilisé pour tous les messages de débogage de faible priorité.
info("installation: message")
Ceci est utilisé pour les messages d'information indiquant une condition normale mais significative. Ceci ne devrait être appelé qu'occasionnellement. Ces messages sont généralement journalisés lorsque SpamAssassin est exécuté en tant que démon.
add(method => 'syslog', socket => $socket, facility => $facility, escape => $escape)
"socket" est le type de syslog ("unix" ou "inet"). "facility" est l'installation syslog (typiquement "mail").

Si l'"escape" optionnel est vrai, tous les caractères non ASCII sont échappés pour une sortie sûre : les antislashs deviennent \\ et les caractères non ASCII deviennent \x{XX} ou \x{XXXX} (Unicode). Si non défini, le nettoyage de style pré-4.0 est utilisé ( tr/\x09\x20\x00-\x1f/_/s ).

La valeur d'échappement peut être remplacée par la variable d'environnement "SA_LOGGER_ESCAPE".

add(method => 'file', filename => $file, escape => $escape)
"filename" est le nom du fichier journal. "escape" fonctionne comme décrit ci-dessus.
add(method => 'stderr', escape => $escape)
Aucune option n'est nécessaire pour la journalisation sur stderr, il suffit de ne pas fermer stderr au préalable. "escape" fonctionne comme décrit ci-dessus.
remove(method)
Supprime une méthode de journalisation. Seul le nom de la méthode doit être passé sous forme scalaire.
would_log($level, $facility)
Retourne faux si un message au niveau donné et avec l'installation donnée ne serait pas journalisé. Retourne 1 si un message à un niveau et une installation donnés serait journalisé normalement. Retourne 2 si l'installation a été spécifiquement activée.

L'argument installation est optionnel.

close_log()
Ferme tous les journaux.
