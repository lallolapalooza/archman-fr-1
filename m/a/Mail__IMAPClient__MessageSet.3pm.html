NOM

Mail::IMAPClient::MessageSet - plages de numéros de séquence de messages

SYNOPSIS

my @msgs = $imap->search("SUBJECT","Virus"); # retourne 1,3,4,5,6,9,10
my $msgset = Mail::IMAPClient::MessageSet->new(@msgs);
print $msgset;  # affiche "1,3:6,9:10"
# ajoute le message 14 à l'ensemble :
$msgset += 14;
print $msgset;  # affiche "1,3:6,9:10,14"
# ajoute les messages 16,17,18,19 et 20 à l'ensemble :
$msgset .= "16,17,18:20";
print $msgset;  # affiche "1,3:6,9:10,14,16:20"
# Tiens, je ne voulais pas vraiment le message 17 ; retirons-le :
$msgset -= 17;
print $msgset;  # affiche "1,3:6,9:10,14,16,18:20"
# Maintenant, parcourons chaque message :
for my $msg (@$msgset)
{  print "$msg\n";  # Affiche : "1\n3\n4\n5\n6..16\n18\n19\n20\n"
}
print join("\n", @$msgset)."\n";     # Idem, plus simple
local $" = "\n"; print "@$msgset\n"; # Encore plus simple

DESCRIPTION

Le module Mail::IMAPClient::MessageSet est conçu pour simplifier la vie des programmeurs qui ont besoin de manipuler des ensembles potentiellement volumineux d'identifiants de messages (UID) ou de numéros de séquence IMAP.

Ce module présente une interface orientée objet pour la gestion de vos ensembles de messages. La référence d'objet retournée par la méthode `new` est une référence surchargée à une variable scalaire qui contient la représentation compacte RFC2060 de l'ensemble de messages. L'objet est surchargé de telle sorte que son utilisation comme une chaîne retourne cette représentation compacte de l'ensemble de messages. Vous pouvez également ajouter des messages à l'ensemble (en utilisant l'opérateur `.=` ou `+=`) ou en supprimer (avec l'opérateur `-=`). Et si vous l'utilisez comme une référence de tableau, il vous conviendra et agira comme tel en appelant `unfold` pour vous.

RFC2060 spécifie que plusieurs messages peuvent être fournis à certaines commandes IMAP en les séparant par des virgules. Par exemple, "1,2,3,4,5" spécifierait les messages 1, 2, 3, 4 et (vous l'avez deviné !) 5. Cependant, si vous effectuez une opération sur de nombreux messages, cette chaîne peut devenir très longue. Si longue qu'elle peut ralentir votre transaction, et peut-être même causer son rejet par le serveur. Ainsi, RFC2060 vous permet également de spécifier une plage de messages, de sorte que les messages 1, 2, 3, 4 et 5 peuvent également être spécifiés comme "1:5".

C'est là qu'intervient Mail::IMAPClient::MessageSet. Il convertira votre ensemble de messages dans la syntaxe correcte la plus courte. Cela peut potentiellement vous faire économiser beaucoup d'entrées/sorties réseau, comme dans le cas où vous souhaitez récupérer les drapeaux de tous les messages d'un dossier de 10000 messages, où les messages sont tous numérotés séquentiellement. Délimité par des virgules, et en faisant l'hypothèse la plus favorable que le premier message est le message "1", il faudrait 48893 octets pour spécifier l'ensemble de messages complet en utilisant la méthode délimitée par des virgules. Pour le spécifier comme une plage, cela ne prend que sept octets (1:10000).

Notez que la méthode Range de Mail::IMAPClient peut être utilisée comme raccourci pour spécifier "Mail::IMAPClient::MessageSet->new(@etc)".)

MÉTHODES DE CLASSE

La seule méthode de classe dont vous devez vous soucier est new. Et si vous créez vos objets Mail::IMAPClient::MessageSet via la méthode Range de Mail::IMAPClient, alors vous n'avez même pas à vous soucier de new.

new

Exemple :

my $msgset = Mail::IMAPClient::MessageSet->new(@msgs);

La méthode new nécessite au moins un argument. Cet argument peut être un message, une liste de messages séparés par des virgules, une plage de messages séparés par des deux-points, ou une combinaison de messages séparés par des virgules et de plages séparées par des deux-points. Il peut également s'agir d'une référence à un tableau de messages, de listes de messages séparés par des virgules et de plages séparées par des deux-points.

Si plus d'un argument est fourni à new, ces arguments doivent être d'autres numéros de message, listes et plages (ou des références à ceux-ci) comme dans le premier argument.

Les numéros de message passés à new peuvent être de n'importe quel type de nombre, mais pour être utiles dans une session Mail::IMAPClient, ils devraient être soit des identifiants de message (UID) (si votre paramètre Uid est vrai), soit des numéros de séquence de message.

La méthode new retournera une référence à un objet Mail::IMAPClient::MessageSet. Cet objet, lorsqu'il est entre guillemets doubles, agira comme une chaîne dont la valeur est l'ensemble de messages exprimé de la manière la plus courte possible, avec les numéros de message triés par ordre croissant et les doublons supprimés.

MÉTHODES D'OBJET

La seule méthode d'objet actuellement disponible pour un objet Mail::IMAPClient::MessageSet est la méthode unfold.

unfold

Exemple :

my $msgset = $imap->Range( $imap->messages ) ;
my @all_messages = $msgset->unfold;

La méthode unfold retourne un tableau de messages appartenant à l'ensemble de messages. Si elle est appelée dans un contexte scalaire, elle retourne une référence au tableau à la place.

OPÉRATIONS SURCHARGÉES

Mail::IMAPClient::MessageSet surcharge un certain nombre d'opérateurs afin de faciliter la manipulation de vos ensembles de messages. Les opérations surchargées sont :

conversion en chaîne

Tenter de convertir un objet Mail::IMAPClient::MessageSet en chaîne de caractères retournera la spécification compacte du message, ce qui est presque certainement ce que vous voudrez.

Auto-incrémentation

Tenter d'auto-incrémenter un objet Mail::IMAPClient::MessageSet entraînera l'ajout d'un message (ou de plusieurs messages) à l'ensemble de messages de l'objet.

Exemple :

$msgset += 34;
# Le message #34 est maintenant dans l'ensemble de messages

Concaténation

Tenter de concaténer à un objet Mail::IMAPClient::MessageSet entraînera l'ajout d'un message (ou de plusieurs messages) à l'ensemble de messages de l'objet.

Exemple :

$msgset .= "34,35,36,40:45";
# Les messages 34,35,36,40,41,42,43,44 et 45 sont maintenant dans l'ensemble de messages

Les opérateurs ".=" et "+=" peuvent être utilisés de manière interchangeable, mais comme vous pouvez le voir en regardant les exemples, il y a des moments où l'utilisation de l'un a un avantage esthétique sur l'autre.

Auto-décrémentation

Tenter d'auto-décrémenter un objet Mail::IMAPClient::MessageSet entraînera la suppression d'un message de l'ensemble de messages de l'objet.

Exemples :

$msgset -= 34;
# Le message #34 n'est plus dans l'ensemble de messages
$msgset -= "1:10";
# Les messages 1 à 10 ne sont plus dans l'ensemble de messages

Si vous tentez de supprimer un message qui ne faisait pas partie de l'ensemble de messages d'origine, votre ensemble de messages résultant sera le même que l'original, mais plus cher. Cependant, si vous tentez de supprimer plusieurs messages de l'ensemble de messages et que certains de ces messages faisaient partie de l'ensemble et d'autres non, le surcoût lié à la vérification des messages qui n'y étaient pas est négligeable. Dans les deux cas, vous obtenez l'ensemble de messages souhaité, qu'il soit déjà comme ça ou non.
