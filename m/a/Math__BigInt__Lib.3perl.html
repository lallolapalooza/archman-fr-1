Math::BigInt::Lib(3perl) Guide de référence du programmeur Perl Math::BigInt::Lib(3perl)

NOM

Math::BigInt::Lib - classe parente virtuelle pour les bibliothèques Math::BigInt

SYNOPSIS

# Dans la bibliothèque backend pour Math::BigInt et autres
package Math::BigInt::MyBackend;
use Math::BigInt::Lib;
our @ISA = qw< Math::BigInt::Lib >;
sub _new { ... }
sub _str { ... }
sub _add { ... }
str _sub { ... }
...
# Dans votre programme principal.
use Math::BigInt lib => 'MyBackend';

DESCRIPTION

Ce module fournit un support pour les calculs sur les grands entiers. Il n'est pas destiné à être utilisé directement, mais plutôt comme classe parente pour les bibliothèques backend utilisées par Math::BigInt, Math::BigFloat, Math::BigRat et les modules associés.

D'autres bibliothèques backend incluent Math::BigInt::Calc, Math::BigInt::FastCalc, Math::BigInt::GMP et Math::BigInt::Pari.

Afin de permettre plusieurs bibliothèques de grands entiers, Math::BigInt a été réécrit pour utiliser une bibliothèque enfichable pour les routines mathématiques de base. Tout module qui respecte l'API peut être utilisé par Math::BigInt en utilisant ceci dans votre programme :

use Math::BigInt lib => 'nomlib';

« nomlib » est soit le nom long, comme 'Math::BigInt::Pari', soit seulement la version courte, comme 'Pari'.

Notes Générales

Une bibliothèque n'a besoin de traiter que des grands entiers non signés. La vérification de la validité des paramètres d'entrée est effectuée par l'appelant, il n'y a donc pas lieu de s'inquiéter des sous-flux (par exemple, dans _sub() et _dec()) ou de la division par zéro (par exemple, dans _div() et _mod()) ou de cas similaires.

Certaines bibliothèques utilisent des méthodes qui ne modifient pas leur argument, et certaines bibliothèques n'utilisent même pas d'objets, mais plutôt des références non bénies. Pour cette raison, les méthodes de bibliothèque sont toujours appelées en tant que méthodes de classe, pas méthodes d'instance :

$x = Classe -> methode($x, $y);     # comme ceci
$x = $x -> methode($y);            # pas comme ceci ...
$x -> methode($y);                 # ... ni comme ceci

Et avec les méthodes booléennes

$bool = Classe -> methode($x, $y);  # comme ceci
$bool = $x -> methode($y);         # pas comme ceci

Les valeurs de retour sont toujours des objets, des chaînes de caractères, des scalaires Perl, ou vrai/faux pour les routines de comparaison.

Version de l'API

CLASSE->api_version()
Cette méthode n'est plus utilisée et peut être omise. Les méthodes qui ne sont pas implémentées par une sous-classe seront héritées de cette classe.

Constructeurs

Les méthodes suivantes sont obligatoires : _new(), _str(), _add() et _sub(). Cependant, les calculs seront très lents sans _mul() et _div().

CLASSE->_new(CHAÎNE)
Convertit une chaîne représentant un nombre décimal non signé en un objet représentant le même nombre. L'entrée est normalisée, c'est-à-dire qu'elle correspond à "^(0|[1-9]\d*)$".
CLASSE->_zero()
Retourne un objet représentant le nombre zéro.
CLASSE->_one()
Retourne un objet représentant le nombre un.
CLASSE->_two()
Retourne un objet représentant le nombre deux.
CLASSE->_ten()
Retourne un objet représentant le nombre dix.
CLASSE->_from_bin(CHAÎNE)
Retourne un objet étant donné une chaîne représentant un nombre binaire. L'entrée a un préfixe '0b' et correspond à l'expression régulière "^0[bB](0|1[01]*)$".
CLASSE->_from_oct(CHAÎNE)
Retourne un objet étant donné une chaîne représentant un nombre octal. L'entrée a un préfixe '0' et correspond à l'expression régulière "^0[1-7]*$".
CLASSE->_from_hex(CHAÎNE)
Retourne un objet étant donné une chaîne représentant un nombre hexadécimal. L'entrée a un préfixe '0x' et correspond à l'expression régulière "^0x(0|[1-9a-fA-F][\da-fA-F]*)$".
CLASSE->_from_bytes(CHAÎNE)
Retourne un objet étant donné une chaîne d'octets représentant le nombre. La chaîne d'octets est en ordre d'octets big-endian, donc la chaîne d'entrée de deux octets "\x01\x00" devrait donner une valeur de sortie représentant le nombre 256.
CLASSE->_from_base(CHAÎNE, BASE, COLLSEQ)
Retourne un objet étant donné une chaîne CHAÎNE, une base BASE et une séquence de collationnement COLLSEQ. Chaque caractère de CHAÎNE représente une valeur numérique identique à la position du caractère dans COLLSEQ. Tous les caractères de CHAÎNE doivent être présents dans COLLSEQ.

Si BASE est inférieur ou égal à 94, et qu'une séquence de collationnement n'est pas spécifiée, la séquence de collationnement par défaut suivante est utilisée. Elle contient tous les 94 caractères ASCII imprimables sauf l'espace :

0123456789                  # ASCII  30 à  39
ABCDEFGHIJKLMNOPQRSTUVWXYZ  # ASCII  65 à  90
abcdefghijklmnopqrstuvwxyz  # ASCII  97 à 122
!"#$%&'()*+,-./             # ASCII  33 à  47
:;<=>?@                     # ASCII  58 à  64
[\]^_`                      # ASCII  91 à  96
{|}~                        # ASCII 123 à 126

Si la séquence de collationnement par défaut est utilisée, et que la BASE est inférieure ou égale à 36, la casse des lettres dans CHAÎNE est ignorée.

Par exemple, avec la base 3 et la séquence de collationnement "-/|", le caractère "-" représente 0, "/" représente 1, et "|" représente 2. Donc si CHAÎNE est "/|-", la sortie est 1 * 3**2 + 2 * 3**1 + 0 * 3**0 = 15.

Les exemples suivants montrent la conversion binaire, octale, décimale et hexadécimale standard. Tous les exemples retournent 250.

$x = $class -> _from_base("11111010", 2)
$x = $class -> _from_base("372", 8)
$x = $class -> _from_base("250", 10)
$x = $class -> _from_base("FA", 16)

Quelques exemples supplémentaires, tous retournant 250 :

$x = $class -> _from_base("100021", 3)
$x = $class -> _from_base("3322", 4)
$x = $class -> _from_base("2000", 5)
$x = $class -> _from_base("caaa", 5, "abcde")
$x = $class -> _from_base("42", 62)
$x = $class -> _from_base("2!", 94)
CLASSE->_from_base_num(TABLEAU, BASE)
Retourne un objet étant donné un tableau de valeurs et une base. Cette méthode est équivalente à _from_base(), mais fonctionne sur des nombres dans un tableau plutôt que des caractères dans une chaîne. Contrairement à _from_base(), toutes les valeurs d'entrée peuvent être arbitrairement grandes. 
$x = $class -> _from_base_num([1, 1, 0, 1], 2)    # $x est 13
$x = $class -> _from_base_num([3, 125, 39], 128)  # $x est 65191

API des sous-classes

Les sous-classes doivent implémenter les méthodes marquées comme obligatoires. Toutes les autres méthodes peuvent être laissées non implémentées et seront héritées de Math::BigInt::Lib. Il est cependant recommandé d'implémenter _mul, _div et _cmp pour de meilleures performances.

Notez que certaines méthodes, comme _add, peuvent retourner le premier argument modifié. D'autres méthodes, comme _str, peuvent retourner des chaînes ou des objets. Les appelants ne doivent pas supposer quoi que ce soit sur les types retournés autres que ceux spécifiés dans la documentation.

Les méthodes qui modifient leurs arguments doivent soit modifier l'objet passé en premier argument, soit retourner un nouveau objet. Les méthodes qui ne modifient pas leurs arguments retournent toujours un nouveau objet.

Les méthodes qui retournent un signe, le font avec une valeur de 0 pour positif, 1 pour négatif et 2 pour zéro.

CLASS->_modinv(OBJ1, OBJ2)
Retourne l'inverse multiplicatif modulaire, c'est-à-dire retourne OBJ3 tel que 
(OBJ3 * OBJ1) % OBJ2 = 1 % OBJ2

Le résultat est retourné sous forme de deux arguments. Si l'inverse multiplicatif modulaire n'existe pas, les deux arguments sont indéfinis. Sinon, les arguments sont un nombre (objet) et son signe ("+" ou "-").

La valeur de sortie, avec son signe, doit être soit une valeur positive dans l'intervalle 1,2,...,OBJ2-1, soit la même valeur moins OBJ2. Par exemple, si les arguments d'entrée sont des objets représentant les nombres 7 et 5, la méthode doit retourner soit un objet représentant le nombre 3 et un signe "+", car (3*7) % 5 = 1 % 5, soit un objet représentant le nombre 2 et un signe "-", car (-2*7) % 5 = 1 % 5.

Retourne l'exponentiation modulaire, c'est-à-dire (OBJ1 ** OBJ2) % OBJ3.
CLASS->_rsft(OBJ, N, B)
Retourne le résultat après avoir décalé OBJ de N chiffres vers la droite en base B. Ceci équivaut à effectuer une division entière par B**N et à ignorer le reste, sauf que cela peut être beaucoup plus rapide.

Par exemple, si l'objet $obj représente le nombre hexadécimal 0xabcde, alors "_rsft($obj, 2, 16)" retourne un objet représentant le nombre 0xabc. Le "reste", 0xde, est ignoré et non retourné.

Dans la sortie, le premier élément est le plus significatif. Contrairement à _to_base(), toutes les valeurs d'entrée peuvent être arbitrairement grandes. 
$x = $class -> _to_base_num(13, 2)        # $x est [1, 1, 0, 1]
$x = $class -> _to_base_num(65191, 128)   # $x est [3, 125, 39]
CLASS->_as_bin(OBJ)
Comme _to_bin() mais avec un préfixe '0b'.
CLASS->_as_oct(OBJ)
Comme _to_oct() mais avec un préfixe '0'.
CLASS->_as_hex(OBJ)
Comme _to_hex() mais avec un préfixe '0x'.
CLASS->_as_bytes(OBJ)
Ceci est un alias pour _to_bytes().

Conversion numérique

CLASS->_num(OBJ)
Renvoie un nombre scalaire Perl représentant le nombre OBJ aussi fidèlement que possible. Comme les scalaires Perl ont une précision limitée, la valeur renvoyée peut ne pas être exactement la même que OBJ.

Divers

CLASS->_copy(OBJ)
Renvoie une copie fidèle de OBJ.
CLASS->_len(OBJ)
Renvoie le nombre de chiffres décimaux dans OBJ. La sortie est un scalaire Perl.
CLASS->_zeros(OBJ)
Renvoie le nombre de zéros décimaux suffixes. La sortie est un scalaire Perl. Le nombre zéro n'a pas de zéros décimaux suffixes.
CLASS->_digit(OBJ, N)
Renvoie le N-ième chiffre de OBJ sous forme de scalaire Perl. N est un scalaire Perl, où zéro fait référence au chiffre le plus à droite (le moins significatif), et les valeurs négatives comptent depuis la gauche (le plus significatif). Si $obj représente le nombre 123, alors 
CLASS->_digit($obj,  0)     # renvoie 3
CLASS->_digit($obj,  1)     # renvoie 2
CLASS->_digit($obj,  2)     # renvoie 1
CLASS->_digit($obj, -1)     # renvoie 1
CLASS->_digitsum(OBJ)
Renvoie la somme des chiffres en base 10.
CLASS->_check(OBJ)
Renvoie vrai si l'objet est invalide et faux sinon. De préférence, la valeur vraie est une chaîne décrivant le problème avec l'objet. Ceci est une routine de vérification pour tester l'état interne de l'objet en cas de corruption.

Si vous souhaitez porter votre bibliothèque C préférée pour les grands nombres vers l'interface Math::BigInt, vous pouvez prendre l'un des modules existants comme ligne directrice générale. use Math::BigInt;

par ceci :

use Math::BigInt lib => 'votrelib';

De cette façon, vous vous assurez que votre bibliothèque fonctionne réellement à 100% dans Math::BigInt.
