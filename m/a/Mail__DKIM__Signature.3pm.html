Mail::DKIM::Signature(3) Documentation Perl fournie par l'utilisateur Mail::DKIM::Signature(3)

NOM

Mail::DKIM::Signature - représente un en-tête DKIM-Signature

VERSION

version 1.20240923

CONSTRUCTEURS

new() - crée une nouvelle signature à partir de paramètres

my $signature = Mail::DKIM::Signature->new(
                    [ Algorithm => 'rsa-sha1', ]
                    [ Signature => $base64, ]
                    [ Method => 'relaxed', ]
                    [ Domain => 'example.org', ]
                    [ Identity => 'user@example.org', ]
                    [ Headers => 'from:subject:date:message-id', ]
                    [ Query => 'dns', ]
                    [ Selector => 'alpha', ]
                    [ Timestamp => time(), ]
                    [ Expiration => time() + 86400, ]
                );

parse() - crée une nouvelle signature à partir d'un en-tête DKIM-Signature

my $sig = Mail::DKIM::Signature->parse(
                'DKIM-Signature: a=rsa-sha1; b=yluiJ7+0=; c=relaxed'
          );

Construit une signature en analysant le contenu de l'en-tête DKIM-Signature fourni. Vous n'avez pas besoin d'inclure le nom de l'en-tête (c'est-à-dire "DKIM-Signature:") mais c'est recommandé, afin que le nom de l'en-tête puisse être préservé et retourné de la même manière dans as_string().

Note : L'entrée de ce constructeur est dans le même format que la sortie de la méthode as_string.

MÉTHODES

algorithm() - obtient ou définit l'algorithme (champ a=)

L'algorithme utilisé pour générer la signature. Doit être l'un des éléments suivants : - "rsa-sha1", un digest SHA-1 signé par RSA - "rsa-sha256", un digest SHA-256 signé par RSA - "ed25519-sha256", un digest SHA-256 signé par Ed25519

Voir aussi hash_algorithm().

as_string() - l'en-tête de signature sous forme de chaîne

print $signature->as_string . "\n";

sorties

DKIM-Signature: a=rsa-sha1; b=yluiJ7+0=; c=relaxed

Comme montré dans l'exemple, la méthode as_string peut être utilisée pour générer le DKIM-Signature qui est préfixé à un message signé.

as_string_without_data() - signature sans les données de signature

print $signature->as_string_without_data . "\n";

sorties

DKIM-Signature: a=rsa-sha1; b=; c=relaxed

Ceci est similaire à la méthode as_string(), mais elle exclut toujours la partie "données". Ceci est utilisé par les méthodes de canonicalisation DKIM, qui nécessitent d'incorporer cette partie de la signature dans le message signé.

body_count() - obtient ou définit le nombre d'octets du corps (champ l=)

my $i = $signature->body_count;

Informe le vérificateur du nombre d'octets dans le corps de l'e-mail inclus dans le hachage cryptographique, commençant à 0 immédiatement après le CRLF précédant le corps. Également connu sous le nom de tag l.

Lors de la création d'une signature, ce tag peut être omis ou défini après que le système de canonicalisation sélectionné a reçu l'intégralité du corps du message (mais avant qu'il ne canonicalise le DKIM-Signature).

body_hash() - obtient ou définit le hachage du corps (champ bh=)

my $bh = $signature->body_hash;

Le hachage de la partie corps du message. Les espaces blancs sont ignorés dans cette valeur. Ce tag est requis.

Lors de l'accès à cette valeur, les espaces blancs sont supprimés du tag pour vous.

canonicalization() - obtient ou définit la canonicalisation (champ c=)

$signature->canonicalization('relaxed', 'simple');
($header, $body) = $signature->canonicalization;

Canonicalisation du message (par défaut "simple/simple"). Cela informe le vérificateur du type de canonicalisation utilisé pour préparer le message à la signature.

En contexte scalaire, retourne la canonicalisation de l'en-tête/corps sous forme d'une seule chaîne séparée par /. En contexte de liste, il retourne un tableau à deux éléments, contenant d'abord la canonicalisation de l'en-tête, puis celle du corps.

data() - obtient ou définit les données de signature (champ b=)

my $base64 = $signature->data;
$signature->data($base64);

Les données de signature. Les espaces blancs sont automatiquement supprimés de la valeur retournée. Les données sont encodées en Base64.

domain() - obtient ou définit le domaine (champ d=)

my $d = $signature->domain;          # récupère la valeur du domaine
$signature->domain('example.org');   # définit la valeur du domaine

Le domaine de l'entité signataire, tel que spécifié dans la signature. C'est le domaine qui sera interrogé pour la clé publique.

Si vous utilisez un "nom de domaine internationalisé", le nom de domaine doit être converti en ASCII (conformément à la section 4.1 de la RFC 3490) avant d'être passé à cette méthode.

expiration() - obtient ou définit l'expiration de la signature (champ x=)

Expiration de la signature (par défaut : undef, signifiant pas d'expiration). L'expiration de la signature, si elle est définie, est un entier non signé identifiant l'heure Unix standard en secondes depuis 1970 à laquelle la signature expirera.

get_public_key() - récupère la clé publique référencée par cette signature

my $pubkey = $signature->get_public_key;

La clé publique à récupérer est déterminée par les champs protocole, sélecteur et domaine.

Cette méthode met en cache le résultat de la récupération, donc les appels ultérieurs ne nécessiteront pas de requêtes DNS supplémentaires.

Cette méthode produira une "erreur" en cas de problème.

get_tag() - accède à la valeur brute d'un tag dans cette signature

my $raw_identity = $signature->get_tag('i');

Utilisez cette méthode pour accéder à un tag non encore pris en charge par Mail::DKIM, ou si vous souhaitez contourner le décodage de la valeur par Mail::DKIM.

Par exemple, le tag brut i= (identité) est encodé en format quoted-printable. Si vous utilisez la méthode identity(), Mail::DKIM décodera depuis quoted-printable avant de retourner la valeur. Mais si vous utilisez get_tag('i'), vous pouvez accéder à la forme encodée quoted-printable de la valeur.

hash_algorithm() - accède à l'algorithme de hachage spécifié dans cette signature

my $hash = $signature->hash_algorithm;

Détermine quel algorithme de hachage est utilisé comme partie de l'algorithme spécifié par la signature.

Pour l'algorithme "rsa-sha1", l'algorithme de hachage est "sha1". De même, pour l'algorithme "rsa-sha256", l'algorithme de hachage est "sha256". Si l'algorithme n'est pas reconnu, undef est retourné.

headerlist() - obtient ou définit les champs d'en-tête signés (champ h=)

$signature->headerlist('a:b:c');
my $headerlist = $signature->headerlist;
my @headers = $signature->headerlist;

Champs d'en-tête signés. Une liste séparée par des deux-points des noms des champs d'en-tête qui identifient les champs d'en-tête présentés à l'algorithme de signature.

En contexte scalaire, la liste des noms de champs d'en-tête sera retournée sous forme d'une seule chaîne, avec les noms joints par des deux-points. En contexte de liste, les noms des champs d'en-tête seront retournés sous forme de liste.

identity() - obtient ou définit l'identité de signature (champ i=)

my $i = $signature->identity;

Identité de l'utilisateur ou de l'agent au nom duquel ce message est signé. L'identité a une partie locale optionnelle, suivie de "@", puis d'un nom de domaine. Le nom de domaine doit être le même que, ou un sous-domaine du, domaine retourné par la méthode "domain".

Idéalement, l'identité devrait correspondre à l'identité listée dans l'en-tête From:, ou l'en-tête Sender:, mais il n'est pas nécessaire d'avoir une signature valide. La question de savoir si l'identité utilisée est "autorisée" à signer pour le message donné n'est pas déterminée ici.

Si vous utilisez un "nom de domaine internationalisé", le nom de domaine doit être converti en ASCII (conformément à la section 4.1 de la RFC 3490) avant d'être passé à cette méthode.
