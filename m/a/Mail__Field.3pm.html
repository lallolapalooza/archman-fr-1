Mail::Field(3) Documentation Perl fournie par l'utilisateur Mail::Field(3)

NOM

Mail::Field - classe de base pour la manipulation des champs d'en-tête de courrier

HÉRITAGE

Mail::Field est étendu par
  Mail::Field::AddrList
  Mail::Field::Date
  Mail::Field::Generic

SYNOPIS

use Mail::Field;

my $field = Mail::Field->new('Subject', 'some subject text');
my $field = Mail::Field->new(Subject => 'some subject text');
print $field->tag,": ",$field->stringify,"\n";
my $field = Mail::Field->subject('some subject text');

DESCRIPTION

"Mail::Field" crée et manipule des champs dans les en-têtes MIME, qui sont collectés dans un objet Mail::Header. Différents types de champs ont leurs propres sous-classes (extensions), définies pour accéder au contenu du champ de manière supplémentaire.

Les utilisateurs sont invités à unifier leurs implémentations dans les champs spéciaux de MailTools, afin de maintenir un ensemble cohérent de paquets et de documentation.

MÉTHODES

Constructeurs

Mail::Field (et ses sous-classes) définissent plusieurs méthodes qui retournent de nouveaux objets. Ceux-ci peuvent être catégorisés comme constructeurs.

Mail::Field->combine($fields)
Reçoit une liste d'objets "Mail::Field" (qui doivent être de la même sous-classe) et crée un nouvel objet dans la même classe.
Mail::Field->extract( $tag, $head [, $index ] )
Reçoit comme arguments le nom du tag, un objet "Mail::Head" et optionnellement un index.

Si l'argument $index est donné, "extract" extraira le tag donné de l'objet "Mail::Head" et créera un objet "Mail::Field" basé sur ce contenu. undef sera retourné si le champ n'existe pas.

Si l'argument $index n'est pas donné, le résultat dépend du contexte dans lequel "extract" est appelé. S'il est appelé dans un contexte scalaire, le résultat sera comme si "extract" avait été appelé avec un indice de 0. S'il est appelé dans un contexte de tableau, tous les tags seront récupérés et une liste d'objets "Mail::Field" sera retournée.

Mail::Field->new( $tag [, STRING | %options] )
Crée un objet dans la classe qui définit le champ spécifié par l'argument $tag.

Constructeurs « Fake »

$obj->create(%options)
Ce constructeur est utilisé en interne avec des informations de champ pré-traitées. Lorsqu'il est appelé sur un objet existant, son contenu original sera remplacé.
$obj->parse()
Parse une ligne de champ.

Accesseurs

$obj->set(%options)
Modifie les paramètres (le contenu, mais de manière intelligente) du champ.
$obj->stringify()
Retourne le champ sous forme de chaîne.
$obj->tag()
Mail::Field->tag()
Retourne le tag (dans le bon cas) pour cet élément. En fait, n'importe quel cas est accepté, car les tags de champs sont considérés comme insensibles à la casse ; cependant, certains utilisateurs ont des préférences.

Accesseurs intelligents

$obj->text( [STRING] )
sans arguments, retourne le champ tel que stringify(). Sinon, le STRING est parsé avec parse() pour remplacer le contenu de l'objet.

Il est plus clair d'appeler directement stringify() ou parse(), car cette méthode n'effectue aucun traitement supplémentaire.

DÉTAILS

NOMS DES PAQUETS DES SOUS-CLASSES

Toutes les sous-classes doivent être nommées Mail::Field::name, où name est dérivé du tag selon les règles suivantes.

  • Considérer le tag comme un ensemble d'éléments séparés par '-'
  • Convertir tous les caractères en minuscules, sauf le premier qui doit être en majuscule.
  • name est créé en combinant les N premiers caractères de chaque élément.
  • N est calculé par la formule :- 
    int((7 + #elements) / #elements)
  • name est limité à un maximum de 8 caractères, en conservant les 8 premiers.

Pour un exemple de ceci, voir la définition de la sous-routine _header_pkg_name() dans "Mail::Field"

DIAGNOSTIQUES

Erreur : sous-routine non définie <method>
Les objets Mail::Field utilisent l'autoloading pour compiler de nouvelles fonctions. Apparemment, la sous-routine appelée n'est pas implémentée pour le type de classe de l'objet de champ.

SYNOPSIS

use Mail::Field;

my $field = Mail::Field->new();
# ... manipulation du champ ...

DESCRIPTION

Le module Mail::Field fournit une interface pour créer, manipuler et analyser des champs d'en-tête d'e-mail conformes aux RFC.

Il est particulièrement utile pour traiter des en-têtes complexes tels que `From`, `To`, `Cc`, `Bcc`, `Subject`, `Date`, etc.

CLASSES

  • Mail::Field : La classe de base pour tous les champs d'en-tête.
  • Mail::Header::From : Pour les champs `From`.
  • Mail::Header::To : Pour les champs `To`.
  • Mail::Header::Cc : Pour les champs `Cc`.
  • Mail::Header::Bcc : Pour les champs `Bcc`.
  • Mail::Header::Subject : Pour les champs `Subject`.
  • Mail::Header::Date : Pour les champs `Date`.
  • Et d'autres classes spécifiques pour différents types de champs.

MÉTHODES

La classe Mail::Field de base et ses sous-classes fournissent diverses méthodes, notamment :

  • new(%args) : Crée une nouvelle instance de champ.
  • parse($string) : Analyse une chaîne de caractères représentant un champ d'en-tête.
  • as_string() : Renvoie la représentation sous forme de chaîne du champ.
  • name() : Renvoie le nom du champ.
  • value() : Renvoie la valeur du champ.
  • Des méthodes spécifiques à chaque type de champ pour accéder à ses composants (par exemple, adresses, noms, dates).

DÉPENDANCES

Ce module peut dépendre d'autres modules Perl standard, tels que Email::Date pour l'analyse des dates.

VOIR AUSSI

  • Mail::Header : Pour la manipulation d'en-têtes d'e-mail complets.
  • Email::Address : Pour la manipulation d'adresses e-mail.
  • Email::Date : Pour l'analyse et la génération de dates d'en-tête.
