DESCRIPTION

Les messages d'e-mail peuvent être dans divers états : non lu, lu partiellement, et lu complètement. La classe stocke un message dont toutes les lignes d'en-tête sont connues avec certitude.

Accès à l'en-tête

Étendu de "Access to the header" dans Mail::Message::Head.

$obj->add( $field | $ligne | <$nom, $corps, [$attrs]> )
Ajoute un champ à l'en-tête. Si un champ est ajouté plusieurs fois, toutes les valeurs sont stockées dans l'en-tête, dans l'ordre où elles sont ajoutées.

Lorsqu'un objet $field est spécifié (une instance de Mail::Message::Field), celui-ci sera ajouté. Une autre possibilité est de spécifier une ligne d'en-tête brute $ligne, ou une ligne d'en-tête joliment divisée en $nom et $corps, auquel cas le constructeur de champ est appelé pour vous.

$ligne ou les spécifications de $corps qui se terminent par un saut de ligne sont considérées comme correctement repliées. Les lignes qui ne se terminent pas par un saut de ligne seront repliées si nécessaire : des sauts de ligne seront ajoutés là où il faut. Il est fortement conseillé de laisser MailBox s'occuper du repliage pour vous.

La valeur de retour de cette méthode est l'objet Mail::Message::Field qui est créé (ou a été spécifié).

» exemple:

my $head  = Mail::Message::Head->new;
$head->add('Subject: hi!');
$head->add(From => 'me@home');
my $field = Mail::Message::Field->new('To: you@there');
$head->add($field);
my Mail::Message::Field $s = $head->add(Sender => 'I');

Lorsque vous avez un groupe de listes préparé, vous pouvez l'ajouter plus tard en utilisant cette méthode. Vous obtiendrez votre copie privée des données du groupe de listes en retour, car le même groupe peut être utilisé pour plusieurs messages.

Un grupo de resent contiene una serie de cabeceras cuyos nombres empiezan con "Resent-*". Antes de la primera línea "Resent" se muestra información de tipo "trace", que está compuesta por un opcional "Return-Path" y un campo obligatorio "Received".

$obj->reset($name, @fields)
Reemplaza los valores de las cabeceras nombradas por $name con los valores especificados en la lista de @fields. Un solo nombre puede corresponder a múltiples cabeceras repetidas. LEA el aviso importante en removeField().

La eliminación de campos que forman parte de uno de los grupos de cabeceras predefinidos no es una idea inteligente. Puedes eliminar estos campos como grupo, juntos. Por ejemplo, las líneas 'Received' son parte de grupos de resent, 'X-Spam' es parte de un grupo de spam, y "List-Post" pertenece a un grupo de listas. Puedes eliminar un grupo completo con Mail::Message::Head::FieldGroup::delete(), o con métodos proporcionados por Mail::Message::Head::Partial.

Si FIELDS está vacío, los campos correspondientes a $name se eliminarán. La posición de los campos eliminados en el orden de la cabecera se recuerda. Los campos con el mismo nombre que se agregan después aparecerán en la posición cubierta. Esto es equivalente al método delete().

» ejemplo:

# reducir el número de líneas 'Keywords' a las últimas 5
my @keywords = $head->get('Keywords');
$head->reset('Keywords', @keywords[-5..-1]) if @keywords > 5;
# reducir el número de líneas 'Received' a solo la última agregada
my @rgs = $head->resentGroups;
shift @rgs;     # mantiene esta (la más reciente se agrega al frente)
$_->delete foreach @rgs;

NAME

Mail::Message::Head - header of a Mail::Message object

SYNOPSIS

  use Mail::Message::Head;
  my $head = Mail::Message::Head->new;
  $head->parse( $message_string );
  my $field = $head->get('Subject');
  $head->put('Subject', 'A new subject');
  $head->print;

DESCRIPTION

This class represents the header part of an electronic mail message. The header contains information about the message, like sender, recipient, subject, date, etc.

The header is structured as a list of fields. Each field has a name (like "Subject") and a value. Some fields may appear multiple times (e.g. "Received"), others only once (e.g. "Subject").

This class inherits much of its functionality from Mail::Message::Head, which is the base class for all header implementations.

Also see Mail::Reporter for the error handling methods.

Access to the header

$obj->recvstamp()
Returns an indication about when the message was sent, but only using the "Date" field in the header as last resort: we do not trust the sender of the message to specify the correct date. See timestamp() when you do trust the sender.

Many spam producers fake a date, which mess up the order of receiving things. The timestamp which is produced is derived from the Received headers, if they are present, and "undef" otherwise.

The timestamp is encoded as "time" is on your system (see perldoc -f time), and as such usable for the "gmtime" and "localtime" methods.

» example: of time-sorting folders with received messages

my $folder = $mgr->open('InBox');
my @messages = sort {$a->recvstamp <=> $b->recvstamp}
                  $folder->messages;

» example: of time-sorting messages of mixed origin

my $folder = $mgr->open('MyFolder');
# Pre-calculate timestamps to be sorted (for speed)
my @stamps = map +[ ($_->timestamp || 0), $_ ],
  $folder->messages;
my @sorted =
  map { $_->[1] }      # get the message for the stamp
    sort {$a->[0] <=> $b->[0]}   # stamps are numerics
       @stamps;
$obj->timestamp()
Returns an indication about when the message was sent, with as little guessing as possible. In this case, the date as specified by the sender is trusted. See recvstamp() when you do not want to trust the sender.

The timestamp is encoded as "time" is on your system (see perldoc -f time), and as such usable for the "gmtime" and "localtime" methods.

$any->messageIdPrefix( [$prefix, [$hostname]|CODE] )
When options are provided, it sets a new way to create message-ids, as used by createMessageId(). You have two choices: either by providing a $prefix and optionally a $hostname, or a "CODE" reference.

The "CODE" reference will be called with the header as first argument. You must ensure yourself that the returned value is RFC compliant.

The $prefix defaults to "mailbox-$$", the $hostname defaults to the return of Net::Domains's function hostfqdn(), or when not installed, the Sys::Hostname's function hostname(). Inbetween the two, a nano-second time provided by Time::HiRes is used. If that module is not available, "time" is called at the start of the program, and incremented for each newly created id.

In any case, a subroutine will be created to be used. A reference to that will be returned. When the method is called without arguments, but no subroutine is defined yet, one will be created.
