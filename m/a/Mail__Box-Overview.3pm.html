NOM

Mail::Box-Overview - objets utilisés par Mail::Box

DESCRIPTION

Introduction

Le paquet MailBox est une suite de classes pour accéder et gérer les dossiers de courrier électronique de manière indépendante des dossiers. Ce paquet est une alternative aux paquets "Mail::Folder" et "MIME::*". Il abstrait les détails des messages, du stockage des messages et des fils de discussion, tout en offrant de meilleures performances que les anciens paquets de courrier. Il est destiné à fournir une boîte à outils orientée objet pour toutes sortes d'applications de messagerie électronique, y compris les agents utilisateurs de messagerie (MUA) et les programmes de filtrage de courrier.

Ce paquet est modulaire : certaines parties peuvent être utilisées indépendamment du reste. Par exemple, Mail::Box::Manager peut déterminer automatiquement qu'un dossier est au format Mbox et renvoyer un objet de la classe Mail::Box::Mbox, ou le programme utilisateur peut contourner le gestionnaire et créer directement des objets Mail::Box::Mbox. De même, si le programme utilisateur ne manipule qu'un seul message, un Mail::Message.

Le paquet Mail::Box offre des fonctionnalités spéciales pour aider les MUA à accéder rapidement aux données des dossiers dans un ordre aléatoire. Vous n'en bénéficierez pas réellement (ni ne serez ralenti) si vous avez besoin de l'intégralité du dossier séquentiellement.

Vous pourriez vouloir consulter les scripts d'exemple dans le répertoire "scripts".

Distributions

Jusqu'à MailBox v2, tous les modules "Mail::*" étaient publiés en une seule distribution. À partir de la v3, il existe quelques distributions séparées dans le but de réduire les dépendances :

  • Mail::Message
  • Mail::Transport
  • Mail::Box
  • Mail::Box::IMAP4
  • Mail::Box::POP3
  • Mail::Box::Parser::C

Les noms des classes ne sont pas toujours idéaux : l'espace de noms 'Mail' sur CPAN est assez plein.

Les relations entre les classes

Les objets Mail::Box::Manager jouent un rôle central dans tout programme construit avec MailBox. Chaque programme créera un gestionnaire, puis ouvrira des dossiers via ce gestionnaire. Outre les dossiers, le gestionnaire peut également être utilisé pour découvrir les fils de discussion des messages : les séquences de messages avec leurs réponses.

                     <a-un>       Mail::Box::Mbox
Mail::Box::Manager <---------*    (Mail::Box::MH)
       ^                :         (Mail::Box::Maildir)
       |           (maintient)    (Mail::Box::POP3)
       |                :
       |                :
       `---------------------*  Mail::Box::Thread::Manager
                    (<a-un>)

Chaque dossier maintient une liste de messages. Beaucoup d'efforts sont faits pour masquer les différences entre les types de dossiers et les sortes de messages. Votre programme peut être utilisé pour les dossiers MBOX, MH, Maildir et POP3 sans aucun changement (tant que vous respectez les règles).

Mail::Box::Mbox  <-----------* Mail::Box::Mbox::Message
       |             <a-un>            |
       | <est-une>                    | <est-une>
       |                              |
   Mail::Box     ............. Mail::Box::Message
                                    |
                                    | <est-une>
                                    |
                              Mail::Message
                                     / \
                                    <a-un>  
                                   /     \
                        Mail::Message   Mail::Message 
                          ::Body            ::Head

La situation pour les dossiers MH et Maildir est un peu plus compliquée, car ils ont un niveau d'abstraction intermédiaire supplémentaire : Mail::Box::Dir. Le dossier POP3 a un intermédiaire Mail::Box::Net.

MailBox utilise activement l'héritage. Pour les dossiers, la structure est juste comme celle représentée pour les relations des classes Message :

MB::MH::Message              MB::POP3::Message
MB::Maildir::Message         MB::IMAP4::Message
      \                              /
       \      MB::Mbox::Message     /
        \             |            /
         \    MB::File::Message   /
          \           |          /
    MB::Dir::Message  |   MB::Net::Message
                \     |     /
                 \    |    /
              Mail::Box::Message
                      |
                 Mail::Message

Tout message a la structure de Mail::Message.

                              MM::Head::Complete
                                      |
Mail::Message                        est-une
      |                               |
      `---a-un---> Mail::Message::Head::Partial
      |             `-- a-plusieurs --> MM::Field::Fast
      |             `-- a-plusieurs --> MM::Field::Full
      |
      `---a-un---> Mail::Message::Body
                    | un de :
                    `--- MMB::Lines
                    `--- MMB::String
                    `--- MMB::File  
                    `--- MMB::Nested
                    |     `--- un ---> MM:Message
                    `--- MMB::Multipart  
                          `--- plusieurs --> MM:Part
                                   est-une Mail::Message

L'en-tête n'est pas toujours totalement connu, par exemple via IMAP ou lorsque le message est situé dans un fichier. Essentiellement, seuls les champs utilisés sont mis en cache jusqu'à ce que l'en-tête entier soit nécessaire pour les ajouts, suppressions ou modifications.

Les champs "Complet" ont une gestion très détaillée et parfaite des RFC. Vous les obtiendrez via les méthodes study(). Le champ Rapide par défaut est bâclé : juste des chaînes de texte.

Le Gestionnaire

Le gestionnaire de boîtes aux lettres Mail::Box::Manager encapsule les problèmes de gestion des dossiers. Il maintient un ensemble de dossiers de courrier ouverts (boîtes aux lettres), et fournit des méthodes pour les ouvrir et les fermer, déplacer efficacement les messages entre les dossiers, et ajouter efficacement des messages aux dossiers. Il contient des objets Mail::Box qui peuvent être de différents types. La plupart des types de dossiers peuvent être détectés automatiquement.

Le gestionnaire principal gère également les objets de détection de fils de discussion de messages, et les informe lorsque le contenu d'un dossier a changé. Cette classe de gestionnaire est la seule que vous instanciez vous-même : les objets de toutes les autres classes vous seront fournis par votre gestionnaire de dossiers.

Il est fortement conseillé d'utiliser cet objet, mais vous pouvez souvent vous en passer et ouvrir directement un type de dossier spécifique.

Les Messages

Mail::Message
Une classe de base qui définit une interface pour manipuler l'en-tête et le corps d'un message. Il existe divers types d'objets d'en-tête (les Mail::Message::Head) et une série d'objets de corps (les Mail::Message::Body).

Le paquet Mail::Message::Construct est chargé lorsque des tâches plus complexes doivent être effectuées sur les messages, comme la création de réponses, de renvois ou d'un message transféré. Ces fonctionnalités sont décrites et implémentées dans le fichier ::Construct, mais sont automatiquement ajoutées à l'espace de noms Mail::Message lorsqu'elles sont utilisées.

Les types de messages étrangers à MailBox peuvent être utilisés dans l'environnement MailBox : il existe quelques convertisseurs implémentés via Mail::Message::Convert. Notamment les populaires Mail::Internet et MIME::Entity sont pris en charge.

Mail::Box::Message
Une classe de base abstraite qui définit une interface pour les messages électroniques stockés dans n'importe quel dossier. Elle hérite de Mail::Message, et ajoute l'idée de base d'*emplacement* à un message.
Mail::Message::Body
C'est la classe de base pour tous les corps de messages. Elle décrit ce que vous pouvez faire avec n'importe quel type de corps. Les types de corps diffèrent par la manière dont ils conservent le contenu du corps pendant l'exécution de votre programme.

Un cas particulier des types de corps est le Mail::Message::Body::Multipart, qui contient un ensemble d'objets Mail::Message::Part. Ceux-ci sont comme des messages normaux, sauf qu'ils sont contenus dans un autre message. Le type de corps Mail::Message::Body::Nested est comparable, mais ne contient qu'un seul message : ils sont utilisés pour les encodages de messages "message/rfc822".

Si nécessaire, la fonctionnalité des objets corps est étendue avec Mail::Message::Body::Construct et Mail::Message::Body::Encode. Le premier paquet implémente des choses comme la concaténation

Les types de dossiers

Mail::Box
Une classe de base qui définit une interface standard pour les boîtes aux lettres indépendantes du type de boîte. Les objets de cette classe contiennent un Mail::Box::Locker et une liste d'objets Mail::Box::Message.
Mail::Box::Dir
La classe de base pour tous les dossiers qui utilisent une organisation de répertoires : chaque message est un objet séparé (fichier) groupé dans un répertoire. Chaque Mail::Box::Dir::Message représente un message, une telle entité.
Mail::Box::Net
La classe de base pour tous les dossiers qui ont des messages hors de la portée directe du MailBox Locker, par exemple sur un système distant ou dans une base de données.
Mail::Box::Mbox
Cette classe dérive de Mail::Box et implémente son interface pour les dossiers de style mbox. Elle maintient un ensemble d'objets Mail::Box::Mbox::Message, qui dérivent d'un Mail::Box::Message.
Mail::Box::MH
Cette classe dérive de Mail::Box::Dir et implémente son interface pour les dossiers de style MH. Elle maintient un ensemble d'objets Mail::Box::MH::Message, qui dérivent d'un Mail::Box::Dir::Message.
Mail::Box::MH::Index
La classe de base pour les index de dossiers MH qui fournit des méthodes pour lire, écrire et gérer les index de messages. Ces index sont utilisés pour accélérer l'accès aux dossiers basés sur des répertoires.
Mail::Box::MH::Labels
Outre des raisons d'efficacité, un fichier séparé est maintenu contenant des signaux sur les messages. Ce fichier liste par exemple les nouveaux fichiers. De cette façon, les fichiers de messages MH n'ont pas besoin d'être ouverts pour trouver cela.
Mail::Box::Maildir
Comme le dossier de type MH, cette classe dérive de Mail::Box::Dir. Elle implémente son interface pour les dossiers de style Maildir. Elle maintient un ensemble d'objets Mail::Box::Maildir::Message, qui dérivent d'un Mail::Box::Dir::Message.
Mail::Box::POP3
Implémente le protocole POP3 basé sur Mail::Box::Net. L'implémentation de Mail::Transport::POP3 gère les détails du protocole. Dans ce type de dossiers, vous ne pouvez que lire et supprimer des messages.

Divers autres classes

Mail::Box::Thread::Manager
Gère un ensemble de fils de discussion de messages sur un ou plusieurs dossiers. Un fil de discussion de messages est un message initial avec toutes les réponses dedans. Et les réponses aux réponses, et ainsi de suite. Cet objet est utilisé pour construire le fil de discussion pour un ensemble de dossiers ouverts.

Cet objet maintient des listes chaînées d'objets Mail::Box::Thread::Node. Les Mail::Message::Dummy comblent certains manques.

Mail::Box::Locker
Fournit une interface de verrouillage de dossier qui est héritée par la classe Mail::Box. Actuellement, elle supporte le verrouillage avec des fichiers de type .lock ("filename.lock"), le verrouillage avec un descripteur de fichier flock et le verrouillage sur NFS. Chacun est implémenté dans une classe séparée. Un multi-locker qui utilise plusieurs méthodes de verrouillage en même temps peut également être utilisé.
Mail::Box::Search
L'ensemble des paquets de recherche implémente des techniques de recherche de manière uniforme. Bien qu'implémenter son propre algorithme de recherche soit généralement simple, en pratique, les multiparts, les encodages et les types MIME compliquent les choses.
Mail::Box::Parser
Le parseur lit les messages et les transforme en structures de données qui permettent d'utiliser le contenu de l'en-tête et du corps dans le programme. Le premier parseur est implémenté en pur Perl. Un second parseur est en cours de développement et sera écrit en C pour gagner en vitesse.
Mail::Box::Tie
Fournit un accès à n'importe quel dossier de messagerie dérivé de Mail::Box via un hash (Mail::Box::Tie::HASH) ou un tableau (Mail::Box::Tie::ARRAY). Cela améliore votre code dans certaines applications.
Mail::Transport
Implémente différentes manières d'envoyer et de recevoir des messages. L'envoi est possible via des programmes externes, tels que "mail", "Mailx", "sendmail" ou de manière autonome avec SMTP direct. La réception est actuellement implémentée uniquement via POP3.
Mail::Reporter
Une classe de débogage et de journalisation qui est héritée par la plupart des modules Mail::. Pour chaque objet, vous pouvez spécifier quels rapports d'erreur et journaux doivent être conservés ou directement présentés à l'utilisateur. Ainsi, vous pouvez décider que Mail::Box rapporte les problèmes, ou le faire vous-même.

Toutes les classes sont écrites pour être extensibles.
