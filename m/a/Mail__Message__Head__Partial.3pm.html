NOM

Mail::Message::Head::Partial - sous-ensemble des informations d'en-tête d'un message

HÉRÉDITÉ

Mail::Message::Head::Partial
  est un Mail::Message::Head::Complete
  est un Mail::Message::Head
  est un Mail::Reporter

SYNOPIS

my $partial = $head->strip;
$partial->isa('Mail::Message::Head')  # vrai
$partial->isDelayed                   # faux
$partial->isPartial                   # vrai
$partial->removeFields( qr/^X-/ );
$partial->removeFieldsExcept( qw/To From/ );
$partial->removeResentGroups;
$partial->removeListGroup;
$partial->removeSpamGroups;

DESCRIPTION

Les informations d'en-tête consomment une quantité de mémoire considérable. La plupart de ces informations ne sont utiles que pendant une courte période dans votre programme, ou parfois elles ne sont pas utilisées du tout. Vous pouvez alors décider de supprimer la plupart des informations d'en-tête. Cependant, attention, elles seront perdues définitivement : l'en-tête (et donc le message) sera mutilé !

L'en-tête maintient une liste de champs qui sont ordonnés selon leur séquence de définition. Il est nécessaire de maintenir l'ordre de l'en-tête pour garder les champs associés des groupes renvoyés ensemble. Les champs sont également inclus dans une table de hachage, triés par leur nom pour un accès rapide.

Les références aux objets de champ dans la table de hachage sont réelles, celles dans la liste ordonnée sont faibles. Donc, lorsque les objets de champ sont retirés de la table de hachage, leurs références dans la liste ordonnée sont automatiquement mis à "undef".

Lorsque de nombreux champs sont supprimés, par exemple avec removeFields() ou removeFieldsExcept(), il est utile de supprimer également la liste des undefs de la liste ordonnée. Dans ces cas, cette méthode est appelée automatiquement, mais vous pouvez avoir vos propres raisons d'appeler cette méthode.

$obj->removeFields( <CHAÎNE|Regexp>, ... )
Supprime les champs de l'en-tête qui sont nommés exactement '"CHAÎNE"' (insensible à la casse) ou qui correspondent à l'expression régulière. N'oubliez pas d'ajouter le modificateur 'i' à l'expression régulière, car les champs sont insensibles à la casse.

Voir aussi removeField() qui est utilisée pour supprimer un objet de champ de l'en-tête. La spécification inverse peut être faite avec removeFieldsExcept(). Améliore la base, voir "Access to the header" dans Mail::Message::Head::Complete

Réduction de la taille de l'en-tête

Un en-tête de message est très coûteux en mémoire et assez volumineux sur disque, il est donc un bon candidat pour la réduction de taille. Une façon de réduire la taille est simplement de supprimer les champs superflus. Chaque champ coûte au moins 100 octets en mémoire à l'exécution, donc cela peut aider !

Avant de commencer à jouer avec removeFields() et removeFieldsExcept(), vous pouvez considérer deux grands groupes de champs qui peuvent être supprimés en tant qu'ensembles : les en-têtes resent et les en-têtes de liste de diffusion.

Les en-têtes resent décrivent les étapes intermédiaires dans le processus de transmission des messages. Après une livraison réussie, ils sont rarement utiles.

Lors de l'archivage d'une liste de diffusion, il est rare de stocker les lignes d'administration de la liste pour chaque message.

» voir examples/reduce.pl dans la distribution

   $msg->head->removeResentList;

DIAGNOSTICS

Warning: Cannot remove field $name from header: not found.
Vous demandez la suppression d'un champ qui n'est pas connu dans l'en-tête. Utiliser delete(), reset() ou set() pour effectuer le travail ne générera pas d'avertissement : ces méthodes vérifient d'abord l'existence du champ. Transmis par removeField()
Warning: Field objects have an implied name ($name)
Transmis par build()
Error: Package $package does not implement $method.
Erreur : Le paquet $package n'implémente pas $method. Error_FATAL : le paquet spécifié (ou l'une de ses superclasses) n'implémente pas cette méthode alors qu'il devrait. Ce message signifie que d'autres classes associées implémentent cette méthode alors que la classe en question ne le fait pas. Vous devriez probablement enquêter sur cela et probablement signaler l'auteur du paquet. Transmis par notImplemented()
