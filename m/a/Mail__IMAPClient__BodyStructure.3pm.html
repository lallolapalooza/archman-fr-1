Mail::IMAPClient::BodyStructure(3) Documentation Perl fournie par l'utilisateur Mail::IMAPClient::BodyStructure(3)

NOM

Mail::IMAPClient::BodyStructure - analyse les résultats récupérés

SYNTAXE

use Mail::IMAPClient;
use Mail::IMAPClient::BodyStructure;
my $imap = Mail::IMAPClient->new(
    Server => $server, User => $login, Password => $pass
);
$imap->select("INBOX") or die "Impossible de sélectionner INBOX : $@\n";
my @recent = $imap->search("recent") or die "Aucun message récent dans INBOX\n";
foreach my $id (@recent) {
    my $bsdat = $imap->fetch( $id, "bodystructure" );
    my $bso   = Mail::IMAPClient::BodyStructure->new( join("", $imap->History) );
    my $mime  = $bso->bodytype . "/" . $bso->bodysubtype;
    my $parts = map( "\n\t" . $_, $bso->parts );
    print "Msg $id (Type de contenu : $mime) contient ces parties :$parts\n";
}

DESCRIPTION

Cette extension analyse le résultat d'une commande IMAP FETCH BODYSTRUCTURE en une structure de données Perl. Elle fournit également des méthodes d'aide pour extraire des informations de la structure de données.

Ce module nécessite Parse::RecDescent.

Méthodes de classe

La méthode de classe suivante est disponible :

new

Cette méthode de classe est la méthode constructeur pour instancier de nouveaux objets Mail::IMAPClient::BodyStructure. La méthode new accepte un argument, une chaîne contenant une réponse du serveur à une directive FETCH BODYSTRUCTURE.

Le module Mail::IMAPClient fournit la méthode pratique get_bodystructure pour simplifier l'utilisation de ce module lorsque l'on commence avec juste un numéro de séquence de message ou un identifiant unique (UID).

Méthodes d'objet

Les méthodes d'objet suivantes sont disponibles :

bodytype

La méthode d'objet bodytype ne nécessite aucun argument. Elle renvoie le type de corps du message dont la structure est décrite par l'objet appelant Mail::IMAPClient::Bodystructure.

bodysubtype

La méthode d'objet bodysubtype ne nécessite aucun argument. Elle renvoie le sous-type de corps du message dont la structure est décrite par l'objet appelant Mail::IMAPClient::Bodystructure.

bodyparms

La méthode d'objet bodyparms ne nécessite aucun argument. Elle renvoie les paramètres du corps du message dont la structure est décrite par l'objet appelant Mail::IMAPClient::Bodystructure.

bodydisp

La méthode d'objet bodydisp ne nécessite aucun argument. Elle renvoie la disposition du corps du message dont la structure est décrite par l'objet appelant Mail::IMAPClient::Bodystructure.

bodyid

La méthode d'objet bodyid ne nécessite aucun argument. Elle renvoie l'identifiant du corps du message dont la structure est décrite par l'objet appelant Mail::IMAPClient::Bodystructure.

bodydesc

La méthode d'objet bodydesc ne nécessite aucun argument. Elle renvoie la description du corps du message dont la structure est décrite par l'objet appelant Mail::IMAPClient::Bodystructure.

bodyenc

La méthode d'objet bodyenc ne nécessite aucun argument. Elle renvoie l'encodage du corps du message dont la structure est décrite par l'objet appelant Mail::IMAPClient::Bodystructure.

bodysize

La méthode d'objet bodysize ne nécessite aucun argument. Elle renvoie la taille du corps du message dont la structure est décrite par l'objet appelant Mail::IMAPClient::Bodystructure.

bodylang

La méthode d'objet bodylang ne nécessite aucun argument. Elle renvoie la langue du corps du message dont la structure est décrite par l'objet appelant Mail::IMAPClient::Bodystructure.

bodystructure

La méthode d'objet bodystructure ne nécessite aucun argument. Elle renvoie la structure du corps du message dont la structure est décrite par l'objet appelant Mail::IMAPClient::Bodystructure.

envelopestruct

La méthode d'objet envelopestruct ne nécessite aucun argument. Elle renvoie un objet Mail::IMAPClient::BodyStructure::Envelope pour le message de l'objet appelant Mail::IMAPClient::Bodystructure.

textlines

La méthode d'objet textlines ne nécessite aucun argument. Elle renvoie les lignes de texte du message dont la structure est décrite par l'objet appelant Mail::IMAPClient::Bodystructure.

Mail::IMAPClient::BodyStructure::Envelope

La norme IMAP spécifie que la sortie de la commande IMAP FETCH ENVELOPE sera une structure d'enveloppe RFC2060. Elle spécifie en outre que la sortie de la commande FETCH BODYSTRUCTURE peut également contenir des structures d'enveloppe imbriquées (si, par exemple, les sous-parties d'un message contiennent un ou plusieurs messages inclus). Les objets appartenant à Mail::IMAPClient::BodyStructure::Envelope sont des représentations Perl de ces structures d'enveloppe, c'est-à-dire les listes parenthésées imbriquées de RFC2060 traduites en une structure de données Perl.

Notez que tous les champs sont relatifs à la partie spécifique à laquelle ils appartiennent. Autrement dit, la sortie d'une commande FETCH nnnn ENVELOPE (ou, dans Mail::IMAPClient, "$imap-"fetch($msgid,"ENVELOPE")> ou "my $env = $imap-"get_envelope($msgid)>) concerne le message, mais les champs provenant d'une structure de corps concernent la sous-partie du message et non le message parent.

La représentation Mail::IMAPClient::BodyStructure::Envelope d'une structure d'enveloppe est une table de hachage d'éléments qui ressemble à ceci :

{
   subject   => "sujet",
   inreplyto => "id_message_de_référence",
   from      => [ structure_adresse1 ],
   messageid => "id_message",
   bcc       => [ structure_adresse1, structure_adresse2 ],
   date      => "Mar, 09 Juil 2002 14:15:53 -0400",
   replyto   => [ structure_adresse1, structure_adresse2 ],
   to        => [ structure_adresse1, structure_adresse2 ],
   sender    => [ structure_adresse1 ],
   cc        => [ structure_adresse1, structure_adresse2 ],
}

L'objet ...::Envelope dispose également de méthodes pour accéder aux données de la structure. Ce sont :

date
Renvoie la date du message.
inreplyto
Renvoie l'identifiant du message auquel ce message répond.
subject
Renvoie le sujet du message.
messageid
Renvoie l'identifiant du message.

Vous pouvez également utiliser les méthodes suivantes pour obtenir des informations d'adressage. Chacune de ces méthodes renvoie un tableau d'objets Mail::IMAPClient::BodyStructure::Address, qui sont des structures de données Perl représentant des structures d'adresses RFC2060. Certains de ces tableaux contiendront naturellement un seul élément (tel que from, qui contient normalement une seule adresse "From:") ; d'autres contiendront souvent plus d'une adresse. Cependant, comme RFC2060 définit toutes ces éléments comme des "listes de structures d'adresses", elles sont toutes traduites en tableaux d'objets ...::Address.

Mail::IMAPClient::BodyStructure(3pm)

NAME

Mail::IMAPClient::BodyStructure::Envelope - An object representing the envelope of an IMAP message

SYNOPSIS

    use Mail::IMAPClient;

    my $imap = Mail::IMAPClient->new(
        ...
    );

    my $message = $imap->get_message( 1 ); # Get a message object
    my $envelope = $message->get_envelope();

    my @to = $envelope->to();
    my @from = $envelope->from();
    my @cc = $envelope->cc();
    my @bcc = $envelope->bcc();
    my @replyto = $envelope->replyto();
    my @sender = $envelope->sender();

    my @to_addrs = $envelope->to_addresses();
    my @from_addrs = $envelope->from_addresses();
    my @cc_addrs = $envelope->cc_addresses();
    my @bcc_addrs = $envelope->bcc_addresses();
    my @replyto_addrs = $envelope->replyto_addresses();
    my @sender_addrs = $envelope->sender_addresses();

DESCRIPTION

This module is part of the Mail::IMAPClient distribution. It represents the envelope of a message, as returned by the IMAP protocol's FETCH command with the ENVELOPE data. It is not meant to be used directly, but rather is returned by the Mail::IMAPClient::get_envelope() method.

The envelope is composed of a number of address fields. See Mail::IMAPClient::BodyStructure::Address, below, for alternate (and preferred) ways of accessing these data.

Object Methods

The methods available are:

bcc
Returns an array of blind cc'ed recipients' address structures. (Don't expect much in here unless the message was sent from the mailbox you're poking around in, by the way.)
cc
Returns an array of cc'ed recipients' address structures.
from
Returns an array of "From:" address structures--usually just one.
replyto
Returns an array of "Reply-to:" address structures. Once again there is usually just one address in the list.
sender
Returns an array of senders' address structures--usually just one and usually the same as from.
to
Returns an array of recipients' address structures.

Each of the methods that returns a list of address structures (i.e. a list of Mail::IMAPClient::BodyStructure::Address arrays) also has an analogous method that will return a list of E-Mail addresses instead. The addresses are in the format "personalname <mailboxname@hostname>" (see the section on Mail::IMAPClient::BodyStructure::Address, below) However, if the personal name is 'NIL' then it is omitted from the address.

These methods are:

bcc_addresses
Returns a list (or an array reference if called in scalar context) of blind cc'ed recipients' email addresses. (Don't expect much in here unless the message was sent from the mailbox you're poking around in, by the way.)
cc_addresses
Returns a list of cc'ed recipients' email addresses. If called in a scalar context it returns a reference to an array of email addresses.
from_addresses
Returns a list of "From:" email addresses. If called in a scalar context it returns the first email address in the list. (It's usually a list of just one anyway.)
replyto_addresses
Returns a list of "Reply-to:" email addresses. If called in a scalar context it returns the first email address in the list.
sender_addresses
Returns a list of senders' email addresses. If called in a scalar context it returns the first email address in the list.
to_addresses
Returns a list of recipients' email addresses. If called in a scalar context it returns a reference to an array of email addresses.

Note that context affects the behavior of all of the above methods.

Those fields that will commonly contain multiple entries (i.e. they are recipients) will return an array reference when called in scalar context. You can use this behavior to optimize performance.

Those fields that will commonly contain just one address (the sender's) will return the first (and usually only) address. You can use this behavior to optimize your development time.

Addresses and the Mail::IMAPClient::BodyStructure::Address

Several components of an envelope structure are address structures. They are each parsed into their own object, Mail::IMAPClient::BodyStructure::Address, which looks like this:

{
   mailboxname  => 'somebody.special',
   hostname     => 'somplace.weird.com'
   personalname => 'Somebody Special
   sourceroute  => 'NIL'
}

RFC2060 specifies that each address component of a bodystructure is a list of address structures, so Mail::IMAPClient::BodyStructure parses each of these into an array of Mail::IMAPClient::BodyStructure::Address objects.

Each of these objects has the following methods available to it:

mailboxname
Returns the "mailboxname" portion of the address, which is the part to the left of the '@' sign.
hostname
Returns the "hostname" portion of the address, which is the part to the right of the '@' sign.
personalname
Returns the "personalname" portion of the address, which is the part of the address that's treated like a comment.
sourceroute
Returns the "sourceroute" portion of the address, which is typically "NIL".

Taken together, the parts of an address structure form an address that will look something like this:

"personalname <mailboxname@hostname>"

Note that because the Mail::IMAPClient::BodyStructure::Address objects come in arrays, it's generally easier to use the methods available to Mail::IMAPClient::BodyStructure::Envelope to obtain all of the addresses in a particular array in one operation. These methods are provided, however, in case you'd rather do things the hard way. (And also because the aforementioned methods from Mail::IMAPClient::BodyStructure::Envelope need them anyway.)
