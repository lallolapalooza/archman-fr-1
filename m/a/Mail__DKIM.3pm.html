NOM

Mail::DKIM - Signe/vérifie les courriels Internet avec des signatures DKIM/DomainKey

VERSION

version 1.20240923

SYNTAXE

# vérifier un message
use Mail::DKIM::Verifier;
# créer un objet vérificateur
my $dkim = Mail::DKIM::Verifier->new();
# lire un email depuis stdin, le passer au vérificateur
while (<STDIN>)
{
    # supprimer les terminaisons de ligne locales
    chomp;
    s/\015$//;
    # utiliser les terminaisons de ligne SMTP
    $dkim->PRINT("$_\015\012");
}
$dkim->CLOSE;
# quel est le résultat de la vérification ?
my $result = $dkim->result;

DESCRIPTION

Ce module implémente les différentes composantes des normes de signature et de vérification de messages DKIM et DomainKeys pour les courriels Internet. Il essaie actuellement d'implémenter ces spécifications :

RFC4871, pour DKIM
RFC4870, pour DomainKeys
draft-ietf-dmarc-arc-protocol-06, pour ARC

Le module utilise une interface orientée objet. Vous utilisez l'une des deux classes différentes, en fonction de si vous signez ou vérifiez un message. Pour signer, utilisez la classe Mail::DKIM::Signer. Pour vérifier, utilisez la classe Mail::DKIM::Verifier. Simple, n'est-ce pas ?

De même pour ARC, utilisez les modules ARC Mail::DKIM::ARC::Signer et Mail::DKIM::ARC::Verifier

Si vous envoyez à des bibliothèques de test qui attendent que les balises dans les en-têtes soient triées, vous pouvez définir $Mail::DKIM::SORTTAGS à une valeur vraie, et tous les en-têtes créés auront des clés triées.

BUGS CONNUS

Les problèmes lors de l'exécution de `make test' semblent généralement pointer vers une configuration DNS défectueuse sur votre machine, ou quelque chose d'étrange avec vos bibliothèques OpenSSL.

La composante "politique de signature de l'auteur" est encore en cours de construction. La politique de signature de l'auteur est censée identifier la pratique de l'auteur du message, vous pourriez donc par exemple rejeter un message d'un auteur qui prétend toujours signer ses messages. Voir Mail::DKIM::Policy.
