NOM

Mail::DKIM::DkimPolicy - représente une règle de politique de signature d'envoi

VERSION

version 1.20240923

DESCRIPTION

La règle de politique de signature d'envoi (SSP) peut être publiée par n'importe quel domaine pour aider un destinataire à savoir quoi faire lorsqu'il rencontre un message non signé qui semble provenir de ce domaine.

La règle est publiée sous forme d'enregistrement TXT dans _policy._domainkey.DOMAIN où DOMAIN est le domaine de l'adresse e-mail "From" du message.

Cette forme de règle a été supplantée par ADSP. Voir Mail::DKIM::AuthorDomainPolicy pour des informations sur ADSP. Cette implémentation est incluse car, en fait, il semblait qu'elle deviendrait standard par l'IETF. Cette règle sera supprimée de Mail::DKIM à l'avenir. La dernière version de la spécification SSP se trouve à l'adresse http://tools.ietf.org/html/draft-ietf-dkim-ssp-02.

CONSTRUCTEURS

fetch()

Interroge une règle de politique de signature d'envoi.

my $policy = Mail::DKIM::DkimPolicy->fetch(
          Protocol => 'dns',
          Author => 'jsmith@example.org',
        );

new()

Crée un objet de politique par défaut.

my $policy = Mail::DKIM::DkimPolicy->new;

MÉTHODES

apply()

Applique la politique aux résultats d'un vérificateur DKIM.

my $result = $policy->apply($dkim_verifier);

L'appelant doit fournir une instance de Mail::DKIM::Verifier, dont l'une a déjà été alimentée avec le message en cours de vérification.

Les résultats possibles sont :

accept
Le message est approuvé par la politique de signature d'envoi.
reject
Le message est rejeté par la politique de signature d'envoi. Il peut être considéré comme très suspect.
neutral
Le message n'est ni approuvé ni rejeté par la politique de signature d'envoi. Il peut être considéré comme quelque peu suspect.

flags()

Obtenir ou définir le tag (t=) des indicateurs.

Une liste d'indicateurs séparés par des deux-points. Les valeurs des indicateurs sont :

y
L'entité teste les pratiques de signature d'envoi, et le vérificateur NE DEVRAIT PAS considérer un message suspect sur la base de cette règle.
s
Les pratiques de signature d'envoi s'appliquent uniquement au domaine nommé, et non à ses sous-domaines.

is_implied_default_policy()

Cette politique est-elle implicite ?

my $is_implied = $policy->is_implied_default_policy;

Si vous récupérez la politique pour un domaine spécifique mais que ce domaine n'a pas de politique publiée, alors la politique par défaut s'appliquera. Utilisez cette méthode pour détecter quand cela se produit.

location()

Où la politique a été obtenue.

Si la politique est à l'échelle du domaine, ce sera le domaine où la politique a été publiée.

Si la politique est spécifique à l'utilisateur, TBD.

S'il n'y a pas de politique publiée pour le domaine et que la politique par défaut a été renvoyée à la place, l'emplacement sera "undef".

policy()

Obtenir ou définir la politique de signature d'envoi (dkim=) de l'entité.

my $sp = $policy->policy;

La politique de signature d'envoi pour l'entité. Les valeurs possibles sont :

"unknown"
La valeur par défaut. L'entité peut signer certains ou tous les e-mails.
"all"
Tous les e-mails de l'entité sont signés. (La signature DKIM peut utiliser n'importe quel domaine, pas nécessairement celui de l'adresse From :).
"strict"
Tous les e-mails de l'entité sont signés avec des signatures d'origine. (La signature DKIM utilise un domaine qui correspond à l'adresse From :).

signall()

Vrai si la politique est "all".

signall_strict()

Vrai si la politique est "strict".

testing()

Vérifie l'indicateur de test.

my $testing = $policy->testing;

Si différent de zéro, l'indicateur de test est défini dans la politique de signature d'envoi, et le vérificateur ne devrait pas considérer un message suspect sur la base de cette politique.

BOGUES

•
Si aucune politique de signature d'envoi n'est trouvée pour un domaine donné, la méthode fetch() devrait rechercher les domaines parents comme spécifié dans la section 4 du draft-ietf-dkim-ssp-02.
