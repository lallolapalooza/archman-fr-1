NOM

URIDNSBL - interroger les listes noires DNS pour les URLs

SYNOPIS

loadplugin    Mail::SpamAssassin::Plugin::URIDNSBL
uridnsbl      URIBL_SBLXBL    sbl-xbl.spamhaus.org.   TXT

DESCRIPTION

Cela fonctionne en analysant le texte des messages et le HTML à la recherche d'URLs, en en extrayant les noms d'hôtes, puis en interrogeant diverses listes noires DNS pour soit : les adresses IP de ces hôtes (uridnsbl,a), soit leurs serveurs de noms (uridnsbl,ns), soit les noms de domaine de ces hôtes (urirhsbl), soit les noms de domaine de leurs serveurs de noms (urinsrhsbl, urifullnsrhsbl).

RÉGLAGES UTILISATEUR

skip_uribl_checks ( 0 | 1 ) (défaut: 0)
L'activation du réglage skip_uribl_checks désactivera le plugin URIDNSBL.

Par défaut, SpamAssassin effectuera les vérifications URIDNSBL. Les listes noires d'URL individuelles peuvent être désactivées sélectivement en réglant le score d'une règle correspondante à 0 ou via le paramètre uridnsbl_skip_domain.

Voir aussi le paramètre de configuration lié skip_rbl_checks, qui contrôle le plugin DNSEval (documenté dans la page man Conf).

uridnsbl_skip_domain domaine1 domaine2 ...
Spécifiez un domaine, ou un certain nombre de domaines, qui doivent être ignorés pour les vérifications URIBL. Ceci est très utile pour spécifier des domaines très courants qui ne seront pas listés dans les URIBLs.

En plus du domaine tronqué, le nom d'hôte complet est également vérifié à partir de la liste.

clear_uridnsbl_skip_domain [domaine1 domaine2 ...]
Si aucun argument n'est donné, cela efface toute la liste des domaines déclarés par les directives de configuration uridnsbl_skip_domain jusqu'à présent. Toutes les directives uridnsbl_skip_domain ultérieures commenceront par créer une nouvelle liste de domaines à ignorer.

Lorsqu'une liste de domaines est donnée en arguments, seuls les domaines spécifiés sont retirés de la liste des domaines ignorés.

DÉFINITIONS DE RÈGLES ET RÉGLAGES PRIVILÉGIÉS

uridnsbl NOM_DE_RÈGLE zone_dnsbl type_interrogation
Spécifie une interrogation. "NOM_DE_RÈGLE" est le nom de la règle à utiliser, "zone_dnsbl" est la zone dans laquelle interroger les IPs, et "type_interrogation" est le type d'interrogation (TXT ou A). Notez que vous devez également définir une règle d'évaluation de corps appelant check_uridnsbl() pour l'utiliser.

Cela fonctionne en collectant les noms de domaine des URLs et en interrogeant les listes noires DNS avec une adresse IP des noms d'hôtes trouvés dans les URLs ou avec les adresses IP de leurs serveurs de noms, conformément aux tflags comme suit.

Si la règle de corps correspondante a un tflag 'a', la liste noire DNS sera interrogée avec une adresse IP d'un hôte trouvé dans les URLs.

Si la règle de corps correspondante a un tflag 'ns', les DNS seront interrogés pour les serveurs de noms (enregistrements NS) d'un nom de domaine trouvé dans les URLs, puis ces noms de serveurs de noms seront résolus en leurs adresses IP, qui seront à leur tour envoyées à la liste noire DNS.

La directive Tflags peut spécifier soit 'a', soit 'ns', soit les deux drapeaux. En l'absence de l'un de ces deux drapeaux, la valeur par défaut est 'ns', ce qui est compatible avec les versions antérieures à 3.4 de SpamAssassin.

Le choix des tflags doit correspondre à la politique et à l'utilisation attendue de chaque liste noire DNS et n'est normalement pas une décision locale. Par exemple, une liste noire attendant des interrogations résultant d'un tflag 'a' est une "black_a.txt" ( http://www.uribl.com/datasets.shtml ).

Exemple:

uridnsbl        URIBL_SBLXBL    sbl-xbl.spamhaus.org.   TXT
body            URIBL_SBLXBL    eval:check_uridnsbl('URIBL_SBLXBL')
describe        URIBL_SBLXBL    Contient une URL listée dans la liste noire SBL/XBL
tflags          URIBL_SBLXBL    net ns
uridnssub NOM_DE_RÈGLE zone_dnsbl type_interrogation sous-test
Spécifie une interrogation de domaine de type DNSBL avec un sous-test. "NOM_DE_RÈGLE" est le nom de la règle à utiliser, "zone_dnsbl" est la zone dans laquelle interroger les IPs, et "type_interrogation" est le type d'interrogation (TXT ou A).

Les tflags 'ns' et 'a' sur une règle de corps correspondante sont reconnus et ont la même signification que dans la directive uridnsbl.

"sous-test" est un sous-test à exécuter sur les données retournées. Le sous-test peut prendre l'une des formes suivantes : m, n1-n2, ou n/m, où n,n1,n2,m peuvent être : des chiffres décimaux, 0x suivi jusqu'à 8 chiffres hexadécimaux, ou une adresse IPv4 sous forme quad-point. Les enregistrements 'A' (adresse IPv4 pointée) retournés par les interrogations DNSBL sont convertis en une forme numérique (r) et comparés au sous-test spécifié comme suit : pour une plage n1-n2, ce qui suit doit être vrai : (r >= n1 && r <= n3) ; pour une forme n/m, ce qui suit doit être vrai : (r & m) == (n & m) ; pour une valeur unique en quad-point, ce qui suit doit être vrai : r == n ; pour une valeur unique décimale ou hexadécimale, ce qui suit doit être vrai :
((r & n) != 0) && ((r & 0xff000000) == 0x7f000000), c'est-à-dire dans 127.0.0.0/8

Quelques exemples typiques de sous-test sont : 127.0.1.2, 127.0.1.20-127.0.1.39, 127.0.1.0/255.255.255.0, 0.0.0.16/0.0.0.16, 0x10/0x10, 16, 0x10 .

Notez que, comme pour "uridnsbl", vous devez également définir une règle d'évaluation de corps appelant check_uridnsbl() pour l'utiliser.

Exemple:

uridnssub   URIBL_DNSBL_4    dnsbl.example.org.   A    127.0.0.4
uridnssub   URIBL_DNSBL_8    dnsbl.example.org.   A    8
urirhsbl NOM_DE_RÈGLE zone_rhsbl type_interrogation
Spécifie une interrogation de domaine de type RHSBL. "NOM_DE_RÈGLE" est le nom de la règle à utiliser, "zone_rhsbl" est la zone dans laquelle interroger les noms de domaine, et "type_interrogation" est le type d'interrogation (TXT ou A). Notez que vous devez également définir une règle d'évaluation de corps appelant check_uridnsbl() pour l'utiliser.

Une zone RHSBL est une zone où le nom de domaine est interrogé, en tant que chaîne ; par exemple, une URL utilisant le domaine "foo.com" provoquera une interrogation de "foo.com.uriblzone.net". Notez que les noms d'hôtes sont tronqués à la partie domaine dans l'interrogation URIBL, donc le domaine "foo.bar.com" interrogera "bar.com.uriblzone.net", et "foo.bar.co.uk" interrogera "bar.co.uk.uriblzone.net". L'utilisation du tflag "notrim" forcera une interrogation du nom d'hôte complet, mais l'uribl spécifique doit supporter cette méthode.

Si une URL consiste en une adresse IP au lieu d'un nom d'hôte, l'adresse IP est interrogée (en utilisant la méthode standard des quads inversés) dans chaque "zone_rhsbl".

Exemple:

urirhsbl        URIBL_RHSBL    rhsbl.example.org.   TXT
urirhssub NOM_DE_RÈGLE zone_rhsbl type_interrogation sous-test
Spécifie une interrogation de domaine de type RHSBL avec un sous-test. "NOM_DE_RÈGLE" est le nom de la règle à utiliser, "zone_rhsbl" est la zone dans laquelle interroger les noms de domaine, et "type_interrogation" est le type d'interrogation (TXT ou A).

"sous-test" est un sous-test à exécuter sur les données retournées. Le sous-test peut prendre l'une des formes suivantes : m, n1-n2, ou n/m, où n,n1,n2,m peuvent être : des chiffres décimaux, 0x suivi jusqu'à 8 chiffres hexadécimaux, ou une adresse IPv4 sous forme quad-point. ((r & n) != 0) && ((r & 0xff000000) == 0x7f000000), c'est-à-dire dans 127.0.0.0/8

Quelques exemples typiques de sous-test sont : 127.0.1.2, 127.0.1.20-127.0.1.39, 127.0.1.0/255.255.255.0, 0.0.0.16/0.0.0.16, 0x10/0x10, 16, 0x10 .

Notez que, comme pour "urirhsbl", vous devez également définir une règle d'évaluation de corps appelant check_uridnsbl() pour l'utiliser.

Exemple:

urirhssub   URIBL_RHS_SUB_4    rhsbl.example.org.   A    127.0.0.4
urirhssub   URIBL_RHS_SUB_8    rhsbl.example.org.   A    8

EXEMPLES

Pour utiliser ce plugin, vous devez d'abord charger le plugin dans votre fichier de configuration (par défaut, le fichier est ~/.spamassassin/v310.pre ou /etc/mail/spamassassin/init.pre), puis définir une ou plusieurs règles.

La configuration par défaut de SpamAssassin inclut la configuration de plusieurs listes noires DNS publiques.

# Chargement du plugin
loadplugin    Mail::SpamAssassin::Plugin::URIDNSBL

# Définitions de règles exemples (les noms de règles et les zones DNSBL peuvent varier)
# pour l'URL domaine.com
uridnsbl        URIBL_SPAMHAUS_SBL    zen.spamhaus.org.   TXT
body            URIBL_SPAMHAUS_SBL    eval:check_uridnsbl('URIBL_SPAMHAUS_SBL')
describe        URIBL_SPAMHAUS_SBL    URL Domain Listed in Spamhaus SBL

# pour l'IP de l'URL
uridnsbl        URIBL_SPAMHAUS_XBL    sbl-xbl.spamhaus.org.   TXT
tflags          URIBL_SPAMHAUS_XBL    a
body            URIBL_SPAMHAUS_XBL    eval:check_uridnsbl('URIBL_SPAMHAUS_XBL')
describe        URIBL_SPAMHAUS_XBL    URL IP Listed in Spamhaus XBL

# Interrogation de la zone RHSBL pour le domaine de l'URL
urirhsbl        URIBL_URIDNSBL_COM    uribl.dnsbl.sorbs.net.  TXT
body            URIBL_URIDNSBL_COM    eval:check_uridnsbl('URIBL_URIDNSBL_COM')
describe        URIBL_URIDNSBL_COM    URL Domain Listed in uribl.dnsbl.sorbs.net

# Ignorer certains domaines de la vérification URIDNSBL
uridnsbl_skip_domain    example.com

NOM

uridnsbl_name NOM_DE_LA_REGLE rhsbl_zone type_de_recherche
Effectue une recherche de domaine de style RHSBL contre le contenu des enregistrements NS pour chaque URI. En d'autres termes, une URI utilisant le domaine "foo.com" provoquera une recherche NS ; en supposant que ce domaine ait un NS de "ns0.bar.com", cela provoquera une recherche de "bar.com.uriblzone.net". Notez que les noms d'hôte sont supprimés à la fois du domaine utilisé dans l'URI et du domaine dans la recherche.
