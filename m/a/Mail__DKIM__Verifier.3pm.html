Mail::DKIM::Verifier(3) Documentation soumise par les utilisateurs de Perl Mail::DKIM::Verifier(3)

NOM

Mail::DKIM::Verifier - vérifie un message DKIM signé

VERSION

version 1.20240923

SYNTAXE

use Mail::DKIM::Verifier;
# créer un objet vérificateur
my $dkim = Mail::DKIM::Verifier->new();
# lire un courriel depuis un flux d'entrée
$dkim->load(*STDIN);
# ou lire un courriel et le passer à la vérification, progressivement
while (<STDIN>)
{
    # supprimer les finisseurs de ligne locaux
    chomp;
    s/\015$//;
    # utiliser les finisseurs de ligne SMTP
    $dkim->PRINT("$_\015\012");
}
$dkim->CLOSE;
# quel est le résultat de la vérification ?
my $result = $dkim->result;
# il y a plusieurs signatures, quel est le résultat par signature ?
foreach my $signature ($dkim->signatures)
{
    print 'identité de la signature : ' . $signature->identity . "\n";
    print 'résultat de la vérification : ' . $signature->result_detail . "\n";
}
# l'auteur invoqué du courriel peut spécifier comment gérer le courriel
foreach my $policy ($dkim->policies)
{
    die 'courriel frauduleux' if ($policy->apply($dkim) eq 'reject');
}

DESCRIPTION

L'objet vérificateur permet de scanner un message électronique à la recherche de signatures DKIM et DomainKeys et de vérifier ces signatures. Le vérificateur suit l'état du message au fur et à mesure de sa lecture en mémoire. Lorsque le message a été entièrement lu, les signatures sont vérifiées et les résultats de la vérification sont accessibles.

Pour utiliser le vérificateur, vous devez d'abord créer l'objet vérificateur. Ensuite, vous devez commencer à "alimenter" le message électronique à vérifier. Lorsque tous les _en-têtes_ ont été lus, le vérificateur :

1. vérifie si des signatures DomainKeys/DKIM ont été trouvées
2. recherche les clés publiques nécessaires pour vérifier les signatures
3. établit les algorithmes et objets de canonicalisation appropriés
4. canonicalise les en-têtes et calcule le hachage des en-têtes

Ensuite, lorsque le _corps_ du message a été entièrement fourni au vérificateur, le hachage du corps est calculé et les signatures sont vérifiées.

Les résultats de la vérification peuvent être vérifiés avec « result() » ou « signatures() ».

Les messages qui ne vérifient pas peuvent être examinés par rapport à la politique de signature publiée par l'expéditeur invoqué avec « policies() » et « apply() » dans Mail::DKIM::Policy.

CONSTRUCTEUR

new()

Crée un objet vérificateur orienté objet.

my $dkim = Mail::DKIM::Verifier->new();
my $dkim = Mail::DKIM::Verifier->new(%options);

Les options actuellement prises en charge sont :

Debug_Canonicalization
Si spécifié, le message canonique pour la première signature est écrit dans la chaîne ou le fichier de sortie référencé.
Strict
Si vrai, rejette les hachages SHA1 et les clés de signature inférieures à 1024 bits.

MÉTHODES

PRINT()

Envoie une partie du message au vérificateur.

$dkim->PRINT("une ligne de message\015\012");
$dkim->PRINT('plus de');
$dkim->PRINT(" le message\015\012au revoir\015\012");

Envoie le contenu du message à vérifier au vérificateur. L'API est conçue de cette manière afin que le message complet N'AIT PAS besoin d'être chargé en mémoire à un seul endroit.

Remarque : bien que la méthode PRINT() s'attende à ce que vous utilisiez les finisseurs de ligne SMTP, vous ne devez pas utiliser la technique de dot-stuffing décrite dans la RFC 2821 section 4.5.2. Vous ne devez pas non plus utiliser une séquence de <CR><LF><CR><LF> pour terminer le message.

CLOSE()

Appelez ceci lorsque vous avez fini d'alimenter le message.

$dkim->CLOSE;

Cette méthode termine le processus de canonicalisation, calcule un hachage et vérifie la signature.

fetch_author_domain_policies()

Récupère les enregistrements ADSP depuis le DNS.

my @policies = $dkim->fetch_author_domain_policies;
foreach my $policy (@policies)
{
    my $policy_result = $policy->apply($dkim);
}

Cette méthode obtiendra toutes les politiques de signature « author-domain-signing-practices » publiées dans le DNS pour ce message. Les politiques de signature sont indexées sur l'adresse électronique dans l'en-tête From :, c'est-à-dire l'auteur invoqué du message.

Cette méthode renvoie une *liste* d'enregistrements de politique, car il peut y avoir 0 ou plusieurs adresses électroniques dans l'en-tête From :.

Le résultat de la méthode apply() est l'un des éléments suivants : « accept », « reject », « neutral ».

Voir également : « policies() ».

fetch_author_policy()

Récupère une politique de signature depuis le DNS.

my $policy = $dkim->fetch_author_policy;
my $policy_result = $policy->apply($dkim);

Cette méthode obtient la règle de signature DKIM Sender Signing Practices telle que décrite dans le brouillon Internet draft-ietf-dkim-ssp-00-01dc. Ce brouillon Internet est maintenant obsolète ; cette méthode est conservée uniquement pour des raisons de rétrocompatibilité.

Veuillez utiliser la méthode « policies() » à la place.

fetch_sender_policy()

Récupère une politique de signature depuis le DNS.

my $policy = $dkim->fetch_sender_policy;
my $policy_result = $policy->apply($dkim);

La politique de « l'expéditeur » est la politique de signature telle que décrite dans la norme DomainKeys, maintenant disponible dans la RFC4870 (historique). J'appelle cette politique « l'expéditeur » car elle est indexée sur l'adresse électronique dans l'en-tête Sender :, ou sur l'en-tête From : s'il n'y a pas d'en-tête Sender. C'est la personne à qui le message prétend être « l'expéditeur » du message (pas nécessairement l'auteur).

Si le courriel en cours de vérification n'a pas d'en-tête From : ou Sender : à partir duquel obtenir une adresse électronique (ce qui viole les normes de messagerie), alors cette méthode "die".

Le résultat de la méthode apply() est l'un des éléments suivants : « accept », « reject », « neutral ».

Voir également : « policies() ».

load()

Charge le message complet depuis un flux d'entrée.

$dkim->load($file_handle);

Lit un message complet depuis le fichier désigné et le transmet au vérificateur. Le message doit utiliser des finisseurs de ligne <CRLF> (comme le protocole SMTP).

message_originator()

Accès à l'en-tête « From ».

my $address = $dkim->message_originator;

Renvoie l'adresse de « l'origineur » trouvée dans le message, sous forme d'objet Mail::Address. Il s'agit généralement de la (première) adresse et adresse électronique trouvées dans l'en-tête From :. S'il n'y a pas d'en-tête From :, un objet Mail::Address vide est renvoyé.

Pour obtenir uniquement la partie adresse électronique, faites :

my $email = $dkim->message_originator->address;

Voir également « message_sender() ».

message_sender()

Accès à l'en-tête « From » ou « Sender ».

my $address = $dkim->message_sender;

Renvoie « l'expéditeur » trouvé dans le message, sous forme d'objet Mail::Address. Il s'agit généralement de la (première) adresse et adresse électronique trouvées dans l'en-tête Sender :. S'il n'y a pas d'en-tête Sender :, c'est la première adresse et adresse électronique de l'en-tête From :. Si aucun des deux en-têtes n'est présent, un objet Mail::Address vide est renvoyé.

Pour obtenir uniquement la partie adresse électronique, faites :

my $email = $dkim->message_sender->address;

« L'expéditeur » est le bureau de poste de l'agent responsable de la transmission du message. Par exemple, si un secrétaire envoyait un message pour une autre personne, « l'expéditeur » serait le secrétaire et « l'origineur » serait la personne réelle qui a écrit le message.

policies()

Récupère les politiques de signature applicables depuis le DNS.

my @policies = $dkim->policies;
foreach my $policy (@policies)
{
    $policy_result = $policy->apply($dkim);
    # $policy_result est l'un des éléments suivants : « accept », « reject », « neutral »
}

Cette méthode renvoie une liste d'objets Mail::DKIM::Policy pour toutes les politiques applicables à ce message. Cela comprend les politiques ADSP (Author Domain Signing Practices) et les politiques de l'expéditeur (DomainKeys).

L'ordre des politiques dans la liste est le suivant : ADSP, puis expéditeur.

Les politiques sont évaluées dans l'ordre dans lequel elles apparaissent dans la liste. La première politique qui renvoie autre chose que « neutral » est la politique appliquée.

Voir également : « fetch_author_domain_policies() », « fetch_sender_policy() ».

PRINT()

Les méthodes PRINT() et CLOSE() sont toutes deux utilisées pour alimenter le vérificateur avec le contenu du message.

$dkim->PRINT( $message_part );
$dkim->CLOSE;

Il s'agit d'une interface pour le contrôle des flux, dans laquelle le corps du message peut être passé au vérificateur en morceaux. Ceci est particulièrement utile lors de la vérification de courriels en temps réel, où le message n'est pas entièrement disponible en mémoire.

result()

Renvoie le résultat de la vérification.

my $result = $dkim->result;

Cela renvoie l'état général de la vérification DKIM pour le message. Les valeurs possibles sont :

none
Aucune signature DKIM trouvée.
valid
Au moins une signature est valide et aucune n'est invalide.
invalid
Au moins une signature est invalide. Les autres peuvent être valides ou non.
permerror
Une erreur de "permanent error" s'est produite lors de la vérification d'une signature.
temperror
Une erreur de "temporary error" s'est produite lors de la vérification d'une signature.

Notez que les erreurs `permerror` et `temperror` se produisent lorsque le vérificateur ne peut pas récupérer la clé publique ou rencontre un autre problème qui empêche la vérification d'avoir lieu. Ces résultats sont distincts de `valid` et `invalid`, qui concernent le résultat de la comparaison de la signature avec le message.

signatures()

Renvoie une liste d'objets Mail::DKIM::Signature.

my @signatures = $dkim->signatures;

Chaque objet retourné par cette méthode représente une seule signature DKIM trouvée dans le message. Ces objets contiennent des informations détaillées sur la signature, y compris l'identité du signataire et le résultat de sa vérification.

Mail::DKIM::Verifier - Perl manual page

NAME

Mail::DKIM::Verifier - verify DKIM signatures

VERSION

1.20240923-2

SYNOPSIS

 use Mail::DKIM::Verifier;

 my $verifier = Mail::DKIM::Verifier->new();
 $verifier->verify(message => $message); # or message_file => $filename

 # Check the overall result
 my $result = $verifier->result;

 # Get more details
 my $detail = $verifier->result_detail;

 # Get the best signature (if any)
 my $signature = $verifier->signature;

 # Get all signatures
 my @signatures = $verifier->signatures;

DESCRIPTION

This class implements DKIM verification. It will examine a message and determine if any DKIM signatures contained within are valid.

The primary method is verify(), which takes a message (as a string or file) and processes it.

See Mail::DKIM::KeyTable, Mail::DKIM::Signer, Mail::DKIM::Trusted, Mail::DKIM::Signature and Mail::DKIM::InternalStorage for more information on how the configuration of the library is handled.

The verification process involves looking for DKIM-Signature headers within the message. For each signature found, the module will look up the public key for the signing domain (specified in the d= tag of the signature) by performing a DNS TXT query for the selector (specified in the s= tag).

The public key is then used to verify the signature. The process of verification involves checking that the signed header fields and the signed body hash all match the contents of the actual message headers and body.

The method signing_policies() is intended to return any signing policies that would apply to this message. Signing policies are selected based on the domain that the message *claims* to be from. So, for example, if a message claims to be from security@bank, and forwarded by trusted@listserv, when in reality the message came from foe@evilcorp, this method would check for signing policies for security@bank and trusted@listserv. The signing policies might tell whether foe@evilcorp (the real sender) is allowed to send mail claiming to be from your bank or your listserv.

I say "might tell", because in reality this is still really hard to specify with any accuracy. In addition, most senders do not publish useful policies.

METHODS

signing_policies()

This method searches for and returns any signing policies that would apply to this message. Signing policies are selected based on the domain that the message *claims* to be from. So, for example, if a message claims to be from security@bank, and forwarded by trusted@listserv, when in reality the message came from foe@evilcorp, this method would check for signing policies for security@bank and trusted@listserv. The signing policies might tell whether foe@evilcorp (the real sender) is allowed to send mail claiming to be from your bank or your listserv.

I say "might tell", because in reality this is still really hard to specify with any accuracy. In addition, most senders do not publish useful policies.

result()

Access the result of the verification.

my $result = $dkim->result;

Gives the result of the verification. The following values are possible:

pass
Returned if a valid DKIM-Signature header was found, and the signature contains a correct value for the message.
fail
Returned if a valid DKIM-Signature header was found, but the signature does not contain a correct value for the message.
invalid
Returned if a DKIM-Signature could not be checked because of a problem in the signature itself or the public key record. I.e. the signature could not be processed.
temperror
Returned if a DKIM-Signature could not be checked due to some error which is likely transient in nature, such as a temporary inability to retrieve a public key. A later attempt may produce a better result.
none
Returned if no DKIM-Signature headers (valid or invalid) were found.

In case of multiple signatures, the "best" result will be returned. Best is defined as "pass", followed by "fail", "invalid", and "none". To examine the results of individual signatures, use the "signatures()" method to retrieve the signature objects. See "result()" in Mail::DKIM::Signature.

result_detail()

Access the result, plus details if available.

my $detail = $dkim->result_detail;

The detail is constructed by taking the result (e.g. "pass", "fail", "invalid" or "none") and appending any details provided by the verification process in parenthesis.

The following are possible results from the result_detail() method:

pass
fail (bad RSA signature)
fail (OpenSSL error: ...)
fail (message has been altered)
fail (body has been altered)
invalid (bad identity)
invalid (invalid domain in d tag)
invalid (missing q tag)
invalid (missing d tag)
invalid (missing s tag)
invalid (unsupported version 0.1)
invalid (unsupported algorithm ...)
invalid (unsupported canonicalization ...)
invalid (unsupported query protocol ...)
invalid (signature is expired)
invalid (public key: not available)
invalid (public key: unknown query type ...)
invalid (public key: syntax error)
invalid (public key: unsupported version)
invalid (public key: unsupported key type)
invalid (public key: missing p= tag)
invalid (public key: invalid data)
invalid (public key: does not support email)
invalid (public key: does not support hash algorithm 'sha1')
invalid (public key: does not support signing subdomains)
invalid (public key: revoked)
invalid (public key: granularity mismatch)
invalid (public key: granularity is empty)
invalid (public key: OpenSSL error: ...)
none

signature()

Access the message's DKIM signature.

my $sig = $dkim->signature;

Accesses the signature found and verified in this message. The returned object is of type Mail::DKIM::Signature.

In case of multiple signatures, the signature with the "best" result will be returned. Best is defined as "pass", followed by "fail", "invalid", and "none".

signatures()

Access all of this message's signatures.

my @all_signatures = $dkim->signatures;

Use $signature->result or $signature->result_detail to access the verification results of each signature.
