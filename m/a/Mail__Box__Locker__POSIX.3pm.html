Mail::Box::Locker::POSIX(3) Documentation Perl fournie par l'utilisateur Mail::Box::Locker::POSIX(3)

NOM

Mail::Box::Locker::POSIX - verrouille un dossier en utilisant les verrous de fichier du noyau

INHERITANCE

Mail::Box::Locker::POSIX
  est un Mail::Box::Locker
  est un Mail::Reporter

SYNOPIS

Voir Mail::Box::Locker

DESCRIPTION

Cet objet verrou est créé par le dossier pour obtenir un verrou exclusif sur le fichier qui contient les données en utilisant les installations POSIX du noyau. Ce verrou est créé sur un descripteur de fichier séparé du fichier du dossier, donc pas sur le descripteur qui lit.

AVERTISSEMENT : Toutes les plateformes ne prennent pas en charge le verrouillage POSIX (via fcntl) et pas toujours de la même manière. Cette implémentation n'utilise pas XS pour accéder à la structure de fcntl() : il est préférable d'utiliser ::FcntlLock qui le fait. Non, cette implémentation « devine » l'emplacement des octets.

DIAGNOSTICS

Avertissement : Le dossier $dossier est déjà locké
Causé par lock()
Erreur : Le paquet $package n'implémente pas $method.
Erreur fatale : le paquet spécifique (ou l'une de ses superclasses) n'implémente pas cette méthode alors qu'il le devrait. Ce message signifie que d'autres classes liées implémentent cette méthode alors que la classe concernée ne le fait pas. Vous devriez probablement enquêter à ce sujet et probablement informer l'auteur du paquet. Causé par notImplemented()
Erreur : Impossible de vérifier le fichier de verrouillage $fichier pour $dossier : $!
Pour vérifier si le $fichier est utilisé pour verrouiller un $dossier, le fichier doit être ouvert. Cela échoue apparemment, ce qui ne signifie ni que le dossier est verrouillé ni qu'il ne l'est pas. Causé par isLocked()
Erreur : Impossible d'ouvrir le fichier de verrouillage POSIX $fichier pour $dossier : $!
Pour le verrouillage de style POSIX, un $dossier doit être ouvert, ce qui ne réussit pas pour la raison spécifiée. Causé par lock()
Erreur : Obtenir un verrou POSIX sur $fichier pour $dossier n'aboutira jamais : $!
Tentative de verrouillage du $dossier, mais cela n'a pas réussi. Le code d'erreur reçu du système d'exploitation indique que cela ne réussira jamais, nous n'avons donc pas besoin de réessayer. Causé par lock()

Mail::Box::Locker::POSIX(3pm)

NAME

Mail::Box::Locker::POSIX - interface pour la gestion des verrous de fichiers POSIX.

INHERITANCE

Mail::Box::Locker::POSIX est un sous-système de Mail::Box::Locker.

SYNOPSIS

use Mail::Box::Locker::POSIX;

my $locker = Mail::Box::Locker::POSIX->new(dir => '/tmp');
$locker->lock(file => 'mylockfile');
# ... faire quelque chose ...
$locker->unlock;

DESCRIPTION

Cette classe implémente le système de verrouillage de fichiers POSIX, qui est la méthode de verrouillage la plus courante et la plus simple sous les systèmes de type Unix.

Elle utilise les appels système flock(2) et fcntl(2) pour gérer les verrous exclusifs sur les fichiers. Les verrous sont associés à un fichier spécifique, et lorsque ce fichier est fermé, le verrou est automatiquement libéré.

METHODS

new( dir => $directory )

Crée un nouvel objet Mail::Box::Locker::POSIX. Le paramètre dir spécifie le répertoire où les fichiers de verrouillage seront créés. Il est recommandé d'utiliser un répertoire temporaire ou un répertoire dédié à cet effet.

lock( file => $filename )

Tente d'acquérir un verrou exclusif sur le fichier spécifié par $filename. Si le verrou ne peut pas être acquis immédiatement (parce qu'un autre processus le détient déjà), la méthode bloquera jusqu'à ce que le verrou soit disponible. Une fois le verrou acquis, il sera conservé jusqu'à ce que le verrou soit explicitement libéré avec unlock ou que le programme se termine.

unlock()

Libère le verrou actuellement détenu. Si aucun verrou n'est détenu, cette méthode n'a aucun effet.

DIAGNOSTICS

Les erreurs lors de l'acquisition ou de la libération des verrous généreront des exceptions Perl. Consultez la documentation de flock(2) et fcntl(2) pour plus de détails sur les erreurs possibles.

SEE ALSO

Mail::Box::Locker, flock, fcntl.
