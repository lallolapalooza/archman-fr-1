Mail::DKIM::Canonicalization::Base(3) Documentation Perl fournie par la communauté Mail::DKIM::Canonicalization::Base(3)

NOM

Mail::DKIM::Canonicalization::Base - classe de base pour les méthodes de canonisation

VERSION

version 1.20240923

SYNTAXE

# les résultats de canonisation sont envoyés sur STDOUT
my $method = new Mail::DKIM::Canonicalization::relaxed(
                  output_fh => *STDOUT,
                  Signature => $dkim_signature);
# ajouter les en-têtes
$method->add_header("Subject: ceci est le sujet\015\012");
$method->finish_header(Headers => \@all_headers);
# ajouter le corps
$method->add_body("Ceci est le corps.\015\012");
$method->add_body("Deux autres lignes\015\012du corps.\015\012");
$method->finish_body;
# ceci ajoute la signature à la fin
$method->finish_message;

CONSTRUCTEUR

Utilisez la méthode new() de la classe d'implémentation de canonisation souhaitée pour construire un objet de canonisation. Par exemple :

my $method = new Mail::DKIM::Canonicalization::relaxed(
                  output_fh => *STDOUT,
                  Signature => $dkim_signature);

Les constructeurs acceptent les arguments suivants :

Signature
(Requis) Fournissez la signature DKIM en cours de construction (si le message est signé) ou la signature DKIM en cours de vérification (si le message est en cours de vérification). La méthode de canonisation écrit des paramètres dans la signature ou lit des paramètres à partir de la signature (par exemple, la balise h=).
output
Si spécifié, le message canonisé sera passé à cet objet avec la méthode PRINT.
output_digest
Si spécifié, le message canonisé sera ajouté à ce digest. (Utilise la méthode add().)
output_fh
Si spécifié, le message canonisé sera écrit dans ce descripteur de fichier.

Si aucun des paramètres de sortie n'est spécifié, le message canonisé est ajouté à un tampon interne. Le contenu de ce tampon peut être consulté à l'aide de la méthode result().

MÉTHODES

add_body() - alimente une partie du corps dans la canonisation

$method->add_body("Ceci est le corps.\015\012");
$method->add_body("Deux autres lignes\015\012du corps.\015\012");

Le corps doit être alimenté une ou plusieurs « lignes » à la fois. C'est-à-dire, ne pas alimenter une partie de ligne.

finish_header() - appelée lorsque l'en-tête a été complètement analysé

$method->finish_header(Headers => \@all_headers);

Auparavant, l'objet de canonisation ne recevait les données d'en-tête qu'à travers des invocations successives de add_header(). Cependant, cela obligeait l'objet de canonisation à stocker une copie de l'en-tête entier afin de pouvoir choisir l'ordre dans lequel les en-têtes étaient transmis à l'objet digest. C'est une utilisation inefficace de la mémoire, car un message avec de nombreuses signatures peut utiliser de nombreux objets de canonisation et chaque objet de canonisation a sa propre copie de l'en-tête.

Le tableau des en-têtes est un tableau d'un élément par champ d'en-tête, les en-têtes n'étant traités/canonisés d'aucune manière.

result()

my $result = $method->result;

Si vous n'avez pas spécifié d'objet ou de descripteur pour envoyer la sortie, le résultat de la canonisation est stocké dans la méthode de canonisation elle-même, et peut être consulté à l'aide de cette méthode.
