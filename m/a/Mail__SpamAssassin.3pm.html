NAME

Mail::SpamAssassin - Moteur de détection et de marquage de spam

SYNOPSIS

my $spamtest = Mail::SpamAssassin->new();
my $mail = $spamtest->parse($message);
my $status = $spamtest->check($mail);
if ($status->is_spam()) {
  $message = $status->rewrite_mail();
}
else {
  ...
}
...
$status->finish();
$mail->finish();
$spamtest->finish();

DESCRIPTION

Mail::SpamAssassin est un module permettant d'identifier le spam en utilisant diverses méthodes, notamment l'analyse de texte, les listes en temps réel basées sur Internet, l'analyse statistique et les algorithmes de hachage basés sur Internet.

En utilisant sa base de règles, il effectue une large gamme de tests heuristiques sur les en-têtes et le corps des e-mails pour identifier le « spam », également connu sous le nom de courrier indésirable en masse. Une fois identifié comme spam, le courrier peut être marqué comme spam pour un filtrage ultérieur à l'aide du client de messagerie de l'utilisateur ou de l'agent de transfert de courrier.

Si vous souhaitez utiliser un outil de filtrage en ligne, essayez les programmes spamassassin ou spamd/spamc.

MÉTHODES

$t = Mail::SpamAssassin->new( { opt => val, ... } )
Construit un objet "Mail::SpamAssassin". Vous pouvez passer une référence de hash au constructeur qui peut contenir les paires attribut-valeur suivantes.
debug
Ceci est le niveau de journalisation utilisé pour déterminer le niveau des messages de débogage. Il existe pour permettre l'activation ou la désactivation de certaines parties des messages de débogage (appels à des « installations »). S'il s'agit d'une chaîne, elle est traitée comme une liste de niveaux de débogage séparés par des virgules. S'il s'agit d'une référence de hash, les clés sont traitées comme la liste des niveaux de débogage, et s'il s'agit d'une référence de tableau, les éléments sont traités comme la liste des niveaux de débogage.
rules_filename
Le nom ou le répertoire à partir duquel charger les règles de spam.
site_rules_filename
Le nom ou le répertoire à partir duquel charger les règles de spam spécifiques au site.
userprefs_filename
Le nom du fichier de préférences.
userstate_dir
Le répertoire où l'état de l'utilisateur est stocké.
config_tree_recurse
S'il est défini sur 1, les répertoires sont parcourus lors de la lecture des fichiers de configuration, plutôt que de lire un seul niveau. (optionnel, par défaut 0)
config_text
Le texte de toutes les règles et préférences. Si vous préférez ne pas charger les règles à partir de fichiers, lisez-les vous-même et définissez cette propriété. En conséquence, cette propriété remplacera les paramètres de rules_filename, site_rules_filename et userprefs_filename).
pre_config_text
Similaire à config_text, ce texte est placé avant config_text pour permettre un remplacement des fichiers de configuration.
post_config_text
Similaire à config_text, ce texte est placé après config_text pour permettre un remplacement des fichiers de configuration.
force_ipv4
S'il est défini sur 1, les tests DNS ou autres protocoles réseau préféreront IPv4 et n'essaieront pas d'utiliser IPv6. Utilisez si les résultats des tests de disponibilité IPv6 donnent des résultats incorrects ou provoquent des plantages.
force_ipv6
Pour la symétrie avec force_ipv4 : s'il est défini sur 1, les tests DNS ou autres protocoles réseau préféreront IPv6 et n'essaieront pas d'utiliser IPv4. Certains plugins peuvent ignorer ce paramètre et utiliser le protocole de famille avec lequel ils sont à l'aise.
require_rules
S'il est défini sur 1, init() s'arrêtera s'il ne parvient pas à charger de règles valides. C'est le comportement par défaut lorsqu'il est appelé depuis spamassassin ou spamd).
languages_filename
Si vous souhaitez pouvoir utiliser les règles de détection de langue "UNWANTED_LANGUAGE_BODY" et que vous utilisez config_text au lieu de rules_filename, site_rules_filename et userprefs_filename, vous devez définir ceci. Cela doit être le chemin d'accès au fichier languages que l'on trouve normalement dans le répertoire des règles de SpamAssassin.
local_tests_only
S'il est défini sur 1, aucun test nécessitant un accès à Internet ne sera effectué. (valeur par défaut : 0)
need_tags
Cette option permet d'éviter un traitement plus coûteux lorsqu'on sait d'avance que certaines informations ne seront pas nécessaires à l'appelant.

Une valeur de l'option peut être une chaîne (une liste de noms d'étiquettes séparés par des virgules), ou une référence à une liste de noms d'étiquettes individuels. Un appelant peut fournir la liste à l'avance, indiquant son intention de récupérer les informations via des appels à $pms->get_tag(). Si un nom d'étiquette commence par 'NO' (quelle que soit la casse), cela indique que l'appelant ne s'intéresse pas à une telle étiquette, bien qu'il n'y ait aucune garantie que cela économisera des ressources ni que la valeur de l'étiquette sera vide. Actuellement, il n'y a pas d'étiquettes prédéfinies commençant par 'NO'. Une entrée ultérieure sur le sujet remplace la précédente, par exemple, ASN,NOASN,ASN,TIMING,NOASN est équivalent à TIMING,NOASN.

Pour des raisons de compatibilité descendante, toutes les étiquettes disponibles depuis la version 3.2.4 seront disponibles par défaut (sauf si elles sont désactivées avec NOtag), même si elles ne sont pas demandées via l'option need_tags. Les versions futures peuvent fournir des étiquettes disponibles conditionnellement.

Actuellement, la seule étiquette qui doit être explicitement demandée est 'TIMING'. Ne pas la demander peut économiser un million de microsecondes - c'est principalement pour illustrer l'utilisation de need_tags.

Exemple :
need_tags => 'TIMING,noLANGUAGES,RELAYCOUNTRY,ASN,noASNCIDR', ou :
need_tags => [qw(TIMING noLANGUAGES RELAYCOUNTRY ASN noASNCIDR)],

ignore_site_cf_files
S'il est défini sur 1, tous les fichiers de règles trouvés dans le répertoire "site_rules_filename" seront ignorés. Les fichiers *.pre (utilisés pour charger les plugins) trouvés dans le répertoire "site_rules_filename" seront toujours utilisés. (valeur par défaut : 0)
dont_copy_prefs
S'il est défini sur 1, le fichier de préférences ne sera pas créé s'il existe déjà. (valeur par défaut : 0)
save_pattern_hits
S'il est défini sur 1, les occurrences de motifs peuvent être récupérées via l'objet "Mail::SpamAssassin::PerMsgStatus". Utilisé pour le débogage.
home_dir_for_helpers
S'il est défini, la valeur de la variable d'environnement "HOME" sera définie sur cette valeur lorsque des utilitaires de test nécessitant leurs informations de configuration, tels que Razor, Pyzor et DCC, sont utilisés.
username
S'il est défini, l'attribut "username" utilisera ce nom comme nom de l'utilisateur actuel. Sinon, la valeur par défaut sera prise de l'environnement d'exécution (c'est-à-dire l'UID effectif du processus UNIX).
skip
S'il est défini sur 1, aucun test nécessitant un accès à Internet ne sera effectué. (valeur par défaut : 0)

Si aucun des valeurs "rules_filename", "site_rules_filename", "userprefs_filename" ou "config_text" n'est défini, le module "Mail::SpamAssassin" recherchera les fichiers de configuration aux emplacements standards en utilisant les définitions de variables suivantes qui peuvent être passées en tant que paramètres.

PREFIX
Est utilisé comme racine de certains chemins de répertoire tels que : 
'__prefix__/etc/mail/spamassassin'

La valeur par défaut est "@@PREFIX@@".

DEF_RULES_DIR
Emplacement où les règles par défaut sont installées. La valeur par défaut est "@@DEF_RULES_DIR@@".
LOCAL_RULES_DIR
Emplacement où les règles locales du site sont installées. La valeur par défaut est "@@LOCAL_RULES_DIR@@".
LOCAL_STATE_DIR
Emplacement du répertoire d'état local, principalement utilisé pour installer les mises à jour via "sa-update" et compiler les règles de type natif. La valeur par défaut est "@@LOCAL_STATE_DIR@@".
parse($message, $parse_now [, $suppl_attrib])
Analyse et renverra un objet "Mail::SpamAssassin::Message" avec uniquement les en-têtes analysés. Lorsque cette fonction est appelée, deux paramètres optionnels peuvent être passés : $message est, par défaut, indéfini (il utilisera STDIN), un scalaire - une chaîne avec un message complet, une référence à une telle chaîne, une référence à un tableau d'un message avec une limite par élément, ou une référence à un glob de fichier ou un objet IO::File contenant tout le contenu du message ; et $parse_now, qui spécifie si un arbre MIME doit être créé au moment de l'analyse ou plus tard, selon les besoins.

Le paramètre $parse_now est, par défaut, faux (0). Cela permet à SpamAssassin de ne pas avoir à générer l'arbre des nœuds internes si les informations ne seront pas utilisées. C'est utile, par exemple, lors de l'exécution de "spamassassin -d", qui n'a besoin que de l'en-tête brut et du corps, qui sont toujours analysés et stockés par cette fonction.

Le paramètre optionnel $suppl_attrib permet à un appelant de transmettre des informations supplémentaires sur un message à SpamAssassin. Il est, par défaut, indéfini, ou une référence à un hachage où chaque paire clé-valeur fournit des attributs supplémentaires du message, typiquement des informations qui ne peuvent pas être déduites du message lui-même, ou sont difficiles à obtenir, ou représenteraient un travail inutile pour SpamAssassin. L'argument est stocké dans un objet "Mail::SpamAssassin::Message" sous le nom "suppl_attrib", le rendant ainsi accessible au reste du code et aux plugins. La liste exacte des attributs peut évoluer avec le temps, et tout attribut inconnu doit être ignoré. Des exemples d'attributs sont : des informations d'envoi SMTP, un indicateur qu'un message fourni par un appelant a été tronqué en raison d'une limite de taille, une liste déjà vérifiée d'objets de signature DKIM, ou peut-être une liste de jalons de règles prédéfinis par un appelant, représentant un autre moyen pour un appelant de fournir des informations métaphoriques (au lieu d'avoir à insérer des en-têtes fictifs pour transmettre des informations), ou peut-être juste des jalons de règles bruts.

Pour plus d'informations, veuillez consulter le document "Mail::SpamAssassin::Message" et "Mail::SpamAssassin::Message::Node".

$status = $f->check ($mail)
Vérifie un message, encapsulé dans un objet "Mail::SpamAssassin::Message", pour déterminer s'il s'agit de spam ou non.

Renvoie un objet "Mail::SpamAssassin::PerMsgStatus" qui peut être utilisé pour tester ou manipuler le message.

Note : L'objet "Mail::SpamAssassin" peut être réutilisé pour des messages ultérieurs sans affecter cette vérification ; en terminologie OO, l'objet "Mail::SpamAssassin" est un « fabricant ».

$status = $f->check_message_text ($mailtext)
Vérifie un message, encapsulé dans une chaîne de texte brut $mailtext, pour déterminer s'il s'agit de spam ou non.

Est identique à la fonction check() précédente.

$status = $f->learn ($mail, $id, $isspam, $forget)
Apprend d'un message, encapsulé dans un objet "Mail::SpamAssassin::Message".

Si $isspam est défini, le message est supposé être du spam, sinon il sera appris comme non spam.

Si $forget est défini, les attributs du message sont supprimés des deux bases d'apprentissage de non-spam et de spam.

Le $id est une chaîne d'identification de message optionnelle, utilisée en interne pour étiqueter le message. S'il est "undef", le message-Id du message sera utilisé. Il doit être unique pour ce message.

Renvoie un objet "Mail::SpamAssassin::PerMsgLearner" qui peut être utilisé pour manipuler le processus d'apprentissage pour chaque message.

Note : L'objet "Mail::SpamAssassin" peut être réutilisé pour des messages ultérieurs sans affecter cette vérification ; en terminologie OO, l'objet "Mail::SpamAssassin" est un « fabricant ».

learn() et check() peuvent être exécutés avec le même fabricant. init_learner() doit être appelé avant d'utiliser cette fonction.

$f->init_learner ( [ { opt => val, ... } ] )
Initialise l'apprentissage. Vous pouvez passer les paires clé-valeur suivantes à cette fonction.
caller_will_untie
Qui se chargera de se désengager des bases bayes (en appelant finish_learner()) ? (optionnel, valeur par défaut 0).
force_expire
Doit-il forcer une expiration immédiate ? (optionnel, valeur par défaut 0).

Doit-il écrire les données d'apprentissage dans le journal, plutôt que dans les bases de données ? (optionnel, valeur par défaut 0).
wait_for_lock
Doit-il attendre longtemps pour terminer les verrous ? (optionnel, valeur par défaut 0).
opportunistic_expire_check_only
Ne doit-il pas réellement effectuer l'expiration lors de la synchronisation du journal et de la vérification d'expiration opportuniste, mais doit-il rapporter si c'est le cas ? (optionnel, valeur par défaut 0).
no_relearn
Si une opération d'apprentissage est effectuée et que le message a déjà été appris comme étant le contraire, le message ne doit pas être réappris.

Reconstruit toutes les bases de cache ; doit être appelé après le processus d'apprentissage. Les options incluent : "verbose", qui affiche des diagnostics sur "stdout" s'il est défini à 1.

Termine l'apprentissage.

Indique que l'utilisateur actuel a changé (potentiellement en utilisant "setuid"), ce qui signifie que SpamAssassin doit fermer toutes les bases d'utilisateurs qu'il a ouvertes et les rouvrir en utilisant celles appropriées pour le nouvel utilisateur.

Note : Il devrait être appelé *après* la lecture de toute configuration utilisateur, car ces données pourraient écraser certains chemins qui ont été ouverts dans cette méthode. Vous pouvez passer les paires clé-valeur suivantes :

Le nom de l'utilisateur. Il sera utilisé pour l'attribut "username".

Un répertoire à utiliser comme répertoire de base pour les données de l'utilisateur actuel, remplaçant la valeur par défaut du système. Ce répertoire doit être lisible et inscriptible par le processus. Note : Le résultat "userstate_dir" sera le répertoire ".spamassassin" de ce répertoire.
userstate_dir
Un répertoire à utiliser comme répertoire de base pour les données de l'utilisateur actuel, remplaçant la valeur par défaut du système. Ce répertoire doit être lisible et inscriptible par le processus. La valeur par défaut est ".spamassassin" de ce répertoire.
"user_dir/.spamassassin".
$f->report_as_spam ($mail, $options)
Signaler un e-mail, encapsulé dans un objet "Mail::SpamAssassin::Message", comme étant du spam vérifié par un humain. Cela soumettra le message à des bases de données de blocage de spam collaboratives en direct, permettant à d'autres utilisateurs de bloquer ce message.

Cela soumettra également le courrier à l'apprenant bayésien de SpamAssassin.

Options est une référence optionnelle à une table de hachage d'options. Actuellement, celles-ci peuvent être :

dont_report_to_dcc
Inhibe la notification du spam au DCC.
dont_report_to_pyzor
Inhibe la notification du spam à Pyzor.
dont_report_to_razor
Inhibe la notification du spam à Razor.
dont_report_to_spamcop
Inhibe la notification du spam à SpamCop.
$f->revoke_as_spam ($mail, $options)
Révocquer un e-mail, encapsulé dans un objet "Mail::SpamAssassin::Message", comme étant du courrier légitime (non-spam) vérifié par un humain. Cela révoquera le message des bases de données collaboratives de blocage de spam en direct, permettant à d'autres utilisateurs de bloquer ce message.

Cela soumettra également le courrier à l'apprenant bayésien de SpamAssassin comme étant du courrier légitime.

Options est une référence optionnelle à une table de hachage d'options. Actuellement, celles-ci peuvent être :

dont_report_to_razor
Inhibe la révocation du spam à Razor.

Si $cli_p est défini, le plugin sous-jacent peut fournir un retour visuel sur les ajouts/échecs.

$text = $f->remove_spamassassin_markup ($mail)
Retourne le texte du message, avec tout texte ajouté par SpamAssassin (tel que le rapport, ou les en-têtes X-Spam-Status) supprimé.

Notez que l'objet $mail n'est pas modifié.

Attention : si le message d'entrée dans $mail contient un mélange de fins de ligne CR-LF (style Windows) et LF (style UNIX), il sera "canonalisé" pour utiliser l'un ou l'autre de manière cohérente.

$f->read_scoreonly_config ($filename)
Lire un fichier de configuration et analyser les préférences utilisateur à partir de celui-ci.

Les préférences utilisateur sont telles que définies dans la page de manuel "Mail::SpamAssassin::Conf". En d'autres termes, elles incluent les options de score, les scores, les listes de bienvenue et les listes de blocage, etc., mais n'incluent pas les définitions de règles, les paramètres privilégiés, etc., à moins que "allow_user_rules" ne soit activé ; et elles n'incluent jamais les paramètres de l'administrateur.

$f->load_scoreonly_sql ($username)
Lire les paramètres de configuration à partir de la base de données SQL et en analyser les scores. Cela ne prendra effet que si le module Perl "DBI" est installé, et que les paramètres de configuration "user_scores_dsn", "user_scores_sql_username", et "user_scores_sql_password" sont correctement définis.

Le nom d'utilisateur dans $username sera également utilisé pour l'attribut "username" de l'objet Mail::SpamAssassin.

$f->load_scoreonly_ldap ($username)
Lire les paramètres de configuration à partir d'un serveur LDAP et en analyser les scores. Cela ne prendra effet que si les modules Perl "Net::LDAP" et "URI" sont installés, et que les paramètres de configuration "user_scores_dsn", "user_scores_ldap_username", et "user_scores_ldap_password" sont correctement définis.

Le nom d'utilisateur dans $username sera également utilisé pour l'attribut "username" de l'objet Mail::SpamAssassin.

$f->set_persistent_address_list_factory ($factoryobj)
Définir la fabrique de listes d'adresses persistantes, utilisée pour créer des objets pour le backend de stockage persistant de l'algorithme de liste de bienvenue automatique. Voir "Mail::SpamAssassin::PersistentAddrList" pour l'API que ces objets fabriques doivent implémenter, et l'API que les objets qu'ils produisent doivent implémenter.
$f->compile_now ($use_user_prefs, $keep_userstate)
Compiler tous les modèles, charger tous les fichiers de configuration, et charger tous les modules Perl potentiellement requis.

Normalement, Mail::SpamAssassin utilise l'évaluation paresseuse lorsque c'est possible, mais si vous prévoyez de faire un **fork()** ou de démarrer un nouveau thread Perl pour traiter un message, cela est sous-optimal, car chaque processus/thread devra effectuer ces actions.

Appelez cette fonction dans le thread ou le processus maître pour effectuer les actions immédiatement, afin que les sous-processus n'aient pas à le faire.

Si $use_user_prefs est 0, cela initialisera la configuration SpamAssassin sans lire le fichier de configuration par utilisateur et supposera que vous appellerez "read_scoreonly_config" ultérieurement.

Si $keep_userstate est vrai, **compile_now()** annulera toutes les options de configuration qui ont une valeur par défaut avec *__userstate__* après **init()**, puis rétablira l'option avant de retourner. Cela vous permet de changer $ENV{'HOME'} vers un répertoire temporaire, de faire exécuter **compile_now()** et de créer les fichiers nécessaires sans perturber les fichiers réels tels que modifiés par une option de configuration. Par défaut, ceci est désactivé.

$f->finish()
Détruire cet objet, de sorte qu'il soit collecté par le garbage collector une fois qu'il sort de sa portée. L'objet ne sera plus utilisable après l'appel de cette méthode.
$fullpath = $f->find_rule_support_file ($filename)
Trouver un fichier de support de règle, tel que "languages" ou "triplets.txt", dans le répertoire de règles système, et retourner son chemin complet s'il existe, ou undef s'il n'existe pas.

(Cette API a été ajoutée dans SpamAssassin 3.1.1.)

$f->create_default_prefs ($filename, $username [ , $userdir ] )
Copier le fichier de préférences par défaut dans le répertoire personnel pour une utilisation et une modification ultérieures, s'il n'existe pas déjà et que "dont_copy_prefs" n'est pas défini.
$f->copy_config ( [ $source ], [ $dest ] )
Utilisé par les démons pour maintenir la configuration d'un objet Mail::SpamAssassin persistant correcte lors du passage d'un utilisateur à un autre. Passez une référence de tableau associatif comme $source ou $dest, et définissez l'autre sur 'undef' afin que l'objet utilise sa configuration actuelle. Par exemple : 
# créer un objet avec configuration
my $spamtest = Mail::SpamAssassin->new( ... );
# sauvegarder la configuration dans %conf_backup
my %conf_backup;
$spamtest->copy_config(undef, \%conf_backup) ||
  die "config: erreur retournée par copy_config!\n";
... faire des choses, potentiellement modifier la configuration, etc ...
# réinitialiser la configuration à l'original
$spamtest->copy_config(\%conf_backup, undef) ||
  die "config: erreur retournée par copy_config!\n";

Notez que le contenu des tableaux associatifs doit être considéré comme opaque par le code appelant.

@plugins = $f->get_loaded

NOM

Mail::SpamAssassin::Conf

SYNOPIS

Mail::SpamAssassin::Conf

DESCRIPTION

Le module Mail::SpamAssassin::Conf fournit les paramètres de configuration pour SpamAssassin.

MÉTHODES

Mail::SpamAssassin::Conf::new( )
Retourne l'objet de configuration pour cette instance SpamAssassin.
Mail::SpamAssassin::Conf::config( )
Retourne les paramètres de configuration pour cette instance SpamAssassin.
Mail::SpamAssassin::Conf::plugins( )
Retourne la liste des plugins actuellement chargés par la configuration de cet objet SpamAssassin ; chaque entrée de la liste est un objet de type "Mail::SpamAssassin::Plugin".
Mail::SpamAssassin::Conf::update( )
Met à jour les paramètres de configuration pour cette instance SpamAssassin.
