Mail::SPF::Request(3) Documentation soumise par les utilisateurs de Perl Mail::SPF::Request(3)

NOM

Mail::SPF::Request - Classe de requête SPF

VERSION

version 3.20250505

SYNOPIS

use Mail::SPF;
my $request = Mail::SPF::Request->new(
    versions    => [1, 2],              # optionnel
    scope       => 'mfrom',             # ou 'helo', 'pra'
    identity    => 'fred@example.com',
    ip_address  => '192.168.0.1',
    helo_identity                       # optionnel,
                => 'mta.example.com'    #   pour l'expansion de macro %{h}
);
my @versions    = $request->versions;
my $scope       = $request->scope;
my $authority_domain
                = $request->authority_domain;
my $identity    = $request->identity;   # 'localpart@domain' ou 'domain'
my $domain      = $request->domain;
my $localpart   = $request->localpart;
my $ip_address  = $request->ip_address;     # adresse IPv4 ou IPv6
my $ip_address_v6
                = $request->ip_address_v6;  # adresse IPv6 native ou
                                            # adresse IPv6 mappée IPv4
my $helo_identity
                = $request->helo_identity;  # identité HELO additionnelle
                                            # pour les scopes autres que HELO
my $record      = $request->record;
    # l'enregistrement sélectionné lors du traitement de la requête, peut être undef
$request->state(field => 'value');
my $value = $request->state('field');

DESCRIPTION

Un objet de classe Mail::SPF::Request représente une requête SPF.

Constructeurs

Les constructeurs suivants sont fournis :

new(%options): retourne Mail::SPF::Request
Crée un nouvel objet de classe Mail::SPF::Request. La requête est considérée comme la requête racine de toute requête enfant (voir le constructeur new_sub_request).

%options est un ensemble de paires clé-valeur représentant n'importe laquelle des options suivantes :

versions
Une référence à un tableau d'entiers listant les versions d'enregistrements SPF qui peuvent être utilisées pour la vérification de la requête. Seuls les enregistrements couvrant le scope désiré seront effectivement utilisés. Au moins une version applicable doit être spécifiée. Pour une seule version d'enregistrement, un scalaire simple peut être spécifié au lieu d'une référence de tableau. Par défaut, toutes les versions couvrant le scope désiré sont utilisées (voir ci-dessous) ; par défaut, [1, 2] est utilisé pour le scope par défaut de 'mfrom'.

Les versions suivantes sont prises en charge :

1
Utilise les enregistrements "v=spf1".
2
Utilise les enregistrements "spf2.0".

Exemple : Une valeur de 1 (ou [1]) signifie que seuls les enregistrements "v=spf1" doivent être utilisés pour la vérification de la requête. Si un scope de 'pra' est également spécifié, une exception Mail::SPF::EInvalidScope sera levée car les enregistrements "v=spf1" ne couvrent pas le scope "pra".

scope
Une chaîne dénotant le scope d'autorisation de l'identité à vérifier. Par défaut, c'est 'mfrom'. Les valeurs de scope suivantes sont prises en charge :
'helo'
L'identité donnée est le paramètre "HELO" d'une transaction SMTP (RFC 2821) et doit être vérifiée par rapport aux enregistrements SPF couvrant le scope "helo" ("v=spf1"). Voir la spécification des scopes SPFv1 (RFC 4408) pour la définition formelle du scope "HELO".
'mfrom'
L'identité donnée est le paramètre "MAIL FROM" d'une transaction SMTP (RFC 2821), et doit être vérifiée par rapport aux enregistrements SPF couvrant le scope "mfrom" ("v=spf1" et "spf2.0/mfrom")). Voir la définition formelle du scope "MAIL FROM" dans la spécification SPFv1 (RFC 4408).

Note : Dans le cas d'une transaction SMTP sans paramètre "MAIL FROM" (par exemple, "MAIL FROM:<" >>), l'identité vérifiée sera le nom postmaster@helo selon RFC 7208.

'pra'
L'identité donnée est l'"Purported Responsible Address" d'un message Internet (RFC 2822) et doit être vérifiée par rapport aux enregistrements SPF couvrant le scope "pra" ("spf2.0/pra"). Voir la spécification formelle du scope "PRA" dans RFC 4407.
authority_domain
Une chaîne dénotant le domaine qui doit être interrogé pour les recherches d'enregistrements SPF. Par défaut, c'est le domaine de l'identité spécifiée dans le paramètre "identity". Il n'est généralement pas nécessaire de spécifier le paramètre "authority_domain".
identity
Requis. Une chaîne dénotant l'identité d'envoi dont l'autorisation doit être vérifiée. Il s'agit d'un nom de domaine pour le scope "helo", et d'une adresse e-mail pour les scopes "mfrom" et "pra".

Note : Aucune identité vide ne doit être passée dans le cas d'une transaction SMTP sans paramètre "MAIL FROM" ("<MAIL FROM:<" >>), auquel cas l'identité vérifiée sera le nom postmaster@helo comme spécifié dans RFC 7208.

ip_address
Requis pour les vérifications avec les scopes "helo", "mfrom" et "pra". Il s'agit d'une chaîne ou d'un objet NetAddr::IP dénotant l'adresse IP de l'hôte qui prétend être l'identité vérifiée. Il peut s'agir d'une adresse IPv4 ou d'une adresse IPv6. Une adresse IPv6 mappée IPv4 (par exemple, '::ffff:192.168.0.1') est traitée comme une adresse IPv4.
helo_identity
Une chaîne dénotant le paramètre "HELO" d'une transaction SMTP dans le cas où l'identité principale est d'un scope autre que "helo". Cette identité n'est utilisée que pour l'expansion des macros "%{h}" lors de l'évaluation de la politique de l'identité principale. Par défaut, c'est undef, qui s'étend à 'unknown'. Si l'identité principale est du scope "helo", cette option n'est pas utilisée.
new_sub_request(%options): retourne Mail::SPF::Request
Doit être appelé sur un objet de requête existant. Crée un nouvel objet de requête enfant en clonant l'objet appelant, qui est maintenant considéré comme le super-request du nouveau request. Toutes les options spécifiées (voir le constructeur new) écrasent les paramètres du super-request. Il n'est généralement pas nécessaire de spécifier d'options sauf l'option "authority_domain".

Méthodes_d_instance

Les méthodes d'instance suivantes sont fournies :

root_request: retourne Mail::SPF::Request
Retourne le nœud racine de la chaîne des super-requests de la requête. Elle retourne la requête elle-même si elle n'a pas de super-requests.
super_request: retourne Mail::SPF::Request
Retourne le super-request de la requête, ou undef s'il n'y en a pas.
versions: retourne

Ce site n'est en aucun cas associé à Arch Linux ni affilié à ce projet. Le contenu est uniquement une traduction des pages de manuel d'Arch publiées sur man.archlinux.org.

liste de chaîne
Renvoie une liste des versions d'enregistrement SPF utilisées pour la requête. Voir la description de l'option "versions" du constructeur "new".
scope: renvoie chaîne
Renvoie la portée de la requête. Voir la description de l'option "scope" du constructeur "new".
authority_domain: renvoie chaîne
Renvoie le domaine d'autorité de la requête. Voir la description de l'option "authority_domain" du constructeur "new".
identity: renvoie chaîne
Renvoie l'identité de la requête. Voir la description de l'option "identity" du constructeur "new".
domain: renvoie chaîne
Renvoie le domaine d'identité de la requête. Voir la description de l'option "identity" du constructeur "new".
localpart: renvoie chaîne
Renvoie la partie locale d'identité de la requête. Voir la description de l'option "identity" du constructeur "new".
ip_address: renvoie NetAddr::IP
Renvoie l'adresse IP de la requête sous forme d'objet NetAddr::IP. Voir la description de l'option "ip_address" du constructeur "new".
ip_address_v6: renvoie NetAddr::IP
Semblable à la méthode "ip_address", cependant, une adresse IPv4 est renvoyée sous forme d'adresse IPv6 mappée IPv4 (par exemple, '::ffff:192.168.0.1') pour faciliter un traitement uniforme.
helo_identity: renvoie chaîne
Renvoie le paramètre de transaction SMTP "HELO" de la requête. Voir la description de l'option "helo_identity" du constructeur "new".
record: renvoie Mail::SPF::Record
Renvoie l'enregistrement SPF sélectionné lors du traitement de la requête, ou undef s'il n'y en a pas.
state($field): renvoie tout
state($field, $value): renvoie tout
Fournit une interface pour stocker des informations d'état temporaires avec l'objet de requête. Ceci est principalement destiné à être utilisé en interne par Mail::SPF::Server et d'autres classes Mail::SPF.

Si $value est spécifié, il est stocké dans un champ d'état nommé $field. Renvoie la valeur actuelle (nouvelle) du champ d'état nommé $field. Cette méthode peut être utilisée comme lvalue.
