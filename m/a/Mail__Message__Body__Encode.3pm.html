NOM

Mail::Message::Body::Encode - organiser les codages généraux des messages

SYNTAXE

my Mail::Message $msg = ...;
my $decoded = $msg->decoded;
my $encoded = $msg->encode(mime_type => 'image/gif',
    transfer_encoding => 'base64');
my $body = $msg->body;
my $decoded = $body->decoded;
my $encoded = $body->encode(transfer_encoding => '7bit');

DESCRIPTION

Gère les codages des corps de messages quand le programme principal le demande. Ce paquet ajoute des fonctionnalités à la classe Mail::Message::Body quand les méthodes decoded() ou encode() sont appelées.

Quatre types de codages sont gérés (dans le bon ordre)

  • codage des lignes

    Divers systèmes d'exploitation ont des idées différentes sur la façon de coder la fin de ligne. UNIX utilise un caractère LF, Macintosh utilise un CR, et Windows utilise un CR/LF. Les messages transportés via Internet utilisent toujours le séparateur CRLF.

  • codage de transfert

    Les messages transmis par Internet doivent être de purs ASCII. Les caractères complexes et les fichiers binaires (comme les images et les archives) doivent être encodés pendant la transmission pour une représentation ASCII.

    L'implémentation des encodeurs et décodeurs nécessaires se trouve dans l'ensemble des paquets Mail::Message::TransferEnc. La page man associée liste les codages de transfert supportés.

  • traduction des types MIME

    Pas encore implémenté

  • conversion des caractères de jeu

MÉTHODES

Attributs

$obj->charsetDetectAlgorithm( [CODE|undef|METHOD] )
[3.013] Quand un objet de corps ne spécifie pas son jeu de caractères, mais qu'il est nécessaire, alors il est auto-détecté. L'algorithme par défaut est implémenté dans charsetDetect(). Vous pouvez changer cet algorithme par défaut, ou passer le paramètre "charset_detect" pour chaque appel à encode().

Quand vous appelez cette méthode avec une valeur explicite "undef", vous réinitialisez l'algorithme par défaut. (Sans paramètre) l'algorithme actuel ("CODE" ou nom de méthode) est retourné.

Construction d'un corps

$obj->charsetDetect(%options)
[3.013] C'est compliqué. Il est difficile de détecter si le corps provient du programme ou d'une source externe. Et qu'en est-il d'une base de données ? Ce sont des octets ou des chaînes de caractères ? S'il vous plaît lisez « Auto-détection du jeu de caractères » dans Mail::Message::Body. 
-Option         --Valeur par défaut
 external         <C<false>>
external => BOOLEAN
Considère seulement les jeux de caractères valides externe, implicitement : "PERL" n'est pas une réponse acceptée.
$obj->check()
Vérifie le contenu du corps pour ne pas inclure de caractères illégaux. Lesquels sont considérés comme illégaux dépend du type de codage de ce corps.

Un corps est retourné qui a été vérifié. Il peut s'agir du corps sur lequel cette méthode est appelée, ou d'un nouvel objet, quand des changements importants ont été faits. S'il n'a pas pu être vérifié car le décodeur n'est pas défini, alors "undef" est retourné.

$obj->encode(%options)
Encode (traduit) un Mail::Message::Body dans un format différent. Voir la description précédente. Les options non spécifiées n'activent aucune conversion. 
-Option           --Valeur par défaut
 charset            PERL
 charset_detect     <intégré>
 mime_type          undef
 result_type        <tel qu'original>
 transfer_encoding  undef
charset => CHARSET|'PERL'
Applique seulement quand le mime_type est textuel.

Si le jeu de caractères est spécifié explicitement (par exemple "iso-8859-10"), la donnée est interprétée comme des octets (blob), pas comme du texte. Cependant, dans le cas de "PERL", elle est considérée comme une représentation interne de caractères (soit latin1 soit utf8 de Perl - pas la même chose que utf-8), donc vous ne devriez pas avoir à la connaître.

Ce paramètre surcharge l'attribut charset dans le champ mime_type.

charset_detect => CODE
[3.013] Quand le corps n'a pas de spécification explicite de jeu de caractères, le RFC dit que c'est "us-ascii". En réalité, ce n'est pas "vrai" : c'est juste un jeu de caractères inconnu. Cela arrive souvent quand on inclut des fichiers texte en pièce jointe, par exemple une pièce jointe.

Si vous voulez être plus intelligent que le détecteur de jeu de caractères par défaut, vous pouvez fournir votre propre fonction pour ce paramètre. La fonction recevra le corps transféré. Vous pouvez changer l'algorithme par défaut globalement via charsetDetectAlgorithm().

mime_type => STRING|FIELD
Convertit vers le type MIME spécifié, qui peut être spécifié comme STRING ou FIELD. Le FIELD est un objet Mail::Message::Field, qui représente un en-tête MIME "Content-Type". Le STRING doit être un contenu valide pour un tel en-tête, et sera converti en objet FIELD.

Le FIELD peut contenir des attributs. Généralement, il a un attribut "charset", qui explique le CHARSET du contenu après décodage du contenu transféré. Le paramètre "charset" mettra à jour ou ajoutera cet attribut. Autrement (dans de rares occasions), le CHARSET est auto-détecté quand le corps est décodé.

result_type => CLASSE
Le type de corps à créer quand le corps est changé pour satisfaire la demande de re-codage. Sera aussi utilisé comme étape intermédiaire dans le processus de traduction (si nécessaire). CLASSE doit hériter de Mail::Message::Body.
transfer_encoding => STRING|FIELD
...
$obj->encoded(%options)
Encode le corps pour un format acceptable pour la transmission ou l'écriture dans un fichier répertoire. Retourne le corps sur lequel cette méthode est appelée quand tout était prêt, ou un corps nouvellement encodé sinon. Dans les deux cas, le corps est vérifié. 
-Option        --Valeur par défaut
 charset_detect  <tel que par défaut>
charset_detect => CODE
Voir charsetDetectAlgorithm().
$obj->eol( ['CR'|'LF'|'CRLF'|'NATIVE'] )
Retourne le caractère (ou les caractères) qui est utilisé pour séparer les lignes dans ce corps. Quand un type de séparateur est spécifié, le corps sera traduit pour inclure les séparateurs spécifiés.

» exemple:

my $body = $msg->decoded->eol('NATIVE');
my $char = $msg->decoded->eol;
$obj->unify($body)
Unifie le type des objets $body donnés avec le type du corps appelant. Si l'unification ne peut être faite, "undef" est retourné. Si les corps ont les mêmes configurations, l'objet $body est retourné sans changement.

Exemples:

my $bodytype = Mail::Message::Body::Lines;
my $html  = $bodytype->new(mime_type=>'text/html', data => []);
my $plain = $bodytype->new(mime_type=>'text/plain', ...);
my $unified = $html->unify($plain);
# $unified est le contenu de plain traduit en html (si possible).

NOM

Mail::Message
Module pour gérer les messages électroniques.

SYNTAXE

Mail::Message::Body::Encode
Classe pour encoder et décoder les messages électroniques.

DESCRIPTION

Mail::Message::Body::Encode
Cette classe est utilisée pour encoder et décoder les messages électroniques. Les attributs "filename" et "name" sont conservés sans modification, sauf si un répertoire est spécifié. Si aucun nom n'est trouvé ou si le nom est déjà utilisé, un nom unique est généré.

MÉTHODES

Mail::Message::Body::Encode->isBinary()
Retourne "true" lorsque le message non encodé est binaire. Cette information est obtenue à partir de MIME::Types.
Mail::Message::Body::Encode->isText()
Retourne "true" lorsque le message non encodé contient du texte imprimable.

DIAGNOSTICS

Avertissement: L'ensemble de caractères $name n'est pas connu
Le traitement d'un corps de message rencontre un ensemble de caractères non compris par le module Encode de Perl. Il est converti avec encode().
Avertissement: Le contenu de transfert $encoding nécessite un charset spécifié, par défaut est utf-8
Il est converti avec encode().
Avertissement: Aucun décodeur défini pour l'encodage de transfert $name.
Le corps du message est encodé d'une manière qui n'est actuellement pas comprise, donc il ne peut pas être décodé (ou ré-encodé). Il est converti avec encode().
Avertissement: Aucun encodeur défini pour l'encodage de transfert $name.
Le corps du message a été décodé, mais l'encodage requis n'est pas connu. Le corps décodé est retourné. Il est converti avec encode().
Avertissement: Le séparateur de ligne $eol ignoré
Il est converti avec eol().
