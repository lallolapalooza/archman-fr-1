NOM

Mail::DKIM::DNS - effectue des requêtes DNS pour Mail::DKIM

VERSION

version 1.20240923

DESCRIPTION

C'est le module qui effectue les requêtes DNS pour Mail::DKIM.

CONFIGURATION

Ce module a quelques paramètres de configuration que l'appelant peut utiliser pour personnaliser le comportement de ce module.

$Mail::DKIM::DNS::TIMEOUT

Cette variable globale spécifie le temps maximum (en secondes) à attendre qu'une seule requête DNS se termine. La valeur par défaut est 10.

Mail::DKIM::DNS::resolver()

Utilisez cette sous-routine globale pour obtenir ou remplacer l'instance de Net::DNS::Resolver que Mail::DKIM utilise. Si elle est définie sur undef (la valeur par défaut), alors une instance toute neuve et par défaut de Net::DNS::Resolver sera créée la première fois qu'une requête DNS sera nécessaire.

Vous appellerez cette sous-routine si vous souhaitez spécifier des options non par défaut à Net::DNS::Resolver, telles que des délais d'attente différents, ou pour activer l'utilisation d'une socket persistante. Par exemple :

# d'abord, construisez un résolveur DNS personnalisé
my $res = Net::DNS::Resolver->new(
                  udp_timeout => 3, tcp_timeout => 3, retry => 2,
               );
$res->udppacketsize(1240);
$res->persistent_udp(1);
# puis, dites à Mail::DKIM d'utiliser ce résolveur
Mail::DKIM::DNS::resolver($res);

Mail::DKIM::DNS::enable_EDNS0()

Ceci est une sous-routine utilitaire qui construira un résolveur DNS approprié utilisant EDNS0 (Extension mechanisms for DNS) pour prendre en charge les réponses DNS volumineuses, et configurera Mail::DKIM pour l'utiliser. (En tant que tel, il ne doit PAS être utilisé conjointement avec la sous-routine resolver() décrite ci-dessus.)

Mail::DKIM::DNS::enable_EDNS0();

L'utilisation d'EDNS0 est recommandée, car elle réduit la nécessité de revenir au TCP lors du traitement de paquets DNS volumineux. Cependant, elle n'est pas activée par défaut car certains pare-feux Internet qui effectuent une inspection approfondie des paquets ne sont pas capables de traiter les paquets activés par EDNS0. Lorsqu'il y a un pare-feu sur un chemin vers un résolveur DNS, la fonctionnalité EDNS0 doit être spécifiquement testée avant d'être activée.
