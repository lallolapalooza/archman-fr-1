SYNOPSIS

L'objet n'est pas instancié par lui-même

DESCRIPTION

Le module "Mail::Box::Parser" gère la lecture de boîtes aux lettres. Normalement, vous n'avez rien à savoir sur ce module, sauf les options qui sont liées à ce code.

Il existe actuellement trois implémentations de ce module :

  • Mail::Box::Parser::C

    Un parseur rapide écrit en "C". Ce paquet est disponible comme module indépendant sur CPAN, car la distribution du module via CPAN ne peut pas gérer les fichiers XS qui ne sont pas à la racine de l'arbre du module. Si vous avez un compilateur C disponible sur votre système, il sera automatiquement utilisé.

  • Mail::Box::Parser::Perl

    Un parseur plus lent quand le message se trouve dans un fichier, comme mbox, qui n'utilise que Perl. Ce module est légèrement plus lent et effectue moins de vérifications et de récupérations.

  • Mail::Box::Parser::Lines

    Utile lorsque le message est déjà en mémoire. Si vous prévoyez de l'utiliser vous-même, vous devrez probablement utiliser Mail::Message::Construct::Read.

Hérite de "DESCRIPTION" dans Mail::Reporter.

Constructeurs

Hérite de "Constructeur" dans Mail::Reporter.

$class->new(%options)
Crée un objet de parseur capable de traiter un fichier. Pour les boîtes aux lettres de type mbox, cet objet peut être utilisé pour lire une boîte aux lettres entière. Dans le cas des boîtes aux lettres de type MH, chaque message est contenu dans un fichier individuel, donc chaque message a son propre objet de parseur. Hérite des options de base, voir "Constructeur" dans Mail::Reporter

 trace              Mail::Reporter   'WARNINGS'

fix_header_errors => BOOLEAN
Si des erreurs d'en-tête sont détectées, le traitement de l'en-tête s'arrête. Les lignes d'en-tête restantes deviennent alors une partie du corps du message. Définissez ce drapeau pour ajouter la ligne erronée à l'en-tête précédent.
log => NIVEAU

trusted => BOOLEAN
Le contenu des données d'entrée est-il digne de confiance ou nécessite-t-il des vérifications supplémentaires. Cette fonction est liée à Mail::Box::new(trusted).

Attributs

Hérite de "Attributs" dans Mail::Reporter.

$any->defaultParserType( [$class] )
Retourne le parseur qui sera utilisé pour analyser tous les messages suivants, et permet éventuellement de définir le parseur en utilisant l'argument optionnel. En général, le parseur est auto-détecté ; le parseur basé sur "C" sera utilisé lorsque cela est possible, et le parseur basé sur Perl sera utilisé sinon.

L'argument $class permet de spécifier un nom de paquet pour forcer un parseur spécifique (comme votre propre paquet personnalisé). Vous devez utiliser "use" ou "require" le paquet avant d'appeler cette méthode avec un argument. Le parseur doit être une sous-classe de "Mail::Box::Parser".

$obj->fixHeaderErrors( [BOOLEAN] )
Si défini à "true", le traitement de l'en-tête ne s'arrête pas en cas d'erreur, mais tente d'ajouter la ligne erronée au champ précédent. Sans valeur booléenne, la valeur actuelle est retournée.

Analyse

$obj->bodyAsFile( $fh [$chars, [$lines]] )
Tente de lire le corps d'un message depuis le fichier, et écrit immédiatement le corps dans le fichier de sortie. Optionnellement, le nombre de caractères prédits et/ou de lignes prédites à lire peut être passé. Ces valeurs peuvent être "undef" et peuvent être incorrectes.

La valeur de retour est une liste de trois scalaires : l'emplacement du corps (début et fin) et le nombre de lignes dans le corps.

$obj->bodyAsList( [$chars, [$lines]] )
Tente de lire le corps d'un message depuis le fichier. Optionnellement, le nombre de caractères prédits et/ou de lignes prédites à lire peut être passé. Ces valeurs peuvent être "undef" et peuvent être incorrectes.

La valeur de retour est une liste de scalaires, chacun contenant une ligne (y compris le terminateur de ligne), précédée de deux entiers représentant l'emplacement dans le fichier où cette partie du corps a commencé et s'est terminée.

$obj->bodyAsString( [$chars, [$lines]] )
Tente de lire le corps d'un message depuis le fichier. Optionnellement, le nombre de caractères prédits et/ou de lignes prédites à lire peut être passé. Ces valeurs peuvent être "undef" et peuvent être incorrectes.

La valeur de retour est une liste de trois scalaires : l'emplacement dans le fichier où commence le corps, où se termine le corps, et la chaîne de caractères complète du corps.

$obj->bodyDelayed( [$chars, [$lines]] )
Tente de lire le corps d'un message depuis le fichier, mais les données sont ignorées. Optionnellement, le nombre de caractères prédits et/ou de lignes prédites à ignorer peut être passé. Ces valeurs peuvent être "undef" et peuvent être incorrectes.

La valeur de retour est une liste de quatre scalaires : l'emplacement du corps (début et fin), la taille du corps et le nombre de lignes dans le corps. Le nombre de lignes peut être "undef".

$obj->lineSeparator()
Retourne le ou les caractères utilisés pour séparer les lignes dans le fichier de boîte aux lettres. Ceci est basé sur la première ligne du fichier. Les systèmes UNIX utilisent une seule LF pour séparer les lignes. Les machines Windows utilisent un CR et une LF. Mac utilise un CR.
$obj->readHeader()
Lit l'intégralité de l'en-tête du message et le retourne sous forme de liste de paires champ-valeur. Il faut tenir compte du fait que certains champs peuvent apparaître plus d'une fois.

Le premier élément représente l'emplacement dans le fichier où commence l'en-tête. Vient ensuite la liste des champs d'en-tête et leurs valeurs.

Exemple :

my ($where, @header) = $parser->readHeader;
$obj->stop()
Arrête le parseur.

Gestion des séparateurs

Les différentes méthodes de "séparateur" sont utilisées par Mail::Message::Body::Multipart pour détecter les parties, et par les boîtes aux lettres basées sur des fichiers pour marquer où commence un nouveau message.

$obj->activeSeparator()
$obj->popSeparator()
Retire le séparateur le plus récent de la liste maintenue par le parseur. Cette fonction retourne "undef" lorsqu'il n'y a plus de séparateurs.
$obj->pushSeparator(STRING|Regexp)
Ajoute une ligne de séparateur. Les séparateurs indiquent au parseur où arrêter la lecture. Une ligne célèbre est la ligne "From", qui est utilisée dans les boîtes aux lettres de type Mbox pour séparer les messages. Cependant, des séparateurs sont également utilisés pour diviser les messages en parties (pièces jointes).

Le "STRING" spécifié est utilisé comme ligne de séparation.

DIAGNOSTICS

Erreur: Nom de fichier ou handle requis pour créer un analyseur.
Un analyseur de message a besoin de connaître la source du message lors de sa création. Ces sources peuvent être un nom de fichier (string), un objet handle de fichier ou un GLOB. Voir new(filename) et new(file). Causé par new()
Erreur: Le package $package n'implémente pas $method.
Erreur de type : le package spécifié (ou l'une de ses superclasses) n'implémente pas cette méthode alors qu'il le devrait. Ce message signifie que certaines autres classes liées implémentent cette méthode, mais pas la classe en question. Vous devriez probablement enquêter sur cela et probablement signaler l'auteur du package. Causé par notImplemented()
Avertissement: Fin inattendue de l'en-tête dans $source: $line
Lors de l'analyse d'un message depuis la source spécifiée (généralement un nom de fichier), l'analyseur a rencontré une erreur de syntaxe. Selon la spécification MIME des RFC, chaque ligne d'en-tête doit contenir un double-point ou commencer par un espace pour indiquer un champ replié. Apparemment, cet en-tête contient une ligne qui commence en première position, mais pas avec un nom de champ.

Par défaut, l'analyse de l'en-tête s'arrête. S'il y a d'autres lignes d'en-tête après la ligne erronée, elles sont ajoutées au corps du message. Si new(fix_header_errors) est défini, l'analyse de l'en-tête continue. La ligne erronée sera ajoutée au champ précédent. Causé par readHeader()
