Mail::Box::Thread::Manager(3) Documentation Perl fournie par l'utilisateur Mail::Box::Thread::Manager(3)

NOM

Mail::Box::Thread::Manager - maintenir des fils de discussion dans un ensemble de dossiers

HÉRITAGE

Mail::Box::Thread::Manager
  est un Mail::Reporter

SYNOPSIS

my $mgr     = Mail::Box::Manager->new;
my $folder  = $mgr->open(folder => '/tmp/inbox');
my $threads = $mgr->threads();
$threads->includeFolder($folder);
my $threads = $msg->threads(folder => $folder);
foreach my $thread ($threads->all) {
    $thread->print;
}
$threads->removeFolder($folder);

DESCRIPTION

Un (fil de message)thread est un message avec des liens vers des messages qui l'ont suivi en réponse. Et puis les messages qui ont répondu aux messages qui ont répondu au message original. Et ainsi de suite. Certains fils de discussion n'ont qu'un seul message (jamais répondu), certains fils de discussion sont très longs.

Le "Mail::Box::Thread::Manager" est très puissant. Non seulement il est capable de faire un travail décent sur les dossiers de type MH (fait un compromis entre perfection et vitesse), mais il peut également maintenir des fils de discussion à partir de messages résidant dans différents dossiers ouverts. Ces deux facilités sont rares pour les agents de messagerie. Le gestionnaire crée des arbres flexibles avec des objets Mail::Box::Thread::Node.

PAS ENCORE IMPLÉMENTÉ.
thread_type => CLASSE
Type des nœuds de fil de discussion.
timespan => TEMPS | 'EVER'
Spécifie la rapidité habituelle de fonctionnement des fils de discussion : le temps entre une réponse et une réplique. Ceci est utilisé en combinaison avec l'option "window" pour déterminer quand abandonner le remplissage des lacunes dans les fils de discussion.

Voir Mail::Box::timespan2seconds() pour les possibilités de TEMPS. Avec 'EVER', la recherche de messages dans un fil de discussion ne sera limitée que par la taille de la fenêtre.

trace => NIVEAU
window => ENTIER|'ALL'
La fenêtre de fil de discussion décrit combien de messages doivent être vérifiés au maximum pour combler les 'lacunes' dans les fils de discussion pour les dossiers qui utilisent le chargement différé des en-têtes de messages.

La constante 'ALL' empêchera la détection de fils de discussion de s'arrêter d'essayer de combler les lacunes, mais continuera à chercher jusqu'au premier message du dossier. Donne les meilleurs résultats, mais peut être lent.

» exemple:

use Mail::Box::Manager;
my $mgr     = Mail::Box::Manager->new;
my $inbox   = $mgr->open(folder => $ENV{MAIL});
my $read    = $mgr->open(folder => 'Mail/read');
my $threads = $mgr->threads(folders => [$inbox, $read]);
# alternative plus longue pour la dernière ligne :
my $threads = $mgr->threads;
$threads->includeFolder($inbox);
$threads->includeFolder($read);

Groupement des dossiers

$obj->includeFolder(@folders)
Ajoute un ou plusieurs @folders à la LISTE des dossiers dont les messages sont organisés dans les fils de discussion maintenus par cet objet. Les inclusions dupliquées ne causeront aucun problème.

Parmi les dossiers, les messages dont les lignes d'en-tête ont été analysées (voir Mail::Box sur l'extraction différée) seront immédiatement analysés. Les messages dont l'en-tête n'est connu que plus tard devront le signaler (voir toBeThreaded()).

» exemple:

$threads->includeFolder($inbox, $draft);
$obj->removeFolder(@folders)
Supprime un ou plusieurs @folders de la LISTE des dossiers dont les messages sont organisés dans les fils de discussion maintenus par cet objet.

» exemple:

$threads->removeFolder($draft);

Les fils de discussion

$obj->all()
Retourne tous les messages qui débutent un fil de discussion. La liste peut contenir des messages fictifs et des messages prévus pour suppression.

Pour pouvoir retourner tous les fils de discussion, la construction des fils de discussion sur chaque message est effectuée d'abord, ce qui peut être lent pour certains types de dossiers car cela forcera l'analyse des corps de messages.

$obj->known()
Retourne la liste de tous les messages qui sont connus comme début d'un fil de discussion. Les fils de discussion contenant des messages qui n'ont pas été lus depuis leur dossier (comme cela arrive souvent avec les messages des dossiers MH) ne sont pas encore connus, et donc ne seront pas retournés.

La liste peut contenir des messages fictifs et des messages prévus pour suppression. Les fils de discussion sont détectés en appelant explicitement inThread() et thread() avec des messages du dossier.

Attention, à chaque fois que l'en-tête d'un message est lu à partir du dossier, le retour de la méthode peut changer.

$obj->sortedAll( [$prepare, [$compare]] )
Retourne par défaut tous les fils de discussion (all()), mais triés par horodatage.
$obj->sortedKnown( [$prepare, [$compare]] )
Retourne tous les fils de discussion connus (known()), dans l'ordre trié. Par défaut, les fils de discussion seront triés par horodatage. Mais une méthode $compare différente peut être spécifiée.

$obj->thread($message)
Retourne le fil de discussion où ce $message est le début. Cependant, il est possible que ce message soit lui-même une réponse.

Généralement, tous les messages qui répondent à ce message sont datés après celui spécifié. Tous les en-têtes des messages postérieurs à celui-ci sont analysés en premier, pour chaque dossier de cet objet de fils de discussion.

» exemple:

my $threads = $mgr->threads(folder => $inbox);
my $thread  = $threads->thread($inbox->message(3));
print $thread->string;
$obj->threadStart($message)
Basé sur un $message et sur les faits des fils de discussion précédemment détectés, essaie de construire une connaissance solide sur le fil de discussion auquel ce message appartient.

DÉTAILS

Ce module implémente la détection de fils de discussion dans un dossier. Les messages créés par les meilleurs programmes de messagerie incluent les lignes "In-Reply-To" et "References", qui sont utilisées pour déterminer comment les messages sont liés. Si vous préférez une meilleure détection des fils de discussion, elles sont implémentables, mais il peut y avoir un impact sérieux sur les performances (dépend du type de dossier utilisé).

Maintien des fils de discussion

Un objet "Mail::Box::Thread::Manager" est créé par Mail::Box::Manager, en utilisant Mail::Box::Manager::threads(). Chaque objet peut surveiller les relations de fils de discussion entre les messages d'un ou plusieurs dossiers. Lorsque plus d'un dossier est spécifié, les messages sont fusionnés lors de la lecture des fils de discussion, bien que rien ne change dans la structure des dossiers. L'ajout et la suppression de dossiers à maintenir sont autorisés à tout moment, bien que cela puisse être coûteux en termes de performances.

Un exemple de la structure maintenue est montré ci-dessous. Le Mail::Box::Manager a deux dossiers ouverts, et un constructeur de fils de discussion qui les surveille tous les deux. Les dossiers combinés ont deux fils de discussion, le second est trop long (msg3 est une réponse à msg2). Msg2 est présent dans deux dossiers simultanément.

manager
 |    \
 |     `----------- threads
 |                  |     |
 |                thread thread---thread
 |                  |    /|        /
 |                  |   //        /
 +---- folder1      |  //        /
 |       |         /  //        /
 |       `-----msg1  //        /
 |       `-----msg2-'/        /
 |                  /        /
 `-----folder2     /        /
         |        /        /
         `-----msg2       /

Détection retardée des fils de discussion

Avec all() vous obtenez les messages de départ de chaque fil de discussion de ce dossier. Si ce message n'a pas été trouvé dans le dossier (pas sauvegardé ou déjà supprimé), vous obtenez un message de type factice. Ces descriptions de fils de discussion sont en parfait état : tous les messages du dossier sont inclus quelque part, et chaque message manquant des fils de discussion (les *trous*) est rempli par des messages factices.

Cependant, pour pouvoir détecter tous les fils de discussion, il est nécessaire d'avoir les en-têtes de tous les messages, ce qui est très lent pour certains types de dossiers, notamment les dossiers MH et IMAP.

Pour les lecteurs de courrier interactifs, il est préférable de détecter les fils de discussion uniquement sur les messages qui sont visibles par l'utilisateur. Cela peut être négligent dans certaines situations, mais tout est préférable à la lecture d'une boîte aux lettres MH contenant 10 000 e-mails pour ne lire que les messages les plus récents.

Dans cet objet, nous prenons un soin particulier à ne pas provoquer d'analyse (chargement) inutile des messages. Les fils de discussion ne seront détectés que sur commande, et par défaut, seuls les en-têtes des messages sont utilisés.

Le code suivant signale le nœud Mail::Box::Thread::Node lié à un message :

my $thread = $message->thread;

Si le message n'a pas encore été inséré dans un fil de discussion, cela est fait maintenant. Mais, plus de travail est effectué pour retourner le meilleur fil de discussion. Sur la base de divers paramètres spécifiés lors de la création du dossier, la méthode parcourt le dossier pour combler les trous dans ce fil de discussion.

En parcourant de la fin vers le début (les messages arrivés récemment sont généralement à la fin du dossier), les messages un par un sont déclenchés pour être inclus dans leur fil de discussion. À un certain moment, tout le fil de discussion de la méthode demandée est trouvé, un certain nombre maximum de messages a été essayé sans succès (fenêtre de recherche atteinte), ou les messages du dossier deviennent trop anciens. La recherche pour compléter le fil de discussion se termine alors, bien que d'autres messages aient pu s'y trouver : nous ne scannons pas tout le dossier pour des raisons de performance.

Enfin, pour chaque message dont l'en-tête est connu, par exemple pour tous les messages des dossiers mbox, le fil de discussion correct est déterminé immédiatement. De plus, tous les messages dont l'en-tête sera chargé plus tard, seront automatiquement inclus.
