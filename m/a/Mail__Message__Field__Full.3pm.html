NOM

Mail::Message::Field::Full - construire une ligne d'en-tête de message intelligente

HÉRITAGE

Mail::Message::Field::Full
                              est un Mail::Message::Field
                              est un Mail::Reporter
                            Mail::Message::Field::Full est étendu par
                              Mail::Message::Field::Structured
                              Mail::Message::Field::Unstructured

SYNTAXE

# Comprendre la complexité d'un en-tête de message...
my $fast = $msg->head->get('subject');
my $full = Mail::Message::Field::Full->from($fast);
my $full = $msg->head->get('subject')->study;  # idem
my $full = $msg->head->study('subject');       # idem
my $full = $msg->study('subject');             # idem
# ... ou construire un en-tête de message complexe vous-même
my $f = Mail::Message::Field::Full->new('To');
my $f = Mail::Message::Field::Full->new('Subject: hi!');
my $f = Mail::Message::Field::Full->new(Subject => 'hi!');

DESCRIPTION

C'est l'implémentation complète d'un en-tête de message : elle a une compréhension complète de tous les en-têtes prédéfinis. Ces objets seront assez lents, car les en-têtes peuvent être très complexes. Bien sûr, cette classe fournit le résultat optimal, mais avec un coût significatif en termes de performances et de consommation mémoire. Êtes-vous prêt à l'accepter ?

Cette classe supporte la description courante des en-têtes de message selon la RFC2822 (anciennement RFC822), les extensions concernant les encodages de caractères selon la RFC2047 et les extensions sur la spécification de langue et la transmission de paramètres longs selon la RFC2231. Si vous n'avez pas besoin des deux derniers, alors Mail::Message::Field::Fast et Mail::Message::Field::Flex suffisent pour votre application.

La RFC5322 (https://www.rfc-editor.org/rfc/rfc5322.html) décrit une longue liste de syntaxes obsolètes pour les en-têtes de message structurés. Cela concerne principalement l'interdiction des espaces et des doubles lignes à des endroits inhabituels. Cela correspond au comportement naturel de MailBox.

Constructeurs

Étendu de "Constructeurs" dans Mail::Message::Field.

$obj->clone()
Hérité, voir "Constructeurs" dans Mail::Message::Field
$class->from($field, %options)
Convertit n'importe quel $field (un objet Mail::Message::Field) en un nouvel objet Mail::Message::Field::Full. Cette conversion est effectuée de manière très directe : la chaîne générée par l'objet original est réanalysée. En général, la chaîne qui est réanalysée est exactement la ligne (ou les lignes) trouvées dans la source d'entrée, ce qui est une bonne chose, car les champs de message complets sont plus attentifs au contenu réel.

%options sont passées au constructeur (voir new()). Dans tous les cas, certaines extensions de cette classe de champ Full sont retournées. Selon le champ créé, la classe retournée peut varier.

Exemple :

my $fast = $msg->head->get('subject');
my $full = Mail::Message::Field::Full->from($fast);
my $full = $msg->head->get('subject')->study;  # idem
my $full = $msg->head->study('subject');       # idem
my $full = $msg->study('subject');             # idem
$class->new(($line | $name, [$body], @attributes), %options)
Créer correctement un objet de champ est un travail très laborieux, car il y a tellement de liberté dans les RFCs, mais aussi tellement de restrictions. La plupart des champs sont implémentés, mais si vous avez votre propre champ (et que vous ne voulez pas le contribuer à MailBox), appelez simplement new dans votre propre package.

Vous avez le choix d'instancier l'objet sous forme de chaîne ou en parties préparées :

  • new($line, %options)

    Passez une $line telle qu'elle peut être trouvée dans un fichier : une ligne (éventuellement pliée) se terminant par un retour à la ligne.

  • new($name, [$body], @attributes, %options)

    Un ensemble de valeurs qui forment la ligne.

Le $name est un nom d'en-tête bien formé (vous pouvez utiliser wellformedName() pour assurer la casse). Le $body est une chaîne, un objet ou un tableau d'objets. Dans le cas d'objets, ils doivent correspondre au constructeur du champ. Les types acceptés peuvent varier. La liste optionnelle d'attributs contient des objets de type Mail::Message::Field::Attribute. Enfin, il y a quelques options. Étendu de la base, voir "Constructeurs" dans Mail::Message::Field.

-Option  -- Défini dans      -- Valeur par défaut
                                 charset                    undef
                                 encoding                   'q'
                                 force                      false
                                 language                   undef
                                 log       Mail::Reporter   'WARNINGS'
                                 trace     Mail::Reporter   'WARNINGS'
charset => $charset
Le corps est spécifié en UTF-8, et doit être converti en ASCII 7 bits pour être transmis. Spécifiez un $charset vers lequel le multi-octet UTF-8 est converti avant d'être encodé. Voir encode(), qui fait le travail.
encoding => 'q'|'Q'|'b'|'B'
Les caractères non ASCII sont encodés en utilisant Quoted-Printable ('q' ou 'Q') ou Base64 ('b' ou 'B').
force => BOOLEAN
Forcer l'encodage dans le charset spécifié, même si ce n'est pas nécessaire car le corps ne contient pas de caractères non ASCII.
language => $language
Le $language utilisé peut être spécifié, bien qu'il soit rarement utilisé par les clients de messagerie.
log => LEVEL
trace => LEVEL

Exemple :

my $s = Mail::Message::Field::Full->new('Subject: Hello World');
my $s = Mail::Message::Field::Full->new('Subject', 'Hello World');
my @attrs   = (Mail::Message::Field::Attribute->new(...), ...);
my @options = (extra => 'la couleur bleue');
my $t = Mail::Message::Field::Full->new(To => \@addrs, @attrs, @options);

Crée un commentaire qui sera partie d'un champ. Les commentaires sont automatiquement mis entre parenthèses. Les paires de parenthèses sont autorisées à l'intérieur du "STRING". $any->decode(STRING, %options)
Décode la "STRING" du champ encodé en une chaîne utf8. La "STRING" fait partie d'un champ d'en-tête, et comme tel peut contenir des mots encodés au format "=?...?...?...?=" défini par RFC2047. La "STRING" peut contenir plusieurs parties encodées, utilisant peut-être des encodages différents.

Attention: vous devez d'abord interpréter le champ en parties, comme phrases et commentaires, puis décoder chaque partie séparément, autrement le texte décodé risque d'interférer avec vos caractères de balisage.

Les informations de langue, définies par RFC2231, sont ignorées.

Les codes avec des charsets inconnus sont laissés tels quels [nécessite v2.085, sinon une exception est levée]. Les caractères inconnus dans un charset sont remplacés par un '?'.

-Option --Default
 is_text  true
is_text => BOOLEAN
L'encodage en texte est un peu plus complexe que l'encodage de données structurées, car il contient des espaces blancs. Les espaces blancs visibles doivent être ignorés entre deux mots encodés dans le texte, mais pas quand un mot encodé suit ou précède un mot non encodé. Les phrases et les commentaires sont des textes.

» exemple:

print Mail::Message::Field::Full->decode('=?iso-8859-1?Q?J=F8rgen?=');
   # imprime   Jørgen
$obj->defaultWrapLength( [$length] )
Inhérent, voir "Internes" dans Mail::Message::Field
$obj->encode(STRING, %options)
Encode la "STRING" (potentiellement encodée en utf8) en une chaîne acceptable par la définition RFC2047 d'un champ d'en-tête : ne contient que des caractères us-ascii. 
-Option  --Default
 charset   'us-ascii'
 encoding  'q'
 force     false
 language  undef
 name      undef
charset => STRING
La "STRING" est une chaîne utf8 qui doit être traduite dans n'importe quel jeu de caractères d'octets pour le transport, car les en-têtes MIME ne peuvent contenir que des caractères ascii.
encoding => 'q'|'Q'|'b'|'B'
Le type d'encodage à utiliser. Avec "q" ou "Q", l'encodage quoted-printable sera utilisé. Avec "b " ou "B ", l'encodage base64 sera utilisé.
force => BOOLEAN
Encode la chaîne, même si elle ne contient que des caractères us-ascii. Par défaut, cette option est désactivée car elle réduit la lisibilité des champs d'en-tête générés.
language => STRING
Définit comment spécifier les codes de langue dans les mots encodés. La "STRING" est un nom de langue standard iso.
name => STRING
[3.002] Quand le nom du champ est donné, la première ligne encodée sera plus courte.

Parsing

Vous ne voudrez probablement pas appeler vous-même ces méthodes de parsing : utilisez les constructeurs standards (new()) et cela sera fait pour vous.

$any->consumeComment(STRING)
Tente de lire un commentaire depuis la "STRING". En cas de succès, le commentaire sans les parenthèses englobantes est retourné, ainsi que le reste de la chaîne.
$obj->consumeDotAtom(STRING)
Retourne trois éléments : le texte de l'atome, la chaîne restante et les commentaires concaténés. L'atome et les commentaires peuvent être "undef".
$any->consumePhrase(STRING)
Prend la "STRING" et tente d'en retirer une phrase valide. Dans l'ancienne syntaxe de phrase, toute séquence de mots est acceptée comme une phrase (sauf utilisation de certains caractères spéciaux). RFC2822 est plus strict : un seul mot ou une chaîne citée est autorisée. Comme toujours, l'ancienne syntaxe est acceptée et la nouvelle est produite.

Cette méthode retourne deux éléments : la phrase (ou "undef") suivi de la chaîne résultante. La phrase sera retirée du

les guillemets optionnels. Soyez averti que "" renverra une phrase vide et valide.

» exemple :

my ($phrase, $rest) = $field->consumePhrase( q["hi!" <sales@example.com>] );
$obj->parse(STRING)
Obtient les informations détaillées de la "STRING" et stocke les données trouvées dans l'objet champ. L'entrée acceptée dépend fortement du type de champ. Les champs non structurés n'effectuent aucun traitement.
$obj->produceBody()
Produit le texte du champ, en se basant sur les informations stockées dans l'objet champ.

Généralement, vous souhaitez la même ligne que celle trouvée dans la source d'entrée d'un message. Mais lorsque vous avez créé un champ vous-même, il devrait être formaté. Vous pouvez appeler beautify() sur un champ préformaté pour forcer un appel à cette méthode lorsque le champ est requis plus tard.

DIAGNOSTICS

Avertissement : le contenu du champ n'est pas numérique : $content
La valeur numérique d'un champ est demandée (par exemple, les champs "Lines" ou "Content-Length" devraient être numériques), cependant les données contiennent des caractères étranges. Conversion par toInt()
Erreur : le nom du champ est trop long (max $length), dans '$name'
Il n'est pas spécifié dans les RFCs quelle est la longueur maximale d'un nom de champ, mais au moins il devrait être quelques caractères plus court que le retour à la ligne. Conversion par fold()
Avertissement : caractère illégal dans le jeu de caractères '$charset'
Le champ est créé avec une chaîne utf8 qui ne contient que des données du jeu de caractères spécifié. Cependant, ce jeu de caractères ne peut jamais être un nom valide car il contient des caractères qui ne sont pas autorisés. Conversion par encode()
Avertissement : caractère illégal dans le nom du champ $name
Un nouveau champ est créé qui contient des caractères non autorisés par les RFCs. L'utilisation de ce champ dans les messages peut casser d'autres clients de messagerie ou agents de transfert, et donc mutiler ou éteindre votre message. Conversion par consume()
Avertissement : caractère illégal dans la langue '$lang'
Le champ est créé avec des données spécifiées pour être dans une certaine langue, cependant, le nom de la langue ne peut pas être valide : il contient des caractères non autorisés par les RFCs. Conversion par encode()
Avertissement : encodage illégal '$encoding', utilisation de 'q'
Les RFCs n'autorisent que l'encodage base64 ("b " ou "B ") ou quoted-printable ("q" ou "Q"). D'autres options que ces quatre sont illégales. Conversion par encode()
Erreur : le paquet $package n'implémente pas $method.
Erreur fatale : le paquet spécifique (ou l'une de ses superclasses) n'implémente pas cette méthode là où il le devrait. Ce message signifie que certaines autres classes connexes implémentent cette méthode, mais pas la classe en question. Probablement, vous devriez investiguer cela et probablement informer l'auteur du paquet. Conversion par notImplemented()
