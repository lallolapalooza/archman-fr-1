Mail::SpamAssassin::Timeout(3) Documentation Perl fournie par l'utilisateur Mail::SpamAssassin::Timeout(3)

NOM

Mail::SpamAssassin::Timeout - des délais d'attente sûrs et fiables en perl

SYNOPIS

# code sans délai d'attente...
my $t = Mail::SpamAssassin::Timeout->new({ secs => 5, deadline => $quand });
$t->run(sub {
    # code à exécuter avec un délai d'attente de 5 secondes...
});
if ($t->timed_out()) {
    # faire quelque chose...
}
# plus de code sans délai d'attente...

DESCRIPTION

Ce module fournit une API sûre, fiable et propre pour implémenter des délais d'attente basés sur alarm(2) pour le code perl.

Notez que $SIG{ALRM} est utilisé pour fournir le délai d'attente, donc cela n'interrompra pas les correspondances d'expressions régulières incontrôlables.

Les délais d'attente imbriqués sont pris en charge.

MÉTHODES PUBLIQUES

my $t = Mail::SpamAssassin::Timeout->new({ ... options ... });
Constructeur. Les options incluent :
secs => $secondes
intervalle de temps, en secondes. Facultatif ; si ni "secs" ni "deadline" n'est spécifié, aucun délai d'attente ne sera appliqué.
deadline => $horodatage_unix
Horodatage Unix (secondes depuis l'époque) jusqu'auquel un délai d'attente est atteint au plus tard. Facultatif ; si ni secs ni deadline n'est spécifié, aucun délai d'attente ne sera appliqué. Si les deux sont spécifiés, l'intervalle le plus court des deux prévaut.
$t->run($coderef)
Exécute une référence de code dans le délai d'attente actuellement défini.

Le délai d'attente est tel que défini par les paramètres secs et deadline du constructeur.

Retourne ce que la sous-routine retourne, ou "undef" en cas de délai d'attente dépassé. Si le minuteur expire, "$t->timed_out()" retournera 1.

Le temps écoulé n'est pas cumulatif ; plusieurs appels à "run" redémarreront le délai d'attente à partir de zéro. D'autre part, les minuteurs imbriqués respectent les délais d'attente externes s'ils sont plus courts, signalant à nouveau un délai d'attente au niveau qui les a établis, c'est-à-dire que le code exécuté sous un minuteur interne ne peut pas dépasser la limite de temps établie par un minuteur externe. Lors du redémarrage d'un minuteur externe au retour, le temps écoulé du code en cours d'exécution est pris en compte.

$t->run_and_catch($coderef)
Exécute une référence de code, comme pour "$t->run()", mais capture également tous les appels die() dans la référence de code.

Retourne "undef" si aucun appel die() n'a été exécuté et que $@ était non défini, ou la valeur de $@ s'il était défini. (L'événement de délai d'attente ne compte pas comme un die().)

$t->timed_out()
Retourne 1 si le code le plus récent exécuté dans run() a dépassé le délai d'attente, ou "undef" s'il ne l'a pas fait.
$t->reset()
Si appelé dans une référence de code run(), restaure le minuteur d'alarme actuel à son réglage d'origine (utile après que notre paramètre d'alarme ait été corrompu par un module sous-jacent).
