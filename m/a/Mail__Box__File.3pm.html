NAME

Mail::Box::File - répertoires basés sur des fichiers

INHERITANCE

Mail::Box::File
  est une classe de Mail::Box
  est une classe de Mail::Reporter
Mail::Box::File est étendue par
  Mail::Box::Mbox

SYNOPSIS

DESCRIPTION

Mail::Box::File est la classe de base pour tous les répertoires basés sur des fichiers : des répertoires qui empaquètent plusieurs messages dans un seul fichier. Généralement, ces messages sont séparés par une ligne spéciale qui indique le début du suivant.

Lors de l'utilisation du mécanisme de verrouillage par points de verrouillage, le verrou est créé avec une liaison dure vers le fichier du répertoire. Pour les répertoires de type « Mail::Box::File », ce nom de fichier par défaut est le fichier du répertoire lui-même suivi de « .lock ». Par exemple : le fichier du répertoire « Mail/inbox » aura une liaison dure créée sous la forme « Mail/inbox.lock ».

Vous pouvez spécifier un fichier absolu, un nom relatif (au répertoire du dossier) ou une extension (précédée d'un point). Par conséquent, des exemples valides sont :

.lock                  # attaché au nom du répertoire
my_own_lockfile.test   # nom complet, même répertoire
/etc/passwd            # ailleurs

Lorsque le programme s'exécute avec moins de privilèges (en tant qu'utilisateur normal), le répertoire d'entrée par défaut ne peut souvent pas être verrouillé avec le nom de fichier de verrouillage généré par défaut.

-Option      --Defini dans     --Défaut
 force         Mail::Box        false

force => BOOLEAN
policy => 'REPLACE'|'INPLACE'|undef
De quelle manière la boîte aux lettres sera mise à jour. Si non spécifié lors de l'écriture, la valeur de new(write_policy) lors de la création du dossier est utilisée.

Valeurs valides :

  • "REPLACE"

    Un nouveau dossier est d'abord écrit dans le même répertoire que le dossier à mettre à jour, puis un appel à move supprime l'ancien en le remplaçant par le nouveau.

    L'écriture en module "REPLACE" est légèrement optimisée : les messages qui ne sont pas modifiés sont copiés du fichier au fichier, octet par octet. C'est beaucoup plus rapide que d'imprimer les données, ce qui sera fait pour les messages modifiés.

  • "INPLACE"

    Le fichier dossier d'origine sera ouvert en lecture/écriture. Tous les messages qui n'ont pas été modifiés resteront inchangés, jusqu'à ce que le premier message supprimé ou modifié soit détecté. Tous les messages suivants seront réimprimés.

  • "undef"

    Par défaut, ou lorsque "undef" est explicitement spécifié, le mode "REPLACE" est d'abord essayé. Seulement lorsque cela échoue, une mise à jour "INPLACE" est effectuée.

"INPLACE" sera beaucoup plus rapide que "REPLACE" lorsqu'il est appliqué à de grands dossiers, mais nécessite que la fonction "truncate" soit implémentée sur votre système d'exploitation (au moins disponible pour les versions récentes de Linux, Solaris, Tru64, HPUX). C'est aussi dangereux : si le programme est interrompu pendant le processus de mise à jour, le dossier est corrompu. Des données peuvent être perdues.

Cependant, dans certains cas, il n'est pas possible d'écrire le dossier avec "REPLACE". Par exemple, le dossier de courrier entrant habituel sur UNIX est stocké dans un répertoire où un utilisateur ne peut pas écrire. Bien sûr, les utilisateurs "root" et "mail" le peuvent, mais si vous souhaitez utiliser ce module Perl avec la permission d'un utilisateur normal, vous ne pourrez le faire qu'en mode "INPLACE". DÉTAILS

Dossiers basés sur des fichiers

Les dossiers basés sur des fichiers maintiennent un dossier (un ensemble de messages) dans un seul fichier. L'avantage est que votre dossier n'a qu'un seul nom, ce qui accélère l'accès à tous les messages en même temps.

Le désavantage par rapport aux dossiers basés sur des répertoires (voir Mail::Box::Dir) est que vous devez trouver un moyen de séparer tous les messages, par exemple en ajoutant un séparateur de messages, et cela causera des problèmes. Alors que l'accès à tous les messages en même temps est plus rapide dans les dossiers basés sur des fichiers, l'accès à un seul message est (beaucoup) plus lent, car tout le dossier doit être lu.

DIAGNOSTICS

Erreur : Impossible d'ajouter des messages au fichier de dossier $filename : $!
L'ajout de messages à un dossier non ouvert organisé par fichier peut échouer lorsque le système d'exploitation n'autorise pas l'accès en écriture au fichier concerné. Déclenché par appendMessages()
Erreur : Impossible de créer le répertoire $dir pour le dossier $name.
Lors de la création d'un dossier organisé par fichier, au plus un niveau de répertoires est créé au-dessus. Apparemment, plus de niveaux de répertoires sont nécessaires, ou le système d'exploitation ne vous permet pas de créer le répertoire. Déclenché par create()
Erreur : Impossible de créer le fichier de dossier $name : $!
Le fichier du dossier organisé par fichier ne peut pas être créé pour la raison indiquée. Dans les cas courants, le système d'exploitation ne vous accorde pas l'accès en écriture au répertoire où le fichier du dossier doit être stocké. Déclenché par create()
Erreur : Impossible d'obtenir un verrou sur le dossier de type $type $self.
Un verrou est nécessaire pour accéder au dossier. Si aucun verrou n'est nécessaire, spécifiez le type de verrou NONE. Déclenché par new()
Erreur : Impossible de déplacer le sous-dossier $dir
Déclenché par moveAwaySubFolder()
Avertissement : Impossible de supprimer le fichier du dossier $name $filename : $!
L'écriture d'un dossier vide entraînera généralement sa suppression, ce qui échoue pour la raison indiquée. new(remove_when_empty) Déclenché par write()
Avertissement : Impossible de supprimer le fichier du dossier $name $filename : $!
L'écriture d'un dossier vide entraînera généralement sa suppression, ce qui échoue pour la raison indiquée. new(remove_when_empty) contrôle si le dossier vide sera supprimé ; il peut être nécessaire de le définir sur "false" (0) pour éviter ce message. Déclenché par write()
Erreur : Impossible de remplacer $filename par $tempname, pour mettre à jour le dossier $name : $!
La politique de remplacement a écrit un nouveau fichier de dossier pour mettre à jour l'existant, mais n'a pas pu effectuer la touche finale : remplacer l'ancienne version du fichier de dossier pour la raison indiquée. Déclenché par write()
Avertissement : Modifications non écrites sur le dossier $self en lecture seule.
Vous avez ouvert le dossier en lecture seule --ce qui est la valeur par défaut définie par new(access)--, effectué des modifications, et vous souhaitez maintenant le fermer. Définissez close(force) si vous souhaitez remplacer le mode d'accès, ou fermez le dossier avec close(write) défini sur "NEVER". Déclenché par close()
Erreur : Copie échouée pour un message.
Pour une raison quelconque, par exemple disque plein, supprimé par un processus externe, ou protection en lecture, il est impossible de copier l'un des messages. La copie se poursuivra pour les autres messages. Déclenché par copyTo()
Erreur : Le dossier de destination $name n'est pas accessible en écriture.
Le dossier vers lequel les messages sont copiés n'est pas ouvert avec un accès en écriture (voir new(access)). Cela n'a aucun rapport avec la permission d'écriture sur le dossier, qui est contrôlée par votre système d'exploitation. Déclenché par copyTo()
Avertissement : Différents messages avec l'id $msgid
L'identifiant du message est découvert plus d'une fois au sein du même dossier, mais le contenu du message semble différent. Cela ne devrait pas être possible : chaque message doit être unique. Déclenché par messageId()
Info : Le fichier $filename pour le dossier $self n'existe pas.
Déclenché par new()
Erreur : Fichier trop court pour obtenir le message d'écriture $nr ($size, $need)
Mail::Box est paresseux : il essaie de laisser les messages dans les dossiers jusqu'à ce qu'ils soient utilisés, ce qui permet d'économiser du temps et de la mémoire. Lorsque ce message apparaît, quelque chose ne va pas : certains messages paresseux sont nécessaires pour mettre à jour le dossier, mais ils ne peuvent plus être récupérés du fichier d'origine. Dans ce cas, des messages peuvent être perdus.

Ce message apparaît régulièrement sur les systèmes Windows lors de l'utilisation de la politique d'écriture 'replace'. Veuillez aider à trouver la cause, probablement quelque chose lié à la gestion incorrecte par Windows de plusieurs descripteurs de fichiers ouverts dans le même fichier. Déclenché par write()

Avertissement : Le fichier du dossier $name $file est protégé en écriture.
Le dossier est ouvert en écriture ou pour ajout via new(access), mais le système d'exploitation n'autorise pas l'écriture sur le $file. Le dossier sera ouvert en lecture seule. Déclenché par new()
Erreur : Le dossier $name n'a pas été supprimé : non accessible en écriture.
Le dossier doit être ouvert avec un accès en écriture via new(access), sinon sa suppression sera refusée. Ainsi, vous pouvez avoir un accès en écriture selon le système d'exploitation, mais cela ne signifie pas automatiquement que cette méthode "delete" vous y autorise. La remarque inverse est également valable. Déclenché par delete()
Erreur : Intervalle de temps invalide '$timespan' spécifié.
La chaîne ne suit pas les règles strictes de la syntaxe de l'intervalle de temps qui est autorisée en tant que paramètre. Déclenché par timespan2seconds()
Avertissement : L'identifiant de message '$msgid' ne contient pas de domaine.
Selon les RFC, les identifiants de message doivent contenir une partie aléatoire unique, puis un "@", puis un nom de domaine. Ceci est fait pour éviter la création de deux messages avec le même identifiant. L'avertissement apparaît lorsque le "@" est manquant dans la chaîne. Déclenché par messageId()
Erreur : Le package $package n'implémente pas $method.
Erreur fatale : le package spécifique (ou l'une de ses superclasses) n'implémente pas cette méthode alors qu'il devrait. Ce message signifie que d'autres classes liées implémentent cette méthode, mais pas la classe concernée. Vous devriez probablement enquêter à ce sujet et informer l'auteur du package. Déclenché par notImplemented()
Erreur : Impossible de créer le sous-dossier $name de $folder.
La copie inclut les sous-dossiers, mais pour une raison quelconque, il n'a pas été possible d'en copier un. La copie se poursuivra pour tous les autres sous-dossiers. Déclenché par copyTo()
Erreur : Impossible de mettre à jour le dossier $self.
Lorsqu'un dossier doit être écrit, les politiques d'écriture par remplacement et sur place sont essayées. Si les deux échouent, la mise à jour entière échoue. Vous pourriez voir d'autres messages d'erreur connexes pour indiquer le problème réel. Déclenché par write()
