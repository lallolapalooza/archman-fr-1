NOM

Mail::Message::Field - une ligne d'en-tête d'un message

HÉRITAGE

Mail::Message::Field
  est une Mail::Reporter
Mail::Message::Field est étendu par
  Mail::Message::Field::Fast
  Mail::Message::Field::Flex
  Mail::Message::Field::Full

SYNTAXE

my $field = Mail::Message::Field->new(From => 'fish@tux.aq');
print $field->name;
print $field->body;
print $field->comment;
print $field->content;  # corps & commentaire
$field->print(\*OUT);
print $field->string;
print "$field\n";
print $field->attribute('charset') || 'us-ascii';

DESCRIPTION

Cette implémentation suit les scripts rfc2822 aussi fidèlement que possible, et peut produire un résultat différent des implémentations basées sur l'ancien rfc822. Cependant, l'ancien résultat sera toujours accepté.

Ces objets stockent une ligne d'en-tête et facilitent les routines d'accès aux informations qui y sont cachées. Vous pouvez également jeter un œil aux méthodes supplémentaires d'un message :

my @from    = $message->from;
my $sender  = $message->sender;
my $subject = $message->subject;
my $msgid   = $message->messageId;
my @to      = $message->to;
my @cc      = $message->cc;
my @bcc     = $message->bcc;
my @dest    = $message->destinations;
my $other   = $message->get('Reply-To');

Étendu de "DESCRIPTION" dans Mail::Reporter.

SURCHARGÉ

overload: "" stringification
Génère le corps déployé de ce champ, ce qui peut être ce que vous attendez. Cela fait que l'objet semble être simplement une chaîne de caractères. La chaîne est générée par la méthode unfoldedBody().

» exemple :

print $msg->get('subject');  # par surcharge
print $msg->get('subject')->unfoldedBody; # idem
my $subject = $msg->get('subject') || 'votre courriel';
print "Re: $subject\n";
overload: 0+ numérisation
Si le champ est numérique, la valeur est retournée. Le résultat est généré par la méthode toInt(). Si la valeur n'est pas valide, 0 est retourné, pour simplifier les calculs.
overload: <=> comparaison numérique
Compare les contenus numériques du champ avec une autre valeur.

» exemple :

if($msg->get('Content-Length') > 10000) ...
if($msg->size > 10000) ... ; # idem, mais mieux
overload: bool booléen
Retourne toujours "true", pour permettre de faire if($field).
overload: cmp comparaison de chaînes
Compare le corps déployé d'un champ avec un autre champ ou une chaîne, en utilisant le built-in "cmp".

Les champs

$any->isStructured()
Certains champs sont décrits dans les RFC comme étant structurés : ils ont un format bien décrit. Ces champs ont des idées communes sur les commentaires et le reste, qu'ils ne partagent pas avec les champs non structurés, comme le champ "Subject".

» exemple :

my $field = Mail::Message::Field->new(From => 'me');
if($field->isStructured)
Mail::Message::Field->isStructured('From');
$obj->length()
Retourne la longueur totale de la ligne du champ en caractères, ce qui inclut le nom de la ligne, le corps et les caractères de pliage.
$obj->nrLines()
Retourne le nombre de lignes nécessaires pour afficher cette ligne d'en-tête.
$obj->print( [$fh] )
Imprime la ligne complète du champ dans le fichier de sortie spécifié. Une ligne peut résulter en plusieurs lignes imprimées en raison du pliage des lignes longues. Le $fh est utilisé par défaut comme le handle sélectionné.
$obj->size()
Retourne le nombre d'octets nécessaires pour afficher cette ligne d'en-tête, ce qui est identique à length().
$obj->string( [$wrap] )
Retourne le champ sous forme de chaîne. Par défaut, cela renvoie la même chose que folded(). Cependant, le paramètre optionnel $wrap provoquera un nouveau pliage, sans changer le pliage stocké dans le champ.
$obj->toDisclose()
Retourne si ce champ peut être révélé à d'autres utilisateurs, par exemple, lors de l'envoi du message à un autre utilisateur. Retourne une valeur "true" ou "false". Voir également Mail::Message::Head::Complete::printUndisclosed().

Accès au nom

$obj->Name()
Retourne le nom de ce champ dans sa casse d'origine. Voir également name().
$obj->name()
Retourne le nom de ce champ, avec tous les caractères en minuscules pour faciliter les comparaisons. Voir également Name().
$obj->wellformedName( [STRING] )
(Méthode de classe instanciée) Retourne le nom de ce champ correctement formaté et sous forme d'instance. Lorsqu'une "STRING" est utilisée, c'est celle-ci qui est formée.

» exemple :

print Mail::Message::Field->Name('content-type')
  # -->  Content-Type
my $field = $head->get('date');
print $field->Name;
  # -->  Date

Accès au corps

$obj->body()
Cette méthode n'est peut-être pas ce que vous souhaitez : foldedBody() et unfoldedBody() sont probablement ce que vous recherchez. Ceux-ci retourneront le contenu complet du champ, même s'il est structuré.

Retourne le corps du champ. Lorsque ce champ est structuré, ce qui se trouve après le premier point-virgule (";") sera supprimé. Dans tous les cas, la chaîne sera dépliée. Est-ce structuré ? Défini par isStructured().

$obj->folded()
Retourne la version pliée de toute la ligne d'en-tête. Lorsque l'en-tête est plus court que la longueur de pliage, une liste d'une ligne est retournée. Sinon, plusieurs lignes sont retournées, toutes sauf la première commençant par au moins un espace blanc. Voir également foldedBody() pour la même information sans le nom du champ.

Dans un contexte scalaire, les lignes sont livrées sous forme d'une seule chaîne, ce qui est un peu plus rapide car c'est ce qui est stocké en interne...

» exemple :

my @lines = $field->folded;
print $field->folded;
print scalar $field->folded; # plus rapide
$obj->foldedBody( [$body] )

Ce site n'est en aucun cas associé à Arch Linux ni affilié à ce projet. Le contenu est uniquement une traduction des pages de manuel d'Arch publiées sur man.archlinux.org.

Renvoie le corps comme un ensemble de lignes. En contexte scalaire, il s'agira d'une seule ligne contenant des sauts de ligne. Bien que je vous avertisse des sauts de ligne lorsque vous effectuerez des correspondances de motifs sur le résultat de cette méthode.

L'argument optionnel $body modifie le corps du champ. Le pliage de l'argument doit être correct.

$any->stripCFWS( [STRING] )
Supprime les commentaires et les espaces de pliage de la "STRING". Sans chaîne et uniquement en tant que méthode d'instance, le unfoldedBody() est supprimé et renvoyé.

AVERTISSEMENT : Cette opération n'est autorisée que pour les en-têtes structurés (définis par les divers RFC). Vous ne voudrez pas que les champs entre parenthèses qui se trouvent sur la ligne d'en-tête de l'objet, par exemple, soient supprimés.

$obj->unfoldedBody( [$body, [$wrap]] )
Renvoie le corps sous forme d'une seule ligne, où toutes les informations de pliage (si disponibles) sont supprimées. Cette ligne ne se termine pas non plus par un nouveau saut de ligne.

L'argument optionnel $body modifie le corps du champ. Les informations de pliage sont effectuées avant l'affectation. Le $wrap peut être spécifié pour forcer une taille de pliage.

exemple :

my $body = $field->unfoldedBody;
print "$field";   # via overloading

Accès au contenu

$obj->addresses()
Renvoie une liste d'objets Mail::Address, qui représentent les adresses électroniques trouvées sur cette ligne d'en-tête.

exemple :

my @addr = $message->head->get('to')->addresses;
my @addr = $message->to;
$obj->attribute( $name, [$value] )
Obtient la valeur d'un attribut, éventuellement après l'avoir défini sur une nouvelle valeur. Les attributs font partie de certaines lignes d'en-tête et sont cachés dans le champ de commentaire. Si l'attribut n'existe pas, "undef" est renvoyé. L'attribut est toujours codé.

exemple :

my $field = Mail::Message::Field->new(
 'Content-Type: text/plain; charset="us-ascii"');
print $field->attribute('charset');
  # --> us-ascii
print $field->attribute('bitmap') || 'no'
  # --> no
$field->atrribute(filename => '/tmp/xyz');
$field->print;
  # --> Content-Type: text/plain; charset="us-ascii";
  #       filename="/tmp/xyz"
  # Automatiquement plié, et aucun pliage n'est créé.
$obj->attributes()
Renvoie une liste de paires clé-valeur, où les valeurs n'ont pas encore été décodées. Les clés peuvent apparaître plus d'une fois.

exemple :

my @pairs = $head->get('Content-Disposition')->attributes;
$obj->comment( [STRING] )
Renvoie le commentaire déplié (partie après un point-virgule) d'une ligne d'en-tête structurée. Optionnellement après l'avoir défini sur une nouvelle "STRING". Lorsque "undef" est spécifié comme "STRING", le commentaire est supprimé. Si la ligne est structurée, elle est définie par isStructured().

La partie commentaire d'une ligne d'en-tête contient souvent des "attributs". Il est parfois préférable d'utiliser attribute() pour les manipuler.

$obj->study()
Étudie en détail la ligne d'en-tête : active l'analyse complète et la compréhension détaillée du contenu des champs. Les objets Mail::Message::Field::Fast et Mail::Message::Field::Fast seront convertis en tout objet Mail::Message::Field::Full.

exemple :

my $subject = $msg->head->get('subject')->study;
my $subject = $msg->head->study('subject');  # identique
my $subject = $msg->study('subject');        # identique
$any->toDate( [$time] )
Convertit une heure serveur dans un format compatible RFC2822. Ceci diffère de la sortie par défaut de "localtime" en contexte scalaire. Sans argument, "localtime" est utilisé pour obtenir l'heure actuelle. $time peut être spécifié comme un nombre (comme le résultat de time()) ou comme une liste (comme produit par localtime() en contexte liste).

Assurez-vous que votre fuseau horaire est correctement configuré, surtout lorsque ce script est exécuté automatiquement.

exemple :

my $now = time;
Mail::Message::Field->toDate($now);
Mail::Message::Field->toDate(time);
Mail::Message::Field->toDate(localtime);
Mail::Message::Field->toDate;      # identique
# renvoie quelque chose comme :
#     Wed, 28 Aug 2002 10:40:25 +0200
$obj->toInt()
Renvoie la valeur associée à ce champ sous forme d'entier. Une vérification est effectuée pour s'assurer qu'elle est correcte.

Méthodes supplémentaires

$any->dateToTimestamp(STRING)
Convertit une "STRING" représentant une chaîne de temps compatible RFC en un horodatage tel que produit par la fonction "time".

Internes

$obj->consume( $line | <$name,$body|$objects> )
Accède à une ligne d'en-tête complète $line, ou une paire avec le nom du champ et son corps. Dans ce dernier cas, le corps peut être spécifié comme un tableau de $objects qui sont sérialisés. Renvoie une paire bien formée de deux chaînes : le nom du champ et un corps déplié.

Cette méthode est appelée par new() et normalement pas par un programme d'application. Les détails sur la conversion de $objects en contenu de champ sont expliqués dans "Exemple de données de champ".

$obj->defaultWrapLength( [$length] )
Chaque champ de chaque en-tête de chaque message aura cette longueur de pliage par défaut. Ceci est conservé dans une variable globale. Sans spécifier $length, la valeur actuelle est renvoyée. La valeur par défaut est 78.
$any->fold( $name, $body, [$maxchars] )
Plie l'en-tête nommé $name en plusieurs lignes. Le pliage est effectué en insérant des sauts de ligne avant les espaces blancs dans le corps $body, en veillant à ce qu'aucune ligne ne dépasse $maxchars et que chaque ligne soit aussi longue que possible.

Les exigences RFC en matière de pliage aux points stylisés sont ignorées car elles rendraient le pliage trop lent.

$obj->setWrapLength( [$length] )
Forcera le pliage de cet en-tête à $length caractères spécifiés. Le pliage est effectué avec fold() et les résultats sont stockés dans l'objet de champ.

exemple : nouveau pliage de l'en-tête

$field->setWrapLength(99);
$obj->stringifyData(STRING|ARRAY|$objects)
Cette méthode implémente la traduction des objets fournis par l'utilisateur en champs en ASCII. Le processus est expliqué dans "Exemple de données de champ".
$obj->unfold(STRING)
Action inverse de fold() : toutes les lignes formant le corps d'un champ sont jointes en une seule ligne en supprimant tous les terminateurs de ligne (même le dernier). Les espaces blancs initiaux sur la première ligne sont également supprimés.

DÉTAILS

Syntaxe des champs

Les champs sont stockés dans l'en-tête d'un message, représentés par des objets Mail::Message::Head. Un champ est une combinaison d'un nom, d'un corps et d'attributs. En particulier, le terme corps prête à confusion : parfois les attributs sont considérés comme faisant partie du corps.

Le nom du champ est suivi d'un tiret (:), non précédé d'espaces blancs, mais suivi d'un espace blanc. Chaque attribut est précédé d'un séparateur point-virgule (;). Les noms de champs ne sont pas sensibles à la casse et ne peuvent pas contenir d'espaces blancs.

exemple : de champs corrects

Champs corrects :

Field: hi!
Content-Type: text/html; charset=latin1

Champs incorrects, mais acceptés :

Field : wrong, blank before colon
Field:                 # wrong, empty
Field:not nice, blank preferred after colon
One Two: wrong, blank in name

Champs pliés

Les champs longs peuvent être pliés pour s'étendre sur plusieurs lignes. La limite réelle de ligne dans les messages n'est que de 998 caractères, mais ces longues lignes sont difficiles à lire sans le support d'un programme. C'est pourquoi les exigences RFC concernant le pliage aux points stylisés sont ignorées car elles rendraient le pliage trop lent.

(qui définit la syntaxe des messages) spécifie explicitement que les lignes de champ peuvent être reformatées en plusieurs lignes trieuses sans changement de sens, en ajoutant des caractères de nouvelle ligne à n'importe quel champ avant tout espace ou tabulation.

En général, les lignes sont reformatées pour créer des lignes dont la longueur maximale est de 78 caractères. Certaines applications s'efforcent de plier à des endroits agréables, comme avant les attributs. En particulier, le champ "Received" est souvent plié manuellement dans une mise en page agréable. Dans la plupart des cas, cependant, il est préférable de produire des lignes aussi longues que possible, mais limitées à 78.

ATTENTION : tous les champs peuvent être soumis à un pliage, et vous souhaitez généralement la valeur dépliée.

» Exemple : de pliage de champ

Subject: this is a short line, and not folded
Subject: this subject field is much longer, and therefore
 folded into multiple
 lines, although one more than needed.

Champs structurés

Le rfc2822 décrit explicitement un grand nombre de champs d'en-tête. Ces champs ont une signification définie. Pour certains des champs, comme le champ "Subject", la signification est directement le contenu lui-même. Ce sont les Champs non structurés.

D'autres champs ont une syntaxe interne bien définie car leur contenu est nécessaire aux applications de courrier électronique. Par exemple, le champ "To" contient des adresses qui doivent être comprises par toutes les applications de la même manière. Ce sont les Champs structurés, voir isStructured().

Commentaires dans les champs

Les champs structurés peuvent contenir des commentaires, qui sont des morceaux de texte entourés de parenthèses. Ces commentaires peuvent être placés presque n'importe où sur la ligne et doivent être ignorés par l'application. Toutes les applications ne sont pas capables de gérer correctement les commentaires dans toutes les circonstances.

» Exemple : de commentaires de champ

To: mailbox (Mail::Box mailinglist) <mailbox@overmeer.net>
Date: Thu, 13 Sep 2001 09:40:48 +0200 (CEST)
Subject: goodbye (was: hi!)

Sur la première ligne, le texte "Mail::Box mailinglist" est utilisé comme commentaire. Attention, le rfc2822 stipule explicitement que les commentaires dans les spécifications d'adresses e-mail ne doivent pas être considérés comme contenant des informations utilisables.

Sur la deuxième ligne, le fuseau horaire est spécifié comme commentaire. Le format du champ "Date" n'a aucun moyen d'indiquer le fuseau horaire de l'expéditeur, mais contient uniquement la différence de fuseau horaire par rapport à l'UTC, cependant on pourrait décider de l'ajouter en commentaire. L'application doit ignorer ces données car le champ "Date" est structuré.

Le dernier champ est non structuré. Le texte entre parenthèses fait partie intégrante de la ligne d'objet.

Obtenir un champ

Autant de programmes qu'il existe pour traiter les e-mails, autant de variations sur la manière d'accéder aux informations d'en-tête sont demandées. Faites attention à la manière dont vous accédez aux données : lisez les variations décrites ici et décidez quelle solution convient le mieux à vos besoins.

Utilisation de la méthode get() de champ

L'interface get() est copiée d'autres modules Perl qui peuvent gérer les messages électroniques. De nombreuses applications qui remplacent simplement les objets Mail::Internet par des objets Mail::Message fonctionneront sans modification.

Il existe plus d'une méthode get. Les résultats exacts dépendent de la méthode get que vous utilisez. Lorsque Mail::Message::get() est appelée, vous obtiendrez le contenu déplié, dépouillé des commentaires, dépouillé des attributs du champ sous forme de chaîne. Les encodages de jeux de caractères seront toujours présents dans la chaîne. Si le même nom de champ apparaît plus d'une fois dans l'en-tête, seule la dernière valeur est renvoyée.

Lorsque Mail::Message::Head::get() est appelée dans un contexte scalaire, le dernier champ portant le nom spécifié est renvoyé sous forme d'objet de champ. Cet objet se transforme en contenu déplié du champ, y compris les attributs et les commentaires. Dans un contexte de liste, toutes les occurrences du champ dans l'en-tête sont renvoyées sous forme d'objets.

ATTENTION : certaines lignes semblent uniques, mais ne le sont pas selon le rfc officiel. Par exemple, les champs "To" peuvent apparaître plus d'une fois. Si votre programme appelle get('to') dans un contexte scalaire, certaines informations sont perdues.

» Exemple : d'utilisation de get()

print $msg->get('subject') || 'no subject';
print $msg->head->get('subject') || 'no subject';
my @to = $msg->head->get('to');

Utilisation de la méthode study() de champ

Comme le nom "study" l'implique déjà, cette manière d'accéder aux champs est beaucoup plus approfondie mais aussi plus lente. L'"étude" d'un champ est comme un "get", mais fournit un accès facile au contenu du champ et gère correctement le décodage des jeux de caractères.

La méthode Mail::Message::study() ne renverra que le dernier champ portant ce nom sous forme d'objet. Mail::Message::Head::study() et Mail::Message::Field::study() renvoient tous les champs lorsqu'ils sont utilisés dans un contexte de liste.

» Exemple : d'utilisation de study()

print $msg->study('subject') || 'no subject';
my @rec  = $msg->head->study('Received');
my $from = $msg->head->get('From')->study;
my $from = $msg->head->study('From');  # same
my @addr = $from->addresses;

Utilisation des groupes de renvoi

Certains champs appartiennent ensemble dans un groupe de champs. Par exemple, un ensemble de lignes est utilisé pour définir une étape dans le processus de transport du courrier. Chaque étape ajoute une ligne "Received", et éventuellement des lignes "Resent-*" et "Return-Path". Ces groupes de lignes doivent rester ensemble et dans l'ordre lors du traitement de l'en-tête du message.

L'objet "Mail::Message::Head::ResentGroup" simplifie l'accès à ces champs connexes. Ces groupes de renvoi peuvent être supprimés dans leur ensemble, ou construits correctement.

» Exemple : d'utilisation des groupes de renvoi

my $rgs = $msg->head->resentGroups;
$rgs[0]->delete if @rgs;
$msg->head->removeResentGroups;

Les données du champ

Il existe de nombreuses façons d'obtenir les informations de champ sous forme d'objet, et il existe également de nombreuses façons de traiter ces données au sein du champ.

Accès au champ

  • string()

    Renvoie le texte du corps exactement tel qu'il sera imprimé sur le fichier lorsque print() est appelée, donc le nom, le corps principal et les attributs.

  • foldedBody()

    Renvoie le texte du corps, comme string(), mais sans le nom du champ.

  • unfoldedBody()

    Renvoie le texte du corps, comme foldedBody(), mais avec tous les sauts de ligne supprimés. C'est la manière normale d'obtenir le contenu des champs non structurés. Les encodages de jeux de caractères seront toujours en place. Les champs sont convertis en leur représentation dépliée.

  • stripCFWS()

    Renvoie le texte des champs structurés, où les sauts de ligne et les commentaires sont supprimés de la chaîne. C'est un bon point de départ pour analyser le champ, par exemple pour y trouver des adresses e-mail.

  • Mail::Message::Field::Full::decodedBody()

    Les champs étudiés peuvent produire le texte déplié décodé en chaînes utf8. C'est un processus coûteux, mais la seule façon correcte d'obtenir les données du champ. Plus utile pour les personnes qui ne vivent pas dans l'espace ASCII.

  • Champs étudiés

    Les champs étudiés disposent de méthodes puissantes pour fournir des moyens d'accéder et de produire le contenu des champs (structurés) exactement comme le prescrivent les rfc concernés.

Utilisation d'un accès simplifié aux champs

Certains champs sont accédés si souvent qu'il existe des méthodes de support pour fournir un accès simplifié. Toutes ces méthodes sont appelées directement sur un message.

» Exemple : d'accès simplifié aux champs

print $message->subject;
print $message->get('subject') || '';  # same
my @from = $message->from; # returns addresses
$message->reply->send if $message->sender;

La méthode "sender" renverra l'adresse spécifiée dans le champ "Sender", ou la première nommée dans le champ "From". Elle renverra "undef" si aucune adresse n'est connue.

Spécification des données de champ

Les données de champ peuvent être n'importe quoi, fortement dépendant du type de champ en question. Si vous décidez de construire les champs très soigneusement via une extension Mail::Message::Field::Full (comme via des objets Mail::Message::Field::Addresses), vous aurez une protection intégrée. Cependant, vous pouvez créer brutalement n'importe quel objet Mail::Message::Field basé sur des données.

Lorsque vous créez un champ, vous pouvez spécifier une chaîne, un objet ou un tableau de chaînes et d'objets. Actuellement, les objets ne sont utilisés que pour aider à la construction des adresses e-mail, cependant vous pouvez en ajouter des vôtres.

Les règles suivantes (implémentées dans stringifyData()) sont respectées si l'argument est :

  • une chaîne

    La chaîne doit suivre les règles (compliquées) du rfc2822, et est utilisée comme contenu de champ comme spécifié. Si la chaîne n'est pas terminée par un saut de ligne ("\n"), elle sera pliée selon les règles standard.

  • un objet Mail::Address

    L'objet Perl le plus utilisé pour analyser et produire des lignes d'adresses. Cet objet ne comprend pas les encodages de jeux de caractères dans les phrases.

  • un objet Mail::Identity

    Dans le cadre de la distribution User::Identity, cet objet comprend pleinement la signification d'une adresse e-mail, liée à une personne. Toutes les fonctionnalités définies par le rfc2822 sont implémentées.

  • un objet User::Identity

    Une personne est spécifiée, qui peut avoir plus d'un Mail::Identity défini. Certaines méthodes, comme Mail::Message::reply() et Mail::Message::forward() essaient de sélectionner la bonne adresse e-mail intelligemment (voir leurs descriptions de méthodes), mais dans d'autres cas, la première adresse e-mail trouvée est utilisée.

  • un objet User::Identity::Collection::Emails

    Tous les objets Mail::Identity de la collection seront inclus dans le champ en tant que groupe portant le nom de la collection.

  • tout autre objet

    Pour tous les autres objets, la surcharge de stringification est utilisée pour produire le contenu du champ.

  • un TABLEAU

    Vous pouvez également spécifier un tableau avec un mélange de tout ce qui précède. Th

e éléments seront joints sous forme de liste séparée par des virgules. Si vous ne voulez pas de virgules entre les éléments, vous devrez traiter le tableau vous-même.

» Exemple : spécification de données de champ simples

my $f = Mail::Message::Field->new(Subject => 'hi!');

» Exemple : spécification d'adresses e-mail pour un champ

use Mail::Address;
my $fish = Mail::Address->new('Mail::Box', 'fish@tux.aq');
print $fish->format;   # ==> Mail::Box <fish@tux.aq>
my $exa  = Mail::Address->new(undef, 'me@example.com');
print $exa->format;    # ==> me@example.com
my $b = $msg->build(To => "you@example.com");
my $b = $msg->build(To => $fish);
my $b = $msg->build(To => [ $fish, $exa ]);
my @all = ($fish, "you@example.com", $exa);
my $b = $msg->build(To => \@all);
my $b = $msg->build(To => [ "xyz", @all ]);

» Exemple : spécification d'identités pour un champ

use User::Identity;

  name      => 'patrik',
  full_name => "Patrik Fältström",  # d'après rfc
  charset   => "ISO-8859-1",
);
$patrik->add(email => "him@home.net");
my $b = $msg->build(To => $patrik);
$b->get('To')->print;

Implémentation de la classe Field

Pour des raisons de performance uniquement, il existe trois types de champs : le rapide, le flexible et le comprend-tout :

  • Mail::Message::Field::Fast

    "Fast" Les objets ne sont pas dérivés de "Mail::Reporter". L'idée est que les champs sont créés très souvent, et sont des objets très petits en même temps, que la mise en place d'un journal pour chacun des objets est relativement coûteuse et pas vraiment utile. L'implémentation de champ rapide utilise un tableau pour stocker les données : ce sera plus rapide que d'utiliser une table de hachage. Les champs rapides ne sont pas facilement héritables, car la création et l'initialisation de l'objet sont fusionnées en une seule méthode.

  • Mail::Message::Field::Flex

    L'implémentation flexible utilise une table de hachage pour stocker les données. Les méthodes new() et "init" sont séparées, donc cet objet est extensible.

  • Mail::Message::Field::Full

    Avec une implémentation complète de tous les RFC applicables (environ 5), la meilleure compréhension des champs est atteinte. Cependant, cela entraîne une pénalité significative en termes de mémoire et de performance. Ces objets sont créés à partir de champs d'en-tête rapides ou flexibles lorsque study() est appelé.

DIAGNOSTICS

Attention : le contenu du champ n'est pas numérique : $content
La valeur numérique d'un champ est demandée (par exemple, les champs "Lines" ou "Content-Length" devraient être numériques), cependant les données contiennent des caractères étranges. Convertir avec toInt()
Erreur : nom de champ trop long (max $length), dans '$name'
Il n'est pas spécifié dans les RFC quelle est la longueur maximale d'un nom de champ, mais au moins il devrait être quelques caractères plus court que le retour à la ligne. Convertir avec fold()
Attention : caractère illégal dans le nom de champ $name
Un nouveau champ est créé qui contient des caractères non autorisés par les RFC. L'utilisation de ce champ dans des messages peut casser d'autres clients de messagerie ou agents de transfert, et donc mutiler ou éteindre votre message. Convertir avec consume()
Erreur : le paquet $package n'implémente pas $method.
Erreur fatale : le paquet spécifique (ou l'une de ses superclasses) n'implémente pas cette méthode là où elle devrait l'être. Ce message signifie que d'autres classes liées implémentent cette méthode, mais pas la classe en question. Vous devriez probablement enquêter là-dessus et probablement informer l'auteur du paquet. Convertir avec notImplemented()
