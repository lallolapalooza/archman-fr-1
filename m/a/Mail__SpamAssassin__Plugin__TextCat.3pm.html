NOM

Mail::SpamAssassin::Plugin::TextCat - Devineur de langue TextCat

SYNOPSIS

loadplugin     Mail::SpamAssassin::Plugin::TextCat

DESCRIPTION

Ce plugin essaiera de deviner la langue utilisée dans le corps du message.

Vous pouvez utiliser la directive "ok_languages" pour définir quelles langues sont considérées comme acceptables pour les courriels entrants et si la langue devinée n'est pas acceptable, "UNWANTED_LANGUAGE_BODY" est déclenchée. Alternativement, vous pouvez utiliser directement l'en-tête de métadonnées X-Languages dans les règles.

Il ajoutera toujours les résultats à une paire nom-valeur "X-Languages" dans la structure de données des métadonnées du message. Cela peut être utile comme jetons Bayes et peut également être utilisé dans les règles pour le score. Les résultats peuvent également être ajoutés aux messages marqués à l'aide de "add_header", avec la balise _LANGUAGES_. Voir Mail::SpamAssassin::Conf pour plus de détails.

Note : la langue ne peut pas toujours être reconnue avec une confiance suffisante. Dans ce cas, aucune action n'est entreprise.

Vous pouvez utiliser la balise _TEXTCATRESULTS_ pour afficher le score interne des n-grammes, cela peut aider à affiner les réglages.

Exemples d'utilisation directe de l'en-tête X-Languages dans les règles :

header OK_LANGS X-Languages =~ /\ben\b/
score OK_LANGS -1
header BAD_LANGS X-Languages =~ /\b(?:ja|zh)\b/
score BAD_LANGS 1

RÉGLAGES UTILISATEUR

ok_languages xx [ yy zz ... ] (par défaut : tout)
Cette option est utilisée pour spécifier quelles langues sont considérées comme acceptables pour les courriels entrants. SpamAssassin essaiera de détecter la langue utilisée dans le corps du message.

Notez que la langue ne peut pas toujours être reconnue avec une confiance suffisante. Dans ce cas, aucune action n'est entreprise.

La règle "UNWANTED_LANGUAGE_BODY" est déclenchée si aucune des langues détectées ne figure dans la liste "ok". Notez que c'est le seul effet de la liste "ok". Elle n'agit pas comme une liste de bienvenue contre toute autre forme d'analyse de spam.

Dans votre configuration, vous devez utiliser le spécificateur de langue à deux ou trois lettres en minuscules, et non le nom anglais de la langue. Vous pouvez également spécifier "all" si une langue désirée n'est pas listée, ou si vous souhaitez autoriser n'importe quelle langue. Le réglage par défaut est "all".

Exemples :

ok_languages all         (autoriser toutes les langues)
ok_languages en          (autoriser uniquement l'anglais)
ok_languages en ja zh    (autoriser l'anglais, le japonais et le chinois)

Note : s'il y a plusieurs lignes ok_languages, seule la dernière est utilisée.

inactive_languages xx [ yy zz ... ] (par défaut : voir ci-dessous)
Cette option est utilisée pour spécifier quelles langues ne seront pas prises en compte lors de la tentative de deviner la langue. Pour des raisons de performance, les langues supportées qui ont moins d'environ 5 millions de locuteurs sont désactivées par défaut. Notez que le fait de lister une langue dans "ok_languages" l'active automatiquement pour cet utilisateur.

Mail::SpamAssassin::Plugin::TextCat(3pm)

Mail::SpamAssassin::Plugin::TextCat 3pm

TextCat language detection plugin for SpamAssassin
2025-07-14

NAME

Mail::SpamAssassin::Plugin::TextCat - TextCat language detection plugin for SpamAssassin

SYNOPSIS

  use Mail::SpamAssassin::Plugin::TextCat;

  # In local or dist conf files:
  #
  # loadplugin Mail::SpamAssassin::Plugin::TextCat
  #
  # # and optionally override defaults:
  #
  # textcat_max_languages 3
  # textcat_acceptable_score 1.02
  # textcat_optimal_ngrams 0
  # textcat_max_ngrams 400

DESCRIPTION

This plugin uses the TextCat library to detect the language of a message. The classification is based on ngrams (sequences of characters) and their frequency. TextCat uses a database of ngrams for various languages. It compares the ngrams found in a message against this database and calculates a score for each language.

The detected languages, along with their scores, are added to the SpamAssassin message headers, e.g.:

        X-Spam-Detected-Languages: en (0.85), fr (0.15)

The plugin can be configured to set scores for specific languages, which can then be used in SpamAssassin rules. For example, to penalize messages detected as Japanese:

        # In local or dist conf files:
        #
        # add_header all X-Spam-Detected-Languages _DETECTEDLANGUAGES_
        #
        # score _DETECTEDLANGUAGES_ =~ /ja/i 2.0

The detection is not perfect, especially for short messages or messages containing multiple languages. The confidence of the detection can be influenced by the settings described below.

USER SETTINGS

languages
A comma-separated list of language codes (e.g. en, fr, de) to use. If not specified, TextCat uses its default list of languages.
textcat_max_languages N (default: 3)
The maximum number of languages any one message can simultaneously match before its classification is considered unknown. You can try reducing this to 2 or possibly even 1 for more confident results, as it's unusual for a message to contain multiple languages.

Read description for textcat_acceptable_score also, as these settings are closely related. Scoring affects how many languages might be matched and here we set the "false positive limit" where we think the engine can't decide what languages message really contain.

textcat_optimal_ngrams N (default: 0)
If the number of ngrams is lower than this number then they will be removed. This can be used to speed up the program for longer inputs. For shorter inputs, this should be set to 0.
textcat_max_ngrams N (default: 400)
The maximum number of ngrams that should be compared with each of the languages models (note that each of those models is used completely).
textcat_acceptable_score N (default: 1.02)
Include any language that scores at least "textcat_acceptable_score" in the returned list of languages.

This setting is basically a percentile range. Any language having internal ngram-score within N-percent of the best score is included into results. Larger values than 1.05 are not recommended as it can generate many false matches. A setting of 1.00 would mean a single best scoring language is always forcibly selected, but this is not recommended as then textcat_max_languages can't do its job classifying language as uncertain.

Read the description for textcat_max_languages, as these are settings are closely related.

You can use _TEXTCATRESULTS_ tag to view the internal ngram-scoring, it might help fine-tuning settings.
