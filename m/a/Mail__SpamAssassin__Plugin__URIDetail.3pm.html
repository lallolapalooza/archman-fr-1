NOM

URIDetail - tester les URI en utilisant des informations détaillées sur les URI

SYNTAXE

Ce plugin crée un nouveau type de test de règle, connu sous le nom de "uri_detail". Ces règles s'appliquent à toutes les URI trouvées dans le message.

loadplugin    Mail::SpamAssassin::Plugin::URIDetail

DÉFINITIONS DE RÈGLES ET PARAMÈTRES PRIVILÉGIÉS

Le format pour définir une règle est le suivant :

uri_detail SYMBOLIC_TEST_NAME key1 =~ /value1/i  key2 !~ /value2/ ...

Les clés supportées sont :

"raw" est l'URI brute avant tout nettoyage (par exemple, "http://spamassassin.apache%2Eorg/").

"type" sont les balises qui référencent le raw_uri. parsed est un type simulé qui spécifie que le raw_uri a été analysé à partir du texte rendu.

"cleaned" est une liste incluant l'URI brute et diverses versions nettoyées de l'URI brute (http://spamassassin.apache%2Eorg/, https://spamassassin.apache.org/).

"text" est le ou les textes d'ancrage (texte entre <a> et </a>) qui pointaient vers l'URI brute.

"domain" est le ou les domaines trouvés dans les URI nettoyées, tronqués à la limite du registraire par Mail::SpamAssassin::Util::RegistrarBoundaries(3).

"host" est le ou les hôtes complets dans les URI nettoyées. (Supporté depuis SA 3.4.5)

Exemple de règle pour trouver une URI où l'URI brute correspond à "%2Ebar", le domaine "bar.com" est trouvé, et le type est "a" (une balise d'ancrage).

uri_detail TEST1 raw =~ /%2Ebar/  domain =~ /^bar\.com$/  type =~ /^a$/

Exemple de règle pour rechercher des liens "https" suspects :

uri_detail FAKE_HTTPS text =~ /\bhttps:/  cleaned !~ /\bhttps:/

Les expressions régulières doivent être délimitées par des barres obliques.
