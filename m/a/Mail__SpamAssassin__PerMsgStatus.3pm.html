NOM

Mail::SpamAssassin::PerMsgStatus - statut par message (spam ou pas spam)

SYNOPIS

my $spamtest = Mail::SpamAssassin->new({
  'rules_filename'      => '/etc/spamassassin.rules',
  'userprefs_filename'  => $ENV{HOME}.'/.spamassassin/user_prefs'
});
my $mail = $spamtest->parse();
my $status = $spamtest->check ($mail);
my $rewritten_mail;
if ($status->is_spam()) {
  $rewritten_mail = $status->rewrite_mail ();
}
...

DESCRIPTION

La méthode check() de Mail::SpamAssassin retourne un objet de cette classe. Cet objet encapsule tout l'état par message.

MÉTHODES

$status->check ()
Exécute les règles SpamAssassin sur le message pointé par l'objet.
$status->learn()
Après qu'un message électronique ait été vérifié, cette méthode peut être appelée. Si le score est en dehors d'une certaine plage autour du seuil, c'est-à-dire si le message est jugé plus ou moins définitivement spam ou définitivement non-spam, il sera transmis aux systèmes d'apprentissage de SpamAssassin (actuellement le classificateur bayésien naïf), afin que les messages similaires futurs soient interceptés.
$score = $status->get_autolearn_points()
Retourne le score du message tel que calculé pour l'auto-apprentissage. Certains tests sont ignorés : 
- les règles avec tflags défini à 'learn' (les règles bayésiennes)
- les règles avec tflags défini à 'userconf' (règles d'accueil utilisateur/liste de blocage, etc.)
- les règles avec tflags défini à 'noautolearn'

Notez également que l'auto-apprentissage se produit en utilisant les scores de l'ensemble de scores 0 ou 1, en fonction de l'ensemble de scores utilisé lors de la vérification du message. Il est probable que les scores de vérification du message et d'auto-apprentissage seront différents.

$score = $status->get_head_only_points()
Retourne le score du message tel que calculé pour l'auto-apprentissage, en ignorant toutes les règles sauf celles basées sur l'en-tête.
$score = $status->get_learned_points()
Retourne le score du message tel que calculé pour l'auto-apprentissage, en ignorant toutes les règles sauf celles basées sur l'apprentissage.
$score = $status->get_body_only_points()
Retourne le score du message tel que calculé pour l'auto-apprentissage, en ignorant toutes les règles sauf celles basées sur le corps.
$score = $status->get_autolearn_force_status()
Retourne si le score d'un message incluait des règles marquées comme autolearn_force.
$rule_names = $status->get_autolearn_force_names()
Retourne une liste de noms de règles séparés par des virgules si le score d'un message incluait des règles marquées comme autolearn_force.
$isspam = $status->is_spam ()
Après qu'un message électronique ait été vérifié, cette méthode peut être appelée. Elle retournera 1 pour les messages considérés comme potentiellement spams, 0 s'ils ne semblent pas être des spams.
$list = $status->get_names_of_tests_hit ()
Après qu'un message électronique ait été vérifié, cette méthode peut être appelée. Elle retournera une chaîne de caractères séparée par des virgules, listant tous les noms de tests symboliques des tests qui ont été déclenchés par le message.
$list = $status->get_names_of_tests_hit_with_scores_hash ()
Après qu'un message électronique ait été vérifié, cette méthode peut être appelée. Elle retournera un pointeur vers une table de hachage pour les paires règle & score de tous les noms de tests symboliques et les scores individuels des tests qui ont été déclenchés par le message.
$list = $status->get_names_of_tests_hit_with_scores ()
Après qu'un message électronique ait été vérifié, cette méthode peut être appelée. Elle retournera une chaîne de caractères séparée par des virgules de paires règle=score pour tous les noms de tests symboliques et les scores individuels des tests qui ont été déclenchés par le message.
$list = $status->get_names_of_subtests_hit ()
Après qu'un message électronique ait été vérifié, cette méthode peut être appelée. Elle retournera une chaîne de caractères séparée par des virgules, listant tous les noms de tests symboliques des sous-tests de méta-règles qui ont été déclenchés par le message. Les sous-tests sont les règles normalement cachées, qui ont un score de 0 et dont les noms commencent par deux underscores, utilisés dans les méta-règles.

Si un paramètre de collapsed ou dbg est passé, la sortie sera un tableau condensé de sous-tests avec des entrées multiples réduites à une seule entrée.

Si le paramètre dbg est passé, la sortie sera une chaîne condensée de sous-tests avec des entrées multiples réduites à une seule entrée avec le nombre de hits entre parenthèses. Certaines informations sont également ajoutées à la fin concernant les succès multiples.

$num = $status->get_score ()
Après qu'un message électronique ait été vérifié, cette méthode peut être appelée. Elle retournera le score du message.
$num = $status->get_required_score ()
Après qu'un message électronique ait été vérifié, cette méthode peut être appelée. Elle retournera le score requis pour qu'un message soit considéré comme spam.
$num = $status->get_autolearn_status ()
Après qu'un message électronique ait été vérifié, cette méthode peut être appelée. Elle retournera l'une des chaînes suivantes en fonction de si le message a été auto-appris ou non : "ham", "no", "spam", "disabled", "failed", "unavailable".

Elle retourne également si elle est marquée avec auto_learn_force, elle inclura également le statut et les règles atteintes. Par exemple : "autolearn_force=yes (AUTOLEARNTEST_BODY)"

$report = $status->get_report ()
Délivre un "rapport de spam" sur le message électronique vérifié. Celui-ci contient des détails sur le nombre de règles de détection de spam qu'il a déclenchées.

Le rapport est retourné sous forme de chaîne multi-lignes, avec les lignes séparées par des caractères "\n".

$preview = $status->get_content_preview ()
Donne un "aperçu" du contenu.

Ceci est retourné sous forme de chaîne multi-lignes, avec les lignes séparées par des caractères "\n", contenant un échantillon texte brut, sûr et entièrement décodé des premières lignes du corps du message.

$msg = $status->get_message()
Retourne l'objet représentant le message en cours d'analyse.
$status->rewrite_mail ()
Réécrit le message électronique. Cela ajoutera au minimum des en-têtes, et au maximum encapsulera le texte du message en MIME, pour refléter son statut de spam ou non-spam. La fonction retournera un scalaire du message réécrit.

Les modifications réelles dépendent de la configuration (voir "Mail::SpamAssassin::Conf" pour plus d'informations).

Les modifications possibles sont les suivantes :

Modification des lignes To:, From: et Subject: pour les spams
Selon la configuration, les lignes To: et From: peuvent avoir un commentaire RFC 2822 défini par l'utilisateur ajouté pour les spams. La ligne subject peut avoir une chaîne définie par l'utilisateur ajoutée en préfixe pour les spams.
En-têtes X-Spam-* pour tous les messages
Selon la configuration, zéro ou plusieurs en-têtes commençant par "X-Spam-" seront ajoutés aux messages en fonction de s'il s'agit de spam ou de ham.
Message spam avec report_safe
Si report_safe est défini à vrai (1), alors les messages spams sont encapsulés dans leur propre pièce jointe MIME message/rfc822 sans aucune modification.

Si report_safe est défini à faux (0), alors le message n'aura que les en-têtes ci-dessus ajoutés/modifiés.

$status->action_depends_on_tags($tags, $code, @args)
Met en file d'attente la référence de sous-routine fournie $code, pour qu'elle devienne exécutable lorsque toutes les balises spécifiées sont disponibles. Les $tags peuvent être un scalaire simple - un nom de balise, ou une référence de liste de noms de balises. La sous-routine &$code lorsqu'elle est appelée recevra un objet "permessagestatus" comme premier argument, suivi de la liste optionnelle fournie @args .
$status->set_tag($tagname, $value)
Définit une balise de modèle, telle qu'utilisée dans "add_header", les modèles de rapport, etc. Cette API est destinée à être utilisée par les plugins. Les noms de balises seront convertis en représentation tout en majuscules en interne. Les noms de balises doivent uniquement contenir des caractères [A-Z0-9_] et ne doivent pas contenir de underscores consécutifs. De plus, le nom ne doit pas commencer ou se terminer par un underscore, car c'est le format de balisage de modèle.

$value
$value peut être un scalaire simple (chaîne ou nombre), ou une référence à un tableau, auquel cas la méthode publique get_tag joindra les éléments du tableau en utilisant un espace comme séparateur, retournant une chaîne unique pour des raisons de compatibilité ascendante.

$value peut également être une référence à une sous-routine, qui sera évaluée chaque fois que le modèle est développé. Le premier argument passé par get_tag à une sous-routine appelée sera un objet PerMsgStatus (l'objet de ce module), suivi des arguments optionnels fournis par un appelant à get_tag.

Notez que Perl prend en charge les fermetures, ce qui signifie que les variables définies dans la portée de l'appelant peuvent être accessibles à l'intérieur de cette "sub". Par exemple :

my $text = "hello world!";
$status->set_tag("FOO", sub {
          my $pms = shift;
          return $text;
        });

Voir les sections "Mail::SpamAssassin::Conf"'s "TEMPLATE TAGS" et "CAPTURING TAGS USING REGEX NAMED CAPTURE GROUPS" pour plus de détails sur la manière dont les balises de modèle sont utilisées.

$string = $status->get_tag($tagname)
Obtient la valeur actuelle d'une balise de modèle, telle qu'utilisée dans "add_header", les modèles de rapport, etc. Cette API est destinée à être utilisée par les plugins. Les noms de balise seront convertis en une représentation entièrement en majuscules en interne.

Voir les sections "Mail::SpamAssassin::Conf"'s "TEMPLATE TAGS" et "CAPTURING TAGS USING REGEX NAMED CAPTURE GROUPS" pour plus de détails sur la manière dont les balises de modèle sont utilisées.

"undef" sera retourné si une balise portant ce nom n'a pas été définie.

$string = $status->get_tag_raw($tagname, @args)
Similaire à "get_tag", mais conserve le nom d'une balise tel quel (ne le met pas en majuscules) et ne convertit pas les valeurs de balise arrayref en une seule chaîne.
$status->set_spamd_result_item($subref)
Définit une entrée pour la ligne de journal des résultats de spamd. $subref doit être une référence de code pour une sous-routine qui retournera une chaîne au format 'name=VALUE', similaire aux autres entrées de la ligne de résultats de spamd : 
Jul 17 14:10:47 radish spamd[16670]: spamd: result: Y 22 - ALL_NATURAL,
DATE_IN_FUTURE_03_06,DIET_1,DRUGS_ERECTILE,DRUGS_PAIN,
TEST_FORGED_YAHOO_RCVD,TEST_INVALID_DATE,TEST_NOREALNAME,
TEST_NORMAL_HTTP_TO_IP,UNDISC_RECIPS scantime=0.4,size=3138,user=jm,
uid=1000,required_score=5.0,rhost=localhost,raddr=127.0.0.1,
rport=33153,mid=<9PS291LhupY>,autolearn=spam

"name" et "VALUE" ne doivent pas contenir de caractères "=" ou ",", car il est important que ces lignes de journal soient faciles à analyser.

La référence de code sera appelée par spamd après que le message a été analysé, et que la méthode PerMsgStatus::check() est retournée.

$status->finish ()
Indique que cet objet $status est terminé et peut être détruit.

Si vous utilisez SpamAssassin dans un environnement persistant, ou si vous analysez de nombreux messages électroniques à partir d'une seule usine "Mail::SpamAssassin", cette méthode doit être appelée pour garantir que le garbage collector de Perl nettoiera les anciens objets de statut.

$name = $status->get_current_eval_rule_name()
Retourne le nom de la règle d'évaluation actuellement en cours d'exécution. "undef" est retourné si aucune règle d'évaluation n'est actuellement en cours d'exécution. Utile pour les plugins afin de déterminer le nom de la règle actuelle lors d'un appel de fonction de test d'évaluation.
$status->get_decoded_body_text_array ()
Retourne le corps du message, avec les encodages base64 ou quoted-printable décodés, et les parties non textuelles ou les pièces jointes non intégrées supprimées.

C'est le même texte de résultat que celui utilisé dans les règles 'rawbody'.

Il est retourné sous forme de tableau de chaînes, chaque chaîne étant un bloc de 2 à 4 Ko du corps, divisé par des délimiteurs si possible.

$status->get_decoded_stripped_body_text_array ()
Retourne le corps du message, décodé (comme décrit dans get_decoded_body_text_array()), avec le HTML rendu, et avec les espaces blancs normalisés.

C'est le même texte de résultat que celui utilisé dans les règles 'body'.

Il rendra toujours le texte/html.

Il est retourné sous forme de tableau de chaînes, chaque chaîne représentant un 'paragraphe'. Les paragraphes, dans les courriels en texte brut, sont des blocs de texte multilignes séparés par des doubles sauts de ligne.

$status->get (header_name [, default_value])
Retourne les en-têtes du message, les pseudo-en-têtes, les noms, les adresses e-mail ou d'autres valeurs analysées définies par les modificateurs. "header_name" est le nom d'un en-tête de courrier tel que 'Subject', 'To' etc, ou un pseudo/méta-en-tête comme 'ALL', 'X-Spam-Relays-Untrusted' etc.

Doit être appelé dans un contexte de liste depuis SpamAssassin 4.0. Cela permet de retourner plusieurs valeurs pour tous les types d'en-têtes et de modificateurs.

Si appelé dans un contexte scalaire (style pré-4.0), seule la première valeur est retournée pour les modificateurs comme ":addr" ou ":name".

Si "default_value" est fourni, il sera utilisé si le "header_name" demandé n'existe pas. C'est principalement utile lorsqu'il est appelé dans un contexte scalaire pour définir 'undef' au lieu de la valeur de retour héritée '' lorsque l'en-tête n'existe pas.

L'ajout du modificateur ":raw" au nom de l'en-tête inhibera le décodage des chaînes encodées en quoted-printable ou base64.

L'ajout du modificateur ":addr" au nom de l'en-tête retournera toutes les adresses e-mail trouvées dans l'en-tête. Il est principalement applicable aux champs d'en-tête 'From', 'Sender', 'To', 'Cc' ainsi qu'à leurs homologues 'Resent-*', et au 'Return-Path'. Par exemple, tous les éléments suivants aboutiront à "example@foo" (et "example@bar") :

example@foo
example@foo (Foo Blah), <example@bar>
example@foo, example@bar
display: example@foo (Foo Blah), example@bar ;
Foo Blah <example@foo>
"Foo Blah" <example@foo>
"'Foo Blah'" <example@foo>

L'ajout du modificateur ":name" au nom de l'en-tête retournera tous les "noms d'affichage" du champ d'en-tête. Comme avec ":addr", il est principalement applicable aux champs d'en-tête 'From', 'Sender', 'To', 'Cc' ainsi qu'à leurs homologues 'Resent-*', et au 'Return-Path'. Par exemple, tous les éléments suivants aboutiront à "Foo Blah" (et "Bar Baz"). Un niveau de guillemets simples est également supprimé, car il est souvent vu.

example@foo (Foo Blah)
example@foo (Foo Blah), "Bar Baz" <example@bargt
display: example@foo (Foo Blah), example@bar ;
Foo Blah <example@foo>
"Foo Blah" <example@foo>
"'Foo Blah'" <example@foo>

L'ajout de ":host" au nom de l'en-tête retournera la première chaîne ressemblant à un nom d'hôte se terminant par un TLD valide. Il essaie d'abord de trouver une correspondance après le caractère @ (éventuelle adresse e-mail), puis à partir de n'importe quelle partie de l'en-tête. L'utilisation normale serait par exemple 'From:addr:host' pour retourner la partie nom d'hôte d'une adresse d'expéditeur.

L'ajout de ":domain" au nom de l'en-tête implique ":host", mais retournera uniquement la partie domaine du nom d'hôte, telle que retournée par RegistryBoundaries::trim_domain().

L'ajout de ":ip" au nom de l'en-tête retournera la première chaîne d'adresse IPv4 ou IPv6 trouvée. Peut être utilisé par exemple comme 'X-Originating-IP:ip'.

L'ajout de ":revip" au nom de l'en-tête implique ":ip", mais retournera l'IP trouvée en inversé (généralement pour une utilisation DNSBL).

L'ajout du modificateur ":first" au nom de l'en-tête retournera uniquement le premier en-tête (celui du haut), s'il y en a plusieurs. De même, ":last" sélectionnera le dernier. Ceux-ci affectent uniquement la sélection de la ligne d'en-tête physique. Si l'en-tête sélectionné est analysé davantage avec ":addr" ou similaire, il peut retourner plusieurs résultats, si l'en-tête sélectionné contient plusieurs adresses.

Il existe plusieurs pseudo-en-têtes spéciaux qui peuvent être spécifiés :

"ALL" peut être utilisé pour désigner le texte de tous les en-têtes du message. Chaque en-tête est décodé et déplié en une seule ligne, sauf s'il est appelé avec :raw.
"ALL-TRUSTED" peut être utilisé pour désigner le texte de tous les en-têtes du message qui n'auraient pu être ajoutés que par des relais fiables.
"ALL-INTERNAL" peut être utilisé pour désigner le texte de tous les en-têtes du message qui n'auraient pu être ajoutés que par des relais internes.
"ALL-UNTRUSTED" peut être utilisé pour désigner le texte de tous les en-têtes du message qui peuvent avoir été ajoutés par des relais non fiables. Pour rendre ce pseudo-en-tête plus utile pour les règles d'en-tête, l'en-tête 'Received' ajouté par le dernier relais fiable est inclus, même s'il peut être considéré comme fiable.
"ALL-EXTERNAL" peut être utilisé pour désigner le texte de tous les en-têtes du message qui peuvent avoir été ajoutés par des relais externes. Comme "ALL-UNTRUSTED", l'en-tête 'Received' ajouté par le dernier relais interne est inclus.
"ToCc" peut être utilisé pour désigner le contenu des en-têtes 'To' et 'Cc'.
"EnvelopeFrom" est l'adresse utilisée dans la phase 'MAIL FROM:' de la transaction SMTP qui a livré ce message.
age, si ces données ont été mises à disposition par le serveur SMTP.
"MESSAGEID" est un symbole signifiant tous les Message-Id trouvés dans le message ; certains logiciels de liste de diffusion déplacent le vrai 'Message-Id' vers 'Resent-Message-Id' ou 'X-Message-Id' ou 'X-Original-Message-ID', puis utilisent leur propre identifiant dans l'en-tête 'Message-Id'. La valeur retournée pour ce symbole est le texte des 4 en-têtes.
"X-Spam-Relays-Untrusted" sont les métadonnées générées des relais non fiables par lesquels le message est passé
"X-Spam-Relays-Trusted" sont les métadonnées générées des relais fiables par lesquels le message est passé
"X-Spam-Relays-External" sont les métadonnées générées des relais externes par lesquels le message est passé
"X-Spam-Relays-Internal" sont les métadonnées générées des relais internes par lesquels le message est passé
$status->get_uri_list ()
Retourne un tableau de toutes les URI uniques trouvées dans le message. Il prend une combinaison des URI trouvées dans le corps rendu (décodé et sans HTML) et des URI trouvées lors de l'analyse du HTML dans le message. Définira également $status->{uri_list} (le tableau tel que retourné par cette fonction).

Le tableau retourné inclura l'URI "brute" ainsi que des versions "légèrement traitées". Par exemple, l'URI unique 'http://%77&#00119;%77.example.com/' sera transformée en : ( 'http://%77&#00119;%77.example.com/', 'http://www.example.com/' )

$status->get_uri_detail_list ()
Retourne une référence de hachage de toutes les URI uniques trouvées dans le message et diverses données sur les endroits où les URI ont été trouvées dans le message. Il prend une combinaison des URI trouvées dans le corps rendu (décodé et sans HTML) et des URI trouvées lors de l'analyse du HTML dans le message. Définira également $status->{uri_detail_list} (la référence de hachage telle que retournée par cette fonction).

Le format de hachage ressemble à ceci :

raw_uri => {
  types => { a => 1, img => 1, parsed => 1, domainkeys => 1,
             unlinked => 1, schemeless => 1 },
  cleaned => [ uri_canonisée ],
  anchor_text => [ "cliquez ici", "ne cliquez pas ici" ],
  domains => { domaine1 => 1, domaine2 => 1 },
  hosts => { hôte1 => domaine1, hôte2 => domaine2 },
}

"raw_uri" est l'URI telle qu'elle était dans le message lui-même (http://spamassassin.apache%2Eorg/). Les URI analysées à partir du texte seront préfixées par un schéma s'il manque (http://, mailto: etc.). Les URI HTML sont telles qu'elles ont été trouvées.

"types" est un hachage des balises HTML (en minuscules) qui référençaient la raw_uri. parsed est un type fictif qui spécifie que la raw_uri a été vue dans le texte rendu. domainkeys est défini lorsque la raw_uri a été trouvée à partir du champ d= de DK/DKIM. unlinked est défini lorsqu'il est supposé que le MUA ne créera pas de lien vers l'URI (trouvée dans le corps sans schéma ou sans préfixe www.). schemeless est toujours ajouté pour les URI sans schéma, indépendamment de la création de lien (par exemple, une adresse e-mail trouvée dans le corps sans mailto:).

"cleaned" est un tableau des versions brutes et canoniques de la raw_uri (http://spamassassin.apache%2Eorg/, https://spamassassin.apache.org/).

"anchor_text" est un tableau du texte d'ancre (texte entre <a> et </a>), le cas échéant, qui liait à l'URI.

"domains" est un hachage des domaines trouvés dans les URI canoniques.

"hosts" est un hachage des noms d'hôte non épurés trouvés dans les URI canoniques comme clés de hachage, avec leur partie domaine stockée comme valeur de chaque entrée de hachage.

$status->add_uri_detail_list ($raw_uri, $types, $source, $valid_domain)
Ajoute des valeurs à la uri_detail_list interne. Lors de l'utilisation à partir de Plugins, il est recommandé d'appeler à partir de parsed_metadata (avec register_method_priority, -10) afin que d'autres Plugins appelant get_uri_detail_list() puissent la voir.

"raw_uri" est l'URI à ajouter. Le seul paramètre requis.

"types" est une référence de hachage optionnelle, dont le contenu est ajouté à uri_detail_list->{types} (voir get_uri_detail_list pour les clés connues). parsed est la valeur par défaut si aucun hachage n'est donné. nocanon n'exécute pas uri_list_canonicalize (pas de redirection, correction d'URI). noclean saute l'ajout de uri_detail_list->{cleaned}, donc elle ne serait pas utilisée dans les vérifications de règles "uri", mais le domaine/les hôtes seraient toujours utilisés à des fins URIBL/RBL.

"source" est une chaîne simple optionnelle, utilisée uniquement à des fins de journalisation de débogage pour identifier l'origine de l'URI (par défaut : "parsed").

"valid_domain" est un booléen optionnel (0/1). S'il est vrai, l'URI ne sera pas ajoutée sauf si le nom d'hôte/domaine est au format valide et contient un TLD valide. (par défaut : 0)

$status->got_hit ($rulename, $desc_prepend [, name => value, ...])
Enregistre un coup contre une règle dans le jeu de règles.

Il y a deux arguments obligatoires. Ce sont $rulename, le nom de la règle qui s'est déclenchée, et $desc_prepend, qui est une courte chaîne qui sera ajoutée au début de la chaîne "describe" de la règle dans les rapports de sortie.

En outre, les appelants peuvent compléter cela avec les données optionnelles suivantes :

score => $num
Optionnel : le score à utiliser pour le coup de la règle. S'il n'est pas spécifié, la valeur de la référence de hachage "{scores}" de l'objet "Mail::SpamAssassin::Conf" sera utilisée (un score configuré), et en son absence la valeur de l'option "defscore".
defscore => $num
Optionnel : le score à utiliser pour le coup de la règle si ni l'option "score" n'est fournie, ni une valeur de score configurée n'est fournie.
value => $num
Optionnel : la valeur à attribuer à la règle ; la valeur par défaut est 1. Les règles avec tflags multiple utilisent des valeurs supérieures à 1 pour indiquer plusieurs coups. Cette valeur est accessible aux méta-règles.
ruletype => $type
Optionnel, mais recommandé : la chaîne de type de règle. Ceci est utilisé dans l'appel de plugin "hit_rule", appelé par cette méthode. Si non défini, 'unknown' est utilisé.
tflags => $string
Optionnel : une chaîne, c'est-à-dire une liste séparée par des espaces de tflags supplémentaires à ajouter à une liste existante de drapeaux dans $self->{conf}->{tflags}, tels que : "nice noautolearn multiple". Aucune vérification de syntaxe n'est effectuée.
description => $string
Optionnel : une chaîne de description de règle personnalisée. Ceci est utilisé dans l'appel de plugin "hit_rule", appelé par cette méthode. Si non défini, la description statique est utilisée.

Compatibilité descendante : les deux arguments obligatoires font partie de cette API depuis SpamAssassin 2.x. Les paires optionnelles "name=>value", cependant, sont une nouvelle addition dans SpamAssassin 3.2.0.

$status->rule_ready ($rulename [, $no_async])
Marque une règle asynchrone comme prête, afin qu'elle puisse être prise en compte pour l'évaluation des méta-règles. Une règle asynchrone est une règle dont la fonction d'évaluation retourne undef, marquant qu'elle n'est pas encore prête et qu'elle attend des résultats ultérieurement. $status->rule_ready() doit être appelée plus tard pour la marquer comme prête, sinon $status->got_hit() le fait également. Si aucune des deux n'est appelée, toute méta-règle qui dépend de cette règle pourrait ne pas s'évaluer.
$status->test_log ($text [, $rulename])
Ajoute une entrée de journal $text pour un coup de règle dans le RAPPORT/RÉSUMÉ final du message.

Généralement appelée juste avant got_hit(), pour décrire par exemple quelle URI la règle a correspondue. L'argument optionnel $rulename est recommandé pour s'assurer que le journal est écrit dans la bonne règle. Si le nom de la règle n'est pas fourni, get_current_eval_rule_name() est utilisé comme solution de secours.

Peut être appelé plusieurs fois par règle pour des entrées supplémentaires.

$status->create_fulltext_tmpfile (fulltext_ref)
Cette fonction crée un fichier temporaire contenant les données de référence scalaire passées. Si aucun scalaire n'est passé, le texte complet/pristine du message est supposé. Ceci est typiquement utilisé par des programmes externes comme pyzor et dccproc, pour éviter des blocages dus à des problèmes de mise en mémoire tampon.

Tous les fichiers temporaires sont automatiquement nettoyés par le destructeur PerMsgStatus.

$status->delete_fulltext_tmpfile (tmpfile)
Nettoiera après un appel à $status->create_fulltext_tmpfile(). Supprime le fichier temporaire et met en cache le nom du fichier. En général, il n'est pas nécessaire d'appeler cela, le destructeur PerMsgStatus nettoie tous les fichiers temporaires.
all_from_addrs_domains
Cette fonction retourne toutes les différentes adresses d'expéditeur dans un message en utilisant all_from_addrs() et retourne ensuite uniquement les noms de domaine.
