NOM

Mail::IMAPClient - Une API de client IMAP

SYNTAXE

use Mail::IMAPClient;
my $imap = Mail::IMAPClient->new(
  Server   => 'localhost',
  User     => 'username',
  Password => 'password',
  Ssl      => 1,
  Uid      => 1,
);
my $folders = $imap->folders
  or die "Erreur liste de dossiers : ", $imap->LastError, "\n";
print "Dossiers : @$folders\n";
$imap->select( $Opt{folder} )
  or die "Sélectionner '$Opt{folder}' erreur : ", $imap->LastError, "\n";
$imap->fetch_hash("FLAGS", "INTERNALDATE", "RFC822.SIZE")
  or die "Récupérer hash '$Opt{folder}' erreur : ", $imap->LastError, "\n";
$imap->logout
  or die "Déconnexion erreur : ", $imap->LastError, "\n";

DESCRIPTION

Ce module fournit des méthodes qui implémentent le protocole IMAP pour interagir avec des magasins de messages IMAP.

Le module est utilisé en construisant ou en instanciant un objet IMAPClient via la méthode constructeur new. Une fois l'objet instancié, la méthode connect est appelée implicitement ou explicitement. À ce stade, des méthodes qui implémentent les commandes client IMAP selon la RFC 3501 sont disponibles. À la fin de l'opération, la méthode logout de l'objet doit être appelée.

Cette documentation ne doit pas remplacer la RFC 3501 ni d'autres RFC relatives à IMAP.

Note : Cette documentation utilise le terme dossier au lieu de mailbox utilisé dans la RFC 3501. Cette documentation réserve l'usage du terme mailbox pour faire référence à une collection de dossiers appartenant à un identifiant IMAP spécifique.

État de la Connexion

La RFC 3501 définit quatre états possibles pour une connexion IMAP : non authentifié, authentifié, sélectionné et déconnecté. Ceux-ci correspondent aux constantes IMAPClient "Conectado", "Autenticado", "Seleccionado" et "Sin Conexión", respectivement. Ces constantes peuvent être utilisées avec la méthode Status pour déterminer l'état d'un objet IMAPClient et de sa session sous-jacente.

Note : Un objet IMAPClient peut être dans l'état "Sin Conexión" avant la connexion au serveur ou après que celle-ci ait été terminée. Cette différence est légèrement distincte de la RFC 3501, qui ne définit pas d'état préalable à la connexion. Pour une discussion sur les méthodes disponibles pour examiner l'état de l'objet IMAPClient, consultez la section intitulée "Méthodes d'état".

Mécanismes d'Authentification Avancés

La RFC 3501 définit deux commandes pour s'authentifier sur un serveur IMAP :

LOGIN
LOGIN est pour l'authentification en texte clair.
AUTHENTICATE
AUTHENTICATE pour une authentification plus avancée et/ou sécurisée.

Mail::IMAPClient prend en charge les mécanismes d'authentification suivants :

DIGEST-MD5
DIGEST-MD5 nécessite les modules Authen::SASL et Digest::MD5. Voir aussi "Authentification".
CRAM-MD5
CRAM-MD5 nécessite le module Digest::HMAC_MD5.
PLAIN (SASL)
PLAIN (SASL) permet l'utilisation optionnelle du paramètre "Proxy". La RFC 4616 documente ce format pour SASL PLAIN : 
message = [authzid] UTF8NUL authcid UTF8NUL passwd

Lorsque "Proxy" est défini, "User" est utilisé comme 'authzid' et "Proxy" comme 'authcid'. Sinon, "User" est utilisé comme 'authcid'.

NTLM
NTLM nécessite le module Authen::NTLM. Voir aussi "Domaine".

Erreurs

Si vous tentez une opération qui résulte en une erreur, vous pouvez récupérer le texte du message d'erreur en utilisant la méthode LastError. Cependant, la méthode LastError est une méthode d'objet (pas une méthode de classe) et ne peut être utilisée qu'une fois que l'objet a été correctement créé. Dans les cas où l'objet n'a pas été correctement créé, la variable $@ est définie avec un message d'erreur.

Mail::IMAPClient réinitialise $@ et LastError avant de nombreuses requêtes IMAP, donc les valeurs n'ont qu'une durée de vie limitée. LastError contiendra toujours des informations d'erreur jusqu'à ce qu'une autre erreur soit rencontrée, qu'une autre commande IMAP soit émise ou qu'elle soit effacée explicitement.

Note : L'utilisation de $@ est sujette à des changements dans les futures versions, il est donc préférable d'utiliser LastError pour vérifier les erreurs une fois que l'objet Mail::IMAPClient a été créé.

Les erreurs dans la méthode new peuvent empêcher votre objet d'être jamais créé. Si les paramètres Server, User et Password sont fournis à new, il tentera d'appeler connect et login. N'importe quelle méthode pourrait échouer et faire que l'appel à new retourne "undef", avec la variable $@ définie avec un message d'erreur.

ATTENTION : (en raison d'un ancien comportement de l'API) en cas d'erreurs, de nombreuses méthodes peuvent retourner undef quel que soit le contexte LIST/SCALAR. Il est donc sage d'utiliser davantage les méthodes dans un contexte scalaire. Cependant, vérifiez LastError pour les détails sur les erreurs.

Transactions

La RFC 3501 exige que chaque ligne d'une conversation IMAP soit précédée d'une étiquette. Une conversation typique consiste en le client émettant une chaîne de commandes préfixée par une étiquette, et le serveur répondant par une ou plusieurs lignes de sortie. Les lignes de sortie incluront un code d'état de complétion de la commande originale, précédé de la même étiquette.

Le module IMAPClient utilise un compteur simple pour s'assurer que chaque commande client est émise avec une valeur d'étiquette unique. Cette valeur d'étiquette fait référence au numéro de transaction du module IMAPClient. Un historique des transactions est maintenu par l'objet IMAPClient, documentant chaque transaction. La méthode Transaction renvoie le numéro de la dernière transaction, et peut être utilisée pour récupérer des lignes de texte de l'historique de l'objet.

Le paramètre Clear est utilisé pour contrôler la taille de l'historique de session, afin d'éviter que des sessions longues n'utilisent trop de mémoire. Consultez la discussion sur le paramètre Clear pour plus d'informations.

La méthode Report renvoie l'historique de toute la session IMAP depuis la connexion initiale ou pour les Clear dernières transactions. Cela fournit un enregistrement complet de la conversation, y compris les chaînes de commandes client et les réponses du serveur, et constitue un excellent outil de débogage ainsi qu'une source utile de données brutes pour l'analyse personnalisée.

MÉTHODES DE CLASSE

Il existe plusieurs méthodes qui peuvent être invoquées en tant que méthodes de classe. Généralement, elles peuvent aussi être invoquées en tant que méthodes d'objet. Note : si la méthode new est appelée en tant que méthode d'objet, l'objet renvoyé est identique à celui qui aurait été renvoyé si new avait été appelé en tant que méthode de classe. Cela ne vous donne pas une copie de l'objet original.

new

Exemple :

my $imap = Mail::IMAPClient->new(%args)
  or die "new a échoué : $@\n";

La méthode new crée une nouvelle instance d'un objet IMAPClient.

Si le paramètre Server est passé comme argument à new, alors new appellera implicitement la méthode connect, plaçant le nouvel objet dans l'état Conectado. Si des valeurs User et Password sont également fournies, alors connect appellera login, et l'objet résultant sera renvoyé par new dans l'état Au

Quote

Exemple :

$imap->search( HEADER => 'Message-id' => \$imap->Quote($msg_id) );

La méthode Quote accepte une valeur comme argument et retourne son argument sous forme de chaîne correctement mise entre guillemets ou de chaîne littérale. Depuis la version 3.17, Mail::IMAPClient met automatiquement entre guillemets les arguments de recherche ; nous utilisons donc un SCALARREF pour que search ne modifie ni ne re-quote la valeur retournée par Quote.

Notez que cette méthode ne doit pas être utilisée sur les noms de dossiers pour les méthodes Mail::IMAPClient, car les méthodes qui acceptent des noms de dossiers comme argument mettent automatiquement ces noms entre guillemets.

Si vous obtenez des résultats inattendus lors de l'exécution de méthodes avec des valeurs qui contiennent (ou pourraient contenir) des espaces intégrés, des guillemets doubles, des accolades ou des parenthèses, alors l'appel à Quote peut être nécessaire. Cette méthode ne doit pas être utilisée avec des arguments qui sont déjà entre guillemets ou parenthèses si ces guillemets ou parenthèses sont requis par RFC3501. Par exemple, si le RFC exige un argument sous cette forme :

( argument )

et que l'argument est (ou pourrait être) "pennies (from heaven)", alors on pourrait utiliser :

$argument = "(" . $imap->Quote($argument) . ")"

Bien sûr, le fait que ces caractères soient parfois des délimiteurs requis est précisément la raison pour laquelle vous devez les mettre entre guillemets lorsqu'ils ne le sont *pas*.

Cependant, il y a des moments où une méthode échoue de manière inattendue et peut nécessiter l'utilisation de Quote pour fonctionner. Si cela se produit, vous pouvez probablement déposer une demande de bug/amélioration pour que Mail::IMAPClient protège mieux l'appel/le cas particulier.

Un exemple est les identifiants de message RFC822, qui ne contiennent *généralement* pas de guillemets ou de parenthèses. Lorsque vous traitez avec ceux-ci, il est généralement préférable de prendre des mesures préventives et défensives dès le départ et d'utiliser Quote.

Range

Exemple :

my $parsed = $imap->parse_headers(
    $imap->Range( $imap->messages ), "Date", "Subject"
);

La méthode Range condense une liste de numéros de séquence de messages ou d'UID de messages dans le format le plus compact supporté par RFC3501. Elle accepte un ou plusieurs arguments, dont chacun peut être :

a) un numéro de message,
b) une liste de numéros de messages séparés par des virgules,
c) une plage de numéros de messages séparés par des deux-points (c.-à-d. "$begin:$end")
d) une combinaison de messages et de plages de messages, séparés par des virgules (c.-à-d. 1,3,5:8,10), ou
e) une référence à un tableau dont les éléments sont comme a) à d).

La méthode Range retourne un objet Mail::IMAPClient::MessageSet. L'objet utilise le surcharge et s'il est traité comme une chaîne, il se comportera comme une chaîne. Cela signifie que vous pouvez ignorer son objectivité et simplement le traiter comme une chaîne dont la valeur est votre ensemble de messages exprimé dans un format compact.

Cette méthode offre un moyen simple d'ajouter ou de supprimer des messages d'un ensemble de messages.

Pour plus d'informations, voir Mail::IMAPClient::MessageSet.

Rfc3501_date

Exemple :

$Rfc3501_date = $imap->Rfc3501_date($seconds);
# ou :
$Rfc3501_date = Mail::IMAPClient->Rfc3501_date($seconds);

La méthode Rfc3501_date accepte un argument d'entrée, un nombre de secondes depuis la date de l'époque. Elle retourne une chaîne de date conforme à la norme RFC3501 pour cette date (telle qu'exigée dans les arguments liés aux dates de SEARCH, comme "since", "before", etc.).

Rfc3501_datetime

Exemple :

$date = $imap->Rfc3501_datetime($seconds);
# ou :
$date = Mail::IMAPClient->Rfc3501_datetime($seconds);

La méthode Rfc3501_datetime accepte un ou deux arguments : un horodatage obligatoire et une zone optionnelle. La zone doit être formatée comme "[+-]\d{4}" et vaut par défaut +0000. L'horodatage suit la définition de la sortie de la fonction plateforme spécifique "time", généralement en secondes depuis le 1er janvier 1970. Cependant, vous devez corriger vous-même le nombre en fonction de la zone.

Rfc822_date

Exemple :

$Rfc822_date = $imap->Rfc822_date($seconds);
# ou :
$Rfc822_date = Mail::IMAPClient->Rfc822_date($seconds);

La méthode Rfc822_date accepte un argument d'entrée, un nombre de secondes depuis la date de l'époque. Elle retourne une chaîne de date conforme à la norme RFC822 pour cette date (sans le préfixe 'Date:'). Utile pour insérer des dates dans des chaînes de messages avant d'appeler "append", "search", etc.

Strip_cr

Exemples :

my $stripped = $imap->Strip_cr($string);
# ou :
my @list = $imap->some_imap_method;
@list = $imap->Strip_cr(@list);
# ou :
my $list = [ $imap->some_imap_method ];   # retourne une référence de tableau
$list = $imap->Strip_cr($list);

La méthode Strip_cr supprime les retours chariot de l'entrée et retourne la nouvelle chaîne à l'appelant. Cette méthode accepte une ou plusieurs lignes de texte comme arguments, et retourne ces lignes avec toutes les séquences <CR><LF> remplacées par <LF>. Tout argument d'entrée sans retour chariot est retourné inchangé. Si le premier argument (sans compter le nom de la classe ou la référence à l'objet) est une référence de tableau, alors les membres de ce tableau sont traités comme ci-dessus et les arguments suivants sont ignorés. Si la méthode est appelée dans un contexte scalaire, une référence de tableau est retournée au lieu d'un tableau de résultats.

NOTE : Strip_cr ne supprime pas les caractères de nouvelle ligne.

MÉTHODES DE L'OBJET

Les méthodes d'objet doivent être appelées sur des objets créés via la méthode "new" et ne peuvent pas être appelées en tant que méthodes de classe.

Ces méthodes d'objet tombent généralement dans l'une des deux catégories. Il y a des méthodes de boîte aux lettres qui participent à la conversation de la session IMAP (c'est-à-dire qu'elles émettent des commandes client IMAP) et des méthodes de contrôle d'objet qui n'entraînent pas de commandes IMAP mais qui peuvent affecter les commandes ultérieures ou fournir des détails sur les commandes précédentes.

Ces méthodes de contrôle d'objet peuvent être subdivisées en deux types : les méthodes d'accès aux paramètres, qui affectent le comportement des méthodes de boîte aux lettres futures, et les "méthodes de statut", qui rendent compte des effets des méthodes de boîte aux lettres précédentes.

Les méthodes qui n'entraînent pas l'émission de nouvelles commandes client IMAP (telles que les méthodes "Transaction", "Status" et "History") commencent toutes par une lettre majuscule, pour les distinguer des méthodes qui correspondent effectivement à des commandes client IMAP. Les méthodes de classe et les méthodes de paramètre éponymes commencent également par une lettre majuscule car elles ne correspondent pas non plus à une commande client IMAP.

En règle générale, les méthodes de contrôle de boîte aux lettres retournent "undef" en cas d'échec et quelque chose d'autre que "undef" lorsqu'elles réussissent. Cette règle est modifiée dans le cas des méthodes qui retournent des résultats de recherche. Lorsqu'elles sont appelées dans un contexte de liste, les recherches qui ne trouvent pas de résultats correspondants retournent une liste vide. Lorsqu'elles sont appelées dans un contexte scalaire, les recherches sans succès retournent 'undef' au lieu d'une référence de tableau. Si vous voulez savoir pourquoi vous n'avez obtenu aucun résultat, vous devriez vérifier "LastError" ou $@, qui sera vide si la recherche a réussi mais n'a trouvé aucun résultat correspondant, mais rempli d'un message d'erreur si la recherche a rencontré un problème (comme des paramètres invalides).

Un certain nombre de commandes IMAP n'ont pas de méthodes Mail::IMAPClient correspondantes. Les correctifs sont les bienvenus. Dans les versions pré-2.99 de ce module, elles étaient automatiquement créées (AUTOLOAD), mais cela était très sujet aux erreurs et a ralenti la progression de ce module.

Méthodes de contrôle de boîte aux lettres

append

Exemple :

my $uid_or_true = $imap->append( $folder, $msgtext )
  or die "Impossible d'ajouter : ", $imap->LastError;

ATTENTION : Cette méthode pourrait être dépréciée à l'avenir, considérez l'utilisation de "append_string" au lieu de cette méthode.

La méthode append ajoute un message au dossier spécifié. Voir "append_string" pour les détails car c'est effectivement un alias pour cette méthode.

COMPORTEMENT DÉPRÉCIÉ : Des arguments supplémentaires sont ajoutés au texte du message, séparés par <CR><LF>.

append_string

Exemple :

# les crochets indiquent les arguments optionnels (pas des références de tableau) :
my $uidort = $imap->append_string( $folder, $msgtext [,$flags [,$date ] ] )
    or die "Impossible d'ajouter la chaîne : ", $imap->LastError;

Arguments :

$folder
le nom du dossier auquel ajouter le message
$msgtext
le texte du message (y compris les en-têtes) du message
$flags
Une liste optionnelle d'indicateurs à définir. La liste doit être spécifiée comme une liste d'indicateurs séparés par des espaces, y compris les barres obliques inverses nécessaires et éventuellement entre parenthèses.
$date

append

Ajoute une message à la boîte aux lettres spécifiée. Le premier argument est le nom de la boîte aux lettres, le deuxième est la chaîne de message, et le troisième est la date. 

my $new_msg_uid = $imap->append(
    $folder,
    $message,
    [ undef, $flags, $date ] # facultatif
) or die "Could not append: ", $imap->LastError;
Les crochets dans l'exemple indiquent des arguments facultatifs ; ils n'indiquent pas que l'argument doit être une référence de tableau.

$folder
le nom de la boîte aux lettres à laquelle ajouter le message.
$message
une chaîne contenant le message ; les retours chariot à l'intérieur seront remplacés par des retours chariot et des flux de ligne (CRLF).
undef
Un argument facultatif de date RFC3501 pour définir la date interne. Elle doit être dans le format décrit pour date_time dans RFC3501, c'est-à-dire "dd-Mon-yyyy hh:mm:ss +0000".

Si vous souhaitez spécifier une date/heure mais ne souhaitez aucun indicateur, spécifiez undef comme troisième argument ($flags).

Retourne :

error: undef
En cas d'erreur, undef peut être retourné indépendamment du contexte LIST/SCALAR. Vérifiez "LastError" pour plus de détails.
success: UID ou $imap
Avec UIDPLUS, l'UID du nouveau message est retourné ; sinon, une valeur vraie (actuellement $self) est retournée.

Pour se protéger contre les "bare newlines", append insérera un retour chariot avant toute nouvelle ligne qui est "bare".

append_file

Exemple :

my $new_msg_uid = $imap->append_file(
    $folder,
    $file,
    [ undef, $flags, $date ] # facultatif
) or die "Could not append_file: ", $imap->LastError;

La méthode append_file ajoute un message à la boîte aux lettres spécifiée. Notez que les crochets dans l'exemple indiquent des arguments facultatifs ; ils n'indiquent pas que l'argument doit être une référence de tableau.

Arguments :

$folder
le nom de la boîte aux lettres à laquelle le message est ajouté
$file
un nom de fichier, un descripteur de fichier ou une référence SCALAR contenant un message formaté RFC822
undef
un argument obsolète utilisé comme espace réservé de compatibilité
$flags
L'argument facultatif est traité de la même manière que append_string.
$date
L'argument facultatif est traité de la même manière que append_string (date RFC3501), sauf que si $date est "1" (un), alors la date de modification (mtime) du fichier sera utilisée.

Retourne :

error: undef
En cas d'erreur, undef peut être retourné indépendamment du contexte LIST/SCALAR. Vérifiez "LastError" pour plus de détails.
success: UID ou $imap
Avec UIDPLUS, l'UID du nouveau message est retourné ; sinon, une valeur vraie (actuellement $self) est retournée.

Pour se protéger contre les "bare newlines", append_file insérera un retour chariot avant toute nouvelle ligne qui est "bare".

La méthode append_file fournit un mécanisme pour ajouter de gros messages sans avoir à stocker le fichier complet en mémoire.

Remarque de version : Dans la version 2.x, un troisième argument facultatif était autorisé pour être utilisé comme "input_record_separator", mais cet argument est ignoré / non pris en charge depuis la version 3.x.

authenticate

Exemple :

$imap->authenticate( $authentication_mechanism, $coderef )
  or die "Could not authenticate: ", $imap->LastError;

Cette méthode implémente la commande AUTHENTICATE du client IMAP. Elle peut être appelée directement ou peut être appelée par "login" si le paramètre "Authmechanism" est défini sur autre chose que "LOGIN".

La méthode authenticate accepte deux arguments, un type d'authentification (par exemple CRAM-MD5) et une référence de code ou un sous-programme à exécuter pour obtenir une réponse. La méthode authenticate suppose que le type d'authentification spécifié dans le premier argument suit un flux défi-réponse. La méthode authenticate émet la commande AUTHENTICATE du client IMAP et reçoit un défi du serveur. Le défi (sans préfixe d'étiquette ni caractères de chaîne + mais dans l'encodage base64 d'origine) est passé comme seul argument au code ou au sous-programme référencé dans le second argument. La valeur retournée par le code du second argument est écrite sur le serveur telle quelle, sauf qu'un <CR><LF> est ajouté si nécessaire.

Si un ou les deux arguments ne sont pas spécifiés dans l'appel à authenticate mais que leurs paramètres correspondants ont été définis ("Authmechanism" et "Authcallback"), alors les valeurs des paramètres sont utilisées. Les arguments fournis à l'appel de méthode remplacent cependant les valeurs des paramètres.

Si vous ne spécifiez pas de deuxième argument et n'avez pas défini le paramètre "Authcallback", alors le premier argument doit être l'un des mécanismes d'authentification pour lesquels Mail::IMAPClient a un support intégré.

Voir aussi la méthode "login", qui est la manière la plus simple d'authentification définie par RFC3501.

before

Exemple :

my @msgs = $imap->before($Rfc3501_date)
  or warn "No messages found before $Rfc3501_date.\n";

La méthode before fonctionne comme la méthode "since", ci-dessous, sauf qu'elle retourne une liste de messages dont les dates internes sont antérieures à la date fournie comme argument à la méthode before.

body_string

Exemple :

my $string = $imap->body_string($msgId)
  or die "body_string failed: ", $imap->LastError;

La méthode body_string accepte un numéro de message (ou un UID de message, si le paramètre "Uid" est défini sur true) comme argument et retourne le corps du message sous forme de chaîne. La valeur retournée contient le corps complet du message dans une variable scalaire sans les en-têtes du message.

bodypart_string

Exemple :

my $string = $imap->bodypart_string(
    $msgid, $part_number, $length, $offset
) or die "Could not get bodypart string: ", $imap->LastError;

La méthode bodypart_string accepte un numéro de message (ou un UID de message, si le paramètre "Uid" est défini sur true) et une partie du message comme arguments et retourne le corps du message sous forme de chaîne. La valeur retournée contient le corps complet du message (ou, éventuellement, une partie du corps) dans une variable scalaire.

Si un troisième argument facultatif est fourni, il s'agit du nombre d'octets à récupérer. (La valeur par défaut est le corps complet du message). Si un quatrième argument facultatif est fourni, il s'agit du décalage dans le corps à partir duquel la récupération doit commencer. La valeur par défaut est le décalage 0, ou le début du corps du message.

Si vous spécifiez un décalage sans spécifier de longueur, le décalage sera ignoré et le corps complet sera retourné.

bodypart_string retournera "undef" s'il rencontre une erreur.

capability

Exemple :

my $features = $imap->capability
  or die "Could not determine capability: ", $imap->LastError;

La méthode capability retourne un tableau (ou une référence de tableau dans un contexte scalaire) des capacités telles que retournées par la commande CAPABILITY du client IMAP. Si la commande CAPABILITY du client IMAP échoue pour une raison quelconque, la méthode capability retournera "undef". Voir aussi "has_capability".

close

Exemple :

$imap->close or die "Could not close: $@\n";

La méthode close est utilisée pour fermer la boîte aux lettres actuellement sélectionnée en utilisant la commande CLOSE du client IMAP. Conformément à RFC3501, la commande CLOSE effectue une EXPUNGE implicite, ce qui signifie que tous les messages marqués comme \Deleted (c'est-à-dire avec la méthode "delete_message") seront maintenant supprimés. Si vous n'avez supprimé aucun message, close peut être considéré comme un "unselect".

Notez que cela ferme la boîte aux lettres actuellement sélectionnée, et non la session IMAP.

Voir aussi "delete_message", "expunge", et RFC3501.

connect

Exemple :

La méthode connect connecte un objet imap au serveur. Elle retourne "undef" si la connexion échoue. Si des valeurs sont disponibles pour les paramètres "User" et "Password" au moment de l'appel de connect, alors connect appellera la méthode "login" après la connexion et retournera le résultat de la méthode "login" à l'appelant de connect. Si aucun des paramètres "User" ou "Password" n'est disponible, mais que la connexion au serveur est établie avec succès, connect retournera un pointeur vers l'objet IMAPClient.

Le paramètre "Server" doit être défini (lors de l'appel de la méthode "new" ou via la méthode "Server" de l'objet) avant d'appeler connect. Lorsque le paramètre est un chemin de fichier absolu, un socket UNIX sera ouvert. Si le paramètre "Server" est fourni à la méthode "new", alors connect est appelé implicitement lors de la construction de l'objet.

La méthode connect définit l'état de l'objet sur "Connected" si elle se connecte avec succès au serveur. Elle retourne "undef" en cas d'échec.

delete_message

Exemple :

my @msgs = $imap->seen;
scalar(@msgs) and $imap->delete_message(\@msgs)
  or die "Could not delete_message: $@\n";

L'exemple précédent pourrait aussi être écrit ainsi :

# contexte scalaire renvoie une référence à un tableau
my $msgs = scalar($imap->seen);
scalar(@$msgs) and $imap->delete_message($msgs)
  or die "Could not delete_message: $@\n";

Ou, en une seule ligne :

$imap->delete_message( scalar($imap->seen) )
  or warn "Could not delete_message: $@\n";
# ne génère qu'un avertissement en cas d'erreur
# car il n'y a pas de messages 'seen' en premier lieu !

La méthode delete_message accepte une liste d'arguments. Si le paramètre « Uid » n'est pas réglé à une valeur vraie, chaque élément de la liste doit être :

  • un numéro de séquence de message,
  • une liste séparée par des virgules de numéros de séquence de message,
  • une référence à un tableau de numéros de séquence de message,

Si le paramètre « Uid » est réglé à une valeur vraie, chaque élément de la liste doit être :

  • un numéro d'UID,
  • une liste séparée par des virgules de numéros d'UID,
  • une référence à un tableau de numéros d'UID.

Les messages identifiés par les numéros de séquence ou d'UID seront supprimés. En cas de succès, delete_message renvoie le nombre de messages qui ont été signalés pour suppression. Cependant, étant donné que la suppression est effectuée à l'aide de l'option +FLAGS.SILENT des commandes STORE IMAP du client, il n'est pas garanti que la suppression soit réussie pour chaque message. Ainsi, la méthode delete_message sacrifie la précision pour la vitesse. Généralement, même si un message d'une liste de messages n'est pas supprimé, c'est parce qu'il a déjà été supprimé, ce qui est ce que vous souhaitez, alors pourquoi s'en soucier ? En cas d'erreur plus grave, comme le serveur répondant avec « NO » ou « BAD » ou, si vous le souhaitez, « BYE », alors delete_message renverra "undef".

Si vous avez besoin de résultats garantis, utilisez la commande STORE IMAP du client (via la méthode par défaut) et utilisez l'option +FLAGS (\Deleted), puis analysez vos résultats manuellement.

Exemple :

$imap->store( $msg_id, '+FLAGS (\Deleted)' );
my @results = $imap->History( $imap->Transaction );
  ...           # le code pour analyser la sortie va ici

(Franchement, je ne vois pas la nécessité de s'inquiéter de tout cela ; si un message n'est pas supprimé, c'est presque toujours parce qu'il n'est plus là, ce qui est ce que vous souhaitez. Mais « votre kilométrage peut varier » et tout ça.)

L'objet IMAPClient doit être dans l'état "Selected" pour utiliser la méthode delete_message.

NOTE : Tous les messages identifiés dans les arguments (un seul ou plusieurs) doivent se trouver dans le dossier actuellement sélectionné. Ne pas respecter cette exigence entraînera probablement la suppression du mauvais message.

NOTE SUPPLÉMENTAIRE : Lors de la traduction du protocole IMAP, la suppression d'un message ne le supprime pas réellement. En fait, si vous voulez vous assurer que le message a été supprimé, vous devez purger le dossier (via la méthode « expunge », qui est implémentée via la méthode par défaut). Ou du moins, fermez le dossier. Ceci est généralement considéré comme une fonctionnalité, car après avoir supprimé un message, vous pouvez changer d'avis et le restaurer à tout moment avant votre « expunge » ou « close ».

Voir aussi : la méthode « delete » pour supprimer un dossier, la méthode « expunge » pour purger un dossier, la méthode « restore_message » pour restaurer un message, et la méthode « close » (implémentée ici via la méthode par défaut) pour fermer un dossier. N'oubliez pas RFC3501 ?

fetch

Utilisation :

$imap->fetch( [$seq_set|ALL], @msg_data_items )

Exemple :

La méthode fetch implémente la commande client IMAP FETCH. Elle accepte une liste d'arguments, qui seront convertis en une liste d'arguments séparés par des espaces pour la commande client IMAP FETCH. Si aucun argument n'est fourni, fetch exécute un FETCH ALL. Si le paramètre "Uid" est défini à une valeur vraie, le premier argument sera traité comme un UID ou une liste d'UIDs, ce qui signifie que la commande client IMAP UID FETCH sera exécutée au lieu de FETCH. (Il serait vraiment judicieux à ce stade de revoir la RFC3501.)

Si appelée dans un contexte de tableau, fetch retournera un tableau de lignes de sortie. Les lignes de sortie seront retournées telles qu'elles ont été reçues du serveur, votre script devra donc être préparé à en extraire les informations dont vous avez besoin. La seule exception concerne les chaînes littérales, qui seront insérées dans la ligne de sortie au point où elles ont été rencontrées (sans l'indicateur de champ littéral {nnn}). Voir la RFC3501 pour une description des champs littéraux.

Si fetch est appelé dans un contexte scalaire, une référence à un tableau (tel que décrit ci-dessus) est retournée au lieu du tableau entier.

fetch retourne "undef" en cas d'échec. Inspectez "LastError" ou $@ pour une explication de votre erreur.

fetch_hash

Utilisation :

$imap->fetch_hash( [$seq_set|ALL], @msg_data_items, [\%msg_by_ids] )

Exemples :

 my $hashref = $imap->fetch_hash("RFC822.SIZE");
OR
 my $hashref = {};
 $imap->fetch_hash( "RFC822.SIZE", $hashref );
 print "Msg #$_ is $hashref->{$_}->{'RFC822.SIZE'} bytes\n" for (keys %$hashref);

La méthode fetch_hash accepte une liste d'attributs de message à récupérer (tels que décrits dans la RFC3501). Elle retourne une table de hachage dont les clés sont tous les messages du dossier actuellement sélectionné et dont les valeurs sont des paires clé-valeur des mots-clés de récupération et la valeur du message pour ce mot-clé (voir l'exemple de sortie ci-dessous).

Si fetch_hash est appelée dans un contexte scalaire, elle retourne une référence à la table de hachage au lieu de la table de hachage elle-même. Si le dernier argument est une référence de table de hachage, alors cette référence de table de hachage sera utilisée comme emplacement pour stocker les résultats (et cette référence sera retournée en cas de succès). Si le dernier argument n'est pas une référence, il sera traité comme l'un des attributs de FETCH et une nouvelle table de hachage sera créée et retournée (soit par valeur, soit par référence, selon le contexte dans lequel fetch_hash a été appelée).

Par exemple, si vous avez un dossier avec 3 messages et que vous souhaitez obtenir la taille et la date interne de chacun d'eux, vous pouvez faire ceci :

use Mail::IMAPClient;
use Data::Dumper;
# ... autre code ici
$imap->select($folder);
my $hash = $imap->fetch_hash( "RFC822.SIZE", "INTERNALDATE" );
# (Idem que :
#  my $hash = $imap->fetch_hash("RFC822.SIZE");
#  $imap->fetch_hash( "INTERNALDATE", $hash );
# ).
print Data::Dumper->Dumpxs( [$hash], ['$hash'] );

Cela produirait une sortie Data::Dumper similaire à la suivante :

$hash = {
    '1' => {
               'INTERNALDATE' => '21-Sep-2002 18:21:56 +0000',
               'RFC822.SIZE' => '1586',
           },
    '2' => {
               'INTERNALDATE' => '22-Sep-2002 11:29:42 +0000',
               'RFC822.SIZE' => '1945',
           },
    '3' => {
               'INTERNALDATE' => '23-Sep-2002 09:16:51 +0000',
               'RFC822.SIZE' => '134314',
           }
  };

En soi, cette méthode peut être utile pour des tâches comme l'obtention de la taille de chaque message d'un dossier. Elle émet une commande et reçoit une réponse (potentiellement longue !) du serveur.

Si la requête de récupération amène le serveur à retourner des données dans une liste entre parenthèses, les données à l'intérieur de la liste entre parenthèses peuvent être échappées via la méthode Escape(). Utilisez la méthode Unescape() pour retrouver les valeurs brutes dans ce cas.

flags

Exemple :

my $flags = $imap->flags($msgid)
  or die "flags failed: $@\n";

La méthode flags implémente la commande client IMAP FETCH pour lister les drapeaux d'un seul message. Elle accepte un argument, un numéro de séquence de message (ou un UID de message, si le paramètre "Uid" est vrai), et retourne un tableau (ou une référence à un tableau, si appelée dans un contexte scalaire) listant les drapeaux qui ont été définis. Les noms de drapeaux sont fournis avec des antislashs en préfixe.

Depuis la version 1.11, vous pouvez fournir soit une liste d'identifiants de messages, soit une référence à un tableau d'identifiants de messages (ce qui signifie soit un numéro de séquence, si le paramètre Uid est faux, soit des UIDs de message, si le paramètre Uid est vrai) au lieu de fournir un seul numéro de séquence de message ou un seul UID. Si vous le faites, la valeur de retour ne sera pas un tableau ou une référence de tableau ; ce sera plutôt une référence de table de hachage, chaque clé étant un numéro de séquence de message (ou un UID) et chaque valeur étant une référence à un tableau de drapeaux définis pour ce message.

Par exemple, si vous voulez afficher les drapeaux de chaque message dans le dossier où vous stockez vos e-mails liés à vos plans de domination mondiale, vous pourriez faire quelque chose comme ceci :

use Mail::IMAPClient;
my $imap = Mail::IMAPClient->new(
    Server   => $imaphost,
    User     => $login,
    Password => $pass,
    Uid      => 1,        # optionnel
);
$imap->select($folder);
# obtenir les drapeaux de chaque message dans mon dossier 'World Domination'
$flaghash = $imap->flags( scalar( $imap->search("ALL") ) );
# parcourir les clés triées de la table de hachage pour imprimer les résultats :
for my $k ( sort { $flaghash->{$a} <=> $flaghash->{$b} } keys %$flaghash ) {
    # imprimer : Message 1: \Flag1, \Flag2, \Flag3
    print "Message $k:\t", join( ", ", @{$flaghash->{$k}} ), "\n";
}

folders

Exemple :

$imap->folders or die "Could not list folders: $@\n";

La méthode folders retourne un tableau listant les dossiers disponibles. Elle ne réussira que si l'objet est dans les états Authenticated ou Selected.

La méthode folders accepte un argument optionnel, qui est un préfixe. Si un préfixe est fourni à la méthode folders, seuls les dossiers commençant par ce préfixe seront retournés.

Par exemple :

print join( ", ", $imap->folders ), ".\n";
# Imprime :
# INBOX, Sent, Projects, Projects/Completed, Projects/Ongoing, Projects Software.
print join( ", ", $imap->folders("Projects") ), ".\n";
# Imprime :
# Projects, Projects/Completed, Projects/Ongoing, Projects Software.
print join( ", ", $imap->folders("Projects" . $imap->separator) ), ".\n";
# Imprime :
# Projects/Completed, Projects/Ongoing

Veuillez noter que la documentation suggérait précédemment que si vous voulez simplement lister les sous-dossiers d'un dossier (et non le dossier lui-même), vous devez inclure le caractère séparateur de hiérarchie (tel que retourné par la méthode "separator"). Cependant, cela ne correspond pas au comportement de l'implémentation existante, vous devrez donc exclure manuellement le dossier parent des résultats.

folders_hash

my @fhashes = $imap->folders_hash
  or die "Could not get list of folder hashes.\n";

La méthode folders_hash accepte un argument optionnel, qui est un préfixe. Si un préfixe est fourni à la méthode folders_hash, seuls les dossiers commençant par ce préfixe seront retournés.

Un tableau (référencé) de tables de hachage est retourné, contenant des informations sur les dossiers demandés. Chaque table de hachage contient trois clés (name, attrs, delim) et ressemble à ceci :

{
  name  => 'Mail/Box/Name',
  attrs => [ '\Marked', '\HasNoChildren' ],
  delim => '/',
}

Les serveurs IMAP implémentant la RFC6154 retournent des attributs à utiliser pour identifier les boîtes aux lettres spéciales (dossiers).

my $sattr_re = /\A\\(?:All|Archive|Drafts|Flagged|Junk|Sent|Trash)\Z/;
foreach my $fhash (@fhashes) {
    next unless defined $fhash->{name};
    my @special = grep { $sattr_re } @{ $fhash->{attrs} };
    print("special: $fhash->{name} : @special\n") if (@special);
}

has_capability

Exemple :

my $has_feature = $imap->has_capability($feature)
  or die "Impossible de faire has_capability($feature): $@\n";

Retourne :

"undef"
Si l'appel sous la couche "capability" échoue, retourne "undef".
"" ou "()"
Si le serveur ne possède pas la capacité demandée, retourne une chaîne vide ("" en contexte scalaire) ou une liste vide ("()" en contexte liste).
une valeur vraie
Si le serveur possède la capacité demandée, retourne une valeur vraie. La valeur vraie dépend du résultat du serveur pour la capacité demandée. La valeur est retournée comme une référence à un tableau en contexte scalaire ou un tableau en contexte liste. Les données retournées sont utiles pour mieux comprendre les capacités spécifiques. Par exemple, considérez l'exemple de réponse CAPABILITY du serveur suivant : 
* CAPABILITY IMAP4rev1 SORT SORT=DISPLAY I18NLEVEL=1 AUTH=PLAIN AUTH=XTEST

Les résultats sont retournés comme indiqué par les commentaires à la fin :

$c = $imap->has_capability("IMAP4rev1");    # [ "IMAP4rev1" ]
@c = $imap->has_capability("IMAP4rev1");    # ( "IMAP4rev1" )
$c = $imap->has_capability("SORT");         # [ "DISPLAY" ]
@c = $imap->has_capability("SORT=DISPLAY"); # ( "SORT=DISPLAY" )
$c = $imap->has_capability("AUTH");         # [ "PLAIN", "XTEST" ]
@c = $imap->has_capability("AUTH");         # ( "PLAIN", "XTEST" )
$c = $imap->has_capability("AUTH=XTEST");   # [ "AUTH=XTEST" ]
@c = $imap->has_capability("AUTH=XTEST");   # ( "AUTH=XTEST" )
$c = $imap->has_capability("AUTH=NADA");    # ''
@c = $imap->has_capability("AUTH=NADA");    # ()
$c = $imap->has_capability("NADA");         # ''
@c = $imap->has_capability("NADA");         # ()

idle

Exemple :

my $tag = $imap->idle or warn "idle a échoué: $@\n";
doSomethingA();
my $idlemsgs = $imap->idle_data() or warn "idle_data erreur: $@\n";
doSomethingB();
my $results = $imap->done($tag) or warn "Erreur de done: $@\n";

La méthode idle envoie au serveur IMAP que le client est prêt à accepter des messages de mise à jour de dossier (dans le dossier sélectionné) sans qu'on les lui demande. Cette méthode n'est valide que sur les serveurs qui supportent l'extension IMAP IDLE, voir RFC2177 pour plus de détails.

La méthode idle n'accepte aucun argument et retourne le tag (identifiant) envoyé par le client pour cette commande. Ce tag doit être fourni comme argument à la fonction done lorsque la commande IDLE est terminée.

En cas d'erreur, retourne "undef" et établit "LastError".

La méthode idle_data peut être utilisée une fois que la commande idle a réussi. Cependant, vous ne pouvez pas appeler d'opérations sur le dossier avant que la commande idle ne soit terminée en appelant done. Ne pas le faire entraînera une erreur et la commande idle sera généralement terminée par le serveur.

Voir aussi idle_data et done.

idle_data

Utilisation :

# un délai optionnel en secondes peut être spécifié
$imap->idle_data( [$timeout] )

Exemple :

my $tag = $imap->idle or warn "idle a échoué: $@\n";
doSomethingA();
my $idlemsgs = $imap->idle_data() or warn "idle_data erreur: $@\n";
doSomethingB();
my $results = $imap->done($tag) or warn "Erreur de done: $@\n";

La méthode idle_data peut être utilisée pour accepter tout message de mise à jour de dossier sans sollicitation qui aurait été envoyé par le serveur pendant une commande idle. Cette méthode n'envoie aucune commande au serveur, elle attend simplement et retourne les données du serveur à l'appelant.

La méthode idle_data accepte un argument optionnel $timeout et retourne une liste (ou une référence à une liste si appelée en contexte scalaire) des messages du serveur.

Par défaut, un délai de 0 seconde (non bloquant) est utilisé. Internement, le délai est passé à select dans perlfunc. Le délai contrôle combien de temps l'appel à select sera bloqué s'il n'y a pas de messages en attente de lecture depuis le serveur.

En cas d'erreur, retourne "undef" et établit "LastError".

Voir aussi imap et done.

Note de version : la méthode a été ajoutée dans Mail::IMAPClient 3.23. Attention : cette méthode est considérée comme expérimentale et l'interface/la présentation pourrait changer dans les futures versions.

imap4rev1

Exemple :

$imap->imap4rev1 or die "Impossible d'effectuer imap4rev1: $@\n";

Retourne vrai si le serveur IMAP auquel l'objet IMAPClient est connecté possède la capacité IMAP4REV1. Si le serveur n'a pas la capacité, retourne une chaîne vide (""), et si l'appel sous la couche capability échoue, retourne "undef".

internaldate

Exemple :

my $msg_internal_date = $imap->internaldate($msgid)
  or die "internaldate a échoué: $@\n";

La méthode internaldate accepte un argument, un identifiant de message (ou un UID si le paramètre Uid est vrai), et retourne la date interne du message ou "undef" si l'appel échoue ou si la date interne n'est pas retournée.

get_bodystructure

Exemple :

my $bodyStructObject = $imap->get_bodystructure($msgid)
  or die "Impossible de récupérer get_bodystructure: $@\n";

La méthode get_bodystructure accepte un argument, un numéro de séquence de message ou, si le paramètre Uid est vrai, un UID de message. Elle récupère la structure du corps du message et retourne un objet Mail::IMAPClient::BodyStructure pour le message.

get_envelope

Exemple :

my $envObject = $imap->get_envelope(@args)
  or die "Impossible de récupérer get_envelope: $@\n";

La méthode get_envelope accepte un argument, un numéro de séquence de message ou, si le paramètre Uid est vrai, un UID de message. Elle récupère l'en-tête du message et retourne un objet Mail::IMAPClient::BodyStructure::Envelope pour l'en-tête, qui n'est qu'une version analysée du message dans un objet Perl.

Pour plus d'informations sur l'utilisation de cet objet après l'avoir obtenu, consultez la documentation de Mail::IMAPClient::BodyStructure. (Bien qu'à l'heure actuelle, il n'y ait pas de documentation séparée pour Mail::IMAPClient::BodyStructure::Envelope).

getacl

Exemple :

my $hash = $imap->getacl($folder)
  or die "Impossible de récupérer getacl pour $folder: $@\n";

La méthode getacl accepte un argument, le nom d'un dossier. Si aucun argument n'est fourni, le dossier sélectionné est utilisé par défaut. Elle retourne une référence à un hash. Les clés du hash sont les identifiants des utilisateurs qui ont accès au dossier, et les valeurs de chaque élément sont les permissions pour cet utilisateur. Les permissions sont affichées sous forme de chaîne, triées comme retournées par le serveur, sans espace ni point-virgule entre elles.

get_header

Exemple :

my $messageId = $imap->get_header( $msg, "Message-Id" );

La méthode get_header accepte deux arguments, un numéro de séquence de message ou, si le paramètre Uid est vrai, un UID de message. Elle retourne la valeur de l'en-tête demandé dans le message dont le numéro de séquence ou l'UID est spécifié comme premier argument. Si la valeur ne peut pas être trouvée, elle retourne "undef" ; si plusieurs valeurs sont trouvées, elle retourne la première. La valeur retournée est toujours un scalaire. La méthode get_header utilise une correspondance insensible à la casse pour récupérer la valeur, vous n'aurez donc pas à vous soucier de la casse du second argument.

La méthode get_header est un raccourci pour :

my $messageId = $imap->parse_headers($msg,"Subject")->{"Subject"}[0];

getquotaroot

Exemple :

my $results = $imap->getquotaroot($mailboxname)
  or die "Impossible de récupérer getquotaroot pour $mailboxname: $@\n";

La méthode getquotaroot implémente la commande RFC2087 GETQUOTAROOT. Le $mailboxname par défaut est INBOX si aucun argument n'est fourni.

En cas d'erreur, retourne "undef", sinon retourne les Results. Les résultats doivent inclure la réponse non étiquetée QUOTAROOT du serveur ainsi que l'utilisation et les limites des ressources QUOTAROOT dans une réponse non étiquetée QUOTA.

Voir aussi RFC2087, getquota, setquota, quota et quota_usage.

getquota

Exemple :

my $results = $imap->getquota($quotaroot)
  or die "Impossible de récupérer getquota pour $quotaroot: $@\n";

La méthode getquota implémente la commande RFC2087 GETQUOTA. Le $quotaroot par défaut est user/User si aucun argument n'est fourni.

Cette méthode est utilisée pour obtenir des informations sur la limite et l'utilisation des ressources du dossier spécifié.

quota

Exemple :

my $limit = $imap->quota($quotaroot)
  or die "Could not get quota limit for $quotaroot: $@\n";

La méthode quota prend les résultats de "Results" de "getquota" et analyse la limite de "STORAGE" renvoyée par le serveur. Le $quotaroot se comporte comme "INBOX" par défaut si aucun argument n'est fourni.

En cas d'erreur, "undef" est renvoyé, sinon la limite de "STORAGE" fournie par le serveur est renvoyée.

Voir aussi RFC2087, "getquotaroot", "getquota" et "quota".

quota_usage

Exemple :

my $usage = $imap->quota_usage($quotaroot)
  or die "Could not get quota usage for $quotaroot: $@\n";

La méthode quota_usage prend les résultats de "Results" de "getquota" et analyse l'utilisation de "STORAGE" renvoyée par le serveur. Le $quotaroot se comporte comme "INBOX" par défaut si aucun argument n'est fourni.

En cas d'erreur, "undef" est renvoyé, sinon l'utilisation de "STORAGE" fournie par le serveur est renvoyée.

Voir aussi RFC2087, "getquotaroot", "getquota" et "quota".

setquota

Exemple :

my $results = $imap->setquota( $quotaroot, $resource, $limit )
  or die "Could not setquota for $quotaroot: $@\n";

La méthode setquota implémente les commandes RFC2087 "SETQUOTA". Elle accepte plusieurs paires de $resource et $limit comme arguments. Le $quotaroot se comporte comme "user/User" par défaut s'il n'est pas défini.

En cas d'erreur, "undef" est renvoyé, sinon les "Results" sont renvoyés.

Voir aussi RFC2087, "getquotaroot" et "getquota".

is_parent

Exemple :

my $hasKids = $imap->is_parent($folder);

La méthode is_parent accepte un argument, le nom d'un dossier. Elle renvoie une valeur indiquant si le dossier a des enfants. La valeur renvoyée est :

1 (ou un nombre positif)
La propriété "\HasChildren" est définie, indiquant que le dossier a des enfants.
0 (zéro)
La propriété "\HasNoChildren" est définie, indiquant que le dossier n'a pas d'enfants pour le moment.
"undef"
La propriété "\NoInferiors" est définie, indiquant que le dossier ne permet pas d'avoir d'enfants.

Exemple :

my $parenthood = $imap->is_parent($folder);
if ( defined($parenthood) ) {
    if ($parenthood) {
        print "$folder has children.\n";
    }
    else {
        print "$folder is permitted children, but has none.\n";
    }
}
else {
    print "$folder is not permitted to have children.\n";
}

list

Exemple :

my @raw_output = $imap->list(@args)
  or die "Could not list: $@\n";

La méthode list implémente les commandes IMAP LIST client. Les arguments sont passés au serveur tels quels, séparés par des espaces. Si aucun argument n'est fourni, la commande par défaut "tag LIST "" '*'" est émise.

La méthode list renvoie un tableau (ou une référence à un tableau, si appelée dans un contexte scalaire). Le tableau est la sortie non modifiée de la commande LIST. (Si vous souhaitez une sortie modifiée, consultez la fonction "folders" plus haut.)

En cas d'erreur, "undef" est renvoyé. Assurez-vous de le vérifier.

listrights

Exemple :

$imap->listrights( $folder, $user )
  or die "Could not listrights: $@\n";

La méthode listrights implémente la commande IMAP LISTRIGHTS client (RFC2086). Elle accepte deux arguments, le nom du dossier et un identifiant d'utilisateur. Elle renvoie les droits que l'utilisateur possède sur le dossier spécifié. Si elle est appelée dans un contexte scalaire, les droits sont renvoyés sous forme de chaînes, sans point ni espace ni autre fioriture. Si elle est appelée dans un contexte de tableau, listrights renvoie un tableau où chaque élément est un droit.

login

Exemple :

$imap->login or die "Could not login: $@\n";

La méthode login implémente la commande IMAP LOGIN client pour se connecter au serveur. Si le paramètre Authmechanism est défini à autre chose que 'LOGIN', une authentification en clair est tentée. Les paramètres User et Password doivent être définis avant d'appeler login. En cas de succès, un objet Mail::IMAPClient avec le statut Authenticated est renvoyé. En cas d'échec, undef est renvoyé et $@ est défini. Les fonctions new, connect et Socket peuvent appeler login automatiquement, selon la documentation de chaque méthode.

Note : Le paramètre "Compress" est utilisé pour appeler automatiquement la méthode compress après une authentification réussie.

Voir aussi "proxyauth" et "Proxy" pour des informations supplémentaires sur l'authentification avec un serveur via SASL et/ou PROXYAUTH.

proxyauth

Exemple :

$imap->login( "admin", "password" );
$imap->proxyauth("someuser");

La méthode proxyauth implémente la commande IMAP PROXYAUTH client. La commande est utilisée pour permettre à un utilisateur administratif de s'identifier comme un autre utilisateur.

logout

Exemple :

$imap->logout or die "Could not logout: $@\n";

La méthode logout implémente la commande LOGOUT IMAP client. Cette méthode demande au serveur de terminer la connexion et le client IMAPClient entre dans l'état Unconnected. Cette méthode ne détruit pas l'objet IMAPClient, de sorte que les méthodes connect et login peuvent être utilisées pour établir une nouvelle session IMAP.

Note : La section RFC2683 3.1.2 (Connexions sévères) recommande le comportement attendu des clients IMAP. La décision quant au comportement préféré incombe à l'utilisateur.

Note : La documentation (de la version 2.x à 3.23) indiquait que l'objet Mail::IMAPClient tenterait de fermer la connexion au serveur lors de DESTROY si l'objet était dans l'état Connected. Cette documentation semblait incorrecte depuis au moins la version 2.2.2 et potentiellement des versions antérieures.

lsub

Exemple :

$imap->lsub(@args) or die "Could not lsub: $@\n";

La méthode lsub implémente la commande IMAP LSUB client. Les arguments sont passés au serveur tels quels, séparés par des espaces. Si aucun argument n'est fourni, la commande par défaut "tag LSUB "" '*'" est émise.

La méthode lsub renvoie un tableau (ou une référence à un tableau, si appelée dans un contexte scalaire). Le tableau est la sortie non modifiée de la commande LSUB. Si vous souhaitez un tableau de dossiers auxquels vous êtes abonné, consultez la fonction "subscribed" plus bas.

mark

Exemple :

$imap->mark(@msgs) or die "Could not mark: $@\n";

La méthode mark accepte une liste d'un ou plusieurs numéros de message, ou une référence à un tableau d'un ou plusieurs numéros de message comme argument. Elle définit ensuite le drapeau "\Flagged" pour ces messages. Évidemment, si le paramètre "Uid" est défini sur une valeur vraie, ces numéros de message doivent être uniques.

Note : Écrire "$imap->see(@msgs)" est un raccourci pour spécifier "$imap->set_flag("Flagged",@msgs)".

Massage

Exemple :

$imap->search(HEADER => 'Message-id' => $imap->Massage($msg_id,1));

AVERTISSEMENT : Cette méthode pourrait être obsolète à l'avenir, envisagez d'utiliser "Quote" à la place de cette méthode.

La méthode Massage accepte une valeur comme argument et, éventuellement, une seconde valeur qui, si elle est vraie, indique que le premier argument n'est pas le nom d'un dossier existant.

AVERTISSEMENT : Si le premier argument commence et se termine par des guillemets doubles, ceux-ci seront supprimés, sauf si le second argument est évalué à vrai.

Renvoie son argument sous forme de chaîne correctement échappée ou de chaîne littérale.

Note : Vous devriez l'utiliser rarement dans les noms de dossiers, car les méthodes qui acceptent des noms de dossiers en argument appellent Quote pour vous.

message_count

Exemple :

my $msgcount = $imap->message_count($folder);
defined($msgcount) or die "message_count failed: $@\n";

La méthode message_count accepte le nom d'un dossier comme argument et renvoie le nombre de messages dans ce dossier. Elle appelle en interne la méthode "status" (voir ci-dessus) et analyse les résultats pour obtenir le nombre de messages. Si aucun argument n'est fourni à message_count, elle renvoie le nombre de messages dans le dossier actuellement sélectionné (en supposant que vous avez utilisé select).

message_string

Exemple :

my $string = $imap->message_string($msgid)
  or die "message_string failed: $@\n";

La méthode message_string accepte en argument un numéro de message (ou un numéro UID de message si le paramètre Uid est vrai) et renvoie le message sous forme de chaîne de caractères. La valeur renvoyée contient le message complet dans une variable scalaire, y compris les en-têtes du message. Note : l'utilisation de cette méthode marquera le message avec le drapeau \Seen par effet secondaire, à moins que le paramètre Peek ne soit vrai.

message_to_file

Exemple :

$imap->message_to_file( $file, @msgs )
  or die "message_to_file failed: $@\n";

La méthode message_to_file accepte un nom de fichier ou un descripteur de fichier et un ou plusieurs numéros de message (ou numéros UID de message si le paramètre Uid est vrai) en tant qu'arguments et place les chaînes de messages (y compris les en-têtes RFC822) dans le fichier spécifié par le premier argument (ou imprime les résultats dans le descripteur de fichier si un descripteur de fichier est passé). La valeur renvoyée est vraie en cas de succès et "undef" en cas d'échec.

Si le premier argument est une référence, il est supposé être un descripteur de fichier ouvert et ne sera pas fermé lorsque la méthode se termine. S'il s'agit d'un fichier, il sera ouvert en mode ajout (append), écrit, puis fermé.

Note : l'utilisation de cette méthode marquera le message avec le drapeau \Seen par effet secondaire. Cependant, vous pouvez utiliser la méthode deny_seeing pour le rétablir, ou définir le paramètre Peek à une valeur vraie pour éviter de définir le drapeau \Seen dans tous les cas.

Cette méthode fonctionne en faisant certaines hypothèses sur le comportement du serveur, notamment que le texte du message sera renvoyé sous forme de chaîne littérale, mais rien de plus. Si vous avez une meilleure idée, je serais ravi de l'entendre.

message_uid

Exemple :

my $msg_uid = $imap->message_uid($msg_seq_no)
  or die "Could not get uid for $msg_seq_no: $@\n";

La méthode message_uid accepte en argument un numéro de message (ou un numéro UID de message si le paramètre Uid est vrai) et renvoie le numéro UID du message. Oui, si Uid est vrai, elle utilisera la commande IMAP UID FETCH UID du client pour obtenir et renvoyer le même argument que vous avez fourni. C'est une fonction IMAP, donc ne vous plaignez pas à moi.

messages

Exemple :

# Get a list of messages in the current folder:
my @msgs = $imap->messages or warn "Could not list messages\n";
# Get a reference to an array of messages in the current folder:
my $msgs = $imap->messages or die "Get messages failed: $@\n";

Lorsqu'elle est appelée dans un contexte de liste, la méthode messages renvoie une liste de tous les messages du dossier actuellement sélectionné. Lorsqu'elle est appelée dans un contexte scalaire, elle renvoie une référence à un tableau contenant tous les messages du dossier. C'est équivalent à spécifier "$imap->"search"("ALL")").

Si aucun message n'est trouvé, une liste vide est renvoyée. En cas d'erreur, "undef" est renvoyé et "LastError" est défini.

migrate

Exemple :

$imap_src->migrate( $imap_dest, "ALL", $targetFolder )
  or die "Could not migrate: ", $imap_src->LastError;

La méthode migrate copie les messages spécifiés depuis le dossier actuellement sélectionné vers un autre objet de session Mail::IMAPClient. Elle nécessite les arguments suivants :

1.
une référence à l'objet Mail::IMAPClient de destination (pas l'objet appelant, qui est connecté au compte source) ;
2.
les messages à copier, spécifiés comme a) un numéro de message (ou un numéro UID de message si le paramètre Uid est vrai), b) une référence à un tableau de numéros de message (ou de numéros UID de message si le paramètre Uid est vrai), ou c) la chaîne spéciale "ALL", qui est un raccourci pour les résultats de ""search"("ALL")" ;
3.
le nom du dossier de destination dans la boîte aux lettres de destination où les messages seront reçus. Si cet argument n'est pas fourni ou est undef, le dossier actuellement sélectionné dans l'objet appelant sera utilisé. Le dossier de destination sera créé automatiquement s'il n'existe pas.

L'objet Mail::IMAPClient de destination ($imap_dest) doit être différent de l'objet source ($imap_src).

Cette méthode ne tente pas de minimiser l'utilisation de la mémoire. Elle pourrait être améliorée à l'avenir (facultativement) en écrivant les données des messages dans un fichier temporaire pour éviter de stocker le message complet en mémoire.

Pour contourner les temps de connexion réseau potentiellement longs pour les gros messages, envisagez de définir "Reconnectretry" à 1 sur $imap_src et $imap_dest).

Voir aussi "Supportedflags").

move

Exemple :

my $newUid = $imap->move( $newFolder, $oldUid )
  or die "Could not move: $@\n";
$imap->expunge;

La méthode move déplace les messages du dossier actuellement sélectionné vers le dossier spécifié dans le premier argument de la méthode move. Si le paramètre Uid n'est pas vrai, les arguments restants doivent être :

a)
un numéro de message ;
b)
une liste de numéros de message séparés par des virgules, ou
c)
une référence à un tableau de numéros de message.

Si le paramètre Uid est vrai, les arguments doivent être :

a)
un numéro UID de message ;
b)
une liste de numéros UID de message séparés par des virgules, ou
c)
une référence à un tableau de numéros UID de message.

Si le dossier de destination n'existe pas, il sera créé.

Si le déplacement réussit, il renvoie une valeur vraie. De plus, si l'objet Mail::IMAPClient est connecté à un serveur qui prend en charge la capacité UIDPLUS, la valeur vraie sera la liste des UID des nouveaux messages, séparés par des virgules. La liste est affichée dans l'ordre où les messages ont été déplacés, ce qui devrait correspondre à l'ordre des numéros UID fournis par l'appelant.

Si le déplacement échoue, move renvoie "undef".

Note : un déplacement consiste en réalité à copier le message dans le nouveau dossier, puis à définir le drapeau \Deleted. Pour supprimer réellement le message d'origine, vous devez ensuite exécuter expunge (ou close).

namespace

Exemple :

my $refs = $imap->namespace
  or die "namespace failed: $@\n";

La méthode namespace exécute la commande IMAP NAMESPACE (telle que définie dans la RFC 2342). Lorsqu'elle est appelée dans un contexte de liste, elle renvoie une liste de trois références. Chaque référence ressemble à ceci :

[
  [ $prefix_1, $separator_1 ],
  [ $prefix_2, $separator_2 ],
  [ $prefix_n, $separator_n ],
]

La première référence fournit une liste de préfixes et de caractères séparateurs pour les espaces de noms personnels disponibles. La deuxième référence fournit une liste de préfixes et de caractères séparateurs pour les espaces partagés disponibles. La troisième référence fournit une liste de préfixes et de caractères séparateurs pour les espaces publics disponibles.

Si l'un des trois espaces n'est pas disponible sur le serveur actuel, "undef" est renvoyé à la place d'une référence. Par exemple, si les dossiers partagés n'étaient pas pris en charge mais que les espaces personnels et publics étaient disponibles (un pour chaque espace), la valeur renvoyée pourrait ressembler à ceci :

[ [ "", "/" ] , undef, [ "#news", "." ] ];

Si la méthode namespace est appelée dans un contexte scalaire, elle renvoie une référence à la liste mentionnée ci-dessus, créant ainsi une structure qui imprimerait quelque chose comme :

$VAR1 = [
    [
        [ $user_prefix_1, $user_separator_1 ],
        [ $user_prefix_2, $user_separator_2 ],
        [ $user_prefix_n, $user_separator_n ],
    ],                    # ou undef
    [
        [ $shared_prefix_1, $shared_separator_1 ],
        [ $shared_prefix_2, $shared_separator_2 ],
        [ $shared_prefix_n, $shared_separator_n ],
    ],                    # ou undef
    [
        [ $public_prefix_1, $public_separator_1 ],
        [ $public_prefix_2, $public_separator_2 ],
        [ $public_prefix_n, $public_separator_n ],
    ],                    # ou undef
];

on

Exemple :

my @msgs = $imap->on($Rfc3501_date)
  or warn "Could not find messages sent on $Rfc3501_date: $@\n";

La méthode on fonctionne de manière similaire à la méthode since, ci-dessous, sauf qu'elle renvoie une liste de messages dont les dates internes sont égales à la date fournie en argument.

parse_headers

Exemple :

my $hashref = $imap->parse_headers( $msg || \@msgs, "Date", "Subject" )
  or die "Could not parse_headers: $@\n";

La méthode parse_headers accepte en argument un numéro de message et une liste de champs d'en-tête. Elle renvoie une référence à un hash où les clés sont les noms des champs d'en-tête (sans le deux-points) et les valeurs sont les valeurs correspondantes.

parse_headers

L'en-tête Received est probablement la principale raison pour laquelle la méthode parse_headers crée une table de listes plutôt qu'une table de valeurs.

Si le deuxième argument de parse_headers est 'ALL' ou s'il est omis, tous les en-têtes disponibles sont inclus dans la table de listes retournée.

Si vous n'êtes pas émotionnellement préparé à gérer une table de listes, vous pouvez toujours appeler vous-même la méthode "fetch" avec les paramètres appropriés et analyser les données comme vous le souhaitez. Si le paramètre "Uid" est vrai, le premier argument sera traité comme un UID de message. Si le premier argument est une référence à un tableau de numéros de séquence de messages (ou d'UID si "Uid" est vrai), alors parse_headers sera exécuté sur chaque message du tableau. Dans ce cas, la valeur de retour est une table, dans laquelle la clé est le numéro de séquence du message (ou l'UID) et la valeur est une référence à une table comme décrit ci-dessus.

Un exemple d'utilisation de parse_headers pour imprimer la date et l'objet de chaque message dans votre dossier de démonstration pourrait ressembler à ceci :

use Mail::IMAPClient;
my $imap = Mail::IMAPClient->new(
    Server => $imaphost, User => $login, Password => $pass, Uid => 1
);
$imap->select("demo");
my $msgs = $imap->search("ALL");
for my $h (
 # obtenir l'objet et la date de chaque message dans le dossier "demo"
 # le premier argument est une référence à un tableau listant tous les messages du
 # dossier (ce qui est retourné par la méthode $imap->search("ALL")
 # lorsqu'elle est appelée en contexte scalaire) et les arguments restants
 # sont les champs à analyser. La clé est le numéro du message, dont
 # dans ce cas, nous n'avons pas à nous soucier :
  values %{ $imap->parse_headers( $msgs , "Subject", "Date") } )
{
    # $h est la valeur de chaque élément de la référence de table retournée
    # par parse_headers, et $h est aussi une référence à une table.
    # Nous imprimerons seulement la première occurrence de chaque champ car
    # nous ne nous attendons pas à plus d'une ligne Date: ou Subject: par
    # message.
    print map { "$_:\t$h->{$_}[0]\n"} keys %$h;
}

envoydepuis

Exemple:

  or warn "Impossible de trouver des messages envoyés depuis le $Rfc3501_date : $@\n";

La méthode envoydepuis accepte un argument, une date au format epoch timestamp (secondes depuis le 1/1/1970, ou tel que produit par "time" dans perlfunc et accepté par "localtime" dans perlfunc) ou au format date_text tel que défini dans RFC3501 (jj-Mmm-aaaa, où Mmm est l'abréviation en anglais du mois). La méthode recherche les messages envoyés depuis le jour dont la date est spécifiée comme argument. Elle utilise l'en-tête RFC822 Date: pour déterminer la date envoydepuis (en réalité, le serveur utilise l'en-tête Date: ; ce document suppose que la date provient de l'en-tête Date: car c'est ce que le RFC3501 indique).

Le protocole IMAP ne prend pas en charge les recherches avec une granularité plus fine qu'un jour, donc je ne le fais pas non plus. D'un autre côté, la seule chose que je vérifie dans un argument date_text est qu'il corresponde au motif "\d\d-\D\D\D-\d\d\d\d" (en notant l'absence d'ancres), donc si votre serveur autorise l'ajout de quelque chose de supplémentaire à une chaîne date_text, alors Mail::IMAPClient le fera aussi.

Si vous le souhaitez, vous pouvez utiliser la méthode "Rfc3501_date" pour convertir du temps epoch (tel que retourné par "time") en une spécification de date RFC3501.

sort

Exemple :

my @msgs = $imap->sort(@args);
warn "Erreur lors du tri : $@\n" if $@;

La méthode sort est identique à la méthode search, à une seule différence près. Elle implémente l'extension SORT décrite dans https://tools.ietf.org/html/rfc5256. Il est prudent d'utiliser la méthode has_capability pour vérifier que la capacité SORT est disponible sur votre serveur avant de tenter d'utiliser la méthode sort. Si vous oubliez de vérifier et que vous vous connectez à un serveur qui n'a pas la capacité SORT, sort renverra undef. LastError indiquera alors BAD. Si votre serveur ne prend pas en charge la capacité SORT, vous devrez utiliser search et trier les résultats vous-même.

Le premier argument de la méthode sort est une liste de critères de tri séparés par des espaces. Le brouillon Internet décrivant SORT exige que cette liste soit entre parenthèses, même s'il n'y a qu'un seul critère de tri. Si vous omettez les parenthèses, la méthode sort les ajoutera. Mais vous devez les omettre toutes les deux ou aucune. Ce n'est pas CMS exécuté sous VM !

Le deuxième argument est un jeu de caractères à utiliser pour le tri. Différents jeux de caractères entraînent des tris différents, cet argument est donc important. Comme tous les serveurs doivent prendre en charge UTF-8 et US-ASCII s'ils prennent en charge la capacité SORT, vous pouvez utiliser l'un d'entre eux si vous n'avez pas de jeu de caractères préféré.

Les autres arguments sont des critères de recherche, tels que vous les fourniriez à la méthode search. Ceux-ci sont tous documentés dans la RFC3501. Si vous souhaitez simplement obtenir tous les messages du dossier actuellement sélectionné, triés, utilisez ALL comme seul critère de recherche.

La méthode sort renvoie un tableau contenant les numéros de séquence des messages qui ont passé les critères de tri de la commande IMAP client SORT. Si le paramètre Uid est vrai, le tableau contiendra les numéros d'UID des messages. Si sort est appelée dans un contexte scalaire, un pointeur vers le tableau est passé, pas le tableau lui-même. Les numéros de séquence ou les identifiants uniques sont triés selon les critères de tri spécifiés. Les critères de tri sont imbriqués dans l'ordre spécifié ; c'est-à-dire que les éléments sont d'abord triés selon le premier critère, puis, au sein du premier critère, selon le deuxième critère, et ainsi de suite.

La méthode sort effacera $@ avant de tenter l'opération SORT, tout comme la méthode search.

  or die "Impossible de tag_and_run : $@\n";

La méthode tag_and_run accepte un ou deux arguments. Le premier argument est une chaîne contenant une commande IMAP client sans balise mais avec tous les arguments nécessaires. Le second argument est une chaîne qui, si elle est trouvée, indiquera le succès (sans délimiteurs de modèle). La valeur par défaut est "OK.*".

La méthode tag_and_run préfixera votre chaîne (du premier argument) avec le numéro de transaction suivant et exécutera la commande. Elle renverra un tableau de lignes de sortie de la commande, que vous pourrez analyser selon vos besoins. L'utilisation de cette méthode au lieu de la méthode run (ci-dessus) vous libère de la nécessité de gérer les balises (et de vous soucier des effets secondaires de la nomination de vos balises).

uidexpunge

Exemple :

$imap->uidexpunge(@uids) or die "Impossible de uidexpunge : $@\n";

La méthode uidexpunge implémente la commande IMAP client (extension RFC4315 UIDPLUS) uidexpunge pour supprimer définitivement tous les messages qui ont le flag Deleted défini et dont l'UID est inclus dans la liste des UIDs.

uidexpunge renvoie un tableau ou une référence de tableau (contexte scalaire) des lignes de sortie renvoyées par la commande uidexpunge.

uidexpunge renvoie undef en cas d'échec.

Si le serveur ne prend pas en charge l'extension UIDPLUS, cette méthode renvoie undef.

uidnext

Exemple :

my $nextUid = $imap->uidnext($folder) or die "uidnext échoué : $@\n";

La méthode uidnext accepte un argument, le nom d'un dossier, et renvoie la chaîne numérique qui est le prochain numéro d'UID disponible pour ce dossier.

thread

Exemple :

my $thread = $imap->thread( $algorithm, $charset, @search_args );

La méthode thread accepte zéro à trois arguments. Le premier argument est l'algorithme de tri à utiliser, généralement ORDEREDSUBJECT ou REFERENCES. Le deuxième argument est le jeu de caractères à utiliser, et le troisième est le jeu d'arguments de recherche à utiliser.

Si l'algorithme n'est pas spécifié, REFERENCES sera utilisé par défaut s'il est disponible, ou ORDEREDSUBJECT s'il est disponible. Si aucun de ceux-ci n'est disponible, la méthode thread renvoie undef.

Si le jeu de caractères n'est pas spécifié, UTF-8 sera utilisé par défaut.

Si aucun argument de recherche n'est spécifié, la valeur par défaut est ALL.

Si thread est appelée pour un objet connecté à un serveur qui ne prend pas en charge l'extension THREADS, la méthode thread renvoie "undef".

La méthode threads émettra la commande THREAD telle que définie dans https://tools.ietf.org/html/rfc5256. Elle renvoie un tableau de threads. Chaque élément du tableau est un identifiant de message ou une référence à un autre tableau de (sous-)threads.

Si le paramètre Uid est vrai, les identifiants de message renvoyés dans la structure de threads seront des identifiants de message UID. Sinon, ce seront des numéros de séquence de message.

uidvalidity

Exemple :

my $validity = $imap->uidvalidity($folder)
  or die "uidvalidity échoué : $@\n";

La méthode uidvalidity accepte un argument, le nom d'un dossier, et renvoie la chaîne numérique qui est la valeur de validité de l'identifiant unique pour le dossier.

id='unmark'>unmark

Exemple:

$imap->unmark(@msgs) or die "Impossible de marquer comme non lu : $@\n";

La méthode unmark accepte une liste d'un ou plusieurs numéros de séquence de messages, ou une seule référence à un tableau d'un ou plusieurs numéros de séquence de messages, comme argument(s). Elle désactive ensuite le drapeau \Flagged pour ces message(s). Bien sûr, si le paramètre "Uid" est défini sur une valeur vraie, alors ces numéros de séquence de messages devraient réellement être des identifiants de messages uniques.

Notez que spécifier "$imap->unmark(@msgs)" est juste un raccourci pour spécifier "$imap->unset_flag("Flagged",@msgs)".

Notez également que le drapeau \Flagged n'est qu'un parmi de nombreux drapeaux possibles. C'est un peu déroutant, mais vous devrez vous habituer à l'idée qu'un des drapeaux réservés spécifiés dans la RFC3501 est nommé \Flagged. Ce drapeau n'a pas de signification spécifique ; il signifie ce que le propriétaire de la boîte aux lettres (ou son délégué) veut qu'il signifie lorsqu'il est activé.

unseen

Exemple:

my @unread = $imap->unseen or warn "Impossible de trouver les messages non lus : $@\n";

La méthode unseen effectue une recherche IMAP SEARCH UNSEEN sur le dossier sélectionné et renvoie un tableau des numéros de séquence des messages qui n'ont pas encore été vus (c'est-à-dire dont le drapeau \Seen n'est pas défini). Si le paramètre "Uid" est vrai, un tableau d'identifiants de messages sera renvoyé à la place. Si elle est appelée dans un contexte scalaire, un pointeur vers le tableau (plutôt que le tableau lui-même) sera renvoyé.

unseen_count

Exemple:

foreach my $f ($imap->folders) {
    print "Le dossier $f contient ",
      $imap->unseen_count($f)||0, " messages non lus.\n";
}

La méthode unseen_count accepte le nom d'un dossier comme argument et renvoie le nombre de messages non lus dans ce dossier. Si aucun argument de dossier n'est fourni, elle renvoie le nombre de messages non lus dans le dossier actuellement sélectionné.

unset_flag

Exemple:

$imap->unset_flag( "\Seen", @msgs )
  or die "unset_flag a échoué : $@\n";

La méthode unset_flag accepte le nom d'un drapeau comme premier argument et une liste d'un ou plusieurs numéros de séquence de messages, ou une seule référence à un tableau d'un ou plusieurs numéros de séquence de messages, comme argument(s) suivant(s). Elle désactive ensuite le drapeau spécifié pour ces message(s). Bien sûr, si le paramètre "Uid" est défini sur une valeur vraie, alors ces numéros de séquence de messages devraient être des identifiants de messages uniques, comme vous vous y attendriez.

Autres commandes client IMAP

Jusqu'à la version 2.99, lorsque vous appeliez une méthode qui n'existait pas, elle était automatiquement traduite en un appel IMAP du même nom via un hack AUTOLOAD. Cette "fonctionnalité" a été supprimée pour diverses raisons : les gens faisaient des fautes de frappe dans la casse des noms de méthodes, et le programme semblait toujours fonctionner correctement. De plus, cela bloquait le développement futur de ce module, car les gens ne contribuaient pas leurs extensions privées à l'implémentation du protocole.

copy($msg, $folder)

Copie un message du dossier actuellement sélectionné vers le dossier dont le nom est dans $folder

subscribe($folder)

S'abonner à un dossier

ATTENTION : Encore une fois, n'oubliez pas de guillemeter vos guillemets (ou d'utiliser la méthode "Quote") si vous voulez que les guillemets fassent partie de la chaîne de commande IMAP.

Vous pouvez également utiliser la méthode par défaut pour outre-passer le comportement des méthodes IMAP implémentées en changeant la casse du nom de la méthode, de préférence en majuscules pour ne pas entrer en conflit avec l'espace de noms des méthodes de classe et des méthodes d'accès. Par exemple, si vous ne souhaitez pas le comportement de la méthode "search" (qui renvoie une liste de numéros de messages) mais préférez obtenir un tableau de données brutes de votre opération "search", vous pouvez exécuter l'extrait de code suivant :

my @raw = $imap->SEARCH("SUBJECT","Whatever...");

ce qui est légèrement plus efficace que l'équivalent :

$imap->search("SUBJECT","Whatever...");
my @raw = $imap->Results;

Bien sûr, vous voudrez probablement que les résultats de la recherche soient bien rangés dans une liste pour vous, auquel cas vous pourriez aussi bien utiliser la méthode "search".

Paramètres

Il existe plusieurs paramètres qui influencent le comportement d'un objet IMAPClient. Chacun est défini en spécifiant une paire nom-valeur lors de l'invocation de la méthode new, comme suit :

my $imap = Mail::IMAPClient->new ( parametre  => "valeur",
    parametre2 => "valeur",
    ...
);

Les paramètres peuvent également être définis après qu'un objet a été instancié en utilisant la méthode d'accesseur éponyme du paramètre, comme ceci :

my $imap = Mail::IMAPClient->new;
   $imap->parametre( "valeur");
   $imap->parametre2("valeur");

Les méthodes d'accesseur éponymes peuvent également être utilisées sans arguments pour obtenir la valeur actuelle du paramètre, comme suit :

my $imap = Mail::IMAPClient->new;
   $imap->parametre( "valeur");
   $imap->parametre2("valeur");
  ...    # Un tas de code Perl génial, omis pour la brièveté
my $forgot  = $imap->parametre;
my $forgot2 = $imap->parametre2;

Notez que dans ces exemples, j'utilise 'parametre' et 'parametre2' comme noms de paramètres génériques. L'objet IMAPClient n'a pas réellement de paramètres nommés 'parametre' et 'parametre2'. Au contraire, les paramètres disponibles sont :

Authmechanism

Exemple:

$imap->Authmechanism("CRAM-MD5");
# ou
my $authmech = $imap->Authmechanism();

Si spécifié, le Authmechanism provoque l'utilisation du mécanisme d'authentification spécifié chaque fois que Mail::IMAPClient invoquerait autrement login. Si la valeur spécifiée pour le paramètre Authmechanism n'est pas un mécanisme d'authentification valide pour votre serveur, alors vous ne pourrez jamais vous connecter à nouveau pour le reste de votre script Perl, probablement. Vous voudrez donc peut-être vérifier, comme ceci :

my $authmech = "CRAM-MD5";
$imap->has_capability($authmech) and $imap->Authmechanism($authmech);

Bien sûr, si vous savez que votre serveur prend en charge votre mécanisme d'authentification préféré, vous le savez, vous pouvez alors inclure votre Authmechanism avec votre appel new, comme suit :

my $imap = Mail::IMAPClient->new(
    User    => $user,
    Passord => $passord,
    Server  => $server,
    Authmechanism  => $authmech,
    %etc
);

Si Authmechanism est fourni mais Authcallback ne l'est pas, alors vous feriez mieux de prendre en charge l'un des mécanismes d'authentification que Mail::IMAPClient prend en charge "prêt à l'emploi" (tel que CRAM-MD5).

Authcallback

Exemple:

$imap->Authcallback( \&callback );

Ceci spécifie une fonction de rappel par défaut pour le mécanisme d'authentification par défaut (voir "Authmechanism", ci-dessus). Ensemble, ces deux méthodes remplacent les appels automatiques à login par des appels automatiques qui ressemblent à ceci (en quelque sorte) :

$imap->authenticate($imap->Authmechanism,$imap->Authcallback);

Si Authmechanism est fourni mais Authcallback ne l'est pas, alors vous feriez mieux de prendre en charge l'un des mécanismes d'authentification que Mail::IMAPClient prend en charge "prêt à l'emploi" (tel que CRAM-MD5).

Authuser

Le paramètre Authuser est utilisé par le mécanisme d'authentification DIGEST-MD5.

Typiquement, lorsque vous vous authentifiez, le nom d'utilisateur spécifié dans le paramètre User est utilisé. Cependant, lors de l'utilisation du Authmechanism DIGEST-MD5, le Authuser peut être utilisé pour spécifier un nom d'utilisateur différent pour la connexion.

Cela peut être utile pour marquer des messages comme lus pour le Authuser si vous ne connaissez pas le mot de passe de l'utilisateur, car l'état de lecture est souvent un état par utilisateur.

Buffer

Exemple:

$Buffer = $imap->Buffer();
# ou:
$imap->Buffer($new_value);

Le paramètre Buffer définit la taille d'un bloc d'E/S. Il est ignoré sauf si "Fast_io", ci-dessous, est défini sur une valeur vraie (par défaut), ou sauf si vous utilisez la méthode "migrate". Sa valeur devrait être le nombre d'octets à tenter de lire en une seule opération d'E/S. La valeur par défaut est 4096.

Lors de l'utilisation de la méthode "migrate", vous pouvez souvent obtenir des améliorations spectaculaires de débit en augmentant ce nombre. Cependant, le faire entraîne également un coût en mémoire, donc s'il est réglé trop haut, vous risquez de perdre tous les avantages de l'algorithme de segmentation de la méthode "migrate". Votre programme peut ainsi se terminer avec une erreur "out of memory" et vous n'aurez que vous-même à blâmer.

Notez que, comme suggéré ci-dessus, le paramètre Buffer affecte le comportement de la méthode "migrate" que vous ayez ou non "Fast_io" activé. Croyez-moi, vous ne voulez pas migrer des tonnes de courrier sans utiliser des E/S bufferisées !

Clear

Exemple:

$Clear = $imap->Clear();
# ou:
$imap->Clear($integer);

Le nom de ce paramètre, pour des raisons historiques, est quelque peu trompeur. Il devrait être nommé Wrap, car il spécifie combien de transactions sont stockées dans le tampon d'historique enveloppé. Mais ce n'était pas toujours le cas ; le tampon était en fait effacé. Le nom reste cependant le même dans un souci de compatibilité ascendante.

Clear spécifie que le tampon d'historique de l'objet doit être enveloppé après chaque n transactions, où n est la valeur spécifiée pour le paramètre Clear. Appeler la méthode éponyme Clear sans argument renverra la valeur actuelle du

Clair paramètre mais ne provoquera pas l'effacement de la mémoire tampon d'historique en boucle.

Définir Clair sur 0 désactive le bouclage automatique de la mémoire tampon d'historique, et le définir sur 1 désactive la fonction de mémoire tampon d'historique (à l'exception de la dernière transaction, qui ne peut pas être désactivée sans casser le module IMAPClient). Définir Clair sur 0 n'entraînera pas d'effacement immédiat de la mémoire tampon d'historique ; le définir sur 1 (ou tout autre nombre) le fera (sauf bien sûr pour cette dernière transaction inévitable).

La valeur par défaut de Clair est fixée à cinq (5) afin de conserver la mémoire.

Compress

S'il est défini, Mail::IMAPClient tente d'activer l'utilisation de l'extension RFC4978 COMPRESS DEFLATE. Cela nécessite que le serveur prenne en charge cette CAPACITÉ. Cet attribut peut être défini sur une valeur vraie pour l'activer ou sur un TABLEAU pour contrôler les arguments utilisés dans l'appel à Compress::Zlib::deflateInit().

Mail::IMAPClient utilisera automatiquement Compress::Zlib pour compresser/décompresser les données vers/depuis le serveur. Cet attribut est utilisé dans la méthode "login".

Voir aussi "compress" et "capability".

Note de version : attribut ajouté dans Mail::IMAPClient 3.30

Debug

Exemple :

$Debug = $imap->Debug();
# ou :
$imap->Debug($vrai_ou_faux);

Définit le drapeau de débogage sur une valeur vraie ou fausse. Peut être fourni lors de l'appel à la méthode "new" ou séparément en appelant la méthode d'objet Debug. L'utilisation de ce paramètre est fortement recommandée lors du débogage de scripts et requise lors du signalement de bugs.

Debug_fh

Exemple :

$Debug_fh = $imap->Debug_fh();
# ou :
$imap->Debug_fh($handleDeFichier);

Spécifie le handle de fichier vers lequel les informations de débogage doivent être imprimées. Il peut s'agir d'une référence à un objet handle de fichier ou d'un glob handle de fichier. Par défaut, les informations de débogage sont imprimées sur STDERR.

Par exemple, vous pouvez :

use Mail::IMAPClient;
use IO::File;
# définissez $user, $pass et $server ici
my $dh = IO::File->new(">debugging.output")
  or die "Impossible d'ouvrir debugging.output: $!\n";
my $imap = Mail::IMAPClient->new(
    User=>$user, Password=>$pass, Server=>$server, Debug=>1, Debug_fh => $dh
);

ce qui est identique à :

use Mail::IMAPClient;
use IO::File;
# définissez $user, $pass et $server ici
my $imap = Mail::IMAPClient->new(
    User     => $user,
    Password => $pass,
    Server   => $server,
    Debug    => "oui, s'il vous plaît",
    Debug_fh => IO::File->new(">debugging.output")
      || die "Impossible d'ouvrir debugging.output: $!\n"
);

Vous pouvez également :

use Mail::IMAPClient;
# définissez $user, $pass et $server ici
open(DBG, ">debugging.output")
  or die "Impossible d'ouvrir debugging.output: $!\n";
my $imap = Mail::IMAPClient->new(
  User=>$user, Password=>$pass, Server=>$server, Debug=> 1, Debug_fh => *DBG
);

Spécifier ce paramètre n'est pas très utile à moins que "Debug" ne soit défini sur une valeur vraie.

Domain

Le paramètre Domain est utilisé par le mécanisme d'authentification NTLM. Le domaine est un paramètre optionnel pour l'authentification NTLM.

EnableServerResponseInLiteral

Supprimé dans la version 2.99_01 (maintenant autodétecté)

Fast_io

Exemple :

$Fast_io = $imap->Fast_io();
# ou :
$imap->Fast_io($vrai_ou_faux);

Le paramètre Fast_io contrôle si l'objet Mail::IMAPClient tentera ou non d'utiliser des E/S non bloquantes sur le socket IMAP. Il est activé par défaut (sauf si l'appelant fournit le socket à utiliser).

Voir aussi "Buffer".

Folder

Exemple :

$Folder = $imap->Folder();
# ou :
$imap->Folder($nouvelle_valeur);

Le paramètre Folder renvoie le nom du dossier actuellement sélectionné (au cas où vous l'auriez oublié). Il peut également être utilisé pour définir le nom du dossier actuellement sélectionné, ce qui est complètement inutile si vous avez utilisé la méthode "select" (ou son équivalent en lecture seule, la méthode "examine") pour le sélectionner.

Notez que la définition du paramètre Folder ne sélectionne pas automatiquement un nouveau dossier ; vous utilisez les méthodes d'objet "select" ou "examine" pour cela. En général, le paramètre Folder ne doit être interrogé que (en utilisant la forme sans argument de la méthode Folder). Vous n'aurez besoin de définir le paramètre Folder que si vous utilisez une technique mystérieuse de votre propre cru pour sélectionner un dossier, ce que vous ne ferez probablement pas.

Ignoresizeerrors

Certains serveurs (de mise en cache), comme Exchange 2007, signalent souvent une taille de message incorrecte. Au lieu de découper le message en fonction de la taille spécifiée, la taille signalée sera simplement ignorée lorsque ce paramètre est défini sur 1.

Keepalive

Certains pare-feux et équipements réseau ont tendance à expirer les connexions prématurément si la connexion reste inactive. Le paramètre Keepalive, lorsqu'il est défini sur une valeur vraie, affecte le comportement de "new" et "Socket" en activant SO_KEEPALIVE sur le socket.

Note de version : attribut ajouté dans Mail::IMAPClient 3.17

Maxcommandlength

L'attribut Maxcommandlength est utilisé par fetch() pour limiter la longueur des commandes envoyées à un serveur. La valeur par défaut est de 1000 caractères, conformément à la recommandation de la section 3.2.1.5 de la RFC2683.

Note : cet attribut devrait également être utilisé pour plusieurs autres méthodes, mais cela n'a pas encore été implémenté. N'hésitez pas à signaler des bugs pour les méthodes pour lesquelles vous rencontrez des problèmes à cet égard.

Cet attribut devrait éliminer le besoin pour des utilitaires comme imapsync de créer leurs propres fonctions split() et permettre plutôt à Mail::IMAPClient de faire ce qu'il faut.

En pratique, ce paramètre s'est avéré utile pour surmonter une limite de 8000 octets pour UW-IMAPD et de 16384 octets pour les serveurs IMAP Courier/Cyrus.

Note de version : attribut ajouté dans Mail::IMAPClient 3.17

Maxtemperrors

Exemple :

$Maxtemperrors = $imap->Maxtemperrors();
# ou :
$imap->Maxtemperrors($nombre);

Le paramètre Maxtemperrors spécifie le nombre de fois où une opération de lecture ou d'écriture est autorisée à échouer sur une erreur "Resource Temporarily Available" (par exemple, EAGAIN). La valeur par défaut est undef, ce qui signifie qu'il n'y a pas de limite.

Définir ce paramètre sur la chaîne "unlimited" (au lieu de undef) pour ignorer les erreurs "Resource Temporarily Unavailable" est déconseillé.

Note : ce réglage doit être utilisé avec prudence et pourrait être supprimé dans une future version. Le régler peut amener les méthodes à retourner à l'appelant avant que les données ne soient reçues (et donc traitées) correctement, laissant potentiellement le module dans un état instable. À l'avenir, ce comportement pourrait être modifié pour tenter d'éviter cette situation.

Password

Exemple :

$Password = $imap->Password();
# ou :
$imap->Password($nouvelle_valeur);

Spécifie le mot de passe à utiliser lors de la connexion au service IMAP sur l'hôte spécifié dans le paramètre Server en tant qu'utilisateur spécifié dans le paramètre User. Peut être fourni lors de l'appel à la méthode new ou séparément en appelant la méthode d'objet Password.

Si Server, User et Password sont tous fournis à la méthode "new", alors l'objet nouvellement instancié sera connecté à l'hôte spécifié dans Server (au port spécifié dans Port ou au port par défaut 143) puis connecté en tant qu'utilisateur spécifié dans le paramètre User (en utilisant le mot de passe fourni dans le paramètre Password). Voir la discussion sur la méthode "new", ci-dessous.

Peek

Exemple :

$Peek = $imap->Peek();
# ou :
$imap->Peek($vrai_ou_faux);

Définir Peek sur une valeur vraie empêchera les méthodes "body_string", "message_string" et "message_to_file" de définir automatiquement le drapeau \Seen. Définir "Peek" sur 0 (zéro) forcera "body_string", "message_string", "message_to_file", et "parse_headers" à définir toujours le drapeau \Seen.

Par défaut, le drapeau vu est défini chaque fois que vous récupérez le corps d'un message, mais pas lorsque vous récupérez simplement les en-têtes. Passer undef à la méthode éponyme Peek réinitialisera le paramètre Peek à son état d'origine et par défaut.

Port

Exemple :

$Port = $imap->Port();
# ou :
$imap->Port($nouvelle_valeur);

Spécifie le port sur lequel le serveur IMAP écoute. Une valeur par défaut de 993 (si "Ssl" est vrai) ou 143 est définie lors d'un appel à "connect" si aucune valeur n'est fournie par l'appelant. Cet argument peut être fourni lors de l'appel à la méthode "new" ou séparément en appelant la méthode d'objet "Port".

Prewritemethod

Le paramètre Prewritemethod devrait contenir une référence à une sous-routine qui effectuera des "choses spéciales" aux données avant qu'elles ne soient envoyées au serveur IMAP (telles que le cryptage ou la signature).

Cette méthode sera appelée immédiatement avant l'envoi d'une commande client IMAP au serveur. Son premier argument est une référence à l'objet Mail::IMAPClient et le second argument est une chaîne contenant la commande qui sera envoyée au serveur. Votre Prewritemethod doit retourner une chaîne qui a été signée ou cryptée ou quoi que ce soit ; cette chaîne retournée est ce qui sera réellement envoyé au serveur.

Tu Prewritemethod aura probablement besoin de connaître plus d'éléments que ceux indiqués pour accomplir ce qu'il fait. Il est recommandé de colorer toutes les informations pertinentes dans une table de hachage et de stocker une référence à cette table dans un endroit où ta méthode pourra y accéder, potentiellement dans l'objet Mail::IMAPClient lui-même.

Note : Cette méthode ne doit rien envoyer via la connexion au serveur ; elle ne fait que convertir les données avant de les envoyer.

Voir aussi "Readmethod".

Ranges

Exemple :

$imap->Ranges(1);
# ou :
my $search = $imap->search(@search_args);
if ( $imap->Ranges) { # $search est un objet Mail::IMAPClient::MessageSet
    print "Ceci est mon résultat de recherche condensé : $search\n";
    print "Voici chaque message dans le résultat de recherche : ",
      join(",",@$search),"\n;
}

Si défini sur une valeur vraie, alors la méthode "search" renverra un objet Mail::IMAPClient::MessageSet si elle est appelée dans un contexte scalaire, au lieu d'une référence à un tableau que fetch renvoie normalement lorsqu'elle est appelée dans un contexte scalaire. Si défini sur zéro ou si indéfini, la méthode search continuera de renvoyer une référence à un tableau lorsqu'elle est appelée dans un contexte scalaire.

Ce paramètre n'a aucun effet sur la méthode search lorsque search est appelée dans un contexte de liste.

RawSocket

Exemple :

$socket = $imap->RawSocket;
# ou :
$imap->RawSocket($socketh);

La méthode RawSocket peut être utilisée pour obtenir le handle du socket de la connexion actuelle (par exemple, pour effectuer des I/O sur la connexion non encore prise en charge par Mail::IMAPClient) ou pour remplacer le socket actuel par un nouveau handle (par exemple, un handle SSL, voir IO::Socket::SSL, mais assure-toi de voir aussi la méthode "Socket").

Si tu fournis toi-même un handle de socket, soit en faisant quelque chose comme :

$imap = Mail::IMAPClient->new(RawSocket => $sock, User => ... );

soit en faisant quelque chose comme :

$imap = Mail::IMAPClient->new(User => $user,
            Password => $pass, Server => $host);
# blablabla
$imap->RawSocket($ssl);

alors tu seras responsable d'établir la connexion et de t'authentifier, soit par la méthode "login", soit par la méthode plus élégante "authenticate", ou, étant donné que tu connais tout, simplement en faisant des I/O directs sur le socket jusqu'à ce que tu sois connecté. Si tu effectues l'une de ces actions, tu dois également définir toi-même le paramètre "State" pour refléter l'état actuel de l'objet (c'est-à-dire Connecté, Authentifié, etc.).

Note : Aucune opération ne sera effectuée sur le socket lorsque cette méthode sera appelée. En particulier, après l'établissement de la connexion TCP vers le serveur IMAP, le protocole impose que le serveur envoie un message de bienvenue initial, et tu devras gérer ce message explicitement avant d'effectuer toute autre opération, par exemple, essayer d'appeler "login". L'avertissement est : Caveat emptor.

Pour une approche plus DWIM pour établir le socket, voir "Socket".

Readmethod

Exemple :

$imap->Readmethod(   # IMAP, HANDLE, BUFFER, LENGTH, OFFSET
    sub {
        my ( $self, $handle, $buffer, $count, $offset ) = @_;
        my $rc = sysread( $handle, $$buffer, $count, $offset );
        # faire quelque chose d'utile ici...
    }
);

La méthode Readmethod doit contenir une référence à une sous-routine qui remplacera sysread. La sous-routine recevra les arguments suivants : d'abord l'objet Mail::IMAPClient utilisé. Deuxièmement, une référence à un socket. Troisièmement, une référence à une variable scalaire dans laquelle les données sont lues (BUFFER). Les données situées ici doivent être des "données finales", donc si tu déchiffres ou supprimes des signatures, assure-toi de le faire avant d'insérer des données dans ce buffer. Quatrièmement, le nombre d'octets demandés à lire ; la LONGUEUR de la requête. Cinquièmement, l'OFFSET dans le BUFFER où les données doivent être lues. Si non spécifié, il doit être par défaut à zéro.

Note : Cette méthode remplace complètement les lectures de la connexion au serveur, donc si tu en définis une, ta sous-routine devra effectivement effectuer la lecture. C'est pour des choses comme celle-ci que nous avons le paramètre "Socket" et la méthode d'accès éponyme.

Ton Readmethod aura probablement besoin de connaître plus d'éléments que ceux indiqués pour accomplir ce qu'il fait. Il est recommandé de colorer toutes les informations pertinentes dans une table de hachage et de stocker une référence à cette table dans un endroit où ta méthode pourra y accéder, potentiellement dans l'objet Mail::IMAPClient lui-même.

Voir aussi "Prewritemethod".

Readmoremethod

La méthode Readmoremethod doit contenir une référence à une sous-routine qui remplacera/améliorera le comportement de la méthode interne _read_more(). La sous-routine recevra les arguments suivants : d'abord l'objet Mail::IMAPClient utilisé. Deuxièmement, une référence à un socket. Troisièmement, une valeur de délai d'attente qui est utilisée comme valeur de délai d'attente pour CORE::select() par défaut. En fonction des changements/fonctionnalités introduits par les changements dans Readmethod, cela pourrait être nécessaire ici.

Note de version : attribut ajouté dans Mail::IMAPClient 3.30

Reconnectretry

Si une connexion IMAP devient inactive trop longtemps, elle peut être fermée par le serveur ou un pare-feu, etc. Le paramètre Reconnectretry, lorsqu'il reçoit une valeur positive, fera en sorte que Mail::IMAPClient réessaye les commandes IMAP jusqu'à X fois lorsqu'une erreur telle que EPIPE ou ECONNRESET se produit. Ceci est désactivé (0) par défaut.

Voir aussi "Keepalive"

Note de version : attribut ajouté dans Mail::IMAPClient 3.17

Server

Exemple :

$Server = $imap->Server();
# ou :
$imap->Server($hostname);

Indique l'adresse IP ou le nom d'hôte sur lequel le serveur IMAP est exécuté. Si elle est fournie dans le cadre de l'appel à la méthode "new", le nouvel objet IMAP se connectera automatiquement au moment de sa création. (Voir la méthode "new", ci-dessous.) Elle peut être fournie dans le cadre de l'appel à la méthode "new" ou séparément en appelant la méthode d'accès Server de l'objet.

Showcredentials

Normalement, la sortie de débogage masquera les identifiants de connexion lors de l'utilisation du mécanisme de connexion en texte clair. Définir Showcredentials sur une valeur vraie supprime cela, permettant de voir la chaîne qui est envoyée et reçue lors de la connexion en texte clair. Utilisez-le uniquement lorsque vous déboguez des problèmes avec la commande IMAP LOGIN, puis désactivez-le immédiatement une fois que vous avez terminé avec ce problème.

Exemple :

print "C'est très risqué !\n" if $imap->Showcredentials();
# ou :
$imap->Showcredentials(0);    # masquer à nouveau les identifiants

Socket

NOTE ! La signification de cette méthode a changé depuis la version 2.99_04 de ce module. Si vous avez besoin de l'ancienne signification, utilisez "RawSocket".

Exemple :

$Socket = $imap->Socket();
# ou :
$imap->Socket($socket_fh);

La méthode Socket peut être utilisée pour obtenir le handle du socket de la connexion actuelle. Cela peut être nécessaire pour effectuer des I/O sur la connexion qui n'est pas encore prise en charge par Mail::IMAPClient) ou pour remplacer le socket actuel par un nouveau handle (par exemple, un handle SSL, voir IO::Socket::SSL).

Si tu fournis toi-même un handle de socket, soit en faisant quelque chose comme :

$imap = Mail::IMAPClient->new( Socket => $sock, User => ... );

soit en faisant quelque chose comme :

$imap = Mail::IMAPClient->new(
  User => $user, Password => $pass, Server => $host
);
$imap->Socket($ssl);

alors tu seras responsable d'établir la connexion, c'est-à-dire assure-toi que $ssl dans l'exemple est un socket valide et connecté.

Cette méthode est principalement utilisée pour fournir un remplacement par défaut pour IO::Socket::(INET|IP), utilisé par "connect" par défaut. En fait, cette méthode est appelée par "connect" lui-même après qu'une connexion IO::Socket::(INET|IP) appropriée ait été établie vers le serveur cible ; pour cette raison, cette méthode effectue également les opérations normales associées à "connect", à savoir :

  • lecture du message de bienvenue initial du serveur ;
  • appel à "login" si les conditions s'appliquent (voir "connect" pour plus de détails) ;
  • laisser l'objet Mail::IMAPClient dans un état approprié.

Pour ces raisons, l'exemple suivant fonctionnera "sans configuration" :

use IO::Socket::SSL;
my $imap = Mail::IMAPClient->new
 ( User     => 'your-username',
   Password => 'your-password',
   Socket   => IO::Socket::SSL->new
   (  Proto    => 'tcp',
      PeerAddr => 'some.imap.server',
      PeerPort => 993, # port standard IMAP sur SSL
   ),
);

Si tu as besoin de plus de contrôle sur le socket, par exemple si tu dois implémenter une méthode d'authentification plus complexe, voir "RawSocket".

Starttls

Si la valeur est une référence à un tableau, elle sera utilisée pour les arguments de IO::Socket::SSL->start_SSL. Par défaut, cette connexion est définie en mode bloquant pendant la négociation TLS. Le socket sera réinitialisé à sa valeur de blocage/non-blocage d'origine après une négociation TLS réussie. Les arguments utilisés dans l'appel à start_SSL peuvent être contrôlés en définissant cet attribut à une référence à un tableau contenant les arguments souhaités.

Note de version : attribut ajouté dans Mail::IMAPClient 3.22

Socketargs

Par exemple, pour toujours passer MultiHomed => 1 à IO::Socket::...->new, vous pouvez utiliser :

$imap = Mail::IMAPClient->new(

Cet attribut est utilisé dans la méthode « connect ». Supportedflags

Particulièrement lors de l'utilisation de « migrate() », le destinataire du message peut avoir besoin d'être explicitement configuré avec la liste des drapeaux pris en charge ; cela peut différer du serveur IMAP d'origine.

Les noms doivent être spécifiés sous forme de tableau. Les traits d'union, les barres obliques et la casse des noms seront ignorés.

Vous pouvez également spécifier une référence à une fonction qui sera appelée pour chaque drapeau. Dans ce cas, les drapeaux ne sont pas (encore) normalisés. Les listes retournées par les appels à CODE détermineront la liste finale des drapeaux.

Timeout

Exemple :

$Timeout = $imap->Timeout();
# ou :
$imap->Timeout($secondes);

Définit la valeur du délai d'attente en secondes pour les lectures (par défaut, 600). Spécifiquement, le paramètre Timeout empêchera Mail::IMAPClient de bloquer pendant une lecture.

Comme les délais d'attente sont implémentés à l'aide de l'opérateur Perl select, le paramètre Timeout peut être défini à un nombre fractionnaire de secondes. Définir Timeout à 0 (zéro) désactive la fonction de délai d'attente.

Uid

Exemple :

$Uid = $imap->Uid();
# ou :
$imap->Uid($vrai_ou_faux);

Si Uid est défini à une valeur vraie (c'est-à-dire 1), le comportement des méthodes fetch, search, copy et store (et leurs dérivés) est modifié, traitant les arguments qui seraient autrement des séquences de messages comme des UID. Les valeurs retournées (dans le cas des méthodes search et de leurs dérivés) qui seraient autrement des séquences de messages sont retournées sous forme d'UID.

Cela est implémenté en interne comme un commutateur qui, s'il est activé, fait que les méthodes qui émettraient autrement une commande IMAP FETCH, STORE, SEARCH ou COPY, émettent respectivement UID FETCH, UID STORE, UID SEARCH ou UID COPY. La principale différence entre les séquences de messages et les UID est que, selon la RFC3501, les UID ne doivent pas changer pendant une session et ne doivent pas changer entre les sessions, et ne doivent jamais être réutilisés. Les séquences de messages n'ont pas cette garantie et peuvent en fait être réutilisées immédiatement.

Comme les noms de dossiers ont également un identifiant unique (UIDVALIDITY), fourni lors de la sélection ou de l'examen du dossier ou via quelque chose comme « $imap->status($folder,« UIDVALIDITY ») », il est possible d'identifier de manière unique chaque message sur le serveur, bien que vous n'ayez normalement pas besoin de vous en soucier.

Les méthodes affectées par le paramètre Uid sont :

copy            fetch
search          store
message_string  message_uid
body_string     flags
move            size
parse_headers   thread

Note : si pour une raison quelconque vous ne souhaitez activer le paramètre Uid que pour une seule instruction, vous pouvez choisir entre les deux extraits suivants, qui sont équivalents :

Exemple 1 :

$imap->Uid(1);
my @uids = $imap->search('SUBJECT',« Just a silly test »); #
$imap->Uid(0);

Exemple 2 :

my @uids;
foreach $r ($imap->UID(« SEARCH »,« SUBJECT »,« Just a silly test ») {
    chomp $r;
    $r =~ s/\r$//;
    $r =~ s/^\*\s+SEARCH\s+// or next;
    push @uids, grep(/\d/,(split(/\s+/,$r)));
}

Dans le second exemple, nous utilisons la méthode par défaut pour émettre la commande IMAP UID du client, en veillant à utiliser un nom de méthode entièrement en majuscules pour ne pas appeler accidentellement la méthode « Uid ». Ensuite, nous analysons manuellement les UID des messages, car nous n'avons pas l'avantage de la méthode intégrée « search ».

Soyez très prudent lorsque vous activez et désactivez le paramètre « Uid » pendant un script. Si vous perdez la trace de l'activation ou de la désactivation du paramètre « Uid », vous pourriez faire quelque chose de tragique, comme supprimer le mauvais message. Rappelez-vous, comme toutes les méthodes accesseurs éponymes, la méthode « Uid » sans paramètre renvoie la valeur actuelle du paramètre « Uid », alors faites-vous une faveur et vérifiez. La manière la plus sûre est de l'activer au début (ou simplement de le laisser dans son état inactif par défaut), puis de le laisser activé. (N'oubliez pas que le laisser inactif peut causer des problèmes si des changements dans le contenu d'un dossier entraînent un réarrangement.)

Par défaut, le paramètre « Uid » est activé.

User

Exemple :

$User = $imap->User();
# ou :
$imap->User($userid);

Spécifie l'ID utilisateur à utiliser lors de la connexion au service IMAP. Il peut être fourni lors de l'appel à la méthode « new » ou via l'appel à la méthode objet « User ».

Les paramètres peuvent être définis lors de l'appel à la méthode « new » en passant des paramètres nommés/valeurs, ou ultérieurement en appelant la méthode objet de paramètre éponyme.

Méthodes d'état

Il existe plusieurs méthodes d'objet qui retournent l'état de l'objet. Elles peuvent être utilisées à tout moment pour vérifier l'état d'un objet IMAPClient, mais sont particulièrement utiles pour déterminer la cause des échecs lors de la tentative d'une connexion et authentification dans le cadre d'un seul appel à la méthode « new ». Les méthodes d'état sont :

Escaped_history

Exemple :

my @history = $imap->Escaped_history;

La méthode « Escaped_history » est presque identique à la méthode « History ». Bien que, comme la méthode « History », la sortie du serveur transmise littéralement soit placée entre guillemets doubles, avec tous les guillemets doubles échappés. Si elle est appelée dans un contexte scalaire, « Escaped_history » renvoie une référence de tableau au lieu d'un tableau.

« Escaped_history » est utile si vous récupérez la sortie et l'analysez manuellement, et que vous vous fiez aux caractères spéciaux mentionnés ci-dessus pour délimiter les données. Elle n'est pas utile lorsque vous récupérez le contenu des messages ; utilisez « message_string » ou « body_string » dans ce cas.

Escaped_results

Exemple :

my @results = $imap->Escaped_results;

La méthode « Escaped_results » est presque identique à la méthode « Results ». Bien que, comme la méthode « Results », la sortie du serveur transmise littéralement soit placée entre guillemets doubles, avec tous les guillemets doubles échappés. Si elle est appelée dans un contexte scalaire, « Escaped_results » renvoie une référence de tableau au lieu d'un tableau.

« Escaped_results » est utile si vous récupérez la sortie et l'analysez manuellement, et que vous vous fiez aux caractères spéciaux mentionnés ci-dessus pour délimiter les données. Elle n'est pas utile lorsque vous récupérez le contenu des messages ; utilisez « message_string » ou « body_string » dans ce cas.

History

Exemple :

my @history = $imap->History;

La méthode « History » est presque identique à la méthode « Results ». Bien que, comme la méthode « Results », la commande IMAP qui a été émise pour créer les résultats retournés n'est pas incluse dans les résultats retournés. Si elle est appelée dans un contexte scalaire, « History » renvoie une référence de tableau au lieu d'un tableau.

IsUnconnected

Renvoie une valeur vraie si l'objet est dans un état « Unconnected ».

IsConnected

Renvoie une valeur vraie si l'objet est dans un état « Connected », « Authenticated » ou « Selected ».

IsAuthenticated

Renvoie une valeur vraie si l'objet est dans un état « Authenticated » ou « Selected ».

IsSelected

Renvoie une valeur vraie si l'objet est dans un état « Selected ».

LastError

En interne, « LastError » est implémenté presque comme un paramètre (comme décrit dans « Parameters », ci-dessus). Il y a un attribut « LastError » et une méthode accesseur éponyme qui renvoie la chaîne « LastError » décrivant la dernière condition d'erreur détectée par le serveur.

Note : certaines erreurs sont plus graves que d'autres, donc la valeur de « LastError » n'est significative que si vous rencontrez une erreur qui ne vous plaît pas. Par exemple, si vous utilisez la méthode « exists » pour voir si un dossier existe et que le dossier n'existe pas, un message d'erreur sera enregistré dans « LastError » même si ce n'est pas une erreur particulièrement grave. D'un autre côté, si vous n'avez pas utilisé « exists » et que vous avez simplement tenté de « select » un dossier inexistant, « select » renverrait « undef » après avoir défini « LastError » à quelque chose comme « NO SELECT failed: Can't open mailbox "mailbox": no such mailbox ». Il serait alors utile d'imprimer le contenu de « LastError » alors que vous êtes sur le point de mourir.

LastIMAPCommand

Nouveau dans la version 2.0.4, « LastIMAPCommand » renvoie la chaîne exacte de la commande IMAP qui doit être envoyée au serveur. Elle est principalement utile dans

constructing messages d'erreur quand "LastError" ne suffit tout simplement pas.

Report

La méthode Report renvoie un tableau contenant l'historique de la session IMAP jusqu'au moment où Report a été appelée. Elle est principalement destinée à aider au débogage, mais peut également être utilisée pour récupérer la sortie brute pour une analyse manuelle. La valeur du paramètre "Clear" contrôle le nombre de transactions dans le rapport.

Results

La méthode Results renvoie un tableau contenant les résultats d'une commande client IMAP. Elle accepte un argument, le numéro de transaction de la commande dont les résultats doivent être retournés. Si le numéro de transaction n'est pas spécifié, Results renvoie les résultats de la dernière commande client IMAP émise. Si elle est appelée dans un contexte scalaire, Results renvoie une référence de tableau plutôt qu'un tableau.

State

La méthode State renvoie une valeur numérique qui indique l'état actuel de l'objet IMAPClient. Si elle est invoquée avec un argument, elle définira l'état de l'objet à cette valeur. Si elle est invoquée sans argument, elle se comporte comme "Status", ci-dessous.

Normalement, vous n'aurez pas à invoquer cette fonction. Une exception est si vous contournez les modules "connect" et/ou "login" du module Mail::IMAPClient pour configurer votre propre connexion (par exemple, sur une socket sécurisée), auquel cas vous devez manuellement faire ce que les méthodes "connect" et "login" feraient autrement pour vous.

Status

La méthode Status renvoie une valeur numérique qui indique l'état actuel de l'objet IMAPClient. (À ne pas confondre avec la méthode "status", entièrement en minuscules, qui est l'implémentation de la commande client IMAP STATUS.)

Transaction

La méthode Transaction renvoie la valeur de la balise (ou le numéro de transaction) de la dernière commande client IMAP.

Mécanismes d'authentification personnalisés

Si vous souhaitez simplement utiliser l'authentification en texte brut ou l'un des "Mécanismes d'authentification avancés" pris en charge, il n'est pas nécessaire de lire cette section.

Il existe un certain nombre de méthodes et de paramètres que vous pouvez utiliser pour construire votre propre mécanisme d'authentification. Toutes les méthodes et tous les paramètres décrits dans cette section sont décrits plus en détail ailleurs dans ce document. Cette section fournit un point de départ pour la construction de votre propre mécanisme d'authentification.

Il existe de nombreux mécanismes d'authentification. Si votre mécanisme préféré n'est pas actuellement pris en charge mais que vous parvenez à le faire fonctionner, veuillez envisager de le faire don à ce module. Les correctifs et suggestions sont toujours les bienvenus.

La prise en charge des mécanismes d'authentification supplémentaires dans Mail::IMAPClient est assez simple. Vous créez un rappel pour fournir la réponse au défi du serveur. Le paramètre "Authcallback" contient une référence au rappel, qui peut être une sous-routine anonyme ou une sous-routine nommée. Ensuite, vous identifiez votre mécanisme d'authentification, soit via le paramètre "Authmechanism", soit comme argument de "authenticate".

Vous devrez peut-être également fournir une sous-routine pour crypter (ou autre) les données avant qu'elles ne soient envoyées au serveur. Le paramètre "Prewritemethod" doit contenir une référence à cette sous-routine. Et, vous aurez besoin de décrypter les données du serveur ; une référence à la sous-routine qui fait cela doit être stockée dans le paramètre "Readmethod".

Ce cadre est basé sur les hypothèses qu'a) le mécanisme que vous utilisez nécessite un échange défi-réponse, et b) le mécanisme ne modifie pas fondamentalement l'échange entre le client et le serveur, mais encapsule simplement l'échange dans une couche de cryptage. Il suppose également que la nature orientée ligne de la conversation IMAP est préservée ; les mécanismes d'authentification qui divisent les messages en blocs de taille prédéterminée peuvent toujours être possibles, mais seront certainement plus difficiles à mettre en œuvre.

Alternativement, si vous avez accès à imtest, un utilitaire inclus dans la distribution Cyrus IMAP, vous pouvez utiliser cet utilitaire pour gérer vos communications avec le serveur IMAP. C'est assez facile à implémenter. Un exemple, examples/imtestExample.pl, se trouve dans le sous-répertoire "examples" de la distribution source.

La liste suivante résume les méthodes et les paramètres qui pourraient vous être utiles dans l'implémentation de l'authentification avancée :

La méthode authenticate
La méthode "authenticate" utilise le paramètre "Authmechanism" pour déterminer comment s'authentifier auprès du serveur, voir la documentation de la méthode pour plus de détails.
Socket et RawSocket
Les méthodes "Socket" et "RawSocket" donnent accès à la connexion socket. La socket est généralement créée automatiquement par la méthode "connect", mais si vous implémentez une technique d'authentification avancée, vous pouvez choisir de configurer votre propre connexion socket, puis de définir ce paramètre manuellement, en contournant complètement la méthode connect. Ceci est également utile si vous voulez utiliser des alternatives IO::Socket::(INET|IP) comme IO::Socket::SSL et nécessitez un contrôle total.

"RawSocket" récupère/définit simplement la socket sans tenter aucune interaction dessus. Dans ce cas, vous devez vous assurer de gérer toutes les opérations préliminaires et de définir manuellement l'objet Mail::IMAPClient en synchronisation avec son état réel par rapport à cette socket (voir ci-dessous pour des paramètres supplémentaires à ce sujet, en particulier le paramètre "State").

Contrairement à "RawSocket", "Socket" tente de poursuivre les phases de connexion préliminaires si les conditions s'appliquent. Si les deux paramètres sont présents, cela a la priorité sur "RawSocket". Si "Starttls" est défini, alors la méthode "starttls" sera appelée par "Socket".

VEUILLEZ NOTER À partir de la version 2.99_04 de ce module, la sémantique de "Socket" a changé pour être plus "DWIM" (Do What I Mean). "RawSocket" a été introduit comme remplaçant du paramètre "Socket" dans les versions plus anciennes.

Paramètres State, Server, User, Password, Proxy et Domain
Si vous avez besoin d'établir votre propre connexion au serveur et d'effectuer manuellement votre authentification, vous pouvez définir ces paramètres pour maintenir votre objet Mail::IMAPClient synchronisé avec son état réel. Parmi ceux-ci, seul le paramètre "State" est toujours nécessaire. Les autres doivent être définis uniquement si vous pensez que votre programme en aura besoin plus tard.
Authmechanism
Définissez ceci sur la valeur que AUTHENTICATE doit envoyer au serveur comme mécanisme d'authentification. Si vous gérez votre propre authentification, ce paramètre peut être moins utile. Il existe principalement pour que vous puissiez le définir lorsque vous appelez "new" pour instancier votre objet. La méthode "new" appellera "connect", qui appellera "login". Si "login" constate que vous avez défini un Authmechanism, il appellera authenticate, en utilisant vos paramètres Authmechanism et Authcallback comme arguments.
Authcallback
Le "Authcallback", s'il est défini, contient un pointeur vers une sous-routine (CODEREF). La méthode "login" l'utilisera comme argument de rappel pour la méthode authenticate si les paramètres Authmechanism et Authcallback sont tous deux définis. Si vous définissez Authmechanism mais pas Authcallback, le rappel par défaut pour votre mécanisme sera utilisé. Tous les mécanismes d'authentification pris en charge ont un rappel par défaut ; dans tous les autres cas, ne pas fournir le rappel entraîne une erreur.

La plupart des mécanismes d'authentification avancés nécessitent un échange défi-réponse. Après que la méthode "authenticate" envoie "<tag> AUTHENTICATE <Authmechanism>\015\012" au serveur IMAP, le serveur répond par un défi. La méthode "authenticate" invoque alors le code dont la référence est stockée dans le paramètre Authcallback comme suit :

$Authcallback->( $challenge, $imap )

où $Authcallback est la référence de code stockée dans le paramètre Authcallback, $challenge est le défi reçu du serveur IMAP, et $imap est un pointeur vers l'objet Mail::IMAPClient. La valeur de retour de la routine Authcallback doit être la réponse au défi, et cette valeur de retour sera envoyée par la méthode "authenticate" au serveur.

Prewritemethod/Readmethod
Le Prewritemethod peut contenir une sous-routine qui effectuera le chiffrement nécessaire, puis renverra le résultat à l'appelant afin qu'il puisse à son tour être envoyé au serveur.

Le Readmethod peut contenir une sous-routine à utiliser pour remplacer sysread généralement effectué par Mail::IMAPClient.

Voir "Prewritemethod" et "Readmethod" pour plus de détails.
