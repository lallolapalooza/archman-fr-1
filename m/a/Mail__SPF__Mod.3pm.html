Mail::SPF::Mod(3) Documentation des contributions Perl Mail::SPF::Mod(3)

NOM

Mail::SPF::Mod - Classe de base des modificateurs d'enregistrement SPF

VERSION

version 3.20250505

DESCRIPTION

Un objet de la classe Mail::SPF::Mod représente un modificateur au sein d'un enregistrement SPF. Mail::SPF::Mod ne peut pas être instancié directement. Vous devriez créer un objet d'une classe spécifique plutôt que d'instancier directement la classe.

CONSTRUCTEURS

Les constructeurs suivants sont fournis :

new(%options) : retourne Mail::SPF::Mod
Abstraction. Crée un objet de type Mail::SPF::Mod.

%options est une liste de paires clé/valeur représentant les options suivantes :

text
Un texte représentant le texte brut du modificateur.
name
Un nom représentant le nom du modificateur. Requis si vous créez un objet Mail::SPF::Mod générique (plutôt qu'une sous-classe spécifique).
domain_spec
Un texte ou un objet Mail::SPF::MacroString représentant un "domain-spec" optionnel du mécanisme.
new_from_string($text, %options) : retourne Mail::SPF::Mod ; lance Mail::SPF::ENothingToParse, Mail::SPF::EInvalidMod
Abstraction. Crée un objet de type Mail::SPF::Mod en analysant le texte et les options données.

Méthodes_de_classe

Les méthodes de classe suivantes sont fournies :

name_pattern : retourne Regexp
Retourne un modèle d'expression régulière qui correspond à tout nom de modificateur légitime.

Méthodes_d_instance

Les méthodes d'instance suivantes sont fournies :

text : retourne string ; lance Mail::SPF::ENoUnparsedText
Retourne le texte brut du modificateur. Lance une exception Mail::SPF::ENoUnparsedText si le modificateur a été créé syntaxiquement plutôt que parsé, et qu'aucun texte n'a été fourni.
name : retourne string
Retourne le nom du modificateur.
params : retourne string
Abstraction. Retourne les paramètres du modificateur sous forme de chaîne.

Une sous-classe de Mail::SPF::Mod n'a pas à implémenter cette méthode si elle ne supporte pas de paramètres, bien que cela soit assez rare.

stringify : retourne string
Formate le nom du modificateur et ses paramètres en une chaîne et la retourne. Vous pouvez simplement utiliser un objet Mail::SPF::Mod comme une chaîne, voir « OVERLOADING ».
process : lance Mail::SPF::Result, Mail::SPF::Result::Error, Mail::SPF::Exception
Abstraction. Traite le modificateur. Ce que cela signifie dépend de l'implémentation spécifique dans les sous-classes. Voir « TYPES DE MODIFICATEURS » ci-dessous.

Cette méthode est abstraite et doit être implémentée par les sous-classes de Mail::SPF::Mod.

TYPES_DE_MODIFICATEURS

Il existe différents types de modificateurs de base, décrits ci-dessous. Tous sont fournis par la classe Mail::SPF::Mod.

Modificateurs_globaux - Mail::SPF::GlobalMod

SPFv1 (RFC 4408) ne connaît que les modificateurs_globaux. Un modificateur global peut apparaître dans n'importe quel enregistrement SPF, mais une seule fois. Pendant l'évaluation de l'enregistrement, les modificateurs globaux sont traités après que le dernier mécanisme a été évalué et qu'un résultat SPF a été déterminé.

Une méthode de classe supplémentaire est fournie par Mail::SPF::GlobalMod :

precedence : retourne real
Abstraction. Retourne un nombre real entre 0 et 1 indiquant la priorité du type de modificateur global. Les modificateurs globaux présents dans un enregistrement SPF sont traités dans l'ordre de leurs valeurs de priorité, 0 signifiant en premier.

Cette méthode est abstraite et doit être implémentée par les sous-classes de Mail::SPF::GlobalMod.

Une méthode d'instance supplémentaire est fournie par Mail::SPF::GlobalMod :

process($server, $request) : lance Mail::SPF::Result
Abstraction. Traite le modificateur. Ce que cela signifie dépend de l'implémentation spécifique dans les sous-classes. Il touche les deux objets Mail::SPF::Server et Mail::SPF::Request. Comme les modificateurs globaux sont généralement traités *après* qu'un résultat SPF a été déterminé, il touche également l'objet Mail::SPF::Result actuel. Si le modificateur souhaite modifier le résultat SPF, il peut lancer un objet Mail::SPF::Result différent.

Cette méthode est abstraite et doit être implémentée par les sous-classes de Mail::SPF::GlobalMod.

Modificateurs_positionnels - Mail::SPF::PositionalMod

Sender ID (RFC 4406) introduit le concept de modificateurs positionnels. Selon la RFC 4406, un modificateur positionnel doit suivre un mécanisme et s'appliquer à ce mécanisme, et seulement à ce mécanisme. Cependant, comme cette définition n'est pas très utile, et parce qu'aucun modificateur positionnel n'est encore défini sur cette base, Mail::SPF s'écarte de la RFC 4406 comme suit :

Un modificateur positionnel peut apparaître dans n'importe quel enregistrement SPF et est stateful, c'est-à-dire qu'il s'applique à tous les mécanismes et modificateurs qui le suivent. Les modificateurs positionnels sont généralement multiples, c'est-à-dire qu'ils peuvent apparaître un nombre quelconque de fois dans l'enregistrement. Pendant l'évaluation de l'enregistrement, les modificateurs positionnels sont traités au moment où ils sont rencontrés par l'évaluateur. Par conséquent, tous les modificateurs positionnels sont traités avant qu'un résultat SPF ne soit déterminé.

Une méthode d'instance supplémentaire est fournie par Mail::SPF::PositionalMod :

process($server, $request) : lance Mail::SPF::Result::Error, Mail::SPF::Exception
Abstraction. Traite le modificateur. Ce que cela signifie dépend de l'implémentation spécifique dans les sous-classes. Il touche les deux objets Mail::SPF::Server et Mail::SPF::Request. Comme les modificateurs globaux sont généralement traités *avant* qu'un résultat SPF ne soit déterminé, aucun objet Mail::SPF::Result n'est disponible pour le modificateur. Le modificateur peut (bien qu'il ne le puisse pas directement pour le moment) ne pas modifier le résultat final du SPF, mais il peut lancer une exception pour indiquer une erreur.

Cette méthode est abstraite et doit être implémentée par les sous-classes de Mail::SPF::PositionalMod.

Modificateurs_non_définis - Mail::SPF::UnknownMod

SPFv1 et Sender ID permettent tous deux que des modificateurs non définis apparaissent dans les enregistrements SPF afin de permettre l'introduction de nouveaux modificateurs sans casser l'implémentation existante. Évidemment, les modificateurs non définis ne sont ni globaux ni positionnels, mais

ils peuvent apparaître un nombre quelconque de fois tout au long de l'enregistrement et sont simplement ignorés lors de l'évaluation de l'enregistrement.

Évidemment aussi, Mail::SPF::UnknownMod ne prend pas en charge une méthode "process".

La méthode d'instance spécifique suivante est fournie par Mail::SPF::UnknownMod :

params : retourne string
Retourne la valeur non analysée du modificateur sous forme de chaîne.

SOVERCHARGE

Si un objet Mail::SPF::Mod est utilisé comme une chaîne, la méthode "stringify" est utilisée pour convertir l'objet en une chaîne.
