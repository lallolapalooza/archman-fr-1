NOM

Mail::Message::Construct::Read - lire un Mail::Message à partir d'une poignée de fichier

SYNOPSIS

my $msg1 = Mail::Message->read(\*STDIN);
my $msg2 = Mail::Message->read(\@lines);

DESCRIPTION

Lorsque des méthodes complexes sont appelées sur un objet "Mail::Message", ce paquet est chargé automatiquement pour supporter la lecture de messages directement à partir de n'importe quelle poignée de fichier.

MÉTHODES

Construction d'un message

$class->read($fh|CHAÎNE|SCALAR|TABLEAU, %options)
Lit un message à partir d'une $fh, "CHAÎNE", "SCALAR", ou une référence à un "TABLEAU" de lignes. La plupart des %options sont passées au new() du message qui est créé, mais quelques-unes supplémentaires sont définies.

Veuillez consulter build() et buildFromBody() avant de penser à cette méthode "read". Utilisez cette "read" uniquement lorsque vous avez une poignée de fichier comme STDIN à analyser, ou une source externe de lignes de message. Lorsque vous avez déjà un ensemble distinct de lignes d'en-tête et de corps, alors "read" n'est certainement pas votre meilleur choix.

Certaines personnes utilisent cette méthode dans un script procmail : le message arrive sur stdin, donc nous n'avons qu'une poignée de fichier. Dans ce cas, vous êtes coincé avec cette méthode. Le message est précédé d'une ligne qui peut être utilisée comme séparateur de message dans les dossiers mbox. Voir l'exemple comment gérer cela.

Cette méthode supprimera les champs "Status" et "X-Status" lorsqu'ils apparaissent dans la source, pour éviter le risque que ces champs interfèrent accidentellement avec votre administration interne, ce qui pourrait avoir des implications de sécurité.

-Option             --Défaut
 body_type            undef
 parser_class         undef
 seekable             false
 strip_status_fields  <C<true>>
 trusted              true
body_type => CLASSE
Force un type de corps (une implémentation spécifique de Mail::Message::Body) à être utilisé pour stocker le contenu du message. Lorsque le corps est multipart ou imbriqué, cela sera outrepassé.
parser_class => CLASSE
Enforce un certain type de parseur à utiliser, qui doit être une extension de la classe de parseur autrement prise.
seekable => BOOLEAN
Indique qu'une poignée de fichier cherchable a été passée. Dans ce cas, nous pouvons utiliser le parseur Mail::Box::Parser::Perl qui lit les messages directement à partir du flux d'entrée.
strip_status_fields => BOOLEAN
Supprime les champs "Status" et "X-Status" du message après lecture, pour réduire le risque que les messages reçus de sources externes n'interfèrent avec votre administration interne. Si vous souhaitez que les champs ne soient pas supprimés (vous souhaitez désactiver la suppression) vous traitez probablement les dossiers vous-même, ce qui est une mauvaise chose !
trusted => BOOLEAN

» exemple :

my $msg1 = Mail::Message->read(\*STDIN);
my $msg2 = Mail::Message->read(\@lines, log => 'PROGRESS');
$folder->addMessages($msg1, $msg2);
my $msg3 = Mail::Message->read(<<MSG);
Subject: hello world
To: you@example.com
                     # attention : ligne vide requise !!!
Hi, greetings!
MSG
# exemple procmail
my $fromline = <STDIN>;
my $msg      = Mail::Message->read(\*STDIN);
my $coerced  = $mboxfolder->addMessage($msg);
$coerced->fromLine($fromline);
