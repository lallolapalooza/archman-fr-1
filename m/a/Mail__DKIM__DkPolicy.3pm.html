NOM

Mail::DKIM::DkPolicy - représente une règle de politique de signature d'envoi DomainKeys

VERSION

version 1.20240923

DESCRIPTION

Les politiques de signature d'envoi DomainKeys sont décrites dans la RFC4870 (historique). Il s'agit d'une règle publiée dans le DNS de l'expéditeur (c'est-à-dire la personne qui transmet le message) qui décrit comment les messages doivent être signés.

CONSTRUCTEURS

fetch() - récupérer une politique de signature d'envoi depuis le DNS

my $policy = Mail::DKIM::DkPolicy->fetch(
                 Protocol => 'dns',
                 Sender => 'joe@example.org',
             );

Les arguments nommés suivants sont acceptés :

Protocol
spécifie toujours "dns"
Author
l'"author" du message pour lequel la politique est vérifiée. Il s'agit de la première adresse e-mail dans l'en-tête "From". Conformément à la RFC2822, section 3.6.2, l'en-tête "From" indique qui est responsable de la rédaction du message.
Sender
l'"expéditeur" du message pour lequel la politique est vérifiée. Il s'agit de la première adresse e-mail dans l'en-tête "Sender", ou s'il n'y a pas d'en-tête "Sender", l'adresse e-mail dans l'en-tête "From". Conformément à la RFC2822, section 3.6.2, l'en-tête "Sender" indique qui est responsable de la transmission du message.

Selon le type de politique vérifiée, les champs "Sender" et "Author" peuvent être nécessaires.

Si une erreur DNS se produit ou si le délai d'attente expire, une exception est levée.

Sinon, un objet de politique est renvoyé. S'il n'y a pas de politique publiée, la politique par défaut est renvoyée. Pour vérifier quand cela se produit, utilisez

my $is_default = $policy->is_implied_default_policy;

new() - créer un objet de politique par défaut

my $policy = Mail::DKIM::DkPolicy->new;

parse() - obtenir un objet de politique à partir de l'analyse d'une chaîne

my $policy = Mail::DKIM::DkPolicy->parse(
                 String => 'o=~; t=y'
             );

MÉTHODES

apply() - appliquer la politique aux résultats d'un vérificateur DKIM

my $result = $policy->apply($dkim_verifier);

L'appelant doit fournir une instance de Mail::DKIM::Verifier, qui a déjà été alimentée avec le message à vérifier.

Les résultats possibles sont :

accept
Le message est accepté par la politique de signature d'envoi de l'expéditeur.
reject
Le message est rejeté par la politique de signature d'envoi de l'expéditeur.
neutral
Le message n'est ni accepté ni rejeté par la politique de signature d'envoi de l'expéditeur. Il peut être considéré comme suspect.

flags() - obtenir ou définir les indicateurs (t=) de la politique

Une liste d'indicateurs séparés par des tirets.

is_implied_default_policy() - cette politique est-elle implicite ?

my $is_implied = $policy->is_implied_default_policy;

Si la politique est récupérée pour un domaine spécifique, mais que ce domaine n'a pas de politique publiée, alors la politique par défaut est activée. Utilisez cette méthode pour détecter quand cela se produit.

location() - où la politique a été publiée

Les politiques DomainKeys n'ont que des politiques par domaine, donc ce sera le domaine où la politique a été publiée.

S'il n'y a pas de politique publiée pour le domaine, et que la politique par défaut a été renvoyée, l'emplacement sera "undef".

note() - obtenir ou définir les notes lisibles par l'homme (n=) de la règle

Notes lisibles par l'homme relatives à la règle. Undef si aucune note n'a été spécifiée.

policy() - obtenir ou définir la politique de signature d'envoi (o=) de l'entité

my $sp = $policy->policy;

La politique de signature d'envoi pour l'entité. Les valeurs possibles sont :

"~"
La valeur par défaut. Le domaine peut signer certains (mais pas tous) des courriels.
"-"
Le domaine signe tous les courriels.

signall() - vrai si la politique est /-"

testing() - vérifie l'indicateur de test

my $testing = $policy->testing;

Si différent de zéro, l'indicateur de test est défini dans la politique de signature d'envoi, et le vérificateur ne doit pas considérer un message comme suspect sur la base de cette politique.
