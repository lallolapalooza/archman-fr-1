NAME

Mail::Identity - un rôle de courrier électronique

INHERITANCE

Mail::Identity
  hérite de User::Identity::Item

SYNOPSIS

use User::Identity;
use Mail::Identity;
my $moi  = User::Identity->new(...);
my $addr = Mail::Identity->new(address => 'x@y');
$moi->add(email => $addr);
# Simplifié
use User::Identity;
my $moi  = User::Identity->new(...);
my $addr = $moi->add(email => 'x@y');
my $addr = $moi->add(email => 'home', address => 'x@y');
# Conversion
my $ma   = Mail::Address->new(...);
my $mi   = Mail::Identity->coerce($ma);

DESCRIPTION

L'objet "Mail::Identity" contient la description du rôle qu'un humain joue lorsqu'il envoie un e-mail. La plupart des gens ont plus d'un rôle aujourd'hui : par exemple, un rôle privé et un rôle professionnel avec différentes adresses e-mail.

Un objet "Mail::Identity" combine une adresse e-mail, une description de l'utilisateur ("phrase"), une signature, une clé PGP, et d'autres. Tous les champs sont optionnels et certains sont intelligents. Un tel ensemble de données représente un rôle. "Mail::Identity" est donc le frère intelligent de l'objet "Mail::Address".

Attributs

Hérite de "Attributes" de User::Identity::Item.

$obj->address()
Retourne l'adresse e-mail pour ce rôle. Si elle n'est pas spécifiée, elle est construite à partir de l'utilisateur et du domaine. Si ceux-ci ne sont pas définis, le name() est utilisé s'il contient un "@", sinon le pseudonyme de l'utilisateur est pris.
$obj->charset()
Retourne le jeu de caractères utilisé dans le commentaire et la phrase. Lorsqu'il est défini à "undef", les chaînes (elles sont déjà codées en) ne contiennent que des caractères ASCII. Ceci prédomine sur la valeur du jeu de caractères de l'utilisateur, si elle est définie.
$obj->comment( [STRING] )
L'adresse e-mail - lorsqu'elle est incluse dans les en-têtes MIME d'un message - peut contenir un commentaire. Les RFC vous avertissent de ne pas stocker d'informations utiles dans ces commentaires, mais si vous le souhaitez, vous pouvez le faire. Le commentaire par défaut est le nom complet de l'utilisateur si la phrase n'est pas le nom complet et qu'un utilisateur est défini.

Les commentaires sont encadrés par des parenthèses lorsqu'ils sont utilisés. Les parenthèses (coïncidentes) ou non qui sont déjà dans la chaîne seront soigneusement échappées lorsque nécessaire. Vous n'avez pas à vous en soucier.

$obj->description()
Hérité, voir "Attributes" dans User::Identity::Item
$obj->domain()
Le domaine est la partie de l'adresse e-mail après le signe "@". Lorsqu'il n'est pas défini, il peut être déduit de l'adresse e-mail (voir address()). Si rien n'est connu, "localhost" est retourné.
$obj->language()
Retourne la langue utilisée pour les champs de description de cette adresse e-mail, ce qui prédomine sur la langue de l'utilisateur.
$obj->location()
Retourne l'objet décrivant à quel lieu cette adresse e-mail correspond. Le lieu peut être utilisé pour trouver le nom de l'organisation impliquée, ou pour créer une signature. Si aucun lieu n'est spécifié, mais qu'un utilisateur avec des lieux est défini, l'un d'eux est choisi au hasard.
$obj->name( [$newname] )
Hérité, voir "Attributes" dans User::Identity::Item
$obj->organization()
Retourne l'organisation qui est liée à cette identité e-mail. Si elle n'est pas explicitement spécifiée, on essaie de la trouver via le lieu.
$obj->phrase()
La phrase est utilisée dans une adresse e-mail pour expliquer qui envoie le message. Il s'agit généralement du nom complet (le nom complet de l'utilisateur est utilisé par défaut), d'une description de votre rôle (Webmaster), ou de tout texte supplémentaire.

Lorsqu'une chaîne de courrier est générée, la phrase est citée si nécessaire. Les guillemets à l'intérieur de la chaîne seront automatiquement échappés, vous n'avez donc pas à vous en soucier : l'entrée ne peut pas casser la sortie !

$obj->username()
Retourne le nom d'utilisateur de cette adresse e-mail. S'il n'est pas spécifié, on essaie de l'extraire de l'adresse e-mail spécifiée. S'il n'y a pas non plus de nom dans l'adresse e-mail, le pseudonyme de l'identité de l'utilisateur est pris.

DIAGNOSTICS

Erreur : $object n'est pas une collection.
Le premier argument est un objet, mais pas d'une classe qui hérite de User::Identity::Collection. À caster par addCollection()
Erreur : Impossible de charger le module de collection pour $type ($class).
Soit le $type spécifié n'existe pas, soit le module nommé $class renvoie des erreurs de compilation. Si le type tel que spécifié dans l'avertissement n'est pas le nom d'un package, vous avez spécifié un surnom qui n'a pas été défini. Peut-être avez-vous oublié de 'require' le package qui définit le surnom. À caster par addCollection()
Erreur : La création d'une collection via $class a échoué.
La classe $class a été compilée, mais il n'a pas été possible de créer un objet de cette classe en utilisant les options que vous avez spécifiées. À caster par addCollection()
Erreur : Je ne sais pas quel type de collection vous voulez ajouter.
Si vous ajoutez une collection, ce doit être soit un objet de collection, soit une liste d'options qui peuvent être utilisées pour créer un objet de collection. Dans ce dernier cas, le type de collection doit être spécifié. À caster par addCollection()
Avertissement : La collection $name n'existe pas
La collection avec le nom $name n'existe pas et ne peut pas être créée. À caster par add()
