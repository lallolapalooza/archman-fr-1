NOM

Mail::DKIM::AuthorDomainPolicy - représente un enregistrement de politique de signature de domaine (ADSP)

VERSION

version 1.20240923

DESCRIPTION

L'enregistrement de politique de signature de domaine (ADSP) peut être publié par n'importe quel domaine pour aider un destinataire à savoir quoi faire lorsqu'il rencontre un message non signé qui prétend provenir de ce domaine.

L'enregistrement est publié sous forme d'enregistrement TXT à _adsp._domainkey.DOMAIN où DOMAIN est le domaine de l'e-mail "From" du message.

Plus de détails sur cet enregistrement peuvent être trouvés en lisant le schéma lui-même à http://tools.ietf.org/html/rfc5617.

CONSTRUCTEURS

fetch()

Récupère un enregistrement ADSP depuis le DNS.

my $policy = Mail::DKIM::AuthorDomainPolicy->fetch(
          Protocol => 'dns',
          Author => 'jsmith@example.org',
        );

Si l'enregistrement ADSP est trouvé et semble valide, un objet contenant les informations de cet enregistrement sera construit et renvoyé. Si l'enregistrement ADSP est vide ou simplement absent, un objet représentant la politique par défaut sera renvoyé. (Voir aussi is_implied_default_policy()). Si une erreur DNS survient (par exemple, SERVFAIL ou timeout), cette méthode échouera.

new()

Crée un objet de politique par défaut.

my $policy = Mail::DKIM::AuthorDomainPolicy->new;

parse()

Construit un enregistrement ADSP à partir d'une chaîne.

my $policy = Mail::DKIM::AuthorDomainPolicy->parse(
        String => 'dkim=all',
        Domain => 'aaa.example',
    );

MÉTHODES

apply()

Applique la politique aux résultats d'un vérificateur DKIM.

my $result = $policy->apply($dkim_verifier);

L'appelant doit fournir une instance de Mail::DKIM::Verifier qui a déjà été alimentée avec le message à vérifier.

Les résultats possibles sont :

accepter
Le message est approuvé par la politique de signature de l'expéditeur.
rejeter
Le message est rejeté par la politique de signature de l'expéditeur. Il peut être considéré comme très suspect.
neutre
Le message n'est ni accepté ni rejeté par la politique de signature de l'expéditeur. Il peut être considéré comme suspect.

Note : à l'avenir, ces valeurs peuvent être remplacées par :

none
Aucun enregistrement ADSP n'est publié.
pass
Une signature réussie est présente.
fail
L'enregistrement ADSP est "all" et aucune signature réussie n'est trouvée.
discard
L'enregistrement ADSP est "discardable" et aucune signature réussie n'est trouvée.
nxdomain
Le domaine n'existe pas en DNS.
temperror
Une erreur temporaire s'est produite.
permerror
Une erreur non temporaire s'est produite.

is_implied_default_policy()

Détermine si cette politique implique la politique par défaut.

my $is_implied = $policy->is_implied_default_policy;

Si vous récupérez la politique pour un domaine spécifique, mais que ce domaine n'a pas de politique publiée, alors la politique par défaut est en vigueur. Utilisez cette méthode pour détecter quand cela se produit.

location()

Indique où la politique a été obtenue.

Si la politique concerne l'ensemble du domaine, ce sera le domaine où la politique a été publiée.

Si la politique est spécifique à l'utilisateur, TBD.

S'il n'y a pas de politique publiée pour le domaine et que la politique par défaut a été renvoyée, la localisation sera "undef".

policy()

Obtient ou définit la politique de signature sortante (dkim=) de l'entité.

my $sp = $policy->policy;

La politique de signature sortante pour l'entité. Les valeurs possibles sont :

"unknown"
La valeur par défaut. L'entité peut signer certains ou tous les e-mails.
"all"
Tous les e-mails de ce domaine sont censés être signés, en utilisant une signature d'auteur valide, mais l'auteur ne suggère pas de rejeter les e-mails non signés valides.
"discardable"
Tous les e-mails de ce domaine sont censés être signés, en utilisant une signature d'auteur valide, et l'auteur est tellement confiant que le serveur de messagerie du destinataire peut automatiquement rejeter les e-mails non signés.
"NXDOMAIN"
Le domaine est hors de portée, c'est-à-dire que le domaine n'existe pas en DNS.

signall()

Vrai si la politique est "all".

signall_discardable()

Vrai si la politique est "strict".

BOGUES

•
La section 4.3 du schéma indique qu'il faut interroger le domaine lui-même pour voir s'il existe. Cette classe ne le fait pas, c'est-à-dire qu'elle pourrait signaler NXDOMAIN parce que _adsp._domainkey.example.org n'existe pas, mais il ne faut pas le traiter de la même manière que si example.org n'existait pas.
