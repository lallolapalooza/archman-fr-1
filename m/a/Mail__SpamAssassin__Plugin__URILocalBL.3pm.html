NOM

URILocalBL - bloquer les URI en utilisant des informations locales (noms de FAI, listes d'adresses et codes de pays)

SYNOPSIS

Ce plugin crée de nouveaux types de tests de règles, tels que "uri_block_cc", "uri_block_cidr" et "uri_block_isp". Ces règles s'appliquent aux URI trouvés dans la partie HTML d'un message, c'est-à-dire le balisage <a href=...>.

loadplugin    Mail::SpamAssassin::Plugin::URILocalBL

Pourquoi une liste de blocage locale ? Il existe d'excellentes listes DNSBL efficaces et bien entretenues. Mais elles présentent plusieurs inconvénients :

  • les listes de blocage peuvent couvrir des dizaines de milliers d'entrées, et vous ne pouvez pas sélectionner celles que vous utilisez ;
  • la vérification de leur configuration correcte peut être non triviale ;
  • les nouvelles entrées de listes de blocage peuvent mettre du temps à être détectées et saisies, ce n'est donc pas instantané.

Parfois, tout ce que vous voulez, c'est une liste de blocage rapide, facile et très chirurgicale d'un site particulier ou d'un FAI particulier. Ce plugin est défini pour ce cas d'utilisation exact.

DÉFINITIONS DE RÈGLES ET PARAMÈTRES PRIVILÉGIÉS

Le format pour définir une règle est le suivant :

uri_block_cc NOM_TEST_SYMBOLIQUE cc1 cc2 cc3 cc4 ..
uri_block_cc NOM_TEST_SYMBOLIQUE !cc1 !cc2 ..

ou :

uri_block_cont NOM_TEST_SYMBOLIQUE co1 co2 co3 co4 ..
uri_block_cont NOM_TEST_SYMBOLIQUE !co1 !co2 ..

ou :

uri_block_cidr NOM_TEST_SYMBOLIQUE a.a.a.a b.b.b.b/cc

ou :

uri_block_isp NOM_TEST_SYMBOLIQUE "Data Rancid" McCarrier Phishers-r-Us

Exemple de règle pour correspondre à un URI en Chine :

uri_block_cc TEST1 cn

Si vous spécifiez une liste de négations, une telle règle correspondra à TOUT pays SAUF ceux listés (Finlande, Suède) :

uri_block_cc TEST1 !fi !se

Les continents uri_block_cont fonctionnent exactement comme uri_block_cc.

Cela bloquerait l'URL http://www.baidu.com/index.htm. De même, pour faire correspondre un bloc de réseau « Spam-haven » :

uri_block_cidr TEST2 65.181.64.0/18

correspondrait à un bloc de réseau où plusieurs sites de phishing ont été hébergés récemment.

Et pour bloquer tous les blocs CIDR enregistrés auprès d'un FAI, on peut utiliser :

uri_block_isp TEST3 "Data Rancid" ColoCrossing

Guillemets des noms de FAI contenant des espaces.

Enfin, s'il existe un pays que vous souhaitez bloquer mais qu'il y a un hôte explicite que vous souhaitez exempter de cette liste de blocage, vous pouvez utiliser :

uri_block_exclude TEST1 www.baidu.com

si vous souhaitez exempter les URL faisant référence à cet hôte. La même syntaxe est applicable aux blocs CIDR et FAI.

DÉPENDANCES

Le filtrage basé sur le code pays peut utiliser n'importe quel module supporté par Mail::SpamAssassin::GeoDB comme MaxMind::DB::Reader (GeoIP2) ou Geo::IP. Le filtrage basé sur les FAI peut nécessiter une base de données sur abonnement payant comme GeoIPISP.
