NOM

Mail::Message::Construct::Build - construire un message de courrier

SYNOPSIS

my $msg1 = Mail::Message->build(
  From => 'me',
  data => 'only two\nlines\n',
);
my $msg2 = Mail::Message->buildFromBody($body);
Mail::Message->build(
  From     => 'me@myhost.com',
  To       => 'you@yourhost.com',
  Subject  => 'Read our folder!',
  data     => \@lines,
  file     => 'folder.pdf',
)->send(via => 'postfix');

DESCRIPTION

La fonctionnalité complexe dans les objets Mail::Message est implémentée dans différents fichiers qui sont chargés automatiquement. Ce fichier implémente la construction de messages à partir de composants plus simples.

MÉTHODES

Construire un message

$class->build( [$message|$part|$body], @fields, %options )
Constructeur d'objet de message simplifié. Si un $message ou un $part est spécifié, un nouveau message est créé avec le même corps, mais avec de nouvelles en-têtes. Un $body peut également être spécifié. Cependant, il existe d'autres moyens d'ajouter des données simplement.

Vous pouvez passer @fields comme objets, même mélangés avec des paires d'options. Les champs sont envoyés dans l'ordre où ils ont été créés, ce qui peut être nécessaire.

Dans la liste de %options, les champs commençant par une majuscule sont utilisés comme lignes d'en-tête. Les champs en minuscules sont utilisés à d'autres fins, comme listé ci-dessous. Chaque champ peut être utilisé plus d'une fois. Les paires où la valeur est undef sont ignorées.

Si plus d'un $data, $file ou $attach est spécifié, un message multi-parties est créé. Certains champs de type "Content-*" sont traités séparément : pour forcer les lignes du corps du message produit, celles-ci doivent être spécifiées après la création du corps. Par exemple, pour spécifier explicitement que vous voulez un $multipart/alternative au lieu du $multipart/mixed par défaut. Si vous voulez spécifier le type pour chaque donnée, vous devez jouer avec les objets Mail::Message::Body vous-même.

Cette méthode de construction build utilisera buildFromBody() une fois que l'objet corps a été construit. Ensemble, ils produisent votre message.

-Option-Valeur par défaut
 attach  undef
 data    undef
 file    undef
 files   [ ]
 head    undef
attach => $body|$part|$message|\@attach
Une pièce jointe au message. Chaque pièce jointe peut être un $message, un $part ou un $body. Tout $message est encapsulé dans un corps $message/rfc822. Vous pouvez spécifier plusieurs éléments (pouvant être de types différents) en même temps.
data => $text|\@lines
Le $text pour une partie, spécifié comme une chaîne, ou un ARRAY de @lines. Chaque ligne, y compris la dernière, doit se terminer par un saut de ligne. Cet argument est passé à Mail::Message::Body::new(data) pour construire un corps.
file => $file|$fh|$io|\@files
Crée un corps où les données sont lues à partir du fichier spécifié par nom, d'un descripteur de fichier $fh ou d'un objet $io de type IO::Handle. Ce corps est également utilisé pour créer un Mail::Message::Body. [2.119] Vous pouvez même passer plusieurs fichiers en même temps : 'file' et 'files' sont équivalents.
files => \@files
Alias de l'option "file".
head => $head
Commence avec une en-tête préparée, sinon une est créée.

» exemple :

my $msg = Mail::Message->build(
  From    => 'me@home.nl',
  To      => Mail::Address->new('your name', 'you@yourplace.aq'),
  Cc      => 'everyone@example.com',
  Subject => 'Let\'s talk',
  $other_message->get('Bcc'),
  data   => [ 'This is\n', 'the first part of\n', 'the message\n' ],
  file   => 'myself.gif',
  file   => 'you.jpg',
  attach => $signature,
);
my $msg = Mail::Message->build(
  To     => 'you',
  'Content-Type' => 'text/html',
  data   => '<html></html>',
);
$class->buildFromBody($body, [$head], $headers)
Forme un message autour d'un $body. Les corps ont des informations sur leur contenu qui sont utilisées pour construire l'en-tête du message. Vous pouvez spécifier un objet $head pré-initialisé, ou un est créé pour vous (même lorsque $head est undef). De plus, plusieurs $headers peuvent être spécifiés qui seront stockés dans cette en-tête.

Les champs d'en-tête sont ajoutés dans l'ordre et avant les lignes d'en-tête définies par le corps. Ils peuvent être fournis sous forme de paires clé-valeur ou d'objets Mail::Message::Field. Dans le cas d'une paire clé-valeur, le nom du champ est utilisé comme clé et la valeur est une chaîne, une adresse (objet Mail::Address) ou une liste d'adresses.

Les champs de type Date, Message-Id et MIME-Version sont ajoutés sauf s'ils sont spécifiés.

» exemple :

my $type = Mail::Message::Field->new('Content-Type', 'text/html',
'charset="us-ascii"');
my @to   = (
  Mail::Address->new('Your name', 'you@example.com'),
  'world@example.info',
);
my $msg  = Mail::Message->buildFromBody($body,
From => 'me@example.nl',
To   => \@to,
$type,
);

DÉTAILS

Construire un message

Construction rapide

Les messages que vous devez construire sont relativement simples. Pour cette raison, ce module fournit une méthode pour préparer un message en un seul appel de méthode : build().

Comparé àMIME::Entity::build()

La méthode build() dans MailBox est modelée sur la méthode build() de MIMETools, mais avec quelques simplifications :

Quand une clé commence par une majuscule, c'est toujours un champ d'en-tête
Quand une clé est en minuscules, c'est toujours autre chose
J'utilise les noms réels des champs, pas des abréviations
Tous les noms de champs sont acceptés
Vous pouvez spécifier des objets de champ entre des paires clé-valeur
De nombreux facteurs sont auto-détectés, tels que le type de contenu et le codage
Vous pouvez créer un multipart en une seule étape

Qu'est-ce qui est équivalent ? MIME::Entity n'est pas si simple après tout ! Jetons un coup d'œil à un exemple de MIME::E...
