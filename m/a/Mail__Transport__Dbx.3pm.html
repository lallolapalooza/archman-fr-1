NOM

Mail::Transport::Dbx - Analyse les boîtes aux lettres d'Outlook Express

SYNOPSIS

use Mail::Transport::Dbx;
my $dbx = eval { Mail::Transport::Dbx->new("box.mbx") };
die $@ if $@;

for my $i (0 .. $dbx->msgcount - 1) {
    my $msg = $dbx->get($i);
    print $msg->subject;
    ...
}
# plus pratique
for my $msg ($dbx->emails) {
    print $msg->subject;
    ...
}

RÉSUMÉ

Lire les fichiers dbx (fichiers de boîte aux lettres d'Outlook Express)

DESCRIPTION

Mail::Transport::Dbx vous offre un accès indépendant de la plateforme aux fichiers .dbx d'Outlook Express. Extrayez les sous-dossiers, les messages, etc., de ceux-ci ou utilisez-le pour convertir les archives .dbx dans un format plus portable (tel que le format mbox standard).

Il s'appuie sur LibDBX pour faire son travail. La mauvaise nouvelle : LibDBX ne connaît pas l'endianness de votre machine, il ne fonctionne donc pas sur les machines big-endian comme Macintosh ou SUN. La bonne nouvelle : j'ai fait les correctifs appropriés pour qu'il fonctionne même sur les machines avec un ordre d'octets 'incorrect' (exception : les machines avec un ordre d'octets encore plus étrange comme les Cray ne sont pas supportées ; exception à l'exception : Si vous m'achetez un Cray, je promets de le corriger. :-)).

Vous devez comprendre la structure des fichiers .dbx pour utiliser ce module correctement. Outlook Express conserve plusieurs de ces fichiers sur votre disque dur. Par exemple :

Folders.dbx
folder1.dbx
comp.lang.perl.misc.dbx

La chose désagréable à ce sujet est qu'il existe en réalité deux types différents de tels fichiers : un qui contient les messages réels et un autre qui ne contient que des références à d'autres fichiers .dbx. Folders.dbx pourrait être considéré comme le fichier de niveau supérieur puisqu'il liste tous les autres fichiers .dbx disponibles. Quant à folder1.dbx et comp.lang.perl.misc.dbx, vous ne pouvez pas encore savoir s'ils contiennent des messages ou des sous-dossiers (bien que comp.lang.perl.misc.dbx contienne probablement des messages de newsgroups qui sont traités comme de simples emails).

Heureusement, ce module vous donne les informations dont vous avez besoin. Une approche courante serait la suivante :

1) créez un nouvel objet Mail::Transport::Dbx à partir de "Folders.dbx"

2) itérez sur ses éléments en utilisant la méthode get()
    2.1 si elle renvoie un Mail::Transport::Dbx::Email  
        => un message
    2.2 si elle renvoie un Mail::Transport::Dbx::Folder 
        => un dossier

3) si c'est un message
    3.1 appelez la méthode nécessaire de Mail::Transport::Dbx::Email 
        dont vous avez besoin

4) si c'est un dossier
    4.1 appelez la méthode nécessaire de Mail::Transport::Dbx::Folder 
        dont vous avez besoin
    OU
    4.2 appelez dbx() dessus pour créer un nouvel objet Mail::Transport::Dbx 
        4.2.1 si dbx() a retourné quelque chose de défini
              => revenir à l'étape 2)

La chose déroutante est que les fichiers .dbx peuvent contenir des références à d'autres dossiers qui n'existent pas réellement ! Si Outlook Express a été utilisé comme client de newsgroups, c'est un scénario courant car Folders.dbx liste tous les groupes de news comme des objets "Mail::Transport::Dbx::Folder" séparés, que vous soyez abonné à l'un d'entre eux ou non. Ainsi, en substance, appeler dbx() sur un dossier ne retournera un nouvel objet que si le fichier .dbx correspondant existe.

MÉTHODES

Voici les méthodes pour les objets Mail::Transport::Dbx :

new(filename)
new(filehandle-ref)
En recevant soit une chaîne de caractères étant le nom du fichier, soit une référence à un descripteur de fichier déjà ouvert et lisible, new() construira un objet Mail::Transport::Dbx à partir de celui-ci.

Cela se produit, que vous ouvriez un fichier .dbx ordinaire ou le fichier spécial Folders.dbx qui contient un aperçu de tous les sous-dossiers .dbx disponibles.

Si l'ouverture échoue pour une raison quelconque, votre programme mourra instantanément, alors assurez-vous d'envelopper le constructeur dans un eval() et de vérifier $@ :

my $dbx = eval { Mail::Transport::Dbx->new( "file.dbx" ) };
die $@ if $@;

Soyez prudent avec l'utilisation d'un descripteur de fichier, cependant. Sur Windows, vous devrez peut-être utiliser binmode() sur votre descripteur ou sinon le flux de votre fichier .dbx pourrait être corrompu.

msgcount
Retourne le nombre d'éléments stockés dans la structure dbx. Si vous avez précédemment ouvert Folders.dbx, msgcount() retourne le nombre de sous-dossiers qu'il contient. Sinon, il retourne le nombre de messages. "msgcount() - 1" est l'indice du dernier élément.
emails
En contexte de liste, cette méthode retourne tous les emails contenus dans le fichier. En contexte booléen (c'est-à-dire scalaire), elle retourne une valeur vraie si le fichier contient des emails et une valeur fausse s'il contient des sous-dossiers. 
if ($dbx->emails) {
    print "Je contiens des emails";
} else {
    print "Je contiens des sous-dossiers";
}

Ceci est utile pour les itérations :

for my $msg ($dbx->emails) {
    ...
}
subfolders
En contexte de liste, cette méthode retourne tous les sous-dossiers du fichier courant sous forme d'objets "Mail::Transport::Dbx::Folder". En contexte booléen (scalaire), elle retourne vrai si le fichier contient des sous-dossiers et faux s'il contient des emails.

N'oubliez pas que vous devez toujours appeler dbx() sur ces sous-dossiers si vous voulez faire quelque chose d'utile avec eux :

for my $sub ($dbx->subfolders) {
    if (my $d = $sub->dbx) {
        # $d est maintenant un objet Mail::Transport::Dbx valide 
        # avec du contenu
    } else {
        print "Sous-dossier référencé mais inexistant";
    }
}
get(n)
Récupère l'élément à la n-ième position. Le premier élément est à la position 0. get() est en fait une méthode usine, elle retourne donc soit un objet "Mail::Transport::Dbx::Email", soit un objet "Mail::Transport::Dbx::Folder". Cela dépend du dossier sur lequel vous appelez cette méthode : 
my $dbx  = Mail::Transport::Dbx->new( "Folders.dbx" );
my $item = $dbx->get(0);

$item sera maintenant certainement un objet "Mail::Transport::Dbx::Folder" puisque Folders.dbx ne contient pas d'emails mais des références à des sous-dossiers.

Vous pouvez utiliser les méthodes is_email() et is_folder() pour vérifier son type :

if ($item->is_email) {
    print $item->subject;
} else {
    # c'est un sous-dossier
    ...
}

En cas d'erreur, cette méthode retourne une valeur indéfinie. Vérifiez "$dbx->errstr" pour savoir ce qui s'est mal passé.

errstr
Chaque fois qu'une erreur se produit, errstr() contiendra une chaîne vous donnant une aide supplémentaire sur ce qui s'est mal passé.

ATTENTION : Il s'appuie en interne sur une variable globale, donc tous les objets auront la même chaîne d'erreur ! Cela signifie qu'il n'est logique de l'utiliser qu'après une opération qui pourrait potentiellement déclencher une erreur :

# exemple 1
my $dbx = Mail::Transport::Dbx->new("box.dbx")
    or die Mail::Transport::Dbx->errstr;
# exemple 2
my $msg = $dbx->get(5) or print $dbx->errstr;
error
Similaire à errstr(), seulement il retournera un code d'erreur. Voir "Constantes exportables / Codes d'erreur" sous "EXPORT" pour les codes qui peuvent être retournés.

Voici les méthodes pour les objets Mail::Transport::Dbx::Email :

as_string
Retourne le message entier (en-tête et corps) sous forme d'une seule longue chaîne.

Notez que la chaîne contient toujours les sauts de ligne bruts tels qu'utilisés par les systèmes de type DOS (\015\012). Si vous souhaitez que les sauts de ligne soient représentés dans le format natif de votre système d'exploitation, utilisez ce qui suit :

my $email = $msg->as_string;
$email =~ s/\015\012/\n/g;

Constantes exportables

Si vous souhaitez utiliser l'une des constantes suivantes, vous devez les importer lorsque vous utilisez le module avec use(). Vous pouvez toutes les importer en une seule fois en utilisant :

use Mail::Transport::Dbx qw(:all);

Ou n'importez que celles dont vous avez besoin :

use Mail::Transport::Dbx qw(DBX_TYPE_EMAIL DBX_TYPE_FOLDER);
Codes d'erreur
  • DBX_NOERROR
  • DBX_BADFILE
  • DBX_DATA_READ
  • DBX_INDEXCOUNT
  • DBX_INDEX_OVERREAD
  • DBX_INDEX_UNDERREAD
  • DBX_INDEX_READ
  • DBX_ITEMCOUNT
  • DBX_NEWS_ITEM
Types Dbx
L'une de ces valeurs est retournée par "$folder->type" pour savoir si le dossier contient des e-mails ou des sous-dossiers. Notez que seuls DBX_TYPE_EMAIL et DBX_TYPE_FOLDER sont retournés, donc même les newsgroups sont de type DBX_TYPE_EMAIL.

  • DBX_TYPE_FOLDER
  • DBX_TYPE_NEWS
  • DBX_TYPE_VOID
Constantes supplémentaires
  • DBX_EMAIL_FLAG_ISSEEN
  • DBX_FLAG_BODY

AVERTISSEMENTS

Il n'est pas possible de récupérer l'état interne des objets en utilisant "Data::Dumper" ou un outil similaire, car "Mail::Transport::Dbx" utilise un scalaire lié pour stocker une référence vers les structures C correspondantes. Cela signifie que vous devez utiliser les méthodes fournies pour chaque objet. Si vous avez besoin d'une dérogation à cette règle, appliquez un encapsulage fort.

Il n'est actuellement pas prévu d'implémenter l'accès en écriture aux fichiers .dbx. Je laisse cela aux auteurs de libdbx.
