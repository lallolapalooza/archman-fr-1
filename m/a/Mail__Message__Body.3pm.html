SYNOPSIS

my Mail::Message $msg = ...;
my $body  = $msg->body;
my @text  = $body->lines;
my $text  = $body->string;
my $file  = $body->file;  # IO::File
$body->print(\*FILE);

my $encoded = $body->encode(mime_type => 'text/html',
   charset => 'us-ascii', transfer_encoding => 'none');\n";

DESCRIPTION

La fonctionnalité d'encodage et de décodage d'un Mail::Message::Body est implémentée dans le package Mail::Message::Body::Encode. Ce package est chargé automatiquement lorsqu'un message doit être encodé ou décodé. Les méthodes pour simplement construire et traiter des objets de corps sont implémentées dans Mail::Message::Body::Construct.

Le corps d'un message (un objet Mail::Message) est stocké dans l'un des nombreux types de corps. La fonctionnalité de chaque type de corps est équivalente, mais il existe des différences de performance. Chaque type de corps a sa propre documentation avec des détails sur son implémentation.

Étendu de "DESCRIPTION" dans Mail::Reporter.

OVERLOADED

overload: "" stringification
Retourne le corps sous forme de chaîne — ce qui déclenchera la complétion — à moins qu'il ne soit appelé pour produire une chaîne pour "Carp". Ce dernier évite les récursions profondes.

» exemple : stringification de corps

print $msg->body;   # implicite par print
my $body = $msg->body;
my $x    = "$body"; # explicite par interpolation
overload: '==' comparaison numérique
compare si deux références pointent vers le même message. Cela ne produit des résultats corrects que si les deux arguments sont des références à des messages dans le même dossier.

» exemple : utilisation de la comparaison numérique sur un corps

my $skip = $folder->message(3);
foreach my $msg (@$folder)
{   next if $msg == $skip;
    $msg->send;
}
overload: @{} adressé comme tableau
lorsqu'un objet de corps est utilisé comme référence à un tableau, les lignes du corps sont retournées. C'est la même chose que d'utiliser lines().

» exemple : utilisation d'un corps comme tableau

print $body->lines->[1];  # deuxième ligne
print $body->[1];         # même résultat
my @lines = $body->lines;
my @lines = @$body;       # même résultat
overload: bool vrai/faux
retourne toujours une valeur "true", nécessaire pour que les objets surchargés puissent être utilisés comme dans if($body). Sinon, il faudrait utiliser "if(defined $body)" pour éviter une erreur d'exécution.

charset => CHARSET|'PERL'|<undef>
Définit l'encodage utilisé dans les données. N'est utile que lorsqu'il est combiné avec un "mime_type" qui fait référence à "text" sous quelque forme que ce soit, qui ne contient pas déjà un encodage explicite. Ce champ est insensible à la casse.

Lorsqu'un CHARSET connu est fourni et que le type MIME indique "text", le contenu est censé être des octets bruts dans cet encodage particulier (voir Encode). Si 'PERL' est fourni, le contenu est dans l'encodage interne de Perl ; soit cp1252, soit utf8. Plus de détails sur "Encodage PERL"

checked => BOOLEAN
Si les informations ajoutées n'ont pas été vérifiées pour ne pas contenir d'octets illégaux par rapport à l'encodage de transfert et au type MIME. Si non vérifié et ensuite défini comme corps d'un message, il sera converti.
content_id => STRING
Dans le contenu MIME de type "multipart/related", le "content_id" est nécessaire pour permettre l'accès au contenu associé via un descripteur de type "cid:<...>" d'une disposition inline.

Un "Content-ID" est supposé être globalement unique. Il est donc courant d'ajouter "@computer.domain" à la fin de certaines chaînes uniques. Comme les autres contenus dans le "multipart/related" ont également besoin de savoir ce qu'est ce "Content-ID", cela devrait être laissé à l'imagination de la personne qui crée le contenu (pour l'instant).

En tant que champ MIME, la chaîne "Content-ID" est censée être entre chevrons.

data => ARRAY-OF-LINES | STRING
Contenu du corps. C'est la seule façon de définir le contenu d'un corps. Par conséquent, si vous souhaitez modifier le contenu d'un message, vous devez créer un nouveau corps avec le nouveau contenu et l'ajouter au corps. La raison derrière cela est que les encodages corrects et les informations du corps doivent être garantis. Cela évite votre embarras à calculer le nombre de lignes dans le corps et à vérifier s'il y a des caractères mauvais enfermés dans le texte.

Spécifiez une référence à un ARRAY de lignes, terminé par un nouveau ligne. Ou un STRING qui peut contenir plusieurs lignes séparées et terminées par un nouveau ligne.

Le contenu de ce champ est spécifié dans la RFC 1806. Le corps du champ peut être "inline", pour indiquer que le corps est destiné à être affiché automatiquement lors de l'affichage du message. eol => 'CR'|'LF'|'CRLF'|'NATIVE'
Convertit le message pour qu'il ait la chaîne spécifiée comme terminateur de ligne pour toutes les lignes du corps. "NATIVE" est utilisé pour représenter le "\n" sur la plateforme actuelle et sera traduit par celui applicable.

ATTENTION : les dossiers avec un encodage non natif peuvent apparaître sur votre plateforme, par exemple dans des dossiers Windows gérés depuis un système UNIX. L'encodage eol a un effet sur la taille du corps !

mime_type => STRING|FIELD|MIME
Le type de données qui est ajouté. Vous pouvez spécifier un contenu de ligne d'en-tête sous forme de CHAÎNE, ou d'objet CHAMP. Vous pouvez également spécifier un objet MIME::Type. Dans tous les cas, il sera conservé en interne comme un vrai champ (un objet Mail::Message::Field). Ceci est lié au champ d'en-tête "Content-Type".

Une spécification de type mime se compose de deux parties : une classe générale ("text", "image", "application", etc.) et une sous-classe spécifique. Des exemples de classes spécifiques avec "text" sont "plain", "html", et "xml". Ce champ ne tient pas compte de la casse mais la conserve. Le type mime par défaut est "text/plain".

   transfer_encoding => 'base64');
my $body = Mail::Message::Body::Lines->new(file => 'picture.gif',
   mime_type => 'image/gif', content_id => '<12345@example.com>',
   disposition => 'inline');

Accès au contenu

$obj->endsOnNewline()
Renvoie si la dernière ligne du corps est terminée par un saut de ligne (transporté en CRLF). Un corps vide renverra "true" car le saut de ligne provient de la ligne précédente.
$obj->file()
Renvoie le contenu du corps sous forme de fichier de lecture. Le flux renvoyé peut être un fichier réel ou un fichier simulé sous une forme que Perl supporte. Bien que vous ne puissiez pas écrire dans le fichier de lecture, vous pourrez en lire.

ATTENTION : Même si le fichier de lecture supporte l'écriture, n'y écrivez pas. Si vous le faites, certaines variables internes de l'objet Mail::Message::Body pourraient ne pas être mises à jour.

$obj->lines()
Renvoie le contenu du corps sous forme de liste de lignes (en contexte LIST) ou de référence à un tableau de lignes (en contexte SCALAR). En contexte SCALAR, le tableau de lignes est mis en cache pour éviter des copies inutiles et fournir un accès rapide pour les gros messages.

Pour obtenir uniquement le nombre de lignes dans le corps, utilisez la méthode nrLines(), qui est généralement plus efficace.

ATTENTION : Pour certains types de corps, la référence pointera vers l'original. Ne modifiez pas le contenu référencé. Si vous le faites, certaines variables internes essentielles de l'objet Mail::Message::Body pourraient ne pas être mises à jour.

Exemple :

my @lines    = $body->lines;     # copie des lignes
my $line3    = ($body->lines)[3] # une seule copie
print $lines[0];
my $linesref = $body->lines;     # référence vers les originaux
my $line3    = $body->lines->[3] # une seule copie (plus rapide)
print $linesref->[0];
print $body->[0];                # par surcharge
$obj->print( [$fh] )
Imprime le corps dans le fichier $fh (par défaut dans le handle sélectionné). Un objet IO::File ou tout objet avec une méthode print() peut être utilisé. Rien n'est renvoyé.
$obj->printEscapedFrom($fh)
Imprime le corps dans le fichier $fh mais toutes les lignes commençant par 'From ' (éventuellement précédées de >) auront un > ajouté devant. Rien n'est renvoyé.
$obj->string()
Renvoie le contenu du corps sous forme de variable scalaire (une seule chaîne). Ceci est une copie des informations internes.

Exemple :

my $text = $body->string;
print "Corps : $body\n";     # par surcharge
$obj->stripTrailingNewline()
Supprime le saut de ligne de la dernière ligne, ou la dernière ligne si elle ne contient qu'un saut de ligne.
$obj->write(%options)
Écrit le contenu du corps dans un fichier. Il est cependant recommandé de déchiffrer le corps avant de l'écrire !

$obj->modified( [BOOLEAN] )
Modifie le drapeau de modification du corps. Cela forcera l'écriture du corps dans un fichier de dossier lors de sa fermeture. Il est assez dangereux de modifier le corps : le même corps peut être partagé entre plusieurs messages dans votre programme.

$obj->read( $parser, $head, $bodytype, [$chars, [$lines]] )
Lit le corps avec le $parser à partir d'un fichier. L'implémentation de cette méthode diffère selon les types de corps. Le $bodytype est un nom de classe ou une référence à une routine pouvant produire un nom de classe, et il est utilisé pour les corps multipart afin de déterminer le type de corps pour chaque partie.

L'argument $chars est le nombre estimé d'octets dans le corps, ou "undef" si non connu. Cette information peut être dérivée de l'en-tête ($Content-Length) ou de la taille du fichier.

Le deuxième argument est le nombre estimé de lignes du corps. Il est moins utile que $chars mais peut être utile pour déterminer si le séparateur de message est fiable. Cette valeur peut être trouvée dans le champ "Lines" de l'en-tête.

DÉTAILS

Accès au corps

Un corps peut être contenu dans un message, mais peut aussi exister sans message. Dans les deux cas, il stocke des données, et les mêmes questions peuvent être posées : quel type de données est-ce, combien d'octets et de lignes, quel encodage est utilisé. N'importe quel corps peut être encodé et décodé, retournant un nouvel objet de corps. Cependant, les corps qui font partie d'un message seront toujours dans une forme permettant de les écrire dans un fichier ou de les envoyer quelque part : ils seront encodés si nécessaire.

» Exemple

my $body    = Mail::Message::Body::String->new(mime_type => 'image/gif');
$body->print(\*OUT);    # ce sont des données binaires d'image...
my $encoded = $message->body($body);
$encoded->print(\*OUT); # données ASCII, image encodée

Maintenant, $encoded fait référence au corps du $message qui est le contenu de $body dans une forme qui peut être transmise. Habituellement, l'encodage "base64" est utilisé.

Implémentation de la classe Body

Le corps d'un message peut être stocké de nombreuses façons. Grossièrement, les implémentations peuvent être divisées en deux groupes : les collecteurs de données et les corps complexes. Les implémentations varient dans les façons d'accéder aux données, et sont entièrement compatibles : elles ne diffèrent que par les performances et l'empreinte mémoire dans différentes circonstances. Ces dernières sont créées pour gérer les multiparts complexes et l'extraction paresseuse.

Corps collecteurs de données

  • Mail::Message::Body::String

    L'intégralité du corps du message est stockée dans un seul scalaire. Les messages courts peuvent être contenus de cette manière sans pénalités de performance.

  • Mail::Message::Body::Lines

    Chaque ligne du corps du message est stockée comme un scalaire unique. C'est une représentation utile pour un examen détaillé du corps du message, qui est généralement organisé en lignes.

  • Mail::Message::Body::File

    Le corps du message est stocké dans un fichier temporaire externe. Ce type de stockage est particulièrement utile lorsque le corps est volumineux, le dossier total est volumineux, ou la mémoire est limitée.

  • "Mail::Message::Body::InFolder"

    PAS ENCORE IMPLÉMENTÉ. Le message est conservé dans le dossier et n'est extrait que lorsque le contenu est modifié.

  • "Mail::Message::Body::External"

    PAS ENCORE IMPLÉMENTÉ. Le message est conservé dans un fichier séparé, généralement parce que le corps du message est volumineux. La différence avec l'objet "::External" est que ce stockage externe reste ainsi entre la fermeture et l'ouverture d'un dossier. L'objet "::External" n'utilise un fichier que lorsque le dossier est ouvert.

Corps complexes

  • Mail::Message::Body::Delayed

    Le corps du message n'est pas encore lu, mais l'emplacement exact du corps est connu de sorte que le message puisse être lu au besoin. Cela fait partie du mécanisme d'extraction paresseuse. Une fois extrait, l'objet peut devenir n'importe quel corps simple ou complexe.

  • Mail::Message::Body::Multipart

    Le corps du message contient un ensemble de sous-messages (qui peuvent eux-mêmes contenir des corps multipart). Chaque sous-message est une instance de Mail::Message::Part, qui est une extension de Mail::Message.

  • Mail::Message::Body::Nested

    Messages imbriqués, comme "message/rfc822" : ils contiennent un message dans le corps. Pour la plupart des codes, ils se comportent simplement comme des multiparts.

Encodage des caractères PERL

Un objet de corps peut faire partie d'un message, ou être autonome. S'il fait partie d'un message, l'"encodage de transport" et le contenu doivent être dans une forme permettant le transport des données via SMTP.

Cependant, lorsque vous souhaitez traiter les données du corps en simple Perl (ou lorsque vous construisez les données du corps à partir de chaînes Perl normales), vous devez être conscient de la représentation interne des chaînes par Perl. Cela peut être cp1252 (latin1 étendu) ou utf8 (pas du vrai UTF-8, mais quelque chose d'approchant, voir la page de manuel perlunicode). Ainsi, avant de commencer à utiliser les données d'un message entrant, faites ceci :

my $body  = $msg->decoded;
my @lines = $body->lines;

Maintenant, le corps a le jeu de caractères 'PERL' (s'il s'agit de texte)

Lorsque vous créez un nouveau corps contenant du contenu textuel (par défaut), il sera créé avec le jeu de caractères 'PERL' à moins que vous ne spécifiiez explicitement un jeu de caractères.

my $body = Mail::Box::Body::Lines->new(data => \@lines);
# maintenant mime=text/plain, charset=PERL
my $msg  = Mail::Message->buildFromBody($body);
$msg->body($body);
$msg->attach($body);   # etc
# tous ces éléments convertiront le charset=PERL en utf-8 réel,
# cp1252 ou us-ascii, selon les caractères trouvés.

Autodétection du jeu de caractères

Cet objet "Body" représente des données faisant partie d'un message existant, ou destinées à faire partie d'un message. Le corps peut être dans deux états :

1. prêt à être traité textuellement, en utilisant les opérations de chaînes de Perl
2. octets bruts lus ou à écrire

Dans le premier cas, le contenu du corps n'a pas d'encodage de transfert dessus ("none"), et le jeu de caractères est "PERL". Dans la deuxième version, le corps peut avoir un encodage de transfert et un jeu de caractères (listé par l'IANA) dessus (par défaut "us-ascii")

En utilisant encode() (peut-être via decoded()), vous pouvez convertir les corps d'un état à un autre. En une seule opération, vous pouvez changer l'encodage de transfert, le jeu de caractères, ou s'il est au format chaîne PERL ou brut (en octets).

[3.013] Un problème sérieux survient lorsqu'une conversion est nécessaire, alors que le jeu de caractères d'entrée ou de sortie n'est pas explicitement connu. Les RFC de courrier électronique stipulent que la valeur par défaut est "us-ascii". Cependant, dans le monde réel, cela peut être n'importe quoi. Par conséquent, dans de telles situations, l'autodétection intervient.

1.
Lorsqu'un corps est lu (en utilisant Mail::Message::read() et ses semblables), le jeu de caractères peut rester indéfini jusqu'à ce que le décodage du transfert ait été appliqué. À ce moment-là, une autodétection (configurable) est appliquée ;
2.
Lorsqu'un corps est créé dans le programme, sans jeu de caractères spécifique, il utilisera 'PERL' ;
3.
Lorsqu'un corps est écrit, que le jeu de caractères demandé n'est pas spécifié, et que le jeu de caractères actuel est "PERL", alors l'autodétection est utilisée. Cela peut aboutir à "us-ascii", "cp1252" et "utf-8" ;
4.
Dans tous les autres cas, le jeu de caractères est connu donc "facile".

DIAGNOSTICS

Avertissement : Charset $name non connu
L'encodage ou le décodage du corps d'un message rencontre un jeu de caractères non compris par le module Encode de Perl. Lancé par encode()
Avertissement : Content-Transfer-Encoding `$encoding' nécessite un charset explicite, par défaut utf-8
Lancé par encode()
Avertissement : Aucun décodeur défini pour l'encodage de transfert $name.
Les données (corps du message) sont encodées d'une manière qui n'est pas actuellement comprise, par conséquent aucun décodage (ou recodage) ne peut avoir lieu. Lancé par encode()
Avertissement : Aucun encodeur défini pour l'encodage de transfert $name.
Les données (corps du message) ont été décodées, mais l'encodage requis est inconnu. Les données décodées sont retournées. Lancé par encode()
Erreur : Le paquet $package n'implémente pas $method.
Erreur fatale : le paquet spécifique (ou l'une de ses superclasses) n'implémente pas cette méthode alors qu'il le devrait. Ce message signifie que d'autres classes liées implémentent cette méthode, mais pas la classe en question. Vous devriez probablement enquêter à ce sujet et peut-être informer l'auteur du paquet. Lancé par notImplemented()
Avertissement : Terminaison de ligne inconnue $eol ignorée
Lancé par eol()
