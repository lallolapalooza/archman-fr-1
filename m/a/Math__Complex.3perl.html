Math::Complex(3perl) Guide du programmeur Perl Math::Complex(3perl)

NOM

Math::Complex - nombres complexes et fonctions mathématiques associées

SYNTAXE

use Math::Complex;
$z = Math::Complex->make(5, 6);
$t = 4 - 3*i + $z;
$j = cplxe(1, 2*pi/3);

DESCRIPTION

Ce paquet vous permet de créer et de manipuler des nombres complexes. Par défaut, Perl se limite aux nombres réels, mais une instruction "use" supplémentaire apporte un support complet des nombres complexes, ainsi qu'un ensemble complet de fonctions mathématiques typiquement associées aux nombres complexes et/ou étendues à ceux-ci.

Si vous vous demandez ce que sont les nombres complexes, ils ont été inventés pour pouvoir résoudre l'équation suivante :

x*x = -1

et par définition, la solution est notée i (les ingénieurs utilisent j à la place car i désigne généralement une intensité, mais le nom n'a pas d'importance). Le nombre i est un nombre purement imaginaire.

L'arithmétique avec les nombres purement imaginaires fonctionne comme vous vous y attendriez avec les nombres réels... il vous suffit de vous souvenir que

i*i = -1

donc vous avez :

5i + 7i = i * (5 + 7) = 12i
4i - 3i = i * (4 - 3) = i
4i * 2i = -8
6i / 2i = 3
1 / i = -i

Les nombres complexes sont des nombres qui ont à la fois une partie réelle et une partie imaginaire, et sont généralement notés :

a + bi

où "a" est la partie réelle et "b" est la partie imaginaire. L'arithmétique avec les nombres complexes est simple. Vous devez garder une trace des parties réelles et imaginaires, mais sinon les règles utilisées pour les nombres réels s'appliquent :

(4 + 3i) + (5 - 2i) = (4 + 5) + i(3 - 2) = 9 + i
(2 + i) * (4 - i) = 2*4 + 4i -2i -i*i = 8 + 2i + 1 = 9 + 2i

Une représentation graphique des nombres complexes est possible dans un plan (également appelé le plan complexe, mais c'est vraiment un plan 2D). Le nombre

z = a + bi

est le point dont les coordonnées sont (a, b). En fait, ce serait le vecteur d'origine (0, 0) au point (a, b). Il s'ensuit que l'addition de deux nombres complexes est une addition vectorielle.

Étant donné qu'il existe une bijection entre un point dans le plan 2D et un nombre complexe (c'est-à-dire que la correspondance est unique et réciproque), un nombre complexe peut également être identifié de manière unique avec des coordonnées polaires :

[rho, theta]

où "rho" est la distance à l'origine et "theta" l'angle entre le vecteur et l'axe des x. Il existe une notation pour cela en utilisant la forme exponentielle, qui est :

rho * exp(i * theta)

où i est le fameux nombre imaginaire introduit ci-dessus. La conversion entre cette forme et la forme cartésienne "a + bi" est immédiate :

a = rho * cos(theta)
b = rho * sin(theta)

ce qui est également exprimé par la formule suivante :

z = rho * exp(i * theta) = rho * (cos theta + i * sin theta)

En d'autres termes, ce sont les projections du vecteur sur les axes x et y. Les mathématiciens appellent rho la norme ou le module et theta l'argument du nombre complexe. La norme de "z" est notée ici abs(z).

La notation polaire (également connue sous le nom de représentation trigonométrique) est beaucoup plus pratique pour effectuer des multiplications et des divisions de nombres complexes, tandis que la notation cartésienne est mieux adaptée aux additions et soustractions. Les nombres réels se trouvent sur l'axe des x, et par conséquent y ou theta est zéro ou pi.

Toutes les opérations courantes qui peuvent être effectuées sur un nombre réel ont été définies pour fonctionner également sur les nombres complexes, et ne sont que des extensions des opérations définies sur les nombres réels. Cela signifie qu'elles conservent leur sens naturel lorsqu'il n'y a pas de partie imaginaire, à condition que le nombre soit dans leur ensemble de définition.

Par exemple, la routine "sqrt" qui calcule la racine carrée de son argument n'est définie que pour les nombres réels non négatifs et produit un nombre réel non négatif (c'est une application de R+ vers R+). Si nous l'autorisons à retourner un nombre complexe, elle peut être étendue aux nombres réels négatifs pour devenir une application de R vers C (l'ensemble des nombres complexes) :

sqrt(x) = x >= 0 ? sqrt(x) : sqrt(-x)*i

Elle peut également être étendue pour être une application de C vers C, tandis que sa restriction à R se comporte comme défini ci-dessus en utilisant la définition suivante :

sqrt(z = [r,t]) = sqrt(r) * exp(i * t/2)

En effet, un nombre réel négatif peut être noté "[x,pi]" (le module x est toujours non négatif, donc "[x,pi]" est réellement "-x", un nombre négatif) et la définition ci-dessus stipule que

sqrt([x,pi]) = sqrt(x) * exp(i*pi/2) = [sqrt(x),pi/2] = sqrt(x)*i

ce qui est exactement ce que nous avions défini pour les nombres réels négatifs ci-dessus. La fonction "sqrt" ne retourne qu'une des solutions : si vous voulez les deux, utilisez la fonction "root".

Toutes les fonctions mathématiques courantes définies sur les nombres réels qui sont étendues aux nombres complexes partagent cette même propriété de fonctionner comme d'habitude lorsque la partie imaginaire est nulle (sinon, elle ne serait pas appelée une extension, n'est-ce pas ?).

Une nouvelle opération possible sur un nombre complexe qui est l'identité pour les nombres réels s'appelle le conjugué, et est notée avec une barre horizontale au-dessus du nombre, ou "~z" ici.

 z = a + bi
~z = a - bi

Simple... Regardez maintenant :

z * ~z = (a + bi) * (a - bi) = a*a + b*b

Nous avons vu que la norme de "z" était notée abs(z) et était définie comme la distance à l'origine, également connue sous le nom de :

rho = abs(z) = sqrt(a*a + b*b)

donc

z * ~z = abs(z) ** 2

Si z est un nombre purement réel (c'est-à-dire "b == 0"), alors ce qui précède donne :

a * a = abs(a) ** 2

ce qui est vrai ("abs" a le sens régulier pour un nombre réel, c'est-à-dire qu'il représente la valeur absolue). Cet exemple explique pourquoi la norme de "z" est notée abs(z) : elle étend la fonction "abs" aux nombres complexes, tout en étant le "abs" régulier que nous connaissons lorsque le nombre complexe n'a effectivement pas de partie imaginaire... Ceci justifie a posteriori notre utilisation de la notation "abs" pour la norme.

OPÉRATIONS

Étant donné les notations suivantes :

z1 = a + bi = r1 * exp(i * t1)
z2 = c + di = r2 * exp(i * t2)
z = <nombre complexe ou réel quelconque>

les opérations (surchargées) suivantes sont supportées sur les nombres complexes :

z1 + z2 = (a + c) + i(b + d)
z1 - z2 = (a - c) + i(b - d)
z1 * z2 = (r1 * r2) * exp(i * (t1 + t2))
z1 / z2 = (r1 / r2) * exp(i * (t1 - t2))
z1 ** z2 = exp(z2 * log z1)
~z = a - bi
abs(z) = r1 = sqrt(a*a + b*b)
sqrt(z) = sqrt(r1) * exp(i * t/2)
exp(z) = exp(a) * exp(i * b)
log(z) = log(r1) + i*t
sin(z) = 1/2i (exp(i * z1) - exp(-i * z))
cos(z) = 1/2 (exp(i * z1) + exp(-i * z))
atan2(y, x) = atan(y / x) # En tenant compte du bon quadrant, noter l'ordre.

La définition utilisée pour les arguments complexes de atan2() est

-i log((x + iy)/sqrt(x*x+y*y))

Notez que atan2(0, 0) n'est pas bien défini.

Les opérations supplémentaires suivantes sont supportées sur les nombres réels et complexes :

Re(z) = a
Im(z) = b
arg(z) = t
abs(z) = r
cbrt(z) = z ** (1/3)
log10(z) = log(z) / log(10)
logn(z, n) = log(z) / log(n)
tan(z) = sin(z) / cos(z)
csc(z) = 1 / sin(z)
sec(z) = 1 / cos(z)
cot(z) = 1 / tan(z)
asin(z) = -i * log(i*z + sqrt(1-z*z))
acos(z) = -i * log(z + i*sqrt(1-z*z))
atan(z) = i/2 * log((i+z) / (i-z))
acsc(z) = asin(1 / z)
asec(z) = acos(1 / z)
acot(z) = atan(1 / z) = -i/2 * log((i+z) / (z-i))
sinh(z) = 1/2 (exp(z) - exp(-z))
cosh(z) = 1/2 (exp(z) + exp(-z))
tanh(z) = sinh(z) / cosh(z) = (exp(z) - exp(-z)) / (exp(z) + exp(-z))
csch(z) = 1 / sinh(z)
sech(z) = 1 / cosh(z)
coth(z) = 1 / tanh(z)
asinh(z) = log(z + sqrt(z*z+1))
acosh(z) = log(z + sqrt(z*z-1))
atanh(z) = 1/2 * log((1+z) / (1-z))
acsch(z) = asinh(1 / z)
asech(z) = acosh(1 / z)
acoth(z) = atanh(1 / z) = 1/2 * log((1+z) / (z-1))

arg, abs, log, csc, cot, acsc, acot, csch, coth, acosech,

acotanh, ont pour alias rho, theta, ln, cosec, cotan, acosec, acotan, cosech, cotanh, acosech, acotanh, respectivement. "Re", "Im", "arg", "abs", "rho", et "theta" peuvent également être utilisés comme mutateurs. Le "cbrt" ne retourne qu'une des solutions : si vous voulez les trois, utilisez la fonction "root".

La fonction root est disponible pour calculer toutes les n racines d'un nombre complexe, où n est un entier strictement positif. Il y a exactement n telles racines, retournées sous forme de liste. Obtenir le nombre que les mathématiciens appellent "j" tel que :

1 + j + j*j = 0;

est une simple affaire d'écrire :

$j = (root(1, 3))[1];

La k-ième racine pour "z = [r,t]" est donnée par :

(root(z, n))[k] = r**(1/n) * exp(i * (t + 2*k*pi)/n)

Vous pouvez retourner directement la k-ième racine en utilisant "root(z, n, k)", l'indexation commençant à zéro et se terminant à n - 1.

L'opérateur de comparaison numérique spaceship, <=>, est également défini. Afin d'assurer que sa restriction aux nombres réels soit conforme à vos attentes, la comparaison s'effectue d'abord sur la partie réelle du nombre complexe, et les parties imaginaires ne sont comparées que lorsque les parties réelles coïncident.

CRÉATION

Pour créer un nombre complexe, utilisez l'une des méthodes suivantes :

$z = Math::Complex->make(3, 4);
$z = cplx(3, 4);

si vous connaissez la forme cartésienne du nombre, ou

$z = 3 + 4*i;

si vous préférez. Pour créer un nombre sous forme polaire, utilisez l'une des méthodes suivantes :

$z = Math::Complex->emake(5, pi/3);
$x = cplxe(5, pi/3);

respectivement. Le premier argument est le module, le second est l'angle (en radians, le cercle complet vaut 2*pi). (Mnémonique : "e" est utilisé comme notation pour les nombres complexes sous forme polaire).

Il est possible d'écrire :

$x = cplxe(-3, pi/4);

mais cela sera silencieusement converti en "[3,-3pi/4]", car le module doit être non négatif (il représente la distance à l'origine dans le plan complexe).

Il est également possible d'avoir un nombre complexe comme argument des méthodes "make", "emake", "cplx" et "cplxe" : le composant approprié de l'argument sera utilisé.

$z1 = cplx(-2,  1);
$z2 = cplx($z1, 4);

Les méthodes "new", "make", "emake", "cplx", et "cplxe" comprendront également un seul argument (chaîne de caractères) des formes :

2-3i
-3i
[2,3]
[2,-3pi/4]
[2]

auquel cas les composants cartésiens et exponentiels appropriés seront analysés à partir de la chaîne et utilisés pour créer de nouveaux nombres complexes. Le composant imaginaire et l'angle thêta, respectivement, seront initialisés à zéro par défaut.

Les méthodes "new", "make", "emake", "cplx", et "cplxe" comprendront également le cas où aucun argument n'est fourni : cela signifie zéro pur ou (0, 0).

AFFICHAGE

Lorsqu'il est imprimé, un nombre complexe est généralement affiché sous sa forme cartésienne a+bi, mais il existe des cas légitimes où la forme polaire [r,t] est plus appropriée. Le processus de conversion du nombre complexe en une chaîne de caractères pouvant être affichée est appelé stringification.

En appelant la méthode de classe "Math::Complex::display_format" et en fournissant soit "polar" soit "cartesian" comme argument, vous remplacez le style d'affichage par défaut, qui est "cartesian". Ne pas fournir d'argument retourne les réglages actuels.

Cette valeur par défaut peut être remplacée sur une base par nombre en appelant la méthode "display_format" à la place. Comme précédemment, ne pas fournir d'argument retourne le style d'affichage actuel pour ce nombre. Sinon, tout ce que vous spécifiez sera le nouveau style d'affichage pour ce nombre particulier.

Par exemple :

use Math::Complex;
Math::Complex::display_format('polar');
$j = (root(1, 3))[1];
print "j = $j\n";               # Imprime "j = [1,2pi/3]"
$j->display_format('cartesian');
print "j = $j\n";               # Imprime "j = -0.5+0.866025403784439i"

Le style polaire tente de mettre en évidence les angles comme k*pi/n (où n est un entier positif et k un entier compris entre -9 et +9), c'est ce qu'on appelle l'impression polaire esthétique (polar pretty-printing).

Pour l'opération inverse de la stringification, voir "make" et "emake".

MODIFIÉ DANS PERL 5.6

La méthode de classe "display_format" et la méthode d'objet correspondante "display_format" peuvent maintenant être appelées en utilisant une table de hachage de paramètres au lieu d'un seul paramètre.

L'ancien style de format d'affichage, qui peut avoir les valeurs "cartesian" ou "polar", peut être modifié en utilisant le paramètre "style".

$j->display_format(style => "polar");

La convention d'appel avec un seul paramètre fonctionne toujours.

$j->display_format("polar");

Il y a deux nouveaux paramètres d'affichage.

Le premier est "format", qui est une chaîne de formatage de style sprintf() à utiliser pour les deux parties numériques du (des) nombre(s) complexe(s). Ceci est quelque peu dépendant du système mais correspond le plus souvent à "%.15g". Vous pouvez revenir à la valeur par défaut en définissant le "format" sur "undef".

# le $j de l'exemple ci-dessus
$j->display_format('format' => '%.5f');
print "j = $j\n";               # Imprime "j = -0.50000+0.86603i"
$j->display_format('format' => undef);
print "j = $j\n";               # Imprime "j = -0.5+0.86603i"

Notez que cela affecte également les valeurs de retour des méthodes "display_format" : en contexte de liste, la table de hachage de paramètres entière sera retournée, contrairement à la seule valeur du paramètre style. Ceci constitue une incompatibilité potentielle avec les versions antérieures si vous avez appelé la méthode "display_format" en contexte de liste.

Le deuxième nouveau paramètre d'affichage est "polar_pretty_print", qui peut être défini à vrai ou faux, la valeur par défaut étant vrai. Voir la section précédente pour ce que cela signifie.

UTILISATION

Grâce à la surcharge, la gestion des opérations arithmétiques avec les nombres complexes est simple et presque transparente.

Voici quelques exemples :

use Math::Complex;
$j = cplxe(1, 2*pi/3);  # $j ** 3 == 1
print "j = $j, j**3 = ", $j ** 3, "\n";
print "1 + j + j**2 = ", 1 + $j + $j**2, "\n";
$z = -16 + 0*i;                 # Force à être complexe
print "sqrt($z) = ", sqrt($z), "\n";
$k = exp(i * 2*pi/3);
print "$j - $k = ", $j - $k, "\n";
$z->Re(3);                      # Re, Im, arg, abs,
$j->arg(2);                     # (les deux derniers alias rho, theta)
                                # peuvent être utilisés aussi comme mutateurs.

CONSTANTES

PI

La constante "pi" et quelques multiples pratiques (pi2, pi4, et pip2 (pi/2) et pip4 (pi/4)) sont également disponibles si exportées séparément :

use Math::Complex ':pi';
$third_of_circle = pi2 / 3;

Inf

L'infini en virgule flottante peut être exporté sous forme de sous-routine Inf() :

use Math::Complex qw(Inf sinh);
my $AlsoInf = Inf() + 42;
my $AnotherInf = sinh(1e42);
print "$AlsoInf est $AnotherInf\n" if $AlsoInf == $AnotherInf;

Notez que la forme stringifiée de l'infini varie selon les plateformes : elle peut par exemple être l'une des suivantes :

inf
infinity
INF
1.#INF

ou autre chose.

Notez également que sur certaines plateformes, tenter d'utiliser l'infini dans des opérations arithmétiques peut entraîner un crash de Perl car l'utilisation d'un infini déclenche l'envoi de SIGFPE ou de son équivalent moral. La manière de l'ignorer est :

local $SIG{FPE} = sub { };

ERREURS LIÉES À LA DIVISION PAR ZÉRO OU AU LOGARITHME DE ZÉRO

La division (/) et les fonctions suivantes

log     ln      log10   logn
tan     sec     csc     cot
atan    asec    acsc    acot
tanh    sech    csch    coth
atanh   asech   acsch   acoth

ERREURS DUES À UNE DIVISION PAR ZÉRO OU AU LOGARITHME DE ZÉRO

L'argument de "log" ne peut pas être 0 (zéro). L'argument de "sqrt" ne peut pas être -1 (moins un). Pour "atanh", "acoth", l'argument ne peut pas être 1 (un). Pour "atanh", "acoth", l'argument ne peut pas être -1 (moins un). Pour "atan", "acot", l'argument ne peut pas être "i" (l'unité imaginaire). Pour "atan", "acoth", l'argument ne peut pas être "-i" (l'unité imaginaire négative). Pour les fonctions "tan", "sec", "tanh", l'argument ne peut pas être pi/2 + k * pi, où k est un entier quelconque. atan2(0, 0) est indéfini, et si des arguments complexes sont utilisés pour atan2(), une division par zéro se produira si z1**2+z2**2 == 0.

Notez qu'en raison de notre travail sur des approximations de nombres réels, ces erreurs peuvent survenir lorsque l'on est simplement « trop proche » des singularités listées ci-dessus.

ERREURS DUES À DES ARGUMENTS INDIFFÉRENTS

Les fonctions "make" et "emake" acceptent des arguments réels et complexes. Lorsqu'elles ne parviennent pas à reconnaître les arguments, elles se terminent avec des messages d'erreur tels que les suivants :

Math::Complex::make: Cannot take real part of ...
Math::Complex::make: Cannot take real part of ...
Math::Complex::emake: Cannot take rho of ...
Math::Complex::emake: Cannot take theta of ...

BOGUES

Dire "use Math::Complex;" exporte de nombreuses routines mathématiques dans l'environnement de l'appelant et remplace même certaines ("sqrt", "log", "atan2"). Ceci est considéré comme une caractéristique par les auteurs, en fait... ;-)

Toutes les routines s'attendent à recevoir des nombres réels ou complexes. N'essayez pas d'utiliser BigFloat, car Perl n'a actuellement aucune règle pour désambiguïser une opération '+' (par exemple) entre deux entités surchargées.

Dans UNICOS de Cray, il existe une étrange instabilité numérique qui entraîne une perte rapide de précision pour root(), cos(), sin(), cosh(), sinh(). Attention. Le bogue peut se trouver dans les bibliothèques mathématiques d'UNICOS, dans le compilateur C d'UNICOS, ou dans Math::Complex. Quoi qu'il en soit, il ne se manifeste nulle part ailleurs où Perl s'exécute.
