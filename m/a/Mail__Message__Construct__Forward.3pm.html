NOM

Mail::Message::Construct::Forward - transfert d'un Mail::Message

SYNOPIS

my Mail::Message $forward = $message->forward(To => 'you');
$forward->send;

DESCRIPTION

Les fonctionnalités complexes sur les objets Mail::Message sont implémentées dans différents fichiers qui sont chargés automatiquement. Ce fichier implémente la fonctionnalité liée à la création de messages transférés.

MÉTHODES

Construction d'un message

$obj->forward(%options)
Transfère le contenu de ce message. Le corps du message à transférer est encapsulé dans un texte d'accompagnement (si vous n'avez pas le souhait de cela, alors "bounce" est votre choix). Un objet Mail::Message est retourné en cas de succès.

Vous pouvez transférer un message entier, mais aussi des parties de message. Vous pouvez souhaiter outrepasser certains des paramètres d'en-tête par défaut pour la réponse immédiatement, ou vous pouvez le faire plus tard avec "set" sur l'en-tête.

Lorsqu'un corps multi-parties est rencontré, et que le message est inclus pour être ATTACHÉ, les parties qui ressemblent à des signatures seront supprimées. S'il ne reste qu'un message, il sera ajouté comme une seule pièce jointe, sinon un multipart imbriqué sera le résultat. La valeur de cette option n'a pas d'importance, tant qu'elle est présente. Voir "Mail::Message::Body::Multipart".

DÉTAILS

Création d'un transfert

La principale différence entre bounce() et forward() est la raison du traitement du message. Le *bounce* n'a pas l'intention de modifier le contenu du message : les mêmes informations sont transmises ailleurs. Cela peut impliquer certaines conversions, mais par exemple, le Message-ID n'a pas besoin d'être modifié.

Le but de forward() est de transmettre des informations qui ont été modifiées : annotées ou réduites. Ces informations ne sont pas renvoyées à l'auteur du message original (implémenté par reply()), mais sont envoyées à quelqu'un d'autre.

Ainsi : certaines informations entrent, sont modifiées et sont ensuite envoyées à quelqu'un d'autre. Actuellement, il existe quatre façons d'inclure les informations d'origine, qui sont expliquées dans les sections suivantes.

Après avoir créé le transfert, vous pouvez appeler rebuild() pour supprimer les complexités inutiles. Cependant, ce n'est pas obligatoire.

transfert, spécifier un corps

Lorsque vous spécifiez forward(body), vous avez créé votre propre objet de corps à utiliser comme contenu du message transféré. Cela implique que forward(include) est 'NO' : il ne génère pas automatiquement le corps du message transféré.

transfert, intégrer l'original

Lorsque forward(include) est défini sur 'INLINE' (la valeur par défaut), c'est la situation la plus complexe, mais la plus courante dans les MUA : le message original est inséré textuellement dans le nouveau corps. Vous pouvez configurer automatiquement la suppression des signatures, le mode d'encapsulation et les textes à ajouter avant et après le bloc encapsulé.

Cependant, le résultat n'est pas toujours celui attendu. Par exemple, certaines personnes utilisent des signatures très longues qui ne sont pas supprimées automatiquement car elles dépassent un certain seuil. Par conséquent, une intervention manuelle est probablement nécessaire après la création du message et avant son envoi.

Lorsqu'un message binaire est rencontré, l'intégration est impossible. Dans ce cas, le message est traité comme si 'ENCAPSULATE' avait été demandé.

transfert, joindre l'original

Lorsque forward(include) est explicitement défini sur 'ATTACH', le résultat sera un multipart contenant deux parties. La première partie sera votre message, et la seconde le corps du message original.

Cela signifie que les en-têtes du message transféré sont utilisés pour le nouveau message, et sont détachés de la partie qui contient maintenant les informations d'origine. Les en-têtes associés resteront partie intégrante de cette partie, mais les lignes "To" et "Subject" ne seront pas stockées avec cette partie.

Comme exemple de transformation structurelle:

# code: $original->printStructure;
multipart/alternative: Le message original
  text/plain: contenu en texte brut
  text/html: contenu au format html
# code: $fwd = $original->forward(include => 'ATTACH');
# code: $fwd->printStructure
multipart/mixed: Le message original
  text/plain: préambule/postambule/signature
  multipart/alternative
    text/plain: contenu en texte brut
    text/html: contenu au format html

transfert, encapsuler l'original

Lorsque forward(include) est explicitement défini sur 'ENCAPSULATE', le message original reste inchangé. Les lignes du message original sont utilisées dans l'en-tête principal du message, et sont également incluses dans l'en-tête de la partie.

L'encapsulation est implémentée en utilisant un message imbriqué, de type de contenu "message/rfc822". Comme exemple de transformation structurelle:

# code: $original->printStructure;
multipart/alternative: Le message original
  text/plain: contenu en texte brut
  text/html: contenu au format html
# code: $fwd = $original->forward(include => 'ENCAPSULATE');
# code: $fwd->printStructure
multipart/mixed: Le message original
  text/plain: préambule/postambule/signature
  message/rfc822
     multipart/alternative: Le message original
        text/plain: contenu en texte brut
        text/html: contenu au format html

La structure du message est beaucoup plus complexe, mais aucune information n'est perdue. C'est probablement pourquoi de nombreux MUA utilisent cette fonctionnalité lorsqu'ils envoient un message original en pièce jointe.
