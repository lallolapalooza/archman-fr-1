NOM

Mail::Box - gérer un dossier de courrier, un répertoire avec des messages

HIÉRARCHIE

Mail::Box
  est un Mail::Reporter
Mail::Box est étendu par
  Mail::Box::Dir
  Mail::Box::File
  Mail::Box::Net

SYNOPIS

use Mail::Box::Manager;
my $mgr    = Mail::Box::Manager->new;
my $folder = $mgr->open(folder => $ENV{MAIL}, ...);
print $folder->name;
# Obtenir le premier message.
print $folder->message(0);
# Supprimer le troisième message
$folder->message(3)->delete;
# Obtenir le nombre de messages en contexte d'échelle.
my $emails = $folder->messages;
# Itérer sur les messages.
foreach ($folder->messages) {...} # tous les messages
foreach (@$folder) {...}          # tous les messages
$folder->addMessage(Mail::Box::Message->new(...));

Interface tie:

tie my(@inbox), 'Mail::Box::Tie::ARRAY', $inbox;
# Quatre fois la même chose :
$inbox[3]->print;                 # tie
$folder->[3]->print;              # surcharge
$folder->message(3)->print;       # normal
print $folder->[3];               # surcharge
tie my(%inbox), 'Mail::Box::Tie::HASH', $inbox;
# Deux fois la même chose
$inbox{$msgid}->print;            # tie
$folder->messageId($msgid)->print;# normal

DESCRIPTION

Un Mail::Box::Manager crée des objets de type "Mail::Box". Mais vous le saviez, puisque vous avez commencé avec la page de manuel Mail::Box-Overview. Cette page est une lecture obligatoire, désolé !

Ceci est une version de maintenance pour l'ancienne interface. Regardez https://github.com/markov2/perl5-Mail-Box/wiki/ pour savoir comment passer à la version 4.

"Mail::Box" est la classe de base pour accéder à différents types de dossiers de courrier (folders) de manière uniforme. Les différents types de dossiers varient dans la façon dont ils stockent leurs messages, mais un effort est fait pour masquer ces différences derrière une API générale. Par exemple, certains dossiers stockent de nombreux messages dans un seul fichier, tandis que d'autres stockent chaque message dans un fichier séparé dans le même répertoire.

Aucun objet dans votre programme n'aura le type "Mail::Box" : c'est juste une classe de base pour les types de dossiers réels. Regardez Mail::Box::Mbox, Mail::Box::MH, Mail::Box::IMAP4, etc.

Étendu de "DESCRIPTION" dans Mail::Reporter.

SURCHARGÉ

overload: "" stringification
Les objets de dossier se transforment en leur nom. Cela simplifie particulièrement les impressions et le tri de nombreux objets.
overload: @{} utiliser comme ARRAY
Lorsque le dossier est utilisé comme une référence à un tableau, il affichera les messages, comme le feraient messages() et message().
overload: cmp comparaison de chaînes
Les dossiers sont comparés en fonction de leur nom. Les règles de tri sont celles du "cmp" intégré.

access => $mode
Les droits d'accès au dossier. Les dossiers sont ouverts en lecture seule (ce qui signifie que le fichier est protégé en écriture). Le $mode peut être
'r': lecture seule (par défaut)
'a': ajout
'rw': lecture et écriture
'd': suppression

Ces MODE n'ont pas de rapport avec les MODE réellement utilisés pour ouvrir les fichiers du dossier au sein de ce module. Par exemple, si vous spécifiez "rw" et ouvrez le dossier, la permission de lecture seule sur le fichier du dossier est suffisante.

Vous devez faire attention : écrire dans une boîte aux lettres MBOX peut créer un nouveau fichier pour remplacer l'ancienne boîte aux lettres. Les permissions et le propriétaire du fichier peuvent ainsi changer.

body_delayed_type => CLASSE
Les corps qui sont différés : ils seront lus du fichier au besoin, mais pas avant.
body_type => CLASSE|CODE
Lors de la lecture de messages à partir d'un fichier de dossier, les en-têtes sont stockés dans un objet de type "head_type". Cependant, pour le corps, il existe une variété d'options sur le type, qui sont décrites dans Mail::Message::Body.

Spécifiez une référence de CODE qui produit le type de corps à créer, ou une CLASSE de corps qui est utilisée lorsque le corps n'est pas multipart ou imbriqué. Dans le cas d'une référence de CODE, la structure des en-têtes est passée comme premier argument à la routine.

Ne retournez pas un type de corps différé (comme "::Delayed"), car celui-ci est déterminé par l'option "extract" pendant que le dossier est ouvert. Même les messages différés nécessiteront un véritable type de corps lorsqu'ils seront finalement analysés. Les messages multipart et imbriqués sont également hors de votre contrôle.

Par exemple :

$mgr->open('InBox', body_type => \&which_body);
sub which_body($) {
    my $head = shift;
    my $size = $head->guessBodySize || 0;
    my $type = $size > 100000 ? 'File' : 'Lines';
    "Mail::Message::Body::$type";
}

La valeur par défaut dépend du type de boîte aux lettres, bien que la valeur générale soit Mail::Message::Body::Lines. Veuillez consulter les pages man applicables.

coerce_options => ARRAY
Stocke les informations de configuration des messages qui sont forcés d'être stockés dans le type de dossier spécifié, en commençant par un type de dossier différent (ou même sans dossier).

Mail::Box::new

Options for the constructor new(). All options are optional.

access => STRING
Which kind of access is required for the folder. This can be one of:
r
read-only
w
write (read and write)
a
append-only (read and append)
rw
read and write
ra
read and append
The default is "r" (read-only).
append_on_new => BOOLEAN
When a new message is created, it is directly written to the folder. This makes the folder object dirty. false is default.
autocreate => BOOLEAN
Same as create.
cache => BOOLEAN
When set to true, the folder will be cached. This is a major speedup for folders that are opened many times with the same settings. Be careful: the cache is global for all folders of the same type. If you change the folder on disk, the cache will not be updated automatically.
codepage => STRING
The codepage of the folder. Default is UTF-8.
create => BOOLEAN
Automatically create the folder when it does not exist yet. This will only work when access is granted for writing or appending to the folder.

Be careful: you may create a different folder type than you expect unless you explicitly specify Mail::Box::Manager::open(type).

extract => INTEGER | CODE | METHOD | 'LAZY'| 'ALWAYS'
Defines when to parse (process) the content of the message. When the header of a message is read, you may want to postpone the reading of the body: header information is more often needed than the body data, so why parse it always together? The cost of delaying is not too high, and with some luck you may never need parsing the body.

If you supply an INTEGER to this option, bodies of those messages with a total size less than that number will be extracted from the folder only when necessary. Messages where the size (in the "Content-Length" field) is not included in the header, like often the case for multiparts and nested messages, will not be extracted by default.

If you supply a CODE reference, that subroutine is called every time that the extraction mechanism wants to determine whether to parse the body or not. The subroutine is called with the following arguments:

CODE->(FOLDER, HEAD)

where FOLDER is a reference to the folder we are reading. HEAD refers to the Mail::Message::Head::Complete head of the message at hand. The routine must return a "true" value (extract now) or a "false" value (be lazy, do not parse yet). Think about using the Mail::Message::Head::guessBodySize() and Mail::Message::guessTimestamp() on the header to determine your choice.

The third possibility is to specify the NAME of a method. In that case, for each message is called:

FOLDER->NAME(HEAD)

Where each component has the same meaning as described above.

The fourth way to use this option involves constants: with "LAZY" all messages will be delayed. With "ALWAYS" you enforce unconditional parsing, no delaying will take place. The latter is usuful when you are sure you always need all the messages in the folder.

$folder->new(extract => 'LAZY');  # Very lazy
$folder->new(extract => 10000);   # Less than 10kB
# same, but implemented yourself
$folder->new(extract => &large);
sub large($) {
   my ($f, $head) = @_;
   my $size = $head->guessBodySize;
   defined $size ? $size < 10000 : 1
};
# method call by name, useful for Mail::Box
# extensions. The example selects all messages
# sent by you to be loaded without delay.
# Other messages will be delayed.
$folder->new(extract => 'sent_by_me');
sub Mail::Box::send_by_me($) {
    my ($self, $header) = @_;
    $header->get('from') =~ m/\bmy\@example.com\b/i;
}
field_type => CLASS
The type of the fields to be used in a header. Must extend Mail::Message::Field.
fix_headers => BOOLEAN
Broken MIME headers usually stop the parser: all lines not parsed are added to the body of the message. With this flag set, the erroneous line is added to the previous header field and parsing is continued. See Mail::Box::Parser::Perl::new(fix_header_errors).
folder => FOLDERNAME
Which folder to open (for reading or writing). When used for reading (the "access" option set to "r" or "a") the mailbox should already exist and must be readable. The file or directory of the mailbox need not exist if it is opened for reading and writing ("rw"). Write-permission is checked when opening an existing mailbox.

The folder name can be preceded by a "=", to indicate that it is named relative to the directory specified in new(folderdir). Otherwise, it is taken as relative or absolute path.

folderdir => $directory
Where are folders to be found by default? A folder-name may be preceded by a equals-sign ("=", a "mutt" convension) to explicitly state that the folder is located below the default directory. For example: in case "folderdir => '/tmp'" and "folder => '=abc'", the name of the folder-file is '/tmp/abc'. Each folder type has already some default set.
head_delayed_type => CLASS
The headers which are delayed: which will be read from file when it is needed, but not before.
head_type => CLASS
The type of header which contains all header information. Must extend Mail::Message::Head::Complete.
keep_dups => BOOLEAN
Indicates whether or not duplicate messages within the folder should be retained. A message is considered to be a duplicate if its message-id is the same as a previously parsed message within the same folder. If this option is "false" (the default) such messages are automatically deleted, because it is considered useless to store the same message twice.
lock_file => $file
The name of the $file which is used to lock. This must be specified when locking is to be used.
lock_timeout => $seconds
When the lock file is older than the specified number of $seconds, it is considered a mistake. The original lock is released, and accepted for this folder.
lock_type => CLASS|STRING|ARRAY
The type of the locker object. This may be the full name of a CLASS which extends Mail::Box::Locker, or one of the known locker types "DotLock", "Flock", "FcntlLock", "Mutt", "NFS", "POSIX", or "NONE". If an ARRAY is specified, then a Multi locker is built which uses the specified list.
lock_wait => $seconds
How many $seconds to wait before failing on opening this folder.
locker => OBJECT
An OBJECT which extends Mail::Box::Locker, and will handle folder locking replacing the default lock behavior.
log => LEVEL
manager => $manager
A reference to the object which manages this folder -- typically an Mail::Box::Manager instance.
message_type => CLASS
What kind of message objects are stored in this type of folder. The default is constructed from the folder class followed by "::Message". For instance, the message type for "Mail::Box::POP3" is "Mail::Box::POP3::Message"
multipart_type => CLASS
The default type of objects which are to be created for multipart message bodies.
remove_when_empty => BOOLEAN
Determines whether to remove the folder file or directory automatically when the write would result in a folder without messages nor sub-folders.
save_on_exit => BOOLEAN
Sets the policy for saving the folder when it is closed. A folder can be closed manually (see close()) or in a number of implicit ways, including on the moment the program is terminated.
trace => LEVEL
trusted => BOOLEAN
Flags whether to trust the data in the folder or not. Folders which reside in your "folderdir" will be trusted by default (even when the names if not specified staring with "="). Folders which are outside the folderdir or read from STDIN (Mail::Message::Construct::read()) are not trused by default, and require some extra checking.

If you do not check encodings of received messages, you may print binary data to the screen, which is a security risk.

Le dossier

$obj->addMessage($message, %options)
Ajoute un message au dossier. Un message est généralement un objet Mail::Box::Message ou une de ses sous-classes. Le message ne doit pas se trouver dans un autre dossier lorsque vous utilisez cette méthode. Dans ce cas, utilisez Mail::Box::Manager::moveMessage() ou Mail::Box::Manager::copyMessage() via le gestionnaire.

Les messages dont les identifiants existent déjà dans ce dossier ne seront pas ajoutés.

ATTENTION ! Les étiquettes de messages peuvent être perdues lors du déplacement d'un dossier à un autre. Nous essayons de traduire les étiquettes, mais il existe des différences significatives dans leur interprétation selon les applications.

-Option--Default
 share   <not used>
share => BOOLEAN
Essayer de partager la ressource physique du message actuel avec le message indiqué. Il est parfois possible de partager des messages entre différents types de dossiers. Si ce n'est pas possible, cette option est ignorée.

Le partage de la ressource est assez risqué et n'est disponible que pour un nombre limité de types de dossiers, pour l'instant seulement pour certains types de dossiers Mail::Box::Dir ; ces messages basés sur des fichiers peuvent être liés (si le système le supporte). Le lien peut être rompu en modifiant l'un des messages du dossier... mais peut-être pas, en fonction des types de dossiers impliqués.

» exemple :

$folder->addMessage($msg);
$folder->addMessages($msg1, $msg2, ...);
$obj->addMessages(@messages)
Ajoute un ensemble d'objets de message au dossier ouvert en même temps. Pour certains types de dossiers, cela peut être plus rapide que de les ajouter un par un.

» exemple :

$folder->addMessages($msg1, $msg2, ...);
$class->appendMessages(%options)
Ajoute un ou plusieurs messages à un dossier non ouvert. Souvent, cette méthode est appelée par Mail::Box::Manager::appendMessage(), dans lequel la correction du type de dossier est vérifiée.

Pour certains types de dossiers, il est nécessaire d'ouvrir le dossier avant de pouvoir l'utiliser pour ajouter. Cela peut être rapide, mais aussi très lent (selon l'implémentation). Toutes les %options passées seront également utilisées pour ouvrir le dossier, si nécessaire.

-Option  --Default

Le nom du dossier auquel les messages seront ajoutés. L'implémentation du dossier évitera d'ouvrir le dossier lorsque c'est possible, car cela consomme des ressources.
message => MESSAGE
...

Une référence à un message ou une référence à un tableau de messages, qui peut être de n'importe quel type. Les messages seront d'abord convertis dans le bon type pour s'adapter au dossier, puis ajoutés à celui-ci.
share => BOOLEAN
Essayer de partager le stockage physique du message. Ceci n'est disponible que pour un nombre limité de types de dossiers, sinon rien ne se passe.

» exemple :

my $message = Mail::Message->new(...);
Mail::Box::Mbox->appendMessages(

mieux :

my Mail::Box::Manager $mgr;
$mgr->appendMessages($message, folder => '=xyz');
$obj->close(%options)
Ferme le dossier, ce qui implique généralement d'écrire les modifications. La méthode renverra "false" si l'écriture est requise mais échoue. Veuillez vérifier cela.

ATTENTION ! Lors du déplacement de messages d'un dossier à un autre, assurez-vous d'écrire le dossier de destination avant de fermer le dossier source. Sinon, vous pourriez perdre des données en cas de crash du système ou de problèmes logiciels.

-Option      --Default
 force         false
 save_deleted  false
 write         'MODIFIED'
force => BOOLEAN
Remplace le nouveau (accès) qui a été spécifié lors de l'ouverture du dossier. Cette option n'a d'effet que si sa valeur est TRUE. NOTE : Il est possible que l'écriture dans le dossier ne soit pas autorisée par le système, auquel cas même "force" n'aidera pas.
save_deleted => BOOLEAN
Écrit également les messages marqués pour suppression dans leur dossier. Le drapeau de suppression est conservé (lorsque c'est possible), ce qui signifie qu'une réouverture du dossier pourrait effectivement supprimer les messages. Voir write(save_deleted).
write => 'ALWAYS'|'NEVER'|'MODIFIED'
Indique si le dossier doit être écrit. Comme on pourrait s'y attendre, "ALWAYS" signifie toujours (même s'il n'y a pas de changements), "NEVER" signifie que les changements apportés au dossier seront perdus et "MODIFIED" n'enregistre le dossier que s'il y a des changements.

» exemple :

my $f = $mgr->open('spam', access => 'rw')
    or die "Cannot open spam: $!\n";
$f->message(0)->delete
    if $f->messages;
$f->close
    or die "Couldn't write $f: $!\n";
$obj->copyTo($folder, %options)
Copie les messages d'un dossier vers un nouveau dossier. Le nouveau dossier peut être d'un type différent. 
-Option       --Default
 delete_copied  <C<false>>
 select         'ACTIVE'
 share          <not used>
 subfolders     <folder type dependent>
delete_copied => BOOLEAN
Marque les messages du dossier source pour être supprimés, juste après leur copie. La suppression n'est effectuée que lors de la fermeture du dossier source.
select => 'ACTIVE'|'DELETED'|'ALL'|LABEL|!LABEL|FILTER
Quels messages vont être copiés ? Voir la description de messages() pour savoir comment ce processus fonctionne.
share => BOOLEAN
Essayer de partager le message entre les dossiers. Certains types de dossiers Mail::Box::Dir le supportent via un lien physique (sur UNIX/Linux).
subfolders => BOOLEAN|'FLATTEN'|'RECURSE'
Comment les sous-dossiers sont-ils gérés ? Quand "false" (0 ou "undef"), les sous-dossiers sont ignorés. Avec "FLATTEN", les messages des sous-dossiers sont inclus dans la copie principale. "RECURSE" copie récursivement les sous-dossiers. Par défaut, lorsque le dossier de destination supporte les sous-dossiers, "RECURSE" est utilisé, sinon "FLATTEN". Une valeur "true" sélectionne la valeur par défaut.

» exemple :

my $mgr  = Mail::Box::Manager->new;
my $imap = $mgr->open(type => 'imap', host => ...);
my $mh   = $mgr->open(type => 'mh', folder => '/tmp/mh',
    create => 1, access => 'w');
$imap->copyTo($mh, delete_copied => 1);
$mh->close; $imap->close;

ATTENTION ! Lors du déplacement de messages d'un dossier à un autre, assurez-vous d'écrire le dossier de destination avant de supprimer le dossier source. Sinon, vous pourriez perdre des données en cas de crash du système ou de problèmes logiciels.

-Option   --Default
 recursive  1
recursive => BOOLEAN
...

» exemple : suppression d'un dossier ouvert

my $folder = Mail::Box::Mbox->new(folder => 'InBox', access => 'rw');

» exemple : suppression d'un dossier fermé

$obj->organization()
Indique comment le dossier est organisé : comme un "FILE" avec de nombreux messages, un "DIRECTORY" avec un message par fichier, ou via un serveur "REMOTE".
$obj->size()
Renvoie la taille du dossier en octets, sans compter les messages supprimés. Le résultat présenté peut comporter une erreur allant jusqu'à 10%, car la représentation en mémoire des messages n'est pas toujours la même que leur taille lorsqu'ils sont écrits.
$obj->update(%options)
Lit les nouveaux messages du dossier, qui ont été reçus après son ouverture. C'est assez risqué et ne devrait pas être possible : les dossiers ouverts sont verrouillés. Cependant, certaines applications n'utilisent pas de verrous ou des types de verrous incorrects. Cette méthode lit les modifications (pas toujours en toute sécurité) et les intègre dans la gestion du dossier ouvert.

$mgr->appendMessages($message, folder => '=xyz');
$obj->close(%options)
Ferme le dossier, ce qui implique généralement d'écrire les modifications. La méthode renverra "false" si l'écriture est requise mais échoue. Veuillez vérifier cela.

ATTENTION ! Lors du déplacement de messages d'un dossier à un autre, assurez-vous d'écrire le dossier de destination avant de fermer le dossier source. Sinon, vous pourriez perdre des données en cas de crash du système ou de problèmes logiciels.

-Option      --Default
 force         false
 save_deleted  false
 write         'MODIFIED'
force => BOOLEAN
Remplace le nouveau (accès) qui a été spécifié lors de l'ouverture du dossier. Cette option n'a d'effet que si sa valeur est TRUE. NOTE : Il est possible que l'écriture dans le dossier ne soit pas autorisée par le système, auquel cas même "force" n'aidera pas.
save_deleted => BOOLEAN
Écrit également les messages marqués pour suppression dans leur dossier. Le drapeau de suppression est conservé (lorsque c'est possible), ce qui signifie qu'une réouverture du dossier pourrait effectivement supprimer les messages. Voir write(save_deleted).
write => 'ALWAYS'|'NEVER'|'MODIFIED'
Indique si le dossier doit être écrit. Comme on pourrait s'y attendre, "ALWAYS" signifie toujours (même s'il n'y a pas de changements), "NEVER" signifie que les changements apportés au dossier seront perdus et "MODIFIED" n'enregistre le dossier que s'il y a des changements.

my $f = $mgr->open('spam', access => 'rw')
    or die "Cannot open spam: $!\n";
$f->message(0)->delete
    if $f->messages;

$obj->copyTo($folder, %options)
Copie les messages d'un dossier vers un nouveau dossier. Le nouveau dossier peut être d'un type différent. 
-Option       --Default
 delete_copied  <C<false>>
 select         'ACTIVE'
 share          <not used>
 subfolders     <folder type dependent>
delete_copied => BOOLEAN
Marque les messages du dossier source pour être supprimés, juste après leur copie. La suppression n'est effectuée que lors de la fermeture du dossier source.

Quels messages vont être copiés ? Voir la description de messages() pour savoir comment ce processus fonctionne.
share => BOOLEAN
Essayer de partager le message entre les dossiers. Certains types de dossiers Mail::Box::Dir le supportent via un lien physique (sur UNIX/Linux).

"RECURSE" copie récursivement les sous-dossiers. Par défaut, lorsque le dossier de destination supporte les sous-dossiers, "RECURSE" est utilisé, sinon "FLATTEN". Les messages

$obj->current( [$number|$message|$message_id] )
Certains lecteurs de messagerie conservent le message current, qui représente le message le plus récemment utilisé. Cette méthode renvoie [après avoir défini] le message actuel. Vous pouvez spécifier un $number, pour spécifier que ce numéro de message soit sélectionné comme actuel, ou un $message/$message_id (sauf si l'en-tête est déjà chargé, auquel cas il ne sera pas reconnu).
$obj->find($message_id)
Similaire à messageId(), cette méthode recherche un message avec le $message_id, renvoyant l'objet message correspondant. Cependant, "find" provoquera le traitement d'un message non traité dans le dossier jusqu'à ce que l'id du message soit trouvé. Le dossier sera parcouru de la fin vers le début.
$obj->findFirstLabeled( $label, [BOOLEAN, [$msgs]] )
Recherche le premier message avec cette $label avec la bonne configuration. Le "BOOLEAN" indique s'il faut rechercher n'importe quelle valeur "true" ou n'importe quelle valeur "false" dans le tableau de $msgs. Par défaut, une valeur "true" est recherchée. Lorsqu'un message n'a pas l'étiquette demandée, il est considéré comme "false".
$obj->message( $index, [$message] )
Obtient ou définit un message avec un indice donné. Les messages marqués pour suppression sont comptés. Les indices négatifs commencent à la fin du dossier.
$obj->messageId( $message_id, [$message] )
Avec un argument, renvoie le message dans le dossier avec le $message_id. Si un objet message est passé comme deuxième argument (facultatif), le message est d'abord stocké dans le dossier, remplaçant tout message ayant le même $message_id. (Le $message_id du message $message n'a pas besoin de correspondre à $message_id).

!!AVERTISSEMENT!!: lors du traitement des en-têtes de message de manière différée, le message peut être dans le dossier mais pas encore traité en mémoire. Dans ce cas, il est recommandé d'utiliser find() plutôt que messageId() si une recherche complète est nécessaire. Ceci est particulièrement pertinent pour les dossiers organisés sans index spécial, comme Mail::Box::MH.

Le $message_id peut encore être entre crochets, qui seront supprimés. Dans ce cas, les espaces (qui proviennent du double saut de ligne d'en-tête) sont également supprimés. D'autres données autour des crochets seront également supprimées.

!!Exemple!!:

my $msg = $folder->messageId('<complex-message.id>');
$folder->messageId("<complex-message\n.id>", $msg);
my $msg = $folder->messageId('complex-message.id');
my $msg = $folder->messageId('garbage <complex-message.id> trash');
...
$obj->messageIds()
Renvoie une liste de *tous* les identifiants de message dans le dossier, y compris ceux des messages qui seront supprimés.

Pour certains types de dossiers (comme MH), cette méthode peut provoquer la lecture de tous les fichiers de messages. Consultez leur documentation correspondante.

!!Exemple!!:

foreach my $id ($folder->messageIds) {
   $folder->messageId($id)->print;
}
...
$obj->messages( <'ALL'|$range|'ACTIVE'|'DELETED'|$label| !$label|$filter> )
Renvoie plusieurs messages du dossier. La valeur par défaut est "ALL", qui renverra (comme attendu) tous les messages du dossier. "ACTIVE" indique les messages non marqués pour suppression. C'est l'inverse de "DELETED", qui renvoie tous les messages du dossier qui seront supprimés à la fermeture du dossier.

Vous pouvez également spécifier une $range : deux nombres spécifiant l'indice de début et de fin dans le tableau des messages. Les indices négatifs comptent à partir de la fin du dossier. Lorsqu'un indice est hors limites, la liste renvoyée sera plus courte sans commentaire.

Tout ce qui n'est pas le nom par défaut est considéré comme une étiquette. Les messages qui ont cette étiquette seront renvoyés. Lorsque la séquence commence par un point d'exclamation (!), le résultat de la recherche est inversé.

Pour des recherches plus complexes, vous pouvez spécifier un $filter, qui est simplement une référence à une fonction. Le message est passé comme seul argument.

!!Exemple!!:

foreach my $message ($folder->messages) {...}
foreach my $message (@$folder) {...}
# deux fois la même chose
my @messages   = $folder->messages;
my @messages   = $folder->messages('ALL');
# Sélection basée sur la plage (début, fin)
my $subset     = $folder->messages(10,-8);
# deux fois la même chose:
my @not_deleted= grep {not $_->isDeleted}
                    $folder->messages;
my @not_deleted= $folder->messages('ACTIVE');
# Contexte scalaire du nombre de messages
my $nr_of_msgs = $folder->messages;
# troisième message, par surcharge
$folder->[2];
# Sélection basée sur les étiquettes
$mgr->moveMessages($spam, $inbox->message('spam'));
$mgr->moveMessages($archive, $inbox->message('seen'));
...
$obj->nrMessages(%options)
Appelle simplement messages() dans un contexte scalaire pour renvoyer un compte au lieu des messages eux-mêmes. Certaines personnes semblent mieux comprendre cela. Notez que nrMessages() renvoie par défaut un compte de *tous* les messages du dossier, y compris les messages "ACTIVE" et "DELETED".

Les %options sont passés à (et expliqués dans) messages().

...
$obj->scanForMessages($message, $message_ids, $timespan, $window)
Vous commencez avec un $message, et recherchez une série de messages qui lui sont liés. Par exemple, des messages qui apparaissent dans les champs d'en-tête 'In-Reply-To' et 'Reference' de ce message. Ces messages sont connus par leurs $message_ids et vous voulez les trouver dans le dossier.

Lorsque tous les identifiants de message sont connus, la recherche est simple : ils sont trouvés dans une table de hachage plate en utilisant messageId(). Mais Mail::Box est lent là où il le peut, donc de nombreux messages n'ont peut-être pas encore été lus depuis le fichier et c'est la situation préférée, car cela économise du temps et de la mémoire.

Il n'est pas intelligent de rechercher les messages de la fin vers le début du dossier : il y a une plus grande probabilité que le message lié soit à proximité. Par conséquent, cette méthode commence à parcourir le dossier depuis le $message spécifié, vers le début du dossier.

Le $timespan peut être utilisé pour terminer la recherche en fonction du temps dans le message. Lorsque la constante "EVER" est utilisée comme $timespan, la recherche n'est pas limitée par cela. Lorsqu'un entier est spécifié, il sera utilisé comme temps absolu en ticks de temps selon la fonction "time" de votre système. Dans d'autres cas, il est passé à timespan2seconds() pour déterminer le seuil de temps relatif au temps du message.

Le $window est utilisé pour limiter le nombre de messages à parcourir sous forme d'entier ou de chaîne constante "ALL".

Les identifiants de message qui n'ont pas été trouvés pendant la recherche sont renvoyés. Il est averti qu'un identifiant de message peut déjà être connu et donc pas trouvé : vérifiez d'abord.

!!Exemple!!:

my $refs   = $msg->get('References') or return;
my @msgids = $ref =~ m/\<([^>]+\>/g;
my @failed = $folder->scanForMessages($msg, \@msgids, '3 days', 50);

DÉTAILS

Différents types de dossiers

En général, il existe trois classes de dossiers : ceux qui regroupent les messages par fichier, ceux qui regroupent les messages dans un répertoire, et ceux qui ne fournissent pas d'accès direct aux données des messages. Ces types de dossiers sont basés sur des classes de base différentes.

  • Dossiers basés sur des fichiers Mail::Box::File

    Les dossiers basés sur des fichiers conservent un dossier (un ensemble de messages) dans un seul fichier. L'avantage est que votre dossier n'a qu'un seul fichier à accéder, ce qui accélère les choses lorsque tous les messages doivent être accédés en même temps.

    L'un des principaux inconvénients par rapport aux dossiers basés sur des répertoires est que vous devez trouver un moyen de séparer tous les messages. Par exemple, MBOX ajoute une ligne de séparation de message entre les messages dans le fichier, et cette ligne peut prêter à confusion avec le contenu du message.

    Alors que l'accès à tous les messages à la fois est plus rapide dans les dossiers basés sur des fichiers, l'accès à un seul message est (beaucoup) plus lent, car l'ensemble du dossier doit être lu. Cependant, dans les dossiers basés sur des répertoires, vous devez déterminer quel message vous avez besoin, ce qui peut également être une tâche fastidieuse.

    Des exemples de dossiers basés sur des fichiers sont MBOX, DBX et NetScape.

  • Dossiers basés sur des répertoires Mail::Box::Dir

    Au lieu de collecter plusieurs messages dans un seul fichier, vous pouvez également placer chaque message dans un fichier séparé et collecter ces fichiers dans un répertoire pour représenter un dossier.

    Les principaux inconvénients de ces dossiers sont l'énorme quantité de petits fichiers que vous obtenez généralement dans votre système de fichiers. Il est extrêmement lent de parcourir l'ensemble de votre dossier, car de nombreux fichiers doivent être ouverts pour ce faire.

    La meilleure caractéristique de cette organisation est que chaque message est conservé exactement tel qu'il a été reçu, et peut également être traité avec des scripts externes : vous n'avez pas besoin d'un agent utilisateur de messagerie (MUA).

    Des exemples de dossiers organisés par répertoire sont MH, Maildir, EMH et XMH.

  • Dossiers réseau (externes) Mail::Box::Net

    Alors que les deux types décrits précédemment fournissent un accès direct aux données des messages, ces types de dossiers conservent les données des messages pour vous : vous devez demander les messages ou des parties de ceux-ci. Ces dossiers n'ont pas de nom de fichier, de privilèges de système de fichiers et de verrouillage système à gérer, mais nécessitent généralement un nom d'hôte, un dossier et des identifiants de message, ainsi qu'une autorisation.

    Des exemples de ces types de dossiers sont les populaires POP et IMAP, et le stockage de messages orienté base de données.

Types de dossiers disponibles

  • Mail::Box::Dbx (lecture seule)

    Les fichiers Dbx sont créés par Outlook Express. En utilisant le module externe (optionnel) Mail::Transport::Dbx, vous pouvez lire ces dossiers, même si vous exécutez MailBox sur une plateforme UNIX/Linux.

    L'écriture et la suppression de messages ne sont pas prises en charge par la bibliothèque, et donc pas par MailBox. L'accès en lecture est suffisant pour effectuer des conversions de dossiers, par exemple.

  • Mail::Box::IMAP4 (partiellement)

    Le protocole IMAP est très complexe. Certaines parties sont implémentées pour créer des clients IMAP (sous-optimaux mais utilisables). De plus, il existe également des parties pour les serveurs IMAP. La caractéristique manquante la plus importante est le support des connexions cryptées.

  • Mail::Box::Maildir

    Les dossiers Maildir ont un répertoire pour chaque dossier. Un répertoire de dossier contient des sous-répertoires "tmp", "new" et "cur", chacun contenant des messages dans un but différent. Les fichiers contenant de nouveaux messages sont créés dans "tmp", puis déplacés vers "new" (prêts à être acceptés). Plus tard, ils sont déplacés vers le répertoire "cur" (acceptés). Chaque message est un fichier dont le nom commence par un horodatage. Le nom contient également des indicateurs sur l'état du message.

    Les dossiers Maildir ne peuvent pas être utilisés sous Windows en raison des limitations de nom de fichier sur cette plateforme.

  • Mail::Box::Mbox

    Un type de dossier dans lequel tous les messages associés sont stockés dans un seul fichier. C'est un type de dossier très courant pour UNIX.

  • Mail::Box::MH

    Ce dossier crée un répertoire pour chaque dossier, et un message est un fichier à l'intérieur de ce répertoire. Les fichiers de message sont numérotés séquentiellement par ordre d'arrivée. Un fichier spécial ".mh_sequences" conserve les indicateurs sur les messages.

  • Mail::Box::POP3 (lecture/suppression uniquement)

    POP3 est un protocole qui peut être utilisé pour récupérer des messages d'un système distant. Après l'établissement de la connexion avec un serveur POP, les messages peuvent être consultés et supprimés comme s'ils étaient sur le système local.

  • Mail::Box::Netzwert

    Le type de dossier Netzwert est optimisé pour la gestion des boîtes aux lettres sur un cluster de systèmes avec un stockage NFS partagé. Le code n'est pas distribué sous GPL (pour l'instant)

D'autres types de dossiers sont sur la liste d'attente (longue) à implémenter. S'il vous plaît, aidez à en implémenter davantage.

Implémentation de la classe dossier

La structure de classe des dossiers est très similaire à celle des messages. Par exemple, un Mail::Box::File::Message est lié à un dossier Mail::Box::File. Les types de dossiers sont :

                   Mail::Box::Netzwert
Mail::Box::Mbox    | Mail::Box::Maildir  Mail::Box::POP3
|  Mail::Box::Dbx  | | Mail::Box::MH     |  Mail::Box::IMAP4
|  |               | | |                 |  |
|  |               | | |                 |  |
Mail::Box::File   Mail::Box::Dir       Mail::Box::Net
      |                  |                   |
      `--------------.   |   .---------------'
                     |   |   |
                     Mail::Box
                         |
                         |
            Mail::Reporter (classe de base générale)

La grande majorité des fonctionnalités des dossiers sont implémentées dans Mail::Box, donc disponibles pour tous les types de dossiers. Parfois, des fonctionnalités qui n'apparaissent que dans certains des types de dossiers sont simulées pour les dossiers qui les manquent, comme le support des sous-dossiers pour MBOX.

DIAGNOSTICS

Avertissement : Modifications non écrites dans le dossier en lecture seule $self.
Vous avez ouvert le dossier en lecture seule -- ce qui est le réglage par défaut défini par new(access)--, effectué des modifications, et vous voulez maintenant le fermer. Définissez close(force) si vous voulez passer outre le mode d'accès, ou fermez le dossier avec close(write) défini sur "NEVER". Appel par close()
Erreur : Copie échouée pour un message.
Pour une raison quelconque, par exemple disque plein, suppression par un processus externe, ou protection en lecture, il est impossible de copier l'un des messages. La copie se poursuivra pour les autres messages. Appel par copyTo()
Erreur : Le dossier de destination $name n'est pas inscriptible.
Le dossier vers lequel les messages sont copiés n'est pas ouvert en accès en écriture (voir new(access)). Ceci n'a aucun rapport avec la permission d'écriture sur le dossier, qui est contrôlée par votre système d'exploitation. Appel par copyTo()
Avertissement : Messages différents avec l'id $msgid
L'identifiant du message est trouvé plus d'une fois dans le même dossier, mais le contenu du message semble être différent. Cela ne devrait pas être possible : chaque message doit être unique. Appel par messageId()
Erreur : Le dossier $name est ouvert en lecture seule
Vous ne pouvez pas écrire dans ce dossier à moins que vous ne l'ayez ouvert en écriture ou en ajout avec new(access), ou que l'option "force" ne soit définie sur "true". Appel par write()
Erreur : Le dossier $name n'a pas été supprimé : non inscriptible.
Le dossier doit être ouvert en accès en écriture via new(access), sinon sa suppression sera refusée. Ainsi, vous pouvez avoir un accès en écriture selon le système d'exploitation, mais cela ne signifiera pas automatiquement que cette méthode "delete" vous le permet. L'inverse est également valable. Appel par delete()
Erreur : Intervalle de temps invalide '$timespan' spécifié.
La chaîne ne suit pas les règles strictes de la syntaxe de l'intervalle de temps qui est autorisée en tant que paramètre. Appel par timespan2seconds()
Avertissement : L'id du message '$msgid' ne contient pas de domaine.
Selon les RFC, les identifiants de message doivent contenir une partie aléatoire unique, puis un "@", puis un nom de domaine. Ceci est fait pour éviter la création de deux messages avec

NAME

Mail::Box - Framework for accessing mail-folders

INHERITANCE

This module is part of the Mail-Box distribution.

SYNOPSIS

  use Mail::Box;
  use Mail::Box::Unique; # Use the unique ID implementation

  my $mailbox = Mail::Box::Unique->new() or die "Cannot open mailbox: $!";
  my $folder  = $mailbox->folder() or die "Cannot open folder: $!";

  # Iterate over the messages in the folder
  $folder->messages and
   while (my $message = $folder->get) {
      print $message->subject, "\n";
   };

  $folder->close;
  $mailbox->close;

DESCRIPTION

This module provides a framework to access mail messages stored in folders. It abstracts the underlying storage mechanism (like Maildir, MH, or even plain files) and provides a common interface to interact with mail messages. The concrete implementation is provided by subclasses like Mail::Box::Unique.

The core concepts are:

  • Mailbox: Represents the entire mail storage, which may contain multiple folders.
  • Folder: Represents a collection of mail messages, typically corresponding to a directory or a single file.
  • Message: Represents an individual email message.

This module defines the interface for these objects and provides common functionality. It's designed to be extensible, allowing new storage backends to be easily integrated.

OVERLOADED

The Mail::Box class overloads the string and numeric comparison operators for convenience when comparing folder or message IDs.

METHODS

The following methods are part of the public interface:

new()
Creates a new Mail::Box object. The constructor takes optional arguments to configure the mailbox, such as the storage path or the specific implementation to use.
folder()
Opens a folder within the mailbox. It can take the folder name as an argument. If no argument is given, it usually opens the default or INBOX folder.
close()
Closes the mailbox, releasing any resources held.
messageId()
Generates a unique message ID. This is typically used internally but can be called directly if needed.
new()
Creates a new folder. The folder name must be provided.
new()
Opens a folder. The folder name must be provided. This is an alternative way to open a folder compared to the folder() method.
notImplemented()
A placeholder method, typically called when a required method is missing in a specific package or subclass.
copyTo()
Copies a folder or messages to another location. Handles subfolders recursively.
write()
Writes changes made to a folder back to the storage.

DIAGNOSTICS

The following warnings and errors can be generated by this module:

Error: Cannot open folder "%s": %s
Failed to open the specified folder. The second argument provides more details about the error (e.g., permissions, non-existent).
Error: Folder $name already exists
The folder with the given name already exists and cannot be created again.
Error: No folder specified
A folder name was expected but not provided.
Error: Cannot open message with id $id
The system failed to open a message with the specified ID. This could be due to the message not existing or an issue with the storage backend.
Error: No unique message ID for this message
A message was expected to have a unique ID, but it was missing. This usually happens when a message object is created incorrectly or doesn't have a persistent identifier.
Warning: messageId() called without '@'
The messageId() function was called with a string that does not contain the expected '@' character, which is usually part of a unique identifier format. Cast by messageId()
Error: No folder name specified.
You did not specify the name of a folder to be opened. Use the new(folder) option or set the "MAIL" environment variable. Cast by new()
Error: Package $package does not implement $method.
Fatal error: the specific package (or one of its superclasses) does not implement this method where it should. This message means that some other related classes do implement this method however the class at hand does not. Probably you should investigate this and probably inform the author of the package. Cast by notImplemented()
Error: Unable to create subfolder $name of $folder.
The copy includes the subfolders, but for some reason it was not possible to copy one of these. Copying will proceed for all other sub-folders. Cast by copyTo()
Error: Writing folder $name failed
For some reason (you probably got more error messages about this problem) it is impossible to write the folder, although you should because there were changes made. Cast by write()
