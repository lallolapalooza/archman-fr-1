NOM

Mail::SpamAssassin::Plugin::AWL - Normalise les scores via la liste blanche automatique

SYNOPIS

Pour tester ceci, ajoutez ou décommentez cette ligne dans init.pre :

loadplugin     Mail::SpamAssassin::Plugin::AWL

Utilisez le fichier 60_awl.cf fourni (c'est-à-dire que vous n'avez rien à faire) ou ajoutez ces lignes à un fichier .cf :

header AWL             eval:check_from_in_auto_welcomelist()
describe AWL           From: address is in the auto welcome-list
tflags AWL             userconf noautolearn
priority AWL           1000

DESCRIPTION

Ce module de plugin fournit la prise en charge de la liste blanche automatique. Il suit le score moyen de SpamAssassin pour les expéditeurs. Les expéditeurs sont suivis en utilisant une combinaison de leur adresse From: et de leur adresse IP. Il utilise ensuite ce score moyen pour réduire la variabilité des scores d'un message à l'autre et modifie le score final en rapprochant le résultat de la moyenne historique. Ceci améliore la précision du filtrage pour la plupart des e-mails.

BALISES DE MODÈLE

Ce module de plugin ajoute les « balises » suivantes qui peuvent être utilisées comme espaces réservés dans certaines options. Voir "Mail::SpamAssassin::Conf" pour plus d'informations sur les BALISES DE MODÈLE.

_AWL_             Modificateur AWL
_AWLMEAN_         Score moyen sur lequel la modification AWL est basée
_AWLCOUNT_        Nombre de messages sur lesquels la modification AWL est basée
_AWLPRESCORE_     Score avant AWL

PRÉFÉRENCES UTILISATEUR

Les options suivantes peuvent être utilisées dans les fichiers de configuration du site ("local.cf") et spécifiques à l'utilisateur ("user_prefs") pour personnaliser la manière dont SpamAssassin traite les messages e-mail entrants.

use_auto_welcomelist ( 0 | 1 ) (défaut: 1)
Précédemment use_auto_whitelist qui fonctionnera de manière interchangeable jusqu'à la version 4.1.

Indique s'il faut utiliser les listes blanches automatiques. Les listes blanches automatiques suivent le score moyen à long terme pour chaque expéditeur, puis rapprochent le score des nouveaux messages vers cette moyenne à long terme. Ceci peut augmenter ou diminuer le score des messages, en fonction du comportement à long terme du correspondant particulier.

Pour plus d'informations sur le système de liste blanche automatique, veuillez consulter la section "Automatic Welcomelist System" du fichier README. La liste blanche automatique n'est pas destinée à remplacer les entrées de liste blanche statiques ajoutées à vos fichiers de configuration.

Notez que certains tests sont ignorés lors de la détermination du score final du message :

- règles avec tflags défini sur 'noautolearn'
auto_welcomelist_factor n (défaut: 0.5, plage [0..1])
Précédemment auto_whitelist_factor qui fonctionnera de manière interchangeable jusqu'à la version 4.1.

Quelle part de la moyenne à long terme de l'expéditeur utiliser pour rapprocher un message. Essentiellement, l'algorithme consiste à suivre la moyenne des scores à long terme des messages pour l'expéditeur ("mean"), puis une fois que nous avons entièrement calculé le score pour ce message ("score"), nous calculons le score final pour le message comme suit :

"finalscore" = "score" + ("mean" - "score") * "factor"

Donc, si "factor" = 0.5, nous nous rapprocherons de la moitié du chemin entre le score calculé et la moyenne. Si "factor" = 0.3, nous nous rapprocherons d'environ 1/3 du chemin entre le score et la moyenne. "factor" = 1 signifie utiliser uniquement la moyenne à long terme ; "factor" = 0 signifie utiliser uniquement le score calculé.

auto_welcomelist_ipv4_mask_len n (défaut: 16, plage [0..32])
Précédemment auto_whitelist_ipv4_mask_len qui fonctionnera de manière interchangeable jusqu'à la version 4.1.

La base de données AWL ne conserve que le nombre spécifié de bits les plus significatifs d'une adresse IPv4 dans ses champs, de sorte que différentes adresses IP individuelles au sein d'un sous-réseau appartenant au même propriétaire sont gérées sous un seul enregistrement de base de données. Comme nous n'avons aucune information sur les plages d'adresses allouées aux expéditeurs, cette longueur de masque CIDR n'est qu'une approximation. La valeur par défaut est de 16 bits, correspondant à une ancienne classe B. Augmentez le nombre si une granularité plus fine est souhaitée, par exemple à 24 (classe C) ou 32. Une valeur de 0 est autorisée mais n'est pas particulièrement utile, car elle traiterait l'ensemble d'Internet comme une seule organisation. Le nombre n'a pas besoin d'être un multiple de 8, toute division est autorisée.

auto_welcomelist_ipv6_mask_len n (défaut: 48, plage [0..128])
Précédemment auto_whitelist_ipv6_mask_len qui fonctionnera de manière interchangeable jusqu'à la version 4.1.

La base de données AWL ne conserve que le nombre spécifié de bits les plus significatifs d'une adresse IPv6 dans ses champs, de sorte que différentes adresses IP individuelles au sein d'un sous-réseau appartenant au même propriétaire sont gérées sous un seul enregistrement de base de données. Comme nous n'avons aucune information sur les plages d'adresses allouées aux expéditeurs, cette longueur de masque CIDR n'est qu'une approximation. La valeur par défaut est de 48 bits, correspondant à une plage d'adresses couramment allouée aux organisations individuelles (plus petites). Augmentez le nombre pour une granularité plus fine, par exemple à 64 ou 96 ou 128, ou diminuez pour des plages plus larges, par exemple 32. Une valeur de 0 est autorisée mais n'est pas particulièrement utile, car elle traiterait l'ensemble d'Internet comme une seule organisation. Le nombre n'a pas besoin d'être un multiple de 4, toute division est autorisée.

user_awl_sql_override_username
Utilisé par l'implémentation de stockage SQLBasedAddrList.

Si cette option est définie, le module SQLBasedAddrList remplacera le nom d'utilisateur défini par la valeur fournie. Cela peut être utile pour implémenter des bases de données de liste blanche automatique globales ou basées sur des groupes.

auto_welcomelist_distinguish_signed
Précédemment auto_whitelist_distinguish_signed qui fonctionnera de manière interchangeable jusqu'à la version 4.1.

Utilisé par l'implémentation de stockage SQLBasedAddrList.

Si cette option est définie, le module SQLBasedAddrList conservera des enregistrements de base de données distincts pour les adresses e-mail validées par DKIM et pour celles qui ne le sont pas. Une condition préalable lors de la définition de cette option est qu'un champ awl.signedby existe dans une table SQL, sinon les opérations SQL échoueront (c'est pourquoi nous avons besoin de cette option - pour la compatibilité avec le schéma de base de données pré-3.3.0). Un plugin DKIM doit également être activé, car sinon il n'y a aucun avantage à activer cette option.

PARAMÈTRES ADMINISTRATEUR

Ces paramètres diffèrent de ceux ci-dessus, en ce sens qu'ils sont considérés comme 'plus privilégiés' - encore plus que ceux de la section PARAMÈTRES PRIVILÉGIÉS. Peu importe la valeur de "allow_user_rules", ceux-ci ne pourront jamais être définis à partir du fichier "user_prefs" d'un utilisateur.

auto_welcomelist_factory module (défaut: Mail::SpamAssassin::DBBasedAddrList)
Précédemment auto_whitelist_factory qui fonctionnera de manière interchangeable jusqu'à la version 4.1.

Sélectionne un module de fabrique de liste blanche alternatif.

auto_welcomelist_path /chemin/nom_de_fichier (défaut: ~/.spamassassin/auto-welcomelist)
Précédemment auto_whitelist_path qui fonctionnera de manière interchangeable jusqu'à la version 4.1.

Ceci est le répertoire et le nom de fichier de la liste blanche automatique. Par défaut, chaque utilisateur a sa propre

auto_welcomelist_db_dir (default: see below)

Le répertoire où le fichier de base de données auto-welcomelist est stocké. Voir aussi auto_welcomelist_db_modules et auto_welcomelist_file_mode.

Si la base de données est stockée dans un fichier, ce fichier sera le premier fichier dans le répertoire listé dans auto_welcomelist_db_dir qui est accessible en écriture. Le répertoire sera créé s'il n'existe pas. Ceci est généralement réglé sur le répertoire "~/.spamassassin" avec le mode 0700. Pour une utilisation de SpamAssassin au niveau du système, vous pourriez vouloir partager cela entre tous les utilisateurs, bien que cela ne soit pas recommandé.

auto_welcomelist_db_modules Module ... (default: voir ci-dessous)
Précédemment auto_whitelist_db_modules, qui fonctionneront de manière interchangeable jusqu'à la version 4.1.

Quels modules de base de données doivent être utilisés pour le fichier de base de données de stockage de l'auto-liste de bienvenue. Le premier module nommé qui peut être chargé depuis le chemin d'inclusion perl sera utilisé. Le format est :

ModulePréféré SecondMeilleur TroisièmeMeilleur ...

c'est-à-dire une liste de noms de modules perl séparés par des espaces. La valeur par défaut est :

DB_File GDBM_File SDBM_File

NDBM_File n'est plus supporté, car il semble avoir des bugs qui empêchent son utilisation pour l'AWL (voir le bug SpamAssassin 4353).

auto_welcomelist_file_mode (default: 0700)
Précédemment auto_whitelist_file_mode, qui fonctionnera de manière interchangeable jusqu'à la version 4.1.

Les bits de mode de fichier utilisés pour le répertoire ou le fichier de la liste de bienvenue automatique.

Assurez-vous de spécifier cela en utilisant les bits de mode 'x' activés, car cela peut également être utilisé pour créer des répertoires. Cependant, si un fichier est créé, le fichier résultant n'aura aucun bit d'exécution défini (l'umask est réglé sur 0111).

user_awl_dsn DBI:typedebase:nombasededonnées:nomhôte:port
Utilisé par l'implémentation de stockage SQLBasedAddrList.

Ceci définira le DSN utilisé pour la connexion. Exemple : "DBI:mysql:spamassassin:localhost"

user_awl_sql_username nomutilisateur
Utilisé par l'implémentation de stockage SQLBasedAddrList.

Le nom d'utilisateur autorisé pour se connecter au DSN ci-dessus.

user_awl_sql_password motdepasse
Utilisé par l'implémentation de stockage SQLBasedAddrList.

Le mot de passe pour le nom d'utilisateur de la base de données, pour le DSN ci-dessus.

user_awl_sql_table nometable
Utilisé par l'implémentation de stockage SQLBasedAddrList.

La table dans laquelle les listes de bienvenue automatiques des utilisateurs sont stockées, pour le DSN ci-dessus.
