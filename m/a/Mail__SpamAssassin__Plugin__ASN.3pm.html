NAME

Mail::SpamAssassin::Plugin::ASN - Plugin pour SpamAssassin qui recherche le numéro de réseau AS (ASN) de l'adresse IP connectée.

SYNOPSIS

loadplugin Mail::SpamAssassin::Plugin::ASN
# Configuration par défaut / recommandée
asn_use_geodb 1
asn_use_dns 1
asn_prefer_geodb 1
# Effectuer des recherches et ajouter des tags / en-tête X-Spam-ASN
asn_lookup asn.routeviews.org _ASN_ _ASNCIDR_
asn_lookup_ipv6 origin6.asn.cymru.com _ASN_ _ASNCIDR_
add_header all ASN _ASN_ _ASNCIDR_
# Règles pour vérifier l'ASN ou l'organisation
# NOTE: N'utilisez pas de règles qui vérifient les métadonnées X-ASN, seule la fonction check_asn() fonctionne correctement.
# L'argument est un motif complet pour la correspondance.
# Numéro d'ASN : GeoIP ASN ou DNS
# La chaîne correspondante inclut asn_prefix s'il est défini, et affiche généralement
# quelque chose comme "AS1234" (DNS) ou "AS1234 Google LLC" (GeoIP)
header AS_1234 eval:check_asn('/^AS1234\b/')
# Organisation ASN : GeoIP ASN a, DNS peut ne pas avoir
# Notez le second argument qui vérifie le tag MYASN (par défaut est ASN)
asn_lookup myview.example.com _MYASN_ _MYASNCIDR_
header AS_GOOGLE eval:check_asn('/\bGoogle\b/i', 'MYASN')

DESCRIPTION

Ce plugin utilise des recherches DNS sur des services de zone DNS externes, comme sur https://www.routeviews.org/, pour effectuer le travail réel. Assurez-vous que votre utilisation du plugin ne surcharge pas votre infrastructure - cela signifie généralement que vous devriez éviter d'utiliser ce plugin dans un environnement à haut volume ou que vous devez utiliser une copie locale de la zone (voir ftp://ftp.routeviews.org/dnszones/). D'autres zones similaires peuvent également être utilisées.

Les recherches GeoDB (ASN GeoIP) sont prises en charge depuis SpamAssassin 4.0 et il est recommandé de les utiliser à la place des recherches DNS, sauf si vous avez besoin d'utiliser _ASNCIDR_.

TAGS DE TEMPLATE

Ce plugin permet de créer des tags de template qui contiennent le numéro de l'ASN de l'adresse IP connectée et les informations réseau correspondantes à l'ASN.

Si vous utilisez add_header comme documenté dans l'exemple ci-dessus, un champ d'en-tête sera ajouté qui ressemble à ceci:

X-Spam-ASN: AS24940 213.239.192.0/18

où "24940" est l'ASN et "213.239.192.0/18" est le réseau annoncé par cet ASN dont provient l'adresse IP connectée. Si l'AS annonce plusieurs réseaux (plus ou moins spécifiques), tous seront ajoutés au tag _ASNCIDR_, séparés par des espaces, comme ceci :

X-Spam-ASN: AS1680 89.138.0.0/15 89.139.0.0/16

Note : Le littéral "AS" avant l'ASN dans le tag _ASN_ peut être configuré via le répertoire asn_prefix, et peut être défini comme une chaîne vide. Le _ASNCIDR_ n'est pas disponible avec les recherches GeoDB ASN locales.

PARAMÈTRES UTILISATEUR

clear_asn_lookups
Supprime toutes les entrées asn_lookup ou asn_lookup_ipv6 précédemment déclarées de la liste des recherches.
asn_prefix 'prefix_string' (valeur par défaut: 'AS')
La chaîne spécifiée dans l'argument est ajoutée avant chaque ASN lors de son stockage sous forme de tag. Ce préfixe est redondant, mais la valeur par défaut 'AS' est conservée pour la compatibilité avec les versions de SpamAssassin antérieures à 3.4.0. Une configuration raisonnable est une chaîne vide. L'argument peut être (mais ne doit pas être) entouré de guillemets pour plus de clarté.

DÉFINITIONS DE RÈGLES ET PARAMÈTRES ADMINISTRATEUR

asn_lookup asn-zone.example.com [ _ASNTAG_ _ASNCIDRTAG_ ]
Utilisez ceci pour obtenir les informations ASN dans la zone spécifiée pour la première adresse IPv4 externe et ajoutez le numéro d'ASN au premier tag spécifié et les informations réseau au second tag.

Si aucun tag n'est spécifié, le numéro d'ASN sera ajouté au tag _ASN_ et les informations réseau au tag _ASNCIDR_. Vous devez spécifier aucun ou les deux tags. Les noms de tags doivent commencer et se terminer par un trait de soulignement.

Si deux asn_lookup ou plus utilisent le même ensemble de tags de template, les résultats de leurs recherches seront ajoutés les uns aux autres dans les valeurs des tags de template dans un ordre non spécifié. Les doublons sont omis lors de la combinaison. De même, vous pouvez utiliser le même tag de template pour le numéro d'ASN et les informations réseau.

Exemples:

asn_lookup asn.routeviews.org
asn_lookup asn.routeviews.org _ASN_ _ASNCIDR_
asn_lookup myview.example.com _MYASN_ _MYASNCIDR_
asn_lookup asn.routeviews.org _COMBINEDASN_ _COMBINEDASNCIDR_
asn_lookup myview.example.com _COMBINEDASN_ _COMBINEDASNCIDR_
asn_lookup in1tag.example.net _ASNDATA_ _ASNDATA_
asn_lookup_ipv6 asn-zone6.example.com [_ASN_ _ASNCIDR_]
Utilise la zone spécifiée pour les recherches d'adresses IPv6. Si la zone prend en charge les recherches IPv4 et IPv6, utilisez à la fois asn_lookup et asn_lookup_ipv6 pour la même zone.

PARAMÈTRES ADMINISTRATEUR

asn_use_geodb ( 0 / 1 ) (valeur par défaut: 1)
Utilise le module Mail::SpamAssassin::GeoDB pour rechercher les numéros d'ASN. Vous avez besoin d'un module compatible comme GeoIP2 ou GeoIP avec une base de données FAI ou ASN installée (par exemple, ajoutez les EditionIDs GeoLite2-ASN dans GeoIP.conf pour le programme geoipupdate).

GeoDB ne définit que le tag _ASN_, et ne dispose pas de données pour _ASNCIDR_. Si vous avez besoin des deux, définissez asn_prefer_geodb sur 0 pour essayer d'abord les règles DNS.

asn_prefer_geodb ( 0 / 1 ) (valeur par défaut: 1)
Si cette valeur est activée, les recherches DNS (règles asn_lookup) ne seront pas exécutées si GeoDB trouve l'ASN. Définissez cette valeur à 0 pour que _ASNCIDR_ soit exécuté même si GeoDB trouve _ASN_.
asn_use_dns ( 0 / 1 ) (valeur par défaut: 1)
Définit à 0 pour ne jamais autoriser les recherches DNS.

BAYES

Le tokenizer bayesien utilisera les données ASN pour calculer les règles bayesiennes et ainsi affecter quelle règle BAYES_* sera déclenchée pour un message particulier. Aucune analyse approfondie de l'utilité de la tokenisation bayesienne pour les données ASN n'a été effectuée.
