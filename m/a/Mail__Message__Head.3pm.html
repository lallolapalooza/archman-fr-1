NOM

Mail::Message::Head - l'en-tête d'un message

HIÉRARCHIE

Mail::Message::Head
  est un Mail::Reporter
Mail::Message::Head est hérité par
  Mail::Box::IMAP4::Head
  Mail::Message::Head::Complete
  Mail::Message::Head::Delayed
  Mail::Message::Head::Subset

SYNTAXE

my $head = Mail::Message::Head->new;
$head->add('From: me@localhost');
$head->add(From => 'me@localhost');
$head->add(Mail::Message::Field->new(From => 'me'));
my $subject = $head->get('subject');
my @rec = $head->get('received');
$head->delete('From');

DESCRIPTION

"Mail::Message::Head" est l'en-tête MIME faisant partie des messages Mail::Message, qui sont stockés dans des dossiers Mail::Box.

Une longue liste d'en-têtes MIME standards avec leurs définitions peut être trouvée dans la RFC4021 (https://www.rfc-editor.org/rfc/rfc4021.html) et ses mises à jour RFC5322 et RFC6854.

ATTENTION!!! La majeure partie des fonctionnalités concernant les en-têtes de courrier est décrite dans Mail::Message::Head::Complete, qui est un objet d'en-tête mature. D'autres types d'en-têtes seront convertis vers ce type lorsque nécessaire.

Sur cette page sont décrites les méthodes générales disponibles sur n'importe quel en-tête. Lisez les différences sur les pages spécifiques des sous-classes.

Cette classe étend la section "DESCRIPTION" de Mail::Reporter.

OVERLOADED

overload: "" stringification
L'en-tête, lorsqu'il est utilisé comme chaîne de caractères, est formaté comme si Mail::Message::Head::Complete::string() avait été appelé, il renvoie donc un en-tête bien formé. Une exception est faite pour Carp, qui recevra une chaîne simplifiée afin d'éviter des messages difficiles à lire provenant de "croak" et "confess".

» exemple : utiliser un objet d'en-tête comme chaîne

print $head;     # stringification implicite par print
$head->print;    # idem
print "$head";   # stringification explicite
overload: bool true/false
Si l'en-tête ne contient aucune ligne (ce qui est illégal selon les RFC), alors "false" est retourné. Dans tous les autres cas, "true" est retourné.

Constructors

$class->build( [PAIR|$field]-LIST )
Une méthode rapide pour construire un en-tête avec de nombreuses lignes. Les PAIRs sont des paires "(name, content)" de l'en-tête, mais il est aussi possible de passer des objets Mail::Message::Field. Un en-tête Mail::Message::Head::Complete est créé en appelant simplement Mail::Message::Head::Complete::build(), puis chaque champ est ajouté. Les champs avec des noms dupliqués sont permis.

» exemple:

my $subject = Mail::Message::Field->new(Subject => 'xyz');
my $head = Mail::Message::Head->build(
  From     => 'me@example.com',
  To       => 'you@anywhere.aq',
  $subject,
  Received => 'one',
  Received => 'two',
);
print ref $head;

Créer un objet d'en-tête de message. L'objet stockera tous les champs d'un en-tête. Lorsque vous obtenez des informations de l'en-tête, elles vous sont retournées sous forme d'objets Mail::Message::Field, même si les champs peuvent être stockés différemment en interne.

Si vous essayez d'instancier un Mail::Message::Head, il se convertira automatiquement en un Mail::Message::Head::Complete — un en-tête complet. Améliore la base, voir "Constructors" dans Mail::Reporter.

L'en-tête

$obj->isDelayed()
Les en-têtes peuvent être lus partiellement, dans ce cas ils sont appelés delayed. Cette méthode renvoie "true" s'il reste des informations d'en-tête à lire. Elle renvoie "false" si toutes les données d'en-tête ont été lues. N'initie jamais de chargement.
$obj->isEmpty()
Y a-t-il des champs définis dans cet en-tête ? Attention, l'en-tête ne sera pas chargé pour ce cas : les en-têtes delayed renverront "true" dans tous les cas.
$obj->isModified()
Cet en-tête a-t-il été modifié après sa lecture ?

» exemple:

if($head->isModified) { ... }
$obj->knownNames()
Comme Mail::Message::Head::Complete::names(), mais ne retourne que les champs connus de l'en-tête, qui peuvent être moins nombreux que "names" pour les types d'en-têtes partiels. names() initie un chargement, tandis que knownNames() ne le fait pas.
$obj->message( [$message] )
Obtient (après définition) le message auquel cet en-tête appartient. N'initie pas de chargement.
$obj->modified( [BOOLEAN] )
Définit le drapeau modified à "BOOLEAN". Sans valeur, renvoie la valeur actuelle, mais vous pouvez alors utiliser isModified() qui est mieux adapté. Modifier ce drapeau n'initie pas de chargement de l'en-tête.

» exemple:

$head->modified(1);
if($head->modified) { ... }
if($head->isModified) { ... }
$obj->orderedFields()
Retourne les champs dans l'ordre dans lequel ils ont été lus ou ajoutés.

Accès à l'en-tête

$obj->get( $name, [$index] )
Obtient les données liées au champ avec le nom $name. La casse des caractères dans $name n'a pas d'importance.

S'il n'y a qu'un seul élément défini pour le $name, ou si un $index est spécifié comme second argument, seul l'élément spécifié est retourné. Si le champ $name correspond à plus d'un en-tête, la valeur retournée dépend du contexte. En contexte LIST, toutes les valeurs sont retournées dans l'ordre où elles ont été lues. En contexte SCALAR, seule la dernière valeur est retournée.

» exemple:

my $head = Mail::Message::Head->new;
$head->add('Received: abc');
$head->add('Received: xyz');
$head->add('Subject: greetings');
my @rec_list   = $head->get('Received');
my $rec_scalar = $head->get('Received');
print ",@rec_list,$rec_scalar,"     # ,abc xyz, xyz,
print $head->get('Received', 0);

NOM

Mail::Message::Head - en-tête d'un message MIME

INHERITANCE

Mail::Message::Head est une sous-classe de Mail::Reporter.

  Mail::Reporter
    isa Mail::Message::Head

SYNOPSIS

  use Mail::Message;

  # Lire un en-tête
  my $head = Mail::Message::Head->new;
  $head->read($parser);

  # Récupérer des champs
  my $subject = $head->get('Subject');
  my @to      = $head->get('To');

  # Ajouter/modifier des champs
  $head->set(Subject => 'A new subject');
  $head->add(CC => 'someone@example.com');

DESCRIPTION

Un objet Mail::Message::Head représente l'en-tête d'un message électronique. L'en-tête est une collection de champs, où chaque champ a un nom et une valeur. Les champs sont généralement stockés dans l'ordre où ils ont été lus à partir du message source.

Cette classe est une implémentation abstraite. Le comportement d'accès et de modification des champs dépend de la sous-classe spécifique utilisée (par exemple, Mail::Message::Head::Complete, Mail::Message::Head::Subset, Mail::Message::Head::Partial).

OVERLOADED

Aucune surcharge de méthode n'est définie dans cette classe.

METHODS

Accès aux champs

$obj->get( $name, [$index] )
Retourne la valeur du champ nommé $name. S'il y a plusieurs champs du même nom, ils sont retournés sous forme de tableau dans un contexte de liste. Dans un contexte scalaire, seul le dernier champ est retourné. Si $index est spécifié, le champ à cet index est retourné (commençant à 0).
$obj->getOne( $name )
Retourne la valeur du premier champ trouvé avec le nom $name. Lève une exception si aucun champ n'est trouvé.
$obj->getDate( $name, [$index] )
Identique à get(), mais tente de parser la valeur comme une date et retourne un objet DateTime::TimeZone::Local.
$obj->getRef( $name, [$index] )
Retourne la valeur brute (non-parsed) du champ nommé $name. Peut retourner un scalaire ou un tableau.
$obj->study( $name, [$index] )
Similaire à get(), mais fait plus d'efforts pour comprendre le contenu du champ. Mail::Message::Field::study() sera appelé pour le champ avec le nom de champ spécifié, qui retourne des objets Mail::Message::Field::Full. Dans un contexte scalaire seul le dernier champ de ce nom est retourné. Quand un $index est spécifié, cet élément est retourné.

À propos du corps

$obj->guessBodySize()
Essaie d'estimer la taille du corps de ce message, mais sans parser l'en-tête ou le corps. Le résultat peut être "undef" ou quelques pourcents de la taille réelle. Il peut même être très éloigné de la valeur réelle, c'est pourquoi c'est une estimation.
$obj->isMultipart()
Retourne si le corps du message associé est un corps multipart. Peut déclencher l'achèvement, quand le champ "Content-Type" n'est pas défini.

Internes

$obj->addNoRealize($field)
Ajoute un champ, comme le fait Mail::Message::Head::Complete::add(), mais évite le chargement d'un en-tête potentiellement partiel. Cette méthode ne teste pas la validité de l'argument, ni ne marque l'en-tête comme modifié. Cela ne déclenche pas d'achèvement.
$obj->addOrderedFields($fields)
$obj->fileLocation()
Retourne l'emplacement de l'en-tête dans le fichier, sous forme de paire début et fin. Le début est le premier octet de l'en-tête. La fin est le premier octet après l'en-tête.
$obj->load()
S'assure que l'en-tête est chargé. Ceci retourne l'objet en-tête chargé.
$obj->moveLocation($distance)
Déplace l'enregistrement de l'en-tête dans le fichier.
$obj->read($parser)
Lit les informations d'en-tête d'un message dans cette structure d'en-tête. Cette méthode est appelée par l'objet dossier (une sous-classe de Mail::Box), qui passe le $parser comme argument.
$obj->setNoRealize($field)
Définit un champ, mais évite le chargement d'un en-tête potentiellement partiel comme le fait set(). Cette méthode ne teste pas la validité de l'argument, ni ne marque l'en-tête comme modifié. Cela ne déclenche pas d'achèvement.

DÉTAILS

Champs d'en-tête ordonnés

Beaucoup d'implémentations Perl font une grosse erreur en perturbant l'ordre des champs d'en-tête. Pour certains champs (en particulier les groupes de renvoi, voir Mail::Message::Head::ResentGroup) l'ordre doit être maintenu.

MailBox maintiendra l'ordre des champs tels qu'ils ont été trouvés dans la source. Quand vous ajoutez un nouveau champ, il sera ajouté à la fin. Si vous remplacez un champ par une nouvelle valeur, il restera dans l'ordre original.

Implémentation de la classe d'en-tête

L'en-tête d'un objet de message MIME contient un ensemble de lignes, qui sont appelées des champs (par défaut représentés par des objets Mail::Message::Field). Selon la situation, la connaissance des champs peut être dans l'une des trois situations, chacune représentée par une sous-classe de ce module :

  • Mail::Message::Head::Complete

    Dans ce cas, il est sûr que toutes les connaissances sur l'en-tête sont disponibles. Quand vous get() des informations de l'en-tête et qu'elles n'y sont pas, elles n'y seront jamais.

  • Mail::Message::Head::Subset

    Il n'y a aucune certitude que toutes les lignes d'en-tête soient connues (probablement pas). Cela peut résulter de la lecture d'un fichier d'index rapide, comme décrit dans Mail::Box::MH::Index. L'objet est automatiquement transformé en Mail::Message::Head::Complete quand toutes les lignes d'en-tête doivent être connues.

  • Mail::Message::Head::Partial

    Un en-tête partiel est comme un en-tête subset : probablement l'en-tête est incomplet. Cela signifie que vous n'êtes pas sûr si un get() pour un champ échoue parce que le champ ne fait pas partie du message ou s'il échoue parce qu'il n'est pas encore connu du programme. Là où l'en-tête subset sait où obtenir les autres champs, l'en-tête partiel ne le sait pas. Il ne peut pas cacher son imperfection.

  • Mail::Message::Head::Delayed

    Dans ce cas, aucun champ individuel n'est connu. L'accès à cet en-tête déclenchera toujours le chargement de l'en-tête complet.

Sous-ensembles de champs d'en-tête

Les en-têtes de messages peuvent être assez volumineux, et par conséquent MailBox fournit un accès simplifié à certains sous-ensembles d'informations. Vous pouvez récupérer ces ensembles de champs ensemble, les créer et les supprimer en groupe.

Actuellement, les ensembles suivants sont définis :

  • Mail::Message::Head::ResentGroup

    Un groupe de renvoi est un ensemble de champs qui est utilisé pour enregistrer une étape dans la transmission du message de l'expéditeur original à la destination.

    Chaque étape ajoute un ensemble d'en-têtes pour indiquer quand le message a été reçu et comment il a été transféré (sans modification). Ces champs sont mieux créés en utilisant Mail::Message::bounce().

  • Mail::Message::Head::ListGroup

    Champs utilisés pour administrer et enregistrer l'activité des listes de diffusion. Le logiciel de liste de diffusion doit jouer des tours au message original pour pouvoir récupérer la réponse à ce message vers la liste de diffusion. Habituellement, un grand nombre de lignes sont ajoutées.

  • Mail::Message::Head::SpamGroup

    Un ensemble de champs qui contient les champs d'en-tête produits par le logiciel de détection de spam. Vous voudrez peut-être supprimer ces champs lorsque vous stockez un message pendant une période prolongée.
