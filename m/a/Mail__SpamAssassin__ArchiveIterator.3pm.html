NOM

Mail::SpamAssassin::ArchiveIterator - trouver et traiter les messages un par un

SYNOPSIS

my $iter = Mail::SpamAssassin::ArchiveIterator->new(
  { 
    'opt_max_size' => 500 * 1024,  # 0 signifie pas de limite
    'opt_cache' => 1,
  }
);
$iter->set_functions( \&wanted, sub { } );
eval { $iter->run(@ARGV); };
sub wanted {
  my($class, $filename, $recv_date, $msg_array) = @_;
  ...
}

DESCRIPTION

Le module Mail::SpamAssassin::ArchiveIterator parcourra un ensemble de fichiers mbox, mbx et de répertoires (un message par fichier) et générera une liste de messages. Il appellera ensuite les sous-routines "wanted_sub" et "result_sub" de manière appropriée pour chaque message.

MÉTHODES

$item = Mail::SpamAssassin::ArchiveIterator->new( [ { opt => val, ... } ] )
Construit un objet "Mail::SpamAssassin::ArchiveIterator". Vous pouvez passer les paires clé-valeur suivantes au constructeur. Les paires sont optionnelles, sauf indication contraire.
opt_max_size
La valeur de l'option opt_max_size détermine une limite (en octets) au-delà de laquelle un message est considéré comme trop grand et est ignoré par ArchiveIterator.

Une valeur de 0 signifie pas de limite de taille, tous les messages sont examinés. Une valeur indéfinie signifie une limite par défaut de 500 KiB.

opt_all
Définir cette option à vrai établit implicitement opt_max_size à 0, c'est-à-dire pas de limite de taille de message, tous les messages sont traités par ArchiveIterator. Pour la compatibilité avec les anciennes versions de SpamAssassin qui ne possédaient pas l'option opt_max_size.
opt_scanprob
Scanne les messages de manière aléatoire avec une probabilité de N, où N varie de 0.0 (aucun message scanné) à 1.0 (tous les messages scannés). La valeur par défaut est 1.0.

Ce réglage peut être spécifié séparément pour chaque cible.

opt_before
Utilise uniquement les messages reçus après la date donnée. Les valeurs négatives sont un décalage par rapport au temps actuel, par exemple -86400 = dernières 24 heures ; ou tel que parsé par Time::ParseDate (par exemple, '-6 mois').

Ce réglage peut être spécifié séparément pour chaque cible.

opt_after
Similaire à opt_before, mais les messages ne sont utilisés que s'ils sont reçus après la date donnée.

Ce réglage peut être spécifié séparément pour chaque cible.

opt_want_date
Définit à 1 (par défaut) si vous souhaitez que la date de réception soit incluse dans le rappel "wanted_sub". Définissez à 0 pour éviter cela ; il est conseillé de le définir à 0 si possible, car cela entraîne un coût de performance.
opt_skip_empty_messages
Définit à 1 si vous souhaitez ignorer les messages corrompus ou de taille 0. La valeur par défaut est 0.
opt_cache
Définit à 0 (par défaut) si vous ne souhaitez pas utiliser les informations mises en cache pour accélérer ArchiveIterator. Définissez à 1 pour activer. Ce réglage nécessite également "opt_cachedir".
opt_cachedir
Définit le chemin du répertoire où vous souhaitez stocker les informations mises en cache pour "opt_cache", si vous ne souhaitez pas qu'elles soient mélangées avec les fichiers d'entrée (ce qui est le cas par défaut). Le répertoire doit être lisible et accessible en écriture.
wanted_sub
Référence vers une sous-routine qui traite les données du message. Est souvent définie via set_functions(). La sous-routine recevra 5 valeurs : classe (scalaire), nom de fichier (scalaire), date de réception (scalaire), contenu du message (tableau de références, une ligne par élément) et le format du message ('f' pour fichier, 'm' pour mbox, 'b' pour mbx).

Note : Si "opt_want_date" est défini à 0, la valeur scalaire de la date de réception sera indéfinie.

result_sub
Référence vers une sous-routine qui traite les résultats de "wanted_sub" pour chaque message traité. Est souvent définie via set_functions(). La sous-routine recevra 3 valeurs : classe (scalaire), résultat (scalaire, retourné par "wanted_sub") et date de réception (scalaire).

Note : Si "opt_want_date" est défini à 0, la valeur scalaire de la date de réception sera indéfinie.

scan_progress_sub
Référence vers une sous-routine qui est appelée de manière intermittente pendant la phase 'scan' du traitement par lots. Il n'y a aucune garantie sur la fréquence d'appel.
opt_from_regex
Permet une flexibilité dans la spécification du délimiteur From au format mbox.

L'expression régulière par défaut est :

/^From \S+ ?(\S\S\S \S\S\S .?\d .?\d:\d\d:\d\d \d{4}|.?\d-\d\d-\d{4}_\d\d:\d\d:\d\d_)/

Certains programmes SpamAssassin comme sa-learn utiliseront l'option de configuration 'mbox_format_from_regex' pour remplacer l'expression régulière par défaut.

set_functions( \&wanted_sub, \&result_sub )
Définit les sous-routines utilisées pour le traitement des messages (wanted_sub) et le reporting des résultats. Pour plus d'informations, voir new() ci-dessus.
run ( @target_paths )
Génère la liste des messages à traiter, puis exécute chaque message via la sous-routine configurée pour le traitement.

Les fichiers compressés sont détectés et décompressés automatiquement, quel que soit le type de fichier. Les formats pris en charge sont "gzip", "bzip2", "xz", "lz4", "lzip", "lzo". Gzip est décompressé via le module IO::Zlib, tandis que les autres utilisent leurs outils spécifiques (bzip2/xz/lz4/lzip/lzop). Les fichiers compressés de type mailbox/mbox ne sont pas pris en charge.

Le tableau de répertoires target_paths doit avoir un élément par chemin sous le format suivant : "class:format:raw_location", ou une référence à un dictionnaire avec des paires clé-valeur et une clé 'target' avec une valeur dans ce format.

Les paires clé-valeur qui peuvent être utilisées sont : opt_scanprob, opt_after, opt_before. Pour plus d'informations sur leur effet, voir la documentation de la méthode new.

run() renvoie 0 en cas d'erreur (par exemple, impossible d'ouvrir un fichier) et 1 en cas de succès (pas d'erreurs).

class
Est 'h' pour ham ou 's' pour spam. Si la classe est composée de plusieurs caractères, elle sera tronquée. Si elle est vide, elle est considérée comme 'h' par défaut.
format
Est le format de raw_location. "dir" est un répertoire avec des fichiers de messages individuels, "file" est un fichier avec un seul message, "mbox" est un fichier mbox, ou "mbx" est un répertoire mbx.

"detect" peut également être utilisé. Cela suppose "mbox" pour tout fichier dont le chemin contient le motif "/\.mbox/i", "file" pour tout ce qui n'est pas un répertoire, ou "directory" sinon.
