NOM

Mail::SpamAssassin::Message - décoder, rendre et conserver un message RFC-2822

DESCRIPTION

Ce module encapsule un message électronique et permet d'accéder aux différentes parties du message MIME et aux métadonnées du message.

La structure du message, après l'initiation d'un cycle parse(), ressemble à ceci :

Objet Message, également nœud de niveau supérieur dans l'arbre Message::Node
   |
   +---> Objet Message::Node pour les autres parties de la structure MIME
   |       |---> [ d'autres parties Message::Node ... ]
   |       [ autres ... ]
   |
   +---> Objet Message::Metadata pour conserver les métadonnées

MÉTHODES PUBLIQUES

new()
Crée un objet Mail::SpamAssassin::Message. Prend en paramètre une référence de hachage. Les paires clé/valeur utilisées sont les suivantes :

"message" est soit undef (qui utilisera STDIN), une chaîne scalaire - une chaîne contenant un message entier, une référence vers une telle chaîne, une référence de tableau du message avec une ligne par élément de tableau, ou un glob de fichier ou un objet IO::File qui contient le contenu entier du message.

Remarque : le message est censé être généralement au format RFC 2822, incluant optionnellement une ligne de séparateur de message mbox (la ligne "From ") comme première ligne.

"parse_now" spécifie si l'arbre MIME doit être créé au moment de la création de l'objet ou plus tard, si nécessaire.

L'option parse_now est, par défaut, définie à false (0). Cela permet à SpamAssassin de ne pas avoir à générer l'arbre des objets Mail::SpamAssassin::Message::Node et de leurs données associées si l'arbre ne doit pas être utilisé. C'est pratique, par exemple, lors de l'exécution de "spamassassin -d", qui n'a besoin que de l'en-tête et du corps originaux, lesquels sont toujours traités lors de la création de l'objet.

"subparse" spécifie combien de niveaux de récursion MIME doivent être analysés. Par défaut, 20.

find_parts()
Utilisé pour rechercher dans l'arbre des parties MIME spécifiques. Voir Mail::SpamAssassin::Message::Node pour plus de détails.
get_pristine_header()
Retourne les en-têtes originaux du message. Si aucun nom d'en-tête spécifique n'est donné en paramètre (insensible à la casse), alors tous les en-têtes seront retournés sous forme scalaire, y compris la ligne vide à la fin des en-têtes.

Si appelé dans un contexte de tableau, un tableau sera retourné avec chaque en-tête spécifique dans un élément différent. Dans un contexte scalaire, le dernier en-tête spécifique est retourné.

Exemple : Si 'Subject' est spécifié comme en-tête, et qu'il y a 2 en-têtes Subject dans un message, le dernier/le plus bas dans le message est retourné dans le contexte scalaire ou les deux sont retournés dans le contexte de tableau.

Au fait, retourner le dernier champ d'en-tête (pas le premier) est cohérent avec les signatures DKIM, qui recherchent et couvrent plusieurs champs d'en-tête de bas en haut selon la balise 'h'. Gardons cela ainsi.

Remarque : l'en-tête retourné inclura la nouvelle ligne finale et tout retrait d'espace blanc intégré.

get_mbox_separator()
Retourne le séparateur mbox trouvé dans le message, ou undef s'il n'y en avait pas.
get_body()
Retourne un tableau du corps du message original, une ligne par élément de tableau.
get_pristine()
Retourne une chaîne scalaire du message original entier.
get_pristine_body()
Retourne une chaîne scalaire du corps du message original.
get_pristine_body_digest()
Retourne le résumé hexadécimal SHA1 du corps du message original. Les fins de ligne CRLF sont normalisées en LF avant le hachage.
get_msgid()
Retourne l'en-tête Message-ID pour le message, avec les <> et les espaces environnants supprimés. Retourne undef s'il n'y a rien trouvé entre <>.
generate_msgid()
Génère un "Message-ID" calculé au format sha1hex@sa_generated, en utilisant les en-têtes To, Date et le corps original comme source pour le hachage.
extract_message_metadata($permsgstatus)
$str = get_metadata($hdr)
put_metadata($hdr, $text)
delete_metadata($hdr)
$str = get_all_metadata()
finish_metadata()
Détruit les métadonnées de ce message. Une fois qu'un message a été entièrement analysé, les métadonnées ne sont plus nécessaires. Leur destruction libérera de la mémoire.
finish()
Nettoie un objet afin qu'il puisse être détruit.
receive_date()
Retourne une valeur time_t de la date de réception du message courant, ou l'heure actuelle si la date de réception n'a pu être déterminée.

MÉTHODES D'ANALYSE, NON PUBLIQUES

Ces méthodes prennent un message de type RFC2822-esque et créent un arbre avec toutes les parties du corps MIME incluses. Ces parties seront décodées si nécessaire, et les parties text/html seront rendues dans un format texte standard, adapté à une utilisation dans SpamAssassin.

parse_body()
parse_body() passe la partie du corps qui a été passée à l'analyseur de partie correct, soit _parse_multipart() pour les parties multipart/*, soit _parse_normal() pour tout le reste. Les sections multipart deviennent la racine de sous-arbres, tandis que tout le reste devient une feuille dans l'arbre.

Pour les messages multipart, le premier appel à parse_body() ne crée pas de nouveau sous-arbre et utilise simplement le nœud parent pour contenir les enfants. Tous les autres appels à parse_body() provoqueront la création d'une nouvelle racine de sous-arbre et les enfants existeront sous cette racine. (ceci est juste pour éviter que l'arbre n'ait un nœud racine qui pointe vers le nœud racine réel...)

_parse_multipart()
Génère un nœud racine, et pour chaque partie enfant appelle parse_body() pour générer l'arbre.
_parse_normal()
Génère un nœud feuille et l'ajoute au parent.
