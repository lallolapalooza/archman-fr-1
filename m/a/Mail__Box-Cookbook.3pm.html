NOM

Mail::Box-Cookbook - Exemples d'utilisation de Mail::Box

DESCRIPTION

La bibliothèque Mail::Box est une collection de classes pour accéder et gérer les boîtes aux lettres d'une manière indépendante du format des boîtes. Ce manuel montre quelques applications simples. Veuillez contribuer avec des exemples et des corrections. Vous pouvez également aider à examiner les programmes inclus dans les répertoires "scripts/" et "examples/" de la distribution.

Le Gestionnaire

Pour plus de détails sur tous les paquets impliqués dans la suite Mail::Box, vous devez lire Mail::Box-Overview. Mais vous n'avez pas besoin d'en savoir beaucoup si vous voulez utiliser la suite Mail::Box.

Utilisez le gestionnaire pour ouvrir vos boîtes aux lettres. Vous en bénéficierez certainement. Le gestionnaire s'occupe de détecter quel type de boîte aux lettres vous utilisez et quelles boîtes sont ouvertes. Cela évite de rouvrir accidentellement une boîte déjà ouverte.

Le script "examples/open.pl" contient principalement

my $mgr    = Mail::Box::Manager->new;
my $folder = $mgr->open($filename);
foreach my $message ($folder->messages) {
    print $message->get('Subject') || '<pas de sujet>', "\n";
}
$folder->close;

qui montre toutes les fonctions les plus importantes. Cela affichera la liste de tous les sujets des messages dans la boîte spécifiée. Par conséquent : bien que le nombre de paquets inclus dans la bibliothèque Mail::Box soit très important, peu sont nécessaires pour les programmes normaux.

Au lieu d'appeler "close" sur la boîte, vous pouvez également appeler

$mgr->closeAllFolders;

Si vous oubliez de fermer une boîte, les modifications ne seront pas enregistrées. Cela pourrait changer à l'avenir.

Messages multipartites

Aux débuts d'Internet, les messages multipartites étaient très rares. Cependant, ces dernières années, une grande partie des messages transmis sont en plusieurs parties. Cela rend la gestion des corps de messages un peu plus difficile : quelle est alors la partie la plus importante à lire ?

Pour compliquer les choses, les messages multipartites peuvent être imbriqués : chaque partie peut être un message multipartite en soi. Cela signifie que les programmes qui traitent le contenu des messages doivent être récursifs ou ignorer les parties multipartites.

La partie centrale du script "examples/multipart.pl" se lit comme suit :

foreach my $message ($folder->messages) {
    show_type($message);
}
show_type($) {
    my $msg = shift;
    print $msg->get('Content-Type'), "\n";
    if($msg->isMultipart) {
        foreach my $part ($msg->parts) {
            show_type($part);
        }
    }
}

Chaque partie est un message en soi. Elle a un en-tête et un corps. Un message multipartite a un corps spécial : il contient une liste de parties et éventuellement aussi un prélude et un épilogue, qui sont respectivement les lignes avant et après les parties. Ces textes peuvent être ignorés, car ils sont uniquement descriptifs sur la façon dont le multipart a été créé.

Filtrage

L'objectif est de sélectionner quelques messages d'une boîte aux lettres et de les déplacer vers une autre. Le script "examples/takelarge.pl" montre comment y parvenir. Attention : cela écrasera votre boîte aux lettres d'entrée !

La description abstraite de la partie critique :

my $inbox = $mgr->open('inbox', access => 'rw');
my $large = $mgr->open('large', access => 'a', create => 1);
foreach my $message ($inbox->messages) {
    next if $message->size < $size;
    $mgr->moveMessage($large, $message);
}
$inbox->close;
$large->close;

La boîte "inbox" est ouverte en lecture et écriture : elle lit d'abord tous les messages, puis réécrit la boîte plus petite sans les messages déplacés. La boîte "large" est créée si elle n'existe pas encore. Dans tous les cas, les messages seront ajoutés à la fin de la boîte.

Le gestionnaire est nécessaire pour déplacer les messages : pour le désenregistrer de la première boîte et le réenregistrer dans la seconde. Vous pouvez déplacer plusieurs messages en même temps, si vous le souhaitez. Lorsque vous déplacez vers une boîte qui n'est pas ouverte, vous ferez encore mieux : ce sera plus rapide :

my @move = grep {$_->size >= $size} $inbox->messages;
$mgr->moveMessage($large, @move);

Dans cet exemple, la "taille" du message détermine s'il est déplacé ou non. Naturellement, il existe de nombreux autres critères que vous pouvez utiliser. Par exemple, utilisez "timestamp" pour trouver les anciens messages :

use constant YEAR => 365 * 24 * 60 * 60;
my $now = time;
my @old = grep {$_->timestamp - $now > YEAR} $inbox->messages;
$mgr->moveMessage($oldbox, @old);

Créer une réponse

Le traitement complexe des messages est implémenté dans Mail::Message::Construct et est chargé automatiquement lorsque vous en avez besoin. Il suffit d'appeler simplement "reply" sur n'importe quel message :

my $folder  = ...;
my $message = $folder->message(8);
my $reply   = $message->reply;
$folder->addMessage($reply);
$reply->print;

La méthode est assez complexe, comme le montre le script "examples/reply.pl", dans lequel la construction d'un message de réponse est illustrée.

Trois types de réponses peuvent être générés : une qui n'inclut pas le message original (NO), une qui inclut le message original cité (INLINE) et, comme troisième option, le message original en pièce jointe (ATTACH). La réponse par défaut est INLINE.

Le paramètre "include" sélectionne le type de réponse. Lors de la réponse à des messages binaires ou multipartites, INLINE est automatiquement promu en ATTACH. Par défaut, le nom de signature des expéditeurs est supprimé. Les messages multipartites sont dépouillés des pièces jointes considérées comme des signatures. Si un multipart (après suppression) ne contient qu'une seule partie et que INLINE est demandé, il sera "aplatit" : le message de réponse peut alors être un simple parti.

Voir les paramètres qui peuvent être transmis à reply dans Mail::Message::Construct. Pour une réponse simple, le résultat sera :

prélude
original cité
postlude
--
signature

Un corps multipartite sera :

partie 1: prélude
        [ voir pièce jointe ]
        postlude
partie 2: multipartite original dépouillé
partie 3: signature

Construire un message

Il existe trois façons de créer un message autre qu'une réponse :

  • Mail::Message::buildFromBody()

    Commence par créer un corps, puis transforme ce corps en message.

  • Mail::Message::build()

    Crée le message complet en une seule étape.

  • Mail::Message::read()

    Lit un message à partir d'un fichier, d'un scalaire ou d'un tableau de lignes.

Toutes les trois méthodes sont implémentées dans Mail::Message::Construct. S'il vous plaît, faites-vous une faveur et privilégiez les méthodes "build*" sur les méthodes "read", car elles sont plus puissantes. Utilisez la méthode "read" uniquement lorsque vous avez le message dans STDIN ou dans un tableau de lignes fourni par un programme externe.

Important : rappelez-vous que les informations sur le contenu du corps (les lignes "Content-*" dans l'en-tête) sont stockées dans l'objet corps, tant que ce corps n'est pas contenu dans un objet message.

Par exemple, la méthode $message "decoded" renvoie le corps décodé du message $message. C'est un objet corps en soi, cependant, en dehors d'un message réel. Vous pouvez ensuite jouer avec lui en concaténant des textes : cela donne à nouveau un nouveau corps. Chaque corps contient les informations "Content-*" correctes. Ensuite, vous pouvez enfin créer un message en spécifiant le corps et les lignes d'en-tête supplémentaires. À ce stade, vous devez spécifier l'expéditeur et le destinataire (les lignes "From" et "To"). À ce stade, le corps sera auto-encodé pour être accepté par les boîtes aux lettres et les programmes de transmission.

NOM

Mail::Box-Cookbook

DESCRIPTION

Mail::Box-Cookbook est un livre de recettes pour le module Mail::Box, qui fournit des guides et des exemples pour la création de messages en Perl. Le module se concentre sur la création de messages avec une structure et un format appropriés, permettant la gestion des données au format MIME, des encodages de transfert et d'autres aspects pertinents.
