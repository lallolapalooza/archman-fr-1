NAME

Mail::DKIM::ARC::Signer - Génère une signature DKIM pour un message

VERSION

version 1.20240923

SYNOPSIS

use Mail::DKIM::ARC::Signer;
use Mail::DKIM::TextWrap;  # recommandé
# créer un objet de cette classe
my $signer = Mail::DKIM::ARC::Signer->new(
                Algorithm => 'rsa-sha256',
                Chain => 'none',    # ou pass|fail|ar
                Domain => 'example.org',
                SrvId => 'example.org',
                Selector => 'selector1',
                KeyFile => 'private.key',
                Headers => 'x-header:x-header2',
           );
# lire un mail depuis un fichier d'entrée
$signer->load(*STDIN);
# NOTE: tout mail qui est scellé avec ARC doit avoir un header d'Authentication-Results pour que le scellé ARC puisse couvrir ces résultats copiés dans un header d'ARC-Authentication-Results.
# ou lire un mail et le passer à la signature, ligne par ligne
while (<STDIN>)
{
    # supprimer les terminaisons locales
    chomp;
    s/\015$//;
    # utiliser les terminaisons SMTP
    $signer->PRINT("$_\015\012");
}
$signer->CLOSE;
die 'Failed' $signer->result_detail() unless $signer->result() eq 'sealed';
# obtenir tous les headers de signature pour préfixer le message
# ARC-Seal, ARC-Message-Signature et ARC-Authentication-Results
# dans cet ordre.
print $signer->as_string;

DESCRIPTION

Cette classe fait partie de Mail::DKIM et est responsable de générer des scellés ARC pour un message donné. Vous créez un objet de cette classe, en spécifiant les paramètres pour le scellé ARC-Message-Signature que vous souhaitez créer.

Vous devez également passer la valeur 'Chain' (pass ou fail) de validation des scellés ARC précédents dans le message.

Ensuite, vous lui passez le message complet en utilisant "PRINT()", puis "CLOSE()".

Finalement, utilisez "as_string()" pour obtenir les nouveaux headers ARC.

Note: vous ne pouvez sceller qu'un message qui a déjà un header Authentication-Results ajouté, soit en utilisant "PRINT()" pour pré-préparer le message dans ce module, soit par un message qui a déjà été authentifié par les mécanismes de scan d'entrée de votre système.

Il n'est pas nécessaire de sceller un message qui a déjà des signatures DKIM si vous ne modifiez pas le message, de sorte que la signature DKIM-Signature existante ou le scellé ARC-Message-Signature dans le mail ne sera pas rompu.

Signatures Propres

Mail::DKIM inclut un module de signature qui insère des lignes de séparation dans la signature générée, de sorte qu'elle soit plus lisible dans le message final. Pour activer ce module, appelez simplement

use Mail::DKIM::TextWrap;

dans votre programme avant de générer la signature.

CONSTRUCTOR

new()

Crée un signataire orienté objet.

# créer un signataire en utilisant la politique par défaut
my $signer = Mail::DKIM::ARC::Signer->new(
                Algorithm => 'rsa-sha256',
                Chain => 'none',    # ou pass|fail|ar
                Domain => 'example.org',
                SrvId => 'example.org',
                Selector => 'selector1',
                KeyFile => 'private.key',
                Headers => 'x-header:x-header2',
           );
Key
au lieu d'utiliser "KeyFile", utilisez "Key" pour utiliser un objet Mail::DKIM::PrivateKey déjà chargé.
Chain
valeur de cv= pour le header de Seal. "ar" signifie le copier d'un header Authentication-Results, ou utiliser none s'il n'y en a pas.
SrvId
l'authserv-id dans les headers Authentication-Results, par défaut c'est le Domain.
Headers
une liste séparée par des deux-points de headers à signer, ceci est ajouté à la liste des headers par défaut, comme dans la spécification DKIM.

Pour chaque header spécifié, tous les headers de ce type présents dans le message seront signés, mais les headers non présents ne seront pas signés.

Si vous voulez plus de contrôle sur les headers signés, utilisez la méthode extended_headers() à la place.

La liste des headers par défaut est la suivante:

From Sender Reply-To Subject Date
Message-ID To Cc MIME-Version
Content-Type Content-Transfer-Encoding Content-ID Content-Description
Resent-Date Resent-From Resent-Sender Resent-To Resent-cc
Resent-Message-ID
In-Reply-To References
List-Id List-Help List-Unsubscribe List-Subscribe List-Post List-Owner List-Archive
Tags
une référence optionnelle de headers supplémentaires à ajouter à la signature ARC.
SealTags
une référence optionnelle de headers supplémentaires à ajouter au scellé ARC.

METHODS

PRINT()

Envoie une partie du message à la signature.

$signer->PRINT("une ligne du message\015\012");

Envoie le contenu du message à signer à la signature. L'API est conçue ainsi pour que le message complet ne soit pas nécessaire à charger en mémoire.

Note: bien que la méthode PRINT() attende que vous utilisiez les terminaisons de ligne SMTP, vous ne devriez pas utiliser la technique de dot-stuffing décrite dans le RFC 2821 section 4.5.2. Vous ne devriez pas non plus utiliser une séquence de <CR><LF>.<CR><LF> pour terminer le message.

CLOSE()

Appelez ceci lorsque vous avez fini d'envoyer le message.

$signer->CLOSE;

Cette méthode termine le processus de canonicalisation, calcule un hash et génère une signature.

extended_headers()

Cette méthode remplace les headers à signer et permet plus de contrôle que ce qui peut être obtenu avec le paramètre Headers dans le constructeur.

La méthode attend un HashRef à passer.

Les clés sont les headers à signer, et les valeurs sont le nombre de headers de ce type à signer, ou les valeurs spéciales '*' et '+'.

* signe tous les headers de ce type présents dans le message.

+ signe tous les headers de ce type + 1 présents dans le message pour éviter que des headers supplémentaires ne soient ajoutés.

Vous pouvez remplacer n'importe quel header par défaut en l'incluant dans le hashref, et le désactiver en donnant une valeur 0.

Les clés sont insensibles à la casse avec les valeurs supplémentaires jusqu'à la valeur maximale.

Headers => {
    'X-test'  => '*',
    'x-test'  => '1',
    'Subject' => '+',
    'Sender'  => 0,
},

add_signature()

Utilisé par les politiques de signature pour créer une nouvelle signature.

$signer->add_signature(new Mail::DKIM::Signature(...));

Les politiques de signature peuvent utiliser cette méthode pour spécifier des paramètres complets pour la signature, y compris le type de signature. Pour plus d'informations, voir Mail::DKIM::SignerPolicy.

algorithm()

Obtenir ou définir l'algorithme sélectionné.

$alg = $signer->algorithm;
$signer->algorithm('rsa-sha256');

domain()

Obtenir ou définir le domaine sélectionné.

$alg = $signer->domain;
$signer->domain('example.org');

load()

Charge le message complet depuis un fichier d'entrée.

$signer->load($file_handle);

Lit un message complet depuis le fichier désigné, en le transmettant à la signature. Le message doit utiliser des terminaisons de ligne <CRLF> (comme le protocole SMTP).

headers()

Détermine quelles headers seront signées.

my $headers = $signer->headers;

Ceci est une chaîne contenant les noms des champs d'header qui seront signés, séparés par des deux-points.

key()

Obtenir ou définir l'objet Mail::DKIM::PrivateKey à utiliser.

$key = $signer->key;

Obtient ou définit l'objet Mail::DKIM::PrivateKey à utiliser.

Mail::DKIM::ARC::Signer(3pm) - Arch Linux Man Pages

NAME

Mail::DKIM::ARC::Signer - signing ARC headers

VERSION

1.20240923-2

SYNOPSIS

 use Mail::DKIM::ARC::Signer;
 use Mail::DKIM::PrivateKey;

 my $signer = Mail::DKIM::ARC::Signer->new(
  domain     => 'example.com',
  selector   => 'alpha',
  key        => Mail::DKIM::PrivateKey->load(File => 'private.key'),
  # ... other options
 );
 $signer->sign($message);
 my $arc_headers = $signer->as_string;

DESCRIPTION

This module implements ARC (Authenticated Received Chain) signing as specified in RFC 8617. It allows you to add ARC-Seal and ARC-Authentication-Results headers to messages, providing an additional layer of authentication.

ARC is designed to allow intermediaries to sign messages, providing cryptographic proof that the message hasn't been tampered with since it left the previous signing entity. This is particularly useful in scenarios like mailing lists, where the original DKIM signature might be invalidated by the list's processing.

This module provides the signing functionality for ARC. For verification, refer to Mail::DKIM::ARC::Verifier.

CONSTRUCTOR

new()

Create a new Mail::DKIM::ARC::Signer object.

 my $signer = Mail::DKIM::ARC::Signer->new(
  domain        => 'example.com', # Required
  selector      => 'alpha',       # Required
  key           => $private_key_object, # Required, see key()
  # Optional parameters:
  identity      => 'signing.example.net', # Default: domain
  timestamp     => time,          # Default: time
  canonicalization => 'relaxed/simple', # Default: relaxed/simple
  body_hash_alg => 'sha256',      # Default: sha256
  # For ARC-Seal
  previous_dkim_signers => [ ... ], # list of Mail::DKIM::Signature objects
  previous_arc_signers  => [ ... ], # list of Mail::DKIM::ARC::Signature objects
 );

Arguments are as follows:

domain
The domain name of the signing entity. This is required.
selector
The selector for the signing key. This is required.
key
The private key object used for signing. This is required. It must support the sign_digest() method. See also key() and key_file().
identity
The identity of the signing entity, as defined in RFC 8617 Section 3.5. Defaults to the value of domain.
timestamp
The timestamp to use for the signature. Defaults to the current time. This should be a Unix timestamp.
canonicalization
The canonicalization method to use for signing. Defaults to relaxed/simple. This should be a string like simple/simple, relaxed/simple, simple/relaxed, or relaxed/relaxed.
body_hash_alg
The algorithm to use for hashing the message body. Defaults to sha256. Supported algorithms include sha1 and sha256.
previous_dkim_signers
A list of Mail::DKIM::Signature objects representing the DKIM signatures of the original message. This is used when creating an ARC-Seal signature.
previous_arc_signers
A list of Mail::DKIM::ARC::Signature objects representing previous ARC signatures in the chain. This is used when creating an ARC-Seal signature.

METHODS

sign()

Sign the given message.

 $signer->sign($message);

The $message argument should be a raw MIME message string.

This method prepares the necessary information for creating the ARC headers. It calculates body hashes and performs the signing operations.

This method must be called before calling as_string() or as_strings()

domain()

Get or set the domain name.

 my $domain = $signer->domain;
 $signer->domain('new.example.com');

selector()

Get or set the key selector.

 my $selector = $signer->selector;
 $signer->selector('beta');

key()

Get or set the private key object.

 my $key = $signer->key;
 $signer->key(Mail::DKIM::PrivateKey->load(File => 'private.key'));

The key object can be any object that implements the sign_digest() method. (Providing your own object can be useful if your actual keys are stored out-of-process.)

If you use this method to specify a private key, do not use "key_file()".

key_file()

Get or set the filename containing the private key.

 my $filename = $signer->key_file;
 $signer->key_file('private.key');

If you use this method to specify a private key file, do not use "key()".

message_originator()

Access the "From" header.

 my $address = $signer->message_originator;

Returns the "originator address" found in the message, as a Mail::Address object. This is typically the (first) name and email address found in the From: header. If there is no From: header, then an empty Mail::Address object is returned.

To get just the email address part, do:

 my $email = $signer->message_originator->address;

See also "message_sender()".

message_sender()

Access the "From" or "Sender" header.

 my $address = $dkim->message_sender;

Returns the "sender" found in the message, as a Mail::Address object. This is typically the (first) name and email address found in the Sender: header. If there is no Sender: header, it is the first name and email address in the From: header. If neither header is present, then an empty Mail::Address object is returned.

To get just the email address part, do:

 my $email = $dkim->message_sender->address;

The "sender" is the mailbox of the agent responsible for the actual transmission of the message. For example, if a secretary were to send a message for another person, the "sender" would be the secretary and the "originator" would be the actual author.

signatures()

Access list of generated signature objects.

 my @signatures = $dkim->signatures;

Returns all generated signatures, as a list.

as_string()

Returns the new ARC headers

 my $pre_headers = $signer->as_string();

The headers are separated by \015\012 (SMTP line separator) including a trailing separator, so can be directly injected in front of the raw message.

as_strings()

Returns the new ARC headers

 my @pre_headers = $signer->as_string();

The headers are returned as a list so you can add whatever line ending your local MTA prefers.
