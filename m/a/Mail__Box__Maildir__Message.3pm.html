NOM

Mail::Box::Maildir::Message - un message dans un dossier Maildir

HÉRITAGE

Mail::Box::Maildir::Message
  est un Mail::Box::Dir::Message
  est un Mail::Box::Message
  est un Mail::Message
  est un Mail::Reporter

SYNTAXE

mon $folder  = Mail::Box::Maildir->new(...);
mon $message = $folder->message(10);

DESCRIPTION

Un "Mail::Box::Maildir::Message" représente un message dans un dossier Maildir. Chaque message est stocké dans un fichier séparé.

Drapeaux dans le nom de fichier

Lorsque de nouveaux messages arrivent sur un système et doivent être stockés dans un dossier maildir, ils sont placés dans le sous-répertoire "new" du dossier (créés d'abord dans le sous-répertoire "tmp" puis immédiatement déplacés vers "new"). Les informations suivantes ont été trouvées sur https://cr.yp.to/proto/maildir.html.

Chaque message est écrit dans un fichier séparé. Le nom du fichier est construit à partir de l'heure d'arrivée, d'un nom d'hôte, d'un composant unique, d'un marqueur de syntaxe et de drapeaux. Par exemple "1014220791.meteor.42:2,DF". Le nom du fichier doit correspondre à :

my ($time, $unique, $hostname, $info) =
   $filename =~ m!^(\d+)\.(.*)\.(\w+)(\:.*)?$!;
my ($semantics, $flags) =
   $info =~ m!([12])\,([DFPRST]*)$!;
my @flags = split //, $flags;

Lorsqu'une application ouvre le dossier, il peut y avoir des messages dans "new" qui sont de nouvelles arrivées, et des messages dans "cur". Ces derniers sont libellés comme "acceptés". Pour déplacer un message de "new" vers "cur", vous avez deux options avec le même effet :

$msg->accept;
$msg->label(accept => 1);

Voir accept(), label(), Mail::Box::Maildir::new(accept_new), et Mail::Box::Maildir::acceptMessages()

Les messages sont déplacés, et leur nom est immédiatement étendu avec des drapeaux. Un exemple :

new/897979431.meteor.42      peut devenir
cur/897979431.meteor.42:2,FS

Les caractères ajoutés ':2,' font référence au "second état de traitement", où le message a été inspecté. Et les caractères (qui devraient être en ordre alphabétique) signifient :

D      => brouillon
F      => signalé
R      => répondu (answerd)
S      => vu
T      => supprimé (marqué pour suppression)

Certains clients maildir supportent

P      => passé (renvoyé/transféré/renvoyé à quelqu'un d'autre)

Les drapeaux changeront immédiatement lorsque label() ou delete() sera utilisé, ce qui diffère des autres implémentations de messages : maildir est sans état, et ne devrait pas planter si les applications plantent.

NAME

Mail::Box::Maildir::Message - L'objet message dans un répertoire de maildir

INHERITANCE

Mail::Box::Maildir::Message is a subclass of Mail::Box::Message.

  Mail::Box::Message
    └── Mail::Box::Maildir::Message

SYNOPSIS

 use Mail::Box;

 my $box  = Mail::Box->new({ location => '~/Maildir/' });
 my $msg  = $box->message( '2003-11-07T10:30:00.123456.V001I001'); # Message unique
 my $view = $box->view;
 my $msg2 = $view->message( '2003-11-07T10:30:00.123456.V001I001'); # Message unique

 $msg->write; # écrire les changements

 my $new  = $box->new({ subject => 'Hello world' });
 $new->append; # ajouter le nouveau message à la boîte

DESCRIPTION

L'objet Mail::Box::Maildir::Message implémente l'interface des messages pour la structure de répertoire Mail::Box::Maildir. Les objets de ce type sont créés quand vous demandez un message à une boîte de type Mail::Box::Maildir.

La plupart des fonctionnalités sont héritées de Mail::Box::Message. Les différences sont dans la manière dont les messages sont stockés sur le disque.

Quand vous appelez write(), les changements sont écrits dans un nouveau fichier. Quand vous appelez append(), le message est écrit dans le répertoire new.

Les messages de type Maildir sont toujours stockés dans le répertoire cur ou new.

METHODS

coerce
Cast Mail::Box::Object into a $class object.
new
Créer un nouveau message.
read
Lire le message depuis le disque.
write
Écrire le message dans le répertoire cur.
append
Écrire le message dans le répertoire new.
delete
Supprimer le message.
move
Déplacer le message vers un autre répertoire.

DETAILS

Les méthodes spécifiques de Mail::Box::Maildir::Message sont implémentées pour gérer le système de fichiers Maildir.

Alternative inconnue pour la fonction forward (include). Les choix valides sont "NO", "INLINE", "ATTACH", et "ENCAPSULATE". Cast par forward()

Alternative inconnue pour l'option "include" de reply(). Les choix valides sont "NO", "INLINE", et "ATTACH". Cast par reply()
Error: Cannot write message to $filename: $!
Lorsqu'un message modifié ou nouveau est écrit sur le disque, il est d'abord écrit dans un fichier temporaire dans le répertoire du dossier. Pour une raison quelconque, il est impossible de créer ce fichier. Cast par create()
Error: Failed to move $new to $filename: $!
Lorsqu'un message modifié ou nouveau est écrit sur le disque, il est d'abord écrit dans un fichier temporaire dans le répertoire du dossier. Ensuite, le nouveau fichier est déplacé pour remplacer le fichier existant. Apparemment, cette dernière opération échoue. Cast par create()
Error: Method bounce requires To, Cc, or Bcc
La méthode bounce() du message transfère un message reçu à quelqu'un d'autre sans modification ; vous devez spécifier sa nouvelle destination. Si vous n'avez pas envie de spécifier de destination, vous cherchez probablement reply(). Lorsque vous souhaitez modifier le contenu, utilisez forward(). Cast par bounce()
Error: Method forwardAttach requires a preamble
Cast par forwardAttach()
Error: Method forwardEncapsulate requires a preamble
Cast par forwardEncapsulate()
Error: No address to create forwarded to.
Si un message transféré est créé, une adresse de destination doit être spécifiée. Cast par forward()
Error: No default mailer found to send message.
Le mécanisme send() du message n'a pas eu assez d'informations pour trouver automatiquement un agent de transfert de courrier pour envoyer ce message. Spécifiez un expéditeur explicitement en utilisant les options "via". Cast par send()
Error: No rebuild rule $name defined.
Cast par rebuild()
Error: Only build() Mail::Message's; they are not in a folder yet
Vous souhaitez peut-être construire un message à stocker dans une sorte de dossier, mais vous devez le faire en deux étapes. D'abord, créez un objet Mail::Message normal, puis ajoutez-le au dossier. Au cours de ce processus Mail::Box::addMessage(), le message sera coerce()-d dans le bon type de message, ajoutant des informations de stockage et autres. Cast par build()
Error: Package $package does not implement $method.
Erreur fatale : le package spécifique (ou l'une de ses superclasses) n'implémente pas cette méthode là où elle devrait. Ce message signifie que d'autres classes liées implémentent cette méthode, mais pas la classe en question. Vous devriez probablement enquêter sur cela et probablement informer l'auteur du package. Cast par notImplemented()
Error: Unable to read delayed body.

Mail::Box essaie d'être paresseux en ce qui concerne l'analyse des messages. Lorsqu'un répertoire organisé en dossier est ouvert, seuls les noms de fichiers des messages sont collectés. Dans un premier temps, les messages sont lus depuis leur fichier. Apparemment, un message est utilisé pour la première fois ici, mais il a disparu ou est illisible pour une autre raison.
