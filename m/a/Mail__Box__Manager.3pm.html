NOM

Mail::Box::Manager - gérer une série de boîtes aux lettres

HÉRITAGE

Mail::Box::Manager
  est un Mail::Reporter
Mail::Box::Manager est étendu par
  Mail::Box::Manage::User

SYNOPSIS

use Mail::Box::Manager;
my $mgr     = new Mail::Box::Manager;
# Créer des objets de boîte.
my $folder   = $mgr->open(folder => $ENV{MAIL});
my $message1 = $folder->message(0);
$mgr->copyMessage('Draft', $message);
my @messages = $folder->message(0,3);
$mgr->moveMessage('Outbox', @messages, create => 1 );
$mgr->close($folder);
# Créer des gestionnaires de fils (voir Mail::Box::Thread::Manager)
my $t       = $mgr->discoverThreads($inbox, $outbox);
my $threads = $mgr->discoverThreads(folder => $folder);
foreach my $thread ($threads->all)
{   $thread->print;
}
$mgr->registerType(mbox => 'Mail::Box::MyType');

DESCRIPTION

Le gestionnaire maintient une trace des boîtes aux lettres ouvertes et des objets de fil de messages. Il n'est pas obligatoire d'utiliser cet objet (vous pouvez créer directement un Mail::Box::Mbox si vous préférez), mais vous écrirez un code plus portable et plus sûr si vous le faites.

Gestion des boîtes aux lettres ouvertes

$obj->close($folder, %options)
Retire la boîte aux lettres spécifiée de l'index des boîtes aux lettres ouvertes. Indirectement, cela mettra à jour les fichiers sur le disque si nécessaire (cela dépend du flag Mail::Box::new(save_on_exit) pour chaque boîte aux lettres). Les options %options sont passées à Mail::Box::close() de la boîte aux lettres.

Les boîtes aux lettres peuvent également être fermées directement. Le gestionnaire sera informé de cet événement et prendra les mesures appropriées.

-Option       --Valeur par défaut
 close_by_self  <C<false>>
close_by_self => BOOLEAN
Utilisé en interne pour éviter toute confusion quant à la façon dont la fermeture a été déclenchée. Ne modifiez pas cela.

exemple :

my $inbox = $mgr->open('inbox');
$mgr->close($inbox);
$inbox->close;        # alternative
$obj->closeAllFolders(%options)
"closeAllFolders" appelle close() pour chaque boîte aux lettres gérée par cet objet. Il est appelé juste avant la fin du programme (avant le nettoyage global).
$obj->isOpenFolder($folder)
Retourne "true" si la boîte aux lettres $folder est actuellement ouverte.
$obj->open( [$foldername], %options )
Ouvre une boîte aux lettres dont le nom est spécifié comme premier paramètre ou avec l'option "folder". Le type de boîte aux lettres est détecté automatiquement, le "type" n'est pas spécifié.

Le "open" prend des options pour le gestionnaire, qui sont décrites ici, mais il peut également prendre des options supplémentaires pour le type de boîte aux lettres. Pour une description des options de boîte aux lettres, consultez les options du constructeur Mail::Box::new() pour chaque type de boîte aux lettres.

-Option      --Valeur par défaut

L'authentification du Mail::Box::Manager est exécutée automatiquement, mais peut être spécifiée. L'option "authenticate" est utilisée pour déterminer le type de boîte aux lettres à utiliser.
type => $foldertypename|$foldertype
Spécifie le type du dossier. Si vous ne spécifiez pas cette option lors de l'ouverture d'un dossier en lecture, le gestionnaire vérifie tous les types de dossiers enregistrés dans l'ordre pour pouvoir ouvrir le dossier. Si vous ouvrez un nouveau dossier en écriture, le défaut sera le type le plus récemment enregistré (si plusieurs types sont spécifiés, le premier de la liste est utilisé).

Actuellement, les types sont :

  • "mbox"
  • "mh"
  • "maildir"
  • "pop3"
  • "pop3s"
  • "imap4"
  • "imap4s"

Vous pouvez également utiliser des noms tels que "pop", "pops", "imap", et "imaps".

my $pop   = 'pop3://myself:secret@pop3.server.com:120/x';
my $send  = $manager->open($url);

  type => 'pop3', username => 'myself', password => 'secret'

Gérer les dossiers existants

$obj->delete($foldername, %options)
Supprime le dossier nommé. Les %options sont les mêmes que pour open().

La suppression d'un dossier peut prendre du temps. Selon le type de dossier, le dossier doit d'abord être lu. Pour certains types de dossiers, cela sera rapide.

-Option   --Default
 recursive  <folder's default>
recursive => BOOLEAN
Certains dossiers ne peuvent être supprimés que récursivement, d'autres offrent plus de flexibilité.

Déplacer les messages vers des dossiers

$obj->appendMessage( [$folder|$foldername], $messages, %options )
Ajoute un ou plusieurs messages à un dossier (donc, est défini comme appendMessages()). Vous pouvez spécifier un $foldername ou un dossier ouvert comme premier argument. Lorsque le nom est celui d'un dossier ouvert, il est traité comme si l'objet dossier était spécifié, et les fichiers du dossier ne sont pas directement accédés. Vous pouvez également spécifier le nom du dossier comme faisant partie de la liste d'options.

Si un message est ajouté à un dossier déjà ouvert, il n'est ajouté qu'en interne à la structure du programme. Les données ne sont écrites sur le disque que lorsqu'une écriture de ce dossier est effectuée. Lorsqu'un nom de dossier non ouvert est donné, le dossier est ouvert, les messages sont stockés sur le disque, puis le dossier est fermé.

Un message doit être une instance d'un Mail::Message. Le type de message réel ne doit pas nécessairement correspondre au type de dossier - le dossier tentera de résoudre les différences avec une perte minimale d'informations. Les messages coercés (comment ils ont réellement été écrits) sont retournés sous forme de liste.

Le %options est une liste de paires clé/valeur, qui sont ajoutées aux options par défaut pour le type de dossier détecté (les écrasant).

» exemple :

$mgr->appendMessage('=send', $message, folderdir => '/');
$mgr->appendMessage($received, $inbox->messages);
my @appended = $mgr->appendMessages($inbox->messages, folder => 'Drafts');
$_->label(seen => 1) for @appended;
$obj->copyMessage( [$folder|$foldername], @messages, %options )
Copie @messages d'un dossier à un autre. Si le dossier de destination est déjà ouvert, Mail::Box::copyTo() est utilisé. Sinon, Mail::Box::appendMessages() est appelé.

Vous devez spécifier un nom de dossier ou un objet dossier comme premier argument, ou dans la liste d'options. Les options sont les mêmes que celles qui peuvent être spécifiées lors de l'ouverture d'un dossier.

-Option--Default
 share   false
share => BOOLEAN
Tente de partager le stockage physique des messages. Les types de dossiers peuvent être différents, mais cela dépend du type de dossier vers lequel le message est copié. Est ignoré silencieusement si le partage n'est pas possible.

» exemple :

my $drafts = $mgr->open(folder => 'Drafts');
my $outbox = $mgr->open(folder => 'Outbox');
$mgr->copyMessage($outbox, $drafts->message(0));
my @messages = $drafts->message(1,2);
$mgr->copyMessage('=Trash', @messages,
   folderdir => '/tmp', create => 1);
$mgr->copyMessage($drafts->message(1), create => 1,
   folder => '=Drafts' folderdir => '/tmp');
$obj->moveMessage( [$folder|$foldername], @messages, %options )
Déplace @message d'un $folder à un autre.

ATTENTION : la suppression d'un message ne se produit que lorsque le dossier est fermé, de sorte que le message n'est marqué comme supprimé que dans le dossier source ouvert.

ATTENTION : les étiquettes des messages peuvent être perdues lors du déplacement d'un message d'un dossier à un autre. Une tentative est faite pour traduire les étiquettes, mais il existe des différences d'interprétation par les applications.

$mgr->moveMessage($received, $inbox->message(1))

est équivalent à

 $mgr->copyMessage($received, $inbox->message(1), share => 1);
 $inbox->message(1)->delete;
-Option--Default
 share   true
share => BOOLEAN

DETAILS

Dans de nombreux endroits de la documentation, vous pouvez lire qu'il est utile d'avoir un objet gestionnaire. Il en existe deux : Mail::Box::Manager, qui maintient un ensemble de dossiers ouverts, et une extension de celui-ci : Mail::Box::Manage::User.

Gestion des dossiers ouverts

Il est utile de commencer votre programme en créant un objet gestionnaire de dossiers, un Mail::Box::Manager. L'objet vous enlève quelques fardeaux :

  • détection automatique du type de dossier utilisé.

    • Cela signifie que votre application peut être totalement indépendante du type de dossier.

  • chargement automatique des modules requis

    • Il y a tellement de modules impliqués dans MailBox qu'il est utile d'avoir un chargement paresseux du code. Le gestionnaire sait quels modules appartiennent à quel type de dossier.

  • éviter les doubles ouvertures

    • Vos erreurs de programmation peuvent provoquer l'ouverture du même dossier deux fois. Le résultat pourrait être très destructeur. Par conséquent, le gestionnaire garde une trace de tous les dossiers ouverts et évite que le même dossier ne soit ouvert une seconde fois.

  • fermer les dossiers lors du nettoyage

    • Lorsque le programme se termine, le gestionnaire fermera proprement tous les dossiers encore ouverts. Ceci est nécessaire car la séquence d'autodestruction de Perl fonctionne dans un ordre imprévisible.

  • détection de fils de discussion de messages

    • MailBox peut découvrir des fils de discussion de messages qui s'étendent sur plusieurs dossiers. Tout ensemble de dossiers ouverts peut être regroupé dans un arbre de réponses aux réponses aux réponses. Lorsqu'un dossier est fermé, il est automatiquement retiré des fils de discussion, et un nouveau dossier peut être dynamiquement ajouté à la structure.

Le gestionnaire simplifie vraiment les choses et devrait donc être la base de tous les programmes. Cependant, il est possible d'écrire des programmes utiles sans lui.

Gestion d'un utilisateur

Un pas de plus est l'objet Mail::Box::Manage::User (depuis MailBox v2.057), qui non seulement garde une trace des dossiers ouverts, mais collecte également des informations sur les dossiers non ouverts.

La classe utilisateur est, comme son nom l'indique, ciblée sur la gestion d'un seul utilisateur. Là où Mail::Box::Manager ouvrira n'importe quel ensemble de fichiers de dossiers, probablement de plusieurs utilisateurs, la classe utilisateur veut un répertoire racine de dossiers.

À bien des égards, le gestionnaire d'utilisateurs simplifie la tâche pour les serveurs basés sur les utilisateurs et autres applications centrées sur l'utilisateur en définissant des valeurs par défaut intelligentes.

DIAGNOSTICS

Erreur : Le dossier $name est déjà ouvert.
Vous ne pouvez pas demander au gestionnaire un dossier qui est déjà ouvert. Dans certaines versions plus anciennes (avant MailBox 2.049), cela était autorisé, mais le comportement a changé, car de nombreux effets secondaires indésirables sont à prévoir. Par exemple, un Mail::Box::update() sur un descripteur de dossier influencerait le second, probablement de manière inattendue. Lancé par open()
Erreur : Le dossier $name n'est pas un Mail::Box ; impossible d'ajouter un message.
Le dossier auquel le message doit être ajouté est un objet qui n'est pas un type de dossier qui étend Mail::Box. Probablement, ce n'est pas un dossier du tout. Lancé par appendMessage()
Avertissement : Le dossier n'existe pas, échec de l'ouverture du dossier $type $name.
Le dossier n'existe pas et sa création n'est pas autorisée (voir open(create)) ou a échoué. Lorsque vous n'avez pas les droits d'accès suffisants au dossier (par exemple, mot de passe incorrect pour POP3), cet avertissement sera également produit.

Le gestionnaire a essayé d'ouvrir un dossier du type spécifié. Il peut être utile de spécifier explicitement le type de votre dossier avec l'option "type". Il y aura probablement un autre avertissement ou message d'erreur lié à ce rapport et fournissant plus de détails sur sa cause. Vous pouvez également consulter new(autodetect) et new(folder_types). Lancé par open()

Avertissement : Le type de dossier $type est inconnu, utilisation de la détection automatique.
Le type de dossier spécifié (voir open(type), potentiellement dérivé du nom du dossier lorsqu'il est spécifié comme URL) n'est pas connu du gestionnaire. Cela peut signifier que vous avez oublié de requérir l'extension Mail::Box qui implémente ce type de dossier, mais c'est probablement une faute de frappe. Habituellement, le gestionnaire est capable de déterminer lui-même quel type utiliser. Lancé par open()
Erreur : URL de dossier invalide '$url'.
Le nom du dossier a été spécifié comme URL, mais pas conformément à la syntaxe. Voir decodeFolderURL() pour une description de la syntaxe. Lancé par open()
Erreur : Aucun nom de dossier spécifié à ouvrir.
open() a besoin d'un nom de dossier comme premier argument (avant la liste des options), ou avec l'option "folder" dans la liste. Si aucun nom n'est trouvé, la variable d'environnement MAIL est vérifiée. Si même cela ne donne pas un dossier utilisable, alors cette erreur est produite. L'erreur peut être causée par une liste d'options de longueur impaire accidentelle. Lancé par open()
Erreur : Le paquet $package n'implémente pas $method.
Erreur fatale : le paquet spécifique (ou l'une de ses superclasses) n'implémente pas cette méthode alors qu'il le devrait. Ce message signifie que d'autres classes liées implémentent cette méthode, mais pas la classe en question. Vous devriez probablement enquêter et probablement informer l'auteur du paquet. Lancé par notImplemented()
Erreur : Utilisez appendMessage() pour ajouter des messages qui ne sont pas dans un dossier.
Vous n'avez pas besoin de copier ce message dans le dossier, car vous ne partagez pas le message entre les dossiers. Lancé par copyMessage()
Avertissement : Utilisez moveMessage() ou copyMessage() pour déplacer entre des dossiers ouverts.
Le message fait déjà partie d'un dossier, et maintenant il doit être ajouté à un autre dossier. Vous devez choisir entre copier ou déplacer, qui cloneront tous deux le message (pas le corps, car ils sont immuables). Lancé par appendMessage()
Avertissement : Ne créera jamais un dossier $name sans avoir les droits d'écriture.
Vous avez défini open(create), mais vous ne voulez lire que le dossier. La création n'est utile que pour les dossiers ayant des modes d'accès en écriture ou en ajout (voir Mail::Box::new(access)). Lancé par open()
