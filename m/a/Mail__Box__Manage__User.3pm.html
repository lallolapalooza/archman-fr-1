Mail::Box::Manage::User(3) Documentation des utilisateurs contributeurs Perl Mail::Box::Manage::User(3)

Nom

Mail::Box::Manage::User - gérer les dossiers d'un utilisateur

Hiérarchie

Mail::Box::Manage::User
  est une Mail::Box::Manager
  est une Mail::Reporter
Mail::Box::Manage::User est étendu par
  Mail::Server::IMAP4::User

Syntaxe

use Mail::Box::Manage::User;
use User::Identity;
my $id      = User::Identity->new(...);
my $user    = Mail::Box::Manage::User->new(
  identity  => $id,
  folderdir => "$ENV{HOME}/Mail",
  inbox     => $ENV{MAIL},
);
my $inbox   = $user->open($user->inbox);
my $top     = $user->topfolder;

Description

Là où Mail::Box::Manager prend en compte certains ensembles de dossiers ouverts, cette extension ajoute la connaissance de ceux qui sont liés à une personne. En même temps, elle essaie de mettre en cache des informations sur les fichiers de dossiers de cette personne.

Étendu la "Description" dans Mail::Box::Manager.

Gérer les dossiers

$obj->create($name, %options)
Crée un nouveau dossier avec le nom spécifié. Une structure administrative (Mail::Box::Identity) est retournée, mais le dossier n'est pas ouvert.

Dans le cas accidentel où le dossier existe déjà, un avertissement sera émis, et une liste vide/"undef" retournée.

Les %options sont passées à Mail::Box::create() de votre type de dossier par défaut, à l'exception des options destinées à cette méthode elle-même.

-Option       --Défaut
 create_real    true
 create_supers  false
 deleted        false
 id_options     []
create_real => BOOLEAN
Lorsque cette option est "false", le dossier physique ne sera pas créé, mais seule l'administration sera mise à jour.
create_supers => BOOLEAN
Lorsque vous créez un dossier où les niveaux hiérarchiques supérieurs sont manquants, ils seront également créés.
deleted => BOOLEAN
Le dossier commence comme supprimé.
id_options => ARRAY
Valeurs passées à l'instance Mail::Box::Identity. Cet objet est très exigeant quant aux valeurs d'initialisation qu'il accepte.
$obj->delete($name)
Supprime toutes les traces du dossier sur le système de fichiers. Les messages toujours dans le dossier seront supprimés. Cette méthode retourne une valeur "true" si le dossier a été supprimé ou non trouvé, donc ""false"" signifie un échec.

Il est également possible de supprimer un dossier en utilisant "$folder->delete", qui appellera cette méthode ici. Les OPTIONS, utilisées pour d'autres types de dossiers, seront ignorées ici : l'index de l'utilisateur contient les détails requis. Améliore la base, voir "Gérer les dossiers existants" dans Mail::Box::Manager

-Option   --Défini dans        --Défaut
 recursive  Mail::Box::Manager  <défaut du dossier>
recursive => BOOLEAN

» exemple : comment supprimer un dossier

print "pas de xyz (enfin)\n" if $user->delete('xyz');
$obj->folder($name)
Retourne la description du dossier, une Mail::Box::Identity.
$obj->folderCollection($name)
Retourne une paire : la collection de dossiers (Mail::Box::Collection) et le nom de base de $name.
$obj->rename($oldname, $newname, %options)
Renomme le dossier avec le nom $oldname en $newname. Les deux noms sont des chemins complets. 
-Option       --Défaut
 create_supers  false
create_supers => BOOLEAN
Lorsque vous renommez un dossier vers un emplacement où les niveaux hiérarchiques supérieurs sont manquants, ils seront définis, mais avec le drapeau supprimé défini.

DIAGNOSTICS

Erreur : Impossible de créer $name : niveaux supérieurs manquants
Sauf si vous avez défini create(create_supers), tous les dossiers de niveau supérieur doivent exister avant que celui-ci ne puisse être créé. Levée par create()
Erreur : Impossible de renommer $name en $new : niveaux supérieurs manquants
Sauf si vous avez défini create(create_supers), tous les dossiers de niveau supérieur doivent exister avant que celui-ci ne puisse être créé. Levée par rename()
Erreur : Le dossier $name est déjà ouvert.
Vous ne pouvez pas demander au gestionnaire un dossier déjà ouvert. Dans certaines anciennes versions (avant MailBox 2.049), cela était autorisé, mais le comportement a ensuite changé, car de nombreux effets secondaires indésirables sont à prévoir. Par exemple, un Mail::Box::update() sur un descripteur de dossier influencerait le second, probablement de manière inattendue. Levée par open()
Erreur : Le dossier $name n'est pas un Mail::Box ; impossible d'ajouter un message.
Le dossier où le message doit être ajouté est un objet qui n'est pas un type de dossier étendant Mail::Box. Probablement, ce n'est pas un dossier du tout. Levée par appendMessage()
Avertissement : Le dossier n'existe pas, ouverture du dossier de type $type $name a échoué.
Le dossier n'existe pas et sa création n'est pas autorisée (voir open(create)) ou n'a pas réussi. Lorsque vous n'avez pas suffisamment de droits d'accès au dossier (par exemple, mot de passe incorrect pour POP3), cet avertissement sera également produit.

Le gestionnaire a essayé d'ouvrir un dossier du type spécifié. Il peut être utile de spécifier explicitement le type de votre dossier avec l'option "type". Il y aura probablement un autre avertissement ou message d'erreur lié à ce rapport et fournissant plus de détails sur sa cause. Vous pouvez également consulter new(autodetect) et new(folder_types). Levée par open()

Avertissement : Le type de dossier $type est inconnu, utilisation de l'autodétection.
Le type de dossier spécifié (voir open(type), éventuellement dérivé du nom du dossier lorsqu'il est spécifié comme URL) n'est pas connu du gestionnaire. Cela peut signifier que vous avez oublié de charger l'extension Mail::Box qui implémente ce type de dossier, mais c'est probablement une faute de frappe. Habituellement, le gestionnaire est capable de déterminer lui-même le type à utiliser. Levée par open()
Erreur : URL de dossier illégale '$url'.
Le nom du dossier a été spécifié comme une URL, mais pas selon la syntaxe. Voir decodeFolderURL() pour une description de la syntaxe. Levée par open()
Erreur : Aucun nom de dossier spécifié pour l'ouverture.
open() nécessite un nom de dossier comme premier argument (avant la liste des options), ou avec l'option "folder" dans la liste. Si aucun nom n'est trouvé, la variable d'environnement MAIL est vérifiée. Si même cela ne donne pas un dossier utilisable, alors cette erreur est produite. L'erreur peut être causée par une liste d'options accidentellement de longueur impaire. Levée par open()
Erreur : Le paquetage $package n'implémente pas $method.
Erreur fatale : le paquetage spécifique (ou l'une de ses superclasses) n'implémente pas cette méthode alors qu'il devrait. Ce message signifie que d'autres classes liées implémentent cette méthode, mais la classe en question ne le fait pas. Vous devriez probablement enquêter et informer l'auteur du paquetage. Levée par notImplemented()
Erreur : Impossible de supprimer le dossier $dir
Levée par delete()
Erreur : Utilisez appendMessage() pour ajouter des messages qui ne sont pas dans un dossier.
Vous n'avez pas besoin de copier ce message dans le dossier, car vous ne partagez pas le message entre les dossiers. Levée par copyMessage()
Avertissement : Utilisez moveMessage() ou copyMessage() pour déplacer entre dossiers ouverts.
Le message fait déjà partie d'un dossier, et maintenant il doit être ajouté à un dossier différent. Vous devez choisir entre copier ou déplacer, qui cloneront tous deux le message (pas le corps, car ils sont immuables). Levée par appendMessage()
Avertissement : Ne créera jamais un dossier $name sans avoir les droits d'écriture.
Vous avez défini open(create), mais vous souhaitez uniquement lire le dossier. Créer n'est utile que pour les dossiers qui ont des modes d'accès en écriture ou en ajout (voir Mail::Box::new(access)). Levée par open()
