Paramètres d'entrée

  • sendbuf: Adresse de départ du tampon d'envoi.
  • sendcounts: Tableau d'entiers, où l'élément i spécifie le nombre d'éléments à envoyer au voisin i.
  • sdispls: Tableau d'entiers, où l'élément i spécifie le décalage (décalage depuis sendbuf, en unités de sendtype) pour envoyer des données au voisin i.
  • sendtype: Type de données des éléments du tampon d'envoi.
  • recvcounts: Tableau d'entiers, où l'élément j spécifie le nombre d'éléments à recevoir du voisin j.
  • rdispls: Tableau d'entiers, où l'élément j spécifie le décalage (décalage depuis recvbuf, en unités de recvtype) où les données du voisin j doivent être écrites.
  • recvtype: Type de données des éléments du tampon de réception.
  • comm: Communicateur sur lequel l'échange de données est effectué.
  • info: Informations (handle, persistant).

Paramètres de sortie

  • recvbuf: Adresse du tampon de réception.
  • request: Requête (handle, non bloquant).
  • ierror: Uniquement en Fortran : statut d'erreur.

Description

MPI_Neighbor_alltoallv est une opération collective généralisée dans laquelle tous les processus envoient des données à et reçoivent des données de tous les voisins. Elle ajoute de la flexibilité à MPI_Neighbor_alltoall en permettant à l'utilisateur de spécifier les données à envoyer et recevoir dans un style vectoriel (via un décalage et un compte d'éléments). L'opération de cette routine peut être pensée comme suit, où chaque processus effectue 2n (n étant le nombre de voisins dans la topologie du communicateur comm) communications point à point indépendantes. La disposition des voisins et du tampon est déterminée par la topologie du communicateur comm.

MPI_Cart_get(comm, maxdims, dims, periods, coords);
for (dim = 0, i = 0 ; dim < dims ; ++dim) {
    MPI_Cart_shift(comm, dim, 1, &r0, &r1);
    MPI_Isend(sendbuf + sdispls[i]  * extent(sendtype),
              sendcount, sendtype, r0, ..., comm, ...);
    MPI_Irecv(recvbuf + rdispls[i] * extent(recvtype),
              recvcount, recvtype, r0, ..., comm, ...);
    ++i;
    MPI_Isend(sendbuf + sdispls[i] * extent(sendtype),
              sendcount, sendtype, r1, ..., comm, &req[i]);
    MPI_Irecv(recvbuf + rdispls[i] * extent(recvtype),
              recvcount, recvtype, r1, ..., comm, ...);
    ++i;
}

Le processus j envoie le bloc k du tampon d'envoi local du processus j au voisin k, ce qui place les données dans le bloc j du tampon de réception local du processus j.

Lorsque deux processus échangent des données, chacun peut passer des arguments de compte d'éléments et de type de données différents, à condition que l'expéditeur spécifie la même quantité de données à envoyer (en octets) que ce que le récepteur s'attend à recevoir.

Note : Le processus i peut envoyer un volume de données différent au processus j qu'il ne reçoit de j. De plus, un processus peut envoyer des volumes de données différents à des processus différents dans le communicateur.

Ordre des voisins

Pour une topologie distribuée créée avec MPI_Dist_graph_create, la séquence des voisins dans les tampons d'envoi et de réception sur chaque processus est définie comme la séquence renvoyée par MPI_Dist_graph_neighbors pour les destinations et les origines respectivement. Pour une topologie générale créée avec MPI_Graph_create, la séquence des voisins dans les tampons d'envoi et de réception est définie comme la séquence des voisins renvoyée par MPI_Graph_neighbors. Note : Les topologies générales devraient généralement être remplacées par les topologies distribuées.

Pour une topologie cartésienne créée avec MPI_Cart_create, la séquence des voisins dans les tampons d'envoi et de réception sur chaque processus est définie selon l'ordre des dimensions, d'abord les voisins dans la direction négative puis dans la direction positive avec un décalage de 1. Le nombre de sources et de destinations dans les routines de communication est de 2*ndims avec ndims défini dans MPI_Cart_create. Si un voisin n'existe pas, c'est-à-dire au bord d'une topologie cartésienne dans le cas d'un réseau virtuel non périodique (c'est-à-dire, periods[...]==false), alors ce voisin est défini comme MPI_PROC_NULL.

Si un voisin dans l'une des fonctions est MPI_PROC_NULL, alors la communication collective se comporte comme une communication point à point avec MPI_PROC_NULL dans cette direction. Autrement dit, le tampon fait toujours partie de la séquence des voisins mais n'est ni communiqué ni mis à jour.

NOTES

L'option MPI_IN_PLACE pour sendbuf n'est pas significative pour cette opération.

La spécification des compteurs et des déplacements ne doit pas entraîner l'écriture d'un emplacement plus d'une fois.

Tous les arguments dans tous les processus sont significatifs. L'argument comm, en particulier, doit décrire le même communicateur sur tous les processus.

Les décalages de sdispls et rdispls sont mesurés en unités de sendtype et recvtype, respectivement. Comparez cela avec MPI_Neighbor_alltoallw, où ces décalages sont mesurés en octets.

ERREURS

Au-delà des valeurs d'erreur, les routines C retournent une valeur d'erreur et les routines Fortran le font dans le dernier argument.

Avant que la valeur d'erreur ne soit retournée, le gestionnaire d'erreurs associé à l'objet de communication (par exemple, communicator, window, file) est appelé. S'il n'y a pas d'objet de communication associé à l'appel MPI, l'appel est considéré comme associé à MPI_COMM_SELF et appelle le gestionnaire d'erreurs associé. Lorsque MPI_COMM_SELF n'est pas initialisé (c'est-à-dire avant MPI_Init/MPI_Init_thread, après MPI_Finalize ou lorsque le modèle de session est utilisé exclusivement), l'erreur déclenche le gestionnaire d'erreurs initial. Le gestionnaire d'erreurs initial peut être modifié en appelant MPI_Comm_set_errhandler sur MPI_COMM_SELF lorsque le modèle du monde est utilisé, ou via l'argument mpi_initial_errhandler de mpiexec ou à la clé info de MPI_Comm_spawn/MPI_Comm_spawn_multiple. Si aucun autre gestionnaire d'erreurs approprié n'est défini, le gestionnaire d'erreurs MPI_ERRORS_RETURN est appelé pour les fonctions d'E/S MPI et le gestionnaire d'erreurs MPI_ERRORS_ABORT pour les autres fonctions MPI.

Open MPI inclut trois gestionnaires d'erreurs prédéfinis qui peuvent être utilisés :

  • MPI_ERRORS_ARE_FATAL Se comporte comme si MPI_Abort avait été appelé sur le communicateur.
  • MPI_ERRORS_ABORT Un gestionnaire d'erreurs qui peut être appelé sur un communicateur, une fenêtre, un fichier ou une session. Lorsqu'il est appelé sur un communicateur, il se comporte comme si MPI_Abort avait été appelé sur ce communicateur. S'il est appelé sur une fenêtre ou un fichier, il se comporte comme si MPI_Abort avait été appelé sur un communicateur contenant le groupe de processus correspondant à la fenêtre ou au fichier. S'il est appelé sur une session, seul le processus local est arrêté.
  • MPI_ERRORS_RETURN Retourne un code d'erreur au programme.

Les applications MPI peuvent également implémenter leurs propres gestionnaires d'erreurs en appelant :

  • MPI_Comm_create_errhandler suivi de MPI_Comm_set_errhandler
  • MPI_File_create_errhandler suivi de MPI_File_set_errhandler
  • MPI_Session_create_errhandler suivi de MPI_Session_set_errhandler ou à MPI_Session_init
  • MPI_Win_create_errhandler suivi de MPI_Win_set_errhandler

Note : MPI ne garantit pas qu'un programme MPI puisse continuer après une erreur.

Voir la page de manuel MPI pour une liste complète des codes d'erreur MPI.

Voir la section sur la gestion des erreurs de la norme MPI-3.1 pour plus d'informations.
