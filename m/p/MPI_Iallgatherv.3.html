MPI_IALLGATHERV(3) Open MPI MPI_IALLGATHERV(3)

MPI_Allgatherv, MPI_Iallgatherv, MPI_Allgatherv_init - Rassemble les données de tous les processus et les livre à tous. Chaque processus peut contribuer une quantité de données différente.

PARAMÈTRES D'ENTRÉE

  • sendbuf: Adresse du tampon d'envoi (choix).
  • sendcount: Nombre d'éléments dans le tampon d'envoi (entier).
  • sendtype: Type de données des éléments du tampon d'envoi (descripteur).
  • recvcount: Tableau d'entiers (de taille égale au nombre de processus dans le groupe) contenant le nombre d'éléments reçus de chaque processus.
  • displs: Tableau d'entiers (de taille égale au nombre de processus dans le groupe). L'entrée i spécifie le déplacement (par rapport à recvbuf) où placer les données entrantes provenant du processus i.
  • recvtype: Type de données des éléments du tampon de réception (descripteur).
  • comm: Communicateur (descripteur).
  • info: Informations (descripteur, persistant uniquement).

PARAMÈTRES DE SORTIE

  • recvbuf: Adresse du tampon de réception (choix).
  • request: Requête (descripteur, non bloquant uniquement).
  • ierror: Fortran uniquement : Statut d'erreur (entier).

DESCRIPTION

MPI_Allgatherv est similaire à MPI_Allgather en ce sens que tous les processus rassemblent les données de tous les autres processus, à la différence près que chaque processus peut envoyer une quantité différente de données. Le bloc de données envoyé par le j-ème processus est reçu par chaque processus et placé dans le j-ème bloc du tampon recvbuf.

La signature de type associée à sendcount, sendtype, au processus j doit être égale à la signature de type associée à recvcounts[j], recvtype à tout autre processus.

Le résultat est comme si tous les processus avaient exécuté des appels à

MPI_Allgatherv(sendbuf, sendcount, sendtype, recvbuf, recvcount,
              displs,recvtype,root,comm);
// pour root = 0 , ..., n-1.

Les règles d'utilisation correcte de MPI_Allgatherv sont facilement dérivées des règles correspondantes pour MPI_Gatherv.

UTILISATION DE L'OPTION IN-PLACE

Lorsque le communicateur est un intracommunicateur, vous pouvez effectuer une opération d'agrégation complète en place (le tampon de sortie est utilisé comme tampon d'entrée). Utilisez la variable MPI_IN_PLACE comme valeur de sendbuf. Dans ce cas, sendcount et sendtype sont ignorés. Les données d'entrée de chaque processus sont supposées se trouver dans la zone où ce processus recevrait sa propre contribution au tampon de réception. Plus précisément, le résultat d'un appel à MPI_Allgatherv utilisant l'option en place est identique au cas où tous les processus ont exécuté n appels à

MPI_Allgatherv ( MPI_IN_PLACE, 0, MPI_DATATYPE_NULL, recvbuf,
                 recvcounts, displs, recvtype, root, comm );
// pour root =0, ... , n-1.

Notez que MPI_IN_PLACE est un type de valeur spécial ; il a les mêmes restrictions d'utilisation que MPI_BOTTOM.

Étant donné que l'option en place convertit le tampon de réception en un tampon d'envoi et de réception, une liaison Fortran incluant INTENT doit les marquer comme INOUT, et non OUT.

QUAND LE COMMUNICATEUR EST UN INTER-COMMUNICATEUR

Lorsque le communicateur est un inter-communicateur, l'opération de rassemblement se déroule en deux phases. Les données sont rassemblées à partir de tous les membres du premier groupe, concaténées et reçues par tous les membres du second groupe. Ensuite, les données sont rassemblées à partir de tous les membres du second groupe, concaténées et reçues par tous les membres du premier. Les arguments du tampon d'envoi dans un groupe doivent être cohérents avec les arguments du tampon de réception dans l'autre groupe, et vice versa. L'opération doit présenter un comportement symétrique et bidirectionnel.

ERREURS

Presque toutes les routines MPI renvoient une valeur d'erreur ; les routines C comme résultat de retour de la fonction et les routines Fortran dans le dernier argument.

Avant que la valeur d'erreur ne soit renvoyée, le gestionnaire d'erreurs MPI actuel associé à l'objet de communication (par exemple, communicateur, fenêtre, fichier) est appelé. Si aucun objet de communication n'est associé à l'appel MPI, alors l'appel est considéré comme attaché à MPI_COMM_SELF et appellera le gestionnaire d'erreurs MPI associé. Lorsque MPI_COMM_SELF n'est pas initialisé (c'est-à-dire avant MPI_Init/MPI_Init_thread, après MPI_Finalize, ou lors de l'utilisation exclusive du modèle de sessions), l'erreur déclenche le gestionnaire d'erreurs initial. Le gestionnaire d'erreurs initial peut être modifié en appelant MPI_Comm_set_errhandler sur MPI_COMM_SELF lors de l'utilisation du modèle World, ou l'argument CLI mpi_initial_errhandler de mpiexec ou la clé d'information de MPI_Comm_spawn/MPI_Comm_spawn_multiple. Si aucun autre gestionnaire d'erreurs approprié n'a été défini, alors le gestionnaire d'erreurs MPI_ERRORS_RETURN est appelé pour les fonctions d'E/S MPI et le gestionnaire d'erreurs MPI_ERRORS_ABORT est appelé pour toutes les autres fonctions MPI.

SYNTAX

Open MPI inclut trois gestionnaires d'erreurs prédéfinis qui peuvent être utilisés :

  • MPI_ERRORS_ARE_FATAL Provoque l'abandon de tous les processus MPI connectés par le programme.
  • MPI_ERRORS_ABORT Un gestionnaire d'erreurs qui peut être invoqué sur un communicateur, une fenêtre, un fichier ou une session. Lorsqu'il est invoqué sur un communicateur, il agit comme si MPI_Abort avait été appelé sur ce communicateur. S'il est invoqué sur une fenêtre ou un fichier, il agit comme si MPI_Abort avait été appelé sur un communicateur contenant le groupe de processus correspondant dans la fenêtre ou le fichier. S'il est invoqué sur une session, il abandonne uniquement le processus local.
  • MPI_ERRORS_RETURN Renvoie un code d'erreur à l'application.

Les applications MPI peuvent également implémenter leurs propres gestionnaires d'erreurs en appelant :

  • MPI_Comm_create_errhandler puis MPI_Comm_set_errhandler
  • MPI_File_create_errhandler puis MPI_File_set_errhandler
  • MPI_Session_create_errhandler puis MPI_Session_set_errhandler ou dans MPI_Session_init
  • MPI_Win_create_errhandler puis MPI_Win_set_errhandler

Note : Open MPI ne garantit pas qu'un programme MPI puisse continuer après une erreur.

Voir la page man MPI pour une liste complète des codes d'erreur MPI.

Voir la section Gestion des erreurs de la spécification MPI-3.1 pour plus d'informations.
