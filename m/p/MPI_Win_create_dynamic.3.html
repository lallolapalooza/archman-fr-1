MPI_WIN_CREATE_DYNAMIC(3) Open MPI MPI_WIN_CREATE_DYNAMIC(3)

MPI_Win_create_dynamic — Appel MPI à une seule partie qui retourne un objet fenêtre pour les opérations RMA.

SYNTAXE

Syntaxe C

#include <mpi.h>
MPI_Win_create_dynamic(MPI_Info info, MPI_Comm comm, MPI_Win *win)

Syntaxe Fortran

USE MPI
! ou l'ancienne forme: INCLUDE 'mpif.h'
MPI_WIN_CREATE_DYNAMIC(INFO, COMM, WIN, IERROR)
     INTEGER INFO, COMM, WIN, IERROR

Syntaxe Fortran 2008

USE mpi_f08
MPI_Win_create_dynamic(info, comm, win, ierror)
     TYPE(MPI_Info), INTENT(IN) :: info
     TYPE(MPI_Comm), INTENT(IN) :: comm
     TYPE(MPI_Win), INTENT(OUT) :: win
     INTEGER, OPTIONAL, INTENT(OUT) :: ierror

PARAMÈTRES D'ENTRÉE

  • info: Argument d'information (handle).
  • comm: Communicateur (handle).

PARAMÈTRES DE SORTIE

  • win: Objet fenêtre retourné par l'appel (handle).
  • ierror: Fortran uniquement : Statut d'erreur (entier).

DESCRIPTION

MPI_Win_create_dynamic est un appel collectif MPI à une seule partie exécuté par tous les processus du groupe de comm. Il retourne un objet fenêtre sans mémoire attachée qui peut être utilisé par ces processus pour effectuer des opérations RMA.

Une fenêtre créée avec MPI_Win_create_dynamic nécessite l'argument target_disp pour toutes les fonctions de communication RMA soit l'adresse réelle à la cible.

Les clés d'information suivantes sont prises en charge :

no_locks
Si défini sur true, alors l'implémentation peut supposer que la fenêtre locale n'est jamais verrouillée (par un appel à MPI_Win_lock ou MPI_Win_lock_all). Définir cette valeur si seule la synchronisation active peut permettre à l'implémentation d'activer certaines optimisations.
accumulate_ordering
Par défaut, les opérations d'accumulation d'un initiateur à une cible sur le même emplacement mémoire de fenêtre sont strictement ordonnancée. Si la clé d'information accumulate_ordering est définie sur none, aucun ordonnancement des opérations d'accumulation n'est garanti. La clé peut également être une liste d'ordonnancements requis séparés par des virgules, constituée de rar, war, raw et waw pour lecture-après-lecture, écriture-après-lecture, lecture-après-écriture et écriture-après-écriture, respectivement. Des contraintes d'ordonnancement plus souples sont susceptibles d'améliorer les performances.
accumulate_ops
Si défini sur same_op, l'implémentation supposera que tous les appels d'accumulation simultanés à la même adresse cible utiliseront la même opération. S'il est défini sur same_op_no_op, l'implémentation supposera que tous les appels d'accumulation simultanés à la même adresse cible utiliseront la même opération ou MPI_NO_OP. La valeur par défaut est same_op_no_op.

NOTES

Étant donné que l'attachement dynamique de mémoire à une fenêtre est une opération locale, il faut communiquer l'adresse réelle à la cible en utilisant MPI_Get_address et une communication.

La mémoire dynamique n'a pas de disp_unit associé et nécessite des calculs de décalage corrects avec une gestion appropriée des types.

ERREURS

Presque toutes les routines MPI retournent une valeur d'erreur ; les routines C comme résultat de la fonction et les routines Fortran dans le dernier argument.

Avant que la valeur d'erreur ne soit retournée, le gestionnaire d'erreurs MPI actuel associé à l'objet de communication (par exemple, communicateur, fenêtre, fichier) est appelé. Si aucun objet de communication n'est associé à l'appel MPI, alors l'appel est considéré comme attaché à MPI_COMM_SELF et appellera le gestionnaire d'erreurs MPI associé. Lorsque MPI_COMM_SELF n'est pas initialisé (c'est-à-dire, avant MPI_Init/MPI_Init_thread, après MPI_Finalize, ou lors de l'utilisation exclusive du modèle de sessions), l'erreur déclenche le gestionnaire d'erreurs initial. Le gestionnaire d'erreurs initial peut être modifié en appelant MPI_Comm_set_errhandler sur MPI_COMM_SELF lors de l'utilisation du modèle World, ou l'argument CLI mpi_initial_errhandler pour mpiexec ou la clé d'information pour MPI_Comm_spawn/MPI_Comm_spawn_multiple. Si aucun autre gestionnaire d'erreurs approprié n'a été défini, alors le gestionnaire d'erreurs MPI_ERRORS_RETURN est appelé pour les fonctions d'E/S MPI et le gestionnaire d'erreurs MPI_ERRORS_ABORT est appelé pour toutes les autres fonctions MPI.

Open MPI inclut trois gestionnaires d'erreurs prédéfinis qui peuvent être utilisés :

  • MPI_ERRORS_ARE_FATAL Provoque l'arrêt du programme de tous les processus MPI connectés.
  • MPI_ERRORS_ABORT Un gestionnaire d'erreurs qui peut être invoqué sur un communicateur, une fenêtre, un fichier ou une session. Lorsqu'il est appelé sur un communicateur, il agit comme si MPI_Abort avait été appelé sur ce communicateur. S'il est appelé sur une fenêtre ou un fichier, il agit comme si MPI_Abort avait été appelé sur un communicateur contenant le groupe de processus dans la fenêtre ou le fichier correspondant. S'il est appelé sur une session, il n'interrompt que le processus local.
  • MPI_ERRORS_RETURN Retourne un code d'erreur à l'application.

Les applications MPI peuvent également implémenter leurs propres gestionnaires d'erreurs en appelant :

  • MPI_Comm_create_errhandler puis MPI_Comm_set_errhandler
  • MPI_File_create_errhandler puis MPI_File_set_errhandler
  • MPI_Session_create_errhandler puis MPI_Session_set_errhandler ou à MPI_Session_init
  • MPI_Win_create_errhandler puis MPI_Win_set_errhandler

Notez que MPI ne garantit pas qu'un programme MPI puisse continuer au-delà d'une erreur.

Voir la page man MPI pour une liste complète des codes d'erreur MPI.

Voir la section Gestion des erreurs de la norme MPI-3.1 pour plus d'informations.
