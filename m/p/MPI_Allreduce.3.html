MPI_ALLREDUCE(3) Open MPI MPI_ALLREDUCE(3)

MPI_Allreduce, MPI_Iallreduce, MPI_Allreduce_init - Combine les valeurs de tous les processus et distribue le résultat à tous les processus.

SYNTAXE

Syntaxe C

                  MPI_Datatype datatype, MPI_Op op, MPI_Comm comm)

                   MPI_Datatype datatype, MPI_Op op, MPI_Comm comm,
                   MPI_Request *request)

                       MPI_Datatype datatype, MPI_Op op, MPI_Comm comm,

PARAMÈTRES D'ENTRÉE

  • sendbuf: Adresse de départ du tampon d'envoi (choix).
  • count: Nombre d'éléments dans le tampon d'envoi (entier).
  • datatype: Type de données des éléments du tampon d'envoi (descripteur).
  • op: Opération (descripteur).
  • comm: Communicateur (descripteur).
  • info: Informations (descripteur, persistant seulement).

PARAMÈTRES DE SORTIE

  • recvbuf: Adresse de départ du tampon de réception (choix).
  • request: Requête (descripteur, non-bloquant seulement).
  • ierror: Fortran seulement: Statut d'erreur (entier).

DESCRIPTION

Identique à MPI_Reduce, sauf que le résultat apparaît dans le tampon de réception de tous les membres du groupe.

Exemple 1: Une routine qui calcule le produit d'un vecteur et d'un tableau distribués sur un groupe de processus et renvoie la réponse à tous les nœuds (comparer avec l'Exemple 2, avec MPI_Reduce, ci-dessous).

SUBROUTINE PAR_BLAS2(m, n, a, b, c, comm)
REAL a(m), b(m,n)    ! tranche locale du tableau
REAL c(n)            ! résultat
REAL sum(n)
INTEGER n, comm, i, j, ierr
! somme locale
DO j= 1, n
  sum(j) = 0.0
  DO i = 1, m
    sum(j) = sum(j) + a(i)*b(i,j)
  END DO
END DO
! somme globale
CALL MPI_ALLREDUCE(sum, c, n, MPI_REAL, MPI_SUM, comm, ierr)
! retourne le résultat à tous les nœuds
RETURN

Exemple 2: Une routine qui calcule le produit d'un vecteur et d'un tableau distribués sur un groupe de processus et renvoie la réponse au nœud zéro.

SUBROUTINE PAR_BLAS2(m, n, a, b, c, comm)
REAL a(m), b(m,n)    ! tranche locale du tableau
REAL c(n)            ! résultat
REAL sum(n)
INTEGER n, comm, i, j, ierr
! somme locale
DO j= 1, n
  sum(j) = 0.0
  DO i = 1, m
    sum(j) = sum(j) + a(i)*b(i,j)
  END DO
END DO
! somme globale
CALL MPI_REDUCE(sum, c, n, MPI_REAL, MPI_SUM, 0, comm, ierr)
! retourne le résultat au nœud zéro (et des déchets sur les autres nœuds)
RETURN

UTILISATION DE L'OPTION EN PLACE

Lorsque le communicateur est un intra-communicateur, vous pouvez effectuer une opération all-reduce en place (le tampon de sortie est utilisé comme tampon d'entrée). Utilisez la variable MPI_IN_PLACE comme valeur de sendbuf sur tous les processus.

Notez que MPI_IN_PLACE est un type de valeur spécial ; il a les mêmes restrictions d'utilisation que MPI_BOTTOM.

Étant donné que l'option en place convertit le tampon de réception en un tampon d'envoi et de réception, une liaison Fortran qui inclut INTENT doit les marquer comme INOUT, et non OUT.

QUAND LE COMMUNICATEUR EST UN INTER-COMMUNICATEUR

Lorsque le communicateur est un inter-communicateur, l'opération de réduction se déroule en deux phases. Les données sont réduites à partir de tous les membres du premier groupe et reçues par tous les membres du second groupe. Ensuite, les données sont réduites à partir de tous les membres du second groupe et reçues par tous les membres du premier. L'opération présente un comportement symétrique, full-duplex.

Lorsque le communicateur est un intra-communicateur, ces groupes sont identiques et l'opération se déroule en une seule phase.

NOTES SUR LES OPÉRATIONS COLLECTIVES

Les fonctions de réduction ( MPI_Op ) ne retournent pas de valeur d'erreur. Par conséquent, si les fonctions détectent une erreur, tout ce qu'elles peuvent faire est soit d'appeler MPI_Abort, soit d'ignorer silencieusement le problème. Ainsi, si vous changez le gestionnaire d'erreurs de MPI_ERRORS_ARE_FATAL à autre chose, par exemple, MPI_ERRORS_RETURN, aucune erreur ne sera peut-être indiquée.

ERREURS

Presque toutes les routines MPI retournent une valeur d'erreur ; les routines C comme résultat de retour de la fonction et les routines Fortran dans le dernier argument.

Avant que la valeur d'erreur ne soit retournée, le gestionnaire d'erreurs MPI actuel associé à l'objet de communication (par exemple, communicateur, fenêtre, fichier) est appelé. Si aucun objet de communication n'est associé à l'appel MPI, alors l'appel est considéré comme attaché à MPI_COMM_SELF et appellera le gestionnaire d'erreurs MPI associé. Lorsque MPI_COMM_SELF n'est pas initialisé (c'est-à-dire avant MPI_Init/MPI_Init_thread, après MPI_Finalize, ou lors de l'utilisation exclusive du modèle de sessions) l'erreur déclenche le gestionnaire d'erreurs initial. Le gestionnaire d'erreurs initial peut être modifié en appelant MPI_Comm_set_errhandler sur MPI_COMM_SELF lors de l'utilisation du modèle World, ou l'argument CLI mpi_initial_errhandler à mpiexec ou la clé d'information à MPI_Comm_spawn/MPI_Comm_spawn_multiple. Si aucun autre gestionnaire d'erreurs approprié n'a été défini, alors le gestionnaire d'erreurs MPI_ERRORS_RETURN est appelé pour les fonctions E/S MPI et le gestionnaire d'erreurs MPI_ERRORS_ABORT est appelé pour toutes les autres fonctions MPI.

Open MPI inclut trois gestionnaires d'erreurs prédéfinis qui peuvent être utilisés:

  • MPI_ERRORS_ARE_FATAL Provoque l'abandon du programme par tous les processus MPI connectés.
  • MPI_ERRORS_ABORT Un gestionnaire d'erreurs qui peut être invoqué sur un communicateur, une fenêtre, un fichier ou une session. Lorsqu'il est appelé sur un communicateur, il agit comme si MPI_Abort était appelé sur ce communicateur. S'il est appelé sur une fenêtre ou un fichier, il agit comme si MPI_Abort était appelé sur un communi
