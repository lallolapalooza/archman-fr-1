MPI_Accumulate, MPI_Raccumulate - Combine le contenu du tampon d'origine avec celui d'un tampon cible.

PARAMÈTRES D'ENTRÉE

  • origin_addr: Adresse initiale du tampon (choix).
  • origin_count: Nombre d'entrées dans le tampon (entier non négatif).
  • origin_datatype: Type de données de chaque entrée du tampon (handle).
  • target_rank: Rang de la cible (entier non négatif).
  • target_disp: Déplacement depuis le début de la fenêtre jusqu'au début du tampon cible (entier non négatif).
  • target_count: Nombre d'entrées dans le tampon cible (entier non négatif).
  • target_datatype: Type de données de chaque entrée dans le tampon cible (handle).
  • op: Opération de réduction (handle).
  • win: Objet fenêtre (handle).

PARAMÈTRE DE SORTIE

  • MPI_Raccumulate: Requête RMA
  • ierror: Fortran seulement : Statut d'erreur (entier).

DESCRIPTION

MPI_Accumulate est une fonction utilisée pour la communication MPI unidirectionnelle qui ajoute le contenu du tampon d'origine (tel que défini par origin_addr, origin_count et origin_datatype) au tampon spécifié par les arguments target_count et target_datatype, à l'offset target_disp, dans la fenêtre cible spécifiée par target_rank et win, en utilisant l'opération op. La fenêtre cible ne peut être accédée que par les processus du même nœud. Ceci est similaire à MPI_Put, sauf que les données sont combinées dans la zone cible au lieu de l'écraser.

Toutes les opérations prédéfinies pour MPI_Reduce peuvent être utilisées. Les fonctions définies par l'utilisateur ne peuvent pas être utilisées. Par exemple, si op est MPI_SUM, chaque élément du tampon d'origine est ajouté à l'élément correspondant dans la cible, remplaçant la valeur précédente dans la cible.

Chaque argument de type de données doit être un type de données prédéfini ou un type de données dérivé, où tous les composants de base sont du même type de données prédéfini. Les deux arguments de type de données doivent être construits à partir du même type de données prédéfini. L'opération op s'applique aux éléments de ce type prédéfini. L'argument target_datatype ne doit pas spécifier d'entrées qui se chevauchent, et le tampon cible doit tenir dans la fenêtre cible.

Une nouvelle opération prédéfinie, MPI_REPLACE, est définie. Elle correspond à la fonction associative f(a, b) =b ; c'est-à-dire, la valeur actuelle dans la mémoire cible est remplacée par la valeur fournie par l'origine.

MPI_Raccumulate est similaire à MPI_Accumulate, sauf qu'elle alloue un objet de requête de communication et l'associe au handle de requête (l'argument request) qui peut être utilisé pour attendre ou tester l'achèvement. L'achèvement d'une opération MPI_Raccumulate indique que le tampon origin_addr est libre d'être mis à jour. Cela n'indique pas que l'opération est terminée dans la fenêtre cible.

NOTES

MPI_Put est un cas particulier de MPI_Accumulate, avec l'opération MPI_REPLACE. Notez cependant que MPI_Put et MPI_Accumulate ont des contraintes différentes sur les mises à jour simultanées.

Il incombe à l'utilisateur de garantir que, lors de l'utilisation des fonctions d'accumulation, l'argument de déplacement cible est tel que les accès à la fenêtre sont correctement alignés selon les arguments de type de données dans l'appel à la fonction MPI_Accumulate.

ERREURS

Presque toutes les routines MPI renvoient une valeur d'erreur ; les routines C comme résultat de retour de la fonction et les routines Fortran dans le dernier argument.

Avant que la valeur d'erreur ne soit renvoyée, le gestionnaire d'erreurs MPI actuel associé à l'objet de communication (par exemple, communicateur, fenêtre, fichier) est appelé. Si aucun objet de communication n'est associé à l'appel MPI, alors l'appel est considéré comme attaché à MPI_COMM_SELF et appellera le gestionnaire d'erreurs MPI associé. Lorsque MPI_COMM_SELF n'est pas initialisé (c'est-à-dire, avant MPI_Init/MPI_Init_thread, après MPI_Finalize, ou lors de l'utilisation exclusive du modèle de sessions) l'erreur déclenche le gestionnaire d'erreurs initial. Le gestionnaire d'erreurs initial peut être modifié en appelant MPI_Comm_set_errhandler sur MPI_COMM_SELF lors de l'utilisation du modèle World, ou l'argument CLI mpi_initial_errhandler à mpiexec ou la clé d'info à MPI_Comm_spawn/MPI_Comm_spawn_multiple. Si aucun autre gestionnaire d'erreurs approprié n'a été défini, alors le gestionnaire d'erreurs MPI_ERRORS_RETURN est appelé pour les fonctions d'E/S MPI et le gestionnaire d'erreurs MPI_ERRORS_ABORT est appelé pour toutes les autres fonctions MPI.

Open MPI inclut trois gestionnaires d'erreurs prédéfinis qui peuvent être utilisés :

  • MPI_ERRORS_ARE_FATAL Provoque l'arrêt du programme par tous les processus MPI connectés.
  • MPI_ERRORS_ABORT Un gestionnaire d'erreurs qui peut être appelé sur un communicateur, une fenêtre, un fichier ou une session. Lorsqu'il est appelé sur un communicateur, il agit comme si MPI_Abort était appelé sur ce communicateur. S'il est appelé sur une fenêtre ou un fichier, il agit comme si MPI_Abort était appelé sur un communicateur contenant le groupe de processus dans la fenêtre ou le fichier correspondant. S'il est appelé sur une session, il n'interrompt que le processus local.
  • MPI_ERRORS_RETURN Renvoie un code d'erreur à l'application.

Les applications MPI peuvent également implémenter leurs propres gestionnaires d'erreurs en appelant :

  • MPI_Comm_create_errhandler puis MPI_Comm_set_errhandler
  • MPI_File_create_errhandler puis MPI_File_set_errhandler
  • MPI_Session_create_errhandler puis MPI_Session_set_errhandler ou à MPI_Session_init
