MPI_Neighbor_allgatherv(3) Open MPI MPI_Neighbor_allgatherv(3)

MPI_Neighbor_allgatherv, MPI_Ineighbor_allgatherv, MPI_Neighbor_allgatherv_init — Collecte et distribue des données depuis et vers tous les voisins. Chaque processus peut contribuer une quantité différente de données.

PARAMÈTRES D'ENTRÉE

  • sendbuf: Adresse de début du tampon d'envoi (optionnel).
  • sendcount: Nombre d'éléments dans le tampon d'envoi (entier).
  • sendtype: Type des éléments dans le tampon d'envoi (descripteur).
  • recvcount: Tableau d'entiers (de taille égale au groupe) contenant le nombre d'éléments à recevoir de chaque voisin.
  • displs: Tableau d'entiers (de taille égale au groupe). L'élément i spécifie le décalage (par rapport à recvbuf) où placer les données provenant du voisin i.
  • recvtype: Type des éléments dans le tampon de réception (descripteur).
  • comm: Communicateur (descripteur).
  • info Info (descripteur, persistant uniquement).:

PARAMÈTRES DE SORTIE

  • recvbuf: Adresse du tampon de réception (optionnel).
  • request: Requête (descripteur, non bloquant).
  • ierror: Uniquement en Fortran : code d'erreur (entier).

DESCRIPTION

MPI_Neighbor_allgatherv est similaire à MPI_Neighbor_allgather en ce sens que tous les processus collectent des données de tous les voisins, sauf que chaque processus peut envoyer une quantité de données différente. Le bloc de données envoyé par le voisin j est reçu par tous les voisins et placé dans le bloc j du tampon. L'ordre des voisins et le tampon sont déterminés par la topologie de comm. recvbuf.

La signature de type associée à sendcount, sendtype au processus j doit être égale à la signature de type associée à l'élément correspondant dans recvcounts chez les voisins voisins.

ORDRE DES VOISINS

Pour une topologie de graphe distribué créée avec MPI_Dist_graph_create, la séquence des voisins dans les tampons d'envoi et de réception sur chaque processus est définie comme la séquence retournée par MPI_Dist_graph_neighbors pour les destinations et les sources respectivement. Pour une topologie générale créée avec MPI_Graph_create, la séquence des voisins dans les tampons d'envoi et de réception est définie comme la séquence des voisins retournée par MPI_Graph_neighbors. Notez que les topologies générales devraient généralement être remplacées par des topologies de graphes distribués.

Pour une topologie cartésienne créée avec MPI_Cart_create, la séquence des voisins dans les tampons d'envoi et de réception sur chaque processus est définie selon l'ordre des dimensions, d'abord les voisins dans la direction négative, puis dans la direction positive avec un décalage de 1. Le nombre de sources et de destinations dans les routines de communication est 2*ndims où ndims est défini dans MPI_Cart_create. Si un voisin n'existe pas, c'est-à-dire au bord d'une topologie cartésienne non périodique (c'est-à-dire, periods[...]==false), alors ce voisin est défini comme MPI_PROC_NULL.

Si un voisin dans l'une des fonctions est MPI_PROC_NULL, alors la communication collective des voisins se comporte comme une communication point à point avec MPI_PROC_NULL dans cette direction. C'est-à-dire que le tampon fait toujours partie de la séquence des voisins mais n'est ni communiqué ni mis à jour.

NOTES

L'option MPI_IN_PLACE pour sendbuf n'a pas de signification pour cette opération.

ERREURS

Toutes les routines MPI retournent une valeur d'erreur ; les routines C retournent le résultat de la fonction et les routines Fortran dans le dernier argument.

Avant que la valeur d'erreur ne soit retournée, le gestionnaire d'erreurs associé à l'objet de communication (par exemple, le communicateur, la fenêtre, le fichier) utilisé est appelé. S'il n'y a pas d'objet de communication associé à l'appel MPI, l'appel est considéré comme associé à MPI_COMM_SELF et appellera le gestionnaire d'erreurs associé à MPI_COMM_SELF. Lorsque MPI_COMM_SELF n'est pas initialisé (c'est-à-dire, avant MPI_Init/MPI_Init_thread, après MPI_Finalize, ou lorsqu'il est utilisé exclusivement dans le Modèle de Sessions), l'erreur initiale est déclenchée. Le gestionnaire d'erreurs initial peut être modifié en appelant MPI_Comm_set_errhandler sur MPI_COMM_SELF lorsqu'il est utilisé dans le Modèle Mondial, ou via l'argument mpi_initial_errhandler de mpiexec ou le paramètre info de MPI_Comm_spawn/MPI_Comm_spawn_multiple. S'il n'y a pas d'autre gestionnaire d'erreurs approprié, le gestionnaire d'erreurs MPI_ERRORS_RETURN est appelé pour les fonctions d'E/S MPI et le gestionnaire d'erreurs MPI_ERRORS_ABORT pour toutes les autres fonctions MPI.

  • MPI_ERRORS_ARE_FATAL Provoque l'arrêt du processus MPI connecté.
  • MPI_ERRORS_ABORT Un gestionnaire d'erreurs qui peut être invoqué sur un communicateur, une fenêtre, un fi
