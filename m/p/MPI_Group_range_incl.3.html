MPI_Group_range_incl(3) Open MPI MPI_Group_range_incl(3)

MPI_Group_range_incl — Crée un nouveau groupe à partir de plages de rangs dans un groupe existant.

Syntaxe

Syntaxe C

#include <mpi.h>
int MPI_Group_range_incl(MPI_Group group, int n, int ranges[][3],
     MPI_Group *newgroup)

Syntaxe Fortran

USE MPI
! ou l'ancien format: INCLUDE 'mpif.h'
MPI_GROUP_RANGE_INCL(GROUP, N, RANGES, NEWGROUP, IERROR)
     INTEGER GROUP, N, RANGES(3,*), NEWGROUP, IERROR

Syntaxe Fortran 2008

USE mpi_f08
MPI_Group_range_incl(group, n, ranges, newgroup, ierror)
     TYPE(MPI_Group), INTENT(IN) :: group
     INTEGER, INTENT(IN) :: n, ranges(3,n)
     TYPE(MPI_Group), INTENT(OUT) :: newgroup
     INTEGER, OPTIONAL, INTENT(OUT) :: ierror

Paramètres d'entrée

  • group: Groupe (handle).
  • n: Nombre de triplets dans le tableau ranges (entier).
  • ranges: Tableau unidimensionnel de triplets d'entiers, de la forme (premier rang, dernier rang, pas), indiquant les rangs dans le groupe ou processus à inclure dans le nouveau groupe.

Paramètres de sortie

  • newgroup: Nouveau groupe dérivé de ce qui précède, dans l'ordre défini par ranges (handle).
  • ierror: Fortran uniquement : Code d'erreur (entier).

Description

Si ranges consiste en les triplets

(first1, last1, stride1), ..., (firstn, lastn, striden)

alors newgroup consiste en la séquence de processus dans le groupe avec les rangs

                                               last(1)-first(1)
first(1), first(1) + stride(1),..., first(1) + ---------------- stride(1),...
                                                   stride(1)
                                               last(n)-first(n)
first(n), first(n) + stride(n),..., first(n) + ---------------- stride(n).
                                                   stride(n)

Chaque rang calculé doit être un rang valide dans le groupe et tous les rangs calculés doivent être distincts, sinon le programme est fautif. Remarque : on peut avoir first(i) > last(i) et stride(i) peut être négatif, mais ne peut pas être zéro.

La fonctionnalité de cette routine est spécifiée comme équivalente à l'expansion du tableau de plages en un tableau de rangs inclus et à la transmission du tableau de rangs et d'autres arguments à MPI_Group_incl. Un appel à MPI_Group_incl est équivalent à un appel à MPI_Group_range_incl avec chaque rang i dans ranges remplacé par le triplet (i, i, 1) dans les arguments ranges.

Note

Cette implémentation ne vérifie actuellement pas que les listes de plages à inclure sont valides dans le groupe.

Erreurs

La plupart des routines MPI renvoient une valeur d'erreur ; les routines C renvoient le résultat de la fonction et les routines Fortran dans le dernier argument.

Avant que la valeur d'erreur ne soit renvoyée, le gestionnaire d'erreurs actuel associé à l'objet de communication (par exemple, le communicateur, la fenêtre, le fichier) lié à l'appel MPI est appelé. S'il n'y a pas d'objet de communication associé à l'appel MPI, l'appel est considéré comme lié à MPI_COMM_SELF et le gestionnaire d'erreurs associé à MPI_COMM_SELF est appelé. Lorsque MPI_COMM_SELF n'est pas initialisé (c'est-à-dire avant MPI_Init/MPI_Init_thread, après MPI_Finalize, ou lorsqu'on utilise le modèle de session exclusivement), l'erreur déclenche le gestionnaire d'erreurs initial. Le gestionnaire d'erreurs initial peut être modifié en appelant MPI_Comm_set_errhandler sur MPI_COMM_SELF lors de l'utilisation du modèle du monde, ou l'argument mpi_initial_errhandler de la CLI de mpiexec ou la clé d'information de MPI_Comm_spawn/MPI_Comm_spawn_multiple. Si aucun autre gestionnaire d'erreurs approprié n'est défini, le gestionnaire MPI_ERRORS_RETURN est appelé pour les fonctions d'E/S MPI et le gestionnaire MPI_ERRORS_ABORT pour toutes les autres fonctions MPI.

Open MPI inclut trois gestionnaires d'erreurs par défaut qui peuvent être utilisés :

  • MPI_ERRORS_ARE_FATAL : Le programme arrête tous les processus MPI connectés.
  • MPI_ERRORS_ABORT : Un gestionnaire d'erreurs qui peut être invoqué sur un communicateur, une fenêtre, un fichier ou une session. Lorsqu'il est invoqué sur un communicateur, il agit comme si MPI_Abort avait été appelé sur ce communicateur. S'il est invoqué sur une fenêtre ou un fichier, il agit comme si MPI_Abort avait été appelé sur un communicateur contenant les processus de la fenêtre ou du fichier correspondant. S'il est invoqué sur une session, il arrête uniquement le processus local.
  • MPI_ERRORS_RETURN : Renvoie un code d'erreur à l'application.

Les programmes MPI peuvent également implémenter leurs propres gestionnaires d'erreurs en appelant :

  • MPI_Comm_create_errhandler et MPI_Comm_set_errhandler
  • MPI_File_create_errhandler et MPI_File_set_errhandler
  • MPI_Session_create_errhandler et MPI_Session_set_errhandler ou à MPI_Session_init
  • MPI_Win_create_errhandler et MPI_Win_set_errhandler

Remarque : MPI ne garantit pas qu'un programme MPI puisse continuer après une erreur.

Voir la page de manuel MPI pour une liste complète des codes d'erreur MPI.

Voir la section sur la gestion des erreurs de la norme MPI-3.1 pour plus d'informations.
