MPI_Intercomm_create — Crée un intercomunicateur à partir de deux intracommunicateurs.

SYNTAXE

Syntaxe C

#include <mpi.h>
int MPI_Intercomm_create(MPI_Comm local_comm, int local_leader,
     MPI_Comm peer_comm, int remote_leader, int tag, MPI_Comm *newintercomm)

Syntaxe Fortran

USE MPI
! ou la vieille forme : INCLUDE 'mpif.h'
MPI_INTERCOMM_CREATE(LOCAL_COMM, LOCAL_LEADER, PEER_COMM,
             REMOTE_LEADER, TAG, NEWINTERCOMM, IERROR)
     INTEGER LOCAL_COMM, LOCAL_LEADER, PEER_COMM, REMOTE_LEADER
     INTEGER TAG, NEWINTERCOMM, IERROR

Syntaxe Fortran 2008

USE mpi_f08
MPI_Intercomm_create(local_comm, local_leader, peer_comm, remote_leader,
             tag, newintercomm, ierror)
     TYPE(MPI_Comm), INTENT(IN) :: local_comm, peer_comm
     INTEGER, INTENT(IN) :: local_leader, remote_leader, tag
     TYPE(MPI_Comm), INTENT(OUT) :: newintercomm
     INTEGER, OPTIONAL, INTENT(OUT) :: ierror

PARAMETRES D'ENTREE

  • local_comm: Le communicateur contenant le processus lançant la communication intercommunicateur (handle).
  • local_leader: Le leader local du groupe dans local_comm (entier).
  • peer_comm: Le communicateur "peer" ; significatif seulement chez le leader local (handle).
  • remote_leader: Le leader distant du communicateur peer_comm ; significatif seulement chez le leader local (entier).
  • tag: Le numéro de tag utilisé pour identifier le nouvel intercomunicateur (entier).

PARAMETRES DE SORTIE

  • newintercomm: Le nouvel intercomunicateur créé (handle).
  • ierror: En Fortran uniquement : le statut d'erreur (entier).

DESCRIPTION

Cet appel crée un intercomunicateur. Il est collectif sur l'union des groupes locaux et distants. Les processus doivent fournir les mêmes valeurs pour local_comm et local_leader au sein de chaque groupe. Les valeurs remote_leader, local_leader et tag ne sont pas autorisées comme jokers.

Cet appel utilise la communication point à point avec le communicateur peer_comm, et avec le tag spécifié entre les leaders. Par conséquent, il faut faire attention à éviter toute communication pendante dans peer_comm qui pourrait interférer avec cette communication.

Si plusieurs appels à MPI_Intercomm_create sont effectués, ceux-ci doivent utiliser des tags différents (plus précisément, il faut s'assurer que les leaders locaux et distants utilisent des tags distincts pour chaque MPI_Intercomm_create).

NOTES

Il est recommandé d'utiliser un communicateur "peer" dédié, tel qu'une copie de MPI_COMM_WORLD, pour éviter des problèmes avec les communicateurs "peer".

La norme MPI 1.1 contient deux commentaires contradictoires concernant les intracommunicateurs d'entrée. L'un dit que les groupes correspondants doivent être disjoints ; l'autre dit que les leaders peuvent être le même processus. Après discussion par le comité MPI, il a été décidé que les groupes doivent être disjoints. La raison pour laquelle c'est indiqué dans la norme n'est pas la raison pour laquelle cette décision a été prise ; au contraire, d'autres opérations sur les intercomunicateurs (comme MPI_Intercomm_merge) n'ont pas de sens si les groupes ne sont pas disjoints.

ERREURS

La plupart des routines MPI renvoient une valeur d'erreur ; les routines C renvoient le résultat de la fonction et les routines Fortran le dernier argument.

Avant de renvoyer la valeur d'erreur, le gestionnaire d'erreurs associé à l'objet de communication actuel (par exemple, communicateur, fenêtre, fichier) est appelé. S'il n'y a pas d'objet de communication associé à l'appel MPI, l'appel est considéré comme associé à MPI_COMM_SELF et le gestionnaire d'erreurs associé à MPI_COMM_SELF est appelé. Lorsque MPI_COMM_SELF n'est pas initialisé (c'est-à-dire avant MPI_Init/MPI_Init_thread, après MPI_Finalize ou lorsque le modèle de sessions est utilisé exclusivement), le gestionnaire d'erreurs initial est déclenché. Le gestionnaire d'erreurs initial peut être modifié en appelant MPI_Comm_set_errhandler sur MPI_COMM_SELF lors de l'utilisation du modèle du monde, ou sur l'argument mpi_initial_errhandler de mpiexec ou sur la clé d'information de MPI_Comm_spawn/MPI_Comm_spawn_multiple. Si aucun autre gestionnaire d'erreurs approprié n'est configuré, le gestionnaire d'erreurs MPI_ERRORS_RETURN est appelé pour les fonctions d'E/S MPI et le gestionnaire d'erreurs MPI_ERRORS_ABORT pour toutes les autres fonctions MPI.

Open MPI inclut trois gestionnaires d'erreurs par défaut qui peuvent être utilisés :

  • MPI_ERRORS_ARE_FATAL Arrête tous les processus MPI connectés.
  • MPI_ERRORS_ABORT Un gestionnaire d'erreurs qui peut être appelé sur un communicateur, une fenêtre, un fichier ou une session. Lorsqu'il est appelé sur un communicateur, il agit comme si MPI_Abort avait été appelé sur ce communicateur. S'il est appelé sur une fenêtre ou un fichier, il agit comme si MPI_Abort avait été appelé sur un communicateur contenant l'ensemble des processus de la fenêtre ou du fichier correspondant. S'il est appelé sur une session, il arrête uniquement le processus local.
  • MPI_ERRORS_RETURN Renvoye le code d'erreur à l'application.

Les applications MPI peuvent également implémenter leurs propres gestionnaires d'erreurs en appelant :

  • MPI_Comm_create_errhandler puis MPI_Comm_set_errhandler
  • MPI_File_create_errhandler puis MPI_File_set_errhandler
  • MPI_Session_create_errhandler puis MPI_Session_set_errhandler ou lors de MPI_Session_init
  • MPI_Win_create_errhandler puis MPI_Win_set_errhandler

Remarque : les programmes MPI ne garantissent pas de pouvoir continuer après une erreur.

Voir la page de manuel MPI pour une liste complète des codes d'erreur MPI.

Voir la section sur la gestion des erreurs de la norme MPI-3.1 pour plus d'informations.
