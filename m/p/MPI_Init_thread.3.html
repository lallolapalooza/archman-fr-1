MPI_Init_thread — Initialise le modèle de monde MPI

SYNTAXE

Syntaxe C

#include <mpi.h>
int MPI_Init_thread(int *argc, char ***argv,
     int required, int *provided)

Syntaxe Fortran

USE MPI
! ou l'ancienne forme : INCLUDE 'mpif.h'
MPI_INIT_THREAD(REQUIRED, PROVIDED, IERROR)
     INTEGER REQUIRED, PROVIDED, IERROR

Syntaxe Fortran 2008

USE mpi_f08
MPI_Init_thread(required, provided, ierror)
     INTEGER, INTENT(IN) :: required
     INTEGER, INTENT(OUT) :: provided
     INTEGER, OPTIONAL, INTENT(OUT) :: ierror

PARAMETRES ENTRANT

  • argc: C seulement : Pointeur vers le nombre d'arguments.
  • argv: C seulement : Vecteur d'arguments.
  • required: Niveau de support de thread souhaité (entier).

PARAMETRES SORTANT

  • provided: Niveau de support de thread disponible (entier).
  • ierror: Fortran seulement : Statut d'erreur (entier).

DESCRIPTION

Cette routine, ou MPI_Init, initialise le modèle de monde MPI. L'une ou l'autre de ces routines doit être appelée avant que les routines de communication MPI ne soient appelées dans le modèle de monde MPI. Le modèle de monde MPI peut être initialisé au plus une fois dans la durée de vie d'un processus MPI. Ceci est différent du modèle de session MPI, qui peut être initialisé et finalisé plusieurs fois dans un processus MPI. Voir MPI_Session_init et MPI_Session_finalize.

Voir MPI-5.0:11.4.1 pour une liste de la fonctionnalité MPI qui est disponible (par exemple, même lorsque le modèle de monde MPI n'a pas encore été initialisé ou a déjà été finalisé).

Le modèle de monde MPI peut être initialisé au plus une fois ; les appels ultérieurs à MPI_Init ou MPI_Init_thread sont erronés.

Alternativement, au lieu du modèle de monde MPI, les applications MPI peuvent utiliser le modèle de sessions ; voir MPI_Session_init.

Au retour, le niveau de support de thread disponible pour le programme est défini dans provided. Dans Open MPI, la valeur dépend de la manière dont la bibliothèque a été configurée et compilée. Notez qu'il n'y a aucune garantie que provided sera supérieur ou égal à required.

Open MPI accepte les arguments C argc et argv de main, mais ne les modifie, ne les interprète ni ne les distribue :

#include <mpi.h>
int main(int argv, char *argv[]) {
    int provided;
    MPI_Init_thread(&argc, &argv, MPI_THREAD_MULTIPLE, &provided);
    /* ...corps du programme MPI principal... */
    MPI_Finalize();
    return 0;
}

MPI_Init_thread a à la fois un mécanisme direct et un mécanisme indirect pour demander un niveau spécifique de support de thread. MPI_Init n'a qu'un mécanisme indirect pour demander un niveau spécifique de support de thread.

Demande directe de niveau de thread

MPI_Init_thread a le paramètre required, qui peut être défini sur l'une des constantes suivantes (depuis mpi.h) :

  • MPI_THREAD_SINGLE : Indique qu'un seul thread sera exécuté.
  • MPI_THREAD_FUNNELED : Indique que si le processus est multithreadé, seul le thread qui a appelé MPI_Init_thread effectuera des appels MPI.
  • MPI_THREAD_SERIALIZED : Indique que si le processus est multithreadé, un seul thread effectuera des appels à la bibliothèque MPI à la fois.
  • MPI_THREAD_MULTIPLE : Indique que si le processus est multithreadé, plusieurs threads peuvent appeler MPI simultanément sans restriction.

Les valeurs de ces constantes respectent les relations suivantes :


\begin{eqnarray}

MPI\_THREAD\_SINGLE & < & MPI\_THREAD\_FUNNELED \\
MPI\_THREAD\_FUNNELED & < & MPI\_THREAD\_SERIALIZED \\
MPI\_THREAD\_SERIALIZED & < & MPI\_THREAD\_MULTIPLE \\ \end{eqnarray}

Demande indirecte de niveau de thread

MPI_Init_thread et MPI_Init prennent en charge une méthode indirecte pour indiquer le niveau de thread requis : définir la variable d'environnement OMPI_MPI_THREAD_LEVEL :

  • Si la variable d'environnement OMPI_MPI_THREAD_LEVEL est définie au moment où MPI_Init est appelé, cela se comporte comme si MPI_Init_thread avait été appelé avec la constante MPI_THREAD_* correspondante passée via le paramètre required.
  • Si la variable d'environnement OMPI_MPI_THREAD_LEVEL est définie au moment où MPI_Init_thread est appelé, la constante MPI_THREAD_* correspondant à la valeur de la variable d'environnement remplace la valeur passée via le paramètre required.

La variable d'environnement OMPI_MPI_THREAD_LEVEL peut être définie sur l'une des valeurs listées ci-dessous.

Valeur utilisée par Open MPI Valeurs autorisées (insensible à la casse)
MPI_THREAD_SINGLE MPI_THREAD_SINGLE, SINGLE, 0
MPI_THREAD_FUNNELED MPI_THREAD_FUNNELED, FUNNELED, 1
MPI_THREAD_SERIALIZED MPI_THREAD_SERIALIZED, SERIALIZED, 2
MPI_THREAD_MULTIPLE MPI_THREAD_MULTIPLE, MULTIPLE, 3

NOTE :

Dans Open MPI v5.0.8 et antérieur, seules les valeurs entières 0 à 3 étaient des valeurs acceptables pour la variable d'environnement OMPI_MPI_THREAD_LEVEL.

À partir d'Open MPI v5.0.9, la communauté Open MPI recommande d'utiliser l'une des variantes de nom de chaîne.

NOTES

La version Fortran n'a pas de dispositions pour argc et argv et ne prend que REQUIRED, PROVIDED et IERROR.

Il incombe à l'appelant de vérifier la valeur de provided, car elle peut être inférieure à ce qui était demandé dans required.

La norme MPI ne spécifie pas ce qu'un programme utilisant le modèle de monde MPI peut faire avant d'appeler MPI_Init ou MPI_Init_thread ou après avoir appelé MPI_Finalize. Dans l'implémentation Open MPI, il devrait faire le moins possible. En particulier, évitez tout ce qui modifie l'état externe du programme, comme ouvrir des fichiers, lire l'entrée standard ou écrire dans la sortie standard.

Support MPI_THREAD_MULTIPLE

Le support MPI_THREAD_MULTIPLE est inclus si l'environnement dans lequel Open MPI a été compilé prend en charge les threads. Vous pouvez vérifier la sortie de ompi_info(1) pour voir si Open MPI a le support MPI_THREAD_MULTIPLE :

shell$ ompi_info | grep "Thread support"
          Thread support: posix (MPI_THREAD_MULTIPLE: yes, OPAL support: yes, OMPI progress: no, Event lib: yes)
shell$

SYNTAX

       C/C++:
           #include <mpi.h>
           int MPI_Init_thread(int *argc, char ***argv, int *provided);
           int MPI_Init(int *argc, char ***argv);

       Fortran:
           INCLUDE "mpif.h"
           SUBROUTINE MPI_INIT_THREAD(argc, argv, provided, ierror)
               INTEGER :: argc, provided, ierror
               CHARACTER(LEN=*), DIMENSION(:), INTENT(INOUT) :: argv
           END SUBROUTINE MPI_INIT_THREAD

           SUBROUTINE MPI_INIT(argc, argv, ierror)
               INTEGER :: argc, ierror
               CHARACTER(LEN=*), DIMENSION(:), INTENT(INOUT) :: argv
           END SUBROUTINE MPI_INIT

INPUT PARAMETERS

argc
Nombre d'arguments de la ligne de commande.
argv
Tableau des arguments de la ligne de commande.

OUTPUT PARAMETERS

provided
Niveau de prise en charge du multithreading garanti par MPI.
ierror
Code d'erreur Fortran.

DESCRIPTION

Initialise l'environnement MPI. La fonction MPI_Init_thread est une extension de MPI_Init qui permet à une application MPI de demander un niveau de prise en charge du multithreading. Les valeurs possibles pour provided sont :

MPI_THREAD_SINGLE
Seul le thread principal peut appeler des routines MPI.
MPI_THREAD_FUNNELED
Plusieurs threads peuvent appeler des routines MPI, mais seul le thread qui a appelé MPI_Init_thread peut le faire.
MPI_THREAD_SERIALIZED
Plusieurs threads peuvent appeler des routines MPI, mais une seule à la fois.
MPI_THREAD_MULTIPLE
Plusieurs threads peuvent appeler des routines MPI indépendamment.

Si MPI_Init est utilisée, le niveau de prise en charge du multithreading est implicitement défini sur MPI_THREAD_SINGLE.

La fonction MPI_Init est un alias pour MPI_Init_thread avec provided défini sur MPI_THREAD_SINGLE.

NOTES

La partie MPI_THREAD_MULTIPLE : oui de la sortie ci-dessus indique qu'Open MPI a été compilé avec la prise en charge de MPI_THREAD_MULTIPLE.

Notez qu'il y a une légère pénalité de performance pour l'utilisation de la prise en charge MPI_THREAD_MULTIPLE ; les latences pour les messages courts seront plus élevées par rapport à l'utilisation de MPI_THREAD_SINGLE, par exemple.

ERRORS

Presque toutes les routines MPI retournent une valeur d'erreur ; les routines C sous forme de résultat de retour de la fonction et les routines Fortran dans le dernier argument.

Avant que la valeur d'erreur ne soit retournée, le gestionnaire d'erreurs MPI actuel associé à l'objet de communication (par exemple, communicateur, fenêtre, fichier) est appelé. S'il n'y a pas d'objet de communication associé à l'appel MPI, alors l'appel est considéré comme attaché à MPI_COMM_SELF et appellera le gestionnaire d'erreurs MPI associé. Lorsque MPI_COMM_SELF n'est pas initialisé (c'est-à-dire avant MPI_Init/MPI_Init_thread, après MPI_Finalize, ou lors de l'utilisation exclusive du modèle Sessions) l'erreur déclenche le gestionnaire d'erreurs initial. Le gestionnaire d'erreurs initial peut être modifié en appelant MPI_Comm_set_errhandler sur MPI_COMM_SELF lors de l'utilisation du modèle World, ou l'argument CLI mpi_initial_errhandler pour mpiexec ou la clé info pour MPI_Comm_spawn/MPI_Comm_spawn_multiple. Si aucun autre gestionnaire d'erreurs approprié n'a été défini, alors le gestionnaire d'erreurs MPI_ERRORS_RETURN est appelé pour les fonctions E/S MPI et le gestionnaire d'erreurs MPI_ERRORS_ABORT est appelé pour toutes les autres fonctions MPI.

Open MPI inclut trois gestionnaires d'erreurs prédéfinis qui peuvent être utilisés :

  • MPI_ERRORS_ARE_FATAL Provoque l'abandon du programme sur tous les processus MPI connectés.
  • MPI_ERRORS_ABORT Un gestionnaire d'erreurs qui peut être invoqué sur un communicateur, une fenêtre, un fichier ou une session. Lorsqu'il est appelé sur un communicateur, il agit comme si MPI_Abort avait été appelé sur ce communicateur. S'il est appelé sur une fenêtre ou un fichier, il agit comme si MPI_Abort avait été appelé sur un communicateur contenant le groupe de processus dans la fenêtre ou le fichier correspondant. S'il est appelé sur une session, il n'abandonne que le processus local.
  • MPI_ERRORS_RETURN Retourne un code d'erreur à l'application.

Les applications MPI peuvent également implémenter leurs propres gestionnaires d'erreurs en appelant :

  • MPI_Comm_create_errhandler puis MPI_Comm_set_errhandler
  • MPI_File_create_errhandler puis MPI_File_set_errhandler
  • MPI_Session_create_errhandler puis MPI_Session_set_errhandler ou à MPI_Session_init
  • MPI_Win_create_errhandler puis MPI_Win_set_errhandler

Notez que MPI ne garantit pas qu'un programme MPI puisse continuer au-delà d'une erreur.

Voir la page de manuel MPI pour une liste complète des codes d'erreur MPI.

Voir la section Gestion des erreurs de la norme MPI-3.1 pour plus d'informations.
