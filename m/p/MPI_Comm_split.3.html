MPI_COMM_SPLIT(3) Open MPI MPI_COMM_SPLIT(3)

MPI_Comm_split — Crée de nouveaux communicateurs basés sur des couleurs et des clés.

SYNTAXE

Syntaxe C

#include <mpi.h>
int MPI_Comm_split(MPI_Comm comm, int color, int key,
     MPI_Comm *newcomm)

Syntaxe Fortran

USE MPI
! ou la forme plus ancienne : INCLUDE 'mpif.h'
MPI_COMM_SPLIT(COMM, COLOR, KEY, NEWCOMM, IERROR)
     INTEGER COMM, COLOR, KEY, NEWCOMM, IERROR

Syntaxe Fortran 2008

USE mpi_f08
MPI_Comm_split(comm, color, key, newcomm, ierror)
     TYPE(MPI_Comm), INTENT(IN) :: comm
     INTEGER, INTENT(IN) :: color, key
     TYPE(MPI_Comm), INTENT(OUT) :: newcomm
     INTEGER, OPTIONAL, INTENT(OUT) :: ierror

PARAMÈTRES D'ENTRÉE

  • comm: Communicateur (handle).
  • color: Contrôle de l'assignation de sous-groupes (entier non négatif).
  • key: Contrôle de l'assignation de rang (entier).

PARAMÈTRES DE SORTIE

  • newcomm: Nouveau communicateur (handle).
  • ierror: Fortran seulement : Statut d'erreur (entier).

DESCRIPTION

Cette fonction partitionne le groupe associé à comm en sous-groupes disjoints, un pour chaque valeur de color. Chaque sous-groupe contient tous les processus de la même couleur. Au sein de chaque sous-groupe, les processus sont classés dans l'ordre défini par la valeur de l'argument key, les égalités étant rompues selon leur rang dans le groupe d'origine. Un nouveau communicateur est créé pour chaque sous-groupe et retourné dans newcomm. Un processus peut fournir la valeur de couleur MPI_UNDEFINED, auquel cas newcomm renvoie MPI_COMM_NULL. C'est un appel collectif, mais chaque processus est autorisé à fournir des valeurs différentes pour color et key.

Lorsque vous appelez MPI_Comm_split sur un inter-communicateur, les processus de gauche ayant la même couleur que ceux de droite se combinent pour créer un nouvel inter-communicateur. L'argument key décrit le rang relatif des processus de chaque côté de l'inter-communicateur. La fonction renvoie MPI_COMM_NULL pour les couleurs spécifiées sur un seul côté de l'inter-communicateur, ou pour celles qui spécifient MPI_UNDEFINED comme couleur.

Un appel à MPI_Comm_create(comm, group, newcomm) est équivalent à un appel à MPI_Comm_split(comm, color,key, newcomm), où tous les membres de group fournissent color = 0 et key = rang dans le groupe, et tous les processus qui ne sont pas membres de group fournissent color = MPI_UNDEFINED. La fonction MPI_Comm_split permet un partitionnement plus général d'un groupe en un ou plusieurs sous-groupes avec réorganisation optionnelle.

La valeur de color doit être non négative ou MPI_UNDEFINED.

NOTES

C'est un mécanisme extrêmement puissant pour diviser un seul groupe de processus communicants en k sous-groupes, k étant choisi implicitement par l'utilisateur (par le nombre de couleurs affirmées sur tous les processus). Chaque communicateur résultant sera non-chevauchant. Une telle division peut être utile pour définir une hiérarchie de calculs, par exemple pour le multigrid ou l'algèbre linéaire.

Des appels multiples à MPI_Comm_split peuvent être utilisés pour surmonter l'exigence qu'un appel n'ait pas de chevauchement des communicateurs résultants (chaque processus n'appartient qu'à une seule couleur par appel). De cette manière, plusieurs structures de communication chevauchantes peuvent être créées. L'utilisation créative de la couleur et de la clé dans de telles opérations de division est encouragée.

Notez que, pour une couleur fixe, les clés ne doivent pas nécessairement être uniques. Il incombe à MPI_Comm_split de trier les processus par ordre croissant selon cette clé, et de rompre les égalités de manière cohérente. Si toutes les clés sont spécifiées de la même manière, alors tous les processus d'une couleur donnée conserveront l'ordre de rang relatif qu'ils avaient dans leur groupe parent. (En général, ils auront des rangs différents.)

Essentiellement, rendre la valeur de la clé égale à zéro pour tous les processus d'une couleur donnée signifie qu'il n'est pas nécessaire de prêter attention à l'ordre des rangs des processus dans le nouveau communicateur.

ERREURS

Presque toutes les routines MPI renvoient une valeur d'erreur ; les routines C comme résultat de retour de la fonction et les routines Fortran dans le dernier argument.

Avant que la valeur d'erreur ne soit renvoyée, le gestionnaire d'erreurs MPI actuel associé à l'objet de communication (par exemple, communicateur, fenêtre, fichier) est appelé. S'il n'y a pas d'objet de communication associé à l'appel MPI, alors l'appel est considéré comme attaché à MPI_COMM_SELF et appellera le gestionnaire d'erreurs MPI associé. Lorsque MPI_COMM_SELF n'est pas initialisé (c'est-à-dire, avant MPI_Init/MPI_Init_thread, après MPI_Finalize, ou lorsque le modèle de sessions est utilisé exclusivement), l'erreur déclenche le gestionnaire d'erreurs initial. Le gestionnaire d'erreurs initial peut être modifié en appelant MPI_Comm_set_errhandler sur MPI_COMM_SELF lors de l'utilisation du modèle World, ou par l'argument CLI mpi_initial_errhandler à mpiexec ou la clé d'information à MPI_Comm_spawn/MPI_Comm_spawn_multiple. Si aucun autre gestionnaire d'erreurs approprié n'a été défini, le gestionnaire d'erreurs MPI_ERRORS_RETURN est appelé pour les fonctions MPI I/O et le gestionnaire d'erreurs MPI_ERRORS_ABORT est appelé pour toutes les autres fonctions MPI.

Open MPI inclut trois gestionnaires d'erreurs prédéfinis qui peuvent être utilisés :

  • MPI_ERRORS_ARE_FATAL Provoque l'abandon du programme de tous les processus MPI connectés.
  • MPI_ERRORS_ABORT Un gestionnaire d'erreurs qui peut être invoqué sur un communicateur, une fenêtre, un fichier ou une session. Lorsqu'il est appelé sur un communicateur, il agit comme si MPI_Abort avait été appelé sur ce communicateur. S'il est appelé sur une fenêtre ou un fichier, il agit comme si MPI_Abort avait été appelé sur un communicateur contenant le groupe des processus dans la fenêtre ou le fichier correspondant. S'il est appelé sur une session, il n'abandonne que le processus local.
  • MPI_ERRORS_RETURN Renvoie un code d'erreur à l'application.

Les applications MPI peuvent également implémenter leurs propres gestionnaires d'erreurs en appelant :

  • MPI_Comm_create_errhandler puis MPI_Comm_set_errhandler
  • MPI_File_create_errhandler puis MPI_File_set_errhandler
  • MPI_Session_create_errhandler puis MPI_Session_set_errhandler ou à MPI_Session_init
  • MPI_Win_create_errhandler puis MPI_Win_set_errhandler

Notez que MPI ne garantit pas qu'un programme MPI puisse continuer après une erreur.

Voir la page de manuel MPI pour une liste complète des codes d'erreur MPI.

Voir la section Gestion des erreurs de la norme MPI-3.1 pour plus d'informations.
