MPI_FILE_WRITE_AT_ALL_BEGIN(3) Open MPI MPI_FILE_WRITE_AT_ALL_BEGIN(3)

MPI_File_write_at_all_begin — Écrit dans un fichier à des emplacements explicitement spécifiés ; partie initiale d'une routine collective divisée (non bloquante).

SYNTAXE

Syntaxe C

#include <mpi.h>
int MPI_File_write_at_all_begin(MPI_File fh, MPI_Offset offset,
     const void *buf, int count, MPI_Datatype datatype)

Syntaxe Fortran

USE MPI
! ou l'ancienne forme : INCLUDE 'mpif.h'
MPI_FILE_WRITE_AT_ALL_BEGIN(FH, OFFSET, BUF, COUNT, DATATYPE, IERROR)
     <type>  BUF(*)
     INTEGER FH, COUNT, DATATYPE, IERROR
     INTEGER(KIND=MPI_OFFSET_KIND)   OFFSET

Syntaxe Fortran 2008

USE mpi_f08
MPI_File_write_at_all_begin(fh, offset, buf, count, datatype, ierror)
     TYPE(MPI_File), INTENT(IN) :: fh
     INTEGER(KIND=MPI_OFFSET_KIND), INTENT(IN) :: offset
     TYPE(*), DIMENSION(..), INTENT(IN), ASYNCHRONOUS :: buf
     INTEGER, INTENT(IN) :: count
     TYPE(MPI_Datatype), INTENT(IN) :: datatype
     INTEGER, OPTIONAL, INTENT(OUT) :: ierror

PARAMÈTRE ENTRÉE/SORTIE

•
fh : Descripteur de fichier (descripteur).

PARAMÈTRES D'ENTRÉE

  • offset : Décalage de fichier (descripteur).
  • buf : Adresse initiale du tampon (choix).
  • count : Nombre d'éléments dans le tampon (entier).
  • datatype : Type de données de chaque élément du tampon (descripteur).

PARAMÈTRE DE SORTIE

•
ierror : Uniquement Fortran : statut d'erreur (entier).

DESCRIPTION

MPI_File_write_at_all_begin est la partie initiale d'une collective divisée, c'est-à-dire une routine non bloquante qui tente d'écrire dans le fichier associé à fh (à la position offset) un nombre total de count éléments de données de type datatype à partir du tampon utilisateur buf. Le décalage est en unités etype relatives à la vue actuelle. C'est-à-dire que les trous ne sont pas comptés lors de la localisation d'un décalage. Les données sont écrites dans les parties du fichier spécifiées par la vue actuelle.

NOTES

Toutes les routines collectives non bloquantes pour l'accès aux données sont « divisées » en deux routines, chacune avec _begin ou _end comme suffixe. Ces routines collectives divisées sont soumises aux règles sémantiques décrites dans la section 9.4.5 de la norme MPI-2.

ERREURS

Presque toutes les routines MPI renvoient une valeur d'erreur ; les routines C comme résultat de la fonction et les routines Fortran dans le dernier argument.

Avant que la valeur d'erreur ne soit renvoyée, le gestionnaire d'erreurs MPI actuel associé à l'objet de communication (par exemple, communicateur, fenêtre, fichier) est appelé. Si aucun objet de communication n'est associé à l'appel MPI, alors l'appel est considéré comme attaché à MPI_COMM_SELF et appellera le gestionnaire d'erreurs MPI associé. Lorsque MPI_COMM_SELF n'est pas initialisé (c'est-à-dire avant MPI_Init/MPI_Init_thread, après MPI_Finalize, ou lorsque vous utilisez exclusivement le modèle de sessions), l'erreur déclenche le gestionnaire d'erreurs initial. Le gestionnaire d'erreurs initial peut être modifié en appelant MPI_Comm_set_errhandler sur MPI_COMM_SELF lors de l'utilisation du modèle World, ou par l'argument CLI mpi_initial_errhandler à mpiexec ou la clé d'info à MPI_Comm_spawn/MPI_Comm_spawn_multiple. Si aucun autre gestionnaire d'erreurs approprié n'a été défini, alors le gestionnaire d'erreurs MPI_ERRORS_RETURN est appelé pour les fonctions MPI I/O et le gestionnaire d'erreurs MPI_ERRORS_ABORT est appelé pour toutes les autres fonctions MPI.

Open MPI inclut trois gestionnaires d'erreurs prédéfinis qui peuvent être utilisés :

  • MPI_ERRORS_ARE_FATAL Provoque l'abandon de tous les processus MPI connectés.
  • MPI_ERRORS_ABORT Un gestionnaire d'erreurs qui peut être invoqué sur un communicateur, une fenêtre, un fichier ou une session. Lorsqu'il est appelé sur un communicateur, il agit comme si MPI_Abort avait été appelé sur ce communicateur. S'il est appelé sur une fenêtre ou un fichier, il agit comme si MPI_Abort avait été appelé sur un communicateur contenant le groupe des processus correspondants dans la fenêtre ou le fichier. S'il est appelé sur une session, il n'abandonne que le processus local.
  • MPI_ERRORS_RETURN Renvoie un code d'erreur à l'application.

Les applications MPI peuvent également implémenter leurs propres gestionnaires d'erreurs en appelant :

  • MPI_Comm_create_errhandler puis MPI_Comm_set_errhandler
  • MPI_File_create_errhandler puis MPI_File_set_errhandler
  • MPI_Session_create_errhandler puis MPI_Session_set_errhandler ou à MPI_Session_init
  • MPI_Win_create_errhandler puis MPI_Win_set_errhandler

Notez que MPI ne garantit pas qu'un programme MPI puisse continuer après une erreur.

Voir la page de manuel MPI pour une liste complète des codes d'erreur MPI.

Voir la section Gestion des erreurs de la norme MPI-3.1 pour plus d'informations.
