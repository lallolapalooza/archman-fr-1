MPI_Gatherv, MPI_Igatherv, MPI_Gatherv_init - Collecte des quantités variables de données de tous les processus vers le processus racine

PARAMÈTRES ENTRÉE

  • sendbuf : Adresse du tampon d'envoi (choix).
  • sendcount : Nombre d'éléments dans le tampon d'envoi (entier).
  • sendtype : Type de données des éléments du tampon d'envoi (handle).
recvcounts
Tableau d'entiers (de taille égale à la taille du groupe) contenant le nombre d'éléments reçus de chaque processus (significatif uniquement à la racine).
•
displs
Tableau d'entiers (de taille égale à la taille du groupe). L'entrée i spécifie le déplacement par rapport à recvbuf pour placer les données entrantes du processus i (significatif uniquement à la racine).
•
recvtype
Type de données des éléments du tampon de réception (significatif uniquement à la racine) (handle).
  • root : Rang du processus de réception (entier).
  • comm : Communicateur (handle).
  • info : Informations (handle, persistant seulement).

PARAMÈTRES SORTIE

•
recvbuf
Adresse du tampon de réception (choix, significatif uniquement à la racine).
  • request : Requête (handle, non-bloquant seulement).
  • ierror : Fortran seulement : Statut d'erreur (entier).

DESCRIPTION

MPI_Gatherv étend les fonctionnalités de MPI_Gather en permettant un nombre variable de données provenant de chaque processus, puisque recvcounts est maintenant un tableau. Il offre également plus de flexibilité quant à l'endroit où les données sont placées sur la racine, en fournissant le nouvel argument, displs.

Le résultat est comme si chaque processus, y compris le processus racine, envoyait un message à la racine,

MPI_Send(sendbuf, sendcount, sendtype, root, ...);

et la racine exécute n réceptions,

MPI_Recv(recvbuf + disp[i] * extent(recvtype), recvcounts[i],
         recvtype, i, ...);

Les messages sont placés dans le tampon de réception du processus racine par ordre de rang, c'est-à-dire que les données envoyées par le processus j sont placées dans la j-ième partie du tampon de réception recvbuf sur le processus racine. La j-ième partie de recvbuf commence à l'offset displs[j] éléments (en termes de recvtype) dans recvbuf.

Le tampon de réception est ignoré pour tous les processus non racines.

La signature de type impliquée par sendcount, sendtype sur le processus i doit être égale à la signature de type impliquée par recvcounts[i], recvtype à la racine. Cela implique que la quantité de données envoyées doit être égale à la quantité de données reçues, par paires entre chaque processus et la racine. Des cartes de types distinctes entre l'expéditeur et le récepteur sont toujours autorisées, comme illustré dans l'exemple 2, ci-dessous.

Tous les arguments de la fonction sont significatifs sur le processus racine, tandis que sur les autres processus, seuls les arguments sendbuf, sendcount, sendtype, root, comm sont significatifs. Les arguments root et comm doivent avoir des valeurs identiques sur tous les processus.

La spécification des comptages, des types et des déplacements ne doit pas provoquer l'écriture d'un emplacement quelconque sur la racine plus d'une fois. Un tel appel est erroné.

Exemple 1 : Chaque processus envoie 100 entiers à la racine, mais place chaque ensemble (de 100) d'entiers espacés d'un pas à la réception. Utiliser MPI_Gatherv et l'argument displs pour y parvenir. Supposer que le pas >= 100.

MPI_Comm comm;
int gsize, sendarray[100];
int root, *rbuf, stride;
int *displs, i, rcounts;
...
MPI_Comm_size(comm, &gsize);
rbuf = (int)malloc(gsize * stride * sizeof(int));
displs = (int)malloc(gsize * sizeof(int));
rcounts = (int )malloc(gsize * sizeof(int));
for (i=0; i<gsize; ++i) {
  displs[i] = i * stride;
  rcounts[i] = 100;
}
MPI_Gatherv(sendarray, 100, MPI_INT, rbuf, rcounts, displs, MPI_INT,
            root, comm);

Notez que le programme est erroné si stride < 100.

  displs[i] = i* stride;
  rcounts[i] = 100-i;

Exemple 6 : Le processus i envoie num entiers de la i-ème colonne d'un tableau d'entiers 100 x 150, en C. Le facteur compliquant est que les différentes valeurs de num ne sont pas connues de root, donc un gather séparé doit d'abord être effectué pour les connaître. Les données sont placées de manière contiguë côté réception.

MPI_Comm comm;
int gsize, sendarray[100][150], *sptr;
int root, *rbuf, stride, myrank, disp[2], blocklen[2];
MPI_Datatype stype,types[2];
int *displs, i, *rcounts, num;
...
MPI_Comm_size( comm, &gsize);
MPI_Comm_rank( comm, &myrank );
// D'abord, rassembler les num à root
rcounts = (int )malloc(gsize * sizeof(int));
MPI_Gather( &num, 1, MPI_INT, rcounts, 1, MPI_INT, root, comm);
// root a maintenant les rcounts corrects, en utilisant ceux-ci, nous définissons
// displs[] de manière à ce que les données soient placées de manière contiguë (ou concaténées) côté réception
displs = (int)malloc(gsize * sizeof(int));
displs[0] = 0;
for (i=1; i<gsize; ++i) {
  displs[i] = displs[i-1]+rcounts[i-1];
}
// Et, crée le tampon de réception
rbuf = (int *)malloc(gsize * (displs[gsize-1]+rcounts[gsize-1]) * sizeof(int));
// Crée le type de données pour un entier, avec l'étendue de toute la ligne
disp[0] = 0;
disp[1] = 150 * sizeof(int);
type[0] = MPI_INT;
type[1] = MPI_UB;
blocklen[0] = 1;
blocklen[1] = 1;
MPI_Type_struct(2, blocklen, disp, type, &stype );
MPI_Type_commit( &stype );
sptr = &sendarray[0][myrank];
MPI_Gatherv(sptr, num, stype, rbuf, rcounts, displs, MPI_INT, root, comm);

UTILISATION DE L'OPTION IN-PLACE

L'option in-place fonctionne de la même manière qu'avec MPI_Gather. Lorsque le communicateur est un intracommunicateur, vous pouvez effectuer une opération de rassemblement in-place (le tampon de sortie est utilisé comme tampon d'entrée). Utilisez la variable MPI_IN_PLACE comme valeur du tampon d'envoi du processus root. Dans ce cas, sendcount et sendtype sont ignorés, et la contribution du processus root au vecteur rassemblé est supposée être déjà à la bonne place dans le tampon de réception.

Notez que MPI_IN_PLACE est un type de valeur spécial ; il a les mêmes restrictions d'utilisation que MPI_BOTTOM.

Étant donné que l'option in-place transforme le tampon de réception en un tampon d'envoi et de réception, une liaison Fortran qui inclut INTENT doit les marquer comme INOUT, et non comme OUT.

QUAND LE COMMUNICATEUR EST UN INTER-COMMUNICATEUR

Lorsque le communicateur est un inter-communicateur, le processus root du premier groupe rassemble les données de tous les processus du second groupe. Le premier groupe définit le processus root. Ce processus utilise MPI_ROOT comme valeur de son argument root. Les processus restants utilisent MPI_PROC_NULL comme valeur de leur argument root. Tous les processus du second groupe utilisent le rang de ce processus root dans le premier groupe comme valeur de leur argument root. Le tampon d'envoi de l'argument des processus du premier groupe doit être cohérent avec le tampon de réception de l'argument du processus root du second groupe.

ERREURS

Presque toutes les routines MPI retournent une valeur d'erreur ; les routines C comme résultat du retour de la fonction et les routines Fortran dans le dernier argument.

Avant que la valeur d'erreur ne soit retournée, le gestionnaire d'erreurs MPI actuel associé à l'objet de communication (par exemple, communicateur, fenêtre, fichier) est appelé. Si aucun objet de communication n'est associé à l'appel MPI, alors l'appel est considéré comme attaché à MPI_COMM_SELF et appellera le gestionnaire d'erreurs MPI associé. Lorsque MPI_COMM_SELF n'est pas initialisé (c'est-à-dire avant MPI_Init/MPI_Init_thread, après MPI_Finalize, ou lors de l'utilisation exclusive du modèle de sessions), l'erreur déclenche le gestionnaire d'erreurs initial. Le gestionnaire d'erreurs initial peut être modifié en appelant MPI_Comm_set_errhandler sur MPI_COMM_SELF lors de l'utilisation du modèle World, ou l'argument CLI mpi_initial_errhandler de mpiexec ou la clé d'info de MPI_Comm_spawn/MPI_Comm_spawn_multiple. Si aucun autre gestionnaire d'erreurs approprié n'a été défini, le gestionnaire d'erreurs MPI_ERRORS_RETURN est appelé pour les fonctions d'E/S MPI et le gestionnaire d'erreurs MPI_ERRORS_ABORT est appelé pour toutes les autres fonctions MPI.

Open MPI inclut trois gestionnaires d'erreurs prédéfinis qui peuvent être utilisés :

  • MPI_ERRORS_ARE_FATAL Provoque l'arrêt de l'ensemble des processus MPI connectés.
  • MPI_ERRORS_ABORT Un gestionnaire d'erreurs qui peut être invoqué sur un communicateur, une fenêtre, un fichier ou une session. Lorsqu'il est appelé sur un communicateur, il agit comme si MPI_Abort avait été appelé sur ce communicateur. S'il est appelé sur une fenêtre ou un fichier, il agit comme si MPI_Abort avait été appelé sur un communicateur contenant le groupe de processus dans la fenêtre ou le fichier correspondant. S'il est appelé sur une session, il n'interrompt que le processus local.
  • MPI_ERRORS_RETURN Retourne un code d'erreur à l'application.

Les applications MPI peuvent également implémenter leurs propres gestionnaires d'erreurs en appelant :

  • MPI_Comm_create_errhandler puis MPI_Comm_set_errhandler
  • MPI_File_create_errhandler puis MPI_File_set_errhandler
  • MPI_Session_create_errhandler puis MPI_Session_set_errhandler ou lors de MPI_Session_init
  • MPI_Win_create_errhandler puis MPI_Win_set_errhandler

Notez que MPI ne garantit pas qu'un programme MPI puisse continuer après une erreur.

Voir la page de manuel MPI pour une liste complète des codes d'erreur MPI.

Voir la section Gestion des erreurs de la norme MPI-3.1 pour plus d'informations.
