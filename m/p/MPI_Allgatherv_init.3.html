MPI_Allgatherv, MPI_Iallgatherv, MPI_Allgatherv_init - Collectent des données de tous les processus et les livrent à tous. Chaque processus peut contribuer une quantité différente de données.

PARAMÈTRES D'ENTRÉE

  • sendbuf: Adresse de départ du buffer d'envoi (optionnel).
  • sendcount: Nombre d'éléments dans le buffer d'envoi (entier).
  • sendtype: Type des éléments dans le buffer d'envoi (handle).
  • recvcount: Tableau d'entiers (de taille du groupe) contenant le nombre d'éléments reçus de chaque processus.
  • displs: Tableau d'entiers (de taille du groupe). L'élément i spécifie le déplacement (par rapport à recvbuf) où les données entrantes du processus i seront placées.
  • recvtype: Type des éléments dans le buffer de réception (handle).
  • comm: Communicateur (handle).
  • info: Informations (handle, persistant seulement).

PARAMÈTRES DE SORTIE

  • recvbuf: Adresse du buffer de réception (optionnel).
  • request: Requête (handle, non bloquant seulement).
  • ierror: En Fortran seulement : code d'erreur (entier).

DESCRIPTION

MPI_Allgatherv est similaire à MPI_Allgather en ce sens que tous les processus reçoivent des données de tous les autres processus, sauf que chaque processus peut envoyer une quantité de données différente. Le bloc de données envoyé par le processus j est reçu par tous les processus et placé dans le bloc j du buffer recvbuf.

La signature de type associée à sendcount, sendtype sur le processus j doit être égale à la signature de type associée à recvcounts[j], recvtype sur tout autre processus.

Le résultat est comme si tous les processus avaient exécuté des appels à

MPI_Allgatherv(sendbuf, sendcount, sendtype, recvbuf, recvcount,
              displs,recvtype,root,comm);
// pour root = 0, ..., n-1.

Les règles pour utiliser correctement MPI_Allgatherv sont facilement dérivées des règles correspondantes pour MPI_Gatherv.

UTILISATION DE L'OPTION EN PLACE

Lorsque le communicateur est un communicateur intergroupe, vous pouvez effectuer une opération de gather en place (le buffer de sortie est utilisé comme buffer d'entrée). Utilisez la variable MPI_IN_PLACE comme valeur de sendbuf. Dans ce cas, sendcount et sendtype sont ignorés. Les données d'entrée de chaque processus sont supposées se trouver dans la zone où ce processus recevrait sa propre contribution dans le buffer de réception. Plus spécifiquement, le résultat d'un appel à MPI_Allgatherv utilisant l'option en place est identique au cas où tous les processus auraient exécuté n appels à

MPI_Allgatherv ( MPI_IN_PLACE, 0, MPI_DATATYPE_NULL, recvbuf,
                 recvcounts, displs, recvtype, root, comm );
// pour root =0, ... , n-1.

Remarque : MPI_IN_PLACE est une valeur de type spécial ; elle a les mêmes restrictions d'utilisation que MPI_BOTTOM.

Étant donné que l'option en place transforme le buffer de réception en buffer d'envoi et de réception, une liaison Fortran incluant INTENT doit les marquer comme INOUT, et non comme OUT.

QUAND LE COMMUNICATEUR EST UN COMMUNICATEUR INTERGROUPE

Lorsque le communicateur est un communicateur intergroupe, l'opération de collectage se déroule en deux phases. Les données sont collectées auprès de tous les membres du premier groupe, concaténées, et reçues par tous les membres du second groupe. Ensuite, les données sont collectées auprès de tous les membres du second groupe, concaténées, et reçues par tous les membres du premier groupe. Les arguments d'envoi dans le premier groupe doivent être cohérents avec les arguments de réception dans le second groupe, et vice versa. L'opération doit présenter un comportement symétrique et d'échange complet.

ERREURS

Plus de 90% des routines MPI renvoient une valeur d'erreur ; les routines C renvoient le résultat de la fonction, et les routines Fortran dans le dernier argument.

Avant que la valeur d'erreur ne soit renvoyée, le gestionnaire d'erreurs associé à l'objet de communication (par exemple, le communicateur, la fenêtre, le fichier) est appelé. S'il n'y a pas d'objet de communication associé à l'appel MPI, l'appel est considéré comme associé à MPI_COMM_SELF et le gestionnaire d'erreurs associé est appelé. Lorsque MPI_COMM_SELF n'est pas initialisé (c'est-à-dire avant MPI_Init/MPI_Init_thread, après MPI_Finalize, ou lorsque le modèle de sessions est utilisé exclusivement), l'erreur déclenche le gestionnaire d'erreurs initial. Le gestionnaire d'erreurs initial peut être modifié en appelant MPI_Comm_set_errhandler sur MPI_COMM_SELF lors de l'utilisation du modèle du Monde, ou via l'argument mpi_initial_errhandler de mpiexec ou la clé d'information de MPI_Comm_spawn/MPI_Comm_spawn_multiple. Si aucun autre gestionnaire d'erreurs approprié n'est disponible, le gestionnaire d'erreurs MPI_ERRORS_RETURN est appelé pour les fonctions d'E/S MPI et le gestionnaire d'erreurs MPI_ERRORS_ABORT pour toutes les autres appels.

ERRORS

The MPI standard specifies that all MPI functions return an error code. MPI_ERR_BUFFER if the buffer is invalid. MPI_ERR_COUNT if the count is invalid. MPI_ERR_TYPE if the datatype is invalid. MPI_ERR_COMM if the communicator is invalid. MPI_ERR_ROOT if the root is invalid. MPI_ERR_DISP if the displacement is invalid. MPI_ERR_ARG if an argument is invalid.

Open MPI includes three predefined error handlers that can be used:

  • MPI_ERRORS_ARE_FATAL Causes the program to abort all connected MPI processes.
  • MPI_ERRORS_ABORT An error handler that can be invoked on a communicator, window, file, or session. When called on a communicator, it acts as if MPI_Abort was called on that communicator. If called on a window or file, acts as if MPI_Abort was called on a communicator containing the group of processes in the corresponding window or file. If called on a session, aborts only the local process.
  • MPI_ERRORS_RETURN Returns an error code to the application.

MPI applications can also implement their own error handlers by calling:

  • MPI_Comm_create_errhandler then MPI_Comm_set_errhandler
  • MPI_File_create_errhandler then MPI_File_set_errhandler
  • MPI_Session_create_errhandler then MPI_Session_set_errhandler or at MPI_Session_init
  • MPI_Win_create_errhandler then MPI_Win_set_errhandler

Note that MPI does not guarantee that an MPI program can continue past an error.

See the MPI man page for a full list of MPI error codes.

See the Error Handling section of the MPI-3.1 standard for more information.
