MPI_Init(3) Open MPI MPI_Init(3)

MPI_Init — Initialise le monde MPI

SYNTAX

Syntaxe C

#include <mpi.h>
int MPI_Init(int *argc, char ***argv)

Syntaxe Fortran

USE MPI
! ou l'ancienne forme : INCLUDE 'mpif.h'
MPI_INIT(IERROR)
     INTEGER IERROR

Syntaxe Fortran 2008

USE mpi_f08
MPI_Init(ierror)
     INTEGER, OPTIONAL, INTENT(OUT) :: ierror

PARAMETRES D'ENTRÉE

  • argc: En C uniquement : pointeur vers le nombre d'arguments.
  • argv: En C uniquement : tableau d'arguments.

PARAMÈTRE DE SORTIE

•
ierror: En Fortran uniquement : statut d'erreur (entier).

DESCRIPTION

Cette routine, ou MPI_Init_thread, initialise le monde MPI. Elle doit être appelée avant d'utiliser des routines de communication MPI au sein du monde MPI. Le monde MPI ne peut être initialisé qu'une seule fois au cours de la vie d'un processus MPI. Ceci est différent du modèle de session MPI, qui peut être initialisé et finalisé plusieurs fois dans un processus MPI. Voir MPI_Session_init et MPI_Session_finalize.

Voir MPI-5.0:11.4.1 pour une liste des fonctionnalités MPI disponibles (par exemple, même lorsque le monde MPI n'a pas été initialisé ou a déjà été finalisé).

Les MPI_Init et MPI_Init_thread d'Open MPI acceptent les arguments C argc et argv de la fonction main, mais aucun d'entre eux n'est modifié, interprété ou distribué :

#include <mpi.h>
int main(int argc, char *argv[]) {
    MPI_Init(&argc, &argv);
    /* ...corps du programme MPI... */
    MPI_Finalize();
    return 0;
}

Par défaut, MPI_Init est effectivement équivalent à l'appel de MPI_Init_thread avec une valeur required de MPI_THREAD_SINGLE. Cependant, si la variable d'environnement OMPI_MPI_THREAD_LEVEL est définie à une valeur valide lors de l'appel à MPI_Init, cela équivaut à appeler MPI_Init_thread avec required à la valeur correspondante de la variable d'environnement OMPI_MPI_THREAD_LEVEL. Voir MPI_Init_thread pour plus de détails.

NOTES

La version Fortran n'a pas de dispositions pour argc et argv et ne prend que ierror.

La fonctionnalité qu'un programme utilisant le monde MPI peut effectuer avant d'appeler MPI_Init ou MPI_Init_thread ou après avoir appelé MPI_Finalize n'est pas spécifiée dans la norme MPI. Dans l'implémentation Open MPI, vous devriez faire le moins possible. En particulier, évitez toute action qui modifierait l'état externe du programme, telle que l'ouverture de fichiers, la lecture de l'entrée standard ou l'écriture sur la sortie standard.

ERREURS

Au-delà du fait que presque toutes les routines MPI renvoient une valeur d'erreur ; les routines C renvoient le résultat de la fonction et les routines Fortran dans le dernier argument.

Avant de renvoyer la valeur d'erreur, le gestionnaire d'erreurs associé à l'objet de communication (par exemple, communicateur, fenêtre, fichier) de l'appel MPI est appelé. S'il n'y a pas d'objet de communication associé à l'appel MPI, l'appel est considéré comme associé à MPI_COMM_SELF et le gestionnaire d'erreurs correspondant est appelé. Lorsque MPI_COMM_SELF n'est pas initialisé (c'est-à-dire avant MPI_Init/MPI_Init_thread, après MPI_Finalize, ou lorsque le modèle de session est utilisé exclusivement), l'erreur élève le gestionnaire d'erreurs initial. Le gestionnaire d'erreurs initial peut être modifié en appelant MPI_Comm_set_errhandler sur MPI_COMM_SELF lors de l'utilisation du monde MPI, ou via l'argument CLI mpi_initial_errhandler dans mpiexec/la clé info dans MPI_Comm_spawn/MPI_Comm_spawn_multiple. Si aucun autre gestionnaire d'erreurs approprié n'est disponible, le gestionnaire MPI_ERRORS_RETURN est appelé pour les fonctions d'E/S MPI et le gestionnaire MPI_ERRORS_ABORT est appelé pour toutes les autres fonctions MPI.

Open MPI inclut trois gestionnaires d'erreurs par défaut qui peuvent être utilisés :

  • MPI_ERRORS_ARE_FATAL Provoque l'abandon de tous les processus MPI connectés par le programme.
  • MPI_ERRORS_ABORT Un gestionnaire d'erreurs qui peut être invoqué sur un communicateur, une fenêtre, un fichier ou une session. Lorsqu'il est invoqué sur un communicateur, il agit comme si MPI_Abort avait été appelé sur ce communicateur. S'il est invoqué sur une fenêtre ou un fichier, il agit comme si MPI_Abort avait été appelé sur un communicateur contenant le groupe de processus dans la fenêtre ou le fichier correspondant. S'il est invoqué sur une session, il n'abandonne que le processus local.
  • MPI_ERRORS_RETURN Renvoie un code d'erreur à l'application.

Les applications MPI peuvent également implémenter leurs propres gestionnaires d'erreurs en appelant :

  • MPI_Comm_create_errhandler puis MPI_Comm_set_errhandler
  • MPI_File_create_errhandler puis MPI_File_set_errhandler
  • MPI_Session_create_errhandler puis MPI_Session_set_errhandler ou lors de l'appel à MPI_Session_init
  • MPI_Win_create_errhandler puis MPI_Win_set_errhandler

Remarque : MPI ne garantit pas qu'un programme MPI puisse continuer après une erreur.

Voir la page de manuel MPI pour une liste complète des codes d'erreur MPI.

Voir la section sur la gestion des erreurs de la norme MPI-3.1 pour plus d'informations.
