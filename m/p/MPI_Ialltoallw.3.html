PARAMÈTRES D'ENTRÉE

  • sendbuf: Adresse de départ du tampon d'envoi.
  • sendcounts: Tableau d'entiers, où l'entrée i spécifie le nombre d'éléments à envoyer au rang i.
  • sdispls: Tableau d'entiers, où l'entrée i spécifie le décalage (en octets, décalage par rapport à sendbuf) à partir duquel envoyer les données au rang i.
  • sendtypes: Tableau de types de données, où l'entrée i spécifie le type de données à utiliser lors de l'envoi de données au rang i.
  • recvcounts: Tableau d'entiers, où l'entrée j spécifie le nombre d'éléments à recevoir du rang j.
  • rdispls: Tableau d'entiers, où l'entrée j spécifie le décalage (en octets, décalage par rapport à recvbuf) auquel les données du rang j doivent être écrites.
  • recvtypes: Tableau de types de données, où l'entrée j spécifie le type de données à utiliser lors de la réception de données du rang j.
  • comm: Communicateur sur lequel les données doivent être échangées.
  • info: Informations (handle, persistant uniquement)

PARAMÈTRES DE SORTIE

  • recvbuf: Adresse du tampon de réception.
  • request: Requête (handle, non bloquant uniquement).
  • ierror: Fortran uniquement : Statut d'erreur.

DESCRIPTION

MPI_Alltoallw est une opération collective généralisée dans laquelle tous les processus envoient des données à tous les autres processus et en reçoivent de tous les autres processus. Elle ajoute de la flexibilité à MPI_Alltoallv en permettant à l'utilisateur de spécifier le type de données des blocs de données individuels (en plus du décalage et du nombre d'éléments). Son fonctionnement peut être imaginé de la manière suivante, où chaque processus effectue 2n (n étant le nombre de processus dans le communicateur comm) communications point à point indépendantes (y compris la communication avec lui-même).

MPI_Comm_size(comm, &n);
for (i = 0, i < n; i++)
    MPI_Send(sendbuf + sdispls[i], sendcounts[i],
        sendtypes[i], i, ..., comm);
for (i = 0, i < n; i++)
    MPI_Recv(recvbuf + rdispls[i], recvcounts[i],
        recvtypes[i], i, ..., comm);

Le processus j envoie le k-ième bloc de son sendbuf local au processus k, qui place les données dans le j-ième bloc de son recvbuf local.

Lorsqu'une paire de processus échange des données, chacun peut passer des arguments de nombre d'éléments et de type de données différents tant que l'expéditeur spécifie la même quantité de données à envoyer (en octets) que ce que le récepteur s'attend à recevoir.

Notez qu'un processus i peut envoyer une quantité de données différente au processus j qu'il n'en reçoit du processus j. De plus, un processus peut envoyer des quantités et des types de données entièrement différents à différents processus du communicateur.

QUAND LE COMMUNICATEUR EST UN INTER-COMMUNICATEUR

Lorsque le communicateur est un inter-communicateur, l'opération de collecte se déroule en deux phases. Les données sont collectées auprès de tous les membres du premier groupe et reçues par tous les membres du second groupe. Ensuite, les données sont collectées auprès de tous les membres du second groupe et reçues par tous les membres du premier. L'opération présente un comportement symétrique, full-duplex.

Le premier groupe définit le processus racine. Le processus racine utilise MPI_ROOT comme valeur de root. Tous les autres processus du premier groupe utilisent MPI_PROC_NULL comme valeur de root. Tous les processus du second groupe utilisent le rang du processus racine du premier groupe comme valeur de root.

Lorsque le communicateur est un intra-communicateur, ces groupes sont les mêmes et l'opération se déroule en une seule phase.

UTILISATION DE L'OPTION IN-PLACE

Lorsque le communicateur est un intra-communicateur, vous pouvez effectuer une opération all-to-all en place (le tampon de sortie est utilisé comme tampon d'entrée). Utilisez la variable MPI_IN_PLACE comme valeur de sendbuf. Dans ce cas, sendcounts, sdispls, et sendtypes sont ignorés. Les données d'entrée de chaque processus sont supposées se trouver dans la zone où ce processus recevrait sa propre contribution au tampon de réception.

NOTES

La spécification des comptes, types et décalages ne doit entraîner l'écriture d'aucun emplacement plus d'une fois.

Tous les arguments sur tous les processus sont significatifs. Le paramètre comm, en particulier, doit décrire le même communicateur sur tous les processus.

PARAMÈTRES D'ENTRÉE

Presque toutes les routines MPI retournent une valeur d'erreur ; les routines C comme résultat de retour de la fonction et les routines Fortran dans le dernier argument.

Avant que la valeur d'erreur ne soit retournée, le gestionnaire d'erreurs MPI actuel associé à l'objet de communication (par exemple, communicateur, fenêtre, fichier) est appelé. Si aucun objet de communication n'est associé à l'appel MPI, l'appel est considéré comme attaché à MPI_COMM_SELF et appellera le gestionnaire d'erreurs MPI associé. Lorsque MPI_COMM_SELF n'est pas initialisé (c'est-à-dire avant MPI_Init/MPI_Init_thread, après MPI_Finalize, ou lors de l'utilisation exclusive du modèle de sessions), l'erreur déclenche le gestionnaire d'erreurs initial. Le gestionnaire d'erreurs initial peut être modifié en appelant MPI_Comm_set_errhandler sur MPI_COMM_SELF lors de l'utilisation du modèle World, ou l'argument CLI mpi_initial_errhandler pour mpiexec ou la clé d'information pour MPI_Comm_spawn/MPI_Comm_spawn_multiple. Si aucun autre gestionnaire d'erreurs approprié n'a été défini, le gestionnaire d'erreurs MPI_ERRORS_RETURN est appelé pour les fonctions d'E/S MPI et le gestionnaire d'erreurs MPI_ERRORS_ABORT est appelé pour toutes les autres fonctions MPI.

Open MPI inclut trois gestionnaires d'erreurs prédéfinis qui peuvent être utilisés :

  • MPI_ERRORS_ARE_FATAL Provoque l'arrêt du programme de tous les processus MPI connectés.
  • MPI_ERRORS_ABORT Un gestionnaire d'erreurs qui peut être invoqué sur un communicateur, une fenêtre, un fichier ou une session. Lorsqu'il est appelé sur un communicateur, il agit comme si MPI_Abort avait été appelé sur ce communicateur. S'il est appelé sur une fenêtre ou un fichier, il agit comme si MPI_Abort avait été appelé sur un communicateur contenant le groupe de processus de la fenêtre ou du fichier correspondant. S'il est appelé sur une session, il n'interrompt que le processus local.
  • MPI_ERRORS_RETURN Retourne un code d'erreur à l'application.

Les applications MPI peuvent également implémenter leurs propres gestionnaires d'erreurs en appelant :

  • MPI_Comm_create_errhandler puis MPI_Comm_set_errhandler
  • MPI_File_create_errhandler puis MPI_File_set_errhandler
  • MPI_Session_create_errhandler puis MPI_Session_set_errhandler ou à MPI_Session_init
  • MPI_Win_create_errhandler puis MPI_Win_set_errhandler

Notez que MPI ne garantit pas qu'un programme MPI puisse continuer après une erreur.

Consultez la page de manuel MPI pour une liste complète des codes d'erreur MPI.

Consultez la section Gestion des erreurs de la norme MPI-3.1 pour plus d'informations.
