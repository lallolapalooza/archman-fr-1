MPI_Allgather, MPI_Iallgather, MPI_Allgather_init - Rassemble les données de tous les processus et les distribue à tous les processus

SYNTAXE

#include <mpi.h>
int MPI_Allgather(const void *sendbuf, int  sendcount,
      MPI_Datatype sendtype, void *recvbuf, int recvcount,
      MPI_Datatype recvtype, MPI_Comm comm)
int MPI_Iallgather(const void *sendbuf, int  sendcount,
      MPI_Datatype sendtype, void *recvbuf, int recvcount,
      MPI_Datatype recvtype, MPI_Comm comm, MPI_Request *request)

PARAMÈTRES D'ENTRÉE

  • sendbuf : Adresse de départ du tampon d'envoi (choix).
  • sendcount : Nombre d'éléments dans le tampon d'envoi (entier).
  • sendtype : Type de données des éléments du tampon d'envoi (handle).
  • recvbuf : Adresse de départ du tampon de réception (choix).
  • recvcount : Nombre d'éléments reçus de n'importe quel processus (entier).
  • recvtype : Type de données des éléments du tampon de réception (handle).
  • comm : Communicateur (handle).
  • info : Informations (handle, persistant seulement).

PARAMÈTRES DE SORTIE

  • recvbuf : Adresse du tampon de réception (choix).
  • request : Requête (handle, non bloquant seulement).
  • ierror : Fortran seulement : Statut d'erreur (entier).

DESCRIPTION

MPI_Allgather est similaire à MPI_Gather, sauf que tous les processus reçoivent le résultat, au lieu d'un seul processus racine. En d'autres termes, tous les processus contribuent au résultat, et tous les processus reçoivent le résultat.

La signature de type associée à sendcount, sendtype dans un processus doit être égale à la signature de type associée à recvcount, recvtype dans tout autre processus.

Le résultat d'un appel à MPI_Allgather est comme si tous les processus exécutaient n appels à

MPI_Gather(sendbuf, sendcount, sendtype, recvbuf, recvcount,
           recvtype, root, comm);
// pour root = 0 , ..., n-1.

Les règles d'utilisation correcte de MPI_Allgather se déduisent facilement des règles correspondantes pour MPI_Gather.

Exemple : La version all-gather de l'Exemple 1 de MPI_Gather. En utilisant MPI_Allgather, nous allons rassembler 100 entiers de chaque processus du groupe vers chaque processus.

MPI_Comm comm;
int gsize,sendarray[100];
int *rbuf;
...
MPI_Comm_size( comm, &gsize);
rbuf = (int *)malloc(gsize*100*sizeof(int));
MPI_Allgather( sendarray, 100, MPI_INT, rbuf, 100, MPI_INT, comm);

Après l'appel, chaque processus possède la concaténation de groupe des ensembles de données.

UTILISATION DE L'OPTION IN-PLACE

Lorsque le communicateur est un intracommunicateur, vous pouvez effectuer une opération d'all-gather en place (le tampon de sortie est utilisé comme tampon d'entrée). Utilisez la variable MPI_IN_PLACE comme valeur de sendbuf. Dans ce cas, sendcount et sendtype sont ignorés. Les données d'entrée de chaque processus sont supposées se trouver dans la zone où ce processus recevrait sa propre contribution au tampon de réception. Plus précisément, le résultat d'un appel à MPI_Allgather qui a utilisé l'option in-place est identique au cas où tous les processus ont exécuté n appels à

MPI_Allgather( MPI_IN_PLACE, 0, MPI_DATATYPE_NULL, recvbuf,
               recvcount, recvtype, root, comm )
// pour root =0, ... , n-1.

Notez que MPI_IN_PLACE est un type de valeur spécial ; il a les mêmes restrictions d'utilisation que MPI_BOTTOM.

Comme l'option in-place convertit le tampon de réception en un tampon d'envoi et de réception, une liaison Fortran qui inclut INTENT doit les marquer comme INOUT, et non OUT.

QUAND LE COMMUNICATEUR EST UN INTER-COMMUNICATEUR

Lorsque le communicateur est un inter-communicateur, l'opération de rassemblement se déroule en deux phases. Les données sont rassemblées à partir de tous les membres du premier groupe et reçues par tous les membres du second groupe. Ensuite, les données sont rassemblées à partir de tous les membres du second groupe et reçues par tous les membres du premier. L'opération, cependant, n'a pas besoin d'être symétrique. Le nombre d'éléments envoyés par les processus du premier groupe n'a pas besoin d'être égal au nombre d'éléments envoyés par les processus du second groupe. Vous pouvez déplacer des données dans une seule direction en donnant à sendcount la valeur 0 pour la communication dans la direction inverse.

ERREURS

Presque toutes les routines MPI retournent une valeur d'erreur ; les routines C comme résultat de la fonction et les routines Fortran dans le dernier argument.

Avant que la valeur d'erreur ne soit retournée, le gestionnaire d'erreur MPI actuel associé à l'objet de communication (par exemple, communicateur, fenêtre, fichier) est appelé. S'il n'y a pas d'objet de communication associé à l'appel MPI, alors l'appel est considéré comme attaché à MPI_COMM_SELF et appellera le gestionnaire d'erreur MPI associé. Lorsque MPI_COMM_SELF n'est pas initialisé (c'est-à-dire avant MPI_Init/MPI_Init_thread, après MPI_Finalize, ou lors de l'utilisation exclusive du modèle de sessions) l'erreur déclenche le gestionnaire d'erreur initial. Le gestionnaire d'erreur initial peut être modifié en appelant MPI_Comm_set_errhandler sur MPI_COMM_SELF lors de l'utilisation du modèle World, ou l'argument CLI mpi_initial_errhandler de mpiexec ou la clé d'information de MPI_Comm_spawn/MPI_Comm_spawn_multiple. Si aucun autre gestionnaire d'erreur approprié n'a été défini, alors le gestionnaire d'erreur MPI_ERRORS_RETURN est appelé pour les fonctions d'E/S MPI et le gestionnaire d'erreur MPI_ERRORS_ABORT est appelé
