Paramètres d'entrée

  • sendbuf: Adresse de début du tampon d'envoi.
  • sendcounts: Tableau d'entiers, où l'élément i spécifie le nombre d'éléments à envoyer au voisin i.
  • sdispls: Tableau d'entiers, où l'élément i spécifie le décalage (en octets, offset par rapport à sendbuf) à partir duquel envoyer des données au voisin i.
  • sendtypes: Tableau de types de données, où l'élément i spécifie le type de données à utiliser lors de l'envoi de données au voisin i.
  • recvcounts: Tableau d'entiers, où l'élément j spécifie le nombre d'éléments à recevoir du voisin j.
  • rdispls: Tableau d'entiers, où l'élément j spécifie le décalage (en octets, offset par rapport à recvbuf) où les données du voisin j doivent être écrites.
  • recvtypes: Tableau de types de données, où l'élément j spécifie le type de données à utiliser lors de la réception de données du voisin j.
  • comm: Communicateur sur lequel les interactions sont effectuées.
  • info: Informations (handle, persistant uniquement).

Paramètres de sortie

  • recvbuf: Adresse du tampon de réception.
  • request: Requête (handle, asynchrone uniquement).
  • ierror: Uniquement en Fortran : code d'erreur.

Description

MPI_Neighbor_alltoallw est une opération collective généralisée dans laquelle tous les processus envoient des données à et reçoivent des données de tous les voisins. Elle offre une flexibilité par rapport à MPI_Neighbor_alltoallv en permettant à l'utilisateur de spécifier le type de données de blocs individuels (en plus du décalage et du nombre d'éléments). Son opération peut être considérée comme suit, où chaque processus effectue 2n (n étant le nombre de voisins dans la topologie du communicateur comm) communications point à point indépendantes. La topologie et la disposition des tampons sont déterminées par la topologie du communicateur comm.

MPI_Cart_get(comm, maxdims, dims, periods, coords);
for (dim = 0, i = 0 ; dim < dims ; ++dim) {
    MPI_Cart_shift(comm, dim, 1, &r0, &r1);
    MPI_Isend(sendbuf + sdispls[i]  * extent(sendtype),
              sendcount, sendtypes[i], r0, ..., comm, ...);
    MPI_Irecv(recvbuf + rdispls[i] * extent(recvtype),
              recvcount, recvtypes[i], r0, ..., comm, ...);
    ++i;
    MPI_Isend(sendbuf + sdispls[i] * extent(sendtype),
              sendcount, sendtypes[i], r1, ..., comm, &req[i]);
    MPI_Irecv(recvbuf + rdispls[i] * extent(recvtype),
              recvcount, recvtypes[i], r1, ..., comm, ...);
    ++i;
}
MPI_Wait_all (...);
MPI_Comm_size(comm, &n);
for (i = 0, i < n; i++)
  MPI_Send(sendbuf + sdispls[i], sendcounts[i],
       sendtypes[i], i, ..., comm);
for (i = 0, i < n; i++)
  MPI_Recv(recvbuf + rdispls[i], recvcounts[i],
       recvtypes[i], i, ..., comm);

Le processus j envoie le bloc k du tampon local sendbuf au voisin k, ce qui place les données dans le bloc j du tampon local recvbuf.

Lorsqu'une paire de processus échange des données, chacun peut passer des arguments de nombre d'éléments et de type de données différents, à condition que l'expéditeur spécifie la même quantité de données (en octets) que le récepteur s'attend à recevoir.

Note : Le processus i peut envoyer un nombre de données différent au processus j de celui que j reçoit. De même, un processus peut envoyer des données complètement différentes et de types différents à différents processus du communicateur.

Remarques

L'option MPI_IN_PLACE pour sendbuf n'est pas significative pour cette opération

Aucun emplacement ne doit être écrit plus d'une fois.

Tous les arguments de tous les processus sont significatifs. L'argument comm, en particulier, doit décrire le même communicateur sur tous les processus.

Les décalages sdispls et rdispls sont mesurés en octets. Comparez cela à MPI_Neighbor_alltoallv, où ces décalages sont mesurés en unités de sendtype et recvtype, respectivement.

SYNTAXE

La valeur d'erreur est renvoyée avant que le gestionnaire d'erreurs associé à l'objet de communication (par exemple, communicateur, fenêtre, fichier) ne soit appelé. S'il n'y a pas d'objet de communication associé à l'appel MPI, l'appel est considéré comme associé à MPI_COMM_SELF et le gestionnaire d'erreurs correspondant est appelé. Lorsque MPI_COMM_SELF n'est pas initialisé (c'est-à-dire avant MPI_Init/MPI_Init_thread, après MPI_Finalize, ou lorsqu'on utilise exclusivement le Modèle de Session), l'erreur élève le gestionnaire d'erreurs initial. Le gestionnaire d'erreurs initial peut être modifié en appelant MPI_Comm_set_errhandler sur MPI_COMM_SELF lors de l'utilisation du Modèle de Monde, ou l'argument mpi_initial_errhandler de mpiexec ou la clé info de MPI_Comm_spawn/MPI_Comm_spawn_multiple. S'il n'y a pas d'autre gestionnaire d'erreurs approprié défini, le gestionnaire d'erreurs MPI_ERRORS_RETURN est appelé pour les fonctions d'E/S MPI et MPI_ERRORS_ABORT pour toutes les autres fonctions MPI.

Open MPI inclut trois gestionnaires d'erreurs par défaut qui peuvent être utilisés :

  • MPI_ERRORS_ARE_FATAL Provoque l'abandon de tous les processus MPI connectés.
  • MPI_ERRORS_ABORT Un gestionnaire d'erreurs qui peut être invoqué sur un communicateur, une fenêtre, un fichier ou une session. Lorsqu'il est appelé sur un communicateur, il agit comme si MPI_Abort avait été appelé sur ce communicateur. S'il est appelé sur une fenêtre ou un fichier, il agit comme si MPI_Abort avait été appelé sur un communicateur contenant le groupe de processus dans la fenêtre ou le fichier correspondant. S'il est appelé sur une session, il n'abandonne que le processus local.
  • MPI_ERRORS_RETURN Renvoie un code d'erreur à l'application.

Les applications MPI peuvent également implémenter leurs propres gestionnaires d'erreurs en appelant :

  • MPI_Comm_create_errhandler puis MPI_Comm_set_errhandler
  • MPI_File_create_errhandler puis MPI_File_set_errhandler
  • MPI_Session_create_errhandler puis MPI_Session_set_errhandler ou à MPI_Session_init
  • MPI_Win_create_errhandler puis MPI_Win_set_errhandler

Notez que MPI ne garantit pas qu'un programme MPI puisse continuer après une erreur.

Voir la page man MPI pour une liste complète des codes d'erreur MPI.

Voir la section Gestion des erreurs de la norme MPI-3.1 pour plus d'informations.
