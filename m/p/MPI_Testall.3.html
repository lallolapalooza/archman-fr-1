MPI_TESTALL(3) Open MPI MPI_TESTALL(3)

MPI_Testall — Teste l'achèvement de toutes les communications précédemment initiées dans une liste.

SYNTAXE

Syntaxe C

#include <mpi.h>
int MPI_Testall(int count, MPI_Request array_of_requests[],
     int *flag, MPI_Status array_of_statuses[])

Syntaxe Fortran

USE MPI
! ou la forme plus ancienne : INCLUDE 'mpif.h'
MPI_TESTALL(COUNT, ARRAY_OF_REQUESTS, FLAG, ARRAY_OF_STATUSES,
             IERROR)
     LOGICAL FLAG
     INTEGER COUNT, ARRAY_OF_REQUESTS(*)
     INTEGER ARRAY_OF_STATUSES(MPI_STATUS_SIZE,*), IERROR

Syntaxe Fortran 2008

USE mpi_f08
MPI_Testall(count, array_of_requests, flag, array_of_statuses, ierror)
     INTEGER, INTENT(IN) :: count
     TYPE(MPI_Request), INTENT(INOUT) :: array_of_requests(count)
     LOGICAL, INTENT(OUT) :: flag
     TYPE(MPI_Status) :: array_of_statuses(*)
     INTEGER, OPTIONAL, INTENT(OUT) :: ierror

PARAMÈTRES D'ENTRÉE

  • count : Longueur de la liste (entier).
  • array_of_requests : Tableau de requêtes (tableau de handles).

PARAMÈTRES DE SORTIE

  • flag : Vrai si les communications précédemment initiées sont terminées (logique).
  • array_of_statuses : Tableau d'objets de statut (tableau de statuts).
  • ierror : Fortran uniquement : Statut d'erreur (entier).

DESCRIPTION

Retourne flag = vrai si toutes les communications associées aux handles actifs dans le tableau sont terminées (cela inclut le cas où aucun handle dans la liste n'est actif). Dans ce cas, chaque entrée de statut correspondant à une requête de handle actif est définie avec le statut de la communication correspondante ; si la requête a été allouée par un appel de communication non bloquante, elle est désallouée et le handle est défini sur MPI_REQUEST_NULL. Chaque entrée de statut correspondant à un handle nul ou inactif est définie comme vide.

Sinon, flag = faux est retourné, aucune requête n'est modifiée et les valeurs des entrées de statut sont indéfinies. Il s'agit d'une opération locale.

Si votre application n'a pas besoin d'examiner le champ array_of_statuses, vous pouvez économiser des ressources en utilisant la constante prédéfinie MPI_STATUSES_IGNORE, qui peut être utilisée comme une valeur spéciale pour l'argument array_of_statuses.

Les erreurs qui se produisent pendant l'exécution de MPI_Testall sont gérées de la même manière que les erreurs dans MPI_Waitall.

NOTE

flag est vrai seulement si toutes les requêtes sont terminées. Sinon, flag est faux, et ni array_of_requests ni array_of_statuses ne sont modifiés.

ERREURS

Presque toutes les routines MPI retournent une valeur d'erreur ; les routines C comme résultat de la fonction et les routines Fortran dans le dernier argument.

Avant que la valeur d'erreur ne soit retournée, le gestionnaire d'erreurs MPI actuel associé à l'objet de communication (par exemple, communicateur, fenêtre, fichier) est appelé. Si aucun objet de communication n'est associé à l'appel MPI, l'appel est considéré comme attaché à MPI_COMM_SELF et appellera le gestionnaire d'erreurs MPI associé. Lorsque MPI_COMM_SELF n'est pas initialisé (c'est-à-dire avant MPI_Init/MPI_Init_thread, après MPI_Finalize, ou lors de l'utilisation exclusive du modèle Sessions), l'erreur déclenche le gestionnaire d'erreurs initial. Le gestionnaire d'erreurs initial peut être modifié en appelant MPI_Comm_set_errhandler sur MPI_COMM_SELF lors de l'utilisation du modèle World, ou l'argument de ligne de commande mpi_initial_errhandler de mpiexec ou la clé d'information de MPI_Comm_spawn/MPI_Comm_spawn_multiple. Si aucun autre gestionnaire d'erreurs approprié n'a été défini, alors le gestionnaire d'erreurs MPI_ERRORS_RETURN est appelé pour les fonctions d'E/S MPI et le gestionnaire d'erreurs MPI_ERRORS_ABORT est appelé pour toutes les autres fonctions MPI.

Open MPI inclut trois gestionnaires d'erreurs prédéfinis qui peuvent être utilisés :

  • MPI_ERRORS_ARE_FATAL Provoque l'arrêt du programme pour tous les processus MPI connectés.
  • MPI_ERRORS_ABORT Un gestionnaire d'erreurs qui peut être invoqué sur un communicateur, une fenêtre, un fichier ou une session. Lorsqu'il est appelé sur un communicateur, il agit comme si MPI_Abort avait été appelé sur ce communicateur. S'il est appelé sur une fenêtre ou un fichier, il agit comme si MPI_Abort avait été appelé sur un communicateur contenant le groupe des processus de la fenêtre ou du fichier correspondant. S'il est appelé sur une session, il n'arrête que le processus local.
  • MPI_ERRORS_RETURN Retourne un code d'erreur à l'application.

Les applications MPI peuvent également implémenter leurs propres gestionnaires d'erreurs en appelant :

  • MPI_Comm_create_errhandler puis MPI_Comm_set_errhandler
  • MPI_File_create_errhandler puis MPI_File_set_errhandler
  • MPI_Session_create_errhandler puis MPI_Session_set_errhandler ou à MPI_Session_init
  • MPI_Win_create_errhandler puis MPI_Win_set_errhandler

Notez que MPI ne garantit pas qu'un programme MPI puisse continuer après une erreur.

Voir la page de manuel MPI pour une liste complète des codes d'erreur MPI.

Voir la section Gestion des erreurs de la norme MPI-3.1 pour plus d'informations.

Pour chaque invocation de MPI_Testall, si une ou plusieurs requêtes génèrent une erreur MPI, seule la première requête MPI qui a causé une erreur sera passée à son gestionnaire d'erreurs correspondant. Aucun autre gestionnaire d'erreurs ne sera invoqué (même si plusieurs requêtes ont généré des erreurs). Cependant, toutes les requêtes qui génèrent une erreur auront un code d'erreur pertinent défini dans le champ status.MPI_ERROR correspondant (sauf si MPI_STATUSES_IGNORE a été utilisé).

Si le gestionnaire d'erreurs invoqué permet à MPI_Testall de retourner à l'appelant, la valeur MPI_ERR_IN_STATUS sera retournée dans les liaisons C et Fortran.
