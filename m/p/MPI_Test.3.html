MPI_TEST(3) Open MPI MPI_TEST(3)

MPI_Test — Teste l'achèvement d'un envoi ou d'une réception spécifique.

SYNTAX

Syntaxe C

#include <mpi.h>
int MPI_Test(MPI_Request *request, int *flag, MPI_Status *status)

Syntaxe Fortran

USE MPI
! ou l'ancienne forme : INCLUDE 'mpif.h'
MPI_TEST(REQUEST, FLAG, STATUS, IERROR)
     LOGICAL FLAG
     INTEGER REQUEST, STATUS(MPI_STATUS_SIZE), IERROR

Syntaxe Fortran 2008

USE mpi_f08
MPI_Test(request, flag, status, ierror)
     TYPE(MPI_Request), INTENT(INOUT) :: request
     LOGICAL, INTENT(OUT) :: flag
     TYPE(MPI_Status) :: status
     INTEGER, OPTIONAL, INTENT(OUT) :: ierror

PARAMÈTRE D'ENTRÉE

•
request : Requête de communication (descripteur).

PARAMÈTRES DE SORTIE

  • flag : Vrai si l'opération est terminée (logique).
  • status : Objet de statut (statut).
  • ierror : Fortran uniquement : Statut d'erreur (entier).

DESCRIPTION

Un appel à MPI_Test renvoie flag = vrai si l'opération identifiée par request est terminée. Dans ce cas, l'objet de statut est défini pour contenir des informations sur l'opération terminée ; si l'objet de communication a été créé par un envoi ou une réception non bloquante, il est alors désalloué et le descripteur de requête est défini sur MPI_REQUEST_NULL. L'appel renvoie flag = faux, sinon. Dans ce cas, la valeur de l'objet de statut est indéfinie. MPI_Test est une opération locale.

L'objet de statut de retour pour une opération de réception contient des informations qui peuvent être accessibles comme décrit dans la sous-section « Statut de retour » du chapitre « Communication point à point » de la Norme MPI. L'objet de statut pour une opération d'envoi contient des informations qui peuvent être accessibles par un appel à MPI_Test_cancelled (voir la section « Sondage et Annulation » de la Norme MPI).

Si votre application n'a pas besoin d'examiner le champ status, vous pouvez économiser des ressources en utilisant la constante prédéfinie MPI_STATUS_IGNORE comme valeur spéciale pour l'argument status.

Il est permis d'appeler MPI_Test avec un argument request nul ou inactif. Dans un tel cas, l'opération renvoie avec flag = vrai et un status vide.

Les fonctions MPI_Wait et MPI_Test peuvent être utilisées pour compléter les envois et les réceptions.

NOTES

L'utilisation de l'appel MPI_Test non bloquant permet à l'utilisateur de planifier des activités alternatives au sein d'un seul fil d'exécution. Un ordonnanceur de fils d'exécution événementiel peut être émulé avec des appels périodiques à MPI_Test.

ERREURS

Presque toutes les routines MPI renvoient une valeur d'erreur ; les routines C comme résultat de retour de la fonction et les routines Fortran dans le dernier argument.

Avant que la valeur d'erreur ne soit renvoyée, le gestionnaire d'erreurs MPI actuel associé à l'objet de communication (par exemple, communicateur, fenêtre, fichier) est appelé. Si aucun objet de communication n'est associé à l'appel MPI, alors l'appel est considéré comme attaché à MPI_COMM_SELF et appellera le gestionnaire d'erreurs MPI associé. Lorsque MPI_COMM_SELF n'est pas initialisé (c'est-à-dire avant MPI_Init/MPI_Init_thread, après MPI_Finalize, ou lors de l'utilisation exclusive du modèle de sessions) l'erreur déclenche le gestionnaire d'erreurs initial. Le gestionnaire d'erreurs initial peut être modifié en appelant MPI_Comm_set_errhandler sur MPI_COMM_SELF lors de l'utilisation du modèle World, ou l'argument de ligne de commande mpi_initial_errhandler à mpiexec ou la clé d'information à MPI_Comm_spawn/MPI_Comm_spawn_multiple. Si aucun autre gestionnaire d'erreurs approprié n'a été défini, alors le gestionnaire d'erreurs MPI_ERRORS_RETURN est appelé pour les fonctions d'E/S MPI et le gestionnaire d'erreurs MPI_ERRORS_ABORT est appelé pour toutes les autres fonctions MPI.

Open MPI inclut trois gestionnaires d'erreurs prédéfinis qui peuvent être utilisés :

  • MPI_ERRORS_ARE_FATAL Provoque l'arrêt du programme pour tous les processus MPI connectés.
  • MPI_ERRORS_ABORT Un gestionnaire d'erreurs qui peut être invoqué sur un communicateur, une fenêtre, un fichier ou une session. Lorsqu'il est appelé sur un communicateur, il agit comme si MPI_Abort avait été appelé sur ce communicateur. S'il est appelé sur une fenêtre ou un fichier, il agit comme si MPI_Abort avait été appelé sur un communicateur contenant le groupe de processus dans la fenêtre ou le fichier correspondant. S'il est appelé sur une session, il n'interrompt que le processus local.
  • MPI_ERRORS_RETURN Renvoie un code d'erreur à l'application.

Les applications MPI peuvent également implémenter leurs propres gestionnaires d'erreurs en appelant :

  • MPI_Comm_create_errhandler puis MPI_Comm_set_errhandler
  • MPI_File_create_errhandler puis MPI_File_set_errhandler
  • MPI_Session_create_errhandler puis MPI_Session_set_errhandler ou à MPI_Session_init
  • MPI_Win_create_errhandler puis MPI_Win_set_errhandler

Notez que MPI ne garantit pas qu'un programme MPI puisse continuer après une erreur.

Voir la page de manuel MPI pour une liste complète des codes d'erreur MPI.

Voir la section Gestion des erreurs de la norme MPI-3.1 pour plus d'informations.

Notez que conformément à la section « Statut de retour » du chapitre « Communication point à point » de la Norme MPI, les erreurs MPI sur les requêtes passées à MPI_Test ne définissent pas le champ status.MPI_ERROR dans le status renvoyé. Le code d'erreur est toujours passé au gestionnaire d'erreurs backend et peut être renvoyé à l'appelant via la valeur de retour de MPI_Test si le gestionnaire d'erreurs backend le renvoie. Le gestionnaire d'erreurs MPI prédéfini MPI_ERRORS_RETURN présente ce comportement, par exemple.
