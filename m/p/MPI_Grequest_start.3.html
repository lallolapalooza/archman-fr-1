MPI_Grequest_start(3) Open MPI MPI_Grequest_start(3)

MPI_Grequest_start — Démarre une requête généralisée et retourne un handle vers celle-ci dans request.

SYNTAXE

Syntaxe C

#include <mpi.h>
int MPI_Grequest_start(MPI_Grequest_query_function *query_fn,
    MPI_Grequest_free_function *free_fn,
    MPI_Grequest_cancel_function *cancel_fn, void *extra_state,
    MPI_Request *request)

Syntaxe Fortran

USE MPI
! ou la forme plus ancienne : INCLUDE 'mpif.h'
MPI_GREQUEST_START(QUERY_FN, FREE_FN, CANCEL_FN, EXTRA_STATE,
    REQUEST, IERROR)
    INTEGER REQUEST, IERROR
    EXTERNAL QUERY_FN, FREE_FN, CANCEL_FN
      INTEGER(KIND=MPI_ADDRESS_KIND) EXTRA_STATE

Syntaxe Fortran 2008

USE mpi_f08
MPI_Grequest_start(query_fn, free_fn, cancel_fn, extra_state, request,
        ierror)
    PROCEDURE(MPI_Grequest_query_function) :: query_fn
    PROCEDURE(MPI_Grequest_free_function) :: free_fn
    PROCEDURE(MPI_Grequest_cancel_function) :: cancel_fn
    INTEGER(KIND=MPI_ADDRESS_KIND), INTENT(IN) :: extra_state
    TYPE(MPI_Request), INTENT(OUT) :: request
    INTEGER, OPTIONAL, INTENT(OUT) :: ierror

PARAMÈTRES D'ENTRÉE

•
query_fn
Fonction de rappel invoquée lorsque le statut de la requête est interrogé (fonction).
•
free_fn
Fonction de rappel invoquée lorsque la requête est libérée (fonction).
•
cancel_fn
Fonction de rappel invoquée lorsque la requête est annulée (fonction).
•
extra_state : État supplémentaire.

PARAMÈTRES DE SORTIE

  • request : Requête généralisée (handle).
  • ierror : Fortran uniquement : Statut d'erreur (entier).

DESCRIPTION

MPI_Grequest_start démarre une request généralisée et retourne un handle vers celle-ci dans request.

La syntaxe et la signification des fonctions de rappel sont listées ci-dessous. Toutes les fonctions de rappel reçoivent l'argument extra_state qui a été associé à la request par l'appel de démarrage MPI_Grequest_start. Cela peut être utilisé pour maintenir un état défini par l'utilisateur pour la request. En C, la fonction de requête est

typedef int MPI_Grequest_query_function(void *extra_state,
    MPI_Status *status);

En Fortran, c'est

SUBROUTINE GREQUEST_QUERY_FUNCTION(EXTRA_STATE, STATUS, IERROR)
    INTEGER STATUS(MPI_STATUS_SIZE), IERROR
    INTEGER(KIND=MPI_ADDRESS_KIND) EXTRA_STATE

La fonction query_fn calcule le statut qui doit être retourné pour la requête généralisée. Le statut inclut également des informations sur l'annulation réussie/non réussie de la requête (résultat à retourner par MPI_Test_cancelled).

La fonction query_fn est invoquée par l'appel MPI_{Wait|Test}{any|some|all} qui a complété la requête généralisée associée à cette fonction de rappel. La fonction de rappel est également invoquée par les appels à MPI_Request_get_status si la requête est complète lorsque l'appel se produit. Dans les deux cas, la fonction de rappel reçoit une référence à la variable de statut correspondante passée par l'utilisateur à l'appel MPI. Si l'utilisateur a fourni MPI_STATUS_IGNORE ou MPI_STATUSES_IGNORE à la fonction MPI qui provoque l'appel de query_fn, alors MPI passera un objet statut valide à query_fn, et ce statut sera ignoré au retour de la fonction de rappel. Notez que query_fn n'est invoquée qu'après que MPI_Grequest_complete a été appelée sur la requête ; elle peut être invoquée plusieurs fois pour la même requête généralisée. Notez également qu'un appel à MPI_{Wait|Test}{some|all} peut provoquer plusieurs invocations des fonctions de rappel query_fn, une pour chaque requête généralisée qui est complétée par l'appel MPI. L'ordre de ces invocations n'est pas spécifié par MPI.

En C, la fonction de libération est

typedef int MPI_Grequest_free_function(void *extra_state);

Et en Fortran, c'est

SUBROUTINE GREQUEST_FREE_FUNCTION(EXTRA_STATE, IERROR)
    INTEGER IERROR
    INTEGER(KIND=MPI_ADDRESS_KIND) EXTRA_STATE

La fonction de rappel free_fn est invoquée pour nettoyer les ressources allouées par l'utilisateur lorsque la requête généralisée est libérée.

La fonction free_fn est invoquée par l'appel MPI_{Wait|Test}{any|some|all} qui a complété la requête généralisée associée à cette fonction de rappel. free_fn est invoquée après l'appel à query_fn pour la même requête. Cependant, si l'appel MPI a complété plusieurs requêtes généralisées, l'ordre dans lequel les fonctions de rappel free_fn sont invoquées n'est pas spécifié par MPI.

La fonction de rappel free_fn est également invoquée pour les requêtes généralisées qui sont libérées par un appel à MPI_Request_free (aucun appel à MPI_{Wait|Test}{any|some|all} ne se produira pour une telle requête). Dans ce cas, la fonction de rappel sera appelée soit dans l'appel MPI MPI_Request_free(request), soit dans l'appel MPI MPI_Grequest_complete(request), le dernier des deux arrivant. Autrement dit, dans ce cas, le code de libération réel est exécuté dès que les deux appels (MPI_Request_free et MPI_Grequest_complete) ont eu lieu. La request n'est pas désallouée avant que free_fn n'ait terminé. Notez que free_fn ne sera invoquée qu'une seule fois par requête par un programme correct.

En C, la fonction d'annulation est

typedef int MPI_Grequest_cancel_function(void *extra_state, int complete);

En Fortran, la fonction d'annulation est

SUBROUTINE GREQUEST_CANCEL_FUNCTION(EXTRA_STATE, COMPLETE, IERROR)
     INTEGER IERROR
     INTEGER(KIND=MPI_ADDRESS_KIND) EXTRA_STATE
     LOGICAL COMPLETE

La fonction cancel_fn est invoquée pour démarrer l'annulation d'une requête généralisée. Elle est appelée par MPI_Request_cancel(request). MPI passe à la fonction de rappel complete=true si MPI_Grequest_complete a déjà été appelée sur la requête, et complete=false sinon.

ERREURS

Presque toutes les routines MPI retournent une valeur d'erreur ; les routines C comme résultat de la fonction et les routines Fortran dans le dernier argument.

Avant que la valeur d'erreur ne soit retournée, le gestionnaire d'erreurs MPI actuel associé à l'objet de communication (par exemple, communicateur, fenêtre, fichier) est appelé. Si aucun objet de communication n'est associé à l'appel MPI, alors l'appel est considéré comme attaché à MPI_COMM_SELF et appellera le gestionnaire d'erreurs MPI associé. Lorsque MPI_COMM_SELF n'est pas initialisé (c'est-à-dire, avant MPI_Init/MPI_Init_thread, après MPI_Finalize, ou lors de l'utilisation exclusive du modèle de sessions), l'erreur déclenche le gestionnaire d'erreurs initial. Le gestionnaire d'erreurs initial peut être modifié en appelant MPI_Comm_set_errhandler sur MPI_COMM_SELF lors de l'utilisation du modèle World, ou par l'argument CLI mpi_initial_errhandler à mpiexec ou une clé d'information à MPI_Comm_spawn/MPI_Comm_spawn_multiple. Si aucun autre gestionnaire d'erreurs approprié n'a été défini, alors le gestionnaire d'erreurs MPI_ERRORS_RETURN est appelé pour les fonctions d'E/S MPI et le gestionnaire d'erreurs MPI_ERRORS_ABORT est appelé pour toutes les autres fonctions MPI.

Open MPI inclut trois gestionnaires d'erreurs prédéfinis qui peuvent être utilisés :

  • MPI_ERRORS_ARE_FATAL Provoque l'abandon du programme de tous les processus MPI connectés.
  • MPI_ERRORS_ABORT Une err

    Toutes les fonctions de rappel renvoient un code d'erreur. Le code est renvoyé et géré de manière appropriée pour le code d'erreur par la fonction MPI qui a appelé la fonction de rappel. Par exemple, si des codes d'erreur sont renvoyés, le code d'erreur renvoyé par la fonction de rappel sera renvoyé par la fonction MPI qui a appelé la fonction de rappel. Dans le cas d'un appel MPI_{Wait|Test}any qui appelle à la fois query_fn et free_fn, l'appel MPI renverra le code d'erreur renvoyé par le dernier rappel, à savoir free_fn. Si une ou plusieurs des requêtes dans un appel à ``MPI_{Wait|Test}{some|all} ont échoué, alors l'appel MPI renverra MPI_ERR_IN_STATUS. Dans un tel cas, si l'appel MPI a reçu un tableau de statuts, alors MPI renverra dans chacun des statuts correspondant à une requête généralisée terminée le code d'erreur renvoyé par l'invocation correspondante de sa fonction de rappel free_fn. Cependant, si la fonction MPI a reçu MPI_STATUSES_IGNORE, alors les codes d'erreur individuels renvoyés par chaque fonction de rappel seront perdus.
