MPI_Scatterv, MPI_Iscatterv, MPI_Scatterv_init - Disperse un tampon en parties à toutes les tâches d'un groupe.

PARAMÈTRES D'ENTRÉE

  • sendbuf: Adresse du tampon d'envoi (choix, significatif uniquement à la racine).
  • sendcounts: Tableau d'entiers (de taille égale à la taille du groupe) spécifiant le nombre d'éléments à envoyer à chaque processeur.
  • displs: Tableau d'entiers (de taille égale à la taille du groupe). L'entrée i spécifie le décalage (par rapport à sendbuf) à partir duquel prendre les données sortantes pour le processeur i.
  • sendtype: Type de données des éléments du tampon d'envoi (handle).
  • recvcount: Nombre d'éléments dans le tampon de réception (entier).
  • recvtype: Type de données des éléments du tampon de réception (handle).
  • root: Rang du processus d'envoi (entier).
  • comm: Communicateur (handle).
  • info: Info (handle, seulement persistant).

PARAMÈTRES DE SORTIE

  • recvbuf: Adresse du tampon de réception (choix).
  • request: Requête (handle, seulement non-bloquant).
  • ierror: Fortran seulement : Statut d'erreur (entier).

DESCRIPTION

MPI_Scatterv est l'opération inverse de MPI_Gatherv.

MPI_Scatterv étend les fonctionnalités de MPI_Scatter en permettant un nombre variable de données à envoyer à chaque processus, puisque sendcounts est maintenant un tableau. Il offre également plus de flexibilité quant à l'endroit où les données sont extraites de la racine, en fournissant le nouveau paramètre, displs.

Le résultat est comme si la racine exécutait n opérations d'envoi,

MPI_Send(sendbuf + displs[i] * extent(sendtype),
         sendcounts[i], sendtype, i, ...);
// et chaque processus exécutait une réception,
MPI_Recv(recvbuf, recvcount, recvtype, root, ...)

Le tampon d'envoi est ignoré pour tous les processus non-racines.

La signature de type implicite par sendcount[i], sendtype à la racine doit être égale à la signature de type implicite par recvcount, recvtype au processus i (cependant, les cartes de type peuvent être différentes). Cela implique que la quantité de données envoyées doit être égale à la quantité de données reçues, par paires entre chaque processus et la racine. Des cartes de type distinctes entre l'expéditeur et le récepteur sont toujours autorisées.

Tous les arguments de la fonction sont significatifs sur le processus root, tandis que sur les autres processus, seuls les arguments recvbuf, recvcount, recvtype, root, comm sont significatifs. Les arguments root et comm doivent avoir des valeurs identiques sur tous les processus.

La spécification des comptes, types et décalages ne doit pas provoquer la lecture d'un même emplacement de la racine plus d'une fois.

Exemple 1 : L'inverse de l'Exemple 5 de la page de manuel MPI_Gatherv. Nous avons un pas variable entre les blocs du côté d'envoi (racine), du côté de réception nous recevons 100 - i éléments dans la i-ème colonne d'un tableau C 100 x 150 au processus i.

MPI_Comm comm;
int gsize,recvarray[100][150],*rptr;
int root, *sendbuf, myrank, bufsize, *stride;
MPI_Datatype rtype;
int i, *displs, *scounts, offset;
...
MPI_Comm_size( comm, &gsize);
MPI_Comm_rank( comm, &myrank );
stride = (int *)malloc(gsize*sizeof(int));
...
/* stride[i] pour i = 0 à gsize-1 est défini quelque part
 * sendbuf provient d'ailleurs
 */
...
displs = (int *)malloc(gsize*sizeof(int));
scounts = (int *)malloc(gsize*sizeof(int));
offset = 0;
for (i=0; i<gsize; ++i) {
    displs[i] = offset;
    offset += stride[i];
    scounts[i] = 100 - i;
}
/* Créer le type de données pour la colonne que nous recevons
 */
MPI_Type_vector( 100-myrank, 1, 150, MPI_INT, &rtype);
MPI_Type_commit( &rtype );
rptr = &recvarray[0][myrank];
MPI_Scatterv(sendbuf, scounts, displs, MPI_INT,
             rptr, 1, rtype, root, comm);

Exemple 2 : L'inverse de l'Exemple 1 de la page de manuel MPI_Gather. Le processus racine disperse des ensembles de 100 entiers aux autres processus, mais les ensembles de 100 sont séparés par un pas d'entiers dans le tampon d'envoi. Nécessite l'utilisation de MPI_Scatterv, où stride >= 100.

MPI_Comm comm;
int gsize,*sendbuf;
int root, rbuf[100], i, *displs, *scounts;
...
MPI_Comm_size(comm, &gsize);
sendbuf = (int *)malloc(gsize*stride*sizeof(int));
...
displs = (int *)malloc(gsize*sizeof(int));
scounts = (int *)malloc(gsize*sizeof(int));
for (i=0; i<gsize; ++i) {
   displs[i] = i*stride;
   scounts[i] = 100;
}
MPI_Scatterv(sendbuf, scounts, displs, MPI_INT,
             rbuf, 100, MPI_INT, root, comm);

UTILISATION DE L'OPTION IN-PLACE

Lorsque le communicateur est un intracommunicateur, vous pouvez effectuer une opération de dispersion en place (le tampon de sortie est utilisé comme tampon d'entrée). Utilisez la variable MPI_IN_PLACE comme valeur du recvbuf du processus racine. Dans ce cas, recvcount et recvtype sont ignorés, et le processus racine n'envoie aucune donnée à lui-même.

ERREURS

La plupart des routines MPI renvoient une valeur d'erreur ; les routines C renvoient le résultat de la fonction et les routines Fortran ont l'argument final.

Avant que la valeur d'erreur ne soit renvoyée, le gestionnaire d'erreurs associé à l'objet de communication (par exemple, communicateur, fenêtre, fichier) associé à l'appel est appelé. S'il n'y a pas d'objet de communication associé à l'appel MPI, l'appel est considéré comme associé à MPI_COMM_SELF et le gestionnaire associé à MPI_COMM_SELF est appelé. Lorsque MPI_COMM_SELF n'est pas initialisé (c'est-à-dire avant MPI_Init/MPI_Init_thread, après MPI_Finalize, ou lorsqu'on utilise uniquement le Modèle de Session), l'erreur déclenche le gestionnaire d'erreur initial. Le gestionnaire d'erreur initial peut être modifié en appelant MPI_Comm_set_errhandler sur MPI_COMM_SELF lors de l'utilisation du Modèle du Monde, ou à l'argument mpi_initial_errhandler de mpiexec ou à la clé d'information de MPI_Comm_spawn/MPI_Comm_spawn_multiple. S'il n'y a pas d'autre gestionnaire d'erreur approprié configuré, le gestionnaire MPI_ERRORS_RETURN est appelé pour les fonctions d'E/S MPI et le gestionnaire MPI_ERRORS_ABORT pour toutes les autres fonctions MPI.

Open MPI inclut trois gestionnaires d'erreurs prédéfinis qui peuvent être utilisés :

  • MPI_ERRORS_ARE_FATAL Déclenche une terminaison de processus pour tous les processus connectés.
  • MPI_ERRORS_ABORT Un gestionnaire d'erreurs qui peut être invoqué sur un communicateur, une fenêtre, un fichier ou une session. Lorsqu'il est invoqué sur un communicateur, il agit comme si MPI_Abort avait été appelé sur ce communicateur. S'il est invoqué sur une fenêtre ou un fichier, il agit comme si MPI_Abort avait été appelé sur un communicateur contenant le groupe de processus correspondant. S'il est invoqué sur une session, il abandonne uniquement le processus local.
  • MPI_ERRORS_RETURN Renvoie un code d'erreur à l'application.

Les applications MPI peuvent également implémenter leurs propres gestionnaires d'erreurs en appelant :

  • MPI_Comm_create_errhandler puis MPI_Comm_set_errhandler
  • MPI_File_create_errhandler puis MPI_File_set_errhandler
  • MPI_Session_create_errhandler puis MPI_Session_set_errhandler ou dans MPI_Session_init
  • MPI_Win_create_errhandler puis MPI_Win_set_errhandler

Remarque : MPI ne garantit pas qu'un programme MPI puisse continuer après une erreur.

Voir la section de gestion des erreurs de la norme MPI-3.1 pour plus d'informations.
