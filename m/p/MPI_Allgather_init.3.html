MPI_Allgather, MPI_Iallgather, MPI_Allgather_init - Collectent des données de tous les processus et les distribuent à tous les processus

Paramètres d'entrée

  • sendbuf: Adresse de début du tampon d'envoi (facultatif).
  • sendcount: Nombre d'éléments dans le tampon d'envoi (entier).
  • sendtype: Type de données des éléments du tampon d'envoi (handle).
  • recvbuf: Adresse de début du tampon de réception (facultatif).
  • recvcount: Nombre d'éléments reçus de n'importe quel processus (entier).
  • recvtype: Type de données des éléments du tampon de réception (handle).
  • comm: Communicateur (handle).
  • info: Informations (handle, persistant).

Paramètres de sortie

  • recvbuf: Adresse du tampon de réception (facultatif).
  • request: Requête (handle, non bloquant).
  • ierror: En Fortran uniquement : statut d'erreur (entier).

Description

MPI_Allgather est similaire à MPI_Gather, sauf que tous les processus reçoivent le résultat, au lieu d'un seul processus racine. En d'autres termes, tous les processus contribuent au résultat et tous les processus reçoivent le résultat.

La signature de type associée à sendcount, sendtype sur un processus doit être identique à la signature de type associée à recvcount, recvtype sur tout autre processus.

Le résultat d'un appel à MPI_Allgather est identique à ce que tous les processus auraient obtenu en exécutant n appels à

MPI_Gather(sendbuf, sendcount, sendtype, recvbuf, recvcount,
           recvtype, root, comm);
// pour root = 0, ..., n-1.

Les règles pour utiliser correctement MPI_Allgather peuvent être facilement déduites des règles correspondantes à MPI_Gather.

Exemple : Version all-gather de l'exemple 1 dans MPI_Gather. En utilisant MPI_Allgather, nous allons collecter 100 entiers de chaque processus du groupe vers chaque processus.

MPI_Comm comm;
int gsize,sendarray[100];
int *rbuf;
...
MPI_Comm_size( comm, &gsize);
rbuf = (int *)malloc(gsize*100*sizeof(int));
MPI_Allgather( sendarray, 100, MPI_INT, rbuf, 100, MPI_INT, comm);

Après l'appel, chaque processus détient la concaténation des données de l'ensemble de données de tous les processus.

Utilisation de l'option in-place

Lorsque le communicateur est un communicateur inter-groupe, vous pouvez effectuer une opération all-gather en place (le tampon de réception est utilisé comme tampon d'envoi). Utilisez la variable MPI_IN_PLACE comme valeur de sendbuf. Dans ce cas, sendcount et sendtype sont ignorés. Les données d'entrée de chaque processus sont supposées se trouver dans la zone où ce processus recevra sa propre contribution au tampon de réception. Plus précisément, le résultat d'un appel à MPI_Allgather qui a utilisé l'option in-place est identique à celui obtenu lorsque tous les processus ont exécuté n appels à

MPI_Allgather( MPI_IN_PLACE, 0, MPI_DATATYPE_NULL, recvbuf,
               recvcount, recvtype, root, comm )
// pour root =0, ... , n-1.

Remarque : MPI_IN_PLACE est une valeur spéciale ; elle a les mêmes restrictions d'utilisation que MPI_BOTTOM.

Étant donné que l'option in-place transforme le tampon de réception en un tampon d'envoi et de réception, une liaison Fortran qui inclut INTENT doit les marquer comme INOUT, et non comme OUT.

Quand le communicateur est un communicateur inter-groupe

Lorsque le communicateur est un communicateur inter-groupe, l'opération de regroupement se déroule en deux phases. Les données sont collectées auprès de tous les membres du premier groupe et envoyées à tous les membres du second groupe. Ensuite, les données sont collectées auprès de tous les membres du second groupe et envoyées à tous les membres du premier. L'opération, cependant, ne doit pas nécessairement être symétrique. Le nombre d'éléments envoyés par les processus du premier groupe n'a pas besoin d'être égal au nombre d'éléments envoyés par les processus du second groupe. Vous pouvez déplacer des données dans une seule direction en donnant à sendcount une valeur de 0 pour la communication dans le sens inverse.

Erreurs

La plupart des routines MPI retournent une valeur d'erreur ; le résultat de la fonction en C et l'argument final en Fortran.

Avant de retourner la valeur d'erreur, le gestionnaire d'erreurs associé à l'objet de communication (par exemple, communicateur, fenêtre, fichier) est appelé. S'il n'y a pas d'objet de communication associé à l'appel MPI, l'appel est considéré comme associé à MPI_COMM_SELF et appellera le gestionnaire d'erreurs associé à MPI_COMM_SELF. Lorsque MPI_COMM_SELF n'est pas initialisé (c'est-à-dire avant MPI_Init/MPI_Init_thread, après MPI_Finalize, ou lorsque le modèle de Sessions est utilisé exclusivement), l'erreur déclenche le gestionnaire d'erreurs initial. Le gestionnaire d'erreurs initial peut être modifié en appelant MPI_Comm_set_errhandler sur MPI_COMM_SELF lorsque le modèle du Monde est utilisé, ou via l'argument mpi_initial_errhandler de mpiexec ou la clé d'information de MPI_Comm_spawn/MPI_Comm_spawn_multiple. S'il n'y a pas d'autre gestionnaire d'erreurs approprié, le gestionnaire d'erreurs MPI_ERRORS_RETURN est appelé pour les opérations d'E/S.

SYNTAXE

La syntaxe du gestionnaire d'erreurs est la suivante :

  • MPI_Comm_create_errhandler puis MPI_Comm_set_errhandler
  • MPI_File_create_errhandler puis MPI_File_set_errhandler
  • MPI_Session_create_errhandler puis MPI_Session_set_errhandler ou à MPI_Session_init
  • MPI_Win_create_errhandler puis MPI_Win_set_errhandler

Note : MPI ne garantit pas qu'un programme MPI puisse continuer après une erreur.

Voir la section MPI man page pour une liste complète des MPI error codes.

Voir la section Error Handling de la norme MPI-3.1 pour plus d'informations.

DESCRIPTION

Description des gestionnaires d'erreurs :

  • MPI_ERRORS_ARE_FATAL Désactive la gestion des erreurs dans le programme, en abrogeant tous les processus MPI connectés.
  • MPI_ERRORS_ABORT Gestionnaire d'erreurs appelable sur un communicateur, une fenêtre, un fichier ou une session. Lorsqu'il est appelé sur un communicateur, il agit comme si MPI_Abort avait été appelé sur ce communicateur. S'il est appelé sur une fenêtre ou un fichier, il agit comme si MPI_Abort avait été appelé sur un communicateur contenant les processus dans la fenêtre ou le fichier correspondant. S'il est appelé sur une session, il abroge uniquement le processus local.
  • MPI_ERRORS_RETURN Renvoie le code d'erreur à l'application.

UTILISATION DE L'OPTION EN-PLACE

Utilisation de l'option en-place :

  • MPI_Comm_create_errhandler puis MPI_Comm_set_errhandler
  • MPI_File_create_errhandler puis MPI_File_set_errhandler
  • MPI_Session_create_errhandler puis MPI_Session_set_errhandler ou à MPI_Session_init
  • MPI_Win_create_errhandler puis MPI_Win_set_errhandler

QUAND LE COMMUNICATEUR EST UN INTER-COMMUNICATEUR

Lorsque le communicateur est un inter-communicateur :

  • MPI_Comm_create_errhandler puis MPI_Comm_set_errhandler
  • MPI_File_create_errhandler puis MPI_File_set_errhandler
  • MPI_Session_create_errhandler puis MPI_Session_set_errhandler ou à MPI_Session_init
  • MPI_Win_create_errhandler puis MPI_Win_set_errhandler

ERREURS

Erreurs :

  • MPI_ERRORS_ARE_FATAL Provoque l'interruption de tous les processus MPI connectés par le programme.
  • MPI_ERRORS_ABORT Gestionnaire d'erreurs appelable sur un communicateur, une fenêtre, un fichier ou une session. Lorsqu'il est appelé sur un communicateur, il agit comme si MPI_Abort avait été appelé sur ce communicateur. S'il est appelé sur une fenêtre ou un fichier, il agit comme si MPI_Abort avait été appelé sur un communicateur contenant les processus dans la fenêtre ou le fichier correspondant. S'il est appelé sur une session, il abroge uniquement le processus local.
  • MPI_ERRORS_RETURN Renvoie le code d'erreur à l'application.
