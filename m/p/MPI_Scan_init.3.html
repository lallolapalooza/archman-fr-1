PARAMÈTRES D'ENTRÉE

  • sendbuf: Tampon d'envoi (choix).
  • count: Nombre d'éléments dans le tampon d'entrée (entier).
  • datatype: Type de données des éléments du tampon d'entrée (handle).
  • op: Opération (handle).
  • comm: Communicateur (handle).
  • info: Informations (handle, persistant seulement)

PARAMÈTRES DE SORTIE

  • recvbuf: Tampon de réception (choix).
  • request: Requête (handle, non bloquant seulement).
  • ierror: Fortran seulement : Statut d'erreur (entier).

DESCRIPTION

MPI_Scan est utilisée pour effectuer une réduction préfixielle inclusive sur des données distribuées entre les processus appelants. L'opération renvoie, dans le recvbuf du processus de rang i, la réduction (calculée selon la fonction op) des valeurs des sendbuf des processus de rangs 0, …, i (inclusif). Le type d'opérations supportées, leurs sémantiques, et les contraintes sur les tampons d'envoi et de réception sont les mêmes que pour MPI_Reduce.

EXEMPLE

Cet exemple utilise une opération définie par l'utilisateur pour produire un scan segmenté. Un scan segmenté prend, en entrée, un ensemble de valeurs et un ensemble de booléens, où les booléens délimitent les différents segments du scan. Par exemple,

valeurs     v1      v2      v3      v4      v5      v6      v7      v8
booléens    0       0       1       1       1       0       0       1
résultat    v1    v1+v2     v3    v3+v4  v3+v4+v5   v6    v6+v7     v8

Le résultat pour le rang j est donc la somme v(i) + … + v(j), où i est le rang le plus bas tel que pour tous les rangs n, i <= n <= j, logique(n) = logique(j). L'opérateur qui produit cet effet est

      [ u ]     [ v ]     [ w ]
      [   ]  o  [   ]  =  [   ]
      [ i ]     [ j ]     [ j ]
où
    ( u + v si i = j w = ( ( v si i != j

Notez qu'il s'agit d'un opérateur non commutatif. Le code C qui l'implémente est donné ci-dessous.

typedef struct {
        double val;
        int log;
} SegScanPair;
/*
 * la fonction définie par l'utilisateur
 */
void segScan(SegScanPair *in, SegScanPair *inout, int *len,
        MPI_Datatype *dptr)
{
        int i;
        SegScanPair c;
        for (i = 0; i < *len; ++i) {
                if (in->log == inout->log)
                        c.val = in->val + inout->val;
                else
                        c.val = inout->val;
                c.log = inout->log;
                *inout = c;
                in++;
                inout++;
        }
}

Notez que l'argument inout de la fonction définie par l'utilisateur correspond à l'opérande de droite de l'opérateur. Lors de l'utilisation de cet opérateur, il faut faire attention à spécifier qu'il est non commutatif, comme suit :

int                     i, base;
SeqScanPair     a, answer;
MPI_Op          myOp;
MPI_Datatype    type[2] = {MPI_DOUBLE, MPI_INT};
MPI_Aint                disp[2];
int                     blocklen[2] = {1, 1};
MPI_Datatype    sspair;
/*
 * expliquer à MPI comment le type SegScanPair est défini
 */
MPI_Get_address(a, disp);
MPI_Get_address(a.log, disp + 1);
base = disp[0];
for (i = 0; i < 2; ++i)
        disp[i] -= base;
MPI_Type_struct(2, blocklen, disp, type, &sspair);
MPI_Type_commit(&sspair);
/*
 * créer l'opération utilisateur de scan segmenté
 * non commutatif - régler commute (arg 2) à 0
 */
MPI_Op_create((MPI_User_function *)segScan, 0, &myOp);
...
MPI_Scan(a, answer, 1, sspair, myOp, comm);

UTILISATION DE L'OPTION EN PLACE

Lorsque le communicateur est un intracommunicateur, vous pouvez effectuer une opération de scan en place (le tampon de sortie est utilisé comme tampon d'entrée). Utilisez la variable MPI_IN_PLACE comme valeur de l'argument sendbuf. Les données d'entrée sont prises dans le tampon de réception et remplacées par les données de sortie.

NOTES SUR LES OPÉRATIONS COLLECTIVES

Les fonctions de réduction de type MPI_Op ne renvoient pas de valeur d'erreur. En conséquence, si les fonctions détectent une erreur, tout ce qu'elles peuvent faire est soit d'appeler MPI_Abort, soit d'ignorer silencieusement le problème. Ainsi, si le gestionnaire d'erreurs est changé de MPI_ERRORS_ARE_FATAL à autre chose (par exemple, MPI_ERRORS_RETURN), alors aucune erreur ne peut être signalée.

La raison de cela réside dans les problèmes de performance liés à la garantie que toutes les routines collectives renvoient la même valeur d'erreur.

ERREURS

Presque toutes les routines MPI renvoient une valeur d'erreur ; les routines C comme résultat de la fonction et les routines Fortran dans le dernier argument.

Avant que la valeur d'erreur ne soit renvoyée, le gestionnaire d'erreurs MPI actuel associé à l'objet de communication (par exemple, communicateur, fenêtre, fichier) est appelé. Si aucun objet de communication n'est associé à l'appel MPI, alors l'appel est considéré comme attaché à MPI_COMM_SELF et appellera le gestionnaire d'erreurs MPI associé. Lorsque MPI_COMM_SELF n'est pas initialisé (c'est-à-dire, avant MPI_Init/MPI_Init_thread, après MPI_Finalize, ou lorsque le modèle de Sessions est utilisé exclusivement), l'erreur déclenche le gestionnaire d'erreurs initial. Le gestionnaire d'erreurs initial peut être modifié en appelant MPI_Comm_set_errhandler sur MPI_COMM_SELF lors de l'utilisation du modèle World, ou le mpi_init

SYNTAXE

Le gestionnaire d'erreurs ial_errhandler pour mpiexec ou la clé d'information info à utiliser dans MPI_Comm_spawn/MPI_Comm_spawn_multiple. S'il n'y a pas d'autre gestionnaire d'erreurs approprié défini, le gestionnaire d'erreurs MPI_ERRORS_RETURN est appelé pour les fonctions d'E/S MPI et MPI_ERRORS_ABORT pour toutes les autres fonctions MPI.

Open MPI inclut trois gestionnaires d'erreurs par défaut qui peuvent être utilisés:

  • MPI_ERRORS_ARE_FATAL Déclenche le processus MPI connecté.
  • MPI_ERRORS_ABORT Un gestionnaire d'erreurs qui peut être invoqué sur un communicateur, une fenêtre, un fichier ou une session. Lorsqu'il est invoqué sur un communicateur, il agit comme si MPI_Abort avait été appelé sur ce communicateur. S'il est invoqué sur une fenêtre ou un fichier, il agit comme si MPI_Abort avait été appelé sur un communicateur contenant le groupe de processus dans la fenêtre ou le fichier correspondant. S'il est invoqué sur une session, seul le processus local est abandonné.
  • MPI_ERRORS_RETURN Retourne le code d'erreur à l'application.

Les programmes MPI peuvent également implémenter leurs propres gestionnaires d'erreurs en appelant:

  • MPI_Comm_create_errhandler suivi de MPI_Comm_set_errhandler
  • MPI_File_create_errhandler suivi de MPI_File_set_errhandler
  • MPI_Session_create_errhandler suivi de MPI_Session_set_errhandler ou dans MPI_Session_init
  • MPI_Win_create_errhandler suivi de MPI_Win_set_errhandler

Note: MPI ne garantit pas qu'un programme MPI puisse continuer après une erreur.

Voir la section "Gestion des erreurs" de la norme MPI-3.1 pour plus d'informations.
