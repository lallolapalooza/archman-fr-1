MPI_Startall(3) Open MPI MPI_Startall(3)

MPI_Startall — Démarre une collection de requêtes.

Syntaxe

Syntaxe C

#include <mpi.h>
int MPI_Startall(int count, MPI_Request array_of_requests[])

Syntaxe Fortran

USE MPI
! ou la forme plus ancienne : INCLUDE 'mpif.h'
MPI_Startall(COUNT, ARRAY_OF_REQUESTS, IERROR)
     INTEGER COUNT, ARRAY_OF_REQUESTS(*), IERROR

Syntaxe Fortran 2008

USE mpi_f08
MPI_Startall(count, array_of_requests, ierror)
     INTEGER, INTENT(IN) :: count
     TYPE(MPI_Request), INTENT(INOUT) :: array_of_requests(count)
     INTEGER, OPTIONAL, INTENT(OUT) :: ierror

Paramètre d'entrée

•
count : Taille de la liste (entier).

Paramètre d'entrée/sortie

•
array_of_requests : Tableau de requêtes (tableau de handles).

Paramètre de sortie

•
ierror : Seulement en Fortran : Code d'erreur (entier).

Description

Démarre toutes les communications associées aux requêtes dans array_of_requests. Un appel à MPI_Startall(count, array_of_requests) a le même effet que plusieurs appels à MPI_Start(&array_of_requests[i]), exécutés pour i=0, ..., count-1, dans un ordre arbitraire.

Une communication démarrée avec un appel à MPI_Start ou MPI_Startall est complétée par un appel à MPI_Wait, MPI_Test ou l'une des fonctions dérivées MPI_Waitany, MPI_Testany, MPI_Waitall, MPI_Testall (celles-ci sont décrites au chapitre 3.7.5 du Standard MPI, « Multi-Completions »). La requête devient inactive après l'exécution réussie d'un tel appel. La requête n'est pas libérée, et peut être réactivée par un autre appel à MPI_Start ou MPI_Startall.

Une requête persistante est libérée par un appel à MPI_Request_free (voir le chapitre 3.7.3 du Standard MPI, « Communication Completion »).

L'appel à MPI_Request_free peut survenir à tout moment après la création de la requête persistante. Cependant, la requête n'est libérée que lorsqu'elle devient inactive. Les requêtes de réception actives ne doivent pas être libérées. Sinon, il ne sera pas possible de vérifier que la réception est terminée. Il est préférable de libérer les requêtes lorsqu'elles sont inactives. Si cette règle est suivie, alors les fonctions de complétion de communication persistante seront appelées dans une séquence de la forme,
Créer (Démarrer Compléter)* Libérer

où * signifie zéro ou plusieurs répétitions. Si le même objet de communication est utilisé dans plusieurs fils d'exécution concurrents, il est de la responsabilité de l'utilisateur de coordonner les appels de manière à suivre la séquence correcte.

Une opération d'envoi démarrée avec MPI_Start peut correspondre à n'importe quelle opération de réception et, de manière similaire, une opération de réception démarrée avec MPI_Start peut recevoir des messages générés par n'importe quelle opération d'envoi.

Erreurs

La plupart des routines MPI renvoient une valeur d'erreur ; dans les routines C, la valeur de retour est le résultat de la fonction, et dans les routines Fortran, le dernier argument est la valeur d'erreur.

Avant que la valeur d'erreur ne soit renvoyée, le gestionnaire d'erreurs associé à l'objet de communication (par exemple, communicateur, fenêtre, fichier) actuel est appelé. S'il n'y a pas d'objet de communication associé à l'appel MPI, l'appel est considéré comme associé à MPI_COMM_SELF et le gestionnaire d'erreurs associé à MPI_COMM_SELF sera appelé. Lorsque MPI_COMM_SELF n'est pas initialisé (c'est-à-dire avant MPI_Init/MPI_Init_thread, après MPI_Finalize, ou lorsque le modèle de session est utilisé exclusivement), l'erreur élève le gestionnaire d'erreurs initial. Le gestionnaire d'erreurs initial peut être modifié en appelant MPI_Comm_set_errhandler sur MPI_COMM_SELF lors de l'utilisation du modèle du monde, ou l'option mpi_initial_errhandler de mpiexec ou la clé info de MPI_Comm_spawn/MPI_Comm_spawn_multiple. Si aucun autre gestionnaire d'erreurs approprié n'est disponible, le gestionnaire d'erreurs MPI_ERRORS_RETURN est appelé pour les fonctions d'E/S MPI et le gestionnaire d'erreurs MPI_ERRORS_ABORT pour toutes les autres fonctions MPI.

Open MPI inclut trois gestionnaires d'erreurs par défaut qui peuvent être utilisés :

  • MPI_ERRORS_ARE_FATAL — Le programme abandonne tous les processus MPI connectés.
  • MPI_ERRORS_ABORT — Un gestionnaire d'erreurs qui peut être appelé sur un communicateur, une fenêtre, un fichier ou une session. Lorsqu'il est appelé sur un communicateur, il agit comme si MPI_Abort avait été appelé sur ce communicateur. S'il est appelé sur une fenêtre ou un fichier, il agit comme si MPI_Abort avait été appelé sur un communicateur contenant le groupe de processus dans la fenêtre ou le fichier correspondant. S'il est appelé sur une session, il abandonne uniquement le processus local.
  • MPI_ERRORS_RETURN — Renvoie un code d'erreur à l'application.

Les programmes MPI peuvent également implémenter leurs propres gestionnaires d'erreurs en appelant :

  • MPI_Comm_create_errhandler suivi de MPI_Comm_set_errhandler
  • MPI_File_create_errhandler suivi de MPI_File_set_errhandler
  • MPI_Session_create_errhandler suivi de MPI_Session_set_errhandler ou dans MPI_Session_init
  • MPI_Win_create_errhandler suivi de MPI_Win_set_errhandler

Note : Les programmes MPI ne garantissent pas qu'un programme MPI puisse continuer après une erreur.

Voir la page de manuel MPI pour une liste complète des codes d'erreur MPI.

Voir la section sur la gestion des erreurs du standard MPI-3.1 pour plus d'informations.
