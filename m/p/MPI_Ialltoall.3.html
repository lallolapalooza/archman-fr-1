MPI_Alltoall, MPI_Ialltoall, MPI_Alltoall_init - Tous les processus envoient des données à tous les processus.

PARAMÈTRES D'ENTRÉE

  • sendbuf: Adresse de début du tampon d'envoi (option).
  • sendcount: Nombre d'éléments à envoyer à chaque processus (entier).
  • sendtype: Type des éléments du tampon d'envoi (handle).
  • recvcount: Nombre d'éléments à recevoir de chaque processus (entier).
  • recvtype: Type des éléments du tampon de réception (handle).
  • comm: Communicateur sur lequel la communication est effectuée (handle).
  • info: Informations (handle, persistant).

PARAMÈTRES DE SORTIE

  • recvbuf: Adresse de début du tampon de réception (option).
  • request: Requête (handle, non bloquante).
  • ierror: En Fortran uniquement : État d'erreur (entier).

DESCRIPTION

MPI_Alltoall est une opération collective durant laquelle tous les processus envoient la même quantité de données à d'autres processus, et reçoivent la même quantité de données d'autres processus. L'opération de cette routine peut être représentée comme suit, où chaque processus effectue 2n (n étant le nombre de processus dans le communicateur comm) communications point à point indépendantes (y compris la communication avec soi-même).

MPI_Comm_size(comm, &n);
for (i = 0, i < n; i++)
    MPI_Send(sendbuf + i * sendcount * extent(sendtype),
        sendcount, sendtype, i, ..., comm);
for (i = 0, i < n; i++)
    MPI_Recv(recvbuf + i * recvcount * extent(recvtype),
        recvcount, recvtype, i, ..., comm);

Chaque processus divise son sendbuf en n blocs - chacun contenant sendcount éléments de type sendtype - et divise son recvbuf de manière similaire selon recvcount et recvtype. Le processus j envoie le bloc k du sendbuf local de son propre processus au processus k, qui place les données dans le bloc j du recvbuf local de son propre processus. Le volume de données envoyées doit être égal au volume de données reçues, par paires, entre chaque paire de processus.

QUAND LE COMMUNICATEUR EST UN INTER-COMMUNICATEUR

Lorsque le communicateur est un communicateur inter, l'opération est réalisée en deux phases. Les données sont collectées auprès de tous les membres du premier groupe et reçues par tous les membres du second groupe. Ensuite, les données sont collectées auprès de tous les membres du second groupe et reçues par tous les membres du premier. L'opération présente un comportement symétrique, bidirectionnel.

Le premier groupe définit le processus racine. Le processus racine utilise MPI_ROOT comme valeur de root. Tous les autres processus du groupe principal utilisent MPI_PROC_NULL comme valeur de root. Tous les processus du groupe secondaire utilisent la valeur de root comme le rang du processus racine dans le groupe principal.

Lorsque le communicateur est un communicateur intra, ces groupes sont les mêmes, et l'opération est réalisée en une seule phase.

UTILISATION DE L'OPTION BUFFER EN PLACE

Lorsque le communicateur est un communicateur intra, vous pouvez effectuer une opération all-to-all au lieu d'une batterie (le tampon de réception est utilisé comme tampon d'entrée). Utilisez la variable MPI_IN_PLACE comme valeur de sendbuf. Dans ce cas, sendcount et sendtype sont ignorés. Les données d'entrée de chaque processus sont supposées se trouver dans la zone où ce processus recevrait sa propre contribution au tampon de réception.

NOTES

Tous les arguments sur tous les processus sont significatifs. L'argument comm, en particulier, doit décrire le même communicateur sur tous les processus.

Il existe deux autres routines de bibliothèque MPI plus génériques que MPI_Alltoall. MPI_Alltoallv permet la communication all-to-all avec des tampons non contigus ; différents processus peuvent envoyer et recevoir des quantités de données différentes. MPI_Alltoallw étend la fonctionnalité de MPI_Alltoallv pour permettre l'échange de données avec différents types de données.

ERREURS

La plupart des routines MPI retournent une valeur d'erreur ; les routines C retournent le résultat de la fonction et les routines Fortran dans le dernier argument.

Avant que la valeur d'erreur ne soit retournée, le gestionnaire d'erreurs associé à l'objet de communication (par exemple, le communicateur, la fenêtre, le fichier) est appelé. S'il n'y a pas d'objet de communication associé à l'appel MPI, l'appel est considéré comme associé à MPI_COMM_SELF et le gestionnaire d'erreurs correspondant est appelé. Lorsque MPI_COMM_SELF n'est pas initialisé (c'est-à-dire avant MPI_Init/MPI_Init_thread, après MPI_Finalize, ou lorsque le modèle de Sessions est utilisé exclusivement), l'erreur initiale est levée. L'erreur initiale peut être modifiée en appelant MPI_Comm_set_errhandler sur MPI_COMM_SELF lorsque le modèle du Monde est utilisé, ou la clé d'information mpi_initial_errhandler pour mpiexec ou la clé d'information pour MPI_Comm_spawn/MPI_Comm_spawn_multiple. S'il n'existe pas d'autre gestionnaire d'erreurs approprié, le gestionnaire d'erreurs MPI_ERRORS_RETURN est appelé pour les fonctions d'E/S MPI et le gestionnaire d'erreurs MPI_ERRORS_ABORT est appelé pour toutes les autres fonctions MPI.

Open MPI inclut trois gestionnaires d'erreurs par défaut qui peuvent être utilisés :

  • mpi_initial_errhandler
  • mpi_comm_set_errhandler
  • mpi_errors_return
