MPI_Alltoallv, MPI_Ialltoallv, MPI_Alltoallv_init - Tous les processus envoient des données différentes à, et reçoivent des données différentes de, tous les processus.

Paramètres d'entrée

  • sendbuf: Adresse de départ du tampon d'envoi.
  • sendcounts: Tableau d'entiers, où l'entrée i spécifie le nombre d'éléments à envoyer au processus i.
  • sdispls: Tableau d'entiers, où l'entrée i spécifie le décalage (offset par rapport à sendbuf, en unités de sendtype) à partir duquel les données sont envoyées au processus i.
  • sendtype: Type de données des éléments du tampon d'envoi.
  • recvcounts: Tableau d'entiers, où l'entrée j spécifie le nombre d'éléments à recevoir du processus j.
  • rdispls: Tableau d'entiers, où l'entrée j spécifie le décalage (offset par rapport à recvbuf, en unités de recvtype) où les données du processus j doivent être écrites.
  • recvtype: Type de données des éléments du tampon de réception.
  • comm: Communicateur sur lequel l'échange de données est effectué.
  • info: Informations (handle, persistant uniquement)

Paramètres de sortie

  • recvbuf: Adresse du tampon de réception.
  • request: Requête (handle, non bloquant).
  • ierror: Uniquement en Fortran : Statut d'erreur.

Description

MPI_Alltoallv est une opération collective généralisée dans laquelle tous les processus envoient des données à, et reçoivent des données de, tous les autres processus. Cela donne de la flexibilité à MPI_Alltoall en permettant à l'utilisateur de spécifier les données à envoyer et à recevoir dans un style vectoriel (via un décalage et un compteur d'éléments). L'opération de cette routine peut être pensée comme suit, où chaque processus effectue 2n (n étant le nombre de processus dans le communicateur comm) communications point à point indépendantes (y compris la communication avec lui-même).

MPI_Comm_size(comm, &n);
for (i = 0, i < n; i++)
    MPI_Send(sendbuf + sdispls[i] * extent(sendtype),
        sendcounts[i], sendtype, i, ..., comm);
for (i = 0, i < n; i++)
    MPI_Recv(recvbuf + rdispls[i] * extent(recvtype),
        recvcounts[i], recvtype, i, ..., comm);

Le processus j envoie le bloc k de son propre sendbuf au processus k, qui place les données dans le bloc j de son propre recvbuf.

Lorsqu'une paire de processus échange des données, chacun peut passer des valeurs de compteur d'éléments et de type de données différentes, à condition que l'expéditeur spécifie le même nombre d'octets à envoyer (en octets) que le récepteur s'attend à recevoir.

Remarque : Le processus i peut envoyer une quantité différente de données au processus j qu'il ne reçoit du processus j. De plus, un processus peut envoyer des quantités différentes de données à différents processus dans le communicateur.

QUAND LE COMMUNICATEUR EST UN INTERCOMMUNICATEUR

Lorsque le communicateur est un inter-communicateur, l'opération de collecte se déroule en deux phases. Les données sont collectées de tous les membres du premier groupe et reçues par tous les membres du second groupe. Ensuite, les données sont collectées de tous les membres du second groupe et reçues par tous les membres du premier. Cette opération présente un comportement symétrique, full-duplex.

Le premier groupe définit le processus racine. Le processus racine utilise MPI_ROOT comme valeur de root. Tous les autres processus du premier groupe utilisent MPI_PROC_NULL comme valeur de root. Tous les processus du second groupe utilisent le rang du processus racine dans le premier groupe comme valeur de root.

Lorsque le communicateur est un intra-communicateur, ces groupes sont les mêmes, et l'opération se déroule en une seule phase.

Utilisation de l'option en place

Lorsque le communicateur est un intra-communicateur, vous pouvez effectuer une opération all-to-all en place (le tampon de sortie est utilisé comme tampon d'entrée). Utilisez la variable MPI_IN_PLACE comme valeur de sendbuf. Dans ce cas, sendcounts, sdispls et sendtype sont ignorés. Les données d'entrée de chaque processus sont supposées se trouver dans la zone où ce processus enverrait sa propre contribution au tampon de réception.

Notes

Les spécifications de compteurs et de décalages ne doivent pas amener à écrire plusieurs fois au même emplacement.

Tous les arguments sur tous les processus sont significatifs. L'argument comm, en particulier, doit décrire le même communicateur sur tous les processus.

Les décalages de sdispls et rdispls sont mesurés en unités de sendtype et recvtype respectivement. Comparez cela avec MPI_Alltoallw, où ces décalages sont mesurés en octets.

Avant que la valeur d'erreur ne soit retournée, le gestionnaire d'erreurs MPI actuel associé à l'objet de communication (par exemple, communicateur, fenêtre, fichier) est appelé. S'il n'y a pas d'objet de communication associé à l'appel MPI, alors l'appel est considéré comme attaché à MPI_COMM_SELF et appellera le gestionnaire d'erreurs MPI associé. Lorsque MPI_COMM_SELF n'est pas initialisé (c'est-à-dire avant MPI_Init/MPI_Init_thread, après MPI_Finalize, ou lorsque le modèle de Sessions est utilisé exclusivement), l'erreur déclenche le gestionnaire d'erreurs initial. Le gestionnaire d'erreurs initial peut être modifié en appelant MPI_Comm_set_errhandler sur MPI_COMM_SELF lors de l'utilisation du modèle World, ou l'argument CLI mpi_initial_errhandler pour mpiexec ou la clé info pour MPI_Comm_spawn/MPI_Comm_spawn_multiple. Si aucun autre gestionnaire d'erreurs approprié n'a été défini, alors le gestionnaire d'erreurs MPI_ERRORS_RETURN est appelé pour les fonctions MPI I/O et le gestionnaire d'erreurs MPI_ERRORS_ABORT est appelé pour toutes les autres fonctions MPI.

Open MPI inclut trois gestionnaires d'erreurs prédéfinis qui peuvent être utilisés :

  • MPI_ERRORS_ARE_FATAL Provoque l'arrêt du programme sur tous les processus MPI connectés.
  • MPI_ERRORS_ABORT Un gestionnaire d'erreurs qui peut être invoqué sur un communicateur, une fenêtre, un fichier ou une session. Lorsqu'il est appelé sur un communicateur, il agit comme si MPI_Abort avait été appelé sur ce communicateur. S'il est appelé sur une fenêtre ou un fichier, il agit comme si MPI_Abort avait été appelé sur un communicateur contenant le groupe de processus de la fenêtre ou du fichier correspondant. S'il est appelé sur une session, il n'interrompt que le processus local.
  • MPI_ERRORS_RETURN Retourne un code d'erreur à l'application.

Les applications MPI peuvent également implémenter leurs propres gestionnaires d'erreurs en appelant :

  • MPI_Comm_create_errhandler puis MPI_Comm_set_errhandler
  • MPI_File_create_errhandler puis MPI_File_set_errhandler
  • MPI_Session_create_errhandler puis MPI_Session_set_errhandler ou lors de MPI_Session_init
  • MPI_Win_create_errhandler puis MPI_Win_set_errhandler

Notez que MPI ne garantit pas qu'un programme MPI puisse continuer après une erreur.
