MPI_Allreduce, MPI_Iallreduce, MPI_Allreduce_init - Combina les valeurs de tous les processus et distribue le résultat à nouveau à tous les processus.

                   MPI_Datatype datatype, MPI_Op op, MPI_Comm comm,

Paramètres d'entrée

  • sendbuf: Adresse de départ du tampon d'envoi (optionnel).
  • count: Nombre d'éléments dans le tampon d'envoi (entier).
  • datatype: Type de données des éléments du tampon d'envoi (handle).
  • op: Opération (handle).
  • comm: Communicateur (handle).
  • info: Informations (handle, persistant).

Paramètres de sortie

  • recvbuf: Adresse de départ du tampon de réception (optionnel).
  • request: Requête (handle, non bloquant).
  • ierror: Fortran uniquement : Statut d'erreur (entier).

Description

Identique à MPI_Reduce, sauf que le résultat apparaît dans le tampon de réception de tous les membres du groupe.

Exemple 1 : Une routine qui calcule le produit d'un vecteur et d'un tableau distribués sur un groupe de processus et renvoie le résultat sur tous les nœuds (comparer avec l'exemple 2, avec MPI_Reduce, ci-dessous).

SUBROUTINE PAR_BLAS2(m, n, a, b, c, comm)
REAL a(m), b(m,n)    ! fragment local du tableau
REAL c(n)            ! résultat
REAL sum(n)
INTEGER n, comm, i, j, ierr
! somme locale
DO j= 1, n
  sum(j) = 0.0
  DO i = 1, m
    sum(j) = sum(j) + a(i)*b(i,j)
  END DO
END DO
! somme globale
CALL MPI_ALLREDUCE(sum, c, n, MPI_REAL, MPI_SUM, comm, ierr)
! renvoie le résultat sur tous les nœuds
RETURN

Exemple 2 : Une routine qui calcule le produit d'un vecteur et d'un tableau distribués sur un groupe de processus et renvoie le résultat sur le nœud zéro.

SUBROUTINE PAR_BLAS2(m, n, a, b, c, comm)
REAL a(m), b(m,n)    ! fragment local du tableau
REAL c(n)            ! résultat
REAL sum(n)
INTEGER n, comm, i, j, ierr
! somme locale
DO j= 1, n
  sum(j) = 0.0
  DO i = 1, m
    sum(j) = sum(j) + a(i)*b(i,j)
  END DO
END DO
! somme globale
CALL MPI_REDUCE(sum, c, n, MPI_REAL, MPI_SUM, 0, comm, ierr)
! renvoie le résultat sur le nœud zéro (et jette les autres nœuds)
RETURN

Utilisation de l'option « en place »

Lorsque le communicateur est un intracommunicateur, vous pouvez effectuer une opération d'all-reduce en place (le tampon de réception est utilisé comme tampon d'envoi). Utilisez la variable MPI_IN_PLACE comme valeur pour sendbuf dans tous les processus.

Notez que MPI_IN_PLACE est une valeur de type spécial ; elle a les mêmes restrictions que MPI_BOTTOM.

Comme l'option « en place » transforme le tampon de réception en un tampon d'envoi et de réception, une liaison Fortran incluant INTENT doit les marquer comme INOUT, pas comme OUT.

Lorsque le communicateur est un intercomunicateur

Lorsque le communicateur est un intercomunicateur, l'opération de réduction se déroule en deux phases. Les données sont réduites à partir de tous les membres du premier groupe et reçues par tous les membres du second groupe. Ensuite, les données sont réduites à partir de tous les membres du second groupe et reçues par tous les membres du premier. L'opération affiche un comportement symétrique, double duplex.

Lorsque le communicateur est un intracommunicateur, ces groupes sont identiques et l'opération se déroule en une seule phase.

Remarques sur les opérations collectives

Les fonctions de réduction (MPI_Op) ne renvoient pas de valeur d'erreur. Par conséquent, si les fonctions détectent une erreur, la seule chose qu'elles peuvent faire est d'appeler MPI_Abort ou d'ignorer le problème. Ainsi, si vous remplacez le gestionnaire d'erreurs MPI_ERRORS_ARE_FATAL par autre chose, par exemple MPI_ERRORS_RETURN, aucune erreur ne sera signalée.

Erreurs

La plupart des routines MPI renvoient une valeur d'erreur ; dans le cas des routines C, le résultat est renvoyé comme valeur de retour de la fonction, et dans le cas des routines Fortran, le dernier argument est la valeur de retour.

Avant que la valeur d'erreur ne soit renvoyée, le gestionnaire d'erreurs associé à l'objet de communication (par exemple, communicateur, fenêtre, fichier) lié à l'appel MPI est appelé. S'il n'y a pas d'objet de communication associé à l'appel MPI, l'appel est considéré comme associé à MPI_COMM_SELF et appellera le gestionnaire d'erreurs associé à MPI_COMM_SELF. Lorsque MPI_COMM_SELF n'est pas initialisé (c'est-à-dire avant MPI_Init/MPI_Init_thread, après MPI_Finalize, ou lorsque le modèle de session est utilisé exclusivement), l'erreur déclenche le gestionnaire d'erreurs initial. Le gestionnaire d'erreurs initial peut être modifié en appelant MPI_Comm_set_errhandler sur MPI_COMM_SELF lors de l'utilisation du modèle de monde, ou via l'argument mpi_initial_errhandler de mpiexec ou la clé d'information de MPI_Comm_spawn/MPI_Comm_spawn_multiple. S'il n'y a pas d'autre gestionnaire d'erreurs approprié, le gestionnaire d'erreurs MPI_ERRORS_RETURN est appelé pour les fonctions d'E/S MPI et le gestionnaire d'erreurs MPI_ERRORS_ABORT pour toutes les autres fonctions MPI.

Open MPI inclut trois gestionnaires d'erreurs prédéfinis qui peuvent être utilisés :

  • MPI_ERRORS_ARE_FATAL fait avorter tous les processus MPI connectés.
  • MPI_ERRORS_ABORT un gestionnaire d'erreurs qui peut être invoqué sur un communicateur, une fenêtre, un fichier ou une session. Lorsqu'il est invoqué sur un communicateur, il agit comme si MPI_Abort avait été appelé sur ce communicateur. S'il est invoqué sur une fenêtre ou un fichier...
