MPI_File_set_info(3)

Paquet: openmpi

Licences: BSD-3-Clause AND LicenseRef-MPICH

MPI_File_set_info(3) Open MPI MPI_File_set_info(3)

MPI_File_set_info établit de nouvelles valeurs pour les indications (collaboratives) d'un fichier associé à fh. Ces indications sont définies par les routines MPI_File_open, MPI_File_delete, MPI_File_set_view et MPI_File_set_info. L'objet opaque info, qui permet de fournir des indications pour optimiser votre code, peut être différent sur chaque processus, mais certaines indications info sont obligatoires sur tous les processus : dans ces cas, elles doivent apparaître avec la même valeur sur chaque objet info de processus. Voir la section HINTS pour une liste des indications qui peuvent être définies.

SYNTAXE

Syntaxe C

#include <mpi.h>
int MPI_File_set_info(MPI_File fh, MPI_Info info)

Syntaxe Fortran

USE MPI
! ou l'ancienne forme : INCLUDE 'mpif.h'
MPI_FILE_SET_INFO(FH, INFO, IERROR)
     INTEGER FH, INFO, IERROR

Syntaxe Fortran 2008

USE mpi_f08
MPI_File_set_info(fh, info, ierror)
     TYPE(MPI_File), INTENT(IN) :: fh
     TYPE(MPI_Info), INTENT(IN) :: info
     INTEGER, OPTIONAL, INTENT(OUT) :: ierror

PARAMÈTRE D'ENTRÉE/SORTIE

•
fh : Handle du fichier.

PARAMÈTRE D'ENTRÉE

•
info : Objet d'informations (handle).

PARAMÈTRE DE SORTIE

•
ierror : Statut d'erreur (entier) en Fortran uniquement.

DESCRIPTION

MPI_File_set_info est une routine collaborative qui définit de nouvelles valeurs pour les indications d'un fichier associé à fh. Ces indications sont définies par les routines MPI_File_open, MPI_File_delete, MPI_File_set_view et MPI_File_set_info. Les indications opaques info, qui permettent de fournir des indications pour l'optimisation de votre code, peuvent être différentes sur chaque processus, mais certaines indications info sont obligatoires sur tous les processus : dans ces cas, elles doivent apparaître avec la même valeur sur chaque objet info de processus. Voir la section HINTS pour une liste des indications qui peuvent être définies.

INDICATIONS

Les indications suivantes peuvent être utilisées comme valeurs pour le paramètre info.

INDICATIONS DE CONFIGURATION

  • shared_file_timeout : Temps (en secondes) pendant lequel on attend pour accéder au pointeur de fichier partagé avant de sortir avec MPI_ERR_TIMEDOUT.
  • rwlock_timeout : Temps (en secondes) pendant lequel on attend pour acquérir un verrou de lecture ou d'écriture sur un bloc continu d'un fichier UNIX avant de sortir avec MPI_ERR_TIMEDOUT.
  • noncoll_read_bufsize : Taille maximale du tampon utilisée par MPI I/O pour satisfaire les requêtes de lecture dans les routines d'accès aux données non collaboratives.

    NOTE :

Une taille de tampon inférieure à la distance (en octets) entre le premier octet et le dernier octet de l'accès demandé dans un fichier UNIX amène MPI I/O à itérer et à effectuer de multiples appels read() ou write() sous UNIX. Si la requête inclut plusieurs blocs non contigus de données et que la taille du tampon est supérieure à la taille de ces blocs, alors l'appel read() ou write() (effectué au niveau de MPI I/O) accédera à des données non demandées par ce processus afin de réduire le nombre total d'appels write() effectués. Si ce comportement n'est pas souhaitable, vous devriez réduire cette taille de tampon pour qu'elle soit égale à la taille des blocs contigus dans ceux demandés.
  • noncoll_write_bufsize : Taille maximale du tampon utilisée par MPI I/O pour satisfaire les requêtes d'écriture dans les routines d'accès aux données non collaboratives.

    Voir la note précédente à propos de noncoll_read_bufsize.

  • coll_read_bufsize : Taille maximale du tampon utilisée par MPI I/O pour satisfaire les requêtes de lecture dans les routines d'accès aux données collaboratives.

    Voir la note précédente à propos de noncoll_read_bufsize.

  • coll_write_bufsize : Taille maximale du tampon utilisée par MPI I/O pour satisfaire les requêtes d'écriture dans les routines d'accès aux données collaboratives.

    Voir la note précédente à propos de noncoll_read_bufsize.

  • mpiio_concurrency : (booléen) contrôle si les routines d'E/S non bloquantes peuvent lier un thread supplémentaire à un LWP.
  • mpiio_coll_contiguous : (booléen) contrôle si les accès collaboratifs ultérieurs aux régions de fichiers seront des requêtes contiguës.
  • filename : Accédez à cette indication pour obtenir le nom du fichier.

ERREURS

La plupart des routines MPI renvoient une valeur d'erreur ; dans les routines C, le résultat est renvoyé comme valeur de retour de la fonction, et dans les routines Fortran, le dernier argument est la valeur d'erreur.

Avant de renvoyer la valeur d'erreur, le gestionnaire d'erreur actuel associé à l'objet de communication (par exemple, le communicateur, la fenêtre, le fichier) est appelé. S'il n'y a pas d'objet de communication associé à l'appel MPI, l'appel est considéré comme associé à MPI_COMM_SELF et le gestionnaire approprié sera appelé. Lorsque MPI_COMM_SELF n'est pas initialisé (c'est-à-dire avant MPI_Init/MPI_Init_thread, après MPI_Finalize ou lorsque le modèle de Sessions est utilisé exclusivement), l'erreur déclenche le gestionnaire d'erreur initial. Le gestionnaire d'erreur initial peut être modifié en appelant MPI_Comm_set_errhandler sur MPI_COMM_SELF lorsque le modèle du Monde est utilisé, ou par l'argument CLI mpi_initial_errhandler pour mpiexec ou la clé d'information pour MPI_Comm_spawn/MPI_Comm_spawn_multiple. Si aucun autre gestionnaire approprié n'est configuré, le gestionnaire d'erreur MPI_ERRORS_RETURN est appelé pour les fonctions d'E/S MPI et le gestionnaire d'erreur MPI_ERRORS_ABORT pour toutes les autres fonctions MPI.

Open MPI inclut trois gestionnaires d'erreurs par défaut qui peuvent être utilisés :

  • MPI_ERRORS_ARE_FATAL : Arrête tous les processus MPI connectés.
  • MPI_ERRORS_ABORT : Un gestionnaire d'erreur qui peut être invoqué sur un communicateur, une fenêtre, un fichier ou une session. Lorsqu'il est invoqué sur un communicateur, il agit comme si MPI_Abort avait été appelé sur ce communicateur. S'il est invoqué sur une fenêtre ou un fichier, il agit comme si MPI_Abort avait été appelé sur un communicateur contenant le groupe de processus de la fenêtre correspondante. S'il est invoqué sur une session, il arrête uniquement le processus local.
  • MPI_ERRORS_RETURN : Renvoie un code d'erreur à l'application.

Les applications MPI peuvent également implémenter leurs propres gestionnaires d'erreurs en appelant :

  • MPI_Comm_create_errhandler puis MPI_Comm_set_errhandler
  • MPI_File_create_errhandler puis MPI_File_set_errhandler
  • MPI_Session_create_errhandler puis MPI_Session_set_errhandler ou dans MPI_Session_init
  • MPI_Win_create_errhandler puis MPI_Win_set_errhandler

Remarque : MPI ne garantit pas qu'un programme MPI puisse continuer après une erreur.

Voir la section de gestion des erreurs de la documentation MPI-3.1 pour plus d'informations.

Voir la section des erreurs de la page de manuel MPI pour une liste complète des codes d'erreur MPI.
