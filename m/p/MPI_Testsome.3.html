MPI_Testsome — Teste l'achèvement d'une ou plusieurs communications précédemment initiées dans une liste.

SYNTAX

Syntaxe C

#include <mpi.h>
int MPI_Testsome(int incount, MPI_Request array_of_requests[],
     int *outcount, int array_of_indices[],
     MPI_Status array_of_statuses[])

Syntaxe Fortran

USE MPI
! ou la forme plus ancienne : INCLUDE 'mpif.h'
MPI_TESTSOME(INCOUNT, ARRAY_OF_REQUESTS, OUTCOUNT,
             ARRAY_OF_INDICES, ARRAY_OF_STATUSES, IERROR)
     INTEGER INCOUNT, ARRAY_OF_REQUESTS(*)
     INTEGER OUTCOUNT, ARRAY_OF_INDICES(*)
     INTEGER ARRAY_OF_STATUSES(MPI_STATUS_SIZE,*), IERROR

Syntaxe Fortran 2008

USE mpi_f08
MPI_Testsome(incount, array_of_requests, outcount, array_of_indices,
             array_of_statuses, ierror)
     INTEGER, INTENT(IN) :: incount
     TYPE(MPI_Request), INTENT(INOUT) :: array_of_requests(incount)
     INTEGER, INTENT(OUT) :: outcount, array_of_indices(*)
     TYPE(MPI_Status) :: array_of_statuses(*)
     INTEGER, OPTIONAL, INTENT(OUT) :: ierror

PARAMÈTRES D'ENTRÉE

  • incount : Longueur de `array_of_requests` (entier).
  • array_of_requests : Tableau de requêtes (tableau de descripteurs).

PARAMÈTRES DE SORTIE

  • outcount : Nombre de requêtes complétées (entier).
  • array_of_indices : Tableau des indices des opérations qui sont terminées (tableau d'entiers).
  • array_of_statuses : Tableau des objets de statut pour les opérations qui sont terminées (tableau de statuts).
  • ierror : Fortran uniquement : statut d'erreur (entier).

DESCRIPTION

Se comporte comme MPI_Waitsome, sauf qu'il retourne immédiatement.

Retourne dans `outcount` le nombre de requêtes de la liste `array_of_requests` qui sont terminées. Retourne dans les `outcount` premières positions du tableau `array_of_indices` les indices de ces opérations (indice dans le tableau `array_of_requests` ; le tableau est indexé à partir de 0 en C et à partir de 1 en Fortran). Retourne dans les `outcount` premières positions du tableau `array_of_status` le statut de ces opérations complétées. Si une requête qui s'est terminée a été allouée par un appel de communication non bloquant, elle est désallouée et son descripteur associé est défini sur MPI_REQUEST_NULL.

Si aucune opération n'est terminée, il retourne `outcount = 0`. S'il n'y a aucun descripteur actif dans la liste, il retourne `outcount = MPI_UNDEFINED`.

MPI_Testsome est une opération locale, qui retourne immédiatement, tandis que MPI_Waitsome bloque jusqu'à ce qu'une communication soit terminée, si elle a reçu une liste contenant au moins un descripteur actif. Les deux appels satisfont une exigence d'équité : si une requête de réception apparaît de manière répétée dans une liste de requêtes passée à MPI_Waitsome ou MPI_Testsome, et qu'un envoi correspondant a été posté, alors la réception réussira éventuellement à moins que l'envoi ne soit satisfait par une autre réception ; les requêtes d'envoi satisfont également cette exigence d'équité.

Les erreurs qui se produisent pendant l'exécution de MPI_Testsome sont gérées comme pour MPI_Waitsome.

Si votre application n'a pas besoin d'examiner le champ array_of_statuses, vous pouvez économiser des ressources en utilisant la constante prédéfinie MPI_STATUSES_IGNORE qui peut être utilisée comme valeur spéciale pour l'argument array_of_statuses.

NOTES

L'utilisation de MPI_Testsome est probablement plus efficace que celle de MPI_Testany. Le premier retourne des informations sur toutes les communications complétées ; avec le second, un nouvel appel est requis pour chaque communication qui se termine.

Un serveur avec plusieurs clients peut utiliser MPI_Waitsome afin de ne pas affamer de client. Les clients envoient des messages au serveur avec des requêtes de service. Le serveur appelle MPI_Waitsome avec une requête de réception pour chaque client, puis traite toutes les réceptions qui se sont terminées. Si un appel à MPI_Waitany est utilisé à la place, alors un client pourrait être affamé pendant que les requêtes d'un autre client arrivent toujours en premier.

ERREURS

Presque toutes les routines MPI retournent une valeur d'erreur ; les routines C comme résultat de la fonction et les routines Fortran dans le dernier argument.

Avant que la valeur d'erreur ne soit retournée, le gestionnaire d'erreurs MPI actuel associé à l'objet de communication (par exemple, communicateur, fenêtre, fichier) est appelé. Si aucun objet de communication n'est associé à l'appel MPI, alors l'appel est considéré comme attaché à MPI_COMM_SELF et appellera le gestionnaire d'erreurs MPI associé. Lorsque MPI_COMM_SELF n'est pas initialisé (c'est-à-dire avant MPI_Init/MPI_Init_thread, après MPI_Finalize, ou lors de l'utilisation exclusive du modèle de sessions), l'erreur déclenche le gestionnaire d'erreurs initial. Le gestionnaire d'erreurs initial peut être modifié en appelant MPI_Comm_set_errhandler sur MPI_COMM_SELF lors de l'utilisation du modèle World, ou via l'argument CLI mpi_initial_errhandler de mpiexec ou la clé d'info pour MPI_Comm_spawn/MPI_Comm_spawn_multiple. Si aucun autre gestionnaire d'erreurs approprié n'a été défini, alors le gestionnaire d'erreurs MPI_ERRORS_RETURN est appelé pour les fonctions d'E/S MPI et le gestionnaire d'erreurs MPI_ERRORS_ABORT est appelé pour toutes les autres fonctions MPI.

Open MPI inclut trois gestionnaires d'erreurs prédéfinis qui peuvent être utilisés :

  • MPI_ERRORS_ARE_FATAL Provoque l'abandon du programme par tous les processus MPI connectés.
  • MPI_ERRORS_ABORT Un gestionnaire d'erreurs qui peut être appelé sur un communicateur, une fenêtre, un fichier ou une session. Lorsqu'il est appelé sur un communicateur, il agit comme si MPI_Abort avait été appelé sur ce communicateur. S'il est appelé sur une fenêtre ou un fichier, il agit comme si MPI_Abort avait été appelé sur un communicateur contenant le groupe de processus de la fenêtre ou du fichier correspondant. S'il est appelé sur une session, il n'abandonne que le processus local.
  • MPI_ERRORS_RETURN Retourne un code d'erreur à l'application.

Les applications MPI peuvent également implémenter leurs propres gestionnaires d'erreurs en appelant :

  • MPI_Comm_create_errhandler puis MPI_Comm_set_errhandler
  • MPI_File_create_errhandler puis MPI_File_set_errhandler
  • MPI_Session_create_errhandler puis MPI_Session_set_errhandler ou lors de MPI_Session_init
  • MPI_Win_create_errhandler puis MPI_Win_set_errhandler

Notez que MPI ne garantit pas qu'un programme MPI puisse continuer après une erreur.

Consultez la page man MPI pour une liste complète des codes d'erreur MPI.

Consultez la section Gestion des erreurs de la norme MPI-3.1 pour plus d'informations.

Pour chaque invocation de MPI_Testsome, si une ou plusieurs requêtes génèrent une erreur MPI, seule la première requête MPI qui a causé une erreur sera transmise à son gestionnaire d'erreurs correspondant. Aucun autre gestionnaire d'erreurs ne sera appelé (même si plusieurs requêtes ont généré des erreurs). Cependant, toutes les requêtes qui génèrent une erreur auront un code d'erreur pertinent défini dans le champ status.MPI_ERROR correspondant (sauf si MPI_STATUSES_IGNORE a été utilisé).

Si le gestionnaire d'erreurs appelé permet à MPI_Testsome de retourner à l'appelant, la valeur MPI_ERR_IN_STATUS sera retournée dans les liaisons C et Fortran.
