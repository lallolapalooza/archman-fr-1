MPIX_Comm_ishrink(3) Open MPI MPIX_Comm_ishrink(3)

MPIX_Comm_shrink, MPIX_Comm_ishrink - Crée un nouveau communicator qui inclut tous les processus du communicator parent qui n'ont pas échoué.

Cette partie de l'extension ULFM de gestion des erreurs au niveau utilisateur.

SYNTAXE

Syntaxe C

#include <mpi.h>
#include <mpi-ext.h>
int MPIX_Comm_shrink(MPI_Comm comm, MPI_Comm *newcomm)
int MPIX_Comm_ishrink(MPI_Comm comm, MPI_Comm *newcomm, MPI_Request *request)

Syntaxe Fortran

USE MPI
USE MPI_EXT
! ou l'ancienne méthode: INCLUDE 'mpif.h'
MPIX_COMM_SHRINK(COMM, NEWCOMM, IERROR)
     INTEGER COMM, NEWCOMM, IERROR
MPIX_COMM_ISHRINK(COMM, NEWCOMM, REQUEST, IERROR)
     INTEGER COMM, NEWCOMM, REQUEST, IERROR

Syntaxe Fortran 2008

USE mpi_f08
USE mpi_ext_f08
MPIX_Comm_shrink(comm, newcomm, ierror)
     TYPE(MPI_Comm), INTENT(IN) :: comm
     TYPE(MPI_Comm), INTENT(OUT) :: newcomm
     INTEGER, OPTIONAL, INTENT(OUT) :: ierror
MPIX_Comm_ishrink(comm, newcomm, request, ierror)
     TYPE(MPI_Comm), INTENT(IN) :: comm
     TYPE(MPI_Comm), INTENT(OUT), ASYNCHRONOUS :: newcomm
     TYPE(MPI_Request), INTENT(OUT) :: request
     INTEGER, OPTIONAL, INTENT(OUT) :: ierror

PARAMÈTRES D'ENTRÉE

•
comm: Communicateur (handle).

PARAMÈTRES DE SORTIE

  • newcomm: Communicateur (handle).
  • request: Requête (handle, uniquement non bloquante).
  • ierror: Fortran uniquement : statut d'erreur (entier).

DESCRIPTION

Cette opération collective crée un nouveau communicator newcomm intra-muros ou inter-processus à partir du communicator comm intra-muros ou inter-processus, en excluant les processus MPI qui ont échoué pendant l'opération.

Les groupes de newcomm doivent inclure tous les processus MPI qui retournent le résultat de MPIX_Comm_shrink, et ils doivent exclure tous les processus MPI dont l'échec a causé une erreur de type MPIX_ERR_PROC_FAILED ou MPIX_ERR_PROC_FAILED_PENDING à un membre des groupes de newcomm avant que ce membre n'ait initié l'opération de réduction.

En d'autres termes, cette procédure est sémantiquement équivalente à une opération MPI_Comm_split qui serait effectuée même en cas d'échecs, où les membres des groupes de newcomm participent avec la même couleur et une clé égale à leur numéro de rang dans comm.

MPIX_Comm_ishrink est la variante non bloquante de MPIX_Comm_shrink. Vous devez faire attention à utiliser newcomm avant que la request ne soit terminée.

QUAND LE COMMUNICATEUR EST RÉVOQUÉ OU CONTIENT DES PROCESSUS ÉCHOUÉS

Cette fonction ne produit jamais d'erreurs de classe MPIX_ERR_REVOKED ou MPIX_ERR_PROC_FAILED. Les définitions sémantiques de MPIX_Comm_shrink et MPIX_Comm_ishrink restent vraies même lorsque comm est révoqué ou lorsque le groupe de comm contient des processus échoués. En particulier, MPIX_Comm_shrink et MPIX_Comm_ishrink sont des opérations collectives, même lorsque comm est révoqué.

L'implémentation tentera de détecter tous les échecs pendant l'opération de réduction, mais dans certaines circonstances, le groupe de newcomm peut encore contenir des processus échoués, dont l'échec sera détecté lors d'opérations ultérieures sur newcomm.

ERREURS

Presque toutes les routines MPI retournent une valeur d'erreur ; le résultat des routines C est la valeur d'erreur, et dans les routines Fortran, le dernier argument est la valeur d'erreur.

Avant que la valeur d'erreur ne soit retournée, le gestionnaire d'erreurs associé à l'objet de communication actuel (par exemple, communicateur, fenêtre, fichier) est appelé. S'il n'y a pas d'objet de communication associé à l'appel MPI, l'appel est considéré comme étant associé à MPI_COMM_SELF et le gestionnaire d'erreurs associé à MPI_COMM_SELF est appelé. Lorsque MPI_COMM_SELF n'est pas initialisé (c'est-à-dire avant MPI_Init/MPI_Init_thread, après MPI_Finalize, ou lors de l'utilisation exclusive du modèle de Sessions), l'erreur appelle le gestionnaire d'erreurs initial. Le gestionnaire d'erreurs initial peut être modifié en appelant MPI_Comm_set_errhandler sur MPI_COMM_SELF lors de l'utilisation du modèle Monde, ou sur la clé d'informations mpi_initial_errhandler de mpiexec ou MPI_Comm_spawn/MPI_Comm_spawn_multiple. Si aucun autre gestionnaire d'erreurs approprié n'est défini, le gestionnaire d'erreurs MPI_ERRORS_RETURN est appelé pour les fonctions d'E/S MPI et le gestionnaire d'erreurs MPI_ERRORS_ABORT pour toutes les autres fonctions MPI.

Open MPI inclut trois gestionnaires d'erreurs par défaut qui peuvent être utilisés :

  • MPI_ERRORS_ARE_FATAL provoque l'abandon du programme pour tous les processus MPI connectés.
  • MPI_ERRORS_ABORT est un gestionnaire d'erreurs qui peut être appelé sur un communicateur, une fenêtre, un fichier ou une session. Lorsqu'il est appelé sur un communicateur, il agit comme si MPI_Abort avait été appelé sur ce communicateur. S'il est appelé sur une fenêtre ou un fichier, il agit comme si MPI_Abort avait été appelé sur un communicateur contenant le groupe de processus dans la fenêtre ou le fichier correspondant. S'il est appelé sur une session, seul le processus local est abandonné.
  • MPI_ERRORS_RETURN retourne un code d'erreur à l'application.

Les applications MPI peuvent également implémenter leurs propres gestionnaires d'erreurs en appelant :

  • MPI_Comm_create_errhandler puis MPI_Comm_set_errhandler
  • MPI_File_create_errhandler puis MPI_File_set_errhandler
  • MPI_Session_create_errhandler puis MPI_Session_set_errhandler ou dans MPI_Session_init
  • MPI_Win_create_errhandler puis MPI_Win_set_errhandler

Note : Les applications MPI ne garantissent pas qu'un programme MPI puisse continuer après une erreur.

Consultez la page de manuel MPI pour une liste complète des codes d'erreur MPI.

Consultez la section de gestion des erreurs de la spécification MPI-3.1 pour plus d'informations.
