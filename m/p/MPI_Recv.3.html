MPI_Recv — Effectue une réception bloquante standard.

Syntaxe C

Syntaxe C

#include <mpi.h>
int MPI_Recv(void *buf, int count, MPI_Datatype datatype,
     int source, int tag, MPI_Comm comm, MPI_Status *status)

Syntaxe Fortran

USE MPI
! ancienne forme: INCLUDE 'mpif.h'
MPI_RECV(BUF, COUNT, DATATYPE, SOURCE, TAG, COMM, STATUS, IERROR)
     <type>  BUF(*)
     INTEGER COUNT, DATATYPE, SOURCE, TAG, COMM
     INTEGER STATUS(MPI_STATUS_SIZE), IERROR

Syntaxe Fortran 2008

USE mpi_f08
MPI_Recv(buf, count, datatype, source, tag, comm, status, ierror)
     TYPE(*), DIMENSION(..) :: buf
     INTEGER, INTENT(IN) :: count, source, tag
     TYPE(MPI_Datatype), INTENT(IN) :: datatype
     TYPE(MPI_Comm), INTENT(IN) :: comm
     TYPE(MPI_Status) :: status
     INTEGER, OPTIONAL, INTENT(OUT) :: ierror

Paramètres d'entrée

  • count: Nombre maximal d'éléments à recevoir (entier).
  • datatype: Type de chaque élément du buffer de réception (handle).
  • source: Rang de la source (entier).
  • tag: Étiquette de message (entier).
  • comm: Communicateur (handle).

Paramètres de sortie

  • buf: Adresse initiale du buffer de réception (optionnel).
  • status: Objet de statut (status).
  • ierror: Seulement en Fortran : État de l'erreur (entier).

Description

Cette opération de réception de base, MPI_Recv, est bloquante : elle ne retourne qu'après que le buffer de réception contient le message fraîchement reçu. Une réception peut se terminer avant que l'envoi correspondant soit terminé (naturellement, elle ne peut se terminer qu'après que l'envoi correspondant ait démarré).

La sémantique bloquante de cet appel est décrite dans la section « Modes de communication » de la norme MPI.

Le buffer de réception contient un nombre (défini par la valeur de count) d'éléments consécutifs. Le premier élément de cet ensemble d'éléments se trouve à l'adresse buf. Le type de chacun de ces éléments est spécifié par datatype.

La longueur du message reçu doit être inférieure ou égale à la longueur du buffer de réception. MPI_ERR_TRUNCATE est retourné en cas de dépassement.

Si un message plus court que la longueur du buffer de réception arrive, seuls les emplacements correspondant à la (plus courte) réception reçue sont modifiés.

Notes

L'argument count indique le nombre maximal d'entrées de type datatype qui peuvent être reçues dans un message. Une fois qu'un message est reçu, la fonction MPI_Get_count peut être utilisée pour déterminer le nombre réel d'entrées dans le message.

Pour recevoir des messages de longueur inconnue, la fonction MPI_Probe peut être utilisée. Pour plus d'informations sur MPI_Probe et MPI_Cancel, voir leurs pages man respectives et la section « Probe and Cancel » de la norme MPI.

Un message peut être reçu uniquement par une opération de réception s'il est destiné au processus de réception, et si ses valeurs de source, étiquette et communicateur (comm) correspondent à celles spécifiées par l'opération de réception. L'opération de réception peut spécifier une valeur de source et d'étiquette de type wildcard, indiquant que toute source et toute étiquette sont acceptables. La valeur wildcard pour la source est source = MPI_ANY_SOURCE. La valeur wildcard pour l'étiquette est tag = MPI_ANY_TAG. Il n'y a pas de valeur wildcard pour comm. La portée de ces valeurs wildcard est limitée aux processus du groupe spécifié.

La valeur de l'étiquette du message est spécifiée par l'argument tag de l'opération de réception.

L'argument source, s'il est différent de MPI_ANY_SOURCE, est spécifié comme le rang dans le groupe de processus associé à ce même communicateur (groupe de processus distant, pour les intercommunicateurs). Par conséquent, la plage des valeurs valides pour l'argument source est {0,…,n-1} {MPI_ANY_SOURCE}, où n est le nombre de processus dans ce groupe.

Notez l'asymétrie entre les opérations d'envoi et de réception : une opération de réception peut accepter des messages de n'importe quel expéditeur ; en revanche, une opération d'envoi doit spécifier un récepteur unique. Ceci correspond à un mécanisme de communication « push », où le transfert de données est effectué par l'expéditeur (plutôt qu'un mécanisme « pull » où le transfert de données est effectué par le récepteur).

La valeur source = destination est permise, c'est-à-dire qu'un processus peut s'envoyer un message à lui-même. Cependant, il est déconseillé d'utiliser les opérations d'envoi et de réception bloquantes décrites ci-dessus, car cela pourrait entraîner un blocage. Pour plus de détails, voir la section « Sémantique de communication point à point » de la norme MPI.

Si votre application n'a pas besoin d'examiner le champ de statut, vous pouvez économiser des ressources en utilisant la valeur par défaut de la constante MPI_STATUS_IGNORE comme valeur spéciale pour l'argument status de l'opération.

Erreurs

La plupart des routines MPI retournent une valeur d'erreur ; les routines C retournent le résultat de la fonction et les routines Fortran dans le dernier argument.

Avant que la valeur d'erreur ne soit retournée, le gestionnaire d'erreurs associé à l'objet de communication (par exemple, communicateur, fenêtre, fichier) actuel est appelé. S'il n'y a pas d'objet de communication associé à l'appel MPI, l'appel est considéré comme associé à MPI_COMM_SELF et le gestionnaire correspondant est appelé. Lorsque MPI_COMM_SELF n'est pas initialisé (c'est-à-dire avant MPI_Init/MPI_Init_thread, après MPI_Finalize, ou lorsque le modèle de Session est utilisé exclusivement), l'erreur déclenche le gestionnaire initial. Le gestionnaire initial peut être modifié en appelant MPI_Comm_set_errhandler sur MPI_COMM_SELF lorsque le modèle du Monde est utilisé, ou via l'argument mpi_initial_errhandler de mpiexec ou la clé d'information pour MPI_Comm_spawn/MPI_Comm_spawn_multiple. Si aucun autre gestionnaire approprié n'est configuré, le gestionnaire MPI_ERRORS_RETURN est appelé pour les fonctions d'E/S MPI et MPI_ERRORS_ABORT pour toutes les autres fonctions MPI.

Open MPI inclut trois gestionnaires d'erreurs par défaut qui peuvent être utilisés :

  • MPI_ERRORS_ARE_FATAL — Arrête tous les processus MPI connectés.
  • MPI_ERRORS_ABORT — Gestionnaire qui peut être invoqué sur un communicateur, une fenêtre, un fichier ou une session. Lorsqu'il est invoqué sur un communicateur, il agit comme si MPI_Abort avait été appelé sur ce communicateur. S'il est invoqué sur une fenêtre ou un fichier, il agit comme si MPI_Abort avait été appelé sur un communicateur contenant les processus de la fenêtre ou du fichier correspondant. S'il est invoqué sur une session, il arrête uniquement le processus local.
  • MPI_ERRORS_RETURN — Retourne un code d'erreur à l'application.

Les programmes MPI peuvent également implémenter leurs propres gestionnaires d'erreurs en appelant :

  • MPI_Comm_create_errhandler puis MPI_Comm_set_errhandler
  • MPI_File_create_errhandler puis MPI_File_set_errhandler
  • MPI_Session_create_errhandler puis MPI_Session_set_errhandler ou lors de MPI_Session_init
  • MPI_Win_create_errhandler puis MPI_Win_set_errhandler

Notez que MPI ne garantit pas qu'un programme MPI puisse continuer après une erreur.

Voir la section « Page de manuel MPI » pour une liste complète des codes d'erreur MPI.

Voir la section « Guide des erreurs » de la norme MPI-3.1 pour plus d'informations.

MPI_Recv(3) — Arch manual pages

NOM

MPI_Recv - Reçoit un message.

SYNTAXIS

C:
int MPI_Recv(void *buf, int count, MPI_Datatype datatype, int source,
             int tag, MPI_Comm comm, MPI_Status *status);

Fortran:
      SUBROUTINE MPI_RECV(BUF, COUNT, DATATYPE, SOURCE, TAG, COMM,
                        STATUS)
          IN OUT CHARACTER*(*) BUF
          IN INTEGER COUNT, DATATYPE, SOURCE, TAG
          IN INTEGER COMM
          OUT INTEGER STATUS(MPI_STATUS_SIZE)

DESCRIPTION

La routine MPI_Recv reçoit un message de la part du processus source sur le communicateur comm. Le message doit avoir été envoyé avec une opération d'envoi correspondante (par exemple, MPI_Send, MPI_Ssend, MPI_Sendrecv, ou MPI_Rsend). Le destinataire spécifie la taille du message attendu via les arguments count et datatype.

Le message est reçu dans le tampon buf. L'argument buf doit être suffisamment grand pour contenir le message reçu. Le nombre d'éléments dans le tampon est donné par count, et le type de chaque élément est donné par datatype.

Le processus source peut être MPI_ANY_SOURCE, auquel cas le message peut provenir de n'importe quel processus. Le processus tag peut être MPI_ANY_TAG, au auquel cas le message peut avoir n'importe quelle étiquette.

L'argument comm spécifie le communicateur sur lequel le message doit être reçu.

L'argument status est une structure qui contiendra des informations sur le message reçu, telles que la taille réelle du message, la source et l'étiquette du message.

PARAMETRES ENTREE

``buf``
Début du tampon de réception.
``count``
Nombre d'éléments du type spécifié dans le tampon.
``datatype``
Type de données des éléments du tampon.
``source``
Rang du processus d'envoi ou MPI_ANY_SOURCE.
``tag``
Étiquette du message ou MPI_ANY_TAG.
``comm``
Communicateur.

PARAMETRES SORTIE

``status``
Statut de la réception. Voir MPI_Status pour plus de détails.

NOTES

La routine MPI_Recv est une opération bloquante. Elle ne retourne que lorsque le message a été entièrement reçu dans le tampon spécifié.

Si la taille du message reçu est différente de celle spécifiée par count et datatype, les données excédentaires seront tronquées. Il est recommandé d'utiliser MPI_Get_count pour obtenir la taille réelle du message reçu.

ERREURS

Aucune.

La gestion des erreurs est effectuée par le gestionnaire d'erreurs qui est retourné. Le gestionnaire d'erreurs prédéfini MPI_ERRORS_RETURN exhibe ce comportement, par exemple.
