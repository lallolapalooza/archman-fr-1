Paquet: openmpi

Licences: BSD-3-Clause AND LicenseRef-MPICH

MPI_IPROBE(3) Open MPI MPI_IPROBE(3)

MPI_Iprobe — Test non bloquant pour un message.

SYNTAXE

Syntaxe C

#include <mpi.h>
int MPI_Iprobe(int source, int tag, MPI_Comm comm, int *flag,
     MPI_Status *status)

Syntaxe Fortran

USE MPI
! ou l'ancienne forme : INCLUDE 'mpif.h'
MPI_IPROBE(SOURCE, TAG, COMM, FLAG, STATUS, IERROR)
     LOGICAL FLAG
     INTEGER SOURCE, TAG, COMM, STATUS(MPI_STATUS_SIZE), IERROR

Syntaxe Fortran 2008

USE mpi_f08
MPI_Iprobe(source, tag, comm, flag, status, ierror)
     INTEGER, INTENT(IN) :: source, tag
     TYPE(MPI_Comm), INTENT(IN) :: comm
     LOGICAL, INTENT(OUT) :: flag
     TYPE(MPI_Status) :: status
     INTEGER, OPTIONAL, INTENT(OUT) :: ierror

PARAMETRES D'ENTRÉE

  • source : Rang de la source ou MPI_ANY_SOURCE (entier).
  • tag : Valeur de l'étiquette ou MPI_ANY_TAG (entier).
  • comm : Communicateur (handle).

PARAMETRES DE SORTIE

  • flag : Indicateur d'attente de message (logique).
  • status : Objet de statut (statut).
  • ierror : Fortran uniquement : Statut d'erreur (entier).

DESCRIPTION

Les opérations MPI_Probe et MPI_Iprobe permettent de vérifier les messages entrants sans les recevoir réellement. L'utilisateur peut alors décider comment les recevoir, en fonction des informations renvoyées par la sonde (principalement, les informations renvoyées par le statut). En particulier, l'utilisateur peut allouer de la mémoire pour le tampon de réception, conformément à la longueur du message sondé.

MPI_Iprobe(source, tag, comm, flag, status) renvoie flag = vrai s'il existe un message qui peut être reçu et qui correspond au modèle spécifié par les arguments source, tag et comm. L'appel correspond au même message qui aurait été reçu par un appel à MPI_Recv(..., source, tag, comm, status) exécuté au même point du programme, et renvoie dans status la même valeur qui aurait été renvoyée par MPI_Recv. Sinon, l'appel renvoie flag = faux, et laisse status indéfini.

Si MPI_Iprobe renvoie flag = vrai, alors le contenu de l'objet status peut être accédé ultérieurement comme décrit dans la sous-section « Statut de retour » du chapitre « Communication point à point » dans la Norme MPI pour trouver la source, l'étiquette et la longueur du message sondé.

Une réception ultérieure exécutée avec le même contexte, et la source et l'étiquette renvoyées dans status par MPI_Iprobe recevra le message qui a été mis en correspondance par la sonde si aucune autre réception intermédiaire n'intervient après la sonde. Si le processus de réception est multithreadé, il incombe à l'utilisateur de s'assurer que la dernière condition est remplie.

L'argument source de MPI_Probe peut être MPI_ANY_SOURCE, et l'argument tag peut être MPI_ANY_TAG, afin qu'on puisse sonder des messages provenant d'une source arbitraire et/ou ayant une étiquette arbitraire. Cependant, un contexte de communication spécifique doit être fourni avec l'argument comm.

Si votre application n'a pas besoin d'examiner le champ status, vous pouvez économiser des ressources en utilisant la constante prédéfinie MPI_STATUS_IGNORE comme valeur spéciale pour l'argument status.

Il n'est pas nécessaire de recevoir un message immédiatement après qu'il ait été sondé, et le même message peut être sondé plusieurs fois avant d'être reçu.

NOTE

Les développeurs d'applications multithreadées doivent se rappeler que deux threads appelant MPI_Iprobe peuvent renvoyer vrai pour le même message dans les deux threads.

ERREURS

Presque toutes les routines MPI renvoient une valeur d'erreur ; les routines C comme résultat de la fonction et les routines Fortran dans le dernier argument.

Avant que la valeur d'erreur ne soit renvoyée, le gestionnaire d'erreurs MPI actuellement associé à l'objet de communication (par exemple, communicateur, fenêtre, fichier) est appelé. S'il n'y a pas d'objet de communication associé à l'appel MPI, alors l'appel est considéré comme attaché à MPI_COMM_SELF et appellera le gestionnaire d'erreurs MPI associé. Lorsque MPI_COMM_SELF n'est pas initialisé (c'est-à-dire avant MPI_Init/MPI_Init_thread, après MPI_Finalize, ou lors de l'utilisation exclusive du modèle de sessions), l'erreur déclenche le gestionnaire d'erreurs initial. Le gestionnaire d'erreurs initial peut être modifié en appelant MPI_Comm_set_errhandler sur MPI_COMM_SELF lors de l'utilisation du modèle World, ou l'argument CLI mpi_initial_errhandler pour mpiexec ou la clé d'information pour MPI_Comm_spawn/MPI_Comm_spawn_multiple. Si aucun autre gestionnaire d'erreurs approprié n'a été défini, alors le gestionnaire d'erreurs MPI_ERRORS_RETURN est appelé pour les fonctions d'E/S MPI et le gestionnaire d'erreurs MPI_ERRORS_ABORT est appelé pour toutes les autres fonctions MPI.

Open MPI inclut trois gestionnaires d'erreurs prédéfinis qui peuvent être utilisés :

  • MPI_ERRORS_ARE_FATAL Provoque l'arrêt du programme pour tous les processus MPI connectés.
  • MPI_ERRORS_ABORT Un gestionnaire d'erreurs qui peut être appelé sur un communicateur, une fenêtre, un fichier ou une session. Lorsqu'il est appelé sur un communicateur, il agit comme si MPI_Abort avait été appelé sur ce communicateur. S'il est appelé sur une fenêtre ou un fichier, il agit comme si MPI_Abort avait été appelé sur un communicateur contenant le groupe de processus de la fenêtre ou du fichier correspondant. S'il est appelé sur une session, il n'interrompt que le processus local.
  • MPI_ERRORS_RETURN Renvoie un code d'erreur à l'application.

Les applications MPI peuvent également implémenter leurs propres gestionnaires d'erreurs en appelant :

  • MPI_Comm_create_errhandler puis MPI_Comm_set_errhandler
  • MPI_File_create_errhandler puis MPI_File_set_errhandler
  • MPI_Session_create_errhandler puis MPI_Session_set_errhandler ou lors de MPI_Session_init
  • MPI_Win_create_errhandler puis MPI_Win_set_errhandler

Notez que MPI ne garantit pas qu'un programme MPI puisse continuer après une erreur.

Voir la page de manuel MPI pour une liste complète des codes d'erreur MPI.

Voir la section Gestion des erreurs de la norme MPI-3.1 pour plus d'informations.

Notez que conformément à la section « Statut de retour » du chapitre « Communication point à point » de la Norme MPI, les erreurs MPI sur les messages interrogés par MPI_Iprobe ne définissent pas le champ status.MPI_ERROR dans le status renvoyé. Le code d'erreur est toujours passé au gestionnaire d'erreurs backend et peut être renvoyé à l'appelant via la valeur de retour de MPI_Iprobe si le gestionnaire d'erreurs backend le renvoie. Le gestionnaire d'erreurs MPI prédéfini MPI_ERRORS_RETURN présente ce comportement, par exemple.
