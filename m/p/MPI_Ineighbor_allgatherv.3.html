MPI_Neighbor_allgatherv, MPI_Ineighbor_allgatherv, MPI_Neighbor_allgatherv_init — Collecte et distribue des données depuis et vers tous les voisins. Chaque processus peut contribuer une quantité de données différente.

PARAMÈTRES D'ENTRÉE

  • sendbuf : Adresse de début du tampon d'envoi (facultatif).
  • sendcount : Nombre d'éléments dans le tampon d'envoi (entier).
  • sendtype : Type de données des éléments du tampon d'envoi (handle).
  • recvcount : Tableau d'entiers (de taille de groupe) contenant le nombre d'éléments reçus de chaque voisin.
  • displs : Tableau d'entiers (de taille de groupe). L'élément i spécifie le déplacement (relatif à recvbuf) où les données du voisin i seront placées.
  • recvtype : Type de données des éléments du tampon de réception (handle).
  • comm : Communicateur (handle).
  • info Info (handle, persistant uniquement). :

PARAMÈTRES DE SORTIE

  • recvbuf : Adresse du tampon de réception (facultatif).
  • request : Requête (handle, non bloquant uniquement).
  • ierror : Fortran uniquement : Valeur d'erreur (entier).

DESCRIPTION

MPI_Neighbor_allgatherv est similaire à MPI_Neighbor_allgather en ce sens que tous les processus collectent des données de tous les voisins, à ceci près que chaque processus peut envoyer une quantité de données différente. Le bloc de données envoyé par le voisin j est reçu par tous les voisins et placé dans le bloc j du tampon. L'ordre des voisins et du tampon est déterminé par la topologie de comm. recvbuf.

La signature de type associée à sendcount, sendtype, sur le processus j doit être égale à la signature de type associée à l'entrée correspondante dans recvcounts sur les voisins.

ORDRE DES VOISINS

Pour une topologie distribuée créée avec MPI_Dist_graph_create, la séquence des voisins dans les tampons d'envoi et de réception sur chaque processus est définie comme la séquence retournée par MPI_Dist_graph_neighbors pour les destinations et les origines respectivement. Pour une topologie générale créée avec MPI_Graph_create, la séquence des voisins dans les tampons d'envoi et de réception est définie comme la séquence des voisins retournée par MPI_Graph_neighbors. Il est à noter que les topologies générales devraient généralement être remplacées par des topologies distribuées.

Pour une topologie cartésienne créée avec MPI_Cart_create, la séquence des voisins dans les tampons d'envoi et de réception sur chaque processus est définie par l'ordre des dimensions, d'abord les voisins dans la direction négative puis dans la direction positive avec un déplacement de 1. Le nombre de sources et de destinations dans les routines de communication est de 2*ndims avec ndims défini dans MPI_Cart_create. Si un voisin n'existe pas, c'est-à-dire au bord d'une topologie cartésienne dans le cas d'un réseau virtuel non périodique (c'est-à-dire periods[...]==false), alors ce voisin est défini comme MPI_PROC_NULL.

Si un voisin dans l'une des fonctions est MPI_PROC_NULL, alors la communication collective se comporte comme une communication point à point avec MPI_PROC_NULL dans cette direction. C'est-à-dire que le tampon reste une partie de la séquence des voisins, mais il n'est ni communiqué ni mis à jour.

NOTES

L'option MPI_IN_PLACE pour sendbuf n'a pas de signification pour cette opération.

ERREURS

La plupart des routines MPI retournent une valeur d'erreur ; les routines C retournent le résultat de la fonction et les routines Fortran dans le dernier argument.

Avant que la valeur d'erreur ne soit retournée, le gestionnaire d'erreurs associé à l'objet de communication (par exemple, communicateur, fenêtre, fichier) est appelé. S'il n'y a pas d'objet de communication associé à l'appel MPI, l'appel est considéré comme associé à MPI_COMM_SELF et le gestionnaire correspondant est appelé. Lorsque MPI_COMM_SELF n'est pas initialisé (c'est-à-dire avant MPI_Init/MPI_Init_thread, après MPI_Finalize, ou lorsque le modèle de sessions est utilisé exclusivement), l'erreur déclenche le gestionnaire d'erreurs initial. Le gestionnaire d'erreurs initial peut être modifié en appelant MPI_Comm_set_errhandler sur MPI_COMM_SELF lorsque le modèle du Monde est utilisé, ou sur le paramètre mpi_initial_errhandler de mpiexec ou la clé d'info de MPI_Comm_spawn/MPI_Comm_spawn_multiple. S'il n'y a pas d'autre gestionnaire d'erreur approprié défini, le gestionnaire MPI_ERRORS_RETURN est appelé pour les fonctions d'E/S MPI et le gestionnaire MPI_ERRORS_ABORT pour toutes les autres fonctions MPI.
