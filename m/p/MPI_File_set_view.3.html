MPI_FILE_SET_VIEW(3) Open MPI MPI_FILE_SET_VIEW(3)

MPI_File_set_view — Modifie la vue des données dans le fichier par le processus (collectif).

SYNTAXE

Syntaxe C

#include <mpi.h>
int MPI_File_set_view(MPI_File fh, MPI_Offset disp,
     MPI_Datatype etype, MPI_Datatype filetype,
     const char *datarep, MPI_Info info)

Syntaxe Fortran

USE MPI
! ou la forme plus ancienne : INCLUDE 'mpif.h'
MPI_FILE_SET_VIEW(FH, DISP, ETYPE,
     FILETYPE, DATAREP, INFO, IERROR)
     INTEGER FH, ETYPE, FILETYPE, INFO, IERROR
     CHARACTER*(*)   DATAREP
     INTEGER(KIND=MPI_OFFSET_KIND)   DISP

Syntaxe Fortran 2008

USE mpi_f08
MPI_File_set_view(fh, disp, etype, filetype, datarep, info, ierror)
     TYPE(MPI_File), INTENT(IN) :: fh
     INTEGER(KIND=MPI_OFFSET_KIND), INTENT(IN) :: disp
     TYPE(MPI_Datatype), INTENT(IN) :: etype, filetype
     CHARACTER(LEN=*), INTENT(IN) :: datarep
     TYPE(MPI_Info), INTENT(IN) :: info
     INTEGER, OPTIONAL, INTENT(OUT) :: ierror

PARAMETRE ENTRÉE/SORTIE

•
fh: Descripteur de fichier (handle).

PARAMETRES ENTRÉE

  • disp: Déplacement (entier).
  • etype: Type de données élémentaire (handle).
  • filetype: Type de fichier (handle). Voir Restrictions, ci-dessous.
  • datarep: Représentation des données (chaîne).
  • info: Objet Info (handle).

PARAMETRE SORTIE

•
ierror: Fortran uniquement : Statut d'erreur (entier).

DESCRIPTION

La routine MPI_File_set_view modifie la vue du processus sur les données dans le fichier — le début des données accessibles dans le fichier par cette vue est défini à disp ; le type de données est défini à etype ; et la distribution des données aux processus est définie à filetype. De plus, MPI_File_set_view réinitialise les pointeurs de fichier indépendants et le pointeur de fichier partagé à zéro. MPI_File_set_view est collectif sur le fh ; tous les processus du groupe doivent passer des valeurs identiques pour datarep et fournir un etype avec une étendue identique. Les valeurs pour disp, filetype, et info peuvent varier. Il est erroné d'utiliser les routines d'accès aux données du pointeur de fichier partagé à moins que des valeurs identiques pour disp et filetype ne soient également fournies. Les types de données passés dans etype et filetype doivent être engagés.

L'argument de déplacement disp spécifie la position (décalage absolu en octets depuis le début du fichier) où la vue commence.

L'interface MPI_File_set_view permet à l'utilisateur de passer une chaîne de représentation de données à MPI I/O via l'argument datarep. Pour obtenir la valeur par défaut, passez la valeur “native”. L'utilisateur peut également passer des informations via l'argument info. Voir la section INDICES pour une liste des indices pouvant être définis.

INDICES

Les indices suivants peuvent être utilisés comme valeurs pour l'argument info.

INDICES POUVANT ÊTRE DÉFINIS

  • MPI_INFO_NULL
  • shared_file_timeout: Durée (en secondes) d'attente pour l'accès au pointeur de fichier partagé avant de sortir avec MPI_ERR_TIMEDOUT.
  • rwlock_timeout: Durée (en secondes) d'attente pour l'obtention d'un verrou de lecture ou d'écriture sur un bloc contigu d'un fichier UNIX avant de sortir avec MPI_ERR_TIMEDOUT.
  • noncoll_read_bufsize: Taille maximale du tampon utilisé par MPI I/O pour satisfaire les requêtes de lecture dans les routines d'accès aux données non collectives.

    NOTE :

Une taille de tampon inférieure à la distance (en octets) dans un fichier UNIX entre le premier octet et le dernier octet de la requête d'accès provoque l'itération de MPI I/O et l'exécution de multiples appels read() ou write() UNIX. Si la requête inclut plusieurs blocs de données non contigus, et que la taille du tampon est supérieure à la taille de ces blocs, alors le read() ou write() UNIX (effectué au niveau de MPI I/O) accédera à des données non demandées par ce processus afin de réduire le nombre total d'appels write() effectués. Si ce comportement n'est pas souhaitable, vous devriez réduire cette taille de tampon pour qu'elle soit égale à la taille des blocs contigus au sein de la requête agrégée.
  • noncoll_write_bufsize: Taille maximale du tampon utilisé par MPI I/O pour satisfaire les requêtes d'écriture dans les routines d'accès aux données non collectives.

    Voir la note ci-dessus dans noncoll_read_bufsize.

  • coll_read_bufsize: Taille maximale du tampon utilisé par MPI I/O pour satisfaire les requêtes de lecture dans les routines d'accès aux données collectives.

    Voir la note ci-dessus dans noncoll_read_bufsize.

  • coll_write_bufsize: Taille maximale du tampon utilisé par MPI I/O pour satisfaire les requêtes d'écriture dans les routines d'accès aux données collectives.

    Voir la note ci-dessus dans noncoll_read_bufsize.

  • mpiio_concurrency: (booléen) contrôle si les routines d'E/S non bloquantes peuvent lier un thread supplémentaire à un LWP.
  • mpiio_coll_contiguous: (booléen) contrôle si les accès aux données collectifs subséquents demanderont des régions contiguës collectivement dans le fichier.

INDICES NON POUVANT ÊTRE DÉFINIS

•
filename: Accédez à cet indice pour obtenir le nom du fichier.

ERREURS

Presque toutes les routines MPI retournent une valeur d'erreur ; les routines C comme résultat de retour de la fonction et les routines Fortran dans le dernier argument.

Avant que la valeur d'erreur ne soit retournée, le gestionnaire d'erreurs MPI actuel associé à l'objet de communication (par exemple, communicateur, fenêtre, fichier) est appelé. Si aucun objet de communication n'est associé à l'appel MPI, alors l'appel est considéré comme attaché à MPI_COMM_SELF et appellera le gestionnaire d'erreurs MPI associé. Lorsque MPI_COMM_SELF n'est pas initialisé (c'est-à-dire avant MPI_Init/MPI_Init_thread, après MPI_Finalize, ou lorsque le modèle de Sessions est utilisé exclusivement) l'erreur déclenche le gestionnaire d'erreurs initial. Le gestionnaire d'erreurs initial peut être modifié en appelant MPI_Comm_set_errhandler sur MPI_COMM_SELF lors de l'utilisation du modèle World, ou l'argument de ligne de commande mpi_initial_errhandler de mpiexec ou la clé d'information de MPI_Comm_spawn/MPI_Comm_spawn_multiple. Si aucun autre gestionnaire d'erreurs approprié n'a été défini, alors le gestionnaire d'erreurs MPI_ERRORS_RETURN est appelé pour les fonctions MPI I/O et le gestionnaire d'erreurs MPI_ERRORS_ABORT est appelé pour toutes les autres fonctions MPI.

Open MPI inclut trois gestionnaires d'erreurs prédéfinis qui peuvent être utilisés :

  • MPI_ERRORS_ARE_FATAL Provoque l'abandon du programme par tous les processus MPI connectés.
  • MPI_ERRORS_ABORT Un gestionnaire d'erreurs qui peut être invoqué sur un communicateur, une fenêtre, un fichier ou une session. Lorsqu'il est appelé sur un communicateur, il agit comme si MPI_Abort avait été appelé sur ce communicateur. S'il est appelé sur une fenêtre ou un fichier, agit comme si MPI_Abort avait été appelé sur un communicateur contenant le groupe de processus de la fenêtre ou du fichier correspondant. S'il est appelé sur une session, n'interrompt que le processus local.
  • MPI_ERRORS_RETURN Retourne un code d'erreur à l'application.

Les applications MPI peuvent également implémenter leurs propres gestionnaires d'erreurs en appelant :

  • MPI_Comm_create_errhandler puis MPI_Comm_set_errhandler
  • MPI_File_create_errhandler puis MPI_File_set_errhandler
  • MPI_Session_create_errhandler puis MPI_Session_set_errhandler ou à MPI_Session_init
  • MPI_Win_create_errhandler puis MPI_Win_set_errhandler

MPI_FILE_SET_VIEW

2023-01-01

NAME

MPI_File_set_view — Establishes a new view of the file associated with the given MPI_FILE.

SYNTAX

C/C++

int MPI_File_set_view(MPI_File fh, MPI_Offset disp, MPI_Datatype etype,
                      MPI_Datatype filetype, const char *datarep,
                      MPI_Info info);

Fortran

SUBROUTINE MPI_FILE_SET_VIEW(FH, DISP, ETYPE, FILETYPE, DATAREP, INFO,
                             IERROR)

Fortran 90

INTEGER FUNCTION MPI_FILE_SET_VIEW(FH, DISP, ETYPE, FILETYPE, DATAREP, INFO,
                                   IERROR)

INPUT/OUTPUT PARAMETER

FH
Un descripteur de fichier MPI. Ouvert par MPI_File_open.
DISP
Déplacement absolu dans le fichier pour le début de la vue. (Fortran 77, Fortran 90 seulement).
ETYPE
Type de données de base du fichier (par exemple, MPI_CHAR, MPI_INT).
FILETYPE
Type de données de fichier qui décrit la structure du fichier. Si MPI_DATATYPE_NULL, ETYPE est utilisé.
DATAREP
Représentation des données du fichier (par exemple, "native", "ascii", "ebcdic").
INFO
Objet d'informations MPI. Voir MPI_Info_create.
IERROR
Variable entière Fortran pour les erreurs.

INPUT PARAMETERS

DISP
Déplacement absolu dans le fichier pour le début de la vue. (C/C++ seulement).

OUTPUT PARAMETER

Aucun

DESCRIPTION

La fonction MPI_File_set_view établit une nouvelle vue du fichier associé au descripteur de fichier fh. La vue définit la façon dont les données du fichier sont organisées et interprétées par les processus MPI.

Le paramètre disp spécifie le décalage absolu dans le fichier où commence la nouvelle vue. Ce décalage est mesuré en unités de taille d'octet du fichier.

Le paramètre etype est un type de données MPI qui représente le type de données de base de chaque élément dans le fichier. Par exemple, si le fichier contient une matrice d'entiers, etype serait MPI_INT.

Le paramètre filetype est un type de données MPI qui décrit la structure globale du fichier. Il peut s'agir d'un type de données MPI dérivé qui représente une structure complexe de types de données de base. Si filetype est MPI_DATATYPE_NULL, le type de données du fichier est supposé être identique au type de données de base (etype).

Le paramètre datarep est une chaîne de caractères spécifiant la représentation des données du fichier. Les valeurs courantes incluent "native" (représentation native de la machine), "ascii" (représentation ASCII) et "ebcdic" (représentation EBCDIC). Il est recommandé d'utiliser "native" lorsque cela est possible pour garantir la portabilité.

Le paramètre info est un objet d'informations MPI qui peut être utilisé pour spécifier des options supplémentaires pour la vue de fichier, telles que la gestion des erreurs ou les caractéristiques d'accès aux fichiers. Il peut être créé en utilisant MPI_Info_create et peut être MPI_INFO_NULL s'il n'y a pas d'informations supplémentaires à fournir.

Une fois qu'une nouvelle vue de fichier a été définie à l'aide de MPI_File_set_view, toutes les opérations de fichier ultérieures sur ce descripteur de fichier utiliseront cette nouvelle vue jusqu'à ce qu'une autre vue soit définie ou que le fichier soit fermé.

HINTS

La vue de fichier est un concept clé dans le modèle de fichiers MPI, permettant une flexibilité considérable dans la façon dont les processus accèdent aux données d'un fichier. Les processus d'un groupe de communicateur MPI peuvent avoir des vues de fichier différentes du même fichier physique.

Il est de la responsabilité du programmeur de s'assurer que les types de données etype et filetype sont correctement définis pour refléter la structure réelle du fichier. Une définition incorrecte peut entraîner une corruption des données ou des erreurs d'accès.

Lorsque le paramètre datarep n'est pas "native", le système MPI peut effectuer des conversions de données entre la représentation du fichier et la représentation native des processus MPI. Cela peut avoir des implications sur les performances.

ERRORS

La fonction MPI_File_set_view peut échouer si une erreur se produit lors de la définition de la vue de fichier. Les codes d'erreur MPI courants incluent :

MPI_ERR_ARG
Un argument invalide a été passé à la fonction.
MPI_ERR_UNSUPPORTED_DATAREP
La représentation des données spécifiée n'est pas prise en charge.
MPI_ERR_IO
Une erreur d'entrée/sortie s'est produite.

Consultez la page de manuel *MPI* pour une liste complète des *codes d'erreur MPI*.

Consultez la section Gestion des erreurs de la norme MPI-3.1 pour plus d'informations.
