MPI_Fetch_and_op — Combine le contenu du buffer source avec celui d'un buffer destination et retourne la valeur du buffer destination.

SYNTAXE

C Syntaxe

#include <mpi.h>
int MPI_Fetch_and_op(const void *origin_addr, void *result_addr,
     MPI_Datatype datatype, int target_rank, MPI_Aint target_disp,
     MPI_Op op, MPI_Win win)

Fortran Syntaxe

USE MPI
! ou l'ancienne forme : INCLUDE 'mpif.h'
MPI_FETCH_AND_OP(ORIGIN_ADDR, RESULT_ADDR, DATATYPE, TARGET_RANK,
                 TARGET_DISP, OP, WIN, IERROR)
     <type> ORIGIN_ADDR, RESULT_ADDR(*)
     INTEGER(KIND=MPI_ADDRESS_KIND) TARGET_DISP
     INTEGER DATATYPE, TARGET_RANK, OP, WIN, IERROR

Fortran 2008 Syntaxe

USE mpi_f08
MPI_Fetch_and_op(origin_addr, result_addr, datatype, target_rank,
             target_disp, op, win, ierror)
     TYPE(*), DIMENSION(..), INTENT(IN) :: origin_addr
     TYPE(*), DIMENSION(..) :: result_addr
     TYPE(MPI_Datatype), INTENT(IN) :: datatype
     INTEGER, INTENT(IN) :: target_rank
     INTEGER(KIND=MPI_ADDRESS_KIND), INTENT(IN) :: target_disp
     TYPE(MPI_Op), INTENET(IN) :: op
     TYPE(MPI_Win), INTENT(IN) :: win
     INTEGER, OPTIONAL, INTENT(OUT) :: ierror

PARAMETRES D'ENTRÉE

  • origin_addr: Adresse du buffer source (choix).
  • result_addr: Adresse du buffer résultat (choix).
  • datatype: Type de données de l'élément dans les buffers source, résultat et destination (gestion).
  • target_rank: Rang de la destination (entier non négatif).
  • target_disp: Déplacement depuis le début de la fenêtre vers le début du buffer destination (entier non négatif).
  • op: Opération de réduction (gestion).
  • win: Objet fenêtre (gestion).

PARAMETRE DE SORTIE

•
ierror: Fortran uniquement : État d'erreur (entier).

DESCRIPTION

Acumule un élément de type datatype à partir du buffer source (origin_addr) dans le buffer au déplacement target_disp, dans le buffer destination de la fenêtre spécifiée par target_rank et win, en utilisant l'opération op et retourne dans le buffer résultat result_addr le contenu du buffer destination avant l'accumulation.

Les buffers source et résultat (origin_addr et result_addr) doivent être disjoints. Toute opération prédéfinie pour MPI_Reduce, ainsi que MPI_NO_OP ou MPI_REPLACE, peuvent être spécifiées comme op; les fonctions définies par l'utilisateur ne peuvent pas être utilisées. Le datatype doit être un type prédéfini. L'opération est exécutée atomiquement.

Une nouvelle opération prédéfinie, MPI_REPLACE, est définie. Celle-ci correspond à la fonction associative f(a, b) = b ; c'est-à-dire que la valeur actuelle dans la mémoire destination est remplacée par la valeur fournie par le buffer source.

Une nouvelle opération prédéfinie, MPI_NO_OP, est définie. Celle-ci correspond à la fonction associative f(a, b) = a ; c'est-à-dire que la valeur actuelle dans la mémoire destination est retournée dans le buffer résultat à la source et aucune opération n'est effectuée sur le buffer destination.

NOTES

Il est de la responsabilité de l'utilisateur de garantir que, lors de l'utilisation des fonctions d'accumulation, le déplacement de destination soit tel que les accès à la fenêtre soient correctement alignés selon les arguments de type de données dans l'appel à la fonction MPI_Fetch_and_op.

ERREURS

La plupart des routines MPI retournent une valeur d'erreur ; dans les routines C, le résultat de la fonction, et dans les routines Fortran, dans le dernier argument.

Avant que la valeur d'erreur ne soit retournée, le gestionnaire d'erreur associé à l'objet de communication (par exemple, communicator, window, file) actuel est appelé. Si aucun objet de communication n'est associé à l'appel MPI, l'appel est considéré comme associé à MPI_COMM_SELF et appellera le gestionnaire d'erreur correspondant. Lorsque MPI_COMM_SELF n'est pas initialisé (c'est-à-dire avant MPI_Init/MPI_Init_thread, après MPI_Finalize, ou lorsqu'on utilise exclusivement le modèle de Sessions), le gestionnaire d'erreur initial est levé. Le gestionnaire d'erreur initial peut être modifié en appelant MPI_Comm_set_errhandler sur MPI_COMM_SELF lorsque le modèle du Monde est utilisé, ou via l'argument mpi_initial_errhandler de mpiexec ou la clé info de MPI_Comm_spawn/MPI_Comm_spawn_multiple. Si aucun autre gestionnaire d'erreur approprié n'est trouvé, le gestionnaire d'erreur MPI_ERRORS_RETURN est appelé pour les fonctions d'E/S MPI et le gestionnaire d'erreur MPI_ERRORS_ABORT pour toutes les autres fonctions MPI.

Open MPI inclut trois gestionnaires d'erreur prédéfinis qui peuvent être utilisés:

  • MPI_ERRORS_ARE_FATAL : Arrête tous les processus connectés à MPI.
  • MPI_ERRORS_ABORT : Un gestionnaire qui peut être appelé sur un communicator, une window, un file ou une session. Lorsqu'il est appelé sur un communicator, il agit comme si MPI_Abort avait été appelé sur ce communicator. S'il est appelé sur une window ou un file, il agit comme si MPI_Abort avait été appelé sur un communicator contenant le groupe de processus dans la window ou le file correspondant. S'il est appelé sur une session, il arrête uniquement le processus local.
  • MPI_ERRORS_RETURN : Retourne un code d'erreur à l'application.

Les programmes MPI peuvent également implémenter leurs propres gestionnaires d'erreur en appelant :

  • MPI_Comm_create_errhandler puis MPI_Comm_set_errhandler
  • MPI_File_create_errhandler puis MPI_File_set_errhandler
  • MPI_Session_create_errhandler puis MPI_Session_set_errhandler ou lors de MPI_Session_init
  • MPI_Win_create_errhandler puis MPI_Win_set_errhandler

Note : Les programmes MPI ne garantissent pas qu'ils pourront continuer après une erreur.

Voir la page de manuel MPI pour une liste complète des codes d'erreur MPI.

Voir la section Gestionnaires d'erreur de la spécification MPI-3.1 pour plus d'informations.
