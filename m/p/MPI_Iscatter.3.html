MPI_Scatter, MPI_Iscatter, MPI_Scatter_init - Envoie des données d'une tâche à toutes les tâches d'un groupe.

PARAMETRES D'ENTRÉE

  • sendbuf: Adresse du tampon d'envoi (choix, significatif uniquement à la racine).
  • sendcount: Nombre d'éléments envoyés à chaque processus (entier, significatif uniquement à la racine).
  • sendtype: Type de données des éléments du tampon d'envoi (descripteur, significatif uniquement à la racine).
  • recvcount: Nombre d'éléments dans le tampon de réception (entier).
  • recvtype: Type de données des éléments du tampon de réception (descripteur).
  • root: Rang du processus d'envoi (entier).
  • comm: Communicateur (descripteur).
  • info: Informations (descripteur, persistant).

PARAMETRES DE SORTIE

  • recvbuf: Adresse du tampon de réception (choix).
  • request: Requête (descripteur, non bloquant uniquement).
  • ierror: Fortran uniquement : Statut d'erreur (entier).

DESCRIPTION

MPI_Scatter est l'opération inverse de MPI_Gather.

Le résultat est comme si la racine exécutait n opérations d'envoi,

MPI_Send(sendbuf + i * sendcount * extent(sendtype), sendcount,
         sendtype, i, ...);

et chaque processus exécutait une réception,

MPI_Recv(recvbuf, recvcount, recvtype, i, ...).;

Une description alternative est que la racine envoie un message avec MPI_Send(sendbuf, sendcount * n, sendtype, ...). Ce message est divisé en n segments égaux, le i-ème segment est envoyé au i-ème processus du groupe, et chaque processus reçoit ce message comme ci-dessus.

Le tampon d'envoi est ignoré pour tous les processus non-racines.

La signature de type associée à sendcount, sendtype à la racine doit être égale à la signature de type associée à recvcount, recvtype à tous les processus (cependant, les mappes de types peuvent être différentes). Cela implique que la quantité de données envoyées doit être égale à la quantité de données reçues, par paires entre chaque processus et la racine. Des maps de types distinctes entre l'expéditeur et le récepteur sont toujours autorisées.

Tous les arguments de la fonction sont significatifs sur le processus root, tandis que sur les autres processus, seuls les arguments recvbuf, recvcount, recvtype, root, comm sont significatifs. Les arguments root et comm doivent avoir des valeurs identiques sur tous les processus.

La spécification des comptes et des types ne doit pas entraîner la lecture d'un emplacement quelconque à la racine plus d'une fois.

Raison : Bien que non nécessaire, la dernière restriction est imposée afin d'obtenir une symétrie avec MPI_Gather, où la restriction correspondante (une restriction d'écriture multiple) est nécessaire.

Exemple : L'inverse de l'Exemple 1 de la page de manuel MPI_Gather. Diffusion de jeux de 100 entiers de la racine à chaque processus du groupe.

MPI_Comm comm;
int gsize,*sendbuf;
int root, rbuf[100];
...
MPI_Comm_size(comm, &gsize);
sendbuf = (int *)malloc(gsize*100*sizeof(int));
...
MPI_Scatter(sendbuf, 100, MPI_INT, rbuf, 100,
            MPI_INT, root, comm);

UTILISATION DE L'OPTION EN PLACE

Lorsque le communicateur est un intracommunicateur, vous pouvez effectuer une opération de diffusion en place (le tampon de sortie est utilisé comme tampon d'entrée). Utilisez la variable MPI_IN_PLACE comme valeur du recvbuf du processus racine. Dans ce cas, recvcount et recvtype sont ignorés, et le processus racine n'envoie aucune donnée à lui-même.

Notez que MPI_IN_PLACE est un type de valeur spécial ; il a les mêmes restrictions d'utilisation que MPI_BOTTOM.

Étant donné que l'option en place convertit le tampon de réception en un tampon d'envoi et de réception, une liaison Fortran qui inclut INTENT doit les marquer comme INOUT, et non OUT.

QUAND LE COMMUNICATEUR EST UN INTER-COMMUNICATEUR

Lorsque le communicateur est un inter-communicateur, le processus racine dans le premier groupe envoie des données à tous les processus dans le second groupe. Le premier groupe définit le processus racine. Ce processus utilise MPI_ROOT comme valeur de son argument root. Les processus restants utilisent MPI_PROC_NULL comme valeur de leur argument root. Tous les processus du second groupe utilisent le rang de ce processus racine dans le premier groupe comme valeur de leur argument root. L'argument de tampon de réception du processus racine dans le premier groupe doit être cohérent avec l'argument de tampon de réception des processus du second groupe.

ERREURS

Presque toutes les routines MPI renvoient une valeur d'erreur ; les routines C comme résultat de la fonction et les routines Fortran dans le dernier argument.

Avant que la valeur d'erreur ne soit renvoyée, le gestionnaire d'erreurs MPI actuel associé à l'objet de communication (par exemple, communicateur, fenêtre, fichier) est appelé. Si aucun objet de communication n'est associé à l'appel MPI, alors l'appel est considéré comme attaché à MPI_COMM_SELF et appellera le gestionnaire d'erreurs MPI associé.
