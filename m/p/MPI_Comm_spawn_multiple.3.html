MPI_Comm_spawn_multiple — Exécute plusieurs binaires, ou le même binaire avec différents ensembles d'arguments.

Syntaxe

Syntaxe C

#include <mpi.h>
int MPI_Comm_spawn_multiple(int count, char *array_of_commands[],
     char **array_of_argv[], const int array_of_maxprocs[], const MPI_Info
     array_of_info[], int root, MPI_Comm comm, MPI_Comm *intercomm,
     int array_of_errcodes[])

     TYPE(MPI_Comm), INTENT(OUT) :: INTERCOMM
     INTEGER :: ARRAY_OF_ERRCODES(*)

Paramètres d'entrée

  • count : Nombre de commandes (entier positif, significatif seulement sur le root — voir NOTES).
  • array_of_commands : Commandes à exécuter (tableau de chaînes, significatif seulement sur le root).
  • array_of_argv : Arguments pour les commandes (tableau de tableaux de chaînes, significatif seulement sur le root).
  • array_of_maxprocs : Nombre maximum de processus à lancer pour chaque commande (tableau d'entiers, significatif seulement sur le root).
  • array_of_info : Objets d'information indiquant au système d'exécution où et comment lancer les processus (tableau de handles, significatif seulement sur le root).
  • root : Rang du processus sur lequel les arguments précédents sont examinés (entier).
  • comm : Communicateur intracommunicateur contenant le groupe de processus à lancer (handle).

Paramètres de sortie

  • intercomm : Communicateur intercomunicateur entre le groupe original et le nouveau groupe de processus (handle).
  • array_of_errcodes : Code d'erreur par processus (tableau d'entiers).
  • ierror : En Fortran uniquement : État d'erreur (entier).

Description

MPI_Comm_spawn_multiple est identique à MPI_Comm_spawn sauf qu'il peut spécifier plusieurs binaires. Le premier argument, count, indique le nombre de binaires. Les trois arguments suivants sont des tableaux des arguments correspondants dans MPI_Comm_spawn. L'argument suivant, array_of_info, est un tableau de info arguments, un pour chaque binaire. Voir la section sur les arguments d'information pour plus d'informations.

Pour la version Fortran de array_of_argv, l'élément array_of_argv(i,j) est le j-ème argument de la commande numéro i.

Dans n'importe quel langage, une application peut utiliser la constante MPI_ARGVS_NULL (qui est probablement (char **)0 en C) pour spécifier qu'aucun argument ne devrait être passé à une commande quelconque. L'effet de la définition d'éléments individuels de array_of_argv à MPI_ARGV_NULL n'est pas défini. Pour spécifier des arguments pour certaines commandes mais pas pour d'autres, les commandes sans arguments devraient avoir un argv correspondant dont le premier élément est NULL (((char *)0 en C et chaîne vide en Fortran).

Tous les processus créés ont le même MPI_COMM_WORLD. Leurs rangs dans MPI_COMM_WORLD correspondent directement à l'ordre dans lequel les commandes sont spécifiées dans MPI_Comm_spawn_multiple. Supposons que m1 processus sont générés par la première commande, m2 par la seconde, etc. Les processus correspondant aux premières commandes ont les rangs 0, 1, ..., m1-1. Les processus de la deuxième commande ont les rangs m1, m1+1, ..., m1+m2-1. Les processus de la troisième commande ont les rangs m1+m2, m1+m2+1, ..., m1+m2+m3-1, etc.

L'argument array_of_errcodes est un tableau unidimensionnel de taille

 _ count
\       n ,
/_ i=1   i

où i est le i-ème élément de array_of_maxprocs. La commande numéro i correspond aux i espaces contigus dans ce tableau, allant de l'élément

                 _              _
 _ i-1          |   _ i          |
\       n ,  to |  \      n      | -1
/_ j=1   i      |  /_ j=1  j     |
                |_              _|

Les codes d'erreur sont traités comme dans MPI_Comm_spawn.

NAME

MPI_Comm_spawn_multiple - Spawn multiple, possibly different, programs.

SYNTAX

C:
    #include <mpi.h>
    int MPI_Comm_spawn_multiple(int count, char *array_of_commands[],
                                char *array_of_argv[][MPI_MAX_VARARGS],
                                int array_of_maxprocs[],
                                struct ompi_info_t *array_of_info[],
                                int root, MPI_Comm comm,
                                MPI_Comm *intercomm,
                                int array_of_errcodes[]);

Fortran:
    SUBROUTINE MPI_COMM_SPAWN_MULTIPLE(COUNT, ARRAY_OF_COMMANDS,
                                     ARRAY_OF_ARGV, ARRAY_OF_MAXPROCS,
                                     ARRAY_OF_INFO, ROOT, COMM,
                                     INTERCOMM, ARRAY_OF_ERRCODES,
                                     IERROR)
        INTEGER :: COUNT
        CHARACTER(LEN=*), DIMENSION(COUNT) :: ARRAY_OF_COMMANDS
        CHARACTER(LEN=*), DIMENSION(COUNT, *) :: ARRAY_OF_ARGV
        INTEGER :: ARRAY_OF_MAXPROCS(COUNT)
        TYPE(OMPI_INFO), DIMENSION(COUNT) :: ARRAY_OF_INFO
        INTEGER :: ROOT
        INTEGER :: COMM
        INTEGER :: INTERCOMM
        INTEGER :: ARRAY_OF_ERRCODES(COUNT)
        INTEGER :: IERROR
    END SUBROUTINE MPI_COMM_SPAWN_MULTIPLE

INPUT PARAMETERS

count
The number of commands to spawn. This argument is significant only at root.
array_of_commands
An array of commands to execute. Each element of the array is a command name. This argument is significant only at root. (Input)
array_of_argv
An array of argument vectors. Each element of the array is an argument vector for the corresponding command in array_of_commands. Each argument vector is an array of strings, terminated by a null pointer in C, or a blank string in Fortran. The first element of the argument vector (index 0) is typically the name of the command. This argument is significant only at root. (Input)
array_of_maxprocs
An array of the maximum number of processes to spawn for each command. Each element of the array corresponds to the element at the same index in array_of_commands. A value of MPI_MAX_PROCESSORS indicates no limit. This argument is significant only at root. (Input)
array_of_info
An array of MPI INFO objects, each providing hints for the spawn operation. Each element of the array corresponds to the element at the same index in array_of_commands. This argument is significant only at root. (Input)
root
The rank in the comm communicator of the process that is initiating the spawn operation. (Input)
comm
A communicator, all members of which the spawn operation is invoked. This communicator must be a Cartesian communicator or a general communicator. (Input)

OUTPUT PARAMETERS

intercomm
An intercommunicator between the local group and the newly spawned processes. This argument is significant only at root. (Output)
array_of_errcodes
An array of error codes associated with each spawn operation. Each element of the array corresponds to the element at the same index in array_of_commands. This argument is significant only at root. (Output)
IERROR
Fortran only: The Fortran status code. A value of 0 indicates success.

DESCRIPTION

MPI_Comm_spawn_multiple spawns multiple, possibly different, new MPI processes. The calling process can be a member of a communicator comm. All processes in comm must invoke MPI_Comm_spawn_multiple. The actual spawning is performed only by the process specified by the root argument.

The count argument indicates the number of commands to spawn. Each command is specified by a command name in array_of_commands and an associated argument vector in array_of_argv. The maximum number of processes to spawn for each command is specified in array_of_maxprocs. MPI_MAX_PROCESSORS can be used to indicate no limit.

The array_of_info argument contains MPI INFO objects that can be used to provide hints to the MPI implementation. These hints might include things like desired binding directives or mapper directives. See the INFO ARGUMENTS section for details.

The function returns an intercommunicator intercomm to the root process. This intercommunicator connects the root process (and potentially other processes in comm, depending on the value of the MPI_LOCALITY_COMM INFO key) to the set of spawned processes. The spawned processes receive a communicator that connects them to the root process of the spawning group.

Each element of the array_of_errcodes argument contains an error code associated with the spawn operation for the corresponding command. A value of MPI_SUCCESS indicates success. This argument is only relevant for the root process.

MPI_Comm_spawn_multiple is intended to be used for spawning multiple instances of the same executable or different executables. It is more flexible than MPI_Comm_spawn, which can only spawn multiple instances of a single executable.

Note that the count, array_of_argv, array_of_maxprocs, array_of_info, intercomm, and array_of_errcodes arguments are only significant for the process specified by the root argument. Other processes in the comm communicator must still provide valid arguments, but their values will be ignored.

INFO ARGUMENTS

The array_of_info argument is an array of MPI_Info objects. These objects are used to pass implementation-specific information to the MPI runtime system. The following is a list of commonly supported keys:

add_host
Add a host to the list of hosts to be used for spawning processes. The value is a comma-separated list of hostnames.
hostfile
Specify a file containing a list of hosts to be used for spawning processes.
file
Specify a file from which to load the list of hosts.
app
Specify an application file containing the list of executables and their arguments.
env
A newline-delimited list of environment variables to be passed to the spawned processes. If an environment variable already exists in the environment, the value will be overwritten by the provided value.
mapper
Mapper to be used for this job
map_by
Mapping directive indicating how processes are to be mapped (slot, node, socket, etc.).
rank_by
Ranking directive indicating how processes are to be ranked (slot, node, socket, etc.).
bind_to
Binding directive indicating how processes are to be bound (core, slot, node, socket, etc.).
path
List of directories to search for the executable
npernode
Number of processes to spawn on each node of the allocation
pernode
Equivalent to npernode of 1
ppr
Spawn specified number of processes on each of the identified object type
env
Newline-delimited list of envars to be passed to the spawned procs

bool info keys are actually strings but are evaluated as follows: if the string value is a number, it is converted to an integer and cast to a boolean (meaning that zero integers are false and non-zero values are true). If the string value is (case-insensitive) “yes” or “true”, the boolean is true. If the string value is (case-insensitive) “no” or “false”, the boolean is false. All other string values are unrecognized, and therefore false.

Note that if any of the info handles have ompi_non_mpi set to true, then all info handles must have it set to true. If some are set to true, but others are set to false (or are unset), MPI_ERR_INFO will be returned.

Note that in “#PACKAGE_NAME#”, the first array location in array_of_info is applied to all the commands in array_of_commands.

NOTES

The argument count is interpreted by MPI only at the root, as is array_of_argv. Since the leading dimension of array_of_argv is count, a nonpositive value of count at a nonroot node could theoretically cause a runtime bounds check error, even though array_of_argv should be ignored by the subroutine. If this happens, you should explicitly supply a reasonable value of count on the nonroot nodes.

Similar to MPI_Comm_spawn, it is the application’s responsibility to terminate each individual set of argv in the array_of_argv argument. In C, each argv array is terminated by a NULL pointer. In Fortran, each argv array is terminated by an empty string (note that compilers will not automatically insert this blank string; the application must ensure to have enough space for an empty string entry as the last element of the array).

Other restrictions apply to the array_of_argv parameter; see MPI_Comm_spawn’s description of the argv parameter for more details.

MPI-3.1 implies (but does not directly state) that the argument array_of_commands must be an array of strings of length count. Unlike the array_of_argv parameter, array_of_commands does not need to be terminated with a NULL pointer in C or a blank string in Fortran. Older versions of Open MPI required that array_of_commands be terminated with a blank string in Fortran; that is no longer required in this version of Open MPI.

Calling MPI_Comm_spawn many times would create many sets of children with different MPI_COMM_WORLDs, whereas MPI_Comm_spawn_multiple creates children with a single MPI_COMM_WORLD, so the two methods are not completely equivalent. Also if you need to spawn multiple executables, you may get better performance by using MPI_Comm_spawn_multiple instead of calling MPI_Comm_spawn several times.

ERRORS

Almost all MPI routines return an error value; C routines as the return result of the function and Fortran routines in the last argument.

Before the error value is returned, the current MPI error handler associated with the communication object (e.g., communicator, window, file) is called. If no communication object is associated with the MPI call, then the call is considered attached to MPI_COMM_SELF and will call the associated MPI error handler. When MPI_COMM_SELF is not initialized (i.e., before MPI_Init/MPI_Init_thread, after MPI_Finalize, or when using the Sessions Model exclusively) the error raises the initial error handler. The initial error handler can be changed by calling MPI_Comm_set_errhandler on MPI_COMM_SELF when using the World model, or the mpi_initial_errhandler CLI argument to mpiexec or info key to MPI_Comm_spawn/MPI_Comm_spawn_multiple. If no other appropriate error handler has been set, then the MPI_ERRORS_RETURN error handler is called for MPI I/O functions and the MPI_ERRORS_ABORT error handler is called for all other MPI functions.

Open MPI includes three predefined error handlers that can be used:

  • MPI_ERRORS_ARE_FATAL Causes the program to abort all connected MPI processes.
  • MPI_ERRORS_ABORT An error handler that can be invoked on a communicator, window, file, or session. When called on a communicator, it acts as if MPI_Abort was called on that communicator. If called on a window or file, acts as if MPI_Abort was called on a communicator containing the group of processes in the corresponding window or file. If called on a session, aborts only the local process.
  • MPI_ERRORS_RETURN Returns an error code to the application.

MPI applications can also implement their own error handlers by calling:

  • MPI_Comm_create_errhandler then MPI_Comm_set_errhandler
  • MPI_File_create_errhandler then MPI_File_set_errhandler
  • MPI_Session_create_errhandler then MPI_Session_set_errhandler or at MPI_Session_init
  • MPI_Win_create_errhandler then MPI_Win_set_errhandler

Note that MPI does not guarantee that an MPI program can continue past an error.

See the MPI man page for a full list of MPI error codes.

See the Error Handling section of the MPI-3.1 standard for more information.
