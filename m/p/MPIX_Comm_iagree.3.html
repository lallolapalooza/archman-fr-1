MPIX_Comm_iagree(3) Open MPI MPIX_Comm_iagree(3)

MPIX_Comm_agree, MPIX_Comm_iagree - S'accordent sur une valeur de drapeau binaire entre tous les processus vivants et distribuent le résultat à tous les processus vivants, même après la survenue de pannes.

Ceci fait partie de l'extension ULFM (User Level Fault Mitigation).

SYNTAXE

Syntaxe C

#include <mpi.h>
#include <mpi-ext.h>
int MPIX_Comm_agree(MPI_Comm comm, int *flag)
int MPIX_Comm_iagree(MPI_Comm comm, int *flag, MPI_Request *request)

Syntaxe Fortran

USE MPI
USE MPI_EXT
! ou l'ancienne forme: INCLUDE 'mpif.h'
MPIX_COMM_AGREE(COMM, FLAG, IERROR)
     INTEGER COMM, FLAG, IERROR
MPIX_COMM_IAGREE(COMM, FLAG, REQUEST, IERROR)
     INTEGER COMM, FLAG, REQUEST, IERROR

Syntaxe Fortran 2008

USE mpi_f08
USE mpi_ext_f08
MPIX_Comm_agree(comm, flag, ierror)
     TYPE(MPI_Comm), INTENT(IN) :: comm
     INTEGER, INTENT(INOUT) :: flag
     INTEGER, OPTIONAL, INTENT(OUT) :: ierror
MPIX_COMM_IAGREE(COMM, FLAG, REQUEST, IERROR)
     TYPE(MPI_Comm), INTENT(IN) :: comm
     INTEGER, INTENT(INOUT), ASYNCHRONOUS :: flag
     TYPE(MPI_Request), INTENT(OUT) :: request
     INTEGER, OPTIONAL, INTENT(OUT) :: ierror

PARAMÈTRES D'ENTRÉE

  • comm: Communicateur (handle).
  • flag: Drapeaux binaires (entier).

PARAMÈTRES DE SORTIE

  • flag: Drapeaux binaires réduits (entier).
  • request: Requête (handle, uniquement non bloquant).
  • ierror: Fortran uniquement : Statut d'erreur (entier).

DESCRIPTION

Cette communication collective s'accorde sur la valeur entière flag et (implicitement) le groupe des processus en panne dans comm.

Une fois terminée, tous les processus non défaillants de MPI se sont accordés pour définir la valeur de sortie de l'entier flag sur le résultat d'une opération AND bit à bit sur les valeurs d'entrée contribuées par flag.

MPIX_Comm_iagree est la version non bloquante de MPIX_Comm_agree.

PANNES DE PROCESSUS

Lorsqu'un processus MPI tombe en panne avant de contribuer à l'opération d'accord, le flag est calculé en ignorant sa contribution, et l'opération lève une erreur de classe MPIX_ERR_PROC_FAILED.

Lorsqu'une erreur de classe MPIX_ERR_PROC_FAILED est levée, elle est cohérente sur tous les processus MPI du ou des groupes de comm.

Après que MPIX_Comm_agree a levé une erreur de classe MPIX_ERR_PROC_FAILED, le groupe produit par un appel ultérieur à MPIX_Comm_get_failed sur comm contient tous les processus MPI qui n'ont pas contribué au calcul de flag.

QUAND LE COMMUNICATEUR CONTIENT DES PANNES ACCUSÉES DE RÉCEPTION

Si tous les processus MPI du groupe de comm ont accusé réception de la panne d'un processus MPI (en utilisant MPIX_Comm_ack_failed) avant l'appel à MPIX_Comm_agree (ou MPIX_Comm_iagree), l'erreur MPIX_ERR_PROC_FAILED n'est pas levée car la valeur de sortie de flag ignore la contribution de ce processus défaillant. Remarque : il s'agit d'une propriété uniforme : si un processus non contributeur qui n'est pas accusé de réception est rencontré par un quelconque processus vivant de comm, alors tous les processus lèvent une erreur de classe MPIX_ERR_PROC_FAILED.

Exemple 1 : En utilisant une combinaison de MPIX_Comm_ack_failed et MPIX_Comm_agree, les utilisateurs peuvent propager et synchroniser la connaissance des pannes parmi tous les processus MPI dans comm.

Comm_get_failed_consistent(MPI_Comm c, MPI_Group * g) {
    int rc; int T=1;
    int size; int num_acked;
    MPI_Group gf;
    int ranges[3] = {0, 0, 1};
    MPI_Comm_size(c, &size);
    do {
        /* cette routine n'est pas pure : l'appel à MPIX_Comm_ack_failed
         * affecte l'état du communicateur c */
        MPIX_Comm_ack_failed(c, size, &num_acked);
        /* ignore simplement la valeur T dans cet exemple */
        rc = MPIX_Comm_agree(c, &T);
    } while( rc != MPI_SUCCESS );
    /* après cette boucle, MPIX_Comm_agree est revenu MPI_SUCCESS sur
     * tous les processus, donc tous les processus ont accusé réception du même
     * ensemble de pannes. Nous allons récupérer cet ensemble de pannes dans le groupe g.
     */
    if( 0 == num_acked ) {
        *g = MPI_GROUP_EMPTY;
    }
    else {
        MPIX_Comm_get_failed(c, &gf);
        ranges[1] = num_acked - 1;
        MPI_Group_range_incl(gf, 1, ranges, g);
        MPI_Group_free(&gf);
    }
}

QUAND LE COMMUNICATEUR EST RÉVOQUÉ

Cette fonction ne lève jamais une erreur de classe MPIX_ERR_REVOKED. La signification définie de MPIX_Comm_agree est maintenue lorsque le communicateur comm est révoqué, ou lorsque le groupe de comm contient des processus MPI en panne. En particulier, MPIX_Comm_agree est une opération collective, même lorsque comm est révoqué.

QUAND LE COMMUNICATEUR EST UN INTER-COMMUNICATEUR

Lorsque le communicateur est un inter-communicateur, la valeur de flag est une opération AND bit à bit sur les valeurs apportées par le groupe distant.

Lorsqu'une erreur de classe MPIX_ERR_PROC_FAILED est levée, elle est cohérente sur tous les processus MPI du ou des groupes de comm, c'est-à-dire sur le groupe local et le groupe distant de l'inter-communicateur.

ERREURS

La plupart des routines MPI renvoient une valeur d'erreur ; dans les routines C, le résultat est la valeur de retour de la fonction, et dans les routines Fortran, le dernier argument est la valeur d'erreur.

Avant de renvoyer la valeur d'erreur, le gestionnaire d'erreur associé à l'objet de communication actuel (par exemple, communicateur, fenêtre, fichier) est appelé. S'il n'y a pas d'objet de communication associé à l'appel MPI, l'appel est considéré comme étant associé à MPI_COMM_SELF et le gestionnaire d'erreur correspondant est appelé. Lorsque MPI_COMM_SELF n'est pas initialisé (c'est-à-dire avant MPI_Init/MPI_Init_thread, après MPI_Finalize, ou lorsque le modèle de sessions est utilisé exclusivement), l'erreur déclenche le gestionnaire d'erreur initial. Le gestionnaire d'erreur initial peut être modifié en appelant MPI_Comm_set_errhandler sur MPI_COMM_SELF lorsque le modèle du monde est utilisé, ou sur l'argument mpi_initial_errhandler de mpiexec ou sur la clé d'information de MPI_Comm_spawn/MPI_Comm_spawn_multiple. Si aucun autre gestionnaire approprié n'est trouvé, le gestionnaire d'erreur MPI_ERRORS_RETURN est appelé pour les fonctions d'E/S MPI et le gestionnaire d'erreur MPI_ERRORS_ABORT pour toutes les autres fonctions MPI.

Open MPI comprend trois gestionnaires prédéfinis qui peuvent être utilisés :

  • MPI_ERRORS_ARE_FATAL Déclenche l'arrêt du programme pour tous les processus MPI connectés.
  • MPI_ERRORS_ABORT Un gestionnaire qui peut être invoqué sur un communicateur, une fenêtre, un fichier ou une session. Lorsqu'il est invoqué sur un communicateur, il agit comme si MPI_Abort avait été appelé sur ce communicateur. S'il est invoqué sur une fenêtre ou un fichier, il agit comme si MPI_Abort avait été appelé sur un communicateur contenant le groupe de processus dans la fenêtre ou le fichier correspondant. S'il est invoqué sur une session, il n'interrompt que le processus local.
  • MPI_ERRORS_RETURN Renvoie un code d'erreur à l'application.

Les applications MPI peuvent également implémenter leurs propres gestionnaires d'erreurs en appelant :

  • MPI_Comm_create_errhandler puis MPI_Comm_set_errhandler
  • MPI_File_create_errhandler puis MPI_File_set_errhandler
  • MPI_Session_create_errhandler puis MPI_Session_set_errhandler ou dans MPI_Session_init
  • MPI_Win_create_errhandler puis MPI_Win_set_errhandler

Remarque : les termes MPI ne sont pas garantis.
