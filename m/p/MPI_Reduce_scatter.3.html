MPI_Reduce_scatter, MPI_Ireduce_scatter, MPI_Reduce_scatter_init — Combina des valeurs et disperse les résultats.

PARAMÈTRES D'ENTRÉE

  • sendbuf: Adresse de début du tampon de sortie (optionnel).
  • recvcounts: Tableau entier spécifiant le nombre d'éléments dans le résultat distribué à chaque processus. Le tableau doit être identique sur tous les processus appelants.
  • datatype: Type des éléments du tampon d'entrée (descripteur).
  • op: Opération (descripteur).
  • comm: Communicateur (descripteur).
  • info: Informations (descripteur, persistant).

PARAMÈTRES DE SORTIE

  • recvbuf: Adresse de début du tampon de réception (optionnel).
  • request: Requête (descripteur, non bloquant).
  • ierror: En Fortran uniquement : État de l'erreur (entier).

DESCRIPTION

MPI_Reduce_scatter effectue une réduction élément par élément sur un vecteur de count = S(i)recvcounts[i] éléments dans le tampon d'entrée défini par sendbuf, count et datatype. Le vecteur résultant de la réduction est ensuite divisé en n segments distincts, où n est le nombre de processus dans le groupe. Le segment i contient recvcounts[i] éléments. Le segment i est envoyé au processus i et stocké dans le tampon de réception défini par recvbuf, recvcounts[i], et datatype.

UTILISATION DU CAS D'ENTRÉE OPTIONNEL

Lorsque le communicateur est un intracommanicoteur, une opération de réduction-dispersion peut être effectuée à la place (le tampon de sortie est utilisé comme tampon d'entrée). Utilisez la valeur MPI_IN_PLACE comme valeur de la variable sendbuf. Dans ce cas, les données d'entrée proviennent du haut du tampon de réception. La zone occupée par les données d'entrée peut être plus grande ou plus petite que les données enregistrées par le tampon de sortie.

QUAND LE COMMUNICATEUR EST UN COMMUNICATEUR INTER

Lorsque le communicateur est un communicateur inter, l'opération de réduction-dispersion se déroule en deux étapes. Premièrement, le résultat de la réduction effectuée sur les données fournies par les processus du premier groupe est dispersé entre les processus du second groupe. Ensuite, le processus inverse se produit : la réduction effectuée sur les données fournies par les processus du second groupe est dispersée entre les processus du premier groupe. Pour chaque groupe, tous les processus fournissent le même argument recvcounts, et la somme des valeurs de recvcounts doit être la même pour les deux groupes.

NOTES SUR LES OPÉRATIONS COLLECTIVES

Les fonctions de réduction (MPI_Op) ne renvoient pas de valeur d'erreur. Par conséquent, si les fonctions détectent une erreur, elles ne peuvent qu'appeler MPI_Abort ou ignorer le problème. Par conséquent, si vous changez le gestionnaire d'erreurs de MPI_ERRORS_ARE_FATAL à autre chose, par exemple, MPI_ERRORS_RETURN, aucune erreur ne sera indiquée.

La raison en est le problème de performance lié à la garantie que toutes les routines d'opérations collectives renvoient la même valeur d'erreur.

ERREURS

Plus de 90 % des routines MPI renvoient une valeur d'erreur ; les routines C la renvoient comme résultat de la fonction et les routines Fortran dans le dernier argument.

Avant de renvoyer la valeur d'erreur, le gestionnaire d'erreurs associé à l'objet de communication actuel (par exemple, communicateur, fenêtre, fichier) est appelé. S'il n'y a pas d'objet de communication associé à l'appel MPI, l'appel est considéré comme associé à MPI_COMM_SELF et le gestionnaire associé à MPI_COMM_SELF est appelé. Lorsque MPI_COMM_SELF n'est pas initialisé (c'est-à-dire avant MPI_Init/MPI_Init_thread, après MPI_Finalize, ou lorsque le modèle de sessions est utilisé exclusivement), le gestionnaire d'erreurs initial est déclenché. Le gestionnaire d'erreurs initial peut être modifié en appelant MPI_Comm_set_errhandler sur MPI_COMM_SELF lors de l'utilisation du modèle de monde, ou la clé d'information dans mpiexec ou la clé d'information dans MPI_Comm_spawn/MPI_Comm_spawn_multiple. S'il n'y a pas d'autre gestionnaire d'erreurs approprié, le gestionnaire d'erreurs MPI_ERRORS_RETURN est appelé pour les fonctions d'E/S MPI et le gestionnaire d'erreurs MPI_ERRORS_ABORT pour les autres fonctions MPI.

Open MPI inclut trois gestionnaires d'erreurs par défaut qui peuvent être utilisés :

  • MPI_ERRORS_ARE_FATAL — Arrête tous les processus MPI connectés.
  • MPI_ERRORS_ABORT — Gestionnaire qui peut être invoqué sur un communicateur, une fenêtre, un fichier ou une session. Lorsqu'il est invoqué sur un communicateur, il agit comme si MPI_Abort avait été appelé sur ce communicateur. S'il est invoqué sur une fenêtre ou un fichier, il agit comme si MPI_Abort avait été appelé sur un communicateur contenant les processus de la fenêtre ou du fichier correspondant. S'il est invoqué sur une session, il arrête uniquement le processus local.
  • MPI_ERRORS_RETURN — Renvoie un code d'erreur à l'application.

Les applications MPI peuvent également implémenter leurs propres gestionnaires d'erreurs en appelant :

  • MPI_Comm_create_errhandler puis MPI_Comm_set_errhandler
  • MPI_File_create_errhandler puis MPI_File_set_errhandler
  • MPI_Session_create_errhandler puis MPI_Session_set_errhandler

PARAMÈTRES D'ENTRÉE

  • Session

PARAMÈTRES DE SORTIE

  • Session

DESCRIPTION

La fonction MPI_Session_init initialise un objet session.

La fonction MPI_Win_create_errhandler crée un gestionnaire d'erreurs pour un objet fenêtre, qui est ensuite défini par MPI_Win_set_errhandler.

UTILISATION DE L'OPTION IN-PLACE

L'option in_place est utilisée pour spécifier si la fonction doit opérer en place.

QUAND LE COMMUNICATEUR EST UN INTER-COMMUNICATEUR

Lorsqu'un communicateur est un inter-communicateur, les fonctions MPI_Win_create et MPI_Win_set sont utilisées pour créer et définir le gestionnaire d'erreurs.

NOTES SUR LES OPÉRATIONS COLLECTIVES

Les opérations collectives nécessitent la participation de tous les processus, et la fonction MPI_Win_create est utilisée pour créer un objet fenêtre pour les opérations collectives.
