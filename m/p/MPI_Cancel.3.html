MPI_Cancel — Annule une requête de communication.

SYNTAX

Syntaxe C

#include <mpi.h>
int MPI_Cancel(MPI_Request *request)

Syntaxe Fortran

USE MPI
! ou l'ancienne forme : INCLUDE 'mpif.h'
MPI_CANCEL(REQUEST, IERROR)
    INTEGER REQUEST, IERROR

Syntaxe Fortran 2008

USE mpi_f08
MPI_Cancel(request, ierror)
    TYPE(MPI_Request), INTENT(IN) :: request
    INTEGER, OPTIONAL, INTENT(OUT) :: ierror

PARAMÈTRE D'ENTRÉE

•
request : Requête de communication (handle).

PARAMÈTRE DE SORTIE

•
ierror : Seulement Fortran : Statut d'erreur (entier).

DESCRIPTION

L'opération MPI_Cancel permet d'annuler des communications en attente. Ceci est requis pour le nettoyage. La publication d'un envoi ou d'une réception lie des ressources utilisateur (tampons d'envoi ou de réception), et une annulation peut être nécessaire pour libérer ces ressources gracieusement.

Un appel à MPI_Cancel marque pour annulation une opération de communication pendante, non bloquante (envoi ou réception). L'appel d'annulation est local. Il retourne immédiatement, potentiellement avant que la communication ne soit effectivement annulée. Il est toujours nécessaire de compléter une communication qui a été marquée pour annulation, en utilisant un appel à MPI_Request_free, MPI_Wait, ou MPI_Test (ou toute opération dérivée).

Si une communication est marquée pour annulation, alors un appel MPI_Wait pour cette communication est garanti de retourner, indépendamment des activités des autres processus (c'est-à-dire que MPI_Wait se comporte comme une fonction locale) ; de même, si MPI_Test est appelé de manière répétée dans une boucle d'attente active pour une communication annulée, alors MPI_Test réussira éventuellement.

MPI_Cancel peut être utilisé pour annuler une communication qui utilise une requête persistante (voir la Section 3.9 de la norme MPI, « Persistent Communication Requests ») de la même manière qu'il est utilisé pour les requêtes non persistantes. Une annulation réussie annule la communication active, mais pas la requête elle-même. Après l'appel à MPI_Cancel et l'appel subséquent à MPI_Wait ou MPI_Test, la requête devient inactive et peut être réactivée pour une nouvelle communication.

L'annulation réussie d'un envoi mis en tampon libère l'espace tampon occupé par le message en attente.

Soit l'annulation réussit, soit la communication réussit, mais pas les deux. Si un envoi est marqué pour annulation, alors il doit être le cas que soit l'envoi se termine normalement, auquel cas le message envoyé est reçu sur le processus de destination, soit que l'envoi est annulé avec succès, auquel cas aucune partie du message n'est reçue à la destination. Alors, toute réception correspondante doit être satisfaite par un autre envoi. Si une réception est marquée pour annulation, alors il doit être le cas que soit la réception se termine normalement, soit que la réception est annulée avec succès, auquel cas aucune partie du tampon de réception n'est altérée. Alors, tout envoi correspondant doit être satisfait par une autre réception.

Si l'opération a été annulée, alors des informations à cet effet seront retournées dans l'argument status de l'opération qui complète la communication.

NOTES

L'utilisation principale attendue de MPI_Cancel se situe dans les schémas de multi-mise en tampon, où des MPI_Irecvs spéculatifs sont effectués. Lorsque le calcul se termine, certaines de ces requêtes peuvent rester ; l'utilisation de MPI_Cancel permet à l'utilisateur d'annuler ces requêtes non satisfaites.

ERREURS

Presque toutes les routines MPI retournent une valeur d'erreur ; les routines C comme résultat de la fonction et les routines Fortran dans le dernier argument.

Avant que la valeur d'erreur ne soit retournée, le gestionnaire d'erreurs MPI actuel associé à l'objet de communication (par exemple, communicateur, fenêtre, fichier) est appelé. Si aucun objet de communication n'est associé à l'appel MPI, alors l'appel est considéré comme attaché à MPI_COMM_SELF et appellera le gestionnaire d'erreurs MPI associé. Lorsque MPI_COMM_SELF n'est pas initialisé (c'est-à-dire avant MPI_Init/MPI_Init_thread, après MPI_Finalize, ou lorsque vous utilisez exclusivement le modèle de sessions) l'erreur élève le gestionnaire d'erreurs initial. Le gestionnaire d'erreurs initial peut être modifié en appelant MPI_Comm_set_errhandler sur MPI_COMM_SELF lors de l'utilisation du modèle World, ou l'argument CLI mpi_initial_errhandler à mpiexec ou la clé info à MPI_Comm_spawn/MPI_Comm_spawn_multiple. Si aucun autre gestionnaire d'erreurs approprié n'a été défini, alors le gestionnaire d'erreurs MPI_ERRORS_RETURN est appelé pour les fonctions d'E/S MPI et le gestionnaire d'erreurs MPI_ERRORS_ABORT est appelé pour toutes les autres fonctions MPI.

Open MPI inclut trois gestionnaires d'erreurs prédéfinis qui peuvent être utilisés :

  • MPI_ERRORS_ARE_FATAL Provoque l'arrêt de tous les processus MPI connectés par le programme.
  • MPI_ERRORS_ABORT Un gestionnaire d'erreurs qui peut être invoqué sur un communicateur, une fenêtre, un fichier ou une session. Lorsqu'il est appelé sur un communicateur, il agit comme si MPI_Abort avait été appelé sur ce communicateur. S'il est appelé sur une fenêtre ou un fichier, il agit comme si MPI_Abort avait été appelé sur un communicateur contenant le groupe de processus dans la fenêtre ou le fichier correspondant. S'il est appelé sur une session, il n'interrompt que le processus local.
  • MPI_ERRORS_RETURN Retourne un code d'erreur à l'application.

Les applications MPI peuvent également implémenter leurs propres gestionnaires d'erreurs en appelant :

  • MPI_Comm_create_errhandler puis MPI_Comm_set_errhandler
  • MPI_File_create_errhandler puis MPI_File_set_errhandler
  • MPI_Session_create_errhandler puis MPI_Session_set_errhandler ou à MPI_Session_init
  • MPI_Win_create_errhandler puis MPI_Win_set_errhandler

Notez que MPI ne garantit pas qu'un programme MPI puisse continuer au-delà d'une erreur.

Voir la page de manuel MPI pour une liste complète des codes d'erreur MPI.

Voir la section Gestion des erreurs de la norme MPI-3.1 pour plus d'informations.
