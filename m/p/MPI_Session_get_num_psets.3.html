MPI_Session_get_num_psets — Interroger le runtime sur le nombre d'ensembles de processus disponibles

SYNTAXE

Syntaxe C

#include <mpi.h>
int MPI_Session_get_num_psets(MPI_Session session, MPI_Info info, int *npset_names)

Syntaxe Fortran

USE MPI
! ou l'ancienne forme : INCLUDE 'mpif.h'
MPI_SESSION_GET_NUM_PSETS(SESSION, INFO, NPSET_NAMES, IERROR)
    INTEGER SESSION, INFO, SESSION, IERROR

Syntaxe Fortran 2008

USE mpi_f08
MPI_Session_get_num_psets(session, info, npset_names, ierror)
    TYPE(MPI_Session), INTENT(IN) :: session
    TYPE(MPI_Info), INTENT(IN) :: info
    INTEGER, INTENT(OUT) :: npset_names
    INTEGER, OPTIONAL, INTENT(OUT) :: ierror

PARAMETRES D'ENTRÉE

  • session : session (descripteur)
  • info : objet info (descripteur)

PARAMETRES DE SORTIE

  • npset_names : nombre d'ensembles de processus disponibles (entier non négatif)
  • ierror : Fortran seulement : Statut d'erreur (entier).

DESCRIPTION

MPI_Session_get_num_psets est utilisé pour interroger le runtime sur le nombre d'ensembles de processus disponibles auxquels le processus MPI appelant appartient. Une implémentation MPI est autorisée à augmenter le nombre d'ensembles de processus disponibles pendant l'exécution d'une application MPI lorsque de nouveaux ensembles de processus deviennent disponibles. Cependant, les implémentations MPI ne sont pas autorisées à modifier l'index d'un nom d'ensemble de processus particulier, ni à modifier le nom de l'ensemble de processus à un index donné, ni à supprimer un nom d'ensemble de processus une fois qu'il a été ajouté.

NOTES

Lorsqu'un ensemble de processus devient invalide, par exemple, lorsque certains processus deviennent inaccessibles en raison de défaillances du système de communication, une utilisation ultérieure du nom de l'ensemble de processus peut entraîner une erreur. Par exemple, la création d'un MPI_Group à partir d'un tel ensemble de processus peut réussir car il s'agit d'une opération locale, mais la création d'un MPI_Comm à partir de ce groupe et la tentative de communication collective peuvent entraîner une erreur.

ERREURS

Presque toutes les routines MPI renvoient une valeur d'erreur ; les routines C comme résultat de la fonction et les routines Fortran dans le dernier argument.

Avant que la valeur d'erreur ne soit renvoyée, le gestionnaire d'erreurs MPI actuel associé à l'objet de communication (par exemple, communicateur, fenêtre, fichier) est appelé. Si aucun objet de communication n'est associé à l'appel MPI, l'appel est considéré comme attaché à MPI_COMM_SELF et appellera le gestionnaire d'erreurs MPI associé. Lorsque MPI_COMM_SELF n'est pas initialisé (c'est-à-dire, avant MPI_Init/MPI_Init_thread, après MPI_Finalize, ou lors de l'utilisation exclusive du modèle de Sessions) l'erreur déclenche le gestionnaire d'erreurs initial. Le gestionnaire d'erreurs initial peut être modifié en appelant MPI_Comm_set_errhandler sur MPI_COMM_SELF lors de l'utilisation du modèle World, ou l'argument CLI mpi_initial_errhandler de mpiexec ou la clé info de MPI_Comm_spawn/MPI_Comm_spawn_multiple. Si aucun autre gestionnaire d'erreurs approprié n'a été défini, alors le gestionnaire d'erreurs MPI_ERRORS_RETURN est appelé pour les fonctions d'E/S MPI et le gestionnaire d'erreurs MPI_ERRORS_ABORT est appelé pour toutes les autres fonctions MPI.

Open MPI inclut trois gestionnaires d'erreurs prédéfinis qui peuvent être utilisés :

  • MPI_ERRORS_ARE_FATAL Provoque l'arrêt du programme pour tous les processus MPI connectés.
  • MPI_ERRORS_ABORT Un gestionnaire d'erreurs qui peut être invoqué sur un communicateur, une fenêtre, un fichier ou une session. Lorsqu'il est appelé sur un communicateur, il agit comme si MPI_Abort avait été appelé sur ce communicateur. S'il est appelé sur une fenêtre ou un fichier, agit comme si MPI_Abort avait été appelé sur un communicateur contenant le groupe de processus de la fenêtre ou du fichier correspondant. S'il est appelé sur une session, il n'arrête que le processus local.
  • MPI_ERRORS_RETURN Renvoie un code d'erreur à l'application.

Les applications MPI peuvent également implémenter leurs propres gestionnaires d'erreurs en appelant :

  • MPI_Comm_create_errhandler puis MPI_Comm_set_errhandler
  • MPI_File_create_errhandler puis MPI_File_set_errhandler
  • MPI_Session_create_errhandler puis MPI_Session_set_errhandler ou lors de MPI_Session_init
  • MPI_Win_create_errhandler puis MPI_Win_set_errhandler

Notez que MPI ne garantit pas qu'un programme MPI puisse continuer après une erreur.

Voir la page de manuel MPI pour une liste complète des codes d'erreur MPI.

Voir la section Gestion des erreurs de la norme MPI-3.1 pour plus d'informations.
