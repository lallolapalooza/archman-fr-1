MPI_BSEND(3) Open MPI MPI_BSEND(3)

MPI_Bsend — Envoi basique avec mise en mémoire tampon spécifiée par l'utilisateur.

SYNTAXE

Syntaxe C

#include <mpi.h>
int MPI_Bsend(const void *buf, int count, MPI_Datatype datatype,
   int dest, int tag, MPI_Comm comm)

Syntaxe Fortran

USE MPI
! ou la forme plus ancienne : INCLUDE 'mpif.h'
MPI_BSEND(BUF, COUNT,DATATYPE, DEST, TAG, COMM, IERROR)
    <type>  BUF(*)
    INTEGER COUNT, DATATYPE, DEST, TAG, COMM, IERROR

Syntaxe Fortran 2008

USE mpi_f08
MPI_Bsend(buf, count, datatype, dest, tag, comm, ierror)
    TYPE(*), DIMENSION(..), INTENT(IN) :: buf
    INTEGER, INTENT(IN) :: count, dest, tag
    TYPE(MPI_Datatype), INTENT(IN) :: datatype
    TYPE(MPI_Comm), INTENT(IN) :: comm
    INTEGER, OPTIONAL, INTENT(OUT) :: ierror

PARAMÈTRES D'ENTRÉE

  • buf : Adresse initiale du tampon d'envoi (choix).
  • count : Nombre d'éléments dans le tampon d'envoi (entier non négatif).
  • datatype : Type de données de chaque élément du tampon d'envoi (handle).
  • dest : Rang de la destination (entier).
  • tag : Tag du message (entier).
  • comm : Communicateur (handle).

PARAMÈTRES DE SORTIE

•
ierror : Fortran uniquement : Statut d'erreur (entier).

DESCRIPTION

MPI_Bsend effectue un envoi bloquant en mode tamponné.

NOTES

Cet envoi est fourni comme une fonction pratique ; il permet à l'utilisateur d'envoyer des messages sans se soucier de l'endroit où ils sont mis en mémoire tampon (car l'utilisateur doit avoir fourni de l'espace tampon avec MPI_Buffer_attach).

Lors de la décision de l'espace tampon à allouer, souvenez-vous que l'espace tampon n'est pas disponible pour être réutilisé par des MPI_Bsend ultérieurs, sauf si vous êtes certain que le message a été reçu (pas seulement qu'il aurait dû être reçu). Par exemple, ce code n'alloue pas suffisamment d'espace tampon :

MPI_Buffer_attach( b, n*sizeof(double) + MPI_BSEND_OVERHEAD );
for (i=0; i<m; i++) {
    MPI_Bsend( buf, n, MPI_DOUBLE, ... );
}

car seul suffisamment d'espace tampon est fourni pour un seul envoi, et la boucle peut démarrer un deuxième MPI_Bsend avant que le premier ne soit terminé en utilisant le tampon.

En C, vous pouvez forcer la livraison des messages par MPI_Buffer_detach( &b, &n ); MPI_Buffer_attach( b, n ); (Le MPI_Buffer_detach ne se terminera pas tant que tous les messages tampons n'auront pas été livrés.)

ERREURS

Presque toutes les routines MPI renvoient une valeur d'erreur ; les routines C comme résultat de la fonction et les routines Fortran dans le dernier argument.

Avant que la valeur d'erreur ne soit renvoyée, le gestionnaire d'erreurs MPI actuel associé à l'objet de communication (par exemple, communicateur, fenêtre, fichier) est appelé. Si aucun objet de communication n'est associé à l'appel MPI, alors l'appel est considéré comme attaché à MPI_COMM_SELF et appellera le gestionnaire d'erreurs MPI associé. Lorsque MPI_COMM_SELF n'est pas initialisé (c'est-à-dire avant MPI_Init/MPI_Init_thread, après MPI_Finalize, ou lorsque vous utilisez exclusivement le modèle de sessions), l'erreur déclenche le gestionnaire d'erreurs initial. Le gestionnaire d'erreurs initial peut être modifié en appelant MPI_Comm_set_errhandler sur MPI_COMM_SELF lors de l'utilisation du modèle World, ou l'argument de ligne de commande mpi_initial_errhandler de mpiexec ou la clé d'informations de MPI_Comm_spawn/MPI_Comm_spawn_multiple. Si aucun autre gestionnaire d'erreurs approprié n'a été défini, alors le gestionnaire d'erreurs MPI_ERRORS_RETURN est appelé pour les fonctions E/S MPI et le gestionnaire d'erreurs MPI_ERRORS_ABORT est appelé pour toutes les autres fonctions MPI.

Open MPI inclut trois gestionnaires d'erreurs prédéfinis qui peuvent être utilisés :

  • MPI_ERRORS_ARE_FATAL Provoque l'arrêt du programme sur tous les processus MPI connectés.
  • MPI_ERRORS_ABORT Un gestionnaire d'erreurs qui peut être invoqué sur un communicateur, une fenêtre, un fichier ou une session. Lorsqu'il est appelé sur un communicateur, il agit comme si MPI_Abort avait été appelé sur ce communicateur. S'il est appelé sur une fenêtre ou un fichier, il agit comme si MPI_Abort avait été appelé sur un communicateur contenant le groupe de processus dans la fenêtre ou le fichier correspondant. S'il est appelé sur une session, il n'interrompt que le processus local.
  • MPI_ERRORS_RETURN Renvoie un code d'erreur à l'application.

Les applications MPI peuvent également implémenter leurs propres gestionnaires d'erreurs en appelant :

  • MPI_Comm_create_errhandler puis MPI_Comm_set_errhandler
  • MPI_File_create_errhandler puis MPI_File_set_errhandler
  • MPI_Session_create_errhandler puis MPI_Session_set_errhandler ou lors de MPI_Session_init
  • MPI_Win_create_errhandler puis MPI_Win_set_errhandler

Notez que MPI ne garantit pas qu'un programme MPI puisse continuer après une erreur.

Voir la page man MPI pour une liste complète des codes d'erreur MPI.

Voir la section Gestion des erreurs de la norme MPI-3.1 pour plus d'informations.
