MPI_Type_create_f90_complex(3) Open MPI MPI_Type_create_f90_complex(3) 
MPI_Type_create_f90_complex - Renvoie un type de données complexe avec des paramètres KIND spécifiés

Syntaxe

Syntaxe C

#include <mpi.h>
int MPI_Type_create_f90_complex(int p, int r,
     MPI_Datatype *newtype)

Syntaxe Fortran

USE MPI
! ou l'ancienne forme: INCLUDE 'mpif.h'
MPI_TYPE_CREATE_F90_COMPLEX (P, R, NEWTYPE, IERROR)
     INTEGER P, R, NEWTYPE, IERROR

Syntaxe Fortran 2008

USE mpi_f08
MPI_Type_create_f90_complex(p, r, newtype, ierror)
     INTEGER, INTENT(IN) :: p, r
     TYPE(MPI_Datatype), INTENT(OUT) :: newtype
     INTEGER, OPTIONAL, INTENT(OUT) :: ierror

Paramètres d'entrée

  • p: Précision, en chiffres décimaux (entier).
  • r: Étendue des exposants décimaux (entier).

Paramètres de sortie

  • newtype: Nouveau type de données (handle).
  • ierror: Fortran uniquement : code d'erreur (entier).

Description

Cette fonction permet de déclarer des types de données MPI complexes avec des paramètres KIND spécifiés. Les arguments sont interprétés de manière similaire à la fonction F90 SELECTED_REAL_KIND. Les paramètres p et r doivent être des entiers scalaires. Le paramètre p représente la précision requise en chiffres décimaux. Le paramètre r indique l'étendue des exposants désirés : le type de données renvoyé aura au moins un exposant compris entre +r et -r (inclus).

Soit p, soit r, mais pas les deux, peut être omis dans les appels à SELECTED_REAL_KIND. De même, un argument de MPI_Type_create_f90_complex peut être défini à MPI_UNDEFINED.

Notes

Il est considéré comme une erreur de fournir des valeurs pour p et r non prises en charge par le compilateur.

La fonction Fortran SELECTED_REAL_KIND associe un grand nombre de paires (p,r) à un plus petit nombre de paramètres KIND pris en charge par le compilateur. Les paramètres KIND ne sont pas spécifiés par le langage et ne sont pas portables. Du point de vue du langage, les variables du même type de base et du même paramètre KIND sont équivalentes, même si leurs paramètres KIND ont été générés par des arguments différents (p,r) à SELECTED_REAL_KIND. Cependant, pour faciliter l'interopérabilité dans un environnement hétérogène, l'équivalence est définie de manière plus stricte pour les types de données renvoyés par MPI_Type_create_f90_complex. Deux types de données MPI, chacun généré par cette fonction, correspondront si et seulement s'ils ont des valeurs identiques pour p et r.

L'interaction entre les types de données renvoyés par cette fonction et la représentation externe32 - utilisée par MPI_Pack_external, MPI_Unpack_external et de nombreuses fonctions MPI_File - est subtile. La représentation externe32 du type de données renvoyé est décrite ci-dessous.

if (p > 33) and/or (r > 4931):
        external32 size = n/a (undefined)
else if (p > 15) and/or (r > 307):
        external32 size = 32
else if (p > 6) and/or (r > 37):
        external32 size = 16
else:
        external32 size = 8

Si la représentation externe32 d'un type de données est indéfinie, il en va de même pour les résultats de l'utilisation de ce type de données dans des opérations nécessitant le format externe32. Vous devez veiller à ne pas utiliser indirectement des types de données incompatibles, par exemple, dans le cadre d'un autre type de données ou via un type dupliqué, dans ces fonctions.

Si une variable est déclarée en spécifiant une valeur KIND non par défaut qui n'a pas été obtenue avec SELECTED_REAL_KIND (c'est-à-dire que p et/ou r sont inconnus), la seule façon d'obtenir un type de données MPI correspondant est d'utiliser les fonctions MPI_Sizeof et MPI_Type_match_size.

Erreurs

Presque toutes les routines MPI renvoient une valeur d'erreur ; les routines C les renvoient comme résultat de fonction, les routines Fortran dans le dernier paramètre.

Le gestionnaire d'erreurs MPI actif associé à l'objet de communication (par exemple, communiteur, fenêtre, fichier) est appelé avant que la valeur d'erreur ne soit renvoyée. Si un appel MPI n'a aucun objet de communication associé, il est considéré comme associé à MPI_COMM_SELF, et ce gestionnaire d'erreurs MPI est appelé. Lorsque MPI_COMM_SELF n'est pas initialisé (c'est-à-dire avant MPI_Init/MPI_Init_thread, après MPI_Finalize, ou lorsqu'il n'utilise que le mode Sessions), les erreurs déclenchent le gestionnaire d'erreurs initial. Le gestionnaire d'erreurs initial peut être défini sur MPI_COMM_SELF en utilisant MPI_Comm_set_errhandler dans le mode World, ou via le paramètre mpi_initial_errhandler dans mpiexec ou une clé d'info. Si aucun autre gestionnaire d'erreurs approprié n'est défini, le gestionnaire d'erreurs MPI_ERRORS_RETURN sera utilisé pour les fonctions MPI I/O, et le gestionnaire d'erreurs MPI_ERRORS_ABORT sera utilisé pour les autres fonctions MPI.

Open MPI inclut trois gestionnaires d'erreurs prédéfinis qui peuvent être utilisés :

  • MPI_ERRORS_ARE_FATAL fait en sorte que le programme termine tous les processus MPI connectés.
  • MPI_ERRORS_ABORT est un gestionnaire d'erreurs qui peut être appelé sur un communiteur, une fenêtre, un fichier ou une session. Lorsqu'il est appelé sur un communiteur, il se comporte comme si MPI_Abort était appelé ; lorsqu'il est appelé sur une fenêtre ou un fichier, il se comporte comme si MPI_Abort était appelé sur le communiteur dont le groupe de processus contient la fenêtre ou le fichier correspondant ; lorsqu'il est appelé sur une session, il termine uniquement le processus local.
  • MPI_ERRORS_RETURN renvoie le code d'erreur à l'application.

Les applications MPI peuvent également implémenter leurs propres gestionnaires d'erreurs en appelant les fonctions suivantes :

  • MPI_Comm_create_errhandler puis MPI_Comm_set_errhandler
  • MPI_File_create_errhandler puis MPI_File_set_errhandler
  • MPI_Session_create_errhandler puis MPI_Session_set_errhandler ou lors de MPI_Session_init
  • MPI_Win_create_errhandler puis MPI_Win_set_errhandler

Notez que MPI ne garantit pas qu'un programme MPI puisse continuer après une erreur.

Veuillez consulter les pages de manuel MPI pour une liste complète des codes d'erreur MPI.

Veuillez consulter la section sur la gestion des erreurs de la norme MPI-3.1 pour plus d'informations.
