MPI_Alltoall, MPI_Ialltoall, MPI_Alltoall_init - Tous les processus envoient des données à tous les processus

PARAMETRES ENTRANTS

  • sendbuf: Adresse de départ du tampon d'envoi (choix).
  • sendcount: Nombre d'éléments à envoyer à chaque processus (entier).
  • sendtype: Type de données des éléments du tampon d'envoi (descripteur).
  • recvcount: Nombre d'éléments à recevoir de chaque processus (entier).
  • recvtype: Type de données des éléments du tampon de réception (descripteur).
  • comm: Communicateur sur lequel les données doivent être échangées (descripteur).
  • info: Informations (descripteur, seulement persistant)

PARAMETRES SORTANTS

  • recvbuf: Adresse de départ du tampon de réception (choix).
  • request: Requête (descripteur, seulement non bloquant).
  • ierror: Fortran uniquement : Statut d'erreur (entier).

DESCRIPTION

MPI_Alltoall est une opération collective au cours de laquelle tous les processus envoient la même quantité de données les uns aux autres, et en reçoivent la même quantité les uns des autres. L'opération de cette routine peut être représentée comme suit, où chaque processus effectue 2n (n étant le nombre de processus dans le communicateur comm) communications point à point indépendantes (y compris la communication avec lui-même).

MPI_Comm_size(comm, &n);
for (i = 0, i < n; i++)
    MPI_Send(sendbuf + i * sendcount * extent(sendtype),
        sendcount, sendtype, i, ..., comm);
for (i = 0, i < n; i++)
    MPI_Recv(recvbuf + i * recvcount * extent(recvtype),
        recvcount, recvtype, i, ..., comm);

Chaque processus découpe son sendbuf local en n blocs - chacun contenant sendcount éléments de type sendtype - et divise son recvbuf de manière similaire selon recvcount et recvtype. Le processus j envoie le k-ième bloc de son sendbuf local au processus k, qui place les données dans le j-ième bloc de son recvbuf local. La quantité de données envoyées doit être égale à la quantité de données reçues, par paire, entre chaque paire de processus.

QUAND LE COMMUNICATEUR EST UN INTER-COMMUNICATEUR

Lorsque le communicateur est un inter-communicateur, l'opération de regroupement se déroule en deux phases. Les données sont regroupées à partir de tous les membres du premier groupe et reçues par tous les membres du second groupe. Ensuite, les données sont regroupées à partir de tous les membres du second groupe et reçues par tous les membres du premier. L'opération présente un comportement symétrique et full-duplex.

Le premier groupe définit le processus racine. Le processus racine utilise MPI_ROOT comme valeur de root. Tous les autres processus du premier groupe utilisent MPI_PROC_NULL comme valeur de root. Tous les processus du second groupe utilisent le rang du processus racine dans le premier groupe comme valeur de root.

Lorsque le communicateur est un intra-communicateur, ces groupes sont les mêmes, et l'opération se déroule en une seule phase.

UTILISATION DE L'OPTION IN-PLACE

Lorsque le communicateur est un intra-communicateur, vous pouvez effectuer une opération all-to-all en place (le tampon de sortie est utilisé comme tampon d'entrée). Utilisez la variable MPI_IN_PLACE comme valeur de sendbuf. Dans ce cas, sendcount et sendtype sont ignorés. Les données d'entrée de chaque processus sont supposées se trouver dans la zone où ce processus recevrait sa propre contribution au tampon de réception.

NOTES

Tous les arguments sur tous les processus sont significatifs. Le paramètre comm, en particulier, doit décrire le même communicateur sur tous les processus.

Il existe deux fonctions de la bibliothèque MPI qui sont plus générales que MPI_Alltoall. MPI_Alltoallv permet une communication all-to-all vers et depuis des tampons qui n'ont pas besoin d'être contigus ; différents processus peuvent envoyer et recevoir différentes quantités de données. MPI_Alltoallw étend la fonctionnalité de MPI_Alltoallv pour permettre l'échange de données avec des types de données différents.

ERREURS

Presque toutes les routines MPI renvoient une valeur d'erreur ; les routines C comme résultat de retour de la fonction et les routines Fortran dans le dernier argument.

Avant que la valeur d'erreur ne soit retournée, le gestionnaire d'erreurs MPI actuel associé à l'objet de communication (par exemple, communicateur, fenêtre, fichier) est appelé. S'il n'y a pas d'objet de communication associé à l'appel MPI, alors l'appel est considéré comme attaché à MPI_COMM_SELF et appellera le gestionnaire d'erreurs MPI associé. Lorsque MPI_COMM_SELF n'est pas initialisé (c'est-à-dire, avant MPI_Init/MPI_Init_thread, après MPI_Finalize, ou en utilisant exclusivement le modèle de sessions) l'erreur déclenche le gestionnaire d'erreurs initial. Le gestionnaire d'erreurs initial peut être modifié en appelant MPI_Comm_set_errhandler sur MPI_COMM_SELF lors de l'utilisation du modèle World, ou l'argument CLI mpi_initial_errhandler pour mpiexec ou la clé d'information pour MPI_Comm_spawn/MPI_Comm_spawn_multiple. Si aucun autre gestionnaire d'erreurs approprié n'a été défini, alors le gestionnaire d'erreurs MPI_ERRORS_RETURN est appelé pour les fonctions E/S MPI et le gestionnaire d'erreurs MPI_ERRORS_ABORT est appelé pour toutes les autres fonctions MPI.
