MPIX_Comm_shrink(3)

Paquet: openmpi

Licences: BSD-3-Clause AND LicenseRef-MPICH

MPIX_COMM_SHRINK(3) Open MPI MPIX_COMM_SHRINK(3)

MPIX_Comm_shrink, MPIX_Comm_ishrink - Crée un nouveau communicateur qui inclut tous les processus du communicateur parent qui ne sont pas en échec.

Ceci fait partie de l'extension ULFM (User Level Fault Mitigation).

SYNTAX

Syntaxe C

#include <mpi.h>
#include <mpi-ext.h>
int MPIX_Comm_shrink(MPI_Comm comm, MPI_Comm *newcomm)
int MPIX_Comm_ishrink(MPI_Comm comm, MPI_Comm *newcomm, MPI_Request *request)

Syntaxe Fortran

USE MPI
USE MPI_EXT
! ou l'ancienne forme : INCLUDE 'mpif.h'
MPIX_COMM_SHRINK(COMM, NEWCOMM, IERROR)
     INTEGER COMM, NEWCOMM, IERROR
MPIX_COMM_ISHRINK(COMM, NEWCOMM, REQUEST, IERROR)
     INTEGER COMM, NEWCOMM, REQUEST, IERROR

Syntaxe Fortran 2008

USE mpi_f08
USE mpi_ext_f08
MPIX_Comm_shrink(comm, newcomm, ierror)
     TYPE(MPI_Comm), INTENT(IN) :: comm
     TYPE(MPI_Comm), INTENT(OUT) :: newcomm
     INTEGER, OPTIONAL, INTENT(OUT) :: ierror
MPIX_Comm_ishrink(comm, newcomm, request, ierror)
     TYPE(MPI_Comm), INTENT(IN) :: comm
     TYPE(MPI_Comm), INTENT(OUT), ASYNCHRONOUS :: newcomm
     TYPE(MPI_Request), INTENT(OUT) :: request
     INTEGER, OPTIONAL, INTENT(OUT) :: ierror

PARAMÈTRES D'ENTRÉE

•
comm: Communicateur (handle).

PARAMÈTRES DE SORTIE

  • newcomm: Communicateur (handle).
  • request: Requête (handle, non-bloquant uniquement).
  • ierror: Fortran uniquement : Statut d'erreur (entier).

DESCRIPTION

Cette opération collective crée un nouveau communicateur intra- ou intercommunicateur newcomm à partir du communicateur intra- ou intercommunicateur comm, respectivement, en excluant le groupe des processus MPI défaillants qui ont été réduits lors de l'opération.

Les groupes de newcomm doivent inclure chaque processus MPI qui revient de MPIX_Comm_shrink, et ils doivent exclure chaque processus MPI dont l'échec a causé une opération sur comm à générer une erreur MPI de classe MPIX_ERR_PROC_FAILED ou MPIX_ERR_PROC_FAILED_PENDING chez un membre des groupes de newcomm, avant que ce membre n'initie l'opération de réduction.

Autrement dit, cette procédure est sémantiquement équivalente à une opération MPI_Comm_split qui réussirait malgré les échecs, où les membres des groupes de newcomm participent avec la même couleur et une clé égale à leur rang dans comm.

MPIX_Comm_ishrink est la variante non bloquante de MPIX_Comm_shrink. Notez que, comme avec MPI_Comm_idup, il est erroné d'utiliser newcomm avant que request ne soit complété.

QUAND LE COMMUNICATEUR EST RÉVOQUÉ OU CONTIENT DES PROCESSUS DÉFAILLANTS

Cette fonction ne génère jamais d'erreur de classes MPIX_ERR_REVOKED ou MPIX_ERR_PROC_FAILED. Les sémantiques définies de MPIX_Comm_shrink et MPIX_Comm_ishrink sont maintenues lorsque comm est révoqué, ou lorsque le groupe de comm contient des processus MPI défaillants. En particulier, MPIX_Comm_shrink et MPIX_Comm_ishrink sont des opérations collectives, même lorsque comm est révoqué.

L'implémentation s'efforcera de détecter tous les échecs pendant l'opération de réduction, mais dans certaines circonstances, le groupe de newcomm peut encore contenir des processus MPI défaillants, dont l'échec sera détecté dans les opérations MPI ultérieures sur newcomm.

ERREURS

Presque toutes les routines MPI renvoient une valeur d'erreur ; les routines C comme résultat de la fonction et les routines Fortran dans le dernier argument.

Avant que la valeur d'erreur ne soit renvoyée, le gestionnaire d'erreurs MPI actuel associé à l'objet de communication (par exemple, communicateur, fenêtre, fichier) est appelé. Si aucun objet de communication n'est associé à l'appel MPI, alors l'appel est considéré comme attaché à MPI_COMM_SELF et appellera le gestionnaire d'erreurs MPI associé. Lorsque MPI_COMM_SELF n'est pas initialisé (c'est-à-dire, avant MPI_Init/MPI_Init_thread, après MPI_Finalize, ou lors de l'utilisation exclusive du modèle de sessions), l'erreur déclenche le gestionnaire d'erreurs initial. Le gestionnaire d'erreurs initial peut être modifié en appelant MPI_Comm_set_errhandler sur MPI_COMM_SELF lors de l'utilisation du modèle World, ou l'argument CLI mpi_initial_errhandler à mpiexec ou la clé d'information à MPI_Comm_spawn/MPI_Comm_spawn_multiple. Si aucun autre gestionnaire d'erreurs approprié n'a été défini, alors le gestionnaire d'erreurs MPI_ERRORS_RETURN est appelé pour les fonctions d'E/S MPI et le gestionnaire d'erreurs MPI_ERRORS_ABORT est appelé pour toutes les autres fonctions MPI.

Open MPI inclut trois gestionnaires d'erreurs prédéfinis qui peuvent être utilisés :

  • MPI_ERRORS_ARE_FATAL Provoque l'abandon du programme par tous les processus MPI connectés.
  • MPI_ERRORS_ABORT Un gestionnaire d'erreurs qui peut être invoqué sur un communicateur, une fenêtre, un fichier ou une session. Lorsqu'il est appelé sur un communicateur, il agit comme si MPI_Abort avait été appelé sur ce communicateur. S'il est appelé sur une fenêtre ou un fichier, il agit comme si MPI_Abort avait été appelé sur un communicateur contenant le groupe de processus dans la fenêtre ou le fichier correspondant. S'il est appelé sur une session, il n'abandonne que le processus local.
  • MPI_ERRORS_RETURN Renvoie un code d'erreur à l'application.

Les applications MPI peuvent également implémenter leurs propres gestionnaires d'erreurs en appelant :

  • MPI_Comm_create_errhandler puis MPI_Comm_set_errhandler
  • MPI_File_create_errhandler puis MPI_File_set_errhandler
  • MPI_Session_create_errhandler puis MPI_Session_set_errhandler ou lors de MPI_Session_init
  • MPI_Win_create_errhandler puis MPI_Win_set_errhandler

Notez que MPI ne garantit pas qu'un programme MPI puisse continuer après une erreur.

Voir la page man MPI pour une liste complète des codes d'erreur MPI.

Voir la section Gestion des erreurs de la norme MPI-3.1 pour plus d'informations.
