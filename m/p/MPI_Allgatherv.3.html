MPI_Allgatherv(3) Open MPI MPI_Allgatherv(3)

MPI_Allgatherv, MPI_Iallgatherv, MPI_Allgatherv_init - Collecte des données de tous les processus et les distribue à tous. Chaque processus peut contribuer une quantité de données différente.

Paramètres d'entrée

  • sendbuf: Adresse de début du tampon d'envoi (optionnel).
  • sendcount: Nombre d'éléments dans le tampon d'envoi (entier).
  • sendtype: Type de données des éléments du tampon d'envoi (handle).
  • recvcount: Tableau d'entiers (de taille du groupe) contenant le nombre d'éléments à recevoir de chaque processus.
  • displs: Tableau d'entiers (de taille du groupe). L'entrée i spécifie le déplacement (par rapport au tampon de réception) où les données de l'entrée du processus i seront placées.
  • recvtype: Type de données des éléments du tampon de réception (handle).
  • comm: Communicateur (handle).
  • info: Informations (handle, uniquement persistant).

Paramètres de sortie

  • recvbuf: Adresse du tampon de réception (optionnel).
  • request: Requête (handle, uniquement non bloquant).
  • ierror: En Fortran uniquement : code d'état d'erreur (entier).

Description

MPI_Allgatherv est similaire à MPI_Allgather en ce sens que tous les processus collectent des données de tous les autres processus, sauf que chaque processus peut envoyer une quantité de données différente. Le bloc de données envoyé par le processus j est reçu par tous les processus et placé dans le bloc j du tampon recvbuf.

La signature de type associée à sendcount, sendtype sur le processus j doit être égale à la signature de type associée à recvcounts[j], recvtype sur tout autre processus.

Le résultat est comme si tous les processus avaient exécuté des appels à

MPI_Allgatherv(sendbuf, sendcount, sendtype, recvbuf, recvcount,
              displs,recvtype,root,comm);
// pour root = 0, ..., n-1.

Les règles d'utilisation correcte de MPI_Allgatherv sont facilement trouvées dans les règles correspondantes de MPI_Gatherv.

Utilisation de l'option en place

Lorsque le communicateur est un intracommunicateur, une opération de rassemblement peut être effectuée en place (le tampon de sortie est utilisé comme tampon d'entrée). Utilisez la valeur MPI_IN_PLACE comme valeur de sendbuf. Dans ce cas, sendcount et sendtype sont ignorés. Les données d'entrée de chaque processus sont supposées se trouver dans la zone où ce processus recevrait sa propre contribution au tampon de réception. Plus précisément, le résultat d'un appel à MPI_Allgatherv utilisant l'option en place est identique au cas où tous les processus auraient exécuté n appels à

MPI_Allgatherv ( MPI_IN_PLACE, 0, MPI_DATATYPE_NULL, recvbuf,
                 recvcounts, displs, recvtype, root, comm );
// pour root =0, ... , n-1.

Note : MPI_IN_PLACE est une valeur de type spécial ; elle a les mêmes restrictions d'utilisation que MPI_BOTTOM.

Comme l'option en place transforme le tampon de réception en un tampon d'envoi et de réception, une liaison Fortran incluant INTENT doit les marquer comme INOUT, et non comme OUT.

Lorsque le communicateur est un intercommunicateur

Lorsque le communicateur est un intercommunicateur, l'opération de rassemblement se déroule en deux phases. Les données sont collectées auprès de tous les membres du premier groupe, concaténées, et reçues par tous les membres du second groupe. Ensuite, les données sont collectées auprès de tous les membres du second groupe, concaténées, et reçues par tous les membres du premier. Les arguments du tampon d'envoi dans le premier groupe doivent être cohérents avec les arguments du tampon de réception dans l'autre groupe, et vice versa. L'opération doit présenter un comportement symétrique et full-duplex.

Erreurs

En plus du fait que presque toutes les routines MPI renvoient une valeur d'erreur ; les routines C renvoient la valeur d'erreur comme résultat de la fonction et les routines Fortran dans le dernier argument.

Avant de renvoyer la valeur d'erreur, le gestionnaire d'erreurs associé à l'objet de communication (par exemple, communicateur, fenêtre, fichier) actuel est appelé. S'il n'y a pas d'objet de communication associé à l'appel MPI, l'appel est considéré comme associé à MPI_COMM_SELF et le gestionnaire d'erreurs associé à MPI_COMM_SELF sera appelé. Lorsque MPI_COMM_SELF n'est pas initialisé (c'est-à-dire avant MPI_Init/MPI_Init_thread, après MPI_Finalize, ou lorsque le modèle de session est utilisé exclusivement), l'erreur élève le gestionnaire d'erreurs initial. Le gestionnaire d'erreurs initial peut être modifié en appelant MPI_Comm_set_errhandler sur MPI_COMM_SELF lors de l'utilisation du modèle mondial, ou par l'option mpi_initial_errhandler de mpiexec ou par la clé info de MPI_Comm_spawn/MPI_Comm_spawn_multiple. Si aucun autre gestionnaire d'erreurs approprié n'existe, le gestionnaire d'erreurs MPI_ERRORS_RETURN sera appelé pour les fonctions d'E/S MPI et le gestionnaire d'erreurs MPI_ERRORS_ABORT pour toutes les autres fonctions MPI.
