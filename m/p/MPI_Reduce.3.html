MPI_Reduce, MPI_Ireduce, MPI_Reduce_init - Réduit les valeurs sur tous les processus d'un groupe.

PARAMÈTRES D'ENTRÉE

  • sendbuf: Adresse du tampon d'envoi (choix).
  • count: Nombre d'éléments dans le tampon d'envoi (entier).
  • datatype: Type de données des éléments du tampon d'envoi (handle).
  • op: Opération de réduction (handle).
  • root: Rang du processus racine (entier).
  • comm: Communicateur (handle).
  • info: Info (handle, persistant).

PARAMÈTRES DE SORTIE

  • recvbuf: Adresse du tampon de réception (choix, significatif uniquement à la racine).
  • request: Requête (handle, non bloquant uniquement).
  • ierror: Fortran uniquement : Statut d'erreur (entier).

DESCRIPTION

Les fonctions de réduction globale (MPI_Reduce, MPI_Op_create, MPI_Op_free, MPI_Allreduce, MPI_Reduce_scatter, MPI_Scan) effectuent une opération de réduction globale (telle que somme, maximum, OU logique, etc.) sur tous les membres d'un groupe. L'opération de réduction peut être soit une parmi une liste prédéfinie d'opérations, soit une opération définie par l'utilisateur. Les fonctions de réduction globale existent sous plusieurs formes : une réduction qui renvoie le résultat de la réduction sur un nœud, une all-réduction qui renvoie ce résultat sur tous les nœuds, et une opération scan (préfixe parallèle). De plus, une opération reduce-scatter combine la fonctionnalité d'une opération de réduction et de diffusion.

MPI_Reduce combine les éléments fournis dans le tampon d'entrée de chaque processus du groupe, en utilisant l'opération op, et renvoie la valeur combinée dans le tampon de sortie du processus de rang root. Le tampon d'entrée est défini par les arguments sendbuf, count et datatype ; le tampon de sortie est défini par les arguments recvbuf, count et datatype ; les deux ont le même nombre d'éléments, avec le même type. La routine est appelée par tous les membres du groupe en utilisant les mêmes arguments pour count, datatype, op, root et comm. Ainsi, tous les processus fournissent des tampons d'entrée et de sortie de la même longueur, avec des éléments du même type. Chaque processus peut fournir un élément, ou une séquence d'éléments, auquel cas l'opération de combinaison est exécutée élément par élément sur chaque entrée de la séquence. Par exemple, si l'opération est MPI_MAX et que le tampon d'envoi contient deux éléments qui sont des nombres à virgule flottante (count = 2 et datatype = MPI_FLOAT), alors recvbuf(1) = max global (sendbuf(1)) et recvbuf(2) = max global(sendbuf(2)).

UTILISATION DE L'OPTION EN PLACE

Lorsque le communicateur est un intracommunicateur, vous pouvez effectuer une opération de réduction en place (le tampon de réception est utilisé comme tampon d'entrée). Utilisez la variable MPI_IN_PLACE comme valeur du sendbuf du processus racine. Dans ce cas, les données d'entrée sont prises à la racine depuis le tampon de réception, où elles seront remplacées par les données de sortie.

Notez que MPI_IN_PLACE est un type de valeur spécial ; il a les mêmes restrictions d'utilisation que MPI_BOTTOM.

Étant donné que l'option en place convertit le tampon de réception en un tampon d'envoi et de réception, une liaison Fortran qui inclut INTENT doit les marquer comme INOUT, et non comme OUT.

QUAND LE COMMUNICATEUR EST UN INTER-COMMUNICATEUR

Lorsque le communicateur est un inter-communicateur, le processus racine du premier groupe combine les données de tous les processus du second groupe, puis effectue l'opération op. Le premier groupe définit le processus racine. Ce processus utilise MPI_ROOT comme valeur de son argument root. Les processus restants utilisent MPI_PROC_NULL comme valeur de leur argument root. Tous les processus du second groupe utilisent le rang de ce processus racine dans le premier groupe comme valeur de leur argument root. Seuls les arguments du tampon d'envoi sont significatifs dans le second groupe, et seuls les arguments du tampon de réception sont significatifs dans le processus racine du premier groupe.

OPÉRATIONS DE RÉDUCTION PRÉDÉFINIES

L'ensemble des opérations prédéfinies fournies par MPI est listé ci-dessous (Opérations de réduction prédéfinies). Cette section énumère également les types de données sur lesquels chaque opération peut être appliquée. De plus, les utilisateurs peuvent définir leurs propres opérations qui peuvent être surchargées pour fonctionner sur plusieurs types de données, qu'ils soient de base ou dérivés. Ceci est expliqué plus en détail dans la description des opérations définies par l'utilisateur (voir les pages de manuel pour MPI_Op_create et MPI_Op_free).

L'opération op est toujours supposée être associative. Toutes les opérations prédéfinies sont également supposées être commutatives. Les utilisateurs peuvent définir des opérations qui sont supposées être associatives, mais pas commutatives. L'ordre d'évaluation « canonique » d'une réduction est déterminé par les rangs des processus dans le groupe. Cependant, l'implémentation peut tirer parti de l'associativité, ou de l'associativité et de la commutativité, afin de modifier l'ordre d'évaluation. Cela peut modifier le résultat de la réduction pour les opérations qui ne sont pas strictement associatives et commutatives, telles que l'addition en virgule flottante.

Les opérateurs prédéfinis ne fonctionnent qu'avec les types MPI listés ci-dessous (Opérations de réduction prédéfinies, et la section MINLOC et MAXLOC, ci-dessous). Les opérateurs définis par l'utilisateur peuvent fonctionner sur des types de données dérivés généraux. Dans ce cas, chaque argument sur lequel l'opération de réduction est appliquée est un élément décrit par un tel type de données, qui peut

contient plusieurs valeurs de base. Ceci est expliqué plus en détail dans la section 4.9.4 de la norme MPI, « Opérations définies par l'utilisateur ».

Les opérations prédéfinies suivantes sont fournies pour MPI_Reduce et les fonctions associées MPI_Allreduce , MPI_Reduce_scatter et MPI_Scan . Ces opérations sont appelées en plaçant ce qui suit dans op :

Exemple 1 : Une routine qui calcule le produit scalaire de deux vecteurs distribués sur un groupe de processus et retourne le résultat au processus zéro.

SUBROUTINE PAR_BLAS1(m, a, b, c, comm)
REAL a(m), b(m)       ! tranche locale du tableau
REAL c                ! résultat (au processus zéro)
REAL sum
INTEGER m, comm, i, ierr
! somme locale
sum = 0.0
DO i = 1, m
   sum = sum + a(i)*b(i)
END DO
! somme globale
CALL MPI_REDUCE(sum, c, 1, MPI_REAL, MPI_SUM, 0, comm, ierr)
RETURN

Exemple 2 : Une routine qui calcule le produit d'un vecteur et d'un tableau distribués sur un groupe de processus et retourne le résultat au processus zéro.

SUBROUTINE PAR_BLAS2(m, n, a, b, c, comm)
REAL a(m), b(m,n)    ! tranche locale du tableau
REAL c(n)            ! résultat
REAL sum(n)
INTEGER n, comm, i, j, ierr
! somme locale
DO j= 1, n
  sum(j) = 0.0
  DO i = 1, m
    sum(j) = sum(j) + a(i)*b(i,j)
  END DO
END DO
! somme globale
CALL MPI_REDUCE(sum, c, n, MPI_REAL, MPI_SUM, 0, comm, ierr)
! retourne le résultat au processus zéro (et des données incorrectes sur les autres nœuds)
RETURN

MINLOC ET MAXLOC

L'opérateur MPI_MINLOC est utilisé pour calculer un minimum global et également un indice associé à la valeur minimale. MPI_MAXLOC calcule de manière similaire un maximum global et son indice. Une application de ceux-ci est de calculer un minimum (maximum) global et le rang du processus contenant cette valeur.

L'opération qui définit MPI_MAXLOC est

         ( u )    (  v )      ( w )
         (   )  o (    )   =  (   )
         ( i )    (  j )      ( k )
où
    w = max(u, v)
et
         ( i            si u > v
         (
   k   = ( min(i, j)    si u = v
         (
         (  j           si u < v)

MPI_MINLOC est défini de manière similaire :

         ( u )    (  v )      ( w )
         (   )  o (    )   =  (   )
         ( i )    (  j )      ( k )
où
    w = min(u, v)
et
         ( i            si u < v
         (
   k   = ( min(i, j)    si u = v
         (
         (  j           si u > v)

Les deux opérations sont associatives et commutatives. Notez que si MPI_MAXLOC est appliqué pour réduire une séquence de paires (u(0), 0), (u(1), 1), ..., (u(n-1), n-1), alors la valeur retournée est (u , r), où u= max(i) u(i) et r est l'indice du premier maximum global dans la séquence. Ainsi, si chaque processus fournit une valeur et son rang au sein du groupe, alors une opération de réduction avec op = MPI_MAXLOC retournera la valeur maximale et le rang du premier processus ayant cette valeur. De même, MPI_MINLOC peut être utilisé pour retourner un minimum et son indice. Plus généralement, MPI_MINLOC calcule un minimum lexicographique, où les éléments sont ordonnés selon le premier composant de chaque paire, et les égalités sont résolues selon le second composant.

L'opération de réduction est définie pour opérer sur des arguments qui consistent en une paire : valeur et indice. Pour Fortran et C, des types sont fournis pour décrire la paire. La nature potentiellement mixte de tels arguments est un problème en Fortran. Le problème est contourné, pour Fortran, en faisant en sorte que le type fourni par MPI consiste en une paire du même type que la valeur, et en forçant également l'indice à ce type. En C, le type de paire fourni par MPI a des types distincts et l'indice est un int.

Afin d'utiliser MPI_MINLOC et MPI_MAXLOC dans une opération de réduction, il faut fournir un argument de type de données qui représente une paire (valeur et indice). MPI fournit neuf types de données prédéfinis. Les opérations MPI_MAXLOC et MPI_MINLOC peuvent être utilisées avec chacun des types de données suivants :

Fortran :
Nom                     Description
MPI_2REAL                paire de REALs
MPI_2DOUBLE_PRECISION    paire de variables DOUBLE_PRECISION
MPI_2INTEGER             paire d'INTEGERs
C :
Nom                     Description
MPI_FLOAT_INT            float et int
MPI_DOUBLE_INT           double et int
MPI_LONG_INT             long et int
MPI_2INT                 paire d'ints
MPI_SHORT_INT            short et int
MPI_LONG_DOUBLE_INT      long double et int

Exemple 3 : Chaque processus possède un tableau de 30 doubles, en C. Pour chacun des 30 emplacements, calculez la valeur et le rang du processus contenant la plus grande valeur.

...
/* chaque processus possède un tableau de 30 doubles : ain[30]
 */
double ain[30], aout[30];
int  ind[30];
struct {
    double val;
    int   rank;
} in[30], out[30];
int i, myrank, root;
MPI_Comm_rank(MPI_COMM_WORLD, &myrank);
for (i=0; i<30; ++i) {
    in[i].val = ain[i];
    in[i].rank = myrank;
}
MPI_Reduce( in, out, 30, MPI_DOUBLE_INT, MPI_MAXLOC, root, comm );
/* À ce stade, la réponse se trouve sur le processus root
 */
if (myrank == root) {
    /* lire les rangs
     */
    for (i=0; i<30; ++i) {
        aout[i] = out[i].val;
        ind[i] = out[i].rank;
    }
}

Exemple 4 : Même exemple, en Fortran.

...
! chaque processus possède un tableau de 30 doubles : ain(30)
DOUBLE PRECISION :: ain(30), aout(30)
INTEGER :: ind(30)
DOUBLE PRECISION :: in(2,30), out(2,30)
INTEGER :: i, myrank, root, ierr
call MPI_COMM_RANK(MPI_COMM_WORLD, myrank)
DO I=1, 30
    in(1,i) = ain(i)
    in(2,i) = myrank    ! myrank est converti en double
END DO
call MPI_REDUCE( in, out, 30, MPI_2DOUBLE_PRECISION, MPI_MAXLOC, root, &
                                                          comm, ierr )
! À ce stade, la réponse se trouve sur le processus root
IF (myrank == root) THEN
    ! lire la réponse
    DO I= 1, 30
        aout(i) = out(1,i)
        ind(i) = out(2,i)  ! le rang est reconverti en entier
    END DO
END IF

Exemple 5 : Chaque processus possède un tableau non vide de valeurs. Trouver la valeur minimale globale, le rang du processus qui la détient, et son indice sur ce processus.

#define  LEN   1000
float val[LEN];        /* tableau local de valeurs */
int count;             /* nombre local de valeurs */
int myrank, minrank, minindex;
float minval;
struct {
    float value;
    int   index;
} in, out;
/* minloc local */
in.value = val[0];
in.index = 0;
for (i=1; i < count; i++)
    if (in.value > val[i]) {
        in.value = val[i];
        in.index = i;
    }
/* minloc global */
MPI_Comm_rank(MPI_COMM_WORLD, &myrank);
in.index = myrank*LEN + in.index;
MPI_Reduce( in, out, 1, MPI_FLOAT_INT, MPI_MINLOC, root, comm );
    /* À ce stade, la réponse se trouve sur le processus root
     */
if (myrank == root) {
    /* lire la réponse
     */
    minval = out.value;
    minrank = out.index / LEN;
    minindex = out.index % LEN;

Tous les objets MPI (par exemple, MPI_Datatype, MPI_Comm) sont de type INTEGER en Fortran.

NOTES SUR LES OPÉRATIONS COLLECTIVES

Les fonctions de réduction ( MPI_Op ) ne retournent pas de valeur d'erreur. Par conséquent, si les fonctions détectent une erreur, tout ce qu'elles peuvent faire est soit d'appeler MPI_Abort , soit d'ignorer silencieusement le problème. Ainsi, si vous modifiez le gestionnaire d'erreurs de MPI_ERRORS_ARE_FATAL à autre chose, par exemple, MPI_ERRORS_RETURN , alors aucune erreur ne peut être indiquée.

La raison en est les problèmes de performance pour garantir que toutes les routines collectives retournent la même valeur d'erreur.

ERREURS

Presque toutes les routines MPI retournent une valeur d'erreur ; les routines C comme résultat de retour de la fonction et les routines Fortran dans le dernier argument.

Avant que la valeur d'erreur ne soit retournée, le gestionnaire d'erreurs MPI actuel associé à l'objet de communication (par exemple, communicateur, fenêtre, fichier) est appelé. Si aucun objet de communication n'est associé à l'appel MPI, alors l'appel est considéré comme attaché à MPI_COMM_SELF et appellera le gestionnaire d'erreurs MPI associé. Lorsque MPI_COMM_SELF n'est pas initialisé (c'est-à-dire avant MPI_Init / MPI_Init_thread , après MPI_Finalize , ou lors de l'utilisation exclusive du modèle de sessions) l'élévation d'erreur

ERRORS

By default, any MPI error that occurs during the execution of an MPI routine will cause the process to return an error code to the calling application. It is the application's responsibility to check for errors returned by MPI routines. If the application does not check for errors, then MPI has the default error handler, which is MPI_Abort(3), invoked.

The default error handler for MPI I/O functions is MPI_ERRORS_RETURN. The default error handler for all other MPI functions is MPI_ERRORS_ABORT.

The initial error handler can be changed by calling MPI_Comm_set_errhandler on MPI_COMM_SELF when using the World model, or the mpi_initial_errhandler CLI argument to mpiexec or info key to MPI_Comm_spawn/MPI_Comm_spawn_multiple. If no other appropriate error handler has been set, then the MPI_ERRORS_RETURN error handler is called for MPI I/O functions and the MPI_ERRORS_ABORT error handler is called for all other MPI functions.

Open MPI includes three predefined error handlers that can be used:

  • MPI_ERRORS_ARE_FATAL Causes the program to abort all connected MPI processes.
  • MPI_ERRORS_ABORT An error handler that can be invoked on a communicator, window, file, or session. When called on a communicator, it acts as if MPI_Abort was called on that communicator. If called on a window or file, acts as if MPI_Abort was called on a communicator containing the group of processes in the corresponding window or file. If called on a session, aborts only the local process.
  • MPI_ERRORS_RETURN Returns an error code to the application.

MPI applications can also implement their own error handlers by calling:

  • MPI_Comm_create_errhandler then MPI_Comm_set_errhandler
  • MPI_File_create_errhandler then MPI_File_set_errhandler
  • MPI_Session_create_errhandler then MPI_Session_set_errhandler or at MPI_Session_init
  • MPI_Win_create_errhandler then MPI_Win_set_errhandler

Note that MPI does not guarantee that an MPI program can continue past an error.

See the MPI man page for a full list of MPI error codes.

See the Error Handling section of the MPI-3.1 standard for more information.
