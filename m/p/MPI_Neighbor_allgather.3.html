PARAMÈTRES D'ENTRÉE

  • sendbuf: Adresse de départ du tampon d'envoi (choix).
  • sendcount: Nombre d'éléments dans le tampon d'envoi (entier).
  • sendtype: Type de données des éléments du tampon d'envoi (handle).
  • recvbuf: Adresse de départ du tampon de réception (choix).
  • recvcount: Nombre d'éléments reçus de chaque processus (entier).
  • recvtype: Type de données des éléments du tampon de réception (handle).
  • comm: Communicateur (handle).

PARAMÈTRES DE SORTIE

  • recvbuf: Adresse du tampon de réception (choix).
  • request: Requête (handle, non bloquant uniquement).
  • ierror: Fortran uniquement : Statut d'erreur (entier).

DESCRIPTION

MPI_Neighbor_allgather est similaire à MPI_Allgather, sauf que seuls les processus voisins reçoivent le résultat, au lieu de tous les processus. Les voisins et la disposition des tampons sont déterminés par la topologie du comm.

La signature de type associée à sendcount, sendtype sur un processus doit être égale à la signature de type associée à recvcount, recvtype sur tout autre processus.

ORDRE DES VOISINS

Pour une topologie de graphe distribué, créée avec MPI_Dist_graph_create, la séquence des voisins dans les tampons d'envoi et de réception sur chaque processus est définie comme la séquence retournée par MPI_Dist_graph_neighbors pour les destinations et les sources, respectivement. Pour une topologie de graphe générale, créée avec MPI_Graph_create, l'ordre des voisins dans les tampons d'envoi et de réception est défini comme la séquence des voisins telle que retournée par MPI_Graph_neighbors. Notez que les topologies de graphes générales devraient généralement être remplacées par les topologies de graphes distribués.

Pour une topologie cartésienne, créée avec MPI_Cart_create, la séquence des voisins dans les tampons d'envoi et de réception sur chaque processus est définie par l'ordre des dimensions, d'abord le voisin dans la direction négative, puis dans la direction positive avec un déplacement de 1. Le nombre de sources et de destinations dans les routines de communication est 2*ndims, où ndims est défini dans MPI_Cart_create. Si un voisin n'existe pas, c'est-à-dire en bordure d'une topologie cartésienne dans le cas d'une dimension de grille virtuelle non périodique (c'est-à-dire periods[…]==false), alors ce voisin est défini comme étant MPI_PROC_NULL.

Si un voisin dans l'une des fonctions est MPI_PROC_NULL, alors la communication collective de voisinage se comporte comme une communication point à point avec MPI_PROC_NULL dans cette direction. C'est-à-dire que le tampon fait toujours partie de la séquence de voisins, mais il n'est ni communiqué ni mis à jour.

NOTES

L'option MPI_IN_PLACE pour sendbuf n'est pas significative pour cette opération.

ERREURS

Presque toutes les routines MPI retournent une valeur d'erreur ; les routines C comme résultat de retour de la fonction et les routines Fortran dans le dernier argument.

Avant que la valeur d'erreur ne soit retournée, le gestionnaire d'erreurs MPI actuel associé à l'objet de communication (par exemple, communicateur, fenêtre, fichier) est appelé. Si aucun objet de communication n'est associé à l'appel MPI, alors l'appel est considéré comme attaché à MPI_COMM_SELF et appellera le gestionnaire d'erreurs MPI associé. Lorsque MPI_COMM_SELF n'est pas initialisé (c'est-à-dire avant MPI_Init/MPI_Init_thread, après MPI_Finalize, ou lors de l'utilisation exclusive du modèle de Sessions) l'erreur déclenche le gestionnaire d'erreurs initial. Le gestionnaire d'erreurs initial peut être modifié en appelant MPI_Comm_set_errhandler sur MPI_COMM_SELF lors de l'utilisation du modèle World, ou l'argument CLI mpi_initial_errhandler de mpiexec ou la clé d'information pour MPI_Comm_spawn/MPI_Comm_spawn_multiple. Si aucun autre gestionnaire d'erreurs approprié n'a été défini, alors le gestionnaire d'erreurs MPI_ERRORS_RETURN est appelé pour les fonctions MPI I/O et le gestionnaire d'erreurs MPI_ERRORS_ABORT est appelé pour toutes les autres fonctions MPI.

Open MPI inclut trois gestionnaires d'erreurs prédéfinis qui peuvent être utilisés :

  • MPI_ERRORS_ARE_FATAL Provoque l'arrêt du programme par tous les processus MPI connectés.
  • MPI_ERRORS_ABORT Un gestionnaire d'erreurs qui peut être invoqué sur un communicateur, une fenêtre, un fichier ou une session. Lorsqu'il est appelé sur un communicateur, il agit comme si MPI_Abort avait été appelé sur ce communicateur. S'il est appelé sur une fenêtre ou un fichier, il agit comme si MPI_Abort avait été appelé sur un communicateur contenant le groupe de processus dans la fenêtre ou le fichier correspondant. S'il est appelé sur une session, il n'interrompt que le processus local.
  • MPI_ERRORS_RETURN Retourne un code d'erreur à l'application.

Les applications MPI peuvent également implémenter leurs propres gestionnaires d'erreurs en appelant :

  • MPI_Comm_create_errhandler puis MPI_Comm_set_errhandler
  • MPI_File_create_errhandler puis MPI_File_set_errhandler
  • MPI_Session_create_errhandler puis MPI_Session_set_errhandler
