MPI_TYPE_CONTIGUOUS(3) Open MPI MPI_TYPE_CONTIGUOUS(3)

MPI_Type_contiguous — Crée un type de données contigu.

SYNTAXE

Syntaxe C

#include <mpi.h>
int MPI_Type_contiguous(int count, MPI_Datatype oldtype,
     MPI_Datatype *newtype)

Syntaxe Fortran

USE MPI
! ou la forme plus ancienne : INCLUDE 'mpif.h'
MPI_TYPE_CONTIGUOUS(COUNT, OLDTYPE, NEWTYPE, IERROR)
     INTEGER COUNT, OLDTYPE, NEWTYPE, IERROR

Syntaxe Fortran 2008

USE mpi_f08
MPI_Type_contiguous(count, oldtype, newtype, ierror)
     INTEGER, INTENT(IN) :: count
     TYPE(MPI_Datatype), INTENT(IN) :: oldtype
     TYPE(MPI_Datatype), INTENT(OUT) :: newtype
     INTEGER, OPTIONAL, INTENT(OUT) :: ierror

PARAMÈTRES ENTRANTS

  • count: Nombre de réplications (entier non négatif).
  • oldtype: Ancien type de données (descripteur).

PARAMÈTRES SORTANTS

  • newtype: Nouveau type de données (descripteur).
  • ierror: Fortran uniquement : Statut d'erreur (entier).

DESCRIPTION

Le constructeur de type de données le plus simple est MPI_Type_contiguous, qui permet la réplication d'un type de données dans des emplacements contigus.

newtype est le type de données obtenu en concaténant count copies de oldtype. La concaténation est définie à l'aide de l'étendue de oldtype comme taille des copies concaténées.

Exemple : Soit oldtype de type map {(double, 0), (char, 8)}, avec une étendue de 16, et count = 3. La map de type du type de données renvoyé par newtype est

{(double, 0), (char, 8), (double, 16), (char, 24),
(double, 32), (char, 40)};

c'est-à-dire des éléments double et char alternés, avec des déplacements de 0, 8, 16, 24, 32, 40.

En général, supposons que la map de type de oldtype soit

{(type(0), disp(0)),...,(type(n-1), disp(n-1))},

avec une étendue ex. Alors newtype a une map de type avec n entrées multipliées par count définies par :

{(type(0), disp(0)), ...,(type(n-1), disp(n-1)),
(type(0), disp(0) + ex), ...,(type(n-1),
disp(n-1) + ex), ...,(type(0), disp(0) + ex * (count - 1)),
...,(type(n-1), disp(n-1) + ex * (count - 1))}.

Pour plus d'informations sur les types de données dérivés, consultez le chapitre sur les types de données du Manuel MPI.

ERREURS

Presque toutes les routines MPI renvoient une valeur d'erreur ; les routines C comme résultat de la fonction et les routines Fortran dans le dernier argument.

Avant que la valeur d'erreur ne soit renvoyée, le gestionnaire d'erreurs MPI actuel associé à l'objet de communication (par exemple, communicateur, fenêtre, fichier) est appelé. Si aucun objet de communication n'est associé à l'appel MPI, l'appel est considéré comme attaché à MPI_COMM_SELF et appellera le gestionnaire d'erreurs MPI associé. Lorsque MPI_COMM_SELF n'est pas initialisé (c'est-à-dire avant MPI_Init/MPI_Init_thread, après MPI_Finalize, ou lors de l'utilisation exclusive du modèle Sessions), l'erreur déclenche le gestionnaire d'erreurs initial. Le gestionnaire d'erreurs initial peut être modifié en appelant MPI_Comm_set_errhandler sur MPI_COMM_SELF lors de l'utilisation du modèle World, ou l'argument de ligne de commande mpi_initial_errhandler de mpiexec ou la clé d'information pour MPI_Comm_spawn/MPI_Comm_spawn_multiple. Si aucun autre gestionnaire d'erreurs approprié n'a été défini, le gestionnaire d'erreurs MPI_ERRORS_RETURN est appelé pour les fonctions E/S MPI et le gestionnaire d'erreurs MPI_ERRORS_ABORT est appelé pour toutes les autres fonctions MPI.

Open MPI inclut trois gestionnaires d'erreurs prédéfinis qui peuvent être utilisés :

  • MPI_ERRORS_ARE_FATAL Provoque l'arrêt de tous les processus MPI connectés.
  • MPI_ERRORS_ABORT Un gestionnaire d'erreurs qui peut être invoqué sur un communicateur, une fenêtre, un fichier ou une session. Lorsqu'il est appelé sur un communicateur, il agit comme si MPI_Abort était appelé sur ce communicateur. S'il est appelé sur une fenêtre ou un fichier, il agit comme si MPI_Abort était appelé sur un communicateur contenant le groupe de processus de la fenêtre ou du fichier correspondant. S'il est appelé sur une session, il n'interrompt que le processus local.
  • MPI_ERRORS_RETURN Renvoie un code d'erreur à l'application.

Les applications MPI peuvent également implémenter leurs propres gestionnaires d'erreurs en appelant :

  • MPI_Comm_create_errhandler puis MPI_Comm_set_errhandler
  • MPI_File_create_errhandler puis MPI_File_set_errhandler
  • MPI_Session_create_errhandler puis MPI_Session_set_errhandler ou à MPI_Session_init
  • MPI_Win_create_errhandler puis MPI_Win_set_errhandler

Notez que MPI ne garantit pas qu'un programme MPI puisse continuer après une erreur.

Voir la page man MPI pour une liste complète des codes d'erreur MPI.

Voir la section Gestion des erreurs de la norme MPI-3.1 pour plus d'informations.
