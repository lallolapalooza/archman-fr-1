MPI_Comm_set_info — Définir des indices d'information pour un communicateur

SYNTAXE

Syntaxe C

#include <mpi.h>
int MPI_Comm_set_info(MPI_Comm comm, MPI_Info info)

Syntaxe Fortran

USE MPI
! ou la forme plus ancienne : INCLUDE 'mpif.h'
MPI_COMM_SET_INFO(COMM, INFO, IERROR)
     INTEGER COMM, INFO, IERROR

Syntaxe Fortran 2008

USE mpi_f08
MPI_Comm_set_info(comm, info, ierror)
     TYPE(MPI_Comm), INTENT(IN) :: comm
     TYPE(MPI_Info), INTENT(IN) :: info
     INTEGER, OPTIONAL, INTENT(OUT) :: ierror

PARAMÈTRES ENTRANTS

  • comm: Communicateur sur lequel définir les indices d'information
  • info: Objet d'information contenant les indices à définir sur comm

PARAMÈTRES SORTANTS

•
ierror: Fortran uniquement : Statut d'erreur (entier).

DESCRIPTION

MPI_Comm_set_info définit de nouvelles valeurs pour les indices du communicateur associé à comm. MPI_Comm_set_info est une routine collective. L'objet d'information peut être différent sur chaque processus, mais toutes les entrées d'information qu'une implémentation exige d'être identiques sur tous les processus doivent apparaître avec la même valeur dans l'objet info de chaque processus.

Les assertions de clés d'information suivantes peuvent être acceptées par Open MPI :

mpi_assert_no_any_tag (booléen) : Si défini sur vrai, l'implémentation peut supposer que le processus n'utilisera pas le caractère générique MPI_ANY_TAG sur le communicateur donné.

mpi_assert_no_any_source (booléen) : Si défini sur vrai, l'implémentation peut supposer que le processus n'utilisera pas le caractère générique MPI_ANY_SOURCE sur le communicateur donné.

mpi_assert_exact_length (booléen) : Si défini sur vrai, l'implémentation peut supposer que les longueurs des messages reçus par le processus sont égales aux longueurs des tampons de réception correspondants, pour les opérations de communication point à point sur le communicateur donné.

mpi_assert_allow_overtaking (booléen) : Si défini sur vrai, l'implémentation peut supposer que les communications point à point sur le communicateur donné ne dépendent pas de la règle de non-dépassement spécifiée dans MPI-3.1 Section 3.5. En d'autres termes, l'application affirme que les opérations d'envoi ne sont pas obligées d'être appariées au récepteur dans l'ordre dans lequel les opérations d'envoi ont été effectuées par l'expéditeur, et que les opérations de réception ne sont pas obligées d'être appariées dans l'ordre dans lequel elles ont été effectuées par le récepteur.

ERREURS

Presque toutes les routines MPI retournent une valeur d'erreur ; les routines C comme résultat de la fonction et les routines Fortran dans le dernier argument.

Avant que la valeur d'erreur ne soit retournée, le gestionnaire d'erreurs MPI actuel associé à l'objet de communication (par exemple, communicateur, fenêtre, fichier) est appelé. Si aucun objet de communication n'est associé à l'appel MPI, l'appel est considéré comme attaché à MPI_COMM_SELF et appellera le gestionnaire d'erreurs MPI associé. Lorsque MPI_COMM_SELF n'est pas initialisé (c'est-à-dire, avant MPI_Init/MPI_Init_thread, après MPI_Finalize, ou lors de l'utilisation exclusive du modèle de sessions) l'erreur déclenche le gestionnaire d'erreurs initial. Le gestionnaire d'erreurs initial peut être modifié en appelant MPI_Comm_set_errhandler sur MPI_COMM_SELF lors de l'utilisation du modèle World, ou via l'argument CLI mpi_initial_errhandler de mpiexec ou la clé d'information de MPI_Comm_spawn/MPI_Comm_spawn_multiple. Si aucun autre gestionnaire d'erreurs approprié n'a été défini, le gestionnaire d'erreurs MPI_ERRORS_RETURN est appelé pour les fonctions d'E/S MPI et le gestionnaire d'erreurs MPI_ERRORS_ABORT est appelé pour toutes les autres fonctions MPI.

Open MPI inclut trois gestionnaires d'erreurs prédéfinis qui peuvent être utilisés :

  • MPI_ERRORS_ARE_FATAL Provoque l'abandon du programme par tous les processus MPI connectés.
  • MPI_ERRORS_ABORT Un gestionnaire d'erreurs qui peut être invoqué sur un communicateur, une fenêtre, un fichier ou une session. Lorsqu'il est appelé sur un communicateur, il agit comme si MPI_Abort avait été appelé sur ce communicateur. S'il est appelé sur une fenêtre ou un fichier, il agit comme si MPI_Abort avait été appelé sur un communicateur contenant le groupe de processus de la fenêtre ou du fichier correspondant. S'il est appelé sur une session, il n'interrompt que le processus local.
  • MPI_ERRORS_RETURN Retourne un code d'erreur à l'application.

Les applications MPI peuvent également implémenter leurs propres gestionnaires d'erreurs en appelant :

  • MPI_Comm_create_errhandler puis MPI_Comm_set_errhandler
  • MPI_File_create_errhandler puis MPI_File_set_errhandler
  • MPI_Session_create_errhandler puis MPI_Session_set_errhandler ou au niveau de MPI_Session_init
  • MPI_Win_create_errhandler puis MPI_Win_set_errhandler

Notez que MPI ne garantit pas qu'un programme MPI puisse continuer après une erreur.

Voir la page de manuel MPI pour une liste complète des codes d'erreur MPI.

Voir la section Gestion des erreurs de la norme MPI-3.1 pour plus d'informations.
