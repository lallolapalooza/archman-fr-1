MPI_Request_free(3) Open MPI MPI_Request_free(3)

MPI_Request_free — Libère un objet de requête de communication.

SYNTAXE

Syntaxe C

#include <mpi.h>
int MPI_Request_free(MPI_Request *request)

Syntaxe Fortran

USE MPI
! ou la vieille forme : INCLUDE 'mpif.h'
MPI_REQUEST_FREE(REQUEST, IERROR)
     INTEGER REQUEST, IERROR

Syntaxe Fortran 2008

USE mpi_f08
MPI_Request_free(request, ierror)
     TYPE(MPI_Request), INTENT(INOUT) :: request
     INTEGER, OPTIONAL, INTENT(OUT) :: ierror

PARAMÈTRE ENTRÉE/SORTIE

|
request: Objet de requête de communication (handle).

DESCRIPTION

Cette opération permet de libérer un objet de requête de communication sans attendre que la communication associée soit terminée.

MPI_Request_free marque l'objet de requête de communication pour libération et met request à MPI_REQUEST_NULL. Toute communication en cours associée à l'objet de requête sera autorisée à se terminer. L'objet de requête ne sera libéré qu'après que sa complétion soit effective.

NOTES

Une fois qu'un objet de requête a été libéré à l'aide de MPI_Request_free, il n'est pas possible de vérifier la complétion réussie de la communication associée à l'aide de MPI_Wait ou MPI_Test. De plus, si une erreur survient ultérieurement pendant la communication, aucun code d'erreur ne pourra être retourné à l'utilisateur ; cette erreur doit être traitée comme fatale. Des questions peuvent se poser quant au moment où l'on sait que les opérations sont terminées lorsqu'on utilise MPI_Request_free. Selon la logique du programme, il peut exister d'autres méthodes par lesquelles le programme sait que certaines opérations sont terminées, ce qui rend l'utilisation de MPI_Request_free pratique. Par exemple, une requête d'envoi active pourrait être libérée lorsque la logique du programme fait que le récepteur envoie une réponse au message envoyé — l'arrivée de la réponse informe l'expéditeur que l'envoi est terminé et que le tampon d'envoi peut être réutilisé. Une requête de réception active ne doit pas être libérée, car le récepteur ne pourra pas vérifier que la réception est terminée et que le tampon de réception peut être réutilisé.

Exemple :

CALL MPI_COMM_RANK(MPI_COMM_WORLD, rank)
IF(rank == 0) THEN
    DO i=1, n
      CALL MPI_ISEND(outval, 1, MPI_REAL, 1, 0, req, ierr)
      CALL MPI_REQUEST_FREE(req, ierr)
      CALL MPI_IRECV(inval, 1, MPI_REAL, 1, 0, req, ierr)
      CALL MPI_WAIT(req, status, ierr)
    END DO
ELSE IF (rank == 1) THEN
    CALL MPI_IRECV(inval, 1, MPI_REAL, 0, 0, req, ierr)
    CALL MPI_WAIT(req, status)
    DO I=1, n-1
       CALL MPI_ISEND(outval, 1, MPI_REAL, 0, 0, req, ierr)
       CALL MPI_REQUEST_FREE(req, ierr)
       CALL MPI_IRECV(inval, 1, MPI_REAL, 0, 0, req, ierr)
       CALL MPI_WAIT(req, status, ierr)
    END DO
    CALL MPI_ISEND(outval, 1, MPI_REAL, 0, 0, req, ierr)
    CALL MPI_WAIT(req, status)
END IF

Cette routine est normalement utilisée pour libérer des requêtes persistantes créées avec MPI_Recv_init ou MPI_Send_init et leurs amis. Cependant, elle peut être utilisée pour libérer une requête créée avec MPI_Irecv ou MPI_Isend et leurs amis ; dans ce cas, la routine de test ou d'attente ne peut pas être utilisée sur l'objet de requête. Il est permis de libérer une requête active. Cependant, une fois libéré, l'objet de requête ne peut pas être utilisé dans une routine d'attente ou de test (par exemple, MPI_Wait).

ERREURS

La plupart des routines MPI retournent une valeur d'erreur ; les routines C retournent la valeur de résultat de la fonction et les routines Fortran dans le dernier argument.

Avant que la valeur d'erreur ne soit retournée, le gestionnaire d'erreurs actuel associé à l'objet de communication (par exemple, le communicateur, la fenêtre, le fichier) est appelé. S'il n'y a pas d'objet de communication associé à l'appel MPI, l'appel est considéré comme associé à MPI_COMM_SELF et le gestionnaire d'erreurs associé est appelé. Lorsque MPI_COMM_SELF n'est pas initialisé (c'est-à-dire, avant MPI_Init/MPI_Init_thread, après MPI_Finalize, ou lorsque le modèle de session est utilisé exclusivement), le gestionnaire d'erreurs initial est levé. Le gestionnaire d'erreurs initial peut être modifié en appelant MPI_Comm_set_errhandler sur MPI_COMM_SELF lors de l'utilisation du modèle du monde, ou par l'argument de ligne de commande mpi_initial_errhandler pour mpiexec ou la clé d'information pour MPI_Comm_spawn/MPI_Comm_spawn_multiple. Si aucun autre gestionnaire d'erreurs approprié n'est trouvé, le gestionnaire d'erreurs MPI_ERRORS_RETURN est appelé pour les fonctions d'E/S MPI et le gestionnaire d'erreurs MPI_ERRORS_ABORT est appelé pour toutes les autres fonctions MPI.

Open MPI inclut trois gestionnaires d'erreurs par défaut qui peuvent être utilisés :

  • MPI_ERRORS_ARE_FATAL — L'application abandonne tous les processus MPI connectés.
  • MPI_ERRORS_ABORT — Un gestionnaire d'erreurs qui peut être invoqué sur un communicateur, une fenêtre, un fichier ou une session. Lorsqu'il est appelé sur un communicateur, il agit comme si MPI_Abort avait été appelé sur ce communicateur. S'il est appelé sur une fenêtre ou un fichier, il agit comme si MPI_Abort avait été appelé sur un communicateur contenant le groupe de processus dans la fenêtre ou le fichier correspondant. S'il est appelé sur une session, il abandonne uniquement le processus local.
  • MPI_ERRORS_RETURN — Retourne un code d'erreur à l'application.

Les applications MPI peuvent également implémenter leurs propres gestionnaires d'erreurs en appelant :

  • MPI_Comm_create_errhandler puis MPI_Comm_set_errhandler
  • MPI_File_create_errhandler puis MPI_File_set_errhandler
  • MPI_Session_create_errhandler puis MPI_Session_set_errhandler ou lors de MPI_Session_init
  • MPI_Win_create_errhandler puis MPI_Win_set_errhandler

Note : Une application MPI n'est pas garantie de pouvoir continuer après une erreur.

Voir la page de manuel de MPI pour une liste complète des codes d'erreur MPI.

Voir la section sur la gestion des erreurs de la norme MPI-3.1 pour plus d'informations.
