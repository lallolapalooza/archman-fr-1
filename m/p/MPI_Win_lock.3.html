MPI_WIN_LOCK(3) Open MPI MPI_WIN_LOCK(3)

MPI_Win_lock — Démarre une époque d'accès RMA bloquant l'accès à un rang particulier.

SYNTAXE

Syntaxe C

#include <mpi.h>
int MPI_Win_lock(int lock_type, int rank, int assert, MPI_Win win)

Syntaxe Fortran

USE MPI
! ou la forme plus ancienne : INCLUDE 'mpif.h'
MPI_WIN_LOCK(LOCK_TYPE, RANK, ASSERT, WIN, IERROR)
     INTEGER LOCK_TYPE, RANK, ASSERT, WIN, IERROR

Syntaxe Fortran 2008

USE mpi_f08
MPI_Win_lock(lock_type, rank, assert, win, ierror)
     INTEGER, INTENT(IN) :: lock_type, rank, assert
     TYPE(MPI_Win), INTENT(IN) :: win
     INTEGER, OPTIONAL, INTENT(OUT) :: ierror

PARAMETRES D'ENTRÉE

  • lock_type : Soit MPI_LOCK_EXCLUSIVE, soit MPI_LOCK_SHARED (état).
  • rank : Rang de la fenêtre verrouillée (entier non négatif).
  • assert : Assertion de programme (entier).
  • win : Objet fenêtre (descripteur).

PARAMETRE DE SORTIE

•
ierror : Fortran uniquement : Statut d'erreur (entier).

DESCRIPTION

Démarre une époque d'accès RMA. Les verrous garantissent que seules les fenêtres créées par des processus spécifiques peuvent être accédées par ces processus (et par aucun autre processus) pendant cette époque.

Les verrous sont utilisés pour protéger les accès à la fenêtre cible verrouillée effectués par les appels RMA émis entre l'appel de verrouillage et de déverrouillage, et pour protéger les accès locaux de chargement/stockage à une fenêtre locale verrouillée exécutés entre l'appel de verrouillage et de déverrouillage. Les accès protégés par un verrou exclusif ne seront pas simultanés sur le site de la fenêtre avec d'autres accès à la même fenêtre qui sont protégés par un verrou. Les accès protégés par un verrou partagé ne seront pas simultanés sur le site de la fenêtre avec des accès protégés par un verrou exclusif à la même fenêtre.

Le paramètre assert est utilisé pour fournir des assertions sur le contexte de l'appel qui peuvent être utilisées pour diverses optimisations. (Voir la section 6.4.4 de la norme MPI-2.) Une valeur de assert = 0 est toujours valide. La valeur d'assertion suivante est prise en charge :

MPI_MODE_NOCHECK
Aucun autre processus ne détiendra ou ne tentera d'acquérir un verrou conflictuel pendant que l'appelant détient le verrou de fenêtre.

NOTES

Dans un environnement client/serveur où les clients se connectent à un serveur et créent des fenêtres qui s'étendent à la fois au client et au serveur, si un client ou un serveur qui a obtenu un verrou sur une telle fenêtre puis se termine anormalement, le serveur ou les autres clients peuvent rester bloqués dans un appel MPI_Win_lock, sans remarquer que le job MPI pair s'est terminé.

ERREURS

Presque toutes les routines MPI renvoient une valeur d'erreur ; les routines C comme résultat de retour de la fonction et les routines Fortran dans le dernier argument.

Avant que la valeur d'erreur ne soit renvoyée, le gestionnaire d'erreurs MPI actuel associé à l'objet de communication (par exemple, communicateur, fenêtre, fichier) est appelé. S'il n'y a pas d'objet de communication associé à l'appel MPI, l'appel est considéré comme attaché à MPI_COMM_SELF et appellera le gestionnaire d'erreurs MPI associé. Lorsque MPI_COMM_SELF n'est pas initialisé (c'est-à-dire avant MPI_Init/MPI_Init_thread, après MPI_Finalize, ou lorsque le modèle de sessions est utilisé exclusivement), l'erreur déclenche le gestionnaire d'erreurs initial. Le gestionnaire d'erreurs initial peut être modifié en appelant MPI_Comm_set_errhandler sur MPI_COMM_SELF lors de l'utilisation du modèle World, ou l'argument de ligne de commande mpi_initial_errhandler à mpiexec ou la clé info à MPI_Comm_spawn/MPI_Comm_spawn_multiple. Si aucun autre gestionnaire d'erreurs approprié n'a été défini, le gestionnaire d'erreurs MPI_ERRORS_RETURN est appelé pour les fonctions d'E/S MPI et le gestionnaire d'erreurs MPI_ERRORS_ABORT est appelé pour toutes les autres fonctions MPI.

Open MPI inclut trois gestionnaires d'erreurs prédéfinis qui peuvent être utilisés :

  • MPI_ERRORS_ARE_FATAL Provoque l'arrêt du programme par tous les processus MPI connectés.
  • MPI_ERRORS_ABORT Un gestionnaire d'erreurs qui peut être invoqué sur un communicateur, une fenêtre, un fichier ou une session. Lorsqu'il est appelé sur un communicateur, il agit comme si MPI_Abort avait été appelé sur ce communicateur. S'il est appelé sur une fenêtre ou un fichier, il agit comme si MPI_Abort avait été appelé sur un communicateur contenant le groupe de processus dans la fenêtre ou le fichier correspondant. S'il est appelé sur une session, il n'interrompt que le processus local.
  • MPI_ERRORS_RETURN Renvoie un code d'erreur à l'application.

Les applications MPI peuvent également implémenter leurs propres gestionnaires d'erreurs en appelant :

  • MPI_Comm_create_errhandler puis MPI_Comm_set_errhandler
  • MPI_File_create_errhandler puis MPI_File_set_errhandler
  • MPI_Session_create_errhandler puis MPI_Session_set_errhandler ou à MPI_Session_init
  • MPI_Win_create_errhandler puis MPI_Win_set_errhandler

Notez que MPI ne garantit pas qu'un programme MPI puisse continuer après une erreur.

Voir la page man MPI pour une liste complète des codes d'erreur MPI.

Voir la section Gestion des erreurs de la norme MPI-3.1 pour plus d'informations.
