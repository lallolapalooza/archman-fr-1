MPI_Get_accumulate, MPI_Rget_accumulate - Combine le contenu du tampon d'origine avec celui d'un tampon cible et retourne la valeur du tampon cible.

DESCRIPTION

MPI_Get_accumulate est une fonction utilisée pour la communication MPI unidirectionnelle qui ajoute le contenu du tampon d'origine (défini par origin_addr, origin_count et origin_datatype) au tampon spécifié par les arguments target_count et target_datatype, à l'offset target_disp, dans la fenêtre cible spécifiée par target_rank et win, en utilisant l'opération op. MPI_Get_accumulate retourne dans le tampon de résultat result_addr le contenu du tampon cible avant l'accumulation.

Toutes les opérations prédéfinies pour MPI_Reduce, ainsi que MPI_NO_OP, peuvent être utilisées. Les fonctions définies par l'utilisateur ne peuvent pas être utilisées. Par exemple, si op est MPI_SUM, chaque élément du tampon d'origine est ajouté à l'élément correspondant dans la cible, remplaçant l'ancienne valeur dans la cible.

Chaque argument de type de données doit être un type de données prédéfini ou un type de données dérivé, où tous les composants de base sont du même type de données prédéfini. Les deux arguments de type de données doivent être construits à partir du même type de données prédéfini. L'opération op s'applique aux éléments de ce type prédéfini. L'argument target_datatype ne doit pas spécifier d'entrées qui se chevauchent, et le tampon cible doit tenir dans la fenêtre cible.

Une nouvelle opération prédéfinie, MPI_REPLACE, est définie. Elle correspond à la fonction associative f(a, b) =b ; c'est-à-dire que la valeur actuelle dans la mémoire cible est remplacée par la valeur fournie par l'origine.

Une nouvelle opération prédéfinie, MPI_NO_OP, est définie. Elle correspond à la fonction associative f(a, b) = a ; c'est-à-dire que la valeur actuelle dans la mémoire cible est retournée dans le tampon de résultat à l'origine et aucune opération n'est effectuée sur le tampon cible.

MPI_Rget_accumulate est similaire à MPI_Get_accumulate, à l'exception qu'il alloue un objet de requête de communication et l'associe au handle de requête (l'argument request) qui peut être utilisé pour attendre ou tester l'achèvement. L'achèvement d'une opération MPI_Rget_accumulate indique que les données sont disponibles dans le tampon de résultat et que le tampon d'origine peut être mis à jour. Cela n'indique pas que l'opération a été complétée dans la fenêtre cible.

NOTES

La fonctionnalité générique de MPI_Get_accumulate peut limiter les performances des appels de type "fetch-and-increment" ou "fetch-and-add" qui pourraient être pris en charge par des opérations matérielles spéciales. MPI_Fetch_and_op permet ainsi une implémentation rapide d'un sous-ensemble couramment utilisé de la fonctionnalité de MPI_Get_accumulate.

MPI_Get est un cas particulier de MPI_Get_accumulate, avec l'opération MPI_NO_OP. Notez cependant que MPI_Get et MPI_Get_accumulate ont des contraintes différentes sur les mises à jour simultanées.

Il incombe à l'utilisateur de garantir que, lors de l'utilisation des fonctions d'accumulation, l'argument de déplacement de cible est tel que les accès à la fenêtre sont correctement alignés selon les arguments de type de données dans l'appel à la fonction MPI_Get_accumulate.

DESCRIPTION


MPI_Rget_accumulate performs a non-blocking remote memory
    accumulate operation. The function sends data from the origin buffer on the
    calling process to the target process specified by target_rank, and
    combines it with the data in the target buffer using the specified op.
    The result replaces the data in the target buffer.


The operation is non-blocking, meaning that the call returns
    immediately after initiating the operation. The actual data transfer and
    combination will be completed later. The completion of the operation can be
    checked using MPI_Wait or MPI_Test.


The target_disp argument is an offset in bytes from the
    start of the window's data. The target_datatype and target_count
    arguments specify the type and number of elements in the target buffer.


The op argument specifies the operation to be performed.
    Valid operations include standard MPI reduction operations like
    MPI_SUM, MPI_PROD, MPI_MAX, MPI_MIN,
    MPI_REPLACE, and user-defined operations.


The win argument is the MPI window object associated with
    the target buffer.


The request argument is an MPI request handle that can be
    used to query the status of the operation and to wait for its completion.







NOTES


The target_disp is specified in bytes and is relative to the
    start of the window's data. This is different from the other MPI datatypes
    which are specified in number of elements.


The op argument must be a commutative operation if the
    target datatype is not basic, or if it is not a basic datatype, or if the
    origin and target datatypes are different. However, MPI-3 requires all
    operations to be commutative for Rget_accumulate.


The MPI_MAXLOC and MPI_MINLOC operations require
    that the origin and target datatypes be MPI_2integer or MPI_LONG_INTEGER.
    The data is assumed to be a pair of values, where the first value is the
    data to be compared, and the second value is the index (rank) of the
    process that supplied the data. When combining values, if the data values
    are equal, the smaller rank is chosen.







ERRORS


When the value of target_rank is not a valid rank in the
    communicator associated with the window, then the behavior is undefined.
    When the value of win is invalid, then the behavior is undefined.
    When the value of op is not a valid operation, then the behavior is
    undefined.


When the MPI_ERRORS_ARE_FATAL error handler is set for
    a routine which fails, then the MPI communication error handler is called
    and may take action to abort out all MPI processes. If the value of some
    input argument is invalid, then the MPI error code is set.


When the MPI_ERRORS_NONFATAL error handler is set for a
    routine which fails, then the MPI communication error handler is called and
    may take action to return the error code in the error handler's return
    value. Otherwise, the error code is returned to the caller. In that case, the
    MPI call does not return.


When the MPI_ERRORS_RETURN error handler is set for a
    routine which fails, then the MPI communication error handler is called and
    may take action to return the error code. Otherwise, the error code is
    returned to the caller. The MPI call returns with the error code.


When a call to the error handler returns the error code of the
    operation, the error handler is called with the communicator associated with
    the window, the error code, and a NULL error handler.


When the call to MPI_Rget_accumulate is made, then the
    call is considered attached to MPI_COMM_SELF and will call the associated
    MPI error handler. When MPI_COMM_SELF is not initialized (i.e., before
    MPI_Init/MPI_Init_thread, after MPI_Finalize, or
    when using the Sessions Model exclusively) the error raises the initial
    error handler. The initial error handler can be changed by calling
    MPI_Comm_set_errhandler on MPI_COMM_SELF when using the World model,
    or the mpi_initial_errhandler CLI argument to mpiexec or info key to
    MPI_Comm_spawn/MPI_Comm_spawn_multiple. If no other
    appropriate error handler has been set, then the MPI_ERRORS_RETURN error
    handler is called for MPI I/O functions and the MPI_ERRORS_ABORT error
    handler is called for all other MPI functions.
