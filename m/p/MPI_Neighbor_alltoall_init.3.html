MPI_Neighbor_alltoall, MPI_Ineighbor_alltoall, MPI_Neighbor_alltoall - Tous les processus envoient des données aux processus voisins dans un communicateur de topologie virtuelle

PARAMÈTRES D'ENTRÉE

  • sendbuf: Adresse de départ du tampon d'envoi (choix).
  • sendcount: Nombre d'éléments à envoyer à chaque processus (entier).
  • sendtype: Type de données des éléments du tampon d'envoi (handle).
  • recvcount: Nombre d'éléments à recevoir de chaque processus (entier).
  • recvtype: Type de données des éléments du tampon de réception (handle).
  • comm: Communicateur sur lequel les données doivent être échangées (handle).
  • info: Informations (handle, persistant uniquement).

PARAMÈTRES DE SORTIE

  • recvbuf: Adresse de départ du tampon de réception (choix).
  • request: Requête (handle, non bloquant uniquement).
  • ierror: Fortran uniquement : Statut d'erreur (entier).

DESCRIPTION

MPI_Neighbor_alltoall est une opération collective dans laquelle tous les processus envoient et reçoivent la même quantité de données à chaque voisin. Le fonctionnement de cette routine peut être représenté comme suit, où chaque processus effectue 2n (n étant le nombre de voisins dans le communicateur comm) communications point à point indépendantes. Les voisins et la disposition des tampons sont déterminés par la topologie de comm.

Exemple de sémantique de MPI_Neighbor_alltoall pour les topologies cartésiennes :

MPI_Cart_get(comm, maxdims, dims, periods, coords);
for (dim = 0, i = 0 ; dim < dims ; ++dim) {
    MPI_Cart_shift(comm, dim, 1, &r0, &r1);
    MPI_Isend(sendbuf + i * sendcount * extent(sendtype),
              sendcount, sendtype, r0, ..., comm, ...);
    MPI_Irecv(recvbuf + i * recvcount * extent(recvtype),
              recvcount, recvtype, r0, ..., comm, ...);
    ++i;
    MPI_Isend(sendbuf + i * sendcount * extent(sendtype),
              sendcount, sendtype, r1, ..., comm, &req[i]);
    MPI_Irecv(recvbuf + i * recvcount * extent(recvtype),
              recvcount, recvtype, r1, ..., comm, ...);
    ++i;
}
MPI_Waitall (...);

Chaque processus divise son sendbuf local en n blocs - chacun contenant sendcount éléments de type sendtype - et divise son recvbuf de manière similaire selon recvcount et recvtype. Le processus j envoie le k-ème bloc de son sendbuf local à son voisin k, qui place les données dans le j-ème bloc de son recvbuf local. La quantité de données envoyées doit être égale à la quantité de données reçues, par paires, entre chaque paire de processus.

ORDRE DES VOISINS

Pour une topologie de graphe distribué, créée avec MPI_Dist_graph_create, la séquence des voisins dans les tampons d'envoi et de réception à chaque processus est définie comme la séquence retournée par MPI_Dist_graph_neighbors pour les destinations et les sources, respectivement. Pour une topologie de graphe générale, créée avec MPI_Graph_create, l'ordre des voisins dans les tampons d'envoi et de réception est défini comme la séquence des voisins telle que retournée par MPI_Graph_neighbors. Notez que les topologies de graphes générales devraient généralement être remplacées par les topologies de graphes distribués.

Pour une topologie cartésienne, créée avec MPI_Cart_create, la séquence des voisins dans les tampons d'envoi et de réception à chaque processus est définie par l'ordre des dimensions, d'abord le voisin dans la direction négative puis dans la direction positive avec un déplacement de 1. Les nombres de sources et de destinations dans les routines de communication sont 2*ndims, où ndims est défini dans MPI_Cart_create. Si un voisin n'existe pas, c'est-à-dire aux frontières d'une topologie cartésienne dans le cas d'une dimension de grille virtuelle non périodique (c'est-à-dire, periods[…]==false), alors ce voisin est défini comme étant MPI_PROC_NULL.

Si un voisin dans l'une des fonctions est MPI_PROC_NULL, alors la communication collective de voisinage se comporte comme une communication point à point avec MPI_PROC_NULL dans cette direction. C'est-à-dire, que le tampon fait toujours partie de la séquence des voisins mais il n'est ni communiqué ni mis à jour.

NOTES

L'option MPI_IN_PLACE pour sendbuf n'a pas de sens pour cette fonction.

Tous les arguments sur tous les processus sont significatifs. Le communicateur comm, en particulier, doit décrire le même communicateur sur tous les processus. comm doit être soit un communicateur cartésien, de graphe ou de graphe distribué.

Il existe deux fonctions de bibliothèque MPI plus générales que MPI_Neighbor_alltoall. MPI_Neighbor_alltoallv permet une communication d'égal à égal vers et depuis des tampons qui ne doivent pas être contigus ; des processus différents peuvent envoyer et recevoir des quantités de données différentes. MPI_Neighbor_alltoallw étend la fonctionnalité de MPI_Neighbor_alltoallv pour permettre l'échange de données avec des types de données différents.

MPI_Neighbor_alltoall_init

MPI_Neighbor_alltoall_init - Creates a distributed graph neighbor communication.

SYNTAX

C/Fortran

int MPI_Neighbor_alltoall_init(
    const void *sendbuf,
    int sendcount,
    MPI_Datatype sendtype,
    void *recvbuf,
    int recvcount,
    MPI_Datatype recvtype,
    MPI_Comm comm,
    MPI_Request *request
);

INPUT PARAMETERS

sendbuf

Starting address of the send buffer (choice).

sendcount

Number of elements to send (non-negative integer).

sendtype

Datatype of send buffer elements (handle).

recvbuf

Starting address of the receive buffer (choice).

recvcount

Number of elements to receive (non-negative integer).

recvtype

Datatype of receive buffer elements (handle).

comm

Communicator with distributed graph topology (handle).

OUTPUT PARAMETERS

request

MPI receive request handle (handle).

DESCRIPTION

MPI_Neighbor_alltoall_init is a generalized neighbor communication call. It is the non-blocking (init) version of MPI_Neighbor_alltoall. This call, along with the other MPI_Neighbor_alltoall family of functions, allows communication based on a dynamically defined neighbor communication pattern. The topology is defined by the communicator comm, which must be a distributed graph communicator. The function is collective on the communicator comm.

In a distributed graph communicator, each process has a set of neighbors. For process i, in_degree(i) is the number of neighbors that will send data to process i, and out_degree(i) is the number of neighbors that process i will send data to.

MPI_Neighbor_alltoall_init distributes data from all processes in the communicator to all neighbors that are sending data. Specifically, process i sends the same contiguous block of data (defined by sendcount, sendtype) to each neighbor that is sending data to process i. Process i receives a contiguous block of data (defined by recvcount, recvtype) from each neighbor that process i is sending data to.

The neighbor relationships are established when the distributed graph communicator is created using functions such as MPI_Dist_graph_create or MPI_Dist_graph_create_adjacent.

NEIGHBOR ORDERING

The order in which neighbors are specified in the MPI_Dist_graph_create and MPI_Dist_graph_create_adjacent functions dictates the order in which data is sent and received. Specifically, if process i receives data from neighbor j, this data will be placed in the receive buffer at an offset corresponding to the position of neighbor j in the neighbors list of process i.

NOTES

The sendbuf and recvbuf arguments are significant only at the root. All processes in the communicator must call the function.

The MPI_Request returned can be used to test for completion using MPI_Test or MPI_Wait. When the request is completed, the communication is finished.

ERRORS

When the value of comm is not a valid communicator or is not a distributed graph communicator, the MPI standard will raise an error. When the value of sendtype or recvtype is not a valid datatype, the MPI standard will raise an error. When the value of request is not a valid request handle, the MPI standard will raise an error.

When the value of sendcount is negative, or the value of recvcount is negative, the MPI standard will raise an error.

When the value of comm is MPI_COMM_SELF, the MPI standard will raise an error.

When the value of comm is MPI_COMM_WORLD, the MPI standard will raise an error.

When the input counts and datatypes do not form a valid sequence of data, the MPI standard will raise an error.

When the communicator comm is not a distributed graph communicator, the MPI standard will raise an error.

In addition, when an error occurs in an MPI function, the corresponding error handler is invoked. MPI may abort the process, or may return the error code from the function to the caller. As a last resort, if an error handler is not set, MPI will call the default error handler, which is MPI_ERRORS_ABORT.

If the communicator comm is associated with a communication object (e.g., communicator, window, file), then the error handler associated with that communication object is called. If no communication object is associated with the MPI call, then the call is considered attached to MPI_COMM_SELF and will call the associated MPI error handler. When MPI_COMM_SELF is not initialized (i.e., before MPI_Init/MPI_Init_thread, after MPI_Finalize, or when using the Sessions Model exclusively) the error raises the initial error handler. The initial error handler can be changed by calling MPI_Comm_set_errhandler on MPI_COMM_SELF when using the World model, or the mpi_initial_errhandler CLI argument to mpiexec or info key to MPI_Comm_spawn/MPI_Comm_spawn_multiple. If no other appropriate error handler has been set, then the MPI_ERRORS_RETURN error handler is called for MPI I/O functions and the MPI_ERRORS_ABORT error handler is called for all other MPI functions.

Open MPI includes three predefined error handlers that can be used:

  • MPI_ERRORS_ARE_FATAL Causes the program to abort all connected MPI processes.
  • MPI_ERRORS_ABORT An error handler that can be invoked on a communicator, window, file, or session. When called on a communicator, it acts as if MPI_Abort was called on that communicator. If called on a window or file, acts as if MPI_Abort was called on a communicator containing the group of processes in the corresponding window or file. If called on a session, aborts only the local process.
  • MPI_ERRORS_RETURN Returns an error code to the application.

MPI applications can also implement their own error handlers by calling:

  • MPI_Comm_create_errhandler then MPI_Comm_set_errhandler
  • MPI_File_create_errhandler then MPI_File_set_errhandler
  • MPI_Session_create_errhandler then MPI_Session_set_errhandler or at MPI_Session_init
  • MPI_Win_create_errhandler then MPI_Win_set_errhandler

Note that MPI does not guarantee that an MPI program can continue past an error.

See the MPI man page for a full list of MPI error codes.

See the Error Handling section of the MPI-3.1 standard for more information.
