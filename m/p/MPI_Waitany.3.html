MPI_Waitany(3) Open MPI MPI_Waitany(3)

MPI_Waitany — Attend l'achèvement de toute requête d'envoi ou de réception spécifiée.

SYNTAXE

Syntaxe C

#include <mpi.h>
int MPI_Waitany(int count, MPI_Request array_of_requests[],
     int *index, MPI_Status *status)

Syntaxe Fortran

USE MPI
! ou l'ancienne forme : INCLUDE 'mpif.h'
MPI_WAITANY(COUNT, ARRAY_OF_REQUESTS, INDEX, STATUS, IERROR)
     INTEGER COUNT, ARRAY_OF_REQUESTS(*), INDEX
     INTEGER STATUS(MPI_STATUS_SIZE), IERROR

Syntaxe Fortran 2008

USE mpi_f08
MPI_Waitany(count, array_of_requests, index, status, ierror)
     INTEGER, INTENT(IN) :: count
     TYPE(MPI_Request), INTENT(INOUT) :: array_of_requests(count)
     INTEGER, INTENT(OUT) :: index
     TYPE(MPI_Status) :: status
     INTEGER, OPTIONAL, INTENT(OUT) :: ierror

PARAMÈTRES D'ENTRÉE

  • count : Compte (entier).
  • array_of_requests : Tableau de requêtes (tableau de handles).

PARAMÈTRES DE SORTIE

  • index : Indice du handle pour l'opération terminée (entier). Dans la plage 0 à count-1. En Fortran, la plage est de 1 à count.
  • status : Objet d'état (status).
  • ierror : Fortran uniquement : Statut d'erreur (entier).

DESCRIPTION

Un appel à MPI_Waitany peut être utilisé pour attendre l'achèvement d'une requête parmi plusieurs. La liste des requêtes peut contenir des requêtes nulles ou inactives. Si la liste ne contient aucune requête active (liste de longueur nulle ou tous les éléments sont nuls ou inactifs), l'appel retourne immédiatement avec index = MPI_UNDEFINED, et un statut vide.

L'exécution de MPI_Waitany(count, array_of_requests, index, status) a le même effet que l'exécution de MPI_Wait(&array_of_requests[i], status), où i est la valeur retournée par index (sauf si la valeur de index est MPI_UNDEFINED). MPI_Waitany avec une liste contenant une seule entrée active est équivalent à MPI_Wait.

Si votre application n'a pas besoin d'examiner le champ de status, vous pouvez économiser des ressources en utilisant la valeur par défaut MPI_STATUS_IGNORE comme valeur spéciale pour l'argument status.

Exemple : Code client-serveur (peut souffrir de la famine).

CALL MPI_COMM_SIZE(comm, size, ierr)
CALL MPI_COMM_RANK(comm, rank, ierr)
IF(rank > 0) THEN         ! client
    DO
       CALL MPI_ISEND(a, n, MPI_REAL, 0, tag, comm, request, ierr)
       CALL MPI_WAIT(request, status, ierr)
    END DO
ELSE         ! rank=0: serveur
       DO i=1, size-1
          CALL MPI_IRECV(a(1,i), n, MPI_REAL, i tag, &
                   comm, request_list(i), ierr)
       END DO
       DO
          CALL MPI_WAITANY(size-1, request_list, index, status, ierr)
          CALL DO_SERVICE(a(1,index))  ! traiter un message
          CALL MPI_IRECV(a(1, index), n, MPI_REAL, index, tag, &
                    comm, request_list(index), ierr)
       END DO
END IF

ERREURS

La plupart des routines MPI retournent une valeur d'erreur ; dans les routines C, le résultat est la valeur de retour de la fonction et dans les routines Fortran dans le dernier argument.

Avant de retourner la valeur d'erreur, le gestionnaire d'erreur associé à l'objet de communication (par exemple, communicator, window, file) est appelé. S'il n'y a pas d'objet de communication associé à l'appel MPI, l'appel est considéré comme étant associé à MPI_COMM_SELF et le gestionnaire d'erreur associé à MPI_COMM_SELF est appelé. Lorsque MPI_COMM_SELF n'est pas initialisé (c'est-à-dire avant MPI_Init/MPI_Init_thread, après MPI_Finalize, ou lorsqu'on utilise exclusivement le Modèle de Session), le gestionnaire d'erreur initial est déclenché. Le gestionnaire d'erreur initial peut être modifié en appelant MPI_Comm_set_errhandler sur MPI_COMM_SELF lors de l'utilisation du Modèle du Monde, ou la clé d'information mpi_initial_errhandler pour mpiexec ou la clé d'information pour MPI_Comm_spawn/MPI_Comm_spawn_multiple. S'il n'y a pas d'autre gestionnaire approprié, le gestionnaire d'erreur MPI_ERRORS_RETURN est appelé pour les fonctions d'E/S MPI et le gestionnaire d'erreur MPI_ERRORS_ABORT pour toutes les autres fonctions MPI.

Open MPI inclut trois gestionnaires d'erreurs par défaut qui peuvent être utilisés :

  • MPI_ERRORS_ARE_FATAL Provoque l'arrêt de tous les processus MPI connectés.
  • MPI_ERRORS_ABORT Un gestionnaire d'erreurs qui peut être invoqué sur un communicateur, une fenêtre, un fichier ou une session. Lorsqu'il est invoqué sur un communicateur, il agit comme si MPI_Abort avait été appelé sur ce communicateur. S'il est invoqué sur une fenêtre ou un fichier, il agit comme si MPI_Abort avait été appelé sur un communicateur contenant les processus de la fenêtre ou du fichier correspondant. S'il est invoqué sur une session, il n'arrête que le processus local.
  • MPI_ERRORS_RETURN Retourne un code d'erreur à l'application.

Les applications MPI peuvent également implémenter leurs propres gestionnaires d'erreurs en appelant :

  • MPI_Comm_create_errhandler puis MPI_Comm_set_errhandler
  • MPI_File_create_errhandler puis MPI_File_set_errhandler
  • MPI_Session_create_errhandler puis MPI_Session_set_errhandler ou lors de MPI_Session_init
  • MPI_Win_create_errhandler puis MPI_Win_set_errhandler

Remarque : Les erreurs MPI ne garantissent pas qu'un programme MPI puisse continuer après une erreur.

Voir la page de manuel MPI pour une liste complète des codes d'erreur MPI.

Voir la section Gestion des erreurs de la norme MPI-3.1 pour plus d'informations.

Remarque : Conformément à la section "Retour d'état" du chapitre "Communication point à point" de la norme MPI, les erreurs sur les requêtes passées à MPI_Waitany ne définissent pas le champ status.MPI_ERROR dans l'état retourné. Le code d'erreur est toujours passé au gestionnaire d'erreurs backend et peut être renvoyé à l'appelant via la valeur de retour de MPI_Waitany si le gestionnaire d'erreurs backend le renvoie. Le gestionnaire d'erreurs par défaut MPI_ERRORS_RETURN affiche par exemple ce comportement.

MPI_Waitany(3)

Wait for any of the requests in a list to complete

NAME

MPI_Waitany - Wait for any of the requests in a list to complete

SYNTAX

int MPI_Waitany(int count, MPI_Request array_of_requests[], MPI_Status *status)

ROUTINE

This routine will block until one of the requests in the array_of_requests list completes. The count argument specifies the number of requests in the list. The array_of_requests argument is an array of MPI_Request objects. The status argument is a pointer to an MPI_Status object that will contain information about the completed request.

The MPI_Waitany routine returns the index of the completed request in the array_of_requests list. The MPI_Status object will be populated with information about the completed request, such as the error code and the number of bytes received for receives.

INPUTS

  • count - The number of requests in the array_of_requests list.
  • array_of_requests - An array of MPI_Request objects.

OUTPUTS

  • status - A pointer to an MPI_Status object that will contain information about the completed request.

ERRORS

MPI standard errors only.

MPI_Waitany(3)

Attend qu'une des requêtes d'une liste soit terminée

NOM

MPI_Waitany - Attend qu'une des requêtes d'une liste soit terminée

SYNTAXE

int MPI_Waitany(int count, MPI_Request array_of_requests[], MPI_Status *status)

ROUTINE

Cette routine bloquera jusqu'à ce que l'une des requêtes dans la liste array_of_requests soit terminée. L'argument count spécifie le nombre de requêtes dans la liste. L'argument array_of_requests est un tableau d'objets MPI_Request. L'argument status est un pointeur vers un objet MPI_Status qui contiendra des informations sur la requête terminée.

La routine MPI_Waitany renvoie l'indice de la requête terminée dans la liste array_of_requests. L'objet MPI_Status sera rempli avec des informations sur la requête terminée, telles que le code d'erreur et le nombre d'octets reçus pour les réceptions.

ENTRÉES

  • count - Le nombre de requêtes dans la liste array_of_requests.
  • array_of_requests - Un tableau d'objets MPI_Request.

SORTIES

  • status - Un pointeur vers un objet MPI_Status qui contiendra des informations sur la requête terminée.

ERREURS

Erreurs standard MPI uniquement.
