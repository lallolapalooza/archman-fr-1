MPIX_Comm_ack_failed(3) Open MPI MPIX_Comm_ack_failed(3)

MPIX_Comm_get_failed - accuser réception des défaillances de processus dans un communicateur.

Ceci fait partie de l'extension ULFM (User Level Fault Mitigation).

Syntaxe

Syntaxe C

#include <mpi.h>
#include <mpi-ext.h>
int MPIX_Comm_ack_failed(MPI_Comm comm, int num_to_ack, int *num_acked)

Syntaxe Fortran

USE MPI
USE MPI_EXT
! ou l'ancienne forme: INCLUDE 'mpif.h'
MPIX_COMM_ACK_FAILED(COMM, NUM_TO_ACK, NUM_ACKED, IERROR)
     INTEGER COMM, NUM_TO_ACK, NUM_ACKED, IERROR

Syntaxe Fortran 2008

USE mpi_f08
USE mpi_ext_f08
MPIX_Comm_ack_failed(comm, num_to_ack, num_acked, ierror)
     TYPE(MPI_Comm), INTENT(IN) :: comm
     INTEGER, INTENT(IN) :: num_to_ack
     INTEGER, INTENT(OUT) :: num_acked
     INTEGER, OPTIONAL, INTENT(OUT) :: ierror

Paramètres d'entrée

  • comm : Communicateur (handle).
  • num_to_ack : nombre maximum de défaillances de processus à accuser réception dans comm (entier).

Paramètres de sortie

  • num_acked : nombre de défaillances de processus accusées réception dans comm (entier).
  • ierror : Fortran seulement : statut d'erreur (entier).

Description

Cette opération locale permet aux utilisateurs de confirmer les défaillances locales signalées dans comm. L'opération confirme les num_to_ack premières défaillances de processus dans comm, c'est-à-dire, elle confirme la défaillance des membres avec un rang inférieur à num_to_ack dans le groupe tel qu'il se présente lors d'un appel concomitant à MPIX_Comm_get_failed sur le même comm.

L'opération définit également la valeur de num_acked comme le nombre actuel de défaillances de processus confirmées dans comm, c'est-à-dire qu'une défaillance de processus a été confirmée dans comm si et seulement si le rang du processus est inférieur à num_acked dans le groupe tel qu'il se présente lors d'un appel ultérieur à MPIX_Comm_get_failed sur le même comm.

Le num_acked peut être supérieur à num_to_ack lorsque des défaillances de processus ont été confirmées lors d'un appel précédent à MPIX_Comm_ack_failed.

Effet de la confirmation des défaillances

Après avoir confirmé une défaillance de processus dans comm, les opérations de réception non appariées de type MPI_ANY_SOURCE sur le même comm qui auraient généré une erreur de classe MPIX_ERR_PROC_FAILED_PENDING continueront sans générer d'erreur en raison de cette défaillance confirmée.

De même, MPIX_Comm_agree sur le même comm ne générera pas d'erreur de classe MPI_ERR_PROC_FAILED en raison de cette défaillance confirmée.

Modèles d'utilisation

Il est possible de consulter le nombre de défaillances de processus confirmées dans comm sans effet supplémentaire en fournissant 0 à num_to_ack.

Inversement, il est possible de confirmer de manière inconditionnelle toutes les défaillances de processus connues dans comm en fournissant la taille du groupe de comm à num_to_ack.

Remarque : Le nombre de processus confirmés, tel que retourné par num_acked, peut être inférieur ou supérieur à la valeur fournie dans num_to_ack ; cependant, il ne sera jamais supérieur à la taille du groupe retournée par un appel ultérieur à MPIX_Comm_get_failed.

Effet sur les opérations collectives

Appeler MPIX_Comm_ack_failed sur un communicateur contenant des processus défaillants n'a aucun effet sur les opérations collectives (sauf MPIX_Comm_agree). Si une opération collective génère une erreur en raison du communicateur contenant un processus défaillant, elle continuera à générer une erreur même après que la défaillance ait été confirmée. Pour utiliser des opérations collectives entre des processus MPI d'un communicateur contenant des processus défaillants, les utilisateurs doivent créer un nouveau communicateur (par exemple, en appelant MPIX_Comm_shrink).

Lorsque le communicateur est un communicateur inter

Lorsque le communicateur est un communicateur inter, les défaillances des membres dans les deux groupes, local et distant, de comm sont confirmées.

Erreurs

La plupart des routines MPI retournent une valeur d'erreur ; les routines C retournent la valeur d'erreur comme résultat de la fonction et les routines Fortran dans le dernier argument.

Avant de retourner la valeur d'erreur, le gestionnaire d'erreur associé à l'objet de communication (par exemple, communicateur, fenêtre, fichier) concerné est appelé. S'il n'y a pas d'objet de communication associé à l'appel MPI, l'appel est considéré comme associé à MPI_COMM_SELF et le gestionnaire d'erreur associé sera appelé. Lorsque MPI_COMM_SELF n'est pas initialisé (c'est-à-dire, avant MPI_Init/MPI_Init_thread, après MPI_Finalize, ou lorsque le modèle de Sessions est utilisé exclusivement), l'erreur appelle le gestionnaire d'erreur initial. Le gestionnaire d'erreur initial peut être modifié en appelant MPI_Comm_set_errhandler sur MPI_COMM_SELF lorsque le modèle Monde est utilisé, ou via l'argument mpi_initial_errhandler de mpiexec ou la clé info de MPI_Comm_spawn/MPI_Comm_spawn_multiple. Si aucun autre gestionnaire d'erreur approprié n'est configuré, MPI_ERRORS_RETURN est appelé pour les fonctions d'E/S MPI et MPI_ERRORS_ABORT pour toutes les autres fonctions MPI.

Open MPI inclut trois gestionnaires d'erreur par défaut qui peuvent être utilisés :

  • MPI_ERRORS_ARE_FATAL Provoque la terminaison de tous les processus MPI connectés par le programme.
  • MPI_ERRORS_ABORT Un gestionnaire d'erreur qui peut être invoqué sur un communicateur, une fenêtre, un fichier ou une session. Lorsqu'il est invoqué sur un communicateur, il agit comme si MPI_Abort avait été appelé sur ce communicateur. S'il est invoqué sur une fenêtre ou un fichier, il agit comme si MPI_Abort avait été appelé sur un communicateur contenant les processus dans la fenêtre ou le fichier correspondant. S'il est invoqué sur une session, il n'abandonne que le processus local.
  • MPI_ERRORS_RETURN Retourne un code d'erreur à l'application.

Les applications MPI peuvent également implémenter leurs propres gestionnaires d'erreur en appelant :

  • MPI_Comm_create_errhandler puis MPI_Comm_set_errhandler
  • MPI_File_create_errhandler puis MPI_File_set_errhandler
  • MPI_Session_create_errhandler puis MPI_Session_set_errhandler ou lors de MPI_Session_init
  • MPI_Win_create_errhandler puis MPI_Win_set_errhandler

Remarque : Le nombre de processus confirmés, tel que retourné par num_acked, peut être inférieur ou supérieur à la valeur fournie dans num_to_ack ; cependant, il ne sera jamais supérieur à la taille du groupe retournée par un appel ultérieur à MPIX_Comm_get_failed.

Voir la page de documentation MPI pour une liste complète des codes d'erreur MPI.

Voir la section sur la gestion des erreurs de la norme MPI-3.1 pour plus d'informations.
