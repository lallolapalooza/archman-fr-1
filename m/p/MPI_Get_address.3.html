MPI_GET_ADDRESS(3) Open MPI MPI_GET_ADDRESS(3)

MPI_Get_address — Obtient l'adresse d'un emplacement en mémoire.

SYNTAXE

Syntaxe C

#include <mpi.h>
int MPI_Get_address(const void *location, MPI_Aint *address)

Syntaxe Fortran

USE MPI
! ou la forme plus ancienne : INCLUDE 'mpif.h'
MPI_GET_ADDRESS(LOCATION, ADDRESS, IERROR)
    <type> LOCATION(*)
    INTEGER(KIND=MPI_ADDRESS_KIND) ADDRESS
    INTEGER IERROR

Syntaxe Fortran 2008

USE mpi_f08
MPI_Get_address(location, address, ierror)
    TYPE(*), DIMENSION(..), ASYNCHRONOUS :: location
    INTEGER(KIND=MPI_ADDRESS_KIND), INTENT(OUT) :: address
    INTEGER, OPTIONAL, INTENT(OUT) :: ierror

PARAMÈTRES D'ENTRÉE

•
location : Emplacement dans la mémoire de l'appelant (choix).

PARAMÈTRES DE SORTIE

  • address : Adresse de l'emplacement (entier).
  • ierror : Fortran uniquement : Statut d'erreur (entier).

DESCRIPTION

MPI_Get_address retourne l'adresse en octets d'un emplacement en mémoire.

Exemple : Utilisation de MPI_Get_address pour un tableau.

REAL :: A(100,100)
INTEGER(MPI_ADDRESS_KIND) :: I1, I2, DIFF
CALL MPI_GET_ADDRESS(A(1,1), I1, IERROR)
CALL MPI_GET_ADDRESS(A(10,10), I2, IERROR)
DIFF = I2 - I1
! La valeur de DIFF est 909*sizeofreal ; les valeurs de I1 et I2 dépendent
! de l'implémentation.

NOTES

Cette routine est fournie pour les programmeurs Fortran et C et peut être utile lors de l'écriture de code portable. Dans la version actuelle, l'adresse retournée par cette routine sera la même que celle produite par l'opérateur C &.

Les utilisateurs C pourraient être tentés d'éviter d'utiliser MPI_Get_address et de s'appuyer sur la disponibilité de l'opérateur d'adresse &. Notez, cependant, que & expression_cast est un pointeur, pas une adresse. ANSI C n'exige pas que la valeur d'un pointeur (ou du pointeur converti en int) soit l'adresse absolue de l'objet pointé, bien que ce soit souvent le cas. De plus, la référence peut ne pas avoir une définition unique sur les machines avec un espace d'adressage segmenté. L'utilisation de MPI_Get_address pour « référencer » des variables C garantit la portabilité vers de telles machines également.

Les codes MPI Fortran actuels s'exécuteront sans modification et seront portables sur n'importe quel système. Cependant, ils pourraient échouer si des adresses supérieures à 2^32 - 1 sont utilisées dans le programme. Les nouveaux codes doivent être écrits de manière à utiliser les nouvelles fonctions. Cela assure la compatibilité avec C et évite les erreurs sur les architectures 64 bits. Cependant, ces nouveaux codes pourraient devoir être (légèrement) réécrits pour être portés sur des environnements Fortran 77 anciens qui ne supportent pas les déclarations KIND.

ERREURS

Presque toutes les routines MPI retournent une valeur d'erreur ; les routines C comme résultat de la fonction et les routines Fortran dans le dernier argument.

Avant que la valeur d'erreur ne soit retournée, le gestionnaire d'erreurs MPI actuel associé à l'objet de communication (par exemple, communicateur, fenêtre, fichier) est appelé. Si aucun objet de communication n'est associé à l'appel MPI, alors l'appel est considéré comme attaché à MPI_COMM_SELF et appellera le gestionnaire d'erreurs MPI associé. Lorsque MPI_COMM_SELF n'est pas initialisé (c'est-à-dire avant MPI_Init/MPI_Init_thread, après MPI_Finalize, ou lorsque vous utilisez uniquement le modèle Sessions) l'erreur déclenche le gestionnaire d'erreurs initial. Le gestionnaire d'erreurs initial peut être modifié en appelant MPI_Comm_set_errhandler sur MPI_COMM_SELF lors de l'utilisation du modèle World, ou via l'argument CLI mpi_initial_errhandler de mpiexec ou la clé d'information de MPI_Comm_spawn/MPI_Comm_spawn_multiple. Si aucun autre gestionnaire d'erreurs approprié n'a été défini, alors le gestionnaire d'erreurs MPI_ERRORS_RETURN est appelé pour les fonctions d'E/S MPI et le gestionnaire d'erreurs MPI_ERRORS_ABORT est appelé pour toutes les autres fonctions MPI.

Open MPI inclut trois gestionnaires d'erreurs prédéfinis qui peuvent être utilisés :

  • MPI_ERRORS_ARE_FATAL Provoque l'arrêt du programme sur tous les processus MPI connectés.
  • MPI_ERRORS_ABORT Un gestionnaire d'erreurs qui peut être invoqué sur un communicateur, une fenêtre, un fichier ou une session. Lorsqu'il est appelé sur un communicateur, il agit comme si MPI_Abort avait été appelé sur ce communicateur. S'il est appelé sur une fenêtre ou un fichier, il agit comme si MPI_Abort avait été appelé sur un communicateur contenant le groupe de processus de la fenêtre ou du fichier correspondant. S'il est appelé sur une session, il n'interrompt que le processus local.
  • MPI_ERRORS_RETURN Retourne un code d'erreur à l'application.

Les applications MPI peuvent également implémenter leurs propres gestionnaires d'erreurs en appelant :

  • MPI_Comm_create_errhandler puis MPI_Comm_set_errhandler
  • MPI_File_create_errhandler puis MPI_File_set_errhandler
  • MPI_Session_create_errhandler puis MPI_Session_set_errhandler ou à MPI_Session_init
  • MPI_Win_create_errhandler puis MPI_Win_set_errhandler

Notez que MPI ne garantit pas qu'un programme MPI puisse continuer après une erreur.

Voir la page de manuel MPI pour une liste complète des codes d'erreur MPI.

Voir la section Gestion des erreurs de la norme MPI-3.1 pour plus d'informations.
