PARAMETRES D'ENTRÉE

  • sendbuf: Adresse de départ du tampon d'envoi.
  • sendcounts: Tableau d'entiers, où l'entrée i spécifie le nombre d'éléments à envoyer au voisin i.
  • sdispls: Tableau d'entiers, où l'entrée i spécifie le déplacement (en octets, décalage par rapport à sendbuf) à partir duquel envoyer les données au voisin i.
  • sendtypes: Tableau de types de données, où l'entrée i spécifie le type de données à utiliser lors de l'envoi de données au voisin i.
  • recvcounts: Tableau d'entiers, où l'entrée j spécifie le nombre d'éléments à recevoir du voisin j.
  • rdispls: Tableau d'entiers, où l'entrée j spécifie le déplacement (en octets, décalage par rapport à recvbuf) auquel les données du voisin j doivent être écrites.
  • recvtypes: Tableau de types de données, où l'entrée j spécifie le type de données à utiliser lors de la réception de données du voisin j.
  • comm: Communicateur sur lequel les données doivent être échangées.
  • info: Informations (handle, persistant uniquement).

PARAMETRES DE SORTIE

  • recvbuf: Adresse du tampon de réception.
  • request: Requête (handle, non bloquant uniquement).
  • ierror: Fortran uniquement : Statut d'erreur.

DESCRIPTION

MPI_Neighbor_alltoallw est une opération collective généralisée dans laquelle tous les processus envoient des données à et reçoivent des données de tous les voisins. Elle ajoute de la flexibilité à MPI_Neighbor_alltoallv en permettant à l'utilisateur de spécifier le type de données des blocs individuels (en plus du déplacement et du nombre d'éléments). Son fonctionnement peut être pensé de la manière suivante, où chaque processus effectue 2n (n étant le nombre de voisins dans la topologie du communicateur comm) communications point à point indépendantes. Les voisins et la disposition des tampons sont déterminés par la topologie de comm.

MPI_Cart_get(comm, maxdims, dims, periods, coords);
for (dim = 0, i = 0 ; dim < dims ; ++dim) {
    MPI_Cart_shift(comm, dim, 1, &r0, &r1);
    MPI_Isend(sendbuf + sdispls[i]  * extent(sendtype),
              sendcount, sendtypes[i], r0, ..., comm, ...);
    MPI_Irecv(recvbuf + rdispls[i] * extent(recvtype),
              recvcount, recvtypes[i], r0, ..., comm, ...);
    ++i;
    MPI_Isend(sendbuf + sdispls[i] * extent(sendtype),
              sendcount, sendtypes[i], r1, ..., comm, &req[i]);
    MPI_Irecv(recvbuf + rdispls[i] * extent(recvtype),
              recvcount, recvtypes[i], r1, ..., comm, ...);
    ++i;
}
MPI_Wait_all (...);
MPI_Comm_size(comm, &n);
for (i = 0, i < n; i++)
  MPI_Send(sendbuf + sdispls[i], sendcounts[i],
       sendtypes[i], i, ..., comm);
for (i = 0, i < n; i++)
  MPI_Recv(recvbuf + rdispls[i], recvcounts[i],
       recvtypes[i], i, ..., comm);

Le processus j envoie le k-ième bloc de son sendbuf local au voisin k, qui place les données dans le j-ième bloc de son recvbuf local.

Lorsqu'une paire de processus échange des données, chacun peut passer des arguments de compte et de type différents tant que l'expéditeur spécifie la même quantité de données à envoyer (en octets) que celle que le destinataire s'attend à recevoir.

Notez qu'un processus i peut envoyer une quantité de données différente au processus j de ce qu'il reçoit du processus j. De plus, un processus peut envoyer des quantités et des types de données entièrement différents à des processus différents dans le communicateur.

NOTES

L'option MPI_IN_PLACE pour sendbuf n'est pas significative pour cette opération.

La spécification des comptes, des types et des déplacements ne doit pas entraîner l'écriture d'un emplacement plus d'une fois.

Tous les arguments sur tous les processus sont significatifs. L'argument comm, en particulier, doit décrire le même communicateur sur tous les processus.

Les décalages de sdispls et rdispls sont mesurés en octets. Comparez cela à MPI_Neighbor_alltoallv, où ces décalages sont mesurés en unités de sendtype et recvtype, respectivement.

PARAMÈTRES D'ENTRÉE

Avant que la valeur d'erreur ne soit retournée, le gestionnaire d'erreurs MPI actuel associé à l'objet de communication (par exemple, communicateur, fenêtre, fichier) est appelé. Si aucun objet de communication n'est associé à l'appel MPI, l'appel est considéré comme attaché à MPI_COMM_SELF et appellera le gestionnaire d'erreurs MPI associé. Lorsque MPI_COMM_SELF n'est pas initialisé (c'est-à-dire avant MPI_Init/MPI_Init_thread, après MPI_Finalize, ou lors de l'utilisation exclusive du modèle de Sessions), l'erreur déclenche le gestionnaire d'erreurs initial. Le gestionnaire d'erreurs initial peut être modifié en appelant MPI_Comm_set_errhandler sur MPI_COMM_SELF lors de l'utilisation du modèle World, ou par l'argument CLI mpi_initial_errhandler de mpiexec ou par la clé d'information de MPI_Comm_spawn/MPI_Comm_spawn_multiple. Si aucun autre gestionnaire d'erreurs approprié n'a été défini, le gestionnaire d'erreurs MPI_ERRORS_RETURN est appelé pour les fonctions MPI I/O et le gestionnaire d'erreurs MPI_ERRORS_ABORT est appelé pour toutes les autres fonctions MPI.

PARAMÈTRES DE SORTIE

Open MPI inclut trois gestionnaires d'erreurs prédéfinis qui peuvent être utilisés :

  • MPI_ERRORS_ARE_FATAL Provoque l'arrêt du programme sur tous les processus MPI connectés.
  • MPI_ERRORS_ABORT Un gestionnaire d'erreurs qui peut être invoqué sur un communicateur, une fenêtre, un fichier ou une session. Lorsqu'il est appelé sur un communicateur, il agit comme si MPI_Abort avait été appelé sur ce communicateur. S'il est appelé sur une fenêtre ou un fichier, il agit comme si MPI_Abort avait été appelé sur un communicateur contenant le groupe de processus de la fenêtre ou du fichier correspondant. S'il est appelé sur une session, il n'interrompt que le processus local.
  • MPI_ERRORS_RETURN Retourne un code d'erreur à l'application.

Les applications MPI peuvent également implémenter leurs propres gestionnaires d'erreurs en appelant :

  • MPI_Comm_create_errhandler puis MPI_Comm_set_errhandler
  • MPI_File_create_errhandler puis MPI_File_set_errhandler
  • MPI_Session_create_errhandler puis MPI_Session_set_errhandler ou lors de MPI_Session_init
  • MPI_Win_create_errhandler puis MPI_Win_set_errhandler

Notez que MPI ne garantit pas qu'un programme MPI puisse continuer après une erreur.
