MPI_Accumulate, MPI_Raccumulate — Combine les contenus d'un tampon source avec un tampon de destination.

Paramètres d'entrée

  • origin_addr : Adresse de départ du tampon (argument).
  • origin_count : Nombre d'éléments dans le tampon (entier non négatif).
  • origin_datatype : Type de données de chaque élément du tampon (handle).
  • target_rank : Rangement de la cible (entier non négatif).
  • target_disp : Décalage depuis le début de la fenêtre jusqu'au début du tampon de destination (entier non négatif).
  • target_count : Nombre d'éléments dans le tampon de destination (entier non négatif).
  • target_datatype : Type de données de chaque élément du tampon de destination (handle).
  • op : Opération de réduction (handle).
  • win : Objet fenêtre (handle).

Paramètre de sortie

  • MPI_Raccumulate : Requête RMA
  • ierror : En Fortran uniquement : État d'erreur (entier).

Description

MPI_Accumulate est une fonction utilisée pour la communication MPI unidirectionnelle qui ajoute les contenus du tampon source (défini par origin_addr, origin_count et origin_datatype) au tampon spécifié par les arguments target_count et target_datatype, à la position target_disp de la fenêtre de destination (dans la fenêtre de destination spécifiée par target_rank et win), en utilisant l'opération op. La fenêtre de destination ne peut être accédée que par des processus du même nœud. Ceci est similaire à MPI_Put, sauf que les données sont combinées dans la zone de destination au lieu de la remplacer.

Toutes les opérations prédéfinies pour MPI_Reduce peuvent être utilisées. Les fonctions définies par l'utilisateur ne peuvent pas être utilisées. Par exemple, si op est MPI_SUM, chaque élément du tampon source est ajouté à l'élément correspondant dans le tampon de destination, remplaçant la valeur précédente dans la destination.

Chaque argument de type de données doit être un type de données prédéfini ou un type de données dérivé, où tous les composants de base sont du même type de données prédéfini. Les deux arguments de type de données doivent être construits à partir du même type de données prédéfini. L'opération op s'applique aux éléments de ce type prédéfini. L'argument target_datatype doit spécifier des éléments non chevauchants, et le tampon de destination doit être contenu dans la fenêtre de destination.

Une nouvelle opération prédéfinie, MPI_REPLACE, est définie, qui correspond à la fonction associative f(a, b) = b, c'est-à-dire que la valeur actuelle dans la mémoire de destination est remplacée par la valeur fournie par le tampon source.

MPI_Raccumulate est similaire à MPI_Accumulate, sauf qu'elle attribue une requête de communication de type objet et l'associe à l'objet de requête de la requête (l'argument request), qui peut être utilisé pour attendre ou tester l'avancement de l'opération. L'avancement d'une opération MPI_Raccumulate indique que le tampon origin_addr est libre d'être mis à jour. Il n'indique pas que l'opération est terminée dans la fenêtre de destination.

Remarques

MPI_Put est un cas particulier de MPI_Accumulate, avec l'opération MPI_REPLACE. Cependant, il est important de noter que MPI_Put et MPI_Accumulate ont des restrictions différentes concernant les mises à jour simultanées.

Il incombe à l'utilisateur de s'assurer que, lors de l'utilisation des fonctions d'accumulation, le décalage de destination est tel que les accès à la fenêtre sont correctement alignés selon les arguments de type de données dans l'appel à la fonction MPI_Accumulate.

Erreurs

La plupart des routines MPI renvoient une valeur d'erreur ; les routines C renvoient la valeur d'erreur comme résultat de la fonction et les routines Fortran dans le dernier argument.

Avant que la valeur d'erreur ne soit renvoyée, le gestionnaire d'erreurs actuel associé à l'objet de communication (par exemple, communicateur, fenêtre, fichier) du processus est appelé. S'il n'y a pas d'objet de communication associé à l'appel MPI, l'appel est considéré comme associé à MPI_COMM_SELF et le gestionnaire d'erreurs associé à MPI_COMM_SELF sera appelé. Lorsque MPI_COMM_SELF n'est pas initialisé (c'est-à-dire avant MPI_Init/MPI_Init_thread, après MPI_Finalize, ou lorsque le modèle de sessions est utilisé exclusivement), le gestionnaire d'erreurs initial est déclenché. Le gestionnaire d'erreurs initial peut être modifié en appelant MPI_Comm_set_errhandler sur MPI_COMM_SELF lorsque le modèle du monde est utilisé, ou par la clé d'informations mpi_initial_errhandler de mpiexec ou la clé d'informations de MPI_Comm_spawn/MPI_Comm_spawn_multiple. Si aucun autre gestionnaire d'erreurs approprié n'est défini, le gestionnaire d'erreurs MPI_ERRORS_RETURN est appelé pour les fonctions d'E/S MPI et le gestionnaire d'erreurs MPI_ERRORS_ABORT pour les autres fonctions MPI.

Open MPI inclut trois gestionnaires d'erreurs par défaut qui peuvent être utilisés :

  • MPI_ERRORS_ARE_FATAL : L'application abandonne tous les processus connectés à MPI.
  • MPI_ERRORS_ABORT : Un gestionnaire d'erreurs qui peut être invoqué sur un communicateur, une fenêtre, un fichier ou une session. Lorsqu'il est appelé sur un communicateur, il agit comme si MPI_Abort avait été appelé sur ce communicateur. S'il est appelé sur une fenêtre ou un fichier, il agit comme si MPI_Abort avait été appelé sur un communicateur qui contient le groupe de processus dans la fenêtre ou le fichier correspondant. S'il est appelé sur une session, il abandonne uniquement le processus local.
  • MPI_ERRORS_RETURN : Renvoie un code d'erreur à l'application.

Les applications MPI peuvent également implémenter leurs propres gestionnaires d'erreurs en appelant :

  • MPI_Comm_create_errhandler puis MPI_Comm_set_errhandler
  • MPI_File_create_errhandler puis MPI_File_set_errhandler
  • MPI_Session_create_errhandler puis MPI_Session_set_errhandler ou
