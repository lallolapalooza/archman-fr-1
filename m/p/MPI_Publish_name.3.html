MPI_Publish_name — Publie un nom de service associé à un port

SYNTAXE

Syntaxe C

#include <mpi.h>
int MPI_Publish_name(const char *service_name, MPI_Info info,
     const char *port_name)

Syntaxe Fortran

USE MPI
! ou l'ancienne forme : INCLUDE 'mpif.h'
MPI_PUBLISH_NAME(SERVICE_NAME, INFO, PORT_NAME, IERROR)
     CHARACTER*(*)   SERVICE_NAME, PORT_NAME
     INTEGER         INFO, IERROR

Syntaxe Fortran 2008

USE mpi_f08
MPI_Publish_name(service_name, info, port_name, ierror)
     TYPE(MPI_Info), INTENT(IN) :: info
     CHARACTER(LEN=*), INTENT(IN) :: service_name, port_name
     INTEGER, OPTIONAL, INTENT(OUT) :: ierror

PARAMÈTRES D'ENTRÉE

  • service_name : Un nom de service (chaîne de caractères).
  • info : Options pour les fonctions de service de nom (descripteur).
  • port_name : Un nom de port (chaîne de caractères).

PARAMÈTRE DE SORTIE

•
ierror : Fortran uniquement : Statut d'erreur (entier).

DESCRIPTION

Cette routine publie la paire (service_name, port_name) afin qu'une application puisse récupérer port_name en appelant MPI_Lookup_name avec service_name comme argument. Il est interdit de publier le même service_name deux fois, ou d'utiliser un argument port_name qui n'a pas été précédemment ouvert par le processus appelant via un appel à MPI_Open_port.

ARGUMENTS INFO

Les clés suivantes pour info sont reconnues :

Clé                   Type      Description
---                   ----      -----------
ompi_global_scope     bool      Si vrai, publie le nom dans la portée
                                globale. Sinon, publie dans la portée
                                locale. Voir la section PORTÉE DES NOMS
                                pour plus de détails.
ompi_unique           bool      Si vrai, renvoie une erreur si le
                                service_name spécifié existe déjà.
                                Par défaut, écrase toute valeur préexistante.

Les clés d'information booléennes sont en fait des chaînes de caractères mais sont évaluées comme suit : si la valeur de la chaîne est un nombre, elle est convertie en entier et castée en booléen (ce qui signifie que les entiers zéro sont faux et les valeurs non nulles sont vraies). Si la valeur de la chaîne est “yes” ou “true” (insensible à la casse), le booléen est vrai. Si la valeur de la chaîne est “no” ou “false” (insensible à la casse), le booléen est faux. Toutes les autres valeurs de chaîne sont non reconnues et donc fausses.

Si aucune clé d'information n'est fournie, la fonction vérifiera d'abord si un serveur global a été spécifié et est disponible. Si c'est le cas, la fonction de publication sera par défaut dans la portée globale d'abord, puis locale. Sinon, les données seront publiées par défaut dans la portée locale.

PORTÉE DES NOMS

Open MPI prend en charge deux portées de nom : globale et locale. La portée locale place la paire service/port spécifiée dans une base de données située sur le mpirun du travail du processus appelant. Ainsi, les données publiées avec une portée locale ne seront accessibles qu'aux processus des travaux lancés par ce mpirun - par exemple, les processus du travail du processus appelant, ou les travaux lancés via MPI_Comm_spawn.

La portée globale place la paire service/port spécifiée dans une base de données située sur un serveur central accessible à tous les travaux en cours d'exécution dans le cluster ou l'environnement. Ainsi, les données publiées avec une portée globale peuvent être accessibles par plusieurs mpirun et utilisées pour MPI_Comm_connect et MPI_Comm_accept entre les travaux.

Notez que les opérations de portée globale nécessitent à la fois la présence du serveur central et que le processus appelant puisse communiquer avec ce serveur. MPI_Publish_name renverra une erreur si la portée globale est spécifiée et qu'un serveur global n'est pas spécifié ou ne peut pas être trouvé.

Open MPI fournit un serveur appelé ompi-server pour prendre en charge les opérations de portée globale. Veuillez vous référer à sa page de manuel pour une description plus détaillée des opérations de stockage/recherche de données.

À titre d'exemple de l'impact de ces règles de portée, considérons le cas où un travail a été lancé avec mpirun - appelons ce travail “travail1”. Un processus dans travail1 crée et publie une paire service/port en utilisant une portée locale. Open MPI stockera ces données dans la base de données située dans mpirun.

Un processus dans travail1 (peut-être le même que celui qui a fait la publication, ou peut-être un autre processus dans le travail) appelle ultérieurement MPI_Comm_spawn pour lancer un autre travail (appelons-le “travail2”) sous ce mpirun. Étant donné que les deux travaux partagent un mpirun commun, les deux travaux ont accès aux données de portée locale. Par conséquent, un processus dans travail2 peut effectuer une MPI_Lookup_name avec une portée locale pour récupérer les informations.

Cependant, supposons qu'un autre utilisateur lance un travail à l'aide de mpirun - appelons ce travail “travail3”. Parce que les données de service/port publiées par travail1 ont spécifié une portée locale, les processus dans travail3 ne peuvent pas accéder à ces données. En revanche, si les données avaient été publiées en utilisant une portée globale, alors tout processus dans travail3 pourrait accéder aux données, à condition que mpirun ait été informé de la manière de contacter le serveur central et que le processus puisse établir une communication avec lui.

ERREURS

Presque toutes les routines MPI renvoient une valeur d'erreur ; les routines C comme résultat de retour de la fonction et les routines Fortran dans le dernier argument.

Avant que la valeur d'erreur ne soit renvoyée, le gestionnaire d'erreurs MPI actuel associé à l'objet de communication (par exemple, communicateur, fenêtre, fichier) est appelé. Si aucun objet de communication n'est associé à l'appel MPI, alors l'appel est considéré comme attaché à MPI_COMM_SELF et appellera le gestionnaire d'erreurs MPI associé. Lorsque MPI_COMM_SELF n'est pas initialisé (c'est-à-dire, avant MPI_Init/MPI_Init_thread, après MPI_Finalize, ou lors de l'utilisation exclusive du modèle de sessions) l'erreur déclenche le gestionnaire d'erreurs initial. Le gestionnaire d'erreurs initial peut être modifié en appelant MPI_Comm_set_errhandler sur MPI_COMM_SELF lors de l'utilisation du modèle World, ou l'argument CLI mpi_initial_errhandler pour mpiexec ou la clé d'information pour MPI_Comm_spawn/MPI_Comm_spawn_multiple. Si aucun autre gestionnaire d'erreurs approprié n'a été défini, alors le gestionnaire d'erreurs MPI_ERRORS_RETURN est appelé pour les fonctions d'E/S MPI et le gestionnaire d'erreurs MPI_ERRORS_ABORT est appelé pour toutes les autres fonctions MPI.

Open MPI inclut trois gestionnaires d'erreurs prédéfinis qui peuvent être utilisés :

  • MPI_ERRORS_ARE_FATAL Provoque l'arrêt du programme par tous les processus MPI connectés.
  • MPI_ERRORS_ABORT Un gestionnaire d'erreurs qui peut être invoqué sur un communicateur, une fenêtre, un fichier ou une session. Lorsqu'il est appelé sur un communicateur, il agit comme si MPI_Abort avait été appelé sur ce communicateur. S'il est appelé sur une fenêtre ou un fichier, il agit comme si MPI_Abort avait été appelé sur un communicateur contenant le groupe des processus dans la fenêtre ou le fichier correspondant. S'il est appelé sur une session, il n'interrompt que le processus local.
  • MPI_ERRORS_RETURN Renvoie un code d'erreur à l'application.

Les applications MPI peuvent également implémenter leurs propres gestionnaires d'erreurs en appelant :

  • MPI_Comm_create_errhandler puis MPI_Comm_set_errhandler
  • MPI_File_create_errhandler puis MPI_File_set_errhandler
  • MPI_Session_create_errhandler puis MPI_Session_set_errhandler ou à MPI_Session_init
  • MPI_Win_create_errhandler puis MPI_Win_set_errhandler

Notez que MPI ne garantit pas qu'un programme MPI puisse continuer après une erreur.

Voir la page de manuel MPI pour une liste complète des codes d'erreur MPI.

NAME

MPI_Publish_name - Publie un nom d’URI de service pour une utilisation future par d’autres processus.

SYNTAX

C

int MPI_Publish_name(const char *service_name, struct ompi_info_t *info);

Fortran

SUBROUTINE MPI_PUBLISH_NAME(SERVICE_NAME, INFO, IERROR)

    CHARACTER(LEN=*), INTENT(IN) :: SERVICE_NAME
    INTEGER, INTENT(IN) :: INFO
    INTEGER, INTENT(OUT) :: IERROR

C++

void MPI::Publish_name(const std::string& service_name, const MPI::Info& info);

INPUT PARAMETERS

service_name
Le nom du service à publier.
info
Objet d’informations MPI.

OUTPUT PARAMETER

IERROR
Entier Fortran.

DESCRIPTION

La fonction MPI_Publish_name publie un nom de service, éventuellement associé à des informations supplémentaires, pour une utilisation future par d’autres processus via MPI_Lookup_name. Le nom du service est un chaîne de caractères qui identifie de manière unique un service. L’objet info peut contenir des informations supplémentaires sur le service, telles que l’URI du point de terminaison du service.

INFO ARGUMENTS

L’objet info est un objet MPI_Info qui peut contenir des paires clé-valeur. Pour MPI_Publish_name, les clés suivantes sont pertinentes :

  • MPI_UN NAMED : Si cette clé est présente, le nom du service n’est pas rendu public, mais il est stocké dans le processus appelant. Cela peut être utile pour des applications qui souhaitent générer un nom mais ne veulent pas le rendre accessible globalement.
  • hostname : L’URI du point de terminaison du service.

NAME SCOPE

Le nom du service est visible par tous les processus de l’application MPI.

ERRORS

Les erreurs MPI sont généralement gérées par le code de retour IERROR. En outre, les erreurs suivantes peuvent survenir :

  • MPI_ERR_INFO : L’objet info est invalide.
  • MPI_ERR_ARG : Le nom du service est invalide ou vide.

Pour plus d’informations sur la gestion des erreurs, consultez la norme MPI-3.1.
