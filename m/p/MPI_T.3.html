MPI_T(3) Open MPI MPI_T(3)

Interface MPI_T d'Open MPI - Informations générales

DESCRIPTION

Il y a quelques notes spécifiques à Open MPI concernant son implémentation de l'interface MPI_T qui méritent d'être mentionnées.

Variables de contrôle MPI_T

L'implémentation par Open MPI des API de variables de contrôle MPI_T (ou "cvar") est une interface aux paramètres/variables de l'architecture modulaire de composants (MCA) sous-jacente d'Open MPI. En termes simples : l'utilisation de l'interface cvar MPI_T est un autre mécanisme pour obtenir/définir les paramètres MCA d'Open MPI.

Par ordre de priorité (du plus élevé au plus bas), Open MPI fournit les mécanismes suivants pour définir les paramètres MCA :

1.
L'interface MPI_T a la priorité la plus élevée. Spécifiquement : les valeurs définies via l'interface MPI_T remplaceront tous les autres réglages.
2.
La ligne de commande mpirun(1) / mpiexec(1) (par exemple, via le paramètre –mca).
3.
Les variables d'environnement.
4.
Les fichiers de paramètres ont la priorité la plus basse. Spécifiquement : les valeurs définies via les fichiers de paramètres peuvent être remplacées par l'un des autres mécanismes de définition de variables MCA.

Initialisation MPI

Une application peut utiliser l'interface MPI_T avant l'initialisation de MPI pour définir des paramètres MCA. La définition de paramètres MCA de niveau MPI avant l'initialisation de MPI peut affecter la manière dont MPI est initialisé (par exemple, en influençant les frameworks et composants qui sont sélectionnés).

L'exemple suivant définit les paramètres MCA pml et btl avant d'appeler MPI_Init afin de forcer une sélection spécifique des composants PML et BTL :

int provided, index, count;
MPI_T_cvar_handle pml_handle, btl_handle;
char pml_value[64], btl_value[64];
MPI_T_init_thread(MPI_THREAD_SINGLE, &provided);
MPI_T_cvar_get_index("pml", &index);
MPI_T_cvar_handle_alloc(index, NULL, &pml_handle, &count);
MPI_T_cvar_write(pml_handle, "ob1");
MPI_T_cvar_get_index("btl", &index);
MPI_T_cvar_handle_alloc(index, NULL, &btl_handle, &count);
MPI_T_cvar_write(btl_handle, "tcp,vader,self");
MPI_T_cvar_read(pml_handle, pml_value);
MPI_T_cvar_read(btl_handle, btl_value);
printf("Set value of cvars: PML: %s, BTL: %s\n",
       pml_value, btl_value);
MPI_T_cvar_handle_free(&pml_handle);
MPI_T_cvar_handle_free(&btl_handle);
MPI_Init(NULL, NULL);
// ...
MPI_Finalize();
MPI_T_finalize();

Notez qu'une fois que MPI est initialisé, la plupart des cvars d'Open MPI deviennent en lecture seule.

Par exemple, après l'initialisation de MPI, il n'est plus possible de définir les mécanismes de sélection PML et BTL. Ceci est dû au fait que bon nombre de ces paramètres MCA ne sont utilisés que pendant l'initialisation de MPI ; les définir après que MPI ait déjà été initialisé serait de toute façon dénué de sens.

Catégories MPI_T

Les catégories MPI_T d'Open MPI sont organisées hiérarchiquement :

1.
Couche (ou "projet"). Il y a deux couches dans Open MPI :
  • ompi : Cette couche contient les cvars, pvars et sous-catégories liés aux caractéristiques MPI.
  • opal : Cette couche contient généralement des cvars, pvars et sous-catégories de constructions de couches inférieures, telles que les problèmes du système d'exploitation, les problèmes de réseau, etc.
2.
Framework ou section.
•
Dans la plupart des cas, le niveau suivant dans la hiérarchie est le framework MCA d'Open MPI.
  • Par exemple, vous pouvez trouver le framework btl sous la couche opal (car il concerne le réseau sous-jacent).
  • De plus, le framework pml est sous la couche ompi (car il concerne la sémantique MPI des messages point à point).
•
Il existe cependant quelques entités non-framework MCA sous la couche.
•
Par exemple, il existe une section mpi sous les couches opal et ompi pour les constructions MPI générales/de base.
3.
Composant.
  • Si pertinent, le troisième niveau de la hiérarchie est le composant MCA.
  • Par exemple, le composant tcp se trouve sous le framework opal dans la couche opal.
