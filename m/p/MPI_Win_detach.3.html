MPI_Win_detach(3)

Paquet: openmpi

Licences: BSD-3-Clause AND LicenseRef-MPICH

MPI_WIN_DETACH(3) Open MPI MPI_WIN_DETACH(3)

MPI_Win_attach, MPI_Win_detach - Appel MPI unilatéral qui attache / détache une région mémoire à / d'un objet fenêtre pour les opérations RMA.

SYNTAXE

Syntaxe C

#include <mpi.h>
MPI_Win_attach(MPI_Win win, void *base, MPI_Aint size)
MPI_Win_detach(MPI_Win win, void *base)

Syntaxe Fortran

USE MPI
! ou la forme plus ancienne : INCLUDE 'mpif.h'
MPI_WIN_ATTACH(WIN, BASE, SIZE, IERROR)
     <type> BASE(*)
     INTEGER(KIND=MPI_ADDRESS_KIND) SIZE
     INTEGER WIN, IERROR
MPI_WIN_DETACH(WIN, BASE, IERROR)
     <type> BASE(*)
     INTEGER WIN, IERROR

Syntaxe Fortran 2008

USE mpi_f08
MPI_Win_attach(win, base, size, ierror)
     TYPE(MPI_Win), INTENT(IN) :: win
     TYPE(*), DIMENSION(..), INTENT(IN) :: base
     INTEGER(KIND=MPI_ADDRESS_KIND), INTENT(IN) :: size
     INTEGER, OPTIONAL, INTENT(OUT) :: ierror
MPI_Win_detach(win, base, ierror)
     TYPE(MPI_Win), INTENT(IN) :: win
     TYPE(*), DIMENSION(..), INTENT(IN) :: base
     INTEGER, OPTIONAL, INTENT(OUT) :: ierror

PARAMÈTRES D'ENTRÉE

  • win : Une fenêtre créée avec MPI_Win_create_dynamic.
  • base : Adresse initiale de la fenêtre (choix).
  • size : Taille de la fenêtre en octets (entier non négatif).

PARAMÈTRES DE SORTIE

  • win : Objet fenêtre renvoyé par l'appel (handle).
  • ierror : Uniquement Fortran : statut d'erreur (entier).

DESCRIPTION

MPI_Win_attach est un appel de communication MPI unilatéral utilisé pour attacher une région mémoire de size octets commençant à l'adresse base à une fenêtre pour un accès RMA. La fenêtre win doit avoir été créée en utilisant MPI_Win_create_dynamic. Plusieurs régions mémoire non chevauchantes peuvent être attachées à la même fenêtre dynamique. L'attachement de régions mémoire chevauchantes à la même fenêtre dynamique est une erreur.

Si la valeur de base utilisée par MPI_Win_attach a été allouée par MPI_Alloc_mem, la taille de la fenêtre ne peut pas être supérieure à la valeur définie par la fonction MPI_Alloc_mem.

MPI_Win_detach peut être utilisé pour détacher une région mémoire précédemment attachée de win. L'adresse mémoire base et win doivent correspondre aux arguments passés à un appel précédent à MPI_Win_attach.

NOTES

Utilisez la mémoire allouée par MPI_Alloc_mem pour garantir des limites de fenêtre correctement alignées (par exemple, mot, double mot, ligne de cache, page mémoire, etc.).

ERREURS

Presque toutes les routines MPI renvoient une valeur d'erreur ; les routines C en tant que résultat de retour de la fonction et les routines Fortran dans le dernier argument.

Avant que la valeur d'erreur ne soit renvoyée, le gestionnaire d'erreurs MPI actuel associé à l'objet de communication (par exemple, communicateur, fenêtre, fichier) est appelé. Si aucun objet de communication n'est associé à l'appel MPI, alors l'appel est considéré comme attaché à MPI_COMM_SELF et appellera le gestionnaire d'erreurs MPI associé. Lorsque MPI_COMM_SELF n'est pas initialisé (c'est-à-dire avant MPI_Init/MPI_Init_thread, après MPI_Finalize, ou lors de l'utilisation exclusive du modèle de sessions), l'erreur déclenche le gestionnaire d'erreurs initial. Le gestionnaire d'erreurs initial peut être modifié en appelant MPI_Comm_set_errhandler sur MPI_COMM_SELF lors de l'utilisation du modèle World, ou via l'argument de ligne de commande mpi_initial_errhandler de mpiexec ou la clé d'information de MPI_Comm_spawn/MPI_Comm_spawn_multiple. Si aucun autre gestionnaire d'erreurs approprié n'a été défini, alors le gestionnaire d'erreurs MPI_ERRORS_RETURN est appelé pour les fonctions d'E/S MPI et le gestionnaire d'erreurs MPI_ERRORS_ABORT est appelé pour toutes les autres fonctions MPI.

Open MPI inclut trois gestionnaires d'erreurs prédéfinis qui peuvent être utilisés :

  • MPI_ERRORS_ARE_FATAL Provoque l'arrêt de tous les processus MPI connectés.
  • MPI_ERRORS_ABORT Un gestionnaire d'erreurs qui peut être invoqué sur un communicateur, une fenêtre, un fichier ou une session. Lorsqu'il est appelé sur un communicateur, il agit comme si MPI_Abort était appelé sur ce communicateur. S'il est appelé sur une fenêtre ou un fichier, il agit comme si MPI_Abort était appelé sur un communicateur contenant le groupe des processus de la fenêtre ou du fichier correspondant. S'il est appelé sur une session, il n'aborte que le processus local.
  • MPI_ERRORS_RETURN Renvoie un code d'erreur à l'application.

Les applications MPI peuvent également implémenter leurs propres gestionnaires d'erreurs en appelant :

  • MPI_Comm_create_errhandler puis MPI_Comm_set_errhandler
  • MPI_File_create_errhandler puis MPI_File_set_errhandler
  • MPI_Session_create_errhandler puis MPI_Session_set_errhandler ou à MPI_Session_init
  • MPI_Win_create_errhandler puis MPI_Win_set_errhandler

Notez que MPI ne garantit pas qu'un programme MPI puisse continuer après une erreur.

Voir la page de manuel MPI pour une liste complète des codes d'erreur MPI.

Voir la section Gestion des erreurs de la norme MPI-3.1 pour plus d'informations.
