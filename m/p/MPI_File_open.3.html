MPI_File_open(3)

Paquet: openmpi

MPI_File_open(3) Open MPI MPI_File_open(3)

MPI_File_open ouvre un fichier (collaborativement).

Syntaxe

Syntaxe C

#include <mpi.h>
int MPI_File_open(MPI_Comm comm, const char *filename,
     int amode, MPI_Info info,
     MPI_File *fh)

Syntaxe Fortran

USE MPI
! ou l'ancienne forme : INCLUDE 'mpif.h'
MPI_FILE_OPEN(COMM, FILENAME, AMODE, INFO, FH, IERROR)
     CHARACTER*(*)   FILENAME
     INTEGER COMM, AMODE, INFO, FH, IERROR

Syntaxe Fortran 2008

USE mpi_f08
MPI_File_open(comm, filename, amode, info, fh, ierror)
     TYPE(MPI_Comm), INTENT(IN) :: comm
     CHARACTER(LEN=*), INTENT(IN) :: filename
     INTEGER, INTENT(IN) :: amode
     TYPE(MPI_Info), INTENT(IN) :: info
     TYPE(MPI_File), INTENT(OUT) :: fh
     INTEGER, OPTIONAL, INTENT(OUT) :: ierror

Paramètres d'entrée

  • comm: Communicateur (handle).
  • filename: Nom du fichier à ouvrir (chaîne).
  • amode: Mode d'accès au fichier (entier).
  • info: Objet d'information (handle).

Paramètres de sortie

  • fh: Nouveau handle de fichier (handle).
  • ierror: Seulement en Fortran : État d'erreur (entier).

Description

MPI_File_open ouvre le fichier identifié par le nom de fichier filename sur tous les processus du groupe de communicateur comm. MPI_File_open est une routine collaborative; tous les processus doivent fournir la même valeur pour amode, et tous les processus doivent fournir des noms de fichiers qui réfèrent au même fichier, qui sont identiques textuellement (note: les plugins d'E/S d'Open MPI peuvent avoir des restrictions sur les caractères qui peuvent être utilisés dans les noms de fichiers. Par exemple, le plugin ROMIO peut interdire le caractère deux-points (":") dans un nom de fichier). Un processus peut ouvrir un fichier indépendamment des autres processus en utilisant le communicateur MPI_COMM_SELF. Le handle de fichier retourné, fh, peut être utilisé ultérieurement pour accéder au fichier jusqu'à ce qu'il soit fermé avec MPI_File_close. Avant d'appeler MPI_Finalize, l'utilisateur doit fermer (avec MPI_File_close) tous les fichiers qui ont été ouverts avec MPI_File_open. Note: le communicateur comm n'est pas affecté par MPI_File_open et reste utilisable dans toutes les routines MPI. De plus, l'utilisation de comm n'interfère pas avec le comportement des E/S.

Initialement, tous les processus voient le fichier comme un flux d'octets linéaire; c'est-à-dire que etype et filetype sont tous deux MPI_BYTE. Le mode de vue du fichier peut être changé par la routine MPI_File_set_view.

Les modes d'accès suivants sont supportés (spécifiés dans amode, en un vecteur de bits ou dans l'une des constantes entières suivantes):

  • MPI_MODE_APPEND
  • MPI_MODE_CREATE: Crée le fichier s'il n'existe pas.
  • MPI_MODE_DELETE_ON_CLOSE
  • MPI_MODE_EXCL: Erreur lors de la création d'un fichier qui existe déjà.
  • MPI_MODE_RDONLY: Lecture seule.
  • MPI_MODE_RDWR: Lecture et écriture.
  • MPI_MODE_SEQUENTIAL
  • MPI__MODE_WRONLY: Écriture seule.
  • MPI_MODE_UNIQUE_OPEN

Les modes MPI_MODE_RDONLY, MPI_MODE_RDWR, MPI_MODE_WRONLY et MPI_MODE_CREATE ont le même sens que leurs correspondants POSIX. Il n'est pas correct de spécifier MPI_MODE_CREATE conjointement avec MPI_MODE_RDONLY. Les erreurs liées au mode d'accès sont générées dans la classe MPI_ERR_AMODE.

Sur les clusters à nœud unique, les fichiers sont ouverts par défaut en utilisant des sémantiques de cohérence de fichiers non atomiques. Des sémantiques de cohérence atomique plus strictes, nécessaires pour l'atomicité des accès chevauchés, sont le défaut lorsque les processeurs d'un groupe de communicateur résident sur plus d'un nœud. Ce réglage peut être changé en utilisant MPI_File_set_atomicity.

L'interface de MPI_File_open permet à l'utilisateur de passer des informations via l'argument info. L'utilisateur peut définir cette valeur à MPI_INFO_NULL. Voir la section HINTS pour une liste d'indices qui peuvent être définis.

Indices

Les indices suivants peuvent être utilisés comme valeurs pour l'argument info.

INDICES CONFIGURABLES

  • MPI_INFO_NULL
  • shared_file_timeout: Temps (en secondes) à attendre avant de sortir avec MPI_ERR_TIMEDOUT pour accéder au pointeur de fichier partagé.
  • rwlock_timeout: Temps (en secondes) à attendre avant de sortir avec MPI_ERR_TIMEDOUT pour obtenir un verrou de lecture ou d'écriture sur un bloc de fichier UNIX continu.
  • noncoll_read_bufsize: Taille maximale du tampon utilisé par les E/S MPI pour satisfaire plusieurs requêtes de lecture non contiguës dans les routines d'accès aux données non collaboratives.

    NOTE:

Une taille de tampon inférieure à la distance (en octets) entre le premier octet et le dernier octet de la requête d'accès à un fichier UNIX entraîne les E/S MPI à itérer et à effectuer plusieurs appels read() ou write() sur UNIX. Si la requête inclut plusieurs fragments non contigus de données et que la taille du tampon est supérieure à la taille de ces fragments, alors l'appel read() ou write() (effectué au niveau des E/S MPI) accèdera à des données non demandées par ce processus afin de réduire le nombre total d'appels write() effectués. Si ce comportement n'est pas souhaitable, vous devez réduire cette taille de tampon pour qu'elle soit égale à la taille des fragments contigus au sein de la requête agrégée.
  • noncoll_write_bufsize: Taille maximale du tampon utilisé par les E/S MPI pour satisfaire plusieurs requêtes d'écriture non contiguës dans les routines d'accès aux données non collaboratives.

    Voir la note sur noncoll_read_bufsize.

  • coll_read_bufsize: Taille maximale du tampon utilisé par les E/S MPI pour satisfaire plusieurs requêtes de lecture non contiguës dans les routines d'accès aux données collaboratives.

    Voir la note sur noncoll_read_bufsize.

  • coll_write_bufsize: Taille maximale du tampon utilisé par les E/S MPI pour satisfaire plusieurs requêtes d'écriture non contiguës dans les routines d'accès aux données collaboratives.

    Voir la note sur noncoll_read_bufsize.

  • mpiio_concurrency: (booléen) contrôle si les routines d'E/S non bloquantes peuvent lier un thread supplémentaire à un LWP. .sp
  • mpiio_coll_contiguous: (booléen) contrôle si les prochains accès collaboratifs à un fichier demanderont des régions contiguës du fichier.

INDICES NON CONFIGURABLES

•
filename: Accède à cet indice pour obtenir le nom du fichier.

ERREURS

Plusieurs routines MPI retournent une valeur d'erreur ; dans les routines C, la valeur d'erreur est le résultat de la fonction, et dans les routines Fortran, le dernier argument est la valeur d'erreur.

Avant que la valeur d'erreur ne soit retournée, le gestionnaire d'erreurs associé à l'objet de communication (par exemple, communicateur, fenêtre, fichier) actuel est appelé. S'il n'y a pas d'objet de communication associé à l'appel MPI, l'appel est considéré comme étant associé à MPI_COMM_SELF et le gestionnaire d'erreurs associé à MPI_COMM_SELF est appelé. Lorsque MPI_COMM_SELF n'est pas initialisé (c'est-à-dire avant MPI_Init/MPI_Init_thread, après MPI_Finalize ou lorsque le modèle de Sessions est utilisé exclusivement), le gestionnaire d'erreurs initial est déclenché. Le gestionnaire d'erreurs initial peut être changé en appelant MPI_Comm_set_errhandler sur MPI_COMM_SELF lorsque le modèle Monde est utilisé, ou à l'argument mpi_initial_errhandler de mpiexec ou à la clé d'information de MPI_Comm_spawn/MPI_Comm_spawn_multiple. Si aucun autre gestionnaire d'erreurs approprié n'est trouvé, le gestionnaire d'erreurs MPI_ERRORS_RETURN est appelé pour les fonctions d'E/S et le gestionnaire d'erreurs MPI_ERRORS_ABORT pour toutes les autres fonctions MPI.

Open MPI comprend trois gestionnaires d'erreurs par défaut qui peuvent être utilisés :

  • MPI_ERRORS_ARE_FATAL Provoque l'arrêt du programme de tous les MP connectés

Ce site n'est en aucun cas associé à Arch Linux ni affilié à ce projet. Le contenu est uniquement une traduction des pages de manuel d'Arch publiées sur man.archlinux.org.

  • MPI_ERRORS_ABORT Un gestionnaire d'erreurs qui peut être invoqué sur un communicateur, une fenêtre, un fichier ou une session. Lorsqu'il est appelé sur un communicateur, il agit comme si MPI_Abort avait été appelé sur ce communicateur. S'il est appelé sur une fenêtre ou un fichier, il agit comme si MPI_Abort avait été appelé sur un communicateur contenant le groupe de processus dans la fenêtre ou le fichier correspondant. S'il est appelé sur une session, il n'interrompt que le processus local.
  • MPI_ERRORS_RETURN Renvoie un code d'erreur à l'application.

Les applications MPI peuvent également implémenter leurs propres gestionnaires d'erreurs en appelant :

  • MPI_Comm_create_errhandler puis MPI_Comm_set_errhandler
  • MPI_File_create_errhandler puis MPI_File_set_errhandler
  • MPI_Session_create_errhandler puis MPI_Session_set_errhandler ou à MPI_Session_init
  • MPI_Win_create_errhandler puis MPI_Win_set_errhandler

Notez que MPI ne garantit pas qu'un programme MPI puisse continuer après une erreur.

Voir la page de manuel MPI pour une liste complète des codes d'erreur MPI.

Voir la section Gestion des erreurs de la norme MPI-3.1 pour plus d'informations.
