MPI_Neighbor_alltoall, MPI_Ineighbor_alltoall, MPI_Neighbor_alltoall - Tous les processus envoient des données aux processus voisins dans un communicateur de topologie virtuelle

PARAMÈTRES D'ENTRÉE

  • sendbuf: Adresse de départ du tampon d'envoi (choix).
  • sendcount: Nombre d'éléments à envoyer à chaque processus (entier).
  • sendtype: Type de données des éléments du tampon d'envoi (handle).
  • recvcount: Nombre d'éléments à recevoir de chaque processus (entier).
  • recvtype: Type de données des éléments du tampon de réception (handle).
  • comm: Communicateur sur lequel les données doivent être échangées (handle).
  • info: Informations (handle, persistant seulement).

PARAMÈTRES DE SORTIE

  • recvbuf: Adresse de départ du tampon de réception (choix).
  • request: Requête (handle, non bloquant seulement).
  • ierror: Fortran seulement : Statut d'erreur (entier).

DESCRIPTION

MPI_Neighbor_alltoall est une opération collective dans laquelle tous les processus envoient et reçoivent la même quantité de données à chaque voisin. Le fonctionnement de cette routine peut être représenté comme suit, où chaque processus effectue 2n (n étant le nombre de voisins dans le communicateur comm) communications point à point indépendantes. Les voisins et la disposition des tampons sont déterminés par la topologie de comm.

Exemple de sémantique de MPI_Neighbor_alltoall pour les topologies cartésiennes :

MPI_Cart_get(comm, maxdims, dims, periods, coords);
for (dim = 0, i = 0 ; dim < dims ; ++dim) {
    MPI_Cart_shift(comm, dim, 1, &r0, &r1);
    MPI_Isend(sendbuf + i * sendcount * extent(sendtype),
              sendcount, sendtype, r0, ..., comm, ...);
    MPI_Irecv(recvbuf + i * recvcount * extent(recvtype),
              recvcount, recvtype, r0, ..., comm, ...);
    ++i;
    MPI_Isend(sendbuf + i * sendcount * extent(sendtype),
              sendcount, sendtype, r1, ..., comm, &req[i]);
    MPI_Irecv(recvbuf + i * recvcount * extent(recvtype),
              recvcount, recvtype, r1, ..., comm, ...);
    ++i;
}
MPI_Waitall (...);

Chaque processus découpe son sendbuf local en n blocs - chacun contenant sendcount éléments de type sendtype - et divise son recvbuf de manière similaire selon recvcount et recvtype. Le processus j envoie le k-ème bloc de son sendbuf local au voisin k, qui place les données dans le j-ème bloc de son recvbuf local. La quantité de données envoyées doit être égale à la quantité de données reçues, par paires, entre chaque paire de processus.

ORDRE DES VOISINS

Pour une topologie de graphe distribué, créée avec MPI_Dist_graph_create, la séquence des voisins dans les tampons d'envoi et de réception à chaque processus est définie comme la séquence retournée par MPI_Dist_graph_neighbors pour les destinations et les sources, respectivement. Pour une topologie de graphe générale, créée avec MPI_Graph_create, l'ordre des voisins dans les tampons d'envoi et de réception est défini comme la séquence des voisins telle que retournée par MPI_Graph_neighbors. Notez que les topologies de graphe générales devraient généralement être remplacées par les topologies de graphes distribués.

Pour une topologie cartésienne, créée avec MPI_Cart_create, la séquence des voisins dans les tampons d'envoi et de réception à chaque processus est définie par l'ordre des dimensions, d'abord le voisin dans la direction négative puis dans la direction positive avec un déplacement de 1. Le nombre de sources et de destinations dans les routines de communication est 2*ndims avec ndims défini dans MPI_Cart_create. Si un voisin n'existe pas, c'est-à-dire au bord d'une topologie cartésienne dans le cas d'une dimension de grille virtuelle non périodique (c'est-à-dire, periods[…]==false), alors ce voisin est défini comme étant MPI_PROC_NULL.

Si un voisin dans l'une des fonctions est MPI_PROC_NULL, alors la communication collective de voisinage se comporte comme une communication point à point avec MPI_PROC_NULL dans cette direction. C'est-à-dire, le tampon fait toujours partie de la séquence de voisins mais il n'est ni communiqué ni mis à jour.

NOTES

L'option MPI_IN_PLACE pour sendbuf n'a pas de sens pour cette fonction.

Tous les arguments sur tous les processus sont significatifs. Le l'argument comm, en particulier, doit décrire le même communicateur sur tous les les processus. comm doit être soit un communicateur cartésien, de graphe, ou de graphe distribué.

Il existe deux fonctions de bibliothèque MPI qui sont plus générales que MPI_Neighbor_alltoall. MPI_Neighbor_alltoallv permet une communication tous-à-tous vers et depuis des tampons qui ne sont pas nécessairement contigus ; différents processus peuvent envoyer et recevoir différentes quantités de données. MPI_Neighbor_alltoallw étend la fonctionnalité de MPI_Neighbor_alltoallv pour permettre l'échange de données avec des types de données différents.
