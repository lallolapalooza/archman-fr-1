MPI_COMM_SET_NAME(3) Open MPI MPI_COMM_SET_NAME(3)

MPI_Comm_set_name — Associe un nom à un communicateur.

SYNTAXE

Syntaxe C

#include <mpi.h>
int MPI_Comm_set_name(MPI_Comm comm, const char *comm_name)

Syntaxe Fortran

USE MPI
! ou la forme plus ancienne : INCLUDE 'mpif.h'
MPI_COMM_SET_NAME(COMM, COMM_NAME, IERROR)
     INTEGER COMM, IERROR
     CHARACTER*(*) COMM_NAME

Syntaxe Fortran 2008

USE mpi_f08
MPI_Comm_set_name(comm, comm_name, ierror)
     TYPE(MPI_Comm), INTENT(IN) :: comm
     CHARACTER(LEN=*), INTENT(IN) :: comm_name
     INTEGER, OPTIONAL, INTENT(OUT) :: ierror

PARAMÈTRE ENTRÉE/SORTIE

•
comm : Communicateur dont l'identifiant doit être défini (descripteur).

PARAMÈTRE ENTRÉE

•
comm_name : Chaîne de caractères à utiliser comme identifiant pour le communicateur (chaîne).

PARAMÈTRE SORTIE

•
ierror : Uniquement Fortran : statut d'erreur (entier).

DESCRIPTION

MPI_Comm_set_name permet à un utilisateur d'associer une chaîne de nom à un communicateur. La chaîne de caractères passée à MPI_Comm_set_name est enregistrée à l'intérieur de la bibliothèque MPI (elle peut donc être libérée par l'appelant immédiatement après l'appel, ou allouée sur la pile). Les espaces en tête de name sont significatifs, mais ceux de fin ne le sont pas.

MPI_Comm_set_name est une opération locale (non collective), qui affecte uniquement le nom du communicateur tel qu'il est vu dans le processus qui a effectué l'appel MPI_Comm_set_name. Il n'est pas requis que le même nom (ou un nom quelconque) soit attribué à un communicateur dans chaque processus où il existe.

La longueur du nom qui peut être stocké est limitée à la valeur de MPI_MAX_OBJECT_NAME en Fortran et MPI_MAX_OBJECT_NAME-1 en C (pour tenir compte du terminateur nul). Les tentatives de définir des noms plus longs que cela entraîneront la troncature du nom. MPI_MAX_OBJECT_NAME doit avoir une valeur d'au moins 64.

NOTES

Étant donné que MPI_Comm_set_name est fourni pour aider au débogage du code, il est judicieux de donner le même nom à un communicateur dans tous les processus où il existe, afin d'éviter toute confusion.

Concernant la longueur du nom, dans des conditions d'épuisement du stockage, une tentative de définir un nom de n'importe quelle longueur pourrait échouer ; par conséquent, la valeur de MPI_MAX_OBJECT_NAME ne doit être considérée que comme une limite supérieure stricte de la longueur du nom, et non comme une garantie que la définition de noms de longueur inférieure réussira toujours.

ERREURS

Presque toutes les routines MPI renvoient une valeur d'erreur ; les routines C sous forme de résultat de retour de la fonction et les routines Fortran dans le dernier argument.

Avant que la valeur d'erreur ne soit retournée, le gestionnaire d'erreurs MPI actuel associé à l'objet de communication (par exemple, communicateur, fenêtre, fichier) est appelé. Si aucun objet de communication n'est associé à l'appel MPI, l'appel est considéré comme attaché à MPI_COMM_SELF et appellera le gestionnaire d'erreurs MPI associé. Lorsque MPI_COMM_SELF n'est pas initialisé (c'est-à-dire avant MPI_Init/MPI_Init_thread, après MPI_Finalize, ou lors de l'utilisation exclusive du modèle de sessions) l'erreur déclenche le gestionnaire d'erreurs initial. Le gestionnaire d'erreurs initial peut être modifié en appelant MPI_Comm_set_errhandler sur MPI_COMM_SELF lors de l'utilisation du modèle du monde, ou par l'argument de ligne de commande mpi_initial_errhandler de mpiexec ou la clé d'information de MPI_Comm_spawn/MPI_Comm_spawn_multiple. Si aucun autre gestionnaire d'erreurs approprié n'a été défini, alors le gestionnaire d'erreurs MPI_ERRORS_RETURN est appelé pour les fonctions d'E/S MPI et le gestionnaire d'erreurs MPI_ERRORS_ABORT est appelé pour toutes les autres fonctions MPI.

Open MPI inclut trois gestionnaires d'erreurs prédéfinis qui peuvent être utilisés :

  • MPI_ERRORS_ARE_FATAL Provoque l'abandon du programme par tous les processus MPI connectés.
  • MPI_ERRORS_ABORT Un gestionnaire d'erreurs qui peut être invoqué sur un communicateur, une fenêtre, un fichier ou une session. Lorsqu'il est appelé sur un communicateur, il agit comme si MPI_Abort était appelé sur ce communicateur. S'il est appelé sur une fenêtre ou un fichier, il agit comme si MPI_Abort était appelé sur un communicateur contenant le groupe de processus dans la fenêtre ou le fichier correspondant. S'il est appelé sur une session, il n'interrompt que le processus local.
  • MPI_ERRORS_RETURN Retourne un code d'erreur à l'application.

Les applications MPI peuvent également implémenter leurs propres gestionnaires d'erreurs en appelant :

  • MPI_Comm_create_errhandler puis MPI_Comm_set_errhandler
  • MPI_File_create_errhandler puis MPI_File_set_errhandler
  • MPI_Session_create_errhandler puis MPI_Session_set_errhandler ou lors de MPI_Session_init
  • MPI_Win_create_errhandler puis MPI_Win_set_errhandler

Notez que MPI ne garantit pas qu'un programme MPI puisse continuer après une erreur.

Voir la page man MPI pour une liste complète des codes d'erreur MPI.

Voir la section Gestion des erreurs de la norme MPI-3.1 pour plus d'informations.
