PARAMÈTRES ENTRÉE

  • sendbuf: Adresse du tampon d'envoi (choix).
  • sendcount: Nombre d'éléments dans le tampon d'envoi (entier).
  • sendtype: Type de données des éléments du tampon d'envoi (handle).
  • recvcount: Tableau d'entiers (de longueur égale à la taille du groupe) contenant le nombre d'éléments reçus de chaque voisin.
  • displs: Tableau d'entiers (de longueur égale à la taille du groupe). L'entrée i spécifie le déplacement (par rapport à recvbuf) où placer les données entrantes du voisin i.
  • recvtype: Type de données des éléments du tampon de réception (handle).
  • comm: Communicateur (handle).
  • info Info (handle, persistant uniquement).:

PARAMÈTRES SORTIE

  • recvbuf: Adresse du tampon de réception (choix).
  • request: Requête (handle, non-bloquant uniquement).
  • ierror: Fortran uniquement : Statut d'erreur (entier).

DESCRIPTION

MPI_Neighbor_allgatherv est similaire à MPI_Neighbor_allgather en ce sens que tous les processus collectent des données de tous les voisins, sauf que chaque processus peut envoyer une quantité de données différente. Le bloc de données envoyé par le j-ème voisin est reçu par tous les voisins et placé dans le j-ème bloc du tampon. Les voisins et la disposition du tampon sont déterminés par la topologie de comm. recvbuf.

La signature de type associée à sendcount, sendtype, au processus j doit être égale à la signature de type associée à l'entrée correspondante dans recvcounts sur les processus voisins.

ORDRE DES VOISINS

Pour une topologie de graphe distribué, créée avec MPI_Dist_graph_create, la séquence de voisins dans les tampons d'envoi et de réception à chaque processus est définie comme la séquence renvoyée par MPI_Dist_graph_neighbors pour les destinations et les sources, respectivement. Pour une topologie de graphe général, créée avec MPI_Graph_create, l'ordre des voisins dans les tampons d'envoi et de réception est défini comme la séquence de voisins telle que renvoyée par MPI_Graph_neighbors. Notez que les topologies de graphes générales devraient généralement être remplacées par les topologies de graphes distribués.

Pour une topologie Cartésienne, créée avec MPI_Cart_create, la séquence de voisins dans les tampons d'envoi et de réception à chaque processus est définie par l'ordre des dimensions, d'abord le voisin dans la direction négative puis dans la direction positive avec un déplacement de 1. Le nombre de sources et de destinations dans les routines de communication est de 2*ndims, où ndims est défini dans MPI_Cart_create. Si un voisin n'existe pas, c'est-à-dire à la frontière d'une topologie Cartésienne dans le cas d'une dimension de grille virtuelle non périodique (c'est-à-dire periods[…]==false), alors ce voisin est défini comme étant MPI_PROC_NULL.

Si un voisin dans l'une des fonctions est MPI_PROC_NULL, alors la communication collective de voisinage se comporte comme une communication point à point avec MPI_PROC_NULL dans cette direction. C'est-à-dire que le tampon fait toujours partie de la séquence de voisins mais il n'est ni communiqué ni mis à jour.

NOTES

L'option MPI_IN_PLACE pour sendbuf n'est pas significative pour cette opération.

ERREURS

Presque toutes les routines MPI retournent une valeur d'erreur ; les routines C comme résultat de retour de la fonction et les routines Fortran dans le dernier argument.

Avant que la valeur d'erreur ne soit retournée, le gestionnaire d'erreurs MPI actuel associé à l'objet de communication (par exemple, communicateur, fenêtre, fichier) est appelé. Si aucun objet de communication n'est associé à l'appel MPI, alors l'appel est considéré comme attaché à MPI_COMM_SELF et appellera le gestionnaire d'erreurs MPI associé. Lorsque MPI_COMM_SELF n'est pas initialisé (c'est-à-dire avant MPI_Init/MPI_Init_thread, après MPI_Finalize, ou lorsque vous utilisez exclusivement le modèle Sessions) l'erreur déclenche le gestionnaire d'erreurs initial. Le gestionnaire d'erreurs initial peut être modifié en appelant MPI_Comm_set_errhandler sur MPI_COMM_SELF lors de l'utilisation du modèle World, ou l'argument CLI mpi_initial_errhandler de mpiexec ou la clé d'information de MPI_Comm_spawn/MPI_Comm_spawn_multiple. Si aucun autre gestionnaire d'erreurs approprié n'a été défini, alors le gestionnaire d'erreurs MPI_ERRORS_RETURN est appelé pour les fonctions d'E/S MPI et le gestionnaire d'erreurs MPI_ERRORS_ABORT est appelé pour toutes les autres fonctions MPI.

Open MPI inclut trois gestionnaires d'erreurs prédéfinis qui peuvent être utilisés :

  • MPI_ERRORS_ARE_FATAL Provoque l'arrêt du programme sur tous les processus MPI connectés.

MPI error handlers can be set on communicators, windows, files, or sessions. The default error handler is MPI_ERRORS_ARE_FATAL. This handler prints an error message and aborts the MPI job.

The following error handlers can be used:

  • MPI_ERRORS_ARE_FATAL Aborts the MPI job when an error occurs. This is the default.
  • MPI_ERRORS_IGNORE Ignores errors. The application is responsible for detecting and handling errors.
  • MPI_ERRORS_RETURN Returns an error code to the application. The application can then check the return code and take appropriate action.

When an error occurs, the error handler is invoked on the object (communicator, window, file, or session) where the error occurred. If MPI_ERRORS_RETURN is used, the function will return the corresponding MPI error code. If MPI_ERRORS_ARE_FATAL is used, the MPI job will terminate. If MPI_ERRORS_IGNORE is used, the application must manually check for errors.

The behavior of error handlers when called on different objects is as follows:

  • When called on a communicator, it acts as if MPI_Abort was called on that communicator.
  • When called on a window or file, it acts as if MPI_Abort was called on a communicator containing the group of processes in the corresponding window or file.
  • When called on a session, it aborts only the local process.

MPI applications can also implement their own error handlers by calling:

  • MPI_Comm_create_errhandler then MPI_Comm_set_errhandler
  • MPI_File_create_errhandler then MPI_File_set_errhandler
  • MPI_Session_create_errhandler then MPI_Session_set_errhandler or at MPI_Session_init
  • MPI_Win_create_errhandler then MPI_Win_set_errhandler

Note that MPI does not guarantee that an MPI program can continue past an error.

See the MPI man page for a full list of MPI error codes.

See the Error Handling section of the MPI-3.1 standard for more information.
