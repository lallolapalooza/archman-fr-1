MPI_Neighbor_alltoallv, MPI_Ineighbor_alltoallv, MPI_Neighbor_alltoallv_init — Tous les processus envoient des montants de données différents à, et reçoivent des montants de données différents de, tous les voisins

PARAMÈTRES ENTRANTS

  • sendbuf : Adresse de départ du tampon d'envoi.
  • sendcounts : Tableau d'entiers, où l'entrée i spécifie le nombre d'éléments à envoyer au voisin i.
  • sdispls : Tableau d'entiers, où l'entrée i spécifie le déplacement (offset par rapport à sendbuf, en unités de sendtype) à partir duquel envoyer les données au voisin i.
  • sendtype : Type de données des éléments du tampon d'envoi.
  • recvcounts : Tableau d'entiers, où l'entrée j spécifie le nombre d'éléments à recevoir du voisin j.
  • rdispls : Tableau d'entiers, où l'entrée j spécifie le déplacement (offset par rapport à recvbuf, en unités de recvtype) auquel les données du voisin j doivent être écrites.
  • recvtype : Type de données des éléments du tampon de réception.
  • comm : Communicateur sur lequel les données doivent être échangées.
  • info : Informations (descripteur, persistant uniquement).

PARAMÈTRES SORTANTS

  • recvbuf : Adresse du tampon de réception.
  • request : Requête (descripteur, non-bloquant uniquement).
  • ierror : Fortran uniquement : Statut d'erreur.

DESCRIPTION

MPI_Neighbor_alltoallv est une opération collective généralisée dans laquelle tous les processus envoient des données à et reçoivent des données de tous les voisins. Elle ajoute de la flexibilité à MPI_Neighbor_alltoall en permettant à l'utilisateur de spécifier les données à envoyer et recevoir de manière vectorielle (via un déplacement et un compte d'éléments). Le fonctionnement de cette routine peut être pensé comme suit, où chaque processus effectue 2n (n étant le nombre de voisins dans la topologie du communicateur comm) communications point à point indépendantes. Les voisins et la disposition des tampons sont déterminés par la topologie de comm.

MPI_Cart_get(comm, maxdims, dims, periods, coords);
for (dim = 0, i = 0 ; dim < dims ; ++dim) {
    MPI_Cart_shift(comm, dim, 1, &r0, &r1);
    MPI_Isend(sendbuf + sdispls[i]  * extent(sendtype),
              sendcount, sendtype, r0, ..., comm, ...);
    MPI_Irecv(recvbuf + rdispls[i] * extent(recvtype),
              recvcount, recvtype, r0, ..., comm, ...);
    ++i;
    MPI_Isend(sendbuf + sdispls[i] * extent(sendtype),
              sendcount, sendtype, r1, ..., comm, &req[i]);
    MPI_Irecv(recvbuf + rdispls[i] * extent(recvtype),
              recvcount, recvtype, r1, ..., comm, ...);
    ++i;
}

Le processus j envoie le k-ième bloc de son sendbuf local au voisin k, qui place les données dans le j-ème bloc de son recvbuf local.

Lorsqu'une paire de processus échange des données, chacun peut passer des arguments de compte et de type différents tant que l'expéditeur spécifie la même quantité de données à envoyer (en octets) que celle que le récepteur s'attend à recevoir.

Notez qu'un processus i peut envoyer une quantité de données différente au processus j qu'il n'en reçoit du processus j. De plus, un processus peut envoyer des quantités de données entièrement différentes à des processus différents dans le communicateur.

ORDRE DES VOISINS

Pour une topologie de graphe distribué, créée avec MPI_Dist_graph_create, la séquence des voisins dans les tampons d'envoi et de réception à chaque processus est définie comme la séquence retournée par MPI_Dist_graph_neighbors pour les destinations et les sources, respectivement. Pour une topologie de graphe générale, créée avec MPI_Graph_create, l'ordre des voisins dans les tampons d'envoi et de réception est défini comme la séquence des voisins retournée par MPI_Graph_neighbors. Notez que les topologies de graphes générales devraient généralement être remplacées par les topologies de graphes distribués.

Pour une topologie cartésienne, créée avec MPI_Cart_create, la séquence des voisins dans les tampons d'envoi et de réception à chaque processus est définie par l'ordre des dimensions, d'abord le voisin dans la direction négative, puis dans la direction positive avec un déplacement de 1. Les nombres de sources et de destinations dans les routines de communication sont 2*ndims avec ndims défini dans MPI_Cart_create. Si un voisin n'existe pas, c'est-à-dire au bord d'une topologie cartésienne dans le cas d'une dimension de grille virtuelle non périodique (c'est-à-dire, periods[…]==false), alors ce voisin est défini comme étant MPI_PROC_NULL.

Si un voisin dans l'une des fonctions est MPI_PROC_NULL, alors la communication collective de voisinage se comporte comme une communication point à point avec MPI_PROC_NULL dans cette direction. C'est-à-dire, le tampon fait toujours partie de la séquence de voisins mais il n'est ni communiqué ni mis à jour.

NOTES

Les routines MPI_Neighbor_alltoallv et MPI_Ineighbor_alltoallv sont des fonctions efficaces dans les cas où les communications réseau peuvent être partiellement ou totalement redondantes, permettant à l'application d'être mieux adaptée à l'architecture de communication sous-jacente. La routine MPI_Neighbor_alltoallv_init prépare une opération de communication de voisinage collective, qui peut ensuite être exécutée de manière répétée.

La routine MPI_Neighbor_alltoallv est identique à MPI_Neighbor_alltoallv, sauf qu'elle ne bloque pas et retourne une requête qui peut être utilisée pour vérifier la complétion. La routine MPI_Neighbor_alltoallv_init est identique à MPI_Neighbor_alltoallv, sauf qu'elle retourne une requête qui peut être utilisée pour exécuter l'opération de communication de voisinage de manière répétée.

Manuel MPI

SYNTAX

La syntaxe de cette commande est :

MPI_Neighbor_alltoallv(sendbuf, sendcount, sendtype, rdispls, recvbuf, recvcount, recvtype, comm)

PARAMÈTRES D'ENTRÉE

Les paramètres d'entrée sont :

  • sendbuf (void*) : adresse mémoire pour envoyer des données.
  • sendcount (int) : nombre d'éléments à envoyer.
  • sendtype (MPI_Datatype) : type de données à envoyer.
  • rdispls (MPI_Datatype) : décalage de réception.
  • recvbuf (void*) : adresse mémoire pour recevoir des données.
  • recvcount (int) : nombre d'éléments à recevoir.
  • recvtype (MPI_Datatype) : type de données à recevoir.
  • comm (MPI_Comm) : communicateur pour le processus.

PARAMÈTRES DE SORTIE

Les paramètres de sortie sont :

  • sendbuf (void*) : adresse mémoire des données envoyées.
  • recvbuf (void*) : adresse mémoire des données reçues.
  • status (MPI_Status) : état de l'opération.

DESCRIPTION

Cette commande effectue une opération alltoallv dans l'environnement de voisinage. Le processus communique avec ses voisins en utilisant le protocole MPI. La commande est plus efficace que MPI_alltoallv, car elle permet une opération de type de données spécifique, tandis que MPI_alltoallv peut être utilisée avec des types de données génériques. Cette commande est utilisée dans les systèmes de communication de voisinage où chaque processus peut avoir un nombre différent de voisins.

ORDRE DES VOISINS

L'ordre des voisins est défini par le communicateur. Le processus communique avec les voisins en fonction de leur ordre dans le communicateur.

NOTES

Le paramètre MPI_IN_PLACE pour sendbuf n'est pas significatif pour cette opération.

La spécification des compteurs et des décalages ne doit pas entraîner l'écriture d'un emplacement plus d'une fois.

Tous les arguments sur tous les processus sont significatifs. L'argument comm, en particulier, doit décrire le même communicateur sur tous les processus.

Les décalages sdispls et rdispls sont mesurés en unités de sendtype et recvtype, respectivement. Comparez cela avec MPI_Neighbor_alltoallw, où ces décalages sont mesurés en octets.

ERREURS

La plupart des routines MPI renvoient une valeur d'erreur ; les routines C renvoient le résultat de la fonction et les routines Fortran sont spécifiées comme dernier argument.

Avant de renvoyer la valeur d'erreur, le gestionnaire d'erreurs actuel associé à l'objet de communication (par exemple, communicateur, fenêtre, fichier) est appelé. S'il n'y a pas d'objet de communication associé à l'appel MPI, l'appel est considéré comme associé à MPI_COMM_SELF et le gestionnaire correspondant est appelé. Lorsque MPI_COMM_SELF n'est pas initialisé (c'est-à-dire avant MPI_Init/MPI_Init_thread, après MPI_Finalize, ou lorsque le modèle de session est utilisé exclusivement), l'erreur élève le gestionnaire d'erreurs initial. Le gestionnaire d'erreurs initial peut être modifié en appelant MPI_Comm_set_errhandler sur MPI_COMM_SELF lors de l'utilisation du modèle du monde, ou via l'option mpi_initial_errhandler de mpiexec ou la clé info de MPI_Comm_spawn/MPI_Comm_spawn_multiple. S'il n'y a pas d'autre gestionnaire d'erreurs approprié défini, le gestionnaire MPI_ERRORS_RETURN est appelé pour les fonctions d'E/S MPI et MPI_ERRORS_ABORT pour les autres fonctions MPI.

Open MPI inclut trois gestionnaires d'erreurs par défaut qui peuvent être utilisés :

  • MPI_ERRORS_ARE_FATAL Provoque la fin du programme de tous les processus MPI connectés.
  • MPI_ERRORS_ABORT Un gestionnaire d'erreurs qui peut être appelé sur un communicateur, une fenêtre, un fichier ou une session. Lorsqu'il est appelé sur un communicateur, il agit comme si MPI_Abort avait été appelé sur ce communicateur. S'il est appelé sur une fenêtre ou un fichier, il agit comme si MPI_Abort avait été appelé sur un communicateur contenant le groupe de processus dans la fenêtre ou le fichier correspondant. S'il est appelé sur une session, il arrête uniquement le processus local.
  • MPI_ERRORS_RETURN Renvoie un code d'erreur à l'application.

Les applications MPI peuvent également implémenter leurs propres gestionnaires d'erreurs en appelant :

  • MPI_Comm_create_errhandler puis MPI_Comm_set_errhandler
  • MPI_File_create_errhandler puis MPI_File_set_errhandler
  • MPI_Session_create_errhandler puis MPI_Session_set_errhandler ou dans MPI_Session_init
  • MPI_Win_create_errhandler puis MPI_Win_set_errhandler

Remarque : MPI ne garantit pas qu'un programme MPI puisse continuer après une erreur.

Voir la page de manuel MPI pour une liste complète des codes d'erreur MPI.

Voir la section sur la gestion des erreurs de la norme MPI-3.1 pour plus d'informations.
