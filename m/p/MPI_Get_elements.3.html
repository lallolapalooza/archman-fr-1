MPI_Get_elements(3) Open MPI MPI_Get_elements(3)

MPI_Get_elements, MPI_Get_elements_x - Retourne le nombre d'éléments de base dans un type de données.

SYNTAXE

Syntaxe C

#include <mpi.h>
int MPI_Get_elements(const MPI_Status *status, MPI_Datatype datatype,
    int *count)
int MPI_Get_elements_x(const MPI_Status *status, MPI_Datatype datatype,
    MPI_Count *count)

Syntaxe Fortran

USE MPI
! ou l'ancien format: INCLUDE 'mpif.h'
MPI_GET_ELEMENTS(STATUS, DATATYPE, COUNT, IERROR)
    INTEGER STATUS(MPI_STATUS_SIZE), DATATYPE, COUNT, IERROR
MPI_GET_ELEMENTS_X(STATUS, DATATYPE, COUNT, IERROR)
    INTEGER STATUS(MPI_STATUS_SIZE), DATATYPE
        INTEGER(KIND=MPI_COUNT_KIND) COUNT
        INTEGER IERROR

Syntaxe Fortran 2008

USE mpi_f08
MPI_Get_elements(status, datatype, count, ierror)
    TYPE(MPI_Status), INTENT(IN) :: status
    TYPE(MPI_Datatype), INTENT(IN) :: datatype
    INTEGER, INTENT(OUT) :: count
    INTEGER, OPTIONAL, INTENT(OUT) :: ierror
MPI_Get_elements_x(status, datatype, count, ierror)
    TYPE(MPI_Status), INTENT(IN) :: status
    TYPE(MPI_Datatype), INTENT(IN) :: datatype
    INTEGER(KIND = MPI_COUNT_KIND), INTENT(OUT) :: count
    INTEGER, OPTIONAL, INTENT(OUT) :: ierror

Paramètres d'entrée

  • status : Le statut de l'opération de réception (status).
  • datatype : Le type de données utilisé dans l'opération de réception (handle).

Paramètres de sortie

•
ierror : Statut d'erreur (entier) en Fortran uniquement.

Description

MPI_Get_elements et MPI_Get_elements_x se comportent différemment de MPI_Get_count, qui retourne le nombre d'« entrées de haut niveau » reçues, c'est-à-dire le nombre de « copies » du datatype. MPI_Get_count peut retourner n'importe quel entier k, où 0 < k < count. Si MPI_Get_count retourne k, alors le nombre d'éléments de base reçus (et la valeur retournée par MPI_Get_elements et MPI_Get_elements_x) est n\*k, où n est le nombre d'éléments de base dans la carte de types du datatype. Si le nombre d'éléments de base reçus n'est pas un multiple de n, c'est-à-dire si l'opération de réception n'a pas reçu un nombre entier de copies du datatype, alors MPI_Get_count retourne la valeur MPI_UNDEFINED. Pour les deux fonctions, si le paramètre count ne peut pas exprimer la valeur à retourner (par exemple, si le paramètre est trop petit pour contenir la valeur de sortie), il est défini à MPI_UNDEFINED.

Exemple : Utilisation de MPI_Get_count et MPI_Get_elements :

call MPI_TYPE_CONTIGUOUS(2, MPI_REAL, Type2, ierr)
call MPI_TYPE_COMMIT(Type2, ierr)
call MPI_COMM_RANK(comm, rank, ierr)
IF ( rank == 0 ) THEN
   CALL MPI_SEND(a, 2, MPI_REAL, 1, 0, comm, ierr)
   CALL MPI_SEND(a, 3, MPI_REAL, 1, 0, comm, ierr)
ELSE
   CALL MPI_RECV(a, 2, Type2, 0, 0, comm, stat, ierr)
   CALL MPI_GET_COUNT(stat, Type2, i, ierr) ! retourne i=1
   CALL MPI_GET_ELEMENTS(stat, Type2, i, ierr) ! retourne i=2
   CALL MPI_RECV(a, 2, Type2, 0, 0, comm, stat, ierr)
   CALL MPI_GET_COUNT(stat, Type2, i, ierr) ! retourne i=MPI_UNDEFINED
   CALL MPI_GET_ELEMENTS(stat, Type2, i, ierr)  ! retourne i=3
END IF

La fonction MPI_Get_elements peut également être utilisée après une inspection pour trouver le nombre d'éléments dans le message inspecté. Notez que les deux fonctions MPI_Get_count et MPI_Get_elements retournent les mêmes valeurs lorsqu'elles sont utilisées avec des types de données primitifs.

Erreurs

La plupart des routines MPI retournent une valeur d'erreur ; les routines C retournent cette valeur comme résultat de la fonction, et les routines Fortran dans le dernier argument.

Avant de retourner la valeur d'erreur, le gestionnaire d'erreurs associé à l'objet de communication actuel (par exemple, communicateur, fenêtre, fichier) est appelé. S'il n'y a pas d'objet de communication associé à l'appel MPI, l'appel est considéré comme associé à MPI_COMM_SELF et le gestionnaire d'erreurs correspondant est appelé. Lorsque MPI_COMM_SELF n'est pas initialisé (c'est-à-dire avant MPI_Init/MPI_Init_thread, après MPI_Finalize, ou lorsqu'on utilise exclusivement le Modèle de Session), l'erreur élève le gestionnaire d'erreurs initial. Le gestionnaire d'erreurs initial peut être modifié en appelant MPI_Comm_set_errhandler sur MPI_COMM_SELF lors de l'utilisation du Modèle du Monde, ou l'argument mpi_initial_errhandler de mpiexec ou la clé d'information de MPI_Comm_spawn/MPI_Comm_spawn_multiple. S'il n'y a pas d'autre gestionnaire d'erreur approprié, le gestionnaire MPI_ERRORS_RETURN est appelé pour les fonctions d'E/S MPI et MPI_ERRORS_ABORT pour toutes les autres fonctions MPI.

Open MPI inclut trois gestionnaires d'erreurs prédéfinis qui peuvent être utilisés :

  • MPI_ERRORS_ARE_FATAL Arrête l'exécution de tous les processus MPI connectés.
  • MPI_ERRORS_ABORT Un gestionnaire d'erreurs qui peut être invoqué sur un communicateur, une fenêtre, un fichier ou une session. Lorsqu'il est invoqué sur un communicateur, il agit comme si MPI_Abort avait été appelé sur ce communicateur. S'il est invoqué sur une fenêtre ou un fichier, il agit comme si MPI_Abort avait été appelé sur un communicateur qui contient l'ensemble des processus dans la fenêtre ou le fichier correspondant. S'il est invoqué sur une session, il arrête uniquement le processus local.
  • MPI_ERRORS_RETURN Retourne un code d'erreur à l'application.

Les applications MPI peuvent également implémenter leurs propres gestionnaires d'erreurs en appelant :

  • MPI_Comm_create_errhandler puis MPI_Comm_set_errhandler
  • MPI_File_create_errhandler puis MPI_File_set_errhandler
  • MPI_Session_create_errhandler puis MPI_Session_set_errhandler ou dans MPI_Session_init
  • MPI_Win_create_errhandler puis MPI_Win_set_errhandler

Remarque : Les applications MPI ne sont pas garanties de pouvoir continuer après une erreur.

Voir la page de manuel MPI pour une liste complète des codes d'erreur MPI.

Voir la section Gestion des erreurs de la norme MPI-3.1 pour plus d'informations.
