MPI_TYPE_CREATE_STRUCT(3) Open MPI MPI_TYPE_CREATE_STRUCT(3)

MPI_Type_create_struct — Crée un type de données structuré.

SYNTAXE

Syntaxe C

#include <mpi.h>
int MPI_Type_create_struct(int count, int array_of_blocklengths[],
     const MPI_Aint array_of_displacements[], const MPI_Datatype array_of_types[],
     MPI_Datatype *newtype)

Syntaxe Fortran

USE MPI
! ou l'ancienne forme: INCLUDE 'mpif.h'
MPI_TYPE_CREATE_STRUCT(COUNT, ARRAY_OF_BLOCKLENGTHS,
             ARRAY_OF_DISPLACEMENTS, ARRAY_OF_TYPES, NEWTYPE, IERROR)
     INTEGER COUNT, ARRAY_OF_BLOCKLENGTHS(*), ARRAY_OF_TYPES(*),
     INTEGER NEWTYPE, IERROR
     INTEGER(KIND=MPI_ADDRESS_KIND) ARRAY_OF_DISPLACEMENTS(*)

Syntaxe Fortran 2008

USE mpi_f08
MPI_Type_create_struct(count, array_of_blocklengths,
             array_of_displacements, array_of_types, newtype, ierror)
     INTEGER, INTENT(IN) :: count, array_of_blocklengths(count)
     INTEGER(KIND=MPI_ADDRESS_KIND), INTENT(IN) ::
     array_of_displacements(count)
     TYPE(MPI_Datatype), INTENT(IN) :: array_of_types(count)
     TYPE(MPI_Datatype), INTENT(OUT) :: newtype
     INTEGER, OPTIONAL, INTENT(OUT) :: ierror

PARAMÈTRES D'ENTRÉE

  • count: Nombre de blocs (entier) — également le nombre d'entrées dans les tableaux array_of_types, array_of_displacements et array_of_blocklengths.
  • array_of_blocklengths: Nombre d'éléments dans chaque bloc (tableau d'entiers).
  • array_of_displacements: Déplacement en octets de chaque bloc (tableau d'entiers).
  • array_of_types: Type d'éléments dans chaque bloc (tableau de descripteurs d'objets de type de données).

PARAMÈTRES DE SORTIE

  • newtype: Nouveau type de données (descripteur).
  • ierror: Fortran uniquement : statut d'erreur (entier).

DESCRIPTION

MPI_Type_create_struct crée un type de données structuré. Cette routine remplace MPI_Type_struct, qui est maintenant obsolète.

MPI_Type_create_struct est le constructeur de type le plus général. Il généralise encore MPI_Type_create_hindexed en ce sens qu'il permet à chaque bloc de contenir des réplications de différents types de données.

Exemple 1 : Soit type1 une carte de type

{(double, 0), (char, 8)}

avec une étendue de 16. Soit B = (2, 1, 3), D = (0, 16, 26), et T = (MPI_FLOAT, type1, MPI_CHAR). Alors un appel à MPI_Type_create_struct(3, B, D, T, newtype) renvoie un type de données avec la carte de type

{
 (float, 0), (float,4),             // 2 float
 (double, 16), (char, 24),          // 1 type1
 (char, 26), (char, 27), (char, 28) // 3 char
}

C'est-à-dire deux copies de MPI_FLOAT commençant à 0, suivies d'une copie de type1 commençant à 16, suivies de trois copies de MPI_CHAR, commençant à 26.

Exemple 2 :

Un exemple de struct avec seulement certains composants faisant partie du type

struct MyStruct {
    double x[2], y;
    char a;
    int n;
};
// créer un nouveau type où nous envoyons seulement x, y et n
int B[] = {
    2, // 2 double
    1, // 1 double
    1, // 1 int
    1  // espace réservé pour l'alignement
};
MPI_Aint D[] = {
    offsetof(struct MyStruct, x),
    offsetof(struct MyStruct, y),
    offsetof(struct MyStruct, n),
    sizeof(struct MyStruct)
};
MPI_Datatype T[] = {
    MPI_DOUBLE,
    MPI_DOUBLE,
    MPI_INT,
    MPI_UB
};
MPI_Datatype mpi_dt_mystruct;
MPI_Type_create_struct(4, B, D, T, &mpi_dt_mystruct);
MPI_Type_commit(&mpi_dt_mystruct);
// Nous pouvons maintenant envoyer une structure (en omettant a)
struct MyStruct values[3];
if ( rank == 0 ) {
    // ... initialiser values
    MPI_Send(values, 3, mpi_dt_mystruct, 1, 0, MPI_COMM_WORLD);
} else if ( rank == 1 ) {
    MPI_Recv(values, 3, mpi_dt_mystruct, 0, 0, MPI_COMM_WORLD, MPI_STATUS_IGNORE);
}

Pour plus d'informations, voir la section 5.1.2 de la norme MPI-4.0.

NOTES

Si une borne supérieure est définie explicitement en utilisant le type de données MPI MPI_UB, l'index correspondant doit être positif.

La norme MPI-1 faisait initialement des déclarations vagues sur le rembourrage et l'alignement ; cela visait à permettre la définition simple de structures qui pouvaient être envoyées avec un décompte supérieur à un. Par exemple,

struct {int a; char b;} foo;

peut avoir

sizeof(foo) = sizeof(int) + sizeof(char);

définissant l'étendue d'un type de données comme incluant un epsilon, ce qui aurait permis à une implémentation de rendre l'étendue d'un type de données MPI pour cette structure égale à 2*sizeof(int). Cependant, comme différents systèmes peuvent définir différents rembourrages, une clarification de la norme a rendu epsilon nul. Ainsi, si vous définissez un type de structure et souhaitez envoyer ou recevoir plusieurs éléments, vous devriez inclure explicitement une entrée MPI_UB comme dernier membre de la structure. Voir l'exemple ci-dessus.

ERREURS

Presque toutes les routines MPI retournent une valeur d'erreur ; les routines C comme résultat de retour de la fonction et les routines Fortran dans le dernier argument.

Avant que la valeur d'erreur ne soit retournée, le gestionnaire d'erreurs MPI actuellement associé à l'objet de communication (par exemple, communicateur, fenêtre, fichier) est appelé. Si aucun objet de communication n'est associé à l'appel MPI, l'appel est considéré comme attaché à MPI_COMM_SELF et appellera le gestionnaire d'erreurs MPI associé. Lorsque MPI_COMM_SELF n'est pas initialisé (c'est-à-dire avant MPI_Init/MPI_Init_thread, après MPI_Finalize, ou lors de l'utilisation exclusive du modèle de Sessions), l'erreur déclenche le gestionnaire d'erreurs initial. Le gestionnaire d'erreurs initial peut être modifié en appelant MPI_Comm_set_errhandler sur MPI_COMM_SELF lors de l'utilisation du modèle World, ou l'argument CLI mpi_initial_errhandler de mpiexec ou une clé d'info pour MPI_Comm_spawn/MPI_Comm_spawn_multiple. Si aucun autre gestionnaire d'erreurs approprié n'a été défini, alors le gestionnaire d'erreurs MPI_ERRORS_RETURN est appelé pour les fonctions d'E/S MPI et le gestionnaire d'erreurs MPI_ERRORS_ABORT est appelé pour toutes les autres fonctions MPI.

Open MPI inclut trois gestionnaires d'erreurs prédéfinis qui peuvent être utilisés :

  • MPI_ERRORS_ARE_FATAL Provoque l'arrêt du programme de tous les processus MPI connectés.
  • MPI_ERRORS_ABORT Un gestionnaire d'erreurs qui peut être invoqué sur un communicateur, une fenêtre, un fichier ou une session. Lorsqu'il est appelé sur un communicateur, il agit comme si MPI_Abort avait été appelé sur ce communicateur. S'il est appelé sur une fenêtre ou un fichier, il agit comme si MPI_Abort avait été appelé sur un communicateur contenant le groupe de processus de la fenêtre ou du fichier correspondant. S'il est appelé sur une session, il n'interrompt que le processus local.
  • MPI_ERRORS_RETURN Retourne un code d'erreur à l'application.

Les applications MPI peuvent également implémenter leurs propres gestionnaires d'erreurs en appelant :

  • MPI_Comm_create_errhandler puis MPI_Comm_set_errhandler
  • MPI_File_create_errhandler puis MPI_File_set_errhandler
  • MPI_Session_create_errhandler puis MPI_Session_set_errhandler ou lors de MPI_Session_init
  • MPI_Win_create_errhandler puis MPI_Win_set_errhandler

Notez que MPI ne garantit pas qu'un programme MPI puisse continuer après une erreur.

Voir la page de manuel MPI pour une liste complète des codes d'erreur MPI.

Voir la section Gestion des erreurs de la norme MPI-3.1 pour plus d'informations.
