MPI_Waitall(3) Open MPI MPI_Waitall(3)

MPI_Waitall — Attend que toutes les communications associées aux handles actifs dans la liste soient terminées.

SYNTAXE

Syntaxe C

#include <mpi.h>
int MPI_Waitall(int count, MPI_Request array_of_requests[],
     MPI_Status *array_of_statuses)

Syntaxe Fortran

USE MPI
! ou l'ancienne forme: INCLUDE 'mpif.h'
MPI_WAITALL(COUNT, ARRAY_OF_REQUESTS, ARRAY_OF_STATUSES, IERROR)
     INTEGER COUNT, ARRAY_OF_REQUESTS(*)
     INTEGER ARRAY_OF_STATUSES(MPI_STATUS_SIZE,*), IERROR

Syntaxe Fortran 2008

USE mpi_f08
MPI_Waitall(count, array_of_requests, array_of_statuses, ierror)
     INTEGER, INTENT(IN) :: count
     TYPE(MPI_Request), INTENT(INOUT) :: array_of_requests(count)
     TYPE(MPI_Status) :: array_of_statuses(*)
     INTEGER, OPTIONAL, INTENT(OUT) :: ierror

PARAMÈTRES D'ENTRÉE

  • count: Longueur de la liste (entier).
  • array_of_requests: Tableau des requêtes (tableau de handles).

PARAMÈTRES DE SORTIE

  • array_of_statuses: Tableau des objets d'état (tableau d'état).
  • ierror: En Fortran seulement : État de l'erreur (entier).

DESCRIPTION

Bloque jusqu'à ce que toutes les opérations de communication associées aux handles actifs dans la liste soient terminées, et retourne l'état de toutes ces opérations (y compris le cas où aucune des handles dans la liste n'est active). Les deux tableaux ont le même nombre d'entrées valides. L'entrée i-ème dans array_of_statuses est définie à l'état de retour de l'opération i-ème. Les requêtes qui ont été créées par des opérations de communication non bloquantes sont libérées, et les handles correspondants dans le tableau sont définis à MPI_REQUEST_NULL. La liste peut contenir des handles nulles ou inactives. L'appel met à vide l'état de chaque entrée correspondante.

L'exécution sans erreur de MPI_Waitall(count, array_of_requests, array_of_statuses) a le même effet que l'exécution de MPI_Wait(&array_of_request[i], &array_of_statuses[i]), pour i=0,..., count-1, dans un ordre quelconque. L'appel MPI_Waitall avec un tableau de longueur 1 est équivalent à MPI_Wait.

Si une ou plusieurs des opérations de communication complétées par un appel à MPI_Waitall échouent, il est souhaitable de retourner des informations spécifiques sur chaque opération de communication. La fonction MPI_Waitall retournera dans ce cas le code d'erreur MPI_ERR_IN_STATUS et définira le champ d'erreur de chaque état à un code spécifique. Ce code sera MPI_SUCCESS si l'opération spécifique s'est terminée ; il sera un autre code spécifique si elle a échoué ; ou il peut être MPI_ERR_PENDING si elle n'a ni échoué ni terminé. La fonction MPI_Waitall retournera MPI_SUCCESS si aucune requête n'a généré d'erreur, ou retournera un autre code d'erreur si elle échoue pour d'autres raisons (comme des arguments invalides). Dans ce cas, elle ne mettra pas à jour les champs d'erreur des états.

Si votre application n'a pas besoin d'examiner le champ array_of_statuses, vous pouvez économiser des ressources en utilisant la constante prédéfinie MPI_STATUSES_IGNORE comme valeur spéciale pour l'argument array_of_statuses.

ERREURS

La plupart des routines MPI retournent une valeur d'erreur ; les routines C retournent le résultat de la fonction et les routines Fortran dans le dernier argument.

Avant que la valeur d'erreur ne soit retournée, le gestionnaire d'erreurs associé à l'objet de communication (par exemple, le communicateur, la fenêtre, le fichier) actuel est appelé. S'il n'y a pas d'objet de communication associé à l'appel MPI, l'appel est considéré comme associé à MPI_COMM_SELF et le gestionnaire correspondant est appelé. Lorsque MPI_COMM_SELF n'est pas initialisé (c'est-à-dire avant MPI_Init/MPI_Init_thread, après MPI_Finalize, ou lorsque le modèle de Sessions est utilisé exclusivement), l'erreur initiale est déclenchée. Le gestionnaire initial peut être modifié en appelant MPI_Comm_set_errhandler sur MPI_COMM_SELF lorsque le modèle du Monde est utilisé, ou l'argument mpi_initial_errhandler de mpiexec ou la clé info de MPI_Comm_spawn/MPI_Comm_spawn_multiple. Si aucun autre gestionnaire d'erreur approprié n'existe, le gestionnaire MPI_ERRORS_RETURN est appelé pour les fonctions d'E/S MPI et le gestionnaire MPI_ERRORS_ABORT pour toutes les autres fonctions MPI.

Open MPI inclut trois gestionnaires d'erreurs par défaut qui peuvent être utilisés :

  • MPI_ERRORS_ARE_FATAL Provoque l'abandon de tous les processus MPI connectés par le programme.
  • MPI_ERRORS_ABORT Un gestionnaire d'erreurs qui peut être invoqué sur un communicateur, une fenêtre, un fichier ou une session. Lorsqu'il est invoqué sur un communicateur, il agit comme si MPI_Abort avait été appelé sur ce communicateur. S'il est invoqué sur une fenêtre ou un fichier, il agit comme si MPI_Abort avait été appelé sur un communicateur contenant le groupe de processus correspondant dans la fenêtre ou le fichier. S'il est invoqué sur une session, il abandonne uniquement le processus local.
  • MPI_ERRORS_RETURN Retourne un code d'erreur à l'application.

Les applications MPI peuvent également implémenter leurs propres gestionnaires d'erreurs en appelant :

  • MPI_Comm_create_errhandler puis MPI_Comm_set_errhandler
  • MPI_File_create_errhandler puis MPI_File_set_errhandler
  • MPI_Session_create_errhandler puis MPI_Session_set_errhandler ou dans MPI_Session_init
  • MPI_Win_create_errhandler puis MPI_Win_set_errhandler

Note : MPI ne garantit pas qu'un programme MPI puisse continuer après une erreur.

Voir la section sur la gestion des erreurs de la spécification MPI-3.1 pour plus d'informations.

Pour chaque invocation de MPI_Waitall, si une requête génère une erreur MPI, seule la première requête MPI ayant causé l'erreur est passée à son gestionnaire d'erreurs correspondant. Aucun autre gestionnaire d'erreurs n'est invoqué (même si plusieurs requêtes ont généré des erreurs). Cependant, toutes les requêtes qui génèrent une erreur auront un code d'erreur pertinent stocké dans le champ status.MPI_ERROR correspondant (sauf si MPI_STATUSES_IGNORE a été utilisé).

Si le gestionnaire d'erreurs invoqué permet à MPI_Waitall de retourner à l'appelant, la valeur MPI_ERR_IN_STATUS sera retournée dans les bindings C et Fortran.
