MPI_Scatterv, MPI_Iscatterv, MPI_Scatterv_init - Diffuse un tampon par morceaux à toutes les tâches d'un groupe.

PARAMETRES D'ENTRÉE

  • sendbuf: Adresse du tampon d'envoi (choix, significatif uniquement à la racine).
  • sendcounts: Tableau d'entiers (de taille égale à la taille du groupe) spécifiant le nombre d'éléments à envoyer à chaque processeur.
  • displs: Tableau d'entiers (de taille égale à la taille du groupe). L'entrée i spécifie le déplacement (par rapport à sendbuf) à partir duquel prendre les données sortantes vers le processeur i.
  • sendtype: Type des éléments du tampon d'envoi (handle).
  • recvcount: Nombre d'éléments dans le tampon de réception (entier).
  • recvtype: Type des éléments du tampon de réception (handle).
  • root: Rang du processus d'envoi (entier).
  • comm: Communicateur (handle).
  • info: Informations (handle, persistant uniquement).

PARAMETRES DE SORTIE

  • recvbuf: Adresse du tampon de réception (choix).
  • request: Requête (handle, non-bloquant uniquement).
  • ierror: Fortran uniquement : Statut d'erreur (entier).

DESCRIPTION

MPI_Scatterv est l'opération inverse de MPI_Gatherv.

MPI_Scatterv étend les fonctionnalités de MPI_Scatter en permettant un nombre variable de données à envoyer à chaque processus, puisque sendcounts est maintenant un tableau. Elle offre également plus de flexibilité quant à l'origine des données sur la racine, en fournissant le nouvel argument, displs.

Le résultat est comme si la racine exécutait n opérations d'envoi,

MPI_Send(sendbuf + displs[i] * extent(sendtype),
         sendcounts[i], sendtype, i, ...);
// et chaque processus exécutait une réception,
MPI_Recv(recvbuf, recvcount, recvtype, root, ...)

Le tampon d'envoi est ignoré pour tous les processus non racines.

La signature de type implicite par sendcount[i], sendtype à la racine doit être égale à la signature de type implicite par recvcount, recvtype au processus i (cependant, les correspondances de types peuvent être différentes). Cela implique que la quantité de données envoyées doit être égale à la quantité de données reçues, par paires entre chaque processus et la racine. Des correspondances de types distinctes entre l'expéditeur et le récepteur sont toujours autorisées.

Tous les arguments de la fonction sont significatifs sur le processus root, tandis que sur les autres processus, seuls les arguments recvbuf, recvcount, recvtype, root, comm sont significatifs. Les arguments root et comm doivent avoir des valeurs identiques sur tous les processus.

La spécification des comptes, types et déplacements ne doit pas entraîner la lecture de plus d'une fois d'un emplacement sur la racine.

Exemple 1 : L'inverse de l'Exemple 5 du manuel MPI_Gatherv. Nous avons un pas variable entre les blocs du côté envoi (racine), du côté réception nous recevons 100 - i éléments dans la ième colonne d'un tableau C 100 x 150 au processus i.

MPI_Comm comm;
int gsize,recvarray[100][150],*rptr;
int root, *sendbuf, myrank, bufsize, *stride;
MPI_Datatype rtype;
int i, *displs, *scounts, offset;
...
MPI_Comm_size( comm, &gsize);
MPI_Comm_rank( comm, &myrank );
stride = (int *)malloc(gsize*sizeof(int));
...
/* stride[i] pour i = 0 à gsize-1 est défini quelque part
 * sendbuf provient d'ailleurs
 */
...
displs = (int *)malloc(gsize*sizeof(int));
scounts = (int *)malloc(gsize*sizeof(int));
offset = 0;
for (i=0; i<gsize; ++i) {
    displs[i] = offset;
    offset += stride[i];
    scounts[i] = 100 - i;
}
/* Créer le type de données pour la colonne que nous recevons
 */
MPI_Type_vector( 100-myrank, 1, 150, MPI_INT, &rtype);
MPI_Type_commit( &rtype );
rptr = &recvarray[0][myrank];
MPI_Scatterv(sendbuf, scounts, displs, MPI_INT,
             rptr, 1, rtype, root, comm);

Exemple 2 : L'inverse de l'Exemple 1 du manuel MPI_Gather . Le processus racine diffuse des ensembles de 100 entiers aux autres processus, mais les ensembles de 100 sont espacés de stride entiers dans le tampon d'envoi. Nécessite l'utilisation de MPI_Scatterv, où stride >= 100.

MPI_Comm comm;
int gsize,*sendbuf;
int root, rbuf[100], i, *displs, *scounts;
...
MPI_Comm_size(comm, &gsize);
sendbuf = (int *)malloc(gsize*stride*sizeof(int));
...
displs = (int *)malloc(gsize*sizeof(int));
scounts = (int *)malloc(gsize*sizeof(int));
for (i=0; i<gsize; ++i) {
   displs[i] = i*stride;
   scounts[i] = 100;
}
MPI_Scatterv(sendbuf, scounts, displs, MPI_INT,
             rbuf, 100, MPI_INT, root, comm);

UTILISATION DE L'OPTION EN PLACE

Lorsque le communicateur est un intracommunicateur, vous pouvez effectuer une opération de diffusion en place (le tampon de sortie est utilisé comme tampon d'entrée). Utilisez la variable MPI_IN_PLACE comme valeur de recvbuf pour le processus racine. Dans ce cas, recvcount et recvtype sont ignorés, et le processus racine n'envoie aucune donnée à lui-même.

Note : MPI_IN_PLACE est un type de valeur spéciale ; il a les mêmes restrictions d'utilisation que MPI_BOTTOM.

Étant donné que l'option en place transforme le buffer de réception en buffer d'envoi et de réception, une liaison Fortran qui inclut INTENT doit marquer ces derniers comme INOUT, et non comme OUT.

QUAND LE COMMUNICATEUR EST UN COMMUNICATEUR INTER

Lorsque le communicateur est un communicateur inter, le processus racine du premier groupe envoie des données à tous les processus du second groupe. Le premier groupe définit le processus racine. Ce processus utilise MPI_ROOT comme valeur de son argument root. Les processus restants utilisent MPI_PROC_NULL comme valeur de leur argument root. Tous les processus du second groupe utilisent le rang du processus racine du premier groupe comme valeur de leur argument root. L'argument buffer de réception du processus racine du premier groupe doit être cohérent avec l'argument buffer de réception des processus du second groupe.

ERREURS

Presque toutes les routines MPI renvoient une valeur d'erreur ; les routines C comme résultat de retour de la fonction et les routines Fortran dans le dernier argument.

Avant que la valeur d'erreur ne soit renvoyée, le gestionnaire d'erreurs MPI actuel associé à l'objet de communication (par exemple, communicateur, fenêtre, fichier) est appelé. S'il n'y a pas d'objet de communication associé à l'appel MPI, alors l'appel est considéré comme attaché à MPI_COMM_SELF et appellera le gestionnaire d'erreurs MPI associé. Lorsque MPI_COMM_SELF n'est pas initialisé (c'est-à-dire avant MPI_Init/MPI_Init_thread, après MPI_Finalize, ou lors de l'utilisation exclusive du modèle de sessions), l'erreur déclenche le gestionnaire d'erreurs initial. Le gestionnaire d'erreurs initial peut être modifié en appelant MPI_Comm_set_errhandler sur MPI_COMM_SELF lors de l'utilisation du modèle World, ou par l'argument de ligne de commande mpi_initial_errhandler de mpiexec ou par la clé d'information de MPI_Comm_spawn/MPI_Comm_spawn_multiple. Si aucun autre gestionnaire d'erreurs approprié n'a été défini, alors le gestionnaire d'erreurs MPI_ERRORS_RETURN est appelé pour les fonctions MPI I/O et le gestionnaire d'erreurs MPI_ERRORS_ABORT est appelé pour toutes les autres fonctions MPI.

Open MPI comprend trois gestionnaires d'erreurs prédéfinis qui peuvent être utilisés :

  • MPI_ERRORS_ARE_FATAL Provoque l'abandon de tous les processus MPI connectés.
  • MPI_ERRORS_ABORT Un gestionnaire d'erreurs qui peut être invoqué sur un communicateur, une fenêtre, un fichier ou une session. Lorsqu'il est appelé sur un communicateur, il agit comme si MPI_Abort avait été appelé sur ce communicateur. S'il est appelé sur une fenêtre ou un fichier, il agit comme si MPI_Abort avait été appelé sur un communicateur contenant le groupe de processus de la fenêtre ou du fichier correspondant. S'il est appelé sur une session, il n'abandonne que le processus local.
  • MPI_ERRORS_RETURN Renvoie un code d'erreur à l'application.

Les applications MPI peuvent également implémenter leurs propres gestionnaires d'erreurs en appelant :

  • MPI_Comm_create_errhandler puis MPI_Comm_set_errhandler
  • MPI_File_create_errhandler puis MPI_File_set_errhandler
  • MPI_Session_create_errhandler puis MPI_Session_set_errhandler ou à MPI_Session_init
  • MPI_Win_create_errhandler puis MPI_Win_set_errhandler

Notez que MPI ne garantit pas qu'un programme MPI puisse continuer après une erreur.

Voir la page de manuel MPI pour une liste complète des codes d'erreur MPI.

Voir la section Gestion des erreurs de la norme MPI-3.1 pour plus d'informations.
