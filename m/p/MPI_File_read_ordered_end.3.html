MPI_FILE_READ_ORDERED_END(3) Open MPI MPI_FILE_READ_ORDERED_END(3)

MPI_File_read_ordered_end — Lit un fichier à un emplacement spécifié par un pointeur de fichier partagé ; partie terminale d'une routine collective divisée (bloquante).

SYNTAXE

Syntaxe C

#include <mpi.h>
int MPI_File_read_ordered_end(MPI_File fh, void *buf,
     MPI_Status *status)

Syntaxe Fortran

USE MPI
! ou la forme plus ancienne : INCLUDE 'mpif.h'
MPI_FILE_READ_ORDERED_END(FH, BUF, STATUS, IERROR)
     <type>  BUF(*)
     INTEGER FH, STATUS(MPI_STATUS_SIZE), IERROR

Syntaxe Fortran 2008

USE mpi_f08
MPI_File_read_ordered_end(fh, buf, status, ierror)
     TYPE(MPI_File), INTENT(IN) :: fh
     TYPE(*), DIMENSION(..), ASYNCHRONOUS :: buf
     TYPE(MPI_Status) :: status
     INTEGER, OPTIONAL, INTENT(OUT) :: ierror

PARAMÈTRE ENTRÉE/SORTIE

•
fh : Handle de fichier (handle).

PARAMÈTRES SORTIE

  • buf : Adresse initiale du tampon (choix).
  • status : Objet statut (statut).
  • ierror : Fortran seulement : statut d'erreur (entier).

DESCRIPTION

MPI_File_read_ordered_end est la partie terminale d'une routine collective divisée qui doit être appelée par tous les processus du groupe de communicateurs associé au handle de fichier fh. MPI_File_rad_ordered_end bloque jusqu'à ce que l'opération initiée par MPI_File_read_ordered_begin soit terminée. Elle tente de lire le fichier associé à fh dans le tampon utilisateur buf. Le pointeur de fichier partagé est mis à jour par les quantités de données demandées par tous les processus du groupe. Pour chaque processus, l'emplacement dans le fichier où les données sont lues est la position à laquelle le pointeur de fichier partagé se trouverait après que tous les processus dont le rang dans le groupe est inférieur à celui de ce processus aient lu leurs données.

NOTES

Toutes les routines collectives non bloquantes pour l'accès aux données sont « divisées » en deux routines, chacune avec _begin ou _end comme suffixe. Ces routines collectives divisées sont soumises aux règles sémantiques décrites dans la section 9.4.5 de la norme MPI-2.

ERREURS

Presque toutes les routines MPI renvoient une valeur d'erreur ; les routines C comme résultat de retour de la fonction et les routines Fortran dans le dernier argument.

Avant que la valeur d'erreur ne soit renvoyée, le gestionnaire d'erreurs MPI actuellement associé à l'objet de communication (par exemple, le communicateur, la fenêtre, le fichier) est appelé. Si aucun objet de communication n'est associé à l'appel MPI, alors l'appel est considéré comme attaché à MPI_COMM_SELF et appellera le gestionnaire d'erreurs MPI associé. Lorsque MPI_COMM_SELF n'est pas initialisé (c'est-à-dire avant MPI_Init/MPI_Init_thread, après MPI_Finalize, ou lorsque vous utilisez exclusivement le modèle de sessions), l'erreur déclenche le gestionnaire d'erreurs initial. Le gestionnaire d'erreurs initial peut être modifié en appelant MPI_Comm_set_errhandler sur MPI_COMM_SELF lorsque vous utilisez le modèle Monde, ou l'argument de ligne de commande mpi_initial_errhandler pour mpiexec ou la clé d'information pour MPI_Comm_spawn/MPI_Comm_spawn_multiple. Si aucun autre gestionnaire d'erreurs approprié n'a été défini, alors le gestionnaire d'erreurs MPI_ERRORS_RETURN est appelé pour les fonctions d'E/S MPI et le gestionnaire d'erreurs MPI_ERRORS_ABORT est appelé pour toutes les autres fonctions MPI.

Open MPI inclut trois gestionnaires d'erreurs prédéfinis qui peuvent être utilisés :

  • MPI_ERRORS_ARE_FATAL Provoque l'abandon de tous les processus MPI connectés.
  • MPI_ERRORS_ABORT Un gestionnaire d'erreurs qui peut être invoqué sur un communicateur, une fenêtre, un fichier ou une session. Lorsqu'il est appelé sur un communicateur, il agit comme si MPI_Abort avait été appelé sur ce communicateur. S'il est appelé sur une fenêtre ou un fichier, il agit comme si MPI_Abort avait été appelé sur un communicateur contenant le groupe des processus de la fenêtre ou du fichier correspondant. S'il est appelé sur une session, seul le processus local est abandonné.
  • MPI_ERRORS_RETURN Renvoie un code d'erreur à l'application.

Les applications MPI peuvent également implémenter leurs propres gestionnaires d'erreurs en appelant :

  • MPI_Comm_create_errhandler puis MPI_Comm_set_errhandler
  • MPI_File_create_errhandler puis MPI_File_set_errhandler
  • MPI_Session_create_errhandler puis MPI_Session_set_errhandler ou lors de MPI_Session_init
  • MPI_Win_create_errhandler puis MPI_Win_set_errhandler

Notez que MPI ne garantit pas qu'un programme MPI puisse continuer après une erreur.

Consultez la page de manuel MPI pour une liste complète des codes d'erreur MPI.

Consultez la section Gestion des erreurs de la norme MPI-3.1 pour plus d'informations.
