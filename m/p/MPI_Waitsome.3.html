MPI_WAITSOME(3) Open MPI MPI_WAITSOME(3)

MPI_Waitsome — Attend que certaines des opérations associées aux handles actifs dans la liste soient terminées.

Syntaxe

Syntaxe C

#include <mpi.h>
int MPI_Waitsome(int incount, MPI_Request array_of_requests[],
     int *outcount, int array_of_indices[],
     MPI_Status array_of_statuses[])

Syntaxe Fortran

USE MPI
! ou l'ancienne forme: INCLUDE 'mpif.h'
MPI_WAITSOME(INCOUNT, ARRAY_OF_REQUESTS, OUTCOUNT,
             ARRAY_OF_INDICES, ARRAY_OF_STATUSES, IERROR)
     INTEGER INCOUNT, ARRAY_OF_REQUESTS(*), OUTCOUNT
     INTEGER ARRAY_OF_INDICES(*)
     INTEGER ARRAY_OF_STATUSES(MPI_STATUS_SIZE*)
     INTEGER IERROR

Syntaxe Fortran 2008

USE mpi_f08
MPI_Waitsome(incount, array_of_requests, outcount, array_of_indices,
             array_of_statuses, ierror)
     INTEGER, INTENT(IN) :: incount
     TYPE(MPI_Request), INTENT(INOUT) :: array_of_requests(incount)
     INTEGER, INTENT(OUT) :: outcount, array_of_indices(*)
     TYPE(MPI_Status) :: array_of_statuses(*)
     INTEGER, OPTIONAL, INTENT(OUT) :: ierror

Paramètres d'entrée

  • incount: Taille du tableau array_of_requests (entier).
  • array_of_requests: Tableau des requêtes (tableau de handles).

Paramètres de sortie

  • outcount: Nombre de requêtes terminées (entier).
  • array_of_indices: Tableau des indices des opérations terminées (tableau d'entiers).
  • array_of_statuses: Tableau des objets d'état pour les opérations terminées (tableau d'état).
  • ierror: Uniquement en Fortran : État d'erreur (entier).

Description

Attend qu'au moins une des opérations associées aux handles actifs dans la liste soit terminée. Renvoie dans outcount le nombre de requêtes qui se sont terminées à partir du tableau array_of_requests. Renvoie dans les outcount premiers emplacements du tableau array_of_indices les indices de ces opérations (indice dans le tableau array_of_requests ; le tableau est indexé à partir de 0 en C et à partir de 1 en Fortran). Renvoie dans les outcount premiers emplacements du tableau array_of_status l'état de ces opérations terminées. Si une requête qui s'est terminée a été attribuée par un appel non bloquant, elle est désallouée et le handle est défini sur MPI_REQUEST_NULL.

Si la liste ne contient aucun handle actif, l'appelant renvoie immédiatement avec outcount = MPI_UNDEFINED.

Lorsque l'une ou plusieurs des communications complétées par MPI_Waitsome échouent, il est souhaitable de renvoyer des informations spécifiques sur chaque communication. Les arguments outcount, array_of_indices et array_of_statuses seront ajustés pour indiquer la fin de toutes les communications qui réussissent ou échouent. L'appelant renverra le code d'erreur MPI_ERR_IN_STATUS et le champ d'erreur de chaque état renvoyé sera défini pour indiquer le succès ou l'erreur spécifique qui s'est produite. L'appelant renverra MPI_SUCCESS si aucune erreur n'a été générée lors de la requête, et renverra un autre code d'erreur si elle a échoué pour d'autres raisons (telles que des arguments invalides). Dans de tels cas, les champs d'erreur des états ne seront pas mis à jour.

Si votre application n'a pas besoin d'examiner le champ array_of_statuses, vous pouvez économiser des ressources en utilisant la constante prédéfinie MPI_STATUSES_IGNORE comme valeur spéciale pour l'argument array_of_statuses.

Exemple : Code similaire à l'exemple MPI_Waitany, mais utilisant MPI_Waitsome.

CALL MPI_COMM_SIZE(comm, size, ierr)
CALL MPI_COMM_RANK(comm, rank, ierr)
IF(rank > 0) THEN         ! code client
    DO
       CALL MPI_ISEND(a, n, MPI_REAL, 0, tag, comm, request, ierr)
       CALL MPI_WAIT(request, status, ierr)
    END DO
ELSE         ! rank=0 : code serveur
    DO i=1, size-1
       CALL MPI_IRECV(a(1,i), n, MPI_REAL, i, tag, &
                      comm, requests(i), ierr)
    END DO
    DO
       CALL MPI_WAITSOME(size, request_list, numdone, &
                        indices, statuses, ierr)
       DO i=1, numdone
          CALL DO_SERVICE(a(1, indices(i)))
          CALL MPI_IRECV(a(1, indices(i)), n, MPI_REAL, i, tag, &
                       comm, requests(indices(i)), ierr)
       END DO
    END DO
END IF

Remarques

Les indices du tableau sont dans la plage 0 à incount-1 en C et dans la plage 1 à incount en Fortran.

Erreurs

La plupart des routines MPI renvoient une valeur d'erreur ; les routines C renvoient le résultat de la fonction et les routines Fortran dans le dernier argument.

Avant de renvoyer la valeur d'erreur, le gestionnaire d'erreurs associé à l'objet de communication (par exemple, communiteur, fenêtre, fichier) est appelé. S'il n'y a pas d'objet de communication associé à l'appel MPI, l'appel est considéré comme associé à MPI_COMM_SELF et le gestionnaire d'erreurs correspondant est appelé. Lorsque MPI_COMM_SELF n'est pas initialisé (c'est-à-dire avant MPI_Init/MPI_Init_thread, après MPI_Finalize ou lorsque le modèle de Sessions est utilisé exclusivement), l'erreur élève le gestionnaire d'erreurs initial. Le gestionnaire d'erreurs initial peut être modifié en appelant MPI_Comm_set_errhandler sur MPI_COMM_SELF lorsque le modèle du Monde est utilisé, ou via l'argument mpi_initial_errhandler dans mpiexec ou la clé info dans MPI_Comm_spawn/MPI_Comm_spawn_multiple. Si aucun autre gestionnaire d'erreurs approprié n'est défini, le gestionnaire d'erreurs MPI_ERRORS_RETURN est appelé pour les fonctions d'E/S MPI et le gestionnaire d'erreurs MPI_ERRORS_ABORT pour toutes les autres fonctions MPI.

Open MPI inclut trois gestionnaires d'erreurs prédéfinis qui peuvent être utilisés :

  • MPI_ERRORS_ARE_FATAL Provoque l'arrêt de tous les processus MPI connectés par le programme.
  • MPI_ERRORS_ABORT Un gestionnaire d'erreurs qui peut être invoqué sur un communiteur, une fenêtre, un fichier ou une session. Lorsqu'il est invoqué sur un communiteur, il agit comme si MPI_Abort avait été appelé sur ce communiteur. S'il est invoqué sur une fenêtre ou un fichier, il agit comme si MPI_Abort avait été appelé sur un communiteur qui contient l'ensemble des processus dans la fenêtre ou le fichier correspondant. S'il est invoqué sur une session, il n'interrompt que le processus local.
  • MPI_ERRORS_RETURN Renvoie un code d'erreur à l'application.

Les applications MPI peuvent également implémenter leurs propres gestionnaires d'erreurs en appelant :

  • MPI_Comm_create_errhandler puis MPI_Comm_set_errhandler
  • MPI_File_create_errhandler puis MPI_File_set_errhandler
  • MPI_Session_create_errhandler puis MPI_Session_set_errhandler ou lors de MPI_Session_init
  • MPI_Win_create_errhandler puis MPI_Win_set_errhandler

Remarque : MPI ne garantit pas qu'une application MPI puisse continuer après une erreur.

Voir la page de manuel MPI pour une liste complète des codes d'erreur MPI.

Voir la section Gestion des erreurs de la spécification MPI-3.1 pour plus d'informations.

Pour chaque invocation de MPI_Waitsome, si une requête génère une erreur MPI, seul le premier MPI request ayant causé l'erreur est passé au gestionnaire d'erreurs correspondant. Aucun autre gestionnaire d'erreurs n'est invoqué (même si plusieurs requêtes ont généré des erreurs). Cependant, toutes les requêtes qui génèrent une erreur auront un code d'erreur pertinent défini dans le champ status.MPI_ERROR correspondant (sauf si MPI_STATUSES_IGNORE a été utilisé).

Si le gestionnaire d'erreurs invoqué permet à MPI_Waitsome de renvoyer à l'appelant, la valeur MPI_ERR_IN_STATUS est renvoyée dans les bindings C et Fortran.

NAME

MPI_Waitsome

SYNTAX


int MPI_Waitsome(int count, MPI_Request requests[], int *outcount, int indices[], MPI_Status statuses[]);

INPUT PARAMETERS

count
Number of requests in the array (integer).
requests
Array of MPI requests (MPI_Request).

OUTPUT PARAMETERS

outcount
Number of requests that completed (integer).
indices
Array of indices of completed requests in the original `requests` array (integer).
statuses
Array of MPI status objects for the completed requests (MPI_Status).

DESCRIPTION

MPI_Waitsome() is a blocking function that waits for at least one of the MPI requests in the given array to complete. It returns the number of completed requests and an array of indices indicating which of the original requests have completed. The status objects for the completed requests are also returned.

If all requests complete, then outcount will be equal to count.

If no requests complete, outcount will be zero. This is not an error condition; it simply means that none of the operations were ready when the function was called.

The statuses array will contain valid status information only for the completed requests. For requests that did not complete, the contents of the corresponding element in the statuses array are undefined.

It is the user's responsibility to ensure that the requests array does not contain duplicate requests.

NOTES

MPI_Waitsome() is particularly useful when you have multiple non-blocking operations in flight and you want to process them as they complete, rather than waiting for all of them to finish.

The order of the completed requests in the indices and statuses arrays is not necessarily the order in which they completed. It is the order in which they appeared in the original requests array.

The behavior of MPI_Waitsome() is undefined if the requests array contains duplicate requests.

ERRORS

The MPI standard classifies errors into different classes. Errors occurring during the execution of MPI routines are reported to the user according to the error handler attached to the communicator for the operation. The default error handler aborts the MPI program.

  • MPI_ERR_INVAL: Invalid arguments. For example, if count is negative or if requests is not a valid array of requests.

NOM

MPI_Waitsome

SYNTAXE


int MPI_Waitsome(int count, MPI_Request requests[], int *outcount, int indices[], MPI_Status statuses[]);

PARAMÈTRES D'ENTRÉE

count
Nombre de requêtes dans le tableau (entier).
requests
Tableau de requêtes MPI (MPI_Request).

PARAMÈTRES DE SORTIE

outcount
Nombre de requêtes terminées (entier).
indices
Tableau des indices des requêtes terminées dans le tableau `requests` original (entier).
statuses
Tableau des objets de statut MPI pour les requêtes terminées (MPI_Status).

DESCRIPTION

MPI_Waitsome() est une fonction bloquante qui attend qu'au moins une des requêtes MPI dans le tableau donné soit terminée. Elle retourne le nombre de requêtes terminées et un tableau d'indices indiquant quelles requêtes originales sont terminées. Les objets de statut pour les requêtes terminées sont également retournés.

Si toutes les requêtes sont terminées, outcount sera égal à count.

Si aucune requête n'est terminée, outcount sera zéro. Ce n'est pas une condition d'erreur ; cela signifie simplement qu'aucune des opérations n'était prête lorsque la fonction a été appelée.

Le tableau statuses contiendra des informations de statut valides uniquement pour les requêtes terminées. Pour les requêtes qui ne sont pas terminées, le contenu de l'élément correspondant dans le tableau statuses est indéfini.

Il est de la responsabilité de l'utilisateur de s'assurer que le tableau requests ne contient pas de requêtes dupliquées.

NOTES

MPI_Waitsome() est particulièrement utile lorsque vous avez plusieurs opérations non bloquantes en cours et que vous souhaitez les traiter dès qu'elles se terminent, plutôt que d'attendre qu'elles soient toutes finies.

L'ordre des requêtes terminées dans les tableaux indices et statuses n'est pas nécessairement l'ordre dans lequel elles se sont terminées. C'est l'ordre dans lequel elles sont apparues dans le tableau requests original.

Le comportement de MPI_Waitsome() est indéfini si le tableau requests contient des requêtes dupliquées.

ERREURS

Le standard MPI classe les erreurs en différentes catégories. Les erreurs survenant lors de l'exécution des routines MPI sont signalées à l'utilisateur conformément au gestionnaire d'erreurs attaché au communicateur pour l'opération. Le gestionnaire d'erreurs par défaut arrête le programme MPI.

  • MPI_ERR_INVAL : Arguments invalides. Par exemple, si count est négatif ou si requests n'est pas un tableau valide de requêtes.
