MPI_ISENDRECV_REPLACE(3) Open MPI MPI_ISENDRECV_REPLACE(3)

MPI_Isendrecv_replace — Envoie et reçoit un message en utilisant un seul tampon.

SYNTAXE

C Syntaxe

#include <mpi.h>
int MPI_Isendrecv_replace(void *buf, int count, MPI_Datatype datatype,
    int dest, int sendtag, int source, int recvtag, MPI_Comm comm,
    MPI_Request *request)

Fortran Syntaxe

USE MPI
! ou la vieille forme: INCLUDE 'mpif.h'
MPI_ISENDRECV_REPLACE(BUF, COUNT, DATATYPE, DEST, SENDTAG, SOURCE,
        RECVTAG, COMM, REQUEST, IERROR)
    TYPE(*), DIMENSION(..) :: BUF
    INTEGER, INTENT(IN) :: COUNT, DEST, SENDTAG, SOURCE, RECVTAG
    TYPE(MPI_Datatype), INTENT(IN) :: DATATYPE
    TYPE(MPI_Comm), INTENT(IN) :: COMM
    TYPE(MPI_Request) :: REQUEST
    INTEGER, OPTIONAL, INTENT(OUT) :: IERROR

Fortran 2008 Syntaxe

USE mpi_f08
MPI_Isendrecv_replace(buf, count, datatype, dest, sendtag, source, recvtag,
        comm, request, ierror)
    TYPE(*), DIMENSION(..) :: buf
    INTEGER, INTENT(IN) :: count, dest, sendtag, source, recvtag
    TYPE(MPI_Datatype), INTENT(IN) :: datatype
    TYPE(MPI_Comm), INTENT(IN) :: comm
    TYPE(MPI_Request) :: request
    INTEGER, OPTIONAL, INTENT(OUT) :: ierror

PARAMÈTRES ENTRÉE/SORTIE

•
buf: Adresse initiale des tampons d'envoi et de réception (sortie).

PARAMÈTRES ENTRÉE

  • count: Nombre d'éléments dans les tampons d'envoi et de réception (entier).
  • datatype: Type des éléments à envoyer et recevoir (handle).
  • dest: Rang de la destination (entier).
  • sendtag: Étiquette du message à envoyer (entier).
  • source: Rang de la source (entier).
  • recvtag: Étiquette du message à recevoir (entier).
  • comm: Communicateur (handle).

PARAMÈTRES SORTIE

  • request: Requête de communication (handle).
  • ierror: En Fortran seulement : Statut d'erreur (entier).

DESCRIPTION

Les opérations d'envoi et de réception non bloquantes combinent en un seul appel l'envoi d'un message à une destination et la réception d'un autre message, provenant d'un autre processus. Les deux (origine et destination) peuvent être les mêmes. Une opération d'envoi-réception est utile pour effectuer un déplacement dans une chaîne de processus. L'opération d'envoi-réception peut être utilisée conjointement avec les fonctions décrites dans le chapitre « Topologie des processus » du standard MPI pour effectuer des déplacements dans différentes topologies logiques. De plus, une opération d'envoi-réception est utile pour implémenter des appels distants. Le message envoyé par une opération d'envoi-réception peut être reçu par une opération de réception régulière ou testé par une opération de test ; une opération d'envoi-réception peut recevoir un message envoyé par une opération d'envoi régulière.

MPI_Isendrecv_replace exécute une opération d'envoi et de réception non bloquante. Le même tampon est utilisé à la fois pour l'envoi et la réception, de sorte que le message envoyé est remplacé par le message reçu.

Une requête d'envoi-réception non bloquante peut être considérée comme complétée en appelant MPI_Wait, MPI_Waitany, MPI_Test ou MPI_Testany avec la requête retournée par cette fonction.

ERREURS

Plus que tout, toutes les routines MPI retournent une valeur d'erreur ; les routines C retournent le résultat de la fonction et les routines Fortran dans le dernier argument.

Avant de retourner la valeur d'erreur, le gestionnaire d'erreur associé à l'objet de communication (par exemple, le communicateur, la fenêtre, le fichier) actuel est appelé. Si aucun objet de communication n'est associé à l'appel MPI, l'appel est considéré comme associé à MPI_COMM_SELF et le gestionnaire d'erreur associé à MPI_COMM_SELF est appelé. Lorsque MPI_COMM_SELF n'est pas initialisé (c'est-à-dire avant MPI_Init/MPI_Init_thread, après MPI_Finalize, ou lorsque le modèle de session est utilisé exclusivement), le gestionnaire d'erreur initial est levé. Le gestionnaire d'erreur initial peut être modifié en appelant MPI_Comm_set_errhandler sur MPI_COMM_SELF lors de l'utilisation du modèle du monde, ou sur l'option mpi_initial_errhandler de mpiexec ou sur la clé info de MPI_Comm_spawn/MPI_Comm_spawn_multiple. Si aucun autre gestionnaire d'erreur approprié n'est configuré, le gestionnaire d'erreur MPI_ERRORS_RETURN est appelé pour les fonctions d'E/S MPI et le gestionnaire d'erreur MPI_ERRORS_ABORT pour les autres fonctions MPI.

Open MPI inclut trois gestionnaires d'erreurs par défaut qui peuvent être utilisés :

  • MPI_ERRORS_ARE_FATAL Peut arrêter tous les processus MPI connectés.
  • MPI_ERRORS_ABORT Un gestionnaire d'erreurs qui peut être invoqué sur un communicateur, une fenêtre, un fichier ou une session. Lorsqu'il est invoqué sur un communicateur, il agit comme si MPI_Abort avait été appelé sur ce communicateur. S'il est invoqué sur une fenêtre ou un fichier, il agit comme si MPI_Abort avait été appelé sur un communicateur contenant le groupe de processus dans la fenêtre ou le fichier correspondant. S'il est invoqué sur une session, il arrête uniquement le processus local.
  • MPI_ERRORS_RETURN Renvoie un code d'erreur à l'application.

Les programmes MPI peuvent également implémenter leurs propres gestionnaires d'erreurs en appelant :

  • MPI_Comm_create_errhandler puis MPI_Comm_set_errhandler
  • MPI_File_create_errhandler puis MPI_File_set_errhandler
  • MPI_Session_create_errhandler puis MPI_Session_set_errhandler ou dans MPI_Session_init
  • MPI_Win_create_errhandler puis MPI_Win_set_errhandler

Remarque : Il n'est pas garanti qu'un programme MPI puisse continuer après une erreur.

Voir la page man de MPI pour une liste complète des codes d'erreur MPI.

Voir la section sur la gestion des erreurs de la norme MPI-3.1 pour plus d'informations.
