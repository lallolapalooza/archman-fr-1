MPI_Dist_graph_create — Crée un nouveau communicateur avec une topologie de graphe distribué.

Syntaxe

Syntaxe C

#include <mpi.h>
int MPI_Dist_graph_create(MPI_Comm comm_old, int n, const int sources[],
     const int degrees[], const int destinations[], const int weights[],
        MPI_Info info, int reorder, MPI_Comm *comm_dist_graph)

USE MPI

MPI_DIST_GRAPH_CREATE(COMM_OLD, N, SOURCES, DEGREES, DESTINATIONS, WEIGHTS,
                INFO, REORDER, COMM_DIST_GRAPH, IERROR)
     INTEGER COMM_OLD, N, SOURCES(*), DEGREES(*), WEIGHTS(*)

Syntaxe Fortran 2008

USE mpi_f08
MPI_Dist_Graph_create(COMM_OLD, N, SOURCES, DEGREES, DESTINATIONS, WEIGHTS,
             INFO, REORDER, COMM_DIST_GRAPH, IERROR)
     TYPE(MPI_Comm), INTENT(IN) :: COMM_OLD
     INTEGER, INTENT(IN) :: N, SOURCES(N), DEGREES(N), DESTINATIONS(*)
     INTEGER, INTENT(IN) :: WEIGHTS(*)
     TYPE(MPI_Info), INTENT(IN) :: INFO

Paramètres d'entrée

  • comm_old : Communicateur sans topologie (handle).
  • n : Nombre de nœuds sources pour lesquels ce processus spécifie des arêtes (entier non négatif).
  • sources : Tableau des n nœuds sources pour lesquels ce processus spécifie des arêtes (tableau d'entiers non négatifs).
  • degrees : Tableau spécifiant le nombre de nœuds de destination pour chaque nœud source dans le tableau sources (tableau d'entiers non négatifs).
  • destinations : Nœuds de destination pour les nœuds sources dans le tableau sources (tableau d'entiers non négatifs).
  • weights : Poids des arêtes source vers destination (tableau d'entiers non négatifs).
  • info : Indices pour l'optimisation et l'interprétation des poids (handle).
  • reorder : La hiérarchie peut être réordonnée (vrai) ou non (faux) (logique).

Paramètres de sortie

  • comm_dist_graph : Communicateur avec la topologie de graphe distribué ajoutée (handle).
  • ierror : Uniquement en Fortran : Statut d'erreur (entier).

Description

MPI_Dist_graph_create crée un nouveau communicateur comm_dist_graph avec une topologie de graphe distribué et retourne un handle vers le nouveau communicateur. Le nombre de processus dans comm_dist_graph est identique au nombre de processus dans comm_old. Spécifiquement, chaque processus appelle le constructeur avec un ensemble d'arêtes dirigées (source, destination) comme décrit ci-dessous. Chaque processus passe un tableau de n nœuds sources dans le tableau sources. Pour chaque nœud source, un nombre non négatif de nœuds de destination est spécifié dans le tableau degrees. Les nœuds de destination sont stockés dans le segment correspondant du tableau destinations. Plus précisément, si le i-ème nœud dans sources est s, cela spécifie degrees[i] arêtes (s, d) avec d des j-èmes arêtes stockées dans destinations[degrees[0] + ... + degrees[i-1] + j]. Le poids de cette arête est stocké dans weights[degrees[0] + ... + degrees[i-1] + j]. Les tableaux sources et destinations peuvent contenir le même nœud plus d'une fois, et l'ordre dans lequel les nœuds sont listés comme source ou destination n'est pas significatif. De même, différents processus peuvent spécifier des arêtes avec des nœuds sources et destinations identiques. Les nœuds sources et destinations doivent être des rangs de processus dans comm_old. Différents processus peuvent spécifier un nombre différent de nœuds sources et de destination, ainsi que des arêtes source-destination différentes. Ceci permet une spécification entièrement distribuée du graphe de communication. Des processus isolés (c'est-à-dire, des processus qui n'ont pas d'arête sortante ou entrante, c'est-à-dire, qui n'apparaissent pas comme nœud source ou destination dans la spécification du graphe) sont autorisés. L'appel à MPI_Dist_graph_create est collectif.

Si reorder est faux, tous les processus auront le même rang dans comm_dist_graph que dans comm_old. Si reorder est vrai, la bibliothèque MPI sera libre de réattribuer à d'autres processus (de comm_old) afin d'améliorer la communication sur les arêtes du graphe de communication. Le poids associé à chaque arête est une indication pour la bibliothèque MPI sur le volume ou l'intensité de la communication sur cette arête, et peut être utilisé pour calculer un

Poids des arêtes

Les poids sont spécifiés comme des entiers non négatifs et peuvent être utilisés pour influencer la stratégie de remappage des processus et d'autres optimisations internes de MPI. Par exemple, les arguments de comptage approximatif d'appels de communication ultérieurs sur certaines arêtes pourraient être utilisés comme leurs poids d'arêtes. La multiplicité des arêtes peut indiquer une communication plus intense entre les paires de processus. Cependant, la signification exacte des poids d'arêtes n'est pas spécifiée par la norme MPI et est à la discrétion de l'implémentation. Une application peut fournir la valeur spéciale MPI_UNWEIGHTED pour le tableau de poids afin d'indiquer que toutes les arêtes ont le même poids (effectivement, aucun). Il est erroné de fournir MPI_UNWEIGHTED pour certains mais pas pour tous les processus de comm_old. Si le graphe est pondéré mais que n = 0, n'importe quel tableau de poids peut être passé à weights. Notez que MPI_UNWEIGHTED et MPI_WEIGHTS_EMPTY ne sont pas des valeurs de poids spéciales ; ce sont des valeurs spéciales pour l'argument tableau entier. En Fortran, MPI_UNWEIGHTED et MPI_WEIGHTS_EMPTY sont des objets comme MPI_BOTTOM (non utilisables pour l'initialisation ou l'assignation). Voir la section MPI-3 2.5.4.

Erreurs

La plupart des routines MPI retournent une valeur d'erreur ; les routines C retournent le résultat de la fonction et les routines Fortran le dernier argument.

Avant que la valeur d'erreur ne soit retournée, la fonction de gestionnaire d'erreur associée à l'objet de communication (par exemple, communicateur, fenêtre, fichier) actuel est appelée. S'il n'y a pas d'objet de communication associé à l'appel MPI, l'appel est considéré comme associé à MPI_COMM_SELF et appellera le gestionnaire d'erreur associé à MPI_COMM_SELF. Si MPI_COMM_SELF n'est pas initialisé (c'est-à-dire avant MPI_Init/MPI_Init_thread, après MPI_Finalize, ou lorsque le modèle de Sessions est utilisé exclusivement), l'erreur déclenche le gestionnaire d'erreur initial. Le gestionnaire d'erreur initial peut être modifié en appelant MPI_Comm_set_errhandler avec MPI_COMM_SELF lorsque le modèle du Monde est utilisé, ou l'argument CLI mpi_initial_errhandler de mpiexec ou la clé d'info de MPI_Comm_spawn/MPI_Comm_spawn_multiple. S'il n'y a pas d'autre gestionnaire d'erreur approprié, le gestionnaire d'erreur MPI_ERRORS_RETURN est appelé pour les fonctions d'E/S MPI et le gestionnaire d'erreur MPI_ERRORS_ABORT est appelé pour toutes les autres fonctions MPI.

Open MPI inclut trois gestionnaires d'erreur prédéfinis qui peuvent être utilisés :

  • MPI_ERRORS_ARE_FATAL : Provoque l'arrêt de tous les processus connectés à MPI.
  • MPI_ERRORS_ABORT : Un gestionnaire d'erreur qui peut être invoqué sur un communicateur, une fenêtre, un fichier ou une session. Lorsqu'il est invoqué sur un communicateur, il agit comme si MPI_Abort avait été appelé sur ce communicateur. S'il est invoqué sur une fenêtre ou un fichier, il agit comme si MPI_Abort avait été appelé sur un communicateur contenant le groupe de processus de la fenêtre ou du fichier correspondant. S'il est invoqué sur une session, il arrête uniquement le processus local.
  • MPI_ERRORS_RETURN : Retourne un code d'erreur à l'application.

Les applications MPI peuvent également implémenter leurs propres gestionnaires d'erreur en appelant :

  • MPI_Comm_create_errhandler puis MPI_Comm_set_errhandler
  • MPI_File_create_errhandler puis MPI_File_set_errhandler
  • MPI_Session_create_errhandler puis MPI_Session_set_errhandler ou dans MPI_Session_init
  • MPI_Win_create_errhandler puis MPI_Win_set_errhandler

DESCRIPTION

MPI_Dist_graph_create creates a new distributed graph communicator. A distributed graph communicator represents a graph where vertices and edges are distributed among the processes. Each process provides information about the vertices it owns and the incoming and outgoing edges connecting to other processes.

The indegrees, outdegrees, sources, and destinations arrays describe the graph structure locally. Each process specifies the indegree and outdegree of the n vertices it owns. The sources array lists the processes from which edges originate to reach the local vertices. The destinations array lists the processes to which edges point from the local vertices.

The info parameter can be used to provide hints to the MPI implementation regarding graph structure or communication patterns, though its specific usage is implementation-defined.

If reorder is true, the MPI implementation is allowed to reorder the vertices within each process to potentially optimize communication or load balancing. If false, the order specified by the input arrays must be preserved.

The created communicator comm_dist_graph will have the same size as comm_old. The graph topology information is implicitly associated with this new communicator.

WEIGHTS

This function does not directly support edge weights. If edge weights are required, they can be provided using the MPI_Dist_graph_create_adjacent function with the appropriate weight arguments.

ERRORS

Returns MPI_SUCCESS on success or an MPI error code on failure. Some possible MPI errors include:

  • MPI_ERR_COMM: Invalid communicator.
  • MPI_ERR_INFO: Invalid info object.
  • MPI_ERR_ARG: Invalid argument.

See the MPI man page for a full list of MPI error codes.

See the Error Handling section of the MPI-3.1 standard for more information.
