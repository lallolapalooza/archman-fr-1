MPI_Comm_create_group(3)

Paquet: openmpi

Licences: BSD-3-Clause AND LicenseRef-MPICH

MPI_Comm_create_group(3) Open MPI MPI_Comm_create_group(3)

MPI_Comm_create_group crée un nouveau communicateur.

Syntaxe

Syntaxe C

#include <mpi.h>
int MPI_Comm_create_group(MPI_Comm comm, MPI_Group group, int tag, MPI_Comm *newcomm)

Syntaxe Fortran

USE MPI
! ou l'ancienne forme: INCLUDE 'mpif.h'
MPI_COMM_CREATE_GROUP(COMM, GROUP, TAG, NEWCOMM, IERROR)
    INTEGER COMM, GROUP, TAG, NEWCOMM, IERROR

Syntaxe Fortran 2008

USE mpi_f08
MPI_Comm_create_group(comm, group, tag, newcomm, ierror)
    TYPE(MPI_Comm), INTENT(IN) :: comm
    TYPE(MPI_Group), INTENT(IN) :: group
    INTEGER, INTENT(IN) :: tag
    TYPE(MPI_Comm), INTENT(OUT) :: newcomm
    INTEGER, OPTIONAL, INTENT(OUT) :: ierror

Paramètres d'entrée

  • comm : Communicateur (handle).
  • group : Groupe, qui est un sous-ensemble du groupe du communicateur (handle).
  • tag : Étiquette (entier).

Paramètres de sortie

  • newcomm : Nouveau communicateur (handle).
  • ierror : Fortran uniquement : Statut d'erreur (entier).

Description

MPI_Comm_create_group est similaire à MPI_Comm_create ; cependant, MPI_Comm_create doit être appelé par tous les processus du groupe de communicateur, tandis que MPI_Comm_create_group doit être appelé par tous les processus du groupe, qui est un sous-groupe du groupe de communicateur. En outre, MPI_Comm_create_group exige que le communicateur soit un intracommunicateur. MPI_Comm_create_group renvoie un nouvel intracommunicateur, newcomm, pour lequel l'argument group définit le groupe de communication. Aucune information stockée n'est propagée de comm à newcomm. Chaque processus doit fournir un argument group qui est un sous-groupe du groupe associé au communicateur ; il pourrait s'agir de MPI_GROUP_EMPTY. Si un groupe non vide est spécifié, alors tous les processus de ce groupe doivent appeler la fonction, et chacun de ces processus doit fournir les mêmes arguments, y compris un groupe contenant les mêmes membres dans le même ordre. Sinon, l'appel est erroné. Si le processus appelant est membre du groupe donné en argument, alors newcomm est un communicateur avec le groupe comme groupe associé. Si le processus appelant n'est pas membre du groupe, par exemple, le groupe est MPI_GROUP_EMPTY, alors l'appel est une opération locale et MPI_COMM_NULL est renvoyé en tant que newcomm.

Notes

MPI_Comm_create_group fournit un moyen de créer un sous-groupe de processus pour le calcul MIMD séparé, avec un espace de communication distinct. newcomm, qui est créé avec MPI_Comm_create_group, peut être utilisé dans des appels ultérieurs à MPI_Comm_create_group (ou à d'autres constructeurs de communicateur) pour subdiviser un calcul en sous-calculs parallèles. Un service plus général est fourni par MPI_Comm_split.

Erreurs

Au-delà des erreurs MPI, les routines C renvoient une valeur d'erreur et les routines Fortran le dernier argument.

Avant que la valeur d'erreur ne soit renvoyée, le gestionnaire d'erreurs actuel associé à l'objet de communication (par exemple, communicateur, fenêtre, fichier) est appelé. Si aucun objet de communication n'est associé à l'appel MPI, l'appel est considéré comme associé à MPI_COMM_SELF et le gestionnaire d'erreurs associé à MPI_COMM_SELF est appelé. Lorsque MPI_COMM_SELF n'est pas initialisé (c'est-à-dire, avant MPI_Init/MPI_Init_thread, après MPI_Finalize ou lorsque le modèle de sessions est utilisé exclusivement), l'erreur initiale est déclenchée. Le gestionnaire d'erreurs initial peut être modifié en appelant MPI_Comm_set_errhandler sur MPI_COMM_SELF lorsqu'il est utilisé dans le modèle du monde, ou sur l'argument mpi_initial_errhandler de mpiexec ou sur la clé d'information de MPI_Comm_spawn/MPI_Comm_spawn_multiple. Si aucun autre gestionnaire d'erreurs approprié n'est défini, le gestionnaire d'erreurs MPI_ERRORS_RETURN est appelé pour les fonctions d'E/S MPI et le gestionnaire d'erreurs MPI_ERRORS_ABORT pour toutes les autres fonctions MPI.

Open MPI inclut trois gestionnaires prédéfinis qui peuvent être utilisés :

  • MPI_ERRORS_ARE_FATAL Provoque l'arrêt du programme sur tous les processus MPI connectés.
  • MPI_ERRORS_ABORT Un gestionnaire d'erreurs qui peut être appelé sur un communicateur, une fenêtre, un fichier ou une session. Lorsqu'il est appelé sur un communicateur, il agit comme si MPI_Abort avait été appelé sur ce communicateur. S'il est appelé sur une fenêtre ou un fichier, il agit comme si MPI_Abort avait été appelé sur un communicateur contenant le groupe de processus correspondant à la fenêtre ou au fichier. S'il est appelé sur une session, seul le processus local est abandonné.
  • MPI_ERRORS_RETURN Renvoie un code d'erreur à l'application.

Les applications MPI peuvent également implémenter leurs propres gestionnaires d'erreurs en appelant :

  • MPI_Comm_create_errhandler puis MPI_Comm_set_errhandler
  • MPI_File_create_errhandler puis MPI_File_set_errhandler
  • MPI_Session_create_errhandler puis MPI_Session_set_errhandler ou lors de MPI_Session_init
  • MPI_Win_create_errhandler puis MPI_Win_set_errhandler

Note : Les gestionnaires d'erreurs MPI ne garantissent pas qu'un programme MPI puisse continuer après une erreur.

Voir la section de gestion des erreurs de la documentation MPI-3.1 pour plus d'informations.

Introduction

Le noyau Linux 6.8 apporte une multitude d'améliorations et de nouvelles fonctionnalités, allant des mises à jour matérielles aux optimisations de performances et aux correctifs de sécurité. Cette version continue de suivre la cadence rapide de développement du noyau Linux.

Principales nouveautés

  • Support amélioré pour l'architecture ARM : De nombreux SoC et périphériques ARM reçoivent un meilleur support, y compris pour les dernières générations de processeurs.
  • Améliorations pour les processeurs Intel : Nouvelles fonctionnalités et optimisations pour les processeurs Intel, notamment une meilleure gestion de l'énergie et des performances graphiques.
  • Mises à jour du système de fichiers : Le noyau 6.8 inclut des améliorations pour les systèmes de fichiers existants comme Btrfs et XFS, ainsi que des avancées dans les nouveaux systèmes de fichiers expérimentaux.
  • Améliorations du réseau : Des optimisations au niveau du réseau, y compris pour les protocoles TCP et UDP, ainsi que pour les pilotes de cartes réseau.

Sécurité

Comme toujours, la sécurité est une priorité. Le noyau 6.8 intègre plusieurs correctifs de sécurité pour atténuer les vulnérabilités connues et renforcer la protection du système. Les mises à jour incluent des améliorations au niveau de la gestion des permissions et des mécanismes d'isolation.

Performances

Plusieurs optimisations de performances ont été intégrées, visant à réduire la latence, à améliorer l'utilisation des ressources et à augmenter la vitesse globale du système. Cela concerne notamment la planification des processus, la gestion de la mémoire et les opérations d'entrée/sortie.

Pilotes

La mise à jour du noyau s'accompagne de l'intégration de nombreux nouveaux pilotes et de mises à jour pour les pilotes existants. Cela inclut un meilleur support pour le matériel graphique, les périphériques USB, les contrôleurs de stockage et les cartes Wi-Fi. Les améliorations visent à assurer une compatibilité plus large et des performances plus stables avec le nouveau matériel.

Conclusion

Le noyau Linux 6.8 est une mise à jour solide qui apporte des améliorations significatives dans de nombreux domaines. Il est recommandé de mettre à jour vers cette version pour bénéficier des dernières fonctionnalités, des optimisations de performances et des correctifs de sécurité.

Ces notes de version sont basées sur les informations disponibles publiquement et peuvent être vérifiées dans le paquet Arch Linux correspondant.
