MPI_Put, MPI_Rput - Copie des données de la mémoire d'origine vers la cible.

PARAMÈTRES D'ENTRÉE

  • origin_addr: Adresse initiale du tampon d'origine (choix).
  • origin_count: Nombre d'entrées dans le tampon d'origine (entier non négatif).
  • origin_datatype: Type de données de chaque entrée dans le tampon d'origine (descripteur).
  • target_rank: Rang de la cible (entier non négatif).
  • target_disp: Décalage par rapport au début de la fenêtre vers le tampon cible (entier non négatif).
  • target_count: Nombre d'entrées dans le tampon cible (entier non négatif).
  • target_datatype: Type de données de chaque entrée dans le tampon cible (descripteur).
  • win: Objet fenêtre utilisé pour la communication (descripteur).

PARAMÈTRE DE SORTIE

  • request: MPI_Rput: Requête RMA
  • ierror: Fortran seulement: Statut d'erreur (entier).

DESCRIPTION

MPI_Put transfère origin_count entrées successives du type spécifié par origin_datatype, commençant à l'adresse origin_addr sur le nœud d'origine, vers le nœud cible spécifié par la paire win, target_rank.

Les données sont écrites dans le tampon cible à l'adresse target_addr ^ window_base + target_disp x disp_unit, où window_base et disp_unit sont l'adresse de base et l'unité de décalage de fenêtre spécifiées lors de l'initialisation de la fenêtre, par le processus cible.

Le tampon cible est spécifié par les arguments target_count et target_datatype.

Le transfert de données est identique à celui qui se produirait si le processus d'origine exécutait une opération d'envoi avec les arguments origin_addr, origin_count, origin_datatype, target_rank, tag, comm, et si le processus cible exécutait une opération de réception avec les arguments target_addr, target_count, target_datatype, source, tag, comm, où target_addr est l'adresse du tampon cible calculée comme expliqué ci-dessus, et comm est un communicateur pour le groupe de win.

La communication doit satisfaire les mêmes contraintes qu'une communication de passage de messages similaire. Le target_datatype ne peut pas spécifier d'entrées qui se chevauchent dans le tampon cible. Le message envoyé doit tenir, sans troncature, dans le tampon cible. De plus, le tampon cible doit tenir dans la fenêtre cible. En outre, seuls les processus au sein du même buffer peuvent accéder à la fenêtre cible.

L'argument target_datatype est un descripteur d'un objet de type de données défini au niveau du processus d'origine. Cependant, cet objet est interprété au niveau du processus cible : le résultat est comme si l'objet de type de données cible était défini au niveau du processus cible, par la même séquence d'appels utilisée pour le définir au niveau du processus d'origine. Le type de données cible ne doit contenir que des décalages relatifs, pas des adresses absolues. Il en va de même pour get et accumulate.

MPI_Rput est similaire à MPI_Put, à la différence qu'il alloue un objet de requête de communication et le lie au descripteur de requête (l'argument request). L'achèvement d'une opération MPI_Rput (c'est-à-dire, après le test ou l'attente correspondant) indique que l'expéditeur est maintenant libre de mettre à jour les emplacements dans le tampon origin_addr. Il n'indique pas que les données sont disponibles dans la fenêtre cible. Si une complétion distante est requise, MPI_Win_flush, MPI_Win_flush_all, MPI_Win_unlock ou MPI_Win_unlock_all peuvent être utilisés.

NOTES

L'argument target_datatype est un descripteur d'un objet de type de données qui est défini au niveau du processus d'origine, même s'il définit une disposition de données dans la mémoire du processus cible. Cela ne pose pas de problème dans un environnement homogène ou hétérogène, tant que seuls des types de données portables sont utilisés (les types de données portables sont définis dans la section 2.4 de la norme MPI-2).

Les performances d'un transfert put peuvent être significativement affectées, sur certains systèmes, par le choix de l'emplacement de la fenêtre et la forme ainsi que l'emplacement du tampon d'origine et cible : les transferts vers une fenêtre cible en mémoire allouée par MPI_Alloc_mem peuvent être beaucoup plus rapides sur les systèmes à mémoire partagée ; les transferts depuis des tampons contigus seront plus rapides sur la plupart des systèmes, voire tous ; l'alignement des tampons de communication peut également avoir un impact sur les performances.

ERREURS

Pratiquement toutes les routines MPI retournent une valeur d'erreur ; les routines C comme résultat de retour de la fonction et les routines Fortran dans le dernier argument.

Avant que la valeur d'erreur ne soit retournée, le gestionnaire d'erreurs MPI courant associé à l'objet de communication (par exemple, communicateur, fenêtre, fichier) est appelé. Si aucun objet de communication n'est associé à l'appel MPI, alors l'appel est considéré comme attaché à MPI_COMM_SELF et appellera le gestionnaire d'erreurs MPI associé. Lorsque MPI_COMM_SELF n'est pas initialisé (c'est-à-dire, avant MPI_Init/MPI_Init_thread, après MPI_Finalize, ou lors de l'utilisation exclusive du modèle Sessions) l'erreur déclenche le gestionnaire d'erreurs initial. Le gestionnaire d'erreurs initial peut être modifié en appelant MPI_Comm_set_errhandler sur MPI_COMM_SELF lors de l'utilisation du modèle World, ou l'argument CLI mpi_initial_errhandler pour mpiexec ou la clé d'info pour MPI_Comm_spawn/MPI_Comm_spawn_multiple. Si aucun autre gestionnaire d'erreurs approprié n'a été défini, alors le gestionnaire d'erreurs MPI_ERRORS_RETURN est appelé pour les fonctions MPI I/O et le gestionnaire d'erreurs MPI_ERRORS_ABORT est appelé pour toutes les autres fonctions MPI.

Open MPI inclut trois gestionnaires d'erreurs prédéfinis qui peuvent être utilisés :

  • MPI_ERRORS_ARE_FATAL Provoque l'arrêt de tous les processus MPI connectés.
  • MPI_ERRORS_ABORT Un gestionnaire d'erreurs qui peut être invoqué sur un communicateur, une fenêtre, un fichier ou une session. Lors de l'appel

NAME

MPI_Abort - Terminate MPI execution.

SYNTAX

C:
int MPI_Abort(MPI_Comm comm, int errorcode)

Fortran:
include 'mpif.h'
integer function MPI_Abort(comm, errorcode)
  integer :: comm, errorcode
end function MPI_Abort

INPUT PARAMETERS

comm
Le communicateur utilisé pour terminer l'exécution (voir la section MPI_Comm_create_errhandler).
errorcode
Le code d'erreur renvoyé à l'environnement d'appel du processus. Ce code d'erreur est renvoyé par la fonction MPI_Abort, et il est également disponible via la fonction MPI_Comm_get_errhandler.

DESCRIPTION

L'appel à MPI_Abort termine toutes les tâches MPI et détruit tous les objets MPI. Il n'y a aucune garantie que toutes les données de la mémoire tampon seront envoyées. Le processus appelant renvoie la valeur errorcode à l'environnement d'appel. Les autres processus du communicateur reçoivent un code d'erreur de terminaison.

Le comportement de MPI_Abort est le même que celui de l'appel de la fonction MPI_Abort avec le code d'erreur approprié sur le communicateur spécifié.

Lorsque vous utilisez un gestionnaire d'erreurs pour un communicateur, un fichier ou une fenêtre, vous devez utiliser les fonctions correspondantes pour créer et définir le gestionnaire d'erreurs. Par exemple:

  • MPI_Comm_create_errhandler puis MPI_Comm_set_errhandler
  • MPI_File_create_errhandler puis MPI_File_set_errhandler
  • MPI_Session_create_errhandler puis MPI_Session_set_errhandler ou à MPI_Session_init
  • MPI_Win_create_errhandler puis MPI_Win_set_errhandler

Nota: MPI ne garantit pas qu'un programme MPI puisse continuer après une erreur.

Voir la section "Error Handling" du standard MPI-3.1 pour plus d'informations.
