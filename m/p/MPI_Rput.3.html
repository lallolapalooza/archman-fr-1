Paramètres d'entrée

  • origin_addr: Adresse du buffer source (pointeur).
  • origin_count: Nombre d'entrées dans le buffer source (entier non négatif).
  • origin_datatype: Type de données de chaque entrée dans le buffer source (handle).
  • target_rank: Rang de la cible (entier non négatif).
  • target_disp: Décalage depuis le début de la fenêtre jusqu'au buffer cible (entier non négatif).
  • target_count: Nombre d'entrées dans le buffer cible (entier non négatif).
  • target_datatype: Type de données de chaque entrée dans le buffer cible (handle).
  • win: Objet fenêtre utilisé pour la communication (handle).

Paramètre de sortie

  • request: Requête MPI_Rput.
  • ierror: Seulement en Fortran : Statut d'erreur (entier).

Description

MPI_Put envoie origin_count entrées consécutives du type spécifié par origin_datatype, commençant à origin_addr sur le nœud source vers la mémoire du nœud cible spécifié par win et target_rank.

Les données sont écrites dans le buffer cible à l'adresse target_addr ^ window_base + target_disp * disp_unit, où window_base et disp_unit sont l'adresse de base et l'unité de décalage de la fenêtre définie par le processus cible.

Le buffer cible est spécifié par les arguments target_count et target_datatype.

Le transfert de données est le même que si le processus source exécutait une opération d'envoi avec les arguments origin_addr, origin_count, origin_datatype, target_rank, tag, comm, et que le processus cible exécutait une opération de réception avec les arguments target_addr, target_count, target_datatype, source, tag, comm, où target_addr est l'adresse du buffer cible calculée comme expliqué ci-dessus, et comm est un communicateur pour le groupe de win.

La communication doit satisfaire les mêmes restrictions qu'une communication de ce type. Le target_datatype ne peut pas spécifier d'entrées qui se chevauchent dans le buffer cible. Le message envoyé doit tenir, sans troncature, dans le buffer cible. De plus, le buffer cible doit tenir dans le buffer cible. En outre, seuls les processus au sein du même buffer peuvent accéder au buffer cible.

Le target_datatype est un handle vers un objet de type de données défini dans le processus source. Cependant, cet objet est interprété dans le processus cible : le résultat est le même que si l'objet de type de données cible était défini dans le processus cible, par la même séquence d'appels que celle utilisée dans le processus source pour le définir. Le type de données cible ne doit contenir que des décalages relatifs, pas des adresses absolues. La même règle s'applique aux opérations get et accumulate.

MPI_Rput est similaire à MPI_Put, mais assigne une requête de communication (l'argument request) à un handle de requête (l'argument request). La fin d'une opération MPI_Rput (c'est-à-dire, après que le test ou l'attente ait réussi) indique que l'expéditeur peut désormais mettre à jour les emplacements dans le buffer origin_addr. Cela n'indique pas que les données sont disponibles dans le buffer cible. Si une attente de complétion distante est nécessaire, on peut utiliser MPI_Win_flush, MPI_Win_flush_all, MPI_Win_unlock, ou MPI_Win_unlock_all.

Notes

Le target_datatype est un handle vers un objet de type de données défini dans le processus source, même s'il définit une disposition de données dans la mémoire du processus cible. Cela ne pose pas de problème dans un environnement homogène ou hétérogène, à condition que des types de données portables soient utilisés (les types de données portables sont définis dans la section 2.4 de la norme MPI-2).

Les performances d'un transfert de données peuvent être considérablement affectées, sur certains systèmes, par le choix de l'emplacement de la fenêtre et par la forme et l'emplacement des buffers source et cible : Les transferts vers un buffer cible dans une fenêtre réservée par MPI_Alloc_mem peuvent être beaucoup plus rapides sur les systèmes à mémoire partagée ; les transferts de buffers consécutifs seront plus rapides sur la plupart des systèmes, même sur de nombreux ; l'alignement des buffers de communication peut également affecter les performances.

Erreurs

La plupart des routines MPI retournent une valeur d'erreur ; dans les routines C, la valeur de retour est le résultat de la fonction, et dans les routines Fortran, le dernier argument est la valeur d'erreur.

Avant que la valeur d'erreur ne soit retournée, le gestionnaire d'erreurs associé à l'objet de communication (par exemple, communicator, window, file) est appelé. S'il n'y a pas d'objet de communication associé à l'appel MPI, l'appel est considéré comme lié à MPI_COMM_SELF et appellera le gestionnaire d'erreurs associé. Lorsque MPI_COMM_SELF n'est pas initialisé (c'est-à-dire, avant MPI_Init/MPI_Init_thread, après MPI_Finalize, ou lorsque le Modèle de Session est utilisé exclusivement), l'erreur élève le gestionnaire d'erreurs initial. Le gestionnaire d'erreurs initial peut être modifié en appelant MPI_Comm_set_errhandler sur MPI_COMM_SELF lors de l'utilisation du Modèle du Monde, ou via l'argument CLI mpi_initial_errhandler de mpiexec ou la clé info de MPI_Comm_spawn/MPI_Comm_spawn_multiple. S'il n'y a pas d'autre gestionnaire d'erreurs approprié, le gestionnaire d'erreurs MPI_ERRORS_RETURN est appelé pour les fonctions d'E/S MPI et le gestionnaire d'erreurs MPI_ERRORS_ABORT est appelé pour toutes les autres fonctions MPI.

Open MPI inclut trois gestionnaires d'erreurs par défaut qui peuvent être utilisés :

  • MPI_ERRORS_ARE_FATAL Provoque l'arrêt du programme de tous les processus MPI connectés.
  • MPI_ERRORS_ABORT Un gestionnaire d'erreurs qui peut être invoqué sur un communicateur

OUTPUT PARAMETER

 
MPI_ERRORS_ARE_FATAL
La plupart des routines MPI retournent un code d'erreur. Si le code d'erreur est MPI_ERRORS_ARE_FATAL, alors lorsque la routine MPI détecte une erreur, tous les processus MPI dans le communicateur sont terminés. Si le code d'erreur est MPI_ERRORS_RETURN, alors lorsque la routine MPI détecte une erreur, la routine retourne le code d'erreur à l'appelant.

DESCRIPTION

La routine MPI_Put transfère des données d'une mémoire source locale vers une mémoire cible distante. C'est une opération unilatérale qui ne nécessite pas d'interaction du processus cible pour compléter le transfert. L'accès à la mémoire distante doit être protégé par des appels à MPI_Win_lock ou MPI_Win_lock_all avant la réception du message, et les verrous doivent être libérés par des appels à MPI_Win_unlock ou MPI_Win_unlock_all.

L'opération MPI_Put est considérée comme terminée côté source lorsque la routine retourne. Cependant, les données ne sont pas garanties d'être disponibles à la destination tant que le processus de destination ne communique pas explicitement son achèvement (par exemple, via une opération d'accumulation ou un appel à MPI_Win_flush).

Le jeu de données de la mémoire cible distante est la portion de la mémoire du processus distant spécifiée par le décalage et le nombre d'éléments dans la fenêtre du processus distant. Les données sont copiées à partir du jeu de données source dans le jeu de données cible.

Les deux routines MPI_Put se comportent de la même manière, sauf que la dernière routine accepte également un argument d'opération MPI_Op. Cette opération sera effectuée sur les données entrantes à la destination.

NOTES

Les opérations unilatérales dans MPI sont destinées à être des opérations à faible latence qui n'impliquent pas un retour d'accusé de réception explicite du processus cible. Cela permet au processus source de continuer son calcul sans attendre que les données soient reçues et traitées par le processus cible.

Il est important de noter que bien que MPI_Put soit une opération non bloquante du point de vue du processus source, elle ne garantit pas que les données soient immédiatement disponibles à la destination. Des appels explicites à MPI_Win_flush ou MPI_Win_flush_all peuvent être nécessaires pour garantir la visibilité des données à la destination.

ERRORS

Au niveau du communicateur par défaut, les erreurs ne sont pas traitées. Les erreurs qui se produisent lors de la réception d'une opération de mise par points dans une fenêtre ne sont pas traitées.

Les gestionnaires d'erreurs suivants peuvent être définis pour MPI_Win:

  • MPI_ERRORS_ARE_FATAL Lorsque MPI_Abort est appelé sur le communicateur.
  • MPI_ERRORS_RETURN Retourne un code d'erreur à l'application.

Les applications MPI peuvent également implémenter leurs propres gestionnaires d'erreurs en appelant :

  • MPI_Comm_create_errhandler puis MPI_Comm_set_errhandler
  • MPI_File_create_errhandler puis MPI_File_set_errhandler
  • MPI_Session_create_errhandler puis MPI_Session_set_errhandler ou à MPI_Session_init
  • MPI_Win_create_errhandler puis MPI_Win_set_errhandler

Notez que MPI ne garantit pas qu'un programme MPI puisse continuer après une erreur.

Voir la page de manuel MPI pour une liste complète des codes d'erreur MPI.

Voir la section Gestion des erreurs de la norme MPI-3.1 pour plus d'informations.
