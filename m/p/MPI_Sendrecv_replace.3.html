MPI_Sendrecv_replace — Envoie et reçoit un message en utilisant un buffer unique.

SYNTAXE

Syntaxe C

#include <mpi.h>
int MPI_Sendrecv_replace(void *buf, int count, MPI_Datatype datatype,
     int dest, int sendtag, int source, int recvtag, MPI_Comm comm,
     MPI_Status *status)

Syntaxe Fortran

USE MPI
! ou l'ancien format : INCLUDE 'mpif.h'
MPI_SENDRECV_REPLACE(BUF, COUNT, DATATYPE, DEST, SENDTAG, SOURCE,
             RECVTAG, COMM, STATUS, IERROR)
     <type>  BUF(*)
     INTEGER COUNT, DATATYPE, DEST, SENDTAG
     INTEGER SOURCE, RECVTAG, COMM
     INTEGER STATUS(MPI_STATUS_SIZE), IERROR

Syntaxe Fortran 2008

USE mpi_f08
MPI_Sendrecv_replace(buf, count, datatype, dest, sendtag, source, recvtag,
             comm, status, ierror)
     TYPE(*), DIMENSION(..) :: buf
     INTEGER, INTENT(IN) :: count, dest, sendtag, source, recvtag
     TYPE(MPI_Datatype), INTENT(IN) :: datatype
     TYPE(MPI_Comm), INTENT(IN) :: comm
     TYPE(MPI_Status) :: status
     INTEGER, OPTIONAL, INTENT(OUT) :: ierror

PARAMETRES ENTREE/SORTIE

•
buf: Adresse initiale du buffer d'envoi et de réception (sortie).

PARAMETRES D'ENTREE

  • count: Nombre d'éléments dans le buffer d'envoi et de réception (entier).
  • datatype: Type des éléments à envoyer et recevoir (handle).
  • dest: Rang du destinataire (entier).
  • sendtag: Étiquette du message à envoyer (entier).
  • source: Rang de la source (entier).
  • recvtag: Étiquette du message à recevoir (entier).
  • comm: Communicateur (handle).

PARAMETRES DE SORTIE

  • status: Objet d'état (état).
  • ierror: Fortran uniquement : État de l'erreur (entier).

DESCRIPTION

Les opérations d'envoi et de réception combinent en un seul appel l'envoi d'un message à un destinataire et la réception d'un autre message d'un autre processus. Les deux (source et destinataire) peuvent être identiques. Une opération d'envoi et de réception est utile pour effectuer une opération de décalage sur une chaîne de processus. Si des envois et réceptions bloquants sont utilisés pour un tel décalage, il faut ordonnancer correctement les envois et les réceptions (par exemple, les processus pairs envoient, puis les processus impairs reçoivent d'abord, puis envoient) afin d'éviter les dépendances cycliques susceptibles de provoquer des blocages. Lorsqu'une opération d'envoi et de réception est utilisée, le sous-système de communication gère ces problèmes. L'opération d'envoi et de réception peut être utilisée conjointement avec les fonctions décrites au chapitre 6 de la norme MPI, « Procéss Topologies », pour effectuer des décalages dans différentes topologies logiques. Elle est également utile pour implémenter des appels distants. Un message envoyé par une opération d'envoi et de réception peut être reçu par une opération de réception normale ou testé par une opération de test ; une opération d'envoi et de réception peut recevoir un message envoyé par une opération d'envoi normale.

MPI_Sendrecv_replace exécute un envoi et une réception bloquants. Le même buffer est utilisé à la fois pour l'envoi et la réception, de sorte que le message envoyé est remplacé par le message reçu.

La sémantique d'une opération d'envoi et de réception est ce que l'on obtiendrait si l'appelant créait deux threads concurrents, l'un pour exécuter l'envoi, l'autre pour exécuter la réception, suivi d'une jointure de ces deux threads.

ERREURS

Presque toutes les routines MPI retournent une valeur d'erreur ; pour les routines C, le résultat de la fonction est la valeur d'erreur ; pour les routines Fortran, le dernier argument est la valeur d'erreur.

Avant de retourner la valeur d'erreur, le gestionnaire d'erreurs associé à l'objet de communication en cours (par exemple, communicateur, fenêtre, fichier) est appelé. S'il n'y a pas d'objet de communication associé à l'appel MPI, l'appel est considéré comme associé à MPI_COMM_SELF et le gestionnaire d'erreurs correspondant est appelé. Lorsque MPI_COMM_SELF n'est pas initialisé (c'est-à-dire avant MPI_Init/MPI_Init_thread, après MPI_Finalize, ou lors de l'utilisation exclusive du modèle de session), l'erreur déclenche le gestionnaire d'erreurs initial. Le gestionnaire d'erreurs initial peut être modifié en appelant MPI_Comm_set_errhandler sur MPI_COMM_SELF lors de l'utilisation du modèle du monde, ou l'argument CLI mpi_initial_errhandler pour mpiexec ou la clé d'information pour MPI_Comm_spawn/MPI_Comm_spawn_multiple. Si aucun autre gestionnaire d'erreurs approprié n'est défini, MPI_ERRORS_RETURN est appelé pour les fonctions MPI d'E/S et MPI_ERRORS_ABORT pour toutes les autres fonctions MPI.

Open MPI inclut trois gestionnaires d'erreurs par défaut qui peuvent être utilisés :

  • MPI_ERRORS_ARE_FATAL: Arrête tous les processus MPI connectés.
  • MPI_ERRORS_ABORT: Un gestionnaire d'erreurs qui peut être invoqué sur un communicateur, une fenêtre, un fichier ou une session. Lorsqu'il est invoqué sur un communicateur, il agit comme si MPI_Abort avait été appelé sur ce communicateur. S'il est invoqué sur une fenêtre ou un fichier, il agit comme si MPI_Abort avait été appelé sur un communicateur contenant le groupe de processus dans la fenêtre ou le fichier correspondant. S'il est invoqué sur une session, il arrête uniquement le processus local.
  • MPI_ERRORS_RETURN: Renvoie un code d'erreur à l'application.

Les applications MPI peuvent également implémenter leurs propres gestionnaires d'erreurs en appelant :

  • MPI_Comm_create_errhandler puis MPI_Comm_set_errhandler
  • MPI_File_create_errhandler puis MPI_File_set_errhandler
  • MPI_Session_create_errhandler puis MPI_Session_set_errhandler ou dans MPI_Session_init
  • MPI_Win_create_errhandler puis MPI_Win_set_errhandler

Remarque : MPI ne garantit pas qu'un programme MPI puisse continuer après une erreur.

Voir la page de manuel MPI pour une liste complète des codes d'erreur MPI.

Voir la section sur la gestion des erreurs de la norme MPI-3.1 pour plus d'informations.

Remarque : Selon la section « Retour d'état » du chapitre « Communication point à point » de la norme MPI, les erreurs sur les messages reçus par MPI_Sendrecv_replace ne définissent pas le champ status.MPI_ERROR dans l'objet d'état retourné. Le code d'erreur est toujours transmis au gestionnaire d'erreurs du backend et peut être retourné à l'appel par la valeur de retour de MPI_Sendrecv_replace si le gestionnaire d'erreurs du backend le retourne. Le gestionnaire d'erreurs par défaut MPI_ERRORS_RETURN présente ce comportement, par exemple.
