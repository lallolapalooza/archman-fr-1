MPI_Type_create_subarray — Crée un type de données décrivant un sous-tableau n-dimensionnel d'un tableau n-dimensionnel.

SYNTAXE

Syntaxe C

#include <mpi.h>
int MPI_Type_create_subarray(int ndims, const int array_of_sizes[],
    const int array_of_subsizes[], const int array_of_starts[],
    int order, MPI_Datatype oldtype, MPI_Datatype *newtype)

Syntaxe Fortran

USE MPI
! Ou l'ancienne forme : INCLUDE 'mpif.h'
MPI_TYPE_CREATE_SUBARRAY(NDIMS, ARRAY_OF_SIZES, ARRAY_OF_SUBSIZES,
     ARRAY_OF_STARTS, ORDER, OLDTYPE, NEWTYPE, IERROR)
     INTEGER NDIMS, ARRAY_OF_SIZES(*), ARRAY_OF_SUBSIZES(*),
     ARRAY_OF_STARTS(*), ORDER, OLDTYPE, NEWTYPE, IERROR

Syntaxe Fortran 2008

USE mpi_f08
MPI_Type_create_subarray(ndims, array_of_sizes, array_of_subsizes,
             array_of_starts, order, oldtype, newtype, ierror)
     INTEGER, INTENT(IN) :: ndims, array_of_sizes(ndims),
     array_of_subsizes(ndims), array_of_starts(ndims), order
     TYPE(MPI_Datatype), INTENT(IN) :: oldtype
     TYPE(MPI_Datatype), INTENT(OUT) :: newtype
     INTEGER, OPTIONAL, INTENT(OUT) :: ierror

PARAMÈTRES D'ENTRÉE

  • ndims: Nombre de dimensions du tableau complet (entier positif).
  • array_of_sizes: Nombre d'éléments du type oldtype dans chaque dimension du tableau complet (tableau d'entiers positifs).
  • array_of_subsizes: Nombre d'éléments du type oldtype dans chaque dimension du sous-tableau (tableau d'entiers positifs).
  • array_of_starts: Coordonnées de début du sous-tableau dans chaque dimension (tableau d'entiers non négatifs).
  • order: Ordre de stockage du sous-tableau (état).
  • oldtype: Type de données des éléments du tableau (handle).

PARAMÈTRES DE SORTIE

  • newtype: Nouveau type de données (handle).
  • ierror: Fortran uniquement : Code d'erreur (entier).

DESCRIPTION

Le constructeur de types de données de sous-tableau crée un type de données MPI qui décrit un sous-tableau n-dimensionnel d'un tableau n-dimensionnel. Le sous-tableau peut être situé n'importe où dans le tableau complet et peut avoir n'importe quelle taille positive, à condition qu'il soit confiné dans ce tableau. Ce constructeur facilite la création de types de données pour accéder à des tableaux répartis par blocs entre processus vers un fichier unique contenant le tableau global.

Ce constructeur peut gérer des tableaux avec n'importe quel nombre de dimensions et fonctionne pour les tableaux ordonnés C et Fortran (c'est-à-dire, tableau par ligne ou par colonne). Note : un programme C peut utiliser l'ordre Fortran et un programme Fortran peut utiliser l'ordre C.

Le paramètre ndims spécifie le nombre de dimensions du tableau complet et donne le nombre d'éléments dans array_of_sizes, array_of_subsizes et array_of_starts.

Le nombre d'éléments du type oldtype dans chaque dimension du tableau n-dimensionnel et du sous-tableau demandé est spécifié par array_of_sizes et array_of_subsizes, respectivement. Pour toute dimension i, il est erroné de spécifier array_of_subsizes[i] < 1 ou array_of_subsizes[i] > array_of_sizes[i].

L'array_of_starts contient les coordonnées de début pour chaque dimension du sous-tableau. Les tableaux sont supposés indexés à partir de zéro. Pour toute dimension i, il est erroné de spécifier

array_of_starts[i] < 0

ou

array_of_starts[i] > (array_of_sizes[i] - array_of_subsizes[i])

Le paramètre order spécifie l'ordre de stockage du sous-tableau ainsi que le tableau complet. Il doit être réglé sur l'un des suivants :

  • MPI_ORDER_C : L'ordre utilisé par les tableaux C (c'est-à-dire, ordre par ligne principal).
  • MPI_ORDER_FORTRAN : L'ordre utilisé par les tableaux Fortran (c'est-à-dire, ordre par colonne principal).

Un sous-tableau ndims-dimensionnel (newtype) sans espaces supplémentaires peut être défini par la fonction Subarray() comme suit :

newtype = Subarray(ndims, {size_0, size_1,..., size_ndims-1},
          {subsize_0, subsize_1, ..., subsize_ndims-1},
          {start_0, start_1, ..., start_ndims-1}, oldtype)

Supposons que le mappage de types de oldtype ait la forme :

{(type_0, disp_0), (type_1, disp_1), ..., (type_n-1, disp_n-1)}

où typei est un type de données MPI prédéfini et soit ex la largeur de oldtype.

La fonction Subarray() est définie récursivement en trois équations à la page 72 de la norme MPI-2.

Pour un exemple d'utilisation de MPI_Type_create_subarray dans le contexte d'E/S, voir la section 9.9.2 de la norme MPI-2.

NOTES

Dans un programme Fortran avec des tableaux indexés à partir de 1, si le début d'une dimension spécifique du sous-tableau est n, alors la valeur dans le tableau des départs pour cette dimension est n-1.

ERREURS

Au-delà des erreurs MPI, les routines C renvoient une valeur d'erreur et les routines Fortran dans le dernier argument.

Avant que la valeur d'erreur ne soit renvoyée, le gestionnaire d'erreurs actuel de l'objet de communication (par exemple, communicateur, fenêtre, fichier) associé est appelé. S'il n'y a pas d'objet de communication associé à l'appel MPI, l'appel est considéré comme associé à MPI_COMM_SELF et le gestionnaire d'erreurs associé à MPI_COMM_SELF est appelé. Lorsque MPI_COMM_SELF n'est pas initialisé (c'est-à-dire, avant MPI_Init/MPI_Init_thread, après MPI_Finalize, ou lorsque le modèle de sessions est utilisé exclusivement), le gestionnaire d'erreurs initial est déclenché. Le gestionnaire d'erreurs initial peut être modifié en appelant MPI_Comm_set_errhandler sur MPI_COMM_SELF lorsque le modèle du Monde est utilisé, ou le paramètre mpi_initial_errhandler de mpiexec, ou la clé info de MPI_Comm_spawn/MPI_Comm_spawn_multiple. S'il n'y a pas d'autre gestionnaire approprié, le gestionnaire d'erreurs MPI_ERRORS_RETURN est appelé pour les fonctions d'E/S MPI et le gestionnaire d'erreurs MPI_ERRORS_ABORT est appelé pour toutes les autres fonctions MPI.

Open MPI comprend trois gestionnaires préconçus qui peuvent être utilisés :

  • MPI_ERRORS_ARE_FATAL : Provoque l'arrêt du programme par tous les processus MPI connectés.
  • MPI_ERRORS_ABORT : Un gestionnaire d'erreurs qui peut être invoqué sur un communicateur, une fenêtre, un fichier ou une session. Lorsqu'il est invoqué sur un communicateur, il agit comme si MPI_Abort avait été appelé sur ce communicateur. S'il est invoqué sur une fenêtre ou un fichier, il agit comme si MPI_Abort avait été appelé sur un communicateur contenant le groupe de processus de la fenêtre ou du fichier correspondant. S'il est invoqué sur une session, il arrête uniquement le processus local.
  • MPI_ERRORS_RETURN : Renvoie un code d'erreur à l'application.

Les applications MPI peuvent également implémenter leurs propres gestionnaires d'erreurs en appelant :

  • MPI_Comm_create_errhandler puis MPI_Comm_set_errhandler
  • MPI_File_create_errhandler puis MPI_File_set_errhandler
  • MPI_Session_create_errhandler puis MPI_Session_set_errhandler ou à MPI_Session_init
  • MPI_Win_create_errhandler puis MPI_Win_set_errhandler

Note : MPI ne garantit pas qu'un programme MPI pourra continuer après une erreur.

Voir la page de manuel MPI pour une liste complète des codes d'erreur MPI.

Voir la section sur la gestion des erreurs de la norme MPI-3.1 pour plus d'informations.
