MPI_DIST_GRAPH_CREATE_ADJACENT(3) Open MPI MPI_DIST_GRAPH_CREATE_ADJACENT(3)

MPI_Dist_graph_create_adjacent — Crée un nouveau communicateur auquel des informations topologiques ont été attachées.

SYNTAX

Syntaxe C

#include <mpi.h>
int MPI_Dist_graph_create_adjacent(MPI_Comm comm_old, int indegree, const int sources[],
     const int sourceweights[], int outdegree, const int destinations[], const int destweights[],
        MPI_Info info, int reorder, MPI_Comm *comm_dist_graph)

Syntaxe Fortran

USE MPI
! ou la forme plus ancienne : INCLUDE 'mpif.h'
MPI_DIST_GRAPH_CREATE_ADJACENT(COMM_OLD, INDEGREE, SOURCES, SOURCEWEIGHTS, OUTDEGREE,
                DESTINATIONS, DESTWEIGHTS, INFO, REORDER, COMM_DIST_GRAPH, IERROR)
     INTEGER COMM_OLD, INDEGREE, SOURCES(*), SOURCEWEIGHTS(*), OUTDEGREE, DESTINATIONS(*), DESTWEIGHTS(*), INFO
     INTEGER COMM_DIST_GRAPH, IERROR
     LOGICAL REORDER

Syntaxe Fortran 2008

USE mpi_f08
MPI_Dist_Graph_create_adjacent(comm_old, ndegree, sources, sourceweights,
             outdegree, destinations, destweights, info, reorder,
             comm_dist_graph, ierror)
     TYPE(MPI_Comm), INTENT(IN) :: comm_old
     INTEGER, INTENT(IN) :: indegree, sources(indegree), outdegree, destinations(outdegree)
     INTEGER, INTENT(IN) :: sourceweights(*), destweights(*)
     TYPE(MPI_Info), INTENT(IN) :: info
     LOGICAL, INTENT(IN) :: reorder
     TYPE(MPI_Comm), INTENT(OUT) :: comm_dist_graph
     INTEGER, OPTIONAL, INTENT(OUT) :: ierror

PARAMÈTRES D'ENTRÉE

  • comm_old : Communicateur d'entrée sans topologie (descripteur).
  • indegree : Taille des tableaux sources et sourceweights (entier non négatif).
  • sources : Rangs des processus pour lesquels le processus appelant est une destination (tableau d'entiers non négatifs).
  • sourceweights : Poids des arêtes entrantes vers le processus appelant (tableau d'entiers non négatifs).
  • outdegree : Taille des tableaux destinations et destweights (entier non négatif).
  • destinations : Rangs des processus pour lesquels le processus appelant est une source (tableau d'entiers non négatifs).
  • destweights : Poids des arêtes sortantes du processus appelant (tableau d'entiers non négatifs).
  • info : Indices pour l'optimisation et l'interprétation des poids (descripteur).
  • reorder : Le re-rangement des processus peut être réordonné (vrai) ou non (faux) (booléen).

PARAMÈTRES DE SORTIE

  • comm_dist_graph : Communicateur avec une topologie de graphe distribuée ajoutée (descripteur).
  • ierror : Uniquement en Fortran : statut d'erreur (entier).

DESCRIPTION

MPI_Dist_graph_create_adjacent crée un nouveau communicateur comm_dist_graph avec une topologie de graphe distribuée et renvoie un descripteur vers le nouveau communicateur. Le nombre de processus dans comm_dist_graph est identique au nombre de processus dans comm_old. Chaque processus passe toutes les informations sur ses arêtes entrantes et sortantes dans la topologie de graphe distribuée virtuelle. Les processus appelants doivent s'assurer que chaque arête du graphe est décrite dans le processus source et dans le processus de destination avec les mêmes poids. S'il existe plusieurs arêtes pour une paire (source, destination) donnée, alors la séquence des poids de ces arêtes n'a pas d'importance. La topologie de communication complète est la combinaison de toutes les arêtes indiquées dans les tableaux sources de tous les processus de comm_old, qui doit être identique à la combinaison de toutes les arêtes indiquées dans les tableaux destinations. Les rangs source et destination doivent être des rangs de processus de comm_old. Cela permet une spécification entièrement distribuée du graphe de communication. Les processus isolés (c'est-à-dire les processus sans arêtes sortantes ou entrantes, c'est-à-dire les processus qui ont spécifié indegree et outdegree comme zéro et qui n'apparaissent donc pas comme rang source ou destination dans la spécification du graphe) sont autorisés. L'appel à MPI_Dist_graph_create_adjacent est collectif.

POIDS

Les poids sont spécifiés comme des entiers non négatifs et peuvent être utilisés pour influencer la stratégie de remappage des processus et d'autres optimisations internes de MPI. Par exemple, les dénombrements approximatifs des appels de communication ultérieurs le long d'arêtes spécifiques pourraient être utilisés comme leurs poids d'arête. La multiplicité des arêtes peut également indiquer une communication plus intense entre les paires de processus. Cependant, la signification exacte des poids d'arête n'est pas spécifiée par la norme MPI et est laissée à l'implémentation. Une application peut fournir la valeur spéciale MPI_UNWEIGHTED pour le tableau de poids afin d'indiquer que toutes les arêtes ont le même poids (effectivement aucun). Il est erroné de fournir MPI_UNWEIGHTED pour certains mais pas pour tous les processus de comm_old. Si le graphe est pondéré mais que indegree ou outdegree est zéro, alors MPI_WEIGHTS_EMPTY ou n'importe quel tableau arbitraire peut être passé à sourceweights ou destweights respectivement. Notez que MPI_UNWEIGHTED et MPI_WEIGHTS_EMPTY ne sont pas des valeurs de poids spéciales ; ce sont plutôt des valeurs spéciales pour l'argument de tableau total. En Fortran, MPI_UNWEIGHTED et MPI_WEIGHTS_EMPTY sont des objets comme MPI_BOTTOM (non utilisables pour l'initialisation ou l'affectation). Voir la section 2.5.4 de MPI-3.

ERREURS

Presque toutes les routines MPI renvoient une valeur d'erreur ; les routines C comme résultat de retour de la fonction et les routines Fortran dans le dernier argument.

Avant que la valeur d'erreur ne soit renvoyée, le gestionnaire d'erreurs MPI actuellement associé à l'objet de communication (par exemple, communicateur, fenêtre, fichier) est appelé. Si aucun objet de communication n'est associé à l'appel MPI, alors l'appel est considéré comme attaché à MPI_COMM_SELF et appellera le gestionnaire d'erreurs MPI associé. Lorsque MPI_COMM_SELF n'est pas initialisé (c'est-à-dire avant MPI_Init/MPI_Init_thread, après MPI_Finalize, ou lors de l'utilisation exclusive du modèle Sessions), l'erreur déclenche le gestionnaire d'erreurs initial. Le gestionnaire d'erreurs initial peut être modifié en appelant MPI_Comm_set_errhandler sur MPI_COMM_SELF lors de l'utilisation du modèle World, ou via l'argument de ligne de commande mpi_initial_errhandler à mpiexec ou la clé d'information à MPI_Comm_spawn/MPI_Comm_spawn_multiple. Si aucun autre gestionnaire d'erreurs approprié n'a été défini, alors le gestionnaire d'erreurs MPI_ERRORS_RETURN est appelé pour les fonctions d'E/S MPI et le gestionnaire d'erreurs MPI_ERRORS_ABORT est appelé pour toutes les autres fonctions MPI.

Open MPI inclut trois gestionnaires d'erreurs prédéfinis qui peuvent être utilisés :

  • MPI_ERRORS_ARE_FATAL Provoque l'arrêt du programme pour tous les processus MPI connectés.
  • MPI_ERRORS_ABORT Un gestionnaire d'erreurs qui peut être invoqué sur un communicateur, une fenêtre, un fichier ou une session. Lorsqu'il est appelé sur un communicateur, il agit comme si MPI_Abort avait été appelé sur ce communicateur. S'il est appelé sur une fenêtre ou un fichier, il agit comme si MPI_Abort avait été appelé sur un communicateur comprenant le groupe de processus dans la fenêtre ou le fichier correspondant. S'il est appelé sur une session, il n'arrête que le processus local.
  • MPI_ERRORS_RETURN Renvoie un code d'erreur à l'application.

Les applications MPI peuvent également implémenter leurs propres gestionnaires d'erreurs en appelant :

  • MPI_Comm_create_errhandler puis MPI_Comm_set_errhandler
  • MPI_File_create_errhandler puis MPI_File_set_errhandler
  • MPI_Session_create_errhandler puis MPI_Session_set_errhandler ou lors de MPI_Session_init
  • MPI_Win_create_errhandler puis MPI_Win_set_errhandler

Notez que MPI ne garantit pas qu'un programme MPI puisse continuer après une erreur.

Voir la page man MPI pour une liste complète des codes d'erreur MPI.

Voir la section Gestion des erreurs de la norme MPI-3.1 pour plus d'informations.
