PARAMÈTRES ENTRANTS

  • sendbuf: Adresse de départ du tampon d'envoi (choix).
  • recvcount: Nombre d'éléments par bloc (entier non négatif).
  • datatype: Type des éléments du tampon d'entrée (descripteur).
  • op: Opération (descripteur).
  • comm: Communicateur (descripteur).
  • info: Informations (descripteur, persistant uniquement).

PARAMÈTRES SORTANTS

  • recvbuf: Adresse de départ du tampon de réception (choix).
  • request: Requête (descripteur, non bloquant seulement).
  • ierror: Fortran seulement : Statut d'erreur (entier).

DESCRIPTION

MPI_Reduce_scatter_block effectue d'abord une réduction élément par élément sur le vecteur de count = n * recvcount éléments du tampon d'envoi défini par sendbuf, count et datatype, en utilisant l'opération op, où n est le nombre de processus du groupe de comm. Ensuite, le vecteur de résultats résultant est divisé en n segments disjoints, où n est le nombre de processus du groupe. Chaque segment contient recvcount éléments. Le i-ème segment est envoyé au processus i et stocké dans le tampon de réception défini par recvbuf, recvcount et datatype.

UTILISATION DE L'OPTION IN-PLACE

Lorsque le communicateur est un intracommunicateur, vous pouvez effectuer une opération de réduction-dispersion "in-place" (le tampon de sortie est utilisé comme tampon d'entrée). Utilisez la variable MPI_IN_PLACE comme valeur de sendbuf. Dans ce cas, les données d'entrée sont prises en haut du tampon de réception. La zone occupée par les données d'entrée peut être plus longue ou plus courte que les données remplies par les données de sortie.

QUAND LE COMMUNICATEUR EST UN INTER-COMMUNICATEUR

Lorsque le communicateur est un inter-communicateur, l'opération de réduction-dispersion se déroule en deux phases. D'abord, le résultat de la réduction effectuée sur les données fournies par les processus du premier groupe est dispersé parmi les processus du second groupe. Ensuite, l'inverse se produit : la réduction effectuée sur les données fournies par les processus du second groupe est dispersée parmi les processus du premier groupe. Pour chaque groupe, tous les processus fournissent le même argument recvcounts, et la somme des valeurs de recvcounts doit être la même pour les deux groupes.

NOTES SUR LES OPÉRATIONS COLLECTIVES

Les fonctions de réduction ( MPI_Op ) ne retournent pas de valeur d'erreur. Par conséquent, si les fonctions détectent une erreur, tout ce qu'elles peuvent faire est soit d'appeler MPI_Abort, soit d'ignorer silencieusement le problème. Ainsi, si vous changez le gestionnaire d'erreur de MPI_ERRORS_ARE_FATAL à autre chose, par exemple, MPI_ERRORS_RETURN, aucune erreur ne pourra être indiquée.

La raison en est les problèmes de performance pour s'assurer que toutes les routines collectives retournent la même valeur d'erreur.

ERREURS

Presque toutes les routines MPI retournent une valeur d'erreur ; les routines C comme résultat de la fonction et les routines Fortran dans le dernier argument.

Avant que la valeur d'erreur ne soit retournée, le gestionnaire d'erreurs MPI actuel associé à l'objet de communication (par exemple, communicateur, fenêtre, fichier) est appelé. S'il n'y a pas d'objet de communication associé à l'appel MPI, alors l'appel est considéré comme attaché à MPI_COMM_SELF et appellera le gestionnaire d'erreurs MPI associé. Lorsque MPI_COMM_SELF n'est pas initialisé (c'est-à-dire, avant MPI_Init/MPI_Init_thread, après MPI_Finalize, ou lors de l'utilisation exclusive du modèle de Sessions), l'erreur déclenche le gestionnaire d'erreurs initial. Le gestionnaire d'erreurs initial peut être modifié en appelant MPI_Comm_set_errhandler sur MPI_COMM_SELF lors de l'utilisation du modèle World, ou par l'argument de ligne de commande mpi_initial_errhandler de mpiexec ou la clé d'information de MPI_Comm_spawn/MPI_Comm_spawn_multiple. Si aucun autre gestionnaire d'erreurs approprié n'a été défini, alors le gestionnaire d'erreurs MPI_ERRORS_RETURN est appelé pour les fonctions d'E/S MPI et le gestionnaire d'erreurs MPI_ERRORS_ABORT est appelé pour toutes les autres fonctions MPI.

Open MPI inclut trois gestionnaires d'erreurs prédéfinis qui peuvent être utilisés :

  • MPI_ERRORS_ARE_FATAL Provoque l'abandon de tous les processus MPI connectés.
  • MPI_ERRORS_ABORT Un gestionnaire d'erreurs qui peut être invoqué sur un communicateur, une fenêtre, un fichier ou une session. Lorsqu'il est appelé sur un communicateur, il agit comme si MPI_Abort était appelé sur ce communicateur. S'il est appelé sur une fenêtre ou un fichier, agit comme si MPI_Abort avait été appelé sur un communicateur contenant le groupe de processus de la fenêtre ou du fichier correspondant. S'il est appelé sur une session, il n'interrompt que le processus local.
  • MPI_ERRORS_RETURN Retourne un code d'erreur à l'application.

Les applications MPI peuvent également implémenter leurs propres gestionnaires d'erreurs en appelant :

  • MPI_Comm_create_errhandler puis MPI_Comm_set_errhandler
  • MPI_File_create_errhandler puis MPI_File_set_errhandler
    • MPI_Session_create_errhandler puis MPI_Session_set_errhandler ou lors de MPI_Session_init
    • MPI_Win_create_errhandler puis MPI_Win_set_errhandler

Notez que MPI ne garantit pas qu'un programme MPI puisse continuer au-delà d'une erreur.

Voir la page de manuel MPI pour une liste complète des codes d'erreur MPI.

Voir la section Gestion des erreurs de la norme MPI-3.1 pour plus d'informations.
