Paquet: openmpi

MPIX_COMM_GET_FAILED(3) Open MPI MPIX_COMM_GET_FAILED(3)

MPIX_Comm_get_failed - Obtenir un groupe listant les processus défaillants dans un communicateur.

Ceci fait partie de l'extension ULFM (User Level Fault Mitigation) du niveau utilisateur.

SYNTAXE

Syntaxe C

#include <mpi.h>
#include <mpi-ext.h>
int MPIX_Comm_get_failed(MPI_Comm comm, MPI_Group *failedgrp)

Syntaxe Fortran

USE MPI
USE MPI_EXT
! ou la forme plus ancienne : INCLUDE 'mpif.h'
MPIX_COMM_GET_FAILED(COMM, FAILEDGRP, IERROR)
     INTEGER COMM, FAILEDGRP, IERROR

Syntaxe Fortran 2008

USE mpi_f08
USE mpi_ext_f08
MPIX_Comm_get_failed(comm, failedgrp, ierror)
     TYPE(MPI_Comm), INTENT(IN) :: comm
     TYPE(MPI_Group), INTENT(OUT) :: failedgrp
     INTEGER, OPTIONAL, INTENT(OUT) :: ierror

PARAMÈTRES ENTRÉE

•
comm: Communicateur (descripteur).

PARAMÈTRES SORTIE

  • failedgrp: Groupe (descripteur).
  • ierror: Fortran seulement : Statut d'erreur (entier).

DESCRIPTION

Cette opération locale retourne le groupe failedgrp des processus du communicateur comm qui sont localement connus comme ayant échoué. Le failedgrp peut être vide, c'est-à-dire égal à MPI_GROUP_EMPTY.

Pour deux groupes quelconques obtenus à partir d'appels à cette routine sur le même processus MPI, avec le même comm, l'intersection du plus grand groupe avec le plus petit groupe est MPI_IDENT au plus petit groupe, c'est-à-dire que les mêmes processus ont les mêmes rangs dans les deux groupes, jusqu'à la taille du plus petit groupe.

DÉFAILLANCES PROCESSUS

MPI ne fait aucune hypothèse sur la progression asynchrone de la détection des défaillances. Une implémentation MPI valide peut choisir de mettre à jour le groupe des processus MPI défaillants connus localement uniquement lorsqu'elle entre dans une fonction qui doit déclencher une erreur de tolérance aux fautes.

Il est possible que seul le processus MPI appelant ait détecté la défaillance signalée. Si une connaissance globale est nécessaire, les processus MPI détectant les défaillances devraient appeler MPIX_Comm_revoke pour forcer une erreur sur les autres rangs.

QUAND LE COMMUNICATEUR EST UN INTER-COMMUNICATEUR

Lorsque le communicateur est un inter-communicateur, la valeur de failedgrp contient les membres connus pour avoir échoué dans les groupes locaux et distants de comm.

ERREURS

Presque toutes les routines MPI retournent une valeur d'erreur ; les routines C comme résultat de la fonction et les routines Fortran dans le dernier argument.

Avant que la valeur d'erreur ne soit retournée, le gestionnaire d'erreurs MPI actuellement associé à l'objet de communication (par exemple, communicateur, fenêtre, fichier) est appelé. S'il n'y a pas d'objet de communication associé à l'appel MPI, alors l'appel est considéré comme attaché à MPI_COMM_SELF et appellera le gestionnaire d'erreurs MPI associé. Lorsque MPI_COMM_SELF n'est pas initialisé (c'est-à-dire avant MPI_Init/MPI_Init_thread, après MPI_Finalize, ou lors de l'utilisation exclusivement du modèle de sessions) l'erreur déclenche le gestionnaire d'erreurs initial. Le gestionnaire d'erreurs initial peut être modifié en appelant MPI_Comm_set_errhandler sur MPI_COMM_SELF lors de l'utilisation du modèle World, ou par l'argument de ligne de commande mpi_initial_errhandler de mpiexec ou par la clé d'information de MPI_Comm_spawn/MPI_Comm_spawn_multiple. Si aucun autre gestionnaire d'erreurs approprié n'a été défini, alors le gestionnaire d'erreurs MPI_ERRORS_RETURN est appelé pour les fonctions d'E/S MPI et le gestionnaire d'erreurs MPI_ERRORS_ABORT est appelé pour toutes les autres fonctions MPI.

Open MPI inclut trois gestionnaires d'erreurs prédéfinis qui peuvent être utilisés :

  • MPI_ERRORS_ARE_FATAL Provoque l'arrêt du programme pour tous les processus MPI connectés.
  • MPI_ERRORS_ABORT Un gestionnaire d'erreurs qui peut être invoqué sur un communicateur, une fenêtre, un fichier ou une session. Lorsqu'il est appelé sur un communicateur, il agit comme si MPI_Abort avait été appelé sur ce communicateur. S'il est appelé sur une fenêtre ou un fichier, il agit comme si MPI_Abort avait été appelé sur un communicateur contenant le groupe des processus de la fenêtre ou du fichier correspondant. S'il est appelé sur une session, il n'arrête que le processus local.
  • MPI_ERRORS_RETURN Retourne un code d'erreur à l'application.

Les applications MPI peuvent également implémenter leurs propres gestionnaires d'erreurs en appelant :

  • MPI_Comm_create_errhandler puis MPI_Comm_set_errhandler
  • MPI_File_create_errhandler puis MPI_File_set_errhandler
  • MPI_Session_create_errhandler puis MPI_Session_set_errhandler ou lors de MPI_Session_init
  • MPI_Win_create_errhandler puis MPI_Win_set_errhandler

Notez que MPI ne garantit pas qu'un programme MPI puisse continuer après une erreur.

Voir la page man MPI pour une liste complète des codes d'erreur MPI.

Voir la section Gestion des erreurs de la norme MPI-3.1 pour plus d'informations.
