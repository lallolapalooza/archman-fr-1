MPI_Recv_init — Construit un handle pour une réception.

SYNTAXE

Syntaxe C

#include <mpi.h>
int MPI_Recv_init(void *buf, int count, MPI_Datatype datatype,
     int source, int tag, MPI_Comm comm, MPI_Request *request)

Syntaxe Fortran

USE MPI
! ou la forme plus ancienne : INCLUDE 'mpif.h'
MPI_RECV_INIT(BUF, COUNT, DATATYPE, SOURCE, TAG, COMM, REQUEST,
             IERROR)
     <type>  BUF(*)
     INTEGER COUNT, DATATYPE, SOURCE, TAG, COMM, REQUEST, IERROR

Syntaxe Fortran 2008

USE mpi_f08
MPI_Recv_init(buf, count, datatype, source, tag, comm, request, ierror)
     TYPE(*), DIMENSION(..), ASYNCHRONOUS :: buf
     INTEGER, INTENT(IN) :: count, source, tag
     TYPE(MPI_Datatype), INTENT(IN) :: datatype
     TYPE(MPI_Comm), INTENT(IN) :: comm
     TYPE(MPI_Request), INTENT(OUT) :: request
     INTEGER, OPTIONAL, INTENT(OUT) :: ierror

PARAMÈTRES D'ENTRÉE

  • count: Nombre maximum d'éléments à recevoir (entier).
  • datatype: Type de chaque entrée (handle).
  • source: Rang de la source (entier).
  • tag: Tag du message (entier).
  • comm: Communicateur (handle).

PARAMÈTRE ENTRÉE/SORTIE

•
buf: Adresse initiale du tampon de réception (choix).

PARAMÈTRES DE SORTIE

  • request: Requête de communication (handle).
  • ierror: Fortran uniquement : Statut d'erreur (entier).

DESCRIPTION

Crée une requête de communication persistante pour une opération de réception. L'argument buf est marqué comme SORTIE car l'utilisateur donne la permission d'écrire sur le tampon de réception en passant l'argument à MPI_Recv_init.

Une requête de communication persistante est inactive après sa création — aucune communication active n'est attachée à la requête.

Une communication (envoi ou réception) qui utilise une requête persistante est initiée par la fonction MPI_Start ou MPI_Startall.

ERREURS

Presque toutes les routines MPI retournent une valeur d'erreur ; les routines C comme résultat de la fonction et les routines Fortran dans le dernier argument.

Avant que la valeur d'erreur ne soit retournée, le gestionnaire d'erreur MPI actuel associé à l'objet de communication (par exemple, communicateur, fenêtre, fichier) est appelé. Si aucun objet de communication n'est associé à l'appel MPI, alors l'appel est considéré comme attaché à MPI_COMM_SELF et appellera le gestionnaire d'erreur MPI associé. Lorsque MPI_COMM_SELF n'est pas initialisé (c'est-à-dire avant MPI_Init/ MPI_Init_thread, après MPI_Finalize, ou lors de l'utilisation exclusive du modèle de sessions) l'erreur déclenche le gestionnaire d'erreur initial. Le gestionnaire d'erreur initial peut être modifié en appelant MPI_Comm_set_errhandler sur MPI_COMM_SELF lors de l'utilisation du modèle World, ou via l'argument CLI mpi_initial_errhandler de mpiexec ou la clé d'information de MPI_Comm_spawn/MPI_Comm_spawn_multiple. Si aucun autre gestionnaire d'erreur approprié n'a été défini, alors le gestionnaire d'erreur MPI_ERRORS_RETURN est appelé pour les fonctions d'E/S MPI et le gestionnaire d'erreur MPI_ERRORS_ABORT est appelé pour toutes les autres fonctions MPI.

Open MPI inclut trois gestionnaires d'erreurs prédéfinis qui peuvent être utilisés :

  • MPI_ERRORS_ARE_FATAL Provoque l'interruption de tous les processus MPI connectés par le programme.
  • MPI_ERRORS_ABORT Un gestionnaire d'erreurs qui peut être invoqué sur un communicateur, une fenêtre, un fichier ou une session. Lorsqu'il est appelé sur un communicateur, il agit comme si MPI_Abort avait été appelé sur ce communicateur. S'il est appelé sur une fenêtre ou un fichier, il agit comme si MPI_Abort avait été appelé sur un communicateur contenant le groupe des processus dans la fenêtre ou le fichier correspondant. S'il est appelé sur une session, il n'interrompt que le processus local.
  • MPI_ERRORS_RETURN Retourne un code d'erreur à l'application.

Les applications MPI peuvent également implémenter leurs propres gestionnaires d'erreurs en appelant :

  • MPI_Comm_create_errhandler puis MPI_Comm_set_errhandler
  • MPI_File_create_errhandler puis MPI_File_set_errhandler
  • MPI_Session_create_errhandler puis MPI_Session_set_errhandler ou à MPI_Session_init
  • MPI_Win_create_errhandler puis MPI_Win_set_errhandler

Notez que MPI ne garantit pas qu'un programme MPI puisse continuer après une erreur.

Voir la page man MPI pour une liste complète des codes d'erreur MPI.

Voir la section Gestion des erreurs de la norme MPI-3.1 pour plus d'informations.
