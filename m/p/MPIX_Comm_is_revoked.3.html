MPIX_Comm_is_revoked - Vérifie si un communicateur est révoqué.

Ceci fait partie de l'extension de mitigation des erreurs au niveau utilisateur ULFM.

Syntaxe

Syntaxe C

#include <mpi.h>
#include <mpi-ext.h>
int MPIX_Comm_is_revoked(MPI_Comm comm, int *flag)

Syntaxe Fortran

USE MPI
USE MPI_EXT
! ou l'ancienne forme : INCLUDE 'mpif.h'
MPIX_COMM_IS_REVOKED(COMM, FLAG, IERROR)
     INTEGER COMM, IERROR
     LOGICAL FLAG

Syntaxe Fortran 2008

USE mpi_f08
USE mpi_ext_f08
MPIX_Comm_is_revoked(comm, flag, ierror)
     TYPE(MPI_Comm), INTENT(IN) :: comm
     LOGICAL, INTENT(OUT) :: flag
     INTEGER, OPTIONAL, INTENT(OUT) :: ierror

Paramètres d'entrée

•
comm: Communicateur (handle).

Paramètres de sortie

  • flag: Vrai si le communicateur est révoqué.
  • ierror: Fortran uniquement : État d'erreur (entier).

Description

Renvoie flag = true si le communicateur associé au handle comm est révoqué sur le processus local. Renvoie flag = false sinon. L'opération est locale.

Comment un communicateur peut devenir révoqué

Un communicateur peut devenir révoqué lorsque

1.
l'utilisateur appelle la procédure MPIX_Comm_revoke sur comm pour révoquer le communicateur sur le processus local ;
2.
une opération MPI déclenche l'erreur de classe MPIX_ERR_REVOKED parce qu'un autre processus a appelé la procédure MPIX_Comm_revoke sur comm ;
3.
le communicateur a la clé d'information mpi_error_range définie sur group ou universe, dans lequel l'échec de tout processus dans, respectivement, le groupe de comm ou l'univers MPI a provoqué une opération d'erreur de classe MPIX_ERR_REVOKED.

Propagation et ordre de la révocation

Note : Dans une application multithreadée, un thread appelant MPIX_Comm_is_revoked peut retourner flag = true avant que l'erreur de classe MPIX_ERR_REVOKED de la première exception ne se termine dans un thread concurrent.

Effet de la révocation d'un communicateur

Une fois qu'un communicateur a été révoqué sur un processus MPI, toutes les opérations ultérieures sur celui-ci (sauf quelques exceptions mentionnées) sont considérées comme locales et doivent se terminer en déclenchant une erreur de classe MPIX_ERR_REVOKED sur ce processus MPI.

Opérations sur un communicateur révoqué

Les opérations suivantes ne déclenchent jamais d'erreur de classe MPIX_ERR_REVOKED et se terminent avec leur sémantique normale sur un communicateur révoqué.

  • MPIX_Comm_agree
  • MPIX_Comm_iagree
  • MPIX_Comm_shrink
  • MPIX_Comm_ishrink

Erreurs

La plupart des routines MPI renvoient une valeur d'erreur ; en C, c'est la valeur de retour de la fonction et en Fortran, c'est le dernier argument.

Avant de renvoyer la valeur d'erreur, le gestionnaire d'erreur associé à l'objet de communication (par exemple, communicateur, fenêtre, fichier) actuel est appelé. S'il n'y a pas d'objet de communication associé à l'appel MPI, l'appel est considéré comme associé à MPI_COMM_SELF et appelle le gestionnaire d'erreur associé.

Si MPI_COMM_SELF n'est pas initialisé (c'est-à-dire avant MPI_Init/MPI_Init_thread, après MPI_Finalize, ou lorsque le modèle de sessions est utilisé exclusivement), l'erreur déclenche le gestionnaire d'erreur initial. Le gestionnaire d'erreur initial peut être modifié en appelant MPI_Comm_set_errhandler sur MPI_COMM_SELF lors de l'utilisation du modèle du monde, ou via l'argument mpi_initial_errhandler de mpiexec ou la clé d'information de MPI_Comm_spawn/MPI_Comm_spawn_multiple. S'il n'y a pas d'autre gestionnaire d'erreur approprié, le gestionnaire d'erreur MPI_ERRORS_RETURN est appelé pour les fonctions d'E/S MPI et le gestionnaire d'erreur MPI_ERRORS_ABORT pour les autres fonctions MPI.

Open MPI inclut trois gestionnaires d'erreurs par défaut qui peuvent être utilisés :

  • MPI_ERRORS_ARE_FATAL : Provoque l'abandon de tous les processus MPI connectés par le programme.
  • MPI_ERRORS_ABORT : Un gestionnaire d'erreur qui peut être appelé sur un communicateur, une fenêtre, un fichier ou une session. Lorsqu'il est appelé sur un communicateur, il agit comme si MPI_Abort avait été appelé sur ce communicateur. S'il est appelé sur une fenêtre ou un fichier, il agit comme si MPI_Abort avait été appelé sur un communicateur contenant le groupe de processus dans la fenêtre ou le fichier correspondant. S'il est appelé sur une session, il n'aborte que le processus local.
  • MPI_ERRORS_RETURN : Renvoie un code d'erreur à l'application.

Les programmes MPI peuvent également implémenter leurs propres gestionnaires d'erreurs en appelant :

  • MPI_Comm_create_errhandler puis MPI_Comm_set_errhandler
  • MPI_File_create_errhandler puis MPI_File_set_errhandler
  • MPI_Session_create_errhandler puis MPI_Session_set_errhandler ou dans MPI_Session_init
  • MPI_Win_create_errhandler puis MPI_Win_set_errhandler

Note : MPI ne garantit pas qu'un programme MPI puisse continuer après une erreur.

Voir la page de manuel de MPI pour une liste complète des codes d'erreur MPI.

Voir la section sur la gestion des erreurs de la norme MPI-3.1 pour plus d'informations.

MPIX_Comm_is_revoked — Test if a communicator has been revoked

SYNTAX 

int MPIX_Comm_is_revoked(MPI_Comm comm);

PARAMETERS

comm
A communicator.

DESCRIPTION

MPIX_Comm_is_revoked tests if the communicator comm has been revoked. If the communicator has been revoked, the function returns 1. Otherwise, it returns 0. The communicator comm must be a valid communicator handle.

RETURN VALUE

MPIX_Comm_is_revoked returns 1 if the communicator has been revoked, and 0 otherwise.

NOTES

This function is part of the MPIX extensions. It is not part of the standard MPI specification.

A communicator is revoked when MPIX_Comm_revoke is called on it. After a communicator is revoked, any operations on it will result in an error.

EFFECT OF A COMMUNICATOR REVOCATION

When a communicator is revoked, all subsequent operations on that communicator, including MPIX_Comm_is_revoked itself, will result in an error. The only exception is MPI_Comm_free, which can still be called on a revoked communicator.

OPERATIONS ON A REVOKED COMMUNICATOR

Any operation on a revoked communicator, except for MPI_Comm_free, will return an error. The specific error code will depend on the MPI implementation.

ERRORS

If the communicator comm is not a valid communicator handle, the behavior is undefined.

If the communicator comm has been revoked, the behavior is undefined, except for MPI_Comm_free.

MPIX_Comm_is_revoked(3)

MPIX_Comm_is_revoked — Tester si un communicateur a été révoqué

SYNTAXE 

int MPIX_Comm_is_revoked(MPI_Comm comm);

PARAMÈTRES

comm
Un communicateur.

DESCRIPTION

MPIX_Comm_is_revoked teste si le communicateur comm a été révoqué. Si le communicateur a été révoqué, la fonction retourne 1. Sinon, elle retourne 0. Le communicateur comm doit être une poignée de communicateur valide.

VALEUR DE RETOUR

MPIX_Comm_is_revoked retourne 1 si le communicateur a été révoqué, et 0 sinon.

NOTES

Cette fonction fait partie des extensions MPIX. Elle ne fait pas partie de la spécification MPI standard.

Un communicateur est révoqué lorsque MPIX_Comm_revoke est appelé sur celui-ci. Après qu'un communicateur a été révoqué, toute opération sur celui-ci entraînera une erreur.

EFFET DE LA RÉVOCATION D'UN COMMUNICATEUR

Lorsqu'un communicateur est révoqué, toutes les opérations ultérieures sur ce communicateur, y compris MPIX_Comm_is_revoked lui-même, entraîneront une erreur. La seule exception est MPI_Comm_free, qui peut toujours être appelée sur un communicateur révoqué.

OPÉRATIONS SUR UN COMMUNICATEUR RÉVOQUÉ

Toute opération sur un communicateur révoqué, à l'exception de MPI_Comm_free, retournera une erreur. Le code d'erreur spécifique dépendra de l'implémentation MPI.

ERREURS

Si le communicateur comm n'est pas une poignée de communicateur valide, le comportement est indéfini.

Si le communicateur comm a été révoqué, le comportement est indéfini, à l'exception de MPI_Comm_free.
