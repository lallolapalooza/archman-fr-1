MPI_Win_allocate_shared(3) Open MPI MPI_Win_allocate_shared(3)

MPI_Win_allocate_shared — appel MPI unidirectionnel qui alloue de la mémoire partagée et retourne un objet fenêtre pour les opérations RMA.

SYNTAXE

Syntaxe C

#include <mpi.h>
int MPI_Win_allocate_shared (MPI_Aint size, int disp_unit, MPI_Info info,
                             MPI_Comm comm, void *baseptr, MPI_Win *win)

Syntaxe Fortran

USE MPI
! ou l'ancienne forme : INCLUDE 'mpif.h'
MPI_WIN_ALLOCATE_SHARED(SIZE, DISP_UNIT, INFO, COMM, BASEPTR, WIN, IERROR)
     INTEGER(KIND=MPI_ADDRESS_KIND) SIZE, BASEPTR
     INTEGER DISP_UNIT, INFO, COMM, WIN, IERROR

Syntaxe Fortran 2008

USE mpi_f08
MPI_Win_allocate_shared(size, disp_unit, info, comm, baseptr, win, ierror)
     USE, INTRINSIC :: ISO_C_BINDING, ONLY : C_PTR
     INTEGER(KIND=MPI_ADDRESS_KIND), INTENT(IN) :: size
     INTEGER, INTENT(IN) :: disp_unit
     TYPE(MPI_Info), INTENT(IN) :: info
     TYPE(MPI_Comm), INTENT(IN) :: comm
     TYPE(C_PTR), INTENT(OUT) :: baseptr
     TYPE(MPI_Win), INTENT(OUT) :: win
     INTEGER, OPTIONAL, INTENT(OUT) :: ierror

PARAMÈTRES ENTRÉE

  • size: Taille de la fenêtre en octets (entier non négatif).
  • disp_unit: Unité de taille pour les déplacements locaux, en octets (entier positif).
  • info: Argument d'info (handle).
  • comm: Communicateur (handle).

PARAMÈTRES SORTIE

  • baseptr: Adresse initiale de la fenêtre.
  • win: Objet fenêtre retourné par l'appel (handle).
  • ierror: Seulement en Fortran : Statut d'erreur (entier).

DESCRIPTION

MPI_Win_allocate_shared est un appel collectif exécuté par tous les processus du groupe de comm. Sur chaque processus, il alloue de la mémoire d'au moins size octets qui est partagée entre tous les processus dans comm, et retourne un pointeur vers la partie allouée localement dans baseptr qui peut être utilisée pour les accès en lecture/écriture sur le processus appelant. La mémoire allouée localement peut être la cible d'accès en lecture/écriture par des processus distants ; les pointeurs de base pour d'autres processus peuvent être interrogés via la fonction MPI_Win_shared_query. L'appel retourne également un objet fenêtre qui peut être utilisé par tous les processus dans comm pour effectuer des opérations RMA. La valeur size peut être différente sur chaque processus et size = 0 est valide. Il incombe à l'utilisateur de garantir que le communicateur comm représente un groupe de processus capables de créer une segmentation de mémoire partagée accessible par tous les processus du groupe. Les discussions sur les justifications de MPI_Alloc_mem et MPI_Free_mem dans la section 8.2 de MPI-3.1 s'appliquent également à MPI_Win_allocate_shared ; en particulier, voir la justification dans la section 8.2 de MPI-3.1 pour une explication de ce qui est utilisé pour baseptr. La mémoire allouée est contiguë entre les processus classés s'il n'est pas spécifié la clé d'info alloc_shared_noncontig. Contiguë entre les processus classés signifie que l'adresse initiale de la segmentation de mémoire sur le processus i est consécutive à la dernière adresse de la segmentation de mémoire sur le processus i-1. Cela peut permettre à l'utilisateur de calculer les décalages d'adresses distantes en utilisant uniquement des informations locales.

Les clés d'info suivantes sont prises en charge :

alloc_shared_noncontig
Si elle n'est pas définie sur true, la stratégie d'allocation est d'allouer de la mémoire contiguë entre les processus classés. Cela peut limiter les performances sur certaines architectures car cela ne permet pas à l'implémenteur de modifier la disposition des données (par exemple, l'ajout d'espacements pour réduire la latence d'accès).
blocking_fence
Si elle est définie sur true, le composant osc/sm utilisera MPI_Barrier pour MPI_Win_fence. Si elle est définie sur false, un condenseur et un compteur seront utilisés à la place. La valeur par défaut est false. Cette clé d'info est spécifique à Open MPI.

Pour plus d'informations sur les clés d'info supplémentaires, voir MPI_Win_create.

NOTES

Les choix courants pour disp_unit sont 1 (pas de mise à l'échelle) et, dans la syntaxe C, sizeof(type), pour un espace de fenêtre composé d'un tableau d'éléments de type type. La deuxième option permet d'utiliser des indices de tableau dans les appels RMA et qu'ils soient correctement mis à l'échelle pour les décalages en octets, même dans des environnements hétérogènes.

L'appel MPI_Win_free libère la mémoire allouée par MPI_Win_allocate_shared. Par conséquent, il est incorrect de libérer manuellement baseptr.

NOTES EN C

Bien que baseptr soit de type void *, cela permet d'utiliser facilement tout objet pointeur pour ce paramètre. Cet argument est en réalité de type void **.

ERREURS

La quasi-totalité des routines MPI retournent une valeur d'erreur ; les routines C retournent le résultat de la fonction et les routines Fortran dans le dernier argument.

Avant que la valeur d'erreur ne soit retournée, le gestionnaire d'erreurs associé à l'objet de communication (par exemple, communicateur, fenêtre, fichier) actuel est appelé. S'il n'y a pas d'objet de communication associé à l'appel MPI, l'appel est considéré comme associé à MPI_COMM_SELF et le gestionnaire associé à MPI_COMM_SELF est appelé. Lorsque MPI_COMM_SELF n'est pas initialisé (c'est-à-dire avant MPI_Init/MPI_Init_thread, après MPI_Finalize, ou lorsque le modèle de session est utilisé exclusivement), le gestionnaire d'erreurs initial est levé. Le gestionnaire d'erreurs initial peut être modifié en appelant MPI_Comm_set_errhandler sur MPI_COMM_SELF lors de l'utilisation du modèle du monde, ou l'argument mpi_initial_errhandler dans mpiexec ou la clé d'information pour MPI_Comm_spawn/MPI_Comm_spawn_multiple. Si aucun autre gestionnaire d'erreurs approprié n'est trouvé, le gestionnaire d'erreurs MPI_ERRORS_RETURN est appelé pour les fonctions d'E/S MPI et le gestionnaire MPI_ERRORS_ABORT pour les autres fonctions MPI.

Open MPI comprend trois gestionnaires d'erreurs prédéfinis qui peuvent être utilisés :

  • MPI_ERRORS_ARE_FATAL Provoque l'arrêt de tous les processus MPI connectés du programme.
  • MPI_ERRORS_ABORT Un gestionnaire d'erreurs qui peut être invoqué sur un communicateur, une fenêtre, un fichier ou une session. Lorsqu'il est invoqué sur un communicateur, il agit comme si MPI_Abort avait été appelé sur ce communicateur. S'il est invoqué sur une fenêtre ou un fichier, il agit comme si MPI_Abort avait été appelé sur un communicateur contenant le groupe de processus dans la fenêtre ou le fichier correspondant. S'il est invoqué sur une session, il n'abandonne que le processus local.
  • MPI_ERRORS_RETURN Retourne un code d'erreur à l'application.

Les applications MPI peuvent également implémenter leurs propres gestionnaires d'erreurs en appelant :

  • MPI_Comm_create_errhandler puis MPI_Comm_set_errhandler
  • MPI_File_create_errhandler puis MPI_File_set_errhandler
  • MPI_Session_create_errhandler puis MPI_Session_set_errhandler ou dans MPI_Session_init
  • MPI_Win_create_errhandler puis MPI_Win_set_errhandler

Remarque : MPI ne garantit pas qu'un programme MPI puisse continuer à s'exécuter après une erreur.

Voir la section sur les gestionnaires d'erreurs de la spécification MPI-3.1 pour plus d'informations.

MPI_Win_allocate_shared(3)

NOM

MPI_Win_allocate_shared - Alloue une mémoire partagée pour une fenêtre.

SYNTAXE

C

int MPI_Win_allocate_shared(MPI_Comm comm, size_t size, int disp_unit, MPI_Info info, void *baseptr, MPI_Win *win);

Fortran

SUBROUTINE MPI_WIN_ALLOCATE_SHARED(COMM, SIZE, DISP_UNIT, INFO, BASEPTR, WIN, IERROR)
    INTEGER :: COMM, DISP_UNIT, INFO, WIN, IERROR
    INTEGER(KIND=MPI_ADDRESS_KIND) :: SIZE
    INTEGER(KIND=MPI_ADDRESS_KIND) :: BASEPTR
END SUBROUTINE MPI_WIN_ALLOCATE_SHARED

PARAMÈTRES D'ENTRÉE

  • comm : Communicateur MPI (integer, IN). Le communicateur utilisé pour la fenêtre.

  • size : Taille de la mémoire à allouer (integer(KIND=MPI_ADDRESS_KIND), IN). La taille, en octets, de la mémoire à allouer.

  • disp_unit : Unité de déplacement (integer, IN). L'unité de déplacement à utiliser pour l'indexation des objets dans la fenêtre. Par exemple, si vous allouez un tableau d'entiers C, disp_unit sera sizeof(int).

  • info : Objet d'information (MPI_Info, IN). Informations facultatives pour l'allocation.

PARAMÈTRES DE SORTIE

  • baseptr : Pointeur vers la base de la mémoire allouée (pointer, OUT). Pointeur vers le début de la région de mémoire allouée.

  • win : Identifiant de fenêtre (MPI_Win, OUT). Le nouveau handle de fenêtre.

  • IERROR : Code d'erreur Fortran (integer, OUT). Le code d'erreur Fortran.

DESCRIPTION

MPI_Win_allocate_shared alloue une région de mémoire partagée pour une fenêtre et la rend accessible à tous les processus dans le communicateur spécifié. La mémoire allouée est partagée dans le sens où le même bloc de mémoire est visible et accessible par tous les processus du groupe de communicateur. Il n'y a pas de garantie que le pointeur renvoyé par MPI_Win_allocate_shared sera le même sur tous les processus. Cependant, tous les processus recevront un pointeur valide vers le même bloc de mémoire physique.

Le paramètre size spécifie la quantité de mémoire, en octets, à allouer. Le paramètre disp_unit spécifie l'unité de déplacement, qui est généralement la taille d'un élément de données si vous allouez un tableau. Par exemple, pour un tableau d'entiers, disp_unit serait sizeof(int).

L'objet info peut être utilisé pour spécifier des attributs d'allocation, tels que les alignements ou les préférences d'emplacement mémoire. Si info est MPI_INFO_NULL, aucune information supplémentaire n'est fournie.

Le pointeur baseptr sera rempli avec l'adresse de base de la mémoire allouée. Le paramètre win sera rempli avec un handle pour la nouvelle fenêtre.

Après avoir alloué la mémoire partagée, chaque processus peut accéder à la mémoire à l'aide du pointeur baseptr, potentiellement en l'utilisant comme base pour des calculs d'adresse d'éléments individuels dans la mémoire allouée. L'accès à la mémoire allouée doit être effectué dans le cadre des opérations de synchronisation MPI, telles que MPI_Win_fence, MPI_Win_post/MPI_Win_wait, ou MPI_Win_lock/MPI_Win_unlock.

La mémoire allouée par MPI_Win_allocate_shared doit être libérée avec MPI_Win_free.

NOTES C
