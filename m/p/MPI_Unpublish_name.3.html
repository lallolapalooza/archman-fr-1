Paquet: openmpi

Licences: BSD-3-Clause AND LicenseRef-MPICH

MPI_UNPUBLISH_NAME(3) Open MPI MPI_UNPUBLISH_NAME(3) 
MPI_Unpublish_name - Annule la publication d'un nom de service

SYNTAXE

Syntaxe C

#include <mpi.h>
int MPI_Unpublish_name(const char *service_name, MPI_Info info,
     const char *port_name)

Syntaxe Fortran

USE MPI
! ou l'ancienne forme : INCLUDE 'mpif.h'
MPI_UNPUBLISH_NAME(SERVICE_NAME, INFO, PORT_NAME, IERROR)
     CHARACTER*(*)   SERVICE_NAME, PORT_NAME
     INTEGER         INFO, IERROR

Syntaxe Fortran 2008

USE mpi_f08
MPI_Unpublish_name(service_name, info, port_name, ierror)
     CHARACTER(LEN=*), INTENT(IN) :: service_name, port_name
     TYPE(MPI_Info), INTENT(IN) :: info
     INTEGER, OPTIONAL, INTENT(OUT) :: ierror

PARAMETRES ENTRANTS

  • service_name: Un nom de service (chaîne).
  • info: Options pour les fonctions de nommage de service (handle).
  • port_name: Un nom de port (chaîne).

PARAMETRE SORTANT

•
ierror: Fortran seulement : Statut d'erreur (entier).

DESCRIPTION

Cette routine supprime la paire (service_name, port_name) afin que les applications ne puissent plus récupérer port_name en appelant MPI_Lookup_name. Il est erroné d'annuler la publication d'un service_name qui n'a pas été publié via MPI_Publish_name. Les arguments service_name et port_name de MPI_Unpublish_name doivent être identiques aux arguments de l'appel précédent à MPI_Publish_name.

ARGUMENTS INFO

Les clés suivantes pour info sont reconnues :

Clé                   Type      Description
---                   ----      -----------
ompi_global_scope     bool      Si défini à vrai, annule la publication du nom
                                depuis la portée globale. Annule la publication
                                depuis la portée locale sinon. Voir la section
                                SCOPE DE NOMS pour plus de détails.

Les clés d'info bool sont en fait des chaînes de caractères mais sont évaluées comme suit : si la valeur de la chaîne est un nombre, elle est convertie en entier et transtypée en booléen (ce qui signifie que les entiers zéro sont faux et les valeurs non nulles sont vraies). Si la valeur de la chaîne est “yes” ou “true” (insensible à la casse), le booléen est vrai. Si la valeur de la chaîne est “no” ou “false” (insensible à la casse), le booléen est faux. Toutes les autres valeurs de chaînes sont non reconnues, et donc fausses.

Si aucune clé d'info n'est fournie, la fonction vérifiera d'abord si un serveur global a été spécifié et est disponible. Si c'est le cas, la fonction d'annulation de publication utilisera par défaut la portée globale en premier, puis la locale. Sinon, les données seront par défaut annulées avec la portée locale.

PORTEE DES NOMS

Open MPI supporte deux portées de noms : globale et locale. Les valeurs de portée locale sont placées dans un magasin de données situé sur le mpirun du job du processus appelant, tandis que les valeurs de portée globale résident sur un serveur central. Les appels à MPI_Unpublish_name doivent spécifier correctement la portée à utiliser pour trouver la valeur à supprimer. La fonction retournera une erreur si le nom de service spécifié n'est pas trouvé à l'emplacement indiqué.

Pour une description plus détaillée des règles de portée, veuillez consulter la page man de MPI_Publish_name.

ERREURS

Presque toutes les routines MPI retournent une valeur d'erreur ; les routines C comme résultat de la fonction et les routines Fortran dans le dernier argument.

Avant que la valeur d'erreur ne soit retournée, le gestionnaire d'erreurs MPI courant associé à l'objet de communication (par exemple, communicateur, fenêtre, fichier) est appelé. Si aucun objet de communication n'est associé à l'appel MPI, alors l'appel est considéré comme attaché à MPI_COMM_SELF et appellera le gestionnaire d'erreurs MPI associé. Lorsque MPI_COMM_SELF n'est pas initialisé (c'est-à-dire avant MPI_Init/MPI_Init_thread, après MPI_Finalize, ou lors de l'utilisation exclusive du modèle de Sessions) l'erreur déclenche le gestionnaire d'erreurs initial. Le gestionnaire d'erreurs initial peut être modifié en appelant MPI_Comm_set_errhandler sur MPI_COMM_SELF lors de l'utilisation du modèle World, ou l'argument CLI mpi_initial_errhandler à mpiexec ou la clé d'info à MPI_Comm_spawn/MPI_Comm_spawn_multiple. Si aucun autre gestionnaire d'erreurs approprié n'a été défini, alors le gestionnaire d'erreurs MPI_ERRORS_RETURN est appelé pour les fonctions d'E/S MPI et le gestionnaire d'erreurs MPI_ERRORS_ABORT est appelé pour toutes les autres fonctions MPI.

Open MPI inclut trois gestionnaires d'erreurs prédéfinis qui peuvent être utilisés :

  • MPI_ERRORS_ARE_FATAL Provoque l'abandon du programme par tous les processus MPI connectés.
  • MPI_ERRORS_ABORT Un gestionnaire d'erreurs qui peut être invoqué sur un communicateur, une fenêtre, un fichier ou une session. Lorsqu'il est appelé sur un communicateur, il agit comme si MPI_Abort avait été appelé sur ce communicateur. S'il est appelé sur une fenêtre ou un fichier, il agit comme si MPI_Abort avait été appelé sur un communicateur contenant le groupe des processus dans la fenêtre ou le fichier correspondant. S'il est appelé sur une session, il n'abandonne que le processus local.
  • MPI_ERRORS_RETURN Retourne un code d'erreur à l'application.

Les applications MPI peuvent également implémenter leurs propres gestionnaires d'erreurs en appelant :

  • MPI_Comm_create_errhandler puis MPI_Comm_set_errhandler
  • MPI_File_create_errhandler puis MPI_File_set_errhandler
  • MPI_Session_create_errhandler puis MPI_Session_set_errhandler ou à MPI_Session_init
  • MPI_Win_create_errhandler puis MPI_Win_set_errhandler

Notez que MPI ne garantit pas qu'un programme MPI puisse continuer après une erreur.

Voir la page man MPI pour une liste complète des codes d'erreur MPI.

Voir la section Gestion des erreurs de la norme MPI-3.1 pour plus d'informations.
