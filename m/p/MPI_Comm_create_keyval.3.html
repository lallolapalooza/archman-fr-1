MPI_Comm_create_keyval(3) Open MPI MPI_Comm_create_keyval(3)

MPI_Comm_create_keyval — Génère une nouvelle valeur d'attribut.

Syntaxe

Syntaxe C

#include <mpi.h>
int MPI_Comm_create_keyval(MPI_Comm_copy_attr_function
    *comm_copy_attr_fn, MPI_Comm_delete_attr_function
    *comm_delete_attr_fn, int *comm_keyval,
    void *extra_state)

Syntaxe Fortran

USE MPI
! o o r d e r: INCLUDE 'mpif.h'
MPI_COMM_CREATE_KEYVAL(COMM_COPY_ATTR_FN, COMM_DELETE_ATTR_FN,
    COMM_KEYVAL, EXTRA_STATE, IERROR)
    EXTERNAL COMM_COPY_ATTR_FN, COMM_DELETE_ATTR_FN
    INTEGER COMM_KEYVAL, IERROR
    INTEGER(KIND=MPI_ADDRESS_KIND) EXTRA_STATE

Syntaxe Fortran 2008

USE mpi_f08
MPI_Comm_create_keyval(comm_copy_attr_fn, comm_delete_attr_fn, comm_keyval,
        extra_state, ierror)
    PROCEDURE(MPI_Comm_copy_attr_function) :: comm_copy_attr_fn
    PROCEDURE(MPI_Comm_delete_attr_function) :: comm_delete_attr_fn
    INTEGER, INTENT(OUT) :: comm_keyval
    INTEGER(KIND=MPI_ADDRESS_KIND), INTENT(IN) :: extra_state
    INTEGER, OPTIONAL, INTENT(OUT) :: ierror

Paramètres d'entrée

•
comm_copy_attr_fn
Fonction de rappel pour comm_keyval (fonction).
•
comm_delete_attr_fn
Fonction de rappel pour comm_keyval (fonction).
•
extra_state : État supplémentaire pour les fonctions de rappel.

Paramètre de sortie

  • comm_keyval : Valeur de clé pour un accès futur (entier).
  • ierror : Fortran uniquement : Code d'erreur (entier).

Description

Cette fonction remplace MPI_Keyval_create, qui est obsolète. La liaison C est identique. La liaison Fortran diffère en ce que extra_state est un entier de la taille d'une adresse. De plus, les fonctions de rappel pour la copie et la suppression ont des liaisons Fortran cohérentes avec les attributs de la taille d'une adresse. L'argument comm_copy_attr_fn peut être spécifié comme MPI_COMM_NULL_COPY_FN ou MPI_COMM_DUP_FN en C ou Fortran. MPI_COMM_NULL_COPY_FN est une fonction qui ne renvoie que flag = 0 et MPI_SUCCESS . MPI_COMM_DUP_FN est une fonction de copie simple qui définit flag = 1 , renvoie la valeur de attribute_val_in dans attribute_val_out et renvoie MPI_SUCCESS . Ceux-ci remplacent les fonctions de rappel prédéfinies MPI-1 MPI_NULL_COPY_FN et MPI_DUP_FN , qui sont obsolètes. Les deux fonctions de rappel C sont :

typedef int MPI_Comm_copy_attr_function(MPI_Comm oldcomm, int comm_keyval,
             void *extra_state, void *attribute_val_in,
             void *attribute_val_out, int *flag);
typedef int MPI_Comm_delete_attr_function(MPI_Comm comm, int comm_keyval,
             void *attribute_val, void *extra_state);

qui sont les mêmes que les appels MPI-1.1, mais avec un nouveau nom. Les anciens noms sont obsolètes. Les deux fonctions de rappel Fortran sont :

SUBROUTINE COMM_COPY_ATTR_FN(OLDCOMM, COMM_KEYVAL, EXTRA_STATE,
             ATTRIBUTE_VAL_IN, ATTRIBUTE_VAL_OUT, FLAG, IERROR)
    INTEGER OLDCOMM, COMM_KEYVAL, IERROR
    INTEGER(KIND=MPI_ADDRESS_KIND) EXTRA_STATE, ATTRIBUTE_VAL_IN,
        ATTRIBUTE_VAL_OUT
    LOGICAL FLAG
SUBROUTINE COMM_DELETE_ATTR_FN(COMM, COMM_KEYVAL, ATTRIBUTE_VAL, EXTRA_STATE,
             IERROR)
    INTEGER COMM, COMM_KEYVAL, IERROR
    INTEGER(KIND=MPI_ADDRESS_KIND) ATTRIBUTE_VAL, EXTRA_STATE

Erreurs

La plupart des routines MPI renvoient une valeur d'erreur ; en C, le résultat est renvoyé comme valeur de retour de la fonction, et en Fortran dans le dernier argument.

Avant que la valeur d'erreur ne soit renvoyée, le gestionnaire d'erreurs associé à l'objet de communication (par exemple, le communicateur, la fenêtre, le fichier) est appelé. S'il n'y a pas d'objet de communication associé à l'appel MPI, l'appel est considéré comme étant lié à MPI_COMM_SELF et le gestionnaire d'erreurs associé sera appelé. Lorsque MPI_COMM_SELF n'est pas initialisé (c'est-à-dire avant MPI_Init/MPI_Init_thread, après MPI_Finalize, ou lorsqu'on utilise le modèle de sessions exclusivement), l'erreur indiquée est levée. Le gestionnaire d'erreurs initial peut être modifié en appelant MPI_Comm_set_errhandler sur MPI_COMM_SELF lorsque le modèle du monde est utilisé, ou via l'argument CLI mpi_initial_errhandler dans mpiexec ou via la clé d'information dans MPI_Comm_spawn/MPI_Comm_spawn_multiple. Si aucun autre gestionnaire d'erreurs approprié n'est défini, le gestionnaire d'erreurs MPI_ERRORS_RETURN est appelé pour les fonctions d'E/S MPI et le gestionnaire d'erreurs MPI_ERRORS_ABORT est appelé pour toutes les autres fonctions MPI.

Open MPI inclut trois gestionnaires d'erreurs par défaut qui peuvent être utilisés :

  • MPI_ERRORS_ARE_FATAL : Arrête tous les processus MPI connectés.
  • MPI_ERRORS_ABORT : Un gestionnaire d'erreurs qui peut être invoqué sur un communicator, une fenêtre, un fichier ou une session. Lorsqu'il est appelé sur un communicator, il agit comme si MPI_Abort avait été appelé sur ce communicator. S'il est appelé sur une fenêtre ou un fichier, il agit comme si MPI_Abort avait été appelé sur un communicator contenant le groupe de processus dans la fenêtre ou le fichier correspondant. S'il est appelé sur une session, il arrête uniquement le processus local.
  • MPI_ERRORS_RETURN : Renvoie un code d'erreur à l'application.

Les applications MPI peuvent également implémenter leurs propres gestionnaires d'erreurs en appelant :

  • MPI_Comm_create_errhandler suivi de MPI_Comm_set_errhandler
  • MPI_File_create_errhandler suivi de MPI_File_set_errhandler
  • MPI_Session_create_errhandler suivi de MPI_Session_set_errhandler ou dans MPI_Session_init
  • MPI_Win_create_errhandler suivi de MPI_Win_set_errhandler

Remarque : les applications MPI ne sont pas garanties de pouvoir continuer après une erreur.

Voir la page de manuel MPI pour une liste complète des codes d'erreur MPI.

Voir la section sur la gestion des erreurs de la norme MPI-3.1 pour plus d'informations.
