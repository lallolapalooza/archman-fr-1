MPI_PROBE(3) Open MPI MPI_PROBE(3)

MPI_Probe — Test bloquant pour un message.

SYNTAXE

Syntaxe C

#include <mpi.h>
int MPI_Probe(int source, int tag, MPI_Comm comm, MPI_Status *status)

Syntaxe Fortran

USE MPI
! ou la forme plus ancienne : INCLUDE 'mpif.h'
MPI_PROBE(SOURCE, TAG, COMM, STATUS, IERROR)
     INTEGER SOURCE, TAG, COMM, STATUS(MPI_STATUS_SIZE), IERROR

Syntaxe Fortran 2008

USE mpi_f08
MPI_Probe(source, tag, comm, status, ierror)
     INTEGER, INTENT(IN) :: source, tag
     TYPE(MPI_Comm), INTENT(IN) :: comm
     TYPE(MPI_Status) :: status
     INTEGER, OPTIONAL, INTENT(OUT) :: ierror

PARAMETRES ENTRANT

  • source : Rang de la source ou MPI_ANY_SOURCE (entier).
  • tag : Valeur du tag ou MPI_ANY_TAG (entier).
  • comm : Communicateur (descripteur).

PARAMETRES SORTANT

  • status : Objet de statut (statut).
  • ierror : Fortran seulement : Statut d'erreur (entier).

DESCRIPTION

Les opérations MPI_Probe et MPI_Iprobe permettent de vérifier les messages entrants, sans les recevoir réellement. L'utilisateur peut alors décider comment les recevoir, en fonction des informations renvoyées par le test dans la variable de statut. Par exemple, l'utilisateur peut allouer de la mémoire pour le tampon de réception, en fonction de la longueur du message testé.

MPI_Probe se comporte comme MPI_Iprobe, sauf que c'est un appel bloquant qui ne retourne qu'après qu'un message correspondant ait été trouvé.

Si votre application n'a pas besoin d'examiner le champ status, vous pouvez économiser des ressources en utilisant la constante prédéfinie MPI_STATUS_IGNORE comme valeur spéciale pour l'argument status.

La sémantique de MPI_Probe et MPI_Iprobe garantit la progression : Si un appel à MPI_Probe a été émis par un processus, et qu'une opération d'envoi correspondant au test a été initiée par un processus, alors l'appel à MPI_Probe retournera, à moins que le message ne soit reçu par une autre opération de réception concurrente (exécutée par un autre thread sur le processus de test). De même, si un processus attend activement avec MPI_Iprobe et qu'un message correspondant a été émis, alors l'appel à MPI_Iprobe retournera éventuellement flag = true, à moins que le message ne soit reçu par une autre opération de réception concurrente.

Exemple 1 : Utilisation d'un test bloquant pour attendre un message entrant.

CALL MPI_COMM_RANK(comm, rank, ierr)
IF (rank == 0) THEN
   CALL MPI_SEND(i, 1, MPI_INTEGER, 2, 0, comm, ierr)
ELSE IF(rank == 1) THEN
   CALL MPI_SEND(x, 1, MPI_REAL, 2, 0, comm, ierr)
ELSE   ! rank == 2
   DO i=1, 2
      CALL MPI_PROBE(MPI_ANY_SOURCE, 0,
                     comm, status, ierr)
      IF (status(MPI_SOURCE) = 0) THEN
         CALL MPI_RECV(i, 1, MPI_INTEGER, 0, 0, status, ierr)
      ELSE
         CALL MPI_RECV(x, 1, MPI_REAL, 1, 0, status, ierr)
      END IF
   END DO
END IF

Chaque message est reçu avec le bon type.

Exemple 2 : Un programme similaire à l'exemple précédent, mais avec un problème.

CALL MPI_COMM_RANK(comm, rank, ierr)
IF (rank == 0) THEN
   CALL MPI_SEND(i, 1, MPI_INTEGER, 2, 0, comm, ierr)
ELSE IF(rank == 1) THEN
   CALL MPI_SEND(x, 1, MPI_REAL, 2, 0, comm, ierr)
ELSE
   DO i=1, 2
      CALL MPI_PROBE(MPI_ANY_SOURCE, 0,
                     comm, status, ierr)
      IF (status(MPI_SOURCE) == 0) THEN
         CALL MPI_RECV(i, 1, MPI_INTEGER, MPI_ANY_SOURCE, &
                       0, status, ierr)
      ELSE
         CALL MPI_RECV(x, 1, MPI_REAL, MPI_ANY_SOURCE, &
                       0, status, ierr)
      END IF
   END DO
END IF

Nous avons légèrement modifié l'Exemple 2, en utilisant MPI_ANY_SOURCE comme argument source dans les deux appels de réception aux instructions 100 et 200. Le programme est maintenant incorrect : l'opération de réception peut recevoir un message différent de celui testé par l'appel précédent à MPI_Probe.

ERREURS

Presque toutes les routines MPI retournent une valeur d'erreur ; les routines C comme résultat de la fonction et les routines Fortran dans le dernier argument.

Avant que la valeur d'erreur ne soit retournée, le gestionnaire d'erreurs MPI courant associé à l'objet de communication (par exemple, le communicateur, la fenêtre, le fichier) est appelé. Si aucun objet de communication n'est associé à l'appel MPI, alors l'appel est considéré comme attaché à MPI_COMM_SELF et appellera le gestionnaire d'erreurs MPI associé. Lorsque MPI_COMM_SELF n'est pas initialisé (c'est-à-dire avant MPI_Init/MPI_Init_thread, après MPI_Finalize, ou lors de l'utilisation exclusive du modèle de sessions), l'erreur déclenche le gestionnaire d'erreurs initial. Le gestionnaire d'erreurs initial peut être modifié en appelant MPI_Comm_set_errhandler sur MPI_COMM_SELF lorsque le modèle World est utilisé, ou l'argument de ligne de commande mpiexec mpi_initial_errhandler ou la clé info de MPI_Comm_spawn/MPI_Comm_spawn_multiple. Si aucun autre gestionnaire d'erreurs approprié n'a été défini, alors le gestionnaire d'erreurs MPI_ERRORS_RETURN est appelé pour les fonctions d'E/S MPI et le gestionnaire d'erreurs MPI_ERRORS_ABORT est appelé pour toutes les autres fonctions MPI.

Open MPI inclut trois gestionnaires d'erreurs prédéfinis qui peuvent être utilisés :

  • MPI_ERRORS_ARE_FATAL Provoque l'arrêt du programme pour tous les processus MPI connectés.
  • MPI_ERRORS_ABORT Un gestionnaire d'erreurs qui peut être invoqué sur un communicateur, une fenêtre, un fichier ou une session. Lorsqu'il est appelé sur un communicateur, il agit comme si MPI_Abort avait été appelé sur ce communicateur. S'il est appelé sur une fenêtre ou un fichier, il agit comme si MPI_Abort avait été appelé sur un communicateur contenant le groupe de processus de la fenêtre ou du fichier correspondant. S'il est appelé sur une session, il n'interrompt que le processus local.
  • MPI_ERRORS_RETURN Retourne un code d'erreur à l'application.

Les applications MPI peuvent également implémenter leurs propres gestionnaires d'erreurs en appelant :

  • MPI_Comm_create_errhandler puis MPI_Comm_set_errhandler
  • MPI_File_create_errhandler puis MPI_File_set_errhandler
  • MPI_Session_create_errhandler puis MPI_Session_set_errhandler ou lors de MPI_Session_init
  • MPI_Win_create_errhandler puis MPI_Win_set_errhandler

Notez que MPI ne garantit pas qu'un programme MPI puisse continuer après une erreur.

Voir la page de manuel MPI pour une liste complète des codes d'erreur MPI.

Voir la section Gestion des erreurs de la norme MPI-3.1 pour plus d'informations.

Notez que conformément à la section « Statut de retour » du chapitre « Communication Point à Point » de la norme MPI, les erreurs MPI sur les messages interrogés par MPI_Probe ne définissent pas le champ status.MPI_ERROR dans le status retourné. Le code d'erreur est toujours passé au gestionnaire d'erreurs backend et peut être renvoyé à l'appelant via la valeur de retour de MPI_Probe si le gestionnaire d'erreurs backend le renvoie. Le gestionnaire d'erreurs MPI prédéfini MPI_ERRORS_RETURN présente ce comportement, par exemple.
