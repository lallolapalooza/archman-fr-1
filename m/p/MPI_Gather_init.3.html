MPI_Gather, MPI_Igather, MPI_Gather_init - Collecte des valeurs à partir d'un groupe de processus.

SYNTAXE

    void *recvbuf, int recvcount, MPI_Datatype recvtype, int root,
    MPI_Comm comm, MPI_Request *request)

PARAMÈTRES D'ENTRÉE

  • sendbuf : Adresse de début du buffer d'envoi (pointeur).
  • sendcount : Nombre d'éléments dans le buffer d'envoi (entier).
  • sendtype : Type des éléments dans le buffer d'envoi (handle).
  • recvcount : Nombre d'éléments à recevoir par processus (entier, significatif uniquement sur le processus racine).
  • recvtype : Type des éléments dans le buffer de réception (handle, significatif uniquement sur le processus racine).
  • root : Rang du processus de réception (entier).
  • comm : Communicateur (handle).
  • info : Informations (handle, persistant).

PARAMÈTRES DE SORTIE

•
recvbuf
Adresse du buffer de réception (pointeur, significatif uniquement sur le processus racine).
  • request : Requête (handle, non bloquant).
  • ierror : Uniquement en Fortran : État de l'erreur (entier).

DESCRIPTION

Chaque processus (y compris le processus racine) envoie le contenu de son buffer d'envoi au processus racine. Le processus racine reçoit les messages et les stocke dans l'ordre des rangs. Le résultat est comme si chacun des n processus du groupe (y compris le processus racine) avait exécuté un appel à

MPI_Send(sendbuf, sendcount, sendtype, root, ...)

et le processus racine avait exécuté n appels à

MPI_Recv(recfbuf + i * recvcount * extent(recvtype), recvcount,
         recvtype, i, ...)

où extent(recvtype) est la taille du type obtenue d'un appel à MPI_Type_extent.

Une description alternative est que les n messages envoyés par les processus du groupe sont concaténés dans l'ordre des rangs et le message résultant est reçu par le processus racine comme si un appel à MPI_Recv(recvbuf, recvcount * n, recvtype, ...) avait été exécuté.

Le buffer de réception est ignoré pour tous les processus non racines.

Les types dérivés sont autorisés pour sendtype et recvtype. La signature de type de sendcount, sendtype sur le processus i doit être égale à la signature de recvcount, recvtype sur le processus racine. Cela implique que le nombre de données envoyées doit être égal au nombre de données reçues, par paire entre chaque processus et le processus racine. Des types de mappe différents entre l'émetteur et le récepteur sont toujours autorisés.

Tous les arguments de la fonction sont significatifs sur le processus racine, tandis que sur les autres processus, seuls les arguments sendbuf, sendcount, sendtype, root, comm sont significatifs. Les arguments root et comm doivent avoir des valeurs identiques sur tous les processus.

La spécification des quantités et des types ne doit pas entraîner l'écriture plus d'une fois à un endroit sur le processus racine. Cet appel est erroné. Notez que l'argument recvcount sur le processus racine indique le nombre d'éléments qu'il reçoit de chaque processus, et non le nombre total d'éléments qu'il reçoit.

Exemple 1 : Collecter 100 entiers de chaque processus du groupe vers le processus racine.

MPI_Comm comm;
int gsize, sendarray[100];
int root, *rbuf;
...
MPI_Comm_size( comm, &gsize);
rbuf = (int*)malloc(gsize * 100 * sizeof(int));
MPI_Gather( sendarray, 100, MPI_INT, rbuf, 100, MPI_INT, root, comm);

Exemple 2 : L'exemple précédent modifié - seul le processus racine réserve le buffer de réception.

MPI_Comm comm;
int gsize, sendarray[100];
int root, myrank, * rbuf;
...
MPI_Comm_rank( comm, myrank);
if ( myrank == root) {
  MPI_Comm_size( comm, &gsize);
  rbuf = (int *)malloc(gsize * 100 * sizeof(int));
}
MPI_Gather( sendarray, 100, MPI_INT, rbuf, 100, MPI_INT, root, comm);

Exemple 3 : Faire la même chose que l'exemple précédent, mais en utilisant un type dérivé. Notez que le type ne peut pas être l'ensemble complet de gsize * 100 entiers, car le type correspondant est défini par paire entre le processus racine et chaque processus du groupe de collecte.

MPI_Comm comm;
int gsize, sendarray[100];
int root, * rbuf;
MPI_Datatype rtype;
...
MPI_Comm_size( comm, &gsize);
MPI_Type_contiguous( 100, MPI_INT, &rtype);
MPI_Type_commit( &rtype );
rbuf = (int*)malloc(gsize * 100 * sizeof(int));
MPI_Gather( sendarray, 100, MPI_INT, rbuf, 1, rtype, root, comm);

UTILISATION DE L'OPTION EN-PLACE

Lorsque le communicateur est un intracommunicateur, vous pouvez effectuer une opération de collecte en place (le buffer de sortie est utilisé comme buffer d'entrée). Utilisez la variable MPI_IN_PLACE comme valeur de sendbuf du processus racine. Dans ce cas, sendcount et sendtype sont ignorés, et la contribution du processus racine à la collection globale est supposée être déjà à la bonne position dans le buffer de réception. Notez que MPI_IN_PLACE est un type spécial ; il a les mêmes restrictions d'utilisation que MPI_BOTTOM. Comme l'option en place transforme le buffer de réception en un buffer d'envoi et de réception, une liaison Fortran incluant INTENT doit les marquer comme INOUT, et non comme OUT.

N INTER-COMMUNICATOR

Lorsque le communicateur est un inter-communicateur, le processus racine du premier groupe collecte les données de tous les processus du second groupe. Le premier groupe définit le processus racine. Ce processus utilise MPI_ROOT comme valeur de son argument racine. Les processus restants utilisent MPI_PROC_NULL comme valeur de leur argument racine. Tous les processus du second groupe utilisent le rang de ce processus racine dans le premier groupe comme valeur de leur argument racine. L'argument du tampon d'envoi des processus du premier groupe doit être cohérent avec l'argument du tampon de réception du processus racine dans le second groupe.

ERREURS

Presque toutes les routines MPI renvoient une valeur d'erreur ; les routines C comme résultat de la fonction et les routines Fortran dans le dernier argument.

Avant que la valeur d'erreur ne soit renvoyée, le gestionnaire d'erreurs MPI actuel associé à l'objet de communication (par exemple, communicateur, fenêtre, fichier) est appelé. S'il n'y a pas d'objet de communication associé à l'appel MPI, alors l'appel est considéré comme attaché à MPI_COMM_SELF et appellera le gestionnaire d'erreurs MPI associé. Lorsque MPI_COMM_SELF n'est pas initialisé (c'est-à-dire avant MPI_Init/MPI_Init_thread, après MPI_Finalize, ou lors de l'utilisation exclusive du modèle de sessions) l'erreur déclenche le gestionnaire d'erreurs initial. Le gestionnaire d'erreurs initial peut être modifié en appelant MPI_Comm_set_errhandler sur MPI_COMM_SELF lors de l'utilisation du modèle World, ou l'argument CLI mpi_initial_errhandler de mpiexec ou la clé d'informations de MPI_Comm_spawn/MPI_Comm_spawn_multiple. Si aucun autre gestionnaire d'erreurs approprié n'a été défini, alors le gestionnaire d'erreurs MPI_ERRORS_RETURN est appelé pour les fonctions d'E/S MPI et le gestionnaire d'erreurs MPI_ERRORS_ABORT est appelé pour toutes les autres fonctions MPI.

Open MPI inclut trois gestionnaires d'erreurs prédéfinis qui peuvent être utilisés :

  • MPI_ERRORS_ARE_FATAL Provoque l'abandon du programme par tous les processus MPI connectés.
  • MPI_ERRORS_ABORT Un gestionnaire d'erreurs qui peut être invoqué sur un communicateur, une fenêtre, un fichier ou une session. Lorsqu'il est appelé sur un communicateur, il agit comme si MPI_Abort avait été appelé sur ce communicateur. S'il est appelé sur une fenêtre ou un fichier, il agit comme si MPI_Abort avait été appelé sur un communicateur contenant le groupe de processus dans la fenêtre ou le fichier correspondant. S'il est appelé sur une session, il n'interrompt que le processus local.
  • MPI_ERRORS_RETURN Renvoie un code d'erreur à l'application.

Les applications MPI peuvent également implémenter leurs propres gestionnaires d'erreurs en appelant :

  • MPI_Comm_create_errhandler puis MPI_Comm_set_errhandler
  • MPI_File_create_errhandler puis MPI_File_set_errhandler
  • MPI_Session_create_errhandler puis MPI_Session_set_errhandler ou à MPI_Session_init
  • MPI_Win_create_errhandler puis MPI_Win_set_errhandler

Notez que MPI ne garantit pas qu'un programme MPI puisse continuer après une erreur.

Voir la page man MPI pour une liste complète des codes d'erreur MPI.

Voir la section Gestion des erreurs de la norme MPI-3.1 pour plus d'informations.
