PARAMETRES D'ENTRÉE

  • sendbuf: Tampon d'envoi (choix).
  • count: Nombre d'éléments dans le tampon d'entrée (entier).
  • datatype: Type de données des éléments du tampon d'entrée (handle).
  • op: Opération (handle).
  • comm: Communicateur (handle).
  • info: Informations (handle, persistant uniquement)

PARAMETRES DE SORTIE

  • recvbuf: Tampon de réception (choix).
  • request: Requête (handle, non bloquant uniquement).
  • ierror: Fortran uniquement : Statut d'erreur (entier).

DESCRIPTION

MPI_Scan est utilisé pour effectuer une réduction préfixée inclusive sur les données distribuées à travers les processus appelants. L'opération renvoie, dans le recvbuf du processus de rang i, la réduction (calculée selon la fonction op) des valeurs des sendbuf des processus de rangs 0, …, i (inclus). Le type d'opérations supportées, leur sémantique, et les contraintes sur les tampons d'envoi et de réception sont les mêmes que pour MPI_Reduce.

EXEMPLE

Cet exemple utilise une opération définie par l'utilisateur pour produire un balayage segmenté. Un balayage segmenté prend, en entrée, un ensemble de valeurs et un ensemble de booléens, où les booléens délimitent les différents segments du balayage. Par exemple,

valeurs    v1      v2      v3      v4      v5      v6      v7      v8
logiques   0       0       1       1       1       0       0       1
résultat   v1    v1+v2     v3    v3+v4  v3+v4+v5   v6    v6+v7     v8

Le résultat pour le rang j est donc la somme v(i) + … + v(j), où i est le rang le plus bas tel que pour tous les rangs n, i <= n <= j, logique(n) = logique(j). L'opérateur qui produit cet effet est

      [ u ]     [ v ]     [ w ]
      [   ]  o  [   ]  =  [   ]
      [ i ]     [ j ]     [ j ]
où
    ( u + v si i = j w = ( ( v si i != j

Notez qu'il s'agit d'un opérateur non commutatif. Le code C qui l'implémente est donné ci-dessous.

typedef struct {
        double val;
        int log;
} SegScanPair;
/*
 * la fonction définie par l'utilisateur
 */
void segScan(SegScanPair *in, SegScanPair *inout, int *len,
        MPI_Datatype *dptr)
{
        int i;
        SegScanPair c;
        for (i = 0; i < *len; ++i) {
                if (in->log == inout->log)
                        c.val = in->val + inout->val;
                else
                        c.val = inout->val;
                c.log = inout->log;
                *inout = c;
                in++;
                inout++;
        }
}

Notez que l'argument inout de la fonction définie par l'utilisateur correspond à l'opérande droit de l'opérateur. Lors de l'utilisation de cet opérateur, il faut veiller à spécifier qu'il est non commutatif, comme dans le code suivant :

int                     i, base;
SeqScanPair     a, answer;
MPI_Op          myOp;
MPI_Datatype    type[2] = {MPI_DOUBLE, MPI_INT};
MPI_Aint                disp[2];
int                     blocklen[2] = {1, 1};
MPI_Datatype    sspair;
/*
 * expliquer à MPI comment le type SegScanPair est défini
 */
MPI_Get_address(a, disp);
MPI_Get_address(a.log, disp + 1);
base = disp[0];
for (i = 0; i < 2; ++i)
        disp[i] -= base;
MPI_Type_struct(2, blocklen, disp, type, &sspair);
MPI_Type_commit(&sspair);
/*
 * créer l'opérateur user-op de balayage segmenté
 * non commutatif - définir commute (arg 2) à 0
 */
MPI_Op_create((MPI_User_function *)segScan, 0, &myOp);
...
MPI_Scan(a, answer, 1, sspair, myOp, comm);

UTILISATION DE L'OPTION EN PLACE

Lorsque le communicateur est un intracommunicateur, vous pouvez effectuer une opération de balayage en place (le tampon de sortie est utilisé comme tampon d'entrée). Utilisez la variable MPI_IN_PLACE comme valeur de l'argument sendbuf. Les données d'entrée sont prises du tampon de réception et remplacées par les données de sortie.

NOTES SUR LES OPÉRATIONS COLLECTIVES

Les fonctions de réduction de type MPI_Op ne renvoient pas de valeur d'erreur. Par conséquent, si les fonctions détectent une erreur, elles ne peuvent que soit appeler MPI_Abort, soit ignorer silencieusement le problème. Ainsi, si le gestionnaire d'erreurs est modifié de MPI_ERRORS_ARE_FATAL à autre chose (par exemple, MPI_ERRORS_RETURN), aucune erreur ne sera indiquée.

La raison en est les problèmes de performance pour garantir que toutes les routines collectives renvoient la même valeur d'erreur.

ERREURS

Presque toutes les routines MPI renvoient une valeur d'erreur ; les routines C comme résultat de la fonction et les routines Fortran dans le dernier argument.

Avant que la valeur d'erreur ne soit renvoyée, le gestionnaire d'erreurs MPI actuel associé à l'objet de communication (par exemple, communicateur, fenêtre, fichier) est appelé. S'il n'y a pas d'objet de communication associé à l'appel MPI, l'appel est considéré comme attaché à MPI_COMM_SELF et appellera le gestionnaire d'erreurs MPI associé. Lorsque MPI_COMM_SELF n'est pas initialisé (c'est-à-dire avant MPI_Init/MPI_Init_thread, après MPI_Finalize, ou lors de l'utilisation exclusive du modèle Sessions), l'erreur déclenche le gestionnaire d'erreurs initial. Le gestionnaire d'erreurs initial peut être modifié en appelant MPI_Comm_set_errhandler sur MPI_COMM_SELF lors de l'utilisation du modèle World, ou le mpi_initial_errhandl
