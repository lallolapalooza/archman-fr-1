MPI_Comm_idup_with_info(3) Open MPI MPI_Comm_idup_with_info(3)

MPI_Comm_idup_with_info — Lancer la duplication non bloquante d'un communicateur existant avec toutes ses informations mises en cache.

Syntaxe

Syntaxe C

#include <mpi.h>
int MPI_Comm_idup_with_info(MPI_Comm comm, MPI_Info info, MPI_Comm *newcomm, MPI_Request *request)

Syntaxe Fortran

USE MPI
! ou la vieille forme: INCLUDE 'mpif.h'
MPI_COMM_IDUP_WITH_INFO(COMM, INFO, NEWCOMM, REQUEST, IERROR)
    INTEGER    COMM, INFO, NEWCOMM, REQUEST, IERROR

Syntaxe Fortran 2008

USE mpi_f08
MPI_Comm_idup_with_info(comm, info, newcomm, request, ierror)
    TYPE(MPI_Comm), INTENT(IN) :: comm
    TYPE(MPI_Info), INTENT(IN) :: info
    TYPE(MPI_Comm), INTENT(OUT) :: newcomm
    TYPE(MPI_Request), INTENT(OUT) :: request
    INTEGER, OPTIONAL, INTENT(OUT) :: ierror

Paramètre d'entrée

•
comm: Communicateur (handle).
•
info: Objet d'information (handle).

Paramètres de sortie

  • newcomm: Copie du communicateur (handle).
  • request: Requête de communication (handle).
  • ierror: Fortran uniquement : état d'erreur (entier).

Description

MPI_Comm_idup_with_info lance la duplication non bloquante d'un communicateur existant comm avec toutes ses valeurs d'information mises en cache. Pour chaque valeur d'information, la fonction de rappel correspondante détermine la valeur associée à cette clé dans le nouveau communicateur ; une action particulière qu'une fonction de rappel de duplication peut effectuer est de supprimer la valeur d'information du nouveau communicateur. Le communicateur renvoyé dans newcomm ne sera pas disponible tant que la requête ne sera pas terminée. Les indicateurs fournis par l'argument info sont associés au communicateur de sortie.

L'achèvement d'une requête de duplication de communicateur peut être déterminé en appelant MPI_Wait, MPI_Waitany, MPI_Test ou MPI_Testany avec la requête renvoyée par cette fonction.

Notes

Cette opération est utilisée pour fournir à une bibliothèque parallèle une copie d'un espace de communication qui a les mêmes propriétés que le communicateur d'origine. Cela inclut tous les attributs (voir ci-dessous) et topologies (voir le chapitre Process Topologies dans le MPI Standard). Cet appel est valide même s'il y a des communications point à point en attente impliquant le communicateur comm. Un appel typique pourrait inclure un MPI_Comm_idup_with_info au début d'un appel parallèle et un MPI_Comm_free de ce communicateur dupliqué à la fin de l'appel. D'autres modèles de gestion de communicateur sont également possibles.

Cet appel s'applique aux communicateurs intra-nœuds et aux inter-communicateurs.

Note : Il n'est pas défini par le standard MPI ce qui se passe si la fonction de rappel de copie d'attributs appelle d'autres fonctions MPI. Dans Open MPI, il n'est pas valide pour les fonctions de rappel de copie d'attributs (ou leurs descendants) d'ajouter ou de supprimer des attributs sur le même objet sur lequel la fonction de rappel de copie d'attributs est en cours d'exécution.

Erreurs

Plus qu'une valeur d'erreur ; les routines C renvoient la valeur d'erreur et les routines Fortran dans le dernier argument.

Avant de renvoyer la valeur d'erreur, le gestionnaire d'erreurs actuel associé à l'objet de communication (par exemple, communicateur, fenêtre, fichier) en cours d'utilisation est appelé. S'il n'y a pas d'objet de communication associé à l'appel MPI, l'appel est considéré comme associé à MPI_COMM_SELF et le gestionnaire d'erreurs associé est appelé. Lorsque MPI_COMM_SELF n'est pas initialisé (c'est-à-dire avant MPI_Init/MPI_Init_thread, après MPI_Finalize, ou lorsque le modèle de Session est utilisé exclusivement), l'erreur appelle le gestionnaire d'erreurs initial. Le gestionnaire d'erreurs initial peut être modifié en appelant MPI_Comm_set_errhandler sur MPI_COMM_SELF lors de l'utilisation du modèle Monde, ou sur l'argument CLI mpi_initial_errhandler de mpiexec ou sur la clé d'information de MPI_Comm_spawn/MPI_Comm_spawn_multiple. S'il n'y a pas d'autre gestionnaire d'erreurs approprié défini, le gestionnaire d'erreurs MPI_ERRORS_RETURN est appelé pour les fonctions MPI I/O et le gestionnaire d'erreurs MPI_ERRORS_ABORT est appelé pour toutes les autres fonctions MPI.

Open MPI inclut trois gestionnaires d'erreurs par défaut qui peuvent être utilisés :

  • MPI_ERRORS_ARE_FATAL : Arrête tous les processus MPI connectés.
  • MPI_ERRORS_ABORT : Un gestionnaire qui peut être appelé sur un communicateur, une fenêtre, un fichier ou une session. Lorsqu'il est appelé sur un communicateur, il agit comme si MPI_Abort avait été appelé sur ce communicateur. S'il est appelé sur une fenêtre ou un fichier, il agit comme si MPI_Abort avait été appelé sur un communicateur contenant l'ensemble des processus dans la fenêtre ou le fichier correspondant. S'il est appelé sur une session, il arrête uniquement le processus local.
  • MPI_ERRORS_RETURN : Renvoie un code d'erreur à l'application.

Les applications MPI peuvent également implémenter leurs propres gestionnaires d'erreurs en appelant :

  • MPI_Comm_create_errhandler puis MPI_Comm_set_errhandler
  • MPI_File_create_errhandler puis MPI_File_set_errhandler
  • MPI_Session_create_errhandler puis MPI_Session_set_errhandler ou lors de MPI_Session_init
  • MPI_Win_create_errhandler puis MPI_Win_set_errhandler

Note : MPI ne garantit pas qu'une application MPI pourra continuer après une erreur.

Voir la page de manuel MPI pour une liste complète des codes d'erreur MPI.

Voir la section Gestion des erreurs de la norme MPI version 3.1 pour plus d'informations.

MPI_Comm_idup_with_info

MPI_Comm_idup_with_info - Duplicates a communicator.

SYNTAX

int MPI_Comm_idup_with_info(MPI_Comm comm, MPI_Info info, MPI_Comm *newcomm, MPI_Request *request);

DESCRIPTION

MPI_Comm_idup_with_info is the non-blocking version of MPI_Comm_dup. It duplicates the communicator comm and returns the new communicator in newcomm. The operation is performed asynchronously. The returned request handle can be used with MPI_Test or MPI_Wait to determine when the duplication is complete.

The info argument is an MPI info object that can be used to provide hints to the MPI implementation about how to perform the duplication. The valid keys for the info object are implementation-dependent.

PARAMETERS

  • comm: communicator to duplicate (handle).
  • info: MPI info object containing hints for the duplication (handle).
  • newcomm: new communicator (handle).
  • request: request object associated with the non-blocking operation (handle).

RETURN VALUE

Returns MPI_SUCCESS on success or an MPI error code on failure.
