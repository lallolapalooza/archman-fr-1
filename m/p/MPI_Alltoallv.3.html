MPI_Alltoallv, MPI_Ialltoallv, MPI_Alltoallv_init - Tous les processus envoient une quantité de données différente à, et reçoivent une quantité de données différente de, tous les processus

PARAMÈTRES D'ENTRÉE

  • sendbuf: Adresse du tampon d'envoi.
  • sendcounts: Tableau d'entiers, où l'entrée i spécifie le nombre d'éléments à envoyer au rang i.
  • sdispls: Tableau d'entiers, où l'entrée i spécifie le déplacement (décalage par rapport à sendbuf, en unités de sendtype) à partir duquel envoyer les données au rang i.
  • sendtype: Type de données des éléments du tampon d'envoi.
  • recvcounts: Tableau d'entiers, où l'entrée j spécifie le nombre d'éléments à recevoir du rang j.
  • rdispls: Tableau d'entiers, où l'entrée j spécifie le déplacement (décalage par rapport à recvbuf, en unités de recvtype) auquel les données du rang j doivent être écrites.
  • recvtype: Type de données des éléments du tampon de réception.
  • comm: Communicateur sur lequel les données doivent être échangées.
  • info: Informations (handle, persistant seulement)

PARAMÈTRES DE SORTIE

  • recvbuf: Adresse du tampon de réception.
  • request: Requête (handle, non bloquant seulement).
  • ierror: Fortran seulement : Statut d'erreur.

DESCRIPTION

MPI_Alltoallv est une opération collective généralisée dans laquelle tous les processus envoient des données à tous les autres processus et en reçoivent de tous les autres processus. Elle ajoute de la flexibilité à MPI_Alltoall en permettant à l'utilisateur de spécifier les données à envoyer et à recevoir de manière vectorielle (via un déplacement et un nombre d'éléments). Le fonctionnement de cette routine peut être envisagé comme suit, où chaque processus effectue 2n (n étant le nombre de processus dans le communicateur comm) communications point à point indépendantes (y compris la communication avec lui-même).

MPI_Comm_size(comm, &n);
for (i = 0, i < n; i++)
    MPI_Send(sendbuf + sdispls[i] * extent(sendtype),
        sendcounts[i], sendtype, i, ..., comm);
for (i = 0, i < n; i++)
    MPI_Recv(recvbuf + rdispls[i] * extent(recvtype),
        recvcounts[i], recvtype, i, ..., comm);

Le processus j envoie le k-ième bloc de son sendbuf local au processus k, qui place les données dans le j-ième bloc de son recvbuf local.

Lorsqu'une paire de processus échange des données, chacun peut passer des arguments de nombre d'éléments et de type de données différents, tant que l'expéditeur spécifie la même quantité de données à envoyer (en octets) que celle que le destinataire s'attend à recevoir.

Notez qu'un processus i peut envoyer une quantité de données différente au processus j de celle qu'il reçoit du processus j. De plus, un processus peut envoyer des quantités de données totalement différentes à différents processus du communicateur.

LORSQUE LE COMMUNICATEUR EST UN INTER-COMMUNICATEUR

Lorsque le communicateur est un inter-communicateur, l'opération de collecte se déroule en deux phases. Les données sont collectées auprès de tous les membres du premier groupe et reçues par tous les membres du second groupe. Ensuite, les données sont collectées auprès de tous les membres du second groupe et reçues par tous les membres du premier. L'opération présente un comportement symétrique, full-duplex.

Le premier groupe définit le processus racine. Le processus racine utilise MPI_ROOT comme valeur de root. Tous les autres processus du premier groupe utilisent MPI_PROC_NULL comme valeur de root. Tous les processus du second groupe utilisent le rang du processus racine dans le premier groupe comme valeur de root.

Lorsque le communicateur est un intra-communicateur, ces groupes sont identiques et l'opération se déroule en une seule phase.

UTILISATION DE L'OPTION IN-PLACE

Lorsque le communicateur est un intracommunicateur, vous pouvez effectuer une opération all-to-all en place (le tampon de sortie est utilisé comme tampon d'entrée). Utilisez la variable MPI_IN_PLACE comme valeur de sendbuf. Dans ce cas, sendcounts, sdispls et sendtype sont ignorés. Les données d'entrée de chaque processus sont supposées se trouver dans la zone où ce processus recevrait sa propre contribution au tampon de réception.

NOTES

La spécification des comptes et des déplacements ne doit pas entraîner l'écriture d'un emplacement plus d'une fois.

Tous les arguments sur tous les processus sont significatifs. Le comm argument, en particulier, doit décrire le même communicateur sur tous les processus.

Les décalages de sdispls et rdispls sont mesurés en unités de sendtype et recvtype, respectivement. Comparez ceci avec MPI_Alltoallw, où ces décalages sont mesurés en octets.

INPUT PARAMETERS

sendbuf
début de la mémoire tampon d'envoi (pointeur de type void *).
sendcounts
tableau d'entiers indiquant le nombre d'éléments envoyés à chaque rang (tableau d'entiers).
displs
tableau d'entiers indiquant les déplacements des données dans la mémoire tampon d'envoi pour chaque rang (tableau d'entiers).
sendtypes
tableau de types de données MPI indiquant le type de chaque bloc envoyé à chaque rang (tableau de MPI_Datatype).
recvbuf
début de la mémoire tampon de réception (pointeur de type void *).
recvcounts
tableau d'entiers indiquant le nombre d'éléments reçus de chaque rang (tableau d'entiers).
recvdispls
tableau d'entiers indiquant les déplacements des données dans la mémoire tampon de réception pour chaque rang (tableau d'entiers).
recvtypes
tableau de types de données MPI indiquant le type de chaque bloc reçu de chaque rang (tableau de MPI_Datatype).
comm
communicateur MPI (MPI_Comm).

OUTPUT PARAMETERS

Aucune (la fonction retourne un entier).

DESCRIPTION

La fonction MPI_Alltoallv est une opération collective qui permet à chaque processus d'envoyer un ensemble de blocs de données à chaque autre processus et de recevoir un ensemble de blocs de données de chaque autre processus. Les données envoyées et reçues par chaque processus peuvent être de tailles et de types différents pour chaque destinataire.

Spécifiquement, le i-ème processus envoie un bloc de données composé de sendcounts[j] éléments de type sendtypes[j] à l'offset displs[j] dans son tampon d'envoi, à destination du processus j. Simultanément, le i-ème processus reçoit un bloc de données composé de recvcounts[j] éléments de type recvtypes[j] à l'offset recvdispls[j] dans son tampon de réception, provenant du processus j.

Tous les processus doivent appeler MPI_Alltoallv avec les mêmes arguments comm. Les arguments sendbuf, sendcounts, displs, sendtypes, recvbuf, recvcounts, recvdispls et recvtypes peuvent être différents sur chaque processus.

USE OF IN-PLACE OPTION

Lorsque le paramètre sendbuf est le même que le paramètre recvbuf, les données sont considérées comme étant "in-place". Dans ce cas, les données envoyées sont placées dans le tampon de réception à la bonne position, comme si une opération MPI_Alltoallv avait eu lieu sans l'option "in-place". Les données d'origine dans le tampon seront écrasées. L'opération est effectuée comme si le tampon contenait d'abord les données envoyées, puis les données reçues sont écrites par-dessus.

NOTES

Les types de données MPI spécifiés par sendtypes et recvtypes doivent être des types de données pleinement compatibles. En particulier, les counts et les displacements doivent être calculés correctement pour chaque processus afin que les données arrivent à la bonne destination et soient correctement interprétées.

Il est de la responsabilité de l'application de s'assurer que les tampons d'envoi et de réception sont suffisamment grands pour contenir toutes les données échangées.

ERRORS

Lorsqu'une erreur se produit dans une routine MPI, le gestionnaire d'erreurs associé à la communication est appelé. Avant le retour de la valeur d'erreur, le gestionnaire d'erreurs actuel associé à l'objet de communication (par exemple, communicateur, fenêtre, fichier) est appelé. S'il n'y a pas d'objet de communication associé à l'appel MPI, alors l'appel est considéré comme attaché à MPI_COMM_SELF et appellera le gestionnaire d'erreurs MPI associé. Lorsque MPI_COMM_SELF n'est pas initialisé (c'est-à-dire avant MPI_Init/MPI_Init_thread, après MPI_Finalize, ou lors de l'utilisation exclusive du modèle de sessions), l'erreur déclenche le gestionnaire d'erreurs initial. Le gestionnaire d'erreurs initial peut être modifié en appelant MPI_Comm_set_errhandler sur MPI_COMM_SELF lors de l'utilisation du modèle World, ou l'argument de ligne de commande mpi_initial_errhandler pour mpiexec ou la clé d'information pour MPI_Comm_spawn/MPI_Comm_spawn_multiple. Si aucun autre gestionnaire d'erreurs approprié n'a été défini, alors le gestionnaire d'erreurs MPI_ERRORS_RETURN est appelé pour les fonctions d'E/S MPI et le gestionnaire d'erreurs MPI_ERRORS_ABORT est appelé pour toutes les autres fonctions MPI.

Open MPI inclut trois gestionnaires d'erreurs prédéfinis qui peuvent être utilisés :

  • MPI_ERRORS_ARE_FATAL Provoque l'abandon de tous les processus MPI connectés par le programme.
  • MPI_ERRORS_ABORT Un gestionnaire d'erreurs qui peut être invoqué sur un communicateur, une fenêtre, un fichier ou une session. Lorsqu'il est appelé sur un communicateur, il agit comme si MPI_Abort avait été appelé sur ce communicateur. S'il est appelé sur une fenêtre ou un fichier, il agit comme si MPI_Abort avait été appelé sur un communicateur contenant le groupe de processus dans la fenêtre ou le fichier correspondant. S'il est appelé sur une session, il n'abandonne que le processus local.
  • MPI_ERRORS_RETURN Renvoie un code d'erreur à l'application.

Les applications MPI peuvent également implémenter leurs propres gestionnaires d'erreurs en appelant :

  • MPI_Comm_create_errhandler puis MPI_Comm_set_errhandler
  • MPI_File_create_errhandler puis MPI_File_set_errhandler
  • MPI_Session_create_errhandler puis MPI_Session_set_errhandler ou à MPI_Session_init
  • MPI_Win_create_errhandler puis MPI_Win_set_errhandler

Notez que MPI ne garantit pas qu'un programme MPI puisse continuer après une erreur.

Voir la page de manuel MPI pour une liste complète des codes d'erreur MPI.

Voir la section Gestion des erreurs de la norme MPI-3.1 pour plus d'informations.
