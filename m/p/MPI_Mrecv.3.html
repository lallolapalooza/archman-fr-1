MPI_Mrecv — Réception bloquante pour un message correspondant

SYNTAX

Syntaxe C

#include <mpi.h>
int MPI_Mrecv(void *buf, int count, MPI_Datatype type,
     MPI_Message *message, MPI_Status *status)

Syntaxe Fortran

USE MPI
! ou l'ancienne forme : INCLUDE 'mpif.h'
MPI_MRECV(BUF, COUNT, DATATYPE, MESSAGE, STATUS, IERROR)
     <type>  BUF(*)
     INTEGER COUNT, DATATYPE, MESSAGE
     INTEGER STATUS(MPI_STATUS_SIZE), IERROR

Syntaxe Fortran 2008

USE mpi_f08
MPI_Mrecv(buf, count, datatype, message, status, ierror)
     TYPE(*), DIMENSION(..) :: buf
     INTEGER, INTENT(IN) :: count
     TYPE(MPI_Datatype), INTENT(IN) :: datatype
     TYPE(MPI_Message), INTENT(INOUT) :: message
     TYPE(MPI_Status) :: status
     INTEGER, OPTIONAL, INTENT(OUT) :: ierror

PARAMÈTRES D'ENTRÉE

  • count: Nombre d'éléments à recevoir (entier non négatif).
  • datatype: Type de données de chaque élément du tampon d'envoi (handle).
  • message: Message (handle).

PARAMÈTRES DE SORTIE

  • buf: Adresse initiale du tampon de réception (choix).
  • status: Objet de statut (statut).
  • ierror: Fortran uniquement : statut d'erreur (entier).

DESCRIPTION

Les fonctions MPI_Mrecv et MPI_Imrecv reçoivent des messages qui ont été précédemment mis en correspondance par une sonde de mise en correspondance.

Si MPI_Mrecv est appelée avec MPI_MESSAGE_NULL comme argument de message, l'appel retourne immédiatement avec l'objet status défini à source = MPI_PROC_NULL, tag = MPI_ANY_TAG et count = 0, comme si une réception depuis MPI_PROC_NULL avait été émise.

Si votre application n'a pas besoin d'examiner le champ status, vous pouvez économiser des ressources en utilisant la constante prédéfinie MPI_STATUS_IGNORE comme valeur spéciale pour l'argument status.

ERREURS

Presque toutes les routines MPI retournent une valeur d'erreur ; les routines C comme résultat de retour de la fonction et les routines Fortran dans le dernier argument.

Avant que la valeur d'erreur ne soit retournée, le gestionnaire d'erreurs MPI actuel associé à l'objet de communication (par exemple, communicateur, fenêtre, fichier) est appelé. Si aucun objet de communication n'est associé à l'appel MPI, alors l'appel est considéré comme attaché à MPI_COMM_SELF et appellera le gestionnaire d'erreurs MPI associé. Lorsque MPI_COMM_SELF n'est pas initialisé (c'est-à-dire avant MPI_Init/MPI_Init_thread, après MPI_Finalize, ou lors de l'utilisation exclusive du modèle Sessions) l'erreur déclenche le gestionnaire d'erreurs initial. Le gestionnaire d'erreurs initial peut être modifié en appelant MPI_Comm_set_errhandler sur MPI_COMM_SELF lors de l'utilisation du modèle World, ou l'argument CLI mpi_initial_errhandler à mpiexec ou la clé d'info à MPI_Comm_spawn/MPI_Comm_spawn_multiple. Si aucun autre gestionnaire d'erreurs approprié n'a été défini, le gestionnaire d'erreurs MPI_ERRORS_RETURN est appelé pour les fonctions d'E/S MPI et le gestionnaire d'erreurs MPI_ERRORS_ABORT est appelé pour toutes les autres fonctions MPI.

Open MPI inclut trois gestionnaires d'erreurs prédéfinis qui peuvent être utilisés :

  • MPI_ERRORS_ARE_FATAL Provoque l'arrêt de tous les processus MPI connectés par le programme.
  • MPI_ERRORS_ABORT Un gestionnaire d'erreurs qui peut être invoqué sur un communicateur, une fenêtre, un fichier ou une session. Lorsqu'il est appelé sur un communicateur, il agit comme si MPI_Abort avait été appelé sur ce communicateur. S'il est appelé sur une fenêtre ou un fichier, il agit comme si MPI_Abort avait été appelé sur un communicateur contenant le groupe de processus dans la fenêtre ou le fichier correspondant. S'il est appelé sur une session, il n'arrête que le processus local.
  • MPI_ERRORS_RETURN Retourne un code d'erreur à l'application.

Les applications MPI peuvent également implémenter leurs propres gestionnaires d'erreurs en appelant :

  • MPI_Comm_create_errhandler puis MPI_Comm_set_errhandler
  • MPI_File_create_errhandler puis MPI_File_set_errhandler
  • MPI_Session_create_errhandler puis MPI_Session_set_errhandler ou à MPI_Session_init
  • MPI_Win_create_errhandler puis MPI_Win_set_errhandler

Notez que MPI ne garantit pas qu'un programme MPI puisse continuer après une erreur.

Voir la page man MPI pour une liste complète des codes d'erreur MPI.

Voir la section Gestion des erreurs de la norme MPI-3.1 pour plus d'informations.

Notez que, conformément à la section « Statut de retour » du chapitre « Communication point à point » de la norme MPI, les erreurs MPI sur les messages reçus par MPI_Mrecv ne définissent pas le champ status.MPI_ERROR dans le statut retourné. Le code d'erreur est toujours transmis au gestionnaire d'erreurs backend et peut être renvoyé à l'appelant via la valeur de retour de MPI_Mrecv si le gestionnaire d'erreurs backend le retourne. Le gestionnaire d'erreurs MPI prédéfini MPI_ERRORS_RETURN présente ce comportement, par exemple.
