MPI_COMM_DUP_WITH_INFO(3) Open MPI MPI_COMM_DUP_WITH_INFO(3)

MPI_Comm_dup_with_info — Duplique un communicateur existant en utilisant les informations fournies.

SYNTAXE

Syntaxe C

#include <mpi.h>
int MPI_Comm_dup_with_info(MPI_Comm comm, MPI_Info info, MPI_Comm *newcomm)

Syntaxe Fortran

USE MPI
! ou la forme plus ancienne : INCLUDE 'mpif.h'
MPI_COMM_DUP_WITH_INFO(COMM, INFO, NEWCOMM, IERROR)
    INTEGER COMM, INFO, NEWCOMM, IERROR

Syntaxe Fortran 2008

USE mpi_f08
MPI_Comm_dup_with_info(comm, info, newcomm, ierror)
    TYPE(MPI_Comm), INTENT(IN) :: comm
    TYPE(MPI_Info), INTENT(IN) :: info
    TYPE(MPI_Comm), INTENT(OUT) :: newcomm
    INTEGER, OPTIONAL, INTENT(OUT) :: ierror

PARAMETRE D'ENTRÉE

  • comm : Communicateur (descripteur).
  • info : Argument d'information (descripteur).

PARAMÈTRES DE SORTIE

  • newcomm : Copie de comm (descripteur).
  • ierror : Fortran uniquement : Statut d'erreur (entier).

DESCRIPTION

MPI_Comm_dup_with_info agit exactement comme MPI_Comm_dup, sauf que les indices d'information associés au communicateur comm ne sont pas dupliqués dans newcomm. Les indices fournis par l'argument info sont associés au communicateur de sortie newcomm à la place. Voir MPI_Comm_set_info pour la liste des clés d'information reconnues.

NOTES

Cette opération est utilisée pour fournir à un appel de bibliothèque parallèle un espace de communication dupliqué qui possède les mêmes propriétés que le communicateur d'origine. Cela inclut tous les attributs (voir ci-dessous) et topologies (voir le chapitre « Topologies de processus » dans la Norme MPI. Cet appel est valide même s'il existe des communications point à point en attente impliquant le communicateur comm. Un appel typique pourrait impliquer un MPI_Comm_dup_with_info au début de l'appel parallèle, et un MPI_Comm_free de ce communicateur dupliqué à la fin de l'appel. D'autres modèles de gestion de communicateur sont également possibles. Cet appel s'applique aux intra- et intercommunicateurs. Notez qu'il n'est pas défini par la norme MPI ce qui se passe si la fonction de rappel de copie d'attributs invoque d'autres fonctions MPI. Dans Open MPI, il n'est pas valide pour les fonctions de rappel de copie d'attributs (ou l'un de leurs enfants) d'ajouter ou de supprimer des attributs sur le même objet sur lequel la fonction de rappel de copie d'attributs est invoquée.

ERREURS

Presque toutes les routines MPI retournent une valeur d'erreur ; les routines C en tant que résultat de retour de la fonction et les routines Fortran dans le dernier argument.

Avant que la valeur d'erreur ne soit retournée, le gestionnaire d'erreurs MPI actuel associé à l'objet de communication (par exemple, communicateur, fenêtre, fichier) est appelé. Si aucun objet de communication n'est associé à l'appel MPI, l'appel est considéré comme attaché à MPI_COMM_SELF et appellera le gestionnaire d'erreurs MPI associé. Lorsque MPI_COMM_SELF n'est pas initialisé (c'est-à-dire avant MPI_Init/MPI_Init_thread, après MPI_Finalize, ou lors de l'utilisation exclusive du modèle de Sessions), l'erreur déclenche le gestionnaire d'erreurs initial. Le gestionnaire d'erreurs initial peut être modifié en appelant MPI_Comm_set_errhandler sur MPI_COMM_SELF lors de l'utilisation du modèle World, ou par l'argument CLI mpi_initial_errhandler de mpiexec ou par la clé d'information de MPI_Comm_spawn/MPI_Comm_spawn_multiple. Si aucun autre gestionnaire d'erreurs approprié n'a été défini, alors le gestionnaire d'erreurs MPI_ERRORS_RETURN est appelé pour les fonctions E/S MPI et le gestionnaire d'erreurs MPI_ERRORS_ABORT est appelé pour toutes les autres fonctions MPI.

Open MPI inclut trois gestionnaires d'erreurs prédéfinis qui peuvent être utilisés :

  • MPI_ERRORS_ARE_FATAL Provoque l'arrêt du programme de tous les processus MPI connectés.
  • MPI_ERRORS_ABORT Un gestionnaire d'erreurs qui peut être invoqué sur un communicateur, une fenêtre, un fichier ou une session. Lorsqu'il est appelé sur un communicateur, il agit comme si MPI_Abort avait été appelé sur ce communicateur. S'il est appelé sur une fenêtre ou un fichier, il agit comme si MPI_Abort avait été appelé sur un communicateur contenant le groupe des processus dans la fenêtre ou le fichier correspondant. S'il est appelé sur une session, il n'interrompt que le processus local.
  • MPI_ERRORS_RETURN Retourne un code d'erreur à l'application.

Les applications MPI peuvent également implémenter leurs propres gestionnaires d'erreurs en appelant :

  • MPI_Comm_create_errhandler puis MPI_Comm_set_errhandler
  • MPI_File_create_errhandler puis MPI_File_set_errhandler
  • MPI_Session_create_errhandler puis MPI_Session_set_errhandler ou à MPI_Session_init
  • MPI_Win_create_errhandler puis MPI_Win_set_errhandler

Notez que MPI ne garantit pas qu'un programme MPI puisse continuer après une erreur.

Voir la page man MPI pour une liste complète des codes d'erreur MPI.

Voir la section Gestion des erreurs de la norme MPI-3.1 pour plus d'informations.
