MPI_Scatter, MPI_Iscatter, MPI_Scatter_init - Envoie des données d'un processus à tous les processus d'un groupe.

SYNTAXE

Syntaxe C

#include <mpi.h>

     void *recvbuf, int recvcount, MPI_Datatype recvtype, int root,

int MPI_Iscatter(const void *sendbuf, int sendcount, MPI_Datatype sendtype,
     void *recvbuf, int recvcount, MPI_Datatype recvtype, int root,
     MPI_Comm comm, MPI_Request *request)
int MPI_Scatter_init(const void *sendbuf, int sendcount, MPI_Datatype sendtype,
     void *recvbuf, int recvcount, MPI_Datatype recvtype, int root,
     MPI_Comm comm, MPI_Info info, MPI_Request *request)

PARAMÈTRES D'ENTRÉE

  • sendbuf: Adresse du tampon d'envoi (facultatif, seulement significatif sur le processus racine).
  • sendcount: Nombre d'éléments envoyés à chaque processus (entier, seulement significatif sur le processus racine).
  • sendtype: Type des éléments dans le tampon d'envoi (handle, seulement significatif sur le processus racine).
  • recvcount: Nombre d'éléments dans le tampon de réception (entier).
  • recvtype: Type des éléments dans le tampon de réception (handle).
  • root: Rang du processus d'envoi (entier).
  • comm: Communicateur (handle).
  • info: Informations (handle, persistant).

PARAMÈTRES DE SORTIE

  • recvbuf: Adresse du tampon de réception (facultatif).
  • request: Requête (handle, non bloquante).
  • ierror: Seulement en Fortran : Statut d'erreur (entier).

DESCRIPTION

MPI_Scatter est l'opération inverse de MPI_Gather.

Le résultat est comme si le processus racine avait exécuté n opérations d'envoi.

MPI_Send(sendbuf + i * sendcount * extent(sendtype), sendcount,
         sendtype, i, ...);

et chaque processus avait exécuté une réception.

MPI_Recv(recvbuf, recvcount, recvtype, i, ...).;

Une description alternative est que le processus racine envoie un message avec MPI_Send(sendbuf, sendcount * n, sendtype, ...), qui est divisé en n segments égaux, le segment i est envoyé au i-ème processus du groupe, et chaque processus reçoit ce message comme ci-dessus.

Le tampon d'envoi est ignoré pour tous les processus sauf le processus racine.

Les types de signature associés à sendcount, sendtype à la racine doivent être égaux aux types de signature associés à recvcount, recvtype sur tous les processus (bien que les mappages de type puissent être différents). Cela implique que la quantité de données envoyées doit être égale à la quantité de données reçues, par paire de processus et la racine. Des mappages de type distincts entre l'émetteur et le récepteur sont toujours autorisés.

Tous les arguments de la fonction sont significatifs sur le processus racine, tandis que sur les autres processus, seuls les arguments recvbuf, recvcount, recvtype, root, comm sont significatifs. Les arguments root et comm doivent avoir les mêmes valeurs sur tous les processus.

La spécification des décomptes et des types ne doit pas provoquer la lecture d'un emplacement du processus racine plus d'une fois.

Pourquoi ? Bien que non strictement nécessaire, la dernière restriction est imposée pour obtenir une symétrie avec MPI_Gather, où la restriction correspondante (une écriture multiple) est nécessaire.

Exemple : L'inverse de l'exemple 1 de la page de manuel MPI_Gather. La diffusion de 100 entiers de la racine vers chaque processus du groupe.

MPI_Comm comm;
int gsize,*sendbuf;
int root, rbuf[100];
...
MPI_Comm_size(comm, &gsize);
sendbuf = (int *)malloc(gsize*100*sizeof(int));
...
MPI_Scatter(sendbuf, 100, MPI_INT, rbuf, 100,
            MPI_INT, root, comm);

UTILISATION DE L'OPTION IN-PLACE

Lorsque le communicateur est un intracommunicateur, vous pouvez effectuer une opération de diffusion au lieu d'utiliser le tampon de réception comme tampon d'envoi. Utilisez la variable MPI_IN_PLACE comme valeur de recvbuf sur le processus racine. Dans ce cas, recvcount et recvtype sont ignorés, et le processus racine ne s'envoie pas de données à lui-même.

Note : MPI_IN_PLACE est un type de valeur spécial ; il a les mêmes restrictions d'utilisation que MPI_BOTTOM.

Comme l'option in-place transforme le tampon de réception en un tampon d'envoi et de réception, une liaison Fortran incluant INTENT doit les marquer comme INOUT, et non OUT.

QUAND LE COMMUNICATEUR EST UN INTER-COMMUNICATEUR

Lorsque le communicateur est un inter-communicateur, le processus racine du premier groupe envoie des données à tous les processus du second groupe. Le premier groupe définit le processus racine. Ce processus utilise MPI_ROOT comme valeur de son argument root. Les processus restants utilisent MPI_PROC_NULL comme valeur de leur argument root. Tous les processus du second groupe utilisent le rang du processus racine du premier groupe comme valeur de leur argument root. L'argument du tampon de réception du processus racine du premier groupe doit être cohérent avec l'argument du tampon de réception des processus du second groupe.

ERREURS

Presque toutes les routines MPI renvoient une valeur d'erreur ; en C, le résultat de la fonction et en Fortran, le dernier argument.

Avant de renvoyer la valeur d'erreur, le gestionnaire d'erreurs associé à l'objet de communication (par exemple, le communicateur, la fenêtre, le fichier) est appelé. S'il n'y a pas d'objet de communication associé à l'appel MPI, l'appel est considéré comme associé à MPI_COMM_SELF et le gestionnaire associé est appelé.

SYNTAXE

La syntaxe suivante est utilisée :

MPI_Scatter_init( int count, sendbuf, recvbuf, root, errhandler )

PARAMÈTRES D'ENTRÉE

Les paramètres d'entrée sont :

int count
void * sendbuf
void * recvbuf
int root
void * errhandler

PARAMÈTRES DE SORTIE

Les paramètres de sortie sont :

int errcode

DESCRIPTION

Cette fonction initialise un gestionnaire d'erreurs pour le communicateur spécifié.

UTILISATION DE L'OPTION IN-PLACE

L'option d'utilisation in-place peut être utilisée avec cette fonction.

QUAND LE COMMUNICATEUR EST UN INTER-COMMUNICATEUR

Si le communicateur spécifié est un inter-communicateur, la fonction renvoie une valeur d'erreur.
