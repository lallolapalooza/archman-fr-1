MPI_Allgather, MPI_Iallgather, MPI_Allgather_init - Collectent des données de tous les processus et les distribuent à tous.

Paramètres d'entrée

  • sendbuf: Adresse de départ du buffer d'envoi (facultatif).
  • sendcount: Nombre d'éléments dans le buffer d'envoi (entier).
  • sendtype: Type des éléments dans le buffer d'envoi (handle).
  • recvbuf: Adresse de départ du buffer de réception (facultatif).
  • recvcount: Nombre d'éléments reçus de n'importe quel processus (entier).
  • recvtype: Type des éléments dans le buffer de réception (handle).
  • comm: Communicateur (handle).
  • info: Informations (handle, persistant uniquement).

Paramètres de sortie

  • recvbuf: Adresse du buffer de réception (facultatif).
  • request: Requête (handle, non bloquant uniquement).
  • ierror: Seulement en Fortran : Code d'erreur (entier).

Description

MPI_Allgather est similaire à MPI_Gather, mais tous les processus reçoivent le résultat, pas seulement le root. En d'autres termes, tous les processus contribuent au résultat et tous les processus reçoivent le résultat.

La signature de type associée à sendcount, sendtype sur un processus doit être égale à la signature de type associée à recvcount, recvtype sur tout autre processus.

Le résultat d'un appel à MPI_Allgather est identique à celui obtenu si tous les processus avaient exécuté n appels à

MPI_Gather(sendbuf, sendcount, sendtype, recvbuf, recvcount,
           recvtype, root, comm);
// pour root = 0, ..., n-1.

Les règles pour une utilisation correcte de MPI_Allgather peuvent être facilement déduites des règles correspondantes de MPI_Gather.

Exemple : Version all-gather de l'exemple 1 dans MPI_Gather. En utilisant MPI_Allgather, nous collecterons 100 entiers de chaque processus du groupe vers chaque processus.

MPI_Comm comm;
int gsize,sendarray[100];
int *rbuf;
...
MPI_Comm_size( comm, &gsize);
rbuf = (int *)malloc(gsize*100*sizeof(int));
MPI_Allgather( sendarray, 100, MPI_INT, rbuf, 100, MPI_INT, comm);

Après l'appel, chaque processus possède la concaténation des ensembles de données de tous les processus.

Utilisation de l'option dans le buffer

Lorsque le communicateur est un intracommunicateur, vous pouvez effectuer une opération de rassemblement dans le buffer (le buffer de réception est utilisé comme buffer d'envoi). Utilisez la variable MPI_IN_PLACE comme valeur pour sendbuf. Dans ce cas, sendcount et sendtype sont ignorés. Les données d'entrée de chaque processus sont supposées se trouver dans la zone où ce processus recevra sa propre contribution au buffer de réception. Spécifiquement, le résultat d'un appel à MPI_Allgather utilisant l'option dans le buffer est identique au cas où tous les processus auraient exécuté n appels à

MPI_Allgather( MPI_IN_PLACE, 0, MPI_DATATYPE_NULL, recvbuf,
               recvcount, recvtype, root, comm )
// pour root = 0, ... , n-1.

Remarque : MPI_IN_PLACE est une valeur de type spécial ; elle a les mêmes restrictions que MPI_BOTTOM.

Étant donné que l'option dans le buffer transforme le buffer de réception en un buffer d'envoi et de réception, une liaison Fortran incluant INTENT doit les marquer comme INOUT, et non comme OUT.

Lorsque le communicateur est un inter-communicateur

Lorsque le communicateur est un inter-communicateur, l'opération de rassemblement se déroule en deux phases. Les données sont collectées auprès de tous les membres du premier groupe et reçues par tous les membres du second groupe. Ensuite, les données sont collectées auprès de tous les membres du second groupe et reçues par tous les membres du premier groupe. Cependant, l'opération n'a pas besoin d'être symétrique. Le nombre d'éléments envoyés par les processus du premier groupe n'a pas nécessairement besoin d'être égal au nombre d'éléments envoyés par les processus du second groupe. Vous pouvez déplacer les données dans une seule direction en donnant une valeur de 0 à sendcount pour la direction inverse.

Erreurs

La quasi-totalité des routines MPI renvoient une valeur d'erreur ; les routines C renvoient le résultat de la fonction et les routines Fortran le dernier argument.

Avant de renvoyer la valeur d'erreur, le gestionnaire d'erreurs actuel associé à l'objet de communication (par exemple, communicateur, fenêtre, fichier) est appelé. S'il n'y a pas d'objet de communication associé à l'appel MPI, l'appel est considéré comme associé à MPI_COMM_SELF et le gestionnaire d'erreurs associé à MPI_COMM_SELF est appelé. Lorsque MPI_COMM_SELF n'est pas initialisé (c'est-à-dire avant MPI_Init/MPI_Init_thread, après MPI_Finalize, ou lorsque le modèle de Sessions est utilisé exclusivement), l'erreur déclenche le gestionnaire d'erreurs initial. Le gestionnaire d'erreurs initial peut être modifié en appelant MPI_Comm_set_errhandler sur MPI_COMM_SELF lorsque le modèle du Monde est utilisé, ou avec l'argument mpi_initial_errhandler de mpiexec, ou avec la clé info de MPI_Comm_spawn/MPI_Comm_spawn_multiple. S'il n'y a pas d'autre gestionnaire d'erreurs approprié, le gestionnaire d'erreurs MPI_ERRORS_RETURN est appelé pour les fonctions d'E/S MPI.

SYNTAXE

Le gestionnaire d'erreurs est appelé MPI_ERRORS_ABORT pour toutes les autres fonctions MPI.

PARAMÈTRES D'ENTRÉE

Open MPI inclut trois gestionnaires d'erreurs prédéfinis qui peuvent être utilisés :

  • MPI_ERRORS_ARE_FATAL Désactive la communication sur tous les processus connectés.
  • MPI_ERRORS_ABORT Un gestionnaire d'erreurs qui peut être invoqué sur un communicateur, une fenêtre, un fichier ou une session. Lorsqu'il est invoqué sur un communicateur, il agit comme si MPI_Abort avait été appelé sur ce communicateur. S'il est invoqué sur une fenêtre ou un fichier, il agit comme si MPI_Abort avait été appelé sur un communicateur contenant le groupe de processus dans la fenêtre ou le fichier correspondant. S'il est invoqué sur une session, seul le processus local est arrêté.
  • MPI_ERRORS_RETURN Renvoie un code d'erreur au programme.

Des gestionnaires d'erreurs personnalisés peuvent également être mis en œuvre en appelant :

  • MPI_Comm_create_errhandler puis MPI_Comm_set_errhandler
  • MPI_File_create_errhandler puis MPI_File_set_errhandler
  • MPI_Session_create_errhandler puis MPI_Session_set_errhandler ou dans MPI_Session_init
  • MPI_Win_create_errhandler puis MPI_Win_set_errhandler

Note : MPI ne garantit pas qu'un programme puisse continuer après une erreur.

Voir la section MPI man page pour une liste complète des MPI error codes.

Voir la section Gestion des erreurs de la norme MPI-3.1 pour plus d'informations.
