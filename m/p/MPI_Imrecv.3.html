MPI_Imrecv(3) Open MPI MPI_Imrecv(3)

MPI_Imrecv — Réception de message non bloquante pour un message déjà sondé

Syntaxe

Syntaxe C

#include <mpi.h>
int MPI_Imrecv(void *buf, int count, MPI_Datatype type,
     MPI_Message *message, MPI_Request *request)

Syntaxe Fortran

USE MPI
! ou l'ancienne forme : INCLUDE 'mpif.h'
MPI_IMRECV(BUF, COUNT, DATATYPE, MESSAGE, REQUEST, IERROR)
     <type>  BUF(*)
     INTEGER COUNT, DATATYPE, MESSAGE, REQUEST, IERROR

Syntaxe Fortran 2008

USE mpi_f08
MPI_Imrecv(buf, count, datatype, message, request, ierror)
     TYPE(*), DIMENSION(..), ASYNCHRONOUS :: buf
     INTEGER, INTENT(IN) :: count
     TYPE(MPI_Datatype), INTENT(IN) :: datatype
     TYPE(MPI_Message), INTENT(INOUT) :: message
     TYPE(MPI_Request), INTENT(OUT) :: request
     INTEGER, OPTIONAL, INTENT(OUT) :: ierror

Paramètres d'entrée

  • count: Nombre d'éléments à recevoir (entier non négatif).
  • datatype: Type de données de chaque élément du tampon de réception (handle).
  • message: Message (handle).

Paramètres de sortie

  • buf: Adresse initiale du tampon de réception (optionnel).
  • request: Requête (handle).
  • ierror: Uniquement en Fortran : Code d'erreur (entier).

Description

Les fonctions MPI_Mrecv et MPI_Imrecv reçoivent des messages qui ont été préalablement sondés par une sonde de correspondance.

Le request renvoyé par MPI_Imrecv peut être utilisé avec n'importe quelle variante de MPI_Test ou MPI_Wait, comme toute requête de réception non bloquante.

Si MPI_Imrecv est appelée avec MPI_MESSAGE_NULL comme argument de message, un appel à l'une des variantes de MPI_Test ou MPI_Wait retournera immédiatement avec l'objet status défini sur source = MPI_PROC_NULL, tag = MPI_ANY_TAG, et count = 0, comme si une réception depuis MPI_PROC_NULL avait été émise.

Si la réception d'un message sondé a été initiée avec MPI_Imrecv, il est possible d'annuler la requête retournée avec MPI_Cancel. Si MPI_Cancel réussit, le message sondé doit être retrouvé via une sonde ultérieure (MPI_Probe, MPI_Iprobe, MPI_Mprobe, ou MPI_Improbe), reçu par une opération de réception ultérieure, ou annulé par l'expéditeur.

Cependant, il est possible que l'annulation des opérations initiées avec MPI_Imrecv échoue. Un exemple de cas d'échec est lorsque l'annulation de la réception du message sondé violerait les règles d'ordonnancement des messages MPI (par exemple, si un autre message ayant la même signature de message a été sondé avant que cet MPI_Imrecv ne soit annulé).

Si votre application n'a pas besoin d'examiner le champ status, vous pouvez économiser des ressources en utilisant la constante prédéfinie MPI_STATUS_IGNORE comme valeur spéciale pour l'argument status.

Erreurs

Plutôt que les routines MPI retournent une valeur d'erreur ; les routines C retournent la valeur de retour de la fonction et les routines Fortran dans le dernier argument.

Avant que la valeur d'erreur ne soit retournée, le gestionnaire d'erreur associé à l'objet de communication (par exemple, communicateur, fenêtre, fichier) actuel est appelé. S'il n'y a pas d'objet de communication associé à l'appel MPI, l'appel est considéré comme associé à MPI_COMM_SELF et le gestionnaire d'erreur correspondant est appelé. Lorsque MPI_COMM_SELF n'est pas initialisé (c'est-à-dire avant MPI_Init/MPI_Init_thread, après MPI_Finalize, ou lorsque le Modèle de Session est utilisé exclusivement), l'erreur déclenche le gestionnaire d'erreur initial. Le gestionnaire d'erreur initial peut être modifié en appelant MPI_Comm_set_errhandler sur MPI_COMM_SELF lors de l'utilisation du Modèle du Monde, ou l'argument CLI mpi_initial_errhandler pour mpiexec ou la clé info pour MPI_Comm_spawn/MPI_Comm_spawn_multiple. Si aucun autre gestionnaire approprié n'est configuré, le gestionnaire d'erreur MPI_ERRORS_RETURN est appelé pour les fonctions d'E/S MPI et le gestionnaire d'erreur MPI_ERRORS_ABORT pour toutes les autres fonctions MPI.

Open MPI inclut trois gestionnaires d'erreur prédéfinis qui peuvent être utilisés :

  • MPI_ERRORS_ARE_FATAL — Arrête tous les processus MPI connectés.
  • MPI_ERRORS_ABORT — Gestionnaire qui peut être invoqué sur un communicateur, une fenêtre, un fichier ou une session. Lorsqu'il est appelé sur un communicateur, il agit comme si MPI_Abort avait été appelé sur ce communicateur. S'il est appelé sur une fenêtre ou un fichier, il agit comme si MPI_Abort avait été appelé sur un communicateur contenant le groupe de processus dans la fenêtre ou le fichier correspondant. S'il est appelé sur une session, il arrête uniquement le processus local.
  • MPI_ERRORS_RETURN — Renvoie un code d'erreur à l'application.

Les applications MPI peuvent également implémenter leurs propres gestionnaires d'erreur en appelant :

  • MPI_Comm_create_errhandler puis MPI_Comm_set_errhandler
  • MPI_File_create_errhandler puis MPI_File_set_errhandler
  • MPI_Session_create_errhandler puis MPI_Session_set_errhandler ou dans MPI_Session_init
  • MPI_Win_create_errhandler puis MPI_Win_set_errhandler

Note : Les MPI ne garantissent pas qu'un programme MPI puisse continuer après une erreur.

Voir la page de manuel MPI pour une liste complète des codes d'erreur MPI.

Voir la section sur la gestion des erreurs de la spécification MPI-3.1 pour plus d'informations.

Note : Conformément à la section "Retour de statut" de la "Communication point à point" dans le "Standard MPI", les erreurs reçues par MPI_Imrecv ne définissent pas le champ status.MPI_ERROR dans l'objet status retourné. Le code d'erreur est toujours transmis au gestionnaire d'erreur en arrière-plan et peut être retourné à l'appelant via la valeur de retour de MPI_Imrecv si le gestionnaire d'erreur en arrière-plan le renvoie. Le gestionnaire d'erreur prédéfini MPI_ERRORS_RETURN présente par exemple ce comportement.
