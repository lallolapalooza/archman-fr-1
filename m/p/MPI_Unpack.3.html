MPI_Unpack — Désérialise un type de données dans une mémoire contiguë.

SYNTAXE

Syntaxe C

#include <mpi.h>
int MPI_Unpack(const void *inbuf, int insize, int *position,
     void *outbuf, int outcount, MPI_Datatype datatype,
     MPI_Comm comm)

Syntaxe Fortran

USE MPI
! ou la forme plus ancienne : INCLUDE 'mpif.h'
MPI_UNPACK(INBUF, INSIZE, POSITION, OUTBUF, OUTCOUNT,
     DATATYPE, COMM, IERROR)
     <type>  INBUF(*), OUTBUF(*)
     INTEGER INSIZE, POSITION, OUTCOUNT, DATATYPE,
             COMM, IERROR

Syntaxe Fortran 2008

USE mpi_f08
MPI_Unpack(inbuf, insize, position, outbuf, outcount, datatype, comm,
             ierror)
     TYPE(*), DIMENSION(..), INTENT(IN) :: inbuf
     TYPE(*), DIMENSION(..) :: outbuf
     INTEGER, INTENT(IN) :: insize, outcount
     INTEGER, INTENT(INOUT) :: position
     TYPE(MPI_Datatype), INTENT(IN) :: datatype
     TYPE(MPI_Comm), INTENT(IN) :: comm
     INTEGER, OPTIONAL, INTENT(OUT) :: ierror

PARAMÈTRES D'ENTRÉE

  • inbuf: Début du tampon d'entrée (choix).
  • insize: Taille du tampon d'entrée, en octets (entier).
  • outcount: Nombre d'éléments à désérialiser (entier).
  • datatype: Type de données de chaque élément de sortie (descripteur).
  • comm: Communicateur pour le message sérialisé (descripteur).

PARAMÈTRE D'ENTRÉE/SORTIE

•
position: Position actuelle en octets (entier).

PARAMÈTRES DE SORTIE

  • outbuf: Début du tampon de sortie (choix).
  • ierror: Fortran seulement : Statut d'erreur (entier).

DESCRIPTION

Désérialise un message dans le tampon de réception spécifié par outbuf, outcount, datatype à partir de l'espace tampon spécifié par inbuf et insize. Le tampon de sortie peut être n'importe quel tampon de communication autorisé dans MPI_Recv. Le tampon d'entrée est une zone de stockage contiguë contenant insize octets, commençant à l'adresse inbuf. La valeur d'entrée de position est le premier emplacement dans le tampon d'entrée occupé par le message sérialisé. position est incrémenté de la taille du message sérialisé, de sorte que la valeur de sortie de position est le premier emplacement dans le tampon d'entrée après les emplacements occupés par le message qui a été désérialisé. comm est le communicateur utilisé pour recevoir le message sérialisé.

NOTES

Noter la différence entre MPI_Recv et MPI_Unpack : Dans MPI_Recv, l'argument count spécifie le nombre maximum d'éléments pouvant être reçus. Le nombre réel d'éléments reçus est déterminé par la longueur du message entrant. Dans MPI_Unpack, l'argument count spécifie le nombre réel d'éléments à désérialiser ; la « taille » du message correspondant est l'incrément de position. La raison de ce changement est que la « taille du message entrant » n'est pas prédéterminée puisque l'utilisateur décide de la quantité à désérialiser ; ni la « taille du message » à partir du nombre d'éléments à désérialiser n'est facile à déterminer.

Pour comprendre le comportement de la sérialisation (pack) et de la désérialisation (unpack), il est utile de considérer la partie données d'un message comme étant la séquence obtenue en concaténant les valeurs successives envoyées dans ce message. L'opération de sérialisation stocke cette séquence dans l'espace tampon, comme si elle envoyait le message à ce tampon. L'opération de désérialisation récupère cette séquence à partir de l'espace tampon, comme si elle recevait un message de ce tampon. (Il est utile de penser aux fichiers internes Fortran ou sscanf en C pour une fonction similaire.)

Plusieurs messages peuvent être sérialisés successivement dans une unité de sérialisation. Ceci est réalisé par plusieurs appels successifs liés à MPI_Pack, où le premier appel fournit position = 0, et chaque appel successif utilise la valeur de position qui a été sortie par l'appel précédent, et les mêmes valeurs pour outbuf, outcount et comm. Cette unité de sérialisation contient maintenant les informations équivalentes qui auraient été stockées dans un message par un appel d'envoi avec un tampon d'envoi qui est la « concaténation » des tampons d'envoi individuels.

Une unité de sérialisation peut être envoyée en utilisant le type MPI_Packed. N'importe quelle fonction de communication point à point ou collective peut être utilisée pour déplacer la séquence d'octets qui forme l'unité de sérialisation d'un processus à un autre. Cette unité de sérialisation peut maintenant être reçue en utilisant n'importe quelle opération de réception, avec n'importe quel type de données : les règles de correspondance des types sont assouplies pour les messages envoyés avec le type MPI_Packed.

Un message envoyé avec n'importe quel type (y compris MPI_Packed) peut être reçu en utilisant le type MPI_Packed. Un tel message peut ensuite être désérialisé par des appels à MPI_Unpack.

Une unité de sérialisation (ou un message créé par un envoi régulier, « typé ») peut être désérialisé en plusieurs messages successifs. Ceci est réalisé par plusieurs appels successifs liés à MPI_Unpack, où le premier appel fournit position = 0, et chaque appel successif utilise la valeur de position qui a été sortie par l'appel précédent, et les mêmes valeurs pour inbuf, insize et comm.

La concaténation de deux unités de sérialisation n'est pas nécessairement une unité de sérialisation ; ni une sous-chaîne d'une unité de sérialisation n'est nécessairement une unité de sérialisation. Ainsi, on ne peut pas concaténer deux unités de sérialisation puis désérialiser le résultat comme une seule unité de sérialisation ; ni désérialiser une sous-chaîne d'une unité de sérialisation comme une unité de sérialisation distincte. Chaque unité de sérialisation qui a été créée par une séquence d'appels de sérialisation liés ou par un envoi régulier doit être désérialisée en tant qu'unité, par une séquence d'appels de désérialisation liés.

ERREURS

Quasi toutes les routines MPI retournent une valeur d'erreur ; les routines C comme résultat de la fonction et les routines Fortran dans le dernier argument.

Avant que la valeur d'erreur ne soit retournée, le gestionnaire d'erreurs MPI actuel associé à l'objet de communication (par exemple, communicateur, fenêtre, fichier) est appelé. Si aucun objet de communication n'est associé à l'appel MPI, alors l'appel est considéré comme attaché à MPI_COMM_SELF et appellera le gestionnaire d'erreurs MPI associé. Lorsque MPI_COMM_SELF n'est pas initialisé (c'est-à-dire, avant MPI_Init/MPI_Init_thread, après MPI_Finalize, ou lorsque le modèle de Sessions est utilisé exclusivement) l'erreur déclenche le gestionnaire d'erreurs initial. Le gestionnaire d'erreurs initial peut être modifié en appelant MPI_Comm_set_errhandler sur MPI_COMM_SELF lors de l'utilisation du modèle Monde, ou via l'argument CLI mpi_initial_errhandler de mpiexec ou la clé d'information de MPI_Comm_spawn/MPI_Comm_spawn_multiple. Si aucun autre gestionnaire d'erreurs approprié n'a été défini, alors le gestionnaire d'erreurs MPI_ERRORS_RETURN est appelé pour les fonctions d'E/S MPI et le gestionnaire d'erreurs MPI_ERRORS_ABORT est appelé pour toutes les autres fonctions MPI.

Open MPI inclut trois gestionnaires d'erreurs prédéfinis qui peuvent être utilisés :

  • MPI_ERRORS_ARE_FATAL Provoque l'arrêt du programme par tous les processus MPI connectés.
  • MPI_ERRORS_ABORT Un gestionnaire d'erreurs qui peut être invoqué sur un communicateur, une fenêtre, un fichier ou une session. Lorsqu'il est appelé sur un communicateur, il agit comme si MPI_Abort avait été appelé sur ce communicateur. S'il est appelé sur une fenêtre ou un fichier, il agit comme si MPI_Abort avait été appelé sur un communicateur contenant le groupe de processus de la fenêtre ou du fichier correspondant. S'il est appelé sur une session, il n'interrompt que le processus local.
  • MPI_ERRORS_RETURN Retourne un code d'erreur à l'application.

Les applications MPI peuvent également implémenter leurs propres gestionnaires d'erreurs en appelant :

  • MPI_Comm_create_errhandler puis MPI_Comm_set_errhandler
  • MPI_File_create_errhandler puis MPI_File_set_errhandler
  • MPI_Session_create_errhandler puis MPI_Session_set_errhandler ou lors de MPI_Session_init
  • MPI_Win_create_errhandler puis MPI_Win_set_errhandler

Notez que MPI ne garantit pas qu'un programme MPI puisse continuer au-delà d'une erreur
