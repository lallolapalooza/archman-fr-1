MPI_FILE_SET_ATOMICITY(3) Open MPI MPI_FILE_SET_ATOMICITY(3)

MPI_File_set_atomicity — Définit les sémantiques de cohérence pour les opérations d'accès aux données (collectives).

SYNTAXE

Syntaxe C

#include <mpi.h>
int MPI_File_set_atomicity(MPI_File fh, int flag)

Syntaxe Fortran

USE MPI
! ou la forme plus ancienne : INCLUDE 'mpif.h'
MPI_FILE_SET_ATOMICITY(FH, FLAG, IERROR)
     INTEGER FH, FLAG, IERROR

Syntaxe Fortran 2008

USE mpi_f08
MPI_File_set_atomicity(fh, flag, ierror)
     TYPE(MPI_File), INTENT(IN) :: fh
     LOGICAL, INTENT(IN) :: flag
     INTEGER, OPTIONAL, INTENT(OUT) :: ierror

PARAMÈTRES ENTRANTS

  • fh: Handle de fichier (handle).
  • flag: true pour activer le mode atomique, false pour activer le mode non atomique (booléen).

PARAMÈTRE SORTANT

•
ierror: Fortran uniquement : Statut d'erreur (entier).

DESCRIPTION

Les sémantiques de cohérence pour les opérations d'accès aux données en utilisant l'ensemble des handles de fichiers créés par un MPI_File_open collectif sont définies en appelant collectivement MPI_File_set_atomicity. Tous les processus du groupe doivent passer des valeurs identiques pour fh et flag. Si flag est true, le mode atomique est défini ; si flag est false, le mode non atomique est défini.

La valeur par défaut lors d'un appel à MPI_File_open dans Open MPI est true pour les jobs s'exécutant sur plus d'un nœud, false pour les jobs s'exécutant sur un seul SMP. Pour plus d'informations, voir la norme MPI-2.

ERREURS

Presque toutes les routines MPI retournent une valeur d'erreur ; les routines C comme résultat de la fonction et les routines Fortran dans le dernier argument.

Avant que la valeur d'erreur ne soit retournée, le gestionnaire d'erreur MPI actuel associé à l'objet de communication (par exemple, communicateur, fenêtre, fichier) est appelé. Si aucun objet de communication n'est associé à l'appel MPI, alors l'appel est considéré comme attaché à MPI_COMM_SELF et appellera le gestionnaire d'erreur MPI associé. Lorsque MPI_COMM_SELF n'est pas initialisé (c'est-à-dire, avant MPI_Init/MPI_Init_thread, après MPI_Finalize, ou lorsque le modèle de Sessions est utilisé exclusivement) l'erreur déclenche le gestionnaire d'erreur initial. Le gestionnaire d'erreur initial peut être modifié en appelant MPI_Comm_set_errhandler sur MPI_COMM_SELF lorsque le modèle World est utilisé, ou l'argument CLI mpi_initial_errhandler de mpiexec ou la clé info de MPI_Comm_spawn/MPI_Comm_spawn_multiple. Si aucun autre gestionnaire d'erreur approprié n'a été défini, alors le gestionnaire d'erreur MPI_ERRORS_RETURN est appelé pour les fonctions d'E/S MPI et le gestionnaire d'erreur MPI_ERRORS_ABORT est appelé pour toutes les autres fonctions MPI.

Open MPI inclut trois gestionnaires d'erreur prédéfinis qui peuvent être utilisés :

  • MPI_ERRORS_ARE_FATAL Provoque l'arrêt du programme sur tous les processus MPI connectés.
  • MPI_ERRORS_ABORT Un gestionnaire d'erreur qui peut être invoqué sur un communicateur, une fenêtre, un fichier ou une session. Lorsqu'il est appelé sur un communicateur, il agit comme si MPI_Abort avait été appelé sur ce communicateur. S'il est appelé sur une fenêtre ou un fichier, agit comme si MPI_Abort avait été appelé sur un communicateur contenant le groupe de processus dans la fenêtre ou le fichier correspondant. S'il est appelé sur une session, n'arrête que le processus local.
  • MPI_ERRORS_RETURN Retourne un code d'erreur à l'application.

Les applications MPI peuvent également implémenter leurs propres gestionnaires d'erreur en appelant :

  • MPI_Comm_create_errhandler puis MPI_Comm_set_errhandler
  • MPI_File_create_errhandler puis MPI_File_set_errhandler
  • MPI_Session_create_errhandler puis MPI_Session_set_errhandler ou à MPI_Session_init
  • MPI_Win_create_errhandler puis MPI_Win_set_errhandler

Notez que MPI ne garantit pas qu'un programme MPI puisse continuer après une erreur.

Voir la page de manuel MPI pour une liste complète des codes d'erreur MPI.

Voir la section Gestion des erreurs de la norme MPI-3.1 pour plus d'informations.
