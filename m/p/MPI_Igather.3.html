MPI_Gather, MPI_Igather, MPI_Gather_init — Collecte des valeurs d'un groupe de processus.

SYNTAXE

PARAMÈTRES D'ENTRÉE

  • sendbuf : Adresse du tampon d'envoi (pointeur).
  • sendcount : Nombre d'éléments dans le tampon d'envoi (entier).
  • sendtype : Type des éléments dans le tampon d'envoi (handle).
  • recvcount : Nombre d'éléments pour toute réception (entier, pertinent uniquement sur le processus racine).
  • recvtype : Type des éléments dans le tampon de réception (handle, pertinent uniquement sur le processus racine).
  • root : Rang du processus de réception (entier).
  • comm : Communicateur (handle).
  • info : Info (handle, persistant).

PARAMÈTRES DE SORTIE

•
recvbuf
Adresse du tampon de réception (pointeur, pertinent uniquement sur le processus racine).
  • request : Requête (handle, non bloquant).
  • ierror : Fortran uniquement : État de l'erreur (entier).

DESCRIPTION

Chaque processus (y compris le processus racine) envoie le contenu de son tampon d'envoi au processus racine. Le processus racine reçoit les messages et les stocke dans l'ordre de leurs rangs. Le résultat est comme si chacun des n processus du groupe (y compris le processus racine) avait exécuté un appel à

MPI_Send(sendbuf, sendcount, sendtype, root, ...)

et que le processus racine avait exécuté n appels à

MPI_Recv(recfbuf + i * recvcount * extent(recvtype), recvcount,
         recvtype, i, ...)

où extent(recvtype) est la taille de type obtenue d'un appel à MPI_Type_extent.

Une description alternative est que les n messages envoyés par les processus du groupe sont concaténés dans l'ordre des rangs, et le message résultant est reçu par le processus racine comme si un appel à MPI_Recv(recvbuf, recvcount * n, recvtype, ...) avait été exécuté.

Le tampon de réception est ignoré par tous les processus autres que la racine.

Les types dérivés sont autorisés pour sendtype et recvtype. Le type de signature de sendcount, sendtype sur le processus i doit être égal au type de signature de recvcount, recvtype sur le processus racine. Cela implique que le volume de données envoyées doit être égal au volume de données reçues, par paires entre chaque processus et le processus racine. Les correspondances de types distinctes entre l'émetteur et le récepteur sont toujours autorisées.

Tous les arguments de la fonction sont pertinents sur le processus racine, tandis que sur les autres processus, seuls les arguments sendbuf, sendcount, sendtype, root, comm sont pertinents. Les arguments root et comm doivent avoir les mêmes valeurs sur tous les processus.

La spécification des compteurs et des types ne doit pas entraîner l'écriture de l'emplacement du processus racine plus d'une fois. Cet appel est erroné. Notez que l'argument recvcount sur le processus racine indique le nombre d'éléments reçus de chaque processus, et non le nombre total d'éléments reçus.

Exemple 1 : Collecter 100 entiers de chaque processus du groupe vers le processus racine.

MPI_Comm comm;
int gsize, sendarray[100];
int root, * rbuf;
...
MPI_Comm_size( comm, &gsize);
rbuf = (int*)malloc(gsize * 100 * sizeof(int));
MPI_Gather( sendarray, 100, MPI_INT, rbuf, 100, MPI_INT, root, comm);

Exemple 2 : Exemple précédent modifié — seul le processus racine alloue de la mémoire pour le tampon de réception.

MPI_Comm comm;
int gsize, sendarray[100];
int root, myrank, * rbuf;
...
MPI_Comm_rank( comm, myrank);
if ( myrank == root) {
  MPI_Comm_size( comm, &gsize);
  rbuf = (int *)malloc(gsize * 100 * sizeof(int));
}
MPI_Gather( sendarray, 100, MPI_INT, rbuf, 100, MPI_INT, root, comm);

Exemple 3 : Faire la même chose que l'exemple précédent, mais utiliser un type de données dérivé. Notez que le type ne peut pas être l'ensemble complet de gsize * 100 entiers, car la correspondance de types est définie par paires entre le processus racine et chaque processus du groupe.

MPI_Comm comm;
int gsize, sendarray[100];
int root, * rbuf;
MPI_Datatype rtype;
...
MPI_Comm_size( comm, &gsize);
MPI_Type_contiguous( 100, MPI_INT, &rtype);
MPI_Type_commit( &rtype );
rbuf = (int*)malloc(gsize * 100 * sizeof(int));
MPI_Gather( sendarray, 100, MPI_INT, rbuf, 1, rtype, root, comm);

UTILISATION DE L'OPTION IN-PLACE

Lorsque le communicateur est un intracomunicateur, vous pouvez effectuer une opération de rassemblement en place (le tampon de réception est utilisé comme tampon d'envoi). Utilisez la variable MPI_IN_PLACE comme valeur du tampon d'envoi du processus racine. Dans ce cas, sendcount et sendtype sont ignorés, et la contribution du processus racine à la collection vectorielle est supposée déjà être à la bonne place dans le tampon de réception. Notez que MPI_IN_PLACE est un type spécial ; il a les mêmes restrictions d'utilisation que MPI_BOTTOM. Comme l'option in-place transforme le tampon de réception en tampon d'envoi et de réception, une liaison Fortran qui inclut INTENT doit les marquer comme INOUT, et non comme OUT.

EXEMPLES

Example 1: Gather 100 ints from every process in group to root.
MPI_Comm comm;
int gsize, sendarray[100];
int root, * rbuf;
...
MPI_Comm_size( comm, &gsize);
rbuf = (int*)malloc(gsize * 100 * sizeof(int));
MPI_Gather( sendarray, 100, MPI_INT, rbuf, 100, MPI_INT, root, comm);
Example 2: Previous example modified — only the root allocates memory for receive buffer.
MPI_Comm comm;
int gsize, sendarray[100];
int root, myrank, * rbuf;
...
MPI_Comm_rank( comm, myrank);
if ( myrank == root) {
  MPI_Comm_size( comm, &gsize);
  rbuf = (int *)malloc(gsize * 100 * sizeof(int));
}
MPI_Gather( sendarray, 100, MPI_INT, rbuf, 100, MPI_INT, root, comm);
Example 3: Do the same as previous example, but use a derived datatype. Note that the type cannot be the entire set of gsize * 100 ints since type matching is defined pairwise between the root and each process in the gather.
MPI_Comm comm;
int gsize, sendarray[100];
int root, * rbuf;
MPI_Datatype rtype;
...
MPI_Comm_size( comm, &gsize);
MPI_Type_contiguous( 100, MPI_INT, &rtype);
MPI_Type_commit( &rtype );
rbuf = (int*)malloc(gsize * 100 * sizeof(int));
MPI_Gather( sendarray, 100, MPI_INT, rbuf, 1, rtype, root, comm);

UNICATOR

Lorsque le communicateur est un intercommunicateur, le processus racine du premier groupe collecte les données de tous les processus du second groupe. Le premier groupe définit le processus racine. Ce processus utilise MPI_ROOT comme valeur de l'argument racine. Les processus restants utilisent MPI_PROC_NULL comme valeur de l'argument racine. Tous les processus du second groupe utilisent le numéro de rang de ce processus racine dans le premier groupe comme valeur de l'argument racine. Le tampon d'envoi des processus du premier groupe doit être cohérent avec le tampon de réception du processus racine du second groupe.

ERRORS

Au-delà des erreurs MPI, les fonctions C renvoient une valeur d'erreur et les fonctions Fortran ont le dernier argument comme résultat.

Avant de renvoyer la valeur d'erreur, le gestionnaire d'erreurs associé à l'objet de communication (par exemple, communicateur, fenêtre, fichier) au moment de l'appel est invoqué. S'il n'y a pas d'objet de communication associé à l'appel MPI, l'appel est considéré comme associé à MPI_COMM_SELF et le gestionnaire associé est invoqué. Lorsque MPI_COMM_SELF n'est pas initialisé (c'est-à-dire avant MPI_Init/MPI_Init_thread, après MPI_Finalize, ou lors de l'utilisation exclusive du modèle de Sessions), l'erreur déclenche le gestionnaire d'erreurs initial. Le gestionnaire d'erreurs initial peut être modifié en appelant MPI_Comm_set_errhandler sur MPI_COMM_SELF lors de l'utilisation du modèle du Monde, ou via l'option mpi_initial_errhandler dans mpiexec ou via la clé info dans MPI_Comm_spawn/MPI_Comm_spawn_multiple. Si aucun autre gestionnaire d'erreurs approprié n'est défini, le gestionnaire MPI_ERRORS_RETURN est appelé pour les fonctions d'E/S MPI et le gestionnaire MPI_ERRORS_ABORT pour les autres fonctions MPI.

Open MPI inclut trois gestionnaires d'erreurs par défaut qui peuvent être utilisés :

  • MPI_ERRORS_ARE_FATAL Indique au programme d'arrêter tous les processus MPI connectés.
  • MPI_ERRORS_ABORT Un gestionnaire d'erreurs qui peut être invoqué sur un communicateur, une fenêtre, un fichier ou une session. Lorsqu'il est invoqué sur un communicateur, il agit comme si MPI_Abort avait été appelé sur ce communicateur. S'il est invoqué sur une fenêtre ou un fichier, il agit comme si MPI_Abort avait été appelé sur un communicateur contenant le groupe de processus correspondant à la fenêtre ou au fichier. S'il est invoqué sur une session, il arrête uniquement le processus local.
  • MPI_ERRORS_RETURN Renvoie un code d'erreur à l'application.

Les applications MPI peuvent également implémenter leurs propres gestionnaires d'erreurs en appelant :

  • MPI_Comm_create_errhandler puis MPI_Comm_set_errhandler
  • MPI_File_create_errhandler puis MPI_File_set_errhandler
  • MPI_Session_create_errhandler puis MPI_Session_set_errhandler ou lors de MPI_Session_init
  • MPI_Win_create_errhandler puis MPI_Win_set_errhandler

Note : MPI ne garantit pas qu'un programme MPI puisse continuer après une erreur.

Voir la page de manuel MPI pour une liste complète des codes d'erreur MPI.

Voir la section Gestion des Erreurs de la norme MPI-3.1 pour plus d'informations.
