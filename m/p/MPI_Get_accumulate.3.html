MPI_Get_accumulate(3) Open MPI MPI_Get_accumulate(3)

MPI_Get_accumulate, MPI_Rget_accumulate - Combine les contenus de l'adresse source avec ceux d'un tampon de destination et retourne la valeur du tampon de destination.

Paramètres d'entrée

  • origin_addr : Adresse source du tampon (optionnel).
  • origin_count : Nombre d'éléments dans le tampon source (entier non négatif).
  • origin_datatype : Type de données de chaque élément dans le tampon source (handle).
  • result_addr : Adresse du tampon de résultat (optionnel).
result_count
Nombre d'éléments dans le tampon de résultat (entier non négatif).
  • result_datatype : Type de données de chaque élément dans le tampon de résultat (handle).
  • target_rank : Rang de la cible (entier non négatif).
target_disp
Décalage par rapport au début de la fenêtre jusqu'au début du tampon cible (entier non négatif).
target_count
Nombre d'éléments dans le tampon cible (entier non négatif).
  • target_datatype : Type de données de chaque élément dans le tampon cible (handle).
  • op : Opération de réduction (handle).
  • win : Objet fenêtre (handle).

Paramètre de sortie

  • MPI_Rget_accumulate: Requête RMA
  • ierror : Fortran uniquement : valeur d'erreur (entier).

Description

MPI_Get_accumulate est une fonction de communication de type un à un de MPI qui ajoute les contenus du tampon source (défini par origin_addr, origin_count et origin_datatype) au tampon spécifié par les arguments target_count et target_datatype, dans le tampon cible de la fenêtre spécifiée par target_rank et win, en utilisant l'opération op. MPI_Get_accumulate retourne dans le tampon de résultat result_addr les contenus du tampon cible avant l'accumulation.

Toute opération prédéfinie pour MPI_Reduce ainsi que MPI_NO_OP peut être utilisée. Les fonctions définies par l'utilisateur ne peuvent pas être utilisées. Par exemple, si op est MPI_SUM, chaque élément du tampon source est ajouté à l'élément correspondant dans le tampon cible, remplaçant la valeur précédente dans le tampon cible.

Chaque argument de type de données doit être un type de données prédéfini ou un type de données dérivé, où tous les composants de base sont du même type de données prédéfini. Les deux arguments de type de données doivent être construits à partir du même type de données prédéfini. L'opération op s'applique à l'élément de ce type de données prédéfini. L'argument target_datatype ne doit pas spécifier d'éléments qui se chevauchent, et le tampon cible doit être correctement aligné dans la fenêtre.

Un nouveau type d'opération prédéfini, MPI_REPLACE, est défini, qui correspond à la fonction associative f(a, b) = b ; c'est-à-dire que la valeur actuelle dans la mémoire cible est remplacée par la valeur fournie par le tampon source.

Un nouveau type d'opération prédéfini, MPI_NO_OP, est défini, qui correspond à la fonction associative f(a, b) = a ; c'est-à-dire que la valeur actuelle dans la mémoire cible est retournée dans le tampon de résultat à la source et aucune opération n'est effectuée sur le tampon cible.

MPI_Rget_accumulate est similaire à MPI_Get_accumulate, sauf qu'un objet de requête de communication (request) est attribué et associé au handle de requête (l'argument request) qui peut être utilisé pour attendre ou tester la complétion de l'opération. La complétion d'une opération MPI_Rget_accumulate indique que les données sont disponibles dans le tampon de résultat et que le tampon source est libre d'être mis à jour. Elle n'indique pas que l'opération a été complétée dans la fenêtre cible.

Notes

La fonctionnalité générale de MPI_Get_accumulate peut limiter les performances des appels de type "fetch-and-increment" ou "fetch-and-add" qui peuvent être implémentés par des opérations matérielles spécifiques. MPI_Fetch_and_op permet une implémentation rapide d'un sous-ensemble courant de la fonctionnalité de MPI_Get_accumulate utilisée.

MPI_Get est un cas particulier de MPI_Get_accumulate, avec l'opération MPI_NO_OP. Cependant, il est important de noter que MPI_Get et MPI_Get_accumulate ont des contraintes différentes sur les mises à jour concurrentes.

Il incombe à l'utilisateur de s'assurer que, lors de l'utilisation des fonctions d'accumulation, l'argument de décalage cible est tel que les accès à la fenêtre sont correctement alignés en fonction des arguments de type de données dans l'appel à MPI_Get_accumulate.

Erreurs

La quasi-totalité des routines MPI retournent une valeur d'erreur ; les routines C retournent la valeur d'erreur comme résultat de la fonction et les routines Fortran dans le dernier argument.

Avant que la valeur d'erreur ne soit retournée, le gestionnaire d'erreurs associé à l'objet de communication actuel (par exemple, communicator, window, file) est appelé. S'il n'y a pas d'objet de communication associé à l'appel MPI, l'appel est considéré comme invalide.
