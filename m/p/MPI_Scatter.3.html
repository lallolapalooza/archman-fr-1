MPI_Scatter(3) Open MPI MPI_Scatter(3)

MPI_Scatter, MPI_Iscatter, MPI_Scatter_init — Envoie des données d'un processus à tous les processus d'un groupe.

Syntaxe

Syntaxe C

#include <mpi.h>
int MPI_Scatter(const void *sendbuf, int sendcount, MPI_Datatype sendtype,
     void *recvbuf, int recvcount, MPI_Datatype recvtype, int root,
     MPI_Comm comm)
int MPI_Iscatter(const void *sendbuf, int sendcount, MPI_Datatype sendtype,
     void *recvbuf, int recvcount, MPI_Datatype recvtype, int root,
     MPI_Comm comm, MPI_Request *request)
int MPI_Scatter_init(const void *sendbuf, int sendcount, MPI_Datatype sendtype,
     void *recvbuf, int recvcount, MPI_Datatype recvtype, int root,
     MPI_Comm comm, MPI_Info info, MPI_Request *request)

Paramètres d'entrée

  • sendbuf: Adresse du buffer d'envoi (pointeur, significatif seulement sur le processus racine).
  • sendcount: Nombre d'éléments envoyés à chaque processus (entier, significatif seulement sur le processus racine).
  • sendtype: Type des éléments du buffer d'envoi (pointeur, significatif seulement sur le processus racine).
  • recvcount: Nombre d'éléments dans le buffer de réception (entier).
  • recvtype: Type des éléments du buffer de réception (pointeur).
  • root: Rang du processus d'envoi (entier).
  • comm: Communicateur (pointeur).
  • info: Informations (pointeur, persistant).

Paramètres de sortie

  • recvbuf: Adresse du buffer de réception (pointeur).
  • request: Requête (pointeur, non bloquant).
  • ierror: Uniquement en Fortran: Statut d'erreur (entier).

Description

MPI_Scatter est l'opération inverse de MPI_Gather.

Le résultat est comme si le processus racine exécutait n opérations d'envoi.

MPI_Send(sendbuf + i * sendcount * extent(sendtype), sendcount,
         sendtype, i, ...);

et que chaque processus exécutait une réception.

MPI_Recv(recvbuf, recvcount, recvtype, i, ...).;

Une description alternative est que le processus racine envoie un message avec MPI_Send(sendbuf, sendcount * n, sendtype, ...), qui est divisé en n segments égaux, le i-ème segment étant envoyé au i-ème processus du groupe, et chaque processus reçoit ce message comme mentionné ci-dessus.

Le buffer d'envoi est ignoré pour tous les processus autres que la racine.

Les types de signature associés à sendcount, sendtype sur le processus racine doivent être égaux aux types de signature associés à recvcount, recvtype sur tous les processus (bien que les mappages de types puissent être différents). Cela implique que la quantité de données envoyées doit être égale à la quantité de données reçues, par paires entre chaque processus et le processus racine. Des mappages de types distincts entre expéditeur et récepteur sont néanmoins autorisés.

Tous les arguments de la fonction sont significatifs sur le processus racine, tandis que sur les autres processus seuls les arguments recvbuf, recvcount, recvtype, root, comm sont significatifs. Les arguments root et comm doivent avoir les mêmes valeurs sur tous les processus.

La spécification des compteurs et des types ne doit pas entraîner la lecture d'un emplacement quelconque dans le processus racine plus d'une fois.

Raison : Bien que non nécessaire, la dernière restriction est imposée pour obtenir une symétrie avec MPI_Gather, où la restriction correspondante (un multiple-écriture) est nécessaire.

Exemple : L'inverse de l'exemple 1 dans la page de manuel de MPI_Gather. La diffusion de 100 entiers de la racine à chaque processus du groupe.

MPI_Comm comm;
int gsize,*sendbuf;
int root, rbuf[100];
...
MPI_Comm_size(comm, &gsize);
sendbuf = (int *)malloc(gsize*100*sizeof(int));
...
MPI_Scatter(sendbuf, 100, MPI_INT, rbuf, 100,
            MPI_INT, root, comm);

Utilisation de l'option en place

Lorsque le communicateur est un intracommunicateur, vous pouvez effectuer une opération de dispersion en place (le buffer de réception est utilisé comme buffer d'envoi). Utilisez la valeur MPI_IN_PLACE comme valeur de recvbuf sur le processus racine. Dans ce cas, recvcount et recvtype sont ignorés et le processus racine n'envoie pas de données à lui-même.

Remarque : MPI_IN_PLACE est un type spécial ; il a les mêmes restrictions d'utilisation que MPI_BOTTOM.

Puisque l'option en place transforme le buffer de réception en un buffer d'envoi et de réception, une liaison Fortran incluant INTENT devrait les marquer comme INOUT, et non comme OUT.

Lorsque le communicateur est un intercommunicateur

Lorsque le communicateur est un intercommunicateur, le processus racine du premier groupe envoie des données à tous les processus du second groupe. Le premier groupe définit le processus racine. Ce processus utilise MPI_ROOT comme valeur de son argument root. Les processus restants utilisent MPI_PROC_NULL comme valeur de leur argument root. Tous les processus du second groupe utilisent le rang du processus racine du premier groupe comme valeur de leur argument root. L'argument recvbuf du processus racine du premier groupe doit être cohérent avec l'argument recvbuf des processus du second groupe.

Erreurs

En plus de toutes les routines MPI, une valeur d'erreur est retournée ; le résultat des routines C est la valeur de retour de la fonction et le dernier argument des routines Fortran.

Avant que la valeur d'erreur ne soit retournée, le gestionnaire d'erreurs associé à l'objet de communication (par exemple, communicateur, fenêtre, fichier) est appelé. S'il n'y a pas d'objet de communication associé à l'appel MPI, l'appel est considéré comme associé à MPI_COMM_SELF et le gestionnaire correspondant est appelé.
