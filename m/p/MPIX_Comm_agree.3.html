MPIX_Comm_agree(3) Open MPI MPIX_Comm_agree(3)

MPIX_Comm_agree, MPIX_Comm_iagree - Accordez une valeur de drapeau sur tous les processus vivants et distribuez le résultat à tous les processus vivants, même après les échecs.

Cette partie fait partie de l'extension de atténuation des défaillances au niveau de l'utilisateur (ULFM).

SYNTAXE

Syntaxe C

#include <mpi.h>
#include <mpi-ext.h>
int MPIX_Comm_agree(MPI_Comm comm, int *flag)
int MPIX_Comm_iagree(MPI_Comm comm, int *flag, MPI_Request *request)

Syntaxe Fortran

USE MPI
USE MPI_EXT
! ou l'ancienne forme: INCLUDE 'mpif.h'
MPIX_COMM_AGREE(COMM, FLAG, IERROR)
     INTEGER COMM, FLAG, IERROR
MPIX_COMM_IAGREE(COMM, FLAG, REQUEST, IERROR)
     INTEGER COMM, FLAG, REQUEST, IERROR

Syntaxe Fortran 2008

USE mpi_f08
USE mpi_ext_f08
MPIX_Comm_agree(comm, flag, ierror)
     TYPE(MPI_Comm), INTENT(IN) :: comm
     INTEGER, INTENT(INOUT) :: flag
     INTEGER, OPTIONAL, INTENT(OUT) :: ierror
MPIX_COMM_IAGREE(COMM, FLAG, REQUEST, IERROR)
     TYPE(MPI_Comm), INTENT(IN) :: comm
     INTEGER, INTENT(INOUT), ASYNCHRONOUS :: flag
     TYPE(MPI_Request), INTENT(OUT) :: request
     INTEGER, OPTIONAL, INTENT(OUT) :: ierror

PARAMETRES D'ENTRÉE

  • comm: Communicateur (handle).
  • flag: Valeurs de drapeau binaires (entier).

PARAMETRES DE SORTIE

  • flag: Valeurs de drapeau binaires réduites (entier).
  • request: Demande (handle, uniquement non bloquant).
  • ierror: Fortran uniquement: État de l'erreur (entier).

DESCRIPTION

Cette communication collective accorde la valeur entière flag et (implicitement) le groupe des processus défaillants dans comm.

À la fin, tous les processus non défaillants ont convenu de définir la valeur de sortie de l'entier flag sur le résultat d'une opération ET binaire sur les valeurs d'entrée contribuées par flag.

MPIX_Comm_iagree est la variante non bloquante de MPIX_Comm_agree.

DÉFAILLANCES DES PROCESSUS

Si tous les processus MPI du groupe de comm ont reconnu la défaillance d'un processus MPI (en utilisant MPIX_Comm_ack_failed) avant l'appel à MPIX_Comm_agree (ou MPIX_Comm_iagree), l'erreur MPIX_ERR_PROC_FAILED n'est pas levée lorsque la valeur de sortie de flag ignore la contribution de ce processus défaillant. Remarque: ceci est une propriété uniforme: si un processus non contributeur est trouvé non reconnu sur n'importe quel processus vivant dans comm, tous les processus lèvent une erreur de classe MPIX_ERR_PROC_FAILED.

Exemple 1: En utilisant une combinaison de MPIX_Comm_ack_failed et MPIX_Comm_agree, les utilisateurs peuvent propager et synchroniser les informations de défaillance entre tous les processus MPI dans comm.

Comm_get_failed_consistente(MPI_Comm c, MPI_Group * g) {
    int rc; int T=1;
    int size; int num_acked;
    MPI_Group gf;
    int ranges[3] = {0, 0, 1};
    MPI_Comm_size(c, &size);
    do {
        /* cette routine n'est pas pure: l'appel à MPIX_Comm_ack_failed affecte l'état du communicateur c */
        MPIX_Comm_ack_failed(c, size, &num_acked);
        /* nous ignorons simplement la valeur T dans cet exemple */
        rc = MPIX_Comm_agree(c, &T);
    } while( rc != MPI_SUCCESS );
    /* après cette boucle, MPIX_Comm_agree a retourné MPI_SUCCESS sur tous les processus, donc tous les processus ont reconnu le même ensemble de défaillances. Obtenons cet ensemble de défaillances dans le groupe g. */
    if( 0 == num_acked ) {
        *g = MPI_GROUP_EMPTY;
    }
    else {
        MPIX_Comm_get_failed(c, &gf);
        ranges[1] = num_acked - 1;
        MPI_Group_range_incl(gf, 1, ranges, g);
        MPI_Group_free(&gf);
    }
}

QUAND LE COMMUNICATEUR EST RÉVOQUÉ

Cette fonction ne déclenche jamais une erreur de classe MPIX_ERR_REVOKED. Les définitions sémantiques de MPIX_Comm_agree sont maintenues lorsque comm est révoqué, ou lorsque le groupe de comm contient des processus MPI défaillants. En particulier, MPIX_Comm_agree est une opération collective, même lorsque comm est révoqué.

QUAND LE COMMUNICATEUR EST UN COMMUNICATEUR INTERNE

Lorsque le communicateur est un communicateur interne, la valeur de flag est une opération ET binaire sur les valeurs apportées par le groupe distant.

Lorsqu'une erreur de classe MPIX_ERR_PROC_FAILED est déclenchée, elle est déclenchée de manière cohérente sur tous les processus MPI des groupes de comm, c'est-à-dire sur les groupes local et distant du communicateur interne.

ERREURS

La plupart des routines MPI retournent une valeur d'erreur; dans les routines C, la valeur de retour est le résultat de la fonction, et dans les routines Fortran, le dernier argument est la valeur d'erreur.

Avant que la valeur d'erreur ne soit retournée, le gestionnaire d'erreurs associé à l'objet de communication (par exemple, communicateur, fenêtre, fichier) actuel est appelé. S'il n'y a pas d'objet de communication associé à l'appel MPI, l'appel est considéré comme associé à MPI_COMM_SELF et le gestionnaire d'erreurs associé à MPI_COMM_SELF sera appelé. Lorsque MPI_COMM_SELF n'est pas initialisé (c'est-à-dire, avant MPI_Init/MPI_Init_thread, après MPI_Finalize, ou lorsque le modèle de sessions est utilisé exclusivement), l'erreur déclenche le gestionnaire d'erreurs initial. Le gestionnaire d'erreurs initial peut être modifié en appelant MPI_Comm_set_errhandler sur MPI_COMM_SELF lorsque le modèle du monde est utilisé, ou via le paramètre mpi_initial_errhandler de mpiexec ou la clé d'information de MPI_Comm_spawn/MPI_Comm_spawn_multiple. Si aucun autre gestionnaire approprié n'est défini, le gestionnaire MPI_ERRORS_RETURN est appelé pour les fonctions d'E/S MPI et le gestionnaire MPI_ERRORS_ABORT pour toutes les autres fonctions MPI.

Open MPI comprend trois gestionnaires d'erreurs prédéfinis qui peuvent être utilisés:

  • MPI_ERRORS_ARE_FATAL Provoque l'abandon de tous les processus MPI connectés par le programme.
  • MPI_ERRORS_ABORT Un gestionnaire d'erreurs qui peut être appelé sur un communicateur, une fenêtre, un fichier ou une session. Lorsqu'il est appelé sur un communicateur, il agit comme si MPI_Abort avait été appelé sur ce communicateur. S'il est appelé sur une fenêtre ou un fichier, il agit comme si MPI_Abort avait été appelé sur un communicateur contenant le groupe de processus dans la fenêtre ou le fichier correspondant. S'il est appelé sur une session, il abandonne uniquement le processus local.
  • MPI_ERRORS_RETURN Retourne un code d'erreur à l'application.

Les applications MPI peuvent également implémenter leurs propres gestionnaires d'erreurs en appelant:

  • MPI_Comm_create_errhandler suivi de MPI_Comm_set_errhandler
  • MPI_File_create_errhandler suivi de MPI_File_set_errhandler
  • MPI_Session_create_errhandler suivi de MPI_Session_set_errhandler ou dans MPI_Session_init
  • MPI_Win_create_errhandler suivi de MPI_Win_set_errhandler
