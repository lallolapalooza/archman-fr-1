MPI_Comm_spawn(3) Open MPI MPI_Comm_spawn(3)

MPI_Comm_spawn — Lance un nombre de binaires identiques.

SYNTAX

Syntaxe C

#include <mpi.h>
int MPI_Comm_spawn(const char *command, char *argv[], int maxprocs,
     MPI_Info info, int root, MPI_Comm comm,
     MPI_Comm *intercomm, int array_of_errcodes[])

Syntaxe Fortran

USE MPI
! ou la forme plus ancienne : INCLUDE 'mpif.h'
MPI_COMM_SPAWN(COMMAND, ARGV, MAXPROCS, INFO, ROOT, COMM,
     INTERCOMM, ARRAY_OF_ERRCODES, IERROR)
     CHARACTER*(*) COMMAND, ARGV(*)
     INTEGER INFO, MAXPROCS, ROOT, COMM, INTERCOMM,
     ARRAY_OF_ERRCODES(*), IERROR

Syntaxe Fortran 2008

USE mpi_f08
MPI_Comm_spawn(command, argv, maxprocs, info, root, comm, intercomm,
             array_of_errcodes, ierror)
     CHARACTER(LEN=*), INTENT(IN) :: command, argv(*)
     INTEGER, INTENT(IN) :: maxprocs, root
     TYPE(MPI_Info), INTENT(IN) :: info
     TYPE(MPI_Comm), INTENT(IN) :: comm
     TYPE(MPI_Comm), INTENT(OUT) :: intercomm
     INTEGER :: array_of_errcodes(*)
     INTEGER, OPTIONAL, INTENT(OUT) :: ierror

PARAMÈTRES D'ENTRÉE

  • command: Nom du programme à lancer (chaîne de caractères, pertinent uniquement au niveau du root).
  • argv: Arguments pour command (tableau de chaînes de caractères, pertinent uniquement au niveau du root).
  • maxprocs: Nombre maximum de processus à démarrer (entier, pertinent uniquement au niveau du root).
  • info: Un ensemble de paires clé-valeur indiquant au système d'exécution où et comment démarrer les processus (handle, pertinent uniquement au niveau du root).
  • root: Rang du processus où les arguments précédents sont examinés (entier).
  • comm: Intracommunicateur contenant le groupe des processus lanceurs (handle).

PARAMÈTRE DE SORTIE

  • intercomm: Intercommunicateur entre le groupe d'origine et le nouveau groupe lancé (handle).
  • array_of_errcodes: Un code par processus (tableau d'entiers).
  • ierror: Fortran uniquement : Statut d'erreur (entier).

DESCRIPTION

MPI_Comm_spawn tente de lancer maxprocs copies identiques du programme MPI spécifié par command, en établissant une communication avec elles et en retournant un intercommunicateur. Les processus lancés sont appelés enfants. Les enfants ont leur propre MPI_COMM_WORLD, distinct de celui des parents. MPI_Comm_spawn est une opération collective sur comm, et peut également ne pas retourner avant que MPI_Init ait été appelé dans les enfants. De même, MPI_Init dans les enfants peut ne pas retourner avant que tous les parents aient appelé MPI_Comm_spawn. En ce sens, MPI_Comm_spawn dans les parents et MPI_Init dans les enfants forment une opération collective sur l'union des processus parents et enfants. L'intercommunicateur retourné par MPI_Comm_spawn contient les processus parents dans le groupe local et les processus enfants dans le groupe distant. L'ordre des processus dans les groupes local et distant est le même que l'ordre du groupe de comm dans les parents et de MPI_COMM_WORLD des enfants, respectivement. Cet intercommunicateur peut être obtenu dans les enfants via la fonction MPI_Comm_get_parent.

La norme MPI permet à une implémentation d'utiliser l'attribut MPI_UNIVERSE_SIZE de MPI_COMM_WORLD pour spécifier le nombre de processus qui seront actifs dans un programme. Bien que cette implémentation de la norme MPI définisse MPI_UNIVERSE_SIZE, elle ne permet pas à l'utilisateur de définir sa valeur. Si vous essayez de définir la valeur de MPI_UNIVERSE_SIZE, vous recevrez un message d'erreur.

L'argument command

L'argument command est une chaîne de caractères contenant le nom d'un programme à lancer. La chaîne est terminée par un caractère nul en C. En Fortran, les espaces de début et de fin sont supprimés. MPI recherche le fichier d'abord dans le répertoire de travail du processus lanceur.

L'argument argv

argv est un tableau de chaînes de caractères contenant les arguments passés au programme. Le premier élément de argv est le premier argument passé à command, et non, comme c'est conventionnel dans certains contextes, la commande elle-même. La liste d'arguments est terminée par NULL en C et par une chaîne vide en Fortran (notez qu'il est de la responsabilité de l'application MPI de s'assurer que la dernière entrée du tableau argv est une chaîne vide ; le compilateur ne l'insérera pas automatiquement). En Fortran, les espaces de début et de fin sont toujours supprimés, de sorte qu'une chaîne constituée uniquement d'espaces est considérée comme une chaîne vide. La constante MPI_ARGV_NULL peut être utilisée en C et en Fortran pour indiquer une liste d'arguments vide. En C, cette constante est identique à NULL.

En C, l'argument argv de MPI_Comm_spawn diffère de l'argument argv de main à deux égards. Premièrement, il est décalé d'un élément. Spécifiquement, argv[0] de main contient le nom du programme (donné par command). argv[1] de main correspond à argv[0] dans MPI_Comm_spawn, argv[2] de main à argv[1] de MPI_Comm_spawn, et ainsi de suite. Deuxièmement, argv de MPI_Comm_spawn doit être terminé par null, afin que sa longueur puisse être déterminée. Passer MPI_ARGV_NULL à MPI_Comm_spawn résulte en un argc de 1 pour main et un argv dont l'élément 0 est le nom du programme.

L'argument maxprocs

Open MPI tente de lancer maxprocs processus. S'il ne parvient pas à lancer maxprocs processus, il génère une erreur de classe MPI_ERR_SPAWN. Si MPI parvient à lancer le nombre spécifié de processus, MPI_Comm_spawn retourne avec succès et le nombre de processus lancés, m, est donné par la taille du groupe distant de intercomm.

Un appel de lancement avec le comportement par défaut est dit « dur ». Un appel de lancement pour lequel moins de maxprocs processus peuvent être retournés est dit « doux ».

L'argument info

L'argument info est un handle opaque de type MPI_Info en C et INTEGER en Fortran. C'est un conteneur pour un certain nombre de paires (clé, valeur) spécifiées par l'utilisateur. clé et valeur sont des chaînes de caractères (char * terminé par null en C, character*(*) en Fortran). Les routines pour créer et manipuler l'argument info sont décrites dans la section 4.10 de la norme MPI-2.

Pour les appels SPAWN, info fournit des instructions supplémentaires, dépendantes de l'implémentation, à MPI et au système d'exécution sur la manière de démarrer les processus. Une application peut passer MPI_INFO_NULL en C ou en Fortran. Les programmes portables n'ayant pas besoin d'un contrôle détaillé sur les emplacements des processus devraient utiliser MPI_INFO_NULL.

Les clés suivantes pour info sont reconnues dans Open MPI. (Les valeurs réservées mentionnées dans la section 5.3.4 de la norme MPI-2 ne sont pas implémentées.)

                                lancé. Voir la page man de orte_host
                                pour une explication de la manière dont
                                cela sera utilisé.
hostfile               char *   Fichier d'hôtes contenant les hôtes sur
                                lesquels les processus doivent être lancés.
                                Voir la page man de orte_hostfile
                                pour une explication de la manière dont
                                cela sera utilisé.

Un répertoire de destination doit également être fourni. ompi_preload_files char * Une liste de fichiers séparés par des virgules qui doivent être pré-positionnés en plus de l'exécutable. Notez que cette option ne dépend pas de ompi_preload_binary - les fichiers peuvent être déplacés vers la cible même si un exécutable n'est pas déplacé. ompi_stdin_target char * Liste de rangs délimitée par des virgules pour recevoir stdin lorsqu'il est transféré. ompi_non_mpi bool S'il est défini sur true, lance une application non-MPI ; le communicateur retourné sera MPI_COMM_NULL. Si ce paramètre existe déjà dans l'environnement, sa valeur sera écrasée par la valeur fournie. mapper char * Mapper à utiliser pour ce job map_by char * Directive de mappage indiquant comment les processus doivent être mappés (slot, nœud, socket, etc.). rank_by char * Directive de classement indiquant comment les processus doivent être classés (slot, nœud, socket, etc.). bind_to char * Directive de liaison indiquant comment les processus doivent être liés (cœur, slot, nœud, socket, etc.). path char * Liste des répertoires à rechercher pour l'exécutable npernode char * Nombre de processus à lancer sur chaque nœud de l'allocation pernode bool Équivalent à npernode de 1 ppr char * Lance le nombre spécifié de processus sur chaque objet du type identifié env char * Liste d'environnements délimités par des sauts de ligne à transmettre aux processus lancés

Les clés d'information bool sont en fait des chaînes de caractères mais sont évaluées comme suit : si la valeur de la chaîne est un nombre, elle est convertie en entier et convertie en booléen (ce qui signifie que les entiers zéro sont faux et les valeurs non nulles sont vraies). Si la valeur de la chaîne est « yes » ou « true » (insensible à la casse), le booléen est vrai. Si la valeur de la chaîne est « no » ou « false » (insensible à la casse), le booléen est faux. Toutes les autres valeurs de chaîne ne sont pas reconnues et donc fausses.

L'argument root

Tous les arguments avant l'argument root sont examinés uniquement sur le processus dont le rang dans comm est égal à root. La valeur de ces arguments sur les autres processus est ignorée.

L'argument array_of_errcodes

Le tableau array_of_errcodes est un tableau de longueur maxprocs dans lequel MPI signale l'état des processus que MPI a été demandé de démarrer. Si les maxprocs processus ont été lancés, array_of_errcodes est rempli avec la valeur MPI_SUCCESS. Si certains des processus ne sont *pas* lancés, array_of_errcodes est rempli avec la valeur MPI_ERR_SPAWN. En C ou Fortran, une application peut passer MPI_ERRCODES_IGNORE si elle ne s'intéresse pas aux codes d'erreur.

NOTES

L'achèvement de MPI_Comm_spawn dans le parent ne signifie pas nécessairement que MPI_Init a été appelé dans les enfants (bien que l'intercommunicateur retourné puisse être utilisé immédiatement).

ERREURS

Presque toutes les routines MPI retournent une valeur d'erreur ; les routines C en tant que résultat de retour de la fonction et les routines Fortran dans le dernier argument.

Avant que la valeur d'erreur ne soit retournée, le gestionnaire d'erreurs MPI actuel associé à l'objet de communication (par exemple, communicateur, fenêtre, fichier) est appelé. Si aucun objet de communication n'est associé à l'appel MPI, alors l'appel est considéré comme attaché à MPI_COMM_SELF et appellera le gestionnaire d'erreurs MPI associé. Lorsque MPI_COMM_SELF n'est pas initialisé (c'est-à-dire avant MPI_Init/MPI_Init_thread, après MPI_Finalize, ou lors de l'utilisation exclusive du modèle Sessions), l'erreur déclenche le gestionnaire d'erreurs initial. Le gestionnaire d'erreurs initial peut être modifié en appelant MPI_Comm_set_errhandler sur MPI_COMM_SELF lors de l'utilisation du modèle World, ou l'argument de ligne de commande mpi_initial_errhandler pour mpiexec ou la clé d'information pour MPI_Comm_spawn/MPI_Comm_spawn_multiple. Si aucun autre gestionnaire d'erreurs approprié n'a été défini, alors le gestionnaire d'erreurs MPI_ERRORS_RETURN est appelé pour les fonctions d'E/S MPI et le gestionnaire d'erreurs MPI_ERRORS_ABORT est appelé pour toutes les autres fonctions MPI.

Open MPI inclut trois gestionnaires d'erreurs prédéfinis qui peuvent être utilisés :

  • MPI_ERRORS_ARE_FATAL Provoque l'abandon de tous les processus MPI connectés par le programme.
  • MPI_ERRORS_ABORT Un gestionnaire d'erreurs qui peut être invoqué sur un communicateur, une fenêtre, un fichier ou une session. Lorsqu'il est appelé sur un communicateur, il agit comme si MPI_Abort avait été appelé sur ce communicateur. S'il est appelé sur une fenêtre ou un fichier, il agit comme si MPI_Abort avait été appelé sur un communicateur contenant le groupe de processus de la fenêtre ou du fichier correspondant. S'il est appelé sur une session, il n'abandonne que le processus local.
  • MPI_ERRORS_RETURN Retourne un code d'erreur à l'application.

Les applications MPI peuvent également implémenter leurs propres gestionnaires d'erreurs en appelant :

  • MPI_Comm_create_errhandler puis MPI_Comm_set_errhandler
  • MPI_File_create_errhandler puis MPI_File_set_errhandler
  • MPI_Session_create_errhandler puis MPI_Session_set_errhandler ou à MPI_Session_init
  • MPI_Win_create_errhandler puis MPI_Win_set_errhandler

Notez que MPI ne garantit pas qu'un programme MPI puisse continuer après une erreur.

Voir la page de manuel MPI pour une liste complète des codes d'erreur MPI.

Voir la section Gestion des erreurs de la norme MPI-3.1 pour plus d'informations.
