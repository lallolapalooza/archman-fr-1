PARAMÈTRES D'ENTRÉE

  • sendbuf: Adresse de départ du buffer d'envoi (choix).
  • recvcounts: Tableau d'entiers spécifiant le nombre d'éléments dans le résultat distribué à chaque processus. Le tableau doit être identique sur tous les processus appelants.
  • datatype: Type de données des éléments du buffer d'entrée (handle).
  • op: Opération (handle).
  • comm: Communicateur (handle).
  • info: Info (handle, persistant).

PARAMÈTRES DE SORTIE

  • recvbuf: Adresse de départ du buffer de réception (choix).
  • request: Requête (handle, non bloquant seulement).
  • ierror: Fortran seulement : Statut d'erreur (entier).

DESCRIPTION

MPI_Reduce_scatter effectue d'abord une réduction élément par élément sur le vecteur de count = S(i)recvcounts[i] éléments dans le buffer d'envoi défini par sendbuf, count et datatype. Ensuite, le vecteur résultant de résultats est divisé en n segments disjoints, où n est le nombre de processus dans le groupe. Le segment i contient recvcounts[i] éléments. Le i-ème segment est envoyé au processus i et stocké dans le buffer de réception défini par recvbuf, recvcounts[i], et datatype.

UTILISATION DE L'OPTION IN-PLACE

Lorsque le communicateur est un intracommunicateur, vous pouvez effectuer une opération de réduction-dispersion en place (le buffer de sortie est utilisé comme buffer d'entrée). Utilisez la variable MPI_IN_PLACE comme valeur pour sendbuf. Dans ce cas, les données d'entrée sont prises depuis le début du buffer de réception. La zone occupée par les données d'entrée peut être plus longue ou plus courte que les données remplies par les données de sortie.

QUAND LE COMMUNICATEUR EST UN INTER-COMMUNICATEUR

Lorsque le communicateur est un inter-communicateur, l'opération de réduction-dispersion se déroule en deux phases. D'abord, le résultat de la réduction effectuée sur les données fournies par les processus du premier groupe est dispersé parmi les processus du second groupe. Ensuite, l'inverse se produit : la réduction effectuée sur les données fournies par les processus du second groupe est dispersée parmi les processus du premier groupe. Pour chaque groupe, tous les processus fournissent le même argument recvcounts, et la somme des valeurs recvcounts doit être la même pour les deux groupes.

NOTES SUR LES OPÉRATIONS COLLECTIVES

Les fonctions de réduction ( MPI_Op ) ne retournent pas de valeur d'erreur. Par conséquent, si les fonctions détectent une erreur, tout ce qu'elles peuvent faire est soit d'appeler MPI_Abort, soit de passer silencieusement sur le problème. Ainsi, si vous changez le gestionnaire d'erreurs de MPI_ERRORS_ARE_FATAL à autre chose, par exemple, MPI_ERRORS_RETURN , aucune erreur ne sera indiquée.

La raison de cela est les problèmes de performance pour s'assurer que toutes les routines collectives retournent la même valeur d'erreur.

ERREURS

Presque toutes les routines MPI retournent une valeur d'erreur ; les routines C comme résultat de la fonction et les routines Fortran dans le dernier argument.

Avant que la valeur d'erreur ne soit retournée, le gestionnaire d'erreurs MPI actuel associé à l'objet de communication (par exemple, communicateur, fenêtre, fichier) est appelé. S'il n'y a pas d'objet de communication associé à l'appel MPI, alors l'appel est considéré comme attaché à MPI_COMM_SELF et appellera le gestionnaire d'erreurs MPI associé. Lorsque MPI_COMM_SELF n'est pas initialisé (c'est-à-dire, avant MPI_Init/MPI_Init_thread, après MPI_Finalize, ou en utilisant exclusivement le modèle de Sessions) l'erreur déclenche le gestionnaire d'erreurs initial. Le gestionnaire d'erreurs initial peut être modifié en appelant MPI_Comm_set_errhandler sur MPI_COMM_SELF en utilisant le modèle World, ou l'argument CLI mpi_initial_errhandler de mpiexec ou la clé d'information de MPI_Comm_spawn/MPI_Comm_spawn_multiple. Si aucun autre gestionnaire d'erreurs approprié n'a été défini, alors le gestionnaire d'erreurs MPI_ERRORS_RETURN est appelé pour les fonctions MPI I/O et le gestionnaire d'erreurs MPI_ERRORS_ABORT est appelé pour toutes les autres fonctions MPI.

Open MPI inclut trois gestionnaires d'erreurs prédéfinis qui peuvent être utilisés :

  • MPI_ERRORS_ARE_FATAL Provoque l'abandon de tous les processus MPI connectés.
  • MPI_ERRORS_ABORT Un gestionnaire d'erreurs qui peut être invoqué sur un communicateur, une fenêtre, un fichier ou une session. Lorsqu'il est appelé sur un communicateur, il agit comme si MPI_Abort avait été appelé sur ce communicateur. S'il est appelé sur une fenêtre ou un fichier, il agit comme si MPI_Abort avait été appelé sur un communicateur contenant le groupe des processus dans la fenêtre ou le fichier correspondant. S'il est appelé sur une session, il n'abandonne que le processus local.
  • MPI_ERRORS_RETURN Retourne un code d'erreur à l'application.

Les applications MPI peuvent également implémenter leurs propres gestionnaires d'erreurs en appelant :

  • MPI_Comm_create_errhandler puis MPI_Comm_set_errhandler
  • MPI_File_create_errhandler puis MPI_File_set_errhandler
  • MPI_Session_create_errhandler

NOM

MPI_Ireduce_scatter - Réduction et diffusion à partir d'un groupe de processus avec des types de données génériques.

SYNTAX

int MPI_Ireduce_scatter(const void *sendbuf, void *recvbuf, const int recvcounts[],
                        MPI_Datatype recvtype, MPI_Op op, MPI_Comm comm);
int MPI_Ireduce_scatter_c(const void *sendbuf, void *recvbuf,
                          MPI_Count recvcounts[], MPI_Datatype recvtype,
                          MPI_Op op, MPI_Comm comm);

PARAMETRES D'ENTRÉE

C:
  • sendbuf: pointeur vers le buffer d'envoi (spécifie les données envoyées par chaque processus).
  • recvcounts: tableau de entiers spécifiant le nombre d'éléments à recevoir de chaque processus dans le groupe de communicateur.
  • recvtype: type de données MPI des éléments dans le buffer de réception.
  • op: opération de réduction MPI (par exemple, MPI_SUM, MPI_PROD, MPI_MAX, MPI_MIN).
  • comm: communicateur MPI.
Fortran:
  • SENDBUF: määrä buffer d'envoi.
  • RECVCOUNTS: määrä tableau des comptes de réception.
  • RECVTYPE: type de données MPI des éléments dans le buffer de réception.
  • OP: opération de réduction MPI.
  • COMM: communicateur MPI.

PARAMETRES DE SORTIE

C:
  • recvbuf: pointeur vers le buffer de réception contenant les données réduites et diffusées.
Fortran:
  • RECVBUF: määrä buffer de réception.

DESCRIPTION

La routine MPI_Ireduce_scatter est la version non bloquante de la routine MPI_Reduce_scatter. Elle effectue une opération de réduction sur les données envoyées par tous les processus dans un communicateur et diffuse ensuite les résultats de la réduction aux processus. Le résultat est divisé en N blocs, où N est le nombre de processus dans le communicateur. Le i-ème bloc est envoyé au i-ème processus dans le communicateur. Le nombre d'éléments reçus par chaque processus est spécifié par le tableau recvcounts.

L'opération de réduction est appliquée aux données envoyées par tous les processus. Chaque processus envoie ses données locales au processus racine, qui effectue la réduction. Ensuite, le processus racine diffuse les résultats à tous les autres processus. Cependant, dans MPI_Ireduce_scatter, la diffusion est telle que le i-ème processus du communicateur reçoit le i-ème bloc des données réduites.

Les types de données génériques (versions `_c`) utilisent des entiers de 64 bits pour spécifier les tailles des types de données, permettant de gérer des communications plus importantes.

UTILISATION DE L'OPTION IN-PLACE

Lorsque l'option in-place est utilisée, `sendbuf` et `recvbuf` sont identiques. Les données envoyées par le processus doivent être suffisantes pour contenir les données reçues.

QUAND LE COMMUNICATEUR EST UN INTER-COMMUNICATEUR

Lorsque le communicateur est un inter-communicateur, l'opération est exécutée sur le groupe des processus locaux. Le processus racine doit être un processus du groupe local.

NOTES SUR LES OPÉRATIONS COLLECTIVES

Les opérations collectives MPI sont considérées comme bloquantes si elles ne sont pas spécifiquement identifiées comme non bloquantes. La sémantique des opérations collectives est définie par le profil MPI.

MPI_Ireduce_scatter est non bloquante. Elle retourne immédiatement. Les données dans `sendbuf` doivent être valides jusqu'à ce que l'opération soit terminée. Le buffer `recvbuf` sera disponible après la fin de l'opération.

ERREURS

Lorsqu'une erreur se produit dans une opération collective, tous les processus du communicateur participent à la gestion de l'erreur. En cas d'erreur, la routine de gestion des erreurs sera appelée. La façon dont les erreurs sont gérées peut dépendre des options de configuration du runtime MPI, mais par défaut, tous les processus s'arrêteront.

Les erreurs typiques incluent:

  • MPI_ERR_COMM: le communicateur n'est pas valide.
  • MPI_ERR_ARG: un argument n'est pas valide.
  • MPI_ERR_TYPE: un type de données n'est pas valide.
  • MPI_ERR_OP: une opération n'est pas valide.
  • MPI_ERR_RANK: un rang n'est pas valide.
  • MPI_ERR_COUNT: le nombre d'éléments est invalide.

Des erreurs spécifiques peuvent survenir, par exemple, si la somme des recvcounts n'est pas égale au nombre total d'éléments envoyés.

Pour plus d'informations sur la gestion des erreurs, consultez la page de manuel de MPI.

Pour une liste complète des codes d'erreur MPI, consultez les pages de manuel MPI.

Consultez la section sur la gestion des erreurs du standard MPI-3.1 pour plus d'informations.
