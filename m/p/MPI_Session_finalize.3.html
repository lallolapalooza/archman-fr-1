Paquet: openmpi

MPI_SESSION_FINALIZE(3) Open MPI MPI_SESSION_FINALIZE(3)

MPI_Session_finalize — libère tout état MPI associé à une session

SYNTAXE

Syntaxe C

#include <mpi.h>
int MPI_Session_finalize(MPI_Session *session)

Syntaxe Fortran

USE MPI
! ou l'ancienne forme : INCLUDE 'mpif.h'
MPI_SESSION_FINALIZE(SESSION, IERROR)
    INTEGER SESSION, IERROR

Syntaxe Fortran 2008

USE mpi_f08
MPI_Session_finalize(session, ierror)
    TYPE(MPI_Session), INTENT(IN) :: session
    INTEGER, OPTIONAL, INTENT(OUT) :: ierror

PARAMÈTRES D'ENTRÉE

•
session : session à finaliser (handle)

PARAMÈTRES DE SORTIE

•
ierror : seulement Fortran : Statut d'erreur (entier).

DESCRIPTION

MPI_Session_finalize libère tout état MPI associé à la session fournie. Chaque session instanciée doit être finalisée en utilisant MPI_Session_finalize. Le handle session est mis à MPI_SESSION_NULL par l'appel.

Plusieurs sessions peuvent être créées et détruites pendant la durée de vie d'un processus MPI. Ceci est différent du modèle MPI mondial, qui peut être initialisé au maximum exactement une fois (puis ensuite finalisé) pendant la durée de vie d'un processus MPI.

NOTES

Avant qu'un processus MPI n'invoque MPI_Session_finalize, le processus doit effectuer tous les appels MPI nécessaires pour compléter son implication dans les communications MPI : il doit terminer localement toutes les opérations MPI qu'il a initiées et il doit exécuter les appels correspondants nécessaires pour compléter les communications MPI initiées par d'autres processus. L'appel à MPI_Session_finalize ne libère pas les objets créés par les appels MPI ; ces objets sont libérés en utilisant les appels MPI_XXX_FREE. MPI_Session_finalize peut se synchroniser sur n'importe lequel ou tous les groupes associés à des communicateurs, des fenêtres ou des fichiers dérivés de la session et qui ne sont pas déconnectés, libérés ou fermés, respectivement, avant l'appel à la procédure MPI_Session_finalize. MPI_Session_finalize se comporte comme si toutes ces synchronisations se produisaient de manière concurrente. Comme MPI_Comm_free peut marquer un communicateur pour une libération ultérieure, MPI_Session_finalize peut se synchroniser sur le groupe associé à un communicateur qui est seulement libéré (avec MPI_Comm_free) plutôt que déconnecté (avec MPI_Comm_disconnect).

ERREURS

Presque toutes les routines MPI retournent une valeur d'erreur ; les routines C comme résultat de la fonction et les routines Fortran dans le dernier argument.

Avant que la valeur d'erreur ne soit retournée, le gestionnaire d'erreurs MPI actuel associé à l'objet de communication (par exemple, communicateur, fenêtre, fichier) est appelé. Si aucun objet de communication n'est associé à l'appel MPI, alors l'appel est considéré comme attaché à MPI_COMM_SELF et appellera le gestionnaire d'erreurs MPI associé. Lorsque MPI_COMM_SELF n'est pas initialisé (c'est-à-dire, avant MPI_Init/MPI_Init_thread, après MPI_Finalize, ou lors de l'utilisation exclusive du modèle de Sessions), l'erreur déclenche le gestionnaire d'erreurs initial. Le gestionnaire d'erreurs initial peut être modifié en appelant MPI_Comm_set_errhandler sur MPI_COMM_SELF lors de l'utilisation du modèle mondial, ou via l'argument de ligne de commande mpi_initial_errhandler de mpiexec ou la clé d'information de MPI_Comm_spawn/MPI_Comm_spawn_multiple. Si aucun autre gestionnaire d'erreurs approprié n'a été défini, alors le gestionnaire d'erreurs MPI_ERRORS_RETURN est appelé pour les fonctions d'E/S MPI et le gestionnaire d'erreurs MPI_ERRORS_ABORT est appelé pour toutes les autres fonctions MPI.

Open MPI inclut trois gestionnaires d'erreurs prédéfinis qui peuvent être utilisés :

  • MPI_ERRORS_ARE_FATAL Provoque l'arrêt du programme sur tous les processus MPI connectés.
  • MPI_ERRORS_ABORT Un gestionnaire d'erreurs qui peut être invoqué sur un communicateur, une fenêtre, un fichier ou une session. Lorsqu'il est appelé sur un communicateur, il agit comme si MPI_Abort avait été appelé sur ce communicateur. S'il est appelé sur une fenêtre ou un fichier, il agit comme si MPI_Abort avait été appelé sur un communicateur contenant le groupe des processus dans la fenêtre ou le fichier correspondant. S'il est appelé sur une session, il n'interrompt que le processus local.
  • MPI_ERRORS_RETURN Retourne un code d'erreur à l'application.

Les applications MPI peuvent également implémenter leurs propres gestionnaires d'erreurs en appelant :

  • MPI_Comm_create_errhandler puis MPI_Comm_set_errhandler
  • MPI_File_create_errhandler puis MPI_File_set_errhandler
  • MPI_Session_create_errhandler puis MPI_Session_set_errhandler ou lors de MPI_Session_init
  • MPI_Win_create_errhandler puis MPI_Win_set_errhandler

Notez que MPI ne garantit pas qu'un programme MPI puisse continuer après une erreur.

Voir la page man MPI pour une liste complète des codes d'erreur MPI.

Voir la section Gestion des erreurs de la norme MPI-3.1 pour plus d'informations.
