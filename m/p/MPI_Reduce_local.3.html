MPI_Reduce_local — Effectuer une réduction locale

SYNTAXE

Syntaxe C

#include <mpi.h>
int MPI_Reduce_local(const void *inbuf, void *inoutbuf, int count,
     MPI_Datatype datatype, MPI_Op op)

Syntaxe Fortran

USE MPI
! ou la forme plus ancienne : INCLUDE 'mpif.h'
MPI_REDUCE_LOCAL(INBUF, INOUTBUF, COUNT, DATATYPE, OP, IERROR)
     <type>  INBUF(*), INOUTBUF(*)
     INTEGER COUNT, DATATYPE, OP, IERROR

Syntaxe Fortran 2008

USE mpi_f08
MPI_Reduce_local(inbuf, inoutbuf, count, datatype, op, ierror)
     TYPE(*), DIMENSION(..), INTENT(IN) :: inbuf
     TYPE(*), DIMENSION(..) :: inoutbuf
     INTEGER, INTENT(IN) :: count
     TYPE(MPI_Datatype), INTENT(IN) :: datatype
     TYPE(MPI_Op), INTENT(IN) :: op
     INTEGER, OPTIONAL, INTENT(OUT) :: ierror

PARAMÈTRES D'ENTRÉE

  • inbuf: Adresse du tampon d'entrée (choix).
  • count: Nombre d'éléments dans le tampon d'entrée (entier).
  • datatype: Type de données des éléments du tampon d'entrée (handle).
  • op: Opération de réduction (handle).

PARAMÈTRES DE SORTIE

  • inoutbuf: Adresse du tampon d'entrée/sortie (choix).
  • ierror: Fortran uniquement : Statut d'erreur (entier).

DESCRIPTION

Les fonctions de réduction globale (MPI_Reduce_local, MPI_Op_create, MPI_Op_free, MPI_Allreduce, MPI_Reduce_local_scatter, MPI_Scan) effectuent une opération de réduction globale (comme une somme, un maximum, un ET logique, etc.) sur tous les membres d'un groupe. L'opération de réduction peut être soit l'une d'une liste d'opérations prédéfinies, soit une opération définie par l'utilisateur. Les fonctions de réduction globale se présentent sous plusieurs formes : une réduction qui renvoie le résultat de la réduction sur un nœud, une all-réduction qui renvoie ce résultat sur tous les nœuds, et une opération scan (préfixe parallèle). De plus, une opération reduce-scatter combine les fonctionnalités d'une opération reduce et d'une opération scatter.

MPI_Reduce_local combine les éléments fournis dans les tampons d'entrée et d'entrée/sortie du processus local, en utilisant l'opération op, et renvoie la valeur combinée dans le tampon d'entrée/sortie. Le tampon d'entrée est défini par les arguments inbuf, count et datatype ; le tampon de sortie est défini par les arguments inoutbuf, count et datatype ; tous deux ont le même nombre d'éléments, avec le même type. La routine est un appel local. Le processus peut fournir un élément, ou une séquence d'éléments, auquel cas l'opération de combinaison est exécutée élément par élément sur chaque entrée de la séquence. Par exemple, si l'opération est MPI_MAX et que le tampon d'entrée contient deux éléments qui sont des nombres à virgule flottante (count = 2 et datatype = MPI_FLOAT), alors inoutbuf(1) = max global (inbuf(1)) et inoutbuf(2) = max global(inbuf(2)).

UTILISATION DE L'OPTION IN-PLACE

L'utilisation de MPI_IN_PLACE est interdite avec MPI_Reduce_local.

OPÉRATIONS DE RÉDUCTION PRÉDÉFINIES

L'ensemble des opérations prédéfinies fournies par MPI est listé ci-dessous (Opérations de réduction prédéfinies). Cette section énumère également les types de données sur lesquels chaque opération peut être appliquée. De plus, les utilisateurs peuvent définir leurs propres opérations qui peuvent être surchargées pour opérer sur plusieurs types de données, qu'ils soient de base ou dérivés. Ceci est expliqué plus en détail dans la description des opérations définies par l'utilisateur (voir les pages man de MPI_Op_create et MPI_Op_free).

L'opération op est toujours supposée être associative. Toutes les opérations prédéfinies sont également supposées être commutatives. Les utilisateurs peuvent définir des opérations qui sont supposées être associatives, mais pas commutatives. L'ordre d'évaluation « canonique » d'une réduction est déterminé par les rangs des processus dans le groupe. Cependant, l'implémentation peut tirer parti de l'associativité, ou de l'associativité et de la commutativité, afin de modifier l'ordre d'évaluation. Cela peut modifier le résultat de la réduction pour les opérations qui ne sont pas strictement associatives et commutatives, comme l'addition en virgule flottante.

Les opérateurs prédéfinis fonctionnent uniquement avec les types MPI listés ci-dessous (Opérations de réduction prédéfinies, et la section MINLOC et MAXLOC, ci-dessous). Les opérateurs définis par l'utilisateur peuvent opérer sur des types de données dérivés généraux. Dans ce cas, chaque argument sur lequel l'opération de réduction est appliquée est un élément décrit par un tel type de données, qui peut contenir plusieurs valeurs de base. Ceci est expliqué plus en détail dans la section 4.9.4 de la norme MPI, « Opérations définies par l'utilisateur ».

Les opérations prédéfinies suivantes sont fournies pour MPI_Reduce_local et les fonctions associées MPI_Allreduce, MPI_Reduce_scatter et MPI_Scan. Ces opérations sont invoquées en plaçant les éléments suivants dans op :

MINLOC ET MAXLOC

L'opérateur MPI_MINLOC est utilisé pour calculer un minimum global ainsi qu'un index associé à la valeur minimale. MPI_MAXLOC calcule de manière similaire un maximum global et son index.

L'opération définissant MPI_MAXLOC est

         ( i )    (  j )      ( k )

et

   k   = ( min(i, j)    si u = v

         (  j           si u < v)

MPI_MINLOC est défini de manière similaire :

         ( u )    (  v )      ( w )
         (   )  o (    )   =  (   )
         ( i )    (  j )      ( k )
où
    w = min(u, v)
et
         ( i            si u < v
         (
   k   = ( min(i, j)    si u = v
         (
         (  j           si u > v)

Les deux opérations sont associatives et commutatives. Notez que si MPI_MAXLOC est appliqué pour réduire une séquence de paires (u(0), 0), (u(1), 1), …, (u(n-1), n-1), alors la valeur retournée est (u, r), où u = max(i) u(i) et r est l'index du premier maximum global dans la séquence. L'opération de réduction est définie pour agir sur des arguments constituants une paire : une valeur et un index. Pour Fortran et C, des types sont fournis pour décrire cette paire. La nature potentiellement mixte de ces arguments est un problème en Fortran. Le problème est évité, pour Fortran, en ayant le type fourni par MPI consistant en une paire de types égaux à la valeur, et en forçant également l'index à ce type. En C, le type fourni par MPI a des types distincts et l'index est un int.

Pour utiliser MPI_MAXLOC et MPI_MINLOC dans une opération de réduction, un argument de type de données représentant une paire (valeur et index) doit être fourni. MPI fournit neuf types de données prédéfinis de ce type. Les opérations MPI_MAXLOC et MPI_MINLOC peuvent être utilisées avec chacun des types de données suivants :

Fortran:
Nom                     Description
MPI_2REAL                paire de REALs
MPI_2DOUBLE_PRECISION    paire de variables DOUBLE-PRECISION
MPI_2INTEGER             paire de INTEGERs
C:
Nom                     Description
MPI_FLOAT_INT            float et int
MPI_DOUBLE_INT           double et int
MPI_LONG_INT             long et int
MPI_2INT                 paire de ints
MPI_SHORT_INT            short et int
MPI_LONG_DOUBLE_INT      long double et int

Le type de données MPI_2REAL est équivalent à :

call MPI_TYPE_CONTIGUOUS(2, MPI_REAL, MPI_2REAL)

Ces déclarations s'appliquent également pour MPI_2INTEGER, MPI_2DOUBLE_PRECISION et MPI_2INT.

Le type de données MPI_FLOAT_INT est comme s'il avait été défini par la séquence d'instructions suivante :

Ces déclarations s'appliquent également pour MPI_LONG_INT et MPI_DOUBLE_INT.

Tous les objets MPI (par exemple, MPI_Datatype, MPI_Comm) sont de type INTEGER en Fortran.

Les opérateurs de réduction (MPI_Op) ne renvoient pas de valeur d'erreur. Par conséquent, si les fonctions détectent une erreur, tout ce qu'elles peuvent faire est d'appeler MPI_Abort ou de passer silencieusement le problème. Ainsi, si vous changez le gestionnaire d'erreurs de MPI_ERRORS_ARE_FATAL à autre chose, par exemple MPI_ERRORS_RETURN, aucune erreur ne sera signalée.

La raison en est le problème de performance lié à la garantie que toutes les routines d'opérations collectives renvoient la même valeur d'erreur.

La plupart des routines MPI renvoient une valeur d'erreur ; les routines C renvoient le résultat de la fonction et les routines Fortran dans le dernier argument.

Avant que la valeur d'erreur ne soit renvoyée, le gestionnaire d'erreurs associé à l'objet de communication (par exemple, communicator, window, file) lié à l'appel MPI est appelé. S'il n'y a pas d'objet de communication associé à l'appel MPI, l'appel est considéré comme associé à MPI_COMM_SELF et le gestionnaire d'erreurs associé à cet objet est appelé. Lorsque MPI_COMM_SELF n'est pas initialisé (c'est-à-dire avant MPI_Init/MPI_Init_thread, après MPI_Finalize, ou lorsque le modèle de session est utilisé exclusivement), le gestionnaire d'erreurs initial est déclenché. Le gestionnaire d'erreurs initial peut être modifié en appelant MPI_Comm_set_errhandler sur MPI_COMM_SELF lors de l'utilisation du modèle mondial, ou l'argument mpi_initial_errhandler de mpiexec, ou la clé info de MPI_Comm_spawn/MPI_Comm_spawn_multiple. Si aucun autre gestionnaire d'erreurs approprié n'est trouvé, le gestionnaire d'erreurs MPI_ERRORS_RETURN est appelé pour les fonctions d'E/S MPI et le gestionnaire d'erreurs MPI_ERRORS_ABORT pour toutes les autres fonctions MPI.

Open MPI inclut trois gestionnaires d'erreurs prédéfinis qui peuvent être utilisés :

  • MPI_ERRORS_ARE_FATAL Provoque l'arrêt du programme de tous les processus MPI connectés.
  • MPI_ERRORS_ABORT Un gestionnaire d'erreurs qui peut être invoqué sur un communicator, une fenêtre, un fichier ou une session. Lorsqu'il est appelé sur un communicator, il agit comme si MPI_Abort avait été appelé sur ce communicator. S'il est appelé sur une fenêtre ou un fichier, il agit comme si MPI_Abort avait été appelé sur un communicator contenant le groupe de processus de la fenêtre ou du fichier correspondant. S'il est appelé sur une session, il n'interrompt que le processus local.
  • MPI_ERRORS_RETURN Renvoie un code d'erreur à l'application.

Les applications MPI peuvent également implémenter leurs propres gestionnaires d'erreurs en appelant :

  • MPI_Comm_create_errhandler puis MPI_Comm_set_errhandler
  • MPI_File_create_errhandler puis MPI_File_set_errhandler
  • MPI_Session_create_errhandler puis MPI_Session_set_errhandler ou lors de MPI_Session_init
  • MPI_Win_create_errhandler puis MPI_Win_set_errhandler

Remarque : MPI ne garantit pas qu'un programme MPI puisse continuer après une erreur.

Voir la page de manuel MPI pour une liste complète des codes d'erreur MPI.
