Paramètres d'entrée

  • sendbuf: Adresse de départ du tampon d'envoi (optionnel).
  • recvcounts: Tableau d'entiers spécifiant le nombre d'éléments dans le résultat distribué à chaque processus. Le tableau doit être identique sur tous les processus appelants.
  • datatype: Type des éléments du tampon d'entrée (handle).
  • op: Opération (handle).
  • comm: Communicateur (handle).
  • info: Informations (handle, persistant).

Paramètres de sortie

  • recvbuf: Adresse de départ du tampon de réception (optionnel).
  • request: Requête (handle, non bloquant uniquement).
  • ierror: En Fortran uniquement : État d'erreur (entier).

Description

MPI_Reduce_scatter effectue une réduction élément par élément sur un vecteur de count = S(i)recvcounts[i] éléments dans le tampon d'envoi défini par sendbuf, count, et datatype. Le vecteur de résultats obtenu est ensuite divisé en n segments disjoints, où n est le nombre de processus dans le groupe. Le segment i contient recvcounts[i] éléments. Le segment i est envoyé au processus i et stocké dans le tampon de réception défini par recvbuf, recvcounts[i], et datatype.

Utilisation de l'option "in-place"

Lorsque le communicateur est un communicateur intra, vous pouvez effectuer une opération de réduction-diffusion directement sur le tampon d'entrée (le tampon de sortie est utilisé comme le tampon d'entrée). Utilisez la variable MPI_IN_PLACE comme valeur pour la variable sendbuf. Dans ce cas, les données d'entrée seront prises à partir du début du tampon de réception. La zone occupée par les données d'entrée peut être plus longue ou plus courte que les données remplies par le tampon de sortie.

Lorsque le communicateur est un communicateur inter-groupe

Lorsque le communicateur est un communicateur inter-groupe, l'opération de réduction-diffusion se déroule en deux phases. Premièrement, le résultat de la réduction effectuée sur les données fournies par les processus du premier groupe est distribué aux processus du second groupe. Ensuite, l'opération inverse se produit : le résultat de la réduction effectuée sur les données fournies par les processus du second groupe est distribué aux processus du premier groupe. Pour chaque groupe, tous les processus fournissent le même argument recvcounts, et la somme des valeurs de recvcounts doit être identique pour les deux groupes.

Remarques sur les opérations collectives

Les fonctions de réduction (MPI_Op) ne retournent pas de valeur d'erreur. Par conséquent, si les fonctions détectent une erreur, elles ne peuvent qu'appeler MPI_Abort ou ignorer le problème. Par conséquent, si vous modifiez le gestionnaire d'erreurs de MPI_ERRORS_ARE_FATAL pour quelque chose d'autre, par exemple MPI_ERRORS_RETURN, aucune erreur ne sera indiquée.

La raison en est le problème de performance lié à la garantie que toutes les routines collectives retournent la même valeur d'erreur.

Erreurs

La plupart des routines MPI retournent une valeur d'erreur ; en C, le résultat est retourné comme valeur de retour de la fonction et en Fortran, dans le dernier argument.

Avant que la valeur d'erreur ne soit retournée, le gestionnaire d'erreurs associé à l'objet de communication (par exemple, communicateur, fenêtre, fichier) actuel est appelé. S'il n'y a pas d'objet de communication associé à l'appel MPI, l'appel est considéré comme associé à MPI_COMM_SELF et le gestionnaire d'erreurs associé à MPI_COMM_SELF est appelé. Lorsque MPI_COMM_SELF n'est pas initialisé (c'est-à-dire avant MPI_Init/MPI_Init_thread, après MPI_Finalize, ou lorsque le modèle de sessions est utilisé exclusivement), le gestionnaire d'erreurs initial est déclenché. Le gestionnaire d'erreurs initial peut être modifié en appelant MPI_Comm_set_errhandler sur MPI_COMM_SELF lors de l'utilisation du modèle du monde, ou via l'argument mpi_initial_errhandler de mpiexec ou via la clé info de MPI_Comm_spawn/MPI_Comm_spawn_multiple. S'il n'y a pas d'autre gestionnaire d'erreurs approprié, le gestionnaire d'erreurs MPI_ERRORS_RETURN est appelé pour les fonctions d'E/S MPI et le gestionnaire d'erreurs MPI_ERRORS_ABORT est appelé pour les autres fonctions MPI.

Open MPI inclut trois gestionnaires d'erreurs prédéfinis qui peuvent être utilisés :

  • MPI_ERRORS_ARE_FATAL Provoque l'arrêt de tous les processus MPI connectés.
  • MPI_ERRORS_ABORT Un gestionnaire d'erreurs qui peut être invoqué sur un communicateur, une fenêtre, un fichier ou une session. Lorsqu'il est invoqué sur un communicateur, il agit comme si MPI_Abort avait été appelé sur ce communicateur. S'il est invoqué sur une fenêtre ou un fichier, il agit comme si MPI_Abort avait été appelé sur un communicateur contenant l'ensemble des processus dans la fenêtre ou le fichier correspondant. S'il est invoqué sur une session, il n'aborte que le processus local.
  • MPI_ERRORS_RETURN Retourne un code d'erreur à l'application.

Les applications MPI peuvent également implémenter leurs propres gestionnaires d'erreurs en appelant :

  • MPI_Comm_create_errhandler puis MPI_Comm_set_errhandler
  • MPI_File_create_errhandler puis MPI_File_set_errhandler
  • MPI_Session_create_ errhandler puis MPI_Session_set_errhandler
