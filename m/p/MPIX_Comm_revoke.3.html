MPIX_COMM_REVOKE(3) Open MPI MPIX_COMM_REVOKE(3)

MPIX_Comm_revoke - Révocquer un communicateur, provoquant la levée d'erreurs, à tous les rangs, pour les opérations non locales sur le communicateur.

Ceci fait partie de l'extension ULFM (User Level Fault Mitigation) de MPI.

SYNTAXE

Syntaxe C

#include <mpi.h>
#include <mpi-ext.h>
int MPIX_Comm_revoke(MPI_Comm comm)

Syntaxe Fortran

USE MPI
USE MPI_EXT
! ou l'ancienne forme : INCLUDE 'mpif.h'
MPIX_COMM_REVOKE(COMM, IERROR)
     INTEGER COMM, IERROR

Syntaxe Fortran 2008

USE mpi_f08
USE mpi_ext_f08
MPIX_Comm_revoke(comm, ierror)
     TYPE(MPI_Comm), INTENT(IN) :: comm
     INTEGER, OPTIONAL, INTENT(OUT) :: ierror

PARAMÈTRES D'ENTRÉE

•
comm: Communicateur (descripteur).

PARAMÈTRES DE SORTIE

•
ierror: Uniquement Fortran : Statut d'erreur (entier).

DESCRIPTION

Cette fonction marque le communicateur comm comme révoqué à tous les processus MPI des groupes (locaux et distants) associés au communicateur comm. Cette fonction n'est pas collective et n'a donc pas d'appel correspondant sur les processus MPI distants.

La documentation de MPIX_Comm_is_revoked détaille les conditions selon lesquelles un communicateur devient révoqué localement, et quelles sémantiques s'appliquent à un communicateur révoqué. En résumé, lorsqu'un communicateur est révoqué, les opérations non locales lèvent une exception de classe MPIX_ERR_REVOKED, à l'exception de certaines opérations tolérantes aux fautes.

PROPAGATION DE L'ÉTAT RÉVOQUÉ ET ORDRE

L'implémentation propage l'état révoqué de manière tolérante aux fautes ; par conséquent, le communicateur devient révoqué à tous les processus MPI non défaillants appartenant à comm, malgré les processus défaillants.

Il n'y a pas d'ordre particulier entre l'appel de révocation sur un autre processus et l'achèvement des opérations sur un processus local. Par exemple, une opération de réception peut lever une erreur de classe MPIX_ERR_REVOKED, même si la procédure d'envoi est appelée avant la procédure de révocation sur l'expéditeur.

ERREURS

Presque toutes les routines MPI retournent une valeur d'erreur ; les routines C comme résultat de la fonction et les routines Fortran dans le dernier argument.

Avant que la valeur d'erreur ne soit retournée, le gestionnaire d'erreurs MPI actuel associé à l'objet de communication (par exemple, communicateur, fenêtre, fichier) est appelé. Si aucun objet de communication n'est associé à l'appel MPI, alors l'appel est considéré comme attaché à MPI_COMM_SELF et appellera le gestionnaire d'erreurs MPI associé. Lorsque MPI_COMM_SELF n'est pas initialisé (c'est-à-dire, avant MPI_Init/MPI_Init_thread, après MPI_Finalize, ou lors de l'utilisation exclusive du modèle de sessions), l'erreur déclenche le gestionnaire d'erreurs initial. Le gestionnaire d'erreurs initial peut être modifié en appelant MPI_Comm_set_errhandler sur MPI_COMM_SELF lors de l'utilisation du modèle World, ou via l'argument de ligne de commande mpi_initial_errhandler de mpiexec ou la clé d'information de MPI_Comm_spawn/MPI_Comm_spawn_multiple. Si aucun autre gestionnaire d'erreurs approprié n'a été défini, le gestionnaire d'erreurs MPI_ERRORS_RETURN est appelé pour les fonctions d'E/S MPI et le gestionnaire d'erreurs MPI_ERRORS_ABORT est appelé pour toutes les autres fonctions MPI.

Open MPI inclut trois gestionnaires d'erreurs prédéfinis qui peuvent être utilisés :

  • MPI_ERRORS_ARE_FATAL Provoque l'abandon du programme par tous les processus MPI connectés.
  • MPI_ERRORS_ABORT Un gestionnaire d'erreurs qui peut être invoqué sur un communicateur, une fenêtre, un fichier ou une session. Lorsqu'il est appelé sur un communicateur, il agit comme si MPI_Abort avait été appelé sur ce communicateur. S'il est appelé sur une fenêtre ou un fichier, il agit comme si MPI_Abort avait été appelé sur un communicateur contenant le groupe de processus dans la fenêtre ou le fichier correspondant. S'il est appelé sur une session, il abandonne uniquement le processus local.
  • MPI_ERRORS_RETURN Retourne un code d'erreur à l'application.

Les applications MPI peuvent également implémenter leurs propres gestionnaires d'erreurs en appelant :

  • MPI_Comm_create_errhandler puis MPI_Comm_set_errhandler
  • MPI_File_create_errhandler puis MPI_File_set_errhandler
  • MPI_Session_create_errhandler puis MPI_Session_set_errhandler ou lors de MPI_Session_init
  • MPI_Win_create_errhandler puis MPI_Win_set_errhandler

Notez que MPI ne garantit pas qu'un programme MPI puisse continuer après une erreur.

Voir la page de manuel MPI pour une liste complète des codes d'erreur MPI.

Voir la section Gestion des erreurs de la norme MPI-3.1 pour plus d'informations.
