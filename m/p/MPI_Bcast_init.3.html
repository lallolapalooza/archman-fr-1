MPI_Bcast_init(3) Open MPI MPI_Bcast_init(3)

MPI_Bcast, MPI_Ibcast - Envoie un message du processus racine à tous les autres processus du groupe.

Syntaxe

Syntaxe C

#include <mpi.h>
int MPI_Bcast(void *buffer, int count, MPI_Datatype datatype,
    int root, MPI_Comm comm)
int MPI_Ibcast(void *buffer, int count, MPI_Datatype datatype,
    int root, MPI_Comm comm, MPI_Request *request)

Syntaxe Fortran

USE MPI
! ou l'ancienne forme : INCLUDE 'mpif.h'
MPI_BCAST(BUFFER, COUNT, DATATYPE, ROOT, COMM, IERROR)
    TYPE(*), DIMENSION(..) :: BUFFER
    INTEGER COUNT, DATATYPE, ROOT, COMM, IERROR
MPI_IBCAST(BUFFER, COUNT, DATATYPE, ROOT, COMM, REQUEST, IERROR)
    TYPE(*), DIMENSION(..), ASYNCHRONOUS :: BUFFER
    INTEGER COUNT, DATATYPE, ROOT, COMM, REQUEST, IERROR

Syntaxe Fortran 2008

USE mpi_f08
MPI_Bcast(buffer, count, datatype, root, comm, ierror)
    TYPE(*), DIMENSION(..) :: buffer
    INTEGER, INTENT(IN) :: count, root
    TYPE(MPI_Datatype), INTENT(IN) :: datatype
    TYPE(MPI_Comm), INTENT(IN) :: comm
    INTEGER, OPTIONAL, INTENT(OUT) :: ierror
MPI_IBcast(buffer, count, datatype, root, comm, request, ierror)
    TYPE(*), DIMENSION(..), ASYNCHRONOUS :: buffer
    INTEGER, INTENT(IN) :: count, root
    TYPE(MPI_Datatype), INTENT(IN) :: datatype
    TYPE(MPI_Comm), INTENT(IN) :: comm
    TYPE(MPI_Request), INTENT(OUT) :: request
    INTEGER, OPTIONAL, INTENT(OUT) :: ierror

Paramètres entrée/sortie

  • buffer: Adresse de début du tampon (optionnel).
  • count: Nombre d'éléments dans le tampon (entier).
  • datatype: Type de données du tampon (handle).
  • root: Rang du processus d'envoi (entier).
  • comm: Communicateur (handle).

Paramètres de sortie

  • request: Requête (handle, non bloquant).
  • ierror: Fortran uniquement : statut d'erreur (entier).

Description

MPI_Bcast envoie un message du processus racine à tous les autres processus du groupe, y compris lui-même. Tous les membres du groupe doivent être appelés avec les mêmes arguments pour comm et root. Au retour, le contenu du tampon de communication de la racine a été copié vers tous les processus.

Les types de données dérivés sont autorisés pour datatype. Le schéma de type de count et datatype sur n'importe quel processus doit être le même que le schéma de type de count et datatype sur le processus racine. Cela implique que le volume de données envoyées doit être égal au volume reçu, entre chaque processus et la racine. MPI_Bcast et toutes les autres routines de déplacement de données permettent cette restriction. Les correspondances de types différentes entre expéditeur et récepteur sont toujours autorisées.

Exemple : Envoyer 100 entiers du processus 0 à tous les processus du groupe.

MPI_Comm comm;
int array[100];
int root=0;
//...
MPI_Bcast( array, 100, MPI_INT, root, comm);

Comme dans bon nombre de nos exemples de code, nous supposons que certaines des variables (comme comm dans l'exemple ci-dessus) ont reçu des valeurs appropriées.

Quand le communicateur est un inter-communicateur

Lorsque le communicateur est un inter-communicateur, le processus racine du premier groupe envoie des données à tous les processus du second groupe. Le premier groupe définit le processus racine. Ce processus utilise MPI_ROOT comme valeur de son argument root. Les processus restants utilisent MPI_PROC_NULL comme valeur de leur argument root. Tous les processus du second groupe utilisent le rang du processus racine du premier groupe comme valeur de leur argument root. Les arguments de tampon de réception des processus du second groupe doivent être cohérents avec les arguments de tampon d'envoi du processus racine du premier groupe.

Notes

Cette fonction ne prend pas en charge l'option in-place.

Erreurs

La plupart des routines MPI renvoient une valeur d'erreur ; en C, la valeur de retour de la fonction ; en Fortran, le dernier argument.

Avant de renvoyer la valeur d'erreur, le gestionnaire d'erreurs associé à l'objet de communication (par exemple, communicateur, fenêtre, fichier) actuel est appelé. S'il n'y a pas d'objet de communication associé à l'appel MPI, l'appel est considéré comme associé à MPI_COMM_SELF et le gestionnaire d'erreurs approprié est appelé. Lorsque MPI_COMM_SELF n'est pas initialisé (c'est-à-dire avant MPI_Init/MPI_Init_thread, après MPI_Finalize, ou lorsque le modèle de session est utilisé exclusivement), l'erreur appelle le gestionnaire d'erreurs initial. Le gestionnaire d'erreurs initial peut être modifié en appelant MPI_Comm_set_errhandler sur MPI_COMM_SELF lors de l'utilisation du modèle World, ou sur l'option mpi_initial_errhandler dans mpiexec ou sur la clé d'informations dans MPI_Comm_spawn/MPI_Comm_spawn_multiple. S'il n'y a pas d'autre gestionnaire d'erreurs approprié, le gestionnaire d'erreurs MPI_ERRORS_RETURN est appelé pour les fonctions d'E/S MPI et le gestionnaire d'erreurs MPI_ERRORS_ABORT pour toutes les autres fonctions MPI.

Open MPI inclut trois gestionnaires d'erreurs par défaut qui peuvent être utilisés :

  • MPI_ERRORS_ARE_FATAL Provoque l'abandon du programme pour tous les processus MPI connectés.
  • MPI_ERRORS_ABORT Un gestionnaire d'erreurs qui peut être appelé sur un communicateur, une fenêtre, un fichier ou une session. Lorsqu'il est appelé sur un communicateur, il agit comme si MPI_Abort avait été appelé sur ce communicateur. S'il est appelé sur une fenêtre ou un fichier, il agit comme si MPI_Abort avait été appelé sur un communicateur contenant le groupe de processus dans la fenêtre ou le fichier correspondant. S'il est appelé sur une session, il abandonne uniquement le processus local.
  • MPI_ERRORS_RETURN Renvoie un code d'erreur au programme.

Les applications MPI peuvent également implémenter leurs propres gestionnaires d'erreurs en appelant :

  • MPI_Comm_create_errhandler puis MPI_Comm_set_errhandler
  • MPI_File_create_errhandler puis MPI_File_set_errhandler
  • MPI_Session_create_errhandler puis MPI_Session_set_errhandler ou dans MPI_Session_init
  • MPI_Win_create_errhandler puis MPI_Win_set_errhandler

Note : Les programmes MPI ne garantissent pas qu'ils peuvent continuer après une erreur.

Voir la page de manuel MPI pour une liste complète des codes d'erreur MPI.

Voir la section sur la gestion des erreurs de la norme MPI-3.1 pour plus d'informations.

    MPI_Bcast_init

    MPI_Bcast_init — Initializes a non-blocking broadcast. (Not yet standardized)

    NOM

    MPI_Bcast_init — Initialise une diffusion non bloquante. (Pas encore standardisé)

    SYNTAXE

    C

    int MPI_Bcast_init(const void *buffer, int count, MPI_Datatype datatype, int root, MPI_Comm comm, MPI_Info info, MPI_Request *request);

    FORTRAN

    CALL MPI_BCAST_INIT(BUFFER, COUNT, DATATYPE, ROOT, COMM, INFO, REQUEST, IERROR)

    C++

    MPI::Request MPI::Comm::Bcast_init(const void* buffer, int count, const MPI::Datatype& datatype, int root, const MPI::Info& info) const;
    MPI::Request MPI::Comm::Bcast_init(const void* buffer, int count, const MPI::Datatype& datatype, int root) const;

    PARAMETRES

    buffer

    Données à diffuser (destination pour les rangs non-racine).

    count

    Nombre d'éléments dans le buffer.

    datatype

    Type de données des éléments dans le buffer.

    root

    Rang du processus racine.

    comm

    Communicateur.

    info

    Objet d'informations (peut être MPI_INFO_NULL).

    request

    Objet requête.

    IERROR

    Variable d'entier Fortran pour le code de retour.

    DESCRIPTION

    MPI_Bcast_init initialise une opération de diffusion non bloquante. L'opération de diffusion, une fois initialisée, peut être exécutée plusieurs fois avec des données potentiellement différentes à chaque fois, mais en utilisant le même objet requête. L'utilisation de plusieurs exécutions de la même requête n'est pas standardisée par MPI.

    Le paramètre buffer pointe vers le buffer de données à diffuser. Pour le processus racine, ce buffer est la source des données. Pour tous les autres processus, ce buffer est le destinataire des données.

    Le paramètre count spécifie le nombre d'éléments dans le buffer, et datatype spécifie le type de données de ces éléments.

    Le paramètre root spécifie le rang du processus qui envoie les données. Tous les autres processus dans le communicateur comm recevront les données.

    Le paramètre comm est le communicateur utilisé pour la diffusion.

    Le paramètre info est un objet d'informations qui peut être utilisé pour fournir des indications à l'implémentation MPI, par exemple pour l'optimisation des performances. Si aucune information spécifique n'est nécessaire, MPI_INFO_NULL doit être utilisé.

    Le paramètre request est un objet requête qui sera associé à cette opération de diffusion non bloquante. Une fois que l'opération est complétée (par exemple, après un appel à MPI_Wait ou MPI_Test), la requête sera associée à une opération complétée.

    QUAND LE COMMUNICATEUR EST UN INTER-COMMUNICATEUR

    Le comportement de MPI_Bcast_init avec un inter-communicateur n'est pas spécifié.

    NOTES

    MPI_Bcast_init est une fonction introduite dans la version 4.0 de MPI. Elle est conçue pour permettre des optimisations potentielles en pré-initialisant les opérations de diffusion qui pourraient être exécutées plusieurs fois.

    Il est de la responsabilité de l'utilisateur de s'assurer que les tampons utilisés pour l'envoi et la réception sont suffisamment grands pour contenir les données transmises. De plus, la synchronisation est nécessaire pour garantir que les données sont complètement transférées avant d'être utilisées. Cela est généralement géré par les fonctions de complétion de requête comme MPI_Wait ou MPI_Test.

    ERREURS

    Les erreurs potentielles incluent l'invalidité des paramètres (par exemple, un communicateur invalide, un rang racine invalide, un type de données invalide) ou des problèmes lors de l'allocation des ressources nécessaires pour l'opération non bloquante.
