MPI_Comm_create_from_group(3) Open MPI MPI_Comm_create_from_group(3)

MPI_Comm_create_from_group crée un nouveau communicateur à partir d'un groupe et d'un stringtag.

SYNTAX

Syntaxe C

#include <mpi.h>
int MPI_Comm_create_from_group(MPI_Group group, const char *stringtag, MPI_Info info, MPI_Errhandler errhandler, MPI_Comm *newcomm)

Syntaxe Fortran

USE MPI
! ou l'ancienne forme: INCLUDE 'mpif.h'
MPI_COMM_CREATE_FROM_GROUP(GROUP, STRINGTAG, INFO, ERRHANDLER, NEWCOMM, IERROR)
    INTEGER GROUP, INFO, ERRHANDLER, NEWCOMM, IERROR
    CHARACTER*(*) STRINGTAG

Syntaxe Fortran 2008

USE mpi_f08
MPI_Comm_create_from_group(group, stringtag, info, errhandler, newcomm, ierror)
    TYPE(MPI_Group), INTENT(IN) :: group
    CHARACTER(LEN=*), INTENT(IN) :: stringtag
    TYPE(MPI_Info), INTENT(IN) :: info
    TYPE(MPI_Errhandler), INTENT(IN) :: errhandler
    TYPE(MPI_Comm), INTENT(OUT) :: newcomm
    INTEGER, OPTIONAL, INTENT(OUT) :: ierror

PARAMÈTRES D'ENTRÉE

  • group : Groupe (handle).
  • stringtag : Identifiant unique pour cette opération (chaîne de caractères).
  • info : Objet d'information (handle).
errhandler
Gestionnaire d'erreur qui sera attaché au nouveau communicateur (handle).

PARAMÈTRES DE SORTIE

  • newcomm : Nouveau communicateur (handle).
  • ierror : En Fortran uniquement : valeur d'erreur (entier).

DESCRIPTION

MPI_Comm_create_from_group est similaire à MPI_Comm_create_group, sauf que l'ensemble des processus MPI impliqués dans la création du nouveau communicateur est spécifié par un argument groupe, au lieu du groupe associé à un communicateur existant. Si un groupe non vide est spécifié, alors tous les processus MPI de ce groupe doivent appeler la fonction, et chacun de ces processus doit fournir les mêmes arguments, y compris un groupe contenant les mêmes membres dans le même ordre et une valeur de stringtag identique. Dans le cas où MPI_GROUP_EMPTY est spécifié comme argument groupe, l'appel est une opération locale et MPI_COMM_NULL est retourné comme newcomm. L'argument stringtag est analogue à la balise utilisée dans MPI_Comm_create_group. Si plusieurs threads d'un processus MPI donné effectuent des opérations MPI_Comm_create_from_group concurrentes, l'utilisateur doit distinguer ces opérations en fournissant différentes valeurs de stringtag. Le stringtag ne doit pas dépasser la longueur de MPI_MAX_STRINGTAG_LEN caractères. Pour C, cela inclut l'espace pour le caractère nul.

NOTES

L'argument errhandler spécifie un gestionnaire d'erreur qui sera attaché au nouveau communicateur. L'argument info fournit des suggestions et des avertissements, potentiellement dépendants de l'implémentation MPI, indiquant les caractéristiques désirées et guidant la création du communicateur. MPI_MAX_STRINGTAG_LEN a une valeur d'au moins 63.

ERREURS

La plupart des routines MPI renvoient une valeur d'erreur ; pour les routines C, le résultat est la valeur d'erreur de la fonction, et pour les routines Fortran, le dernier argument.

Avant de renvoyer la valeur d'erreur, le gestionnaire d'erreur associé à l'objet de communication (par exemple, communicateur, fenêtre, fichier) actuel est appelé. S'il n'y a pas d'objet de communication associé à l'appel MPI, l'appel est considéré comme associé à MPI_COMM_SELF et le gestionnaire d'erreur associé à MPI_COMM_SELF est appelé. Lorsque MPI_COMM_SELF n'est pas initialisé (c'est-à-dire avant MPI_Init/MPI_Init_thread, après MPI_Finalize, ou lors de l'utilisation exclusive du Modèle de Session), l'erreur déclenche le gestionnaire d'erreur initial. Le gestionnaire d'erreur initial peut être modifié en appelant MPI_Comm_set_errhandler sur MPI_COMM_SELF lors de l'utilisation du Modèle du Monde, ou l'argument mpi_initial_errhandler de mpiexec ou la clé info de MPI_Comm_spawn/MPI_Comm_spawn_multiple. Si aucun autre gestionnaire d'erreur approprié n'est trouvé, le gestionnaire d'erreur MPI_ERRORS_RETURN est appelé pour les fonctions d'E/S MPI et le gestionnaire d'erreur MPI_ERRORS_ABORT pour toutes les autres fonctions MPI.

Open MPI inclut trois gestionnaires d'erreur par défaut qui peuvent être utilisés :

  • MPI_ERRORS_ARE_FATAL Arrête le programme de tous les processus MPI connectés.
  • MPI_ERRORS_ABORT Un gestionnaire d'erreur qui peut être invoqué sur un communicateur, une fenêtre, un fichier ou une session. Lorsqu'il est invoqué sur un communicateur, il agit comme si MPI_Abort avait été appelé sur ce communicateur. S'il est invoqué sur une fenêtre ou un fichier, il agit comme si MPI_Abort avait été appelé sur un communicateur contenant les processus de la fenêtre ou du fichier correspondant. S'il est invoqué sur une session, il arrête uniquement le processus local.
  • MPI_ERRORS_RETURN Renvoie un code d'erreur à l'application.

Les applications MPI peuvent également implémenter leurs propres gestionnaires d'erreur en appelant :

  • MPI_Comm_create_errhandler puis MPI_Comm_set_errhandler
  • MPI_File_create_errhandler puis MPI_File_set_errhandler
  • MPI_Session_create_errhandler puis MPI_Session_set_errhandler ou dans MPI_Session_init
  • MPI_Win_create_errhandler puis MPI_Win_set_errhandler

Note : MPI ne garantit pas qu'un programme MPI puisse continuer après une erreur.

Voir la page de manuel de MPI pour une liste complète des codes d'erreur MPI.

Voir la section sur la gestion des erreurs de la norme MPI-3.1 pour plus d'informations.
