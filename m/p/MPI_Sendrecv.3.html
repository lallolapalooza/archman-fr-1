MPI_Sendrecv — Envoie et reçoit un message.

SYNTAXE

Syntaxe C

#include <mpi.h>
int MPI_Sendrecv(const void *sendbuf, int sendcount, MPI_Datatype sendtype,
     int dest, int sendtag, void *recvbuf, int recvcount,
     MPI_Datatype recvtype, int source, int recvtag,
     MPI_Comm comm, MPI_Status *status)

Syntaxe Fortran

USE MPI
! ou l'ancienne forme : INCLUDE 'mpif.h'
MPI_SENDRECV(SENDBUF, SENDCOUNT, SENDTYPE, DEST, SENDTAG,
             RECVBUF, RECVCOUNT, RECVTYPE, SOURCE, RECVTAG, COMM,
             STATUS, IERROR)
     <type>  SENDBUF(*), RECVBUF(*)
     INTEGER SENDCOUNT, SENDTYPE, DEST, SENDTAG
     INTEGER RECVCOUNT, RECVTYPE, SOURCE, RECVTAG, COMM
     INTEGER STATUS(MPI_STATUS_SIZE), IERROR

Syntaxe Fortran 2008

USE mpi_f08
MPI_Sendrecv(sendbuf, sendcount, sendtype, dest, sendtag, recvbuf,
             recvcount, recvtype, source, recvtag, comm, status, ierror)
     TYPE(*), DIMENSION(..), INTENT(IN) :: sendbuf
     TYPE(*), DIMENSION(..) :: recvbuf
     INTEGER, INTENT(IN) :: sendcount, dest, sendtag, recvcount, source,
     recvtag
     TYPE(MPI_Datatype), INTENT(IN) :: sendtype, recvtype
     TYPE(MPI_Comm), INTENT(IN) :: comm
     TYPE(MPI_Status) :: status
     INTEGER, OPTIONAL, INTENT(OUT) :: ierror

PARAMÈTRES D'ENTRÉE

  • sendbuf : Adresse initiale du tampon d'envoi (optionnel).
  • sendcount : Nombre d'éléments à envoyer (entier).
  • sendtype : Type des éléments dans le tampon d'envoi (référence).
  • dest : Rang de destination (entier).
  • sendtag : Étiquette d'envoi (entier).
  • recvcount : Nombre maximal d'éléments à recevoir (entier).
  • recvtype : Type des éléments dans le tampon de réception (référence).
  • source : Rang de la source (entier).
  • recvtag : Étiquette de réception (entier).
  • comm : Communicateur (référence).

PARAMÈTRES DE SORTIE

  • recvbuf : Adresse initiale du tampon de réception (optionnel).
  • status : Objet d'état (status). Fait référence à l'opération de réception.
  • ierror : Fortran uniquement : État d'erreur (entier).

DESCRIPTION

Les opérations d'envoi et de réception combinent en un seul appel l'envoi d'un message vers une destination et la réception d'un autre message depuis un autre processus. Les deux (source et destination) peuvent être identiques. Une opération d'envoi et de réception est utile pour exécuter une opération de décalage dans une chaîne de processus. Si des opérations bloquantes d'envoi et de réception sont utilisées pour un tel décalage, il est nécessaire de bien ordonnancer les envois et les réceptions (par exemple, les processus pairs envoient en premier, puis les impairs reçoivent en premier, puis envoient) afin d'éviter des dépendances cycliques pouvant conduire à un blocage. Lorsque vous utilisez une opération d'envoi et de réception, le système de communication s'occupe de ces questions. L'opération d'envoi et de réception peut être utilisée en conjonction avec les fonctions décrites dans le chapitre « Topologie des processus » du Standard MPI pour effectuer des décalages sur différentes topologies logiques. Elle est également utile pour implémenter des appels de procédure distants.

Un message envoyé par une opération d'envoi et de réception peut être reçu par une opération de réception ordinaire ou testé par une opération de test ; une opération d'envoi et de réception peut recevoir un message envoyé par une opération d'envoi ordinaire.

MPI_Sendrecv exécute une opération d'envoi et de réception bloquante. L'envoi et la réception utilisent le même communicateur, mais peuvent avoir des étiquettes différentes. Les tampons d'envoi et de réception doivent être disjoints et peuvent avoir des longueurs et des types de données différents.

Si votre application n'a pas besoin d'examiner le champ d'état, vous pouvez économiser des ressources en utilisant la constante pré-définie MPI_STATUS_IGNORE comme valeur spéciale pour l'argument d'état.

ERREURS

La plupart des routines MPI retournent une valeur d'erreur ; les routines C retournent le résultat de la fonction et les routines Fortran dans le dernier argument.

Avant de retourner la valeur d'erreur, le gestionnaire d'erreurs associé à l'objet de communication (par exemple, communicateur, fenêtre, fichier) en cours d'utilisation est appelé. S'il n'y a pas d'objet de communication associé à l'appel MPI, l'appel est considéré comme associé à MPI_COMM_SELF et le gestionnaire d'erreurs correspondant est appelé. Lorsque MPI_COMM_SELF n'est pas initialisé (c'est-à-dire avant MPI_Init/MPI_Init_thread, après MPI_Finalize, ou lorsque le modèle de Sessions est utilisé exclusivement), le gestionnaire d'erreurs initial est déclenché. Le gestionnaire d'erreurs initial peut être modifié en appelant MPI_Comm_set_errhandler sur MPI_COMM_SELF lors de l'utilisation du modèle du Monde, ou via l'argument mpi_initial_errhandler de mpiexec ou la clé d'information pour MPI_Comm_spawn/MPI_Comm_spawn_multiple. S'il n'y a pas d'autre gestionnaire d'erreurs approprié, le gestionnaire d'erreurs MPI_ERRORS_RETURN est appelé pour les fonctions d'E/S MPI et le gestionnaire d'erreurs MPI_ERRORS_ABORT pour toutes les autres fonctions MPI.

Open MPI inclut trois gestionnaires d'erreurs prédéfinis qui peuvent être utilisés :

  • MPI_ERRORS_ARE_FATAL : Entraîne la fin du programme pour tous les processus MPI connectés.
  • MPI_ERRORS_ABORT : Un gestionnaire d'erreurs qui peut être invoqué sur un communicateur, une fenêtre, un fichier ou une session. Lorsqu'il est invoqué sur un communicateur, il agit comme si MPI_Abort avait été appelé sur ce communicateur. S'il est invoqué sur une fenêtre ou un fichier, il agit comme si MPI_Abort avait été appelé sur un communicateur contenant le groupe de processus dans la fenêtre ou le fichier correspondant. S'il est invoqué sur une session, seul le processus local est arrêté.
  • MPI_ERRORS_RETURN : Retourne un code d'erreur à l'application.

Les applications MPI peuvent également implémenter leurs propres gestionnaires d'erreurs en appelant :

  • MPI_Comm_create_errhandler puis MPI_Comm_set_errhandler
  • MPI_File_create_errhandler puis MPI_File_set_errhandler
  • MPI_Session_create_errhandler puis MPI_Session_set_errhandler ou dans MPI_Session_init
  • MPI_Win_create_errhandler puis MPI_Win_set_errhandler

Remarque : les gestionnaires d'erreurs MPI ne garantissent pas qu'un programme MPI puisse continuer après une erreur.

Voir la page de manuel MPI pour une liste complète des codes d'erreur MPI.

Voir la section de gestion des erreurs du standard MPI-3.1 pour plus d'informations.

Remarque : conformément à la section « Retour d'état » du chapitre « Communication point à point » du Standard MPI, les erreurs dans les messages reçus par MPI_Sendrecv ne définissent pas le champ status.MPI_ERROR dans l'objet d'état retourné. Le code d'erreur est toujours passé au gestionnaire d'erreurs du côté backend et peut être retourné à l'appelant via la valeur de retour de MPI_Sendrecv si le gestionnaire d'erreurs du côté backend retourne ce code. Le gestionnaire d'erreurs par défaut MPI_ERRORS_RETURN affiche ce comportement, par exemple.
