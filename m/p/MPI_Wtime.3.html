MPI_Wtime — Retourne le temps écoulé sur le processeur appelant.

SYNTAXE

Syntaxe C

#include <mpi.h>
double MPI_Wtime()

Syntaxe Fortran

USE MPI
! ou l'ancienne forme : INCLUDE 'mpif.h'
DOUBLE PRECISION MPI_WTIME()

Syntaxe Fortran 2008

USE mpi_f08
DOUBLE PRECISION MPI_WTIME()

VALEUR DE RETOUR

Temps en secondes depuis une heure arbitraire dans le passé.

DESCRIPTION

MPI_Wtime retourne un nombre à virgule flottante de secondes, représentant le temps écoulé (wall-clock time) depuis un moment donné dans le passé.

L'heure « du passé » est garantie de ne pas changer pendant la vie du processus. L'utilisateur est responsable de convertir de grands nombres de secondes en d'autres unités si elles sont préférées.

Cette fonction est portable (elle retourne des secondes, pas des « ticks »), elle permet une haute résolution et ne transporte aucun fardeau inutile. On l'utiliserait comme ceci :

{
   double starttime, endtime;
   starttime = MPI_Wtime();
    ....  ce qui doit être chronométré  ...
   endtime   = MPI_Wtime();
   printf("Cela a pris %f secondes\n", endtime-starttime);
}

Les temps retournés sont locaux au nœud qui les a appelés. Il n'y a aucune obligation que différents nœuds retournent la « même » heure.

NOTES

La variable booléenne MPI_WTIME_IS_GLOBAL, une clé d'attribut prédéfinie qui indique si les horloges sont synchronisées, n'a pas de valeur valide dans Open MPI, car les horloges ne sont pas garanties d'être synchronisées.

Cette fonction est conçue pour être une horloge à haute résolution, écoulée (ou murale). Voir MPI_Wtick pour déterminer la résolution de MPI_Wtime.

Sur les plateformes POSIX, cette fonction peut utiliser un timer moins coûteux à invoquer que l'appel système gettimeofday(), mais se rabattra sur gettimeofday() si un timer haute résolution peu coûteux n'est pas disponible. La commande ompi_info(1) peut être consultée pour voir si Open MPI prend en charge un timer haute résolution natif sur votre plateforme ; voir la valeur pour « MPI_Wtime support » (ou « options:mpi-wtime » lors de la visualisation de la sortie parsable). Si cette valeur est « native », une méthode qui est probablement moins coûteuse que gettimeofday() sera utilisée pour obtenir l'heure lors de l'invocation de MPI_Wtime.

Par exemple, sur les plateformes qui le prennent en charge, la fonction clock_gettime() sera utilisée pour obtenir une valeur d'horloge monotone avec la précision prise en charge sur cette plateforme (par exemple, des nanosecondes).

Notez également que le paramètre MCA opal_timer_require_monotonic peut influencer ce comportement. Il est vrai par défaut, mais s'il est défini sur faux, Open MPI peut utiliser un mécanisme de synchronisation plus fin (par exemple, les ticks de l'horloge RDTSC/RDTSCP sur les plateformes x86_64), mais n'est pas garanti d'être monotone dans certains cas (par exemple, si le processus MPI n'est pas lié à un seul cœur de processeur).

Cette fonction ne retourne pas de valeur d'erreur. Par conséquent, le résultat de son appel avant MPI_Init ou après MPI_Finalize est indéfini.
