MPI_GATHER(3) Open MPI MPI_GATHER(3)

MPI_Gather, MPI_Igather, MPI_Gather_init — collecte des valeurs à partir de processus d'un groupe.

SYNOPIS

PARAMÈTRES D'ENTRÉE

  • sendbuf : Adresse de début du buffer d'envoi (sélection).
  • sendcount : Nombre d'éléments dans le buffer d'envoi (entier).
  • sendtype : Type de données des éléments du buffer d'envoi (handle).
  • recvcount : Nombre d'éléments à recevoir par chacun (entier, significatif uniquement sur le processus racine).
  • recvtype : Type de données des éléments du buffer de réception (handle, significatif uniquement sur le processus racine).
  • root : Rangement du processus de réception (entier).
  • comm : Communicateur (handle).
  • info : Informations (handle, persistant).

PARAMÈTRES DE SORTIE

•
recvbuf
Adresse du buffer de réception (sélection, significatif uniquement sur le processus racine).
  • request : Requête (handle, non bloquant).
  • ierror : En Fortran uniquement : Statut d'erreur (entier).

DESCRIPTION

Chaque processus (y compris le processus racine) envoie le contenu de son buffer d'envoi au processus racine. Le processus racine reçoit les messages et les stocke dans l'ordre des rangs. Le résultat est comme si chacun des n processus du groupe (y compris le processus racine) avait exécuté un appel à

MPI_Send(sendbuf, sendcount, sendtype, root, ...)

et que le processus racine avait exécuté n appels à

MPI_Recv(recfbuf + i * recvcount * extent(recvtype), recvcount,
         recvtype, i, ...)

où extent(recvtype) est la taille du type obtenue par un appel à MPI_Type_extent.

Une description alternative est que les n messages envoyés par les processus du groupe sont concaténés dans l'ordre des rangs et que le message résultant est reçu par le processus racine comme si un appel à MPI_Recv(recvbuf, recvcount * n, recvtype, ...) avait été exécuté.

Le buffer de réception est ignoré pour tous les processus autres que la racine.

Les types dérivés sont autorisés pour sendtype et recvtype. La signature de type de sendcount, sendtype sur le processus i doit être identique à la signature de recvcount, recvtype sur le processus racine. Cela implique que la quantité de données envoyées doit être égale à la quantité de données reçues, par paires entre chaque processus et le processus racine. Des types de correspondance différents entre émetteur et récepteur sont toujours autorisés.

Tous les arguments de la fonction sont significatifs sur le processus racine, tandis que sur les autres processus seuls les arguments sendbuf, sendcount, sendtype, root, comm sont significatifs. Les arguments root et comm doivent avoir les mêmes valeurs sur tous les processus.

La spécification des comptages et des types ne doit pas entraîner l'écriture à plusieurs reprises au même endroit sur le processus racine. Cet appel est erroné. Il convient de noter que l'argument recvcount sur le processus racine indique le nombre d'éléments reçus de chaque processus, et non le nombre total d'éléments reçus.

Exemple 1 : Collecter 100 entiers de chaque processus du groupe vers le processus racine.

MPI_Comm comm;
int gsize, sendarray[100];
int root, *rbuf;
...
MPI_Comm_size( comm, &gsize);
rbuf = (int*)malloc(gsize * 100 * sizeof(int));
MPI_Gather( sendarray, 100, MPI_INT, rbuf, 100, MPI_INT, root, comm);

Exemple 2 : L'exemple précédent modifié — seul le processus racine alloue la mémoire du buffer de réception.

MPI_Comm comm;
int gsize, sendarray[100];
int root, myrank, * rbuf;
...
MPI_Comm_rank( comm, myrank);
if ( myrank == root) {
  MPI_Comm_size( comm, &gsize);
  rbuf = (int *)malloc(gsize * 100 * sizeof(int));
}
MPI_Gather( sendarray, 100, MPI_INT, rbuf, 100, MPI_INT, root, comm);

Exemple 3 : Faire la même chose que l'exemple précédent, mais en utilisant un type dérivé. Remarque : Le type ne peut pas être l'ensemble complet des entiers gsize * 100, car le type de correspondance est défini par paires entre le processus racine et chaque processus du groupe.

MPI_Comm comm;
int gsize, sendarray[100];
int root, * rbuf;
MPI_Datatype rtype;
...
MPI_Comm_size( comm, &gsize);
MPI_Type_contiguous( 100, MPI_INT, &rtype);
MPI_Type_commit( &rtype );
rbuf = (int*)malloc(gsize * 100 * sizeof(int));
MPI_Gather( sendarray, 100, MPI_INT, rbuf, 1, rtype, root, comm);

UTILISATION DE L'OPTION IN-PLACE

Lorsque le communicateur est un communicateur intra, vous pouvez effectuer une opération de rassemblement dans un buffer de remplacement (le buffer de sortie est utilisé comme buffer d'entrée). Utilisez la variable MPI_IN_PLACE comme valeur de sendbuf du processus racine. Dans ce cas, sendcount et sendtype sont ignorés, et la contribution du processus racine au vecteur collecté est supposée être déjà à la bonne place dans le buffer de réception. Remarque : MPI_IN_PLACE est un type spécial ; il a les mêmes restrictions d'utilisation que MPI_BOTTOM. Étant donné que l'option in-place transforme le buffer de réception en un buffer d'envoi et de réception, une liaison Fortran incluant INTENT doit les marquer comme INOUT, et non comme OUT.

QUAND LE COMMUNICATEUR EST UN COMMUNICATEUR INTER

Lorsque le communicateur est un communicateur inter, l'opération de rassemblement peut être effectuée dans un buffer de remplacement (le buffer de sortie est utilisé comme buffer d'entrée). Utilisez la variable MPI_IN_PLACE comme valeur de sendbuf du processus racine. Dans ce cas, sendcount et sendtype sont ignorés, et la contribution du processus racine au vecteur collecté est supposée être déjà à la bonne place dans le buffer de réception. DESCRIPTION

MPI_Gather gathers data from all processes in a communicator and delivers the data at the root process.

All processes in the communicator must call MPI_Gather. The sendbuf and sendtype arguments on all processes must match. The recvtype argument on the root process must match the sendtype argument on all processes. The recvcount argument on the root process specifies the number of items to be received from each process.

The buffer argument recvbuf is used only on the root process. On the root process, the buffer must be large enough to hold recvcount * size(recvtype) bytes of data. The data from each process is concatenated into the receive buffer on the root process. Specifically, the data from process i is placed in the receive buffer starting at offset recvcount * size(recvtype) * i.

If the communicator comm is an inter-communicator, then the set of processes in the local side of the communicator call MPI_Gather. The root process is specified in the local communicator. The value of root must be a rank in the local communicator.

All non-root processes use MPI_PROC_NULL as the value of their root argument. All processes in the remote group use the rank of the root process in the local group as the value of their root argument.

The sendbuf argument on the non-root processes must be consistent with the recvbuf argument on the root process.

USE OF IN-PLACE OPTION

The value MPI_IN_PLACE may be given for the sendbuf argument on the root process. When this is done, the recvbuf argument on the root process must be identical to the sendbuf argument on the root process, and it specifies the (potentially overlapping) buffer where the data is to be received. The data from all other processes is gathered into this buffer. The data from process i is concatenated into the buffer starting at offset recvcount * size(recvtype) * i. Note that in this case, the recvcount argument must be specified, and it must be the same value as the sendcount argument on all non-root processes.

WHEN COMMUNICATOR IS AN INTER-COMMUNICATOR

When the communicator is an inter-communicator, the set of processes in the local side of the communicator call MPI_Gather. The root process is specified in the local communicator. The value of root must be a rank in the local communicator.

All processes in the local group call MPI_Gather. The processes in the first group (that called MPI_Comm_connect or MPI_Comm_accept) define the root process. That process uses MPI_ROOT as the value of its root argument. The remaining processes in the first group use MPI_PROC_NULL as the value of their root argument.

All processes in the second group (that called MPI_Comm_connect or MPI_Comm_accept) use the rank of that root process in the first group as the value of their root argument.

The sendbuf argument of the processes in the first group must be consistent with the recvbuf argument of the root process in the second group.

ERRORS

Almost all MPI routines return an error value; C routines as the return result of the function and Fortran routines in the last argument.

Before the error value is returned, the current MPI error handler associated with the communication object (e.g., communicator, window, file) is called. If no communication object is associated with the MPI call, then the call is considered attached to MPI_COMM_SELF and will call the associated MPI error handler. When MPI_COMM_SELF is not initialized (i.e., before MPI_Init/MPI_Init_thread, after MPI_Finalize, or when using the Sessions Model exclusively) the error raises the initial error handler. The initial error handler can be changed by calling MPI_Comm_set_errhandler on MPI_COMM_SELF when using the World model, or the mpi_initial_errhandler CLI argument to mpiexec or info key to MPI_Comm_spawn/MPI_Comm_spawn_multiple. If no other appropriate error handler has been set, then the MPI_ERRORS_RETURN error handler is called for MPI I/O functions and the MPI_ERRORS_ABORT error handler is called for all other MPI functions.

Open MPI includes three predefined error handlers that can be used:

  • MPI_ERRORS_ARE_FATAL Causes the program to abort all connected MPI processes.
  • MPI_ERRORS_ABORT An error handler that can be invoked on a communicator, window, file, or session. When called on a communicator, it acts as if MPI_Abort was called on that communicator. If called on a window or file, acts as if MPI_Abort was called on a communicator containing the group of processes in the corresponding window or file. If called on a session, aborts only the local process.
  • MPI_ERRORS_RETURN Returns an error code to the application.

MPI applications can also implement their own error handlers by calling:

  • MPI_Comm_create_errhandler then MPI_Comm_set_errhandler
  • MPI_File_create_errhandler then MPI_File_set_errhandler
  • MPI_Session_create_errhandler then MPI_Session_set_errhandler or at MPI_Session_init
  • MPI_Win_create_errhandler then MPI_Win_set_errhandler

Note that MPI does not guarantee that an MPI program can continue past an error.

See the MPI man page for a full list of MPI error codes.

See the Error Handling section of the MPI-3.1 standard for more information.
