MPI_Testany(3) Open MPI MPI_Testany(3)

MPI_Testany — Teste l'achèvement de toute communication précédemment initiée dans une liste.

Syntaxe

Syntaxe C

#include <mpi.h>
int MPI_Testany(int count, MPI_Request array_of_requests[],
     int *index, int *flag, MPI_Status *status)

Syntaxe Fortran

USE MPI
! ou la vieille forme : INCLUDE 'mpif.h'
MPI_TESTANY(COUNT, ARRAY_OF_REQUESTS, INDEX, FLAG, STATUS, IERROR)
     LOGICAL FLAG
     INTEGER COUNT, ARRAY_OF_REQUESTS(*), INDEX
     INTEGER STATUS(MPI_STATUS_SIZE), IERROR

Syntaxe Fortran 2008

USE mpi_f08
MPI_Testany(count, array_of_requests, index, flag, status, ierror)
     INTEGER, INTENT(IN) :: count
     TYPE(MPI_Request), INTENT(INOUT) :: array_of_requests(count)
     INTEGER, INTENT(OUT) :: index
     LOGICAL, INTENT(OUT) :: flag
     TYPE(MPI_Status) :: status
     INTEGER, OPTIONAL, INTENT(OUT) :: ierror

Paramètres d'entrée

  • count: Taille de la liste (entier).
  • array_of_requests: Tableau de requêtes (tableau de pointeurs).

Paramètres de sortie

  • index: Index de l'opération terminée, ou MPI_UNDEFINED si aucune ne s'est terminée (entier).
  • flag: Vrai si l'une des opérations s'est terminée (logique).
  • status: Objet d'état (status).
  • ierror: En Fortran seulement : code d'erreur (entier).

Description

MPI_Testany teste l'achèvement d'une ou aucune des opérations associées aux pointeurs actifs. Si une opération est terminée, elle renvoie flag = vrai, renvoie dans index l'indice de cette requête dans le tableau, et renvoie dans status l'état de cette opération ; si la requête a été attribuée par un appel de communication non bloquant, la requête est libérée et le pointeur est mis à MPI_REQUEST_NULL. (Le tableau est indexé à partir de 0 en C, et à partir de 1 en Fortran.) Si aucune opération n'est terminée, elle renvoie flag = faux, renvoie une valeur de MPI_UNDEFINED dans index, et status est indéfini.

Le tableau peut contenir des pointeurs nuls ou inactifs. S'il ne contient aucun pointeur actif, l'appel renvoie immédiatement avec flag = vrai, index = MPI_UNDEFINED, et un état vide.

Si le tableau de requêtes contient des pointeurs actifs, l'exécution de MPI_Testany(count, array_of_requests, index, status) a le même effet que l'exécution de MPI_Test(&array_of_requests[i], flag, status), pour i=0,1,...,count-1, dans un ordre arbitraire, jusqu'à ce qu'un appel renvoie flag = true, ou que tous échouent. Dans le premier cas, index est défini sur la dernière valeur de i, et dans le second cas, sur MPI_UNDEFINED. L'appel MPI_Testany avec un tableau contenant un seul pointeur actif est équivalent à MPI_Test.

Si votre application n'a pas besoin d'examiner le champ status, vous pouvez économiser des ressources en utilisant la constante prédéfinie MPI_STATUS_IGNORE comme valeur spéciale pour l'argument status.

Erreurs

La plupart des routines MPI renvoient une valeur d'erreur ; les routines C renvoient le résultat de la fonction et les routines Fortran dans le dernier argument.

Avant de renvoyer la valeur d'erreur, le gestionnaire d'erreurs associé à l'objet de communication (par exemple, le communicateur, la fenêtre, le fichier) correspondant est appelé. S'il n'y a pas d'objet de communication associé à l'appel MPI, l'appel est considéré comme associé à MPI_COMM_SELF et le gestionnaire correspondant est appelé. Lorsque MPI_COMM_SELF n'est pas initialisé (c'est-à-dire avant MPI_Init/MPI_Init_thread, après MPI_Finalize, ou lorsque le modèle de Sessions est utilisé exclusivement), l'erreur déclenche le gestionnaire d'erreurs initial. Le gestionnaire d'erreurs initial peut être modifié en appelant MPI_Comm_set_errhandler sur MPI_COMM_SELF lors de l'utilisation du modèle du Monde, ou sur la clé d'informations dans MPI_Comm_spawn/MPI_Comm_spawn_multiple. Si aucun autre gestionnaire d'erreurs approprié n'est disponible, le gestionnaire MPI_ERRORS_RETURN est appelé pour les fonctions d'E/S MPI et le gestionnaire MPI_ERRORS_ABORT pour toutes les autres fonctions MPI.

Open MPI inclut trois gestionnaires d'erreurs prédéfinis qui peuvent être utilisés :

  • MPI_ERRORS_ARE_FATAL : Arrête tous les processus MPI connectés.
  • MPI_ERRORS_ABORT : Un gestionnaire qui peut être invoqué sur un communicateur, une fenêtre, un fichier ou une session. Lorsqu'il est invoqué sur un communicateur, il agit comme si MPI_Abort avait été appelé sur ce communicateur. S'il est invoqué sur une fenêtre ou un fichier, il agit comme si MPI_Abort avait été appelé sur un communicateur contenant le groupe de processus correspondant dans la fenêtre ou le fichier. S'il est invoqué sur une session, il arrête uniquement le processus local.
  • MPI_ERRORS_RETURN : Renvoie un code d'erreur à l'application.

Les applications MPI peuvent également implémenter leurs propres gestionnaires d'erreurs en appelant :

  • MPI_Comm_create_errhandler puis MPI_Comm_set_errhandler
  • MPI_File_create_errhandler puis MPI_File_set_errhandler
  • MPI_Session_create_errhandler puis MPI_Session_set_errhandler ou dans MPI_Session_init
  • MPI_Win_create_errhandler puis MPI_Win_set_errhandler

Remarque : les erreurs MPI ne garantissent pas qu'une application MPI puisse continuer après une erreur.

Voir la page de manuel MPI pour une liste complète des codes d'erreur MPI.

Voir la section Gestion des erreurs de la norme MPI-3.1 pour plus d'informations.

Remarque : Selon la section "Retour d'état" de la "Communication point à point" dans la "Page de manuel MPI", les erreurs MPI sur les requêtes transmises à MPI_Testany ne définissent pas le champ status.MPI_ERROR dans l'état renvoyé. Le code d'erreur est toujours transmis au gestionnaire d'erreurs du backend et peut être renvoyé à l'appel par la valeur de retour de MPI_Testany si le gestionnaire du backend renvoie ce code. Le gestionnaire d'erreurs par défaut MPI_ERRORS_RETURN présente par exemple ce comportement.
