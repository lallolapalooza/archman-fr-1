MPI_KEYVAL_CREATE(3) Open MPI MPI_KEYVAL_CREATE(3)

MPI_Keyval_create — Génère une nouvelle clé d'attribut — cette routine est dépréciée en faveur de MPI_Comm_create_keyval.

SYNTAXE

Syntaxe C

#include <mpi.h>
int MPI_Keyval_create(MPI_Copy_function *copy_fn,
     MPI_Delete_function *delete_fn, int *keyval, void *extra_state)

Syntaxe Fortran

USE MPI
! ou l'ancienne forme : INCLUDE 'mpif.h'
MPI_KEYVAL_CREATE(COPY_FN, DELETE_FN, KEYVAL, EXTRA_STATE, IERROR)
     EXTERNAL        COPY_FN, DELETE_FN
     INTEGER KEYVAL, EXTRA_STATE, IERROR

PARAMÈTRES D'ENTRÉE

  • copy_fn : Fonction de rappel de copie pour keyval.
  • delete_fn : Fonction de rappel de suppression pour keyval.
  • extra_state : État supplémentaire pour les fonctions de rappel.

PARAMÈTRES DE SORTIE

  • keyval : Valeur de clé pour un accès futur (entier).
  • ierror : Fortran seulement : Statut d'erreur (entier).

DESCRIPTION

Notez que l'utilisation de cette routine est dépréciée depuis MPI-2. Veuillez utiliser MPI_Comm_create_keyval à la place.

Génère une nouvelle clé d'attribut. Les clés sont uniques localement dans un processus et opaques pour l'utilisateur, bien qu'elles soient explicitement stockées dans des entiers. Une fois allouée, la valeur de la clé peut être utilisée pour associer des attributs et y accéder sur n'importe quel communicateur défini localement.

La fonction copy_fn est appelée lors de la duplication d'un communicateur par MPI_Comm_dup. copy_fn doit être de type MPI_Copy_function, qui est défini comme suit :

typedef int MPI_Copy_function(MPI_Comm oldcomm, int keyval,
                              void *extra_state, void *attribute_val_in,
                              void *attribute_val_out, int *flag)

Une déclaration Fortran pour une telle fonction est la suivante :

SUBROUTINE COPY_FUNCTION(OLDCOMM, KEYVAL, EXTRA_STATE, ATTRIBUTE_VAL_IN,
            ATTRIBUTE_VAL_OUT, FLAG, IERR)
INTEGER OLDCOMM, KEYVAL, EXTRA_STATE,
ATTRIBUTE_VAL_IN, ATTRIBUTE_VAL_OUT, IERR
LOGICAL FLAG

La fonction de rappel de copie est appelée pour chaque valeur de clé dans oldcomm dans un ordre arbitraire. Chaque appel à la fonction de rappel de copie est effectué avec une clé et son attribut correspondant. Si elle retourne flag = 0, l'attribut est supprimé dans le communicateur dupliqué. Sinon ( flag = 1), la nouvelle valeur de l'attribut est définie à la valeur retournée dans attribute_val_out. La fonction retourne MPI_SUCCESS en cas de succès et un code d'erreur en cas d'échec (auquel cas MPI_Comm_dup échouera).

copy_fn peut être spécifié comme MPI_NULL_COPY_FN ou MPI_DUP_FN à partir de C ou de Fortran ; MPI_NULL_COPY_FN est une fonction qui ne fait rien d'autre que retourner flag = 0 et MPI_SUCCESS. MPI_DUP_FN est une fonction de copie simple qui définit flag = 1, retourne la valeur de attribute_val_in dans attribute_val_out, et retourne MPI_SUCCESS.

NOTES

Les valeurs de clé sont globales (disponibles pour tous les communicateurs).

Il existe des différences subtiles entre C et Fortran qui exigent que copy_fn soit écrite dans le même langage que celui à partir duquel MPI_Keyval_create est appelée. Cela ne devrait pas poser de problème à la plupart des utilisateurs ; seuls les programmeurs utilisant à la fois Fortran et C dans le même programme doivent s'assurer qu'ils suivent cette règle.

Même si les deux arguments formels attribute_val_in et attribute_val_out sont de type void*, leur utilisation diffère. La fonction de copie C reçoit par MPI dans attribute_val_in la valeur de l'attribut, et dans attribute_val_out l'adresse de l'attribut, de manière à permettre à la fonction de retourner la (nouvelle) valeur de l'attribut. L'utilisation du type void * pour les deux est d'éviter des conversions de type fastidieuses.

Une fonction de copie valide est une fonction qui duplique complètement l'information en effectuant une copie complète des structures de données impliquées par un attribut ; une autre peut simplement faire une autre référence à cette structure de données, tout en utilisant un mécanisme de comptage de références. D'autres types d'attributs peuvent ne pas être copiés du tout (ils peuvent être spécifiques à oldcomm uniquement).

Parallèlement à copy_fn, il y a une fonction de suppression de rappel, définie comme suit. La fonction delete_fn est appelée lorsqu'un communicateur est supprimé par MPI_Comm_free ou lorsqu'un appel est fait explicitement à MPI_Attr_delete. delete_fn doit être de type MPI_Delete_function, qui est définie comme suit :

typedef int MPI_Delete_function(MPI_Comm comm, int keyval,
                                void *attribute_val, void *extra_state);

Une déclaration Fortran pour une telle fonction est la suivante :

SUBROUTINE DELETE_FUNCTION(COMM, KEYVAL,ATTRIBUTE_VAL, EXTRA_STATE, IERR)
    INTEGER COMM, KEYVAL, ATTRIBUTE_VAL, EXTRA_STATE, IERR

Cette fonction est appelée par MPI_Comm_free, MPI_Attr_delete, et MPI_Attr_put pour effectuer les actions nécessaires à la suppression d'un attribut. La fonction retourne MPI_SUCCESS en cas de succès et un code d'erreur en cas d'échec (auquel cas MPI_Comm_free échouera).

delete_fn peut être spécifié comme MPI_NULL_DELETE_FN à partir de C ou de FORTRAN ; MPI_NULL_DELETE_FN est une fonction qui ne fait rien d'autre que retourner MPI_SUCCESS.

La valeur de clé spéciale MPI_KEYVAL_INVALID n'est jamais retournée par MPI_Keyval_create. Par conséquent, elle peut être utilisée pour l'initialisation statique des valeurs de clé.

ERREURS

Presque toutes les routines MPI retournent une valeur d'erreur ; les routines C en tant que résultat de retour de la fonction et les routines Fortran dans le dernier argument.

Avant que la valeur d'erreur ne soit retournée, le gestionnaire d'erreurs MPI actuel associé à l'objet de communication (par exemple, communicateur, fenêtre, fichier) est appelé. Si aucun objet de communication n'est associé à l'appel MPI, l'appel est considéré comme attaché à MPI_COMM_SELF et appellera le gestionnaire d'erreurs MPI associé. Lorsque MPI_COMM_SELF n'est pas initialisé (c'est-à-dire avant MPI_Init/MPI_Init_thread, après MPI_Finalize, ou lors de l'utilisation exclusive du modèle de sessions), l'erreur déclenche le gestionnaire d'erreurs initial. Le gestionnaire d'erreurs initial peut être modifié en appelant MPI_Comm_set_errhandler sur MPI_COMM_SELF lors de l'utilisation du modèle World, ou l'argument CLI mpi_initial_errhandler à mpiexec ou la clé d'information à MPI_Comm_spawn/MPI_Comm_spawn_multiple. Si aucun autre gestionnaire d'erreurs approprié n'a été défini, alors le gestionnaire d'erreurs MPI_ERRORS_RETURN est appelé pour les fonctions d'E/S MPI et le gestionnaire d'erreurs MPI_ERRORS_ABORT est appelé pour toutes les autres fonctions MPI.

Open MPI inclut trois gestionnaires d'erreurs prédéfinis qui peuvent être utilisés :

  • MPI_ERRORS_ARE_FATAL Provoque l'arrêt du programme pour tous les processus MPI connectés.
  • MPI_ERRORS_ABORT Un gestionnaire d'erreurs qui peut être invoqué sur un communicateur, une fenêtre, un fichier ou une session. Lorsqu'il est appelé sur un communicateur, il agit comme si MPI_Abort avait été appelé sur ce communicateur. S'il est appelé sur une fenêtre ou un fichier, il agit comme si MPI_Abort avait été appelé sur un communicateur contenant le groupe de processus de la fenêtre ou du fichier correspondant. S'il est appelé sur une session, il n'interrompt que le processus local.
  • MPI_ERRORS_RETURN Retourne un code d'erreur à l'application.

Les applications MPI peuvent également implémenter leurs propres gestionnaires d'erreurs en appelant :

  • MPI_Comm_create_errhandler puis MPI_Comm_set_errhandler
  • MPI_File_create_errhandler puis MPI_File_set_errhandler
  • MPI_Session_create_errhandler puis MPI_Session_set_errhandler ou à MPI_Session_init
  • MPI_Win_create_errhandler puis MPI_Win_set_errhandler

Notez que MPI ne garantit pas qu'un programme MPI puisse continuer après une erreur.

Voir la page de manuel MPI pour une liste complète des codes d'erreur MPI.

Voir la section Gestion des erreurs de la norme MPI-3.1 pour plus d'informations.
