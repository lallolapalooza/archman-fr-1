MPI_Alltoallv, MPI_Ialltoallv, MPI_Alltoallv_init - Tous les processus envoient des données différentes à et reçoivent des données différentes de tous les processus.

PARAMETRES D'ENTRÉE

  • sendbuf: Adresse de début du tampon d'envoi.
  • sendcounts: Tableau d'entiers, où l'élément i spécifie le nombre d'éléments à envoyer au rang i.
  • sdispls: Tableau d'entiers, où l'élément i spécifie le décalage (offset depuis sendbuf, en unités de sendtype) pour envoyer des données au rang i.
  • sendtype: Type de données des éléments du tampon d'envoi.
  • recvcounts: Tableau d'entiers, où l'élément j spécifie le nombre d'éléments à recevoir du rang j.
  • rdispls: Tableau d'entiers, où l'élément j spécifie le décalage (offset depuis recvbuf, en unités de recvtype) où les données du rang j doivent être écrites.
  • recvtype: Type de données des éléments du tampon de réception.
  • comm: Communicateur sur lequel l'échange de données est effectué.
  • info: Informations (handle, persistant seulement)

PARAMETRES DE SORTIE

  • recvbuf: Adresse du tampon de réception.
  • request: Requête (handle, non bloquant).
  • ierror: Fortran uniquement : code d'erreur.

DESCRIPTION

MPI_Alltoallv est une opération collective généralisée dans laquelle tous les processus envoient des données à et reçoivent des données de tous les autres processus. Elle permet une flexibilité supplémentaire par rapport à MPI_Alltoall en permettant à l'utilisateur de spécifier des données à envoyer et à recevoir sous forme vectorielle (via un décalage et un compteur d'éléments). L'opération de cette routine peut être pensée comme suit, où chaque processus effectue 2n (n étant le nombre de processus dans le communicateur comm) communications point à point indépendantes (y compris la communication avec lui-même).

MPI_Comm_size(comm, &n);
for (i = 0, i < n; i++)
    MPI_Send(sendbuf + sdispls[i] * extent(sendtype),
        sendcounts[i], sendtype, i, ..., comm);
for (i = 0, i < n; i++)
    MPI_Recv(recvbuf + rdispls[i] * extent(recvtype),
        recvcounts[i], recvtype, i, ..., comm);

Le processus j envoie le bloc k de son propre sendbuf au processus k, qui place les données dans le bloc j de son propre recvbuf.

Lorsqu'une paire de processus échange des données, chacun peut passer différents arguments de comptage et de types de données, à condition que l'expéditeur spécifie le même nombre d'octets à envoyer que le récepteur s'attend à recevoir.

Remarque : Le processus i peut envoyer un nombre différent de données au processus j que ce qu'il reçoit du processus j. De plus, un processus peut envoyer différentes quantités de données à différents processus dans le communicateur.

LORSQUE LE COMMUNICATEUR EST UN INTERCOMMUNICATEUR

Lorsque le communicateur est un intercommunicateur, l'opération de collecte se déroule en deux phases. Les données sont collectées auprès de tous les membres du premier groupe et reçues par tous les membres du deuxième groupe. Ensuite, les données sont collectées auprès de tous les membres du deuxième groupe et reçues par tous les membres du premier. L'opération présente un comportement symétrique, bidirectionnel.

Le premier groupe définit le processus racine. Le processus racine utilise MPI_ROOT comme valeur de root. Tous les autres processus du premier groupe utilisent MPI_PROC_NULL comme valeur de root. Tous les processus du deuxième groupe utilisent le numéro de rang du processus racine dans le premier groupe comme valeur de root.

Lorsque le communicateur est un intracomunicateur, ces groupes sont les mêmes et l'opération se déroule en une seule phase.

UTILISATION DE L'OPTION EN-PLACE

Lorsque le communicateur est un intracomunicateur, une opération all-to-all peut être effectuée en place (le tampon de sortie est utilisé comme tampon d'entrée). Utilisez la valeur MPI_IN_PLACE pour sendbuf. Dans ce cas, sendcounts, sdispls et sendtype sont ignorés. Les données d'entrée de chaque processus sont supposées se trouver dans la zone où ce processus recevra sa propre contribution dans le tampon de réception.

NOTES

Les spécificateurs de compte et de décalage ne doivent pas entraîner l'écriture d'un emplacement plus d'une fois.

Tous les arguments sur tous les processus sont significatifs. L'argument comm, en particulier, doit décrire le même communicateur sur tous les processus.

Les décalages de sdispls et rdispls sont mesurés en unités de sendtype et recvtype, respectivement. Comparez cela avec MPI_Alltoallw, où ces décalages sont mesurés en octets.

ERRORS

All MPI error handlers are invoked on the error value of the return code. Before the error value is returned, the current MPI error handler associated with the communication object (e.g., communicator, window, file) is called. If no communication object is associated with the MPI call, then the call is considered attached to MPI_COMM_SELF and will call the associated MPI error handler. When MPI_COMM_SELF is not initialized (i.e., before MPI_Init/MPI_Init_thread, after MPI_Finalize, or when using the Sessions Model exclusively) the error raises the initial error handler. The initial error handler can be changed by calling MPI_Comm_set_errhandler on MPI_COMM_SELF when using the World model, or the mpi_initial_errhandler CLI argument to mpiexec or info key to MPI_Comm_spawn/MPI_Comm_spawn_multiple. If no other appropriate error handler has been set, then the MPI_ERRORS_RETURN error handler is called for MPI I/O functions and the MPI_ERRORS_ABORT error handler is called for all other MPI functions.

Open MPI includes three predefined error handlers that can be used:

  • MPI_ERRORS_ARE_FATAL Causes the program to abort all connected MPI processes.
  • MPI_ERRORS_ABORT An error handler that can be invoked on a communicator, window, file, or session. When called on a communicator, it acts as if MPI_Abort was called on that communicator. If called on a window or file, acts as if MPI_Abort was called on a communicator containing the group of processes in the corresponding window or file. If called on a session, aborts only the local process.
  • MPI_ERRORS_RETURN Returns an error code to the application.

MPI applications can also implement their own error handlers by calling:

  • MPI_Comm_create_errhandler then MPI_Comm_set_errhandler
  • MPI_File_create_errhandler then MPI_File_set_errhandler
  • MPI_Session_create_errhandler then MPI_Session_set_errhandler or at MPI_Session_init
  • MPI_Win_create_errhandler then MPI_Win_set_errhandler

Note that MPI does not guarantee that an MPI program can continue past an error.

See the MPI man page for a full list of MPI error codes.

See the Error Handling section of the MPI-3.1 standard for more information.
