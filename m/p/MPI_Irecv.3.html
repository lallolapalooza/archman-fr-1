MPI_IRECV(3) Open MPI MPI_IRECV(3)

MPI_Irecv — Démarre une réception non bloquante en mode standard.

SYNTAXE

Syntaxe C

#include <mpi.h>
int MPI_Irecv(void *buf, int count, MPI_Datatype datatype,
        int source, int tag, MPI_Comm comm, MPI_Request *request)

Syntaxe Fortran

USE MPI
! ou l'ancienne forme : INCLUDE 'mpif.h'
MPI_IRECV(BUF, COUNT, DATATYPE, SOURCE, TAG, COMM, REQUEST,
             IERROR)
     <type>  BUF(*)
     INTEGER COUNT, DATATYPE, SOURCE, TAG, COMM, REQUEST, IERROR

Syntaxe Fortran 2008

USE mpi_f08
MPI_Irecv(buf, count, datatype, source, tag, comm, request, ierror)
     TYPE(*), DIMENSION(..), ASYNCHRONOUS :: buf
     INTEGER, INTENT(IN) :: count, source, tag
     TYPE(MPI_Datatype), INTENT(IN) :: datatype
     TYPE(MPI_Comm), INTENT(IN) :: comm
     TYPE(MPI_Request), INTENT(OUT) :: request
     INTEGER, OPTIONAL, INTENT(OUT) :: ierror

PARAMÈTRES D'ENTRÉE

  • buf: Adresse initiale du tampon de réception (choix).
  • count: Nombre d'éléments dans le tampon de réception (entier).
  • datatype: Type de données de chaque élément du tampon de réception (descripteur).
  • source: Rang de la source (entier).
  • tag: Étiquette du message (entier).
  • comm: Communicateur (descripteur).

PARAMÈTRES DE SORTIE

  • request: Requête de communication (descripteur).
  • ierror: Fortran uniquement : Statut d'erreur (entier).

DESCRIPTION

Les appels non bloquants allouent un objet de requête de communication et l'associent au descripteur de requête (l'argument request). La requête peut être utilisée ultérieurement pour interroger l'état de la communication ou attendre son achèvement.

Un appel de réception non bloquante indique que le système peut commencer à écrire des données dans le tampon de réception. Le destinataire ne doit accéder à aucune partie du tampon de réception après l'appel d'une opération de réception non bloquante, jusqu'à ce que la réception soit terminée.

Une requête de réception peut être déterminée comme terminée en appelant MPI_Wait, MPI_Waitany, MPI_Test ou MPI_Testany avec la requête retournée par cette fonction.

ERREURS

Presque toutes les routines MPI retournent une valeur d'erreur ; en C, comme résultat de la fonction, et en Fortran dans le dernier argument.

Avant que la valeur d'erreur ne soit retournée, le gestionnaire d'erreurs MPI actuel associé à l'objet de communication (par exemple, le communicateur, la fenêtre, le fichier) est appelé. Si aucun objet de communication n'est associé à l'appel MPI, l'appel est considéré comme attaché à MPI_COMM_SELF et appellera le gestionnaire d'erreurs MPI associé. Lorsque MPI_COMM_SELF n'est pas initialisé (c'est-à-dire avant MPI_Init/MPI_Init_thread, après MPI_Finalize, ou lors de l'utilisation exclusive du modèle de sessions), l'erreur déclenche le gestionnaire d'erreurs initial. Le gestionnaire d'erreurs initial peut être modifié en appelant MPI_Comm_set_errhandler sur MPI_COMM_SELF lors de l'utilisation du modèle mondial, ou via l'argument CLI mpi_initial_errhandler de mpiexec ou la clé d'information de MPI_Comm_spawn/MPI_Comm_spawn_multiple. Si aucun autre gestionnaire d'erreurs approprié n'a été défini, le gestionnaire d'erreurs MPI_ERRORS_RETURN est appelé pour les fonctions d'E/S MPI et le gestionnaire d'erreurs MPI_ERRORS_ABORT est appelé pour toutes les autres fonctions MPI.

Open MPI inclut trois gestionnaires d'erreurs prédéfinis qui peuvent être utilisés :

  • MPI_ERRORS_ARE_FATAL Provoque l'arrêt du programme pour tous les processus MPI connectés.
  • MPI_ERRORS_ABORT Un gestionnaire d'erreurs qui peut être invoqué sur un communicateur, une fenêtre, un fichier ou une session. Lorsqu'il est appelé sur un communicateur, il agit comme si MPI_Abort était appelé sur ce communicateur. S'il est appelé sur une fenêtre ou un fichier, il agit comme si MPI_Abort était appelé sur un communicateur contenant le groupe des processus dans la fenêtre ou le fichier correspondant. S'il est appelé sur une session, il n'interrompt que le processus local.
  • MPI_ERRORS_RETURN Retourne un code d'erreur à l'application.

Les applications MPI peuvent également implémenter leurs propres gestionnaires d'erreurs en appelant :

  • MPI_Comm_create_errhandler puis MPI_Comm_set_errhandler
  • MPI_File_create_errhandler puis MPI_File_set_errhandler
  • MPI_Session_create_errhandler puis MPI_Session_set_errhandler ou lors de MPI_Session_init
  • MPI_Win_create_errhandler puis MPI_Win_set_errhandler

Notez que MPI ne garantit pas qu'un programme MPI puisse continuer après une erreur.

Voir la page de manuel MPI pour une liste complète des codes d'erreur MPI.

Voir la section Gestion des erreurs de la norme MPI-3.1 pour plus d'informations.
