PARAMÈTRES D'ENTRÉE

  • sendbuf: Tampon d'envoi (choix).
  • count: Nombre d'éléments dans le tampon d'entrée (entier).
  • datatype: Type de données des éléments du tampon d'entrée (handle).
  • op: Opération (handle).
  • comm: Communicateur (handle).
  • info: Informations (handle, persistant uniquement)

PARAMÈTRES DE SORTIE

  • recvbuf: Tampon de réception (choix).
  • request: Requête (handle, non bloquant uniquement).
  • ierror: Fortran uniquement : Statut d'erreur (entier).

DESCRIPTION

MPI_Scan est utilisé pour effectuer une réduction de préfixe inclusive sur des données distribuées à travers les processus appelants. L'opération retourne, dans le recvbuf du processus de rang i, la réduction (calculée selon la fonction op) des valeurs des sendbuf des processus de rangs 0, …, i (inclus). Le type d'opérations supportées, leur sémantique et les contraintes sur les tampons d'envoi et de réception sont les mêmes que pour MPI_Reduce.

EXEMPLE

Cet exemple utilise une opération définie par l'utilisateur pour produire un scan segmenté. Un scan segmenté prend en entrée un ensemble de valeurs et un ensemble de booléens, où les booléens délimitent les différents segments du scan. Par exemple,

valeurs     v1      v2      v3      v4      v5      v6      v7      v8
booléens   0       0       1       1       1       0       0       1
résultat     v1    v1+v2     v3    v3+v4  v3+v4+v5   v6    v6+v7     v8

Le résultat pour le rang j est donc la somme v(i) + … + v(j), où i est le rang le plus bas tel que pour tous les rangs n, i <= n <= j, booléen(n) = booléen(j). L'opérateur qui produit cet effet est

      [ u ]     [ v ]     [ w ]
      [   ]  o  [   ]  =  [   ]
      [ i ]     [ j ]     [ j ]
où
    ( u + v si i = j w = ( ( v si i != j

Notez qu'il s'agit d'un opérateur non commutatif. Le code C qui l'implémente est donné ci-dessous.

typedef struct {
        double val;
        int log;
} SegScanPair;
/*
 * la fonction définie par l'utilisateur
 */
void segScan(SegScanPair *in, SegScanPair *inout, int *len,
        MPI_Datatype *dptr)
{
        int i;
        SegScanPair c;
        for (i = 0; i < *len; ++i) {
                if (in->log == inout->log)
                        c.val = in->val + inout->val;
                else
                        c.val = inout->val;
                c.log = inout->log;
                *inout = c;
                in++;
                inout++;
        }
}

Notez que l'argument inout de la fonction définie par l'utilisateur correspond à l'opérande de droite de l'opérateur. En utilisant cet opérateur, nous devons faire attention à spécifier qu'il est non commutatif, comme suit :

int                     i, base;
SeqScanPair     a, answer;
MPI_Op          myOp;
MPI_Datatype    type[2] = {MPI_DOUBLE, MPI_INT};
MPI_Aint                disp[2];
int                     blocklen[2] = {1, 1};
MPI_Datatype    sspair;
/*
 * expliquer à MPI comment le type SegScanPair est défini
 */
MPI_Get_address(a, disp);
MPI_Get_address(a.log, disp + 1);
base = disp[0];
for (i = 0; i < 2; ++i)
        disp[i] -= base;
MPI_Type_struct(2, blocklen, disp, type, &sspair);
MPI_Type_commit(&sspair);
/*
 * créer l'opérateur user-scan segmenté
 * non commutatif - mettre commute (arg 2) à 0
 */
MPI_Op_create((MPI_User_function *)segScan, 0, &myOp);
...
MPI_Scan(a, answer, 1, sspair, myOp, comm);

UTILISATION DE L'OPTION IN-PLACE

Lorsque le communicateur est un intracommunicateur, vous pouvez effectuer une opération de scanne en place (le tampon de sortie est utilisé comme tampon d'entrée). Utilisez la variable MPI_IN_PLACE comme valeur de l'argument sendbuf. Les données d'entrée sont prises dans le tampon de réception et remplacées par les données de sortie.

NOTES SUR LES OPÉRATIONS COLLECTIVES

Les fonctions de réduction de type MPI_Op ne retournent pas de valeur d'erreur. Par conséquent, si les fonctions détectent une erreur, tout ce qu'elles peuvent faire est soit d'appeler MPI_Abort, soit d'ignorer silencieusement le problème. Ainsi, si le gestionnaire d'erreurs est modifié de MPI_ERRORS_ARE_FATAL à autre chose (par exemple, MPI_ERRORS_RETURN), alors aucune erreur ne peut être indiquée.

La raison en est les problèmes de performance pour garantir que toutes les routines collectives retournent la même valeur d'erreur.

ERREURS

Presque toutes les routines MPI retournent une valeur d'erreur ; les routines C comme résultat de la fonction et les routines Fortran dans le dernier argument.

Avant que la valeur d'erreur ne soit retournée, le gestionnaire d'erreurs MPI actuel associé à l'objet de communication (par exemple, communicateur, fenêtre, fichier) est appelé. Si aucun objet de communication n'est associé à l'appel MPI, l'appel est considéré comme attaché à MPI_COMM_SELF et appellera le gestionnaire d'erreurs MPI associé. Lorsque MPI_COMM_SELF n'est pas initialisé (c'est-à-dire avant MPI_Init/MPI_Init_thread, après MPI_Finalize, ou lors de l'utilisation exclusive du modèle de Sessions) l'erreur déclenche le gestionnaire d'erreurs initial. Le gestionnaire d'erreurs initial peut être modifié en appelant MPI_Comm_set_errhandler sur MPI_COMM_SELF lors de l'utilisation du modèle World, ou l'argument de ligne de commande mpi_initial_errhandler de mpiexec ou la clé d'information pour

ERRORS

By default, any MPI routine called by an application is required to return an error code to the application. However, MPI routines may also be configured to abort the entire MPI program. If the MPI_ERRORS_ARE_FATAL error handler is set for any MPI object, then any MPI function error will cause all MPI processes to abort. The MPI_ERRORS_RETURN error handler is the default for MPI I/O functions. If no other appropriate error handler has been set, then the MPI_ERRORS_RETURN error handler is called for MPI I/O functions and the MPI_ERRORS_ABORT error handler is called for all other MPI functions.

Open MPI includes three predefined error handlers that can be used:

  • MPI_ERRORS_ARE_FATAL Causes the program to abort all connected MPI processes.
  • MPI_ERRORS_ABORT An error handler that can be invoked on a communicator, window, file, or session. When called on a communicator, it acts as if MPI_Abort was called on that communicator. If called on a window or file, acts as if MPI_Abort was called on a communicator containing the group of processes in the corresponding window or file. If called on a session, aborts only the local process.
  • MPI_ERRORS_RETURN Returns an error code to the application.

MPI applications can also implement their own error handlers by calling:

  • MPI_Comm_create_errhandler then MPI_Comm_set_errhandler
  • MPI_File_create_errhandler then MPI_File_set_errhandler
  • MPI_Session_create_errhandler then MPI_Session_set_errhandler or at MPI_Session_init
  • MPI_Win_create_errhandler then MPI_Win_set_errhandler

Note that MPI does not guarantee that an MPI program can continue past an error.

See the MPI man page for a full list of MPI error codes.

See the Error Handling section of the MPI-3.1 standard for more information.
