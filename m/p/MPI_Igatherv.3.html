PARAMÈTRES D'ENTRÉE

  • sendbuf : Adresse de départ du tampon d'envoi (choix).
  • sendcount : Nombre d'éléments dans le tampon d'envoi (entier).
  • sendtype : Type de données des éléments du tampon d'envoi (handle).
recvcounts
Tableau d'entiers (de taille égale à la taille du groupe) contenant le nombre d'éléments reçus de chaque processus (significatif uniquement à la racine).
•
displs
Tableau d'entiers (de taille égale à la taille du groupe). L'entrée i spécifie le déplacement par rapport à recvbuf où placer les données entrantes du processus i (significatif uniquement à la racine).
•
recvtype
Type de données des éléments du tampon de réception (significatif uniquement à la racine) (handle).
  • root : Rang du processus de réception (entier).
  • comm : Communicateur (handle).
  • info : Info (handle, persistant seulement).

PARAMÈTRES DE SORTIE

•
recvbuf
Adresse du tampon de réception (choix, significatif uniquement à la racine).
  • request : Requête (handle, non-bloquant seulement).
  • ierror : Fortran seulement : Statut d'erreur (entier).

DESCRIPTION

MPI_Gatherv étend la fonctionnalité de MPI_Gather en permettant un nombre variable de données de chaque processus, puisque recvcounts est maintenant un tableau. Il permet également plus de flexibilité quant à l'endroit où les données sont placées à la racine, en fournissant le nouvel argument, displs.

Le résultat est comme si chaque processus, y compris le processus racine, envoyait un message à la racine,

MPI_Send(sendbuf, sendcount, sendtype, root, ...);

et la racine exécute n réceptions,

MPI_Recv(recvbuf + disp[i] * extent(recvtype), recvcounts[i],
         recvtype, i, ...);

Les messages sont placés dans le tampon de réception du processus racine dans l'ordre des rangs, c'est-à-dire que les données envoyées par le processus j sont placées dans la j-ème partie du tampon de réception recvbuf sur le processus root. La j-ème partie de recvbuf commence à l'offset displs[j] éléments (en termes de recvtype) dans recvbuf.

Le tampon de réception est ignoré pour tous les processus non racines.

La signature de type implicite par sendcount, sendtype sur le processus i doit être égale à la signature de type implicite par recvcounts[i], recvtype à la racine. Cela implique que la quantité de données envoyées doit être égale à la quantité de données reçues, par paires entre chaque processus et la racine. Des correspondances de types distinctes entre l'expéditeur et le récepteur sont toujours autorisées, comme illustré dans l'Exemple 2, ci-dessous.

Tous les arguments de la fonction sont significatifs sur le processus racine, tandis que sur les autres processus, seuls les arguments sendbuf, sendcount, sendtype, root, comm sont significatifs. Les arguments root et comm doivent avoir des valeurs identiques sur tous les processus.

La spécification des comptes, des types et des déplacements ne doit pas entraîner l'écriture d'un emplacement quelconque sur la racine plus d'une fois. Un tel appel est erroné.

Exemple 1 : Faites en sorte que chaque processus envoie 100 entiers à la racine, mais placez chaque ensemble (de 100) entiers espacés à l'extrémité de réception. Utilisez MPI_Gatherv et l'argument displs pour obtenir cet effet. Supposons stride >= 100.

MPI_Comm comm;
int gsize, sendarray[100];
int root, *rbuf, stride;
int *displs, i, rcounts;
...
MPI_Comm_size(comm, &gsize);
rbuf = (int)malloc(gsize * stride * sizeof(int));
displs = (int)malloc(gsize * sizeof(int));
rcounts = (int )malloc(gsize * sizeof(int));
for (i=0; i<gsize; ++i) {
  displs[i] = i * stride;
  rcounts[i] = 100;
}
MPI_Gatherv(sendarray, 100, MPI_INT, rbuf, rcounts, displs, MPI_INT,
            root, comm);

Notez que le programme est erroné si stride < 100.

Exemple 2 : Identique à l'Exemple 1 du côté réception, mais envoyez les 100 entiers de la 0ème colonne d'un tableau de 100x150 entiers, en C.

MPI_Comm comm;
int gsize, sendarray[100][150];
int root, *rbuf, stride;
MPI_Datatype stype;
int displs,i, rcounts;
...
MPI_Comm_size(comm, &gsize);
rbuf = (int )malloc(gsize * stride * sizeof(int));
displs = (int)malloc(gsize * sizeof(int));
rcounts = (int )malloc(gsize * sizeof(int));
for (i=0; i<gsize; ++i) {
  displs[i] = i * stride;
  rcounts[i] = 100;
}
// Créer le type de données pour 1 colonne du tableau
MPI_Type_vector(100, 1, 150, MPI_INT, &stype);
MPI_Type_commit( &stype );

UTILISATION DE L'OPTION EN PLACE

L'option en place fonctionne de manière similaire à celle de MPI_Gather. Lorsque le communicateur est un communicateur intra, vous pouvez effectuer une opération de rassemblement sur place (le tampon de sortie est utilisé comme tampon d'entrée). Utilisez la variable MPI_IN_PLACE comme valeur du tampon d'envoi du processus racine. Dans ce cas, sendcount et sendtype sont ignorés, et la contribution du processus racine au vecteur collecté est supposée être déjà au bon endroit dans le tampon de réception.

Note : MPI_IN_PLACE est un type de valeur spécial ; il a les mêmes restrictions d'utilisation que MPI_BOTTOM.

Étant donné que l'option en place transforme le tampon de réception en un tampon d'envoi et de réception, les liaisons Fortran qui incluent INTENT doivent les marquer comme INOUT, et non comme OUT.

QUAND LE COMMUNICATEUR EST UN COMMUNICATEUR INTER

Lorsque le communicateur est un communicateur inter, le processus racine du premier groupe collecte des données de tous les processus du second groupe. Le premier groupe définit le processus racine. Ce processus utilise MPI_ROOT comme valeur de l'argument racine. Les processus restants utilisent MPI_PROC_NULL comme valeur de l'argument racine. Tous les processus du second groupe utilisent le rang du processus racine du premier groupe comme valeur de l'argument racine. L'argument du tampon d'envoi des processus du premier groupe doit être cohérent avec l'argument du tampon de réception du processus racine du second groupe.

ERREURS

Dans l'ensemble, presque toutes les routines MPI renvoient une valeur d'erreur ; dans les routines C, le résultat est la valeur de retour de la fonction et dans les routines Fortran, le dernier argument.

Avant que la valeur d'erreur ne soit renvoyée, le gestionnaire d'erreurs associé à l'objet de communication actuel (par exemple, communicateur, fenêtre, fichier) est appelé. S'il n'y a pas d'objet de communication associé à l'appel MPI, l'appel est considéré comme associé à MPI_COMM_SELF et le gestionnaire d'erreurs correspondant est appelé. Lorsque MPI_COMM_SELF n'est pas initialisé (c'est-à-dire avant MPI_Init/MPI_Init_thread, après MPI_Finalize, ou lorsque le modèle de session est utilisé exclusivement), l'erreur déclenche le gestionnaire d'erreurs initial. Le gestionnaire d'erreurs initial peut être modifié en appelant MPI_Comm_set_errhandler sur MPI_COMM_SELF lorsque le modèle monde est utilisé, ou sur l'argument mpi_initial_errhandler de mpiexec ou sur la clé mpi_info de MPI_Comm_spawn/MPI_Comm_spawn_multiple. Si aucun autre gestionnaire d'erreurs approprié n'est configuré, le gestionnaire d'erreurs MPI_ERRORS_RETURN est appelé pour les fonctions d'E/S MPI et le gestionnaire d'erreurs MPI_ERRORS_ABORT pour toutes les autres fonctions MPI.

Open MPI inclut trois gestionnaires prédéfinis qui peuvent être utilisés :

  • MPI_ERRORS_ARE_FATAL Provoque l'arrêt de l'exécution de tous les processus MPI connectés.
  • MPI_ERRORS_ABORT Un gestionnaire d'erreurs qui peut être invoqué sur un communicateur, une fenêtre, un fichier ou une session. Lorsqu'il est invoqué sur un communicateur, il agit comme si MPI_Abort avait été appelé sur ce communicateur. S'il est invoqué sur une fenêtre ou un fichier, il agit comme si MPI_Abort avait été appelé sur un communicateur contenant la liste des processus dans la fenêtre ou le fichier correspondant. S'il est invoqué sur une session, il arrête uniquement le processus local.
  • MPI_ERRORS_RETURN Renvoie un code d'erreur à l'application.

Les programmes MPI peuvent également implémenter leurs propres gestionnaires d'erreurs en appelant :

  • MPI_Comm_create_errhandler puis MPI_Comm_set_errhandler
  • MPI_File_create_errhandler puis MPI_File_set_errhandler
  • MPI_Session_create_errhandler puis MPI_Session_set_errhandler ou dans MPI_Session_init
  • MPI_Win_create_errhandler puis MPI_Win_set_errhandler

Note : MPI ne garantit pas qu'un programme MPI puisse continuer après une erreur.

Voir la documentation de la page de manuel MPI pour une liste complète des codes d'erreur MPI.

Voir la section sur la gestion des erreurs de la norme MPI-3.1 pour plus d'informations.
