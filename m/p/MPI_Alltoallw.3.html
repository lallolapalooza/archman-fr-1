MPI_Alltoallw, MPI_Ialltoallw, MPI_Alltoallw_init — Tous les processus envoient des données de différents types vers, et reçoivent des données de différents types de, tous les processus.

Paramètres d'entrée

  • sendbuf: Adresse du tampon d'envoi.
  • sendcounts: Tableau d'entiers, où l'élément i spécifie le nombre d'éléments à envoyer au processus i.
  • sdispls: Tableau d'entiers, où l'élément i spécifie le décalage (en octets, décalage par rapport à sendbuf) pour envoyer des données au processus i.
  • sendtypes: Tableau de types de données, où l'élément i spécifie le type de données à utiliser lors de l'envoi de données au processus i.
  • recvcounts: Tableau d'entiers, où l'élément j spécifie le nombre d'éléments à recevoir du processus j.
  • rdispls: Tableau d'entiers, où l'élément j spécifie le décalage (en octets, décalage par rapport à recvbuf) où les données du processus j doivent être écrites.
  • recvtypes: Tableau de types de données, où l'élément j spécifie le type de données à utiliser lors de la réception de données du processus j.
  • comm: Communicateur sur lequel les échanges de données seront effectués.
  • info: Informations (handle, persistant uniquement)

Paramètres de sortie

  • recvbuf: Adresse du tampon de réception.
  • request: Requête (handle, non bloquant).
  • ierror: En Fortran uniquement : état d'erreur.

Description

MPI_Alltoallw est une opération collective généralisée dans laquelle tous les processus envoient des données à et reçoivent des données de tous les autres processus. Elle permet la spécification de types de données individuels de blocs de données (au-delà du décalage et du nombre d'éléments) pour l'utilisateur. Son opération peut être envisagée ainsi, où chaque processus effectue 2n (n étant le nombre de processus dans le communicateur comm) communications point à point indépendantes (y compris la communication avec soi-même).

MPI_Comm_size(comm, &n);
for (i = 0, i < n; i++)
    MPI_Send(sendbuf + sdispls[i], sendcounts[i],
        sendtypes[i], i, ..., comm);
for (i = 0, i < n; i++)
    MPI_Recv(recvbuf + rdispls[i], recvcounts[i],
        recvtypes[i], i, ..., comm);

Le processus j envoie le bloc k de son propre sendbuf au processus k, qui place les données dans le bloc j de son propre recvbuf.

Lorsqu'une paire de processus échange des données, chacun peut passer des quantités d'éléments et des types de données différents, à condition que l'expéditeur spécifie la même quantité de données (en octets) que le récepteur s'attend à recevoir.

Remarque : Le processus i peut envoyer une quantité de données différente au processus j que ce qu'il reçoit du processus j. De plus, un processus peut envoyer des données complètement différentes et de types différents à différents processus dans le communicateur.

QUAND LE COMMUNICATEUR EST UN INTER-COMMUNICATEUR

Lorsque le communicateur est un inter-communicateur, l'opération de collecte se déroule en deux phases. Les données sont collectées auprès de tous les membres du premier groupe et reçues par tous les membres du second groupe. Ensuite, les données sont collectées auprès de tous les membres du second groupe et reçues par tous les membres du premier. L'opération présente un comportement symétrique et en double.

Le premier groupe définit le processus racine. Le processus racine utilise MPI_ROOT comme valeur de root. Tous les autres processus du groupe racine utilisent MPI_PROC_NULL comme valeur de root. Tous les processus du second groupe utilisent le numéro de la racine de ce processus dans le groupe racine comme valeur de root.

Lorsque le communicateur est un intra-communicateur, ces groupes sont les mêmes et l'opération se déroule en une seule phase.

Utilisation de l'option en place

Lorsque le communicateur est un intra-communicateur, vous pouvez effectuer une opération all-to-all en place (le tampon de sortie est utilisé comme tampon d'entrée). Utilisez la variable MPI_IN_PLACE comme valeur de sendbuf. Dans ce cas, sendcounts, sdispls et sendtypes sont ignorés. Les données d'entrée de chaque processus sont supposées se trouver dans la zone où ce processus recevra sa propre contribution au tampon de réception.

Notes

La spécification des comptages, types et décalages ne doit pas entraîner d'écriture répétée au même endroit.

Tous les arguments sur tous les processus sont significatifs. L'argument comm, en particulier, doit décrire le même communicateur sur tous les processus.

ERRORS

Presque toutes les routines MPI retournent une valeur d'erreur ; les routines C comme résultat de retour de la fonction et les routines Fortran dans le dernier argument.

Avant que la valeur d'erreur ne soit retournée, le gestionnaire d'erreurs MPI actuel associé à l'objet de communication (par exemple, le communicateur, la fenêtre, le fichier) est appelé. S'il n'y a pas d'objet de communication associé à l'appel MPI, alors l'appel est considéré comme attaché à MPI_COMM_SELF et appellera le gestionnaire d'erreurs MPI associé. Lorsque MPI_COMM_SELF n'est pas initialisé (c'est-à-dire avant MPI_Init/MPI_Init_thread, après MPI_Finalize, ou lors de l'utilisation exclusive du modèle Sessions) l'erreur déclenche le gestionnaire d'erreurs initial. Le gestionnaire d'erreurs initial peut être modifié en appelant MPI_Comm_set_errhandler sur MPI_COMM_SELF lors de l'utilisation du modèle World, ou l'argument de ligne de commande mpi_initial_errhandler de mpiexec ou la clé d'information de MPI_Comm_spawn/MPI_Comm_spawn_multiple. Si aucun autre gestionnaire d'erreurs approprié n'a été défini, le gestionnaire d'erreurs MPI_ERRORS_RETURN est appelé pour les fonctions d'E/S MPI et le gestionnaire d'erreurs MPI_ERRORS_ABORT est appelé pour toutes les autres fonctions MPI.

Open MPI inclut trois gestionnaires d'erreurs prédéfinis qui peuvent être utilisés :

  • MPI_ERRORS_ARE_FATAL Provoque l'arrêt du programme sur tous les processus MPI connectés.
  • MPI_ERRORS_ABORT Un gestionnaire d'erreurs qui peut être invoqué sur un communicateur, une fenêtre, un fichier ou une session. Lorsqu'il est appelé sur un communicateur, il agit comme si MPI_Abort avait été appelé sur ce communicateur. S'il est appelé sur une fenêtre ou un fichier, il agit comme si MPI_Abort avait été appelé sur un communicateur contenant le groupe de processus de la fenêtre ou du fichier correspondant. S'il est appelé sur une session, il n'interrompt que le processus local.
  • MPI_ERRORS_RETURN Retourne un code d'erreur à l'application.

Les applications MPI peuvent également implémenter leurs propres gestionnaires d'erreurs en appelant :

  • MPI_Comm_create_errhandler puis MPI_Comm_set_errhandler
  • MPI_File_create_errhandler puis MPI_File_set_errhandler
  • MPI_Session_create_errhandler puis MPI_Session_set_errhandler ou au niveau de MPI_Session_init
  • MPI_Win_create_errhandler puis MPI_Win_set_errhandler

Notez que MPI ne garantit pas qu'un programme MPI puisse continuer après une erreur.

Voir la page man MPI pour une liste complète des codes d'erreur MPI.

Voir la section Gestion des erreurs de la norme MPI-3.1 pour plus d'informations.
