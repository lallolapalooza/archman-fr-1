PARAMÈTRES D'ENTRÉE

  • sendbuf: Adresse de départ du tampon d'envoi.
  • sendcounts: Tableau d'entiers, où l'entrée i spécifie le nombre d'éléments à envoyer au voisin i.
  • sdispls: Tableau d'entiers, où l'entrée i spécifie le décalage (en octets, par rapport à sendbuf) à partir duquel envoyer les données au voisin i.
  • sendtypes: Tableau de types de données, où l'entrée i spécifie le type de données à utiliser lors de l'envoi de données au voisin i.
  • recvcounts: Tableau d'entiers, où l'entrée j spécifie le nombre d'éléments à recevoir du voisin j.
  • rdispls: Tableau d'entiers, où l'entrée j spécifie le décalage (en octets, par rapport à recvbuf) auquel les données du voisin j doivent être écrites.
  • recvtypes: Tableau de types de données, où l'entrée j spécifie le type de données à utiliser lors de la réception de données du voisin j.
  • comm: Communicateur sur lequel les données doivent être échangées.
  • info: Informations (handle, persistant uniquement).

PARAMÈTRES DE SORTIE

  • recvbuf: Adresse du tampon de réception.
  • request: Requête (handle, non bloquant uniquement).
  • ierror: Fortran uniquement : Statut d'erreur.

DESCRIPTION

MPI_Neighbor_alltoallw est une opération collective généralisée dans laquelle tous les processus envoient des données à tous les voisins et en reçoivent de tous. Elle ajoute de la flexibilité à MPI_Neighbor_alltoallv en permettant à l'utilisateur de spécifier le type de données de blocs individuels (en plus du décalage et du nombre d'éléments). Son fonctionnement peut être envisagé de la manière suivante, où chaque processus effectue 2n (n étant le nombre de voisins dans la topologie du communicateur comm) communications ponctuelles indépendantes. Les voisins et la disposition des tampons sont déterminés par la topologie de comm.

MPI_Cart_get(comm, maxdims, dims, periods, coords);
for (dim = 0, i = 0 ; dim < dims ; ++dim) {
    MPI_Cart_shift(comm, dim, 1, &r0, &r1);
    MPI_Isend(sendbuf + sdispls[i]  * extent(sendtype),
              sendcount, sendtypes[i], r0, ..., comm, ...);
    MPI_Irecv(recvbuf + rdispls[i] * extent(recvtype),
              recvcount, recvtypes[i], r0, ..., comm, ...);
    ++i;
    MPI_Isend(sendbuf + sdispls[i] * extent(sendtype),
              sendcount, sendtypes[i], r1, ..., comm, &req[i]);
    MPI_Irecv(recvbuf + rdispls[i] * extent(recvtype),
              recvcount, recvtypes[i], r1, ..., comm, ...);
    ++i;
}
MPI_Wait_all (...);
MPI_Comm_size(comm, &n);
for (i = 0, i < n; i++)
  MPI_Send(sendbuf + sdispls[i], sendcounts[i],
       sendtypes[i], i, ..., comm);
for (i = 0, i < n; i++)
  MPI_Recv(recvbuf + rdispls[i], recvcounts[i],
       recvtypes[i], i, ..., comm);

Le processus j envoie le k-ième bloc de son sendbuf local au voisin k, qui place les données dans le j-ième bloc de son recvbuf local.

Lorsqu'une paire de processus échange des données, chacun peut passer des arguments de compte et de type différents tant que l'expéditeur spécifie la même quantité de données à envoyer (en octets) que celle que le destinataire s'attend à recevoir.

Notez qu'un processus i peut envoyer une quantité de données différente au processus j de celle qu'il reçoit du processus j. De plus, un processus peut envoyer des quantités et des types de données entièrement différents à différents processus du communicateur.

NOTES

L'option MPI_IN_PLACE pour sendbuf n'est pas significative pour cette opération.

La spécification des comptes, types et décalages ne doit pas entraîner l'écriture multiple d'un même emplacement.

Tous les arguments sur tous les processus sont significatifs. Le paramètre comm, en particulier, doit décrire le même communicateur sur tous les processus.

Les décalages de sdispls et rdispls sont mesurés en octets. Comparez cela à MPI_Neighbor_alltoallv, où ces décalages sont mesurés en unités de sendtype et recvtype, respectivement.

INPUT_PARAMETERS

Avant que la valeur d'erreur ne soit retournée, le gestionnaire d'erreurs associé à l'objet de communication (par exemple, communicator, window, file) appelé avant l'appel est invoqué. S'il n'y a pas d'objet de communication associé à l'appel MPI, l'appel est considéré comme étant associé à MPI_COMM_SELF et invoquera le gestionnaire d'erreurs correspondant. Lorsque MPI_COMM_SELF n'est pas initialisé (c'est-à-dire, avant MPI_Init/MPI_Init_thread, après MPI_Finalize, ou lorsque le modèle de sessions est utilisé exclusivement), l'erreur élève le gestionnaire d'erreurs initial. Le gestionnaire d'erreurs initial peut être modifié en appelant MPI_Comm_set_errhandler sur MPI_COMM_SELF lorsque le modèle du Monde est utilisé, ou par l'argument CLI mpi_initial_errhandler dans mpiexec ou par la clé info dans MPI_Comm_spawn/MPI_Comm_spawn_multiple. S'il n'y a pas d'autre gestionnaire d'erreurs approprié, le gestionnaire d'erreurs MPI_ERRORS_RETURN est appelé pour les fonctions d'E/S MPI et le gestionnaire d'erreurs MPI_ERRORS_ABORT pour toutes les autres fonctions MPI.

Open MPI inclut trois gestionnaires d'erreurs par défaut qui peuvent être utilisés :

  • MPI_ERRORS_ARE_FATAL Se comporte comme si MPI_Abort avait été appelé sur le processus correspondant.
  • MPI_ERRORS_ABORT Se comporte comme si MPI_Abort avait été appelé sur le communicateur correspondant. S'il est appelé sur une fenêtre ou un fichier, il se comporte comme si MPI_Abort avait été appelé sur le communicateur contenant le groupe de processus dans la fenêtre ou le fichier correspondant. S'il est appelé sur une session, il arrête uniquement le processus local.
  • MPI_ERRORS_RETURN Retourne un code d'erreur à l'application.

Les applications MPI peuvent également implémenter leurs propres gestionnaires d'erreurs en appelant :

  • MPI_Comm_create_errhandler puis MPI_Comm_set_errhandler
  • MPI_File_create_errhandler puis MPI_File_set_errhandler
  • MPI_Session_create_errhandler puis MPI_Session_set_errhandler ou sur MPI_Session_init
  • MPI_Win_create_errhandler puis MPI_Win_set_errhandler

Remarque : MPI ne garantit pas qu'un programme MPI puisse continuer après une erreur.

Voir la page man MPI pour une liste complète des codes d'erreur MPI.

Voir la section Gestion des erreurs de la norme MPI-3.1 pour plus d'informations.
