MPI_Unpack_external — Lit des données à partir d'un format portable

SYNTAXE

Syntaxe C

#include <mpi.h>
int MPI_Unpack_external(const char datarep[], const void *inbuf,
     MPI_Aint insize, MPI_Aint *position,
     void *outbuf, int outcount,
     MPI_Datatype datatype)

Syntaxe Fortran

USE MPI
! ou l'ancienne forme : INCLUDE 'mpif.h'
MPI_UNPACK_EXTERNAL(DATAREP, INBUF, INSIZE, POSITION,
     OUTBUF, OUTCOUNT, DATATYPE, IERROR)
     INTEGER         OUTCOUNT, DATATYPE, IERROR
     INTEGER(KIND=MPI_ADDRESS_KIND) INSIZE, POSITION
     CHARACTER*(*)   DATAREP
     <type>          INBUF(*), OUTBUF(*)

Syntaxe Fortran 2008

USE mpi_f08
MPI_Unpack_external(datarep, inbuf, insize, position, outbuf, outcount,
             datatype, ierror)
     CHARACTER(LEN=*), INTENT(IN) :: datarep
     TYPE(*), DIMENSION(..), INTENT(IN) :: inbuf
     TYPE(*), DIMENSION(..) :: outbuf
     INTEGER(KIND=MPI_ADDRESS_KIND), INTENT(IN) :: insize
     INTEGER(KIND=MPI_ADDRESS_KIND), INTENT(INOUT) :: position
     INTEGER, INTENT(IN) :: outcount
     TYPE(MPI_Datatype), INTENT(IN) :: datatype
     INTEGER, OPTIONAL, INTENT(OUT) :: ierror

PARAMÈTRES D'ENTRÉE

  • datarep : Représentation des données (chaîne de caractères).
  • inbuf : Début du tampon d'entrée (choix).
  • insize : Taille du tampon d'entrée, en octets (entier).
  • outcount : Nombre d'éléments à décompresser (entier).
  • datatype : Type de données de chaque élément de sortie (handle).

PARAMÈTRE D'ENTRÉE/SORTIE

•
position : Position actuelle dans le tampon, en octets (entier).

PARAMÈTRES DE SORTIE

  • outbuf : Début du tampon de sortie (choix).
  • ierror : Fortran uniquement : Statut d'erreur (entier).

DESCRIPTION

MPI_Unpack_external décompresse des données à partir du format external32, une représentation de données universelle définie par le MPI Forum. Ce format est utile pour l'échange de données entre implémentations MPI, ou lors de l'écriture de données dans un fichier.

Le tampon d'entrée est une zone de stockage contiguë pointée par inbuf contenant insize octets. Le tampon de sortie peut être n'importe quel tampon de communication autorisé dans MPI_Recv, et est spécifié par outbuf, outcount et datatype.

La valeur d'entrée de position est la première position dans inbuf à lire pour la décompression (mesurée en octets, pas en éléments, par rapport au début du tampon). Lorsque la fonction retourne, position est incrémenté de la taille du message compressé, de sorte qu'il pointe vers le premier emplacement dans inbuf après le message qui a été décompressé. Il peut ainsi être utilisé comme entrée pour un appel ultérieur à MPI_Unpack_external.

NOTES

Notez la différence entre MPI_Recv et MPI_Unpack_external : Dans MPI_Recv, l'argument count spécifie le nombre maximum d'éléments qui peuvent être reçus. Dans MPI_Unpack_external, l'argument outcount spécifie le nombre réel d'éléments à décompresser. Avec une opération de réception normale, la taille du message entrant détermine le nombre de composants qui seront reçus. Avec MPI_Unpack_external, il appartient à l'utilisateur de spécifier combien de composants décompresser, car l'utilisateur peut souhaiter décompresser le message reçu plusieurs fois dans divers tampons.

Pour comprendre le comportement de la compression et de la décompression, il est pratique de considérer la partie données d'un message comme la séquence obtenue en concaténant les valeurs successives envoyées dans ce message. L'opération de compression stocke cette séquence dans l'espace tampon, comme si on envoyait le message vers ce tampon. L'opération de décompression récupère cette séquence à partir de l'espace tampon, comme si on recevait un message de ce tampon. (Il est utile de penser aux fichiers internes de Fortran ou à sscanf en C pour une fonction similaire.)

Plusieurs messages peuvent être compressés successivement dans une unité de compression. Ceci est réalisé par plusieurs appels successifs reliés de MPI_Pack_external, où le premier appel fournit position=0, et chaque appel successif utilise la valeur de position qui a été générée par l'appel précédent, ainsi que les mêmes valeurs pour outbuf et outcount. Cette unité de compression contient maintenant l'information équivalente qui aurait été stockée dans un message par un appel de send avec un tampon de send qui est la « concaténation » des tampons de send individuels.

Une unité de compression peut être envoyée en utilisant le type MPI_BYTE. Toute fonction de communication point à point ou collective peut être utilisée pour déplacer la séquence d'octets qui forme l'unité de compression d'un processus à un autre. Cette unité de compression peut alors être reçue en utilisant n'importe quelle opération de réception, avec n'importe quel type de données : Les règles de correspondance des types sont assouplies pour les messages envoyés avec le type MPI_BYTE.

Une unité de compression peut être décompressée en plusieurs messages successifs. Ceci est réalisé par plusieurs appels successifs reliés de MPI_Unpack_external, où le premier appel fournit position=0, et chaque appel successif utilise la valeur de position qui a été générée par l'appel précédent, et les mêmes valeurs pour inbuf et insize.

La concaténation de deux unités de compression n'est pas nécessairement une unité de compression ; un sous-chaîne d'une unité de compression n'est pas nécessairement une unité de compression. Ainsi, on ne peut pas concaténer deux unités de compression puis décompresser le résultat comme une seule unité de compression ; on ne peut pas non plus décompresser une sous-chaîne d'une unité de compression comme une unité de compression séparée. Chaque unité de compression créée par une séquence d'appels de compression liés doit être décompressée comme une unité par une séquence d'appels de décompression reliés.

ERREURS

Presque toutes les routines MPI retournent une valeur d'erreur ; les routines C comme résultat de retour de la fonction et les routines Fortran dans le dernier argument.

Avant que la valeur d'erreur ne soit retournée, le gestionnaire d'erreurs MPI actuel associé à l'objet de communication (par exemple, communicateur, fenêtre, fichier) est appelé. Si aucun objet de communication n'est associé à l'appel MPI, alors l'appel est considéré comme attaché à MPI_COMM_SELF et appellera le gestionnaire d'erreurs MPI associé. Lorsque MPI_COMM_SELF n'est pas initialisé (c'est-à-dire avant MPI_Init/MPI_Init_thread, après MPI_Finalize, ou lorsqu'on utilise exclusivement le modèle de Sessions), l'erreur déclenche le gestionnaire d'erreurs initial. Le gestionnaire d'erreurs initial peut être modifié en appelant MPI_Comm_set_errhandler sur MPI_COMM_SELF lors de l'utilisation du modèle World, ou via l'argument CLI mpi_initial_errhandler de mpiexec ou une clé d'information pour MPI_Comm_spawn/MPI_Comm_spawn_multiple. Si aucun autre gestionnaire d'erreurs approprié n'a été défini, alors le gestionnaire d'erreurs MPI_ERRORS_RETURN est appelé pour les fonctions E/S MPI et le gestionnaire d'erreurs MPI_ERRORS_ABORT est appelé pour toutes les autres fonctions MPI.

Open MPI inclut trois gestionnaires d'erreurs prédéfinis qui peuvent être utilisés :

  • MPI_ERRORS_ARE_FATAL Provoque l'abandon du programme sur tous les processus MPI connectés.
  • MPI_ERRORS_ABORT Un gestionnaire d'erreurs qui peut être invoqué sur un communicateur, une fenêtre, un fichier ou une session. Lorsqu'il est appelé sur un communicateur, il agit comme si MPI_Abort avait été appelé sur ce communicateur. S'il est appelé sur une fenêtre ou un fichier, il agit comme si MPI_Abort avait été appelé sur un communicateur contenant le groupe des processus dans la fenêtre ou le fichier correspondant. S'il est appelé sur une session, il n'abandonne que le processus local.
  • MPI_ERRORS_RETURN Retourne un code d'erreur à l'application.

Les applications MPI peuvent également implémenter leurs propres gestionnaires d'erreurs en appelant :

  • MPI_Comm_create_errhandler puis MPI_Comm_set_errhandler
  • MPI_File_create_errhandler puis MPI_File_set_errhandler
  • MPI_Session_create_errhandler puis MPI_Session_set_errhandler ou à MPI_Session_init
