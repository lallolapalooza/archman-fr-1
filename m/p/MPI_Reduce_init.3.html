MPI_Reduce, MPI_Ireduce, MPI_Reduce_init - Réduit les valeurs sur tous les processus d'un groupe.

SYNTAXE

PARAMÈTRES ENTRANTS

  • sendbuf: Adresse du tampon d'envoi (choix).
  • count: Nombre d'éléments dans le tampon d'envoi (entier).
  • datatype: Type de données des éléments du tampon d'envoi (handle).
  • op: Opération de réduction (handle).
  • root: Rang du processus racine (entier).
  • comm: Communicateur (handle).
  • info: Info (handle, persistant).

PARAMÈTRES SORTANTS

  • recvbuf: Adresse du tampon de réception (choix, significatif uniquement à la racine).
  • request: Requête (handle, uniquement non bloquant).
  • ierror: Fortran uniquement : Statut d'erreur (entier).

DESCRIPTION

Les fonctions de réduction globale (MPI_Reduce, MPI_Op_create, MPI_Op_free, MPI_Allreduce, MPI_Reduce_scatter, MPI_Scan) effectuent une opération de réduction globale (telle que somme, max, OU logique, etc.) sur tous les membres d'un groupe. L'opération de réduction peut être l'une d'une liste prédéfinie d'opérations, ou une opération définie par l'utilisateur. Les fonctions de réduction globale existent sous plusieurs formes : une réduction qui renvoie le résultat de la réduction sur un nœud, une all-réduction qui renvoie ce résultat sur tous les nœuds, et une opération de scan (préfixe parallèle). De plus, une opération reduce-scatter combine les fonctionnalités d'une opération de réduction et de diffusion.

MPI_Reduce combine les éléments fournis dans le tampon d'entrée de chaque processus du groupe, en utilisant l'opération op, et renvoie la valeur combinée dans le tampon de sortie du processus de rang root. Le tampon d'entrée est défini par les arguments sendbuf, count et datatype ; le tampon de sortie est défini par les arguments recvbuf, count et datatype ; les deux ont le même nombre d'éléments, avec le même type. La routine est appelée par tous les membres du groupe en utilisant les mêmes arguments pour count, datatype, op, root et comm. Ainsi, tous les processus fournissent des tampons d'entrée et de sortie de même longueur, avec des éléments du même type. Chaque processus peut fournir un élément, ou une séquence d'éléments, auquel cas l'opération de combinaison est exécutée élément par élément sur chaque entrée de la séquence. Par exemple, si l'opération est MPI_MAX et que le tampon d'envoi contient deux éléments qui sont des nombres flottants (count = 2 et datatype = MPI_FLOAT), alors recvbuf(1) = max global (sendbuf(1)) et recvbuf(2) = max global(sendbuf(2)).

UTILISATION DE L'OPTION IN-PLACE

Lorsque le communicateur est un intracommunicateur, vous pouvez effectuer une opération de réduction en place (le tampon de réception est utilisé comme tampon d'entrée). Utilisez la variable MPI_IN_PLACE comme valeur du sendbuf du processus racine. Dans ce cas, les données d'entrée sont prises à la racine à partir du tampon de réception, où elles seront remplacées par les données de sortie.

Notez que MPI_IN_PLACE est un type de valeur spécial ; il a les mêmes restrictions d'utilisation que MPI_BOTTOM.

Étant donné que l'option in-place convertit le tampon de réception en un tampon d'envoi et de réception, une liaison Fortran qui inclut INTENT doit les marquer comme INOUT, et non OUT.

QUAND LE COMMUNICATEUR EST UN INTER-COMMUNICATEUR

Lorsque le communicateur est un inter-communicateur, le processus racine du premier groupe combine les données de tous les processus du second groupe, puis effectue l'opération op. Le premier groupe définit le processus racine. Ce processus utilise MPI_ROOT comme valeur de son argument root. Les processus restants utilisent MPI_PROC_NULL comme valeur de leur argument root. Tous les processus du second groupe utilisent le rang de ce processus racine dans le premier groupe comme valeur de leur argument root. Seuls les arguments du tampon d'envoi sont significatifs dans le second groupe, et seuls les arguments du tampon de réception sont significatifs dans le processus racine du premier groupe.

OPÉRATIONS DE RÉDUCTION PRÉDÉFINIES

L'ensemble des opérations prédéfinies fournies par MPI est listé ci-dessous (Opérations de Réduction Prédéfinies). Cette section énumère également les types de données auxquels chaque opération peut être appliquée. De plus, les utilisateurs peuvent définir leurs propres opérations qui peuvent être surchargées pour opérer sur plusieurs types de données, qu'ils soient de base ou dérivés. Ceci est expliqué plus en détail dans la description des opérations définies par l'utilisateur (voir les pages de manuel pour MPI_Op_create et MPI_Op_free).

L'opération op est toujours supposée associative. Toutes les opérations prédéfinies sont également supposées commutatives. Les utilisateurs peuvent définir des opérations qui sont supposées associatives, mais pas commutatives. L'ordre d'évaluation "canonique" d'une réduction est déterminé par les rangs des processus dans le groupe. Cependant, l'implémentation peut tirer parti de l'associativité, ou de l'associativité et de la commutativité, afin de changer l'ordre d'évaluation. Cela peut modifier le résultat de la réduction pour les opérations qui ne sont pas strictement associatives et commutatives, telles que l'addition flottante.

Les opérateurs prédéfinis fonctionnent uniquement avec les types MPI listés ci-dessous (Opérations de Réduction Prédéfinies, et la section MINLOC et MAXLOC, ci-dessous). Les opérateurs définis par l'utilisateur peuvent opérer sur des types de données généraux et dérivés. Dans ce cas, chaque argument sur lequel l'opération de réduction est appliquée est sur

MINLOC ET MAXLOC

L'opération MPI_MINLOC est utilisée pour calculer une valeur minimale globale et aussi un index associé à cette valeur minimale. Similairement, MPI_MAXLOC calcule une valeur maximale globale et un index. Une application de ces opérations est de calculer la valeur globale minimale (maximale) et le rank du processus qui contient cette valeur.

L'opération définissant MPI_MAXLOC est :

         ( u )    (  v )      ( w )
         (   )  o (    )   =  (   )
         ( i )    (  j )      ( k )
where
    w = max(u, v)
and
         ( i            if u > v
         (
   k   = ( min(i, j)    if u = v
         (
         (  j           if u < v)

MPI_MINLOC est défini similairement :

         ( u )    (  v )      ( w )
         (   )  o (    )   =  (   )
         ( i )    (  j )      ( k )
where
    w = min(u, v)
and
         ( i            if u < v
         (
   k   = ( min(i, j)    if u = v
         (
         (  j           if u > v)

Les deux opérations sont associatives et commutatives. Vous devriez noter que si MPI_MAXLOC est appliqué à une séquence de paires (u(0), 0), (u(1), 1), ..., (u(n-1), n-1), la valeur retournée est (u, r), où u = max(i), u(i) et r est l'index du premier maximum global dans la séquence. Par conséquent, si chaque processus fournit une valeur et son rank au sein du groupe, une opération reduce avec op = MPI_MAXLOC retournera la valeur maximale et le rank du premier processus ayant cette valeur. Similairement, MPI_MINLOC peut être utilisé pour retourner la valeur minimale et son index. Plus généralement, MPI_MINLOC calcule un minimum lexicographique, où les éléments sont ordonnés selon la première composante de chaque paire et les égalités sont résolues selon la seconde composante.

L'opération de réduction est définie pour opérer sur des arguments qui consistent en une paire : valeur et index. Pour Fortran et C, des types sont fournis pour décrire cette paire. La nature potentiellement mixte de ces arguments est un problème en Fortran. Pour Fortran, ce problème est évité en utilisant un type MPI fourni qui consiste en une paire de types égaux au type de valeur, et en convertissant l'index à ce type également. En C, le type de paire fourni par MPI a des types distincts et l'index est un int.

Pour utiliser MPI_MINLOC et MPI_MAXLOC dans une opération de réduction, vous devez fournir un argument de type qui représente une paire (valeur et index). MPI fournit neuf types prédéfinis de ce type. Les opérations MPI_MAXLOC et MPI_MINLOC peuvent être utilisées avec chacun des types de données suivants :

Fortran:
Name                     Description
MPI_2REAL                paire de REALs
MPI_2DOUBLE_PRECISION    paire de variables double-précision
MPI_2INTEGER             paire d'entiers
C:
Name                     Description
MPI_FLOAT_INT            float et int
MPI_DOUBLE_INT           double et int
MPI_LONG_INT             long et int
MPI_2INT                 paire d'int
MPI_SHORT_INT            short et int
MPI_LONG_DOUBLE_INT      double-précision et int

Le type de données MPI_2REAL est équivalent à :

MPI_TYPE_CONTIGUOUS(2, MPI_REAL, MPI_2REAL)

Ces affirmations s'appliquent de manière égale pour MPI_2INTEGER, MPI_2DOUBLE_PRECISION et MPI_2INT.

Le type de données MPI_FLOAT_INT est défini comme s'il avait été défini de la manière suivante :

type[0] = MPI_FLOAT
type[1] = MPI_INT
disp[0] = 0
disp[1] = sizeof(float)
block[0] = 1
block[1] = 1
MPI_TYPE_STRUCT(2, block, disp, type, MPI_FLOAT_INT)

Ces affirmations s'appliquent de manière égale pour MPI_LONG_INT et MPI_DOUBLE_INT.

Exemple 3 : Chaque processus a un tableau de 30 doubles en C. Pour chacun des 30 emplacements, calculer la valeur et le rank du processus qui contient la valeur maximale.

...
/* chaque processus a un tableau de 30 doubles: ain[30] */
double ain[30], aout[30];
int  ind[30];
struct {
    double val;
    int   rank;
} in[30], out[30];
int i, myrank, root;
MPI_Comm_rank(MPI_COMM_WORLD, &myrank);
for (i=0; i<30; ++i) {
    in.val = ain[i];
    in.rank = myrank;
}
MPI_Reduce( in, out, 30, MPI_DOUBLE_INT, MPI_MAXLOC, root, comm );
/* À ce moment, le résultat réside dans le processus root */
if (myrank == root) {
    /* lire les ranks out */
    for (i=0; i<30; ++i) {
        aout[i] = out.val;
        ind[i] = out.rank;
    }
}

Exemple 4 : Exemple similaire en Fortran.

...
! chaque processus a un tableau de 30 doubles: ain(30)
DOUBLE PRECISION :: ain(30), aout(30)
INTEGER :: ind(30)
DOUBLE PRECISION :: in(2,30), out(2,30)
INTEGER :: i, myrank, root, ierr
call MPI_COMM_RANK(MPI_COMM_WORLD, myrank)
DO I=1, 30
    in(1,i) = ain(i)
    in(2,i) = myrank    ! myrank est converti en double
END DO
call MPI_REDUCE( in, out, 30, MPI_2DOUBLE_PRECISION, MPI_MAXLOC, root, &
                                                          comm, ierr )
! À ce moment, le résultat réside dans le processus root
IF (myrank == root) THEN
    ! lire les ranks out
    DO I= 1, 30
        aout(i) = out(1,i)
        ind(i) = out(2,i)  ! rank est reconverti en entier
    END DO
END IF

Exemple 5 : Chaque processus a un tableau non vide de valeurs. Trouver la valeur minimale globale, le rank du processus qui la contient et son index dans ce processus.

#define  LEN   1000
float val[LEN];        /* tableau local de valeurs */
int count;             /* nombre local de valeurs */
int myrank, minrank, minindex;
float minval;
struct {
    float value;
    int   index;
} in, out;
/* minimum local */
in.value = val[0];
in.index = 0;
for (i=1; i < count; i++)
    if (in.value > val[i]) {
        in.value = val[i];
        in.index = i;
    }
/* minimum global */
MPI_Comm_rank(MPI_COMM_WORLD, &myrank);
in.index = myrank*LEN + in.index;
MPI_Reduce( in, out, 1, MPI_FLOAT_INT, MPI_MINLOC, root, comm );
    /* À ce moment, le résultat réside dans le processus root */
if (myrank == root) {
    /* lire le résultat */
    minval = out.value;
    minrank = out.index / LEN;
    minindex = out.index % LEN;

Tous les objets MPI (par exemple, MPI_Datatype, MPI_Comm) sont de type INTEGER en Fortran.

NOTES SUR LES OPÉRATIONS COLLECTIVES

Les fonctions de réduction (MPI_Op) ne retournent pas de valeur d'erreur. En conséquence, si elles détectent une erreur, elles ne peuvent qu'appeler MPI_Abort ou ignorer le problème silencieusement. Par conséquent, si vous changez le gestionnaire d'erreurs de MPI_ERRORS_ARE_FATAL à autre chose, par exemple MPI_ERRORS_RETURN, aucune erreur ne pourra être signalée.

La raison de cela est le problème de performance pour garantir que toutes les routines de réduction retournent la même valeur d'erreur.

ERREURS

La plupart des routines MPI retournent une valeur d'erreur ; en C, le résultat de la fonction est retourné comme valeur de retour, et en Fortran, comme dernier argument de la routine.

Avant que la valeur d'erreur ne soit retournée, le gestionnaire d'erreur associé à l'objet de communication (par exemple, communicator, window, file) est appelé. S'il n'y a pas d'objet de communication associé à l'appel MPI, l'appel est considéré comme associé à MPI_COMM_SELF et le gestionnaire d'erreur associé à MPI_COMM_SELF est appelé. Lorsque MPI_COMM_SELF n'est pas initialisé (c'est-à-dire avant MPI_Init/MPI_Init_thread, après MPI_Finalize), l'appel est considéré comme n'ayant pas été effectué.

SYNTAXE

Le modèle de session est exclusivement utilisé, et l'erreur lance le premier gestionnaire d'erreurs. Le gestionnaire d'erreurs initial peut être modifié en appelant MPI_Comm_set_errhandler avec MPI_COMM_SELF lors de l'utilisation du modèle mondial, ou l'argument CLI mpi_initial_errhandler de mpiexec ou la clé info de MPI_Comm_spawn/MPI_Comm_spawn_multiple. Si aucun autre gestionnaire d'erreurs approprié n'a été défini, le gestionnaire d'erreurs MPI_ERRORS_RETURN est appelé pour les fonctions d'E/S MPI et le gestionnaire d'erreurs MPI_ERRORS_ABORT est appelé pour toutes les autres fonctions.

Open MPI comprend trois gestionnaires d'erreurs prédéfinis qui peuvent être utilisés :

  • MPI_ERRORS_ARE_FATAL Provoque l'arrêt de l'exécution de tous les processus MPI connectés.
  • MPI_ERRORS_ABORT Un gestionnaire d'erreurs qui peut être invoqué sur un communicateur, une fenêtre, un fichier ou une session. Lorsqu'il est appelé sur un communicateur, il agit comme si MPI_Abort avait été appelé sur ce communicateur. S'il est appelé sur une fenêtre ou un fichier, il agit comme si MPI_Abort avait été appelé sur un communicateur contenant l'ensemble des processus de la fenêtre ou du fichier correspondant. S'il est appelé sur une session, il arrête uniquement le processus local.
  • MPI_ERRORS_RETURN Renvoie un code d'erreur à l'application.

Les applications MPI peuvent également implémenter leurs propres gestionnaires d'erreurs en appelant :

  • MPI_Comm_create_errhandler puis MPI_Comm_set_errhandler
  • MPI_File_create_errhandler puis MPI_File_set_errhandler
  • MPI_Session_create_errhandler puis MPI_Session_set_errhandler ou dans MPI_Session_init
  • MPI_Win_create_errhandler puis MPI_Win_set_errhandler

Note : MPI ne garantit pas qu'un programme MPI puisse continuer après une erreur.

Voir la page de manuel MPI pour une liste complète des codes d'erreur MPI.

Voir la section sur la gestion des erreurs de la norme MPI-3.1 pour plus d'informations.
