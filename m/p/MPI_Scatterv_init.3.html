MPI_Scatterv, MPI_Iscatterv, MPI_Scatterv_init - Diffuse un tampon par morceaux à toutes les tâches d'un groupe.

PARAMETRES ENTRANTS

  • sendbuf: Adresse du tampon d'envoi (choix, significatif uniquement à la racine).
  • sendcounts: Tableau d'entiers (de taille égale à la taille du groupe) spécifiant le nombre d'éléments à envoyer à chaque processeur.
  • displs: Tableau d'entiers (de taille égale à la taille du groupe). L'entrée i spécifie le déplacement (relatif à sendbuf) à partir duquel prendre les données sortantes pour le processeur i.
  • sendtype: Type des éléments du tampon d'envoi (descripteur).
  • recvcount: Nombre d'éléments dans le tampon de réception (entier).
  • recvtype: Type des éléments du tampon de réception (descripteur).
  • root: Rang du processus d'envoi (entier).
  • comm: Communicateur (descripteur).
  • info: Informations (descripteur, persistant uniquement).

PARAMETRES SORTANTS

  • recvbuf: Adresse du tampon de réception (choix).
  • request: Requête (descripteur, non bloquant uniquement).
  • ierror: Fortran uniquement : statut d'erreur (entier).

DESCRIPTION

MPI_Scatterv est l'opération inverse de MPI_Gatherv.

MPI_Scatterv étend la fonctionnalité de MPI_Scatter en permettant un nombre variable de données à envoyer à chaque processus, puisque sendcounts est maintenant un tableau. Il offre également plus de flexibilité quant à l'emplacement des données à partir de la racine, en fournissant le nouveau paramètre, displs.

Le résultat est comme si la racine exécutait n opérations d'envoi,

MPI_Send(sendbuf + displs[i] * extent(sendtype),
         sendcounts[i], sendtype, i, ...);
// et chaque processus exécutait une réception,
MPI_Recv(recvbuf, recvcount, recvtype, root, ...)

Le tampon d'envoi est ignoré pour tous les processus non racine.

La signature de type implicite par sendcount[i], sendtype à la racine doit être égale à la signature de type implicite par recvcount, recvtype au processus i (cependant, les cartes de type peuvent être différentes). Cela implique que la quantité de données envoyées doit être égale à la quantité de données reçues, par paires entre chaque processus et la racine. Des cartes de type distinctes entre l'expéditeur et le destinataire sont toujours autorisées.

Tous les arguments de la fonction sont significatifs sur le processus root, tandis que sur les autres processus, seuls les arguments recvbuf, recvcount, recvtype, root, comm sont significatifs. Les arguments root et comm doivent avoir des valeurs identiques sur tous les processeurs.

La spécification des comptes, des types et des déplacements ne doit pas entraîner la lecture d'un emplacement sur la racine plus d'une fois.

Exemple 1 : L'inverse de l'Exemple 5 dans la page de manuel MPI_Gatherv. Nous avons une stride variable entre les blocs du côté de l'envoi (racine), du côté de la réception nous recevons 100 - i éléments dans la ième colonne d'un tableau C de 100 x 150 au processeur i.

MPI_Comm comm;
int gsize,recvarray[100][150],*rptr;
int root, *sendbuf, myrank, bufsize, *stride;
MPI_Datatype rtype;
int i, *displs, *scounts, offset;
...
MPI_Comm_size( comm, &gsize);
MPI_Comm_rank( comm, &myrank );
stride = (int *)malloc(gsize*sizeof(int));
...
/* stride[i] pour i = 0 à gsize-1 est défini d'une manière ou d'une autre
 * sendbuf provient d'ailleurs
 */
...
displs = (int *)malloc(gsize*sizeof(int));
scounts = (int *)malloc(gsize*sizeof(int));
offset = 0;
for (i=0; i<gsize; ++i) {
    displs[i] = offset;
    offset += stride[i];
    scounts[i] = 100 - i;
}
/* Créer le type de données pour la colonne que nous recevons
 */
MPI_Type_vector( 100-myrank, 1, 150, MPI_INT, &rtype);
MPI_Type_commit( &rtype );
rptr = &recvarray[0][myrank];
MPI_Scatterv(sendbuf, scounts, displs, MPI_INT,
             rptr, 1, rtype, root, comm);

Exemple 2 : L'inverse de l'Exemple 1 dans la page de manuel MPI_Gather. Le processus racine diffuse des ensembles de 100 entiers aux autres processus, mais les ensembles de 100 sont espacés de stride entiers dans le tampon d'envoi. Nécessite l'utilisation de MPI_Scatterv, où stride >= 100.

MPI_Comm comm;
int gsize,*sendbuf;
int root, rbuf[100], i, *displs, *scounts;
...
MPI_Comm_size(comm, &gsize);
sendbuf = (int *)malloc(gsize*stride*sizeof(int));
...
displs = (int *)malloc(gsize*sizeof(int));
scounts = (int *)malloc(gsize*sizeof(int));
for (i=0; i<gsize; ++i) {
   displs[i] = i*stride;
   scounts[i] = 100;
}
MPI_Scatterv(sendbuf, scounts, displs, MPI_INT,
             rbuf, 100, MPI_INT, root, comm);

UTILISATION DE L'OPTION IN-PLACE

Lorsque le communicateur est un intracommunicateur, vous pouvez effectuer une opération de diffusion en place (le tampon de sortie est utilisé comme tampon d'entrée). Utilisez la variable MPI_IN_PLACE comme valeur du recvbuf du processus racine. Dans ce cas, recvcount et recvtype sont ignorés, et le processus racine n'envoie aucune donnée.

SYNTAX

MPI_Scatterv_init(sendbuf, sendcounts, displs, sendtype, recvbuf, recvcounts, displs, recvtype, root, comm, info, estatus)

INPUT PARAMETERS

Pointeur vers le buffer d'envoi (spécifique à l'entrée).

displs
Tableau des déplacements en éléments de type sendtype depuis le début de sendbuf vers chaque processus de destination (spécifique à l'entrée).
sendtype
Type de données des éléments dans le buffer d'envoi (spécifique à l'entrée).
recvcounts
Tableau du nombre d'éléments de type recvtype reçus de chaque processus source (spécifique à l'entrée).
displs
Tableau des déplacements en éléments de type recvtype depuis le début de recvbuf pour chaque processus source (spécifique à l'entrée).
recvtype
Type de données des éléments dans le buffer de réception (spécifique à l'entrée).
root
Rang du processus racine dans le communicateur (spécifique à l'entrée).
comm
Communicateur (spécifique à l'entrée).
info
Objet d'information (spécifique à l'entrée).
estatus
Statut d'achèvement (spécifique à la sortie).

OUTPUT PARAMETERS

recvbuf
Pointeur vers le buffer de réception (spécifique à la sortie).
estatus
Statut d'achèvement.

DESCRIPTION

MPI_Scatterv_init est une version optimisée de MPI_Scatterv. Il crée un objet de requête d'opération de communication à partir des arguments fournis, qui peut ensuite être utilisé pour effectuer l'opération de diffusion (scatter) de manière asynchrone. L'appel à MPI_Scatterv_init prend les arguments de MPI_Scatterv, mais au lieu d'effectuer immédiatement la communication, il renvoie un objet de requête d'opération de communication (MPI_Request) qui encapsule les informations nécessaires pour effectuer la communication plus tard.

L'opération de diffusion (scatter) distribue des données du processus racine à tous les processus d'un groupe. Plus précisément, le processus racine envoie des blocs de données du buffer sendbuf à chaque processus du communicateur. Le i-ème bloc de données envoyé par le processus racine est composé de sendcounts[i] éléments de type sendtype, qui sont placés dans le buffer sendbuf à l'offset displs[i]. Chaque processus reçoit un bloc de données du processus racine.

Le buffer de réception recvbuf de chaque processus reçoit un bloc de données d'une taille de recvcounts[i] éléments de type recvtype, envoyés depuis le processus source i. Le bloc est stocké dans le buffer recvbuf à l'offset displs[i].

Les tableaux sendcounts et displs sont utilisés par le processus racine pour déterminer comment distribuer les données. Les tableaux recvcounts et displs sont utilisés par tous les processus pour déterminer comment recevoir les données du processus racine.

Lorsque le communicateur est un inter-communicateur, le processus racine du premier groupe envoie des données à tous les processus du second groupe. Le processus racine utilise MPI_ROOT comme valeur de son argument root. Les autres processus du premier groupe utilisent MPI_PROC_NULL comme valeur de leur argument root. Tous les processus du second groupe utilisent le rang du processus racine du premier groupe comme valeur de leur argument root.

L'objet d'information info peut être utilisé pour spécifier des optimisations ou des contraintes particulières pour l'opération de communication. S'il n'est pas nécessaire, MPI_INFO_NULL peut être utilisé.

L'objet de requête retourné estatus peut être utilisé plus tard avec MPI_Startall, MPI_Test, ou MPI_Wait pour gérer la progression et l'achèvement de l'opération de communication.

USE OF IN-PLACE OPTION

Lorsque l'option in-place est utilisée, sendbuf et recvbuf doivent être identiques. Le buffer d'envoi est utilisé pour recevoir les données, et il doit être suffisamment grand pour contenir les données reçues.

Notez que MPI_IN_PLACE est une valeur spéciale; elle a les mêmes restrictions d'utilisation que MPI_BOTTOM.

Étant donné que l'option in-place convertit le buffer de réception en un buffer d'envoi et de réception, une liaison Fortran qui inclut INTENT doit les marquer comme INOUT, et non comme OUT.

WHEN COMMUNICATOR IS AN INTER-COMMUNICATOR

Lorsque le communicateur est un inter-communicateur, le processus racine du premier groupe envoie des données à tous les processus du second groupe. Le premier groupe définit le processus racine. Ce processus utilise MPI_ROOT comme valeur de son argument root. Les processus restants utilisent MPI_PROC_NULL comme valeur de leur argument root. Tous les processus du second groupe utilisent le rang de ce processus racine dans le premier groupe comme valeur de leur argument root. L'argument du buffer de réception du processus racine dans le premier groupe doit être cohérent avec l'argument du buffer de réception des processus dans le second groupe.

ERRORS

Presque toutes les routines MPI renvoient une valeur d'erreur ; les routines C comme résultat de retour de la fonction et les routines Fortran dans le dernier argument.

Avant le retour de la valeur d'erreur, le gestionnaire d'erreurs MPI actuel associé à l'objet de communication (par exemple, communicateur, fenêtre, fichier) est appelé. Si aucun objet de communication n'est associé à l'appel MPI, alors l'appel est considéré comme attaché à MPI_COMM_SELF et appellera le gestionnaire d'erreurs MPI associé. Lorsque MPI_COMM_SELF n'est pas initialisé (c'est-à-dire avant MPI_Init/ MPI_Init_thread, après MPI_Finalize, ou lors de l'utilisation exclusive du modèle de sessions) l'erreur déclenche le gestionnaire d'erreurs initial. Le gestionnaire d'erreurs initial peut être modifié en appelant MPI_Comm_set_errhandler sur MPI_COMM_SELF lors de l'utilisation du modèle World, ou l'argument de ligne de commande mpi_initial_errhandler pour mpiexec ou la clé d'information pour MPI_Comm_spawn/ MPI_Comm_spawn_multiple. Si aucun autre gestionnaire d'erreurs approprié n'a été défini, alors le gestionnaire d'erreurs MPI_ERRORS_RETURN est appelé pour les fonctions MPI I/O et le gestionnaire d'erreurs MPI_ERRORS_ABORT est appelé pour toutes les autres fonctions MPI.

Open MPI inclut trois gestionnaires d'erreurs prédéfinis qui peuvent être utilisés:

  • MPI_ERRORS_ARE_FATAL Provoque l'abandon du programme de tous les processus MPI connectés.
  • MPI_ERRORS_ABORT Un gestionnaire d'erreurs qui peut être invoqué sur un communicateur, une fenêtre, un fichier ou une session. Lorsqu'il est appelé sur un communicateur, il agit comme si MPI_Abort avait été appelé sur ce communicateur. S'il est appelé sur une fenêtre ou un fichier, il agit comme si MPI_Abort avait été appelé sur un communicateur contenant le groupe de processus de la fenêtre ou du fichier correspondant. S'il est appelé sur une session, il n'abandonne que le processus local.
  • MPI_ERRORS_RETURN Renvoie un code d'erreur à l'application.

Les applications MPI peuvent également implémenter leurs propres gestionnaires d'erreurs en appelant:

  • MPI_Comm_create_errhandler puis MPI_Comm_set_errhandler
  • MPI_File_create_errhandler puis MPI_File_set_errhandler
  • MPI_Session_create_errhandler puis MPI_Session_set_errhandler ou à MPI_Session_init
  • MPI_Win_create_errhandler puis MPI_Win_set_errhandler

Notez que MPI ne garantit pas qu'un programme MPI puisse continuer après une erreur.

Voir la page de manuel MPI pour une liste complète des codes d'erreur MPI.

Voir la section Gestion des erreurs de la norme MPI-3.1 pour plus d'informations.
