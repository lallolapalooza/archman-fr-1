MPI_Reduce, MPI_Ireduce, MPI_Reduce_init - Réduit des valeurs sur tous les processus d'un groupe.

PARAMÈTRES D'ENTRÉE

  • sendbuf: Adresse du tampon d'envoi (choix).
  • count: Nombre d'éléments dans le tampon d'envoi (entier).
  • datatype: Type de données des éléments du tampon d'envoi (handle).
  • op: Opération de réduction (handle).
  • root: Rang du processus racine (entier).
  • comm: Communicateur (handle).
  • info: Info (handle, persistant).

PARAMÈTRES DE SORTIE

  • recvbuf: Adresse du tampon de réception (choix, significatif uniquement à la racine).
  • request: Requête (handle, non-bloquant seulement).
  • ierror: Fortran seulement : Statut d'erreur (entier).

DESCRIPTION

Les fonctions de réduction globale (MPI_Reduce, MPI_Op_create, MPI_Op_free, MPI_Allreduce, MPI_Reduce_scatter, MPI_Scan) effectuent une opération de réduction globale (telle que somme, maximum, ET logique, etc.) entre tous les membres d'un groupe. L'opération de réduction peut être soit l'une d'une liste prédéfinie d'opérations, soit une opération définie par l'utilisateur. Les fonctions de réduction globale existent en plusieurs versions : une réduction qui retourne le résultat de la réduction sur un nœud, une all-réduction qui retourne ce résultat sur tous les nœuds, et une opération de scan (préfixe parallèle). De plus, une opération de réduction-diffusion combine les fonctionnalités d'une opération de réduction et d'une diffusion.

MPI_Reduce combine les éléments fournis dans le tampon d'entrée de chaque processus du groupe, en utilisant l'opération op, et retourne la valeur combinée dans le tampon de sortie du processus dont le rang est root. Le tampon d'entrée est défini par les arguments sendbuf, count et datatype ; le tampon de sortie est défini par les arguments recvbuf, count et datatype ; les deux ont le même nombre d'éléments, avec le même type. La routine est appelée par tous les membres du groupe en utilisant les mêmes arguments pour count, datatype, op, root, et comm. Ainsi, tous les processus fournissent des tampons d'entrée et de sortie de la même longueur, avec des éléments du même type. Chaque processus peut fournir un élément, ou une séquence d'éléments, auquel cas l'opération de combinaison est exécutée élément par élément sur chaque entrée de la séquence. Par exemple, si l'opération est MPI_MAX et que le tampon d'envoi contient deux éléments qui sont des nombres à virgule flottante (count = 2 et datatype = MPI_FLOAT), alors recvbuf(1) = maximum global (sendbuf(1)) et recvbuf(2) = maximum global(sendbuf(2)).

UTILISATION DE L'OPTION IN-PLACE

Lorsque le communicateur est un intracommunicateur, vous pouvez effectuer une opération de réduction en place (le tampon de sortie est utilisé comme tampon d'entrée). Utilisez la variable MPI_IN_PLACE comme valeur du sendbuf du processus racine. Dans ce cas, les données d'entrée sont prises à la racine à partir du tampon de réception, où elles seront remplacées par les données de sortie.

Notez que MPI_IN_PLACE est une valeur spéciale ; elle a les mêmes restrictions d'utilisation que MPI_BOTTOM.

Comme l'option en place convertit le tampon de réception en un tampon d'envoi et de réception, une liaison Fortran qui inclut INTENT doit les marquer comme INOUT, et non comme OUT.

QUAND LE COMMUNICATEUR EST UN INTER-COMMUNICATEUR

Lorsque le communicateur est un inter-communicateur, le processus racine du premier groupe combine les données de tous les processus du second groupe puis effectue l'opération op. Le premier groupe définit le processus racine. Ce processus utilise MPI_ROOT comme valeur de son argument root. Les processus restants utilisent MPI_PROC_NULL comme valeur de leur argument root. Tous les processus du second groupe utilisent le rang de ce processus racine dans le premier groupe comme valeur de leur argument root. Seuls les arguments du tampon d'envoi sont significatifs dans le second groupe, et seuls les arguments du tampon de réception sont significatifs dans le processus racine du premier groupe.

OPÉRATIONS DE RÉDUCTION PRÉDÉFINIES

La liste des opérations prédéfinies fournies par MPI est indiquée ci-dessous (Opérations de Réduction Prédéfinies). Cette section énumère également les types de données sur lesquels chaque opération peut être appliquée. De plus, les utilisateurs peuvent définir leurs propres opérations qui peuvent être surchargées pour opérer sur plusieurs types de données, qu'ils soient de base ou dérivés. Ceci est expliqué plus en détail dans la description des opérations définies par l'utilisateur (voir les pages de manuel pour MPI_Op_create et MPI_Op_free).

L'opération op est toujours supposée être associative. Toutes les opérations prédéfinies sont également supposées être commutatives. Les utilisateurs peuvent définir des opérations qui sont supposées être associatives, mais pas commutatives. L'ordre d'évaluation « canonique » d'une réduction est déterminé par les rangs des processus dans le groupe. Cependant, l'implémentation peut tirer parti de l'associativité, ou de l'associativité et de la commutativité, afin de changer l'ordre d'évaluation. Cela peut modifier le résultat de la réduction pour les opérations qui ne sont pas strictement associatives et commutatives, comme l'addition en virgule flottante.

Les opérateurs prédéfinis fonctionnent uniquement avec les types MPI listés ci-dessous (Opérations de Réduction Prédéfinies, et la section MINLOC et MAXLOC, ci-dessous). Les opérateurs définis par l'utilisateur peuvent opérer sur des types de données généraux et dérivés. Dans ce cas, chaque argument sur lequel l'opération de réduction est appliquée est un élément

Exemple 1 : Une routine qui calcule le produit scalaire de deux vecteurs distribués sur un groupe de processus et renvoie le résultat sur le processus zéro. 
   SUBROUTINE PAR_BLAS1(m, a, b, c, comm)
   REAL a(m), b(m)       ! partie locale du tableau
   REAL c                ! résultat (sur le processus zéro)
   REAL sum
   INTEGER m, comm, i, ierr
   ! somme locale
   sum = 0.0
   DO i = 1, m
       sum = sum + a(i)*b(i)
   END DO
   ! somme globale
   CALL MPI_REDUCE(sum, c, 1, MPI_REAL, MPI_SUM, 0, comm, ierr)
   RETURN
Exemple 2 : Une routine qui calcule le produit d'un vecteur et d'un tableau distribué sur un groupe de processus et renvoie le résultat sur le processus zéro. 
   SUBROUTINE PAR_BLAS2(m, n, a, b, c, comm)
   REAL a(m), b(m,n)    ! partie locale du tableau
   REAL c(n)            ! résultat
   REAL sum(n)
   INTEGER n, comm, i, j, ierr
   ! somme locale
   DO j= 1, n
       sum(j) = 0.0
       DO i = 1, m
           sum(j) = sum(j) + a(i)*b(i,j)
       END DO
   END DO
   ! somme globale
   CALL MPI_REDUCE(sum, c, n, MPI_REAL, MPI_SUM, 0, comm, ierr)
   ! renvoie le résultat sur le processus zéro (et est jeté sur les autres nœuds)
   RETURN

MINLOC ET MAXLOC

L'opération MPI_MINLOC est utilisée pour calculer une valeur globale minimale et également une position associée à cette valeur. MPI_MAXLOC calcule de même une valeur globale maximale et une position. Une application de celles-ci est de calculer une valeur globale minimale (maximale) et le rang du processus qui contient cette valeur.

L'opération qui définit MPI_MAXLOC est :

   (u)    (v)      (w)
   (   )  o (    )   =  (   )
   (i)    (j)      (k)
   où
   w = max(u, v)
   et
   (i            si u > v
   (k = (min(i, j)     si u = v
   (j            si u < v)

MPI_MINLOC est défini de manière similaire :

   (u)    (v)      (w)
   (   )  o (    )   =  (   )
   (i)    (j)      (k)
   où
   w = min(u, v)
   et
   (i            si u < v
   (k = (min(i, j)     si u = v
   (j            si u > v)

Les deux opérations sont associatives et commutatives. Il convient de noter que si MPI_MAXLOC est appliqué à une séquence de paires (u(0), 0), (u(1), 1), ..., (u(n-1), n-1), alors la valeur renvoyée est (u, r), où u = max(i), u(i) et r est la position du premier maximum global dans la séquence. Par conséquent, si chaque processus fournit une valeur et son rang au sein du groupe, une opération de réduction avec op = MPI_MAXLOC renverra la valeur maximale et le rang du premier processus ayant cette valeur. De même, MPI_MINLOC peut être utilisé pour renvoyer une valeur minimale et sa position. Plus généralement, MPI_MINLOC calcule un minimum lexicographique, où les éléments sont triés selon la première composante de chaque paire, et en cas d'égalité, selon la deuxième composante.

L'opération de réduction est définie pour opérer avec des arguments consistant en une valeur et une position. Pour Fortran et C, des types sont proposés pour décrire cette paire. La nature mixte de tels arguments peut poser problème en Fortran. Le problème est évité, pour Fortran, en faisant en sorte que le type fourni par MPI soit une paire de types égaux à la valeur, et en convertissant également l'indice à ce type. En C, le type de paire fourni par MPI a des types distincts et l'indice est un int.

Pour utiliser MPI_MINLOC et MPI_MAXLOC dans une opération de réduction, il est nécessaire de fournir un argument de type de données représentant une paire (valeur et position). MPI fournit neuf types de données prédéfinis ainsi. Les opérations MPI_MAXLOC et MPI_MINLOC peuvent être utilisées avec chacun des types de données suivants :

   Fortran :
   Nom                     Description
   MPI_2REAL                paire de REALs
   MPI_2DOUBLE_PRECISION    paire de variables double précision
   MPI_2INTEGER             paire d'ENTIERS
   C :
   Nom                     Description
   MPI_FLOAT_INT            float et int
   MPI_DOUBLE_INT            double et int
   MPI_LONG_INT             long et int
   MPI_2INT                 paire d'entiers
   MPI_SHORT_INT            short et int
   MPI_LONG_DOUBLE_INT      double précision et int

Le type de données MPI_2REAL est équivalent à :

   MPI_TYPE_CONTIGUOUS(2, MPI_REAL, MPI_2REAL)

Des estimations similaires s'appliquent à MPI_2INTEGER, MPI_2DOUBLE_PRECISION et MPI_2INT.

Le type de données MPI_FLOAT_INT est défini comme s'il était défini ainsi :

   type[0] = MPI_FLOAT
   type[1] = MPI_INT
   disp[0] = 0
   disp[1] = sizeof(float)
   block[0] = 1
   block[1] = 1
   MPI_TYPE_STRUCT(2, block, disp, type, MPI_FLOAT_INT)

Des estimations similaires s'appliquent à MPI_LONG_INT et MPI_DOUBLE_INT.

Exemple 3 : Chaque processus possède un tableau de 30 doubles en C. Pour chacun des 30 emplacements, calculez la valeur et le rang du processus qui contient la valeur maximale.

   ...
   /* chaque processus a un tableau de 30 doubles : ain[30] */
   double ain[30], aout[30];
   int ind[30];
   struct {
       double val;
       int rank;
   } in[30], out[30];
   int i, myrank, root;
   MPI_Comm_rank(MPI_COMM_WORLD, &myrank);
   for (i=0; i<30; ++i) {
       in[i].val = ain[i];
       in[i].rank = myrank;
   }
   MPI_Reduce( in, out, 30, MPI_DOUBLE_INT, MPI_MAXLOC, root, comm );
   /* À ce moment, le résultat se trouve sur le processus root */
   if (myrank == root) {
       /* lire les rangs sortants */
       for (i=0; i<30; ++i) {
           aout[i] = out[i].val;
           ind[i] = out[i].rank;
       }
   }

Exemple 4 : Exemple similaire en Fortran.

   ...
   ! chaque processus a un tableau de 30 doubles : ain(30)
   DOUBLE PRECISION :: ain(30), aout(30)
   INTEGER :: ind(30)
   DOUBLE PRECISION :: in(2,30), out(2,30)
   INTEGER :: i, myrank, root, ierr
   call MPI_COMM_RANK(MPI_COMM_WORLD, myrank)
   DO I=1, 30
       in(1,i) = ain(i)
       in(2,i) = myrank    ! myrank est converti en double
   END DO
   call MPI_REDUCE( in, out, 30, MPI_2DOUBLE_PRECISION, MPI_MAXLOC, root, &
                                                          comm, ierr )
   ! À ce moment, le résultat se trouve sur le processus root
   IF (myrank == root) THEN
       ! lire le résultat
       DO I= 1, 30
           aout(i) = out(1,i)
           ind(i) = out(2,i)  ! le rang est converti en entier
       END DO
   END IF

Exemple 5 : Chaque processus possède un tableau non vide de valeurs. Trouvez la valeur minimale globale, le rang du processus qui la contient et sa position dans ce processus.

   #define  LEN   1000
   float val[LEN];        /* tableau local de valeurs */
   int count;             /* nombre local de valeurs */
   int myrank, minrank, minindex;
   float minval;
   struct {
       float value;
       int   index;
   } in, out;
   /* minloc local */
   in.value = val[0];
   in.index = 0;
   for (i=1; i < count; i++)
       if (in.value > val[i]) {
           in.value = val[i];
           in.index = i;
       }
   /* minloc global */
   MPI_Comm_rank(MPI_COMM_WORLD, &myrank);
   in.index = myrank*LEN + in.index;
   MPI_Reduce( in, out, 1, MPI_FLOAT_INT, MPI_MINLOC, root, comm );
   /* À ce moment, le résultat se trouve sur le processus root */
   if (myrank == root) {
       /* lire le résultat */
       minval = out.value;
       minrank = out.index / LEN;
       minindex = out.index % LEN;
   }

Tous les objets MPI (par exemple, MPI_Datatype, MPI_Comm) sont de type INTEGER en Fortran.

NOTES SUR LES OPÉRATIONS COLLECTIVES

Les fonctions de réduction (MPI_Op) ne renvoient pas de valeur d'erreur. Par conséquent, si elles détectent une erreur, la seule chose qu'elles peuvent faire est d'appeler MPI_Abort ou de passer silencieusement le problème. Par conséquent, si vous changez le gestionnaire d'erreurs de MPI_ERRORS_ARE_FATAL à autre chose, par exemple, MPI_ERRORS_RETURN, alors aucune erreur ne sera signalée.

La raison en est le problème de performance pour garantir que toutes les routines de réduction renvoient la même valeur d'erreur.

ERREURS

La plupart des routines MPI renvoient une valeur d'erreur ; les routines C renvoient le résultat de la fonction et les routines Fortran dans le dernier argument.

Avant que la valeur d'erreur ne soit renvoyée, le gestionnaire d'erreurs actuel associé à l'objet de communication (par exemple, communicator, window, file) est appelé. S'il n'y a pas d'objet de communication associé à l'appel MPI, l'appel est considéré comme associé à MPI_COMM_SELF et appellera le gestionnaire d'erreurs associé à MPI_COMM_SELF. Lorsque MPI_COMM_SELF n'est pas initialisé (c'est-à-dire avant MPI_Init/MPI_Init_thread, après MPI_Finalize, ou lorsque utilisé...)

SYNTAXE

Le modèle de session est strictement limité à la détection d'erreurs. Le gestionnaire d'erreurs initial peut être modifié en appelant MPI_Comm_set_errhandler sur MPI_COMM_SELF lors de l'utilisation du modèle world, ou via l'argument CLI mpi_initial_errhandler de mpiexec ou la clé mpi_initial_errhandler de MPI_Comm_spawn/MPI_Comm_spawn_multiple. Si aucun autre gestionnaire d'erreurs approprié n'est défini, le gestionnaire d'erreurs MPI_ERRORS_RETURN est appelé pour les fonctions MPI d'E/S et le gestionnaire MPI_ERRORS_ABORT pour toutes les autres fonctions MPI.

Open MPI inclut trois gestionnaires d'erreurs par défaut qui peuvent être utilisés :

  • MPI_ERRORS_ARE_FATAL Indique que le programme abandonne tous les processus MPI connectés.
  • MPI_ERRORS_ABORT Un gestionnaire d'erreurs qui peut être invoqué sur un communicateur, une fenêtre, un fichier ou une session. Lorsqu'il est invoqué sur un communicateur, il agit comme si MPI_Abort avait été appelé sur ce communicateur. S'il est invoqué sur une fenêtre ou un fichier, il agit comme si MPI_Abort avait été appelé sur un communicateur contenant le groupe de processus dans la fenêtre ou le fichier correspondant. S'il est invoqué sur une session, il abandonne uniquement le processus local.
  • MPI_ERRORS_RETURN Renvoie un code d'erreur à l'application.

Vos propres gestionnaires d'erreurs peuvent également être implémentés en appelant :

  • MPI_Comm_create_errhandler suivi de MPI_Comm_set_errhandler
  • MPI_File_create_errhandler suivi de MPI_File_set_errhandler
  • MPI_Session_create_errhandler suivi de MPI_Session_set_errhandler ou dans MPI_Session_init
  • MPI_Win_create_errhandler suivi de MPI_Win_set_errhandler

Remarque : MPI ne garantit pas qu'un programme MPI puisse continuer après une erreur.

Voir la page de manuel MPI pour une liste complète des codes d'erreur MPI.

Voir la section Gestion des erreurs de la norme MPI-3.1 pour plus d'informations.
