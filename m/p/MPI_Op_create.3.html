MPI_Op_create(3)

Paquet: openmpi

Licences: BSD-3-Clause AND LicenseRef-MPICH

MPI_Op_create(3) Open MPI MPI_Op_create(3)

MPI_Op_create crée un handle de fonction personnalisée qui peut être utilisé plus tard dans MPI_Reduce, MPI_Allreduce, MPI_Reduce_scatter et MPI_Scan. La fonction personnalisée est supposée être associative. Si commute = true, alors l'opération doit être à la fois commutative et associative. Si commute = false, l'ordre des opérandes est fixe et est défini comme l'ordre croissant des rangs de processus, en commençant par le processus zéro. L'ordre d'évaluation peut être modifié, en exploitant l'associativité de l'opération. Si commute = true, l'ordre d'évaluation peut être modifié, en exploitant la commutativité et l'associativité.

function est la fonction personnalisée qui doit avoir les quatre arguments suivants : invec, inoutvec, len et datatype.

Le prototype ANSI-C de la fonction est le suivant :

typedef void MPI_User_function(void *invec, void *inoutvec,
                               int *len,
                               MPI_Datatype *datatype);

La déclaration de la fonction personnalisée en Fortran est la suivante.

FUNCTION USER_FUNCTION( INVEC(*), INOUTVEC(*), LEN, TYPE)
<type> INVEC(LEN), INOUTVEC(LEN)
 INTEGER LEN, TYPE

L'argument datatype est un handle vers le type de données qui a été passé dans l'appel à MPI_Reduce. La fonction de réduction personnalisée doit être écrite de manière à ce que ce qui suit soit vrai : Supposons que u[0], ..., u[len-1] soient les len éléments du tampon de communication décrits par les arguments invec, len et datatype lors de l'invocation de la fonction ; et que v[0], ..., v[len-1] soient les len éléments du tampon de communication décrits par les arguments inoutvec, len et datatype lors de l'invocation de la fonction ; et que w[0], ..., w[len-1] soient les len éléments du tampon de communication décrits par les arguments inoutvec, len et datatype lors du retour de la fonction ; alors w[i] = u[i] ou v[i], pour i=0, ..., len-1, où o est l'opération de réduction que la fonction calcule.

En bref, nous pouvons considérer invec et inoutvec comme des tableaux de len éléments que la fonction combine. Le résultat de la réduction écrase les valeurs dans inoutvec, d'où le nom de l'opération. Chaque invocation de la fonction produit une évaluation ponctuelle de l'opération de réduction sur len éléments : c'est-à-dire que la fonction renvoie dans inoutvec[i] la valeur de u[i] ou inoutvec[i], pour i=0, ..., count-1, où o est l'opération de combinaison calculée par la fonction.

Internelement, en comparant la valeur de l'argument datatype avec des handles globaux connus, il est possible de surcharger l'utilisation d'une seule fonction personnalisée pour plusieurs types de données.

Les types de données généraux peuvent être passés à la fonction personnalisée. Cependant, l'utilisation de types de données non contigus peut entraîner des inefficacités.

Aucune fonction de communication MPI ne peut être appelée à l'intérieur de la fonction personnalisée. MPI_Abort peut être appelée à l'intérieur de la fonction en cas d'erreur.

NOTES

Supposons qu'une bibliothèque de fonctions de réduction personnalisées surchargées soit définie : L'argument datatype est utilisé pour sélectionner la voie d'exécution appropriée en fonction des types d'opérandes. La fonction personnalisée ne peut pas décoder l'argument datatype qu'elle reçoit et ne peut pas identifier par elle-même la correspondance entre les handles de données et les données qu'ils représentent. Cette correspondance a été établie lors de la création des types de données. Avant d'utiliser la bibliothèque, un préambule d'initialisation de la bibliothèque doit être exécuté. Ce code de préambule définira les types de données que la bibliothèque utilisera et stockera les handles de ces types de données dans des variables globales et statiques partagées par le code utilisateur et le code de la bibliothèque.

Exemple : Exemple de fonction de réduction personnalisée :

Calculer le produit d'un tableau de nombres complexes, en C.

typedef struct {
    double real, imag;
} Complex;
/* la fonction personnalisée */
void myProd( Complex *in, Complex *inout, int *len,
             MPI_Datatype *dptr )
{
    int i;
    Complex c;
for (i=0; i< *len; ++i) {
        c.real = inout->real*in->real -
                   inout->imag*in->imag;
        c.imag = inout->real*in->imag +
                   inout->imag*in->real;
        *inout = c;
        in++; inout++;
    }
}
/* et, pour l'appeler... */
...
/* chaque processus a un tableau de 100 Complexes */
    Complex a[100], answer[100];
    MPI_Op myOp;
    MPI_Datatype ctype;
/* expliquer à MPI comment le type Complex est défini */
   MPI_Type_contiguous( 2, MPI_DOUBLE, &ctype );
    MPI_Type_commit( &ctype );
    /* créer l'opération de produit complexe personnalisée */
    MPI_Op_create( myProd, True, &myOp );
    MPI_Reduce( a, answer, 100, ctype, myOp, root, comm );
    /* à ce stade, la réponse, composée de 100 Complexes, réside dans le processus racine */

La version Fortran de MPI_Reduce appellera une fonction de réduction personnalisée en utilisant les conventions d'appel Fortran et passera un argument de type de données Fortran ; la version C utilisera les conventions d'appel C et la représentation du handle de type de données en C. Les utilisateurs qui prévoient de mélanger les langages devraient définir leurs fonctions de réduction en conséquence.

NOTES SUR LES OPÉRATIONS COLLECTIVES

Les fonctions de réduction (MPI_Op) ne renvoient pas de valeur d'erreur. Par conséquent, si elles détectent une erreur, elles ne peuvent qu'appeler MPI_Abort ou ignorer le problème. Ainsi, si vous changez le gestionnaire d'erreurs de MPI_ERRORS_ARE_FATAL à autre chose, par exemple MPI_ERRORS_RETURN, aucune erreur ne peut être signalée.

La raison en est le problème de performance lié à la garantie que toutes les routines d'opération collectives renvoient la même valeur d'erreur.

ERREURS

La plupart des routines MPI renvoient une valeur d'erreur ; les routines C la renvoient comme résultat de la fonction et les routines Fortran dans le dernier argument.

Avant de renvoyer la valeur d'erreur, le gestionnaire d'erreurs associé à l'objet de communication (par exemple, communicator, window, file) est appelé. S'il n'y a pas d'objet de communication associé à l'appel MPI, l'appel est considéré comme associé à MPI_COMM_SELF et le gestionnaire d'erreurs associé est appelé. Lorsque MPI_COMM_SELF n'est pas initialisé (c'est-à-dire avant MPI_Init/MPI_Init_thread, après MPI_Finalize, ou lorsque le modèle de session est utilisé exclusivement), le gestionnaire d'erreurs initial est déclenché. Le gestionnaire d'erreurs initial peut être modifié en appelant MPI_Comm_set_errhandler sur MPI_COMM_SELF lors de l'utilisation du modèle du monde, ou via l'argument mpi_initial_errhandler de mpiexec ou la clé d'info de MPI_Comm_spawn/MPI_Comm_spawn_multiple. Si aucun autre gestionnaire d'erreurs approprié n'existe, l'erreur MPI_ERRORS_RETURN se produit.

handler est appelé pour les fonctions E/S MPI et le gestionnaire d'erreurs MPI_ERRORS_ABORT est appelé pour toutes les autres fonctions MPI.

Open MPI inclut trois gestionnaires d'erreurs prédéfinis qui peuvent être utilisés :

  • MPI_ERRORS_ARE_FATAL Provoque l'abandon de tous les processus MPI connectés.
  • MPI_ERRORS_ABORT Un gestionnaire d'erreurs qui peut être invoqué sur un communicateur, une fenêtre, un fichier ou une session. Lorsqu'il est appelé sur un communicateur, il agit comme si MPI_Abort avait été appelé sur ce communicateur. S'il est appelé sur une fenêtre ou un fichier, il agit comme si MPI_Abort avait été appelé sur un communicateur contenant le groupe de processus de la fenêtre ou du fichier correspondant. S'il est appelé sur une session, il n'abandonne que le processus local.
  • MPI_ERRORS_RETURN Retourne un code d'erreur à l'application.

Les applications MPI peuvent également implémenter leurs propres gestionnaires d'erreurs en appelant :

  • MPI_Comm_create_errhandler puis MPI_Comm_set_errhandler
  • MPI_File_create_errhandler puis MPI_File_set_errhandler
  • MPI_Session_create_errhandler puis MPI_Session_set_errhandler ou à MPI_Session_init
  • MPI_Win_create_errhandler puis MPI_Win_set_errhandler

Notez que MPI ne garantit pas qu'un programme MPI puisse continuer après une erreur.

Voir la page de manuel MPI pour une liste complète des codes d'erreur MPI.

Voir la section Gestion des erreurs de la norme MPI-3.1 pour plus d'informations.
