MPI_Allreduce, MPI_Iallreduce, MPI_Allreduce_init - Combine des valeurs de tous les processus et distribue le résultat à tous les processus.

Paramètres d'entrée

  • sendbuf: Adresse de départ du tampon d'envoi (facultatif).
  • count: Nombre d'éléments dans le tampon d'envoi (entier).
  • datatype: Type de données des éléments du tampon d'envoi (manipulation).
  • op: Opération (manipulation).
  • comm: Communicateur (manipulation).
  • info: Informations (manipulation, persistante).

Paramètres de sortie

  • recvbuf: Adresse de départ du tampon de réception (facultatif).
  • request: Requête (manipulation, non bloquante).
  • ierror: En Fortran uniquement : état d'erreur (entier).

Description

Similaire à MPI_Reduce, sauf que le résultat apparaît dans le tampon de réception de tous les membres du groupe.

Exemple 1 : Une routine qui calcule le produit d'un vecteur et d'un tableau distribués sur un groupe de processus et renvoie le résultat à tous les nœuds (à comparer avec l'exemple 2, avec MPI_Reduce, ci-dessous).

SUBROUTINE PAR_BLAS2(m, n, a, b, c, comm)
REAL a(m), b(m,n)    ! partie locale du tableau
REAL c(n)            ! résultat
REAL sum(n)
INTEGER n, comm, i, j, ierr
! somme locale
DO j= 1, n
  sum(j) = 0.0
  DO i = 1, m
    sum(j) = sum(j) + a(i)*b(i,j)
  END DO
END DO
! somme globale
CALL MPI_ALLREDUCE(sum, c, n, MPI_REAL, MPI_SUM, comm, ierr)
! renvoyer le résultat à tous les nœuds
RETURN

Exemple 2 : Une routine qui calcule le produit d'un vecteur et d'un tableau distribués sur un groupe de processus et renvoie le résultat au nœud zéro.

SUBROUTINE PAR_BLAS2(m, n, a, b, c, comm)
REAL a(m), b(m,n)    ! partie locale du tableau
REAL c(n)            ! résultat
REAL sum(n)
INTEGER n, comm, i, j, ierr
! somme locale
DO j= 1, n
  sum(j) = 0.0
  DO i = 1, m
    sum(j) = sum(j) + a(i)*b(i,j)
  END DO
END DO
! somme globale
CALL MPI_REDUCE(sum, c, n, MPI_REAL, MPI_SUM, 0, comm, ierr)
! renvoyer le résultat au nœud zéro (et le jeter sur les autres nœuds)
RETURN

Utilisation de l'option « in place »

Lorsque le communicateur est un intra-communicateur, vous pouvez effectuer une opération de réduction sur place (le tampon de réception est utilisé comme tampon d'envoi). Utilisez la variable MPI_IN_PLACE comme valeur pour sendbuf sur tous les processus.

Note : MPI_IN_PLACE est un type spécial ; il a les mêmes restrictions d'utilisation que MPI_BOTTOM.

Comme l'option « in place » transforme le tampon de réception en tampon d'envoi et de réception, une liaison Fortran incluant INTENT doit les marquer comme INOUT, et non comme OUT.

Lorsque le communicateur est un inter-communicateur

Lorsque le communicateur est un inter-communicateur, l'opération de réduction se déroule en deux phases. Les données sont réduites à partir de tous les membres du premier groupe et reçues par tous les membres du second groupe. Ensuite, les données sont réduites à partir de tous les membres du second groupe et reçues par tous les membres du premier. L'opération présente un comportement symétrique et double dans la direction.

Lorsque le communicateur est un intra-communicateur, ces groupes sont les mêmes et l'opération se déroule en une seule phase.

Remarques sur les opérations collectives

Les fonctions de réduction (MPI_Op) ne renvoient pas de valeur d'erreur. Par conséquent, si les fonctions détectent une erreur, elles ne peuvent qu'appeler MPI_Abort ou ignorer le problème. Par conséquent, si vous changez le gestionnaire d'erreurs de MPI_ERRORS_ARE_FATAL à autre chose, par exemple MPI_ERRORS_RETURN, aucune erreur ne peut être signalée.

Erreurs

Pour plus d'informations sur les erreurs MPI, les routines C renvoient une valeur d'erreur et les routines Fortran ont le dernier argument comme résultat.

Avant de renvoyer la valeur d'erreur, le gestionnaire d'erreurs associé à l'objet de communication (par exemple, communicateur, fenêtre, fichier) en cours d'utilisation est appelé. S'il n'y a pas d'objet de communication associé à l'appel MPI, l'appel est considéré comme associé à MPI_COMM_SELF et le gestionnaire d'erreurs associé à MPI_COMM_SELF est appelé. Lorsque MPI_COMM_SELF n'est pas initialisé (c'est-à-dire avant MPI_Init/MPI_Init_thread, après MPI_Finalize, ou lorsque le modèle de session est utilisé exclusivement), le gestionnaire d'erreurs initial est levé. Le gestionnaire d'erreurs initial peut être modifié en appelant MPI_Comm_set_errhandler sur MPI_COMM_SELF lorsque le modèle du monde est utilisé, ou via l'argument CLI mpi_initial_errhandler de mpiexec ou la clé d'info de MPI_Comm_spawn/MPI_Comm_spawn_multiple. S'il n'y a pas d'autre gestionnaire d'erreurs approprié, le gestionnaire d'erreurs MPI_ERRORS_RETURN est appelé pour les fonctions d'E/S MPI et le gestionnaire d'erreurs MPI_ERRORS_ABORT est appelé pour toutes les autres fonctions MPI.

Open MPI comprend trois gestionnaires d'erreurs par défaut qui peuvent être utilisés :

  • MPI_ERRORS_ARE_FATAL Provoque la fin du programme de tous les processus connectés à MPI.
  • MPI_ERRORS_ABORT Un gestionnaire d'erreurs qui peut être invoqué sur un communicateur, une fenêtre, un fichier ou une session. Lorsqu'il est invoqué sur un communicateur, il agit comme si MPI_Abort avait été appelé sur ce communicateur. S'il est invoqué sur une fenêtre ou un fichier, il agit comme si MPI_Abort avait été appelé sur ce fichier.

PARAMÈTRES ENTRANTS

Les paramètres suivants peuvent être passés en entrée :

  • Comm (in)
  • File (in)
  • Session (in)
  • Win (in)

Pour le cas de Comm, File, Session et Win, des valeurs de type Comm, File, Session ou Win peuvent respectivement être passées.

PARAMÈTRES SORTANTS

Les paramètres suivants peuvent être retournés en sortie :

  • Comm (out)
  • File (out)
  • Session (out)
  • Win (out)

DESCRIPTION

Cette fonction crée un nouveau communicator, file, session ou win à partir d'un communicator, file, session ou win existant. Le paramètre Comm peut être utilisé en entrée pour créer un nouveau communicator, et les paramètres File, Session et Win comme entrée pour créer un nouveau file, session ou win.

UTILISATION DE L'OPTION EN PLACE

L'option d'utilisation en place peut être utilisée pour créer un nouveau communicator, file, session ou win à partir d'un communicator, file, session ou win existant. Le paramètre Comm peut être utilisé en entrée pour créer un nouveau communicator, et les paramètres File, Session et Win comme entrée pour créer un nouveau file, session ou win.

QUAND LE COMMUNICATEUR EST UN INTER-COMMUNICATEUR

Si le communicator est un inter-communicator, les paramètres Comm, File, Session et Win peuvent être utilisés en entrée pour créer un nouveau communicator, file, session ou win.

NOTES SUR LES OPÉRATIONS COLLECTIVES

L'option d'utilisation en place peut être utilisée pour créer un nouveau communicator, file, session ou win à partir d'un communicator, file, session ou win existant. Le paramètre Comm peut être utilisé en entrée pour créer un nouveau communicator, et les paramètres File, Session et Win comme entrée pour créer un nouveau file, session ou win.
