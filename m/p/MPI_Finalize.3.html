MPI_Finalize — Termine le modèle monde MPI.

SYNTAXE

Syntaxe C

#include <mpi.h>
int MPI_Finalize()

Syntaxe Fortran

USE MPI
! ou la forme plus ancienne : INCLUDE 'mpif.h'
MPI_FINALIZE(IERROR)
    INTEGER IERROR

Syntaxe Fortran 2008

USE mpi_f08
MPI_Finalize(ierror)
    INTEGER, OPTIONAL, INTENT(OUT) :: ierror

PARAMÈTRE DE SORTIE

•
ierror : Seulement en Fortran : Statut d'erreur (entier).

DESCRIPTION

Cette routine finalise le modèle monde MPI. Si le modèle monde MPI a été initialisé dans un processus MPI, il *doit* être finalisé exactement une fois en appelant cette routine au cours de la durée de vie de ce processus MPI. Ceci est différent du modèle de session MPI, qui peut être initialisé et finalisé plusieurs fois dans un processus MPI. Voir MPI_Session_init et MPI_Session_finalize.

Sauf s'il y a eu un appel à MPI_Abort, vous devez vous assurer que toutes les communications en attente dans le modèle monde MPI impliquant un processus sont complètes avant que le processus n'appelle MPI_Finalize. Si l'appel retourne, chaque processus peut soit continuer les calculs locaux, soit se terminer sans participer à d'autres communications avec d'autres processus dans le modèle monde MPI. Au moment où le dernier processus appelle MPI_Finalize, tous les envois en attente dans le modèle monde MPI doivent être appariés par une réception, et toutes les réceptions en attente dans le modèle monde MPI doivent être appariées par un envoi.

Voir MPI-5.0:11.4.1 pour une liste des fonctionnalités MPI disponibles (par exemple, même lorsque le modèle monde MPI n'est pas encore initialisé ou a déjà été finalisé).

MPI_Finalize est collective sur tous les processus connectés. Si aucun processus n'a été lancé, accepté ou connecté, cela signifie qu'elle est collective sur MPI_COMM_WORLD. Sinon, elle est collective sur l'union de tous les processus qui ont été et continuent d'être connectés.

NOTES

Le modèle de session MPI est différent du modèle monde MPI, et a des portées différentes de disponibilité pour les fonctionnalités MPI. Voir MPI_Session_init et MPI_Session_finalize.

Tous les processus qui ont initialisé le modèle monde MPI doivent appeler cette routine avant de se terminer. Tous les processus existeront toujours mais ne pourront plus effectuer d'appels MPI dans le modèle monde MPI. MPI_Finalize garantit que toutes les actions locales requises par les communications dans le modèle monde MPI que l'utilisateur a complétées auront effectivement lieu avant son retour. Cependant, MPI_Finalize ne garantit rien concernant les communications en attente dans le modèle monde MPI qui n'ont pas été complétées ; l'achèvement n'est assuré que par les variantes MPI_Wait et MPI_Test, ou MPI_Request_free combiné à une autre vérification d'achèvement.

Par exemple, un retour réussi d'une opération de communication bloquante ou d'une des variantes MPI_Wait ou MPI_Test signifie que la communication est complétée par l'utilisateur et que le tampon peut être réutilisé, mais ne garantit pas que le processus local n'a plus de travail à faire. De même, un retour réussi de MPI_Request_free avec un handle de requête généré par un MPI_Isend annule le handle mais ne garantit pas que l'opération est terminée. Le MPI_Isend est complété uniquement lorsqu'une réception correspondante est complétée.

Si vous souhaitez déclencher des actions lors de la finalisation du modèle monde MPI par un processus, attachez un attribut à MPI_COMM_SELF avec une fonction de rappel. Ensuite, lorsque MPI_Finalize est appelé, il exécutera d'abord l'équivalent d'un MPI_Comm_free sur MPI_COMM_SELF. Cela provoquera l'exécution de la fonction de rappel de suppression sur toutes les clés associées à MPI_COMM_SELF dans un ordre arbitraire. Si aucune clé n'a été attachée à MPI_COMM_SELF, aucun rappel n'est invoqué. Cette libération de MPI_COMM_SELF se produit avant que toute autre partie du modèle monde MPI ne soit affectée. L'appel à MPI_Finalized retournera donc false dans l'une de ces fonctions de rappel. Une fois que vous avez fait cela avec MPI_COMM_SELF, les résultats de MPI_Finalize ne sont pas spécifiés.

ERREURS

Presque toutes les routines MPI retournent une valeur d'erreur ; les routines C comme résultat de la fonction et les routines Fortran dans le dernier argument.

Avant que la valeur d'erreur ne soit retournée, le gestionnaire d'erreur MPI actuel associé à l'objet de communication (par exemple, communicateur, fenêtre, fichier) est appelé. Si aucun objet de communication n'est associé à l'appel MPI, alors l'appel est considéré comme attaché à MPI_COMM_SELF et appellera le gestionnaire d'erreur MPI associé. Lorsque MPI_COMM_SELF n'est pas initialisé (c'est-à-dire avant MPI_Init/ MPI_Init_thread, après MPI_Finalize, ou lors de l'utilisation exclusive du modèle de sessions), l'erreur déclenche le gestionnaire d'erreur initial. Le gestionnaire d'erreur initial peut être modifié en appelant MPI_Comm_set_errhandler sur MPI_COMM_SELF lors de l'utilisation du modèle Monde, ou via l'argument de ligne de commande mpi_initial_errhandler de mpiexec ou la clé d'information de MPI_Comm_spawn/ MPI_Comm_spawn_multiple. Si aucun autre gestionnaire d'erreur approprié n'a été défini, alors le gestionnaire d'erreur MPI_ERRORS_RETURN est appelé pour les fonctions MPI I/O et le gestionnaire d'erreur MPI_ERRORS_ABORT est appelé pour toutes les autres fonctions MPI.

Open MPI inclut trois gestionnaires d'erreurs prédéfinis qui peuvent être utilisés :

  • MPI_ERRORS_ARE_FATAL Provoque l'arrêt du programme pour tous les processus MPI connectés.
  • MPI_ERRORS_ABORT Un gestionnaire d'erreurs qui peut être invoqué sur un communicateur, une fenêtre, un fichier ou une session. Lorsqu'il est appelé sur un communicateur, il agit comme si MPI_Abort avait été appelé sur ce communicateur. S'il est appelé sur une fenêtre ou un fichier, il agit comme si MPI_Abort avait été appelé sur un communicateur contenant le groupe de processus dans la fenêtre ou le fichier correspondant. S'il est appelé sur une session, il n'interrompt que le processus local.
  • MPI_ERRORS_RETURN Retourne un code d'erreur à l'application.

Les applications MPI peuvent également implémenter leurs propres gestionnaires d'erreurs en appelant :

  • MPI_Comm_create_errhandler puis MPI_Comm_set_errhandler
  • MPI_File_create_errhandler puis MPI_File_set_errhandler
  • MPI_Session_create_errhandler puis MPI_Session_set_errhandler ou lors de MPI_Session_init
  • MPI_Win_create_errhandler puis MPI_Win_set_errhandler

Notez que MPI ne garantit pas qu'un programme MPI puisse continuer après une erreur.

Voir la page man MPI pour une liste complète des codes d'erreur MPI.

Voir la section Gestion des erreurs de la norme MPI-3.1 pour plus d'informations.

MPI_Finalize(3)

MPI_Finalize - Termine l'environnement MPI.

SYNTAX

C:

#include <mpi.h>
int MPI_Finalize(void);

Fortran:

INCLUDE "mpif.h"
INTEGER FUNCTION MPI_FINALIZE()

Fortran 2008:

USE mpi_f08
MPI_FINALIZE()

OUTPUT PARAMETER

Aucun.

DESCRIPTION

MPI_Finalize nettoie l'environnement MPI. Après avoir appelé MPI_Finalize, aucune autre routine MPI ne peut être appelée, à l'exception de MPI_Finalize elle-même et des routines d'initialisation.

NOTES

Si MPI_Finalize est appelée plusieurs fois, le comportement n'est pas défini. Le programme doit s'assurer que MPI_Finalize n'est appelée qu'une seule fois, à la fin du programme.

ERRORS

Aucune erreur.
