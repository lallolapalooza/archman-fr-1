PARAMÈTRES D'ENTRÉE

  • sendbuf: Tampon d'envoi (choix).
  • count: Nombre d'éléments dans le tampon d'entrée (entier).
  • datatype: Type de données des éléments du tampon d'entrée (handle).
  • op: Opération (handle).
  • comm: Communicateur (handle).

PARAMÈTRES DE SORTIE

  • recvbuf: Tampon de réception (choix).
  • request: Requête (handle, uniquement non bloquant).
  • ierror: Fortran uniquement : Statut d'erreur (entier).

DESCRIPTION

MPI_Exscan est utilisée pour effectuer une réduction préfixielle exclusive sur les données distribuées entre les processus appelants. L'opération retourne, dans le recvbuf du processus de rang i, la réduction (calculée selon la fonction op) des valeurs des sendbuf des processus de rangs 0, ..., i-1. Comparer cela avec la fonctionnalité de MPI_Scan, qui calcule sur la plage 0, ..., i (inclusive). Le type d'opérations supportées, leurs sémantiques et les contraintes sur les tampons d'envoi et de réception sont les mêmes que pour MPI_Reduce.

La valeur dans recvbuf sur le processus 0 est indéfinie et peu fiable car recvbuf n'est pas significatif pour le processus 0. La valeur de recvbuf sur le processus 1 est toujours la valeur dans sendbuf sur le processus 0.

UTILISATION DE L'OPTION EN PLACE

L'option « en place » pour les intracommunicateurs est spécifiée en passant MPI_IN_PLACE dans l'argument sendbuf. Dans ce cas, les données d'entrée sont prises du tampon de réception et remplacées par les données de sortie.

Notez que MPI_IN_PLACE est un type de valeur spécial ; il a les mêmes restrictions d'utilisation que MPI_BOTTOM.

Étant donné que l'option en place convertit le tampon de réception en un tampon d'envoi et de réception, une liaison Fortran qui inclut INTENT doit les marquer comme INOUT, et non OUT.

NOTES

MPI ne spécifie pas quel processus calcule quelle opération. En particulier, les deux processus 0 et 1 peuvent participer au calcul même si les résultats pour le recvbuf des deux processus sont dégénérés. Par conséquent, tous les processus, y compris 0 et 1, doivent fournir le même op.

On peut soutenir, d'un point de vue mathématique, que la définition de MPI_Exscan est insatisfaisante car la sortie au processus 0 est indéfinie. La sortie « mathématiquement correcte » pour le processus 0 serait l'élément unité de l'opération de réduction. Cependant, une telle définition d'un scan exclusif ne fonctionnerait pas avec des fonctions op définies par l'utilisateur car il n'y a aucun moyen pour MPI de « connaître » la valeur unitaire pour ces opérations personnalisées.

NOTES SUR LES OPÉRATIONS COLLECTIVES

Les fonctions de réduction de type MPI_Op ne retournent pas de valeur d'erreur. Par conséquent, si les fonctions détectent une erreur, tout ce qu'elles peuvent faire est soit d'appeler MPI_Abort, soit d'ignorer silencieusement le problème. Ainsi, si le gestionnaire d'erreurs est changé de MPI_ERRORS_ARE_FATAL à autre chose (par exemple, MPI_ERRORS_RETURN), aucune erreur ne peut être indiquée.

La raison de cela réside dans les problèmes de performance pour garantir que toutes les routines collectives retournent la même valeur d'erreur.

ERREURS

Presque toutes les routines MPI retournent une valeur d'erreur ; les routines C comme résultat de retour de la fonction et les routines Fortran dans le dernier argument.

Avant que la valeur d'erreur ne soit retournée, le gestionnaire d'erreurs MPI actuel associé à l'objet de communication (par exemple, le communicateur, la fenêtre, le fichier) est appelé. Si aucun objet de communication n'est associé à l'appel MPI, alors l'appel est considéré comme attaché à MPI_COMM_SELF et appellera le gestionnaire d'erreurs MPI associé. Lorsque MPI_COMM_SELF n'est pas initialisé (c'est-à-dire avant MPI_Init/MPI_Init_thread, après MPI_Finalize, ou lorsque le modèle de sessions est utilisé exclusivement), l'erreur déclenche le gestionnaire d'erreurs initial. Le gestionnaire d'erreurs initial peut être modifié en appelant MPI_Comm_set_errhandler sur MPI_COMM_SELF en utilisant le modèle World, ou l'argument de ligne de commande mpi_initial_errhandler de mpiexec ou la clé d'information de MPI_Comm_spawn/MPI_Comm_spawn_multiple. Si aucun autre gestionnaire d'erreurs approprié n'a été défini, alors le gestionnaire d'erreurs MPI_ERRORS_RETURN est appelé pour les fonctions d'E/S MPI et le gestionnaire d'erreurs MPI_ERRORS_ABORT est appelé pour toutes les autres fonctions MPI.

Open MPI inclut trois gestionnaires d'erreurs prédéfinis qui peuvent être utilisés :

  • MPI_ERRORS_ARE_FATAL Provoque l'arrêt du programme de tous les processus MPI connectés.
  • MPI_ERRORS_ABORT Un gestionnaire d'erreurs qui peut être invoqué sur un communicateur, une fenêtre, un fichier ou une session. Lorsqu'il est appelé sur un communicateur, il agit comme si MPI_Abort avait été appelé sur ce communicateur. S'il est appelé sur une fenêtre ou un fichier, il agit comme si MPI_Abort avait été appelé sur un communicateur contenant le groupe de processus dans la fenêtre ou le fichier correspondant. S'il est appelé sur une session, il n'interrompt que le processus local.
  • MPI_ERRORS_RETURN Retourne un code d'erreur à l'application.

Les applications MPI peuvent également implémenter leurs propres gestionnaires d'erreurs en appelant :

  • MPI_Comm_create_errhandler puis MPI_Comm_set_errhandler
  • MPI_File_create_errhandler puis MPI_File_set_errhandler
  • MPI_Session_create_errhandler puis MPI_Session_set_errhandler
