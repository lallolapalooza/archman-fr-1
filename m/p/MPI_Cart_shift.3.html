MPI_CART_SHIFT(3) Open MPI MPI_CART_SHIFT(3)

MPI_Cart_shift — Renvoie les rangs source et destination, étant donné une adresse de déplacement et une taille.

Syntaxe

Syntaxe C

#include <mpi.h>
int MPI_Cart_shift(MPI_Comm comm, int direction, int disp,
    int *rank_source, int *rank_dest)

Syntaxe Fortran

USE MPI
! ou la vieille forme: INCLUDE 'mpif.h'
MPI_CART_SHIFT(COMM, DIRECTION, DISP, RANK_SOURCE,
        RANK_DEST, IERROR)
    INTEGER COMM, DIRECTION, DISP, RANK_SOURCE
    INTEGER RANK_DEST, IERROR

Syntaxe Fortran 2008

USE mpi_f08
MPI_Cart_shift(comm, direction, disp, rank_source, rank_dest, ierror)
    TYPE(MPI_Comm), INTENT(IN) :: comm
    INTEGER, INTENT(IN) :: direction, disp
    INTEGER, INTENT(OUT) :: rank_source, rank_dest
    INTEGER, OPTIONAL, INTENT(OUT) :: ierror

Paramètres d'entrée

  • comm : Communicateur avec une topologie de carte (handle).
  • direction : Dimension du déplacement (entier).
disp
Déplacement (> 0 : déplacement vers le haut, < 0 : déplacement vers le bas) (entier).

Paramètres de sortie

  • rank_source : Rang du processus source (entier).
  • rank_dest : Rang du processus de destination (entier).
  • ierror : Fortran seulement : Statut d'erreur (entier).

Description

Si la topologie du processus est une carte, une opération MPI_Sendrecv est probablement utilisée dans une dimension de coordonnées pour effectuer un décalage de données. En entrée, MPI_Sendrecv prend le rang d'un processus source pour la réception, et le rang d'un processus de destination pour l'envoi. Si la fonction MPI_Cart_shift est appelée pour un groupe de processus cartésiens, elle fournit au processus appelant les identifiants mentionnés ci-dessus, qui peuvent ensuite être passés à MPI_Sendrecv. L'utilisateur spécifie la dimension du décalage et la taille du pas (positif ou négatif). La fonction est locale.

L'argument direction indique la dimension du décalage, c'est-à-dire la coordonnée dont la valeur est modifiée par le décalage. Les coordonnées sont numérotées de 0 à ndims-1, où ndims est le nombre de dimensions.

Note : L'argument direction est dans la plage [0, n-1] pour une grille cartésienne à n dimensions.

Selon la périodicité du groupe cartésien dans la coordonnée spécifiée direction, MPI_Cart_shift fournit les identifiants d'un décalage cyclique ou d'un décalage de bord. Dans le cas d'un décalage de bord, MPI_PROC_NULL peut être renvoyé dans rank_source ou rank_dest, indiquant que le processus source ou de destination pour le décalage est hors limites.

Exemple : Le communicateur comm a une topologie cartésienne bidimensionnelle périodique. Une matrice de réels bidimensionnels est stockée une entrée par processus dans la variable A. On veut décaler cette matrice, en décalant la colonne i (verticalement, c'est-à-dire le long de la colonne) par i pas.

! trouver le rang du processus
    CALL MPI_COMM_RANK(comm, rank, ierr)
! trouver les coordonnées cartésiennes
    CALL MPI_CART_COORDS(comm, rank, maxdims, coords, ierr)
! calculer la source et la destination
    CALL MPI_CART_SHIFT(comm, 0, coords(2), source, dest, ierr)
! décaler la matrice
    CALL MPI_SENDRECV_REPLACE(A, 1, MPI_REAL, dest, 0, source, 0, comm, status,
                              ierr)

Note

En Fortran, la dimension indiquée par DIRECTION = i a DIMS(i+1) nœuds, où DIMS est le tableau utilisé pour créer la grille. En C, la dimension indiquée par direction = i est la dimension spécifiée par dims[i].

Erreurs

Outre le fait que presque toutes les routines MPI renvoient une valeur d'erreur ; en C, la valeur de retour de la fonction est le résultat de la routine, et en Fortran, le dernier argument est la valeur d'erreur.

Avant de renvoyer la valeur d'erreur, le gestionnaire d'erreurs associé à l'objet de communication actuel (par exemple, communicateur, fenêtre, fichier) est appelé. S'il n'y a pas d'objet de communication associé à l'appel MPI, l'appel est considéré comme associé à MPI_COMM_SELF et le gestionnaire d'erreurs associé à MPI_COMM_SELF est appelé. Lorsque MPI_COMM_SELF n'est pas initialisé (c'est-à-dire avant MPI_Init/MPI_Init_thread, après MPI_Finalize, ou lorsqu'on utilise exclusivement le modèle de session), le gestionnaire d'erreurs par défaut est appelé. Le gestionnaire par défaut peut être modifié en appelant MPI_Comm_set_errhandler sur MPI_COMM_SELF lors de l'utilisation du modèle mondial, ou la clé d'information mpi_initial_errhandler de mpiexec ou MPI_Comm_spawn/MPI_Comm_spawn_multiple. Si aucun autre gestionnaire approprié n'est disponible, le gestionnaire MPI_ERRORS_RETURN est appelé pour les routines d'E/S MPI et MPI_ERRORS_ABORT pour toutes les autres routines MPI.

Open MPI inclut trois gestionnaires d'erreurs par défaut qui peuvent être utilisés :

  • MPI_ERRORS_ARE_FATAL : Le programme interrompt tous les processus MPI connectés.
  • MPI_ERRORS_ABORT : Un gestionnaire d'erreurs qui peut être appelé sur un communicateur, une fenêtre, un fichier ou une session. Lorsqu'il est appelé sur un communicateur, il agit comme si MPI_Abort avait été appelé sur ce communicateur. S'il est appelé sur une fenêtre ou un fichier, il agit comme si MPI_Abort avait été appelé sur un communicateur contenant les processus de la fenêtre ou du fichier correspondant. S'il est appelé sur une session, il interrompt uniquement le processus local.
  • MPI_ERRORS_RETURN : Renvoie un code d'erreur à l'application.

Les applications MPI peuvent également implémenter leurs propres gestionnaires d'erreurs en appelant :

  • MPI_Comm_create_errhandler suivi de MPI_Comm_set_errhandler
  • MPI_File_create_errhandler suivi de MPI_File_set_errhandler
  • MPI_Session_create_errhandler suivi de MPI_Session_set_errhandler ou dans MPI_Session_init
  • MPI_Win_create_errhandler suivi de MPI_Win_set_errhandler

Note : MPI ne garantit pas qu'un programme MPI puisse continuer après une erreur.
