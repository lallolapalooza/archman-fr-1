MPI_Get_elements_x(3) Open MPI MPI_Get_elements_x(3)

MPI_Get_elements, MPI_Get_elements_x - Renvoie le nombre d'éléments de base dans un type de données.

SYNTAXE

Syntaxe C

#include <mpi.h>
int MPI_Get_elements(const MPI_Status *status, MPI_Datatype datatype,
    int *count)
int MPI_Get_elements_x(const MPI_Status *status, MPI_Datatype datatype,
    MPI_Count *count)

Syntaxe Fortran

USE MPI
! ou l'ancien format : INCLUDE 'mpif.h'
MPI_GET_ELEMENTS(STATUS, DATATYPE, COUNT, IERROR)
    INTEGER STATUS(MPI_STATUS_SIZE), DATATYPE, COUNT, IERROR
MPI_GET_ELEMENTS_X(STATUS, DATATYPE, COUNT, IERROR)
    INTEGER STATUS(MPI_STATUS_SIZE), DATATYPE
        INTEGER(KIND=MPI_COUNT_KIND) COUNT
        INTEGER IERROR

Syntaxe Fortran 2008

USE mpi_f08
MPI_Get_elements(status, datatype, count, ierror)
    TYPE(MPI_Status), INTENT(IN) :: status
    TYPE(MPI_Datatype), INTENT(IN) :: datatype
    INTEGER, INTENT(OUT) :: count
    INTEGER, OPTIONAL, INTENT(OUT) :: ierror
MPI_Get_elements_x(status, datatype, count, ierror)
    TYPE(MPI_Status), INTENT(IN) :: status
    TYPE(MPI_Datatype), INTENT(IN) :: datatype
    INTEGER(KIND = MPI_COUNT_KIND), INTENT(OUT) :: count
    INTEGER, OPTIONAL, INTENT(OUT) :: ierror

PARAMÈTRES D'ENTRÉE

  • status : État de l'opération de réception (status).
  • datatype : Type de données utilisé dans l'opération de réception (handle).

PARAMÈTRES DE SORTIE

•
ierror : Statut d'erreur (entier) seulement en Fortran.

DESCRIPTION

MPI_Get_elements et MPI_Get_elements_x se comportent différemment de MPI_Get_count, qui renvoie le nombre d'« entrées de haut niveau » reçues, c'est-à-dire le nombre de « copies » du type de données. MPI_Get_count peut renvoyer n'importe quelle valeur entière k, où 0 < k < count. Si MPI_Get_count renvoie k, alors le nombre d'éléments de base reçus (et la valeur renvoyée par MPI_Get_elements et MPI_Get_elements_x) est n * k, où n est le nombre d'éléments de base dans le type de données. Si le nombre d'éléments de base reçus n'est pas un multiple de n, c'est-à-dire si l'opération de réception n'a pas reçu un nombre intégral de copies du type de données, alors MPI_Get_count renvoie MPI_UNDEFINED. Pour les deux fonctions, si le paramètre count ne peut pas exprimer la valeur à renvoyer (par exemple, si le paramètre est trop petit pour stocker la valeur de sortie), il est défini à MPI_UNDEFINED.

Exemple : Utilisation de MPI_Get_count et MPI_Get_elements :

call MPI_TYPE_CONTIGUOUS(2, MPI_REAL, Type2, ierr)
call MPI_TYPE_COMMIT(Type2, ierr)
call MPI_COMM_RANK(comm, rank, ierr)
IF ( rank == 0 ) THEN
   CALL MPI_SEND(a, 2, MPI_REAL, 1, 0, comm, ierr)
   CALL MPI_SEND(a, 3, MPI_REAL, 1, 0, comm, ierr)
ELSE
   CALL MPI_RECV(a, 2, Type2, 0, 0, comm, stat, ierr)
   CALL MPI_GET_COUNT(stat, Type2, i, ierr) ! renvoie i=1
   CALL MPI_GET_ELEMENTS(stat, Type2, i, ierr) ! renvoie i=2
   CALL MPI_RECV(a, 2, Type2, 0, 0, comm, stat, ierr)
   CALL MPI_GET_COUNT(stat, Type2, i, ierr) ! renvoie i=MPI_UNDEFINED
   CALL MPI_GET_ELEMENTS(stat, Type2, i, ierr)  ! renvoie i=3
END IF

La fonction MPI_Get_elements peut également être utilisée après un balayage pour trouver le nombre d'éléments dans le message balayé. Notez que les deux fonctions MPI_Get_count et MPI_Get_elements renvoient les mêmes valeurs lorsqu'elles sont utilisées avec des données primitives.

ERREURS

La plupart des routines MPI renvoient une valeur d'erreur ; les routines C renvoient cette valeur comme résultat de la fonction et les routines Fortran dans le dernier argument.

Avant que la valeur d'erreur ne soit renvoyée, le gestionnaire d'erreurs actuel associé à l'objet de communication (par exemple, communicator, window, file) est appelé. S'il n'y a pas d'objet de communication associé à l'appel MPI, alors l'appel est considéré comme associé à MPI_COMM_SELF et le gestionnaire d'erreurs associé est appelé. Lorsque MPI_COMM_SELF n'est pas initialisé (c'est-à-dire avant MPI_Init/MPI_Init_thread, après MPI_Finalize, ou lors de l'utilisation exclusive du modèle de Sessions), l'erreur déclenche le gestionnaire d'erreurs initial. Le gestionnaire d'erreurs initial peut être modifié en appelant MPI_Comm_set_errhandler sur MPI_COMM_SELF lors de l'utilisation du modèle du Monde, ou l'argument mpi_initial_errhandler CLI pour mpiexec ou la clé d'information pour MPI_Comm_spawn/MPI_Comm_spawn_multiple. Si aucun autre gestionnaire d'erreurs approprié n'est défini, le gestionnaire d'erreurs MPI_ERRORS_RETURN est appelé pour les fonctions d'E/S MPI et le gestionnaire d'erreurs MPI_ERRORS_ABORT pour toutes les autres fonctions MPI.

Open MPI inclut trois gestionnaires d'erreurs par défaut qui peuvent être utilisés :

  • MPI_ERRORS_ARE_FATAL Provoque l'arrêt du programme pour tous les processus MPI connectés.
  • MPI_ERRORS_ABORT Un gestionnaire d'erreurs qui peut être invoqué sur un communicateur, une fenêtre, un fichier ou une session. Lorsqu'il est invoqué sur un communicateur, il agit comme si MPI_Abort avait été appelé sur ce communicateur. S'il est invoqué sur une fenêtre ou un fichier, il agit comme si MPI_Abort avait été appelé sur un communicateur contenant le groupe de processus correspondant dans la fenêtre ou le fichier. S'il est invoqué sur une session, seul le processus local est abandonné.
  • MPI_ERRORS_RETURN Renvoie un code d'erreur à l'application.

Les programmes MPI peuvent également implémenter leurs propres gestionnaires d'erreurs en appelant :

  • MPI_Comm_create_errhandler puis MPI_Comm_set_errhandler
  • MPI_File_create_errhandler puis MPI_File_set_errhandler
  • MPI_Session_create_errhandler puis MPI_Session_set_errhandler ou dans MPI_Session_init
  • MPI_Win_create_errhandler puis MPI_Win_set_errhandler

Note : MPI ne garantit pas qu'un programme MPI puisse continuer après une erreur.

Voir la page de manuel MPI pour une liste complète des codes d'erreur MPI.

Voir la section sur la gestion des erreurs de la norme MPI-3.1 pour plus d'informations.
