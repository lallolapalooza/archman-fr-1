MPI_COMM_GET_NAME(3) Open MPI MPI_COMM_GET_NAME(3)

MPI_Comm_get_name — Renvoie le nom qui a été le plus récemment associé à un communicateur.

SYNTAXE

Syntaxe C

#include <mpi.h>
int MPI_Comm_get_name(MPI_Comm comm, char *comm_name, int *resultlen)

Syntaxe Fortran

USE MPI
! ou la forme plus ancienne: INCLUDE 'mpif.h'
MPI_COMM_GET_NAME(COMM, COMM_NAME, RESULTLEN, IERROR)
     INTEGER COMM, RESULTLEN, IERROR
     CHARACTER*(*) COMM_NAME

Syntaxe Fortran 2008

USE mpi_f08
MPI_Comm_get_name(comm, comm_name, resultlen, ierror)
     TYPE(MPI_Comm), INTENT(IN) :: comm
     CHARACTER(LEN=MPI_MAX_OBJECT_NAME), INTENT(OUT) :: comm_name
     INTEGER, INTENT(OUT) :: resultlen
     INTEGER, OPTIONAL, INTENT(OUT) :: ierror

PARAMÈTRE D'ENTRÉE

•
comm: Communicateur dont le nom doit être retourné (descripteur).

PARAMÈTRE DE SORTIE

  • comm_name: Nom précédemment stocké sur le communicateur, ou une chaîne vide si aucun nom de ce type n'existe (chaîne).
  • resultlen: Longueur du nom retourné (entier).
  • ierror: Fortran uniquement : Statut d'erreur (entier).

DESCRIPTION

MPI_Comm_get_name renvoie le dernier nom qui a été précédemment associé au communicateur donné. Le nom peut être défini et récupéré depuis n'importe quel langage. Le même nom sera retourné indépendamment du langage utilisé. comm_name doit être alloué de manière à pouvoir contenir une chaîne résultante de longueur MPI_MAX_OBJECT_NAME caractères. MPI_Comm_get_name renvoie une copie du nom défini dans comm_name.

Si l'utilisateur n'a pas associé de nom à un communicateur, ou si une erreur se produit, MPI_Comm_get_name renverra une chaîne vide (toutes des espaces en Fortran, “” en C). Les trois communicateurs prédéfinis auront des noms prédéfinis associés. Ainsi, les noms de MPI_COMM_WORLD, MPI_COMM_SELF et MPI_COMM_PARENT auront par défaut MPI_COMM_WORLD, MPI_COMM_SELF et MPI_COMM_PARENT. Le fait que le système ait pu attribuer un nom par défaut à un communicateur n'empêche pas l'utilisateur de définir un nom sur le même communicateur ; faire cela supprime l'ancien nom et attribue le nouveau.

NOTES

Il est sûr d'imprimer simplement la chaîne retournée par MPI_Comm_get_name, car c'est toujours une chaîne valide même s'il n'y avait pas de nom.

Notez que l'association d'un nom à un communicateur n'a aucun effet sur la sémantique d'un programme MPI, et augmentera (nécessairement) les exigences de stockage du programme, car les noms doivent être sauvegardés. Par conséquent, rien n'oblige les utilisateurs à utiliser ces fonctions pour associer des noms à des communicateurs. Cependant, le débogage et le profilage des applications MPI peuvent être facilités si des noms sont associés aux communicateurs, car le débogueur ou le profileur devrait alors pouvoir présenter les informations de manière moins cryptique.

ERREURS

Presque toutes les routines MPI renvoient une valeur d'erreur ; les routines C comme résultat de la fonction et les routines Fortran dans le dernier argument.

Avant que la valeur d'erreur ne soit retournée, le gestionnaire d'erreurs MPI actuel associé à l'objet de communication (par exemple, communicateur, fenêtre, fichier) est appelé. Si aucun objet de communication n'est associé à l'appel MPI, alors l'appel est considéré comme attaché à MPI_COMM_SELF et appellera le gestionnaire d'erreurs MPI associé. Lorsque MPI_COMM_SELF n'est pas initialisé (c'est-à-dire avant MPI_Init/MPI_Init_thread, après MPI_Finalize, ou lors de l'utilisation exclusive du modèle de sessions), l'erreur déclenche le gestionnaire d'erreurs initial. Le gestionnaire d'erreurs initial peut être modifié en appelant MPI_Comm_set_errhandler sur MPI_COMM_SELF lors de l'utilisation du modèle World, ou via l'argument de ligne de commande mpi_initial_errhandler de mpiexec ou la clé d'information de MPI_Comm_spawn/MPI_Comm_spawn_multiple. Si aucun autre gestionnaire d'erreurs approprié n'a été défini, le gestionnaire d'erreurs MPI_ERRORS_RETURN est appelé pour les fonctions d'E/S MPI et le gestionnaire d'erreurs MPI_ERRORS_ABORT est appelé pour toutes les autres fonctions MPI.

Open MPI inclut trois gestionnaires d'erreurs prédéfinis qui peuvent être utilisés :

  • MPI_ERRORS_ARE_FATAL Provoque l'arrêt du programme de tous les processus MPI connectés.
  • MPI_ERRORS_ABORT Un gestionnaire d'erreurs qui peut être invoqué sur un communicateur, une fenêtre, un fichier ou une session. Lorsqu'il est appelé sur un communicateur, il agit comme si MPI_Abort avait été appelé sur ce communicateur. S'il est appelé sur une fenêtre ou un fichier, il agit comme si MPI_Abort avait été appelé sur un communicateur contenant le groupe de processus de la fenêtre ou du fichier correspondant. S'il est appelé sur une session, il n'arrête que le processus local.
  • MPI_ERRORS_RETURN Renvoie un code d'erreur à l'application.

Les applications MPI peuvent également implémenter leurs propres gestionnaires d'erreurs en appelant :

  • MPI_Comm_create_errhandler puis MPI_Comm_set_errhandler
  • MPI_File_create_errhandler puis MPI_File_set_errhandler
  • MPI_Session_create_errhandler puis MPI_Session_set_errhandler ou à MPI_Session_init
  • MPI_Win_create_errhandler puis MPI_Win_set_errhandler

Notez que MPI ne garantit pas qu'un programme MPI puisse continuer après une erreur.

Voir la page de manuel MPI pour une liste complète des codes d'erreur MPI.

Voir la section Gestion des erreurs de la norme MPI-3.1 pour plus d'informations.
