MPI_BUFFER_DETACH(3) Open MPI MPI_BUFFER_DETACH(3)

MPI_Buffer_detach — Supprime un tampon existant (à utiliser dans MPI_Bsend, etc.)

SYNTAXE

Syntaxe C

#include <mpi.h>
int MPI_Buffer_detach(void *buf, int *size)

Syntaxe Fortran

USE MPI
! ou l'ancienne forme: INCLUDE 'mpif.h'
MPI_BUFFER_DETACH(BUF, SIZE, IERROR)
    <type>  BUF(*)
    INTEGER SIZE, IERROR

Syntaxe Fortran 2008

USE mpi_f08
MPI_Buffer_detach(buffer_addr, size, ierror)
    USE, INTRINSIC :: ISO_C_BINDING, ONLY
    TYPE(C_PTR), INTENT(OUT) :: buffer_addr
    INTEGER, INTENT(OUT) :: size
    INTEGER, OPTIONAL, INTENT(OUT) :: ierror

PARAMÈTRES DE SORTIE

  • buf : Adresse initiale du tampon (choix).
  • size : Taille du tampon, en octets (entier).
  • ierror : Fortran uniquement : Statut d'erreur (entier).

DESCRIPTION

Détache le tampon actuellement associé à MPI. L'appel renvoie l'adresse et la taille du tampon détaché. Cette opération bloquera jusqu'à ce que tous les messages actuellement dans le tampon aient été transmis. Au retour de cette fonction, l'utilisateur peut réutiliser ou libérer l'espace occupé par le tampon.

Exemple : Appels pour attacher et détacher des tampons.

#define BUFFSIZE 10000
int size char *buff;
MPI_Buffer_attach( malloc(BUFFSIZE), BUFFSIZE);
// un tampon de 10000 octets peut maintenant être utilisé par MPI_Bsend
MPI_Buffer_detach( &buff, &size); // Taille du tampon réduite à zéro
MPI_Buffer_attach( buff, size); // Tampon de 10000 octets à nouveau disponible

NOTES

La raison pour laquelle MPI_Buffer_detach renvoie l'adresse et la taille du tampon détaché est de permettre aux bibliothèques imbriquées de remplacer et de restaurer le tampon. Par exemple, considérez

int size, mysize, idummy;
void *ptr, *myptr, *dummy;
MPI_Buffer_detach( &ptr, &size );
MPI_Buffer_attach( myptr, mysize );
/* ... code de la bibliothèque ... */
MPI_Buffer_detach( &dummy, &idummy );
MPI_Buffer_attach( ptr, size );

C'est très similaire à l'action de la routine de signal UNIX et cela a les mêmes forces (c'est simple) et faiblesses (cela ne fonctionne qu'en cas d'usages imbriqués).

Pour Fortran : La liaison Fortran pour cette routine est différente. Parce que Fortran n'a pas de pointeurs, il est impossible de fournir un moyen d'utiliser la sortie de cette routine pour échanger des tampons. Dans ce cas, seul le champ taille est défini.

Pour C : Même si les fonctions C MPI_Buffer_attach et MPI_Buffer_detach ont toutes deux un premier argument de type void*, ces arguments sont utilisés différemment : un pointeur vers le tampon est passé à MPI_Buffer_attach ; l'adresse du pointeur est passée à MPI_Buffer_detach, de sorte que cet appel puisse renvoyer la valeur du pointeur.

ERREURS

Presque toutes les routines MPI renvoient une valeur d'erreur ; les routines C comme résultat de retour de la fonction et les routines Fortran dans le dernier argument.

Avant que la valeur d'erreur ne soit renvoyée, le gestionnaire d'erreurs MPI actuel associé à l'objet de communication (par exemple, communicateur, fenêtre, fichier) est appelé. Si aucun objet de communication n'est associé à l'appel MPI, l'appel est considéré comme attaché à MPI_COMM_SELF et appellera le gestionnaire d'erreurs MPI associé. Lorsque MPI_COMM_SELF n'est pas initialisé (c'est-à-dire, avant MPI_Init/MPI_Init_thread, après MPI_Finalize, ou lorsque le modèle de sessions est utilisé exclusivement), l'erreur déclenche le gestionnaire d'erreurs initial. Le gestionnaire d'erreurs initial peut être modifié en appelant MPI_Comm_set_errhandler sur MPI_COMM_SELF lors de l'utilisation du modèle World, ou via l'argument de ligne de commande mpiexec mpi_initial_errhandler ou la clé d'informations de MPI_Comm_spawn/MPI_Comm_spawn_multiple. Si aucun autre gestionnaire d'erreurs approprié n'a été défini, alors le gestionnaire d'erreurs MPI_ERRORS_RETURN est appelé pour les fonctions d'E/S MPI et le gestionnaire d'erreurs MPI_ERRORS_ABORT est appelé pour toutes les autres fonctions MPI.

Open MPI inclut trois gestionnaires d'erreurs prédéfinis qui peuvent être utilisés :

  • MPI_ERRORS_ARE_FATAL Provoque l'arrêt du programme de tous les processus MPI connectés.
  • MPI_ERRORS_ABORT Un gestionnaire d'erreurs qui peut être appelé sur un communicateur, une fenêtre, un fichier ou une session. Lorsqu'il est appelé sur un communicateur, il agit comme si MPI_Abort avait été appelé sur ce communicateur. S'il est appelé sur une fenêtre ou un fichier, il agit comme si MPI_Abort avait été appelé sur un communicateur contenant le groupe des processus de la fenêtre ou du fichier correspondant. S'il est appelé sur une session, il n'interrompt que le processus local.
  • MPI_ERRORS_RETURN Renvoie un code d'erreur à l'application.

Les applications MPI peuvent également implémenter leurs propres gestionnaires d'erreurs en appelant :

  • MPI_Comm_create_errhandler puis MPI_Comm_set_errhandler
  • MPI_File_create_errhandler puis MPI_File_set_errhandler
  • MPI_Session_create_errhandler puis MPI_Session_set_errhandler ou lors de MPI_Session_init
  • MPI_Win_create_errhandler puis MPI_Win_set_errhandler

Notez que MPI ne garantit pas qu'un programme MPI puisse continuer après une erreur.

Voir la page de manuel MPI pour une liste complète des codes d'erreur MPI.

Voir la section Gestion des erreurs de la norme MPI-3.1 pour plus d'informations.

Using archlinux-keyring in Arch Linux

Utilisation de `archlinux-keyring` sous Arch Linux

Ceci est un guide sur la manière d'utiliser le paquet Arch Linux `archlinux-keyring`.

Qu'est-ce que `archlinux-keyring` ?

Le paquet `archlinux-keyring` contient les clés publiques utilisées pour vérifier l'authenticité des paquets binaires dans les dépôts d'Arch Linux. Ces clés sont utilisées par le gestionnaire de paquets Pacman pour s'assurer que les paquets que vous téléchargez et installez proviennent bien d'Arch Linux et n'ont pas été falsifiés.

Pourquoi est-il important ?

La sécurité des paquets est primordiale. Si un attaquant parvenait à compromettre un dépôt et à y placer un paquet malveillant, les utilisateurs seraient infectés sans le savoir. Les clés de signature dans `archlinux-keyring` empêchent cela en permettant à Pacman de vérifier la signature numérique de chaque paquet par rapport à une clé de confiance.

Gestion de `archlinux-keyring`

Normalement, vous n'avez pas à gérer `archlinux-keyring` manuellement. Il est mis à jour automatiquement lorsque vous mettez à jour votre système avec `pacman -Syu`. Pacman utilise les clés contenues dans ce paquet pour vérifier les nouvelles clés téléchargées lors de la synchronisation des dépôts.

Cependant, il peut arriver que vous rencontriez des problèmes liés aux clés, par exemple si vous n'avez pas mis à jour votre système depuis longtemps ou si vous avez des problèmes avec la synchronisation des clés.

Cas de figure courant : échec de la vérification de l'intégrité des paquets

Si vous obtenez des erreurs du type : 

error: failed retrieving file '...' from ...
error: failed retrieving file '...' from ...
error: failed retrieving file '...' from ...
error: failed retrieving file '...' from ...
error: ...
error: key "..." is unknown
error: failed to synchronize all databases

Cela signifie généralement que Pacman ne fait pas confiance à la clé publique utilisée pour signer les paquets des dépôts. La cause la plus fréquente est que les clés de confiance n'ont pas été mises à jour depuis longtemps et que les dépôts utilisent désormais de nouvelles clés.

Solution : Mettre à jour les clés

La méthode recommandée pour résoudre ce problème est de synchroniser et de mettre à jour les clés de manière explicite.

  1. Tout d'abord, assurez-vous que votre système est à jour, y compris le paquet `archlinux-keyring` lui-même. Si vous ne pouvez pas synchroniser à cause des clés, vous pouvez essayer de forcer la mise à jour de `archlinux-keyring` : 
    sudo pacman -Sy archlinux-keyring
    Si cela ne fonctionne pas, vous pourriez devoir importer manuellement les clés publiques de confiance.
  2. Ensuite, synchronisez les bases de données des paquets et importez les clés publiques nécessaires. La commande suivante va synchroniser les bases de données, mettre à jour les clés existantes et importer les nouvelles : 
    sudo pacman -Syu
    Si cette commande échoue toujours à cause de clés inconnues, vous pouvez tenter de réinitialiser le trousseau de clés et d'importer les clés par défaut :

Réinitialisation et importation manuelle des clés (en dernier recours)

Si `pacman -Syu` ne fonctionne toujours pas après avoir mis à jour `archlinux-keyring`, vous devrez peut-être réinitialiser le trousseau de clés de Pacman et importer manuellement les clés publiques officielles d'Arch Linux.

  1. Supprimez toutes les clés du trousseau de Pacman : 
    sudo rm -r /etc/pacman.d/gnupg
  2. Initialisez un nouveau trousseau de clés : 
    sudo pacman-key --init
  3. Remplissez le trousseau avec les clés d'urgence : 
    sudo pacman-key --populate archlinux
  4. Mettez à jour toutes les clés : 
    sudo pacman-key --refresh-keys
  5. Enfin, synchronisez et mettez à jour votre système : 
    sudo pacman -Syu

Attention : La suppression et la réinitialisation manuelles du trousseau de clés doivent être effectuées avec prudence. Assurez-vous de suivre les étapes correctement. Si vous n'êtes pas sûr, consultez la documentation officielle d'Arch Linux ou demandez de l'aide sur les forums.

Conclusion

Le paquet `archlinux-keyring` est un composant essentiel pour la sécurité de votre système Arch Linux. En général, il se gère tout seul lors des mises à jour système. Cependant, comprendre comment résoudre les problèmes liés aux clés peut vous éviter des maux de tête si jamais vous rencontrez des erreurs de synchronisation ou de vérification de paquets. Gardez toujours votre système à jour pour minimiser ces risques.

Ce guide a été créé pour aider les utilisateurs d'Arch Linux à comprendre et à gérer le paquet `archlinux-keyring`. Les commandes et les étapes fournies sont basées sur les pratiques courantes et les recommandations officielles. Le paquet `archlinux-keyring` est géré et spécifié dans le paquet Arch Linux correspondant.
