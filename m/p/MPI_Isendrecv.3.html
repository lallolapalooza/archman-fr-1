MPI_Isendrecv — envoie et reçoit un message.

SYNTAXE

Syntaxe C

#include <mpi.h>
int MPI_Isendrecv(const void *sendbuf, int sendcount, MPI_Datatype sendtype,
    int dest, int sendtag, void *recvbuf, int recvcount,
    MPI_Datatype recvtype, int source, int recvtag,
    MPI_Comm comm, MPI_Request *request)

Syntaxe Fortran

USE MPI
! ou o o o: INCLUDE 'mpif.h'
MPI_ISENDRECV(SENDBUF, SENDCOUNT, SENDTYPE, DEST, SENDTAG,
        RECVBUF, RECVCOUNT, RECVTYPE, SOURCE, RECVTAG, COMM,
        REQUEST, IERROR)

Syntaxe Fortran 2008

USE mpi_f08
MPI_Isendrecv(sendbuf, sendcount, sendtype, dest, sendtag, recvbuf,
        recvcount, recvtype, source, recvtag, comm, request, ierror)

PARAMÈTRES D'ENTRÉE

  • sendbuf : Adresse de début du tampon d'envoi (option).
  • sendcount : Nombre d'éléments à envoyer (entier).
  • sendtype : Type des éléments dans le tampon d'envoi (descripteur).
  • dest : Rang du destinataire (entier).
  • sendtag : Étiquette d'envoi (entier).
  • recvcount : Nombre maximal d'éléments à recevoir (entier).
  • recvtype : Type des éléments dans le tampon de réception (descripteur).
  • source : Rang de l'expéditeur (entier).
  • recvtag : Étiquette de réception (entier).
  • comm : Communicateur (descripteur).

PARAMÈTRES DE SORTIE

  • recvbuf : Adresse de début du tampon de réception (option).
  • request : Requête de communication (descripteur).
  • ierror : Seulement en Fortran : statut d'erreur (entier).

DESCRIPTION

Les opérations d'envoi et de réception non bloquantes combinent en un seul appel l'envoi d'un message vers une destination et la réception d'un autre message, à partir d'un autre processus. Les deux (expéditeur et destinataire) peuvent être identiques. Cette opération est utile pour effectuer une opération de décalage dans une chaîne de processus. L'opération d'envoi et de réception peut être utilisée conjointement avec les fonctions décrites dans le chapitre sur les topologies de processus de la norme MPI pour effectuer des décalages dans différentes topologies logiques.

Un message envoyé par une opération d'envoi et de réception peut être reçu par une opération de réception régulière ou testé par une opération de test ; une opération d'envoi et de réception peut recevoir un message envoyé par une opération d'envoi régulière.

MPI_Isendrecv exécute une opération d'envoi et de réception non bloquante. L'envoi et la réception utilisent le même communicateur, mais peuvent avoir des étiquettes différentes. Les tampons d'envoi et de réception doivent être disjoints et peuvent avoir des longueurs et des types de données différents.

Une requête d'envoi et de réception non bloquante peut être marquée comme terminée en appelant MPI_Wait, MPI_Waitany, MPI_Test ou MPI_Testany avec la requête renvoyée par cette fonction.

ERREURS

La plupart des routines MPI renvoient une valeur d'erreur ; les routines C renvoient le résultat de la fonction et les routines Fortran le dernier argument.

Avant de renvoyer la valeur d'erreur, le gestionnaire d'erreurs associé à l'objet de communication actuel (par exemple, communicateur, fenêtre, fichier) est appelé. S'il n'y a pas d'objet de communication associé à l'appel MPI, l'appel est considéré comme associé à MPI_COMM_SELF et le gestionnaire d'erreurs associé à MPI_COMM_SELF est appelé. Lorsque MPI_COMM_SELF n'est pas initialisé (c'est-à-dire avant MPI_Init/MPI_Init_thread, après MPI_Finalize, ou lorsque le modèle de sessions est utilisé exclusivement), l'erreur déclenche le gestionnaire d'erreurs initial. Le gestionnaire d'erreurs initial peut être modifié en appelant MPI_Comm_set_errhandler sur MPI_COMM_SELF lors de l'utilisation du modèle Monde, ou la clé d'information mpi_initial_errhandler pour mpiexec ou la clé d'information pour MPI_Comm_spawn/MPI_Comm_spawn_multiple. Si aucun autre gestionnaire d'erreurs approprié n'est défini, le gestionnaire d'erreurs MPI_ERRORS_RETURN est appelé pour les fonctions d'E/S MPI et le gestionnaire d'erreurs MPI_ERRORS_ABORT pour toutes les fonctions MPI.

Open MPI inclut trois gestionnaires d'erreurs par défaut qui peuvent être utilisés :

  • MPI_ERRORS_ARE_FATAL — arrête tous les processus MPI connectés.
  • MPI_ERRORS_ABORT — un gestionnaire d'erreurs qui peut être invoqué sur un communicateur, une fenêtre, un fichier ou une session. Lorsqu'il est invoqué sur un communicateur, il agit comme si MPI_Abort avait été appelé sur ce communicateur. S'il est invoqué sur une fenêtre ou un fichier, il agit comme si MPI_Abort avait été appelé sur un communicateur contenant l'ensemble des processus dans la fenêtre ou le fichier correspondant. S'il est invoqué sur une session, il arrête uniquement le processus local.
  • MPI_ERRORS_RETURN — renvoie un code d'erreur à l'application.

Les applications MPI peuvent également implémenter leurs propres gestionnaires d'erreurs en appelant :

  • MPI_Comm_create_errhandler puis MPI_Comm_set_errhandler
  • MPI_File_create_errhandler puis MPI_File_set_errhandler
  • MPI_Session_create_errhandler puis MPI_Session_set_errhandler ou dans MPI_Session_init
  • MPI_Win_create_errhandler puis MPI_Win_set_errhandler

Remarque : Les gestionnaires d'erreurs MPI ne garantissent pas qu'un programme MPI puisse continuer après une erreur.

Voir la page de manuel MPI pour une liste complète des codes d'erreur MPI.

Voir la section sur la gestion des erreurs de la norme MPI-3.1 pour plus d'informations.
