MPI_Pack_external — Écrit des données dans un format portable

SYNTAX

Syntaxe C

#include <mpi.h>
int MPI_Pack_external(const char *datarep, const void *inbuf,
     int incount, MPI_Datatype datatype,
     void *outbuf, MPI_Aint outsize,
     MPI_Aint *position)

Syntaxe Fortran

USE MPI
! ou l'ancienne forme : INCLUDE 'mpif.h'
MPI_PACK_EXTERNAL(DATAREP, INBUF, INCOUNT, DATATYPE,
     OUTBUF, OUTSIZE, POSITION, IERROR)
     INTEGER         INCOUNT, DATATYPE, IERROR
     INTEGER(KIND=MPI_ADDRESS_KIND) OUTSIZE, POSITION
     CHARACTER*(*)   DATAREP
     <type>          INBUF(*), OUTBUF(*)

Syntaxe Fortran 2008

USE mpi_f08
MPI_Pack_external(datarep, inbuf, incount, datatype, outbuf, outsize,
             position, ierror)
     CHARACTER(LEN=*), INTENT(IN) :: datarep
     TYPE(*), DIMENSION(..), INTENT(IN) :: inbuf
     TYPE(*), DIMENSION(..) :: outbuf

     TYPE(MPI_Datatype), INTENT(IN) :: datatype

PARAMÈTRES D'ENTRÉE

  • datarep: Représentation des données (chaîne).
  • inbuf: Début du tampon d'entrée (choix).
  • incount: Nombre d'éléments de données d'entrée (entier).
  • datatype: Type de données de chaque élément de données d'entrée (descripteur).
  • outsize: Taille du tampon de sortie, en octets (entier).

PARAMÈTRE D'ENTRÉE/SORTIE

•
position: Position actuelle dans le tampon, en octets (entier).

PARAMÈTRES DE SORTIE

  • outbuf: Début du tampon de sortie (choix).
  • ierror: Fortran uniquement : Statut d'erreur (entier).

DESCRIPTION

MPI_Pack_external empile des données dans le format external32, une représentation de données universelle définie par le Forum MPI. Ce format est utile pour l'échange de données entre implémentations MPI, ou lors de l'écriture de données dans un fichier.

Le tampon d'entrée est spécifié par inbuf, incount et datatype, et peut être n'importe quel tampon de communication autorisé dans MPI_Send. Le tampon de sortie outbuf doit être une zone de stockage contiguë contenant outsize octets.

La valeur d'entrée de position est la première position dans outbuf à utiliser pour l'empilement (mesurée en octets, pas en éléments, par rapport au début du tampon). Lorsque la fonction retourne, position est incrémenté de la taille du message empilé, de sorte qu'il pointe vers le premier emplacement dans outbuf suivant le message empilé. De cette façon, il peut être utilisé comme entrée pour un appel ultérieur à MPI_Pack_external.

Exemple : Un exemple utilisant MPI_Pack_external :

int position, i;
double msg[5];
char buf[1000];
...
MPI_Comm_rank(MPI_COMM_WORLD, &myrank);
if (myrank == 0) {      /* CODE EXPÉDITEUR */
        position = 0;
        i = 5; /* nombre de doubles dans msg[] */
        MPI_Pack_external("external32", &i, 1, MPI_INT,
            buf, 1000, &position);
        MPI_Pack_external("external32", &msg, i, MPI_DOUBLE,
            buf, 1000, &position);
        MPI_Send(buf, position, MPI_BYTE, 1, 0,
            MPI_COMM_WORLD);
} else {                /* CODE RÉCEPTEUR */
        MPI_Recv(buf, 1, MPI_BYTE, 0, 0, MPI_COMM_WORLD,
            MPI_STATUS_IGNORE);
        MPI_Unpack_external("external32", buf, 1000,
            MPI_INT, &i, 1, &position);
        MPI_Unpack_external("external32", buf, 1000,
            MPI_DOUBLE, &msg, i, &position);
}

NOTES

L'argument datarep spécifie le format des données. La seule valeur valide dans la version actuelle de MPI est « external32 ». L'argument est fourni pour l'extensibilité future.

Pour comprendre le comportement de pack et unpack, il est commode de considérer la partie données d'un message comme la séquence obtenue en concaténant les valeurs successives envoyées dans ce message. L'opération de pack stocke cette séquence dans l'espace tampon, comme si elle envoyait le message à ce tampon. L'opération d'unpack récupère cette séquence depuis l'espace tampon, comme si elle recevait un message de ce tampon. (Il est utile de penser aux fichiers internes Fortran ou à sscanf en C pour une fonction similaire.)

Plusieurs messages peuvent être empilés successivement dans une unité d'empilement. Ceci est réalisé par plusieurs appels successifs et liés à MPI_Pack_external, où le premier appel fournit position=0, et chaque appel successif utilise la valeur de position qui a été générée par l'appel précédent, avec les mêmes valeurs pour outbuf et outcount. Cette unité d'empilement contient maintenant les informations équivalentes qui auraient été stockées dans un message par un appel send avec un tampon send qui est la « concaténation » des tampons send individuels.

Une unité d'empilement peut être envoyée en utilisant le type MPI_BYTE. Toute fonction de communication point à point ou collective peut être utilisée pour déplacer la séquence d'octets qui forme l'unité d'empilement d'un processus à un autre. Cette unité d'empilement peut maintenant être reçue en utilisant n'importe quelle opération de réception, avec n'importe quel type de données. (Les règles de correspondance de type sont assouplies pour les messages envoyés avec le type MPI_BYTE.)

Une unité d'empilement peut être dépilée en plusieurs messages successifs. Ceci est réalisé par plusieurs appels successifs et liés à MPI_Unpack_external, où le premier appel fournit position=0, et chaque appel successif utilise la valeur de position qui a été générée par l'appel précédent, et les mêmes valeurs pour inbuf et insize.

La concaténation de deux unités d'empilement n'est pas nécessairement une unité d'empilement ; ni une sous-chaîne d'une unité d'empilement n'est nécessairement une unité d'empilement. Ainsi, on ne peut pas concaténer deux unités d'empilement puis dépiler le résultat comme une seule unité d'empilement ; ni dépiler une sous-chaîne d'une unité d'empilement comme une unité d'empilement séparée. Chaque unité d'empilement créée par une séquence d'appels d'empilement liés doit être dépilée comme une unité par une séquence d'appels de dépilement liés.

ERREURS

Presque toutes les routines MPI retournent une valeur d'erreur ; les routines C comme résultat de retour de la fonction et les routines Fortran dans le dernier argument.

Avant que la valeur d'erreur ne soit retournée, le gestionnaire d'erreurs MPI actuel associé à l'objet de communication (par exemple, communicateur, fenêtre, fichier) est appelé. Si aucun objet de communication n'est associé à l'appel MPI, alors l'appel est considéré comme attaché à MPI_COMM_SELF et appellera le gestionnaire d'erreurs MPI associé. Lorsque MPI_COMM_SELF n'est pas initialisé (c'est-à-dire, avant MPI_Init/MPI_Init_thread, après MPI_Finalize, ou lors de l'utilisation exclusive du modèle de Sessions) l'erreur déclenche le gestionnaire d'erreurs initial. Le gestionnaire d'erreurs initial peut être modifié en appelant MPI_Comm_set_errhandler sur MPI_COMM_SELF lors de l'utilisation du modèle World, ou via l'argument de ligne de commande mpiexec ou la clé d'information de MPI_Comm_spawn/MPI_Comm_spawn_multiple. Si aucun autre gestionnaire d'erreurs approprié n'a été défini, alors le gestionnaire d'erreurs MPI_ERRORS_RETURN est appelé pour les fonctions E/S MPI et le gestionnaire d'erreurs MPI_ERRORS_ABORT est appelé pour toutes les autres fonctions MPI.

Open MPI inclut trois gestionnaires d'erreurs prédéfinis qui peuvent être utilisés :

  • MPI_ERRORS_ARE_FATAL Provoque l'arrêt du programme pour tous les processus MPI connectés.
  • MPI_ERRORS_ABORT Un gestionnaire d'erreurs qui peut être invoqué sur un communicateur, une fenêtre, un fichier ou une session. Lorsqu'il est appelé sur un communicateur, il agit comme si MPI_Abort était appelé sur ce communicateur. S'il est appelé sur une fenêtre ou un fichier, il agit comme si MPI_Abort était appelé sur un communicateur contenant le groupe des processus de la fenêtre ou du fichier correspondant.
