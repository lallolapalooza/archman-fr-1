MPI_Win_create — Appel MPI unidirectionnel retournant un objet fenêtre pour les opérations RMA.

SYNTAXE

Syntaxe C

#include <mpi.h>
MPI_Win_create(void *base, MPI_Aint size, int disp_unit,
     MPI_Info info, MPI_Comm comm, MPI_Win *win)

Syntaxe Fortran

USE MPI
! ou l'ancienne forme : INCLUDE 'mpif.h'
MPI_WIN_CREATE(BASE, SIZE, DISP_UNIT, INFO, COMM, WIN, IERROR)
     <type> BASE(*)
     INTEGER(KIND=MPI_ADDRESS_KIND) SIZE
     INTEGER DISP_UNIT, INFO, COMM, WIN, IERROR

Syntaxe Fortran 2008

USE mpi_f08
MPI_Win_create(base, size, disp_unit, info, comm, win, ierror)
     TYPE(*), DIMENSION(..), ASYNCHRONOUS :: base
     INTEGER(KIND=MPI_ADDRESS_KIND), INTENT(IN) :: size
     INTEGER, INTENT(IN) :: disp_unit
     TYPE(MPI_Info), INTENT(IN) :: info
     TYPE(MPI_Comm), INTENT(IN) :: comm
     TYPE(MPI_Win), INTENT(OUT) :: win
     INTEGER, OPTIONAL, INTENT(OUT) :: ierror

PARAMÈTRES D'ENTRÉE

  • base: Adresse initiale de la fenêtre (choix).
  • size: Taille de la fenêtre en octets (entier non négatif).
  • disp_unit: Unité de déplacement locale, en octets (entier positif).
  • info: Argument d'information (handle).
  • comm: Communicateur (handle).

PARAMÈTRES DE SORTIE

  • win: Objet fenêtre retourné par l'appel (handle).
  • ierror: Uniquement en Fortran : Statut d'erreur (entier).

DESCRIPTION

MPI_Win_create est un appel MPI collectif unidirectionnel exécuté par tous les processus du groupe de comm. Il retourne un objet fenêtre qui peut être utilisé par ces processus pour effectuer des opérations RMA. Chaque processus spécifie une fenêtre de mémoire existante qu'il expose aux opérations RMA des processus du groupe de comm. La fenêtre se compose de size octets, commençant à l'adresse base. Un processus peut choisir de ne pas exposer de mémoire en spécifiant size = 0.

Si la valeur base utilisée par MPI_Win_create a été allouée par MPI_Alloc_mem, la taille de la fenêtre ne peut pas être supérieure à la valeur définie par la fonction MPI_Alloc_mem.

La valeur de disp_unit est fournie pour faciliter le calcul des déplacements dans les opérations RMA : l'argument de déplacement d'une opération RMA est mis à l'échelle par le facteur disp_unit spécifié par le processus cible lors de la création de la fenêtre.

Les clés d'information suivantes sont prises en charge :

no_locks
Si défini sur true, l'implémentation peut supposer que la fenêtre locale n'est pas verrouillée (par un appel à MPI_Win_lock ou MPI_Win_lock_all). La définition de cette valeur si elle n'est que de synchronisation active peut permettre à l'implémentation d'activer certaines optimisations.
accumulate_ordering
Par défaut, les opérations d'accumulation d'un initiateur vers une cible dans le même emplacement mémoire de la fenêtre sont strictement ordonnancées. Si la clé d'information accumulate_ordering est définie sur none, aucun ordonnancement des opérations d'accumulation n'est garanti. La clé peut également être une liste séparée par des virgules d'ordres requis de rar, war, raw et waw pour lecture après lecture, écriture après lecture, lecture après écriture et écriture après écriture, respectivement. Des contraintes d'ordonnancement plus laxistes peuvent entraîner de meilleures performances.
accumulate_ops
Si défini sur same_op, l'implémentation suppose que tous les appels concurrents à la même adresse cible utiliseront la même opération. Si défini sur same_op_no_op, l'implémentation suppose que tous les appels concurrents à la même adresse cible utiliseront la même opération ou MPI_NO_OP. La valeur par défaut est same_op_no_op.
same_size
Si défini sur true, l'implémentation peut supposer que la valeur size est identique sur tous les processus et que tous les processus ont fourni cette clé d'information avec la même valeur.
same_disp_unit
Si défini sur true, l'implémentation peut supposer que la valeur disp_unit est identique sur tous les processus et que tous les processus ont fourni cette clé d'information avec la même valeur.

NOTES

Les choix courants pour disp_unit sont 1 (pas de mise à l'échelle) et, dans la syntaxe C, sizeof(type), pour une fenêtre composée d'un tableau d'éléments de type type. Ce dernier choix permet d'utiliser des indices de tableau dans les appels RMA et de faire correctement correspondre les déplacements, même dans des environnements hétérogènes.

Utilisez la mémoire allouée par MPI_Alloc_mem pour garantir des bords de fenêtre bien alignés (par exemple, mot, double mot, ligne de cache, page de frame, etc.).

ERREURS

La plupart des routines MPI retournent une valeur d'erreur ; les routines C retournent le résultat de la fonction et les routines Fortran dans le dernier argument.

Avant de retourner la valeur d'erreur, le gestionnaire d'erreurs associé à l'objet de communication actuel (par exemple, communicateur, fenêtre, fichier) est appelé. S'il n'y a pas d'objet de communication associé à l'appel MPI, l'appel est considéré comme associé à MPI_COMM_SELF et le gestionnaire d'erreurs associé à MPI_COMM_SELF sera appelé. Lorsque MPI_COMM_SELF n'est pas initialisé (c'est-à-dire avant MPI_Init/MPI_Init_thread, après MPI_Finalize, ou lors de l'utilisation exclusive du modèle de sessions), le gestionnaire d'erreurs initial est invoqué. Le gestionnaire d'erreurs initial peut être modifié en appelant MPI_Comm_set_errhandler avec MPI_COMM_SELF lors de l'utilisation du modèle du Monde, ou via l'argument de ligne de commande mpi_initial_errhandler dans mpiexec ou via la clé d'information MPI_Comm_spawn/MPI_Comm_spawn_multiple. Si aucun autre gestionnaire d'erreurs approprié n'est trouvé, le gestionnaire d'erreurs MPI_ERRORS_RETURN est appelé pour les fonctions d'E/S MPI et le gestionnaire d'erreurs MPI_ERRORS_ABORT pour toutes les autres fonctions MPI.

Open MPI inclut trois gestionnaires prédéfinis qui peuvent être utilisés :

  • MPI_ERRORS_ARE_FATAL Provoque l'arrêt de tous les processus connectés à MPI par le programme.
  • MPI_ERRORS_ABORT Un gestionnaire d'erreurs qui peut être invoqué sur un communicateur, une fenêtre, un fichier ou une session. Lorsqu'il est invoqué sur un communicateur, il agit comme si MPI_Abort avait été appelé sur ce communicateur. S'il est invoqué sur une fenêtre ou un fichier, il agit comme si MPI_Abort avait été appelé sur un communicateur contenant les processus dans la fenêtre ou le fichier correspondant. S'il est invoqué sur une session, il n'interrompt que le processus local.
  • MPI_ERRORS_RETURN Retourne un code d'erreur à l'application.

Les applications MPI peuvent également implémenter leurs propres gestionnaires d'erreurs en appelant :

  • MPI_Comm_create_errhandler puis MPI_Comm_set_errhandler
  • MPI_File_create_errhandler puis MPI_File_set_errhandler
  • MPI_Session_create_errhandler puis MPI_Session_set_errhandler ou dans MPI_Session_init
  • MPI_Win_create_errhandler puis MPI_Win_set_errhandler

Note : Les applications MPI ne garantissent pas qu'un programme MPI puisse continuer après une erreur.

Voir la page de manuel MPI pour une liste complète des codes d'erreur MPI.

Voir la section sur la gestion des erreurs de la norme MPI-3.1 pour plus d'informations.

SYNTAX

C++

#include <mpi.h>

int MPI::Win::Create(const void *model, int size, int disp_unit, MPI::Intracomm &comm) const;
int MPI::Win::Create(void *baseptr, MPI_Aint size, int disp_unit, MPI::Intracomm &comm) const;
int MPI::Win::Create(const void *model, MPI_Aint size, int disp_unit, MPI::Intracomm &comm) const;
int MPI::Win::Create(void *baseptr, int size, int disp_unit, MPI::Intracomm &comm) const;

C

#include <mpi.h>

int MPI_Win_create(void *baseptr, MPI_Aint size, int disp_unit, MPI_Comm comm, MPI_Win *win);

INPUT PARAMETERS

baseptr
Puntero al inicio del espacio de memoria que se asociará con la ventana. Puede ser MPI_BOTTOM.
size
Tamaño en bytes del espacio de memoria al que se puede acceder en la ventana. Puede ser 0.
disp_unit
Unidad de visualización (desplazamiento). Puede ser MPI_DATATYPE_NULL o un valor positivo.
comm
Comunicador utilizado para crear la ventana. Todos los procesos en comm deben ser parte del mismo grupo de procesos.
win
Puntero a la mano de ventana que se creará.

OUTPUT PARAMETERS

win
Puntero al objeto de ventana de MPI recién creado.

DESCRIPTION

MPI_Win_create crea una nueva ventana de acceso remoto de memoria (RMA) y asocia un espacio de memoria contiguo con ella. El espacio de memoria se define por el puntero de base y el tamaño.

baseptr y size definen el espacio de memoria que se puede acceder mediante operaciones RMA. Si baseptr es MPI_BOTTOM, se utiliza el valor de size para determinar el tamaño de la ventana. Si size es 0, la ventana estará vacía.

disp_unit especifica la unidad de desplazamiento para las operaciones RMA. Puede ser MPI_DATATYPE_NULL, lo que significa que solo se pueden usar desplazamientos en bytes. Si es un valor positivo, representa el tamaño en bytes de la unidad de desplazamiento. Por ejemplo, si disp_unit es igual al tamaño de un entero, entonces un desplazamiento de 3 se refiere al cuarto entero en el espacio de memoria.

comm es el comunicador que define el grupo de procesos que pueden participar en operaciones RMA utilizando esta ventana. Todos los procesos en el comunicador deben llamar a MPI_Win_create.

La mano de ventana recién creada se devuelve en el argumento win.

El espacio de memoria especificado por baseptr y size debe ser válido durante la vida útil de la ventana. Cualquier operación de acceso remoto realizada en la ventana está sujeta a las reglas de sincronización de MPI.

NOTES

La versión C++ de esta función es un constructor de la clase MPI::Win.

ERRORS

Los errores de creación de ventanas de MPI se producen si el comunicador no es válido o si la memoria especificada no es válida. También pueden producirse errores si la unidad de desplazamiento es un valor negativo.
