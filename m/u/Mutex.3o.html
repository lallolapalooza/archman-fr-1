Module Mutex
: sig fin

Verrous d'exclusion mutuelle.

Les mutex (verrous d'exclusion mutuelle) sont utilisés pour implémenter des sections critiques et protéger des structures de données partagées mutables contre les accès concurrents. L'utilisation typique est (si m est le mutex associé à la structure de données D ):

     Mutex.lock m;
     (* Section critique opérant sur D *);
     Mutex.unlock m

type t

Le type des mutex.

val create : unit -> t

Retourne un nouveau mutex.

val lock : t -> unit

Verrouille le mutex donné. Un seul thread peut avoir le mutex verrouillé à la fois. Un thread qui tente de verrouiller un mutex déjà verrouillé par un autre thread sera suspendu jusqu'à ce que l'autre thread déverrouille le mutex.

Avant4.12

Sys_error n'était pas levée pour un verrouillage récursif (comportement dépendant de la plateforme)

Lève Sys_error si le mutex est déjà verrouillé par le thread appelant Mutex.lock .

val try_lock : t -> bool

Identique à Mutex.lock , mais ne suspend pas le thread appelant si le mutex est déjà verrouillé : retourne immédiatement false dans ce cas. Si le mutex est déverrouillé, le verrouille et retourne true .

val unlock : t -> unit

Déverrouille le mutex donné. Les autres threads suspendus essayant de verrouiller le mutex redémarreront. Le mutex doit avoir été précédemment verrouillé par le thread qui appelle Mutex.unlock .

Avant4.12

Sys_error n'était pas levée lors du déverrouillage d'un mutex déverrouillé ou lors du déverrouillage d'un mutex par un autre thread.

Lève Sys_error si le mutex est déverrouillé ou a été verrouillé par un autre thread.

val protect : t -> (unit -> 'a) -> 'a

protect mutex f exécute f() dans une section critique où mutex est verrouillé (en utilisant Mutex.lock ); il prend ensuite soin de relâcher mutex , que f() ait retourné une valeur ou levé une exception.

L'opération de déverrouillage est garantie de se produire toujours, même dans le cas où une exception asynchrone (par exemple, Sys.Break ) est levée dans un gestionnaire de signaux.
