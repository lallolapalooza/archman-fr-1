NOM

Munin::Plugin::SNMP - Sous-classe de Net::SNMP pour les plugins Munin

SYNOPSIS

Le module Munin::Plugin::SNMP étend Net::SNMP avec des méthodes utiles pour les plugins Munin.

CONFIGURATION SNMP

Les plugins SNMP (qui utilisent ce module) partagent une interface de configuration commune implémentée dans la fonction session(). Veuillez consulter la documentation de cette fonction pour des instructions complètes et des exemples sur la façon de configurer SNMP. La documentation est située là pour s'assurer qu'elle est à jour et correspond au code.

DÉPANNAGE

Des messages de débogage supplémentaires peuvent être activés en définissant $Munin::Plugin::SNMP::DEBUG, $Munin::Plugin::DEBUG, ou en exportant la variable d'environnement "MUNIN_DEBUG" avant d'exécuter le plugin (en passant l'option "--pidebug" à "munin-run", par exemple).

MÉTHODES

config_session() - Décoder l'environnement pour obtenir les paramètres de configuration nécessaires du plugin

($host, $port, $version, $tail) = Munin::Plugin::SNMP->config_session();

C'est une fonction pratique pour la partie "config" du plugin - elle décode l'environnement/le nom du plugin pour récupérer les informations nécessaires lors de la phase de configuration. Elle renvoie un 4-uplet composé de :

1) le nom d'hôte
2) le port UDP à utiliser
3) la version SNMP à utiliser (3 pour la version 3, 2 pour la version 1 ou 2c)
4) la queue du nom du plugin : tout ce qui reste du nom du plugin après "snmp_<hôte>_".

La queue peut être intéressante pour la partie "fetch" du plugin également.

session([options Net::SNMP optionnelles]) - créer un nouvel objet Munin::Plugin::SNMP

$session = Munin::Plugin::SNMP->session();

Cette méthode surcharge le constructeur Net::SNMP pour obtenir les informations de connexion à partir du nom du plugin et/ou de l'environnement. Notez qu'aucune chaîne d'erreur n'est renvoyée. La fonction gère les erreurs en interne - affichant un message d'erreur et appelant `die`. Appeler `die` est la chose à faire.

Le nom d'hôte est pris à partir du lien symbolique du plugin, qui doit être sous la forme "snmp[v3]_<nom_d_hote>_<nom_plugin>[_arguments]".

La forme "v3" est prise pour signifier que SNMPv3 doit être utilisé. C'est aussi une astuce de nommage fournissant un "espace de noms" séparé pour les périphériques qui utilisent SNMPv3 afin qu'il puisse être configuré séparément dans les fichiers munin/plugin-conf.d/. Par exemple :

[snmp_*]
   env.version 2
   env.community public
[snmpv3_*]
   env.v3username snmpoperator
   env.v3authpassword s3cr1tpa55w0rd

Voir ci-dessous comment configurer pour chaque cas différent. Le premier cas ci-dessus montre la configuration par défaut de Munin.

NOTE : munin-node-configure n'utilise pas encore la chose "v3".

Les variables d'environnement suivantes sont consultées :

"env.host"
Si le nom du plugin (lien symbolique) ne contient pas le nom d'hôte, celui-ci est utilisé comme nom d'hôte à connecter.

Le nom d'hôte doit être spécifié, mais il est généralement spécifié dans le nom du plugin. Si le nom d'hôte ne se résout pas dans DNS (ou le fichier hosts) il est possible de faire ceci :

[snmp_*]
   env.version 2c
   env.community floppa
[snmp_switch1.langfeldt.net]
   env.host 192.168.2.45
[snmp_switch2.langfeldt.net]
   env.host 192.168.2.46
"env.port"
Le port à connecter. Par défaut 161.
"env.timeout"
Le délai d'attente en secondes à utiliser. Par défaut 5.
"env.domain"
Le Domaine de Transport à utiliser pour échanger des messages SNMP. Le défaut est UDP/IPv4. Valeurs possibles : 'udp', 'udp4', 'udp/ipv4' ; 'udp6', 'udp/ipv6' ; 'tcp', 'tcp4', 'tcp/ipv4' ; 'tcp6', 'tcp/ipv6'.
"env.version"
La version SNMP à utiliser pour la connexion. L'une des valeurs : 1, 2, 3, snmpv1, snmpv2c ou snmpv3. SNMP v2 est préférable car il prend en charge les opérations groupées. Par conséquent, 2 est la valeur par défaut dans "Munin::Plugin::SNMP". Si votre appareil prend en charge v3, cela peut être encore mieux car il prend en charge la sécurité appropriée - mais le chiffrement peut ralentir les choses.

La sécurité est gérée différemment pour les versions 1/2c et 3. Voir ci-dessous.

Authentification SNMP 1/2c
"env.community"
Le nom de communauté pour les agents des versions 1 et 2c. La valeur par défaut est 'public'. Si cela fonctionne, votre appareil est probablement très peu sécurisé et a besoin d'une vérification de sécurité.
Authentification SNMP 3
SNMP v3 possède trois niveaux de sécurité. Le plus bas est "noAuthNoPriv", qui n'offre ni authentification ni chiffrement. Si un nom d'utilisateur et un "authpassword" sont fournis, il passe à "authNoPriv", et la connexion est authentifiée. Si "privpassword" est fourni, le niveau de sécurité devient "authPriv" - la connexion est authentifiée et chiffrée.

Note : Le chiffrement peut ralentir les périphériques réseau lents ou très chargés. Pour la plupart des utilisations, "authNoPriv" sera suffisamment sécurisé - le mot de passe est de toute façon envoyé sur le réseau chiffré.

"Munin::Plugin::SNMP" ne prend pas en charge les ContextEngineIDs et autres pour l'authentification/la confidentialité. Si vous en voyez le besoin et savez comment cela doit être fait, veuillez envoyer des correctifs !

Pour plus d'informations sur les modèles de sécurité SNMP v3, veuillez consulter la RFC3414 et la documentation de Net::SNMP.

Si la version est définie sur 3 ou snmpv3, les variables suivantes sont utilisées pour définir l'authentification :

"env.v3username"
Nom d'utilisateur. Il n'y a pas de valeur par défaut.
"env.v3authpassword"
Mot de passe d'authentification. Optionnel lorsque le chiffrement est également activé, auquel cas il prend par défaut le mot de passe de confidentialité ("env.v3privpassword"). Le mot de passe est envoyé chiffré (hachage unidirectionnel) sur le réseau.
"env.v3authprotocol"
Protocole d'authentification. L'une des valeurs : 'md5' ou 'sha' (HMAC-MD5-96, RFC1321 et SHA-1/HMAC-SHA-96, NIST FIPS PIB 180, RFC2264). La valeur par défaut est 'md5'.
"env.v3privpassword"
Mot de passe de confidentialité pour activer le chiffrement. Un mot de passe vide ('') est considéré comme aucun mot de passe et n'activera pas le chiffrement.

La confidentialité nécessite un v3privprotocol ainsi qu'un v3authprotocol et un v3authpassword, mais tous ceux-ci sont mis par défaut (à 'des', 'md5', et la valeur v3privpassword, respectivement) et peuvent par conséquent être laissés non spécifiés.

"env.v3privprotocol"
Si v3privpassword est défini, ce paramètre contrôle quel type de chiffrement est utilisé pour assurer la confidentialité dans la session. Seule la méthode de chiffrement 'des', très faible, est officiellement prise en charge. La valeur par défaut est 'des'.

Le module Perl d'implémentation (Net::SNMP) prend également en charge '3des' (CBC-3DES-EDE, alias Triple-DES, NIST FIPS 46-3) comme spécifié dans l'ébauche IETF draft-reeder-snmpv3-usm-3desede. Que cela fonctionne ou non avec un périphérique particulier, nous ne le savons pas.

get_hash() - récupérer une table sous forme de hachage de hachages

$result = $session->get_hash(
                       [-callback        => sub {},]     # non bloquant
                       [-delay           => $secondes,]   # non bloquant
                       [-contextengineid => $engine_id,] # v3
                       [-contextname     => $name,]      # v3
                       -baseoid          => $oid,
                       -cols             => \%colonnes
                   );

Cette méthode transforme le -baseoid et -cols en un tableau de -colonnes et appelle get_entries() avec tous les autres arguments. Elle transforme ensuite les données en un hachage de hachages de la manière suivante :

NOM

get_hash - Obtenir un hash de valeurs par OID

SYNTAXE

$session->get_hash(
             -baseoid => '1.3.6.1.2.1.2.2.1', # IF-MIB
             -cols    => {
                          1 => 'index',
                          2 => 'descr',
                          4 => 'mtu',
                         }
          );

Si l'appel échoue à obtenir une valeur, la valeur est définie à 'U' dans $uptime, ce que Munin interprète comme "Undefined" et gère correctement.

MÉTHODES

$uptime = $session->get_single("1.3.6.1.2.1.1.3.0") || 'U';

Si l'appel échoue à obtenir une valeur, la valeur est définie à 'U' dans $uptime, ce que Munin interprète comme "Undefined" et gère correctement.

GET_BY_REGEX

my $tcpConnState = "1.3.6.1.2.1.6.13.1.1.";
my $connections = $session->get_by_regex($tcpConnState, "[1-9]");

Obtient une table de valeurs filtrées selon une expression régulière appliquée à la valeur.

get_single() - Obtenir une valeur unique par OID

$uptime = $session->get_single("1.3.6.1.2.1.1.3.0") || 'U';

Si l'appel échoue à obtenir une valeur, la valeur est définie à 'U' dans $uptime, ce que Munin interprète comme "Undefined" et gère correctement.

get_by_regex() - Obtenir une table de valeurs filtrées selon une expression régulière appliquée à la valeur

Cet exemple montre l'utilisation d'un plugin netstat.

my $tcpConnState = "1.3.6.1.2.1.6.13.1.1.";
my $connections = $session->get_by_regex($tcpConnState, "[1-9]");

Obtient tous les OID basés sur $tcpConnState et ne retourne que ceux qui contiennent un chiffre dans la valeur.
