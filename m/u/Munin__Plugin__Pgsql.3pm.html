NOM

Munin::Plugin::Pgsql - Module de base pour les plugins Munin de PostgreSQL

SYNOPSIS

Le module Munin::Plugin::Pgsql fournit des fonctionnalités de base pour tous les plugins Munin de PostgreSQL, y compris des paramètres de configuration communs.

CONFIGURATION

Toute la configuration se fait via les variables d'environnement.

VARIABLES D'ENVIRONNEMENT

Tous les plugins basés sur Munin::Plugin::Pgsql acceptent toutes les variables d'environnement que libpq accepte. Les plus couramment utilisées sont :

PGHOST      nom d'hôte à contacter, ou chemin du socket Unix
PGPORT      numéro de port à contacter
PGUSER      nom d'utilisateur pour se connecter
PGPASSWORD  mot de passe pour se connecter, si un mot de passe est requis

Les plugins se connecteront par défaut à la base de données 'template1', sauf pour les plugins wildcard par base de données. Ceci peut être annulé en utilisant la variable PGDATABASE, mais c'est généralement une mauvaise idée.

Si vous utilisez le plugin pour plusieurs instances postgres, vous pouvez personnaliser le titre du graphique avec la variable d'environnement PGLABEL.

Les seuils d'alerte (warning) et critique (critical) peuvent être personnalisés en définissant des variables d'environnement "warning" et "critical" par plugin.

Exemple

[postgres_*]
   user postgres
   env.PGUSER postgres
   env.PGPORT 5433
 [postgres_connections_ALL]
   env.warning :450
   env.critical :500

CORRESPONDANCE WILDCARD

Les plugins wildcard basés sur ce module correspondront au type d'objet spécifié pour un filtre, généralement une base de données. Si le nom d'objet ALL est utilisé (par exemple, un lien symbolique vers postgres_connections_ALL), le filtre ne sera pas appliqué, et le plugin se comportera comme un plugin non-wildcard.

REQUIS

Le module nécessite DBD::Pg pour fonctionner.

DOCUMENTATION API

Les fonctions suivantes sont disponibles pour les plugins utilisant ce module.

Initialisation

use Munin::Plugin::Pgsql;
my $pg = Munin::Plugin::Pgsql->new(
   parametre=>valeur,
   parametre=>valeur
);

Paramètres

minversion     Version PostgreSQL minimale requise, formatée comme 8.2. Si la
               base de données est une version antérieure, le plugin se terminera
               avec une erreur.
category       La catégorie de ce plugin. Copiée directement dans la sortie de
               configuration. Par défaut : 'db'.
title          Le titre de ce plugin. Copié directement dans la sortie de
               configuration.
info           Les informations de ce plugin. Copiées directement dans la sortie
               de configuration.
vlabel         L'étiquette verticale pour le graphique. Copiée directement dans
               la sortie de configuration.
basename       Pour les plugins wildcard, c'est le nom de base du plugin,
               incluant le trait de soulignement final.
basequery      Requête SQL exécutée pour obtenir les valeurs du plugin. La requête
               doit retourner deux colonnes, l'une étant le nom du compteur et
               la seconde la valeur actuelle du compteur.
pivotquery     Mis à 1 pour indiquer que la requête dans basequery retourne une
               seule ligne, avec un champ pour chaque compteur. Le nom du compteur
               est pris du nom de la colonne retournée, et la valeur de la
               première ligne du résultat.
configquery    Requête SQL exécutée pour générer les informations de
               configuration pour le plugin. La requête doit retourner au moins
               deux colonnes, qui sont le nom du compteur et l'étiquette du
               compteur. Si une troisième colonne est présente, elle sera
               utilisée comme paramètre d'information.
suggestquery   Requête SQL à exécuter pour générer la liste des suggestions pour
               un plugin wildcard. N'oubliez pas d'inclure ALL si le plugin
               prend en charge les statistiques agrégées.
autoconfquery  Requête SQL à exécuter comme dernière étape de "autoconf", pour
               déterminer si le plugin doit être exécuté sur cette machine. Doit
               retourner une seule ligne, deux colonnes. La première est un champ
               booléen représentant oui ou non, la seconde une raison pour "non".
warning        Les seuils d'alerte bas et/ou hauts.
critical       Les seuils critiques bas et/ou hauts.
graphdraw      Le paramètre draw pour le graphique. Par défaut : LINE1.
graphtype      Le paramètre type pour le graphique. Par défaut : GAUGE.
graphperiod    La période pour le graphique. Copiée directement dans la sortie de
               configuration.
graphmin       Le paramètre min pour le graphique. Par défaut : pas de minimum.
graphmax       Le paramètre max pour le graphique. Par défaut : pas de maximum.
stack          Si défini à 1, tous les compteurs sauf le premier seront écrits avec
               un type de dessin STACK.
base           Utilisé pour graph_args --base. Par défaut : 1000, mis à 1024 lors
               du retour de tailles en Ko par exemple.
wildcardfilter Le SQL à substituer lors de l'exécution d'un plugin wildcard contre
               une entité spécifique, par exemple une base de données. Toutes les
               occurrences de la chaîne %%FILTER%% seront remplacées par cette
               chaîne, et pour chaque occurrence un paramètre avec la valeur de la
               condition de filtrage sera ajouté à l'instruction DBI.
paramdatabase  Fait en sorte que le plugin se connecte à la base de données dans le
               premier paramètre (plugins wildcard uniquement) au lieu de
               'template1'.
defaultdb      Fait en sorte que le plugin se connecte à la base de données spécifiée
               dans ce paramètre au lieu de 'template1'.
extraconfig    Cette chaîne est copiée directement dans la sortie de configuration
               lorsque le plugin est exécuté en mode configuration, permettant une
               personnalisation de bas niveau.
postprocess    Une fonction qui est appelée avec le résultat de la requête de base,
               et qui peut post-traiter le résultat et retourner un nouvel
               ensemble de résultats.
postconfig     Une fonction qui est appelée avec le résultat de la requête de
               configuration, et qui peut post-traiter le résultat et retourner
               un nouvel ensemble de résultats.
postautoconf   Une fonction qui est appelée avec le résultat de la requête
               autoconf, et qui peut post-traiter le résultat et retourner un
               nouvel ensemble de résultats.
postsuggest    Une fonction qui est appelée avec le résultat de la requête suggest,
               et qui peut post-traiter le résultat et retourner un nouvel
               ensemble de résultats.

Spécification des requêtes

Les requêtes spécifiées dans l'un des paramètres ci-dessus peuvent prendre l'une des deux formes. La plus simple est une chaîne de caractères, qui sera alors toujours exécutée, quelle que soit la version du serveur. L'autre forme est un tableau, ressemblant à ceci :
[
"SELECT 'default',... FROM ...",
[
"8.3", "SELECT 'requête pour 8.3 ou antérieur',... FROM ...",
"8.1", "SELECT 'requête pour 8.1 ou antérieur',... FROM ..."
]
] Ce tableau est analysé de haut en bas, donc les entrées doivent être dans l'ordre des numéros de version. La *dernière* valeur trouvée où la version spécifiée est supérieure ou égale à la version du serveur sera utilisée (oui, ça compte à l'envers).

Traitement

$pg->Process();
Cette commande exécute le plugin. Elle analysera automatiquement le tableau ARGV
pour les commandes données par Munin.
