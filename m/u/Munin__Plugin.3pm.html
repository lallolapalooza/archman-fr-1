NOM

Munin::Plugin - Fonctions utilitaires pour les plugins Perl de Munin.

Usage

use lib $ENV{'MUNIN_LIBDIR'};
use Munin::Plugin;

Si votre installation de Munin est antérieure aux variables d'environnement MUNIN_* (introduites dans la version 1.3.3), vous pouvez ajouter ceci dans la configuration de votre plugin :

[*]
    env.MUNIN_PLUGSTATE /var/lib/munin-node/plugin-state
    env.MUNIN_LIBDIR /usr/share\200b/munin

SI, en effet, c'est le répertoire d'état des plugins de munin. Le répertoire d'installation par défaut de Munin::Plugin se trouve dans le chemin de recherche des modules de Perl, le "use lib" est là pour les cas où ce n'est pas le cas, et la variable doit être définie pour éviter que Perl ne se plaigne.

Le module exporte les fonctions suivantes : clean_fieldname, set_state_name, save_state, restore_state, tail_open, tail_close.

Variables

Le module instancie un certain nombre de variables dans le scope $Munin::Plugin. Aucune de celles-ci n'est exportée, et elles doivent être référencées par leurs noms complets tels qu'indiqués ici.

$Munin::Plugin::me

Le nom du plugin sans aucun préfixe de répertoire, etc. Identique à "basename $0" dans un shell. Il est fortement conseillé d'utiliser ceci dans les messages d'avertissement et/ou d'erreur afin que les logs indiquent clairement de quel plugin provient le message d'erreur.

$Munin::Plugin::pluginstatedir

Identique à la variable d'environnement MUNIN_PLUGSTATE (disponible depuis Munin 1.3.3)

Vous pouvez l'utiliser si vous avez besoin de sauvegarder plusieurs fichiers d'état différents. Mais il existe également une fonction pour changer le nom du fichier d'état afin que les fonctions de support de fichier d'état puissent être utilisées pour plusieurs fichiers d'état.

Si sa valeur ne peut être déterminée, le plugin sera immédiatement abandonné avec un message explicatif. Les causes les plus probables sont :

  • Vous exécutez le plugin directement et non depuis munin-node ou munin-run ;
  • Votre munin-node est trop ancien ;
  • munin-node a été mal installé.

Les deux derniers points peuvent être contournés par la configuration du plugin présentée au début de ce document.

$Munin::Plugin::statefile

Le nom calculé automatiquement pour le fichier d'état du plugin. Le nom est fourni par munin-node ou munin-run (dans la variable d'environnement MUNIN_STATEFILE). Le nom du fichier contient le nom du plugin et l'adresse IP du munin-master auquel le nœud parle (munin-run laisse la partie maître vide). Ceci permet aux plugins d'état qui calculent des jauges et supposent un intervalle d'exécution de 5 minutes de fonctionner correctement dans des configurations avec plusieurs maîtres (ce n'est pas une façon inhabituelle de configurer Munin).

Pour modifier la valeur de ceci, veuillez utiliser la procédure set_state_name($) (voir ci-dessous).

$Munin::Plugin::DEBUG

Mis à vrai si le plugin doit émettre des sorties de débogage. Il y a quelques (mais pas beaucoup) instructions d'impression de débogage dans le Module également, qui obéissent toutes à cette variable. Défini à partir de la variable d'environnement MUNIN_DEBUG. Par défaut, il est faux (0).

Fonctions

$fieldname = clean_fieldname($input_fieldname)

Les noms de champs des plugins Munin sont restreints quant aux caractères qu'ils peuvent utiliser : les caractères doivent être "[a-zA-Z0-9_]", tandis que le premier caractère doit être "[a-zA-Z_]". Pour satisfaire ces exigences, la fonction remplace les caractères illégaux par un '_'.

Voir aussi http://munin-monitoring.org/wiki/notes_on_datasource_names

set_state_name($statefile_name)

Remplace le nom de fichier d'état par défaut. Ceci ne modifie que la partie nom de fichier, pas le nom du répertoire. La fonction ajoute inconditionnellement "-$MUNIN_MASTER_IP" au nom de fichier pour prendre en charge plusieurs maîtres comme décrit dans la documentation de la variable de fichier d'état (ci-dessus).

L'appel de cette fonction n'est normalement pas nécessaire et n'est pas recommandé.

save_state(@state_vector)

Sauvegarde le vecteur d'état passé dans le fichier d'état approprié pour le plugin. Le vecteur d'état ne doit contenir que des chaînes (ou des nombres), et absolument aucun objet ou référence. Les chaînes peuvent contenir des sauts de ligne sans effet négatif.

Si le fichier ne peut pas être ouvert en écriture, le plugin sera abandonné.

Le nom du fichier d'état est déterminé automatiquement en fonction du nom du processus que nous exécutons. Voir $Munin::Plugin::me, $Munin::Plugin::statefile et set_state_name ci-dessus concernant le nom du fichier.

Le fichier contiendra une ligne de départ avec un nombre magique afin que la bibliothèque puisse faire la différence entre un véritable fichier d'état et un fichier contenant des déchets. Actuellement, ce nombre magique est '%MUNIN-STATE1.0\n'. Les fichiers avec ce nombre magique contiendront le vecteur tel quel, avec les caractères \r, \n et % encodés en URL.

La fonction prend des précautions de sécurité, comme protester fatalement si le fichier d'état est un lien symbolique (l'écrasement de liens symboliques peut avoir des implications de sécurité malencontreuses).

@state_vector = restore_state()

Lit l'état du fichier d'état écrit par save_state(@). Si tout est correct, le vecteur d'état sera retourné.

undef sera retourné si le fichier ne peut pas être ouvert. De même s'il n'a pas de nombre magique reconnu (dans ce cas, un avertissement sera également imprimé, qui apparaîtra dans les journaux de munin-node).

($warning, $critical) = get_thresholds($field, [$warning_env, [$critical_env]])

Recherche les seuils pour le champ spécifié à partir des variables d'environnement nommées d'après le champ : "$field_warning" et "$field_critical". Retourne leurs valeurs. S'il n'y a pas de valeurs $field_warning ou $field_critical, recherche alors les variables "warning" et "critical" et retourne leurs valeurs s'il y en a.

Si le deuxième et/ou troisième arguments sont spécifiés, ils seront utilisés pour spécifier le nom des variables donnant les niveaux d'avertissement et critique.

Si aucune valeur n'est trouvée pour un seuil, undef est retourné.

print_thresholds($field, [$warning_env, [$critical_env]])

Si $field a des seuils d'avertissement ou critiques définis pour lui, les imprime de la manière par défaut (par exemple, 'field.warning 42').

Voir get_thresholds pour une explication des arguments.

adjust_threshold($threshold, $base)

Si $threshold contient des signes %, retourne un nouveau seuil avec des valeurs ajustées pour ces pourcentages par rapport à $base.

($file_handle,$rotated) = tail_open($file_name, $position)

Ouvre le fichier et se positionne à la position donnée. Si cette position est au-delà de la fin du fichier, la fonction suppose que le fichier a été pivoté et que la position du fichier sera au début du fichier.

Si le fichier est ouvert correctement, la fonction retourne un tuple composé du descripteur de fichier et d'un indicateur de rotation de fichier. $rotated sera 1 si le fichier a été pivoté et 0 sinon. De plus, si le fichier a été pivoté, un avertissement est imprimé (uniquement en mode débogage, cela peut être trouvé dans le journal de munin-node ou vu dans le terminal lors de l'utilisation de munin-run).

À ce stade, le plugin peut lire dans le fichier avec <$file_handle> en boucle comme d'habitude jusqu'à ce que la fin du fichier soit atteinte.

Si le fichier ne peut pas être staté "(undef,undef)" est retourné. Si le fichier ne peut pas être ouvert en lecture, le plugin est abandonné avec une erreur dans un souci de clarté des erreurs.

$position = tail_close($file_handle)

Ferme le fichier et retourne la position actuelle dans le fichier. Cette position peut être stockée dans un fichier d'état jusqu'à la prochaine exécution du plugin.

Si l'appel système "close" échoue, un avertissement sera imprimé (qui peut être trouvé dans le journal de munin-node ou vu lors de l'utilisation de munin-run).

$string = scaleNumber($number, $unit, $ifZero, $ifNotZero)

Cette fonction est utilisée pour formater des nombres avec des unités appropriées. Si $number est zéro, elle retourne $ifZero, sinon elle retourne $ifNotZero. Les arguments $unit, $ifZero, et $ifNotZero peuvent être des chaînes ou des sous-routines.

Retourne une représentation textuelle du nombre donné, mis à l'échelle avec des préfixes SI tels que G(iga), M(ega), et k(ilo), m(illi), u (pour micro) et ainsi de suite pour des magnitudes allant de 10^-24 à 10^24.

La variable $unit est l'unité de base pour le nombre et est ajoutée au préfixe.

Le contenu de $ifZero est utilisé si le nombre est 0 (inférieur à 10^-26), au lieu de toute autre chaîne. Dans certains contextes, "" (une chaîne vide) est le plus approprié et parfois "0" sans aucune échelle ni préfixe est plus approprié.

$format peut être une chaîne de format printf Perl valide. La valeur par défaut est "%.1f%s%s".

$format peut être spécifié comme une chaîne entière telle que "La vitesse de l'interface est de %.1f%s%s.". Dans ce cas, $ifZero pourrait être défini sur "L'interface est inactive" -- certains équipements utilisent une vitesse d'interface de 0 pour une interface inactive, et d'autres non.

need_multigraph()

Doit être appelée en haut de tous les plugins multigraphiques.

Vérifie l'environnement actuel et se termine avec la sortie appropriée s'il ne prend pas en charge les plugins multigraphiques.

Tests

Il y a du matériel de test dans ce module.

Testez comme ceci :
MUNIN_PLUGSTATE=/var/lib/munin-node/plugin-state -e 'require "Plugin.pm.in"; Munin::Plugin::_test;' -- ou quelque chose de similaire.
sub _test () {
  my $pos;
  my $fh;
  my $reset;
  warn "Test de la queue et du fichier d'état. Appuyez sur ^C pour arrêter\n";
  do {
      $pos = undef;
      ($pos) = restore_state();
      $pos = 0 unless defined($pos);
      ($fh,$reset) = tail_open('/var/log/messages',$pos);
      while (<$fh>) {
          print;
      }
      $pos = tail_close($fh);
      print "**La position est $pos\n";
      save_state($pos);
  } while sleep 1;
}
