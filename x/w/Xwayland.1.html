XWAYLAND(1) Manuel des commandes générales XWAYLAND(1)

NOM

Xwayland - un serveur X pour exécuter des clients X sous Wayland.

SYNTAXE

Xwayland [option ...]

DESCRIPTION

Xwayland est un serveur X et un client Wayland. Il joue le rôle de proxy entre les clients X hérités qui ne supportent pas les protocoles Wayland et le serveur Wayland.

Généralement, Xwayland est lancé automatiquement par le serveur Wayland et fonctionne sans privilèges (rootless) afin que les clients X s'intègrent de manière transparente avec le reste du bureau Wayland. Il est cependant possible pour un utilisateur de lancer Xwayland avec privilèges, principalement à des fins de test.

Comme tous les serveurs X, Xwayland accepte les options de ligne de commande décrites dans la page de manuel de Xserver(7). Les arguments supplémentaires suivants sont également pris en charge.

-decorate
Ajoute des décorations à la fenêtre racine Xwayland lors de l'exécution avec privilèges (rootful).

Cette option n'a aucun effet si Xwayland est compilé sans le support de libdecor (optionnel).

Cette option n'est pas compatible avec le mode sans privilèges (-rootless).

-enable-ei-portal
Active le support du portail XDG pour l'émulation d'entrée.

Un compositeur Wayland exécutant en mode imbriqué ne devrait pas utiliser cette option de ligne de commande avec Xwayland.

Cette option n'a aucun effet si le compositeur ne supporte pas le portail XDG pertinent ou si Xwayland n'a pas été compilé avec le support EI et OEFFIS.

-fullscreen
Met la fenêtre Xwayland en plein écran lors de l'exécution avec privilèges (rootful).

Cette option n'est pas compatible avec le mode sans privilèges (-rootless).

-geometry LxH
Définit la géométrie de la fenêtre Xwayland à LxH lors de l'exécution avec privilèges (rootful).

Cette option n'est pas compatible avec le mode sans privilèges (-rootless).

-glamor [gl|es|off]
Utilise l'API de rendu donnée pour l'accélération Glamor. Les options possibles sont gl et es. Si Xwayland a été compilé avec le support Glamor, cette option demandera à Xwayland d'utiliser uniquement l'API demandée pour Glamor. Si elle est définie sur off, l'effet est équivalent à l'option -shm. Sans cette option et sans l'option -shm, Xwayland essaie d'abord l'API de rendu OpenGL, puis se rabat sur GL ES si la version GL est inférieure à 2.1.

Cette option n'est pas compatible avec l'option -shm.

-hidpi
S'adapte à l'échelle des sorties lors de l'exécution avec privilèges (rootful) en mode fenêtre.

Cette option n'est pas compatible avec le mode sans privilèges (-rootless).

-host-grab
Désactive les raccourcis clavier de l'hôte et confine le pointeur lors de l'exécution avec privilèges (rootful).

Cette fonctionnalité repose sur le protocole d'inhibition des raccourcis clavier du compositeur et sur le protocole de verrouillage et de confinement du pointeur, et peut n'avoir aucun effet si le compositeur Wayland utilisé ne supporte pas ces protocoles.

Utilisez les touches [CTRL]+[SHIFT] simultanément pour libérer les périphériques clavier et pointeur.

Cette option n'est pas compatible avec le mode sans privilèges (-rootless).

-initfd fd
Ajoute le fd donné comme socket d'écoute pour l'initialisation des clients X. Cette option est destinée aux serveurs Wayland qui exécutent Xwayland à la demande, afin de pouvoir lancer des clients X spécifiques qui doivent être terminés avant que d'autres clients X réguliers puissent se connecter à Xwayland, comme xrdb.
-listen fd
Obsolète, utilisez -listenfd à la place.
-listenfd fd
Ajoute le fd donné comme socket d'écoute. Cette option est utilisée par le serveur Wayland pour passer au Xwayland le socket auquel les clients X se connectent.
-noTouchPointerEmulation
Désactive l'émulation de pointeur tactile. Cela permet au compositeur Wayland d'implémenter son propre mécanisme d'émulation de pointeur pour les clients X11 qui ne supportent pas l'entrée tactile.
-force-xrandr-emulation
Force des modes supplémentaires non natifs à être exposés lorsque le visualiseur (viewporter) n'est pas supporté par le compositeur Wayland.
-nokeymap
Indique à Xwayland d'ignorer la table des clés (keymap) définie par le compositeur Wayland.

Par défaut, Xwayland (comme tout client Wayland) utilise la table des clés définie par le compositeur Wayland via le protocole Wayland standard.

Cette option est destinée à certains cas d'utilisation spécifiques où il peut être souhaitable de laisser les clients X11 contrôler la table des clés utilisée dans Xwayland, en ignorant la table des clés spécifiée par le compositeur Wayland. -output nom Spécifie sur quelle sortie Xwayland en plein écran avec privilèges (rootful) doit être placé. Le nom doit correspondre au nom d'une sortie Wayland existante (les noms de sortie peuvent être trouvés en utilisant wayland-info).

Si aucune sortie correspondante ne peut être trouvée, le compositeur Wayland décidera sur quelle sortie la fenêtre Xwayland en plein écran avec privilèges sera placée.

Cette option n'a aucun effet si Xwayland n'est pas exécuté en plein écran avec privilèges.

-rootless
Exécute Xwayland sans privilèges (rootless), afin que les clients X s'intègrent de manière transparente avec les clients Wayland dans un bureau Wayland. Cela nécessite que le serveur Wayland soit également un gestionnaire de fenêtres X.
-shm
Force le backend de mémoire partagée (shared memory) au lieu de glamor (si disponible) pour passer les tampons au serveur Wayland.

Cette option n'est pas compatible avec l'option -glamor.

-verbose [n]
Définit le niveau de verbosité pour les informations imprimées sur stderr. Si la valeur n n'est pas fournie, chaque occurrence de cette option incrémente le niveau de verbosité. Lorsque la valeur n est fournie, le niveau de verbosité est défini à cette valeur. Le niveau de verbosité par défaut est 0.
-version
Affiche la version du serveur et quitte.
-wm fd
Cette option est utilisée par le serveur Wayland pour passer au Xwayland le socket auquel le client gestionnaire de fenêtres X se connecte, lorsque Xwayland s'exécute avec -rootless.

ENVIRONNEMENT

WAYLAND_DISPLAY
le nom de l'affichage du serveur Wayland.
XWAYLAND_NO_GLAMOR
désactive glamor et le support DRI3 dans Xwayland, à des fins de test.
