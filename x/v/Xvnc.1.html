Xvnc(1) Virtual Network Computing Xvnc(1)

NOM

Xvnc - le serveur X VNC (Virtual Network Computing)

SYNTAXE

Xvnc [options] :numéro_affichage

DESCRIPTION

Xvnc est le serveur X VNC (Virtual Network Computing). Il est basé sur un serveur X standard, mais il possède un écran "virtuel" plutôt qu'un écran physique. Les applications X s'affichent dessus comme s'il s'agissait d'un écran X normal, mais elles ne sont accessibles que via un spectateur VNC - voir vncviewer(1).

Ainsi, Xvnc est en réalité deux serveurs en un. Pour les applications, c'est un serveur X, et pour les utilisateurs VNC distants, c'est un serveur VNC. Par convention, nous avons fait en sorte que le numéro d'affichage du serveur VNC soit le même que celui du serveur X, ce qui signifie que vous pouvez utiliser par exemple snoopy:2 pour désigner l'affichage 2 sur la machine "snoopy" dans le monde X et dans le monde VNC.

La meilleure façon de lancer Xvnc est via vncsession. Ceci configure l'environnement de manière appropriée et lance un environnement de bureau. Voir la page de manuel de vncsession(8) pour plus d'informations.

OPTIONS

Xvnc prend de nombreuses options - lancer Xvnc -help donne une liste. Beaucoup de ces options sont des options standard du serveur X, qui sont décrites dans la page de manuel Xserver(1). En plus des options qui ne peuvent être définies que via la ligne de commande, il existe également des "paramètres" qui peuvent être définis à la fois via la ligne de commande et via le programme vncconfig(1).

-depth profondeur
Spécifie la profondeur de pixels en bits du bureau à créer. La valeur par défaut est 24, les autres valeurs possibles sont 16 et 32. Toute autre valeur est susceptible de provoquer un comportement étrange de la part des applications et peut empêcher le démarrage du serveur.
-geometry largeurxhauteur
Spécifie la taille du bureau à créer. La valeur par défaut est 1024x768.
-help
Liste toutes les options et tous les paramètres
-inetd
Ceci modifie considérablement le comportement de Xvnc afin qu'il puisse être lancé depuis inetd. Voir la section ci-dessous sur l'utilisation avec inetd.
-pixelformat format
Spécifie le format de pixel que le serveur doit utiliser (BGRnnn ou RGBnnn). La valeur par défaut pour la profondeur 16 est RGB565 et pour les profondeurs 24 et 32 est RGB888.
-rendernode chemin
Nœud de rendu DRM à utiliser pour l'accélération GPU DRI3. Spécifiez un chemin vide pour désactiver DRI3. La valeur par défaut est auto, ce qui permet à Xvnc de choisir un nœud de rendu disponible approprié.

PARAMETRES

Les paramètres VNC peuvent être définis à la fois via la ligne de commande et via le programme vncconfig(1), et avec un serveur Xorg compatible VNC via les entrées Options dans le fichier xorg.conf.

Les paramètres peuvent être activés avec -paramètre ou désactivés avec -paramètre=0. Les paramètres qui prennent une valeur peuvent être spécifiés comme -paramètre valeur. D'autres formes valides sont paramètre=valeur -paramètre=valeur --paramètre=valeur. Les noms de paramètres ne sont pas sensibles à la casse.

-AcceptCutText
Accepter les mises à jour du presse-papiers provenant des clients. Activé par défaut.
-AcceptKeyEvents
Accepter les événements de pression et de relâchement de touche provenant des clients. Activé par défaut.
-AcceptPointerEvents
Accepter les événements de mouvement du pointeur et de clic de bouton provenant des clients. Activé par défaut.
-AcceptSetDesktopSize
Accepter les requêtes de redimensionnement du bureau. Activé par défaut.
-AllowOverride
Liste séparée par des virgules des paramètres qui peuvent être modifiés en utilisant l'extension VNC. Les paramètres peuvent être modifiés, par exemple, en utilisant le programme vncconfig(1) depuis une session en cours.
-AlwaysShared
Traiter toujours les connexions entrantes comme partagées, indépendamment du paramètre spécifié par le client. Désactivé par défaut.
-AvoidShiftNumLock
Les touches affectées par Verrouillage Majuscule nécessitent souvent l'insertion d'une fausse Majuscule pour générer le symbole correct. L'activation de cette option évite ces événements de fausse Majuscule supplémentaires, mais peut résulter en un symbole légèrement différent (par exemple, un Retour au lieu d'une touche Entrée du pavé numérique).
-BlacklistThreshold compte
Le nombre de tentatives de connexion non authentifiées autorisées depuis une hôte individuelle avant que cet hôte ne soit mis sur liste noire. La valeur par défaut est 5.
-BlacklistTimeout secondes
Le délai initial appliqué lorsqu'un hôte est mis sur liste noire pour la première fois. L'hôte ne peut pas retenter une connexion avant l'expiration du délai. La valeur par défaut est 10.
-CompareFB mode
Effectue une comparaison des pixels sur le tampon d'image pour réduire les mises à jour inutiles. Peut être soit 0 (désactivé), 1 (toujours) ou 2 (automatique). La valeur par défaut est 2.
-desktop nom-du-bureau
Chaque bureau a un nom qui peut être affiché par le spectateur. Il est par défaut "<utilisateur>@<nom-hote>".
-DisconnectClients
Déconnecter les clients existants si une connexion entrante n'est pas partagée. Activé par défaut. Si DisconnectClients est faux, alors une nouvelle connexion non partagée sera refusée pendant qu'un client est actif. Lorsqu'il est combiné avec NeverShared, cela signifie qu'un seul client est autorisé à la fois.
-FrameRate ips
Le nombre maximum de mises à jour par seconde envoyées à chaque client. Si l'écran se met à jour plus rapidement, ces changements seront agrégés et envoyés en une seule mise à jour au client. Notez que cela contrôle uniquement le taux maximum et qu'un client peut obtenir un taux inférieur lorsque les ressources sont limitées. La valeur par défaut est 60.
-GnuTLSPriority priorite
Chaîne de priorité GnuTLS qui contrôle les algorithmes de négociation de la session TLS. Voir le manuel GnuTLS pour les valeurs possibles. Pour GnuTLS < 3.6.3, la valeur par défaut sera NORMAL pour utiliser la valeur par défaut en amont. Pour les versions plus récentes de GnuTLS, la politique cryptographique globale sera utilisée.
-IdleTimeout secondes
Le nombre de secondes après lequel une connexion VNC inactive sera déconnectée. La valeur par défaut est 0, ce qui signifie que les connexions inactives ne seront jamais déconnectées.
-ImprovedHextile
Utilise un algorithme de compression amélioré pour le codage Hextile, qui atteint de meilleurs taux de compression au prix d'une utilisation légèrement plus importante du temps CPU. Activé par défaut.
-interface adresse IP
Écoute sur l'interface. Par défaut, Xvnc écoute sur toutes les interfaces disponibles.
-localhost
N'autorise que les connexions provenant de la même machine. Utile si vous utilisez SSH et que vous souhaitez empêcher les connexions non-SSH provenant d'autres hôtes.
-Log nom-journal:destination:niveau[, ...]
Configure les paramètres du journal de débogage. destination peut actuellement être stderr, stdout ou syslog, et niveau est compris entre 0 et 100, 100 signifiant une sortie la plus verbeuse. nom-journal est généralement *, signifiant tout, mais vous pouvez cibler un fichier source spécifique si vous connaissez le nom de son "LogWriter". La valeur par défaut est *:stderr:30.
-MaxConnectionTime ctionTime">-MaxConnectionTime secondes
Terminer lorsqu'un client est connecté depuis N secondes. La valeur par défaut est 0.
-MaxCutText octets
La taille maximale d'une mise à jour du presse-papiers qui sera acceptée d'un client. La valeur par défaut est 262144.
-MaxDisconnectionTime secondes
Terminer lorsqu'aucun client n'est connecté depuis N secondes. La valeur par défaut est 0.
-MaxIdleTime secondes
Terminer après N secondes d'inactivité de l'utilisateur. La valeur par défaut est 0.
-NeverShared
Ne jamais considérer les connexions entrantes comme partagées, quelle que soit la configuration spécifiée par le client. La valeur par défaut est désactivée.
-pam_service nom, -PAMService nom
Nom du service PAM à utiliser lors de l'authentification des utilisateurs à l'aide de l'un des types de sécurité « Plain ». La valeur par défaut est vnc.
-Password mot de passe
Encodage binaire obfusqué du mot de passe que les clients doivent fournir pour accéder au serveur. L'utilisation de ce paramètre est non sécurisée, utilisez le paramètre PasswordFile à la place.
-PasswordFile fichier-passwd, -rfbauth fichier-passwd
Fichier de mots de passe pour l'authentification VNC. Il n'y a pas de valeur par défaut, vous devez spécifier explicitement le fichier de mots de passe. Le fichier de mots de passe doit être créé avec l'utilitaire vncpasswd(1). Le fichier est accédé à chaque connexion entrante, il peut donc être modifié à la volée.
-PlainUsers liste d'utilisateurs
Une liste d'utilisateurs séparés par des virgules autorisés à s'authentifier via l'un des types de sécurité « Plain » (Plain, TLSPlain, etc.). Spécifiez * pour autoriser n'importe quel utilisateur à s'authentifier en utilisant ce type de sécurité. Spécifiez %u pour autoriser l'utilisateur du processus serveur. La valeur par défaut est de refuser tous les utilisateurs.
-Protocol3.3
Utiliser toujours le protocole version 3.3 pour la compatibilité descendante avec les clients mal comportés. La valeur par défaut est désactivée.
-QueryConnect
Demande à l'utilisateur du bureau d'accepter ou de refuser explicitement les connexions entrantes. La valeur par défaut est désactivée.

Le programme vncconfig(1) doit être en cours d'exécution sur le bureau pour que QueryConnect soit pris en charge.

-QueryConnectTimeout secondes
Nombre de secondes pendant lesquelles afficher la boîte de dialogue d'acceptation de connexion avant de rejeter la connexion. La valeur par défaut est 10.
-RawKeyboard
Envoie les événements du clavier directement sans les mapper à la disposition du clavier actuelle. Cela fait en sorte que le clavier se comporte effectivement selon la disposition configurée sur le serveur au lieu de la disposition configurée sur le client. La valeur par défaut est désactivée.
-RemapKeys mappage
Configure un mappage de clavier. mappage est une chaîne de caractères séparée par des virgules de mappages de caractères, chacun de la forme caractère->caractère, ou caractère<>caractère, où caractère est un keysym hexadécimal. Par exemple, pour échanger les symboles « " » et « @ », vous spécifieriez ce qui suit :
RemapKeys=0x22<>0x40
-RequireUsername
Exiger un nom d'utilisateur pour les types de sécurité RSA-AES. La valeur par défaut est désactivée.
-rfbport port
Spécifie le port TCP sur lequel Xvnc écoute les connexions des visualiseurs (le protocole utilisé dans VNC s'appelle RFB - « remote framebuffer »). La valeur par défaut est 5900 plus le numéro d'affichage. Spécifiez -1 pour désactiver l'écoute sur un port TCP.
-rfbunixmode mode
Spécifie le mode du socket de domaine Unix. La valeur par défaut est 0600.
-rfbunixpath chemin
Spécifie le chemin d'un socket de domaine Unix sur lequel Xvnc écoute les connexions des visualiseurs.
-RSAKey chemin
Chemin vers la clé RSA pour les types de sécurité RSA-AES (RA2, RA2ne, RA2_256 et RA2ne_256) au format PEM.
-SecurityTypes types de sécurité
Spécifie quel schéma de sécurité utiliser pour les connexions entrantes. Les valeurs valides sont une liste séparée par des virgules de None, VncAuth, Plain, TLSNone, TLSVnc, TLSPlain, X509None, X509Vnc, X509Plain, RA2, RA2ne, RA2_256 et RA2ne_256. La valeur par défaut est TLSVnc,VncAuth.
-SendCutText
Envoie les changements de presse-papiers aux clients. La valeur par défaut est activée.
-SendPrimary
Envoie la sélection primaire et le buffer de copie au serveur, ainsi que la sélection du presse-papiers. La valeur par défaut est activée.
-SetPrimary
Définit la sélection primaire ainsi que la sélection du presse-papiers. La valeur par défaut est activée.
-UseBlacklist
Rejette temporairement les connexions d'un hôte s'il échoue à s'authentifier de manière répétée. La valeur par défaut est activée.
-UseIPv4
Utilise IPv4 pour les connexions entrantes et sortantes. La valeur par défaut est activée.
-UseIPv6
Utilise IPv6 pour les connexions entrantes et sortantes. La valeur par défaut est activée.
-X509Cert chemin
Chemin vers un certificat X509 au format PEM à utiliser pour tous les types de sécurité basés sur X509 (X509None, X509Vnc, etc.).
-X509Key chemin
La contrepartie de la clé privée du certificat fourni dans X509Cert. Doit également être au format PEM.

Autoriser la substitution de paramètres tels que PAMService ou PasswordFile peut avoir un impact négatif sur la sécurité si Xvnc s'exécute sous un utilisateur différent de celui des programmes autorisés à substituer les paramètres.

Lorsque le paramètre NoClipboard est défini, autoriser la substitution de SendCutText et AcceptCutText n'a aucun effet.

La valeur par défaut est desktop,AcceptPointerEvents,SendCutText,AcceptCutText,SendPrimary,SetPrimary.

UTILISATION AVEC INETD

En configurant le service inetd(1) de manière appropriée, Xvnc peut être lancé à la demande lorsqu'une connexion arrive, plutôt que d'avoir à être démarré manuellement. Lorsqu'il reçoit l'option -inetd, au lieu d'écouter les connexions TCP sur un port donné, il utilise son entrée standard et sa sortie standard. Il existe deux modes contrôlés par l'entrée wait/nowait dans le fichier inetd.conf.

En mode nowait, Xvnc utilise directement son entrée et sa sortie standard comme connexion à un visualiseur. Il n'a jamais de socket d'écoute, il ne peut donc pas accepter de connexions supplémentaires de la part des visualiseurs (il peut cependant se connecter à des visualiseurs en écoute via le programme vncconfig). D'autres connexions de visualiseurs sur le même port TCP entraînent le lancement d'un nouveau Xvnc par inetd pour gérer chaque connexion. Lorsque la connexion au visualiseur prend fin, le Xvnc et tous les clients X associés meurent. Ce comportement est le plus utile lorsqu'il est combiné avec les options XDMCP -query et -once. Un exemple typique dans inetd.conf pourrait être (tout sur une seule ligne) :

5950 stream tcp nowait nobody /usr/local/bin/Xvnc Xvnc -inetd -query localhost -once securitytypes=none

Dans cet exemple, une connexion de visualiseur à :50 entraînera un nouveau Xvnc pour cette connexion, qui devrait afficher l'écran de connexion XDM standard sur cette machine. Il est généralement acceptable d'accepter les connexions sans mot de passe VNC, car l'utilisateur doit toujours se connecter via XDM dans ce cas.

En mode wait, lorsque la première connexion arrive, inetd donne le socket d'écoute à Xvnc. Cela signifie que pour un port TCP donné, il n'y a jamais qu'un seul Xvnc à la fois. Les connexions de visualiseurs supplémentaires au même port sont acceptées par le même Xvnc de manière normale. Même lorsque la connexion initiale est rompue, le Xvnc continue de fonctionner. Si cela est utilisé avec les options XDMCP -query et -once, le Xvnc et les clients X associés mourront lorsque l'utilisateur se déconnectera de la session X de manière normale. Il est important d'utiliser un mot de passe VNC dans ce cas. Une entrée typique dans inetd.conf pourrait être :

5951 stream tcp wait james /usr/local/bin/Xvnc Xvnc -inetd -query localhost -once passwordFile=/home/james/.config/tigervnc/passwd

En fait, typiquement, vous auriez une entrée pour chaque utilisateur qui utilise régulièrement VNC, chacun ayant son propre port TCP dédié qu'il utilise. Dans cet exemple, lorsque l'utilisateur « james » se connecte à :51, il entre son mot de passe VNC, puis obtient l'écran de connexion XDM où il se connecte de manière normale. Cependant, contrairement à l'exemple précédent, s'il se déconnecte, la session reste persistante, et lorsqu'il se reconnecte, il retrouve la même session. Lorsqu'il se déconnecte de la session X, le Xvnc meurt, mais bien sûr un nouveau sera créé automatiquement la prochaine fois qu'il se connectera.
