NOM

XIGrabDevice, XIUngrabDevice - saisir ou relâcher le périphérique.

SYNOPSIS

#include <X11/extensions/XInput2.h>
Status XIGrabDevice( Display *display,
                     int deviceid,
                     Window grab_window,
                     Time time,
                     Cursor cursor,
                     int grab_mode,
                     int paired_device_mode,
                     Bool owner_events,
                     XIEventMask *mask);
Status XIUngrabDevice( Display *display,
                       int deviceid,
                       Time time);
cursor
       Spécifie l'image du curseur à afficher pendant la durée
       de la saisie.
display
       Spécifie la connexion au serveur X.
deviceid
       Spécifie le périphérique qui doit être saisi ou relâché.
grab_mode, paired_device_mode
       Le mode de saisie pour ce périphérique et (si applicable)
       le périphérique associé.
grab_window
       La fenêtre de saisie.
mask
       Masque d'événements.
owner_events
       Vrai si les événements doivent être rapportés normalement.
time
       Un horodatage valide ou CurrentTime.

DESCRIPTION

XIGrabDevice saisit activement le contrôle du périphérique. Les événements
ultérieurs du périphérique ne sont rapportés qu'au client qui saisit.
XIGrabDevice annule toute saisie active par ce client.
Si le périphérique est un périphérique esclave attaché, il est
automatiquement détaché du périphérique maître et rattaché au
même périphérique maître lorsque le client relâche la saisie. Si le
périphérique maître est supprimé alors que le périphérique est flottant
à la suite d'une saisie, le périphérique reste flottant une fois la saisie
désactivée.
Si owner_events est Faux, tous les événements de périphérique générés sont
rapportés par rapport à grab_window s'ils sont sélectionnés. Si
owner_events est Vrai et si un événement de périphérique généré serait
normalement rapporté à ce client, il est rapporté normalement ; sinon,
l'événement est rapporté par rapport à la fenêtre de saisie, et n'est
rapporté que s'il est spécifié dans le masque d'événements.
Si l'argument grab_mode est XIGrabModeAsync, le traitement des événements du
périphérique continue comme d'habitude. Si le périphérique est actuellement
gelé par ce client, le traitement des événements du périphérique reprend.
Si l'argument grab_mode est XIGrabModeSync, l'état du périphérique (tel que vu
par les applications clientes) semble se figer, et le serveur X ne génère
plus d'événements de périphérique tant que le client qui saisit n'émet pas
un appel XIAllowEvents de libération ou tant que la saisie du périphérique
n'est pas relâchée. Les modifications réelles du périphérique ne sont pas
perdues pendant que le périphérique est gelé ; elles sont simplement mises en
file d'attente dans le serveur pour un traitement ultérieur.
Si paired_device_mode est XIGrabModeAsync, le traitement des événements du
périphérique maître associé est inchangé par l'activation de la saisie.
Si paired_device_mode est XIGrabModeSync, l'état du périphérique maître
associé (tel que vu par les applications clientes) semble se figer, et le
serveur X ne génère plus d'événements de ce périphérique tant que le client
qui saisit n'émet pas un appel XIAllowEvents de libération ou tant que la
saisie du périphérique n'est pas relâchée. Les événements réels ne sont pas
perdus pendant que les périphériques sont gelés ; ils sont simplement mis en
file d'attente dans le serveur pour un traitement ultérieur. Si le
périphérique est un périphérique esclave, paired_device_mode est ignoré.
Si le périphérique est activement saisi par un autre client,
XIGrabDevice échoue et retourne AlreadyGrabbed. Si grab_window n'est pas
visible, il échoue et retourne GrabNotViewable. Si le périphérique est gelé
par une saisie active d'un autre client, il échoue et retourne GrabFrozen.
Si l'heure spécifiée est antérieure à la dernière heure de saisie du
périphérique ou postérieure à l'heure actuelle du serveur X, il échoue et
retourne GrabInvalidTime. Sinon, la dernière heure de saisie du périphérique
est définie à l'heure spécifiée. CurrentTime est remplacé par l'heure
actuelle du serveur X.
Si cursor n'est pas None, ce curseur est affiché jusqu'à ce que le client
appelle XIUngrabDevice.
XIGrabDevice peut générer des erreurs BadDevice, BadValue et BadWindow.
XIUngrabDevice libère le périphérique et les événements mis en file d'attente si ce
client l'a activement saisi via XIGrabDevice ou XIGrabKey ou XIGrabButton. Si
d'autres périphériques sont gelés par la saisie, XUngrabDevice les dégèle.
XUngrabDevice ne libère pas le périphérique et les événements mis en file
d'attente si l'heure spécifiée est antérieure à la dernière heure de saisie du
périphérique ou est postérieure à l'heure actuelle du serveur X. Le serveur X
exécute automatiquement une requête XIUngrabDevice si la fenêtre d'événement
d'une saisie de périphérique active devient non visible.
XIUngrabDevice peut générer une erreur BadDevice.

DIAGNOSTICS

BadValue
       Une valeur est en dehors de la plage autorisée.
BadDevice
       Un périphérique invalide a été spécifié. Le périphérique n'existe
       pas ou n'est pas approprié pour le type de modification.
BadMatch
       La fenêtre n'est pas visible.
BadWindow
       Une valeur pour un argument de type Window ne nomme pas une Window
       définie.

BOGUES

Les en-têtes de protocole pour XI 2.0 n'ont pas fourni
XIGrabModeAsync ou XIGrabModeSync. Utilisez GrabModeSync et
GrabModeAsync respectivement.
