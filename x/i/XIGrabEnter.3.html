XIGRABENTER(3)   XIGRABENTER(3)

NOM

XIGrabEnter, XIUngrabEnter, XIGrabFocusIn, XIUngrabFocusIn - capture/libérer les événements d'entrée ou de focus.

SYNTAXE

#include <X11/extensions/XInput.h>
int XIGrabEnter( Display *display,
                 int deviceid,
                 Window grab_window,
                 Cursor cursor,
                 int grab_mode,
                 int paired_device_mode,
                 Bool owner_events,
                 XIEventMask *mask,
                 int num_modifiers,
                 XIGrabModifiers *modifiers_inout);
int XIUngrabEnter( Display *display,
                   int deviceid,
                   Window grab_window
                   int num_modifiers,
                   XIGrabModifiers *modifiers);
int XIGrabFocusIn ( Display *display,
                    int deviceid,
                    Window grab_window
                    int grab_mode,
                    int paired_device_mode,
                    Bool owner_events,
                    XIEventMask *mask,
                    int num_modifiers,
                    XIGrabModifiers *modifiers_inout);
int XIUngrabFocusIn( Display *display,
                     int deviceid,
                     Window grab_window
                     int num_modifiers,
                     XIGrabModifiers *modifiers);
display
       Spécifie la connexion au serveur X.
device
       Spécifie le périphérique qui doit être capturé ou libéré
num_modifiers
       Nombre d'éléments dans modifiers ou modifiers_inout.
modifiers
       Spécifie l'ensemble des modificateurs latches et de base ou
       XIAnyModifier pour libérer. Le type de données est pour
       la cohérence avec la requête de capture respective et le
       code d'état de la structure XIGrabModifiers est ignoré.
modifiers_inout
       Spécifie l'ensemble des modificateurs latches et de base ou
       XIAnyModifier à capturer. Retourne les modificateurs qui n'ont pas pu être capturés et leur code d'état.
grab_window
       Spécifie la fenêtre de capture.
owner_events
       Spécifie une valeur booléenne indiquant si les événements
       doivent être rapportés comme d'habitude ou rapportés par rapport à la
       fenêtre de capture.
mask
       Spécifie le masque d'événements.
grab_mode
       Spécifie le traitement ultérieur des événements de ce périphérique.
       Vous pouvez passer XIGrabModeSync ou XIGrabModeAsync.
paired_device_mode
       Spécifie le traitement ultérieur des événements du périphérique maître associé. Vous pouvez passer XIGrabModeSync ou
       XIGrabModeAsync. Si deviceid spécifie un périphérique esclave flottant, ce paramètre est ignoré.

DESCRIPTION

XIGrabEnter et XIGrabFocusIn établissent une capture passive. Le
périphérique modificateur pour une capture d'entrée est le périphérique maître associé si
deviceid spécifie un pointeur maître. Sinon, le périphérique modificateur est le périphérique spécifié avec deviceid.
Pour XIGrabEnter et XIGrabFocusIn, à l'avenir, le périphérique est capturé activement
(comme pour XIGrabDevice, l'heure de la dernière capture est
définie à l'heure à laquelle le pointeur/focus est entré dans la
fenêtre) si le périphérique n'est pas capturé et que le pointeur est entré dans
grab_window ou que le focus a été défini sur grab_window lorsque
les touches modificateurs spécifiées sont logiquement enfoncées sur le périphérique modificateur et qu'aucun autre bouton ou touche modificateur n'est logiquement enfoncé.
L'interprétation des arguments restants est la même que pour
XIGrabDevice. La capture active est automatiquement terminée lorsque
le pointeur quitte la fenêtre ou que le focus est défini sur une
fenêtre différente (indépendamment de l'état logique des
touches modificateurs).
Si le périphérique est un périphérique esclave attaché, le périphérique est
automatiquement détaché du périphérique maître lorsque la capture
s'active et ré-attaché au même périphérique maître lorsque la
capture se désactive. Si le périphérique maître est supprimé pendant que le
périphérique flotte en raison d'une capture, le périphérique reste flottant une fois la
capture désactivée.
Notez que l'état logique d'un périphérique (tel que vu par les applications clientes)
peut être en retard par rapport à l'état physique si le traitement des événements du périphérique est gelé.
Cette requête remplace toutes les captures précédentes par le même client du même type et des mêmes combinaisons de modificateurs sur la même fenêtre. Un modificateur de XIAnyModifier équivaut à émettre la requête de capture pour toutes les combinaisons de modificateurs possibles (y compris la combinaison d'aucun modificateur). Il n'est pas requis que tous les modificateurs spécifiés aient actuellement des KeyCodes assignés.
Si un autre client a déjà émis un XIGrabEnter ou XIGrabFocusIn
sur la même fenêtre, une erreur BadAccess en résulte.
Lors de l'utilisation de XIAnyModifier, la requête échoue complètement, et une
erreur XIBadAccess en résulte (aucune capture n'est établie) s'il y a une capture conflictuelle pour une combinaison quelconque. XIGrabEnter et XIGrabFocusIn n'ont aucun effet sur une capture active.
En cas de succès, XIGrabEnter et XIGrabFocusIn retournent 0 ;
Si une ou plusieurs combinaisons de modificateurs n'ont pas pu être capturées,
XIGrabEnter et XIGrabFocusIn retournent le nombre de combinaisons échouées et modifiers_inout contient les combinaisons échouées
et leurs codes d'état respectifs.
XIGrabEnter et XIGrabFocusIn peuvent générer des erreurs BadDevice,
BadMatch, BadValue et BadWindow.
XIUngrabEnter et XIUngrabFocusIn libèrent la capture passive sur
la fenêtre spécifiée si elle a été capturée par ce client. Un
modificateur de XIAnyModifier équivaut à émettre la requête de libération pour toutes les combinaisons de modificateurs possibles, y compris la combinaison d'aucun modificateur. XIUngrabEnter et XIUngrabFocusIn
n'ont aucun effet sur une capture active.
XIUngrabEnter et XIUngrabFocusIn peuvent générer des erreurs BadDevice,
BadMatch, BadValue et BadWindow.

VALEUR DE RETOUR

XIGrabEnter et XIGrabFocusIn retournent le nombre de combinaisons de modificateurs
qui n'ont pas pu établir une capture passive. Les modificateurs sont retournés dans
modifiers_inout, avec l'erreur respective pour cette combinaison de modificateurs. Si XIGrabEnter ou XIGrabFocusIn retournent zéro, les captures passives avec toutes les combinaisons de modificateurs demandées ont été établies avec succès.

DIAGNOSTICS

BadDevice
       Un deviceid invalide a été spécifié.
BadMatch
       Cette erreur peut survenir si XIGrabEnter a spécifié un périphérique
       qui n'a pas de valueurs, ou XIGrabFocusIn a spécifié un périphérique
       qui n'a pas de touches.
BadValue
       Une valeur numérique se trouve en dehors de la plage de valeurs
       acceptées par la requête. Sauf si une plage spécifique est
       spécifiée pour un argument, la plage complète définie par le
       type de l'argument est acceptée. Tout argument défini comme un
       ensemble d'alternatives peut générer cette erreur.
BadWindow
       Une valeur pour un argument Window ne nomme pas une fenêtre définie.

BOGUES

Les en-têtes de protocole pour XI 2.0 n'ont pas fourni
XIGrabModeAsync ou XIGrabModeSync. Utilisez GrabModeSync et
GrabModeAsync respectivement.
