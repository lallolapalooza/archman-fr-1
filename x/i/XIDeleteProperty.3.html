XICHANGEPROPERTY(3)   XICHANGEPROPERTY(3)

NOM

XIChangeProperty, XIGetProperty, XIDeleteProperty - changer, récupérer ou supprimer une propriété d'un périphérique.

SYNTAXE

#include <X11/extensions/XInput2.h>
void XIChangeProperty( Display* dpy,
                       int deviceid,
                       Atom property,
                       Atom type,
                       int format,
                       int mode,
                       unsigned char *data,
                       int num_items)
void XIDeleteProperty( Display *dpy,
                       int deviceid,
                       Atom property)
Status XIGetProperty( Display *dpy,
                      int deviceid,
                      Atom property,
                      long offset,
                      long length,
                      Bool delete_property,
                      Atom type,
                      Atom *type_return,
                      int *format_return,
                      unsigned long *num_items_return,
                      unsigned long *bytes_after_return,
                      unsigned char **data)
bytes_after_return
       Retourne le nombre d'octets restants à lire dans la propriété
       si une lecture partielle a été effectuée.
data
       Spécifie les données de la propriété.
display
       Spécifie la connexion au serveur X.
delete_property
       Spécifie une valeur booléenne qui détermine si la propriété
       doit être supprimée.
deviceid
       Le périphérique pour lequel lister les propriétés.
format
       Spécifie si les données doivent être considérées comme une liste
       de quantités de 8, 16 ou 32 bits. Les valeurs possibles sont 8,
       16 et 32. Ces informations permettent au serveur X d'effectuer
       correctement les opérations de permutation d'octets si nécessaire.
       Si le format est de 16 ou 32 bits, vous devez explicitement
       caster votre pointeur de données en (unsigned char *) dans l'appel
       à XIChangeProperty.
format_return
       Retourne le format réel de la propriété.
length
       Spécifie la longueur en multiples de 32 bits des données à
       récupérer.
offset
       Spécifie le décalage dans la propriété spécifiée (en quantités
       de 32 bits) où les données doivent être récupérées.
mode
       L'un des XIPropModeAppend, XIPropModePrepend ou XIPropModeReplace.
num_items
       Nombre d'éléments dans data selon le format spécifié.
nitems_return
       Retourne le nombre réel d'éléments de 8, 16 ou 32 bits
       stockés dans data.
property
       Spécifie le nom de la propriété.
type
       Spécifie le type de la propriété. Le serveur X n'interprète pas
       le type mais le renvoie à une application qui appelle ultérieurement
       XIGetProperty.
type_return
       Retourne l'identifiant d'atome qui définit le type réel de la
       propriété.

DESCRIPTION

La fonction XIGetProperty renvoie le type réel de la propriété ; le format réel de la propriété ; le nombre d'éléments de 8, 16 ou 32 bits transférés ; le nombre d'octets restants à lire dans la propriété ; et un pointeur vers les données réellement retournées. XIGetProperty définit les arguments de retour comme suit :

•Si la propriété spécifiée n'existe pas pour le périphérique spécifié, XIGetProperty renvoie None à actual_type_return et la valeur zéro à actual_format_return et bytes_after_return. L'argument nitems_return est vide. Dans ce cas, l'argument delete est ignoré.
•Si la propriété spécifiée existe mais que son type ne correspond pas au type spécifié, XIGetProperty renvoie le type réel de la propriété à actual_type_return, le format réel de la propriété (jamais zéro) à actual_format_return, et la longueur de la propriété en octets (même si actual_format_return est 16 ou 32) à bytes_after_return. Il ignore également l'argument delete. L'argument nitems_return est vide.
•Si la propriété spécifiée existe et que vous affectez XIAnyPropertyType à l'argument req_type ou que le type spécifié correspond au type réel de la propriété, XIGetProperty renvoie le type réel de la propriété à actual_type_return et le format réel de la propriété (jamais zéro) à actual_format_return. Il renvoie également une valeur à bytes_after_return et nitems_return, en définissant les valeurs suivantes : 
N = longueur de la propriété stockée en octets
I = 4 * offset
T = N - I
L = MINIMUM(T, 4 * length)
A = N - (I + L)

La valeur retournée commence à l'indice d'octet I dans la propriété (indexation à partir de zéro), et sa longueur en octets est L. Si la valeur de long_offset rend L négatif, une erreur BadValue se produit. La valeur de bytes_after_return est A, indiquant le nombre d'octets non lus à la fin de la propriété stockée.

Si le format retourné est 8, les données retournées sont représentées comme un tableau de char. Si le format retourné est 16, les données retournées sont représentées comme un tableau de uint16_t et doivent être castées dans ce type pour obtenir les éléments. Si le format retourné est 32, les données retournées sont représentées comme un tableau de uint32_t et doivent être castées dans ce type pour obtenir les éléments.

XIGetProperty alloue toujours un octet supplémentaire dans prop_return (même si la propriété est de longueur zéro) et le met à zéro afin que les propriétés simples composées de caractères n'aient pas besoin d'être copiées dans une chaîne supplémentaire avant utilisation.

Si delete est True et que bytes_after_return est zéro, XIGetProperty supprime la propriété de la fenêtre et génère un événement XIPropertyNotify sur la fenêtre.

La fonction renvoie Success si elle s'exécute avec succès. Pour libérer les données résultantes, utilisez XFree.

XIGetProperty peut générer des erreurs BadAtom, BadValue et BadWindow.

La fonction XIChangeProperty modifie la propriété pour le périphérique spécifié et provoque l'envoi d'un événement XIPropertyNotify pour ce périphérique par le serveur X. XIChangeProperty effectue les opérations suivantes :

•Si le mode est XIPropModeReplace, XIChangeProperty rejette la valeur précédente de la propriété et stocke les nouvelles données.
•Si le mode est XIPropModePrepend ou XIPropModeAppend, XIChangeProperty insère les données spécifiées avant le début des données existantes ou à la fin des données existantes, respectivement. Le type et le format doivent correspondre à la valeur existante de la propriété, sinon une erreur BadMatch se produit. Si la propriété est indéfinie, elle est traitée comme définie avec le type et le format corrects avec des données de longueur zéro.

Si le format spécifié est 8, les données de la propriété doivent être un tableau de char. Si le format spécifié est 16, les données de la propriété doivent être un tableau de uint16_t. Si le format spécifié est 32, les données de la propriété doivent être un tableau de uint32_t.

La durée de vie d'une propriété n'est pas liée au client qui la stocke. Les propriétés persistent jusqu'à ce qu'elles soient explicitement supprimées, jusqu'à ce que le périphérique soit supprimé, ou jusqu'à ce que le serveur soit réinitialisé. La taille maximale d'une propriété dépend du serveur et peut varier dynamiquement en fonction de la mémoire disponible pour le serveur. (En cas d'espace insuffisant, une erreur BadAlloc se produit.)

XIChangeProperty peut générer des erreurs BadAlloc, BadAtom, BadMatch, BadValue et BadDevice.

La fonction XIDeleteProperty supprime la propriété spécifiée uniquement si la propriété était définie sur le périphérique spécifié et provoque l'envoi d'un événement XIPropertyNotify pour le périphérique par le serveur X, sauf si la propriété n'existe pas.

XIDeleteProperty peut générer des erreurs BadAtom et BadDevice.

DIAGNOSTICS

BadAlloc Le serveur n'a pas pu allouer la ressource demandée ou la mémoire du serveur.

BadAtom Une valeur pour un argument Atom ne nomme pas un Atom défini.

BadValue Une valeur numérique tombe en dehors de la plage de valeurs acceptées par la requête. Sauf si une plage spécifique est spécifiée pour un argument, la plage complète définie par le type de l'argument est acceptée. Tout argument défini comme un ensemble d'alternatives peut générer cette erreur.

BadDevice Un périphérique invalide a été spécifié. Le périphérique n'existe pas.

BadAtom Une propriété invalide a été spécifiée. La propriété n'existe pas.

BOGUES

Les en-têtes de protocole pour XI 2.0 n'ont pas fourni
XIAnyPropertyType, XIPropModeReplace, XIPropModePrepend ou
XIPropModeAppend. Utilisez respectivement AnyPropertyType,
PropModeReplace, PropModePrepend et PropModeAppend à la place.
