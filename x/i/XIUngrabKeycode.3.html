display
       Spécifie la connexion au serveur X.

       Spécifie le périphérique qui doit être saisi ou libéré

grab_window
       Spécifie la fenêtre de saisie.

mask
       Spécifie le masque d'événements.
grab_mode
       Spécifie le traitement ultérieur des événements de ce périphérique.

paired_device_mode
       Spécifie le traitement ultérieur des événements du périphérique maître associé.
       Vous pouvez passer XIGrabModeSync ou XIGrabModeAsync. Si deviceid
       spécifie un périphérique esclave flottant, ce paramètre est ignoré.

DESCRIPTION

XIGrabButton, XIGrabKeycode, XIGrabTouchBegin, XIGrabPinchGestureBegin,
XIGrabSwipeTouchBegin établissent une saisie passive.
Le périphérique modificateur pour une saisie de bouton est le périphérique maître associé
si deviceid spécifie un pointeur maître. Sinon, le périphérique modificateur est le
périphérique spécifié par deviceid. À l'avenir,
le périphérique est saisi activement (comme pour XIGrabDevice, l'heure de la dernière saisie
est définie à l'heure à laquelle le bouton ou le code de touche
a été pressé et l'événement XI_ButtonPress ou XI_KeyPress est
rapporté si toutes les conditions suivantes sont vraies :
  * Le périphérique n'est pas saisi, et le bouton ou le
    code de touche spécifié est logiquement pressé, un événement tactile ou de geste se produit lorsque les
    touches modificatrices spécifiées sont logiquement enfoncées sur le périphérique modificateur
    et qu'aucun autre bouton ou touche modificateur n'est logiquement enfoncé.
  * Soit la fenêtre de saisie est un ancêtre (ou est) la fenêtre de focus
    , soit la fenêtre de saisie est un descendant de la fenêtre de focus
    et contient le périphérique.
  * Aucune saisie passive sur la même combinaison bouton/modificateur
    n'existe sur un ancêtre de grab_window.
L'interprétation des arguments restants est la même que pour
XIGrabDevice. La saisie active est terminée automatiquement lorsque
l'état logique du périphérique a tous les boutons ou touches
relâchés (indépendamment de l'état logique des touches
modificatrices).
Si le périphérique est un périphérique esclave attaché, le périphérique est
automatiquement détaché du périphérique maître lorsque la saisie
s'active et rattaché au même périphérique maître lorsque la saisie
se désactive. Si le périphérique maître est retiré pendant que le
périphérique flotte en conséquence d'une saisie, le périphérique reste flottant
une fois la saisie désactivée.
Notez que l'état logique d'un périphérique (tel que vu par les applications clientes) peut être en retard par rapport à l'état physique si le traitement des événements du périphérique est gelé.
Cette requête remplace toutes les saisies précédentes par le même client sur les mêmes combinaisons de boutons/modificateurs ou de codes de touches/modificateurs sur la même fenêtre. Un modificateur de XIAnyModifier équivaut à émettre la requête de saisie pour toutes les combinaisons de modificateurs possibles (y compris la combinaison d'aucun modificateur). Il n'est pas nécessaire que tous les modificateurs spécifiés aient actuellement des KeyCodes assignés. Un bouton de XIAnyButton équivaut à émettre la requête pour tous les boutons possibles. Sinon, il n'est pas nécessaire que le bouton spécifié soit actuellement assigné à un bouton physique.
Si un autre client a déjà émis un XIGrabButton ou
XIGrabKeycode avec la même combinaison bouton/modificateur ou code de touche/modificateur
sur la même fenêtre, une erreur BadAccess en résulte. Lors de l'utilisation de XIAnyModifier ou XIAnyButton, la requête échoue complètement et une erreur XIBadAccess en résulte (aucune saisie n'est établie) s'il existe une saisie conflictuelle pour une combinaison quelconque. XIGrabButton et XIGrabKeycode n'ont aucun effet sur une saisie active.
En cas de succès, XIGrabButton, XIGrabKeycode, XIGrabTouchBegin,
XIGrabPinchGestureBegin et XIGrabSwipeGestureBegin retournent 0 ;
Si une ou plusieurs combinaisons de modificateurs n'ont pas pu être saisies,
XIGrabButton, XIGrabKeycode, XIGrabTouchBegin, XIGrabPinchGestureBegin
et XIGrabSwipeGestureBegin retournent le nombre de
combinaisons échouées et modifiers_inout contient les combinaisons échouées
et leurs codes d'erreur respectifs.
XIGrabButton, XIGrabKeycode, XIGrabTouchBegin, XIGrabPinchGestureBegin
et XIGrabSwipeGestureBegin peuvent générer des erreurs BadClass,
BadDevice, BadMatch, BadValue et BadWindow.
XIUngrabButton, XIUngrabKeycode, XIUngrabTouchBegin, XIUngrabPinchGestureBegin
et XIUngrabSwipeGestureBegin libèrent la
saisie passive pour une combinaison bouton/modificateur, code de touche/modificateur ou tactile/modificateur
sur la fenêtre spécifiée si elle a été saisie par ce client. Un
modificateur de XIAnyModifier équivaut à émettre la requête de libération
pour toutes les combinaisons de modificateurs possibles, y compris la
combinaison d'aucun modificateur. Un bouton de XIAnyButton équivaut à émettre la requête pour tous les boutons possibles.
XIUngrabButton et XIUngrabKeycode n'ont aucun effet sur une saisie active.

NAME

XIUngrabKeycode, XIUngrabButton, XIUngrabTouchBegin, XIUngrabPinchGestureBegin, XIUngrabSwipeGestureBegin - ungrab devices

SYNOPSIS

#include <X11/Xlib.h>
#include <X11/extensions/XInput.h>
#include <X11/extensions/XI.h>
#include <X11/extensions/XInput2.h>

int
XIUngrabKeycode(Display *display,
        unsigned int keycode,
        unsigned int modifiers,
        Window grab_window,
        Time time,
        unsigned int mask);

int
XIUngrabButton(Display *display,
        unsigned int button,
        unsigned int modifiers,
        Window grab_window,
        Time time,
        unsigned int mask);

int
XIUngrabTouchBegin(Display *display,
        Window grab_window,
        Time time,
        unsigned int mask);

int
XIUngrabPinchGestureBegin(Display *display,
        Window grab_window,
        Time time,
        unsigned int mask);

int
XIUngrabSwipeGestureBegin(Display *display,
        Window grab_window,
        Time time,
        unsigned int mask);

DESCRIPTION

The XIUngrabKeycode function releases the device specified by
       `display` for passive grabs previously established with XIGrabKeycode.
       The grab is released for the specified keycode and modifiers.
       The grab_window must be the same window that was used when the grab
       was established. The time must be the same time that was used when
       the grab was established. The mask must specify the same mask that
       was used when the grab was established.
       A value of AllModifierMask for the mask argument will ungrab all
       possible modifier combinations for the given keycode and modifiers.
The XIUngrabButton function releases the device specified by
       `display` for passive grabs previously established with XIGrabButton.
       The grab is released for the specified button and modifiers.
       The grab_window must be the same window that was used when the grab
       was established. The time must be the same time that was used when
       the grab was established. The mask must specify the same mask that
       was used when the grab was established.
       A value of AllModifierMask for the mask argument will ungrab all
       possible modifier combinations for the given button and modifiers.
The XIUngrabTouchBegin function releases the device specified by
       `display` for passive grabs previously established with
       XIUngrabTouchBegin. The grab_window must be the same window that was
       used when the grab was established. The time must be the same time
       that was used when the grab was established. The mask must specify the
       same mask that was used when the grab was established.
       A value of AllModifierMask for the mask argument will ungrab all
       possible modifier combinations for the given device.
The XIUngrabPinchGestureBegin function releases the device specified by
       `display` for passive grabs previously established with
       XIUngrabPinchGestureBegin. The grab_window must be the same window
       that was used when the grab was established. The time must be the
       same time that was used when the grab was established. The mask must
       specify the same mask that was used when the grab was established.
       A value of AllModifierMask for the mask argument will ungrab all
       possible modifier combinations for the given device.
The XIUngrabSwipeGestureBegin function releases the device specified by
       `display` for passive grabs previously established with
       XIUngrabSwipeGestureBegin. The grab_window must be the same window
       that was used when the grab was established. The time must be the
       same time that was used when the grab was established. The mask must
       specify the same mask that was used when the grab was established.
       A value of AllModifierMask for the mask argument will ungrab all
       possible modifier combinations for the given device.
XIUngrabKeycode, XIUngrabButton, XIUngrabTouchBegin and
XIUngrabPinchGestureBegin and XIUngrabSwipeGestureBegin can generate
BadDevice, BadMatch, BadValue and BadWindow errors.

RETURN VALUE

XIGrabButton, XIGrabKeycode, XIGrabTouchBegin and
XIGrabPinchGestureBegin and XIGrabSwipeGestureBegin return the number of
modifier combination that could not establish a passive grab. The
modifiers are returned in modifiers_inout, along with the respective
error for this modifier combination. If XIGrabButton, XIGrabKeycode
or XIGrabTouchBegin return zero, passive grabs with all requested
modifier combinations were established successfully.

DIAGNOSTICS

BadDevice
       An invalid deviceid was specified.
BadMatch
       This error may occur if XIGrabButton specified a device
       that has no buttons, or XIGrabKeycode specified a device
       that has no keys,
       or XIGrabTouchBegin specified a device that is not touch-capable,
       or XIGrabPinchGestureBegin specified a device that is not gesture-capable,
       or XIGrabSwipeGestureBegin specified a device that is not gesture-capable.
BadValue
       Some numeric value falls outside the range of values
       accepted by the request. Unless a specific range is
       specified for an argument, the full range defined by the
       argument's type is accepted. Any argument defined as a
       set of alternatives can generate this error.
BadWindow
       A value for a Window argument does not name a defined
       Window.

BUGS

The protocol headers for XI 2.0 did not provide
XIGrabModeAsync or XIGrabModeSync. Use GrabModeSync and
GrabModeAsync instead, respectively.
