XIQUERYDEVICE(3)   XIQUERYDEVICE(3)

NOM

XIQueryDevice, XIFreeDeviceInfo - obtenir des informations sur les périphériques.

SYNTAXE

#include <X11/extensions/XInput2.h>
XIDeviceInfo* XIQueryDevice( Display *display,
                             int deviceid,
                             int *ndevices_return);
XIFreeDeviceInfo( XIDeviceInfo *info);
deviceid
       Spécifie le périphérique à interroger ou XIAllDevices ou
       XIAllMasterDevices.
display
       Spécifie la connexion au serveur X.
ndevices_return
       Retourne le nombre de périphériques renvoyés.
info
       Une liste de structures XIDeviceInfo de périphériques à libérer.

DESCRIPTION

La fonction XIQueryDevice renvoie des informations sur un ou plusieurs périphériques d'entrée. Si l'identifiant du périphérique spécifie un périphérique, ndevices_return est 1 et les informations renvoyées ne décrivent que le périphérique demandé. Si deviceid est XIAllDevices ou XIAllMasterDevices, ndevices_return est le nombre de périphériques ou de périphériques maîtres, respectivement, et les informations renvoyées représentent tous les périphériques ou tous les périphériques maîtres, respectivement.
Pour libérer le tableau XIDeviceInfo renvoyé par XIQueryDevice, utilisez XIFreeDeviceInfo.
Pour chaque périphérique d'entrée demandé, XIQueryDevice renvoie une structure XIDeviceInfo. Chaque structure contient des informations sur les capacités de chaque périphérique d'entrée disponible pour le serveur.
typedef struct
{
    int                 deviceid;
    char                *name;
    int                 use;
    int                 attachment;
    Bool                enabled;
    int                 num_classes;
    XIAnyClassInfo      **classes;
} XIDeviceInfo;
deviceid est l'identifiant numérique unique du périphérique. Un deviceid est unique pendant la durée de vie d'un périphérique, mais un serveur peut réutiliser l'identifiant une fois qu'un périphérique a été supprimé.
name pointe vers une chaîne terminée par null spécifiant l'identifiant du périphérique.
Les champs use et attachment spécifient le type du périphérique et l'attachement ou l'appariement actuel.
- Si use est XIMasterPointer, le périphérique est un pointeur maître et attachment spécifie l'identifiant du périphérique du clavier maître apparié.
- Si use est XIMasterKeyboard, le périphérique est un clavier maître, et le champ attachment spécifie le pointeur maître apparié.
- Si use est XISlavePointer, le périphérique est un périphérique esclave et est actuellement attaché au pointeur maître spécifié dans attachment.
- Si use est XISlaveKeyboard, le périphérique est un périphérique esclave et est actuellement attaché au clavier maître spécifié dans attachment.
- Si use est XIFloatingSlave, le périphérique est un périphérique esclave actuellement non attaché à un périphérique maître. La valeur du champ attachment pour les périphériques esclaves flottants est indéfinie.
Le champ enabled spécifie si le périphérique est actuellement activé et peut envoyer des événements. Les périphériques désactivés n'enverront pas d'événements.
Le champ num_classes spécifie le nombre de classes d'entrée pointées par classes. Les deux premiers champs de toutes les classes d'entrée sont identiques.
typedef struct
{
    int         type;
    int         sourceid;
} XIAnyClassInfo;
Le champ type spécifie le type de la classe d'entrée.
Actuellement, les types suivants sont définis :
    XIKeyClass, XIButtonClass, XIValuatorClass, XIScrollClass,
    XITouchClass, XIGestureClass.
À l'avenir, des types supplémentaires pourront être ajoutés. Les clients sont tenus d'ignorer les classes d'entrée inconnues.
sourceid est l'identifiant du périphérique d'où provient cette classe. Pour les périphériques maîtres, sourceid est généralement l'identifiant du périphérique esclave qui envoie actuellement des événements. Pour les périphériques esclaves, sourceid est généralement l'identifiant du périphérique.
Un périphérique peut avoir zéro ou une XIButtonClass, indiquant la capacité du périphérique à envoyer des événements de bouton.
typedef struct {
    int           mask_len;
    unsigned char *mask;
} XIButtonState;
typedef struct
{
    int         type;
    int         sourceid;
    int         num_buttons;
    Atom        *labels;
    XIButtonState state;
} XIButtonClassInfo;
Le champ num_buttons spécifie le nombre de boutons disponibles sur ce périphérique. Un périphérique possédant une XIButtonClass doit avoir au moins un bouton.
labels est une liste d'Atoms num_buttons spécifiant les étiquettes des boutons pour ce périphérique. Si l'étiquette n'est pas None, alors l'étiquette spécifie le type de bouton dans l'ordre du périphérique physique (c'est-à-dire tel que les boutons sont numérotés sur le périphérique d'entrée physique).
state est l'état actuel des boutons tel que vu par les clients (c'est-à-dire après application du mappage des boutons). Le champ mask_len spécifie la longueur du masque en octets. Pour chaque bouton du périphérique, le bit correspondant dans mask est défini si le bouton est actuellement logiquement enfoncé.
Un périphérique peut avoir zéro ou une XIKeyClass, indiquant la capacité du périphérique à envoyer des événements de touche.
typedef struct
{
    int         type;
    int         sourceid;
    int         num_keycodes;
    int         *keycodes;
} XIKeyClassInfo;
Le champ num_keycodes spécifie le nombre de codes de touches disponibles sur ce périphérique. Un périphérique possédant une XIKeyClass doit avoir au moins un code de touche.
keycodes est une liste de num_keycodes codes de touches que le périphérique peut envoyer.
Un périphérique peut avoir zéro ou plusieurs XIValuatorClass, indiquant la capacité du périphérique à envoyer des coordonnées.
typedef struct
{
    int         type;
    int         sourceid;
    int         number;
    Atom        label;
    double      min;
    double      max;
    double      value;
    int         resolution;
    int         mode;
} XIValuatorClassInfo;
Le champ number spécifie le numéro de l'axe sur le périphérique physique.
Si le champ label n'est pas None, la valeur de label est un Atom décrivant l'axe.
min et max sont les valeurs minimale et maximale autorisées sur cet axe. Si les deux sont zéro, aucune valeur minimale ou maximale n'est définie sur ce périphérique. value est la valeur actuelle de cet axe.
Le champ resolution spécifie la résolution du périphérique en unités/m.
Le champ mode spécifie le mode de cet axe. Si le mode est XIModeAbsolute, cet axe envoie des coordonnées absolues. Si le mode est XIModeRelative, ce périphérique envoie des coordonnées relatives.
typedef struct
{
    int         type;
    int         sourceid;
    int         number;
    int         scroll_type;
    double      increment;
    int         flags;
} XIScrollClassInfo;
Cette classe décrit la capacité de défilement sur un valuator. Pour chaque XIScrollClassInfo, un XIValuatorClassInfo portant le même numéro est présent sur le périphérique.
Le champ number spécifie le numéro du valuator sur le périphérique physique auquel s'appliquent ces informations de défilement. Voir le XIValuatorClassInfo correspondant pour des informations détaillées sur ce valuator.
Le champ scroll_type spécifie le type de défilement, soit XIScrollTypeVertical, soit XIScrollTypeHorizontal.
L'incrément spécifie le changement de valeur considéré comme une unité de défilement vers le bas.
Le champ flags spécifie les drapeaux qui s'appliquent à ces informations de défilement :
Si XIScrollFlagNoEmulation est défini, le serveur n'émulera pas d'événements de bouton hérités pour les changements de valuator sur ce valuator.
Si XIScrollFlagPreferred est défini, cet axe est l'axe préféré pour ce type de défilement et sera utilisé pour l'émulation des événements XI_Motion lorsque le pilote soumet des événements de bouton de défilement hérités.
typedef struct
{
    int         type;
    int         sourceid;
    int         mode;
    int         num_touches;
} XITouchClassInfo;
Un périphérique peut avoir zéro ou une XITouchClassInfo, indiquant une capacité multi-touch sur le périphérique. Un périphérique avec une XITouchClassInfo peut envoyer des événements TouchBegin, TouchUpdate, TouchEnd et TouchOwnership.
Le champ mode est soit XIDirectTouch pour les périphériques tactiles à entrée directe tels que les écrans tactiles, soit XIDependentTouch pour les périphériques à entrée indirecte tels que les pavés tactiles. Pour les périphériques XIDirectTouch, les événements tactiles sont envoyés à la fenêtre à la position où le contact a eu lieu. Pour les périphériques XIDependentTouch, les événements tactiles sont envoyés à la fenêtre à la position du sprite du périphérique.

XIQueryDevice(3) — Arch Linux

NAME

XIQueryDevice - query information about an input device

SYNOPSIS

#include <X11/extensions/XInput.h>

int XIQueryDevice(Display *display, int deviceid,
                  XIDeviceInfo **devices_return);

DESCRIPTION

The num_touches field defines the maximum number of simultaneous touches
the device supports. A num_touches of 0 means the maximum number of
simultaneous touches is undefined or unspecified. This field should be
used as a guide only, devices will lie about their capabilities.
A device with an XITouchClassInfo may still send pointer events. The
valuators must be defined with the respective XIValuatorClass
classes. A valuator may send both pointer and touch-events.
typedef struct
{
    int         type;
    int         sourceid;
    int         num_touches;
} XIGestureClassInfo;
A device may have zero or one XIGestureClassInfo, denoting
touchpad gesture capability on the device. A device with a XIGestureClassInfo
may send GestureSwipeBegin, GestureSwipeUpdate, GestureSwipeEnd,
GesturePinchBegin, GesturePinchUpdate, GesturePinchEnd.
The num_touches field defines the maximum number of simultaneous touches
the device supports. A num_touches of 0 means the maximum number of
simultaneous touches is undefined or unspecified. This field should be
used as a guide only, devices will lie about their capabilities.
XIQueryDevice can generate a BadDevice error.
XIFreeDeviceInfo frees the information returned by
XIQueryDevice.

DIAGNOSTICS

BadDevice
       An invalid device was specified. The device does not
       exist or is not a pointer device.
