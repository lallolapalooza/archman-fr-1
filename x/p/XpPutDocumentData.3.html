XpPutDocumentData(3Xp) FONCTIONS D'IMPRESSION Xp XpPutDocumentData(3Xp)

NOM

void XpPutDocumentData - Envoie et intègre des données dans la sortie.

SYNTAXE


cc [ flag... ] file... -lXp [ library... ]
#include <X11/extensions/Print.h>

XpPutDocumentData ( display, drawable, data, data_len, doc_fmt, options )
Display *display;
Drawable drawable;
unsigned char *data;
int data_len;
char *doc_fmt;
char *options;

ARGUMENTS

display
Spécifie un pointeur vers la structure Display ; retourné par XOpenDisplay.
drawable
Spécifie le dessinable de destination pour le rendu.
data
Spécifie les données spécifiques à l'appareil envoyées.
data_len
Spécifie le nombre d'octets dans data.
doc_fmt
Spécifie le type des données envoyées. Voir ci-dessous pour les valeurs valides. Chaîne limitée aux caractères XPCS.
options
Spécifie les options dépendant du pilote DDX. Chaîne limitée aux caractères XPCS.

DESCRIPTION

Selon le type pour XpStartDoc, XpPutDocumentData a deux modes de fonctionnement.

En mode XPDocRaw, XpPutDocumentData envoie data directement à la sortie, et drawable doit être None, sinon une erreur BadDrawable est générée. Le serveur d'impression X n'émet pas de codes de contrôle de document ou de page dans la sortie, et les données sont transmises sans modification. Ceci est utile pour envoyer des documents précédemment construits et complétés en utilisant les capacités de contrôle et de soumission de travaux du serveur d'impression X. L'attribut d'imprimante xp-raw-formats-supported définit les valeurs valides pour doc_fmt dans ce mode. Les valeurs non prises en charge pour doc_fmt génèrent une erreur BadMatch.

En mode XPDocNormal, XpPutDocumentData envoie data au serveur d'impression X et, en fonction de l'implémentation du pilote DDX, intègre data dans la sortie. Les paramètres doc_fmt et options décrivent le format des données, ce qui guide le pilote DDX dans l'interprétation des données. L'attribut d'imprimante xp-embedded-formats-supported définit les valeurs valides pour doc_fmt dans ce mode, les valeurs non prises en charge pour doc_fmt générant une erreur BadMatch.

Si doc_fmt n'est ni dans xp-raw-formats-supported ni dans xp-embedded-formats-supported, une erreur BadValue est générée.

Selon l'implémentation du pilote DDX utilisé, XpPutDocumentData peut être utilisé, par exemple, pour envoyer un simple fichier texte à un pilote DDX Postscript capable d'encapsuler les constructions de contrôle de document et de page appropriées autour du texte afin qu'il puisse être imprimé sur une imprimante Postscript. De même, les fichiers Postscript encapsulés peuvent être gérés. Une autre utilisation pourrait être d'envoyer un fichier TIFF à un pilote DDX PCL capable de convertir l'image de TIFF en PCL, puis de l'intégrer dans la sortie PCL actuelle.

Il n'y a pas de limite à la valeur de data_len. XpPutDocumentData décompose automatiquement l'appel en plusieurs requêtes de protocole pour s'assurer que la taille maximale des requêtes du serveur n'est pas dépassée.

DIAGNOSTICS

BadDrawable
La valeur spécifiée pour drawable n'est pas valide.
BadMatch
La valeur spécifiée pour doc_fmt n'est pas valide pour le type de document actuel ou la valeur spécifiée pour est invalide pour le contexte d'impression et l'écran d'impression.
BadValue
La valeur spécifiée pour doc_fmt n'est pas prise en charge.
XPBadContext
Un identifiant de contexte d'impression valide n'a pas été défini avant de faire cet appel.
XPBadSequence
La fonction n'a pas été appelée dans le bon ordre par rapport aux autres appels du service d'impression X (par exemple, XpPutDocumentData avant XpStartDoc).
