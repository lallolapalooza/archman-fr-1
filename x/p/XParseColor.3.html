Paquet: libx11

XQueryColor(3) FONCTIONS XLIB XQueryColor(3)

NOM

XQueryColor, XQueryColors, XLookupColor, XParseColor - obtenir les valeurs de couleur

SYNTAXE

int XQueryColor(Display *display, Colormap colormap, XColor *def_in_out);

int XQueryColors(Display *display, Colormap colormap, XColor defs_in_out[], int ncolors);

Status XLookupColor(Display *display, Colormap colormap, _Xconst char *color_name, XColor *exact_def_return, XColor *screen_def_return);

Status XParseColor(Display *display, Colormap colormap, _Xconst char *spec, XColor *exact_def_return);

ARGUMENTS

colormap
Spécifie la palette de couleurs.
color_name
Spécifie la chaîne de nom de couleur (par exemple, red) dont vous voulez la structure de définition de couleur.
def_in_out
Spécifie et retourne les valeurs RVB pour le pixel spécifié dans la structure.
defs_in_out
Spécifie et retourne un tableau de structures de définition de couleur pour le pixel spécifié dans la structure.
display
Spécifie la connexion au serveur X.
exact_def_return
Retourne les valeurs RVB exactes.
ncolors
Spécifie le nombre de structures XColor dans le tableau de définition de couleur.
screen_def_return
Retourne les valeurs RVB les plus proches fournies par le matériel.
spec
Spécifie la chaîne de nom de couleur ; la casse est ignorée.
exact_def_return
Retourne la valeur de couleur exacte pour une utilisation ultérieure et définit les indicateurs DoRed, DoGreen et DoBlue.

DESCRIPTION

La fonction XQueryColor retourne la valeur RVB actuelle pour le pixel dans la structure XColor et définit les indicateurs DoRed, DoGreen et DoBlue. La fonction XQueryColors retourne la valeur RVB pour chaque pixel dans chaque structure XColor et définit les indicateurs DoRed, DoGreen et DoBlue dans chaque structure.

XQueryColor et XQueryColors peuvent générer des erreurs BadColor et BadValue.

La fonction XLookupColor recherche le nom de chaîne d'une couleur par rapport à l'écran associé à la palette de couleurs spécifiée. Elle retourne à la fois les valeurs de couleur exactes et les valeurs les plus proches fournies par l'écran par rapport au type visuel de la palette de couleurs spécifiée. Si le nom de la couleur n'est pas dans le codage de caractères portable hôte, le résultat dépend de l'implémentation. L'utilisation de la casse majuscule ou minuscule n'a pas d'importance. XLookupColor retourne une valeur non nulle si le nom est résolu ; sinon, elle retourne zéro.

La fonction XParseColor recherche le nom de chaîne d'une couleur par rapport à l'écran associé à la palette de couleurs spécifiée. Elle retourne la valeur de couleur exacte. Si le nom de la couleur n'est pas dans le codage de caractères portable hôte, le résultat dépend de l'implémentation. L'utilisation de la casse majuscule ou minuscule n'a pas d'importance. XParseColor retourne une valeur non nulle si le nom est résolu ; sinon, elle retourne zéro.

XLookupColor et XParseColor peuvent générer une erreur BadColor.

NOMS DE COULEURS

Une spécification de périphérique RVB est identifiée par le préfixe « rgb: » et est conforme à la syntaxe suivante :

rgb:<rouge>/<vert>/<bleu>
    <rouge>, <vert>, <bleu> := h | hh | hhh | hhhh
    h := chiffre hexadécimal unique (casse non significative)

Notez que h indique la valeur mise à l'échelle sur 4 bits, hh la valeur mise à l'échelle sur 8 bits, hhh la valeur mise à l'échelle sur 12 bits et hhhh la valeur mise à l'échelle sur 16 bits, respectivement.

Pour des raisons de compatibilité ascendante, une ancienne syntaxe pour les périphériques RVB est prise en charge, mais son utilisation continue n'est pas encouragée. La syntaxe consiste en un caractère dièse initial suivi d'une spécification numérique, dans l'un des formats suivants :

#RGB (4 bits chacun)
#RRGGBB (8 bits chacun)
#RRRGGGBBB (12 bits chacun)
#RRRRGGGGBBBB (16 bits chacun)

Les R, G et B représentent des chiffres hexadécimaux uniques. Lorsque moins de 16 bits chacun sont spécifiés, ils représentent les bits de poids fort de la valeur (contrairement à la syntaxe « rgb: », où les valeurs sont mises à l'échelle). Par exemple, la chaîne « #3a7 » est équivalente à « #3000a0007000 ».

Une spécification d'intensité RVB est identifiée par le préfixe « rgbi: » et est conforme à la syntaxe suivante :

rgbi:<rouge>/<vert>/<bleu>

Notez que rouge, vert et bleu sont des valeurs à virgule flottante entre 0,0 et 1,0, inclus. Le format d'entrée pour ces valeurs est un signe facultatif, une chaîne de chiffres pouvant contenir un point décimal, et un champ d'exposant facultatif contenant un E ou un e suivi d'une chaîne d'entiers éventuellement signée.

Les spécifications de chaînes standard indépendantes du périphérique ont la syntaxe suivante :

CIEXYZ:<X>/<Y>/<Z>
CIEuvY:<u>/<v>/<Y>
CIExyY:<x>/<y>/<Y>
CIELab:<L>/<a>/<b>
CIELuv:<L>/<u>/<v>
TekHVC:<H>/<V>/<C>

Toutes les valeurs (C, H, V, X, Y, Z, a, b, u, v, y, x) sont des valeurs à virgule flottante. La syntaxe de ces valeurs est un signe plus ou moins facultatif, une chaîne de chiffres pouvant contenir un point décimal, et un champ d'exposant facultatif composé d'un « E » ou « e » suivi d'un signe plus ou moins facultatif suivi d'une chaîne de chiffres.

DIAGNOSTICS

BadColor
Une valeur pour un argument Colormap ne nomme pas une palette de couleurs définie.
BadValue
Une valeur numérique tombe en dehors de la plage de valeurs acceptées par la requête. Sauf si une plage spécifique est spécifiée pour un argument, la plage complète définie par le type de l'argument est acceptée. Tout argument défini comme un ensemble d'alternatives peut générer cette erreur.

NAME

XParseColor - parse a color string

SYNOPSIS

#include <X11/Xlib.h>

int XParseColor(
    Display *display,
    Colormap   colormap,
    _Xconst char *string,
    XColor      *color_return
);

DESCRIPTION

The XParseColor function parses a string representation of a color and returns the XColor structure. The string can be a standard name (e.g., "red", "blue") or a hexadecimal value (e.g., "#RRGGBB"). The colormap argument specifies the colormap to use for looking up color names. If colormap is None, the default colormap of the screen is used.

The color string can be in one of the following formats:

  • A standard color name, such as "red", "green", "blue", "white", "black". These names are defined in the rgb.txt file on most systems.
  • A hexadecimal value in the format "#RRGGBB", where RR, GG, and BB are hexadecimal values from 00 to FF representing the red, green, and blue components, respectively.
  • A hexadecimal value in the format "#RGB", where R, G, and B are hexadecimal values from 0 to F representing the red, green, and blue components, respectively. This is a shorthand for "#RRGGBB" where each component is replicated.

The color_return argument is a pointer to an XColor structure that will be filled with the parsed color information. The red, green, and blue members of the XColor structure will be set to the corresponding color components, scaled to the range 0 to 65535. The pixel member will be set to the pixel value of the color in the specified colormap. The flags member will be set to indicate which components (red, green, blue) were successfully parsed.

RETURN VALUE

XParseColor returns one of the following values:

  • 0: If the color string could not be parsed or the color name was not found in the colormap.
  • 1: If the color string was parsed successfully, but the exact color could not be found in the colormap. In this case, the closest available color is returned.
  • 2: If the color string was parsed successfully and the exact color was found in the colormap.

ERRORS

None.

STRUCTURES

The XColor structure is defined as follows:

typedef struct {
    unsigned long pixel;
    unsigned short red;
    unsigned short green;
    unsigned short blue;
    char         exact_red:1;
    char         exact_green:1;
    char         exact_blue:1;
    char         pad:5;
} XColor;
  • pixel: The pixel value of the color.
  • red, green, blue: The red, green, and blue components of the color, scaled from 0 to 65535.
  • exact_red, exact_green, exact_blue: Flags indicating whether the specified component was exactly matched.
  • pad: Padding.

COLOR NAMES

Color names are typically defined in the rgb.txt file, which is usually located in the /usr/share/X11/rgb.txt directory. The format of this file is:

red    255   0     0
green  0     255   0
blue   0     0     255

You can also specify colors using names defined by the X Consortium.

DIAGNOSTICS

If string cannot be parsed or the color is not found in the colormap, XParseColor returns 0. If the closest match is returned, it returns 1. If the exact color is found, it returns 2.

NOM

XParseColor - analyse une chaîne de couleur

SYNTAXE

#include <X11/Xlib.h>

int XParseColor(
    Display *display,
    Colormap   colormap,
    _Xconst char *string,
    XColor      *color_return
);

DESCRIPTION

La fonction XParseColor analyse une représentation en chaîne de caractères d'une couleur et retourne la structure XColor. La chaîne peut être un nom standard (par exemple, "red", "blue") ou une valeur hexadécimale (par exemple, "#RRGGBB"). L'argument colormap spécifie la table des couleurs à utiliser pour rechercher les noms de couleurs. Si colormap est None, la table des couleurs par défaut de l'écran est utilisée.

La chaîne de couleur peut être dans l'un des formats suivants :

  • Un nom de couleur standard, tel que "red", "green", "blue", "white", "black". Ces noms sont définis dans le fichier rgb.txt sur la plupart des systèmes.
  • Une valeur hexadécimale au format "#RRGGBB", où RR, GG et BB sont des valeurs hexadécimales de 00 à FF représentant les composantes rouge, verte et bleue, respectivement.
  • Une valeur hexadécimale au format "#RGB", où R, G et B sont des valeurs hexadécimales de 0 à F représentant les composantes rouge, verte et bleue, respectivement. Il s'agit d'une version abrégée de "#RRGGBB" où chaque composante est répétée.

L'argument color_return est un pointeur vers une structure XColor qui sera remplie avec les informations de couleur analysées. Les membres red, green et blue de la structure XColor seront définis aux composantes de couleur correspondantes, mises à l'échelle dans la plage de 0 à 65535. Le membre pixel sera défini à la valeur de pixel de la couleur dans la table des couleurs spécifiée. Le membre flags sera défini pour indiquer quelles composantes (rouge, verte, bleue) ont été analysées avec succès.

VALEUR DE RETOUR

XParseColor retourne l'une des valeurs suivantes :

  • 0 : Si la chaîne de couleur n'a pas pu être analysée ou si le nom de couleur n'a pas été trouvé dans la table des couleurs.
  • 1 : Si la chaîne de couleur a été analysée avec succès, mais que la couleur exacte n'a pas pu être trouvée dans la table des couleurs. Dans ce cas, la couleur la plus proche disponible est retournée.
  • 2 : Si la chaîne de couleur a été analysée avec succès et que la couleur exacte a été trouvée dans la table des couleurs.

ERREURS

Aucune.

STRUCTURES

La structure XColor est définie comme suit :

typedef struct {
    unsigned long pixel;
    unsigned short red;
    unsigned short green;
    unsigned short blue;
    char         exact_red:1;
    char         exact_green:1;
    char         exact_blue:1;
    char         pad:5;
} XColor;
  • pixel : La valeur de pixel de la couleur.
  • red, green, blue : Les composantes rouge, verte et bleue de la couleur, mises à l'échelle de 0 à 65535.
  • exact_red, exact_green, exact_blue : Indicateurs indiquant si la composante spécifiée a été exactement correspondante.
  • pad : Bourrage.

NOMS DE COULEUR

Les noms de couleur sont généralement définis dans le fichier rgb.txt, qui est généralement situé dans le répertoire /usr/share/X11/rgb.txt. Le format de ce fichier est :

red    255   0     0
green  0     255   0
blue   0     0     255

Vous pouvez également spécifier des couleurs à l'aide de noms définis par le Consortium X.

DIAGNOSTICS

Si string ne peut pas être analysé ou si la couleur n'est pas trouvée dans la table des couleurs, XParseColor retourne 0. Si la correspondance la plus proche est retournée, elle retourne 1. Si la couleur exacte est trouvée, elle retourne 2.

VOIR AUSSI

XAllocColor(3), XQueryColor(3), XcmsQueryColor(3)
