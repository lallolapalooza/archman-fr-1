XpGetDocumentData(3Xp) XPRINT FUNCTIONS XpGetDocumentData(3Xp)

NOM

XpGetDocumentData - Crée et initialise un nouveau contexte d'impression.

SYNOPSIS


cc [ flag... ] file... -lXp [ library... ]
#include <X11/extensions/Print.h>

Status XpGetDocumentData ( data_display, context, save_proc, finish_proc, client_data )
Display *data_display;
XPContext context;
XPSaveProc save_proc;
XPFinishProc finish_proc;
XPointer client_data;

ARGUMENTS

data_display
Spécifie un pointeur vers la structure Display ; retourné par XOpenDisplay.
context
Le contexte d'impression à partir duquel les données du document doivent être récupérées.
save_proc
Une procédure à enregistrer et à appeler de manière répétée pour sauvegarder des blocs de données de document.
finish_proc
Une procédure à enregistrer et à appeler une fois lorsque le travail d'impression est terminé et que toutes les données du document ont été envoyées à save_proc.
client_data
Spécifie les données client à passer à save_proc et finish_proc lorsqu'elles sont appelées.

DESCRIPTION

XpGetDocumentData enregistre des rappels qui permettent à un « consommateur » de récupérer en continu les données de document générées dans le Serveur d'impression X par un « producteur » distinct, où les deux font référence au même contexte d'impression via des connexions d'affichage différentes. Bien que XpGetDocumentData récupère les données du document, son effet est délimité par XpStartJob et XpEndJob. XpGetDocumentData retourne toujours immédiatement ; si une erreur se produit et que les rappels ne peuvent pas être enregistrés, le statut de retour est 0, sinon le statut de retour est non nul et les rappels seront appelés après le retour de XpGetDocumentData. Cet échange producteur/consommateur est configuré lorsque XpStartJob est appelé par le producteur avec output_mode égal à XPGetData, et est initié par la suite lorsque XpGetDocumentData est appelé par le consommateur. Bien que XpStartJob retourne immédiatement, d'autres tentatives d'utilisation de la connexion d'affichage du producteur peuvent être bloquées par le Serveur d'impression X jusqu'à ce que XpGetDocumentData soit appelé sur la connexion d'affichage du consommateur.

Suite à un appel réussi à XpGetDocumentData, le consommateur doit entrer dans une boucle pour traiter les événements du serveur, par exemple, en appelant XNextEvent. Le code de traitement des événements invoquera save_proc et finish_proc si nécessaire pour consommer les données entrantes. Pour éviter de bloquer indéfiniment dans XNextEvent, le consommateur doit sélectionner les événements XPPrintNotify et surveiller XPEndJobNotify. Cet événement sera envoyé après l'appel à finish_proc et le consommateur peut quitter la boucle en toute sécurité à ce moment-là. En dehors de ce traitement des événements XPrintNotify, data_display ne doit pas être utilisé pour d'autres requêtes X tant que finish_proc n'est pas appelé et ne retourne pas.

STRUCTURES

La procédure save_proc est définie dans <X11/extensions/Print.h> comme suit :

typedef void (*XPSaveProc)( Display *data_display,
                           XPContext context,
                           unsigned char *data,
                           unsigned int data_len,
                           XPointer client_data);

La procédure save_proc est appelée de manière répétée pour chaque bloc de données de document envoyé par le serveur d'impression X jusqu'à ce que XpEndJob ou XpCancelJob soit appelé. data_len spécifie le nombre d'octets dans data. La mémoire pour data elle-même appartient à la bibliothèque, donc save_proc doit copier data dans un autre emplacement avant de retourner. Après que le dernier bloc de données a été livré à save_proc, finish_proc est appelé avec le statut final.

La procédure finish_proc est définie dans <X11/extensions/Print.h> comme suit :

typedef void (*XPFinishProc)( Display *data_display,
                             XPContext context,
                             XPGetDocStatus status,
                             XPointer client_data);

Après que XpGetDocumentData a enregistré avec succès les rappels, toutes les erreurs X générées (par exemple, BadAlloc) ou les erreurs Xp (par exemple, XPBadContext ou XPBadSequence) qui résultent de XpGetDocumentData provoqueront l'invocation du gestionnaire d'erreurs Xlib, puis provoqueront l'appel de finish_proc avec un statut de XPGetDocError. Toute autre activité (par exemple, un processus distinct détruisant le contexte d'impression) qui s'avère fatale au bon déroulement de XpGetDocumentData appellera également finish_proc avec un statut de XPGetDocError.

Si XpGetDocumentData est appelé avant XpStartJob, une erreur XPBadSequence est générée et finish_proc est appelé avec XPGetDocError. Si XpGetDocumentData est appelé après XpStartJob et que output_mode a été spécifié comme XPSpool, alors une erreur XPBadSequence est générée et finish_proc est appelé avec XPGetDocError. Si le producteur commence à générer des données et que le consommateur ne peut pas consommer les données assez rapidement, la connexion d'affichage du producteur sera bloquée par le Serveur d'impression X.

Jusqu'à ce que XpEndJob ou XpCancelJob soit appelé, il est possible que divers événements XPPrintNotify soient générés (par exemple, une page a été annulée). Les données passées à save_proc ne sont pas nécessairement organisées selon les requêtes du consommateur ou les événements générés, et leur cohérence n'est garantie que si l'ensemble du travail se termine avec succès (c'est-à-dire sans être annulé ou sans générer d'erreur).

Lorsque finish_proc est appelé, un certain temps après que XpGetDocumentData a été appelé et est retourné, status donne le statut d'achèvement du travail et est défini dans <X11/extensions/Print.h> comme suit :

#define XPGetDocFinished        0       /*∗ termination normale */
#define XPGetDocSecondConsumer  1       /*∗ erreur de configuration */
#define XPGetDocError           2       /*∗ erreur de progression */

XPGetDocFinished indique que toutes les données de document prévues ont été livrées via save_proc. Tous les événements d'annulation sont garantis d'être arrivés au moment où finished_proc est appelé, et ils doivent être pris en compte pour évaluer la validité des données de document renvoyées.

XPGetDocSecondConsumer indique qu'un consommateur avait déjà été établi pour le contexte d'impression. Le Serveur d'impression X ne prend en charge qu'un seul consommateur par contexte d'impression.

XPGetDocError indique qu'une erreur a été générée (par exemple, XPBadContext ou XPBadSequence) et qu'aucune donnée de document supplémentaire ne sera livrée par le Serveur d'impression X à save_proc.

Après le retour de finish_proc, save_proc et finish_proc sont désenregistrés et ne seront plus appelés.

DIAGNOSTICS

XPBadContext
Un identifiant de contexte d'impression valide n'a pas été défini avant de faire cet appel.
XPBadSequence
La fonction n'a pas été appelée dans le bon ordre par rapport aux autres appels de l'extension du service d'impression X (par exemple, XpGetDocumentData avant XpStartJob).
