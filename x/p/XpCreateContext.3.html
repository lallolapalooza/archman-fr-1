XpCreateContext(3Xp) FONCTIONS XPRINT XpCreateContext(3Xp)

NOM

XpCreateContext - Crée et initialise un nouveau contexte d'impression.

SYNTAXE


cc [ indicateur... ] fichier... -lXp [ bibliothèque... ]
#include <X11/extensions/Print.h>

XPContext XpCreateContext ( display, printer_name )
Display *display;
char *printer_name;

ARGUMENTS

display
Spécifie un pointeur vers la structure Display ; retournée par XOpenDisplay.
printer_name
Le nom d'une imprimante sur display. Chaîne encodée en COMPOUND_TEXT.

DESCRIPTION

XpCreateContext crée un nouveau contexte d'impression qui est initialisé avec les attributs par défaut de l'imprimante et d'autres informations disponibles pour printer_name sur display. Un contexte d'impression maintient le nom de l'imprimante, les attributs d'impression, les capacités de polices, l'état et les résultats d'impression (rendu), et est l'objet sur lequel les appels Xp agissent.

Si la bibliothèque ne parvient pas à générer un nouvel identifiant de contexte d'impression, une valeur de None est retournée, sinon un identifiant de contexte d'impression est toujours retourné. Si printer_name est invalide, un BadMatch sera généré plus tard par le Serveur d'impression X.

Un appel à XpGetPrinterList retournera une liste valide de valeurs pour printer_name. Tous les noms d'imprimantes dans le Service d'impression X sont encodés en COMPOUND_TEXT (dont le jeu de codes ISO-8859-1 est un sous-ensemble propre).

Dès qu'un contexte d'impression est créé, les attributs d'impression qu'il contient peuvent être accédés et modifiés en appelant XpGetAttributes et XpSetAttributes, et les sélections d'événements qu'il contient peuvent être modifiées en appelant XpSelectInput et XpInputSelected. D'autres appels Xp qui prennent explicitement un identifiant de contexte d'impression comme paramètre agiront directement sur ce contexte d'impression. Tous les appels Xp et X sans paramètre d'identifiant de contexte d'impression (par exemple, tous les appels orientés rendu comme XpStartJob et XDrawLine) nécessitent qu'un contexte d'impression soit défini sur la connexion d'affichage (voir XpSetContext). L'échec de la définition d'un contexte d'impression avant d'appeler un appel dépendant du contexte d'impression entraînera la génération d'une erreur XPBadContext.

Le XPContext retourné par XpCreateContext est un XID, et peut être utilisé pour définir le contexte d'impression sur les connexions d'affichage en appelant XpSetContext. L'identifiant XPContext peut être partagé entre les processus et les connexions d'affichage. Il appartient aux clients partageant un contexte d'impression de coordonner leur utilisation du contexte ; par exemple, ils doivent s'assurer que les contextes d'impression en cours d'utilisation ne soient pas détruits prématurément.

Le contexte_id reste valide pour tous les clients jusqu'à ce que 1) le client créant le contexte d'impression ferme sa connexion d'affichage, ou 2) un client quelconque appelle XpDestroyContext. Le contexte_id peut rester valide après la fermeture de la connexion d'affichage du client créateur si XSetCloseDownMode est appelé sur display avec RetainPermanent ou RetainTemporary.

Après avoir créé un contexte d'impression, et éventuellement modifié l'attribut XPDocAttr document-format en utilisant une valeur de la liste des formats disponibles indiqués dans l'attribut XPPrinterAttr document-formats-supported, l'application doit interroger le Serveur d'impression X via XpGetScreenOfContext pour obtenir l'écran qui a été associé au contexte d'impression, et ensuite créer toutes les ressources serveur qui seront utilisées dans le travail d'impression sur cet écran. Le non-respect de cette consigne entraînera un comportement indéfini.

Lorsque XpCreateContext est appelé, la locale du client (voir XpSetLocaleHinter) est incluse dans la requête comme un "indice" pour le Serveur d'impression X. Si l'implémentation le supporte, le Serveur d'impression X utilisera l'indice pour initialiser les pools d'attributs avec toutes les valeurs d'attributs localisées (par exemple, l'attribut XPPrinterAttr lisible par l'homme "descriptor" peut être disponible en plusieurs langues différentes, et l'indice sera utilisé pour en sélectionner une). Si le Serveur d'impression X ne peut pas comprendre l'indice, le Serveur d'impression X choisira une valeur par défaut.

Cette fonction peut générer une erreur BadMatch si le printer_name spécifié n'existe pas sur display, ou si le serveur d'impression n'a pas pu interpréter le jeu de codes spécifié dans printer_name.

DIAGNOSTICS

BadMatch
La valeur spécifiée pour doc_fmt n'est pas valide pour le type de document actuel ou la valeur spécifiée pour drawable n'est pas valide pour le contexte d'impression et l'écran d'impression.
