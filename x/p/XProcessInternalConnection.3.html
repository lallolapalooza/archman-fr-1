XAddConnectionWatch(3) FONCTIONS XLIB XAddConnectionWatch(3)

NOM

XAddConnectionWatch, XRemoveConnectionWatch, XProcessInternalConnection, XInternalConnectionNumbers - gérer les connexions internes Xlib

SYNTAXE

typedef void (*XConnectionWatchProc)(Display *display, XPointer client_data, int fd, Bool opening, XPointer *watch_data);

Status XAddConnectionWatch(Display *display, XConnectionWatchProc procedure, XPointer client_data);

void XRemoveConnectionWatch(Display *display, XConnectionWatchProc procedure, XPointer client_data);

void XProcessInternalConnection(Display *display, int fd);

Status XInternalConnectionNumbers(Display *display, int **fd_return, int *count_return);

ARGUMENTS

client_data
Spécifie les données client supplémentaires.
count_return
Retourne le nombre de descripteurs de fichiers.
display
Spécifie la connexion au serveur X.
fd
Spécifie le descripteur de fichier.
fd_return
Retourne les descripteurs de fichiers.
procedure
Spécifie la procédure à appeler.

DESCRIPTION

La fonction XAddConnectionWatch enregistre une procédure à appeler chaque fois que Xlib ouvre ou ferme une connexion interne pour l'affichage spécifié. La procédure reçoit l'affichage, les client_data spécifiés, le descripteur de fichier de la connexion, un booléen indiquant si la connexion est en cours d'ouverture ou de fermeture, et un pointeur vers un emplacement pour des données de surveillance privées. Si opening est True, la procédure peut stocker un pointeur vers des données privées dans l'emplacement pointé par watch_data ; lorsque la procédure est appelée plus tard pour la même connexion et que opening est False, l'emplacement pointé par watch_data contiendra ce même pointeur de données privées.

Cette fonction peut être appelée à tout moment après l'ouverture d'un affichage. Si des connexions internes existent déjà, la procédure enregistrée sera immédiatement appelée pour chacune d'elles, avant que XAddConnectionWatch ne retourne. XAddConnectionWatch renvoie un statut non nul si la procédure est enregistrée avec succès ; sinon, elle renvoie zéro.

La procédure enregistrée ne doit appeler aucune fonction Xlib. Si la procédure appelle directement ou indirectement les fonctions qui modifient l'état des connexions internes ou des procédures de surveillance, le résultat n'est pas défini. Si Xlib a été initialisé pour les threads, la procédure est appelée avec l'affichage verrouillé et le résultat d'un appel par la procédure à toute fonction Xlib qui verrouille l'affichage n'est pas défini, sauf si le thread exécutant a verrouillé l'affichage extérieurement à l'aide de XLockDisplay.

La fonction XRemoveConnectionWatch supprime une procédure de surveillance de connexion précédemment enregistrée. Les client_data doivent correspondre aux client_data utilisés lors de l'enregistrement initial de la procédure.

La fonction XProcessInternalConnection traite les entrées disponibles sur une connexion interne. Cette fonction ne doit être appelée pour une connexion interne qu'après qu'une installation du système d'exploitation (par exemple, select ou poll) ait indiqué que des entrées sont disponibles ; sinon, l'effet n'est pas défini.

La fonction XInternalConnectionNumbers renvoie une liste des descripteurs de fichiers pour toutes les connexions internes actuellement ouvertes pour l'affichage spécifié. Lorsque la liste allouée n'est plus nécessaire, libérez-la en utilisant XFree. Cette fonction renvoie un statut non nul si la liste est allouée avec succès ; sinon, elle renvoie zéro.
