X509_get_extension_flags(3ssl)

Paquet: openssl

Licences: Apache-2.0

X509_GET_EXTENSION_FLAGS(3ssl) OpenSSL X509_GET_EXTENSION_FLAGS(3ssl)

NOM

X509_get0_subject_key_id, X509_get0_authority_key_id, X509_get0_authority_issuer, X509_get0_authority_serial, X509_get_pathlen, X509_get_extension_flags, X509_get_key_usage, X509_get_extended_key_usage, X509_set_proxy_flag, X509_set_proxy_pathlen, X509_get_proxy_pathlen - récupérer les données d'extension de certificat

SYNTAXE

#include <openssl/x509v3.h>
long X509_get_pathlen(X509 *x);
uint32_t X509_get_extension_flags(X509 *x);
uint32_t X509_get_key_usage(X509 *x);
uint32_t X509_get_extended_key_usage(X509 *x);
const ASN1_OCTET_STRING *X509_get0_subject_key_id(X509 *x);
const ASN1_OCTET_STRING *X509_get0_authority_key_id(X509 *x);
const GENERAL_NAMES *X509_get0_authority_issuer(X509 *x);
const ASN1_INTEGER *X509_get0_authority_serial(X509 *x);
void X509_set_proxy_flag(X509 *x);
void X509_set_proxy_pathlen(int l);
long X509_get_proxy_pathlen(X509 *x);

DESCRIPTION

Ces fonctions récupèrent des informations relatives aux extensions de certificat couramment utilisées.

X509_get_pathlen() récupère l'extension de longueur de chemin d'un certificat. Cette extension est utilisée pour limiter la longueur d'une chaîne de certificats pouvant être émise à partir de cette AC.

X509_get_extension_flags() récupère des informations générales sur un certificat. Elle renvoie un ou plusieurs des drapeaux suivants, combinés par OU.

EXFLAG_V1
Le certificat est un certificat version 1 obsolète.
EXFLAG_BCONS
Le certificat contient une extension de contraintes de base.
EXFLAG_CA
Le certificat contient des contraintes de base et affirme le drapeau CA.
EXFLAG_PROXY
Le certificat est un certificat proxy valide.
EXFLAG_SI
Le certificat est auto-signé (c'est-à-dire que les noms du sujet et de l'émetteur correspondent).
EXFLAG_SS
Les noms du sujet et de l'émetteur correspondent et les valeurs d'extension impliquent qu'il est auto-signé.
EXFLAG_FRESHEST
L'extension CRL la plus récente est présente dans le certificat.
EXFLAG_CRITICAL
Le certificat contient une extension critique non traitée.
EXFLAG_INVALID
Certaines valeurs d'extension de certificat sont invalides ou incohérentes. Le certificat doit être rejeté. Ce bit peut également être levé après une erreur de manque de mémoire lors du traitement de l'objet X509, il peut donc ne pas être lié à l'objet ASN1 traité lui-même.
EXFLAG_NO_FINGERPRINT
Échec du calcul de la valeur de hachage SHA1 interne du certificat ou de la CRL. Cela peut être dû à un échec malloc ou à l'absence d'implémentation SHA1 trouvée.
EXFLAG_INVALID_POLICY
L'extension de certificat NID_certificate_policies est invalide ou incohérente. Le certificat doit être rejeté. Ce bit peut également être levé après une erreur de manque de mémoire lors du traitement de l'objet X509, il peut donc ne pas être lié à l'objet ASN1 traité lui-même.
EXFLAG_KUSAGE
Le certificat contient une extension d'utilisation de clé. La valeur peut être récupérée à l'aide de X509_get_key_usage().
EXFLAG_XKUSAGE
Le certificat contient une extension d'utilisation de clé étendue. La valeur peut être récupérée à l'aide de X509_get_extended_key_usage().

X509_get_key_usage() renvoie la valeur de l'extension d'utilisation de clé. Si l'utilisation de clé est présente, elle renvoie zéro ou plusieurs des drapeaux : KU_DIGITAL_SIGNATURE, KU_NON_REPUDIATION, KU_KEY_ENCIPHERMENT, KU_DATA_ENCIPHERMENT, KU_KEY_AGREEMENT, KU_KEY_CERT_SIGN, KU_CRL_SIGN, KU_ENCIPHER_ONLY ou KU_DECIPHER_ONLY correspondant aux bits d'utilisation de clé individuels. Si l'utilisation de clé est absente, UINT32_MAX est renvoyé.

X509_get_extended_key_usage() renvoie la valeur de l'extension d'utilisation de clé étendue. Si l'utilisation de clé étendue est présente, elle renvoie zéro ou plusieurs des drapeaux : XKU_SSL_SERVER, XKU_SSL_CLIENT, XKU_SMIME, XKU_CODE_SIGN XKU_OCSP_SIGN, XKU_TIMESTAMP, XKU_DVCS ou XKU_ANYEKU. Ceux-ci correspondent respectivement aux OID id-kp-serverAuth, id-kp-clientAuth, id-kp-emailProtection, id-kp-codeSigning, id-kp-OCSPSigning, id-kp-timeStamping, id-kp-dvcs et anyExtendedKeyUsage. De plus, XKU_SGC est défini si les OID Netscape ou Microsoft SGC sont présents.

X509_get0_subject_key_id() renvoie un pointeur interne vers l'identifiant de clé du sujet de x sous forme d'une ASN1_OCTET_STRING ou NULL si l'extension n'est pas présente ou ne peut pas être analysée.

X509_get0_authority_key_id() renvoie un pointeur interne vers l'identifiant de clé de l'autorité de x sous forme d'une ASN1_OCTET_STRING ou NULL si l'extension n'est pas présente ou ne peut pas être analysée.

X509_get0_authority_issuer() renvoie un pointeur interne vers l'émetteur du certificat d'autorité de x sous forme d'une pile de structures GENERAL_NAME ou NULL si l'extension n'est pas présente ou ne peut pas être analysée.

X509_get0_authority_serial() renvoie un pointeur interne vers le numéro de série du certificat d'autorité de x sous forme d'un ASN1_INTEGER ou NULL si l'extension n'est pas présente ou ne peut pas être analysée.

X509_set_proxy_flag() marque le certificat avec le drapeau EXFLAG_PROXY. Ceci est destiné aux utilisateurs qui ont besoin de marquer les certificats proxy non conformes à la RFC3820 comme tels, car OpenSSL ne détecte que ceux conformes à la RFC3820.

X509_set_proxy_pathlen() définit la longueur du chemin du certificat proxy pour le certificat x donné. Ceci est destiné aux utilisateurs qui ont besoin de marquer les certificats proxy non conformes à la RFC3820 comme tels, car OpenSSL ne détecte que ceux conformes à la RFC3820.

X509_get_proxy_pathlen() renvoie la longueur du chemin du certificat proxy pour le certificat x donné s'il s'agit d'un certificat proxy.

NOTES

La valeur des drapeaux correspond aux valeurs d'extension qui sont mémorisées dans la structure X509. Si les drapeaux renvoyés ne fournissent pas d'informations suffisantes, une application doit examiner les valeurs d'extension directement, par exemple en utilisant X509_get_ext_d2i().

Si l'extension d'utilisation de clé ou d'utilisation de clé étendue est absente, l'utilisation est généralement illimitée. Pour cette raison, X509_get_key_usage() et X509_get_extended_key_usage() renvoient UINT32_MAX lorsque l'extension correspondante est absente. Les applications peuvent également vérifier la valeur de retour de X509_get_extension_flags() et prendre les mesures appropriées si une extension est absente.

Si X509_get0_subject_key_id() renvoie NULL, l'extension peut être absente ou mal formée. Les applications peuvent déterminer la raison précise en utilisant X509_get_ext_d2i().

VALEUR DE RETOUR

X509_get_pathlen() renvoie la valeur de la longueur du chemin, ou -1 si l'extension n'est pas présente.

X509_get_extension_flags(), X509_get_key_usage() et X509_get_extended_key_usage() renvoient des ensembles de drapeaux correspondant aux valeurs d'extension du certificat.

X509_get0_subject_key_id() renvoie l'identifiant de clé du sujet sous forme d'un pointeur vers une structure ASN1_OCTET_STRING ou NULL si l'extension est absente ou si une erreur s'est produite lors de l'analyse.

X509_get_proxy_pathlen() renvoie la valeur de la longueur du chemin si le certificat donné est un certificat proxy et possède une longueur de chemin définie, et -1 sinon.
