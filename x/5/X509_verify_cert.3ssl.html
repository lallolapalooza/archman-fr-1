X509_VERIFY_CERT(3ssl) OpenSSL X509_VERIFY_CERT(3ssl)

NOM

X509_build_chain, X509_verify_cert, X509_STORE_CTX_verify - construire et vérifier la chaîne de certificats X509

SYNOPSIS

#include <openssl/x509_vfy.h>
STACK_OF(X509) *X509_build_chain(X509 *target, STACK_OF(X509) *certs,
                                 X509_STORE *store, int with_self_signed,
                                 OSSL_LIB_CTX *libctx, const char *propq);
int X509_verify_cert(X509_STORE_CTX *ctx);
int X509_STORE_CTX_verify(X509_STORE_CTX *ctx);

DESCRIPTION

X509_build_chain() construit une chaîne de certificats à partir de target en utilisant la liste optionnelle de certificats CA intermédiaires certs. Si store est NULL, elle construit la chaîne aussi loin que possible en ignorant les erreurs. Sinon, la chaîne doit atteindre un point de confiance contenu dans store. Elle utilise en interne une structure X509_STORE_CTX associée au contexte de bibliothèque libctx et à la chaîne de requêtes propq, qui peuvent tous deux être NULL. S'il existe plus d'une possibilité pour la chaîne, une seule est retenue.

En cas de succès, elle retourne un pointeur vers une nouvelle pile de certificats (avec référence incrémentée) commençant par target et suivie de tous les certificats intermédiaires disponibles. Une ancre de confiance auto-signée n'est incluse que si target est l'ancre de confiance et que with_self_signed est égal à 1. Si une pile non NULL est retournée, l'appelant est responsable de sa libération.

La fonction X509_verify_cert() tente de découvrir et de valider une chaîne de certificats en fonction des paramètres dans ctx. Le contexte de vérification, de type X509_STORE_CTX, peut être construit en utilisant X509_STORE_CTX_new(3) et X509_STORE_CTX_init(3). Il inclut généralement un certificat cible à vérifier, un ensemble de certificats servant d'ancres de confiance, une liste de certificats non fiables qui peuvent être utiles pour la construction de la chaîne, des indicateurs tels que X509_V_FLAG_X509_STRICT, et divers autres composants optionnels tels qu'une fonction de rappel qui permet de personnaliser le résultat de la vérification. Une description complète du processus de vérification des certificats est contenue dans la page de manuel openssl-verification-options(1).

Les applications appellent rarement cette fonction directement, mais elle est utilisée par OpenSSL en interne pour la validation des certificats, tant dans le code S/MIME que dans le code SSL/TLS.

Une valeur de retour négative de X509_verify_cert() peut survenir si elle est invoquée incorrectement, par exemple sans certificat défini dans ctx, ou si elle est appelée deux fois de suite sans réinitialiser ctx pour le second appel. Une valeur de retour négative peut également se produire en raison de problèmes de ressources internes ou parce qu'une incohérence interne a été détectée. Les applications doivent interpréter toute valeur de retour <= 0 comme une erreur.

La fonction X509_STORE_CTX_verify() se comporte comme X509_verify_cert(), sauf que son certificat cible est le premier élément de la liste des certificats non fiables dans ctx*, à moins qu'un certificat cible ne soit défini explicitement.

Lorsque la cible de vérification est une clé publique brute, plutôt qu'un certificat, les deux fonctions valident la clé publique brute cible. Dans ce cas, le nombre de vérifications possibles est considérablement réduit. La clé publique brute ne peut être authentifiée que via des enregistrements DANE TLSA, soit synthétisés localement, soit obtenus par l'application à partir du DNS. Les enregistrements DANE TLSA de clés publiques brutes peuvent être ajoutés via SSL_add_expected_rpk(3) ou SSL_dane_tlsa_add(3).

VALEURS DE RETOUR

X509_build_chain() retourne NULL en cas d'erreur, sinon une pile de certificats.

Les deux fonctions X509_verify_cert() et X509_STORE_CTX_verify() retournent 1 si une chaîne complète peut être construite et validée, sinon elles retournent 0, et dans des circonstances exceptionnelles (telles qu'une échec de malloc et des erreurs internes), elles peuvent également retourner un code négatif.

Si une chaîne complète peut être construite et validée, les deux fonctions retournent 1. Si le certificat doit être rejeté sur la base des données disponibles ou si des données de statut de certificat requises ne sont pas disponibles, elles retournent 0. S' aucune réponse définitive n'est possible, elles retournent généralement un code négatif.

En cas d'erreur ou d'échec, des informations d'erreur supplémentaires peuvent être obtenues en examinant ctx en utilisant, par exemple, X509_STORE_CTX_get_error(3). Même si la vérification a indiqué un succès, le code d'erreur stocké peut être différent de X509_V_OK, probablement parce qu'une fonction de rappel de vérification a outrepassé l'erreur.

VOIR AUSSI

HISTORIQUE
