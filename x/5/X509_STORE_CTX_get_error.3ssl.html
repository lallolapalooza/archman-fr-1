NOM

SYNTAXE

#include <openssl/x509.h>
int   X509_STORE_CTX_get_error(const X509_STORE_CTX *ctx);
void  X509_STORE_CTX_set_error(X509_STORE_CTX *ctx, int s);
int   X509_STORE_CTX_get_error_depth(const X509_STORE_CTX *ctx);
void  X509_STORE_CTX_set_error_depth(X509_STORE_CTX *ctx, int depth);
X509 *X509_STORE_CTX_get_current_cert(const X509_STORE_CTX *ctx);
void  X509_STORE_CTX_set_current_cert(X509_STORE_CTX *ctx, X509 *x);
X509 *X509_STORE_CTX_get0_cert(const X509_STORE_CTX *ctx);
STACK_OF(X509) *X509_STORE_CTX_get1_chain(const X509_STORE_CTX *ctx);
const char *X509_verify_cert_error_string(long n);

DESCRIPTION

Ces fonctions sont généralement appelées après que la vérification du certificat ou de la chaîne à l'aide de X509_verify_cert(3) ou X509_STORE_CTX_verify(3) a indiqué une erreur, ou dans une fonction de rappel de vérification pour déterminer la nature d'une erreur.

X509_STORE_CTX_get_error() renvoie le code d'erreur de ctx. ctx NE DOIT PAS être NULL. Voir la section "CODES D'ERREUR" pour une description complète de tous les codes d'erreur. Il peut renvoyer un code différent de X509_V_OK même si X509_verify_cert() n'a pas indiqué d'erreur, probablement parce qu'une fonction de rappel de vérification a ignoré l'erreur.

X509_STORE_CTX_set_error() définit le code d'erreur de ctx à s. Par exemple, il peut être utilisé dans une fonction de rappel de vérification pour définir une erreur basée sur des vérifications supplémentaires. ctx NE DOIT PAS être NULL.

X509_STORE_CTX_get_error_depth() renvoie la profondeur de l'erreur. Il s'agit d'un entier non négatif représentant où dans la chaîne de certificats l'erreur s'est produite. Si elle est de zéro, elle s'est produite dans le certificat de l'entité finale, un si c'est le certificat qui a signé le certificat de l'entité finale, et ainsi de suite. ctx NE DOIT PAS être NULL.

X509_STORE_CTX_set_error_depth() définit la profondeur de l'erreur. Cela peut être utilisé en combinaison avec X509_STORE_CTX_set_error() pour définir la profondeur à laquelle une condition d'erreur a été détectée.

X509_STORE_CTX_get_current_cert() renvoie le certificat courant dans ctx. Si une erreur s'est produite, le certificat courant sera celui qui est le plus étroitement lié à l'erreur, ou potentiellement NULL si aucun certificat pertinent n'est trouvé.

X509_STORE_CTX_set_current_cert() définit le certificat x dans ctx qui a causé l'erreur. Cette valeur n'est pas censée rester valide très longtemps et reste la propriété de l'appelant. Elle peut être examinée par une fonction de rappel de vérification invoquée pour gérer chaque erreur rencontrée lors de la vérification de la chaîne et n'est plus requise après le retour de cette fonction de rappel. Si une fonction de rappel souhaite sauvegarder le certificat pour une utilisation après son retour, elle doit incrémenter son compteur de références via X509_up_ref(3). Une fois que ce certificat sauvegardé n'est plus nécessaire, il peut être libéré avec X509_free(3).

X509_STORE_CTX_get0_cert() récupère un pointeur interne vers le certificat en cours de vérification par le ctx. Il peut être NULL si une clé publique brute est en cours de vérification.

X509_STORE_CTX_get1_chain() renvoie une chaîne de validation complète si une vérification précédente a réussi. Sinon, la chaîne retournée peut être incomplète ou invalide. La chaîne retournée persiste après que la structure ctx est libérée. Lorsqu'elle n'est plus nécessaire, elle doit être libérée en utilisant :

OSSL_STACK_OF(X509)_free(chain);

X509_verify_cert_error_string() renvoie une chaîne d'erreur lisible par l'homme pour l'erreur de vérification n.

VALEURS DE RETOUR

X509_STORE_CTX_get_error() renvoie X509_V_OK ou un code d'erreur.

X509_STORE_CTX_get_error_depth() renvoie une profondeur d'erreur non négative.

X509_STORE_CTX_get_current_cert() renvoie le certificat qui a causé l'erreur ou NULL si aucun certificat n'est pertinent pour l'erreur.

X509_verify_cert_error_string() renvoie une chaîne d'erreur lisible par l'homme pour l'erreur de vérification n.

DESCRIPTION

The X509_STORE_CTX structure is used to hold the context for a certificate verification operation. This context contains information about the certificate chain being verified, the trusted certificates available, and various parameters and results of the verification process.

The functions described here allow applications to access and manipulate this context.

X509_STORE_CTX_init() initializes the context structure ctx. The store parameter is the certificate store containing trusted certificates. The cert parameter is the certificate to be verified. The chain parameter is a stack of intermediate certificates.

X509_STORE_CTX_verify() performs the certificate verification using the context initialized by X509_STORE_CTX_init().

X509_STORE_CTX_cleanup() cleans up the context structure ctx, freeing any allocated resources.

X509_STORE_CTX_get_error() returns the error code from the last verification operation. If the verification was successful, it returns 0. Otherwise, it returns a value corresponding to one of the error codes listed below.

X509_STORE_CTX_set_error() sets the error code in the context ctx to error.

X509_STORE_CTX_get_error_depth() returns the current depth of the certificate chain being processed. The depth is 0 for the end-entity certificate, 1 for the first intermediate CA, and so on.

X509_STORE_CTX_set_error_depth() sets the current error depth.

X509_verify_cert_error_string() returns a human-readable string describing the error code n.

X509_STORE_CTX_get_current_cert() returns the current certificate being processed in the verification chain. This is useful for debugging and error reporting.

X509_STORE_CTX_set_current_cert() sets the current certificate in the context.

X509_STORE_CTX_get_chain() returns the stack of intermediate certificates in the verification context.

X509_STORE_CTX_get_ex_data() and X509_STORE_CTX_set_ex_data() are used for managing application-specific data associated with the verification context. idx is an index obtained from X509_STORE_CTX_get_ex_new_index().

X509_STORE_CTX_get_ex_new_index() obtains a new index for application-specific data. The new_func, dup_func, and free_func parameters specify functions for creating, duplicating, and freeing the application-specific data.

RETURN VALUES

X509_STORE_CTX_init(), X509_STORE_CTX_verify(), and X509_STORE_CTX_set_ex_data() return 1 on success, and 0 on failure.

X509_STORE_CTX_get_error(), X509_STORE_CTX_get_error_depth(), X509_STORE_CTX_get_ex_data(), and X509_STORE_CTX_get_ex_new_index() return the requested value or index.

X509_verify_cert_error_string() returns a pointer to a static string describing the error.

X509_STORE_CTX_get_current_cert() and X509_STORE_CTX_get_chain() return pointers to X509 objects or stacks.

NOTES

The above functions should be used instead of directly referencing the fields in the X509_VERIFY_CTX structure.

In versions of OpenSSL before 1.0 the current certificate returned by X509_STORE_CTX_get_current_cert() was never NULL. Applications should check the return value before printing out any debugging information relating to the current certificate.

If an unrecognised error code is passed to X509_verify_cert_error_string() the numerical value of the unknown code is returned in a static buffer. This is not thread safe but will never happen unless an invalid code is passed.
