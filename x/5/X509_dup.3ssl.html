ASN1_ITEM_dup(3) — OpenSSL — Documentation d'une page man d'Arch Linux

NAME

ASN1_ITEM_dup, ASN1_ITEM_free, ASN1_ITEM_new, DECLARE_ASN1_FUNCTIONS, IMPLEMENT_ASN1_FUNCTIONS, TYPE_print_ctx - Gestion des structures de données ASN.1

SYNOPSIS

#include <openssl/asn1t.h>
DECLARE_ASN1_FUNCTIONS(type)
IMPLEMENT_ASN1_FUNCTIONS(stname)
typedef struct ASN1_ITEM_st ASN1_ITEM;
extern const ASN1_ITEM TYPE_it;
TYPE *TYPE_new(void);
TYPE *TYPE_dup(const TYPE *a);
void TYPE_free(TYPE *a);
int TYPE_print_ctx(BIO *out, TYPE *a, int indent, const ASN1_PCTX *pctx);

Les fonctions suivantes ont été dépréciées depuis OpenSSL 3.0 et peuvent être entièrement masquées en définissant OPENSSL_API_COMPAT avec une valeur de version appropriée, voir openssl_user_macros(7) :

DSA *DSAparams_dup(const DSA *dsa);
RSA *RSAPrivateKey_dup(const RSA *rsa);
RSA *RSAPublicKey_dup(const RSA *rsa);

DESCRIPTION

Dans la description ci-dessous, TYPE est utilisé comme espace réservé pour tout type de données OpenSSL, tel que X509.

Les modèles de la bibliothèque d'analyse ASN.1 OpenSSL sont comme un interpréteur de bytecode piloté par les données. Chaque objet ASN.1 possède une variable globale, TYPE_it, qui décrit l'élément tel que ses champs. (Sur les systèmes qui ne peuvent pas exporter de variables à partir de bibliothèques partagées, la variable globale est à la place une fonction qui renvoie un pointeur vers une variable statique.

La macro DECLARE_ASN1_FUNCTIONS() est généralement utilisée dans les fichiers d'en-tête pour générer les déclarations de fonctions.

La macro IMPLEMENT_ASN1_FUNCTIONS() est utilisée une seule fois dans un fichier source pour générer les corps des fonctions.

TYPE_new() alloue un objet vide du type indiqué. L'objet retourné doit être libéré en appelant TYPE_free().

TYPE_new_ex() est similaire à TYPE_new() mais passe également le contexte de la bibliothèque libctx et la requête de propriété propq à utiliser lors de la récupération d'algorithmes auprès des fournisseurs. Cet objet créé peut ensuite être utilisé lors du chargement de données binaires à l'aide de d2i_TYPE().

TYPE_dup() copie un objet existant, en le laissant inchangé. Notez, cependant, que la représentation interne de l'objet peut contenir (outre la structure ASN.1) d'autres données qui ne sont pas copiées. Par exemple, un objet X509 est généralement augmenté par des informations mises en cache sur les extensions X.509v3, etc., et les perdre peut entraîner des résultats de validation erronés. Pour éviter de telles situations, il est préférable d'utiliser TYPE_up_ref() si disponible. Dans le cas des objets X509, une alternative à l'utilisation de X509_up_ref(3) peut être d'appeler toujours TYPE_dup(), par exemple, copied_cert = X509_dup(cert), suivi de X509_check_purpose(copied_cert, -1, 0), ce qui reconstruit les données mises en cache.

TYPE_free() libère l'objet et tous les pointeurs et sous-objets qu'il contient. Si l'argument est NULL, rien n'est fait.

TYPE_print_ctx() imprime l'objet a sur le BIO spécifié out. Chaque ligne sera préfixée par indent espaces. Le pctx spécifie le contexte d'impression et est destiné à un usage interne ; utilisez NULL pour obtenir le comportement par défaut. Si une fonction d'impression est définie par l'utilisateur, passez n'importe quel pctx aux appels imbriqués.

VALEURS DE RETOUR

TYPE_new(), TYPE_new_ex() et TYPE_dup() renvoient un pointeur vers l'objet ou NULL en cas d'échec.

TYPE_print_ctx() renvoie 1 en cas de succès ou zéro en cas d'échec.
