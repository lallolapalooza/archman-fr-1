Paquet: openssl

Licences: Apache-2.0

X509_NAME_PRINT_EX(3ssl) OpenSSL X509_NAME_PRINT_EX(3ssl)

NOM

X509_NAME_print_ex, X509_NAME_print_ex_fp, X509_NAME_print, X509_NAME_oneline - Routines d'impression de X509_NAME

SYNOPSIS

#include <openssl/x509.h>
int X509_NAME_print_ex(BIO *out, const X509_NAME *nm,
                       int indent, unsigned long flags);
int X509_NAME_print_ex_fp(FILE *fp, const X509_NAME *nm,
                          int indent, unsigned long flags);
char *X509_NAME_oneline(const X509_NAME *a, char *buf, int size);
int X509_NAME_print(BIO *bp, const X509_NAME *name, int obase);

DESCRIPTION

X509_NAME_print_ex() imprime une version lisible par l'homme de nm dans le BIO out. Chaque ligne (pour les formats multilignes) est indentée de indent espaces. Le format de sortie peut être largement personnalisé grâce au paramètre flags.

X509_NAME_print_ex_fp() est identique à X509_NAME_print_ex(), sauf que la sortie est écrite dans le pointeur de fichier fp.

X509_NAME_oneline() imprime une version ASCII de a dans buf. Cela prend en charge les RDN multivalués et échappe les caractères / et + dans les valeurs. Si buf est **NULL**, un tampon est alloué dynamiquement et retourné, et size est ignoré. Sinon, au plus size octets seront écrits, y compris le caractère nul de fin '\0', et buf est retourné.

X509_NAME_print() imprime name dans bp en indenter chaque ligne de obase caractères. Des lignes multiples sont utilisées si la sortie (y compris l'indentation) dépasse 80 caractères.

NOTES

Les fonctions X509_NAME_oneline() et X509_NAME_print() produisent une forme de sortie non standard, elles ne gèrent pas les champs multi-caractères et présentent diverses particularités et incohérences. Leur utilisation est fortement déconseillée dans les nouvelles applications et elles pourraient être obsolètes dans une future version.

Bien qu'il existe un grand nombre de drapeaux possibles, pour la plupart des usages, XN_FLAG_ONELINE, XN_FLAG_MULTILINE ou XN_FLAG_RFC2253 suffiront. Comme indiqué sur la page de manuel de ASN1_STRING_print_ex(3), pour les terminaux UTF8, ASN1_STRFLGS_ESC_MSB doit être désactivé : ainsi, par exemple, XN_FLAG_ONELINE & ~ASN1_STRFLGS_ESC_MSB serait utilisé.

L'ensemble complet des drapeaux pris en charge par X509_NAME_print_ex() est listé ci-dessous.

Plusieurs options peuvent être combinées par l'opérateur OU.

Les options XN_FLAG_SEP_COMMA_PLUS, XN_FLAG_SEP_CPLUS_SPC, XN_FLAG_SEP_SPLUS_SPC et XN_FLAG_SEP_MULTILINE déterminent les séparateurs de champs à utiliser. Deux séparateurs distincts sont utilisés entre les différents composants RelativeDistinguishedName et séparent les valeurs dans le même RDN pour un RDN multivalué. Les RDN multivalués sont actuellement très rares, donc le second séparateur ne sera presque jamais utilisé.

XN_FLAG_SEP_COMMA_PLUS utilise la virgule et le plus comme séparateurs. XN_FLAG_SEP_CPLUS_SPC utilise la virgule et le plus avec des espaces : c'est plus lisible que la virgule et le plus seuls. XN_FLAG_SEP_SPLUS_SPC utilise le point-virgule espacé et le plus. XN_FLAG_SEP_MULTILINE utilise respectivement une nouvelle ligne espacée et le plus.

Si XN_FLAG_DN_REV est défini, le DN entier est imprimé en ordre inversé.

Les champs XN_FLAG_FN_SN, XN_FLAG_FN_LN, XN_FLAG_FN_OID, XN_FLAG_FN_NONE déterminent comment un nom de champ est affiché. Il utilisera le nom court (par exemple, CN), le nom long (par exemple, commonName), utilisera toujours la forme numérique de l'OID (normalement, les OID ne sont utilisés que si le nom du champ n'est pas reconnu) et aucun nom de champ respectivement.

Si XN_FLAG_SPC_EQ est défini, des espaces seront placés autour du caractère '=' séparant les noms de champs et les valeurs.

Si XN_FLAG_DUMP_UNKNOWN_FIELDS est défini, le codage des champs inconnus sera imprimé au lieu des valeurs.

Si XN_FLAG_FN_ALIGN est défini, les noms des champs seront remplis sur 20 caractères : ceci n'est utile que pour le format multiligne.

De plus, toutes les options prises en charge par ASN1_STRING_print_ex() peuvent être utilisées pour contrôler la manière dont chaque valeur de champ est affichée.

En outre, un certain nombre d'options peuvent être définies pour des formats couramment utilisés.

XN_FLAG_RFC2253 définit les options qui produisent une sortie compatible avec RFC2253. Elle est équivalente à :
"ASN1_STRFLGS_RFC2253 | XN_FLAG_SEP_COMMA_PLUS | XN_FLAG_DN_REV
| XN_FLAG_FN_SN | XN_FLAG_DUMP_UNKNOWN_FIELDS"

XN_FLAG_ONELINE est un format sur une seule ligne plus lisible, qui est identique à :
"ASN1_STRFLGS_RFC2253 | ASN1_STRFLGS_ESC_QUOTE | XN_FLAG_SEP_CPLUS_SPC
| XN_FLAG_SPC_EQ | XN_FLAG_FN_SN"

XN_FLAG_MULTILINE est un format multiligne qui est identique à :
"ASN1_STRFLGS_ESC_CTRL | ASN1_STRFLGS_ESC_MSB | XN_FLAG_SEP_MULTILINE
| XN_FLAG_SPC_EQ | XN_FLAG_FN_LN | XN_FLAG_FN_ALIGN"

XN_FLAG_COMPAT utilise un format identique à X509_NAME_print() : en fait, il appelle X509_NAME_print() en interne.

VALEURS DE RETOUR

X509_NAME_oneline() renvoie une chaîne de caractères valide en cas de succès ou **NULL** en cas d'erreur.

X509_NAME_print() renvoie 1 en cas de succès ou 0 en cas d'erreur.

X509_NAME_print_ex() et X509_NAME_print_ex_fp() renvoient 1 en cas de succès ou 0 en cas d'erreur si XN_FLAG_COMPAT est défini, ce qui est identique à X509_NAME_print(). Sinon, il renvoie -1 en cas d'erreur ou d'autres valeurs en cas de succès.
