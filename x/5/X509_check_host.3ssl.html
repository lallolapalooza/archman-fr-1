X509_CHECK_HOST(3ssl) OpenSSL X509_CHECK_HOST(3ssl)

NOM

X509_check_host, X509_check_email, X509_check_ip, X509_check_ip_asc - Correspondance de certificat X.509

SYNTAXE

#include <openssl/x509v3.h>
int X509_check_host(X509 *, const char *name, size_t namelen,
                    unsigned int flags, char **peername);
int X509_check_email(X509 *, const char *address, size_t addresslen,
                     unsigned int flags);
int X509_check_ip(X509 *, const unsigned char *address, size_t addresslen,
                  unsigned int flags);
int X509_check_ip_asc(X509 *, const char *address, unsigned int flags);

DESCRIPTION

Les fonctions de correspondance de certificat sont utilisées pour vérifier si un certificat correspond à un nom d'hôte, une adresse e-mail ou une adresse IP donné(e). La validité du certificat et son niveau de confiance doivent être vérifiés par d'autres moyens.

X509_check_host() vérifie si le nom alternatif du sujet (SAN) ou le nom commun du sujet (CN) du certificat correspond au nom d'hôte spécifié, qui doit être encodé dans la syntaxe de nom préférée décrite dans la section 3.5 de la RFC 1034. Par défaut, les jokers sont pris en charge et ils correspondent uniquement au label le plus à gauche ; mais ils peuvent correspondre à une partie de ce label avec un préfixe ou un suffixe explicite. Par exemple, par défaut, le nom d'hôte name "www.example.com" correspondra à un certificat avec une valeur SAN ou CN de "*.example.com", "w*.example.com" ou "*w.example.com".

Conformément à la section 6.4.2 de la RFC 6125, les valeurs de name représentant des noms de domaine internationaux doivent être fournies sous forme d'étiquette A. L'argument namelen doit être le nombre de caractères dans la chaîne de nom ou zéro auquel cas la longueur est calculée avec strlen(name). Lorsque name commence par un point (par exemple, ".example.com"), il correspondra à un certificat valide pour n'importe quel sous-domaine de name (voir également X509_CHECK_FLAG_SINGLE_LABEL_SUBDOMAINS ci-dessous).

Lorsque le certificat correspond et que peername n'est pas NULL, un pointeur vers une copie du SAN ou du CN correspondant du certificat pair est stocké à l'adresse passée dans peername. L'application est responsable de libérer peername via OPENSSL_free() lorsqu'il n'est plus nécessaire.

X509_check_email() vérifie si le certificat correspond à l'adresse e-mail spécifiée address. La syntaxe de boîte aux lettres de la RFC 822 est prise en charge, les commentaires ne sont pas autorisés et aucune tentative n'est faite pour normaliser les caractères entre guillemets. La syntaxe de boîte aux lettres de la RFC 6531 est prise en charge pour les adresses SmtpUTF8Mailbox dans subjectAltName conformément à la RFC 8398, avec des limitations similaires à celles de la syntaxe RFC 822, et aucune tentative n'est faite pour convertir de l'étiquette A à l'étiquette U avant la comparaison. L'argument addresslen doit être le nombre de caractères dans la chaîne d'adresse ou zéro auquel cas la longueur est calculée avec strlen(address).

X509_check_ip() vérifie si le certificat correspond à une adresse IPv4 ou IPv6 spécifiée. Le tableau address est au format binaire, en ordre d'octets réseau. La longueur est de 4 (IPv4) ou 16 (IPv6). Seules les adresses explicitement marquées dans les certificats sont prises en compte ; les adresses IP stockées dans les noms DNS et les noms communs sont ignorées. Il n'y a actuellement aucun flags qui affecterait le comportement de cet appel.

X509_check_ip_asc() est similaire, sauf que la chaîne se terminant par un NUL address est d'abord convertie en la représentation interne.

L'argument flags est généralement 0. Il peut être le OU binaire des indicateurs suivants :

X509_CHECK_FLAG_ALWAYS_CHECK_SUBJECT,
X509_CHECK_FLAG_NEVER_CHECK_SUBJECT,
X509_CHECK_FLAG_NO_WILDCARDS,
X509_CHECK_FLAG_NO_PARTIAL_WILDCARDS,
X509_CHECK_FLAG_MULTI_LABEL_WILDCARDS.
X509_CHECK_FLAG_SINGLE_LABEL_SUBDOMAINS.

L'indicateur X509_CHECK_FLAG_ALWAYS_CHECK_SUBJECT fait que la fonction prend en compte le DN du sujet même si le certificat contient au moins un nom alternatif du sujet du bon type (nom DNS ou adresse e-mail selon le cas) ; par défaut, le DN du sujet est ignoré lorsqu'au moins un nom alternatif correspondant est présent.

L'indicateur X509_CHECK_FLAG_NEVER_CHECK_SUBJECT fait que la fonction ne prend jamais en compte le DN du sujet même si le certificat ne contient aucun nom alternatif du sujet du bon type (nom DNS ou adresse e-mail selon le cas) ; par défaut, le DN du sujet est utilisé lorsqu'aucun nom alternatif correspondant n'est présent. Si X509_CHECK_FLAG_ALWAYS_CHECK_SUBJECT et X509_CHECK_FLAG_NEVER_CHECK_SUBJECT sont tous deux spécifiés, le dernier a la priorité et le DN du sujet n'est pas vérifié pour les noms correspondants.

Si défini, X509_CHECK_FLAG_NO_WILDCARDS désactive l'expansion des jokers ; cela ne s'applique qu'à X509_check_host.

Si défini, X509_CHECK_FLAG_NO_PARTIAL_WILDCARDS supprime la prise en charge de "*" comme motif joker dans les labels ayant un préfixe ou un suffixe, tels que : "www*" ou "*www" ; cela ne s'applique qu'à X509_check_host.

Si défini, X509_CHECK_FLAG_MULTI_LABEL_WILDCARDS permet à un "*" qui constitue le label complet d'un nom DNS (par exemple, "*.example.com") de correspondre à plus d'un label dans name ; cet indicateur ne s'applique qu'à X509_check_host.

Si défini, X509_CHECK_FLAG_SINGLE_LABEL_SUBDOMAINS restreint les valeurs de name commençant par ".", qui correspondraient autrement à n'importe quel sous-domaine dans le certificat pair, à ne correspondre qu'aux sous-domaines enfants directs. Ainsi, par exemple, avec cet indicateur défini, un name de ".example.com" correspondrait à un certificat pair avec un nom DNS de "www.example.com", mais ne correspondrait pas à un certificat pair avec un nom DNS de "www.sub.example.com" ; cet indicateur ne s'applique qu'à X509_check_host.

VALEURS DE RETOUR

Les fonctions renvoient 1 en cas de correspondance réussie, 0 en cas d'échec de correspondance et -1 en cas d'erreur interne : typiquement une échec d'allocation mémoire ou une erreur de décodage ASN.1.

Toutes les fonctions peuvent également renvoyer -2 si l'entrée est mal formée. Par exemple, X509_check_host() renvoie -2 si le name fourni contient des NUL intégrés.

NOTES

Il est conseillé aux applications d'utiliser X509_VERIFY_PARAM_set1_host() plutôt que d'appeler explicitement X509_check_host(3). Les vérifications de noms d'hôtes peuvent être hors périmètre avec l'utilisation du certificat DANE-EE(3), et les vérifications internes seront supprimées si nécessaire lorsque le support DANE est activé.
