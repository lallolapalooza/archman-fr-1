DESCRIPTION

XML::LibXML::Node définit les fonctions communes à tous les types de nœuds. Un nœud XML::LibXML ne doit jamais être créé indépendamment, mais comme une instance d'une classe de haut niveau telle que XML::LibXML::Element ou XML::LibXML::Text. La classe elle-même ne devrait fournir que les fonctionnalités communes. Dans XML::LibXML, chaque nœud fait partie soit d'un document, soit d'un fragment de document. Pour cette raison, il n'existe pas de nœud sans parent. Cela peut prêter à confusion avec les nœuds "détachés".

MÉTHODES

De nombreuses fonctions listées ici sont largement documentées dans la spécification DOM Level 3 (http://www.w3.org/TR/DOM-Level-3-Core/). Veuillez vous référer à la spécification pour une documentation complète.

nodeName
$nom = $noeud->nodeName;

Retourne le nom du nœud. Cette fonction est consciente des espaces de noms et retourne le nom complet du nœud actuel ("prefix:nomlocal").

Depuis la version 1.62, cette fonction retourne également les noms DOM corrects pour les types de nœuds avec des noms constants, à savoir : #text, #cdata-section, #comment, #document, #document-fragment.

setNodeName
$noeud->setNodeName( $nouveauNom );

Dans des situations très limitées, il est utile de changer le nom d'un nœud. Dans la spécification DOM, cela devrait générer une erreur. Cette fonction est consciente des espaces de noms.

isSameNode
$bool = $noeud->isSameNode( $autre_noeud );

Retourne VRAI (1) si les nœuds donnés font référence à la même structure de nœud, sinon FAUX (0) est retourné.

isEqual
$bool = $noeud->isEqual( $autre_noeud );

Version obsolète de isSameNode().

NOTE : isEqual changera son comportement pour suivre la spécification DOM.

unique_key
$num = $noeud->unique_key;

Cette fonction n'est spécifiée pour aucun niveau DOM. Elle retourne une clé garantie unique pour ce nœud, et qui sera toujours la même valeur pour ce nœud. En d'autres termes, deux objets nœuds retournent la même clé si et seulement si isSameNode indique qu'ils sont le même nœud.

La valeur de clé retournée est utile comme clé dans les hachages.

nodeValue
$contenu = $noeud->nodeValue;

Si le nœud a un contenu (comme celui stocké dans un "nœud texte"), il peut être récupéré via cette fonction.

NOTE : Les nœuds d'élément n'ont pas de contenu par définition. Pour obtenir la valeur textuelle d'un élément, utilisez plutôt textContent() !

textContent
$contenu = $noeud->textContent;

Cette fonction retourne le contenu de tous les nœuds texte dans les descendants du nœud donné, conformément à la spécification DOM.

nodeType
$type = $noeud->nodeType;

Retourne une valeur numérique représentant le type de nœud de ce nœud. Le module XML::LibXML exporte par défaut des constantes pour les types de nœuds (voir la section EXPORT dans la page de manuel XML::LibXML).

unbindNode
$noeud->unbindNode();

Détache le nœud de ses frères et sœurs et de son parent, mais pas du document auquel il appartient. Si le nœud n'est pas inséré dans le DOM par la suite, il sera perdu après la fin du programme. D'un point de vue de bas niveau, le nœud détaché est dépouillé du contexte qu'il occupe et inséré dans un fragment de document (caché).

removeChild
$noeud_enfant = $noeud->removeChild( $noeud_enfant );

Ceci détachera le nœud enfant de son parent $noeud. La fonction retourne le nœud détaché. Si $noeud_enfant n'est pas un enfant du nœud donné, la fonction échouera.

replaceChild
$ancien_noeud = $noeud->replaceChild( $nouveau_noeud, $ancien_noeud );

Remplace $ancien_noeud par $nouveau_noeud. $ancien_noeud sera détaché du nœud. Cette fonction diffère de la spécification DOM L2, car si le nouveau nœud ne fait pas partie du document, il sera d'abord importé.

replaceNode
$noeud->replaceNode($nouveau_noeud);

Cette fonction est très similaire à replaceChild(), mais elle remplace le nœud lui-même plutôt qu'un nœud enfant. Ceci est utile si un nœud trouvé par une fonction XPath doit être remplacé.

appendChild
$noeud_enfant = $noeud->appendChild( $noeud_enfant );

La fonction ajoutera le $noeud_enfant à la fin des enfants de $noeud. La fonction devrait échouer si le nouveau nœud enfant est déjà un enfant de $noeud. Cette fonction diffère de la spécification DOM L2, car si le nouveau nœud ne fait pas partie du document, il sera d'abord importé.

addChild
$noeud_enfant = $noeud->addChild( $noeud_enfant );

En alternative à appendChild(), on peut utiliser la fonction addChild(). Cette fonction est un peu plus rapide car elle évite toutes les vérifications de conformité DOM. Par conséquent, elle est plus rapide mais peut également échouer si le nœud enfant est déjà un enfant du nœud parent.

addNewChild
$noeud = $parent->addNewChild( $nsURI, $nom );

Crée un nouveau nœud enfant avec le nom $nom et le namespace $nsURI. Le nouveau nœud enfant est ajouté à la fin de la liste des enfants de $parent. Le nœud créé est retourné.

Pour les éléments sans namespace, $nsURI peut être undef.

addSibling
$noeud->addSibling($nouveau_noeud);

Ajoute $nouveau_noeud comme un frère après le nœud courant. Le nœud courant est le nœud parent.

cloneNode
$nouveau_noeud =$noeud->cloneNode( $prof );

Retourne une copie du nœud. Si $prof vaut TRUE, la copie sera profonde (tous les descendants seront également copiés).

parentNode
$noeud_parent = $noeud->parentNode;

Retourne le nœud parent du nœud courant.

nextSibling
$prochain_noeud = $noeud->nextSibling();

Retourne le prochain nœud frère.

nextNonBlankSibling
$prochain_noeud = $noeud->nextNonBlankSibling();

Retourne le prochain nœud frère qui n'est pas un nœud blanc (texte, commentaires, etc.).

previousSibling
$noeud_precedent = $noeud->previousSibling();

Retourne le nœud frère précédent.

previousNonBlankSibling
$noeud_precedent = $noeud->previousNonBlankSibling();

Retourne le nœud frère précédent qui n'est pas un nœud blanc.

hasChildNodes
$bool = $noeud->hasChildNodes();

Retourne TRUE (1) si le nœud a des enfants, FALSE (0) sinon.

firstChild
$noeud_enfant = $noeud->firstChild;

Retourne le premier nœud enfant.

lastChild
$noeud_enfant = $noeud->lastChild;

Retourne le dernier nœud enfant.

ownerDocument
$document_noeud = $noeud->ownerDocument;

Retourne le nœud document auquel ce nœud appartient.

getOwner
$noeud = $noeud->getOwner;

Identique à ownerDocument().

setOwnerDocument
$noeud->setOwnerDocument( $doc );

Définit le document propriétaire de ce nœud.

insertBefore
$noeud->insertBefore( $nouveau_noeud, $noeud_ref );

Insère $nouveau_noeud comme enfant avant $noeud_ref. Si $noeud_ref est undef, $nouveau_noeud est ajouté à la fin.

insertAfter
$noeud->insertAfter( $nouveau_noeud, $noeud_ref );

Insère $nouveau_noeud comme enfant après $noeud_ref. Si $noeud_ref est undef, $nouveau_noeud est ajouté au début.

findnodes
@noeuds = $noeud->findnodes( $expression_xpath );

Retourne une liste de tous les nœuds qui correspondent à l'expression XPath spécifiée. Les nœuds sont retournés dans l'ordre où ils apparaissent dans le document.

find
$resultat = $noeud->find( $xpath );

Fonctionne comme findnodes(), mais retourne le premier résultat seulement.

findvalue
print $noeud->findvalue( $xpath );

Retourne la valeur du premier nœud correspondant à l'expression XPath.

exists
$bool = $noeud->exists( $expression_xpath );

Retourne TRUE (1) si au moins un nœud correspond à l'expression XPath, FALSE (0) sinon.

childNodes
@noeuds_enfants = $noeud->childNodes();

Retourne une liste de tous les nœuds enfants du nœud courant.

nonBlankChildNodes
@noeuds_enfants = $noeud->nonBlankChildNodes();

Retourne une liste de tous les nœuds enfants du nœud courant qui ne sont pas des nœuds blancs (texte, commentaires, etc.).

toString
$chaine_xml = $noeud->toString($format,$encodage_doc);

Retourne la représentation XML du nœud courant. Si $format est TRUE, le code XML sera formaté avec des indentations. $encodage_doc spécifie l'encodage du document XML.

toStringC14N
$chaine_c14n = $noeud->toStringC14N();
$chaine_c14n = $noeud->toStringC14N($avec_commentaires, $expression_xpath , $contexte_xpath );

Retourne la représentation C14N (Canonical XML) du nœud courant. La spécification est disponible sur http://www.w3.org/TR/xml-c14n. Si $avec_commentaires est TRUE, les commentaires seront inclus.

Les arguments optionnels $expression_xpath et $contexte_xpath sont utilisés pour définir un sous-ensemble de nœuds à canoniser.

toStringC14N_v1_1
$chaine_c14n = $noeud->toStringC14N_v1_1();
$chaine_c14n = $noeud->toStringC14N_v1_1($avec_commentaires, $expression_xpath , $contexte_xpath );

Idem que toStringC14N(), mais utilise la version 1.1 de la spécification C14N.

toStringEC14N
$chaine_ec14n = $noeud->toStringEC14N();
$chaine_ec14n = $noeud->toStringEC14N($avec_commentaires, $expression_xpath, $liste_prefix_inclus);
$chaine_ec14n = $noeud->toStringEC14N($avec_commentaires, $expression_xpath, $contexte_xpath, $liste_prefix_inclus);

Retourne la représentation EC14N (Exclusive Canonical XML) du nœud courant. La spécification est disponible sur http://www.w3.org/TR/xml-exc-c14n/. Si $avec_commentaires est TRUE, les commentaires seront inclus.

$liste_prefix_inclus est une liste de préfixes d'espaces de noms à inclure de manière exclusive.

Les arguments optionnels $expression_xpath et $contexte_xpath sont utilisés pour définir un sous-ensemble de nœuds à canoniser.

serialize
$str = $doc->serialize($format);

Retourne le document entier sous forme de chaîne de caractères. Si $format est TRUE, le code XML sera formaté.

localname
$nom_local = $noeud->localname;

Retourne le nom local du nœud (sans préfixe).

prefix
$prefix_nom = $noeud->prefix;

Retourne le préfixe d'espace de noms du nœud.

namespaceURI
$uri = $noeud->namespaceURI();

Retourne l'URI d'espace de noms du nœud.

hasAttributes
$bool = $noeud->hasAttributes();

Retourne TRUE (1) si le nœud a des attributs, FALSE (0) sinon.

attributes
@liste_attributs = $noeud->attributes();

Retourne une liste des attributs du nœud courant.

lookupNamespaceURI
$URI = $noeud->lookupNamespaceURI( $prefix );

Recherche l'URI d'espace de noms associé au préfixe donné, en remontant dans la hiérarchie des ancêtres si nécessaire.

lookupNamespacePrefix
$prefix = $noeud->lookupNamespacePrefix( $URI );

Recherche un préfixe associé à l'URI d'espace de noms donné, en remontant dans la hiérarchie des ancêtres si nécessaire.

normalize
$noeud->normalize;

Normalise le nœud. Combine les nœuds texte adjacents et supprime les nœuds vides.

getNamespaces
@liste_ns = $noeud->getNamespaces;

Retourne une liste des déclarations d'espaces de noms dans le nœud courant et ses ancêtres.

removeChildNodes
$noeud->removeChildNodes();

Supprime tous les nœuds enfants du nœud courant.

baseURI
$strURI = $noeud->baseURI();

Retourne l'URI de base du nœud.

setBaseURI
$noeud->setBaseURI($strURI);

Définit l'URI de base du nœud.

nodePath
$noeud->nodePath();

Retourne le chemin XPath du nœud.

line_number
$num_ligne = $noeud->line_number();

Retourne le numéro de ligne où le nœud a été trouvé dans le document source.

addChild
$node->addChild($newNode);

cette fonction est tout à fait utile si l'on construit des documents XML en mémoire où l'ordre et la propriété ("ownerDocument") sont assurés.

addChild() utilise la fonction xmlAddChild() de libxml2. Elle doit donc être utilisée avec précaution : Si un nœud texte est ajouté à un nœud et que le nœud lui-même ou son dernier enfant est également un nœud texte, le nœud à ajouter sera fusionné avec celui déjà présent. Le nœud courant sera supprimé de la mémoire après cette action. Comme perl n'est pas au courant de cette action, l'instance perl est toujours disponible. XML::LibXML détectera la perte d'un nœud et refusera d'exécuter toute fonction appelée sur ce nœud.

my $t1 = $doc->createTextNode( "foo" );
 my $t2 = $doc->createTextNode( "bar" );
 $t1->addChild( $t2 );       # c'est bon
 my $val = $t2->nodeValue(); # échouera, le script plante

De plus, addChild() ne vérifiera pas si le nœud ajouté appartient au même document que le nœud auquel il sera ajouté. Cela pourrait conduire à des documents incohérents et, dans des cas plus graves, même à des violations de mémoire, si l'on ne garde pas une trace de ce problème.

Bien que cela puisse sembler problématique, addChild() est utile lorsqu'un document est construit à partir d'un flux, comme cela arrive parfois dans les gestionnaires SAX ou les filtres.

Si vous n'êtes pas sûr de la provenance de vos nœuds, il vaut mieux vous en tenir à appendChild(), car cette fonction est plus conviviale dans le sens où elle tolère mieux les erreurs.

addNewChild
$node = $parent->addNewChild( $nsURI, $name );

Similaire à addChild(), cette fonction utilise des fonctionnalités de bas niveau de libxml2 pour fournir une interface plus rapide pour la construction du DOM. addNewChild() utilise xmlNewChild() pour créer un nouveau nœud sur un élément parent donné.

addNewChild() a deux paramètres $nsURI et $name, où $nsURI est un URI d'espace de noms (optionnel). $name est le nom d'élément complètement qualifié ; addNewChild() déterminera le préfixe correct si nécessaire.

La fonction retourne le nœud nouvellement créé.

Cette fonction est très utile pour la construction du DOM, où un nœud créé peut être directement associé à son parent. NOTE cette fonction ne fait pas partie de la spécification DOM et son utilisation limitera votre code à XML::LibXML.

addSibling
$node->addSibling($newNode);

addSibling() permet d'ajouter un nœud supplémentaire à la fin d'une liste de nœuds, définie par le nœud donné.

cloneNode
$newnode = $node->cloneNode( $deep );

cloneNode crée une copie de $node. Lorsque $deep est défini sur 1 (vrai), la fonction copie également tous les nœuds enfants. Si $deep est 0, seul le nœud courant est copié. Notez que dans le cas d'un élément, les attributs sont copiés même si $deep est 0.

Notez que le comportement de cette fonction pour $deep=0 a changé dans la version 1.62 afin d'être cohérent avec la spécification DOM (dans les versions antérieures, les attributs et les informations d'espace de noms n'étaient pas copiés pour les éléments).

NOTE cloneNode crée une copie du nœud sélectionné qui inclut les *namespaces* définis par le parent qui sont utilisés par le nœud (ou ses enfants) en cours de clonage. Cela le rend utile pour extraire un fragment de xml qui peut être utilisé comme un document xml valide.

parentNode
$parentnode = $node->parentNode;

Retourne simplement le Nœud Parent du nœud courant.

nextSibling
$nextnode = $node->nextSibling();

Retourne le frère suivant s'il y en a un.

nextNonBlankSibling
$nextnode = $node->nextNonBlankSibling();

Retourne le frère non blanc suivant s'il y en a un (un nœud est blanc s'il s'agit d'un nœud Texte ou CDATA composé uniquement d'espaces blancs). Cette méthode n'est pas définie par le DOM.

previousSibling
$prevnode = $node->previousSibling();

Analoque à *getNextSibling*, la fonction retourne le frère précédent s'il y en a un.

previousNonBlankSibling
$prevnode = $node->previousNonBlankSibling();

Retourne le frère non blanc précédent s'il y en a un (un nœud est blanc s'il s'agit d'un nœud Texte ou CDATA composé uniquement d'espaces blancs). Cette méthode n'est pas définie par le DOM.

hasChildNodes
$boolean = $node->hasChildNodes();

Si le nœud courant a des nœuds enfants, cette fonction retourne VRAI (1), sinon elle retourne FAUX (0, pas undef).

firstChild
$childnode = $node->firstChild;

Si un nœud a des nœuds enfants, cette fonction retournera le premier nœud de la liste des enfants.

lastChild
$childnode = $node->lastChild;

Si le $node a des nœuds enfants, cette fonction retourne le dernier nœud enfant.

ownerDocument
$documentnode = $node->ownerDocument;

Grâce à cette fonction, il est toujours possible d'accéder au document auquel le nœud courant est lié.

getOwner
$node = $node->getOwner;

Cette fonction retourne le nœud auquel le nœud courant est associé. Dans la plupart des cas, il s'agira d'un nœud document ou d'un nœud fragment de document.

setOwnerDocument
$node->setOwnerDocument( $doc );

Cette fonction lie un nœud à un autre DOM. Cette méthode délie d'abord le nœud s'il est déjà lié à un autre document.

Cette fonction est l'appel opposé de la fonction adoptNode() de XML::LibXML::Document. Par conséquent, elle a les mêmes limitations avec les références d'entité que adoptNode().

insertBefore
$node->insertBefore( $newNode, $refNode );

La méthode insère $newNode avant $refNode. Si $refNode est indéfini, le newNode sera défini comme le nouveau dernier enfant du nœud parent. Cette fonction diffère de la spécification DOM L2, dans le cas où le nouveau nœud ne fait pas partie du document, le nœud sera d'abord importé, automatiquement.

$refNode doit être passé à la fonction même s'il est indéfini :

$node->insertBefore( $newNode, undef ); # équivalent à $node->appendChild( $newNode );
 $node->insertBefore( $newNode ); # incorrect

Notez que le nœud de référence doit être un enfant direct du nœud sur lequel la fonction est appelée. De plus, $newChild ne peut pas être un ancêtre du nouveau nœud parent.

insertAfter
$node->insertAfter( $newNode, $refNode );

La méthode insère $newNode après $refNode. Si $refNode est indéfini, le newNode sera défini comme le nouveau dernier enfant du nœud parent.

Notez que $refNode doit être passé explicitement même s'il est indéfini.

findnodes
@nodes = $node->findnodes( $xpath_expression );

findnodes évalue l'expression xpath (XPath 1.0) sur le nœud courant et retourne l'ensemble de nœuds résultant sous forme de tableau. En contexte scalaire, retourne un objet XML::LibXML::NodeList.

L'expression xpath peut être passée soit sous forme de chaîne, soit sous forme d'objet XML::LibXML::XPathExpression.

NOTE SUR LES ESPACES DE NOMS ET XPATH :

Une erreur courante concernant XPath est de supposer que les tests de nœuds composés d'un nom d'élément sans préfixe correspondent aux éléments dans l'espace de noms par défaut. Cette supposition est fausse - selon la spécification XPath, de tels tests de nœuds ne peuvent correspondre qu'aux éléments qui n'ont aucun espace de noms (c'est-à-dire null).

Ainsi, par exemple, on ne peut pas faire correspondre l'élément racine d'un document XHTML avec "$node->find('/html')" car '/html' ne correspondrait que si l'élément racine "<html>" n'avait pas d'espace de noms, mais tous les éléments XHTML appartiennent à l'espace de noms http://www.w3.org/1999/xhtml. (Notez que les déclarations d'espace de noms "xmlns="..."" peuvent également être spécifiées dans une DTD, ce qui aggrave la situation, car le document XML semble ne pas avoir d'espace de noms par défaut).

Il existe plusieurs façons de gérer les espaces de noms dans XPath :

  • La méthode recommandée est d'utiliser le module XML::LibXML::XPathContext pour définir un contexte explicite pour l'évaluation XPath, dans lequel une cartographie préfixe-vers-espace de noms indépendante du document peut être définie. Par exemple : 
    my $xpc = XML::LibXML::XPathContext->new;
$xpc->registerNs('x', 'http://www.w3.org/1999/xhtml');
$xpc->find('/x:html',$node);
  • Une autre possibilité est d'utiliser les préfixes déclarés dans le document interrogé (si connus). Si le document déclare un préfixe pour l'espace de noms en question (et que le nœud de contexte est dans la portée de la déclaration), "XML::LibXML" vous permet d'utiliser le préfixe dans l'expression XPath, par exemple : 
    $node->find('/x:html');

Voir aussi XML::LibXML::XPathContext->findnodes.

find
$result = $node->find( $xpath );

find évalue l'expression XPath 1.0 en utilisant le nœud courant comme contexte de l'expression, et retourne le résultat en fonction du type de résultat de l'expression XPath. Par exemple, l'expression XPath "1 * 3 + 52" retourne un objet XML::LibXML::Number. D'autres expressions peuvent retourner un objet XML::LibXML::Boolean, ou un objet XML::LibXML::Literal (une chaîne de caractères). Chacun de ces objets utilise la fonctionnalité de surcharge de Perl pour "faire ce qu'il faut" dans différents contextes.

L'expression xpath peut être passée soit sous forme de chaîne, soit sous forme d'objet XML::LibXML::XPathExpression.

Voir aussi XML::LibXML::XPathContext->find.

findvalue
print $node->findvalue( $xpath );

findvalue est exactement équivalent à :

$node->find( $xpath )->to_literal;

C'est-à-dire qu'il retourne la valeur littérale des résultats. Cela vous permet de vous assurer que vous obtenez une chaîne de caractères de votre recherche, permettant certains raccourcis. Cela pourrait être utilisé comme l'équivalent de <xsl:value-of select="some_xpath"/> de XSLT.

Voir aussi XML::LibXML::XPathContext->findvalue.

L'expression xpath peut être passée soit sous forme de chaîne, soit sous forme d'objet XML::LibXML::XPathExpression.

exists
$bool = $node->exists( $xpath_expression );

Cette méthode se comporte comme findnodes, sauf qu'elle ne retourne qu'une valeur booléenne (1 si l'expression correspond à un nœud, 0 sinon) et peut être plus rapide que findnodes, car l'évaluation XPath peut s'arrêter tôt à la première correspondance (cela est vrai pour libxml2 >= 2.6.27).

Pour les expressions XPath qui ne retournent pas d'ensemble de nœuds, la méthode retourne vrai si la valeur retournée est un nombre non nul ou une chaîne non vide.

childNodes
@childnodes = $node->childNodes();

childNodes implémente une interface plus intuitive aux nœuds enfants du nœud courant. Elle vous permet de passer tous les enfants directement à une fonction "map" ou "grep". Si cette fonction est appelée dans un contexte scalaire, un objet XML::LibXML::NodeList sera retourné.

nonBlankChildNodes
@childnodes = $node->nonBlankChildNodes();

Ceci est similaire à childNodes, mais ne retourne que les nœuds non vides (où un nœud est considéré vide s'il s'agit d'un nœud Text ou CDATA ne contenant que des espaces blancs). Cette méthode n'est pas définie par DOM.

toString
$xmlstring = $node->toString($format,$docencoding);

Cette méthode est similaire à la méthode "toString" d'un XML::LibXML::Document mais pour un seul nœud. Elle retourne une chaîne de caractères composée de la sérialisation XML du nœud donné et de tous ses descendants. Contrairement à "XML::LibXML::Document::toString", dans ce cas, la chaîne résultante est par défaut une chaîne de caractères (codée en UTF-8 avec le drapeau UTF8 activé). Un drapeau optionnel $format contrôle l'indentation, comme dans "XML::LibXML::Document::toString". Si le second drapeau optionnel $docencoding est vrai, le résultat sera une chaîne d'octets dans l'encodage du document (voir "XML::LibXML::Document::actualEncoding").

toStringC14N
$c14nstring = $node->toStringC14N();
$c14nstring = $node->toStringC14N($with_comments, $xpath_expression , $xpath_context);

La fonction est similaire à toString(). Au lieu de simplement sérialiser l'arbre du document, elle le transforme comme spécifié dans la spécification XML-C14N (voir http://www.w3.org/TR/xml-c14n). Une telle transformation est connue sous le nom de canonisation.

Si $with_comments est 0 ou non défini, le document résultant ne contiendra aucun commentaire existant dans le document original. Pour inclure les commentaires dans le document canonisé, $with_comments doit être défini à 1.

Le paramètre $xpath_expression définit l'ensemble de nœuds qui devraient être visibles dans le document résultant. Ceci peut être utilisé pour filtrer certains nœuds. Il faut noter que seuls les nœuds qui font partie de l'ensemble de nœuds seront inclus dans le document résultant. Leurs nœuds enfants n'existeront pas dans le document résultant, à moins qu'ils ne fassent partie de l'ensemble défini par l'expression XPath.

Si $xpath_expression est omis ou vide, toStringC14N() inclura tous les nœuds dans le sous-arbre donné, en utilisant les expressions XPath suivantes : avec commentaires

(. | .//node() | .//@* | .//namespace::*)

et sans commentaires

(. | .//node() | .//@* | .//namespace::*)[not(self::comment())]

Un paramètre optionnel $xpath_context peut être utilisé pour passer un objet XML::LibXML::XPathContext définissant le contexte pour l'évaluation de $xpath_expression. Ceci est utile pour mapper les préfixes d'espaces de noms utilisés dans l'expression XPath aux URIs d'espaces de noms. Notez cependant que $node sera utilisé comme nœud de contexte pour l'évaluation, et non le nœud de contexte de $xpath_context !

toStringC14N_v1_1
$c14nstring = $node->toStringC14N_v1_1();
$c14nstring = $node->toStringC14N_v1_1($with_comments, $xpath_expression , $xpath_context);

Cette fonction se comporte comme toStringC14N() sauf qu'elle utilise la constante "XML_C14N_1_1" pour canoniser en utilisant la "spécification C14N 1.1".

toStringEC14N
$ec14nstring = $node->toStringEC14N();
$ec14nstring = $node->toStringEC14N($with_comments, $xpath_expression, $inclusive_prefix_list);
$ec14nstring = $node->toStringEC14N($with_comments, $xpath_expression, $xpath_context, $inclusive_prefix_list);

La fonction est similaire à toStringC14N() mais suit la spécification XML-EXC-C14N (voir http://www.w3.org/TR/xml-exc-c14n) pour la canonisation exclusive de XML.

Les arguments $with_comments, $xpath_expression, $xpath_context sont comme dans toStringC14N(). Une référence ARRAY peut être passée comme dernier argument $inclusive_prefix_list, listant les préfixes d'espaces de noms qui doivent être traités de la manière décrite par la Recommandation Canonical XML (c'est-à-dire préservés dans la sortie même si l'espace de noms n'est pas utilisé). Cf. la spécification pour les détails.

serialize
$str = $doc->serialize($format);

Un alias pour toString(). Cette fonction a été renommée pour être plus cohérente avec libxml2.

serialize_c14n
Un alias pour toStringC14N().
serialize_exc_c14n
Un alias pour toStringEC14N().
localname
$localname = $node->localname;

Retourne le nom local d'une balise. C'est la partie après les deux points.

prefix
$nameprefix = $node->prefix;

Retourne le préfixe d'une balise. C'est la partie avant les deux points.

namespaceURI
$uri = $node->namespaceURI();

retourne l'URI de l'espace de noms courant.

hasAttributes
$boolean = $node->hasAttributes();

retourne 1 (VRAI) si le nœud courant a des attributs définis, sinon 0 (FAUX) est retourné.

attributes
@attributelist = $node->attributes();

Cette fonction retourne tous les attributs et déclarations d'espace de noms assignés au nœud donné.

Comme XML::LibXML n'implémente pas les déclarations d'espace de noms et les attributs de la même manière, il est nécessaire de tester quel type de nœud est traité lors de l'accès au résultat de la fonction.

Si cette fonction est appelée dans un contexte de tableau, les nœuds attributs sont retournés sous forme de tableau. Dans un contexte scalaire, la fonction retournera un objet XML::LibXML::NamedNodeMap.

lookupNamespaceURI
$URI = $node->lookupNamespaceURI( $prefix );

Recherche un URI d'espace de noms par son préfixe en partant du nœud courant.

lookupNamespacePrefix
$prefix = $node->lookupNamespacePrefix( $URI );

Recherche un préfixe d'espace de noms par son URI en partant du nœud courant.

NOTE Seuls les URIs d'espaces de noms sont censés être uniques. Le préfixe n'est lié qu'au document. De plus, le document peut avoir plus d'un préfixe défini pour un espace de noms.

normalize
$node->normalize;

Cette fonction normalise les nœuds de texte adjacents. Cette fonction n'est pas aussi stricte que la fonction xmlTextMerge() de libxml2, car elle ne libérera pas un nœud qui est toujours référencé par la couche Perl.

XML::LibXML::Node(3pm)

NAME

XML::LibXML::Node – Representation of a node within an XML::LibXML document

SYNOPSIS

  use XML::LibXML;

  my $doc  = XML::LibXML->load_xml(string => $xml_string);
  my $node = $doc->findvalue('//some/xpath');

  # Accessing Nodes
  my $child = $node->firstChild;
  my $next  = $node->nextSibling;
  my $parent= $node->parentNode;

  # Node information
  my $nodename = $node->nodeName;
  my $nodetype = $node->nodeType;
  my $nodeval  = $node->nodeValue;

  # Working with namespaces
  my %ns = $node->getNamespaces;

  # Manipulating nodes
  $node->removeChildNodes;
  $node->setBaseURI($uri);

  # Node properties
  my $base_uri = $node->baseURI;
  my $path     = $node->nodePath;
  my $lineno   = $node->line_number;

DESCRIPTION

This module provides the XML::LibXML::Node class, which represents a node within an XML document parsed by XML::LibXML. This class is the base class for all node types, such as elements, attributes, text, comments, etc. Instances of this class are returned by various methods of the XML::LibXML and XML::LibXML::Document classes, most notably through the various find* methods.

It is important to note that XML::LibXML::Node is an object-oriented interface to the underlying libxml2 library. As such, it inherits much of its functionality and behavior from libxml2.

METHODS

nodeName ()
$node->nodeName();

Returns the name of the node. For elements and attributes, this is the tag name. For text nodes, this is #text, for comments #comment and so on.

nodeType ()
$type = $node->nodeType();

Returns the type of the node. The possible return values are constants defined in XML::LibXML:

XML::LibXML::NODE_ELEMENT
Element node
XML::LibXML::NODE_ATTRIBUTE
Attribute node
XML::LibXML::NODE_TEXT
Text node
XML::LibXML::NODE_CDATA
CData node
XML::LibXML::NODE_ENTITY_REF
Entity reference node
XML::LibXML::NODE_ENTITY
Entity node
XML::LibXML::NODE_PI
Processing instruction node
XML::LibXML::NODE_COMMENT
Comment node
XML::LibXML::NODE_DOCUMENT
Document node
XML::LibXML::NODE_DOCUMENT_TYPE
Document type node
XML::LibXML::NODE_DOCUMENT_FRAGMENT
Document fragment node
XML::LibXML::NODE_NOTATION
Notation node
nodeValue ()
$value = $node->nodeValue();

Returns the value of the node. For text nodes, this is the text content. For attribute nodes, this is the attribute value. For other node types, this is typically an empty string.

getNamespaces ()
%namespaces = $node->getNamespaces;
my %namespaces = $node->getNamespaces(2); # include inherited namespaces

Returns a hash where keys are namespace URIs and values are namespace prefixes. The hash contains all namespaces declared for this node. If the argument 2 is passed, inherited namespaces are included too.

Note that this will not return all namespaces that are in scope, but only the ones declared explicitly for that node.

Although getNamespaces is available for all nodes, it only makes sense if used with element nodes.

removeChildNodes
$node->removeChildNodes();

This function is not specified for any DOM level: It removes all childnodes from a node in a single step. Other than the libxml2 function itself (xmlFreeNodeList), this function will not immediately remove the nodes from the memory. This saves one from getting memory violations, if there are nodes still referred to from the Perl level.

baseURI ()
$strURI = $node->baseURI();

Searches for the base URL of the node. The method should work on both XML and HTML documents even if base mechanisms for these are completely different. It returns the base as defined in RFC 2396 sections "5.1.1. Base URI within Document Content" and "5.1.2. Base URI from the Encapsulating Entity". However it does not return the document base (5.1.3), use method "URI" of "XML::LibXML::Document" for this.

setBaseURI ($strURI)
$node->setBaseURI($strURI);

This method only does something useful for an element node in an XML document. It sets the xml:base attribute on the node to $strURI, which effectively sets the base URI of the node to the same value.

Note: For HTML documents this behaves as if the document was XML which may not be desired, since it does not effectively set the base URI of the node. See RFC 2396 appendix D for an example of how base URI can be specified in HTML.

nodePath
$node->nodePath();

This function is not specified for any DOM level: It returns a canonical structure based XPath for a given node.

line_number
$lineno = $node->line_number();

This function returns the line number where the tag was found during parsing. If a node is added to the document the line number is 0. Problems may occur, if a node from one document is passed to another one.

IMPORTANT: Due to limitations in the libxml2 library line numbers greater than 65535 will be returned as 65535. Please see http://bugzilla.gnome.org/show_bug.cgi?id=325533 for more details.

Note: line_number() is special to XML::LibXML and not part of the DOM specification.

If the line_numbers flag of the parser was not activated before parsing, line_number() will always return 0.
