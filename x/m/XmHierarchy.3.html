NOM

XmHierarchy — La classe du widget Hierarchy

SYNTAXE

#include <Xm/Hierarchy.h>

DESCRIPTION

Le widget Hierarchy n'est pas destiné à être instancié lui-même, mais doit plutôt servir de classe de base pour tout widget qui souhaite présenter une hiérarchie d'informations à l'utilisateur, différente de la hiérarchie réelle des instances de widgets de l'application. Cette classe de base est actuellement utilisée pour deux widgets de la boîte à outils Motif, Tree et Outline, donnant à ces deux widgets une API très similaire.

Note : Le widget Hierarchy suppose qu'il sera totalement responsable du mappage et du démappage de ses enfants. Par conséquent, aucun enfant de ce widget ne devrait jamais modifier sa ressource mappedWhenManaged. Si un enfant modifie cette ressource, le comportement est indéfini.

CLASSES

Hierarchy hérite des comportements, ressources et traits des classes Core, Composite, Composite, Constraint et XmManager.

Le pointeur de classe est xmHierarchyWidgetClass.

Le nom de la classe est XmHierarchy.

XmNautoClose
Cette ressource détermine si la hiérarchie doit automatiquement restaurer les enfants d'un nœud parent lorsque celui-ci est rouvert. Si autoClose est False, et que la hiérarchie est complètement développée lorsque le nœud racine est fermé, alors toute la hiérarchie sera affichée comme développée lorsque le nœud racine sera rouvert. Si autoClose est True, alors les enfants du nœud racine sont fermés lorsque le nœud racine est rouvert.
XmNcloseFolderPixmap
Cette ressource définit un pixmap pour la représentation fermée du pixmap du dossier à utiliser dans tout l'arbre. Il peut s'agir d'un pixmap couleur ou d'un bitmap. Si l'utilisateur ne spécifie pas de pixmap, le bitmap par défaut sera utilisé.
XmNhorizontalMargin
XmNverticalMargin
La définition exacte de ces ressources est laissée à la sous-classe du widget hierarchy qui effectue la disposition géométrique. Elles sont destinées à être utilisées comme espace entre l'objet et les bords de la fenêtre dans laquelle il est affiché. Elles sont incluses ici pour des raisons de cohérence.
XmNopenFolderPixmap
Cette ressource définit un pixmap pour la représentation ouverte du pixmap du dossier à utiliser dans tout l'arbre. Il peut s'agir d'un pixmap couleur ou d'un bitmap. Si l'utilisateur ne spécifie pas de pixmap, le bitmap par défaut du dossier ouvert.
XmNnodeStateCallback
La liste des routines de rappel appelées lorsqu'un bouton de dossier est cliqué. Voir "Routine de rappel" pour plus de détails.
XmNrefigureMode
Cette ressource détermine si la hiérarchie doit ajuster les tailles des enfants après une demande de géométrie ou de redimensionnement, ou simplement ignorer la demande. Cette ressource est très utile pour améliorer les performances d'une application qui effectue un grand nombre de modifications géométriques en une seule fois.

XmNinsertBefore
Spécifie un autre nœud qui a le même parentNode. Ce nœud sera alors placé juste avant ce nœud dans la hiérarchie. Si cette valeur est NULL, le nœud sera inséré à la fin de la liste. Cette ressource permet de réordonner les enfants de la hiérarchie.
XmNnodeState
L'état de ce nœud. Les valeurs acceptables sont : XmOpen, XmClosed, XmAlwaysOpen, et XmHidden. Un convertisseur de type a été enregistré qui peut convertir les chaînes suivantes : "open", "close", "alwaysOpen", et "hidden".
XmNparentNode
Le parent de la hiérarchie de ce nœud. Le nœud parent DOIT être un widget frère du nœud courant.

Informations de rappel

Lorsqu'un dossier est cliqué, les routines enregistrées sur la liste XmNnodeStateCallback reçoivent un pointeur vers la structure suivante en tant que données client:

typedef struct _XmHierarchyNodeStateData {
	Widget widget;
	XmHierarchyNodeState state;
} XmHierarchyNodeStateData;
widget
le nœud enfant de Hierarchy en cours d'ouverture ou de fermeture.
state
l'état actuel XmNnodeState (après le clic) du
nœud. Les valeurs autorisées sont XmOpen, XmClosed, XmAlwaysOpen,
et XmHidden.

Enfants

La hiérarchie maintient des IconButtons pour chaque nœud de la hiérarchie. Le réglage de openFolderPixmap ou closeFolderPixmap se fait via XtSetValues. Les IconButtons ne peuvent être manipulés que par la Hiérarchie.
