Paquet: libx11

XMapEvent(3) FONCTIONS XLIB XMapEvent(3)

NOM

XMapEvent, XMappingEvent - Structures d'événements MapNotify et MappingNotify

STRUCTURES

La structure pour les événements MapNotify contient :

typedef struct {
        int type;       /* MapNotify */
        unsigned long serial;   /* # de la dernière requête traitée par le serveur */
        Bool send_event;        /* true si ceci provenait d'une requête SendEvent */
        Display *display;       /* Display à partir duquel l'événement a été lu */
        Window event;
        Window window;
        Bool override_redirect; /* booléen, est-ce que override est défini... */
} XMapEvent;

Lorsque vous recevez cet événement, les membres de la structure sont définis comme suit.

Le membre type est défini à la constante du nom de type d'événement qui l'identifie de manière unique. Par exemple, lorsque le serveur X signale un événement GraphicsExpose à une application cliente, il envoie une structure XGraphicsExposeEvent avec le membre type défini à GraphicsExpose. Le membre display est défini à un pointeur vers le display sur lequel l'événement a été lu. Le membre send_event est défini à True si l'événement provenait d'une requête de protocole SendEvent. Le membre serial est défini à partir du numéro de série rapporté dans le protocole mais développé à partir des 16 bits de poids faible en une valeur complète de 32 bits. Le membre window est défini à la fenêtre qui est la plus utile pour les répartiteurs de toolkit.

Le membre event est défini soit à la fenêtre qui a été mappée, soit à son parent, selon que StructureNotify ou SubstructureNotify a été sélectionné. Le membre window est défini à la fenêtre qui a été mappée. Le membre override_redirect est défini à l'attribut override-redirect de la fenêtre. Les clients du gestionnaire de fenêtre devraient normalement ignorer cette fenêtre si l'attribut override-redirect est True, car ces événements sont généralement générés à partir de pop-ups, qui outrepassent le contrôle de la structure.

La structure pour les événements MappingNotify est :

typedef struct {
        int type;       /* MappingNotify */
        unsigned long serial;   /* # de la dernière requête traitée par le serveur */
        Bool send_event;        /* true si ceci provenait d'une requête SendEvent */
        Display *display;       /* Display à partir duquel l'événement a été lu */
        Window window;  /* inutilisé */
        int request;    /* une de MappingModifier, MappingKeyboard,
                   MappingPointer */
        int first_keycode;      /* premier keycode */
        int count;      /* définit la plage de changement avec first_keycode*/
} XMappingEvent;

Lorsque vous recevez cet événement, les membres de la structure sont définis comme suit.

Le membre type est défini à la constante du nom de type d'événement qui l'identifie de manière unique. Par exemple, lorsque le serveur X signale un événement GraphicsExpose à une application cliente, il envoie une structure XGraphicsExposeEvent avec le membre type défini à GraphicsExpose. Le membre display est défini à un pointeur vers le display sur lequel l'événement a été lu. Le membre send_event est défini à True si l'événement provenait d'une requête de protocole SendEvent. Le membre serial est défini à partir du numéro de série rapporté dans le protocole mais développé à partir des 16 bits de poids faible en une valeur complète de 32 bits. Le membre window est défini à la fenêtre qui est la plus utile pour les répartiteurs de toolkit.

Le membre request est défini pour indiquer le type de changement de mappage qui s'est produit et peut être MappingModifier, MappingKeyboard, MappingPointer. S'il s'agit de MappingModifier, le mappage des modificateurs a été modifié. S'il s'agit de MappingKeyboard, le mappage du clavier a été modifié. S'il s'agit de MappingPointer, le mappage des boutons du pointeur a été modifié. Les membres first_keycode et count sont définis uniquement si le membre request a été défini à MappingKeyboard. Le nombre dans first_keycode représente le premier nombre dans la plage du mappage modifié, et count représente le nombre de keycodes modifiés.
