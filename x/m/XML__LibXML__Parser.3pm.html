NOM

XML::LibXML::Parser - Analyse des données XML avec XML::LibXML

SYNOPIS

use XML::LibXML '1.70';
# Constructeur du parseur
$parser = XML::LibXML->new();
$parser = XML::LibXML->new(option=>valeur, ...);
$parser = XML::LibXML->new({option=>valeur, ...});
# Analyse XML
$dom = XML::LibXML->load_xml(
    location => $fichier_ou_url
    # options du parseur ...
  );
$dom = XML::LibXML->load_xml(
    string => $chaine_xml
    # options du parseur ...
  );
$dom = XML::LibXML->load_xml(
    string => (\$chaine_xml)
    # options du parseur ...
  );
$dom = XML::LibXML->load_xml({
    IO => $descripteur_fichier_perl
    # options du parseur ...
  });
$dom = $parser->load_xml(...);
# Analyse HTML
$dom = XML::LibXML->load_html(...);
$dom = $parser->load_html(...);
# Analyse de fragments XML bien équilibrés
$fragment = $parser->parse_balanced_chunk( $chaine_xml_wb, $encodage );
# Traitement de XInclude
$parser->process_xincludes( $doc );
$parser->processXIncludes( $doc );
# Interfaces de parseur anciennes
$doc = $parser->parse_file( $nom_fichier_xml );
$doc = $parser->parse_fh( $descripteur_fichier_io );
$doc = $parser->parse_string( $chaine_xml);
$doc = $parser->parse_html_file( $fichier_html, \%opts );
$doc = $parser->parse_html_fh( $descripteur_fichier_io, \%opts );
$doc = $parser->parse_html_string( $chaine_html, \%opts );
# Parseur par flux (push parser)
$parser->parse_chunk($chaine, $terminer);
$parser->init_push();
$parser->push(@donnees);
$doc = $parser->finish_push( $recuperer );
# Définir/interroger les options du parseur
$parser->option_exists($nom);
$parser->get_option($nom);
$parser->set_option($nom,$valeur);
$parser->set_options({$nom=>$valeur,...});
# Catalogues XML
$parser->load_catalog( $fichier_catalogue );

ANALYSE

Un document XML est lu dans une structure de données telle qu'un arbre DOM par un logiciel appelé analyseur (parser). XML::LibXML fournit actuellement quatre interfaces d'analyseur différentes :

  • Un analyseur DOM Pull
  • Un analyseur DOM Push
  • Un analyseur SAX
  • Un analyseur SAX basé sur DOM.

Création d'une instance d'analyseur

XML::LibXML fournit une interface orientée objet aux fonctions d'analyse de libxml2. Ainsi, vous devez créer une instance d'analyseur avant de pouvoir analyser des données XML.

new
$parser = XML::LibXML->new();
$parser = XML::LibXML->new(option=>valeur, ...);
$parser = XML::LibXML->new({option=>valeur, ...});

Crée une nouvelle instance d'analyseur XML et HTML. Chaque instance d'analyseur conserve les valeurs par défaut pour diverses options d'analyse. Facultativement, on peut passer une référence de hachage ou une liste de paires option => valeur pour définir un ensemble différent d'options par défaut. Sauf indication contraire, les options "load_ext_dtd" et "expand_entities" sont mises à 1. Voir "Options du parseur" pour une liste des options du parseur libxml2.

Analyseur DOM

L'une des interfaces d'analyseur courantes de XML::LibXML est l'analyseur DOM. Cet analyseur lit les données XML dans une structure de données de type DOM, de sorte que chaque balise puisse être accédée et transformée.

L'analyseur DOM de XML::LibXML est capable non seulement d'analyser des données XML, mais aussi des fichiers (strictement) HTML. Il existe trois façons d'analyser des documents : sous forme de chaîne, sous forme de descripteur de fichier Perl, ou sous forme de nom de fichier/URL. La valeur de retour de chacune est un objet XML::LibXML::Document, qui est un objet DOM.

Toutes les fonctions listées ci-dessous lanceront une exception si le document est invalide. Pour éviter que cela n'arrête votre programme, encapsulez l'appel dans un bloc eval{}

load_xml
$dom = XML::LibXML->load_xml(
    location => $fichier_ou_url
    # options du parseur ...
  );
$dom = XML::LibXML->load_xml(
    string => $chaine_xml
    # options du parseur ...
  );
$dom = XML::LibXML->load_xml(
    string => (\$chaine_xml)
    # options du parseur ...
  );
$dom = XML::LibXML->load_xml({
    IO => $descripteur_fichier_perl
    # options du parseur ...
  });
$dom = $parser->load_xml(...);

Cette fonction est disponible depuis XML::LibXML 1.70. Elle fournit une interface facile à utiliser pour l'analyseur XML qui analyse le fichier (ou l'URL non-HTTPS) donné, la chaîne ou le flux d'entrée en un arbre DOM. Les arguments peuvent être passés dans une référence HASH ou sous forme de paires nom => valeur. La fonction peut être appelée en tant que méthode de classe ou méthode d'objet. Dans les deux cas, elle crée en interne une nouvelle instance d'analyseur en passant les options d'analyse spécifiées ; si elle est appelée en tant que méthode d'objet, elle clone l'analyseur d'origine (en préservant ses paramètres) et applique en plus les options spécifiées au nouvel analyseur. Voir le constructeur "new" et "Options du parseur" pour plus d'informations.

Notez que, en raison d'une limitation de la bibliothèque libxml2 sous-jacente, cet appel ne reconnaît pas les URL basées sur HTTPS. (Il traitera une URL HTTPS comme un nom de fichier, lançant probablement une exception "Aucun fichier ou répertoire de ce type".)

load_html
$dom = XML::LibXML->load_html(...);
$dom = $parser->load_html(...);

Cette fonction est disponible depuis XML::LibXML 1.70. Elle a la même utilisation que "load_xml", fournissant une interface à l'analyseur HTML. Voir "load_xml" pour plus d'informations.

L'analyse HTML peut poser des problèmes, notamment si l'esperluette ('&') est utilisée. C'est un problème courant si du code HTML contenant des liens vers des scripts CGI est analysé. Ces liens provoquent des erreurs lors de l'analyse par le parseur. Dans de tels cas, libxml2 analyse toujours le document entier comme s'il n'y avait pas eu d'erreur, mais l'erreur fait que XML::LibXML arrête le processus d'analyse. Cependant, le document n'est pas perdu. Ces documents HTML devraient être analysés en utilisant le drapeau recover. Par défaut, la récupération est désactivée.

Les fonctions décrites ci-dessus sont implémentées pour analyser des documents bien formés. Dans certains cas, un programme reçoit du XML bien équilibré au lieu de documents bien formés (par exemple, un fragment XML provenant d'une base de données). Avec XML::LibXML, il n'est pas nécessaire d'encapsuler de tels fragments dans le code, car XML::LibXML est capable même d'analyser des fragments XML bien équilibrés.

parse_balanced_chunk
$fragment = $parser->parse_balanced_chunk( $chaine_xml_wb, $encodage );

Cette fonction analyse une chaîne XML bien équilibrée en un XML::LibXML::DocumentFragment. Le premier argument contient la chaîne d'entrée, le deuxième argument optionnel peut être utilisé pour spécifier l'encodage de caractères de l'entrée (UTF-8 est supposé par défaut).

parse_xml_chunk
C'est l'ancien nom de parse_balanced_chunk(). Comme il peut prêter à confusion avec l'interface du parseur par flux (push parser), cette fonction ne devrait plus être utilisée.

Par défaut, XML::LibXML ne traite pas les balises XInclude dans un Document XML (voir la section des options ci-dessous). XML::LibXML permet de traiter ultérieurement un document pour développer les balises XInclude.

process_xincludes
$parser->process_xincludes( $doc );

Après qu'un document a été analysé en une structure DOM, vous pourriez vouloir développer les balises XInclude du document. Cette fonction traite la structure du document donnée et développe toutes les balises XInclude (ou lance une erreur) en utilisant les drapeaux et les rappels de l'instance d'analyseur donnée.

Notez que l'arbre résultant contient des nœuds supplémentaires (de type XML_XINCLUDE_START et XML_XINCLUDE_END) après le traitement réussi du document. Ces nœuds indiquent où les données ont été incluses dans l'arbre d'origine. Si le document est sérialisé, ces nœuds supplémentaires n'apparaîtront pas.

Rappelez-vous : Un document avec XIncludes traités diffère du document d'origine après sérialisation, car les balises XInclude d'origine ne seront pas restaurées !

Si le drapeau d'analyse "expand_xincludes" est défini à 1, vous n'avez pas besoin de traiter le document analysé après coup.

processXIncludes
$parser->processXIncludes( $doc );

Ceci est un alias de process_xincludes, mais avec un nom de fonction similaire à Java.

Interfaces d'analyseur anciennes

XML::LibXML->new() retourne une instance du parseur. Les interfaces d'analyseur ci-dessous peuvent être appelées comme méthodes d'objet.

parse_file
$doc = $parser->parse_file($xmlfilename);

Analyse un fichier XML. Renvoie un objet XML::LibXML::Document.

parse_fh
$doc = $parser->parse_fh($io_fh);

Analyse à partir d'un descripteur de fichier Perl. Renvoie un objet XML::LibXML::Document.

parse_string
$doc = $parser->parse_string($xmlstring);

Analyse une chaîne XML. Renvoie un objet XML::LibXML::Document.

parse_html_file
$doc = $parser->parse_html_file($htmlfile, \%opts);

Analyse un fichier HTML. Renvoie un objet XML::LibXML::Document.

Les options peuvent inclure :

recover
Active la récupération des erreurs (Défaut: 0)
no_dicts
Ne crée pas de dictionnaires pour les attributs de table (Défaut: 0)
parse_html_fh
$doc = $parser->parse_html_fh($io_fh, \%opts);

Analyse à partir d'un descripteur de fichier Perl d'un document HTML. Renvoie un objet XML::LibXML::Document.

parse_html_string
$doc = $parser->parse_html_string($htmlstring, \%opts);

Analyse une chaîne HTML. Renvoie un objet XML::LibXML::Document.

Analyseur par flux (Push Parser)

Pour analyser des documents qui ne rentrent pas dans la mémoire ou pour des raisons de performance, XML::LibXML offre un analyseur par flux. L'analyseur par flux gère l'analyse de documents en plusieurs étapes. Le document est divisé en morceaux qui sont envoyés à l'analyseur par flux. Les morceaux sont assemblés, et une fois le document complet, le DOM est construit.

init_push
$parser->init_push();

Initialise le parseur par flux. Doit être appelé avant d'envoyer des données.

parse_chunk
$parser->parse_chunk($string, $terminate);

Envoie un morceau de données à l'analyseur. Si $terminate est vrai, l'analyseur essaiera de terminer le document.

push
$parser->push(@data);

Envoie un tableau de données à l'analyseur. L'équivalent de l'appel de "parse_chunk" pour chaque élément du tableau.

finish_push
$doc = $parser->finish_push($recover);

Termine l'analyse par flux et construit le document DOM. Si $recover est vrai, l'analyseur essaiera de récupérer les erreurs.

Catalogues XML

XML::LibXML supporte les catalogues XML, qui sont des fichiers permettant de mapper des identificateurs système à des URI ou des noms de fichiers.

Les catalogues peuvent être chargés en utilisant la méthode "load_catalog".

load_catalog
$parser->load_catalog($catalog_file);

Charge un fichier catalogue XML. La méthode peut être appelée plusieurs fois pour charger plusieurs catalogues.

Pour que les catalogues soient utilisés lors de l'analyse, l'option "opt_catalogs" doit être activée (ce qui est le cas par défaut si un catalogue a été chargé).

Voir également la documentation de libxml2 pour plus d'informations sur les catalogues XML.

parse_file
$doc = $parser->parse_file( $xmlfilename );

Cette fonction analyse un document XML à partir d'un fichier ou d'une connexion réseau ; $xmlfilename peut être un nom de fichier ou une URL (non-HTTPS). Notez que pour l'analyse de fichiers, cette fonction est le choix le plus rapide, environ 6 à 8 fois plus rapide que parse_fh().

parse_fh
$doc = $parser->parse_fh( $io_fh );

parse_fh() analyse un objet IOREF ou une sous-classe de IO::Handle.

Comme les données proviennent d'une poignée ouverte, l'analyseur libxml2 ne connaît pas l'URI de base du document. Pour définir l'URI de base, il faut utiliser parse_fh() comme suit :

my $doc = $parser->parse_fh( $io_fh, $baseuri );
parse_string
$doc = $parser->parse_string( $xmlstring);

Cette fonction est similaire à parse_fh(), mais elle analyse un document XML qui est disponible sous forme d'une seule chaîne en mémoire, ou alternativement comme une référence vers un scalaire contenant une chaîne. Encore une fois, vous pouvez passer une URI de base facultative à la fonction.

my $doc = $parser->parse_string( $xmlstring, $baseuri );
my $doc = $parser->parse_string(\$xmlstring, $baseuri);
parse_html_file
$doc = $parser->parse_html_file( $htmlfile, \%opts );

Similaire à parse_file() mais analyse des documents HTML (stricts) ; $htmlfile peut être un nom de fichier ou une URL (non-HTTPS).

Un second argument facultatif peut être utilisé pour passer des options à l'analyseur HTML sous forme de référence HASH. Voir les options marquées HTML dans "Options de l'analyseur".

parse_html_fh
$doc = $parser->parse_html_fh( $io_fh, \%opts );

Similaire à parse_fh() mais analyse des flux HTML (stricts).

Un second argument facultatif peut être utilisé pour passer des options à l'analyseur HTML sous forme de référence HASH. Voir les options marquées HTML dans "Options de l'analyseur".

Note : l'option d'encodage peut ne pas fonctionner correctement avec cette fonction dans libxml2 < 2.6.27 si le fichier HTML déclare son jeu de caractères à l'aide d'une balise META.

Similaire à parse_string() mais analyse des chaînes HTML (strictes).

Analyseur Push

XML::LibXML fournit une interface d'analyseur push. Au lieu de tirer les données d'une source donnée, l'analyseur push attend que les données lui soient poussées.

Cela permet d'analyser de grands documents sans attendre que l'analyseur ait terminé. L'interface est particulièrement utile si un programme doit prétraiter les morceaux XML entrants (par exemple, pour détecter les limites du document).

Alors que les fonctions parse_*() de XML::LibXML forcent les données à être un XML bien formé, l'analyseur push acceptera toute chaîne arbitraire contenant des données XML. La seule exigence est que toutes les chaînes poussées forment ensemble un document bien formé. Avec l'interface de l'analyseur push, un programme peut interrompre le processus d'analyse selon les besoins, alors que les fonctions parse_*() ne donnent pas suffisamment de flexibilité.

Contrairement à l'analyseur pull implémenté dans parse_fh() ou parse_file(), l'analyseur push n'est pas capable de découvrir la fin du document par lui-même. Ainsi, le programme appelant doit indiquer explicitement quand l'analyse est terminée.

Dans XML::LibXML, cela se fait par une seule fonction :

parse_chunk
$parser->parse_chunk($string, $terminate);

parse_chunk() tente d'analyser un morceau de données donné, qui n'est pas nécessairement équilibré. La fonction prend deux paramètres : le morceau de données sous forme de chaîne et éventuellement un indicateur de terminaison. Si l'indicateur de terminaison est défini sur une valeur vraie (par exemple, 1), l'analyse sera arrêtée et le document résultant sera renvoyé comme décrit dans l'exemple suivant :

my $parser = XML::LibXML->new;
for my $string ( "<", "foo", ' bar="hello world"', "/>") {
     $parser->parse_chunk( $string );
}
my $doc = $parser->parse_chunk("", 1); # termine l'analyse

Internement, XML::LibXML fournit trois fonctions qui contrôlent le processus de l'analyseur push :

init_push
$parser->init_push();

Initialise l'analyseur push.

push
$parser->push(@data);

Cette fonction pousse les données stockées dans le tableau vers l'analyseur de libxml2. Chaque entrée dans @data doit être un scalaire normal ! Cette méthode peut être appelée de manière répétée.

finish_push
$doc = $parser->finish_push( $recover );

Cette fonction renvoie le résultat du processus d'analyse. Si cette fonction est appelée sans paramètre, elle se plaindra de documents mal formés. Si $restore vaut 1, l'analyseur push peut être utilisé pour restaurer des documents XML cassés ou mal formés, comme le montre l'exemple suivant :

eval {
    $parser->push( "<foo>", "bar" );
    $doc = $parser->finish_push();    # signalera un XML cassé
};
if ( $@ ) {
   # ...
}

Cela peut être gênant si la balise de fermeture est manquée par accident. Le code suivant restaurera le document :

eval {
    $parser->push( "<foo>", "bar" );
    $doc = $parser->finish_push(1);   # renverra les données analysées
                                      # sauf si une erreur s'est produite
};
print $doc->toString(); # renvoie "<foo>bar</foo>"

Bien sûr, finish_push() ne renverra rien s'il n'y avait aucune donnée poussée vers l'analyseur auparavant.

Analyseur Pull (Reader)

XML::LibXML fournit également une interface d'analyseur pull similaire à l'interface XmlReader dans .NET. Cette interface est presque en streaming, et est généralement plus rapide et plus simple à utiliser que SAX. Voir XML::LibXML::Reader.

Analyseur SAX Direct

XML::LibXML fournit un analyseur SAX direct dans le module XML::LibXML::SAX.

Analyseur SAX basé sur DOM

XML::LibXML fournit également un analyseur SAX basé sur DOM. L'analyseur SAX est défini dans le module XML::LibXML::SAX::Parser. Comme ce n'est pas un analyseur basé sur flux, il analyse les documents en un DOM et parcourt l'arbre DOM à la place.

L'API de cet analyseur est exactement la même que celle de tout autre analyseur Perl SAX2. Voir XML::SAX::Intro pour plus de détails.

Outre les méthodes d'analyse régulières, vous pouvez accéder directement au parcours de l'arbre DOM en utilisant la méthode generate() :

my $doc = build_yourself_a_document();
my $saxparser = $XML::LibXML::SAX::Parser->new( ... );
$parser->generate( $doc );

Ceci est utile pour sérialiser des arbres DOM, par exemple, sur lesquels vous auriez effectué un traitement préalable, ou que vous avez comme résultat d'un traitement XSLT.

ATTENTION

Ce n'est PAS un analyseur SAX en streaming. Comme je l'ai dit plus haut, cet analyseur lit le document entier dans un DOM puis le sérialise. Certaines personnes n'ont pas pu comprendre cela dans le paragraphe précédent, j'ai donc ajouté cet avertissement. Si vous voulez un analyseur SAX en streaming, consultez la page de manuel XML::LibXML::SAX

SERIALISATION

XML::LibXML fournit des fonctions pour sérialiser des nœuds et des documents. Les fonctions de sérialisation sont décrites dans la page de manuel XML::LibXML::Node ou XML::LibXML::Document. XML::LibXML vérifie trois indicateurs globaux qui modifient le processus de sérialisation :

  • skipXMLDeclaration
  • skipDTD
  • setTagCompression

Parmi ces trois fonctions, seule setTagCompression est disponible pour toutes les fonctions de sérialisation.

Comme XML::LibXML ne gère pas ces indicateurs lui-même, il faut les définir localement comme le montre l'exemple suivant :

local $XML::LibXML::skipXMLDeclaration = 1;
local $XML::LibXML::skipDTD = 1;
local $XML::LibXML::setTagCompression = 1;

Si skipXMLDeclaration est défini et différent de '0', la déclaration XML est omise lors de la sérialisation.

Si skipDTD est défini et différent de '0', une DTD existante ne sera pas sérialisée avec le document.

Si setTagCompression est défini et différent de '0', les balises vides sont affichées sous forme de balises ouvertes et fermantes plutôt que de raccourci. Par exemple, la balise vide foo sera rendue comme <foo></foo> plutôt que <foo/>.

OPTIONS DE L'ANALYSEUR

La gestion des options de l'analyseur libxml2 a été unifiée et améliorée dans XML::LibXML 1.70. Vous pouvez maintenant définir des options par défaut pour une instance d'analyseur particulière en les passant au constructeur sous la forme "XML::LibXML->new({name=>value, ...})" ou "XML::LibXML->new(name=>value,...)". Les options peuvent être interrogées et modifiées à l'aide des méthodes suivantes (les interfaces avant 1.70 telles que "$parser->load_ext_dtd(0)" existent également, voir ci-dessous) :

option_exists
$parser->option_exists($name);

Renvoie 1 si la version actuelle de XML::LibXML supporte l'option $name, sinon renvoie 0 (notez que cela ne signifie pas nécessairement que l'option est supportée par la bibliothèque sous-jacente libxml2).

get_option
t_option">get_option 
$parser->get_option($name);

Retourne la valeur actuelle de l'option du parseur $name.

set_option
$parser->set_option($name,$value);

Définit l'option $name à la valeur $value.

set_options
$parser->set_options({$name=>$value,...});

Définit plusieurs options d'analyse en même temps.

NOTE IMPORTANTE : Cette documentation reflète les indicateurs d'analyse disponibles dans libxml2 2.7.3. Certaines options n'ont aucun effet si une version plus ancienne de libxml2 est utilisée.

Chacun des indicateurs listés ci-dessous est étiqueté

/parser/
s'il peut être utilisé avec un objet de parseur "XML::LibXML" (c'est-à-dire passé à "XML::LibXML->new", "XML::LibXML->set_option", etc.)
/html/
s'il peut être passé aux méthodes "parse_html_*"
/reader/
s'il peut être utilisé avec "XML::LibXML::Reader".

Sauf indication contraire, la valeur par défaut des options booléennes est 0 (faux).

Les options disponibles sont :

URI
/parser, html, reader/

Dans le cas de l'analyse de chaînes ou de descripteurs de fichiers, XML::LibXML ne connaît pas l'URI de base du document. Pour que les références relatives comme XIncludes fonctionnent, il faut définir une URI de base, qui est ensuite utilisée pour le document analysé.

line_numbers
/parser, html, reader/

Si cette option est activée, libxml2 stockera le numéro de ligne de chaque nœud élément dans le document analysé. Le numéro de ligne peut être obtenu en utilisant la méthode line_number() de la classe "XML::LibXML::Node" (pour les nœuds non élémentaires, cela peut renvoyer le numéro de ligne de l'élément contenant). Les numéros de ligne sont également utilisés pour signaler les positions des erreurs de validation.

IMPORTANT : En raison des limitations de la bibliothèque libxml2, les numéros de ligne supérieurs à 65535 seront renvoyés comme 65535. Malheureusement, c'est une longue et triste histoire, veuillez consulter http://bugzilla.gnome.org/show_bug.cgi?id=325533 pour plus de détails.

encoding
/html/

encodage des caractères de l'entrée

recover
/parser, html, reader/

récupérer des erreurs ; valeurs possibles : 0, 1 et 2

Une valeur vraie active le mode de récupération, qui permet d'analyser des données XML ou HTML corrompues. Le mode de récupération permet au parseur de renvoyer la partie du document d'entrée qui a été analysée avec succès. Ceci est utile pour les documents presque bien formés, où par exemple une balise de fermeture manque quelque part. Néanmoins, XML::LibXML n'analysera que jusqu'à la première erreur fatale (non récupérable), signalant les erreurs d'analyse récupérables comme des avertissements. Pour supprimer même ces avertissements, utilisez recover=>2.

Notez que la validation est désactivée automatiquement en mode récupération.

expand_entities
/parser, reader/

substituer les entités ; valeurs possibles : 0 et 1 ; par défaut : 1

Notez que bien que cet indicateur désactive la substitution d'entités, il n'empêche pas le parseur de charger des entités externes ; lorsque la substitution d'une entité externe est désactivée, l'entité sera représentée dans l'arbre du document par un nœud XML_ENTITY_REF_NODE dont le sous-arbre sera le contenu obtenu en analysant la ressource externe ; bien que cette imbrication soit visible depuis le DOM, elle est transparente pour le modèle de données XPath, il est donc possible de faire correspondre des nœuds dans une entité non étendue avec la même expression XPath que si l'entité avait été étendue. Voir aussi ext_ent_handler.

ext_ent_handler
/parser/

Fournir un gestionnaire d'entités externes personnalisé à utiliser lorsque expand_entities est défini à 1. La valeur possible est une référence de sous-routine.

Cette fonctionnalité ne fonctionne pas correctement dans libxml2 < 2.6.27 !

La sous-routine fournie est appelée chaque fois que le parseur a besoin de récupérer le contenu d'une entité externe. Elle est appelée avec deux arguments : l'ID système (URI) et l'ID public. La valeur renvoyée par la sous-routine est analysée comme le contenu de l'entité.

Cette méthode peut être utilisée pour désactiver complètement le chargement d'entités, par exemple pour prévenir des exploits du type décrit à (http://searchsecuritychannel.techtarget.com/generic/0,295582,sid97_gci1304703,00.html), où un service est trompé pour exposer ses données privées en le faisant analyser un fichier distant (flux RSS) qui contient une référence d'entité vers un fichier local (par exemple, "/etc/fstab").

Une solution plus granulaire à ce problème est cependant fournie par des résolveurs d'URL personnalisés, comme dans

my $c = XML::LibXML::InputCallback->new();
sub match {   # accepter les URI file:/ sauf les catalogues XML dans /etc/xml/
  my ($uri) = @_;
  return ($uri=~m{^file:/}
          and $uri !~ m{^file:///etc/xml/})
         ? 1 : 0;
}
$c->register_callbacks([ \&match, sub{}, sub{}, sub{} ]);
$parser->input_callbacks($c);
load_ext_dtd
/parser, reader/

charger la sous-partie DTD externe lors de l'analyse ; valeurs possibles : 0 et 1. Sauf indication contraire, XML::LibXML définit cette option à 1.

Cet indicateur est également requis pour la validation DTD, pour fournir des attributs complets et pour étendre les entités, indépendamment du fait que le document ait une sous-partie interne. Ainsi, désactiver le chargement de la DTD externe désactivera également l'extension des entités, la validation et les attributs complets sur les sous-parties internes.

complete_attributes
/parser, reader/

créer les attributs DTD par défaut ; valeurs possibles : 0 et 1

validation
/parser, reader/

valider avec la DTD ; valeurs possibles : 0 et 1

suppress_errors
/parser, html, reader/

supprimer les rapports d'erreurs ; valeurs possibles : 0 et 1

suppress_warnings
/parser, html, reader/

supprimer les rapports d'avertissements ; valeurs possibles : 0 et 1

pedantic_parser
/parser, html, reader/

rapport d'erreurs pédant ; valeurs possibles : 0 et 1

no_blanks
/parser, html, reader/

supprimer les nœuds vides ; valeurs possibles : 0 et 1

no_defdtd
/html/

ne pas ajouter de DOCTYPE par défaut ; valeurs possibles : 0 et 1

la valeur par défaut est (0) pour ajouter une DTD lorsque le HTML d'entrée n'en a pas

expand_xinclude ou xinclude
/parser, reader/

implémenter la substitution XInclude ; valeurs possibles : 0 et 1

Développe les balises XInclude immédiatement lors de l'analyse du document. Notez que le parseur utilisera les résolveurs d'URI installés via "XML::LibXML::InputCallback" pour analyser le document inclus (le cas échéant).

no_xinclude_nodes
/parser, reader/

ne pas générer de nœuds XINCLUDE START/END ; valeurs possibles : 0 et 1

no_network
/parser, html, reader/

interdire l'accès réseau ; valeurs possibles : 0 et 1

Si défini à vrai, toutes les tentatives de récupération de ressources non locales (comme les DTD ou les entités externes) échoueront (sauf si des rappels personnalisés sont définis).

Il peut être nécessaire d'utiliser l'indicateur "recover" pour traiter des documents nécessitant de telles ressources alors que le réseau est désactivé.

clean_namespaces
/parser, reader/

supprimer les déclarations de namespaces redondantes lors de l'analyse ; valeurs possibles : 0 et 1.

no_cdata
/parser, html, reader/

fusionner CDATA en nœuds texte ; valeurs possibles : 0 et 1

no_basefix
/parser, reader/

ne pas corriger les URI xml#base de XINCLUDE ; valeurs possibles : 0 et 1

huge
/parser, html, reader/

relâcher toute limite codée en dur du parseur ; valeurs possibles : 0 et 1. Sauf indication contraire, XML::LibXML définit cette option à 0.

Note : la valeur par défaut de cette option a été modifiée pour se protéger contre le déni de service par des attaques d'expansion d'entités. Avant d'activer cette option, assurez-vous d'avoir pris des mesures alternatives pour protéger votre application contre ce type d'attaque.

gdome
/parser/

CETTE OPTION EST EXPÉRIMENTALE !

Bien que très puissante, l'implémentation DOM de XML::LibXML est incomplète par rapport aux spécifications DOM de niveau 2 ou 3. XML::GDOME est également basé sur libxml2 et fournit une implémentation DOM assez complète en encapsulant libgdome. Cet indicateur vous permet d'utiliser simultanément toutes les options d'analyse de XML::LibXML et l'implémentation DOM de XML::GDOME.

Pour utiliser cette fonction, il faut installer libgdome et configurer XML::LibXML pour utiliser cette bibliothèque. Pour cela, vous devez reconstruire XML::LibXML !

Note : cette fonctionnalité n'a pas été testée sérieusement dans les versions récentes de XML::LibXML.

XML::LibXML::Parser(3pm)

NAME

XML::LibXML::Parser - The XML::LibXML parser class

SYNOPSIS

    use XML::LibXML;

    my $parser = XML::LibXML::Parser->new();
    my $dom = $parser->parse_string($xml_string);
    # or
    my $dom = $parser->parse_file($file_path);
    # or
    my $dom = $parser->parse_fh($filehandle);

    # Set parser options
    $parser->validation(1);
    $parser->load_ext_dtd(1);

    # Access parser options
    if ($parser->validation()) {
        print "Validation enabled\n";
    }

    # Set other options
    $parser->pedantic_parser(1);
    $parser->recover(); # Sets recover to 1, enabling error recovery
    $parser->recover(2); # Enables more aggressive error recovery

    # Set URI option
    $parser->base_uri('http://example.com/');
    print $parser->base_uri();

    # Using XML Catalogs
    $parser->load_catalog('my_catalog.xml');

    # Error handling
    eval {
        my $dom = $parser->parse_string($invalid_xml);
        # ... process $dom ...
    };
    if ($@) {
        # handle error
        print "An error occurred: $@\n";
    }

    # Or use the new error handler
    $XML::LibXML::Error::throw_as_exception = 1;
    eval {
        my $dom = $parser->parse_string($invalid_xml);
        # ... process $dom ...
    };
    if ($@) {
        # $@ is now an XML::LibXML::Error object
        print "An error occurred: $@\n";
        # Or more detailed error info
        print "Error level: ", $@->level, "\n";
        print "Error message: ", $@->message, "\n";
        print "Error file: ", $@->file, "\n";
        print "Error line: ", $@->line, "\n";
    }

PARSING

The primary methods for parsing XML are:

new()
Creates a new parser object.
parse_string( $xml_string )
Parses an XML document from a string. Returns an XML::LibXML::Document object.
parse_file( $file_path )
Parses an XML document from a file. Returns an XML::LibXML::Document object.
parse_fh( $filehandle )
Parses an XML document from a filehandle. Returns an XML::LibXML::Document object.

SERIALIZATION

Methods to serialize the DOM:

toString()
Serializes the DOM to a string.
toFile( $filename )
Serializes the DOM to a file.
toFH( $filehandle )
Serializes the DOM to a filehandle.

These methods are part of the XML::LibXML::Document class, not the parser class itself.

PARSER OPTIONS

For compatibility with XML::LibXML versions prior to 1.70, the following methods are also supported for querying and setting the corresponding parser options (if called without arguments, the methods return the current value of the corresponding parser options; with an argument sets the option to a given value):

$parser->validation();
$parser->recover();
$parser->pedantic_parser();
$parser->line_numbers();
$parser->load_ext_dtd();
$parser->complete_attributes();
$parser->expand_xinclude();
$parser->gdome_dom();
$parser->clean_namespaces();
$parser->no_network();

The following obsolete methods trigger parser options in some special way:

recover_silently
$parser->recover_silently(1);

If called without an argument, returns true if the current value of the "recover" parser option is 2 and returns false otherwise. With a true argument sets the "recover" parser option to 2; with a false argument sets the "recover" parser option to 0.

expand_entities
$parser->expand_entities(0);

Get/set the "expand_entities" option. If called with a true argument, also turns the "load_ext_dtd" option to 1.

keep_blanks
$parser->keep_blanks(0);

This is actually the opposite of the "no_blanks" parser option. If used without an argument retrieves negated value of "no_blanks". If used with an argument sets "no_blanks" to the opposite value.

base_uri
$parser->base_uri( $your_base_uri );

Get/set the "URI" option.

XML CATALOGS

"libxml2" supports XML catalogs. Catalogs are used to map remote resources to their local copies. Using catalogs can speed up parsing processes if many external resources from remote addresses are loaded into the parsed documents (such as DTDs or XIncludes).

Note that libxml2 has a global pool of loaded catalogs, so if you apply the method "load_catalog" to one parser instance, all parser instances will start using the catalog (in addition to other previously loaded catalogs).

Note also that catalogs are not used when a custom external entity handler is specified. At the current state it is not possible to make use of both types of resolving systems at the same time.

load_catalog
$parser->load_catalog( $catalog_file );

Loads the XML catalog file $catalog_file.

# Global external entity loader (similar to ext_ent_handler option
# but this works really globally, also in XML::LibXSLT include etc..)
XML::LibXML::externalEntityLoader(\&my_loader);

ERROR REPORTING

XML::LibXML throws exceptions during parsing, validation or XPath processing (and some other occasions). These errors can be caught by using eval blocks. The error is stored in $@. There are two implementations: the old one throws $@ which is just a message string, in the new one $@ is an object from the class XML::LibXML::Error; this class overrides the operator "" so that when printed, the object flattens to the usual error message.

XML::LibXML throws errors as they occur. This is a very common misunderstanding in the use of XML::LibXML. If the eval is omitted, XML::LibXML will always halt your script by "croaking" (see Carp man page for details).

Also note that an increasing number of functions throw errors if bad data is passed as arguments. If you cannot assure valid data passed to XML::LibXML you should eval these functions.

Note: since version 1.59, get_last_error() is no longer available in XML::LibXML for thread-safety reasons.
