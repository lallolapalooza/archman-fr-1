NOM

XML::LibXML::Devel - rend accessibles les fonctions de LibXML.xs

SYNOPIS

/**********************************************
 * Fonctions C que vous voulez accéder
 */
xmlNode *return_node();
void receive_node(xmlNode *);
###############################################
# Code XS
void *
  xs_return_node
  CODE:
      RETVAL = return_node();
  OUTPUT:
      RETVAL
void
  xs_receive_node
      void *n
  CODE:
      receive_node(n);
###############################################
# Code Perl
use XML::LibXML::Devel;
sub return_node
{
  my $raw_node = xs_return_node();
  my $node = XML::LibXML::Devel::node_to_perl($raw_node);
  XML::LibXML::Devel::refcnt_inc($raw_node);
  return $node;
}
sub receive_node
{
  my ($node) = @_;
  my $raw_node = XML::LibXML::Devel::node_from_perl($node);
  xs_receive_node($raw_node);
  XML::LibXML::Devel::refcnt_inc($raw_node);
}

DESCRIPTION

"XML::LibXML::Devel" rend accessibles les fonctions de LibXML.xs nécessaires pour encapsuler les nœuds de libxml2 dans et hors des nœuds XML::LibXML::Node. Cela permet des dépendances plus propres que l'utilisation directe de LibXML.so.

Pour XSer une bibliothèque qui utilise des nœuds libxml2, la première étape consiste à le faire afin que xmlNodePtr soit passé en tant que void *. Ces nœuds bruts sont ensuite transformés en nœuds libxml en utilisant ces fonctions de "Devel".

Soyez conscient que ce module est actuellement plutôt expérimental. Les noms de fonctions peuvent changer si j'exerce plus de fonctions et que j'introduis une convention de nommage raisonnable.

Soyez également conscient que ce module est un excellent outil pour provoquer des segfaults et introduire des fuites de mémoire. Il fournit cependant un remède partiel en rendant "xmlMemUsed" disponible sous le nom de "mem_used".

FONCTIONS

GESTION DES NŒUDS

node_to_perl
node_to_perl($raw_node);

Retourne un objet LibXML::Node. Celui-ci possède un nœud proxy avec un compteur de références et un propriétaire attaché. Le nœud brut sera supprimé dès que le compteur de références atteindra zéro. Si la bibliothèque C conserve un pointeur vers le nœud brut, vous devez appeler refcnt_inc immédiatement. Vous devez également remplacer xmlFreeNode par un appel à refcnt_dec.

node_to_perl
node_from_perl($node);

Retourne un nœud brut. C'est un pointeur void * et vous ne pouvez rien faire d'autre que de le passer à des fonctions qui le traitent comme un xmlNodePtr. Le nœud brut sera libéré dès que son compteur de références atteindra zéro. Si la bibliothèque C conserve un pointeur vers le nœud brut, vous devez appeler refcnt_inc immédiatement. Vous devez également remplacer xmlFreeNode par un appel à refcnt_dec.

refcnt_inc
refcnt_inc($raw_node);

Incrémente le compteur de références du nœud brut. Le nœud brut doit déjà être connu de Perl pour avoir un compteur de références.

refcnt_dec
refcnt_dec($raw_node);

Décrémente le compteur de références du nœud brut et retourne la valeur qu'il avait avant. Si le compteur atteint zéro ou moins, cette méthode libérera le nœud proxy détenant le compteur de références. Si le nœud fait partie d'un sous-arbre, refcnt_dec corrigera les comptes de référence et supprimera le sous-arbre s'il n'est plus nécessaire.

refcnt
refcnt($raw_node);

Retourne la valeur du compteur de références.

fix_owner
fix_owner($raw_node, $raw_parent);

Cette fonction corrige les comptes de référence pour un sous-arbre entier. Il est très important de corriger un sous-arbre entier après des opérations sur les nœuds où les documents ou le nœud propriétaire peuvent être modifiés. cette méthode est consciente des nœuds qui appartiennent déjà à un certain nœud propriétaire.

DÉBOGAGE MÉMOIRE

$ENV{DEBUG_MEMORY}
BEGIN {$ENV{DEBUG_MEMORY} = 1;};
use XML::LibXML;

Cela active le débogage de la mémoire de libxml2. Il doit être défini avant le chargement de XML::LibXML.

mem_used
mem_used();

Retourne le nombre d'octets actuellement alloués.

EXPORT

Aucun par défaut.
