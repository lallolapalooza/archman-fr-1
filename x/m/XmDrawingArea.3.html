XmDrawingArea(library call) XmDrawingArea(library call)

NOM

XmDrawingArea — La classe de widget DrawingArea

SYNTAXE

#include <Xm/DrawingA.h>

DESCRIPTION

DrawingArea est un widget vide qui est facilement adaptable à une variété d'utilisations. Il ne dessine rien et ne définit aucun comportement à l'exception de l'invocation de rappels. Les rappels notifient l'application lorsque des graphiques doivent être dessinés (événements d'exposition ou redimensionnement du widget) et lorsque le widget reçoit une entrée du clavier ou de la souris.

Il incombe aux applications de définir l'apparence et le comportement selon les besoins, en réponse aux rappels de DrawingArea.

DrawingArea est également un widget composite et une sous-classe de XmManager qui prend en charge une gestion minimale de la géométrie pour plusieurs enfants widgets ou gadgets.

DrawingArea utilise la ressource XmNinitialFocus de XmManager pour définir si DrawingArea recevra le focus lorsqu'il sera traversé, même s'il a des enfants traversables. Si XmNinitialFocus est NULL, DrawingArea ne reçoit le focus que s'il n'a aucun enfant traversable. Si XmNinitialFocus n'est pas NULL, alors DrawingArea reçoit le focus lorsqu'il est traversé. Dans ce dernier cas, l'application doit d'abord être capable de réaliser que DrawingArea recevra le focus, puis, le cas échéant, doit appeler la fonction XmProcessTraversal pour l'enfant désiré, ou naviguer sur les objets graphiques privés de DrawingArea.

Les ressources suivantes ne sont actuellement pas utilisées par le widget DrawingArea : XmNshadowThickness, XmNtopShadowPixmap, XmNbottomShadowPixmap, XmNtopShadowColor, et XmNbottomShadowColor

Comportement de transfert de données

DrawingArea n'a pas de procédure de conversion de classe de widget ni de procédure de destination. Les sous-classes et les procédures XmNconvertCallback sont responsables de toute conversion de sélections. Les sous-classes et les procédures XmNdestinationCallback sont responsables de tout transfert de données vers le widget.

Classes

DrawingArea hérite du comportement et des ressources des classes Core, Composite, Constraint, et XmManager.

Le pointeur de classe est xmDrawingAreaWidgetClass.

Le nom de la classe est XmDrawingArea.

Informations sur le rappel

Un pointeur vers la structure suivante est passé aux procédures XmNexposeCallback, XmNinputCallback et XmNresizeCallback :

typedef struct
{
        int raison;
        XEvent * événement;
        Window fenêtre;
} XmDrawingAreaCallbackStruct;
raison
Indique la raison pour laquelle le rappel a été appelé.
événement
Pointe vers l'XEvent qui a déclenché le rappel. Ceci est NULL pour le XmNresizeCallback.
fenêtre
Est défini sur la fenêtre du widget.

Un pointeur vers la structure suivante est passé aux procédures XmNconvertCallback :

typedef struct
{
        int raison;
        XEvent *événement;
        Atom sélection;
        Atom cible;
        XtPointer données_source;
        XtPointer données_emplacement;
        int indicateurs;
        XtPointer parm;
        int format_parm;
        unsigned long longueur_parm;
        int statut;
        XtPointer valeur;
        Atom type;
        int format;
        unsigned long longueur;
} XmConvertCallbackStruct;
raison
Indique la raison pour laquelle le rappel a été appelé.
événement
Pointe vers l'XEvent qui a déclenché le rappel. Il peut être NULL.
sélection
Indique la sélection pour laquelle la conversion est demandée. Les valeurs possibles sont CLIPBOARD, PRIMARY, SECONDARY et _MOTIF_DROP.
cible
Indique la cible de conversion.
données_source
Contient des informations sur la source de la sélection. Lorsque la sélection est _MOTIF_DROP, données_source est le DragContext. Sinon, il est NULL.
données_emplacement
Contient des informations sur l'emplacement des données à convertir. Si la valeur est NULL, les données à transférer consistent en la sélection actuelle du widget.
indicateurs
Indique le statut de la conversion. Voici les valeurs possibles :
XmCONVERTING_NONE
Cet indicateur n'est actuellement pas utilisé.
XmCONVERTING_PARTIAL
Le widget cible a pu être converti, mais certaines données ont été perdues.
XmCONVERTING_SAME
La cible de conversion est la source des données à transférer.
XmCONVERTING_TRANSACT
Cet indicateur n'est actuellement pas utilisé.
parm
Contient des données de paramètre pour cette cible. S'il n'y a pas de données de paramètre, la valeur est NULL.
Lorsque sélection est CLIPBOARD et cible est _MOTIF_CLIPBOARD_TARGETS ou _MOTIF_DEFERRED_CLIPBOARD_TARGETS, la valeur est l'opération demandée (XmCOPY, XmMOVE ou XmLINK).
format_parm
Spécifie si les données dans parm doivent être considérées comme une liste de quantités char, short ou long. Les valeurs possibles sont 0 (lorsque parm est NULL), 8 (lorsque les données dans parm doivent être considérées comme une liste de char), 16 (lorsque les données dans parm doivent être considérées comme une liste de short) ou 32 (lorsque les données dans parm doivent être considérées comme une liste de long). Notez que format_parm symbolise un type de données, et non le nombre de bits dans chaque élément de liste. Par exemple, sur certaines machines, un format_parm de 32 signifie que les données dans parm doivent être considérées comme une liste de quantités de 64 bits, et non de 32 bits.
longueur_parm
Spécifie le nombre d'éléments de données dans parm, où chaque élément a la taille spécifiée par format_parm. Lorsque parm est NULL, la valeur est 0.
statut
Un membre ENTRÉE/SORTIE qui spécifie le statut de la conversion. La valeur initiale est XmCONVERT_DEFAULT. La procédure de rappel peut définir ce membre sur l'une des valeurs suivantes :
XmCONVERT_DEFAULT
Cette valeur signifie que la procédure de conversion de la classe du widget, le cas échéant, est appelée après le retour des procédures de rappel. Si la procédure de conversion de la classe du widget produit des données, elle écrase les données fournies par les procédures de rappel dans le membre valeur.
XmCONVERT_MERGE
Cette valeur signifie que la procédure de conversion de la classe du widget, le cas échéant, est appelée après le retour des procédures de rappel. Si la procédure de conversion de la classe du widget produit des données, elle ajoute ses données à celles fournies par les procédures de rappel dans le membre valeur. Cette valeur est destinée à être utilisée avec des cibles qui produisent des listes de données, telles que TARGETS.
XmCONVERT_DONE
Cette valeur signifie que la procédure de rappel a terminé la conversion avec succès. La procédure de conversion de la classe du widget, le cas échéant, n'est pas appelée après le retour des procédures de rappel.
XmCONVERT_REFUSE
Cette valeur signifie que la procédure de rappel a interrompu le processus de conversion sans terminer la conversion demandée. La procédure de conversion de la classe du widget, le cas échéant, n'est pas appelée après le retour des procédures de rappel.
valeur
Un paramètre ENTRÉE/SORTIE qui contient toutes les données produites par la procédure de rappel en résultat de la conversion. La valeur initiale est NULL. Si la procédure de rappel définit ce membre, elle doit s'assurer que les membres type, format et longueur correspondent aux données dans valeur. La procédure de rappel est responsable de l'allocation, mais pas de la libération, de la mémoire lors de la définition de ce membre.
type
Un paramètre ENTRÉE/SORTIE qui indique le type des données dans le membre valeur. La valeur initiale est INTEGER.
format
Un paramètre ENTRÉE/SORTIE qui spécifie si les données dans valeur doivent être considérées comme une liste de quantités char, short ou long. La valeur initiale est 8. La procédure de rappel peut définir ce membre sur 8 (pour une liste de char), 16 (pour une liste de short) ou 32 (pour une liste de long).
longueur
Un membre ENTRÉE/SORTIE qui spécifie le nombre d'éléments de données dans valeur, où chaque élément a la taille symbolisée par format. La valeur initiale est 0.

        XEvent *événement;
        Atom sélection;
        XtEnum opération;
        int indicateurs;
        XtPointer transfer_id;
        XtPointer données_destination;
        XtPointer données_emplacement;
        Time temps;

Indique la raison pour laquelle le rappel a été appelé.
événement
Pointe vers l'XEvent qui a déclenché le rappel. Il peut être NULL.
sélection
Indique la sélection pour laquelle le transfert de données est demandé. Les valeurs possibles sont CLIPBOARD, PRIMARY, SECONDARY et _MOTIF_DROP.
opération
Indique le type d'opération de transfert demandée.
•
Lorsque la sélection est PRIMARY, les valeurs possibles sont XmMOVE, XmCOPY et XmLINK.
•
Lorsque la sélection est SECONDARY ou CLIPBOARD, les valeurs possibles sont XmCOPY et XmLINK.
•
Lorsque la sélection est _MOTIF_DROP, les valeurs possibles sont XmMOVE, XmCOPY, XmLINK et XmOTHER. Une valeur de XmOTHER signifie que la procédure de rappel doit obtenir des informations supplémentaires de la XmDropProcCallbackStruct dans le membre données_destination.
indicateurs
Indique si le widget de destination est également la source des données à transférer. Voici les valeurs possibles :
XmCONVERTING_NONE
Le widget de destination n'est pas la source des données à transférer.
XmCONVERTING_SAME
Le widget de destination est la source des données à transférer.
transfer_id

XmDrawingArea(3)

NAME

XmDrawingArea — zone de dessin pour l'application.

SYNOPSIS

     #include <Xm/DrawingA.h>

DESCRIPTION

La zone de dessin XmDrawingArea est un widget simple qui permet aux applications de recevoir et de traiter des événements d'entrée utilisateur et de gérer les événements d'exposition et de redimensionnement. Il est principalement utilisé pour la création de zones de dessin personnalisées dans une interface utilisateur.

Callbacks

Le widget XmDrawingArea a les callbacks suivants :

XmNinputCallback
Est appelé lorsqu'un événement d'entrée utilisateur (par exemple, un clic de souris ou une frappe au clavier) se produit dans la zone de dessin. Les données de rappel sont un pointeur vers une structure XmDrawingAreaCallbackStruct.
XmNexposeCallback
Est appelé lorsqu'un événement d'exposition se produit pour la zone de dessin. Cela se produit généralement lorsque la fenêtre doit être redessinée, par exemple, après avoir été couverte et découverte. Les données de rappel sont un pointeur vers une structure XmDrawingAreaCallbackStruct.
XmNresizeCallback
Est appelé lorsqu'une ressource de redimensionnement de la zone de dessin se produit. Les données de rappel sont un pointeur vers une structure XmDrawingAreaCallbackStruct.

La structure XmDrawingAreaCallbackStruct est définie comme suit :

typedef struct {
    int reason;
    XEvent *event;
    Window window;
    Dimension width;
    Dimension height;
    XtPointer data; /* pour les transferts de données via les sélections */
} XmDrawingAreaCallbackStruct;
reason
Indique la raison pour laquelle le callback est appelé. Il peut s'agir de XmCR_INPUT, XmCR_EXPOSE ou XmCR_RESIZE.
event
Un pointeur vers la structure d'événement X (si applicable).
window
La fenêtre de la zone de dessin.
width
La nouvelle largeur de la zone de dessin (pour XmCR_RESIZE).
height
La nouvelle hauteur de la zone de dessin (pour XmCR_RESIZE).
data
Contient des informations supplémentaires pour des opérations spécifiques.

Transfer Data Callbacks

Les callbacks suivants sont liés au transfert de données via les sélections :

transfer_type
Indique le type de transfert de données. Les valeurs possibles sont XmTRANSFER_TYPE_CLIPBOARD, XmTRANSFER_TYPE_PRIMARY, XmTRANSFER_TYPE_SECONDARY et XmTRANSFER_TYPE_DRAG_AND_DROP.
selection
Indique la sélection utilisée pour le transfert. Les valeurs possibles sont PRIMARY, SECONDARY et CLIPBOARD.
transfer_id
Un identifiant unique pour la transaction de transfert.
destination_data
Contient des informations sur la destination. Lorsque la sélection est _MOTIF_DROP, les procédures de rappel sont appelées par le XmNdropProc du site de dépôt, et destination_data est un pointeur vers la XmDropProcCallbackStruct passée à la procédure XmNdropProc. Lorsque la sélection est SECONDARY, destination_data est un Atom représentant une cible recommandée par le propriétaire de la sélection pour une utilisation lors de la conversion de la sélection. Sinon, destination_data est NULL.
location_data
Contient des informations sur l'emplacement où les données doivent être transférées. La valeur est toujours NULL lorsque la sélection est SECONDARY ou CLIPBOARD. Si la valeur est NULL, les données doivent être insérées à la position du curseur du widget. location_data n'est valide que pendant la durée d'un transfert. Une fois que les procédures XmTransferDone commencent à être appelées, location_data ne sera plus stable.
time
Indique l'heure à laquelle l'opération de transfert a commencé.

Translations

XmDrawingArea hérite des traductions de XmManager. Avant d'appeler les actions XmManager, tous les événements dans les traductions héritées, à l'exception de <BtnMotion>, <EnterWindow>, <LeaveWindow>, <FocusIn> et <FocusOut>, appellent également l'action DrawingAreaInput().

XmDrawingArea a les traductions supplémentaires suivantes. Les noms de touches suivants sont répertoriés dans la syntaxe de la table de traduction des événements de touche standard X. Ce format est celui utilisé par Motif pour spécifier les actions du widget correspondant à une touche donnée. Un bref aperçu du format est fourni sous VirtualBindings(3). Pour une description complète du format, veuillez vous référer à la documentation des intrinsèques du kit d'outils X.

<BtnDown>:
DrawingAreaInput()
<BtnUp>:
DrawingAreaInput()
<KeyDown>:
DrawingAreaInput() ManagerGadgetKeyInput()
<KeyUp>:
DrawingAreaInput()

Routines d'action

Les routines d'action XmDrawingArea sont :

DrawingAreaInput():
Sauf si l'événement se produit dans un gadget, appelle les callbacks pour XmNinputCallback
ManagerGadgetKeyInput():
Permet au gadget courant de traiter un événement clavier

Comportement supplémentaire

Le widget XmDrawingArea a le comportement supplémentaire suivant :

<Expose>:
Appelle les callbacks pour XmNexposeCallback
<Widget Resize>:
Appelle les callbacks pour XmNresizeCallback

Liaisons virtuelles

Les liaisons pour les touches virtuelles sont spécifiques au vendeur. Pour plus d'informations sur les liaisons pour les boutons et les touches virtuels, voir VirtualBindings(3).
