NOM

XmPrintShell — une classe de widget shell utilisée pour l'impression dans Motif

SYNOPSIS

#include <Xm/Print.h>
Boolean XmIsPrintShell(
Widget);

DESCRIPTION

Le XmPrintShell fournit au programmeur d'application Motif une API orientée widget Xt pour certaines des ressources d'impression X et un rappel pour gérer la pagination.

Le XmPrintShell fournit un rappel simple pour gérer la logique de pagination et un ensemble de ressources pour obtenir et définir les attributs communs de l'imprimante.

S'il n'est pas créé sur une connexion XPrint, XmPrintShell se comporte comme un applicationShell normal.

Le XmPrintShell initialise également le mécanisme de gestion des événements d'extension Xp, en enregistrant un sélecteur d'extension qui appelle XpSelectInput et un répartiteur d'événements pour les événements Xp d'impression et d'attributs, afin que les applications puissent utiliser XtInsertEventTypeHandler pour enregistrer leur propre gestionnaire avec les événements Xp.

Arguments

Aucune fonction XmCreate n'est fournie, car il s'agit d'un shell de haut niveau, très probablement créé via une routine de création de shell Xt ou XmPrintSetup.

Classes

XmPrintShell est une sous-classe de ApplicationShell; il hérite du comportement, des ressources et des traits de toutes ses superclasses. Le pointeur de classe est XmPrintShellWidgetClass.

XmNstartJobCallback
Spécifie le rappel qui pilote le début du rendu. Il est sûr pour une application de commencer le rendu après l'activation de ce rappel. XpStartJob doit être appelé pour déclencher ce rappel.
XmNendJobCallback
Spécifie le rappel qui pilote la fin du rendu. Informe le client que tout le rendu a été traité (que ce soit sur impression vers fichier ou spooling normal). XpEndJob est appelé par le shell d'impression pour déclencher ce rappel.
XmNpageSetupCallback
Spécifie le rappel qui pilote la mise en page. Il est sûr pour une application de commencer le rendu à partir de ce rappel, même si le XmNstartJobCallback n'est pas utilisé.
XmNminX, XmNminY, XmNmaxX, XmNmaxY
Spécifient la zone imprimable de la page dans le contexte d'impression actuel. XmPrintShell maintient également une taille correcte à tout moment en mettant à jour sa propre dimension de widget chaque fois qu'un attribut, tel que la résolution ou l'orientation, change. Sa taille est définie dans sa routine Initialize afin que l'application puisse compter sur une taille correcte avant que le premier appel StartPage ne soit émis.

XmNpdmNotificationCallback
Un rappel informant l'application sur le statut du PDM (voir XmPrintPopupPDM). Un XmPrintShellCallbackStruct est utilisé, avec la raison :
•
XmCR_PDM_NONE : aucun PDM disponible sur cet écran pour la sélection nommée (fournie en détail)
•
XmCR_PDM_START_VXAUTH : le PDM n'est pas autorisé à se connecter à l'écran vidéo.
•
XmCR_PDM_START_PXAUTH : le PDM n'est pas autorisé à se connecter à l'écran d'impression.
•
XmCR_PDM_UP : le PDM est en cours d'exécution
•
XmCR_PDM_OK : le PDM s'est terminé avec le statut OK
•
XmCR_PDM_CANCEL : le PDM s'est terminé avec ANNULER
•
XmCR_PDM_START_ERROR : le PDM ne peut pas démarrer en raison d'une erreur (généralement enregistrée)
•
XmCR_PDM_EXIT_ERROR : le PDM s'est terminé avec une erreur

Informations de rappel

Les rappels XmNstartJobCallback, XmNendJobCallback, XmNpageSetupCallback et XmNpdmNotificationCallback opèrent sur une XmPrintShellCallbackStruct, qui est définie comme suit :

typedef struct
{
    int     reason;  /* XmCR_START_JOB, XmCR_END_JOB,
                        XmCR_PAGE_SETUP, XmCR_PDM_* */
    XEvent  *event;
    XPContext print_context;
    Boolean last_page; /* in_out */
    XtPointer detail;
} XmPrintShellCallbackStruct;

Comportement supplementaire

Le champ last_page n'est pertinent que lorsque la raison est XmCR_PAGE_SETUP.

Le rappel de configuration de page est appelé avec last_page False pour informer l'application qu'elle doit préparer son état de mise en page interne pour la page suivante. Généralement, une application basée sur des widgets modifiera le contenu d'une Label affichant le numéro de page, ou fera défiler le contenu du widget Text.

Lorsque l'application a traité sa dernière page, elle doit définir le champ last_page de la structure de rappel sur True. Le rappel sera appelé une dernière fois après cela avec last_page False pour informer l'application qu'elle peut nettoyer son état interne en toute sécurité (par exemple, détruire les widgets).

Aucun dessin ne doit être effectué à l'intérieur de la fonction de rappel dans l'application ; il s'agit d'un modèle de programmation basé sur des événements d'exposition où les widgets se rendent eux-mêmes à partir de leurs méthodes d'exposition.

Le shell d'impression appelle XpStartPage après le rappel pageSetupCallback

/*----------*/ XmPrintSetPageCBStruct psp)
{
    static int cur_page = 0;
    cur_page++;
    if (! psp->last_page
        && curPage > 1) /* pas besoin de faire défiler pour la première page */
    {
        XmTextScroll(ptext, prows);  /* se préparer pour la page suivante */
    } else {    /**** J'ai terminé */
       XtDestroyWidget(pshell);
       XtCloseDisplay(XtDisplay(pshell));
    }
    if (cur_page == (int) n_pages) psp->last_page = True;
}

/*-------------*/

    pshell = XmPrintSetup (widget, pbs->print_screen,

Exemples d'utilisation de XmNdefaultPixmapResolution :

•
Une application réutilise les mêmes sources d'images qu'elle utilise pour l'interface vidéo, en XBM, XPM, PNG ou JPEG, pour les disposer sur ses pages imprimées. Dans ce cas, la mise à l'échelle est transparente.
    ! icon.xpm fait 30x30 pixels
    app*dialog.pushb.labelPixmap:icon.xpm
    ! l'impression est à 400 dpi
    app.print*form.lab.labelPixmap:icon.xpm
    ! 120x120 pixels sur le papier (mise à l'échelle automatique)
•
Une application fournit un nouvel ensemble de fichiers d'images, pour une résolution d'imprimante donnée (disons 300). Elle ne souhaite pas de mise à l'échelle automatique par la boîte à outils pour cette résolution, elle souhaite une mise à l'échelle basée sur ces images 300 dpi pour une résolution plus élevée. Elle crée son shell d'impression en interne en utilisant le nom "printHiRes" et ajoute ce qui suit dans son fichier de ressources :
    app.printHiRes.defaultPixmapResolution:300
    ! icon300.xpm fait 120x120 pixels
    app.printHiRes*form.lab.labelPixmap:icon300.xpm
    ! 120x120 pixels sur le papier (pas de mise à l'échelle)

De cette façon, une résolution d'imprimante de 600 entraînera une mise à l'échelle d'une image de 300 dpi par 2 (dpi=600 divisé par base=300), tandis qu'une résolution d'imprimante de 150 (en utilisant le nom de shell d'impression par défaut "print") utilisera l'icône de 100 dpi mise à l'échelle par 1,5 (dpi=150 divisé par base par défaut=100).
