XML::Atom::Server(3pm) Documentation Perl fournie par l'utilisateur XML::Atom::Server(3pm)

NOM

XML::Atom::Server - Un serveur pour l'API Atom

SYNOPIS

package My::Server;
use base qw( XML::Atom::Server );
sub handle_request {
    my $server = shift;
    $server->authenticate or return;
    my $method = $server->request_method;
    if ($method eq 'POST') {
        return $server->new_post;
    }
    ...
}
my %Passwords;
sub password_for_user {
    my $server = shift;
    my($username) = @_;
    $Passwords{$username};
}
sub new_post {
    my $server = shift;
    my $entry = $server->atom_body or return;
    ## $entry est un objet XML::Atom::Entry.
    ## ... Sauvegarder la nouvelle entrée ...
}
package main;
my $server = My::Server->new;
$server->run;

DESCRIPTION

XML::Atom::Server fournit une classe de base pour les serveurs API Atom. Il gère tout le traitement serveur principal, les formats SOAP et REST du protocole, ainsi que l'authentification WSSE. Il peut également fonctionner soit comme un gestionnaire mod_perl, soit dans le cadre d'un programme CGI.

Il ne fournit pas de fonctions spécifiques à une implémentation particulière, telles que la publication d'une entrée, la récupération d'une liste d'entrées, la suppression d'une entrée, etc. Les implémentations doivent hériter de XML::Atom::Server, surcharger la méthode handle_request, et gérer toutes les fonctions de ce type elles-mêmes.

SOUSCLASSES

Gestion des requêtes

Les sous-classes de XML::Atom::Server doivent surcharger la méthode handle_request pour effectuer tout le traitement des requêtes. L'implémentation doit définir tous les en-têtes de réponse, y compris le code de réponse et tous les en-têtes HTTP pertinents, et doit renvoyer un scalaire représentant le corps de la réponse à renvoyer au client.

Par exemple :

sub handle_request {
    my $server = shift;
    my $method = $server->request_method;
    if ($method eq 'POST') {
        return $server->new_post;
    }
    ## ... gérer GET, PUT, etc.
}

sub new_post {
    my $server = shift;
    my $entry = $server->atom_body or return;
    my $id = save_this_entry($entry);  ## Spécifique à l'implémentation
    $server->response_header(Location => $server->uri . '/entry_id=' . $id);
    $server->response_code(201);
    $server->response_content_type('application/x.atom+xml');
    return serialize_entry($entry);    ## Spécifique à l'implémentation
}

Authentification

Les serveurs qui nécessitent une authentification pour publier ou récupérer des entrées ou des flux doivent surcharger la méthode password_for_user. Étant donné un nom d'utilisateur (provenant de l'en-tête WSSE), password_for_user doit renvoyer le mot de passe de cet utilisateur en clair. Celui-ci sera ensuite combiné avec le nonce et l'heure de création pour générer le hachage, qui sera comparé au hachage envoyé dans l'en-tête WSSE. Si le nom d'utilisateur fourni n'existe pas dans votre base de données d'utilisateurs ou similaire, renvoyez simplement "undef".

Par exemple :

my %Passwords = ( foo => 'bar' );   ## Le mot de passe pour "foo" est "bar".
sub password_for_user {
    my $server = shift;
    my($username) = @_;
    $Passwords{$username};
}

MÉTHODES

XML::Atom::Server fournit une variété de méthodes à être utilisées par les sous-classes pour récupérer les en-têtes, le contenu et d'autres informations de requête, et pour définir ceux de la réponse.

Paramètres de requête client

  • $server->uri

    Renvoie l'URI de l'implémentation du serveur Atom.

  • $server->request_method

    Renvoie le nom de la méthode de requête envoyée au serveur par le client (par exemple, "GET", "POST", etc.). Notez que si le client a envoyé la requête dans une enveloppe SOAP, la méthode est obtenue à partir de l'en-tête HTTP SOAPAction.

  • $server->request_header($header)

    Récupère la valeur de l'en-tête de requête HTTP $header.

  • $server->request_content

    Renvoie un scalaire contenant le contenu d'une requête POST ou PUT du client.

  • $server->request_param($param)

    XML::Atom::Server analyse automatiquement le PATH_INFO envoyé dans la requête et le décompose en paires clé-valeur. Cela peut être utilisé pour passer des paramètres. Par exemple, dans l'URI

    http://localhost/atom-server/entry_id=1

    le paramètre entry_id sera défini sur 1.

    request_param renvoie la valeur du paramètre $param.

Configuration de la réponse

  • $server->response_header($header, $value)

    Définit la valeur de l'en-tête de réponse HTTP $header à $value.

  • $server->response_code([ $code ])

    Renvoie le code de réponse actuel à envoyer au client, et si $code est fourni, définit le code de réponse.

  • $server->response_content_type([ $type ])

    Renvoie l'en-tête Content-Type actuel à envoyer au client, et si $type est fourni, définit la valeur de cet en-tête.

Traitement de la requête

  • $server->authenticate

    Tente d'authentifier la requête sur la base des informations d'authentification présentes dans la requête (actuellement seulement WSSE). Cela appellera la méthode password_for_user dans la sous-classe pour obtenir le mot de passe en clair du nom d'utilisateur fourni dans la requête.

  • $server->atom_body

    Renvoie un objet XML::Atom::Entry contenant l'entrée envoyée dans la requête.

UTILISATION

Une fois que vous avez défini votre sous-classe de serveur, vous pouvez la configurer soit comme un programme CGI, soit comme un gestionnaire mod_perl.

Un programme CGI simple ressemblerait à ceci :

#!/usr/bin/perl -w
use strict;
use My::Server;
my $server = My::Server->new;
$server->run;

Une configuration simple de gestionnaire mod_perl ressemblerait à cela :

PerlModule My::Server
<Location /atom-server>
    SetHandler perl-script
    PerlHandler My::Server
</Location>

GESTION DES ERREURS

Si vous souhaitez renvoyer une erreur depuis handle_request, vous pouvez utiliser la méthode intégrée error :

sub handle_request {
    my $server = shift;
    ...
    return $server->error(500, "Quelque chose s'est mal passé");
}

Cela sera renvoyé au client avec un code de réponse de 500 et une chaîne d'erreur de "Quelque chose s'est mal passé". Les erreurs sont automatiquement sérialisées en erreurs SOAP si la requête entrante est encapsulée dans une enveloppe SOAP.
