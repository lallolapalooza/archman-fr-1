NOM

XmResolveAllPartOffsets — Une fonction qui permet l'écriture d'applications et de widgets compatibles ascendants

SYNTAXE

#include <Xm/Xm.h>
void XmResolveAllPartOffsets(
WidgetClass widget_class,
XmOffsetPtr * offset,
XmOffsetPtr * constraint_offset);

DESCRIPTION

Note :

Cette routine est obsolète et existe pour assurer la compatibilité avec les versions antérieures. Vous devriez appeler XmeResolvePartOffsets à la place.

L'utilisation d'enregistrements d'offsets nécessite deux variables globales supplémentaires par classe de widget. Les variables consistent en des pointeurs vers des tableaux d'offsets dans l'enregistrement de widget et l'enregistrement de contrainte pour chaque partie de la structure du widget. La fonction XmResolveAllPartOffsets alloue les enregistrements d'offsets nécessaires à une application pour garantir un accès compatible ascendant aux enregistrements d'instances de widgets et de contraintes par les applications et les widgets. Ces enregistrements d'offsets sont utilisés par le widget pour accéder à toutes les variables du widget. Un widget doit suivre les étapes décrites dans les paragraphes suivants.

Au lieu de créer une liste de ressources, le widget crée une liste de ressources d'offsets. Pour ce faire, utilisez la structure XmPartResource et la macro XmPartOffset. La structure de données XmPartResource ressemble à une liste de ressources, mais au lieu d'avoir un entier pour son offset, elle a deux shorts. Cette structure est placée dans l'enregistrement de classe comme s'il s'agissait d'une liste de ressources normale. Au lieu d'utiliser XtOffset pour l'offset, le widget utilise XmPartOffset.

Si le widget est une sous-classe de la classe Constraint et qu'il définit des ressources de contrainte supplémentaires, créez également une liste de ressources d'offsets pour la partie contrainte. Au lieu d'utiliser XtOffset pour l'offset, le widget utilise XmConstraintPartOffset dans la liste de ressources de contrainte.

XmPartResource resources[] = {
        {       BarNxyz, BarCXyz, XmRBoolean, sizeof(Boolean),
                XmPartOffset(Bar,xyz), XmRImmediate, (XtPointer)False } };
XmPartResource constraints[] = {
        {       BarNmaxWidth, BarNMaxWidth,
          XmRDimension, sizeof(Dimension),
          XmConstraintPartOffset(Bar,max_width),
          XmRImmediate, (XtPointer)100 } };

Au lieu de placer la taille du widget dans l'enregistrement de classe, le widget place la taille de la partie widget dans le même champ. Si le widget est une sous-classe de la classe Constraint, au lieu de placer la taille de l'enregistrement de contrainte du widget dans l'enregistrement de classe, le widget place la taille de la partie contrainte du widget dans le même champ.

Au lieu de placer XtVersion dans l'enregistrement de classe, le widget place XtVersionDontCheck dans l'enregistrement de classe.

Définissez une variable, de type XmOffsetPtr, pour pointer vers l'enregistrement d'offsets. Si le widget est une sous-classe de la classe Constraint, définissez une variable de type XmOffsetPtr pour pointer vers l'enregistrement d'offsets de contrainte. Ceux-ci peuvent faire partie de l'enregistrement de classe du widget ou être des variables globales séparées.

Lors de l'initialisation de classe, le widget appelle XmResolveAllPartOffsets, en lui passant des pointeurs vers l'enregistrement de classe, l'adresse de l'enregistrement d'offsets, et l'adresse de l'enregistrement d'offsets de contrainte. Si le widget n'est pas une sous-classe de la classe Constraint, il doit passer NULL comme adresse de l'enregistrement d'offsets de contrainte. Ceci fait plusieurs choses :

•
Ajoute la taille du super-classe (qui, par définition, a déjà été initialisée) au champ de taille de partie
•
Si le widget est une sous-classe de la classe Constraint, ajoute la taille de la partie contrainte du super-classe au champ de taille de contrainte
•
Alloue un tableau basé sur le nombre de super-classes
•
Si le widget est une sous-classe de la classe constraint, alloue un tableau pour l'enregistrement d'offsets de contrainte
•
Remplit les offsets de toutes les parties de widget et de contrainte avec les valeurs appropriées, déterminées en examinant les champs de taille de tous les enregistrements de super-classes
•
Utilise le tableau d'offsets de partie pour modifier les entrées d'offsets dans la liste de ressources en offsets réels, en place

Le widget définit une constante qui sera l'index de sa structure de partie dans le tableau des offsets. La valeur doit être égale à 1 plus l'index du super-classe du widget. Les constantes définies pour tous les widgets Xm se trouvent dans XmP.h.

#define BarIndex (XmBulletinBIndex + 1)

Au lieu d'accéder directement aux champs, le widget doit toujours passer par la table d'offsets. Les macros XmField et XmConstraintField vous aident à accéder à ces champs. Parce que les macros XmPartOffset, XmConstraintPartOffset, XmField, et XmConstraintField concatènent des éléments, vous devez vous assurer qu'il n'y a pas d'espace après l'argument de partie. Par exemple, les macros suivantes ne fonctionnent pas en raison de l'espace après l'argument de partie (Label) :

XmField(w, offset, Label, text, char *)
XmPartOffset(Label, text).

Par conséquent, vous ne devez pas avoir d'espaces après l'argument de partie (Label), comme illustré ici :

XmField(w, offset, Label, text, char *)

Vous pouvez définir des macros pour chaque champ afin de simplifier cela. Supposons un champ entier xyz :

#define BarXyz(w) (*(int *)(((char *) w) + \
        offset[BarIndex] + XtOffset(BarPart,xyz)))

Pour le champ de contrainte max_width :

#define BarMaxWidth(w) \
        XmConstraintField(w,constraint_offsets,Bar,max_width,Dimension)

Les paramètres de XmResolveAllPartOffsets sont

widget_class
Spécifie le pointeur de classe du widget pour le widget créé
offset
Retourne l'enregistrement d'offsets
constraint_offset
Retourne l'enregistrement d'offsets de contrainte
