NOM

XML::Parser::Expat - Accès de bas niveau au parseur XML expat de James Clark

SYNOPIS

use XML::Parser::Expat;
$parser = XML::Parser::Expat->new;
$parser->setHandlers('Start' => \&sh,
                     'End'   => \&eh,
                     'Char'  => \&ch);
open(my $fh, '<', 'info.xml') or die "Impossible d'ouvrir";
$parser->parse($fh);
close($fh);
# $parser->parse('<foo id="me"> ici <em>nous</em> allons </foo>');
sub sh
{
  my ($p, $el, %atts) = @_;
  $p->setHandlers('Char' => \&spec)
    if ($el eq 'special');
  ...
}
sub eh
{
  my ($p, $el) = @_;
  $p->setHandlers('Char' => \&ch)  # Les éléments spéciaux ne contiendront pas
    if ($el eq 'special');         # d'autres éléments spéciaux
  ...
}

DESCRIPTION

Ce module fournit une interface au parseur XML de James Clark, expat. Comme avec expat, une seule instance du parseur ne peut analyser qu'un seul document. Les appels à parsestring après le premier pour une instance donnée échoueront.

Expat (et XML::Parser::Expat) sont basés sur les événements. Lorsque le parseur reconnaît des parties du document (par exemple, le début ou la fin d'un élément XML), les gestionnaires enregistrés pour ce type d'événement sont appelés avec les paramètres appropriés.

MÉTHODES

new
C'est une méthode de classe, le constructeur pour XML::Parser::Expat. Les options sont passées sous forme de paires clé-valeur. Les options reconnues sont :
  • ProtocolEncoding

    Le nom de l'encodage du protocole. La valeur par défaut est aucune. Les encodages intégrés d'expat sont : "UTF-8", "ISO-8859-1", "UTF-16", et "US-ASCII". D'autres encodages peuvent être utilisés s'ils disposent de cartes d'encodage dans l'un des répertoires de la liste @Encoding_Path. La définition de l'encodage du protocole remplace tout encodage dans la déclaration XML.

  • Namespaces

    Lorsque cette option est donnée avec une valeur vraie, le parseur effectue le traitement des espaces de noms. Par défaut, le traitement des espaces de noms est désactivé. Lorsqu'il est activé, le parseur consomme les attributs xmlns et supprime les préfixes des noms d'éléments et d'attributs dont les préfixes ont un espace de noms défini. L'espace de noms d'un nom peut être trouvé en utilisant la méthode "namespace" et deux noms peuvent être comparés pour une égalité absolue avec la méthode "eq_name".

  • NoExpand

    Normalement, le parseur essaie d'étendre les références aux entités définies dans le sous-ensemble interne. Si cette option est définie à une valeur vraie, et qu'un gestionnaire par défaut est également défini, alors le gestionnaire par défaut sera appelé lorsqu'une référence d'entité est vue dans le texte. Cela n'a aucun effet si aucun gestionnaire par défaut n'a été enregistré, et cela n'a aucun effet sur l'expansion des références d'entités dans les valeurs d'attributs.

  • Stream_Delimiter

    Cette option prend une valeur de chaîne. Lorsque cette chaîne est trouvée seule sur une ligne lors de l'analyse d'un flux, l'analyse s'arrête comme si elle avait vu une fin de fichier. L'utilisation prévue est avec un flux de documents xml au format MIME multipart. La chaîne ne doit pas contenir de nouvelle ligne finale.

  • ErrorContext

    Lorsque cette option est définie, les erreurs sont signalées dans leur contexte. La valeur de ErrorContext doit être le nombre de lignes à afficher de chaque côté de la ligne dans laquelle l'erreur s'est produite.

  • ParseParamEnt

    À moins que standalone ne soit défini sur "yes" dans la déclaration XML, la définition de cette option à une valeur vraie permet de lire la DTD externe, et d'analyser et d'étendre les entités paramétriques.

  • Base

    La base à utiliser pour les noms de fichiers ou les URL relatifs. Cela peut également être fait en utilisant la méthode base.

setHandlers(TYPE, GESTIONNAIRE [, TYPE, GESTIONNAIRE [...]])
Cette méthode enregistre les gestionnaires pour les différents événements. Si aucun gestionnaire n'est enregistré, alors un appel à parsestring ou parsefile déterminera uniquement si le document XML correspondant est bien formé (en retournant sans erreur). Ceci peut être appelé depuis un gestionnaire, après le début de l'analyse.

Définir un gestionnaire à quelque chose qui s'évalue à faux le désenregistre.

Cette méthode renvoie une liste de paires type, gestionnaire correspondant à l'entrée. Les gestionnaires renvoyés sont ceux qui étaient en vigueur avant l'appel à setHandlers.

Les événements reconnus et les paramètres passés aux gestionnaires correspondants sont :

  • Start (Parseur, Élément [, Att, Val [,...]])

    Cet événement est généré lorsqu'une balise de début XML est reconnue. Parseur est une instance de XML::Parser::Expat. Élément est le nom de l'élément XML qui est ouvert avec la balise de début. Les paires Att & Val sont générées pour chaque attribut dans la balise de début.

  • End (Parseur, Élément)

    Cet événement est généré lorsqu'une balise de fin XML est reconnue. Notez qu'une balise vide XML (<foo/>) génère à la fois un événement de début et de fin.

    Il y a toujours un gestionnaire de début et de fin de bas niveau installé qui enveloppe les callbacks correspondants. Ceci est pour gérer le mécanisme de contexte. Une conséquence de ceci est que le gestionnaire par défaut (voir ci-dessous) ne verra pas de balise de début ou de fin, sauf si la méthode default_current est appelée.

  • Char (Parseur, Chaîne)

    Cet événement est généré lorsque du contenu non-markup est reconnu. La séquence de caractères non-markup se trouve dans Chaîne. Une seule séquence de caractères non-markup peut générer plusieurs appels à ce gestionnaire. Quel que soit l'encodage de la chaîne dans le document d'origine, elle est fournie au gestionnaire en UTF-8.

  • Proc (Parseur, Cible, Données)

    Cet événement est généré lorsqu'une instruction de traitement est reconnue.

  • Comment (Parseur, Chaîne)

    Cet événement est généré lorsqu'un commentaire est reconnu.

  • CdataStart (Parseur)

    Ceci est appelé au début d'une section CDATA.

  • CdataEnd (Parseur)

    Ceci est appelé à la fin d'une section CDATA.

  • Default (Parseur, Chaîne)

    Ceci est appelé pour tous les caractères qui n'ont pas de gestionnaire enregistré. Cela inclut à la fois les caractères qui font partie de la structure (déclarations de balisage) pour lesquelles aucun événement n'est généré, et les caractères qui pourraient générer des événements, mais pour lesquels aucun gestionnaire n'a été enregistré.

    Quel que soit l'encodage dans le document d'origine, la chaîne est renvoyée au gestionnaire en UTF-8.

  • Unparsed (Parseur, Entité, Base, Sysid, Pubid, Notation)

    Ceci est appelé pour une déclaration d'une entité non analysée. Entité est le nom de l'entité. Base est la base à utiliser pour résoudre une URI relative. Sysid est l'identifiant système. Pubid est l'identifiant public. Notation est le nom de la notation. Base et Pubid peuvent être non définis.

  • Notation (Parseur, Notation, Base, Sysid, Pubid)

    Ceci est appelé pour une déclaration de notation. Notation est le nom de la notation. Base est la base à utiliser pour résoudre une URI relative. Sysid est l'identifiant système. Pubid est l'identifiant public. Base, Sysid et Pubid peuvent tous être non définis.

  • ExternEnt (Parseur, Base, Sysid, Pubid)

    Ceci est appelé lorsqu'une entité externe est référencée. Base est la base à utiliser pour résoudre une URI relative. Sysid est l'identifiant système. Pubid est l'identifiant public. Base et Pubid peuvent être non définis.

    Ce gestionnaire doit soit retourner une chaîne, qui représente le contenu de l'entité externe, soit retourner une poignée de fichier ouverte qui peut être lue pour obtenir le contenu de l'entité externe, soit retourner undef, ce qui indique que l'entité externe n'a pas pu être trouvée et générera une erreur d'analyse.

    Si une poignée de fichier ouverte est retournée, elle doit être retournée soit sous forme de glob (*FOO) soit sous forme de référence vers un glob (par exemple, une instance de IO::Handle).

  • ExternEntFin (Parseur)

    Ceci est appelé après qu'une entité externe a été analysée. Il permet aux applications d'effectuer un nettoyage sur les actions effectuées dans le gestionnaire ExternEnt ci-dessus.

  • Entity (Parseur, Nom, Val, Sysid, Pubid, Ndata, IsParam)

    Ceci est appelé lorsqu'une entité est déclarée. Pour les entités internes, le paramètre Val contiendra t

  • Ent (Parser, Name, Value, systemId, publicId, Ndata, IsParam)

    Cette gestion est appelée pour les entités non analysées. Le paramètre Name est le nom de l'entité. Si l'entité est interne, le paramètre Value contiendra la valeur de l'entité, et les trois autres paramètres seront indéfinis. Pour les entités externes, le paramètre Val sera indéfini, le paramètre Sysid contiendra l'identifiant du système, le paramètre Pubid contiendra l'identifiant public s'il a été fourni (il sera indéfini sinon), le paramètre Ndata contiendra la notation pour les entités non analysées. S'il s'agit d'une déclaration d'entité paramètre, alors le paramètre IsParam sera vrai.

    Notez que cette gestion et la gestion Unparsed ci-dessus se chevauchent. Si les deux sont définies, alors cette gestion ne sera pas appelée pour les entités non analysées.

  • Element (Parser, Name, Model)

    La gestion d'élément est appelée lorsqu'une déclaration d'élément est trouvée. Name est le nom de l'élément, et Model est le modèle de contenu sous forme d'objet XML::Parser::ContentModel. Voir "XML::Parser::ContentModel Methods" pour les méthodes disponibles pour cette classe.

  • Attlist (Parser, Elname, Attname, Type, Default, Fixed)

    Cette gestion est appelée pour chaque attribut dans une déclaration ATTLIST. Ainsi, une déclaration ATTLIST comportant plusieurs attributs générera plusieurs appels à cette gestion. Le paramètre Elname est le nom de l'élément auquel l'attribut est associé. Le paramètre Attname est le nom de l'attribut. Type est le type d'attribut, donné sous forme de chaîne de caractères. Default est la valeur par défaut, qui sera soit "#REQUIRED", soit "#IMPLIED", soit une chaîne entre guillemets (c'est-à-dire que la chaîne renvoyée commencera et se terminera par un caractère guillemet). Si Fixed est vrai, alors il s'agit d'un attribut fixe.

  • Doctype (Parser, Name, Sysid, Pubid, Internal)

    Cette gestion est appelée pour les déclarations DOCTYPE. Name est le nom du type de document. Sysid est l'identifiant du système du type de document, s'il a été fourni, sinon il est indéfini. Pubid est l'identifiant public du type de document, qui sera indéfini s'il n'y a pas d'identifiant public. Internal sera vrai ou faux, indiquant si la déclaration doctype contient ou non un sous-ensemble interne.

  • DoctypeFin (Parser)

    Cette gestion est appelée après la fin de l'analyse de la déclaration DOCTYPE, y compris les déclarations DTD internes ou externes.

  • XMLDecl (Parser, Version, Encoding, Standalone)

    Cette gestion est appelée pour les déclarations XML. Version est une chaîne de caractères contenant la version. Encoding est soit indéfini, soit contient une chaîne d'encodage. Standalone est soit indéfini, soit vrai ou faux. Indéfini indique qu'aucun paramètre standalone n'a été donné dans la déclaration XML. Vrai ou faux indique respectivement "oui" ou "non".

namespace(name)
Retourne l'URI de l'espace de noms auquel le nom appartient. Si le nom n'appartient à aucun espace de noms, undef est retourné. Ceci n'est valide que pour les noms reçus via les gestions Start ou End d'un seul document, ou via un appel à la méthode generate_ns_name. En d'autres termes, n'utilisez pas les noms générés à partir d'une instance de XML::Parser::Expat avec d'autres instances.
eq_name(name1, name2)
Retourne vrai si name1 et name2 sont identiques (c'est-à-dire même nom et provenant du même espace de noms). Ceci n'est pertinent que si les deux noms ont été obtenus via les gestions Start ou End d'un seul document, ou via un appel à la méthode generate_ns_name.
generate_ns_name(name, namespace)
Retourne un nom, associé à un espace de noms donné, utilisable avec les 2 méthodes ci-dessus. L'argument namespace doit être l'URI de l'espace de noms, pas un préfixe.
new_ns_prefixes
Lorsqu'elle est appelée depuis une gestion de balise de début, renvoie les préfixes d'espace de noms déclarés avec cette balise de début. Si elle est appelée ailleurs (ou s'il n'y avait pas de préfixes d'espace de noms déclarés), elle renvoie une liste vide. La définition de l'espace de noms par défaut est indiquée par '#default' comme préfixe.
expand_ns_prefix(prefix)
Retourne l'URI auquel le préfixe donné est actuellement lié. Retourne undef si le préfixe n'est pas actuellement lié. Utilisez '#default' pour trouver la liaison actuelle de l'espace de noms par défaut (le cas échéant).
current_ns_prefixes
Retourne une liste des préfixes d'espaces de noms actuellement liés. L'ordre des préfixes dans la liste n'a aucune signification. Si l'espace de noms par défaut est actuellement lié, '#default' apparaît dans la liste.
recognized_string
Retourne la chaîne du document qui a été reconnue pour appeler la gestion actuelle. Par exemple, lorsqu'elle est appelée depuis une gestion de début, elle nous donnera la chaîne de la balise de début. La chaîne est encodée en UTF-8. Cette méthode ne renvoie pas une chaîne significative dans les gestions de déclaration.
original_string
Retourne la chaîne verbatim du document qui a été reconnue pour appeler la gestion actuelle. La chaîne est dans l'encodage d'origine du document. Cette méthode ne renvoie pas une chaîne significative dans les gestions de déclaration.
default_current
Lorsqu'elle est appelée depuis une gestion, provoque l'envoi de la séquence de caractères qui a généré l'événement correspondant à la gestion par défaut (si une est enregistrée). L'utilisation de cette méthode est dépréciée au profit de la méthode recognized_string, que vous pouvez utiliser sans installer de gestion par défaut. Cette méthode ne transmet pas de chaîne significative à la gestion par défaut lorsqu'elle est appelée depuis des gestions de déclaration.
xpcroak(message)
Concatène le numéro de ligne actuel dans le document XML plus le message implicite par ErrorContext au message donné. Puis croak avec le message formé.
xpcarp(message)
Concatène le numéro de ligne actuel dans le document XML plus le message implicite par ErrorContext au message donné. Puis carp avec le message formé.
current_line
Retourne le numéro de ligne de la position actuelle de l'analyse.
current_column
Retourne le numéro de colonne de la position actuelle de l'analyse.
current_byte
Retourne la position actuelle de l'analyse.
base([NEWBASE]);
Retourne la valeur actuelle de la base pour la résolution des URI relatifs. Si NEWBASE est fourni, change la base à cette valeur.
context
Retourne une liste de noms d'éléments qui représentent des éléments ouverts, le dernier étant le plus interne. Dans les gestions de balises de début et de fin, ce sera la balise de l'élément parent.
current_element
Retourne le nom de l'élément actuellement ouvert le plus interne. Dans les gestions de début ou de fin, retourne le parent de l'élément associé à ces balises.
in_element(NAME)
Retourne vrai si NAME est égal au nom de l'élément actuellement ouvert le plus interne. Si le traitement des espaces de noms est utilisé et que vous voulez vérifier par rapport à un nom qui peut être dans un espace de noms, alors utilisez la méthode generate_ns_name pour créer l'argument NAME.
within_element(NAME)
Retourne le nombre de fois où le nom donné apparaît dans la liste de contexte. Si le traitement des espaces de noms est utilisé et que vous voulez vérifier par rapport à un nom qui peut être dans un espace de noms, alors utilisez la méthode generate_ns_name pour créer l'argument NAME.
depth
Retourne la taille de la liste de contexte.
element_index
Retourne un entier qui représente l'ordre de visite en profondeur de l'élément actuel. Ce sera zéro en dehors de l'élément racine. Par exemple, cela retournera 1 lorsqu'il est appelé depuis la gestion de la balise de début de l'élément racine.
skip_until(INDEX)
INDEX est un entier qui représente un index d'élément. Lorsque cette méthode est appelée, toutes les gestions sont suspendues jusqu'à ce que la balise de début d'un élément dont l'index est égal à INDEX soit vue. Si une gestion de début a été définie, alors c'est la première balise que la gestion de début verra après l'appel à skip_until.
position_in_context(LINES)
Retourne une chaîne qui montre la position d'analyse actuelle. LINES doit être un entier >= 0 qui représente le nombre de lignes de chaque côté de la ligne d'analyse actuelle à inclure dans la chaîne retournée.
xml_escape(TEXT [, CHAR [, CHAR ...]])
Retourne TEXT avec les caractères de balisage transformés en entités de caractères. Tous les caractères supplémentaires fournis comme arguments sont également transformés en références de caractères lorsqu'ils sont trouvés dans TEXT.
parse (SOURCE)
Le paramètre SOURCE doit soit être une chaîne contenant l'intégralité du document XML, soit un objet IO::Handle ouvert. Un seul document peut être analysé pour une instance donnée de XML::Parser::Expat, donc cela croakera s'il a déjà été appelé pour cette instance.
parsestring(XML_DOC_STRING)
Analyse la chaîne donnée comme un document XML. Un seul document peut être analysé pour une instance donnée de XML::Parser::Expat, donc cela mourra si parsestring ou parsefile a déjà été appelé pour cette instance.

Cette méthode est dépréciée au profit de la méthode parse.

parsefile(FILENAME)
Analyse le document XML contenu dans le fichier donné. Mourra si parsestring ou parsefile a déjà été appelé pour cette instance.
is_defaulted(ATTNAME)
NE FONCTIONNE PLUS. Pour savoir si un attribut est par défaut, utilisez la méthode specified_attr.
XML::Parser::Expat(3pm) — Arch manual pages

NAME

XML::Parser::Expat - Perl interface to the Expat XML parser

SYNOPSIS

    use XML::Parser;
    my $parser = new XML::Parser (
        AcceptProlog => 1,
        NoExpand     => 1,
        ErrorContext => 1,
        SGMLDecl     => 1,
        )
        or die "could not create parser: $!;";

    # Call with a file
    $parser->parsefile( "somefile.xml" );

    # Call with a string
    $parser->parsestring( "<root>Hello</root>" );

    # Call with filehandle
    open my $fh, '<', "somefile.xml";
    $parser->parsefilehandle($fh);
    close $fh;

DESCRIPTION

This module provides a Perl interface to the Expat XML parser by James Clark. It is intended to be a fairly low-level interface, providing direct access to the Expat callbacks.

The primary methods are:

new
Creates a new parser object.
parsefile
Parses the named file.
parsestring
Parses the given string.
parsefilehandle
Parses from a filehandle.

It also supports a number of optional arguments to the constructor and a number of accessor methods.

METHODS

The following methods are available on parser objects:

ErrorString
Returns a string representation of the last error encountered.
ByteOffset
Returns the byte offset in the document where the last error occurred.
LineNumber
Returns the line number where the last error occurred.
ColumnNumber
Returns the column number where the last error occurred.
SetCurrentParser
Sets the parser object as the current parser. This is done implicitly when a parser is created, but can be done explicitly if needed.
specified_attr
When the start handler receives lists of attributes and values, the non-defaulted (i.e. explicitly specified) attributes occur in the list first. This method returns the number of specified items in the list. So if this number is equal to the length of the list, there were no defaulted values. Otherwise the number points to the index of the first defaulted attribute name.
finish
Unsets all handlers (including internal ones that set context), but expat continues parsing to the end of the document or until it finds an error. It should finish up a lot faster than with the handlers set.
release
There are data structures used by XML::Parser::Expat that have circular references. This means that these structures will never be garbage collected unless these references are explicitly broken. Calling this method breaks those references (and makes the instance unusable.)

Normally, higher level calls handle this for you, but if you are using XML::Parser::Expat directly, then it's your responsibility to call it.

XML::Parser::ContentModel Methods

The element declaration handlers are passed objects of this class as the content model of the element declaration. They also represent content particles, components of a content model.

When referred to as a string, these objects are automagically converted to a string representation of the model (or content particle).

isempty
This method returns true if the object is "EMPTY", false otherwise.
isany
This method returns true if the object is "ANY", false otherwise.
ismixed
This method returns true if the object is "(#PCDATA)" or "(#PCDATA|...)*", false otherwise.
isname
This method returns if the object is an element name.
ischoice
This method returns true if the object is a choice of content particles.
isseq
This method returns true if the object is a sequence of content particles.
quant
This method returns undef or a string representing the quantifier ('?', '*', '+') associated with the model or particle.
children
This method returns undef or (for mixed, choice, and sequence types) an array of component content particles. There will always be at least one component for choices and sequences, but for a mixed content model of pure PCDATA, "(#PCDATA)", then an undef is returned.

XML::Parser::ExpatNB Methods

The class XML::Parser::ExpatNB is a subclass of XML::Parser::Expat used for non-blocking access to the expat library. It does not support the parse, parsestring, or parsefile methods, but it does have these additional methods:

parse_more(DATA)
Feed expat more text to munch on.
parse_done
Tell expat that it's gotten the whole document.

FUNCTIONS

XML::Parser::Expat::load_encoding(ENCODING)
Load an external encoding. ENCODING is either the name of an encoding or the name of a file. The basename is converted to lowercase and a '.enc' extension is appended unless there's one already there. Then, unless it's an absolute pathname (i.e. begins with '/'), the first file by that name discovered in the @Encoding_Path path list is used.

The encoding in the file is loaded and kept in the %Encoding_Table table. Earlier encodings of the same name are replaced.

This function is automatically called by expat when it encounters an encoding it doesn't know about. Expat shouldn't call this twice for the same encoding name. The only reason users should use this function is to explicitly load an encoding not contained in the @Encoding_Path list.
