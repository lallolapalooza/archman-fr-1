NOM

XML::Writer - Extension Perl pour l'écriture de documents XML.

SYNOPSIS

use XML::Writer;
use IO::File;
my $output = IO::File->new(">output.xml");
my $writer = XML::Writer->new(OUTPUT => $output);
$writer->startTag("greeting",
                  "class" => "simple");
$writer->characters("Bonjour tout le monde !");
$writer->endTag("greeting");
$writer->end();
$output->close();

DESCRIPTION

XML::Writer est un module d'aide pour les programmes Perl qui écrivent un document XML. Le module gère tous les échappements pour les valeurs d'attributs et les données de caractères, et construit différents types de balisage, tels que des balises, des commentaires et des instructions de traitement.

Par défaut, le module effectue plusieurs vérifications de conformité pour détecter les erreurs pendant la sortie. Ce comportement peut être extrêmement utile pendant le développement et le débogage, mais il peut être désactivé pour le code de production.

Le module peut fonctionner soit en mode normal, soit en mode de traitement d'espaces de noms. En mode espaces de noms, le module générera lui-même les déclarations d'espaces de noms et effectuera des vérifications supplémentaires sur la sortie.

Un support supplémentaire est disponible pour un mode de données simplifié sans contenu mixte : les nouvelles lignes sont automatiquement insérées autour des éléments et les éléments peuvent éventuellement être indentés en fonction de leur niveau d'imbrication.

MÉTHODES

Écriture XML

new([$params])
Crée un nouvel objet XML::Writer : 
my $writer = XML::Writer->new(OUTPUT => $output, NEWLINES => 1);

Les arguments sont un tableau associatif anonyme de paramètres :

OUTPUT
Un objet béni dans IO::Handle ou l'une de ses sous-classes (comme IO::File), ou une référence à une chaîne de caractères, ou tout objet béni qui a une méthode print() ; si ce paramètre n'est pas présent, le module écrira sur la sortie standard. Si une référence de chaîne est passée, elle capturera le XML généré (sous forme de chaîne ; pour obtenir des octets, utilisez le module "Encode").

Si la chaîne de caractères self est passée, la sortie sera capturée en interne par l'objet, et pourra être accédée via la méthode to_string(), ou en appelant l'objet dans un contexte de chaîne.

my $writer = XML::Writer->new( OUTPUT => 'self' );
$writer->dataElement( hello => 'world' );
print $writer->to_string;  # affiche <hello>world</hello>
print "$writer";           # idem
NAMESPACES
Une valeur vraie (1) ou fausse (0, undef) ; si ce paramètre est présent et sa valeur est vraie, alors le module acceptera une référence de tableau à deux membres à la place des noms d'éléments et d'attributs, comme dans l'exemple suivant : 
my $rdfns = "http://www.w3.org/1999/02/22-rdf-syntax-ns#";
my $writer = XML::Writer->new(NAMESPACES => 1);
$writer->startTag([$rdfns, "Description"]);

Le premier membre du tableau est un URI d'espace de noms, et la seconde partie est la partie locale d'un nom qualifié. Le module générera automatiquement les déclarations d'espaces de noms appropriées et remplacera la partie URI par un préfixe.

PREFIX_MAP
Une référence de hachage ; si ce paramètre est présent et que le module traite les espaces de noms (voir le paramètre NAMESPACES), alors le module utilisera ce hachage pour rechercher les préfixes préférés pour les URI d'espaces de noms : 
my $rdfns = "http://www.w3.org/1999/02/22-rdf-syntax-ns#";
my $writer = XML::Writer->new(NAMESPACES => 1,
                             PREFIX_MAP => {$rdfns => 'rdf'});

Les clés de la table de hachage sont les URI d'espaces de noms, et les valeurs sont les préfixes associés. S'il n'y a pas de préfixe préféré pour l'URI de l'espace de noms dans ce hachage, alors le module générera automatiquement des préfixes de la forme "__NS1", "__NS2", etc.

Pour définir l'espace de noms par défaut, utilisez '' pour le préfixe.

FORCED_NS_DECLS
Une référence de tableau ; si ce paramètre est présent, l'élément racine du document contiendra des déclarations pour tous les URI d'espaces de noms donnés. Déclarer les espaces de noms à l'avance est particulièrement utile lorsqu'un grand nombre d'éléments d'un espace de noms sont frères, mais ne partagent pas d'ancêtre direct du même espace de noms.
NEWLINES
Une valeur vraie ou fausse ; si ce paramètre est présent et sa valeur est vraie, alors le module insérera un retour à la ligne supplémentaire avant le délimiteur de fermeture des balises de début, de fin et vides pour garantir que le document ne se retrouve pas sur une seule longue ligne. Si le paramètre n'est pas présent, le module n'insérera pas de retours à la ligne.
UNSAFE
Une valeur vraie ou fausse ; si ce paramètre est présent et sa valeur est vraie, alors le module ignorera la plupart des vérifications d'erreurs de conformité. Si le paramètre n'est pas présent, le module effectuera les vérifications d'erreurs de conformité par défaut. Désactivez la vérification des erreurs à vos risques et périls !
DATA_MODE
Une valeur vraie ou fausse ; si ce paramètre est présent et sa valeur est vraie, alors le module entrera dans un mode de données spécial, insérant automatiquement des retours à la ligne autour des éléments et (sauf si UNSAFE est également spécifié) signalant une erreur si un élément contient à la fois des caractères et des éléments comme contenu.
DATA_INDENT
Une valeur numérique ou un espace blanc ; si ce paramètre est présent, il représente le pas d'indentation pour les éléments en mode données (il sera ignoré lorsqu'on n'est pas en mode données). S'il s'agit d'un espace blanc, il sera répété pour chaque niveau d'indentation.
ENCODING
Un encodage de caractères à utiliser pour la sortie ; actuellement, il doit s'agir de 'utf-8' ou 'us-ascii'. S'il est présent, il sera utilisé pour l'encodage de caractères sous-jacent et comme valeur par défaut dans la déclaration XML. Toutes les données de caractères doivent être fournies sous forme de chaînes Unicode lorsqu'un encodage est défini.
CHECK_PRINT
Une valeur vraie ou fausse ; si ce paramètre est présent et sa valeur est vraie, tous les appels à print sur la sortie sous-jacente seront vérifiés pour leur succès. Les échecs provoqueront un croak plutôt que d'être ignorés.
end()
Termine la création d'un document XML. Cette méthode vérifiera que le document a exactement un élément racine et que toutes les balises de début sont fermées : 
$writer->end();

Si OUTPUT a été défini sur self, end() retournera également le document généré.

xmlDecl([$encoding, $standalone])
Ajoute une déclaration XML au début d'un document XML. La version sera toujours "1.0". Si vous fournissez un argument d'encodage ou autonome non nul, sa valeur apparaîtra dans la déclaration (toute valeur non nulle pour autonome, sauf 'no', sera automatiquement convertie en 'yes'). Si non spécifié ici, l'encodage sera pris à partir de l'argument ENCODING. Passez une chaîne vide pour supprimer ce comportement. 
$writer->xmlDecl("UTF-8");
doctype($name, [$publicId, $systemId])
Ajoute une déclaration DOCTYPE à un document XML. La déclaration doit apparaître avant le début de l'élément racine. Si vous fournissez un publicId, vous devez également fournir un systemId, mais vous pouvez fournir uniquement un systemId en passant 'undef' pour le publicId. 
$writer->doctype("html");
comment($text)
Ajoute un commentaire à un document XML. Si le commentaire apparaît en dehors de l'élément racine (soit avant la première balise de début, soit après la dernière balise de fin), le module ajoutera un retour chariot après pour améliorer la lisibilité. En mode données, les commentaires seront traités comme des balises vides :

NAME

XML::Writer - Simple interface for writing XML documents

SYNOPSIS

  use XML::Writer;

  my $output = '';
  my $writer = XML::Writer->new(OUTPUT => \$output);

  $writer->startTag('doc');
  $writer->tag('title', 'A simple example');
  $writer->emptyTag('br');
  $writer->dataElement('para', 'This is a paragraph.');
  $writer->startTag('list', 'type' => 'ordered');
  $writer->dataElement('item', 'First item');
  $writer->dataElement('item', 'Second item');
  $writer->endTag('list');
  $writer->endTag('doc');
  $writer->end();

  print $output;

DESCRIPTION

This module provides a simple, object-oriented interface for creating well-formed XML documents. It handles the escaping of special characters and ensures that tags are properly nested.

The constructor for XML::Writer takes the following named parameters:

OUTPUT
Specifies where the XML output should be sent. This can be a filehandle (like STDOUT), a scalar reference (like \$string_ref) to append to a string, or the string 'self' to allow the object to be used as a string.
ENCODING
Specifies the character encoding of the output. Defaults to 'UTF-8'. The XML declaration will be written with this encoding. Note that the module doesn't actually perform any character encoding conversion; it simply writes the output string and inserts the correct XML declaration.
DATA_MODE
A boolean value. If true, the module enters data mode. In data mode, the module automatically indents character data, and line breaks are inserted between elements.
DATA_INDENT
The string used for indentation in data mode. Defaults to two spaces.
UNSAFE
A boolean value. If true, the module will allow the use of the raw() method, which bypasses all well-formedness checking.
PREFIX_MAP
A hash reference mapping namespace URIs to preferred prefixes. This is useful for controlling namespace prefixes. See also addPrefix().

Generating XML

The following methods are used to generate XML output:

startTag($name [, $aname1 => $value1, ...])
Add a start tag to an XML document. Any arguments after the element name are assumed to be name/value pairs for attributes: the module will escape all '&', '<', '>', and '"' characters in the attribute values using the predefined XML entities: 
$writer->startTag('doc', 'version' => '1.0',
                         'status' => 'draft',
                         'topic' => 'AT&T');

All start tags must eventually have matching end tags.

emptyTag($name [, $aname1 => $value1, ...])
Add an empty tag to an XML document. Any arguments after the element name are assumed to be name/value pairs for attributes (see startTag() for details): 
$writer->emptyTag('img', 'src' => 'portrait.jpg',
                         'alt' => 'Portrait of Emma.');
endTag([$name])
Add an end tag to an XML document. The end tag must match the closest open start tag, and there must be a matching and properly-nested end tag for every start tag: 
$writer->endTag('doc');

If the $name argument is omitted, then the module will automatically supply the name of the currently open element:

$writer->startTag('p');
$writer->endTag();
dataElement($name, $data [, $aname1 => $value1, ...])
Print an entire element containing only character data. This is equivalent to 
$writer->startTag($name [, $aname1 => $value1, ...]);
$writer->characters($data);
$writer->endTag($name);
characters($data)
Add character data to an XML document. All '<', '>', and '&' characters in the $data argument will automatically be escaped using the predefined XML entities: 
$writer->characters("Here is the formula: ");
$writer->characters("a < 100 && a > 5");

You may invoke this method only within the document element (i.e. after the first start tag and before the last end tag).

In data mode, you must not use this method to add whitespace between elements.

raw($data)
Print data completely unquoted and unchecked to the XML document. For example raw('<') will print a literal < character. This necessarily bypasses all well-formedness checking, and is therefore only available in unsafe mode.

This can sometimes be useful for printing entities which are defined for your XML format but the module doesn't know about, for example &nbsp; for XHTML.

cdata($data)
As characters() but writes the data quoted in a CDATA section, that is, between <![CDATA[ and ]]>. If the data to be written itself contains ]]>, it will be written as several consecutive CDATA sections.
cdataElement($name, $data [, $aname1 => $value1, ...])
As dataElement() but the element content is written as one or more CDATA sections (see cdata()).
pi($target [, $data])
Add a processing instruction to an XML document: 
$writer->pi('xml-stylesheet', 'href="style.css" type="text/css"');

If the processing instruction appears outside the document element (either before the first start tag or after the last end tag), the module will add a carriage return after it to improve readability.

The $target argument must be a single XML name. If you provide the $data argument, the module will insert its contents following the $target argument, separated by a single space.

comment($comment)
Add an XML comment to the document. The comment text must not contain a double-hyphen (--) or end with a hyphen (-). 
$writer->comment('This is a comment.');

If the comment appears outside the document element, a carriage return will be added after it.

doctype($name, $dtd [, $type])
Add a DOCTYPE declaration to the document. 
$writer->doctype('html',
                         '-//W3C//DTD XHTML 1.0 Strict//EN',
                         'http://www.w3.org/TR/xhtml1/DTD/xhtml1-strict.dtd');

The $type parameter is optional and defaults to 'SYSTEM'.

A DOCTYPE declaration must be added before any start tag.

startDocument([$version, $encoding])
Add the XML declaration (e.g., <?xml version="1.0" encoding="UTF-8"?>) to the document. This method is automatically called by the constructor if the ENCODING parameter is provided. You can use it to explicitly add or override the XML declaration.
end()
Call this method when you have finished writing the XML document. It ensures that all open tags are properly closed and performs final well-formedness checks.
setOutput($output)
Set the current output destination, as in the OUTPUT parameter for the constructor.
getOutput()
Return the current output destination, as in the OUTPUT parameter for the constructor.
setDataMode($mode)
Enable or disable data mode, as in the DATA_MODE parameter for the constructor.
getDataMode()
Return the current data mode, as in the DATA_MODE parameter for the constructor.
setDataIndent($step)
Set the indent step for data mode, as in the DATA_INDENT parameter for the constructor.
getDataIndent()
Return the indent step for data mode, as in the DATA_INDENT parameter for the constructor.

Querying XML

in_element($name)
Return a true value if the most recent open element matches $name: 
if ($writer->in_element('dl')) {
  $writer->startTag('dt');
} else {
  $writer->startTag('li');
}
within_element($name)
Return a true value if any open element matches $name: 
if ($writer->within_element('body')) {
  $writer->startTag('h1');
} else {
  $writer->startTag('title');
}
current_element()
Return the name of the currently open element: 
my $name = $writer->current_element();

This is the equivalent of

my $name = $writer->ancestor(0);
ancestor($n)
Return the name of the nth ancestor, where $n=0 for the current open element.

Additional Namespace Support

As of 0.510, these methods may be used while writing a document.

addPrefix($uri, $prefix)
Add a preferred mapping between a Namespace URI and a prefix. See also the PREFIX_MAP constructor parameter.

To set the default namespace, omit the $prefix parameter or set it to ''.

removePrefix($uri)
Remove a preferred mapping between a Namespace URI and a prefix.
forceNSDecl($uri)
Indicate that a namespace declaration for this URI should be included with the next element to be started.

ERROR REPORTING

With the default settings, the XML::Writer module can detect several basic XML well-formedness errors:

  • Lack of a (top-level) document element, or multiple document elements.
  • Unclosed start tags.
  • Misplaced delimiters in the contents of processing instructions or comments.
  • Misplaced or duplicate XML declaration(s).
  • Misplaced or duplicate DOCTYPE declaration(s).
  • Mismatch between the document type name in the DOCTYPE declaration and the name of the document element.
  • Mismatched start and end tags.
  • Attempts to insert character data outside the document element.
  • Duplicate attributes with the same name.

During Namespace processing, the module can detect the following additional errors:

  • Attempts to use PI targets or element or attribute names containing a colon.
  • Attempts to use attributes with names beginning "xmlns".

To ensure full error detection, a program must also invoke the end method when it has finished writing a document:

$writer->startTag('greeting');
$writer->characters("Hello, world!");
$writer->endTag('greeting');
$writer->end();

This error reporting can catch many hidden bugs in Perl programs that create XML documents; however, if necessary, it can be turned off by providing an UNSAFE parameter:

my $writer = XML::Writer->new(OUTPUT => $output, UNSAFE => 1);

PRINTING OUTPUT

If OUTPUT has been set to self and the object has been called in a string context, it'll return the xml document.

to_string
If OUTPUT has been set to self, calls an implicit end() on the document and prints it. Dies if OUTPUT has been set to anything else.
