XML::XPath::XMLParser(3) Documentation Perl fournie par l'utilisateur XML::XPath::XMLParser(3)

NOM

XML::XPath::XMLParser - La classe d'analyse XML par défaut qui produit un arbre de nœuds

SYNOPSIS

my $parser = XML::XPath::XMLParser->new(
            filename => $self->get_filename,
            xml => $self->get_xml,
            ioref => $self->get_ioref,
            parser => $self->get_parser,
        );
my $root_node = $parser->parse;

DESCRIPTION

Ce module génère un arbre de nœuds destiné à être utilisé comme nœud de contexte pour le traitement XPath. Il vise à être un analyseur rapide, rien de fantaisiste, et pourtant il doit stocker plus d'informations que la plupart des analyseurs. Pour ce faire, j'ai utilisé des références de tableaux partout - pas de hachages. Je n'ai aucun chiffre de performance pour les gains de vitesse obtenus, je ne m'excuse donc pas auprès de ceux qui ne sont pas habitués à utiliser des tableaux au lieu de hachages. Je pense qu'ils ont du sens ici où nous connaissons les attributs de chaque type de nœud.

STRUCTURE_DU_NŒUD

Tous les nœuds ont les 2 premières entrées dans le tableau : node_parent et node_pos. Le type du nœud est déterminé à l'aide de la fonction ref(). Le node_parent contient toujours une entrée pour le parent du nœud actuel - à l'exception du nœud racine qui a undef comme valeur. Et node_pos est la position de ce nœud dans le tableau auquel il appartient (pensez : $node == $node->[node_parent]->[node_children]->[$node->[node_pos]])

Les nœuds sont structurés comme suit :

NŒUD_RACINE

Le nœud racine est juste un nœud d'élément sans parent.

[
  undef, # node_parent - vérifier undef pour identifier le nœud racine
  undef, # node_pos
  undef, # node_prefix
  [ ... ], # node_children (voir ci-dessous)
]

NŒUD_ÉLÉMENT

[
  $parent, # node_parent
  <position dans le tableau actuel>, # node_pos
  'xxx', # node_prefix - préfixe de namespace sur cet élément
  [ ... ], # node_children
  'yyy', # node_name - nom de la balise de l'élément
  [ ... ], # node_attribs - attributs sur cet élément
  [ ... ], # node_namespaces - namespaces actuellement en portée
]

NŒUD_ATTRIBUT

[
  $parent, # node_parent - le nœud élément
  <position dans le tableau actuel>, # node_pos
  'xxx', # node_prefix - préfixe de namespace sur cet élément
  'href', # node_key - nom de l'attribut
  'ftp://ftp.com/', # node_value - valeur dans le nœud
]

NŒUDS_NAMESPACE

Chaque élément a un ensemble associé de nœuds de namespace qui sont actuellement en portée. Chaque nœud de namespace stocke un préfixe et le nom développé (récupéré de l'attribut xmlns:prefix="...").

[
  $parent,
  <pos>,
  'a', # node_prefix - le namespace tel qu'il était écrit comme préfixe
  'http://my.namespace.com', # node_expanded - le nom développé.
]

NŒUDS_TEXTE

[
  $parent,
  <pos>,
  'Ceci est du texte' # node_text - le texte dans le nœud
]

NŒUDS_COMMENTAIRE

[
  $parent,
  <pos>,
  'Ceci est un commentaire' # node_comment
]

NŒUDS_INSTRUCTION_DE_TRAITEMENT

[
  $parent,
  <pos>,
  'cible', # node_target
  'données', # node_data
]

UTILISATION

Si vous ressentez le besoin d'utiliser ce module en dehors de XML::XPath (par exemple, vous pourriez utiliser ce module directement afin de mettre en cache les arbres analysés), vous pouvez suivre l'API suivante :

new

La méthode new ne prend aucun paramètre, ou l'un des paramètres suivants :

filename
xml
parser
ioref

Elle utilise la syntaxe de hachage familière, donc un exemple pourrait être :

use XML::XPath::XMLParser;
my $parser = XML::XPath::XMLParser->new(filename => 'example.xml');

Les paramètres représentent un nom de fichier, une chaîne contenant du XML, une instance de XML::Parser et une référence de descripteur de fichier ouvert respectivement. Vous pouvez également définir ou obtenir toutes ces propriétés à l'aide des fonctions get_ et set_ qui portent le même nom que la propriété : par exemple, get_filename, set_ioref, etc.

parse

La méthode parse ne prend généralement aucun paramètre, cependant vous êtes libre de passer une référence de descripteur de fichier ouvert ou une chaîne XML si vous le souhaitez. La valeur de retour est un arbre que XML::XPath peut utiliser. La méthode parse mourra s'il y a une erreur dans votre XML, alors assurez-vous d'utiliser le mécanisme de gestion des exceptions de perl (eval{};) si vous voulez éviter cela.

parsefile

La méthode parsefile est identique à parse() sauf qu'elle attend un seul paramètre qui est une chaîne nommant un fichier à ouvrir et à analyser. Encore une fois, elle renvoie un arbre et meurt également en cas d'erreurs XML.
