XML::Smart(3) Documentation Perl fournie par l'utilisateur XML::Smart(3)

NOM

XML::Smart - Un moyen intelligent, facile et puissant d'accéder ou de créer du XML à partir de fichiers, de données et d'URL.

VERSION

Version 1.79

SYNOPSIS

Ce module fournit un moyen facile d'accéder/créer des données XML. Il est basé sur une arborescence HASH créée à partir des données XML, et permet un accès dynamique à celle-ci via la syntaxe Perl standard pour les HASH et les Tableaux, sans qu'il soit nécessaire de se soucier de ce que l'on manipule. En d'autres termes, chaque point de l'arborescence fonctionne comme un HASH et un Tableau en même temps !

Ce module fournit en outre des ressources spéciales telles que : la recherche de nœuds par attribut, la sélection d'une valeur d'attribut dans chaque nœud multiple, le changement du format de sortie, etc.

Le module gère également automatiquement les données binaires (encodage/décodage base64), le CDATA (contenu comme avec des <balises>) et l'Unicode. Il peut être utilisé pour créer des fichiers XML, charger du XML depuis le Web (juste en utilisant une URL comme chemin de fichier) et dispose d'un moyen simple d'envoyer des données XML via des sockets - en ajoutant simplement la longueur des données dans l'en-tête <?xml ?>.

Vous pouvez utiliser XML::Smart avec XML::Parser, ou avec les 2 analyseurs standard de XML::Smart :

XML::Smart::Parser
XML::Smart::HTMLParser.

XML::Smart::HTMLParser peut être utilisé pour charger/analyser des données XML sauvages/mauvaises, ou des balises HTML.

TUTORIEL ET FAQ

Vous pouvez trouver des documents supplémentaires sur XML::Smart à l'adresse :

XML::Smart::Tutorial - Tutoriel et exemples pour XML::Smart.
XML::Smart::FAQ - Questions fréquemment posées sur XML::Smart.

UTILISATION

## Créer l'objet et charger le fichier :
my $XML = XML::Smart->new('file.xml') ;

## Forcer l'utilisation de l'analyseur 'XML::Smart::Parser'.
my $XML = XML::Smart->new('file.xml' , 'XML::Smart::Parser') ;

## Obtenir depuis le web :
my $XML = XML::Smart->new('http://www.perlmonks.org/index.pl?node_id=16046') ;
## Couper la racine :
$XML = $XML->cut_root ;
## Ou changer la racine :
$XML = $XML->{hosts} ;
## Obtenir l'adresse [0] du serveur [0] :
my $srv0_addr0 = $XML->{server}[0]{address}[0] ;
## ...ou...
my $srv0_addr0 = $XML->{server}{address} ;

## Obtenir le serveur dont l'attribut 'type' est égal à 'suse' :
my $server = $XML->{server}('type','eq','suse') ;

## Obtenir l'adresse à nouveau :
my $addr1 = $server->{address}[1] ;
## ...ou...
my $addr1 = $XML->{server}('type','eq','suse'){address}[1] ;

## Obtenir toutes les adresses d'un serveur :
my @addrs = @{$XML->{server}{address}} ;
## ...ou...
my @addrs = $XML->{server}{address}('@') ;

## Obtenir une liste de types de tous les serveurs :
my @types = $XML->{server}('[@]','type') ;

## Ajouter un nouveau nœud serveur :
my $newsrv = {
os      => 'Linux' ,
type    => 'Mandrake' ,
version => 8.9 ,
address => [qw(192.168.3.201 192.168.3.202)]
} ;

push(@{$XML->{server}} , $newsrv) ;
## Obtenir/reconstruire les données XML :
my $xmldata = $XML->data ;

## Enregistrer dans un fichier :
$XML->save('newfile.xml') ;

## Envoyer via un socket :
print $socket $XML->data(length => 1) ; ## affiche 'length' dans l'en-tête XML pour que le
                                        ## socket sache la quantité de données à lire.

__DATA__
<?xml version="1.0" encoding="iso-8859-1"?>
<hosts>
  <server os="linux" type="redhat" version="8.0">
    <address>192.168.0.1</address>
    <address>192.168.0.2</address>
  </server>
  <server os="linux" type="suse" version="7.0">
    <address>192.168.1.10</address>
    <address>192.168.1.20</address>
  </server>
  <server address="192.168.2.100" os="linux" type="conectiva" version="9.0"/>
</hosts>

MÉTHODES

new (FICHIER|DONNÉES|URL , ANALYSEUR , OPTIONS)

Crée un objet XML.

Arguments :

FICHIER|DONNÉES|URL
Le premier argument peut être : 
- Données XML sous forme de chaîne.
- Chemin de fichier.
- Descripteur de fichier (GLOB).
- URL (Nécessite LWP::UserAgent).

S'il n'est pas passé, un arbre XML vide est démarré, où vous devriez créer vos propres données XML, puis les construire/sauvegarder/envoyer.

ANALYSEUR (optionnel)
Définit l'analyseur XML à utiliser. Options : 
XML::Parser
XML::Smart::Parser
XML::Smart::HTMLParser

XML::Smart::Parser ne peut gérer que des données XML de base (pas de PCDATA supporté, ni d'en-tête comme : ENTITY, NOTATION, etc...), mais c'est un bon choix lorsque vous ne voulez pas installer de gros modules pour analyser du XML, puisqu'il est inclus dans le module principal. Mais il peut toujours gérer les CDATA et les données binaires.

** Voir "ANALYSE HTML comme XML" pour XML::Smart::HTMLParser.

Alias pour les options :

SMART|REGEXP   => XML::Smart::Parser
HTML           => XML::Smart::HTMLParser

Par défaut :

S'il n'est pas défini, il recherche XML::Parser et le charge. Si XML::Parser ne peut pas être chargé, il utilise XML::Smart::Parser, qui est en fait un clone de XML::Parser::Lite avec quelques corrections.

OPTIONS
Vous pouvez forcer la casse supérieure et inférieure pour les balises (nœuds) et les arguments (attributs), ainsi que d'autres éléments supplémentaires.
lowtag
Mettre les balises en minuscules.
lowarg
Mettre les arguments en minuscules.
upertag
Mettre les balises en majuscules.
uperarg
Mettre les arguments en majuscules.
arg_single
Définit la valeur des arguments à 1 lorsqu'ils ont une valeur undef.

** Cette option ne fonctionnera que lorsque le XML est analysé par XML::Smart::HTMLParser, car il accepte des arguments sans valeurs :

my $xml = new XML::Smart(
'<root><foo arg1="" flag></root>' ,
'XML::Smart::HTMLParser' ,
arg_single => 1 ,
) ;

Dans cet exemple, l'option "arg_single" a été utilisée, ce qui définira flag à 1, mais arg1 conservera une chaîne vide ("").

Voici l'arborescence de l'exemple ci-dessus :

'root' => {
            'foo' => {
                       'flag' => 1,
                       'arg1' => ''
                     },
          },
use_spaces
Accepter les contenus qui ne contiennent que des espaces.
on_start (CODE) *optionnel
Code/sous-routine à appeler au début d'une balise.

** Ceci sera appelé après que XML::Smart ait analysé la balise, ne devrait être utilisé que si vous souhaitez modifier l'arborescence.

on_char (CODE) *optionnel
Code/sous-routine à appeler lors de la lecture du contenu.

** Ceci sera appelé après que XML::Smart ait analysé la balise, ne devrait être utilisé que si vous souhaitez modifier l'arborescence.

on_end (CODE) *optionnel
Code/sous-routine à appeler à la fin d'une balise.

** Ceci sera appelé après que XML::Smart ait analysé la balise, ne devrait être utilisé que si vous souhaitez modifier l'arborescence.

** Ces options sont appliquées lorsque les données XML sont chargées. Pour la génération XML, voir les OPTIONS de data().

Exemples d'utilisation :

apply_dtd (DTD , OPTIONS)

Appliquer le DTD à l'arbre XML.

DTD peut être une source, un fichier, un GLOB ou une URL.

Cette méthode est utile si vous avez besoin que les données XML générées par data() soient formatées selon un DTD spécifique. Ainsi, les éléments deviendront automatiquement des nœuds, les attributs seront vérifiés, les éléments et attributs requis seront créés, l'ordre des éléments sera défini, etc...

OPTIONS :

no_delete BOOL
Si VRAI, indique que les éléments et attributs non définis dans le DTD ne seront pas supprimés de l'arbre XML.

Exemple d'utilisation :

$xml->apply_dtd(q`
<!DOCTYPE cds [
<!ELEMENT cds (album+)>
<!ATTLIST cds
          creator  CDATA
          date     CDATA #REQUIRED
          type     (a|b|c) #REQUIRED "a"
>
<!ELEMENT album (#PCDATA)>
]>
` ,
no_delete => 1 ,
);

args()

Retourne les noms des arguments (pas les nœuds).

args_values()

Retourne les valeurs des arguments (pas les nœuds).

back()

Remonte d'un niveau dans l'arbre.

** Voir base().

base()

Retourne à la base de l'arbre.

Chaque requête à l'objet XML::Smart renvoie un objet pointant vers un endroit différent dans l'arbre (et partage le même arbre HASH). Ainsi, vous pouvez récupérer l'objet principal à nouveau (un objet qui pointe vers la base) :

my $srv = $XML->{root}{host}{server} ;
my $addr = $srv->{adress} ;
my $XML2 = $srv->base() ;
$XML2->{root}{hosts}...

content()

Retourne le contenu d'un nœud :

## Données :
<foo>mon contenu</foo>

## Accès :

my $content = $XML->{foo}->content ;
print "<<$content>>\n" ; ## Affiche : <<mon contenu>>

## Ou simplement :
my $content = $XML->{foo} ;

Peut également être utilisé avec plusieurs contenus :

Pour ces données XML :

<root>
contenu0
<tag1 arg="1"/>
contenu1
</root>

Pour obtenir tout le contenu :

my $all_content = $XML->{root}->content ;
print "[$all_content]\n" ;

Sortie :

[
contenu0

contenu1
]

Pour obtenir par morceaux :

my @contents = $XML->{root}->content ;
print "[@contents[0]]\n" ;
print "[@contents[1]]\n" ;

Sortie

[
contenu0
]
[
contenu1
]

Définition de plusieurs contenus :

$XML->{root}->content(0,"aaaaa") ;
$XML->{root}->content(1,"bbbbb") ;

La sortie sera maintenant :

[aaaaa]
[bbbbb]

Et maintenant les données XML générées seront :

<root>aaaaa<tag1 arg="1"/>bbbbb</root>

copy()

Retourne une copie de l'objet XML::Smart (pointant vers la base).

** Ceci est utile lorsque vous souhaitez conserver 2 versions du même arbre XML en mémoire, car un objet ne peut pas modifier l'arbre de l'autre !

AVERTISSEMENT : Les modifications de set_node(), set_cdata() et set_binary() ne sont pas persistantes après une copie - une fois qu'une seconde copie est créée, ces états sont perdus.

b<avertissement :> ne pas copier après apply_dtd() sauf si vous avez vérifié les erreurs DTD.

cut_root()

Supprime la clé racine :

my $srv = $XML->{rootx}{host}{server} ;

## Ou si vous ne connaissez pas le nom de la racine :
$XML = $XML->cut_root() ;
my $srv = $XML->{host}{server} ;

** Notez que cela coupera la racine du pointeur dans l'arbre. Donc, si vous êtes dans un endroit qui a plus d'une clé (racines multiples), le même objet sera retourné sans rien couper.

data (OPTIONS)

Retourne les données de l'objet XML (en le reconstruisant).

Options :

nodtd
N'ajoute pas le DTD appliqué par la méthode apply_dtd() dans le contenu XML.
noident
Si défini à vrai, les données ne sont pas indentées.
nospace
Si défini à vrai, les données ne sont pas indentées et n'ont pas d'espace entre les balises (sauf si le CONTENU en a).
lowtag
Met les balises en minuscules.
lowarg
Met les arguments en minuscules.
upertag
Met les balises en majuscules.
uperarg
Met les arguments en majuscules.
length
Si défini à vrai, ajoute l'attribut 'length' avec la taille des données à l'en-tête xml (<?xml ...?>). Ceci est utile lors de l'envoi de données via une socket, car la socket peut connaître la quantité totale de données à lire.
noheader
Ne pas ajouter l'en-tête <?xml ...?>.
nometagen
Ne pas ajouter la balise meta de générateur : <?meta generator="XML::Smart" ?>
meta
Définit les balises meta du document XML.
decode
Depuis la VERSION 1.73, il existe trois différents encodages base64 utilisés. Ils sont choisis en fonction de ceux qui supportent les données fournies. Si vous souhaitez récupérer des données en utilisant la fonction 'data', le XML résultant contiendra dt:dt="binary.based". Pour récupérer les données décodées, utilisez : $XML->data( decode => 1 )

Exemples :

my $meta = {
build_from => "wxWindows 2.4.0" ,
file => "wx26.htm" ,
} ;

print $XML->data( meta => $meta ) ;

__DATA__
<?meta build_from="wxWindows 2.4.0" file="wx283.htm" ?>

Métadonnées multiples :

my $meta = [
{build_from => "wxWindows 2.4.0" , file => "wx26.htm" } ,
{script => "genxml.pl" , ver => "1.0" } ,
] ;

__DATA__
<?meta build_from="wxWindows 2.4.0" file="wx26.htm" ?>
<?meta script="genxml.pl" ver="1.0" ?>

Ou définir directement la balise meta :

my $meta = '<?meta foo="bar" ?>' ;
## Pour plusieurs :
my $meta = ['<?meta foo="bar" ?>' , '<?meta x="1" ?>'] ;

print $XML->data( meta => $meta ) ;
tree
Définit l'arbre HASH à analyser. S'il n'est pas défini, il utilisera l'arbre de l'objet XML::Smart (tree()).
wild
Accepte les balises et arguments génériques.

** Cela ne corrigera pas les clés et balises incorrectes.

sortall
Trie toutes les balises par ordre alphabétique. Si non défini, conservera l'ordre du document chargé, ou l'ordre de création des balises. Défaut : désactivé

data_pointer (OPTIONS)

Crée l'arbre à partir du point actuel dans l'arbre XML (pas de la base comme data()).

Accepte les mêmes OPTIONS que la méthode data().

dump_tree()

Affiche l'arbre de l'objet en utilisant Data::Dumper.

dump_tree_pointer()

Affiche l'arbre de l'objet, à partir du pointeur, en utilisant Data::Dumper.

dump_pointer()

** Identique à dump_tree_pointer().

i()

Retourne l'index de la valeur.

** Si la valeur provient d'une clé de hash (pas d'une référence ARRAY), undef est retourné.

is_node()

Retourne si une clé est un nœud.

key()

Retourne la clé de la valeur.

Si la liste est demandée, retourne aussi l'index : return(KEY , I) ;

nodes()

Retourne les nœuds (objets) présents au niveau du pointeur (clés qui ne sont pas des arguments).

nodes_keys()

Retourne les noms des nœuds (pas les objets) présents au niveau du pointeur (clés qui ne sont pas des arguments).

null()

Retourne vrai si l'objet XML a un arbre nul ou si le pointeur se trouve dans un endroit qui n'existe pas.

order()

Retourne l'ordre des clés. Voir set_order().

path()

Retourne le chemin du pointeur.

Exemple :

/hosts/server[1]/address[0]

Notez que l'index est basé sur 0 et 'address' peut être un attribut ou un nœud, ce qui n'est pas compatible avec XPath.

** Voir path_as_xpath().

path_as_xpath()

Retourne le chemin du pointeur au format XPath.

pointer

Retourne l'arbre HASH à partir du pointeur.

pointer_ok

>

Retourne une copie de l'arbre de l'objet, depuis le pointeur, mais sans les clés internes ajoutées par XML::Smart.

root

Retourne le nom ROOT de l'arbre XML (clé principale).

** Voir aussi key() pour les nœuds enfants.

save (FILEPATH , OPTIONS)

Enregistre les données XML dans un fichier.

Accepte les mêmes OPTIONS que la méthode data().

set_auto

Définit la clé à gérer automatiquement. Ainsi, data() définira automatiquement s'il s'agit d'un nœud, d'un contenu ou d'un attribut.

** Cette méthode est utile pour supprimer les modifications de set_node(), set_cdata() et set_binary().

set_auto_node

Définit la clé comme un nœud, et data() définira automatiquement s'il s'agit de CDATA ou de BINARY.

** Cette méthode est utile pour supprimer les modifications de set_cdata() et set_binary().

set_binary(BOOL)

Définit le nœud comme un contenu BINAIRE lorsque TRUE, ou force à ne pas le traiter comme BINARY lorsque FALSE.

Exemple de nœud traité comme BINARY :

<root><foo dt:dt="binary.base64">PGgxPnRlc3QgAzwvaDE+</foo></root>

Contenu original de foo (les données base64) :

<h1>test \x03</h1>

set_cdata(BOOL)

Définit le nœud comme CDATA lorsque TRUE, ou force à ne pas le traiter comme CDATA lorsque FALSE.

Exemple de nœud CDATA :

<root><foo><![CDATA[bla bla bla <tag> bla bla]]></foo></root>

set_node(BOOL)

Définit/annule la clé actuelle comme un nœud (balise).

** Si BOOL n'est pas défini, il utilisera TRUE.

ATTENTION : Vous ne pouvez pas faire set_node, copier l'objet puis set_node( 0 ) [ Annuler le nœud ]

set_order(KEYS)

Définit l'ordre des clés (nœuds et attributs) à ce point.

set_tag

Identique à set_node.

tree()

Retourne l'arbre HASH des données XML.

** Notez que le véritable arbre HASH est retourné ici. Toutes les autres méthodes retournent un objet qui fonctionne comme un HASH/ARRAY via tie.

tree_pointer()

Identique à pointer().

tree_ok()

Retourne une copie de l'arbre de l'objet, mais sans les clés internes ajoutées par XML::Smart, comme /order et /nodes.

tree_pointer_ok()

Retourne une copie de l'arbre de l'objet, depuis le pointeur, mais sans les clés internes ajoutées par XML::Smart.

xpath() || XPath()

Retourne un objet XML::XPath, basé sur la racine XML dans l'arbre.

## recherche depuis la racine :
my $data = $XML->XPath->findnodes_as_string('/') ;

** Nécessite XML::XPath installé, mais est uniquement chargé quand nécessaire.

xpath_pointer() || XPath_pointer()

Retourne un objet XML::XPath, basé sur le pointeur XML::Smart dans l'arbre.

## recherche depuis ce point, donc XPath '/' commence en fait à /server/ :

my $srvs = $XML->{server} ;
my $data = $srvs->XPath_pointer->findnodes_as_string('/') ;

** Nécessite XML::XPath installé, mais est uniquement chargé quand nécessaire.

ANNIHILATE

XML::Smart utilise XML::XPath qui, pour des raisons de performance, laisse fuir de la mémoire. Pour garantir que cette mémoire est libérée, vous pouvez explicitement appeler ANNIHILATE avant que l'objet XML::Smart ne sorte de sa portée.

ACCÈS

Pour accéder aux données, vous utilisez l'objet d'une manière similaire à HASH et ARRAY :

my $XML = XML::Smart->new('file.xml') ;

my $server = $XML->{server} ;

Mais lorsque vous obtenez une clé {server}, vous accédez en fait aux données via tie(), et non directement à l'arbre HASH à l'intérieur de l'objet (cela corrigera les accès incorrects) :

## {server} est une clé normale, pas une référence ARRAY :
my $server = $XML->{server}[0] ; ## retourne $XML->{server}
my $server = $XML->{server}[1] ; ## retourne UNDEF

## {server} a une référence ARRAY avec 2 éléments :
my $server = $XML->{server} ;    ## retourne $XML->{server}[0]
my $server = $XML->{server}[0] ; ## retourne $XML->{server}[0]
my $server = $XML->{server}[1] ; ## retourne $XML->{server}[1]

Pour obtenir toutes les valeurs de plusieurs éléments/clés :

## Cela fonctionne même si {address} contient uniquement une chaîne, ou avec une référence ARRAY :
my @addrsses = @{$XML->{server}{address}} ;

Sélection recherche

Lorsque vous ne connaissez pas la position des nœuds, vous pouvez les sélectionner par la valeur d'un attribut :

my $server = $XML->{server}('type','eq','suse') ; ## retourne $XML->{server}[1]

Syntaxe pour la recherche par sélection :

(NOM, CONDITION , VALEUR)
NOM
Le nom de l'attribut dans le nœud (balise).
CONDITION
Peut être 
eq  ne  ==  !=  <=  >=  <  >

Pour les EXPRESSIONS RÉGULIÈRES :

=~  !~

## Insensible à la casse :
=~i !~i
VALEUR
La valeur.

Pour les EXPRESSIONS RÉGULIÈRES, utilisez comme suit :

$XML->{server}('type','=~','^s\w+$') ;

Sélection attributs dans plusieurs nœuds :

Vous pouvez obtenir la liste des valeurs d'un attribut en recherchant dans tous les nœuds multiples :

## Obtenir tous les types de serveurs :
my @types = $XML->{server}('[@]','type') ;

Aussi comme ceci :

my @types = $XML->{server}{type}('<@') ;

Sans la ressource :

my @list ;
my @servers = @{$XML->{server}} ;

foreach my $servers_i ( @servers ) {
  push(@list , $servers_i->{type} ) ;
}

Format de retour

Vous pouvez modifier le format retourné :

Syntaxe :

(TYPE)

Où TYPE peut être :

$  ## le contenu.
@  ## un tableau (liste de valeurs multiples).
%  ## une table de hachage.
.  ## Le point exact dans l'arbre, pas un objet.

$@  ## un tableau, mais avec le contenu, pas des objets.
$%  ## une table de hachage, mais les valeurs sont le contenu, pas un objet.

## L'utilisation de $@ et $% est bien si vous ne voulez pas conserver la
## référence d'objet (et économiser de la mémoire).

@keys  ## Les clés du nœud. Notez que si vous avez une clé avec
       ## plusieurs nœuds, elle sera répliquée (c'est la
       ## différence de "keys %{$this->{node}}" ).
<@ ## Retourne l'attribut dans le nœud précédent, mais en recherchant
   ## plusieurs nœuds. Exemple :

my @names = $this->{method}{wxFrame}{arg}{name}('<@') ;
#### @names = (parent , id , title) ;

<xml> ## Retourne des données XML à partir de ce point.

__DATA__
<method>
  <wxFrame return="wxFrame">
    <arg name="parent" type="wxWindow" />
    <arg name="id" type="wxWindowID" />
    <arg name="title" type="wxString" />
  </wxFrame>
</method>

Exemple :

## Contenu d'un serveur
my $name = $XML->{server}{name}('$') ;
## ... ou :
my $name = $XML->{server}{name}->content ;
## ... ou :
my $name = $XML->{server}{name} ;
$name = "$name" ;

## Tous les serveurs
my @servers = $XML->{server}('@') ;
## ... ou :
my @servers = @{$XML->{server}} ;

## Il conserve la référence d'objet :
@servers[0]->{name} ;

## Sans la référence :
my @servers = $XML->{server}('$@') ;

## Des données XML, identique à data_pointer() :
my $xml_data = $XML->{server}('<xml>') ;

CONTENU

Si une {clé} a un contenu, vous pouvez y accéder directement depuis la variable ou depuis la méthode :

my $server = $XML->{server} ;
print "Contenu : $server\n" ;
## ...ou...
print "Contenu : ". $server->content ."\n" ;

Donc, si vous utilisez l'objet comme une chaîne, il fonctionne comme une chaîne, si vous l'utilisez comme un objet, il fonctionne comme un objet ! ;-P

** Voir la méthode content() pour plus d'informations.

CRÉATION DE DONNÉES XML

Créer des données XML est facile, vous l'utilisez comme une table de hachage normale, mais vous n'avez pas besoin de vous soucier des nœuds multiples, de la création/conversion de tableaux !

## Créer un objet XML nul :
my $XML = XML::Smart->new() ;

## Ajouter un serveur à la liste :
$XML->{server} = {
os => 'Linux' ,
type => 'mandrake' ,
version => 8.9 ,
address => '192.168.3.201' ,
} ;

## Les données maintenant :
<server address="192.168.3.201" os="Linux" type="mandrake" version="8.9"/>

## Ajouter une nouvelle adresse au serveur. Crée un ARRAY, convertit
## la clé précédente en ARRAY :
$XML->{server}{address}[1] = '192.168.3.202' ;

## Les données maintenant :
<server os="Linux" type="mandrake" version="8.9">
  <address>192.168.3.201</address>
  <address>192.168.3.202</address>
</server>

Après avoir créé votre arbre XML, vous le sauvegardez ou obtenez les données :

## Obtenir les données :
my $data = $XML->data ;

## Ou sauvegardez-le directement :
$XML->save('newfile.xml') ;

## Ou envoyez-le à un socket :
print $socket $XML->data(length => 1) ;

DONNÉES BINAIRES &amp; CDATA

p; CDATA

À partir de la version 1.2, XML::Smart peut gérer automatiquement les données binaires et les blocs CDATA.

Lors de l'analyse, les données binaires seront détectées comme suit :

<code dt:dt="binary.base64">f1NPTUUgQklOQVJZIERBVEE=</code>

Puisqu'il s'agit du format officiel automatique pour les données binaires sur XML.com http://www.xml.com/pub/a/98/07/binary/binary.html. Le contenu sera décodé à partir de base64 et enregistré dans l'arborescence d'objets.

Les CDATA seront analysés comme tout autre contenu, car CDATA n'est qu'un bloc qui ne sera pas analysé.

Lors de la création de données XML, comme dans $XML->data(), le format binaire et CDATA sont détectés selon les règles suivantes :

BINAIRE :
- Si vos données contiennent des caractères qui ne peuvent pas être présents en XML.
* Caractères acceptés :

  \s \w \d

CDATA :
- S'il contient des balises : <...>

CONTENU : (<balise>contenu</balise>)
- S'il contient \r\n\t, ou ' et " en même temps.

Ainsi, ce sera un contenu CDATA :

<code><![CDATA[
  ligne1
  <balise_non_analysée>
  ligne2
]]></code>

Si un contenu binaire est détecté, il sera converti en base64 et un attribut dt:dt sera ajouté dans la balise pour spécifier le format.

<code dt:dt="binary.base64">f1NPTUUgQklOQVJZIERBVEE=</code>

NOTE : Depuis la VERSION 1.73, trois différents encodages base64 sont utilisés. Ils sont choisis en fonction de celui qui prend en charge les données fournies. Si vous souhaitez récupérer des données en utilisant la fonction 'data', le XML résultant contiendra dt:dt="binary.based". Pour récupérer les données décodées, utilisez : $XML->data( decode => 1 )

UNICODE et ASCII-étendu (ISO-8859-1)

XML::Smart ne prend en charge que ces 2 types d'encodage, Unicode (UTF-8) et ASCII étendu (ISO-8859-1), et cela devrait suffire. (Notez que UTF-8 n'est pris en charge qu'à partir de Perl-5.8+).

Lors de la création de données XML, si un caractère UTF-8 est détecté, l'attribut encoding dans l'en-tête <?xml ...?> sera défini sur UTF-8 :

<?xml version="1.0" encoding="utf-8" ?>
<data>0x82, 0x83</data>

Sinon, iso-8859-1 est utilisé :

<?xml version="1.0" encoding="iso-8859-1" ?>
<data>0x82</data>

Lors du chargement de données XML avec UTF-8, Perl (5.8+) devrait gérer tout le travail en interne.

ANALYSE HTML comme XML, ou formats XML MAUVAIS

Vous pouvez utiliser l'analyseur spécial XML::Smart::HTMLParser pour "utiliser" du HTML comme du XML ou des données XML mal formées.

Les différences entre un analyseur XML normal et XML::Smart::HTMLParser sont :

- Accepte les valeurs sans guillemets :
  <foo bar=x>

- Accepte n'importe quelles données dans les valeurs, y compris <> et & :
  <root><echo sample="echo \"Hello!\">out.txt"></root>

- Accepte les valeurs d'URI sans guillemets :
  <link url=http://www.foo.com/dir/file?query?q=v&x=y target=#_blank>

- N'a pas besoin de fermer les balises en ajoutant le '/' avant le '>' :
  <root><foo bar="1"></root>

  ** Notez que l'analyseur essaiera de détecter les nœuds et de les fermer
     automatiquement ou non.

- N'a pas besoin d'avoir un seul élément racine :
  <foo>données</foo><bar>données</bar>

Ainsi, XML::Smart::HTMLParser est un moyen souple de charger des données balisées (comme le HTML), ou si vous ne voulez pas vous soucier des guillemets, des balises de fin, etc... lors de la rédaction manuelle de vos données XML. Vous pouvez donc écrire manuellement un mauvais fichier XML, le charger avec XML::Smart::HTMLParser et le réécrire correctement en le sauvegardant à nouveau ! ;-P

** Notez que les balises <SCRIPT> ne seront correctement analysées que si le contenu est à l'intérieur de commentaires <!--...-->, car elles peuvent contenir des balises :

<SCRIPT LANGUAGE="JavaScript"><!--
document.writeln("some <tag> in the string");
--></SCRIPT>

ENTITÉS

Les entités (ENTITY) sont gérées par l'analyseur. Donc, si vous utilisez XML::Parser, il fera tout le travail correctement. Mais si vous utilisez XML::Smart::Parser ou XML::Smart::HMLParser, seules les entités de base (par défaut) seront analysées :

&lt;   => Le signe inférieur à (<).
&gt;   => Le signe supérieur à (>).
&amp;  => Le signe esperluette (&).
&apos; => L'apostrophe (').
&quot; => Le guillemet double (").
&#ddd;  => Un caractère ASCII ou un caractère Unicode (>255). Où ddd est un décimal.
&#xHHH; => Un caractère Unicode. Où HHH est en hexadécimal.

Lors de la création de données XML, les entités déjà existantes ne seront pas modifiées, et les caractères '<', '&' et '>' seront convertis en l'entité appropriée.

** Notez que si un contenu contient une <balise>, les caractères '<' et '>' ne seront pas convertis en entités, et ce contenu sera à l'intérieur d'un bloc CDATA.

POURQUOI ET COMMENT ÇA MARCHE

Tous ceux qui ont essayé d'utiliser des HASH et des ARRAY Perl pour accéder aux données XML, comme dans XML::Simple, ont eu des problèmes pour ajouter de nouveaux nœuds, ou pour accéder au nœud lorsque l'utilisateur ne sait pas s'il se trouve dans un ARRAY, un HASH ou une clé HASH. XML::Smart crée autour de cela une manière très dynamique d'accéder aux données, car en même temps, n'importe quel nœud/point de l'arbre peut être un HASH et un ARRAY. Vous avez également d'autres ressources supplémentaires, comme la recherche de nœuds par attribut :

my $server = $XML->{server}('type','eq','suse') ; ## Cette syntaxe n'est pas fausse ! ;-)
## Au lieu de :
my $server = $XML->{server}[1] ;

__DATA__
<hosts>
  <server os="linux" type="redhat" version="8.0">
  <server os="linux" type="suse" version="7.0">
</hosts>

L'idée de ce module est venue du problème d'accès à une structure complexe en XML. Il suffit de connaître la structure, ce qui se fait généralement en regardant le fichier XML (ce qui est faux). Mais en même temps, il est difficile de vérifier constamment (par le code) la structure, avant d'y accéder. XML est un format bon et facile pour déclarer vos données, mais pour les extraire sous forme d'arbre, au moins à mon avis, ce n'est pas facile. Pour y remédier, m'est venue à l'esprit une manière d'accéder aux données avec un langage de requête, comme SQL. La première idée était d'accéder en utilisant quelque chose comme :

XML.foo.bar.baz{arg1}
X = XML.foo.bar*
X.baz{arg1}

XML.hosts.server[0]{argx}

Et j'ai vu que c'était très similaire aux Hashes et aux Arrays en Perl :

$XML->{foo}{bar}{baz}{arg1} ;

$X = $XML->{foo}{bar} ;
$X->{baz}{arg1} ;

$XML->{hosts}{server}[0]{argx} ;

Mais le problème des Hash et Array, c'est de ne pas savoir si on a une référence d'Array ou pas. Par exemple, dans XML::Simple :

## C'est très différent
$XML->{server}{address} ;
## ... de ceci :
$XML->{server}{address}[0] ;

Alors, pourquoi ne pas faire fonctionner les deux ? Parce qu'il faut faire quelque chose de fou !

Pour créer XML::Smart, j'ai d'abord créé le module Object::MultiType. Avec lui, vous pouvez avoir un objet qui fonctionne en même temps comme un HASH, ARRAY, SCALAR, CODE et GLOB. Vous pouvez donc faire des choses comme ceci avec le même objet :

$obj = Object::MultiType->new() ;

$obj->{key} ;
$obj->[0] ;
$obj->method ;  

@l = @{$obj} ;
%h = %{$obj} ;

&$obj(args) ;

print $obj "send data\n" ;

Cela semble fou, et peut l'être encore plus si vous utilisez tie() à l'intérieur, et c'est ce que fait XML::Smart.

Pour XML::Smart, l'accès en mode Hash et Array passe par tie(). Autrement dit, vous avez un HASH lié et un ARRAY lié à l'intérieur. Ce Hash et cet Array liés fonctionnent ensemble, de sorte que vous pouvez accéder à une clé Hash comme à l'indice 0 d'un Array, ou accéder à un indice 0 comme à la clé Hash :

%hash = (
key => ['a','b','c']
) ;

$hash->{key}    ## retourne $hash{key}[0]
$hash->{key}[0] ## retourne $hash{key}[0]  
$hash->{key}[1] ## retourne $hash{key}[1]

## Inverse :

%hash = ( key => 'a' ) ;

$hash->{key}    ## retourne $hash{key}
$hash->{key}[0] ## retourne $hash{key}
$hash->{key}[1] ## retourne undef

Le meilleur aspect de cette nouvelle ressource est d'éviter les accès erronés aux données et les avertissements lorsque vous essayez d'accéder à un Hash qui contient un Array (et vice-versa). Chose qui fait généralement planter le script (die()).

Une fois que vous avez un accès facile aux données, vous pouvez utiliser la même ressource pour créer des données ! Par exemple :

## Données précédentes :
<hosts>
  <server address="192.168.2.100" os="linux" type="conectiva" version="9.0"/>
</hosts>

## Maintenant, vous avez {address} comme une clé normale avec une chaîne à l'intérieur :
$XML->{hosts}{server}{address}

## Et pour ajouter une nouvelle adresse, la clé {address} doit être une référence ARRAY !
## Donc, XML::Smart effectue la conversion : ;-P
$XML->{hosts}{server}{address}[1] = '192.168.2.101' ;

## Ajout à une liste dont vous ne connaissez pas la taille :
push(@{$XML->{hosts}{server}{address}} , '192.168.2.102') ;

## Les données maintenant :
<hosts>
  <server os="linux" type="conectiva" version="9.0"/>
    <address>192.168.2.100</address>
    <address>192.168.2.101</address>
    <address>192.168.2.102</address>
  </server>
</hosts>

Après avoir modifié votre arbre XML en utilisant les ressources Hash et Array, il suffit de récupérer les données refaites (via l'arbre Hash à l'intérieur de l'objet) :

my $xmldata = $XML->data ;

Mais notez que XML::Smart retourne toujours un objet ! Même lorsque vous obtenez une clé finale. Donc, ceci retourne en fait un autre objet, pointant (à l'intérieur) vers la clé :

$addr = $XML->{hosts}{server}{address}[0] ;

## Comme $addr est un objet, vous pouvez ESSAYER d'accéder à plus de données :
$addr->{foo}{bar} ; ## Ceci ne génère pas d'avertissement ! retourne simplement UNDEF.
