NOM

XmClipboardRetrieve — Une fonction de presse-papiers qui récupère un élément de données du presse-papiers

SYNTAXE

#include <Xm/CutPaste.h>
int XmClipboardRetrieve (display, window, format_name,
        buffer, length, num_bytes, private_id)
        Display * display;
        Window  window;
        char    * format_name;
        XtPointer       buffer;
        unsigned long   length;
        unsigned long   * num_bytes;
        long    * private_id;
(void)

DESCRIPTION

XmClipboardRetrieve récupère l'élément de données actuel du stockage du presse-papiers. Elle renvoie un avertissement si le presse-papiers est verrouillé, s'il n'y a pas de données dans le presse-papiers, ou si les données doivent être tronquées parce que la longueur du tampon est trop courte.

Entre un appel à XmClipboardStartRetrieve et un appel à XmClipboardEndRetrieve, plusieurs appels à XmClipboardRetrieve avec le même nom de format entraînent une copie incrémentielle des données du presse-papiers jusqu'à ce que toutes les données dans ce format aient été copiées.

La valeur de retour XmClipboardTruncate des appels à XmClipboardRetrieve indique que des données supplémentaires restent à copier dans le format donné. Il est recommandé que tous les appels aux fonctions Inquire que l'application doit effectuer pour effectuer la copie du presse-papiers soient effectués entre l'appel à XmClipboardStartRetrieve et le premier appel à XmClipboardRetrieve. De cette façon, l'application n'a pas besoin d'appeler XmClipboardLock et XmClipboardUnlock.

display
Spécifie un pointeur vers la structure Display qui a été retournée lors d'un appel précédent à XOpenDisplay ou XtDisplay.
window
Spécifie l'ID de fenêtre d'un widget qui relie la fenêtre de l'application au presse-papiers. L'ID de fenêtre du widget peut être obtenu via XtWindow. La même instance d'application doit passer le même ID de fenêtre à chacune des fonctions de presse-papiers qu'elle appelle.
format_name
Spécifie le nom d'un format dans lequel les données sont stockées sur le presse-papiers.
buffer
Spécifie le tampon vers lequel l'application souhaite que le presse-papiers copie les données. La fonction alloue de l'espace pour contenir les données renvoyées dans le tampon. L'application est responsable de la gestion de cet espace alloué. L'application peut récupérer cet espace alloué en appelant XtFree.
length
Spécifie la longueur du tampon de l'application.
num_bytes
Spécifie le nombre d'octets de données copiés dans le tampon de l'application.
private_id
Spécifie les données privées stockées avec l'élément de données par l'application qui a placé l'élément de données sur le presse-papiers. Si l'application n'a pas stocké de données privées avec l'élément de données, cet argument renvoie 0 (zéro).

RETOUR

XmClipboardSuccess
La fonction a réussi.
XmClipboardLocked
La fonction a échoué parce que le presse-papiers était verrouillé par une autre application. L'application peut continuer à appeler la fonction à nouveau avec les mêmes paramètres jusqu'à ce que le verrou disparaisse. Cela donne à l'application l'opportunité de demander si l'utilisateur souhaite continuer à essayer ou abandonner l'opération.
XmClipboardTruncate
Les données renvoyées sont tronquées parce que l'utilisateur n'a pas fourni un tampon suffisamment grand pour contenir les données.
XmClipboardNoData
La fonction n'a pas pu trouver de données dans le presse-papiers correspondant au format demandé. Cela pourrait se produire parce que le presse-papiers est vide ; il y a des données dans le presse-papiers mais pas dans le format demandé ; ou les données dans le format demandé ont été passées par nom et ne sont plus disponibles.

VOIR AUSSI

XmClipboardEndRetrieve(3), XmClipboardLock(3), XmClipboardStartCopy(3), XmClipboardStartRetrieve(3), et XmClipboardUnlock(3).
