NOM

XML::Parser - Un module Perl pour l'analyse syntaxique de documents XML

SYNTAXE

use XML::Parser;
$p1 = XML::Parser->new(Style => 'Debug');
$p1->parsefile('REC-xml-19980210.xml');
$p1->parse('<foo id="me">Hello World</foo>');
# Alternative
$p2 = XML::Parser->new(Handlers => {Start => \&handle_start,
                                   End   => \&handle_end,
                                   Char  => \&handle_char});
$p2->parse($socket);
# Autre alternative
$p3 = XML::Parser->new(ErrorContext => 2);
$p3->setHandlers(Char    => \&text,
                 Default => \&other);
open(my $fh, 'xmlgenerator |');
$p3->parse($fh, ProtocolEncoding => 'ISO-8859-1');
close($fh);
$p3->parsefile('junk.xml', ErrorContext => 3);

DESCRIPTION

Ce module fournit des moyens d'analyser des documents XML. Il est basé sur XML::Parser::Expat, qui est une interface de plus bas niveau à la bibliothèque expat de James Clark. Chaque appel à l'une des méthodes d'analyse crée une nouvelle instance de XML::Parser::Expat qui est ensuite utilisée pour analyser le document. Les options Expat peuvent être fournies lors de la création de l'objet XML::Parser. Ces options sont ensuite transmises à l'objet Expat lors de chaque appel d'analyse. Elles peuvent également être fournies en arguments supplémentaires aux méthodes d'analyse, auquel cas elles remplacent les options données lors de la création de XML::Parser.

Le comportement de l'analyseur est contrôlé soit par les options "STYLES" et/ou "HANDLERS", soit par la méthode "setHandlers". Tous fournissent des mécanismes pour que XML::Parser configure les gestionnaires nécessaires à XML::Parser::Expat. Si ni "Style" ni "Handlers" ne sont spécifiés, l'analyse se contente de vérifier que le document est bien formé.

Lorsque les gestionnaires sous-jacents sont appelés, ils reçoivent comme premier paramètre l'objet Expat, et non l'objet Parser.

MÉTHODES

new
Ceci est une méthode de classe, le constructeur de XML::Parser. Les options sont passées sous forme de paires mot-clé-valeur. Les options reconnues sont :
  • Style

    Cette option fournit un moyen simple de créer un style donné d'analyseur. Les styles intégrés sont : "Debug", "Subs", "Tree", "Objects", et "Stream". Ceux-ci sont tous définis dans des paquets séparés sous "XML::Parser::Style::*", et vous pouvez trouver une documentation supplémentaire pour chaque style ci-dessous, et dans ces paquets.

    Des styles personnalisés peuvent être fournis en donnant un nom de paquet complet contenant au moins un '::'. Ce paquet devrait alors avoir des sous-programmes définis pour chaque gestionnaire qu'il souhaite installer. Voir "STYLES" ci-dessous pour une discussion de chaque style intégré.

  • Handlers

    Lorsqu'elle est fournie, cette option doit être une table de hachage anonyme contenant comme clés le type de gestionnaire et comme valeurs une référence de sous-programme pour gérer ce type d'événement. Tous les gestionnaires reçoivent comme premier paramètre l'instance d'expat qui analyse le document. Plus de détails sur les gestionnaires peuvent être trouvés dans "HANDLERS". Tout gestionnaire défini ici remplace le gestionnaire correspondant défini avec l'option Style.

  • Pkg

    Certains styles feront référence à des sous-programmes définis dans ce paquet. S'il n'est pas fourni, il prend par défaut le paquet qui a appelé le constructeur.

  • ErrorContext

    C'est une option Expat. Lorsque cette option est définie, les erreurs sont signalées dans leur contexte. La valeur doit être le nombre de lignes à afficher de chaque côté de la ligne où l'erreur s'est produite.

  • ProtocolEncoding

    C'est une option Expat. Elle définit le nom de l'encodage du protocole. Elle est indéfinie par défaut. Les encodages intégrés sont : "UTF-8", "ISO-8859-1", "UTF-16", et "US-ASCII". D'autres encodages peuvent être utilisés s'ils ont des cartes d'encodage dans l'un des répertoires de la liste @Encoding_Path. Consultez "ENCODINGS" pour plus d'informations sur les cartes d'encodage. La définition de l'encodage du protocole remplace tout encodage dans la déclaration XML.

  • Namespaces

    C'est une option Expat. Si elle est définie à une valeur vraie, alors le traitement des espaces de noms est effectué pendant l'analyse. Voir "Namespaces" dans XML::Parser::Expat pour une discussion plus approfondie du traitement des espaces de noms.

  • NoExpand

    C'est une option Expat. Normalement, l'analyseur essaiera de développer les références aux entités définies dans le sous-ensemble interne. Si cette option est définie à une valeur vraie, et qu'un gestionnaire par défaut est également défini, alors le gestionnaire par défaut sera appelé lorsqu'une référence d'entité est rencontrée dans du texte. Ceci n'a aucun effet si un gestionnaire par défaut n'a pas été enregistré, et cela n'a aucun effet sur le développement des références d'entités à l'intérieur des valeurs d'attributs.

  • Stream_Delimiter

    C'est une option Expat. Elle prend une valeur de chaîne. Lorsque cette chaîne est trouvée seule sur une ligne lors de l'analyse d'un flux, l'analyse se termine comme si un fin de fichier était rencontrée. L'usage prévu est avec un flux de documents xml au format MIME multipart. La chaîne ne doit pas contenir de nouvelle ligne finale.

  • ParseParamEnt

    C'est une option Expat. Sauf si standalone est défini à "yes" dans la déclaration XML, la définition de cette option à une valeur vraie permet de lire la DTD externe, et d'analyser et développer les entités de paramètre.

  • NoLWP

    Cette option n'a aucun effet si les gestionnaires ExternEnt ou ExternEntFin sont directement définis. Sinon, si elle est vraie, elle force l'utilisation d'un gestionnaire d'entités externes basé sur des fichiers.

  • Non_Expat_Options

    Si elle est fournie, ceci doit être une table de hachage anonyme dont les clés sont des options qui ne devraient pas être passées à Expat. Ceci ne devrait concerner que ceux qui sous-classent XML::Parser.

setHandlers(TYPE, HANDLER [, TYPE, HANDLER [...]])
Cette méthode enregistre des gestionnaires pour divers événements de l'analyseur. Elle remplace tous les gestionnaires précédemment enregistrés via les options Style ou Handler ou via des appels antérieurs à setHandlers. En fournissant une valeur fausse ou indéfinie comme gestionnaire, le gestionnaire existant peut être désactivé.

Cette méthode retourne une liste de paires type, gestionnaire correspondant à l'entrée. Les gestionnaires retournés sont ceux qui étaient en vigueur avant l'appel.

Voir une description des types de gestionnaires dans "HANDLERS".

parse(SOURCE [, OPT => OPT_VALUE [...]])
Le paramètre SOURCE doit être soit une chaîne contenant le document XML entier, soit une poignée IO::Handle ouverte. Les options du constructeur pour XML::Parser::Expat fournies sous forme de paires mot-clé-valeur peuvent suivre le paramètre SOURCE. Celles-ci remplacent, pour cet appel, toute option ou attribut passé depuis l'instance XML::Parser.

Un appel à die est déclenché si une erreur d'analyse se produit. Sinon, il retournera 1 ou ce que retourne le gestionnaire Final, s'il en est installé un. Autrement dit, ce que parse peut retourner dépend du style.

parsestring
Ceci est juste un alias pour parse pour des raisons de compatibilité descendante.
parsefile(FILE [, OPT => OPT_VALUE [...]])
Ouvre FILE en lecture, puis appelle parse avec la poignée ouverte. Le fichier est fermé quelle que soit la manière dont parse retourne. Retourne ce que retourne parse.
parse_start([ OPT => OPT_VALUE [...]])
Crée et retourne une nouvelle instance de XML::Parser::ExpatNB. Des options de constructeur peuvent être fournies. Si un gestionnaire d'initialisation a été fourni, il est appelé avant de retourner l'objet ExpatNB. Les documents sont analysés en faisant des appels incrémentiels à la méthode parse_more de cet objet, qui prend une chaîne. Un seul appel à la méthode parse_done de cet objet, qui ne prend aucun argument, indique que le document est terminé.

S'il y a un gestionnaire final installé, il est exécuté par la méthode parse_done avant de retourner et la méthode parse_done retourne ce que retourne le gestionnaire final

Ce site n'est en aucun cas associé à Arch Linux ni affilié à ce projet. Le contenu est uniquement une traduction des pages de manuel d'Arch publiées sur man.archlinux.org.

Pour plus de détails, veuillez consulter la section "Méthodes" de XML::Parser::Expat.

MANIPULATEURS

Expat est un analyseur basé sur les événements. Lorsque l'analyseur reconnaît des parties du document (par exemple, la balise de début ou de fin pour un élément XML), les manipulateurs enregistrés pour ce type d'événement sont appelés avec les paramètres appropriés. Tous les manipulateurs reçoivent une instance de XML::Parser::Expat comme premier argument. Voir "MÉTHODES" dans XML::Parser::Expat pour une discussion sur les méthodes qui peuvent être appelées sur cet objet.

Init (Expat)

Ceci est appelé juste avant le début de l'analyse du document.

Final (Expat)

Ceci est appelé juste après la fin de l'analyse, mais seulement si aucune erreur ne s'est produite pendant l'analyse. Parse renvoie ce que ceci renvoie.

Start (Expat, Élément [, Attribut, Valeur [, ...]])

Cet événement est généré lorsqu'une balise de début XML est reconnuée. Élément est le nom du type d'élément XML qui est ouvert avec la balise de début. Les paires Attribut & Valeur sont générées pour chaque attribut dans la balise de début.

End (Expat, Élément)

Cet événement est généré lorsqu'une balise de fin XML est reconnuée. Notez qu'une balise vide XML (<foo/>) génère à la fois un événement de début et de fin.

Char (Expat, Chaîne)

Cet événement est généré lorsque du contenu non balisé est reconnu. La séquence de caractères non balisés se trouve dans Chaîne. Une seule séquence de caractères non balisés peut générer plusieurs appels à ce manipulateur. Quel que soit l'encodage de la chaîne dans le document original, celle-ci est transmise au manipulateur en UTF-8.

Proc (Expat, Cible, Données)

Cet événement est généré lorsqu'une instruction de traitement est reconnuée.

Comment (Expat, Données)

Cet événement est généré lorsqu'un commentaire est reconnu.

CdataStart (Expat)

Ceci est appelé au début d'une section CDATA.

CdataEnd (Expat)

Ceci est appelé à la fin d'une section CDATA.

Default (Expat, Chaîne)

Ceci est appelé pour tous les caractères qui n'ont pas de manipulateur enregistré. Cela inclut à la fois les caractères qui font partie de balisage pour lequel aucun événement n'est généré (déclarations de balisage) et les caractères qui pourraient générer des événements, mais pour lesquels aucun manipulateur n'a été enregistré.

Quel que soit l'encodage du document original, la chaîne est renvoyée au manipulateur en UTF-8.

Unparsed (Expat, Entité, Base, Sysid, Pubid, Notation)

Ceci est appelé pour une déclaration d'entité non analysée. Entité est le nom de l'entité. Base est la base à utiliser pour résoudre une URI relative. Sysid est l'identifiant système. Pubid est l'identifiant public. Notation est le nom de la notation. Base et Pubid peuvent être indéfinis.

Notation (Expat, Notation, Base, Sysid, Pubid)

Ceci est appelé pour une déclaration de notation. Notation est le nom de la notation. Base est la base à utiliser pour résoudre une URI relative. Sysid est l'identifiant système. Pubid est l'identifiant public. Base, Sysid et Pubid peuvent tous être indéfinis.

ExternEnt (Expat, Base, Sysid, Pubid)

Ceci est appelé lorsqu'une entité externe est référencée. Base est la base à utiliser pour résoudre une URI relative. Sysid est l'identifiant système. Pubid est l'identifiant public. Base et Pubid peuvent être indéfinis.

Ce manipulateur doit soit renvoyer une chaîne qui représente le contenu de l'entité externe, soit renvoyer un descripteur de fichier ouvert qui peut être lu pour obtenir le contenu de l'entité externe, soit renvoyer undef, ce qui indique que l'entité externe n'a pas pu être trouvée et générera une erreur d'analyse.

Si un descripteur de fichier ouvert est renvoyé, il doit être renvoyé soit sous forme de glob (*FOO), soit sous forme de référence à un glob (par exemple, une instance de IO::Handle).

Un manipulateur par défaut est installé pour cet événement. Le manipulateur par défaut est XML::Parser::lwp_ext_ent_handler, à moins que l'option NoLWP n'ait été fournie avec une valeur vraie, sinon XML::Parser::file_ext_ent_handler est le manipulateur par défaut pour les entités externes. Même sans l'option NoLWP, si les modules URI ou LWP sont manquants, le manipulateur basé sur les fichiers finit par être utilisé après avoir émis un avertissement lors de la première référence à une entité externe.

Le manipulateur d'entités externes LWP utilisera les proxys définis dans l'environnement (http_proxy, ftp_proxy, etc.).

Veuillez noter que le manipulateur d'entités externes LWP lit l'intégralité de l'entité dans une chaîne et la renvoie, tandis que le manipulateur de fichiers ouvre un descripteur de fichier.

Notez également que le manipulateur d'entités externes de fichiers échouera probablement avec des URIs absolues ou des noms de fichiers qui ne correspondent pas aux conventions du système d'exploitation local.

La méthode de base d'expat peut être utilisée pour définir un nom de base pour les chemins relatifs. Si aucun nom de base n'est donné, ou si le nom de base est lui-même un nom relatif, alors il est relatif au répertoire de travail courant.

ExternEntFin (Expat)

Ceci est appelé après l'analyse d'une entité externe. Il n'est pas appelé sauf si un manipulateur ExternEnt est également défini. Il existe un manipulateur par défaut installé qui correspond au manipulateur ExternEnt par défaut.

Si vous installez votre propre manipulateur ExternEnt, vous devriez également définir (ou désactiver) ce manipulateur.

Entity (Expat, Nom, Val, Sysid, Pubid, Ndata, IsParam)

Ceci est appelé lorsqu'une entité est déclarée. Pour les entités internes, le paramètre Val contiendra la valeur et les trois paramètres restants seront indéfinis. Pour les entités externes, le paramètre Val sera indéfini, le paramètre Sysid contiendra l'identifiant système, le paramètre Pubid contiendra l'identifiant public s'il a été fourni (il sera indéfini sinon), le paramètre Ndata contiendra la notation pour les entités non analysées. S'il s'agit d'une déclaration d'entité paramètre, le paramètre IsParam est vrai.

Notez que ce manipulateur et le manipulateur Unparsed ci-dessus se chevauchent. Si les deux sont définis, ce manipulateur ne sera pas appelé pour les entités non analysées.

Element (Expat, Nom, Modèle)

Le manipulateur d'éléments est appelé lorsqu'une déclaration d'élément est trouvée. Nom est le nom de l'élément, et Modèle est le modèle de contenu en tant qu'objet XML::Parser::Content. Voir "Méthodes XML::Parser::ContentModel" dans XML::Parser::Expat pour les méthodes disponibles pour cette classe.

Attlist (Expat, NomEl, NomAtt, Type, Défaut, Fixe)

Ce manipulateur est appelé pour chaque attribut dans une déclaration ATTLIST. Ainsi, une déclaration ATTLIST comportant plusieurs attributs générera plusieurs appels à ce manipulateur. Le paramètre NomEl est le nom de l'élément auquel l'attribut est associé. Le paramètre NomAtt est le nom de l'attribut. Type est le type d'attribut, donné sous forme de chaîne. Défaut est la valeur par défaut, qui sera soit "#REQUIRED", soit "#IMPLIED", soit une chaîne entre guillemets (c'est-à-dire que la chaîne renvoyée commencera et se terminera par un guillemet). Si Fixe est vrai, alors il s'agit d'un attribut fixe.

Doctype (Expat, Nom, Sysid, Pubid, Interne)

Ce manipulateur est appelé pour les déclarations DOCTYPE. Nom est le nom du type de document. Sysid est l'identifiant système du type de document, s'il a été fourni, sinon il est indéfini. Pubid est l'identifiant public du type de document, qui sera indéfini si aucun identifiant public n'a été donné. Interne est le sous-ensemble interne, donné sous forme de chaîne. S'il n'y a pas eu de sous-ensemble interne, il sera indéfini. Interne contiendra tous les espaces blancs, commentaires, instructions de traitement et déclarations vécus dans le sous-ensemble interne. Les déclarations seront présentes que les déclarations aient été traitées ou non par un autre manipulateur (sauf pour les entités non analysées traitées par le manipulateur Unparsed). Cependant, les commentaires et les instructions de traitement n'apparaîtront pas s'ils ont été traités par leurs manipulateurs respectifs.

* DoctypeFin (Analyseur)

Ce manipulateur est appelé après la fin de l'analyse de la déclaration DOCTYPE, y compris toutes les déclarations DTD internes ou externes.

XMLDecl (Expat, Version, Encodage, Autonome)

Ce manipulateur est appelé pour les déclarations xml. Version est une chaîne contenant la version. Encodage est soit indéfini, soit contient une chaîne d'encodage. Autonome sera soit vrai, soit faux, soit indéfini si l'attribut autonome est oui, non, ou non spécifié respectivement.

STYLES

Debug

Ceci affiche simplement le document sous forme de plan. Rien de spécial n'est renvoyé par parse.

NAME

XML::Parser - A Perl extension for parsing XML documents

SYNOPSIS

use XML::Parser;
my $parser = new XML::Parser Options;
my $data   = $parser->parse("file.xml");
# or
my $data = $parser->parse_string($string);

DESCRIPTION

XML::Parser is a Perl interface to the Expat XML parsing library. It allows you to parse XML documents and respond to various parsing events.

METHODS

The following methods are available:

new XML::Parser (Options)
Creates a new XML::Parser object. Options is an optional hash of configuration options. The available options are:

:
The output style to use. Can be one of:

  • Tree (the default) - Returns a parse tree.
  • Objects - Returns a tree of objects.
  • Stream - Calls handler subroutines.
  • Subs - Calls handler subroutines with automatic name generation.

:
The package where handler subroutines reside. Defaults to the caller's package.

$:
A boolean flag. If set, warnings are generated for non-fatal errors.

$:
A boolean flag. If set, error messages include line numbers.

$:
An integer specifying the number of attribute values to retain. Defaults to 1000.

$:
A hash reference containing default namespace mappings.

parse_string (XML-document)
Parses the given XML document string and returns the result according to the style specified.
parse_from_file (filename)
Parses the XML document from the specified file and returns the result according to the style specified.
get_error
Returns a string describing the last error encountered during parsing.
set_element_limit (count)
Sets the maximum number of elements to parse. Returns the previous limit.
set_data_limit (count)
Sets the maximum amount of data (in bytes) to parse. Returns the previous limit.

HANDLERS

When using the Stream or Subs styles, the parser will call specific subroutines (handlers) to notify you of parsing events. These handlers are defined in the package specified by the Pkg option.

Subs

Each time an element starts, a sub by that name in the package specified by the Pkg option is called with the same parameters that the Start handler gets called with.

Each time an element ends, a sub with that name appended with an underscore ("_"), is called with the same parameters that the End handler gets called with.

Nothing special is returned by parse.

Tree

Parse will return a parse tree for the document. Each node in the tree takes the form of a tag, content pair. Text nodes are represented with a pseudo-tag of "0" and the string that is their content. For elements, the content is an array reference. The first item in the array is a (possibly empty) hash reference containing attributes. The remainder of the array is a sequence of tag-content pairs representing the content of the element.

So for example the result of parsing:

<foo><head id="a">Hello <em>there</em></head><bar>Howdy<ref/></bar>do</foo>

would be:

           Tag   Content
==================================================================
[foo, [{}, head, [{id => "a"}, 0, "Hello ",  em, [{}, 0, "there"]],
            bar, [         {}, 0, "Howdy",  ref, [{}]],
              0, "do"
      ]
]

The root document "foo", has 3 children: a "head" element, a "bar" element and the text "do". After the empty attribute hash, these are represented in it's contents by 3 tag-content pairs.

Objects

This is similar to the Tree style, except that a hash object is created for each element. The corresponding object will be in the class whose name is created by appending "::" and the element name to the package set with the Pkg option. Non-markup text will be in the ::Characters class. The contents of the corresponding object will be in an anonymous array that is the value of the Kids property for that object.

Stream

This style also uses the Pkg package. If none of the subs that this style looks for is there, then the effect of parsing with this style is to print a canonical copy of the document without comments or declarations. All the subs receive as their 1st parameter the Expat instance for the document they're parsing.

It looks for the following routines:

  • StartDocument

    Called at the start of the parse .

  • StartTag

    Called for every start tag with a second parameter of the element type. The $_ variable will contain a copy of the tag and the %_ variable will contain attribute values supplied for that element.

  • EndTag

    Called for every end tag with a second parameter of the element type. The $_ variable will contain a copy of the end tag.

  • Text

    Called just before start or end tags with accumulated non-markup text in the $_ variable.

  • PI

    Called for processing instructions. The $_ variable will contain a copy of the PI and the target and data are sent as 2nd and 3rd parameters respectively.

  • EndDocument

    Called at conclusion of the parse.

ENCODINGS

XML documents may be encoded in character sets other than Unicode as long as they may be mapped into the Unicode character set. Expat has further restrictions on encodings. Read the xmlparse.h header file in the expat distribution to see details on these restrictions.

Expat has built-in encodings for: "UTF-8", "ISO-8859-1", "UTF-16", and "US-ASCII". Encodings are set either through the XML declaration encoding attribute or through the ProtocolEncoding option to XML::Parser or XML::Parser::Expat.

For encodings other than the built-ins, expat calls the function load_encoding in the Expat package with the encoding name. This function looks for a file in the path list @XML::Parser::Expat::Encoding_Path, that matches the lower-cased name with a '.enc' extension. The first one it finds, it loads.

If you wish to build your own encoding maps, check out the XML::Encoding module from CPAN.
