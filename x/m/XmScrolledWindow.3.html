NOM

XmScrolledWindow — La classe de widget ScrolledWindow

SYNTAXE

#include <Xm/ScrolledW.h>

DESCRIPTION

Le widget ScrolledWindow combine une ou deux barres de défilement (ScrollBar) et une zone de visualisation pour implémenter une fenêtre visible sur un autre affichage de données (généralement plus grand). La partie visible de la fenêtre peut être déplacée sur le grand affichage à l'aide des barres de défilement.

Pour utiliser ScrolledWindow, une application crée d'abord un widget ScrolledWindow, les widgets ScrollBar nécessaires et un widget capable d'afficher les données souhaitées comme zone de travail de ScrolledWindow. ScrolledWindow positionne le widget de la zone de travail et affiche les ScrollBar si demandé. Lorsque l'utilisateur effectue une action sur la barre de défilement, l'application est informée via l'interface de rappel normale de la barre de défilement.

ScrolledWindow peut être configuré pour fonctionner automatiquement, de sorte qu'il effectue toutes les actions de défilement et d'affichage sans aucune intervention du programme applicatif. Il peut également être configuré pour fournir un cadre de support minimal dans lequel l'application est responsable du traitement de toutes les entrées utilisateur et de la réalisation de toutes les modifications visuelles des données affichées en réponse à cette entrée.

Lorsque ScrolledWindow effectue un défilement automatique, il crée une fenêtre de découpage et crée automatiquement les barres de défilement. Conceptuellement, cette fenêtre devient le viewport à travers lequel l'utilisateur examine la zone de données sous-jacente plus grande. L'application crée simplement les données souhaitées, puis fait de ces données la zone de travail du ScrolledWindow. Lorsque l'utilisateur déplace le curseur pour modifier les données affichées, l'espace de travail est déplacé sous la zone de visualisation afin qu'une nouvelle partie des données devienne visible.

Il est parfois peu pratique pour une application de créer un grand espace de données et de simplement l'afficher à travers une petite fenêtre de découpage. Par exemple, dans un éditeur de texte, créer une zone de données unique qui consiste en un gros fichier impliquerait une surcharge indésirable. L'application doit utiliser un ScrolledWindow (un petit viewport sur des données plus grandes), mais doit être informée lorsque l'utilisateur fait défiler le viewport afin qu'elle puisse importer davantage de données du stockage et mettre à jour la zone d'affichage. Pour ces cas, ScrolledWindow peut être configuré pour ne fournir qu'un support visuel de mise en page. Aucune fenêtre de découpage n'est créée, et l'application doit maintenir les données affichées dans la zone de travail, ainsi que répondre aux entrées utilisateur sur les barres de défilement.

L'utilisateur peut spécifier des ressources dans un fichier de ressources pour les widgets créés automatiquement qui contiennent les barres de défilement horizontales et verticales et la zone de découpage du widget ScrolledWindow. Les noms de ces widgets sont HorScrollBar, VertScrollBar et ClipWindow respectivement, et restent cohérents qu'ils soient créés par XmCreateScrolledList, XmCreateScrolledText ou XmCreateScrolledWindow.

ScrolledWindow utilise le trait XmQTnavigator et détient le trait XmQTscrollFrame.

Exemple

Cet exemple crée un widget ScrolledWindow avec une zone de travail qui contient une grande zone de texte.

#include <Xm/ScrolledW.h>
#include <Xm/Text.h>

Widget main_window, scrolled_window, text_widget;
Arg args[2];
int n;

/* Créer la fenêtre principale */
main_window = ... ;

/* Initialiser les arguments pour ScrolledWindow */
n = 0;
XtSetArg(args[n], XmNscrollingPolicy, XmAUTOMATIC); n++;
XtSetArg(args[n], XmNworkWindow, text_widget); n++;

/* Créer le ScrolledWindow */
scrolled_window = XmCreateScrolledWindow(main_window, "scrolled_window", args, n);
XtManageChild(scrolled_window);

/* Créer la zone de texte qui sera la zone de travail */
n = 0;
text_widget = XmCreateText(scrolled_window, "text_widget", args, n);
/* (Code pour remplir la zone de texte avec des données) */
XtManageChild(text_widget);

/* Associer la zone de travail au ScrolledWindow */
XmScrolledWindowSetAreas(scrolled_window, NULL, NULL, text_widget);

XmNautoDragModel
Indique si le glisser-déposer automatique est activé (XmAUTO_DRAG_ENABLED) ou désactivé (XmAUTO_DRAG_DISABLED). Par défaut, il est activé.
XmNclipWindow
Spécifie l'identifiant du widget de la zone de découpage. Il est automatiquement créé par ScrolledWindow lorsque la ressource XmNvisualPolicy est définie sur XmCONSTANT et ne peut être lu que par l'application. Toute tentative de définir cette ressource sur une nouvelle valeur entraîne l'affichage d'un message d'avertissement par la fenêtre à défilement. Si la ressource XmNvisualPolicy est définie sur XmVARIABLE, cette ressource est définie sur NULL et aucune fenêtre de découpage n'est créée.
XmNhorizontalScrollBar
Spécifie l'identifiant du widget de la barre de défilement horizontale. Elle est automatiquement créée par ScrolledWindow lorsque XmNscrollingPolicy est initialisé à XmAUTOMATIC ; sinon, la valeur par défaut est NULL.
XmNscrollBarDisplayPolicy
Contrôle le placement automatique des barres de défilement. Si elle est définie sur XmAS_NEEDED et si XmNscrollingPolicy est défini sur XmAUTOMATIC, les barres de défilement ne sont affichées que si l'espace de travail dépasse la zone de découpage dans une ou deux dimensions. Une valeur de ressource XmSTATIC entraîne l'affichage des barres de défilement par ScrolledWindow chaque fois qu'elles sont gérées, indépendamment de la relation entre la fenêtre de découpage et la zone de travail. Cette ressource doit être XmSTATIC lorsque XmNscrollingPolicy est XmAPPLICATION_DEFINED. La valeur par défaut est XmAS_NEEDED lorsque XmNscrollingPolicy est XmAUTOMATIC, et XmSTATIC sinon.
XmNscrollBarPlacement
Spécifie le positionnement des barres de défilement par rapport à la fenêtre de travail. Les valeurs sont :
XmTOP_LEFT
La barre de défilement horizontale est placée au-dessus de la fenêtre de travail ; la barre de défilement verticale est placée à gauche.
XmBOTTOM_LEFT
La barre de défilement horizontale est placée en dessous de la fenêtre de travail ; la barre de défilement verticale est placée à gauche.
XmTOP_RIGHT
La barre de défilement horizontale est placée au-dessus de la fenêtre de travail ; la barre de défilement verticale est placée à droite.
XmBOTTOM_RIGHT
La barre de défilement horizontale est placée en dessous de la fenêtre de travail ; la barre de défilement verticale est placée à droite.
La valeur par défaut dépend de la valeur de la ressource XmNlayoutDirection du widget.
XmNscrolledWindowMarginHeight
Spécifie la hauteur de la marge en haut et en bas de la ScrolledWindow. Pour utiliser la fonctionnalité de glisser-déposer automatique de la fonction de glisser-déposer de Motif, un utilisateur doit pouvoir maintenir une icône de glisser-déposer au-dessus de la marge d'une fenêtre à défilement. Bien que le glisser-déposer fonctionne avec une taille de marge par défaut de zéro, un utilisateur peut trouver difficile de positionner l'icône avec suffisamment de précision pour utiliser la fonctionnalité facilement. Le programmeur de l'application doit s'assurer que les marges de la fenêtre sont définies sur une taille adéquate si l'utilisation de la fonctionnalité de glisser-déposer automatique est souhaitée.
XmNscrolledWindowMarginWidth
Spécifie la largeur de la marge sur les côtés droit et gauche de la ScrolledWindow. Veuillez vous référer à l'avertissement concernant la taille de marge par défaut pour la ressource XmNscrolledWindowMarginHeight, ci-dessus.
XmNscrollingPolicy
Effectue un défilement automatique de la zone de travail sans interaction de l'application. Si la valeur de cette ressource est XmAUTOMATIC, ScrolledWindow crée automatiquement les barres de défilement ; attache des rappels aux barres de défilement ; définit la politique visuelle sur XmCONSTANT ; et déplace automatiquement la zone de travail à travers la fenêtre de découpage en réponse à toute interaction utilisateur avec les barres de défilement. Une application peut également ajouter ses propres rappels aux barres de défilement. Cela permet à l'application d'être informée d'un événement de défilement sans avoir à effectuer de procédures de mise en page.
REMARQUE : Étant donné que ScrolledWindow ajoute des rappels aux barres de défilement, une application ne doit pas effectuer d'appel XtRemoveAllCallbacks sur l'un des widgets de barre de défilement.
Lorsque XmNscrollingPolicy est défini sur XmAPPLICATION_DEFINED, l'application est responsable de tous les aspects du défilement. Les barres de défilement doivent être créées par l'application, et celle-ci est responsable de l'exécution de toute modification visuelle dans la zone de travail en réponse à l'entrée utilisateur.
Cette ressource doit être définie sur la politique souhaitée au moment de la création de la ScrolledWindow. Elle ne peut pas être modifiée via SetValues.
XmNspacing
Spécifie la distance qui sépare les barres de défilement de la fenêtre de travail.
XmNtraverseObscuredCallback
Spécifie une liste de rappels qui est appelée lors de la traversée vers un widget ou un gadget qui est obscurci en raison de sa position dans la zone de travail par rapport à l'emplacement de la fenêtre d'affichage de la ScrolledWindow. Cette ressource n'est valide que lorsque XmNscrollingPolicy est XmAUTOMATIC. Si cette ressource est NULL, un widget obscurci ne peut pas être traversé. La raison du rappel est XmCR_OBSCURED_TRAVERSAL.
XmNverticalScrollBar
Spécifie l'identifiant du widget de la barre de défilement verticale. Elle est automatiquement créée par ScrolledWindow lorsque XmNscrollingPolicy est initialisé à XmAUTOMATIC ; sinon, la valeur par défaut est NULL.
XmNvisualPolicy
Agrandit la ScrolledWindow pour qu'elle corresponde à la taille de la zone de travail. Elle peut également être utilisée comme une fenêtre d'affichage statique sur un espace de données plus grand. Si la politique visuelle est XmVARIABLE, la ScrolledWindow force les barres de défilement

RESOURCES

The XmScrolledWindow widget has the following resources in addition to the default values for the superclasses listed in X(1). The summary table spec ifies the calling sequence, widget class, and default value. The detailed descriptions are in subsequent subsections.

XmNscrollingPolicy
Determines how the widget scrolls. The possible values are:
XmCONSTANT
The work area is clipped to the size of the ScrolledWindow widget. The ScrolledWindow widget remains a fixed size and does not change dynamically. When the policy is XmCONSTANT, the work area grows or shrinks as requested, but a clipping window forces the size of the visible portion to remain constant. The only time the viewing area can grow is in response to a resize from the ScrolledWindow's parent. The default is XmCONSTANT when XmNscrollingPolicy is XmAUTOMATIC, and XmVARIABLE otherwise.
XmSTATIC
The ScrolledWindow widget resizes to match the size of the work area. The XmSTATIC policy corresponds to the XmSTATIC display policy to XmSTATIC and allows the work area to grow or shrink at any time and adjusts its layout to accommodate the new size.
XmVARIABLE
The ScrolledWindow widget resizes to match the size of the work area. The default is XmCONSTANT when XmNscrollingPolicy is XmAUTOMATIC, and XmVARIABLE otherwise.
NOTE: This resource must be set to the desired policy at the time the ScrolledWindow is created. It cannot be changed through SetValues.
XmNworkWindow
Specifies the widget ID of the viewing area.
