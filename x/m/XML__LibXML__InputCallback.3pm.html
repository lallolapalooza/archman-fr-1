NOM

XML::LibXML::InputCallback - Classe XML::LibXML pour les rappels d'entrée

SYNOPIS

use XML::LibXML;

DESCRIPTION

Vous pourriez obtenir des résultats inattendus si vous essayez de charger des documents externes lors de l'analyse libxml2 si l'emplacement de la ressource n'est pas une URL HTTP, FTP ou un emplacement relatif, mais un chemin absolu par exemple. Pour contourner cette limitation, vous pouvez ajouter votre propre gestionnaire d'entrée pour ouvrir, lire et fermer des types particuliers d'emplacements ou de classes d'URI. En utilisant ces gestionnaires de rappel d'entrée, vous pouvez gérer vos propres schémas d'URI personnalisés par exemple.

Les rappels d'entrée sont utilisés chaque fois que XML::LibXML doit obtenir autre chose que des entités externes analysées à partir de quelque part. Ils sont implémentés à l'aide d'une pile de rappels au niveau Perl, par analogie avec la pile de rappels native de libxml2.

La classe XML::LibXML::InputCallback enregistre de manière transparente les rappels d'entrée pour les processus d'analyse de libxml2.

Comment fonctionne XML::LibXML::InputCallback ?

La bibliothèque libxml2 offre une implémentation de rappel sous forme de fonctions globales uniquement. Pour contourner les problèmes résultant de n'avoir que des rappels globaux - par exemple, si la même pile de rappels globale est manipulée par différentes applications s'exécutant ensemble dans un seul environnement de serveur Web Apache -, XML::LibXML::InputCallback est livré avec une partie orientée objet et une partie orientée fonction.

En utilisant la partie orientée fonction, la pile de rappels globale de libxml2 peut être manipulée. Ces fonctions peuvent être utilisées comme interface pour les rappels au niveau C et XS. Dans la partie orientée objet, les opérations de travail avec la pile de rappels "pseudo-localisée" sont implémentées. Actuellement, vous pouvez enregistrer et désenregistrer des rappels au niveau Perl et les initialiser par analyseur.

Groupes de rappels

Les rappels d'entrée libxml2 sont regroupés. Un groupe contient un moteur de recherche d'URI (match), un constructeur de flux de données (open), un lecteur de flux de données (read) et un destructeur de flux de données (close). Les rappels peuvent être manipulés uniquement par groupe.

Le processus d'analyse

Le processus d'analyse fonctionne sur un flux de données XML, le long duquel, des liens vers d'autres ressources peuvent être intégrés. Il peut s'agir de liens vers des DTD externes ou des XIncludes par exemple. Ces ressources sont identifiées par des URI. L'implémentation de rappel de libxml2 suppose qu'un groupe de rappels peut gérer une certaine quantité d'URI et un certain schéma d'URI. Par défaut, des gestionnaires de rappels pour file://*, file:://*.gz, http://* et ftp://* sont enregistrés.

Les groupes de rappels dans la pile de rappels sont traités de haut en bas, ce qui signifie que les groupes de rappels enregistrés plus tard seront traités avant ceux enregistrés précédemment.

Lors de l'analyse du flux de données, l'analyseur libxml2 vérifie si un groupe de rappels enregistré gérera une URI - s'il ne le fait pas, l'URI sera interprétée comme file://URI. Pour gérer une URI, le rappel match devra retourner '1'. Si cela se produit, la gestion de l'URI sera transmise à ce groupe de rappels. Ensuite, l'URI sera passée au rappel open, qui devrait retourner une référence au flux de données s'il a réussi à ouvrir le fichier, '0' sinon. Si l'ouverture du flux a réussi, le rappel read sera appelé à plusieurs reprises jusqu'à ce qu'il retourne une chaîne vide. Après le rappel de lecture, le rappel close sera appelé pour fermer le flux.

Organisation des groupes de rappels dans XML::LibXML::InputCallback

Les groupes de rappels sont implémentés sous forme de pile (tableau), chaque entrée contient une référence à un tableau de rappels. Pour la bibliothèque libxml2, l'implémentation de rappel XML::LibXML::InputCallback apparaît comme un seul groupe de rappels. Cependant, l'implémentation Perl permet de gérer différentes piles de rappels par analyseur libxml2.

Utilisation de XML::LibXML::InputCallback

Après l'instanciation de l'objet à l'aide du constructeur sans paramètre, vous pouvez enregistrer des groupes de rappels.

my $input_callbacks = XML::LibXML::InputCallback->new();
$input_callbacks->register_callbacks([ $match_cb1, $open_cb1,
                                       $read_cb1, $close_cb1 ] );
$input_callbacks->register_callbacks([ $match_cb2, $open_cb2,
                                       $read_cb2, $close_cb2 ] );
$input_callbacks->register_callbacks( [ $match_cb3, $open_cb3,
                                        $read_cb3, $close_cb3 ] );
$parser->input_callbacks( $input_callbacks );
$parser->parse_file( $some_xml_file );

Qu'en est-il de l'ancien système de rappel avant XML::LibXML::InputCallback ?

Dans les versions de XML::LibXML antérieures à 1.59 - c'est-à-dire sans le module XML::LibXML::InputCallback - vous pouviez définir vos rappels globalement ou localement. Vous pouvez toujours le faire en utilisant XML::LibXML::InputCallback, et en plus de cela, vous pouvez définir les rappels par analyseur !

Si vous utilisez l'ancienne interface de rappel via des rappels globaux, XML::LibXML::InputCallback les traitera avec une priorité inférieure à ceux enregistrés à l'aide de la nouvelle interface. Les rappels globaux ne remplaceront pas les groupes de rappels enregistrés à l'aide de la nouvelle interface. Les rappels locaux sont attachés à une instance d'analyseur spécifique, ils sont donc traités avec la priorité la plus élevée. Si le rappel match du groupe de rappels enregistré en tant que variable locale est identique à l'un des groupes de rappels enregistrés à l'aide de la nouvelle interface, ce groupe de rappels sera remplacé.

Les utilisateurs de l'ancienne implémentation de rappel dont le rappel open retournait une chaîne simple devront adapter leur code pour retourner une référence à cette chaîne après la mise à niveau vers la version >= 1.59. Le nouveau système de rappel ne peut fonctionner qu'avec le rappel open retournant une référence !

DESCRIPTION DE L'INTERFACE

Variables globales

$_CUR_CB
Stocke le rappel actuel et peut être utilisé comme raccourci pour accéder à la pile de rappels.
@_GLOBAL_CALLBACKS
Stocke tous les groupes de rappels pour le processus d'analyse actuel.
@_CB_STACK
Stocke le groupe de rappels actuellement utilisé. Utilisé pour éviter les erreurs d'analyse lors du traitement de données XML imbriquées.

Callbacks globaux

_callback_match
Implémente l'interface pour le rappel match au niveau C et pour la sélection du groupe de rappels parmi les rappels définis au niveau Perl.
_callback_open
Transmet le rappel open de libxml2 à la fonction de rappel correspondante au niveau Perl.
_callback_read
Transmet la demande de lecture à la fonction de rappel correspondante au niveau Perl et retourne le résultat à libxml2.
_callback_close
Transmet le rappel close de libxml2 à la fonction de rappel correspondante au niveau Perl.

Méthodes de classe

new()
Un constructeur simple.
register_callbacks( [ $match_cb, $open_cb, $read_cb, $close_cb ])
Les quatre rappels doivent être donnés sous forme de référence de tableau dans l'ordre ci-dessus : match, open, read, close !
unregister_callbacks( [ $match_cb, $open_cb, $read_cb, $close_cb ])
Sans arguments, unregister_callbacks() supprimera le dernier groupe de rappels enregistré de la pile. Si quatre rappels sont passés sous forme de référence de tableau, le groupe de rappels à désenregistrer sera identifié par le rappel match et supprimé de la pile de rappels. EXEMPLE DE RAPPELS

L'exemple suivant est un exemple purement fictif qui utilise un objet MyScheme::Handler qui répond à des méthodes similaires à un objet IO::Handle.

# Définir les quatre fonctions de rappel
sub match_uri {
    my $uri = shift;
    return $uri =~ /^myscheme:/; # déclencher notre groupe de rappels pour les URI 'myscheme'
}
sub open_uri {
    my $uri = shift;
    my $handler = MyScheme::Handler->new($uri);
    return $handler;
}
# Le $buffer retourné sera analysé par l'analyseur libxml2
sub read_uri {
    my $handler = shift;
    my $length = shift;
    my $buffer;
    read($handler, $buffer, $length);
    return $buffer; # $buffer sera une chaîne vide '' si read() est terminé
}
# Fermer le handle associé à la ressource.
sub close_uri {
    my $handler = shift;
    close($handler);
}
# Les enregistrer avec une instance de XML::LibXML::InputCallback
my $input_callbacks = XML::LibXML::InputCallback->new();
$input_callbacks->register_callbacks([ \&match_uri, \&open_uri,
                                       \&read_uri, \&close_uri ] );
# Enregistrer le groupe de rappels auprès d'une instance de l'analyseur
$parser->input_callbacks( $input_callbacks );
# $some_xml_file sera analysé en utilisant nos rappels
$parser->parse_file( $some_xml_file );
