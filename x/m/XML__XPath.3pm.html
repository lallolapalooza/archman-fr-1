XML::XPath(3) Documentation Perl Contribuée par l'Utilisateur XML::XPath(3)

NOM

XML::XPath - Analyse et évalue des instructions XPath.

VERSION

Version 1.48

DESCRIPTION

Ce module vise à respecter exactement la spécification XPath à l'adresse http://www.w3.org/TR/xpath et pourtant à permettre l'ajout d'extensions sous forme de fonctions. Des modules comme XSLT et XPointer pourraient avoir besoin de faire cela car ils prennent en charge des fonctionnalités au-delà de XPath.

SYNTAXE

use XML::XPath;
use XML::XPath::XMLParser;
my $xp = XML::XPath->new(filename => 'test.xhtml');
my $nodeset = $xp->find('/html/body/p'); # trouver tous les paragraphes
foreach my $node ($nodeset->get_nodelist) {
    print "TROUVÉ\n\n",
        XML::XPath::XMLParser::as_string($node),
        "\n\n";
}

DETAILS

Il y a beaucoup à comprendre dans tout cela, alors soyez patient - si vous persévérez, cela devrait en valoir la peine. Veuillez acquérir une bonne compréhension de XPath en lisant la spécification avant de me poser des questions. Toutes les classes et parties ici présentes sont nommées de manière à être synonymes des noms de la spécification, alors consultez celle-ci si vous ne comprenez pas pourquoi je fais quelque chose dans le code.

Actuellement, il prend en charge XPath 1.0 avec un petit nombre de fonctions XPath 2.0. Voir XML::XPath::Function pour la liste complète des fonctions prédéfinies.

MÉTHODES

L'API de XML::XPath elle-même est extrêmement simple pour vous permettre de commencer presque immédiatement. Les API plus profondes sont plus complexes, mais vous ne devriez pas avoir à toucher la majeure partie de cela.

new()

Ce constructeur suit la méthode courante d'appel de paramètres nommés. Les paramètres que vous pouvez utiliser sont : filename, parser, xml, ioref et context. Le paramètre filename spécifie un fichier XML à analyser. Le paramètre xml spécifie une chaîne à analyser, et le paramètre ioref spécifie un ioref à analyser. L'option context vous permet de spécifier un nœud de contexte. Le nœud de contexte doit être au format d'un nœud tel que spécifié dans XML::XPath::XMLParser. Les 4 paramètres filename, xml, ioref et context sont mutuellement exclusifs - vous ne devriez en spécifier qu'un seul (si vous spécifiez autre chose que context, le nœud de contexte est la racine de votre document). L'option parser vous permet de passer un objet XML::Parser déjà préparé, pour vous éviter de créer plus d'un objet dans votre application (si, par exemple, vous faites plus que juste XPath).

my $xp = XML::XPath->new( context => $node );

Il est fortement recommandé de n'utiliser qu'un seul objet XPath tout au long de la vie de votre application. En effet, l'objet (et ses sous-objets) maintient certaines informations d'état qui seront utiles (telles que les variables XPath) pour les appels ultérieurs à find(). C'est aussi une bonne idée car vous utiliserez moins de mémoire de cette façon.

trouver($chemin, [$contexte])

La fonction find prend une expression XPath (une chaîne) et renvoie soit un objet XML::XPath::NodeSet contenant les nœuds trouvés (ou vide si aucun nœud ne correspond au chemin), soit l'un de XML::XPath::Literal (une chaîne), XML::XPath::Number ou XML::XPath::Boolean. Elle devrait toujours renvoyer quelque chose - et vous pouvez utiliser ->isa() pour savoir ce qu'elle a renvoyé. Si vous devez vérifier combien de nœuds elle a trouvés, vous devriez vérifier $nodeset->size. Voir XML::XPath::NodeSet. Un deuxième paramètre optionnel d'un nœud de contexte vous permet d'utiliser cette méthode de manière répétée, par exemple XSLT doit le faire.

trouvernœuds($chemin, [$contexte])

Renvoie une liste de nœuds trouvés par $chemin, éventuellement dans le contexte $contexte. En contexte scalaire, renvoie un objet XML::XPath::NodeSet.

correspond($nœud, $chemin, [$contexte])

Renvoie vrai si le nœud correspond au chemin (éventuellement dans le contexte $contexte).

trouvernœuds_en_chaîne($chemin, [$contexte])

Renvoie les nœuds trouvés reproduits sous forme XML. Le résultat n'est cependant pas garanti d'être un XML valide.

trouvervaleur($chemin, [$contexte])

Renvoie soit un objet "XML::XPath::Literal", soit un objet "XML::XPath::Boolean", soit un objet "XML::XPath::Number". Si le chemin renvoie un NodeSet, $nodeset->to_literal est appelé automatiquement pour vous (et donc un "XML::XPath::Literal" est renvoyé). Notez que pour chacun des objets, la stringification est surchargée, vous pouvez donc simplement imprimer la valeur trouvée, ou la manipuler comme vous le feriez avec une valeur perl normale (par exemple, en utilisant des expressions régulières).

existe($chemin, [$contexte])

Renvoie vrai si le chemin donné existe.

obtenirTexteNœud($chemin)

Renvoie XML::XPath::Literal pour un nœud XML particulier. Renvoie une chaîne si elle existe ou '' (chaîne vide) si le nœud n'existe pas.

définirTexteNœud($chemin, $texte)

Définit la chaîne de texte pour un nœud XML particulier. Le nœud peut être un élément ou un attribut. Si le nœud à définir est un attribut et que le nœud attribut n'existe pas, il sera créé automatiquement.

créerNœud($chemin)

Crée le nœud correspondant au $chemin donné. Si une partie du chemin donné ou tout le chemin n'existe pas, les nœuds nécessaires seront créés automatiquement.

définir_espace_nom($préfixe, $uri)

Définit le mappage du préfixe d'espace de noms à l'uri.

Normalement dans "XML::XPath" les préfixes dans le test de nœud XPath tirent leur contexte du nœud courant. Cela signifie que foo:bar correspondra toujours à un élément <foo:bar> quel que soit l'espace de noms auquel le préfixe foo est mappé (qui pourrait même changer dans le document, entraînant des résultats inattendus). Afin que les préfixes dans les tests de nœud XPath correspondent réellement à un URI réel, vous devez l'activer via un appel à la méthode set_namespace de votre objet "XML::XPath".

clear_namespaces()

Efface tous les mappages d'espaces de noms précédemment définis.

$XML::XPath::Namespaces

Définissez ceci sur 0 si vous ne voulez pas que le traitement des espaces de noms se produise. Cela rendra tout un peu (très peu) plus rapide, mais vous en souffrirez probablement.

Modèle Objet Nœud

Voir XML::XPath::Node, XML::XPath::Node::Element, XML::XPath::Node::Text, XML::XPath::Node::Comment, XML::XPath::Node::Attribute, XML::XPath::Node::Namespace, et XML::XPath::Node::PI.

Sur la Collecte des Déchets

Les nœuds XPath fonctionnent d'une manière spéciale qui permet des références circulaires, tout en permettant au collecteur de déchets de comptage de références de Perl de nettoyer les nœuds après utilisation. Cela devrait être totalement transparent pour l'utilisateur, à une seule exception : SI VOUS LIBÉREZ VOTRE ARBRE AVANT DE VOUS DÉBARRASSER D'UN SOUS-ARBRE, CONSIDÉREZ QUE VOUS JOUEZ AVEC LE FEU ET QUE VOUS POURRIEZ VOUS BRÛLER. Qu'est-ce que cela signifie pour l'utilisateur moyen ? Pas grand-chose. Tant que vous ne libérez pas (ou ne vous débarrassez pas de l'objet XPath principal ou ne laissez pas l'objet Perl lui-même être détruit) d'une manière ou d'une autre, tout ira bien.
