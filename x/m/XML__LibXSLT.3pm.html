NOM

XML::LibXSLT - Interface à la bibliothèque GNOME libxslt

SYNOPIS

use XML::LibXSLT;
use XML::LibXML;
my $xslt = XML::LibXSLT->new();
my $source = XML::LibXML->load_xml(location => 'foo.xml');
my $style_doc = XML::LibXML->load_xml(location=>'bar.xsl', no_cdata=>1);
my $stylesheet = $xslt->parse_stylesheet($style_doc);
my $results = $stylesheet->transform($source);
print $stylesheet->output_as_bytes($results);

DESCRIPTION

Ce module est une interface à libxslt du projet GNOME. C'est un moteur XSLT extrêmement performant, hautement conforme et également très rapide. J'ai des tests montrant qu'il est plus de deux fois plus rapide que Sablotron.

OPTIONS

XML::LibXSLT possède quelques options globales. Notez qu'elles ne sont probablement pas sûres pour les threads ou même le fork - ne les définissez donc qu'une seule fois par processus. Chacune de ces options peut être appelée soit en tant que méthodes de classe, soit en tant que méthodes d'instance. Cependant, quelle que soit la manière dont vous les appelez, elles définissent toujours des options globales.

Chacune des méthodes d'option retourne sa valeur précédente, et peut être appelée sans paramètre pour récupérer la valeur actuelle.

max_depth
XML::LibXSLT->max_depth(1000);

Cette option définit la profondeur de récursion maximale pour une feuille de style. Voir la toute fin de la section 5.4 de la spécification XSLT pour plus de détails sur la récursion et sa détection. Si votre feuille de style ou votre fichier XML nécessite une récursion sérieusement profonde, c'est ainsi que vous la définissez. La valeur par défaut est 250.

max_vars
XML::LibXSLT->max_vars(100_000);

Cette option définit le nombre maximal de variables pour une feuille de style. Si votre feuille de style ou votre fichier XML nécessite de nombreuses variables, c'est ainsi que vous augmentez leur limite. La valeur par défaut est spécifique au système et peut varier.

debug_callback
XML::LibXSLT->debug_callback($subref);

Définit une fonction de rappel à utiliser pour les messages de débogage. Si vous ne définissez pas cela, les messages de débogage seront ignorés.

register_function
XML::LibXSLT->register_function($uri, $name, $subref);
$stylesheet->register_function($uri, $name, $subref);

Enregistre une fonction d'extension XSLT mappée à l'URI donné. Par exemple:

XML::LibXSLT->register_function("urn:foo", "bar",
  sub { scalar localtime });

Enregistrera une fonction "bar" dans l'espace de noms "urn:foo" (que vous devez définir dans votre XSLT en utilisant "xmlns:...") qui retournera la date et l'heure actuelles sous forme de chaîne de caractères:

<xsl:stylesheet version="1.0"
  xmlns:xsl="http://www.w3.org/1999/XSL/Transform"
  xmlns:foo="urn:foo">
<xsl:template match="/">
  The time is: <xsl:value-of select="foo:bar()"/>
</xsl:template>
</xsl:stylesheet>

Les paramètres peuvent être dans n'importe quel format de votre choix. Si vous passez une liste de nœuds, ce sera un objet XML::LibXML::NodeList dans votre code Perl, mais les valeurs ordinaires (chaînes, nombres et booléens) seront des scalaires Perl ordinaires. Si vous souhaitez qu'ils soient des valeurs "XML::LibXML::Literal", "XML::LibXML::Number" et "XML::LibXML::Number" respectivement, alors définissez la variable $XML::LibXSLT::USE_LIBXML_DATA_TYPES à une valeur vraie. Les valeurs de retour peuvent être une liste de nœuds ou une valeur simple - le code fera simplement la bonne chose. Mais seule une valeur de retour unique est supportée (une liste n'est pas convertie en liste de nœuds).

register_element
$stylesheet->register_element($uri, $name, $subref)

Enregistre un élément d'extension XSLT $name mappé à l'URI donné. Par exemple:

$stylesheet->register_element("urn:foo", "hello", sub {
        my $name = $_[2]->getAttribute( "name" );
        return XML::LibXML::Text->new( "Hello, $name!" );
});

Enregistrera un élément "hello" dans l'espace de noms "urn:foo" qui retourne un nœud de texte "Hello, X!". Vous devez définir cet espace de noms dans votre XSLT et inclure son préfixe dans la liste "extension-element-prefixes":

<xsl:stylesheet version="1.0"
  xmlns:xsl="http://www.w3.org/1999/XSL/Transform"
  xmlns:foo="urn:foo"
      extension-element-prefixes="foo">
<xsl:template match="/">
  <foo:hello name="bob"/>
</xsl:template>
</xsl:stylesheet>

La fonction de rappel reçoit le nœud du document d'entrée en tant que $_[1] et le nœud de la feuille de style en tant que $_[2]. $_[0] est réservé pour une utilisation future.

API

Les méthodes suivantes sont disponibles sur le nouvel objet XML::LibXSLT :

parse_stylesheet($stylesheet_doc)
$stylesheet_doc est ici un objet XML::LibXML::Document (voir XML::LibXML) représentant un fichier XSLT. Cette méthode retournera un objet XML::LibXSLT::Stylesheet, ou undef en cas d'échec. Si le XSLT est invalide, une exception sera levée, donc entourez l'appel à parse_stylesheet d'un bloc eval{} pour le piéger.

IMPORTANT : $stylesheet_doc ne doit pas contenir de sections CDATA, sinon libxslt pourrait mal se comporter. La meilleure façon de s'en assurer est de charger la feuille de style avec l'indicateur no_cdata, par exemple.

my $stylesheet_doc = XML::LibXML->load_xml(location=>"some.xsl", no_cdata=>1);
parse_stylesheet_file($filename)
Exactement la même chose que ci-dessus, mais analyse directement le nom de fichier donné.

Callbacks d'entrée

Pour définir des callbacks d'entrée spécifiques à XML::LibXSLT ou XML::LibXSLT::Stylesheet, réutilisez l'API de callback d'entrée de XML::LibXML telle que décrite dans XML::LibXML::InputCallback(3).

input_callbacks($icb)
Active les callbacks dans $icb uniquement pour cet objet XML::LibXSLT. $icb doit être un objet "XML::LibXML::InputCallback". Cela appellera "init_callbacks" et "cleanup_callbacks" automatiquement pendant l'analyse ou la transformation.

Callbacks de sécurité

Pour créer des préférences de sécurité pour la transformation, voir XML::LibXSLT::Security. Une fois les préférences de sécurité définies, vous pouvez les appliquer à une instance XML::LibXSLT ou XML::LibXSLT::Stylesheet en utilisant la méthode security_callbacks().

XML::LibXSLT::Stylesheet

L'API principale se trouve sur la feuille de style, bien qu'elle soit assez minimale.

L'un des principaux avantages de XML::LibXSLT est que vous disposez d'un objet feuille de style générique auquel vous appelez la méthode transform() en passant un document à transformer. Cela vous permet d'effectuer plusieurs transformations avec une seule feuille de style sans nécessiter de re-parsing.

transform(doc, %params)
my $results = $stylesheet->transform($doc, foo => "'bar'");
print $stylesheet->output_as_bytes($results);

Transforme le document XML::LibXML::Document

t objet, et renvoie un nouveau XML::LibXML::Document. Les entrées de hachage supplémentaires sont utilisées comme paramètres. Assurez-vous de garder à l'esprit la mise en garde concernant les guillemets expliquée dans la section "Paramètres" ci-dessous.

transform_file(filename, %params)
my $results = $stylesheet->transform_file($filename, bar => "'baz'");

Notez la mise en garde concernant les paramètres de chaîne, détaillée dans la section "Paramètres" ci-dessous.

output_as_bytes(result)
Renvoie une scalaire qui est le rendu XSLT de l'objet XML::LibXML::Document en utilisant le format de sortie désiré (spécifié dans la balise xsl:output de la feuille de style). Notez que vous pouvez également appeler $result->toString, mais cela affichera *toujours* le document au format XML, ce qui peut ne pas être ce que vous avez demandé dans la balise xsl:output. La scalaire est une chaîne d'octets encodée dans l'encodage de sortie spécifié dans la feuille de style.
output_as_chars(result)
Similaire à output_as_bytes(result), mais renvoie toujours la sortie sous forme de chaîne de caractères (encodée en UTF-8).
output_string(result)
OBSOLÈTE : Cette méthode se situe entre output_as_bytes(result) et output_as_bytes(result) : La scalaire renvoyée par cette fonction apparaît à Perl comme des caractères (drapeau UTF8 activé) si l'encodage de sortie spécifié dans la feuille de style XSLT était UTF-8 et comme des octets si aucun encodage de sortie n'a été spécifié ou si l'encodage de sortie était différent de UTF-8. Étant donné que le comportement de cette fonction dépend de la feuille de style particulière, elle est obsolète au profit de output_as_bytes(result) et output_as_chars(result).
output_fh(result, fh)
Affiche le résultat dans le descripteur de fichier donné dans $fh.
output_file(result, filename)
Affiche le résultat dans le fichier nommé dans $filename.
output_encoding()
Renvoie l'encodage de sortie des résultats. Par défaut, "UTF-8".
output_method()
Renvoie la valeur de l'attribut "method" de "xsl:output" (généralement "xml", "html" ou "text"). Si cet attribut n'est pas spécifié, la valeur par défaut est initialement "xml". Si la méthode de transformation est utilisée pour produire un document HTML, conformément à la spécification XSLT http://www.w3.org/TR/xslt#output, la valeur par défaut passera à "html". Pour outrepasser complètement ce comportement, fournissez un élément "xsl:output" dans le document source de la feuille de style.
media_type()
Renvoie la valeur de l'attribut "media-type" de "xsl:output". Si cet attribut n'est pas spécifié, le type de média par défaut est initialement "text/xml". Cette valeur par défaut passe à "text/html" dans les mêmes conditions que output_method.
input_callbacks($icb)
Active les rappels dans $icb uniquement pour cette feuille de style. $icb doit être un objet "XML::LibXML::InputCallback". Cela appellera "init_callbacks" et "cleanup_callbacks" automatiquement pendant la transformation.
transform_into_chars(doc, %params)
Combine transform() et output_as_chars().

(Ajouté dans la version 2.0000 .)

Paramètres

LibXSLT attend les paramètres au format XPath. C'est-à-dire, si vous souhaitez passer une chaîne de caractères au moteur XSLT, vous devez en fait la passer comme une chaîne entre guillemets :

$stylesheet->transform($doc, param => "'string'");

Notez les guillemets dans les guillemets !

Évidemment, ce n'est pas très amusant, vous pouvez donc vous faciliter la tâche :

$stylesheet->transform($doc, XML::LibXSLT::xpath_to_string(
      param => "string"
      ));

La fonction utilitaire fait ce qu'il faut concernant les chaînes de caractères en XPath, y compris lorsque vous avez déjà des guillemets intégrés dans votre chaîne.

XML::LibXSLT::Security

Fournit une interface au framework de sécurité libxslt en permettant de définir des rappels qui peuvent restreindre l'accès à diverses ressources (fichiers ou URL) pendant une transformation.

Le framework de sécurité libxslt permet de définir des rappels pour certaines actions qu'une feuille de style peut tenter pendant une transformation. Il peut être souhaitable de restreindre certaines de ces actions (par exemple, écrire un nouveau fichier en utilisant exsl:document). Les actions qui peuvent être restreintes sont :

read_file
Appelé lorsque la feuille de style tente d'ouvrir un fichier local (c'est-à-dire lors de l'utilisation de la fonction document()).
write_file
Appelé lorsqu'une tentative est faite pour écrire un fichier local (c'est-à-dire lors de l'utilisation de l'élément exsl:document).
create_dir
Appelé lorsqu'un répertoire doit être créé pour écrire un fichier.

NOTE : Par défaut, create_dir n'est pas autorisé. Pour l'activer, un rappel doit être enregistré.

read_net
Appelé lorsque la feuille de style tente de lire sur le réseau.
write_net
Appelé lorsque la feuille de style tente d'écrire sur le réseau.

Utilisation de XML::LibXSLT::Security

L'interface de ce module est similaire à XML::LibXML::InputCallback. Après avoir créé une nouvelle instance, vous pouvez enregistrer des rappels pour chacune des options de sécurité listées ci-dessus. Ensuite, vous appliquez les préférences de sécurité à l'objet XML::LibXSLT ou XML::LibXSLT::Stylesheet en utilisant security_callbacks().

my $security = XML::LibXSLT::Security->new();
$security->register_callback( read_file  => $read_cb );
$security->register_callback( write_file => $write_cb );
$security->register_callback( create_dir => $create_cb );
$security->register_callback( read_net   => $read_net_cb );
$security->register_callback( write_net  => $write_net_cb );
$xslt->security_callbacks( $security );
 -OR-
$stylesheet->security_callbacks( $security );

Les fonctions de rappel enregistrées sont appelées lorsque l'accès à une ressource est demandé. Si l'accès doit être autorisé, le rappel doit renvoyer 1, sinon il doit renvoyer 0. Les fonctions de rappel doivent accepter les arguments suivants :

$tctxt
C'est le contexte de transformation (XML::LibXSLT::TransformContext). Vous pouvez l'utiliser pour obtenir l'objet XML::LibXSLT::Stylesheet actuel en appelant stylesheet(). 
my $stylesheet = $tctxt->stylesheet();

L'objet feuille de style peut alors être utilisé pour partager des informations contextuelles entre différents appels aux rappels de sécurité.

$value
C'est le nom de la ressource (fichier ou URI) qui a été demandée.

Si une option particulière (sauf pour "create_dir") n'a pas de rappel enregistré, alors la feuille de style aura un accès complet pour cette action.

Interface

new()
Crée un nouvel objet XML::LibXSLT::Security.
register_callback( $option, $callback )
Enregistre une fonction de rappel pour l'option de sécurité donnée (listée ci-dessus).
unregister_callback( $option )
Supprime le rappel pour l'option donnée. Cela a pour effet d'autoriser tout accès pour l'option donnée (sauf pour "create_dir").

BENCHMARK

Inclus dans la distribution se trouve un script de benchmark simple, qui a deux pilotes - un pour LibXSLT et un pour Sablotron. Le benchmark nécessite les fichiers de cas de test de la distribution XSLTMark que vous pouvez trouver sur http://www.datapower.com/XSLTMark/

Placez le répertoire des cas de test dans le répertoire créé par cette distribution, puis exécutez :

perl benchmark.pl -h

pour obtenir une liste d'options.

Le benchmark nécessite XML::XPath pour le moment, mais j'espère pouvoir le retirer de l'équation assez bientôt. Il nécessite également Time::HiRes, que je pourrais être persuadé de retirer, en le remplaçant par Benchmark.pm, mais je ne l'ai pas encore fait.

J'aimerais beaucoup obtenir des pilotes pour XML::XSLT et XML::Transformiix, si vous souhaitez les contribuer. De plus, si vous parvenez à faire fonctionner cela sous Win32, j'aimerais beaucoup obtenir un pilote pour MSXSLT via OLE, pour voir ce que nous pouvons faire contre ces garçons de Redmond !

VERSIONS DES BIBLIOTHÈQUES

À des fins de débogage, XML::LibXSLT fournit des informations de version sur la bibliothèque C libxslt (mais ne la confondez pas avec le numéro de version du module XML::LibXSLT lui-même, c'est-à-dire avec $XML::LibXSLT::VERSION).

XML::LibXSLT émet un avertissement si la version d'exécution de la bibliothèque est inférieure à la version de compilation.

XML::LibXSLT::LIBXSLT_VERSION()
Retourne le numéro de version de la bibliothèque libxslt qui a été utilisée pour compiler XML::LibXSLT sous forme d'entier. Par exemple, pour libxslt-1.1.18, il retournera 10118.
XML::LibXSLT::LIBXSLT_DOTTED_VERSION()
Retourne le numéro de version de la bibliothèque libxslt qui a été utilisée pour compiler XML::LibXSLT sous forme de chaîne de caractères, par exemple "1.1.18".
XML::LibXSLT::LIBXSLT_RUNTIME_VERSION()
Retourne le numéro de version de la bibliothèque libxslt à laquelle XML::LibXSLT est lié en cours d'exécution (dynamiquement ou statiquement). Par exemple, pour libxslt.so.1.1.18, il retournera 10118.
XML::LibXSLT::HAVE_EXLT()
Retourne 1 si le module a été compilé avec libexslt, 0 sinon.
