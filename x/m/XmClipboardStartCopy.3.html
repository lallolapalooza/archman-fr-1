XmClipboardStartCopy(3)

Paquet: openmotif

Licences: LGPL-2.1-or-later

XmClipboardStartCopy(appel de bibliothèque) XmClipboardStartCopy(appel de bibliothèque)

NOM

XmClipboardStartCopy — Une fonction de presse-papiers qui met en place un espace de stockage et une structure de données

SYNTAXE

#include <Xm/CutPaste.h>
int XmClipboardStartCopy (display, window, clip_label,
        timestamp, widget, callback, item_id)
        Display * display;
        Window  window;
        XmString        clip_label;
        Time    timestamp;
        Widget  widget;
        XmCutPasteProc  callback;
        long    * item_id;
(void)

DESCRIPTION

XmClipboardStartCopy met en place un espace de stockage et des structures de données pour recevoir les données du presse-papiers. Une application appelle cette fonction lors d'une opération de coupe ou de copie. L'élément de données que ces structures reçoivent devient alors le prochain élément de données dans le presse-papiers.

La copie d'une grande quantité de données dans le presse-papiers peut prendre du temps. Il est possible qu'une fois les données copiées, aucune application ne les demande jamais. Le Motif Toolkit fournit un mécanisme pour que l'application n'ait pas besoin de transmettre réellement les données au presse-papiers tant qu'elles n'ont pas été demandées par une application.

Au lieu de cela, l'application transmet des informations de format et de longueur dans XmClipboardCopy aux fonctions de presse-papiers, ainsi qu'un ID de widget et une adresse de fonction de rappel qui sont passés dans XmClipboardStartCopy. L'ID du widget est nécessaire pour les communications entre les fonctions de presse-papiers de l'application qui possède les données et les fonctions de presse-papiers de l'application qui demande les données.

Les fonctions de rappel sont responsables de la copie des données réelles dans le presse-papiers via XmClipboardCopyByName. La fonction de rappel est également appelée si l'élément de données est supprimé du presse-papiers et que les données réelles ne sont plus nécessaires.

display
Spécifie un pointeur vers la structure Display qui a été retournée lors d'un appel précédent à XOpenDisplay ou XtDisplay.
window
Spécifie l'ID de la fenêtre d'un widget qui relie la fenêtre de l'application au presse-papiers. L'ID de la fenêtre du widget peut être obtenu via XtWindow. La même instance d'application doit passer le même ID de fenêtre à chacune des fonctions de presse-papiers qu'elle appelle.
clip_label
Spécifie l'étiquette à associer à l'élément de données. Cet argument est utilisé pour identifier l'élément de données, comme dans un visualiseur de presse-papiers. Un exemple d'étiquette est le nom de l'application qui place les données dans le presse-papiers.
timestamp
Spécifie l'heure de l'événement qui a déclenché la copie. Un horodatage valide doit être fourni ; il n'est pas suffisant d'utiliser CurrentTime.
widget
Spécifie l'ID du widget qui reçoit les messages demandant des données précédemment transmises par nom. Cet argument doit être présent pour transmettre des données par nom. N'importe quel ID de widget valide dans votre application peut être utilisé à cette fin et toute la gestion des messages est prise en charge par les fonctions de coupe et de collage.
callback
Spécifie l'adresse de la fonction de rappel qui est appelée lorsque le presse-papiers a besoin de données qui ont été initialement transmises par nom. C'est également la fonction de rappel pour recevoir le message delete pour les éléments qui ont été initialement transmis par nom. Cet argument doit être présent pour transmettre des données par nom.
item_id
Spécifie le numéro attribué à cet élément de données. L'application utilise ce numéro dans les appels à XmClipboardCopy, XmClipboardEndCopy et XmClipboardCancelCopy.

Pour plus d'informations sur la transmission de données par nom, voir XmClipboardCopy(3) et XmClipboardCopyByName(3).

Les arguments widget et callback doivent être présents pour transmettre des données par nom. Le format de rappel est le suivant :

void (*callback) (widget, data_id, private, reason)
        Widget  widget;
        long    *data_id;
        long    *private;
        int     *reason;
(void)
widget
Spécifie l'ID du widget passé à cette fonction.
data_id
Spécifie le numéro d'identification retourné par XmClipboardCopy, qui identifie les données transmises par nom.
private
Spécifie les informations privées passées à XmClipboardCopy.
reason
Spécifie la raison. XmCR_CLIPBOARD_DATA_DELETE ou XmCR_CLIPBOARD_DATA_REQUEST sont les valeurs possibles.

VALEUR

XmClipboardSuccess
La fonction a réussi.
XmClipboardLocked
La fonction a échoué car le presse-papiers était verrouillé par une autre application. L'application peut continuer à appeler la fonction à nouveau avec les mêmes paramètres jusqu'à ce que le verrou disparaisse. Cela donne à l'application la possibilité de demander si l'utilisateur souhaite continuer à essayer ou abandonner l'opération.
