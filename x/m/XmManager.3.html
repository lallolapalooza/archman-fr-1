NOM

XmManager — La classe de widget Manager

SYNTAXE

#include <Xm/Xm.h>

DESCRIPTION

Manager est une classe de widget utilisée comme superclasse de support pour d'autres classes de widgets. Elle prend en charge les ressources visuelles, les contextes graphiques et les ressources de parcours nécessaires aux mécanismes graphiques et de parcours.

CLASSES

Manager hérite du comportement et des ressources de Core, Composite et Constraint.

Le pointeur de classe est xmManagerWidgetClass.

Le nom de la classe est XmManager.

NOUVELLES RESSOURCES

Le tableau suivant définit un ensemble de ressources de widget utilisées par le programmeur pour spécifier des données. Le programmeur peut également définir les valeurs des ressources pour les classes héritées afin de définir les attributs de ce widget. Pour référencer une ressource par son nom ou sa classe dans un fichier .Xdefaults, supprimez le préfixe XmN ou XmC et utilisez les lettres restantes. Pour spécifier l'une des valeurs définies pour une ressource dans un fichier .Xdefaults, supprimez le préfixe Xm et utilisez les lettres restantes (en minuscules ou en majuscules, mais incluez les éventuels underscores entre les mots). Les codes dans la colonne d'accès indiquent si la ressource donnée peut être définie au moment de la création (C), peut être définie en utilisant XtSetValues (S), peut être récupérée en utilisant XtGetValues (G), ou n'est pas applicable (N/A).

XmNbottomShadowColor
Spécifie la couleur à utiliser pour dessiner les côtés inférieur et droit de l'ombre de bordure. Cette couleur est utilisée si la ressource XmNbottomShadowPixmap est NULL.
XmNbottomShadowPixmap
Spécifie le pixmap à utiliser pour dessiner les côtés inférieur et droit de l'ombre de bordure.
XmNforeground
Spécifie la couleur de dessin du premier plan utilisée par les widgets gestionnaires.
XmNhelpCallback
Spécifie la liste des rappels qui sont appelés lorsque la séquence de touches d'aide est pressée. La raison envoyée par ce rappel est XmCR_HELP.
XmNhighlightColor
Spécifie la couleur du rectangle de surbrillance. Cette couleur est utilisée si la ressource de pixmap de surbrillance est XmUNSPECIFIED_PIXMAP.
XmNhighlightPixmap
Spécifie le pixmap utilisé pour dessiner le rectangle de surbrillance.
XmNinitialFocus
Spécifie l'ID d'un widget descendant du gestionnaire. Le widget doit satisfaire les conditions suivantes :
•
Le widget doit être soit un groupe d'onglets, soit un widget ne faisant pas partie d'un groupe d'onglets et capable de recevoir le focus clavier. Pour la définition d'un groupe d'onglets, voir la description des ressources XmNnavigationType des gestionnaires, des primitives et des gadgets. En général, un widget peut recevoir le focus clavier lorsqu'il est une primitive, un gadget, ou un gestionnaire (tel qu'une zone de dessin sans enfants traversables) qui agit comme une primitive.
•
Le widget ne doit pas être descendant d'un groupe d'onglets qui est lui-même descendant du gestionnaire. Autrement dit, le widget ne peut pas être contenu dans un groupe d'onglets imbriqué dans le gestionnaire.
•
Le widget et ses ancêtres doivent avoir une valeur Vrai pour leur ressource XmNtraversalOn.
Si le widget ne satisfait pas ces conditions, XmNinitialFocus est traité comme si la valeur était NULL.
Cette ressource n'est significative que lorsque XmNkeyboardFocusPolicy de l'ancêtre de la fenêtre la plus proche est XmEXPLICIT. Elle est utilisée pour déterminer quel widget reçoit le focus dans les situations suivantes :
•
Lorsque le gestionnaire est enfant d'une fenêtre et que la hiérarchie de fenêtres reçoit le focus pour la première fois
•
Lorsque le focus est à l'intérieur de la hiérarchie de fenêtres, que le gestionnaire est un groupe d'onglets composite et que l'utilisateur navigue vers le gestionnaire via le clavier
Le focus est alors déterminé comme suit :
•
Si XmNinitialFocus est un widget non-groupe-d'onglets traversable, ce widget reçoit le focus.
•
Si XmNinitialFocus est un groupe d'onglets traversable, ce groupe d'onglets reçoit le focus. Si ce groupe d'onglets est un composite avec des groupes d'onglets descendants ou des widgets non-groupe-d'onglets traversables, ces procédures sont utilisées récursivement pour attribuer le focus à un descendant de ce groupe d'onglets.
•
Si XmNinitialFocus est NULL, le premier widget non-groupe-d'onglets traversable qui n'est pas contenu dans un groupe d'onglets imbriqué reçoit le focus.
•
Si XmNinitialFocus est NULL et qu'aucun widget non-groupe-d'onglets traversable n'existe, le premier groupe d'onglets traversable qui n'est pas contenu dans un groupe d'onglets imbriqué reçoit le focus. Si ce groupe d'onglets est un composite avec des groupes d'onglets descendants ou des widgets non-groupe-d'onglets traversables, ces procédures sont utilisées récursivement pour attribuer le focus à un descendant de ce groupe d'onglets.
Si une hiérarchie de fenêtres regagne le focus après l'avoir perdu, le focus revient au widget qui avait le focus au moment où il a quitté la hiérarchie.
L'utilisation de XmNinitialFocus est indéfinie si le gestionnaire est une MenuBar, PulldownMenu, PopupMenu ou OptionMenu.
XmNlayoutDirection
Spécifie la direction dans laquelle les composants du gestionnaire (y compris les chaînes de caractères) sont disposés. Les valeurs sont de type XmDirection. Si le parent du widget est un gestionnaire ou une fenêtre, la valeur est héritée du parent du widget. Sinon, elle est héritée du plus proche ancêtre vendeur ou de la fenêtre de menu. Référez-vous à la page de référence XmDirection(3) pour les valeurs de direction possibles.
XmNnavigationType
Détermine si le widget est un groupe d'onglets.
XmNONE
Indique que le widget n'est pas un groupe d'onglets.
XmTAB_GROUP
Indique que le widget est un groupe d'onglets, à moins que la ressource XmNnavigationType d'un autre widget dans la hiérarchie ne soit XmEXCLUSIVE_TAB_GROUP.
XmSTICKY_TAB_GROUP
Indique que le widget est un groupe d'onglets, même si la ressource XmNnavigationType d'un autre widget dans la hiérarchie est XmEXCLUSIVE_TAB_GROUP.
XmEXCLUSIVE_TAB_GROUP
Indique que le widget est un groupe d'onglets et que les widgets de la hiérarchie dont la ressource XmNnavigationType est XmTAB_GROUP ne sont pas des groupes d'onglets.
Lorsqu'un widget parent a une XmNnavigationType de XmEXCLUSIVE_TAB_GROUP, la navigation des widgets ne faisant pas partie d'un groupe d'onglets à l'intérieur du groupe est basée sur l'ordre de ces widgets dans la liste XmNchildren de leur parent.
Lorsque la XmNnavigationType de n'importe quel widget dans une hiérarchie est XmEXCLUSIVE_TAB_GROUP, la navigation des groupes d'onglets dans la hiérarchie se poursuit vers les widgets dans l'ordre où leurs ressources XmNnavigationType ont été spécifiées comme XmEXCLUSIVE_TAB_GROUP ou XmSTICKY_TAB_GROUP, que ce soit en créant les widgets avec cette valeur, en appelant XtSetValues, ou en appelant XmAddTabGroup.
XmNpopupHandlerCallback
Permet à l'application de contrôler quel menu contextuel sera automatiquement affiché. La raison peut être XmCR_POST ou XmCR_REPOST :
XmCR_POST
Indique qu'il s'agit d'une demande d'affichage normale.
XmCR_REPOST
Indique que le menu vient d'être masqué et que ce rappel a été invoqué lors d'une relecture.
Ce rappel utilise la structure XmPopupHandlerCallbackStruct pour passer des informations.
XmNshadowThickness
Spécifie l'épaisseur de l'ombre de bordure dessinée. XmBulletinBoard et ses descendants définissent cette valeur dynamiquement. Si le widget est une fenêtre de niveau supérieur, cette valeur est définie à 1. S'il ne s'agit pas d'une fenêtre de niveau supérieur, cette valeur est définie à 0 (zéro).
XmNstringDirection
Est une ressource synthétique pour définir XmNlayoutDirection. Les valeurs de cette ressource sont XmSTRING_DIRECTION_L_TO_R et XmSTRING_DIRECTION_R_TO_L. Référez-vous à la description de la ressource XmNlayoutDirection. La ressource XmNstringDirection est obsolète par XmNlayoutDirection, mais est conservée ici pour la compatibilité ascendante.
XmNtopShadowColor
Spécifie la couleur à utiliser pour dessiner les côtés supérieur et gauche de l'ombre de bordure. Cette couleur est utilisée si la ressource XmNtopShadowPixmap est NULL.
XmNtopShadowPixmap
Spécifie le pixmap à utiliser pour dessiner les côtés supérieur et gauche de l'ombre de bordure.
XmNtraversalOn
Spécifie si la navigation est activée pour ce widget.

XmMILLIMETERS

XmCENTIMETERS
Toutes les valeurs fournies au widget sont traitées comme des valeurs de centimètres normales.
XmINCHES
Toutes les valeurs fournies au widget sont traitées comme des valeurs de pouces normales.

XmFONT_UNITS
Toutes les valeurs fournies au widget sont traitées comme des unités de police normales. Une unité de police a des composantes horizontale et verticale. Ce sont les valeurs des ressources XmScreen XmNhorizontalFontUnit et XmNverticalFontUnit.
Xm100TH_FONT_UNITS
Toutes les valeurs fournies au widget sont traitées comme 1/100 d'unité de police. Une unité de police a des composantes horizontale et verticale. Ce sont les valeurs des ressources XmScreen XmNhorizontalFontUnit et XmNverticalFontUnit.
XmNuserData
Permet à l'application d'associer toute donnée spécifique nécessaire au widget. Il s'agit d'une ressource non utilisée en interne.

Paramètres par défaut de couleur dynamiques

Les ressources de couleur de premier plan, d'arrière-plan, d'ombre supérieure, d'ombre inférieure et de surbrillance sont définies dynamiquement par défaut. Si aucune donnée de couleur n'est spécifiée, les couleurs sont générées automatiquement. Sur un système à un seul plan, un schéma de couleurs noir et blanc est généré. Sinon, quatre couleurs sont générées, qui affichent le bon ombrage pour les visuels 3D. Si la couleur d'arrière-plan est la seule couleur spécifiée pour un widget, les couleurs d'ombre supérieure et d'ombre inférieure sont générées pour donner l'apparence 3D. Les couleurs de premier plan et de surbrillance sont générées pour fournir un contraste suffisant avec la couleur d'arrière-plan.

Les couleurs sont générées uniquement lors de la création. La réinitialisation de l'arrière-plan via XtSetValues ne régénère pas les autres couleurs. XmChangeColor peut être utilisé pour recalculer toutes les couleurs associées en fonction d'une nouvelle couleur d'arrière-plan.

Informations sur les rappels

Un pointeur vers la structure suivante est passé à chaque rappel pour XmNhelpCallback:

typedef struct
{
        int reason;
        XEvent * event;
} XmAnyCallbackStruct;
reason
Indique la raison pour laquelle le rappel a été invoqué. Pour ce rappel, reason est défini sur XmCR_HELP.
event
Pointe vers le XEvent qui a déclenché le rappel.

Un pointeur vers la structure suivante est passé à chaque rappel pour XmNpopupHandlerCallback:

typedef struct
{
        int reason;
        XEvent * event;
        Widget menuToPost;
        Boolean postIt;
        Widget target;
} XmPopupHandlerCallbackStruct;
reason
Indique la raison pour laquelle le rappel a été invoqué.
event
Pointe vers le XEvent qui a déclenché le gestionnaire.
menuToPost
Spécifie le menu contextuel que le système de menu pense devoir être affiché. L'application peut modifier ce champ.
postIt
Indique si le processus d'affichage doit se poursuivre. L'application peut modifier ce champ.
target
Spécifie le widget ou le gadget le plus spécifique que le système de menu a trouvé à partir de l'événement, qui correspond à l'événement.

Routines d'action

Les routines d'action de XmManager sont

GadgetTakeFocus():
Fait en sorte que le gadget actuel obtienne le focus du clavier lorsque Ctrl<Btn1Down> est pressé.
ManagerGadgetActivate():
Fait en sorte que le gadget actuel soit activé.
ManagerGadgetArm():
Fait en sorte que le gadget actuel soit armé.
ManagerGadgetButtonMotion():
Fait en sorte que le gadget actuel traite un événement de mouvement de souris.
ManagerGadgetDrag():
Fait en sorte que le gadget actuel commence une opération de glisser-déposer. Cette action est non définie pour les gadgets utilisés dans un système de menu.
ManagerGadgetHelp():
Appelle les rappels pour le XmNhelpCallback du gadget actuel, s'ils existent. S'il n'y a pas de rappels d'aide pour ce widget, cette action appelle les rappels d'aide de l'ancêtre le plus proche qui en possède.
ManagerGadgetKeyInput():
Fait en sorte que le gadget actuel traite un événement clavier.
ManagerGadgetMultiActivate():
Fait en sorte que le gadget actuel traite un clic de souris multiple.
ManagerGadgetMultiArm():
Fait en sorte que le gadget actuel traite une pression de bouton de souris multiple.
ManagerGadgetNextTabGroup():
Cette action dépend de la valeur de la ressource d'affichage XmNenableButtonTab. Lorsque XmNenableButtonTab est Faux (par défaut), cette action navigue vers le premier élément du groupe d'onglets suivant. Si le groupe d'onglets actuel est la dernière entrée de la liste des groupes d'onglets, elle revient au début de la liste des groupes d'onglets.
Lorsque XmNenableButtonTab est Vrai, cette action se déplace vers l'élément suivant dans le groupe d'onglets actuel, sauf s'il s'agit du dernier élément du groupe. Lorsque l'élément est le dernier du groupe, l'action navigue vers le premier élément du groupe d'onglets suivant. Le comportement de XmNenableButtonTab s'applique uniquement aux PushButton, ArrowButton et DrawnArrow.
ManagerGadgetPrevTabGroup():
Cette action dépend de la valeur de la ressource d'affichage XmNenableButtonTab. Lorsque XmNenableButtonTab est Faux (par défaut), cette action navigue vers le premier élément du groupe d'onglets précédent. Si le début de la liste des groupes d'onglets est atteint, elle revient à la fin de la liste des groupes d'onglets.
Lorsque XmNenableButtonTab est Vrai, cette action se déplace vers l'élément précédent dans le groupe d'onglets actuel, sauf s'il s'agit du premier élément du groupe. Lorsque l'élément est le premier du groupe, l'action navigue vers le premier élément du groupe d'onglets précédent. Le comportement de XmNenableButtonTab s'applique uniquement aux PushButton, ArrowButton et DrawnButton.
ManagerGadgetSelect():
Fait en sorte que le gadget actuel soit armé et activé.
ManagerGadgetTraverseCurrent
Fait en sorte que le gadget actuel obtienne le focus du clavier lorsque Ctrl<Btn1Down> est pressé. Le gadget n'est pas activé.
ManagerGadgetTraverseDown():
Navigue vers l'élément suivant en dessous du gadget actuel dans le groupe d'onglets actuel, en revenant si nécessaire. La direction de retour dépend de la direction de mise en page du groupe d'onglets du widget.
ManagerGadgetTraverseHome():
Navigue vers le premier widget ou gadget dans le groupe d'onglets actuel.
ManagerGadgetTraverseLeft():
Navigue vers l'élément suivant à gauche du gadget actuel dans le groupe d'onglets actuel, en revenant si nécessaire. La direction de retour dépend de la direction de mise en page du groupe d'onglets du widget.
ManagerGadgetTraverseNext():
Navigue vers l'élément suivant dans le groupe d'onglets actuel, en revenant si nécessaire. La direction de retour dépend de la direction de mise en page du groupe d'onglets du widget.
ManagerGadgetTraversePrev():
Navigue vers l'élément précédent dans le groupe d'onglets actuel, en revenant si nécessaire. La direction de retour dépend de la direction de mise en page du groupe d'onglets du widget.
ManagerGadgetTraverseRight()
Navigue vers l'élément suivant à droite du gadget actuel dans l'onglet actuel, en revenant si nécessaire. groupe d'onglets du widget. La direction de retour dépend de la direction de mise en page du groupe d'onglets du widget.
ManagerGadgetTraverseUp():
Navigue vers l'élément suivant au-dessus du gadget actuel dans le groupe d'onglets actuel, en revenant si nécessaire. La direction de retour dépend de la direction de mise en page du groupe d'onglets du widget.
ManagerParentActivate():
Si le parent est un gestionnaire, transmet l'événement <osfActivate> reçu par le widget/gadget actuel à son parent.
ManagerParentCancel():
Si le parent est un gestionnaire, transmet l'événement <osfCancel> reçu par le widget/gadget actuel à son parent.

Comportement supplémentaire

Ce widget a le comportement supplémentaire décrit ci-dessous :

<FocusIn>:
Si la politique de focus clavier du shell est XmEXPLICIT et que l'événement se produit dans un gadget, fait en sorte que le gadget soit mis en évidence et obtienne le focus.
<FocusOut>:
Si la politique de focus clavier du shell est XmEXPLICIT et que l'événement se produit dans un gadget, fait en sorte que le gadget soit désaffiché et perde le focus.

Liaisons virtuelles

Les liaisons des touches virtuelles sont spécifiques au vendeur. Pour plus d'informations sur les liaisons des boutons et touches virtuels, voir VirtualBindings(3).
