NOM

XML::Stream - Crée une connexion de flux XML et analyse les données retournées

SYNOPSIS

XML::Stream est une tentative de solidification de l'utilisation de XML via le streaming.

DESCRIPTION

Ce module fournit à l'utilisateur des méthodes pour se connecter à un serveur distant, envoyer un flux de XML au serveur, et recevoir/analyser un flux de XML du serveur. Il est principalement basé sur le travail effectué pour le routeur XML Etherx développé par l'équipe de développement Jabber. Pour plus d'informations sur ce projet, visitez http://xmpp.org/protocols/streams/.

XML::Stream donne à l'utilisateur la possibilité de définir un rappel central qui sera utilisé pour gérer les balises reçues du serveur. Ces balises sont passées dans le format défini au moment de l'instanciation. Lorsque la balise fermante d'un objet est vue, l'arbre est terminé et passé à la fonction de rappel. Ce que l'utilisateur en fait ensuite dépend de lui.

Pour une description détaillée du fonctionnement de ce module et de la structure de données qu'il retourne, veuillez consulter le code source de Stream.pm et regarder la description détaillée à la fin du fichier.

NOTE : L'analyseur fourni par XML::Stream::Parser, comme la plupart des analyseurs Perl, est synchrone. Si vous êtes en train d'analyser un paquet et que vous appelez un rappel défini par l'utilisateur, l'analyseur est bloqué jusqu'à ce que votre rappel se termine. Cela signifie que vous ne pouvez pas manipuler un paquet, envoyer un autre paquet et attendre une réponse à ce paquet. Elle ne vous parviendra jamais. Le multithreading pourrait résoudre cela, mais comme nous le savons tous, le multithreading en Perl n'est pas encore au point. Ce problème sera revu à l'avenir.

METHODES

new

new(
    debug      => chaîne,
    debugfh    => FileHandle,
    debuglevel => 0|1|N,
    debugtime  => 0|1,
    style      => chaîne)

Crée l'objet XML::Stream. debug doit être défini sur le chemin du journal de débogage à écrire. S'il est défini sur "stdout", le débogage ira là-bas. De plus, vous pouvez spécifier un handle de fichier existant en utilisant debugfh.

debuglevel détermine la quantité de débogage à générer. 0 est le moins, 1 est un peu plus, N est la limite que vous souhaitez.

debugtime détermine si une estampille temporelle doit être ajoutée à l'entrée. style définit la manière dont la structure de données est retournée. Les deux styles disponibles sont :

tree - Format d'arbre L<XML::Parser>
node - Format L<XML::Stream::Node>

Pour plus d'informations, consultez les pages de manuel respectives.

Listen

Démarre le flux en écoutant sur un port pour que quelqu'un se connecte, envoie la balise de flux d'ouverture, puis envoie une réponse basée sur la conformité de l'en-tête reçu à ce flux. Le nom du serveur, le port et l'espace de noms sont requis, sinon nous ne savons pas où écouter et quel espace de noms accepter.

ConnectionAccept

Accepte une connexion entrante.

Respond

S'il s'agit d'une prise d'écoute, nous devons répondre à l'<stream:stream/> d'ouverture.

Connect

Démarre le flux en se connectant au serveur, en envoyant la balise de flux d'ouverture, puis en attendant une réponse et en vérifiant qu'elle est correcte pour ce flux. Le nom du serveur, le port et l'espace de noms sont requis, sinon nous ne savons pas où envoyer le flux...

Connect(hostname=>chaîne,       
        port=>entier, 
        to=>chaîne,             
        from=>chaîne,           
        myhostname=>chaîne,     
        namespace=>chaîne,      
        namespaces=>tableau,      
        connectiontype=>chaîne, 
        ssl=>0|1,
        ssl_verify =>0x00|0x01|0x02|0x04,
        ssl_ca_path=>chaîne,
        srv=>chaîne)

Ouvre une connexion tcp au serveur spécifié et envoie la balise de flux XML d'ouverture appropriée. "hostname", "port" et "namespace" sont requis. namespaces vous permet d'utiliser des objets XML::Stream::Namespace.

"to" est nécessaire si vous voulez que l'attribut du flux soit différent de l'hôte auquel vous vous connectez.

"from" est nécessaire si vous voulez que l'attribut du flux provenant soit différent de l'hôte d'où vous vous connectez.

"myhostname" ne devrait pas être nécessaire, mais si le module ne parvient pas à déterminer correctement votre nom d'hôte (vérifiez le journal de débogage), définissez-le sur la valeur correcte, ou si vous voulez que l'autre partie du flux pense que vous êtes quelqu'un d'autre. Le type détermine le type de connexion établie :

"tcpip"    - TCP/IP (par défaut)
"stdinout" - STDIN/STDOUT
"http"     - HTTP

HTTP reconnaît les proxys si les variables d'environnement http_proxy ou https_proxy sont définies.

"ssl" spécifie si une socket SSL doit être utilisée pour les communications cryptées.

"ssl_verify" détermine si la vérification du certificat du pair a lieu. Voir la documentation du paramètre SSL_verify_mode pour IO::Socket::SSL-new()|IO::Socket::SSL>. La valeur par défaut est 0x01, ce qui entraîne la vérification du certificat du serveur et exige que ssl_ca_path soit défini.

"ssl_ca_path" doit être défini sur le chemin d'accès soit à un répertoire contenant des certificats CA hachés, soit à un seul fichier contenant des certificats CA acceptables concaténés. Ce paramètre est requis si ssl_verify est défini sur autre chose que 0x00 (pas de vérification).

Si srv est spécifié ET que Net::DNS est installé et peut être chargé, alors une requête SRV est envoyée à srv.hostname et les résultats sont traités pour remplacer le nom d'hôte et le port. Si la recherche échoue, ou si Net::DNS ne peut pas être chargé, alors le nom d'hôte et le port sont laissés tels quels comme valeurs par défaut.

Cette fonction retourne le même hash que GetRoot() ci-dessous. Assurez-vous d'obtenir le SID (Session ID) car vous devez l'utiliser pour appeler la plupart des autres fonctions ici.

OpenFile

Démarre le flux en ouvrant un fichier et en le configurant de sorte que Process lise depuis le handle de fichier pour obtenir le flux entrant.

OpenFile(chaîne)

Ouvre un handle de fichier vers l'argument spécifié et prétend que c'est un flux. Il ignorera la balise externe et ne vérifiera pas s'il s'agissait d'un <stream:stream/>. Ceci est utile pour écrire un programme qui doit analyser n'importe quel fichier XML qui est essentiellement composé de petits paquets (comme RDF).

Disconnect

InitConnection

ParseStream

Prend le flux entrant et s'assure que seules des balises XML complètes sont passées à l'analyseur. Si une balise complète n'a pas encore été lue, le Flux enregistre la partie incomplète et envoie le reste à l'analyseur.

Process

Vérifie les données sur la socket et retourne un code d'état en fonction de la présence ou non de données. Si aucun délai d'attente n'est défini dans l'appel, le délai d'attente défini dans Connect() est utilisé. Si un délai d'attente de 0 est utilisé, l'appel se bloque jusqu'à ce qu'il reçoive des données, sinon il retourne après la période de délai d'attente.

SetXMLData

Takes a host of arguments and sets a portion of the specified data strucure with that data. The function works in two modes "single" or "multiple". "single" denotes that the function should locate the current tag that matches this data and overwrite it's contents with data passed in. "multiple" denotes that a new tag should be created even if others exist.

type - single or multiple XMLTree - pointer to XML::Stream data object (tree or node) tag - name of tag to create/modify (if blank assumes
working with top level tag) data - CDATA to set for tag attribs - attributes to ADD to tag

GetXMLData

Takes a host of arguments and returns various data structures that match them.

type "existence" - returns 1 or 0 if the tag exists in the top level.

"value" - returns either the CDATA of the tag, or the value of the attribute depending on which is sought. This ignores any mark ups to the data and just returns the raw CDATA.

"value array" returns an array of strings representing all of the CDATA in the specified tag. This ignores any mark ups to the data and just returns the raw CDATA.

"tree" - returns a data structure that represents the XML with the specified tag as the root tag. Depends on the format that you are working with.

"tree array" returns an array of data structures each with the specified tag as the root tag.

"child array" - returns a list of all children nodes
not including CDATA nodes.

"attribs" - returns a hash with the attributes, and
their values, for the things that match
the parameters

"count" - returns the number of things that match
the arguments

"tag" - returns the root tag of this tree

XMLTree - pointer to XML::Stream data structure

"tag" - tag to pull data from. If blank then the top level
tag is accessed. "attrib" - attribute value to retrieve. Ignored for types
"value array", "tree", "tree array". If paired
with value can be used to filter tags based on
attributes and values. "value" - only valid if an attribute is supplied. Used to
filter for tags that only contain this attribute.
Useful to search through multiple tags that all
reference different name spaces.

XPath

XPath(node,path) returns an array of results that match the xpath. node can be any of the three types (Tree, Node).

XML2Config

Takes an XML data tree and turns it into a hash of hashes. This only works for certain kinds of XML trees like this:

<foo>
  <bar>1</bar>
  <x>
    <y>foo</y>
  </x>
  <z>5</z>
  <z>6</z>
</foo>

The resulting hash would be:

$hash{bar} = 1;
$hash{x}->{y} = "foo";
$hash{z}->[0] = 5;
$hash{z}->[1] = 6;

Good for config files.

Config2XML

Takes a hash and produces an XML string from it. If the hash looks like this:

$hash{bar} = 1;
$hash{x}->{y} = "foo";
$hash{z}->[0] = 5;
$hash{z}->[1] = 6;

The resulting xml would be:

<foo>
  <bar>1</bar>
  <x>
    <y>foo</y>
  </x>
  <z>5</z>
  <z>6</z>
</foo>

Good for config files.

EscapeXML

Simple function to make sure that no bad characters make it into in the XML string that might cause the string to be misinterpreted.

UnescapeXML

Simple function to take an escaped string and return it to normal.

NewSID

Retourne un ID de session à envoyer à un flux entrant dans l'en-tête de retour. Par défaut, il incrémente simplement un compteur et le retourne, ou vous pouvez définir une fonction et la définir à l'aide de la fonction SetCallBacks.

SetCallBacks

Prend une table de hachage avec les balises de niveau supérieur à rechercher comme clés et des pointeurs vers des fonctions comme valeurs.

SetCallBacks(node=>function, update=>function);

Définit le rappel qui doit être appelé dans diverses situations.

"node" est utilisé pour gérer les structures de données qui sont construites pour chaque balise de niveau supérieur. "update" est utilisé lorsque Process est bloqué en attente de données, mais que vous souhaitez que votre code original soit mis à jour.

VARIABLES

$NONBLOCKING

Indique à l'analyseur d'entrer dans un état non bloquant. Cela peut entraîner un comportement étrange car vous pouvez obtenir des rappels imbriqués pendant que les choses sont en attente. 1=activé, 0=désactivé (par défaut).

EXEMPLES

exemple simple

use XML::Stream qw( Tree );
$stream = XML::Stream->new;
my $status = $stream->Connect(hostname => "jabber.org",
                              port => 5222,
                              namespace => "jabber:client");
if (!defined($status)) {
  print "ERREUR : Impossible de se connecter au serveur\n";
  print "       (",$stream->GetErrorCode(),")\n";
  exit(0);
}
while($node = $stream->Process()) {
  # faire quelque chose avec $node
}
$stream->Disconnect();

Exemple utilisant un gestionnaire

use XML::Stream qw( Tree );
$stream = XML::Stream->new;
$stream->SetCallBacks(node=>\&noder);
$stream->Connect(hostname => "jabber.org",
                 port => 5222,
                 namespace => "jabber:client",
                 timeout => undef) || die $!;
# Se bloque ici indéfiniment, noder est appelé pour les paquets entrants
# lorsqu'ils arrivent.
while(defined($stream->Process())) { }
print "ERREUR : Le flux a planté (",$stream->GetErrorCode(),")\n";
sub noder
{
  my $sid = shift;
  my $node = shift;
  # faire quelque chose avec $node
}
