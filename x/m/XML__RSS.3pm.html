DESCRIPTION

Ce module fournit un cadre de base pour la création et la maintenance des fichiers RDF Site Summary (RSS). Cette distribution contient également de nombreux exemples qui vous permettent de générer du HTML à partir d'un RSS, de convertir entre les versions 0.9, 0.91, 1.0 et 2.0, et d'autres choses intéressantes. Cela peut être utile si vous souhaitez inclure des flux d'actualités sur votre site Web provenant de sources comme Slashdot et Freshmeat, ou si vous souhaitez syndiquer votre propre contenu.

XML::RSS prend actuellement en charge les versions 0.9 http://www.rssboard.org/rss-0-9-0, 0.91 http://www.rssboard.org/rss-0-9-1, 1.0 http://web.resource.org/rss/1.0/ et 2.0 http://www.rssboard.org/rss-2-0 de RSS.

RSS a été initialement développé par Netscape comme format pour les canaux Netscape Netcenter, cependant, de nombreux sites Web l'ont depuis adopté comme un format de syndication simple. Avec l'avènement de RSS 1.0, les utilisateurs peuvent désormais syndiquer de nombreux types de contenu différents, y compris les titres d'actualités, les messages à fils, les catalogues de produits, etc.

Note : Afin d'analyser et de générer des dates (telles que "pubDate" et "dc:date"), il est recommandé d'utiliser DateTime::Format::Mail et DateTime::Format::W3CDTF, ce que XML::RSS utilise en interne et requiert. Il devrait également être possible de passer des objets DateTime qui seront formatés en conséquence. Par exemple :

use DateTime ();
my $dt = DateTime->from_epoch(epoch => 1_500_000_000);
$rss->channel(
    pubDate => $dt,
    .
    .
    .
);

MÉTHODES

XML::RSS->new(version=>$version, encoding=>$encoding, output=>$output, stylesheet=>$stylesheet_url, 'xml:base'=>$base)
Constructeur pour XML::RSS. Il renvoie une référence à un objet XML::RSS. Vous pouvez également passer la version RSS et l'encodage XML à utiliser. La version par défaut est 1.0. L'encodage par défaut est UTF-8. Vous pouvez également spécifier le format de sortie indépendamment de la version d'entrée. Cela est utile lorsque vous souhaitez convertir du RSS entre versions. Les modules XML::RSS convertiront entre tous les formats. Si vous définissez <encode_output>, XML::RSS s'assurera d'encoder toutes les entités dans le RSS généré. Ceci est activé par défaut.

Vous pouvez également passer une URL optionnelle vers une feuille de style XSL qui peut être utilisée pour générer un "<?xsl-stylesheet ...

Ce site n'est en aucun cas associé à Arch Linux ni affilié à ce projet. Le contenu est uniquement une traduction des pages de manuel d'Arch publiées sur man.archlinux.org.

?>" méta-tag dans l'en-tête qui permettra à certains navigateurs d'afficher le fichier RSS en HTML.

Vous pouvez également définir "encode_cb" à une référence de sous-routine qui encodera la sortie d'une manière personnalisée. Cette sous-routine accepte deux paramètres : une référence à l'objet dérivé de "XML::RSS::Private::Output::Base" (ce qui ne devrait normalement pas vous concerner) et le texte à encoder. Elle doit retourner le texte à encoder. S'il n'est pas défini, le module encoderra en utilisant sa routine d'encodage personnalisée.

xml:base définira une propriété "xml:base" conformément à

http://www.w3.org/TR/xmlbase/

Notez que pour un encodage correct, vous devez gérer correctement les sections "CDATA". Regardez la méthode _default_encode() de XML::RSS::Private::Output::Base pour savoir comment le faire correctement.

add_item (title=>$title, link=>$link, description=>$desc, mode=>$mode)
Ajoute un élément à l'objet XML::RSS. mode et description sont optionnels. Le mode par défaut est 'append', qui ajoute l'élément à la fin de la liste. Pour insérer un élément, définissez le mode sur insert.

Les éléments sont stockés dans le tableau "@{$obj->{'items'}}" où $obj est une référence à un objet XML::RSS.

On peut spécifier une catégorie en utilisant la clé 'category'. 'category' peut pointer vers une référence de tableau de catégories :

$rss->add_item(
    title => "Foo&Bar",
    link => "http://www.my.tld/",
    category => ["OneCat", "TooCat", "3Kitties"],
);
as_string;
Retourne une chaîne contenant le flux RSS de l'objet XML::RSS. Cette méthode encodera également les caractères spéciaux au passage.
channel (title=>$title, link=>$link, description=>$desc, language=>$language, rating=>$rating, copyright=>$copyright, pubDate=>$pubDate, lastBuildDate=>$lastBuild, docs=>$docs, managingEditor=>$editor, webMaster=>$webMaster)
Les informations du canal sont requises dans RSS. Le title ne peut pas dépasser 40 caractères, le link 500, et la description 500 lors de la génération de RSS 0.9. Le title, le link et la description sont requis pour RSS 1.0. Le language est requis pour RSS 0.91. Les autres paramètres sont optionnels pour RSS 0.91 et 1.0.

Pour récupérer les valeurs du canal, passez le nom de la valeur (title, link, ou description) comme premier et unique argument ainsi :

$title = channel('title');

image (title=>$title, url=>$url, link=>$link, width=>$width, height=>$height, description=>$desc)
L'ajout d'une image n'est pas requis. url est l'URL de l'image, link est l'URL vers laquelle l'image est liée. Les paramètres title, url et link sont requis si vous allez utiliser une image dans votre fichier RSS. Les éléments d'image restants sont utilisés dans RSS 0.91 ou importés optionnellement dans RSS 1.0 via l'espace de noms rss091.

La méthode pour récupérer les valeurs de l'image est la même que pour channel().

parse ($string, \%options)
Analyse un flux RDF Site Summary qui est passé à parse() comme premier paramètre. Retourne l'instance de l'objet afin que l'on puisse dire "$rss->parse($string)->other_method()".

Voir la méthode add_module() pour des instructions sur l'ajout automatique de modules lors de l'analyse d'une chaîne.

%options est une liste d'options qui spécifient comment l'analyse doit être effectuée. Les options disponibles sont :

  • allow_multiple

    Prend une référence de tableau de noms qui indique quels éléments doivent être autorisés à avoir des occurrences multiples. Ainsi, par exemple, pour analyser des flux avec plusieurs pièces jointes (enclosures)

    $rss->parse($xml, { allow_multiple => ['enclosure'] });
  • hashrefs_instead_of_strings

    Si vrai, alors certains éléments (jusqu'à présent ""description"") deviendront des références de hachage au lieu de chaînes (avec une clé content contenant leur contenu, s'ils ont des attributs XML. Sans cette clé, les attributs seront ignorés et il n'y aura qu'une chaîne. Par conséquent, spécifier cette option peut rompre la compatibilité.

  • modules_as_arrays

    Cette option, lorsqu'elle est vraie, analysera les paires clé-valeur des modules comme une référence de tableau d'objets de hachage "{ el => $key_name, value => $value, }" pour gérer gracieusement les éléments dupliqués (voir ci-dessous). Elle n'affectera pas les modules connus tels que dc ("Dublin Core").

  • allow_empty

    Prend une référence de tableau de noms qui indique quels éléments sont autorisés à être vides. Ainsi, par exemple, pour analyser des flux avec des champs personnalisés sous la forme "<foo bar="1" baz="2" />" qui n'ont pas de contenu, seulement des attributs, ajoutez :

    $rss->parse($xml, { allow_empty => ['foo'] });

    (Ajouté dans XML::RSS v 1.63.)

parsefile ($file, \%options)
Identique à parse() sauf qu'il analyse un fichier plutôt qu'une chaîne.

Voir la méthode add_module() pour des instructions sur l'ajout automatique de modules lors de l'analyse d'une chaîne.

save ($file)
Enregistre le flux RSS dans un fichier spécifié.
skipDays (day => $day)
Peuple l'élément skipDays avec le jour $day.
skipHours (hour => $hour)
Peuple l'élément skipHours, avec l'heure $hour.
strict ($boolean)
S'il est défini sur 1, il respectera les longueurs telles que spécifiées par les exigences de Netscape Netcenter. Il est défini sur 0 par défaut. Utilisez-le si le fichier RSS que vous générez est destiné à Netcenter. strict ne fonctionnera que pour RSS 0.9 et 0.91. Ne l'utilisez pas pour RSS 1.0.
textinput (title=>$title, description=>$desc, name=>$name, link=>$link);
Cet élément RSS est également optionnel. Son utilisation permet aux utilisateurs de soumettre une requête à un programme sur un serveur Web via un formulaire HTML. name est le nom du formulaire HTML et link est l'URL du programme. Le contenu est soumis en utilisant la méthode GET.

L'accès aux valeurs de textinput est le même que pour channel() et image().

add_module(prefix=>$prefix, uri=>$uri)
Ajoute une déclaration d'espace de noms de module à l'objet XML::RSS, vous permettant d'ajouter de la modularité en dehors des modules RSS 1.0 standard. Actuellement, les modules standard Dublin Core (dc) et Syndication (syn) sont prédéfinis pour votre commodité. Le module Taxonomy (taxo) est également pris en charge en interne.

Les modules sont stockés dans la table de hachage %{$obj->{'modules'}} où $obj est une référence à un objet XML::RSS.

Si vous souhaitez ajouter automatiquement les modules que l'analyseur trouve dans les espaces de noms, définissez la variable $XML::RSS::AUTO_ADD à une valeur vraie. Par défaut, la valeur est fausse. (N.B. AUTO_ADD met uniquement à jour la table de hachage %{$obj->{'modules'}}. Il ne fournit pas les autres avantages de l'utilisation de add_module.)

MODULES RSS 1.0

La modularisation basée sur les espaces de noms XML permet une extensibilité compartimentée de RSS 1.0. Les seuls modules livrés "prêts à l'emploi" avec RSS 1.0 sont Dublin Core (http://purl.org/rss/1.0/modules/dc/), Syndication (http://purl.org/rss/1.0/modules/syndication/), et Taxonomy (http://purl.org/rss/1.0/modules/taxonomy/). Consultez la documentation du module approprié pour plus d'informations.

L'ajout d'éléments de ces modules dans XML::RSS est aussi simple que l'ajout d'autres attributs tels que titre, lien et description. La seule différence est la compartimentation de leurs paires clé/valeur dans une table de hachage de second niveau.

$rss->add_item (title=>$title, link=>$link, dc=>{ subject=>$subject, creator=>$creator, date=>$date });

Pour les éléments du module Dublin Core, utilisez la clé 'dc'. Pour les éléments du module Syndication, 'syn'. Pour les éléments du module Taxonomy, 'taxo'. Ce sont les préfixes utilisés dans le document XML RSS lui-même. Ils sont associés à des espaces de noms basés sur des URI appropriés :

syn:  http://purl.org/rss/1.0/modules/syndication/
dc:   http://purl.org/dc/elements/1.1/
taxo: http://purl.org/rss/1.0/modules/taxonomy/

Les éléments Dublin Core ('dc') peuvent pointer vers une référence de tableau, qui à son tour spécifiera plusieurs clés de ce type, et les rendra une après l'autre. Par exemple :

$rss->add_item (
    title => $title,
    link => $link,
    dc => {
        subject=> ["Jungle", "Desert", "Swamp"],
        creator=>$creator,
        date=>$date
    },
);

Les éléments Dublin Core peuvent apparaître dans le canal, l'image, les éléments (item) et le champ de texte (textinput) -- bien qu'il soit rare de les trouver sous image et textinput. Les éléments de syndication sont limités à l'élément canal. Les éléments de taxonomie peuvent apparaître dans les éléments canal ou item.

L'accès aux éléments de module après l'analyse d'un document RSS 1.0 utilisant XML::RSS se fait soit par le préfixe, soit par l'URI de l'espace de noms pour votre commodité.

print $rss->{items}->[0]->{dc}->{subject};
ou
print $rss->{items}->[0]->{'http://purl.org/dc/elements/1.1/'}->{subject};

XML::RSS prend également en charge la modularisation RSS 1.0 "non standard" aux niveaux canal, image, élément et champ de texte. L'analyse d'un document RSS récupère tous les éléments d'autres espaces de noms qui pourraient apparaître. XML::RSS permet également l'inclusion d'espaces de noms arbitraires et d'éléments associés lors de la construction de documents RSS.

Extending XML::RSS

For example, to add elements of a made-up "My" module, first declare the namespace by associating a prefix with a URI:

$rss->add_module(prefix=>'my', uri=>'http://purl.org/my/rss/module/');

Then proceed as usual:

$rss->add_item (title=>$title, link=>$link, my=>{ rating=>$rating });

You can also set the value of the module's prefix to an array reference of "{ el => , val => }" hash-references, in which case duplicate elements are possible:

$rss->add_item(title=>$title, link=>$link, my=> [
  {el => "rating", value => $rating1, }
  {el => "rating", value => $rating2, },
]

Non-standard namespaces are not, however, currently accessible via a simple prefix; access them via their namespace URL like so:

print $rss->{items}->[0]->{'http://purl.org/my/rss/module/'}->{rating};

XML::RSS will continue to provide built-in support for standard RSS 1.0 modules as they appear.
