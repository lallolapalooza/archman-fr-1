NOM

XML::LibXML::DOM - Implémentation DOM de XML::LibXML

DESCRIPTION

XML::LibXML fournit une interface légère pour modifier un nœud de l'arbre de documents généré par le parseur XML::LibXML. Cette interface suit autant que possible la spécification DOM de niveau 3. En plus des fonctions spécifiées, XML::LibXML prend en charge certaines fonctions plus pratiques à utiliser dans l'environnement perl.

Il faut aussi se rappeler que XML::LibXML est une interface vers les nœuds libxml2 qui résident en fait au niveau C de XML::LibXML. Cela signifie que chaque nœud est une référence à une structure différente d'une table de hachage ou d'un tableau perl. Le seul moyen d'accéder aux valeurs de ces structures est via l'interface DOM fournie par XML::LibXML. Cela signifie également qu'on ne peut pas simplement hériter d'un nœud XML::LibXML et ajouter de nouvelles variables membres comme s'il s'agissait de clés de table de hachage.

L'interface DOM de XML::LibXML n'a pas pour but d'implémenter une interface DOM complète comme le fait XML::GDOME et qui est utilisée pour les applications complètes. De plus, elle offre un moyen simple de construire ou de modifier des documents créés par le parseur de XML::LibXML.

Une autre cible de l'interface XML::LibXML est de rendre les interfaces de libxml2 disponibles à la communauté perl. Cela inclut également certaines solutions de contournement pour des fonctionnalités où libxml2 exerce plus de contrôle au niveau C que la plupart des utilisateurs perl n'en ont.

L'une des parties les plus importantes de l'interface DOM de XML::LibXML est que les interfaces tentent de suivre assez strictement la spécification DOM de niveau 3 (http://www.w3.org/TR/DOM-Level-3-Core/). Cela signifie que les noms des fonctions d'interface sont tels que spécifiés par la spécification DOM et non ce que les interfaces Java largement répandues prétendent être la norme. Bien qu'il existe plusieurs fonctions qui n'ont qu'une seule interface conforme à la spécification DOM, XML::LibXML fournit une interface alias supplémentaire de style Java.

De plus, certaines interfaces de fonctions subsistent des premières étapes de XML::LibXML pour des raisons de compatibilité. Ces interfaces sont uniquement pour des raisons de compatibilité. Elles pourraient disparaître dans une future version de XML::LibXML, donc un utilisateur est invité à passer aux fonctions officielles.

Espaces de noms et implémentation DOM de XML::LibXML

L'implémentation DOM de XML::LibXML est limitée par l'implémentation DOM de libxml2 qui traite les espaces de noms légèrement différemment de ce qu'exige la spécification DOM de niveau 2.

Selon la spécification DOM de niveau 2, les espaces de noms des éléments et attributs doivent être persistants, et les nœuds doivent être liés de manière permanente aux URI d'espace de noms lors de leur création ; il doit être possible de manipuler les attributs spéciaux utilisés pour déclarer les espaces de noms XML comme d'autres attributs sans affecter les espaces de noms des autres nœuds. Dans DOM de niveau 2, l'application est responsable de la création cohérente des attributs spéciaux et/ou de la sérialisation correcte du document.

Ceci est à la fois peu pratique, pose des problèmes lors de la sérialisation DOM vers XML, et surtout, semble presque impossible à implémenter sur libxml2.

Dans libxml2, l'URI et le préfixe d'espace de noms d'un nœud sont fournis par un pointeur vers une déclaration d'espace de noms (apparaissant comme un attribut xmlns spécial dans le document XML). Si le préfixe ou l'URI d'espace de noms de la déclaration change, le préfixe et l'URI d'espace de noms de tous les nœuds qui y pointent changent également. De plus, contrairement à DOM, un nœud (élément ou attribut) ne peut être lié à un URI d'espace de noms que s'il existe une déclaration d'espace de noms dans le document vers laquelle pointer.

Par conséquent, l'implémentation DOM actuelle dans XML::LibXML tente de traiter les déclarations d'espace de noms dans un compromis entre la raison, le bon sens, les limitations de libxml2 et la spécification DOM de niveau 2.

Dans XML::LibXML, les attributs spéciaux déclarant les espaces de noms XML sont souvent créés automatiquement, généralement lorsqu'un nœud avec espace de noms est attaché à un document et qu'aucune déclaration existante de l'espace de noms et du préfixe n'est dans la portée pour être réutilisée. À cet égard, l'implémentation DOM de XML::LibXML diffère de la spécification DOM de niveau 2 selon laquelle les attributs spéciaux pour déclarer les espaces de noms XML appropriés ne devraient pas être ajoutés lors de la création d'un nœud avec un préfixe et un URI d'espace de noms.

Les déclarations d'espace de noms sont également créées lorsque la fonction createElementNS() ou createAttributeNS() de XML::LibXML::Document est utilisée. Si un espace de noms n'est pas déclaré sur l'élément racine, l'espace de noms sera déclaré localement pour le nœud nouvellement créé. Dans le cas des attributs, cela peut sembler un peu confusant, car ces nœuds ne peuvent pas avoir de déclarations d'espace de noms eux-mêmes. Dans ce cas, l'espace de noms est appliqué en interne à l'attribut et déclaré plus tard sur le nœud auquel l'attribut est ajouté (si nécessaire).

L'exemple suivant peut expliquer cela un peu :

my $doc = XML::LibXML->createDocument;
my $root = $doc->createElementNS( "", "foo" );
$doc->setDocumentElement( $root );
my $attr = $doc->createAttributeNS( "bar", "bar:foo", "test" );
$root->setAttributeNodeNS( $attr );

Ce morceau de code donnera le document suivant :

<?xml version="1.0"?>
<foo xmlns:bar="bar" bar:foo="test"/>

L'espace de noms est déclaré sur l'élément racine lors de l'appel à setAttributeNodeNS().

Les espaces de noms peuvent également être déclarés explicitement en utilisant la fonction setNamespace() de XML::LibXML::Element. Depuis la version 1.61, ils peuvent également être manipulés avec les fonctions setNamespaceDeclPrefix() et setNamespaceDeclURI() (non disponibles dans DOM). Modifier un URI ou un préfixe d'une déclaration d'espace de noms existante affecte l'URI et le préfixe d'espace de noms de tous les nœuds qui y pointent (c'est-à-dire les nœuds dans leur portée).

Il est également important de répéter la spécification : lorsque vous travaillez avec des espaces de noms, vous devez utiliser les fonctions sensibles aux espaces de noms au lieu des versions simplifiées. Par exemple, vous ne devriez jamais utiliser setAttribute() mais setAttributeNS().
