NOM

XmTextField — La classe TextField

SYNOPSIS

#include <Xm/Xm.h>

DESCRIPTION

Le widget TextField fournit un éditeur de texte sur une seule ligne pour personnaliser les interfaces utilisateur et programmatiques. Il est utilisé pour la saisie de chaînes sur une seule ligne, et pour la saisie de formulaires avec des procédures de vérification. Il fournit à une application un système d'édition cohérent pour les données textuelles.

TextField fournit des listes de rappels séparées pour vérifier le déplacement du curseur d'insertion, la modification du texte et les changements de focus d'entrée. Chacun de ces rappels fournit à la fonction de vérification l'instance du widget, l'événement qui a causé le rappel, et une structure de données spécifique au type de vérification. À partir de ces informations, la fonction peut vérifier si l'application considère qu'il s'agit d'un changement d'état légitime et peut signaler au widget s'il doit continuer l'action.

L'interface utilisateur adapte un nouvel ensemble d'actions. Les raccourcis clavier ont été ajoutés pour le mouvement du curseur d'insertion, la suppression, l'insertion et la sélection de texte.

TextField permet à l'utilisateur de sélectionner des régions de texte. La sélection est basée sur le modèle spécifié dans le Inter-Client Communication Conventions Manual (ICCCM). TextField prend en charge la sélection primaire et secondaire.

TextField utilise les traits XmQTnavigator, XmQTspecifyRenderTable, et XmQTscrollFrame, et détient les traits XmQTaccessTextual XmQTtransfer.

Si une application ou un widget appelle la méthode de trait setValue de XmQTaccessTextual, alors XmTextField appellera XmTextFieldSetString pour définir la valeur de la chaîne.

Comportement de transfert de données

TextField prend en charge le transfert des sélections primaire, secondaire et du presse-papiers, ainsi que le glisser-déposer du texte sélectionné à partir du widget. TextField peut également être la destination des sélections primaire, secondaire et du presse-papiers, et il prend en charge le dépôt de données lors du glisser-déposer sur le widget.

Lorsque les procédures XmNconvertCallback sont appelées, le membre location_data du membre XmConvertCallbackStruct est NULL si le texte sélectionné est transféré. Si le texte entier, et non le texte sélectionné, est transféré, la valeur de ce membre est l'ID du widget TextField.

En tant que source de données, TextField prend en charge les cibles suivantes et les conversions associées de données vers ces cibles :

UTF8_STRING
Le widget transfère le texte sélectionné sous le type UTF8_STRING.
locale
Si la cible locale correspond à la locale du widget, le widget transfère le texte sélectionné dans le codage de la locale.
COMPOUND_TEXT
Le widget transfère le texte sélectionné sous le type COMPOUND_TEXT.
STRING
Le widget transfère le texte sélectionné sous le type STRING.
TEXT
Si le texte sélectionné est entièrement convertible dans le codage de la locale, le widget transfère le texte sélectionné dans le codage de la locale. Sinon, le widget transfère le texte sélectionné sous le type COMPOUND_TEXT.
DELETE
Le widget supprime le texte sélectionné.
_MOTIF_CLIPBOARD_TARGETS
Le widget transfère, sous forme de type ATOM, une liste des cibles vers lesquelles le widget peut convertir les données à placer immédiatement dans le presse-papiers. Celles-ci incluent les cibles suivantes :
•
UTF8_STRING
•
COMPOUND_TEXT
•
Le codage de la locale, si le texte sélectionné est entièrement convertible dans le codage de la locale
•
STRING, si le texte sélectionné est entièrement convertible en STRING
_MOTIF_EXPORT_TARGETS
Le widget transfère, sous forme de type ATOM, une liste des cibles à utiliser comme valeur de XmNexportTargets du DragContext dans un transfert par glisser-déposer. Celles-ci incluent COMPOUND_TEXT, le codage de la locale, STRING, TEXT, UTF8_STRING, BACKGROUND et FOREGROUND.
_MOTIF_LOSE_SELECTION
Le widget effectue les actions suivantes :
•
Lors de la perte de la sélection PRIMARY, il désélectionne le texte sélectionné et appelle les procédures XmNlosePrimaryCallback.
•
Lors de la perte de la sélection SECONDARY, il supprime la surbrillance de la sélection secondaire.
•
Lors de la perte de la sélection _MOTIF_DESTINATION, si le widget n'a pas le focus, il change le curseur pour indiquer que le widget n'est plus la destination.

En tant que source de données, TextField prend également en charge les cibles Motif standard suivantes :

BACKGROUND
Le widget transfère XmNbackground sous le type PIXEL.
CLASS
Le widget trouve le premier shell dans la hiérarchie des widgets qui a une propriété WM_CLASS et transfère le contenu sous forme de texte dans la locale actuelle.
CLIENT_WINDOW
Le widget trouve le premier shell dans la hiérarchie des widgets et transfère sa fenêtre sous le type WINDOW.
COLORMAP
Le widget transfère XmNcolormap sous le type COLORMAP.
FOREGROUND
Le widget transfère XmNforeground sous le type PIXEL.
NAME
Le widget trouve le premier shell dans la hiérarchie des widgets qui a une propriété WM_NAME et transfère le contenu sous forme de texte dans la locale actuelle.
TARGETS
Le widget transfère, sous forme de type ATOM, une liste des cibles qu'il prend en charge. Celles-ci incluent les cibles standard de cette liste. Elles incluent également COMPOUND_TEXT, le codage de la locale, STRING, TEXT et UTF8_STRING.
TIMESTAMP
Le widget transfère l'horodatage utilisé pour acquérir la sélection sous le type INTEGER.
_MOTIF_RENDER_TABLE
Le widget transfère XmNrenderTable s'il existe, sinon la table de rendu de texte par défaut, sous le type STRING.
_MOTIF_ENCODING_REGISTRY
Le widget transfère son registre d'encodage sous le type STRING. La valeur est une liste d'éléments séparés par NULL sous la forme de paires tag-encodage. Cette cible symbolise la cible de transfert pour le registre d'encodage de segments Motif. Les widgets et applications peuvent utiliser ce registre pour enregistrer les formats d'encodage de texte pour des balises de table de rendu spécifiées. Les applications accèdent à ce registre en appelant XmRegisterSegmentEncoding et XmMapSegmentEncoding.

En tant que destination pour les données, TextField choisit une cible et demande la conversion de la sélection vers cette cible. Si le codage de la locale est présent dans la liste des cibles disponibles, TextField choisit une cible demandée parmi les cibles disponibles dans l'ordre de préférence suivant :

1.
TEXT
1.
UTF8_STRING
2.
COMPOUND_TEXT
3.
Le codage de la locale
4.
STRING

Si le codage de la locale n'est pas présent dans la liste des cibles disponibles, TextField choisit une cible demandée parmi les cibles disponibles dans l'ordre de préférence suivant :

1.
UTF8_STRING
1.
COMPOUND_TEXT
2.
STRING

XmNactivateCallback
Spécifie la liste des rappels qui sont appelés lorsque l'utilisateur déclenche un événement qui appelle l'action activate(). Le type de la structure dont l'adresse est passée à ce rappel est XmAnyCallbackStruct. La raison envoyée par le rappel est XmCR_ACTIVATE.
XmNblinkRate
Spécifie la fréquence de clignotement du curseur de texte en millisecondes. Le temps indiqué dans la fréquence de clignotement se rapporte à la durée pendant laquelle le curseur est visible et à la durée pendant laquelle le curseur est invisible (c'est-à-dire, la durée qu'il faudra pour faire clignoter le curseur d'insertion) sera deux fois la fréquence de clignotement). Le curseur ne clignotera pas lorsque la fréquence de clignotement est réglée sur 0 (zéro). La valeur ne doit pas être négative.
XmNcolumns
Spécifie la largeur initiale de la fenêtre de texte comme un nombre entier de caractères. La largeur est égale au nombre de caractères spécifié par cette ressource multiplié par la largeur dérivée de la police spécifiée. Si la valeur de l'espace em est disponible, elle est utilisée. Sinon, la largeur du chiffre "0" est utilisée. Si ce n'est pas disponible, la largeur maximale est utilisée. Pour les polices proportionnelles, le nombre réel de caractères qui tiennent sur une ligne donnée peut être supérieur à la valeur spécifiée.
XmNcursorPosition
Indique la position dans le texte où le curseur d'insertion actuel doit être placé. La position est déterminée par le nombre de caractères à partir du début du texte.
XmNcursorPositionVisible
Si le widget texte a un XmPrintShell comme l'un de ses ancêtres (c'est-à-dire, le widget a été créé sur une connexion de serveur d'impression) alors la valeur par défaut est Faux ; sinon, elle est Vrai.
XmNdestinationCallback
Spécifie une liste de rappels appelés lorsque le widget est la destination d'une opération de transfert. Le type de la structure dont l'adresse est passée à ces rappels est XmDestinationCallbackStruct. La raison est XmCR_OK.
XmNeditable
Lorsqu'il est défini sur Vrai, indique que l'utilisateur peut modifier la chaîne de texte. Une valeur fausse interdira à l'utilisateur de modifier le texte.
Lorsque XmNeditable est utilisé sur un widget, il définit le site de dépôt sur XmDROP_SITE_ACTIVE.
XmNfocusCallback
Spécifie la liste des rappels appelés lorsque TextField accepte le focus d'entrée. Le type de la structure dont l'adresse est passée à ce rappel est XmAnyCallbackStruct. La raison envoyée par le rappel est XmCR_FOCUS.
XmNfontList
Spécifie la liste de polices à utiliser pour TextField. La liste de polices est une structure obsolète, et n'est conservée que pour la compatibilité avec les versions antérieures de Motif. Utilisez la table de rendu (XmNrenderTable) au lieu des listes de polices chaque fois que possible. Si les deux sont spécifiés, la table de rendu aura la priorité. Si cette valeur est NULL lors de l'initialisation, la hiérarchie parente du widget est recherchée pour trouver un ancêtre qui détient le trait XmQTspecifyRenderTable. Si un tel ancêtre est trouvé, la liste de polices est initialisée à la valeur XmTEXT_RENDER_TABLE de l'ancêtre widget. Si aucun ancêtre n'est trouvé, la valeur par défaut dépend de l'implémentation.
TextField recherche dans la liste de polices la première occurrence d'un ensemble de polices qui a un XmFONTLIST_DEFAULT_TAG. Si un élément par défaut n'est pas trouvé, le premier ensemble de polices de la liste de polices est utilisé. Si la liste ne contient aucun ensemble de polices, la première police de la liste de polices sera utilisée. Référez-vous à XmFontList(3) pour plus d'informations sur une structure de liste de polices.
XmNgainPrimaryCallback
Spécifie la liste des rappels qui sont appelés lorsque l'utilisateur déclenche un événement qui fait que le widget texte acquiert la propriété de la sélection primaire. La raison du rappel pour ce rappel est XmCR_GAIN_PRIMARY.
XmNlosePrimaryCallback
Spécifie la liste des rappels qui sont appelés lorsque l'utilisateur déclenche un événement qui fait que le widget texte perd la propriété de la sélection primaire. La raison du rappel pour ce rappel est XmCR_LOSE_PRIMARY.
XmNlosingFocusCallback
Spécifie la liste des rappels qui sont appelés avant que le widget TextField ne perde le focus d'entrée. Le type de la structure dont l'adresse est passée à ce rappel est XmTextVerifyCallbackStruct. La raison envoyée par le rappel est XmCR_LOSING_FOCUS.
XmNmarginHeight
Spécifie la distance entre le bord supérieur de la fenêtre du widget et le texte, et le bord inférieur de la fenêtre du widget et le texte.
XmNmarginWidth
Spécifie la distance entre le bord gauche de la fenêtre du widget et le texte, et le bord droit de la fenêtre du widget et le texte.
XmNmaxLength
Spécifie la longueur maximale de la chaîne de texte qui peut être saisie dans le texte à partir du clavier. Cette valeur doit être non négative. Les chaînes qui sont entrées à l'aide de la ressource XmNvalue ou de la fonction XmTextFieldSetString ignorent cette ressource.
XmNmodifyVerifyCallback
Spécifie la liste des rappels qui est appelée avant que du texte ne soit supprimé de ou inséré dans TextField. Le type de la structure dont l'adresse est passée à ce rappel est XmTextVerifyCallbackStruct. La raison envoyée par le rappel est XmCR_MODIFYING_TEXT_VALUE. Lorsque plusieurs widgets TextField partagent la même source, seul le widget qui initie le changement de source générera le XmNmodifyVerifyCallback.
Si les deux listes de rappels XmNmodifyVerifyCallback et XmNmodifyVerifyCallbackWcs sont enregistrées, la procédure (les procédures) dans la liste XmNmodifyVerifyCallback est toujours exécutée en premier ; et les données résultantes, qui peuvent avoir été modifiées, sont passées aux routines de rappel XmNmodifyVerifyCallbackWcs.

RESOURCES

TextField widget supports the following resources:

XmNautoShowCursorPosition
Specifies whether the cursor position is automatically adjusted to remain visible when text is modified. If this resource is True, the cursor position is automatically adjusted to remain visible when text is modified. The default is True.
XmNcolumns
Specifies the number of characters that the TextField widget should be wide. This resource is used when the widget is created and when the widget is resized. The width is calculated based on the average character width for the widget's font. The value must be greater than or equal to 0. The default is 20.
XmNcursorPosition
Specifies the position of the insertion cursor within the text data. The position is zero-based. The value must be less than or equal to the length of the text in the widget. If a value is provided that is greater than the length of the text, the position is set to the end of the text. The default is 0.
XmNcursorPositionVisible
Specifies whether the cursor position should be visible. If True, the cursor is visible. If False, the cursor is not visible. The default is True.
XmNeditMode
Specifies the editing mode of the TextField widget. Valid values are XmSINGLE_LINE_EDIT and XmMULTI_LINE_EDIT. The default is XmSINGLE_LINE_EDIT.
XmNexpandInsertCursor
Specifies whether the insert cursor should expand to the width of the text it occupies. If True, the cursor is a block that spans the width of the character. If False, the cursor is a vertical line. The default is True.
XmNfontList
Specifies the font list that will be used to display text in the widget. See XmFontList(3) for more information.
XmNinputCallback
Specifies the list of callbacks that is called when the user types a character into the TextField widget. The type of the structure whose address is passed to this callback is XmTextVerifyCallbackStructWcs. The reason sent by the callback is XmCR_INPUT. This callback is called before the text is changed. If the callback sets the doit field to False, the input character is not accepted.
XmNmarginHeight
Specifies the margin, in pixels, between the top and bottom borders of the widget and the text. The default is 5.
XmNmarginWidth
Specifies the margin, in pixels, between the left and right borders of the widget and the text. The default is 5.
XmNmodifySelVerifyCallback
Specifies the list of callbacks called before text is deleted from or inserted into Text. The type of the structure whose address is passed to this callback is XmTextVerifyCallbackStructWcs. The reason sent by the callback is XmCR_MODIFYING_TEXT_VALUE. When multiple TextField widgets share the same source, only the widget that initiates the source change will generate the XmNmodifyVerifyCallbackWcs.
If both XmNmodifyVerifyCallback and XmNmodifyVerifyCallbackWcs are registered callback lists, the procedure(s) in the XmNmodifyVerifyCallback list is always executed first; and the resulting data, which may have been modified, is passed to the XmNmodifyVerifyCallbackWcs callback routines.
XmNmotionVerifyCallback
Specifies the list of callbacks that is called before the insert cursor is moved to a new position. The type of the structure whose address is passed to this callback is XmTextVerifyCallbackStruct. The reason sent by the callback is XmCR_MOVING_INSERT_CURSOR. It is possible for more than one XmNmotionVerifyCallbacks to be generated from a single action.
XmNpendingDelete
Indicates that pending delete mode is on when the Boolean is True. Pending deletion is defined as deletion of the selected text when an insertion is made.
XmNrenderTable
Specifies the render table to be used in deriving a font set or font for displaying text. If both a render table and a font list are specified, the render table will take precedence. If the value of XmNrenderTable is NULL at initialization, the parent hierarchy of the widget is searched for an ancestor that holds the XmQTspecifyRenderTable trait. If such an ancestor is found, the font list is initialized to the XmTEXT_RENDER_TABLE value of the ancestor widget. If no such ancestor is found, the default is implementation dependent.
TextField searches the render table for the first occurrence of a rendition that has the tag _MOTIF_DEFAULT_LOCALE. If a default element is not found, the first rendition in the table is used. Refer to XmRenderTable(3) for more information on the render table structure.
XmNresizeWidth
Indicates that the TextField widget will attempt to resize its width to accommodate all the text contained in the widget when Boolean is True.
XmNselectionArray
Defines the actions for multiple mouse clicks. Each mouse click performed within some time of the previous mouse click will increment the index into this array and perform the defined action for that index. (This "multi-click" time is specified by the operating environment, and varies among different systems. In general, it is usually set to some fraction of a second.) The possible actions are
XmSELECT_POSITION
Resets the insert cursor position
XmSELECT_WORD
Selects a word
XmSELECT_LINE
Selects a line of text
XmNselectionArrayCount
Specifies the number of actions that are defined in the XmNselectionArray resource. The value must not be negative.
XmNselectThreshold
Specifies the number of pixels of motion that is required to select the next character when selection is performed using the click-drag mode of selection. The value must not be negative. This resource also specifies whether a drag should be started and the number of pixels to start a drag when Btn2Down and Btn1Down are integrated.
XmNvalue
Specifies the string value of the TextField widget as a char* data value. Moves the cursor to position 0 unless a value of XmNcursorPosition was explicitly supplied in the argument list. If XmNvalue and XmNvalueWcs are both defined, the value of XmNvalueWcs supersedes that of XmNvalue. XtGetValues returns a copy of the value of the internal buffer and XtSetValues copies the string values into the internal buffer.
XmNvalueChangedCallback
Specifies the list of callbacks that is called after text is deleted from or inserted into TextField. The type of the structure whose address is passed to this callback is XmAnyCallbackStruct. The reason sent by the callback is XmCR_VALUE_CHANGED. The XmNvalueChangedCallback should occur only in pairs with a XmNmodifyVerifyCallback, assuming that the doit flag in the callback structure of the XmNmodifyVerifyCallback is not set to False.
XmNvalueWcs
Specifies the string value of the TextField widget as a wchar_t* data value. Moves the cursor to position 0 unless a value of XmNcursorPosition was explicitly supplied in the argument list.
This resource cannot be specified in a resource file.
If XmNvalue and XmNvalueWcs are both defined, the value of XmNvalueWcs supersedes that of XmNvalue. XtGetValues returns a copy of the value of the internal buffer encoded as a wide character string. XtSetValues copies the value of the wide character string into the internal buffer.
XmNverifyBell
Specifies whether a bell will sound when an action is reversed during a verification callback. The default depends on the value of the ancestor VendorShell's XmNaudibleWarning resource.

XmTextField - un widget de champ de texte

Synopsis

Pour inclure la définition de ce widget, utilisez la commande suivante :

#include <Xm/TextF.h>

Pour créer un widget de champ de texte, utilisez la fonction suivante :

Widget XmCreateTextField(
        Widget          parent,
        char            *name,
        ArgList         arglist,
        Cardinal        num_args );

Le widget de champ de texte prend en charge les ressources suivantes et les utilise comme valeurs pour les arguments de création et les valeurs de ressources des widgets.

Le widget TextField définit une nouvelle structure de rappel à utiliser avec les rappels de vérification. Notez que tous les champs ne sont pas pertinents pour chaque raison de rappel. L'application doit d'abord examiner le champ reason et utiliser uniquement les membres de la structure qui sont valides pour la raison particulière. Les valeurs startPos, endPos et text dans la structure de rappel XmTextVerifyCallbackStruct peuvent être modifiées lors de la réception du rappel, et ces modifications seront reflétées comme la modification apportée à la source du widget TextField. (Par exemple, toutes les frappes peuvent être converties en espaces ou en caractères NULL lorsqu'un mot de passe est saisi dans un widget TextField.) Le programmeur de l'application ne doit pas écraser le champ text, mais doit attacher des données à ce pointeur.

DESCRIPTION

The XmTextField widget provides a single-line text input field. It allows users to enter and edit text. The widget supports cut, copy, and paste operations, as well as drag and drop.

The XmTextField widget provides a text buffer and a set of actions that manipulate the buffer and its display. These actions can be invoked through translations, accelerators, or directly from an application.

CALLBACK STRUCTURES

Several callback structures are used by the XmTextField widget to communicate events and data to application routines. These include:

XmNchangeCallback
This callback is invoked whenever the text in the text field is modified. It is also invoked when the insertion cursor is moved.
XmNmodifyTextCallback
This callback is invoked when the text field's value is about to be modified. This allows the application to validate or modify the incoming text before it is inserted.
XmNdestinationCallback
This callback is invoked when the text field receives a drag-and-drop operation or a paste operation from the clipboard or a selection. It allows the application to determine the type of operation and where the data should be placed.

XmCR_LOSING_FOCUS

The text field is losing the keyboard focus.

reason
Set to XmCR_LOSING_FOCUS.
event
Points to the X event that caused the focus loss.
doit
A pointer to an integer. If set to 1, the focus loss is allowed. If set to 0, the focus loss is disallowed, and the text field will attempt to regain focus.

XmCR_MODIFYING_TEXT_VALUE

The text field's value is about to be modified.

reason
Set to XmCR_MODIFYING_TEXT_VALUE.
event
Points to the X event that triggered the modification. Can be NULL.
doit
A pointer to an integer. If set to 1, the modification is allowed. If set to 0, the modification is disallowed.
currInsert
The current insertion position.
newInsert
The proposed new insertion position.
startPos
The starting position of the text to be modified.
endPos
The ending position of the text to be modified.
text
A pointer to the XmString structure containing the new text to be inserted.

XmCR_MOVING_INSERT_CURSOR

The insertion cursor is being moved within the text field.

reason
Set to XmCR_MOVING_INSERT_CURSOR.
doit
A pointer to an integer. If set to 1, the cursor movement is allowed. If set to 0, the cursor movement is disallowed.
currInsert
The current insertion position.
newInsert
The proposed new insertion position.

The following table describes the reasons for which the individual verification callback structure fields are valid. Note that the event field will never be valid for XmCR_MOVING_INSERT_CURSOR.

Reason Valid Fields
XmCR_LOSING_FOCUS reason, event, doit
XmCR_MODIFYING_TEXT_VALUE reason, event, doit, currInsert, newInsert, startPos, endPos, text
XmCR_MOVING_INSERT_CURSOR reason, doit, currInsert, newInsert

A pointer to the following callback structure is passed to the XmNdestinationCallback procedures:

typedef struct
{
        int reason;
        XEvent *event;
        Atom selection;
        XtEnum operation;
        int flags;
        XtPointer transfer_id;
        XtPointer destination_data;
        XtPointer location_data;
        Time time;
} XmDestinationCallbackStruct;
reason
Indicates why the callback was invoked.
event
Points to the XEvent that triggered the callback. It can be NULL.
selection
Indicates the selection for which data transfer is being requested. Possible values are CLIPBOARD, PRIMARY, SECONDARY, and _MOTIF_DROP.
operation
Indicates the type of transfer operation requested.
•
When the selection is PRIMARY or SECONDARY, possible values are XmMOVE, XmCOPY, and XmLINK.
•
When the selection is CLIPBOARD, possible values are XmCOPY and XmLINK.
•
When the selection is _MOTIF_DROP, possible values are XmMOVE, XmCOPY, XmLINK, and XmOTHER. A value of XmOTHER means that the callback procedure must get further information from the XmDropProcCallbackStruct in the destination_data member.
flags
Indicates whether or not the destination widget is also the source of the data to be transferred. Following are the possible values:
XmCONVERTING_NONE
The destination widget is not the source of the data to be transferred.
XmCONVERTING_SAME
The destination widget is the source of the data to be transferred.
transfer_id
Serves as a unique ID to identify the transfer transaction.
destination_data
Contains information about the destination. When the selection is _MOTIF_DROP, the callback procedures are called by the drop site's XmNdropProc, and destination_data is a pointer to the XmDropProcCallbackStruct passed to the XmNdropProc procedure. When the selection is SECONDARY, destination_data is an Atom representing a target recommmended by the selection owner for use in converting the selection. Otherwise, destination_data is NULL.
location_data
Contains information about the location where data is to be transferred. The value is always NULL when the selection is CLIPBOARD. If the value is NULL, the data is to be inserted at the widget's cursor position. Otherwise, the value is a pointer to an XPoint structure containing the x and y coordinates at the location where the data is to be transferred. Once XmTransferDone procedures start to be called, location_data will no longer be stable.
time
Indicates the time when the transfer operation began.

Routine d'action

Les routines d'action XmTextField sont

activate():
Appelle les callbacks pour XmNactivateCallback. Si le parent est un gestionnaire, transmet l'événement au parent.
backward-character(extend):
Déplace le curseur d'insertion d'un caractère vers la gauche. Cette action peut avoir un comportement différent dans un environnement linguistique de droite à gauche.
Si appelée avec l'argument extend, déplace le curseur d'insertion comme dans le cas sans argument et étend la sélection actuelle.
L'action backward-character() génère des appels aux procédures XmNmotionVerifyCallback avec la valeur de raison XmCR_MOVING_INSERT_CURSOR. Si appelée avec l'argument extend, l'action backward-character() peut générer des appels aux procédures XmNgainPrimaryCallback. Voir la description du callback pour plus d'informations.
backward-word(extend):
Si cette action est appelée sans argument, déplace le curseur d'insertion vers le premier caractère non blanc après le premier caractère blanc à gauche ou après le début de la ligne. Si le curseur d'insertion est déjà au début d'un mot, déplace le curseur d'insertion vers le début du mot précédent. Cette action peut avoir un comportement différent dans une locale autre que la locale C.
Si appelée avec l'argument extend, déplace le curseur d'insertion comme dans le cas sans argument et étend la sélection actuelle.
L'action backward-word() génère des appels aux procédures XmNmotionVerifyCallback avec la valeur de raison XmCR_MOVING_INSERT_CURSOR. Si appelée avec l'argument extend, l'action backward-word() peut générer des appels aux procédures XmNgainPrimaryCallback. Voir la description du callback pour plus d'informations.
beginning-of-line(extend):
Si cette action est appelée sans argument, déplace le curseur d'insertion vers le début de la ligne.
Si appelée avec l'argument extend, déplace le curseur d'insertion comme dans le cas sans argument et étend la sélection actuelle.
L'action beginning-of-line() génère des appels aux XmNmotionVerifyCallback avec la valeur de raison XmCR_MOVING_INSERT_CURSOR. Si appelée avec l'argument extend, l'action beginning-of-line() peut générer des appels aux procédures XmNgainPrimaryCallback. Voir la description du callback pour plus d'informations.
clear-selection():
Efface la sélection actuelle en remplaçant chaque caractère, sauf <Return>, par un caractère <espace>.
L'action clear-selection() génère des appels aux procédures XmNmodifyVerifyCallback avec la valeur de raison XmCR_MODIFYING_TEXT_VALUE et aux procédures XmNvalueChangedCallback avec la valeur de raison XmCR_VALUE_CHANGED.

Si ce widget possède la sélection primaire, cette action copie la sélection dans le presse-papiers. Cette action appelle les procédures XmNconvertCallback, éventuellement plusieurs fois, pour la sélection CLIPBOARD.

Copie la sélection primaire juste avant le curseur d'insertion. Cette action appelle les procédures XmNdestinationCallback pour la sélection PRIMARY et l'opération XmCOPY. Elle appelle les procédures XmNconvertCallback du propriétaire de la sélection, éventuellement plusieurs fois, pour la sélection PRIMARY.

Cette action appelle les procédures XmNdestinationCallback de la destination pour la sélection SECONDARY et l'opération XmCOPY. Les procédures XmNdestinationCallback de la destination ou le composant de destination lui-même invoquent les procédures XmNconvertCallback du propriétaire de la sélection, éventuellement plusieurs fois, pour la sélection SECONDARY.
Si aucune sélection secondaire n'existe, cette action copie la sélection primaire à la position du pointeur. Cette action appelle les procédures XmNdestinationCallback pour la sélection PRIMARY et l'opération XmCOPY. Elle appelle les procédures XmNconvertCallback du propriétaire de la sélection, éventuellement plusieurs fois, pour la sélection PRIMARY.
De plus, l'action copy-to() génère des appels aux procédures XmNmodifyVerifyCallback avec la valeur de raison XmCR_MODIFYING_TEXT_VALUE, aux procédures XmNvalueChangedCallback avec la valeur de raison XmCR_VALUE_CHANGED, et aux procédures XmNmotionVerifyCallback avec la valeur de raison XmCR_MOVING_INSERT_CURSOR. L'action delete-selection() produit des appels aux procédures XmNmodifyVerifyCallback avec la valeur de raison XmCR_MODIFYING_TEXT_VALUE, aux procédures XmNvalueChangedCallback avec la valeur de raison XmCR_VALUE_CHANGED, et aux procédures XmNmotionVerifyCallback avec la valeur de raison XmCR_MOVING_INSERT_CURSOR.
delete-to-end-of-line():
En mode normal, s'il y a une sélection non nulle, supprime la sélection ; sinon, supprime les caractères suivant le curseur d'insertion jusqu'à la prochaine fin de ligne. En mode ajout, s'il y a une sélection non nulle, le curseur n'est pas disjoint de la sélection et XmNpendingDelete est vrai, supprime la sélection ; sinon, supprime les caractères suivant le curseur d'insertion jusqu'à la prochaine fin de ligne. Ceci peut avoir un impact sur la sélection.
L'action delete-to-end-of-line() produit des appels aux procédures XmNmodifyVerifyCallback avec la valeur de raison XmCR_MODIFYING_TEXT_VALUE, et aux procédures XmNvalueChangedCallback avec la valeur de raison XmCR_VALUE_CHANGED.
delete-to-start-of-line():
En mode normal, s'il y a une sélection non nulle, supprime la sélection ; sinon, supprime les caractères précédant le curseur d'insertion jusqu'à le précédent début de ligne. En mode ajout, s'il y a une sélection non nulle, le curseur n'est pas disjoint de la sélection et XmNpendingDelete est vrai, supprime la sélection ; sinon, supprime les caractères précédant le curseur d'insertion jusqu'au précédent début de ligne. Ceci peut avoir un impact sur la sélection.
L'action delete-to-start-of-line() produit des appels aux procédures XmNmodifyVerifyCallback avec la valeur de raison XmCR_MODIFYING_TEXT_VALUE, aux procédures XmNvalueChangedCallback avec la valeur de raison XmCR_VALUE_CHANGED, et aux procédures XmNmotionVerifyCallback avec la valeur de raison XmCR_MOVING_INSERT_CURSOR.
deselect-all():
Désélectionne la sélection courante.
L'action deselect-all() ne produit aucun rappel.
end-of-line(extend):
Si cette action est appelée sans argument, déplace le curseur d'insertion en fin de ligne. Si elle est appelée avec l'argument extend, déplace le curseur d'insertion comme dans le cas sans argument et étend la sélection courante.
L'action end-of-line() produit des appels aux procédures XmNmotionVerifyCallback avec la valeur de raison XmCR_MOVING_INSERT_CURSOR. Si elle est appelée avec l'argument extend, l'action end-of-line() peut produire des appels aux procédures XmNgainPrimaryCallback. Voir la description du rappel pour plus d'informations.
extend-adjust():
Sélectionne le texte de l'ancre à la position du pointeur et désélectionne le texte en dehors de cette plage.
L'action extend-adjust() produit des appels aux procédures XmNmotionVerifyCallback avec la valeur de raison XmCR_MOVING_INSERT_CURSOR. L'action extend-adjust() peut produire des appels aux procédures XmNgainPrimaryCallback. Voir la description du rappel pour plus d'informations.
extend-end():
Déplace le curseur d'insertion à la position du pointeur. L'action extend-end() est utilisée pour valider la sélection. Après que cette action a été effectuée, process-cancel() n'annulera plus la sélection.
L'action extend-end() produit des appels aux procédures XmNmotionVerifyCallback avec la valeur de raison XmCR_MOVING_INSERT_CURSOR. L'action extend-end() peut produire des appels aux procédures XmNgainPrimaryCallback. Voir la description du rappel pour plus d'informations.
extend-start():
Ajuste l'ancre en utilisant la méthode du balancier. Sélectionne le texte de l'ancre à la position du pointeur et désélectionne le texte en dehors de cette plage.
L'action extend-start() peut ne produire aucun rappel, cependant, elle peut produire des appels aux procédures XmNgainPrimaryCallback et XmNmotionVerifyCallback. Voir la description du rappel pour plus d'informations.
forward-character(extend):
Déplace le curseur d'insertion d'un caractère vers la droite. Cette action peut avoir un comportement différent dans un environnement linguistique de droite à gauche.
Si elle est appelée avec l'argument extend, déplace le curseur d'insertion comme dans le cas sans argument et étend la sélection courante.
L'action forward-character() produit des appels aux procédures XmNmotionVerifyCallback avec la valeur de raison XmCR_MOVING_INSERT_CURSOR. Si elle est appelée avec l'argument extend, l'action forward-character() peut produire des appels aux procédures XmNgainPrimaryCallback. Voir la description du rappel pour plus d'informations.
forward-word(extend):
Si cette action est appelée sans argument, déplace le curseur d'insertion au premier caractère d'espacement ou fin de ligne suivant le prochain caractère non-espacement. Si le curseur d'insertion est déjà à la fin d'un mot, déplace le curseur d'insertion à la fin du mot suivant. Cette action peut avoir un comportement différent dans une locale autre que la locale C.
Si elle est appelée avec l'argument extend, déplace le curseur d'insertion comme dans le cas sans argument et étend la sélection courante.
L'action forward-word() produit des appels aux procédures XmNmotionVerifyCallback avec la valeur de raison XmCR_MOVING_INSERT_CURSOR. Si elle est appelée avec l'argument extend, l'action forward-word() peut produire des appels aux procédures XmNgainPrimaryCallback. Voir la description du rappel pour plus d'informations.
grab-focus():
Cette liaison de touche exécute l'action définie dans XmNselectionArray, en fonction du nombre de clics de souris multiples. L'ordre par défaut du tableau de sélection est : un clic pour déplacer le curseur d'insertion à la position du pointeur, deux clics pour sélectionner un mot, et trois clics pour sélectionner une ligne de texte. Un seul clic désélectionne également tout texte sélectionné et place l'ancre à la position du pointeur. Cette action peut avoir un comportement différent dans une locale autre que la locale C.
L'action grab-focus() produit des appels aux procédures XmNmotionVerifyCallback avec la valeur de raison XmCR_MOVING_INSERT_CURSOR.
Help():
Appelle les rappels pour XmNhelpCallback s'il en existe. S'il n'y a pas de rappels d'aide pour ce widget, cette action appelle les rappels d'aide de l'ancêtre le plus proche qui en possède.
key-select(right|left):
Si appelée avec l'argument right, déplace le curseur d'insertion d'un caractère vers la droite et étend
Voici le contenu traduit en français, en conservant la structure du fichier : s la sélection actuelle. Si appelée avec un argument de left, déplace le curseur d'insertion d'un caractère vers la gauche et étend la sélection actuelle. Si appelée sans argument, étend la sélection actuelle.
Notez qu'après une action key-select, la sélection commencera toujours à l'ancre d'origine, et s'étendra à la position indiquée dans l'appel d'action. Si cette nouvelle position est du côté opposé de l'ancre de sélection par rapport à la limite de sélection précédente, la sélection d'origine sera désélectionnée.
L'action key-select() produit des appels aux procédures XmNmotionVerifyCallback avec la valeur de raison XmCR_MOVING_INSERT_CURSOR. L'action key-select() peut également produire des appels aux procédures XmNgainPrimaryCallback. Voir la description du rappel pour plus d'informations.
link-primary():
Place un lien vers la sélection primaire juste avant le curseur d'insertion. Cette action appelle les procédures XmNdestinationCallback pour la sélection PRIMARY et l'opération XmLINK. Le widget TextField lui-même n'effectue aucun transfert ; les procédures XmNdestinationCallback sont responsables de l'insertion du lien vers la sélection primaire et de la prise de toute action connexe.
link-to():
Si une sélection secondaire existe, cette action place un lien vers la sélection secondaire à la position d'insertion du composant de destination. Cette action appelle les procédures XmNdestinationCallback de la destination pour la sélection SECONDARY et l'opération XmLINK.
Si aucune sélection secondaire n'existe, cette action place un lien vers la sélection primaire à la position du pointeur. Cette action appelle les procédures XmNdestinationCallback pour la sélection PRIMARY et l'opération XmLINK.
Le widget TextField lui-même n'effectue aucun transfert ; les procédures XmNdestinationCallback sont responsables de l'insertion du lien vers la sélection primaire ou secondaire et de la prise de toute action connexe.
move-destination():
Déplace le curseur d'insertion à la position du pointeur sans modifier aucune sélection actuelle existante. S'il y a une sélection actuelle, définit le widget comme widget de destination. Cela déplace également le focus du widget pour correspondre au curseur d'insertion.
L'action move-destination() produit des appels aux procédures XmNmotionVerifyCallback avec la valeur de raison XmCR_MOVING_INSERT_CURSOR.
move-to():
Si une sélection secondaire existe, cette action déplace la sélection secondaire vers la position d'insertion du composant de destination. Si la sélection secondaire se trouve dans le widget de destination, et si la sélection secondaire et la sélection primaire se chevauchent, le résultat est indéfini. Cette action appelle les procédures XmNdestinationCallback de la destination pour la sélection SECONDARY et l'opération XmCOPY. Les procédures XmNdestinationCallback de la destination ou le composant de destination lui-même invoquent les procédures XmNconvertCallback du propriétaire de la sélection, éventuellement plusieurs fois, pour la sélection SECONDARY. Si le transfert réussit, cette action appelle ensuite les procédures XmNconvertCallback du propriétaire de la sélection pour la sélection SECONDARY et la cible DELETE.
Si aucune sélection secondaire n'existe, cette action déplace la sélection primaire vers la position du pointeur. Cette action appelle les procédures XmNdestinationCallback pour la sélection PRIMARY et l'opération XmMOVE. Elle appelle les procédures XmNconvertCallback du propriétaire de la sélection, éventuellement plusieurs fois, pour la sélection PRIMARY. Si le transfert réussit, cette action appelle ensuite les procédures XmNconvertCallback du propriétaire de la sélection pour la sélection PRIMARY et la cible DELETE.
De plus, l'action move-to() produit des appels aux procédures XmNmodifyVerifyCallback avec la valeur de raison XmCR_MODIFYING_TEXT_VALUE, aux procédures XmNvalueChangedCallback avec la valeur de raison XmCR_VALUE_CHANGED, et aux procédures XmNmotionVerifyCallback avec la valeur de raison XmCR_MOVING_INSERT_CURSOR. Cette action peut également produire des appels aux procédures XmNgainPrimaryCallback.
next-tab-group():
Traverse vers le groupe d'onglets suivant.
L'action next-tab-group() ne produit aucun rappel, sauf si elle entraîne la perte de focus du widget, auquel cas, les procédures XmNlosingFocusCallback sont appelées avec la valeur de raison XmCR_LOSING_FOCUS.
page-left():
Fait défiler la fenêtre d'affichage d'une page de texte vers la gauche.
L'action page-left() ne produit aucun rappel.
page-right():
Fait défiler la fenêtre d'affichage d'une page de texte vers la droite.
L'action page-right() ne produit aucun rappel.
paste-clipboard():
Colle le contenu du presse-papiers avant le curseur d'insertion. Cette action appelle les procédures XmNdestinationCallback pour la sélection CLIPBOARD et l'opération XmCOPY.
L'action paste-clipboard() produit des appels aux procédures XmNmodifyVerifyCallback avec la valeur de raison XmCR_MODIFYING_TEXT_VALUE, aux procédures XmNvalueChangedCallback avec la valeur de raison XmCR_VALUE_CHANGED, et aux procédures XmNmotionVerifyCallback avec la valeur de raison XmCR_MOVING_INSERT_CURSOR.
prev-tab-group():
Traverse vers le groupe d'onglets précédent.
L'action prev-tab-group() ne produit aucun rappel, sauf si elle entraîne la perte de focus du widget, auquel cas, les procédures XmNlosingFocusCallback sont appelées avec la valeur de raison XmCR_LOSING_FOCUS.
process-bdrag()
Si le pointeur se trouve dans la sélection, cette action démarre une opération de glisser-déposer pour la sélection. Cette action définit le XmNconvertProc du DragContext sur une fonction qui appelle les procédures XmNconvertCallback, éventuellement plusieurs fois, pour la sélection _MOTIF_DROP.
Si aucune sélection n'existe ou si le pointeur est en dehors de la sélection, cette action se prépare à démarrer une sélection secondaire à la position du pointeur.
process-cancel():
Annule l'opération en cours extend-adjust(), secondary-adjust() ou process-bdrag() et laisse l'état de la sélection tel qu'il était avant l'opération ; sinon, et si le parent est un gestionnaire, il transmet l'événement au parent.
secondary-adjust():
Étends la sélection secondaire à la position du pointeur.
L'action secondary-adjust() ne produit aucun rappel.
secondary-start():
Marque le début d'une sélection secondaire.
L'action secondary-start() ne produit aucun rappel.
select-all():
Sélectionne tout le texte.
L'action select-all() peut ne produire aucun rappel, cependant, elle peut produire des appels aux procédures XmNgainPrimaryCallback et XmNmotionVerifyCallback. Voir la description du rappel pour plus d'informations.
self-insert():
Si XmNpendingDelete est True et que le curseur n'est pas disjoint de la sélection actuelle, supprime toute la sélection. Insère le caractère associé à la touche pressée avant le curseur d'insertion.
L'action self-insert() produit des appels aux procédures XmNmodifyVerifyCallback avec la valeur de raison XmCR_MODIFYING_TEXT_VALUE, aux procédures XmNvalueChangedCallback avec la valeur de raison XmCR_VALUE_CHANGED, et aux procédures XmNmotionVerifyCallback avec la valeur de raison XmCR_MOVING_INSERT_CURSOR.
set-anchor():
Réinitialise le point d'ancrage pour les sélections étendues. Réinitialise la destination des actions de sélection secondaire.
L'action set-anchor() ne produit aucun rappel.
toggle-add-mode():
Commute l'état du mode Ajouter.
L'action toggle-add-mode() ne produit aucun rappel.
toggle-overstrike():
Commute l'état du mode d'insertion de texte. Par défaut, les caractères tapés dans le widget TextField sont insérés avant la position du curseur d'insertion. En mode écrasement, les caractères saisis dans le widget TextField remplacent les caractères qui suivent immédiatement le curseur d'insertion. En mode écrasement, lorsque la fin d'une ligne est atteinte, les caractères sont ajoutés à la fin de la ligne.
Les actions de parcours suivantes ne génèrent aucun rappel à moins qu'elles n'entraînent la perte de focus du widget concerné, comme lorsque XmNnavigationType est XmNONE. Dans ce cas, elles produisent des appels aux procédures XmNlosingFocusCallback, avec la valeur de raison XmCR_FOCUS_MOVED.
traverse-home():
Traverse vers le premier widget du groupe d'onglets.
traverse-next():
Traverse vers le widget suivant du groupe d'onglets.
traverse-prev():
Traverse vers le widget précédent du groupe d'onglets.

Comportement Additionnel

Ce widget a le comportement additionnel suivant :

<FocusIn>:
Dessine le curseur d'insertion de manière continue et commence à faire clignoter le curseur.
<FocusOut>:
Affiche le curseur d'insertion sous la forme d'un curseur I stylisé, sauf s'il s'agit du widget de destination.
