XML::LibXML - Interface Perl pour libxml2

DESCRIPTION

Ce module est une interface pour libxml2, fournissant des analyseurs XML et HTML avec des interfaces DOM, SAX et XMLReader, un sous-ensemble important de l'interface DOM Layer 3 et une interface de type XML::XPath pour l'API XPath de libxml2. Le module est divisé en plusieurs packages qui ne sont pas décrits dans cette section ; sauf indication contraire, vous n'avez besoin que de "use XML::LibXML;" dans vos programmes.

Consultez XML::LibXML par l'exemple (http://grantm.github.io/perl-libxml-by-example/) pour un tutoriel.

Pour plus d'informations, veuillez consulter la documentation suivante :

PRISE EN CHARGE DES ENCODAGES DANS XML::LIBXML

Rappelons que depuis la version 5.6.1, Perl distingue les chaînes de caractères (internes encodées en UTF-8) des données dites binaires et leur applique en conséquence soit une sémantique de caractères, soit une sémantique d'octets. Un scalaire représentant une chaîne de caractères se distingue d'une chaîne d'octets par un indicateur spécial (UTF8). Veuillez vous référer à perlunicode pour plus de détails.

L'API de XML::LibXML est conçue pour gérer de nombreux encodages de documents XML de manière complètement transparente, de sorte que l'application utilisant XML::LibXML puisse ignorer l'encodage des documents XML avec lesquels elle travaille. D'autre part, des fonctions comme "XML::LibXML::Document->setEncoding" donnent à l'utilisateur le contrôle sur l'encodage du document.

Pour garantir la transparence et l'uniformité susmentionnées, la plupart des fonctions de XML::LibXML qui travaillent avec des arbres en mémoire acceptent et retournent des données sous forme de chaînes de caractères (c'est-à-dire encodées en UTF-8 avec l'indicateur UTF8 activé), quelle que soit l'encodage original du document ; cependant, les fonctions liées aux opérations d'E/S (c'est-à-dire l'analyse et la sauvegarde) opèrent avec des données binaires (dans l'encodage original du document) en respectant la déclaration d'encodage des documents XML.

Ci-dessous, nous résumons les règles et principes de base concernant l'encodage :

1.
NE PAS appliquer de couches PerlIO liées à l'encodage (":utf8" ou :encoding(...)) aux descripteurs de fichiers qui sont une entrée pour les analyseurs ou une sortie pour un sérialiseur de documents XML (complets). Ceci est dû au fait que la conversion des données vers/depuis la représentation interne des caractères est fournie par libxml2 elle-même, qui doit être en mesure d'appliquer l'encodage spécifié par la déclaration "<?xml version="1.0" encoding="..."?>". Voici un exemple à suivre : 
use XML::LibXML;
# charger
open my $fh, '<', 'file.xml';
binmode $fh; # supprimer toutes les couches PerlIO potentiellement créées par un pragma use open
$doc = XML::LibXML->load_xml(IO => $fh);
# sauvegarder
open my $out, '>', 'out.xml';
binmode $out; # comme ci-dessus
$doc->toFH($out);
# ou
print {$out} $doc->toString();
2.
Toutes les fonctions travaillant avec le DOM acceptent et retournent des chaînes de caractères (encodées en UTF-8 avec l'indicateur UTF8 activé). Par exemple : 
my $doc = XML::LibXML::Document->new('1.0',$some_encoding);
my $element = $doc->createElement($name);
$element->appendText($text);
$xml_fragment = $element->toString(); # retourne une chaîne de caractères
$xml_document = $doc->toString(); # retourne une chaîne d'octets

où $some_encoding est l'encodage du document qui sera utilisé lors de la sauvegarde du document, et $name et $text contiennent des chaînes de caractères (encodées en UTF-8 avec l'indicateur UTF8 activé). Notez que la méthode "toString" renvoie le XML sous forme de chaîne de caractères s'il est appliqué à un nœud autre que le nœud Document, et une chaîne d'octets contenant la déclaration appropriée

<?xml version="1.0" encoding="..."?>

si elle est appliquée à un XML::LibXML::Document.

3.
Les méthodes DOM acceptent également des chaînes binaires dans l'encodage original du document auquel le nœud appartient (UTF-8 est supposé si le nœud n'est attaché à aucun document). L'exploitation de cette fonctionnalité N'EST PAS RECOMMANDÉE car elle est considérée comme une mauvaise pratique. 
my $doc = XML::LibXML::Document->new('1.0','iso-8859-2');
my $text = $doc->createTextNode($some_latin2_encoded_byte_string);
# FONCTIONNE, MAIS N'EST PAS RECOMMANDÉ !

NOTE : Le support de nombreux encodages par libxml2 repose sur la bibliothèque iconv. La liste réelle des encodages pris en charge peut varier d'une plateforme à l'autre. Pour tester si votre plateforme fonctionne correctement avec l'encodage de votre langue, construisez un document simple dans l'encodage particulier et essayez de l'analyser avec XML::LibXML pour voir si l'analyseur produit des erreurs. Des plantages occasionnels ont été signalés sur des plateformes rares qui livrent une version défectueuse d'iconv.

THREADS

Prérequis : Perl >= 5.8.8. XML::LibXML peut être utilisé avec des threads de deux manières :

Par défaut, toutes les classes XML::LibXML utilisent la méthode de classe CLONE_SKIP pour empêcher Perl de copier les objets XML::LibXML::* lorsqu'un nouveau thread est lancé. Dans ce mode, tous les objets XML::LibXML::* sont spécifiques au thread. C'est la façon la plus sûre de travailler avec XML::LibXML dans des threads.

Alternativement, on peut utiliser

use threads;
use XML::LibXML qw(:threads_shared);

pour indiquer que tous les objets de nœud et d'analyse XML::LibXML doivent être partagés entre le thread principal et tout thread lancé à partir de celui-ci. Par exemple, dans

my $doc = XML::LibXML->load_xml(location => $filename);
my $thr = threads->new(sub{
  # code travaillant avec $doc
  1;
});
$thr->join;

la variable $doc fait référence au même objet XML::LibXML::Document dans le thread lancé que dans le thread principal.

Sans utiliser de verrous mutex, des threads parallèles peuvent lire le même document (c'est-à-dire n'importe quel nœud appartenant au document), analyser des fichiers et modifier des documents différents.

Cependant, s'il y a une possibilité que certains threads tentent de modifier un document (ou même de créer de nouveaux nœuds basés sur ce document, par exemple avec "$doc->createElement") que d'autres threads pourraient lire en même temps, l'utilisateur est responsable de la création d'un verrou mutex et de son utilisation *dans le thread* qui modifie et *dans le thread* qui lit :

my $doc = XML::LibXML->load_xml(location => $filename);
my $mutex : shared;
my $thr = threads->new(sub{
   lock $mutex;
   my $el = $doc->createElement('foo');
   # ...
  1;
});
{
  lock $mutex;
  my $root = $doc->documentElement;
  say $root->name;
}
$thr->join;

Notez que libxml2 utilise des dictionnaires pour stocker des chaînes courtes et que ces dictionnaires sont conservés sur un nœud de document. Sans verrous mutex, il pourrait arriver dans l'exemple précédent que le thread modifie le dictionnaire pendant que d'autres threads tentent d'y lire, ce qui pourrait facilement entraîner un crash.

INFORMATIONS SUR LA VERSION

Il est parfois utile de déterminer pour quelle version XML::LibXML a été compilé. Dans la plupart des cas, c'est pour le débogage ou pour vérifier si une installation donnée répond à toutes les fonctionnalités du paquet. Les fonctions XML::LibXML::LIBXML_DOTTED_VERSION et XML::LibXML::LIBXML_VERSION fournissent ces informations de version. Ces deux fonctions transmettent simplement les valeurs des macros du même nom de libxml2. De même, XML::LibXML::LIBXML_RUNTIME_VERSION retourne la version de libxml2 (généralement lié dynamiquement).

XML::LibXML::LIBXML_DOTTED_VERSION
$Version_String = XML::LibXML::LIBXML_DOTTED_VERSION;

Retourne la chaîne de version de la version libxml2 pour laquelle XML::LibXML a été compilé. Ce sera "2.6.2" pour "libxml2 2.6.2".

XML::LibXML::LIBXML_VERSION
$Version_ID = XML::LibXML::LIBXML_VERSION;

Retourne l'ID de version de la version libxml2 pour laquelle XML::LibXML a été compilé. Ce sera "20602" pour "libxml2 2.6.2". Ne confondez pas cet ID de version avec $XML::LibXML::VERSION. Ce dernier contient la version de XML::LibXML elle-même, tandis que le premier contient la version de libxml2 pour laquelle XML::LibXML a été compilé.

XML::LibXML::LIBXML_RUNTIME_VERSION
$DLL_Version = XML::LibXML::LIBXML_RUNTIME_VERSION;

Retourne une chaîne de version de libxml2 qui est (généralement liée dynamiquement) par XML::LibXML. Ce sera "20602" pour libxml2 publié comme "2.6.2" et quelque chose comme "20602-CVS2032" pour une construction CVS de libxml2.

XML::LibXML émet un avertissement si la version de libxml2 qui lui est liée dynamiquement est inférieure à la version de libxml2 contre laquelle il a été compilé.

XML::LIBXML ET XML::GDOME

Remarque : *LES FONCTIONS DÉCRITES ICI SONT ENCORE EXPÉRIMENTALES*

Bien que les deux modules utilisent les capacités XML de libxml2, l'implémentation DOM des deux modules n'est pas compatible. Mais il est toujours possible d'échanger des nœuds d'un DOM à l'autre. Le concept de cet échange est très similaire à la fonction cloneNode() : le nœud particulier est copié au niveau bas vers l'implémentation DOM opposée.

Comme les implémentations DOM ne peuvent pas coexister au sein d'un même document, on est obligé de copier chaque nœud qui doit être utilisé. Parce que vous conservez toujours deux nœuds, cela peut avoir un impact assez important sur l'utilisation de la mémoire de la machine.

XML::LibXML fournit deux fonctions pour exporter ou importer des nœuds GDOME : import_GDOME() et export_GDOME(). Les deux fonctions ont deux paramètres : le nœud et un indicateur pour l'importation récursive. L'indicateur fonctionne comme dans cloneNode().

Les deux fonctions permettent d'exporter et d'importer explicitement des nœuds XML::GDOME. Cependant, XML::LibXML permet également l'importation transparente de nœuds XML::GDOME dans des fonctions telles que appendChild(), insertAfter() et ainsi de suite. Alors que les nœuds natifs sont automatiquement adoptés dans la plupart des fonctions, les nœuds XML::GDOME sont toujours clonés à l'avance. Ainsi, si le nœud d'origine est modifié après l'opération, le nœud dans le document XML::LibXML n'aura pas cette information.

import_GDOME
$libxmlnode = XML::LibXML->import_GDOME( $node, $deep );

Ceci clone un nœud XML::GDOME vers un nœud XML::LibXML explicitement.

export_GDOME
$gdomenode = XML::LibXML->export_GDOME( $node, $deep );

Permet de cloner un nœud XML::LibXML en un nœud XML::GDOME.
