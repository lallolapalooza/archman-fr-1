XML::SAX::ParserFactory(3) Documentation Perl fournie par l'utilisateur XML::SAX::ParserFactory(3)

NOM

XML::SAX::ParserFactory - Obtenir un analyseur SAX

SYNOPIS

use XML::SAX::ParserFactory;
use XML::SAX::XYZHandler;
my $handler = XML::SAX::XYZHandler->new();
my $p = XML::SAX::ParserFactory->parser(Handler => $handler);
$p->parse_uri("foo.xml");
# ou $p->parse_string("<foo/>") ou $p->parse_file($fh);

DESCRIPTION

XML::SAX::ParserFactory est une classe de fabrique pour fournir à une application un analyseur XML SAX2 Perl. Il est similaire à DBI : une interface frontale pour d'autres classes d'analyseurs. Chaque nouvel analyseur SAX2 installé s'enregistrera auprès de XML::SAX, puis sera disponible pour toutes les applications qui utilisent XML::SAX::ParserFactory pour obtenir un analyseur SAX.

Contrairement à DBI cependant, les analyseurs XML/SAX fonctionnent presque tous de la même manière (surtout s'ils héritent de XML::SAX::Base, comme ils le devraient), donc plutôt que de spécifier l'analyseur que vous souhaitez dans l'appel à parser(), XML::SAX dispose de plusieurs méthodes pour choisir automatiquement quel analyseur utiliser :

  • $XML::SAX::ParserPackage

    Si cette variable de paquet est définie, alors ce paquet est require()d et une instance de ce paquet est retournée en appelant la méthode de classe new() dans ce paquet. Si elle ne peut pas être chargée ou s'il y a une erreur, une exception sera levée. La variable peut également contenir un numéro de version :

    $XML::SAX::ParserPackage = "XML::SAX::Expat (0.72)";

    Et le nombre sera traité comme un numéro de version minimum.

  • Fonctionnalités requises

    Il est possible de demander des fonctionnalités aux analyseurs. Par exemple, vous pourriez souhaiter un analyseur qui prend en charge la validation via une DTD. Pour ce faire, utilisez le code suivant :

    use XML::SAX::ParserFactory;
my $factory = XML::SAX::ParserFactory->new();
$factory->require_feature('http://xml.org/sax/features/validation');
my $parser = $factory->parser(...);

    Alternativement, spécifiez les fonctionnalités requises dans l'appel au constructeur de ParserFactory :

    my $factory = XML::SAX::ParserFactory->new(
        RequiredFeatures => {
             'http://xml.org/sax/features/validation' => 1,
             }
        );

    Si les fonctionnalités que vous avez demandées ne sont pas disponibles (par exemple, l'utilisateur pourrait ne pas avoir d'analyseur validant installé), une exception sera levée.

    La liste des analyseurs connus est recherchée dans l'ordre inverse, elle retournera donc toujours le dernier analyseur installé qui prend en charge toutes vos fonctionnalités demandées (Note : cela est susceptible de changer si quelqu'un trouve une meilleure façon de faire fonctionner cela).

  • SAX.ini

    ParserFactory recherche dans @INC un fichier appelé SAX.ini, qui est au format simple :

    # un commentaire ressemble à ceci,
; ou à ceci, et est supprimé n'importe où dans le fichier
key = value # SAX.in contient des paires clé/valeur.

    Tous les espaces blancs sont non significatifs.

    Ce fichier peut contenir soit une ligne :

    ParserPackage = MyParserModule (1.02)

    Où MyParserModule est le module à charger et à utiliser pour l'analyseur, et le nombre entre parenthèses est une version minimale à charger.

    Soit vous pouvez lister les fonctionnalités requises :

    http://xml.org/sax/features/validation = 1

    Et chaque fonctionnalité avec une valeur vraie sera requise.

  • Solution de repli

    Si rien de ce qui précède ne fonctionne, le dernier analyseur installé sur le système de l'utilisateur sera utilisé. Le paquet XML::SAX est livré avec un analyseur XML pur Perl, XML::SAX::PurePerl, de sorte qu'il y aura toujours un analyseur de secours.
