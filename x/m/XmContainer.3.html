NOM

XmContainer — La classe de widget Container

SYNOPSIS

#include <Xm/Container.h>

DESCRIPTION

Container gère les widgets enfants qui possèdent le trait ContainerItem. Ces widgets enfants peuvent être visualisés dans plusieurs formats de disposition différents, sélectionnés à l'aide de types et techniques de sélection variés, et manipulés directement par l'utilisateur.

Trois formats ou vues différents sont pris en charge par le Container. Ils sont spécifiés via la ressource XmNentryViewType :

•
XmLARGE_ICON
•
XmSMALL_ICON
•
XmANY_ICON

Trois types de disposition différents sont pris en charge par le Container. Ils sont spécifiés par la ressource XmNlayoutType :

•
XmSPATIAL
•
XmOUTLINE
•
XmDETAIL

Dans le type de disposition XmSPATIAL, plusieurs autres ressources (XmNspatialStyle, XmNspatialIncludeModel, XmNspatialSnapModel) contrôlent le positionnement des éléments au sein du Container ; un programmeur d'application peut spécifier ces ressources afin que le Container applique strictement la position de chaque élément ou afin que le Container positionne les éléments conformément aux ressources de contrainte spécifiées pour chaque élément. L'utilisateur, cependant, peut modifier la position d'un élément dans le type de disposition XmSPATIAL au sein du Container par manipulation directe ; par exemple, en appuyant sur BTransfer sur l'élément et en faisant glisser puis en relâchant BTransfer sur un emplacement quelconque au sein du Container.

Dans le type de disposition XmOUTLINE, le Container contrôle le positionnement des éléments. Les éléments au sein du Container peuvent avoir des relations parent-enfant entre eux. La ressource XmNentryParent de chaque élément peut spécifier un autre élément du même Container comme son parent ; les éléments ayant une valeur non NULL pour XmNentryParent ne peuvent être affichés que dans le type de disposition XmOUTLINE. Dans le type de disposition XmOUTLINE, les éléments sont positionnés en configuration arborescente avec des lignes de connexion dessinées pour illustrer les relations. Les éléments sont positionnés de haut en bas dans l'ordre spécifié par XmNpositionIndex au sein de leur parent. Le Container positionne un bouton poussoir à côté de chaque élément qui a une relation parentale avec d'autres éléments. Le bouton poussoir contient une pixmap pour illustrer si les éléments enfants sont affichés ou non ; l'utilisateur peut activer le bouton poussoir pour basculer entre l'affichage ou la masquage des éléments enfants. La manipulation directe pour modifier la position de l'élément n'est pas prise en charge dans le type de disposition XmOUTLINE. Notez que la ressource XmNtraversalOn des boutons pousseurs créés par Container est définie à False.

Le type de disposition XmDETAIL est identique à XmOUTLINE, à la différence près que chaque élément peut également afficher des informations supplémentaires sous forme de lignes dans des colonnes avec des en-têtes de colonne spécifiés dans les ressources XmNdetailColumnHeading. Dans chaque ligne d'élément, les informations de détail de l'élément (voir la page de référence sur XmIconGadget pour une description de la ressource XmNentryDetail) sont affichées. Les éléments sont positionnés de haut en bas dans l'ordre spécifié par XmNpositionIndex au sein du parent.

Sélection

Lorsqu'un widget enfant du container est sélectionné, le container spécifie que l'élément doit afficher les informations visuelles appropriées à l'utilisateur via le trait ContainerItem. Le programme applicatif est notifié des changements de sélection via XmNselectionCallback.

Le container utilise quatre politiques de sélection :

•
Unique
•
Navigation
•
Multiple
•
Étendu

En mode Sélection Unique et Navigation, un seul élément peut être sélectionné à la fois. Appuyer sur BSelect sur un élément le sélectionne et désélectionne tout autre élément sélectionné. Appuyer sur BSelect sur un espace vide dans le Container désélectionne tous les éléments. En mode Navigation, faire glisser BSelect déplace la sélection à mesure que le pointeur est déplacé.

En modes Sélection Multiple et Sélection Étendue, un nombre quelconque d'éléments peut être sélectionné en même temps. En mode Sélection Multiple, appuyer et faire glisser BSelect ou BExtend pour spécifier un élément, une plage d'éléments, ou un groupe d'éléments discontinus provoque le basculement des états de sélection de ces éléments. En mode Sélection Étendue, appuyer et faire glisser BSelect pour indiquer un élément, une plage d'éléments, ou un groupe d'éléments discontinus sélectionne ces éléments et désélectionne tous les autres. Appuyer et faire glisser BExtend en mode Sélection Étendue pour indiquer un élément, une plage d'éléments, ou un groupe d'éléments discontinus provoque le basculement des états de sélection de ces éléments.

Plusieurs techniques sont disponibles pour indiquer un élément, une plage d'éléments, ou un groupe d'éléments discontinus en modes Sélection Multiple et Sélection Étendue.

Dans les types de disposition XmSPATIAL et XmOUTLINE, la ressource XmNselectionTechnique spécifie les techniques à utiliser pour indiquer les éléments. La spécification par défaut de XmTOUCH_OVER permet aux techniques Random-Swipe et Marquee d'être utilisées lorsque XmNlayoutStyle est XmSPATIAL. La spécification par défaut de XmTOUCH_OVER permet aux techniques Range-Swipe, Range-Click et Marquee d'être utilisées lorsque XmNlayoutStyle est XmOUTLINE.

Les groupes discontinus d'éléments peuvent être sélectionnés en utilisant la technique Random-Swipe. Dans la technique Random-Swipe, appuyer sur BSelect (ou BExtend) sur un élément et faire glisser BSelect sur d'autres éléments sélectionne tous ces éléments. Seuls les éléments sur lesquels le pointeur est passé sont sélectionnés.

Dans la technique Range-Swipe, l'utilisateur appuie sur BSelect (ou BExtend) sur le premier élément et relâche BSelect sur le dernier élément ; tous les éléments dans la plage entre le premier et le dernier élément sont sélectionnés, que le pointeur soit passé sur eux ou non. Dans la technique Range-Click, l'utilisateur appuie et relâche BSelect (ou BExtend) sur le premier élément, puis appuie et relâche BExtend sur le dernier élément.

Dans la technique Marquee, appuyer sur BSelect (ou BExtend) sur un espace vide dans le Container indique le point de départ d'un rectangle Marquee. Faire glisser BSelect dessine un rectangle Marquee (ligne élastique) entre le point de départ et le pointeur actuel. Tous les éléments entièrement contenus dans le rectangle Marquee sont sélectionnés.

Spécifier XmTOUCH_ONLY pour XmNselectionTechnique force la technique Random-Swipe même lorsque BSelect (ou BExtend) est appuyé sur un espace vide. De même, spécifier XmMARQUEE force la technique Marquee même lorsque BSelect (ou BExtend) est appuyé sur un élément ; puisque l'élément sur lequel la pression est effectuée n'est que partiellement inclus dans le rectangle Marquee, il n'est pas sélectionné. XmMARQUEE_EXTEND_START et XmMARQUEE_EXTEND_BOTH forcent la technique Marquee et font également en sorte que le rectangle s'étende automatiquement autour du premier élément indiqué et, pour XmMARQUEE_EXTEND_BOTH, du dernier élément.

Dans le type de disposition XmDETAIL, les techniques Range-Swipe et Range-Click sont disponibles pour indiquer une plage d'éléments à sélectionner.

Container utilise les traits XmQTcontainerItem, XmQTscrollFrame, et XmQTspecifyRenderTable et détient les traits XmQTcontainer et XmQTtransfer.

Comportement de transfert de données

Container prend en charge le glisser-déposer d'éléments sélectionnés depuis le widget. Selon la valeur de XmNprimaryOwnership, Container peut également prendre en charge la sélection primaire.

En tant que source de données, Container prend en charge les cibles suivantes et les conversions de données associées vers ces cibles :

locale
Si la cible locale correspond à la locale du widget, le widget transfère les éléments sélectionnés dans l'encodage de la locale. La valeur pour chaque élément transféré, sauf le dernier, inclut un séparateur final. La valeur de chaque élément est le XmNlabelString de l'élément.
COMPOUND_TEXT
Le widget transfère les éléments sélectionnés sous le type COMPOUND_TEXT. La valeur pour chaque élément transféré, sauf le dernier, inclut un séparateur final. La valeur de chaque élément est le XmNlabelString de l'élément.
DELETE

PIXMAP
Le widget transfère une liste des identifiants de pixmap des éléments sélectionnés sous le type DRAWABLE.
STRING
Le widget transfère les éléments sélectionnés sous le type STRING. La valeur pour chaque élément transféré, sauf le dernier, inclut un séparateur final. Chaque valeur d'élément est le XmNlabelString de l'élément.
TEXT
Si les éléments sélectionnés sont entièrement convertibles dans le codage de la locale, le widget transfère les éléments sélectionnés dans le codage de la locale. Sinon, le widget transfère les éléments sélectionnés sous le type COMPOUND_TEXT. La valeur pour chaque élément transféré, sauf le dernier, inclut un séparateur final. Chaque valeur d'élément est le XmNlabelString de l'élément.
_MOTIF_CLIPBOARD_TARGETS
Le widget transfère, sous le type ATOM, une liste des cibles qu'il prend en charge pour un transfert immédiat pour la sélection CLIPBOARD. Celles-ci incluent _MOTIF_COMPOUND_STRING et PIXMAP. Si les éléments sélectionnés sont entièrement convertibles en STRING, celles-ci incluent également STRING ; sinon, elles incluent également COMPOUND_TEXT et UTF8_STRING.
_MOTIF_COMPOUND_STRING
Le widget transfère les éléments sélectionnés sous forme de chaîne composée au format Byte Stream. La valeur pour chaque élément transféré, sauf le dernier, inclut un séparateur final. Chaque valeur d'élément est le XmNlabelString de l'élément.
UTF8_STRING
Le widget transfère les éléments sélectionnés sous le type UTF8_STRING. La valeur pour chaque élément transféré, sauf le dernier, inclut un séparateur final. Chaque valeur d'élément est le XmNlabelString de l'élément.
_MOTIF_DEFERRED_CLIPBOARD_TARGETS
Le widget transfère, sous le type ATOM, une liste des cibles qu'il prend en charge pour un transfert différé pour la sélection CLIPBOARD. Ce widget ne fournit actuellement aucune cible pour _MOTIF_DEFERRED_CLIPBOARD_TARGETS.
_MOTIF_DRAG_OFFSET
Le widget transfère une liste de deux nombres de 16 bits, de type INTEGER, représentant un décalage x et y pour un élément en cours de glissement. Ce décalage est calculé de telle sorte que, si le décalage était ajouté aux coordonnées x et y du site de dépôt, et que le pixmap glissé était placé à cette position, cela correspondrait à la position où l'utilisateur s'attendrait à ce que le pixmap soit placé, en fonction de l'icône de glissement utilisée sur le site de dépôt.
_MOTIF_EXPORT_TARGETS
Le widget transfère, sous le type ATOM, une liste des cibles à utiliser comme valeur de XmNexportTargets du DragContext dans un transfert glisser-déposer. Celles-ci incluent _MOTIF_COMPOUND_STRING, PIXMAP, COMPOUND_TEXT, le codage de la locale, STRING, TEXT, BACKGROUND, FOREGROUND, et UTF8_STRING.

En tant que source de données, Container prend également en charge les cibles Motif standard suivantes :

BACKGROUND
Le widget transfère XmNbackground sous le type PIXEL.
CLASS
Le widget recherche le premier shell dans la hiérarchie des widgets qui possède une propriété WM_CLASS et transfère le contenu sous forme de texte dans la locale actuelle.
CLIENT_WINDOW
Le widget recherche le premier shell dans la hiérarchie des widgets et transfère sa fenêtre sous le type WINDOW.
COLORMAP
Le widget transfère XmNcolormap sous le type COLORMAP.
FOREGROUND
Le widget transfère XmNforeground sous le type PIXEL.
NAME
Le widget recherche le premier shell dans la hiérarchie des widgets qui possède une propriété WM_NAME et transfère le contenu sous forme de texte dans la locale actuelle.
TARGETS
Le widget transfère, sous le type ATOM, une liste des cibles qu'il prend en charge. Celles-ci incluent les cibles standard de cette liste. Elles incluent également _MOTIF_COMPOUND_STRING, PIXMAP, COMPOUND_TEXT, le codage de la locale, STRING, TEXT, et UTF8_STRING.
TIMESTAMP
Le widget transfère l'horodatage utilisé pour acquérir la sélection sous le type INTEGER.
_MOTIF_RENDER_TABLE
Le widget transfère XmNrenderTable s'il existe, sinon la table de rendu de texte par défaut, sous le type STRING.
_MOTIF_ENCODING_REGISTRY
Le widget transfère son registre d'encodage sous le type STRING. La valeur est une liste d'éléments séparés par NULL sous forme de paires balise-encodage. Cette cible symbolise la cible de transfert pour le registre d'encodage de segment Motif. Les widgets et les applications peuvent utiliser ce registre pour enregistrer des formats d'encodage de texte pour des balises de table de rendu spécifiées. Les applications accèdent à ce registre en appelant XmRegisterSegmentEncoding et XmMapSegmentEncoding.

En tant que destination de données, Container ne prend en charge que le dépôt d'éléments glissés depuis le même widget. Les sous-classes et les procédures XmNdestinationCallback sont responsables de tout autre transfert de données vers le widget.

Classes

Container hérite du comportement, des ressources et des traits des classes Core, Composite, Constraint et XmManager.

Le pointeur de classe est xmContainerWidgetClass.

Le nom de la classe est XmContainer.

XmNautomaticSelection
Indique si le Conteneur invoque les rappels de sélection lorsque chaque élément est sélectionné (ou basculé) ou si les rappels de sélection ne sont pas invoqués jusqu'à ce que l'utilisateur ait terminé les actions de sélection (par exemple, l'utilisateur a relâché le bouton de la souris). Il peut prendre l'une des valeurs suivantes :
XmAUTO_SELECT
Invoque automatiquement les rappels de sélection lorsque chaque élément est sélectionné ou basculé. Cela peut aussi être la valeur TRUE.
XmNO_AUTO_SELECT
Retarde les rappels de sélection jusqu'à ce que l'utilisateur ait terminé les actions de sélection. Cela peut aussi être la valeur FALSE.
XmNcollapsedStatePixmap
Spécifie le pixmap à afficher sur un PushButton à côté d'un élément du Conteneur avec des éléments enfants, lorsque XmNoutlineButtonPolicy est XmOUTLINE_BUTTON_PRESENT. XmNcollapsedStatePixmap indique que les éléments enfants ne sont pas affichés. S'il est défini sur XmUNSPECIFIED_PIXMAP, un pixmap par défaut montrant une flèche pointant vers le haut est utilisé.
XmNconvertCallback
Spécifie une liste de rappels à appeler lorsque le Conteneur est invité à convertir une sélection. Le type de la structure dont l'adresse est passée à ces rappels est XmConvertCallbackStruct. La raison est XmCR_OK.
XmNdefaultActionCallback
Spécifie une liste de rappels à appeler lorsque l'utilisateur double-clique sur un élément ou appuie sur <Entrée> ou <Retour> sur un élément. La structure de rappel est XmContainerSelectCallbackStruct. La raison est XmCR_DEFAULT_ACTION.
XmNdestinationCallback
Spécifie une liste de rappels à appeler lorsque le Conteneur est la destination d'une opération de transfert. Le type de la structure dont l'adresse est passée à ces rappels est XmDestinationCallbackStruct. La raison est XmCR_OK.
XmNdetailColumnHeading
Spécifie un tableau de XmStrings à afficher comme en-têtes de colonnes. S'il est NULL, ou si XmNlayoutType n'est pas XmDETAIL, aucun en-tête n'est affiché.
XmNdetailColumnHeadingCount
Spécifie un nombre de XmStrings dans le tableau spécifié pour XmNdetailColumnHeading.
XmNdetailOrder
Spécifie un tableau de Cardinals qui indiquent quelles informations de détail de colonne, et dans quel ordre, chaque enfant du Conteneur affichera ses informations de détail. Cette ressource est ignorée si XmNlayoutType n'est pas XmDETAIL. S'il est NULL, le comportement par défaut est déterminé par XmNdetailOrderCount.
XmNdetailOrderCount
Spécifie un nombre de Cardinals dans le tableau spécifié pour XmNdetailOrder. Si XmNdetailOrder est NULL et XmNdetailOrderCount n'est pas 0, alors chaque enfant du Conteneur affiche ses informations de détail dans l'ordre de la colonne 1 au numéro de colonne XmNdetailOrderCount. XmNdetailTabList
Indique une XmTabList spécifiant le début de chaque colonne dans la disposition XmDETAIL. Si cette ressource est définie sur NULL, alors le Conteneur calcule une XmTabList. Cette ressource est ignorée si XmNlayoutType n'est pas XmDETAIL.

XmSMALL_ICON

Spécifie un Pixel accessible par les enfants du conteneur et utilisé pour indiquer que l'enfant est dans un état sélectionné. En plus d'une valeur Pixel, les valeurs symboliques suivantes peuvent être spécifiées :
XmDEFAULT_SELECT_COLOR

Un pointeur vers la structure suivante est passé aux procédures de rappel XmNconvertCallback :

typedef struct
{
        int reason;
        XEvent  *event;
        Atom selection;
        Atom target;
        XtPointer source_data;
        XtPointer location_data;
        int flags;
        XtPointer parm;
        int parm_format;
        unsigned long parm_length;
        int status;
        XtPointer value;
        Atom type;
        int format;
        unsigned long length;
} XmConvertCallbackStruct;
reason
Indique pourquoi le rappel a été invoqué.
event
Pointe vers le XEvent qui a déclenché le rappel. Il peut être NULL.
selection
Indique la sélection pour laquelle la conversion est demandée. Les valeurs possibles sont CLIPBOARD, PRIMARY, SECONDARY et _MOTIF_DROP.
target
Indique la cible de la conversion.
source_data
Contient des informations sur la source de la sélection. Lorsque la sélection est _MOTIF_DROP, source_data est le DragContext. Sinon, c'est NULL.
location_data
Contient des informations sur l'emplacement des données à convertir. Si la valeur est NULL, les données à transférer consistent en la sélection actuelle du widget. Sinon,
ou l'identifiant de widget du Container si tous les éléments sont transférés.
flags
Indique le statut de la conversion. Les valeurs possibles sont les suivantes :
XmCONVERTING_NONE
Ce drapeau est actuellement inutilisé.
XmCONVERTING_PARTIAL
Le widget cible a pu être converti, mais certaines données ont été perdues.
XmCONVERTING_SAME
La cible de conversion est la source des données à transférer.
XmCONVERTING_TRANSACT
Ce drapeau est actuellement inutilisé.
parm
Contient les données de paramètres pour cette cible. Si aucune donnée de paramètre n'existe, la valeur est NULL.
Lorsque selection est CLIPBOARD et target est _MOTIF_CLIPBOARD_TARGETS ou _MOTIF_DEFERRED_CLIPBOARD_TARGETS, la valeur est l'opération demandée (XmCOPY, XmMOVE, ou XmLINK).
parm_format
Spécifie si les données dans parm doivent être considérées comme une liste de quantités de type char, short, ou long. Les valeurs possibles sont 0 (quand parm est NULL), 8 (quand les données dans parm doivent être considérées comme une liste de char), 16 (quand les données dans parm doivent être considérées comme une liste de short), ou 32 (quand les données dans parm doivent être considérées comme une liste de long). Notez que parm_format symbolise un type de données, et non le nombre de bits dans chaque élément de la liste. Par exemple, sur certaines machines, un parm_format de 32 signifie que les données dans parm doivent être considérées comme une liste de quantités de 64 bits, et non de 32 bits.
parm_length
Spécifie le nombre d'éléments de données dans parm, où chaque élément a la taille spécifiée par parm_format. Lorsque parm est NULL, la valeur est 0.
status
Un membre IN/OUT qui spécifie le statut de la conversion. La valeur initiale est XmCONVERT_DEFAULT. La procédure de rappel peut définir ce membre sur l'une des valeurs suivantes :
XmCONVERT_DEFAULT
La procédure de conversion de la classe du widget, le cas échéant, est appelée après le retour des procédures de rappel. Si la procédure de conversion de la classe du widget produit des données, elle écrase les données fournies par les procédures de rappel dans le membre value.
XmCONVERT_MERGE
La procédure de conversion de la classe du widget, le cas échéant, est appelée après le retour des procédures de rappel. Si la procédure de conversion de la classe du widget produit des données, elle ajoute ses données aux données fournies par les procédures de rappel dans le membre value. Cette valeur est destinée à être utilisée avec des cibles qui résultent en des listes de données, telles que TARGETS.
XmCONVERT_DONE
La procédure de rappel a terminé la conversion avec succès. La procédure de conversion de la classe du widget, le cas échéant, n'est pas appelée après le retour des procédures de rappel.
XmCONVERT_REFUSE
La procédure de rappel a terminé le processus de conversion sans accomplir la conversion demandée. La procédure de conversion de la classe du widget, le cas échéant, n'est pas appelée après le retour des procédures de rappel.
value
Un paramètre IN/OUT qui contient toutes les données produites par la procédure de rappel en résultat de la conversion. La valeur initiale est NULL. Si la procédure de rappel définit ce membre, elle doit s'assurer que les membres type, format, et length correspondent aux données dans value. La procédure de rappel est responsable de l'allocation, mais pas de la libération, de la mémoire lorsqu'elle définit ce membre.
type
Un paramètre IN/OUT qui indique le type des données dans le membre value. La valeur initiale est INTEGER.
format
Un paramètre IN/OUT qui spécifie si les données dans value doivent être considérées comme une liste de quantités de char, short, ou long. La valeur initiale est 8. La procédure de rappel peut définir ce membre sur 8 (pour une liste de char), 16 (pour une liste de short), ou 32 (pour une liste de long).
length
Un membre IN/OUT qui spécifie le nombre d'éléments de données dans value, où chaque élément a la taille symbolisée par format. La valeur initiale est 0 (zéro).

The Container action routines are described below. The current selections are always shown with the background color specified by the XmNselectColor resource.

ContainerActivate():
This action calls XmNdefaultActionCallback with reason XmCR_DEFAULT_ACTION.
ContainerBeginExtend():
Simply returns if XmNselectionPolicy is XmSINGLE_SELECT or XmBROWSE_SELECT. Simply returns if XmNlayoutType is XmSPATIAL.
Otherwise, this action sets the selection state of all items between the anchor item and the item under the pointer to the selection state of the anchor item. The location cursor is moved to the item under the pointer. If XmNautomaticSelection is XmAUTO_SELECT, the XmNselectionCallback(s) is called with either XmCR_MULTIPLE_SELECT or XmCR_EXTENDED_SELECT as the reason depending on XmNselectionPolicy, and with auto_selection_type XmAUTO_CHANGE.
ContainerBeginSelect():
If this is a second ContainerBeginSelect() action that has occurred within the time specified by the display's multiclick time, this action calls XmNdefaultActionCallback with reason XmCR_DEFAULT_ACTION and returns.
Otherwise, processing depends on the value of XmNselectionPolicy as follows:
XmSINGLE_SELECT
This action deselects all items and toggles the item (if any) under the pointer.
XmBROWSE_SELECT
This action deselects all items and toggles the item (if any) under the pointer. This item is now the anchor item for further selection. If XmNautomaticSelection is XmAUTO_SELECT and a change in any item's selection state is made, the XmNselectionCallback(s) is called with reason XmCR_BROWSE_SELECT and auto_selection_type XmAUTO_BEGIN.
XmMULTIPLE_SELECT
If the pointer is over an item and XmNselectionTechnique is not XmMARQUEE, this action toggles the selection state of that item. The item becomes the anchor item for further selection. If XmNselectionTechnique is XmMARQUEE, XmMARQUEE_EXTEND_START, or XmMARQUEE_EXTEND_BOTH, this action sets the start point for the Marquee rectangle. If XmNselectionTechnique is XmMARQUEE_EXTEND_START or XmMARQUEE_EXTEND_BOTH and the pointer is over an item, this action draws the Marquee rectangle around the item. If XmNautomaticSelection is XmAUTO_SELECT, the XmNselectionCallback(s) is called with reason XmCR_MULTIPLE_SELECT and auto_selection_type XmAUTO_BEGIN.
XmEXTENDED_SELECT
All items are first deselected. Processing is then identical to the case where XmNselectionPolicy is XmMULTIPLE_SELECT, except that XmCR_EXTENDED_SELECT is the callback reason given if XmNselectionCallback is called.
ContainerBeginToggle():
Simply returns if XmNselectionPolicy is XmSINGLE_SELECT or XmBROWSE_SELECT.
Otherwise, if the pointer is over an item and XmNselectionTechnique is not XmMARQUEE, this action toggles the selection state of that item. The item becomes the anchor item for further selection. If XmNselectionTechnique is XmMARQUEE, XmMARQUEE_EXTEND_START, or XmMARQUEE_EXTEND_BOTH this action sets the start point for the Marquee rectangle. If XmNselectionTechnique is XmMARQUEE_EXTEND_START or XmMARQUEE_EXTEND_BOTH and the pointer is over an item, this action draws the Marquee rectangle around the item. If
XmNautomaticSelection est XmAUTO_SELECT, XmNselectionCallback(s) est appelé avec XmCR_MULTIPLE_SELECT ou XmCR_EXTENDED_SELECT comme raison, selon XmNselectionPolicy, et avec auto_selection_type XmAUTO_BEGIN.
ContainerButtonMotion():
Le traitement dépend de la valeur de XmNselectionPolicy, comme suit :
XmSINGLE_SELECT
Cette action retourne simplement à l'appelant.
XmBROWSE_SELECT
Retourne simplement si cette action suit une action ContainerBeginExtend() ou ContainerBeginToggle().
Si le pointeur n'est plus sur l'élément d'ancrage actuel, cette action inverse la sélection de l'élément d'ancrage actuel, puis inverse la sélection de l'élément sous le pointeur (le cas échéant) et en fait le nouvel élément d'ancrage pour le traitement ultérieur. Si XmNautomaticSelection est XmAUTO_SELECT et qu'une modification de l'état de sélection d'un élément est effectuée, le XmNselectionCallback(s) est appelé avec la raison XmCR_BROWSE_SELECT et auto_selection_type XmAUTO_MOTION.
XmMULTIPLE_SELECT
Si une action précédente a défini un point de départ pour le rectangle Marquee, cette action dessine le rectangle Marquee entre la position actuelle du pointeur et le point de départ du Marquee. Si XmNselectionTechnique est XmMARQUEE_EXTEND_BOTH et que le pointeur est sur un élément, le point final du rectangle Marquee est étendu pour inclure l'élément. Les états de sélection de tous les éléments à l'intérieur du rectangle Marquee sont inversés pour correspondre à l'état de l'élément d'ancrage.
Si aucun point de départ de rectangle Marquee n'est défini et que le pointeur est sur un élément, le traitement dépend de la ressource XmNlayoutType. L'élément d'ancrage de l'action précédente est utilisé. Si XmNlayoutType est XmSPATIAL, l'état de sélection de l'élément sous le pointeur est inversé pour correspondre à l'état de sélection de l'élément d'ancrage. Si XmNlayoutType est XmOUTLINE ou XmDETAIL, l'état de sélection de tous les éléments entre l'élément d'ancrage et l'élément sous le pointeur sont inversés pour correspondre à l'état de sélection de l'élément d'ancrage.
Si XmNautomaticSelection est XmAUTO_SELECT et qu'une modification de l'état de sélection d'un élément est effectuée, le XmNselectionCallback(s) est appelé avec la raison XmCR_MULTIPLE_SELECT et auto_selection_type XmAUTO_MOTION.
XmEXTENDED_SELECT
Le traitement est identique au cas où XmNselectionPolicy est XmMULTIPLE_SELECT, sauf que XmCR_EXTENDED_SELECT est la raison du rappel donnée si XmNselectionCallback est appelé.
ContainerCancel():
Si une sélection est en cours, cette action restaure les états de sélection de tous les éléments à leur état avant le début de la sélection. Si XmNautomaticSelection est vrai et qu'une modification de l'état de sélection d'un élément est effectuée, le XmNselectionCallback est appelé avec la raison XmCR_BROWSE_SELECT, XmMULTIPLE_SELECT, ou XmCR_EXTENDED_SELECT selon la ressource XmNselectionPolicy et auto_selection_type XmAUTO_CANCEL.
ContainerDeselectAll():
Cette action désélectionne tous les éléments et appelle XmNselectionCallback avec une raison dépendant de XmNselectionPolicy.
ContainerEndExtend():
Retourne simplement si XmNselectionPolicy est XmSINGLE_SELECT ou XmBROWSE_SELECT. Retourne simplement si XmNlayoutType est XmSPATIAL.
Sinon, si XmNautomaticSelection est XmNO_AUTO_SELECT, XmNselectionCallback(s) est appelé avec XmCR_MULTIPLE_SELECT ou XmCR_EXTENDED_SELECT comme raison, selon XmNselectionPolicy. Si XmNautomaticSelection est XmAUTO_SELECT et qu'aucune modification n'est apportée à l'état de sélection d'un élément par cette action, XmNselectionCallback(s) est appelé avec XmCR_MULTIPLE_SELECT ou XmCR_EXTENDED_SELECT comme raison, selon XmNselectionPolicy et auto_selection_type XmAUTO_CHANGE. Si XmNautomaticSelection est XmAUTO_SELECT et que cette action n'apporte aucune modification à l'état de sélection d'un élément, XmNselectionCallback(s) est appelé avec XmCR_MULTIPLE_SELECT ou XmCR_EXTENDED_SELECT comme raison, selon XmNselectionPolicy et auto_selection_type XmAUTO_NO_CHANGE.
ContainerEndSelect():
Le traitement dépend de la valeur de XmNselectionPolicy, comme suit :
XmSINGLE_SELECT
Cette action appelle XmNselectionCallback avec la raison XmCR_SINGLE_SELECT.
XmBROWSE_SELECT
Si le pointeur n'est plus sur l'élément d'ancrage actuel, cette action inverse la sélection de l'élément d'ancrage actuel, puis inverse la sélection de l'élément sous le pointeur (le cas échéant). Si XmNautomaticSelection est XmNO_AUTO_SELECT, le XmNselectionCallback(s) est appelé avec la raison XmCR_BROWSE_SELECT. Si XmNautomaticSelection est XmAUTO_SELECT et qu'une modification de l'état de sélection d'un élément est effectuée, XmNselectionCallback(s) est appelé avec la raison XmCR_BROWSE_SELECT et auto_selection_type XmAUTO_CHANGE. Si XmNautomaticSelection est XmAUTO_SELECT et qu'aucune modification n'est apportée à l'état de sélection d'un élément par cette action, XmNselectionCallback(s) est appelé avec la raison XmCR_BROWSE_SELECT et auto_selection_type XmAUTO_NO_CHANGE.
XmMULTIPLE_SELECT
Cette action effectue d'abord le même traitement que l'action ContainerButtonMotion(), à l'exception du fait que XmNselectionCallback n'est pas appelé. Si XmNautomaticSelection est XmNO_AUTO_SELECT, le XmNselectionCallback(s) est appelé avec la raison XmCR_MULTIPLE_SELECT. Si XmNautomaticSelection est XmAUTO_SELECT et qu'une modification de l'état de sélection d'un élément est effectuée, le XmNselectionCallback(s) est appelé avec la raison XmCR_MULTIPLE_SELECT et auto_selection_type XmAUTO_CHANGE. Si XmNautomaticSelection est XmAUTO_SELECT et que cette action n'apporte aucune modification à l'état de sélection d'un élément, le XmNselectionCallback(s) est appelé avec la raison XmCR_MULTIPLE_SELECT et auto_selection_type XmAUTO_NO_CHANGE.
XmEXTENDED_SELECT
Cette action effectue d'abord le même traitement que l'action ContainerButtonMotion(), à l'exception du fait que XmNselectionCallback n'est pas appelé. Si XmNautomaticSelection est XmNO_AUTO_SELECT, le XmNselectionCallback(s) est appelé avec la raison XmCR_EXTENDED_SELECT. Si XmNautomaticSelection est XmAUTO_SELECT et qu'une modification de l'état de sélection d'un élément est effectuée, XmNselectionCallback(s) est appelé avec la raison XmCR_EXTENDED_SELECT et auto_selection_type XmAUTO_CHANGE. Si XmNautomaticSelection est XmAUTO_SELECT et que cette action n'apporte aucune modification à l'état de sélection d'un élément, XmNselectionCallback(s) est appelé avec la raison XmCR_EXTENDED_SELECT et auto_selection_type XmAUTO_NO_CHANGE.
ContainerEndToggle():
Retourne simplement si XmNselectionPolicy est XmSINGLE_SELECT ou XmBROWSE_SELECT. Si XmNselectionPolicy est XmMULTIPLE_SELECT ou XmEXTENDED_SELECT, cette action effectue le même traitement que l'action ContainerEndSelect().
ContainerEndTransfer()::
Si le temps écoulé depuis une action ContainerStartTransfer() dépasse la période spécifiée par le temps de clic multiple de l'affichage, cette action retourne.
Sinon, l'action ContainerPrimaryCopy(), ContainerPrimaryLink(), ou ContainerPrimaryMove() est appelée, en fonction de la valeur du paramètre d'opération enregistré par ContainerStartTransfer().
ContainerExpandOrCollapse(Left|Right|Collapse|Expand):
Cette action modifie la valeur de XmNoutlineState du widget de focus actuel. Si la valeur de l'argument est Collapse ou Left, la valeur de la ressource XmNoutlineState est définie sur XmCOLLAPSED. Si la valeur de l'argument est Expand ou Right, la valeur de la ressource XmNoutlineState est définie sur XmEXPANDED.
Si l'argument est Left ou Right et que la disposition est de droite à gauche, alors la définition de la valeur XmNoutlineState est inversée par rapport à celle décrite dans le paragraphe précédent.
Retourne simplement si XmNlayoutType est XmSPATIAL.
ContainerExtend():
Le traitement dépend de la valeur de XmNselectionPolicy, comme suit :
Si la politique de sélection est XmSINGLE_SELECT ou XmBROWSE_SELECT, cette action retourne. Si XmNlayoutType est XmSPATIAL, cette action retourne.
Si la politique de sélection est XmMULTIPLE_SELECT, cette action définit l'état de sélection de tous les éléments entre l'élément d'ancrage et le curseur de texte à l'état de sélection de l'élément d'ancrage.
Si la politique de sélection est XmEXTENDED_SELECT et que le conteneur est en mode Normal, cette action désélectionne tous les éléments et sélectionne tous les éléments entre l'élément d'ancrage et le curseur de texte. Si la politique de sélection est XmEXTENDED_SELECT et que le conteneur est en mode Ajout, cette action définit l'état de sélection de tous les éléments entre l'élément d'ancrage et le curseur de texte à l'état de sélection de l'élément d'ancrage.
XmNselectionCallback est appelé avec la raison XmCR_MULTIPLE_SELECT ou XmCR_EXTENDED_SELECT selon
XmNselectionPolicy.
ContainerExtendCursor(Gauche|Droite|Haut|Bas):
Le traitement dépend de la valeur de XmNselectionPolicy, comme suit :
Si la politique de sélection est XmSINGLE_SELECT ou XmBROWSE_SELECT, cette action est ignorée. Si XmNlayoutType est XmSPATIAL, cette action est ignorée.
Cette action déplace le curseur de localisation d'un élément dans la direction indiquée, si possible. Si la valeur de la chaîne d'argument est First (Premier) ou Last (Dernier), cette action déplace le curseur de localisation vers l'élément indiqué. Pour les autres valeurs de la chaîne d'argument, le curseur de localisation n'est pas affecté.
Si la politique de sélection est XmMULTIPLE_SELECT, cette action définit l'état de sélection de tous les éléments situés entre l'élément d'ancrage et le curseur de localisation sur l'état de sélection de l'élément d'ancrage.
Si la politique de sélection est XmEXTENDED_SELECT et que le conteneur est en mode Normal, cette action désélectionne tous les éléments et sélectionne tous les éléments situés entre l'élément d'ancrage et le curseur de localisation. Si la politique de sélection est XmEXTENDED_SELECT et que le conteneur est en mode Ajout, cette action définit l'état de sélection de tous les éléments situés entre l'élément d'ancrage et le curseur de localisation sur l'état de sélection de l'élément d'ancrage.
XmNselectionCallback est appelé avec la raison XmCR_MULTIPLE_SELECT ou XmCR_EXTENDED_SELECT en fonction de XmNselectionPolicy.
ContainerHandleBtn1Down(chaîne)
Lorsque la ressource XmNenableBtn1Transfer de Display n'est pas XmOFF, les actions de sélection et de transfert sont intégrées sur <Btn1>. Si le pointeur se trouve sur un élément non sélectionné ou sur l'arrière-plan, l'élément est d'abord sélectionné avant le début du transfert. Sinon, si l'élément est déjà sélectionné, le transfert commence. La valeur de chaîne peut être l'une des actions suivantes :
•
ContainerBeginSelect,Copy
•
ContainerBeginToggle,Copy
•
ContainerNoop,Link
•
ContainerBeginExtend,Move
ContainerHandleBtn1Motion(chaîne)
Lorsque la ressource XmNenableBtn1Transfer de Display n'est pas XmOFF, les actions de sélection et de transfert sont intégrées sur <Btn1>. Lorsque cette action est appelée et qu'une sélection est en cours, un glisser-déposer est effectué. Sinon, l'action par défaut spécifiée dans chaîne est effectuée. La valeur de chaîne peut être ContainerButtonMotion.
ContainerHandleBtn1Up(chaîne)
Si un transfert Btn1 était en cours, alors lorsque cette action est appelée, ce transfert est annulé. Sinon, l'action par défaut spécifiée dans chaîne est effectuée. La valeur de chaîne peut être l'une des actions suivantes :
•
ContainerEndSelect
•
ContainerEndToggle
•
ContainerEndExtend
ContainerHandleBtn2Down(chaîne)
Lorsque la ressource XmNenableBtn1Transfer de Display a la valeur XmBUTTON2_ADJUST, les actions d'extension de sélection sont liées sur <Btn2>. Sinon, l'action effectuée dépend de la valeur de chaîne, qui peut être l'une des actions suivantes :
•
ContainerStartTransfer,Copy
•
ContainerStartTransfer,Link
•
ContainerStartTransfer,Move
ContainerHandleBtn2Motion(chaîne)
Lorsque la ressource XmNenableBtn1Transfer de Display n'est pas XmBUTTON2_ADJUST et qu'une sélection est en cours, un glisser-déposer est effectué. Sinon, l'action par défaut effectuée dépend de la valeur de chaîne, qui peut être ContainerButtonMotion.
ContainerHandleBtn2Up(chaîne)
Lorsque la ressource XmNenableBtn1Transfer de Display a la valeur XmBUTTON2_ADJUST, cette action met fin à une extension. Sinon, l'action effectuée dépend de la valeur de chaîne, qui peut être ContainerEndTransfer.
ContainerMoveCursor(Gauche|Droite|Haut|Bas|First|Last):
Si l'argument est Gauche, Droite, Haut ou Bas, cette action déplace le curseur de localisation d'un élément dans la direction indiquée, si possible. Si la valeur de la chaîne d'argument est First (Premier) ou Last (Dernier), cette action déplace le curseur de localisation vers l'élément indiqué. Tous les autres arguments sont ignorés.
Si XmNselectionPolicy est XmBROWSE_SELECT, ou si XmNselectionPolicy est XmEXTENDED_SELECT et que le conteneur est en mode Normal, cette action désélectionne tous les éléments, sélectionne l'élément au niveau du curseur de localisation et appelle XmNselectionCallback avec la raison dépendant de XmNselectionPolicy.
ContainerPrimaryCopy():
Cette action demande que les données de sélection principale soient copiées dans le conteneur. Cette action appelle les procédures XmNdestinationCallback pour la sélection PRIMARY (principale) et l'opération XmCOPY. Par défaut, le conteneur n'effectue aucun transfert, et la copie de la sélection est la responsabilité des procédures XmNdestinationCallback.
ContainerPrimaryLink():
Cette action demande que les données de sélection principale soient liées au conteneur. Cette action appelle les procédures XmNdestinationCallback pour la sélection PRIMARY (principale) et l'opération XmLINK. Par défaut, le conteneur n'effectue aucun transfert, et la liaison de la sélection est la responsabilité des procédures XmNdestinationCallback.
ContainerPrimaryMove():
Cette action demande que les données de sélection principale soient copiées dans le conteneur et supprimées de la source principale. Cette action appelle les procédures XmNdestinationCallback pour la sélection PRIMARY (principale) et l'opération XmMOVE. Par défaut, le conteneur n'effectue aucun transfert, et le déplacement de la sélection est la responsabilité des procédures XmNdestinationCallback. Si le transfert réussit, cette action appelle ensuite les procédures XmNconvertCallback du propriétaire de la sélection pour la sélection PRIMARY (principale) et la cible DELETE (supprimer).
ContainerSelect():
Le traitement dépend de la valeur de XmNselectionPolicy, comme suit :
Si la politique de sélection est XmSINGLE_SELECT ou XmBROWSE_SELECT, cette action désélectionne tous les éléments et sélectionne l'élément au niveau du curseur de localisation.
Si la politique de sélection est XmMULTIPLE_SELECT, cette action bascule l'état de sélection de l'élément au niveau du curseur de localisation. Cet élément devient l'élément d'ancrage pour les sélections ultérieures.
Si la politique de sélection est XmEXTENDED_SELECT et que le conteneur est en mode Normal, cette action désélectionne tous les éléments et sélectionne l'élément au niveau du curseur de localisation. Si la politique de sélection est XmEXTENDED_SELECT et que le conteneur est en mode Ajout, cette action bascule l'état de sélection de l'élément au niveau du curseur de localisation. L'élément sélectionné/basculé devient l'élément d'ancrage pour les sélections ultérieures.
XmNselectionCallback est appelé avec la raison dépendant de XmNselectionPolicy.
ContainerSelectAll():
Si XmNselectionPolicy est XmSINGLE_SELECT ou XmBROWSE_SELECT, cette action désélectionne tous les éléments et sélectionne l'élément à la position du curseur de localisation.
Si XmNselectionPolicy est XmMULTIPLE_SELECT ou XmEXTENDED_SELECT, cette action sélectionne tous les éléments.
XmNselectionCallback est appelé avec la raison dépendant de la valeur de XmNselectionCallback.
ContainerStartTransfer(Copier|Déplacer|Lier):
Cette action enregistre l'événement et l'opération spécifiés dans la chaîne d'argument pour une utilisation par les actions ultérieures. Si aucune action ContainerEndTransfer() ne se produit dans le délai spécifié par le temps de double-clic de l'affichage et si XmNlayoutType est XmSPATIAL, cette action crée un DragContext et démarre un transfert par glisser-déposer en utilisant chaîne pour spécifier l'opération de transfert. Si aucune chaîne d'argument n'est spécifiée, Copy (Copier) est la valeur par défaut.
À moins que le comportement par défaut de glisser-déposer n'ait été substitué par une procédure XmNconvertCallback, si l'opération de dépôt se produit dans le conteneur, alors l'élément (les éléments) en cours de glissement est (sont) déplacé(s) à la position de l'opération de dépôt. Si l'élément ciblé par l'opération de glisser n'est pas dans l'état sélectionné, alors seul cet élément est déplacé. Si l'élément est dans l'état sélectionné, cependant, tous les éléments dans l'état sélectionné sont déplacés.
ContainerToggleMode():
Si XmNselectionPolicy est XmEXTENDED_SELECT, cette action bascule le conteneur entre le mode Normal et le mode Ajout.
