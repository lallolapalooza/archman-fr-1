XML::LibXML::Element(3) Documentation Perl fournie par l'utilisateur XML::LibXML::Element(3)

NOM

XML::LibXML::Element - Classe XML::LibXML pour les nœuds d'élément

SYNOPSIS

use XML::LibXML;
# Seules les méthodes spécifiques aux nœuds d'élément sont listées ici,
# voir la page man de XML::LibXML::Node pour les autres méthodes
$node = XML::LibXML::Element->new( $name );
$node->setAttribute( $aname, $avalue );
$node->setAttributeNS( $nsURI, $aname, $avalue );
$avalue = $node->getAttribute( $aname );
$avalue = $node->getAttributeNS( $nsURI, $aname );
$attrnode = $node->getAttributeNode( $aname );
$attrnode = $node->getAttributeNodeNS( $namespaceURI, $aname );
$node->removeAttribute( $aname );
$node->removeAttributeNS( $nsURI, $aname );
$boolean = $node->hasAttribute( $aname );
$boolean = $node->hasAttributeNS( $nsURI, $aname );
@nodes = $node->getChildrenByTagName($tagname);
@nodes = $node->getChildrenByTagNameNS($nsURI,$tagname);
@nodes = $node->getChildrenByLocalName($localname);
@nodes = $node->getElementsByTagName($tagname);
@nodes = $node->getElementsByTagNameNS($nsURI,$localname);
@nodes = $node->getElementsByLocalName($localname);
$node->appendWellBalancedChunk( $chunk );
$node->appendText( $PCDATA );
$node->appendTextNode( $PCDATA );
$node->appendTextChild( $childname , $PCDATA );
$node->setNamespace( $nsURI , $nsPrefix, $activate );
$node->setNamespaceDeclURI( $nsPrefix, $newURI );
$node->setNamespaceDeclPrefix( $oldPrefix, $newPrefix );

MÉTHODES

La classe hérite de XML::LibXML::Node. La documentation des méthodes héritées n'est pas listée ici.

De nombreuses fonctions listées ici sont documentées de manière exhaustive dans la spécification DOM Level 3 (http://www.w3.org/TR/DOM-Level-3-Core/). Veuillez vous référer à la spécification pour une documentation complète.

new
$node = XML::LibXML::Element->new( $name );

Cette fonction crée un nouveau nœud non lié à un DOM.

setAttribute
$node->setAttribute( $aname, $avalue );

Cette méthode définit ou remplace l'attribut du nœud $aname par la valeur $avalue

setAttributeNS
$node->setAttributeNS( $nsURI, $aname, $avalue );

Version prenant en compte les namespaces de "setAttribute", où $nsURI est un URI de namespace, $aname est un nom qualifié, et $avalue est la valeur. L'URI de namespace peut être nul (vide ou indéfini) afin de créer un attribut qui n'a pas de namespace.

L'implémentation actuelle diffère de DOM dans les aspects suivants

Si un attribut portant le même nom local et le même URI de namespace existe déjà sur l'élément, mais que son préfixe diffère de celui de $aname, alors cette fonction est censée changer le préfixe (indépendamment des déclarations de namespace et des collisions possibles). Cependant, l'implémentation actuelle fait plutôt le contraire. Si un préfixe est déclaré pour l'URI de namespace dans la portée de l'attribut, alors le préfixe déjà déclaré est utilisé, sans tenir compte du préfixe spécifié dans $aname. Si aucun préfixe n'est déclaré pour le namespace, la fonction essaie de déclarer le préfixe spécifié dans $aname et échoue si le préfixe est déjà utilisé par un autre namespace.

Selon la spécification DOM Level 2, cette méthode peut aussi être utilisée pour créer ou modifier des attributs spéciaux utilisés pour déclarer des namespaces XML (qui appartiennent au namespace "http://www.w3.org/2000/xmlns/" et ont le préfixe ou le nom "xmlns"). Cela devrait fonctionner à partir de la version 1.61, mais encore une fois, l'implémentation diffère de la spécification DOM dans le point suivant : si une déclaration du même préfixe de namespace existe déjà sur l'élément, alors la modification de sa valeur via cette méthode change automatiquement le namespace de tous les éléments et attributs dans sa portée. C'est parce que dans libxml2, l'URI de namespace d'un élément n'est pas statique mais est calculé à partir d'un pointeur vers un attribut de déclaration de namespace.

getAttribute
$avalue = $node->getAttribute( $aname );

Si $node a un attribut dont le nom est $aname, la valeur de cet attribut sera retournée.

getAttributeNS
$avalue = $node->getAttributeNS( $nsURI, $aname );

Récupère la valeur d'un attribut par nom local et URI de namespace.

getAttributeNode
$attrnode = $node->getAttributeNode( $aname );

Récupère un nœud d'attribut par nom. Si aucun attribut avec le nom donné n'existe, "undef" est retourné.

getAttributeNodeNS
$attrnode = $node->getAttributeNodeNS( $namespaceURI, $aname );

Récupère un nœud d'attribut par nom local et URI de namespace. Si aucun attribut avec le nom local et l'URI de namespace donnés n'existe, "undef" est retourné.

removeAttribute
$node->removeAttribute( $aname );

La méthode supprime l'attribut $aname de la liste d'attributs du nœud, si l'attribut peut être trouvé.

removeAttributeNS
$node->removeAttributeNS( $nsURI, $aname );

Version avec namespace de "removeAttribute"

hasAttribute
$boolean = $node->hasAttribute( $aname );

Cette fonction teste si l'attribut nommé est défini pour le nœud. Si l'attribut est spécifié, TRUE (1) sera retourné, sinon la valeur de retour est FALSE (0).

hasAttributeNS
$boolean = $node->hasAttributeNS( $nsURI, $aname );

Version avec namespace de "hasAttribute"

getChildrenByTagName
@nodes = $node->getChildrenByTagName($tagname);

La fonction donne un accès direct à tous les éléments enfants du nœud courant avec un nom de balise donné, où le nom de balise est un nom qualifié, c'est-à-dire qu'en cas d'utilisation de namespace, il peut se composer d'un préfixe et d'un nom local. Cette fonction rend les choses beaucoup plus faciles si l'on doit traiter de grands ensembles de données. Un nom de balise spécial '*' peut être utilisé pour correspondre à n'importe quel nom.

Si cette fonction est appelée dans un contexte SCALAR, elle retourne le nombre d'éléments trouvés.

getChildrenByTagNameNS
@nodes = $node->getChildrenByTagNameNS($nsURI,$tagname);

Version avec namespace de "getChildrenByTagName". Un URI de namespace spécial '*' correspond à n'importe quel URI de namespace, auquel cas la fonction se comporte comme "getChildrenByLocalName".

Si cette fonction est appelée dans un contexte SCALAR, elle retourne le nombre d'éléments trouvés.

getChildrenByLocalName
@nodes = $node->getChildrenByLocalName($localname);

La fonction donne un accès direct à tous les éléments enfants du nœud courant avec un nom local donné. Elle rend les choses beaucoup plus faciles si l'on doit traiter de grands ensembles de données. Un "nom local" spécial '*' peut être utilisé pour correspondre à n'importe quel nom local.

Si cette fonction est appelée dans un contexte SCALAR, elle retourne le nombre d'éléments trouvés.

getElementsByTagName
@nodes = $node->getElementsByTagName($tagname);

La fonction donne un accès direct à tous les éléments enfants du nœud courant avec un nom de balise donné, où le nom de balise est un nom qualifié, c'est-à-dire qu'en cas d'utilisation de namespace, il peut se composer d'un préfixe et d'un nom local. Cette fonction rend les choses beaucoup plus faciles si l'on doit traiter de grands ensembles de données. Un nom de balise spécial '*' peut être utilisé pour correspondre à n'importe quel nom.

Si cette fonction est appelée dans un contexte SCALAR, elle retourne le nombre d'éléments trouvés.

getElementsByTagNameNS
@nodes = $node->getElementsByTagNameNS($nsURI,$localname);

Version avec namespace de "getElementsByTagName". Un URI de namespace spécial '*' correspond à n'importe quel URI de namespace, auquel cas la fonction se comporte comme "getElementsByLocalName".

Si cette fonction est appelée dans un contexte SCALAR, elle retourne le nombre d'éléments trouvés.

getElementsByLocalName
@nodes = $node->getElementsByLocalName($localname);

La fonction donne un accès direct à tous les éléments enfants du nœud courant avec un nom local donné. Elle rend les choses beaucoup plus faciles si l'on doit traiter de grands ensembles de données. Un "nom local" spécial '*' peut être utilisé pour correspondre à n'importe quel nom local.

Si cette fonction est appelée dans un contexte SCALAR, elle retourne le nombre d'éléments trouvés.

appendWellBalancedChunk
$node->appendWellBalancedChunk( $chunk );

Cette méthode insère un morceau de XML bien équilibré à la fin du nœud courant. La chaîne de caractères doit être un morceau de XML bien équilibré, c'est-à-dire qu'elle ne doit pas nécessairement être un document XML valide complet.

Cette méthode est utile pour insérer des fragments XML, tels que ceux renvoyés par des appels à "XML::LibXML::Parser::parse_chunk".

appendText
$node->appendText( $PCDATA );

Crée ou remplace le contenu textuel du nœud courant. Si le nœud courant est déjà un nœud texte, son contenu est remplacé par $PCDATA. Si le nœud courant est un élément, un nouveau nœud texte est créé et inséré comme dernier enfant de cet élément. Si des nœuds texte existaient déjà, ils sont supprimés.

appendTextNode
$node->appendTextNode( $PCDATA );

Crée un nouveau nœud texte avec le contenu $PCDATA et l'insère comme dernier enfant du nœud courant.

appendTextChild
$node->appendTextChild( $childname , $PCDATA );

Crée un nouveau nœud élément avec le nom $childname, lui ajoute un nœud texte avec le contenu $PCDATA, et insère le nouveau nœud élément comme dernier enfant du nœud courant.

setNamespace
$node->setNamespace( $nsURI , $nsPrefix, $activate );

Déclare un nouveau namespace pour le nœud courant. $nsURI est l'URI du namespace, $nsPrefix est le préfixe à utiliser, et $activate est un booléen indiquant si ce namespace doit être activé pour le nœud courant.

Si $activate est vrai, un attribut d'espace de noms est créé ou modifié pour le nœud courant, associant $nsPrefix à $nsURI. Si l'attribut existe déjà avec un préfixe différent, il est mis à jour.

Si $activate est faux, la déclaration de namespace est supprimée pour le nœud courant et sa portée.

Si $nsPrefix est vide, le namespace par défaut est affecté.

setNamespaceDeclURI
$node->setNamespaceDeclURI( $nsPrefix, $newURI );

Change l'URI d'une déclaration de namespace existante. $nsPrefix est le préfixe de la déclaration à modifier, et $newURI est le nouvel URI.

Si $nsPrefix est vide, cela modifie l'URI du namespace par défaut.

setNamespaceDeclPrefix
$node->setNamespaceDeclPrefix( $oldPrefix, $newPrefix );

Renomme une déclaration de namespace existante. $oldPrefix est le préfixe actuel, et $newPrefix est le nouveau préfixe.

Si $oldPrefix est vide, cela change le préfixe du namespace par défaut, ce qui n'est généralement pas autorisé dans XML.

= $node->getElementsByTagName($tagname);

Cette fonction fait partie de la spécification. Elle récupère tous les descendants d'un nœud ayant un nom de balise donné, où "tagname" est un nom qualifié, c'est-à-dire qu'en cas d'utilisation d'espaces de noms, il peut se composer d'un préfixe et d'un nom local. Un nom de balise spécial "tagname" '*' peut être utilisé pour faire correspondre n'importe quel nom de balise.

Dans un contexte SCALAR, cette fonction retourne un objet XML::LibXML::NodeList.

getElementsByTagNameNS
@nodes = $node->getElementsByTagNameNS($nsURI,$localname);

Version pour les espaces de noms de "getElementsByTagName" telle que trouvée dans la spécification DOM. Un nom local spécial "localname" '*' peut être utilisé pour faire correspondre n'importe quel nom local et "nsURI" '*' peut être utilisé pour faire correspondre n'importe quel URI d'espace de noms.

Dans un contexte SCALAR, cette fonction retourne un objet XML::LibXML::NodeList.

getElementsByLocalName
@nodes = $node->getElementsByLocalName($localname);

Cette fonction ne se trouve pas dans la spécification DOM. C'est un mélange de getElementsByTagName et getElementsByTagNameNS. Elle récupérera toutes les balises correspondant au nom local donné. Cela permet de sélectionner des balises ayant le même nom local à travers les frontières des espaces de noms.

Dans un contexte SCALAR, cette fonction retourne un objet XML::LibXML::NodeList.

appendWellBalancedChunk
$node->appendWellBalancedChunk( $chunk );

Il est parfois nécessaire d'ajouter une chaîne XML codée à un nœud. appendWellBalancedChunk fera l'affaire pour vous. Mais cela ne se fait que si la chaîne est "bien formée".

Notez que appendWellBalancedChunk() n'est conservé que pour des raisons de compatibilité. Il utilise implicitement

my $fragment = $parser->parse_balanced_chunk( $chunk );
 $node->appendChild( $fragment );

Cette forme est plus explicite et facilite le contrôle du flux d'un script.

appendText
$node->appendText( $PCDATA );

alias pour appendTextNode().

appendTextNode
$node->appendTextNode( $PCDATA );

Cette fonction enveloppante vous permet d'ajouter directement une chaîne à un nœud d'élément.

appendTextChild
$node->appendTextChild( $childname , $PCDATA );

Un peu similaire à "appendTextNode" : Elle vous permet de définir directement un élément qui ne contient qu'un "nœud de texte" en spécifiant le nom et le contenu textuel.

setNamespace
$node->setNamespace( $nsURI , $nsPrefix, $activate );

setNamespace() permet d'appliquer un espace de noms à un élément. La fonction prend trois paramètres : 1. l'URI de l'espace de noms, qui est requis, et les deux valeurs optionnelles : le préfixe, tel qu'il doit être utilisé dans les éléments enfants ou les attributs, ainsi que le paramètre supplémentaire d'activation. Si le préfixe n'est pas fourni, indéfini ou vide, cette fonction essaie de créer une déclaration de l'espace de noms par défaut.

Le paramètre d'activation est très utile : s'il est défini sur FALSE (0), une nouvelle déclaration d'espace de noms est simplement ajoutée à l'élément, tandis que l'espace de noms de l'élément lui-même n'est pas modifié. Néanmoins, `activate` est défini sur TRUE (1) par défaut. Dans ce cas, l'espace de noms est utilisé comme l'espace de noms effectif du nœud. Cela signifie que le préfixe de l'espace de noms est ajouté au nom du nœud et si un espace de noms était déjà actif pour le nœud, il sera remplacé (mais sa déclaration ne sera pas supprimée du document). Une nouvelle déclaration d'espace de noms n'est créée que si nécessaire (c'est-à-dire si l'élément est déjà dans la portée d'une déclaration d'espace de noms associant le préfixe à l'URI de l'espace de noms, alors cette déclaration est réutilisée).

L'exemple suivant peut clarifier cela :

my $e1 = $doc->createElement("bar");
 $e1->setNamespace("http://foobar.org", "foo")

résulte en

<foo:bar xmlns:foo="http://foobar.org"/>

tandis que

my $e2 = $doc->createElement("bar");
 $e2->setNamespace("http://foobar.org", "foo",0)

ne résulte qu'en

<bar xmlns:foo="http://foobar.org"/>

En utilisant $activate == 0, il est possible de créer plusieurs déclarations d'espace de noms sur un seul élément.

La fonction échoue s'il est nécessaire de créer une déclaration associant le préfixe à l'URI de l'espace de noms mais que l'élément porte déjà une déclaration avec le même préfixe mais un URI d'espace de noms différent.

setNamespaceDeclURI
$node->setNamespaceDeclURI( $nsPrefix, $newURI );

EXPÉRIMENTAL EN 1.61 !

Cette fonction manipule directement une déclaration d'espace de noms existante sur un élément. Elle prend deux paramètres : le préfixe par lequel elle recherche la déclaration d'espace de noms et un nouvel URI d'espace de noms qui remplace sa valeur précédente.

Elle retourne 1 si la déclaration d'espace de noms a été trouvée et modifiée, 0 sinon.

Tous les éléments et attributs (même ceux précédemment non liés au document) pour lesquels la déclaration d'espace de noms détermine leur espace de noms appartiennent au nouvel espace de noms après la modification.

Si le nouvel URI est indéfini ou vide, les nœuds n'ont plus d'espace de noms ni de préfixe après la modification. Les déclarations d'espace de noms une fois nullifiées de cette manière n'apparaissent plus dans la sortie sérialisée (mais restent dans le document pour l'intégrité interne des structures de données de libxml2).

Cette fonction ne fait PAS partie de l'API DOM.

setNamespaceDeclPrefix
$node->setNamespaceDeclPrefix( $oldPrefix, $newPrefix );

EXPÉRIMENTAL EN 1.61 !

Cette fonction manipule directement une déclaration d'espace de noms existante sur un élément. Elle prend deux paramètres : l'ancien préfixe par lequel elle recherche la déclaration d'espace de noms et un nouveau préfixe qui doit remplacer l'ancien.

La fonction échoue avec une erreur si l'élément est dans la portée d'une autre déclaration dont le préfixe est égal au nouveau préfixe, ou si la modification devait entraîner une déclaration avec un préfixe non vide mais un URI d'espace de noms vide. Sinon, elle retourne 1 si la déclaration d'espace de noms a été trouvée et modifiée, et 0 si elle n'a pas été trouvée.

Tous les éléments et attributs (même ceux précédemment non liés au document) pour lesquels la déclaration d'espace de noms détermine leur espace de noms changent leur préfixe pour la nouvelle valeur.

Si le nouveau préfixe est indéfini ou vide, la déclaration d'espace de noms devient une déclaration d'un espace de noms par défaut. Les nœuds correspondants abandonnent leur préfixe d'espace de noms (mais restent dans l'espace de noms, maintenant par défaut). Dans ce cas, la fonction échoue si l'élément contenant est dans la portée d'une autre déclaration d'espace de noms par défaut.

Cette fonction ne fait PAS partie de l'API DOM.

SURCHARGE

XML::LibXML::Element surcharge le déréférencement de hachage pour fournir l'accès aux attributs de l'élément. Pour les attributs sans espace de noms, le nom de l'attribut est la clé de hachage, et la valeur de l'attribut est la valeur de hachage. Pour les attributs avec espace de noms, la clé de hachage est qualifiée par l'URI de l'espace de noms, en utilisant la notation de Clark.

La fonctionnalité de "hachage lié" de Perl est utilisée, ce qui signifie que le hachage vous donne un accès en lecture-écriture aux attributs de l'élément. Pour plus d'informations, voir XML::LibXML::AttributeHash
