XmResolvePartOffsets(library call) XmResolvePartOffsets(library call)

NOM

XmResolvePartOffsets — Une fonction qui permet l'écriture d'applications et de widgets compatibles ascendances

SYNTAXE

#include <Xm/Xm.h>
void XmResolvePartOffsets(
WidgetClass widget_class,
XmOffsetPtr * offset);

DESCRIPTION

L'utilisation d'enregistrements d'offsets nécessite une variable globale supplémentaire par classe de widget. La variable consiste en un pointeur vers un tableau d'offsets dans l'enregistrement du widget pour chaque partie de la structure du widget. La fonction XmResolvePartOffsets alloue les enregistrements d'offsets nécessaires à une application pour garantir un accès compatible ascendances aux enregistrements d'instances de widgets par les applications et les widgets. Ces enregistrements d'offsets sont utilisés par le widget pour accéder à toutes les variables du widget.

Au lieu de créer une liste de ressources, le widget crée une liste de ressources d'offsets. Pour y parvenir, utilisez la structure XmPartResource et la macro XmPartOffset. La structure de données XmPartResource ressemble à une liste de ressources, mais au lieu d'avoir un entier pour son offset, elle a deux `short`. Cette structure est placée dans l'enregistrement de classe comme s'il s'agissait d'une liste de ressources normale. Au lieu d'utiliser XtOffset pour l'offset, le widget utilise XmPartOffset.

XmPartResource resources[] = {
  { BarNxyz, BarCXyz, XmRBoolean,
    sizeof(Boolean), XmPartOffset(Bar,xyz),
    XmRImmediate, (XtPointer)False }
};

Au lieu de placer la taille du widget dans l'enregistrement de classe, le widget place la taille de la partie du widget dans le même champ.

Au lieu de placer XtVersion dans l'enregistrement de classe, le widget place XtVersionDontCheck dans l'enregistrement de classe.

Le widget définit une variable, de type XmOffsetPtr, pour pointer vers l'enregistrement d'offsets. Cela peut faire partie de l'enregistrement de classe du widget ou être une variable globale séparée.

Lors de l'initialisation de la classe, le widget appelle XmResolvePartOffsets, lui passant un pointeur pour contenir l'adresse de l'enregistrement d'offsets et l'enregistrement de classe. Cela fait plusieurs choses :

•
Ajoute le champ de taille de la classe parente (qui, par définition, a déjà été initialisée) au champ de taille de la partie.
•
Alloue un tableau basé sur le nombre de classes parentes.
•
Remplit les offsets de toutes les parties du widget avec les valeurs appropriées, déterminées en examinant les champs de taille de tous les enregistrements de classes parentes.
•
Utilise le tableau d'offsets de partie pour modifier les entrées d'offsets dans la liste de ressources afin qu'elles soient des offsets réels, en place.

Le widget définit une constante qui sera l'index de sa structure de partie dans le tableau des offsets. La valeur doit être supérieure de 1 à l'index de la classe parente du widget. Les constantes définies pour tous les widgets Xm se trouvent dans XmP.h.

#define BarIndex (XmBulletinBIndex + 1)

Au lieu d'accéder directement aux champs, le widget doit toujours passer par le tableau d'offsets. La macro XmField vous aide à accéder à ces champs. Étant donné que les macros XmPartOffset et XmField concatènent des éléments, vous devez vous assurer qu'il n'y a pas d'espace après l'argument de partie. Par exemple, les macros suivantes ne fonctionnent pas en raison de l'espace après l'argument de partie (Label) :

XmField(w, offset, Label, text, char *)
XmPartOffset(Label, text)

Par conséquent, vous ne devez pas avoir d'espaces après l'argument de partie (Label), comme illustré ici :

XmField(w, offset, Label, text, char *)

Vous pouvez définir des macros pour chaque champ afin de faciliter cela. Supposons un champ entier *xyz* :

#define BarXyz(w) (*(int *)(((char *) w) + \
        offset[BarIndex] + XtOffset(BarPart,xyz)))

Les paramètres de XmResolvePartOffsets sont :

widget_class
Spécifie le pointeur de classe de widget pour le widget créé.
offset
Retourne l'enregistrement d'offsets.
