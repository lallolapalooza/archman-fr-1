NOM

XmDisplay — La classe de widget Display

SYNTAXE

#include <Xm/Display.h>

DESCRIPTION

L'objet XmDisplay est utilisé par les widgets Motif pour stocker des informations spécifiques à un affichage. Il permet également à la boîte à outils d'accéder à certaines informations sur les hiérarchies de widgets qui seraient autrement inaccessibles. Chaque client possède un objet XmDisplay pour chaque affichage auquel il accède.

Un objet XmDisplay est créé automatiquement lorsque l'application crée le premier shell sur un affichage (généralement réalisé par un appel à XtAppInitialize ou XtAppCreateShell). Il n'est pas nécessaire de créer un objet XmDisplay par tout autre moyen. Une application peut utiliser la fonction XmGetXmDisplay pour obtenir l'ID du widget de l'objet XmDisplay pour un affichage donné.

Une application ne peut pas fournir de valeurs initiales pour les ressources XmDisplay en tant qu'arguments à un appel à une fonction qui crée des widgets. L'application ou l'utilisateur peut fournir des valeurs initiales dans un fichier de ressources. Après avoir créé le premier shell sur l'affichage, l'application peut utiliser XmGetXmDisplay pour obtenir l'ID du widget de l'objet XmDisplay, puis appeler XtSetValues pour définir les ressources XmDisplay.

Les ressources XmDisplay spécifient le style de protocole de glisser-déposer pour un client participant à des transactions de glisser-déposer. Les deux types de protocoles de base sont pré-enregistrement et dynamique. Lorsqu'un protocole de pré-enregistrement est utilisé, la boîte à outils gère toute la communication entre les clients initiateurs et récepteurs et affiche les effets visuels appropriés de survol et de sous-survol. Un client enregistre ses sites de dépôt à l'avance et ces informations sont stockées dans une propriété pour chaque fenêtre de niveau supérieur. Lorsque le pointeur de glissement entre dans une fenêtre de niveau supérieur, les informations du site de dépôt sont lues par l'initiateur. Un protocole dynamique permet aux clients source et destination de communiquer dynamiquement les informations d'état de glisser-déposer entre eux, et de mettre à jour leurs visuels respectifs en conséquence. La boîte à outils fournit les informations sur les sites de dépôt lorsque le pointeur passe sur un site de dépôt donné. Dans ce mode, un récepteur peut fournir une procédure pour générer ses propres effets de sous-survol.

Classes

Display hérite du comportement et des ressources des classes Core, Composite, Shell, WMShell, VendorShell, TopLevelShell et ApplicationShell.

Le pointeur de classe est xmDisplayClass.

Le nom de la classe est XmDisplay.

Nouvelles ressources

Le tableau suivant définit un ensemble de ressources de widget utilisées par le programmeur pour spécifier des données. Le programmeur peut également définir les valeurs des ressources pour les classes héritées afin de définir les attributs de ce widget. Pour référencer une ressource par son nom ou par sa classe dans un fichier .Xdefaults, supprimez le préfixe XmN ou XmC et utilisez les lettres restantes. Pour spécifier l'une des valeurs définies pour une ressource dans un fichier .Xdefaults, supprimez le préfixe Xm et utilisez les lettres restantes (en minuscules ou en majuscules, mais incluez les underscores entre les mots). Les codes dans la colonne d'accès indiquent si la ressource donnée peut être définie au moment de la création (C), définie à l'aide de XtSetValues (S), récupérée à l'aide de XtGetValues (G) ou si elle n'est pas applicable (N/A).

XmNdefaultButtonEmphasis
Spécifie si l'apparence du widget et du gadget PushButton ayant la ressource XmNshowAsDefault définie doit être modifiée. Lorsque le PushButton est le bouton par défaut, il a un bouton gravé qui est entouré d'une autre bordure gravée. Les valeurs possibles pour XmNdefaultButtonEmphasis, qui affectent le curseur de localisation, sont les suivantes :
XmINTERNAL_HIGHLIGHT
Fait apparaître le curseur de localisation entre les deux bordures gravées pour minimiser l'espace requis.
XmEXTERNAL_HIGHLIGHT
Induit le PushButton à dessiner le curseur de localisation à l'extérieur de la seconde bordure.
XmNdefaultVirtualBindings
Spécifie les liaisons virtuelles par défaut pour l'affichage. Voici un exemple de spécification pour la ressource defaultVirtualBindings dans un fichier de ressources :
*defaultVirtualBindings: \
        osfBackSpace:       <Key>BackSpace       \n\
        osfInsert:       <Key>InsertChar      \n\
        osfDelete:       <Key>DeleteChar      \n\
        ...
        osfLeft:       <Key>left, Ctrl<Key>H
XmNdragInitiatorProtocolStyle
Spécifie les exigences ou la préférence du protocole de glisser-déposer lorsque le client est un initiateur. Les valeurs possibles sont :
XmDRAG_PREREGISTER
En tant qu'initiateur, ce client n'utilise pas le protocole dynamique et ne peut arranger les effets visuels qu'avec des récepteurs fournissant des informations préenregistrées.
XmDRAG_DYNAMIC
En tant qu'initiateur, ce client n'utilise aucune des informations de site de dépôt préenregistrées mises à disposition par d'autres clients, et ne peut arranger les effets visuels qu'avec des récepteurs utilisant le protocole dynamique.
XmDRAG_NONE
Spécifie que le glisser-déposer est désactivé pour ce client.
XmDRAG_DROP_ONLY
En tant qu'initiateur, ce client n'utilise ni les informations de site de dépôt préenregistrées ni le protocole dynamique. Il prend en charge le glisser, et chaque fois que le curseur est sur un client prenant en charge le glisser-déposer, un retour visuel valide est fourni. Il n'y a pas d'autres effets visuels.
XmDRAG_PREFER_DYNAMIC
En tant qu'initiateur, ce client peut prendre en charge les protocoles préenregistré et dynamique, mais préfère utiliser les protocoles dynamiques chaque fois que possible afin de fournir un retour visuel de haute qualité sous le curseur.
XmDRAG_PREFER_PREREGISTER
En tant qu'initiateur, ce client peut prendre en charge les protocoles préenregistré et dynamique, mais préfère utiliser le protocole préenregistré chaque fois que possible afin de répondre aux besoins de performance ou de fournir un retour visuel cohérent lors du survol.
XmDRAG_PREFER_RECEIVER
Indique que ce client peut prendre en charge les protocoles préenregistré et dynamique, mais s'en remettra à la préférence du client récepteur. Cette valeur n'est valide que pour la ressource XmNdragInitiatorProtocolStyle, et c'est sa valeur par défaut.
XmNdragReceiverProtocolStyle
Spécifie les exigences ou la préférence du protocole de glisser-déposer lorsque ce client est un récepteur. Les valeurs sont :
XmDRAG_PREREGISTER
En tant que récepteur, ce client préenregistre les informations du site de dépôt et n'utilise pas le protocole dynamique. Il ne peut arranger les effets visuels qu'avec les initiateurs qui utilisent les informations préenregistrées.
XmDRAG_DYNAMIC
En tant que récepteur, ce client utilise le protocole dynamique et ne préenregistre pas les informations du site de dépôt. Il ne peut arranger les effets visuels qu'avec les initiateurs qui utilisent le protocole dynamique.
XmDRAG_NONE
Spécifie que le glisser-déposer est désactivé pour ce client.
XmDRAG_DROP_ONLY
En tant que récepteur, ce client n'utilise ni le protocole dynamique ni ne préenregistre les informations du site de dépôt. Il prend en charge le dépôt, et lorsque le curseur survole ce client, un retour visuel valide est toujours fourni, mais il n'y a pas d'autres effets visuels.
XmDRAG_PREFER_DYNAMIC
En tant que récepteur, ce client peut prendre en charge les protocoles préenregistré et dynamique, mais préfère utiliser le protocole dynamique chaque fois que possible afin de fournir un retour visuel de haute qualité sous le curseur.
XmDRAG_PREFER_PREREGISTER
En tant que récepteur, ce client peut prendre en charge les protocoles préenregistré et dynamique, mais préfère utiliser le protocole préenregistré chaque fois que possible afin de répondre aux besoins de performance.
La valeur par défaut de cette ressource dépend des capacités de l'affichage. Si l'affichage prend en charge l'extension de forme, permettant au protocole dynamique d'utiliser des curseurs de glissement de taille arbitraire, la valeur par défaut de cette ressource est XmDRAG_PREFER_DYNAMIC, sinon la valeur par défaut est XmDRAG_PREFER_PREREGISTER.
Le protocole réel utilisé entre un initiateur et un récepteur est basé sur le style de protocole du récepteur et de l'initiateur. La matrice de décision est décrite dans le tableau suivant.

La valeur XmDRAG_NONE n'apparaît pas dans la matrice. Lorsqu'elle est spécifiée pour le côté initiateur ou récepteur, XmDRAG_NONE implique que les transactions de glisser-déposer ne sont pas prises en charge. Une valeur de XmDRAG_DROP_ONLY (Drop Only) résulte lorsqu'un initiateur et un récepteur ne parviennent pas à un compromis sur les styles de protocole, c'est-à-dire qu'un client requiert un mode dynamique tandis que l'autre ne peut prendre en charge que le mode pré-enregistrement, ou si l'un d'eux a explicitement spécifié XmDRAG_DROP_ONLY.
XmNdragStartCallback
Spécifie la liste des rappels qui sont invoqués lorsque la fonction XmDragStart est appelée. Le type de structure dont l'adresse est passée à ce rappel est XmDragStartCallbackStruct. La raison du rappel est XmCR_DRAG_START.
XmNenableBtn1Transfer
Spécifie si les actions de sélection et de transfert sont intégrées sur le Bouton1 et si les actions d'extension sont activées sur le Bouton2. Cette ressource peut prendre les valeurs suivantes :
XmOFF
Désactive l'intégration et l'activation de la sélection sur le Bouton1.
XmBUTTON2_TRANSFER
Active l'intégration et l'activation de la sélection sur le Bouton1 et le transfert sur le Bouton2.
XmBUTTON2_ADJUST
Active l'intégration et l'activation de la sélection sur le Bouton1 et l'ajustement sur le Bouton2.
Cette ressource affecte les actions de Text, TextField, List et Container.
XmNenableButtonTab
Spécifie si l'action pour la touche <Tab> (actions KNextField et KPrevField) doit être modifiée. Une valeur de True modifie la touche pour qu'elle se déplace comme une touche fléchée jusqu'à la limite d'un groupe de tabulation. Ensuite, à la limite du groupe de tabulation, KNextField et KPrevField se déplaceront vers le groupe de tabulation suivant ou précédent, respectivement. Une valeur de False n'entraîne aucune modification.
XmNenableDragIcon
Spécifie quel ensemble d'icônes doit être utilisé pour les curseurs par défaut du système pendant les opérations de glisser-déposer. Une valeur de False spécifie que les icônes des versions antérieures de Motif sont utilisées, une valeur de True spécifie que des icônes alternatives sont utilisées. Cette ressource affecte les icônes 16x16 et 32x32 par défaut du système pour chacun des objets Screen associés à cet affichage.
XmNenableEtchedInMenu
Spécifie l'ombrage des widgets et gadgets de boutons dans les menus lorsque le contrôle est activé. Une valeur de True fait que le menu sélectionné est affiché avec l'ombre gravée vers l'intérieur ; ce style d'ombre est cohérent avec l'apparence sélectionnée des autres widgets de boutons en dehors des menus. Une valeur de False fait que le menu sélectionné est affiché avec l'ombre gravée vers l'extérieur. Cette ressource affecte les actions des widgets et gadgets PushButton, ToggleButton et CascadeButton lorsqu'ils sont enfants de Menu.
Lorsque cette ressource est définie, l'arrière-plan d'un bouton dans un menu utilise la valeur XmNselectColor (dérivée de XmNselectPixel) lorsqu'il est armé comme défaut. Un PushButton utilise la valeur XmNarmColor si elle est définie. Un ToggleButton utilise la valeur XmNselectColor si XmNindicatorOn est False et XmNfillOnSelect est True.
XmNenableToggleColor
Spécifie comment déterminer la valeur par défaut de la ressource XmNselectColor de ToggleButton et ToggleButtonGadget. Une valeur de True fait que la valeur par défaut de XmNselectColor est définie à la valeur de XmNhighlightColor. Une valeur de False fait que la valeur par défaut de XmNselectColor est définie à la valeur de XmNbackground. Cette ressource n'affecte que l'apparence des widgets et gadgets ToggleButton qui sont en mode XmONE_OF_MANY ou XmONE_OF_MANY_ROUND. De plus, XmNenableToggleColor n'influence que la valeur par défaut de XmNselectColor. C'est-à-dire, si l'utilisateur ou l'application définit une valeur pour XmNselectColor, alors XmNenableToggleColor est ignorée.
XmNenableToggleVisual
Spécifie l'apparence visuelle du widget et/ou gadget ToggleButton. Cette ressource affecte la valeur par défaut des ressources XmNindicatorType et XmNindicatorOn de ToggleButton[Gadget]. Lorsque le ToggleButton est dans une RadioBox, une valeur de True fait que XmONE_OF_MANY_ROUND (un cercle ombré) est la valeur par défaut. Sinon, lorsque cette ressource est True, la ressource XmNindicatorOn de ToggleButton provoque une valeur par défaut de XmN_OF_MANY, qui sera un carré ombré avec une coche (case à cocher).
Une valeur de False provoque ce qui suit :
XmONE_OF_MANY
Est un losange ombré.
XmN_OF_MANY
Est un carré ombré.
XmNenableUnselectableDrag
Spécifie s'il est possible ou non de glisser depuis Label et Scale. Une valeur de True active le glissement ; une valeur de False le désactive.
XmNenableWarp
Spécifie si une application est autorisée à déplacer le pointeur depuis l'utilisateur. Une valeur de True active le déplacement, une valeur de False ne le fait pas.
XmNmotifVersion
Spécifie la version actuelle de Motif à laquelle l'implémentation actuelle doit se comporter. Par défaut, cette ressource obtient sa valeur des valeurs de version dans Xm.h.
XmNnoFontCallback
Ce rappel est appelé chaque fois qu'une rendition tente de charger une police ou un jeu de polices et échoue. Cela peut se produire lors de la création si la police est spécifiée comme XmLOAD_IMMEDIATE ou lorsqu'une tentative est faite pour rendre un XmString en utilisant une police spécifiée comme XmLOAD_DEFERRED. Une application peut faire en sorte que ce rappel tente de remédier à ce problème en appelant XmRenditionUpdate sur la rendition d'entrée pour fournir une police au widget à utiliser. Cela peut être fait en fournissant un nom de police alternatif à charger en utilisant les ressources XmNfontName et XmNfontType ou avec une police déjà chargée en utilisant la ressource XmNfont. La raison du rappel est XmCR_NO_FONT. Ce rappel utilise la structure XmDisplayCallbackStruct.
XmNnoRenditionCallback
Ce rappel est appelé chaque fois qu'une tentative est faite pour rendre un segment avec une balise RENDITION qui ne correspond à aucune rendition dans une table de renditions donnée. La raison du rappel est XmCR_NO_RENDITION. Ce rappel utilise la structure XmDisplayCallbackStruct.
Une application peut faire en sorte que ce rappel tente de remédier à ce problème en créant une nouvelle rendition avec la balise donnée et en l'ajoutant à render_table.
Le XmNnoRenditionCallback doit désallouer la table de renditions passée dans le champ render_table de la structure de rappel. Notez que la table sera automatiquement désallouée si la fonction XmRenderTableAddRenditions est appelée dessus. Le rappel ne doit PAS désallouer la table de renditions modifiée qui est renvoyée à Motif dans le champ render_table. Si l'application souhaite manipuler davantage cette table de renditions, elle doit en faire une copie avec la fonction XmRenderTableCopy avant de retourner du rappel.
XmNuserData
Spécifie un pointeur de données client pour les applications. Une ressource non utilisée en interne.

Informations de rappel

Un pointeur vers la structure suivante est passé au rappel XmNdragStartCallback :

typedef struct
{
        int reason;
        XEvent  *event;
        Widget timeStamp;
        Boolean doit;
}XmDragStartCallbackStruct;
reason
Indique la raison de l'invocation du rappel.
event
Pointe vers l'événement XEvent qui a déclenché le rappel.
widget
Indique l'ID du widget à partir duquel le glisser-déposer a été initié.
doit
Est un membre ENTRÉE/SORTIE qui permet au rappel de déterminer s'il faut continuer le glisser-déposer ou l'annuler. La mise à False de doit annulera le glisser-déposer. La valeur par défaut est NULL.

Un pointeur vers la structure suivante est passé aux rappels XmNnoFontCallback et XmNnoRenditionCallback :

typedef struct
{
        int reason;
        XEvent *event;
        XmRendition rendition;
        char *font_name;
        XmRenderTable render_table;
        XmStringTag tag;
}XmDisplayCallbackStruct;
reason
Indique la raison de l'invocation du rappel.
event
Pointe vers l'événement XEvent qui a déclenché le rappel. Il peut être NULL.
rendition
Spécifie la rendition avec la police manquante.
font_name
Spécifie le nom de la police ou de l'ensemble de polices qui n'a pas pu être chargé.
render_table
Spécifie la table de rendu avec la rendition manquante.
tag
Spécifie l'étiquette de la rendition manquante.

Raison Champs valides
XmCR_NO_FONT rendition, font_name
XmCR_NO_RENDITION render_table, tag
