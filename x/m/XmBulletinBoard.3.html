NOM

XmBulletinBoard — Classe de widget BulletinBoard

SYNTAXE

#include <Xm/BulletinB.h>

DESCRIPTION

BulletinBoard est un widget composite qui fournit une gestion de géométrie simple pour les widgets enfants. Il n'impose pas de positionnement à ses enfants, mais peut être configuré pour rejeter les requêtes de géométrie qui entraînent un chevauchement des enfants. BulletinBoard est le widget de base pour la plupart des widgets de dialogue et est également utilisé comme widget conteneur général.

Les dialogues modaux et non modaux sont implémentés comme des collections de widgets qui incluent un DialogShell, un enfant BulletinBoard (ou sous-classe) du shell, et divers composants de dialogue (boutons, étiquettes, etc.) qui sont des enfants de BulletinBoard. BulletinBoard définit des rappels utiles pour les dialogues (focus, map, unmap), qui sont disponibles pour l'application. Si son parent est un DialogShell, BulletinBoard transmet les informations de titre et de mode d'entrée (basées sur le style du dialogue) au parent, qui est responsable de la communication appropriée avec le gestionnaire de fenêtres.

La valeur par défaut de XmNinitialFocus est la valeur de XmNdefaultButton.

BulletinBoard utilise le trait XmQTtakesDefault et détient les traits XmQTdialogShellSavvy et XmQTspecifyRenderTable.

CLASSES

BulletinBoard hérite du comportement, des ressources et des traits des classes Core, Composite, Constraint et XmManager.

Le pointeur de classe est xmBulletinBoardWidgetClass.

Le nom de la classe est XmBulletinBoard.

XmNallowOverlap
Contrôle la politique de chevauchement des widgets enfants. Si cette ressource est vraie, BulletinBoard autorise les requêtes de géométrie qui entraînent le chevauchement des enfants.
XmNautoUnmanage
Contrôle si BulletinBoard est automatiquement désactivé après l'activation d'un bouton. Si cette ressource est vraie lors de l'initialisation et si le parent de BulletinBoard est un DialogShell, BulletinBoard ajoute une routine de rappel aux enfants boutons (PushButtons, PushButtonGadgets et DrawnButtons) qui désactive le BulletinBoard lorsqu'un bouton est activé. Si cette ressource est fausse lors de l'initialisation ou si le parent de BulletinBoard n'est pas un DialogShell, le BulletinBoard n'est pas automatiquement désactivé. Pour les sous-classes de BulletinBoard avec des boutons Appliquer ou Aide, l'activation de ces boutons ne désactive pas automatiquement le BulletinBoard.
XmNbuttonFontList
Spécifie la liste de polices utilisée pour les descendants des boutons. Voir la ressource XmNbuttonRenderTable.
XmNbuttonRenderTable
Spécifie la table de rendu utilisée pour les descendants des boutons de BulletinBoard. Si cette valeur est NULL lors de l'initialisation, la hiérarchie parente du widget est recherchée pour trouver un ancêtre qui détient le trait XmQTspecifyRenderTable. Si un tel ancêtre est trouvé, la table de rendu est initialisée à la valeur XmBUTTON_RENDER_TABLE du widget ancêtre. Si aucun ancêtre de ce type n'est trouvé, la valeur par défaut dépend de l'implémentation. Reportez-vous à XmRenderTable(3) pour plus d'informations sur la création et la structure d'une table de rendu.
XmNcancelButton
Spécifie l'ID du widget du bouton Annuler. Les sous-classes de BulletinBoard, qui définissent un bouton Annuler, définissent cette ressource. BulletinBoard ne fournit directement aucun comportement pour ce bouton.
XmNdefaultButton
Spécifie l'ID du widget du bouton par défaut. Certaines sous-classes de BulletinBoard, qui définissent un bouton par défaut, définissent cette ressource. BulletinBoard définit des traductions et installe des accélérateurs qui activent ce bouton lorsque KActivate est pressé et que le focus clavier n'est pas dans un autre bouton.
XmNdefaultPosition
Contrôle le positionnement d'un DialogShell gérant un BulletinBoard. Si le BulletinBoard n'est pas géré par un DialogShell, cette ressource n'a aucun effet. Si XmNdefaultPosition est vrai, le DialogShell se centrera au centre de son propre parent. Par exemple, si le parent du DialogShell est un ApplicationShell, alors le centre du DialogShell sera aux mêmes coordonnées que le centre de l'ApplicationShell. Si le DialogShell devient désaffiché (mais reste géré) et est ensuite réaffiché, cette ressource n'a aucune influence sur la position du DialogShell. Si cette ressource est fausse, le DialogShell ne se centre pas automatiquement.

XmDIALOG_FULL_APPLICATION_MODAL
Utilisé pour les dialogues auxquels il faut répondre avant certaines autres interactions dans la même application.
XmDIALOG_MODELESS
Utilisé pour les dialogues qui n'interrompent pas l'interaction de n'importe quelle application. C'est la valeur par défaut lorsque le parent du BulletinBoard est un DialogShell.
XmDIALOG_WORK_AREA

xmBulletinBoardWidgetClass

DESCRIPTION

The XmBulletinBoard widget is a primitive dialog widget that allows the user to place children in arbitrary locations within the widget. The widget's geometry manager manages the children's geometry. If the widget is a child of a dialog shell, it is a dialog widget. The default dialog widget is XmBulletinBoard.

The XmBulletinBoard widget provides a simple way to create dialog boxes. It does not perform any specific geometry management of its children. Instead, it relies on the parent widget to control its geometry. The XmBulletinBoard widget itself has no explicit geometry management policy other than to allow its children to be placed at absolute coordinates specified by their XmNvalue resource.

Additional Behavior

The XmBulletinBoard widget has the following additional behavior:

<Key><osfCancel>:
Calls the activate callbacks for the cancel button if it is sensitive. If no cancel button exists and if the parent of the BulletinBoard is a manager, passes the event to the parent.
<Key><osfActivate>:
Calls the activate callbacks for the button with the keyboard focus. If no button has the keyboard focus, calls the activate callbacks for the default button if it is sensitive. In a List widget or single-line Text widget, the List or Text action associated with <Key><osfActivate> is called before the BulletinBoard actions associated with <Key><osfActivate>.
In a multiline Text widget, any <Key><osfActivate> event except <Key><Enter> calls the Text action associated with <Key><osfActivate>, then the BulletinBoard actions associated with <Key><osfActivate>. If no button has the focus, no default button exists, and the parent of the BulletinBoard is a manager, passes the event to the parent.
<FocusIn>:
Calls the callbacks for XmNfocusCallback. When the focus policy is XmPOINTER, the callbacks are called when the pointer enters the window. When the focus policy is XmEXPLICIT, the callbacks are called when the user traverses to the widget.
<Map>:
Calls the callbacks for XmNmapCallback.
<Unmap>:
Calls the callbacks for XmNunmapCallback.
