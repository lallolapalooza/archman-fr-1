XML::NamespaceSupport(3) Documentation Perl contribuée par l'utilisateur XML::NamespaceSupport(3)

NOM

XML::NamespaceSupport - Un processeur de namespace XML générique simple

VERSION

version 1.12

SYNOPSIS

use XML::NamespaceSupport;
my $nsup = XML::NamespaceSupport->new;
# ajouter un nouveau contexte vide
$nsup->push_context;
# déclarer quelques préfixes
$nsup->declare_prefix($prefix1, $uri1);
$nsup->declare_prefix($prefix2, $uri2);
# le même, plus court
$nsup->declare_prefixes($prefix1 => $uri1, $prefix2 => $uri2);
# obtenir un préfixe unique pour un URI (aléatoirement)
$prefix = $nsup->get_prefix($uri);
# obtenir tous les préfixes pour un URI (probablement mieux)
@prefixes = $nsup->get_prefixes($uri);
# obtenir tous les préfixes dans la portée
@prefixes = $nsup->get_prefixes();
# obtenir tous les préfixes qui ont été déclarés pour la portée actuelle
@prefixes = $nsup->get_declared_prefixes;
# obtenir un URI pour un préfixe donné
$uri = $nsup->get_uri($prefix);
# obtenir des informations sur un qname (à la manière Java, c'est un peu bizarre)
($ns_uri, $local_name, $qname) = $nsup->process_name($qname, $is_attr);
# le même, plus perlisant
($ns_uri, $prefix, $local_name) = $nsup->process_element_name($qname);
($ns_uri, $prefix, $local_name) = $nsup->process_attribute_name($qname);
# supprimer le contexte actuel
$nsup->pop_context;
# réinitialiser l'objet pour une réutilisation dans un autre document
$nsup->reset;
# un simple utilitaire pour traiter la notation Clark
my ($ns, $lname) = $nsup->parse_jclark_notation('{http://foo}bar');
# ou (étant donné qu'il ne se soucie pas de l'objet
my ($ns, $lname) = XML::NamespaceSupport->parse_jclark_notation('{http://foo}bar');

DESCRIPTION

Ce module offre une manière simple de traiter les noms XML avec namespace (unames) à partir de n'importe quelle application qui pourrait en avoir besoin. Il aide également à maintenir une correspondance préfixe vers URI de namespace, et fournit un certain nombre de vérifications de base.

Le modèle pour ce module est la classe NamespaceSupport de SAX2, lisible à http://www.saxproject.org/namespaces.html. Il ajoute quelques perlisations là où nous avons pensé que c'était approprié.

NOM

XML::NamespaceSupport - une classe de support de namespace générique simple

MÉTHODES

  • XML::NamespaceSupport->new(\%options)

    Un constructeur simple.

    Les options sont "xmlns", "fatal_errors", et "auto_prefix"

    Si "xmlns" est activé (il est désactivé par défaut), la correspondance du préfixe xmlns à l'URI qui lui est associé dans DOM level 2 est ajoutée à la liste des correspondances prédéfinies (qui ne contient normalement que la correspondance du préfixe xml).

    Si "fatal_errors" est désactivé (il est activé par défaut), un certain nombre d'erreurs de validité seront simplement signalées comme des échecs, au lieu de provoquer un die().

    Si "auto_prefix" est activé (il est désactivé par défaut), lorsque vous fournissez un préfixe de "undef" à "declare_prefix", il générera un préfixe aléatoire mappé à ce namespace. Sinon, un préfixe undef déclenchera un avertissement (vous devriez probablement savoir ce que vous faites si vous activez cette option).

    Si "xmlns_11" est désactivé, il devient illégal de désannuler les préfixes de namespace. Il est activé par défaut. Ce comportement est conforme aux Namespaces dans XML 1.1, le désactiver vous ramène à la version 1.0.

  • $nsup->push_context

    Ajoute un nouveau contexte vide à la pile. Vous pouvez ensuite le remplir avec de nouveaux préfixes définis à ce niveau.

  • $nsup->pop_context

    Supprime le contexte supérieur de la pile et revient au précédent. Il provoquera un die() si vous essayez de dépiler plus que ce que vous n'avez dépilé.

  • $nsup->declare_prefix($prefix, $uri)

    Déclare une correspondance de $prefix à $uri, au niveau actuel.

    Notez qu'avec "auto_prefix" activé, si vous déclarez une correspondance de préfixe dans laquelle $prefix est undef(), vous obtiendrez un préfixe automatique sélectionné pour vous. S'il est désactivé, vous obtiendrez un avertissement.

    Ceci est utile lorsque vous traitez du code qui n'a pas conservé les préfixes et qui doit resérialiser les nœuds. Cela signifie également que si vous souhaitez définir le namespace par défaut (c'est-à-dire avec un préfixe vide), vous devez utiliser la chaîne vide au lieu d'undef. Ce comportement est cohérent avec la spécification SAX 2.0.

  • $nsup->declare_prefixes(%prefixes2uris)

    Déclare une correspondance de plusieurs préfixes à des URIs, au niveau actuel.

  • $nsup->get_prefix($uri)

    Renvoie un préfixe étant donné un URI. Notez que comme plusieurs préfixes peuvent être mappés au même URI, il en renvoie un arbitraire. Il renverra undef en cas d'échec.

  • $nsup->get_prefixes($uri)

    Renvoie un tableau de préfixes étant donné un URI. Il renverra tous les préfixes si l'uri est undef.

  • $nsup->get_declared_prefixes

    Renvoie un tableau de tous les préfixes qui ont été déclarés dans ce contexte, c'est-à-dire ceux qui ont été déclarés sur le dernier élément, pas ceux qui étaient déclarés au-dessus et qui sont simplement dans la portée.

    Notez qu'au moins un contexte doit être ajouté à la pile via "push_context" avant que cette méthode ne puisse être appelée.

  • $nsup->get_uri($prefix)

    Renvoie un URI pour un préfixe donné. Renvoie undef en cas d'échec.

  • $nsup->process_name($qname, $is_attr)

    Étant donné un nom qualifié et un booléen indiquant s'il s'agit d'un attribut ou d'un autre type de nom (ceux-ci sont affectés différemment par les namespaces par défaut), il renvoie un tuple URI de namespace, nom local, nom qualifié. Je sais que c'est une liste plutôt anormale à renvoyer, mais c'est ainsi pour la compatibilité avec la spécification Java. Voir ci-dessous pour des alternatives plus perlisantes.

    Si le préfixe n'est pas déclaré, ou si le nom n'est pas valide, il provoquera un die ou renverra undef en fonction du réglage actuel de "fatal_errors".

  • $nsup->undeclare_prefix($prefix);

    Supprime un préfixe de namespace du contexte actuel. Cette fonction peut être utilisée dans end_prefix_mapping de SAX lorsqu'il y a la crainte qu'une déclaration de namespace ne soit disponible en dehors de leur portée (ce qui ne devrait normalement pas arriver, mais on ne sait jamais ;) ). Cela peut être nécessaire pour supporter correctement Namespace 1.1.

  • $nsup->process_element_name($qname)

    Étant donné un nom qualifié, il renvoie un tuple URI de namespace, préfixe et nom local. Cette méthode s'applique aux noms d'éléments.

    Si le préfixe n'est pas déclaré, ou si le nom n'est pas valide, il provoquera un die ou renverra undef en fonction du réglage actuel de "fatal_errors".

  • $nsup->process_attribute_name($qname)

    Étant donné un nom qualifié, il renvoie un tuple URI de namespace, préfixe et nom local. Cette méthode s'applique aux noms d'attributs.

    Si le préfixe n'est pas déclaré, ou si le nom n'est pas valide, il provoquera un die ou renverra undef en fonction du réglage actuel de "fatal_errors".

  • $nsup->reset

    Réinitialise l'objet afin qu'il puisse être réutilisé sur un autre document.

Toutes les méthodes de l'interface ont un alias qui est le nom utilisé dans la spécification Java originale. Vous pouvez utiliser l'un ou l'autre nom de manière interchangeable. Voici la correspondance :

Nom Java                 Nom Perl
---------------------------------------------------
pushContext               push_context
popContext                pop_context
declarePrefix             declare_prefix
declarePrefixes           declare_prefixes
getPrefix                 get_prefix
getPrefixes               get_prefixes
getDeclaredPrefixes       get_declared_prefixes
getURI                    get_uri

XML::NamespaceSupport - Support pour les espaces de noms XML

NOM

XML::NamespaceSupport - Support pour les espaces de noms XML

VERSION

1.12

SYNOPSIS

 use XML::NamespaceSupport;

 my $ns = XML::NamespaceSupport->new();
 $ns->push_context("myprefix", "http://my.namespace.org");
 ...
 my $uri = $ns->get_uri("myprefix");
 ...
 $ns->pop_context();

DESCRIPTION

Cette classe implémente une pile de contextes d'espaces de noms XML, permettant de gérer les préfixes et les URI d'espaces de noms dans une structure hiérarchique, telle que celle rencontrée lors de l'analyse d'un document XML.

Elle est souvent utilisée en conjonction avec des analyseurs SAX pour suivre les déclarations d'espaces de noms et résoudre les préfixes en URI.

NOM

XML::NamespaceSupport

MÉTHODES

new
Crée et retourne une nouvelle instance de XML::NamespaceSupport.
push_context ($prefix, $uri)
Ajoute un nouveau contexte à la pile. Le préfixe est associé à l'URI spécifié. Les déclarations d'espaces de noms dans un document XML sont généralement poussées sur la pile lorsque l'analyseur rencontre un élément ou un attribut avec une déclaration d'espace de noms.
pop_context ()
Retire le contexte le plus récent de la pile. Ceci est fait lorsque l'analyseur sort d'un élément XML.
get_uri ($prefix)
Retourne l'URI d'espace de noms associé au préfixe donné, en cherchant dans la pile de contextes depuis le contexte le plus récent jusqu'au plus ancien.
get_prefix ($uri)
Retourne le préfixe associé à l'URI donné, en cherchant dans la pile de contextes.
declare_prefix ($prefix, $uri)
Déclare un nouveau préfixe pour un URI dans le contexte courant.
undeclare_prefix ($prefix)
Supprime la déclaration d'un préfixe dans le contexte courant.
processJClarkNotation ($notation)
Traite une notation de type J.Clark (par exemple, "xmlns:foo='bar'").

Les noms des méthodes dans la documentation originale sont en camel case. Le code Perl utilise souvent des noms de méthodes en snake_case. Les noms suivants correspondent aux fonctions Perl, mais ils sont documentés ici sous leur forme originale.

process_name              processName
process_element_name      processElementName
process_attribute_name    processAttributeName
parse_jclark_notation     parseJClarkNotation
undeclare_prefix          undeclarePrefix

VARIABLES

Deux variables globales sont mises à votre disposition. Elles étaient auparavant des constantes, mais des scalaires simples sont plus faciles à utiliser dans de nombreux contextes. Elles ne sont pas exportées mais peuvent facilement être accédées depuis n'importe quel package, ou copiées dedans.

  • $NS_XMLNS

    L'espace de noms pour les préfixes xmlns, http://www.w3.org/2000/xmlns/.

  • $NS_XML

    L'espace de noms pour les préfixes xml, http://www.w3.org/XML/1998/namespace.
