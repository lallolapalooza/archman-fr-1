NOM

XmPrimitive — La classe de widget Primitive

SYNTAXE

#include <Xm/Xm.h>

DESCRIPTION

Primitive est une classe de widget utilisée comme superclasse de support pour d'autres classes de widgets. Elle gère le dessin et la mise en évidence des bordures, l'activation et la désactivation du parcours, ainsi que diverses listes de rappels nécessaires aux widgets Primitives. Primitive et toutes ses sous-classes détiennent le trait XmQTcareParentVisual.

Comportement de transfert de données

Primitive n'a pas de conversion de classe de widget ni de procédure de destination. Les sous-classes et les procédures XmNconvertCallback sont responsables de toute conversion de sélections. Les sous-classes et les procédures XmNdestinationCallback de sous-classes sont responsables de tout transfert de données vers le widget.

Classes

Primitive hérite du comportement, des ressources et des traits de Core.

Le pointeur de classe est xmPrimitiveWidgetClass.

Le nom de la classe est XmPrimitive.

Paramètres par défaut dynamiques des couleurs

Les ressources de couleur de premier plan, d'arrière-plan, d'ombre supérieure, d'ombre inférieure et de mise en évidence sont définies dynamiquement par défaut. Si aucune donnée de couleur n'est spécifiée, les couleurs sont générées automatiquement. Sur un système à plan unique, un schéma de couleurs noir et blanc est généré. Sinon, quatre couleurs sont générées, qui affichent le bon ombrage pour les visuels 3D. Si l'arrière-plan est la seule couleur spécifiée pour un widget, les couleurs d'ombre supérieure et d'ombre inférieure sont générées pour donner l'apparence 3D. Les couleurs de premier plan et de mise en évidence sont générées pour offrir un contraste suffisant avec la couleur d'arrière-plan.

Les couleurs sont générées uniquement lors de la création. La réinitialisation de l'arrière-plan via XtSetValues ne régénère pas les autres couleurs. XmChangeColor peut être utilisé pour recalculer toutes les couleurs associées en fonction d'une nouvelle couleur d'arrière-plan.

Informations sur les rappels

Un pointeur vers la structure suivante est passé à chaque rappel pour XmNhelpCallback:

typedef struct
{
        int reason;
        XEvent * event;
} XmAnyCallbackStruct;
reason
Indique la raison pour laquelle le rappel a été déclenché. Pour ce rappel, reason est défini à XmCR_HELP.
event
Pointe vers l'événement XEvent qui a déclenché le rappel.

Un pointeur vers la structure de rappel suivante est passé aux procédures XmNconvertCallback:

typedef struct
{
        int reason;
        XEvent *event;
        Atom selection;
        Atom target;
        XtPointer source_data;
        XtPointer location_data;
        int flags;
        XtPointer parm;
        int parm_format;
        unsigned long parm_length;
        Atom parm_type;
        int status;
        XtPointer value;
        Atom type;
        int format;
        unsigned long length;
} XmConvertCallbackStruct;
reason
Indique la raison pour laquelle le rappel a été déclenché.
event
Pointe vers l'événement XEvent qui a déclenché le rappel. Il peut être NULL.
selection
Indique la sélection pour laquelle la conversion est demandée. Les valeurs possibles sont CLIPBOARD, PRIMARY, SECONDARY et _MOTIF_DROP.
target
Indique la cible de la conversion.
source_data
Contient des informations sur la source de la sélection. Lorsque la sélection est _MOTIF_DROP, source_data est le DragContext. Sinon, il est NULL.
location_data
Contient des informations sur l'emplacement des données à convertir. Si la valeur est NULL, les données à transférer consistent en la sélection actuelle du widget. Sinon, le type et l'interprétation de la valeur sont spécifiques à la classe du widget.
flags
Indique l'état de la conversion. Les valeurs possibles sont:
XmCONVERTING_NONE
Ce drapeau est actuellement inutilisé.
XmCONVERTING_PARTIAL
Le widget cible a pu être converti, mais certaines données ont été perdues.
XmCONVERTING_SAME
La cible de conversion est la source des données à transférer.
XmCONVERTING_TRANSACT
Ce drapeau est actuellement inutilisé.
parm
Contient les données du paramètre pour cette cible. S'il n'y a pas de données de paramètre, la valeur est NULL.
Lorsque selection est CLIPBOARD et target est _MOTIF_CLIPBOARD_TARGETS ou _MOTIF_DEFERRED_CLIPBOARD_TARGETS, la valeur est l'opération demandée (XmCOPY, XmMOVE ou XmLINK).
parm_format
Spécifie si les données dans parm doivent être considérées comme une liste de quantités char, short ou long. Les valeurs possibles sont 0 (lorsque parm est NULL), 8 (lorsque les données dans parm doivent être considérées comme une liste de chars), 16 (lorsque les données dans parm doivent être considérées comme une liste de shorts) ou 32 (lorsque les données dans parm doivent être considérées comme une liste de longs). Notez que parm_format symbolise un type de données, et non le nombre de bits dans chaque élément de la liste. Par exemple, sur certaines machines, un parm_format de 32 signifie que les données dans parm doivent être considérées comme une liste de quantités de 64 bits, et non de 32 bits.
parm_length
Spécifie le nombre d'éléments de données dans parm, où chaque élément a la taille spécifiée par parm_format. Lorsque parm est NULL, la valeur est 0.
parm_type
Spécifie le type de paramètre de parm.
status
Un membre ENTRÉE/SORTIE qui spécifie l'état de la conversion. La valeur initiale est XmCONVERT_DEFAULT. La procédure de rappel peut définir ce membre à l'une des valeurs suivantes:
XmCONVERT_DEFAULT
Cette valeur signifie que la procédure de conversion de la classe du widget, le cas échéant, est appelée après le retour des procédures de rappel. Si la procédure de conversion de la classe du widget produit des données, elle écrase les données fournies par les procédures de rappel dans le membre value.
XmCONVERT_MERGE
Cette valeur signifie que la procédure de conversion de la classe du widget, le cas échéant, est appelée après le retour des procédures de rappel. Si la procédure de conversion de la classe du widget produit des données, elle ajoute ses données aux données fournies par les procédures de rappel dans le membre value. Cette valeur est destinée à être utilisée avec des cibles qui résultent en des listes de données, telles que TARGETS.
XmCONVERT_DONE
Cette valeur signifie que la procédure de rappel a terminé avec succès la conversion. La procédure de conversion de la classe du widget, le cas échéant, n'est pas appelée après le retour des procédures de rappel.
XmCONVERT_REFUSE
Cette valeur signifie que la procédure de rappel a terminé le processus de conversion sans achever la conversion demandée. La procédure de conversion de la classe du widget, le cas échéant, n'est pas appelée après le retour des procédures de rappel.
value
Contient un pointeur vers les données converties. La procédure de rappel est responsable de l'allocation de la mémoire pour ces données si nécessaire.
type
Spécifie le type de données dans value.
format
Spécifie si les données dans value doivent être considérées comme une liste de char, short ou long. Les valeurs possibles sont 8, 16 ou 32.
length
Spécifie le nombre d'éléments de données dans value, où chaque élément a la taille spécifiée par format.
>valeur
Un paramètre IN/OUT qui contient toute donnée que la procédure de rappel produit comme résultat de la conversion. La valeur initiale est NULL. Si la procédure de rappel définit ce membre, elle doit s'assurer que les membres type, format et length correspondent aux données de valeur. La procédure de rappel est responsable de l'allocation de mémoire lorsqu'elle définit ce membre. La boîte à outils libère cette mémoire lorsqu'elle n'est plus nécessaire.
type
Un paramètre IN/OUT qui indique le type des données dans le membre valeur. La valeur initiale est INTEGER.
format
Un paramètre IN/OUT qui spécifie si les données dans valeur doivent être vues comme une liste de quantités char, short, ou long. La valeur initiale est 8. La procédure de rappel peut définir ce membre sur 8 (pour une liste de char), 16 (pour une liste de short), ou 32 (pour une liste de long).
length
Un membre IN/OUT qui spécifie le nombre d'éléments de données dans valeur, où chaque élément a la taille symbolisée par format. La valeur initiale est 0.

Les procédures d'action XmPrimitive sont

PrimitiveHelp():
Appelle les rappels pour XmNhelpCallback s'il en existe. S'il n'y a pas de rappels d'aide pour ce widget, cette action appelle les rappels d'aide de l'ancêtre le plus proche qui en possède.
PrimitiveNextTabGroup():
Cette action dépend de la valeur de la ressource d'affichage XmNenableButtonTab. Lorsque XmNenableButtonTab est False (par défaut), cette action se déplace vers le premier élément du groupe de tabulation suivant. Si le groupe de tabulation actuel est la dernière entrée de la liste des groupes de tabulation, elle revient au début de la liste des groupes de tabulation.
Lorsque XmNenableButtonTab est True, cette action se déplace vers l'élément suivant dans le groupe de tabulation actuel, sauf s'il s'agit du dernier élément du groupe. Lorsque l'élément est le dernier du groupe, l'action se déplace vers le premier élément du groupe de tabulation suivant. Le comportement de XmNenableButtonTab s'applique uniquement aux boutons PushButton, ArrowButton et DrawnArrow.
PrimitiveParentActivate():
Si le parent est un gestionnaire, passe l'événement KActivate reçu par le widget au parent.
PrimitiveParentCancel():
Si le parent est un gestionnaire, passe l'événement KCancel reçu par le widget au parent.
PrimitivePrevTabGroup():
Cette action dépend de la valeur de la ressource d'affichage XmNenableButtonTab. Lorsque XmNenableButtonTab est False (par défaut), cette action se déplace vers le premier élément du groupe de tabulation précédent. Si le début de la liste des groupes de tabulation est atteint, elle revient à la fin de la liste des groupes de tabulation.
Lorsque XmNenableButtonTab est True, cette action se déplace vers l'élément précédent dans le groupe de tabulation actuel, sauf s'il s'agit du premier élément du groupe de tabulation. Lorsque l'élément est le premier du groupe, l'action se déplace vers le premier élément du groupe de tabulation précédent. Le comportement de XmNenableButtonTab s'applique uniquement aux boutons PushButton, ArrowButton et DrawnButton.
PrimitiveTraverseDown():
Se déplace vers l'élément suivant en dessous du widget actuel dans le groupe de tabulation actuel, en bouclant si nécessaire. La direction de bouclage dépend de la direction de disposition du groupe de tabulation du widget.
PrimitiveTraverseHome():
Se déplace vers le premier widget ou gadget dans le groupe de tabulation actuel.
PrimitiveTraverseLeft():
Se déplace vers l'élément suivant à gauche du widget actuel dans le groupe de tabulation actuel, en bouclant si nécessaire. La direction de bouclage dépend de la direction de disposition du groupe de tabulation du widget.
PrimitiveTraverseNext():
Se déplace vers l'élément suivant dans le groupe de tabulation actuel, en bouclant si nécessaire. La direction de bouclage dépend de la direction de disposition du groupe de tabulation du widget.
PrimitiveTraversePrev():
Se déplace vers l'élément précédent dans le groupe de tabulation actuel, en bouclant si nécessaire. La direction de bouclage dépend de la direction de disposition du groupe de tabulation du widget.
PrimitiveTraverseRight():
Se déplace vers l'élément suivant à droite du gadget actuel dans le groupe de tabulation actuel, en bouclant si nécessaire. La direction de bouclage dépend de la direction de disposition du groupe de tabulation du widget.
PrimitiveTraverseUp():
Se déplace vers l'élément suivant au-dessus du gadget actuel dans le groupe de tabulation actuel, en bouclant si nécessaire. La direction de bouclage dépend de la direction de disposition du groupe de tabulation du widget.

Comportement supplémentaire

Ce widget a le comportement supplémentaire suivant :

<FocusIn>:
Si la politique de focus clavier du shell est XmEXPLICIT, met en surbrillance le widget et lui donne le focus.
<FocusOut>:
Si la politique de focus clavier du shell est XmEXPLICIT, retire la mise en surbrillance du widget et lui retire le focus.

Liaisons virtuelles

Les liaisons pour les touches virtuelles sont spécifiques au vendeur. Pour des informations sur les liaisons des boutons et touches virtuels, voir VirtualBindings(3).
