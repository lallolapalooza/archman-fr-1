Paquet: perl-xml-libxml-prettyprint

XML::LibXML::PrettyPrint(3) Documentation Perl fournie par l'utilisateur XML::LibXML::PrettyPrint(3)

NOM

XML::LibXML::PrettyPrint - ajouter des espaces blancs agréables à un arbre DOM

SYNTAXE

my $document = XML::LibXML->new->parse_file('in.xml');
my $pp = XML::LibXML::PrettyPrint->new(indent_string => "  ");
$pp->pretty_print($document); # modifié en place
print $document->toString;

DESCRIPTION

Les longs fichiers XML peuvent être intimidants à lire pour les humains. Bien sûr, XML est vraiment conçu pour être lu par des ordinateurs - pas par des gens - mais il y a des moments où des mortels ont besoin de lire et modifier du XML à la main. Par exemple, si votre application stocke sa configuration en XML, ou si vous avez besoin de déverser du XML sur STDOUT à des fins de débogage.

La coloration syntaxique aide, mais pour vraiment comprendre certains XML, une indentation correcte peut être vitale. D'où "XML::LibXML::PrettyPrint" - il peut être appliqué à un arbre DOM XML::LibXML pour le reformater en un résultat plus lisible.

Le formatage lisible du XML n'est pas aussi efficace en termes de CPU que de le déverser maladroitement, donc à moins que vous ne soyez à peu près sûr qu'un humain aura besoin de comprendre votre XML, vous ne devriez probablement pas utiliser ce module.

Constructeurs

new(%options)
Construit un objet de formatage.

Options :

  • indent_string - La chaîne à utiliser pour indenter chaque ligne. Par défaut, un seul caractère de tabulation. La définir sur un caractère non blanc est autorisé, mais générera un avertissement.
  • new_line - La chaîne à utiliser pour commencer une nouvelle ligne. Par défaut, "\n".
  • element - Un hash de catégorisations d'éléments. Chaque catégorisation est une référence à un tableau de noms d'éléments ou de fonctions de rappel. Les noms d'éléments peuvent utiliser la notation de Clark. 
    my $callback = sub {
  my $node = shift;
  return 1 if $node->hasAttribute('is_block');
  return undef;
};
my $pp = XML::LibXML::PrettyPrint->new(
    element => {
        inline   => [qw/span strong em b i a/],
        block    => [qw/p div body html head/, $callback],
        compact  => [qw/title caption li dd dt th td/],
        preserves_whitespace => [qw/pre script style/],
        }
    );

    Les rappels devraient retourner 1 (vrai), 0 (faux) ou undef (ne sait pas).

new_for_html(%options)
Construit un objet de formatage pré-configuré pour être adapté au HTML et au XHTML. Les options indent_string et new_line sont supportées.

Méthodes

Si vous avez juste besoin d'utiliser une configuration par défaut (aucune option passée au constructeur), vous pouvez appeler celles-ci comme des méthodes de classe, sauf indication contraire.

strip_whitespace($node)
Supprime les espaces blancs superflus d'un "XML::LibXML::Document" ou "XML::LibXML::Element".

Les espaces blancs juste avant, juste après ou en tête/queue d'un élément en ligne ne sont pas considérés comme superflus. Les séquences de plusieurs caractères blancs sont remplacées par un seul espace. Les espaces blancs ne sont pas modifiés dans un élément qui préserve les espaces blancs.

Le nœud est modifié en place.

"indent($node, $level)"
Indente le nœud à un certain niveau d'indentation, et ses enfants directs au niveau "$level + 1", les petits-enfants au niveau "$level + 2", etc. Typiquement, vous voudrez juste indenter le nœud racine au niveau 0.

Le nœud est modifié en place.

Les éléments qui préservent les espaces blancs ne sont pas modifiés.

"pretty_print($node, $level)"
Supprime les espaces blancs et indente. Le nœud est modifié en place et retourné.

Exemple d'utilisation en tant que méthode de classe :

print XML::LibXML::PrettyPrint
  ->pretty_print(XML::LibXML->new->parse_string($XML))
  ->toString;
indent_string($level)
Retourne la chaîne qui serait utilisée pour indenter quelque chose à un niveau particulier. Les classes descendantes pourraient remplacer cette méthode pour faire une indentation fantaisiste, comme avoir des niveaux d'indentation variables.
"new_line"
Retourne la chaîne qui serait utilisée pour commencer une nouvelle ligne.
element_category($node)
Retourne EL_INLINE, EL_BLOCK, EL_COMPACT ou undef.
element_preserves_whitespace($node)
Booléen indiquant si le contenu de l'élément a des espaces blancs significatifs qui doivent être préservés.

Retourne undef si $node n'est pas un "XML::LibXML::Element".

Fonctions

"print_xml $xml"
Étant donné une chaîne XML ou un objet XML::LibXML::Node, l'affiche joliment.

Cette fonction n'est pas exportée par défaut, mais peut être demandée :

use XML::LibXML::PrettyPrint 0.001 qw(print_xml);

Utilisation :

print_xml '<foo> <bar> </bar> </foo>';
"IO::Handle::print_xml($handle, $xml)"
Partiellement expérimental, partiellement mental. Vous pouvez activer cette fonctionnalité comme suit : 
use XML::LibXML::PrettyPrint 0.001 qw(-io);

Et cela permettra à des choses comme celles-ci de fonctionner :

open LOG, '>mylog.xml';
print_xml LOG '<foo> <bar> </bar> </foo>';
close LOG;
open my $log, '>otherlog.xml';
print_xml $log '<foo> <bar> </bar> </foo>';
close $log;
print_xml STDERR '<foo> <bar> </bar> </foo>';

Constantes

Celles-ci peuvent être exportées :

use XML::LibXML::PrettyPrint 0.001 qw(:constants);
"EL_BLOCK"
"EL_COMPACT"
"EL_INLINE"

CATÉGORIES D'ÉLÉMENTS

Il existe trois catégories d'éléments : en ligne, bloc et compact.

Pour les éléments en ligne, la présence d'espaces blancs (mais pas la quantité d'espaces blancs) est considérée comme significative juste avant l'élément, juste après l'élément, ou juste à l'intérieur de l'élément.

En XHTML, considérez la différence entre l'élément de bloc "<div>" :

<div>Will</div><div>Carlton</div> <div>Ashley</div>

et l'élément en ligne "<span>" :

<span>Spider</span>-<span>Man</span> <span>lives</span>

L'espace ou l'absence d'espace entre les éléments "<div>" n'a aucune importance. L'absence d'espaces entre les deux premiers éléments "<span>" leur permet d'être lus comme un seul mot (dans ce cas, avec un trait d'union), tandis que l'espace avant le troisième "<span>" sépare le mot "lives".

En termes d'indentation, les éléments en ligne ne commencent pas une nouvelle ligne indentée, sauf s'ils sont le premier élément à l'intérieur de leur bloc, ou s'ils sont précédés d'un élément de bloc ou compact.

Les éléments de bloc commencent toujours une nouvelle ligne et provoquent l'indentation de leurs nœuds enfants au niveau suivant.

Les éléments compacts sont quelque part entre les deux. En ce qui concerne la suppression des espaces blancs, ils sont traités comme des éléments de bloc. En termes d'indentation, ils commencent toujours une nouvelle ligne, mais ils n'indenteront leurs nœuds enfants au niveau suivant que s'ils ont des descendants de type bloc. Si nous imaginons qu'en HTML, "<ul>" est un élément de bloc, "<i>" est un élément en ligne, et "<li>" est un élément compact

XML::LibXML::PrettyPrint - Perl 5.42.0 man page

NAME

XML::LibXML::PrettyPrint - Pretty-print XML or HTML, with support for element categories and indentation control

SYNOPSIS

  use XML::LibXML::PrettyPrint;

  my $formatter = XML::LibLibXML::PrettyPrint->new(
      indent    => 1,    # or 0, or any number
      indent_char => '  ', # or '\t', or whatever you like
      line_ending => "\n", # or "\r\n", etc
  );
  my $pretty_xml = $formatter->pretty_print($xml);

DESCRIPTION

This module provides a simple way to pretty-print XML or HTML documents, with control over indentation and whitespace handling.

ELEMENT CATEGORIES

By default, all elements are treated as block elements. You can specify particular elements as inline or compact using callbacks or node names provided to the constructor. Whitespace is generally preserved unless specified otherwise.

Here is an example:

<ul>
  <li>Will Smith - Will Smith</li>
  <li>Carlton Banks - Alfonso Ribeiro</li>
  <li>
    Vivian Banks:
    <ul>
      <li>Janet Hubert-Whitten <i>(seasons 1-3)</i></li>
      <li>Daphne Maxwell Reid <i>(seasons 3-6)</i></li>
    </ul>
  </li>
</ul>

The third "<li>" element is indented like a block element because it contains a block "<ul>" element. The other "<li>" elements do not have their contents indented, because they contain only inline content.

Elements default to being block, but you can specify particular elements as inline or compact by passing node names or callbacks to the constructor. Elements default to not preserving whitespace unless they have an "xml:space="preserve""" attribute, but again you can use the constructor to change this.

Comments and processing instructions default to being compact, but you can make particular comments or PIs inline or block by passing appropriate callbacks to the constructor. Whitespace within comments and PIs is always preserved. (There is rarely any reason to make comments and processing instructions block, but making them inline can occasionally be useful, as it will mean that the presence of whitespace just before or just after the comment is treated as significant.)

Text nodes are always inline.
