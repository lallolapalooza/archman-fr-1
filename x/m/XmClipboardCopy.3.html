NOM

XmClipboardCopy — Fonction du presse-papiers qui copie un élément de données dans un stockage temporaire pour copie ultérieure vers le presse-papiers

SYNTAXE

#include <Xm/CutPaste.h>
int XmClipboardCopy (display, window, item_id, format_name,
        buffer, length, private_id, data_id)
        Display * display;
        Window  window;
        long    item_id;
        char    * format_name;
        XtPointer       buffer;
        unsigned long   length;
        long    private_id;
        long    * data_id;
(void)

DESCRIPTION

XmClipboardCopy copie un élément de données dans un stockage temporaire. L'élément de données est déplacé du stockage temporaire vers la structure de données du presse-papiers lorsqu'un appel à XmClipboardEndCopy est effectué. Les appels supplémentaires à XmClipboardCopy avant un appel à XmClipboardEndCopy ajoutent des formats d'éléments de données supplémentaires au même élément de données ou ajoutent des données à un format existant. Les formats sont décrits dans le manuel Inter-Client Communication Conventions Manual (ICCCM) en tant que cibles.

NOTE : N'appelez pas XmClipboardCopy avant qu'un appel à XmClipboardStartCopy n'ait été effectué. Cette dernière fonction alloue le stockage temporaire requis par XmClipboardCopy.

Si l'argument buffer est NULL, les données sont considérées comme transmises par nom. Lorsque des données transmises par nom sont ultérieurement demandées par une autre application, l'application qui possède les données reçoit un rappel avec une requête pour les données. L'application qui possède les données doit alors transférer les données vers le presse-papiers avec la fonction XmClipboardCopyByName. Lorsqu'un élément de données transmis par nom est supprimé du presse-papiers, l'application qui possède les données reçoit un rappel indiquant que les données ne sont plus nécessaires.

Pour plus d'informations sur la fonction de rappel, voir la description de l'argument de rappel pour XmClipboardStartCopy.

display
Spécifie un pointeur vers la structure Display qui a été retournée lors d'un appel précédent à XOpenDisplay ou XtDisplay.
window
Spécifie l'identifiant de fenêtre d'un widget qui relie la fenêtre de l'application au presse-papiers. L'identifiant de fenêtre du widget peut être obtenu via XtWindow. La même instance d'application doit passer le même identifiant de fenêtre à chacune des fonctions de presse-papiers qu'elle appelle.
item_id
Spécifie le numéro attribué à cet élément de données. Ce numéro a été retourné par un appel précédent à XmClipboardStartCopy.
format_name
Spécifie le nom du format dans lequel l'élément de données est stocké sur le presse-papiers. Le format était connu sous le nom de cible dans l'ICCCM.
buffer
Spécifie le tampon à partir duquel le presse-papiers copie les données.
length
Spécifie la longueur, en octets, des données copiées dans le presse-papiers.
private_id
Spécifie les données privées que l'application souhaite stocker avec l'élément de données.
data_id
Spécifie un numéro d'identification attribué à l'élément de données qui identifie de manière unique l'élément de données et le format. Cet argument n'est requis que pour les données transmises par nom.

RETOUR

XmClipboardSuccess
La fonction a réussi.
XmClipboardLocked
La fonction a échoué car le presse-papiers était verrouillé par une autre application. L'application peut continuer à appeler la fonction avec les mêmes paramètres jusqu'à ce que le verrouillage disparaisse. Cela donne à l'application la possibilité de demander si l'utilisateur souhaite continuer ou abandonner l'opération.
XmClipboardFail
La fonction a échoué car XmClipboardStartCopy n'a pas été appelée ou parce que l'élément de données contient trop de formats.

VOIR AUSSI

XmClipboardCopyByName(3), XmClipboardEndCopy(3), et XmClipboardStartCopy(3).
