XSLoader(3perl) Guide du programmeur Perl XSLoader(3perl)

NOM

XSLoader — Charger dynamiquement des bibliothèques C dans du code Perl

VERSION

Version 0.32

SYNOPIS

package VotrePackage;
require XSLoader;
XSLoader::load(__PACKAGE__, $VERSION);

DESCRIPTION

Ce module définit une interface standard *simplifiée* aux mécanismes de liaison dynamique disponibles sur de nombreuses plateformes. Son but principal est de mettre en œuvre le chargement dynamique peu coûteux et automatique des modules Perl.

Pour une interface plus complexe, voir DynaLoader. La plupart des fonctionnalités de "DynaLoader" ne sont pas implémentées dans "XSLoader", comme par exemple les "dl_load_flags", non respectés par "XSLoader".

Migration depuis "DynaLoader"

Un module typique utilisant DynaLoader commence comme ceci :

package VotrePackage;
require DynaLoader;
our @ISA = qw( OnePackage OtherPackage DynaLoader );
our $VERSION = '0.01';
__PACKAGE__->bootstrap($VERSION);

Changez ceci en :

package VotrePackage;
use XSLoader;
our @ISA = qw( OnePackage OtherPackage );
our $VERSION = '0.01';
XSLoader::load(__PACKAGE__, $VERSION);

En d'autres termes : remplacez "require DynaLoader" par "use XSLoader", retirez "DynaLoader" de @ISA, remplacez "bootstrap" par "XSLoader::load". N'oubliez pas de citer le nom de votre paquet sur la ligne "XSLoader::load", et ajoutez une virgule (",") avant les arguments ($VERSION ci-dessus).

Bien sûr, si @ISA ne contenait que "DynaLoader", il n'y a pas besoin d'avoir l'affectation @ISA du tout ; de plus, si au lieu de "our" on utilise le plus compatible avec les versions antérieures

use vars qw($VERSION @ISA);

on peut supprimer cette référence à @ISA ainsi que l'affectation @ISA.

Si aucune $VERSION n'était spécifiée sur la ligne "bootstrap", la dernière ligne devient

XSLoader::load(__PACKAGE__);

auquel cas elle peut être encore simplifiée en

XSLoader::load();

car "load" utilisera "caller" pour déterminer le paquet.

Boilerplate compatible avec les versions antérieures

Si vous voulez avoir le beurre et l'argent du beurre, il vous faut un boilerplate plus compliqué.

package VotrePackage;
our @ISA = qw( OnePackage OtherPackage );
our $VERSION = '0.01';
eval {
   require XSLoader;
    XSLoader::load(__PACKAGE__, $VERSION);
   1;
} or do {
   require DynaLoader;
   push @ISA, 'DynaLoader';
   __PACKAGE__->bootstrap($VERSION);
};

Les parenthèses autour des arguments de XSLoader::load() sont nécessaires car nous avons remplacé "use XSLoader" par "require", donc le compilateur ne sait pas qu'une fonction XSLoader::load() est présente.

Ce boilerplate utilise l'"XSLoader" à faible surcharge s'il est présent ; s'il est utilisé avec une version ancienne de Perl qui n'a pas "XSLoader", il se rabat sur l'"DynaLoader".

Ordre d'initialisation: load() précoce

*Ignorez cette section si les fonctions XSUB sont censées être appelées uniquement depuis d'autres modules ; lisez-la seulement si vous appelez vos XSUBs depuis le code de votre module, ou si vous avez une section "BOOT:" dans votre fichier XS (voir "The BOOT: Keyword" dans perlxs). Ce qui est décrit ici s'applique également à l'interface DynaLoader.*

Un module suffisamment compliqué utilisant XS aurait à la fois du code Perl (défini dans *YourPackage.pm*) et du code XS (défini dans *YourPackage.xs*). Si ce code Perl fait des appels vers ce code XS, et/ou si ce code XS fait des appels vers le code Perl, il faut faire attention à l'ordre d'initialisation.

L'appel à XSLoader::load() (ou bootstrap()) appelle le code de démarrage du module. Pour les modules construits par *xsubpp* (presque tous les modules), cela a trois effets secondaires :

  • Une vérification de cohérence est effectuée pour s'assurer que les versions des parties *.pm* et *.xs* (compilées) sont compatibles. Si $VERSION a été spécifiée, elle est utilisée pour la vérification. Si elle n'est pas spécifiée, elle prend par défaut "$XS_VERSION // $VERSION" (dans l'espace de noms du module).
  • les XSUBs sont rendues accessibles depuis Perl.
  • s'il y avait une section "BOOT:" dans le fichier *.xs*, le code qu'elle contient est appelé.

Par conséquent, si le code du fichier *.pm* fait des appels à ces XSUBs, il est pratique d'avoir les XSUBs installées avant que le code Perl ne soit défini ; par exemple, cela rend les prototypes des XSUBs visibles par ce code Perl. Alternativement, si la section "BOOT:" fait des appels à des fonctions Perl (ou utilise des variables Perl) définies dans le fichier *.pm*, elles doivent être définies avant l'appel à XSLoader::load() (ou bootstrap()).

La première situation étant beaucoup plus fréquente, il est logique de réécrire le boilerplate comme suit :

package VotrePackage;
use XSLoader;
our ($VERSION, @ISA);
BEGIN {
   @ISA = qw( OnePackage OtherPackage );
   $VERSION = '0.01';
   # Placer le code Perl utilisé dans la section BOOT: ici
   XSLoader::load(__PACKAGE__, $VERSION);
}
# Placer le code Perl qui fait des appels aux XSUBs ici

Le cas le plus complexe

Si l'interdépendance de votre section "BOOT:" et du code Perl est plus compliquée que cela (par exemple, la section "BOOT:" fait des appels à des fonctions Perl qui font des appels à des XSUBs avec prototypes), débarrassez-vous complètement de la section "BOOT:". Remplacez-la par une fonction onBOOT(), et appelez-la comme ceci :

package VotrePackage;
use XSLoader;
our ($VERSION, @ISA);
BEGIN {
   @ISA = qw( OnePackage OtherPackage );
   $VERSION = '0.01';
   XSLoader::load(__PACKAGE__, $VERSION);
}
# Placer le code Perl utilisé dans la fonction onBOOT() ici ; les appels aux XSUBs
# sont vérifiés par prototype.
onBOOT;
# Placer le code d'initialisation Perl en supposant que XS est initialisé ici

DIAGNOSTICS

"Can't find '%s' symbol in %s"
(F) Le symbole de démarrage n'a pas pu être trouvé dans le module d'extension.
"Can't load '%s' for module %s: %s"
(F) Le chargement ou l'initialisation du module d'extension a échoué. Le détail de l'erreur suit.
"Undefined symbols present after loading %s: %s"
(W) Comme le dit le message, certains symboles restent indéfinis bien que le module d'extension ait été correctement chargé et initialisé. La liste des symboles indéfinis suit.

LIMITATIONS

Pour réduire la surcharge autant que possible, un seul emplacement possible est vérifié pour trouver la DLL d'extension (cet emplacement est celui où "make install" placerait la DLL). Si elle n'est pas trouvée, la recherche de la DLL est déléguée de manière transparente à "DynaLoader", qui recherche la DLL le long de la liste @INC.

En particulier, cela s'applique à la structure de @INC utilisée pour tester des extensions non encore installées. Cela signifie que l'exécution d'extensions non installées peut

ont beaucoup plus de surcharge que l'exécution des mêmes extensions après "make install".

BUGS CONNUS

La nouvelle façon plus simple d'appeler XSLoader::load() sans aucun argument ne fonctionne pas sur Perl 5.8.4 et 5.8.5.
