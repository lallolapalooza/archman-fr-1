XSetClipMask(3)

Paquet: libx11

Licences: MIT AND X11

XSetClipOrigin(3) FONCTIONS XLIB XSetClipOrigin(3)

NOM

XSetClipOrigin, XSetClipMask, XSetClipRectangles - routines de commodité GC

SYNTAXE

int XSetClipOrigin(Display *display, GC gc, int clip_x_origin, int clip_y_origin);

int XSetClipMask(Display *display, GC gc, Pixmap pixmap);

int XSetClipRectangles(Display *display, GC gc, int clip_x_origin, int clip_y_origin, XRectangle rectangles[], int n, int ordering);

ARGUMENTS

display
Spécifie la connexion au serveur X.
clip_x_origin

clip_y_origin
Spécifient les coordonnées x et y de l'origine du masque de découpage.
gc
Spécifie le GC.
n
Spécifie le nombre de rectangles.
ordering
Spécifie les relations d'ordonnancement sur les rectangles. Vous pouvez passer Unsorted, YSorted, YXSorted, ou YXBanded.
pixmap
Spécifie le pixmap ou None.
rectangles
Spécifie un tableau de rectangles qui définissent le masque de découpage.

DESCRIPTION

La fonction XSetClipOrigin définit l'origine du découpage dans le GC spécifié. L'origine du masque de découpage est interprétée par rapport à l'origine de tout dessin de destination spécifié dans la requête graphique.

XSetClipOrigin peut générer des erreurs BadAlloc et BadGC.

La fonction XSetClipMask définit le masque de découpage dans le GC spécifié au pixmap spécifié. Si le masque de découpage est défini sur None, les pixels sont toujours dessinés (indépendamment de l'origine du découpage).

XSetClipMask peut générer des erreurs BadAlloc, BadGC, BadMatch et BadValue.

La fonction XSetClipRectangles modifie le masque de découpage dans le GC spécifié en la liste de rectangles spécifiée et définit l'origine du découpage. La sortie est découpée pour rester contenue dans les rectangles. L'origine du découpage est interprétée par rapport à l'origine de tout dessin de destination spécifié dans une requête graphique. Les coordonnées des rectangles sont interprétées par rapport à l'origine du découpage. Les rectangles ne doivent pas s'intersecter, sinon les résultats graphiques seront indéfinis. Notez que la liste de rectangles peut être vide, ce qui désactive effectivement la sortie. Ceci est l'inverse du passage de None comme masque de découpage dans XCreateGC, XChangeGC et XSetClipMask.

Si elles sont connues du client, les relations d'ordonnancement sur les rectangles peuvent être spécifiées avec l'argument ordering. Cela peut fournir une opération plus rapide par le serveur. Si un ordonnancement incorrect est spécifié, le serveur X peut générer une erreur BadMatch, mais il n'est pas obligé de le faire. Si aucune erreur n'est générée, les résultats graphiques sont indéfinis. Unsorted signifie que les rectangles sont dans un ordre arbitraire. YSorted signifie que les rectangles sont non décroissants dans leur origine Y. YXSorted contraint en outre l'ordre YSorted en ce que tous les rectangles avec une origine Y égale sont non décroissants dans leur origine X. YXBanded contraint en outre YXSorted en exigeant que, pour chaque ligne de balayage Y possible, tous les rectangles qui incluent cette ligne de balayage aient des origines Y et des étendues Y identiques.

XSetClipRectangles peut générer des erreurs BadAlloc, BadGC, BadMatch et BadValue.

DIAGNOSTICS

BadAlloc
Le serveur n'a pas pu allouer la ressource demandée ou la mémoire du serveur.
BadGC
Une valeur pour un argument GContext ne nomme pas un GContext défini.
BadMatch
Un argument ou une paire d'arguments a le bon type et la bonne portée mais ne correspond pas d'une autre manière requise par la requête.
BadValue
Une valeur numérique tombe en dehors de la plage de valeurs acceptées par la requête. À moins qu'une plage spécifique ne soit spécifiée pour un argument, toute la plage définie par le type de l'argument est acceptée. Tout argument défini comme un ensemble d'alternatives peut générer cette erreur.
