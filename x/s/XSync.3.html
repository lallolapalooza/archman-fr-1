NOM

XFlush, XSync, XEventsQueued, XPending - gérer le tampon de sortie ou la file d'attente d'événements

SYNTAXE

int XFlush(Display *display);

int XSync(Display *display, Bool discard);

int XEventsQueued(Display *display, int mode);

int XPending(Display *display);

ARGUMENTS

discard
Spécifie une valeur booléenne qui indique si XSync supprime tous les événements de la file d'attente d'événements.
display
Spécifie la connexion au serveur X.
mode
Spécifie le mode. Vous pouvez passer QueuedAlready, QueuedAfterFlush, ou QueuedAfterReading.

DESCRIPTION

La fonction XFlush vide le tampon de sortie. La plupart des applications clientes n'ont pas besoin d'utiliser cette fonction car le tampon de sortie est automatiquement vidé au besoin par les appels à XPending, XNextEvent, et XWindowEvent. Les événements générés par le serveur peuvent être mis en file d'attente dans la file d'attente d'événements de la bibliothèque.

La fonction XSync vide le tampon de sortie puis attend jusqu'à ce que toutes les requêtes aient été reçues et traitées par le serveur X. Toutes les erreurs générées doivent être gérées par le gestionnaire d'erreurs. Pour chaque erreur de protocole reçue par Xlib, XSync appelle la routine de gestion d'erreurs de l'application cliente (voir section 11.8.2). Tous les événements générés par le serveur sont mis en file d'attente dans la file d'attente d'événements de la bibliothèque.

Enfin, si vous avez passé False, XSync ne supprime pas les événements dans la file d'attente. Si vous avez passé True, XSync supprime tous les événements dans la file d'attente, y compris les événements qui étaient dans la file avant l'appel à XSync. Les applications clientes appellent rarement XSync.

Si mode est QueuedAlready, XEventsQueued retourne le nombre d'événements déjà dans la file d'attente d'événements (et n'effectue jamais d'appel système). Si mode est QueuedAfterFlush, XEventsQueued retourne le nombre d'événements déjà dans la file d'attente si ce nombre est non nul. S'il n'y a pas d'événements dans la file d'attente, XEventsQueued vide le tampon de sortie, tente de lire d'autres événements à partir de la connexion de l'application, et retourne le nombre lu. Si mode est QueuedAfterReading, XEventsQueued retourne le nombre d'événements déjà dans la file d'attente si ce nombre est non nul. S'il n'y a pas d'événements dans la file d'attente, XEventsQueued tente de lire d'autres événements à partir de la connexion de l'application sans vider le tampon de sortie et retourne le nombre lu.

XEventsQueued retourne toujours immédiatement sans I/O s'il y a déjà des événements dans la file d'attente. XEventsQueued avec le mode QueuedAfterFlush est identique en comportement à XPending. XEventsQueued avec le mode QueuedAlready est identique à la fonction XQLength.

La fonction XPending retourne le nombre d'événements qui ont été reçus du serveur X mais qui n'ont pas encore été retirés de la file d'attente d'événements. XPending est identique à XEventsQueued avec le mode QueuedAfterFlush spécifié.
