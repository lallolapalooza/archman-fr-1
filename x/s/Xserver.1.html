XSERVER(1) Manuel des commandes générales XSERVER(1)

NOM

Xserver - serveur d'affichage X Window System

SYNTAXE

X [option ...]

DESCRIPTION

X est le nom générique du serveur d'affichage du système X Window. Il s'agit souvent d'un lien symbolique ou d'une copie du binaire du serveur approprié pour piloter le serveur le plus fréquemment utilisé sur une machine donnée.

DÉMARRAGE DU SERVEUR

Le serveur X est généralement démarré depuis le programme de gestion d'affichage X, xdm(1), ou un programme similaire. Cet utilitaire est exécuté à partir des fichiers de démarrage du système et prend en charge le maintien du serveur en cours d'exécution, la demande des noms d'utilisateur et des mots de passe, ainsi que le lancement des sessions utilisateur.

Les installations qui exécutent plus d'un système de fenêtrage peuvent avoir besoin d'utiliser l'utilitaire xinit(1) à la place d'un gestionnaire d'affichage. Cependant, xinit est considéré comme un outil pour construire des scripts de démarrage et n'est pas destiné à être utilisé par les utilisateurs finaux. Les administrateurs système sont **fortement** encouragés à utiliser un gestionnaire d'affichage ou à créer d'autres interfaces pour les utilisateurs novices.

Le serveur X peut également être démarré directement par l'utilisateur, bien que cette méthode soit généralement réservée aux tests et ne soit pas recommandée pour une utilisation normale. Sur certaines plateformes, l'utilisateur doit disposer d'une permission spéciale pour démarrer le serveur X, souvent parce que l'accès à certains périphériques (par exemple, /dev/mouse) est restreint. Le cas échéant, le serveur X notifie systemd lorsqu'il est prêt à traiter les requêtes.

Au démarrage du serveur X, il prend généralement le contrôle de l'affichage. Si vous utilisez un poste de travail dont la console est l'affichage, il se peut que vous ne puissiez pas vous connecter à la console pendant que le serveur est en cours d'exécution.

OPTIONS

De nombreux serveurs X ont des options de ligne de commande spécifiques au matériel. Voir les pages de manuel des serveurs individuels pour plus de détails ; une liste des pages de manuel spécifiques aux serveurs est fournie dans la section VOIR AUSSI ci-dessous.

Tous les serveurs X acceptent les options de ligne de commande décrites ci-dessous. Certains serveurs X peuvent avoir des moyens alternatifs de fournir les paramètres décrits ici, mais les valeurs fournies via les options de ligne de commande doivent remplacer les valeurs spécifiées via d'autres mécanismes.

:numéro_affichage
Le serveur X s'exécute avec le numéro_affichage donné, qui est 0 par défaut. Si plusieurs serveurs X doivent s'exécuter simultanément sur un hôte, chacun doit avoir un numéro d'affichage unique. Voir la section NOMS D'AFFICHAGE de la page de manuel X(7) pour savoir comment spécifier quel numéro d'affichage les clients doivent essayer d'utiliser.
-a nombre
définit l'accélération du pointeur (c'est-à-dire le ratio entre ce qui est signalé et la façon dont l'utilisateur a réellement déplacé le pointeur).
-ac
désactive les mécanismes de contrôle d'accès basés sur l'hôte. Permet l'accès par n'importe quel hôte et autorise n'importe quel hôte à modifier la liste de contrôle d'accès. À utiliser avec une extrême prudence. Cette option existe principalement pour l'exécution de suites de tests à distance.
-audit niveau
définit le niveau de la piste d'audit. Le niveau par défaut est 1, ce qui signifie que seuls les rejets de connexion sont signalés. Le niveau 2 signale en plus toutes les connexions réussies et les déconnexions. Le niveau 4 active les messages de l'extension SECURITY, si elle est présente, y compris la génération et la révocation des autorisations et les violations de la politique de sécurité. Le niveau 0 désactive la piste d'audit. Les lignes d'audit sont envoyées en tant que sortie d'erreur standard.
-auth fichier_autorisation
spécifie un fichier contenant une collection d'enregistrements d'autorisation utilisés pour authentifier l'accès. Voir également les pages de manuel xdm(1) et Xsecurity(7).
-background none
demande au pilote de ne pas effacer l'arrière-plan au démarrage, si le pilote le prend en charge. Peut être utile pour une transition en douceur avec, par exemple, le pilote fbdev. Pour des raisons de sécurité, ce n'est pas le comportement par défaut, car le contenu de l'écran pourrait afficher une session utilisateur précédente.
-br
définit la fenêtre racine par défaut sur un noir uni au lieu du motif de tissage standard de la racine. C'est le comportement par défaut, sauf si -retro ou -wr est spécifié.
-bs
désactive le support du stockage intermédiaire (backing store) sur tous les écrans.
+byteswappedclients
Autorise les connexions de clients avec une endianité différente de celle du serveur. C'est le comportement par défaut, sauf si -byteswappedclients est spécifié.
-byteswappedclients
Interdit les connexions de clients avec une endianité différente de celle du serveur.
-c
désactive le clic de touche.
c volume
définit le volume du clic de touche (plage autorisée : 0-100).
-cc classe
définit la classe visuelle pour la fenêtre racine des écrans couleur. Les numéros de classe sont ceux spécifiés dans le protocole X. Non respecté par tous les serveurs.
-core
provoque la génération d'une vidage mémoire (core dump) par le serveur en cas d'erreurs fatales.
-displayfd descripteur
spécifie un descripteur de fichier dans le processus de lancement. Au lieu de spécifier un numéro d'affichage, le serveur X tentera d'écouter sur des numéros d'affichage successivement plus élevés, et lorsqu'il en trouvera un libre, il écrira le numéro d'affichage sur ce descripteur de fichier sous forme de chaîne terminée par un saut de ligne. L'option -pn est ignorée lors de l'utilisation de -displayfd.
-deferglyphs polices
spécifie les types de polices pour lesquelles le serveur doit tenter d'utiliser le chargement différé des glyphes. polices peut être all (toutes les polices), none (aucune police), ou 16 (uniquement les polices 16 bits).
-dpi résolution
définit la résolution pour tous les écrans, en points par pouce. À utiliser lorsque le serveur ne peut pas déterminer la taille de l'écran à partir du matériel.
dpms
active les services DPMS (gestion de l'alimentation de l'affichage), là où ils sont supportés. L'état par défaut est spécifique à la plateforme et à la configuration.
-dpms
désactive les services DPMS (gestion de l'alimentation de l'affichage). L'état par défaut est spécifique à la plateforme et à la configuration.
-extensionnomExtension
désactive l'extension nommée. Si un nom d'extension inconnu est spécifié, une liste des noms d'extensions acceptés est imprimée.
+extensionnomExtension
active l'extension nommée. Si un nom d'extension inconnu est spécifié, une liste des noms d'extensions acceptés est imprimée.
-f volume
définit le volume du bip (sonnerie) (plage autorisée : 0-100).
-fakescreenfps ps
définit les images par seconde (IPS) par défaut de l'écran simulé (plage autorisée : 1-600).
-fp chemin_polices
définit le chemin de recherche des polices. Ce chemin est une liste de répertoires séparés par des virgules que le serveur X recherche pour trouver les bases de données de polices. Voir la section POLICES de cette page de manuel pour plus d'informations et la liste par défaut.
-help
affiche un message d'utilisation.
-I
ignore tous les arguments de ligne de commande restants.
-iglx
Interdit la création de contextes GLX indirects. GLX indirect est d'une utilité limitée, car il manque de prise en charge de nombreuses fonctionnalités et extensions OpenGL modernes ; il est plus lent que les contextes directs ; et il ouvre une large surface d'attaque pour les erreurs d'analyse de protocole. C'est le comportement par défaut, sauf si +iglx est spécifié.
+iglx
Autorise la création de contextes GLX indirects.
-maxbigreqsize taille
définit la taille maximale des requêtes volumineuses (big request) à taille Mo.
-nocur
désactive

Ce site n'est en aucun cas associé à Arch Linux ni affilié à ce projet. Le contenu est uniquement une traduction des pages de manuel d'Arch publiées sur man.archlinux.org.

OPTIONS GÉNÉRALES

-norender
désactive l'extension Render.
-noscanout
désactive le vidage de la mémoire tampon des événements.
-nospec
désactive la sortie du curseur du pointeur.
-nolisten trans-type
désactive un type de transport. Par exemple, les connexions TCP/IP peuvent être désactivées avec -nolisten tcp. Cette option peut être émise plusieurs fois pour désactiver l'écoute de différents types de transport. Les types de transport pris en charge dépendent de la plateforme, mais incluent généralement :
tcp TCP sur IPv4 ou IPv6
inet TCP sur IPv4 uniquement
inet6 TCP sur IPv6 uniquement
unix Sockets de domaine UNIX
local Méthode de connexion locale préférée par la plateforme
-listen trans-type
active un type de transport. Par exemple, les connexions TCP/IP peuvent être activées avec -listen tcp. Cette option peut être émise plusieurs fois pour activer l'écoute de différents types de transport.
-noreset
empêche une réinitialisation du serveur lorsque la dernière connexion client est fermée. Ceci annule une option de ligne de commande -terminate précédente.
-p minutes
définit le temps de cycle du motif de l'économiseur d'écran en minutes.
-pn
permet au serveur de continuer à s'exécuter s'il ne parvient pas à établir toutes ses sockets bien connues (points de connexion pour les clients), mais en établit au moins une. Cette option est définie par défaut.
-nopn
oblige le serveur à se terminer s'il ne parvient pas à établir toutes ses sockets bien connues (points de connexion pour les clients).
-r
désactive la répétition automatique.
r
active la répétition automatique.
-retro
démarre le serveur avec le motif de remplissage et le curseur classiques visibles. Par défaut, il démarre avec une fenêtre racine noire et supprime l'affichage du curseur jusqu'à ce qu'une application appelle XDefineCursor() pour la première fois. Pour les serveurs kdrive, cela implique -zap.
-s minutes
définit le temps d'attente de l'économiseur d'écran en minutes.
-su
désactive le support de sauvegarde sous sur tous les écrans.
-seat seat
siège sur lequel exécuter. Prend une chaîne identifiant un siège dans une syntaxe spécifique à la plateforme. Sur les plateformes qui prennent en charge cette fonctionnalité, cela peut être utilisé pour limiter le serveur à exposer uniquement un sous-ensemble spécifique d'appareils connectés au système.
-t nombre
définit le seuil d'accélération du pointeur en pixels (c'est-à-dire après combien de pixels l'accélération du pointeur doit prendre effet).
-terminate [delay]
provoque la terminaison du serveur lors de la réinitialisation du serveur, au lieu de continuer à fonctionner. Ceci annule une option de ligne de commande -noreset précédente. Si un délai en secondes est spécifié, le serveur attend au moins ce délai. À la fin de cette période de grâce, si aucun client n'est connecté, le serveur se termine immédiatement.
-tst
désactive toutes les extensions de test (par exemple, XTEST, XTrap, XTestExtension1, RECORD).
ttyxx
ignoré, pour les serveurs démarrés à l'ancienne (depuis init).
v
définit la préférence de l'économiseur d'écran désactivant la vidéo.
-v
définit la préférence de l'économiseur d'écran activant la vidéo.
-wr
définit la fenêtre racine par défaut sur un blanc uni au lieu du motif de tissage racine standard.
-x extension
charge l'extension spécifiée à l'initialisation. Ceci est une opération nulle pour la plupart des implémentations.
[+-]xinerama
active(+) ou désactive(-) l'extension XINERAMA. L'état par défaut dépend de la plateforme et de la configuration.

OPTIONS SPÉCIFIQUES AU SERVEUR

Certains serveurs X acceptent les options suivantes :

-ld kilooctets
définit la limite de l'espace de données du serveur au nombre spécifié de kilooctets. Une valeur de zéro rend la taille des données aussi grande que possible. La valeur par défaut de -1 laisse la limite de l'espace de données inchangée.
-lf fichiers
définit la limite du nombre de fichiers ouverts du serveur au nombre spécifié. Une valeur de zéro rend la limite aussi grande que possible. La valeur par défaut de -1 laisse la limite inchangée.
-ls kilooctets
définit la limite de l'espace de pile du serveur au nombre spécifié de kilooctets. Une valeur de zéro rend la taille de la pile aussi grande que possible. La valeur par défaut de -1 laisse la limite de l'espace de pile inchangée.
-maxclients
64|128|256|512 Définit le nombre maximum de clients autorisés à se connecter au serveur X. Les valeurs acceptables sont 64, 128, 256 ou 512.
-render
default|mono|gray|color définit la politique d'allocation de couleur qui sera utilisée par l'extension render.
default
sélectionne la politique par défaut définie pour la profondeur d'affichage du serveur X.
mono
n'utilise aucune cellule de couleur.
gray
utilise une carte de gris de 13 cellules de couleur pour l'extension X render.
color
utilise un cube de couleurs d'au plus 4x4x4 couleurs (soit 64 cellules de couleur).
-dumbSched
désactive la planification intelligente sur les plateformes qui prennent en charge le planificateur intelligent.
-schedInterval interval
définit l'intervalle de planification du planificateur intelligent à interval millisecondes.

OPTIONS XDMCP

Les serveurs X qui prennent en charge XDMCP ont les options suivantes. Consultez la spécification du X Display Manager Control Protocol pour plus d'informations.

-query hostname
active XDMCP et envoie des paquets Query à l'hôte spécifié hostname.
-broadcast
active XDMCP et diffuse des paquets BroadcastQuery sur le réseau. Le premier gestionnaire d'affichage qui répondra sera choisi pour la session.
-multicast [address [hop count]]
Active XDMCP et diffuse des paquets BroadcastQuery en multicast sur le réseau. Le premier gestionnaire d'affichage qui répondra sera choisi pour la session. Si une adresse est spécifiée, le multicast est envoyé à cette adresse. Si aucune adresse n'est spécifiée, le multicast est envoyé au groupe multicast XDMCP IPv6 par défaut. Si un nombre de sauts est spécifié, il est utilisé comme nombre maximum de sauts pour le multicast. Si aucun nombre de sauts n'est spécifié, le multicast est réglé sur un maximum de 1 saut, pour éviter que le multicast ne soit routé au-delà du réseau local.
-indirect hostname
active XDMCP et envoie des paquets IndirectQuery à l'hôte spécifié hostname.
-port port-number
utilise le numéro de port spécifié pour les paquets XDMCP, au lieu du défaut. Cette option doit être spécifiée avant toute option -query, -broadcast, -multicast ou -indirect.
-from local-address
spécifie l'adresse locale à partir de laquelle se connecter (utile si l'hôte de connexion a plusieurs interfaces réseau). L'adresse local-address peut être exprimée sous toute forme acceptable par l'implémentation de gethostbyname(3) de la plateforme hôte.
-once
provoque la terminaison du serveur (au lieu de la réinitialisation) lorsque la session XDMCP se termine.
-class display-class
XDMCP a un qualificateur d'affichage supplémentaire utilisé dans la recherche de ressources pour les options spécifiques à l'affichage. Cette option définit cette valeur, par défaut elle est "MIT-unspecified" (une valeur pas très utile).
-cookie xdm-auth-bits
Lors du test de XDM-AUTHENTICATION-1, une clé privée est partagée entre le serveur et le gestionnaire. Cette option définit la valeur de ces données privées (bien qu'elles ne soient pas très privées, étant sur la ligne de commande !).
-displayID display-id
Encore une autre valeur spécifique à XDMCP, celle-ci permet au gestionnaire d'affichage d'identifier chaque affichage afin qu'il puisse localiser la clé partagée.

OPTIONS XKEYBOARD

Les serveurs X qui prennent en charge l'extension XKEYBOARD (alias "XKB") acceptent les options suivantes. Tous les fichiers de disposition spécifiés sur la ligne de commande doivent être situés dans le répertoire de base XKB ou dans un sous-répertoire, et être spécifiés comme le chemin relatif depuis le répertoire de base XKB. Le répertoire de base XKB par défaut est /usr/lib/X11/xkb.

[+-]accessx [ timeout [ timeout_mask [ feedback [ options_mask ] ] ] ]
active(+) ou désactive(-) les séquences de touches AccessX.
-xkbdir directory
répertoire de base pour les fichiers de disposition du clavier. Cette option n'est pas disponible pour les serveurs X définis en setuid (c'est-à-dire lorsque les UID réels et effectifs du serveur X sont différents).
-ardelay millisecond
s
définit le délai de répétition automatique (durée en millisecondes pendant laquelle une touche doit être enfoncée avant que la répétition automatique ne commence).
-arinterval millisecondes
définit l'intervalle de répétition automatique (durée en millisecondes qui doit s'écouler entre les frappes générées par la répétition automatique).
-xkbmap nom_fichier
charge la description du clavier dans nom_fichier au démarrage du serveur.

CONNEXIONS RÉSEAU

Le serveur X prend en charge les connexions client via un sous-ensemble dépendant de la plateforme des types de transport suivants : TCP/IP, sockets de domaine Unix et plusieurs variétés de connexions locales SVR4. Consultez la section NOMS D'AFFICHAGE de la page de manuel X(7) pour savoir comment spécifier le type de transport que les clients doivent essayer d'utiliser.

OCTROI DACCÈS

Le serveur X implémente un sous-ensemble dépendant de la plateforme des protocoles d'autorisation suivants : MIT-MAGIC-COOKIE-1, XDM-AUTHORIZATION-1, SUN-DES-1, accès hôte et interprété par le serveur. Consultez la page de manuel Xsecurity(7) pour plus d'informations sur le fonctionnement de ces protocoles.

Les données d'autorisation requises par les protocoles ci-dessus sont transmises au serveur dans un fichier privé nommé avec l'option de ligne de commande -auth. Chaque fois que le serveur est sur le point d'accepter la première connexion après une réinitialisation (ou lors du démarrage du serveur), il lit ce fichier. Si ce fichier contient des enregistrements d'autorisation, l'hôte local n'est pas automatiquement autorisé à accéder au serveur, et seuls les clients qui envoient l'un des enregistrements d'autorisation contenus dans le fichier dans les informations de configuration de connexion seront autorisés. Consultez la page de manuel Xau pour une description du format binaire de ce fichier. Consultez xauth(1) pour la maintenance de ce fichier et la distribution de son contenu aux hôtes distants.

Le serveur X utilise également une liste de contrôle d'accès basée sur les hôtes pour décider d'accepter ou non les connexions des clients d'une machine particulière. Si aucun autre mécanisme d'autorisation n'est utilisé, cette liste se compose initialement de l'hôte sur lequel le serveur s'exécute ainsi que de toutes les machines répertoriées dans le fichier /etc/Xn.hosts, où n est le numéro d'affichage du serveur. Chaque ligne du fichier doit contenir soit un nom d'hôte Internet (par exemple, expo.lcs.mit.edu) soit un nom complet au format famille:nom tel que décrit dans la page de manuel xhost(1). Il ne doit y avoir aucun espace au début ou à la fin des lignes. Par exemple :


joesworkstation
corporate.company.com
inet:bigcpu
local:

Les utilisateurs peuvent ajouter ou supprimer des hôtes de cette liste et activer ou désactiver le contrôle d'accès à l'aide de la commande xhost depuis la même machine que le serveur.

Le protocole X n'a intrinsèquement aucune notion de permissions d'opération de fenêtre ni aucune restriction sur ce qu'un client peut faire ; si un programme peut se connecter à un affichage, il a un contrôle total sur l'écran. Les serveurs X qui prennent en charge l'extension SECURITY s'en sortent mieux car les clients peuvent être désignés comme non fiables via l'autorisation qu'ils utilisent pour se connecter ; consultez la page de manuel xauth(1) pour plus de détails. Des restrictions sont imposées aux clients non fiables qui limitent les dégâts qu'ils peuvent causer. Consultez la spécification de l'extension SECURITY pour une liste complète de ces restrictions.

Les sites qui disposent de meilleurs systèmes d'authentification et d'autorisation pourraient souhaiter utiliser les points d'extension dans les bibliothèques et le serveur pour fournir des modèles de sécurité supplémentaires.

SIGNAUX

Le serveur X attribue une signification particulière aux signaux suivants :

SIGHUP
Ce signal provoque la fermeture par le serveur de toutes les connexions existantes, la libération de toutes les ressources et la restauration de tous les paramètres par défaut. Il est envoyé par le gestionnaire d'affichage chaque fois que l'application principale de l'utilisateur principal (généralement un xterm ou un gestionnaire de fenêtres) se termine, pour forcer le serveur à nettoyer et à se préparer pour l'utilisateur suivant.
SIGTERM
Ce signal provoque la sortie propre du serveur.
SIGUSR1
Ce signal est utilisé de manière assez différente des deux précédents. Au démarrage du serveur, il vérifie s'il a hérité de SIGUSR1 en tant que SIG_IGN au lieu du SIG_DFL habituel. Dans ce cas, le serveur envoie un SIGUSR1 à son processus parent après avoir configuré les différents schémas de connexion. Xdm utilise cette fonctionnalité pour reconnaître quand une connexion au serveur est possible.

POLICES

Le serveur X peut obtenir des polices à partir de répertoires et/ou de serveurs de polices. La liste des répertoires et des serveurs de polices que le serveur X utilise lors de la tentative d'ouverture d'une police est contrôlée par le chemin des polices.

Le chemin des polices par défaut est /usr/share/fonts/misc,/usr/share/fonts/TTF,/usr/share/fonts/OTF,/usr/share/fonts/Type1,/usr/share/fonts/100dpi,/usr/share/fonts/75dpi .

Un type spécial de répertoire peut être spécifié en utilisant le préfixe catalogue:. Les répertoires spécifiés de cette manière peuvent contenir des liens symboliques pointant vers les vrais répertoires de polices. Consultez la section FONTPATH.D pour plus de détails.

Le chemin des polices peut être défini avec l'option -fp ou par xset(1) après le démarrage du serveur.

FONTPATH.D

Vous pouvez spécifier un type spécial de chemin de polices sous la forme catalogue:<rép>. Le répertoire spécifié après le préfixe catalogue : sera analysé pour les liens symboliques et chaque destination de lien symbolique sera ajoutée en tant que FPE de fichier de polices local.

Le lien symbolique peut être suffixé par des attributs tels que 'unscaled', qui seront transmis au FPE de fichier de polices sous-jacent. La seule exception est l'attribut 'pri' introduit récemment, qui sera utilisé pour ordonner les chemins de polices spécifiés par les liens symboliques.

Un exemple de configuration :

    75dpi:unscaled:pri=20 -> /usr/share/X11/fonts/75dpi
    ghostscript:pri=60 -> /usr/share/fonts/default/ghostscript
    misc:unscaled:pri=10 -> /usr/share/X11/fonts/misc
    type1:pri=40 -> /usr/share/X11/fonts/Type1
    type1:pri=50 -> /usr/share/fonts/default/Type1

Cela ajoutera /usr/share/X11/fonts/misc comme premier FPE avec l'attribut 'unscaled', le deuxième FPE sera /usr/share/X11/fonts/75dpi, également avec l'attribut 'unscaled', etc. Ceci est fonctionnellement équivalent à définir le chemin des polices suivant :

    /usr/share/X11/fonts/misc:unscaled,
    /usr/share/X11/fonts/75dpi:unscaled,
    /usr/share/X11/fonts/Type1,
    /usr/share/fonts/default/Type1,
    /usr/share/fonts/default/ghostscript
