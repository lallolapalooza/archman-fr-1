NOM

XScreenSaver - Bibliothèque client d'extension de protecteur d'écran X11

SYNTAXE

#include <X11/extensions/scrnsaver.h>

typedef struct {
    Window window;                /* fenêtre du protecteur d'écran */
    int state;                    /* ScreenSaver{Off,On,Disabled} */
    int kind;                     /* ScreenSaver{Blanked,Internal,External} */
    unsigned long til_or_since;   /* millisecondes */
    unsigned long idle;           /* millisecondes */
    unsigned long eventMask;      /* événements */
} XScreenSaverInfo;

typedef struct {
    int type;               /* type d'événement */
    unsigned long serial;   /* # de la dernière requête traitée par le serveur */
    Bool send_event;        /* vrai si cela provient d'une requête SendEvent */
    Display *display;       /* Display à partir duquel l'événement a été lu */
    Window window;          /* fenêtre du protecteur d'écran */
    Window root;            /* fenêtre racine de l'écran de l'événement */
    int state;              /* ScreenSaver{Off,On,Cycle} */
    int kind;               /* ScreenSaver{Blanked,Internal,External} */
    Bool forced;            /* étendues de la nouvelle région */
    Time time;              /* horodatage de l'événement */
} XScreenSaverNotifyEvent;
Bool XScreenSaverQueryExtension(Display *dpy,
    int *event_base_return, int *error_base_return);
Status XScreenSaverQueryVersion(Display *dpy,
    int *major_version_return, int *minor_version_return);
XScreenSaverInfo *XScreenSaverAllocInfo(void);
Status XScreenSaverQueryInfo(Display *dpy, Drawable drawable,
    XScreenSaverInfo *saver_info);
void XScreenSaverSelectInput(Display *dpy, Drawable drawable,
    unsigned long mask);
void XScreenSaverSetAttributes(Display *dpy, Drawable drawable,
    int x, int y, unsigned int width, unsigned int height,
    unsigned int border_width, int depth, unsigned int class,
    Visual *visual, unsigned long valuemask,
    XSetWindowAttributes *attributes);
void XScreenSaverUnsetAttributes(Display *dpy, Drawable drawable);
void XScreenSaverRegister(Display *dpy, int screen, XID xid, Atom type);
Status XScreenSaverUnregister(Display *dpy, int screen);
Status XScreenSaverGetRegistered(Display *dpy, int screen,
    XID *xid, Atom *type);
void XScreenSaverSuspend(Display *dpy, Bool suspend);

DESCRIPTION

Le système X Window fournit un support pour changer l'image sur un écran après une période d'inactivité configurable par l'utilisateur afin d'éviter de brûler les luminophores du tube cathodique. Cependant, aucune interface n'est fournie à l'utilisateur pour contrôler l'image affichée. Cette extension permet à un client externe de « protecteur d'écran » de détecter quand l'image alternative doit être affichée et de fournir les graphismes.

Les implémentations actuelles de serveurs X fournissent généralement au moins une forme d'image de « protecteur d'écran ». Historiquement, il s'agissait d'une copie du logo X dessinée sur le fond de la fenêtre racine. Cependant, de nombreux utilisateurs ont demandé un mécanisme leur permettant d'écrire des programmes de protecteur d'écran offrant des capacités similaires à celles fournies par d'autres systèmes de fenêtrage. En particulier, ces utilisateurs souhaitent souvent pouvoir afficher des logos d'entreprise, des instructions sur la façon de réactiver l'écran et des utilitaires de verrouillage automatique de l'écran. Cette extension fournit un moyen d'écrire de tels clients.

Hypothèses

Cette extension exporte la notion d'une fenêtre de protecteur d'écran spéciale qui est mappée au-dessus de toutes les autres fenêtres d'un écran. Cette fenêtre a l'attribut override-redirect défini de sorte qu'elle ne soit pas sujette à la manipulation par le gestionnaire de fenêtres. De plus, l'identifiant X de la fenêtre n'est jamais retourné par les requêtes QueryTree sur la fenêtre racine, de sorte qu'il n'est généralement pas visible par d'autres clients.

XScreenSaverQueryExtension retourne True si l'extension XScreenSaver est disponible sur l'écran donné. Un client doit appeler XScreenSaverQueryExtension avant d'appeler toute autre fonction XScreenSaver afin de négocier une version de protocole compatible ; sinon, le comportement du client sera indéfini (XScreenSaver peut fonctionner ou non).

Si l'extension est prise en charge, le numéro d'événement pour les événements ScreenSaverNotify est retourné dans la valeur pointée par event_base. Aucun erreur supplémentaire n'étant défini par cette extension, les résultats de error_base ne sont pas définis.

XScreenSaverQueryVersion retourne True si la requête a réussi ; les valeurs des versions de protocole majeure et mineure prises en charge par le serveur sont retournées dans major_version_return et minor_version_return.

XScreenSaverAllocInfo alloue et retourne une structure XScreenSaverInfo à utiliser dans les appels à XScreenSaverQueryInfo. Tous les champs de la structure sont initialisés à zéro. Si une mémoire insuffisante est disponible, NULL est retourné. Les résultats de cette routine peuvent être libérés en utilisant XFree.

XScreenSaverQueryInfo retourne des informations sur l'état actuel du serveur d'écran dans saver_info et une valeur non nulle est retournée. Si l'extension n'est pas prise en charge, saver_info n'est pas modifié et 0 est retourné.

Le champ state spécifie si le protecteur d'écran est actuellement actif et comment la valeur til-or-since doit être interprétée :

Off
L'écran n'est pas sauvegardé actuellement ; til-or-since spécifie le nombre de millisecondes jusqu'à ce que le protecteur d'écran soit censé s'activer.
On
L'écran est actuellement sauvegardé ; til-or-since spécifie le nombre de millisecondes depuis l'activation du protecteur d'écran.
Disabled
Le protecteur d'écran est actuellement désactivé ; til-or-since est zéro.

Le champ kind spécifie le mécanisme qui est actuellement utilisé ou qui aurait été utilisé si l'écran était sauvegardé :

Blanked
Le signal vidéo vers le moniteur d'affichage a été désactivé.
Internal
Une image de protecteur d'écran intégrée et dépendante du serveur a été affichée ; soit aucun client n'avait défini les attributs de la fenêtre du protecteur d'écran, soit un autre client avait le serveur saisi lorsque le protecteur d'écran s'est activé.
External
La fenêtre du protecteur d'écran a été mappée avec des attributs définis par un client utilisant la requête ScreenSaverSetAttributes.

Le champ idle spécifie le nombre de millisecondes depuis la dernière entrée reçue de l'utilisateur sur l'un des périphériques d'entrée.
Le champ event-mask spécifie quels événements de protecteur d'écran, le cas échéant, ce client a demandés en utilisant ScreenSaverSelectInput.

XScreenSaverSelectInput demande que des événements liés au protecteur d'écran soient générés pour ce client. Si aucun bit n'est défini dans event-mask, aucun événement ne sera généré. Sinon, toute combinaison des bits suivants peut être définie :

ScreenSaverNotify
Si ce bit est défini, des événements ScreenSaverNotify sont générés chaque fois que le protecteur d'écran est activé ou désactivé.
ScreenSaverCycle
Si ce bit est défini, des événements ScreenSaverNotify sont générés chaque fois que l'intervalle de cycle du protecteur d'écran est atteint.

XScreenSaverSetAttributes définit les attributs à utiliser la prochaine fois que le protecteur d'écran externe sera activé. Si un autre client a actuellement les attributs définis, une erreur BadAccess est générée et la requête est ignorée.
Sinon, les attributs spécifiés sont vérifiés comme s'ils étaient utilisés dans une requête core CreateWindow dont le parent est la racine. Le champ override-redirect est ignoré car il est implicitement défini à True. Si les attributs de fenêtre entraînent une erreur conformément aux règles de CreateWindow, la requête est ignorée.
Sinon, les attributs sont stockés et prendront effet lors de la prochaine activation qui se produit lorsque le serveur n'est pas saisi par un autre client. Toutes les ressources spécifiées pour les attributs background-pixmap ou cursor peuvent être libérées immédiatement. Le serveur est libre de

DESCRIPTION

The X Screen Saver extension provides a mechanism for applications to interact with the X server's screen saver functionality. It allows clients to control the screen saver's behavior, query its status, and receive events related to screen saver activation and deactivation.

XScreenSaverQueryExtension determines if the screen saver extension is available on the server. If it is, it returns True and fills in the event_base_return and error_base_return arguments with the base event and error codes for the extension.

XScreenSaverQueryVersion queries the version of the X Screen Saver extension implemented by the server. It returns True if the extension is present and fills in the major_version_return and minor_version_return arguments with the version numbers.

XScreenSaverAllocEvent allocates an event code for the screen saver extension if it has not already been allocated by another client. It returns True if successful, and fills in the event_base_return and error_base_return arguments.

XScreenSaverAllocColor allocates a color for use by the screen saver. It takes a pointer to an XColor structure containing the desired color definition and returns a pointer to an XColor structure containing the allocated color closest to the requested color.

XScreenSaverSelectInput tells the X server which windows should receive screen saver events. The window_list argument is a list of window IDs, and count is the number of windows in the list.

XScreenSaverGetScreenSaverInfo retrieves information about the current screen saver settings. It returns a pointer to an XScreenSaverInfo structure containing details such as the delay before activation, the timeout period, whether the screen saver is enabled, and the root window ID of the screen the information pertains to. If the screen saver is currently active, the root_return argument will be set to the root window of the screen where the screen saver is active.

XScreenSaverSetAttributes sets the attributes for a screen saver window. The window_list and count arguments specify the windows for which to set the attributes. The other arguments specify parameters such as maximum recursions, fill style for width and height, and the event mask to be used.

XScreenSaverGetAttributes retrieves the screen saver attributes for a specific window.

XScreenSaverUnsetAttributes instructs the server to discard any previously set screen saver window attributes for the specified window.

XScreenSaverForce can be used to force the screen saver state. A value of Activate (typically 1) activates the screen saver, and a value of Reset (typically 0) resets the screen saver timer. Note that the actual values for Activate and Reset might vary depending on the implementation.

When the screen saver is activated, the server may create a window to display the screen saver. The attributes of this window, such as its pixmap, cursor, and colormap, can be influenced by the client. However, it's important to note that the server may choose to ignore or modify certain attributes, especially those related to dynamically changing resources.

If the specified colormap no longer exists when the screen saver activates, the parent's colormap is used instead. If no errors are generated by this request, any previous screen saver window attributes set by this client are released.

When the screen saver next activates and the server is not grabbed by another client, the screen saver window is created, if necessary, and set to the specified attributes and events are generated as usual. The colormap associated with the screen saver window is installed. Finally, the screen saver window is mapped.

The window remains mapped and at the top of the stacking order until the screen saver is deactivated in response to activity on any of the user input devices, a ForceScreenSaver request with a value of Reset, or any request that would cause the window to be unmapped.

If the screen saver activates while the server is grabbed by another client, the internal saver mechanism is used. The ForceScreenSaver request may be used with a value of Active to deactivate the internal saver and activate the external saver.

If the screen saver client's connection to the server is broken while the screen saver is activated and the client's close down mode has not been RetainPermanent or RetainTemporary, the current screen saver is deactivated and the internal screen saver is immediately activated.

When the screen saver deactivates, the screen saver window's colormap is uninstalled and the window is unmapped (except as described below). The screen saver XID is disassociated with the window and the server may, but is not required to, destroy the window along with any children.

When the screen saver is being deactivated and then immediately reactivated (such as when switching screen savers), the server may leave the screen saver window mapped (typically to avoid generating exposures).

XScreenSaverUnsetAttributes instructs the server to discard any previous screen saver window attributes set by this client.

XScreenSaverRegister stores the given XID in the _SCREEN_SAVER_ID property (of the given type) on the root window of the specified screen. It returns zero if an error is encountered and the property is not changed, otherwise it returns non-zero.

XScreenSaverUnregister removes any _SCREEN_SAVER_ID from the root window of the specified screen. It returns zero if an error is encountered and the property is changed, otherwise it returns non-zero.

XScreenSaverGetRegistered returns the XID and type stored in the _SCREEN_SAVER_ID property on the root window of the specified screen. It returns zero if an error is encountered or if the property does not exist or is not of the correct format; otherwise it returns non-zero.

XScreenSaverSuspend temporarily suspends the screensaver and DPMS timer if suspend is 'True', and restarts the timer if suspend is 'False'.

This function should be used by applications that don't want the screensaver or DPMS to become activated while they're for example in the process of playing a media sequence, or are otherwise continuously presenting visual information to the user while in a non-interactive state. This function is not intended to be called by an external screensaver application.

If XScreenSaverSuspend is called multiple times with suspend set to 'True', it must be called an equal number of times with suspend set to 'False' in order for the screensaver timer to be restarted. This request has no affect if a client tries to resume the screensaver without first having suspended it. XScreenSaverSuspend can thus not be used by one client to resume the screensaver if it's been suspended by another client.

If a client that has suspended the screensaver becomes disconnected from the X server, the screensaver timer will automatically be restarted, unless it's still suspended by another client. Suspending the screensaver timer doesn't prevent the screensaver from being forcibly activated with the ForceScreenSaver request, or a DPMS mode from being set with the DPMSForceLevel request.

XScreenSaverSuspend also doesn't deactivate the screensaver or DPMS if either is active at the time the request to suspend them is received by the X server. But once they've been deactivated, they won't automatically be activated again, until the client has canceled the suspension.

ERRORS

XScreenSaverSelectInput, XScreenSaverQueryInfo, XScreenSaverSetAttributes, and XScreenSaverUnsetAttributes will generate a BadDrawable error if drawable is not a valid drawable identifier. If any undefined bits are set in event-mask, a BadValue error is generated by XScreenSaverSelectInput.

AVAILABILITY

XScreenSaverSuspend is available in version 1.1 and later versions of the X Screen Saver Extension. Version 1.1 was first released with X11R7.1.
