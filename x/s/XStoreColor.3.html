XStoreColors(3) FONCTIONS XLIB XStoreColors(3)

NOM

XStoreColors, XStoreColor, XStoreNamedColor - définir les couleurs

SYNTAXE

int XStoreColors(Display *display, Colormap colormap, XColor color[], int ncolors);

int XStoreColor(Display *display, Colormap colormap, XColor *color);

int XStoreNamedColor(Display *display, Colormap colormap, _Xconst char *color, unsigned long pixel, int flags);

ARGUMENTS

couleur
Spécifie les valeurs RVB et de pixel ou la chaîne de nom de couleur (par exemple, red).
couleur
Spécifie un tableau de structures de définition de couleur à stocker.
colormap
Spécifie la table des couleurs.
display
Spécifie la connexion au serveur X.
flags
Spécifie quels composants rouge, vert et bleu sont définis.
ncolors
Spécifie le nombre de structures XColor dans le tableau de définition de couleur.
pixel
Spécifie l'entrée dans la table des couleurs.

DESCRIPTION

La fonction XStoreColors modifie les entrées de la table des couleurs des valeurs de pixel spécifiées dans les membres pixel des structures XColor. Vous spécifiez quels composants de couleur doivent être modifiés en définissant DoRed, DoGreen et/ou DoBlue dans le membre flags des structures XColor. Si la table des couleurs est installée pour son écran, les modifications sont visibles immédiatement. XStoreColors modifie les pixels spécifiés s'ils sont alloués en écriture dans la table des couleurs par n'importe quel client, même si un ou plusieurs pixels génèrent une erreur. Si un pixel spécifié n'est pas un index valide dans la table des couleurs, une erreur BadValue résulte. Si un pixel spécifié est soit non alloué, soit alloué en lecture seule, une erreur BadAccess résulte. Si plusieurs pixels sont en erreur, celui qui est signalé est arbitraire.

XStoreColors peut générer des erreurs BadAccess, BadColor et BadValue.

La fonction XStoreColor modifie l'entrée de la table des couleurs de la valeur de pixel spécifiée dans le membre pixel de la structure XColor. Vous avez spécifié cette valeur dans le membre pixel de la structure XColor. Cette valeur de pixel doit être une cellule de lecture/écriture et un index valide dans la table des couleurs. Si un pixel spécifié n'est pas un index valide dans la table des couleurs, une erreur BadValue résulte. XStoreColor modifie également les composants de couleur rouge, vert et/ou bleu. Vous spécifiez quels composants de couleur doivent être modifiés en définissant DoRed, DoGreen et/ou DoBlue dans le membre flags de la structure XColor. Si la table des couleurs est installée pour son écran, les modifications sont visibles immédiatement.

XStoreColor peut générer des erreurs BadAccess, BadColor et BadValue.

La fonction XStoreNamedColor recherche le nom de couleur nommé par rapport à l'écran associé à la table des couleurs et stocke le résultat dans la table des couleurs spécifiée. L'argument pixel détermine l'entrée dans la table des couleurs. L'argument flags détermine quels composants rouge, vert et bleu sont définis. Vous pouvez définir ce membre avec l'OU exclusif binaire des bits DoRed, DoGreen et DoBlue. Si le nom de couleur n'est pas dans l'encodage de caractères portable hôte, le résultat est dépendant de l'implémentation. L'utilisation de majuscules ou de minuscules n'a pas d'importance. Si le pixel spécifié n'est pas un index valide dans la table des couleurs, une erreur BadValue résulte. Si le pixel spécifié est soit non alloué, soit alloué en lecture seule, une erreur BadAccess résulte.

XStoreNamedColor peut générer des erreurs BadAccess, BadColor, BadName et BadValue.

DIAGNOSTICS

BadAccess
Un client a tenté de libérer une entrée de table de couleurs qu'il n'avait pas déjà allouée.
BadAccess
Un client a tenté d'écrire dans une entrée de table de couleurs en lecture seule.
BadColor
Une valeur pour un argument Colormap ne nomme pas une Colormap définie.
BadName
Une police ou une couleur du nom spécifié n'existe pas.
BadValue
Une valeur numérique se situe en dehors de la plage de valeurs acceptées par la requête. Sauf si une plage spécifique est spécifiée pour un argument, la plage complète définie par le type de l'argument est acceptée. Tout argument défini comme un ensemble d'alternatives peut générer cette erreur.
