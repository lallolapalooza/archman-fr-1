XScreenSaverGetRegistered(3)

Paquet: libxss

Licences: X11

XScreenSaver(3) Version X 11 XScreenSaver(3)

NOM

XScreenSaver - Bibliothèque client de l'extension X11 de l'économiseur d'écran

SYNTAXE

#include <X11/extensions/scrnsaver.h>

typedef struct {
    Window window;                /* fenêtre de l'économiseur d'écran */
    int state;                    /* ScreenSaver{Off,On,Disabled} */
    int kind;                     /* ScreenSaver{Blanked,Internal,External} */
    unsigned long til_or_since;   /* millisecondes */
    unsigned long idle;           /* millisecondes */
    unsigned long eventMask;      /* événements */
} XScreenSaverInfo;

typedef struct {
    int type;               /* type d'événement */
    unsigned long serial;   /* numéro de la dernière requête traitée par le serveur */
    Bool send_event;        /* vrai si ceci provient d'une requête SendEvent */
    Display *display;       /* affichage à partir duquel l'événement a été lu */
    Window window;          /* fenêtre de l'économiseur d'écran */
    Window root;            /* fenêtre racine de l'écran d'événement */
    int state;              /* ScreenSaver{Off,On,Cycle} */
    int kind;               /* ScreenSaver{Blanked,Internal,External} */
    Bool forced;            /* étendues de la nouvelle région */
    Time time;              /* horodatage de l'événement */
} XScreenSaverNotifyEvent;
Bool XScreenSaverQueryExtension(Display *dpy,
    int *event_base_return, int *error_base_return);
Status XScreenSaverQueryVersion(Display *dpy,
    int *major_version_return, int *minor_version_return);
XScreenSaverInfo *XScreenSaverAllocInfo(void);
Status XScreenSaverQueryInfo(Display *dpy, Drawable drawable,
    XScreenSaverInfo *saver_info);
void XScreenSaverSelectInput(Display *dpy, Drawable drawable,
    unsigned long mask);
void XScreenSaverSetAttributes(Display *dpy, Drawable drawable,
    int x, int y, unsigned int width, unsigned int height,
    unsigned int border_width, int depth, unsigned int class,
    Visual *visual, unsigned long valuemask,
    XSetWindowAttributes *attributes);
void XScreenSaverUnsetAttributes(Display *dpy, Drawable drawable);
void XScreenSaverRegister(Display *dpy, int screen, XID xid, Atom type);
Status XScreenSaverUnregister(Display *dpy, int screen);
Status XScreenSaverGetRegistered(Display *dpy, int screen,
    XID *xid, Atom *type);
void XScreenSaverSuspend(Display *dpy, Bool suspend);

DESCRIPTION

Le système de fenêtrage X fournit une prise en charge pour changer l'image sur un écran après une période d'inactivité configurable par l'utilisateur, afin d'éviter de brûler les phosphores du tube cathodique. Cependant, aucune interface n'est fournie à l'utilisateur pour contrôler l'image qui est dessinée. Cette extension permet à un client externe « d'économiseur d'écran » de détecter quand l'image alternative doit être affichée et de fournir les graphiques.

Les implémentations actuelles de serveurs X fournissent généralement au moins une forme d'image « d'économiseur d'écran ». Historiquement, il s'agissait d'une copie du logo X dessinée sur le motif de fond racine. Cependant, de nombreux utilisateurs ont demandé un mécanisme leur permettant d'écrire des programmes d'économiseur d'écran offrant des fonctionnalités similaires à celles fournies par d'autres systèmes de fenêtrage. En particulier, ces utilisateurs souhaitent souvent pouvoir afficher des logos d'entreprise, des instructions sur la façon de réactiver l'écran et des utilitaires de verrouillage automatique de l'écran. Cette extension fournit un moyen d'écrire de tels clients.

Hypothèses

Cette extension exporte la notion d'une fenêtre spéciale d'économiseur d'écran qui est mappée au-dessus de toutes les autres fenêtres d'un affichage. Cette fenêtre a l'attribut override-redirect défini afin qu'elle ne soit pas soumise à la manipulation par le gestionnaire de fenêtres. De plus, l'identifiant X de la fenêtre n'est jamais retourné par les requêtes QueryTree sur la fenêtre racine, de sorte qu'elle n'est généralement pas visible par d'autres clients.

XScreenSaverQueryExtension renvoie True si l'extension XScreenSaver est disponible sur l'affichage donné. Un client doit appeler XScreenSaverQueryExtension avant d'appeler toute autre fonction XScreenSaver afin de négocier une version de protocole compatible ; sinon, le client obtiendra un comportement indéfini (XScreenSaver peut fonctionner ou non).

Si l'extension est prise en charge, le numéro d'événement pour les événements ScreenSaverNotify est renvoyé dans la valeur pointée par event_base. Aucune erreur supplémentaire n'étant définie par cette extension, les résultats de error_base ne sont pas définis.

XScreenSaverQueryVersion renvoie True si la requête a réussi ; les valeurs des versions de protocole majeure et mineure prises en charge par le serveur sont renvoyées dans major_version_return et minor_version_return.

XScreenSaverAllocInfo alloue et renvoie une structure XScreenSaverInfo à utiliser dans les appels à XScreenSaverQueryInfo. Tous les champs de la structure sont initialisés à zéro. Si une mémoire insuffisante est disponible, NULL est renvoyé. Les résultats de cette routine peuvent être libérés à l'aide de XFree.

XScreenSaverQueryInfo renvoie des informations sur l'état actuel du serveur d'affichage dans saver_info et une valeur non nulle est renvoyée. Si l'extension n'est pas prise en charge, saver_info n'est pas modifié et 0 est renvoyé.

Le champ state spécifie si l'économiseur d'écran est actuellement actif et comment la valeur til-or-since doit être interprétée :

Off
L'écran n'est pas actuellement économisé ; til-or-since spécifie le nombre de millisecondes jusqu'à ce que l'économiseur d'écran soit censé s'activer.
On
L'écran est actuellement économisé ; til-or-since spécifie le nombre de millisecondes depuis que l'économiseur d'écran s'est activé.
Disabled
L'économiseur d'écran est actuellement désactivé ; til-or-since est zéro.

Le champ kind spécifie le mécanisme qui est actuellement utilisé ou qui l'aurait été si l'écran avait été économisé :

Blanked
Le signal vidéo vers le moniteur d'affichage a été désactivé.
Internal
Une image d'économiseur d'écran intégrée et dépendante du serveur a été affichée ; soit aucun client n'avait défini les attributs de la fenêtre de l'économiseur d'écran, soit un autre client avait le serveur capturé lorsque l'économiseur d'écran s'est activé.
External
La fenêtre de l'économiseur d'écran a été mappée avec des attributs définis par un client utilisant la requête ScreenSaverSetAttributes.

Le champ idle spécifie le nombre de millisecondes depuis la dernière entrée reçue de l'utilisateur sur l'un des périphériques d'entrée.
Le champ event-mask spécifie quels événements d'économiseur d'écran, le cas échéant, ce client a demandés à l'aide de ScreenSaverSelectInput.

XScreenSaverSelectInput demande que des événements liés à l'économiseur d'écran soient générés pour ce client. Si aucun bit n'est défini dans event-mask, aucun événement ne sera généré. Sinon, toute combinaison des bits suivants peut être définie :

ScreenSaverNotify
Si ce bit est défini, des événements ScreenSaverNotify sont générés chaque fois que l'économiseur d'écran est activé ou désactivé.
ScreenSaverCycle
Si ce bit est défini, des événements ScreenSaverNotify sont générés chaque fois que l'intervalle de cycle de l'économiseur d'écran est atteint.

XScreenSaverSetAttributes définit les attributs à utiliser lors de la prochaine activation de l'économiseur d'écran externe. Si un autre client a actuellement les attributs définis, une erreur BadAccess est générée et la requête est ignorée.
Sinon, les attributs spécifiés sont vérifiés comme s'ils avaient été utilisés dans une requête CreateWindow de base dont le parent est la racine. Le champ override-redirect est ignoré car il est implicitement défini sur True. Si les attributs de la fenêtre entraînent une erreur conformément aux règles de CreateWindow, la requête est ignorée.
Sinon, les attributs sont stockés et prendront effet lors de la prochaine activation qui se produit lorsque le serveur n'est pas capturé par un autre client. Les ressources spécifiées pour les attributs background-pixmap ou cursor peuvent être libérées immédiatement.

DESCRIPTION

Le serveur est libre de copier les ressources background-pixmap ou cursor ou de les utiliser telles quelles ; par conséquent, l'effet de la modification du contenu de ces ressources est indéfini. Si la colormap spécifiée n'existe plus lorsque le protège-écran s'active, la colormap du parent est utilisée à la place. Si aucune erreur n'est générée par cette requête, tous les attributs de fenêtre de protège-écran précédemment définis par ce client sont libérés.

Lorsque le protège-écran s'activera la prochaine fois et que le serveur ne sera pas saisi par un autre client, la fenêtre du protège-écran sera créée, si nécessaire, et configurée avec les attributs spécifiés, et les événements seront générés comme d'habitude. La colormap associée à la fenêtre du protège-écran sera installée. Enfin, la fenêtre du protège-écran sera mappée.

La fenêtre reste mappée et au sommet de l'ordre d'empilement jusqu'à ce que le protège-écran soit désactivé en réponse à une activité sur l'un des périphériques d'entrée utilisateur, une requête ForceScreenSaver avec une valeur Reset, ou toute requête qui provoquerait le démappage de la fenêtre.

Si le protège-écran s'active alors que le serveur est saisi par un autre client, le mécanisme de sauvegarde interne est utilisé. La requête ForceScreenSaver peut être utilisée avec une valeur Active pour désactiver le protège-écran interne et activer le protège-écran externe.

Si la connexion du client de protège-écran au serveur est rompue pendant que le protège-écran est activé et que le mode de fermeture du client n'a pas été RetainPermanent ou RetainTemporary, le protège-écran actuel est désactivé et le protège-écran interne est immédiatement activé.

Lorsque le protège-écran se désactive, la colormap de la fenêtre du protège-écran est désinstallée et la fenêtre est démappée (sauf comme décrit ci-dessous). Le XID du protège-écran est dissocié de la fenêtre et le serveur peut, mais n'est pas obligé de, détruire la fenêtre ainsi que tous ses enfants.

Lorsque le protège-écran est en cours de désactivation puis de réactivation immédiate (comme lors du changement de protège-écran), le serveur peut laisser la fenêtre du protège-écran mappée (typiquement pour éviter de générer des expositions).

XScreenSaverUnsetAttributes demande au serveur de rejeter tous les attributs de fenêtre de protège-écran précédemment définis par ce client.

XScreenSaverRegister stocke le XID donné dans la propriété _SCREEN_SAVER_ID (du type donné type) sur la fenêtre racine de l'écran spécifié screen. Il renvoie zéro si une erreur est rencontrée et que la propriété n'est pas modifiée, sinon il renvoie une valeur non nulle.

XScreenSaverUnregister supprime tout _SCREEN_SAVER_ID de la fenêtre racine de l'écran spécifié screen. Il renvoie zéro si une erreur est rencontrée et que la propriété est modifiée, sinon il renvoie une valeur non nulle.

XScreenSaverGetRegistered renvoie le XID et le type stockés dans la propriété _SCREEN_SAVER_ID sur la fenêtre racine de l'écran spécifié screen. Il renvoie zéro si une erreur est rencontrée ou si la propriété n'existe pas ou n'est pas du bon format ; sinon il renvoie une valeur non nulle.

XScreenSaverSuspend suspend temporairement le protège-écran et le minuteur DPMS si suspend est 'True', et redémarre le minuteur si suspend est 'False'.
Cette fonction doit être utilisée par les applications qui ne veulent pas que le protège-écran ou le DPMS s'activent pendant qu'elles sont, par exemple, en train de jouer une séquence média, ou présentent continuellement des informations visuelles à l'utilisateur dans un état non interactif. Cette fonction n'est pas destinée à être appelée par une application de protège-écran externe.
Si XScreenSaverSuspend est appelée plusieurs fois avec suspend à 'True', elle doit être appelée un nombre égal de fois avec suspend à 'False' pour que le minuteur du protège-écran soit redémarré. Cette requête n'a aucun effet si un client tente de reprendre le protège-écran sans l'avoir préalablement suspendu. XScreenSaverSuspend ne peut donc pas être utilisée par un client pour reprendre le protège-écran s'il a été suspendu par un autre client.
Si un client qui a suspendu le protège-écran se déconnecte du serveur X, le minuteur du protège-écran sera automatiquement redémarré, à moins qu'il ne soit encore suspendu par un autre client. La suspension du minuteur du protège-écran n'empêche pas l'activation forcée du protège-écran avec la requête ForceScreenSaver, ou la définition d'un mode DPMS avec la requête DPMSForceLevel.
XScreenSaverSuspend ne désactive pas non plus le protège-écran ou le DPMS s'ils sont actifs au moment où la requête pour les suspendre est reçue par le serveur X. Mais une fois qu'ils ont été désactivés, ils ne seront pas automatiquement réactivés, jusqu'à ce que le client ait annulé la suspension.

ERREURS

XScreenSaverSelectInput, XScreenSaverQueryInfo, XScreenSaverSetAttributes, et XScreenSaverUnsetAttributes généreront une erreur BadDrawable si drawable n'est pas un identifiant de dessin valide. Si des bits indéfinis sont définis dans event-mask, une erreur BadValue est générée par XScreenSaverSelectInput.

DISPONIBILITÉ

XScreenSaverSuspend est disponible dans la version 1.1 et les versions ultérieures de l'extension X Screen Saver. La version 1.1 est sortie pour la première fois avec X11R7.1.
