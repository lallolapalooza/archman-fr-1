NOM

XScreenSaver - Bibliothèque client d'extension X11 pour le protège-écran

SYNTAXE

#include <X11/extensions/scrnsaver.h>

typedef struct {
    Window window;                /∗ fenêtre du protège-écran */
    int state;                    /∗ ScreenSaver{Off,On,Disabled} */
    int kind;                     /∗ ScreenSaver{Blanked,Internal,External} */
    unsigned long til_or_since;   /∗ millisecondes */
    unsigned long idle;           /∗ millisecondes */
    unsigned long eventMask;      /∗ événements */
} XScreenSaverInfo;

typedef struct {
    int type;               /∗ de l'événement */
    unsigned long serial;   /∗ # de la dernière requête traitée par le serveur */
    Bool send_event;        /∗ true si ceci provient d'une requête SendEvent */
    Display *display;       /∗ Affichage à partir duquel l'événement a été lu */
    Window window;          /∗ fenêtre du protège-écran */
    Window root;            /∗ fenêtre racine de l'écran de l'événement */
    int state;              /∗ ScreenSaver{Off,On,Cycle} */
    int kind;               /∗ ScreenSaver{Blanked,Internal,External} */
    Bool forced;            /∗ étendues de la nouvelle région */
    Time time;              /∗ horodatage de l'événement */
} XScreenSaverNotifyEvent;

DESCRIPTION

Le système de fenêtrage X fournit un support pour changer l'image affichée sur un écran après une période d'inactivité configurable par l'utilisateur, afin d'éviter de brûler les luminophores du tube cathodique. Cependant, aucune interface n'est fournie pour que l'utilisateur puisse contrôler l'image affichée. Cette extension permet à un client externe de « protège-écran » de détecter quand l'image alternative doit être affichée et de fournir les graphiques.

Les implémentations actuelles de serveurs X fournissent généralement au moins une forme d'image de « protège-écran ». Historiquement, il s'agissait d'une copie du logo X dessinée sur le motif de fond de la fenêtre racine. Cependant, de nombreux utilisateurs ont demandé un mécanisme leur permettant d'écrire des programmes de protège-écran offrant des fonctionnalités similaires à celles fournies par d'autres systèmes de fenêtrage. En particulier, ces utilisateurs souhaitent souvent pouvoir afficher des logos d'entreprise, des instructions sur la manière de réactiver l'écran et des utilitaires de verrouillage d'écran automatique. Cette extension fournit un moyen d'écrire de tels clients.

Hypothèses

Cette extension exporte la notion d'une fenêtre spéciale de protège-écran, qui est mappée au-dessus de toutes les autres fenêtres d'un affichage. Cette fenêtre a l'attribut override-redirect défini de sorte qu'elle ne soit pas soumise à une manipulation par le gestionnaire de fenêtres. De plus, l'identifiant X de la fenêtre n'est jamais retourné par les requêtes QueryTree sur la fenêtre racine, de sorte qu'elle n'est généralement pas visible par d'autres clients.

XScreenSaverQueryExtension retourne True si l'extension XScreenSaver est disponible sur l'affichage donné. Un client doit appeler XScreenSaverQueryExtension avant d'appeler toute autre fonction XScreenSaver afin de négocier une version de protocole compatible ; sinon, le comportement du client sera indéfini (XScreenSaver peut fonctionner ou non).

Si l'extension est prise en charge, le numéro d'événement pour les événements ScreenSaverNotify est retourné dans la valeur pointée par event_base. Comme aucun erreur supplémentaire n'est défini par cette extension, les résultats de error_base ne sont pas définis.

XScreenSaverQueryVersion retourne True si la requête a réussi ; les valeurs des versions de protocole majeures et mineures prises en charge par le serveur sont retournées dans major_version_return et minor_version_return.

XScreenSaverAllocInfo alloue et retourne une structure XScreenSaverInfo à utiliser dans les appels à XScreenSaverQueryInfo. Tous les champs de la structure sont initialisés à zéro. Si la mémoire disponible est insuffisante, NULL est retourné. Les résultats de cette routine peuvent être libérés à l'aide de XFree.

XScreenSaverQueryInfo retourne des informations sur l'état actuel du serveur d'affichage dans saver_info et une valeur non nulle est retournée. Si l'extension n'est pas prise en charge, saver_info n'est pas modifié et 0 est retourné.

Le champ state spécifie si le protège-écran est actuellement actif ou non, et comment la valeur til-or-since doit être interprétée :

Off
L'écran n'est actuellement pas protégé ; til-or-since spécifie le nombre de millisecondes jusqu'à ce que le protège-écran doive s'activer.
On
L'écran est actuellement protégé ; til-or-since spécifie le nombre de millisecondes depuis l'activation du protège-écran.
Disabled
Le protège-écran est actuellement désactivé ; til-or-since est zéro.

Le champ kind spécifie le mécanisme qui est actuellement utilisé, ou qui aurait été utilisé si l'écran avait été protégé :

Blanked
Le signal vidéo vers le moniteur d'affichage a été désactivé.
Internal
Une image de protège-écran intégrée, dépendante du serveur, a été affichée ; soit aucun client n'avait défini les attributs de la fenêtre de protège-écran, soit un autre client avait saisi le serveur au moment de l'activation du protège-écran.
External
La fenêtre de protège-écran a été mappée avec les attributs définis par un client utilisant la requête ScreenSaverSetAttributes.

Le champ idle spécifie le nombre de millisecondes depuis la dernière entrée reçue de l'utilisateur sur l'un des périphériques d'entrée.
Le champ event-mask spécifie quels événements de protège-écran, le cas échéant, ce client a demandés à l'aide de ScreenSaverSelectInput.

XScreenSaverSelectInput demande que les événements liés au protège-écran soient générés pour ce client. Si aucun bit n'est défini dans event-mask, aucun événement ne sera généré. Sinon, toute combinaison des bits suivants peut être définie :

ScreenSaverNotify
Si ce bit est défini, des événements ScreenSaverNotify sont générés chaque fois que le protège-écran est activé ou désactivé.
ScreenSaverCycle
Si ce bit est défini, des événements ScreenSaverNotify sont générés chaque fois que l'intervalle de cycle du protège-écran est atteint.

XScreenSaverSetAttributes définit les attributs à utiliser la prochaine fois que le protège-écran externe sera activé. Si un autre client a actuellement les attributs définis, une erreur BadAccess est générée et la requête est ignorée.
Sinon, les attributs spécifiés sont vérifiés comme s'ils étaient utilisés dans une requête CreateWindow de base dont le parent est la racine. Le champ override-redirect est ignoré car il est implicitement défini à True. Si les attributs de la fenêtre entraînent une erreur conformément aux règles de CreateWindow, la requête est ignorée.
Sinon, les attributs sont stockés et prendront effet lors de la prochaine activation qui se produit lorsque le serveur n'est pas saisi par un autre client. Toutes les ressources spécifiées pour les attributs background-pixmap ou cursor peuvent être libérées immédiatement. T

DESCRIPTION

Le protocole de l'économiseur d'écran X fournit des fonctions pour contrôler les économiseurs d'écran des fenêtres.

XScreenSaverQueryExtension interroge le serveur pour déterminer si le protocole de l'économiseur d'écran X est disponible. Si c'est le cas, il renvoie True et remplit event_base_return et error_base_return avec les numéros de base des événements et des erreurs du protocole, respectivement. Sinon, il renvoie False.

XScreenSaverQueryVersion interroge le serveur pour la version de l'extension de l'économiseur d'écran X. Il renvoie True si la requête aboutit et remplit major_version_return et minor_version_return avec les numéros de version.

XScreenSaverQueryInfo renvoie des informations sur l'état actuel de l'économiseur d'écran pour le drawable spécifié. Il renvoie un pointeur vers une structure XScreenSaverInfo qui contient les informations suivantes :

prefer_blanking
Indique la préférence du serveur pour le blanc de l'écran. Les valeurs possibles sont DontPreferBlanking, PassiveBlanking, et AlwaysBlanking.
allow_exposures
Indique si les expositions sont autorisées pendant que l'économiseur d'écran est actif. Les valeurs possibles sont DontAllowExposures, PassiveExposures, et AlwaysExposures.
event_delay
Le délai en millisecondes avant que l'économiseur d'écran ne soit activé après une période d'inactivité.
blank_delay
Le délai en millisecondes avant que l'écran ne devienne blanc.
expose_delay
Le délai en millisecondes avant que le contenu de l'économiseur d'écran ne soit dessiné.
version
La version de la structure XScreenSaverInfo.

La structure XScreenSaverInfo est allouée par la bibliothèque Xlib et doit être libérée par XFree.

XScreenSaverSetAttributes définit les attributs de la fenêtre de l'économiseur d'écran. Les attributs sont spécifiés par la structure XScreenSaverAttributes, qui contient les champs suivants :

background_pixmap
Le pixmap à utiliser comme arrière-plan de la fenêtre de l'économiseur d'écran.
background_pixel
La couleur de pixel à utiliser comme arrière-plan de la fenêtre de l'économiseur d'écran.
border_pixmap
Le pixmap à utiliser comme bordure de la fenêtre de l'économiseur d'écran.
border_pixel
La couleur de pixel à utiliser comme bordure de la fenêtre de l'économiseur d'écran.
border_width
La largeur de la bordure de la fenêtre de l'économiseur d'écran.
event_mask
Le masque d'événements à sélectionner pour la fenêtre de l'économiseur d'écran.
backing_store
Indique le type de stockage de sauvegarde souhaité pour la fenêtre de l'économiseur d'écran.
save_under
Indique si la fenêtre doit être enregistrée sous la fenêtre de l'économiseur d'écran.
colormap
La colormap à utiliser pour la fenêtre de l'économiseur d'écran.
cursor
Le curseur à utiliser pour la fenêtre de l'économiseur d'écran.

Le serveur est libre de copier les ressources background_pixmap ou cursor ou de les utiliser telles quelles ; par conséquent, l'effet de la modification du contenu de ces ressources est indéfini. Si la colormap spécifiée n'existe plus lorsque l'économiseur d'écran s'active, la colormap du parent est utilisée à la place. Si aucune erreur n'est générée par cette requête, tous les attributs précédents de la fenêtre de l'économiseur d'écran définis par ce client sont libérés.

Lorsque l'économiseur d'écran s'activera ensuite et que le serveur ne sera pas saisi par un autre client, la fenêtre de l'économiseur d'écran sera créée, si nécessaire, et définie avec les attributs spécifiés et les événements seront générés comme d'habitude. La colormap associée à la fenêtre de l'économiseur d'écran sera installée. Enfin, la fenêtre de l'économiseur d'écran sera mappée.

La fenêtre reste mappée et au sommet de l'ordre de superposition jusqu'à ce que l'économiseur d'écran soit désactivé en réponse à une activité sur l'un des périphériques d'entrée utilisateur, une requête ForceScreenSaver avec la valeur Reset, ou toute requête qui provoquerait le démappage de la fenêtre.

Si l'économiseur d'écran s'active alors que le serveur est saisi par un autre client, le mécanisme d'économiseur interne est utilisé. La requête ForceScreenSaver peut être utilisée avec la valeur Active pour désactiver l'économiseur interne et activer l'économiseur externe.

Si la connexion du client de l'économiseur d'écran au serveur est rompue pendant que l'économiseur d'écran est activé et que le mode de fermeture du client n'a pas été RetainPermanent ou RetainTemporary, l'économiseur d'écran actuel est désactivé et l'économiseur d'écran interne est immédiatement activé.

Lorsque l'économiseur d'écran est désactivé, la colormap de la fenêtre de l'économiseur d'écran est désinstallée et la fenêtre est démappée (sauf comme décrit ci-dessous). Le XID de l'économiseur d'écran est dissocié de la fenêtre et le serveur peut, mais n'est pas obligé de, détruire la fenêtre ainsi que tous ses enfants.

Lorsque l'économiseur d'écran est en cours de désactivation puis de réactivation immédiate (comme lors du changement d'économiseurs d'écran), le serveur peut laisser la fenêtre de l'économiseur d'écran mappée (typiquement pour éviter de générer des expositions).

XScreenSaverUnsetAttributes demande au serveur de supprimer tous les attributs précédents de la fenêtre de l'économiseur d'écran définis par ce client.

XScreenSaverRegister stocke le XID donné dans la propriété _SCREEN_SAVER_ID (du type donné) sur la fenêtre racine de l'écran spécifié. Il renvoie zéro si une erreur est rencontrée et que la propriété n'est pas modifiée, sinon il renvoie une valeur non nulle.

XScreenSaverUnregister supprime toute propriété _SCREEN_SAVER_ID de la fenêtre racine de l'écran spécifié. Il renvoie zéro si une erreur est rencontrée et que la propriété est modifiée, sinon il renvoie une valeur non nulle.

XScreenSaverGetRegistered renvoie le XID et le type stockés dans la propriété _SCREEN_SAVER_ID sur la fenêtre racine de l'écran spécifié. Il renvoie zéro si une erreur est rencontrée ou si la propriété n'existe pas ou n'est pas du bon format ; sinon il renvoie une valeur non nulle.

XScreenSaverSuspend suspend temporairement l'économiseur d'écran et le minuteur DPMS si suspend est 'True', et redémarre le minuteur si suspend est 'False'.
Cette fonction doit être utilisée par les applications qui ne veulent pas que l'économiseur d'écran ou le DPMS s'activent pendant qu'elles jouent par exemple une séquence média, ou présentent autrement des informations visuelles continues à l'utilisateur dans un état non interactif. Cette fonction n'est pas destinée à être appelée par une application d'économiseur d'écran externe.
Si XScreenSaverSuspend est appelée plusieurs fois avec suspend défini à 'True', elle doit être appelée un nombre égal de fois avec suspend défini à 'False' pour que le minuteur de l'économiseur d'écran soit redémarré. Cette requête n'a aucun effet si un client tente de reprendre l'économiseur d'écran sans l'avoir d'abord suspendu. XScreenSaverSuspend ne peut donc pas être utilisé par un client pour reprendre l'économiseur d'écran s'il a été suspendu par un autre client.
Si un client qui a suspendu l'économiseur d'écran se déconnecte du serveur X, le minuteur de l'économiseur d'écran sera automatiquement redémarré, sauf s'il est toujours suspendu par un autre client. Suspendre le minuteur de l'économiseur d'écran n'empêche pas l'activation forcée de l'économiseur d'écran avec la requête ForceScreenSaver, ou la définition d'un mode DPMS avec la requête DPMSForceLevel.
XScreenSaverSuspend ne désactive pas non plus l'économiseur d'écran ou le DPMS s'ils sont actifs au moment où la requête pour les suspendre est reçue par le serveur X. Mais une fois qu'ils ont été désactivés, ils ne s'activeront pas automatiquement à nouveau, jusqu'à ce que le client ait annulé la suspension.

ERREURS

XScreenSaverSelectInput, XScreenSaverQueryInfo, XScreenSaverSetAttributes et XScreenSaverUnsetAttributes généreront une erreur BadDrawable si drawable n'est pas un identifiant de drawable valide. Si des bits indéfinis sont définis dans event_mask, une erreur BadValue est générée par XScreenSaverSelectInput.

DISPONIBILITÉ

XScreenSaverSuspend est disponible dans la version 1.1 et les versions ultérieures de l'extension X Screen Saver. La version 1.1 a été initialement publiée avec X11R7.1.
