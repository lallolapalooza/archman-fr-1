XSETDEVICEFOCUS(3)   XSETDEVICEFOCUS(3)

NOM

XSetDeviceFocus, XGetDeviceFocus - contrôler le focus des périphériques d'extension X

SYNTAXE

#include <X11/extensions/XInput.h>
XSetDeviceFocus( Display *display,
                 XDevice *device,
                 Window focus,
                 int revert_to,
                 Time time);
XGetDeviceFocus( Display *display,
                 XDevice *device,
                 Window *focus_return,
                 int *revert_to_return,
                 int * time_return);

Arguments

display
       Spécifie la connexion au serveur X.
device
       Spécifie le périphérique dont le focus doit être interrogé ou
       modifié.
focus
       Spécifie la fenêtre, PointerRoot, FollowKeyboard, ou
       None.
focus_return
       Retourne la fenêtre de focus, PointerRoot, FollowKeyboard, ou
       None.
revert_to
       Spécifie vers quoi le focus des entrées est rétabli si la fenêtre
       devient non visible. Vous pouvez passer RevertToParent,
       RevertToPointerRoot, RevertToFollowKeyboard, ou
       RevertToNone.
revert_to_return
       Retourne l'état du focus actuel RevertToParent,
       RevertToPointerRoot, RevertToFollowKeyboard, ou
       RevertToNone.
time_return
       Retourne le last_focus_time pour le périphérique.
time
       Spécifie le temps. Vous pouvez passer un timestamp ou
       CurrentTime.

DESCRIPTION

La requête XSetDeviceFocus modifie le focus du périphérique spécifié et
son temps de dernier changement de focus. Elle n'a aucun effet si le
temps spécifié est antérieur au temps actuel de dernier changement de
focus ou s'il est postérieur au temps actuel du serveur X. Sinon, le
temps du dernier changement de focus est défini au temps spécifié
(CurrentTime est remplacé par le temps actuel du serveur X).
XSetDeviceFocus provoque la génération d'événements DeviceFocusIn et
DeviceFocusOut par le serveur X.
Selon l'argument focus, le comportement suivant se produit :
  * Si focus est None , tous les événements du périphérique sont
    ignorés jusqu'à ce qu'une nouvelle fenêtre de focus soit définie,
    et l'argument revert_to est ignoré.
  * Si focus est une fenêtre, elle devient la fenêtre de focus du
    périphérique. Si un événement de périphérique généré devait
    normalement être rapporté à cette fenêtre ou à l'un de ses
    descendants, l'événement est rapporté comme d'habitude. Sinon,
    l'événement est rapporté par rapport à la fenêtre de focus.
  * Si focus est PointerRoot, la fenêtre de focus est dynamiquement
    considérée comme la fenêtre racine de l'écran sur lequel le
    pointeur se trouve à chaque événement du périphérique spécifié.
    Dans ce cas, l'argument revert_to est ignoré.
  * Si focus est FollowKeyboard, la fenêtre de focus est dynamiquement
    considérée comme la fenêtre à laquelle le focus du clavier X est
    défini à chaque événement d'entrée.
La fenêtre de focus spécifiée doit être visible au moment où
XSetDeviceFocus est appelée, sinon une erreur BadMatch se produit. Si
la fenêtre de focus devient plus tard non visible, le serveur X évalue
l'argument revert_to pour déterminer la nouvelle fenêtre de focus comme
suit :
  * Si revert_to est RevertToParent, le focus est rétabli sur le parent
    (ou l'ancêtre visible le plus proche), et la nouvelle valeur de
    revert_to est considérée comme RevertToNone.
  * Si revert_to est RevertToPointerRoot,
    RevertToFollowKeyboard, ou RevertToNone, le focus est rétabli sur
    PointerRoot, FollowKeyboard, ou None, respectivement.
Lorsque le focus est rétabli, le serveur X génère des événements
DeviceFocusIn et DeviceFocusOut, mais le temps du dernier changement de
focus n'est pas affecté.
Les périphériques d'extension d'entrée ne sont pas obligés de prendre
en charge la capacité d'être focalisés. Tenter de définir le focus d'un
périphérique qui ne prend pas en charge cette requête entraînera une
erreur BadMatch. La possibilité pour un périphérique donné de prendre en
charge cette requête peut être déterminée par les informations renvoyées
par XOpenDevice. Pour les périphériques qui prennent en charge le focus,
XOpenDevice renverra une structure XInputClassInfo dont le champ
input_class sera égal à la constante FocusClass (définie dans le
fichier XI.h).
XSetDeviceFocus peut générer les erreurs BadDevice, BadMatch, BadValue
et BadWindow.
La requête XGetDeviceFocus renvoie la fenêtre de focus et l'état
actuel du focus.
Tous les périphériques d'extension d'entrée ne peuvent pas être
focalisés. Tenter d'interroger l'état du focus d'un périphérique qui ne
peut pas être focalisé entraîne une erreur BadMatch. Un périphérique qui
peut être focalisé renvoie des informations pour la classe d'entrée Focus
lorsqu'une requête XOpenDevice est effectuée.
XGetDeviceFocus peut générer les erreurs BadDevice et BadMatch.

DIAGNOSTICS

BadDevice
       Un périphérique invalide a été spécifié. Le périphérique spécifié
       n'existe pas ou n'a pas été ouvert par ce client via
       XOpenInputDevice. Cette erreur peut également survenir si le
       périphérique spécifié est le clavier X ou le pointeur X.
BadValue
       Une valeur numérique se situe en dehors de la plage de valeurs
       acceptées par la requête. Sauf si une plage spécifique est
       spécifiée pour un argument, la plage complète définie par le type
       de l'argument est acceptée. Tout argument défini comme un ensemble
       d'alternatives peut générer cette erreur.
BadWindow
       Une valeur pour un argument Window ne nomme pas une fenêtre définie.
BadMatch
       Cette erreur peut survenir si une requête XGetDeviceFocus ou
       XSetDeviceFocus a été effectuée en spécifiant un périphérique pour
       lequel l'implémentation du serveur ne permet pas le focus.
