XrmGetFileDatabase(3) FONCTIONS XLIB XrmGetFileDatabase(3)

NOM

XrmGetFileDatabase, XrmPutFileDatabase, XrmGetStringDatabase, XrmLocaleOfDatabase, XrmGetDatabase, XrmSetDatabase, XrmDestroyDatabase - récupérer et stocker des bases de données de ressources

SYNTAXE

#include <X11/Xresource.h>

XrmDatabase XrmGetFileDatabase(char *filename);

void XrmPutFileDatabase(XrmDatabase database, _Xconst char *stored_db);

XrmDatabase XrmGetStringDatabase(_Xconst char *data);

const char *XrmLocaleOfDatabase(XrmDatabase database);

XrmDatabase XrmGetDatabase(Display *display);

void XrmSetDatabase(Display *display, XrmDatabase database);

void XrmDestroyDatabase(XrmDatabase database);

ARGUMENTS

filename
Spécifie le nom du fichier de la base de données de ressources.
database
Spécifie la base de données qui doit être utilisée.
stored_db
Spécifie le nom du fichier pour la base de données stockée.
data
Spécifie le contenu de la base de données à l'aide d'une chaîne.
database
Spécifie la base de données de ressources.
display
Spécifie la connexion au serveur X.

DESCRIPTION

La fonction XrmGetFileDatabase ouvre le fichier spécifié, crée une nouvelle base de données de ressources et la charge avec les spécifications lues à partir du fichier spécifié. Le fichier spécifié doit contenir une séquence d'entrées au format valide ResourceLine (voir la section 15.1) ; la base de données résultant de la lecture d'un fichier avec une syntaxe incorrecte est dépendante de l'implémentation. Le fichier est analysé dans la locale courante, et la base de données est créée dans la locale courante. Si elle ne parvient pas à ouvrir le fichier spécifié, XrmGetFileDatabase retourne NULL.

La fonction XrmPutFileDatabase stocke une copie de la base de données spécifiée dans le fichier spécifié. Le texte est écrit dans le fichier sous forme d'une séquence d'entrées au format valide ResourceLine (voir la section 15.1). Le fichier est écrit dans la locale de la base de données. Les entrées contenant des noms de ressources qui ne sont pas dans l'Encodage de Caractères Portable Hôte ou contenant des valeurs qui ne sont pas dans l'encodage de la locale de la base de données, sont écrites d'une manière dépendante de l'implémentation. L'ordre dans lequel les entrées sont écrites est dépendant de l'implémentation. Les entrées dont les types de représentation autres que “String” sont ignorées.

La fonction XrmGetStringDatabase crée une nouvelle base de données et stocke les ressources spécifiées dans la chaîne terminée par null spécifiée. XrmGetStringDatabase est similaire à XrmGetFileDatabase sauf qu'elle lit les informations à partir d'une chaîne au lieu d'un fichier. La chaîne doit contenir une séquence d'entrées au format valide ResourceLine (voir la section 15.1) terminée par un caractère null ; la base de données résultant de l'utilisation d'une chaîne avec une syntaxe incorrecte est dépendante de l'implémentation. La chaîne est analysée dans la locale courante, et la base de données est créée dans la locale courante.

Si database est NULL, XrmDestroyDatabase retourne immédiatement.

La fonction XrmLocaleOfDatabase retourne le nom de la locale associée à la base de données spécifiée, sous forme de chaîne terminée par null. La chaîne de nom de locale retournée appartient à Xlib et ne doit pas être modifiée ou libérée par le client. Xlib n'est pas autorisé à libérer la chaîne tant que la base de données n'est pas détruite. Jusqu'à ce que la chaîne soit libérée, elle ne sera pas modifiée par Xlib.

La fonction XrmGetDatabase retourne la base de données associée à l'affichage spécifié. Elle retourne NULL si une base de données n'a pas encore été définie.

La fonction XrmSetDatabase associe la base de données de ressources spécifiée (ou NULL) à l'affichage spécifié. La base de données précédemment associée à l'affichage (le cas échéant) n'est pas détruite. Un client ou une boîte à outils peut trouver cette fonction pratique pour conserver une base de données une fois qu'elle est construite.

SYNTAXE FICHIER

La syntaxe d'un fichier de ressources est une séquence de lignes de ressources terminées par des caractères de nouvelle ligne ou la fin du fichier. La syntaxe d'une ligne de ressource individuelle est :

ResourceLine	=	Comment | IncludeFile | ResourceSpec | <ligne vide>
Comment	=	"!" {<tout caractère sauf null ou nouvelle ligne>}
IncludeFile	=	"#" WhiteSpace "include" WhiteSpace FileName WhiteSpace
FileName	=	<nom de fichier valide pour le système d'exploitation>
ResourceSpec	=	WhiteSpace ResourceName WhiteSpace ":" WhiteSpace Value
ResourceName	=	[Binding] {Component Binding} ComponentName
Binding	=	"." | "*"
WhiteSpace	=	{<espace> | <tabulation horizontale>}
Component	=	"?" | ComponentName
ComponentName	=	NameChar {NameChar}
NameChar	=	"a"-"z" | "A"-"Z" | "0"-"9" | "_" | "-"
Value	=	{<tout caractère sauf null ou nouvelle ligne non échappée>}

Les éléments séparés par une barre verticale (|) sont des alternatives. Les accolades ({...}) indiquent zéro ou plusieurs répétitions des éléments inclus. Les crochets ([...]) indiquent que l'élément inclus est facultatif. Les guillemets ("...") sont utilisés autour des caractères littéraux.

Les lignes IncludeFile sont interprétées en remplaçant la ligne par le contenu du fichier spécifié. Le mot “include” doit être en minuscules. Le nom de fichier est interprété par rapport au répertoire du fichier dans lequel la ligne se trouve (par exemple, si le nom de fichier ne contient aucun répertoire ou contient une spécification de répertoire relative).

Si un ResourceName contient une séquence continue de deux caractères Binding ou plus, la séquence sera remplacée par un seul caractère “.” si la séquence ne contient que des caractères “.” ; sinon, la séquence sera remplacée par un seul caractère “*”.

Une base de données de ressources ne contient jamais plus d'une entrée pour un ResourceName donné. Si un fichier de ressources contient plusieurs lignes avec le même ResourceName, la dernière ligne du fichier est utilisée.

Tous les caractères d'espacement avant ou après le nom ou le deux-points dans une ResourceSpec sont ignorés. Pour permettre à une Value de commencer par un espace blanc, la séquence de deux caractères “\espace” (antislash suivi d'un espace) est reconnue et remplacée par un caractère d'espace, et la séquence de deux caractères “\tab” (antislash suivi d'une tabulation horizontale) est reconnue et remplacée par un caractère de tabulation horizontale. Pour permettre à une Value de contenir des caractères de nouvelle ligne intégrés, la séquence de deux caractères “\n” est reconnue et remplacée par un caractère de nouvelle ligne. Pour permettre à une Value d'être répartie sur plusieurs lignes dans un fichier texte, la séquence de deux caractères “\nouvelle ligne” (antislash suivi d'une nouvelle ligne) est reconnue et supprimée de la valeur. Pour permettre à une Value de contenir des codes de caractères arbitraires, la séquence de quatre caractères “\nnn”, où chaque n est un chiffre dans la plage de “0” à “7”, est reconnue et remplacée par un seul octet contenant la valeur octale spécifiée par la séquence. Enfin, la séquence de deux caractères “\\” est reconnue et remplacée par un seul antislash.

NOM

XrmSetDatabase - Associe une base de données de ressources à un écran.

SYNTAXE

#include <X11/Xresource.h>

void XrmSetDatabase(
    Display *display,
    XrmDatabase     database
);

ARGUMENTS

display
Spécifie la connexion au serveur X.
database
Spécifie la base de données de ressources à associer.

DESCRIPTION

La fonction XrmSetDatabase associe une base de données de ressources audisplay spécifié. Il s'agit d'un mécanisme permettant à une application de fournir sa propre base de données de ressources au système de gestion des ressources X.

Normalement, le système X fournit une base de données de ressources par défaut pour chaque écran, qui est chargée à partir de fichiers de configuration tels que ~/.Xresources ou /etc/X11/app-defaults/. Cependant, une application peut souhaiter utiliser une base de données de ressources personnalisée, par exemple pour un comportement spécifique ou pour des raisons de test.

Après avoir appelé XrmSetDatabase, les recherches de ressources pour cet écran utiliseront ladatabase fournie au lieu de la base de données par défaut. La base de données fournie devient la propriété de la bibliothèque Xlib et ne doit pas être libérée par l'appelant tant que la connexion d'affichage est active.

Il est important de noter que cette fonction ne doit être appelée qu'une seule fois pardisplay, et idéalement avant toute autre opération de gestion des ressources qui pourrait nécessiter l'accès à la base de données.

SYNTAXE DE FICHIER

La syntaxe des fichiers de ressources est décrite dans la documentation deXrmGetFileDatabase. Essentiellement, elle se compose de lignes de la forme :

NomClasse.nomInstance: valeur

ou

NomClasse*nomInstance: valeur
