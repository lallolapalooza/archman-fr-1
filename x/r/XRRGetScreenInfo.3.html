TYPES DE DONNÉES

Rotations/Reflexions

Peut être l'un des éléments suivants :

#define RR_Rotate_0             1
#define RR_Rotate_90            2
#define RR_Rotate_180           4
#define RR_Rotate_270           8
/∗ nouveau dans le protocole 1.0, pour permettre la réflexion de l'écran */
/∗ la réflexion est appliquée après la rotation */
#define RR_Reflect_X            16
#define RR_Reflect_Y            32
typedef struct {
    int	width, height;
    int	mwidth, mheight;
} XRRScreenSize;
typedef struct {
    int type;				/∗ base d'événement */
    unsigned long serial;	/∗ # de la dernière requête traitée par le serveur */
    Bool send_event;		/∗ true si cela provient d'une requête SendEvent */
    Display *display;		/∗ Affichage à partir duquel l'événement a été lu */
    Window window;			/∗ fenêtre qui s'est abonnée à cet événement */
    Window root;			/∗ Fenêtre racine pour l'écran modifié */
    Time timestamp;			/∗ quand le changement d'écran s'est produit */
    Time config_timestamp;	/∗ quand la dernière modification de configuration */
    SizeID size_index;
    SubpixelOrder subpixel_order;
    Rotation rotation;
    int width;
    int height;
    int mwidth;
    int mheight;
} XRRScreenChangeNotifyEvent;
La structure XRRScreenSize contient une taille racine possible en pixels et en millimètres.

Un XRRScreenChangeNotifyEvent est envoyé à un client qui a demandé une notification chaque fois que la configuration de l'écran est modifiée. Un client peut effectuer cette requête en appelant XRRSelectInput, en passant l'affichage, la fenêtre racine et le masque RRScreenChangeNotifyMask.

XRRScreenConfiguration est un type de données opaque contenant les informations de configuration d'un écran.

Horodatages

Les horodatages sont inclus et doivent être utilisés pour s'assurer que le client est à jour : l'écran peut changer de propriétés à la volée et cela garantit que ses connaissances de la configuration sont à jour. Ceci vise à résoudre les problèmes lorsque les écrans pourraient devenir hot-plug dans le futur.

DESCRIPTION

Xrandr est une bibliothèque simple conçue pour interagir avec l'extension X de redimensionnement et de rotation. Cela permet aux clients de changer la taille et la rotation de la fenêtre racine d'un écran, ainsi que la possibilité de réfléchir l'écran sur l'un ou l'autre axe (si supporté par l'implémentation). La rotation et la réflexion peuvent être implémentées par logiciel et peuvent entraîner des performances plus lentes si la rotation et la réflexion sont implémentées de cette manière (comme le sont toutes les implémentations en octobre 2002).

La bibliothèque Xrandr effectue une mise en cache minimale pour éviter les allers-retours afin de fournir aux clients des informations fréquemment utilisées. Voir "The X Resize and Rotate Extension" pour une description détaillée ; notez également que le changement de profondeur (depth switching), tel que décrit dans le document, n'est pas implémenté, et pourrait (ou pourrait ne pas) jamais être implémenté, car la mémoire d'affichage croît rapidement, et les toolkits supportent déjà la migration, atténuant ainsi le besoin de changement de profondeur. S'il est implémenté à l'avenir, nous prévoyons de le faire via une extension rétrocompatible avec la bibliothèque/protocole actuel ; la fonctionnalité décrite ici devrait continuer à fonctionner.

La rotation et la réflexion, ainsi que leur interaction, peuvent être déroutantes. Dans Randr, le système de coordonnées est tourné dans le sens inverse des aiguilles d'une montre par rapport à l'orientation normale. La réflexion se fait le long du système de coordonnées du système de fenêtrage, et non des axes X et Y physiques de l'écran, de sorte que la rotation et la réflexion n'interagissent pas. L'autre façon d'envisager la réflexion est de la traiter comme spécifiée dans l'orientation "normale", avant la rotation.

L'événement XRRScreenChangeNotify est envoyé aux clients qui demandent à être informés chaque fois que la configuration de la fenêtre racine change. Les changements de configuration peuvent inclure la résolution, la taille physique, l'ordre des sous-pixels (voir XRender(3)), et la rotation. Notez que des changements à n'importe lequel ou à tous ces éléments peuvent survenir en raison d'événements externes (contrôle utilisateur sur le serveur X, branchement/débranchement d'un moniteur/écran plat différent) et ne sont pas seulement le résultat d'une demande de protocole/bibliothèque au serveur X.

De plus, afin d'éliminer une condition de concurrence potentielle, cet événement peut être généré immédiatement lors de la sélection de la notification si l'écran a changé depuis que le client s'est connecté à Xrandr au serveur X, pour permettre un changement fiable de résolution d'écran lorsqu'un utilisateur peut se connecter et changer la configuration pendant qu'un ou plusieurs clients démarrent.

Notification Xlib

Les clients doivent rappeler Xlib en utilisant XRRUpdateConfiguration lorsque des événements de notification de changement de configuration d'écran sont générés (ou que des changements de configuration de la fenêtre racine se produisent, pour mettre à jour la vue de Xlib sur la résolution, la taille, la rotation, la réflexion ou l'ordre des sous-pixels. En général, les toolkits effectueront cette opération au nom des applications ; nous ne voulions pas modifier les données de la structure d'affichage derrière le dos des toolkits, car dans les clients multithreadés, diverses conditions de concurrence pourraient survenir. Les toolkits devraient fournir aux clients un mécanisme de notification des changements d'écran, bien sûr.

XRRGetScreenInfo — get screen configuration information

Specifies the root window of the screen for which information is to be retrieved.

Specifies the desired rotation or reflection to be set.

Specifies the desired screen size configuration to be used.

Specifies the desired refresh rate to be set.

DATATYPES

XRRScreenConfiguration
A structure containing the screen configuration information. This structure is private to the library.
XRRScreenSize
A structure containing the screen dimensions (width and height).
Rotation
An integer type representing the rotation and reflection settings.
Time
An integer type representing a timestamp.
RRCrtc
A type representing a CRTC identifier.
XRRCurrentConfiguration
A structure containing the current configuration of the screen, including rotation, size index, and rate.

DESCRIPTION

There are two classes of interfaces: those which can be safely called even if RandR is not implemented on a screen (to make common idioms not dependent on the server having support), and those which will return errors if the extension is not present.

XRRRotations returns both the possible set of rotations/reflections supported (as a bitmask) as the value of the function, along with the current rotation/reflection of the screen.

XRRSizes returns the size and a pointer to the current sizes supported by the specified screen. The first size specified is the default size of the server. If RandR is not supported, it returns 0 for the number of sizes.

XRRRates returns a pointer to the rates supported by the specified size. If RandR is not supported, it returns 0 for the number of rates.

XRRTimes returns the time last reported by the server along with the timestamp the last configuration changed. If the configuration has changed since the client last updated its view of the server time, requests to change the configuration will fail until the client has an up to date timestamp.

XRRRootToScreen returns the screen number given a root window (for example, from an XRRScreenChangeNotifyEvent).

The rest of the functions will fail if applied to screens not implementing the RandR extension. XRRSetScreenConfig sets the screen size and rotation and reflection to the desired values on the screen specified by draw, or returns a BadValue error. size_index specifies which size configuration is to be used, rotation specifies which rotation or reflection is to be used (or a BadValue error is returned). The timestamp is used by the server to make sure the client has up to date configuration information. Status is returned to indicate success or failure; a client must refresh its configuration information if it fails and try the call again (by calling XRRGetScreenInfo).

XRRSetScreenConfigAndRate is like XRRSetScreenConfig but also sets the refresh rate. If specified rate is not supported a BadValue error is returned.

XRRConfigRotations, XRRConfigSizes, XRRConfigCurrentConfiguration, XRRConfigTimes, XRRConfigRates, and XRRConfigCurrentRate are used to get specific configuration information out of a screen configuration.

XRRGetScreenInfo returns a screen configuration for later use; the information is private to the library. Call XRRFreeScreenConfigInfo to free this information when you are finished with it. It forces a round trip to the server.

Other functions include: XRRQueryExtension which returns the event and error base codes, XRRQueryVersion , which returns the current version of the extension (this information is cached by the library).

RESTRICTIONS

Xrandr will remain upward compatible after the current 1.0 release.
