display
Spécifie la connexion au serveur X.

Spécifie quel écran.

rate
Spécifie le taux de rafraîchissement en Hz.

TYPES DE DONNÉES

Rotations/Réflexions

Peut être l'un des éléments suivants :

#define RR_Rotate_0             1
#define RR_Rotate_90            2
#define RR_Rotate_180           4
#define RR_Rotate_270           8
/∗ nouveau dans le protocole 1.0, pour permettre la réflexion de l'écran */
/∗ la réflexion est appliquée après la rotation */
#define RR_Reflect_X            16
#define RR_Reflect_Y            32
typedef struct {
    int	width, height;
    int	mwidth, mheight;
} XRRScreenSize;
typedef struct {
    int type;				/∗ base d'événement */
    unsigned long serial;	/∗ # de la dernière requête traitée par le serveur */
    Bool send_event;		/∗ vrai si ceci provient d'une requête SendEvent */
    Display *display;		/∗ Affichage à partir duquel l'événement a été lu */
    Window window;			/∗ fenêtre qui a sélectionné cet événement */
    Window root;			/∗ Fenêtre racine pour l'écran modifié */
    Time timestamp;			/∗ quand le changement d'écran s'est produit */
    Time config_timestamp;	/∗ quand le dernier changement de configuration */
    SizeID size_index;
    SubpixelOrder subpixel_order;
    Rotation rotation;
    int width;
    int height;
    int mwidth;
    int mheight;
} XRRScreenChangeNotifyEvent;
La structure XRRScreenSize contient une taille racine possible en pixels et en millimètres.

Un événement XRRScreenChangeNotifyEvent est envoyé à un client qui a demandé une notification chaque fois que la configuration de l'écran est modifiée. Un client peut effectuer cette requête en appelant XRRSelectInput, en passant l'affichage, la fenêtre racine et le masque RRScreenChangeNotifyMask.

XRRScreenConfiguration est un type de données opaque contenant les informations de configuration d'un écran.

Horodatages

Les horodatages sont inclus et doivent être utilisés pour s'assurer que le client joue avec un jeu complet : l'écran peut changer de propriétés à la volée et cela garantit que sa connaissance de la configuration est à jour. Ceci est destiné à résoudre les problèmes lorsque les écrans peuvent devenir enfichables à chaud à l'avenir.

DESCRIPTION

Xrandr est une bibliothèque simple conçue pour interfacer l'extension X de redimensionnement et de rotation. Cela permet aux clients de changer la taille et la rotation de la fenêtre racine d'un écran, ainsi que la capacité de refléter l'écran sur l'un ou l'autre axe (si pris en charge par l'implémentation). La rotation et la réflexion peuvent être implémentées par logiciel et peuvent entraîner des performances plus lentes si la rotation et la réflexion sont implémentées de cette manière (comme toutes les implémentations à partir d'octobre 2002).

La bibliothèque Xrandr effectue une mise en cache minimale pour éviter les allers-retours afin de fournir aux clients des informations fréquemment utilisées. Voir "L'extension X de redimensionnement et de rotation" pour une description détaillée ; notez également que la commutation de profondeur, telle que décrite dans le document, n'est pas implémentée et peut (ou peut-être pas) jamais être implémentée, car la mémoire d'affichage croît rapidement et les kits d'outils commencent déjà à prendre en charge la migration, atténuant ainsi le besoin de commutation de profondeur. Si elle est implémentée à l'avenir, nous prévoyons de le faire via une extension compatible ascendante à la bibliothèque/protocole actuel ; les fonctionnalités décrites ici devraient continuer à fonctionner.

La rotation et la réflexion, ainsi que leur interaction, peuvent être déroutantes. Dans Randr, le système de coordonnées est tourné dans le sens inverse des aiguilles d'une montre par rapport à l'orientation normale. La réflexion se fait le long du système de coordonnées du système de fenêtrage, et non des axes X et Y physiques de l'écran, de sorte que la rotation et la réflexion n'interagissent pas. L'autre façon d'envisager la réflexion est de la traiter comme spécifiée dans l'orientation "normale", avant la rotation.

L'événement XRRScreenChangeNotify est envoyé aux clients qui demandent à être informés chaque fois que la configuration de la fenêtre racine change. Les changements de configuration peuvent inclure la résolution, la taille physique, l'ordre des sous-pixels (voir XRender(3)), et la rotation. Notez que des changements sur l'un ou tous ces éléments peuvent se produire en raison d'événements externes (contrôle utilisateur dans le serveur X, connexion/déconnexion d'un moniteur/écran plat différent) et ne sont pas seulement le résultat d'une demande de protocole/bibliothèque au serveur X.

De plus, pour éliminer une condition de concurrence potentielle, cet événement peut être généré immédiatement lors de la sélection de la notification si l'écran a changé depuis que le client de Xrandr s'est connecté au serveur X, afin de permettre un changement fiable de résolution d'écran lorsqu'un utilisateur peut se connecter et modifier la configuration pendant que plusieurs clients démarrent.

Notification Xlib

Les clients doivent rappeler Xlib en utilisant XRRUpdateConfiguration lorsque des événements de notification de changement de configuration d'écran sont générés (ou que des changements de configuration de la fenêtre racine se produisent, pour mettre à jour la vue de Xlib sur la résolution, la taille, la rotation, la réflexion ou l'ordre des sous-pixels. Généralement, les kits d'outils effectueront cette opération au nom des applications ; nous ne voulions pas modifier les données de structure d'affichage derrière le dos des kits d'outils, car dans les clients multithread, diverses conditions de concurrence pourraient survenir. Les kits d'outils devraient fournir aux clients un mécanisme de notification de changement d'écran, bien sûr.

FONCTIONS

XRRQueryExtension renvoie TRUE si l'extension Xrandr est disponible sur le serveur, sinon FALSE. Les arguments event_base_return et error_base_return sont remplis avec les numéros de base des événements et des erreurs pour l'extension.

XRRQueryVersion interroge la version du protocole RandR supportée par le serveur et la remplit dans major_version_return et minor_version_return. Elle renvoie SUCCESS si la requête a réussi, sinon FAILURE.

XRRGetScreenInfo renvoie une structure XRRScreenConfiguration contenant des informations sur la configuration actuelle de l'écran. L'argument draw doit être une fenêtre sur l'écran pour lequel vous souhaitez obtenir les informations.

XRRFreeScreenConfigInfo libère la mémoire allouée par XRRGetScreenInfo.

XRRSetScreenConfig tente de définir la configuration de l'écran. L'argument config est le pointeur vers la structure de configuration retournée par XRRGetScreenInfo. draw doit être une fenêtre sur l'écran cible. size_index spécifie l'index de la taille de l'écran souhaitée, rotation spécifie la rotation souhaitée, et timestamp est l'horodatage de la dernière modification de configuration connue du client. Elle renvoie SUCCESS si la demande réussit, sinon FAILURE.

XRRSetScreenConfigAndRate est similaire à XRRSetScreenConfig, mais permet également de spécifier le taux de rafraîchissement souhaité pour l'écran.

Les fonctions XRRConfigRotations, XRRConfigTimes, XRRConfigSizes, XRRConfigRates, XRRConfigCurrentConfiguration, et XRRConfigCurrentRate extraient des informations spécifiques de la structure XRRScreenConfiguration.

XRRRootToScreen renvoie le numéro d'écran pour une fenêtre racine donnée.

XRRSelectInput demande au serveur X d'envoyer des événements RRScreenChangeNotify à la fenêtre spécifiée lorsque la configuration de l'écran change. Le masque mask doit inclure RRScreenChangeNotifyMask.

XRRUpdateConfiguration est destiné à être appelé lorsque des événements de changement de configuration d'écran sont reçus. Il met à jour l'état interne de Xlib et renvoie 1 si l'événement est compris comme un événement de changement de configuration, 0 sinon.

Les fonctions XRRRotations, XRRSizes, XRRRates et XRRTimes sont des alternatives de niveau inférieur à leurs homologues XRRConfig* qui n'utilisent pas de structure XRRScreenConfiguration mise en cache et peuvent être appelées en toute sécurité même si l'extension RandR n'est pas implémentée.

NOM

XRRSetScreenConfigAndRate — configurer la taille, la rotation, la réflexion et le taux de rafraîchissement de l'écran

SYNTAXE

XRRScreenConfiguration *
XRRSetScreenConfigAndRate(Display *dpy,
    RROutput output,
    RRCrtc crtc,
    int size_index,
    Rotation rotation,
    int rate,
    unsigned int timestamp);

ARGUMENTS

dpy
Spécifie la connexion au serveur X.
output
Spécifie la sortie à configurer.
crtc
Spécifie le CRTC à configurer.
size_index
L'index de la taille souhaitée.
rotation
La rotation ou la réflexion souhaitée.
rate
Le taux de rafraîchissement souhaité.
timestamp
L'horodatage de la dernière modification de configuration connue du client.

DESCRIPTION

La bibliothèque libXrandr fournit deux classes d'interfaces : celles qui peuvent être appelées en toute sécurité même si RandR n'est pas implémenté sur un écran (pour que les idiomes courants ne dépendent pas du support du serveur), et celles qui renverront des erreurs si l'extension n'est pas présente.

XRRRotations renvoie à la fois l'ensemble possible des rotations/réflexions supportées (sous forme de masque binaire) comme valeur de la fonction, ainsi que la rotation/réflexion actuelle de l'écran.

XRRSizes renvoie la taille et un pointeur vers les tailles actuelles supportées par l'écran spécifié. La première taille spécifiée est la taille par défaut du serveur. Si RandR n'est pas supporté, il renvoie 0 pour le nombre de tailles.

XRRRates renvoie un pointeur vers les taux supportés par la taille spécifiée. Si RandR n'est pas supporté, il renvoie 0 pour le nombre de taux.

XRRTimes renvoie le dernier temps signalé par le serveur ainsi que l'horodatage du dernier changement de configuration. Si la configuration a changé depuis que le client a mis à jour sa vue du temps du serveur, les requêtes pour modifier la configuration échoueront jusqu'à ce que le client ait un horodatage à jour.

XRRRootToScreen renvoie le numéro de l'écran donné une fenêtre racine (par exemple, à partir d'un XRRScreenChangeNotifyEvent).

Le reste des fonctions échouera si elles sont appliquées à des écrans n'implémentant pas l'extension RandR. XRRSetScreenConfig définit la taille de l'écran et la rotation/réflexion aux valeurs souhaitées sur l'écran spécifié par draw, ou renvoie une erreur BadValue. size_index spécifie quelle configuration de taille doit être utilisée, rotation spécifie quelle rotation ou réflexion doit être utilisée (ou une erreur BadValue est renvoyée). L' timestamp est utilisé par le serveur pour s'assurer que le client dispose d'informations de configuration à jour. Le statut est renvoyé pour indiquer le succès ou l'échec ; un client doit actualiser ses informations de configuration si l'appel échoue et essayer à nouveau (en appelant XRRGetScreenInfo).

XRRSetScreenConfigAndRate est similaire à XRRSetScreenConfig mais définit également le taux de rafraîchissement. Si le taux spécifié n'est pas supporté, une erreur BadValue est renvoyée.

XRRConfigRotations, XRRConfigSizes, XRRConfigCurrentConfiguration, XRRConfigTimes, XRRConfigRates, et XRRConfigCurrentRate sont utilisés pour extraire des informations de configuration spécifiques d'une configuration d'écran.

XRRGetScreenInfo renvoie une configuration d'écran pour une utilisation ultérieure ; les informations sont privées à la bibliothèque. Appelez XRRFreeScreenConfigInfo pour libérer ces informations lorsque vous avez terminé. Cela force un aller-retour vers le serveur.

D'autres fonctions incluent : XRRQueryExtension qui renvoie les codes de base des événements et des erreurs, XRRQueryVersion , qui renvoie la version actuelle de l'extension (ces informations sont mises en cache par la bibliothèque).

RESTRICTIONS

Xrandr restera compatible avec les versions antérieures après la version actuelle 1.0.
