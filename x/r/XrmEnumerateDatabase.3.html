XrmEnumerateDatabase(3)

Paquet: libx11

Licences: MIT AND X11

XrmEnumerateDatabase(3) FONCTIONS XLIB XrmEnumerateDatabase(3)

NOM

XrmEnumerateDatabase - énumérer les entrées de la base de données des ressources

SYNTAXE

#include <X11/Xresource.h>

#define XrmEnumAllLevels 0
#define XrmEnumOneLevel 1

Bool XrmEnumerateDatabase(XrmDatabase database, XrmNameList name_prefix, XrmClassList class_prefix, int mode, Bool (*proc)(), XPointer arg);

ARGUMENTS

database
Spécifie la base de données des ressources.
name_prefix
Spécifie le préfixe du nom de la ressource.
class_prefix
Spécifie le préfixe de la classe de la ressource.
mode
Spécifie le nombre de niveaux à énumérer.
proc
Spécifie la procédure à appeler pour chaque entrée correspondante.
arg
Spécifie l'argument fourni par l'utilisateur qui sera passé à la procédure.

DESCRIPTION

La fonction XrmEnumerateDatabase appelle la procédure spécifiée pour chaque ressource de la base de données qui correspondrait à une complétion du préfixe de nom/classe de ressource donné. L'ordre dans lequel les ressources sont trouvées dépend de l'implémentation. Si le mode est XrmEnumOneLevel, une ressource doit correspondre au préfixe nom/classe donné avec seulement un nom et une classe ajoutés. Si le mode est XrmEnumAllLevels, la ressource doit correspondre au préfixe nom/classe donné avec un ou plusieurs noms et classes ajoutés. Si la procédure retourne True, l'énumération se termine et la fonction retourne True. Si la procédure retourne toujours False, toutes les ressources correspondantes sont énumérées et la fonction retourne False.

La procédure est appelée avec les arguments suivants :

(*proc)(database, bindings, quarks, type, value, arg)
        XrmDatabase *database;
        XrmBindingList bindings;
        XrmQuarkList quarks;
        XrmRepresentation *type;
        XrmValue *value;
        XPointer arg;

Les listes de liaisons et de quarks sont terminées par NULLQUARK. Notez que des pointeurs vers la base de données et le type sont passés, mais ces valeurs ne doivent pas être modifiées.

La procédure ne doit pas modifier la base de données. Si Xlib a été initialisé pour les threads, la procédure est appelée avec la base de données verrouillée et le résultat d'un appel par la procédure à toute fonction Xlib utilisant la même base de données n'est pas défini.
