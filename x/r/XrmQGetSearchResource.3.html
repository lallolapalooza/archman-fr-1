NOM

XrmGetResource, XrmQGetResource, XrmQGetSearchList, XrmQGetSearchResource - récupérer les ressources de base de données et les listes de recherche

SYNTAXE

#include <X11/Xresource.h>

Bool XrmGetResource(XrmDatabase database, char *str_name, char *str_class, char **str_type_return, XrmValue *value_return);

Bool XrmQGetResource(XrmDatabase database, XrmNameList quark_name, XrmClassList quark_class, XrmRepresentation *quark_type_return, XrmValue *value_return);

typedef XrmHashTable *XrmSearchList;

Bool XrmQGetSearchList(XrmDatabase database, XrmNameList names, XrmClassList classes, XrmSearchList list_return, int list_length);

Bool XrmQGetSearchResource(XrmSearchList list, XrmName name, XrmClass class, XrmRepresentation *type_return, XrmValue *value_return);

ARGUMENTS

class
Spécifie la classe de la ressource.
classes
Spécifie une liste de classes de ressources.
database
Spécifie la base de données à utiliser.
list
Spécifie la liste de recherche retournée par XrmQGetSearchList.
list_length
Spécifie le nombre d'entrées (et non la taille en octets) allouées pour list_return.
list_return
Retourne une liste de recherche pour une utilisation ultérieure.
name
Spécifie le nom de la ressource.
names
Spécifie une liste de noms de ressources.
quark_class
Spécifie la classe complètement qualifiée de la valeur récupérée (sous forme de quark).
quark_name
Spécifie le nom complètement qualifié de la valeur récupérée (sous forme de quark).
quark_type_return
Retourne le type de représentation de la destination (sous forme de quark).
str_class
Spécifie la classe complètement qualifiée de la valeur récupérée (sous forme de chaîne).
str_name
Spécifie le nom complètement qualifié de la valeur récupérée (sous forme de chaîne).
str_type_return
Retourne le type de représentation de la destination (sous forme de chaîne).
type_return
Retourne le type de représentation des données.
value_return
Retourne la valeur dans la base de données.

DESCRIPTION

Les fonctions XrmGetResource et XrmQGetResource récupèrent une ressource de la base de données spécifiée. Les deux prennent une paire nom/classe complètement qualifiée, une représentation de ressource de destination et l'adresse d'une valeur (paire taille/adresse). La valeur et le type retourné pointent dans la mémoire de la base de données ; par conséquent, vous ne devez pas modifier les données.

La base de données ne libère ou n'écrase les entrées que sur XrmPutResource, XrmQPutResource ou XrmMergeDatabases. Un client qui ne stocke pas de nouvelles valeurs dans la base de données ou ne fusionne pas la base de données devrait pouvoir utiliser en toute sécurité l'adresse retournée à tout moment jusqu'à sa sortie. Si une ressource a été trouvée, XrmGetResource et XrmQGetResource retournent True ; sinon, elles retournent False.

La fonction XrmQGetSearchList prend une liste de noms et de classes et retourne une liste de niveaux de base de données où une correspondance pourrait se produire. La liste retournée est en ordre du meilleur au pire et utilise le même algorithme que XrmGetResource pour déterminer la précédence. Si list_return était suffisamment grand pour la liste de recherche, XrmQGetSearchList retourne True ; sinon, elle retourne False.

La taille de la liste de recherche que l'appelant doit allouer dépend du nombre de niveaux et de caractères génériques dans les spécificateurs de ressources qui sont stockés dans la base de données. La longueur dans le pire des cas est de %3 sup n%, où n est le nombre de composants de nom ou de classe dans names ou classes.

Lors de l'utilisation de XrmQGetSearchList suivie de multiples sondes pour des ressources avec un préfixe de nom et de classe commun, seul le préfixe commun doit être spécifié dans la liste de noms et de classes pour XrmQGetSearchList.

La fonction XrmQGetSearchResource recherche dans les niveaux de base de données spécifiés la ressource qui est complètement identifiée par le nom et la classe spécifiés. La recherche s'arrête à la première correspondance. XrmQGetSearchResource retourne True si la ressource a été trouvée ; sinon, elle retourne False.

Un appel à XrmQGetSearchList avec une liste de noms et de classes contenant tous les composants sauf le dernier d'un nom de ressource, suivi d'un appel à XrmQGetSearchResource avec le dernier composant nom et classe, retourne la même entrée de base de données que XrmGetResource et XrmQGetResource avec le nom et la classe complètement qualifiés.

RÈGLES DE CORRESPONDANCE

L'algorithme pour déterminer quelle entrée de base de données de ressource correspond à une requête donnée est le cœur du gestionnaire de ressources. Toutes les requêtes doivent spécifier complètement le nom et la classe de la ressource souhaitée (l'utilisation des caractères « * » et « ? » n'est pas autorisée). La bibliothèque prend en charge jusqu'à 100 composants dans un nom ou une classe complets. Les ressources sont stockées dans la base de données avec des noms et des classes partiellement spécifiés, en utilisant des constructions de correspondance de motifs. Un astérisque (*) est une liaison lâche et est utilisé pour représenter n'importe quel nombre de composants intermédiaires, y compris aucun. Un point (.) est une liaison serrée et est utilisé pour séparer des composants immédiatement adjacents. Un point d'interrogation (?) est utilisé pour faire correspondre n'importe quel nom ou classe de composant unique. Une entrée de base de données ne peut pas se terminer par une liaison lâche ; le composant final (qui ne peut pas être le caractère « ? ») doit être spécifié. L'algorithme de recherche parcourt la base de données à la recherche de l'entrée qui correspond le plus étroitement (est la plus spécifique pour) le nom et la classe complets interrogés. Lorsque plusieurs entrées de base de données correspondent au nom et à la classe complets, des règles de précédence sont utilisées pour en sélectionner une seule.

Le nom et la classe complets sont analysés de gauche à droite (du niveau le plus élevé de la hiérarchie au plus bas), un composant à la fois. À chaque niveau, le composant et/ou la liaison correspondante de chaque entrée correspondante sont déterminés, et ces composants et liaisons correspondants sont comparés selon les règles de précédence. Chacune des règles est appliquée à chaque niveau avant de passer au niveau suivant, jusqu'à ce qu'une règle sélectionne une seule entrée parmi toutes les autres. Les règles, par ordre de précédence, sont :

1.
Une entrée contenant un composant correspondant (qu'il s'agisse d'un nom, d'une classe ou du caractère « ? ») a la précédence sur les entrées qui élident le niveau (c'est-à-dire les entrées qui correspondent au niveau dans une liaison lâche).
2.
Une entrée avec un nom correspondant a la précédence sur les entrées avec une classe correspondante et sur les entrées qui correspondent en utilisant le caractère « ? ». Une entrée avec une classe correspondante a la précédence sur les entrées qui correspondent en utilisant le caractère « ? ».
3.
Une entrée précédée par une liaison serrée a la précédence sur les entrées précédées par une liaison lâche.
