XrmGetFileDatabase(3) FONCTIONS XLIB XrmGetFileDatabase(3)

NOM

XrmGetFileDatabase, XrmPutFileDatabase, XrmGetStringDatabase, XrmLocaleOfDatabase, XrmGetDatabase, XrmSetDatabase, XrmDestroyDatabase - récupérer et stocker des bases de données de ressources

SYNTAXE

#include <X11/Xresource.h>

XrmDatabase XrmGetFileDatabase(char *nom_fichier);

void XrmPutFileDatabase(XrmDatabase base_de_donnees, _Xconst char *db_stockee);

XrmDatabase XrmGetStringDatabase(_Xconst char *donnees);

const char *XrmLocaleOfDatabase(XrmDatabase base_de_donnees);

XrmDatabase XrmGetDatabase(Display *affichage);

void XrmSetDatabase(Display *affichage, XrmDatabase base_de_donnees);

void XrmDestroyDatabase(XrmDatabase base_de_donnees);

ARGUMENTS

nom_fichier
Spécifie le nom du fichier de la base de données de ressources.
base_de_donnees
Spécifie la base de données à utiliser.
db_stockee
Spécifie le nom du fichier pour la base de données stockée.
donnees
Spécifie le contenu de la base de données à l'aide d'une chaîne.
base_de_donnees
Spécifie la base de données de ressources.
affichage
Spécifie la connexion au serveur X.

DESCRIPTION

La fonction XrmGetFileDatabase ouvre le fichier spécifié, crée une nouvelle base de données de ressources et la charge avec les spécifications lues depuis le fichier spécifié. Le fichier spécifié doit contenir une séquence d'entrées au format ResourceLine valide (voir la section 15.1); la base de données résultant de la lecture d'un fichier dont la syntaxe est incorrecte est dépendante de l'implémentation. Le fichier est analysé dans la locale courante, et la base de données est créée dans la locale courante. Si elle ne peut pas ouvrir le fichier spécifié, XrmGetFileDatabase retourne NULL.

La fonction XrmPutFileDatabase stocke une copie de la base de données spécifiée dans le fichier spécifié. Le texte est écrit dans le fichier sous forme d'une séquence d'entrées au format ResourceLine valide (voir la section 15.1). Le fichier est écrit dans la locale de la base de données. Les entrées contenant des noms de ressources qui ne sont pas dans l'encodage de caractères portable hôte (Host Portable Character Encoding) ou contenant des valeurs qui ne sont pas dans l'encodage de la locale de la base de données, sont écrites d'une manière dépendante de l'implémentation. L'ordre dans lequel les entrées sont écrites est dépendant de l'implémentation. Les entrées avec des types de représentation autres que «String» sont ignorées.

La fonction XrmGetStringDatabase crée une nouvelle base de données et stocke les ressources spécifiées dans la chaîne terminée par un caractère nul spécifiée. XrmGetStringDatabase est similaire à XrmGetFileDatabase sauf qu'elle lit les informations à partir d'une chaîne au lieu d'un fichier. La chaîne doit contenir une séquence d'entrées au format ResourceLine valide (voir la section 15.1) terminée par un caractère nul; la base de données résultant de l'utilisation d'une chaîne dont la syntaxe est incorrecte est dépendante de l'implémentation. La chaîne est analysée dans la locale courante, et la base de données est créée dans la locale courante.

Si base_de_donnees est NULL, XrmDestroyDatabase retourne immédiatement.

La fonction XrmLocaleOfDatabase retourne le nom de la locale associée à la base de données spécifiée, sous forme de chaîne terminée par un caractère nul. La chaîne de nom de locale retournée est détenue par Xlib et ne doit pas être modifiée ou libérée par le client. Xlib n'est pas autorisé à libérer la chaîne avant que la base de données ne soit détruite. Jusqu'à ce que la chaîne soit libérée, elle ne sera pas modifiée par Xlib.

La fonction XrmGetDatabase retourne la base de données associée à l'affichage spécifié. Elle retourne NULL si une base de données n'a pas encore été définie.

La fonction XrmSetDatabase associe la base de données de ressources spécifiée (ou NULL) à l'affichage spécifié. La base de données précédemment associée à l'affichage (le cas échéant) n'est pas détruite. Un client ou une boîte à outils peut trouver cette fonction pratique pour conserver une base de données une fois qu'elle est construite.

SYNTAXE FICHIER

La syntaxe d'un fichier de ressources est une séquence de lignes de ressources terminées par des caractères de nouvelle ligne ou la fin du fichier. La syntaxe d'une ligne de ressource individuelle est :

ResourceLine	=	Commentaire | FichierInclusion | SpecRessource | <ligne vide>
Commentaire	=	"!" {<tout caractère sauf nul ou nouvelle ligne>}
FichierInclusion	=	"#" WhiteSpace "include" WhiteSpace NomFichier WhiteSpace
NomFichier	=	<nom de fichier valide pour le système d'exploitation>
SpecRessource	=	WhiteSpace NomRessource WhiteSpace ":" WhiteSpace Valeur
NomRessource	=	[Liaison] {Composant Liaison} NomComposant
Liaison	=	"." | "*"
Composant	=	"?" | NomComposant
NomComposant	=	CharNom {CharNom}
CharNom	=	"a"-"z" | "A"-"Z" | "0"-"9" | "_" | "-"
Valeur	=	{<tout caractère sauf nul ou nouvelle ligne non échappée>}

Les éléments séparés par une barre verticale (|) sont des alternatives. Les accolades ({...}) indiquent zéro ou plusieurs répétitions des éléments inclus. Les crochets ([...]) indiquent que l'élément inclus est optionnel. Les guillemets ("...") sont utilisés autour des caractères littéraux.

Les lignes FichierInclusion sont interprétées en remplaçant la ligne par le contenu du fichier spécifié. Le mot «include» doit être en minuscules. Le nom du fichier est interprété par rapport au répertoire du fichier dans lequel la ligne se trouve (par exemple, si le nom du fichier ne contient aucun répertoire ou contient une spécification de répertoire relative).

Si un NomRessource contient une séquence contiguë de deux caractères Liaison ou plus, la séquence sera remplacée par un seul caractère «.», si la séquence ne contient que des caractères «.», sinon la séquence sera remplacée par un seul caractère «*».

Une base de données de ressources ne contient jamais plus d'une entrée pour un NomRessource donné. Si un fichier de ressources contient plusieurs lignes avec le même NomRessource, la dernière ligne du fichier est utilisée.

Les caractères d'espacement avant ou après le nom ou le deux-points dans une SpecRessource sont ignorés. Pour permettre à une Valeur de commencer par un espace, la séquence de deux caractères «\espace» (antislash suivi d'un espace) est reconnue et remplacée par un caractère espace, et la séquence de deux caractères «\tab» (antislash suivi d'une tabulation horizontale) est reconnue et remplacée par un caractère de tabulation horizontale. Pour permettre à une Valeur de contenir des caractères de nouvelle ligne intégrés, la séquence de deux caractères «\n» est reconnue et remplacée par un caractère de nouvelle ligne. Pour permettre à une Valeur d'être divisée sur plusieurs lignes dans un fichier texte, la séquence de deux caractères «\nouvelle ligne» (antislash suivi d'une nouvelle ligne) est reconnue et supprimée de la valeur. Pour permettre à une Valeur de contenir des codes de caractères arbitraires, la séquence de quatre caractères «\nnn», où chaque n est un chiffre dans la plage «0»-«7», est reconnue et remplacée par un seul octet contenant la valeur octale spécifiée par la séquence. Enfin, la séquence de deux caractères «\\» est reconnue et remplacée par un seul antislash.

XrmDestroyDatabase(3)

NOM

XrmDestroyDatabase - détruit une base de données de ressources.

SYNTAXE

void XrmDestroyDatabase(XrmDatabase database);

ARGUMENTS

database
Spécifie la base de données de ressources à détruire.

DESCRIPTION

La fonction XrmDestroyDatabase détruit la base de données de ressources spécifiée par database. Après l'appel de cette fonction, la base de données n'est plus valide et ne doit pas être utilisée. Toutes les ressources allouées pour cette base de données sont libérées.

SYNTAXE DES FICHIERS

Aucun.
