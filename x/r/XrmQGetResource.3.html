NOM

XrmGetResource, XrmQGetResource, XrmQGetSearchList, XrmQGetSearchResource - récupérer des ressources de base de données et des listes de recherche

SYNTAXE

#include <X11/Xresource.h>

Bool XrmGetResource(XrmDatabase database, char *str_name, char *str_class, char **str_type_return, XrmValue *value_return);

Bool XrmQGetResource(XrmDatabase database, XrmNameList quark_name, XrmClassList quark_class, XrmRepresentation *quark_type_return, XrmValue *value_return);

typedef XrmHashTable *XrmSearchList;

Bool XrmQGetSearchList(XrmDatabase database, XrmNameList names, XrmClassList classes, XrmSearchList list_return, int list_length);

Bool XrmQGetSearchResource(XrmSearchList list, XrmName name, XrmClass class, XrmRepresentation *type_return, XrmValue *value_return);

ARGUMENTS

class
Spécifie la classe de ressource.
classes
Spécifie une liste de classes de ressources.
database
Spécifie la base de données qui doit être utilisée.
list
Spécifie la liste de recherche renvoyée par XrmQGetSearchList.
list_length
Spécifie le nombre d'entrées (et non la taille en octets) allouées pour list_return.
list_return
Renvoie une liste de recherche pour une utilisation ultérieure.
name
Spécifie le nom de la ressource.
names
Spécifie une liste de noms de ressources.
quark_class
Spécifie la classe complètement qualifiée de la valeur récupérée (sous forme de quark).
quark_name
Spécifie le nom complètement qualifié de la valeur récupérée (sous forme de quark).
quark_type_return
Renvoie le type de représentation de destination (sous forme de quark).
str_class
Spécifie la classe complètement qualifiée de la valeur récupérée (sous forme de chaîne).
str_name
Spécifie le nom complètement qualifié de la valeur récupérée (sous forme de chaîne).
str_type_return
Renvoie le type de représentation de destination (sous forme de chaîne).
type_return
Renvoie le type de représentation des données.
value_return
Renvoie la valeur dans la base de données.

DESCRIPTION

Les fonctions XrmGetResource et XrmQGetResource récupèrent une ressource de la base de données spécifiée. Les deux prennent une paire nom/classe complètement qualifiée, une représentation de ressource de destination, et l'adresse d'une valeur (paire taille/adresse). La valeur et le type renvoyés pointent vers la mémoire de la base de données ; par conséquent, vous ne devez pas modifier les données.

La base de données ne libère ou ne remplace les entrées que lors des appels à XrmPutResource, XrmQPutResource, ou XrmMergeDatabases. Un client qui ne stocke pas de nouvelles valeurs dans la base de données ou qui ne fusionne pas la base de données devrait être en sécurité en utilisant l'adresse renvoyée à tout moment jusqu'à sa sortie. Si une ressource a été trouvée, XrmGetResource et XrmQGetResource renvoient True ; sinon, elles renvoient False.

La fonction XrmQGetSearchList prend une liste de noms et de classes et renvoie une liste de niveaux de base de données où une correspondance pourrait se produire. La liste renvoyée est dans l'ordre du meilleur au pire et utilise le même algorithme que XrmGetResource pour déterminer la priorité. Si list_return était suffisamment grande pour la liste de recherche, XrmQGetSearchList renvoie True ; sinon, elle renvoie False.

La taille de la liste de recherche que l'appelant doit allouer dépend du nombre de niveaux et de caractères génériques dans les spécificateurs de ressources stockés dans la base de données. La longueur du pire cas est %3 sup n%, où n est le nombre de composantes de nom ou de classe dans les noms ou les classes.

Lors de l'utilisation de XrmQGetSearchList suivie de multiples sondes pour des ressources avec un préfixe de nom et de classe commun, seul le préfixe commun doit être spécifié dans la liste de noms et de classes passée à XrmQGetSearchList.

La fonction XrmQGetSearchResource recherche dans les niveaux de base de données spécifiés la ressource qui est complètement identifiée par le nom et la classe spécifiés. La recherche s'arrête à la première correspondance. XrmQGetSearchResource renvoie True si la ressource a été trouvée ; sinon, elle renvoie False.

Un appel à XrmQGetSearchList avec une liste de noms et de classes contenant toutes les composantes sauf la dernière d'un nom de ressource, suivi d'un appel à XrmQGetSearchResource avec la dernière composante nom et classe, renvoie la même entrée de base de données que XrmGetResource et XrmQGetResource avec le nom et la classe complètement qualifiés.

RÈGLES DE CORRESPONDANCE

L'algorithme pour déterminer quelle entrée de base de données de ressource correspond à une requête donnée est le cœur du gestionnaire de ressources. Toutes les requêtes doivent spécifier complètement le nom et la classe de la ressource souhaitée (l'utilisation des caractères «*» et «?» n'est pas autorisée). La bibliothèque prend en charge jusqu'à 100 composantes dans un nom ou une classe complet. Les ressources sont stockées dans la base de données avec des noms et des classes partiellement spécifiés, en utilisant des constructions de correspondance de motifs. Un astérisque (*) est une liaison lâche et est utilisé pour représenter tout nombre de composantes intermédiaires, y compris aucune. Un point (.) est une liaison serrée et est utilisé pour séparer les composantes immédiatement adjacentes. Un point d'interrogation (?) est utilisé pour faire correspondre une seule composante de nom ou de classe. Une entrée de base de données ne peut pas se terminer par une liaison lâche ; la composante finale (qui ne peut pas être le caractère «?» ) doit être spécifiée. L'algorithme de recherche recherche dans la base de données l'entrée qui correspond le plus étroitement (est la plus spécifique pour) le nom et la classe complets interrogés. Lorsque plusieurs entrées de base de données correspondent au nom et à la classe complets, des règles de priorité sont utilisées pour en sélectionner une seule.

Le nom et la classe complets sont parcourus de gauche à droite (du niveau le plus haut dans la hiérarchie au plus bas), une composante à la fois. À chaque niveau, la composante et/ou la liaison correspondante de chaque entrée correspondante est déterminée, et ces composantes et liaisons correspondantes sont comparées selon des règles de priorité. Chacune des règles est appliquée à chaque niveau avant de passer au niveau suivant, jusqu'à ce qu'une règle sélectionne une seule entrée parmi toutes les autres. Les règles, par ordre de priorité, sont :

1.
Une entrée contenant une composante correspondante (qu'il s'agisse d'un nom, d'une classe, ou du caractère «?» ) a la priorité sur les entrées qui élident le niveau (c'est-à-dire les entrées qui correspondent au niveau dans une liaison lâche).
2.
Une entrée avec un nom correspondant a la priorité sur les entrées avec une classe correspondante et sur les entrées qui correspondent en utilisant le caractère «?» . Une entrée avec une classe correspondante a la priorité sur les entrées qui correspondent en utilisant le caractère «?» .
3.
Une entrée précédée d'une liaison serrée a la priorité sur les entrées précédées d'une liaison lâche.
